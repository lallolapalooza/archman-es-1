NOMBRE

Mouse::Role - El Rol de Mouse

VERSIÓN

Este documento describe la versión v2.6.0 de Mouse

SINOPSIS

package Comparable;
use Mouse::Role; # el paquete es ahora un rol de Mouse
# Declara métodos que son requeridos por este rol
requires qw(compare);
# Define métodos que este rol proporciona
sub equals {
    my($self, $other) = @_;
    return $self->compare($other) == 0;
}
# y más tarde
package MyObject;
use Mouse;
with qw(Comparable); # Ahora MyObject puede equals()

    # ...

DESCRIPCIÓN

Este módulo declara la clase que lo llama como un rol de Mouse.

El concepto de roles se documenta en Moose::Manual::Roles. Este documento sirve como documentación de la API.

FUNCIONES EXPORTADAS

Mouse::Role soporta todas las funciones que Mouse exporta, pero difiere ligeramente en cómo se manejan algunos elementos (ver "CAVEATS" a continuación para más detalles).

Mouse::Role también ofrece dos palabras clave específicas de roles:

requires(@nombres_de_métodos)

Los roles pueden requerir que ciertos métodos sean implementados por cualquier clase que "haga" el rol.

Tenga en cuenta que los accesorios de atributos también cuentan como métodos a efectos de cumplir los requisitos de un rol.

excludes(@nombres_de_roles)

Esto se exporta pero no se implementa en Mouse.

IMPORTAR Y DESIMPORTAR

import

Importar Mouse::Role te dará azúcar sintáctico. "-traits" también son compatibles.

unimport

Por favor, desimporte ("no Mouse::Role") para que si alguien llama a una de las palabras clave (como "has") falle de forma ruidosa en lugar de fallar sutilmente.

CAVEATS

El soporte de roles tiene solo algunas advertencias:

  • Los roles no pueden usar la palabra clave "extends"; lanzará una excepción por ahora. Lo mismo ocurre con las palabras clave "augment" y "inner" (no estoy seguro de que realmente tengan sentido para los roles). Todas las demás palabras clave de Mouse se retrasarán para que puedan aplicarse a la clase que las consume.
  • La composición de roles hace todo lo posible para **no** ser sensible al orden cuando se trata de la resolución de conflictos y la detección de requisitos. Sin embargo, es sensible al orden cuando se trata de modificadores de métodos. Todos los modificadores before/around/after se incluyen cada vez que se compone un rol en una clase, y luego se aplican en el orden en que se utilizan los roles. Esto también significa que no hay conflicto para los modificadores before/around/after.

    En la mayoría de los casos, esto no será un problema; sin embargo, es algo a tener en cuenta al usar modificadores de métodos en un rol. Nunca debes asumir ningún orden.
