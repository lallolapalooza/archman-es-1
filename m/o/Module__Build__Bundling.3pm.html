Module::Build::Bundling(3pm) Documentación de Perl contribuida por el usuario Module::Build::Bundling(3pm)

NOMBRE

Module::Build::Bundling - Cómo empaquetar Module::Build con una distribución

SINOPSIS

# Build.PL
use inc::latest 'Module::Build';
Module::Build->new(
  module_name => 'Foo::Bar',
  license => 'perl',
)->create_build_script;

DESCRIPCIÓN

ADVERTENCIA -- ESTA ES UNA CARACTERÍSTICA EXPERIMENTAL

Para instalar una distribución que usa Module::Build, los usuarios deben tener Module::Build disponible en sus sistemas. Hay dos formas de hacer esto. La primera es incluir Module::Build en el campo de metadatos "configure_requires". Este campo es compatible con versiones recientes de CPAN y CPANPLUS y es una característica estándar en el núcleo de Perl a partir de Perl 5.10.1. Module::Build se añade ahora a "configure_requires" por defecto.

La segunda forma es compatible con versiones anteriores de Perl que no han actualizado CPAN o CPANPLUS e implica empaquetar una copia completa de Module::Build en el directorio "inc/" de la distribución. Este es el mismo enfoque utilizado por Module::Install, un envoltorio moderno para ExtUtils::MakeMaker para distribuciones basadas en Makefile.PL.

El "truco" para que esto funcione para Module::Build es asegurarse de que se utiliza la versión más reciente de Module::Build, ya sea en "inc/" o ya instalada en el sistema del usuario. Esto garantiza que todas las características necesarias estén disponibles, así como cualquier nueva corrección de errores. Esto se hace utilizando el módulo experimental inc::latest, disponible en CPAN.

Un Build.PL "normal" se ve así (con solo los campos mínimos requeridos):

use Module::Build;
Module::Build->new(
  module_name => 'Foo::Bar',
  license     => 'perl',
)->create_build_script;

Un Build.PL de "empaquetado" reemplaza la línea "use" inicial con un reemplazo casi transparente:

use inc::latest 'Module::Build';
Module::Build->new(
  module_name => 'Foo::Bar',
  license => 'perl',
)->create_build_script;

Para los *autores*, cuando se ejecuta "Build dist", Module::Build se empaquetará automáticamente en "inc" según las reglas de inc::latest.

Para los *usuarios*, inc::latest cargará la última versión de Module::Build, ya sea instalada o empaquetada en "inc/".

EMPAQUETANDO OTRAS DEPENDENCIAS DE CONFIGURACIÓN

El mismo enfoque funciona para otras dependencias de configuración: módulos que *deben* estar disponibles para que Build.PL se ejecute. Todas las demás dependencias se pueden especificar como de costumbre en Build.PL y CPAN o CPANPLUS las instalará después de que Build.PL finalice.

Por ejemplo, para empaquetar el módulo Devel::AssertOS::Unix (que asegura un sistema operativo "tipo Unix"), se podría hacer esto:

use inc::latest 'Devel::AssertOS::Unix';
use inc::latest 'Module::Build';
Module::Build->new(
  module_name => 'Foo::Bar',
  license => 'perl',
)->create_build_script;

El módulo "inc::latest" crea directorios empaquetados basados en el archivo de lista de paquetes de una distribución instalada. Aunque "inc::latest" acepta argumentos de nombre de módulo, es mejor pensar en ello como empaquetar y poner a disposición distribuciones completas. Cuando se carga un módulo a través de "inc::latest", busca en todas las distribuciones empaquetadas en "inc/" una módulo más reciente que la que se encuentra en la matriz @INC existente.

Por lo tanto, el nombre de módulo proporcionado generalmente debe ser el nombre de módulo de "nivel superior" de una distribución, aunque esto no es estrictamente necesario. Por ejemplo, Module::Build tiene una serie de heurísticas para mapear nombres de módulos a listas de paquetes, permitiendo a los usuarios hacer cosas como esta:

use inc::latest 'Devel::AssertOS::Unix';

incluso si Devel::AssertOS::Unix está contenido dentro de la distribución Devel-CheckOS.

Actualmente, se requieren listas de paquetes. Por lo tanto, empaquetar módulos centrales duales, *incluido Module::Build*, puede requerir una 'instalación forzada' sobre las versiones en la última versión de perl para crear la lista de paquetes necesaria para el empaquetado. Se espera que esta limitación se aborde en una futura versión de Module::Build.

ADVERTENCIA -- Cómo gestionar cadenas de dependencias

Antes de empaquetar una distribución, debe asegurarse de que todos los requisitos previos también estén empaquetados y se carguen en el orden correcto. Para Module::Build en sí, esto no debería ser necesario, pero lo es para cualquier otra distribución. (Se espera que una futura versión de Module::Build aborde esta deficiencia).

Por ejemplo, si necesita "Wibble", pero "Wibble" depende de "Wobble", su Build.PL podría verse así:

use inc::latest 'Wobble';
use inc::latest 'Wibble';
use inc::latest 'Module::Build';
Module::Build->new(
  module_name => 'Foo::Bar',
  license => 'perl',
)->create_build_script;

Se recomienda encarecidamente a los autores que limiten el empaquetado de dependencias adicionales si es posible y que prueben cuidadosamente sus archivos tar de distribución en versiones anteriores de Perl antes de subirlos a CPAN.
