Module::Implementation(3) Documentación de Perl aportada por el usuario Module::Implementation(3)

NOMBRE

Module::Implementation - Carga una de varias implementaciones subyacentes alternativas para un módulo

VERSIÓN

versión 0.09

SINOPSIS

package Foo::Bar;
use Module::Implementation;
BEGIN {
    my $loader = Module::Implementation::build_loader_sub(
        implementations => [ 'XS',  'PurePerl' ],
        symbols         => [ 'run', 'check' ],
    );
    $loader->();
}
package Consumer;
# carga la primera implementación viable
use Foo::Bar;

DESCRIPCIÓN

Este módulo abstrae el proceso de elegir una de varias implementaciones subyacentes para un módulo. Esto se puede usar para proporcionar implementaciones XS y puras de Perl de un módulo, o se podría usar para cargar una implementación para un sistema operativo dado o cualquier otro caso en el que necesite proporcionar múltiples implementaciones.

Este módulo solo es útil cuando conoce todas las implementaciones con anticipación. Si desea cargar implementaciones arbitrarias, probablemente necesite algo como un sistema de complementos, no este módulo.

API

Este módulo proporciona dos subrutinas, ninguna de las cuales se exporta.

Module::Implementation::build_loader_sub(...)

Esta subrutina toma los siguientes argumentos.

  • implementations

    Debería ser una referencia de matriz de nombres de implementación. Cada nombre debe corresponder a un módulo en el espacio de nombres del llamador.

    En otras palabras, usando el ejemplo en la "SINOPSIS", este módulo buscará los módulos "Foo::Bar::XS" y "Foo::Bar::PurePerl".

    Este argumento es obligatorio.

  • symbols

    Una lista de símbolos para copiar del paquete de implementación al paquete que llama.

    Estos pueden ir precedidos por un tipo de variable: "$", "@", "%", "&", o "*)". Si no se proporciona prefijo, se asume que el símbolo es una subrutina.

    Este argumento es opcional.

Esta subrutina *devuelve* el cargador de implementación como una referencia a subrutina.

Depende de usted llamar a esta subrutina cargadora en su código.

Recomiendo que *no* llame a este cargador en una subrutina import(). Si un llamador solicita explícitamente ninguna importación, su subrutina import() no se ejecutará en absoluto, lo que puede causar errores extraños.

Module::Implementation::implementation_for($package)

Dado un nombre de paquete, esta subrutina devuelve la implementación que se cargó para el paquete. Este no es un nombre de paquete completo, solo el sufijo que identifica la implementación. Para el ejemplo de la "SINOPSIS", esta subrutina se llamaría como Module::Implementation::implementation_for('Foo::Bar'), y devolvería "XS" o "PurePerl".

CÓMO FUNCIONA EL CARGADOR DE IMPLEMENTACIÓN

El cargador de implementación funciona de la siguiente manera...

Primero, comprueba una variable de %ENV que especifica la implementación a cargar. La variable de entorno se basa en el nombre del paquete que carga las implementaciones. El separador de paquetes "::" se reemplaza por "_", y se convierte completamente a mayúsculas. Finalmente, agregamos "_IMPLEMENTATION" a este nombre.

Por lo tanto, en nuestro ejemplo de "SINOPSIS", la clave de %ENV correspondiente sería "FOO_BAR_IMPLEMENTATION".

Si esto está configurado, el cargador *solo* intentará cargar esta implementación.

Si la solicitud de la variable de entorno es para una implementación que no coincide con una de las implementaciones especificadas cuando se creó el cargador, se genera un error.

Si esta única implementación falla al cargarse, el cargador genera un error. Esto es útil para probar. Puede solicitar una implementación específica en un archivo de prueba escribiendo algo como esto:

BEGIN { $ENV{FOO_BAR_IMPLEMENTATION} = 'XS' }
use Foo::Bar;

Si la variable de entorno *no* está configurada, el cargador simplemente intenta las implementaciones pasadas originalmente a "Module::Implementation". Las implementaciones se prueban en el orden en que se pasaron originalmente.

El cargador utilizará la primera implementación que se cargue sin errores. Copiará los símbolos solicitados de esta implementación.

Si ninguna de las implementaciones se puede cargar, el cargador lanza una excepción.

El cargador devuelve el nombre del paquete que cargó.
