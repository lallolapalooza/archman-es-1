NOMBRE

Module::Pluggable - da automáticamente a tu módulo la capacidad de tener plugins

SINOPSIS

Uso simple de Module::Pluggable -

package MyClass;
use Module::Pluggable;

y luego más tarde...

use MyClass;
my $mc = MyClass->new();
# devuelve los nombres de todos los plugins instalados bajo MyClass::Plugin::*
my @plugins = $mc->plugins();

EJEMPLO

¿Por qué querrías hacer esto? Digamos que tienes algo que quiere pasar un objeto a varios plugins diferentes en turno. Por ejemplo, puede que quieras extraer metadatos de cada correo electrónico que recibes y hacer algo con ellos. Los plugins tienen sentido aquí porque entonces puedes seguir añadiendo nuevos analizadores de metadatos y toda la lógica y la documentación para cada uno estarán autocontenidas y los nuevos manejadores son fáciles de añadir sin cambiar el código principal. Para eso, podrías hacer algo como...

package Email::Examiner;
use strict;
use Email::Simple;
use Module::Pluggable require => 1;
sub handle_email {
    my $self  = shift;
    my $email = shift;
    foreach my $plugin ($self->plugins) {
        $plugin->examine($email);
    }
    return 1;
}

.. y todos los plugins tendrán la oportunidad en turno de mirarlo.

Esto se puede extender trivialmente para que los plugins puedan guardar el correo electrónico en algún lugar y que ningún otro plugin intente hacer eso. Simplemente haz que el método "examine" devuelva 1 si ha guardado el correo electrónico en algún lugar. También podrías querer ser paranoico y comprobar si el plugin tiene un método "examine".

foreach my $plugin ($self->plugins) {
    next unless $plugin->can('examine');
    last if     $plugin->examine($email);
}

Y así sucesivamente. El cielo es el límite.

DESCRIPCIÓN

Proporciona una forma simple pero, con suerte, extensible de tener 'plugins' para tu módulo. Obviamente, esta no será la solución definitiva, pero a mí me funciona.

Esencialmente, todo lo que hace es exportar un método a tu espacio de nombres que busca en una ruta de búsqueda de archivos .pm y los convierte en nombres de clase.

Opcionalmente, instancia esas clases por ti.

USO AVANZADO

Alternativamente, si no quieres usar 'plugins' como método...

package MyClass;
use Module::Pluggable sub_name => 'foo';

y luego más tarde...

my @plugins = $mc->foo();

O si quieres buscar en otro espacio de nombres

package MyClass;
use Module::Pluggable search_path => ['Acme::MyClass::Plugin', 'MyClass::Extend'];

o directorio

use Module::Pluggable search_dirs => ['mylibs/Foo'];

O si quieres instanciar cada plugin en lugar de simplemente devolver el nombre

package MyClass;
use Module::Pluggable instantiate => 'new';

y luego

# lo que sea que se pase a 'plugins' se pasará
# a 'new' para cada plugin
my @plugins = $mc->plugins(@options);

alternativamente, puedes simplemente requerir el módulo sin instanciarlo

package MyClass;
use Module::Pluggable require => 1;

ya que requerir automáticamente busca paquetes internos, lo cual puede no ser deseable, puedes desactivarlo

package MyClass;
use Module::Pluggable require => 1, inner => 0;

Puedes limitar los plugins cargados usando la opción `except`, ya sea como una cadena, una referencia de array o una expresión regular.

package MyClass;
use Module::Pluggable except => 'MyClass::Plugin::Foo';

o

package MyClass;
use Module::Pluggable except => ['MyClass::Plugin::Foo', 'MyClass::Plugin::Bar'];

o

package MyClass;
use Module::Pluggable except => qr/^MyClass::Plugin::(Foo|Bar)$/;

y de forma similar para `only`, que solo cargará plugins que coincidan.

Recuerda que puedes usar el módulo más de una vez

package MyClass;
use Module::Pluggable search_path => 'MyClass::Filters', sub_name => 'filters';
use Module::Pluggable search_path => 'MyClass::Plugins', sub_name => 'plugins';

y luego más tarde...

my @filters = $self->filters;
my @plugins = $self->plugins;

BÚSQUEDA DE PLUGINS

Cada vez que llamas a 'plugins', se recorre de nuevo toda la ruta de búsqueda. Esto permite cargar plugins dinámicamente incluso en tiempo de ejecución. Sin embargo, esto puede ser costoso y, por lo tanto, si no esperas querer añadir nuevos plugins en tiempo de ejecución, podrías hacer esto

package Foo;
use strict;
use Module::Pluggable sub_name => '_plugins';
our @PLUGINS;
sub plugins { @PLUGINS ||= shift->_plugins }
1;

PAQUETES INTERNOS

Si tienes, por ejemplo, un archivo lib/Something/Plugin/Foo.pm que contiene definiciones de paquetes para tanto "Something::Plugin::Foo" como "Something::Plugin::Bar", entonces siempre que tengas la opción require o instantiate configurada, también encontraremos "Something::Plugin::Bar". ¡Nifty!

OPCIONES

Puedes pasar un hash de opciones al importar este módulo.

Las opciones pueden ser...

sub_name

El nombre de la subrutina a crear en tu espacio de nombres.

Por defecto es 'plugins'

search_path

Una referencia de array de espacios de nombres en los que buscar.

search_dirs

Una referencia de array de directorios en los que buscar antes de @INC.

instantiate

Llama a este método en la clase. En general, probablemente será 'new', pero puede ser lo que quieras. Los argumentos que se pasen a 'plugins' se pasarán al método.

El valor por defecto es 'undef', es decir, solo devuelve el nombre de la clase.

require

Simplemente requiere la clase, no la instancia (anula 'instantiate');

inner

Si se establece en 0, no buscará en paquetes internos. Si se establece en 1, anulará "require".

only

Toma una cadena, una referencia de array o una expresión regular que describa los nombres de los únicos plugins a devolver. Aunque esto pueda parecer perverso... bueno, lo es. Pero también tiene sentido. Confía en mí.

except

Similar a "only", toma una descripción de los plugins a excluir de la devolución. Esto es un poco menos perverso.

package

Esto es para uso de módulos de extensión que se basan en "Module::Pluggable": pasar una opción "package" te permite colocar el método de plugin en un paquete diferente a tu propio paquete.

file_regex

Por defecto, "Module::Pluggable" solo busca archivos .pm.

Al proporcionar un nuevo "file_regex" puedes cambiar este comportamiento, por ejemplo:

file_regex => qr/\.plugin$/

include_editor_junk

Por defecto, "Module::Pluggable" ignora los archivos que parecen haber sido dejados por los editores. Actualmente, esto significa archivos que terminan en ~ (~), las extensiones .swp o .swo, o archivos que comienzan con .#.
