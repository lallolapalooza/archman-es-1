MojoX::MIME::Types(3) Documentación de Perl Contribuida por Usuarios MojoX::MIME::Types(3)

NOMBRE

MojoX::MIME::Types - Tipos MIME para Mojolicious

HERENCIA

MojoX::MIME::Types
  es un Mojo::Base

SINOPSIS

use MojoX::MIME::Types;
# configurado en Mojolicious como predeterminado
$app->types(MojoX::MIME::Types->new);
app->types(MojoX::MIME::Types->new);   # ::Lite
# interfaz básica traducida a MIME::Types puro
$types->type(foo => 'text/foo');
say $types->type('foo');

DESCRIPCIÓN

[Añadido a MIME::Types 2.07] Este módulo es un reemplazo directo para Mojolicious::Types, pero con un manejo más correcto además de una lista completa de tipos... una enorme lista de tipos.

Algunos métodos ignoran la información que reciben: esos parámetros se aceptan por compatibilidad con la interfaz de Mojolicious::Types, pero no deberían contener información útil.

Lee los "DETALLES" a continuación, sobre cómo conectar este módulo en Mojolicious y las diferencias que obtienes.

MÉTODOS

Constructores

$class->new(%opciones)
Crea el manejador de 'tipo' para Mojolicious. Cuando no especificas tu propio objeto MIME::Type ("mime_types"), se instanciará para ti. Creas uno tú mismo cuando te gustaría pasar algún parámetro al constructor del objeto. 
-Opción    --Predeterminado
 mime_types  <creado internamente>
 types       undef
mime_types => objeto MIME::Types
Pasa tu propio objeto MIME::Types preparado, cuando necesitas parámetros de instanciación diferentes a los predeterminados.
types => HASH
Ignorado.

ejemplo:

$app->types(MojoX::MIME::Types->new);
# cuando necesitas pasar opciones a MIME::Types->new
my $mt    = MIME::Types->new(%opts);
my $types = MojoX::MIME::Types->new(mime_types => $mt);
$app->types($types);

Atributos

$obj->mapping( [\%tabla] )
En Mojolicious::Types, este atributo expone la administración interna de tipos, ofreciendo cambiarla usando una interfaz abstracta limpia. Ese error de interfaz muerde ahora tenemos internos más complejos.

¡Evita este método! El HASH devuelto es costoso de construir, los cambios pasados a través de %tabla se ignoran: ¡MIME::Types es muy completo!

$obj->mimeTypes()
Devuelve el objeto interno de tipos mime.

Acciones

$obj->content_type($controlador, \%opciones)
Establece un tipo de contenido en el controlador cuando aún no está establecido. Las %opciones contienen "ext" o "file" para especificar una extensión de archivo o un nombre de archivo que se utiliza para derivar el tipo de contenido. Añadido y marcado como EXPERIMENTAL en Mojo 7.94.
$obj->detect( $accept, [$prio] )
Devuelve una lista de extensiones de nombres de archivo. El encabezado $accept en HTTP puede contener múltiples tipos, con una indicación de prioridad (atributos 'q'). La lista devuelta contiene una lista con extensiones, las extensiones relacionadas con el tipo de mayor prioridad primero. El flag $prio se ignora. Véase MIME::Types::httpAccept().

Esta función detect() no es el enfoque correcto para el encabezado Accept: el "Accept" puede contener comodines ('*') en tipos para globbing, lo que no produce extensiones. Es mejor usar MIME::Types::httpAcceptBest() o MIME::Types::httpAcceptSelect().

ejemplo:

my $exts = $types->detect('application/json;q=9');
my $exts = $types->detect('text/html, application/json;q=9');
$obj->file_type($nombre_archivo)
Devuelve el tipo mime para un nombre de archivo. Añadido y marcado como EXPERIMENTAL en Mojo 7.94.
$obj->type( $ext, [$type|\@types] )
Devuelve el primer nombre de tipo para una extensión $ext, a menos que especifiques nombres de tipo.

Cuando se especifica un único $type o un ARRAY de @types, se devuelve el objeto actual. No se hace nada con la información proporcionada.

DETALLES

¿Por qué?

El módulo Mojolicious::Types solo tiene muy poco conocimiento sobre lo que realmente se necesita para tratar los tipos correctamente, y solo contiene una pequeña lista de extensiones. MIME::Types intenta seguir los estándares muy de cerca y contiene todos los tipos encontrados en varias listas en internet.

Cómo usar con Mojolicious

Inicia tu aplicación Mojo de esta manera:

package MyApp;
use Mojo::Base 'Mojolicious';
sub startup {
   my $self = shift;
   ...
   $self->types(MojoX::MIME::Types->new);
}

Si tienes opciones especiales para MIME::Types::new(), entonces crea tu propio objeto MIME::Types primero:

my $mt    = MIME::Types->new(%opts);
my $types = MojoX::MIME::Types->new(mime_types => $mt);
$self->types($types);

En cualquier caso, puedes alcanzar el objeto MIME::Types inteligente más tarde como

my $mt    = $app->types->mimeTypes;
my $mime  = $mt->mimeTypeOf($nombre_archivo);

Cómo usar con Mojolicious::Lite

El uso en aplicaciones Mojolicious::Lite es solo ligeramente diferente de lo anterior:

app->types(MojoX::MIME::Types->new);
my $types = app->types;

Diferencias con Mojolicious::Types

Hay algunas diferencias importantes con Mojolicious::Types:

  • las tablas mantenidas por MIME::Types están completas. Por lo tanto: no debería haber necesidad de añadir tus propios tipos, ni a través de types(), ni a través de type(). Todos los intentos de añadir tipos se ignoran; es mejor eliminarlos de tu código.
  • Este plugin entiende la bandera experimental 'x-' en tipos y maneja problemas de mayúsculas/minúsculas.
  • Las actualizaciones al hash interno a través de types() se ignoran simplemente, porque es costoso de implementar (y no añadirá nada nuevo).
  • El detect() está implementado de forma compatible, pero no entiende comodines ('*'). Deberías usar MIME::Types::httpAcceptBest() o MIME::Types::httpAcceptSelect() para reemplazar esta función rota.
