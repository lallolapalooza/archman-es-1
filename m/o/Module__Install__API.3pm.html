Module::Install::API(3) Documentación aportada por el usuario de Perl Module::Install::API(3)

Nombre

Module::Install::API - Referencia de comandos para Module::Install

DESCRIPCIÓN

Module::Install tiene muchos comandos dispersos en las extensiones. Algunos comandos comunes se describen en el pod principal de Module::Install, pero a menudo necesitas conocer más para hacer lo que quieres.

Este documento de API lista y describe todos los comandos públicos *soportados*, agrupados según su naturaleza o importancia.

Si eres autor de un módulo y quieres usar Module::Install en tus distribuciones, este es el documento que debes consultar.

Si eres un usuario (o contribuyente) de distribuciones que usan Module::Install, también podrías querer revisar Module::Install::FAQ donde encontrarás algunos problemas comunes que puedes encontrar.

Nota: los comandos no listados aquí deben considerarse comandos privados para los desarrolladores de Module::Install, o *no soportados* con razones diversas (algunas son experimentales y medio construidas, algunas son mal implementadas (por diseño o por implementación), algunas son simplemente degradadas, y así sucesivamente). Puedes encontrar algunos de ellos usados de manera amplia, pero su uso se recomienda con cautela. Te has sido advertido.

COMANDOS PARA PROVEER DATOS BÁSICOS

La mayoría de estos también se describen en el pod principal de Module::Install. Básicamente, (más o menos) casi todo lo que necesitas saber es el comando all_from que intenta extraer todos los datos meta necesarios de un archivo de módulo, pero también puedes especificar uno por uno los datos que no están escritos en el módulo y no pueden extraerse (normalmente prefieres escribir estos comandos antes de all_from() para no ser advertido por la falta de información).

all_from (Module::Install::Metadata)

all_from 'lib/Foo/Bar.pm';

all_from toma una ruta de archivo de módulo y intenta extraer datos meta de dicho módulo, incluyendo el nombre de la distribución, el versión del módulo, la versión mínima de Perl requerida para el módulo, información de autores, una licencia, una descripción breve del módulo. Ve los siguientes comandos para detalles de extracción.

name, name_from, module_name (Module::Install::Metadata)

name 'Foo-Bar';
name_from 'lib/Foo/Bar.pm';

name toma un nombre de distribución. A menudo difiere ligeramente de un nombre de módulo (un nombre de módulo se separa con dos puntos; un nombre de distribución se separa con guiones). Simplemente reemplazar todos los dos puntos de tu módulo principal con guiones sería suficiente para ti.

name_from toma una ruta de archivo de módulo y busca la declaración más alta de "package" para extraer un nombre de módulo, y luego lo convierte en nombre de distribución.

También puedes opcionalmente establecer module_name para especificar el nombre del módulo principal (si prefieres un esquema de nombre diferente para tu distribución). Este valor se pasa directamente a ExtUtils::MakeMaker en el fondo como un atributo "NAME" (Module::Install suele crear este atributo a partir del nombre de la distribución establecido por name o name_from).

abstract, abstract_from (Module::Install::Metadata)

abstract 'una breve descripción de la distribución';
abstract_from 'lib/Foo/Bar.pm';

abstract toma una cadena para describir qué módulo/distribución es. abstract_from toma una ruta de archivo de módulo y busca una cadena que sigue el nombre del módulo y un guión para separar en la sección "NAME" del pod.

El valor establecido por abstract o abstract_from se pasa a ExtUtils::MakeMaker como un atributo "ABSTRACT".

version, version_from (Module::Install::Metadata)

version '0.01';
version_from 'lib/Foo/Bar.pm';

version toma una cadena de versión para la distribución. version_from toma una ruta de archivo de módulo y busca la instrucción "\$VERSION" del módulo.

El valor establecido por version o version_from se pasa a ExtUtils::MakeMaker como un atributo "VERSION". version_from (y all_from) también establece un atributo "VERSION_FROM" para verificar la integridad de la distribución.

perl_version, perl_version_from (Module::Install::Metadata)

perl_version '5.008';
perl_version_from 'lib/Foo/Bar.pm';

perl_version toma la versión mínima de Perl requerida para la distribución. perl_version_from toma una ruta de archivo de módulo y busca una instrucción "use <perl_version>" (o "require <perl_version>") del módulo (nota: ahora Module::Install solo soporta Perl 5.005 y versiones posteriores).

El valor establecido por perl_version o perl_version_from se pasa a ExtUtils::MakeMaker como un atributo "MIN_PERL_VERSION" (si es aplicable).

author, author_from (Module::Install::Metadata)

author 'John Doe <john.doe at cpan.org>';
author_from 'lib/Foo/Bar.pm';

author toma una cadena para describir los autores. Puedes establecer múltiples autores con una sola author o con múltiples author (también puedes usar el alias authors si lo prefieres).

author_from toma una ruta de archivo de módulo y busca una sección "AUTHOR" (o "AUTHORS") en el pod (y también secciones de licencia/copyright si no encuentra ninguna sección de autores) para extraer un autor.

El valor establecido por author o author_from se concatena y se pasa a ExtUtils::MakeMaker como un atributo "AUTHOR".

license, license_from (Module::Install::Metadata)

license 'perl';
license_from 'lib/Foo/Bar.pm';

license toma un nombre de licencia abreviado incluyendo "perl", "artistic", "apache", "(l)gpl", "bsd", "mit", "mozilla", "open_source", y así sucesivamente. Si no (prefieres) especificar una licencia particular, será "unknown".

license_from toma una ruta de archivo de módulo y busca una sección "LICENSE" (o "LICENCE") en el pod (y también sección "COPYRIGHT" si no encuentra ninguna sección de autores) para extraer una licencia.

El valor establecido por license o license_from se pasa a ExtUtils::MakeMaker como un atributo "LICENSE" (si es aplicable). Tampoco se debe olvidar que si la distribución está diseñada para ser subida a CPAN, debe ser una licencia aceptada por OSI. El software comercial no está permitido en CPAN.

COMMANDS PARA REQUERIR MÓDULOS

Estos comandos se utilizan para especificar los módulos de los que depende tu distribución.

requires (Module::Install::Metadata)

requires 'Foo::Bar';
requires 'Foo::Bar' => '0.01';
requires 'Foo::Bar', 'Foo::Baz';
requires 'Foo::Bar' => '0.01', 'Foo::Baz' => '0.02';

El comando requires toma un nombre de módulo del que tu distribución depende, y su versión mínima requerida si la hay. Puedes añadir un número arbitrario de "requires". Incluso puedes añadir múltiples números de dependencias en el mismo módulo con diferentes versiones requeridas (que se ordenarán más tarde, sin embargo). Ten en cuenta que esta dependencia se basa en un módulo, no en una distribución. Esto normalmente no importa, y solo necesitas llamar a un módulo que realmente necesites (entonces obtendrás la distribución entera a la que pertenece), pero a veces podrías necesitar llamar a todos los módulos que el módulo requerido implícitamente requiere.

Los valores establecidos por requires se pasan a ExtUtils::MakeMaker como un atributo "PREREQ_PM".

build_requires, test_requires (Module::Install::Metadata)

build_requires 'ExtUtils::Foo::Bar';
build_requires 'ExtUtils::Foo::Baz' => '1.00';
test_requires  'Test::Foo::Bar';
test_requires  'Test::Foo::Baz' => '1.00';

El comando build_requires también toma un nombre de módulo y una versión mínima requerida si la hay. La diferencia con el comando "requires" es que build_requires es para llamar a módulos que requerirás mientras construyes la distribución, o en las pruebas, y que en teoría no son necesarios en tiempo de ejecución. Esta distinción es más para otros gestores de paquetes del sistema que para CPAN, desde donde normalmente quieres instalar todo para su reutilización futura (a menos que seas demasiado perezoso para probar distribuciones).

En el momento de escribir esto, "test_requires" es solo un alias para "build_requires", pero esto podría cambiar en el futuro.

Los valores establecidos por build_requires y test_requires se pasan a ExtUtils::MakeMaker como un atributo "BUILD_REQUIRES", que puede recurrir a "PREREQ_PM" si tu ExtUtils::MakeMaker no es lo suficientemente nuevo.

configure_requires (Module::Install::Metadata)

configure_requires 'ExtUtils::Foo::Bar';
configure_requires 'ExtUtils::Foo::Baz' => '1.00';

El comando configure_requires también toma un nombre de módulo y una versión mínima requerida si la hay. La diferencia con el comando "requires" es que configure_requires es para llamar a módulos que necesitarás para ejecutar "perl Makefile.PL". Este atributo solo tiene sentido para las últimas cadenas de herramientas de CPAN que analizan "META.yml" antes de ejecutar "perl Makefile.PL".

Los valores establecidos por configure_requires se pasan a ExtUtils::MakeMaker como un atributo "CONFIGURE_REQUIRES", que puede recurrir a "PREREQ_PM" si tu ExtUtils::MakeMaker no es lo suficientemente nuevo.

recommends (Module::Install::Metadata)

recommends 'ExtUtils::Foo::Bar';
recommends 'ExtUtils::Foo::Baz' => '1.00';

El comando recommends también toma un nombre de módulo y una versión mínima requerida si la hay. En el momento de escribir esto, "recommends" es puramente informativo, solo escrito en el "META.yml". Los módulos recomendados *no* serán instalados normalmente por las cadenas de herramientas actuales de CPAN (otros gestores de paquetes del sistema podrían pedirte que los instales).

features, feature (Module::Install::Metadata)

feature( 'share directory support',
  -default => 1,
  'File::ShareDir' => '1.00',
);
features(
  'JSON support', [
    -default => 0,
    'JSON::MaybeXS' => '1.003003',
  ],
  'YAML support', [
    'YAML' => '0',
  ],
);

El comando feature toma una cadena para describir para qué es la característica, y una matriz de módulos (opcionales) y sus versiones recomendadas si las hay. El comando features toma una matriz de una descripción y una matriz de módulos.

En el momento de escribir esto, tanto "feature" como "features" solo funcionan cuando auto_install (ver más abajo) está configurado. Se utilizan para permitir a los usuarios de la distribución elegir qué instalan junto con la distribución. Esto puede ser útil si la distribución tiene muchas características opcionales que pueden no funcionar en todas las plataformas, o que requieren demasiados módulos para los usuarios promedio.

Sin embargo, solicitar a los usuarios también dificulta la instalación automática o las pruebas de humo, y se considera una mala práctica (es mucho preferible dar valores predeterminados sensatos).

Aunque los módulos "feature"d son opcionales y pueden ser elegidos durante la instalación, los módulos elegidos se tratan de la misma manera que los establecidos por el comando "requires". (No están listados en la sección "recommends" en el "META.yml"). Esto podría cambiar en el futuro.

Puedes añadir "-default => [01]" en una matriz de módulos requeridos en la(s) feature(s), para establecer un valor predeterminado para el aviso.

COMANDOS PARA ESCRIBIR METADATOS

Estos son los comandos para escribir archivos de metadatos reales.

WriteAll (Module::Install::WriteAll)

use inc::Module::Install;

all_from 'lib/Foo/Bar.pm';

WriteAll;

El comando WriteAll es usualmente el último comando en el "Makefile.PL". Puede tomar varios atributos, pero usualmente no necesitas preocuparte a menos que quieras escribir un Makefile para un módulo basado en Inline. Esto escribe "Makefile", "META.yml", y "MYMETA.yml" (o "MYMETA.json") si estableces una variable ambiental experimental "X_MYMETA".

WriteMakefile (Module::Install::MakeMaker)

use inc::Module::Install;

requires 'Foo::Baz';  # a la Module::Install

WriteMakefile(        # a la ExtUtils::MakeMaker
  NAME => 'Foo::Bar',
  VERSION_FROM => 'lib/Foo/Bar.pm',
);

Si estás familiarizado con ExtUtils::MakeMaker y generalmente quieres adherirte a su forma, puedes hacerlo. Usa tanta magia de Module::Install como quieras, y luego recurre a la vieja y buena forma. Simplemente funciona.

write_mymeta_yaml, write_mymeta_json (Module::Install::Metadata)

write_mymeta_yaml;
write_mymeta_json;

El comando write_mymeta_yaml y el comando write_mymeta_json son para escribir "MYMETA.yml" y "MYMETA.json" respectivamente, que son una nueva mejora para las cadenas de herramientas de CPAN que eventualmente permitirán a los módulos de la cadena de herramientas saber qué módulos se requieren sin analizar Makefile, etc. Estos son principalmente para uso interno (en el comando "WriteAll") pero puedes escribir explícitamente estos comandos en tu Makefile.PL.

COMANDOS PARA AJUSTAR Makefile

makemaker_args (Module::Install::Makefile)

makemaker_args(
  PREREQ_FATAL => 1,
  dist => { PREOP => 'pod2text lib/Foo/Bar.pm > README' },
);

El comando makemaker_args se utiliza en el comando WriteMakefile, y toma cualquier atributo que ExtUtils::MakeMaker entienda. Consulta ExtUtils::MakeMaker para ver los atributos disponibles.

preamble, postamble (Module::Install::Makefile)

preamble "# my preamble\n";
postamble qq{my_done ::
\t\$(PERL) -e "print qq/done\\n/"\n};

Los comandos preamble y postamble toman una cadena para ser incrustada en el "Makefile". Puedes añadir objetivos personalizados con esto. Consulta los manuales apropiados para aprender cómo escribir un Makefile.

COMANDOS PARA PRUEBAS

Estos son para configurar archivos de prueba.

tests (Module::Install::Metadata)

tests 't/*.t t/*/*.t';

El comando tests toma una cadena para especificar los archivos de prueba. Puedes usar caracteres comodín, y si quieres ejecutar pruebas en varios directorios, concatena las especificaciones con espacios en blanco.

Si no has configurado "tests" de ninguna manera (con el comando explícito "tests", o extensiones como Module::Install::AuthorTests o Module::Install::ExtraTests), y si tienes un directorio "xt", Module::Install añade silenciosamente esas pruebas bajo el directorio "xt" cuando estás en modo autor, o estás haciendo pruebas de lanzamiento (con la variable ambiental "RELEASE_TESTING").

El valor establecido por tests se pasa a ExtUtils::MakeMaker como un atributo "test".

ARCHIVOS DE PRUEBA

Esta sección describe los comandos para generar, instalar, desinstalar y probar los archivos.

CREAR_ARCHIVOS_DE_PRUEBA (Module::Install::Test)

test_files
    't/foo.t',
    't/bar.t';
test_files 't/*.t';

El comando test_files toma un patrón de globbing o una lista de nombres de archivo, y genera las entradas apropiadas para Makefile.PL. El valor establecido por test_files se pasa a ExtUtils::MakeMaker como un atributo "TEST_FILES".

INSTALAR_ARCHIVOS_DE_PRUEBA (Module::Install::Test)

install_test_files;

El comando install_test_files le dice a Module::Install que instale los archivos de prueba en la instalación de Perl. Esto se usa principalmente para propósitos de depuración.

DESINSTALAR_ARCHIVOS_DE_PRUEBA (Module::Install::Test)

uninstall_test_files;

El comando uninstall_test_files hace que Module::Install desinstale los archivos de prueba. Esto también se usa principalmente para propósitos de depuración.

EJECUTAR_PRUEBAS_CON_PROVEEDOR (Module::Install::Test)

run_tests_with_prove;

El comando run_tests_with_prove hace que Module::Install use prove para ejecutar las pruebas. Esto se usa principalmente para propósitos de depuración.

COMANDO_PARA_EJECUTAR_PRUEBAS_EN_SUBDIRECTORIOS (Module::Install::Test)

build_test_subdirs;

El comando build_test_subdirs es un alias para build_subdirs (ver más abajo) que solo toma subdirectorios que contienen pruebas.

BUSCAR_ARCHIVOS_DE_PRUEBA_EN_SUBDIRECTORIOS (Module::Install::Test)

find_test_files;

El comando find_test_files busca archivos de prueba en el directorio actual y busca archivos de prueba en él recursivamente. Al momento de escribir esto, no puede usar este comando con otros comandos relacionados con pruebas.

COMANDOS PARA AJUSTAR DIRECTORIOS DE INSTALACIÓN

INSTALAR_DIRECTORIOS (Module::Install::Metadata)

installdirs 'site';

El comando installdirs toma un tipo de directorio y cambia un directorio para instalar módulos y así sucesivamente, aunque normalmente no necesita usarlo. El valor establecido por installdirs se pasa a ExtUtils::MakeMaker como un atributo "INSTALLDIRS".

INSTALAR_COMO_PRINCIPAL, INSTALAR_COMO_CPAN, INSTALAR_COMO_SITIO, INSTALAR_COMO_PROVEEDOR (Module::Install::Metadata)

install_as_core;   # = installdirs 'perl';
install_as_cpan;   # = installdirs 'site';
install_as_site;   # = installdirs 'site';
install_as_vendor; # = installdirs 'vendor';

Los comandos install_as_* son alias de los comandos correspondientes que se muestran en los comentarios anteriores.

COMANDOS PARA INSTALAR ARCHIVOS SUBORDINADOS

Estos son para instalar archivos que no sean los del directorio "lib".

INSTALAR_SCRIPT (Module::Install::Scripts)

install_script('foo');
install_script('script/foo');

El comando install_script toma el nombre de un archivo de script y lo instala en un directorio "script" para su instalación de Perl. Si su script está en un directorio "script", puede omitir la parte "script/".

El valor establecido por install_script se pasa a ExtUtils::MakeMaker como un atributo "EXE_FILES".

INSTALAR_COMPARTIDO (Module::Install::Share)

install_share;
install_share('templates');
install_share('dist', 'templates');
install_share('module', 'My::WebApp', 'share');

El comando install_share puede tomar un tipo de directorio (ya sea "dist" o "module"), un nombre de módulo si es necesario, y un directorio ("share" por defecto), e instala los archivos bajo el directorio en un directorio "share" para el tipo, que generalmente se encuentra en un directorio donde está instalado su perl (pero esto puede no ser cierto si está usando local::lib y similares).

Puede acceder a estos archivos compartidos a través de "dist_file" o "module_file" de File::ShareDir según el tipo. Tenga en cuenta también que un directorio compartido suele ser de solo lectura. No puede usarlo como un directorio temporal privado.

COMANDOS PARA INSTALACIÓN AUTOMÁTICA

AUTO_INSTALAR (Module::Install::AutoInstall)

auto_install;

El comando auto_install se utiliza para permitir a los usuarios instalar dependencias de un proyecto local cuando ejecutan "make" después de "<perl Makefile.PL">. En el pasado, esta era la única forma sensata de obtener dependencias adicionales sin instalar el módulo real, aunque ahora existen algunas alternativas (que sin embargo **no** reemplazan completamente "auto_install"). Por ejemplo, puede usar "cpan ." (con CPAN más reciente) o "cpanm --installdeps ." (con App::cpanminus).

"auto_install" también habilita los comandos feature(s) para elegir qué instalar (tenga en cuenta que el uso de feature() en distribuciones de CPAN generalmente se considera una mala práctica).

COMANDOS PARA INSTALACIÓN EN SUBDIRECTORIOS

Module::Install 0.96 y superior instalan distribuciones en los subdirectorios por defecto, al igual que ExtUtils::MakeMaker. También puede especificar qué instalar uno por uno.

CONSTRUIR_SUBDIRECTORIOS (Module::Install::Makefile)

build_subdirs 'win32' if $^O eq 'MSWin32';

El comando build_subdirs toma subdirectorios donde se encuentran los proyectos que desea instalar. Los valores establecidos por build_subdirs se pasan a ExtUtils::MakeMaker como un atributo "DIR".

COMANDOS PARA PROPORCIONAR METADATOS OPCIONALES ADICIONALES

Estos son para proporcionar metadatos opcionales utilizados principalmente por el indexador de PAUSE y el sitio de búsqueda de CPAN. Consulte también la página META-spec (http://module-build.sourceforge.net/META-spec.html) para obtener más detalles.

NO_INDEX (Module::Install::Metadata)

no_index file      => 'lib/My/Test/Module.pm';
no_index directory => 'templates';
no_index package   => 'Test::Foo::Bar';
no_index namespace => 'Test::Foo::Bar';

El comando no_index toma un hash para describir qué debe excluirse del índice de PAUSE, etc. Module::Install proporciona varios directorios "no_index" por defecto, incluidos "inc", "share", "(x)t", "test", ejemplo(s), "demo".

RECURSOS (Module::Install::Metadata)

resources
  license     => "http://dev.perl.org/licenses",
  homepage    => "http://yourproject.host.org",
  bugtracker  => "http://rt.cpan.org/NoAuth/Bugs.html?Dist=Foo-Bar",
  repository  => "http://yourhost.com/myscm",
  MailingList => "http://yourhost.com/listinfo/foo-bar";

El comando resources toma un hash que contiene varias URL para los recursos relacionados. Las claves en minúsculas están reservadas. Estos recursos se escriben en "META.yml".

HOMEPAGE, BUGTRACKER, REPOSITORY (Module::Install::Metadata)

homepage   'http://example.com';
bugtracker 'http://rt.cpan.org';
repository 'http://github.com/foo/bar';

Los comandos homepage, bugtracker y "repository" toman una URL para el recurso correspondiente.

COMANDOS PARA EMPAQUETAR DISTRIBUCIONES

Existen varios comandos para empaquetar módulos/distribuciones en su distribución, pero en general todavía están rotos. No los use por ahora.

COMANDOS PARA SOPORTE XS

LIBS (Module::Install::Makefile), CC_LIB_PATHS, CC_LIB_LINKS (Module::Install::Compiler)

libs '-lz';
libs [qw/-lz -Llibs/];
cc_lib_paths 'libs';
cc_lib_links qw/z iconv/;

El comando libs toma una cadena o una referencia a un array de cadenas que se pasarán a ExtUtils::MakeMaker como un atributo "LIBS". cc_lib_paths y cc_lib_links son sus alternativas, ambas toman un array de cadenas. "cc_lib_paths" es para "-L" en mayúsculas (directorios), y "cc_lib_links" es para "-l" en minúsculas (bibliotecas).

INC (Module::Install::Makefile), CC_INC_PATHS (Module::Install::Compiler)

inc '-I. -Iinclude';
cc_inc_paths qw/. include/;

El comando inc toma una cadena que se pasará a ExtUtils::MakeMaker como un atributo "INC". cc_inc_paths es su alternativa, y toma un array de directorios.

CC_OPTIMIZE_FLAGS (Module::Install::Compiler)

cc_optimize_flags '-O2';

El comando cc_optimize_flags toma una cadena que se pasará a ExtUtils::MakeMaker como un atributo "OPTIMIZE".

PPPORT (Module::Install::Compiler)

ppport;

El comando ppport se utiliza para empaquetar "ppport.h" en una distribución.

REQUIERE_CC_EXTERNO (Module::Install::External)

requires_external_cc;

El comando requires_external_cc hace que Module::Install genere un archivo de configuración que verifique la presencia de un compilador C externo.

COMANDOS PARA LIMPIEZA

clean_files, realclean_files (Module::Install::Makefile)

clean_files '*.o Foo-*';
realclean_files '*.o Foo-*';

El comando clean_files toma una cadena o un array de cadenas, las concatena con espacios y pasa el resultado a ExtUtils::MakeMaker como un atributo "clean". realclean_files hace lo mismo para un atributo "realclean".

COMANDOS UTILITARIOS

can_use (Module::Install::Can)

if (can_use('Some::Module', '0.05')) {
  Some::Module::do_something();
}

El comando can_use toma el nombre de un módulo y, opcionalmente, una versión, y verifica si el módulo (con la versión si es apropiado) está instalado o no.

can_run (Module::Install::Can)

if (can_run('svn')) {
  # hacer algo con el binario C<svn>
}

El comando can_run toma la ruta de un ejecutable y verifica si el ejecutable está disponible o no.

requires_external_bin (Module::Install::External)

requires_external_bin 'svn';

El comando requires_external_bin toma la ruta de un ejecutable y sale de "Makefile.PL" si no hay ninguno disponible.
