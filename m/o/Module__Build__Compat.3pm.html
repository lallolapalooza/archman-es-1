Module::Build::Compat(3pm) Documentación de Perl contribuida por el usuario Module::Build::Compat(3pm)

NOMBRE

Module::Build::Compat - Compatibilidad con ExtUtils::MakeMaker

SINOPSIS

# En un Build.PL :
use Module::Build;
my $build = Module::Build->new
  ( module_name => 'Foo::Bar',
    license     => 'perl',
    create_makefile_pl => 'traditional' );
...

DESCRIPCIÓN

Dado que "ExtUtils::MakeMaker" ha sido la forma estándar de distribuir módulos durante mucho tiempo, muchas herramientas (CPAN.pm, o tu administrador de sistema) pueden esperar encontrar un Makefile.PL funcional en cada distribución que descarguen de CPAN. Si quieres facilitarles las cosas, puedes usar "Module::Build::Compat" para generar automáticamente un Makefile.PL, en uno de varios estilos diferentes.

"Module::Build::Compat" también proporciona código que ayuda al Makefile.PL en tiempo de ejecución.

ADVERTENCIA

Ten en cuenta que "Module::Build::Compat" causa más problemas de instalación de los que resuelve, y cada uno de los tres estilos de generación de Makefile.PL tiene problemas de compatibilidad o funcionalidad únicos que es poco probable que se solucionen. Por lo tanto, se desaconseja el uso de este módulo y de "create_makefile_pl".

MÉTODOS

create_makefile_pl($style, $build)
Crea un Makefile.PL en el directorio actual en uno de varios estilos, basado en el objeto "Module::Build" $build proporcionado. Esto se controla típicamente pasando el estilo deseado como parámetro "create_makefile_pl" al método new() de "Module::Build"; el Makefile.PL se creará automáticamente durante la acción "distdir".

Los estilos actualmente soportados son:

traditional
Se creará un Makefile.PL en el estilo "tradicional", es decir, usará "ExtUtils::MakeMaker" y no dependerá de "Module::Build" en absoluto. Para crear el Makefile.PL, incluiremos las dependencias "requires" y "build_requires" como parámetro "PREREQ_PM".

No querrás usar este estilo si durante la etapa "perl Build.PL" haces preguntas al usuario, o realizas alguna detección automática sobre el entorno del usuario, o si creas una subclase de "Module::Build" para hacer alguna personalización, porque el Makefile.PL genérico no hará nada de eso. Muchas características estándar de "Module::Build" como "test_requires" tampoco son soportadas.

small
Se creará un pequeño Makefile.PL que pasará toda la funcionalidad al script Build.PL en el mismo directorio. El usuario debe tener ya instalado "Module::Build", de lo contrario recibirá un error de módulo no encontrado.

Este estilo intenta (con éxito variable) traducir el protocolo de Makefile.PL a Build.PL, y es innecesario en cualquier cadena de herramientas moderna que reconozca los metadatos de "configure_requires" descritos a continuación, ya que Build.PL se ejecutará por defecto en este caso. Consulta https://rt.cpan.org/Public/Bug/Display.html?id=75936 para un ejemplo de los problemas que puede causar.

passthrough (OBSOLETO)
Esto es igual que la opción "small" anterior, pero si "Module::Build" aún no está instalado en el sistema del usuario, el script ofrecerá usar "CPAN.pm" para descargarlo e instalarlo antes de continuar con la compilación.

Esta opción ha sido deprecada y puede ser eliminada en una futura versión de Module::Build. CPAN.pm y CPANPLUS modernos reconocerán la propiedad de metadatos "configure_requires" e instalarán Module::Build antes de ejecutar Build.PL si Module::Build se lista y Module::Build ahora se añade a configure_requires por defecto.

Perl 5.10.1 incluye soporte para "configure_requires". En el futuro, cuando el soporte para "configure_requires" se considere suficientemente extendido, se eliminará el estilo "passthrough".

run_build_pl(args => \@ARGV)
Este método ejecuta el script Build.PL, pasándole cualquier argumento que el usuario pueda haber proporcionado al comando "perl Makefile.PL". Dado que "ExtUtils::MakeMaker" y "Module::Build" aceptan argumentos diferentes, este método también realiza una traducción entre ambos.

run_build_pl() acepta los siguientes parámetros con nombre:

args
El parámetro "args" especifica los parámetros que normalmente aparecerían en la línea de comandos del comando "perl Makefile.PL"; normalmente solo pasarás una referencia a @ARGV.
script
Este es el nombre del archivo del script a ejecutar; por defecto es "Build.PL".
write_makefile()
Este método escribe un Makefile 'ficticio' que pasará todos los comandos a las acciones correspondientes de "Module::Build".

write_makefile() acepta los siguientes parámetros con nombre:

makefile
El nombre del archivo a escribir; por defecto es la cadena "Makefile".

ESCENARIOS

Así, algunos escenarios comunes son:

1.
Simplemente incluye un script Build.PL (sin script Makefile.PL) y proporciona instrucciones de instalación en un documento README o INSTALL explicando cómo instalar el módulo. En particular, explica que el usuario debe instalar "Module::Build" antes de instalar tu módulo.

Ten en cuenta que si haces esto, puedes facilitarte las cosas, pero dificultárselas a las personas con versiones antiguas de CPAN o CPANPLUS en su sistema, ya que esas herramientas generalmente solo entienden la forma Makefile.PL/"ExtUtils::MakeMaker" de hacer las cosas.

2.
Incluye un script Build.PL y un Makefile.PL "tradicional", creado manualmente o con create_makefile_pl(). Los usuarios nunca tendrán que instalar "Module::Build" si usan el Makefile.PL, pero tampoco podrán aprovechar las funciones adicionales de "Module::Build".

Para mayor seguridad, por supuesto, prueba tanto el Makefile.PL como el Build.PL antes de publicarlo.

NOMBRE

Module::Build::Compat

SINOPSIS

use Module::Build::Compat;

DESCRIPCIÓN

Module::Build::Compat es un módulo de compatibilidad para Module::Build.

ADVERTENCIA

Este módulo no está completamente probado y puede contener errores.

MÉTODOS

Este módulo proporciona los siguientes métodos:

  • compat()

  • compat_build()

  • compat_clean()

  • compat_install()

  • compat_run()

ESCENARIOS

Este módulo es útil en los siguientes escenarios:

  • Compatibilidad con versiones antiguas de CPAN y CPANPLUS.

  • Uso con Module::Build.

  • Uso con ExtUtils::MakeMaker.
