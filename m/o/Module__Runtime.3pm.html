NOMBRE

Module::Runtime - manejo de módulos en tiempo de ejecución

SINOPSIS

use Module::Runtime qw(
    $module_name_rx is_module_name check_module_name
    module_notional_filename require_module);
if($module_name =~ /\A$module_name_rx\z/o) { ...
if(is_module_name($module_name)) { ...
check_module_name($module_name);
$notional_filename = module_notional_filename($module_name);
require_module($module_name);
use Module::Runtime qw(use_module use_package_optimistically);
$bi = use_module("Math::BigInt", 1.31)->new("1_234");
$widget = use_package_optimistically("Local::Widget")->new;
use Module::Runtime qw(
    $top_module_spec_rx $sub_module_spec_rx
    is_module_spec check_module_spec
    compose_module_name);
if($spec =~ /\A$top_module_spec_rx\z/o) { ...
if($spec =~ /\A$sub_module_spec_rx\z/o) { ...
if(is_module_spec("Standard::Prefix", $spec)) { ...
check_module_spec("Standard::Prefix", $spec);
$module_name = compose_module_name("Standard::Prefix", $spec);

DESCRIPCIÓN

Las funciones exportadas por este módulo se ocupan del manejo en tiempo de ejecución de módulos de Perl, que normalmente se manejan en tiempo de compilación. Este módulo evita usar cualquier otro módulo, para que pueda ser utilizado en infraestructura de bajo nivel.

Las partes de este módulo que trabajan con nombres de módulos aplican la misma sintaxis que se utiliza para las palabras clave desnudas en el código fuente de Perl. En principio, esta sintaxis puede variar entre versiones de Perl, y este módulo aplica la sintaxis del Perl en el que se está ejecutando. En la práctica, la sintaxis utilizable aún no ha cambiado. Hay cierta intención de que los nombres de módulos Unicode sean compatibles en el futuro, pero esto aún no ha resultado en ninguna instalación coherente.

Las funciones de este módulo cuyo propósito es cargar módulos incluyen soluciones alternativas para tres errores antiguos del núcleo de Perl relacionados con "require". Estas soluciones alternativas se aplican en cualquier versión de Perl donde existan los errores, excepto en un caso donde uno de los errores no se puede solucionar adecuadamente en Perl puro.

Sintaxis del nombre del módulo

La sintaxis utilizable del nombre del módulo no ha cambiado desde Perl 5.000 hasta Perl 5.19.8. La sintaxis está compuesta enteramente por caracteres ASCII. Desde Perl 5.6 en adelante, ha habido un intento de permitir el uso de caracteres Unicode no ASCII en el código fuente de Perl, pero estaba fundamentalmente roto (como toda la manipulación de Unicode de Perl 5.6) y permaneció prácticamente inutilizable hasta que recibió algo de atención en la serie Perl 5.15. Aunque Unicode ahora es aceptado consistentemente por el analizador en algunos lugares, sigue estando roto para los nombres de módulos. Además, todavía no ha habido ningún trabajo sobre cómo mapear los nombres de módulos Unicode a nombres de archivo, por lo que en ese aspecto también los nombres de módulos Unicode son inutilizables.

La sintaxis del nombre del módulo es, precisamente: la cadena debe consistir en uno o más segmentos separados por "::"; cada segmento debe consistir en uno o más caracteres identificadores (alfanuméricos ASCII más "_"); el primer carácter de la cadena no debe ser un dígito. Por lo tanto, ""IO::File"", ""warnings"", y ""foo::123::x_0"" son todos nombres de módulos válidos, mientras que ""IO::"" y ""1foo::bar"" no lo son. Los separadores de "'" no son permitidos por este módulo, aunque siguen siendo utilizables en el código fuente de Perl, siendo traducidos a "::" en el analizador.

Errores del núcleo solucionados

El primer error solucionado es el error central [perl #68590], que provoca que el estado léxico en un archivo se filtre a otro que se carga/usa desde él. Este error está presente desde Perl 5.6 hasta Perl 5.10, y se soluciona en Perl 5.11.0. Desde Perl 5.9.4 hasta Perl 5.10.0 no es posible una solución satisfactoria en Perl puro. La solución implica que los módulos cargados a través de este módulo no sufren esta contaminación de su estado léxico. Los módulos cargados de otras maneras, o a través de este módulo en las versiones de Perl donde la solución en Perl puro es imposible, permanecen vulnerables. El módulo Lexical::SealRequireHints proporciona una solución completa para este error.

El segundo error solucionado provoca ciertos tipos de fallos en la carga de módulos, principalmente errores de compilación en el módulo cargado, que se registran en %INC como si hubieran tenido éxito, por lo que los intentos posteriores de cargar el mismo módulo indican inmediatamente éxito. Este error está presente hasta Perl 5.8.9 y se soluciona en Perl 5.9.0. La solución implica que un error de compilación en un módulo cargado a través de este módulo no se almacenará en caché como un éxito. Los módulos cargados de otras maneras siguen siendo susceptibles de producir entradas falsas en %INC, y si existe una entrada falsa, engañará a este módulo si se utiliza para intentar cargar de nuevo.

El tercer error solucionado provoca que se vea el contexto incorrecto en el ámbito del archivo de un módulo cargado, si "require" se invoca en una ubicación que hereda el contexto de un ámbito superior. Este error está presente hasta Perl 5.11.2 y se soluciona en Perl 5.11.3. La solución implica que un módulo cargado a través de este módulo siempre verá el contexto correcto. Los módulos cargados de otras maneras permanecen vulnerables.

EXPRESIONES REGULARES

Estas expresiones regulares no incluyen anclajes, por lo que para verificar si una cadena completa coincide con un elemento de sintaxis, debe proporcionar los anclajes usted mismo.

$module_name_rx
Coincide con un nombre de módulo de Perl válido en sintaxis de palabra clave desnuda.
$top_module_spec_rx
Coincide con una especificación de módulo para usar con "compose_module_name", donde no se está utilizando ningún prefijo.
$sub_module_spec_rx
Coincide con una especificación de módulo para usar con "compose_module_name", donde se está utilizando un prefijo.

FUNCIONES

Manejo básico de módulos

is_module_name(ARG)
Devuelve un valor verdadero indicando si ARG es una cadena simple que cumple con la sintaxis del nombre de módulo de Perl, como se describe para "$module_name_rx".
is_valid_module_name(ARG)
Alias obsoleto para "is_module_name".
check_module_name(ARG)
Verifica si ARG es una cadena simple que cumple con la sintaxis del nombre de módulo de Perl, como se describe para "$module_name_rx". Retorna normalmente si lo es, o ejecuta "die" si no lo es.
module_notional_filename(NAME)
Genera un nombre de archivo relativo teórico para un módulo, que se utiliza en algunas interfaces principales de Perl. NAME es una cadena, que debería ser un nombre de módulo válido (uno o más segmentos separados por "::"). Si no es un nombre válido, la función ejecuta "die".

Se genera y devuelve el nombre de archivo teórico para el módulo nombrado. Este nombre de archivo está siempre en estilo Unix, con separadores de directorio "/" y un sufijo ".pm". Este tipo de nombre de archivo puede usarse como argumento para "require", y es la clave que aparece en %INC para identificar un módulo, independientemente de la sintaxis real del nombre de archivo local.

require_module(NAME)
Esencialmente, esta es la forma de palabra clave desnuda de "require", en forma de tiempo de ejecución. NAME es una cadena, que debe ser un nombre de módulo válido (uno o más segmentos separados por "::"). Si no es un nombre válido, la función ejecuta "die".

NAME

Module::Runtime - runtime evaluation of Perl modules

SYNOPSIS

    use Module::Runtime qw(require_module use_module);

    # Load a module and possibly call a method on it
    my $obj = use_module('Foo::Bar', '1.23')->new();

    # Load a module, but don't do anything else with it
    require_module('Baz::Quux');

DESCRIPTION

This module provides functions for loading Perl modules at runtime. It is primarily intended for use by other modules that need to load modules dynamically, such as those that use the base pragma, or that need to construct module names from user input.

REGULAR EXPRESSIONS

This module provides no regular expressions.

FUNCTIONS

Basic module loading

require_module(NAME[,VERSION])
This function loads a Perl module. The module name is given by NAME, which should be a string like "Foo::Bar". It is handled exactly like a bareword module name in a "require" statement. That is, a search through @INC is performed, and a byte-compiled form of the module will be used if available.

If a VERSION is specified, the "VERSION" method of the loaded module is called with the specified VERSION as an argument. This normally serves to ensure that the version loaded is at least the version required. This is the same functionality provided by the VERSION parameter of "use".

The return value is as for "require". That is, it is the value returned by the module itself if the module is loaded anew, or 1 if the module was already loaded.

Structured module use

use_module(NAME[, VERSION])
This is essentially "use" in runtime form, but without the importing feature (which is fundamentally a compile-time thing). The NAME is handled just like in "require_module" above: it must be a module name, and the named module is loaded as if by the bareword form of "require".

If a VERSION is specified, the "VERSION" method of the loaded module is called with the specified VERSION as an argument. This normally serves to ensure that the version loaded is at least the version required. This is the same functionality provided by the VERSION parameter of "use".

On success, the name of the module is returned. This is unlike "require_module", and is done so that the entire call to "use_module" can be used as a class name to call a constructor, as in the example in the synopsis.

use_package_optimistically(NAME[, VERSION])
This is an analogue of "use_module" for the situation where there is uncertainty as to whether a package/class is defined in its own module or by some other means. It attempts to arrange for the named package to be available, either by loading a module or by doing nothing and hoping.

An attempt is made to load the named module (as if by the bareword form of "require"). If the module cannot be found then it is assumed that the package was actually already loaded by other means, and no error is signaled. That's the optimistic bit.

Warning: this optional module loading is liable to cause unreliable behaviour, including security problems. It interacts especially badly with having "." in @INC, which was the default state of affairs in Perls prior to 5.25.11. If a package is actually defined by some means other than a module, then applying this function to it causes a spurious attempt to load a module that is expected to be non-existent. If a module actually exists under that name then it will be unintentionally loaded. If "." is in @INC and this code is ever run with the current directory being one writable by a malicious user (such as /tmp), then the malicious user can easily cause the victim to run arbitrary code, by creating a module file under the predictable spuriously-loaded name in the writable directory. Generally, optional module loading should be avoided.

This is mostly the same operation that is performed by the base pragma to ensure that the specified base classes are available. The behaviour of base was simplified in version 2.18, and later improved in version 2.20, and on both occasions this function changed to match.

If a VERSION is specified, the "VERSION" method of the loaded package is called with the specified VERSION as an argument. This normally serves to ensure that the version loaded is at least the version required. On success, the name of the package is returned. These aspects of the function work just like "use_module".

Module name composition

is_module_spec(PREFIX, SPEC)
Returns a truth value indicating whether SPEC is valid input for "compose_module_name". See below for what that entails. Whether a PREFIX is supplied affects the validity of SPEC, but the exact value of the prefix is unimportant, so this function treats PREFIX as a truth value.
is_valid_module_spec(PREFIX, SPEC)
Deprecated alias for "is_module_spec".
check_module_spec(PREFIX, SPEC)
Check whether SPEC is valid input for "compose_module_name". Return normally if it is, or "die" if it is not.
compose_module_name(PREFIX, SPEC)
This function is intended to make it more convenient for a user to specify a Perl module name at runtime. Users have greater need for abbreviations and context-sensitivity than programmers, and Perl module names get a little unwieldy. SPEC is what the user specifies, and this function translates it into a module name in standard form, which it returns.

SPEC has syntax approximately that of a standard module name: it should consist of one or more name segments, each of which consists of one or more identifier characters. However, "/" is permitted as a separator, in addition to the standard "::". The two separators are entirely interchangeable.

Additionally, if PREFIX is not "undef" then it must be a module name in standard form, and it is prefixed to the user-specified name. The user can inhibit the prefix addition by starting SPEC with a separator (either "/" or "::").

BUGS

On Perl versions 5.7.2 to 5.8.8, if "require" is overridden by the "CORE::GLOBAL" mechanism, it is likely to break the heuristics used by "use_package_optimistically", making it signal an error for a missing module rather than assume that it was already loaded. From Perl 5.8.9 onward, and on 5.7.1 and earlier, this module can avoid being confused by such an override. On the affected versions, a "require" override might be installed by Lexical::SealRequireHints, if something requires its bugfix but for some reason its XS implementation isn't available.
