Module::Install(3) Documentación de contribuciones de Perl Module::Install(3)

NOMBRE

Module::Install - Instalador de paquetes de Perl estandar y extensible

SINTAXIS DE USO

En tu archivo Makefile.PL (uso recomendado):

use inc::Module::Install;

Definir metadatos:

name           'Tu-Módulo';

Dependencias específicas:

requires       'File::Spec'  => '0.80';

Dependencias de prueba:

test_requires  'Test::More'  => '0.42';

Recomendaciones:

recommends     'Text::CSV_XS'=> '0.50';

No indexar:

no_index       'directory'   => 'demos';

Escribir el script de instalación:

install_script 'myscript';

Ejemplo de actualización rápida de un instalador antiguo:

use inc::Module::Install;

Escribe Makefile.PL:

WriteMakefile( ... );

ADVERTENCIA

Nota: Aunque Module::Install introdujo muchas ideas geniales en su tiempo, sus principales beneficios han sido mejor alcanzados por el autor de Dist::Zilla y sus derivados Dist::Milla y Minilla. Estas herramientas permiten a los autores crear y mantener distribuciones con una conveniencia de DWIM, mientras que la distribución se instala directamente por ExtUtils::MakeMaker o herramientas de instalación similares, evitando la complejidad de incluir el instalador. Dist::Zilla tiene un sistema de plugins más robusto que facilita mantenerse al día con los cambios de CPAN::Meta::Spec y agregar otras funcionalidades nuevas. Por tanto, el uso de Module::Install para nuevas distribuciones es desaconsejado por los mantenedores.

DESCRIPCIÓN

Module::Install es un paquete para escribir instaladores de distribuciones CPAN (o similares) que son limpias, simples, minimalistas, actúan correctamente con ExtUtils::MakeMaker y funcionan en cualquier instalación de Perl versión 5.005 o superior.

El propósito es hacerlo tan fácil como sea posible para los autores de CPAN (y especialmente para autores nuevos de CPAN) tener instaladores que sigan todas las mejores prácticas para la instalación de distribuciones, pero involucrarse lo más posible en el DWIM (Do What I Mean) al escribirlos.

Escribir instaladores de Module::Install

El modo más rápido de empezar con Module::Install es copiar el texto de "SYNOPSIS" anterior y guardarlo como tu propio Makefile.PL. Luego modifica el archivo según tu caso particular, utilizando la lista de comandos documentada en "COMANDOS COMUNES" a continuación.

Si solo quieres escribir un instalador, hazlo ahora. No necesitas el resto de esta descripción a menos que estés interesado en los detalles.

Cómo funciona

El motivo detrás de Module::Install es que las distribuciones necesitan interactuar con una gran cantidad de diferentes versiones de Perl y de instaladores de módulos, principalmente con CPAN.pm, CPANPLUS.pm, ExtUtils::MakeMaker y Module::Build.

Estos han acumulado un perfil de características y errores muy variados a lo largo del tiempo, y ahora es muy difícil escribir un instalador que funcione correctamente solo utilizando las versiones instaladas de estos módulos.

Por ejemplo, la versión CPAN.pm que viene con Perl 5.005 es ahora más de cinco años antigua y considerada muy inestable, pero aún existe en varios equipos de máquinas antiguas.

En lugar de intentar dirigirse a un único instalador y/o hacerte añadir expresiones de trabajo alrededor de cada bloque de código de instalación, Module::Install copia parte de sí mismo en cada distribución de módulos que crea.

Esto permite utilizar mejoras nuevas en tus instaladores independientemente de la edad de la distribución en la que se instale, a costa de un pequeño aumento en el tamaño de tu distribución.

Historia

Este módulo fue originalmente escrito por Brian Ingerson como sustituto inteligente para ExtUtils::MakeMaker.

Para más información, vea el artículo de The Perl Journal de junio de 2003, "Creating Module Distributions with Module::Install" (http://www.drdobbs.com/web-development/creating-module-distributions-with-modul/184416018).

Para más información y opiniones personales sobre el módulo y su creación, vea Module::Install::Philosophy.

COMANDOS COMUNES

Los siguientes son los comandos más comunes utilizados en instaladores.

No es una lista exhaustiva, ya que muchos de los plugins proporcionan comandos más detallados que normalmente necesitarías.

name

name 'Mi-Módulo';

El comando "name" es un comando obligatorio, generalmente el primero.

Proporciona el nombre de tu distribución, que para un módulo como "Tu::Módulo" sería normalmente "Tu-Módulo".

Este esquema de nombres no es estricto y deberías notar que las distribuciones son realmente un esquema de nombres distinto de los módulos.

Por ejemplo, los módulos LWP vienen en una distribución llamada "libwww-perl"."

all_from

all_from 'lib/Mi/Módulo.pm';

Para distribuciones simples de Perl que tienen un módulo o clase dominante, puedes obtener la mayor cantidad de funcionalidad DWIM mediante el comando "all_from", que intentará extraer la mayor cantidad de metadatos posible de los archivos Perl y POD en ese módulo principal.

Funcionalmente, "all_from" es equivalente a "abstract_from" + "author_from" + "version_from" + "license_from" + "perl_version_from". Véase más detalles a continuación.

Si algún valor es ya definido antes de que se use "all_from", estos valores se mantendrán y no serán reescritos.

abstract

abstract 'Esta distribución hace algo';

Todas las distribuciones tienen un abstract, una descripción breve de la distribución como un todo. Es normalmente de 30 a 70 caracteres.

El comando "abstract" se utiliza para establecer explícitamente el abstract para la distribución, al menos en cuanto el archivo de metadatos de la distribución se preocupe.

abstract_from

abstract_from 'lib/Mi/Módulo.pm';

El comando "abstract_from" recoge el abstract de un archivo específico que se encuentra dentro de la distribución. Normalmente se hace así desde el módulo principal, donde Module::Install leerá el POD y utilizará lo que encuentre en la sección "=head1 NAME" (con el nombre del módulo sin el prefijo "Module::").

El "abstract_from" se establece como parte del "all_from".

author

author 'Adam Kennedy <adamk@cpan.org>';

La metadata de la distribución contiene información sobre el autor principal o el mantenidor si el autor original no está más involucrado. Debería generalmente ser especificado en forma de dirección de correo electrónico.

Si no quieres revelar una dirección de correo real, debes usar la dirección "CPANID@cpan.org" que recibe automáticamente cuando obtienes tu cuenta de PAUSE.

El comando "author" se utiliza para establecer explícitamente este valor.

author_from

author_from 'lib/Mi/Módulo.pm';

El comando "author_from" recoge el autor de un archivo específico que se encuentra dentro de la distribución. Normalmente se hace así usando el módulo principal, donde Module::Install leerá el POD y utilizará lo que pueda encontrar en la sección "=head1 AUTHOR" (con el nombre del autor).

version

version '0.01';

La "version" se usa para especificar la versión de la distribución, para distinguirla de la versión de cualquier módulo dentro de la distribución.

Sin embargo, en casi todos los casos querrás que coincida con la versión del módulo principal de la distribución, lo cual puedes hacer usando "version_from".

version_from

version_from 'lib/My/Module.pm';

La "version_from" obtiene la versión de la distribución de un archivo específico contenido en el paquete de distribución. La mayoría de las veces, esto se hace desde el módulo principal.

"version_from" buscará la primera ocurrencia de $VERSION y usará el mismo valor, usando una técnica consistente con otras herramientas de escaneo de versiones de módulos.

license

license 'perl';

La "license" especifica la licencia para la distribución.

En la mayoría de los casos, este valor será 'perl', que significa "la misma que la de Perl mismo". Otros valores permitidos incluyen 'gpl', 'lgpl', 'bsd', 'MIT' y 'artistic'.

Este valor siempre se considera un resumen, y es normal incluir un archivo LICENSE en la distribución que contenga la licencia completa para la distribución.

También se recuerda que si la distribución está prevista para ser subida a CPAN, **debe** ser una licencia abierta de acuerdo con la OSI. El software comercial no está permitido en CPAN.

license_from

license_from 'lib/My/Module.pm';

La "license_from" obtiene la licencia de la distribución de un archivo específico contenido en el paquete de distribución. La mayoría de las veces, esto se hace desde el módulo principal.

"license_from" buscará en el archivo especificado una sección de licencia o copyright y buscará varias cadenas que identifiquen el tipo general de licencia.

Actualmente, solo admite los 6 valores mencionados en la suma de "license".

perl_version

perl_version '5.006';

El "perl_version" se utiliza para especificar la versión mínima de la interpretación de Perl que requiere tu distribución.

Al especificar la versión, debes intentar usar la cadena de versión normalizada. Las partes de la versión de Perl tienen 3 dígitos, por lo que una dependencia de Perl 5.6 se convertirá en '5.006' y una versión de Perl 5.10.2 se convertirá en '5.010002'.

perl_version_from

perl_version_from 'lib/My/Module.pm'

El "perl_version_from" obtiene la versión mínima de la interpretación de Perl de un archivo específico contenido en el paquete de distribución. La mayoría de las veces, esto se hace desde el módulo principal.

La versión mínima se detecta buscando llamadas a la pragma "use 5.xxx" en el archivo del módulo.

recommends

recommends 'Text::CSV_XS' => '0.50'

El "recommends" indica un módulo opcional en tiempo de ejecución que proporciona funcionalidad adicional. Las dependencias recomendadas no son necesarias para construir o probar tu distribución, pero se consideran "buenas de tener".

Al igual que con "requires", la dependencia se basa en un **módulo**, no en una distribución. Una versión de cero indica que cualquier versión del módulo es recomendada.

requires

requires 'List::Util' => 0;
requires 'LWP'        => '5.69';

El "requires" indica una dependencia de ejecución normal de tu distribución en otro módulo. La mayoría de las distribuciones incluirán una de estas instrucciones, indicando los módulos necesarios para CPAN (u otros).

Una dependencia "requires" se puede verbalizar como "Si quieres instalar y usar esta distribución, primero debes instalar estos módulos".

Ten en cuenta que la dependencia se basa en un **módulo**, no en una distribución. Esto asegura que tu dependencia sea siempre correcta, incluso si el módulo se mueve o se mezcla con otra distribución, lo cual es a veces posible.

Una dependencia de versión cero indica que **cualquier** versión del módulo es suficiente. Las versiones deben generalmente citarse para mayor claridad.

test_requires

test_requires 'Test::More' => '0.47';

El "test_requires" indica una dependencia de script de prueba para tu distribución. El formato de especificación es idéntico al de "requires".

El "test_requires" es distinto de "requires" en que indica un módulo que se necesita **solo** durante la prueba de la distribución (a menudo un período de tiempo corto) pero no se necesita después de la instalación de la distribución.

El "test_requires" se utiliza para permitir al instalador tener flexibilidad en cómo proporciona el módulo, y para permitir a los empaquetadores (Debian, FreeBSD, ActivePerl, etc.) mantener solo las dependencias necesarias para la ejecución en tiempo real.

El "include" se usa a veces junto con "test_requires" para incluir un módulo bien probado en el paquete de distribución, además de que el usuario lo instale directamente desde CPAN.

configure_requires

configure_requires 'File::Spec' => '0.80';

El "configure_requires" indica una dependencia de configuración para tu distribución. El formato de especificación es idéntico al de "requires".

El "configure_requires" se utiliza para evitar el dilema de cómo usar un módulo CPAN en tu Makefile.PL, cuando tienes que cargar Makefile.PL (y por lo tanto el módulo CPAN) para saber que lo necesitas.

Tradicionalmente, esto no se podía romper y, por lo tanto, los scripts Makefile.PL tenían que depender de enfoques de denominador común o incluir esas dependencias con el comando "include".

El "configure_requires" crea un registro en la clave especial "configure_requires:" en el archivo META.yml de la distribución.

Aunque gran parte de META.yml se considera consultiva, un cliente CPAN tratará el contenido de "configure_requires:" como autoritativo e instalará los módulos mencionados **antes** de ejecutar "Makefile.PL" (de donde luego determinará otras dependencias).

Tenga en cuenta que el soporte para "configure_requires:" en clientes CPAN no es 100% completo en el momento de escribir esto y aún no se puede confiar plenamente.

Debido a que **Module::Install** en sí mismo solo admite 5.005, se añadirá silenciosamente una instrucción equivalente de "configure_requires( perl => '5.005' );" a tu distribución.

requires_external_bin

requires_external_bin 'cvs';

Como parte de su papel como lenguaje de unión principal, muchísimos módulos de Perl ejecutan comandos o programas en el sistema anfitrión.

El "requires_external_bin" se utiliza para verificar que un comando particular esté disponible en el sistema anfitrión.

Mientras que un módulo de Perl faltante es resoluble en tiempo de compilación, un binario externo faltante no lo es y, por lo tanto, la ejecución de "Makefile.PL" abortará con un resultado 'NA' (No Aplicable).

En el futuro, este comando también agregará información adicional a los metadatos de la distribución, permitiendo que los auto-empaquetadores de sistemas operativos específicos descubran automáticamente los paquetes no de Perl necesarios como dependencia.

install_script

# The following are equivalent
install_script 'script/scriptname'

El "install_script" proporciona soporte para la instalación de scripts que se convertirán en comandos en la terminal tanto en Unix como en Windows (en este último caso, mediante un archivo .bat).

Ten en cuenta que es habitual no colocar un .pl al final de estos scripts, para que se sientan más naturales cuando se usen.

En el ejemplo anterior, el programa script/scriptname podría ejecutarse después de la instalación simplemente haciendo lo siguiente:

> scriptname
Running scriptname 0.01...
>

Por convención, los scripts deben estar ubicados en una carpeta /script dentro de tu distribución. Para admitir menos tipos de entrada, si un script está ubicado en la carpeta script, solo debes referirte a él por su nombre.

# The following are equivalent
install_script 'foo';
install_script 'script/foo';

no_index

no_index directory => 'examples';
no_index package   => 'DB';

A menudo una distribución proporciona scripts de ejemplo o módulos de prueba (.pm) además de los módulos de librería reales.

En casi todos los casos, no querrás que estos se indexen en el índice de CPAN, los paquetes maestros de Perl.

FAQ

¿Cuáles son los beneficios de usar Module::Install?

Here is a brief rundown of the reasons:

  • It is very easy for beginners to learn.
  • It does everything that ExtUtils::MakeMaker does.
  • It does everything with a much simpler syntax.
  • It automatically scans for metadata.
  • It requires no installation for end-users.
  • It is future-proofed.
  • It automatically updates your MANIFEST.
  • It is easy to distribute scripts.
  • It includes prerequisite modules (fewer dependencies to install).
  • It automatically installs prerequisite modules.
  • It supports Inline-based modules.
  • It supports shared data files with File::ShareDir.
  • It supports pre-compiled binaries.
  • It handles installation problems on Windows.

By reducing and simplifying the syntax, Module::Install makes the work required to maintain your Makefile.PLs minimal.

And if you maintain more than one module that requires non-standard installation tricks, you can create a custom distribution module to abstract away this complexity.

Module::Install no está a 1.00 aún, ¿es seguro usarlo aún?

As long as you are going to periodically do incremental releases to get any bug fixes and new functionality, yes.

If you don't plan to do incremental releases, it might be a good idea to continue to wait for a while.

COOKBOOK / EJEMPLOS

The following are real-world examples of Makefile.PL files using Module::Install.

Method::Alias

Method::Alias is an extremely small utility module, with the smallest possible Makefile.PL.

use inc::Module::Install;
name          'Method-Alias';
all_from      'lib/Method/Alias.pm';
test_requires 'Test::More' => '0.42';

File::HomeDir

File::HomeDir locates your home directory on any platform. It needs an installer that can handle different dependencies on different platforms.

use inc::Module::Install;
name          'File-HomeDir';
all_from      'lib/File/HomeDir.pm';
requires      'File::Spec' => '0.80';
test_requires 'Test::More' => '0.47';
if ( $MacPerl::Version ) {
    # Needed on legacy Mac OS 9
    requires 'Mac::Files' => 0;
}
if ( $^O eq 'MXWin32' ) {
    # Needed on Windows platforms
    requires 'Win32::TieRegistry' => 0;
}
WriteAll;
