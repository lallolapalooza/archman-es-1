Munin::Plugin::SNMP(3pm) Documentación de Perl contribuida por el usuario Munin::Plugin::SNMP(3pm)

NOMBRE

Munin::Plugin::SNMP - Subclase de Net::SNMP para plugins de Munin

SINOPSIS

El módulo Munin::Plugin::SNMP extiende Net::SNMP con métodos útiles para plugins de Munin.

CONFIGURACIÓN SNMP

Los plugins SNMP (que usan este módulo) comparten una interfaz de configuración común implementada en la función session(). Por favor, consulta la documentación de dicha función para obtener instrucciones completas y ejemplos sobre cómo configurar SNMP. La documentación se encuentra allí para asegurar que esté actualizada y coincida con el código.

DEPURACIÓN

Se pueden habilitar mensajes de depuración adicionales configurando $Munin::Plugin::SNMP::DEBUG, $Munin::Plugin::DEBUG, o exportando la variable de entorno "MUNIN_DEBUG" antes de ejecutar el plugin (pasando la opción "--pidebug" a "munin-run", por ejemplo).

MÉTODOS

config_session() - Decodifica el entorno para obtener los parámetros de configuración del plugin necesarios

($host, $port, $version, $tail) = Munin::Plugin::SNMP->config_session();

Esta es una función de conveniencia para la parte de "config" del plugin: decodifica el entorno/nombre del plugin para recuperar la información necesaria en la fase de configuración. Devuelve una tupla de 4 elementos que consiste en:

1) el nombre del host
2) el puerto UDP a utilizar
3) la versión SNMP a utilizar (3 para la versión 3, 2 para la versión 1 o 2c)
4) la cola del nombre del plugin: lo que quede del nombre del plugin después de "snmp_<host>_".

La cola puede ser interesante también para la parte de "fetch" del plugin.

session([opciones_opcionales_de_Net::SNMP]) - crea un nuevo objeto Munin::Plugin::SNMP

$session = Munin::Plugin::SNMP->session();

Este método anula el constructor de Net::SNMP para obtener la información de conexión del nombre del plugin y/o del entorno. Ten en cuenta que no se devuelve ninguna cadena de error. La función maneja los errores internamente, mostrando un mensaje de error y llamando a `die`. Llamar a `die` es lo correcto.

El nombre del host se toma del enlace simbólico del plugin, que debe tener la forma "snmp[v3]_<nombre_del_host>_<nombre_del_plugin>[_argumentos]".

La forma "v3" se utiliza para indicar que se debe usar SNMPv3. También es un truco de nombres que proporciona un "espacio de nombres" separado para los dispositivos que usan SNMPv3, de modo que se pueda configurar por separado en archivos de munin/plugin-conf.d/. Por ejemplo:

[snmp_*]
   env.version 2
   env.community public
[snmpv3_*]
   env.v3username snmpoperator
   env.v3authpassword s3cr1tpa55w0rd

Consulta más abajo cómo configurar para cada caso diferente. El primer caso anterior muestra la configuración predeterminada de Munin.

NOTA: munin-node-configure aún no utiliza la opción "v3".

Se consultan las siguientes variables de entorno:

"env.host"
Si el nombre del plugin (enlace simbólico) no contiene el nombre del host, este se utiliza como el nombre del host al que conectarse.

El nombre del host debe especificarse, pero generalmente se especifica en el nombre del plugin. Si el nombre del host de alguna manera no se resuelve en DNS (o en el archivo de hosts), es posible hacer esto:

[snmp_*]
   env.version 2c
   env.community floppa
[snmp_switch1.langfeldt.net]
   env.host 192.168.2.45
[snmp_switch2.langfeldt.net]
   env.host 192.168.2.46
"env.port"
El puerto al que conectarse. Predeterminado: 161.
"env.timeout"
El tiempo de espera en segundos a utilizar. Predeterminado: 5.
"env.domain"
El Dominio de Transporte a utilizar para intercambiar mensajes SNMP. El valor predeterminado es UDP/IPv4. Valores posibles: 'udp', 'udp4', 'udp/ipv4'; 'udp6', 'udp/ipv6'; 'tcp', 'tcp4', 'tcp/ipv4'; 'tcp6', 'tcp/ipv6'.
"env.version"
La versión SNMP a utilizar para la conexión. Una de 1, 2, 3, snmpv1, snmpv2c o snmpv3. SNMP v2 es mejor ya que admite operaciones masivas. Por lo tanto, 2 es el valor predeterminado en "Munin::Plugin::SNMP". Si tu dispositivo admite v3, podría ser aún mejor, ya que admite seguridad adecuada, pero el cifrado puede ralentizar las cosas.

La seguridad se maneja de manera diferente para las versiones 1/2c y 3. Consulta más abajo.

Autenticación SNMP 1/2c
"env.community"
El nombre de la comunidad para agentes de versión 1 y 2c. El valor predeterminado es 'public'. Si esto funciona, tu dispositivo probablemente sea muy inseguro y necesite una revisión de seguridad.
Autenticación SNMP 3
SNMP v3 tiene tres niveles de seguridad. El más bajo es "noAuthNoPriv", que no proporciona autenticación ni cifrado. Si se proporcionan un nombre de usuario y "authpassword", aumenta a "authNoPriv", y la conexión se autentica. Si se proporciona "privpassword", el nivel de seguridad se convierte en "authPriv": la conexión se autentica y cifra.

Nota: El cifrado puede ralentizar dispositivos de red lentos o muy cargados. Para la mayoría de los usos, "authNoPriv" será suficientemente seguro, ya que la contraseña se envía a través de la red cifrada (hash unidireccional) en cualquier caso.

"Munin::Plugin::SNMP" no admite ContextEngineIDs y similares para autenticación/privacidad. Si ves la necesidad y sabes cómo hacerlo, ¡envía parches!

Para más información sobre los modelos de seguridad de SNMP v3, consulta RFC3414 y la documentación de Net::SNMP.

Si la versión se establece en 3 o snmpv3, las siguientes variables se utilizan para definir la autenticación:

"env.v3username"
Nombre de usuario. No hay valor predeterminado.
"env.v3authpassword"
Contraseña de autenticación. Opcional cuando también está habilitado el cifrado, en cuyo caso tiene como valor predeterminado la contraseña de privacidad ("env.v3privpassword"). La contraseña se envía cifrada (hash unidireccional) a través de la red.
"env.v3authprotocol"
Protocolo de autenticación. Uno de 'md5' o 'sha' (HMAC-MD5-96, RFC1321 y SHA-1/HMAC-SHA-96, NIST FIPS PIB 180, RFC2264). El valor predeterminado es 'md5'.
"env.v3privpassword"
Contraseña de privacidad para habilitar el cifrado. Una contraseña vacía ('') se considera sin contraseña y no habilitará el cifrado.

La privacidad requiere un v3privprotocol así como un v3authprotocol y un v3authpassword, pero todos estos tienen valores predeterminados (a 'des', 'md5' y el valor de v3privpassword, respectivamente) y, por lo tanto, pueden dejarse sin especificar.

"env.v3privprotocol"
Si se establece v3privpassword, esta configuración controla qué tipo de cifrado se utiliza para lograr la privacidad en la sesión. Solo se admite oficialmente el método de cifrado 'des', que es muy débil. El valor predeterminado es 'des'.

El módulo perl de implementación (Net::SNMP) también admite '3des' (CBC-3DES-EDE, también conocido como Triple-DES, NIST FIPS 46-3) según se especifica en el borrador de la IETF draft-reeder-snmpv3-usm-3desede. Si esto funciona o no con un dispositivo en particular, no lo sabemos.

Munin::Plugin::SNMP(3pm) - Perl manual page

NAME

Munin::Plugin::SNMP - SNMP base class for Munin plugins

SYNOPSIS

  use Munin::Plugin::SNMP;
  use Munin::Plugin::SNMP qw(get_hash get_single get_by_regex);

  # ... inside a plugin's config() or get() method ...

  my $session = Munin::Plugin::SNMP->new(
      -host    => $ENV{'MUNIN_NODE_hostname'},
      -port    => $ENV{'MUNIN_NODE_port'},
      -timeout => 10,
  );

  # ... use methods like get_hash() etc ...

SNMP CONFIGURATION

This module uses SNMPv2c and Community strings for authentication. The Community string must be configured in /etc/munin/plugin-conf.d/snmp or ~/.munin/plugin-conf.d/snmp.

The file has to be owned by root and only readable by root.

  [snmp]
    user  munin
    group munin
    env.SNMP_COMMUNITY  my_snmp_community_string
    env.SNMP_PORT       161
    env.SNMP_TIMEOUT    5
    env.SNMP_VERSION    2

See munin-node.conf(5) for details.

DEBUGGING

Set the SNMP_DEBUG environment variable to enable verbose debugging output.

  SNMP_DEBUG=1 munin-run ifoperstatus

METHODS

new() - Constructor

Creates a new SNMP session. Takes the same arguments as Net::SNMP's `session` method. Default values for port, timeout and version are set to 161, 5 and 2 respectively, which is suitable for SNMPv2c.

  my $session = Munin::Plugin::SNMP->new(
      -host    => $ENV{'MUNIN_NODE_hostname'},
      -port    => $ENV{'MUNIN_NODE_port'},
      -timeout => 10,
  );

get_entries() - Retrieve a table of values

Retrieves a table of values based on a base OID and a hash mapping OID suffixes to column names.

The method is designed to be used for tabular data. It expects that the OID for each value ends with a unique index number.

Returns a hash where the keys are the index numbers, and the values are hashes containing the column names and their corresponding values.

  my $iface_data = $session->get_entries(
      -baseoid => '1.3.6.1.2.1.2.2.1', # IF-MIB::ifEntry
      -cols    => {
                    1 => 'index',     # IF-MIB::ifIndex
                    2 => 'descr',     # IF-MIB::ifDescr
                    3 => 'type',      # IF-MIB::ifType
                    4 => 'mtu',       # IF-MIB::ifMtu
                    5 => 'speed',     # IF-MIB::ifSpeed
                    7 => 'physaddr',  # IF-MIB::ifPhysAddress
                    8 => 'adminstatus', # IF-MIB::ifAdminStatus
                    9 => 'operstatus',  # IF-MIB::ifOperStatus
                   }
  );

The above example would return a hash like:

'1' => {
        'adminstatus' => '1',
        'mtu' => '32768',
        'descr' => 'lo0',
        'operstatus' => '2',
        'physaddr' => '0:0:0:0:0:0',
        'index' => '1',
        'type' => 'softwareLoopback(24)',
        'speed' => '0'
       },
'2' => {
        'adminstatus' => '1',
        'mtu' => '1500',
        'descr' => 'lna0',
        'operstatus' => '1',
        'physaddr' => '0:1:0:0:0:0',
        'index' => '2',
        'type' => 'ethernetCsmacd(6)',
        'speed' => '10000000'
       }

If all OIDs are unavailable, an empty hash reference is returned.

get_hash() - Retrieve a table of values as a nested hash

This method is similar to get_entries(), but the keys of the main hash are derived from the OID suffixes.

The keys of the main hash are the last element(s) of the OIDs, after $oid and the matching keys from %columns are removed. The values are hashes with keys corresponding to the values of %columns hash and values from the subtables corresponding to the keys of %columns.

For this to work, all the keys of "-cols" must have the same number of elements. Also, don't try to specify a next-to-next-to-leaf-node baseoid, the principle it breaks both "get_entries" and the logic in "get_hash".

If (all) the OIDs are unavailable a defined but empty hashref is returned.

Example:

$session->get_hash(
             -baseoid => '1.3.6.1.2.1.2.2.1', # IF-MIB
             -cols    => {
                          1 => 'index',
                          2 => 'descr',
                          4 => 'mtu',
                         }
          );

given the following SNMP table:

IF-MIB::ifIndex.1 = INTEGER: 1
IF-MIB::ifIndex.2 = INTEGER: 2
IF-MIB::ifDescr.1 = STRING: lo0
IF-MIB::ifDescr.2 = STRING: lna0
IF-MIB::ifType.1 = INTEGER: softwareLoopback(24)
IF-MIB::ifType.2 = INTEGER: ethernetCsmacd(6)
IF-MIB::ifMtu.1 = INTEGER: 32768
IF-MIB::ifMtu.2 = INTEGER: 1500
...

will return a hash like this:

'1' => {
        'index' => '1',
        'mtu' => '32768',
        'descr' => 'lo0'
       },
'2' => {
        'index' => '2',
        'descr' => 'lna0',
        'mtu' => '1500'
       }

get_single() - Retrieve a single value by OID

$uptime = $session->get_single("1.3.6.1.2.1.1.3.0") || 'U';

If the call fails to get a value the above call sets $uptime to 'U' which Munin interprets as "Undefined" and handles accordingly.

get_by_regex() - Retrieve table of values filtered by regex applied to the value

This example shows the usage for a netstat plugin.

my $tcpConnState = "1.3.6.1.2.1.6.13.1.1.";
my $connections = $session->get_by_regex($tcpConnState, "[1-9]");

It gets all OIDs based at $tcpConnState and only returns the ones that contain a number in the value.
