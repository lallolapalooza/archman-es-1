NOMBRE

MIME::Parser - clase experimental para analizar flujos MIME

SINOPSIS

Antes de seguir leyendo, deberías ver MIME::Tools para asegurarte de que entiendes dónde encaja este módulo en el gran esquema de las cosas. Adelante, hazlo ahora. Te esperaré.

¿Listo? Ok...

Ejemplos de uso básico

### Crea un nuevo objeto analizador:
my $parser = new MIME::Parser;
### Dile dónde poner las cosas:
$parser->output_under("/tmp");
### Analiza un manejador de entrada:
$entity = $parser->parse(\*STDIN);
### ¡Felicitaciones: ahora tienes una entidad MIME (posiblemente multipart)!
$entity->dump_skeleton;          # para depuración

Ejemplos de entrada

### Analiza desde manejadores de archivo:
$entity = $parser->parse(\*STDIN);
$entity = $parser->parse(IO::File->new("some command|");
### Analiza desde cualquier objeto que soporte getline() y read():
$entity = $parser->parse($myHandle);
### Analiza un mensaje MIME en memoria:
$entity = $parser->parse_data($message);
### Analiza un mensaje MIME en un archivo:
$entity = $parser->parse_open("/some/file.msg");
### Analiza un mensaje MIME de una tubería:
$entity = $parser->parse_open("gunzip - < file.msg.gz |");
### Analiza entrada ya dividida (tal como te la daría "deliver"):
$entity = $parser->parse_two("msg.head", "msg.body");

Ejemplos de control de salida

### Mantén los cuerpos de mensaje analizados en memoria (por defecto se envían al disco):
$parser->output_to_core(1);
### Envía cada cuerpo de mensaje a un directorio por mensaje:
$parser->output_under("/tmp");
### Envía cada cuerpo de mensaje al mismo directorio:
$parser->output_dir("/tmp");
### Cambia cómo se nombran los archivos de componentes de mensaje sin nombre:
$parser->output_prefix("msg");
### Coloca archivos temporales en otro lugar
$parser->tmp_dir("/var/tmp/mytmpdir");

Ejemplos de recuperación de errores

### Mecanismo normal:
eval { $entity = $parser->parse(\*STDIN) };
if ($@) {
    $results  = $parser->results;
    $decapitated = $parser->last_head;  ### obtiene la última cabecera de nivel superior
}
### Mecanismo ultra-tolerante:
$parser->ignore_errors(1);
$entity = eval { $parser->parse(\*STDIN) };
$error = ($@ || $parser->last_error);
### Limpia todos los archivos creados por el análisis:
eval { $entity = $parser->parse(\*STDIN) };
...
$parser->filer->purge;

Ejemplos de opciones del analizador

### ¿Intentar decodificar automáticamente los encabezados MIME RFC 2047?
$parser->decode_headers(1);             ### por defecto es falso
### ¿Analizar objetos contenidos "message/rfc822" como flujos MIME anidados?
$parser->extract_nested_messages(0);    ### por defecto es verdadero
### ¿Buscar uuencode en mensajes "text" y extraerlo?
$parser->extract_uuencode(1);           ### por defecto es falso
### ¿Deberíamos perdonar errores normalmente fatales?
$parser->ignore_errors(0);              ### por defecto es verdadero

Ejemplos varios

### Convertir un objeto Mail::Internet a un MIME::Entity:
my $data = join('', (@{$mail->header}, "\n", @{$mail->body}));
$entity = $parser->parse_data(\$data);

DESCRIPCIÓN

Puedes heredar de esta clase para crear tus propias subclases que analicen flujos MIME en objetos MIME::Entity.

INTERFAZ PÚBLICA

Construcción

new ARGS...
Método de clase. Crea un nuevo objeto analizador. Una vez que hagas esto, puedes configurar varios parámetros antes de realizar el análisis real. Por ejemplo: 
my $parser = new MIME::Parser;
$parser->output_dir("/tmp");
$parser->output_prefix("msg1");
my $entity = $parser->parse(\*STDIN);

Cualquier argumento se pasa a init(). No anules esto en tus subclases; anula init() en su lugar.

init ARGS...
Método de instancia. Inicializa un nuevo objeto MIME::Parser. Esto se envía automáticamente a un nuevo objeto; es posible que desees anularlo. Si anulas esto, asegúrate de invocar el método heredado.
init_parse
Método de instancia. Se invoca automáticamente cada vez que se llama a uno de los métodos parse() de nivel superior, para restablecer el analizador a un estado de "listo".

Alterar cómo se analizan los mensajes

decode_headers [SÍNO]
Método de instancia. Controla si el analizador intentará decodificar todos los encabezados MIME (según RFC 2047) en el momento en que los vea. Esto no es aconsejable por dos razones muy importantes:
  • Arruina la extracción de información de los campos MIME. Si decodificas completamente los encabezados en bytes, puedes transformar inadvertidamente un encabezado MIME analizable como este: 
    Content-type: text/plain; filename="=?ISO-8859-1?Q?Hi=22Ho?="

    en galimatías inanalizables; en este caso:

    Content-type: text/plain; filename="Hi"Ho"
  • Pierde información. Una cadena codificada que contiene caracteres tanto latinos como cirílicos se convertirá en una mezcla binaria que simplemente no se puede representar.

Historial. Este método fue una vez la única forma disponible para tratar con archivos adjuntos cuyos nombres de archivo tenían caracteres no ASCII. Sin embargo, desde MIME-tools 5.4xx ya no es necesario.

Parámetros. Si YESNO es verdadero, se realiza la decodificación. Sin embargo, recibirás una advertencia a menos que uses uno de los valores especiales "verdaderos":

"I_NEED_TO_FIX_THIS"
       Simplemente cállate y hazlo. No recomendado.
       Proporcionado solo para aquellos que necesitan mantener scripts antiguos en funcionamiento.
"I_KNOW_WHAT_I_AM_DOING"
       Simplemente cállate y hazlo. No recomendado.
       Proporcionado para aquellos que REALMENTE saben lo que están haciendo.

Si YESNO es falso (el valor predeterminado), no se intentará decodificar. Sin argumentos, simplemente devuelve la configuración actual. Recuerda: siempre puedes decodificar los encabezados *después* de que el análisis se haya completado (ver MIME::Head::decode()), o decodificar las palabras bajo demanda (ver MIME::Words).

extract_nested_messages OPCIÓN
Método de instancia. Algunos mensajes MIME contendrán una parte de tipo "message/rfc822" ,"message/partial" o "message/external-body": literalmente, el texto de un mensaje incrustado de correo/noticias/etc. Esta opción controla si (y cómo) analizamos ese mensaje incrustado.

Si la OPCIÓN es falsa, tratamos dicho mensaje como si fuera un documento "text/plain", sin intentar decodificar su contenido.

Si la OPCIÓN es verdadera (el valor predeterminado), el cuerpo de la parte "message/rfc822" o "message/partial" es analizado por este analizador, creando un objeto entidad. Lo que sucede entonces está determinado por la OPCIÓN real:

NEST o 1
La configuración predeterminada. El mensaje contenido se convierte en la única "parte" de la entidad "message/rfc822" (como si el mensaje contenedor fuera un tipo especial de mensaje "multipart"). Puedes recuperar la sub-entidad invocando el método parts() en la entidad "message/rfc822"

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

Gracias a Andreas Koenig por sugerir este método.

extract_uuencode [YESNO]
Método de instancia. Si se establece en true, entonces cuando se encuentre un mensaje cuyo tipo de contenido efectivo sea "text/plain" y su codificación sea 7bit/8bit/binary, el cuerpo codificado se analizará para ver si contiene datos codificados en uu (generalmente señalados por una línea "begin XXX").

Si es así, el mensaje codificado se descompone en un multipart, donde el texto antes de la primera línea "begin XXX" se convierte en la primera parte, y todas las secciones "begin...end" subsiguientes se convierten en las partes siguientes. El nombre de archivo (si se especifica) será accesible a través de los medios normales.

ignore_errors [YESNO]
Método de instancia. Controla si el parser intentará ignorar errores normalmente graves, tratándolos como advertencias y continuando con el análisis.

Si YESNO es true (el valor predeterminado), se toleran muchos errores de sintaxis. Si es false, los errores graves lanzan excepciones. Sin argumento, devuelve el valor actual.

decode_bodies [YESNO]
Método de instancia. Controla si el parser debe decodificar los cuerpos de las entidades. Si este valor es false (el valor predeterminado es true), todos los cuerpos de las entidades se mantendrán en su contenido codificado original.

Para evitar la doble codificación en el lado de la salida, MIME::Body->is_encoded se establece en false, lo que indica a MIME::Body que no codifique los datos nuevamente si se le ha solicitado codificar. Esto es especialmente útil cuando es importante que el contenido no se modifique, por ejemplo, si deseas calcular firmas OpenPGP a partir de él.

¡ADVERTENCIA! Los significados cambian significativamente si analiza mensajes MIME con esta opción habilitada, ya que MIME::Entity y MIME::Body *siempre* ven datos codificados ahora, mientras que el comportamiento predeterminado es trabajar con datos decodificados (y codificarlos solo si se solicita). Debe decodificar los datos usted mismo si desea tenerlos decodificados.

Por lo tanto, úselo solo si sabe exactamente lo que está haciendo y está seguro de que realmente lo necesita.

Analizar una fuente de entrada

parse_data DATOS
Método de instancia. Analiza un mensaje MIME ya en memoria. Internamente crea un manejador de archivos en memoria usando PerlIO.

Puede proporcionar los DATOS de cualquier manera...

  • Un escalar que almacena el mensaje. Se usará una referencia a este escalar internamente.
  • Una referencia a un escalar que almacena el mensaje. Esta referencia se usará internamente.
  • OBSOLETO

    Una referencia a un array de escalares. El array se concatena internamente en una cadena temporal, y se usa una referencia a la nueva cadena internamente.

    Es más eficiente pasar una referencia a un escalar, por lo que te recomiendo reestructurar tu código para usar esta interfaz. Si absolutamente necesitas pasar un array, puede ser mejor usar IO::ScalarArray en el código que llama a parse()

Devuelve el MIME::Entity analizado en caso de éxito.

parse INSTREAM
Método de instancia. Toma una transmisión MIME y la divide en sus entidades componentes.

El INSTREAM puede proporcionarse como un IO::File, un manejador de archivos globref (como "\*STDIN"), o como cualquier objeto que implemente la interfaz IO (que como mínimo implementa getline() y read()).

Devuelve el MIME::Entity analizado en caso de éxito. Lanza una excepción en caso de error. Si el mensaje tiene demasiadas partes (según lo establecido por max_parts), devuelve undef.

parse_open EXPR
Método de instancia. Interfaz conveniente a parse(). Simplemente proporcione a este método cualquier expresión que pueda usarse como segundo argumento a open() para abrir un manejador de archivos para lectura.

Devuelve el MIME::Entity analizado en caso de éxito. Lanza una excepción en caso de error.

parse_two HEADFILE, BODYFILE
Método de instancia. Interfaz conveniente a parse_open(), para programas que se ejecutan bajo manejadores de correo como deliver, que divide el mensaje de correo en un archivo de encabezado y un cuerpo. Simplemente proporcione a este método las rutas a los archivos correspondientes.

¡Advertencia! Se asume que, una vez concatenados los archivos, habrá una línea en blanco separando la parte del encabezado y el cuerpo.

¡Advertencia! La nueva implementación lee los archivos en un array de líneas para mayor portabilidad, en lugar de usar 'cat'. Esto puede ser un problema si sus mensajes son grandes.

Devuelve el MIME::Entity analizado en caso de éxito. Lanza una excepción en caso de error.

Especificar el destino de salida

¡Advertencia! En las versiones 5.212 y anteriores, esto se hacía a través de métodos de MIME::Parser. Sin embargo, dado que muchos usuarios han solicitado un control fino sobre cómo se realiza esto, la lógica se ha separado del parser y se ha colocado en su propia clase, MIME::Parser::Filer. Cada MIME::Parser maneja una instancia de una clase derivada de MIME::Parser::Filer para administrar la salida a disco (consulte MIME::Parser::Filer para obtener detalles).

La ventaja es que el código de MIME::Parser no se verá saturado con muchas cosas relacionadas con el disco. La desventaja es que la forma en que anula el comportamiento predeterminado cambiará.

Por ahora, todos los métodos públicos normales todavía se proporcionan, pero muchos son solo stubs que crean o delegan a la clase MIME::Parser::Filer subyacente.

filer [FILER]
Método de instancia. Obtiene/establece el objeto FILER utilizado para administrar la salida a disco. Este será una subclase de MIME::Parser::Filer.
output_dir DIRECTORIO
Método de instancia. Crea mensajes que se guardan directamente en el DIRECTORIO dado. Esto lo hace estableciendo el objeto subyacente en filer() a una nueva instancia de MIME::Parser::FileInto, y pasa los argumentos a su método new().

Nota: Este método reemplaza el objeto subyacente, por lo que debes invocarlo antes de realizar cambios en cualquier atributo del objeto, como el prefijo de salida; de lo contrario, esos cambios se perderán.

output_under BASEDIR, OPTS...
Método de instancia. Crea mensajes que se guardan directamente en subdirectorios de BASEDIR, uno por mensaje. Esto lo hace estableciendo el objeto subyacente en filer() a una nueva instancia de MIME::Parser::FileUnder, y pasa los argumentos a su método new().

Nota: Este método reemplaza el objeto subyacente, por lo que debes invocarlo antes de realizar cambios en cualquier atributo del objeto, como el prefijo de salida; de lo contrario, esos cambios se perderán.

output_path HEAD
Método de instancia, OBSOLETO. Dado un encabezado MIME para un archivo que se extraerá, genera una buena ruta de salida para el archivo extraído. Idéntico a la forma preferida: 
$parser->filer->output_path(...args...);

Delegamos esto al objeto subyacente filer()

output_prefix [PREFIX]
Método de instancia, OBSOLETO. Obtiene/establece la cadena corta con la que comenzarán todos los directorios de archivos extraídos (asumiendo que no hay un "nombre recomendado" mejor). Idéntico a la forma preferida: 
$parser->filer->output_prefix(...args...);

Delegamos esto al objeto subyacente filer()

evil_filename NAME
Método de instancia, OBSOLETO. Idéntico a la forma preferida: 
$parser->filer->evil_filename(...args...);

Delegamos esto al objeto subyacente filer()

max_parts NUM
Método de instancia. Limita el número de partes MIME que se analizarán.

Normalmente, las instancias de esta clase analizan un mensaje hasta el final. Los mensajes con muchas partes MIME pueden causar un consumo excesivo de memoria. Si invoca este método, el análisis se detendrá con die() si un mensaje tiene más de NUM partes.

Si NUM se establece en -1 (el valor predeterminado), no se establece ningún límite.

Sin argumento, devuelve el valor actual como un entero.

output_to_core YESNO
Método de instancia. Normalmente, las instancias de esta clase escriben todos sus datos de cuerpo decodificados en archivos en disco (a través de MIME::Body::File). Sin embargo, puede cambiar este comportamiento invocando este método antes de analizar:

Si YESNO es false (el valor predeterminado), todos los datos del cuerpo van a archivos en disco.

Si YESNO es true, todos los datos del cuerpo van a estructuras de datos en memoria. Esto es un poco arriesgado (¿qué pasa si alguien te envía un MPEG o...

Archivo Tar

tar_file
Método de instancia. Mantiene la configuración del archivo tar como un valor booleano.

tmp_to_core

tmp_to_core [YESNO]
Método de instancia. ¿Debería new_tmpfile() crear archivos temporales en disco o usar archivos en memoria? Normalmente permitimos la creación de archivos temporales en disco, ya que permite manejar grandes archivos adjuntos incluso cuando el núcleo está limitado.

use_inner_files

use_inner_files [YESNO]
ELIMINADO.

Método de instancia.

MIME::Parser ya no soporta IO::InnerFile, pero este método se mantiene por compatibilidad inversa. No hace nada.

Especificando clases a instanciar

interface ROL,[VALOR]
Método de instancia. Durante el análisis, el analizador normalmente crea instancias de ciertas clases, como MIME::Entity. Sin embargo, podrías querer crear una subclase del analizador que use tus propias clases experimentales de cabecera, entidad, etc. (por ejemplo, tu clase de "cabecera" puede proporcionar métodos adicionales orientados a MIME).

Si lo deseas, entonces este es el método que tu subclase debe invocar durante la inicialización. Usa como ejemplo:

package MiAnalizador;
@ISA = qw(MIME::Analizador);
...
sub init {
    my $self = shift;
    $self->SUPER::init(@_);        ### hacer la inicialización del padre
    $self->interface(ENTIDAD_CLASE => 'MIME::MiEntidad');
    $self->interface(CABECERA_CLASE   => 'MIME::MiCabecera');
    $self;                         ### devolver
}

Sin valor, devuelve el valor asociado con ese Rol actual.

new_body_for CABECERA

new_body_for CABECERA
Método de instancia. Dada la CABECERA de una parte que estamos analizando, devuelve un nuevo objeto de tipo MIME::Body (cualquiera que sea su subclase) para recibir los datos de esa parte.

Si has configurado la opción output_to_core a falso (el valor por defecto), entonces llamamos a output_path() y creamos un objeto MIME::Body::File en ese archivo.

Si has configurado la opción output_to_core a verdadero antes de analizar, entonces obtienes un objeto MIME::Body::InCore.

Si quieres que el analizador haga algo diferente, puedes sobreescribir este método en una subclase.

Creación de Archivos Temporales

tmp_dir DIRECTORIO
Método de instancia. Crea cualquier archivo temporal generado por este analizador en el directorio especificado.

Si se llama sin argumentos, devuelve el valor actual.

new_tmpfile

new_tmpfile
Método de instancia. Devuelve un handle de IO para almacenar datos temporales durante el análisis.

El valor por defecto usa MIME::Tools::tmpopen() para crear un archivo temporal nuevo, excepto si tmp_to_core() lo indica, pero puedes sobrescribirlo. No deberías necesitarlo.

El lugar donde se guardan los archivos temporales puede cambiarse por defecto en el análisis del parser con tmp_dir().

Resultados del análisis y recuperación de errores

last_error
Método de instancia. Devuelve el error (si existe) que ignoró en el último análisis.

ambiguous_content

ambiguous_content
Método de instancia. Devuelve verdadero si el mensaje más reciente tiene una o más entidades con contenido ambiguo. Consulta la documentación del método ambiguous_content de MIME::Entity para más detalles.

Nota: aunque estas dos llamadas a ambiguous_content devuelven el mismo resultado:

$entidad = $parser->parse($whatever_stream);
$parser->ambiguous_content();
$entidad->ambiguous_content();

La primera es más rápida porque simplemente devuelve los resultados detectados durante el análisis, mientras que la segunda ejecuta el código que verifica explícitamente el contenido ambiguo.

last_head

last_head
Método de instancia. Devuelve la cabecera MIME más alta del último stream que intentó analizar. Es útil para responder a usuarios que envían mensajes MIME mal formados. 
### Analiza un stream de entrada:
eval { $entidad = $parser->parse(\*STDIN) };
if (!$entidad) {    ### ¡falló el análisis!
    my $decabezado = $parser->last_head;
    ...
}

results

results
Método de instancia. Devuelve un objeto que contiene mucha información de la última entidad analizada. Este será una instancia de la clase MIME::Parser::Results.

OPTIMIZANDO TU ANALIZADOR

Maximizando la velocidad

Mejores mecanismos de entrada:

parse()                    SÍ (si le das un globref o una subclase de IO::File)
parse_open()               SÍ
parse_data()               NO  (ver abajo)
parse_two()                NO  (ver abajo)

Mejores configuraciones:

decode_headers()           *** (no hay diferencia real; 0 es ligeramente más rápido)
extract_nested_messages()  0   (puede ser ligeramente más rápido, pero generalmente querrás configurarlo a 1)
output_to_core()           0   (será mucho más rápido)
tmp_to_core()              0   (será mucho más rápido)

La I/O nativa es mucho más rápida que la I/O orientada a objetos. Es mucho más rápido usar <$foo> que $foo->getline. Para compatibilidad inversa, este módulo debe continuar usando I/O orientada a objetos en la mayoría de los lugares, pero si usas parse() con un archivo real (string, globref, o subclase de IO::File), MIME::Parser puede realizar algunas optimizaciones importantes.

La llamada parse_two() es muy ineficiente. Actualmente es solo una interfaz para parse_data(). Si tu sistema lo soporta, estás *mucho mejor* haciendo algo como:

$parser->parse_open("/bin/cat msg.head msg.body |");

Minimizando la memoria

Mejores mecanismos de entrada:

parse()                    SÍ
parse_open()               SÍ
parse_data()               NO  (la I/O en memoria consumirá el core)
parse_two()                NO  (la I/O en memoria consumirá el core)

Mejores configuraciones:

decode_headers()           *** (no hay diferencia real)
extract_nested_messages()  *** (no hay diferencia real)
output_to_core()           0   (usará mucha menos memoria)
                                tmp_to_core es 1)
tmp_to_core()              0   (usará mucha menos memoria)

Maximizando la tolerancia a MIME defectuoso

Mejores mecanismos de entrada:

parse()                    *** (no importa)
parse_open()               *** (no importa)
parse_data()               *** (no importa)
parse_two()                *** (no importa)

Mejores configuraciones:

decode_headers()           0   (evita el problema de las cabeceras mal codificadas)
extract_nested_messages()  0   (evita problemas con mensajes anidados defectuosos, pero a menudo querrás configurarlo a 1)
output_to_core()           *** (no importa)
tmp_to_core()              *** (no importa)

Evitando archivos temporales basados en disco

OPTIMIZING YOUR PARSER

Avoiding disk-based temporary files

Optimum input mechanisms:

parse()                    YES (if you give it a seekable handle)
parse_open()               YES (becomes a seekable handle)
parse_data()               NO  (unless you set tmp_to_core(1))
parse_two()                NO  (unless you set tmp_to_core(1))

Optimum settings:

decode_headers()           *** (doesn't matter)
extract_nested_messages()  *** (doesn't matter)
output_to_core()           *** (doesn't matter)
tmp_to_core()              1

You can veto tmpfiles entirely. You can set tmp_to_core() true: this will always use in-core I/O for the buffering (warning: this will slow down the parsing of messages with large attachments).

Final resort. You can always override new_tmpfile() in a subclass.

WARNINGS

Multipart messages are always read line-by-line
Multipart document parts are read line-by-line, so that the encapsulation boundaries may easily be detected. However, bad MIME composition agents (for example, naive CGI scripts) might return multipart documents where the parts are, say, unencoded bitmap files... and, consequently, where such "lines" might be veeeeeeeeery long indeed.

A better solution for this case would be to set up some form of state machine for input processing. This will be left for future versions.

Multipart parts read into temp files before decoding
In my original implementation, the MIME::Decoder classes had to be aware of encapsulation boundaries in multipart MIME documents. While this decode-while-parsing approach obviated the need for temporary files, it resulted in inflexible and complex decoder implementations.

The revised implementation uses a temporary file (a la tmpfile()) during parsing to hold the encoded portion of the current MIME document or part. This file is deleted automatically after the current part is decoded and the data is written to the "body stream" object; you'll never see it, and should never need to worry about it.

Some folks have asked for the ability to bypass this temp-file mechanism, I suppose because they assume it would slow down their application. I considered accommodating this wish, but the temp-file approach solves a lot of thorny problems in parsing, and it also protects against hidden bugs in user applications (what if you've directed the encoded part into a scalar, and someone unexpectedly sends you a 6 MB tar file?). Finally, I'm just not convinced that the temp-file use adds significant overhead.

Fuzzing of CRLF and newline on input
RFC 2045 dictates that MIME streams have lines terminated by CRLF ("\r\n"). However, it is extremely likely that folks will want to parse MIME streams where each line ends in the local newline character "\n" instead.

An attempt has been made to allow the parser to handle both CRLF and newline-terminated input.

Fuzzing of CRLF and newline on output
The "7bit" and "8bit" decoders will decode both a "\n" and a "\r\n" end-of-line sequence into a "\n".

The "binary" decoder (default if no encoding specified) still outputs stuff verbatim... so a MIME message with CRLFs and no explicit encoding will be output as a text file that, on many systems, will have an annoying ^M at the end of each line... but this is as it should be.

Inability to handle multipart boundaries that contain newlines
First, let's get something straight: this is an evil, EVIL practice, and is incompatible with RFC 2046... hence, it's not valid MIME.

If your mailer creates multipart boundary strings that contain newlines when they appear in the message body, give it two weeks notice and find another one. If your mail robot receives MIME mail like this, regard it as syntactically incorrect MIME, which it is.

Why do I say that? Well, in RFC 2046, the syntax of a boundary is given quite clearly:

boundary := 0*69<bchars> bcharsnospace
bchars := bcharsnospace / " "
bcharsnospace :=    DIGIT / ALPHA / "'" / "(" / ")" / "+" /"_"
             / "," / "-" / "." / "/" / ":" / "=" / "?"

All of which means that a valid boundary string cannot have newlines in it, and any newlines in such a string in the message header are expected to be solely the result of folding the string (i.e., inserting to-be-removed newlines for readability and line-shortening only).

Yet, there is at least one brain-damaged user agent out there that composes mail like this:

MIME-Version: 1.0
Content-type: multipart/mixed; boundary="----ABC-
 123----"
Subject: Hi... I'm a dork!
This is a multipart MIME message (yeah, right...)
----ABC-
 123----
Hi there!

We have got to discourage practices like this (and the recent file upload idiocy where binary files that are part of a multipart MIME message aren't base64-encoded) if we want MIME to stay relatively simple, and MIME parsers to be relatively robust.
