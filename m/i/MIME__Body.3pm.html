NOMBRE

MIME::Body - el cuerpo de un mensaje MIME

SINOPSIS

Antes de seguir leyendo, deberías ver MIME::Tools para asegurarte de que entiendes dónde encaja este módulo en el gran esquema de las cosas. ¡Vamos, hazlo ahora! Te esperaré.

¿Listo? Vale...

Obtención de cuerpos

### Obtener el manejador de cuerpo de un objeto MIME::Entity:
$body = $entity->bodyhandle;
### Crear un cuerpo que almacena datos en un archivo del disco:
$body = new MIME::Body::File "/ruta/al/archivo";
### Crear un cuerpo que almacena datos en un array en memoria:
$body = new MIME::Body::InCore \@strings;

Abrir, cerrar y usar manejadores de IO

### Escribir datos al cuerpo:
$IO = $body->open("w")      || die "abrir cuerpo: $!";
$IO->print($mensaje);
$IO->close                  || die "cerrar manejador de I/O: $!";
### Leer datos del cuerpo (en este caso, línea por línea):
$IO = $body->open("r")      || die "abrir cuerpo: $!";
while (defined($_ = $IO->getline)) {
    ### hacer cosas
}
$IO->close                  || die "cerrar manejador de I/O: $!";

Otra IO

### Volcar los datos del cuerpo CODIFICADOS a un manejador de archivo:
$body->print(\*STDOUT);
### Cargar todos los datos SIN CODIFICAR y ponerlos en un escalar:
$string = $body->as_string;
### Cargar todos los datos SIN CODIFICAR y ponerlos en un array de líneas:
@lines = $body->as_lines;

Trabajar directamente con rutas a archivos subyacentes

### ¿Dónde están los datos?
if (defined($body->path)) {   ### los datos están en el disco:
    print "los datos se almacenan externamente, en ", $body->path;
}
else {                        ### los datos están en memoria:
    print "los datos ya están en memoria, y son...\n", $body->as_string;
}
### Deshacerse de cualquier cosa en el disco:
$body->purge;

DESCRIPCIÓN

Los mensajes MIME pueden ser muy largos (por ejemplo, archivos tar, MPEG, etc.) o muy cortos (notas textuales breves, como en el correo ordinario). Los mensajes largos se almacenan mejor en archivos, mientras que los cortos quizás se almacenen mejor en memoria.

Esta clase es un intento de definir una interfaz común para objetos que contienen datos de mensajes, independientemente de cómo se almacenen físicamente los datos. La vida útil de un objeto "cuerpo" suele ser así:

1.
Se crea un objeto de cuerpo por un MIME::Parser durante el análisis. Es en este punto cuando se elige la subclase MIME::Body real, y se invoca a new(). (Por ejemplo: si los datos del cuerpo van a un archivo, es en este punto cuando se elige la clase MIME::Body::File, y el nombre del archivo).
2.
Se escriben datos en el cuerpo (normalmente por el analizador MIME) así: El cuerpo se abre para escribir, a través de open("w"). Esto eliminará cualquier contenido anterior y devolverá un "manejador de I/O" abierto para escribir. Los datos se escriben en este manejador de I/O, a través de print(). Luego, el manejador de I/O se cierra, a través de close().
3.
Se leen datos del cuerpo (normalmente por la aplicación del usuario) así: El cuerpo se abre para leer por una aplicación de usuario, a través de open("r"). Esto devolverá un "manejador de I/O" abierto para leer. Los datos se leen del manejador de I/O, a través de read(), getline() o getlines(). Luego, el manejador de I/O se cierra, a través de close().
4.
Se destruye el objeto de cuerpo.

Puedes escribir tus propias subclases, siempre que sigan la interfaz descrita a continuación. Los implementadores de subclases deben asumir que los pasos 2 y 3 pueden repetirse cualquier número de veces, y en órdenes diferentes (por ejemplo, 1-2-2-3-2-3-3-3-3-3-2-4).

En cualquier caso, una vez creado un MIME::Body, pides que se abra para leer o escribir, lo que te da un "manejador de i/o": luego usas los mismos mecanismos para leer o escribir en ese manejador, sin importar de qué clase sea.

Advertencia: a menos que sepas con certeza qué tipo de cuerpo tienes, no debes asumir que el cuerpo tiene un manejador de archivo subyacente.

INTERFAZ PÚBLICA

new ARGS...
Método de clase, constructor. Crea un nuevo cuerpo. Cualquier ARGS se envía a init().
init ARGS...
Método de instancia, abstracto, inicializador. Esto es llamado automáticamente por new(), con los argumentos dados a new(). Los argumentos son opcionales y dependen totalmente de la subclase. El método por defecto no hace nada.
as_lines
Método de instancia. Devuelve el contenido del cuerpo como un array de líneas (cada una terminada por un salto de línea, con la posible excepción de la última). Devuelve vacío en caso de fallo (¡Nota: indistinguible de un cuerpo vacío!).

Nota: el método por defecto obtiene los datos mediante llamadas repetidas a getline(); tu subclase podría querer anular esto.

as_string
Método de instancia. Devuelve los datos del cuerpo como una cadena (cargándolos en memoria si es necesario). Es mejor no hacer esto a menos que estés *seguro* de que el cuerpo es razonablemente pequeño. Devuelve una cadena vacía para un cuerpo vacío y undef en caso de fallo.

Nota: el método por defecto usa print(), que obtiene los datos mediante llamadas repetidas a read(); tu subclase podría querer anular esto.

binmode [ONOFF]
Método de instancia. Con argumento, indica si open() debe devolver un manejador de I/O al que se le haya activado binmode(). Sin argumento, simplemente devuelve el valor actual.
is_encoded [ONOFF]
Método de instancia. Si se establece en sí, no se aplica ninguna decodificación en la salida. Esta bandera es establecida por MIME::Parser, si el analizador se ejecuta en modo decode_bodies(0), para que el contenido se maneje sin modificaciones.
dup
Método de instancia. Duplica el manejador del cuerpo.

Advertencia: los datos externos en los manejadores de cuerpo *no* se copian a nuevos archivos. Cambiar los datos en el archivo de datos de un cuerpo, o purgar ese cuerpo, *afectará* a su duplicado. Los cuerpos con datos en memoria probablemente no necesiten preocuparse.

open READWRITE
Método de instancia, abstracto. Debe hacer lo necesario para abrir el cuerpo para escribir (si READWRITE es "w") o para leer (si el modo es "r").

Se espera que este método devuelva un objeto "manejador de I/O" en caso de éxito y undef en caso de error. Un manejador de I/O puede ser cualquier objeto que soporte un pequeño conjunto de métodos estándar para leer/escribir datos. Consulta la clase IO::Handle para ver un ejemplo.

path [PATH]
Método de instancia. Si estás almacenando los datos del cuerpo externamente (por ejemplo, en un archivo de disco), querrás dar a las aplicaciones la capacidad de acceder a esos datos, para su limpieza. Este método debe devolver la ruta a los datos, o undef si no hay ninguna.

Donde sea apropiado, la ruta *debe* ser una cadena simple, como un nombre de archivo. Con argumento, establece la RUTA, que debe ser undef si no hay ninguna.

print FILEHANDLE
Método de instancia. Envía los datos del cuerpo al manejador de archivo dado, o al actualmente seleccionado si no se proporciona ninguno.
purge
Método de instancia, abstracto. Elimina cualquier dato que resida externamente al programa (por ejemplo, en archivos de disco). Inmediatamente después de un purge(), path() debería devolver undef para indicar que los datos externos ya no están disponibles.

NAME

MIME::Body - Contenedor para datos de cuerpo MIME

SYNOPSIS

    use MIME::Body;
    use MIME::Entity;
    # ...
    my $entity = MIME::Entity->build($args);
    # ...
    my $body = $entity->bodyhandle;
    # ...
    # Acceso a través de IO::Handle
    $body->open("r");
    while (defined(my $line = $body->getline)) {
        # ...
    }
    $body->close;
    # ...
    # Abrir para escritura
    $body->open("w");
    $body->print("Some data\n");
    $body->close;
    # ...
    # Para obtener un handle de archivo
    my $path = $body->path;
    if (defined $path) {
        open my $fh, '<', $path or die $!;
        # ...
        close $fh;
    }
    # ...
    # Para obtener el contenido como una cadena
    my $string = $body->as_string;
    # ...
    # Para obtener el contenido como una lista de líneas
    my @lines = $body->as_lines;
    # ...
    # Crear un nuevo cuerpo MIME::Body::File
    my $body_file = MIME::Body::File->new("/path/to/file");
    # ...
    # Crear un nuevo cuerpo MIME::Body::Scalar
    my $body_scalar = MIME::Body::Scalar->new("some data");
    # ...
    # Crear un nuevo cuerpo MIME::Body::InCore
    my $body_incore = MIME::Body::InCore->new("some data");

DESCRIPTION

Los objetos MIME::Body son usados para representar el contenido de un mensaje MIME. MIME::Parser crea estos objetos internamente y los devuelve cuando se le solicita a través del método bodyhandle de un objeto MIME::Entity.

En general, no deberías necesitar crear objetos MIME::Body directamente. En su lugar, deberías obtenerlos de un objeto MIME::Entity, el cual se crea a partir de un archivo de mensaje MIME, o se construye a partir de datos.

Los objetos MIME::Body son flexibles en cuanto a cómo almacenan sus datos. Pueden almacenar datos en un archivo en disco, en una variable escalar en memoria, o en un array de escalares en memoria. La clase base es MIME::Body, y tiene varias subclases que implementan estas diferentes estrategias de almacenamiento.

Independientemente de cómo se almacenen los datos, todos los objetos MIME::Body deberían proporcionar una interfaz consistente para acceder a ellos. La interfaz más básica es la de IO::Handle. Esto significa que puedes llamar a los métodos estándar de IO::Handle en un objeto MIME::Body, como open, read, write, getline, close, etc.

Esto permite que el código que consume MIME::Entity escriba código que funcione con cualquier tipo de objeto MIME::Body, sin tener que preocuparse por los detalles de implementación subyacentes.

PUBLIC INTERFACE

Estos métodos son comunes a todas las subclases de MIME::Body.

open(MODE)
Abre el cuerpo para leer o escribir, según MODE. MODE puede ser "r", "w", "a", o "r+". Devuelve un handle de archivo (un objeto IO::Handle o una subclase de él).
close()
Cierra el handle de archivo asociado con el cuerpo.
read(BUFFER, LENGTH)
Lee hasta LENGTH bytes del cuerpo en BUFFER. Devuelve el número de bytes leídos, o undef en EOF.
write(STRING)
Escribe STRING en el cuerpo.
binmode([ONOFF])
Establece o obtiene el modo binario del cuerpo. Si se proporciona ONOFF, establece el modo binario. Si no, devuelve el estado actual.
path()
Si el cuerpo está almacenado en un archivo, devuelve la ruta de ese archivo. De lo contrario, devuelve undef.
as_lines()
Devuelve el contenido del cuerpo como una lista de líneas (escalares terminados en newline).
as_string()
Devuelve el contenido del cuerpo como una sola cadena.
dup()
Crea y devuelve una copia duplicada del objeto MIME::Body.
init(ARGS...)
Método de inicialización. Llamado por el constructor.
print(FILES...)
Imprime el contenido del cuerpo en los archivos o handles de archivo dados.
purge()
Libera cualquier recurso asociado con el cuerpo (por ejemplo, archivos temporales).

SUBCLASSES

Aquí hay una descripción de las subclases de MIME::Body proporcionadas con MIME::Tools.

data in:        returns:
--------------------------------------------------------
MIME::Body::File     archivo en disco       IO::Handle
MIME::Body::Scalar   escalado             IO::Handle
MIME::Body::InCore   array de escalados    IO::Handle

MIME::Body::File

Una clase de cuerpo que almacena los datos en un archivo en disco. Llama al constructor así:

$body = new MIME::Body::File "/path/to/file";

En este caso, el método path() devuelve la ruta dada, así que puedes decir:

if (defined($body->path)) {
    open BODY, $body->path or die "open: $!";
    while (<BODY>) {
        ### hacer algo
    }
    close BODY;
}

Pero es mejor no hacer esto.

MIME::Body::Scalar

Una clase de cuerpo que almacena los datos en memoria, en un escalar sencillo. Llama al constructor así:

$body = new MIME::Body::Scalar \$string;

Un argumento único de escalar establece el cuerpo a ese valor, exactamente como si hubieras abierto el cuerpo para escritura, escrito el valor y cerrado el cuerpo de nuevo:

$body = new MIME::Body::Scalar "Line 1\nLine 2\nLine 3";

Un único array de referencias establece el cuerpo a la concatenación de todos los elementos de ese array:

$body = new MIME::Body::Scalar ["Line 1\n",
                                "Line 2\n",
                                "Line 3"];

MIME::Body::InCore

Una clase de cuerpo que almacena los datos en memoria. Llama al constructor así:

$body = new MIME::Body::InCore \$string;
$body = new MIME::Body::InCore  $string;
$body = new MIME::Body::InCore \@stringarray

Un argumento único de escalar establece el cuerpo a ese valor, exactamente como si hubieras abierto el cuerpo para escritura, escrito el valor y cerrado el cuerpo de nuevo:

$body = new MIME::Body::InCore "Line 1\nLine 2\nLine 3";

Un único array de referencias establece el cuerpo a la concatenación de todos los escalados que contiene:

$body = new MIME::Body::InCore ["Line 1\n",
                                "Line 2\n",
                                "Line 3"];

Definiendo tus propias subclases

No te sientes cómodo con archivos y arrays de escalados? No hay problema: define tu propia clase de MIME::Body y crea una subclase de MIME::Parser o MIME::ParserBase que devuelva un objeto de tu clase cuando se use el método new_body_for(head).

Tu clase de "cuerpo" debe heredar de MIME::Body (o alguna subclase de ella), y debe proporcionar (o heredar el valor por defecto) las siguientes métodos...

El método por defecto heredado debería funcionar para todos estos:

new
binmode [ONOFF]
path

El método por defecto heredado puede funcionar para estos, pero podría haber una mejor implementación para tu subclase.

init ARGS...
as_lines
as_string
dup
print
purge

El método por defecto heredado probablemente no funcionará para estos:

open

NOTES

Una razón por la cual no use directamente objetos de IO::Handle para los cuerpos de mensaje fue que deseaba que el objeto "cuerpo" sea un tipo de almacenamiento de programa persistente, completamente encapsulado; es decir, que los usuarios pudieran escribir código similar a este...

### Obtener el handle del cuerpo desde este mensaje MIME y leer sus datos:
$body = $entity->bodyhandle;
$IO = $body->open("r");
while (defined($_ = $IO->getline)) {
    print STDOUT $_;
}
$IO->close;

...sin tener que saber más sobre cómo el objeto $body realmente almacena sus datos (archivo en disco, variable escalar, array de escalados, o lo que sea).

Almacenar el cuerpo de cada mensaje MIME en un archivo que se cierra de forma persistente usando IO::Handle era una posibilidad, pero parecía ser un mal idea, dado que un mensaje MIME multipart podría fácilmente consumir todos los descriptores de archivo disponibles en algunos sistemas. Este riesgo aumenta si el usuario aplica es procesa más de un entidad MIME a la vez.
