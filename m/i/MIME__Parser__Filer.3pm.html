NAME

MIME::Parser::Filer - gestionar el archivo de salida del parser

SYNOPSIS

Antes de seguir, debes ver MIME::Parser para asegurar que entiendes dónde este módulo se integra en el esquema general de cosas. Vamos, hazlo ahora. Me lo comeré.

Listo? Ok... ahora lee "DESCRIPCIÓN" a continuación, y todo el resto debería hacer sentido.

Interfaz pública

### Crea un "filer" de la clase deseada:
my $filer = MIME::Parser::FileInto->new($dir);
my $filer = MIME::Parser::FileUnder->new($basedir);
...
### Para añadir seguridad, no dejes a los exteriores a nombre de tus archivos:
$filer->ignore_filename(1);
### Prepárate para el parsing de un mensaje top-level nuevo:
$filer->init_parse;
### Devuelve el camino donde debería estar el datos de este mensaje:
$path = $filer->output_path($head);

Interfaz semi-pública

Estas métodos pueden ser sobrescritas o ignoradas en algunas subclases, por lo que no son siempre válidas en todos los casos:

### Ajusta la mapeo de tipo de contenido a extensión:
$emap = $filer->output_extension_map;
$emap->{"text/html"} = ".htm";

DESCRIPCIÓN

Cómo esta clase se usa cuando se parsea

Cuando un MIME::Parser decide que quiere escribir un archivo en disco, usa su "Filer" objeto -- una instancia de una clase de subclass de MIME::Parser::Filer -- para determinar dónde colocar el archivo.

Cada parser tiene un único objeto de Filer, que lo usa para todo el parsing. Puedes obtener el Filer para un $parser como este:

$filer = $parser->filer;

Al principio de cada parse(), el estado interno del filer se resetea por el parser:

$parser->filer->init_parse;

Después, el parser puede obtener un camino para cada entidad en el mensaje mediante la entrega del encabezado (un MIME::Head) a el filer, y tener que hacer el trabajo, como así:

$new_file = $parser->filer->output_path($head);

Pues es bonito poder limpiar después de un parse (especialmente un parse fallido), el parser le dice al filer cuando ha realmente usado un camino:

$parser->filer->purgeable($new_file);

Luego, si quieres limpiar los archivos que fueron creados para un parse particular (y también cualquier directorio que el Filer creó), harías esto:

$parser->filer->purge;

Escribir tus propias subclases

Hay dos clases estándar de "Filer" (ver abajo): MIME::Parser::FileInto, que lanzar todos los archivos de todos los parses a una misma carpeta, y MIME::Parser::FileUnder (preferido), que crea una subdirectorio para cada mensaje. Esperamos que sean suficientes para la mayoría de los usos, pero solo en caso de que lo necesites...

La única método que tienes que sobrescribir es output_path():

$filer->output_path($head);

Este método se invoca por MIME::Parser cuando quiere poner el cuerpo de un mensaje desencriptado en un archivo de salida. Debe devolver una ruta para crear el archivo. La fallo se indica mediante lanzar una excepción.

El camino devuelto por output_path() debe estar "preparado para open()": cualquier directorio padre necesario debe existir en ese momento. Estos directorios pueden ser creados por el Filer, si lo deseas, y deben marcarse como purgeable() si se debe eliminar.

De hecho, si tu problema es más donde los archivos van que qué se les llama, puedes usar el método por defecto output_path() y solo sobrescribir una de sus partes:

$dir  = $filer->output_dir($head);
$name = $filer->output_filename($head);
...

INTERFACIA PÚBLICA

MIME::Parser::Filer

Esta es la superclase abstracta de todos los "filer" objetos.

new INITARGS...
Metodo de clase, constructor. Crea un nuevo outputter para el parser dado. Todos los argumentos siguientes son dados a init(), que las subclases deben sobrescribir para su uso propio (el default init no hace nada).
results RESULTS
Metodo de instancia. Conecta este filer a un objeto MIME::Parser::Results que cuantificará los mensajes. Nota que evitamos conectarlo al parser para evitar referencia circular!
init_parse
Metodo de instancia. Prepara para comenzar el parsing de un mensaje nuevo. Las subclases deben asegurarse de invocar el metodo heredado.
evil_filename FILENAME
Metodo de instancia. Es este un nombre malo; es decir, uno que debería no usarse en el nombre de un archivo de disco? Si cualquiera de estos es verdadero: 
* es vacío o es solo espacio en blanco
* contiene espacios al inicio o al final
* es una cadena de puntos: ".", "..", etc.
* contiene caracteres no en el conjunto: "A" - "Z", "a" - "z",
  "0" - "9", "-", "_", "+", "=", ".", ",", "@", "#",
  "$", y " ".
* es demasiado largo

Si quieres cambiar este comportamiento, deberías sobrescribir este metodo en la subclase de MIME::Parser::Filer que uses.

Nota: Subclases de MIME::Parser::Filer que sobrescriben output_path() podrían no consultar este metodo; sin embargo, note que los sustitutos internos consultan este metodo.

Gracias a Andrew Pimlott por encontrar un bug real en la versión original. Gracias a Nickolay Saukh por notar que el malo es en el ojo del espectador.

exorcise_filename FILENAME
Metodo de instancia. Si un nombre dado es malo (ver "evil_filename"), intentamos rescatarlo haciendo algunas operaciones básicas: cortar el nombre, eliminar caracteres malos, etc., y verificando cada uno contra evil_filename().

Devuelve el nombre rescatado (que es garantizado no ser malo), o undef si no se pudo rescatar.

Advertencia: al momento de invocar este metodo, el FILENAME ya ha sido desencriptado en el conjunto de caracteres locales. Si estás usando cualquier conjunto de caracteres distinto de ASCII, ISO-8859-*, o UTF-8, la interpretación de los caracteres "path" puede ser muy diferente, y necesitarás sobrescribir este metodo. Ver "unmime" en MIME::WordDecoder para más detalles.

find_unused_path DIR, FILENAME
Metodo de instancia, solo subclases. Hemos decidido un directorio de salida y nombre de archivo tentativo, pero hay un chance que ya exista. Añade un sufijo numérico "-1", "-2", etc., al nombre hasta encontrar un camino no usado, y luego devuelve ese camino.

El sufijo se agrega antes de la primera "." en el nombre si hay una; por ejemplo:

picture.gif       archive.tar.gz      readme
picture-1.gif     archive-1.tar.gz    readme-1
picture-2.gif     archive-2.tar.gz    readme-2
...               ...                 ...
picture-10.gif
...

Esta puede ser una operación costosa y riesgosa si no quieres renombrar archivos, así que es de tu mejor interés minimizar las situaciones donde estas colisiones ocurren. Aunque así, si un mensaje multipartitario da a todos sus partes...

MIME::Parser::Filer

This is the base class for filing MIME entity bodies. It is subclassed by MIME::Parser::FileInto and MIME::Parser::FileUnder.

You can control the names of the files that are created by overriding various methods. If you do this, you'll want to look at output_path(), which is the primary method called by the parser to get the name of a file to write to.

It is not recommended that you subclass this unless you know what you are doing. However, if you need to file parts into a specific directory, or you want to name them in a specific way, you may need to subclass this.

PUBLIC INTERFACE

evil_filename FILENAME
Instance method. Return true if FILENAME is unsuitable for use on the current filesystem (e.g., contains illegal characters, is too long, etc.). With argument, sets the value to be returned for the given FILENAME.
find_unused_path DIRECTORY, FILENAME
Instance method. Given a DIRECTORY and a FILENAME, find a path that does not exist. If FILENAME does not exist in DIRECTORY, then DIRECTORY/FILENAME is returned. If it does exist, then DIRECTORY/FILENAME.1 is returned. If that exists, then DIRECTORY/FILENAME.2 is returned, and so on. Returns the full pathname.
ignore_filename [YESNO]
Instance method. Return true if we should always ignore recommended filenames in messages, choosing instead to always generate our own filenames. With argument, sets this value.

Note: subclasses of MIME::Parser::Filer which override output_path() might not honor this setting; note, however, that the built-in subclasses honor it.

output_dir HEAD
Instance method. Return the output directory for the given header. The default method returns ".".
output_filename HEAD
Instance method, subclasses only. A given recommended filename was either not given, or it was judged to be evil. Return a fake name, possibly using information in the message HEADer. Note that this is just the filename, not the full path.

Used by output_path(). If you're using the default output_path(), you probably don't need to worry about avoiding collisions with existing files; we take care of that in find_unused_path().

output_prefix [PREFIX]
Instance method. Get the short string that all filenames for extracted body-parts will begin with (assuming that there is no better "recommended filename"). The default is "msg".

If PREFIX is not given, the current output prefix is returned. If PREFIX is given, the output prefix is set to the new value, and the previous value is returned.

Used by output_filename().

Note: subclasses of MIME::Parser::Filer which override output_path() or output_filename() might not honor this setting; note, however, that the built-in subclasses honor it.

output_type_ext
Instance method. Return a reference to the hash used by the default output_filename() for mapping from content-types to extensions when there is no default extension to use. 
$emap = $filer->output_typemap;
$emap->{'text/plain'} = '.txt';
$emap->{'text/html'}  = '.html';
$emap->{'text/*'}     = '.txt';
$emap->{'*/*'}        = '.dat';

Note: subclasses of MIME::Parser::Filer which override output_path() or output_filename() might not consult this hash; note, however, that the built-in subclasses consult it.

output_path HEAD
Instance method, subclasses only. Given a MIME head for a file to be extracted, come up with a good output pathname for the extracted file. This is the only method you need to worry about if you are building a custom filer.

The default implementation does a lot of work; subclass implementers really should try to just override its components instead of the whole thing. It works basically as follows:

$directory = $self->output_dir($head);
$filename = $head->recommended_filename();
if (!$filename or
     $self->ignore_filename() or
     $self->evil_filename($filename)) {
    $filename = $self->output_filename($head);
}
return $self->find_unused_path($directory, $filename);

Note: There are many, many, many ways you might want to control the naming of files, based on your application. If you don't like the behavior of this function, you can easily define your own subclass of MIME::Parser::Filer and override it there.

Note: Nickolay Saukh pointed out that, given the subjective nature of what is "evil", this function really shouldn't warn about an evil filename, but maybe just issue a debug message. I considered that, but then I thought: if debugging were off, people wouldn't know why (or even if) a given filename had been ignored. In mail robots that depend on externally-provided filenames, this could cause hard-to-diagnose problems. So, the message is still a warning.

Thanks to Laurent Amon for pointing out problems with the original implementation, and for making some good suggestions. Thanks also to Achim Bohnet for pointing out that there should be a hookless, OO way of overriding the output path.

purge
Instance method, final. Purge all files/directories created by the last parse. This method simply goes through the purgeable list in reverse order (see "purgeable") and removes all existing files/directories in it. You should not need to override this method.
purgeable [FILE]
Instance method, final. Add FILE to the list of "purgeable" files/directories (those which will be removed if you do a purge()). You should not need to override this method.

If FILE is not given, the "purgeable" list is returned. This may be used for more-sophisticated purging.

As a special case, invoking this method with a FILE that is an arrayref will replace the purgeable list with a copy of the array's contents, so [] may be used to clear the list.

Note that the "purgeable" list is cleared when a parser begins a new parse; therefore, if you want to use purge() to do cleanup, you must do so before starting a new parse!

MIME::Parser::FileInto

This concrete subclass of MIME::Parser::Filer supports filing into a given directory.

init DIRECTORY
Instance method, initiallizer. Set the directory where all files will go.

MIME::Parser::FileUnder

This concrete subclass of MIME::Parser::Filer supports filing under a given directory, using one subdirectory per message, but with all message parts in the same directory.

init BASEDIR, OPTSHASH...
Instance method, initiallizer. Set the base directory which will contain the message directories. If used, then each parse of begins by creating a new subdirectory of BASEDIR where the actual parts of the message are placed. OPTSHASH can contain the following:
DirName
Explicitly set the name of the subdirectory which is created. The default is to use the time, process id, and a sequence number, but you might want a predictable directory.
Purge
Automatically purge the contents of the directory (including all subdirectories) before each parse. This is really only needed if using an explicit DirName, and is provided as a convenience only. Currently we use the 1-arg form of File::Path::rmtree; you should familiarize yourself with the caveats therein.

The output_dir() will return the path to this message-specific directory until the next parse is begun, so you can do this:

use File::Path;
$parser->output_under("/tmp");
$ent = eval { $parser->parse_open($msg); };   ### parse
if (!$ent) {         ### parse failed
    rmtree($parser->output_dir);
    die "parse failed: $@";
}
else {               ### parse succeeded
    ...do stuff...
}
