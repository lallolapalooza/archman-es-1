NOMBRE

MIME::Lite - generador de MIME de bajas calorías

¡ESPERA!

El mantenedor actual no recomienda MIME::Lite. Existen varias alternativas, como Email::MIME o MIME::Entity y Email::Sender, que probablemente deberías usar en su lugar. MIME::Lite continúa acumulando extraños informes de errores y no está recibiendo una gran cantidad de refactorización debido a la disponibilidad de alternativas mejores. Por favor, considera usar algo más.

SINOPSIS

Crear y enviar usando el método de envío predeterminado para tu sistema operativo un mensaje de una sola parte:

use MIME::Lite;
### Crea un nuevo mensaje de una sola parte, para enviar un archivo GIF:
$msg = MIME::Lite->new(
    From     => 'yo@mihost.com',
    To       => 'tu@tuhost.com',
    Cc       => 'otro@mas.com, otro@aunmas.com',
    Subject  => '¡Holaaaaaaa, enfermera!',
    Type     => 'image/gif',
    Encoding => 'base64',
    Path     => 'hellonurse.gif'
);
$msg->send; # enviar vía predeterminado

Crear un mensaje multipart (es decir, uno con archivos adjuntos) y enviarlo vía SMTP

### Crea un nuevo mensaje multipart:
$msg = MIME::Lite->new(
    From    =>'yo@mihost.com',
    To      =>'tu@tuhost.com',
    Cc      =>'otro@mas.com, otro@aunmas.com',
    Subject =>'Un mensaje con 2 partes...',
    Type    =>'multipart/mixed'
);
### Añade partes (cada "adjuntar" tiene los mismos argumentos que "new"):
$msg->attach(
    Type     =>'TEXT',
    Data     =>"Aquí tienes el archivo GIF que querías"
);
$msg->attach(
    Type     =>'image/gif',
    Path     =>'aaa000123.gif',
    Filename =>'logo.gif',
    Disposition =>'attachment'
);
### usa Net::SMTP para hacer el envío
$msg->send('smtp','algun.host', Debug=>1 );

Generar una salida de mensaje:

### Formatear como una cadena:
$str = $msg->as_string;
### Imprimir en un manejador de archivos (digamos, un stream "sendmail"):
$msg->print(\*SENDMAIL);

Enviar un mensaje:

### Enviar de la "mejor" manera (el valor predeterminado es usar "sendmail"):
$msg->send;
### Enviar de una manera específica:
$msg->send('tipo',@argumentos);

Especificar el método de envío predeterminado:

MIME::Lite->send('smtp','algun.host',Debug=>0);

con autenticación

MIME::Lite->send('smtp','algun.host', AuthUser=>$usuario, AuthPass=>$contraseña);

usando SSL

MIME::Lite->send('smtp','algun.host', SSL => 1, Port => 465 );

DESCRIPCIÓN

En la interminable búsqueda de un gran sabor con menos calorías, presentamos con orgullo: MIME::Lite.

MIME::Lite está diseñado como un módulo simple e independiente para generar (¡no analizar!) mensajes MIME... específicamente, te permite generar un mensaje simple y decente de una o varias partes con adjuntos de texto o binarios. No requiere que tengas instalados los módulos Mail:: o MIME::, pero funcionará con ellos si están disponibles.

Puedes especificar cada parte del mensaje como el dato literal mismo (en un escalar o array), o como una cadena que se puede pasar a open() para obtener un manejador de archivos legible (por ejemplo, "<nombre_archivo" o "algún_comando|").

No necesitas preocuparte por codificar los datos de tu mensaje: este módulo lo hará por ti. Maneja las 5 codificaciones MIME estándar.

EJEMPLOS

Crear un mensaje simple que contenga solo texto

$msg = MIME::Lite->new(
    From     =>'yo@mihost.com',
    To       =>'tu@tuhost.com',
    Cc       =>'otro@mas.com, otro@aunmas.com',
    Subject  =>'¡Holaaaaaaa, enfermera!',
    Data     =>"¿Cómo te va, eh?"
);

Crear un mensaje simple que contenga solo una imagen

$msg = MIME::Lite->new(
    From     =>'yo@mihost.com',
    To       =>'tu@tuhost.com',
    Cc       =>'otro@mas.com, otro@aunmas.com',
    Subject  =>'¡Holaaaaaaa, enfermera!',
    Type     =>'image/gif',
    Encoding =>'base64',
    Path     =>'hellonurse.gif'
);

Crear un mensaje multipart

### Crea el "contenedor" multipart:
$msg = MIME::Lite->new(
    From    =>'yo@mihost.com',
    To      =>'tu@tuhost.com',
    Cc      =>'otro@mas.com, otro@aunmas.com',
    Subject =>'Un mensaje con 2 partes...',
    Type    =>'multipart/mixed'
);
### Añade el mensaje de texto:
### (Nota que "adjuntar" tiene los mismos argumentos que "new"):
$msg->attach(
    Type     =>'TEXT',
    Data     =>"Aquí tienes el archivo GIF que querías"
);
### Añade la parte de la imagen:
$msg->attach(
    Type     =>'image/gif',
    Path     =>'aaa000123.gif',
    Filename =>'logo.gif',
    Disposition =>'attachment'
);

Adjuntar un GIF a un mensaje de texto

Esto creará un mensaje multipart exactamente como el anterior, pero usando el truco de "adjuntar a una sola parte":

### Empieza con un mensaje de texto simple:
$msg = MIME::Lite->new(
    From    =>'yo@mihost.com',
    To      =>'tu@tuhost.com',
    Cc      =>'otro@mas.com, otro@aunmas.com',
    Subject =>'Un mensaje con 2 partes...',
    Type    =>'TEXT',
    Data    =>"Aquí tienes el archivo GIF que querías"
);
### Adjunta una parte... luego haz que el mensaje sea multipart automáticamente:
$msg->attach(
    Type     =>'image/gif',
    Path     =>'aaa000123.gif',
    Filename =>'logo.gif'
);

Adjuntar una parte pre-preparada a un mensaje

### Crea una parte independiente:
$part = MIME::Lite->new(
    Top      => 0,
    Type     =>'text/html',
    Data     =>'<H1>Hola</H1>',
);
$part->attr('content-type.charset' => 'UTF-8');
$part->add('X-Comment' => 'Un mensaje para ti');
### Adjúntala a cualquier mensaje:
$msg->attach($part);

Imprimir un mensaje en un manejador de archivos

### Escribirlo en un manejador de archivos:
$msg->print(\*STDOUT);
### Escribir solo la cabecera:
$msg->print_header(\*STDOUT);
### Escribir solo el cuerpo codificado:
$msg->print_body(\*STDOUT);

Imprimir un mensaje en una cadena

### Obtener todo el mensaje como una cadena:
$str = $msg->as_string;
### Obtener solo la cabecera:
$str = $msg->header_as_string;
### Obtener solo el cuerpo codificado:
$str = $msg->body_as_string;

Enviar un mensaje

### Enviar de la "mejor" manera (el valor predeterminado es usar "sendmail"):
$msg->send;

Enviar un documento HTML... ¡con imágenes incluidas!

$msg = MIME::Lite->new(
     To      =>'tu@tuhost.com',
     Subject =>'¡HTML con imágenes en línea!',
     Type    =>'multipart/related'
);
$msg->attach(
    Type => 'text/html',
    Data => qq{
        <body>
            Esta es mi imagen:
            <img src="cid:miimagen.gif">
        </body>
    },
);
$msg->attach(
    Type => 'image/gif',
    Id   => 'miimagen.gif',
    Path => '/ruta/a/algun_archivo.gif',
);
$msg->send();

Cambiar cómo se envían los mensajes

### Haz algo como esto en tu 'main':
if ($NO_TENGO_SENDMAIL) {
   MIME::Lite->send('smtp', $host, Timeout=>60,
       AuthUser=>$usuario, AuthPass=>$contraseña);
}
### Ahora esto hará lo correcto:
$msg->send;         ### ahora usará Net::SMTP como se muestra arriba

MIME::Lite->field_order()
Cuando se utiliza como un método de clase, cambia el orden predeterminado en el que se emiten las cabeceras para todos los mensajes. Sin embargo, considera usar la variante de método de instancia para evitar que estropees en otros remitentes en la misma aplicación.
MIME::Lite->quiet()
Este método de clase puede usarse para suprimir o desactivar todas las advertencias de este módulo.
MIME::Lite->send()
Cuando se utiliza como un método de clase, puede usarse para especificar un mecanismo diferente por defecto para enviar mensajes. El valor por defecto es: 
MIME::Lite->send("sendmail", "/usr/lib/sendmail -t -oi -oem");

Sin embargo, considera usar la variante similar pero más inteligente y segura de tipo de datos:

MIME::Lite->send("sendmail");

O, para usuarios no Unix:

MIME::Lite->send("smtp");
$MIME::Lite::AUTO_CC
Si es verdadero, automáticamente envía a las direcciones Cc/Bcc para send_by_smtp(). El valor por defecto es verdadero.
$MIME::Lite::AUTO_CONTENT_TYPE
Si es verdadero, intenta elegir automáticamente el tipo de contenido a partir del nombre del archivo en new()/build(). En otras palabras, establecer este valor cambia el tipo de contenido predeterminado desde "TEXT" a "AUTO".

El valor por defecto es falso, ya que debe mantener la compatibilidad inversa con el comportamiento anterior. Por favor considera mantenerlo como falso y usar Type 'AUTO' cuando build() o attach().

$MIME::Lite::AUTO_ENCODE
Si es verdadero, automáticamente elige la codificación a partir del tipo de contenido. El valor por defecto es verdadero.
$MIME::Lite::AUTO_VERIFY
Si es verdadero, verifica las rutas a los adjuntos antes de imprimir, levantando una excepción si alguna de las rutas es inaccesible. El valor por defecto es verdadero.
$MIME::Lite::PARANOID
Si es verdadero, no intentará usar MIME::Base64, MIME::QuotedPrint o MIME::Types, incluso si están disponibles. El valor por defecto es falso. Por favor, considera mantenerlo como falso y confiar en otros paquetes para hacer lo correcto.

Construction

new [PARAMHASH]
Método de clase, constructor. Crea un objeto de mensaje nuevo.

Si se dan algunos argumentos, se pasan a build(); de lo contrario, se crea solo el objeto vacío.

attach PART
attach PARAMHASH...
Método de instancia. Agrega una nueva parte a este mensaje y devuelve la nueva parte.

Si se proporciona un único argumento de PART, se considera como un objeto MIME::Lite a adjuntar. De lo contrario, este método asume que se está proporcionando un par de parámetros en PARAMHASH que se usarán en new() para crear la nueva parte.

Uno de los hacks posiblemente útiles introducidos en esto es el hack de "attach-to-singlepart": si se intenta adjuntar una parte (llámala "parte 1") a un mensaje que no tiene un tipo de contenido de "multipart" o "message", ocurre lo siguiente:

  • Se crea una nueva parte (llámala "parte 0").
  • Se cortan los atributos MIME y los datos (pero no las otras cabeceras) del mensaje "self", y se pegan en "parte 0".
  • El mensaje "self" se convierte en un mensaje "multipart/mixed".
  • La nueva "parte 0" se agrega a "self", y después de eso, se agrega "parte 1".

Un efecto deseable de un lado es que puedes crear un mensaje de texto y luego agregar cero o más adjuntos a él, de manera similar a como un agente de correo como Netscape permite.

build [PARAMHASH]
Método de clase/instancia, inicializador. Crea (o inicializa) un objeto de mensaje MIME. Normalmente, usarás las claves siguientes en PARAMHASH: 
* Data, FH, o Path (uno de estos, o ninguno si es multipart)
* Type (ejemplo: "image/jpeg")
* From, To, y Subject (si este es el nivel superior de un mensaje)

El PARAMHASH puede contener las siguientes claves:

(fieldname)
Alguna cabecera que quieras colocar en la cabecera del mensaje, tomada de la lista estándar de cabeceras (no necesitas preocuparte por mayúsculas o minúsculas): 
Approved      Encrypted     Received      Sender
Bcc           From          References    Subject
Cc            Keywords      Reply-To      To
Comments      Message-ID    Resent-*      X-*
Content-*     MIME-Version  Return-Path
Date                        Organization

Para dar a los usuarios experimentados algún poder de veto, estas cabeceras se establecerán después de las que yo establezco... así que ten cuidado: no establezcas ninguna cabecera MIME (como "Content-type") sin saber lo que estás haciendo!

Para especificar un nombre de cabecera que no esté en la lista anterior, incluso uno que sea idéntico a una opción inferior, solo da el nombre con un sufijo ":", como "My-field:". Cuando estés en duda, siempre indica una cabecera de correo (y parece un poco como tal).

Data
Alternativa a "Path" o "FH". Los datos del mensaje. Esto puede ser un escalar o un ref a un array de strings; si es el último, el mensaje consiste en una concatenación simple de todos los strings en el array.
Datestamp
Opcional. Si se le da verdadero (o se omite), se fuerza la creación de una cabecera "Date:" con la fecha/hora actual si este es un mensaje de nivel superior. Puedes querer esto si estás usando send_by_smtp(). Si no quieres que se ejecute, proporciona tu propio Date o explícitamente establece este a falso.
Disposition
Opcional. La disposición del contenido, "inline" o "attachment". El valor por defecto es "inline".
Encoding
Opcional. La codificación que debería usarse para codificar tus datos: 
Usa codificación: | Si tu mensaje contiene:
------------------------------------------------------------
7bit              | Solo texto 7bits, todas las líneas <1000 caracteres
8bit              | Texto 8bits, todas las líneas <1000 caracteres
quoted-printable  | Texto 8bits o líneas largas (más confiable que "8bit")
base64            | Datos principalmente no textuales: un GIF, un archivo tar, etc.

El valor por defecto se toma del Tipo; generalmente es "binary" (sin codificación) para text/*, message/* y multipart/*, y "base64" para todo lo demás. Un valor de "binary" generalmente no es adecuado para enviar más que archivos de texto ASCII con líneas menores a 1000 caracteres, así que considera uno de los otros valores.

En el caso de 7bit/8bit, las líneas largas se cortan automáticamente a longitud legible; en el caso de 7bit, todos los caracteres 8bits son automáticamente eliminados. Esto puede no ser lo que quieres, así que elige tu codificación bien! Para más información, ve "A MIME PRIMER".

FH
Alternativa a "Data" o "Path". Un manejador de archivo que contiene los datos, abierto para lectura. Véase ReadNow también.
Filename
Opcional. El nombre del adjunto. Puedes usarlo para proporcionar un nombre recomendado al usuario final que almacene el adjunto en un disco. Solo necesitas esto si el nombre al final de la Path no es suficiente, o si estás usando Data en lugar de Path. No debes colocar información de ruta aquí (por ejemplo, no "/" o "\" o ":").
Id
Opcional. Lo mismo que establecer "content-id".
Length
Opcional. Establece la longitud del contenido explícitamente. Normalmente, esta cabecera se calcula automáticamente, pero solo en ciertas circunstancias (ver Benign limitations).
Path
Alternativa a "Data" o "FH". Ruta a un archivo que contiene los datos... de hecho, puede ser cualquier expresión open()able. Si parece una ruta, el último elemento se tratará automáticamente como el nombre de archivo. Véase ReadNow también.
ReadNow
Opcional, para uso con "Path". Si es verdadero, abrirá la ruta y "slurp" el contenido en el núcleo ahora. Esto es útil si la ruta apunta a un comando y no quieres ejecutarlo varias veces si estás generando el mensaje varias veces. Se levanta un error fatal si el open falla.
Top
Opcional. Si está definido, indica si es un mensaje MIME de "nivel superior". Las partes de un mensaje multipart no son "nivel superior". El valor por defecto es verdadero.
Type
Opcional. El tipo MIME del contenido, o uno de estos valores especiales (en mayúsculas): 
"TEXT"   significa "text/plain"
"BINARY" significa "application/octet-stream"
"AUTO"   intenta adivinar del nombre del archivo, restando a "application/octet-stream". Esto es bueno si tienes MIME::Types instalado y no sabes qué archivo podría usarse para el adjunto.

El valor por defecto es "TEXT", pero será "AUTO" si estableces $AUTO_CONTENT_TYPE a verdadero (perdón, pero tienes que saber lo que estás haciendo).

Para habilitarlo explícitamente, ya que no queremos romper el código que depende del comportamiento antiguo:

Una imagen vale 1000 palabras (que es naturalmente 2000 bytes, así que probablemente sea más un «icono» que un «imagen»), aquí hay algunos ejemplos:

$msg = MIME::Lite->build(
    From     => 'yelling@inter.com',
    To       => 'stocking@fish.net',
    Subject  => "Hi there!",
    Type     => 'TEXT',
    Encoding => '7bit',
    Data     => "Just a quick note to say hi!"
);
$msg = MIME::Lite->build(
    From     => 'dorothy@emerald-city.oz',
    To       => 'gesundheit@edu.edu.edu',
    Subject  => "A gif for U"

);
$msg = MIME::Lite->build(

$msg->add(From    => "laughing@all.of.us");

Setting/getting headers and attributes

add TAG,VALUE
Método de instancia. Añade el campo TAG con el valor dado al final del encabezado. El TAG se convertirá a minúsculas, y el valor se convertirá a "seguro" (retornará un valor con un espacio al final).

¡Atención: cualquier campo MIME que añadas se sobrescribirá cualquier atributo MIME que tenga cuando se outpute. Normalmente, usarás este método para añadir campos no MIME:

$msg->add("Subject" => "Hi there!");

Dando un valor como arrayref hará que todos esos valores se añadan. Esto es únicamente útil para campos multivaluados como Received:

$msg->add("Received" => ["here", "there", "everywhere"]

Dando un valor vacío añade un placeholder invisible al encabezado, que puede utilizarse para suprimir la salida de los campos Content-* o el campo especial MIME-Version. Cuando suprimes campos, deberías usar replace() en lugar de add():

$msg->replace("Content-disposition" => "");

Nota: El nombre proviene de Mail::Header.

attr ATTR,[VALUE]
Método de instancia. Establece el atributo MIME ATTR al valor STRING. ATTR se convertirá a minúsculas. Este método normalmente se usa para establecer/getear atributos MIME: 
$msg->attr("content-type"         => "text/html");
$msg->attr("content-type.charset" => "US-ASCII");
$msg->attr("content-type.name"    => "homepage.html");

Esto causaría el output final algo así como:

Content-type: text/html; charset=US-ASCII; name="homepage.html"

La sub-ámbito vacío indica el primer campo anónimo.

Dando un valor como undef causará la eliminación del contenido del sub-ámbito correspondiente.

Sin argumento, devuelve el valor del atributo:

$type = $msg->attr("content-type");        ### devuelve "text/html"
$name = $msg->attr("content-type.name");   ### devuelve "homepage.html"
delete TAG
Metodo de instancia. Elimina el campo TAG con el valor dado al final del encabezado. El TAG se convertirá a minúsculas. 
$msg->delete("Subject");

Nota: El nombre proviene de Mail::Header.

field_order FIELD,...FIELD
Metodo de clase/instancia. Cambia el orden en el que se outputean los campos del encabezado para este objeto: 
$msg->field_order('from', 'to', 'content-type', 'subject');

Cuando se usa como metodo de clase, cambia los ajustes por defecto para todos los objetos:

MIME::Lite->field_order('from', 'to', 'content-type', 'subject');

El caso no importa: todos los nombres se convierten a minúsculas. En cualquier caso, proporciona el array vacío para restaurar el orden por defecto.

fields
Metodo de instancia. Devuelve el encabezado completo del objeto como un array de pares ""[TAG, VALUE]"", donde cada TAG es todo en minúsculas. Nota que cualquier campo que el usuario haya explicitamente establecido superará los campos MIME que normally se generarían. Así, no debes decir: 
$msg->set("Content-type" => "text/html; charset=US-ASCII");

a menos que quieras que el valor anterior sobre escriba el campo MIME Content-type que normally se genera.

Nota: llamé a este método fields porque el método header() de Mail::Header devuelve algo diferente, pero es suficientemente similar para causar confusión.

Puedes cambiar el orden de los campos: ve field_order. No debería necesitarse, pero algunos tienen que gestionar módulos mal implementados.

filename [FILENAME]
Metodo de instancia. Establece el nombre del archivo que se reportará como este dato. Esto realmente establece ambos atributos standar.

Sin argumento, devuelve el nombre como indicado por el content-disposition.

get TAG,[INDEX]
Metodo de instancia. Obtiene el contenido del campo TAG, que podría haber sido establecido con set() o replace(). Devuelve el texto del campo. 
$ml->get('Subject', 0);

Si se da el índice opcional 0-based, devolverá la OCCURS-0 de campo TAG. De lo contrario, mira el contexto: en un contexto escalar, solo devuelve la OCURS-0; en un contexto array, devuelve todas las OCURS.

Advertencia: solo se debe usar con campos no MIME. El comportamiento con campos MIME es pendiente de definir, y lanzará una excepción ahora.

get_length
Metodo de instancia. Recomputa el largo del cuerpo del mensaje si el proceso es trivial, y establece el atributo content-length como efecto secundario: 
$msg->get_length;

Devuelve el largo, o undefined si no está establecido.

Nota: el largo del contenido puede ser difícil de calcular, ya que implica construir el cuerpo completo en codificación y tomar su longitud (lo cual, en el caso de mensajes multipart, implica congelar todos los sub-componentes, etc.).

Este método solo establece el largo a un valor definido si el mensaje es un único componente con codificación binary, y el cuerpo está disponible en memoria o como un archivo simple. De lo contrario, el largo es establecido como undefined.

Dado que el content-length no es un campo MIME estándar (¡así que es correcto!), parece bastante justo.

parts
Metodo de instancia. Devuelve los componentes de este entidad, y esta entidad solo. Devuelve una matriz vacía si esta entidad no tiene componentes.

Este es no recursivo! Los componentes pueden tener sub-componentes; usa parts_DFS() para obtener todo.

parts_DFS
Metodo de instancia. Devuelve la lista de todos los objetos MIME::Lite incluidos en esta entidad, comenzando con la entidad misma, en orden de búsqueda profundo primero. Si este objeto no tiene componentes, se devuelve solo él.
preamble [TEXT]
Metodo de instancia. Obtiene/define la cadena de preambulo, asumiendo que este objeto tiene subcomponentes. La defina como undef para la cadena por defecto.
replace TAG,VALUE
Metodo de instancia. Elimina todas las ocurrencias de campos con nombre TAG, y añade un campo nuevo con el valor dado. TAG se convertirá a minúsculas.

¡Atención: los campos MIME (MIME-version, Content-*): si replaces un campo MIME, el texto de reemplazo sobrescribirá los atributos MIME reales cuando se outpute ese campo. Así, normally se usa attr() para cambiar los campos MIME y add()/replace() para cambiar los campos no MIME:

$msg->replace("Subject" => "Hi there!");

Dando un valor como la cadena vacía eliminará efectivamente ese campo de salida. Esto es el modo correcto para suprimir los campos especiales MIME:

$msg->replace("Content-disposition" => "");

Dando un valor como undefined eliminará todos los valores explícitos para TAG sin añadir nuevos valores.

Nota: el nombre de este método proviene de Mail::Header.

scrub
Metodo de instancia. Este es código alfa. Si lo usas, por favor dime cómo va. Recursivamente busca en el árbol de componentes de este mensaje y busca atributos MIME que pueden ser eliminados. Con un argumento array, elimina exactamente esos atributos; por ejemplo: 
$msg->scrub(['content-disposition', 'content-length']);

Es lo mismo que hacerlo recursivamente:

$msg->replace('Content-dispo
sition' => ''); $msg->replace('Content-length' => ''); ```

Configuración/obtención de datos del mensaje

binmode [SOBREESCRIBIR]
Método de instancia. Sin argumento, devuelve si cree o no que los datos (según lo proporcionado por el argumento "Path" de build()) deben leerse usando binmode() (por ejemplo, cuando se invoca read_now()).

El comportamiento predeterminado es que cualquier tipo de contenido que no sea "text/*" o "message/*" se procesa en modo binario; esto generalmente debería funcionar bien.

Con un argumento definido, este método establece un valor de "sobreescritura" explícito. Un argumento indefinido elimina la sobreescritura. Se devuelve el nuevo valor actual.

data [DATOS]
Método de instancia. Obtiene/establece los DATOS literales del mensaje. Los DATOS pueden ser un escalar o una referencia a un array de escalares (que simplemente se unirán).

Advertencia: establecer los datos provoca que el atributo "content-length" se recalcule (posiblemente a nada).

fh [MANEJADOR_DE_ARCHIVO]
Método de instancia. Obtiene/establece el MANEJADOR_DE_ARCHIVO que contiene los datos del mensaje.

Toma un manejador de archivo como entrada y lo almacena en el objeto. Esta rutina es similar a path(); una diferencia importante es que no se hace ningún intento de establecer la longitud del contenido.

path [RUTA]
Método de instancia. Obtiene/establece la RUTA a los datos del mensaje.

Advertencia: establecer la ruta recalcula cualquier campo "content-length" existente y restablece el "filename" (al último elemento de la ruta si parece una ruta simple, y a nada si no).

resetfh [MANEJADOR_DE_ARCHIVO]
Método de instancia. Restablece la posición actual del manejador de archivo al principio. Solo se aplica si usó "FH" en build() o attach() para este mensaje.

Devuelve falso si no se puede restablecer el manejador de archivo (ya que no todos los manejadores de archivo son buscables).

read_now
Método de instancia. Fuerza la lectura inmediata de los datos de la ruta/manejador de archivo (según lo especificado por build()) en memoria, como si los hubiera proporcionado literalmente con la palabra clave "Data".

Tenga en cuenta que los datos en memoria siempre se utilizarán si están disponibles.

Tenga en cuenta que todo se carga en un escalar gigante: es posible que no desee utilizar esto si envía archivos tar. El beneficio de *no* leer los datos es que los archivos muy grandes pueden ser manejados por este módulo si permanecen en disco hasta que el mensaje se envíe a través de print() o print_body().

sign HASH_DE_PARAMETROS
Método de instancia. Firma el mensaje. Esto fuerza que el mensaje se lea en memoria, después de lo cual la firma se adjunta a él.
Data
Como en build(): los datos de firma literales. Puede ser un escalar o una referencia a un array de escalares.
Path
Como en build(): la ruta al archivo.

Si no se proporcionan argumentos, el valor predeterminado es:

Path => "$ENV{HOME}/.signature"

La longitud del contenido se recalcula.

verify_data
Método de instancia. Verifica que todas las "rutas" a los datos adjuntos existan, recursivamente. Podría ser una buena idea hacer esto antes de un print(), para evitar una salida parcial accidental si un archivo pudiera faltar. Genera una excepción si alguna ruta no es legible.

Salida

print [MANEJADOR_DE_SALIDA]
Método de instancia. Imprime el mensaje en el manejador de salida dado, o en el manejador de archivo seleccionado actualmente si no se proporcionó ninguno.

Todo MANEJADOR_DE_SALIDA tiene que ser un manejador de archivo (posiblemente una referencia a un glob), o cualquier objeto que responda a un mensaje print().

Método de instancia. Imprime el cuerpo de un mensaje en el manejador de salida dado, o en el manejador de archivo seleccionado actualmente si no se proporcionó ninguno.

Todo MANEJADOR_DE_SALIDA tiene que ser un manejador de archivo (posiblemente una referencia a un glob), o cualquier objeto que responda a un mensaje print().

Excepción fatal generada si no se pueden abrir ninguno de los archivos de entrada, o si una parte no contiene datos, o si se encuentra una codificación no admitida.

Específicamente, esto asegura que el último byte enviado NO sea '\n' (octal \012) si los dos últimos bytes no son '\r\n' (\015\012) ya que esto provocará que algunos servidores SMTP se cuelguen.

Método de instancia. Imprime la cabecera del mensaje en el manejador de salida dado, o en el manejador de archivo seleccionado actualmente si no se proporcionó ninguno.

Todo MANEJADOR_DE_SALIDA tiene que ser un manejador de archivo (posiblemente una referencia a un glob), o cualquier objeto que responda a un mensaje print().

as_string
Método de instancia. Devuelve el mensaje completo como una cadena, con una cabecera y un cuerpo codificado.
body_as_string
Método de instancia. Devuelve el cuerpo codificado como una cadena. Esta es la porción después de la cabecera y la línea en blanco.

header_as_string
Método de instancia. Devuelve la cabecera como una cadena.

Envío

send
send CÓMO, [CÓMOARGs...}
Método de clase/instancia. Este es el método principal para enviar correo y para configurar cómo se enviará el correo.

Como método de clase con un argumento CÓMO y CÓMOARGs opcionales, establece el mecanismo de envío predeterminado que utilizará el método de instancia sin argumentos. CÓMO es un nombre de instalación (ver abajo), y CÓMOARGs es interpretado por la instalación. El método de clase devuelve el CÓMO y CÓMOARGs anteriores como un array.

MIME::Lite->send('sendmail', "d:\\\\programs\\\\sendmail.exe");
...
$msg = MIME::Lite->new(...);
$msg->send;

Como método de instancia con argumentos (un argumento CÓMO y CÓMOARGs opcionales), envía el mensaje de la manera solicitada; por ejemplo:

$msg->send('sendmail', "d:\\\\programs\\\\sendmail.exe");

Como método de instancia sin argumentos, envía el mensaje por el mecanismo predeterminado configurado por el método de clase. Devuelve lo que sea que devuelva la rutina de manejo de correo: debería ser verdadero en caso de éxito, falso/excepción en caso de error:

$msg = MIME::Lite->new(From=>...);
$msg->send || die "¡NO tienes correo!";

En sistemas Unix (o más bien sistemas que no son Win32), la configuración predeterminada es equivalente a:

MIME::Lite->send("sendmail", "/usr/lib/sendmail -t -oi -oem");

En sistemas Win32, la configuración predeterminada es equivalente a:

MIME::Lite->send("smtp");

Se asume que en Win32 su archivo site/lib/Net/libnet.cfg estará preconfigurado para usar el servidor SMTP apropiado. Ver abajo para configurar la autenticación.

Hay tres instalaciones:

"sendmail", ARGS...
Envía un mensaje canalizándolo al comando "sendmail". Utiliza el método send_by_sendmail(), dándole los ARGS. Este uso implementa (y desaprueba) el método sendmail().
"smtp", [HOSTNAME, [NAMEDPARMS] ]
Envía un mensaje por SMTP, utilizando HOSTNAME opcional como host de envío SMTP. Se requerirá Net::SMTP. Utiliza el método send_by_smtp(). Cualquier argumento adicional pasado también se pasará a send_by_smtp. Esto es útil para cosas como servidores de correo que requieren autenticación donde se puede decir algo como lo siguiente 
MIME::Lite->send('smtp', $host, AuthUser=>$user, AuthPass=>$pass);

lo que configurará las cosas para que los usos futuros de

$msg->send();

hagan lo correcto.

"sub", \&SUBREF, ARGS...
Envía un mensaje MSG invocando la subrutina SUBREF de su elección, con MSG como primer argumento y ARGS después.

Por ejemplo: digamos que está en un sistema operativo que carece de la instalación "sendmail" normal de Unix, pero ha instalado algo muy parecido, y necesita configurar su script Perl para usar este programa "sendmail.exe". Haga lo siguiente en la configuración de su script:

MIME::Lite->send('sendmail', "d:\\\\programs\\\\sendmail.exe");

Entonces, cada vez que necesite enviar un mensaje $msg, simplemente diga:

$msg->send;

Eso es todo. Ahora, si alguna vez mueve su script a una máquina Unix, todo lo que necesita hacer es cambiar esa línea en la configuración y listo. Todas sus invocaciones $msg->send funcionarán como se espera.

Trabalhando com UTF-8 e outros conjuntos de caracteres

Todo o texto adicionado à sua mensagem de e-mail deve ser codificado corretamente. O MIME::Lite não faz isso por você. Por exemplo, se você quiser enviar sua mensagem em UTF-8, onde $to, $subject e $text têm os seguintes valores:

  • Para: "Ramón Núñez <foo@bar.com>"
  • Assunto: "!Aquí está!"
  • Texto: "¿Quieres ganar muchos €?"
use MIME::Lite;
use Encode qw(encode encode_utf8 );
my $to      = "Ramón Núñez <foo\@bar.com>";
my $subject = "¡Aquí está!";
my $text    = "¿Quieres ganar muchos €s?";
### Criar uma nova mensagem codificada em UTF-8:
my $msg = MIME::Lite->new(
    From    => 'me@myhost.com',
    To      => encode( 'MIME-Header', $to ),
    Subject => encode( 'MIME-Header', $subject ),
    Data    => encode_utf8($text)
);
$msg->attr( 'content-type' => 'text/plain; charset=utf-8' );
$msg->send;

Nota:

  • O exemplo abaixo pressupõe que os valores que você deseja codificar estão no formato interno do Perl, ou seja, as strings contêm caracteres decodificados de UTF-8, não os bytes que representam esses caracteres.
  • Se, para o corpo da mensagem, você quiser usar um conjunto de caracteres diferente de UTF-8, você deve codificá-lo apropriadamente e definir o "content-type", por exemplo:
    • ...
Data => encode('iso-8859-15',$text)
...
$msg->attr( 'content-type' => 'text/plain; charset=iso-8859-15' );
  • Encode::MIME::Header só suporta UTF-8, mas os clientes modernos devem ser capazes de lidar com isso. Não é um problema ter os cabeçalhos em uma codificação diferente do corpo da mensagem.

Limitações benéficas

É "lite", afinal...

  • Não há análise. Obtenha MIME-tools se precisar analisar mensagens MIME.
  • Mensagens MIME::Lite atualmente não são intercambiáveis com objetos Mail::Internet ou MIME::Entity. Este é um módulo completamente separado.
  • Um campo content-length só é inserido se a codificação for binária, a mensagem for uniparte e todos os dados do documento estiverem disponíveis no momento da construção da mensagem, pois residem em um caminho simples ou em memória.
  • MIME::Lite só pode ajudá-lo a perder peso se você complementar o uso de MIME::Lite com uma dieta saudável e exercícios.

Envio de e-mail barato e fácil

Eu pensei que incluir uma invocação padrão de "sendmail" não seria tão ruim, já que muitos usuários de Perl estão em sistemas UNIX. (A partir da versão 3.02, este é apenas o padrão em caixas não Win32. Em caixas Win32, o padrão é usar SMTP e as configurações padrão fornecidas em site/lib/Net/libnet.cfg)

A configuração padrão é:

MIME::Lite->send('sendmail', "/usr/lib/sendmail -t -oi -oem");

No entanto, estes são os argumentos para sendmail:

-t      Procura a mensagem em To:, Cc:, Bcc:, etc.
-oi     Não trata uma linha contendo apenas "." como terminador de mensagem. Por exemplo, "-oi vey, it truncated my message... why?!"
-oem    Em caso de erro, devolva a mensagem (assumindo o endereço correspondente, dado no cabeçalho). Quando o e-mail for enviado, o ciclo se completa. Jai Guru Deva -oem.

Nota: estes são os mesmos argumentos que você obtém se configurar para usar o envio de e-mail mais inteligente e seguro:

MIME::Lite->send('sendmail');

Se você obtiver cabeçalhos "X-Authentication-Warning" dessa forma, poderá evitar a manipulação do envelope especificando:

MIME::Lite->send('sendmail', SetSender =>0);

E, se você não estiver em um sistema Unix, ou se quiser enviar o e-mail de outra forma, sempre existem os métodos SMTP, que hoje em dia provavelmente exigem autenticação, então você provavelmente precisa especificar:

MIME::Lite->send('smtp', "smtp.myisp.net",
   AuthUser =>"YourName",AuthPass =>"YourPass" );

Ou você pode configurar sua própria sub-rotina para chamar. Em qualquer caso, consulte o método send().

AVISOS

Endereços de e-mail bons vs. ruins com send_by_smtp()

Se estiver usando send_by_smtp, lembre-se de que, a menos que você forneça explicitamente os endereços de e-mail para enviar e receber, o MIME::Lite forçará a extração dos endereços de e-mail de uma lista possivelmente fornecida nas linhas "To:", "Cc:" e "Bcc:". Isso é complicado e, portanto, só funcionará de forma confiável com os seguintes tipos de endereços:

username
full.name@some.host.com
"Name, Full" <full.name@some.host.com>

Aviso: O MIME::Lite nunca foi intencionalmente projetado como um agente de usuário de e-mail, portanto, não espere uma implementação completa do RFC-822. Limite-se às formas comuns de endereços da Internet descritas aqui e você ficará bem. Se isso não for possível, considere usar o MIME::Lite apenas para preparar a mensagem e usar Net::SMTP explicitamente para enviar a mensagem.

Nota: A partir da versão 3.02 do MIME::Lite, as sub-rotinas de extração de nomes de e-mail foram significativamente aprimoradas. Além disso, se o Mail::Address estiver disponível, o nome será extraído usando-o. Portanto, a recomendação acima é menos verdadeira do que antes. Endereços de e-mail complicados devem funcionar corretamente agora. No entanto, o aviso permanece. Pequenos patches são bem-vindos. :-)

Formatação de cabeçalhos adiada até print()

Esta classe trata um cabeçalho MIME de forma mais abstrata, como uma coleção de atributos de nível superior. Os campos de cabeçalho RFC-822 não são construídos até o momento em que a mensagem é realmente impressa.

Codificação de dados adiada até print()

Ao especificar corpos de mensagem (em build() ou attach()), seja por FH, Data ou Path, esteja ciente de que não tentamos abrir arquivos, ler handle de entrada ou codificar os dados até que print() seja invocado.

No passado, isso criava confusão para os usuários que usavam sendmail e forneciam caminhos incorretos para o corpo do anexo, pois print() era executado o suficiente para extrair a parte inicial da mensagem. Atualmente, $AUTO_VERIFY é usado para verificar caminhos antes que o serviço de e-mail seja utilizado. Mais lento, mas muito mais seguro.

Nota: se você fornecer um corpo de mensagem via FH e tentar imprimir uma mensagem duas vezes, a segunda impressão não fará o que deveria, a menos que você explicitamente rebobine o handle do arquivo.

Você pode escapar dessas dificuldades usando a opção ReadNow, desde que tenha memória suficiente para lidar com suas mensagens.

Atributos MIME são separados dos campos de cabeçalho!

Importante: os atributos MIME são armazenados e manipulados separadamente dos campos de cabeçalho da mensagem; quando chega a hora de imprimir o cabeçalho, qualquer campo de cabeçalho explicitamente fornecido substitui aqueles que seriam criados a partir dos atributos MIME. Isso significa que:

### DANGER ### DANGER ### DANGER ### DANGER ### DANGER ###
$msg->add("Content-type", "text/html; charset=US-ASCII");

isso definirá exatamente o campo "Content-type" no cabeçalho que é escrito, independentemente de quais sejam os atributos MIME reais.

Esta função é apenas para usuários experientes, pois é um escape caso o código que normalmente formata os campos de cabeçalho MIME não esteja fazendo o que você espera. E, como qualquer escape, ele vem com um aviso: o MIME::Lite irá avisá-lo se você tentar set() ou replace() qualquer campo de cabeçalho MIME. Use attr() em vez disso.

Cuidado com linhas que consistem em um único ponto

Julian Haight observou que o MIME::Lite permite criar mensagens com linhas no corpo que consistem em apenas um "." . Isso é verdade: deve ser totalmente inofensivo, a menos que o sendmail seja usado com a opção -oi (veja "Envio de e-mail barato e fácil").

No entanto, não sei se o uso do Net::SMTP para transferir uma mensagem com essa estrutura é igualmente seguro. O feedback é bem-vindo.

Minha opinião: Não quero manipular magicamente uma mensagem do usuário, a menos que seja absolutamente necessário. Alguns usuários podem querer enviar arquivos com apenas um "." em uma linha; meu pequeno ajuste pode prejudicá-los seriamente.

Loops infinitos podem significar dados sujos!

Stefan Sautter observou um bug em 2.106, onde uma correspondência m//gc estava falhando devido a dados sujos, o que causou um loop infinito dentro do MIME::Lite.

Estou tentando corrigir isso, mas lembre-se de que minha correção irá "sujar" silenciosamente os dados (dado o contexto em que o problema ocorre, isso deve ser benéfico: já marquei o código-fonte com comentários UNTAINT para os curiosos).

Portanto: não desative a verificação de "taint" para salvá-lo de sair com dados sujos.

No ajustes a la configuración global

Las variables de configuración global son malas, y deberían eliminarlas. Hasta que lo hagan, por favor siga las indicaciones con cada configuración sobre cómo no cambiarla.

Un primerasobre MIME

Tipos de contenido

El parámetro "Type" de build() es un tipo de contenido. Este es el tipo real de los datos que estás enviando. Generalmente es una cadena de la forma "majortype/minortype".

A continuación se presentan los tipos de MIME principales. Una lista más completa puede encontrarse en RFC-2046.

application
Los datos que no se ajustan a ninguna de las categorías restantes, especialmente los datos que se procesan por algún tipo de programa de aplicación. "application/octet-stream", "application/gzip", "application/postscript"...
audio
Datos de audio. "audio/basic"...
image
Datos gráficos. "image/gif", "image/jpeg"...
message
Un mensaje, generalmente otro correo o mensaje MIME. "message/rfc822"...
multipart
Un mensaje que contiene otros mensajes. "multipart/mixed", "multipart/alternative"...
text
Datos de texto, destinados a leer por humanos. "text/plain", "text/html"...
video
Datos de video o datos de video+audio. "video/mpeg"...

Codificaciones de transferencia de contenido

El parámetro "Encoding" de build(). Este es cómo se envía el cuerpo del mensaje para transitar de forma segura.

A continuación se presentan las cinco codificaciones principales de MIME. Una lista más completa puede encontrarse en RFC-2045.

7bit
Basicamente, no se realiza ninguna codificación real. Sin embargo, este etiquetado garantiza que no hay caracteres de 8 bits y que las líneas no excedan los 1000 caracteres de longitud.
8bit
Basicamente, no se realiza ninguna codificación real. El mensaje puede contener caracteres de 8 bits, pero esta codificación garantiza que las líneas no excedan los 1000 caracteres de longitud.
binary
No se realiza ninguna codificación. El mensaje puede contener caracteres de 8 bits, y las líneas pueden ser más largas que 1000 caracteres.
base64
Similar a "uuencode", pero bien definida. Esta es cómo debes enviar información binaria (archivos tar, GIFs, JPEGs, etc.).
quoted-printable
Útil para codificar mensajes que son textuales pero contienen caracteres no ASCII (por ejemplo, Latin-1, Latin-2, o cualquier otro alfabeto de 8 bits).

MÓDULOS DE APOYO

MIME::Lite funciona bien con otros módulos si están presentes. Los módulos que se recomiendan instalar son el último MIME::Types, Mail::Address, MIME::Base64, MIME::QuotedPrint, y Net::SMTP. Email::Date::Format es estrictamente necesario.

Si estos módulos no están presentes, algunas funciones no funcionarán y otras características no serán tan eficientes o actualizadas como podrían ser. Sin embargo, son extras opcionales.

GOODIES BUNDLED

La carpeta ./examples contiene varios snippets preparados, generalmente documentados, pero deberían ser fáciles de entender.

La carpeta ./contrib contiene módulos de acompañamiento/ herramientas que vienen incluidos con MIME::Lite, pero no se instalan por defecto. Por favor revisa los POD que vienen con ellos.
