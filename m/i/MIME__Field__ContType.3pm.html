MIME::Field::ContType(3) Documentación de Perl aportada por el usuario MIME::Field::ContType(3)

NOMBRE

MIME::Field::ContType - un campo "Content-type"

DESCRIPCIÓN

Una subclase de Mail::Field.

No uses esta clase directamente... ¡su nombre podría cambiar en el futuro! En su lugar, ¡pide a Mail::Field instancias nuevas basadas en el nombre del campo!

SINOPSIS

use Mail::Field;
use MIME::Head;
# Crear una instancia a partir de algún texto:
$field = Mail::Field->new('Content-type',
                          'text/HTML; charset="US-ASCII"');
# Obtener el tipo MIME, como 'text/plain' o 'x-foobar'.
# Devuelve 'text/plain' por defecto, según RFC 2045:
my ($type, $subtype) = split('/', $field->type);
# Obtener información genérica:
print $field->name;
# Obtener información relacionada con el tipo "message":
if ($type eq 'message') {
    print $field->id;
    print $field->number;
    print $field->total;
}
# Obtener información relacionada con el tipo "multipart":
if ($type eq 'multipart') {
    print $field->boundary;            # el valor básico, arreglado
    print $field->multipart_boundary;  # ¡vacío si no es un mensaje multipart!
}
# Obtener información relacionada con el tipo "text":
if ($type eq 'text') {
    print $field->charset;      # devuelve 'us-ascii' por defecto
}

INTERFAZ PÚBLICA

boundary
Devuelve el campo de delimitador. El delimitador se devuelve exactamente como se proporciona en el campo "Content-type:"; es decir, los guiones dobles iniciales ("--") no se anteponen.

(Bueno, casi exactamente... de RFC 2046:

(Si un delimitador parece terminar con espacio en blanco, se debe suponer
que el espacio en blanco fue agregado por una pasarela, y debe ser eliminado.)

así que cumplimos y eliminamos cualquier espacio final.)

Devuelve la cadena vacía si no hay delimitador, o si el delimitador es ilegal (por ejemplo, si está vacío después de eliminar todo el espacio en blanco final).

multipart_boundary
Similar a boundary(), excepto que esto también devolverá la cadena vacía si el mensaje no es un mensaje multipart. En otras palabras, hay una verificación de sanidad automática.
type
Intenta determinar enérgicamente el tipo de contenido (por ejemplo, "text/plain", "image/gif", "x-weird-type", que se devuelve en minúsculas.

Una cosa feliz: el siguiente código funcionará tal como lo desearías, incluso si no hay subtipo (como en "x-weird-type")... en tal caso, el $subtype simplemente sería la cadena vacía:

($type, $subtype) = split('/', $head->mime_type);

Si falta la información del tipo de contenido, se establece por defecto a "text/plain", según RFC 2045:

Los mensajes RFC 2822 por defecto son tipificados por este protocolo como
texto plano en el conjunto de caracteres US-ASCII, lo cual puede ser
especificado explícitamente como "Content-type: text/plain;
charset=us-ascii". Si no se especifica Content-Type, se asume este
valor predeterminado.

Nota: bajo el principio de "ser liberal en lo que aceptamos", esta rutina ya no verifica la sintaxis del tipo de contenido. Si no está vacío, simplemente conviértelo a minúsculas y devuélvelo.

NOTAS

Dado que casi todos (si no todos) los parámetros deben tener valores no vacíos para ser considerados válidos, simplemente devolvemos la cadena vacía para indicar campos faltantes. Si necesita obtener el valor subyacente *real*, use el método heredado param() (que devuelve undef si el parámetro falta).
