NOMBRE

MIME::Entity - clase para mensajes MIME analizados y decodificados

SINOPSIS

Antes de seguir leyendo, deberías ver MIME::Tools para asegurarte de que entiendes dónde encaja este módulo en el panorama general. ¡Vamos, hazlo ahora! Esperaré.

¿Listo? De acuerdo...

### Crear una entidad:
$top = MIME::Entity->build(From    => 'yo@mihost.com',
                           To      => 'tu@tuhost.com',
                           Subject => "¡Hola, enfermera!",
                           Data    => \@mi_mensaje);
### Adjuntar cosas a ella:
$top->attach(Path     => $ruta_gif,
             Type     => "image/gif",
             Encoding => "base64");
### Firmarla:
$top->sign;
### Salida:
$top->print(\*STDOUT);

DESCRIPCIÓN

Una subclase de Mail::Internet.

Este paquete proporciona una clase para representar entidades de mensajes MIME, según lo especificado en los RFC 2045, 2046, 2047, 2048 y 2049.

EJEMPLOS

Ejemplos de construcción

Crear un documento para un archivo de texto ASCII de 7 bits ordinario (muchas cosas se configuran por defecto para nosotros):

$ent = MIME::Entity->build(Path=>"mensaje-ingles.txt");

Crear un documento para un archivo de texto con caracteres de 8 bits (Latin-1):

$ent = MIME::Entity->build(Path     =>"mensaje-frances.txt",
                           Encoding =>"quoted-printable",
                           From     =>'jean.luc@inria.fr',
                           Subject  =>"¡Es bueno!");

Crear un documento para un archivo GIF (la descripción es completamente opcional; tenga en cuenta que tenemos que especificar el tipo de contenido y la codificación ya que no son los valores predeterminados):

$ent = MIME::Entity->build(Description => "Una imagen bonita",
                           Path        => "./docs/mime-sm.gif",
                           Type        => "image/gif",
                           Encoding    => "base64");

Crear un documento para el que ya tienes el texto, usando "Data":

$ent = MIME::Entity->build(Type        => "text/plain",
                           Encoding    => "quoted-printable",
                           Data        => ["Primera línea.\n",
                                          "Segunda línea.\n",
                                          "Última línea.\n"]);

Crear un mensaje multipart, con toda la estructura dada explícitamente:

### Crear el nivel superior y configurar las cabeceras del correo:
$top = MIME::Entity->build(Type     => "multipart/mixed",
                           From     => 'yo@mihost.com',
                           To       => 'tu@tuhost.com',
                           Subject  => "¡Hola, enfermera!");
### Adjunto #1: un documento de texto simple:
$top->attach(Path=>"./testin/short.txt");
### Adjunto #2: un archivo GIF:
$top->attach(Path        => "./docs/mime-sm.gif",
             Type        => "image/gif",
             Encoding    => "base64");
### Adjunto #3: texto que crearemos con texto que tenemos a mano:
$top->attach(Data => $contents);

¿Supongamos que no sabes de antemano que tendrás adjuntos? No hay problema: también puedes "adjuntar" a singleparts:

$top = MIME::Entity->build(From    => 'yo@mihost.com',
                           To      => 'tu@tuhost.com',
                           Subject => "¡Hola, enfermera!",
                           Data    => \@mi_mensaje);
if ($ruta_GIF) {
    $top->attach(Path     => $ruta_GIF,
                 Type     => 'image/gif');
}

Copiar una entidad (cabeceras, partes... todo excepto datos del cuerpo externo):

my $deepcopy = $top->dup;

Ejemplos de acceso

### Obtener la cabecera, un MIME::Head:
$head = $ent->head;
### Obtener el cuerpo, como un MIME::Body;
$bodyh = $ent->bodyhandle;
### Obtener el tipo MIME previsto (declarado en la cabecera):
$type = $ent->mime_type;
### Obtener el tipo MIME efectivo (en caso de que la decodificación fallara):
$eff_type = $ent->effective_type;
### Obtener preámbulo, partes y epílogo:
$preamble   = $ent->preamble;          ### ref a un array de líneas
$num_parts  = $ent->parts;
$first_part = $ent->parts(0);          ### una entidad
$epilogue   = $ent->epilogue;          ### ref a un array de líneas

Ejemplos de manipulación

Manipular los datos del cuerpo:

### Leer los datos del cuerpo (sin codificar):
if ($io = $ent->open("r")) {
    while (defined($_ = $io->getline)) { print $_ }
    $io->close;
}
### Escribir los datos del cuerpo (sin codificar):
if ($io = $ent->open("w")) {
    foreach (@lines) { $io->print($_) }
    $io->close;
}
### Eliminar los archivos de cualquier dato externo (en disco):
$ent->purge;

Manipular la firma:

### Firmarla (elimina automáticamente cualquier firma existente):
$top->sign(File=>"$ENV{HOME}/.signature");
### Eliminar cualquier firma dentro de las 15 líneas finales:
$top->remove_sig(15);

Manipular las cabeceras:

### Calcular las longitudes de contenido para singleparts basándose en los cuerpos:
###   (¡Haz esto justo antes de imprimir!)
$entity->sync_headers(Length=>'COMPUTE');

Manipular la estructura:

### Si es un multipart con 0 o 1 parte, colapsarlo a un singlepart:
$top->make_singlepart;
### Si es un singlepart, expandirlo a un multipart con 1 parte:
$top->make_multipart;

Eliminar partes:

### Eliminar algunas partes de un mensaje multipart:
my @keep = grep { keep_part($_) } $msg->parts;
$msg->parts(\@keep);

Ejemplos de salida

Imprimir a manejadores de archivo:

### Imprimir el mensaje completo:
$top->print(\*STDOUT);
### Imprimir solo la cabecera:
$top->print_header(\*STDOUT);
### Imprimir solo el cuerpo (codificado)... ¡incluye las partes también!
$top->print_body(\*STDOUT);

Convertir a cadena... tenga en cuenta que "stringify_xx" también se puede escribir como "xx_as_string"; los métodos son sinónimos y ninguna forma será deprecada.

Si establece la variable $MIME::Entity::BOUNDARY_DELIMITER a una cadena, esa cadena se utilizará como delimitador de fin de línea en la salida. Si no está establecida, el fin de línea será un carácter de nueva línea (\n)

TENGA EN CUENTA que $MIME::Entity::BOUNDARY_DELIMITER solo se aplica a partes estructurales de los datos MIME generados por este paquete y a la salida codificada en Base64; si una parte utiliza internamente un delimitador de fin de línea diferente y se imprime tal cual, el fin de línea no se cambia para que coincida con $MIME::Entity::BOUNDARY_DELIMITER.

### Convertir el mensaje completo a cadena:
print $top->stringify;              ### o $top->as_string
### Convertir solo la cabecera a cadena:
print $top->stringify_header;       ### o $top->header_as_string
### Convertir solo el cuerpo (codificado) a cadena... ¡incluye las partes también!
print $top->stringify_body;         ### o $top->body_as_string

Depuración:

### Imprimir información de depuración:
$entity->dump_skeleton(\*STDERR);

INTERFAZ PÚBLICA

Construcción

new [FUENTE]
Método de clase. Crea una entidad MIME nueva y vacía. Básicamente, esto usa el constructor de Mail::Internet...

Si FUENTE es un ARRAYREF, se asume que es un array de líneas que se utilizará para crear tanto la cabecera como un cuerpo en memoria.

De lo contrario, si FUENTE está definido, se asume que es un manejador de archivo del cual se leerán la cabecera y el cuerpo en memoria.

Nota: en cualquier caso, el cuerpo no será analizado: ¡simplemente leído!

ambiguous_content
Método de instancia.

Devuelve verdadero si esta entidad o alguna de sus partes, recursivamente tiene una "MIME::Head" que indica contenido ambiguo.

MIME::Entity - Perl module for manipulating MIME messages

NAME

MIME::Entity - Perl module for manipulating MIME messages

SYNOPSIS

    use MIME::Entity;

    # Create a new entity from a file
    my $entity = MIME::Entity->build(
        Type     => "image/gif",
        Path     => "/path/to/my.gif",
        Filename => "saved.gif",
        Disposition => "attachment",
    );

    # Create a multipart entity
    my $multipart = MIME::Entity->build(Type => "multipart/mixed");
    $multipart->attach(
        Type     => "text/plain",
        Data     => "Hello there!",
        Filename => "greeting.txt",
    );
    $multipart->attach(
        Type => "image/gif",
        Path => "/path/to/image.gif",
    );

    # Read an entity from a filehandle
    my $entity = MIME::Entity->read(\*STDIN);

    # Print the entity to a filehandle
    $entity->print(\*STDOUT);

    # Access the header
    print $entity->head->get("Subject");

    # Access the body
    my $body_handle = $entity->bodyhandle;
    if ($body_handle) {
        my $content_type = $entity->head->mime_type;
        if ($content_type =~ /^text\//) {
            while (my $line = $body_handle->getline) {
                # process text line
            }
        } else {
            my $buffer;
            while ($body_handle->read($buffer, 4096)) {
                # process binary data
            }
        }
    }

    # Check for ambiguity
    if ($entity->ambiguous_content) {
        # ...
    }

    # Add a part to a multipart entity
    $multipart->add_part($new_part);

DESCRIPTION

MIME::Entity provides a convenient object-oriented interface for creating, reading, and manipulating MIME messages. It is built upon MIME::Head and MIME::Body.

The basic structure of a MIME message is that of a tree. Each node in the tree is a MIME::Entity. Entities have a head (MIME::Head) and a body (MIME::Body). If an entity has a content-type of "multipart/*", its body is conceptually replaced by a list of children, each of which is a MIME::Entity. Otherwise, it has a single body.

This module provides both class methods for creating new entities and instance methods for manipulating existing ones.

Constructors and Mutators

build PARAMHASH
Class/instance method. A quick-and-easy catch-all way to create an entity. Use it like this to build a "normal" single-part entity: 
$ent = MIME::Entity->build(Type     => "image/gif",
                           Encoding => "base64",
                           Path     => "/path/to/xyz12345.gif",
                           Filename => "saveme.gif",
                           Disposition => "attachment");

And like this to build a "multipart" entity:

$ent = MIME::Entity->build(Type     => "multipart/mixed",
                           Boundary => "---1234567");

A minimal MIME header will be created. If you want to add or modify any header fields afterwards, you can of course do so via the underlying head object... but hey, there's now a prettier syntax!

$ent = MIME::Entity->build(Type          =>"multipart/mixed",
                           From          => $myaddr,
                           Subject       => "Hi!",
                           'X-Certified' => ['SINED',
                                             'SEELED',
                                             'DELIVERED']);

Normally, an "X-Mailer" header field is output which contains this toolkit's name and version (plus this module's RCS version). This will allow any bad MIME we generate to be traced back to us. You can of course overwrite that header with your own:

$ent = MIME::Entity->build(Type        => "multipart/mixed",
                           'X-Mailer'  => "myprog 1.1");

Or remove it entirely:

$ent = MIME::Entity->build(Type       => "multipart/mixed",
                           'X-Mailer' => undef);

OK, enough hype. The parameters are:

(FIELDNAME)
Any field you want placed in the message header, taken from the standard list of header fields (you don't need to worry about case): 
Bcc           Encrypted     Received      Sender
Cc            From          References    Subject
Comments      Keywords      Reply-To      To
Content-*     Message-ID    Resent-*      X-*
Date          MIME-Version  Return-Path
              Organization

To give experienced users some veto power, these fields will be set after the ones I set... so be careful: don't set any MIME fields (like "Content-type") unless you know what you're doing!

To specify a fieldname that's not in the above list, even one that's identical to an option below, just give it with a trailing ":", like "My-field:". When in doubt, that always signals a mail field (and it sort of looks like one too).

Boundary
Multipart entities only. Optional. The boundary string. As per RFC-2046, it must consist only of the characters "[0-9a-zA-Z'()+_,-./:=?]" and space (you'll be warned, and your boundary will be ignored, if this is not the case). If you omit this, a random string will be chosen... which is probably safer.
Charset
Optional. The character set.
Data
Single-part entities only. Optional. An alternative to Path (q.v.): the actual data, either as a scalar or an array reference (whose elements are joined together to make the actual scalar). The body is opened on the data using MIME::Body::InCore.

Note that for text parts, the Data scalar or array is assumed to be encoded in a suitable character encoding (as if by "Encode::encode") rather than a native Perl string. The encoding you use must, of course, match the "charset" option of the "MIME-Type" header.

Description
Optional. The text of the content-description. If you don't specify it, the field is not put in the header.
Disposition
Optional. The basic content-disposition ("attachment" or "inline"). If you don't specify it, it defaults to "inline" for backwards compatibility. Thanks to Kurt Freytag for suggesting this feature.
Encoding
Optional. The content-transfer-encoding. If you don't specify it, a reasonable default is put in. You can also give the special value '-SUGGEST', to have it chosen for you in a heavy-duty fashion which scans the data itself.
Filename
Single-part entities only. Optional. The recommended filename. Overrides any name extracted from "Path". The information is stored both the deprecated (content-type) and preferred (content-disposition) locations. If you explicitly want to avoid a recommended filename (even when Path is used), supply this as empty or undef.
Id
Optional. Set the content-id.
Path
Single-part entities only. Optional. The path to the file to attach. The body is opened on that file using MIME::Body::File.
Top
Optional. Is this a top-level entity? If so, it must sport a MIME-Version. The default is true. (NB: look at how attach() uses it.)
Type
Optional. The basic content-type ("text/plain", etc.). If you don't specify it, it defaults to "text/plain" as per RFC 2045. Do yourself a favor: put it in.
add_part ENTITY, [OFFSET]
Instance method. Assuming we are a multipart message, add a body part (a MIME::Entity) to the array of body parts. Returns the part that was just added.

If OFFSET is positive, the new part is added at that offset from the beginning of the array of parts. If it is negative, it counts from the end of the array. (An INDEX of -1 will place the new part at the very end of the array, -2 will place it as the penultimate item in the array, etc.) If OFFSET is not given, the new part is added to the end of the array. Thanks to Jason L Tibbitts III for providing support for OFFSET.

Warning: in general, you only want to attach parts to entities with a content-type of "multipart/*").

attach PARAMHASH
Instance method. The real quick-and-easy way to create multipart messages. The PARAMHASH is used to "build" a new entity; this method is basically equivalent to: 
$entity->add_part(ref($entity)->build(PARAMHASH, Top=>0));

Note: normally, you attach to multipart entities; however, if you attach something to a singlepart (like attaching a GIF to a text message), the singlepart will be coerced into a multipart automatically.

dup
Instance method. Duplicate the entity. Does a deep, recursive copy, but beware: external data in bodyhandles is not copied to new files! Changing the data in one entity's data file, or purging that entity, will affect its duplicate. Entities with in-core data probably need not worry.
is_multipart
Instance method. Returns true if the entity is a multipart message.
parts
Instance method. Returns an array reference of the parts of this entity. If this entity is not a multipart message, returns an empty array reference. If the entity is not a multipart message, but its contents are a single MIME::Entity (which can happen with message/* types), then the array will contain that single entity. Otherwise, the array will be empty.
read FH, [MAXLEN]
Class method. Reads a MIME message from the given filehandle FH, up to a maximum of MAXLEN bytes (useful for reading raw email from a pipe). Returns the new MIME::Entity, or undef on failure.
remove_part ENTITY
Instance method. Remove the given part ENTITY from a multipart message. Returns the part that was removed, or undef if the part was not found.
replace_part OLD, NEW
Instance method. Replace the part OLD with the part NEW in a multipart message. Returns the NEW part, or undef if OLD was not found.
write FH
Instance method. Writes the entity to the given filehandle FH. This is the inverse of read().

AMBIGUITY

MIME::Entity is able to represent messages that are not well-formed according to RFC2045. It does this by allowing entities to be "ambiguous". An entity is ambiguous if it has headers that cannot be represented in a single RFC2045 entity. For example, an entity with both a Content-Type: text/plain and a Content-Type: image/gif header is ambiguous.

The following methods can be used to detect ambiguity:

ambiguous
Instance method. Returns true if this entity is ambiguous.
ambiguous_content
Instance method. Returns true if this entity's content-type header is ambiguous. This means it has multiple content-type headers (or other headers that affect the content-type, like content-transfer-encoding). It is equivalent to:
ambiguous_content
Instance method. Returns true if this entity's content-type header is ambiguous. This means it has multiple content-type headers (or other headers that affect the content-type, like content-transfer-encoding). It is equivalent to:
$entity->head->ambiguous_content();

and

$entity->ambiguous_content();

The first returns true only if this specific entity's headers indicate ambiguity. The second returns true if this entity or any of its parts, recursively has headers that indicate ambiguity.

Access

body [VALUE]
Instance method. Get the encoded (transport-ready) body, as an array of lines. Returns an array reference. Each array entry is a newline-terminated line.

This is a read-only data structure: changing its contents will have no effect. Its contents are identical to what is printed by print_body().

Provided for compatibility with Mail::Internet, so that methods like smtpsend() will work. Note however that if VALUE is given, a fatal exception is thrown, since you cannot use this method to set the lines of the encoded message.

If you want the raw (unencoded) body data, use the bodyhandle() method to get and use a MIME::Body. The content-type of the entity will tell you whether that body is best read as text (via getline()) or raw data (via read()).

bodyhandle [VALUE]
Instance method. Get or set an abstract object representing the body of the message. The body holds the decoded message data.

Note that not all entities have bodies! An entity will have either a body or parts: not both. This method will only return an object if this entity can have a body; otherwise, it will return undefined. Whether-or-not a given entity can have a body is determined by (1) its content type, and (2) whether-or-not the parser was told to extract nested messages:

Type:        | Extract nested? | bodyhandle() | parts()
-----------------------------------------------------------------------
multipart/*  | -               | undef        | 0 or more MIME::Entity
message/*    | true            | undef        | 0 or 1 MIME::Entity
message/*    | false           | MIME::Body   | empty list
(other)      | -               | MIME::Body   | empty list

If "VALUE" is not given, the current bodyhandle is returned, or undef if the entity cannot have a body.

If "VALUE" is given, the bodyhandle is set to VALUE. VALUE must be a MIME::Body object, or something that can be used as one (e.g. a file path or scalar data). This method returns VALUE. If VALUE is undef, the entity's body is emptied (and will be represented as an empty body). This is generally only useful if you are preparing to replace the body with parts.

close
Instance method. Close the entity's bodyhandle. This is useful if you are done with the entity and want to release any underlying file handles. This method is called automatically when the entity is destroyed.
complete_head
Instance method. Ensure that the entity has a complete set of headers (including MIME-Version, Content-Type, etc.). This is normally called automatically when needed, but can be called manually if desired.
decodable
Instance method. Returns true if the entity's body can be decoded (i.e., if it has a bodyhandle).
encode TYPE
Instance method. Encodes the entity's body using the specified transfer encoding TYPE. If TYPE is not given, the default encoding is used. This method is normally called automatically by print() or write(), but can be called manually to pre-encode the body.
get_description
Instance method. Returns the content-description, if any.
get_disposition
Instance method. Returns the content-disposition, if any.
get_filename
Instance method. Returns the recommended filename, if any.
get_id
Instance method. Returns the content-id, if any.
get_type
Instance method. Returns the content-type, if any.
head [VALUE]
Instance method. Get or set the head object (MIME::Head) of this entity. If VALUE is provided, it must be a MIME::Head object. This method returns the head object.
is_top_level
Instance method. Returns true if this entity is a top-level entity (i.e., it has a MIME-Version header).
message_id
Instance method. Returns the Message-ID header, or undef if not present.
modified
Instance method. Returns true if the entity has been modified since it was read or created. This is mainly used internally to optimize encoding.
path
Instance method. If the entity's body was created from a file, this method returns the path to that file. Otherwise, it returns undef.
print FH
Instance method. Prints the entity to the filehandle FH. This is equivalent to calling write().
print_body FH
Instance method. Prints the encoded body of the entity to filehandle FH. This is useful if you want to print only the body, without the headers.
purge
Instance method. Releases the memory associated with the entity's body. If the body was read from a file, the file is not deleted. This is useful for freeing up memory when dealing with large messages.
stringify
Instance method. Returns a string representation of the entity, suitable for debugging.
unmodified
Instance method. Marks the entity as unmodified. This is normally called automatically when the entity is read or created.

SIGN

sign PARAMHASH
Método de instancia, anula. Adjunta una firma al mensaje. Los parámetros son:
Attach
En lugar de adjuntar el texto, agrégalo al mensaje como un archivo adjunto. La disposición será "inline" y la descripción indicará que es una firma. El comportamiento predeterminado es adjuntar la firma al texto del mensaje (o al texto de su primera parte si es multipart). Específico de MIME; nuevo en esta subclase.
File
Utiliza el contenido de este archivo como firma. Error fatal si no se puede leer. Como en el método de la superclase.
Force
Fírmalo incluso si el tipo de contenido no es "text/*". Útil para tipos no estándar como "x-foobar", ¡pero ten cuidado! Específico de MIME; nuevo en esta subclase.
Remove
Normalmente, intentamos eliminar cualquier firma existente. Si es verdadero, esto nos da el parámetro NLINES de la llamada a remove_sig. Si es cero pero está definido, nos dice que no eliminemos ninguna firma existente. Si no está definido, la eliminación se realiza con el valor predeterminado de 10 líneas. Nuevo en esta subclase.
Signature
Usa este texto como firma. Puedes proporcionarlo como un escalar, o como una referencia a un array de escalares terminados en nueva línea. Como en el método de la superclase.

Para mensajes MIME, este método es razonablemente cauteloso: solo intentará firmar un mensaje con un tipo de contenido de "text/*", a menos que se especifique "Force".

Si envía este mensaje a una entidad multipart, lo retransmitirá a la primera parte (las otras suelen ser los "archivos adjuntos").

Advertencia: actualmente consume todo el parte del mensaje en memoria como un array de líneas, por lo que probablemente no querrá usar esto en mensajes extremadamente largos.

Devuelve verdadero en caso de éxito, falso en caso contrario.

suggest_encoding
Método de instancia. Basado en el tipo de contenido efectivo, devuelve una buena codificación sugerida.

"text" y "message" los tipos escanean sus cuerpos línea por línea en busca de caracteres de 8 bits y líneas largas; la ausencia de ambos significa que el mensaje está en 7 bits. Otros tipos se eligen independientemente de su cuerpo:

Tipo principal:    ¿ok en 7 bits?    Codificación sugerida:
-----------------------------------------------------------
text             sí         7bit
text             no         quoted-printable
message          sí         7bit
message          no         binary
multipart        *          binary (en caso de que algunas partes estén mal)
image, etc...    *          base64
sync_headers OPTIONS
Método de instancia. Este método realiza una variedad de actividades que aseguran que las cabeceras MIME de un "árbol" de entidades estén sincronizadas con las partes del cuerpo que describen. Puede ser una operación tan costosa como la impresión si implica pre-codificar las partes del cuerpo; sin embargo, el objetivo es producir MIME bastante limpio. Solo necesitará invocar esto si procesa y reenvía MIME de una fuente externa.

OPTIONS es un hash, que describe lo que se debe hacer.

Length
Uno de los campos MIME "no oficiales oficiales" es "Content-Length". Normalmente, a uno no le importa un bledo este campo; sin embargo, si está preparando una salida destinada a HTTP, puede que le interese. El valor de esta opción dicta lo que se hará:

COMPUTE significa establecer un campo "Content-Length" para cada parte no multipart en la entidad, y borrar ese campo para cada parte multipart en la entidad.

ERASE significa que todos los campos "Content-Length" se borrarán. Esto es rápido, indoloro y seguro.

Cualquier valor falso (el predeterminado) significa no realizar ninguna acción.

Nonstandard
Cualquier campo de cabecera que comience con "Content-" es, según la RFC, un campo MIME. Sin embargo, algunos son no estándar y pueden causar problemas con ciertos lectores MIME que los interpretan de manera diferente.

ERASE significa que todos esos campos se borrarán. Esto se hace antes de que se examine y se actúe sobre la opción Length (ver más abajo).

Cualquier valor falso (el predeterminado) significa no realizar ninguna acción.

Devuelve un valor verdadero si todo salió bien, un valor falso en caso contrario.

tidy_body
Método de instancia, anula. Actualmente no implementado para mensajes MIME. No hace nada, devuelve falso.

Salida

dump_skeleton [FILEHANDLE]
Método de instancia. Volca el esqueleto de la entidad al FILEHANDLE dado, o al actualmente seleccionado si no se proporciona ninguno.

Cada entidad se genera con un nivel de indentación apropiado, la siguiente selección de atributos:

Content-type: multipart/mixed
Effective-type: multipart/mixed
Body-file: NONE
Subject: Hola!
Num-parts: 2

Esto es realmente solo útil para fines de depuración; no hago garantías sobre la consistencia del formato de salida con el tiempo.

print [OUTSTREAM]
Método de instancia, anula. Imprime la entidad en el OUTSTREAM dado, o en el filehandle actualmente seleccionado si no se proporciona ninguno. OUTSTREAM puede ser un filehandle, o cualquier objeto que responda a un mensaje print().

La entidad se genera como un flujo MIME válido. Esto significa que la cabecera siempre se genera primero, y los datos del cuerpo (si los hay) se codificarán si la cabecera indica que debe hacerlo. Por ejemplo, tu salida puede parecerse a esto:

Subject: Saludos
Content-transfer-encoding: base64
SGkgdGhlcmUhCkJ5ZSB0aGVyZSEK

Si esta entidad tiene el tipo MIME "multipart/*", el preámbulo, las partes y el epílogo se generan con los límites apropiados que separan cada uno. Se ignora cualquier manejador de cuerpo:

Content-type: multipart/mixed; boundary="*----*"
Content-transfer-encoding: 7bit
[Preámbulo]
--*----*
[Entidad: Parte 0]
--*----*
[Entidad: Parte 1]
--*----*--
[Epílogo]

Si esta entidad tiene un tipo MIME de una sola parte sin partes adjuntas, entonces estamos ante una entidad normal de una sola parte: el cuerpo se genera según la codificación especificada por la cabecera. Si no hay cuerpo, se genera una advertencia y el cuerpo se trata como vacío:

Content-type: image/gif
Content-transfer-encoding: base64
[Cuerpo codificado]

Si esta entidad tiene un tipo MIME de una sola parte pero también tiene partes, entonces probablemente estemos ante una "re-analizada" una sola parte, generalmente de tipo "message/*" (puedes obtener entidades como estas si configuras la opción parse_nested_messages(NEST) en el analizador a verdadero). En este caso, las partes se generan con líneas en blanco simples separando cada una, y se ignora cualquier manejador de cuerpo:

Content-type: message/rfc822
Content-transfer-encoding: 7bit
[Entidad: Parte 0]
[Entidad: Parte 1]

En todos los casos, al generar una "parte" de la entidad, este método se invoca recursivamente.

Nota: es muy probable que la salida no sea idéntica a ninguna entrada que hayas analizado para obtener esta entidad. Si estás creando algún tipo de gestor de correo electrónico, depende de ti guardar esta información.

print_body [OUTSTREAM]
Método de instancia, anula. Imprime el cuerpo de la entidad en el OUTSTREAM dado, o en el filehandle actualmente seleccionado si no se proporciona ninguno. OUTSTREAM puede ser un filehandle, o cualquier objeto que responda a un mensaje print().

El cuerpo se genera para ser incluido en un flujo MIME válido; esto significa que los datos del cuerpo se codificarán si la cabecera indica que debe hacerlo.

Nota: por "cuerpo", nos referimos a "el contenido que sigue a la cabecera". Un cuerpo multipart impreso incluye las representaciones impresas de sus subpartes.

Nota: El cuerpo se almacena en un formato no codificado; sin embargo, la idea es que la codificación de transferencia se utilice para determinar cómo debe ser generado. Esto significa que el método print() siempre te garantiza un flujo listo para sendmail cuyo cuerpo sea coherente con su cabecera. Si desea que se generen los datos del cuerpo en bruto, puede leerlos usted mismo desde el manejador de cuerpo, o usar:

$ent->bodyhandle->print($outstream);

lo cual utiliza llamadas read() para extraer la información, y por lo tanto funcionará tanto con cuerpos de texto como binarios.

Advertencia: Por favor, proporcione un OUTSTREAM. Este método anula difiere del comportamiento de Mail::Internet, que genera en STDOUT si no se proporciona ningún filehandle: esto puede llevar a confusión.

print_header [OUTSTREAM]
Método de instancia, heredado. Genera la cabecera en el OUTSTREAM dado. Realmente deberías proporcionar el OUTSTREAM.
stringify
Método de instancia. Devuelve la entidad como una cadena, exactamente como "print" la imprimiría. El cuerpo se codificará según sea necesario y contendrá cualquier subparte. También puedes usar as_string().
stringify_body
Método de instancia. Devuelve el cuerpo del mensaje codificado como una cadena, exactamente como "print_body" lo imprimiría. También puedes usar body_as_string().

Si desea el cuerpo no codificado, y está tratando con un mensaje de una sola parte (como

a "text/plain"), usa bodyhandle() en su lugar:

if ($ent->bodyhandle) {
    $unencoded_data = $ent->bodyhandle->as_string;
}
else {
    ### este mensaje no tiene datos de cuerpo (¡pero podría tener partes!)
}
stringify_header
Método de instancia. Devuelve la cabecera como una cadena, exactamente como "print_header" la imprimiría. También puedes usar header_as_string().

NOTAS

Por dentro

Una MIME::Entity se compone de los siguientes elementos:

  • Una cabecera, que es una referencia a un objeto MIME::Head que contiene la información de la cabecera.
  • Un manejador de cuerpo (bodyhandle), que es una referencia a un objeto MIME::Body que contiene los datos del cuerpo decodificados. Esto solo se define si el mensaje es de tipo "singlepart": 
    application/*
audio/*
image/*
text/*
video/*
  • Una matriz de partes, donde cada parte es un objeto MIME::Entity. El número de partes solo será distinto de cero si el tipo de contenido no es uno de los tipos "singlepart": 
    message/*        (debería tener exactamente una parte)
multipart/*      (debería tener una o más partes)

El "problema de los dos cuerpos"

MIME::Entity y Mail::Internet ven los cuerpos de los mensajes de forma diferente, y esto puede causar confusión e inconvenientes. Lamentablemente, no puedo cambiar el comportamiento de MIME::Entity sin romper mucho código ya existente. Pero abramos el debate para algunas preguntas...

¿Cuál es la diferencia entre un "mensaje" y una "entidad"?
Un mensaje son los datos reales que se envían o reciben; normalmente esto significa un flujo de líneas terminadas por saltos de línea. Una entidad es la representación de un mensaje como un objeto.

Esto significa que obtienes un "mensaje" cuando imprimes una "entidad" *a* un manejador de archivos, y obtienes una "entidad" cuando analizas un mensaje *desde* un manejador de archivos.

¿Qué es el cuerpo de un mensaje?
Mail::Internet: La porción del mensaje impreso después de la cabecera.

MIME::Entity: La porción del mensaje impreso después de la cabecera.

¿Cómo se almacena el cuerpo de un mensaje en una entidad?
Mail::Internet: Como una matriz de líneas.

MIME::Entity: Depende del tipo de contenido del mensaje. Para los tipos "contenedores" ("multipart/*", "message/*"), almacenamos las entidades contenidas como una matriz de "partes", a las que se accede a través del método parts(), donde cada parte es una MIME::Entity completa. Para los tipos "singlepart" ("text/*", "image/*", etc.), los datos del cuerpo sin codificar se referencian a través de un objeto MIME::Body, al que se accede a través del método bodyhandle():

                  bodyhandle()   parts()
Content-type:     devuelve:      devuelve:
------------------------------------------------------------
application/*     MIME::Body     vacío
audio/*           MIME::Body     vacío
image/*           MIME::Body     vacío
message/*         undef          lista MIME::Entity (generalmente 1)
multipart/*       undef          lista MIME::Entity (generalmente >0)
text/*            MIME::Body     vacío
video/*           MIME::Body     vacío
x-*/*             MIME::Body     vacío

Como caso especial, "message/*" es actualmente ambiguo: dependiendo del analizador, un "message/*" podría tratarse como un singlepart, con un MIME::Body y sin partes. Usa bodyhandle() como árbitro final.

¿Qué devuelve el método body()?
Mail::Internet: Como una matriz de líneas, lista para ser enviada.

MIME::Entity: Como una matriz de líneas, lista para ser enviada.

¿Cuál es la mejor manera de acceder a los datos del cuerpo?
Mail::Internet: Usa el método body().

MIME::Entity: Depende de lo que quieras... ¿los datos *codificados* (tal como se transportan), o los datos *sin codificar*? Continúa leyendo...

¿Cómo obtengo los datos del cuerpo "codificados"?
Mail::Internet: Usa el método body().

MIME::Entity: Usa el método body(). También puedes usar:

$entity->print_body()
$entity->stringify_body()   ### también conocido como $entity->body_as_string()
¿Cómo obtengo los datos del cuerpo "sin codificar"?
Mail::Internet: Usa el método body().

MIME::Entity: ¡Usa el método bodyhandle()! Si el método bodyhandle() devuelve verdadero, entonces ese valor es un MIME::Body que se puede usar para acceder a los datos a través de su método open(). Si el método bodyhandle() devuelve un valor indefinido, entonces la entidad es probablemente un "contenedor" que no tiene datos de cuerpo propios (por ejemplo, un mensaje "multipart"): en este caso, deberías acceder a los componentes a través del método parts(). Así:

if ($bh = $entity->bodyhandle) {
    $io = $bh->open;
    ...accede a los datos sin codificar a través de $io->getline o $io->read...
    $io->close;
}
else {
    foreach my $part (@parts) {
        ...haz algo con la parte...
    }
}

También puedes usar:

if ($bh = $entity->bodyhandle) {
    $unencoded_data = $bh->as_string;
}
else {
    ...haz cosas con las partes...
}
¿Qué devuelve el método body()?
Mail::Internet: El cuerpo del mensaje codificado para el transporte, como una matriz de líneas.

MIME::Entity: El cuerpo del mensaje codificado para el transporte, como una matriz de líneas.

¿Qué imprime print_body()?
Mail::Internet: Exactamente lo que body() te devolvería.

MIME::Entity: Exactamente lo que body() te devolvería.

Supongamos que tengo una entidad que podría ser singlepart o multipart. ¿Cómo imprimo solo "el contenido después de la cabecera"?
Mail::Internet: Usa print_body().

MIME::Entity: Usa print_body().

¿Por qué MIME::Entity es tan diferente de Mail::Internet?
Porque se espera que los flujos MIME tengan datos no textuales... posiblemente, una gran cantidad de ellos, como un archivo tar.

Porque los mensajes MIME pueden consistir en múltiples partes, que son más fácilmente manipulables como objetos MIME::Entity.

Porque en el mundo más simple de Mail::Internet, los datos de un mensaje y su representación impresa son *idénticos*... y en el mundo MIME, no lo son.

Porque analizar cuerpos multipart sobre la marcha, o formatear cuerpos multipart para su salida, es una tarea no trivial.

Esto es confuso. ¿Se pueden hacer las dos clases más compatibles?
No fácilmente; sus implementaciones son necesariamente muy diferentes. Mail::Internet es una forma simple y eficiente de tratar con un mensaje de correo de "caja negra"... cuyos datos internos no te importan mucho. MIME::Entity, en contraste, se preocupa *mucho* por el contenido del mensaje: ¡ese es su trabajo!

Asuntos de diseño

Algunas cosas simplemente no pueden ser ignoradas
En los mensajes multipart, la "preámbulo" es la porción que precede al primer límite de encapsulación, y el "epílogo" es la porción que sigue al último límite de encapsulación.

Según RFC 2046:

Parece haber espacio para información adicional antes
del primer límite de encapsulación y después del último
límite.  Estas áreas generalmente deben dejarse en blanco, y
las implementaciones deben ignorar cualquier cosa que aparezca antes del
primer límite o después del último.
NOTA: Estas áreas de "preámbulo" y "epílogo" generalmente
no se utilizan debido a la falta de tipificación adecuada de estas partes
y la falta de semántica clara para manejar estas áreas en las pasarelas,
particularmente en las pasarelas X.400.  Sin embargo, en lugar de
dejar el área del preámbulo en blanco, muchos implementadores de MIME
han encontrado que es un lugar conveniente para insertar una
nota explicativa para los destinatarios que leen el mensaje con
software pre-MIME, ya que dicho notas serán ignoradas por
el software compatible con MIME.

En el mundo de estándares y prácticas, ese es el estándar. Ahora, sobre la práctica:

Algunos "mailers" de "MIME" pueden poner incorrectamente una "parte" en el preámbulo. Dado que tenemos que analizar el contenido *de todos modos*, en el futuro *puede* que permita la opción del analizador de crear objetos MIME::Entity especiales para el preámbulo y el epílogo, con objetos MIME::Head falsos.

Por ahora, sin embargo, somos compatibles con MIME, así que probablemente no cambiaré cómo funcionamos.
