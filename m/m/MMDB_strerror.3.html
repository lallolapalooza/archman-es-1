DESCRIPCIÓN

La biblioteca libmaxminddb proporciona funciones para trabajar con archivos MaxMind DB. Ver https://maxmind.github.io/MaxMind-DB/ para la especificación del formato MaxMind DB. Las bases de datos y los resultados se representan mediante diferentes estructuras. Las bases de datos se abren llamando a MMDB_open(). Puedes buscar direcciones IP como cadenas con MMDB_lookup_string() o como punteros a estructuras sockaddr con MMDB_lookup_sockaddr().

Si la búsqueda encuentra la dirección IP en la base de datos, devuelve una estructura MMDB_lookup_result_s. Si esa estructura indica que la base de datos tiene datos para la dirección IP, hay varias funciones que puedes usar para recuperar esos datos. Estas incluyen MMDB_get_value() y MMDB_get_entry_data_list(). Consulta la documentación de las funciones para más detalles.

Cuando hayas terminado con el manejador de la base de datos, debes llamar a MMDB_close().

Todas las funciones, estructuras y macros públicas comienzan con MMDB_.

ESTRUCTURAS DE DATOS

Todas las estructuras exportadas por el encabezado maxminddb.h de esta biblioteca se definen como typedef struct foo_s { ... } foo_s, por lo que puedes referirte a ellas sin el prefijo struct.

Esta biblioteca proporciona las siguientes estructuras:

MMDB_s

Esta es la referencia del manejador de un archivo MaxMind DB. Solo documentamos algunos de los campos de esta estructura destinados a uso público. Todos los demás campos están sujetos a cambios y están destinados únicamente a uso interno.

typedef struct MMDB_s {
    uint32_t flags;
    const char *filename;
    ...
    MMDB_metadata_s metadata;
} MMDB_s;
  • uint32_t flags - los flags con los que se abrió la base de datos. Ver la documentación de MMDB_open() para más detalles.
  • const char *filename - el nombre del archivo que se abrió, como se pasó a MMDB_open().
  • MMDB_metadata_s metadata - los metadatos de la base de datos.

MMDB_metadata_s y MMDB_description_s

Esta estructura se puede obtener desde la estructura MMDB_s. Contiene los metadatos leídos desde el archivo de base de datos. Nota: puede ser más conveniente acceder a estos metadatos llamando MMDB_get_metadata_as_entry_data_list().

typedef struct MMDB_metadata_s {
    uint32_t node_count;
    uint16_t record_size;
    uint16_t ip_version;
    const char *database_type;
    struct {
        size_t count;
        const char **names;
    } languages;
    uint16_t binary_format_major_version;
    uint16_t binary_format_minor_version;
    uint64_t build_epoch;
    struct {
        size_t count;
        MMDB_description_s **descriptions;
    } description;
} MMDB_metadata_s;
typedef struct MMDB_description_s {
    const char *language;
    const char *description;
} MMDB_description_s;

Estas estructuras deben ser principalmente autoexplicativas.

El miembro ip_version debe ser siempre 4 o 6. El miembro binary_format_major_version debe ser siempre 2.

No hay requisito que los metadatos de la base de datos incluyan idiomas o descripciones, por lo que los miembros count de estos elementos de metadatos pueden ser cero. Todos los demás miembros de MMDB_metadata_s deben estar poblados.

MMDB_lookup_result_s

Esta estructura se devuelve como resultado de una búsqueda de una dirección IP.

typedef struct MMDB_lookup_result_s {
    bool found_entry;
    MMDB_entry_s entry;
    uint16_t netmask;
} MMDB_lookup_result_s;

Si el miembro found_entry es falso, los demás miembros de esta estructura no contienen valores significativos. Siempre verifica que found_entry sea verdadero primero.

El miembro entry se usa para buscar los datos asociados con la dirección IP.

El miembro netmask indica qué subred pertenece la dirección IP en esta base de datos. Por ejemplo, si buscas la dirección 1.1.1.1 en una base de datos IPv4 y el valor devuelto es 16, entonces la dirección pertenece a la subred 1.1.0.0/16.

Si la base de datos es una base de datos IPv6, el valor devuelto para netmask siempre es una longitud de red IPv6 (de 0 a 128), incluso si esa base de datos también contiene redes IPv4. Si buscas una dirección IPv4 y quieres convertir el netmask en un valor de netmask IPv4, simplemente resta 96 del valor.

MMDB_result_s

No necesitas profundizar demasiado en esta estructura. Obtendrás esta estructura de una estructura MMDB_lookup_result_s y la pasarás a varias funciones.

MMDB_entry_data_s

Esta estructura se usa para devolver un solo segmento de datos asociado con una dirección IP. Estos segmentos pueden apuntar a otros segmentos, como en el caso de mapas y arreglos. Algunos miembros de esta estructura no están documentados y son únicamente para uso interno.

typedef struct MMDB_entry_data_s {
    bool has_data;
    union {
        uint32_t pointer;
        const char *utf8_string;
        double double_value;
        const uint8_t *bytes;
        uint16_t uint16;
        uint32_t uint32;
        int32_t int32;
        uint64_t uint64;
        {mmdb_uint128_t or uint8_t[16]} uint128;
        bool boolean;
        float float_value;
    };
    ...
    uint32_t data_size;
    uint32_t type;
} MMDB_entry_data_s;

El miembro has_data es verdadero si se encontró datos para una búsqueda dada. Ver MMDB_get_value() para más detalles. Si este miembro es falso, ninguno de los otros valores en la estructura es significativo.

La unión al inicio de la estructura define los datos reales. Para determinar cuál miembro de la unión es el correcto, ve el contenido de la estructura.

EJEMPLO

El siguiente ejemplo muestra cómo usar la biblioteca MMDB con un archivo MaxMind DB:


#include <maxminddb.h>

int main() {
    MMDB_s *mmdb = MMDB_open("example.db", MMDB_RDONLY, NULL);
    if (mmdb == NULL) {
        // manejo de errores
    }
    MMDB_lookup_result_s result = MMDB_lookup_string(mmdb, "1.1.1.1", NULL, NULL);
    if (result.found_entry) {
        // procesar el resultado
    }
    MMDB_close(mmdb);
}

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

El miembro type de la unión debe ser revisado. El miembro pointer de la unión debe nunca ser poblado en cualquier dato devuelto por la API. Los punteros deben resolverse internamente.

El miembro data_size es relevante solo para los datos de tipo utf8_string y bytes. El utf8_string no es terminado con null y data_size debe usarse para determinar su longitud.

El miembro type puede ser comparado con uno de los macros MMDB_DATA_TYPE_*.

Enteros de 128 bits

El manejo de datos de tipo uint128 depende de cómo tu plataforma soporta enteros de 128 bits, si lo hace o no. Con GCC 4.4 y 4.5 podemos escribir unsigned int __attribute__ ((__mode__ (TI))). Con versiones más recientes de GCC (4.6+) y clang (3.2+) podemos simplemente escribir "unsigned __int128".

Para trabajar alrededor de estas diferencias, esta biblioteca define un tipo mmdb_uint128_t. Este tipo se define en el archivo maxminddb.h para que puedas usarlo en tu código propio.

Con compiladores antiguos, no podemos usar un entero, por lo que usamos un array de 16 bytes de uint8_t. Esto es los datos brutos de la base de datos.

Esta biblioteca proporciona un macro público MMDB_UINT128_IS_BYTE_ARRAY. Si es verdadero (1), los valores de uint128 se devuelven como un array de bytes, si es falso se devuelven como un entero mmdb_uint128_t.

Macros de tipo de dato

Esta biblioteca proporciona un macro para cada tipo de datos definido por el estándar MaxMind DB.

  • MMDB_DATA_TYPE_UTF8_STRING
  • MMDB_DATA_TYPE_DOUBLE
  • MMDB_DATA_TYPE_BYTES
  • MMDB_DATA_TYPE_UINT16
  • MMDB_DATA_TYPE_UINT32
  • MMDB_DATA_TYPE_MAP
  • MMDB_DATA_TYPE_INT32
  • MMDB_DATA_TYPE_UINT64
  • MMDB_DATA_TYPE_UINT128
  • MMDB_DATA_TYPE_ARRAY
  • MMDB_DATA_TYPE_BOOLEAN
  • MMDB_DATA_TYPE_FLOAT

También hay algunos tipos para uso interno:

  • MMDB_DATA_TYPE_EXTENDED
  • MMDB_DATA_TYPE_POINTER
  • MMDB_DATA_TYPE_CONTAINER
  • MMDB_DATA_TYPE_END_MARKER

Si ves uno de estos en los datos devueltos, algo ha ido muy mal. La base de datos está dañada o se generó incorrectamente o hay un error en el código de libmaxminddb.

Valores de puntero y MMDB_close()

Los miembros utf8_string, bytes y (tal vez) el miembro uint128 de esta estructura son punteros directamente hacia la sección de datos de la base de datos. Esto puede ser un bloque calloc o mmap de memoria. En cualquier caso, estos punteros se vuelven inválidos después de llamarse MMDB_close().

Si necesitas referirte a este dato después de ese tiempo, debes copiar los datos con una función adecuada (strdup, memcpy, etc.).

MMDB_entry_data_list_s

Esta estructura encapsula una lista ligada de estructuras MMDB_entry_data_s.

typedef struct MMDB_entry_data_list_s {
    MMDB_entry_data_s entry_data;
    struct MMDB_entry_data_list_s *next;
} MMDB_entry_data_list_s;

Esta estructura te permite ver datos de mapa o arreglo completo iterando por la lista ligada.

MMDB_search_node_s

Esta estructura encapsula los dos registros de un nodo de búsqueda. Este es realmente útil solo si quieres escribir código que iterate sobre el árbol de búsqueda completo en lugar de buscar un IP específico.

typedef struct MMDB_search_node_s {
    uint64_t left_record;
    uint64_t right_record;
    uint8_t left_record_type;
    uint8_t right_record_type;
    MMDB_entry_s left_record_entry;
    MMDB_entry_s right_record_entry;
} MMDB_search_node_s;

Los tipos de registro serán uno de los siguientes valores:

  • MMDB_RECORD_TYPE_SEARCH_NODE - El registro apunta al siguiente nodo de búsqueda.
  • MMDB_RECORD_TYPE_EMPTY - El registro es un placeholder que indica que no hay datos para el IP. La búsqueda debe finalizar aquí.
  • MMDB_RECORD_TYPE_DATA - El registro contiene datos en la sección de datos de la base de datos. Usa el registro cuando busques los datos del registro.
  • MMDB_RECORD_TYPE_INVALID - El registro es inválido. Esto puede deberse a un nodo inválido o a una base de datos corrupta.

El MMDB_entry_s del registro es válido solo si el tipo es MMDB_RECORD_TYPE_DATA. Los intentos de usar un registro para otros tipos de registro generan un error o datos inválidos.

CÓDIGOS DE ESTADO

Esta biblioteca devuelve (o poblada) códigos de estado para muchas funciones. Estos códigos de estado son:

  • MMDB_SUCCESS - todo funcionó
  • MMDB_FILE_OPEN_ERROR - hubo un error al abrir el archivo MaxMind DB.
  • MMDB_IO_ERROR - una operación de I/O falló. Verifica errno para más detalles.
  • MMDB_CORRUPT_SEARCH_TREE_ERROR - al buscar un IP en el árbol de búsqueda se obtuvo un resultado imposible. La base de datos está dañada o fue generada incorrectamente o hay un error en el código de libmaxminddb.
  • MMDB_INVALID_METADATA_ERROR - algo en la base de datos está mal. Esto incluye claves de metadatos ausentes o valores imposibles (como un ip_version de 7).
  • MMDB_UNKNOWN_DATABASE_FORMAT_ERROR - la metadatos de la base de datos indican que su versión principal no es 2. Esta biblioteca solo puede manejar la versión 2.
  • MMDB_OUT_OF_MEMORY_ERROR - falló una llamada a la memoria (malloc, etc.).
  • MMDB_INVALID_DATA_ERROR - un campo de datos en la sección de datos contiene datos inválidos. Por ejemplo, un campo uint16 afirma ser más largo que 2 bytes. La base de datos probablemente está dañada o fue generada incorrectamente.
  • MMDB_INVALID_LOOKUP_PATH_ERROR - el camino de búsqueda pasado a MMDB_get_value, MMDB_vget_value o MMDB_aget_value contiene un desplazamiento de array mayor que LONG_MAX o menor que LONG_MIN.
  • MMDB_LOOKUP_PATH_DOES_NOT_MATCH_DATA_ERROR - el camino de búsqueda pasado a MMDB_get_value, MMDB_vget_value o MMDB_aget_value no coincide con la estructura de datos del registro. Pueden causar varias razones. El camino de búsqueda puede incluir un clave no en un mapa. El camino de búsqueda puede incluir un índice de array mayor que un array o menor que el offset mínimo desde el final de un array. También puede ocurrir cuando el camino espera encontrar un mapa o array que no existan.

Todos los códigos de estado deben tratarse como valores de int.

MMDB_strerror()

const char *MMDB_strerror(int error_code)

Esta función toma un código de estado y devuelve una cadena en inglés explicando el estado.

FUNCIONES

Esta biblioteca proporciona las siguientes funciones exportadas:

MMDB_open()

int MMDB_open(
    const char *const filename,
    uint32_t flags,
    MMDB_s *const mmdb);

Esta función abre una conexión a un archivo de MaxMind DB. Su valor de retorno es un código de estado como se define anteriormente. Siempre verifica el valor de retorno de esta llamada.

MMDB_s mmdb;
int status = MMDB_open("/path/to/file.mmdb", MMDB_MODE_MMAP, &mmdb);
if (MMDB_SUCCESS != status) { ... }
...
MMDB_close(&mmdb);

El filename debe codificarse como UTF-8 en Windows.

La estructura MMDB_s que pasas puede estar en la pila o reservada en la memoria heap. Sin embargo, si el abrir es exitoso, contendrá datos reservados en la memoria heap, por lo que necesitas cerrarla con MMDB_close(). Si el estado devuelto no es MMDB_SUCCESS, esta biblioteca asegura que se libere la memoria asignada antes de devolver.

Los flags actualmente proporcionados son:

•
MMDB_MODE_MMAP - abre el archivo con mmap().

Pasando otros valores para flags puede producir resultados inesperados. En el futuro, podríamos agregar más flags que puedas unir con el modo, así como más modos.

También puedes pasar 0 como valor de flags, en el cual el archivo se abrirá con los flags por defecto. Sin embargo, estos valores por defecto pueden cambiar en futuras versiones. El valor por defecto actual es MMDB_MODE_MMAP.

MMDB_close()

void MMDB_close(MMDB_s *const mmdb);

Esta libera cualquier memoria reservada o mmap'ada que se encuentre en la estructura MMDB_s. No libera la memoria allocada en la pila.

MMDB_lookup_string()

MMDB_lookup_result_s MMDB_lookup_string(
    MMDB_s *const mmdb,
    const char *const ipstr,
    int *const gai_error,
    int *const mmdb_error);

Esta función busca una dirección IP que se pasa como una cadena terminada en nulo. Internamente llama a getaddrinfo() para resolver la dirección a una forma binaria. Luego llama a MMDB_lookup_sockaddr() para buscar la dirección en la base de datos. Si ya ha resuelto una dirección, puede llamar directamente a MMDB_lookup_sockaddr(), en lugar de resolver la dirección dos veces.

int gai_error, mmdb_error;
MMDB_lookup_result_s result =
    MMDB_lookup_string(&mmdb, "1.2.3.4", &gai_error, &mmdb_error);
if (0 != gai_error) { ... }
if (MMDB_SUCCESS != mmdb_error) { ... }
if (result.found_entry) { ... }

Esta función siempre devuelve una estructura MMDB_lookup_result_s, pero también debe comprobar los parámetros gai_error y mmdb_error. Si alguno de ellos indica un error, la estructura devuelta no tiene sentido.

Si no ocurrió ningún error, aún debe asegurarse de que el miembro found_entry en el resultado devuelto sea verdadero. Si no lo es, esto significa que la dirección IP no tiene una entrada en la base de datos.

Esta función funcionará con direcciones IPv4 incluso cuando la base de datos contenga datos tanto para direcciones IPv4 como IPv6. La dirección IPv4 se buscará como '::xxx.xxx.xxx.xxx' en lugar de ser remapeada al bloque ::ffff:xxx.xxx.xxx.xxx asignado a direcciones IPv6 mapeadas a IPv4.

Si pasa una dirección IPv6 a una base de datos solo con datos IPv4, el miembro found_entry será falso, pero el estado mmdb_error seguirá siendo MMDB_SUCCESS.

MMDB_lookup_sockaddr()

MMDB_lookup_result_s MMDB_lookup_sockaddr(
    MMDB_s *const mmdb,
    const struct sockaddr *const sockaddr,
    int *const mmdb_error);

Esta función busca una dirección IP que ya ha sido resuelta por getaddrinfo().

Aparte de no llamar a getaddrinfo() en sí, esta función es idéntica a la función MMDB_lookup_string().

int mmdb_error;
MMDB_lookup_result_s result =
    MMDB_lookup_sockaddr(&mmdb, address->ai_addr, &mmdb_error);
if (MMDB_SUCCESS != mmdb_error) { ... }
if (result.found_entry) { ... }

Funciones de Búsqueda de Datos

Hay tres funciones para buscar datos asociados con una dirección IP.

int MMDB_get_value(
    MMDB_entry_s *const start,
    MMDB_entry_data_s *const entry_data,
    ...);
int MMDB_vget_value(
    MMDB_entry_s *const start,
    MMDB_entry_data_s *const entry_data,
    va_list va_path);
int MMDB_aget_value(
    MMDB_entry_s *const start,
    MMDB_entry_data_s *const entry_data,
    const char *const *const path);

Las tres funciones permiten tres estilos de llamada ligeramente diferentes, pero todas hacen lo mismo.

El primer parámetro es un valor MMDB_entry_s. En la mayoría de los casos, provendrá del valor MMDB_lookup_result_s devuelto por MMDB_lookup_string() o MMDB_lookup_sockaddr().

El segundo parámetro es una referencia a una estructura MMDB_entry_data_s. Esta se poblará con los datos que se están buscando, si se encuentra alguno. Si no se encuentra nada, el miembro has_data de esta estructura será falso. Si has_data es verdadero, puede ver el miembro data_type.

El último parámetro es una ruta de búsqueda. La ruta consta de un conjunto de cadenas que representan claves de mapa (por ejemplo, "city") o índices de matriz (por ejemplo, "0", "1", "-1") para usar en la búsqueda.

Los índices de matriz negativos se tratarán como un desplazamiento desde el final de la matriz. Por ejemplo, "-1" se refiere al último elemento de la matriz.

La ruta de búsqueda le permite navegar por una estructura de datos compleja. Por ejemplo, dados estos datos:

{
    "names": {
        "en": "Germany",
        "de": "Deutschland"
    },
    "cities": [ "Berlin", "Frankfurt" ]
}

Podríamos buscar el nombre en inglés con este código:

MMDB_lookup_result_s result =
    MMDB_lookup_sockaddr(&mmdb, address->ai_addr, &mmdb_error);
MMDB_entry_data_s entry_data;
int status =
    MMDB_get_value(&result.entry, &entry_data,
                   "names", "en", NULL);
if (MMDB_SUCCESS != status) { ... }
if (entry_data.has_data) { ... }

Si quisiéramos encontrar la primera ciudad, la ruta de búsqueda sería "cities", "0". Si no proporciona ninguna ruta de búsqueda, obtendrá la entrada que corresponde al mapa de nivel superior. La ruta de búsqueda siempre debe terminar en NULL, independientemente de la función que llame.

La función MMDB_get_value toma un número variable de argumentos. Todos los argumentos después del puntero de estructura MMDB_entry_data_s * son la ruta de búsqueda. El último argumento debe ser NULL.

La función MMDB_vget_value acepta una va_list como ruta de búsqueda. El último elemento recuperado por va_arg() debe ser NULL.

Finalmente, MMDB_aget_value acepta una matriz de cadenas como ruta de búsqueda. El último miembro de esta matriz debe ser NULL.

Si desea obtener todos los datos de entrada a la vez, puede llamar a MMDB_get_entry_data_list() en su lugar.

Para cada una de las tres funciones, el valor de retorno es un código de estado según se define anteriormente.

MMDB_get_entry_data_list()

int MMDB_get_entry_data_list(
    MMDB_entry_s *start,
    MMDB_entry_data_list_s **const entry_data_list);

Esta función le permite obtener todos los datos de una estructura de datos compleja a la vez, en lugar de buscar cada pieza mediante llamadas repetidas a MMDB_get_value().

MMDB_lookup_result_s result =
    MMDB_lookup_sockaddr(&mmdb, address->ai_addr, &mmdb_error);
MMDB_entry_data_list_s *entry_data_list, *first;
int status =
    MMDB_get_entry_data_list(&result.entry, &entry_data_list);
if (MMDB_SUCCESS != status) { ... }
// guardamos esto para poder liberar estos datos más tarde
first = entry_data_list;
while (1) {
    MMDB_entry_data_list_s *next = entry_data_list = entry_data_list->next;
    if (NULL == next) {
        break;
    }
    switch (next->entry_data.type) {
        case MMDB_DATA_TYPE_MAP: { ... }
        case MMDB_DATA_TYPE_UTF8_STRING: { ... }
        ...
    }
}
MMDB_free_entry_data_list(first);

NAME

MMDB_strerror - Return a string representation of an error code

SYNOPSIS

#include <maxminddb.h>
const char *
MMDB_strerror(int status);

DESCRIPTION

The MMDB_strerror() function returns a pointer to a statically allocated string describing the error code given by status. The string is owned by the library and should not be modified or freed.

The return value is guaranteed to be non-NULL.

Error codes are defined in the header file.

FUNCTIONS

MMDB_dump_entry_data_list()

void MMDB_dump_entry_data_list(
    FILE *const file,
    MMDB_entry_data_list_s *const entry_data_list,
    int spaces);

This dumps the contents of an MMDB_entry_data_list_s structure to the specified file handle. The spaces argument is the number of spaces to indent for pretty printing. This function is intended for debugging and showing data to users.

This function has no return value.

Note that the structure of the output is not stable between libmaxminddb releases, so you should not rely on the specific formatting produced by this function. It is intended to be used to show data to users in a readable way and for debugging purposes.

The return value of the function is a status code as defined above.

MMDB_read_node()

int MMDB_read_node(
    MMDB_s *const mmdb,
    uint32_t node_number,
    MMDB_search_node_s *const node);

This reads a specific node in the search tree. The third argument is a reference to an MMDB_search_node_s structure that will be populated by this function.

The return value is a status code. If you pass a node_number that is greater than the number of nodes in the database, this function will return MMDB_INVALID_NODE_NUMBER_ERROR, otherwise it will return MMDB_SUCCESS.

The first node in the search tree is always node 0. If you wanted to iterate over the whole search tree, you would start by reading node 0 and then following the the records that make up this node, based on the type of each record. If the type is MMDB_RECORD_TYPE_SEARCH_NODE then the record contains an integer for the next node to look up.

MMDB_lib_version()

const char *MMDB_lib_version(void)

This function returns the library version as a string, something like "2.0.0".

#include <string.h>

        MMDB_lookup_string(&mmdb, ip_address, &gai_error, &mmdb_error);
    if (0 != gai_error) {
        fprintf(stderr,
                "\n  Error from getaddrinfo for %s - %s\n\n",
                ip_address, gai_strerror(gai_error));
        exit(2);
    }
    if (MMDB_SUCCESS != mmdb_error) {

            "\n  No entry for this IP address (%s) was found\n\n",
