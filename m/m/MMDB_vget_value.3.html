DESCRIPCIÓN

La biblioteca libmaxminddb proporciona funciones para trabajar con archivos de MaxMind DB. Consulte https://maxmind.github.io/MaxMind-DB/ para la especificación de formato de MaxMind DB. Las bases de datos y los resultados se representan por estructuras diferentes. Las bases de datos se abren llamando a MMDB_open(). Puede buscar direcciones IP como cadena con MMDB_lookup_string() o como una referencia a una estructura sockaddr con MMDB_lookup_sockaddr().

Si la búsqueda encuentra la dirección IP en la base de datos, devuelve una estructura MMDB_lookup_result_s. Si esta estructura indica que la base de datos tiene datos para la dirección IP, hay varias funciones que pueden usarse para obtener esos datos. Estas incluyen MMDB_get_value() y MMDB_get_entry_data_list(). Consulte la documentación de las funciones por separado para más detalles.

Cuando haya terminado con el manejador de base de datos, debe llamar a MMDB_close().

Todas las funciones públicas, estructuras y macros comienzan con MMDB_.

ESTRUCTURAS DE DATOS

Todas las estructuras exportadas por el encabezado maxminddb.h de esta biblioteca se definen como typedef struct foo_s { ... } foo_s, por lo que puede referirse a ellas sin el prefijo struct.

Esta biblioteca proporciona las siguientes estructuras:

MMDB_s

Esta es la handle para un archivo de MaxMind DB. Solo documentamos algunos de los campos de esta estructura intenados para uso público. Todos los otros campos son sujetos a cambios y están destinados únicamente a uso interno.

typedef struct MMDB_s {
    uint32_t flags;
    const char *filename;
    ...
    MMDB_metadata_s metadata;
} MMDB_s;
  • uint32_t flags - los flags con los que se abrió la base de datos. Consulte la documentación de MMDB_open() para más detalles.
  • const char *filename - el nombre del archivo que se abrió, como se pasó a MMDB_open().
  • MMDB_metadata_s metadata - los metadatos de la base de datos.

MMDB_metadata_s y MMDB_description_s

Esta estructura puede ser obtenida desde la estructura MMDB_s. Contiene los metadatos leídos de un archivo de base de datos. Nota que puede ser más conveniente acceder a estos metadatos llamando MMDB_get_metadata_as_entry_data_list().

typedef struct MMDB_metadata_s {
    uint32_t node_count;
    uint16_t record_size;
    uint16_t ip_version;
    const char *database_type;
    struct {
        size_t count;
        const char **names;
    } languages;
    uint16_t binary_format_major_version;
    uint16_t binary_format_minor_version;
    uint64_t build_epoch;
    struct {
        size_t count;
        MMDB_description_s **descriptions;
    } description;
} MMDB_metadata_s;
typedef struct MMDB_description_s {
    const char *language;
    const char *description;
} MMDB_description_s;

Estas estructuras deben ser mayoría self-explanatory.

El miembro ip_version debe siempre ser 4 o 6. El miembro binary_format_major_version debe siempre ser 2.

No hay requisito que los metadatos de la base de datos incluyan idiomas o descripciones, por lo que el count para estos aspectos de los metadatos puede ser cero. Todos los otros miembros de MMDB_metadata_s deben ser populados.

MMDB_lookup_result_s

Esta estructura se devuelve como resultado de la búsqueda de una dirección IP.

typedef struct MMDB_lookup_result_s {
    bool found_entry;
    MMDB_entry_s entry;
    uint16_t netmask;
} MMDB_lookup_result_s;

Si el miembro found_entry es falso, los demás miembros de esta estructura no contienen valores significativos. Deben verificar primero que found_entry sea verdadero.

El miembro entry se usa para buscar los datos asociados a la dirección IP.

El miembro netmask indica qué subred pertenece la dirección IP en esta base de datos. Por ejemplo, si busca la dirección 1.1.1.1 en una base de datos IPv4 y el valor devuelto netmask es 16, entonces la dirección pertenece a la subred 1.1.0.0/16.

Si la base de datos es una base de datos IPv6, el valor devuelto netmask siempre es un prefijo de IPv6 (de 0 a 128), incluso si esa base de datos también contiene redes IPv4. Si busca una dirección IPv4 y quieres convertir el netmask en un valor de subred IPv4, puedes simplemente restar 96 del valor.

MMDB_result_s

No necesita profundizar en esta estructura. Se obtendrá de una estructura MMDB_lookup_result_s y se pasará a diversas funciones.

MMDB_entry_data_s

Esta estructura se usa para devolver un único bloque de datos asociado con una dirección IP. Estos bloques pueden apuntar a otros bloques, como en el caso de mapas y arrays. Algunos miembros de esta estructura no están documentados debido a su uso exclusivo interno.

typedef struct MMDB_entry_data_s {
    bool has_data;
    union {
        uint32_t pointer;
        const char *utf8_string;
        double double_value;
        const uint8_t *bytes;
        uint16_t uint16;
        uint32_t uint32;
        int32_t int32;
        uint64_t uint64;
        {mmdb_uint128_t or uint8_t[16]} uint128;
        bool boolean;
        float float_value;
    };
    ...
    uint32_t data_size;
    uint32_t type;
} MMDB_entry_data_s;

El miembro has_data es verdadero si se encontró datos para una búsqueda específica. Consulte MMDB_get_value() para más detalles. Si este miembro es falso, ninguno de los otros valores en la estructura es significativo.

La unión al inicio de la estructura define los datos reales. Para determinar cuál miembro de la unión está siendo usado, puede consultar el valor de has_data.

está poblado, deberías mirar el miembro type. El miembro pointer de la unión nunca debe estar poblado en ningún dato devuelto por la API. Los punteros siempre deben resolverse internamente.

El miembro data_size solo es relevante para los datos utf8_string y bytes. utf8_string no termina en nulo y data_size *debe* usarse para determinar su longitud.

El miembro type se puede comparar con uno de los macros MMDB_DATA_TYPE_*.

Enteros de 128 bits

El manejo de datos uint128 depende de cómo tu plataforma soporte enteros de 128 bits, si es que lo hace. Con GCC 4.4 y 4.5 podemos escribir unsigned int __attribute__ ((__mode__ (TI))). Con versiones más nuevas de GCC (4.6+) y clang (3.2+) simplemente podemos escribir "unsigned __int128".

Para sortear estas diferencias, esta librería define un tipo mmdb_uint128_t. Este tipo se define en el encabezado maxminddb.h para que puedas usarlo en tu propio código.

Con compiladores más antiguos, no podemos usar un entero, así que en su lugar usamos un array de 16 bytes de valores uint8_t. Estos son los datos crudos de la base de datos.

Esta librería proporciona un macro público MMDB_UINT128_IS_BYTE_ARRAY. Si este es verdadero (1), entonces los valores uint128 se devuelven como un array de bytes; si es falso, se devuelven como un entero mmdb_uint128_t.

Macros de Tipo de Datos

Esta librería proporciona un macro para cada tipo de dato definido por la especificación MaxMind DB.

  • MMDB_DATA_TYPE_UTF8_STRING
  • MMDB_DATA_TYPE_DOUBLE
  • MMDB_DATA_TYPE_BYTES
  • MMDB_DATA_TYPE_UINT16
  • MMDB_DATA_TYPE_UINT32
  • MMDB_DATA_TYPE_MAP
  • MMDB_DATA_TYPE_INT32
  • MMDB_DATA_TYPE_UINT64
  • MMDB_DATA_TYPE_UINT128
  • MMDB_DATA_TYPE_ARRAY
  • MMDB_DATA_TYPE_BOOLEAN
  • MMDB_DATA_TYPE_FLOAT

También hay algunos tipos que son solo para uso interno:

  • MMDB_DATA_TYPE_EXTENDED
  • MMDB_DATA_TYPE_POINTER
  • MMDB_DATA_TYPE_CONTAINER
  • MMDB_DATA_TYPE_END_MARKER

Si ves alguno de estos en los datos devueltos, algo ha ido muy mal. La base de datos está dañada o se generó incorrectamente, o hay un error en el código de libmaxminddb.

Valores de Puntero y MMDB_close()

Los miembros utf8_string, bytes y (quizás) uint128 de esta estructura son todos punteros directos a la sección de datos de la base de datos. Este puede ser un bloque de memoria reservado con calloc o mmap. En cualquier caso, estos punteros se invalidarán después de que se llame a MMDB_close().

Si necesitas referirte a estos datos después de ese momento, deberías copiar los datos con una función apropiada (strdup, memcpy, etc.).

MMDB_entry_data_list_s

Esta estructura encapsula una lista enlazada de estructuras MMDB_entry_data_s.

typedef struct MMDB_entry_data_list_s {
    MMDB_entry_data_s entry_data;
    struct MMDB_entry_data_list_s *next;
} MMDB_entry_data_list_s;

Esta estructura te permite ver datos completos de tipo mapa o array iterando sobre la lista enlazada.

MMDB_search_node_s

Esta estructura encapsula los dos registros en un nodo de búsqueda. Esto es realmente útil solo si deseas escribir código que itere sobre todo el árbol de búsqueda en lugar de buscar una dirección IP específica.

typedef struct MMDB_search_node_s {
    uint64_t left_record;
    uint64_t right_record;
    uint8_t left_record_type;
    uint8_t right_record_type;
    MMDB_entry_s left_record_entry;
    MMDB_entry_s right_record_entry;
} MMDB_search_node_s;

Los dos tipos de registro tomarán uno de los siguientes valores:

  • MMDB_RECORD_TYPE_SEARCH_NODE - El registro apunta al siguiente nodo de búsqueda.
  • MMDB_RECORD_TYPE_EMPTY - El registro es un marcador de posición que indica que no hay datos para la dirección IP. La búsqueda debería terminar aquí.
  • MMDB_RECORD_TYPE_DATA - El registro es para datos en la sección de datos de la base de datos. Usa la entrada para el registro al buscar los datos del registro.
  • MMDB_RECORD_TYPE_INVALID - El registro no es válido. Se buscó un nodo no válido o la base de datos está corrupta.

La MMDB_entry_s para el registro solo es válida si el tipo es MMDB_RECORD_TYPE_DATA. Los intentos de usar una entrada para otros tipos de registro resultarán en un error o datos inválidos.

CÓDIGOS DE ESTADO

Esta librería devuelve (o rellena) códigos de estado para muchas funciones. Estos códigos de estado son:

  • MMDB_SUCCESS - todo funcionó
  • MMDB_FILE_OPEN_ERROR - hubo un error al intentar abrir el archivo MaxMind DB.
  • MMDB_IO_ERROR - una operación de E/S falló. Consulta errno para más detalles.
  • MMDB_CORRUPT_SEARCH_TREE_ERROR - buscar una dirección IP en el árbol de búsqueda nos dio un resultado imposible. La base de datos está dañada o se generó incorrectamente, o hay un error en el código de libmaxminddb.
  • MMDB_INVALID_METADATA_ERROR - algo en la base de datos está mal. Esto incluye claves de metadatos faltantes así como valores imposibles (como una ip_version de 7).
  • MMDB_UNKNOWN_DATABASE_FORMAT_ERROR - Los metadatos de la base de datos indican que su versión principal no es 2. Esta librería solo puede manejar la versión principal 2.
  • MMDB_OUT_OF_MEMORY_ERROR - una llamada de asignación de memoria (malloc, etc.) falló.
  • MMDB_INVALID_DATA_ERROR - una entrada en la sección de datos contiene datos inválidos. Por ejemplo, un campo uint16 afirma tener más de 2 bytes de longitud. La base de datos probablemente está dañada o se generó incorrectamente.
  • MMDB_INVALID_LOOKUP_PATH_ERROR - La ruta de búsqueda pasada a MMDB_get_value, MMDB_vget_value, o MMDB_aget_value contiene un índice de array que es mayor que LONGMAX o menor que LONGMIN.
  • MMDB_LOOKUP_PATH_DOES_NOT_MATCH_DATA_ERROR - La ruta de búsqueda pasada a MMDB_get_value,MMDB_vget_value, o MMDB_aget_value no coincide con la estructura de datos de la entrada. Hay varias razones por las que esto puede suceder. La ruta de búsqueda podría incluir una clave que no está en un mapa. La ruta de búsqueda podría incluir un índice de array mayor que un array o menor que el desplazamiento mínimo desde el final de un array. También puede ocurrir cuando la ruta espera encontrar un mapa o un array donde no existen.

Todos los códigos de estado deben tratarse como valores int.

MMDB_strerror()

const char *MMDB_strerror(int error_code)

Esta función toma un código de estado y devuelve una cadena en inglés que explica el estado.

FUNCIONES

Esta librería proporciona las siguientes funciones exportadas:

MMDB_open()

int MMDB_open(
    const char *const filename,
    uint32_t flags,
    MMDB_s *const mmdb);

Esta función abre un manejador para un archivo MaxMind DB. Su valor de retorno es un código de estado como se define arriba. Siempre verifica el valor de retorno de esta llamada.

MMDB_s mmdb;
int status =
    MMDB_open("/path/to/file.mmdb", MMDB_MODE_MMAP, &mmdb);
if (MMDB_SUCCESS != status) { ... }
...
MMDB_close(&mmdb);

filename debe estar codificado como UTF-8 en Windows.

La estructura MMDB_s que pasas puede estar en la pila o asignada desde el heap. Sin embargo, si la apertura es exitosa, contendrá datos asignados del heap, por lo que necesitas cerrarla con MMDB_close(). Si el estado devuelto no es MMDB_SUCCESS, esta librería se asegura de que toda la memoria asignada se libere antes de devolver.

Las banderas actualmente proporcionadas son:

•
MMDB_MODE_MMAP - abre la base de datos con mmap().

Pasar otros valores para flags puede producir resultados impredecibles. En el futuro, podemos añadir banderas adicionales que puedas combinar con un OR a nivel de bits con el modo, así como modos adicionales.

También puedes pasar 0 como valor de flags, en cuyo caso la base de datos se abrirá con las banderas por defecto. Sin embargo, estos valores por defecto pueden cambiar en futuras versiones. El valor por defecto actual es MMDB_MODE_MMAP.

MMDB_close()

void MMDB_close(MMDB_s *const mmdb);

Esto libera cualquier memoria asignada o mapeada por mmap que sea retenida por la estructura MMDB_s. *No libera la memoria de todos

MMDB_lookup_string()

MMDB_lookup_result_s MMDB_lookup_string(
    MMDB_s *const mmdb,
    const char *const ipstr,
    int *const gai_error,
    int *const mmdb_error);

This function looks up an IP address passed as a null-terminated string. It internally calls getaddrinfo() to resolve the address into binary form. It then calls MMDB_lookup_sockaddr() to look up the address in the database. If you have already resolved an address, you can call MMDB_lookup_sockaddr() directly without resolving it twice.

int gai_error, mmdb_error;
MMDB_lookup_result_s result =
    MMDB_lookup_string(&mmdb, "1.2.3.4", &gai_error, &mmdb_error);
if (0 != gai_error) { ... }
if (MMDB_SUCCESS != mmdb_error) { ... }
if (result.found_entry) { ... }

This function always returns an MMDB_lookup_result_s structure, but you must also check the gai_error and mmdb_error parameters. If either of them indicates an error, the returned structure will be useless.

If there are no errors, you must still ensure that the found_entry member in the returned structure is true. If it is not, it means that the IP address has no record in the database.

This function works with IPv4 addresses even when the database contains data for both IPv4 and IPv6. The IPv4 address will be looked up as ::xxx.xxx.xxx.xxx, not as ::ffff:xxx.xxx.xxx.xxx.

If you pass an IPv6 address to a database with only IPv4 data, the found_entry member will be false, but the mmdb_error status will still be MMDB_SUCCESS.

MMDB_lookup_sockaddr()

MMDB_lookup_result_s MMDB_lookup_sockaddr(
    MMDB_s *const mmdb,
    const struct sockaddr *const sockaddr,
    int *const mmdb_error);

This function looks up an IP address that has already been resolved via getaddrinfo().

Other than not calling getaddrinfo() itself, this function is identical to the MMDB_lookup_string() function.

int mmdb_error;
MMDB_lookup_result_s result =
    MMDB_lookup_sockaddr(&mmdb, address->ai_addr, &mmdb_error);
if (MMDB_SUCCESS != mmdb_error) { ... }
if (result.found_entry) { ... }

Data Lookup Functions

There are three functions for looking up data associated with an IP address.

int MMDB_get_value(
    MMDB_entry_s *const start,
    MMDB_entry_data_s *const entry_data,
    ...);
int MMDB_vget_value(
    MMDB_entry_s *const start,
    MMDB_entry_data_s *const entry_data,
    va_list va_path);
int MMDB_aget_value(
    MMDB_entry_s *const start,
    MMDB_entry_data_s *const entry_data,
    const char *const *const path);

All three functions allow for three slightly different calling styles, but they all do the same thing.

The first parameter is an MMDB_entry_s value. In most cases, this will come from the MMDB_lookup_result_s structure returned by MMDB_lookup_string() or MMDB_lookup_sockaddr().

The second parameter is a reference to an MMDB_entry_data_s structure. This will be filled with the data being looked up, if any data is found. If no data is found, the has_data member of this structure will be false. If has_data is true, you can inspect the data_type member.

The last parameter is a search path. The path consists of a set of strings that represent map keys (e.g. "city") or array indices (e.g. "0", "1", "-1") to use in the lookup.

Negative array indices are considered an offset from the end of the array. For example, "-1" refers to the last element of the array.

The search path allows you to navigate a complex structure. For example, given this data:

{
    "names": {
        "en": "Germany",
        "de": "Deutschland"
    },
    "cities": [ "Berlin", "Frankfurt" ]
}

We could look up the English name with this code:

MMDB_lookup_result_s result =
    MMDB_lookup_sockaddr(&mmdb, address->ai_addr, &mmdb_error);
MMDB_entry_data_s entry_data;
int status =
    MMDB_get_value(&result.entry, &entry_data,
                   "names", "en", NULL);
if (MMDB_SUCCESS != status) { ... }
if (entry_data.has_data) { ... }

If we want to find the first city, the search path would be "cities", "0". If you do not provide a search path, you will get the record corresponding to the top-level map. The search path must always end with NULL, regardless of which function you use.

The MMDB_get_value function accepts a variable number of arguments. All arguments after the pointer to the MMDB_entry_data_s structure are the search path. The last argument must be NULL.

The MMDB_vget_value function accepts a va_list as the search path. The last element retrieved by va_arg() must be NULL.

Finally, the MMDB_aget_value function accepts an array of strings as the search path. The last element of this array must be NULL.

If you want to get all entry data at once, you can call MMDB_get_entry_data_list().

For each of the three functions, the return value is a status code as defined above.

MMDB_get_entry_data_list()

int MMDB_get_entry_data_list(
    MMDB_entry_s *start,
    MMDB_entry_data_list_s **const entry_data_list);

This function allows you to get all of the data from a complex structure at once, rather than looking up each piece via repeated calls to MMDB_get_value().

MMDB_lookup_result_s result =
    MMDB_lookup_sockaddr(&mmdb, address->ai_addr, &mmdb_error);
MMDB_entry_data_list_s *entry_data_list, *first;
int status =
    MMDB_get_entry_data_list(&result.entry, &entry_data_list);
if (MMDB_SUCCESS != status) { ... }
// save this structure so you can free it later
first = entry_data_list;
while (1) {
    MMDB_entry_data_list_s *next = entry_data_list = entry_data_list->next;
    if (NULL == next) {
        break;
    }
    switch (next->entry_data.type) {
        case MMDB_DATA_TYPE_MAP: { ... }
        case MMDB_DATA_TYPE_UTF8_STRING: { ... }
        ...
    }
}
MMDB_free_entry_data_list(first);

It is your responsibility to interpret the entry_data_list structure. The list is tied together in a depth-first traversal. We will use this data as an example:

{
    "names": {
        "en": "Germany",
        "de": "Deutschland"
    },
    "cities": [ "Berlin", "Frankfurt" ]
}

The list will contain the following elements:

1.
MAP - top-level map
2.
UTF8_STRING - key "names"
3.
MAP - map for key "names"
4.
UTF8_STRING - key "en"
5.
UTF8_STRING - value for key "en"
6.
UTF8_STRING - key "de"
7.
UTF8_STRING - value for key "de"
8.
UTF8_STRING - key "cities"
9.
ARRAY - value for key "cities"
10.
UTF8_STRING - array[0]
11.
UTF8_STRING - array[1]

The return value is a status code as defined above.

MMDB_free_entry_data_list()

void MMDB_free_entry_data_list(
    MMDB_entry_data_list_s *const entry_data_list);

The MMDB_get_entry_data_list() and MMDB_get_metadata_as_entry_data_list() functions allocate the linked list structure in heap memory. Call this function to free the MMDB_entry_data_list_s structure.

MMDB_get_metadata_as_entry_data_list()

int MMDB_get_metadata_as_entry_data_list(
    MMDB_s *const mmdb,
    MMDB_entry_data_list_s **const entry_data_list);

This function allows you to retrieve the database's metadata as a linked list of MMDB_entry_data_list_s structures. This can be a more convenient way to handle metadata than using the structure directly.

    MMDB_entry_data_list_s *entry_data_list, *first;
    int status =
        MMDB_get_metadata_as_entry_data_list(&mmdb, &entry_data_list);
    if (MMDB_SUCCESS != status) { ... }
    first = entry_data_list;
    ... // do something with the data
    MMDB_free_entry_data_list(first);

The return value is a status code as defined above.

MMDB_dump_entry_data_list()

int MMDB_dump_entry_data_list(
    FILE *const stream,
    MMDB_entry_data_list_s *const entry_data_list,
    int indent);

This function takes a linked list of MMDB_entry_data_list_s structures and serializes it to the stream file. The indent parameter is the initial indentation level for the generated output. It is incremented for nested structures (maps, arrays, etc.).

The stream should be a file (e.g. stdout). If your platform provides something like GNU's open_memstream(), you can use it to capture the output as a string.

The output is formatted similarly to JSON, but the values are marked with their data type (except for maps and arrays which are displayed as "{}" and "[]").

The specific format of the output may change in future versions.

MMDB_read_node()

SINÓPSIS

int MMDB_read_node(
    MMDB_s *const mmdb,
    uint32_t node_number,
    MMDB_search_node_s *const node);

DESCRIPCIÓN

Esta función lee un nodo específico en el árbol de búsqueda. El tercer argumento es una referencia a una estructura MMDB_search_node_s que será poblada por esta función.

ESTRUCTURAS DE DATOS

El valor de retorno de la función es un código de estado según se define arriba.

CÓDIGOS DE ESTADO

La función retorna un código de estado. Si se le pasa un node_number mayor que el número de nodos en la base de datos, esta función retornará MMDB_INVALID_NODE_NUMBER_ERROR, en caso contrario, retornará MMDB_SUCCESS.

FUNCIONES

El primer nodo en el árbol de búsqueda es siempre el nodo 0. Si deseas iterar sobre todo el árbol de búsqueda, debes leer el nodo 0 y luego seguir los registros que componen este nodo, según el tipo de cada registro. Si el tipo es MMDB_RECORD_TYPE_SEARCH_NODE, el registro contiene un entero para el siguiente nodo a buscar.

EJEMPLO

#include <errno.h>
#include <maxminddb.h>
#include <stdlib.h>
#include <string.h>
int main(int argc, char **argv)
{
    char *filename = argv[1];
    char *ip_address = argv[2];
    MMDB_s mmdb;
    int status = MMDB_open(filename, MMDB_MODE_MMAP, &mmdb);
    if (MMDB_SUCCESS != status) {
        fprintf(stderr, "\n  Can't open %s - %s\n",
                filename, MMDB_strerror(status));
        if (MMDB_IO_ERROR == status) {
            fprintf(stderr, "    IO error: %s\n", strerror(errno));
        }
        exit(1);
    }
    int gai_error, mmdb_error;
    MMDB_lookup_result_s result =
        MMDB_lookup_string(&mmdb, ip_address, &gai_error, &mmdb_error);
    if (0 != gai_error) {
        fprintf(stderr,
                "\n  Error from getaddrinfo for %s - %s\n\n",
                ip_address, gai_strerror(gai_error));
        exit(2);
    }
    if (MMDB_SUCCESS != mmdb_error) {
        fprintf(stderr,
                "\n  Got an error from libmaxminddb: %s\n\n",
                MMDB_strerror(mmdb_error));
        exit(3);
    }
    MMDB_entry_data_list_s *entry_data_list = NULL;
    int exit_code = 0;
    if (result.found_entry) {
        int status = MMDB_get_entry_data_list(&result.entry,
                                              &entry_data_list);
        if (MMDB_SUCCESS != status) {
            fprintf(
                stderr,
                "Got an error looking up the entry data - %s\n",
                MMDB_strerror(status));
            exit_code = 4;
            goto end;
        }
        if (NULL != entry_data_list) {
            MMDB_dump_entry_data_list(stdout, entry_data_list, 2);
        }
    } else {
        fprintf(
            stderr,
            "\n  No entry for this IP address (%s) was found\n\n",
            ip_address);
        exit_code = 5;
    }
    end:
        MMDB_free_entry_data_list(entry_data_list);
        MMDB_close(&mmdb);
        exit(exit_code);
}
