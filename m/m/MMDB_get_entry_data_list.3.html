DESCRIPCIÓN

La biblioteca libmaxminddb proporciona funciones para trabajar con archivos MaxMind DB. Consulte https://maxmind.github.io/MaxMind-DB/ para la especificación del formato de MaxMind DB. Las bases de datos y los resultados se representan mediante estructuras diferentes. Las bases de datos se abren llamando a MMDB_open(). Puede consultar direcciones IP como strings con MMDB_lookup_string() o como punteros a estructuras sockaddr con MMDB_lookup_sockaddr().

Si la consulta encuentra la dirección IP en la base de datos, devuelve una estructura MMDB_lookup_result_s. Si esta estructura indica que la base de datos tiene datos para la dirección IP, hay varias funciones que pueden usarse para obtener ese dato. Estas incluyen MMDB_get_value() y MMDB_get_entry_data_list(). Consulte la documentación de las funciones para más detalles.

Al terminar con el handle de base de datos, debe llamar a MMDB_close().

Todas las funciones, estructuras y macros públicas comienzan con "MMDB_".

ESTRUCTURAS DE DATOS

Todas las estructuras exportadas por el encabezado maxminddb.h de esta biblioteca se definen como typedef struct foo_s { ... } foo_s, por lo que puede referirse a ellas sin el prefijo struct.

Esta biblioteca proporciona las siguientes estructuras:

MMDB_s

Esta es la referencia del handle de un archivo MaxMind DB. Solo documentamos algunos de los campos de esta estructura destinados a uso público. Todos los demás campos están sujetos a cambios y son destinados únicamente a uso interno.

typedef struct MMDB_s {
    uint32_t flags;
    const char *filename;
    ...
    MMDB_metadata_s metadata;
} MMDB_s;
  • uint32_t flags - los flags con los que se abrió esta base de datos. Consulte la documentación de MMDB_open() para más detalles.
  • const char *filename - el nombre del archivo que se abrió, como se pasó a MMDB_open().
  • MMDB_metadata_s metadata - los metadatos de la base de datos.

MMDB_metadata_s y MMDB_description_s

Esta estructura se puede obtener de la estructura MMDB_s. Contiene los metadatos leídos de un archivo de base de datos. Debe ser más conveniente acceder a estos metadatos llamando a MMDB_get_metadata_as_entry_data_list().

typedef struct MMDB_metadata_s {
    uint32_t node_count;
    uint16_t record_size;
    uint16_t ip_version;
    const char *database_type;
    struct {
        size_t count;
        const char **names;
    } languages;
    uint16_t binary_format_major_version;
    uint16_t binary_format_minor_version;
    uint64_t build_epoch;
    struct {
        size_t count;
        MMDB_description_s **descriptions;
    } description;
} MMDB_metadata_s;
typedef struct MMDB_description_s {
    const char *language;
    const char *description;
} MMDB_description_s;

Estas estructuras deberían ser principalmente autoexplicativas.

El miembro ip_version debe siempre ser 4 o 6. El miembro binary_format_major_version debe siempre ser 2.

No hay requisito que los metadatos de la base de datos incluyan idiomas o descripciones, por lo que los miembros count para estos aspectos de los metadatos pueden ser cero. Todos los demás miembros de MMDB_metadata_s deben estar poblados.

MMDB_lookup_result_s

Esta estructura se devuelve como resultado de la consulta de una dirección IP.

typedef struct MMDB_lookup_result_s {
    bool found_entry;
    MMDB_entry_s entry;
    uint16_t netmask;
} MMDB_lookup_result_s;

Si el miembro found_entry es falso, los demás miembros de esta estructura no contienen valores significativos. Debe verificar primero que found_entry sea verdadero.

El miembro entry se usa para buscar el dato asociado a la dirección IP.

El miembro netmask indica qué subred pertenece la dirección IP en esta base de datos. Por ejemplo, si consulta la dirección 1.1.1.1 en una base de datos IPv4 y el valor devuelto netmask es 16, entonces la dirección pertenece a la subred 1.1.0.0/16.

Si la base de datos es una base de datos IPv6, el valor devuelto netmask siempre es un largo de prefijo IPv6 (de 0 a 128), incluso si ese banco de datos también contiene redes IPv4. Si consulta una dirección IPv4 y deseas convertir el netmask en un valor de subred IPv4, puedes simplemente restar 96 del valor.

MMDB_result_s

No necesitas buscar profundamente en esta estructura. La obtendrás desde una estructura MMDB_lookup_result_s y pasarás esta a varias funciones.

MMDB_entry_data_s

Esta estructura se usa para devolver un único bloque de datos de una dirección IP. Estos bloques pueden apuntar a otros bloques, como en el caso de mapas y arrays. Algunos miembros de esta estructura no están documentados ya que son únicamente para uso interno.

typedef struct MMDB_entry_data_s {
    bool has_data;
    union {
        uint32_t pointer;
        const char *utf8_string;
        double double_value;
        const uint8_t *bytes;
        uint16_t uint16;
        uint32_t uint32;
        int32_t int32;
        uint64_t uint64;
        {mmdb_uint128_t or uint8_t[16]} uint128;
        bool boolean;
        float float_value;
    };
    ...
    uint32_t data_size;
    uint32_t type;
} MMDB_entry_data_s;

El miembro has_data es verdadero si se encontró datos para una consulta específica. Consulte MMDB_get_value() para más detalles. Si este miembro es falso, ninguno de los valores restantes en la estructura es significativo.

La unión al principio de la estructura define los datos reales. Para determinar qué unión se está utilizando, puede consultar el valor de type.

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

el miembro data_size solo es relevante para datos utf8_string y bytes. utf8_string no tiene terminación nula y se data_size debe usar para determinar su longitud.

El miembro type se puede comparar con uno de los macros MMDB_DATA_TYPE_*.

Enteros de 128 bits

El manejo de datos uint128 depende de cómo tu plataforma soporte enteros de 128 bits, si es que lo hace. Con GCC 4.4 y 4.5 podemos escribir unsigned int __attribute__ ((__mode__ (TI))). Con versiones más nuevas de GCC (4.6+) y clang (3.2+) podemos simplemente escribir "unsigned __int128".

Para solucionar estas diferencias, esta biblioteca define un tipo mmdb_uint128_t. Este tipo está definido en el encabezado maxminddb.h para que puedas usarlo en tu propio código.

Con compiladores más antiguos, no podemos usar un entero, así que en su lugar usamos un array de 16 bytes de valores uint8_t. Estos son los datos brutos de la base de datos.

Esta biblioteca proporciona un macro público MMDB_UINT128_IS_BYTE_ARRAY. Si este es verdadero (1), entonces los valores uint128 se devuelven como un array de bytes, si es falso, se devuelven como un entero mmdb_uint128_t.

Macros de tipo de dato

Esta biblioteca proporciona un macro para cada tipo de dato definido por la especificación de MaxMind DB.

  • MMDB_DATA_TYPE_UTF8_STRING
  • MMDB_DATA_TYPE_DOUBLE
  • MMDB_DATA_TYPE_BYTES
  • MMDB_DATA_TYPE_UINT16
  • MMDB_DATA_TYPE_UINT32
  • MMDB_DATA_TYPE_MAP
  • MMDB_DATA_TYPE_INT32
  • MMDB_DATA_TYPE_UINT64
  • MMDB_DATA_TYPE_UINT128
  • MMDB_DATA_TYPE_ARRAY
  • MMDB_DATA_TYPE_BOOLEAN
  • MMDB_DATA_TYPE_FLOAT

También hay algunos tipos que son solo para uso interno:

  • MMDB_DATA_TYPE_EXTENDED
  • MMDB_DATA_TYPE_POINTER
  • MMDB_DATA_TYPE_CONTAINER
  • MMDB_DATA_TYPE_END_MARKER

Si ves uno de estos en los datos devueltos, algo ha ido muy mal. La base de datos está dañada o fue generada incorrectamente, o hay un error en el código de libmaxminddb.

Valores de puntero y MMDB_close()

Los miembros utf8_string, bytes, y (quizás) uint128 de esta estructura son todos punteros directos a la sección de datos de la base de datos. Este puede ser un bloque de memoria asignado con calloc o con mmap. En cualquier caso, estos punteros se invalidarán después de llamar a MMDB_close().

Si necesitas referenciar estos datos después de ese momento, deberías copiar los datos con una función apropiada (strdup, memcpy, etc.).

MMDB_entry_data_list_s

Esta estructura encapsula una lista enlazada de estructuras MMDB_entry_data_s.

typedef struct MMDB_entry_data_list_s {
    MMDB_entry_data_s entry_data;
    struct MMDB_entry_data_list_s *next;
} MMDB_entry_data_list_s;

Esta estructura te permite ver datos completos de mapas o arrays iterando sobre la lista enlazada.

MMDB_search_node_s

Esta estructura encapsula los dos registros en un nodo de búsqueda. Esto solo es realmente útil si quieres escribir código que itere sobre todo el árbol de búsqueda en lugar de buscar una dirección IP específica.

typedef struct MMDB_search_node_s {
    uint64_t left_record;
    uint64_t right_record;
    uint8_t left_record_type;
    uint8_t right_record_type;
    MMDB_entry_s left_record_entry;
    MMDB_entry_s right_record_entry;
} MMDB_search_node_s;

Los dos tipos de registro tomarán uno de los siguientes valores:

  • MMDB_RECORD_TYPE_SEARCH_NODE - El registro apunta al siguiente nodo de búsqueda.
  • MMDB_RECORD_TYPE_EMPTY - El registro es un marcador de posición que indica que no hay datos para la dirección IP. La búsqueda debería terminar aquí.
  • MMDB_RECORD_TYPE_DATA - El registro es para datos en la sección de datos de la base de datos. Usa la entrada para el registro al buscar los datos del registro.
  • MMDB_RECORD_TYPE_INVALID - El registro es inválido. Se buscó un nodo inválido o la base de datos está corrupta.

La MMDB_entry_s para el registro solo es válida si el tipo es MMDB_RECORD_TYPE_DATA. Intentar usar una entrada para otros tipos de registro resultará en un error o datos inválidos.

Códigos de estado

Esta biblioteca devuelve (o rellena) códigos de estado para muchas funciones. Estos códigos de estado son:

  • MMDB_SUCCESS - todo funcionó
  • MMDB_FILE_OPEN_ERROR - hubo un error al intentar abrir el archivo MaxMind DB.
  • MMDB_IO_ERROR - una operación de E/S falló. Consulta errno para más detalles.
  • MMDB_CORRUPT_SEARCH_TREE_ERROR - buscar una dirección IP en el árbol de búsqueda nos dio un resultado imposible. La base de datos está dañada o fue generada incorrectamente, o hay un error en el código de libmaxminddb.
  • MMDB_INVALID_METADATA_ERROR - algo en la base de datos está mal. Esto incluye claves de metadatos faltantes, así como valores imposibles (como una ip_version de 7).
  • MMDB_UNKNOWN_DATABASE_FORMAT_ERROR - Los metadatos de la base de datos indican que su versión principal no es 2. Esta biblioteca solo puede manejar la versión principal 2.
  • MMDB_OUT_OF_MEMORY_ERROR - falló una llamada de asignación de memoria (malloc, etc.).
  • MMDB_INVALID_DATA_ERROR - una entrada en la sección de datos contiene datos inválidos. Por ejemplo, un campo uint16 dice tener más de 2 bytes de longitud. La base de datos probablemente está dañada o fue generada incorrectamente.
  • MMDB_INVALID_LOOKUP_PATH_ERROR - La ruta de búsqueda pasada a MMDB_get_value, MMDB_vget_value, o MMDB_aget_value contiene un índice de array que es mayor que LONGMAX o menor que LONGMIN.
  • MMDB_LOOKUP_PATH_DOES_NOT_MATCH_DATA_ERROR - La ruta de búsqueda pasada a MMDB_get_value,MMDB_vget_value, o MMDB_aget_value no coincide con la estructura de datos de la entrada. Hay varias razones por las que esto puede suceder. La ruta de búsqueda podría incluir una clave que no está en un mapa. La ruta de búsqueda podría incluir un índice de array mayor que un array o menor que el desplazamiento mínimo desde el final de un array. También puede suceder cuando la ruta espera encontrar un mapa o array donde no existen.

Todos los códigos de estado deben tratarse como valores int.

MMDB_strerror()

const char *MMDB_strerror(int error_code)

Esta función toma un código de estado y devuelve una cadena en inglés que explica el estado.

Funciones

Esta biblioteca proporciona las siguientes funciones exportadas:

MMDB_open()

int MMDB_open(
    const char *const filename,
    uint32_t flags,
    MMDB_s *const mmdb);

Esta función abre un manejador para un archivo MaxMind DB. Su valor de retorno es un código de estado como se define arriba. Siempre verifica el valor de retorno de esta llamada.

MMDB_s mmdb;
int status =
    MMDB_open("/ruta/al/archivo.mmdb", MMDB_MODE_MMAP, &mmdb);
if (MMDB_SUCCESS != status) { ... }
...
MMDB_close(&mmdb);

filename debe estar codificado como UTF-8 en Windows.

La estructura MMDB_s que pasas puede estar en la pila o asignada desde el heap. Sin embargo, si la apertura es exitosa, contendrá datos asignados del heap, por lo que necesitas cerrarla con MMDB_close(). Si el estado devuelto no es MMDB_SUCCESS, esta biblioteca se asegura de que toda la memoria asignada se libere antes de devolver.

Las banderas actualmente proporcionadas son:

•
MMDB_MODE_MMAP - abre la base de datos con mmap().

Pasar otros valores para flags puede producir resultados impredecibles. En el futuro, podemos agregar banderas adicionales que puedes combinar bit a bit con el modo, así como modos adicionales.

También puedes pasar 0 como valor de flags, en cuyo caso la base de datos se abrirá con las banderas predeterminadas. Sin embargo, estos predeterminados pueden cambiar en futuras versiones. El predeterminado actual es MMDB_MODE_MMAP.

MMDB_close()

void MMDB_close(MMDB_s *const mmdb);

Esto libera cualquier memoria asignada o mapeada (mmap'd) que sea mantenida por la estructura MMDB_s. *No libera la memoria

MMDB_open()

MMDB_s *MMDB_open(const char *filename, int flags, int *error);

Abre un archivo de base de datos MaxMind DB. El nombre de archivo debe ser una ruta completa o relativa al archivo de base de datos MMDB. Las marcas son un OR bit a bit de las siguientes:

MMDB_MODE_MMAP
Mapea el archivo en memoria (modo predeterminado). Es la forma más rápida para acceder a los datos.
MMDB_MODE_FILE
Lee el archivo en memoria. Útil si no puedes usar mmap.
MMDB_MODE_CACHE
Lee el archivo en memoria y lo guarda en caché. Más lento que MMDB_MODE_MMAP, pero más rápido que MMDB_MODE_FILE para accesos repetidos, ya que los datos se mantienen en la caché de la biblioteca.

MMDB_close()

void MMDB_close(MMDB_s *mmdb);

Cierra un archivo de base de datos MaxMind DB abierto previamente con MMDB_open(). Si la estructura MMDB_s fue asignada desde el heap, eres responsable de liberarla.

MMDB_lookup_string()

MMDB_lookup_result_s MMDB_lookup_string(
    MMDB_s *const mmdb,
    const char *const ipstr,
    int *const gai_error,
    int *const mmdb_error);

Busca una dirección IP pasada como una cadena terminada en nulo. Internamente, llama a getaddrinfo() para resolver la dirección en formato binario. Luego, llama a MMDB_lookup_sockaddr() para buscar la dirección en la base de datos. Si ya has resuelto una dirección, puedes llamar a MMDB_lookup_sockaddr() directamente, en lugar de resolverla dos veces.

int gai_error, mmdb_error;
MMDB_lookup_result_s result =
    MMDB_lookup_string(&mmdb, "1.2.3.4", &gai_error, &mmdb_error);
if (0 != gai_error) { ... }
if (MMDB_SUCCESS != mmdb_error) { ... }
if (result.found_entry) { ... }

Esta función siempre devuelve una estructura MMDB_lookup_result_s, pero también debes comprobar los parámetros gai_error y mmdb_error. Si alguno indica un error, la estructura devuelta será inútil.

Si no hay error, aún debes asegurarte de que el miembro found_entry en la estructura devuelta sea verdadero. Si no lo es, esto significa que la dirección IP no tiene un registro en la base de datos.

Esta función funciona con direcciones IPv4 incluso cuando la base de datos contiene datos para IPv4 e IPv6. La dirección IPv4 se buscará como '::xxx.xxx.xxx.xxx' en lugar de ser mapeada al prefijo ::ffff:xxx.xxx.xxx.xxx reservado para direcciones IPv6 mapeadas a IPv4.

Si pasas una dirección IPv6 a una base de datos que solo contiene datos IPv4, el miembro found_entry será falso, pero el estado mmdb_error seguirá siendo MMDB_SUCCESS.

MMDB_lookup_sockaddr()

MMDB_lookup_result_s MMDB_lookup_sockaddr(
    MMDB_s *const mmdb,
    const struct sockaddr *const sockaddr,
    int *const mmdb_error);

Busca una dirección IP que ya ha sido resuelta con getaddrinfo().

A menos que no llames a getaddrinfo() por sí sola, esta función es idéntica a la función MMDB_lookup_string().

int mmdb_error;
MMDB_lookup_result_s result =
    MMDB_lookup_sockaddr(&mmdb, address->ai_addr, &mmdb_error);
if (MMDB_SUCCESS != mmdb_error) { ... }
if (result.found_entry) { ... }

Funciones de Búsqueda de Datos

Hay tres funciones para buscar datos asociados a una dirección IP.

int MMDB_get_value(
    MMDB_entry_s *const start,
    MMDB_entry_data_s *const entry_data,
    ...);
int MMDB_vget_value(
    MMDB_entry_s *const start,
    MMDB_entry_data_s *const entry_data,
    va_list va_path);
int MMDB_aget_value(
    MMDB_entry_s *const start,
    MMDB_entry_data_s *const entry_data,
    const char *const *const path);

Las tres funciones permiten tres estilos de llamada ligeramente diferentes, pero todas realizan la misma tarea.

El primer parámetro es un valor MMDB_entry_s. En la mayoría de los casos, esto provendrá del valor MMDB_lookup_result_s devuelto por MMDB_lookup_string() o MMDB_lookup_sockaddr().

El segundo parámetro es una referencia a una estructura MMDB_entry_data_s. Esta se llenará con los datos que se están buscando, si los hay. Si no se encuentra nada, el miembro has_data de esta estructura será falso. Si has_data es verdadero, puedes ver el miembro data_type.

El último parámetro es una ruta de búsqueda. La ruta consta de un conjunto de cadenas que representan claves de mapa (por ejemplo, "city") o índices de array (por ejemplo, "0", "1", "-1") para usar en la búsqueda.

Los índices negativos en el array se tratarán como un desplazamiento desde el final del array. Por ejemplo, "-1" se refiere al último elemento del array.

La ruta de búsqueda permite navegar en una estructura compleja. Por ejemplo, dados estos datos:

{
    "names": {
        "en": "Germany",
        "de": "Deutschland"
    },
    "cities": [ "Berlin", "Frankfurt" ]
}

Podemos buscar el nombre en inglés con este código:

MMDB_lookup_result_s result =
    MMDB_lookup_sockaddr(&mmdb, address->ai_addr, &mmdb_error);
MMDB_entry_data_s entry_data;
int status =
    MMDB_get_value(&result.entry, &entry_data,
                   "names", "en", NULL);
if (MMDB_SUCCESS != status) { ... }
if (entry_data.has_data) { ... }

Si queremos encontrar la primera ciudad, la ruta de búsqueda sería "cities", "0". Si no proporcionas una ruta de búsqueda, obtendrás el registro que corresponde al mapa de nivel superior. La ruta de búsqueda debe terminar siempre con NULL, independientemente de la función que uses.

La función MMDB_get_value acepta un número variable de argumentos. Todos los argumentos después de MMDB_entry_data_s * son la ruta de búsqueda. El último argumento debe ser NULL.

La función MMDB_vget_value acepta un va_list como ruta de búsqueda. El último elemento recuperado con va_arg() debe ser NULL.

Finalmente, la función MMDB_aget_value acepta un array de cadenas como ruta de búsqueda. El último elemento de este array debe ser NULL.

Si deseas obtener todos los datos de la entrada a la vez, puedes llamar a MMDB_get_entry_data_list().

Para cada una de las tres funciones, el valor devuelto es un código de estado según se describe.

MMDB_get_entry_data_list()

int MMDB_get_entry_data_list(
    MMDB_entry_s *start,
    MMDB_entry_data_list_s **const entry_data_list);

Esta función te permite obtener todos los datos de una estructura compleja de una sola vez, en lugar de buscar cada pieza con llamadas repetidas a MMDB_get_value().

MMDB_lookup_result_s result =
    MMDB_lookup_sockaddr(&mmdb, address->ai_addr, &mmdb_error);
MMDB_entry_data_list_s *entry_data_list, *first;
int status =
    MMDB_get_entry_data_list(&result.entry, &entry_data_list);
if (MMDB_SUCCESS != status) { ... }
// guarda esto para poder liberar estos datos más tarde
first = entry_data_list;
while (1) {
    MMDB_entry_data_list_s *next = entry_data_list = entry_data_list->next;
    if (NULL == next) {
        break;
    }
    switch (next->entry_data.type) {
        case MMDB_DATA_TYPE_MAP: { ... }
        case MMDB_DATA_TYPE_UTF8_STRING: { ... }
        ...
    }
}
MMDB_free_entry_data_list(first);

Es tu responsabilidad interpretar la estructura entry_data_list. La lista está enlazada en un recorrido profundo. Usaremos esta estructura como ejemplo:

{
    "names": {
        "en": "Germany",
        "de": "Deutschland"
    },
    "cities": [ "Berlin", "Frankfurt" ]
}

La lista contendrá los siguientes elementos:

1.
MAP - mapa de nivel superior
2.
UTF8_STRING - clave "names"
3.
MAP - mapa de "names"
4.
UTF8_STRING - clave "en"
5.
UTF8_STRING - valor de "en"
6.
UTF8_STRING - clave "de"
7.
UTF8_STRING - valor de "de"
8.
UTF8_STRING - clave "cities"
9.
ARRAY - valor de "cities"
10.
UTF8_STRING - array[0]
11.
UTF8_STRING - array[1]

El valor devuelto de la función es un código de estado como se define anteriormente.

MMDB_free_entry_data_list()

void MMDB_free_entry_data_list(
    MMDB_entry_data_list_s *const entry_data_list);

Las funciones MMDB_get_entry_data_list() y MMDB_get_metadata_as_entry_data_list() alojan la estructura de lista enlazada en el heap. Llama a esta función para liberar la estructura MMDB_entry_data_list_s.

MMDB_get_metadata_as_entry_data_list()

int MMDB_get_metadata_as_entry_data_list(
    MMDB_s *const mmdb,
    MMDB_entry_data_list_s **const entry_data_list);

Esta función permite recuperar la metadatos de la base de datos como una lista enlazada de estructuras MMDB_entry_data_list_s. Esta puede ser una forma más conveniente de manejar las metadatos que usar la estructura de metadatos directamente.

    MMDB_entry_data_list_s *entry_data_list, *first;
    int status =
        MMDB_get_metadata_as_entry_data_list(&mmdb, &entry_data_list);
    if (MMDB_SUCCESS != status) { ... }
    first = entry_data_list;
    ... // hacer algo con los datos
    MMDB_free_entry_data_list(first);

El valor devuelto de la función es un código de estado como se define anteriormente.

MMDB_dump_entry_data_list()

int MMDB_dump_entry_data_list(
    FILE *const stream,
    MMDB_entry_data_list_s *const entry_data_list,
    int indent);

Esta función toma una lista enlazada de estructuras MMDB_entry_data_list_s y la serializa en el flujo dado stream. El parámetro indent es el nivel de indentación inicial para la salida generada. Se incrementa para estructuras anidadas (mapas, arrays, etc.).

El stream debe ser un manejador de archivo (stdout, etc.). Si tu plataforma proporciona algo como open_memstream() (GNU), puedes usarlo para capturar la salida como una cadena.

La salida está formateada de forma similar a JSON, pero los valores están marcados con su tipo de datos (a menos que los mapas y los arrays se muestren como "{}" y "[]" respectivamente).

El formato específico de la salida puede cambiar.
