DESCRIPCIÓN

La biblioteca libmaxminddb proporciona funciones para trabajar con archivos MaxMind DB. Ver https://maxmind.github.io/MaxMind-DB/ para la especificación del formato MaxMind DB. La base de datos y los resultados se representan mediante diferentes estructuras de datos. Las bases de datos se abren llamando a MMDB_open(). Puede buscar direcciones IP como una cadena con MMDB_lookup_string() o como un puntero a una estructura sockaddr con MMDB_lookup_sockaddr().

Si la búsqueda encuentra la dirección IP en la base de datos, devuelve una estructura MMDB_lookup_result_s. Si esa estructura indica que la base de datos tiene datos para la IP, hay una serie de funciones que se pueden utilizar para obtener esos datos. Estas incluyen MMDB_get_value() y MMDB_get_entry_data_list(). Consulte la documentación de la función a continuación para obtener más detalles.

Cuando haya terminado con el manejador de la base de datos, debe llamar a MMDB_close().

Todas las funciones, estructuras y macros visibles públicamente comienzan con "MMDB_".

ESTRUCTURAS DE DATOS

Todas las estructuras de datos exportadas por el encabezado maxminddb.h de esta biblioteca están definidas mediante typedef con el formato typedef struct foo_s { ... } foo_s para que pueda referirse a ellas sin el prefijo struct.

Esta biblioteca proporciona las siguientes estructuras de datos:

MMDB_s

Este es el manejador para un archivo MaxMind DB. Solo documentamos algunos de los campos de esta estructura destinados a uso público. Todos los demás campos están sujetos a cambios y solo están destinados a uso interno.

typedef struct MMDB_s {
    uint32_t flags;
    const char *filename;
    ...
    MMDB_metadata_s metadata;
} MMDB_s;
  • uint32_t flags - las banderas con las que se abrió esta base de datos. Consulte la documentación de MMDB_open() para obtener más detalles.
  • const char *filename - el nombre del archivo que se abrió, tal como se pasó a MMDB_open().
  • MMDB_metadata_s metadata - los metadatos de la base de datos.

MMDB_metadata_s y MMDB_description_s

Esta estructura se puede recuperar de la estructura MMDB_s. Contiene los metadatos leídos del archivo de base de datos. Tenga en cuenta que puede encontrar más conveniente acceder a estos metadatos llamando a MMDB_get_metadata_as_entry_data_list() en su lugar.

typedef struct MMDB_metadata_s {
    uint32_t node_count;
    uint16_t record_size;
    uint16_t ip_version;
    const char *database_type;
    struct {
        size_t count;
        const char **names;
    } languages;
    uint16_t binary_format_major_version;
    uint16_t binary_format_minor_version;
    uint64_t build_epoch;
    struct {
        size_t count;
        MMDB_description_s **descriptions;
    } description;
} MMDB_metadata_s;
typedef struct MMDB_description_s {
    const char *language;
    const char *description;
} MMDB_description_s;

Estas estructuras deberían ser en su mayoría autoexplicativas.

El miembro ip_version siempre debe ser 4 o 6. El miembro binary_format_major_version siempre debe ser 2.

No hay requisito de que los metadatos de la base de datos incluyan idiomas o descripciones, por lo que el count para estas partes de los metadatos puede ser cero. Todos los demás campos de MMDB_metadata_s deben estar poblados.

MMDB_lookup_result_s

Esta estructura se devuelve como resultado de buscar una dirección IP.

typedef struct MMDB_lookup_result_s {
    bool found_entry;
    MMDB_entry_s entry;
    uint16_t netmask;
} MMDB_lookup_result_s;

Si el miembro found_entry es falso, entonces los otros miembros de esta estructura no contienen valores significativos. Siempre compruebe primero que found_entry sea verdadero.

El miembro entry se utiliza para buscar los datos asociados con la dirección IP.

El miembro netmask le indica a qué subred pertenece la dirección IP en esta base de datos. Por ejemplo, si busca la dirección 1.1.1.1 en una base de datos IPv4 y la máscara de red devuelta es 16, entonces la dirección es parte de la subred 1.1.0.0/16.

Si la base de datos es una base de datos IPv6, la máscara de red devuelta es siempre una longitud de prefijo IPv6 (de 0 a 128), incluso si esa base de datos también contiene redes IPv4. Si busca una dirección IPv4 y desea convertir la máscara de red en un valor de máscara de red IPv4, simplemente puede restar 96 del valor.

MMDB_result_s

Realmente no necesitas indagar en esta estructura. La obtendrás de una estructura MMDB_lookup_result_s y la pasarás a varias funciones.

MMDB_entry_data_s

Esta estructura se utiliza para devolver una única entrada de sección de datos para una IP. Estas entradas, a su vez, pueden apuntar a otras entradas, como es el caso de cosas como mapas y arreglos. Algunos miembros de esta estructura no están documentados ya que son solo para uso interno.

typedef struct MMDB_entry_data_s {
    bool has_data;
    union {
        uint32_t pointer;
        const char *utf8_string;
        double double_value;
        const uint8_t *bytes;
        uint16_t uint16;
        uint32_t uint32;
        int32_t int32;
        uint64_t uint64;
        {mmdb_uint128_t or uint8_t[16]} uint128;
        bool boolean;
        float float_value;
    };
    ...
    uint32_t data_size;
    uint32_t type;
} MMDB_entry_data_s;

El miembro has_data es verdadero si se encontraron datos para una búsqueda dada. Consulte MMDB_get_value() para obtener más detalles. Si este miembro es falso, entonces ninguno de los otros valores en la estructura es significativo.

La unión al principio de la estructura define los datos reales. Para determinar qué miembro de la unión

se ha poblado, debe examinar el miembro type. El miembro pointer de la unión nunca debe poblarse en ningún dato devuelto por la API. Los punteros siempre deben resolverse internamente.

El miembro data_size solo es relevante para los datos utf8_string y bytes. utf8_string no tiene terminación nula y data_size *debe* usarse para determinar su longitud.

El miembro type se puede comparar con una de las macros MMDB_DATA_TYPE_*.

Enteros de 128 bits

El manejo de datos uint128 depende de cómo su plataforma admita enteros de 128 bits, si es que lo hace. Con GCC 4.4 y 4.5 podemos escribir unsigned int __attribute__ ((__mode__ (TI))). Con versiones más recientes de GCC (4.6+) y clang (3.2+) podemos simplemente escribir "unsigned __int128".

Para solucionar estas diferencias, esta biblioteca define un tipo mmdb_uint128_t. Este tipo se define en el encabezado maxminddb.h para que pueda usarlo en su propio código.

Con compiladores más antiguos, no podemos usar un entero, por lo que en su lugar usamos una matriz de 16 bytes de valores uint8_t. Estos son los datos brutos de la base de datos.

Esta biblioteca proporciona una macro pública MMDB_UINT128_IS_BYTE_ARRAY. Si esta es verdadera (1), entonces los valores uint128 se devuelven como una matriz de bytes; si es falsa, se devuelven como un entero mmdb_uint128_t.

Macros de tipo de datos

Esta biblioteca proporciona una macro para cada tipo de datos definido por la especificación MaxMind DB.

  • MMDB_DATA_TYPE_UTF8_STRING
  • MMDB_DATA_TYPE_DOUBLE
  • MMDB_DATA_TYPE_BYTES
  • MMDB_DATA_TYPE_UINT16
  • MMDB_DATA_TYPE_UINT32
  • MMDB_DATA_TYPE_MAP
  • MMDB_DATA_TYPE_INT32
  • MMDB_DATA_TYPE_UINT64
  • MMDB_DATA_TYPE_UINT128
  • MMDB_DATA_TYPE_ARRAY
  • MMDB_DATA_TYPE_BOOLEAN
  • MMDB_DATA_TYPE_FLOAT

También hay algunos tipos que son solo para uso interno:

  • MMDB_DATA_TYPE_EXTENDED
  • MMDB_DATA_TYPE_POINTER
  • MMDB_DATA_TYPE_CONTAINER
  • MMDB_DATA_TYPE_END_MARKER

Si ve alguno de estos en los datos devueltos, algo ha ido muy mal. La base de datos está dañada o se generó incorrectamente, o hay un error en el código de libmaxminddb.

Valores de puntero y MMDB_close()

Los miembros utf8_string, bytes y (quizás) uint128 de esta estructura son punteros directos a la sección de datos de la base de datos. Este puede ser un bloque de memoria asignado con calloc o mmap. En cualquier caso, estos punteros dejarán de ser válidos después de llamar a MMDB_close().

Si necesita hacer referencia a estos datos después de ese momento, debe copiar los datos con una función apropiada (strdup, memcpy, etc.).

MMDB_entry_data_list_s

Esta estructura encapsula una lista enlazada de estructuras MMDB_entry_data_s.

typedef struct MMDB_entry_data_list_s {
    MMDB_entry_data_s entry_data;
    struct MMDB_entry_data_list_s *next;
} MMDB_entry_data_list_s;

Esta estructura le permite ver datos de mapa o matriz completos iterando sobre la lista enlazada.

MMDB_search_node_s

Esta estructura encapsula los dos registros en un nodo de búsqueda. Esto es realmente útil solo si desea escribir código que itere sobre todo el árbol de búsqueda en lugar de buscar una dirección IP específica.

typedef struct MMDB_search_node_s {
    uint64_t left_record;
    uint64_t right_record;
    uint8_t left_record_type;
    uint8_t right_record_type;
    MMDB_entry_s left_record_entry;
    MMDB_entry_s right_record_entry;
} MMDB_search_node_s;

Los dos tipos de registro tomarán uno de los siguientes valores:

  • MMDB_RECORD_TYPE_SEARCH_NODE - El registro apunta al siguiente nodo de búsqueda.
  • MMDB_RECORD_TYPE_EMPTY - El registro es un marcador de posición que indica que no hay datos para la dirección IP. La búsqueda debería terminar aquí.
  • MMDB_RECORD_TYPE_DATA - El registro es para datos en la sección de datos de la base de datos. Utilice la entrada del registro al buscar los datos del registro.
  • MMDB_RECORD_TYPE_INVALID - El registro no es válido. Se buscó un nodo no válido o la base de datos está corrupta.

La MMDB_entry_s para el registro solo es válida si el tipo es MMDB_RECORD_TYPE_DATA. Los intentos de usar una entrada para otros tipos de registro resultarán en un error o datos no válidos.

Códigos de estado

Esta biblioteca devuelve (o popula) códigos de estado para muchas funciones. Estos códigos de estado son:

  • MMDB_SUCCESS - todo funcionó
  • MMDB_FILE_OPEN_ERROR - hubo un error al intentar abrir el archivo MaxMind DB.
  • MMDB_IO_ERROR - una operación de E/S falló. Verifique errno para más detalles.
  • MMDB_CORRUPT_SEARCH_TREE_ERROR - buscar una dirección IP en el árbol de búsqueda nos dio un resultado imposible. La base de datos está dañada o se generó incorrectamente, o hay un error en el código de libmaxminddb.
  • MMDB_INVALID_METADATA_ERROR - algo en la base de datos está mal. Esto incluye claves de metadatos faltantes y valores imposibles (como una ip_version de 7).
  • MMDB_UNKNOWN_DATABASE_FORMAT_ERROR - Los metadatos de la base de datos indican que su versión principal no es 2. Esta biblioteca solo puede manejar la versión principal 2.
  • MMDB_OUT_OF_MEMORY_ERROR - una llamada de asignación de memoria (malloc, etc.) falló.
  • MMDB_INVALID_DATA_ERROR - una entrada en la sección de datos contiene datos no válidos. Por ejemplo, un campo uint16 afirma tener más de 2 bytes de longitud. La base de datos probablemente está dañada o se generó incorrectamente.
  • MMDB_INVALID_LOOKUP_PATH_ERROR - La ruta de búsqueda pasada a MMDB_get_value, MMDB_vget_value o MMDB_aget_value contiene un desplazamiento de matriz que es mayor que LONGMAX o menor que LONGMIN.
  • MMDB_LOOKUP_PATH_DOES_NOT_MATCH_DATA_ERROR - La ruta de búsqueda pasada a MMDB_get_value,MMDB_vget_value o MMDB_aget_value no coincide con la estructura de datos de la entrada. Hay varias razones por las que esto puede suceder. La ruta de búsqueda podría incluir una clave que no está en un mapa. La ruta de búsqueda podría incluir un índice de matriz mayor que una matriz o menor que el desplazamiento mínimo desde el final de una matriz. También puede suceder cuando la ruta espera encontrar un mapa o una matriz donde no existen.

Todos los códigos de estado deben tratarse como valores int.

MMDB_strerror()

const char *MMDB_strerror(int error_code)

Esta función toma un código de estado y devuelve una cadena en inglés que explica el estado.

Funciones

Esta biblioteca proporciona las siguientes funciones exportadas:

MMDB_open()

int MMDB_open(
    const char *const filename,
    uint32_t flags,
    MMDB_s *const mmdb);

Esta función abre un manejador para un archivo MaxMind DB. Su valor de retorno es un código de estado como se definió anteriormente. Siempre verifique el valor de retorno de esta llamada.

MMDB_s mmdb;
int status =
    MMDB_open("/path/to/file.mmdb", MMDB_MODE_MMAP, &mmdb);
if (MMDB_SUCCESS != status) { ... }
...
MMDB_close(&mmdb);

filename debe estar codificado como UTF-8 en Windows.

La estructura MMDB_s que pase puede estar en la pila o asignada desde el heap. Sin embargo, si la apertura es exitosa, contendrá datos asignados en el heap, por lo que necesita cerrarla con MMDB_close(). Si el estado devuelto no es MMDB_SUCCESS, esta biblioteca se asegura de que toda la memoria asignada se libere antes de devolver.

Las banderas actualmente proporcionadas son:

•
MMDB_MODE_MMAP - abrir la base de datos con mmap().

Pasar otros valores para flags puede producir resultados impredecibles. En el futuro, podemos agregar banderas adicionales que puede combinar mediante OR bit a bit con el modo, así como modos adicionales.

También puede pasar 0 como valor de flags, en cuyo caso la base de datos se abrirá con las banderas predeterminadas. Sin embargo, estos predeterminados pueden cambiar en futuras versiones. El predeterminado actual es MMDB_MODE_MMAP.

MMDB_close()

void MMDB_close(MMDB_s *const mmdb);

Esto libera cualquier memoria asignada o mapeada que se mantenga de la estructura MMDB_s. *No libera la memoria al

MMDB_lookup_string()

MMDB_lookup_result_s MMDB_lookup_string(
    MMDB_s *const mmdb,
    const char *const ipstr,
    int *const gai_error,
    int *const mmdb_error);

This function looks up an IP address passed as a null-terminated string. It internally calls getaddrinfo() to resolve the address into binary form. Then it calls MMDB_lookup_sockaddr() to look up the address in the database. If you have already resolved an address, you may call MMDB_lookup_sockaddr() directly, instead of resolving it twice.

int gai_error, mmdb_error;
MMDB_lookup_result_s result =
    MMDB_lookup_string(&mmdb, "1.2.3.4", &gai_error, &mmdb_error);
if (0 != gai_error) { ... }
if (MMDB_SUCCESS != mmdb_error) { ... }
if (result.found_entry) { ... }

This function always returns an MMDB_lookup_result_s struct, but you must check the gai_error and mmdb_error parameters as well. If either of these indicate an error, the returned struct will be useless.

If no error has occurred, you must still ensure that the found_entry member in the returned struct is true. If it is not, then this means that the IP address has no record in the database.

This function works with IPv4 addresses even if the database contains data for both IPv4 and IPv6. The IPv4 address will be looked up as ::xxx.xxx.xxx.xxx, rather than being remapped to ::ffff:xxx.xxx.xxx.xxx, which is allocated for IPv4-mapped IPv6 addresses.

If you pass an IPv6 address to a database that only has IPv4 data, the found_entry member will be false, but the mmdb_error status will still be MMDB_SUCCESS.

MMDB_lookup_sockaddr()

MMDB_lookup_result_s MMDB_lookup_sockaddr(
    MMDB_s *const mmdb,
    const struct sockaddr *const sockaddr,
    int *const mmdb_error);

This function looks up an IP address that has already been resolved using getaddrinfo().

Unless you do not call getaddrinfo() itself, this function is identical to the MMDB_lookup_string() function.

int mmdb_error;
MMDB_lookup_result_s result =
    MMDB_lookup_sockaddr(&mmdb, address->ai_addr, &mmdb_error);
if (MMDB_SUCCESS != mmdb_error) { ... }
if (result.found_entry) { ... }

Data Lookup Functions

There are three functions for looking up data associated with an IP address.

int MMDB_get_value(
    MMDB_entry_s *const start,
    MMDB_entry_data_s *const entry_data,
    ...);
int MMDB_vget_value(
    MMDB_entry_s *const start,
    MMDB_entry_data_s *const entry_data,
    va_list va_path);
int MMDB_aget_value(
    MMDB_entry_s *const start,
    MMDB_entry_data_s *const entry_data,
    const char *const *const path);

All three functions allow for three slightly different calling styles, but they all perform the same task.

The first parameter is an MMDB_entry_s value. In most cases, this value will come from the result of MMDB_lookup_string() or MMDB_lookup_sockaddr().

The second parameter is a reference to an MMDB_entry_data_s struct. This will be filled with the data being sought, if any. If there is no data, the has_data member of this struct will be false. If has_data is true, you may examine the data_type member.

The last parameter is a lookup path. This path consists of a series of strings representing map keys (e.g. "city") or array indices (e.g. "0", "1", "-1"). They are used in the lookup.

Negative indices are considered an offset from the end of the array. For example, "-1" refers to the last element of the array.

The lookup path allows for navigating complex structures. For example, given this information:

{
    "names": {
        "en": "Germany",
        "de": "Deutschland"
    },
    "cities": [ "Berlin", "Frankfurt" ]
}

You could look up the English name with this code:

MMDB_lookup_result_s result =
    MMDB_lookup_sockaddr(&mmdb, address->ai_addr, &mmdb_error);
MMDB_entry_data_s entry_data;
int status =
    MMDB_get_value(&result.entry, &entry_data,
                   "names", "en", NULL);
if (MMDB_SUCCESS != status) { ... }
if (entry_data.has_data) { ... }

If you want to find the first city, the lookup path would be "cities", "0". If you do not specify a lookup path, you will get the record corresponding to the top-level map. The lookup path must always end with NULL, regardless of which function you use.

The MMDB_get_value function takes a variable number of arguments. All arguments after the MMDB_entry_data_s * are the lookup path. The last argument must be NULL.

The MMDB_vget_value function accepts a va_list as the lookup path. The last element obtained with va_arg() must be NULL.

Finally, the MMDB_aget_value function accepts an array of strings as the lookup path. The last member of this array must be NULL.

If you wish to retrieve all data for an entry at once, you can call MMDB_get_entry_data_list().

For each of the three functions, the return value is a status code as defined above.

MMDB_get_entry_data_list()

int MMDB_get_entry_data_list(
    MMDB_entry_s *start,
    MMDB_entry_data_list_s **const entry_data_list);

This function allows you to retrieve all of the data for a complex structure in one go, rather than looking up each piece via repeated calls to MMDB_get_value().

MMDB_lookup_result_s result =
    MMDB_lookup_sockaddr(&mmdb, address->ai_addr, &mmdb_error);
MMDB_entry_data_list_s *entry_data_list, *first;
int status =
    MMDB_get_entry_data_list(&result.entry, &entry_data_list);
if (MMDB_SUCCESS != status) { ... }
// save this so you can free it later
first = entry_data_list;
while (1) {
    MMDB_entry_data_list_s *next = entry_data_list = entry_data_list->next;
    if (NULL == next) {
        break;
    }
    switch (next->entry_data.type) {
        case MMDB_DATA_TYPE_MAP: { ... }
        case MMDB_DATA_TYPE_UTF8_STRING: { ... }
        ...
    }
}
MMDB_free_entry_data_list(first);

It is your responsibility to interpret the entry_data_list structure. The list is linked in a depth-first traversal. We will use this structure as an example:

{
    "names": {
        "en": "Germany",
        "de": "Deutschland"
    },
    "cities": [ "Berlin", "Frankfurt" ]
}

The list will contain the following elements:

1.
MAP - top level map
2.
UTF8_STRING - key "names"
3.
MAP - map for key "names"
4.
UTF8_STRING - key "en"
5.
UTF8_STRING - value for key "en"
6.
UTF8_STRING - key "de"
7.
UTF8_STRING - value for key "de"
8.
UTF8_STRING - key "cities"
9.
ARRAY - value for key "cities"
10.
UTF8_STRING - array[0]
11.
UTF8_STRING - array[1]

The return value of the function is a status code as defined above.

MMDB_free_entry_data_list()

void MMDB_free_entry_data_list(
    MMDB_entry_data_list_s *const entry_data_list);

The MMDB_get_entry_data_list() and MMDB_get_metadata_as_entry_data_list() functions allocate the linked list struct from memory. Call this function to free the MMDB_entry_data_list_s struct.

MMDB_get_metadata_as_entry_data_list()

int MMDB_get_metadata_as_entry_data_list(
    MMDB_s *const mmdb,
    MMDB_entry_data_list_s **const entry_data_list);

This function allows you to retrieve the database metadata as a linked list of MMDB_entry_data_list_s structs. This can be a more convenient way to handle the metadata than using the metadata struct directly.

    MMDB_entry_data_list_s *entry_data_list, *first;
    int status =
        MMDB_get_metadata_as_entry_data_list(&mmdb, &entry_data_list);
    if (MMDB_SUCCESS != status) { ... }
    first = entry_data_list;
    ... // do something with the data
    MMDB_free_entry_data_list(first);

The return value of the function is a status code as defined above.

MMDB_dump_entry_data_list()

int MMDB_dump_entry_data_list(
    FILE *const stream,
    MMDB_entry_data_list_s *const entry_data_list,
    int indent);

This function takes a linked list of MMDB_entry_data_list_s structs and serializes it to the stream file. The indent parameter is the initial indent level for the generated output. It is incremented for nested structures (maps, arrays, etc.).

The stream must be a file (e.g. stdout). If your platform provides something like open_memstream() (on GNU), you can use that to capture the output as a string.

The output is in a JSON-like format, but the values are tagged with their data type (except for maps and arrays, which are shown as "{}" and "[]").

The specific format of the output may change in future versions.

NAME

MMDB_lib_version - Get the library version

SYNOPSIS

#include <maxminddb.h>
const char *
MMDB_lib_version(void);

DESCRIPTION

The MMDB_lib_version function returns a string containing the version of the libmaxminddb library that is currently linked against.

This can be useful for debugging purposes, especially if you need to ensure that the correct version of the library is being used.

DATA STRUCTURES

MMDB_s

typedef struct {
    MMDB_lookup_tree_s *lookup_tree;
    MMDB_metadata_s metadata;
    MMDB_mode_e mode;
    int file_descriptor;
    uint8_t *map_memory_start;
    size_t map_memory_length;
    bool uses_mmap;
} MMDB_s;

This structure holds the state for an opened MaxMind DB database. It contains the lookup tree, metadata, the mode used to open the database, and information about the memory mapping if applicable.

MMDB_lookup_result_s

typedef struct {
    bool found_entry;
    MMDB_entry_s entry;
    int16_t address_family;
} MMDB_lookup_result_s;

This structure holds the result of a lookup operation. found_entry indicates if an entry was found for the given IP address. entry contains the actual data for the found entry, and address_family specifies whether the lookup was for an IPv4 or IPv6 address.

MMDB_entry_s

typedef struct {
    uint32_t pool_address;
    uint32_t map_address;
} MMDB_entry_s;

Represents a pointer to an entry in the database's data pool.

MMDB_entry_data_s

typedef struct {
    MMDB_data_type_e type;
    size_t data_size;
    const uint8_t *data;
} MMDB_entry_data_s;

Represents a single piece of data within a database entry. It includes the data type, size, and a pointer to the data itself.

MMDB_entry_data_list_s

typedef struct MMDB_entry_data_list_s {
    MMDB_entry_data_s entry_data;
    struct MMDB_entry_data_list_s *next;
} MMDB_entry_data_list_s;

A linked list node for holding multiple MMDB_entry_data_s items, typically representing the components of a JSON-like structure found in a database entry.

MMDB_metadata_s

typedef struct {
    uint8_t database_type[MAX_DB_TYPE_LEN];
    uint32_t build_major;
    uint32_t build_minor;
    uint32_t build_user_count;
    uint64_t build_epoch;
    uint32_t segments_per_address_family;
    uint32_t node_count;
    uint32_t record_size;
} MMDB_metadata_s;

Contains metadata about the MaxMind DB database, such as its type, build information, and structure.

MMDB_search_node_s

typedef struct {
    uint32_t children_node_number;
    uint32_t siblings_node_number;
    MMDB_entry_s entry;
} MMDB_search_node_s;

Represents a node in the MaxMind DB search tree. It stores pointers to child and sibling nodes, along with the entry data for the current node.

MMDB_mode_e

typedef enum {
    MMDB_MODE_MMAP = 0,
    MMDB_MODE_FILE = 1,
    MMDB_MODE_STRICT_MMAP = 2
} MMDB_mode_e;

Enumeration defining the modes in which a MaxMind DB database can be opened. MMDB_MODE_MMAP uses memory mapping, MMDB_MODE_FILE reads the entire file into memory, and MMDB_MODE_STRICT_MMAP uses memory mapping but disables some optimizations for stricter adherence to memory mapping behavior.

MMDB_data_type_e

typedef enum {
    MMDB_DATA_TYPE_UNKNOWN = 0,
    MMDB_DATA_TYPE_BOOLEAN = 1,
    MMDB_DATA_TYPE_CARRIER = 2,
    MMDB_DATA_TYPE_CITY = 3,
    MMDB_DATA_TYPE_COUNTRY = 4,

    MMDB_DATA_TYPE_LOCATION = 7,
    MMDB_DATA_TYPE_METRO_CODE = 8,
    MMDB_DATA_TYPE_POSTAL = 9,
    MMDB_DATA_TYPE_PROTECTED_AREA = 10,
    MMDB_DATA_TYPE_REGION = 11,
    MMDB_DATA_TYPE_SUBDIVISION = 11,
    MMDB_DATA_TYPE_TIME_ZONE = 12,
    MMDB_DATA_TYPE_ISP = 13,
    MMDB_DATA_TYPE_ORGANIZATION = 14,
    MMDB_DATA_TYPE_ASNUM = 15,
    MMDB_DATA_TYPE_NETMASK = 16,
    MMDB_DATA_TYPE_IP_ADDRESS = 17,
    MMDB_DATA_TYPE_ARRAY = 18,
    MMDB_DATA_TYPE_MAP = 19,
    MMDB_DATA_TYPE_INTEGER = 20,
    MMDB_DATA_TYPE_UNSIGNED_INTEGER = 21,
    MMDB_DATA_TYPE_DOUBLE = 22,
    MMDB_DATA_TYPE_FLOAT = 23,
    MMDB_DATA_TYPE_UTF8_STRING = 24,
    MMDB_DATA_TYPE_IMPLICIT_DECIMALS = 25,

    MMDB_DATA_TYPE_JSON_STRING = 35,

} MMDB_data_type_e;

Enumeration representing the possible data types stored within a MaxMind DB database entry. This includes primitives like integers, strings, booleans, and complex types like arrays and maps, as well as JSON types.

Note: The internal structure of MMDB_s is subject to change between library releases. Do not rely on its specific fields.

STATUS CODES

The following status codes are returned by the library functions:

MMDB_SUCCESS
Operation completed successfully.
MMDB_START_ERROR
An error occurred during library initialization or startup.
MMDB_END_ERROR
An error occurred during library shutdown or cleanup.
MMDB_READ_ERROR
An error occurred while reading from the database file.
MMDB_INVALID_INTERFACE_ERROR
An invalid argument or parameter was passed to a function.
MMDB_INVALID_DATA_ERROR
The database file contains invalid or corrupted data.
MMDB_INVALID_METADATA_ERROR
The database metadata is missing or invalid.
MMDB_INDEX_ERROR
An index-related error occurred, likely due to an invalid lookup path or corrupted index data.
MMDB_INVALID_NODE_NUMBER_ERROR
A specified node number is out of the valid range for the database's search tree.
MMDB_OUT_OF_MEMORY_ERROR
The library failed to allocate sufficient memory.
MMDB_IO_ERROR
A general input/output error occurred.

FUNCTIONS

MMDB_open()

int MMDB_open(
    const char *filename,
    MMDB_mode_e mode,
    MMDB_s *const mmdb);

Opens a MaxMind DB database file specified by filename. The mode parameter determines how the database is accessed (e.g., memory-mapped or read into memory). The opened database state is stored in the mmdb structure.

Returns MMDB_SUCCESS on success, or an error code otherwise.

MMDB_close()

void MMDB_close(MMDB_s *const mmdb);

Closes an opened MaxMind DB database and frees any associated resources.

MMDB_lookup_string()

MMDB_lookup_result_s MMDB_lookup_string(
    MMDB_s *const mmdb,
    const char *ip_address,
    int *gai_error,
    int *mmdb_error);

Looks up an IP address (provided as a string) in the opened MaxMind DB database. It returns an MMDB_lookup_result_s structure containing information about the found entry or indicating that no entry was found. It also returns error codes for both the underlying getaddrinfo call (gai_error) and libmaxminddb itself (mmdb_error).

MMDB_lookup_sock()

MMDB_lookup_result_s MMDB_lookup_sock(
    MMDB_s *const mmdb,
    const struct sockaddr *sa,
    int *mmdb_error);

Similar to MMDB_lookup_string, but takes a pointer to a struct sockaddr (containing the IP address and port information) as input.

MMDB_get_entry_data_list()

int MMDB_get_entry_data_list(
    const MMDB_entry_s *const entry,
    MMDB_entry_data_list_s **entry_data_list);

Retrieves the data associated with a database entry as a linked list of MMDB_entry_data_s structures. This allows traversal of potentially complex nested data (like maps and arrays).

Returns MMDB_SUCCESS on success.

MMDB_free_entry_data_list()

void MMDB_free_entry_data_list(MMDB_entry_data_list_s *list);

Frees the memory allocated for an entry data list created by MMDB_get_entry_data_list.

MMDB_strerror()

const char * MMDB_strerror(int status);

Converts a libmaxminddb status code into a human-readable error string.

MMDB_dump_entry_data_list()

void MMDB_dump_entry_data_list(
    FILE *file,
    MMDB_entry_data_list_s *entry_data_list,
    int indent);

Prints a formatted representation of the entry data list to the specified file pointer (file). The indent parameter controls the indentation level for pretty-printing.

Note: The exact formatting of the output is considered an implementation detail and may change in future library releases, so you should not rely on the specific formatting produced by this function. It is intended to be used to show data to users in a readable way and for debugging purposes.

The return value of the function is a status code as defined above.

MMDB_read_node()

int MMDB_read_node(
    MMDB_s *const mmdb,
    uint32_t node_number,
    MMDB_search_node_s *const node);

This reads a specific node in the search tree. The third argument is a reference to an MMDB_search_node_s structure that will be populated by this function.

The return value is a status code. If you pass a node_number that is greater than the number of nodes in the database, this function will return MMDB_INVALID_NODE_NUMBER_ERROR, otherwise it will return MMDB_SUCCESS.

The first node in the search tree is always node 0. If you wanted to iterate over the whole search tree, you would start by reading node 0 and then following the the records that make up this node, based on the type of each record. If the type is MMDB_RECORD_TYPE_SEARCH_NODE then the record contains an integer for the next node to look up.

MMDB_lib_version()

const char *MMDB_lib_version(void)

This function returns the library version as a string, something like "2.0.0".

EXAMPLE

#include <errno.h>
#include <maxminddb.h>
#include <stdlib.h>
#include <string.h>
int main(int argc, char **argv)
{
    char *filename = argv[1];
    char *ip_address = argv[2];
    MMDB_s mmdb;
    int status = MMDB_open(filename, MMDB_MODE_MMAP, &mmdb);
    if (MMDB_SUCCESS != status) {
        fprintf(stderr, "\n  Can't open %s - %s\n",
                filename, MMDB_strerror(status));
        if (MMDB_IO_ERROR == status) {
            fprintf(stderr, "    IO error: %s\n", strerror(errno));
        }
        exit(1);
    }
    int gai_error, mmdb_error;
    MMDB_lookup_result_s result =
        MMDB_lookup_string(&mmdb, ip_address, &gai_error, &mmdb_error);
    if (0 != gai_error) {
        fprintf(stderr,
                "\n  Error from getaddrinfo for %s - %s\n\n",
                ip_address, gai_strerror(gai_error));
        exit(2);
    }
    if (MMDB_SUCCESS != mmdb_error) {
        fprintf(stderr,
                "\n  Got an error from libmaxminddb: %s\n\n",
                MMDB_strerror(mmdb_error));
        exit(3);
    }
    MMDB_entry_data_list_s *entry_data_list = NULL;
    int exit_code = 0;
    if (result.found_entry) {
        int status = MMDB_get_entry_data_list(&result.entry,
                                              &entry_data_list);
        if (MMDB_SUCCESS != status) {
            fprintf(
                stderr,
                "Got an error looking up the entry data - %s\n",
                MMDB_strerror(status));
            exit_code = 4;
            goto end;
        }
        if (NULL != entry_data_list) {
            MMDB_dump_entry_data_list(stdout, entry_data_list, 2);
        }
    } else {
        fprintf(
            stderr,
            "\n  No entry for this IP address (%s) was found\n\n",
            ip_address);
        exit_code = 5;
    }
    end:
        MMDB_free_entry_data_list(entry_data_list);
        MMDB_close(&mmdb);
        exit(exit_code);
}
