MPI_Get_elements_x(3)

Paquete: openmpi

Licencias: BSD-3-Clause AND LicenseRef-MPICH

MPI_Get_elements_x(3) Open MPI MPI_Get_elements_x(3)

MPI_Get_elements, MPI_Get_elements_x - Devuelve el número de elementos básicos en un tipo de dato.

SINTAXIS

Sintaxis C

#include <mpi.h>
int MPI_Get_elements(const MPI_Status *status, MPI_Datatype datatype,
    int *count)
int MPI_Get_elements_x(const MPI_Status *status, MPI_Datatype datatype,
    MPI_Count *count)

Sintaxis Fortran

USE MPI
! o el antiguo formato: INCLUDE 'mpif.h'
MPI_GET_ELEMENTS(STATUS, DATATYPE, COUNT, IERROR)
    INTEGER STATUS(MPI_STATUS_SIZE), DATATYPE, COUNT, IERROR
MPI_GET_ELEMENTS_X(STATUS, DATATYPE, COUNT, IERROR)
    INTEGER STATUS(MPI_STATUS_SIZE), DATATYPE
        INTEGER(KIND=MPI_COUNT_KIND) COUNT
        INTEGER IERROR

Sintaxis Fortran 2008

USE mpi_f08
MPI_Get_elements(status, datatype, count, ierror)
    TYPE(MPI_Status), INTENT(IN) :: status
    TYPE(MPI_Datatype), INTENT(IN) :: datatype
    INTEGER, INTENT(OUT) :: count
    INTEGER, OPTIONAL, INTENT(OUT) :: ierror
MPI_Get_elements_x(status, datatype, count, ierror)
    TYPE(MPI_Status), INTENT(IN) :: status
    TYPE(MPI_Datatype), INTENT(IN) :: datatype
    INTEGER(KIND = MPI_COUNT_KIND), INTENT(OUT) :: count
    INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARÁMETROS DE ENTRADA

  • status : Estado de la operación de recepción (status).
  • datatype : Tipo de dato utilizado en la operación de recepción (handle).

PARÁMETROS DE SALIDA

•
ierror : Estado de error (entero) solo en Fortran.

DESCRIPCIÓN

MPI_Get_elements y MPI_Get_elements_x se diferencian de MPI_Get_count en que devuelven el número de "entradas de nivel superior" recibidas, es decir, el número de "copias" del tipo de dato. MPI_Get_count puede devolver cualquier valor entero k, donde 0 < k < count. Si MPI_Get_count devuelve k, entonces el número de elementos básicos recibidos (y el valor devuelto por MPI_Get_elements y MPI_Get_elements_x) es n * k, donde n es el número de elementos básicos en el mapa de tipo de dato. Si el número de elementos básicos recibidos no es un múltiplo de n, es decir, si la operación de recepción no ha recibido un número integral de copias del tipo de dato, entonces MPI_Get_count devuelve MPI_UNDEFINED. Para ambas funciones, si el parámetro count no puede expresar el valor a devolver (por ejemplo, si el parámetro es demasiado pequeño para almacenar el valor de salida), se establece a MPI_UNDEFINED.

Ejemplo: Uso de MPI_Get_count y MPI_Get_elements:

call MPI_TYPE_CONTIGUOUS(2, MPI_REAL, Type2, ierr)
call MPI_TYPE_COMMIT(Type2, ierr)
call MPI_COMM_RANK(comm, rank, ierr)
IF ( rank == 0 ) THEN
   CALL MPI_SEND(a, 2, MPI_REAL, 1, 0, comm, ierr)
   CALL MPI_SEND(a, 3, MPI_REAL, 1, 0, comm, ierr)
ELSE
   CALL MPI_RECV(a, 2, Type2, 0, 0, comm, stat, ierr)
   CALL MPI_GET_COUNT(stat, Type2, i, ierr) ! devuelve i=1
   CALL MPI_GET_ELEMENTS(stat, Type2, i, ierr) ! devuelve i=2
   CALL MPI_RECV(a, 2, Type2, 0, 0, comm, stat, ierr)
   CALL MPI_GET_COUNT(stat, Type2, i, ierr) ! devuelve i=MPI_UNDEFINED
   CALL MPI_GET_ELEMENTS(stat, Type2, i, ierr)  ! devuelve i=3
END IF

La función MPI_Get_elements también puede usarse después de una recepción para determinar el número de elementos en el mensaje recibido. Nótese que las dos funciones MPI_Get_count y MPI_Get_elements devuelven los mismos valores cuando se usan con tipos de datos primitivos.

ERRORES

La mayoría de las rutinas MPI devuelven un valor de error; las rutinas C lo devuelven como resultado de la función y las rutinas Fortran en el último argumento.

Antes de que se devuelva el valor de error, se llama al manejador de error actual asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo). Si no hay ningún objeto de comunicación asociado con la llamada MPI, entonces la llamada se considera asociada a MPI_COMM_SELF y se llama al manejador de error asociado. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se usa el modelo de Sesiones exclusivamente), el error llama al manejador de error inicial. El manejador de error inicial puede cambiarse llamando a MPI_Comm_set_errhandler en MPI_COMM_SELF cuando se usa el modelo del Mundo, o el argumento CLI mpi_initial_errhandler para mpiexec o la clave info para MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no se establece ningún otro manejador de error adecuado, se llama al manejador de error MPI_ERRORS_RETURN para las funciones de E/S MPI y al manejador de error MPI_ERRORS_ABORT para todas las demás funciones MPI.

Open MPI incluye tres manejadores de error predeterminados que pueden usarse:

  • MPI_ERRORS_ARE_FATAL Hace que el programa aborte todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT Un manejador de error que puede invocarse en un comunicador, ventana, archivo o sesión. Cuando se invoca en un comunicador, actúa como si se hubiera llamado MPI_Abort en ese comunicador. Si se invoca en una ventana o archivo, actúa como si se hubiera llamado MPI_Abort en un comunicador que contiene el grupo de procesos correspondiente en la ventana o archivo. Si se invoca en una sesión, solo se aborta el proceso local.
  • MPI_ERRORS_RETURN Devuelve un código de error a la aplicación.

Los programas MPI también pueden implementar sus propios manejadores de error llamando:

  • MPI_Comm_create_errhandler luego MPI_Comm_set_errhandler
  • MPI_File_create_errhandler luego MPI_File_set_errhandler
  • MPI_Session_create_errhandler luego MPI_Session_set_errhandler o en MPI_Session_init
  • MPI_Win_create_errhandler luego MPI_Win_set_errhandler

Nota: MPI no garantiza que un programa MPI pueda continuar después de un error.

Ver la página del manual de MPI para una lista completa de códigos de error MPI.

Ver la sección de manejo de errores de la estándar MPI-3.1 para más información.
