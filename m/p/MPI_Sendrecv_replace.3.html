Licencias: BSD-3-Clause AND LicenseRef-MPICH

MPI_SENDRECV_REPLACE(3) Open MPI MPI_SENDRECV_REPLACE(3)

MPI_Sendrecv_replace — Envía y recibe un mensaje usando un único buffer.

SINTAXIS

Sintaxis C

#include <mpi.h>
int MPI_Sendrecv_replace(void *buf, int count, MPI_Datatype datatype,
     int dest, int sendtag, int source, int recvtag, MPI_Comm comm,
     MPI_Status *status)

Sintaxis Fortran

USE MPI
! o la forma más antigua: INCLUDE 'mpif.h'
MPI_SENDRECV_REPLACE(BUF, COUNT, DATATYPE, DEST, SENDTAG, SOURCE,
             RECVTAG, COMM, STATUS, IERROR)
     <type>  BUF(*)
     INTEGER COUNT, DATATYPE, DEST, SENDTAG
     INTEGER SOURCE, RECVTAG, COMM
     INTEGER STATUS(MPI_STATUS_SIZE), IERROR

Sintaxis Fortran 2008

USE mpi_f08
MPI_Sendrecv_replace(buf, count, datatype, dest, sendtag, source, recvtag,
             comm, status, ierror)
     TYPE(*), DIMENSION(..) :: buf
     INTEGER, INTENT(IN) :: count, dest, sendtag, source, recvtag
     TYPE(MPI_Datatype), INTENT(IN) :: datatype
     TYPE(MPI_Comm), INTENT(IN) :: comm
     TYPE(MPI_Status) :: status
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARÁMETROS ENTRADA/SALIDA

•
buf: Dirección inicial del buffer de envío y recepción (elección).

PARÁMETROS DE ENTRADA

  • count: Número de elementos en el buffer de envío y recepción (entero).
  • datatype: Tipo de elementos a enviar y recibir (manejador).
  • dest: Rango del destino (entero).
  • sendtag: Etiqueta del mensaje de envío (entero).
  • source: Rango de la fuente (entero).
  • recvtag: Etiqueta del mensaje de recepción (entero).
  • comm: Comunicador (manejador).

PARÁMETROS DE SALIDA

  • status: Objeto de estado (estado).
  • ierror: Solo Fortran: Estado de error (entero).

DESCRIPCIÓN

Las operaciones de envío-recepción combinan en una sola llamada el envío de un mensaje a un destino y la recepción de otro mensaje, desde otro proceso. Los dos (origen y destino) son posiblemente el mismo. Una operación de envío-recepción es útil para ejecutar una operación de desplazamiento a través de una cadena de procesos. Si se utilizan envíos y recepciones bloqueantes para dicho desplazamiento, se necesita ordenar correctamente los envíos y recepciones (por ejemplo, los procesos pares envían, luego reciben; los procesos impares reciben primero, luego envían) para evitar dependencias cíclicas que puedan conducir a un interbloqueo. Cuando se utiliza una operación de envío-recepción, el subsistema de comunicación se encarga de estos problemas. La operación de envío-recepción se puede utilizar junto con las funciones descritas en el Capítulo 6 del Estándar MPI, «Topologías de Procesos», para realizar desplazamientos en varias topologías lógicas. Además, una operación de envío-recepción es útil para implementar llamadas a procedimientos remotos.

Un mensaje enviado por una operación de envío-recepción puede ser recibido por una operación de recepción regular o sondeado por una operación de sondeo; una operación de envío-recepción puede recibir un mensaje enviado por una operación de envío regular.

MPI_Sendrecv_replace ejecuta un envío y una recepción bloqueantes. Se utiliza el mismo buffer tanto para el envío como para la recepción, de modo que el mensaje enviado es reemplazado por el mensaje recibido.

La semántica de una operación de envío-recepción es lo que se obtendría si el llamador creara dos hilos concurrentes, uno para ejecutar el envío y otro para ejecutar la recepción, seguido de una unión de estos dos hilos.

ERRORES

Casi todas las rutinas de MPI devuelven un valor de error; las rutinas C como resultado de la función y las rutinas Fortran en el último argumento.

Antes de que se devuelva el valor de error, se llama al manejador de errores MPI actual asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo). Si no hay ningún objeto de comunicación asociado con la llamada MPI, la llamada se considera asociada a MPI_COMM_SELF y llamará al manejador de errores MPI asociado. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se utiliza exclusivamente el Modelo de Sesiones), el error activa el manejador de errores inicial. El manejador de errores inicial se puede cambiar llamando a MPI_Comm_set_errhandler en MPI_COMM_SELF cuando se utiliza el modelo World, o al argumento CLI mpi_initial_errhandler de mpiexec o a la clave de información de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no se ha configurado ningún otro manejador de errores apropiado, entonces se llama al manejador de errores MPI_ERRORS_RETURN para las funciones de E/S de MPI y al manejador de errores MPI_ERRORS_ABORT para todas las demás funciones de MPI.

Open MPI incluye tres manejadores de errores predefinidos que se pueden utilizar:

  • MPI_ERRORS_ARE_FATAL Provoca que el programa aborte todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT Un manejador de errores que se puede invocar en un comunicador, ventana, archivo o sesión. Cuando se llama en un comunicador, actúa como si se hubiera llamado a MPI_Abort en ese comunicador. Si se llama en una ventana o archivo, actúa como si se hubiera llamado a MPI_Abort en un comunicador que contiene el grupo de procesos de la ventana o archivo correspondiente. Si se llama en una sesión, aborta solo el proceso local.
  • MPI_ERRORS_RETURN Devuelve un código de error a la aplicación.

Las aplicaciones MPI también pueden implementar sus propios manejadores de errores llamando a:

  • MPI_Comm_create_errhandler luego MPI_Comm_set_errhandler
  • MPI_File_create_errhandler luego MPI_File_set_errhandler
  • MPI_Session_create_errhandler luego MPI_Session_set_errhandler o en MPI_Session_init
  • MPI_Win_create_errhandler luego MPI_Win_set_errhandler

Tenga en cuenta que MPI no garantiza que un programa MPI pueda continuar después de un error.

Consulte la página del manual de MPI para obtener una lista completa de los *códigos de error de MPI*.

Consulte la sección de Manejo de Errores del estándar MPI-3.1 para obtener más información.

Tenga en cuenta que según la sección «Estado de Retorno» del capítulo «Comunicación Punto a Punto» del *Estándar MPI*, los errores de MPI en los mensajes recibidos por MPI_Sendrecv_replace no establecen el campo status.MPI_ERROR en el status devuelto. El código de error siempre se pasa al manejador de errores de backend y puede ser devuelto al llamador a través del valor de retorno de MPI_Sendrecv_replace si el manejador de errores de backend lo devuelve. El manejador de errores predefinido de MPI MPI_ERRORS_RETURN exhibe este comportamiento, por ejemplo.
