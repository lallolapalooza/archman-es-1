PARÁMETROS DE ENTRADA

  • sendbuf: Dirección de inicio del búfer de envío (elección).
  • recvcounts: Matriz entera que especifica el número de elementos en el resultado distribuido a cada proceso. La matriz debe ser idéntica en todos los procesos que llaman.
  • datatype: Tipo de datos de los elementos del búfer de entrada (manejador).
  • op: Operación (manejador).
  • comm: Comunicador (manejador).
  • info: Información (manejador, persistente).

PARÁMETROS DE SALIDA

  • recvbuf: Dirección de inicio del búfer de recepción (elección).
  • request: Solicitud (manejador, solo no bloqueante).
  • ierror: Solo Fortran: estado de error (entero).

DESCRIPCIÓN

MPI_Reduce_scatter primero realiza una reducción elemento a elemento en el vector de count = S(i)recvcounts[i] elementos en el búfer de envío definido por sendbuf, count y datatype. A continuación, el vector resultante de resultados se divide en n segmentos disjuntos, donde n es el número de procesos del grupo. El segmento i contiene recvcounts[i] elementos. El i-ésimo segmento se envía al proceso i y se almacena en el búfer de recepción definido por recvbuf, recvcounts[i] y datatype.

USO DE LA OPCIÓN IN-PLACE

Cuando el comunicador es un intracommunicator, se puede realizar una operación de reduce-scatter in-place (el búfer de salida se utiliza como el búfer de entrada). Utilice la variable MPI_IN_PLACE como valor de sendbuf. En este caso, los datos de entrada se toman de la parte superior del búfer de recepción. El área ocupada por los datos de entrada puede ser más larga o más corta que los datos llenados por los datos de salida.

CUANDO EL COMUNICADOR ES UN INTER-COMUNICADOR

Cuando el comunicador es un inter-comunicador, la operación de reduce-scatter ocurre en dos fases. Primero, el resultado de la reducción realizada en los datos proporcionados por los procesos del primer grupo se distribuye entre los procesos del segundo grupo. Luego ocurre lo inverso: la reducción realizada en los datos proporcionados por los procesos del segundo grupo se distribuye entre los procesos del primer grupo. Para cada grupo, todos los procesos proporcionan el mismo argumento recvcounts, y la suma de los valores de recvcounts debe ser la misma para ambos grupos.

NOTAS SOBRE OPERACIONES COLECTIVAS

Las funciones de reducción ( MPI_Op ) no devuelven un valor de error. Por lo tanto, si las funciones detectan un error, lo único que pueden hacer es llamar a MPI_Abort o omitir silenciosamente el problema. Por lo tanto, si cambia el controlador de errores de MPI_ERRORS_ARE_FATAL a otro, por ejemplo, MPI_ERRORS_RETURN , es posible que no se indique ningún error.

La razón de esto son los problemas de rendimiento para asegurar que todas las rutinas colectivas devuelvan el mismo valor de error.

ERRORES

Casi todas las rutinas MPI devuelven un valor de error; las rutinas C como resultado de la función y las rutinas Fortran en el último argumento.

Antes de que se devuelva el valor de error, se llama al controlador de errores MPI actual asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo). Si no hay ningún objeto de comunicación asociado con la llamada MPI, entonces la llamada se considera adjunta a MPI_COMM_SELF y llamará al controlador de errores MPI asociado. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize o cuando se utiliza exclusivamente el modelo de sesiones), el error eleva el controlador de errores inicial. El controlador de errores inicial se puede cambiar llamando a MPI_Comm_set_errhandler en MPI_COMM_SELF cuando se utiliza el modelo World, o el argumento de CLI mpi_initial_errhandler a mpiexec o la clave de información a MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no se ha establecido ningún otro controlador de errores apropiado, entonces se llama al controlador de errores MPI_ERRORS_RETURN para las funciones de E/S de MPI y al controlador de errores MPI_ERRORS_ABORT para todas las demás funciones de MPI.

Open MPI incluye tres controladores de errores predefinidos que se pueden utilizar:

  • MPI_ERRORS_ARE_FATAL Provoca que el programa aborte todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT Un controlador de errores que se puede invocar en un comunicador, ventana, archivo o sesión. Cuando se llama en un comunicador, actúa como si se hubiera llamado a MPI_Abort en ese comunicador. Si se llama en una ventana o archivo, actúa como si se hubiera llamado a MPI_Abort en un comunicador que contiene el grupo de procesos en la ventana o archivo correspondiente. Si se llama en una sesión, aborta solo el proceso local.
  • MPI_ERRORS_RETURN Devuelve un código de error a la aplicación.

Las aplicaciones MPI también pueden implementar sus propios controladores de errores llamando a:

  • MPI_Comm_create_errhandler y luego MPI_Comm_set_errhandler
  • MPI_File_create_errhandler y luego MPI_File_set_errhandler
  • MPI_Session_create_
