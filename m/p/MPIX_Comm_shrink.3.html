MPIX_Comm_shrink(3)

Paquete: openmpi

Licencias: BSD-3-Clause AND LicenseRef-MPICH

MPIX_COMM_SHRINK(3) Open MPI MPIX_COMM_SHRINK(3)

MPIX_Comm_shrink, MPIX_Comm_ishrink - Crea un nuevo comunicador que incluye a todos los procesos del comunicador padre que no han fallado.

Esto es parte de la extensión *User Level Fault Mitigation* (*ULFM*).

SINTAXIS

Sintaxis C

#include <mpi.h>
#include <mpi-ext.h>
int MPIX_Comm_shrink(MPI_Comm comm, MPI_Comm *newcomm)
int MPIX_Comm_ishrink(MPI_Comm comm, MPI_Comm *newcomm, MPI_Request *request)

Sintaxis Fortran

USE MPI
USE MPI_EXT
! o la forma antigua: INCLUDE 'mpif.h'
MPIX_COMM_SHRINK(COMM, NEWCOMM, IERROR)
     INTEGER COMM, NEWCOMM, IERROR
MPIX_COMM_ISHRINK(COMM, NEWCOMM, REQUEST, IERROR)
     INTEGER COMM, NEWCOMM, REQUEST, IERROR

Sintaxis Fortran 2008

USE mpi_f08
USE mpi_ext_f08
MPIX_Comm_shrink(comm, newcomm, ierror)
     TYPE(MPI_Comm), INTENT(IN) :: comm
     TYPE(MPI_Comm), INTENT(OUT) :: newcomm
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror
MPIX_Comm_ishrink(comm, newcomm, request, ierror)
     TYPE(MPI_Comm), INTENT(IN) :: comm
     TYPE(MPI_Comm), INTENT(OUT), ASYNCHRONOUS :: newcomm
     TYPE(MPI_Request), INTENT(OUT) :: request
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARÁMETROS DE ENTRADA

•
comm: Comunicador (manejador).

PARÁMETROS DE SALIDA

  • newcomm: Comunicador (manejador).
  • request: Solicitud (manejador, solo no bloqueante).
  • ierror: Solo Fortran: Estado de error (entero).

DESCRIPCIÓN

Esta operación colectiva crea un nuevo intercomunicador o comunicador intracomunicador newcomm a partir del intercomunicador o comunicador intracomunicador comm, respectivamente, excluyendo el grupo de procesos MPI fallidos detectados durante la operación.

Los grupos de newcomm deben incluir a cada proceso MPI que regresa de MPIX_Comm_shrink, y deben excluir a cada proceso MPI cuya falla causó que una operación en comm generara un error MPI de clase MPIX_ERR_PROC_FAILED o MPIX_ERR_PROC_FAILED_PENDING en un miembro de los grupos de newcomm, antes de que dicho miembro iniciara la operación de reducción.

En otras palabras, este procedimiento es semánticamente equivalente a una operación MPI_Comm_split que tendría éxito a pesar de las fallas, donde los miembros de los grupos de newcomm participan con el mismo color y una clave igual a su rango en comm.

MPIX_Comm_ishrink es la variante no bloqueante de MPIX_Comm_shrink. Tenga en cuenta que, al igual que con MPI_Comm_idup, es erróneo usar newcomm antes de que request haya completado.

CUANDO EL COMUNICADOR ES REVOCADO O CONTIENE PROCESOS FALLIDOS

Esta función nunca genera un error de las clases MPIX_ERR_REVOKED o MPIX_ERR_PROC_FAILED. Las semánticas definidas de MPIX_Comm_shrink y MPIX_Comm_ishrink se mantienen cuando comm es revocado, o cuando el grupo de comm contiene procesos MPI fallidos. En particular, MPIX_Comm_shrink y MPIX_Comm_ishrink son operaciones colectivas, incluso cuando comm es revocado.

La implementación se esforzará por detectar todas las fallas durante la operación de reducción, pero en ciertas circunstancias, el grupo de newcomm aún puede contener procesos MPI fallidos, cuya falla se detectará en operaciones MPI posteriores en newcomm.

ERRORES

Casi todas las rutinas MPI devuelven un valor de error; rutinas C como resultado de la función y rutinas Fortran en el último argumento.

Antes de que se devuelva el valor de error, se llama al manejador de errores MPI actual asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo). Si no hay ningún objeto de comunicación asociado con la llamada MPI, entonces la llamada se considera adjunta a MPI_COMM_SELF y llamará al manejador de errores MPI asociado. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se usa exclusivamente el Modelo de Sesiones), el error genera el manejador de errores inicial. El manejador de errores inicial se puede cambiar llamando a MPI_Comm_set_errhandler en MPI_COMM_SELF cuando se usa el modelo World, o el argumento de línea de comandos mpi_initial_errhandler a mpiexec o la clave info a MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no se ha establecido ningún otro manejador de errores apropiado, entonces se llama al manejador de errores MPI_ERRORS_RETURN para las funciones de E/S MPI y al manejador de errores MPI_ERRORS_ABORT para todas las demás funciones MPI.

Open MPI incluye tres manejadores de errores predefinidos que se pueden usar:

  • MPI_ERRORS_ARE_FATAL Provoca que el programa aborte todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT Un manejador de errores que se puede invocar en un comunicador, ventana, archivo o sesión. Cuando se llama en un comunicador, actúa como si se hubiera llamado a MPI_Abort en ese comunicador. Si se llama en una ventana o archivo, actúa como si se hubiera llamado a MPI_Abort en un comunicador que contiene el grupo de procesos en la ventana o archivo correspondiente. Si se llama en una sesión, solo aborta el proceso local.
  • MPI_ERRORS_RETURN Devuelve un código de error a la aplicación.

Las aplicaciones MPI también pueden implementar sus propios manejadores de errores llamando a:

  • MPI_Comm_create_errhandler luego MPI_Comm_set_errhandler
  • MPI_File_create_errhandler luego MPI_File_set_errhandler
  • MPI_Session_create_errhandler luego MPI_Session_set_errhandler o en MPI_Session_init
  • MPI_Win_create_errhandler luego MPI_Win_set_errhandler

Tenga en cuenta que MPI no garantiza que un programa MPI pueda continuar después de un error.

Consulte la *página del manual de MPI* para obtener una lista completa de los *códigos de error de MPI*.

Consulte la sección de Manejo de Errores del estándar MPI-3.1 para más información.
