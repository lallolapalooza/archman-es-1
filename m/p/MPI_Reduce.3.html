MPI_Reduce, MPI_Ireduce, MPI_Reduce_init - Reduce valores en todos los procesos dentro de un grupo.

PARÁMETROS DE ENTRADA

  • sendbuf: Dirección del búfer de envío (opcional).
  • count: Número de elementos en el búfer de envío (entero).
  • datatype: Tipo de datos de los elementos del búfer de envío (handle).
  • op: Operación de reducción (handle).
  • root: Rango del proceso raíz (entero).
  • comm: Comunicador (handle).
  • info: Información (handle, persistente).

PARÁMETROS DE SALIDA

  • recvbuf: Dirección del búfer de recepción (opcional, significativo solo en la raíz).
  • request: Solicitud (handle, solo no bloqueante).
  • ierror: Solo Fortran: Estado de error (entero).

DESCRIPCIÓN

Las funciones de reducción global (MPI_Reduce, MPI_Op_create, MPI_Op_free, MPI_Allreduce, MPI_Reduce_scatter, MPI_Scan) realizan una operación de reducción global (como suma, máximo, AND lógico, etc.) en todos los miembros de un grupo. La operación de reducción puede ser una de una lista predefinida de operaciones, o una operación definida por el usuario. Las funciones de reducción global vienen en varios sabores: una reducción que devuelve el resultado de la reducción en un nodo, una all-reduce que devuelve este resultado en todos los nodos, y una operación de scan (prefijo paralelo). Además, una operación reduce-scatter combina la funcionalidad de una operación de reduce y scatter.

MPI_Reduce combina los elementos proporcionados en el búfer de entrada de cada proceso en el grupo, utilizando la operación op, y devuelve el valor combinado en el búfer de salida del proceso con rango root. El búfer de entrada se define por los argumentos sendbuf, count y datatype; el búfer de salida se define por los argumentos recvbuf, count y datatype; ambos tienen el mismo número de elementos, con el mismo tipo. La rutina es llamada por todos los miembros del grupo usando los mismos argumentos para count, datatype, op, root, y comm. Por lo tanto, todos los procesos proporcionan búferes de entrada y búferes de salida de la misma longitud, con elementos del mismo tipo. Cada proceso puede proporcionar un elemento, o una secuencia de elementos, en cuyo caso la operación combine se ejecuta elemento por elemento en cada entrada de la secuencia. Por ejemplo, si la operación es MPI_MAX y el búfer de envío contiene dos elementos que son números de punto flotante (count = 2 y datatype = MPI_FLOAT), entonces recvbuf(1) = máximo global (sendbuf(1)) y recvbuf(2) = máximo global(sendbuf(2)).

USO DE LA OPCIÓN IN-PLACE

Cuando el comunicador es un intracommunicator, puedes realizar una operación de reducción in-place (el búfer de salida se utiliza como búfer de entrada). Utiliza la variable MPI_IN_PLACE como valor del sendbuf del proceso raíz. En este caso, los datos de entrada se toman en la raíz del búfer de recepción, donde serán reemplazados por los datos de salida.

Ten en cuenta que MPI_IN_PLACE es un tipo especial de valor; tiene las mismas restricciones de uso que MPI_BOTTOM.

Dado que la opción in-place convierte el búfer de recepción en un búfer de envío y recepción, una vinculación de Fortran que incluya INTENT debe marcarlos como INOUT, no como OUT.

CUANDO EL COMUNICADOR ES UN INTER-COMUNICADOR

Cuando el comunicador es un inter-comunicador, el proceso raíz del primer grupo combina datos de todos los procesos del segundo grupo y luego realiza la operación op. El primer grupo define el proceso raíz. Ese proceso utiliza MPI_ROOT como valor de su argumento root. Los procesos restantes utilizan MPI_PROC_NULL como valor de su argumento root. Todos los procesos del segundo grupo utilizan el rango de ese proceso raíz en el primer grupo como valor de su argumento root. Solo los argumentos del búfer de envío son significativos en el segundo grupo, y solo los argumentos del búfer de recepción son significativos en el proceso raíz del primer grupo.

OPERACIONES DE REDUCCIÓN PREDEFINIDAS

El conjunto de operaciones predefinidas proporcionadas por MPI se enumera a continuación (Operaciones de Reducción Predefinidas). Esa sección también enumera los tipos de datos a los que se puede aplicar cada operación. Además, los usuarios pueden definir sus propias operaciones que pueden ser sobrecargadas para operar en varios tipos de datos, ya sean básicos o derivados. Esto se explica más adelante en la descripción de las operaciones definidas por el usuario (ver las páginas del manual para MPI_Op_create y MPI_Op_free).

Se asume que la operación op es siempre asociativa. Se asume que todas las operaciones predefinidas también son conmutativas. Los usuarios pueden definir operaciones que se asumen asociativas, pero no conmutativas. El orden de evaluación "canónico" de una reducción se determina por los rangos de los procesos en el grupo. Sin embargo, la implementación puede aprovechar la asociatividad, o la asociatividad y la conmutatividad, para cambiar el orden de evaluación. Esto puede cambiar el resultado de la reducción para operaciones que no son estrictamente asociativas y conmutativas, como la suma de punto flotante.

Los operadores predefinidos funcionan solo con los tipos MPI listados a continuación (Operaciones de Reducción Predefinidas, y la sección MINLOC y MAXLOC, más abajo). Los operadores definidos por el usuario pueden operar en tipos de datos generales y derivados. En este caso, cada argumento al que se aplica la operación de reducción es un elemento descrito por dicho tipo de datos, que puede

contiene varios valores básicos. Esto se explica con más detalle en la Sección 4.9.4 del Estándar MPI, "Operaciones definidas por el usuario". Las siguientes operaciones predefinidas se proporcionan para MPI_Reduce y funciones relacionadas MPI_Allreduce, MPI_Reduce_scatter y MPI_Scan. Estas operaciones se invocan colocando lo siguiente en op:

**Ejemplo 1:** Una rutina que calcula el producto escalar de dos vectores que se distribuyen entre un grupo de procesos y devuelve la respuesta en el proceso cero. 
SUBROUTINE PAR_BLAS1(m, a, b, c, comm)
REAL a(m), b(m)       ! porción local del array
REAL c                ! resultado (en el proceso cero)
REAL sum
INTEGER m, comm, i, ierr
! suma local
sum = 0.0
DO i = 1, m
   sum = sum + a(i)*b(i)
END DO
! suma global
CALL MPI_REDUCE(sum, c, 1, MPI_REAL, MPI_SUM, 0, comm, ierr)
RETURN
**Ejemplo 2:** Una rutina que calcula el producto de un vector y una matriz que se distribuyen entre un grupo de procesos y devuelve la respuesta en el proceso cero. 
SUBROUTINE PAR_BLAS2(m, n, a, b, c, comm)
REAL a(m), b(m,n)    ! porción local del array
REAL c(n)            ! resultado
REAL sum(n)
INTEGER n, comm, i, j, ierr
! suma local
DO j= 1, n
  sum(j) = 0.0
  DO i = 1, m
    sum(j) = sum(j) + a(i)*b(i,j)
  END DO
END DO
! suma global
CALL MPI_REDUCE(sum, c, n, MPI_REAL, MPI_SUM, 0, comm, ierr)
! devolver el resultado en el proceso cero (y basura en los otros nodos)
RETURN

MINLOC Y MAXLOC

El operador MPI_MINLOC se utiliza para calcular un mínimo global y también un índice asociado al valor mínimo. MPI_MAXLOC calcula de manera similar un máximo global e índice. Una aplicación de estos es calcular un mínimo (máximo) global y el rango del proceso que contiene este valor.

La operación que define MPI_MAXLOC es

         ( u )    (  v )      ( w )
         (   )  o (    )   =  (   )
         ( i )    (  j )      ( k )
donde
    w = max(u, v)
y
         ( i            si u > v
         (
   k   = ( min(i, j)    si u = v
         (
         (  j           si u < v)

MPI_MINLOC se define de manera similar:

         ( u )    (  v )      ( w )
         (   )  o (    )   =  (   )
         ( i )    (  j )      ( k )
donde
    w = min(u, v)
y
         ( i            si u < v
         (
   k   = ( min(i, j)    si u = v
         (
         (  j           si u > v)

Ambas operaciones son asociativas y conmutativas. Tenga en cuenta que si MPI_MAXLOC se aplica para reducir una secuencia de pares (u(0), 0), (u(1), 1), ..., (u(n-1), n-1), entonces el valor devuelto es (u , r), donde u = max(i) u(i) y r es el índice del primer máximo global en la secuencia. Por lo tanto, si cada proceso proporciona un valor y su rango dentro del grupo, entonces una operación de reducción con op = MPI_MAXLOC devolverá el valor máximo y el rango del primer proceso con ese valor. De manera similar, MPI_MINLOC se puede usar para devolver un mínimo y su índice. De forma más general, MPI_MINLOC calcula un mínimo lexicográfico, donde los elementos se ordenan según el primer componente de cada par, y los empates se resuelven según el segundo componente.

La operación de reducción está definida para operar sobre argumentos que consisten en un par: valor e índice. Tanto para Fortran como para C, se proporcionan tipos para describir el par. La naturaleza potencialmente mixta de tales argumentos es un problema en Fortran. El problema se circunvala, para Fortran, al hacer que el tipo proporcionado por MPI consista en un par del mismo tipo que el valor, y al forzar la coerción del índice a este tipo también. En C, el tipo de par proporcionado por MPI tiene tipos distintos y el índice es un int.

Para utilizar MPI_MINLOC y MPI_MAXLOC en una operación de reducción, se debe proporcionar un argumento de tipo de datos que represente un par (valor e índice). MPI proporciona nueve de estos tipos de datos predefinidos. Las operaciones MPI_MAXLOC y MPI_MINLOC se pueden usar con cada uno de los siguientes tipos de datos:

Fortran:
Nombre                     Descripción
MPI_2REAL                par de REALs
MPI_2DOUBLE_PRECISION    par de variables DOUBLE_PRECISION
MPI_2INTEGER             par de INTEGERs
C:
Nombre                     Descripción
MPI_FLOAT_INT            float e int
MPI_DOUBLE_INT           double e int
MPI_LONG_INT             long e int
MPI_2INT                 par de ints
MPI_SHORT_INT            short e int
MPI_LONG_DOUBLE_INT      long double e int

El tipo de datos MPI_2REAL es equivalente a:

MPI_TYPE_CONTIGUOUS(2, MPI_REAL, MPI_2REAL)

Declaraciones similares se aplican para MPI_2INTEGER, MPI_2DOUBLE_PRECISION y MPI_2INT.

El tipo de datos MPI_FLOAT_INT es como si estuviera definido por la siguiente secuencia de instrucciones.

type[0] = MPI_FLOAT
type[1] = MPI_INT
disp[0] = 0
disp[1] = sizeof(float)
block[0] = 1
block[1] = 1
MPI_TYPE_STRUCT(2, block, disp, type, MPI_FLOAT_INT)

Declaraciones similares se aplican para MPI_LONG_INT y MPI_DOUBLE_INT.

**Ejemplo 3:** Cada proceso tiene un array de 30 doubles, en C. Para cada una de las 30 ubicaciones, calcule el valor y el rango del proceso que contiene el valor más grande.

...
/* cada proceso tiene un array de 30 double: ain[30]
 */
double ain[30], aout[30];
int  ind[30];
struct {
    double val;
    int   rank;
} in[30], out[30];
int i, myrank, root;
MPI_Comm_rank(MPI_COMM_WORLD, &myrank);
for (i=0; i<30; ++i) {
    in[i].val = ain[i];
    in[i].rank = myrank;
}
MPI_Reduce( in, out, 30, MPI_DOUBLE_INT, MPI_MAXLOC, root, comm );
/* En este punto, la respuesta reside en el proceso root
 */
if (myrank == root) {
    /* leer los rangos
     */
    for (i=0; i<30; ++i) {
        aout[i] = out[i].val;
        ind[i] = out[i].rank;
    }
}

**Ejemplo 4:** Mismo ejemplo, en Fortran.

...
! cada proceso tiene un array de 30 double: ain(30)
DOUBLE PRECISION :: ain(30), aout(30)
INTEGER :: ind(30)
DOUBLE PRECISION :: in(2,30), out(2,30)
INTEGER :: i, myrank, root, ierr
call MPI_COMM_RANK(MPI_COMM_WORLD, myrank)
DO I=1, 30
    in(1,i) = ain(i)
    in(2,i) = myrank    ! myrank se fuerza a un double
END DO
call MPI_REDUCE( in, out, 30, MPI_2DOUBLE_PRECISION, MPI_MAXLOC, root, &
                                                          comm, ierr )
! En este punto, la respuesta reside en el proceso root
IF (myrank == root) THEN
    ! leer la respuesta
    DO I= 1, 30
        aout(i) = out(1,i)
        ind(i) = out(2,i)  ! el rango se fuerza de vuelta a un entero
    END DO

**Ejemplo 5:** Cada proceso tiene un array no vacío de valores. Encuentra el valor mínimo global, el rango del proceso que lo contiene y su índice en este proceso.

#define  LEN   1000
float val[LEN];        /* array local de valores */
int count;             /* número local de valores */
int myrank, minrank, minindex;
float minval;
struct {
    float value;
    int   index;
} in, out;
/* minloc local */
in.value = val[0];
in.index = 0;
for (i=1; i < count; i++)
    if (in.value > val[i]) {
        in.value = val[i];
        in.index = i;
    }
/* minloc global */
MPI_Comm_rank(MPI_COMM_WORLD, &myrank);
in.index = myrank*LEN + in.index;
MPI_Reduce( in, out, 1, MPI_FLOAT_INT, MPI_MINLOC, root, comm );
    /* En este punto, la respuesta reside en el proceso root
     */
if (myrank == root) {
    /* leer la respuesta
     */
    minval = out.value;
    minrank = out.index / LEN;
    minindex = out.index % LEN;

NOTAS SOBRE OPERACIONES COLECTIVAS

Las funciones de reducción ( MPI_Op ) no devuelven un valor de error. Como resultado, si las funciones detectan un error, todo lo que pueden hacer es llamar a MPI_Abort o omitir silenciosamente el problema. Por lo tanto, si cambia el manejador de errores de MPI_ERRORS_ARE_FATAL a otra cosa, por ejemplo, MPI_ERRORS_RETURN , es posible que no se indique ningún error.

La razón de esto son los problemas de rendimiento para garantizar que todas las rutinas colectivas devuelvan el mismo valor de error.

ERRORES

Casi todas las rutinas de MPI devuelven un valor de error; las rutinas C como resultado de la función y las rutinas Fortran en el último argumento.

Antes de que se devuelva el valor de error, se llama al manejador de errores de MPI actual asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo). Si no hay un objeto de comunicación asociado con la llamada MPI, entonces la llamada se considera adjunta a MPI_COMM_SELF y llamará al manejador de errores de MPI asociado. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se utiliza exclusivamente el Modelo de Sesiones) el error lanzado

ERRORS

The initial error handler is the one that is set by default when MPI is initialized. The initial error handler can be changed by calling MPI_Comm_set_errhandler on MPI_COMM_SELF when using the World model, or the mpi_initial_errhandler CLI argument to mpiexec or info key to MPI_Comm_spawn/MPI_Comm_spawn_multiple. If no other appropriate error handler has been set, then the MPI_ERRORS_RETURN error handler is called for MPI I/O functions and the MPI_ERRORS_ABORT error handler is called for all other MPI functions.

Open MPI includes three predefined error handlers that can be used:

  • MPI_ERRORS_ARE_FATAL Causes the program to abort all connected MPI processes.
  • MPI_ERRORS_ABORT An error handler that can be invoked on a communicator, window, file, or session. When called on a communicator, it acts as if MPI_Abort was called on that communicator. If called on a window or file, acts as if MPI_Abort was called on a communicator containing the group of processes in the corresponding window or file. If called on a session, aborts only the local process.
  • MPI_ERRORS_RETURN Returns an error code to the application.

MPI applications can also implement their own error handlers by calling:

  • MPI_Comm_create_errhandler then MPI_Comm_set_errhandler
  • MPI_File_create_errhandler then MPI_File_set_errhandler
  • MPI_Session_create_errhandler then MPI_Session_set_errhandler or at MPI_Session_init
  • MPI_Win_create_errhandler then MPI_Win_set_errhandler

Note that MPI does not guarantee that an MPI program can continue past an error.

See the MPI man page for a full list of MPI error codes.

See the Error Handling Section of the MPI-3.1 standard for more information.
