PARÁMETROS DE ENTRADA

  • sendbuf: Dirección de inicio del búfer de envío (elección).
  • recvcount: Conteo de elementos por bloque (entero no negativo).
  • datatype: Tipo de dato de los elementos del búfer de entrada (manejador).
  • op: Operación (manejador).
  • comm: Comunicador (manejador).
  • info: Información (manejador, solo persistente).

PARÁMETROS DE SALIDA

  • recvbuf: Dirección de inicio del búfer de recepción (elección).
  • request: Solicitud (manejador, solo no bloqueante).
  • ierror: Solo Fortran: Estado del error (entero).

DESCRIPCIÓN

MPI_Reduce_scatter_block primero realiza una reducción elemento a elemento en el vector de count = n * recvcount elementos en el búfer de envío definido por sendbuf, count y datatype, usando la operación op, donde n es el número de procesos en el grupo de comm. Luego, el vector resultante de resultados se divide en n segmentos disjuntos, donde n es el número de procesos en el grupo. Cada segmento contiene recvcount elementos. El i-ésimo segmento se envía al proceso i y se almacena en el búfer de recepción definido por recvbuf, recvcount y datatype.

USO DE LA OPCIÓN IN-PLACE

Cuando el comunicador es un intracommunicator, puedes realizar una operación reduce-scatter in-place (el búfer de salida se utiliza como el búfer de entrada). Usa la variable MPI_IN_PLACE como valor de sendbuf. En este caso, los datos de entrada se toman de la parte superior del búfer de recepción. El área ocupada por los datos de entrada puede ser más larga o más corta que los datos llenados por los datos de salida.

CUANDO EL COMUNICADOR ES UN INTER-COMUNICADOR

Cuando el comunicador es un inter-communicator, la operación reduce-scatter ocurre en dos fases. Primero, el resultado de la reducción realizada en los datos proporcionados por los procesos en el primer grupo se distribuye entre los procesos en el segundo grupo. Luego ocurre lo inverso: la reducción realizada en los datos proporcionados por los procesos en el segundo grupo se distribuye entre los procesos en el primer grupo. Para cada grupo, todos los procesos proporcionan el mismo argumento recvcounts, y la suma de los valores de recvcounts debe ser la misma para ambos grupos.

NOTAS SOBRE OPERACIONES COLECTIVAS

Las funciones de reducción ( MPI_Op ) no devuelven un valor de error. Como resultado, si las funciones detectan un error, lo único que pueden hacer es llamar a MPI_Abort o omitir silenciosamente el problema. Por lo tanto, si cambias el manejador de errores de MPI_ERRORS_ARE_FATAL a otro, por ejemplo, MPI_ERRORS_RETURN , entonces puede que no se indique ningún error.

La razón de esto son los problemas de rendimiento para garantizar que todas las rutinas colectivas devuelvan el mismo valor de error.

ERRORES

Casi todas las rutinas MPI devuelven un valor de error; las rutinas C como resultado de la función y las rutinas Fortran en el último argumento.

Antes de que se devuelva el valor de error, se llama al manejador de errores MPI actual asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo). Si no hay ningún objeto de comunicación asociado con la llamada MPI, entonces la llamada se considera adjunta a MPI_COMM_SELF y llamará al manejador de errores MPI asociado. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se usa exclusivamente el Modelo de Sesiones) el error eleva el manejador de errores inicial. El manejador de errores inicial se puede cambiar llamando a MPI_Comm_set_errhandler en MPI_COMM_SELF cuando se usa el modelo World, o el argumento de línea de comandos mpi_initial_errhandler a mpiexec o la clave de información para MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no se ha establecido ningún otro manejador de errores apropiado, entonces se llama al manejador de errores MPI_ERRORS_RETURN para las funciones de E/S de MPI y al manejador de errores MPI_ERRORS_ABORT para todas las demás funciones de MPI.

Open MPI incluye tres manejadores de errores predefinidos que se pueden usar:

  • MPI_ERRORS_ARE_FATAL Causa que el programa aborte todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT Un manejador de errores que se puede invocar en un comunicador, ventana, archivo o sesión. Cuando se llama en un comunicador, actúa como si se hubiera llamado a MPI_Abort en ese comunicador. Si se llama en una ventana o archivo, actúa como si se hubiera llamado a MPI_Abort en un comunicador que contiene el grupo de procesos en la ventana o archivo correspondiente. Si se llama en una sesión, aborta solo el proceso local.
  • MPI_ERRORS_RETURN Devuelve un código de error a la aplicación.

Las aplicaciones MPI también pueden implementar sus propios manejadores de errores llamando a:

  • MPI_Comm_create_errhandler luego MPI_Comm_set_errhandler
  • MPI_File_create_errhandler luego MPI_File_set_errhandler
MPI_Reduce_scatter_block_init(3) — OpenMPI 5.0.9

NAME

MPI_Reduce_scatter_block_init - Initializes a non-blocking generalized reduce-scatter-block operation.

SYNTAX

C

int MPI_Reduce_scatter_block_init(MPI_Comm comm, const void *sendbuf, void *recvbuf, int recvcount, MPI_Datatype datatype, MPI_Op op, MPI_Info info, MPI_Request *request);

Fortran

CALL MPI_REDUCE_SCATTER_BLOCK_INIT(COMM, SENDBUF, RECVBUF, RECVCOUNT, DATATYPE, OP, INFO, REQUEST, IERROR)
INTEGER COMM, RECVCOUNT, DATATYPE, OP, REQUEST, IERROR
TYPE(*), DIMENSION(..), INTENT(IN) :: SENDBUF
TYPE(*), DIMENSION(..), INTENT(OUT) :: RECVBUF
INTEGER, INTENT(IN) :: INFO

C++

MPI::Intracomm::reduce_scatter_block_init(const void *sendbuf, void *recvbuf, int recvcount, const MPI::Datatype& datatype, const MPI::Op& op, const MPI::Info& info, MPI::Request& request);

INPUT PARAMETERS

• comm
Communicator with a uniform reduction subtree structure. (handle)
• sendbuf
Address of the send buffer (if not MPI_IN_PLACE).
• recvcount
Number of elements in the receive buffer for each process.
• datatype
Data type of elements in send and receive buffers.
• op
Operation to be applied.
• info
Info object to control the operation (handle).

OUTPUT PARAMETERS

• recvbuf
Address of the receive buffer.
• request
MPI request object (handle).
• IERROR (Fortran)
Fortran return code. On the return from the function, this will be set to MPI_SUCCESS if the no errors occurred or a negative value if an error occurred.

DESCRIPTION

MPI_Reduce_scatter_block_init initializes a non-blocking generalized reduce-scatter-block operation. The operation applies a reduction operation to data distributed across the processes in the communicator `comm`, and then distributes the results across the processes. Each process receives a single block of data from the reduced result.

The communicator `comm` must have a uniform reduction subtree structure. This means that the number of processes in the communicator must be a multiple of the number of processes in each subgroup, and the subgroups must be of the same size.

The `sendbuf` argument is the starting address of the send buffer. If the communicator is an intracommunicator, all processes send data. If the communicator is an intercommunicator, only processes in the first group send data. The `recvbuf` argument is the starting address of the receive buffer. Each process receives a block of `recvcount` elements of type `datatype`.

The `datatype` argument specifies the data type of the elements in the send and receive buffers. The `op` argument specifies the reduction operation to be applied. Predefined operations include MPI_SUM, MPI_PROD, MPI_MAX, MPI_MIN, MPI_LAND, MPI_BAND, MPI_LOR, MPI_BOR, MPI_LXOR, MPI_BXOR, MPI_MAXLOC, MPI_MINLOC, MPI_IAND, MPI_ILAND, MPI_IOR, MPI_ILOR, MPI_IXOR, MPI_IBXOR. User-defined operations can also be used.

The `info` argument provides hints for optimizing the operation. The `request` argument is an MPI handle that will be used to identify the communication.

MPI_Reduce_scatter_block_init is the non-blocking version of MPI_Reduce_scatter_block. It returns immediately after initiating the operation. The actual reduction and data transfer may occur concurrently with other computations.

To complete the operation and retrieve the results, MPI_Wait or MPI_Test must be called with the returned `request` handle.

USE OF IN-PLACE OPTION

When a communicator is an intracommunicator, you can perform your reduction "in place". This means that the receive buffer is the same as the send buffer. In this case, the `sendbuf` argument is ignored, and the data is reduced in place in the `recvbuf`. The data in the receive buffer must be laid out identically to the data in the send buffer if it were not in place.

WHEN COMMUNICATOR IS AN INTER-COMMUNICATOR

If the communicator is an intercommunicator, then the operation is performed only between the local group and the remote group. The `sendbuf` must be specified on the processes in the local group, and the `recvbuf` must be specified on the processes in the remote group. The `recvcount` and `datatype` arguments must be the same on all processes. The `op` argument must be specified on the processes in the remote group.

NOTES ON COLLECTIVE OPERATIONS

Collective communication routines are called by all processes in a group. If a set of processes calls a collective communication routine, then all processes in the group must call that same routine, and must supply compatible arguments.

The communicators used in collective operations must have a uniform reduction subtree structure.

ERRORS

When an error occurs during this function call, the communicator is left in a state that may allow for error recovery.

  • MPI_ERR_COMM: Invalid communicator.
  • MPI_ERR_COUNT: Invalid count.
  • MPI_ERR_DATATYPE: Invalid datatype.
  • MPI_ERR_OP: Invalid operation.
  • MPI_ERR_INFO: Invalid info.
  • MPI_ERR_REQUEST: Invalid request.

The binding for `MPI_Reduce_scatter_block_init` may return `MPI_ERR_PENDING` if an error occurs during the initiation of the operation.

The binding for `MPI_Reduce_scatter_block_init` may return `MPI_ERR_IN_STATUS` if an error occurred during a previous collective operation on the same communicator. In this case, the error code for the previous operation will be returned in the `MPI_ERROR` field of the `MPI_Status` object associated with the request.

Note that MPI does not guarantee that an MPI program can continue past an error.

See the MPI man page for a full list of MPI error codes.

See the Error Handling section of the MPI-3.1 standard for more information.
