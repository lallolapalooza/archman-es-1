MPI_COMM_SPLIT_TYPE(3) Open MPI MPI_COMM_SPLIT_TYPE(3)

MPI_Comm_split_type — Crea nuevos comunicadores basados en colores y claves.

SINTAXIS

Sintaxis en C

#include <mpi.h>
int MPI_Comm_split_type(MPI_Comm comm, int split_type, int key,
     MPI_Info info, MPI_Comm *newcomm)

Sintaxis en Fortran

USE MPI
! o la forma antigua: INCLUDE 'mpif.h'
MPI_COMM_SPLIT_TYPE(COMM, SPLIT_TYPE, KEY, INFO, NEWCOMM, IERROR)
     INTEGER COMM, SPLIT_TYPE, KEY, INFO, NEWCOMM, IERROR

Sintaxis en Fortran 2008

USE mpi_f08
MPI_Comm_split_type(comm, split_type, key, info, newcomm, ierror)
     TYPE(MPI_Comm), INTENT(IN) :: comm
     INTEGER, INTENT(IN) :: split_type, key
     TYPE(MPI_Info), INTENT(IN) :: info
     TYPE(MPI_Comm), INTENT(OUT) :: newcomm
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARÁMETROS DE ENTRADA

  • comm: Comunicador (identificador).
  • split_type: Tipo de procesos que se agruparán (entero).
  • key: Control de asignación de rango (entero).
  • info: Parámetro de información (identificador).

PARÁMETROS DE SALIDA

  • newcomm: Nuevo comunicador (identificador).
  • ierror: Solo Fortran: estado de error (entero).

DESCRIPCIÓN

Esta función particiona el grupo asociado a comm en subgrupos disjuntos, basándose en el tipo especificado por split_type. Cada subgrupo contiene todos los procesos del mismo tipo. Dentro de cada subgrupo, los procesos se ordenan según el valor del argumento key, rompiendo empates según su rango en el grupo anterior. Se crea un nuevo comunicador para cada subgrupo y se devuelve en newcomm. Esta es una llamada colectiva; todos los procesos deben proporcionar el mismo split_type, pero cada proceso tiene permitido proporcionar valores diferentes para key. Una excepción a esta regla es que un proceso puede suministrar el valor de tipo MPI_UNDEFINED, en cuyo caso newcomm devuelve MPI_COMM_NULL.

TIPOS DE DIVISIÓN

MPI_COMM_TYPE_SHARED
Este tipo divide el comunicador en subcomunicadores, cada uno de los cuales puede crear una región de memoria compartida.
OMPI_COMM_TYPE_NODE
Sinónimo de MPI_COMM_TYPE_SHARED.
OMPI_COMM_TYPE_HWTHREAD
Este tipo divide el comunicador en subcomunicadores, cada uno de los cuales pertenece al mismo hilo de hardware.
OMPI_COMM_TYPE_CORE
Este tipo divide el comunicador en subcomunicadores, cada uno de los cuales pertenece al mismo núcleo/unidad de procesamiento.
OMPI_COMM_TYPE_L1CACHE
Este tipo divide el comunicador en subcomunicadores, cada uno de los cuales pertenece a la misma caché L1.
OMPI_COMM_TYPE_L2CACHE
Este tipo divide el comunicador en subcomunicadores, cada uno de los cuales pertenece a la misma caché L2.
OMPI_COMM_TYPE_L3CACHE
Este tipo divide el comunicador en subcomunicadores, cada uno de los cuales pertenece a la misma caché L3.
OMPI_COMM_TYPE_SOCKET
Este tipo divide el comunicador en subcomunicadores, cada uno de los cuales pertenece al mismo zócalo.
OMPI_COMM_TYPE_NUMA
Este tipo divide el comunicador en subcomunicadores, cada uno de los cuales pertenece al mismo nodo NUMA.
OMPI_COMM_TYPE_BOARD
Este tipo divide el comunicador en subcomunicadores, cada uno de los cuales pertenece a la misma placa.
OMPI_COMM_TYPE_HOST
Este tipo divide el comunicador en subcomunicadores, cada uno de los cuales pertenece al mismo host.
OMPI_COMM_TYPE_CU
Este tipo divide el comunicador en subcomunicadores, cada uno de los cuales pertenece a la misma unidad computacional.
OMPI_COMM_TYPE_CLUSTER
Este tipo divide el comunicador en subcomunicadores, cada uno de los cuales pertenece al mismo clúster.

NOTAS

Las claves de comunicador que se indican con el prefijo OMPI_ en lugar de MPI_ son específicas de Open MPI y no forman parte del estándar MPI. Su uso debe protegerse con la macro del preprocesador C OPEN_MPI.

ERRORES

Casi todas las rutinas MPI devuelven un valor de error; las rutinas en C como resultado de la función y las rutinas en Fortran en el último argumento.

Antes de que se devuelva el valor de error, se llama al manejador de errores MPI actual asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo). Si no hay ningún objeto de comunicación asociado con la llamada MPI, entonces la llamada se considera adjunta a MPI_COMM_SELF y llamará al manejador de errores MPI asociado. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se utiliza exclusivamente el Modelo de Sesiones) el error eleva el manejador de errores inicial. El manejador de errores inicial se puede cambiar llamando a MPI_Comm_set_errhandler en MPI_COMM_SELF cuando se utiliza el modelo World, o el argumento de CLI mpi_initial_errhandler a mpiexec o la clave de información a MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no se ha establecido ningún otro manejador de errores apropiado, entonces se llama al manejador de errores MPI_ERRORS_RETURN para las funciones de E/S de MPI y al manejador de errores MPI_ERRORS_ABORT para todas las demás funciones de MPI.

Open MPI incluye tres manejadores de errores predefinidos que se pueden utilizar:

  • MPI_ERRORS_ARE_FATAL Provoca que el programa aborte todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT Un manejador de errores que se puede invocar en un comunicador, ventana, archivo o sesión. Cuando se llama en un comunicador, actúa como si se hubiera llamado a MPI_Abort en ese comunicador. Si se llama en una ventana o archivo, actúa como si se hubiera llamado a MPI_Abort en un comunicador que contiene el grupo de procesos en la ventana o archivo correspondiente. Si se llama en una sesión, solo aborta el proceso local.
  • MPI_ERRORS_RETURN Devuelve un código de error a la aplicación.

Las aplicaciones MPI también pueden implementar sus propios manejadores de errores llamando a:

  • MPI_Comm_create_errhandler luego MPI_Comm_set_errhandler
  • MPI_File_create_errhandler luego MPI_File_set_errhandler
  • MPI_Session_create_errhandler luego MPI_Session_set_errhandler o en MPI_Session_init
  • MPI_Win_create_errhandler luego MPI_Win_set_errhandler

Tenga en cuenta que MPI no garantiza que un programa MPI pueda continuar después de un error.

Consulte la página del manual de MPI para ver una lista completa de códigos de error de MPI.

Consulte la sección de Manejo de Errores del estándar MPI-3.1 para obtener más información.

DESCRIPTION

La rutina MPI_Comm_split_type divide el comunicador de entrada comm en varios comunicadores nuevos. Los procesos que reciben el mismo valor de clave en el nuevo comunicador pertenecerán al mismo nuevo comunicador. El orden de los procesos dentro de cada nuevo comunicador está determinado por el orden de los procesos en el comunicador de entrada.

El parámetro split_type determina cómo se agrupan los procesos. Los valores posibles para split_type son:

SPLIT TYPES

MPI_COMM_TYPE_SHARED
Los procesos que comparten el mismo espacio de memoria se agrupan juntos.
MPI_COMM_TYPE_NESTED
Los procesos que pertenecen al mismo nivel de anidamiento de comunicadores se agrupan juntos.
MPI_COMM_TYPE_HOST
Los procesos que se ejecutan en el mismo host físico se agrupan juntos.
MPI_COMM_TYPE_LOCAL
Los procesos que se ejecutan en el mismo nodo de procesamiento local se agrupan juntos. Esto es similar a MPI_COMM_TYPE_HOST pero puede ser más granular en algunos sistemas.

Si un proceso no pertenece a ningún grupo del tipo de división especificado, el nuevo comunicador devuelto para ese proceso será MPI_COMM_NULL.

NOTES

La rutina MPI_Comm_split_type es una extensión de la primitiva MPI_Comm_split y proporciona una forma más flexible de dividir comunicadores basada en propiedades del sistema o de la ejecución.

El parámetro info está obsoleto y se recomienda que se establezca en MPI_INFO_NULL.

ERRORS

Cuando ocurre un error, los procedimientos MPI pueden devolver un código de error en el último parámetro (si se proporciona). Si el código de retorno no se proporciona, se toma la acción predeterminada, que suele ser la terminación del programa.

El código de retorno MPI_SUCCESS indica éxito. Los códigos de retorno posteriores son indicativos de errores.
