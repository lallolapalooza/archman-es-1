PARAMETROS DE ENTRADA

  • sendbuf: Dirección de inicio del buffer de envío.
  • sendcounts: Array de enteros, donde el elemento i especifica el número de elementos a enviar al rango i.
  • sdispls: Array de enteros, donde el elemento i especifica el desplazamiento (offset desde sendbuf, en unidades de sendtype) para enviar datos al rango i.
  • sendtype: Tipo de datos de los elementos del buffer de envío.
  • recvcounts: Array de enteros, donde el elemento j especifica el número de elementos a recibir del rango j.
  • rdispls: Array de enteros, donde el elemento j especifica el desplazamiento (offset desde recvbuf, en unidades de recvtype) a donde se deben escribir los datos del rango j.
  • recvtype: Tipo de datos de los elementos del buffer de recepción.
  • comm: Comunicador sobre el cual se realiza el intercambio de datos.
  • info: Información (handle, solo persistente).

PARAMETROS DE SALIDA

  • recvbuf: Dirección del buffer de recepción.
  • request: Solicitud (handle, no bloqueante).
  • ierror: Solo en Fortran: Código de error.

DESCRIPCION

MPI_Alltoallv es una operación colectiva generalizada en la cual todos los procesos envían datos a y reciben datos de todos los otros procesos. Permite una flexibilidad adicional a MPI_Alltoall al permitir al usuario especificar datos a enviar y recibir en forma vectorial (a través de un desplazamiento y un contador de elementos). La operación de esta rutina puede pensarse así, donde cada proceso realiza 2n (n siendo el número de procesos en el comunicador comm) comunicaciones punto a punto independientes (incluyendo comunicación consigo mismo).

MPI_Comm_size(comm, &n);
for (i = 0, i < n; i++)
    MPI_Send(sendbuf + sdispls[i] * extent(sendtype),
        sendcounts[i], sendtype, i, ..., comm);
for (i = 0, i < n; i++)
    MPI_Recv(recvbuf + rdispls[i] * extent(recvtype),
        recvcounts[i], recvtype, i, ..., comm);

El proceso j envía el bloque k de su propio sendbuf al proceso k, que coloca los datos en el bloque j de su propio recvbuf.

Cuando un par de procesos intercambian datos, cada uno puede pasar diferentes argumentos de contador y tipos de datos, siempre que el emisor especifique el mismo número de bytes a enviar que el receptor espera recibir.

Nota: El proceso i puede enviar un número diferente de datos al proceso j del que recibe del proceso j. Además, un proceso puede enviar diferentes cantidades de datos a distintos procesos en el comunicador.

CUANDO EL COMUNICADOR ES UN INTERCOMUNICADOR

Cuando el comunicador es un intercomunicador, la operación de recolección ocurre en dos fases. Los datos se recolectan de todos los miembros del primer grupo y se reciben por todos los miembros del segundo grupo. Luego, los datos se recolectan de todos los miembros del segundo grupo y se reciben por todos los miembros del primer. La operación presenta un comportamiento simétrico, de doble dirección.

El primer grupo define el proceso raíz. El proceso raíz usa MPI_ROOT como valor de root. Todos los demás procesos del primer grupo usan MPI_PROC_NULL como valor de root. Todos los procesos del segundo grupo usan el número de rango del proceso raíz en el primer grupo como valor de root.

Cuando el comunicador es un intracomunicador, estos grupos son los mismos y la operación ocurre en una sola fase.

USO DE LA OPCION EN-SITIO

Cuando el comunicador es un intracomunicador, se puede realizar una operación "all-to-all" en su lugar (el buffer de salida se usa como el buffer de entrada). Use el valor MPI_IN_PLACE como valor de sendbuf. En este caso, sendcounts, sdispls y sendtype son ignorados. Se asume que los datos de entrada de cada proceso están en el área donde ese proceso recibirá su propia contribución al buffer de recepción.

NOTAS

Los especificadores de conteo y desplazamiento no deben hacer que ningún lugar se escriba más de una vez.

Todos los argumentos en todos los procesos son significativos. El argumento comm, en particular, debe describir el mismo comunicador en todos los procesos.

Los desplazamientos de sdispls y rdispls se miden en unidades de sendtype y recvtype, respectivamente. Compare esto con MPI_Alltoallw, donde estos desplazamientos se miden en bytes.

ERRORES

Antes de devolver el valor de error, se llama al manejador de errores MPI actual asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo). Si no hay ningún objeto de comunicación asociado con la llamada MPI, la llamada se considera adjunta a MPI_COMM_SELF y llamará al manejador de errores MPI asociado. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se usa exclusivamente el Modelo de Sesiones) el error activa el manejador de errores inicial. El manejador de errores inicial se puede cambiar llamando a MPI_Comm_set_errhandler en MPI_COMM_SELF cuando se usa el modelo World, o el argumento de línea de comandos mpi_initial_errhandler para mpiexec o la clave info para MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no se ha establecido ningún otro manejador de errores apropiado, se llama al manejador de errores MPI_ERRORS_RETURN para las funciones de E/S de MPI y al manejador de errores MPI_ERRORS_ABORT para todas las demás funciones de MPI.

Open MPI incluye tres manejadores de errores predefinidos que se pueden usar:

  • MPI_ERRORS_ARE_FATAL Hace que el programa aborte todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT Un manejador de errores que se puede invocar en un comunicador, ventana, archivo o sesión. Cuando se llama en un comunicador, actúa como si se hubiera llamado a MPI_Abort en ese comunicador. Si se llama en una ventana o archivo, actúa como si se hubiera llamado a MPI_Abort en un comunicador que contiene el grupo de procesos del correspondiente ventana o archivo. Si se llama en una sesión, aborta solo el proceso local.
  • MPI_ERRORS_RETURN Devuelve un código de error a la aplicación.

Las aplicaciones MPI también pueden implementar sus propios manejadores de errores llamando a:

  • MPI_Comm_create_errhandler luego MPI_Comm_set_errhandler
  • MPI_File_create_errhandler luego MPI_File_set_errhandler
  • MPI_Session_create_errhandler luego MPI_Session_set_errhandler o en MPI_Session_init
  • MPI_Win_create_errhandler luego MPI_Win_set_errhandler

Tenga en cuenta que MPI no garantiza que un programa MPI pueda continuar después de un error.

Consulte la página man de MPI para obtener una lista completa de los códigos de error de MPI.

Consulte la sección Manejo de Errores del estándar MPI-3.1 para más información.
