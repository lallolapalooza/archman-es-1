MPI_Ibcast(3)

Paquete: openmpi

Licencias: BSD-3-Clause AND LicenseRef-MPICH

MPI_IBCAST(3) Open MPI MPI_IBCAST(3)

MPI_Bcast, MPI_Ibcast - Envía un mensaje desde el proceso con rank root a todos los demás procesos del grupo.

SINTAXIS

Sintaxis C

#include <mpi.h>
int MPI_Bcast(void *buffer, int count, MPI_Datatype datatype,
    int root, MPI_Comm comm)
int MPI_Ibcast(void *buffer, int count, MPI_Datatype datatype,
    int root, MPI_Comm comm, MPI_Request *request)

Sintaxis Fortran

USE MPI
! ojo: la forma antigua: INCLUDE 'mpif.h'
MPI_BCAST(BUFFER, COUNT, DATATYPE, ROOT, COMM, IERROR)
    TYPE(*), DIMENSION(..) :: BUFFER
    INTEGER COUNT, DATATYPE, ROOT, COMM, IERROR
MPI_IBCAST(BUFFER, COUNT, DATATYPE, ROOT, COMM, REQUEST, IERROR)
    TYPE(*), DIMENSION(..), ASYNCHRONOUS :: BUFFER
    INTEGER COUNT, DATATYPE, ROOT, COMM, REQUEST, IERROR

Sintaxis Fortran 2008

USE mpi_f08
MPI_Bcast(buffer, count, datatype, root, comm, ierror)
    TYPE(*), DIMENSION(..) :: buffer
    INTEGER, INTENT(IN) :: count, root
    TYPE(MPI_Datatype), INTENT(IN) :: datatype
    TYPE(MPI_Comm), INTENT(IN) :: comm
    INTEGER, OPTIONAL, INTENT(OUT) :: ierror
MPI_Ibcast(buffer, count, datatype, root, comm, request, ierror)
    TYPE(*), DIMENSION(..), ASYNCHRONOUS :: buffer
    INTEGER, INTENT(IN) :: count, root
    TYPE(MPI_Datatype), INTENT(IN) :: datatype
    TYPE(MPI_Comm), INTENT(IN) :: comm
    TYPE(MPI_Request), INTENT(OUT) :: request
    INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARÁMETROS DE ENTRADA/SALIDA

  • buffer: Dirección de inicio del buffer (opcional).
  • count: Número de entradas en el buffer (entero).
  • datatype: Tipo de datos del buffer (identificador).
  • root: Rango del proceso emisor (entero).
  • comm: Comunicador (identificador).

PARÁMETROS DE SALIDA

  • request: Petición (identificador, no bloqueante).
  • ierror: Solo en Fortran: Estado de error (entero).

DESCRIPCIÓN

MPI_Bcast envía un mensaje desde el proceso con rank root a todos los procesos del grupo, incluido él mismo. Todos los miembros del grupo invocan la función con los mismos argumentos para comm y root. Al retornar, el buffer de comunicación de root se ha copiado a todos los procesos.

Se permiten tipos de datos generales y derivados para datatype. La firma del tipo de count en cualquier proceso debe ser igual a la firma del count y datatype en el root. Esto implica que el volumen de datos enviado debe ser igual al volumen recibido, en pares entre cada proceso y el root. MPI_Bcast y todas las demás rutinas de movimiento de datos imponen esta restricción. Los tipos de mapa distintos entre emisor y receptor aún son permitidos.

Ejemplo: Enviar 100 enteros desde el proceso 0 a todos los procesos del grupo.

MPI_Comm comm;
int array[100];
int root=0;
//...
MPI_Bcast( array, 100, MPI_INT, root, comm);

Como en muchos de nuestros fragmentos de código de ejemplo, asumimos que algunas de las variables (como comm en el ejemplo anterior) tienen valores adecuados asignados.

CUANDO EL COMUNICADOR ES UN INTER-COMUNICADOR

Cuando el comunicador es un inter-comunicador, el proceso root del primer grupo envía datos a todos los procesos del segundo grupo. El primer grupo define el proceso root. Este proceso usa MPI_ROOT como valor de su argumento root. Los demás procesos usan MPI_PROC_NULL como valor de su argumento root. Todos los procesos del segundo grupo usan el rango del root del primer grupo como valor de su argumento root. Los argumentos de buffer de recepción de los procesos del segundo grupo deben ser consistentes con los argumentos de buffer de envío del proceso root del primer grupo.

NOTAS

Esta función no soporta la opción 'en lugar de sí'.

ERRORES

La mayoría de las rutinas MPI devuelven un valor de error; en C, el resultado de la función; en Fortran, en el último argumento.

Antes de devolver el valor de error, se invoca el manejador de error asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo) actual. Si no hay ningún objeto de comunicación asociado con la llamada MPI, se considera que la llamada está asociada a MPI_COMM_SELF y se invoca el manejador de error correspondiente. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se usa el Modelo de Sesiones exclusivamente), el error desencadena el manejador de error inicial. El manejador de error inicial puede cambiarse llamando a MPI_Comm_set_errhandler sobre MPI_COMM_SELF cuando se use el Modelo del Mundo, o el parámetro mpi_initial_errhandler de mpiexec o la clave info de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no hay otro manejador adecuado establecido, se invoca el manejador de error MPI_ERRORS_RETURN para las funciones de I/O MPI y el manejador de error MPI_ERRORS_ABORT para otras funciones MPI.

Open MPI incluye tres manejadores de error predefinidos que pueden ser utilizados:

  • MPI_ERRORS_ARE_FATAL hace que el programa aborte todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT un manejador de error que puede ser invocado en un comunicador, ventana, archivo o sesión. Cuando se invoca en un comunicador, actúa como si se hubiera llamado MPI_Abort en ese comunicador. Si se invoca en una ventana o archivo, actúa como si se hubiera llamado MPI_Abort en un comunicador que contiene el grupo de procesos en la ventana o archivo correspondiente. Si se invoca en una sesión, aborta solo el proceso local.
  • MPI_ERRORS_RETURN devuelve un código de error a la aplicación.

Las aplicaciones MPI también pueden implementar sus propios manejadores de error llamando:

  • MPI_Comm_create_errhandler y luego MPI_Comm_set_errhandler
  • MPI_File_create_errhandler y luego MPI_File_set_errhandler
  • MPI_Session_create_errhandler y luego MPI_Session_set_errhandler o en MPI_Session_init
  • MPI_Win_create_errhandler y luego MPI_Win_set_errhandler

Nota: MPI no garantiza que un programa MPI pueda continuar después de un error.

Ver la página del manual de MPI para una lista completa de códigos de error MPI.

Ver la sección de manejo de errores del estándar MPI-3.1 para más información.
