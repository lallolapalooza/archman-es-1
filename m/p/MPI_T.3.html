Interfaz MPI_T de Open MPI - Información general

DESCRIPCIÓN

Hay algunas notas específicas de Open MPI sobre su implementación de la interfaz MPI_T que vale la pena mencionar.

VARIABLES DE CONTROL MPI_T

La implementación de Open MPI de las APIs de Variables de Control MPI_T (denominadas "cvar") es una interfaz a los parámetros/variables subyacentes de la Arquitectura de Componentes Modulares (MCA) de Open MPI. Dicho de forma sencilla: usar la interfaz cvar de MPI_T es otro mecanismo para obtener/establecer parámetros MCA de Open MPI.

En orden de precedencia (de mayor a menor), Open MPI proporciona los siguientes mecanismos para establecer parámetros MCA:

1.
La interfaz MPI_T tiene la mayor precedencia. Específicamente: los valores establecidos a través de la interfaz MPI_T anularán todas las demás configuraciones.
2.
La línea de comandos de mpirun(1) / mpiexec(1) (por ejemplo, a través del parámetro –mca).
3.
Variables de entorno.
4.
Los archivos de parámetros tienen la menor precedencia. Específicamente: los valores establecidos a través de archivos de parámetros pueden ser anulados por cualquiera de los otros mecanismos de configuración de variables MCA.

INICIALIZACIÓN MPI

Una aplicación puede usar la interfaz MPI_T antes de que MPI esté inicializado para establecer parámetros MCA. Establecer parámetros MCA a nivel de MPI antes de que MPI esté inicializado puede afectar a *cómo* se inicializa MPI (por ejemplo, influyendo en qué frameworks y componentes se seleccionan).

El siguiente ejemplo establece los parámetros MCA pml y btl antes de invocar MPI_Init para forzar una selección específica de componentes PML y BTL:

int provided, index, count;
MPI_T_cvar_handle pml_handle, btl_handle;
char pml_value[64], btl_value[64];
MPI_T_init_thread(MPI_THREAD_SINGLE, &provided);
MPI_T_cvar_get_index("pml", &index);
MPI_T_cvar_handle_alloc(index, NULL, &pml_handle, &count);
MPI_T_cvar_write(pml_handle, "ob1");
MPI_T_cvar_get_index("btl", &index);
MPI_T_cvar_handle_alloc(index, NULL, &btl_handle, &count);
MPI_T_cvar_write(btl_handle, "tcp,vader,self");
MPI_T_cvar_read(pml_handle, pml_value);
MPI_T_cvar_read(btl_handle, btl_value);
printf("Valor establecido de los cvars: PML: %s, BTL: %s\n",
       pml_value, btl_value);
MPI_T_cvar_handle_free(&pml_handle);
MPI_T_cvar_handle_free(&btl_handle);
MPI_Init(NULL, NULL);
// ...
MPI_Finalize();
MPI_T_finalize();

Tenga en cuenta que una vez que MPI está inicializado, la mayoría de los cvars de Open MPI se vuelven de solo lectura.

Por ejemplo, una vez que MPI está inicializado, ya no es posible establecer los mecanismos de selección PML y BTL. Esto se debe a que muchos de estos parámetros MCA solo se utilizan durante la inicialización de MPI; establecerlos después de que MPI ya se haya inicializado sería inútil, de todos modos.

CATEGORÍAS MPI_T

Las categorías MPI_T de Open MPI están organizadas jerárquicamente:

1.
Capa (o "proyecto"). Hay dos capas en Open MPI:
  • ompi: Esta capa contiene cvars, pvats y subcategorías relacionadas con las características de MPI.
  • opal: Esta capa generalmente contiene cvars, pvats y subcategorías de construcciones de capa inferior, como problemas del sistema operativo, problemas de red, etc.
2.
Framework o sección.
•
En la mayoría de los casos, el siguiente nivel en la jerarquía es el framework MCA de Open MPI.
  • Por ejemplo, puede encontrar el framework btl bajo la capa opal (porque tiene que ver con la red subyacente).
  • Además, el framework pml está bajo la capa ompi (porque tiene que ver con la semántica de los mensajes punto a punto de MPI).
•
Sin embargo, hay algunas entidades no frameworks MCA bajo la capa.
•
Por ejemplo, hay una sección mpi bajo las capas opal y ompi para construcciones generales/centrales de MPI.
3.
Componente.
  • Si es relevante, el tercer nivel de la jerarquía es el componente MCA.
  • Por ejemplo, el componente tcp se puede encontrar bajo el framework opal en la capa opal.
