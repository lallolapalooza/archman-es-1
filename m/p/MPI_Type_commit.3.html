MPI_TYPE_COMMIT(3) Open MPI MPI_TYPE_COMMIT(3)

MPI_Type_commit — Comprometir un tipo de datos.

SINTAXIS

Sintaxis C

#include <mpi.h>
int MPI_Type_commit(MPI_Datatype *datatype)

Sintaxis Fortran

USE MPI
! o la forma antigua: INCLUDE 'mpif.h'
MPI_TYPE_COMMIT(DATATYPE, IERROR)
     INTEGER DATATYPE, IERROR

Sintaxis Fortran 2008

USE mpi_f08
MPI_Type_commit(datatype, ierror)
     TYPE(MPI_Datatype), INTENT(INOUT) :: datatype
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARÁMETRO DE ENTRADA

•
datatype: Tipo de datos (manejador).

PARÁMETRO DE SALIDA

•
ierror: Solo Fortran: Estado de error (entero).

DESCRIPCIÓN

La operación de compromiso compromete el tipo de datos. Un tipo de datos es la descripción formal de un búfer de comunicación, no el contenido de ese búfer. Una vez que un tipo de datos ha sido comprometido, puede ser reutilizado repetidamente para comunicar el contenido cambiante de un búfer o, de hecho, el contenido de diferentes búferes, con direcciones de inicio diferentes.

Ejemplo: El siguiente fragmento de código Fortran ofrece ejemplos de uso de MPI_Type_commit.

INTEGER :: type1, type2
CALL MPI_TYPE_CONTIGUOUS(5, MPI_REAL, type1, ierr)
              ! se crea un nuevo objeto de tipo
CALL MPI_TYPE_COMMIT(type1, ierr)
              ! ahora type1 se puede usar para la comunicación

Si el tipo de datos especificado en datatype ya está comprometido, es equivalente a una operación nula.

ERRORES

Casi todas las rutinas de MPI devuelven un valor de error; las rutinas C como resultado de la función y las rutinas Fortran en el último argumento.

Antes de que se devuelva el valor de error, se llama al controlador de errores de MPI actual asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo). Si no hay ningún objeto de comunicación asociado con la llamada MPI, entonces la llamada se considera adjunta a MPI_COMM_SELF y llamará al controlador de errores de MPI asociado. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se utiliza exclusivamente el Modelo de Sesiones) el error eleva el controlador de errores inicial. El controlador de errores inicial se puede cambiar llamando a MPI_Comm_set_errhandler en MPI_COMM_SELF cuando se usa el modelo World, o el argumento de línea de comandos mpi_initial_errhandler de mpiexec o la clave info de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no se ha configurado ningún otro controlador de errores apropiado, se llama al controlador de errores MPI_ERRORS_RETURN para las funciones de E/S de MPI y se llama al controlador de errores MPI_ERRORS_ABORT para todas las demás funciones de MPI.

Open MPI incluye tres controladores de errores predefinidos que se pueden utilizar:

  • MPI_ERRORS_ARE_FATAL Provoca que el programa termine todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT Un controlador de errores que se puede invocar en un comunicador, ventana, archivo o sesión. Cuando se llama en un comunicador, actúa como si se hubiera llamado a MPI_Abort en ese comunicador. Si se llama en una ventana o archivo, actúa como si se hubiera llamado a MPI_Abort en un comunicador que contiene el grupo de procesos en la ventana o archivo correspondiente. Si se llama en una sesión, termina solo el proceso local.
  • MPI_ERRORS_RETURN Devuelve un código de error a la aplicación.

Las aplicaciones MPI también pueden implementar sus propios controladores de errores llamando a:

  • MPI_Comm_create_errhandler luego MPI_Comm_set_errhandler
  • MPI_File_create_errhandler luego MPI_File_set_errhandler
  • MPI_Session_create_errhandler luego MPI_Session_set_errhandler o en MPI_Session_init
  • MPI_Win_create_errhandler luego MPI_Win_set_errhandler

Tenga en cuenta que MPI no garantiza que un programa MPI pueda continuar después de un error.

Consulte la página del manual de MPI para obtener una lista completa de los códigos de error de MPI.

Consulte la sección de Manejo de Errores del estándar MPI-3.1 para obtener más información.
