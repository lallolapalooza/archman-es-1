MPI_COMM_SET_INFO(3) Open MPI MPI_COMM_SET_INFO(3)

MPI_Comm_set_info — Establece sugerencias de información de comunicador

SINTAXIS

Sintaxis C

#include <mpi.h>
int MPI_Comm_set_info(MPI_Comm comm, MPI_Info info)

Sintaxis Fortran

USE MPI
! o la forma antigua: INCLUDE 'mpif.h'
MPI_COMM_SET_INFO(COMM, INFO, IERROR)
     INTEGER COMM, INFO, IERROR

Sintaxis Fortran 2008

USE mpi_f08
MPI_Comm_set_info(comm, info, ierror)
     TYPE(MPI_Comm), INTENT(IN) :: comm
     TYPE(MPI_Info), INTENT(IN) :: info
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARÁMETROS DE ENTRADA

  • comm: Comunicador en el que establecer las sugerencias de información.
  • info: Objeto de información que contiene las sugerencias que se establecerán en comm.

PARÁMETROS DE SALIDA

•
ierror: Solo Fortran: estado de error (entero).

DESCRIPCIÓN

MPI_Comm_set_info establece nuevos valores para las sugerencias del comunicador asociado con comm. MPI_Comm_set_info es una rutina colectiva. El objeto de información puede ser diferente en cada proceso, pero cualquier entrada de información que una implementación requiera que sea igual en todos los procesos debe aparecer con el mismo valor en el objeto info de cada proceso.

Las siguientes afirmaciones de clave de información pueden ser aceptadas por Open MPI:

mpi_assert_no_any_tag (booleano): Si se establece en verdadero, la implementación puede asumir que el proceso no usará el comodín MPI_ANY_TAG en el comunicador dado.

mpi_assert_no_any_source (booleano): Si se establece en verdadero, la implementación puede asumir que el proceso no usará el comodín MPI_ANY_SOURCE en el comunicador dado.

mpi_assert_exact_length (booleano): Si se establece en verdadero, la implementación puede asumir que las longitudes de los mensajes recibidos por el proceso son iguales a las longitudes de los búferes de recepción correspondientes, para operaciones de comunicación punto a punto en el comunicador dado.

mpi_assert_allow_overtaking (booleano): Si se establece en verdadero, la implementación puede asumir que las comunicaciones punto a punto en el comunicador dado no dependen de la regla de no adelantamiento especificada en MPI-3.1 Sección 3.5. En otras palabras, la aplicación afirma que las operaciones de envío no requieren ser emparejadas en el receptor en el orden en que se realizaron las operaciones de envío por el emisor, y las operaciones de recepción no requieren ser emparejadas en el orden en que se realizaron por el receptor.

ERRORES

Casi todas las rutinas de MPI devuelven un valor de error; las rutinas C como resultado de la función y las rutinas Fortran en el último argumento.

Antes de que se devuelva el valor de error, se llama al controlador de error MPI actual asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo). Si no hay ningún objeto de comunicación asociado con la llamada MPI, la llamada se considera adjunta a MPI_COMM_SELF y llamará al controlador de error MPI asociado. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se usa exclusivamente el Modelo de Sesiones), el error eleva el controlador de error inicial. El controlador de error inicial se puede cambiar llamando a MPI_Comm_set_errhandler en MPI_COMM_SELF cuando se usa el modelo World, o el argumento de línea de comandos mpiexec mpi_initial_errhandler o la clave de información para MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no se ha establecido ningún otro controlador de error apropiado, entonces se llama al controlador de error MPI_ERRORS_RETURN para las funciones de E/S de MPI y al controlador de error MPI_ERRORS_ABORT para todas las demás funciones de MPI.

Open MPI incluye tres controladores de error predefinidos que se pueden usar:

  • MPI_ERRORS_ARE_FATAL Provoca que el programa aborte todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT Un controlador de errores que puede ser invocado en un comunicador, ventana, archivo o sesión. Cuando se llama en un comunicador, actúa como si se hubiera llamado a MPI_Abort en ese comunicador. Si se llama en una ventana o archivo, actúa como si se hubiera llamado a MPI_Abort en un comunicador que contiene el grupo de procesos en la ventana o archivo correspondiente. Si se llama en una sesión, aborta solo el proceso local.
  • MPI_ERRORS_RETURN Devuelve un código de error a la aplicación.

Las aplicaciones MPI también pueden implementar sus propios controladores de error llamando a:

  • MPI_Comm_create_errhandler luego MPI_Comm_set_errhandler
  • MPI_File_create_errhandler luego MPI_File_set_errhandler
  • MPI_Session_create_errhandler luego MPI_Session_set_errhandler o en MPI_Session_init
  • MPI_Win_create_errhandler luego MPI_Win_set_errhandler

Tenga en cuenta que MPI no garantiza que un programa MPI pueda continuar después de un error.

Consulte la página del manual de MPI para obtener una lista completa de los códigos de error de MPI.

Consulte la sección de Manejo de Errores del estándar MPI-3.1 para obtener más información.
