PARÁMETROS DE ENTRADA

  • sendbuf: Dirección de inicio del búfer de envío (elección).
  • sendcount: Número de elementos en el búfer de envío (entero).
  • sendtype: Tipo de datos de los elementos del búfer de envío (manejador).
  • recvbuf: Dirección de inicio del búfer de recepción (elección).
  • recvcount: Número de elementos recibidos de cualquier proceso (entero).
  • recvtype: Tipo de datos de los elementos del búfer de recepción (manejador).
  • comm: Comunicador (manejador).

PARÁMETROS DE SALIDA

  • recvbuf: Dirección del búfer de recepción (elección).
  • request: Solicitud (manejador, solo no bloqueante).
  • ierror: Solo Fortran: Estado de error (entero).

DESCRIPCIÓN

MPI_Neighbor_allgather es similar a MPI_Allgather, excepto que solo los procesos vecinos reciben el resultado, en lugar de todos los procesos. Los vecinos y la disposición del búfer se determinan mediante la topología de comm.

La firma de tipo asociada con sendcount, sendtype en un proceso debe ser igual a la firma de tipo asociada con recvcount, recvtype en cualquier otro proceso.

ORDEN DE VECINOS

Para una topología de grafo distribuido, creada con MPI_Dist_graph_create, la secuencia de vecinos en los búferes de envío y recepción en cada proceso se define como la secuencia devuelta por MPI_Dist_graph_neighbors para destinos y fuentes, respectivamente. Para una topología de grafo general, creada con MPI_Graph_create, el orden de los vecinos en los búferes de envío y recepción se define como la secuencia de vecinos tal como la devuelve MPI_Graph_neighbors. Tenga en cuenta que las topologías de grafo generales generalmente deben ser reemplazadas por las topologías de grafo distribuidas.

Para una topología cartesiana, creada con MPI_Cart_create, la secuencia de vecinos en los búferes de envío y recepción en cada proceso se define por el orden de las dimensiones, primero el vecino en la dirección negativa y luego en la dirección positiva con desplazamiento 1. Los números de fuentes y destinos en las rutinas de comunicación son 2*ndims con ndims definido en MPI_Cart_create. Si un vecino no existe, es decir, en el borde de una topología cartesiana en el caso de una dimensión de cuadrícula virtual no periódica (es decir, periods[…]==false), entonces este vecino se define como MPI_PROC_NULL.

Si un vecino en cualquiera de las funciones es MPI_PROC_NULL, entonces la comunicación colectiva de vecindario se comporta como una comunicación punto a punto con MPI_PROC_NULL en esa dirección. Es decir, el búfer sigue siendo parte de la secuencia de vecinos, pero ni se comunica ni se actualiza.

NOTAS

La opción MPI_IN_PLACE para sendbuf no tiene sentido para esta operación.

ERRORES

Casi todas las rutinas MPI devuelven un valor de error; las rutinas C como resultado de la función y las rutinas Fortran en el último argumento.

Antes de que se devuelva el valor de error, se llama al manejador de errores MPI actual asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo). Si no hay ningún objeto de comunicación asociado con la llamada MPI, entonces la llamada se considera adjunta a MPI_COMM_SELF y llamará al manejador de errores MPI asociado. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se usa exclusivamente el Modelo de Sesiones) el error eleva el manejador de errores inicial. El manejador de errores inicial se puede cambiar llamando a MPI_Comm_set_errhandler en MPI_COMM_SELF cuando se utiliza el modelo World, o el argumento de CLI mpi_initial_errhandler para mpiexec o la clave info para MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no se ha establecido ningún otro manejador de errores apropiado, entonces se llama al manejador de errores MPI_ERRORS_RETURN para las funciones de E/S MPI y al manejador de errores MPI_ERRORS_ABORT para todas las demás funciones MPI.

Open MPI incluye tres manejadores de errores predefinidos que se pueden utilizar:

  • MPI_ERRORS_ARE_FATAL Provoca que el programa aborte todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT Un manejador de errores que puede invocarse en un comunicador, ventana, archivo o sesión. Cuando se llama en un comunicador, actúa como si se hubiera llamado a MPI_Abort en ese comunicador. Si se llama en una ventana o archivo, actúa como si se hubiera llamado a MPI_Abort en un comunicador que contiene el grupo de procesos en la ventana o archivo correspondiente. Si se llama en una sesión, solo aborta el proceso local.
  • MPI_ERRORS_RETURN Devuelve un código de error a la aplicación.

Las aplicaciones MPI también pueden implementar sus propios manejadores de errores llamando a:

  • MPI_Comm_create_errhandler luego MPI_Comm_set_errhandler
  • MPI_File_create_errhandler luego MPI_File_set_errhandler
  • MPI_Session_c
