MPI_Alltoallw, MPI_Ialltoallw, MPI_Alltoallw_init — Todos los procesos envían datos de diferentes tipos a, y reciben datos de diferentes tipos de, todos los procesos.

Parámetros de entrada

  • sendbuf: Dirección del buffer de envío.
  • sendcounts: Array de enteros, donde el elemento i especifica el número de elementos a enviar al proceso i.
  • sdispls: Array de enteros, donde el elemento i especifica el desplazamiento (en bytes, desplazamiento desde sendbuf) para enviar datos al proceso i.
  • sendtypes: Array de tipos de datos, donde el elemento i especifica el tipo de datos a usar al enviar datos al proceso i.
  • recvcounts: Array de enteros, donde el elemento j especifica el número de elementos a recibir del proceso j.
  • rdispls: Array de enteros, donde el elemento j especifica el desplazamiento (en bytes, desplazamiento desde recvbuf) a donde los datos del proceso j deberían ser escritos.
  • recvtypes: Array de tipos de datos, donde el elemento j especifica el tipo de datos a usar al recibir datos del proceso j.
  • comm: Comunicador sobre el cual se realizarán los intercambios de datos.
  • info: Información (handle, solo persistente)

Parámetros de salida

  • recvbuf: Dirección del buffer de recepción.
  • request: Solicitante (handle, no bloqueado).
  • ierror: Solo en Fortran: Estado de error.

Descripción

MPI_Alltoallw es una operación colectiva generalizada en la que todos los procesos envían datos a y reciben datos de todos los otros procesos. Permite la especificación de tipos de datos individuales de bloques de datos (más allá de desplazamiento y cantidad de elementos) para el usuario. Su operación puede pensarse así, donde cada proceso realiza 2n (n siendo el número de procesos en el comunicador comm) comunicaciones punto a punto independientes (incluyendo comunicación consigo mismo).

MPI_Comm_size(comm, &n);
for (i = 0, i < n; i++)
    MPI_Send(sendbuf + sdispls[i], sendcounts[i],
        sendtypes[i], i, ..., comm);
for (i = 0, i < n; i++)
    MPI_Recv(recvbuf + rdispls[i], recvcounts[i],
        recvtypes[i], i, ..., comm);

El proceso j envía el bloque k de su propio sendbuf al proceso k, lo que coloca los datos en el bloque j de su propio recvbuf.

Cuando un par de procesos intercambian datos, cada uno puede pasar diferentes cantidades de elementos y tipos de datos, siempre que el emisor especifique la misma cantidad de datos (en bytes) que el receptor espera recibir.

Nota: El proceso i puede enviar una cantidad diferente de datos al proceso j que la que recibe del proceso j. También, un proceso puede enviar datos completamente diferentes y de tipos diferentes a diferentes procesos en el comunicador.

CUANDO EL COMUNICADOR ES UN INTER-COMUNICADOR

Cuando el comunicador es un inter-comunicador, la operación colectiva ocurre en dos fases. Los datos se recolectan de todos los miembros del primer grupo y se reciben por todos los miembros del segundo grupo. Luego, los datos se recolectan de todos los miembros del segundo grupo y se reciben por todos los miembros del primer. La operación muestra un comportamiento simétrico y de dupla.

El primer grupo define el proceso raíz. El proceso raíz usa MPI_ROOT como el valor de root. Todos los otros procesos en el grupo de raíz usan MPI_PROC_NULL como el valor de root. Todos los procesos en el segundo grupo usan el número de raíz de este proceso en el grupo de raíz como el valor de root.

Cuando el comunicador es un intra-comunicador, estos grupos son los mismos y la operación ocurre en una sola fase.

Uso de la opción en lugar de sí mismo

Cuando el comunicador es un intra-comunicador, puedes realizar una operación all-to-all en lugar de sí mismo (el buffer de salida se utiliza como el buffer de entrada). Usa la variable MPI_IN_PLACE como el valor de sendbuf. En este caso, sendcounts, sdispls y sendtypes son ignorados. Se asume que los datos de entrada de cada proceso están en el área donde ese proceso recibirá su propia contribución al buffer de recepción.

Notas

La especificación de cantidades, tipos y desplazamientos no debe causar que ningún lugar se escriba más de una vez.

Todos los argumentos en todos los procesos son significativos. El argumento comm, en particular, debe describir el mismo comunicador en todos los procesos.

ERRORES

Casi todas las rutinas MPI devuelven un valor de error; las rutinas C como resultado del retorno de la función y las rutinas Fortran en el último argumento.

Antes de que se devuelva el valor de error, se llama al manejador de errores MPI actual asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo). Si no hay ningún objeto de comunicación asociado con la llamada MPI, entonces la llamada se considera adjunta a MPI_COMM_SELF y llamará al manejador de errores MPI asociado. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se utiliza el Modelo de Sesiones exclusivamente), el error activa el manejador de errores inicial. El manejador de errores inicial se puede cambiar llamando a MPI_Comm_set_errhandler en MPI_COMM_SELF cuando se utiliza el modelo World, o el argumento CLI mpi_initial_errhandler de mpiexec o la clave de información de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no se ha establecido ningún otro manejador de errores apropiado, entonces se llama al manejador de errores MPI_ERRORS_RETURN para las funciones de E/S MPI y al manejador de errores MPI_ERRORS_ABORT para todas las demás funciones MPI.

Open MPI incluye tres manejadores de errores predefinidos que se pueden utilizar:

  • MPI_ERRORS_ARE_FATAL Provoca que el programa aborte todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT Un manejador de errores que se puede invocar en un comunicador, ventana, archivo o sesión. Cuando se llama en un comunicador, actúa como si se hubiera llamado a MPI_Abort en ese comunicador. Si se llama en una ventana o archivo, actúa como si se hubiera llamado a MPI_Abort en un comunicador que contiene el grupo de procesos en la ventana o archivo correspondiente. Si se llama en una sesión, aborta solo el proceso local.
  • MPI_ERRORS_RETURN Devuelve un código de error a la aplicación.

Las aplicaciones MPI también pueden implementar sus propios manejadores de errores llamando a:

  • MPI_Comm_create_errhandler y luego MPI_Comm_set_errhandler
  • MPI_File_create_errhandler y luego MPI_File_set_errhandler
  • MPI_Session_create_errhandler y luego MPI_Session_set_errhandler o en MPI_Session_init
  • MPI_Win_create_errhandler y luego MPI_Win_set_errhandler

Tenga en cuenta que MPI no garantiza que un programa MPI pueda continuar después de un error.

Consulte la página man de MPI para obtener una lista completa de los códigos de error de MPI.

Consulte la sección de Manejo de Errores del estándar MPI-3.1 para obtener más información.
