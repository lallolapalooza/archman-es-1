MPI_COMM_SPLIT(3) Open MPI MPI_COMM_SPLIT(3)

MPI_Comm_split — Crea nuevos comunicadores basados en colores y claves.

SINTAXIS

Sintaxis C

#include <mpi.h>
int MPI_Comm_split(MPI_Comm comm, int color, int key,
     MPI_Comm *newcomm)

Sintaxis Fortran

USE MPI
! o la forma más antigua: INCLUDE 'mpif.h'
MPI_COMM_SPLIT(COMM, COLOR, KEY, NEWCOMM, IERROR)
     INTEGER COMM, COLOR, KEY, NEWCOMM, IERROR

Sintaxis Fortran 2008

USE mpi_f08
MPI_Comm_split(comm, color, key, newcomm, ierror)
     TYPE(MPI_Comm), INTENT(IN) :: comm
     INTEGER, INTENT(IN) :: color, key
     TYPE(MPI_Comm), INTENT(OUT) :: newcomm
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARÁMETROS DE ENTRADA

  • comm: Comunicador (manejador).
  • color: Control de asignación de subconjunto (entero no negativo).
  • key: Control de asignación de rango (entero).

PARÁMETROS DE SALIDA

  • newcomm: Nuevo comunicador (manejador).
  • ierror: Solo Fortran: Estado de error (entero).

DESCRIPCIÓN

Esta función particiona el grupo asociado con comm en subgrupos disjuntos, uno para cada valor de color. Cada subgrupo contiene todos los procesos del mismo color. Dentro de cada subgrupo, los procesos se clasifican en el orden definido por el valor del argumento key, con los empates resueltos de acuerdo con su rango en el grupo anterior. Se crea un nuevo comunicador para cada subgrupo y se devuelve en newcomm. Un proceso puede suministrar el valor de color MPI_UNDEFINED, en cuyo caso newcomm devuelve MPI_COMM_NULL. Esta es una llamada colectiva, pero cada proceso tiene permitido proporcionar diferentes valores para color y key.

Cuando llamas a MPI_Comm_split en un inter-comunicador, los procesos de la izquierda con el mismo color que los de la derecha se combinan para crear un nuevo inter-comunicador. El argumento key describe el rango relativo de los procesos en cada lado del inter-comunicador. La función devuelve MPI_COMM_NULL para aquellos colores que se especifican en un solo lado del inter-comunicador, o para aquellos que especifican MPI_UNDEFINED como color.

Una llamada a MPI_Comm_create(comm, group, newcomm) es equivalente a una llamada a MPI_Comm_split(comm, color,key, newcomm), donde todos los miembros de group proporcionan color = 0 y key = rango en el grupo, y todos los procesos que no son miembros de group proporcionan color = MPI_UNDEFINED. La función MPI_Comm_split permite una partición más general de un grupo en uno o más subgrupos con reordenación opcional.

El valor de color debe ser no negativo o MPI_UNDEFINED.

NOTAS

Este es un mecanismo extremadamente potente para dividir un único grupo de procesos comunicantes en k subgrupos, con k elegido implícitamente por el usuario (por el número de colores afirmados en todos los procesos). Cada comunicador resultante será no superpuesto. Tal división podría ser útil para definir una jerarquía de cálculos, como para multigrid o álgebra lineal.

Se pueden realizar múltiples llamadas a MPI_Comm_split para superar el requisito de que cualquier llamada no tenga superposición de los comunicadores resultantes (cada proceso pertenece a un solo color por llamada). De esta manera, se pueden crear múltiples estructuras de comunicación superpuestas. Se alienta el uso creativo del color y la clave en tales operaciones de división.

Tenga en cuenta que, para un color fijo, las claves no necesitan ser únicas. Es responsabilidad de MPI_Comm_split clasificar los procesos en orden ascendente según esta clave, y resolver los empates de manera consistente. Si todas las claves se especifican de la misma manera, entonces todos los procesos en un color dado tendrán el orden de rango relativo como lo tenían en su grupo padre. (En general, tendrán rangos diferentes).

Esencialmente, hacer que el valor de la clave sea cero para todos los procesos de un color dado significa que uno no necesita prestar atención al orden de rango de los procesos en el nuevo comunicador.

ERRORES

Casi todas las rutinas MPI devuelven un valor de error; las rutinas C como el resultado de la función y las rutinas Fortran en el último argumento.

Antes de que se devuelva el valor de error, se llama al controlador de errores MPI actual asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo). Si no hay ningún objeto de comunicación asociado con la llamada MPI, entonces la llamada se considera adjunta a MPI_COMM_SELF y llamará al controlador de errores MPI asociado. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se utiliza exclusivamente el modelo de sesiones) el error eleva el controlador de errores inicial. El controlador de errores inicial puede cambiarse llamando a MPI_Comm_set_errhandler en MPI_COMM_SELF cuando se utiliza el modelo World, o el argumento de línea de comandos MPI_ERRORS_RETURN a mpiexec o la clave de información para MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no se ha establecido ningún otro controlador de errores apropiado, entonces se llama al controlador de errores MPI_ERRORS_RETURN para las funciones de E/S MPI y al controlador de errores MPI_ERRORS_ABORT para todas las demás funciones MPI.

Open MPI incluye tres controladores de errores predefinidos que se pueden utilizar:

  • MPI_ERRORS_ARE_FATAL Provoca que el programa aborte todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT Un controlador de errores que se puede invocar en un comunicador, ventana, archivo o sesión. Cuando se llama en un comunicador, actúa como si se hubiera llamado a MPI_Abort en ese comunicador. Si se llama en una ventana o archivo, actúa como si se hubiera llamado a MPI_Abort en un comunicador que contiene el grupo de procesos en la ventana o archivo correspondiente. Si se llama en una sesión, aborta solo el proceso local.
  • MPI_ERRORS_RETURN Devuelve un código de error a la aplicación.

Las aplicaciones MPI también pueden implementar sus propios controladores de errores llamando a:

  • MPI_Comm_create_errhandler y luego MPI_Comm_set_errhandler
  • MPI_File_create_errhandler y luego MPI_File_set_errhandler
  • MPI_Session_create_errhandler y luego MPI_Session_set_errhandler o en MPI_Session_init
  • MPI_Win_create_errhandler y luego MPI_Win_set_errhandler

Tenga en cuenta que MPI no garantiza que un programa MPI pueda continuar después de un error.

Consulte la página del manual de MPI para obtener una lista completa de los códigos de error de MPI.

Consulte la sección de Manejo de Errores del estándar MPI-3.1 para obtener más información.
