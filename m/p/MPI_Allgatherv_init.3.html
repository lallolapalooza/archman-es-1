MPI_Allgatherv_init(3) Open MPI MPI_Allgatherv_init(3)

MPI_Allgatherv, MPI_Iallgatherv, MPI_Allgatherv_init - Recogen datos de todos los procesos y los distribuyen a todos los procesos. Cada proceso puede contribuir con una cantidad diferente de datos.

PARÁMETROS DE ENTRADA

  • sendbuf: Dirección de inicio del buffer de envío (opcional).
  • sendcount: Número de elementos en el buffer de envío (entero).
  • sendtype: Tipo de elementos en el buffer de envío (handle).
  • recvcount: Array de enteros (de longitud del grupo) que contiene el número de elementos recibidos de cada proceso.
  • displs: Array de enteros (de longitud del grupo). El elemento i especifica el desplazamiento (relativo a recvbuf) en el que se colocarán los datos entrantes del proceso i.
  • recvtype: Tipo de elementos en el buffer de recepción (handle).
  • comm: Comunicador (handle).
  • info: Información (handle, solo persistente).

PARÁMETROS DE SALIDA

  • recvbuf: Dirección del buffer de recepción (opcional).
  • request: Petición (handle, solo no bloqueante).
  • ierror: Solo en Fortran: Código de error (entero).

DESCRIPCIÓN

MPI_Allgatherv es similar a MPI_Allgather en que todos los procesos reciben datos de todos los otros procesos, excepto que cada proceso puede enviar una cantidad diferente de datos. El bloque de datos enviado desde el proceso j se recibe por todos los procesos y se coloca en el bloque j del buffer recvbuf.

La firma de tipo asociada con sendcount, sendtype en el proceso j debe ser igual a la firma de tipo asociada con recvcounts[j], recvtype en cualquier otro proceso.

El resultado es como si todos los procesos hubieran ejecutado llamadas a

MPI_Allgatherv(sendbuf, sendcount, sendtype, recvbuf, recvcount,
              displs,recvtype,root,comm);
// para root = 0, ..., n-1.

Las reglas para usar correctamente MPI_Allgatherv se encuentran fácilmente a partir de las reglas correspondientes a MPI_Gatherv.

USO DE LA OPCIÓN IN PLACE

Cuando el comunicador es un comunicador intragrupo, puedes realizar una operación de recolección en su lugar (el buffer de salida se utiliza como buffer de entrada). Usa la variable MPI_IN_PLACE como valor de sendbuf. En este caso, sendcount y sendtype se ignoran. Se supone que los datos de entrada de cada proceso se encuentran en el área donde ese proceso recibiría su propia contribución en el buffer de recepción. Específicamente, el resultado de una llamada a MPI_Allgatherv que utilizó la opción in place es igual al caso en que todos los procesos ejecutaron n llamadas a

MPI_Allgatherv ( MPI_IN_PLACE, 0, MPI_DATATYPE_NULL, recvbuf,
                 recvcounts, displs, recvtype, root, comm );
// para root =0, ... , n-1.

Nota: MPI_IN_PLACE es un valor de tipo especial; tiene las mismas restricciones de uso que MPI_BOTTOM.

Dado que la opción in place convierte el buffer de recepción en un buffer de envío y recepción, una vinculación de Fortran que incluya INTENT debe marcar estos como INOUT, no como OUT.

CUANDO EL COMUNICADOR ES UN COMUNICADOR INTERNO

Cuando el comunicador es un comunicador interno, la operación de recolección ocurre en dos fases. Los datos se recogen de todos los miembros del primer grupo, se concatenan y se reciben por todos los miembros del segundo grupo. Luego, los datos se recogen de todos los miembros del segundo grupo, se concatenan y se reciben por todos los miembros del primer grupo. Los argumentos de envío en el primer grupo deben ser consistentes con los argumentos de recepción en el segundo grupo, y viceversa. La operación debe exhibir un comportamiento simétrico y de dúplex completo.

ERRORES

Más del 90% de las rutinas MPI devuelven un valor de error; las rutinas C devuelven el resultado de la función, y las rutinas Fortran en el último argumento.

Antes de que se devuelva el valor de error, se llama al manejador de errores asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo). Si no hay un objeto de comunicación asociado con la llamada MPI, la llamada se considera asociada con MPI_COMM_SELF y se llama al manejador de errores correspondiente. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se utiliza exclusivamente el modelo de Sesiones), el error llama al manejador de errores inicial. El manejador de errores inicial se puede cambiar llamando a MPI_Comm_set_errhandler en MPI_COMM_SELF cuando se utiliza el modelo del Mundo, o mediante el argumento mpi_initial_errhandler de mpiexec o la clave info de MPI_Comm_spawn/MPI_Comm_spawn_multiple. ERRORS

MPI's error handling strategy relies on the use of error handlers. The MPI standard defines specific error handlers that all MPI implementations must support. Open MPI includes these predefined error handlers and provides mechanisms for users to define their own custom error handlers.

Open MPI includes three predefined error handlers that can be used:

  • MPI_ERRORS_ARE_FATAL Causes the program to abort all connected MPI processes.
  • MPI_ERRORS_ABORT An error handler that can be invoked on a communicator, window, file, or session. When called on a communicator, it acts as if MPI_Abort was called on that communicator. If called on a window or file, acts as if MPI_Abort was called on a communicator containing the group of processes in the corresponding window or file. If called on a session, aborts only the local process.
  • MPI_ERRORS_RETURN Returns an error code to the application.

MPI applications can also implement their own error handlers by calling:

  • MPI_Comm_create_errhandler then MPI_Comm_set_errhandler
  • MPI_File_create_errhandler then MPI_File_set_errhandler
  • MPI_Session_create_errhandler then MPI_Session_set_errhandler or at MPI_Session_init
  • MPI_Win_create_errhandler then MPI_Win_set_errhandler

Note that MPI does not guarantee that an MPI program can continue past an error.

See the MPI man page for a full list of MPI error codes.

See the Error Handling section of the MPI-3.1 standard for more information.
