PARÁMETROS DE ENTRADA

  • sendbuf: Dirección de inicio del buffer de envío (opcional).
  • recvcount: Número de elementos por bloque (entero no negativo).
  • datatype: Tipo de datos de los elementos del buffer de entrada (handle).
  • op: Operación (handle).
  • comm: Comunicador (handle).
  • info: Información (handle, persistente).

PARÁMETROS DE SALIDA

  • recvbuf: Dirección de inicio del buffer de recepción (opcional).
  • request: Peticion (handle, no bloqueado).
  • ierror: Solo en Fortran: Código de error (entero).

DESCRIPCIÓN

MPI_Reduce_scatter_block realiza una reducción elemento a elemento en un vector de count = n * recvcount elementos en el buffer de entrada definido por sendbuf, count y datatype, usando la operación op, donde n es el número de procesos en el grupo de comm. Luego, el vector de resultados obtenido se divide en n segmentos, donde n es el número de procesos en el grupo. Cada segmento contiene recvcount elementos. El ith segmento se envía a proceso i y se almacena en el buffer de recepción definido por recvbuf, recvcount y datatype.

USO DE LA OPCION DE EN-PLACE

Cuando el comunicador es un intracomunicador, puedes realizar una operación de reducción-scatter en lugar de usar el buffer de entrada. En este caso, el buffer de salida se usa como el buffer de entrada. Usa la variable MPI_IN_PLACE como valor de sendbuf. En este caso, los datos de entrada se obtienen del cuello de botella del buffer de recepción. El área ocupada por los datos de entrada puede ser más larga o más corta que la data que se llenó por el buffer de salida.

CUANDO EL COMUNICADOR ES UN INTER-COMUNICADOR

Cuando el comunicador es un intercomunicador, la operación de reducción-scatter ocurre en dos fases. Primero, el resultado de la reducción realizada en los datos proporcionados por los procesos de la primera grupo se distribuye entre los procesos de la segunda grupo. Luego, la operación se inversa: el resultado de la reducción realizada en los datos proporcionados por los procesos de la segunda grupo se distribuye entre los procesos de la primera grupo. Para cada grupo, todos los procesos proporcionan el mismo recvcounts argumento, y el sum de los recvcounts debe ser la misma para ambos grupos.

NOTAS SOBRE LAS OPERACIONES COLLECTIVAS

Las funciones de reducción ( MPI_Op ) no devuelven un valor de error. Por lo tanto, si detectan un error, solo pueden llamar a MPI_Abort o pasar por alto el problema. Por eso, si cambias el gestor de errores desde MPI_ERRORS_ARE_FATAL a algo como MPI_ERRORS_RETURN, no se indicará ningún error.

La razón de esto es el problema de rendimiento en garantizar que todas las rutinas de colectiva devuelvan el mismo valor de error.

ERRORES

Más que todo, los rutínas MPI devuelven un valor de error; en C, el resultado de la función es el valor de retorno, y en Fortran, el último argumento es el valor de retorno.

Antes de devolver el valor de error, se llama al gestor de error asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo) actual. Si no hay objeto de comunicación asociado con la llamada MPI, se considera que la llamada está asociada a MPI_COMM_SELF y se llama al gestor asociado con MPI_COMM_SELF. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se use el modelo de Sesiones exclusivamente), el error eleva el gestor de error inicial. El gestor de error inicial puede cambiarse llamando a MPI_Comm_set_errhandler en MPI_COMM_SELF cuando se use el modelo del Mundo, o mediante el argumento mpi_initial_errhandler de mpiexec o la clave info de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no hay otro gestor de error adecuado, se llama el gestor de error MPI_ERRORS_RETURN para las funciones de I/O de MPI y el gestor de error MPI_ERRORS_ABORT para todas las otras funciones de MPI.

El Open MPI incluye tres gestores de error predeterminados que pueden usarse:

  • MPI_ERRORS_ARE_FATAL Provoca que el programa aborte todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT Un gestor de errores que puede invocarse en un comunicador, ventana, archivo o sesión. Cuando se llama en un comunicador, actúa como si MPI_Abort hubiera sido llamado en ese comunicador. Si se llama en una ventana o archivo, actúa como si MPI_Abort hubiera sido llamado en un comunicador que contiene el grupo de procesos en la ventana o archivo correspondiente. Si se llama en una sesión, aborta solo el proceso local.
  • MPI_ERRORS_RETURN Devuelve un código de error a la aplicación.

Las aplicaciones MPI también pueden implementar sus propios gestores de error llamando a:

  • MPI_Comm_create_errhandler luego MPI_Comm_set_errhandler
  • MPI_File_create_errhandler luego MPI_File_set_errhandler

MPI_Ireduce_scatter_block(3)

NAME

MPI_Ireduce_scatter_block - Irregular reduce-scatter operation. Non-blocking version.

SYNTAX

C/FORTRAN

C++:
MPI::Intracomm&.Ireduce_scatter_block(const void* sendbuf, void* recvbuf, int recvcount, MPI::Datatype datatype, MPI::Op op) const

Fortran:
MPI_IREDUCE_SCATTER_BLOCK(SENDBUF, RECVBUF, RECVCOUNT, DATATYPE, OP, COMM, REQUEST)
INTEGER RECVCOUNT
TYPE(MPI_DATATYPE), INTENT(IN) :: DATATYPE
TYPE(MPI_OP), INTENT(IN) :: OP
TYPE(MPI_COMM), INTENT(IN) :: COMM
TYPE(MPI_REQUEST), INTENT(OUT) :: REQUEST
TYPE(MPI_OFFSET), INTENT(OUT) :: SENDDISP
TYPE(MPI_OFFSET), INTENT(OUT) :: RECVDISP
FORTRAN 2008:
MPI_IREDUCE_SCATTER_BLOCK(SENDBUF, RECVBUF, RECVCOUNT, DATATYPE, OP, COMM, SENDDISP, RECVDISP, REQUEST)

C:
int MPI_Ireduce_scatter_block(const void* sendbuf, void* recvbuf, int recvcount, MPI_Datatype datatype, MPI_Op op, MPI_Comm comm, MPI_Request *request)

INPUT PARAMETERS

•
sendbuf: (Contiguous) Initial address of send buffer (choice).
•
recvbuf: (Non-contiguous) Address of receive buffer (choice).
•
recvcount: Number of elements in the receive buffer for each process (non-negative integer).
•
datatype: Datatype of elements of receive buffer (handle).
•
op: Operation (handle).
•
comm: Communicator of the group (handle).
•
senddisp: Offset of the first element of the send buffer relative to the start of the send buffer (Fortran 2008).
•
recvdisp: Offset of the first element of the receive buffer relative to the start of the receive buffer (Fortran 2008).

OUTPUT PARAMETERS

•
request: Communication handle (handle).

DESCRIPTION

Reduces the elements in the common data buffer of all processes in the group, performs a scatterv operation, and places the result in the receive buffer of each process. The MPI_Ireduce_scatter_block operation is the non-blocking version of MPI_Reduce_scatter_block.

The input arguments are the same as for MPI_Reduce_scatter_block. The output argument request is of type MPI_Request, which is used to identify the particular communication.

USE OF IN-PLACE OPTION

When the communicator is a Cartesian communicator, the same buffer may be specified for sendbuf and recvbuf. In this case, the data is reduced and scattered in place. The result is put back into the original buffer.

WHEN COMMUNICATOR IS AN INTER-COMMUNICATOR

The MPI_Ireduce_scatter_block function can be used with an inter-communicator. In this case, the operation is performed between the processes in the lower group and the processes in the upper group.

NOTES ON COLLECTIVE OPERATIONS

All processes participating in the collective operation must call MPI_Ireduce_scatter_block with the same generic command-line arguments. The recvcount argument must be the same for all processes. The datatype and op arguments must be identical for all processes.

The sendbuf and recvbuf arguments are distinguished from the other arguments in that they are of pointer type. The size of the send buffer must be at least comm-size * recvcount elements, and the size of the receive buffer must be at least recvcount elements.

The MPI_Ireduce_scatter_block operation is non-blocking. The communication handle returned in request can be used later with MPI_Wait or MPI_Test to check for completion.
