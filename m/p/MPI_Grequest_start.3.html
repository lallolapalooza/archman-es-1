MPI_GREQUEST_START(3) Open MPI MPI_GREQUEST_START(3)

MPI_Grequest_start — Inicia una solicitud generalizada y devuelve un manejador a ella en request.

SINTAXIS

Sintaxis C

#include <mpi.h>
int MPI_Grequest_start(MPI_Grequest_query_function *query_fn,
    MPI_Grequest_free_function *free_fn,
    MPI_Grequest_cancel_function *cancel_fn, void *extra_state,
    MPI_Request *request)

Sintaxis Fortran

USE MPI
! o la forma antigua: INCLUDE 'mpif.h'
MPI_GREQUEST_START(QUERY_FN, FREE_FN, CANCEL_FN, EXTRA_STATE,
    REQUEST, IERROR)
    INTEGER REQUEST, IERROR
    EXTERNAL QUERY_FN, FREE_FN, CANCEL_FN
      INTEGER(KIND=MPI_ADDRESS_KIND) EXTRA_STATE

Sintaxis Fortran 2008

USE mpi_f08
MPI_Grequest_start(query_fn, free_fn, cancel_fn, extra_state, request,
        ierror)
    PROCEDURE(MPI_Grequest_query_function) :: query_fn
    PROCEDURE(MPI_Grequest_free_function) :: free_fn
    PROCEDURE(MPI_Grequest_cancel_function) :: cancel_fn
    INTEGER(KIND=MPI_ADDRESS_KIND), INTENT(IN) :: extra_state
    TYPE(MPI_Request), INTENT(OUT) :: request
    INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARÁMETROS DE ENTRADA

•
query_fn
Función de devolución de llamada invocada cuando se consulta el estado de la solicitud (función).
•
free_fn
Función de devolución de llamada invocada cuando se libera la solicitud (función).
•
cancel_fn
Función de devolución de llamada invocada cuando se cancela la solicitud (función).
•
extra_state : Estado adicional.

PARÁMETROS DE SALIDA

  • request : Solicitud generalizada (manejador).
  • ierror : Solo Fortran: Estado de error (entero).

DESCRIPCIÓN

MPI_Grequest_start inicia una request generalizada y devuelve un manejador a ella en request.

La sintaxis y el significado de las funciones de devolución de llamada se enumeran a continuación. A todas las funciones de devolución de llamada se les pasa el argumento extra_state que se asoció con la request mediante la llamada de inicio MPI_Grequest_start. Esto se puede usar para mantener un estado definido por el usuario para la request. En C, la función de consulta es

typedef int MPI_Grequest_query_function(void *extra_state,
    MPI_Status *status);

En Fortran, es

SUBROUTINE GREQUEST_QUERY_FUNCTION(EXTRA_STATE, STATUS, IERROR)
    INTEGER STATUS(MPI_STATUS_SIZE), IERROR
    INTEGER(KIND=MPI_ADDRESS_KIND) EXTRA_STATE

La función query_fn calcula el estado que debe devolverse para la solicitud generalizada. El estado también incluye información sobre la cancelación exitosa/no exitosa de la solicitud (resultado a devolver por MPI_Test_cancelled).

La función query_fn es invocada por la llamada MPI_{Wait|Test}{any|some|all} que completó la solicitud generalizada asociada con esta devolución de llamada. La función de devolución de llamada también es invocada por llamadas a MPI_Request_get_status si la solicitud está completa cuando ocurre la llamada. En ambos casos, la devolución de llamada recibe una referencia a la variable de estado correspondiente pasada por el usuario a la llamada MPI. Si el usuario proporcionó MPI_STATUS_IGNORE o MPI_STATUSES_IGNORE a la función MPI que causa que se llame a query_fn, entonces MPI pasará un objeto de estado válido a query_fn, y este estado se ignorará al regresar de la función de devolución de llamada. Tenga en cuenta que query_fn solo se invoca después de que MPI_Grequest_complete se llama en la solicitud; puede ser invocada varias veces para la misma solicitud generalizada. Tenga en cuenta también que una llamada a MPI_{Wait|Test}{some|all} puede causar múltiples invocaciones de funciones de devolución de llamada query_fn, una por cada solicitud generalizada que se completa con la llamada MPI. El orden de estas invocaciones no está especificado por MPI.

En C, la función de liberación es

typedef int MPI_Grequest_free_function(void *extra_state);

Y en Fortran, es

SUBROUTINE GREQUEST_FREE_FUNCTION(EXTRA_STATE, IERROR)
    INTEGER IERROR
    INTEGER(KIND=MPI_ADDRESS_KIND) EXTRA_STATE

La función de devolución de llamada free_fn es invocada para limpiar los recursos asignados por el usuario cuando se libera la solicitud generalizada.

La función free_fn es invocada por la llamada MPI_{Wait|Test}{any|some|all} que completó la solicitud generalizada asociada con esta devolución de llamada. free_fn se invoca después de la llamada a query_fn para la misma solicitud. Sin embargo, si la llamada MPI completó múltiples solicitudes generalizadas, el orden en que se invocan las funciones de devolución de llamada free_fn no está especificado por MPI.

La devolución de llamada free_fn también se invoca para solicitudes generalizadas que se liberan mediante una llamada a MPI_Request_free (no se producirá ninguna llamada a MPI_{Wait|Test}{any|some|all} para dicha solicitud). En este caso, la función de devolución de llamada se llamará en la llamada MPI MPI_Request_free(request) o en la llamada MPI MPI_Grequest_complete(request), la que ocurra más tarde. En otras palabras, en este caso, el código de liberación real se ejecuta tan pronto como ambas llamadas (MPI_Request_free y MPI_Grequest_complete) hayan ocurrido. La request no se desasigna hasta después de que free_fn se complete. Tenga en cuenta que free_fn solo se invocará una vez por solicitud en un programa correcto.

En C, la función de cancelación es

typedef int MPI_Grequest_cancel_function(void *extra_state, int complete);

En Fortran, la función de cancelación es

SUBROUTINE GREQUEST_CANCEL_FUNCTION(EXTRA_STATE, COMPLETE, IERROR)
     INTEGER IERROR
     INTEGER(KIND=MPI_ADDRESS_KIND) EXTRA_STATE
     LOGICAL COMPLETE

La función cancel_fn es invocada para iniciar la cancelación de una solicitud generalizada. Es llamada por MPI_Request_cancel(request). MPI pasa a la función de devolución de llamada complete=true si MPI_Grequest_complete ya ha sido llamada en la solicitud, y complete=false en caso contrario.

ERRORES

Casi todas las rutinas MPI devuelven un valor de error; las rutinas C como resultado de retorno de la función y las rutinas Fortran en el último argumento.

Antes de que se devuelva el valor de error, se llama al controlador de errores MPI actual asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo). Si no hay ningún objeto de comunicación asociado con la llamada MPI, entonces la llamada se considera adjunta a MPI_COMM_SELF y llamará al controlador de errores MPI asociado. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se utiliza el modelo de Sesiones exclusivamente) el error eleva el controlador de errores inicial. El controlador de errores inicial se puede cambiar llamando a MPI_Comm_set_errhandler en MPI_COMM_SELF cuando se utiliza el modelo Mundial, o el argumento de línea de comandos mpi_initial_errhandler a mpiexec o la clave info a MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no se ha establecido ningún otro controlador de errores apropiado, entonces se llama al controlador de errores MPI_ERRORS_RETURN para las funciones de E/S MPI y al controlador de errores MPI_ERRORS_ABORT para todas las demás funciones MPI.

Open MPI incluye tres controladores de errores predefinidos que se pueden utilizar:

  • MPI_ERRORS_ARE_FATAL Provoca que el programa aborte todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT Un err

ERRORS

All MPI functions must return an error code. Some functions may return an error code, and other functions may not. If a function returns an error code other than MPI_SUCCESS, then the value passed in the comm argument to that function is used for the error handler.

The following error handlers are predefined:

  • MPI_ERRORS_ARE_FATAL Fatal error: aborts the process.
  • MPI_ERRORS_IGNORE Ignores errors. This is generally not a good idea.
  • MPI_ERRORS_RETURN Returns an error code to the application.

MPI applications can also implement their own error handlers by calling:

  • MPI_Comm_create_errhandler then MPI_Comm_set_errhandler
  • MPI_File_create_errhandler then MPI_File_set_errhandler
  • MPI_Session_create_errhandler then MPI_Session_set_errhandler or at MPI_Session_init
  • MPI_Win_create_errhandler then MPI_Win_set_errhandler

Note that MPI does not guarantee that an MPI program can continue past an error.

See the MPI man page for a full list of MPI error codes.

See the Error Handling section of the MPI-3.1 standard for more information.

All callback functions return an error code. The code is passed back and dealt with as appropriate for the error code by the MPI function that invoked the callback function. For example, if error codes are returned, then the error code returned by the callback function will be returned by the MPI function that invoked the callback function. In the case of a MPI_{Wait|Test}any call that invokes both query_fn and free_fn, the MPI call will return the error code returned by the last callback, namely free_fn. If one or more of the request``s in a call to ``MPI_{Wait|Test}{some|all} has failed, then the MPI call will return MPI_ERR_IN_STATUS. In such a case, if the MPI call was passed an array of statuses, then MPI will return in each of the statuses that correspond to a completed generalized request the error code returned by the corresponding invocation of its free_fn callback function. However, if the MPI function was passed MPI_STATUSES_IGNORE, then the individual error codes returned by each callback function will be lost.
