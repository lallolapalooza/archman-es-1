MPIX_Comm_ishrink(3)

Paquete: openmpi

Licencias: BSD-3-Clause AND LicenseRef-MPICH

MPIX_Comm_ishrink(3) Open MPI MPIX_Comm_ishrink(3)

MPIX_Comm_shrink, MPIX_Comm_ishrink - Crea un nuevo comunicador que incluya a todos los procesos del comunicador padre que no hayan fallado.

Esta es parte de la extensión ULFM de mitigación de errores a nivel de usuario.

SINTAXIS

Sintaxis C

#include <mpi.h>
#include <mpi-ext.h>
int MPIX_Comm_shrink(MPI_Comm comm, MPI_Comm *newcomm)
int MPIX_Comm_ishrink(MPI_Comm comm, MPI_Comm *newcomm, MPI_Request *request)

Sintaxis Fortran

USE MPI
USE MPI_EXT
! o la forma antigua: INCLUDE 'mpif.h'
MPIX_COMM_SHRINK(COMM, NEWCOMM, IERROR)
     INTEGER COMM, NEWCOMM, IERROR
MPIX_COMM_ISHRINK(COMM, NEWCOMM, REQUEST, IERROR)
     INTEGER COMM, NEWCOMM, REQUEST, IERROR

Sintaxis Fortran 2008

USE mpi_f08
USE mpi_ext_f08
MPIX_Comm_shrink(comm, newcomm, ierror)
     TYPE(MPI_Comm), INTENT(IN) :: comm
     TYPE(MPI_Comm), INTENT(OUT) :: newcomm
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror
MPIX_Comm_ishrink(comm, newcomm, request, ierror)
     TYPE(MPI_Comm), INTENT(IN) :: comm
     TYPE(MPI_Comm), INTENT(OUT), ASYNCHRONOUS :: newcomm
     TYPE(MPI_Request), INTENT(OUT) :: request
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARÁMETROS DE ENTRADA

•
comm: Comunicador (handle).

PARÁMETROS DE SALIDA

  • newcomm: Comunicador (handle).
  • request: Solicitud (handle, solo no bloqueante).
  • ierror: Solo Fortran: Estado de error (entero).

DESCRIPCIÓN

Esta operación colectiva crea un nuevo comunicador newcomm interno o externo a partir del comunicador comm interno o externo, excluyendo los procesos MPI que hayan fallado durante la operación.

Los grupos de newcomm deben incluir todos los procesos MPI que devuelvan el resultado de MPIX_Comm_shrink, y deben excluir todos los procesos MPI cuya falla haya causado un error de tipo MPIX_ERR_PROC_FAILED o MPIX_ERR_PROC_FAILED_PENDING en un miembro de los grupos de newcomm antes de que ese miembro iniciara la operación de reducción.

En otras palabras, esta función es semánticamente equivalente a una operación de MPI_Comm_split que se realizaría incluso con fallos, donde los miembros de los grupos de newcomm participan con el mismo color y una clave igual a su número de rango en comm.

MPIX_Comm_ishrink es la variante no bloqueante de MPIX_Comm_shrink. Se debe tener cuidado al usar newcomm antes de que la solicitud (request) haya finalizado.

CUANDO EL COMUNICADOR ES REVOKADO O CONTIENE PROCESOS FALLADOS

Esta función nunca produce un error de clase MPIX_ERR_REVOKED o MPIX_ERR_PROC_FAILED. Las definiciones semánticas de MPIX_Comm_shrink y MPIX_Comm_ishrink se mantienen incluso cuando comm es revocado o cuando el grupo de comm contiene procesos fallados. En particular, MPIX_Comm_shrink y MPIX_Comm_ishrink son operaciones colectivas, incluso cuando comm es revocado.

La implementación intentará detectar todas las fallas durante la operación de reducción, pero en ciertas circunstancias, el grupo de newcomm puede aún contener procesos fallados, cuya falla se detectará en operaciones posteriores en newcomm.

ERRORES

Casi todas las rutinas MPI devuelven un valor de error; el resultado de las rutinas C es el valor de error, y en las rutinas Fortran, el último argumento es el valor de error.

Antes de que se devuelva el valor de error, se llama al manejador de errores asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo) actual. Si no hay ningún objeto de comunicación asociado con la llamada MPI, se considera que la llamada está asociada a MPI_COMM_SELF y se llama al manejador de errores asociado a MPI_COMM_SELF. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se usa el modelo de Sesiones exclusivamente), el error invoca al manejador de errores inicial. El manejador de errores inicial puede cambiarse llamando a MPI_Comm_set_errhandler sobre MPI_COMM_SELF cuando se usa el modelo del Mundo, o al argumento mpi_initial_errhandler de mpiexec o a la clave info de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no hay otro manejador de errores apropiado establecido, se invoca al manejador de errores MPI_ERRORS_RETURN para las funciones de I/O MPI y al manejador de errores MPI_ERRORS_ABORT para todas las demás funciones MPI.

Open MPI incluye tres manejadores de errores predeterminados que pueden usarse:

  • MPI_ERRORS_ARE_FATAL Causa que el programa aborte todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT Un manejador de errores que puede invocarse en un comunicador, ventana, archivo o sesión. Cuando se llama en un comunicador, actúa como si se hubiera llamado MPI_Abort en ese comunicador. Si se llama en una ventana o archivo, actúa como si se hubiera llamado MPI_Abort en un comunicador que contiene el grupo de procesos en la ventana o archivo correspondiente. Si se llama en una sesión, solo se aborta el proceso local.
  • MPI_ERRORS_RETURN Devuelve un código de error a la aplicación.

Las aplicaciones MPI también pueden implementar sus propios manejadores de errores llamando:

  • MPI_Comm_create_errhandler luego MPI_Comm_set_errhandler
  • MPI_File_create_errhandler luego MPI_File_set_errhandler
  • MPI_Session_create_errhandler luego MPI_Session_set_errhandler o en MPI_Session_init
  • MPI_Win_create_errhandler luego MPI_Win_set_errhandler

Nota: Las aplicaciones MPI no garantizan que un programa MPI pueda continuar después de un error.

Consulte la página de man de MPI para obtener una lista completa de códigos de error MPI.

Consulte la sección de manejo de errores de la especificación MPI-3.1 para obtener más información.
