MPI_Comm_spawn_multiple(3) Open MPI MPI_Comm_spawn_multiple(3)

MPI_Comm_spawn_multiple — Ejecuta múltiples binarios, o el mismo binario con múltiples conjuntos de argumentos.

Sintaxis

Sintaxis C

#include <mpi.h>
int MPI_Comm_spawn_multiple(int count, char *array_of_commands[],
     char **array_of_argv[], const int array_of_maxprocs[], const MPI_Info
     array_of_info[], int root, MPI_Comm comm, MPI_Comm *intercomm,
     int array_of_errcodes[])

Sintaxis Fortran

USE MPI
! o la forma antigua: INCLUDE 'mpif.h'
MPI_COMM_SPAWN_MULTIPLE(COUNT, ARRAY_OF_COMMANDS, ARRAY_OF_ARGV,
     ARRAY_OF_MAXPROCS, ARRAY_OF_INFO, ROOT, COMM, INTERCOMM,
     ARRAY_OF_ERRCODES, IERROR)
     INTEGER COUNT, ARRAY_OF_INFO(*), ARRAY_OF_MAXPROCS(*), ROOT,
             COMM, INTERCOMM, ARRAY_OF_ERRCODES(*), IERROR
     CHARACTER*(*) ARRAY_OF_COMMANDS(*), ARRAY_OF_ARGV(COUNT, *)
     TYPE(MPI_Info), INTENT(IN) :: ARRAY_OF_INFO(*)
     TYPE(MPI_Comm), INTENT(IN) :: COMM
     TYPE(MPI_Comm), INTENT(OUT) :: INTERCOMM
     INTEGER :: ARRAY_OF_ERRCODES(*)
     INTEGER, OPTIONAL, INTENT(OUT) :: IERROR

Sintaxis Fortran 2008

USE mpi_f08
MPI_Comm_spawn_multiple(count, array_of_commands, array_of_argv,
     array_of_maxprocs, array_of_info, root, comm, intercomm,
             array_of_errcodes, ierror)
     INTEGER, INTENT(IN) :: count, array_of_maxprocs(*), root
     CHARACTER(LEN=*), INTENT(IN) :: array_of_commands(*)
     CHARACTER(LEN=*), INTENT(IN) :: array_of_argv(count, *)
     TYPE(MPI_Info), INTENT(IN) :: array_of_info(*)
     TYPE(MPI_Comm), INTENT(IN) :: comm
     TYPE(MPI_Comm), INTENT(OUT) :: intercomm
     INTEGER :: array_of_errcodes(*)
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

Parámetros de entrada

  • count: Número de comandos (entero positivo, significativo solo en el root — ver NOTAS).
  • array_of_commands: Comandos a ejecutar (array de strings, significativo solo en el root).
  • array_of_argv: Argumentos para los comandos (array de array de strings, significativo solo en el root).
  • array_of_maxprocs: Número máximo de procesos a iniciar para cada comando (array de enteros, significativo solo en el root).
  • array_of_info: Objetos de información que indican al sistema de ejecución dónde y cómo iniciar los procesos (array de handles, significativo solo en el root).
  • root: Rango del proceso en el cual se examinan los argumentos previos (entero).
  • comm: Comunicador intracommunicador que contiene el grupo de procesos a iniciar (handle).

Parámetros de salida

  • intercomm: Comunicador intercomunicador entre el grupo original y el nuevo grupo de procesos (handle).
  • array_of_errcodes: Código de error por proceso (array de enteros).
  • ierror: Solo en Fortran: Estado de error (entero).

Descripción

MPI_Comm_spawn_multiple es idéntico a MPI_Comm_spawn excepto que puede especificar múltiples binarios. El primer argumento, count, indica el número de binarios. Los siguientes tres argumentos son arrays de los argumentos correspondientes en MPI_Comm_spawn. El siguiente argumento, array_of_info, es un array de info argumentos, uno por cada binario. Ver la sección sobre los argumentos de información para más información.

Para el versión Fortran de array_of_argv, el elemento array_of_argv(i,j) es el j-ésimo argumento para el comando número i.

En cualquier lenguaje, un aplicación puede utilizar la constante MPI_ARGVS_NULL (cual es probablemente (char **)0 en C) para especificar que no se deberían pasar argumentos a ningún comando. El efecto de establecer elementos individuales de array_of_argv a MPI_ARGV_NULL no está definido. Para especificar argumentos para algunos comandos pero no para otros, los comandos sin argumentos deberían tener un argv correspondiente cuyo primer elemento sea NULL (((char *)0 en C y cadena vacía en Fortran).

Todas las procesos creadas tienen el mismo MPI_COMM_WORLD. Sus rangos en MPI_COMM_WORLD corresponden directamente al orden en el que los comandos se especifican en MPI_Comm_spawn_multiple. Supón que m1 procesos son generados por el primer comando, m2 por el segundo, etc. Las procesos correspondientes a los primeros comandos tienen rangos 0, 1, ..., m1-1. Las procesos en el segundo comando tienen rangos m1, m1+1, ..., m1+m2-1. Las procesos en el tercer comando tienen rangos m1+m2, m1+m2+1, ..., m1+m2+m3-1, etc.

El argumento array_of_errcodes es un arreglo unidimensional de tamaño

 _ count
\       n ,
/_ i=1   i

donde i es el i-ésimo elemento de array_of_maxprocs. El comando número i corresponde a los i espacios contíguos en este array desde el elemento

                 _              _
 _ i-1          |   _ i          |
\       n ,  to |  \      n      | -1
/_ j=1   i      |  /_ j=1  j     |
                |_              _|

Los códigos de error se tratan como en MPI_Comm_spawn.

PARÁMETROS DE ENTRADA

count

Número de comandos a spawnear.

array_of_commands

Array de cadenas que especifican los comandos a ejecutar.

array_of_argv

Array de arrays de cadenas de argumentos para cada comando.

array_of_maxprocs

Array de enteros que especifican el número máximo de procesos a spawnear para cada comando.

array_of_info

Array de estructuras MPI_Info que especifican las directivas de spawn.

comm

Communicador que contiene el grupo de procesos que spawnearán los nuevos procesos.

PARÁMETROS DE SALIDA

intercomm

Nuevo comunicador inter-comunicador entre el grupo padre y el grupo hijo.

DESCRIPCIÓN

La rutina MPI_Comm_spawn_multiple spawnea múltiples procesos ejecutando uno o más comandos especificados. Los nuevos procesos se conectan al comunicador de entrada comm, creando un nuevo comunicador inter-comunicador.

Los argumentos count, array_of_commands, array_of_argv, array_of_maxprocs, y array_of_info se utilizan para especificar los comandos a spawnear, sus argumentos, el número de procesos a spawnear para cada comando, y las directivas de spawn, respectivamente. Los argumentos count y los arrays deben tener la misma longitud.

El comunicador comm es el comunicador que contiene el grupo de procesos que spawnearán los nuevos procesos. El nuevo comunicador inter-comunicador intercomm se utiliza para la comunicación entre los procesos padre e hijo.

El argumento array_of_info es un array de estructuras MPI_Info. Cada estructura MPI_Info puede contener las siguientes claves:

                    process. If this key is specified, then all processes spawned
                    must have the same value for this key.  If this key is
                    unspecified, it is assumed to be false.  If a value is specified
                    in the environment, the value
                                will be overwritten by the provided
                                value.
mapper                 char *   Mapper to be used for this job
map_by                 char *   Mapping directive indicating how
                                processes are to be mapped (slot,
                                node, socket, etc.).
rank_by                char *   Ranking directive indicating how
                                processes are to be ranked (slot,
                                node, socket, etc.).
bind_to                char *   Binding directive indicating how
                                processes are to be bound (core, slot,
                                node, socket, etc.).

                                the executable

ppr                    char *   Spawn specified number of processes
                                on each of the identified object type
env                    char *   Newline-delimited list of envars to
                                be passed to the spawned procs

Las claves de info de tipo bool son en realidad cadenas pero se evalúan de la siguiente manera: si el valor de la cadena es un número, se convierte a un entero y se castea a un booleano (lo que significa que los enteros cero son falsos y los valores distintos de cero son verdaderos). Si el valor de la cadena es (sin distinción de mayúsculas y minúsculas) "yes" o "true", el booleano es verdadero. Si el valor de la cadena es (sin distinción de mayúsculas y minúsculas) "no" o "false", el booleano es falso. Todos los demás valores de cadena no son reconocidos y, por lo tanto, son falsos.

Tenga en cuenta que si alguno de los manejadores de info tiene ompi_non_mpi establecido en true, entonces todos los manejadores de info deben tenerlo establecido en true. Si algunos están establecidos en true, pero otros están establecidos en false (o no están definidos), se devolverá MPI_ERR_INFO.

Tenga en cuenta que en "#PACKAGE_NAME#", la primera ubicación de array en array_of_info se aplica a todos los comandos en array_of_commands.

NOTAS

El argumento count es interpretado por MPI solo en la raíz, al igual que array_of_argv. Dado que la dimensión principal de array_of_argv es count, un valor no positivo de count en un nodo no raíz podría teóricamente causar un error de verificación de límites en tiempo de ejecución, aunque array_of_argv debería ser ignorado por la subrutina. Si esto sucede, debe proporcionar explícitamente un valor razonable de count en los nodos no raíz.

Similar a MPI_Comm_spawn, es responsabilidad de la aplicación terminar cada conjunto individual de argv en el argumento array_of_argv. En C, cada array argv se termina con un puntero NULL. En Fortran, cada array argv se termina con una cadena vacía (tenga en cuenta que los compiladores no insertarán automáticamente esta cadena en blanco; la aplicación debe asegurarse de tener suficiente espacio para una entrada de cadena en blanco como último elemento del array).

Se aplican otras restricciones al parámetro array_of_argv; consulte la descripción del parámetro argv en MPI_Comm_spawn para obtener más detalles.

MPI-3.1 implica (pero no establece directamente) que el argumento array_of_commands debe ser un array de cadenas de longitud count. A diferencia del parámetro array_of_argv, array_of_commands no necesita terminarse con un puntero NULL en C o una cadena en blanco en Fortran. Versiones anteriores de Open MPI requerían que array_of_commands se terminara con una cadena en blanco en Fortran; eso ya no es necesario en esta versión de Open MPI.

Llamar a MPI_Comm_spawn muchas veces crearía muchos conjuntos de hijos con diferentes MPI_COMM_WORLDs, mientras que MPI_Comm_spawn_multiple crea hijos con un único MPI_COMM_WORLD, por lo que los dos métodos no son completamente equivalentes. Además, si necesita spawnear múltiples ejecutables, puede obtener un mejor rendimiento utilizando MPI_Comm_spawn_multiple en lugar de llamar a MPI_Comm_spawn varias veces.

ERRORES

Casi todas las rutinas MPI devuelven un valor de error; las rutinas C como resultado de retorno de la función y las rutinas Fortran en el último argumento.

Antes de que se devuelva el valor de error, se llama al manejador de errores MPI actual asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo). Si no hay ningún objeto de comunicación asociado con la llamada MPI, entonces la llamada se considera adjunta a MPI_COMM_SELF y llamará al manejador de errores MPI asociado. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se utiliza exclusivamente el Modelo de Sesiones) el error eleva el manejador de errores inicial. El manejador de errores inicial se puede cambiar llamando a MPI_Comm_set_errhandler en MPI_COMM_SELF cuando se utiliza el modelo World, o el argumento CLI mpi_initial_errhandler a mpiexec o la clave de info a MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no se ha configurado ningún otro manejador de errores apropiado, entonces se llama al manejador de errores MPI_ERRORS_RETURN para las funciones de E/S MPI y al manejador de errores MPI_ERRORS_ABORT para todas las demás funciones MPI.

Open MPI incluye tres manejadores de errores predefinidos que se pueden utilizar:

  • MPI_ERRORS_ARE_FATAL Causa que el programa aborte todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT Un manejador de errores que puede ser invocado en un comunicador, ventana, archivo o sesión. Cuando se llama en un comunicador, actúa como si se hubiera llamado a MPI_Abort en ese comunicador. Si se llama en una ventana o archivo, actúa como si se hubiera llamado a MPI_Abort en un comunicador que contiene el grupo de procesos en la ventana o archivo correspondiente. Si se llama en una sesión, solo termina el proceso local.
  • MPI_ERRORS_RETURN Devuelve un código de error a la aplicación.

Las aplicaciones MPI también pueden implementar sus propios manejadores de errores llamando a:

  • MPI_Comm_create_errhandler luego MPI_Comm_set_errhandler
  • MPI_File_create_errhandler luego MPI_File_set_errhandler
  • MPI_Session_create_errhandler luego MPI_Session_set_errhandler o en MPI_Session_init
  • MPI_Win_create_errhandler luego MPI_Win_set_errhandler

Tenga en cuenta que MPI no garantiza que un programa MPI pueda continuar después de un error.

Consulte la página man de MPI para obtener una lista completa de los códigos de error de MPI.

Consulte la sección Manejo de Errores del estándar MPI-3.1 para obtener más información.
