MPI_Accumulate, MPI_Raccumulate - Combina los contenidos del búfer de origen con los de un búfer de destino.

SINTAXIS

Sintaxis C

#include <mpi.h>
int MPI_Accumulate(const void *origin_addr, int origin_count,
     MPI_Datatype origin_datatype, int target_rank,
     MPI_Aint target_disp, int target_count,
     MPI_Datatype target_datatype, MPI_Op op, MPI_Win win)
int MPI_Raccumulate(const void *origin_addr, int origin_count,
     MPI_Datatype origin_datatype, int target_rank,
     MPI_Aint target_disp, int target_count,
     MPI_Datatype target_datatype, MPI_Op op, MPI_Win win,
     MPI_Request *request)

PARÁMETROS DE ENTRADA

  • origin_addr: Dirección inicial del búfer (elección).
  • origin_count: Número de entradas en el búfer (entero no negativo).
  • origin_datatype: Tipo de dato de cada entrada del búfer (manejador).
  • target_rank: Rango del destino (entero no negativo).
  • target_disp: Desplazamiento desde el inicio de la ventana hasta el principio del búfer de destino (entero no negativo).
  • target_count: Número de entradas en el búfer de destino (entero no negativo).
  • target_datatype: Tipo de dato de cada entrada en el búfer de destino (manejador).
  • op: Operación de reducción (manejador).
  • win: Objeto de ventana (manejador).

PARÁMETRO DE SALIDA

  • MPI_Raccumulate: Solicitud RMA
  • ierror: Solo Fortran: Estado de error (entero).

DESCRIPCIÓN

MPI_Accumulate es una función utilizada para comunicación MPI unidireccional que suma los contenidos del búfer de origen (según se define por origin_addr, origin_count y origin_datatype) al búfer especificado por los argumentos target_count y target_datatype, en el desplazamiento target_disp, en la ventana de destino especificada por target_rank y win, utilizando la operación op. La ventana de destino solo puede ser accedida por procesos dentro del mismo nodo. Esto es similar a MPI_Put, excepto que los datos se combinan en el área de destino en lugar de sobrescribirla.

Se pueden utilizar cualquiera de las operaciones predefinidas para MPI_Reduce. No se pueden utilizar funciones definidas por el usuario. Por ejemplo, si op es MPI_SUM, cada elemento del búfer de origen se suma al elemento correspondiente en el destino, reemplazando el valor anterior en el destino.

Cada argumento de tipo de dato debe ser un tipo de dato predefinido o un tipo de dato derivado, donde todos los componentes básicos sean del mismo tipo de dato predefinido. Ambos argumentos de tipo de dato deben construirse a partir del mismo tipo de dato predefinido. La operación op se aplica a elementos de ese tipo predefinido. El argumento target_datatype no debe especificar entradas superpuestas, y el búfer de destino debe caber en la ventana de destino.

Se define una nueva operación predefinida, MPI_REPLACE. Corresponde a la función asociativa f(a, b) =b; es decir, el valor actual en la memoria de destino se reemplaza por el valor suministrado por el origen.

MPI_Raccumulate es similar a MPI_Accumulate, excepto que asigna un objeto de solicitud de comunicación y lo asocia con el manejador de solicitud (el argumento request) que se puede utilizar para esperar o probar la finalización. La finalización de una operación MPI_Raccumulate indica que el búfer origin_addr está libre para ser actualizado. No indica que la operación se haya completado en la ventana de destino.

NOTAS

MPI_Put es un caso especial de MPI_Accumulate, con la operación MPI_REPLACE. Tenga en cuenta, sin embargo, que MPI_Put y MPI_Accumulate tienen diferentes restricciones en las actualizaciones concurrentes.

Es responsabilidad del usuario garantizar que, al usar las funciones de acumulación, el argumento de desplazamiento de destino sea tal que los accesos a la ventana estén correctamente alineados según los argumentos del tipo de dato en la llamada a la función MPI_Accumulate.

ERRORES

Casi todas las rutinas MPI devuelven un valor de error; las rutinas C como resultado de retorno de la función y las rutinas Fortran en el último argumento.

Antes de que se devuelva el valor de error, se llama al manejador de errores MPI actual asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo). Si no hay ningún objeto de comunicación asociado con la llamada MPI, la llamada se considera adjunta a MPI_COMM_SELF y llamará al manejador de errores MPI asociado. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se usa exclusivamente el Modelo de Sesiones) el error eleva el manejador de errores inicial. El manejador de errores inicial se puede cambiar llamando a MPI_Comm_set_errhandler en MPI_COMM_SELF cuando se usa el modelo World, o el argumento CLI mpi_initial_errhandler para mpiexec o la clave info para MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no se ha configurado ningún otro manejador de errores apropiado, se llama al manejador de errores MPI_ERRORS_RETURN para las funciones de E/S de MPI y al manejador de errores MPI_ERRORS_ABORT para todas las demás funciones MPI.

Open MPI incluye tres manejadores de errores predefinidos que se pueden usar:

  • MPI_ERRORS_ARE_FATAL Provoca que el programa aborte todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT Un manejador de errores que se puede invocar en un comunicador, ventana, archivo o sesión. Cuando se llama en un comunicador, actúa como si se hubiera llamado a MPI_Abort en ese comunicador. Si se llama en una ventana o archivo, actúa como si se hubiera llamado a MPI_Abort en un comunicador que contiene el grupo de procesos en la ventana o archivo correspondiente. Si se llama en una sesión, aborta solo el proceso local.
  • MPI_ERRORS_RETURN Devuelve un código de error a la aplicación.

Las aplicaciones MPI también pueden implementar sus propios manejadores de errores llamando a:

  • MPI_Comm_create_errhandler y luego MPI_Comm_set_errhandler
  • MPI_File_create_errhandler y luego MPI_File_set_errhandler
  • MPI_Session_create_errhandler y luego MPI_Session_set_errhandler o
