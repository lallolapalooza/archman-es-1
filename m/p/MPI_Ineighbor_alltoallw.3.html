PARAMETROS DE ENTRADA

  • sendbuf: Dirección de inicio del búfer de envío.
  • sendcounts: Array de enteros, donde la entrada i especifica el número de elementos a enviar al vecino i.
  • sdispls: Array de enteros, donde la entrada i especifica el desplazamiento (en bytes, desplazamiento desde sendbuf) desde el cual enviar datos al vecino i.
  • sendtypes: Array de tipos de datos, donde la entrada i especifica el tipo de datos a usar al enviar datos al vecino i.
  • recvcounts: Array de enteros, donde la entrada j especifica el número de elementos a recibir del vecino j.
  • rdispls: Array de enteros, donde la entrada j especifica el desplazamiento (en bytes, desplazamiento desde recvbuf) al cual se deben escribir los datos del vecino j.
  • recvtypes: Array de tipos de datos, donde la entrada j especifica el tipo de datos a usar al recibir datos del vecino j.
  • comm: Comunicador sobre el cual se intercambiarán los datos.
  • info: Info (manejador, solo persistente).

PARAMETROS DE SALIDA

  • recvbuf: Dirección del búfer de recepción.
  • request: Solicitud (manejador, solo no bloqueante).
  • ierror: Solo Fortran: Estado de error.

DESCRIPCION

MPI_Neighbor_alltoallw es una operación colectiva generalizada en la cual todos los procesos envían datos a y reciben datos de todos los vecinos. Añade flexibilidad a MPI_Neighbor_alltoallv al permitir al usuario especificar el tipo de datos de bloques de datos individuales (además del desplazamiento y el número de elementos). Su operación puede pensarse de la siguiente manera, donde cada proceso realiza 2n (n siendo el número de vecinos en la topología del comunicador comm) comunicaciones punto a punto independientes. Los vecinos y la disposición del búfer se determinan por la topología de comm.

MPI_Cart_get(comm, maxdims, dims, periods, coords);
for (dim = 0, i = 0 ; dim < dims ; ++dim) {
    MPI_Cart_shift(comm, dim, 1, &r0, &r1);
    MPI_Isend(sendbuf + sdispls[i]  * extent(sendtype),
              sendcount, sendtypes[i], r0, ..., comm, ...);
    MPI_Irecv(recvbuf + rdispls[i] * extent(recvtype),
              recvcount, recvtypes[i], r0, ..., comm, ...);
    ++i;
    MPI_Isend(sendbuf + sdispls[i] * extent(sendtype),
              sendcount, sendtypes[i], r1, ..., comm, &req[i]);
    MPI_Irecv(recvbuf + rdispls[i] * extent(recvtype),
              recvcount, recvtypes[i], r1, ..., comm, ...);
    ++i;
}
MPI_Wait_all (...);
MPI_Comm_size(comm, &n);
for (i = 0, i < n; i++)
  MPI_Send(sendbuf + sdispls[i], sendcounts[i],
       sendtypes[i], i, ..., comm);
for (i = 0, i < n; i++)
  MPI_Recv(recvbuf + rdispls[i], recvcounts[i],
       recvtypes[i], i, ..., comm);

El proceso j envía el k-ésimo bloque de su sendbuf local al vecino k, que coloca los datos en el j-ésimo bloque de su recvbuf local.

Cuando un par de procesos intercambia datos, cada uno puede pasar argumentos de recuento y tipo diferentes siempre que el remitente especifique la misma cantidad de datos a enviar (en bytes) que el receptor espera recibir.

Tenga en cuenta que el proceso i puede enviar una cantidad de datos diferente al proceso j de la que recibe del proceso j. Además, un proceso puede enviar cantidades y tipos de datos completamente diferentes a diferentes procesos en el comunicador.

NOTAS

La opción MPI_IN_PLACE para sendbuf no tiene sentido para esta operación.

La especificación de recuentos, tipos y desplazamientos no debe hacer que ninguna ubicación se escriba más de una vez.

Todos los argumentos en todos los procesos son significativos. El argumento comm, en particular, debe describir el mismo comunicador en todos los procesos.

Los desplazamientos de sdispls y rdispls se miden en bytes. Compárelo con MPI_Neighbor_alltoallv, donde estos desplazamientos se miden en unidades de sendtype y recvtype, respectivamente.

PARÁMETROS DE ENTRADA

Antes de que el valor de error sea devuelto, se llama al manejador de errores asociado con el objeto de comunicación (por ejemplo, communicator, window, file) antes de la llamada. Si no hay objeto de comunicación asociado con la llamada MPI, se considera que la llamada está asociada a MPI_COMM_SELF y ejecutará el manejador de errores correspondiente. Cuando MPI_COMM_SELF no esté inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se use el modelo de Sesiones exclusivamente), el error eleva el manejador de errores inicial. El manejador de errores inicial puede cambiarse llamando a MPI_Comm_set_errhandler en MPI_COMM_SELF cuando se use el modelo del Mundo, o al argumento CLI mpi_initial_errhandler en mpiexec o a la clave info en MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no hay otro manejador de errores adecuado, se llama al manejador de errores MPI_ERRORS_RETURN para funciones de I/O MPI y al manejador de errores MPI_ERRORS_ABORT para todas las otras funciones MPI.

Open MPI incluye tres manejadores de errores predeterminados que pueden usarse:

  • MPI_ERRORS_ARE_FATAL Actúa como si se hubiera llamado MPI_Abort en el proceso correspondiente.
  • MPI_ERRORS_ABORT Actúa como si se hubiera llamado MPI_Abort en el comunicador correspondiente. Si se llama a una ventana o archivo, actúa como si se hubiera llamado MPI_Abort en el comunicador que contiene el grupo de procesos en la ventana o archivo correspondiente. Si se llama a una sesión, detiene solo el proceso local.
  • MPI_ERRORS_RETURN Devuelve un código de error a la aplicación.

Las aplicaciones MPI también pueden implementar sus propios manejadores de errores llamando:

  • MPI_Comm_create_errhandler luego MPI_Comm_set_errhandler
  • MPI_File_create_errhandler luego MPI_File_set_errhandler
  • MPI_Session_create_errhandler luego MPI_Session_set_errhandler o al MPI_Session_init
  • MPI_Win_create_errhandler luego MPI_Win_set_errhandler

Nota: MPI no garantiza que un programa MPI pueda continuar tras un error.
