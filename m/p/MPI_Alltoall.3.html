PARAMETROS DE ENTRADA

  • sendbuf: Dirección de inicio del búfer de envío (elección).
  • sendcount: Número de elementos a enviar a cada proceso (entero).
  • sendtype: Tipo de datos de los elementos del búfer de envío (identificador).
  • recvcount: Número de elementos a recibir de cada proceso (entero).
  • recvtype: Tipo de datos de los elementos del búfer de recepción (identificador).
  • comm: Comunicador sobre el cual se intercambiarán los datos (identificador).
  • info: Información (identificador, solo persistente)

PARAMETROS DE SALIDA

  • recvbuf: Dirección de inicio del búfer de recepción (elección).
  • request: Solicitud (identificador, solo no bloqueante).
  • ierror: Solo Fortran: Estado de error (entero).

DESCRIPCION

MPI_Alltoall es una operación colectiva en la que todos los procesos envían la misma cantidad de datos entre sí y reciben la misma cantidad de datos entre sí. La operación de esta rutina se puede representar de la siguiente manera, donde cada proceso realiza 2n (siendo n el número de procesos en el comunicador comm) comunicaciones punto a punto independientes (incluida la comunicación consigo mismo).

MPI_Comm_size(comm, &n);
for (i = 0, i < n; i++)
    MPI_Send(sendbuf + i * sendcount * extent(sendtype),
        sendcount, sendtype, i, ..., comm);
for (i = 0, i < n; i++)
    MPI_Recv(recvbuf + i * recvcount * extent(recvtype),
        recvcount, recvtype, i, ..., comm);

Cada proceso divide su sendbuf local en n bloques - cada uno contiene sendcount elementos del tipo sendtype - y divide su recvbuf de manera similar según recvcount y recvtype. El proceso j envía el k-ésimo bloque de su sendbuf local al proceso k, que coloca los datos en el j-ésimo bloque de su recvbuf local. La cantidad de datos enviados debe ser igual a la cantidad de datos recibidos, par a par, entre cada par de procesos.

CUANDO EL COMUNICADOR ES UN INTERCOMUNICADOR

Cuando el comunicador es un intercomunicador, la operación de agrupación ocurre en dos fases. Los datos se agrupan de todos los miembros del primer grupo y se reciben por todos los miembros del segundo grupo. Luego, los datos se agrupan de todos los miembros del segundo grupo y se reciben por todos los miembros del primero. La operación exhibe un comportamiento simétrico y dúplex completo.

El primer grupo define el proceso raíz. El proceso raíz utiliza MPI_ROOT como valor de root. Todos los demás procesos del primer grupo utilizan MPI_PROC_NULL como valor de root. Todos los procesos del segundo grupo utilizan el rango del proceso raíz en el primer grupo como valor de root.

Cuando el comunicador es un intra-comunicador, estos grupos son los mismos y la operación ocurre en una sola fase.

USO DE LA OPCION IN-PLACE

Cuando el comunicador es un intra-comunicador, puede realizar una operación de todos a todos en el lugar (el búfer de salida se usa como búfer de entrada). Utilice la variable MPI_IN_PLACE como valor de sendbuf. En este caso, se ignoran sendcount y sendtype. Se asume que los datos de entrada de cada proceso se encuentran en el área donde ese proceso recibiría su propia contribución al búfer de recepción.

NOTAS

Todos los argumentos en todos los procesos son significativos. El argumento comm, en particular, debe describir el mismo comunicador en todos los procesos.

Existen dos funciones de biblioteca MPI que son más generales que MPI_Alltoall. MPI_Alltoallv permite la comunicación de todos a todos hacia y desde búferes que no necesitan ser contiguos; diferentes procesos pueden enviar y recibir diferentes cantidades de datos. MPI_Alltoallw amplía la funcionalidad de MPI_Alltoallv para permitir el intercambio de datos con diferentes tipos de datos.

ERRORES

Casi todas las rutinas MPI devuelven un valor de error; las rutinas C como resultado de retorno de la función y las rutinas Fortran en el último argumento.

Antes de que se devuelva el valor de error, se llama al controlador de errores MPI actual asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo). Si no hay ningún objeto de comunicación asociado con la llamada MPI, entonces la llamada se considera adjunta a MPI_COMM_SELF y llamará al controlador de errores MPI asociado. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se utiliza exclusivamente el Modelo de Sesiones) el error eleva el controlador de errores inicial. El controlador de errores inicial puede cambiarse llamando a MPI_Comm_set_errhandler en MPI_COMM_SELF cuando se utiliza el modelo World, o el argumento CLI mpi_initial_errhandler para mpiexec o la clave de información para MPI_Comm_spawn/ MPI_Comm_spawn_multiple. Si no se ha establecido ningún otro controlador de errores apropiado, entonces se llama al controlador de errores MPI_ERRORS_RETURN para las funciones de E/S de MPI y al controlador de errores MPI_ERRORS_ABORT para todas las demás funciones de MPI.

ERRORES

Todos los procedimientos de MPI pueden fallar. Cuando un procedimiento MPI falla, se invoca un manejador de errores. El propósito de un manejador de errores es determinar la acción que debe tomar el programa MPI en respuesta a un error. El MPI estándar define tres manejadores de errores incorporados que se pueden utilizar para manejar errores:

  • MPI_ERRORS_ARE_FATAL Hace que el programa aborte todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT Un manejador de errores que se puede invocar en un comunicador, ventana, archivo o sesión. Cuando se llama en un comunicador, actúa como si se hubiera llamado a MPI_Abort en ese comunicador. Si se llama en una ventana o archivo, actúa como si se hubiera llamado a MPI_Abort en un comunicador que contiene el grupo de procesos en la ventana o archivo correspondiente. Si se llama en una sesión, aborta solo el proceso local.
  • MPI_ERRORS_RETURN Devuelve un código de error a la aplicación.

Las aplicaciones MPI también pueden implementar sus propios manejadores de errores llamando a:

  • MPI_Comm_create_errhandler luego MPI_Comm_set_errhandler
  • MPI_File_create_errhandler luego MPI_File_set_errhandler
  • MPI_Session_create_errhandler luego MPI_Session_set_errhandler o en MPI_Session_init
  • MPI_Win_create_errhandler luego MPI_Win_set_errhandler

Tenga en cuenta que MPI no garantiza que un programa MPI pueda continuar después de un error.
