MPI_Finalize — Finaliza el modelo de mundo MPI.

Sintaxis

Sintaxis C

#include <mpi.h>
int MPI_Finalize()

Sintaxis Fortran

USE MPI
! o o l d e r f o r m: INCLUDE 'mpif.h'
MPI_FINALIZE(IERROR)
    INTEGER IERROR

Sintaxis Fortran 2008

USE mpi_f08
MPI_Finalize(ierror)
    INTEGER, OPTIONAL, INTENT(OUT) :: ierror

Parámetro de salida

•
ierror : Solo en Fortran: Código de error (entero).

Descripción

Esta rutina finaliza el modelo de mundo MPI. Si el modelo de mundo MPI ha sido inicializado en un proceso MPI, debe ser finalizado exactamente una vez invocando esta rutina durante la vida del proceso MPI. Esto es diferente del modelo de sesión MPI, que puede ser inicializado y finalizado múltiples veces en un proceso MPI. Véase MPI_Session_init y MPI_Session_finalize.

No debe garantizar que las comunicaciones pendientes en el modelo de mundo MPI se completen antes de que el proceso invoque MPI_Finalize. Si la llamada devuelve un código de error, cada proceso puede continuar con cálculos locales o salir sin participar en comunicaciones con otros procesos en el modelo de mundo MPI. En el momento en que el último proceso llama a MPI_Finalize, todos los envíos pendientes en el modelo de mundo MPI deben tener un receptor correspondiente, y todos los recibos pendientes deben tener un envío correspondiente.

Ver MPI-5.0:11.4.1 para una lista de funcionalidades MPI disponibles (por ejemplo, incluso cuando el modelo de mundo MPI no ha sido inicializado o ya ha sido finalizado).

MPI_Finalize es coloquial sobre todos los procesos conectados. Si no hubo procesos espawnados, aceptados o conectados, significa que es coloquial sobre MPI_COMM_WORLD. De otro modo, es coloquial sobre la unión de todos los procesos que hayan sido y continúen siendo conectados.

Notas

El modelo de sesión MPI es diferente del modelo de mundo MPI, y tiene diferentes ámbitos de disponibilidad de funcionalidad MPI. Véase MPI_Session_init y MPI_Session_finalize.

Todos los procesos que inician el modelo de mundo MPI deben invocar esta rutina antes de salir. Todos los procesos seguirán existiendo, pero no harán más llamadas MPI en el modelo de mundo MPI. MPI_Finalize garantiza que todas las acciones locales requeridas por comunicaciones en el modelo de mundo MPI que el usuario haya completado se realizarán de hecho antes de regresar. Sin embargo, MPI_Finalize no garantiza nada sobre comunicaciones pendientes en el modelo de mundo MPI que no hayan sido completadas; la completación se asegura mediante MPI_Wait y MPI_Test o MPI_Request_free combinado con verificación de completación.

Por ejemplo, un retorno exitoso de una operación de comunicación bloqueante o de uno de los MPI_Wait o MPI_Test significa que la comunicación se completó por el usuario y el buffer puede ser reutilizado, pero no garantiza que el proceso local no tenga más trabajo por hacer. De manera similar, un retorno exitoso de MPI_Request_free con un handle de solicitud generado por un MPI_Isend anula el handle pero no garantiza que la operación haya completado. La MPI_Isend se completa solo cuando un receptor correspondiente ha completado.

Si quieres causar acciones cuando un proceso finaliza el modelo de mundo MPI, ancla una función de callback a MPI_COMM_SELF con un atributo. Luego, cuando MPI_Finalize se llama, ejecutará primero el equivalente de un MPI_Comm_free en MPI_COMM_SELF. Esto causará la ejecución de la función de liberación del atributo en todas las claves asociadas a MPI_COMM_SELF en cualquier orden. Si no hay ninguna clave asociada a MPI_COMM_SELF, no se invoca ninguna función de liberación. La liberación de MPI_COMM_SELF ocurre antes de cualquier otra parte del modelo de mundo MPI. Llamar a MPI_Finalized devolverá Falso en cualquier función de liberación de estas. Una vez que hayas hecho esto con MPI_COMM_SELF, los resultados de MPI_Finalize no están especificados.

Errores

La mayoría de las rutinas MPI devuelven un valor de error; las rutinas C devuelven el valor de error como resultado de la función y las rutinas Fortran en el último argumento.

Antes de que el valor de error se devuelva, se llama al gestor de errores asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo) en el momento. Si no hay objeto de comunicación asociado con la llamada MPI, se considera que la llamada está asociada a MPI_COMM_SELF y se llama al gestor de errores asociado. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se está usando el modelo de sesión exclusivamente), el error eleva el gestor de errores inicial. El gestor de errores inicial puede cambiarse llamando a MPI_Comm_set_errhandler en MPI_COMM_SELF cuando se usa el modelo de mundo, o al argumento CLI mpi_initial_errhandler en mpiexec/mpiexec_multiple o en la clave info de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no hay otro gestor adecuado configurado, se llama al gestor de errores MPI_ERRORS_RETURN para las funciones de I/O MPI y al gestor de errores MPI_ERRORS_ABORT para todas las otras funciones MPI.

Open MPI incluye tres gestores de errores predeterminados que pueden usarse:

  • MPI_ERRORS_ARE_FATAL Lanza al programa el cierre de todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT Un gestor de errores que puede invocarse en un comunicador, ventana, archivo o sesión. Cuando se invoca en un comunicador, actúa como si se hubiera llamado MPI_Abort en ese comunicador. Si se invoca en una ventana o archivo, actúa como si se hubiera llamado MPI_Abort en un comunicador que contiene el grupo de procesos en la ventana o archivo correspondiente. Si se invoca en una sesión, se detiene solo el proceso local.
  • MPI_ERRORS_RETURN Devuelve un código de error al programa.

Los programas MPI también pueden implementar sus propios gestores de errores llamando:

  • MPI_Comm_create_errhandler luego MPI_Comm_set_errhandler
  • MPI_File_create_errhandler luego MPI_File_set_errhandler
  • MPI_Session_create_errhandler luego MPI_Session_set_errhandler o al MPI_Session_init
  • MPI_Win_create_errhandler luego MPI_Win_set_errhandler

Nota: MPI no garantiza que un programa MPI pueda continuar después de un error.

Ver la sección de manejo de errores de la especificación MPI-3.1 para más información.

OUTPUT PARAMETER

F: 
ierror      Fortran only: exit status of the function.

DESCRIPTION

This routine, MPI_Finalize, is the last MPI routine called in an MPI program. It completes MPI operations and frees all MPI resources. After this routine is called, no other MPI routines can be called.

In some implementations, MPI_Finalize can be called multiple times, but this is not recommended. In most implementations, it is safe to call MPI_Init multiple times (but not between MPI_Init and MPI_Finalize).

The MPI standard specifies that MPI_Finalize must be called by all MPI processes. The MPI program should exit after MPI_Finalize returns.

NOTES

It is not necessary to call MPI_Init to call MPI_Finalize. A program can call MPI_Finalize even if it did not call MPI_Init.

ERRORS

When the C binding for this function is called, if the communicator is not valid or if another MPI error occurs, then the MPI_ERR_OTHER error code is returned. Otherwise, MPI_ERR_SUCCESS is returned.

When the Fortran binding for this function is called, the value returned in ierror is the MPI error code described above on all exit paths.

MPI_ERR_OTHER     Invalid communicator. This occurs if the communicator is not valid. Not a collective operation.

MPI_ERR_SUCCESS     No error occurred.
