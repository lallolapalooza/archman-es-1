MPI_Bcast_init(3)

Paquete: openmpi

Licencias: BSD-3-Clause AND LicenseRef-MPICH

MPI_BCAST_INIT(3) Open MPI MPI_BCAST_INIT(3)

MPI_Bcast, MPI_Ibcast - Transmite un mensaje desde el proceso con rango root a todos los demás procesos del grupo.

SINTAXIS

Sintaxis C

#include <mpi.h>
int MPI_Bcast(void *buffer, int count, MPI_Datatype datatype,
    int root, MPI_Comm comm)
int MPI_Ibcast(void *buffer, int count, MPI_Datatype datatype,
    int root, MPI_Comm comm, MPI_Request *request)

Sintaxis Fortran

USE MPI
! o la forma anterior: INCLUDE 'mpif.h'
MPI_BCAST(BUFFER, COUNT, DATATYPE, ROOT, COMM, IERROR)
    <type>  BUFFER(*)
    INTEGER COUNT, DATATYPE, ROOT, COMM, IERROR
MPI_IBCAST(BUFFER, COUNT, DATATYPE, ROOT, COMM, REQUEST, IERROR)
    <type>  BUFFER(*)
    INTEGER COUNT, DATATYPE, ROOT, COMM, REQUEST, IERROR

Sintaxis Fortran 2008

USE mpi_f08
MPI_Bcast(buffer, count, datatype, root, comm, ierror)
    TYPE(*), DIMENSION(..) :: buffer
    INTEGER, INTENT(IN) :: count, root
    TYPE(MPI_Datatype), INTENT(IN) :: datatype
    TYPE(MPI_Comm), INTENT(IN) :: comm
    INTEGER, OPTIONAL, INTENT(OUT) :: ierror
MPI_Ibcast(buffer, count, datatype, root, comm, request, ierror)
    TYPE(*), DIMENSION(..), ASYNCHRONOUS :: buffer
    INTEGER, INTENT(IN) :: count, root
    TYPE(MPI_Datatype), INTENT(IN) :: datatype
    TYPE(MPI_Comm), INTENT(IN) :: comm
    TYPE(MPI_Request), INTENT(OUT) :: request
    INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARÁMETROS DE ENTRADA/SALIDA

  • buffer: Dirección de inicio del buffer (elección).
  • count: Número de entradas en el buffer (entero).
  • datatype: Tipo de dato del buffer (manejador).
  • root: Rango de la raíz de transmisión (entero).
  • comm: Comunicador (manejador).

PARÁMETROS DE SALIDA

  • request: Solicitud (manejador, solo no bloqueante).
  • ierror: Solo Fortran: Estado de error (entero).

DESCRIPCIÓN

MPI_Bcast transmite un mensaje desde el proceso con rango root a todos los procesos del grupo, incluyéndose a sí mismo. Es llamado por todos los miembros del grupo usando los mismos argumentos para comm y root. Al regresar, el contenido del buffer de comunicación de root se ha copiado a todos los procesos.

Se permiten tipos de datos generales y derivados para datatype. La firma de tipo de count y datatype en cualquier proceso debe ser igual a la firma de tipo de count y datatype en la raíz. Esto implica que la cantidad de datos enviados debe ser igual a la cantidad recibida, par a par entre cada proceso y la raíz. MPI_Bcast y todas las demás rutinas colectivas de movimiento de datos imponen esta restricción. Todavía se permiten mapas de tipo distintos entre emisor y receptor.

Ejemplo: Transmitir 100 enteros desde el proceso 0 a cada proceso del grupo.

MPI_Comm comm;
int array[100];
int root=0;
//...
MPI_Bcast( array, 100, MPI_INT, root, comm);

Como en muchos de nuestros fragmentos de código de ejemplo, asumimos que algunas de las variables (como comm en el ejemplo anterior) se han asignado valores apropiados.

CUANDO EL COMUNICADOR ES UN INTER-COMUNICADOR

Cuando el comunicador es un inter-comunicador, el proceso raíz en el primer grupo transmite datos a todos los procesos del segundo grupo. El primer grupo define el proceso raíz. Ese proceso usa MPI_ROOT como el valor de su argumento root. Los procesos restantes usan MPI_PROC_NULL como el valor de su argumento root. Todos los procesos del segundo grupo usan el rango de ese proceso raíz en el primer grupo como el valor de su argumento root. Los argumentos del buffer de recepción de los procesos en el segundo grupo deben ser consistentes con el argumento del buffer de envío del proceso raíz en el primer grupo.

NOTAS

Esta función no admite la opción in-place.

ERRORES

Casi todas las rutinas MPI devuelven un valor de error; en las rutinas C como resultado de retorno de la función y en las rutinas Fortran en el último argumento.

Antes de que se devuelva el valor de error, se llama al controlador de error MPI actual asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo). Si no hay ningún objeto de comunicación asociado con la llamada MPI, entonces la llamada se considera adjunta a MPI_COMM_SELF y llamará al controlador de error MPI asociado. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se usa exclusivamente el Modelo de Sesiones), el error eleva el controlador de error inicial. El controlador de error inicial se puede cambiar llamando a MPI_Comm_set_errhandler en MPI_COMM_SELF cuando se usa el modelo World, o el argumento de línea de comandos mpiexec mpi_initial_errhandler o la clave de información para MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no se ha establecido ningún otro controlador de error apropiado, entonces se llama al controlador de error MPI_ERRORS_RETURN para las funciones de E/S de MPI y al controlador de error MPI_ERRORS_ABORT para todas las demás funciones de MPI.

Open MPI incluye tres controladores de error predefinidos que se pueden usar:

  • MPI_ERRORS_ARE_FATAL Provoca que el programa aborte todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT Un controlador de error que puede ser invocado en un comunicador, ventana, archivo o sesión. Cuando se llama en un comunicador, actúa como si se hubiera llamado MPI_Abort en ese comunicador. Si se llama en una ventana o archivo, actúa como si se hubiera llamado MPI_Abort en un comunicador que contiene el grupo de procesos en la ventana o archivo correspondiente. Si se llama en una sesión, solo aborta el proceso local.
  • MPI_ERRORS_RETURN Devuelve un código de error a la aplicación.

Las aplicaciones MPI también pueden implementar sus propios controladores de error llamando a:

  • MPI_Comm_create_errhandler luego MPI_Comm_set_errhandler
  • MPI_File_create_errhandler luego MPI_File_set_errhandler
  • MPI_Session_create_errhandler luego MPI_Session_set_errhandler o en MPI_Session_init
  • MPI_Win_create_errhandler luego MPI_Win_set_errhandler

Tenga en cuenta que MPI no garantiza que un programa MPI pueda continuar después de un error.

Consulte la página del manual de MPI para obtener una lista completa de los códigos de error de MPI.

Consulte la sección de Manejo de Errores del estándar MPI-3.1 para obtener más información.

MPI_Bcast_init(3)

NOMBRE

MPI_Bcast_init - Prepara una operación de difusión no bloqueante.

SINOPSIS

MPI_Bcast_init

int MPI_Bcast_init(const void *buffer, int count, MPI_Datatype datatype, int root, MPI_Comm comm, MPI_Info info, MPI_Request *request);

DESCRIPCIÓN

MPI_Bcast_init prepara una operación de difusión no bloqueante. La operación de difusión comenzará cuando se llame a MPI_Start o MPI_Startall.

  • buffer: Puntero al buffer de datos a enviar (en el proceso raíz) o a recibir (en los otros procesos).
  • count: Número de elementos de datos en el buffer.
  • datatype: Tipo de datos de los elementos en el buffer.
  • root: Rango del proceso raíz en el comunicador comm.
  • comm: Comunicador.
  • info: Objeto de información utilizado para especificar parámetros de rendimiento opcionales.
  • request: Manejador de solicitud devuelto.

CUANDO EL COMUNICADOR ES UN INTER-COMUNICADOR

Cuando el comunicador es un inter-comunicador, la raíz debe ser un miembro del grupo del comunicador local y el resto de los procesos deben ser miembros del grupo del comunicador remoto. La operación de difusión se realiza desde la raíz en el grupo local a todos los procesos del grupo remoto.

NOTAS

La operación de difusión se completa cuando el buffer de envío en el proceso raíz es seguro para ser reutilizado y el buffer de recepción en los otros procesos contiene los datos transmitidos.

ERRORES

MPI_ERR_BUFFER: El búfer de entrada/salida es inválido.

MPI_ERR_COUNT: El recuento es inválido.

MPI_ERR_TYPE: El tipo de datos es inválido.

MPI_ERR_ROOT: El rango raíz es inválido.

MPI_ERR_COMM: El comunicador no es válido.

MPI_ERR_INFO: El objeto de información no es válido.
