MPI_Allgatherv(3)

Paquete: openmpi

MPI_ALLGATHERV(3) Open MPI MPI_ALLGATHERV(3)

MPI_Allgatherv, MPI_Iallgatherv, MPI_Allgatherv_init - Reúne datos de todos los procesos y los entrega a todos. Cada proceso puede contribuir con una cantidad diferente de datos.

PARÁMETROS DE ENTRADA

  • sendbuf: Dirección de inicio del búfer de envío (elección).
  • sendcount: Número de elementos en el búfer de envío (entero).
  • sendtype: Tipo de datos de los elementos del búfer de envío (manejador).
  • recvcount: Matriz de enteros (de longitud igual al tamaño del grupo) que contiene el número de elementos que se reciben de cada proceso.
  • displs: Matriz de enteros (de longitud igual al tamaño del grupo). La entrada i especifica el desplazamiento (relativo a recvbuf) en el que se colocan los datos entrantes del proceso i.
  • recvtype: Tipo de datos de los elementos del búfer de recepción (manejador).
  • comm: Comunicador (manejador).
  • info: Info (manejador, solo persistente).

PARÁMETROS DE SALIDA

  • recvbuf: Dirección del búfer de recepción (elección).
  • request: Solicitud (manejador, solo no bloqueante).
  • ierror: Solo Fortran: Estado de error (entero).

DESCRIPCIÓN

MPI_Allgatherv es similar a MPI_Allgather en que todos los procesos recopilan datos de todos los demás procesos, excepto que cada proceso puede enviar una cantidad diferente de datos. El bloque de datos enviado por el j-ésimo proceso es recibido por cada proceso y colocado en el j-ésimo bloque del búfer recvbuf.

La firma de tipo asociada con sendcount, sendtype, en el proceso j debe ser igual a la firma de tipo asociada con recvcounts[j], recvtype en cualquier otro proceso.

El resultado es como si todos los procesos ejecutaran llamadas a

MPI_Allgatherv(sendbuf, sendcount, sendtype, recvbuf, recvcount,
              displs,recvtype,root,comm);
// para root = 0 , ..., n-1.

Las reglas para el uso correcto de MPI_Allgatherv se encuentran fácilmente en las reglas correspondientes para MPI_Gatherv.

USO DE LA OPCIÓN EN EL SITIO

Cuando el comunicador es un intracommunicator, se puede realizar una operación de recopilación completa en el sitio (el búfer de salida se utiliza como búfer de entrada). Utilice la variable MPI_IN_PLACE como valor de sendbuf. En este caso, sendcount y sendtype se ignoran. Se asume que los datos de entrada de cada proceso se encuentran en el área donde ese proceso recibiría su propia contribución al búfer de recepción. Específicamente, el resultado de una llamada a MPI_Allgatherv que utilizó la opción en el sitio es idéntico al caso en el que todos los procesos ejecutaron n llamadas a

MPI_Allgatherv ( MPI_IN_PLACE, 0, MPI_DATATYPE_NULL, recvbuf,
                 recvcounts, displs, recvtype, root, comm );
// para root =0, ... , n-1.

Tenga en cuenta que MPI_IN_PLACE es un tipo especial de valor; tiene las mismas restricciones en su uso que MPI_BOTTOM.

Debido a que la opción en el sitio convierte el búfer de recepción en un búfer de envío y recepción, una vinculación Fortran que incluye INTENT debe marcarlas como INOUT, no OUT.

CUANDO EL COMUNICADOR ES UN INTERCOMUNICADOR

Cuando el comunicador es un intercomunicador, la operación de recopilación se realiza en dos fases. Los datos se recopilan de todos los miembros del primer grupo, se concatenan y se reciben por todos los miembros del segundo grupo. Luego, los datos se recopilan de todos los miembros del segundo grupo, se concatenan y se reciben por todos los miembros del primero. Los argumentos del búfer de envío en un grupo deben ser consistentes con los argumentos del búfer de recepción en el otro grupo, y viceversa. La operación debe exhibir un comportamiento simétrico y full-duplex.

ERRORES

Casi todas las rutinas MPI devuelven un valor de error; las rutinas C como resultado de la función y las rutinas Fortran en el último argumento.

Antes de que se devuelva el valor de error, se llama al controlador de errores MPI actual asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo). Si no hay ningún objeto de comunicación asociado con la llamada MPI, entonces la llamada se considera adjunta a MPI_COMM_SELF y llamará al controlador de errores MPI asociado. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se utiliza exclusivamente el modelo de Sesiones) el error eleva el controlador de errores inicial. El controlador de errores inicial se puede cambiar llamando a MPI_Comm_set_errhandler en MPI_COMM_SELF cuando se utiliza el modelo World, o el argumento de línea de comandos mpiexec mpi_initial_errhandler o la clave de información para MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no se ha configurado ningún otro controlador de errores adecuado, entonces se llama al controlador de errores MPI_ERRORS_RETURN para las funciones de E/S MPI y al controlador de errores MPI_ERRORS_ABORT para todas las demás funciones MPI.
