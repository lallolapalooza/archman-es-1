MPI_Scatterv, MPI_Iscatterv, MPI_Scatterv_init - Distribuye un buffer en partes a todas las tareas de un grupo.

Parámetros de entrada

  • sendbuf: Dirección del buffer de envío (elección, solo relevante en el proceso raíz).
  • sendcounts: Array de enteros (de longitud del tamaño del grupo) que especifica el número de elementos a enviar a cada proceso.
  • displs: Array de enteros (de longitud del tamaño del grupo). El elemento i especifica el desplazamiento (relativo al sendbuf) desde el cual tomar los datos de salida para el proceso i.
  • sendtype: Tipo de elementos del buffer de envío (indicador).
  • recvcount: Número de elementos en el buffer de recepción (entero).
  • recvtype: Tipo de elementos del buffer de recepción (indicador).
  • root: Rango del proceso de envío (entero).
  • comm: Comunicador (indicador).
  • info: Información (indicador, persistente).

Parámetros de salida

  • recvbuf: Dirección del buffer de recepción (elección).
  • request: Petición (indicador, no bloqueante).
  • ierror: Solo en Fortran: Estado de error (entero).

Descripción

MPI_Scatterv es la operación inversa de MPI_Gatherv.

MPI_Scatterv extiende la funcionalidad de MPI_Scatter permitiendo enviar un número variante de datos a cada proceso, ya que sendcounts ahora es un array. También permite más flexibilidad sobre dónde tomar los datos en el proceso raíz, mediante el nuevo argumento displs.

El resultado es como si el proceso raíz ejecutara n operaciones de envío.

MPI_Send(sendbuf + displs[i] * extent(sendtype),
         sendcounts[i], sendtype, i, ...);
// y cada proceso ejecutará una recepción,
MPI_Recv(recvbuf, recvcount, recvtype, root, ...)

El buffer de envío es ignorado para todos los procesos no raíz.

El tipo de firma implícita por sendcount[i], sendtype en el proceso raíz debe ser igual a la firma de tipo implícita por recvcount, recvtype en el proceso i (aunque los mapas de tipo pueden ser diferentes). Esto implica que la cantidad de datos enviada debe ser igual a la recibida, por pares entre cada proceso y la raíz. Los mapas de tipo distintos entre emisor y receptor aún son permitidos.

Todos los argumentos de la función son significativos en el proceso raíz, mientras que en otros procesos solo los argumentos recvbuf, recvcount, recvtype, root, comm son significativos. Los argumentos root y comm deben tener valores idénticos en todos los procesos.

La especificación de contadores, tipos y desplazamientos no debe causar que ningún lugar en la raíz sea leído más de una vez.

Ejemplo 1: El inverso del Ejemplo 5 en la página de MPI_Gatherv. Tenemos un stride variante entre bloques en el lado de envío (raíz), y en el lado de recepción recibimos 100 - i elementos en la i-ésima columna de un array de 100 x 150 en el proceso i.

MPI_Comm comm;
int recvarray[100][150],*rptr;
int root, *sendbuf, myrank, bufsize, *stride;
TYPE(MPI_Datatype) rtype;
int i, *displs, *scounts, offset, gsize;
...
MPI_Comm_size( comm, &gsize);
MPI_Comm_rank( comm, &myrank );
stride = (int *)malloc(gsize*sizeof(int));
...
/* stride[i] para i = 0 a gsize-1 es establecido de alguna forma
 * sendbuf viene de otro lado
 */
...
displs = (int *)malloc(gsize*sizeof(int));
scounts = (int *)malloc(gsize*sizeof(int));
offset = 0;
for (i=0; i<gsize; ++i) {
    displs[i] = offset;
    offset += stride[i];
    scounts[i] = 100 - i;
}
/* Crear el tipo de dato para la columna que estamos recibiendo
 */
MPI_Type_vector( 100-myrank, 1, 150, MPI_INT, &rtype);
MPI_Type_commit( &rtype );
rptr = &recvarray[0][myrank];
MPI_Scatterv(sendbuf, scounts, displs, MPI_INT,
             rptr, 1, rtype, root, comm);

Ejemplo 2: El inverso del Ejemplo 1 en la página de MPI_Gather. El proceso raíz scattera sets de 100 enteros a otros procesos, pero los sets de 100 son enteros de stride aparte en el buffer de envío. Se requiere el uso de MPI_Scatterv, donde stride > 100.

MPI_Comm comm;
int gsize,*sendbuf;
int root, rbuf[100], i, *displs, *scounts;
...
MPI_Comm_size(comm, &gsize);
sendbuf = (int *)malloc(gsize*stride*sizeof(int));
...
displs = (int *)malloc(gsize*sizeof(int));
scounts = (int *)malloc(gsize*sizeof(int));
for (i=0; i<gsize; ++i) {
   displs[i] = i*stride;
   scounts[i] = 100;
}
MPI_Scatterv(sendbuf, scounts, displs, MPI_INT,
             rbuf, 100, MPI_INT, root, comm);

Uso de la opción de lugar en lugar de valor

Cuando el comunicador es un intracommunicador, puedes realizar una operación de scatter en lugar de valor (el buffer de recepción se usa como el buffer de entrada). Usa la variable MPI_IN_PLACE como el valor del proceso raíz recvbuf. En este caso, recvcount y recvtype son ignorados, y el proceso raíz envía ningún dato a sí mismo.

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

Nota: MPI_IN_PLACE es un tipo de valor especial; tiene las mismas restricciones de uso que MPI_BOTTOM.

Debido a que la opción de en-place convierte el buffer de recepción en un buffer de envío y recepción, un enlace Fortran que incluya INTENT debe marcar estos como INOUT, no como OUT.

CUANDO EL COMUNICADOR ES UN COMUNICADOR INTER

Cuando el comunicador es un comunicador inter, el proceso raíz del primer grupo envía datos a todos los procesos del segundo grupo. El grupo primero define el proceso raíz. Este proceso utiliza MPI_ROOT como valor de su argumento root. Los procesos restantes utilizan MPI_PROC_NULL como valor de su argumento root. Todos los procesos del segundo grupo utilizan el rango del proceso raíz del grupo primero como valor de su argumento root. El argumento buffer de recepción del proceso raíz del grupo primero debe ser consistente con el argumento buffer de recepción de los procesos del segundo grupo.

ERRORES

Casi todas las rutinas MPI devuelven un valor de error; las rutinas C como resultado de la función y las rutinas Fortran en el último argumento.

Antes de que se devuelva el valor de error, se llama al controlador de errores MPI actual asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo). Si no hay un objeto de comunicación asociado con la llamada MPI, entonces la llamada se considera asociada a MPI_COMM_SELF y llamará al controlador de errores MPI asociado. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se utiliza exclusivamente el modelo de sesiones), el error activa el controlador de errores inicial. El controlador de errores inicial se puede cambiar llamando a MPI_Comm_set_errhandler en MPI_COMM_SELF cuando se utiliza el modelo World, o el argumento de línea de comandos mpiexec mpi_initial_errhandler o la clave de información de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no se ha establecido ningún otro controlador de errores apropiado, entonces se llama al controlador de errores MPI_ERRORS_RETURN para las funciones de E/S de MPI y al controlador de errores MPI_ERRORS_ABORT para todas las demás funciones de MPI.

Open MPI incluye tres controladores de errores predefinidos que se pueden utilizar:

  • MPI_ERRORS_ARE_FATAL Provoca que el programa aborte todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT Un controlador de errores que se puede invocar en un comunicador, ventana, archivo o sesión. Cuando se llama en un comunicador, actúa como si se hubiera llamado a MPI_Abort en ese comunicador. Si se llama en una ventana o archivo, actúa como si se hubiera llamado a MPI_Abort en un comunicador que contiene el grupo de procesos en la ventana o archivo correspondiente. Si se llama en una sesión, aborta solo el proceso local.
  • MPI_ERRORS_RETURN Devuelve un código de error a la aplicación.

Las aplicaciones MPI también pueden implementar sus propios controladores de errores llamando a:

  • MPI_Comm_create_errhandler luego MPI_Comm_set_errhandler
  • MPI_File_create_errhandler luego MPI_File_set_errhandler
  • MPI_Session_create_errhandler luego MPI_Session_set_errhandler o en MPI_Session_init
  • MPI_Win_create_errhandler luego MPI_Win_set_errhandler

Tenga en cuenta que MPI no garantiza que un programa MPI pueda continuar después de un error.

Consulte la página del manual de MPI para obtener una lista completa de los códigos de error de MPI.

Consulte la sección de Manejo de Errores del estándar MPI-3.1 para obtener más información.
