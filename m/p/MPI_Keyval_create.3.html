MPI_Keyval_create(3)

Paquete: openmpi

Licencias: BSD-3-Clause AND LicenseRef-MPICH

MPI_KEYVAL_CREATE(3) Open MPI MPI_KEYVAL_CREATE(3)

MPI_Keyval_create — Genera una nueva clave de atributo — esta rutina está obsoleta en favor de MPI_Comm_create_keyval.

SINTAXIS

Sintaxis C

#include <mpi.h>
int MPI_Keyval_create(MPI_Copy_function *copy_fn,
     MPI_Delete_function *delete_fn, int *keyval, void *extra_state)

Sintaxis Fortran

USE MPI
! o la forma antigua: INCLUDE 'mpif.h'
MPI_KEYVAL_CREATE(COPY_FN, DELETE_FN, KEYVAL, EXTRA_STATE, IERROR)
     EXTERNAL        COPY_FN, DELETE_FN
     INTEGER KEYVAL, EXTRA_STATE, IERROR

PARÁMETROS DE ENTRADA

  • copy_fn: Función de llamada de copia para la claveval.
  • delete_fn: Función de llamada de eliminación para la claveval.
  • extra_state: Estado adicional para las funciones de llamada.

PARÁMETROS DE SALIDA

  • keyval: Valor de la clave para acceso futuro (entero).
  • ierror: Solo Fortran: Estado de error (entero).

DESCRIPCIÓN

Tenga en cuenta que el uso de esta rutina está obsoleto a partir de MPI-2. Utilice MPI_Comm_create_keyval en su lugar.

Genera una nueva clave de atributo. Las claves son localmente únicas en un proceso y opacas para el usuario, aunque se almacenan explícitamente en enteros. Una vez asignada, el valor de la clave se puede utilizar para asociar atributos y acceder a ellos en cualquier comunicador definido localmente.

La función copy_fn se invoca cuando un comunicador es duplicado por MPI_Comm_dup. copy_fn debe ser de tipo MPI_Copy_function, que se define de la siguiente manera:

typedef int MPI_Copy_function(MPI_Comm oldcomm, int keyval,
                              void *extra_state, void *attribute_val_in,
                              void *attribute_val_out, int *flag)

Una declaración Fortran para dicha función es la siguiente:

SUBROUTINE COPY_FUNCTION(OLDCOMM, KEYVAL, EXTRA_STATE, ATTRIBUTE_VAL_IN,
            ATTRIBUTE_VAL_OUT, FLAG, IERR)
INTEGER OLDCOMM, KEYVAL, EXTRA_STATE,
ATTRIBUTE_VAL_IN, ATTRIBUTE_VAL_OUT, IERR
LOGICAL FLAG

La función de llamada de copia se invoca para cada valor de clave en oldcomm en orden arbitrario. Cada llamada a la función de llamada de copia se realiza con un valor de clave y su atributo correspondiente. Si devuelve flag = 0, entonces el atributo se elimina en el comunicador duplicado. De lo contrario (flag = 1), el nuevo valor del atributo se establece en el valor devuelto en attribute_val_out. La función devuelve MPI_SUCCESS al éxito y un código de error al fallar (en cuyo caso MPI_Comm_dup fallará).

copy_fn puede especificarse como MPI_NULL_COPY_FN o MPI_DUP_FN tanto desde C como desde Fortran; MPI_NULL_COPY_FN es una función que no hace nada más que devolver flag = 0 y MPI_SUCCESS. MPI_DUP_FN es una función de copia simple que establece flag = 1, devuelve el valor de attribute_val_in en attribute_val_out y devuelve MPI_SUCCESS.

NOTAS

Las claves son globales (disponibles para todos y cada uno de los comunicadores).

Existen sutiles diferencias entre C y Fortran que requieren que copy_fn se escriba en el mismo idioma desde el que se llama a MPI_Keyval_create. Esto no debería ser un problema para la mayoría de los usuarios; solo los programadores que utilizan tanto Fortran como C en el mismo programa deben asegurarse de seguir esta regla.

Aunque ambos argumentos formales attribute_val_in y attribute_val_out son de tipo void*, su uso difiere. MPI pasa a la función de copia C el valor del atributo en attribute_val_in, y la dirección del atributo en attribute_val_out, para permitir que la función devuelva el (nuevo) valor del atributo. El uso del tipo void * para ambos es para evitar molestos cambios de tipo.

Una función de copia válida es aquella que duplica completamente la información al hacer una copia completa de las estructuras de datos implicadas por un atributo; otra podría simplemente hacer otra referencia a esa estructura de datos, utilizando un mecanismo de recuento de referencias. Otros tipos de atributos podrían no copiarse en absoluto (podrían ser específicos solo de oldcomm).

De forma análoga a copy_fn hay una función de eliminación de llamada, definida de la siguiente manera. La función delete_fn se invoca cuando un comunicador es liberado por MPI_Comm_free o cuando se realiza una llamada explícita a MPI_Attr_delete. delete_fn debe ser de tipo MPI_Delete_function, que se define de la siguiente manera:

typedef int MPI_Delete_function(MPI_Comm comm, int keyval,
    void *attribute_val, void *extra_state);

Una declaración Fortran para dicha función es la siguiente:

SUBROUTINE DELETE_FUNCTION(COMM, KEYVAL,ATTRIBUTE_VAL, EXTRA_STATE, IERR)
    INTEGER COMM, KEYVAL, ATTRIBUTE_VAL, EXTRA_STATE, IERR

Esta función es llamada por MPI_Comm_free, MPI_Attr_delete y MPI_Attr_put para hacer lo necesario para eliminar un atributo. La función devuelve MPI_SUCCESS al éxito y un código de error al fallar (en cuyo caso MPI_Comm_free fallará).

delete_fn puede especificarse como MPI_NULL_DELETE_FN tanto desde C como desde FORTRAN; MPI_NULL_DELETE_FN es una función que no hace nada, aparte de devolver MPI_SUCCESS.

El valor de clave especial MPI_KEYVAL_INVALID nunca es devuelto por MPI_Keyval_create. Por lo tanto, puede utilizarse para la inicialización estática de valores de clave.

ERRORES

Casi todas las rutinas MPI devuelven un valor de error; las rutinas C como resultado de la función y las rutinas Fortran en el último argumento.

Antes de devolver el valor de error, se llama al controlador de errores MPI actual asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo). Si no hay ningún objeto de comunicación asociado con la llamada MPI, entonces la llamada se considera adjunta a MPI_COMM_SELF y llamará al controlador de errores MPI asociado. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se utiliza exclusivamente el Modelo de Sesiones) el error eleva el controlador de errores inicial. El controlador de errores inicial se puede cambiar llamando a MPI_Comm_set_errhandler en MPI_COMM_SELF al usar el modelo World, o el argumento de línea de comandos mpi_initial_errhandler de mpiexec o la clave de información de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no se ha establecido ningún otro controlador de errores apropiado, entonces se llama al controlador de errores MPI_ERRORS_RETURN para las funciones de E/S de MPI y al controlador de errores MPI_ERRORS_ABORT para todas las demás funciones MPI.

Open MPI incluye tres controladores de errores predefinidos que se pueden utilizar:

  • MPI_ERRORS_ARE_FATAL Provoca que el programa aborte todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT Un controlador de errores que se puede invocar en un comunicador, ventana, archivo o sesión. Cuando se llama en un comunicador, actúa como si MPI_Abort fuera llamado en ese comunicador. Si se llama en una ventana o archivo, actúa como si MPI_Abort fuera llamado en un comunicador que contiene el grupo de procesos en la ventana o archivo correspondiente. Si se llama en una sesión, solo aborta el proceso local.
  • MPI_ERRORS_RETURN Devuelve un código de error a la aplicación.

Las aplicaciones MPI también pueden implementar sus propios controladores de errores llamando a:

  • MPI_Comm_create_errhandler y luego MPI_Comm_set_errhandler
  • MPI_File_create_errhandler y luego MPI_File_set_errhandler
  • MPI_Session_create_errhandler y luego MPI_Session_set_errhandler o en MPI_Session_init
  • MPI_Win_create_errhandler y luego MPI_Win_set_errhandler

Tenga en cuenta que MPI no garantiza que un programa MPI pueda continuar después de un error.

Consulte la página man de MPI para obtener una lista completa de los códigos de error de MPI.

Consulte la sección de Manejo de Errores del estándar MPI-3.1 para obtener más información.
