MPI_Allgather, MPI_Iallgather, MPI_Allgather_init - Reúne datos de todos los procesos y los distribuye a todos los procesos

SINTAXIS

      MPI_Datatype sendtype, void *recvbuf, int recvcount,
      MPI_Datatype recvtype, MPI_Comm comm)

      MPI_Datatype sendtype, void *recvbuf, int recvcount,
      MPI_Datatype recvtype, MPI_Comm comm, MPI_Request *request)

PARÁMETROS DE ENTRADA

  • sendbuf: Dirección de inicio del buffer de envío (elección).
  • sendcount: Número de elementos en el buffer de envío (entero).
  • sendtype: Tipo de dato de los elementos del buffer de envío (manejador).
  • recvbuf: Dirección de inicio del buffer de recepción (elección).
  • recvcount: Número de elementos recibidos de cualquier proceso (entero).
  • recvtype: Tipo de dato de los elementos del buffer de recepción (manejador).
  • comm: Comunicador (manejador).
  • info: Información (manejador, solo persistente).

PARÁMETROS DE SALIDA

  • recvbuf: Dirección del buffer de recepción (elección).
  • request: Solicitud (manejador, solo no bloqueante).
  • ierror: Solo Fortran: Estado de error (entero).

DESCRIPCIÓN

MPI_Allgather es similar a MPI_Gather, excepto que todos los procesos reciben el resultado, en lugar de solo la raíz. En otras palabras, todos los procesos contribuyen al resultado y todos los procesos reciben el resultado.

La firma de tipo asociada con sendcount, sendtype en un proceso debe ser igual a la firma de tipo asociada con recvcount, recvtype en cualquier otro proceso.

El resultado de una llamada a MPI_Allgather es como si todos los procesos ejecutaran n llamadas a

MPI_Gather(sendbuf, sendcount, sendtype, recvbuf, recvcount,
           recvtype, root, comm);
// para root = 0 , ..., n-1.

Las reglas para el uso correcto de MPI_Allgather se encuentran fácilmente en las reglas correspondientes para MPI_Gather.

Ejemplo: La versión de all-gather del Ejemplo 1 en MPI_Gather. Usando MPI_Allgather, recopilaremos 100 enteros de cada proceso del grupo para cada proceso.

MPI_Comm comm;
int gsize,sendarray[100];
int *rbuf;
...
MPI_Comm_size( comm, &gsize);
rbuf = (int *)malloc(gsize*100*sizeof(int));
MPI_Allgather( sendarray, 100, MPI_INT, rbuf, 100, MPI_INT, comm);

Después de la llamada, cada proceso tiene la concatenación a nivel de grupo de los conjuntos de datos.

USO DE LA OPCIÓN IN-PLACE

Cuando el comunicador es un intracommunicator, puede realizar una operación de all-gather in-place (el buffer de salida se usa como buffer de entrada). Use la variable MPI_IN_PLACE como valor de sendbuf. En este caso, se ignoran sendcount y sendtype. Se asume que los datos de entrada de cada proceso están en el área donde ese proceso recibiría su propia contribución al buffer de recepción. Específicamente, el resultado de una llamada a MPI_Allgather que usó la opción in-place es idéntico al caso en el que todos los procesos ejecutaron n llamadas a

MPI_Allgather( MPI_IN_PLACE, 0, MPI_DATATYPE_NULL, recvbuf,
               recvcount, recvtype, root, comm )
// para root =0, ... , n-1.

Tenga en cuenta que MPI_IN_PLACE es un tipo especial de valor; tiene las mismas restricciones de uso que MPI_BOTTOM.

Dado que la opción in-place convierte el buffer de recepción en un buffer de envío y recepción, una vinculación Fortran que incluya INTENT debe marcarlas como INOUT, no OUT.

CUANDO EL COMUNICADOR ES UN INTER-COMUNICADOR

Cuando el comunicador es un inter-comunicador, la operación de recopilación ocurre en dos fases. Los datos se recopilan de todos los miembros del primer grupo y se reciben por todos los miembros del segundo grupo. Luego los datos se recopilan de todos los miembros del segundo grupo y se reciben por todos los miembros del primer grupo. Sin embargo, la operación no tiene por qué ser simétrica. El número de elementos enviados por los procesos del primer grupo no tiene por qué ser igual al número de elementos enviados por los procesos del segundo grupo. Puede mover datos en una sola dirección asignando a sendcount un valor de 0 para la comunicación en la dirección inversa.

ERRORES

Casi todas las rutinas de MPI devuelven un valor de error; las rutinas C como resultado de la función y las rutinas Fortran en el último argumento.

Antes de que se devuelva el valor de error, se llama al manejador de errores de MPI actual asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo). Si no hay ningún objeto de comunicación asociado con la llamada MPI, entonces la llamada se considera adjunta a MPI_COMM_SELF y llamará al manejador de errores de MPI asociado. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se usa exclusivamente el Modelo de Sesiones) el error genera el manejador de errores inicial. El manejador de errores inicial se puede cambiar llamando a MPI_Comm_set_errhandler en MPI_COMM_SELF cuando se usa el modelo World, o el argumento de línea de comandos MPI_ERRORS_RETURN para mpiexec o la clave de información para MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no se ha configurado ningún otro manejador de errores apropiado, entonces se llama al manejador de errores MPI_ERRORS_RETURN para las funciones de E/S de MPI y al manejador de errores MPI_ERRORS_ABORT se le llama

ERRORS

All MPI routines block, exceptions are documented in the "Errors" section of the MPI Standard.

By default, on error, MPI routines are not allowed to return. Instead, they will cause the process to be terminated.

MPI provides three predefined error handlers that can be used:

  • MPI_ERRORS_ARE_FATALCauses the program to abort all connected MPI processes.
  • MPI_ERRORS_ABORTAn error handler that can be invoked on a communicator, window, file, or session. When called on a communicator, it acts as if MPI_Abort was called on that communicator. If called on a window or file, acts as if MPI_Abort was called on a communicator containing the group of processes in the corresponding window or file. If called on a session, aborts only the local process.
  • MPI_ERRORS_RETURNReturns an error code to the application.

MPI applications can also implement their own error handlers by calling:

  • MPI_Comm_create_errhandler then MPI_Comm_set_errhandler
  • MPI_File_create_errhandler then MPI_File_set_errhandler
  • MPI_Session_create_errhandler then MPI_Session_set_errhandler or at MPI_Session_init
  • MPI_Win_create_errhandler then MPI_Win_set_errhandler

Note that MPI does not guarantee that an MPI program can continue past an error.

See the MPI man page for a full list of MPI error codes.

See the Error Handling section of the MPI-3.1 standard for more information.
