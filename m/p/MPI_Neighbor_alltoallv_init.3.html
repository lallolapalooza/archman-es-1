Parámetros de entrada

  • sendbuf: Dirección de inicio del búfer de envío.
  • sendcounts: Array de enteros, donde el elemento i especifica el número de elementos a enviar al vecino i.
  • sdispls: Array de enteros, donde el elemento i especifica el desplazamiento (desplazamiento desde sendbuf, en unidades de sendtype) para enviar datos al vecino i.
  • sendtype: Tipo de datos de los elementos del búfer de envío.
  • recvcounts: Array de enteros, donde el elemento j especifica el número de elementos a recibir del vecino j.
  • rdispls: Array de enteros, donde el elemento j especifica el desplazamiento (desplazamiento desde recvbuf, en unidades de recvtype) a donde los datos de vecino j deberían escribirse.
  • recvtype: Tipo de datos de los elementos del búfer de recepción.
  • comm: Comunicador sobre el cual se realiza el intercambio de datos.
  • info: Información (handle, persistente).

Parámetros de salida

  • recvbuf: Dirección del búfer de recepción.
  • request: Requisición (handle, no bloqueada).
  • ierror: Solo en Fortran: Estado de error.

Descripción

MPI_Neighbor_alltoallv es una operación colectiva generalizada en la cual todos los procesos envían datos a y reciben datos de todos los vecinos. Agrega flexibilidad a MPI_Neighbor_alltoall permitiendo al usuario especificar los datos a enviar y recibir en un estilo vectorial (a través de un desplazamiento y un conteo de elementos). La operación de esta rutina puede pensarse así, donde cada proceso realiza 2n (n siendo el número de vecinos en la topología del comunicador comm) comunicaciones punto a punto independientes. La disposición de los vecinos y el búfer son determinados por la topología del comunicador comm.

MPI_Cart_get(comm, maxdims, dims, periods, coords);
for (dim = 0, i = 0 ; dim < dims ; ++dim) {
    MPI_Cart_shift(comm, dim, 1, &r0, &r1);
    MPI_Isend(sendbuf + sdispls[i]  * extent(sendtype),
              sendcount, sendtype, r0, ..., comm, ...);
    MPI_Irecv(recvbuf + rdispls[i] * extent(recvtype),
              recvcount, recvtype, r0, ..., comm, ...);
    ++i;
    MPI_Isend(sendbuf + sdispls[i] * extent(sendtype),
              sendcount, sendtype, r1, ..., comm, &req[i]);
    MPI_Irecv(recvbuf + rdispls[i] * extent(recvtype),
              recvcount, recvtype, r1, ..., comm, ...);
    ++i;
}

El proceso j envía el bloque k del búfer local de envío del proceso j al vecino k, lo que coloca los datos en el bloque j del búfer local de recepción del proceso j.

Cuando dos procesos intercambian datos, cada uno puede pasar diferentes argumentos de elemento count y tipo de datos, siempre que el emisor especifique la misma cantidad de datos a enviar (en bytes) que el receptor espera recibir.

Nota: El proceso i puede enviar un diferente volumen de datos al proceso j que reciba de j. También, un proceso puede enviar diferentes volúmenes de datos a diferentes procesos en el comunicador.

Ordenación de vecinos

Para una topología distribuida creada con MPI_Dist_graph_create, la secuencia de vecinos en los búferes de envío y recepción en cada proceso se define como la secuencia retornada por MPI_Dist_graph_neighbors para los destinos y orígenes respectivamente. Para una topología general creada con MPI_Graph_create, la secuencia de vecinos en los búferes de envío y recepción se define como la secuencia de vecinos retornada por MPI_Graph_neighbors. Nota: Las topologías generales deberían generalmente reemplazarse por las topologías distribuidas.

Para una topología cartesiana creada con MPI_Cart_create, la secuencia de vecinos en los búferes de envío y recepción en cada proceso se define según el orden de las dimensiones, primero los vecinos en la dirección negativa y luego en la dirección positiva con desplazamiento 1. El número de fuentes y destinos en las rutinas de comunicación es 2*ndims con ndims definido en MPI_Cart_create. Si un vecino no existe, es decir, en el borde de una topología cartesiana en el caso de una red virtual no periódica (es decir, periods[...]==false), entonces este vecino se define como MPI_PROC_NULL.

Si un vecino en cualquiera de las funciones es MPI_PROC_NULL, entonces la comunicación colectiva comporta como una comunicación punto a punto con MPI_PROC_NULL en esta dirección. Es decir, el búfer aún forma parte de la secuencia de vecinos pero no se comunica ni se actualiza.

NOTAS

La opción MPI_IN_PLACE para sendbuf no tiene sentido para esta operación.

La especificación de las cuentas y los desplazamientos no debe provocar que se escriba en ninguna ubicación más de una vez.

Todos los argumentos en todos los procesos son significativos. El argumento comm, en particular, debe describir el mismo comunicador en todos los procesos.

Los desplazamientos de sdispls y rdispls se miden en unidades de sendtype y recvtype, respectivamente. Compare esto con MPI_Neighbor_alltoallw, donde estos desplazamientos se miden en bytes.

ERRORES

Casi todas las rutinas de MPI devuelven un valor de error; las rutinas C como resultado de retorno de la función y las rutinas de Fortran en el último argumento.

Antes de que se devuelva el valor de error, se llama al manejador de errores de MPI actual asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo). Si no hay ningún objeto de comunicación asociado con la llamada a MPI, entonces la llamada se considera adjunta a MPI_COMM_SELF y llamará al manejador de errores de MPI asociado. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se utiliza exclusivamente el Modelo de Sesiones) el error eleva el manejador de errores inicial. El manejador de errores inicial puede cambiarse llamando a MPI_Comm_set_errhandler en MPI_COMM_SELF cuando se utiliza el modelo World, o el argumento de CLI mpi_initial_errhandler a mpiexec o la clave de información a MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no se ha configurado ningún otro manejador de errores apropiado, entonces se llama al manejador de errores MPI_ERRORS_RETURN para las funciones de E/S de MPI y al manejador de errores MPI_ERRORS_ABORT para todas las demás funciones de MPI.

Open MPI incluye tres manejadores de errores predefinidos que se pueden utilizar:

  • MPI_ERRORS_ARE_FATAL Causa que el programa aborte todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT Un manejador de errores que se puede invocar en un comunicador, ventana, archivo o sesión. Cuando se llama en un comunicador, actúa como si se hubiera llamado a MPI_Abort en ese comunicador. Si se llama en una ventana o archivo, actúa como si se hubiera llamado a MPI_Abort en un comunicador que contiene el grupo de procesos en la ventana o archivo correspondiente. Si se llama en una sesión, aborta solo el proceso local.
  • MPI_ERRORS_RETURN Devuelve un código de error a la aplicación.

Las aplicaciones MPI también pueden implementar sus propios manejadores de errores llamando a:

  • MPI_Comm_create_errhandler luego MPI_Comm_set_errhandler
  • MPI_File_create_errhandler luego MPI_File_set_errhandler
  • MPI_Session_create_errhandler luego MPI_Session_set_errhandler o en MPI_Session_init
  • MPI_Win_create_errhandler luego MPI_Win_set_errhandler

Tenga en cuenta que MPI no garantiza que un programa MPI pueda continuar después de un error.

Consulte la página man de MPI para obtener una lista completa de los códigos de error de MPI.

Consulte la sección Manejo de Errores del estándar MPI-3.1 para obtener más información.
