MPI_Allgather, MPI_Iallgather, MPI_Allgather_init - Reúne datos de todos los procesos y los distribuye a todos los procesos

PARÁMETROS DE ENTRADA

  • sendbuf: Dirección de inicio del búfer de envío (elección).
  • sendcount: Número de elementos en el búfer de envío (entero).
  • sendtype: Tipo de datos de los elementos del búfer de envío (manejador).
  • recvbuf: Dirección de inicio del búfer de recepción (elección).
  • recvcount: Número de elementos recibidos de cualquier proceso (entero).
  • recvtype: Tipo de datos de los elementos del búfer de recepción (manejador).
  • comm: Comunicador (manejador).
  • info: Información (manejador, solo persistente).

PARÁMETROS DE SALIDA

  • recvbuf: Dirección del búfer de recepción (elección).
  • request: Solicitud (manejador, solo no bloqueante).
  • ierror: Solo Fortran: Estado de error (entero).

DESCRIPCIÓN

MPI_Allgather es similar a MPI_Gather, excepto que todos los procesos reciben el resultado, en lugar de solo la raíz. En otras palabras, todos los procesos contribuyen al resultado y todos los procesos reciben el resultado.

La firma de tipo asociada con sendcount, sendtype en un proceso debe ser igual a la firma de tipo asociada con recvcount, recvtype en cualquier otro proceso.

El resultado de una llamada a MPI_Allgather es como si todos los procesos ejecutaran n llamadas a

MPI_Gather(sendbuf, sendcount, sendtype, recvbuf, recvcount,
           recvtype, root, comm);
// para root = 0 , ..., n-1.

Las reglas para el uso correcto de MPI_Allgather se encuentran fácilmente a partir de las reglas correspondientes para MPI_Gather.

Ejemplo: La versión all-gather del Ejemplo 1 en MPI_Gather. Usando MPI_Allgather, reuniremos 100 enteros de cada proceso del grupo en cada proceso.

MPI_Comm comm;
int gsize,sendarray[100];
int *rbuf;
...
MPI_Comm_size( comm, &gsize);
rbuf = (int *)malloc(gsize*100*sizeof(int));
MPI_Allgather( sendarray, 100, MPI_INT, rbuf, 100, MPI_INT, comm);

Después de la llamada, cada proceso tiene la concatenación a nivel de grupo de los conjuntos de datos.

USO DE LA OPCIÓN IN-PLACE

Cuando el comunicador es un intracommunicator, puede realizar una operación de all-gather in-place (el búfer de salida se utiliza como búfer de entrada). Utilice la variable MPI_IN_PLACE como valor de sendbuf. En este caso, se ignoran sendcount y sendtype. Se asume que los datos de entrada de cada proceso se encuentran en el área donde ese proceso recibiría su propia contribución al búfer de recepción. Específicamente, el resultado de una llamada a MPI_Allgather que utilizó la opción in-place es idéntico al caso en el que todos los procesos ejecutaron n llamadas a

MPI_Allgather( MPI_IN_PLACE, 0, MPI_DATATYPE_NULL, recvbuf,
               recvcount, recvtype, root, comm )
// para root =0, ... , n-1.

Tenga en cuenta que MPI_IN_PLACE es un tipo especial de valor; tiene las mismas restricciones de uso que MPI_BOTTOM.

Debido a que la opción in-place convierte el búfer de recepción en un búfer de envío y recepción, una vinculación de Fortran que incluya INTENT debe marcarlos como INOUT, no OUT.

CUANDO EL COMUNICADOR ES UN INTER-COMUNICADOR

Cuando el comunicador es un inter-comunicador, la operación de recolección ocurre en dos fases. Los datos se recogen de todos los miembros del primer grupo y se reciben por todos los miembros del segundo grupo. Luego, los datos se recogen de todos los miembros del segundo grupo y se reciben por todos los miembros del primer grupo. Sin embargo, la operación no tiene por qué ser simétrica. El número de elementos enviados por los procesos del primer grupo no tiene por qué ser igual al número de elementos enviados por los procesos del segundo grupo. Puede mover datos en una sola dirección asignando a sendcount un valor de 0 para la comunicación en la dirección inversa.

ERRORES

Casi todas las rutinas MPI devuelven un valor de error; las rutinas C como resultado de la función y las rutinas Fortran en el último argumento.

Antes de que se devuelva el valor de error, se llama al manejador de errores MPI actual asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo). Si no hay ningún objeto de comunicación asociado con la llamada MPI, entonces la llamada se considera adjunta a MPI_COMM_SELF y llamará al manejador de errores MPI asociado. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se utiliza exclusivamente el Modelo de Sesiones) el error invoca al manejador de errores inicial. El manejador de errores inicial se puede cambiar llamando a MPI_Comm_set_errhandler en MPI_COMM_SELF cuando se utiliza el modelo World, o el argumento de información mpi_initial_errhandler a mpiexec o la clave de información para MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no se ha establecido ningún otro manejador de errores adecuado, entonces se llama al manejador de errores MPI_ERRORS_RETURN para la función I/O de MPI.

  • MPI_Win_create_errhandler luego MPI_Win_set_errhandler

DESCRIPCIÓN

Descripción de los manejadores de errores:

  • MPI_ERRORS_ARE_FATAL Desactiva el manejo de errores en el programa, abortando todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT Manejador de errores invocable en un comunicador, ventana, archivo o sesión. Cuando se invoca en un comunicador, actúa como si se hubiera invocado MPI_Abort en ese comunicador. Si se invoca en una ventana o archivo, actúa como si se hubiera invocado MPI_Abort en un comunicador que contiene los procesos en la correspondiente ventana o archivo. Si se invoca en una sesión, aborta solo el proceso local.
  • MPI_ERRORS_RETURN Devuelve el código de error a la aplicación.
