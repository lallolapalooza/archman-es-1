MPI_Put, MPI_Rput - Copia de datos de la memoria de origen a la de destino.

Sintaxis

Sintaxis C

#include <mpi.h>
MPI_Put(const void *origin_addr, int origin_count, MPI_Datatype
     origin_datatype, int target_rank, MPI_Aint target_disp,
     int target_count, MPI_Datatype target_datatype, MPI_Win win)
MPI_Rput(const void *origin_addr, int origin_count, MPI_Datatype
      origin_datatype, int target_rank, MPI_Aint target_disp,
      int target_count, MPI_Datatype target_datatype, MPI_Win win,
      MPI_Request *request)

Parámetros de entrada

  • origin_addr: Dirección inicial del buffer de origen (constante).
  • origin_count: Número de entradas en el buffer de origen (entero no negativo).
  • origin_datatype: Tipo de datos de cada entrada en el buffer de origen (manejador).
  • target_rank: Rango del destino (entero no negativo).
  • target_disp: Desplazamiento desde el inicio de la ventana hasta el buffer de destino (entero no negativo).
  • target_count: Número de entradas en el buffer de destino (entero no negativo).
  • target_datatype: Tipo de datos de cada entrada en el buffer de destino (manejador).
  • win: Objeto de ventana utilizado para la comunicación (manejador).

Parámetro de salida

  • request: Solicitud MPI_Rput.
  • ierror: Solo en Fortran: Estado de error (entero).

Descripción

MPI_Put envía origin_count entradas consecutivas del tipo especificado por origin_datatype, comenzando en origin_addr en el nodo de origen a la memoria del nodo de destino especificado por win y target_rank.

Los datos se escriben en el buffer de destino en la dirección target_addr ^ window_base + target_disp * disp_unit, donde window_base y disp_unit son la dirección base y la unidad de desplazamiento de la ventana definida por el proceso de destino.

El buffer de destino se especifica mediante los argumentos target_count y target_datatype.

La transferencia de datos es la misma que si el proceso de origen ejecutara una operación de envío con los argumentos origin_addr, origin_count, origin_datatype, target_rank, tag, comm, y el proceso de destino ejecutara una operación de recepción con los argumentos target_addr, target_count, target_datatype, source, tag, comm, donde target_addr es la dirección del buffer de destino calculada como se explicó anteriormente, y comm es un comunicador para el grupo de win.

La comunicación debe satisfacer las mismas restricciones que una comunicación de este tipo. El target_datatype no puede especificar entradas superpuestas en el buffer de destino. La mensajería enviada debe caber, sin truncar, en el buffer de destino. Además, el buffer de destino debe caber en el buffer de destino. Adicionalmente, solo los procesos dentro del mismo buffer pueden acceder al buffer de destino.

El target_datatype es un manejador de un objeto de tipo de datos definido en el proceso de origen. Sin embargo, este objeto se interpreta en el proceso de destino: el resultado es el mismo que si el objeto de tipo de datos de destino fuera definido en el proceso de destino, por la misma secuencia de llamadas que se usó en el proceso de origen para definirlo. El tipo de datos de destino solo debe contener desplazamientos relativos, no direcciones absolutas. La misma regla se aplica para get y accumulate.

MPI_Rput es similar a MPI_Put, pero asigna una solicitud de comunicación (el argumento request) a un manejador de solicitud (el argumento request). El final de una operación MPI_Rput (es decir, después de que se complete el test o la espera) indica que el remitente ya puede actualizar las ubicaciones en el buffer origin_addr. No indica que los datos estén disponibles en el buffer de destino. Si es necesario esperar la completación remota, se pueden usar MPI_Win_flush, MPI_Win_flush_all, MPI_Win_unlock, o MPI_Win_unlock_all.

Notas

El target_datatype es un manejador de un objeto de tipo de datos definido en el proceso de origen, incluso si define una disposición de datos en la memoria del proceso de destino. Esto no causa problemas en un entorno homogéneo o heterogéneo, siempre que se utilicen tipos de datos portables (los tipos de datos portables están definidos en la Sección 2.4 del estándar MPI-2).

El rendimiento de una transferencia de datos puede verse afectado significativamente, en algunos sistemas, por la elección de la ubicación de la ventana y la forma y ubicación de los buffers de origen y destino: las transferencias a un buffer de destino en una ventana reservada por MPI_Alloc_mem pueden ser mucho más rápidas en sistemas con memoria compartida; las transferencias de buffers consecutivos serán más rápidas en la mayoría de los sistemas, incluso en muchos; la alineación de los buffers de comunicación también puede afectar el rendimiento.

Errores

La mayoría de las rutinas MPI devuelven un valor de error; en las rutinas C, el valor de retorno es el resultado de la función, y en las rutinas Fortran, el último argumento es el valor de error.

Antes de que se devuelva el valor de error, se llama al manejador de errores asociado con el objeto de comunicación (por ejemplo, communicator, window, file). Si no hay objeto de comunicación asociado con la llamada MPI, la llamada se considera asociada con MPI_COMM_SELF y llamará al manejador de errores asociado. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se usa el Modelo de Sesiones exclusivamente), el error invoca al manejador de errores inicial. El manejador de errores inicial puede cambiarse llamando a MPI_Comm_set_errhandler sobre MPI_COMM_SELF cuando se utiliza el Modelo del Mundo, o al argumento CLI mpi_initial_errhandler de mpiexec o a la clave de información de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no hay otro manejador de errores adecuado, se llama al manejador de errores MPI_ERRORS_RETURN para las funciones de I/O de MPI y al manejador de errores MPI_ERRORS_ABORT para todas las demás funciones de MPI.

Open MPI incluye tres manejadores de errores predeterminados que pueden ser utilizados:

  • MPI_ERRORS_ARE_FATAL Causa que el programa aborte todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT Un manejador de errores que puede ser invocado en un communicator

DESCRIPCIÓN

La rutina MPI_Rput no bloqueante envía un mensaje de una memoria remota a otra memoria remota. La operación se inicia de forma asíncrona. El llamante puede continuar la ejecución y el envío puede completarse en un momento posterior.

Los descriptores de ventana se utilizan para proporcionar información sobre la memoria remota para el acceso de memoria remota (RMA). Los descriptores de ventana se crean utilizando las rutinas MPI_Win_create, MPI_Win_allocate, MPI_Win_create_hook, MPI_Win_shared_query, etc.

El argumento origin_addr debe referirse a una dirección dentro de una región de memoria que sea accesible para RMA en el proceso de origen. La longitud total de los datos enviados desde el origen debe ser origin_count elementos de tamaño origin_datatype.

El argumento target_addr debe referirse a una dirección dentro de una región de memoria que sea accesible para RMA en el proceso de destino. La longitud total de los datos recibidos en el destino debe ser target_count elementos de tamaño target_datatype.

Los argumentos origin_datatype y target_datatype deben ser tipos de datos MPI válidos. El argumento win debe ser un descriptor de ventana válido que haga referencia a una ventana creada en el proceso de origen, y que contenga el grupo de procesos que incluye al proceso de destino.

La llamada a MPI_Rput inicia la operación de envío.

Los objetos de tipo de datos de origen y destino se definen en el proceso de origen. Los objetos de tipo de datos de origen y destino pueden ser diferentes, siempre que el número total de bytes enviados desde el origen sea igual al número total de bytes recibidos en el destino. Por ejemplo, el origen puede enviar un vector de elementos mientras que el destino recibe un vector de elementos diferentes, siempre que el tamaño total de los datos coincida.

El desplazamiento total en el origen es origin_count * sizeof(origin_datatype). El desplazamiento total en el destino es target_count * sizeof(target_datatype). Estos desplazamientos totales deben ser iguales. El usuario es responsable de garantizar que los desplazamientos de origen y destino sean compatibles.

La memoria en la dirección origin_addr no debe modificarse hasta que la operación de envío se complete. La memoria en la dirección target_addr no debe modificarse hasta que la operación de envío se complete.

El argumento request devuelve un objeto de solicitud que se puede usar para verificar la finalización de la operación de envío y liberar los recursos asociados con ella. La finalización de la operación de envío se puede verificar llamando a MPI_Wait o MPI_Test.

El argumento assert se utiliza para indicar al sistema MPI que ciertas condiciones se mantienen durante la ejecución. Consulte la sección de asserts de la especificación MPI para obtener más detalles.

MANEJO DE ERRORES

La rutina MPI_Rput devuelve el código de error permitido.

  • MPI_SUCCESS: Éxito.
  • MPI_ERR_WIN: El descriptor de ventana no es válido.
  • MPI_ERR_REDUCE_DATATYPE: Los tipos de datos de origen y destino no son compatibles.
  • MPI_ERR_COUNT: El número de elementos es incorrecto.
  • MPI_ERR_PERM: Se intentó acceder a una dirección de memoria sin permiso.
  • MPI_ERR_REQUEST: La solicitud es inválida.
  • MPI_ERR_RMA_ATTACH: No se pudo adjuntar a la memoria remota.
  • MPI_ERR_RMA_FLUSH: El dispositivo de RMA no se pudo vaciar.
  • MPI_ERR_RMA_SYSCALL: Error en una llamada del sistema RMA.
  • MPI_ERR_BUFFER: El búfer de origen o destino no es válido.
  • MPI_ERR_OTHER: Otro error.

Cuando se llama a un manejador de errores con un descriptor de ventana, este actúa como si se hubiera llamado a MPI_Abort en un comunicador que contiene el grupo de procesos en la ventana correspondiente. Si se llama en un comunicador, actúa como si MPI_Abort se hubiera llamado en ese comunicador. Si se llama en un archivo, actúa como si MPI_Abort se hubiera llamado en un comunicador que contiene el grupo de procesos en el archivo correspondiente. Si se llama en una sesión, solo aborta el proceso local.

  • MPI_ERRORS_ARE_FATAL Se abortará todo el proceso.
  • MPI_ERRORS_RETURN Devolverá un código de error a la aplicación.

Las aplicaciones MPI también pueden implementar sus propios manejadores de errores llamando a:

  • MPI_Comm_create_errhandler y luego MPI_Comm_set_errhandler
  • MPI_File_create_errhandler y luego MPI_File_set_errhandler
  • MPI_Session_create_errhandler y luego MPI_Session_set_errhandler o en MPI_Session_init
  • MPI_Win_create_errhandler y luego MPI_Win_set_errhandler

Tenga en cuenta que MPI no garantiza que un programa MPI pueda continuar después de un error.
