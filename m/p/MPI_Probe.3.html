MPI_PROBE(3) Open MPI MPI_PROBE(3)

MPI_Probe — Prueba bloqueante para un mensaje.

SINTAXIS

Sintaxis C

#include <mpi.h>
int MPI_Probe(int source, int tag, MPI_Comm comm, MPI_Status *status)

Sintaxis Fortran

USE MPI
! o la forma antigua: INCLUDE 'mpif.h'
MPI_PROBE(SOURCE, TAG, COMM, STATUS, IERROR)
     INTEGER SOURCE, TAG, COMM, STATUS(MPI_STATUS_SIZE), IERROR

Sintaxis Fortran 2008

USE mpi_f08
MPI_Probe(source, tag, comm, status, ierror)
     INTEGER, INTENT(IN) :: source, tag
     TYPE(MPI_Comm), INTENT(IN) :: comm
     TYPE(MPI_Status) :: status
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARÁMETROS DE ENTRADA

  • source: Rango de origen o MPI_ANY_SOURCE (entero).
  • tag: Valor de etiqueta o MPI_ANY_TAG (entero).
  • comm: Comunicador (handle).

PARÁMETROS DE SALIDA

  • status: Objeto de estado (estado).
  • ierror: Solo Fortran: Estado de error (entero).

DESCRIPCIÓN

Las operaciones MPI_Probe y MPI_Iprobe permiten verificar mensajes entrantes, sin recibirlos realmente. El usuario puede entonces decidir cómo recibirlos, basándose en la información devuelta por la sonda en la variable de estado. Por ejemplo, el usuario puede asignar memoria para el búfer de recepción, de acuerdo con la longitud del mensaje sondado.

MPI_Probe se comporta como MPI_Iprobe excepto que es una llamada bloqueante que solo retorna después de que se ha encontrado un mensaje coincidente.

Si su aplicación no necesita examinar el campo status, puede ahorrar recursos utilizando la constante predefinida MPI_STATUS_IGNORE como un valor especial para el argumento status.

La semántica de MPI_Probe y MPI_Iprobe garantiza el progreso: Si un proceso ha emitido una llamada a MPI_Probe y algún proceso ha iniciado un envío que coincide con la sonda, entonces la llamada a MPI_Probe retornará, a menos que el mensaje sea recibido por otra operación de recepción concurrente (que se ejecuta en otro hilo en el proceso que sondea). De manera similar, si un proceso espera activamente con MPI_Iprobe y se ha emitido un mensaje coincidente, entonces la llamada a MPI_Iprobe eventualmente devolverá flag = true a menos que el mensaje sea recibido por otra operación de recepción concurrente.

Ejemplo 1: Usar una sonda bloqueante para esperar un mensaje entrante.

CALL MPI_COMM_RANK(comm, rank, ierr)
IF (rank == 0) THEN
   CALL MPI_SEND(i, 1, MPI_INTEGER, 2, 0, comm, ierr)
ELSE IF(rank == 1) THEN
   CALL MPI_SEND(x, 1, MPI_REAL, 2, 0, comm, ierr)
ELSE   ! rank == 2
   DO i=1, 2
      CALL MPI_PROBE(MPI_ANY_SOURCE, 0,
                     comm, status, ierr)
      IF (status(MPI_SOURCE) = 0) THEN
         CALL MPI_RECV(i, 1, MPI_INTEGER, 0, 0, status, ierr)
      ELSE
         CALL MPI_RECV(x, 1, MPI_REAL, 1, 0, status, ierr)
      END IF
   END DO
END IF

Cada mensaje se recibe con el tipo correcto.

Ejemplo 2: Un programa similar al ejemplo anterior, pero con un problema.

CALL MPI_COMM_RANK(comm, rank, ierr)
IF (rank == 0) THEN
   CALL MPI_SEND(i, 1, MPI_INTEGER, 2, 0, comm, ierr)
ELSE IF(rank == 1) THEN
   CALL MPI_SEND(x, 1, MPI_REAL, 2, 0, comm, ierr)
ELSE
   DO i=1, 2
      CALL MPI_PROBE(MPI_ANY_SOURCE, 0,
                     comm, status, ierr)
      IF (status(MPI_SOURCE) == 0) THEN
         CALL MPI_RECV(i, 1, MPI_INTEGER, MPI_ANY_SOURCE, &
                       0, status, ierr)
      ELSE
         CALL MPI_RECV(x, 1, MPI_REAL, MPI_ANY_SOURCE, &
                       0, status, ierr)
      END IF
   END DO
END IF

Hemos modificado ligeramente el Ejemplo 2, utilizando MPI_ANY_SOURCE como argumento de origen en las dos llamadas de recepción en las sentencias etiquetadas 100 y 200. El programa ahora es incorrecto: la operación de recepción puede recibir un mensaje distinto del mensaje sondado por la llamada anterior a MPI_Probe.

ERRORES

Casi todas las rutinas MPI devuelven un valor de error; en rutinas C, como resultado de la función y en rutinas Fortran, en el último argumento.

Antes de que se devuelva el valor de error, se llama al manejador de errores MPI actual asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo). Si no hay un objeto de comunicación asociado con la llamada MPI, entonces la llamada se considera adjunta a MPI_COMM_SELF y llamará al manejador de errores MPI asociado. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se usa exclusivamente el Modelo de Sesiones) el error eleva el manejador de errores inicial. El manejador de errores inicial puede ser cambiado llamando a MPI_Comm_set_errhandler en MPI_COMM_SELF cuando se usa el modelo World, o el argumento de línea de comandos mpiexec mpi_initial_errhandler o la clave info de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no se ha establecido ningún otro manejador de errores apropiado, entonces el manejador de errores MPI_ERRORS_RETURN se llama para las funciones de E/S MPI y el manejador de errores MPI_ERRORS_ABORT se llama para todas las demás funciones MPI.

Open MPI incluye tres manejadores de errores predefinidos que se pueden utilizar:

  • MPI_ERRORS_ARE_FATAL Provoca que el programa aborte todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT Un manejador de errores que se puede invocar en un comunicador, ventana, archivo o sesión. Cuando se llama en un comunicador, actúa como si se hubiera llamado a MPI_Abort en ese comunicador. Si se llama en una ventana o archivo, actúa como si se hubiera llamado a MPI_Abort en un comunicador que contiene el grupo de procesos de la ventana o archivo correspondiente. Si se llama en una sesión, solo aborta el proceso local.
  • MPI_ERRORS_RETURN Devuelve un código de error a la aplicación.

Las aplicaciones MPI también pueden implementar sus propios manejadores de errores llamando a:

  • MPI_Comm_create_errhandler luego MPI_Comm_set_errhandler
  • MPI_File_create_errhandler luego MPI_File_set_errhandler
  • MPI_Session_create_errhandler luego MPI_Session_set_errhandler o en MPI_Session_init
  • MPI_Win_create_errhandler luego MPI_Win_set_errhandler

Tenga en cuenta que MPI no garantiza que un programa MPI pueda continuar después de un error.

Consulte la página del manual de MPI para obtener una lista completa de los códigos de error de MPI.

Consulte la sección de Manejo de Errores del estándar MPI-3.1 para obtener más información.

Tenga en cuenta que según la sección "Estado de Retorno" en el capítulo "Comunicación Punto a Punto" de la Norma MPI, los errores de MPI en mensajes consultados por MPI_Probe no establecen el campo status.MPI_ERROR en el status devuelto. El código de error siempre se pasa al manejador de errores de back-end y puede pasarse al llamador a través del valor de retorno de MPI_Probe si el manejador de errores de back-end lo devuelve. Por ejemplo, el manejador de errores predefinido de MPI MPI_ERRORS_RETURN exhibe este comportamiento.
