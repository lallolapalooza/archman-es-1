MPI_Win_allocate(3)

Paquete: openmpi

Licencias: BSD-3-Clause AND LicenseRef-MPICH

MPI_WIN_ALLOCATE(3) Open MPI MPI_WIN_ALLOCATE(3)

MPI_Win_allocate — Llamada MPI de una cara que asigna memoria y devuelve un objeto de ventana para operaciones RMA.

SINTAXIS

Sintaxis C

#include <mpi.h>
int MPI_Win_allocate (MPI_Aint size, int disp_unit, MPI_Info info,
                      MPI_Comm comm, void *baseptr, MPI_Win *win)

Sintaxis Fortran

USE MPI
! o la forma más antigua: INCLUDE 'mpif.h'
MPI_WIN_ALLOCATE(SIZE, DISP_UNIT, INFO, COMM, BASEPTR, WIN, IERROR)
     INTEGER(KIND=MPI_ADDRESS_KIND) SIZE, BASEPTR
     INTEGER DISP_UNIT, INFO, COMM, WIN, IERROR

Sintaxis Fortran 2008

USE mpi_f08
MPI_Win_allocate(size, disp_unit, info, comm, baseptr, win, ierror)
     USE, INTRINSIC :: ISO_C_BINDING, ONLY : C_PTR
     INTEGER(KIND=MPI_ADDRESS_KIND), INTENT(IN) :: size
     INTEGER, INTENT(IN) :: disp_unit
     TYPE(MPI_Info), INTENT(IN) :: info
     TYPE(MPI_Comm), INTENT(IN) :: comm
     TYPE(C_PTR), INTENT(OUT) :: baseptr
     TYPE(MPI_Win), INTENT(OUT) :: win
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARÁMETROS DE ENTRADA

  • size: Tamaño de la ventana en bytes (entero no negativo).
  • disp_unit: Tamaño de unidad local para los desplazamientos, en bytes (entero positivo).
  • info: Argumento de información (manejador).
  • comm: Comunicador (manejador).

PARÁMETROS DE SALIDA

  • baseptr: Dirección inicial de la ventana.
  • win: Objeto de ventana devuelto por la llamada (manejador).
  • ierror: Solo Fortran: Estado del error (entero).

DESCRIPCIÓN

MPI_Win_allocate es una llamada colectiva ejecutada por todos los procesos del grupo de comm. En cada proceso, asigna memoria de al menos size bytes, devuelve un puntero a ella y devuelve un objeto de ventana que puede ser utilizado por todos los procesos en comm para realizar operaciones RMA. La memoria devuelta consiste en size bytes locales a cada proceso, comenzando en la dirección baseptr y está asociada a la ventana como si el usuario hubiera llamado a MPI_Win_create sobre memoria existente. El argumento size puede ser diferente en cada proceso y size = 0 es válido; sin embargo, una biblioteca podría asignar y exponer más memoria para crear una asignación rápida y globalmente simétrica. La discusión y las justificaciones de MPI_Alloc_mem y MPI_Free_mem en la sección 8.2 de MPI-3.1 también se aplican a MPI_Win_allocate; en particular, véase la justificación en la sección 8.2 de MPI-3.1 para una explicación del tipo utilizado para baseptr.

El argumento de unidad de desplazamiento se proporciona para facilitar la aritmética de direcciones en las operaciones RMA: el argumento de desplazamiento de destino de una operación RMA se escala por el factor disp_unit especificado por el proceso de destino, en la creación de la ventana.

Para las claves de información admitidas, consulte MPI_Win_create.

NOTAS

Las opciones comunes para disp_unit son 1 (sin escala) y (en sintaxis C) sizeof(type), para una ventana que consiste en una matriz de elementos del tipo type. Esta última opción permitirá utilizar índices de matriz en llamadas RMA, y que estos se escalen correctamente a desplazamientos de bytes, incluso en un entorno heterogéneo.

Llamar a MPI_Win_free liberará la memoria asignada por MPI_Win_allocate. Por lo tanto, es erróneo liberar manualmente baseptr.

NOTAS C

Aunque baseptr es de tipo void *, esto es para permitir un uso fácil de cualquier objeto puntero para este parámetro. Este argumento es en realidad de tipo void **.

ERRORES

Casi todas las rutinas MPI devuelven un valor de error; las rutinas C como resultado de la función y las rutinas Fortran en el último argumento.

Antes de que se devuelva el valor de error, se llama al controlador de errores MPI actual asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo). Si no hay ningún objeto de comunicación asociado con la llamada MPI, entonces la llamada se considera adjunta a MPI_COMM_SELF y llamará al controlador de errores MPI asociado. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se utiliza exclusivamente el Modelo de Sesiones), el error invoca al controlador de errores inicial. El controlador de errores inicial se puede cambiar llamando a MPI_Comm_set_errhandler en MPI_COMM_SELF cuando se utiliza el modelo World, o el argumento de información mpi_initial_errhandler para mpiexec o clave de información para MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no se ha establecido ningún otro controlador de errores apropiado, entonces se llama al controlador de errores MPI_ERRORS_RETURN para las funciones de E/S de MPI y al controlador de errores MPI_ERRORS_ABORT para todas las demás funciones de MPI.

Open MPI incluye tres controladores de errores predefinidos que se pueden utilizar:

  • MPI_ERRORS_ARE_FATAL Provoca que el programa aborte todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT Un controlador de errores que se puede invocar en un comunicador, ventana, archivo o sesión. Cuando se llama en un comunicador, actúa como si se hubiera llamado a MPI_Abort en ese comunicador. Si se llama en una ventana o archivo, actúa como si se hubiera llamado a MPI_Abort en un comunicador que contiene el grupo de procesos de la ventana o archivo correspondiente. Si se llama en una sesión, solo aborta el proceso local.
  • MPI_ERRORS_RETURN Devuelve un código de error a la aplicación.

Las aplicaciones MPI también pueden implementar sus propios controladores de errores llamando a:

  • MPI_Comm_create_errhandler luego MPI_Comm_set_errhandler
  • MPI_File_create_errhandler luego MPI_File_set_errhandler
  • MPI_Session_create_errhandler luego MPI_Session_set_errhandler o en MPI_Session_init
  • MPI_Win_create_errhandler luego MPI_Win_set_errhandler

Tenga en cuenta que MPI no garantiza que un programa MPI pueda continuar después de un error.

Consulte la página del manual de MPI para obtener una lista completa de los códigos de error de MPI.

Consulte la sección de Manejo de Errores del estándar MPI-3.1 para obtener más información.

MPI_Win_allocate(3)

NOMBRE

MPI_Win_allocate - Asigna memoria para una ventana de memoria remota

SINOPSIS

#include <mpi.h>

int MPI_Win_allocate(MPI_Comm comm, MPI_Aint size, int disp_unit,
                     MPI_Info info, MPI_Win *win);

PARÁMETROS DE ENTRADA

  • comm: Comunicador MPI que abarca la creación de la ventana (iniciar la llamada).
  • size: Longitud, en bytes, del espacio de memoria que se asignará.
  • disp_unit: Unidad de desplazamiento (en bytes). Las direcciones de los objetos dentro del espacio de memoria de la ventana se expresarán como múltiplos de esta unidad.
  • info: Objeto de información utilizado para especificar los atributos de la ventana.

PARÁMETROS DE SALIDA

  • win: Ventana que se creará.

DESCRIPCIÓN

La rutina MPI_Win_allocate asigna un espacio de memoria de tamañosize bytes en el proceso que realiza la llamada. La memoria asignada se puede acceder de forma remota utilizando el objeto de ventana win que se devuelve. El parámetro disp_unit especifica la unidad de desplazamiento para la ventana. Las direcciones de los objetos dentro del espacio de memoria de la ventana se expresarán como múltiplos de esta unidad. Por ejemplo, si disp_unit es 1, las direcciones se expresarán en bytes. Si disp_unit es el tamaño de un tipo de datos, las direcciones se expresarán como el número de elementos de ese tipo de datos. El parámetro info se puede usar para especificar el comportamiento de asignación, como las restricciones de alineación de memoria.

La memoria asignada se puede liberar más tarde usando MPI_Win_free.

NOTAS

Esta rutina está diseñada para simplificar la asignación de memoria para ventanas de memoria remota. Los usuarios no necesitan preocuparse por la gestión de la memoria o las marcas de acceso a la memoria. La memoria asignada por esta rutina será accesible para todos los procesos del comunicador comm.

NOTAS C

No hay notas específicas de C.

ERRORES

Cuando ocurre un error, todas las llamadas de rutina MPI fallan. El archivo de registro de errores de MPI o la salida de stderr se utilizarán para identificar el tipo de error que se ha producido.
