PARÁMETROS DE ENTRADA

  • sendbuf: Dirección de inicio del búfer de envío (elección).
  • recvcount: Conteo de elementos por bloque (entero no negativo).
  • datatype: Tipo de dato de los elementos del búfer de entrada (manejador).
  • op: Operación (manejador).
  • comm: Comunicador (manejador).
  • info: Información (manejador, solo persistente).

PARÁMETROS DE SALIDA

  • recvbuf: Dirección de inicio del búfer de recepción (elección).
  • request: Solicitud (manejador, solo no bloqueante).
  • ierror: Solo Fortran: Estado de error (entero).

DESCRIPCIÓN

MPI_Reduce_scatter_block primero realiza una reducción elemento a elemento en un vector de count = n * recvcount elementos en el búfer de envío definido por sendbuf, count y datatype, usando la operación op, donde n es el número de procesos en el grupo de comm. A continuación, el vector de resultados resultante se divide en n segmentos disjuntos, donde n es el número de procesos en el grupo. Cada segmento contiene recvcount elementos. El i-ésimo segmento se envía al proceso i y se almacena en el búfer de recepción definido por recvbuf, recvcount y datatype.

USO DE LA OPCIÓN IN-PLACE

Cuando el comunicador es un intracominicador, puede realizar una operación de reduce-scatter in-place (el búfer de salida se utiliza como búfer de entrada). Utilice la variable MPI_IN_PLACE como valor de sendbuf. En este caso, los datos de entrada se toman de la parte superior del búfer de recepción. El área ocupada por los datos de entrada puede ser más larga o más corta que los datos llenados por los datos de salida.

CUANDO EL COMUNICADOR ES UN INTERCOMUNICADOR

Cuando el comunicador es un intercomunicador, la operación de reduce-scatter se realiza en dos fases. Primero, el resultado de la reducción realizada en los datos proporcionados por los procesos en el primer grupo se dispersa entre los procesos en el segundo grupo. Luego ocurre lo inverso: la reducción realizada en los datos proporcionados por los procesos en el segundo grupo se dispersa entre los procesos en el primer grupo. Para cada grupo, todos los procesos proporcionan el mismo argumento recvcounts, y la suma de los valores de recvcounts debe ser la misma para ambos grupos.

NOTAS SOBRE OPERACIONES COLECTIVAS

Las funciones de reducción ( MPI_Op ) no devuelven un valor de error. Por lo tanto, si las funciones detectan un error, lo único que pueden hacer es llamar a MPI_Abort o ignorar silenciosamente el problema. Por lo tanto, si cambia el manejador de errores de MPI_ERRORS_ARE_FATAL a otro, por ejemplo, MPI_ERRORS_RETURN , entonces es posible que no se indique ningún error.

La razón de esto son los problemas de rendimiento para asegurar que todas las rutinas colectivas devuelvan el mismo valor de error.

ERRORES

Casi todas las rutinas de MPI devuelven un valor de error; las rutinas C como resultado de la función y las rutinas Fortran en el último argumento.

Antes de que se devuelva el valor de error, se llama al manejador de errores de MPI actual asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo). Si no hay ningún objeto de comunicación asociado con la llamada MPI, entonces la llamada se considera adjunta a MPI_COMM_SELF y llamará al manejador de errores de MPI asociado. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se usa exclusivamente el Modelo de Sesiones) el error invoca el manejador de errores inicial. El manejador de errores inicial se puede cambiar llamando a MPI_Comm_set_errhandler en MPI_COMM_SELF al usar el modelo World, o el argumento CLI mpi_initial_errhandler para mpiexec o la clave de información para MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no se ha establecido ningún otro manejador de errores apropiado, entonces se llama al manejador de errores MPI_ERRORS_RETURN para las funciones de E/S de MPI y al manejador de errores MPI_ERRORS_ABORT para todas las demás funciones de MPI.

Open MPI incluye tres manejadores de errores predefinidos que se pueden utilizar:

  • MPI_ERRORS_ARE_FATAL Provoca que el programa aborte todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT Un manejador de errores que se puede invocar en un comunicador, ventana, archivo o sesión. Cuando se llama en un comunicador, actúa como si se hubiera llamado a MPI_Abort en ese comunicador. Si se llama en una ventana o archivo, actúa como si se hubiera llamado a MPI_Abort en un comunicador que contiene el grupo de procesos en la ventana o archivo correspondiente. Si se llama en una sesión, solo aborta el proceso local.
  • MPI_ERRORS_RETURN Devuelve un código de error a la aplicación.

Las aplicaciones MPI también pueden implementar sus propios manejadores de errores llamando a:

  • MPI_Comm_create_errhandler luego MPI_Comm_set_errhandler
  • MPI_File_create_errhandler luego MPI_File_set_errhandler

MPI_Reduce_scatter_block

NAME

MPI_Reduce_scatter_block - Combines a block of data from all processes in a communicator and distributes the results to all processes in a communicator.

SYNTAX

C++

#include <mpi.h>
int MPI::Reduce_scatter_block(const void* sendbuf, void* recvbuf, int recvcount,
                              const MPI::Datatype& sendtype,
                              MPI::Op op)

Fortran

INCLUDE "mpif.h"
INTEGER FUNCTION MPI_REDUCE_SCATTER_BLOCK(sendbuf, recvbuf, recvcount,
                                          sendtype, op)
    <type> sendbuf(*)
    <type> recvbuf(*)
    INTEGER recvcount
    INTEGER sendtype, op
END FUNCTION MPI_REDUCE_SCATTER_BLOCK

C

#include <mpi.h>
int MPI_Reduce_scatter_block(const void* sendbuf, void* recvbuf, int recvcount,
                             MPI_Datatype sendtype, MPI_Op op)

INPUT PARAMETERS

• sendbuf
Puntero a buffer de envío (en todas las invocaciones, excepto si el proceso es un proceso raíz).
• recvbuf
Puntero a buffer de recepción (en todas las invocaciones).
• recvcount
Número de elementos de tipo de datos de entrada en el buffer de recepción (en todas las invocaciones).
• sendtype
Tipo de datos de los elementos en el buffer de envío (en todas las invocaciones, excepto si el proceso es un proceso raíz).
• op
Operación de reducción (en todas las invocaciones).

OUTPUT PARAMETERS

• recvbuf
Contiene el resultado de la operación de reducción en el buffer de recepción.

DESCRIPTION

MPI_Reduce_scatter_block es una generalización de MPI_Reduce_scatter. En esta operación, cada proceso envía un bloque de datos, todos los bloques de datos se combinan usando la operación especificada, y el resultado se distribuye a todos los procesos. El resultado distribuido es un bloque de tamaño recvcount para cada proceso.

El número total de elementos enviados por cada proceso debe ser un múltiplo del número de procesos en el comunicador. Cada proceso recibe un bloque de datos de tamaño recvcount.

La operación op debe ser una operación de reducción válida.

La operación se realiza en el orden de los procesos en el comunicador.

USE OF IN-PLACE OPTION

Cuando el argumento sendbuf es el mismo que el argumento recvbuf, se considera una operación in-place. El resultado de la reducción se escribirá en el mismo buffer.

WHEN COMMUNICATOR IS AN INTER-COMMUNICATOR

Esta operación no está definida para comunicadores inter-comunicadores.

NOTES ON COLLECTIVE OPERATIONS

Todos los procesos en el comunicador deben llamar a esta rutina. Todos los procesos deben especificar los mismos argumentos para recvcount y sendtype. El argumento op debe ser el mismo en todos los procesos.

ERRORS

Los errores que ocurren durante la ejecución de esta operación pueden ser manejados por el manejador de errores de la sesión o del comunicador.

El manejo de errores se puede configurar usando:

  • MPI_Session_set_errhandler o en MPI_Session_init
  • MPI_Win_create_errhandler luego MPI_Win_set_errhandler

Tenga en cuenta que MPI no garantiza que un programa MPI pueda continuar después de un error.

Consulte la página del manual de MPI para obtener una lista completa de los códigos de error de MPI.

Consulte la sección de Manejo de Errores del estándar MPI-3.1 para más información.
