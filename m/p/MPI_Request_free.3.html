MPI_Request_free(3)

Paquete: openmpi

Licencias: BSD-3-Clause AND LicenseRef-MPICH

MPI_REQUEST_FREE(3) Open MPI MPI_REQUEST_FREE(3)

MPI_Request_free — Libera un objeto de solicitud de comunicación.

SINTAXIS

Sintaxis C

#include <mpi.h>
int MPI_Request_free(MPI_Request *request)

Sintaxis Fortran

USE MPI
! o la forma antigua: INCLUDE 'mpif.h'
MPI_REQUEST_FREE(REQUEST, IERROR)
     INTEGER REQUEST, IERROR

Sintaxis Fortran 2008

USE mpi_f08
MPI_Request_free(request, ierror)
     TYPE(MPI_Request), INTENT(INOUT) :: request
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARÁMETRO ENTRADA/SALIDA

•
request: Objeto de solicitud de comunicación (manejador).

DESCRIPCIÓN

Esta operación permite desasignar un objeto de solicitud sin esperar a que la comunicación asociada se complete.

MPI_Request_free marca el objeto de solicitud para desasignación y establece request a MPI_REQUEST_NULL. Se permitirá que cualquier comunicación en curso asociada a la solicitud se complete. La solicitud se desasignará solo después de su finalización.

NOTAS

Una vez que una solicitud se libera mediante una llamada a MPI_Request_free, no es posible verificar la finalización exitosa de la comunicación asociada con llamadas a MPI_Wait o MPI_Test. Además, si posteriormente ocurre un error durante la comunicación, no se puede devolver un código de error al usuario; dicho error debe tratarse como fatal. Surgen preguntas sobre cómo saber cuándo han finalizado las operaciones al utilizar MPI_Request_free. Dependiendo de la lógica del programa, puede haber otras formas en las que el programa sepa que ciertas operaciones han finalizado y esto hace que el uso de MPI_Request_free sea práctico. Por ejemplo, una solicitud de envío activa podría liberarse cuando la lógica del programa es tal que el receptor envía una respuesta al mensaje enviado: la llegada de la respuesta informa al remitente que el envío ha finalizado y que el búfer de envío puede reutilizarse. Nunca se debe liberar una solicitud de recepción activa, ya que el receptor no tendrá forma de verificar que la recepción ha finalizado y que el búfer de recepción puede reutilizarse.

Ejemplo:

CALL MPI_COMM_RANK(MPI_COMM_WORLD, rank)
IF(rank == 0) THEN
    DO i=1, n
      CALL MPI_ISEND(outval, 1, MPI_REAL, 1, 0, req, ierr)
      CALL MPI_REQUEST_FREE(req, ierr)
      CALL MPI_IRECV(inval, 1, MPI_REAL, 1, 0, req, ierr)
      CALL MPI_WAIT(req, status, ierr)
    END DO
ELSE IF (rank == 1) THEN
    CALL MPI_IRECV(inval, 1, MPI_REAL, 0, 0, req, ierr)
    CALL MPI_WAIT(req, status)
    DO I=1, n-1
       CALL MPI_ISEND(outval, 1, MPI_REAL, 0, 0, req, ierr)
       CALL MPI_REQUEST_FREE(req, ierr)
       CALL MPI_IRECV(inval, 1, MPI_REAL, 0, 0, req, ierr)
       CALL MPI_WAIT(req, status, ierr)
    END DO
    CALL MPI_ISEND(outval, 1, MPI_REAL, 0, 0, req, ierr)
    CALL MPI_WAIT(req, status)
END IF

Esta rutina se usa normalmente para liberar solicitudes persistentes creadas con MPI_Recv_init o MPI_Send_init y sus derivados. Sin embargo, se puede usar para liberar una solicitud creada con MPI_Irecv o MPI_Isend y sus derivados; en ese caso, el usuario no puede usar las rutinas de prueba/espera en la solicitud.

Se permite liberar una solicitud activa. Sin embargo, una vez liberada, no se puede usar la solicitud en una rutina de espera o prueba (por ejemplo, MPI_Wait).

ERRORES

Casi todas las rutinas MPI devuelven un valor de error; las rutinas C como resultado de retorno de la función y las rutinas Fortran en el último argumento.

Antes de que se devuelva el valor de error, se llama al controlador de errores MPI actual asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo). Si no hay ningún objeto de comunicación asociado con la llamada MPI, entonces la llamada se considera adjunta a MPI_COMM_SELF y llamará al controlador de errores MPI asociado. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/ MPI_Init_thread, después de MPI_Finalize, o cuando se utiliza exclusivamente el modelo de sesiones), el error invoca el controlador de errores inicial. El controlador de errores inicial se puede cambiar llamando a MPI_Comm_set_errhandler en MPI_COMM_SELF cuando se utiliza el modelo World, o el argumento de línea de comandos mpi_initial_errhandler a mpiexec o la clave info a MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no se ha establecido ningún otro controlador de errores apropiado, se llama al controlador de errores MPI_ERRORS_RETURN para las funciones de E/S de MPI y al controlador de errores MPI_ERRORS_ABORT para todas las demás funciones MPI.

Open MPI incluye tres controladores de errores predefinidos que se pueden utilizar:

  • MPI_ERRORS_ARE_FATAL Hace que el programa termine todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT Un controlador de errores que puede ser invocado en un comunicador, ventana, archivo o sesión. Cuando se llama en un comunicador, actúa como si se hubiera llamado a MPI_Abort en ese comunicador. Si se llama en una ventana o archivo, actúa como si se hubiera llamado a MPI_Abort en un comunicador que contiene el grupo de procesos en la ventana o archivo correspondiente. Si se llama en una sesión, solo termina el proceso local.
  • MPI_ERRORS_RETURN Devuelve un código de error a la aplicación.

Las aplicaciones MPI también pueden implementar sus propios controladores de errores llamando a:

  • MPI_Comm_create_errhandler y luego MPI_Comm_set_errhandler
  • MPI_File_create_errhandler y luego MPI_File_set_errhandler
  • MPI_Session_create_errhandler y luego MPI_Session_set_errhandler o en MPI_Session_init
  • MPI_Win_create_errhandler y luego MPI_Win_set_errhandler

Tenga en cuenta que MPI no garantiza que un programa MPI pueda continuar después de un error.

Consulte la página del manual de MPI para obtener una lista completa de los códigos de error de MPI.

Consulte la sección de Manejo de Errores del estándar MPI-3.1 para obtener más información.
