MPI_Win_fence — Sincroniza llamadas RMA en una ventana.

SINTAXIS

Sintaxis en C

#include <mpi.h>
int MPI_Win_fence(int assert, MPI_Win win)

Sintaxis en Fortran

USE MPI
! o la forma antigua: INCLUDE 'mpif.h'
MPI_WIN_FENCE(ASSERT, WIN, IERROR)
     INTEGER ASSERT, WIN, IERROR

Sintaxis en Fortran 2008

USE mpi_f08
MPI_Win_fence(assert, win, ierror)
     INTEGER, INTENT(IN) :: assert
     TYPE(MPI_Win), INTENT(IN) :: win
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARÁMETROS DE ENTRADA

  • assert: Afirmación del programa (entero).
  • win: Objeto de ventana (manejador).

PARÁMETRO DE SALIDA

•
ierror: Solo Fortran: Estado de error (entero).

DESCRIPCIÓN

MPI_Win_fence sincroniza las llamadas RMA en win. La llamada es colectiva para el grupo de win. Todas las operaciones RMA en win originadas en un proceso dado y iniciadas antes de la llamada fence se completarán en ese proceso antes de que la llamada fence devuelva. Se completarán en su destino antes de que la llamada fence devuelva en el destino. Las operaciones RMA en win iniciadas por un proceso después de que la llamada fence devuelva accederán a su ventana de destino solo después de que MPI_Win_fence haya sido llamada por el proceso de destino.

La llamada completa una época de acceso RMA si fue precedida por otra llamada fence y el proceso local emitió llamadas de comunicación RMA en win entre estas dos llamadas. La llamada completa una época de exposición RMA si fue precedida por otra llamada fence y la ventana local fue el objetivo de accesos RMA entre estas dos llamadas. La llamada inicia una época de acceso RMA si es seguida por otra llamada fence y por llamadas de comunicación RMA emitidas entre estas dos llamadas fence. Por lo tanto, la llamada fence es equivalente a llamadas a un subconjunto de post, start, complete, wait.

El argumento assert se utiliza para proporcionar afirmaciones sobre el contexto de la llamada que pueden ser utilizadas para diversas optimizaciones. Un valor de assert ^ 0 es siempre válido. Se soporta el siguiente valor de afirmación:

MPI_MODE_NOPRECEDE
No se han emitido llamadas RMA locales antes de esta fence. Esta afirmación debe ser proporcionada por todos o ninguno de los miembros del grupo de la ventana. Puede permitir una llamada fence más rápida al evitar sincronizaciones innecesarias.
MPI_MODE_NOSTORE
Informa que la ventana local no fue actualizada por tiendas locales o llamadas get en la época precedente.
MPI_MODE_NOPUT
Informa que la ventana local no será actualizada por ninguna llamada put o accumulate en la época siguiente (hasta la próxima llamada fence).
MPI_MODE_NOSUCCEED
No se emitirán llamadas RMA locales después de esta fence. Esta afirmación debe ser proporcionada por todos o ninguno de los miembros del grupo de la ventana. Puede permitir una llamada fence más rápida al evitar sincronizaciones innecesarias.

NOTA

Las llamadas a MPI_Win_fence deben preceder y seguir a las llamadas a put, get o accumulate que se sincronizan con llamadas fence.

ERRORES

Casi todas las rutinas MPI devuelven un valor de error; las rutinas en C como resultado del retorno de la función y las rutinas en Fortran en el último argumento.

Antes de que se devuelva el valor de error, se llama al manejador de errores MPI actual asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo). Si no hay ningún objeto de comunicación asociado con la llamada MPI, entonces la llamada se considera adjunta a MPI_COMM_SELF y llamará al manejador de errores MPI asociado. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se utiliza exclusivamente el modelo de Sesiones) el error eleva el manejador de errores inicial. El manejador de errores inicial se puede cambiar llamando a MPI_Comm_set_errhandler en MPI_COMM_SELF cuando se utiliza el modelo World, o el argumento de línea de comandos mpiexec mpi_initial_errhandler o la clave de información para MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no se ha configurado ningún otro manejador de errores apropiado, entonces se llama al manejador de errores MPI_ERRORS_RETURN para las funciones de E/S de MPI y al manejador de errores MPI_ERRORS_ABORT para todas las demás funciones MPI.

Open MPI incluye tres manejadores de errores predefinidos que pueden ser utilizados:

  • MPI_ERRORS_ARE_FATAL Provoca que el programa aborte todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT Un manejador de errores que puede ser invocado en un comunicador, ventana, archivo o sesión. Cuando se llama en un comunicador, actúa como si se hubiera llamado a MPI_Abort en ese comunicador. Si se llama en una ventana o archivo, actúa como si se hubiera llamado a MPI_Abort en un comunicador que contiene el grupo de procesos en la ventana o archivo correspondiente. Si se llama en una sesión, solo aborta el proceso local.
  • MPI_ERRORS_RETURN Devuelve un código de error a la aplicación.

Las aplicaciones MPI también pueden implementar sus propios manejadores de errores llamando a:

  • MPI_Comm_create_errhandler luego MPI_Comm_set_errhandler
  • MPI_File_create_errhandler luego MPI_File_set_errhandler
  • MPI_Session_create_errhandler luego MPI_Session_set_errhandler o en MPI_Session_init
  • MPI_Win_create_errhandler luego MPI_Win_set_errhandler

Tenga en cuenta que MPI no garantiza que un programa MPI pueda continuar después de un error.

Consulte la página del manual de MPI para ver una lista completa de los códigos de error de MPI.

Consulte la sección de Manejo de Errores del estándar MPI-3.1 para obtener más información.

    MPI_Win_fence

    NAME

    MPI_Win_fence - MPI one-sided communication synchronization primitive.

    SYNOPSIS

    C:

    int MPI_Win_fence(int assert);

    Fortran:

    SUBROUTINE MPI_WIN_FENCE(ASSERT, IERROR)
    INTEGER ASSERT, IERROR

    DESCRIPTION

    MPI_Win_fence is an MPI one-sided communication synchronization primitive. It is used to synchronize operations performed on MPI windows. It can be used to establish epochs for one-sided communications. The `assert` argument allows the user to provide information about the expected collective communication operations that will be performed by the processes in the communicator associated with the window. This information can be used by the MPI implementation to optimize the communication. Possible values for `assert` are MPI_MODE_NOCHECK, MPI_MODE_NOPUT, MPI_MODE_NOPRECEDE, MPI_MODE_NOSUCCEED.

    PARAMETERS

    assert
    Input argument. Specifies assertions about the collective communication operations. Can be MPI_MODE_NOCHECK, MPI_MODE_NOPUT, MPI_MODE_NOPRECEDE, MPI_MODE_NOSUCCEED, or any combination thereof.
    IERROR
    Output argument. Fortran only. The error status of the call.

    RETURN VALUES

    MPI_SUCCESS, MPI_ERR_ASSERT, MPI_ERR_WIN

    SYNCHRONIZATION

    MPI_Win_fence synchronizes all processes in the communicator associated with the window. After MPI_Win_fence returns, all previous one-sided communication operations initiated by any process in the communicator are guaranteed to be completed. Furthermore, any one-sided communication operations initiated after MPI_Win_fence returns will not be affected by operations initiated before MPI_Win_fence. This establishes a fence for one-sided communication operations.

    NOTES

    The `assert` argument can be used to provide hints to the MPI implementation about the nature of the one-sided communication operations that will follow. For example, if a process knows that it will not initiate any PUT operations after the fence, it can specify MPI_MODE_NOPUT to potentially enable optimizations.

    • MPI_MODE_NOCHECK: No checks are performed.
    • MPI_MODE_NOPUT: No PUT operations are expected.
    • MPI_MODE_NOPRECEDE: No operations are expected to precede this fence.
    • MPI_MODE_NOSUCCEED: No operations are expected to succeed this fence.

    ERRORS

    MPI_ERR_ASSERT: An invalid assert value was provided.

    MPI_ERR_WIN: An invalid MPI window was provided.
