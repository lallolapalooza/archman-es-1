MPI_COMM_DUP(3) Open MPI MPI_Comm_dup(3)

MPI_Comm_dup — Duplica un comunicador existente con toda su información cacheada.

SINTAXIS

Sintaxis C

#include <mpi.h>
int MPI_Comm_dup(MPI_Comm comm, MPI_Comm *newcomm)

Sintaxis Fortran

USE MPI
! o la forma antigua: INCLUDE 'mpif.h'
MPI_COMM_DUP(COMM, NEWCOMM, IERROR)
    INTEGER COMM, NEWCOMM, IERROR

Sintaxis Fortran 2008

USE mpi_f08
MPI_Comm_dup(comm, newcomm, ierror)
    TYPE(MPI_Comm), INTENT(IN) :: comm
    TYPE(MPI_Comm), INTENT(OUT) :: newcomm
    INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARÁMETRO DE ENTRADA

•
comm : Comunicador (manejador).

PARÁMETROS DE SALIDA

  • newcomm : Copia de comm (manejador).
  • ierror : Solo Fortran: Estado de error (entero).

DESCRIPCIÓN

MPI_Comm_dup duplica el comunicador existente comm con los valores de clave asociados. Para cada valor de clave, la función de devolución de llamada de copia respectiva determina el valor del atributo asociado a esta clave en el nuevo comunicador; una acción particular que una devolución de llamada de copia puede tomar es eliminar el atributo del nuevo comunicador. Devuelve en newcomm un nuevo comunicador con el mismo grupo, cualquier información cacheada copiada, pero un nuevo contexto (ver la subsección "Funcionalidad" de la sección "Caché" en el capítulo "Grupos, Contextos y Comunicadores" del *Estándar MPI*).

NOTAS

Esta operación se utiliza para proporcionar a una llamada de biblioteca paralela un espacio de comunicación duplicado que tenga las mismas propiedades que el comunicador original. Esto incluye cualquier atributo (ver abajo) y topologías (ver el capítulo "Topologías de Procesos" en el *Estándar MPI*). Esta llamada es válida incluso si hay comunicaciones punto a punto pendientes que involucran al comunicador comm. Una llamada típica podría implicar un *MPI_Comm_dup* al principio de la llamada paralela, y un *MPI_Comm_free* de ese comunicador duplicado al final de la llamada. También son posibles otros modelos de gestión de comunicadores. Esta llamada se aplica tanto a intercomunicadores como a intracomunicadores. Tenga en cuenta que el estándar MPI no define qué sucede si la devolución de llamada de copia de atributo invoca otras funciones MPI. En Open MPI, no es válido que las devoluciones de llamada de copia de atributos (o cualquiera de sus hijos) agreguen o eliminen atributos en el mismo objeto en el que se está invocando la devolución de llamada de copia de atributo.

ERRORES

Casi todas las rutinas MPI devuelven un valor de error; las rutinas de C como resultado del retorno de la función y las rutinas de Fortran en el último argumento.

Antes de que se devuelva el valor de error, se llama al controlador de errores MPI actual asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo). Si no hay un objeto de comunicación asociado con la llamada MPI, entonces la llamada se considera adjunta a MPI_COMM_SELF y llamará al controlador de errores MPI asociado. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de *MPI_Init*/*MPI_Init_thread*, después de *MPI_Finalize*, o cuando se utiliza exclusivamente el Modelo de Sesiones) el error eleva el controlador de errores inicial. El controlador de errores inicial se puede cambiar llamando a *MPI_Comm_set_errhandler* en MPI_COMM_SELF cuando se utiliza el modelo World, o el argumento CLI mpi_initial_errhandler para mpiexec o la clave info para *MPI_Comm_spawn*/*MPI_Comm_spawn_multiple*. Si no se ha configurado ningún otro controlador de errores apropiado, entonces se llama al controlador de errores MPI_ERRORS_RETURN para las funciones de E/S MPI y al controlador de errores MPI_ERRORS_ABORT para todas las demás funciones MPI.

Open MPI incluye tres controladores de errores predefinidos que se pueden utilizar:

  • MPI_ERRORS_ARE_FATAL Provoca que el programa termine todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT Un controlador de errores que se puede invocar en un comunicador, ventana, archivo o sesión. Cuando se llama en un comunicador, actúa como si se hubiera llamado a *MPI_Abort* en ese comunicador. Si se llama en una ventana o archivo, actúa como si se hubiera llamado a *MPI_Abort* en un comunicador que contiene el grupo de procesos en la ventana o archivo correspondiente. Si se llama en una sesión, aborta solo el proceso local.
  • MPI_ERRORS_RETURN Devuelve un código de error a la aplicación.

Las aplicaciones MPI también pueden implementar sus propios controladores de errores llamando a:

  • *MPI_Comm_create_errhandler* luego *MPI_Comm_set_errhandler*
  • *MPI_File_create_errhandler* luego *MPI_File_set_errhandler*
  • *MPI_Session_create_errhandler* luego *MPI_Session_set_errhandler* o en *MPI_Session_init*
  • *MPI_Win_create_errhandler* luego *MPI_Win_set_errhandler*

Tenga en cuenta que MPI no garantiza que un programa MPI pueda continuar después de un error.

Ver la *página del manual de MPI* para una lista completa de *códigos de error de MPI*.

Ver la sección Manejo de Errores del estándar MPI-3.1 para más información.
