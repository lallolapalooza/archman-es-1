MPI_TESTANY(3) Open MPI MPI_TESTANY(3)

MPI_Testany — Comprueba la finalización de una comunicación anteriormente iniciada en una lista.

SINTAXIS

Sintaxis C

#include <mpi.h>
int MPI_Testany(int count, MPI_Request array_of_requests[],
     int *index, int *flag, MPI_Status *status)

Sintaxis Fortran

USE MPI
! o la forma anterior: INCLUDE 'mpif.h'
MPI_TESTANY(COUNT, ARRAY_OF_REQUESTS, INDEX, FLAG, STATUS, IERROR)
     LOGICAL FLAG
     INTEGER COUNT, ARRAY_OF_REQUESTS(*), INDEX
     INTEGER STATUS(MPI_STATUS_SIZE), IERROR

Sintaxis Fortran 2008

USE mpi_f08
MPI_Testany(count, array_of_requests, index, flag, status, ierror)
     INTEGER, INTENT(IN) :: count
     TYPE(MPI_Request), INTENT(INOUT) :: array_of_requests(count)
     INTEGER, INTENT(OUT) :: index
     LOGICAL, INTENT(OUT) :: flag
     TYPE(MPI_Status) :: status
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARÁMETROS DE ENTRADA

  • count: Longitud de la lista (entero).
  • array_of_requests: Matriz de solicitudes (matriz de identificadores).

PARÁMETROS DE SALIDA

  • index: Índice de la operación que se completó, o MPI_UNDEFINED si ninguna se completó (entero).
  • flag: Verdadero si una de las operaciones está completa (lógico).
  • status: Objeto de estado (estado).
  • ierror: Solo Fortran: Estado de error (entero).

DESCRIPCIÓN

MPI_Testany comprueba la finalización de una o ninguna de las operaciones asociadas con identificadores activos. En el primer caso, devuelve flag = verdadero, devuelve en index el índice de esta solicitud en la matriz, y devuelve en status el estado de esa operación; si la solicitud fue asignada por una llamada de comunicación no bloqueante, entonces la solicitud se desasigna y el identificador se establece en MPI_REQUEST_NULL. (La matriz se indexa desde 0 en C, y desde 1 en Fortran). En el segundo caso (ninguna operación completada), devuelve flag = falso, devuelve un valor de MPI_UNDEFINED en index, y status no está definido.

La matriz puede contener identificadores nulos o inactivos. Si la matriz no contiene identificadores activos, la llamada retorna inmediatamente con flag = verdadero, index = MPI_UNDEFINED, y un status vacío.

Si la matriz de solicitudes contiene identificadores activos, la ejecución de MPI_Testany(count, array_of_requests, index, status) tiene el mismo efecto que la ejecución de MPI_Test(&array_of_requests[i], flag, status), para i=0,1,…,count-1, en algún orden arbitrario, hasta que una llamada retorne flag = verdadero, o todas fallen. En el primer caso, index se establece en el último valor de i, y en el segundo caso, se establece en MPI_UNDEFINED. MPI_Testany con una matriz que contiene una entrada activa es equivalente a MPI_Test.

Si su aplicación no necesita examinar el campo status, puede ahorrar recursos utilizando la constante predefinida MPI_STATUS_IGNORE como un valor especial para el argumento status.

ERRORES

Casi todas las rutinas MPI devuelven un valor de error; las rutinas C como el resultado de la función y las rutinas Fortran en el último argumento.

Antes de que se devuelva el valor de error, se llama al manejador de errores MPI actual asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo). Si no hay ningún objeto de comunicación asociado con la llamada MPI, entonces la llamada se considera adjunta a MPI_COMM_SELF y llamará al manejador de errores MPI asociado. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se utiliza exclusivamente el Modelo de Sesiones) el error activa el manejador de errores inicial. El manejador de errores inicial se puede cambiar llamando a MPI_Comm_set_errhandler en MPI_COMM_SELF cuando se utiliza el modelo World, o el argumento de CLI mpi_initial_errhandler para mpiexec o la clave de información para MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no se ha establecido ningún otro manejador de errores apropiado, entonces se llama al manejador de errores MPI_ERRORS_RETURN para las funciones de E/S MPI y al manejador de errores MPI_ERRORS_ABORT para todas las demás funciones MPI.

Open MPI incluye tres manejadores de errores predefinidos que se pueden utilizar:

  • MPI_ERRORS_ARE_FATAL Provoca que el programa aborte todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT Un manejador de errores que se puede invocar en un comunicador, ventana, archivo o sesión. Cuando se llama en un comunicador, actúa como si se hubiera llamado a MPI_Abort en ese comunicador. Si se llama en una ventana o archivo, actúa como si se hubiera llamado a MPI_Abort en un comunicador que contiene el grupo de procesos en la ventana o archivo correspondiente. Si se llama en una sesión, solo aborta el proceso local.
  • MPI_ERRORS_RETURN Devuelve un código de error a la aplicación.

Las aplicaciones MPI también pueden implementar sus propios manejadores de errores llamando a:

  • MPI_Comm_create_errhandler luego MPI_Comm_set_errhandler
  • MPI_File_create_errhandler luego MPI_File_set_errhandler
  • MPI_Session_create_errhandler luego MPI_Session_set_errhandler o en MPI_Session_init
  • MPI_Win_create_errhandler luego MPI_Win_set_errhandler

Tenga en cuenta que MPI no garantiza que un programa MPI pueda continuar después de un error.

Consulte la página del manual de MPI para obtener una lista completa de los códigos de error de MPI.

Consulte la sección de Manejo de Errores del estándar MPI-3.1 para obtener más información.

Tenga en cuenta que según la sección de "Estado de Retorno" en el capítulo de "Comunicación Punto a Punto" del Estándar MPI, los errores MPI en las solicitudes pasadas a MPI_Testany no establecen el campo status.MPI_ERROR en el status devuelto. El código de error se pasa siempre al manejador de errores backend y puede devolverse al llamante a través del valor de retorno de MPI_Testany si el manejador de errores backend lo devuelve. El manejador de errores predefinido de MPI MPI_ERRORS_RETURN exhibe este comportamiento, por ejemplo.
