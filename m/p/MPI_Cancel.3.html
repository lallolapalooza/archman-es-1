MPI_Cancel — Cancela una solicitud de comunicación.

SINTAXIS

Sintaxis C

#include <mpi.h>
int MPI_Cancel(MPI_Request *request)

Sintaxis Fortran

USE MPI
! o la forma antigua: INCLUDE 'mpif.h'
MPI_CANCEL(REQUEST, IERROR)
    INTEGER REQUEST, IERROR

Sintaxis Fortran 2008

USE mpi_f08
MPI_Cancel(request, ierror)
    TYPE(MPI_Request), INTENT(IN) :: request
    INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARÁMETRO DE ENTRADA

•
request : Solicitud de comunicación (manejador).

PARÁMETRO DE SALIDA

•
ierror : Solo Fortran: Estado de error (entero).

DESCRIPCIÓN

La operación MPI_Cancel permite cancelar comunicaciones pendientes. Esto es necesario para la limpieza. Publicar un envío o recepción vincula recursos del usuario (búferes de envío o recepción), y puede ser necesario un `cancel` para liberar estos recursos de forma elegante.

Una llamada a MPI_Cancel marca para cancelación una operación de comunicación pendiente, no bloqueante (envío o recepción). La llamada de cancelación es local. Devuelve inmediatamente, posiblemente antes de que la comunicación se cancele realmente. Todavía es necesario completar una comunicación que ha sido marcada para cancelación, utilizando una llamada a MPI_Request_free, MPI_Wait, o MPI_Test (o cualquiera de las operaciones derivadas).

Si una comunicación se marca para cancelación, entonces una llamada a MPI_Wait para esa comunicación tiene garantizado que devolverá, independientemente de las actividades de otros procesos (es decir, MPI_Wait se comporta como una función local); de manera similar, si MPI_Test se llama repetidamente en un bucle de espera activo para una comunicación cancelada, entonces MPI_Test eventualmente tendrá éxito.

MPI_Cancel puede usarse para cancelar una comunicación que utiliza una solicitud persistente (ver Sección 3.9 en el *Estándar MPI*, "Solicitudes de Comunicación Persistentes") de la misma manera que se usa para solicitudes no persistentes. Una cancelación exitosa cancela la comunicación activa, pero no la solicitud en sí. Después de la llamada a MPI_Cancel y la llamada subsiguiente a MPI_Wait o MPI_Test, la solicitud se vuelve inactiva y puede activarse para una nueva comunicación.

La cancelación exitosa de un envío en búfer libera el espacio en búfer ocupado por el mensaje pendiente.

O la cancelación tiene éxito o la comunicación tiene éxito, pero no ambas. Si un envío se marca para cancelación, entonces debe darse el caso de que o bien el envío se complete normalmente, en cuyo caso el mensaje enviado se recibe en el proceso de destino, o bien que el envío se cancele exitosamente, en cuyo caso ninguna parte del mensaje se recibe en el destino. Entonces, cualquier recepción coincidente debe ser satisfecha por otro envío. Si una recepción se marca para cancelación, entonces debe darse el caso de que o bien la recepción se complete normalmente, o bien que la recepción se cancele exitosamente, en cuyo caso ninguna parte del búfer de recepción se altera. Entonces, cualquier envío coincidente debe ser satisfecho por otra recepción.

Si la operación ha sido cancelada, entonces se devolverá información a ese efecto en el argumento de estado de la operación que completa la comunicación.

NOTAS

El uso principal esperado de MPI_Cancel es en esquemas de múltiples búferes, donde se realizan `MPI_Irecvs` especulativos. Cuando la computación se completa, algunas de estas solicitudes pueden permanecer; el uso de MPI_Cancel permite al usuario cancelar estas solicitudes no satisfechas.

ERRORES

Casi todas las rutinas MPI devuelven un valor de error; las rutinas C como resultado de retorno de la función y las rutinas Fortran en el último argumento.

Antes de que se devuelva el valor de error, se llama al manejador de errores MPI actual asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo). Si no hay un objeto de comunicación asociado con la llamada MPI, entonces la llamada se considera adjunta a MPI_COMM_SELF y llamará al manejador de errores MPI asociado. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se usa exclusivamente el Modelo de Sesiones) el error eleva el manejador de errores inicial. El manejador de errores inicial se puede cambiar llamando a MPI_Comm_set_errhandler en MPI_COMM_SELF cuando se usa el modelo World, o el argumento CLI mpi_initial_errhandler para mpiexec o la clave `info` para MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no se ha establecido ningún otro manejador de errores apropiado, entonces se llama al manejador de errores MPI_ERRORS_RETURN para las funciones de E/S MPI y al manejador de errores MPI_ERRORS_ABORT para todas las demás funciones MPI.

Open MPI incluye tres manejadores de errores predefinidos que pueden usarse:

  • MPI_ERRORS_ARE_FATAL Causa que el programa aborte todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT Un manejador de errores que se puede invocar en un comunicador, ventana, archivo o sesión. Cuando se llama en un comunicador, actúa como si se hubiera llamado MPI_Abort en ese comunicador. Si se llama en una ventana o archivo, actúa como si se hubiera llamado MPI_Abort en un comunicador que contiene el grupo de procesos de la ventana o archivo correspondiente. Si se llama en una sesión, aborta solo el proceso local.
  • MPI_ERRORS_RETURN Devuelve un código de error a la aplicación.

Las aplicaciones MPI también pueden implementar sus propios manejadores de errores llamando a:

  • MPI_Comm_create_errhandler luego MPI_Comm_set_errhandler
  • MPI_File_create_errhandler luego MPI_File_set_errhandler
  • MPI_Session_create_errhandler luego MPI_Session_set_errhandler o en MPI_Session_init
  • MPI_Win_create_errhandler luego MPI_Win_set_errhandler

Tenga en cuenta que MPI no garantiza que un programa MPI pueda continuar después de un error.

Consulte la *página del manual de MPI* para obtener una lista completa de los *códigos de error de MPI*.

Consulte la sección Manejo de Errores del estándar MPI-3.1 para obtener más información.

MPI_Cancel(3)

MPI_Cancel - Cancela una solicitud de operación de comunicación.

Sintaxis

#include <mpi.h>
int MPI_Cancel(MPI_Request *request);

Descripción

MPI_Cancel marca una operación de comunicación para su cancelación.

Cuando se llama a MPI_Cancel con un manejador de solicitud, la operación correspondiente se marca para su cancelación. Si la operación no se ha iniciado (o si se puede detener sin afectar a otras operaciones), se cancelará y la llamada a MPI_Test o MPI_Wait para esa solicitud devolverá MPI_ERR_PENDING.

Si la operación ya se ha completado o está en proceso y no se puede detener, MPI_Cancel no tendrá ningún efecto y la llamada a MPI_Test o MPI_Wait para esa solicitud devolverá MPI_SUCCESS.

Es posible que la operación no se cancele inmediatamente. Por lo tanto, debe llamar a MPI_Test o MPI_Wait para determinar si la cancelación fue exitosa. Después de una llamada exitosa a MPI_Cancel, el manejador de solicitud se establece en MPI_REQUEST_NULL.

Parámetros

  • request: Un puntero al manejador de solicitud de la operación a cancelar.

Valor de retorno

  • MPI_SUCCESS: Se ejecutó sin error.
  • MPI_ERR_REQUEST: El manejador de solicitud no es válido.

Nota

La operación de cancelación en sí misma no garantiza que la operación de comunicación asociada no se complete. Por lo tanto, se debe verificar el estado de la solicitud después de llamar a MPI_Cancel para determinar si la operación se canceló o se completó.
