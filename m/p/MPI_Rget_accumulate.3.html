DESCRIPCIÓN

MPI_Get_accumulate es una función utilizada para la comunicación unidireccional de MPI que suma los contenidos del búfer de origen (según se define por origin_addr, origin_count y origin_datatype) al búfer especificado por los argumentos target_count y target_datatype, en el desplazamiento target_disp, en la ventana de destino especificada por target_rank y win, utilizando la operación op. MPI_Get_accumulate devuelve en el búfer de resultado result_addr los contenidos del búfer de destino antes de la acumulación.

Se pueden usar cualquiera de las operaciones predefinidas para MPI_Reduce, así como MPI_NO_OP. No se pueden usar funciones definidas por el usuario. Por ejemplo, si op es MPI_SUM, cada elemento del búfer de origen se suma al elemento correspondiente en el destino, reemplazando el valor anterior en el destino.

Cada argumento de tipo de datos debe ser un tipo de datos predefinido o un tipo de datos derivado, donde todos los componentes básicos son del mismo tipo de datos predefinido. Ambos argumentos de tipo de datos deben construirse a partir del mismo tipo de datos predefinido. La operación op se aplica a los elementos de ese tipo predefinido. El argumento target_datatype no debe especificar entradas superpuestas, y el búfer de destino debe caber en la ventana de destino.

Se define una nueva operación predefinida, MPI_REPLACE. Corresponde a la función asociativa f(a, b) =b; es decir, el valor actual en la memoria de destino se reemplaza por el valor proporcionado por el origen.

Se define una nueva operación predefinida, MPI_NO_OP. Corresponde a la función asociativa f(a, b) = a; es decir, el valor actual en la memoria de destino se devuelve en el búfer de resultado en el origen y no se realiza ninguna operación en el búfer de destino.

MPI_Rget_accumulate es similar a MPI_Get_accumulate, excepto que asigna un objeto de solicitud de comunicación y lo asocia con el manejador de solicitud (el argumento request) que se puede utilizar para esperar o probar la finalización. La finalización de una operación MPI_Rget_accumulate indica que los datos están disponibles en el búfer de resultado y que el búfer de origen está libre para ser actualizado. No indica que la operación se haya completado en la ventana de destino.

NOTAS

La funcionalidad genérica de MPI_Get_accumulate puede limitar el rendimiento de las llamadas de obtención e incremento o obtención y suma que podrían ser compatibles con operaciones de hardware especiales. Por lo tanto, MPI_Fetch_and_op permite una implementación rápida de un subconjunto de la funcionalidad de MPI_Get_accumulate de uso común.

MPI_Get es un caso especial de MPI_Get_accumulate, con la operación MPI_NO_OP. Sin embargo, tenga en cuenta que MPI_Get y MPI_Get_accumulate tienen diferentes restricciones en las actualizaciones concurrentes.

Es responsabilidad del usuario garantizar que, al usar las funciones de acumulación, el argumento de desplazamiento de destino sea tal que los accesos a la ventana estén correctamente alineados según los argumentos de tipo de datos en la llamada a la función MPI_Get_accumulate.

MPI_Rget_accumulate(3)

NAME

MPI_Rget_accumulate - Performs a remote memory accumulate operation with a local completion handle.

SYNTAX

int MPI_Rget_accumulate(const void *origin_addr, int origin_count,
                        MPI_Datatype origin_datatype, void *target_addr,
                        int target_count, MPI_Datatype target_datatype,
                        MPI_Op op, MPI_Win win,
                        MPI_Request *request);

INPUT PARAMETERS

“origin_addr”
Local address of origin buffer (choice).
“origin_count”
Number of elements at origin address (integer).
“origin_datatype”
Local data type of elements at origin address (handle).
“target_addr”
Remote address of target buffer (integer).
“target_count”
Number of elements at target address (integer).
“target_datatype”
Remote data type of elements at target address (handle).
“op”
The reduction operation (handle).
“win”
The window object (handle).

OUTPUT PARAMETER

“request”
The MPI request handle (handle).

DESCRIPTION

MPI_Rget_accumulate performs a remote memory accumulate operation. It reads data from the origin buffer, performs an accumulation operation with the data specified by the target buffer, and writes the result to the target buffer. The operation is non-blocking, and a request handle is returned which can be used to query the status of the operation.

The operation is defined between a local buffer (origin) and a remote buffer (target). The data at the origin is read, combined with the data at the target using the specified operation, and the result is written back to the target. The target buffer's contents are updated in place.

The target address is relative to the start of the remote process's memory space accessible via the window object. The origin buffer must be allocated within the caller's process.

The size of the origin and target buffers are determined by the count and datatype arguments. Both origin and target must use the same count and datatype. The operation specified by op must be a predefined MPI reduction operation or a user-defined one.

The win argument must be a window object created with the MPI_Win_allocate_shared, MPI_Win_allocate, MPI_Win_create, or MPI_Win_create_dynamic functions.

The operation completes when the data has been written to the target buffer and the local process is free to reuse the origin buffer.

NOTES

This function is part of the MPI one-sided communication. It allows a process to access the memory of another process without the cooperation of the target process.

The target buffer address is interpreted as an offset from the base address of the remote memory region associated with the window object.

MPI_Rget_accumulate is the non-blocking version of MPI_Get_accumulate.

ERRORS

When the value of the comm argument of the invoking routine is a communicator other than MPI_COMM_WORLD, the error handling depends for the communicator is set. If the error handler for the communicator is not set, then the MPI behavior is as if the error handler was set for the communicator MPI_COMM_WORLD.

Before the MPI environment is initialized or after it has been finalized, the call is considered attached to MPI_COMM_SELF and will call the associated MPI error handler. When MPI_COMM_SELF is not initialized (i.e., before MPI_Init/MPI_Init_thread, after MPI_Finalize, or when using the Sessions Model exclusively) the error raises the initial error handler. The initial error handler can be changed by calling MPI_Comm_set_errhandler on MPI_COMM_SELF when using the World model, or the mpi_initial_errhandler CLI argument to mpiexec or info key to MPI_Comm_spawn/MPI_Comm_spawn_multiple. If no other appropriate error handler has been set, then the MPI_ERRORS_RETURN error handler is called for MPI I/O functions and the MPI_ERRORS_ABORT error handler is called for all other MPI functions.

Open MPI includes three predefined error handlers that can be used:

  • MPI_ERRORS_ARE_FATAL Causes the program to abort all connected MPI processes.
  • MPI_ERRORS_ABORT An error handler that can be invoked on a communicator, window, file, or session. When called on a communicator, it acts as if MPI_Abort was called on that communicator. If called on a window or file, acts as if MPI_Abort was called on a communicator containing the group of processes in the corresponding window or file. If called on a session, aborts only the local process.
  • MPI_ERRORS_RETURN Returns an error code to the application.

MPI applications can also implement their own error handlers by calling:

  • MPI_Comm_create_errhandler then MPI_Comm_set_errhandler
  • MPI_File_create_errhandler then MPI_File_set_errhandler
  • MPI_Session_create_errhandler then MPI_Session_set_errhandler or at MPI_Session_init
  • MPI_Win_create_errhandler then MPI_Win_set_errhandler

Note that MPI does not guarantee that an MPI program can continue past an error.

See the MPI man page for a full list of MPI error codes.
