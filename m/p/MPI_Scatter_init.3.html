MPI_Scatter_init(3)

MPI_SCATTER_INIT(3) Open MPI MPI_SCATTER_INIT(3)

MPI_Scatter, MPI_Iscatter, MPI_Scatter_init - Envía datos desde una tarea a todas las tareas de un grupo.

SINTAXIS

Sintaxis en C

#include <mpi.h>
int MPI_Scatter(const void *sendbuf, int sendcount, MPI_Datatype sendtype,
     void *recvbuf, int recvcount, MPI_Datatype recvtype, int root,
     MPI_Comm comm)
int MPI_Iscatter(const void *sendbuf, int sendcount, MPI_Datatype sendtype,
     void *recvbuf, int recvcount, MPI_Datatype recvtype, int root,
     MPI_Comm comm, MPI_Request *request)
int MPI_Scatter_init(const void *sendbuf, int sendcount, MPI_Datatype sendtype,
     void *recvbuf, int recvcount, MPI_Datatype recvtype, int root,
     MPI_Comm comm, MPI_Info info, MPI_Request *request)

PARÁMETROS DE ENTRADA

  • sendbuf: Dirección del búfer de envío (elección, significativo solo en la raíz).
  • sendcount: Número de elementos enviados a cada proceso (entero, significativo solo en la raíz).
  • sendtype: Tipo de datos de los elementos del búfer de envío (manejador, significativo solo en la raíz).
  • recvcount: Número de elementos en el búfer de recepción (entero).
  • recvtype: Tipo de datos de los elementos del búfer de recepción (manejador).
  • root: Rango del proceso de envío (entero).
  • comm: Comunicador (manejador).
  • info: Información (manejador, persistente).

PARÁMETROS DE SALIDA

  • recvbuf: Dirección del búfer de recepción (elección).
  • request: Solicitud (manejador, solo no bloqueante).
  • ierror: Solo Fortran: Estado de error (entero).

DESCRIPCIÓN

MPI_Scatter es la operación inversa a MPI_Gather.

El resultado es como si la raíz ejecutara n operaciones de envío,

MPI_Send(sendbuf + i * sendcount * extent(sendtype), sendcount,
         sendtype, i, ...);

y cada proceso ejecutara una recepción,

MPI_Recv(recvbuf, recvcount, recvtype, i, ...).;

Una descripción alternativa es que la raíz envía un mensaje con MPI_Send(sendbuf, sendcount * n, sendtype, ...). Este mensaje se divide en n segmentos iguales, el i-ésimo segmento se envía al i-ésimo proceso del grupo, y cada proceso recibe este mensaje como se describió anteriormente.

El búfer de envío es ignorado para todos los procesos que no son la raíz.

La firma de tipo asociada con sendcount, sendtype en la raíz debe ser igual a la firma de tipo asociada con recvcount, recvtype en todos los procesos (sin embargo, los mapas de tipo pueden ser diferentes). Esto implica que la cantidad de datos enviados debe ser igual a la cantidad de datos recibidos, de forma par entre cada proceso y la raíz. Todavía se permiten mapas de tipo distintos entre remitente y receptor.

Todos los argumentos de la función son significativos en el proceso root, mientras que en otros procesos, solo los argumentos recvbuf, recvcount, recvtype, root, comm son significativos. Los argumentos root y comm deben tener valores idénticos en todos los procesos.

La especificación de recuentos y tipos no debe hacer que ninguna ubicación en la raíz se lea más de una vez.

Razón: Aunque no es necesario, la última restricción se impone para lograr la simetría con MPI_Gather, donde la restricción correspondiente (una restricción de escritura múltiple) es necesaria.

Ejemplo: El inverso del Ejemplo 1 en la página del manual de MPI_Gather. Scatter conjuntos de 100 enteros desde la raíz a cada proceso del grupo.

MPI_Comm comm;
int gsize,*sendbuf;
int root, rbuf[100];
...
MPI_Comm_size(comm, &gsize);
sendbuf = (int *)malloc(gsize*100*sizeof(int));
...
MPI_Scatter(sendbuf, 100, MPI_INT, rbuf, 100,
            MPI_INT, root, comm);

USO DE LA OPCIÓN IN-PLACE

Cuando el comunicador es un intracunicador, puede realizar una operación de scatter in-place (el búfer de salida se utiliza como búfer de entrada). Utilice la variable MPI_IN_PLACE como valor del recvbuf del proceso raíz. En este caso, se ignoran recvcount y recvtype, y el proceso raíz no envía datos a sí mismo.

Tenga en cuenta que MPI_IN_PLACE es un tipo especial de valor; tiene las mismas restricciones de uso que MPI_BOTTOM.

Dado que la opción in-place convierte el búfer de recepción en un búfer de envío y recepción, una vinculación de Fortran que incluye INTENT debe marcarlos como INOUT, no OUT.

CUANDO EL COMUNICADOR ES UN INTERCOMUNICADOR

Cuando el comunicador es un intercomunicador, el proceso raíz del primer grupo envía datos a todos los procesos del segundo grupo. El primer grupo define el proceso raíz. Ese proceso utiliza MPI_ROOT como valor de su argumento root. Los procesos restantes utilizan MPI_PROC_NULL como valor de sus argumentos root. Todos los procesos del segundo grupo utilizan el rango de ese proceso raíz en el primer grupo como valor de su argumento root. El argumento del búfer de recepción del proceso raíz en el primer grupo debe ser coherente con el argumento del búfer de recepción de los procesos en el segundo grupo.

ERRORES

Casi todas las rutinas de MPI devuelven un valor de error; las rutinas de C como resultado de la función y las rutinas de Fortran en el último argumento.

Antes de que se devuelva el valor de error, se llama al controlador de errores de MPI actual asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo). Si no hay ningún objeto de comunicación asociado con la llamada MPI, entonces la llamada se considera adjunta a MPI_COMM_SELF y llamará al manejador asociado.

Proporcionado por Arch Linux.

SINTAXIS

Se utiliza la siguiente sintaxis:

MPI_Scatter_init( int count, sendbuf, recvbuf, root, errhandler )

PARAMETROS DE ENTRADA

Los parámetros de entrada son:

int count
void * sendbuf
void * recvbuf
int root
void * errhandler

PARAMETROS DE SALIDA

Los parámetros de salida son:

int errcode

DESCRIPCION

Esta función inicializa un manejador de errores para el comunicador especificado.

USO DE LA OPCION EN SITIO

La opción de uso en sitio (in-place) puede ser utilizada con esta función.

CUANDO EL COMUNICADOR ES UN INTERCOMUNICADOR

Si el comunicador especificado es un intercomunicador, la función devuelve un código de error.
