MPI_Get, MPI_Rget - Copia de datos desde la memoria del objetivo a la del origen.

Sintaxis

Sintaxis C

#include <mpi.h>
MPI_Get(void *origin_addr, int origin_count, MPI_Datatype
    origin_datatype, int target_rank, MPI_Aint target_disp,
    int target_count, MPI_Datatype target_datatype, MPI_Win win)
MPI_Rget(void *origin_addr, int origin_count, MPI_Datatype
     origin_datatype, int target_rank, MPI_Aint target_disp,
     int target_count, MPI_Datatype target_datatype, MPI_Win win,
         MPI_Request *request)

Parámetros de entrada

  • origin_addr : Dirección inicial del buffer de origen (puntero).
origin_count
Número de elementos en el buffer de origen (entero no negativo).
  • origin_datatype : Tipo de dato de cada elemento en el buffer de origen (handle).
  • target_rank : Rango del proceso destino (entero no negativo).
target_disp
Desplazamiento desde el inicio de la ventana hasta el inicio del buffer destino (entero no negativo).
•
target_count
Número de elementos en el buffer destino (entero no negativo).
  • tipo de dato de destino: tipo de dato de cada elemento en el buffer destino (handle).
  • win : Objeto de ventana utilizado para la comunicación (handle).

Parámetro de salida

  • request : MPI_Rget: solicitud RMA
  • ierror : Solo en Fortran: código de error (entero).

Descripción

MPI_Get copia datos desde la memoria del proceso destino a la del proceso origen, de forma similar a MPI_Put, pero la dirección de la transferencia de datos es inversa. El tipo de dato de origen no puede especificar elementos superpuestos en el buffer de origen. El buffer destino debe estar contenido dentro de la ventana destino, y los datos copiados deben caber sin truncamiento en el buffer de origen. Solo los procesos en el mismo nodo pueden acceder a la ventana destino.

MPI_Rget es similar a MPI_Get, excepto que aloja una solicitud de comunicación y la asocia con el handle de solicitud (el argumento request), que puede ser usado para esperar o comprobar la finalización de la operación. La finalización de una operación MPI_Rget indica que los datos están disponibles en el buffer de origen. Si origin_addr apunta a memoria asociada a una ventana, los datos se vuelven disponibles en la copia privada de esta ventana.

Errores

La mayoría de las rutinas MPI devuelven un valor de error; en las rutinas C, el resultado se devuelve como el valor de retorno de la función, y en las rutinas Fortran, en el último argumento.

Antes de devolver el valor de error, se llama al gestor de errores asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo) que se está utilizando. Si no hay ningún objeto de comunicación asociado con la llamada MPI, se considera que la llamada está asociada a MPI_COMM_SELF y se llama al gestor correspondiente. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se usa el modelo de sesiones exclusivamente), el error eleva el gestor de errores inicial. El gestor de errores inicial puede cambiarse llamando a MPI_Comm_set_errhandler sobre MPI_COMM_SELF cuando se utiliza el modelo del mundo, o mediante el argumento mpi_initial_errhandler de mpiexec o la clave info de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no hay otro gestor de errores adecuado configurado, se llama al gestor MPI_ERRORS_RETURN para las funciones de I/O MPI y al gestor MPI_ERRORS_ABORT para todas las demás funciones MPI.

Open MPI incluye tres gestores de errores predefinidos que se pueden utilizar:

  • MPI_ERRORS_ARE_FATAL : El programa aborta todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT : Un gestor de errores que puede ser invocado en un comunicador, ventana, archivo o sesión. Cuando se invoca en un comunicador, actúa como si se hubiera llamado MPI_Abort en ese comunicador. Si se invoca en una ventana o archivo, actúa como si se hubiera llamado MPI_Abort en un comunicador que contiene el grupo de procesos en la ventana o archivo correspondiente. Si se invoca en una sesión, aborta solo el proceso local.
  • MPI_ERRORS_RETURN : Devuelve un código de error al programa.

Las aplicaciones MPI también pueden implementar sus propios gestores de errores llamando:

  • MPI_Comm_create_errhandler seguido de MPI_Comm_set_errhandler
  • MPI_File_create_errhandler seguido de MPI_File_set_errhandler
  • MPI_Session_create_errhandler seguido de MPI_Session_set_errhandler o en MPI_Session_init
  • MPI_Win_create_errhandler seguido de MPI_Win_set_errhandler

Nota: MPI no garantiza que un programa MPI pueda continuar después de un error.

Ver la página del manual de MPI para una lista completa de códigos de error MPI.

Ver la sección de manejo de errores de la especificación MPI-3.1 para más información.
