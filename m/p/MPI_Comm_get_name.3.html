Paquete: openmpi

MPI_COMM_GET_NAME(3) Open MPI MPI_Comm_get_name(3)

MPI_Comm_get_name — Devuelve el nombre que fue asociado más recientemente con un comunicador.

SINTAXIS

Sintaxis C

#include <mpi.h>
int MPI_Comm_get_name(MPI_Comm comm, char *comm_name, int *resultlen)

Sintaxis Fortran

USE MPI
! o la forma antigua: INCLUDE 'mpif.h'
MPI_COMM_GET_NAME(COMM, COMM_NAME, RESULTLEN, IERROR)
     INTEGER COMM, RESULTLEN, IERROR
     CHARACTER*(*) COMM_NAME

Sintaxis Fortran 2008

USE mpi_f08
MPI_Comm_get_name(comm, comm_name, resultlen, ierror)
     TYPE(MPI_Comm), INTENT(IN) :: comm
     CHARACTER(LEN=MPI_MAX_OBJECT_NAME), INTENT(OUT) :: comm_name
     INTEGER, INTENT(OUT) :: resultlen
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARÁMETRO DE ENTRADA

•
comm: Comunicador cuyo nombre se va a devolver (handle).

PARÁMETRO DE SALIDA

  • comm_name: Nombre almacenado previamente en el comunicador, o una cadena vacía si no existe dicho nombre (cadena).
  • resultlen: Longitud del nombre devuelto (entero).
  • ierror: Solo Fortran: Estado del error (entero).

DESCRIPCIÓN

MPI_Comm_get_name devuelve el último nombre que se asoció previamente con el comunicador dado. El nombre puede ser establecido y recuperado desde cualquier lenguaje. El mismo nombre se devolverá independientemente del lenguaje utilizado. comm_name debe ser asignado para que pueda contener una cadena resultante de longitud MPI_MAX_OBJECT_NAME caracteres. MPI_Comm_get_name devuelve una copia del nombre establecido en comm_name.

Si el usuario no ha asociado un nombre con un comunicador, o si ocurre un error, MPI_Comm_get_name devolverá una cadena vacía (todos espacios en Fortran, “” en C). Los tres comunicadores predefinidos tendrán nombres predefinidos asociados con ellos. Por lo tanto, los nombres de MPI_COMM_WORLD, MPI_COMM_SELF y MPI_COMM_PARENT tendrán el valor predeterminado de MPI_COMM_WORLD, MPI_COMM_SELF y MPI_COMM_PARENT. El hecho de que el sistema pueda haber elegido dar un nombre predeterminado a un comunicador no impide que el usuario establezca un nombre en el mismo comunicador; hacer esto elimina el nombre antiguo y asigna uno nuevo.

NOTAS

Es seguro simplemente imprimir la cadena devuelta por MPI_Comm_get_name, ya que siempre es una cadena válida, incluso si no había ningún nombre.

Tenga en cuenta que asociar un nombre con un comunicador no tiene ningún efecto en la semántica de un programa MPI, y aumentará (necesariamente) el requisito de almacenamiento del programa, ya que los nombres deben guardarse. Por lo tanto, no hay ningún requisito de que los usuarios utilicen estas funciones para asociar nombres con comunicadores. Sin embargo, la depuración y la generación de perfiles de aplicaciones MPI pueden facilitarse si se asocian nombres con comunicadores, ya que el depurador o generador de perfiles debería poder presentar la información de una manera menos críptica.

ERRORES

Casi todas las rutinas MPI devuelven un valor de error; las rutinas C como resultado de la función y las rutinas Fortran en el último argumento.

Antes de que se devuelva el valor de error, se llama al controlador de errores MPI actual asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo). Si no hay ningún objeto de comunicación asociado con la llamada MPI, la llamada se considera adjunta a MPI_COMM_SELF y llamará al controlador de errores MPI asociado. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se utiliza exclusivamente el Modelo de Sesiones) el error invoca el controlador de errores inicial. El controlador de errores inicial se puede cambiar llamando a MPI_Comm_set_errhandler en MPI_COMM_SELF cuando se utiliza el modelo World, o el argumento de línea de comandos mpi_initial_errhandler de mpiexec o la clave de información de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no se ha establecido ningún otro controlador de errores apropiado, entonces se llama al controlador de errores MPI_ERRORS_RETURN para las funciones de E/S MPI y al controlador de errores MPI_ERRORS_ABORT para todas las demás funciones MPI.

Open MPI incluye tres controladores de errores predefinidos que se pueden utilizar:

  • MPI_ERRORS_ARE_FATAL Provoca que el programa aborte todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT Un controlador de errores que puede ser invocado en un comunicador, ventana, archivo o sesión. Cuando se llama en un comunicador, actúa como si se hubiera llamado a MPI_Abort en ese comunicador. Si se llama en una ventana o archivo, actúa como si se hubiera llamado a MPI_Abort en un comunicador que contiene el grupo de procesos de la ventana o archivo correspondiente. Si se llama en una sesión, solo aborta el proceso local.
  • MPI_ERRORS_RETURN Devuelve un código de error a la aplicación.

Las aplicaciones MPI también pueden implementar sus propios controladores de errores llamando a:

  • MPI_Comm_create_errhandler y luego MPI_Comm_set_errhandler
  • MPI_File_create_errhandler y luego MPI_File_set_errhandler
  • MPI_Session_create_errhandler y luego MPI_Session_set_errhandler o en MPI_Session_init
  • MPI_Win_create_errhandler y luego MPI_Win_set_errhandler

Tenga en cuenta que MPI no garantiza que un programa MPI pueda continuar después de un error.

Consulte la página del manual de MPI para obtener una lista completa de los códigos de error de MPI.

Consulte la sección de Manejo de Errores del estándar MPI-3.1 para obtener más información.
