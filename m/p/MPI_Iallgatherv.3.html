MPI_Iallgatherv(3) Open MPI MPI_Iallgatherv(3)

MPI_Allgatherv, MPI_Iallgatherv, MPI_Allgatherv_init - Recopila datos de todos los procesos y los entrega a todos. Cada proceso puede contribuir una cantidad diferente de datos.

SINTAXIS

     MPI_Datatype sendtype, void *recvbuf, const int recvcounts[],
     const int displs[], MPI_Datatype recvtype, MPI_Comm comm)
int MPI_Iallgatherv(const void *sendbuf, int sendcount,
     MPI_Datatype sendtype, void *recvbuf, const int recvcounts[],
     const int displs[], MPI_Datatype recvtype, MPI_Comm comm,

        MPI_Info info, MPI_Request *request)

PARÁMETROS DE ENTRADA

  • sendbuf: Dirección de inicio del buffer de envío (opcional).
  • sendcount: Número de elementos en el buffer de envío (entero).
  • sendtype: Tipo de datos de los elementos del buffer de envío (handle).
  • recvcount: Array de enteros (de longitud del grupo) que contienen el número de elementos a recibir de cada proceso.
  • displs: Array de enteros (de longitud del grupo). El elemento i especifica el desplazamiento (relativo a recvbuf) donde se colocarán los datos entrantes del proceso i.
  • recvtype: Tipo de datos de los elementos del buffer de recepción (handle).
  • comm: Comunicador (handle).
  • info: Información (handle, solo persistente).

PARÁMETROS DE SALIDA

  • recvbuf: Dirección del buffer de recepción (opcional).
  • request: Solicitud (handle, no bloqueante).
  • ierror: Solo en Fortran: Código de error (entero).

DESCRIPCIÓN

MPI_Allgatherv es similar a MPI_Allgather en que todos los procesos recopilan datos de todos los otros procesos, excepto que cada proceso puede enviar una cantidad diferente de datos. El bloque de datos enviado desde el proceso j se recibe por todos los procesos y se coloca en el bloque j del buffer recvbuf.

La firma de tipo asociada con sendcount, sendtype en el proceso j debe ser igual a la firma de tipo asociada con recvcounts[j], recvtype en cualquier otro proceso.

El resultado es como si todos los procesos hubieran ejecutado llamadas a

MPI_Allgatherv(sendbuf, sendcount, sendtype, recvbuf, recvcount,
              displs,recvtype,root,comm);
// para root = 0, ..., n-1.

Las reglas para el uso correcto de MPI_Allgatherv se encuentran fácilmente en las reglas correspondientes a MPI_Gatherv.

USO DE LA OPCIÓN EN SITIO (IN-PLACE)

Cuando el comunicador es un comunicador intragrupo, puede realizar una operación de recopilación en sitio (el buffer de salida se usa como el buffer de entrada). Use la variable MPI_IN_PLACE como el valor de sendbuf. En este caso, sendcount y sendtype se ignoran. Se supone que los datos de entrada de cada proceso están en el área donde ese proceso recibiría su propia contribución en el buffer de recepción. Específicamente, el resultado de una llamada a MPI_Allgatherv que utilizó la opción en sitio es idéntico al caso en que todos los procesos hubieran ejecutado n llamadas a

MPI_Allgatherv ( MPI_IN_PLACE, 0, MPI_DATATYPE_NULL, recvbuf,
                 recvcounts, displs, recvtype, root, comm );
// para root =0, ... , n-1.

Nota: MPI_IN_PLACE es un valor especial; tiene las mismas restricciones de uso que MPI_BOTTOM.

Dado que la opción en sitio convierte el buffer de recepción en un buffer de envío y recepción, una vinculación de Fortran que incluya INTENT debe marcarlos como INOUT, no como OUT.

CUANDO EL COMUNICADOR ES UN COMUNICADOR INTERGRUPO

Cuando el comunicador es un comunicador intergrupo, la operación de recopilación ocurre en dos fases. Los datos se recopilan de todos los miembros del primer grupo, se concatenan y se reciben por todos los miembros del segundo grupo. Luego, los datos se recopilan de todos los miembros del segundo grupo, se concatenan y se reciben por todos los miembros del primero. Los argumentos del buffer de envío en el grupo uno deben ser consistentes con los argumentos del buffer de recepción en el grupo dos, y viceversa. La operación debe exhibir un comportamiento simétrico, dúplex completo.

ERRORES

La mayoría de las rutinas MPI devuelven un valor de error; en las rutinas C, el resultado se devuelve como el valor de retorno de la función, y en las rutinas Fortran, el último argumento es el valor de error.

Antes de devolver el valor de error, se llama al manejador de errores asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo) actual. Si no hay ningún objeto de comunicación asociado con la llamada MPI, se considera que la llamada está asociada con MPI_COMM_SELF y se llama al manejador de errores correspondiente. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se usa el Modelo de Sesiones exclusivamente), el error eleva el manejador de errores inicial. El manejador de errores inicial se puede cambiar llamando a MPI_Comm_set_errhandler en MPI_COMM_SELF cuando se usa el modelo del mundo, o a través del parámetro mpi_initial_errhandler de mpiexec o la clave info de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no hay ningún manejador adecuado establecido, se llama al manejador de errores MPI_ERRORS_RETURN para las funciones de E/S de MPI y al manejador de errores MPI_ERRORS_ABORT para todas las demás funciones de MPI.

SINTAXIS

Open MPI incluye tres manejadores de errores predefinidos que pueden usarse:

  • MPI_ERRORS_ARE_FATAL Causa que el programa aborte todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT Un manejador de errores que puede invocarse en un comunicador, ventana, archivo o sesión. Cuando se invoca en un comunicador, actúa como si se hubiera llamado MPI_Abort en ese comunicador. Si se invoca en una ventana o archivo, actúa como si se hubiera llamado MPI_Abort en un comunicador que contiene el grupo de procesos correspondiente en la ventana o archivo. Si se invoca en una sesión, aborta solo el proceso local.
  • MPI_ERRORS_RETURN Devuelve un código de error a la aplicación.

Las aplicaciones MPI también pueden implementar sus propios manejadores de errores llamando:

  • MPI_Comm_create_errhandler seguido de MPI_Comm_set_errhandler
  • MPI_File_create_errhandler seguido de MPI_File_set_errhandler
  • MPI_Session_create_errhandler seguido de MPI_Session_set_errhandler o en MPI_Session_init
  • MPI_Win_create_errhandler seguido de MPI_Win_set_errhandler

Nota: Open MPI no garantiza que un programa MPI pueda continuar después de un error.

Consulte la página man de MPI para una lista completa de códigos de error de MPI.

Consulte la sección de Manejo de Errores de la especificación MPI-3.1 para más información.
