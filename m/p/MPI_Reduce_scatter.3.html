PARÁMETROS DE ENTRADA

  • sendbuf: Dirección de inicio del buffer de salida (opcional).
  • recvcounts: Array entero que especifica el número de elementos en el resultado distribuido a cada proceso. El array debe ser idéntico en todos los procesos de llamada.
  • datatype: Tipo de elementos del buffer de entrada (handle).
  • op: Operación (handle).
  • comm: Comunicador (handle).
  • info: Información (handle, persistente).

PARÁMETROS DE SALIDA

  • recvbuf: Dirección de inicio del buffer de recepción (opcional).
  • request: Solicitante (handle, no bloqueado).
  • ierror: Solo en Fortran: Estado de error (entero).

DESCRIPCIÓN

MPI_Reduce_scatter realiza una reducción elemento a elemento en un vector de count = S(i)recvcounts[i] elementos en el buffer de entrada definido por sendbuf, count y datatype. Luego, el vector de resultados de la reducción se divide en n segmentos distintos, donde n es el número de procesos en el grupo. El segmento i contiene recvcounts[i] elementos. El segmento i se envía a proceso i y se almacena en el buffer de recepción definido por recvbuf, recvcounts[i], y datatype.

USO DE OPCION DE ENTRADA

Cuando el comunicador es un comunicador intracomunicador, se puede realizar una operación de reducción-scatter en lugar de (el buffer de salida se usa como el buffer de entrada). Use el valor MPI_IN_PLACE como el valor de la variable sendbuf. En este caso, los datos de entrada provienen del tope del buffer de recepción. El área ocupada por los datos de entrada puede ser mayor o menor que la data registrada por el buffer de salida.

CUANDO EL COMUNICADOR ES UN COMUNICADOR INTER

Cuando el comunicador es un comunicador inter, la operación de reducción-scatter ocurre en dos etapas. Primero, el resultado de la reducción realizada en los datos proporcionados por los procesos del primer grupo se dispersa entre los procesos del segundo grupo. Luego, el proceso inverso ocurre: la reducción realizada en los datos proporcionados por los procesos del segundo grupo se dispersa entre los procesos del primer grupo. Para cada grupo, todos los procesos proporcionan el mismo recvcounts argumento, y la suma de los valores de recvcounts debe ser la misma para ambos grupos.

NOTAS SOBRE OPCIONES COLLECTIVAS

Las funciones de reducción (MPI_Op) no devuelven un valor de error. Como resultado, si las funciones detectan un error, solo pueden llamar a MPI_Abort o pasar por alto el problema. Por lo tanto, si cambias el manejador de errores de MPI_ERRORS_ARE_FATAL a algo else, por ejemplo, MPI_ERRORS_RETURN, no se indicará ningún error.

La razón de esto es el problema de rendimiento en garantizar que todas las rutinas de operación colectiva devuelvan el mismo valor de error.

ERRORES

Más del 90% de las rutínas MPI devuelven un valor de error; las rutínas C lo devuelven como resultado de la función y las rutínas Fortran en el último argumento.

Antes de devolver el valor de error, se llama al manejador de error asociado con el objeto de comunicación (por ejemplo, communicator, window, file) actual. Si no hay objeto de comunicación asociado con la llamada MPI, se considera que la llamada está asociada a MPI_COMM_SELF y se llama al manejador asociado con MPI_COMM_SELF. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se usa el Modelo de Sesiones exclusivamente), se lanza el manejador de error inicial. El manejador de error inicial puede cambiarse llamando a MPI_Comm_set_errhandler sobre MPI_COMM_SELF cuando se use el modelo del Mundo, o el argumento mpi_initial_errhandler en mpiexec o la clave info en MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no hay otro manejador de error apropiado, se llama el manejador de error MPI_ERRORS_RETURN para las funciones de I/O MPI y el manejador de error MPI_ERRORS_ABORT para otras funciones MPI.

Open MPI incluye tres manejadores de error predeterminados que pueden usarse:

  • MPI_ERRORS_ARE_FATAL — Detiene todos los procesos conectados de MPI.
  • MPI_ERRORS_ABORT — Manejador que puede invocarse en un comunicador, ventana, archivo o sesión. Cuando se invoca en un comunicador, actúa como si se hubiera llamado MPI_Abort en ese comunicador. Si se invoca en una ventana o archivo, actúa como si se hubiera llamado MPI_Abort en un comunicador que contiene los procesos en la ventana o archivo correspondiente. Si se invoca en una sesión, detiene solo el proceso local.
  • MPI_ERRORS_RETURN — Devuelve un código de error a la aplicación.

Las aplicaciones MPI pueden también implementar sus propios manejadores de error llamando:

  • MPI_Comm_create_errhandler luego MPI_Comm_set_errhandler
  • MPI_File_create_errhandler luego MPI_File_set_errhandler
  • MPI_Session_create_errhandler luego MPI_Session_set_errhandler

MPI_Reduce_scatter.3 - Open MPI 5.0.9

SYNTAX

int MPI_Reduce_scatter(const void *sendbuf, void *recvbuf, const int recvcounts[],
                       MPI_Datatype datatype, MPI_Op op, MPI_Comm comm);

INPUT PARAMETERS

sendbuf
punto de partida de los datos de entrada (si el valor es MPI_IN_PLACE, los datos se toman del búfer de recepción).
recvbuf
punto de partida de los datos de salida.
recvcounts
número de elementos de datos a recibir del procesador remoto para cada uno de los procesadores de la comm. Cada entrada debe ser no negativa.
datatype
tipo de datos de los elementos en los búferes.
op
operación de reducción (véase laSección de Operaciones de Reducción).
comm
comunicador (véase laSección de Comunicadores).

OUTPUT PARAMETERS

recvbuf
datos de salida de la operación de reducción.

DESCRIPTION

La rutina MPI_Reduce_scatter es una combinación de las rutinas MPI_Scatter y MPI_Reduce. Realiza una operación de reducción en los datos enviados desde todos los procesos de un comunicador y distribuye los resultados de la reducción a los procesos de ese mismo comunicador. Específicamente, la rutina realiza las siguientes operaciones:

  1. Cada proceso participa en una operación de reducción utilizando la rutina MPI_Reduce. El argumento op se utiliza para especificar la operación de reducción, y comm es el comunicador. Cada proceso envía el contenido de su búfer de envío sendbuf.
  2. El resultado de esta reducción es un conjunto de elementos que son idénticos en todos los procesos.
  3. Este conjunto de elementos se distribuye de forma dispersa entre los procesos del comunicador. La dispersión se realiza utilizando el argumento recvcounts. Para cada proceso i en el comunicador, recvcounts[i] especifica el número de elementos de la reducción que se reciben en el búfer de recepción de ese proceso, recvbuf.

La suma de todas las entradas en recvcounts debe ser igual al número de elementos en el búfer de envío de cada proceso. El número total de elementos de datos enviados por cada proceso debe ser igual a la suma de las entradas en recvcounts.

Los argumentos sendbuf y recvbuf se utilizan para enviar y recibir los datos, respectivamente. Si sendbuf es MPI_IN_PLACE, el búfer de recepción en cada proceso contendrá los datos que se van a enviar. Los datos en el búfer de recepción se utilizan como datos de envío y el resultado de la reducción se coloca de nuevo en el mismo búfer de recepción.

USE OF IN-PLACE OPTION

Cuando el argumento sendbuf se establece en MPI_IN_PLACE, los datos que se van a enviar desde cada proceso se encuentran en el búfer de recepción de ese proceso. El resultado de la operación de reducción se coloca de nuevo en el mismo búfer de recepción. En este caso, el argumento recvbuf se utiliza tanto para la entrada como para la salida. El búfer de recepción debe estar correctamente particionado para que coincida con la estructura de recvcounts.

WHEN COMMUNICATOR IS AN INTER-COMMUNICATOR

Cuando el comunicador es un inter-comunicador, la operación se realiza entre los procesos del grupo anterior y los procesos del grupo posterior. Los procesos del grupo anterior envían sus datos y los procesos del grupo posterior reciben los resultados de la reducción. La rutina MPI_Reduce_scatter no está definida para inter-comunicadores.

NOTES ON COLLECTIVE OPERATIONS

Los argumentos sendbuf y recvbuf se utilizan de manera diferente dependiendo de si el proceso participa como remitente o receptor. En el caso de una operación colectiva que implica un MPI_IN_PLACE, el búfer especificado se utiliza para la entrada y la salida.

Todas las operaciones colectivas deben ejecutarse con la misma firma de rutina en todos los procesos del comunicador. Las operaciones colectivas pueden ser ejecutadas sólo por los procesos de un comunicador.

Una operación colectiva es un error si el comunicador no es un comunicador intracomunicador.

El argumento recvcounts debe ser el mismo para todos los procesos de un comunicador. Sin embargo, esto no es cierto para MPI_Reduce_scatter. La suma de las entradas de recvcounts debe ser igual al número de elementos del tipo de datos especificado en el búfer de envío.

ERRORS

Los errores de MPI ocurren cuando un comunicador es inválido. Los errores de tiempo de espera pueden ocurrir si los procesos no responden. Si se detecta un error de tiempo de espera, la rutina puede devolver o no devolver un código de error, dependiendo de la configuración de la infraestructura de tiempo de espera.

Si se detecta un error grave, los procesos pueden salir. Si se requiere la finalización de la ejecución, se debe llamar a MPI_Abort o MPI_Finalize.

Cuando se produce un error, si la rutina no devuelve un código de error, puede ser que el error no se pueda manejar o que el manejador de errores predeterminado no pueda registrar el error. Para obtener más información sobre los manejadores de errores, consulte MPI_Errhandler_create, MPI_Errhandler_set o MPI_Errhandler_free. Para más información, consulte la Sección de Manejo de Errores del Estándar MPI-3.1.

Los manejadores de errores para las rutinas de MPI pueden ser definidos y utilizados en el punto de entrada de la rutina o en MPI_Session_init.

  • MPI_Win_create_errhandler luego MPI_Win_set_errhandler

Nota: MPI no garantiza que un programa MPI pueda continuar después de un error.
