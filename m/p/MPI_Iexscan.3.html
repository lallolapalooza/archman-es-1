PARÁMETROS DE ENTRADA

  • sendbuf: Búfer de envío (opcional).
  • count: Número de elementos en el búfer de entrada (entero).
  • datatype: Tipo de dato de los elementos del búfer de entrada (manejador).
  • op: Operación (manejador).
  • comm: Comunicador (manejador).

PARÁMETROS DE SALIDA

  • recvbuf: Búfer de recepción (opcional).
  • request: Solicitud (manejador, solo no bloqueante).
  • ierror: Solo Fortran: Estado de error (entero).

DESCRIPCIÓN

MPI_Exscan se utiliza para realizar una reducción de prefijo exclusiva en datos distribuidos entre los procesos que llaman. La operación devuelve, en el recvbuf del proceso con rango i, la reducción (calculada según la función op) de los valores en los sendbuf de los procesos con rangos 0, ..., i-1. Compárese esto con la funcionalidad de MPI_Scan, que calcula sobre el rango 0, ..., i (inclusive). El tipo de operaciones soportadas, sus semánticas y las restricciones en los búferes de envío y recepción son las mismas que para MPI_Reduce.

El valor en recvbuf en el proceso 0 no está definido y no es fiable, ya que recvbuf no es significativo para el proceso 0. El valor de recvbuf en el proceso 1 es siempre el valor en sendbuf del proceso 0.

USO DE LA OPCIÓN IN-PLACE

La opción "in place" para intracommunicators se especifica pasando MPI_IN_PLACE en el argumento sendbuf. En este caso, los datos de entrada se toman del búfer de recepción y se reemplazan por los datos de salida.

Tenga en cuenta que MPI_IN_PLACE es un tipo especial de valor; tiene las mismas restricciones de uso que MPI_BOTTOM.

Dado que la opción in-place convierte el búfer de recepción en un búfer de envío y recepción, una vinculación de Fortran que incluya INTENT debe marcarlos como INOUT, no como OUT.

NOTAS

MPI no especifica qué proceso calcula qué operación. En particular, ambos procesos 0 y 1 pueden participar en el cálculo, aunque los resultados para el recvbuf de ambos procesos sean degenerados. Por lo tanto, todos los procesos, incluidos 0 y 1, deben proporcionar el mismo op.

Se puede argumentar, desde una perspectiva matemática, que la definición de MPI_Exscan es insatisfactoria porque la salida en el proceso 0 no está definida. La salida "matemáticamente correcta" para el proceso 0 sería el elemento unitario de la operación de reducción. Sin embargo, tal definición de un escaneo exclusivo no funcionaría con funciones op definidas por el usuario, ya que no hay forma de que MPI "sepa" el valor unitario para estas operaciones personalizadas.

NOTAS SOBRE OPERACIONES COLECTIVAS

Las funciones de reducción de tipo MPI_Op no devuelven un valor de error. Como resultado, si las funciones detectan un error, lo único que pueden hacer es llamar a MPI_Abort o omitir silenciosamente el problema. Por lo tanto, si el manejador de errores se cambia de MPI_ERRORS_ARE_FATAL a otra cosa (por ejemplo, MPI_ERRORS_RETURN), es posible que no se indique ningún error.

La razón de esto son los problemas de rendimiento para garantizar que todas las rutinas colectivas devuelvan el mismo valor de error.

ERRORES

Casi todas las rutinas de MPI devuelven un valor de error; en las rutinas C como resultado de retorno de la función y en las rutinas Fortran en el último argumento.

Antes de que se devuelva el valor de error, se llama al manejador de errores de MPI actual asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo). Si no hay ningún objeto de comunicación asociado con la llamada MPI, entonces la llamada se considera adjunta a MPI_COMM_SELF y llamará al manejador de errores de MPI asociado. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se usa exclusivamente el Modelo de Sesiones), el error eleva el manejador de errores inicial. El manejador de errores inicial se puede cambiar llamando a MPI_Comm_set_errhandler en MPI_COMM_SELF cuando se usa el modelo World, o el argumento de información mpi_initial_errhandler de mpiexec o la clave de información para MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no se ha configurado ningún otro manejador de errores apropiado, entonces se llama al manejador de errores MPI_ERRORS_RETURN para las funciones de E/S de MPI y al manejador de errores MPI_ERRORS_ABORT para todas las demás funciones de MPI.

Open MPI incluye tres manejadores de errores predefinidos que se pueden usar:

  • MPI_ERRORS_ARE_FATAL Provoca que el programa aborte todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT Un manejador de errores que puede invocarse en un comunicador, ventana, archivo o sesión. Cuando se llama en un comunicador, actúa como si se hubiera llamado a MPI_Abort en ese comunicador. Si se llama en una ventana o archivo, actúa como si se hubiera llamado a MPI_Abort en un comunicador que contiene el grupo de procesos de la ventana o archivo correspondiente. Si se llama en una sesión, solo aborta el proceso local.
  • MPI_ERRORS_RETURN Devuelve un código de error a la aplicación.

Las aplicaciones MPI también pueden implementar sus propios manejadores de errores llamando a:

  • MPI_Comm_create_errhandler luego MPI_Comm_set_errhandler
  • MPI_File_create_errhandler luego MPI_File_set_errhandler
  • MPI_Session_create_errhandler luego
