PARÁMETROS DE ENTRADA

  • sendbuf : Dirección de inicio del búfer de envío (elección).
  • sendcount : Número de elementos en el búfer de envío (entero).
  • sendtype : Tipo de datos de los elementos del búfer de envío (manejador).
recvcounts
Arreglo de enteros (de longitud igual al tamaño del grupo) que contiene el número de elementos que se reciben de cada proceso (solo significativo en la raíz).
•
displs
Arreglo de enteros (de longitud igual al tamaño del grupo). La entrada i especifica el desplazamiento relativo a recvbuf en el que se colocará la información entrante del proceso i (solo significativo en la raíz).
•
recvtype
Tipo de datos de los elementos del búfer de recepción (solo significativo en la raíz) (manejador).
  • root : Rango del proceso receptor (entero).
  • comm : Comunicador (manejador).
  • info : Información (manejador, solo persistente).

PARÁMETROS DE SALIDA

•
recvbuf
Dirección del búfer de recepción (elección, solo significativa en la raíz).
  • request : Solicitud (manejador, solo no bloqueante).
  • ierror : Solo Fortran: Estado de error (entero).

DESCRIPCIÓN

MPI_Gatherv extiende la funcionalidad de MPI_Gather al permitir un recuento variable de datos de cada proceso, ya que recvcounts es ahora un arreglo. También permite mayor flexibilidad en cuanto a dónde se colocan los datos en la raíz, proporcionando el nuevo argumento displs.

El resultado es como si cada proceso, incluido el proceso raíz, enviara un mensaje a la raíz,

MPI_Send(sendbuf, sendcount, sendtype, root, ...);

y la raíz ejecutara n recepciones,

MPI_Recv(recvbuf + disp[i] * extent(recvtype), recvcounts[i],
         recvtype, i, ...);

Los mensajes se colocan en el búfer de recepción del proceso raíz en orden de rango, es decir, los datos enviados desde el proceso j se colocan en la j-ésima porción del búfer de recepción recvbuf en el proceso root. La j-ésima porción de recvbuf comienza en el desplazamiento displs[j] elementos (en términos de recvtype) dentro de recvbuf.

El búfer de recepción se ignora para todos los procesos que no son raíz.

La firma de tipo implícita por sendcount, sendtype en el proceso i debe ser igual a la firma de tipo implícita por recvcounts[i], recvtype en la raíz. Esto implica que la cantidad de datos enviados debe ser igual a la cantidad de datos recibidos, par a par entre cada proceso y la raíz. Aún se permiten mapas de tipos distintos entre el remitente y el receptor, como se ilustra en el Ejemplo 2.

Todos los argumentos de la función son significativos en el proceso raíz, mientras que en otros procesos, solo los argumentos sendbuf, sendcount, sendtype, root, comm son significativos. Los argumentos root y comm deben tener valores idénticos en todos los procesos.

La especificación de recuentos, tipos y desplazamientos no debe provocar que ninguna ubicación en la raíz se escriba más de una vez. Tal llamada es errónea.

Ejemplo 1: Ahora cada proceso envía 100 enteros a la raíz, pero coloca cada conjunto (de 100) de enteros escalonados en el extremo receptor. Use MPI_Gatherv y el argumento displs para lograr este efecto. Suponga que stride >= 100.

MPI_Comm comm;
int gsize, sendarray[100];
int root, *rbuf, stride;
int *displs, i, rcounts;
...
MPI_Comm_size(comm, &gsize);
rbuf = (int)malloc(gsize * stride * sizeof(int));
displs = (int)malloc(gsize * sizeof(int));
rcounts = (int )malloc(gsize * sizeof(int));
for (i=0; i<gsize; ++i) {
  displs[i] = i * stride;
  rcounts[i] = 100;
}
MPI_Gatherv(sendarray, 100, MPI_INT, rbuf, rcounts, displs, MPI_INT,
            root, comm);

Tenga en cuenta que el programa es erróneo si stride < 100.

Descripción

El MPI_Gatherv crea un tipo de datos de colección donde cada proceso puede enviar una cantidad de datos diferente. El entero recvbuf de entrada, utilizado por el proceso raíz, es un búfer que contiene los datos enviados por todos los procesos del comunicador. Parámetros recvcount y displs, que son vectores, especifican la cantidad de elementos de datos que se van a recibir de cada proceso y el desplazamiento de cada bloque en el búfer de recepción, respectivamente. Los tipos de datos de envío y recepción no necesitan ser los mismos.

Los argumentos sendbuf y recvbuf se refieren a búferes en el espacio de direcciones del proceso que llama. El argumento sendbuf se ignora si el proceso que llama es el proceso raíz.

Ejemplo 1: Cada proceso envía una matriz de enteros de 100x150 en C. Todos los procesos envían el mismo número de datos. La raíz recibe estos datos en un búfer linealmente, con bloques de 100 * 150 enteros.

MPI_Comm comm;
int gsize, sendarray[100][150], *sptr;
int root, *rbuf, stride, myrank;
MPI_Datatype stype;
int displs, i, rcounts;
...
MPI_Comm_size(comm, &gsize);
MPI_Comm_rank( comm, &myrank );
stride = 150; // stride for receiving into a linear buffer
rbuf = (int)malloc(gsize * stride * 100 * sizeof(int));
displs = (int)malloc(gsize * sizeof(int));
rcounts = (int )malloc(gsize * sizeof(int));
for (i=0; i<gsize; ++i) {
  displs[i] = i * stride * 100; // displacement for each block
  rcounts[i] = stride * 100;   // count for each block
}
// Create datatype for sending a whole row
MPI_Type_vector(100, 1, stride, MPI_INT, &stype);
MPI_Type_commit( &stype );
sptr = &sendarray[0][0]; // address of the start of the array
MPI_Gatherv(sptr, 1, stype, rbuf, rcounts, displs, MPI_INT,
            root, comm);

Ejemplo 2: El proceso i envía 100 * 150 enteros de la matriz 100x150. A diferencia del ejemplo anterior, los datos recibidos en la raíz se organizan en un búfer con un stride determinado.

MPI_Comm comm;
int gsize, sendarray[100][150], *sptr;
int root, *rbuf, stride, myrank;
MPI_Datatype stype;
int displs, i, rcounts;
...
MPI_Comm_size(comm, &gsize);
MPI_Comm_rank( comm, &myrank );
stride = gsize * 150; // stride between blocks at the receiving end
rbuf = (int)malloc(stride * 100 * sizeof(int));
displs = (int)malloc(gsize * sizeof(int));
rcounts = (int )malloc(gsize * sizeof(int));
for (i=0; i<gsize; ++i) {
  displs[i] = i * stride; // displacement for each block
  rcounts[i] = 150 * 100;   // count for each block
}
// Create datatype for sending a whole row
MPI_Type_vector(100, 1, 150, MPI_INT, &stype);
MPI_Type_commit( &stype );
sptr = &sendarray[0][0]; // address of the start of the array
MPI_Gatherv(sptr, 1, stype, rbuf, rcounts, displs, MPI_INT,
            root, comm);

Ejemplo 3: El proceso i envía (100-i) enteros de la i-ésima columna de una matriz de enteros de 100 x 150, en C. Se recibe en un búfer con stride, como en los dos ejemplos anteriores.

MPI_Comm comm;
int gsize, sendarray[100][150], *sptr;
int root, *rbuf, stride, myrank;
MPI_Datatype stype;
int displs, i, rcounts;
...
MPI_Comm_size(comm, &gsize);
MPI_Comm_rank( comm, &myrank );
rbuf = (int)malloc(gsize * stride * sizeof(int));
displs = (int)malloc(gsize * sizeof(int));
rcounts = (int )malloc(gsize * sizeof(int));
for (i=0; i<gsize; ++i) {
  displs[i] = i * stride;
  rcounts[i] = 100-i; // nota el cambio del ejemplo anterior
}
// Crear tipo de datos para la columna que estamos enviando
MPI_Type_vector(100-myrank, 1, 150, MPI_INT, &stype);
MPI_Type_commit( &stype );
// sptr es la dirección de inicio de la columna "myrank"
sptr = &sendarray[0][myrank];
MPI_Gatherv(sptr, 1, stype, rbuf, rcounts, displs, MPI_INT,
            root, comm);

Observe que se recibe una cantidad diferente de datos de cada proceso.

Ejemplo 4: Igual que el Ejemplo 3, pero hecho de una manera diferente en el lado de envío. Creamos un tipo de datos que causa el stride correcto en el lado de envío para poder leer una columna de una matriz C.

MPI_Comm comm;
int gsize, sendarray[100][150], *sptr;
int root, *rbuf, stride, myrank, disp[2], blocklen[2];
MPI_Datatype stype, type[2];
int displs, i, rcounts;
...
MPI_Comm_size(comm, &gsize);
MPI_Comm_rank(comm, &myrank );
rbuf = (int )alloc(gsize * stride * sizeof(int));
displs = (int )malloc(gsize * sizeof(int));
rcounts = (int)malloc(gsize * sizeof(int));
for (i=0; i<gsize; ++i) {
  displs[i] = i* stride;
  rcounts[i] = 100-i;
}
// Crear tipo de datos para un entero, con la extensión de toda la fila
disp[0] = 0;
disp[1] = 150 * sizeof(int);
type[0] = MPI_INT;
type[1] = MPI_UB;
blocklen[0] = 1;
blocklen[1] = 1;
MPI_Type_struct( 2, blocklen, disp, type, &stype );
MPI_Type_commit(&stype );
sptr = &sendarray[0][myrank];
MPI_Gatherv(sptr, 100-myrank, stype, rbuf, rcounts, displs, MPI_INT,
            root, comm);

Ejemplo 5: Igual que el Ejemplo 3 en el lado de envío, pero en el lado de recepción hacemos que el stride entre los bloques recibidos varíe de un bloque a otro.

MPI_Comm comm;
int gsize, sendarray[100][150], *sptr;
int root, *rbuf, *stride, myrank, bufsize;
MPI_Datatype stype;
int *displs, i, *rcounts, offset;
...
MPI_Comm_size( comm, &gsize);
MPI_Comm_rank( comm, &myrank );
de = (int )malloc(gsize * sizeof(int));
...
// stride[i] para i = 0 a gsize-1 se establece de alguna manera
// primero configurar los vectores displs y rcounts
displs = (int)malloc(gsize * sizeof(int));
rcounts = (int )malloc(gsize * sizeof(int));
offset = 0;
for (i=0; i<gsize; ++i) {
  displs[i] = offset;
  offset += stride[i];
  rcounts[i] = 100-i;
}
// el tamaño del búfer requerido para rbuf ahora se obtiene fácilmente
bufsize = displs[gsize-1]+rcounts[gsize-1];
rbuf = (int )malloc(bufsize * sizeof(int));
// Crear tipo de datos para la columna que estamos enviando
MPI_Type_vector(100-myrank, 1, 150, MPI_INT, &stype);
MPI_Type_commit( &stype );
sptr = &sendarray[0][myrank];
MPI_Gatherv(sptr, 1, stype, rbuf, rcounts, displs, MPI_INT,
            root, comm);

Ejemplo 6: El proceso i envía num enteros de la i-ésima columna de una matriz de enteros de 100 x 150, en C. El factor complicante es que la raíz no conoce los diversos valores de num, por lo que primero se debe ejecutar una recopilación separada para descubrirlos. Los datos se colocan de forma contigua en el extremo de recepción.

MPI_Comm comm;
int gsize, sendarray[100][150], *sptr;
int root, *rbuf, stride, myrank, disp[2], blocklen[2];
MPI_Datatype stype,types[2];
int *displs, i, *rcounts, num;
...
MPI_Comm_size( comm, &gsize);
MPI_Comm_rank( comm, &myrank );
// Primero, recopilar nums en la raíz
rcounts = (int )malloc(gsize * sizeof(int));
MPI_Gather( &num, 1, MPI_INT, rcounts, 1, MPI_INT, root, comm);
// la raíz ahora tiene rcounts correctos, usándolos configuramos
// displs[] para que los datos se coloquen de forma contigua (o concatenada) en el extremo de recepción
displs = (int)malloc(gsize * sizeof(int));
displs[0] = 0;
for (i=1; i<gsize; ++i) {
  displs[i] = displs[i-1]+rcounts[i-1];
}
// Y, crear búfer de recepción
rbuf = (int *)malloc(gsize * (displs[gsize-1]+rcounts[gsize-1]) * sizeof(int));
// Crear tipo de datos para un entero, con la extensión de toda la fila
disp[0] = 0;
disp[1] = 150 * sizeof(int);
type[0] = MPI_INT;
type[1] = MPI_UB;
blocklen[0] = 1;
blocklen[1] = 1;
MPI_Type_struct(2, blocklen, disp, type, &stype );
MPI_Type_commit( &stype );
sptr = &sendarray[0][myrank];
MPI_Gatherv(sptr, num, stype, rbuf, rcounts, displs, MPI_INT, root, comm);

USO DE LA OPCIÓN IN-PLACE

La opción in-place opera de la misma manera que para MPI_Gather. Cuando el comunicador es un intracommunicator, puede realizar una operación de recopilación in-place (el búfer de salida se utiliza como búfer de entrada). Utilice la variable MPI_IN_PLACE como valor del búfer de envío del proceso raíz. En este caso, sendcount y sendtype se ignoran, y se asume que la contribución del proceso raíz al vector recopilado ya está en el lugar correcto en el búfer de recepción.

Tenga en cuenta que MPI_IN_PLACE es un tipo especial de valor; tiene las mismas restricciones de uso que MPI_BOTTOM.

Dado que la opción in-place convierte el búfer de recepción en un búfer de envío y recepción, una vinculación de Fortran que incluya INTENT debe marcarlos como INOUT, no como OUT.

CUANDO EL COMUNICADOR ES UN INTERCOMUNICADOR

Cuando el comunicador es un intercomunicador, el proceso raíz del primer grupo recopila datos de todos los procesos del segundo grupo. El primer grupo define el proceso raíz. Ese proceso utiliza MPI_ROOT como valor de su argumento de raíz. Los procesos restantes utilizan MPI_PROC_NULL como valor de su argumento de raíz. Todos los procesos del segundo grupo utilizan el rango de ese proceso raíz en el primer grupo como valor de su argumento de raíz. El argumento del búfer de envío de los procesos del primer grupo debe ser coherente con el argumento del búfer de recepción del proceso raíz del segundo grupo.

ERRORES

Casi todas las rutinas de MPI devuelven un valor de error; las rutinas C como resultado de la función y las rutinas de Fortran en el último argumento.

Antes de devolver el valor de error, se llama al controlador de errores MPI actual asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo). Si no hay ningún objeto de comunicación asociado con la llamada MPI, la llamada se considera adjunta a MPI_COMM_SELF y llamará al controlador de errores MPI asociado. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se utiliza exclusivamente el modelo de sesiones), el error eleva el controlador de errores inicial. El controlador de errores inicial se puede cambiar llamando a MPI_Comm_set_errhandler en MPI_COMM_SELF cuando se utiliza el modelo World, o el argumento CLI mpi_initial_errhandler para mpiexec o la clave info para MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no se ha establecido ningún otro controlador de errores apropiado, se llama al controlador de errores MPI_ERRORS_RETURN para las funciones de E/S de MPI y al controlador de errores MPI_ERRORS_ABORT para todas las demás funciones de MPI.

Open MPI incluye tres controladores de errores predefinidos que se pueden utilizar:

  • MPI_ERRORS_ARE_FATAL hace que el programa aborte todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT Un controlador de errores que se puede invocar en un comunicador, ventana, archivo o sesión. Cuando se llama en un comunicador, actúa como si se hubiera llamado a MPI_Abort en ese comunicador. Si se llama en una ventana o archivo, actúa como si se hubiera llamado a MPI_Abort en un comunicador que contiene el grupo de procesos en la ventana o archivo correspondiente. Si se llama en una sesión, solo aborta el proceso local.
  • MPI_ERRORS_RETURN devuelve un código de error a la aplicación.

Las aplicaciones MPI también pueden implementar sus propios controladores de errores llamando a:

  • MPI_Comm_create_errhandler luego MPI_Comm_set_errhandler
  • MPI_File_create_errhandler luego MPI_File_set_errhandler
  • MPI_Session_create_errhandler luego MPI_Session_set_errhandler o en MPI_Session_init
  • MPI_Win_create_errhandler luego MPI_Win_set_errhandler

Tenga en cuenta que MPI no garantiza que un programa MPI pueda continuar después de un error.

Consulte la página man de MPI para obtener una lista completa de los códigos de error de MPI.

Consulte la sección de Manejo de Errores del estándar MPI-3.1 para obtener más información.
