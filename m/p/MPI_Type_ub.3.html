MPI_Type_ub(3) Open MPI MPI_Type_ub(3)

MPI_Type_ub — Devuelve el límite superior de un tipo de dato — esta rutina está obsoleta y se recomienda usar MPI_Type_get_extent en su lugar.

SINTAXIS

Sintaxis C

#include <mpi.h>
int MPI_Type_ub(MPI_Datatype datatype, MPI_Aint *displacement)

Sintaxis Fortran

USE MPI
! o la forma antigua: INCLUDE 'mpif.h'
MPI_TYPE_UB(DATATYPE, DISPLACEMENT, IERROR)
     INTEGER DATATYPE, DISPLACEMENT, IERROR

PARÁMETRO DE ENTRADA

•
datatype: Tipo de dato (identificador).

PARÁMETROS DE SALIDA

  • displacement: Desplazamiento del límite superior desde el origen, en bytes (entero).
  • ierror: Solo Fortran: Estado de error (entero).

DESCRIPCIÓN

Tenga en cuenta que el uso de esta rutina está *obsoleto* a partir de MPI-2. Utilice MPI_Type_get_extent en su lugar.

MPI_Type_ub devuelve el límite superior de un tipo de dato. Esto diferirá de cero si el tipo fue construido usando MPI_UB. El límite superior tendrá en cuenta las consideraciones de alineación.

Los "pseudotipos de datos", MPI_LB y MPI_UB, se pueden usar, respectivamente, para marcar el límite superior (o el límite inferior) de un tipo de dato. Estos pseudotipos de datos no ocupan espacio (extensión (MPI_LB) = extensión (MPI_UB) = 0. No afectan el tamaño ni el recuento de un tipo de dato, y no afectan el contexto de un mensaje creado con este tipo de dato. Sin embargo, sí afectan la definición de la extensión de un tipo de dato y, por lo tanto, afectan el resultado de una replicación de este tipo de dato por un constructor de tipos de datos.

En general, si

Typemap = {(type(0), disp(0)), ..., (type(n-1), disp(n-1))}

entonces el límite inferior de Typemap se define como

              (min(j) disp(j)                          si no hay entrada con
lb(Typemap) = (                                        límite inferior de tipo básico
              (min(j) {disp(j) tal que type(j) = lb} de lo contrario

De manera similar, el límite superior de Typemap se define como

              (max(j) disp(j) + sizeof(type(j) = lb}   si no hay entrada con
ub(Typemap) = (                                        límite superior de tipo básico
              (max(j) {disp(j) tal que type(j) = ub} de lo contrario

Entonces

extent(Typemap) = ub(Typemap) - lb(Typemap)

Si type(i) requiere alineación a una dirección de bytes que es múltiplo de k(i), entonces e es el menor incremento no negativo necesario para redondear extent(Typemap) al siguiente múltiplo de max(i) k(i).

ERRORES

Casi todas las rutinas de MPI devuelven un valor de error; las rutinas C como el resultado de retorno de la función y las rutinas Fortran en el último argumento.

Antes de que se devuelva el valor de error, se llama al controlador de error de MPI actual asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo). Si no hay ningún objeto de comunicación asociado con la llamada MPI, entonces la llamada se considera adjunta a MPI_COMM_SELF y llamará al controlador de error de MPI asociado. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se utiliza exclusivamente el Modelo de Sesiones) el error eleva el controlador de error inicial. El controlador de error inicial se puede cambiar llamando a MPI_Comm_set_errhandler en MPI_COMM_SELF cuando se utiliza el modelo World, o al argumento de CLI mpi_initial_errhandler de mpiexec o a la clave de información de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no se ha establecido ningún otro controlador de error apropiado, entonces se llama al controlador de error MPI_ERRORS_RETURN para las funciones de E/S de MPI y al controlador de error MPI_ERRORS_ABORT para todas las demás funciones de MPI.

Open MPI incluye tres controladores de error predefinidos que se pueden utilizar:

  • MPI_ERRORS_ARE_FATAL Causa que el programa aborte todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT Un controlador de errores que se puede invocar en un comunicador, ventana, archivo o sesión. Cuando se llama en un comunicador, actúa como si se hubiera llamado a MPI_Abort en ese comunicador. Si se llama en una ventana o archivo, actúa como si se hubiera llamado a MPI_Abort en un comunicador que contiene el grupo de procesos en la ventana o archivo correspondiente. Si se llama en una sesión, solo aborta el proceso local.
  • MPI_ERRORS_RETURN Devuelve un código de error a la aplicación.

Las aplicaciones MPI también pueden implementar sus propios controladores de error llamando a:

  • MPI_Comm_create_errhandler luego MPI_Comm_set_errhandler
  • MPI_File_create_errhandler luego MPI_File_set_errhandler
  • MPI_Session_create_errhandler luego MPI_Session_set_errhandler o en MPI_Session_init
  • MPI_Win_create_errhandler luego MPI_Win_set_errhandler

Tenga en cuenta que MPI no garantiza que un programa MPI pueda continuar después de un error.

Consulte la página del manual de MPI para obtener una lista completa de los códigos de error de MPI.

Consulte la sección de Manejo de Errores del estándar MPI-3.1 para obtener más información.
