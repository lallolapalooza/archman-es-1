MPI_Op_create(3)

Paquete: openmpi

Licencias: BSD-3-Clause AND LicenseRef-MPICH

MPI_Op_create(3) Open MPI MPI_Op_create(3)

MPI_Op_create crea un identificador de operación personalizada que puede usarse posteriormente en MPI_Reduce, MPI_Allreduce, MPI_Reduce_scatter y MPI_Scan. Se asume que la operación personalizada es asociativa. Si commute=true, entonces la operación debe ser tanto conmutativa como asociativa. Si commute=false, el orden de los operandos es fijo y se define como el orden ascendente de las rutas de proceso, comenzando con el proceso cero. El orden de evaluación puede ser cambiado, aprovechando la asociatividad de la operación. Si commute=true, el orden de evaluación puede ser cambiado, aprovechando la conmutatividad y la asociatividad.

function es la función personalizada que debe tener los siguientes cuatro argumentos: invec, inoutvec, len y datatype.

El prototipo ANSI-C de la función es el siguiente:

typedef void MPI_User_function(void *invec, void *inoutvec,
                               int *len,
                               MPI_Datatype *datatype);

La declaración de la función personalizada en Fortran aparece a continuación.

FUNCTION USER_FUNCTION( INVEC(*), INOUTVEC(*), LEN, TYPE)
<type> INVEC(LEN), INOUTVEC(LEN)
 INTEGER LEN, TYPE

El argumento datatype es un identificador del tipo de datos que se pasó en la llamada a MPI_Reduce. La función de reducción personalizada debe escribirse de manera que se cumplan las siguientes condiciones: Suponiendo que u[0], ..., u[len-1] son los len elementos en el buffer de comunicación descrito por los argumentos invec, len y datatype cuando se invoca la función; y v[0], ..., v[len-1] son los len elementos en el buffer de comunicación descrito por los argumentos inoutvec, len y datatype cuando se invoca la función; y w[0], ..., w[len-1] son los len elementos en el buffer de comunicación descrito por los argumentos inoutvec, len y datatype cuando se devuelve la función, entonces w[i] = u[i] o v[i], para i=0, ..., len-1, donde o es la operación de reducción que la función calcula.

En resumen, podemos pensar en invec y inoutvec como arrays de len elementos que la función combina. El resultado de la reducción sobrescribe los valores en inoutvec, de ahí el nombre de la operación. Cada invocación de la función produce una evaluación puntual de la operación de reducción en len elementos: es decir, la función devuelve en inoutvec[i] el valor de u[i] o inoutvec[i], para i=0, ..., count-1, donde o es la operación de combinación calculada por la función.

Internamente, comparando el valor del argumento datatype con identificadores globales conocidos, es posible sobrecargar el uso de una única función personalizada para varios tipos de datos.

Se pueden pasar tipos de datos generales a la función personalizada. Sin embargo, el uso de tipos de datos no contiguos puede causar ineficiencias.

No se puede llamar a ninguna función de comunicación MPI dentro de la función personalizada. Se puede llamar a MPI_Abort dentro de la función si hay un error.

NOTAS

Supongamos que se define una biblioteca de funciones de reducción personalizadas que se sobrecargan: El argumento datatype se utiliza para seleccionar la ruta de ejecución adecuada según los tipos de los operandos. La función personalizada no puede decodificar el argumento datatype que recibe y no puede identificar por sí sola la correspondencia entre los identificadores de datos y los datos que representan. Esta correspondencia se estableció cuando se crearon los tipos de datos. Antes de utilizar la biblioteca, se debe ejecutar un preámbulo de inicialización de la biblioteca. Este código de preámbulo definirá los tipos de datos que utilizará la biblioteca y almacenará los identificadores de estos tipos de datos en variables globales y estáticas compartidas por el código del usuario y el código de la biblioteca.

Ejemplo: Ejemplo de función de reducción personalizada:

Calcular el producto de un array de números complejos, en C.

typedef struct {
    double real, imag;
} Complex;
/* la función personalizada */
void myProd( Complex *in, Complex *inout, int *len,
             MPI_Datatype *dptr )
{
    int i;
    Complex c;
for (i=0; i< *len; ++i) {
        c.real = inout->real*in->real -
                   inout->imag*in->imag;
        c.imag = inout->real*in->imag +
                   inout->imag*in->real;
        *inout = c;
        in++; inout++;
    }
}
/* y, para llamarla... */
...
/* cada proceso tiene un array de 100 Complex */
    Complex a[100], answer[100];
    MPI_Op myOp;
    MPI_Datatype ctype;
/* explicar a MPI cómo se define el tipo Complex */
   MPI_Type_contiguous( 2, MPI_DOUBLE, &ctype );
    MPI_Type_commit( &ctype );
    /* crear la operación de producto complejo personalizada */
    MPI_Op_create( myProd, True, &myOp );
    MPI_Reduce( a, answer, 100, ctype, myOp, root, comm );
    /* en este punto, la respuesta, que consiste en 100 Complex, reside en el proceso root */

La versión Fortran de MPI_Reduce invocará una función de reducción personalizada utilizando las convenciones de llamada de Fortran y pasará un tipo de datos de Fortran; la versión C utilizará las convenciones de llamada de C y la representación del identificador de tipo de datos en C. Los usuarios que planeen mezclar lenguajes deberían definir sus funciones de reducción adecuadamente.

NOTAS DE OPERACIONES COLECTIVAS

Las funciones de reducción (MPI_Op) no devuelven un valor de error. Por lo tanto, si detectan un error, solo pueden llamar a MPI_Abort o ignorar el problema. Por lo tanto, si se cambia el manejador de errores de MPI_ERRORS_ARE_FATAL a algo más, por ejemplo, MPI_ERRORS_RETURN, no se puede indicar ningún error.

La razón de esto es el problema de rendimiento para garantizar que todas las rutinas de operación colectiva devuelvan el mismo valor de error.

ERRORES

La mayoría de las rutinas de MPI devuelven un valor de error; las rutinas C lo devuelven como el resultado de la función y las rutinas Fortran en el último argumento.

Antes de devolver el valor de error, se llama al manejador de errores asociado con el objeto de comunicación (por ejemplo, communicator, window, file). Si no hay objeto de comunicación asociado con la llamada MPI, se considera que la llamada está asociada a MPI_COMM_SELF y se llama al manejador de errores asociado. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se utiliza exclusivamente el Modelo de Sesiones), se activa el manejador de errores inicial. El manejador de errores inicial se puede cambiar llamando a MPI_Comm_set_errhandler sobre MPI_COMM_SELF cuando se utiliza el Modelo del Mundo, o a través del argumento mpi_initial_errhandler de mpiexec o la clave info de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no hay otro manejador de errores apropiado, se produce el error MPI_ERRORS_RETURN.

ERRORS

The MPI standard defines a number of error codes that can be returned by MPI functions. The behavior of MPI functions when an error occurs is controlled by an error handler that is associated with a communicator, window, file, or session. By default, the MPI_ERRORS_ARE_FATAL error handler is associated with all MPI objects. This means that if an MPI function returns an error, the program will abort all MPI processes. Open MPI provides a mechanism to change this default behavior. The MPI_Comm_set_errhandler and MPI_Win_set_errhandler functions can be used to associate a different error handler with a communicator or window, respectively. The MPI_File_set_errhandler function can be used to associate a different error handler with a file, and the MPI_Session_set_errhandler or MPI_Session_init functions can be used to associate a different error handler with a session.

Open MPI includes three predefined error handlers that can be used:

  • MPI_ERRORS_ARE_FATAL Causes the program to abort all connected MPI processes.
  • MPI_ERRORS_ABORT An error handler that can be invoked on a communicator, window, file, or session. When called on a communicator, it acts as if MPI_Abort was called on that communicator. If called on a window or file, acts as if MPI_Abort was called on a communicator containing the group of processes in the corresponding window or file. If called on a session, aborts only the local process.
  • MPI_ERRORS_RETURN Returns an error code to the application.

MPI applications can also implement their own error handlers by calling:

  • MPI_Comm_create_errhandler then MPI_Comm_set_errhandler
  • MPI_File_create_errhandler then MPI_File_set_errhandler
  • MPI_Session_create_errhandler then MPI_Session_set_errhandler or at MPI_Session_init
  • MPI_Win_create_errhandler then MPI_Win_set_errhandler

Note that MPI does not guarantee that an MPI program can continue past an error.

See the MPI man page for a full list of MPI error codes.

See the Error Handling section of the MPI-3.1 standard for more information.
