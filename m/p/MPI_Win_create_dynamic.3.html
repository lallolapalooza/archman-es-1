MPI_Win_create_dynamic(3)

Paquete: openmpi

Licencias: BSD-3-Clause AND LicenseRef-MPICH

MPI_WIN_CREATE_DYNAMIC(3) Open MPI MPI_WIN_CREATE_DYNAMIC(3)

MPI_Win_create_dynamic — Llamada MPI de un solo lado que devuelve un objeto de ventana para operaciones RMA.

SINTAXIS

Sintaxis C

#include <mpi.h>
MPI_Win_create_dynamic(MPI_Info info, MPI_Comm comm, MPI_Win *win)

Sintaxis Fortran

USE MPI
! o la forma más antigua: INCLUDE 'mpif.h'
MPI_WIN_CREATE_DYNAMIC(INFO, COMM, WIN, IERROR)
     INTEGER INFO, COMM, WIN, IERROR

Sintaxis Fortran 2008

USE mpi_f08
MPI_Win_create_dynamic(info, comm, win, ierror)
     TYPE(MPI_Info), INTENT(IN) :: info
     TYPE(MPI_Comm), INTENT(IN) :: comm
     TYPE(MPI_Win), INTENT(OUT) :: win
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARÁMETROS DE ENTRADA

  • info: Argumento de Info (manejador).
  • comm: Comunicador (manejador).

PARÁMETROS DE SALIDA

  • win: Objeto de ventana devuelto por la llamada (manejador).
  • ierror: Solo Fortran: Estado de error (entero).

DESCRIPCIÓN

MPI_Win_create_dynamic es una llamada colectiva de comunicación unidireccional de MPI ejecutada por todos los procesos del grupo de comm. Devuelve un objeto de ventana sin memoria adjunta que puede ser utilizado por estos procesos para realizar operaciones RMA.

Una ventana creada con MPI_Win_create_dynamic requiere el argumento target_disp para todas las funciones de comunicación RMA para que sea la dirección real en el destino.

Las siguientes claves de información son compatibles:

no_locks
Si se establece en true, la implementación puede asumir que la ventana local nunca se bloquea (mediante una llamada a MPI_Win_lock o MPI_Win_lock_all). Establecer este valor si solo la sincronización activa puede permitir a la implementación habilitar ciertas optimizaciones.
accumulate_ordering
Por defecto, las operaciones de acumulación de un iniciador a un destino en la misma ubicación de memoria de ventana están estrictamente ordenadas. Si la clave de información accumulate_ordering se establece en none, no se garantiza ningún orden de las operaciones de acumulación. La clave también puede ser una lista separada por comas de ordenamientos requeridos que consisten en rar, war, raw y waw para lectura-después-lectura, escritura-después-lectura, lectura-después-escritura y escritura-después-escritura, respectivamente. Restricciones de ordenamiento más laxas probablemente resultarán en un mejor rendimiento.
accumulate_ops
Si se establece en same_op, la implementación asumirá que todas las llamadas concurrentes de acumulación a la misma dirección de destino usarán la misma operación. Si se establece en same_op_no_op, la implementación asumirá que todas las llamadas concurrentes de acumulación a la misma dirección de destino usarán la misma operación o MPI_NO_OP. El valor predeterminado es same_op_no_op.

NOTAS

Dado que adjuntar memoria dinámicamente a una ventana es una operación local, hay que comunicar la dirección real en el destino usando MPI_Get_address y alguna comunicación.

La memoria dinámica no tiene ninguna disp_unit asociada y requiere cálculos de desplazamiento correctos con el manejo adecuado de tipos.

ERRORES

Casi todas las rutinas MPI devuelven un valor de error; las rutinas C como resultado de retorno de la función y las rutinas Fortran en el último argumento.

Antes de que se devuelva el valor de error, se llama al controlador de errores MPI actual asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo). Si no hay ningún objeto de comunicación asociado con la llamada MPI, entonces la llamada se considera adjunta a MPI_COMM_SELF y llamará al controlador de errores MPI asociado. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se usa exclusivamente el Modelo de Sesiones) el error eleva el controlador de errores inicial. El controlador de errores inicial puede ser cambiado llamando a MPI_Comm_set_errhandler en MPI_COMM_SELF cuando se usa el modelo World, o el argumento CLI mpi_initial_errhandler a mpiexec o la clave de información a MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no se ha establecido ningún otro controlador de errores apropiado, entonces se llama al controlador de errores MPI_ERRORS_RETURN para las funciones de E/S de MPI y al controlador de errores MPI_ERRORS_ABORT para todas las demás funciones de MPI.

Open MPI incluye tres controladores de errores predefinidos que se pueden utilizar:

  • MPI_ERRORS_ARE_FATAL Provoca que el programa aborte todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT Un controlador de errores que puede ser invocado en un comunicador, ventana, archivo o sesión. Cuando se llama en un comunicador, actúa como si MPI_Abort se hubiera llamado en ese comunicador. Si se llama en una ventana o archivo, actúa como si MPI_Abort se hubiera llamado en un comunicador que contiene el grupo de procesos en la ventana o archivo correspondiente. Si se llama en una sesión, aborta solo el proceso local.
  • MPI_ERRORS_RETURN Devuelve un código de error a la aplicación.

Las aplicaciones MPI también pueden implementar sus propios controladores de errores llamando a:

  • MPI_Comm_create_errhandler luego MPI_Comm_set_errhandler
  • MPI_File_create_errhandler luego MPI_File_set_errhandler
  • MPI_Session_create_errhandler luego MPI_Session_set_errhandler o en MPI_Session_init
  • MPI_Win_create_errhandler luego MPI_Win_set_errhandler

Tenga en cuenta que MPI no garantiza que un programa MPI pueda continuar después de un error.

Consulte la página del manual de MPI para obtener una lista completa de los códigos de error de MPI.

Consulte la sección de Manejo de Errores del estándar MPI-3.1 para obtener más información.
