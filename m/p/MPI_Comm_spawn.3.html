MPI_Comm_spawn(3)

Paquete: openmpi

Licencias: BSD-3-Clause AND LicenseRef-MPICH

MPI_COMM_SPAWN(3) Open MPI MPI_COMM_SPAWN(3)

MPI_Comm_spawn — Crea un número de binarios idénticos.

SINTAXIS

Sintaxis C

#include <mpi.h>
int MPI_Comm_spawn(const char *command, char *argv[], int maxprocs,
     MPI_Info info, int root, MPI_Comm comm,
     MPI_Comm *intercomm, int array_of_errcodes[])

Sintaxis Fortran

USE MPI
! o la forma antigua: INCLUDE 'mpif.h'
MPI_COMM_SPAWN(COMMAND, ARGV, MAXPROCS, INFO, ROOT, COMM,
     INTERCOMM, ARRAY_OF_ERRCODES, IERROR)
     CHARACTER*(*) COMMAND, ARGV(*)
     INTEGER INFO, MAXPROCS, ROOT, COMM, INTERCOMM,
     ARRAY_OF_ERRCODES(*), IERROR

Sintaxis Fortran 2008

USE mpi_f08
MPI_Comm_spawn(command, argv, maxprocs, info, root, comm, intercomm,
             array_of_errcodes, ierror)
     CHARACTER(LEN=*), INTENT(IN) :: command, argv(*)
     INTEGER, INTENT(IN) :: maxprocs, root
     TYPE(MPI_Info), INTENT(IN) :: info
     TYPE(MPI_Comm), INTENT(IN) :: comm
     TYPE(MPI_Comm), INTENT(OUT) :: intercomm
     INTEGER :: array_of_errcodes(*)
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARÁMETROS DE ENTRADA

  • command: Nombre del programa a crear (cadena, significativo solo en root).
  • argv: Argumentos para command (matriz de cadenas, significativo solo en root).
  • maxprocs: Número máximo de procesos a iniciar (entero, significativo solo en root).
  • info: Un conjunto de pares clave-valor que indican al sistema de ejecución dónde y cómo iniciar los procesos (handle, significativo solo en root).
  • root: Rango del proceso en el que se examinan los argumentos anteriores (entero).
  • comm: Intracomunicador que contiene el grupo de procesos que crean (handle).

PARÁMETRO DE SALIDA

  • intercomm: Intercomunicador entre el grupo original y el grupo recién creado (handle).
  • array_of_errcodes: Un código por proceso (matriz de enteros).
  • ierror: Solo Fortran: Estado de error (entero).

DESCRIPCIÓN

MPI_Comm_spawn intenta iniciar maxprocs copias idénticas del programa MPI especificado por command, estableciendo comunicación con ellas y devolviendo un intercomunicador. Los procesos creados se denominan hijos. Los hijos tienen su propio MPI_COMM_WORLD, que es independiente del de los padres. MPI_Comm_spawn es colectivo sobre comm, y tampoco puede devolver hasta que MPI_Init se haya llamado en los hijos. De manera similar, MPI_Init en los hijos puede no devolver hasta que todos los padres hayan llamado a MPI_Comm_spawn. En este sentido, MPI_Comm_spawn en los padres y MPI_Init en los hijos forman una operación colectiva sobre la unión de procesos padres e hijos. El intercomunicador devuelto por MPI_Comm_spawn contiene los procesos padres en el grupo local y los procesos hijos en el grupo remoto. El orden de los procesos en los grupos local y remoto es el mismo que el orden del grupo de comm en los padres y de MPI_COMM_WORLD de los hijos, respectivamente. Este intercomunicador se puede obtener en los hijos a través de la función MPI_Comm_get_parent.

El estándar MPI permite a una implementación usar el atributo MPI_UNIVERSE_SIZE de MPI_COMM_WORLD para especificar el número de procesos que estarán activos en un programa. Aunque esta implementación del estándar MPI define MPI_UNIVERSE_SIZE, no permite al usuario establecer su valor. Si intenta establecer el valor de MPI_UNIVERSE_SIZE, recibirá un mensaje de error.

El argumento command

El argumento command es una cadena que contiene el nombre de un programa que se va a crear. La cadena termina en nulo en C. En Fortran, se eliminan los espacios iniciales y finales. MPI busca el archivo primero en el directorio de trabajo del proceso que crea.

El argumento argv

argv es una matriz de cadenas que contiene los argumentos que se pasan al programa. El primer elemento de argv es el primer argumento que se pasa a command, no, como es convencional en algunos contextos, el propio comando. La lista de argumentos termina en NULL en C y en una cadena vacía en Fortran (tenga en cuenta que es responsabilidad de la aplicación MPI asegurarse de que la última entrada de la matriz argv sea una cadena vacía; el compilador no la insertará automáticamente). En Fortran, los espacios iniciales y finales siempre se eliminan, por lo que una cadena que consista en todos espacios se considera una cadena vacía. La constante MPI_ARGV_NULL puede ser usada en C y Fortran para indicar una lista de argumentos vacía. En C, esta constante es la misma que NULL.

En C, el argumento argv de MPI_Comm_spawn difiere del argumento argv de main en dos aspectos. Primero, está desplazado en un elemento. Específicamente, argv[0] de main contiene el nombre del programa (dado por command). argv[1] de main corresponde a argv[0] en MPI_Comm_spawn, argv[2] de main a argv[1] de MPI_Comm_spawn, y así sucesivamente. Segundo, argv de MPI_Comm_spawn debe estar terminado en nulo, para que se pueda determinar su longitud. Pasar un argv de MPI_ARGV_NULL a MPI_Comm_spawn resulta en que main recibe argc de 1 y un argv cuyo elemento 0 es el nombre del programa.

El argumento maxprocs

Open MPI intenta crear maxprocs procesos. Si no puede crear maxprocs procesos, genera un error de clase MPI_ERR_SPAWN. Si MPI puede crear el número especificado de procesos, MPI_Comm_spawn se ejecuta correctamente y el número de procesos creados, m, se da por el tamaño del grupo remoto de intercomm.

Una llamada de creación con el comportamiento por defecto se llama dura. Una llamada de creación para la que se pueden devolver menos de maxprocs procesos se llama suave.

El argumento info

El argumento info es un handle opaco de tipo MPI_Info en C e INTEGER en Fortran. Es un contenedor para un número de pares (clave,valor) especificados por el usuario. clave y valor son cadenas (char * terminado en nulo en C, character*(*) en Fortran). Las rutinas para crear y manipular el argumento info se describen en la sección 4.10 del estándar MPI-2.

Para las llamadas SPAWN, info proporciona instrucciones adicionales, dependientes de la implementación, a MPI y al sistema de ejecución sobre cómo iniciar procesos. Una aplicación puede pasar MPI_INFO_NULL en C o Fortran. Los programas portables que no requieren un control detallado sobre la ubicación de los procesos deben usar MPI_INFO_NULL.

El Argumento root

Todos los argumentos antes del argumento root se examinan solo en el proceso cuyo rango en comm es igual a root. El valor de estos argumentos en otros procesos se ignora.

El Argumento array_of_errcodes

El array_of_errcodes es una matriz de longitud maxprocs en la que MPI informa el estado de los procesos que se solicitó a MPI iniciar. Si se generaron los maxprocs procesos, array_of_errcodes se llena con el valor MPI_SUCCESS. Si alguno de los procesos no se genera, array_of_errcodes se llena con el valor MPI_ERR_SPAWN. En C o Fortran, una aplicación puede pasar MPI_ERRCODES_IGNORE si no está interesada en los códigos de error.

NOTAS

La finalización de MPI_Comm_spawn en el proceso padre no significa necesariamente que MPI_Init se haya llamado en los hijos (aunque el intercommunicator devuelto se puede usar de inmediato).

ERRORES

Casi todas las rutinas MPI devuelven un valor de error; las rutinas en C como resultado de retorno de la función y las rutinas de Fortran en el último argumento.

Antes de que se devuelva el valor de error, se llama al controlador de errores MPI actual asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo). Si no hay ningún objeto de comunicación asociado con la llamada MPI, la llamada se considera adjunta a MPI_COMM_SELF y llamará al controlador de errores MPI asociado. Cuando MPI_COMM_SELF no se inicializa (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se usa exclusivamente el Modelo de Sesiones), el error activa el controlador de errores inicial. El controlador de errores inicial se puede cambiar llamando a MPI_Comm_set_errhandler en MPI_COMM_SELF cuando se usa el modelo World, o el argumento de línea de comandos mpi_initial_errhandler a mpiexec o la clave de información a MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no se ha configurado ningún otro controlador de errores apropiado, se llama al controlador de errores MPI_ERRORS_RETURN para las funciones de E/S MPI y al controlador de errores MPI_ERRORS_ABORT para todas las demás funciones MPI.

Open MPI incluye tres controladores de errores predefinidos que se pueden usar:

  • MPI_ERRORS_ARE_FATAL Provoca que el programa aborte todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT Un controlador de errores que se puede invocar en un comunicador, ventana, archivo o sesión. Cuando se llama en un comunicador, actúa como si se hubiera llamado a MPI_Abort en ese comunicador. Si se llama en una ventana o archivo, actúa como si se hubiera llamado a MPI_Abort en un comunicador que contiene el grupo de procesos en la ventana o archivo correspondiente. Si se llama en una sesión, solo aborta el proceso local.
  • MPI_ERRORS_RETURN Devuelve un código de error a la aplicación.

Las aplicaciones MPI también pueden implementar sus propios controladores de errores llamando a:

  • MPI_Comm_create_errhandler luego MPI_Comm_set_errhandler
  • MPI_File_create_errhandler luego MPI_File_set_errhandler
  • MPI_Session_create_errhandler luego MPI_Session_set_errhandler o en MPI_Session_init
  • MPI_Win_create_errhandler luego MPI_Win_set_errhandler

Tenga en cuenta que MPI no garantiza que un programa MPI pueda continuar después de un error.

Consulte la página del manual de MPI para obtener una lista completa de los códigos de error de MPI.

Consulte la sección Manejo de Errores del estándar MPI-3.1 para obtener más información.
