MPI_UNPACK(3) Open MPI MPI_UNPACK(3)

MPI_Unpack — Desempaqueta un tipo de dato en memoria contigua.

SINTAXIS

Sintaxis C

#include <mpi.h>
int MPI_Unpack(const void *inbuf, int insize, int *position,
     void *outbuf, int outcount, MPI_Datatype datatype,
     MPI_Comm comm)

Sintaxis Fortran

USE MPI
! o la forma antigua: INCLUDE 'mpif.h'
MPI_UNPACK(INBUF, INSIZE, POSITION, OUTBUF, OUTCOUNT,
     DATATYPE, COMM, IERROR)
     <type>  INBUF(*), OUTBUF(*)
     INTEGER INSIZE, POSITION, OUTCOUNT, DATATYPE,
             COMM, IERROR

Sintaxis Fortran 2008

USE mpi_f08
MPI_Unpack(inbuf, insize, position, outbuf, outcount, datatype, comm,
             ierror)
     TYPE(*), DIMENSION(..), INTENT(IN) :: inbuf
     TYPE(*), DIMENSION(..) :: outbuf
     INTEGER, INTENT(IN) :: insize, outcount
     INTEGER, INTENT(INOUT) :: position
     TYPE(MPI_Datatype), INTENT(IN) :: datatype
     TYPE(MPI_Comm), INTENT(IN) :: comm
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARÁMETROS DE ENTRADA

  • inbuf: Inicio del búfer de entrada (elección).
  • insize: Tamaño del búfer de entrada, en bytes (entero).
  • outcount: Número de elementos a desempaquetar (entero).
  • datatype: Tipo de dato de cada elemento de salida (manejador).
  • comm: Comunicador para el mensaje empaquetado (manejador).

PARÁMETRO ENTRADA/SALIDA

•
position: Posición actual en bytes (entero).

PARÁMETROS DE SALIDA

  • outbuf: Inicio del búfer de salida (elección).
  • ierror: Solo Fortran: Estado de error (entero).

DESCRIPCIÓN

Desempaqueta un mensaje en el búfer de recepción especificado por outbuf, outcount, datatype a partir del espacio de búfer especificado por inbuf e insize. El búfer de salida puede ser cualquier búfer de comunicación permitido en MPI_Recv. El búfer de entrada es un área de almacenamiento contigua que contiene insize bytes, comenzando en la dirección inbuf. El valor de entrada de position es la primera ubicación en el búfer de entrada ocupada por el mensaje empaquetado. position se incrementa por el tamaño del mensaje empaquetado, de modo que el valor de salida de position sea la primera ubicación en el búfer de entrada después de las ubicaciones ocupadas por el mensaje que se desempaquetó. comm es el comunicador utilizado para recibir el mensaje empaquetado.

NOTAS

Observe la diferencia entre MPI_Recv y MPI_Unpack: En MPI_Recv, el argumento count especifica el número máximo de elementos que se pueden recibir. El número real de elementos recibidos está determinado por la longitud del mensaje entrante. En MPI_Unpack, el argumento count especifica el número real de elementos que se van a desempaquetar; el “tamaño” del mensaje correspondiente es el incremento en la posición. La razón de este cambio es que el “tamaño del mensaje entrante” no está predeterminado ya que el usuario decide cuánto desempaquetar; ni es fácil determinar el “tamaño del mensaje” a partir del número de elementos a desempaquetar.

Para comprender el comportamiento de empaquetar y desempaquetar, es conveniente pensar en la parte de datos de un mensaje como la secuencia obtenida al concatenar los valores sucesivos enviados en ese mensaje. La operación de empaquetado almacena esta secuencia en el espacio del búfer, como si enviara el mensaje a ese búfer. La operación de desempaquetado recupera esta secuencia del espacio del búfer, como si recibiera un mensaje de ese búfer. (Es útil pensar en archivos internos de Fortran o sscanf en C para una función similar).

Varios mensajes pueden empaquetarse sucesivamente en una unidad de empaquetado. Esto se logra mediante varias llamadas sucesivas relacionadas a MPI_Pack, donde la primera llamada proporciona position = 0, y cada llamada sucesiva introduce el valor de position que fue generado por la llamada anterior, y los mismos valores para outbuf, outcount y comm. Esta unidad de empaquetado ahora contiene la información equivalente que se habría almacenado en un mensaje por una llamada de envío con un búfer de envío que es la “concatenación” de los búferes de envío individuales.

Una unidad de empaquetado puede enviarse usando el tipo MPI_Packed. Cualquier función de comunicación punto a punto o colectiva puede usarse para mover la secuencia de bytes que forma la unidad de empaquetado de un proceso a otro. Esta unidad de empaquetado ahora puede ser recibida usando cualquier operación de recepción, con cualquier tipo de dato: Las reglas de coincidencia de tipos se relajan para los mensajes enviados con el tipo MPI_Packed.

Un mensaje enviado con cualquier tipo (incluido MPI_Packed) puede ser recibido usando el tipo MPI_Packed. Dicho mensaje puede ser desempaquetado por llamadas a MPI_Unpack.

Una unidad de empaquetado (o un mensaje creado por un envío regular y “tipado”) puede desempaquetarse en varios mensajes sucesivos. Esto se logra mediante varias llamadas sucesivas relacionadas a MPI_Unpack, donde la primera llamada proporciona position = 0, y cada llamada sucesiva introduce el valor de position que fue generado por la llamada anterior, y los mismos valores para inbuf, insize y comm.

La concatenación de dos unidades de empaquetado no es necesariamente una unidad de empaquetado; tampoco lo es una subcadena de una unidad de empaquetado. Por lo tanto, uno no puede concatenar dos unidades de empaquetado y luego desempaquetar el resultado como una sola unidad de empaquetado; ni puede desempaquetar una subcadena de una unidad de empaquetado como una unidad de empaquetado separada. Cada unidad de empaquetado que fue creada por una secuencia relacionada de llamadas de empaquetado o por un envío regular debe ser desempaquetada como una unidad, mediante una secuencia de llamadas de desempaquetado relacionadas.

ERRORES

Casi todas las rutinas de MPI devuelven un valor de error; las rutinas C como resultado de la función y las rutinas Fortran en el último argumento.

Antes de que se devuelva el valor de error, se llama al manejador de errores de MPI actual asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo). Si no hay ningún objeto de comunicación asociado con la llamada MPI, la llamada se considera adjunta a MPI_COMM_SELF y llamará al manejador de errores de MPI asociado. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se usa el Modelo de Sesiones exclusivamente) el error genera el manejador de errores inicial. El manejador de errores inicial puede cambiarse llamando a MPI_Comm_set_errhandler en MPI_COMM_SELF cuando se usa el modelo World, o el argumento de línea de comandos mpiexec mpi_initial_errhandler o la clave de información para MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no se ha establecido ningún otro manejador de errores apropiado, se llama al manejador de errores MPI_ERRORS_RETURN para las funciones de E/S de MPI y al manejador de errores MPI_ERRORS_ABORT para todas las demás funciones de MPI.

Open MPI incluye tres manejadores de errores predefinidos que pueden utilizarse:

  • MPI_ERRORS_ARE_FATAL Provoca que el programa aborte todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT Un manejador de errores que puede invocarse en un comunicador, ventana, archivo o sesión. Cuando se llama en un comunicador, actúa como si se hubiera llamado MPI_Abort en ese comunicador. Si se llama en una ventana o archivo, actúa como si se hubiera llamado MPI_Abort en un comunicador que contiene el grupo de procesos en la ventana o archivo correspondiente. Si se llama en una sesión, solo aborta el proceso local.
  • MPI_ERRORS_RETURN Devuelve un código de error a la aplicación.

Las aplicaciones MPI también pueden implementar sus propios manejadores de errores llamando a:

  • MPI_Comm_create_errhandler luego MPI_Comm_set_errhandler
  • MPI_File_create_errhandler luego MPI_File_set_errhandler
  • MPI_Session_create_errhandler luego MPI_Session_set_errhandler o en MPI_Session_init
  • MPI_Win_create_errhandler luego MPI_Win_set_errhandler

Tenga en cuenta que MPI no garantiza que un programa MPI pueda continuar después de un err
