MPI_Reduce_local — Realiza una reducción local

SINTAXIS

Sintaxis C

#include <mpi.h>
int MPI_Reduce_local(const void *inbuf, void *inoutbuf, int count,
     MPI_Datatype datatype, MPI_Op op)

Sintaxis Fortran

USE MPI
! o la forma antigua: INCLUDE 'mpif.h'
MPI_REDUCE_LOCAL(INBUF, INOUTBUF, COUNT, DATATYPE, OP, IERROR)
     <type>  INBUF(*), INOUTBUF(*)
     INTEGER COUNT, DATATYPE, OP, IERROR

Sintaxis Fortran 2008

USE mpi_f08
MPI_Reduce_local(inbuf, inoutbuf, count, datatype, op, ierror)
     TYPE(*), DIMENSION(..), INTENT(IN) :: inbuf
     TYPE(*), DIMENSION(..) :: inoutbuf
     INTEGER, INTENT(IN) :: count
     TYPE(MPI_Datatype), INTENT(IN) :: datatype
     TYPE(MPI_Op), INTENT(IN) :: op
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARÁMETROS DE ENTRADA

  • inbuf: Dirección del buffer de entrada (variable).
  • count: Número de elementos en el buffer de entrada (entero).
  • datatype: Tipo de dato de los elementos del buffer de entrada (handle).
  • op: Operación de reducción (handle).

PARÁMETROS DE SALIDA

  • inoutbuf: Dirección del buffer de entrada/salida (variable).
  • ierror: Solo Fortran: Estado de error (entero).

DESCRIPCIÓN

Las funciones de reducción global (MPI_Reduce_local, MPI_Op_create, MPI_Op_free, MPI_Allreduce, MPI_Reduce_local_scatter, MPI_Scan) realizan una operación de reducción global (como suma, máximo, AND lógico, etc.) entre todos los miembros de un grupo. La operación de reducción puede ser una de una lista predefinida de operaciones o una operación definida por el usuario. Las funciones de reducción global vienen en varios formatos: una reducción que devuelve el resultado de la reducción en un nodo, una all-reduce que devuelve este resultado en todos los nodos y una operación scan (prefijo paralelo). Además, una operación reduce-scatter combina la funcionalidad de una operación reduce y scatter.

MPI_Reduce_local combina los elementos proporcionados en los buffers de entrada y entrada/salida del proceso local, utilizando la operación op, y devuelve el valor combinado en el buffer de entrada/salida. El buffer de entrada se define mediante los argumentos inbuf, count y datatype; el buffer de salida se define mediante los argumentos inoutbuf, count y datatype; ambos tienen el mismo número de elementos, con el mismo tipo. La rutina es una llamada local. El proceso puede proporcionar un elemento, o una secuencia de elementos, en cuyo caso la operación de combinación se ejecuta elemento a elemento en cada entrada de la secuencia. Por ejemplo, si la operación es MPI_MAX y el buffer de entrada contiene dos elementos que son números de punto flotante (count = 2 y datatype = MPI_FLOAT), entonces inoutbuf(1) = máximo global (inbuf(1)) e inoutbuf(2) = máximo global(inbuf(2)).

USO DE LA OPCIÓN IN-PLACE

El uso de MPI_IN_PLACE está prohibido con MPI_Reduce_local.

OPERACIONES DE REDUCCIÓN PREDETERMINADAS

La lista de operaciones predeterminadas proporcionadas por MPI se enumera a continuación (Operaciones de Reducción Predeterminadas). Esa sección también enumera los tipos de datos a los que se pueden aplicar cada operación. Además, los usuarios pueden definir sus propias operaciones que pueden ser sobrecargadas para operar en varios tipos de datos, ya sean básicos o derivados. Esto se explica más detalladamente en la descripción de las operaciones definidas por el usuario (ver las páginas man de MPI_Op_create y MPI_Op_free).

Se asume que la operación op siempre es asociativa. Se asume que todas las operaciones predeterminadas también son conmutativas. Los usuarios pueden definir operaciones que se asumen asociativas, pero no conmutativas. El orden de evaluación "canónico" de una reducción está determinado por los rangos de los procesos en el grupo. Sin embargo, la implementación puede aprovechar la asociatividad, o la asociatividad y la conmutatividad, para cambiar el orden de evaluación. Esto puede cambiar el resultado de la reducción para operaciones que no son estrictamente asociativas y conmutativas, como la suma de punto flotante.

Los operadores predeterminados solo funcionan con los tipos MPI enumerados a continuación (Operaciones de Reducción Predeterminadas, y la sección MINLOC y MAXLOC, más abajo). Los operadores definidos por el usuario pueden operar en tipos de datos generales y derivados. En este caso, cada argumento al que se aplica la operación de reducción es un elemento descrito por dicho tipo de datos, que puede contener varios valores básicos. Esto se explica más detalladamente en la Sección 4.9.4 del Estándar MPI, "Operaciones Definidas por el Usuario".

Las siguientes operaciones predeterminadas se proporcionan para MPI_Reduce_local y las funciones relacionadas MPI_Allreduce, MPI_Reduce_scatter y MPI_Scan. Estas operaciones se invocan colocando lo siguiente en op:

La operación de reducción se define para actuar sobre argumentos que consisten en un par: valor e índice. Para Fortran y C, se proporcionan tipos para describir este par. La naturaleza potencialmente mixta de estos argumentos es un problema en Fortran. El problema se evita, para Fortran, al tener el tipo proporcionado por MPI consistente en un par de tipos iguales que el valor, y forzando el índice a este tipo también. En C, el tipo proporcionado por MPI tiene tipos distintos y el índice es un int.

Para usar MPI_MAXLOC y MPI_MINLOC en una operación de reducción, se debe proporcionar un argumento de tipo de datos que represente un par (valor e índice). MPI proporciona nueve tipos de datos predefinidos de este tipo. Las operaciones MPI_MAXLOC y MPI_MINLOC se pueden usar con cada uno de los siguientes tipos de datos:

MPI_2INTEGER             par de INTEGERs

MPI_FLOAT_INT            float y int
MPI_DOUBLE_INT           double y int
MPI_LONG_INT             long y int

Todos los objetos MPI (por ejemplo, MPI_Datatype, MPI_Comm) son de tipo INTEGER en Fortran.

Los operadores de reducción (MPI_Op) no devuelven un valor de error. Como resultado, si las funciones detectan un error, todo lo que pueden hacer es llamar a MPI_Abort o pasar silenciosamente el problema. Por lo tanto, si cambia el manejador de errores de MPI_ERRORS_ARE_FATAL a algo más, por ejemplo, MPI_ERRORS_RETURN, no se indicará ningún error.

La razón para esto es el problema de rendimiento al garantizar que todas las rutinas de operación colectiva devuelvan el mismo valor de error.

La mayoría de las rutinas MPI devuelven un valor de error; las rutinas C devuelven el resultado de la función y las rutinas Fortran en el último argumento.

Antes de que se devuelva el valor de error, se llama al manejador de errores asociado con el objeto de comunicación (por ejemplo, communicator, window, file) relacionado con la llamada MPI. Si no hay ningún objeto de comunicación asociado con la llamada MPI, se considera que la llamada está asociada a MPI_COMM_SELF y se llama al manejador de errores asociado con este objeto. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize o cuando se usa el modelo de sesiones exclusivamente), se activa el manejador de errores inicial. El manejador de errores inicial se puede cambiar llamando a MPI_Comm_set_errhandler sobre MPI_COMM_SELF cuando se usa el modelo del mundo, o el argumento mpi_initial_errhandler de mpiexec o la clave info de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no hay ningún otro manejador de errores adecuado, se llama al manejador de errores MPI_ERRORS_RETURN para funciones de I/O de MPI y al manejador de errores MPI_ERRORS_ABORT para todas las demás funciones de MPI.

Open MPI incluye tres manejadores de errores predefinidos que se pueden usar:

  • MPI_ERRORS_ARE_FATAL Hace que el programa aborte todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT Un manejador de errores que se puede invocar en un comunicador, ventana, archivo o sesión. Cuando se llama en un comunicador, actúa como si se hubiera llamado a MPI_Abort en ese comunicador. Si se llama en una ventana o archivo, actúa como si se hubiera llamado a MPI_Abort en un comunicador que contiene el grupo de procesos en la ventana o archivo correspondiente. Si se llama en una sesión, aborta solo el proceso local.
  • MPI_ERRORS_RETURN Devuelve un código de error a la aplicación.

Las aplicaciones MPI también pueden implementar sus propios manejadores de errores llamando:

  • MPI_Comm_create_errhandler luego MPI_Comm_set_errhandler
  • MPI_File_create_errhandler luego MPI_File_set_errhandler
  • MPI_Session_create_errhandler luego MPI_Session_set_errhandler o en MPI_Session_init
  • MPI_Win_create_errhandler luego MPI_Win_set_errhandler

Nota: MPI no garantiza que un programa MPI pueda continuar después de un error.

Consulte la página del manual de MPI para obtener una lista completa de los códigos de error de MPI.

Consulte la sección sobre manejo de errores de la norma MPI-3.1 para obtener más información.
