Licencias: BSD-3-Clause AND LicenseRef-MPICH

MPI_NEIGHBOR_ALLGATHERV(3) Open MPI MPI_NEIGHBOR_ALLGATHERV(3)

MPI_Neighbor_allgatherv, MPI_Ineighbor_allgatherv, MPI_Neighbor_allgatherv_init — Recopila y distribuye datos desde y hacia todos los vecinos. Cada proceso puede contribuir con una cantidad diferente de datos.

PARÁMETROS DE ENTRADA

  • sendbuf: Dirección de inicio del búfer de envío (elección).
  • sendcount: Número de elementos en el búfer de envío (entero).
  • sendtype: Tipo de datos de los elementos del búfer de envío (manejador).
  • recvcount: Matriz de enteros (de longitud igual al tamaño del grupo) que contiene el número de elementos que se reciben de cada vecino.
  • displs: Matriz de enteros (de longitud igual al tamaño del grupo). La entrada i especifica el desplazamiento (relativo a recvbuf) en el que se colocan los datos entrantes del vecino i.
  • recvtype: Tipo de datos de los elementos del búfer de recepción (manejador).
  • comm: Comunicador (manejador).
  • info Info (manejador, solo persistente).:

PARÁMETROS DE SALIDA

  • recvbuf: Dirección del búfer de recepción (elección).
  • request: Solicitud (manejador, solo no bloqueante).
  • ierror: Solo Fortran: Estado de error (entero).

DESCRIPCIÓN

MPI_Neighbor_allgatherv es similar a MPI_Neighbor_allgather en que todos los procesos recopilan datos de todos los vecinos, excepto que cada proceso puede enviar una cantidad diferente de datos. El bloque de datos enviado desde el vecino j es recibido por cada vecino y colocado en el bloque j del búfer. Los vecinos y la disposición del búfer se determinan por la topología de comm. recvbuf.

La firma de tipo asociada con sendcount, sendtype, en el proceso j debe ser igual a la firma de tipo asociada con la entrada correspondiente en recvcounts en los procesos vecinos.

ORDEN DE VECINOS

Para una topología de grafo distribuido, creada con MPI_Dist_graph_create, la secuencia de vecinos en los búferes de envío y recepción en cada proceso se define como la secuencia devuelta por MPI_Dist_graph_neighbors para destinos y orígenes, respectivamente. Para una topología de grafo general, creada con MPI_Graph_create, el orden de los vecinos en los búferes de envío y recepción se define como la secuencia de vecinos devuelta por MPI_Graph_neighbors. Tenga en cuenta que las topologías de grafo generales generalmente deben ser reemplazadas por las topologías de grafo distribuidas.

Para una topología cartesiana, creada con MPI_Cart_create, la secuencia de vecinos en los búferes de envío y recepción en cada proceso se define por el orden de las dimensiones, primero el vecino en la dirección negativa y luego en la dirección positiva con un desplazamiento de 1. Los números de orígenes y destinos en las rutinas de comunicación son 2*ndims, donde ndims se define en MPI_Cart_create. Si un vecino no existe, es decir, en el borde de una topología cartesiana en el caso de una dimensión de cuadrícula virtual no periódica (es decir, periods[…]==false), entonces este vecino se define como MPI_PROC_NULL.

Si un vecino en cualquiera de las funciones es MPI_PROC_NULL, entonces la comunicación colectiva de vecindad se comporta como una comunicación punto a punto con MPI_PROC_NULL en esa dirección. Es decir, el búfer sigue siendo parte de la secuencia de vecinos, pero ni se comunica ni se actualiza.

NOTAS

La opción MPI_IN_PLACE para sendbuf no tiene sentido para esta operación.

ERRORES

Casi todas las rutinas MPI devuelven un valor de error; las rutinas C como resultado de retorno de la función y las rutinas Fortran en el último argumento.

Antes de que se devuelva el valor de error, se llama al controlador de error MPI actual asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo). Si no hay ningún objeto de comunicación asociado con la llamada MPI, entonces la llamada se considera adjunta a MPI_COMM_SELF y llamará al controlador de error MPI asociado. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se usa exclusivamente el Modelo de Sesiones) el error eleva el controlador de error inicial. El controlador de error inicial se puede cambiar llamando a MPI_Comm_set_errhandler en MPI_COMM_SELF cuando se usa el modelo World, o el argumento de línea de comandos mpi_initial_errhandler para mpiexec o clave de información para MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no se ha configurado ningún otro controlador de error apropiado, entonces se llama al controlador de error MPI_ERRORS_RETURN para las funciones de E/S de MPI y al controlador de error MPI_ERRORS_ABORT para todas las demás funciones MPI.

Open MPI incluye tres controladores de error predefinidos que se pueden utilizar:

  • MPI_ERRORS_ARE_FATAL Provoca que el programa aborte todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT Un controlador de error que puede invocarse en un comunicador, ventana, fi
