Paquete: openmpi

MPI_TESTSOME(3) Open MPI MPI_TESTSOME(3)

MPI_Testsome — Comprueba la finalización de una o más comunicaciones iniciadas previamente en una lista.

SINTAXIS

Sintaxis C

#include <mpi.h>
int MPI_Testsome(int incount, MPI_Request array_of_requests[],
     int *outcount, int array_of_indices[],
     MPI_Status array_of_statuses[])

Sintaxis Fortran

USE MPI
! o la forma más antigua: INCLUDE 'mpif.h'
MPI_TESTSOME(INCOUNT, ARRAY_OF_REQUESTS, OUTCOUNT,
             ARRAY_OF_INDICES, ARRAY_OF_STATUSES, IERROR)
     INTEGER INCOUNT, ARRAY_OF_REQUESTS(*)
     INTEGER OUTCOUNT, ARRAY_OF_INDICES(*)
     INTEGER ARRAY_OF_STATUSES(MPI_STATUS_SIZE,*), IERROR

Sintaxis Fortran 2008

USE mpi_f08
MPI_Testsome(incount, array_of_requests, outcount, array_of_indices,
             array_of_statuses, ierror)
     INTEGER, INTENT(IN) :: incount
     TYPE(MPI_Request), INTENT(INOUT) :: array_of_requests(incount)
     INTEGER, INTENT(OUT) :: outcount, array_of_indices(*)
     TYPE(MPI_Status) :: array_of_statuses(*)
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARÁMETROS DE ENTRADA

  • incount: Longitud de array_of_requests (entero).
  • array_of_requests: Matriz de solicitudes (matriz de identificadores).

PARÁMETROS DE SALIDA

  • outcount: Número de solicitudes completadas (entero).
  • array_of_indices: Matriz de índices de operaciones que se completaron (matriz de enteros).
  • array_of_statuses: Matriz de objetos de estado para operaciones que se completaron (matriz de estado).
  • ierror: Solo Fortran: Estado del error (entero).

DESCRIPCIÓN

Se comporta como MPI_Waitsome, excepto en que retorna inmediatamente.

Devuelve en outcount el número de solicitudes de la lista array_of_requests que se han completado. Devuelve en las primeras outcount ubicaciones de la matriz array_of_indices los índices de estas operaciones (índice dentro de la matriz array_of_requests; la matriz se indexa desde 0 en C y desde 1 en Fortran). Devuelve en las primeras outcount ubicaciones de la matriz array_of_status el estado de estas operaciones completadas. Si una solicitud que se completó fue asignada por una llamada de comunicación no bloqueante, entonces se libera y el identificador asociado se establece en MPI_REQUEST_NULL.

Si ninguna operación se ha completado, devuelve outcount = 0. Si no hay ningún identificador activo en la lista, devuelve outcount = MPI_UNDEFINED.

MPI_Testsome es una operación local que retorna inmediatamente, mientras que MPI_Waitsome se bloquea hasta que una comunicación se completa, si se le pasó una lista que contiene al menos un identificador activo. Ambas llamadas cumplen un requisito de justicia: si una solicitud de recepción aparece repetidamente en una lista de solicitudes pasadas a MPI_Waitsome o MPI_Testsome, y se ha publicado una envío coincidente, la recepción finalmente tendrá éxito a menos que el envío se satisfaga con otra recepción; las solicitudes de envío también cumplen este requisito de justicia.

Los errores que ocurren durante la ejecución de MPI_Testsome se manejan como para MPI_Waitsome.

Si su aplicación no necesita examinar el campo array_of_statuses, puede ahorrar recursos utilizando la constante predefinida MPI_STATUSES_IGNORE que puede usarse como valor especial para el argumento array_of_statuses.

NOTAS

El uso de MPI_Testsome es probablemente más eficiente que el uso de MPI_Testany. El primero devuelve información sobre todas las comunicaciones completadas; con el último, se requiere una nueva llamada por cada comunicación que se complete.

Un servidor con múltiples clientes puede usar MPI_Waitsome para no dejar a ningún cliente sin atención. Los clientes envían mensajes al servidor con solicitudes de servicio. El servidor llama a MPI_Waitsome con una solicitud de recepción por cada cliente, y luego maneja todas las recepciones que se han completado. Si en su lugar se usa una llamada a MPI_Waitany, entonces un cliente podría quedar sin atención mientras las solicitudes de otro cliente siempre se cuelan primero.

ERRORES

Casi todas las rutinas MPI devuelven un valor de error; las rutinas C como resultado de la función y las rutinas Fortran en el último argumento.

Antes de que se devuelva el valor de error, se llama al controlador de errores MPI actual asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo). Si no hay ningún objeto de comunicación asociado con la llamada MPI, entonces la llamada se considera adjunta a MPI_COMM_SELF y llamará al controlador de errores MPI asociado. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se usa exclusivamente el Modelo de Sesiones) el error eleva el controlador de errores inicial. El controlador de errores inicial se puede cambiar llamando a MPI_Comm_set_errhandler en MPI_COMM_SELF cuando se usa el modelo World, o al argumento de CLI mpi_initial_errhandler de mpiexec o la clave de información para MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no se ha establecido ningún otro controlador de errores apropiado, entonces se llama al controlador de errores MPI_ERRORS_RETURN para las funciones de E/S MPI y al controlador de errores MPI_ERRORS_ABORT para todas las demás funciones MPI.

Open MPI incluye tres controladores de errores predefinidos que se pueden utilizar:

  • MPI_ERRORS_ARE_FATAL Provoca que el programa aborte todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT Un controlador de errores que puede invocarse en un comunicador, ventana, archivo o sesión. Cuando se llama en un comunicador, actúa como si se hubiera llamado a MPI_Abort en ese comunicador. Si se llama en una ventana o archivo, actúa como si se hubiera llamado a MPI_Abort en un comunicador que contiene el grupo de procesos de la ventana o archivo correspondiente. Si se llama en una sesión, solo aborta el proceso local.
  • MPI_ERRORS_RETURN Devuelve un código de error a la aplicación.

Las aplicaciones MPI también pueden implementar sus propios controladores de errores llamando a:

  • MPI_Comm_create_errhandler luego MPI_Comm_set_errhandler
  • MPI_File_create_errhandler luego MPI_File_set_errhandler
  • MPI_Session_create_errhandler luego MPI_Session_set_errhandler o en MPI_Session_init
  • MPI_Win_create_errhandler luego MPI_Win_set_errhandler

Tenga en cuenta que MPI no garantiza que un programa MPI pueda continuar después de un error.

Consulte la página del manual de MPI para obtener una lista completa de los códigos de error de MPI.

Consulte la sección de Manejo de Errores del estándar MPI-3.1 para obtener más información.

Para cada invocación de MPI_Testsome, si una o más solicitudes generan un error MPI, solo la primera solicitud MPI que causó un error se pasará a su controlador de errores correspondiente. No se invocarán otros controladores de errores (incluso si varias solicitudes generaron errores). Sin embargo, a todas las solicitudes que generen un error se les establecerá un código de error relevante en el campo status.MPI_ERROR correspondiente (a menos que se haya utilizado MPI_STATUSES_IGNORE).

Si el controlador de errores invocado permite que MPI_Testsome retorne al llamador, el valor MPI_ERR_IN_STATUS se devolverá en los enlaces C y Fortran.
