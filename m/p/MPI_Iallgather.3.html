MPI_Allgather, MPI_Iallgather, MPI_Allgather_init - Recopila datos de todos los procesos y los distribuye a todos los procesos

SINTAXIS

Sintaxis C

#include <mpi.h>
int MPI_Allgather(const void *sendbuf, int  sendcount,
      MPI_Datatype sendtype, void *recvbuf, int recvcount,
      MPI_Datatype recvtype, MPI_Comm comm)
int MPI_Iallgather(const void *sendbuf, int  sendcount,
      MPI_Datatype sendtype, void *recvbuf, int recvcount,
      MPI_Datatype recvtype, MPI_Comm comm, MPI_Request *request)
int MPI_Allgather_init(const void *sendbuf, int  sendcount,
      MPI_Datatype sendtype, void *recvbuf, int recvcount,
      MPI_Datatype recvtype, MPI_Comm comm, MPI_Info info, MPI_Request *request)

PARÁMETROS DE ENTRADA

  • sendbuf: Dirección de inicio del búfer de envío (elección).
  • sendcount: Número de elementos en el búfer de envío (entero).
  • sendtype: Tipo de datos de los elementos del búfer de envío (manejador).
  • recvbuf: Dirección de inicio del búfer de recepción (elección).
  • recvcount: Número de elementos recibidos de cualquier proceso (entero).
  • recvtype: Tipo de datos de los elementos del búfer de recepción (manejador).
  • comm: Comunicador (manejador).
  • info: Información (manejador, solo persistente).

PARÁMETROS DE SALIDA

  • recvbuf: Dirección del búfer de recepción (elección).
  • request: Solicitud (manejador, solo no bloqueante).
  • ierror: Solo Fortran: Estado de error (entero).

DESCRIPCIÓN

MPI_Allgather es similar a MPI_Gather, excepto que todos los procesos reciben el resultado, en lugar de solo la raíz. En otras palabras, todos los procesos contribuyen al resultado y todos los procesos reciben el resultado.

La firma del tipo asociada con sendcount, sendtype en un proceso debe ser igual a la firma del tipo asociada con recvcount, recvtype en cualquier otro proceso.

El resultado de una llamada a MPI_Allgather es como si todos los procesos ejecutaran n llamadas a

MPI_Gather(sendbuf, sendcount, sendtype, recvbuf, recvcount,
           recvtype, root, comm);
// para root = 0 , ..., n-1.

Las reglas para el uso correcto de MPI_Allgather se encuentran fácilmente a partir de las reglas correspondientes para MPI_Gather.

Ejemplo: La versión all-gather del Ejemplo 1 en MPI_Gather. Usando MPI_Allgather, recopilaremos 100 enteros de cada proceso del grupo para cada proceso.

MPI_Comm comm;
int gsize,sendarray[100];
int *rbuf;
...
MPI_Comm_size( comm, &gsize);
rbuf = (int *)malloc(gsize*100*sizeof(int));
MPI_Allgather( sendarray, 100, MPI_INT, rbuf, 100, MPI_INT, comm);

Después de la llamada, cada proceso tiene la concatenación a nivel de grupo de los conjuntos de datos.

USO DE LA OPCIÓN IN-PLACE

Cuando el comunicador es un intracommunicador, puede realizar una operación de all-gather en el lugar (el búfer de salida se usa como el búfer de entrada). Use la variable MPI_IN_PLACE como valor de sendbuf. En este caso, sendcount y sendtype se ignoran. Se asume que los datos de entrada de cada proceso están en el área donde ese proceso recibiría su propia contribución al búfer de recepción. Específicamente, el resultado de una llamada a MPI_Allgather que usó la opción in-place es idéntico al caso en el que todos los procesos ejecutaron n llamadas a

MPI_Allgather( MPI_IN_PLACE, 0, MPI_DATATYPE_NULL, recvbuf,
               recvcount, recvtype, root, comm )
// para root =0, ... , n-1.

Tenga en cuenta que MPI_IN_PLACE es un tipo especial de valor; tiene las mismas restricciones de uso que MPI_BOTTOM.

Debido a que la opción in-place convierte el búfer de recepción en un búfer de envío y recepción, una vinculación de Fortran que incluye INTENT debe marcarlas como INOUT, no OUT.

CUANDO EL COMUNICADOR ES UN INTER-COMUNICADOR

Cuando el comunicador es un inter-comunicador, la operación de recopilación ocurre en dos fases. Los datos se recopilan de todos los miembros del primer grupo y se reciben por todos los miembros del segundo grupo. Luego, los datos se recopilan de todos los miembros del segundo grupo y se reciben por todos los miembros del primero. Sin embargo, la operación no tiene que ser simétrica. El número de elementos enviados por los procesos del primer grupo no tiene que ser igual al número de elementos enviados por los procesos del segundo grupo. Puede mover datos en una sola dirección dando a sendcount un valor de 0 para la comunicación en la dirección inversa.

ERRORES

Casi todas las rutinas de MPI devuelven un valor de error; las rutinas de C como resultado de la función y las rutinas de Fortran en el último argumento.

Antes de que se devuelva el valor de error, se llama al controlador de errores MPI actual asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo). Si no hay ningún objeto de comunicación asociado con la llamada MPI, entonces la llamada se considera adjunta a MPI_COMM_SELF y llamará al controlador de errores MPI asociado. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se usa exclusivamente el Modelo de Sesiones) el error activa el controlador de errores inicial. El controlador de errores inicial se puede cambiar llamando a MPI_Comm_set_errhandler en MPI_COMM_SELF cuando se usa el modelo World, o el argumento de línea de comandos mpi_initial_errhandler para mpiexec o la clave info para MPI_Comm_spawn/MPI_Comm_spawn_multiple. PARÁMETROS DE ENTRADA

Open MPI incluye tres manejadores de errores predefinidos que se pueden utilizar:

  • MPI_ERRORS_ARE_FATAL Desactiva el proceso de comunicación en todos los procesos conectados.
  • MPI_ERRORS_ABORT Un manejador de errores que puede invocarse en un comunicador, ventana, archivo o sesión. Cuando se invoca en un comunicador, actúa como si se hubiera llamado MPI_Abort en ese comunicador. Si se invoca en una ventana o archivo, actúa como si se hubiera llamado MPI_Abort en un comunicador que contiene el grupo de procesos en la correspondiente ventana o archivo. Si se invoca en una sesión, se detiene solo el proceso local.
  • MPI_ERRORS_RETURN Devuelve un código de error al programa.

También se pueden implementar manejadores de errores propios llamando:

  • MPI_Comm_create_errhandler y luego MPI_Comm_set_errhandler
  • MPI_File_create_errhandler y luego MPI_File_set_errhandler
  • MPI_Session_create_errhandler y luego MPI_Session_set_errhandler o en MPI_Session_init
  • MPI_Win_create_errhandler y luego MPI_Win_set_errhandler

Nota: MPI no garantiza que un programa pueda continuar después de un error.

Consulte la sección MPI man page para obtener una lista completa de los MPI error codes.

Consulte la sección de Manejo de Errores de la norma MPI-3.1 para más información.
