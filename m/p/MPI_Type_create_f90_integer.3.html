MPI_Type_create_f90_integer(3)

Paquete: openmpi

Licencias: BSD-3-Clause AND LicenseRef-MPICH

MPI_Type_create_f90_integer(3) Open MPI MPI_Type_create_f90_integer(3) 
MPI_Type_create_f90_integer - Devuelve un tipo de dato entero con precisión limitada

SINTAXIS

Sintaxis C

#include <mpi.h>
int MPI_Type_create_f90_integer(int r, MPI_Datatype *newtype)

Sintaxis Fortran

USE MPI
! o la forma antigua: INCLUDE 'mpif.h'
MPI_TYPE_CREATE_F90_INTEGER (R, NEWTYPE, IERROR)
     INTEGER R, NEWTYPE, IERROR

Sintaxis Fortran 2008

USE mpi_f08
MPI_Type_create_f90_integer(r, newtype, ierror)
     INTEGER, INTENT(IN) :: r
     TYPE(MPI_Datatype), INTENT(OUT) :: newtype
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARÁMETRO DE INGRESO

•
r: Precisión, en dígitos decimales (entero).

PARÁMETROS DE SALIDA

  • newtype: Nuevo tipo de dato (handle).
  • ierror: Solo en Fortran: Estado de error (entero).

DESCRIPCIÓN

Esta función proporciona un modo de declarar tipos de dato MPI con parámetro KIND. El argumento se interpreta de manera similar a la función F90 SELECTED_INT_KIND: r debe ser un entero escalar y representa la precisión deseada en dígitos decimales.

NOTAS

Se considera erróneo proporcionar un valor para r no soportado por el compilador.

La función Fortran SELECTED_INT_KIND mapea un gran número de valores de r a un número más reducido de parámetros KIND soportados por el compilador. Los parámetros KIND no son especificados por el lenguaje y no son portables. Desde el punto de vista del lenguaje, variables del mismo tipo base y parámetro KIND son equivalentes, incluso si sus parámetros KIND fueron generados por diferentes r de SELECTED_INT_KIND. Sin embargo, para facilitar la interoperabilidad en entornos heterogéneos, la equivalencia es más estricta para los tipos de dato devueltos por MPI_Type_create_f90_integer. Dos tipos de dato MPI, cada uno generado por esta función, coincidirán si y solo si tienen valores iguales para r.

La interacción entre los tipos de dato devueltos por esta función y la representación externa32 - utilizada por MPI_Pack_external, MPI_Unpack_external y muchas funciones MPI_File - es sutil. La representación externa32 del tipo de dato devuelto se especifica como sigue.

if (r > 38):
        external32 size = n/a (undefined)
else if (r > 18):
        external32 size = 16
else if (r > 9):
        external32 size = 8
else if (r > 4):
        external32 size = 4
else if (r > 2):
        external32 size = 2
else:
        external32 size = 1

Si la representación externa32 de un tipo de dato es undefined, así son los resultados de usar ese tipo de dato en operaciones que requieren la representación externa32. Debe tener cuidado para no usar tipos de dato incompatibles indirectamente, por ejemplo, como parte de otro tipo de dato o a través de un tipo de dato duplicado, en estas funciones.

Si una variable es declarada especificando un valor de KIND no por defecto que no fue obtenido con SELECTED_INT_KIND (es decir, r es desconocido), la única manera de obtener un tipo de dato MPI correspondiente es usar las funciones MPI_Sizeof y MPI_Type_match_size.

ERRORES

Más que los errores MPI, el resultado de las rutinas C es el valor de error; para las rutinas Fortran, el último argumento es el valor de error.

Antes de que el valor de error sea devuelto, se llama al handler de error asociado con el objeto de comunicación (por ejemplo, communicator, window, file) y si no hay objeto de comunicación asociado, se considera que la llamada está asociada a MPI_COMM_SELF y se llama al handler de error correspondiente. Si MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se utiliza el modelo de Sesiones exclusivamente), el error eleva el handler de error inicial. El handler de error inicial puede cambiarse llamando a MPI_Comm_set_errhandler sobre MPI_COMM_SELF cuando se use el modelo del Mundo, o mediante el argumento mpi_initial_errhandler de mpiexec o mediante la clave info de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no hay otro handler de error adecuado, se llama el handler MPI_ERRORS_RETURN para las funciones de I/O MPI y MPI_ERRORS_ABORT para todas las demás funciones MPI.

El Open MPI incluye tres handlers de error predeterminados que pueden usarse:

  • MPI_ERRORS_ARE_FATAL Lanza el programa para abortar todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT Un handler de error que puede invocarse en un communicator, window, file o sesión. Cuando se invoca en un communicator, actúa como si se hubiera llamado MPI_Abort en ese communicator. Si se invoca en un window o file, actúa como si se hubiera llamado MPI_Abort en un communicator que contiene los procesos en la correspondiente window o file. Si se invoca en una sesión, aborta solo el proceso local.
  • MPI_ERRORS_RETURN Devuelve un código de error a la aplicación.

Los programas MPI pueden también implementar sus propios handlers de error llamando:

  • MPI_Comm_create_errhandler luego MPI_Comm_set_errhandler
  • MPI_File_create_errhandler luego MPI_File_set_errhandler
  • MPI_Session_create_errhandler luego MPI_Session_set_errhandler o al MPI_Session_init
  • MPI_Win_create_errhandler luego MPI_Win_set_errhandler

Nota: Los programas MPI no garantizan que puedan continuar después de un error.
