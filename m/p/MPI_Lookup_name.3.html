MPI_Lookup_name(3)

Paquete: openmpi

Licencias: BSD-3-Clause AND LicenseRef-MPICH

MPI_LOOKUP_NAME(3) Open MPI MPI_LOOKUP_NAME(3) 
MPI_Lookup_name - Encuentra el puerto asociado a un nombre de servicio

SINTAXIS

Sintaxis C

#include <mpi.h>
int MPI_Lookup_name(const char *service_name, MPI_Info info,
     char *port_name)

Sintaxis Fortran

USE MPI
! o la forma más antigua: INCLUDE 'mpif.h'
MPI_LOOKUP_NAME(SERVICE_NAME, INFO, PORT_NAME, IERROR)
     CHARACTER*(*)   SERVICE_NAME, PORT_NAME
     INTEGER         INFO, IERROR

Sintaxis Fortran 2008

USE mpi_f08
MPI_Lookup_name(service_name, info, port_name, ierror)
     CHARACTER(LEN=*), INTENT(IN) :: service_name
     TYPE(MPI_Info), INTENT(IN) :: info
     CHARACTER(LEN=MPI_MAX_PORT_NAME), INTENT(OUT) :: port_name
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARÁMETROS DE ENTRADA

  • service_name: Un nombre de servicio (cadena).
  • info: Opciones para las funciones de servicio de nombres (manejador).

PARÁMETROS DE SALIDA

  • port_name: un nombre de puerto (cadena).
  • ierror: solo Fortran: Estado de error (entero).

DESCRIPCIÓN

Esta función recupera un port_name publicado bajo service_name por una invocación previa de MPI_Publish_name. La aplicación debe proporcionar un búfer port_name lo suficientemente grande como para contener el nombre de puerto más grande posible (es decir, MPI_MAX_PORT_NAME bytes).

ARGUMENTOS INFO

Se reconocen las siguientes claves para info:

Clave                   Tipo      Descripción
---                   ----      -----------
ompi_lookup_order     char *    Orden de resolución para la búsqueda de nombres.

La clave de información ompi_lookup_order puede especificar uno de los cuatro valores de cadena válidos (consulte la sección NAME SCOPE a continuación para obtener más información sobre los ámbitos de nombres):

local: Solo buscar en el ámbito local para la resolución de nombres.

global: Solo buscar en el ámbito global para la resolución de nombres.

local,global: Buscar en el ámbito local para la resolución de nombres. Si
no se encuentra, intente buscar en el ámbito global para la resolución de nombres. Este comportamiento es el predeterminado si la clave de información ompi_lookup_order no se especifica.
global,local: Buscar en el ámbito global para la resolución de nombres. Si
no se encuentra, intente buscar en el ámbito local para la resolución de nombres.

Si no se proporciona ninguna clave de info, la búsqueda verificará primero si se ha especificado y está disponible un servidor global. Si es así, la búsqueda tendrá como valor predeterminado el ámbito global primero, seguido del local. De lo contrario, la búsqueda tendrá como valor predeterminado el local.

AMBITO DE NOMBRES

Open MPI admite dos ámbitos de nombres: global y local. Los valores de ámbito local se colocan en un almacén de datos ubicado en el mpirun del proceso de llamada de la tarea, mientras que los valores de ámbito global residen en un servidor central. Las llamadas a MPI_Unpublish_name deben especificar correctamente el ámbito que se utilizará para encontrar el valor a eliminar. La función devolverá un error si el nombre de servicio especificado no se encuentra en la ubicación indicada.

Para una descripción más detallada de las reglas de ámbito, consulte la página del manual de MPI_Publish_name.

ERRORES

Casi todas las rutinas de MPI devuelven un valor de error; rutinas C como resultado de la función y rutinas Fortran en el último argumento.

Antes de devolver el valor de error, se llama al controlador de errores MPI actual asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo). Si no hay ningún objeto de comunicación asociado con la llamada MPI, la llamada se considera adjunta a MPI_COMM_SELF y llamará al controlador de errores MPI asociado. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se usa exclusivamente el Modelo de Sesiones), el error eleva el controlador de errores inicial. El controlador de errores inicial se puede cambiar llamando a MPI_Comm_set_errhandler en MPI_COMM_SELF cuando se usa el modelo World, o el argumento de línea de comandos mpi_initial_errhandler para mpiexec o la clave de información para MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no se ha establecido ningún otro controlador de errores apropiado, se llama al controlador de errores MPI_ERRORS_RETURN para las funciones de E/S de MPI y se llama al controlador de errores MPI_ERRORS_ABORT para todas las demás funciones de MPI.

Open MPI incluye tres controladores de errores predefinidos que se pueden utilizar:

  • MPI_ERRORS_ARE_FATAL Causa que el programa aborte todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT Un controlador de errores que se puede invocar en un comunicador, ventana, archivo o sesión. Cuando se llama en un comunicador, actúa como si se hubiera llamado a MPI_Abort en ese comunicador. Si se llama en una ventana o archivo, actúa como si se hubiera llamado a MPI_Abort en un comunicador que contiene el grupo de procesos de la ventana o archivo correspondiente. Si se llama en una sesión, aborta solo el proceso local.
  • MPI_ERRORS_RETURN Devuelve un código de error a la aplicación.

Las aplicaciones MPI también pueden implementar sus propios controladores de errores llamando a:

  • MPI_Comm_create_errhandler y luego MPI_Comm_set_errhandler
  • MPI_File_create_errhandler y luego MPI_File_set_errhandler
  • MPI_Session_create_errhandler y luego MPI_Session_set_errhandler o en MPI_Session_init
  • MPI_Win_create_errhandler y luego MPI_Win_set_errhandler

Tenga en cuenta que MPI no garantiza que un programa MPI pueda continuar después de un error.

Consulte la página del manual de MPI para obtener una lista completa de los códigos de error de MPI.

Consulte la sección Manejo de Errores del estándar MPI-3.1 para obtener más información.
