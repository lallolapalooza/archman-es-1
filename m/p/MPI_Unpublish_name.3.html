MPI_Unpublish_name(3) Open MPI MPI_Unpublish_name(3) 
MPI_Unpublish_name - Elimina un nombre de servicio

Sintaxis

Sintaxis C

#include <mpi.h>
int MPI_Unpublish_name(const char *service_name, MPI_Info info,
     const char *port_name)

Sintaxis Fortran

USE MPI
! o un antiguo formato: INCLUDE 'mpif.h'
MPI_UNPUBLISH_NAME(SERVICE_NAME, INFO, PORT_NAME, IERROR)
     CHARACTER*(*)   SERVICE_NAME, PORT_NAME
     INTEGER         INFO, IERROR

Sintaxis Fortran 2008

USE mpi_f08
MPI_Unpublish_name(service_name, info, port_name, ierror)
     CHARACTER(LEN=*), INTENT(IN) :: service_name, port_name
     TYPE(MPI_Info), INTENT(IN) :: info
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

Parámetros de entrada

  • service_name: Nombre del servicio (cadena).
  • info: Opciones para las funciones de nombres de servicio (handle).
  • port_name: Nombre del puerto (cadena).

Parámetro de salida

•
ierror: Solo Fortran: Código de error (entero).

Descripción

Esta rutina elimina el par (service_name, port_name) para que las aplicaciones no puedan recuperar port_name llamando a MPI_Lookup_name. Es un error despublicar un service_name que no haya sido publicado mediante MPI_Publish_name. Tanto los argumentos service_name como port_name de MPI_Unpublish_name deben ser idénticos a los argumentos de la llamada anterior a MPI_Publish_name.

Argumentos de información

Se reconocen las siguientes claves para info:

Clave                Tipo      Descripción
---                   ----      -----------
ompi_global_scope     bool      Si se establece en true, elimina el nombre de servicio del ámbito global. Si no, elimina el nombre de servicio del ámbito local. Para más detalles, véase la sección sobre el ámbito del nombre.

Las claves bool son en realidad cadenas, pero se evalúan como sigue: si el valor de la cadena es un número, se convierte a un entero y se castea a un booleano (es decir, los enteros 0 son falsos y los valores distintos de cero son verdaderos). Si el valor de la cadena es (sin distinción de mayúsculas) "yes" o "true", el booleano es verdadero. Si el valor de la cadena es (sin distinción de mayúsculas) "no" o "false", el booleano es falso. Todos los demás valores de cadena no se reconocen y, por lo tanto, son falsos.

Si no se proporciona ninguna clave de información, la función primero comprueba si hay un servidor global especificado y disponible. Si es así, la función de eliminación predeterminada utilizará el ámbito global, seguido del ámbito local. De lo contrario, los datos utilizan el ámbito local.

Ámbito del nombre

Open MPI soporta dos ámbitos de nombres: global y local. Los valores del ámbito local se almacenan en un almacenamiento local ubicado en el proceso de ejecución del trabajo de mpirun, mientras que los valores del ámbito global se almacenan en un servidor central. Las llamadas a MPI_Unpublish_name deben especificar correctamente el ámbito que se utilizará para encontrar el valor a eliminar. La función devolverá un error si el nombre de servicio especificado no se encuentra en la ubicación correcta.

Para una descripción más detallada de las reglas de ámbito, véase la página de MPI_Publish_name.

Errores

La mayoría de las rutinas MPI devuelven un valor de error; para las rutinas C, el resultado es el valor de error de la función, y para las rutinas Fortran, el argumento final.

Antes de devolver el valor de error, se llama a la función controladora de errores asociada con el objeto de comunicación actual (por ejemplo, comunicador, ventana, archivo). Si no hay un objeto de comunicación asociado con la llamada MPI, se considera que la llamada está asociada con MPI_COMM_SELF y se llamará a la función controladora de errores asociada con MPI_COMM_SELF. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize o cuando se utiliza exclusivamente el modelo de sesiones), el error eleva el controlador de errores inicial. El controlador de errores inicial puede cambiarse llamando a MPI_Comm_set_errhandler sobre MPI_COMM_SELF cuando se utiliza el modelo del mundo, o la clave info CLI mpi_initial_errhandler para mpiexec o la clave info para MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no hay ningún otro controlador de errores adecuado configurado, se llama al controlador de errores MPI_ERRORS_RETURN para las funciones de E/S MPI y al controlador de errores MPI_ERRORS_ABORT para todas las demás funciones MPI.

Open MPI incluye tres controladores de errores prediseñados que se pueden utilizar:

  • MPI_ERRORS_ARE_FATAL hace que el programa finalice todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT es un controlador de errores que puede invocarse en un comunicador, ventana, archivo o sesión. Cuando se invoca en un comunicador, actúa como si se hubiera llamado MPI_Abort en ese comunicador. Si se invoca en una ventana o archivo, actúa como si se hubiera llamado MPI_Abort en un comunicador que contiene el conjunto de procesos en la ventana o archivo correspondiente. Si se invoca en una sesión, finaliza solo el proceso local.
  • MPI_ERRORS_RETURN devuelve un código de error a la aplicación.

Las aplicaciones MPI también pueden implementar sus propios controladores de errores llamando a:

  • MPI_Comm_create_errhandler luego MPI_Comm_set_errhandler
  • MPI_File_create_errhandler luego MPI_File_set_errhandler
  • MPI_Session_create_errhandler luego MPI_Session_set_errhandler o en MPI_Session_init
  • MPI_Win_create_errhandler luego MPI_Win_set_errhandler

Nota: Los programas MPI no garantizan que puedan continuar después de un error.

Ver la página de MPI man para una lista completa de errores MPI.

Ver la sección de manejo de errores de la especificación MPI-3.1 para más información.
