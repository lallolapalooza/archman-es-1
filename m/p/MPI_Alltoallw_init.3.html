PARÁMETROS DE ENTRADA

  • sendbuf: Dirección de inicio del búfer de envío.
  • sendcounts: Array de enteros, donde el elemento i especifica el número de elementos a enviar a el proceso i.
  • sdispls: Array de enteros, donde el elemento i especifica el desplazamiento (en bytes, offset desde sendbuf) de los que se envían a el proceso i.
  • sendtypes: Array de tipos de datos, donde el elemento i especifica el tipo de datos a usar cuando se envían datos a el proceso i.
  • recvcounts: Array de enteros, donde el elemento j especifica el número de elementos a recibir de el proceso j.
  • rdispls: Array de enteros, donde el elemento j especifica la desplazamiento (en bytes, offset desde recvbuf) a donde se deben escribir los datos del proceso j.
  • recvtypes: Array de tipos de datos, donde el elemento j especifica el tipo de datos a usar cuando se reciben datos del proceso j.
  • comm: Comunicador sobre el cual se realizarán las operaciones.
  • info: Info (handle, persistente)

PARÁMETROS DE SALIDA

  • recvbuf: Dirección del búfer de recepción.
  • request: Peticion (handle, no bloqueante).
  • ierror: Solo en Fortran: Estado de error.

DESCRIPCIÓN

MPI_Alltoallw es una operación colectiva generalizada en la que todos los procesos envían datos a y reciben datos desde todos los otros procesos. Esto añade flexibilidad a MPI_Alltoallv permitiendo al usuario especificar el tipo de datos de cada bloque de datos (además de desplazamiento y cantidad de elementos). Su operación puede pensarse así, donde cada proceso realiza 2n (n siendo el número de procesos en el comunicador comm) comunicaciones punto a punto independientes.

MPI_Comm_size(comm, &n);
for (i = 0, i < n; i++)
    MPI_Send(sendbuf + sdispls[i], sendcounts[i],
        sendtypes[i], i, ..., comm);
for (i = 0, i < n; i++)
    MPI_Recv(recvbuf + rdispls[i], recvcounts[i],
        recvtypes[i], i, ..., comm);

El proceso j envía el bloque k del búfer de envío local a el proceso k, que coloca los datos en el bloque j del búfer de recepción local.

Cuando un par de procesos intercambian datos, cada puede pasar diferentes argumentos de cantidad de elementos y tipo de datos, siempre que el emisor especifique el mismo cantidad de datos (en bytes) que el receptor espera recibir.

Nota: El proceso i puede enviar un diferente cantidad de datos a el proceso j que reciba de j. También, un proceso puede enviar diferentes cantidades y tipos de datos a diferentes procesos en el comunicador.

CUANDO EL COMUNICADORES ES UN COMUNICADORES INTERCOMUNICA

Cuando el comunicador es un comunicador intercomunicador, la operación se realiza en dos fases. El dato se recolecta de todos los miembros del primer grupo y se recibe por todos los miembros del segundo grupo. Luego, el dato se recolecta de todos los miembros del segundo grupo y se recibe por todos los miembros del primer grupo. Esta operación muestra un comportamiento simétrico, doble, completo.

El primer grupo define el proceso raíz. El proceso raíz usa MPI_ROOT como el valor de root. Todos los otros procesos en el primer grupo usan MPI_PROC_NULL como el valor de root. Todos los procesos en el segundo grupo usan el número de rank del proceso raíz en el primer grupo como el valor de root.

Cuando el comunicador es un comunicador intracomunicador, estos grupos son los mismos y la operación ocurre en una sola fase.

USO DE LA OPCION DE EN PUNTO

Cuando el comunicador es un intracomunicador, puedes realizar una operación all-to-all en lugar de (el búfer de salida se usa como el búfer de entrada). Usa la variable MPI_IN_PLACE como el valor de sendbuf. En este caso, sendcounts, sdispls, y sendtypes son ignorados. Los datos de entrada de cada proceso se asumen que están en el área donde ese proceso recibiría su propio contribución al búfer de recepción.

NOTAS

La especificación de cantidades, tipos y desplazamientos no debe causar que ningún lugar sea escrito más de una vez.

Todos los argumentos en todos los procesos son significativos. El argumento comm, en particular, debe describir el mismo comunicador en todos los procesos.

Los desplazamientos de sdispls y rdispls se miden en bytes. Compare esto con MPI_Alltoallv

ERRORES

Casi todas las rutinas de MPI devuelven un valor de error; las rutinas de C como resultado de retorno de la función y las rutinas de Fortran en el último argumento.

Antes de que se devuelva el valor de error, se llama al manejador de errores de MPI actual asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo). Si no hay ningún objeto de comunicación asociado con la llamada MPI, entonces la llamada se considera adjunta a MPI_COMM_SELF y llamará al manejador de errores de MPI asociado. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se utiliza exclusivamente el Modelo de Sesiones), el error activa el manejador de errores inicial. El manejador de errores inicial se puede cambiar llamando a MPI_Comm_set_errhandler en MPI_COMM_SELF cuando se utiliza el modelo World, o el argumento de CLI mpi_initial_errhandler para mpiexec o la clave de información para MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no se ha establecido ningún otro manejador de errores apropiado, entonces se llama al manejador de errores MPI_ERRORS_RETURN para las funciones de E/S de MPI y al manejador de errores MPI_ERRORS_ABORT para todas las demás funciones de MPI.

Open MPI incluye tres manejadores de errores predefinidos que se pueden utilizar:

  • MPI_ERRORS_ARE_FATAL Provoca que el programa aborte todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT Un manejador de errores que se puede invocar en un comunicador, ventana, archivo o sesión. Cuando se llama en un comunicador, actúa como si se hubiera llamado a MPI_Abort en ese comunicador. Si se llama en una ventana o archivo, actúa como si se hubiera llamado a MPI_Abort en un comunicador que contiene el grupo de procesos en la ventana o archivo correspondiente. Si se llama en una sesión, aborta solo el proceso local.
  • MPI_ERRORS_RETURN Devuelve un código de error a la aplicación.

Las aplicaciones MPI también pueden implementar sus propios manejadores de errores llamando a:

  • MPI_Comm_create_errhandler luego MPI_Comm_set_errhandler
  • MPI_File_create_errhandler luego MPI_File_set_errhandler
  • MPI_Session_create_errhandler luego MPI_Session_set_errhandler o en MPI_Session_init
  • MPI_Win_create_errhandler luego MPI_Win_set_errhandler

Tenga en cuenta que MPI no garantiza que un programa MPI pueda continuar después de un error.

Consulte la página del manual de MPI para obtener una lista completa de los códigos de error de MPI.

Consulte la sección de Manejo de Errores del estándar MPI-3.1 para obtener más información.
