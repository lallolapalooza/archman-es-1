MPI_Neighbor_allgatherv, MPI_Ineighbor_allgatherv, MPI_Neighbor_allgatherv_init — Recopila y distribuye datos de y hacia todos los vecinos. Cada proceso puede contribuir una cantidad diferente de datos.

PARAMETROS DE ENTRADA

  • sendbuf: Dirección del buffer de envío (opcional).
  • sendcount: Cantidad de elementos en el buffer de envío (entero).
  • sendtype: Tipo de elementos del buffer de envío (handle).
  • recvcount: Array de enteros (de longitud del tamaño del grupo) que contienen la cantidad de elementos que se reciben de cada vecino.
  • displs: Array de enteros (de longitud del tamaño del grupo). El elemento i especifica el desplazamiento (relativo a recvbuf) en el que se colocarán los datos del vecino i.
  • recvtype: Tipo de elementos del buffer de recepción (handle).
  • comm: Comunicador (handle).
  • info: Info (handle, solo persistente).

PARAMETROS DE SALIDA

  • recvbuf: Dirección del buffer de recepción (opcional).
  • request: Solicitud (handle, no bloqueante).
  • ierror: Solo en Fortran: Valor de error (entero).

DESCRIPCION

MPI_Neighbor_allgatherv es similar a MPI_Neighbor_allgather en que todos los procesos recopilan datos de todos los vecinos, excepto que cada proceso puede enviar una cantidad diferente de datos. El bloque de datos enviado desde el vecino j es recibido por todos los vecinos y se coloca en el bloque j del buffer. El orden de los vecinos y la disposición del buffer están determinados por la topología de comm. recvbuf.

La firma del tipo asociada con sendcount, sendtype en el proceso j debe ser igual a la firma del tipo asociada con el elemento correspondiente en recvcounts en los vecinos del proceso j.

ORDENAMIENTO DE VECINOS

Para una topología de grafo distribuido, creada con MPI_Dist_graph_create, la secuencia de vecinos en los buffers de envío y recepción en cada proceso se define como la secuencia devuelta por MPI_Dist_graph_neighbors para los destinos y orígenes respectivamente. Para una topología de grafo general, creada con MPI_Graph_create, la secuencia de vecinos en los buffers de envío y recepción se define como la secuencia de vecinos devuelta por MPI_Graph_neighbors. Tenga en cuenta que las topologías de grafo generales deben ser reemplazadas generalmente por las topologías de grafo distribuidas.

Para una topología cartesiana, creada con MPI_Cart_create, la secuencia de vecinos en los buffers de envío y recepción en cada proceso se define según el orden de las dimensiones, primero en la dirección negativa y luego en la dirección positiva con un desplazamiento de 1. El número de fuentes y destinos en las rutinas de comunicación es 2*ndims con ndims definido en MPI_Cart_create. Si un vecino no existe, es decir, en el borde de una topología cartesiana en el caso de una red virtual no periódica (es decir, periods[...]==false), entonces este vecino se define como MPI_PROC_NULL.

Si un vecino en cualquiera de las funciones es MPI_PROC_NULL, entonces la comunicación colectiva se comporta como una comunicación punto a punto con MPI_PROC_NULL en esa dirección. Es decir, el buffer sigue siendo parte de la secuencia de vecinos, pero no se comunica ni se actualiza.

NOTAS

La opción sendbuf MPI_IN_PLACE no es significativa para esta operación.

ERRORES

Casi todas las rutinas MPI devuelven un valor de error; las rutinas C devuelven el resultado de la función y las rutinas Fortran en el último argumento.

Antes de devolver el valor de error, se llama al manejador de errores asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo) actual. Si no hay objeto de comunicación asociado con la llamada MPI, la llamada se considera asociada a MPI_COMM_SELF y se llama al manejador de errores asociado con MPI_COMM_SELF. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se utiliza el modelo de Sesiones exclusivamente), el error llama al manejador de errores inicial. El manejador de errores inicial puede ser cambiado llamando a MPI_Comm_set_errhandler con MPI_COMM_SELF cuando se usa el modelo del Mundo, o a través del argumento CLI mpi_initial_errhandler en mpiexec o la clave info en MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no hay otro manejador de errores apropiado, se llama al manejador de errores MPI_ERRORS_RETURN para las funciones de I/O MPI y al manejador de errores MPI_ERRORS_ABORT para todas las otras funciones MPI.

ERRORS

The default error handler for all MPI routines is MPI_ERRORS_ARE_FATAL. When this error handler is invoked, the MPI execution environment is immediately terminated and all processes are aborted. The MPI standard specifies that when an error occurs, the default error handler is invoked on a communicator determined by the context in which the error occurred. For example, if an error occurs during a collective operation on a communicator comm, the error handler is invoked on comm. If an error occurs during a point-to-point communication, the error handler is invoked on the communicator that contains the involved processes.

The following error handlers are predefined in the MPI standard:

  • MPI_ERRORS_ARE_FATAL: Aborts all processes.
  • MPI_ERRORS_RETURN: Returns an error code to the application.

MPI applications can also implement their own error handlers by calling:

  • MPI_Comm_create_errhandler then MPI_Comm_set_errhandler
  • MPI_File_create_errhandler then MPI_File_set_errhandler
  • MPI_Session_create_errhandler then MPI_Session_set_errhandler or at MPI_Session_init
  • MPI_Win_create_errhandler then MPI_Win_set_errhandler

Note that MPI does not guarantee that an MPI program can continue past an error.

See the MPI man page for a full list of MPI error codes.

See the Error Handling section of the MPI-3.1 standard for more information.
