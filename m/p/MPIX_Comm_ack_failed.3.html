MPIX_Comm_ack_failed(3)

Paquete: openmpi

Licencias: BSD-3-Clause AND LicenseRef-MPICH

MPIX_COMM_ACK_FAILED(3) Open MPI MPIX_COMM_ACK_FAILED(3)

MPIX_Comm_get_failed - acusa recibo de procesos fallidos en un comunicador.

Esto es parte de la extensión ULFM de User Level Fault Mitigation.

SINTAXIS

Sintaxis C

#include <mpi.h>
#include <mpi-ext.h>
int MPIX_Comm_ack_failed(MPI_Comm comm, int num_to_ack, int *num_acked)

Sintaxis Fortran

USE MPI
USE MPI_EXT
! o la forma más antigua: INCLUDE 'mpif.h'
MPIX_COMM_ACK_FAILED(COMM, NUM_TO_ACK, NUM_ACKED, IERROR)
     INTEGER COMM, NUM_TO_ACK, NUM_ACKED, IERROR

Sintaxis Fortran 2008

USE mpi_f08
USE mpi_ext_f08
MPIX_Comm_ack_failed(comm, num_to_ack, num_acked, ierror)
     TYPE(MPI_Comm), INTENT(IN) :: comm
     INTEGER, INTENT(IN) :: num_to_ack
     INTEGER, INTENT(OUT) :: num_acked
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARÁMETROS DE ENTRADA

  • comm: Comunicador (identificador).
  • num_to_ack: número máximo de fallos de procesos a acusar recibo en comm (entero)

PARÁMETROS DE SALIDA

  • num_acked: número de fallos acusados recibo en comm (entero).
  • ierror: solo Fortran: Estado de error (entero).

DESCRIPCIÓN

Esta operación local proporciona a los usuarios una forma de **acusar recibo** de fallos notificados localmente en comm. La operación acusa recibo de los primeros num_to_ack fallos de procesos en comm, es decir, acusa recibo del fallo de los miembros con un rango inferior a num_to_ack en el grupo que se produciría por una llamada concurrente a MPIX_Comm_get_failed en el mismo comm.

La operación también establece el valor de num_acked al número actual de fallos de procesos acusados recibo en comm, es decir, un fallo de proceso ha sido acusado recibo en comm si y solo si el rango del proceso es inferior a num_acked en el grupo que se produciría por una llamada posterior a MPIX_Comm_get_failed en el mismo comm.

num_acked puede ser mayor que num_to_ack cuando los fallos de procesos han sido acusados recibo en una llamada anterior a MPIX_Comm_ack_failed.

EFECTO DE ACUSAR RECIBO DE FALLOS

Después de que se acuse recibo de un fallo de proceso MPI en comm, las operaciones de recepción no coincidentes MPI_ANY_SOURCE en el mismo comm que habrían generado un error de clase MPIX_ERR_PROC_FAILED_PENDING procederán sin generar más errores debido a este fallo acusado recibo.

Además, MPIX_Comm_agree en el mismo comm no generará un error de clase MPI_ERR_PROC_FAILED debido a este fallo acusado recibo.

PATRONES DE USO

Se puede consultar, sin efectos secundarios, el número de fallos de procesos actualmente acusados recibo en comm proporcionando 0 en num_to_ack.

Por el contrario, se pueden acusar recibo incondicionalmente todos los fallos de procesos actualmente conocidos en comm proporcionando el tamaño del grupo de comm en num_to_ack.

Tenga en cuenta que el número de procesos acusados recibo, devuelto en num_acked, puede ser menor o mayor que el valor proporcionado en num_to_ack; sin embargo, nunca es mayor que el tamaño del grupo devuelto por una llamada posterior a MPIX_Comm_get_failed.

EFECTO EN OPERACIONES COLECTIVAS

Llamar a MPIX_Comm_ack_failed en un comunicador con procesos MPI fallidos no tiene efecto en las operaciones colectivas (excepto para MPIX_Comm_agree). Si una operación colectiva generara un error debido a que el comunicador contiene un proceso fallido, seguirá generando un error incluso después de que se haya acusado recibo del fallo. Para utilizar operaciones colectivas entre procesos MPI de un comunicador que contiene procesos MPI fallidos, los usuarios deben crear un nuevo comunicador (por ejemplo, llamando a MPIX_Comm_shrink).

CUANDO EL COMUNICADOR ES UN INTERCOMUNICADOR

Cuando el comunicador es un intercomunicador, se acusan recibo de los fallos de los miembros tanto de los grupos local como remoto de comm.

ERRORES

Casi todas las rutinas MPI devuelven un valor de error; las rutinas C como resultado de la función y las rutinas Fortran en el último argumento.

Antes de que se devuelva el valor de error, se llama al controlador de errores MPI actual asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo). Si no hay ningún objeto de comunicación asociado con la llamada MPI, la llamada se considera adjunta a MPI_COMM_SELF y llamará al controlador de errores MPI asociado. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se utiliza exclusivamente el Modelo de Sesiones) el error genera el controlador de errores inicial. El controlador de errores inicial se puede cambiar llamando a MPI_Comm_set_errhandler en MPI_COMM_SELF cuando se utiliza el modelo World, o el argumento de línea de comandos mpiexec mpi_initial_errhandler o la clave info de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no se ha establecido ningún otro controlador de errores adecuado, se llama al controlador de errores MPI_ERRORS_RETURN para las funciones de E/S de MPI y al controlador de errores MPI_ERRORS_ABORT para todas las demás funciones MPI.

Open MPI incluye tres controladores de errores predefinidos que se pueden utilizar:

  • MPI_ERRORS_ARE_FATAL Provoca que el programa aborte todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT Un controlador de errores que se puede invocar en un comunicador, ventana, archivo o sesión. Cuando se llama en un comunicador, actúa como si se hubiera llamado a MPI_Abort en ese comunicador. Si se llama en una ventana o archivo, actúa como si se hubiera llamado a MPI_Abort en un comunicador que contiene el grupo de procesos en la ventana o archivo correspondiente. Si se llama en una sesión, solo aborta el proceso local.
  • MPI_ERRORS_RETURN Devuelve un código de error a la aplicación.

Las aplicaciones MPI también pueden implementar sus propios controladores de errores llamando a:

  • MPI_Comm_create_errhandler luego MPI_Comm_set_errhandler
  • MPI_File_create_errhandler luego MPI_File_set_errhandler
  • MPI_Session_create_errhandler luego MPI_Session_set_errhandler o en MPI_Session_init
  • MPI_Win_create_errhandler luego MPI_Win_set_errhandler

Tenga en cuenta que MPI no garantiza que un programa MPI pueda continuar después de un error.

Consulte la página del manual de MPI para obtener una lista completa de los códigos de error de MPI.

Consulte la sección de Manejo de Errores del estándar MPI-3.1 para obtener más información.
