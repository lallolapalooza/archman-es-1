PARÁMETROS DE ENTRADA

  • sendbuf: Dirección de inicio del búfer de envío.
  • sendcounts: Array de enteros, donde la entrada i especifica el número de elementos a enviar al vecino i.
  • sdispls: Array de enteros, donde la entrada i especifica el desplazamiento (en bytes, compensación desde sendbuf) desde el cual enviar datos al vecino i.
  • sendtypes: Array de tipos de datos, donde la entrada i especifica el tipo de datos a utilizar al enviar datos al vecino i.
  • recvcounts: Array de enteros, donde la entrada j especifica el número de elementos a recibir del vecino j.
  • rdispls: Array de enteros, donde la entrada j especifica el desplazamiento (en bytes, compensación desde recvbuf) al cual deben escribirse los datos del vecino j.
  • recvtypes: Array de tipos de datos, donde la entrada j especifica el tipo de datos a utilizar al recibir datos del vecino j.
  • comm: Comunicador sobre el cual se intercambiarán los datos.
  • info: Información (handle, solo persistente).

PARÁMETROS DE SALIDA

  • recvbuf: Dirección del búfer de recepción.
  • request: Solicitud (handle, solo no bloqueante).
  • ierror: Solo Fortran: Estado de error.

DESCRIPCIÓN

MPI_Neighbor_alltoallw es una operación colectiva generalizada en la que todos los procesos envían datos a y reciben datos de todos los vecinos. Añade flexibilidad a MPI_Neighbor_alltoallv al permitir al usuario especificar el tipo de datos de bloques de datos individuales (además del desplazamiento y la cuenta de elementos). Su operación puede pensarse de la siguiente manera, donde cada proceso realiza 2n (n siendo el número de vecinos en la topología del comunicador comm) comunicaciones punto a punto independientes. Los vecinos y la disposición del búfer se determinan por la topología de comm.

MPI_Cart_get(comm, maxdims, dims, periods, coords);
for (dim = 0, i = 0 ; dim < dims ; ++dim) {
    MPI_Cart_shift(comm, dim, 1, &r0, &r1);
    MPI_Isend(sendbuf + sdispls[i]  * extent(sendtype),
              sendcount, sendtypes[i], r0, ..., comm, ...);
    MPI_Irecv(recvbuf + rdispls[i] * extent(recvtype),
              recvcount, recvtypes[i], r0, ..., comm, ...);
    ++i;
    MPI_Isend(sendbuf + sdispls[i] * extent(sendtype),
              sendcount, sendtypes[i], r1, ..., comm, &req[i]);
    MPI_Irecv(recvbuf + rdispls[i] * extent(recvtype),
              recvcount, recvtypes[i], r1, ..., comm, ...);
    ++i;
}
MPI_Wait_all (...);
MPI_Comm_size(comm, &n);
for (i = 0, i < n; i++)
  MPI_Send(sendbuf + sdispls[i], sendcounts[i],
       sendtypes[i], i, ..., comm);
for (i = 0, i < n; i++)
  MPI_Recv(recvbuf + rdispls[i], recvcounts[i],
       recvtypes[i], i, ..., comm);

El proceso j envía el k-ésimo bloque de su sendbuf local al vecino k, el cual coloca los datos en el j-ésimo bloque de su recvbuf local.

Cuando un par de procesos intercambia datos, cada uno puede pasar argumentos de recuento y tipo de datos diferentes, siempre que el remitente especifique la misma cantidad de datos a enviar (en bytes) que la que el receptor espera recibir.

Tenga en cuenta que el proceso i puede enviar una cantidad de datos diferente al proceso j de la que recibe del proceso j. Además, un proceso puede enviar cantidades y tipos de datos completamente diferentes a procesos diferentes en el comunicador.

NOTAS

La opción MPI_IN_PLACE para sendbuf no tiene sentido para esta operación

La especificación de recuentos, tipos y desplazamientos no debe hacer que ninguna ubicación se escriba más de una vez.

Todos los argumentos en todos los procesos son significativos. El argumento comm, en particular, debe describir el mismo comunicador en todos los procesos.

Los desplazamientos de sdispls y rdispls se miden en bytes. Compare esto con MPI_Neighbor_alltoallv, donde estos desplazamientos se miden en unidades de sendtype y recvtype, respectivamente.

ERRORES

Casi todas las rutinas MPI devuelven un valor de error; las rutinas C como resultado de la devolución

SINTAXIS

La función y las rutinas de Fortran en el último argumento.

PARAMETROS DE ENTRADA

Antes de que se devuelva el valor de error, se llama al controlador de errores MPI actual asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo). Si no hay ningún objeto de comunicación asociado con la llamada MPI, la llamada se considera adjunta a MPI_COMM_SELF y llamará al controlador de errores MPI asociado. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se utiliza exclusivamente el Modelo de Sesiones) el error eleva el controlador de errores inicial. El controlador de errores inicial se puede cambiar llamando a MPI_Comm_set_errhandler en MPI_COMM_SELF cuando se utiliza el modelo World, o al argumento de línea de comandos mpi_initial_errhandler de mpiexec o a la clave de información de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no se ha configurado ningún otro controlador de errores apropiado, se llamará al controlador de errores MPI_ERRORS_RETURN para las funciones de E/S de MPI y al controlador de errores MPI_ERRORS_ABORT para todas las demás funciones de MPI.

PARAMETROS DE SALIDA

Open MPI incluye tres controladores de errores predefinidos que se pueden utilizar:

  • MPI_ERRORS_ARE_FATAL Provoca que el programa aborte todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT Un controlador de errores que se puede invocar en un comunicador, ventana, archivo o sesión. Cuando se llama en un comunicador, actúa como si se hubiera llamado a MPI_Abort en ese comunicador. Si se llama en una ventana o archivo, actúa como si se hubiera llamado a MPI_Abort en un comunicador que contiene el grupo de procesos de la ventana o archivo correspondiente. Si se llama en una sesión, solo aborta el proceso local.
  • MPI_ERRORS_RETURN Devuelve un código de error a la aplicación.

Las aplicaciones MPI también pueden implementar sus propios controladores de errores llamando a:

  • MPI_Comm_create_errhandler y luego MPI_Comm_set_errhandler
  • MPI_File_create_errhandler y luego MPI_File_set_errhandler
  • MPI_Session_create_errhandler y luego MPI_Session_set_errhandler o en MPI_Session_init
  • MPI_Win_create_errhandler y luego MPI_Win_set_errhandler

Tenga en cuenta que MPI no garantiza que un programa MPI pueda continuar después de un error.
