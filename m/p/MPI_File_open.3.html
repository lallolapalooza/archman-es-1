MPI_File_open(3)

Paquete: openmpi

Licencias: BSD-3-Clause AND LicenseRef-MPICH

MPI_File_open(3) Open MPI MPI_File_open(3)

MPI_File_open abre un archivo (colaborativamente).

Sintaxis

Sintaxis C

#include <mpi.h>
int MPI_File_open(MPI_Comm comm, const char *filename,
     int amode, MPI_Info info,
     MPI_File *fh)

Sintaxis Fortran

USE MPI
! o la antigua forma: INCLUDE 'mpif.h'
MPI_FILE_OPEN(COMM, FILENAME, AMODE, INFO, FH, IERROR)
     CHARACTER*(*)   FILENAME
     INTEGER COMM, AMODE, INFO, FH, IERROR

Sintaxis Fortran 2008

USE mpi_f08
MPI_File_open(comm, filename, amode, info, fh, ierror)
     TYPE(MPI_Comm), INTENT(IN) :: comm
     CHARACTER(LEN=*), INTENT(IN) :: filename
     INTEGER, INTENT(IN) :: amode
     TYPE(MPI_Info), INTENT(IN) :: info
     TYPE(MPI_File), INTENT(OUT) :: fh
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

Parámetros de entrada

  • comm: Comunicador (handle).
  • filename: Nombre del archivo a abrir (cadena).
  • amode: Modo de acceso al archivo (entero).
  • info: Objeto de información (handle).

Parámetros de salida

  • fh: Manejo de archivo nuevo (handle).
  • ierror: Solo en Fortran: Estado de error (entero).

Descripción

MPI_File_open abre el archivo identificado por el nombre de archivo filename en todos los procesos del grupo de comunicadores comm. MPI_File_open es una rutina colaborativa; todos los procesos deben proporcionar el mismo valor para amode, y todos los procesos deben proporcionar nombres de archivos que refieran al mismo archivo, que sean idénticos textualmente (nota: los plugins de I/O de Open MPI pueden tener restricciones sobre los caracteres que pueden usarse en nombres de archivos. Por ejemplo, el plugin ROMIO puede prohibir el carácter colón (":") en un nombre de archivo). Un proceso puede abrir un archivo independientemente de otros procesos usando el comunicador MPI_COMM_SELF>. El manejo de archivo devuelto, fh, puede usarse posteriormente para acceder al archivo hasta que se cierre con MPI_File_close. Antes de llamar a MPI_Finalize, el usuario debe cerrar (con MPI_File_close) todos los archivos que fueron abiertos con MPI_File_open. Nota: el comunicador comm no se ve afectado por MPI_File_open y sigue siendo usable en todas las rutinas MPI. Además, el uso de comm no interfiere con el comportamiento de I/O.

Inicialmente, todos los procesos ven el archivo como un flujo de bytes lineal; es decir, etype y filetype son ambos MPI_BYTE. El modo de vista del archivo puede cambiarse mediante la rutina MPI_File_set_view.

Los siguientes modos de acceso son soportados (específicos en amode, en un bit-vector o en uno de los siguientes constantes enteras):

  • MPI_MODE_APPEND
  • MPI_MODE_CREATE: Crea el archivo si no existe.
  • MPI_MODE_DELETE_ON_CLOSE
  • MPI_MODE_EXCL: Error al crear un archivo que ya existe.
  • MPI_MODE_RDONLY: Solo lectura.
  • MPI_MODE_RDWR: Lectura y escritura.
  • MPI_MODE_SEQUENTIAL
  • MPI__MODE_WRONLY: Escritura solo.
  • MPI_MODE_UNIQUE_OPEN

Los modos MPI_MODE_RDONLY, MPI_MODE_RDWR, MPI_MODE_WRONLY y MPI_MODE_CREATE tienen el mismo sentido que sus correspondientes POSIX. No es correcto especificar MPI_MODE_CREATE junto con MPI_MODE_RDONLY. Las Errores relacionadas con el modo de acceso se generan en la clase MPI_ERR_AMODE.

En clústeres de un solo nodo, los archivos se abren por defecto usando semánticas de consistencia de archivos no atómicas. Las semánticas más estrictas de consistencia atómica, necesarias para la atomicidad de accesos sobrelapedados, son el por defecto cuando los procesadores en un grupo de comunicadores residen en más de un nodo. Este ajuste puede cambiarse usando MPI_File_set_atomicity.

La interfaz de MPI_File_open permite al usuario pasar información mediante el argumento info. Puede establecer este valor a MPI_INFO_NULL. Véase la sección HINTS para una lista de consejos que pueden establecerse.

Consejos

Los siguientes consejos pueden usarse como valores para el argumento info.

CONSEJOS CONFIGURABLES

  • MPI_INFO_NULL
  • shared_file_timeout: Tiempo (en segundos) a esperar antes de salir con MPI_ERR_TIMEDOUT para acceder al puntero de archivo compartido.
  • rwlock_timeout: Tiempo (en segundos) a esperar antes de salir con MPI_ERR_TIMEDOUT para obtener un bloque de lectura o escritura en un bloque de archivo UNIX contínuo.
  • noncoll_read_bufsize: Tamaño máximo del buffer utilizado por I/O MPI para satisfacer múltiples solicitudes de lectura no contínuas en rutinas de acceso de datos no colaborativas.

    NOTA:

Un tamaño de buffer menor que la distancia (en bytes) entre el primer byte y el último byte de la solicitud de acceso a un archivo UNIX causa que I/O MPI iterará y realizará múltiples llamadas read() o write() en UNIX. Si la solicitud incluye múltiples fragmentos no contínuos de datos y el tamaño del buffer es mayor que el tamaño de esos fragmentos, entonces la llamada read() o write() (haciéndose en el nivel de I/O MPI) accederá a datos no solicitados por este proceso para reducir el número total de llamadas write() realizadas. Si este comportamiento no es deseable, debes reducir este tamaño de buffer a igual que el tamaño de los fragmentos contínuos dentro de la solicitud agregada.
  • noncoll_write_bufsize: Tamaño máximo del buffer utilizado por I/O MPI para satisfacer múltiples solicitudes de escritura no contínuas en rutinas de acceso de datos no colaborativas.

    Ver la nota en noncoll_read_bufsize.

  • coll_read_bufsize: Tamaño máximo del buffer utilizado por I/O MPI para satisfacer múltiples solicitudes de lectura no contínuas en rutinas de acceso de datos colaborativas.

    Ver la nota en noncoll_read_bufsize.

  • coll_write_bufsize: Tamaño máximo del buffer utilizado por I/O MPI para satisfacer múltiples solicitudes de escritura no contínuas en rutinas de acceso de datos colaborativas.

    Ver la nota en noncoll_read_bufsize.

  • mpiio_concurrency: (boolean) controla si las rutinas de I/O no bloqueadas pueden vincular un extra hilo a un LWP. .sp
  • mpiio_coll_contiguous: (boolean) controla si los siguientes accesos colaborativos a un archivo solicitarán regiones contiguas del archivo.

CONSEJOS NO CONFIGURABLES

•
filename: Accede a este consejo para obtener el nombre del archivo.

ERRORES

Más de una rutina MPI devuelve un valor de error; en las rutinas C, el valor de error es el resultado de la función, y en las rutinas Fortran, el último argumento es el valor de error.

Antes de que el valor de error sea devuelto, se llama a la función de error handler asociada al objeto de comunicación (por ejemplo, comunicador, ventana, archivo) actual. Si no hay objeto de comunicación asociado a la llamada MPI, se considera que la llamada está asociada a MPI_COMM_SELF y se llama a la función de error handler asociada a MPI_COMM_SELF. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize o cuando se utilice el modelo de Sesiones exclusivamente), se eleva el error inicial. El handler de error inicial puede cambiarse llamando a MPI_Comm_set_errhandler sobre MPI_COMM_SELF cuando se utilice el modelo del Mundo, o al argumento mpi_initial_errhandler de mpiexec o a la clave info de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no hay otro handler de error adecuado, se llama el handler de error MPI_ERRORS_RETURN para las funciones de I/O y el handler de error MPI_ERRORS_ABORT para todas las otras funciones MPI.

Open MPI incluye tres handlers predeterminados de errores que pueden usarse:

  • MPI_ERRORS_ARE_FATAL Caused the program to abort all connected MP

SINTAXIS

La siguiente es la sintaxis para las funciones mencionadas:

  • MPI_ERRORS_ABORT - Un manejador de errores que se puede invocar en un comunicador, ventana, archivo o sesión. Cuando se llama en un comunicador, actúa como si se hubiera llamado MPI_Abort en ese comunicador. Si se llama en una ventana o archivo, actúa como si se hubiera llamado MPI_Abort en un comunicador que contiene los procesos en la ventana o archivo correspondiente. Si se llama en una sesión, aborta solo el proceso local.
  • MPI_ERRORS_RETURN - Devuelve un código de error a la aplicación.

Los programas MPI también pueden implementar sus propios manejadores de errores llamando:

  • MPI_Comm_create_errhandler seguido de MPI_Comm_set_errhandler
  • MPI_File_create_errhandler seguido de MPI_File_set_errhandler
  • MPI_Session_create_errhandler seguido de MPI_Session_set_errhandler o en MPI_Session_init
  • MPI_Win_create_errhandler seguido de MPI_Win_set_errhandler

Nota: MPI no garantiza que un programa MPI pueda seguir ejecutándose después de un error.
