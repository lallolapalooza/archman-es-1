PARAMETROS DE ENTRADA

  • sendbuf: Dirección de inicio del búfer de envío.
  • sendcounts: Array de enteros, donde la entrada i especifica el número de elementos a enviar al vecino i.
  • sdispls: Array de enteros, donde la entrada i especifica el desplazamiento (desfase desde sendbuf, en unidades de sendtype) desde donde enviar los datos al vecino i.
  • sendtype: Tipo de datos de los elementos del búfer de envío.
  • recvcounts: Array de enteros, donde la entrada j especifica el número de elementos a recibir del vecino j.
  • rdispls: Array de enteros, donde la entrada j especifica el desplazamiento (desfase desde recvbuf, en unidades de recvtype) donde los datos del vecino j deben ser escritos.
  • recvtype: Tipo de datos de los elementos del búfer de recepción.
  • comm: Comunicador sobre el cual intercambiar los datos.
  • info: Info (manejador, solo persistente).

PARAMETROS DE SALIDA

  • recvbuf: Dirección del búfer de recepción.
  • request: Solicitud (manejador, solo no bloqueante).
  • ierror: Solo Fortran: Estado de error.

DESCRIPCION

MPI_Neighbor_alltoallv es una operación colectiva generalizada en la cual todos los procesos envían datos a y reciben datos de todos los vecinos. Añade flexibilidad a MPI_Neighbor_alltoall al permitir al usuario especificar datos para enviar y recibir de forma vectorial (mediante un desplazamiento y un recuento de elementos). La operación de esta rutina se puede pensar de la siguiente manera, donde cada proceso realiza 2n (siendo n el número de vecinos en la topología del comunicador comm) comunicaciones punto a punto independientes. Los vecinos y la disposición del búfer se determinan por la topología de comm.

MPI_Cart_get(comm, maxdims, dims, periods, coords);
for (dim = 0, i = 0 ; dim < dims ; ++dim) {
    MPI_Cart_shift(comm, dim, 1, &r0, &r1);
    MPI_Isend(sendbuf + sdispls[i]  * extent(sendtype),
              sendcount, sendtype, r0, ..., comm, ...);
    MPI_Irecv(recvbuf + rdispls[i] * extent(recvtype),
              recvcount, recvtype, r0, ..., comm, ...);
    ++i;
    MPI_Isend(sendbuf + sdispls[i] * extent(sendtype),
              sendcount, sendtype, r1, ..., comm, &req[i]);
    MPI_Irecv(recvbuf + rdispls[i] * extent(recvtype),
              recvcount, recvtype, r1, ..., comm, ...);
    ++i;
}

El proceso j envía el k-ésimo bloque de su sendbuf local al vecino k, el cual coloca los datos en el j-ésimo bloque de su recvbuf local.

Cuando un par de procesos intercambia datos, cada uno puede pasar diferentes recuentos de elementos y argumentos de tipo de datos siempre que el remitente especifique la misma cantidad de datos a enviar (en bytes) que el receptor espera recibir.

Tenga en cuenta que el proceso i puede enviar una cantidad diferente de datos al proceso j de la que recibe del proceso j. Además, un proceso puede enviar cantidades de datos completamente diferentes a diferentes procesos en el comunicador.

ORDEN DE VECINOS

Para una topología de grafo distribuido, creada con MPI_Dist_graph_create, la secuencia de vecinos en los búferes de envío y recepción en cada proceso se define como la secuencia devuelta por MPI_Dist_graph_neighbors para destinos y orígenes, respectivamente. Para una topología de grafo general, creada con MPI_Graph_create, el orden de los vecinos en los búferes de envío y recepción se define como la secuencia de vecinos devuelta por MPI_Graph_neighbors. Tenga en cuenta que las topologías de grafo generales deberían ser reemplazadas generalmente por las topologías de grafo distribuidas.

Para una topología cartesiana, creada con MPI_Cart_create, la secuencia de vecinos en los búferes de envío y recepción en cada proceso se define por el orden de las dimensiones, primero el vecino en la dirección negativa y luego en la dirección positiva con desplazamiento 1. Los números de orígenes y destinos en las rutinas de comunicación son 2*ndims, donde ndims se define en MPI_Cart_create. Si un vecino no existe, es decir, en el borde de una topología cartesiana en el caso de una dimensión de red virtual no periódica (es decir, periods[…]==false), entonces este vecino se define como MPI_PROC_NULL.

Si un vecino en cualquiera de las funciones es MPI_PROC_NULL, entonces la comunicación colectiva de vecindad se comporta como una comunicación punto a punto con MPI_PROC_NULL en esa dirección. Es decir, el búfer sigue siendo parte de la secuencia de vecinos pero no se comunica ni se actualiza.

EQUIVALENCIA DE BÚFERES

En todas las funciones de comunicación de vecindad, la cantidad total de datos enviados por un proceso debe ser igual a la cantidad total de datos recibidos por ese mismo proceso.

NOTAS

Las versiones _init de estas rutinas preparan una operación colectiva persistente. El argumento info puede usarse para especificar parámetros de optimización de rendimiento. La operación se inicia con la llamada a la rutina _init y se completa mediante una o más llamadas a MPI_Start, MPI_Startall, o al mismo tiempo con una llamada a MPI_Wait, MPI_Test, MPI_Waitall, MPI_Waitany, MPI_Waitsome, o MPI_Testall, MPI_Testany, MPI_Testsome.

Los detalles de la asignación de memoria para los argumentos de desplazamiento y recuento no están especificados. Sin embargo, las rutinas deben ser capaces de manejar búferes de envío y recepción que residen en diferentes ubicaciones de memoria, siempre que las direcciones y tipos de datos sean correctos.

EJEMPLO DE USO

El siguiente código demuestra el uso de MPI_Ineighbor_alltoallv en una topología de anillo.

#include <mpi.h>
#include <stdio.h>
#include <stdlib.h>

int main(int argc, char **argv) {
    int rank, size;
    MPI_Comm comm_cart;
    MPI_Request request;
    int dims[1] = {-1}; // Anillo 1D
    int periods[1] = {1};
    int coords[1];
    int left, right;
    int *sendbuf, *recvbuf;
    int sendcounts[2], recvcounts[2];
    int sdispls[2], rdispls[2];
    int data_size = 10;

    MPI_Init(&argc, &argv);
    MPI_Comm_rank(MPI_COMM_WORLD, &rank);
    MPI_Comm_size(MPI_COMM_WORLD, &size);

    // Crear topología de anillo
    MPI_Cart_create(MPI_COMM_WORLD, 1, dims, periods, 1, &comm_cart);
    MPI_Cart_coords(comm_cart, rank, 1, coords);
    MPI_Cart_shift(comm_cart, 0, 1, &left, &right); // Obtener vecinos

    // Inicializar búferes
    sendbuf = (int *)malloc(data_size * 2 * sizeof(int));
    recvbuf = (int *)malloc(data_size * 2 * sizeof(int));

    // Llenar sendbuf (ejemplo: enviar 5 elementos a la izquierda, 5 a la derecha)
    for (int i = 0; i < data_size; ++i) {
        sendbuf[i] = rank * 100 + i; // Datos para el vecino izquierdo
        sendbuf[i + data_size] = rank * 100 + i + 50; // Datos para el vecino derecho
    }

    // Definir recuentos y desplazamientos
    sendcounts[0] = data_size; // Enviar data_size elementos al primer vecino
    sendcounts[1] = data_size; // Enviar data_size elementos al segundo vecino
    sdispls[0] = 0;            // Desplazamiento para el primer vecino
    sdispls[1] = data_size;    // Desplazamiento para el segundo vecino

    recvcounts[0] = data_size; // Recibir data_size elementos del primer vecino
    recvcounts[1] = data_size; // Recibir data_size elementos del segundo vecino
    rdispls[0] = 0;            // Desplazamiento para el primer vecino
    rdispls[1] = data_size;    // Desplazamiento para el segundo vecino

    // Realizar el intercambio no bloqueante
    MPI_Ineighbor_alltoallv(sendbuf, sendcounts, sdispls, MPI_INT,
                           recvbuf, recvcounts, rdispls, MPI_INT,
                           comm_cart, &request);

    // Esperar a que la operación se complete
    MPI_Wait(&request, MPI_STATUS_IGNORE);

    // Verificar los datos recibidos (ejemplo)
    // El vecino izquierdo (left) debería haber enviado datos a recvbuf[0:data_size-1]
    // El vecino derecho (right) debería haber enviado datos a recvbuf[data_size:2*data_size-1]
    printf("Rank %d: Recvbuf[0] = %d, Recvbuf[%d] = %d\n", rank, recvbuf[0], data_size, recvbuf[data_size]);

    free(sendbuf);
    free(recvbuf);
    MPI_Comm_free(&comm_cart);
    MPI_Finalize();
    return 0;
}

Este ejemplo asume una topología de anillo simple. Para topologías más complejas, la definición de los recuentos y desplazamientos deberá ajustarse en consecuencia.
