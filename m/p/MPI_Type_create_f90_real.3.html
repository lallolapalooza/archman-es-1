MPI_Type_create_f90_real(3)

Paquete: openmpi

Licencias: BSD-3-Clause AND LicenseRef-MPICH

MPI_Type_create_f90_real(3) Open MPI MPI_Type_create_f90_real(3) 
MPI_Type_create_f90_real - Devuelve un tipo de datos real acotado

Sintaxis

Sintaxis C

#include <mpi.h>
int MPI_Type_create_f90_real(int p, int r, MPI_Datatype *newtype)

Sintaxis Fortran

USE MPI
! o la forma antigua: INCLUDE 'mpif.h'
MPI_TYPE_CREATE_F90_REAL (P, R, NEWTYPE, IERROR)
     INTEGER P, R, NEWTYPE, IERROR

Sintaxis Fortran 2008

USE mpi_f08
MPI_Type_create_f90_real(p, r, newtype, ierror)
     INTEGER, INTENT(IN) :: p, r
     TYPE(MPI_Datatype), INTENT(OUT) :: newtype
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

Parámetros de entrada

  • p: Precisión, en dígitos decimales (entero).
  • r: Rango de exponentes (entero).

Parámetros de salida

  • newtype: Tipo de datos nuevo (manejador).
  • ierror: Solo Fortran: Código de error (entero).

Descripción

Esta función permite declarar tipos de datos MPI parametrizados con el parámetro KIND. Los argumentos se interpretan de manera similar a la función F90 SELECTED_REAL_KIND. Los parámetros p y r deben ser enteros escalares. El parámetro p representa la precisión requerida en dígitos decimales. El parámetro r indica el rango de exponentes deseado: el tipo de datos devuelto tendrá al menos un exponente entre +r y -r (inclusivo).

O bien p o r, pero no ambos, pueden omitirse en llamadas a SELECTED_REAL_KIND. De manera similar, un argumento a MPI_Type_create_f90_real puede ser MPI_UNDEFINED.

Notas

Se considera erróneo proporcionar valores para p y r no soportados por el compilador.

La función Fortran SELECTED_REAL_KIND mapea una gran cantidad de (p, r) a un número menor de KIND parameters soportados por el compilador. Los KIND parameters no son especificados por el lenguaje y no son portables. Desde el punto de vista del lenguaje, variables de la misma base de tipo y KIND parameters equivalentes, incluso si sus KIND parameters se generaron por diferentes (p, r) a SELECTED_REAL_KIND, son equivalentes. Sin embargo, para facilitar la interoperabilidad en entornos heterogéneos, la equivalencia es más estricta para los tipos de datos devueltos por MPI_Type_create_f90_real. Dos tipos de datos MPI generados por esta función coincidirán si y solo si tienen valores idénticos para ambos p y r.

La interacción entre los tipos de datos devueltos por esta función y la representación externa32 - utilizada por MPI_Pack_external, MPI_Unpack_external y muchas funciones MPI_File - es sutil. La representación externa32 de los tipos de datos devueltos se describe a continuación.

if (p > 33) and/or (r > 4931):
        external32 size = n/a (undefined)
else if (p > 15) and/or (r > 307):
        external32 size = 16
else if (p > 6) and/or (r > 37):
        external32 size = 8
else:
        external32 size = 4

Si la representación externa32 de un tipo de datos es undefined, así lo son los resultados de usar ese tipo de datos en operaciones que requieren la representación externa32. Deben tomarse precauciones para no usar tipos de datos incompatibles indirectamente, por ejemplo, como parte de otro tipo de datos o a través de un tipo de datos duplicado, en estas funciones.

Si una variable se declara especificando un valor de KIND no por defecto que no se obtuvo con SELECTED_REAL_KIND (es decir, p y/o r son desconocidos), la única forma de obtener un tipo de datos MPI que coincida es usar las funciones MPI_Sizeof y MPI_Type_match_size.

Errores

La mayoría de las rutinas MPI devuelven un valor de error; los rutinarios C como valor de retorno de la función y las rutinarias Fortran en el último argumento.

Antes de que se devuelva el valor de error, se llama al manejador de errores asociado con el objeto de comunicación (por ejemplo, communicator, window, file) actual. Si no hay objeto de comunicación asociado con la llamada MPI, se considera que la llamada está asociada a MPI_COMM_SELF y llamará al manejador de errores asociado. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize o cuando se usa el modelo de Sesiones exclusivamente), el error eleva el manejador de errores inicial. El manejador de errores inicial puede ser cambiado llamando a MPI_Comm_set_errhandler sobre MPI_COMM_SELF cuando se usa el modelo del Mundo, o a través del argumento CLI mpi_initial_errhandler de mpiexec o la clave de información de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no hay otro manejador de errores adecuado establecido, se llama al manejador de errores MPI_ERRORS_RETURN para funciones de I/O MPI y al manejador de errores MPI_ERRORS_ABORT para todas las demás funciones MPI.

Open MPI incluye tres manejadores predeterminados de errores que pueden ser utilizados:

  • MPI_ERRORS_ARE_FATAL Provoca que el programa termine todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT Un manejador de errores que puede ser invocado en un communicator, window, file o sesión. Cuando se llama en un communicator, actúa como si se hubiera llamado MPI_Abort en ese communicator. Si se llama en un window o file, actúa como si se hubiera llamado MPI_Abort en un communicator que contiene el grupo de procesos en la ventana o archivo correspondiente. Si se llama en una sesión, se detiene solo el proceso local.
  • MPI_ERRORS_RETURN Devuelve un código de error a la aplicación.

Las aplicaciones MPI también pueden implementar sus propios manejadores de errores llamando:

  • MPI_Comm_create_errhandler luego MPI_Comm_set_errhandler
  • MPI_File_create_errhandler luego MPI_File_set_errhandler
  • MPI_Session_create_errhandler luego MPI_Session_set_errhandler o en MPI_Session_init
  • MPI_Win_create_errhandler luego MPI_Win_set_errhandler

Nota: Los tipos de datos MPI no garantizan que un programa MPI pueda continuar tras un error.

Ver la página del manual de MPI para una lista completa de códigos de error MPI.

Ver la sección de manejo de errores del estándar MPI-3.1 para más información.
