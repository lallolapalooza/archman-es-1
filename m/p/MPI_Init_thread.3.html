MPI_INIT_THREAD(3) Open MPI MPI_INIT_THREAD(3)

MPI_Init_thread — Inicializa el modelo de mundo MPI

SINTAXIS

Sintaxis C

#include <mpi.h>
int MPI_Init_thread(int *argc, char ***argv,
     int required, int *provided)

Sintaxis Fortran

USE MPI
! o la forma antigua: INCLUDE 'mpif.h'
MPI_INIT_THREAD(REQUIRED, PROVIDED, IERROR)
     INTEGER REQUIRED, PROVIDED, IERROR

Sintaxis Fortran 2008

USE mpi_f08
MPI_Init_thread(required, provided, ierror)
     INTEGER, INTENT(IN) :: required
     INTEGER, INTENT(OUT) :: provided
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARÁMETROS DE ENTRADA

  • argc: Solo C: Puntero al número de argumentos.
  • argv: Solo C: Vector de argumentos.
  • required: Nivel de soporte de hilos deseado (entero).

PARÁMETROS DE SALIDA

  • provided: Nivel de soporte de hilos disponible (entero).
  • ierror: Solo Fortran: Estado de error (entero).

DESCRIPCIÓN

Esta rutina, o MPI_Init, inicializa el modelo de mundo MPI. Cualquiera de estas rutinas debe ser llamada antes de que las rutinas de comunicación MPI sean llamadas dentro del modelo de mundo MPI. El modelo de mundo MPI puede ser inicializado como máximo una vez en la vida de un proceso MPI. Esto es diferente del modelo de sesión MPI, que puede ser inicializado y finalizado múltiples veces en un proceso MPI. Ver MPI_Session_init y MPI_Session_finalize.

Ver MPI-5.0:11.4.1 para una lista de la funcionalidad MPI que está disponible (por ejemplo, incluso cuando el modelo de mundo MPI aún no se ha inicializado o ya se ha finalizado).

El modelo de mundo MPI puede ser inicializado como máximo una vez; las llamadas subsiguientes a MPI_Init o MPI_Init_thread son erróneas.

Alternativamente, en lugar del modelo de mundo MPI, las aplicaciones MPI pueden usar el modelo de sesiones; ver MPI_Session_init.

Al regresar, el nivel de soporte de hilos disponible para el programa se establece en provided. En Open MPI, el valor depende de cómo se configuró y compiló la biblioteca. Tenga en cuenta que no hay garantía de que provided sea mayor o igual que required.

Open MPI acepta los argumentos C argc y argv para main, pero no los modifica, interpreta ni distribuye:

#include <mpi.h>
int main(int argv, char *argv[]) {
    int provided;
    MPI_Init_thread(&argc, &argv, MPI_THREAD_MULTIPLE, &provided);
    /* ...cuerpo del programa MPI principal... */
    MPI_Finalize();
    return 0;
}

MPI_Init_thread tiene un mecanismo directo y uno indirecto para solicitar un nivel específico de soporte de hilos. MPI_Init solo tiene un mecanismo indirecto para solicitar un nivel específico de soporte de hilos.

Solicitud directa de nivel de hilo

MPI_Init_thread tiene el parámetro required, que puede establecerse en cualquiera de las siguientes constantes (desde mpi.h):

  • MPI_THREAD_SINGLE: Indicando que solo un hilo se ejecutará.
  • MPI_THREAD_FUNNELED: Indicando que si el proceso es multihilo, solo el hilo que llamó a MPI_Init_thread realizará llamadas MPI.
  • MPI_THREAD_SERIALIZED: Indicando que si el proceso es multihilo, solo un hilo realizará llamadas a la biblioteca MPI a la vez.
  • MPI_THREAD_MULTIPLE: Indicando que si el proceso es multihilo, múltiples hilos pueden llamar a MPI a la vez sin restricciones.

Los valores de estas constantes cumplen las siguientes relaciones:


\begin{eqnarray}

MPI\_THREAD\_SINGLE & < & MPI\_THREAD\_FUNNELED \\
MPI\_THREAD\_FUNNELED & < & MPI\_THREAD\_SERIALIZED \\
MPI\_THREAD\_SERIALIZED & < & MPI\_THREAD\_MULTIPLE \\ \end{eqnarray}

Solicitud indirecta de nivel de hilo

Tanto MPI_Init_thread como MPI_Init admiten un método indirecto para indicar el nivel de hilo requerido: estableciendo la variable de entorno OMPI_MPI_THREAD_LEVEL:

  • Si la variable de entorno OMPI_MPI_THREAD_LEVEL se establece en el momento en que se invoca MPI_Init, se comporta como si se hubiera invocado MPI_Init_thread con el valor de constante MPI_THREAD_* correspondiente pasado a través del parámetro required.
  • Si la variable de entorno OMPI_MPI_THREAD_LEVEL se establece en el momento en que se invoca MPI_Init_thread, el valor de constante MPI_THREAD_* correspondiente al valor de la variable de entorno anula el valor pasado a través del parámetro required.

La variable de entorno OMPI_MPI_THREAD_LEVEL puede establecerse en cualquiera de los siguientes valores.

Valor que usa Open MPI Valores permitidos (sin distinción entre mayúsculas y minúsculas)
MPI_THREAD_SINGLE MPI_THREAD_SINGLE, SINGLE, 0
MPI_THREAD_FUNNELED MPI_THREAD_FUNNELED, FUNNELED, 1
MPI_THREAD_SERIALIZED MPI_THREAD_SERIALIZED, SERIALIZED, 2
MPI_THREAD_MULTIPLE MPI_THREAD_MULTIPLE, MULTIPLE, 3

NOTA:

En Open MPI v5.0.8 y anteriores, solo los valores enteros 0 a 3 eran valores aceptables para la variable de entorno OMPI_MPI_THREAD_LEVEL.

A partir de Open MPI v5.0.9, la comunidad de Open MPI recomienda usar una de las variantes de nombre de cadena.

NOTAS

La versión Fortran no tiene disposiciones para argc y argv y solo toma REQUIRED, PROVIDED, e IERROR.

Es responsabilidad del llamante verificar el valor de provided, ya que puede ser menor de lo solicitado en required.

El Estándar MPI no especifica qué puede hacer un programa que utiliza el modelo de mundo MPI antes de invocar MPI_Init o MPI_Init_thread o después de invocar MPI_Finalize. En la implementación de Open MPI, debe hacer lo menos posible. En particular, evite cualquier cosa que cambie el estado externo del programa, como abrir archivos, leer la entrada estándar o escribir en la salida estándar.

Soporte MPI_THREAD_MULTIPLE

El soporte de MPI_THREAD_MULTIPLE se incluye si el entorno en el que se compiló Open MPI admite hilos. Puede verificar la salida de ompi_info(1) para ver si Open MPI tiene soporte para MPI_THREAD_MULTIPLE:

shell$ ompi_info | grep "Thread support"
          Thread support: posix (MPI_THREAD_MULTIPLE: yes, OPAL support: yes, OMPI progress: no, Event lib: yes)
shell$

MPI_Init_thread(3) - Open MPI 5.0.9 - Arch Linux

NOMBRE

MPI_Init_thread - Inicializa el entorno MPI, solicitando un nivel de concurrencia determinado.

SINTAXIS

C

#include <mpi.h>
int MPI_Init_thread(int *argc, char ***argv, int *required, int *provided);

Fortran

CALL MPI_INIT_THREAD(REQUIRED, PROVIDED, IERROR)
CALL MPI_INIT_THREAD_THREAD(REQUIRED, PROVIDED, THREAD_REQ, THREAD_PROV, IERROR)

PARÁMETROS DE ENTRADA

argc
Puntero al número de argumentos de línea de comandos.
argv
Puntero a la matriz de argumentos de línea de comandos.
required
Nivel de concurrencia solicitado. Los valores posibles son:
  • MPI_THREAD_SINGLE: Solo un hilo ejecutará código MPI.
  • MPI_THREAD_FUNNELED: Solo el hilo que llamó a MPI_Init_thread ejecutará código MPI.
  • MPI_THREAD_SERIALIZED: Varios hilos pueden ejecutar código MPI, pero solo un hilo puede ejecutar código MPI a la vez.
  • MPI_THREAD_MULTIPLE: Varios hilos pueden ejecutar código MPI en cualquier momento.

PARÁMETROS DE SALIDA

provided
Nivel de concurrencia proporcionado por la implementación de MPI. Este valor será uno de los valores de required o uno menor.
IERROR
Variable de tipo entero que contiene el código de retorno del error. Puede ser MPI_SUCCESS o un código de error.

DESCRIPCIÓN

La rutina MPI_Init_thread inicializa el entorno MPI y el soporte para hilos. El argumento required especifica el nivel de concurrencia solicitado por la aplicación. El argumento provided indica el nivel de concurrencia real proporcionado por la implementación de MPI. Si required es MPI_THREAD_MULTIPLE, la aplicación puede usar múltiples hilos para ejecutar código MPI. Si required es MPI_THREAD_SINGLE, solo un hilo puede ejecutar código MPI. Si required es MPI_THREAD_FUNNELED, solo el hilo principal puede ejecutar código MPI. Si required es MPI_THREAD_SERIALIZED, varios hilos pueden ejecutar código MPI, pero solo uno a la vez.

La rutina MPI_Init_thread también procesa los argumentos de línea de comandos y los pasa a la implementación de MPI. Los argumentos argc y argv se utilizan para pasar estos argumentos.

NOTAS

La porción MPI_THREAD_MULTIPLE: sí de la salida anterior indica que Open MPI se compiló con soporte para MPI_THREAD_MULTIPLE.

Tenga en cuenta que existe una pequeña penalización de rendimiento por usar el soporte MPI_THREAD_MULTIPLE; las latencias para mensajes cortos serán mayores en comparación con el uso de MPI_THREAD_SINGLE, por ejemplo.

ERRORES

Casi todas las rutinas MPI devuelven un valor de error; las rutinas C como resultado de retorno de la función y las rutinas Fortran en el último argumento.

Antes de que se devuelva el valor de error, se llama al manejador de errores MPI actual asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo). Si no hay ningún objeto de comunicación asociado con la llamada MPI, entonces la llamada se considera adjunta a MPI_COMM_SELF y llamará al manejador de errores MPI asociado. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se utiliza exclusivamente el Modelo de Sesión) el error eleva el manejador de errores inicial. El manejador de errores inicial se puede cambiar llamando a MPI_Comm_set_errhandler en MPI_COMM_SELF cuando se utiliza el modelo de Mundo, o el argumento de línea de comandos mpi_initial_errhandler para mpiexec o la clave de información para MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no se ha configurado ningún otro manejador de errores apropiado, entonces se llama al manejador de errores MPI_ERRORS_RETURN para las funciones de E/S MPI y al manejador de errores MPI_ERRORS_ABORT para todas las demás funciones MPI.

Open MPI incluye tres manejadores de errores predefinidos que se pueden usar:

  • MPI_ERRORS_ARE_FATAL Causa que el programa aborte todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT Un manejador de errores que se puede invocar en un comunicador, ventana, archivo o sesión. Cuando se llama en un comunicador, actúa como si se hubiera llamado a MPI_Abort en ese comunicador. Si se llama en una ventana o archivo, actúa como si se hubiera llamado a MPI_Abort en un comunicador que contiene el grupo de procesos en la ventana o archivo correspondiente. Si se llama en una sesión, solo aborta el proceso local.
  • MPI_ERRORS_RETURN Devuelve un código de error a la aplicación.

Las aplicaciones MPI también pueden implementar sus propios manejadores de errores llamando a:

  • MPI_Comm_create_errhandler luego MPI_Comm_set_errhandler
  • MPI_File_create_errhandler luego MPI_File_set_errhandler
  • MPI_Session_create_errhandler luego MPI_Session_set_errhandler o en MPI_Session_init
  • MPI_Win_create_errhandler luego MPI_Win_set_errhandler

Tenga en cuenta que MPI no garantiza que un programa MPI pueda continuar después de un error.

Consulte la página man de MPI para obtener una lista completa de códigos de error de MPI.

Consulte la sección Manejo de Errores del estándar MPI-3.1 para obtener más información.
