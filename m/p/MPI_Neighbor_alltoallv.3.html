PARÁMETROS DE ENTRADA

  • sendbuf: Dirección de inicio del búfer de envío.
  • sendcounts: Array de enteros, donde la entrada i especifica el número de elementos a enviar al vecino i.
  • sdispls: Array de enteros, donde la entrada i especifica el desplazamiento (desfase desde sendbuf, en unidades de sendtype) desde el cual enviar datos al vecino i.
  • sendtype: Tipo de datos de los elementos del búfer de envío.
  • recvcounts: Array de enteros, donde la entrada j especifica el número de elementos a recibir del vecino j.
  • rdispls: Array de enteros, donde la entrada j especifica el desplazamiento (desfase desde recvbuf, en unidades de recvtype) a donde deben escribirse los datos del vecino j.
  • recvtype: Tipo de datos de los elementos del búfer de recepción.
  • comm: Comunicador sobre el cual se intercambiarán los datos.
  • info: Info (manejador, solo persistente).

PARÁMETROS DE SALIDA

  • recvbuf: Dirección del búfer de recepción.
  • request: Solicitud (manejador, solo no bloqueante).
  • ierror: Solo Fortran: Estado del error.

DESCRIPCIÓN

MPI_Neighbor_alltoallv es una operación colectiva generalizada en la que todos los procesos envían datos a y reciben datos de todos los vecinos. Añade flexibilidad a MPI_Neighbor_alltoall al permitir al usuario especificar datos para enviar y recibir de estilo vectorial (a través de un desplazamiento y un recuento de elementos). La operación de esta rutina puede pensarse de la siguiente manera, donde cada proceso realiza 2n (siendo n el número de vecinos en la topología del comunicador comm) comunicaciones punto a punto independientes. Los vecinos y la disposición de los búferes se determinan por la topología de comm.

MPI_Cart_get(comm, maxdims, dims, periods, coords);
for (dim = 0, i = 0 ; dim < dims ; ++dim) {
    MPI_Cart_shift(comm, dim, 1, &r0, &r1);
    MPI_Isend(sendbuf + sdispls[i]  * extent(sendtype),
              sendcount, sendtype, r0, ..., comm, ...);
    MPI_Irecv(recvbuf + rdispls[i] * extent(recvtype),
              recvcount, recvtype, r0, ..., comm, ...);
    ++i;
    MPI_Isend(sendbuf + sdispls[i] * extent(sendtype),
              sendcount, sendtype, r1, ..., comm, &req[i]);
    MPI_Irecv(recvbuf + rdispls[i] * extent(recvtype),
              recvcount, recvtype, r1, ..., comm, ...);
    ++i;
}

El proceso j envía el k-ésimo bloque de su sendbuf local al vecino k, que coloca los datos en el j-ésimo bloque de su recvbuf local.

Cuando un par de procesos intercambia datos, cada uno puede pasar diferentes recuentos de elementos y tipos de datos siempre que el remitente especifique la misma cantidad de datos a enviar (en bytes) que la que el receptor espera recibir.

Tenga en cuenta que el proceso i puede enviar una cantidad de datos diferente al proceso j de la que recibe del proceso j. Además, un proceso puede enviar cantidades de datos completamente diferentes a diferentes procesos en el comunicador.

ORDEN DE VECINOS

Para una topología de grafo distribuido, creada con MPI_Dist_graph_create, la secuencia de vecinos en los búferes de envío y recepción en cada proceso se define como la secuencia devuelta por MPI_Dist_graph_neighbors para destinos y fuentes, respectivamente. Para una topología de grafo general, creada con MPI_Graph_create, el orden de los vecinos en los búferes de envío y recepción se define como la secuencia de vecinos devuelta por MPI_Graph_neighbors. Tenga en cuenta que las topologías de grafo generales deberían reemplazarse generalmente por las topologías de grafo distribuidas.

Para una topología cartesiana, creada con MPI_Cart_create, la secuencia de vecinos en los búferes de envío y recepción en cada proceso se define por el orden de las dimensiones, primero el vecino en la dirección negativa y luego en la dirección positiva con un desplazamiento de 1. Los números de fuentes y destinos en las rutinas de comunicación son 2*ndims con ndims definidos en MPI_Cart_create. Si un vecino no existe, es decir, en el borde de una topología cartesiana en el caso de una dimensión de cuadrícula virtual no periódica (es decir, periods[…]==false), entonces este vecino se define como MPI_PROC_NULL.

Si un vecino en cualquiera de las funciones es MPI_PROC_NULL, entonces la comunicación colectiva de vecindad se comporta como una comunicación punto a punto con MPI_PROC_NULL en esa dirección. Es decir, el búfer sigue siendo parte de la secuencia de vecinos pero no se comunica ni se actualiza.

NOTAS

Estas rutinas se deprecian en favor de las rutinas de comunicación colectiva de vecindad que no están limitadas a topologías de grafo o cartesianas. Para más información, ver MPI_Neighbor_alltoallw.

Manual de MPI

SINTAXIS

La sintaxis de este comando es:

MPI_Neighbor_alltoallv(sendbuf, sendcount, sendtype, rdispls, recvbuf, recvcount, recvtype, comm)

PARÁMETROS DE ENTRADA

Los parámetros de entrada son:

  • sendbuf (void*): dirección de memoria para enviar datos.
  • sendcount (int): número de elementos a enviar.
  • sendtype (MPI_Datatype): tipo de datos a enviar.
  • rdispls (int): desplazamientos de recepción.
  • recvbuf (void*): dirección de memoria para recibir datos.
  • recvcount (int): número de elementos a recibir.
  • recvtype (MPI_Datatype): tipo de datos a recibir.
  • comm (MPI_Comm): comunicador para el proceso.

PARÁMETROS DE SALIDA

Los parámetros de salida son:

  • sendbuf (void*): dirección de memoria de los datos enviados.
  • recvbuf (void*): dirección de memoria de los datos recibidos.
  • status (MPI_Status): estado de la operación.

DESCRIPCIÓN

Este comando realiza una operación alltoallv en el entorno de vecindad. El proceso se comunica con sus vecinos utilizando el protocolo MPI. El comando es más eficiente que MPI_alltoallv, ya que permite una operación de tipo de datos específico, mientras que MPI_alltoallv se puede usar con tipos de datos genéricos. Este comando se utiliza en sistemas de comunicación con vecindad en los que cada proceso puede tener un número diferente de vecinos.

ORDEN DE VECINOS

El orden de los vecinos se establece por el comunicador. El proceso se comunica con los vecinos en base a su orden en el comunicador.

NOTAS

El parámetro MPI_IN_PLACE para sendbuf no es significativo para esta operación.

La especificación de contadores y desplazamientos no debe causar que ninguna ubicación sea escrita más de una vez.

Todos los argumentos en todos los procesos son significativos. El argumento comm, en particular, debe describir el mismo comunicador en todos los procesos.

Los desplazamientos de sdispls y rdispls se miden en unidades de sendtype y recvtype, respectivamente. Compare esto con MPI_Neighbor_alltoallw, donde estos desplazamientos se miden en bytes.

ERRORES

La mayoría de las rutinas MPI devuelven un valor de error; las rutinas C devuelven el resultado de la función y las rutinas Fortran se especifican como el último argumento.

Antes de devolver el valor de error, se llama al gestor de errores actual asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo). Si no hay ningún objeto de comunicación asociado con la llamada MPI, la llamada se considera asociada a MPI_COMM_SELF y se llama al gestor correspondiente. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize o cuando se utiliza exclusivamente el modelo de sesiones), el error eleva el gestor de errores inicial. El gestor de errores inicial se puede cambiar llamando a MPI_Comm_set_errhandler en MPI_COMM_SELF cuando se utiliza el modelo del mundo, o a la opción mpi_initial_errhandler de mpiexec o a la clave info de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no se establece ningún otro gestor de errores adecuado, se llama al gestor MPI_ERRORS_RETURN para las funciones de E/S de MPI y MPI_ERRORS_ABORT para otras funciones de MPI.

Open MPI incluye tres gestores de errores predeterminados que se pueden utilizar:

  • MPI_ERRORS_ARE_FATAL Causa que el programa termine todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT Un gestor de errores que puede invocarse en un comunicador, ventana, archivo o sesión. Cuando se llama en un comunicador, actúa como si se hubiera llamado MPI_Abort en ese comunicador. Si se llama en una ventana o archivo, actúa como si se hubiera llamado MPI_Abort en un comunicador que contiene el grupo de procesos en la ventana o archivo correspondiente. Si se llama en una sesión, detiene solo el proceso local.
  • MPI_ERRORS_RETURN Devuelve un código de error a la aplicación.

Las aplicaciones MPI también pueden implementar sus propios gestores de errores llamando a:

  • MPI_Comm_create_errhandler luego MPI_Comm_set_errhandler
  • MPI_File_create_errhandler luego MPI_File_set_errhandler
  • MPI_Session_create_errhandler luego MPI_Session_set_errhandler o en MPI_Session_init
  • MPI_Win_create_errhandler luego MPI_Win_set_errhandler

Nota: MPI no garantiza que un programa MPI pueda continuar después de un error.

Ver la página del manual de MPI para una lista completa de códigos de error MPI.
