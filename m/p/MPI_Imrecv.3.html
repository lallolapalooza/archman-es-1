MPI_Imrecv(3) Open MPI MPI_Imrecv(3)

MPI_Imrecv — Recibir mensaje no bloqueante para un mensaje ya buscado

Sintaxis

Sintaxis C

#include <mpi.h>
int MPI_Imrecv(void *buf, int count, MPI_Datatype type,
     MPI_Message *message, MPI_Request *request)

Sintaxis Fortran

USE MPI
! o la forma antigua: INCLUDE 'mpif.h'
MPI_IMRECV(BUF, COUNT, DATATYPE, MESSAGE, REQUEST, IERROR)
     <type>  BUF(*)
     INTEGER COUNT, DATATYPE, MESSAGE, REQUEST, IERROR

Sintaxis Fortran 2008

USE mpi_f08
MPI_Imrecv(buf, count, datatype, message, request, ierror)
     TYPE(*), DIMENSION(..), ASYNCHRONOUS :: buf
     INTEGER, INTENT(IN) :: count
     TYPE(MPI_Datatype), INTENT(IN) :: datatype
     TYPE(MPI_Message), INTENT(INOUT) :: message
     TYPE(MPI_Request), INTENT(OUT) :: request
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

Parámetros de entrada

  • count: Número de elementos a recibir (entero no negativo).
  • datatype: Tipo de dato de cada elemento del buffer de envío (manejador).
  • message: Mensaje (manejador).

Parámetros de salida

  • buf: Dirección inicial del buffer de recepción (opcional).
  • request: Solicitud (manejador).
  • ierror: Solo en Fortran: Código de error (entero).

Descripción

Las funciones MPI_Mrecv y MPI_Imrecv reciben mensajes que han sido previamente buscados por una búsqueda de correspondencia.

El request devuelto por MPI_Imrecv puede ser utilizado con cualquier variante de MPI_Test o MPI_Wait, como cualquier solicitud de recepción no bloqueante.

Si MPI_Imrecv se llama con MPI_MESSAGE_NULL como el argumento de mensaje, una llamada a una de las variantes de MPI_Test o MPI_Wait devolverá inmediatamente con el objeto status establecido a source = MPI_PROC_NULL, tag = MPI_ANY_TAG, y count = 0, como si se hubiera emitido una recepción desde MPI_PROC_NULL.

Si se inició la recepción de un mensaje buscado con MPI_Imrecv, es posible cancelar la solicitud devuelta con MPI_Cancel. Si MPI_Cancel es exitoso, el mensaje buscado debe encontrarse mediante una búsqueda posterior (MPI_Probe, MPI_Iprobe, MPI_Mprobe, o MPI_Improbe), recibido por una operación de recepción posterior o cancelado por el emisor.

Sin embargo, puede ser posible que la cancelación de operaciones iniciadas con MPI_Imrecv falle. Un ejemplo de caso fallido es cuando la cancelación del recibido del mensaje buscado violaría las reglas de ordenamiento de mensaje MPI (por ejemplo, si otro mensaje con la misma firma de mensaje ha sido buscado antes de que este MPI_Imrecv sea cancelado).

Si tu aplicación no necesita examinar el campo status, puedes ahorrar recursos usando la constante predefinida MPI_STATUS_IGNORE como un valor especial para el argumento status.

Errores

Más que las rutinas MPI devuelven un valor de error; las rutinas C devuelven el valor de resultado de la función y las rutinas Fortran en el último argumento.

Antes de que se devuelva el valor de error, se llama al manejador de error asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo) actual. Si no hay un objeto de comunicación asociado con la llamada MPI, se considera que la llamada está asociada a MPI_COMM_SELF y se llama al manejador de error correspondiente. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se usa el Modelo de Sesiones exclusivamente), el error invoca al manejador de error inicial. El manejador de error inicial puede ser cambiado llamando MPI_Comm_set_errhandler sobre MPI_COMM_SELF cuando se usa el Modelo del Mundo, o el argumento CLI mpi_initial_errhandler para mpiexec o la clave info para MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no hay otro manejador adecuado configurado, se llama al manejador de error MPI_ERRORS_RETURN para las funciones de E/S MPI y al manejador de error MPI_ERRORS_ABORT para todas las demás funciones MPI.

Open MPI incluye tres manejadores de error predefinidos que se pueden usar:

  • MPI_ERRORS_ARE_FATAL — Detiene todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT — Un manejador que puede ser invocado en un comunicador, ventana, archivo o sesión. Cuando se llama en un comunicador, actúa como si se hubiera llamado MPI_Abort en ese comunicador. Si se llama en una ventana o archivo, actúa como si se hubiera llamado MPI_Abort en un comunicador que contiene el grupo de procesos en la ventana o archivo correspondiente. Si se llama en una sesión, detiene solo el proceso local.
  • MPI_ERRORS_RETURN — Devuelve un código de error a la aplicación.

Las aplicaciones MPI también pueden implementar sus propios manejadores de error llamando:

  • MPI_Comm_create_errhandler y luego MPI_Comm_set_errhandler
  • MPI_File_create_errhandler y luego MPI_File_set_errhandler
  • MPI_Session_create_errhandler y luego MPI_Session_set_errhandler o en MPI_Session_init
  • MPI_Win_create_errhandler y luego MPI_Win_set_errhandler

Nota: MPI no garantiza que un programa MPI pueda continuar después de un error.

Ver la página de manual de MPI para una lista completa de códigos de error MPI.

Ver la sección de manejo de errores de la especificación MPI-3.1 para más información.

Nota: Según la sección "Retorno de estado" de la "Comunicación punto a punto" en el "Estándar MPI", los errores recibidos por MPI_Imrecv no establecen el campo status.MPI_ERROR en el objeto status devuelto. El código de error siempre se pasa al manejador de error de backend y puede ser devuelto a la llamada del usuario a través del valor de retorno de MPI_Imrecv si el manejador de error de backend lo devuelve. El manejador de error predefinido MPI_ERRORS_RETURN muestra este comportamiento, por ejemplo.
