MPIX_COMM_IS_REVOKED(3) Open MPI MPIX_COMM_IS_REVOKED(3)

MPIX_Comm_is_revoked - Comprueba si un comunicador está revocado.

Esto forma parte de la extensión ULFM de Mitigación de Fallos a Nivel de Usuario.

SINTAXIS

Sintaxis C

#include <mpi.h>
#include <mpi-ext.h>
int MPIX_Comm_is_revoked(MPI_Comm comm, int *flag)

Sintaxis Fortran

USE MPI
USE MPI_EXT
! o la forma antigua: INCLUDE 'mpif.h'
MPIX_COMM_IS_REVOKED(COMM, FLAG, IERROR)
     INTEGER COMM, IERROR
     LOGICAL FLAG

Sintaxis Fortran 2008

USE mpi_f08
USE mpi_ext_f08
MPIX_Comm_is_revoked(comm, flag, ierror)
     TYPE(MPI_Comm), INTENT(IN) :: comm
     LOGICAL, INTENT(OUT) :: flag
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARÁMETROS DE ENTRADA

•
comm: Comunicador (identificador).

PARÁMETROS DE SALIDA

  • flag: true si el comunicador está revocado.
  • ierror: Solo Fortran: Estado de error (entero).

DESCRIPCIÓN

Devuelve flag = true si el comunicador asociado al identificador comm está revocado en el proceso de llamada. Devuelve flag = false en caso contrario. La operación es local.

¿CÓMO PUEDE UN COMUNICADOR SER REVOCADO?

Un comunicador puede ser revocado cuando

1.
el usuario llama al procedimiento MPIX_Comm_revoke en comm para revocar el comunicador en el proceso local;
2.
una operación MPI elevó la clase de error MPIX_ERR_REVOKED porque otro proceso llamó al procedimiento MPIX_Comm_revoke en comm;
3.
el comunicador tiene la clave de información mpi_error_range establecida en group o universe, en cuyo caso el fallo de cualquier proceso en, respectivamente, el grupo de comm o el universo MPI causó que una operación elevara un error de clase MPIX_ERR_REVOKED.

PROPAGACIÓN Y ORDEN DE LA REVOCACIÓN

Tenga en cuenta que en una aplicación multihilo, un hilo que llama a MPIX_Comm_is_revoked puede devolver flag = true antes de que la operación que eleva la primera excepción de clase MPIX_ERR_REVOKED haya completado en un hilo concurrente.

EFECTO DE LA REVOCACIÓN DE UN COMUNICADOR

Una vez que un comunicador ha sido revocado en un proceso MPI, todas las operaciones subsiguientes no locales en ese comunicador (con algunas excepciones enumeradas a continuación) se consideran locales y deben completarse elevando un error de clase MPIX_ERR_REVOKED en ese proceso MPI.

OPERACIONES SOBRE UN COMUNICADOR REVOCADO

Las siguientes operaciones nunca elevan un error de clase MPIX_ERR_REVOKED y se completan con su semántica normal en un comunicador revocado.

  • MPIX_Comm_agree
  • MPIX_Comm_iagree
  • MPIX_Comm_shrink
  • MPIX_Comm_ishrink

ERRORES

Casi todas las rutinas MPI devuelven un valor de error; las rutinas C como resultado de la función y las rutinas Fortran en el último argumento.

Antes de que se devuelva el valor de error, se llama al controlador de errores MPI actual asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo). Si no hay ningún objeto de comunicación asociado con la llamada MPI, entonces la llamada se considera adjunta a MPI_COMM_SELF y llamará al controlador de errores MPI asociado. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se utiliza el Modelo de Sesiones exclusivamente) el error eleva el controlador de errores inicial. El controlador de errores inicial puede modificarse llamando a MPI_Comm_set_errhandler en MPI_COMM_SELF al usar el modelo World, o el argumento CLI mpi_initial_errhandler para mpiexec o la clave de información para MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no se ha configurado ningún otro controlador de errores apropiado, entonces se llama al controlador de errores MPI_ERRORS_RETURN para las funciones de E/S de MPI y al controlador de errores MPI_ERRORS_ABORT para todas las demás funciones MPI.

Open MPI incluye tres controladores de errores predefinidos que pueden utilizarse:

  • MPI_ERRORS_ARE_FATAL Provoca que el programa aborte todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT Un controlador de errores que se puede invocar en un comunicador, ventana, archivo o sesión. Cuando se llama en un comunicador, actúa como si se hubiera llamado a MPI_Abort en ese comunicador. Si se llama en una ventana o archivo, actúa como si se hubiera llamado a MPI_Abort en un comunicador que contiene el grupo de procesos en la ventana o archivo correspondiente. Si se llama en una sesión, solo aborta el proceso local.
  • MPI_ERRORS_RETURN Devuelve un código de error a la aplicación.

Las aplicaciones MPI también pueden implementar sus propios controladores de errores llamando a:

  • MPI_Comm_create_errhandler luego MPI_Comm_set_errhandler
  • MPI_File_create_errhandler luego MPI_File_set_errhandler
  • MPI_Session_create_errhandler luego MPI_Session_set_errhandler o en MPI_Session_init
  • MPI_Win_create_errhandler luego MPI_Win_set_errhandler

Tenga en cuenta que MPI no garantiza que un programa MPI pueda continuar después de un error.

Consulte la página del manual de MPI para obtener una lista completa de los códigos de error de MPI.

Consulte la sección de Manejo de Errores del estándar MPI-3.1 para obtener más información.
