PARAMETROS DE ENTRADA

  • sendbuf: Dirección de inicio del búfer de envío.
  • sendcounts: Array de enteros, donde la entrada i especifica el número de elementos a enviar al rango i.
  • sdispls: Array de enteros, donde la entrada i especifica el desplazamiento (en bytes, offset desde sendbuf) desde el cual enviar datos al rango i.
  • sendtypes: Array de tipos de datos, donde la entrada i especifica el tipo de datos a usar al enviar datos al rango i.
  • recvcounts: Array de enteros, donde la entrada j especifica el número de elementos a recibir del rango j.
  • rdispls: Array de enteros, donde la entrada j especifica el desplazamiento (en bytes, offset desde recvbuf) al cual se deben escribir los datos del rango j.
  • recvtypes: Array de tipos de datos, donde la entrada j especifica el tipo de datos a usar al recibir datos del rango j.
  • comm: Comunicador sobre el cual se intercambiarán los datos.
  • info: Información (manejador, solo persistente)

PARAMETROS DE SALIDA

  • recvbuf: Dirección del búfer de recepción.
  • request: Solicitud (manejador, solo no bloqueante).
  • ierror: Solo Fortran: Estado de error.

DESCRIPCION

MPI_Alltoallw es una operación colectiva generalizada en la que todos los procesos envían datos a y reciben datos de todos los demás procesos. Añade flexibilidad a MPI_Alltoallv al permitir al usuario especificar el tipo de dato de los bloques de datos individuales (además del desplazamiento y el recuento de elementos). Su operación puede pensarse de la siguiente manera, donde cada proceso realiza 2n (siendo n el número de procesos en el comunicador comm) comunicaciones punto a punto independientes (incluida la comunicación consigo mismo).

MPI_Comm_size(comm, &n);
for (i = 0, i < n; i++)
    MPI_Send(sendbuf + sdispls[i], sendcounts[i],
        sendtypes[i], i, ..., comm);
for (i = 0, i < n; i++)
    MPI_Recv(recvbuf + rdispls[i], recvcounts[i],
        recvtypes[i], i, ..., comm);

El proceso j envía el k-ésimo bloque de su sendbuf local al proceso k, el cual coloca los datos en el j-ésimo bloque de su recvbuf local.

Cuando un par de procesos intercambia datos, cada uno puede pasar argumentos de recuento y tipo de datos diferentes, siempre que el emisor especifique la misma cantidad de datos para enviar (en bytes) que la que el receptor espera recibir.

Tenga en cuenta que el proceso i puede enviar una cantidad de datos diferente al proceso j de la que recibe del proceso j. Además, un proceso puede enviar cantidades y tipos de datos completamente diferentes a diferentes procesos en el comunicador.

CUANDO EL COMUNICADOR ES UN INTERCOMUNICADOR

Cuando el comunicador es un intercomunicador, la operación de recopilación se produce en dos fases. Los datos se recopilan de todos los miembros del primer grupo y se reciben por todos los miembros del segundo grupo. Luego, los datos se recopilan de todos los miembros del segundo grupo y se reciben por todos los miembros del primero. La operación exhibe un comportamiento simétrico, dúplex completo.

El primer grupo define el proceso raíz. El proceso raíz utiliza MPI_ROOT como valor de root. Todos los demás procesos del primer grupo usan MPI_PROC_NULL como valor de root. Todos los procesos del segundo grupo usan el rango del proceso raíz en el primer grupo como valor de root.

Cuando el comunicador es un intracomunicador, estos grupos son los mismos y la operación ocurre en una sola fase.

USO DE LA OPCION IN-PLACE

Cuando el comunicador es un intracomunicador, puede realizar una operación "todos a todos" in-place (el búfer de salida se utiliza como búfer de entrada). Utilice la variable MPI_IN_PLACE como valor de sendbuf. En este caso, sendcounts, sdispls y sendtypes se ignoran. Se asume que los datos de entrada de cada proceso se encuentran en el área donde ese proceso recibiría su propia contribución al búfer de recepción.

NOTAS

La especificación de recuentos, tipos y desplazamientos no debe provocar que ninguna ubicación se escriba más de una vez.

Todos los argumentos en todos los procesos son significativos. El argumento comm, en particular, debe describir el mismo comunicador en todos los procesos.

Los offsets de sdispls y rdispls se miden en bytes. Compárese esto con MPI_Alltoallv, donde los

e offsets are measured in units of sendtype and recvtype, respectively.

ERRORES

Casi todas las rutinas de MPI devuelven un valor de error; las rutinas de C como resultado de retorno de la función y las rutinas de Fortran en el último argumento.

Antes de que se devuelva el valor de error, se llama al controlador de errores de MPI actual asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo). Si no hay ningún objeto de comunicación asociado con la llamada MPI, entonces la llamada se considera adjunta a MPI_COMM_SELF y llamará al controlador de errores de MPI asociado. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se utiliza exclusivamente el modelo de sesiones) el error eleva el controlador de errores inicial. El controlador de errores inicial se puede cambiar llamando a MPI_Comm_set_errhandler en MPI_COMM_SELF cuando se utiliza el modelo World, o el argumento de línea de comandos mpi_initial_errhandler para mpiexec o la clave de información para MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no se ha establecido ningún otro controlador de errores apropiado, entonces se llama al controlador de errores MPI_ERRORS_RETURN para las funciones de E/S de MPI y al controlador de errores MPI_ERRORS_ABORT para todas las demás funciones de MPI.

Open MPI incluye tres controladores de errores predefinidos que se pueden utilizar:

  • MPI_ERRORS_ARE_FATAL Provoca que el programa aborte todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT Un controlador de errores que puede invocarse en un comunicador, ventana, archivo o sesión. Cuando se llama en un comunicador, actúa como si se hubiera llamado a MPI_Abort en ese comunicador. Si se llama en una ventana o archivo, actúa como si se hubiera llamado a MPI_Abort en un comunicador que contiene el grupo de procesos de la ventana o archivo correspondiente. Si se llama en una sesión, solo aborta el proceso local.
  • MPI_ERRORS_RETURN Devuelve un código de error a la aplicación.

Las aplicaciones MPI también pueden implementar sus propios controladores de errores llamando a:

  • MPI_Comm_create_errhandler luego MPI_Comm_set_errhandler
  • MPI_File_create_errhandler luego MPI_File_set_errhandler
  • MPI_Session_create_errhandler luego MPI_Session_set_errhandler o en MPI_Session_init
  • MPI_Win_create_errhandler luego MPI_Win_set_errhandler

Tenga en cuenta que MPI no garantiza que un programa MPI pueda continuar después de un error.

Consulte la página del manual de MPI para obtener una lista completa de los códigos de error de MPI.

Consulte la sección de Manejo de Errores del estándar MPI-3.1 para obtener más información.
