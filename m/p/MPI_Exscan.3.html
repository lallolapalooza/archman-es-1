PARÁMETROS DE ENTRADA

  • sendbuf: Búfer de envío (elección).
  • count: Número de elementos en el búfer de entrada (entero).
  • datatype: Tipo de datos de los elementos del búfer de entrada (manejador).
  • op: Operación (manejador).
  • comm: Comunicador (manejador).

PARÁMETROS DE SALIDA

  • recvbuf: Búfer de recepción (elección).
  • request: Solicitud (manejador, solo no bloqueante).
  • ierror: Solo Fortran: Estado de error (entero).

DESCRIPCIÓN

MPI_Exscan se utiliza para realizar una reducción de prefijo exclusiva en datos distribuidos entre los procesos que llaman. La operación devuelve, en el recvbuf del proceso con rango i, la reducción (calculada según la función op) de los valores en los sendbufs de los procesos con rangos 0, ..., i-1. Compárese esto con la funcionalidad de MPI_Scan, que calcula sobre el rango 0, ..., i (inclusivo). El tipo de operaciones soportadas, sus semánticas y las restricciones en los búferes de envío y recepción son como para MPI_Reduce.

El valor en recvbuf en el proceso 0 no está definido y no es fiable, ya que recvbuf no es significativo para el proceso 0. El valor de recvbuf en el proceso 1 es siempre el valor en sendbuf del proceso 0.

USO DE LA OPCIÓN IN-PLACE

La opción 'in place' para intracommunicators se especifica pasando MPI_IN_PLACE en el argumento sendbuf. En este caso, los datos de entrada se toman del búfer de recepción y se reemplazan por los datos de salida.

Tenga en cuenta que MPI_IN_PLACE es un tipo especial de valor; tiene las mismas restricciones de uso que MPI_BOTTOM.

Dado que la opción in-place convierte el búfer de recepción en un búfer de envío y recepción, una vinculación de Fortran que incluya INTENT debe marcar estos como INOUT, no OUT.

NOTAS

MPI no especifica qué proceso calcula qué operación. En particular, ambos procesos 0 y 1 pueden participar en el cálculo aunque los resultados para el recvbuf de ambos procesos sean degenerados. Por lo tanto, todos los procesos, incluidos 0 y 1, deben proporcionar la misma op.

Se puede argumentar, desde una perspectiva matemática, que la definición de MPI_Exscan no es satisfactoria porque la salida en el proceso 0 no está definida. La salida "matemáticamente correcta" para el proceso 0 sería el elemento unitario de la operación de reducción. Sin embargo, tal definición de un escaneo exclusivo no funcionaría con funciones op definidas por el usuario, ya que no hay forma de que MPI "conozca" el valor unitario para estas operaciones personalizadas.

NOTAS SOBRE OPERACIONES COLECTIVAS

Las funciones de reducción de tipo MPI_Op no devuelven un valor de error. Como resultado, si las funciones detectan un error, lo único que pueden hacer es llamar a MPI_Abort o omitir silenciosamente el problema. Por lo tanto, si el manejador de errores se cambia de MPI_ERRORS_ARE_FATAL a otra cosa (por ejemplo, MPI_ERRORS_RETURN), es posible que no se indique ningún error.

La razón de esto son los problemas de rendimiento para garantizar que todas las rutinas colectivas devuelvan el mismo valor de error.

ERRORES

Casi todas las rutinas de MPI devuelven un valor de error; en C como resultado de retorno de la función y en Fortran en el último argumento.

Antes de que se devuelva el valor de error, se llama al manejador de errores de MPI actual asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo). Si no hay ningún objeto de comunicación asociado con la llamada a MPI, entonces la llamada se considera adjunta a MPI_COMM_SELF y llamará al manejador de errores de MPI asociado. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/ MPI_Init_thread, después de MPI_Finalize, o cuando se utiliza exclusivamente el Modelo de Sesiones) el error eleva el manejador de errores inicial. El manejador de errores inicial puede cambiarse llamando a MPI_Comm_set_errhandler en MPI_COMM_SELF cuando se utiliza el modelo Mundial, o el argumento CLI mpi_initial_errhandler a mpiexec o la clave de información a MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no se ha establecido ningún otro manejador de errores apropiado, entonces se llama al manejador de errores MPI_ERRORS_RETURN para las funciones de E/S de MPI y al manejador de errores MPI_ERRORS_ABORT para todas las demás funciones de MPI.

Open MPI incluye tres manejadores de errores predefinidos que se pueden utilizar:

  • MPI_ERRORS_ARE_FATAL Provoca que el programa aborte todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT Un manejador de errores que se puede invocar en un comunicador, ventana, archivo o sesión. Cuando se llama en un comunicador, actúa como si se hubiera llamado a MPI_Abort en ese comunicador. Si se llama en una ventana o archivo, actúa como si se hubiera llamado a MPI_Abort en un comunicador que contiene el grupo de procesos en la ventana o archivo correspondiente. Si se llama en una sesión, aborta solo el proceso local.
  • MPI_ERRORS_RETURN Devuelve un código de error a la aplicación.

Las aplicaciones MPI también pueden implementar sus propios manejadores de errores llamando a:

  • MPI_Comm_create_errhandler luego MPI_Comm_set_errhandler
  • MPI_File_create_errhandler luego MPI_File_set_errhandler
  • MPI_Session_create_errhandler luego MPI_Session_set_errhandler o en M

SYNTAX

Call:
  MPI_Exscan(sendbuf, recvbuf, count, datatype, op, comm)

C binding:
  int MPI_Exscan(const void *sendbuf, void *recvbuf, int count,
                 MPI_Datatype datatype, MPI_Op op, MPI_Comm comm)

Fortran binding:
  SUBROUTINE MPI_EXSCAN(SENDBUF, RECVBUF, COUNT, DATATYPE, OP, COMM,
                        IERROR)
      MPI_Datatype, INTENT(IN) :: DATATYPE
      MPI_Op, INTENT(IN) :: OP
      MPI_Comm, INTENT(IN) :: COMM
      INTEGER, INTENT(IN) :: COUNT
      MPI_Status :: STATUS
      INTEGER, INTENT(OUT) :: IERROR
      MPI_Aint :: SEND
      MPI_Aint :: RECV
      ! Typed variables and parameters
      MPI_Aint :: SEND
      MPI_Aint :: RECV

INPUT PARAMETERS

  • sendbuf: Inicializa el buffer de envío (puntero a la matriz).
  • count: Número de elementos en el buffer de envío.
  • datatype: Tipo de datos de los elementos en el buffer de envío.
  • op: La operación de reducción que se va a aplicar (ver la sección "OPERACIONES DE REDUCCIÓN").
  • comm: Comunicador con el que se va a realizar la operación.

OUTPUT PARAMETERS

  • recvbuf: Buffer de recepción (puntero a la matriz).

DESCRIPTION

MPI_Exscan es una versión de MPI_Scan que devuelve el resultado de la operación de reducción acumulativa a todos los procesos, excepto al primer proceso en el comunicador. El primer proceso no devuelve ningún resultado.

En la operación, el proceso con rango i en el comunicador recibe el resultado de la operación de reducción sobre los argumentos de envío de los procesos con rango 0 a i. El proceso con rango 0 no recibe ningún resultado, ya que no hay ningún proceso con un rango menor que él.

La operación MPI_Exscan es una operación colectiva. Debe ser llamada por todos los procesos del mismo comunicador. Todos los procesos deben especificar los mismos argumentos para los parámetros count, datatype, op y comm.

El argumento sendbuf es utilizado por el proceso de rango i para especificar los datos que se van a incluir en la operación de reducción. El argumento recvbuf se utiliza para recibir el resultado de la operación.

El primer proceso (rango 0) en el comunicador no recibe ningún resultado.

USE OF IN-PLACE OPTION

Cuando el argumento comm representa un comunicador intracomunícola, puede especificar un buffer "in-place" para enviar y recibir. Es decir, sendbuf y recvbuf pueden referirse al mismo objeto.

Si sendbuf y recvbuf se refieren al mismo objeto, entonces el contenido del buffer de envío original debe ser preservado hasta que la operación MPI_Exscan se complete. Esto significa que el objeto referenciado por sendbuf y recvbuf no puede ser modificado por ningún otro proceso durante la llamada a MPI_Exscan.

NOTES

La operación MPI_Exscan es similar a MPI_Scan, pero el resultado se desplaza un proceso hacia abajo en el comunicador. Esto significa que el primer proceso (rango 0) no recibe ningún resultado.

NOTES ON COLLECTIVE OPERATIONS

Las operaciones colectivas de MPI son rutinas que involucran a todos los procesos de un grupo. Deben ser llamadas por todos los procesos del grupo. Se garantiza que todas las operaciones colectivas de MPI estén sincronizadas en el sentido de que todos los procesos deben invocar la misma rutina colectiva. Si no es así, el comportamiento no está definido. La única excepción es el caso en el que se proporcionan argumentos diferentes para la misma rutina colectiva, lo que también resulta en un comportamiento no definido.

Una operación colectiva se considera bloqueante si regresa solo después de que todos los procesos del grupo hayan entrado y salido de la operación colectiva.

Una operación colectiva no bloqueante se invoca mediante una llamada a una interfaz de comunicación no bloqueante (por ejemplo, MPI_Isend, MPI_Irecv, o una variante colectiva no bloqueante) y se completa con una llamada a MPI_Wait o MPI_Test.

El argumento comm se utiliza para determinar el grupo de procesos que participan en la operación colectiva. Las operaciones colectivas de MPI son particularmente susceptibles a errores debido a la necesidad de que todos los procesos del grupo invoquen la misma operación.

ERRORS

Cuando ocurre un error en una operación colectiva, el comportamiento no está definido. Sin embargo, para algunas clases de errores de comunicación, MPI puede invocar un manejador de errores en nombre del usuario. Los errores que ocurren durante la ejecución de una operación colectiva pueden incluir la terminación de un proceso sin notificación a otros o la terminación de un proceso sin ninguna notificación.

Se pueden invocar los siguientes manejadores de errores:

  • MPI_ERRORS_ARE_FATAL
  • MPI_ERRORS_RETURN

A partir de MPI 2.2, se puede invocar un manejador de errores de ventana para manejar errores que ocurren en operaciones de ventana. Los siguientes errores pueden ocurrir durante la ejecución de MPI_Exscan:

  • MPI_ERR_TOPOLOGY: error de topología de proceso.
  • MPI_ERR_TRUNCATE: mensaje truncado.
  • MPI_ERR_RMA_SYNC: error de sincronización RMA.
  • MPI_ERR_RMA_RANGE: el rango de RMA está fuera de los límites.
  • MPI_ERR_RMA_ATTACH: error al adjuntar RMA.
  • MPI_ERR_RMA_SHARED: memoria compartida no válida para RMA.
  • MPI_ERR_RMA_CONFLICT: conflicto de acceso RMA.
  • MPI_ERR_INTERN: error interno de MPI.
  • MPI_ERR_BUFFER: se ha producido un error en el buffer de comunicación.
  • MPI_ERR_COUNT: se ha producido un error en el recuento.
  • MPI_ERR_DATATYPE: se ha producido un error en el tipo de datos.
  • MPI_ERR_OP: se ha producido un error en la operación.
  • MPI_ERR_COMM: se ha producido un error en el comunicador.
  • MPI_ERR_RANK: rango inválido.
  • MPI_ERR_REQUEST: se ha producido un error en la solicitud.
  • MPI_ERR_ROOT: raíz incorrecta.
  • MPI_ERR_GROUP: se ha producido un error en el grupo.
  • MPI_ERR_SYSCALL: error de llamada al sistema.
  • MPI_ERR_WIN: se ha producido un error en la ventana.

El programador debe asegurarse de que se hayan configurado manejadores de errores adecuados para las operaciones de MPI.

Para obtener más información, consulte las secciones:

  • MPI_Init
  • MPI_Win_create_errhandler then MPI_Win_set_errhandler

Tenga en cuenta que MPI no garantiza que un programa MPI pueda continuar después de un error.
