MPI_Startall(3) Open MPI MPI_Startall(3)

MPI_Startall — Inicia una colección de solicitudes.

Sintaxis

Sintaxis C

#include <mpi.h>
int MPI_Startall(int count, MPI_Request array_of_requests[])

Sintaxis Fortran

USE MPI
! o la forma más antigua: INCLUDE 'mpif.h'
MPI_Startall(COUNT, ARRAY_OF_REQUESTS, IERROR)
     INTEGER COUNT, ARRAY_OF_REQUESTS(*), IERROR

Sintaxis Fortran 2008

USE mpi_f08
MPI_Startall(count, array_of_requests, ierror)
     INTEGER, INTENT(IN) :: count
     TYPE(MPI_Request), INTENT(INOUT) :: array_of_requests(count)
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

Parámetro de entrada

•
count: Tamaño de la lista (entero).

Parámetro de entrada/salida

•
array_of_requests: Array de solicitudes (array de handles).

Parámetro de salida

•
ierror: Solo en Fortran: Código de error (entero).

Descripción

Inicia todas las comunicaciones asociadas con las solicitudes en array_of_requests. Una llamada a MPI_Startall(count, array_of_requests) tiene el mismo efecto que varias llamadas a MPI_Start(&array_of_requests[i]), ejecutadas para i=0, ..., count-1, en algún orden arbitrario.

Una comunicación iniciada con una llamada a MPI_Start o MPI_Startall se completa con una llamada a MPI_Wait, MPI_Test o una de las funciones derivadas MPI_Waitany, MPI_Testany, MPI_Waitall, MPI_Testall (estas se describen en el Capítulo 3.7.5 de la Estándar MPI, "Completaciones múltiples"). La solicitud se vuelve inactiva después de la ejecución exitosa de dicha llamada. La solicitud no se libera, y puede activarse nuevamente con otra llamada a MPI_Start o MPI_Startall.

Una solicitud persistente se libera con una llamada a MPI_Request_free (ver Capítulo 3.7.3 de la Estándar MPI, "Completación de comunicación").

La llamada a MPI_Request_free puede ocurrir en cualquier momento después de que la solicitud persistente fue creada. Sin embargo, la solicitud solo se libera cuando se convierte en inactiva. Las solicitudes de recepción activas no deben ser liberadas. De lo contrario, no será posible verificar que la recepción ha completado. Es preferible liberar las solicitudes cuando estén inactivas. Si se sigue esta regla, entonces las funciones de completación de comunicación persistente se invocarán en una secuencia de la forma,
Crea (Inicia Completa)* Libera

donde * indica cero o más repeticiones. Si el mismo objeto de comunicación se usa en varios hilos concurrentes, es la responsabilidad del usuario coordinar las llamadas de manera que se siga la secuencia correcta.

Una operación de envío iniciada con MPI_Start puede coincidir con cualquier operación de recepción y, de manera similar, una operación de recepción iniciada con MPI_Start puede recibir mensajes generados por cualquier operación de envío.

Errores

La mayoría de las rutinas MPI devuelven un valor de error; en las rutinas C, el valor de retorno es el resultado de la función, y en las rutinas Fortran, el último argumento es el valor de error.

Antes de que el valor de error sea devuelto, se llama al manejador de errores asociado con el objeto de comunicación (por ejemplo, communicator, window, file) actual. Si no hay objeto de comunicación asociado con la llamada MPI, se considera que la llamada está asociada con MPI_COMM_SELF y se llamará al manejador de errores asociado con MPI_COMM_SELF. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se use el modelo de sesiones exclusivamente), el error se eleva el manejador de errores inicial. El manejador de errores inicial puede cambiarse llamando a MPI_Comm_set_errhandler en MPI_COMM_SELF cuando se use el modelo del mundo, o a la opción mpi_initial_errhandler del mpiexec o a la clave info del MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no hay otro manejador de error apropiado, se llama el manejador de errores MPI_ERRORS_RETURN para las funciones de I/O MPI y el manejador de errores MPI_ERRORS_ABORT para todas las otras funciones MPI.

Open MPI incluye tres manejadores de errores predeterminados que se pueden usar:

  • MPI_ERRORS_ARE_FATAL - El programa aborta todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT - Un manejador de errores que puede llamarse en un comunicador, ventana, archivo o sesión. Cuando se llama en un comunicador, actúa como si se hubiera llamado MPI_Abort en ese comunicador. Si se llama en una ventana o archivo, actúa como si se hubiera llamado MPI_Abort en un comunicador que contiene el grupo de procesos en la ventana o archivo correspondiente. Si se llama en una sesión, aborta solo el proceso local.
  • MPI_ERRORS_RETURN - Devuelve un código de error a la aplicación.

Los programas MPI también pueden implementar sus propios manejadores de errores llamando:

  • MPI_Comm_create_errhandler seguido de MPI_Comm_set_errhandler
  • MPI_File_create_errhandler seguido de MPI_File_set_errhandler
  • MPI_Session_create_errhandler seguido de MPI_Session_set_errhandler o en MPI_Session_init
  • MPI_Win_create_errhandler seguido de MPI_Win_set_errhandler

Nota: Los programas MPI no garantizan que un programa MPI pueda continuar después de un error.

Ver la manpage MPI para una lista completa de códigos de error MPI.

Ver la sección de manejo de errores del estándar MPI-3.1 para más información.
