MPI_Type_create_f90_complex(3) Open MPI MPI_Type_create_f90_complex(3) 
MPI_Type_create_f90_complex - Devuelve un tipo de dato complejo MPI delimitado

SINTAXIS

Sintaxis C

#include <mpi.h>
int MPI_Type_create_f90_complex(int p, int r,
     MPI_Datatype *newtype)

Sintaxis Fortran

USE MPI
! o la forma antigua: INCLUDE 'mpif.h'
MPI_TYPE_CREATE_F90_COMPLEX (P, R, NEWTYPE, IERROR)
     INTEGER P, R, NEWTYPE, IERROR

Sintaxis Fortran 2008

USE mpi_f08
MPI_Type_create_f90_complex(p, r, newtype, ierror)
     INTEGER, INTENT(IN) :: p, r
     TYPE(MPI_Datatype), INTENT(OUT) :: newtype
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARÁMETROS DE ENTRADA

  • p: Precisión, en dígitos decimales (entero).
  • r: Rango de exponentes decimales (entero).

PARÁMETROS DE SALIDA

  • newtype: Nuevo tipo de dato (manejador).
  • ierror: Solo Fortran: Estado de error (entero).

DESCRIPCIÓN

Esta función proporciona una forma de declarar tipos de datos COMPLEX MPI parametrizados por KIND. Los argumentos se interpretan de manera similar a la función F90 SELECTED_REAL_KIND. Los parámetros p y r deben ser enteros escalares. El argumento p representa el nivel requerido de precisión numérica, en dígitos decimales. El parámetro r indica el rango de exponentes deseado: el tipo de dato devuelto tendrá al menos un exponente entre +r y -r (inclusive).

Ya sea p o r, pero no ambos, pueden omitirse de las llamadas a SELECTED_REAL_KIND. De manera similar, cualquiera de los argumentos de MPI_Type_create_f90_complex puede establecerse en MPI_UNDEFINED.

NOTAS

Es erróneo proporcionar valores para p y r que no sean compatibles con el compilador.

La función Fortran SELECTED_REAL_KIND mapea un gran número de pares (p,r) a un número mucho menor de parámetros KIND soportados por el compilador. Los parámetros KIND no son especificados por el lenguaje y no son portátiles. Desde el punto de vista del lenguaje, las variables del mismo tipo base y parámetro KIND son equivalentes, incluso si sus parámetros KIND fueron generados por diferentes argumentos (p,r) a SELECTED_REAL_KIND. Sin embargo, para facilitar la interoperabilidad en un entorno heterogéneo, la equivalencia se define de manera más estricta para los tipos de datos devueltos por MPI_Type_create_f90_complex. Dos tipos de datos MPI, cada uno generado por esta función, coincidirán si y solo si tienen valores idénticos para p y r.

La interacción entre los tipos de datos devueltos por esta función y la representación de datos external32 - utilizada por MPI_Pack_external, MPI_Unpack_external y muchas funciones MPI_File - es sutil. La representación external32 de los tipos de datos devueltos es la siguiente.

if (p > 33) and/or (r > 4931):
        external32 size = n/a (undefined)
else if (p > 15) and/or (r > 307):
        external32 size = 32
else if (p > 6) and/or (r > 37):
        external32 size = 16
else:
        external32 size = 8

Si la representación external32 de un tipo de dato no está definida, también lo están los resultados de usar ese tipo de dato en operaciones que requieren el formato external32. Se debe tener cuidado de no usar tipos de datos incompatibles indirectamente, por ejemplo, como parte de otro tipo de dato o a través de un tipo de dato duplicado, en estas funciones.

Si una variable se declara especificando un valor KIND no predeterminado que no se obtuvo con SELECTED_REAL_KIND (es decir, p y/o r son desconocidos), la única forma de obtener un tipo de dato MPI coincidente es usar las funciones MPI_Sizeof y MPI_Type_match_size.

ERRORES

Casi todas las rutinas MPI devuelven un valor de error; en C, como resultado de la función y en Fortran, en el último argumento.

Antes de que se devuelva el valor de error, se llama al controlador de errores MPI actual asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo). Si no hay ningún objeto de comunicación asociado con la llamada MPI, entonces la llamada se considera adjunta a MPI_COMM_SELF y llamará al controlador de errores MPI asociado. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se usa exclusivamente el Modelo de Sesiones), el error activa el controlador de errores inicial. El controlador de errores inicial se puede cambiar llamando a MPI_Comm_set_errhandler en MPI_COMM_SELF cuando se utiliza el modelo World, o el argumento CLI mpi_initial_errhandler a mpiexec o la clave de información a MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no se ha establecido ningún otro controlador de errores apropiado, entonces el controlador de errores MPI_ERRORS_RETURN se llama para las funciones de E/S MPI y el controlador de errores MPI_ERRORS_ABORT se llama para todas las demás funciones MPI.

Open MPI incluye tres controladores de errores predefinidos que se pueden usar:

  • MPI_ERRORS_ARE_FATAL Causa que el programa aborte todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT Un controlador de errores que puede ser invocado en un comunicador, ventana, archivo o sesión. Cuando se llama en un comunicador, actúa como si se hubiera llamado a MPI_Abort en ese comunicador. Si se llama en una ventana o archivo, actúa como si se hubiera llamado a MPI_Abort en un comunicador que contiene el grupo de procesos de la ventana o archivo correspondiente. Si se llama en una sesión, aborta solo el proceso local.
  • MPI_ERRORS_RETURN Devuelve un código de error a la aplicación.

Las aplicaciones MPI también pueden implementar sus propios controladores de errores llamando a:

  • MPI_Comm_create_errhandler luego MPI_Comm_set_errhandler
  • MPI_File_create_errhandler luego MPI_File_set_errhandler
  • MPI_Session_create_errhandler luego MPI_Session_set_errhandler o en MPI_Session_init
  • MPI_Win_create_errhandler luego MPI_Win_set_errhandler

Tenga en cuenta que MPI no garantiza que un programa MPI pueda continuar después de un error.

Consulte la página del manual de MPI para obtener una lista completa de los códigos de error de MPI.

Consulte la sección de Manejo de Errores del estándar MPI-3.1 para obtener más información.

MPI_Type_create_f90_complex(3)

MPI_Type_create_f90_complex - Creates a complex datatype that corresponds to the Fortran 90 COMPLEX kind.

NAME

MPI_Type_create_f90_complex - Creates a complex datatype that corresponds to the Fortran 90 COMPLEX kind.

SYNOPSIS


C++
    MPI::Datatype MPI::Datatype::Create_f90_complex(int kind)

C
    MPI_Datatype MPI_Type_create_f90_complex(int kind)

Fortran
    MPI_Type_create_f90_complex(kind, newtype)
    integer, intent(in) :: kind
    MPI_Datatype, intent(out) :: newtype

PARAMETERS

kind

Specification of the COMPLEX kind. It must be one of the constants defined in the mpif.h module (e.g., COMPLEX*16, COMPLEX*32, etc.).

newtype

The new MPI datatype that corresponds to the specified Fortran 90 COMPLEX kind.

RETURN

MPI Standard: Primitive datatype creation routines.

DESCRIPTION

MPI_Type_create_f90_complex creates a new MPI datatype that corresponds to the specified Fortran 90 COMPLEX kind. This function is useful when you need to send or receive Fortran 90 complex numbers that may not have a direct mapping to C or C++ complex types. The kind parameter specifies the precision of the complex number. For example, kind=16 would typically correspond to a double-precision complex number (COMPLEX*16 in Fortran), and kind=32 would correspond to a quadruple-precision complex number (COMPLEX*32 in Fortran).

NOTES

The specific values for kind that are supported depend on the MPI implementation. Commonly supported values are 8, 16, and 32, corresponding to single, double, and quadruple precision complex numbers, respectively.

This function is part of the MPI standard for Fortran interface and is designed to facilitate interoperability between Fortran and C/C++ programs using MPI.

ERRORS

When the value of the argument kind is not a supported kind, the MPI routine may return an error code. Error codes are generally one of the following:

MPI_ERR_ARG

Either the input argument kind is invalid or is not supported by the implementation.
