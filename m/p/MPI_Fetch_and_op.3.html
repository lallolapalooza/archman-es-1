MPI_Fetch_and_op(3) Open MPI MPI_Fetch_and_op(3)

MPI_Fetch_and_op — Combina el contenido del búfer de origen con el de un búfer de destino y devuelve el valor del búfer de destino.

SINTAXIS

C Sintaxis

#include <mpi.h>
int MPI_Fetch_and_op(const void *origin_addr, void *result_addr,
     MPI_Datatype datatype, int target_rank, MPI_Aint target_disp,
     MPI_Op op, MPI_Win win)

Fortran Sintaxis

USE MPI
! o la antigua forma: INCLUDE 'mpif.h'
MPI_FETCH_AND_OP(ORIGIN_ADDR, RESULT_ADDR, DATATYPE, TARGET_RANK,
                 TARGET_DISP, OP, WIN, IERROR)
     <tipo> ORIGIN_ADDR, RESULT_ADDR(*)
     INTEGER(KIND=MPI_ADDRESS_KIND) TARGET_DISP
     INTEGER DATATYPE, TARGET_RANK, OP, WIN, IERROR

Fortran 2008 Sintaxis

USE mpi_f08
MPI_Fetch_and_op(origin_addr, result_addr, datatype, target_rank,
             target_disp, op, win, ierror)
     TYPE(*), DIMENSION(..), INTENT(IN) :: origin_addr
     TYPE(*), DIMENSION(..) :: result_addr
     TYPE(MPI_Datatype), INTENT(IN) :: datatype
     INTEGER, INTENT(IN) :: target_rank
     INTEGER(KIND=MPI_ADDRESS_KIND), INTENT(IN) :: target_disp
     TYPE(MPI_Op), INTENET(IN) :: op
     TYPE(MPI_Win), INTENT(IN) :: win
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARAMETROS DE ENTRADA

  • origin_addr: Dirección de origen del búfer (elección).
  • result_addr: Dirección de búfer resultado (elección).
  • datatype: Tipo de datos del elemento en los búferes de origen, resultado y destino (manejo).
  • target_rank: Rango del destino (entero no negativo).
  • target_disp: Desplazamiento desde el inicio del ventana hasta el inicio del búfer de destino (entero no negativo).
  • op: Operación reducir (manejo).
  • win: Objeto de ventana (manejo).

PARAMETRO DE SALIDA

•
ierror: Solo Fortran: Estado de error (entero).

DESCRIPCIÓN

Acumula un elemento de tipo datatype del búfer de origen (origin_addr) en el búfer en el desplazamiento target_disp, en el búfer de destino de la ventana especificada por target_rank y win, usando la operación op y devuelve en el búfer de resultado result_addr el contenido del búfer de destino antes de la acumulación.

Los búferes de origen y resultado (origin_addr y result_addr) deben ser disjuntos. Cualquier operación predefinida para MPI_Rreduce, así como MPI_NO_OP o MPI_REPLACE, pueden especificarse como op; no se pueden usar funciones definidas por el usuario. El datatype debe ser un tipo predefinido. La operación se ejecuta de forma átomica.

Se define una nueva operación predefinida, MPI_REPLACE. Esta corresponde a la función asociativa f(a, b) = b; es decir, el valor actual en la memoria de destino se reemplaza por el valor proporcionado por el búfer de origen.

Se define una nueva operación predefinida, MPI_NO_OP. Esta corresponde a la función asociativa f(a, b) = a; es decir, el valor actual en la memoria de destino se devuelve en el búfer de resultado en el origen y no se realiza ninguna operación en el búfer de destino.

NOTAS

Es la responsabilidad del usuario garantizar que, al usar las funciones de acumulación, el desplazamiento de destino sea tal que las accesos a la ventana se alineen correctamente según los argumentos de tipo de datos en la llamada a la función MPI_Fetch_and_op.

ERRORES

La mayoría de las rutinas MPI devuelven un valor de error; en las rutinas C, el resultado de la función, y en las rutinas Fortran, en el último argumento.

Antes de que el valor de error sea devuelto, se llama al gestor de error asociado con el objeto de comunicación (por ejemplo, communicator, window, file) actual. Si no hay objeto de comunicación asociado con la llamada MPI, se considera que la llamada está asociada a MPI_COMM_SELF y llamará al gestor de error correspondiente. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se use exclusivamente el modelo de Sesiones), se levanta el gestor de error inicial. El gestor de error inicial puede cambiarse llamando a MPI_Comm_set_errhandler sobre MPI_COMM_SELF cuando se use el modelo del Mundo, o a través del argumento mpi_initial_errhandler de mpiexec o a la clave info de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no hay otro gestor de error adecuado, se llama el gestor de error MPI_ERRORS_RETURN para las funciones de I/O MPI y el gestor de error MPI_ERRORS_ABORT para todas las otras funciones MPI.

Open MPI incluye tres gestores de error predefinidos que pueden usarse:

  • MPI_ERRORS_ARE_FATAL : Detiene todos los procesos conectados a MPI.
  • MPI_ERRORS_ABORT : Gestor que puede invocarse en un communicator, window, file o sesión. Cuando se invoca en un communicator, actúa como si se hubiera llamado MPI_Abort en ese communicator. Si se invoca en un window o file, actúa como si se hubiera llamado MPI_Abort en un communicator que contiene el grupo de procesos en el correspondiente window o file. Si se invoca en una sesión, detiene solo el proceso local.
  • MPI_ERRORS_RETURN : Devuelve un código de error a la aplicación.

Los programas MPI pueden también implementar sus propios gestores de error llamando:

  • MPI_Comm_create_errhandler luego MPI_Comm_set_errhandler
  • MPI_File_create_errhandler luego MPI_File_set_errhandler
  • MPI_Session_create_errhandler luego MPI_Session_set_errhandler o al MPI_Session_init
  • MPI_Win_create_errhandler luego MPI_Win_set_errhandler

Nota: Los programas MPI no garantizan que puedan continuar después de un error.

Ver la página de man de MPI para una lista completa de códigos de error MPI.

Ver la sección de Gestores de Error de la especificación MPI-3.1 para más información.
