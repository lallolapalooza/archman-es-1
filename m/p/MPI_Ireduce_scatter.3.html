PARÁMETROS DE ENTRADA

  • sendbuf: Dirección de inicio del búfer de envío (elección).
  • recvcounts: Matriz de enteros que especifica el número de elementos en el resultado distribuido a cada proceso. La matriz debe ser idéntica en todos los procesos que llaman.
  • datatype: Tipo de datos de los elementos del búfer de entrada (manejador).
  • op: Operación (manejador).
  • comm: Comunicador (manejador).
  • info: Información (manejador, persistente).

PARÁMETROS DE SALIDA

  • recvbuf: Dirección de inicio del búfer de recepción (elección).
  • request: Solicitud (manejador, solo no bloqueante).
  • ierror: Solo Fortran: Estado del error (entero).

DESCRIPCIÓN

MPI_Reduce_scatter primero realiza una reducción elemento a elemento en el vector de count = S(i)recvcounts[i] elementos en el búfer de envío definido por sendbuf, count y datatype. A continuación, el vector resultante de resultados se divide en n segmentos disjuntos, donde n es el número de procesos en el grupo. El segmento i contiene recvcounts[i] elementos. El i-ésimo segmento se envía al proceso i y se almacena en el búfer de recepción definido por recvbuf, recvcounts[i] y datatype.

USO DE LA OPCIÓN IN-PLACE

Cuando el comunicador es un intracommunicator, puede realizar una operación de reduce-scatter in-place (el búfer de salida se utiliza como el búfer de entrada). Utilice la variable MPI_IN_PLACE como valor de sendbuf. En este caso, los datos de entrada se toman de la parte superior del búfer de recepción. El área ocupada por los datos de entrada puede ser más larga o más corta que los datos rellenados por los datos de salida.

CUANDO EL COMUNICADOR ES UN INTER-COMUNICADOR

Cuando el comunicador es un inter-comunicador, la operación de reduce-scatter se realiza en dos fases. Primero, el resultado de la reducción realizada en los datos proporcionados por los procesos del primer grupo se distribuye entre los procesos del segundo grupo. Luego ocurre lo inverso: la reducción realizada en los datos proporcionados por los procesos del segundo grupo se distribuye entre los procesos del primer grupo. Para cada grupo, todos los procesos proporcionan el mismo argumento recvcounts, y la suma de los valores recvcounts debe ser la misma para ambos grupos.

NOTAS SOBRE OPERACIONES COLECTIVAS

Las funciones de reducción ( MPI_Op ) no devuelven un valor de error. Por lo tanto, si las funciones detectan un error, lo único que pueden hacer es llamar a MPI_Abort o omitir silenciosamente el problema. Por lo tanto, si cambia el manejador de errores de MPI_ERRORS_ARE_FATAL a otra cosa, por ejemplo, MPI_ERRORS_RETURN, entonces no se indicará ningún error.

La razón de esto son los problemas de rendimiento para garantizar que todas las rutinas colectivas devuelvan el mismo valor de error.

ERRORES

Casi todas las rutinas de MPI devuelven un valor de error; las rutinas C como resultado de retorno de la función y las rutinas Fortran en el último argumento.

Antes de que se devuelva el valor de error, se llama al manejador de errores de MPI actual asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo). Si no hay ningún objeto de comunicación asociado con la llamada MPI, entonces la llamada se considera adjunta a MPI_COMM_SELF y llamará al manejador de errores de MPI asociado. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se utiliza exclusivamente el Modelo de Sesiones), el error activa el manejador de errores inicial. El manejador de errores inicial se puede cambiar llamando a MPI_Comm_set_errhandler en MPI_COMM_SELF cuando se utiliza el modelo World, o el argumento de línea de comandos mpi_initial_errhandler a mpiexec o la clave de información para MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no se ha establecido ningún otro manejador de errores apropiado, entonces se llama al manejador de errores MPI_ERRORS_RETURN para las funciones de E/S de MPI y al manejador de errores MPI_ERRORS_ABORT para todas las demás funciones de MPI.

Open MPI incluye tres manejadores de errores predefinidos que se pueden utilizar:

  • MPI_ERRORS_ARE_FATAL Provoca que el programa aborte todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT Un manejador de errores que se puede invocar en un comunicador, ventana, archivo o sesión. Cuando se llama en un comunicador, actúa como si se hubiera llamado a MPI_Abort en ese comunicador. Si se llama en una ventana o archivo, actúa como si se hubiera llamado a MPI_Abort en un comunicador que contiene el grupo de procesos en la ventana o archivo correspondiente. Si se llama en una sesión, solo aborta el proceso local.
  • MPI_ERRORS_RETURN Devuelve un código de error a la aplicación.

Las aplicaciones MPI también pueden implementar sus propios manejadores de errores llamando a:

  • MPI_Comm_create_errhandler luego MPI_Comm_set_errhandler
  • MPI_File_create_errhandler luego MPI_File_set_errhandler
  • MPI_Session_create_errhandler

NOMBRE

MPI_Ireduce_scatter - Reduce y dispersa datos en un comunicador no bloqueante.

SINTAXIS

#include <mpi.h>

int MPI_Ireduce_scatter(const void *sendbuf, void *recvbuf,
                        const int recvcounts[], const MPI_Datatype datatype,
                        MPI_Op op, MPI_Comm comm, MPI_Request *request);

PARÁMETROS DE ENTRADA

sendbuf
Puntero al búfer de envío (especificación de elección en el raíz).
recvcounts
Matriz de enteros que especifica el número de elementos a recibir de cada proceso en el comunicador.
datatype
Tipo de datos MPI de los elementos en los búferes.
op
Operación de reducción (ej. MPI_SUM, MPI_MAX, MPI_MIN, etc.).
comm
Comunicador.

PARÁMETROS DE SALIDA

recvbuf
Puntero al búfer de recepción.
request
Puntero a la solicitud del MPI (identificador de la operación no bloqueante).

DESCRIPCIÓN

La rutina MPI_Ireduce_scatter es la versión no bloqueante de MPI_Reduce_scatter. Realiza una operación de reducción en los datos de todos los procesos en el comunicador comm, y luego dispersa los resultados en los procesos del comunicador.

La operación se define como un par de MPI_Reduce seguido de MPI_Scatter. El resultado de la operación de reducción se ve como si todos los datos se enviaran al proceso raíz (el proceso con rango 0), y luego los datos se dispersan desde el proceso raíz a todos los procesos del comunicador.

En detalle, la operación de reducción se aplica a los datos en los búferes de envío de todos los procesos y el resultado se almacena en el búfer de recepción del proceso raíz. Luego, el búfer de recepción del proceso raíz se divide en tantos bloques como procesos haya en el comunicador. El bloque i se envía al proceso i.

Cada proceso contribuye con un bloque de datos al conjunto de datos de entrada. El tamaño de este bloque es el número total de elementos especificados por recvcounts[j] para todos los j, es decir, la suma de los elementos especificados en recvcounts.

El búfer de recepción recvbuf en cada proceso i debe ser lo suficientemente grande como para contener recvcounts[i] elementos del tipo especificado por datatype.

La raíz de la operación es el proceso con rango 0 en el comunicador comm. Los búferes de envío y recepción son significativos solo en la raíz, excepto que todos los procesos deben proporcionar un sendbuf no nulo. El recvbuf de los no-raíces es ignorado.

La operación de reducción se aplica a los datos en el orden especificado por op. La operación debe ser una operación reductora predefinida de MPI o una operación reductora definida por el usuario. Las operaciones predefinidas incluyen MPI_SUM, MPI_PROD, MPI_MAX, MPI_MIN, MPI_LAND, MPI_BAND, MPI_LOR, MPI_BOR, MPI_LXOR, MPI_BXOR, MPI_MAXLOC, MPI_MINLOC.

La rutina devuelve un MPI_Request que puede ser utilizado para consultar la finalización de la operación utilizando MPI_Wait o MPI_Test.

USO DE LA OPCIÓN IN-PLACE

Cuando se utiliza la opción in-place, sendbuf y recvbuf se refieren al mismo búfer. Este búfer debe ser lo suficientemente grande como para contener recvcounts[i] elementos del tipo datatype para el proceso i. El resultado de la operación se encuentra en el búfer de recepción después de que la operación se complete. El contenido del búfer de envío original se pierde.

CUANDO EL COMUNICADOR ES UN INTER-COMUNICADOR

Cuando el comunicador comm es un inter-comunicador, la operación se realiza entre los dos grupos de procesos del inter-comunicador. El sendbuf y el recvbuf se especifican en el grupo local. recvcounts se especifica en el grupo local. El op se aplica a los datos de los procesos del grupo remoto. El resultado se devuelve en recvbuf en el grupo local.

El proceso raíz de cada grupo (denominado raíz local y raíz remota, respectivamente) deben tener el mismo valor para el argumento op. En la raíz del grupo local, sendbuf se ignora y el resultado se coloca en recvbuf. En las no-raíces del grupo local, sendbuf y recvbuf se ignoran.

NOTAS SOBRE OPERACIONES COLECTIVAS

Las operaciones colectivas requieren que todos los procesos del comunicador llamen a la rutina con los mismos argumentos (excepto para los búferes de envío/recepción y el rango del proceso). Las diferencias en los argumentos entre los procesos resultarán en un comportamiento indefinido.

ERRORES

La rutina MPI_Ireduce_scatter puede fallar si la operación no se puede completar. Esto puede suceder si los búferes no son lo suficientemente grandes, si los argumentos son inválidos o si la operación de reducción falla.

Los errores que ocurren durante la ejecución de esta operación pueden ser manejados por el manejador de errores global o el manejador de errores de la ventana.

Los siguientes códigos de error pueden ser devueltos por la rutina MPI_Ireduce_scatter:

  • MPI_SUCCESS: Éxito.
  • MPI_ERR_COMM: El comunicador proporcionado no es válido.
  • MPI_ERR_ARG: Argumento de rutina inválido. Esto puede incluir el uso de un tipo de datos no válido, un búfer nulo o un tamaño de búfer incorrecto.
  • MPI_ERR_TYPE: Tipo de datos no válido.
  • MPI_ERR_OP: Operación no válida.
  • MPI_ERR_REQUEST: Solicitud no válida.

El manejo de errores se puede establecer usando MPI_Comm_set_errhandler o MPI_Win_set_errhandler.

Nota: MPI no garantiza que un programa MPI pueda continuar después de un error.

Ver la MPI man page para una lista completa de MPI error codes.

Ver la sección de Error Handling del estándar MPI-3.1 para más información.
