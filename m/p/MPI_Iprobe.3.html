MPI_Iprobe(3)

Paquete: openmpi

Licencias: BSD-3-Clause AND LicenseRef-MPICH

MPI_IPROBE(3) Open MPI MPI_IPROBE(3)

MPI_Iprobe — Comprobación no bloqueante de un mensaje.

SINTAXIS

Sintaxis C

#include <mpi.h>
int MPI_Iprobe(int source, int tag, MPI_Comm comm, int *flag,
     MPI_Status *status)

Sintaxis Fortran

USE MPI
! o la forma antigua: INCLUDE 'mpif.h'
MPI_IPROBE(SOURCE, TAG, COMM, FLAG, STATUS, IERROR)
     LOGICAL FLAG
     INTEGER SOURCE, TAG, COMM, STATUS(MPI_STATUS_SIZE), IERROR

Sintaxis Fortran 2008

USE mpi_f08
MPI_Iprobe(source, tag, comm, flag, status, ierror)
     INTEGER, INTENT(IN) :: source, tag
     TYPE(MPI_Comm), INTENT(IN) :: comm
     LOGICAL, INTENT(OUT) :: flag
     TYPE(MPI_Status) :: status
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARÁMETROS DE ENTRADA

  • source: Rango de origen o MPI_ANY_SOURCE (entero).
  • tag: Valor de etiqueta o MPI_ANY_TAG (entero).
  • comm: Comunicador (handle).

PARÁMETROS DE SALIDA

  • flag: Bandera de espera de mensaje (lógico).
  • status: Objeto de estado (estado).
  • ierror: Solo Fortran: estado de error (entero).

DESCRIPCIÓN

Las operaciones MPI_Probe y MPI_Iprobe permiten comprobar mensajes entrantes sin recibirlos realmente. El usuario puede entonces decidir cómo recibirlos, basándose en la información devuelta por la comprobación (básicamente, la información devuelta por el estado). En particular, el usuario puede asignar memoria para el búfer de recepción, de acuerdo con la longitud del mensaje comprobado.

MPI_Iprobe(source, tag, comm, flag, status) devuelve flag = true si hay un mensaje que puede ser recibido y que coincide con el patrón especificado por los argumentos fuente, etiqueta y comunicador. La llamada coincide con el mismo mensaje que habría sido recibido por una llamada a MPI_Recv(..., source, tag, comm, status) ejecutada en el mismo punto del programa, y devuelve en status el mismo valor que habría sido devuelto por MPI_Recv. En caso contrario, la llamada devuelve flag = false, y deja status indefinido.

Si MPI_Iprobe devuelve flag = true, el contenido del objeto de estado puede ser accedido posteriormente como se describe en la subsección "Estado de Retorno" del capítulo "Comunicación Punto a Punto" en el Estándar MPI para encontrar la fuente, etiqueta y longitud del mensaje comprobado.

Una recepción posterior ejecutada con el mismo contexto, y la fuente y etiqueta devueltas en status por MPI_Iprobe recibirá el mensaje que fue emparejado por la comprobación si ninguna otra recepción intermedia ocurre después de la comprobación. Si el proceso receptor es multihilo, es responsabilidad del usuario asegurarse de que la última condición se cumpla.

El argumento fuente de MPI_Probe puede ser MPI_ANY_SOURCE, y el argumento etiqueta puede ser MPI_ANY_TAG, de modo que se pueda comprobar mensajes de una fuente arbitraria y/o con una etiqueta arbitraria. Sin embargo, se debe proporcionar un contexto de comunicación específico con el argumento comm.

Si su aplicación no necesita examinar el campo status, puede ahorrar recursos utilizando la constante predefinida MPI_STATUS_IGNORE como valor especial para el argumento status.

No es necesario recibir un mensaje inmediatamente después de que se haya comprobado, y el mismo mensaje puede ser comprobado varias veces antes de ser recibido.

NOTA

Los desarrolladores de aplicaciones multihilo deben recordar que dos hilos que llaman a MPI_Iprobe pueden devolver true para el mismo mensaje en ambos hilos.

ERRORES

Casi todas las rutinas MPI devuelven un valor de error; las rutinas C como resultado de la función y las rutinas Fortran en el último argumento.

Antes de que se devuelva el valor de error, se llama al manejador de errores MPI actual asociado con el objeto de comunicación (p. ej., comunicador, ventana, archivo). Si no hay ningún objeto de comunicación asociado con la llamada MPI, entonces la llamada se considera adjunta a MPI_COMM_SELF y llamará al manejador de errores MPI asociado. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/ MPI_Init_thread, después de MPI_Finalize, o cuando se usa exclusivamente el Modelo de Sesiones) el error genera el manejador de errores inicial. El manejador de errores inicial se puede cambiar llamando a MPI_Comm_set_errhandler en MPI_COMM_SELF cuando se usa el modelo World, o el argumento de CLI mpi_initial_errhandler para mpiexec o clave de info para MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no se ha establecido ningún otro manejador de errores apropiado, entonces se llama al manejador de errores MPI_ERRORS_RETURN para las funciones de E/S MPI y al manejador de errores MPI_ERRORS_ABORT para todas las demás funciones MPI.

Open MPI incluye tres manejadores de errores predefinidos que pueden ser utilizados:

  • MPI_ERRORS_ARE_FATAL Hace que el programa aborte todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT Un manejador de errores que se puede invocar en un comunicador, ventana, archivo o sesión. Cuando se llama en un comunicador, actúa como si se hubiera llamado a MPI_Abort en ese comunicador. Si se llama en una ventana o archivo, actúa como si se hubiera llamado a MPI_Abort en un comunicador que contiene el grupo de procesos en la ventana o archivo correspondiente. Si se llama en una sesión, solo aborta el proceso local.
  • MPI_ERRORS_RETURN Devuelve un código de error a la aplicación.

Las aplicaciones MPI también pueden implementar sus propios manejadores de errores llamando a:

  • MPI_Comm_create_errhandler y luego MPI_Comm_set_errhandler
  • MPI_File_create_errhandler y luego MPI_File_set_errhandler
  • MPI_Session_create_errhandler y luego MPI_Session_set_errhandler o en MPI_Session_init
  • MPI_Win_create_errhandler y luego MPI_Win_set_errhandler

Tenga en cuenta que MPI no garantiza que un programa MPI pueda continuar después de un error.

Consulte la página del manual de MPI para obtener una lista completa de los códigos de error de MPI.

Consulte la sección de Manejo de Errores del estándar MPI-3.1 para obtener más información.

Tenga en cuenta que según la sección "Estado de Retorno" en el capítulo "Comunicación Punto a Punto" en el Estándar MPI, los errores MPI en mensajes consultados por MPI_Iprobe no establecen el campo status.MPI_ERROR en el status devuelto. El código de error se pasa siempre al manejador de errores de backend y puede ser devuelto al llamante a través del valor de retorno de MPI_Iprobe si el manejador de errores de backend lo devuelve. El manejador de errores predefinido de MPI MPI_ERRORS_RETURN exhibe este comportamiento, por ejemplo.
