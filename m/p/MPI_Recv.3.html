MPI_Recv — Realiza una recepción bloqueante en modo estándar.

SINTAXIS

Sintaxis C

#include <mpi.h>
int MPI_Recv(void *buf, int count, MPI_Datatype datatype,
     int source, int tag, MPI_Comm comm, MPI_Status *status)

Sintaxis Fortran

USE MPI
! o la forma antigua: INCLUDE 'mpif.h'
MPI_RECV(BUF, COUNT, DATATYPE, SOURCE, TAG, COMM, STATUS, IERROR)
     <type>  BUF(*)
     INTEGER COUNT, DATATYPE, SOURCE, TAG, COMM
     INTEGER STATUS(MPI_STATUS_SIZE), IERROR

Sintaxis Fortran 2008

USE mpi_f08
MPI_Recv(buf, count, datatype, source, tag, comm, status, ierror)
     TYPE(*), DIMENSION(..) :: buf
     INTEGER, INTENT(IN) :: count, source, tag
     TYPE(MPI_Datatype), INTENT(IN) :: datatype
     TYPE(MPI_Comm), INTENT(IN) :: comm
     TYPE(MPI_Status) :: status
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARÁMETROS DE ENTRADA

  • count: Número máximo de elementos a recibir (entero).
  • datatype: Tipo de dato de cada entrada del buffer de recepción (manejador).
  • source: Rango de la fuente (entero).
  • tag: Etiqueta del mensaje (entero).
  • comm: Comunicador (manejador).

PARÁMETROS DE SALIDA

  • buf: Dirección inicial del buffer de recepción (elección).
  • status: Objeto de estado (estado).
  • ierror: Solo Fortran: Estado de error (entero).

DESCRIPCIÓN

Esta operación de recepción básica, MPI_Recv, es bloqueante: devuelve el control solo después de que el buffer de recepción contiene el mensaje recién recibido. Una recepción puede completarse antes de que el envío correspondiente se haya completado (por supuesto, solo puede completarse después de que el envío correspondiente haya comenzado).

La semántica bloqueante de esta llamada se describe en la sección "Modos de Comunicación" del Estándar MPI.

El buffer de recepción contiene un número (definido por el valor de count) de elementos consecutivos. El primer elemento en el conjunto de elementos se encuentra en address_buf. El tipo de cada uno de estos elementos se especifica mediante datatype.

La longitud del mensaje recibido debe ser menor o igual a la longitud del buffer de recepción. Se devuelve un MPI_ERR_TRUNCATE en caso de desbordamiento.

Si llega un mensaje más corto que la longitud del buffer de recepción, solo se modificarán aquellas ubicaciones correspondientes al mensaje recibido (más corto).

NOTAS

El argumento count indica el número máximo de entradas del tipo datatype que se pueden recibir en un mensaje. Una vez que se recibe un mensaje, use la función MPI_Get_count para determinar el número real de entradas dentro de ese mensaje.

Para recibir mensajes de longitud desconocida, use la función MPI_Probe. Para más información sobre MPI_Probe y MPI_Cancel, consulte sus páginas man respectivas y la sección "Probe and Cancel" del Estándar MPI.

Una recepción puede ser recibida por una operación de recepción solo si está dirigida al proceso receptor, y si sus valores de fuente, etiqueta y comunicador (comm) coinciden con los valores de fuente, etiqueta y comm especificados por la operación de recepción. La operación de recepción puede especificar un valor comodín para la fuente y/o la etiqueta, indicando que cualquier fuente y/o etiqueta son aceptables. El valor comodín para la fuente es source = MPI_ANY_SOURCE. El valor comodín para la etiqueta es tag = MPI_ANY_TAG. No hay un valor comodín para comm. El alcance de estos comodines se limita a los procesos del grupo del comunicador especificado.

La etiqueta del mensaje se especifica mediante el argumento tag de la operación de recepción.

El argumento source, si es diferente de MPI_ANY_SOURCE, se especifica como un rango dentro del grupo de procesos asociado con ese mismo comunicador (grupo de procesos remoto, para inter comunicadores). Por lo tanto, el rango de valores válidos para el argumento source es {0,…,n-1} {MPI_ANY_SOURCE}, donde n es el número de procesos en este grupo.

Observe la asimetría entre las operaciones de envío y recepción: una operación de recepción puede aceptar mensajes de un remitente arbitrario; por otro lado, una operación de envío debe especificar un receptor único. Esto coincide con un mecanismo de comunicación de "empuje" (push), donde la transferencia de datos es efectuada por el remitente (en lugar de un mecanismo de "tirar" (pull), donde la transferencia de datos es efectuada por el receptor).

Se permite source = destination, es decir, un proceso puede enviarse un mensaje a sí mismo. Sin embargo, no se recomienda que un proceso se envíe mensajes a sí mismo utilizando las operaciones de envío y recepción bloqueantes descritas anteriormente, ya que esto puede conducir a un interbloqueo. Consulte la sección "Semántica de la Comunicación Punto a Punto" del Estándar MPI para más detalles.

Si su aplicación no necesita examinar el campo status, puede ahorrar recursos utilizando la constante predefinida MPI_STATUS_IGNORE como un valor especial para el argumento status.

ERRORES

Casi todas las rutinas MPI devuelven un valor de error; las rutinas C como resultado del retorno de la función y las rutinas Fortran en el último argumento.

Antes de que se devuelva el valor de error, se llama al controlador de errores MPI actual asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo). Si no hay un objeto de comunicación asociado con la llamada MPI, entonces la llamada se considera adjunta a MPI_COMM_SELF y llamará al controlador de errores MPI asociado. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se usa exclusivamente el Modelo de Sesiones) el error eleva el controlador de errores inicial. El controlador de errores inicial se puede cambiar llamando a MPI_Comm_set_errhandler en MPI_COMM_SELF cuando se usa el modelo World, o el argumento de CLI mpi_initial_errhandler de mpiexec o la clave de información para MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no se ha establecido ningún otro controlador de errores apropiado, entonces se llama al controlador de errores MPI_ERRORS_RETURN para las funciones de E/S de MPI y al controlador de errores MPI_ERRORS_ABORT para todas las demás funciones de MPI.

Open MPI incluye tres controladores de errores predefinidos que se pueden utilizar:

  • MPI_ERRORS_ARE_FATAL Provoca que el programa aborte todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT Un controlador de errores que se puede invocar en un comunicador, ventana, archivo o sesión. Cuando se llama en un comunicador, actúa como si se hubiera llamado a MPI_Abort en ese comunicador. Si se llama en una ventana o archivo, actúa como si se hubiera llamado a MPI_Abort en un comunicador que contiene el grupo de procesos de la ventana o archivo correspondiente. Si se llama en una sesión, solo aborta el proceso local.
  • MPI_ERRORS_RETURN Devuelve un código de error a la aplicación.

Las aplicaciones MPI también pueden implementar sus propios controladores de errores llamando a:

  • MPI_Comm_create_errhandler luego MPI_Comm_set_errhandler
  • MPI_File_create_errhandler luego MPI_File_set_errhandler
  • MPI_Session_create_errhandler luego MPI_Session_set_errhandler o en MPI_Session_init
  • MPI_Win_create_errhandler luego MPI_Win_set_errhandler

Tenga en cuenta que MPI no garantiza que un programa MPI pueda continuar después de un error.

Consulte la página man de MPI para obtener una lista completa de los códigos de error de MPI.

Consulte la sección Manejo de Errores del estándar MPI-3.1 para obtener más información.

Tenga en cuenta que según la sección "Estado de Retorno" en el capítulo "Comunicación Punto a Punto" del Estándar MPI, los errores de MPI en mensajes recibidos por MPI_Recv no establecen el campo status.MPI_ERROR en el status devuelto. DESCRIPTION

This function provides the basic functionality to receive a message. MPI defines several functions to receive messages, which vary in their flexibility and performance characteristics.

The simplest function is MPI_Recv(). It blocks until a message matching the tag and communicator is available and then receives it. The buffer provided must be large enough to hold the message.

The non-blocking variants MPI_Irecv() and MPI_Mrecv() (for multiple receivers) allow other operations to proceed while the receive is pending.

MPI_Probe() and MPI_Improbe() can be used to check for incoming messages without receiving them. This allows the program to determine the size and source of the message before allocating a receive buffer or initiating the receive. This is useful for dynamic message handling.

The _init variants are used for persistent communication requests. They initiate the communication but do not wait for it to complete. The communication can be completed later by calling the corresponding MPI_Start, MPI_Startall, or MPI_Wait functions.

NOTES

The receive buffer must be large enough to accommodate the received message. If the buffer is too small, the behavior is undefined, though typically it will result in an error.

MPI provides several error handling mechanisms. By default, MPI error handlers will abort the process. The MPI_ERRORS_RETURN error handler returns the error code to the calling function, which the user can then check. The pre-defined MPI error handler MPI_ERRORS_RETURN exhibits this behavior, for example.

ERRORS

The behavior of MPI functions in case of an error is determined by the MPI error handler that is set for the communicator. The default error handler is MPI_ERRORS_ARE_FATAL, which causes all MPI processes to abort upon an MPI error. The predefined error handler MPI_ERRORS_RETURN causes the error handler to return the error code to the function. This error code can then be checked by the application. The specific error codes returned by this function are detailed in the MPI standard.
