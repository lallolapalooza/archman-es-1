Paquete: openmpi

MPI_TESTALL(3) Open MPI MPI_TESTALL(3)

MPI_Testall — Comprueba la finalización de todas las comunicaciones iniciadas previamente en una lista.

SINTAXIS

Sintaxis en C

#include <mpi.h>
int MPI_Testall(int count, MPI_Request array_of_requests[],
     int *flag, MPI_Status array_of_statuses[])

Sintaxis Fortran

USE MPI
! o la forma más antigua: INCLUDE 'mpif.h'
MPI_TESTALL(COUNT, ARRAY_OF_REQUESTS, FLAG, ARRAY_OF_STATUSES,
             IERROR)
     LOGICAL FLAG
     INTEGER COUNT, ARRAY_OF_REQUESTS(*)
     INTEGER ARRAY_OF_STATUSES(MPI_STATUS_SIZE,*), IERROR

Sintaxis Fortran 2008

USE mpi_f08
MPI_Testall(count, array_of_requests, flag, array_of_statuses, ierror)
     INTEGER, INTENT(IN) :: count
     TYPE(MPI_Request), INTENT(INOUT) :: array_of_requests(count)
     LOGICAL, INTENT(OUT) :: flag
     TYPE(MPI_Status) :: array_of_statuses(*)
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARÁMETROS DE ENTRADA

  • count: Longitud de la lista (entero).
  • array_of_requests: Array de solicitudes (array de identificadores).

PARÁMETROS DE SALIDA

  • flag: Verdadero si las comunicaciones iniciadas previamente se han completado (lógico).
  • array_of_statuses: Array de objetos de estado (array de estados).
  • ierror: Solo Fortran: Estado de error (entero).

DESCRIPCIÓN

Devuelve flag = verdadero si todas las comunicaciones asociadas a los identificadores activos en el array han completado (esto incluye el caso en que ningún identificador en la lista está activo). En este caso, cada entrada de estado que corresponde a una solicitud de identificador activa se establece al estado de la comunicación correspondiente; si la solicitud fue asignada por una llamada de comunicación no bloqueante, se libera y el identificador se establece a MPI_REQUEST_NULL. Cada entrada de estado que corresponde a un identificador nulo o inactivo se establece como vacía.

En caso contrario, se devuelve flag = falso, no se modifica ninguna solicitud y los valores de las entradas de estado no están definidos. Esta es una operación local.

Si su aplicación no necesita examinar el campo array_of_statuses, puede ahorrar recursos utilizando la constante predefinida MPI_STATUSES_IGNORE, que puede usarse como un valor especial para el argumento array_of_statuses.

Los errores que ocurrieron durante la ejecución de MPI_Testall se manejan de la misma manera que los errores en MPI_Waitall.

NOTA

flag es verdadero solo si todas las solicitudes se han completado. En caso contrario, flag es falso, y ni array_of_requests ni array_of_statuses se modifican.

ERRORES

Casi todas las rutinas MPI devuelven un valor de error; las rutinas C como resultado de retorno de la función y las rutinas Fortran en el último argumento.

Antes de que se devuelva el valor de error, se llama al controlador de errores MPI actual asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo). Si no hay ningún objeto de comunicación asociado con la llamada MPI, entonces la llamada se considera adjunta a MPI_COMM_SELF y llamará al controlador de errores MPI asociado. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se utiliza exclusivamente el Modelo de Sesiones) el error eleva el controlador de errores inicial. El controlador de errores inicial puede ser cambiado llamando a MPI_Comm_set_errhandler en MPI_COMM_SELF cuando se utiliza el modelo World, o el argumento de línea de comandos mpiexec mpi_initial_errhandler o la clave de información de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no se ha configurado ningún otro controlador de errores apropiado, se llama al controlador de errores MPI_ERRORS_RETURN para las funciones de E/S de MPI y al controlador de errores MPI_ERRORS_ABORT para todas las demás funciones MPI.

Open MPI incluye tres controladores de errores predefinidos que pueden ser utilizados:

  • MPI_ERRORS_ARE_FATAL Provoca que el programa aborte todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT Un controlador de errores que puede ser invocado en un comunicador, ventana, archivo o sesión. Cuando se llama en un comunicador, actúa como si se hubiera llamado a MPI_Abort en ese comunicador. Si se llama en una ventana o archivo, actúa como si se hubiera llamado a MPI_Abort en un comunicador que contiene el grupo de procesos en la ventana o archivo correspondiente. Si se llama en una sesión, aborta solo el proceso local.
  • MPI_ERRORS_RETURN Devuelve un código de error a la aplicación.

Las aplicaciones MPI también pueden implementar sus propios controladores de errores llamando a:

  • MPI_Comm_create_errhandler luego MPI_Comm_set_errhandler
  • MPI_File_create_errhandler luego MPI_File_set_errhandler
  • MPI_Session_create_errhandler luego MPI_Session_set_errhandler o en MPI_Session_init
  • MPI_Win_create_errhandler luego MPI_Win_set_errhandler

Tenga en cuenta que MPI no garantiza que un programa MPI pueda continuar después de un error.

Consulte la página man de MPI para obtener una lista completa de los códigos de error de MPI.

Consulte la sección de Manejo de Errores del estándar MPI-3.1 para obtener más información.

Para cada invocación de MPI_Testall, si una o más solicitudes generan un error MPI, solo la primera solicitud MPI que causó un error se pasará a su controlador de errores correspondiente. No se invocarán otros controladores de errores (incluso si varias solicitudes generaron errores). Sin embargo, a todas las solicitudes que generen un error se les establecerá un código de error relevante en el campo correspondiente de status.MPI_ERROR (a menos que se haya utilizado MPI_STATUSES_IGNORE).

Si el controlador de errores invocado permite que MPI_Testall regrese al llamador, el valor MPI_ERR_IN_STATUS será devuelto en los enlaces C y Fortran.
