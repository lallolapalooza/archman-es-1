MPI_Win_allocate_shared(3)

Paquete: openmpi

Licencias: BSD-3-Clause AND LicenseRef-MPICH

MPI_Win_allocate_shared(3) Open MPI MPI_Win_allocate_shared(3)

MPI_Win_allocate_shared — llamada MPI unidireccional que reserva memoria compartida y devuelve un objeto de ventana para operaciones RMA.

SINTAXIS

C Sintaxis

#include <mpi.h>
int MPI_Win_allocate_shared (MPI_Aint size, int disp_unit, MPI_Info info,
                             MPI_Comm comm, void *baseptr, MPI_Win *win)

Fortran Sintaxis

USE MPI
! o la forma antigua: INCLUDE 'mpif.h'
MPI_WIN_ALLOCATE_SHARED(SIZE, DISP_UNIT, INFO, COMM, BASEPTR, WIN, IERROR)
     INTEGER(KIND=MPI_ADDRESS_KIND) SIZE, BASEPTR
     INTEGER DISP_UNIT, INFO, COMM, WIN, IERROR

Fortran 2008 Sintaxis

USE mpi_f08
MPI_Win_allocate_shared(size, disp_unit, info, comm, baseptr, win, ierror)
     USE, INTRINSIC :: ISO_C_BINDING, ONLY : C_PTR
     INTEGER(KIND=MPI_ADDRESS_KIND), INTENT(IN) :: size
     INTEGER, INTENT(IN) :: disp_unit
     TYPE(MPI_Info), INTENT(IN) :: info
     TYPE(MPI_Comm), INTENT(IN) :: comm
     TYPE(C_PTR), INTENT(OUT) :: baseptr
     TYPE(MPI_Win), INTENT(OUT) :: win
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARÁMETROS DE ENTRADA

  • size: Tamaño de la ventana en bytes (entero no negativo).
  • disp_unit: Unidad de tamaño para desplazamientos locales, en bytes (entero positivo).
  • info: Argumento de info (handle).
  • comm: Comunicador (handle).

PARÁMETROS DE SALIDA

  • baseptr: Dirección inicial de la ventana.
  • win: Objeto de ventana devuelto por la llamada (handle).
  • ierror: Solo en Fortran: Estado de error (entero).

DESCRIPCIÓN

MPI_Win_allocate_shared es una llamada colectiva ejecutada por todos los procesos en comm. En cada proceso, reserva memoria de al menos size bytes que se comparte entre todos los procesos en comm, y devuelve un puntero a la parte localmente asignada en baseptr que puede usarse para accesos de carga/store en el proceso del llamador. La memoria localmente asignada puede ser el objetivo de accesos de carga/store por procesos remotos; los punteros de base para otros procesos pueden consultarse mediante la función MPI_Win_shared_query. La llamada también devuelve un objeto de ventana que puede usarse por todos los procesos en comm para realizar operaciones RMA. El valor size puede ser diferente en cada proceso y size = 0 es válid. Es la responsabilidad del usuario garantizar que el comunicador comm represente un grupo de procesos que puedan crear una segmentación de memoria compartida que pueda ser accedida por todos los procesos en el grupo. Las discusiones sobre los razonamientos de MPI_Alloc_mem y MPI_Free_mem en la sección 8.2 de MPI-3.1 también aplican a MPI_Win_allocate_shared; en particular, vea la razonamiento en la sección 8.2 de MPI-3.1 para una explicación de lo que se utiliza para baseptr. La memoria asignada es contigua entre los procesos de rank si no se especifica el clave de info alloc_shared_noncontig. Contigua entre los procesos de rank significa que la dirección inicial de la segmentación de memoria en el proceso i es consecutiva con la última dirección de la segmentación de memoria en el proceso i-1. Esto puede permitir al usuario calcular los desplazamientos de direcciones remotas solo con información local.

Las siguientes claves de info son compatibles:

alloc_shared_noncontig
Si no se establece como true, el estrategia de asignación es asignar memoria contigua entre los procesos de rank. Esto puede limitar la performance en ciertos arquitecturas porque no permite al implementador modificar la disposición de los datos (por ejemplo, la adición de espacios para reducir la latencia de acceso).
blocking_fence
Si se establece como true, el componente osc/sm usará MPI_Barrier para MPI_Win_fence. Si se establece como false, se utilizará un condensador y un contador en su lugar. El valor por defecto es false. Esta clave de info es específica de Open MPI.

Para más información sobre claves de info adicionales, consulte MPI_Win_create.

NOTAS

Las elecciones comunes para disp_unit son 1 (sin escalado) y, en la sintaxis de C, sizeof(type), para un espacio de ventana que consiste en un array de elementos de tipo type. El segundo opción permite usar índices de array en llamadas RMA y que estos estén correctamente escalados para desplazamientos de byte, incluso en entornos heterogéneos.

La llamada MPI_Win_free libera la memoria asignada por MPI_Win_allocate_shared. Por lo tanto, es erróneo liberar manualmente baseptr.

NOTAS EN C

Aunque baseptr es un tipo de void *, esto permite usar fácilmente cualquier objeto de puntero para este parámetro. Este argumento es realmente un tipo de void **.

ERRORES

Más de casi todas las rutinas MPI devuelven un valor de error; las rutinas C devuelven el resultado del función y las rutinas Fortran en el último argumento.

Antes de que el valor de error sea devuelto, se llama a la handler de error asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo) actual. Si no hay objeto de comunicación asociado con la llamada MPI, se considera que la llamada está asociada a MPI_COMM_SELF y se llama al handler asociado con MPI_COMM_SELF. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se use el Modelo de Sesiones exclusivamente), se levanta el handler de error inicial. El handler de error inicial puede cambiarse llamando a MPI_Comm_set_errhandler en MPI_COMM_SELF cuando se use el Modelo del Mundo, o el argumento mpi_initial_errhandler en mpiexec o la clave de información para MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no hay otro handler de error adecuado, se llama el handler de error MPI_ERRORS_RETURN para funciones de I/O MPI y el handler MPI_ERRORS_ABORT para otras funciones MPI.

El Open MPI incluye tres handlers de error prediseñados que pueden usarse:

  • MPI_ERRORS_ARE_FATAL Causa al programa que aborte todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT Un handler de error que puede invocarse en un comunicador, ventana, archivo o sesión. Cuando se invoca en un comunicador, actúa como si se hubiera llamado MPI_Abort en ese comunicador. Si se invoca en una ventana o archivo, actúa como si se hubiera llamado MPI_Abort en un comunicador que contiene el grupo de procesos en la ventana o archivo correspondiente. Si se invoca en una sesión, aborta solo el proceso local.
  • MPI_ERRORS_RETURN Devuelve un código de error a la aplicación.

Las aplicaciones MPI también pueden implementar sus propios handlers de error llamando:

  • MPI_Comm_create_errhandler luego MPI_Comm_set_errhandler
  • MPI_File_create_errhandler luego MPI_File_set_errhandler
  • MPI_Session_create_errhandler luego MPI_Session_set_errhandler o en MPI_Session_init
  • MPI_Win_create_errhandler luego MPI_Win_set_errhandler

Nota: El MPI no garantiza que un programa MPI pueda seguir ejecutándose después de un error.

Ver la sección de Handlers de Error de la especificación MPI-3.1 para más información.
