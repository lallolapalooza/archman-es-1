MPI_Accumulate, MPI_Raccumulate - Combina los contenidos del búfer de origen con los de un búfer de destino.

PARÁMETROS DE ENTRADA

  • origin_addr: Dirección inicial del búfer (elección).
  • origin_count: Número de entradas en el búfer (entero no negativo).
  • origin_datatype: Tipo de dato de cada entrada del búfer (manejador).
  • target_rank: Rango del destino (entero no negativo).
  • target_disp: Desplazamiento desde el inicio de la ventana hasta el principio del búfer de destino (entero no negativo).
  • target_count: Número de entradas en el búfer de destino (entero no negativo).
  • target_datatype: Tipo de dato de cada entrada en el búfer de destino (manejador).
  • op: Operación de reducción (manejador).
  • win: Objeto de ventana (manejador).

PARÁMETRO DE SALIDA

  • MPI_Raccumulate: Solicitud RMA
  • ierror: Solo Fortran: Estado de error (entero).

DESCRIPCIÓN

MPI_Accumulate es una función utilizada para comunicación MPI unidireccional que suma los contenidos del búfer de origen (según se define por origin_addr, origin_count y origin_datatype) al búfer especificado por los argumentos target_count y target_datatype, en el desplazamiento target_disp, dentro de la ventana de destino especificada por target_rank y win, utilizando la operación op. La ventana de destino solo puede ser accedida por procesos dentro del mismo nodo. Esto es similar a MPI_Put, excepto que los datos se combinan en el área de destino en lugar de sobrescribirla.

Cualquiera de las operaciones predefinidas para MPI_Reduce puede ser utilizada. No se pueden usar funciones definidas por el usuario. Por ejemplo, si op es MPI_SUM, cada elemento del búfer de origen se suma al elemento correspondiente en el destino, reemplazando el valor anterior en el destino.

Cada argumento de tipo de dato debe ser un tipo de dato predefinido o un tipo de dato derivado, donde todos los componentes básicos son del mismo tipo de dato predefinido. Ambos argumentos de tipo de dato deben estar construidos a partir del mismo tipo de dato predefinido. La operación op se aplica a los elementos de ese tipo predefinido. El argumento target_datatype no debe especificar entradas superpuestas, y el búfer de destino debe caber en la ventana de destino.

Se define una nueva operación predefinida, MPI_REPLACE. Corresponde a la función asociativa f(a, b) =b; es decir, el valor actual en la memoria de destino es reemplazado por el valor suministrado por el origen.

MPI_Raccumulate es similar a MPI_Accumulate, excepto que asigna un objeto de solicitud de comunicación y lo asocia con el manejador de solicitud (el argumento request) que se puede usar para esperar o probar la finalización. La finalización de una operación MPI_Raccumulate indica que el búfer origin_addr está libre para ser actualizado. No indica que la operación se ha completado en la ventana de destino.

NOTAS

MPI_Put es un caso especial de MPI_Accumulate, con la operación MPI_REPLACE. Tenga en cuenta, sin embargo, que MPI_Put y MPI_Accumulate tienen diferentes restricciones en cuanto a actualizaciones concurrentes.

Es responsabilidad del usuario garantizar que, al utilizar las funciones de acumulación, el argumento de desplazamiento de destino sea tal que los accesos a la ventana estén correctamente alineados de acuerdo con los argumentos de tipo de dato en la llamada a la función MPI_Accumulate.

ERRORES

Casi todas las rutinas de MPI devuelven un valor de error; las rutinas C como el resultado de la función y las rutinas Fortran en el último argumento.

Antes de que se devuelva el valor de error, se llama al controlador de errores MPI actual asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo). Si no hay ningún objeto de comunicación asociado con la llamada MPI, entonces la llamada se considera adjunta a MPI_COMM_SELF y llamará al controlador de errores MPI asociado. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se usa exclusivamente el Modelo de Sesiones) el error eleva el controlador de errores inicial. El controlador de errores inicial se puede cambiar llamando a MPI_Comm_set_errhandler en MPI_COMM_SELF cuando se usa el modelo World, o el argumento de línea de comandos mpiexec mpi_initial_errhandler o la clave de información para MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no se ha establecido ningún otro controlador de errores apropiado, entonces se llama al controlador de errores MPI_ERRORS_RETURN para las funciones de E/S de MPI y al controlador de errores MPI_ERRORS_ABORT para todas las demás funciones de MPI.

Open MPI incluye tres controladores de errores predefinidos que se pueden utilizar:

  • MPI_ERRORS_ARE_FATAL Provoca que el programa aborte todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT Un controlador de errores que se puede invocar en un comunicador, ventana, archivo o sesión. Cuando se llama en un comunicador, actúa como si MPI_Abort se hubiera llamado en ese comunicador. Si se llama en una ventana o archivo, actúa como si MPI_Abort se hubiera llamado en un comunicador que contiene el grupo de procesos en la ventana o archivo correspondiente. Si se llama en una sesión, aborta solo el proceso local.
  • MPI_ERRORS_RETURN Devuelve un código de error a la aplicación.

Las aplicaciones MPI también pueden implementar sus propios controladores de errores llamando a:

  • MPI_Comm_create_errhandler y luego MPI_Comm_set_errhandler
  • MPI_File_create_errhandler y luego MPI_File_set_errhandler
  • MPI_Session_create_errhandler y luego MPI_Session_set_errhandler o en MPI_Session_init

NAME

MPI_Accumulate - Accumulates data from a remote buffer to a local buffer

SYNTAX

INPUT PARAMETERS

• origin_addr
Dirección del buffer de origen (vector de enteros).
• origin_count
Número de elementos en el buffer de origen.
• origin_datatype
Tipo de datos de los elementos en el buffer de origen.
• target_rank
Rango del proceso remoto al que se dirige la operación.
• target_disp
Desplazamiento a la ubicación del buffer de destino en la ventana remota (en unidades de target_datatype).
• target_count
Número de elementos en el buffer de destino.
• target_datatype
Tipo de datos de los elementos en el buffer de destino.
• op
Operación de acumulación (por ejemplo, MPI_SUM, MPI_PROD, MPI_MAX, MPI_MIN, MPI_REPLACE, etc.).
• win
Ventana que se utilizará para el acceso remoto.

OUTPUT PARAMETER

• win
Ventana que se utilizará para el acceso remoto.

DESCRIPTION

La función MPI_Accumulate realiza una operación de acumulación de uno lado. Combina los datos del buffer de origen local con los datos en la ubicación de memoria remota especificada en el buffer de destino. El resultado de esta combinación se almacena en la ubicación de memoria remota. La operación utilizada para combinar los datos se especifica mediante el parámetro op.

La operación de acumulación se realiza de forma atómica con respecto a otros accesos remotos a la misma ubicación de memoria en la ventana remota. Esto significa que si varios procesos intentan acumular en la misma ubicación remota simultáneamente, la operación se comportará como si se ejecutara secuencialmente, sin condiciones de carrera.

Los buffers de origen y destino deben ser del mismo tamaño (es decir, origin_count * sizeof(origin_datatype) == target_count * sizeof(target_datatype)).

La operación MPI_Accumulate es una operación de sincronización. La llamada no retornará hasta que se hayan completado todas las operaciones de acceso remoto asociadas con la ventana.

NOTES

La función MPI_Accumulate se utiliza en el modelo de comunicación de acceso/actualización remota (RMA) de MPI. Requiere que se haya creado una ventana utilizando MPI_Win_create o una función similar.

Las operaciones de acumulación son particularmente útiles para implementar estructuras de datos compartidas y para realizar cálculos paralelos donde los procesos necesitan combinar sus resultados de manera eficiente.

Las operaciones de acumulación se pueden acoplar con las funciones de sincronización de ventanas como MPI_Win_flush, MPI_Win_sync, etc., para controlar el comportamiento y garantizar la finalización de las operaciones.

ERRORS

La función MPI_Accumulate puede fallar si:

  • El comunicador de la ventana no es válido.
  • La ventana no es válida.
  • El tipo de datos de origen o destino no es válido.
  • El rango de destino no es válido.
  • Se produce un error durante la operación de acumulación remota.

Los errores pueden ser manejados por el manejador de errores asociado con la ventana. Se puede establecer un manejador de errores personalizado usando MPI_Win_set_errhandler.

Tenga en cuenta que MPI no garantiza que un programa MPI pueda continuar después de un error.

Consulte la página man de MPI para obtener una lista completa de los códigos de error de MPI.

Consulte la sección de manejo de errores del estándar MPI-3.1 para obtener más información.
