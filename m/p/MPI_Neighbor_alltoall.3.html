Parámetros de entrada

  • sendbuf: Dirección de inicio del buffer de envío (opcional).
  • sendcount: Número de elementos a enviar a cada proceso (entero).
  • sendtype: Tipo de elementos del buffer de envío (handle).
  • recvcount: Número de elementos a recibir de cada proceso (entero).
  • recvtype: Tipo de elementos del buffer de recepción (handle).
  • comm: Comunicador sobre el cual se realizará el intercambio de datos (handle).
  • info: Información (handle, persistente).

Parámetros de salida

  • recvbuf: Dirección de inicio del buffer de recepción (opcional).
  • request: Peticion (handle, no bloqueante).
  • ierror: Solo en Fortran: Estado de error (entero).

Descripción

MPI_Neighbor_alltoall es una operación colectiva en la cual todos los procesos envían y reciben el mismo número de datos a cada vecino. La operación de esta rutina puede representarse así, donde cada proceso realiza 2n (n siendo el número de vecinos en el comunicador comm) comunica punto a punto independientes. El orden de los vecinos y el layout del buffer son determinados por la topología de comm.

Ejemplo de semántica de MPI_Neighbor_alltoall para topologías cartesianas:

MPI_Cart_get(comm, maxdims, dims, periods, coords);
for (dim = 0, i = 0 ; dim < dims ; ++dim) {
    MPI_Cart_shift(comm, dim, 1, &r0, &r1);
    MPI_Isend(sendbuf + i * sendcount * extent(sendtype),
              sendcount, sendtype, r0, ..., comm, ...);
    MPI_Irecv(recvbuf + i * recvcount * extent(recvtype),
              recvcount, recvtype, r0, ..., comm, ...);
    ++i;
    MPI_Isend(sendbuf + i * sendcount * extent(sendtype),
              sendcount, sendtype, r1, ..., comm, &req[i]);
    MPI_Irecv(recvbuf + i * recvcount * extent(recvtype),
              recvcount, recvtype, r1, ..., comm, ...);
    ++i;
}
MPI_Waitall (...);

Cada proceso divide su sendbuf en n bloques - cada uno conteniendo sendcount elementos de tipo sendtype - y divide su recvbuf similarmente según recvcount y recvtype. El proceso j envía el k-ésimo bloque de su sendbuf al vecino k, lo cual coloca los datos en el k-ésimo bloque de su recvbuf. El número de datos enviado debe ser igual al número de datos recibido, por pareja, entre cada par de procesos.

Orden de vecinos

Para una topología de grafos distribuidos creada con MPI_Dist_graph_create, el orden de vecinos en los buffers de envío y recepción en cada proceso es definido por la secuencia retornada por MPI_Dist_graph_neighbors para los destinos y fuentes respectivamente. Para una topología general de grafos creada con MPI_Graph_create, el orden de vecinos en los buffers de envío y recepción es definido por la secuencia de vecinos retornada por MPI_Graph_neighbors. Debe tenerse en cuenta que las topologías de grafos generales deberían generalmente reemplazarse por las topologías de grafos distribuidos.

Para una topología de cartesiano creada con MPI_Cart_create, el orden de vecinos en los buffers de envío y recepción en cada proceso es definido por el orden de los ejes, primero los vecinos en la dirección negativa y luego en la dirección positiva con desplazamiento 1. El número de fuentes y destinos en las rutinas de comunicación es 2*ndims con ndims definido en MPI_Cart_create. Si un vecino no existe, es decir, en el borde de una topología de cartesiano en el caso de una red virtual no periódica (es decir, periods[...]==false), entonces este vecino se define como MPI_PROC_NULL.

Si un vecino en cualquier de las funciones es MPI_PROC_NULL, entonces la comunicación colectiva de vecinos se comporta como una comunicación punto a punto con MPI_PROC_NULL en este sentido. Es decir, el buffer aún está parte de la secuencia de vecinos, pero no se comunica ni se actualiza.

Notas

La opción MPI_IN_PLACE para sendbuf no es significativa para esta función.

Todos los argumentos en todos los procesos son significativos. El argumento comm, en particular, debe describir el mismo comunicador en todos los procesos. comm debe ser un comunicador de tipo cartesian, grafico o dist graph.

Hay dos funciones de biblioteca MPI más generales que MPI_Neighbor_alltoall. MPI_Neighbor_alltoallv permite el intercambio de datos entre buffers que no necesariamente sean contiguos; diferentes procesos pueden enviar y recibir diferente cantidad de datos. MPI_Neighbor_alltoallw amplía la funcionalidad de MPI_Neighbor_alltoallv para permitir el intercambio de datos con distintos tipos de datos.

ERRORS

When an MPI function call fails, an error handler is invoked. The error handler is associated with the communicator (e.g., communicator, window, file) that is called. If no communication object is associated with the MPI call, then the call is considered attached to MPI_COMM_SELF and will call the associated MPI error handler. When MPI_COMM_SELF is not initialized (i.e., before MPI_Init/MPI_Init_thread, after MPI_Finalize, or when using the Sessions Model exclusively) the error raises the initial error handler. The initial error handler can be changed by calling MPI_Comm_set_errhandler on MPI_COMM_SELF when using the World model, or the mpi_initial_errhandler CLI argument to mpiexec or info key to MPI_Comm_spawn/MPI_Comm_spawn_multiple. If no other appropriate error handler has been set, then the MPI_ERRORS_RETURN error handler is called for MPI I/O functions and the MPI_ERRORS_ABORT error handler is called for all other MPI functions.

Open MPI includes three predefined error handlers that can be used:

  • MPI_ERRORS_ARE_FATAL Causes the program to abort all connected MPI processes.
  • MPI_ERRORS_ABORT An error handler that can be invoked on a communicator, window, file, or session. When called on a communicator, it acts as if MPI_Abort was called on that communicator. If called on a window or file, acts as if MPI_Abort was called on a communicator containing the group of processes in the corresponding window or file. If called on a session, aborts only the local process.
  • MPI_ERRORS_RETURN Returns an error code to the application.

MPI applications can also implement their own error handlers by calling:

  • MPI_Comm_create_errhandler then MPI_Comm_set_errhandler
  • MPI_File_create_errhandler then MPI_File_set_errhandler
  • MPI_Session_create_errhandler then MPI_Session_set_errhandler or at MPI_Session_init
  • MPI_Win_create_errhandler then MPI_Win_set_errhandler

Note that MPI does not guarantee that an MPI program can continue past an error.

See the MPI man page for a full list of MPI error codes.

See the Error Handling section of the MPI-3.1 standard for more information.
