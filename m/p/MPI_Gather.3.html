MPI_Gather, MPI_Igather, MPI_Gather_init — recolecta valores de procesos de un grupo.

SINOPSIS

Sintaxis C

#include <mpi.h>
int MPI_Gather(const void *sendbuf, int sendcount, MPI_Datatype sendtype,
    void *recvbuf, int recvcount, MPI_Datatype recvtype, int root,
    MPI_Comm comm)
int MPI_Igather(const void *sendbuf, int sendcount, MPI_Datatype sendtype,
    void *recvbuf, int recvcount, MPI_Datatype recvtype, int root,
    MPI_Comm comm, MPI_Request *request)
int MPI_Gather_init(const void *sendbuf, int sendcount, MPI_Datatype sendtype,
    void *recvbuf, int recvcount, MPI_Datatype recvtype, int root,
    MPI_Comm comm, MPI_Info info, MPI_Request *request)

PARÁMETROS DE ENTRADA

  • sendbuf : Dirección de inicio del buffer de envío (elección).
  • sendcount : Número de elementos en el buffer de envío (entero).
  • sendtype : Tipo de datos de los elementos del buffer de envío (handle).
  • recvcount : Número de elementos para cualquier recibir (entero, significativo solo en el proceso raíz).
  • recvtype : Tipo de datos de los elementos del buffer de recepción (handle, significativo solo en el proceso raíz).
  • root : Rango del proceso de recepción (entero).
  • comm : Comunicador (handle).
  • info : Información (handle, persistente).

PARÁMETROS DE SALIDA

•
recvbuf
Dirección del buffer de recepción (elección, significativo solo en el proceso raíz).
  • request : Petición (handle, no bloqueante).
  • ierror : Solo en Fortran: Estado de error (entero).

DESCRIPCIÓN

Cada proceso (incluido el proceso raíz) envía los contenidos de su buffer de envío al proceso raíz. El proceso raíz recibe los mensajes y los almacena en orden de rango. El resultado es como si cada uno de los n procesos en el grupo (incluido el proceso raíz) hubiera ejecutado una llamada a

MPI_Send(sendbuf, sendcount, sendtype, root, ...)

y el proceso raíz hubiera ejecutado n llamadas a

MPI_Recv(recfbuf + i * recvcount * extent(recvtype), recvcount,
         recvtype, i, ...)

donde extent(recvtype) es el tamaño de tipo obtenido de una llamada a MPI_Type_extent.

Una descripción alternativa es que los n mensajes enviados por los procesos en el grupo se concatenan en orden de rango y el mensaje resultante es recibido por el proceso raíz como si se hubiera ejecutado una llamada a MPI_Recv(recvbuf, recvcount * n, recvtype, ...).

El buffer de recepción se ignora para todos los procesos no raíz.

Los tipos derivados son permitidos para both sendtype y recvtype. El tipo de firma de sendcount, sendtype en el proceso i debe ser igual a la firma de recvcount, recvtype en el proceso raíz. Esto implica que el número de datos enviado debe ser igual al número de datos recibido, por pares entre cada proceso y el proceso raíz. Los tipos de mapas distintos entre emisor y receptor son aún permitidos.

Todos los argumentos a la función son significativos en el proceso raíz, mientras que en otros procesos solo los argumentos sendbuf, sendcount, sendtype, root, comm son significativos. Los argumentos root y comm deben tener los mismos valores en todos los procesos.

La especificación de conteos y tipos no debe causar que ningún lugar en el proceso raíz sea escrito más de una vez. Esta llamada es errónea. Debe notarse que el argumento recvcount en el proceso raíz indica el número de elementos que recibe de cada proceso, no el total de elementos que recibe.

Ejemplo 1: Recoger 100 enteros de cada proceso en el grupo hacia el proceso raíz.

MPI_Comm comm;
int gsize, sendarray[100];
int root, * rbuf;
...
MPI_Comm_size( comm, &gsize);
rbuf = (int*)malloc(gsize * 100 * sizeof(int));
MPI_Gather( sendarray, 100, MPI_INT, rbuf, 100, MPI_INT, root, comm);

Ejemplo 2: Ejemplo anterior modificado — solo el proceso raíz asigna memoria al buffer de recepción.

MPI_Comm comm;
int gsize, sendarray[100];
int root, myrank, * rbuf;
...
MPI_Comm_rank( comm, myrank);
if ( myrank == root) {
  MPI_Comm_size( comm, &gsize);
  rbuf = (int *)malloc(gsize * 100 * sizeof(int));
}
MPI_Gather( sendarray, 100, MPI_INT, rbuf, 100, MPI_INT, root, comm);

Ejemplo 3: Realizar lo mismo que el ejemplo anterior, pero utilizando un tipo derivado. Nota: El tipo no puede ser el conjunto completo de gsize * 100 enteros, ya que el tipo de coincidencia está definido por pares entre el proceso raíz y cada proceso en el grupo.

MPI_Comm comm;
int gsize, sendarray[100];
int root, * rbuf;
MPI_Datatype rtype;
...
MPI_Comm_size( comm, &gsize);
MPI_Type_contiguous( 100, MPI_INT, &rtype);
MPI_Type_commit( &rtype );
rbuf = (int*)malloc(gsize * 100 * sizeof(int));
MPI_Gather( sendarray, 100, MPI_INT, rbuf, 1, rtype, root, comm);

USO DE LA OPCIÓN DE IN-PLACE

Cuando el comunicador es un comunicador intracommunicador, puedes realizar una operación de recolección en lugar de buffer (el buffer de salida se usa como el buffer de entrada). Usa la variable MPI_IN_PLACE como el valor de sendbuf del proceso raíz. En este caso, sendcount y sendtype son ignorados, y la contribución del proceso raíz a la vector recolectado se asume ya estar en el lugar correcto en el buffer de recepción. Nota: MPI_IN_PLACE es un tipo especial; tiene las mismas restricciones en su uso que MPI_BOTTOM. Debido a que la opción de in-place convierte el buffer de recepción en un buffer de envío y recepción, una vinculación Fortran que incluye INTENT debe marcar estos como INOUT, no como OUT.

CUANDO EL COMUNICADOR ES UN COMUNICADOR INTER

Cuando el comunicador es un comunicador inter, la operación de recolección se puede realizar en lugar de buffer (el buffer de salida se usa como el buffer de entrada). Usa la variable MPI_IN_PLACE como el valor de sendbuf del proceso raíz. En este caso, sendcount y sendtype son ignorados, y la contribución del proceso raíz a la vector recolectado se asume ya estar en el lugar correcto en el buffer de recepción. Nota: MPI_IN_PLACE es un tipo especial; tiene las mismas restricciones en su uso que MPI_BOTTOM. Debido a que la opción de in-place convierte el buffer de recepción en un buffer de envío y recepción, una vinculación Fortran que incluye INTENT debe marcar estos como INOUT, no como OUT.

MPI_Gather

INPUT PARAMETERS

•
sendbuf (entrada) Puntero a la memoria que contiene los datos para enviar el proceso raíz.
•
sendcount (entrada) Número de elementos en el búfer de envío.
•
sendtype (entrada) Tipo de datos de los elementos en el búfer de envío.
•
recvbuf (salida) Puntero a la memoria que recibe los datos del proceso raíz.
•
recvcount (entrada) Número de elementos recibidos de cada proceso de origen.
•
recvtype (entrada) Tipo de datos de los elementos en el búfer de recepción.
•
root (entrada) Rango del proceso raíz.
•
comm (entrada) Comunicador.

OUTPUT PARAMETERS

†
recvbuf (salida) Búfer de recepción que contiene los datos recopilados.

DESCRIPTION

La rutina MPI_Gather recopila datos de todos los procesos de un comunicador en un búfer en el proceso raíz.

Todos los procesos en el comunicador envían el contenido de su búfer de envío al proceso raíz. El proceso raíz recibe el contenido del búfer de envío de cada proceso y los concatena en su propio búfer de recepción. El búfer de recepción en el proceso raíz debe ser lo suficientemente grande como para contener los datos de todos los procesos en el comunicador.

Los datos enviados por el proceso i en el comunicador se colocan al principio de los datos enviados por el proceso i+1 en el búfer de recepción del proceso raíz. Específicamente, si el proceso raíz tiene el rango root, entonces el búfer de envío del proceso j se coloca en la posición j * sendcount en el búfer de recepción del proceso root, asumiendo que sendtype y recvtype son tipos de datos base escalares y recvcount es igual a sendcount.

Si comm es un inter-comunicador, entonces el grupo raíz (el grupo que contiene el proceso raíz del MPI_Comm_connect o MPI_Comm_accept de la llamada) debe estar vacío, y el otro grupo debe contener los procesos que enviarán los datos. En este caso, sendbuf, sendcount y sendtype son especificados por los procesos en el grupo de origen. El proceso raíz en el grupo raíz recibe los datos.

USE OF IN-PLACE OPTION

Cuando se utiliza la opción in-place, recvbuf se interpreta como un puntero al mismo búfer que sendbuf. En este caso, los datos de entrada en sendbuf se recopilan en el búfer especificado por recvbuf. Los datos en sendbuf deben ser suficientes para contener los datos de todos los procesos de origen. El búfer de recepción en el proceso raíz debe ser lo suficientemente grande como para contener los datos de todos los procesos en el comunicador.

WHEN COMMUNICATOR IS AN INTER-COMMUNICATOR

Si comm es un inter-comunicador, los procesos en el grupo raíz (el grupo que contiene el proceso raíz de la llamada MPI_Comm_connect o MPI_Comm_accept) deben llamar a MPI_Gather con MPI_ROOT como el valor de su argumento root. Los procesos en el otro grupo deben llamar a MPI_Gather con el rango del proceso raíz en el grupo raíz como el valor de su argumento root. Los procesos en el grupo raíz no envían datos; simplemente reciben los datos de los procesos en el otro grupo. El búfer de envío de los procesos en el grupo de origen debe ser consistente con el búfer de recepción del proceso raíz en el grupo raíz.

Si el comunicador es un inter-comunicador, el proceso raíz en el primer grupo recopila datos de todos los procesos en el segundo grupo. El primer grupo define el proceso raíz. Ese proceso utiliza MPI_ROOT como el valor de su argumento raíz. Los procesos restantes utilizan MPI_PROC_NULL como el valor de su argumento raíz. Todos los procesos en el segundo grupo utilizan el rango de ese proceso raíz en el primer grupo como el valor de su argumento raíz. El argumento del búfer de envío de los procesos en el primer grupo debe ser consistente con el argumento del búfer de recepción del proceso raíz en el segundo grupo.

ERRORS

Casi todas las rutinas MPI devuelven un valor de error; las rutinas C como resultado de retorno de la función y las rutinas Fortran en el último argumento.

Antes de que se devuelva el valor de error, se llama al controlador de error MPI actual asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo). Si no hay ningún objeto de comunicación asociado con la llamada MPI, entonces la llamada se considera adjunta a MPI_COMM_SELF y llamará al controlador de error MPI asociado. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se utiliza exclusivamente el Modelo de Sesiones) el error eleva el controlador de error inicial. El controlador de error inicial se puede cambiar llamando a MPI_Comm_set_errhandler en MPI_COMM_SELF cuando se utiliza el modelo World, o el argumento de CLI mpi_initial_errhandler para mpiexec o la clave info para MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no se ha establecido ningún otro controlador de error apropiado, entonces se llama al controlador de error MPI_ERRORS_RETURN para las funciones de E/S de MPI y al controlador de error MPI_ERRORS_ABORT para todas las demás funciones de MPI.

Open MPI incluye tres controladores de error predefinidos que se pueden utilizar:

  • MPI_ERRORS_ARE_FATAL Provoca que el programa aborte todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT Un controlador de error que se puede invocar en un comunicador, ventana, archivo o sesión. Cuando se llama en un comunicador, actúa como si se hubiera llamado a MPI_Abort en ese comunicador. Si se llama en una ventana o archivo, actúa como si se hubiera llamado a MPI_Abort en un comunicador que contiene el grupo de procesos en la ventana o archivo correspondiente. Si se llama en una sesión, solo aborta el proceso local.
  • MPI_ERRORS_RETURN Devuelve un código de error a la aplicación.

Las aplicaciones MPI también pueden implementar sus propios controladores de error llamando a:

  • MPI_Comm_create_errhandler luego MPI_Comm_set_errhandler
  • MPI_File_create_errhandler luego MPI_File_set_errhandler
  • MPI_Session_create_errhandler luego MPI_Session_set_errhandler o en MPI_Session_init
  • MPI_Win_create_errhandler luego MPI_Win_set_errhandler

Tenga en cuenta que MPI no garantiza que un programa MPI pueda continuar después de un error.

Consulte la página del manual de MPI para obtener una lista completa de los códigos de error de MPI.

Consulte la sección de Manejo de Errores del estándar MPI-3.1 para obtener más información.
