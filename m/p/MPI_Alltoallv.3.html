PARÁMETROS DE ENTRADA

  • sendbuf: Dirección de inicio del búfer de envío.
  • sendcounts: Arreglo de enteros, donde la entrada i especifica el número de elementos a enviar al rango i.
  • sdispls: Arreglo de enteros, donde la entrada i especifica el desplazamiento (desfase desde sendbuf, en unidades de sendtype) desde el cual enviar datos al rango i.
  • sendtype: Tipo de datos de los elementos del búfer de envío.
  • recvcounts: Arreglo de enteros, donde la entrada j especifica el número de elementos a recibir del rango j.
  • rdispls: Arreglo de enteros, donde la entrada j especifica el desplazamiento (desfase desde recvbuf, en unidades de recvtype) al cual los datos del rango j deben ser escritos.
  • recvtype: Tipo de datos de los elementos del búfer de recepción.
  • comm: Comunicador sobre el cual se intercambiarán los datos.
  • info: Información (manejador, solo persistente)

PARÁMETROS DE SALIDA

  • recvbuf: Dirección del búfer de recepción.
  • request: Solicitud (manejador, solo no bloqueante).
  • ierror: Solo Fortran: Estado de error.

DESCRIPCIÓN

MPI_Alltoallv es una operación colectiva generalizada en la que todos los procesos envían datos a y reciben datos de todos los demás procesos. Añade flexibilidad a MPI_Alltoall al permitir al usuario especificar datos para enviar y recibir en estilo vector (a través de un desplazamiento y un recuento de elementos). El funcionamiento de esta rutina se puede pensar de la siguiente manera, donde cada proceso realiza 2n (n siendo el número de procesos en el comunicador comm) comunicaciones punto a punto independientes (incluida la comunicación consigo mismo).

MPI_Comm_size(comm, &n);
for (i = 0, i < n; i++)
    MPI_Send(sendbuf + sdispls[i] * extent(sendtype),
        sendcounts[i], sendtype, i, ..., comm);
for (i = 0, i < n; i++)
    MPI_Recv(recvbuf + rdispls[i] * extent(recvtype),
        recvcounts[i], recvtype, i, ..., comm);

El proceso j envía el k-ésimo bloque de su sendbuf local al proceso k, el cual coloca los datos en el j-ésimo bloque de su recvbuf local.

Cuando un par de procesos intercambia datos, cada uno puede pasar recuentos y tipos de datos diferentes, siempre que el emisor especifique la misma cantidad de datos a enviar (en bytes) que la que el receptor espera recibir.

Tenga en cuenta que el proceso i puede enviar una cantidad de datos diferente al proceso j de la que recibe del proceso j. Además, un proceso puede enviar cantidades de datos completamente diferentes a procesos distintos dentro del comunicador.

CUANDO EL COMUNICADOR ES UN INTERCOMUNICADOR

Cuando el comunicador es un intercomunicador, la operación de recolección ocurre en dos fases. Los datos se recolectan de todos los miembros del primer grupo y se reciben por todos los miembros del segundo grupo. Luego, los datos se recolectan de todos los miembros del segundo grupo y se reciben por todos los miembros del primer grupo. La operación exhibe un comportamiento simétrico y full-duplex.

El primer grupo define el proceso raíz. El proceso raíz utiliza MPI_ROOT como valor de root. Todos los demás procesos del primer grupo utilizan MPI_PROC_NULL como valor de root. Todos los procesos del segundo grupo utilizan el rango del proceso raíz en el primer grupo como valor de root.

Cuando el comunicador es un intracomunicador, estos grupos son los mismos y la operación ocurre en una sola fase.

USO DE LA OPCIÓN IN-PLACE

Cuando el comunicador es un intracomunicador, puede realizar una operación de todos a todos in-place (el búfer de salida se utiliza como búfer de entrada). Utilice la variable MPI_IN_PLACE como valor de sendbuf. En este caso, sendcounts, sdispls y sendtype se ignoran. Se asume que los datos de entrada de cada proceso se encuentran en el área donde ese proceso recibiría su propia contribución al búfer de recepción.

NOTAS

La especificación de recuentos y desplazamientos no debe hacer que ninguna ubicación se escriba más de una vez.

Todos los argumentos en todos los procesos son significativos. El argumento comm, en particular, debe describir el mismo comunicador en todos los procesos.

Los desfases de sdispls y rdispls se miden en unidades de sendtype y recvtype, respectivamente. Compárese esto con MPI_Alltoallw, donde estos desfases se miden en bytes.

ERRORS

All MPI routines that return an error value on failure must always handle all standard MPI errors. The MPI standard specifies the following error values that the MPI functions can return:

MPI_SUCCESS
No error.
MPI_ERR_ARG
One or more arguments are invalid. This is the error returned if the `sendcounts` array contains negative values or if `recvcounts` contains negative values. It is also returned if the derived datatypes are invalid or if the sum of the elements in `sendcounts` is not equal to the sum of the elements in `recvcounts`.
MPI_ERR_BUFFER
Invalid buffer pointer. This error is returned if the buffer is not allocated or points to uninitialized memory.
MPI_ERR_COMM
Invalid communicator. No out-of-range communicator must be given to a routine that binds to a communicator.
MPI_ERR_COUNT
Invalid count. This error is returned if the count is negative.
MPI_ERR_DATATYPE
Invalid datatype argument. This error is returned if the datatype is invalid for the operation.
MPI_ERR_DISP
Invalid displacement. This error is returned if the displacement is negative.
MPI_ERR_INTERN
Internal error: Not applicable.
MPI_ERR_IO
IO error.
MPI_ERR_PENDING
Pending request. This error is returned if a request is pending and the associated buffers are still in use.
MPI_ERR_REQUEST
Invalid request. No out-of-range request must be given to a routine that binds to a request.
MPI_ERR_ROOT
Invalid root. This error is returned if the root argument is not valid for the specified operation.
MPI_ERR_TOPOLOGY
Invalid topology.
MPI_ERR_TRUNCATE
Message truncated. This error is returned if a message is larger than the receive buffer.
MPI_ERR_UNKNOWN
Unknown error.
MPI_ERR_WIN
Invalid window.

MPI function calls that return an error code will invoke the current MPI error handler if it is set. The error handler is invoked on the communicator that the MPI function is associated with. If no communicator is explicitly associated with the MPI function call, the call is considered attached to MPI_COMM_SELF. In this case, the error handler for MPI_COMM_SELF is invoked. The default error handler for MPI_COMM_SELF is MPI_ERRORS_ARE_FATAL. The error handler can be changed by calling MPI_Comm_set_errhandler on the MPI_COMM_SELF communicator.

The `sendcounts`, `recvcounts`, `sdispls`, `rdispls`, and `MPI_Datatypes` arguments can be declared as Fortran procedures or C functions in the last argument. Before the error value is returned, the current MPI error handler associated with the communication object (e.g., communicator, window, file) is called. If no communication object is associated with the MPI call, then the call is considered attached to MPI_COMM_SELF and will call the associated MPI error handler. When MPI_COMM_SELF is not initialized (i.e., before MPI_Init/MPI_Init_thread, after MPI_Finalize, or when using the Sessions Model exclusively) the error raises the initial error handler. The initial error handler can be changed by calling MPI_Comm_set_errhandler on MPI_COMM_SELF when using the World model, or the mpi_initial_errhandler CLI argument to mpiexec or info key to MPI_Comm_spawn/MPI_Comm_spawn_multiple. If no other appropriate error handler has been set, then the MPI_ERRORS_RETURN error handler is called for MPI I/O functions and the MPI_ERRORS_ABORT error handler is called for all other MPI functions.

Open MPI includes three predefined error handlers that can be used:

  • MPI_ERRORS_ARE_FATAL Causes the program to abort all connected MPI processes.
  • MPI_ERRORS_ABORT An error handler that can be invoked on a communicator, window, file, or session. When called on a communicator, it acts as if MPI_Abort was called on that communicator. If called on a window or file, acts as if MPI_Abort was called on a communicator containing the group of processes in the corresponding window or file. If called on a session, aborts only the local process.
  • MPI_ERRORS_RETURN Returns an error code to the application.

MPI applications can also implement their own error handlers by calling:

  • MPI_Comm_create_errhandler then MPI_Comm_set_errhandler
  • MPI_File_create_errhandler then MPI_File_set_errhandler
  • MPI_Session_create_errhandler then MPI_Session_set_errhandler or at MPI_Session_init
  • MPI_Win_create_errhandler then MPI_Win_set_errhandler

Note that MPI does not guarantee that an MPI program can continue past an error.

See the MPI man page for a full list of MPI error codes.

See the Error Handling section of the MPI-3.1 standard for more information.
