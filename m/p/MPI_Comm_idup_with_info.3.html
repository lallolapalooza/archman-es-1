MPI_Comm_idup_with_info(3) Open MPI MPI_Comm_idup_with_info(3)

MPI_Comm_idup_with_info — Iniciar la duplicación no bloqueada de un comunicador existente con toda su información cachada.

Sintaxis

Sintaxis C

#include <mpi.h>
int MPI_Comm_idup_with_info(MPI_Comm comm, MPI_Info info, MPI_Comm *newcomm, MPI_Request *request)

Sintaxis Fortran

USE MPI
! o la forma antigua: INCLUDE 'mpif.h'
MPI_COMM_IDUP_WITH_INFO(COMM, INFO, NEWCOMM, REQUEST, IERROR)
    INTEGER    COMM, INFO, NEWCOMM, REQUEST, IERROR

Sintaxis Fortran 2008

USE mpi_f08
MPI_Comm_idup_with_info(comm, info, newcomm, request, ierror)
    TYPE(MPI_Comm), INTENT(IN) :: comm
    TYPE(MPI_Info), INTENT(IN) :: info
    TYPE(MPI_Comm), INTENT(OUT) :: newcomm
    TYPE(MPI_Request), INTENT(OUT) :: request
    INTEGER, OPTIONAL, INTENT(OUT) :: ierror

Parámetro de entrada

•
comm: Comunicador (handle). Objeto de información (handle).

Parámetros de salida

  • newcomm: Copia del comunicador (handle).
  • request: Solicitud de comunicación (handle).
  • ierror: Solo Fortran: Estado de error (entero).

Descripción

MPI_Comm_idup_with_info inicia la duplicación no bloqueada de un comunicador existente comm con todos sus valores de información almacenados. Para cada valor de información, la función de callback correspondiente determina el valor asociado a este clave en el nuevo comunicador; una acción particular que puede realizar una función de callback de duplicación es eliminar el valor de la información del nuevo comunicador. El comunicador devuelto en newcomm no estará disponible hasta que la solicitud esté completada. Los indicadores proporcionados por el argumento info están asociados al comunicador de salida.

La completación de una solicitud de duplicación de comunicador puede determinarse llamando a cualquier de MPI_Wait, MPI_Waitany, MPI_Test o MPI_Testany con la solicitud devuelta por esta función.

Notas

Esta operación se utiliza para proporcionar una llamada de biblioteca paralela con un espacio de comunicación duplicado que tenga las mismas propiedades que el comunicador original. Esto incluye cualquier atributo (ver abajo) y topologías (ver el capítulo Process Topologies en el MPI Standard). Esta llamada es válida incluso si hay comunicaciones punto a punto pendientes involucradas en el comunicador comm. Una llamada típica podría incluir una MPI_Comm_idup_with_info al inicio de una llamada paralela y una MPI_Comm_free de ese comunicador duplicado al final de la llamada. Otros modelos de gestión de comunicadores también son posibles.

Esta llamada aplica a ambos comunicadores intranodos y intercomunicadores.

Nota: No está definida por el estándar MPI qué ocurre si la función de callback de copia de atributos invoca otras funciones MPI. En Open MPI, no es válido para las funciones de callback de copia de atributos (o sus hijos) agregar o eliminar atributos en el mismo objeto sobre el cual se está ejecutando la función de callback de copia de atributos.

Errores

Más que una error value; los rutines C devuelven el valor de error y los rutines Fortran en el último argumento.

Antes de devolver el valor de error, se llama al error handler actual asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo) que se está utilizando. Si no hay objeto de comunicación asociado con la llamada MPI, la llamada se considera asociada a MPI_COMM_SELF y se llama al error handler asociado. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se use el modelo de Sesiones exclusivamente), el error genera el error handler inicial. El error handler inicial puede cambiarse llamando a MPI_Comm_set_errhandler en MPI_COMM_SELF cuando se use el modelo de Mundo, o al argumento CLI mpi_initial_errhandler de mpiexec o a la clave info de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no hay otro error handler apropiado establecido, se llama el error handler MPI_ERRORS_RETURN para las funciones de I/O MPI y el error handler MPI_ERRORS_ABORT para todas las otras funciones MPI.

Open MPI incluye tres handlers de error predeterminados que pueden utilizarse:

  • MPI_ERRORS_ARE_FATAL : Detiene todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT : Handler que puede invocarse en un comunicador, ventana, archivo o sesión. Cuando se invoca en un comunicador, actúa como si se hubiera llamado MPI_Abort en ese comunicador. Si se invoca en una ventana o archivo, actúa como si se hubiera llamado MPI_Abort en un comunicador que contiene el conjunto de procesos en la ventana o archivo correspondiente. Si se invoca en una sesión, detiene solo el proceso local.
  • MPI_ERRORS_RETURN : Devuelve un código de error a la aplicación.

Las aplicaciones MPI pueden también implementar sus propios handlers de error llamando:

  • MPI_Comm_create_errhandler luego MPI_Comm_set_errhandler
  • MPI_File_create_errhandler luego MPI_File_set_errhandler
  • MPI_Session_create_errhandler luego MPI_Session_set_errhandler o al MPI_Session_init
  • MPI_Win_create_errhandler luego MPI_Win_set_errhandler

Nota: MPI no garantiza que una aplicación MPI pueda continuar después de un error.

Ver la página de man de MPI para una lista completa de códigos de error MPI.

Ver la sección de Gestión de Errores de la versión 3.1 del estándar MPI para más información.
