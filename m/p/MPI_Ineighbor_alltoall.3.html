PARÁMETROS DE ENTRADA

  • sendbuf: Dirección de inicio del búfer de envío (elección).
  • sendcount: Número de elementos a enviar a cada proceso (entero).
  • sendtype: Tipo de datos de los elementos del búfer de envío (manejador).
  • recvcount: Número de elementos a recibir de cada proceso (entero).
  • recvtype: Tipo de datos de los elementos del búfer de recepción (manejador).
  • comm: Comunicador sobre el cual intercambiar datos (manejador).
  • info: Información (manejador, solo persistente).

PARÁMETROS DE SALIDA

  • recvbuf: Dirección de inicio del búfer de recepción (elección).
  • request: Solicitud (manejador, solo no bloqueante).
  • ierror: Solo Fortran: Estado de error (entero).

DESCRIPCIÓN

MPI_Neighbor_alltoall es una operación colectiva en la que todos los procesos envían y reciben la misma cantidad de datos a cada vecino. La operación de esta rutina se puede representar de la siguiente manera, donde cada proceso realiza 2n (siendo n el número de vecinos en el comunicador comm) comunicaciones punto a punto independientes. Los vecinos y la disposición de los búferes están determinados por la topología de comm.

Ejemplo de semántica de MPI_Neighbor_alltoall para topologías cartesianas:

MPI_Cart_get(comm, maxdims, dims, periods, coords);
for (dim = 0, i = 0 ; dim < dims ; ++dim) {
    MPI_Cart_shift(comm, dim, 1, &r0, &r1);
    MPI_Isend(sendbuf + i * sendcount * extent(sendtype),
              sendcount, sendtype, r0, ..., comm, ...);
    MPI_Irecv(recvbuf + i * recvcount * extent(recvtype),
              recvcount, recvtype, r0, ..., comm, ...);
    ++i;
    MPI_Isend(sendbuf + i * sendcount * extent(sendtype),
              sendcount, sendtype, r1, ..., comm, &req[i]);
    MPI_Irecv(recvbuf + i * recvcount * extent(recvtype),
              recvcount, recvtype, r1, ..., comm, ...);
    ++i;
}
MPI_Waitall (...);

Cada proceso divide su sendbuf local en n bloques, cada uno que contiene sendcount elementos del tipo sendtype, y divide su recvbuf de manera similar según recvcount y recvtype. El proceso j envía el bloque k de su sendbuf local al vecino k, que coloca los datos en el bloque j de su recvbuf local. La cantidad de datos enviados debe ser igual a la cantidad de datos recibidos, por pares, entre cada par de procesos.

ORDEN DE VECINOS

Para una topología de grafo distribuido, creada con MPI_Dist_graph_create, la secuencia de vecinos en los búferes de envío y recepción en cada proceso se define como la secuencia devuelta por MPI_Dist_graph_neighbors para destinos y orígenes, respectivamente. Para una topología de grafo general, creada con MPI_Graph_create, el orden de los vecinos en los búferes de envío y recepción se define como la secuencia de vecinos devuelta por MPI_Graph_neighbors. Tenga en cuenta que las topologías de grafo generales generalmente deben ser reemplazadas por las topologías de grafo distribuidas.

Para una topología cartesiana, creada con MPI_Cart_create, la secuencia de vecinos en los búferes de envío y recepción en cada proceso se define por el orden de las dimensiones, primero el vecino en la dirección negativa y luego en la dirección positiva con un desplazamiento de 1. El número de orígenes y destinos en las rutinas de comunicación es 2 * ndims, con ndims definido en MPI_Cart_create. Si un vecino no existe, es decir, en el borde de una topología cartesiana en el caso de una dimensión de cuadrícula virtual no periódica (es decir, periods[…]==false), entonces este vecino se define como MPI_PROC_NULL.

Si un vecino en cualquiera de las funciones es MPI_PROC_NULL, entonces la comunicación colectiva de vecindario se comporta como una comunicación punto a punto con MPI_PROC_NULL en esa dirección. Es decir, el búfer sigue siendo parte de la secuencia de vecinos, pero no se comunica ni se actualiza.

NOTAS

La opción MPI_IN_PLACE para sendbuf no es significativa para esta función.

Todos los argumentos en todos los procesos son significativos. El argumento comm, en particular, debe describir el mismo comunicador en todos los procesos. comm debe ser un comunicador cartesiano, de grafo o de grafo distribuido.

Existen dos funciones de la biblioteca MPI que son más generales que MPI_Neighbor_alltoall. MPI_Neighbor_alltoallv permite la comunicación de todos a todos hacia y desde búferes que no necesitan ser contiguos; diferentes procesos pueden enviar y recibir diferentes cantidades de datos. MPI_Neighbor_alltoallw amplía la funcionalidad de MPI_Neighbor_alltoallv para permitir el intercambio de datos con diferentes tipos de datos.

ERRORES

Casi todas las rutinas MPI devuelven un valor de error; las rutinas C como resultado de retorno de la función y las rutinas Fortran en el último argumento.

Si no hay ningún objeto de comunicación asociado con la llamada MPI, entonces la llamada se considera adjunta a MPI_COMM_SELF y llamará al manejador de errores MPI asociado. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se usa el modelo de Sesiones exclusivamente) el error invoca el manejador de errores inicial. Open MPI incluye tres manejadores de errores predefinidos que se pueden utilizar:

  • MPI_ERRORS_ARE_FATAL Provoca que el programa aborte todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT Un manejador de errores que puede ser invocado en un comunicador, ventana, archivo o sesión. Cuando se llama en un comunicador, actúa como si se hubiera llamado a MPI_Abort en ese comunicador. Si se llama en una ventana o archivo, actúa como si se hubiera llamado a MPI_Abort en un comunicador que contiene el grupo de procesos de la ventana o archivo correspondiente. Si se llama en una sesión, aborta solo el proceso local.
  • MPI_ERRORS_RETURN Devuelve un código de error a la aplicación.

Las aplicaciones MPI también pueden implementar sus propios manejadores de errores llamando a:

  • MPI_Comm_create_errhandler luego MPI_Comm_set_errhandler
  • MPI_File_create_errhandler luego MPI_File_set_errhandler
  • MPI_Session_create_errhandler luego MPI_Session_set_errhandler o en MPI_Session_init
  • MPI_Win_create_errhandler luego MPI_Win_set_errhandler

Tenga en cuenta que MPI no garantiza que un programa MPI pueda continuar después de un error.
