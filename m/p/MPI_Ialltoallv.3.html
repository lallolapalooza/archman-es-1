Parámetros de entrada

  • sendbuf: Dirección de inicio del buffer de envío.
  • sendcounts: Array de enteros, donde la entrada i especifica el número de elementos a enviar al proceso i.
  • sdispls: Array de enteros, donde la entrada i especifica el desplazamiento (offset desde sendbuf, en unidades de sendtype) desde el cual se envían los datos al proceso i.
  • sendtype: Tipo de dato de los elementos del buffer de envío.
  • recvcounts: Array de enteros, donde la entrada j especifica el número de elementos a recibir del proceso j.
  • rdispls: Array de enteros, donde la entrada j especifica el desplazamiento (offset desde recvbuf, en unidades de recvtype) a donde se deben escribir los datos del proceso j.
  • recvtype: Tipo de dato de los elementos del buffer de recepción.
  • comm: Comunicador sobre el cual se realiza el intercambio de datos.
  • info: Info (handle, persistente solo)

Parámetros de salida

  • recvbuf: Dirección del buffer de recepción.
  • request: Petición (handle, no bloqueada).
  • ierror: Solo en Fortran: Estado de error.

Descripción

MPI_Alltoallv es una operación colectiva generalizada en la que todos los procesos envían datos a y reciben datos de todos los otros procesos. Esta le da flexibilidad a MPI_Alltoall permitiendo al usuario especificar datos a enviar y recibir en un estilo vectorial (a través de un desplazamiento y un contador de elemento). La operación de esta rutina puede pensarse como sigue, donde cada proceso realiza 2n (n siendo el número de procesos en el comunicador comm) comunicaciones punto a punto independientes (incluyendo comunicación consigo mismo).

MPI_Comm_size(comm, &n);
for (i = 0, i < n; i++)
    MPI_Send(sendbuf + sdispls[i] * extent(sendtype),
        sendcounts[i], sendtype, i, ..., comm);
for (i = 0, i < n; i++)
    MPI_Recv(recvbuf + rdispls[i] * extent(recvtype),
        recvcounts[i], recvtype, i, ..., comm);

El proceso j envía el bloque k de su propio sendbuf al proceso k, que coloca los datos en el bloque j de su propio recvbuf.

Cuando un par de procesos intercambian datos, cada uno puede pasar diferentes valores de contador de elementos y tipo de dato, siempre que el emisor especifique el mismo número de bytes a enviar (en bytes) que el receptor espera recibir.

Nota: El proceso i puede enviar un número diferente de datos al proceso j de lo que reciba del proceso j. Además, un proceso puede enviar diferentes cantidades de datos a diferentes procesos en el comunicador.

CUANDO EL COMUNICADOR ES UN INTERCOMUNICADOR

Cuando el comunicador es un intercomunicador, la operación de recolección ocurre en dos fases. Los datos se recolectan de todos los miembros del primer grupo y se reciben por todos los miembros del segundo grupo. Luego, los datos se recolectan de todos los miembros del segundo grupo y se reciben por todos los miembros del primero. Esta operación exhibe un comportamiento simétrico, full-duplex.

El primer grupo define el proceso raíz. El proceso raíz usa MPI_ROOT como el valor de root. Todos los otros procesos en el primer grupo usan MPI_PROC_NULL como el valor de root. Todos los procesos en el segundo grupo usan el número de rango del proceso raíz en el primer grupo como el valor de root.

Cuando el comunicador es un intracomunicador, estos grupos son los mismos, y la operación ocurre en una sola fase.

Uso de la opción en lugar de sí mismo

Cuando el comunicador es un intracomunicador, puedes realizar una operación all-to-all en lugar de sí mismo (el buffer de salida se usa como el buffer de entrada). Usa la variable MPI_IN_PLACE como el valor de sendbuf. En este caso, sendcounts, sdispls y sendtype se ignoran. Los datos de entrada de cada proceso se asumen que están en el área donde ese proceso enviaría su propia contribución al buffer de recepción.

Notas

Las especificaciones de contadores y desplazamientos no deberían causar que ninguna ubicación sea escrita más de una vez.

Todos los argumentos en todos los procesos son significativos. El argumento comm, en particular, debe describir el mismo comunicador en todos los procesos.

Los desplazamientos de sdispls y rdispls se miden en unidades de sendtype y recvtype respectivamente. Compara esto con MPI_Alltoallw, donde estos desplazamientos se miden en bytes.

Errores

Más que casi todas las rutinas MPI devuelven un valor de error.

INPUT PARAMETERS

sendcounts
Number of elements to send to each process.
sendtypes
Datatype of send elements to each process.
displs
Displacements of send data from the beginning of the send buffer to each process.
recvcounts
Number of elements to receive from each process.
recvtypes
Datatype of receive elements from each process.
recvdispls
Displacements of receive data from the beginning of the receive buffer from each process.
comm
Communicator.

OUTPUT PARAMETERS

request
MPI request handle.

DESCRIPTION

Performs a non-blocking generalized all-to-all communication. This is a generalized version of MPI_Alltoall in that each process can send a different number of elements to, and receive a different number of elements from, other processes. The send and receive buffers are described by counts, types, and displacements. Specifically, the i-th process sends data from its send buffer described by sendcounts[i], sendtypes[i], and displs[i] to the i-th process in the communicator. Similarly, the i-th process receives data into its receive buffer described by recvcounts[i], recvtypes[i], and recvdispls[i] from the i-th process in the communicator.

The send buffer is described by the arguments sendcounts, sendtypes, and displs. The sendcounts array specifies the number of elements to be sent to each process. The sendtypes array specifies the datatype of the elements to be sent to each process. The displs array specifies the displacement (in terms of the number of elements of the corresponding datatype) of the data for each process from the beginning of the send buffer.

The receive buffer is described by the arguments recvcounts, recvtypes, and recvdispls. The recvcounts array specifies the number of elements to be received from each process. The recvtypes array specifies the datatype of the elements to be received from each process. The recvdispls array specifies the displacement (in terms of the number of elements of the corresponding datatype) of the data for each process from the beginning of the receive buffer.

All three arrays (counts, types, and displacements) must be of length equal to the size of the communicator.

The specification of the communication is one-sided: process i sends data to process j and process j receives data from process i. The data sent by process i to process j is specified by sendcounts[j], sendtypes[j], and displs[j]. The data received by process j from process i is specified by recvcounts[i], recvtypes[i], and recvdispls[i].

All arguments are input arguments except for request, which is an output argument.

The Fortran 2008 ELATREE-like interface is also provided.

USE OF IN-PLACE OPTION

When the communicator is a derived Cartesian communicator or a communicator obtained from duplicated communicator, then all input arrays in the C call are referenced relative to the same buffer, and the buffer must be specified as MPI_IN_PLACE. In this case, the data is received directly from the send buffer. The send and receive buffer arguments are all equal to MPI_IN_PLACE. The sendcounts, sendtypes, and displs arguments describe the data sent to the other processes, and the recvcounts, recvtypes, and recvdispls arguments describe the data received from the other processes. The data sent to process j is specified by sendcounts[j], sendtypes[j], and displs[j], and the data received from process i is specified by recvcounts[i], recvtypes[i], and recvdispls[i].

NOTES

A common use case is to send data from process i to process j and receive data from process j to process i. However, this is not required. The data can be sent to and received from any process. It is also possible for the send and receive operations to overlap.

The non-blocking functions MPI_Ialltoallv returns an MPI request handle. This handle can be used to check for completion of the operation and to free the request handle itself using MPI_Wait.

ERRORS

All MPI routines (except MPI_Wtime and MPI_Wtick) check for an error at the same time the routine returns. If the error value is caught, then the current MPI error handler is called. If the error handler returns, then the C routine returns the error code. The MPI standard guarantees that only MPI routines called after a communication error may return an error code other than MPI_SUCCESS.

The error handler, if set, is called before the C routine returns. If no communication object is associated with the MPI call, then the call is considered attached to MPI_COMM_SELF and will call the associated MPI error handler. When MPI_COMM_SELF is not initialized (i.e., before MPI_Init/MPI_Init_thread, after MPI_Finalize, or when using the Sessions Model exclusively) the error raises the initial error handler. The initial error handler can be changed by calling MPI_Comm_set_errhandler on MPI_COMM_SELF when using the World model, or the mpi_initial_errhandler CLI argument to mpiexec or info key to MPI_Comm_spawn/MPI_Comm_spawn_multiple. If no other appropriate error handler has been set, then the MPI_ERRORS_RETURN error handler is called for MPI I/O functions and the MPI_ERRORS_ABORT error handler is called for all other MPI functions.

Open MPI includes three predefined error handlers that can be used:

  • MPI_ERRORS_ARE_FATAL Causes the program to abort all connected MPI processes.
  • MPI_ERRORS_ABORT An error handler that can be invoked on a communicator, window, file, or session. When called on a communicator, it acts as if MPI_Abort was called on that communicator. If called on a window or file, acts as if MPI_Abort was called on a communicator containing the group of processes in the corresponding window or file. If called on a session, aborts only the local process.
  • MPI_ERRORS_RETURN Returns an error code to the application.

MPI applications can also implement their own error handlers by calling:

  • MPI_Comm_create_errhandler then MPI_Comm_set_errhandler
  • MPI_File_create_errhandler then MPI_File_set_errhandler
  • MPI_Session_create_errhandler then MPI_Session_set_errhandler or at MPI_Session_init
  • MPI_Win_create_errhandler then MPI_Win_set_errhandler

Note that MPI does not guarantee that an MPI program can continue past an error.

See the MPI man page for a full list of MPI error codes.

See the Error Handling section of the MPI-3.1 standard for more information.
