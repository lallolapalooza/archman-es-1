PARÁMETROS DE ENTRADA

  • sendbuf: Dirección del búfer de envío (opcional, significativo solo en la raíz).
  • sendcounts: Array de enteros (de tamaño igual al del grupo) que especifica el número de elementos a enviar a cada procesador.
  • displs: Array de enteros (de tamaño igual al del grupo). La entrada i especifica el desplazamiento (relativo a sendbuf) desde donde tomar los datos de salida para el proceso i.
  • sendtype: Tipo de datos de los elementos del búfer de envío (manejador).
  • recvcount: Número de elementos en el búfer de recepción (entero).
  • recvtype: Tipo de datos de los elementos del búfer de recepción (manejador).
  • root: Rango del proceso de envío (entero).
  • comm: Comunicador (manejador).
  • info: Información (manejador, solo persistente).

PARÁMETROS DE SALIDA

  • recvbuf: Dirección del búfer de recepción (opcional).
  • request: Solicitud (manejador, solo no bloqueante).
  • ierror: Solo Fortran: Estado de error (entero).

DESCRIPCIÓN

MPI_Scatterv es la operación inversa a MPI_Gatherv.

MPI_Scatterv extiende la funcionalidad de MPI_Scatter al permitir una cantidad variable de datos a enviar a cada proceso, ya que sendcounts es ahora un array. También permite mayor flexibilidad en cuanto a dónde se toman los datos en la raíz, al proporcionar el nuevo argumento, displs.

El resultado es como si la raíz ejecutara n operaciones de envío,

MPI_Send(sendbuf + displs[i] * extent(sendtype),
         sendcounts[i], sendtype, i, ...);
// y cada proceso ejecutara una recepción,
MPI_Recv(recvbuf, recvcount, recvtype, root, ...)

El búfer de envío se ignora para todos los procesos que no son la raíz.

La firma de tipo implícita por sendcount[i], sendtype en la raíz debe ser igual a la firma de tipo implícita por recvcount, recvtype en el proceso i (sin embargo, los mapas de tipo pueden ser diferentes). Esto implica que la cantidad de datos enviados debe ser igual a la cantidad de datos recibidos, par a par entre cada proceso y la raíz. Todavía se permiten mapas de tipo distintos entre el remitente y el receptor.

Todos los argumentos de la función son significativos en el proceso root, mientras que en otros procesos, solo los argumentos recvbuf, recvcount, recvtype, root, comm son significativos. Los argumentos root y comm deben tener valores idénticos en todos los procesos.

La especificación de recuentos, tipos y desplazamientos no debe causar que ninguna ubicación en la raíz se lea más de una vez.

Ejemplo 1: El reverso del Ejemplo 5 en la página del manual de MPI_Gatherv. Tenemos un stride variable entre bloques en el lado de envío (raíz), en el lado de recepción recibimos 100 - i elementos en la i-ésima columna de un array C de 100 x 150 en el proceso i.

MPI_Comm comm;
int gsize,recvarray[100][150],*rptr;
int root, *sendbuf, myrank, bufsize, *stride;
MPI_Datatype rtype;
int i, *displs, *scounts, offset;
...
MPI_Comm_size( comm, &gsize);
MPI_Comm_rank( comm, &myrank );
stride = (int *)malloc(gsize*sizeof(int));
...
/* stride[i] para i = 0 a gsize-1 se establece de alguna manera
 * sendbuf proviene de otro lugar
 */
...
displs = (int *)malloc(gsize*sizeof(int));
scounts = (int *)malloc(gsize*sizeof(int));
offset = 0;
for (i=0; i<gsize; ++i) {
    displs[i] = offset;
    offset += stride[i];
    scounts[i] = 100 - i;
}
/* Crear tipo de datos para la columna que estamos recibiendo
 */
MPI_Type_vector( 100-myrank, 1, 150, MPI_INT, &rtype);
MPI_Type_commit( &rtype );
rptr = &recvarray[0][myrank];
MPI_Scatterv(sendbuf, scounts, displs, MPI_INT,
             rptr, 1, rtype, root, comm);

Ejemplo 2: El reverso del Ejemplo 1 en el manual de MPI_Gather . El proceso raíz dispersa conjuntos de 100 enteros a los otros procesos, pero los conjuntos de 100 están separados por enteros stride en el búfer de envío. Requiere el uso de MPI_Scatterv, donde stride >= 100.

MPI_Comm comm;
int gsize,*sendbuf;
int root, rbuf[100], i, *displs, *scounts;
...
MPI_Comm_size(comm, &gsize);
sendbuf = (int *)malloc(gsize*stride*sizeof(int));
...
displs = (int *)malloc(gsize*sizeof(int));
scounts = (int *)malloc(gsize*sizeof(int));
for (i=0; i<gsize; ++i) {
   displs[i] = i*stride;
   scounts[i] = 100;
}
MPI_Scatterv(sendbuf, scounts, displs, MPI_INT,
             rbuf, 100, MPI_INT, root, comm);

USO DE LA OPCIÓN IN-PLACE

Cuando el comunicador es un intracommunicador, puedes realizar una operación de dispersión in-place (el búfer de salida se utiliza como búfer de entrada). Usa la variable MPI_IN_PLACE como valor del recvbuf del proceso raíz. En este caso, recvcount y recvtype se ignoran, y el proceso raíz no envía ningún dato.

SYNTAX

MPI_Scatterv_init

Initializes a scatterv operation.

int MPI_Scatterv_init(MPI_Comm comm, const void *sendbuf, const int sendcounts[],
                      const int displacements[], MPI_Datatype sendtype,
                      void *recvbuf, int recvcount, MPI_Datatype recvtype,
                      int root, MPI_Info info, MPI_Request *request)

INPUT PARAMETERS

comm
Communicator with all participating processes (handle).
sendbuf
Address of send buffer (choice).
sendcounts
Array of integers specifying the number of elements to send to each process (array of length of group size).
displacements
Array of integers specifying the displacements of the send buffer for each process (array of length of group size).
sendtype
Datatype of elements in send buffer.
recvbuf
Address of receive buffer (choice).
recvcount
Number of elements in receive buffer.
recvtype
Datatype of elements in receive buffer.
root
Rank of root process (integer).
info
Information hint object (handle).

OUTPUT PARAMETERS

request
Communication request (handle).

DESCRIPTION

MPI_Scatterv_init is a generalized collective operation that prepares a scatterv operation. It is functionally equivalent to MPI_Scatterv, but it returns a communication request handle rather than performing the communication directly. The actual communication is performed when the request is passed to MPI_Start or MPI_Startall.

The operation consists of a scatter from the root process to all processes in the communicator. The root process sends blocks of data from its send buffer to the receive buffers of other processes. All processes receive a block of data from the root.

The amount of data sent by the root to process i is determined by sendcounts[i] and sendtype. The size of the data sent to process i must be equal to the size of the data received by process i, which is determined by recvcount and recvtype.

The displacements array specifies the offset, in units of the number of elements specified by sendtype, of each send block within the send buffer. Thus, the data for process i starts at the address &sendbuf[displacements[i] * sizeof(sendtype)].

The recvbuf argument is significant only at the root. All other processes can specify MPI_IN_PLACE as the value for recvbuf. If MPI_IN_PLACE is used, the data sent by the root is placed directly into the receive buffer specified by the caller. The receive buffer argument of the root process must be consistent with the receive buffer argument of the other processes.

The info argument is a handle to an MPI information object that can be used to specify performance hints for the operation.

USE OF IN-PLACE OPTION

When all processes provide the same communicator, and when the communicator is not an inter-communicator, then all processes execute the same call. The recvbuf argument is specified as MPI_IN_PLACE. In this case, the contribution of the receive buffer to the communication is the same as if it were the send buffer. The send buffer must be large enough to hold the data sent by the root process. The root process sends data from its sendbuf argument. All other processes receive data into their recvbuf argument.

Note that MPI_IN_PLACE is a special kind of value; it has the same restrictions on its use as MPI_BOTTOM.

Because the in-place option converts the receive buffer into a send-and-receive buffer, a Fortran binding that includes INTENT must mark these as INOUT, not OUT.

WHEN COMMUNICATOR IS AN INTER-COMMUNICATOR

When the communicator is an inter-communicator, the root process in the first group sends data to all processes in the second group. The first group defines the root process. That process uses MPI_ROOT as the value of its root argument. The remaining processes use MPI_PROC_NULL as the value of their root argument. All processes in the second group use the rank of that root process in the first group as the value of their root argument. The receive buffer argument of the root process in the first group must be consistent with the receive buffer argument of the processes in the second group.

ERRORS

Almost all MPI routines return an error value; C routines as the return result of the function and Fortran routines in the last argument.

Before the error value is returned, the current MPI error handler associated with the communication object (e.g., communicator, window, file) is called. If no communication object is associated with the MPI call, then the call is considered attached to MPI_COMM_SELF and will call the associated MPI error handler. When MPI_COMM_SELF is not initialized (i.e., before MPI_Init/MPI_Init_thread, after MPI_Finalize, or when using the Sessions Model exclusively) the error raises the initial error handler. The initial error handler can be changed by calling MPI_Comm_set_errhandler on MPI_COMM_SELF when using the World model, or the mpi_initial_errhandler CLI argument to mpiexec or info key to MPI_Comm_spawn/MPI_Comm_spawn_multiple. If no other appropriate error handler has been set, then the MPI_ERRORS_RETURN error handler is called for MPI I/O functions and the MPI_ERRORS_ABORT error handler is called for all other MPI functions.

Open MPI includes three predefined error handlers that can be used:

  • MPI_ERRORS_ARE_FATAL Causes the program to abort all connected MPI processes.
  • MPI_ERRORS_ABORT An error handler that can be invoked on a communicator, window, file, or session. When called on a communicator, it acts as if MPI_Abort was called on that communicator. If called on a window or file, acts as if MPI_Abort was called on a communicator containing the group of processes in the corresponding window or file. If called on a session, aborts only the local process.
  • MPI_ERRORS_RETURN Returns an error code to the application.

MPI applications can also implement their own error handlers by calling:

  • MPI_Comm_create_errhandler then MPI_Comm_set_errhandler
  • MPI_File_create_errhandler then MPI_File_set_errhandler
  • MPI_Session_create_errhandler then MPI_Session_set_errhandler or at MPI_Session_init
  • MPI_Win_create_errhandler then MPI_Win_set_errhandler

Note that MPI does not guarantee that an MPI program can continue past an error.

See the MPI man page for a full list of MPI error codes.

See the Error Handling section of the MPI-3.1 standard for more information.
