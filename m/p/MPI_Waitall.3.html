MPI_Waitall(3)

Paquete: openmpi

Licencias: BSD-3-Clause AND LicenseRef-MPICH

MPI_Waitall(3) Open MPI MPI_Waitall(3)

MPI_Waitall — Espera hasta que todas las comunicaciones asociadas con los manejadores activos en la lista hayan terminado.

SINTAXIS

Sintaxis C

#include <mpi.h>
int MPI_Waitall(int count, MPI_Request array_of_requests[],
     MPI_Status *array_of_statuses)

Sintaxis Fortran

USE MPI
! o la antigua forma: INCLUDE 'mpif.h'
MPI_WAITALL(COUNT, ARRAY_OF_REQUESTS, ARRAY_OF_STATUSES, IERROR)
     INTEGER COUNT, ARRAY_OF_REQUESTS(*)
     INTEGER ARRAY_OF_STATUSES(MPI_STATUS_SIZE,*), IERROR

Sintaxis Fortran 2008

USE mpi_f08
MPI_Waitall(count, array_of_requests, array_of_statuses, ierror)
     INTEGER, INTENT(IN) :: count
     TYPE(MPI_Request), INTENT(INOUT) :: array_of_requests(count)
     TYPE(MPI_Status) :: array_of_statuses(*)
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARÁMETROS DE ENTRADA

  • count: Longitud de la lista (entero).
  • array_of_requests: Array de solicitudes (array de manejadores).

PARÁMETROS DE SALIDA

  • array_of_statuses: Array de objetos de estado (array de estado).
  • ierror: Solo en Fortran: Estado de error (entero).

DESCRIPCIÓN

Bloquea hasta que todas las operaciones de comunicación asociadas con los manejadores activos en la lista hayan terminado, y devuelve el estado de todas estas operaciones (incluye el caso donde ninguno de los manejadores en la lista esté activo). Ambos arrays tienen el mismo número de entradas válidas. La entrada i-ésima en array_of_statuses se establece al estado de retorno de la i-ésima operación. Las solicitudes que fueron creadas por operaciones de comunicación no bloqueadas se liberan, y los manejadores correspondientes en el array se establecen a MPI_REQUEST_NULL. El listado puede contener manejadores nulos o inactivos. La llamada establece a vacío el estado de cada entrada correspondiente.

La ejecución sin errores de MPI_Waitall(count, array_of_requests, array_of_statuses) tiene el mismo efecto que la ejecución de MPI_Wait(&array_of_request[i], &array_of_statuses[i]), para i=0,..., count-1, en algún orden arbitrario. La llamada MPI_Waitall con un array de longitud 1 es equivalente a MPI_Wait.

Si una o más de las operaciones de comunicación completadas por una llamada a MPI_Waitall fallan, es deseable devolver información específica sobre cada operación de comunicación. La función MPI_Waitall devolverá en este caso el código de error MPI_ERR_IN_STATUS y establecerá el campo de error de cada estado en un código específico. Este código será MPI_SUCCESS si la operación específica completó; será otro código específico si falló; o puede ser MPI_ERR_PENDING si no ha fallado ni terminado. La función MPI_Waitall devolverá MPI_SUCCESS si no hubo solicitud con error, o devolverá otro código de error si falló debido a otros motivos (como argumentos inválidos). En este caso, no actualizará los campos de error de los estados.

Si tu aplicación no necesita examinar el campo array_of_statuses, puedes ahorrar recursos utilizando la constante predefinida MPI_STATUSES_IGNORE como un valor especial para el argumento array_of_statuses.

ERRORES

La mayoría de las rutinas MPI devuelven un valor de error; las rutinas C devuelven el resultado de la función y las rutinas Fortran en el último argumento.

Antes de que el valor de error sea devuelto, se llama al manejador de error asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo) actual. Si no hay objeto de comunicación asociado con la llamada MPI, se considera que la llamada está asociada a MPI_COMM_SELF y se llama al manejador correspondiente. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se utiliza el modelo de Sesiones exclusivamente), se lanza el error inicial. El manejador inicial puede cambiarse llamando a MPI_Comm_set_errhandler sobre MPI_COMM_SELF cuando se usa el modelo del Mundo, o el argumento mpi_initial_errhandler de mpiexec o la clave info de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no hay otro manejador de error adecuado, se llama al manejador MPI_ERRORS_RETURN para las funciones de I/O de MPI y al manejador MPI_ERRORS_ABORT para todas las otras funciones de MPI.

Open MPI incluye tres manejadores de error predeterminados que pueden ser usados:

  • MPI_ERRORS_ARE_FATAL Causa que el programa aborte todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT Un manejador de error que puede ser invocado en un comunicador, ventana, archivo o sesión. Cuando se invoca en un comunicador, actúa como si se hubiera llamado MPI_Abort en ese comunicador. Si se invoca en una ventana o archivo, actúa como si se hubiera llamado MPI_Abort en un comunicador que contiene el grupo de procesos correspondiente en la ventana o archivo. Si se invoca en una sesión, aborta solo el proceso local.
  • MPI_ERRORS_RETURN Devuelve un código de error al aplicativo.

Las aplicaciones MPI también pueden implementar sus propios manejadores de error llamando:

  • MPI_Comm_create_errhandler luego MPI_Comm_set_errhandler
  • MPI_File_create_errhandler luego MPI_File_set_errhandler
  • MPI_Session_create_errhandler luego MPI_Session_set_errhandler o en MPI_Session_init
  • MPI_Win_create_errhandler luego MPI_Win_set_errhandler

Nota: MPI no garantiza que un programa MPI pueda continuar después de un error.

Ver la sección de manejo de errores de la especificación MPI-3.1 para más información.

Para cada invocación de MPI_Waitall, si alguna solicitud genera un error MPI, solo la primera solicitud MPI que causó el error se pasa a su correspondiente manejador de error. No se invocan otros manejadores de error (incluso si múltiples solicitudes generaron errores). Sin embargo, todas las solicitudes que generaron un error tendrán un código de error relevante almacenado en el campo correspondiente status.MPI_ERROR (excepto si se usó MPI_STATUSES_IGNORE).

Si el manejador de error invocado permite a MPI_Waitall devolverse al llamador, se devolverá el valor MPI_ERR_IN_STATUS en las bindings C y Fortran.
