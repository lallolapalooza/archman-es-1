MPI_Allreduce_init(3)

Paquete: openmpi

Licencias: BSD-3-Clause AND LicenseRef-MPICH

MPI_ALLREDUCE_INIT(3) Open MPI MPI_ALLREDUCE_INIT(3)

MPI_Allreduce, MPI_Iallreduce, MPI_Allreduce_init - Combina valores de todos los procesos y distribuye el resultado de vuelta a todos los procesos.

SINTAXIS

                   MPI_Datatype datatype, MPI_Op op, MPI_Comm comm,

PARÁMETROS DE ENTRADA

  • sendbuf: Dirección de inicio del buffer de envío (elección).
  • count: Número de elementos en el buffer de envío (entero).
  • datatype: Tipo de datos de los elementos del buffer de envío (manejador).
  • op: Operación (manejador).
  • comm: Comunicador (manejador).
  • info: Info (manejador, solo persistente).

PARÁMETROS DE SALIDA

  • recvbuf: Dirección de inicio del buffer de recepción (elección).
  • request: Solicitud (manejador, solo no bloqueante).
  • ierror: Solo Fortran: Estado de error (entero).

DESCRIPCIÓN

Igual que MPI_Reduce excepto que el resultado aparece en el buffer de recepción de todos los miembros del grupo.

Ejemplo 1: Una rutina que calcula el producto de un vector y una matriz que están distribuidos en un grupo de procesos y devuelve la respuesta en todos los nodos (comparar con el Ejemplo 2, con MPI_Reduce, a continuación).

SUBROUTINE PAR_BLAS2(m, n, a, b, c, comm)
REAL a(m), b(m,n)    ! slice local de la matriz
REAL c(n)            ! resultado
REAL sum(n)
INTEGER n, comm, i, j, ierr
! suma local
DO j= 1, n
  sum(j) = 0.0
  DO i = 1, m
    sum(j) = sum(j) + a(i)*b(i,j)
  END DO
END DO
! suma global
CALL MPI_ALLREDUCE(sum, c, n, MPI_REAL, MPI_SUM, comm, ierr)
! devuelve el resultado en todos los nodos
RETURN

Ejemplo 2: Una rutina que calcula el producto de un vector y una matriz que están distribuidos en un grupo de procesos y devuelve la respuesta en el nodo cero.

SUBROUTINE PAR_BLAS2(m, n, a, b, c, comm)
REAL a(m), b(m,n)    ! slice local de la matriz
REAL c(n)            ! resultado
REAL sum(n)
INTEGER n, comm, i, j, ierr
! suma local
DO j= 1, n
  sum(j) = 0.0
  DO i = 1, m
    sum(j) = sum(j) + a(i)*b(i,j)
  END DO
END DO
! suma global
CALL MPI_REDUCE(sum, c, n, MPI_REAL, MPI_SUM, 0, comm, ierr)
! devuelve el resultado en el nodo cero (y basura en los otros nodos)
RETURN

USO DE LA OPCIÓN IN-PLACE

Cuando el comunicador es un intracommunicador, se puede realizar una operación all-reduce in-place (el buffer de salida se utiliza como buffer de entrada). Utilice la variable MPI_IN_PLACE como valor de sendbuf en todos los procesos.

Tenga en cuenta que MPI_IN_PLACE es un tipo especial de valor; tiene las mismas restricciones de uso que MPI_BOTTOM.

Dado que la opción in-place convierte el buffer de recepción en un buffer de envío y recepción, una vinculación de Fortran que incluya INTENT debe marcarlas como INOUT, no OUT.

CUANDO EL COMUNICADOR ES UN INTER-COMUNICADOR

Cuando el comunicador es un inter-comunicador, la operación de reducción ocurre en dos fases. Los datos se reducen de todos los miembros del primer grupo y se reciben en todos los miembros del segundo grupo. Luego, los datos se reducen de todos los miembros del segundo grupo y se reciben en todos los miembros del primero. La operación exhibe un comportamiento simétrico y full-duplex.

Cuando el comunicador es un intra-comunicador, estos grupos son los mismos y la operación ocurre en una sola fase.

NOTAS SOBRE OPERACIONES COLECTIVAS

Las funciones de reducción ( MPI_Op ) no devuelven un valor de error. Como resultado, si las funciones detectan un error, lo único que pueden hacer es llamar a MPI_Abort o ignorar silenciosamente el problema. Por lo tanto, si cambia el manejador de errores de MPI_ERRORS_ARE_FATAL a otra cosa, por ejemplo, MPI_ERRORS_RETURN , es posible que no se indique ningún error.

ERRORES

Casi todas las rutinas de MPI devuelven un valor de error; las rutinas C como resultado de la función y las rutinas Fortran en el último argumento.

Antes de que se devuelva el valor de error, se llama al manejador de errores de MPI actual asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo). Si no hay ningún objeto de comunicación asociado con la llamada MPI, la llamada se considera adjunta a MPI_COMM_SELF y llamará al manejador de errores de MPI asociado. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se utiliza exclusivamente el Modelo de Sesiones), el error activa el manejador de errores inicial. El manejador de errores inicial se puede cambiar llamando a MPI_Comm_set_errhandler en MPI_COMM_SELF cuando se utiliza el modelo World, o mediante el argumento de línea de comandos mpi_initial_errhandler para mpiexec o la clave info para MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no se ha establecido ningún otro manejador de errores apropiado, entonces se llama al manejador de errores MPI_ERRORS_RETURN para las funciones de E/S de MPI y al manejador de errores MPI_ERRORS_ABORT para todas las demás funciones de MPI.
