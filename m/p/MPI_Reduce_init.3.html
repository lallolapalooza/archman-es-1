MPI_Reduce, MPI_Ireduce, MPI_Reduce_init - Reduce los valores en todos los procesos dentro de un grupo.

PARÁMETROS DE ENTRADA

  • sendbuf: Dirección del búfer de envío (elección).
  • count: Número de elementos en el búfer de envío (entero).
  • datatype: Tipo de datos de los elementos del búfer de envío (manejador).
  • op: Operación de reducción (manejador).
  • root: Rango del proceso raíz (entero).
  • comm: Comunicador (manejador).
  • info: Información (manejador, persistente).

PARÁMETROS DE SALIDA

  • recvbuf: Dirección del búfer de recepción (elección, significativo solo en la raíz).
  • request: Solicitud (manejador, solo no bloqueante).
  • ierror: Solo Fortran: Estado de error (entero).

DESCRIPCIÓN

Las funciones globales de reducción (MPI_Reduce, MPI_Op_create, MPI_Op_free, MPI_Allreduce, MPI_Reduce_scatter, MPI_Scan) realizan una operación de reducción global (como suma, máximo, AND lógico, etc.) entre todos los miembros de un grupo. La operación de reducción puede ser una de una lista predefinida de operaciones, o una operación definida por el usuario. Las funciones de reducción global vienen en varios sabores: una reducción que devuelve el resultado de la reducción en un nodo, una all-reduce que devuelve este resultado en todos los nodos, y una operación scan (prefijo paralelo). Además, una operación reduce-scatter combina la funcionalidad de una operación de reducción y dispersión.

MPI_Reduce combina los elementos proporcionados en el búfer de entrada de cada proceso en el grupo, utilizando la operación op, y devuelve el valor combinado en el búfer de salida del proceso con rango root. El búfer de entrada se define por los argumentos sendbuf, count y datatype; el búfer de salida se define por los argumentos recvbuf, count y datatype; ambos tienen el mismo número de elementos, con el mismo tipo. La rutina es llamada por todos los miembros del grupo usando los mismos argumentos para count, datatype, op, root, y comm. Por lo tanto, todos los procesos proporcionan búferes de entrada y salida de la misma longitud, con elementos del mismo tipo. Cada proceso puede proporcionar un elemento, o una secuencia de elementos, en cuyo caso la operación de combinación se ejecuta elemento a elemento en cada entrada de la secuencia. Por ejemplo, si la operación es MPI_MAX y el búfer de envío contiene dos elementos que son números de punto flotante (count = 2 y datatype = MPI_FLOAT), entonces recvbuf(1) = máximo global (sendbuf(1)) y recvbuf(2) = máximo global(sendbuf(2)).

USO DE LA OPCIÓN IN-PLACE

Cuando el comunicador es un intracommunicator, puede realizar una operación de reducción in-place (el búfer de salida se usa como búfer de entrada). Use la variable MPI_IN_PLACE como valor del sendbuf del proceso raíz. En este caso, los datos de entrada se toman en la raíz del búfer de recepción, donde serán reemplazados por los datos de salida.

Tenga en cuenta que MPI_IN_PLACE es un tipo especial de valor; tiene las mismas restricciones de uso que MPI_BOTTOM.

Dado que la opción in-place convierte el búfer de recepción en un búfer de envío y recepción, una vinculación de Fortran que incluye INTENT debe marcarlos como INOUT, no OUT.

CUANDO EL COMUNICADOR ES UN INTER-COMUNICADOR

Cuando el comunicador es un inter-comunicador, el proceso raíz en el primer grupo combina datos de todos los procesos en el segundo grupo y luego realiza la operación op. El primer grupo define el proceso raíz. Ese proceso utiliza MPI_ROOT como el valor de su argumento root. Los procesos restantes utilizan MPI_PROC_NULL como el valor de su argumento root. Todos los procesos en el segundo grupo utilizan el rango de ese proceso raíz en el primer grupo como el valor de su argumento root. Solo los argumentos del búfer de envío son significativos en el segundo grupo, y solo los argumentos del búfer de recepción son significativos en el proceso raíz del primer grupo.

OPERACIONES DE REDUCCIÓN PREDEFINIDAS

El conjunto de operaciones predefinidas proporcionadas por MPI se enumera a continuación (Operaciones de Reducción Predefinidas). Esa sección también enumera los tipos de datos a los que cada operación puede aplicarse. Además, los usuarios pueden definir sus propias operaciones que pueden sobrecargarse para operar en varios tipos de datos, ya sean básicos o derivados. Esto se explica con más detalle en la descripción de las operaciones definidas por el usuario (ver las páginas man para MPI_Op_create y MPI_Op_free).

Se supone que la operación op es siempre asociativa. Se supone que todas las operaciones predefinidas también son conmutativas. Los usuarios pueden definir operaciones que se asumen asociativas, pero no conmutativas. El orden de evaluación "canónico" de una reducción está determinado por los rangos de los procesos en el grupo. Sin embargo, la implementación puede aprovechar la asociatividad, o la asociatividad y la conmutatividad, para cambiar el orden de evaluación. Esto puede cambiar el resultado de la reducción para operaciones que no son estrictamente asociativas y conmutativas, como la suma de punto flotante.

Los operadores predefinidos solo funcionan con los tipos MPI listados a continuación (Operaciones de Reducción Predefinidas, y la sección MINLOC y MAXLOC, más abajo). MINLOC Y MAXLOC

La operación MPI_MINLOC se utiliza para calcular un valor mínimo global y también un índice asociado a este valor mínimo. Similarmente, MPI_MAXLOC calcula un valor máximo global y un índice. Una aplicación de estas operaciones es calcular el valor global mínimo (máximo) y el rango del proceso que contiene este valor.

La operación que define MPI_MAXLOC es:

         ( u )    (  v )      ( w )
         (   )  o (    )   =  (   )
         ( i )    (  j )      ( k )
donde
    w = max(u, v)
y
         ( i            si u > v
         (
   k   = ( min(i, j)    si u = v
         (
         (  j           si u < v)

MPI_MINLOC está definido de forma similar:

         ( u )    (  v )      ( w )
         (   )  o (    )   =  (   )
         ( i )    (  j )      ( k )
donde
    w = min(u, v)
y
         ( i            si u < v
         (
   k   = ( min(i, j)    si u = v
         (
         (  j           si u > v)

Ambas operaciones son asociativas y conmutativas. Debe notar que si MPI_MAXLOC se aplica a una secuencia de pares (u(0), 0), (u(1), 1), ..., (u(n-1), n-1), el valor devuelto es (u, r), donde u = max(i), u(i) y r es el índice del primer máximo global en la secuencia. Por lo tanto, si cada proceso proporciona un valor y su rango dentro del grupo, una operación reduce con op = MPI_MAXLOC devolverá el valor máximo y el rango del primer proceso con ese valor. Similarmente, MPI_MINLOC puede usarse para devolver el valor mínimo y su índice. Más generalmente, MPI_MINLOC calcula un mínimo lexicográfico, donde los elementos se ordenan según la primera componente de cada par y se resuelven los empates según la segunda componente.

La operación de reducción se define para operar sobre argumentos que consisten en un par: valor e índice. Para Fortran y C, se proporcionan tipos para describir este par. La naturaleza potencialmente mixta de estos argumentos es un problema en Fortran. Para Fortran, este problema se evita utilizando un tipo MPI proporcionado que consiste en un par de tipos iguales al tipo de valor, y se fuerza el índice a este tipo también. En C, el tipo de par proporcionado por MPI tiene tipos distintos y el índice es un int.

Para usar MPI_MINLOC y MPI_MAXLOC en una operación de reducción, debe proporcionar un argumento de tipo que represente un par (valor e índice). MPI proporciona nueve tipos predefinidos de este tipo. Las operaciones MPI_MAXLOC y MPI_MINLOC pueden usarse con cada uno de los siguientes tipos de datos:

Fortran:
Nombre                     Descripción
MPI_2REAL                par de REALs
MPI_2DOUBLE_PRECISION    par de variables de doble precisión
MPI_2INTEGER             par de enteros
C:
Nombre                     Descripción
MPI_FLOAT_INT            float e int
MPI_DOUBLE_INT           doble e int
MPI_LONG_INT             largo e int
MPI_2INT                 par de int
MPI_SHORT_INT            corto e int
MPI_LONG_DOUBLE_INT      doble de precisión e int

El tipo de datos MPI_2REAL es equivalente a:

MPI_TYPE_CONTIGUOUS(2, MPI_REAL, MPI_2REAL)

Estas afirmaciones se aplican igualmente para MPI_2INTEGER, MPI_2DOUBLE_PRECISION y MPI_2INT.

El tipo de datos MPI_FLOAT_INT se define como si se hubiera definido de la siguiente manera:

type[0] = MPI_FLOAT
type[1] = MPI_INT
disp[0] = 0
disp[1] = sizeof(float)
block[0] = 1
block[1] = 1
MPI_TYPE_STRUCT(2, block, disp, type, MPI_FLOAT_INT)

Estas afirmaciones se aplican igualmente para MPI_LONG_INT y MPI_DOUBLE_INT.

Ejemplo 3: Cada proceso tiene un array de 30 doubles en C. Para cada uno de los 30 lugares, calcular el valor y el rango del proceso que contiene el valor máximo.

...
/* cada proceso tiene un array de 30 doubles: ain[30] */
double ain[30], aout[30];
int  ind[30];
struct {
    double val;
    int   rank;
} in[30], out[30];
int i, myrank, root;
MPI_Comm_rank(MPI_COMM_WORLD, &myrank);
for (i=0; i<30; ++i) {
    in.val = ain[i];
    in.rank = myrank;
}
MPI_Reduce( in, out, 30, MPI_DOUBLE_INT, MPI_MAXLOC, root, comm );
/* En este momento, el resultado reside en el proceso root */
if (myrank == root) {
    /* leer ranks out */
    for (i=0; i<30; ++i) {
        aout[i] = out.val;
        ind[i] = out.rank;
    }
}

Ejemplo 4: Ejemplo similar en Fortran.

...
! cada proceso tiene un array de 30 doubles: ain(30)
DOUBLE PRECISION :: ain(30), aout(30)
INTEGER :: ind(30)
DOUBLE PRECISION :: in(2,30), out(2,30)

call MPI_COMM_RANK(MPI_COMM_WORLD, myrank)
DO I=1, 30
    in(1,i) = ain(i)
    in(2,i) = myrank    ! myrank se fuerza a un doble

                                                          comm, ierr )

IF (myrank == root) THEN
    ! leer ranks out
    DO I= 1, 30
        aout(i) = out(1,i)
        ind(i) = out(2,i)  ! rank se fuerza de vuelta a un entero
    END DO
END IF

Ejemplo 5: Cada proceso tiene un array no vacío de valores. Encontrar el valor mínimo global, el rango del proceso que lo contiene y su índice en este proceso.

#define  LEN   1000
float val[LEN];        /* array local de valores */
int count;             /* número local de valores */
int myrank, minrank, minindex;
float minval;
struct {
    float value;
    int   index;
} in, out;
/* mínimo local */
in.value = val[0];
in.index = 0;
for (i=1; i < count; i++)
    if (in.value > val[i]) {
        in.value = val[i];
        in.index = i;
    }
/* mínimo global */
MPI_Comm_rank(MPI_COMM_WORLD, &myrank);
in.index = myrank*LEN + in.index;
MPI_Reduce( in, out, 1, MPI_FLOAT_INT, MPI_MINLOC, root, comm );
    /* En este momento, el resultado reside en el proceso root */
if (myrank == root) {
    /* leer el resultado */
    minval = out.value;
    minrank = out.index / LEN;
    minindex = out.index % LEN;

NOTAS SOBRE LAS OPERACIONES COLECTIVAS

Las funciones de reducción (MPI_Op) no devuelven un valor de error. Como resultado, si detectan un error, solo pueden llamar a MPI_Abort o ignorar el problema de forma silenciosa. Por lo tanto, si cambia el gestor de errores de MPI_ERRORS_ARE_FATAL a algo else, por ejemplo, MPI_ERRORS_RETURN, no se podrá indicar ningún error.

La razón de esto es el problema de rendimiento al garantizar que todas las rutinas de reducción devuelvan el mismo valor de error.

ERRORES

La mayoría de las rutinas MPI devuelven un valor de error; en C, el resultado de la función se devuelve como el valor de retorno, y en Fortran, como el último argumento de la rutina.

Antes de que se devuelva el valor de error, se llama al gestor de errores asociado con el objeto de comunicación (por ejemplo, communicator, window, file). Si no hay un objeto de comunicación asociado con la llamada MPI, se considera que la llamada está asociada a MPI_COMM_SELF y se llama al gestor de errores asociado a MPI_COMM_SELF. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize), se considera que la llamada no se ha realizado.

ERRORS

All MPI functions should raise an error if it is detected. When an error is detected, the error handler that was most recently set for the communicator of the function call is called. If the error handler was set on MPI_COMM_SELF using the Sessions Model exclusively, then the initial error handler is invoked. The initial error handler can be changed by calling MPI_Comm_set_errhandler on MPI_COMM_SELF when using the World model, or the mpi_initial_errhandler CLI argument to mpiexec or info key to MPI_Comm_spawn/MPI_Comm_spawn_multiple. If no other appropriate error handler has been set, then the MPI_ERRORS_RETURN error handler is called for MPI I/O functions and the MPI_ERRORS_ABORT error handler is called for all other MPI functions.

Open MPI includes three predefined error handlers that can be used:

  • MPI_ERRORS_ARE_FATAL Causes the program to abort all connected MPI processes.
  • MPI_ERRORS_ABORT An error handler that can be invoked on a communicator, window, file, or session. When called on a communicator, it acts as if MPI_Abort was called on that communicator. If called on a window or file, acts as if MPI_Abort was called on a communicator containing the group of processes in the corresponding window or file. If called on a session, aborts only the local process.
  • MPI_ERRORS_RETURN Returns an error code to the application.

MPI applications can also implement their own error handlers by calling:

  • MPI_Comm_create_errhandler then MPI_Comm_set_errhandler
  • MPI_File_create_errhandler then MPI_File_set_errhandler
  • MPI_Session_create_errhandler then MPI_Session_set_errhandler or at MPI_Session_init
  • MPI_Win_create_errhandler then MPI_Win_set_errhandler

Note that MPI does not guarantee that an MPI program can continue past an error.

See the MPI man page for a full list of MPI error codes.

See the Error Handling section of the MPI-3.1 standard for more information.
