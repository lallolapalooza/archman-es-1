MPI_Type_vector(3) Open MPI MPI_Type_vector(3)

MPI_Type_vector — Crea un tipo de dato vector (estratificado) en memoria.

Sintaxis

Sintaxis C

#include <mpi.h>
int MPI_Type_vector(int count, int blocklength, int stride,
     MPI_Datatype oldtype, MPI_Datatype *newtype)

Sintaxis Fortran

USE MPI
! o la antigua forma: INCLUDE 'mpif.h'
MPI_TYPE_VECTOR(COUNT, BLOCKLENGTH, STRIDE, OLDTYPE, NEWTYPE,
             IERROR)
     INTEGER COUNT, BLOCKLENGTH, STRIDE, OLDTYPE
     INTEGER NEWTYPE, IERROR

Sintaxis Fortran 2008

USE mpi_f08
MPI_Type_vector(count, blocklength, stride, oldtype, newtype, ierror)
     INTEGER, INTENT(IN) :: count, blocklength, stride
     TYPE(MPI_Datatype), INTENT(IN) :: oldtype
     TYPE(MPI_Datatype), INTENT(OUT) :: newtype
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

Parámetros de entrada

  • count: Número de bloques (entero no negativo).
  • blocklength: Número de elementos en cada bloque (entero no negativo).
  • stride: Número de elementos entre el inicio de cada bloque (entero).
  • oldtype: Tipo de dato antiguo (handle).

Parámetros de salida

  • newtype: Tipo de dato nuevo (handle).
  • ierror: Solo Fortran: Código de error (entero).

Descripción

La función MPI_Type_vector es un constructor general que permite replicar un tipo de dato en ubicaciones que consisten en bloques igualmente espaciados. Cada bloque se obtiene concatenando el mismo número de copias del tipo de dato antiguo. El espacio entre los bloques es múltiplo del tamaño del tipo de dato antiguo.

Ejemplo 1: Supongamos de nuevo que el tipo de dato antiguo tiene el mapa de tipo {(double, 0), (char, 8)}, con un tamaño de 16. Una llamada a MPI_Type_vector(2, 3, 4, oldtype, newtype) creará el tipo de dato con el mapa de tipo:

{(double, 0), (char, 8), (double, 16), (char, 24),
(double, 32), (char, 40),
(double, 64), (char, 72),
(double, 80), (char, 88), (double, 96), (char, 104)}

Es decir, dos bloques con tres copias cada uno del tipo de dato antiguo, con un desplazamiento de 4 elementos (4 x 16 bytes).

Ejemplo 2: Una llamada a MPI_Type_vector(3, 1, -2, oldtype, newtype) creará el tipo de dato:

{(double, 0), (char, 8), (double, -32), (char, -24),
(double, -64), (char, -56)}

En general, supongamos que el tipo de dato antiguo tiene el mapa de tipo:

{(type(0), disp(0)), ..., (type(n-1), disp(n-1))},

con un tamaño de ex. Sea bl el número de elementos en cada bloque. El tipo de dato nuevo tiene un mapa de tipo con count x bl x n entradas:

{(type(0), disp(0)), ..., (type(n-1), disp(n-1)),
(type(0), disp(0) + ex), ..., (type(n-1), disp(n-1) + ex), ...,
(type(0), disp(0) + (bl -1) * ex),...,
(type(n-1), disp(n-1) + (bl -1) * ex),
(type(0), disp(0) + stride * ex),..., (type(n-1),
disp(n-1) + stride * ex), ...,
(type(0), disp(0) + (stride + bl - 1) * ex), ...,
(type(n-1), disp(n-1) + (stride + bl - 1) * ex), ...,
(type(0), disp(0) + stride * (count -1) * ex), ...,
(type(n-1), disp(n-1) + stride * (count -1) * ex), ...,
(type(0), disp(0) + (stride * (count -1) + bl -1) * ex), ...,
(type(n-1), disp(n-1) + (stride * (count -1) + bl -1) * ex)}

Una llamada a MPI_Type_contiguous(count, oldtype, newtype) es equivalente a una llamada a MPI_Type_vector(count, 1, 1, oldtype, newtype), o a una llamada a MPI_Type_vector(1, count, n, oldtype, newtype), con n arbitrario.

Errores

La mayoría de las rutinas MPI devuelven un valor de error; en las rutinas C, el valor de retorno es el resultado de la función, y en las rutinas Fortran, el último argumento es el código de error.

Antes de devolver el valor de error, se llama al manejador de error asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo). Si no hay objeto de comunicación asociado con la llamada MPI, la llamada se considera asociada a MPI_COMM_SELF y se llama al manejador de error correspondiente. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se usa el modelo de Sesiones exclusivamente), el error genera el manejador de error inicial. El manejador de error inicial puede cambiarse llamando a MPI_Comm_set_errhandler sobre MPI_COMM_SELF cuando se use el modelo del Mundo, o a través del argumento mpi_initial_errhandler del mpiexec o la clave de información de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no hay otro manejador de error adecuado, se llama al manejador de error MPI_ERRORS_RETURN para las funciones de I/O de MPI y al manejador de error MPI_ERRORS_ABORT para otras funciones de MPI.

Open MPI incluye tres manejadores de error predeterminados que pueden usarse:

  • MPI_ERRORS_ARE_FATAL Causa que el programa se detenga en todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT Un manejador de error que puede ser invocado en un comunicador, ventana, archivo o sesión. Al ser invocado en un comunicador, actúa como si se hubiera llamado MPI_Abort en ese comunicador. Si se invoca en una ventana o archivo, actúa como si se hubiera llamado MPI_Abort en un comunicador que contiene el grupo de procesos en la ventana o archivo correspondiente. Si se invoca en una sesión, detiene solo el proceso local.
  • MPI_ERRORS_RETURN Devuelve un código de error a la aplicación.

Las aplicaciones MPI también pueden implementar sus propios manejadores de error llamando:

  • MPI_Comm_create_errhandler luego MPI_Comm_set_errhandler
  • MPI_File_create_errhandler luego MPI_File_set_errhandler
  • MPI_Session_create_errhandler luego MPI_Session_set_errhandler o en MPI_Session_init
  • MPI_Win_create_errhandler luego MPI_Win_set_errhandler

Nota: Las aplicaciones MPI no tienen garantía de que puedan continuar después de un error.

Ver la documentación de la página del manual de MPI para una lista completa de códigos de error MPI.

Ver la sección de Manejo de Errores de la estándar MPI-3.1 para más información.
