MPI_Intercomm_create(3) Open MPI MPI_Intercomm_create(3)

MPI_Intercomm_create — Crea un intercomunicador a partir de dos comunicadores intracomunicadores.

SINTAXIS

Sintaxis C

#include <mpi.h>
int MPI_Intercomm_create(MPI_Comm local_comm, int local_leader,
     MPI_Comm peer_comm, int remote_leader, int tag, MPI_Comm *newintercomm)

Sintaxis Fortran

USE MPI
! o la forma antigua: INCLUDE 'mpif.h'
MPI_INTERCOMM_CREATE(LOCAL_COMM, LOCAL_LEADER, PEER_COMM,
             REMOTE_LEADER, TAG, NEWINTERCOMM, IERROR)
     INTEGER LOCAL_COMM, LOCAL_LEADER, PEER_COMM, REMOTE_LEADER
     INTEGER TAG, NEWINTERCOMM, IERROR

Sintaxis Fortran 2008

USE mpi_f08
MPI_Intercomm_create(local_comm, local_leader, peer_comm, remote_leader,
             tag, newintercomm, ierror)
     TYPE(MPI_Comm), INTENT(IN) :: local_comm, peer_comm
     INTEGER, INTENT(IN) :: local_leader, remote_leader, tag
     TYPE(MPI_Comm), INTENT(OUT) :: newintercomm
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARAMETROS DE ENTRADA

  • local_comm: El comunicador que contiene el proceso que inicia la comunicación intercomunicadora (handle).
  • local_leader: El líder local del grupo en local_comm (entero).
  • peer_comm: El comunicador "peered"; significativo solo en el líder local (handle).
  • remote_leader: El líder remoto del comunicador peer_comm; significativo solo en el líder local (entero).
  • tag: El número de etiqueta usado para identificar el nuevo intercomunicador (entero).

PARAMETROS DE SALIDA

  • newintercomm: El nuevo intercomunicador creado (handle).
  • ierror: Solo en Fortran: El estado de error (entero).

DESCRIPCIÓN

Esta llamada crea un intercomunicador. Es colectiva sobre la unión de los grupos locales y remotos. Los procesos deben proporcionar los mismos valores de local_comm y local_leader dentro de cada grupo. Los valores de remote_leader, local_leader y tag no son permitidos como comodines.

Esta llamada utiliza comunicación punto a punto con el comunicador peer_comm, y con el etiquetado tag entre los líderes. Por lo tanto, es necesario tener cuidado para evitar que haya comunicación pendiente en peer_comm que pueda interferir con esta comunicación.

Si se están realizando múltiples llamadas a MPI_Intercomm_create, estas deben usar diferentes etiquetas (más precisamente, deben asegurarse de que los líderes locales y remotos estén utilizando etiquetas distintas para cada MPI_Intercomm_create).

NOTAS

Se recomienda usar un comunicador "peered" dedicado, como una copia de MPI_COMM_WORLD, para evitar problemas con los comunicadores "peered".

El estándar MPI 1.1 contiene dos comentarios mutuamente excluyentes sobre los intracomunicadores de entrada. Uno dice que los grupos correspondientes deben ser disjuntos; el otro dice que los líderes pueden ser el mismo proceso. Después de una discusión por parte del comité MPI, se ha decidido que los grupos deben ser disjuntos. La razón por la cual se dice en el estándar no es la razón por la cual se tomó esta decisión; en cambio, las operaciones otras sobre intercomunicadores (como MPI_Intercomm_merge) no tienen sentido si los grupos no son disjuntos.

ERRORES

La mayoría de las rutinas MPI devuelven un valor de error; las rutinas C devuelven el resultado de la función y las rutinas Fortran en el último argumento.

Antes de devolver el valor de error, se llama al manejador de errores asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo) actual. Si no hay objeto de comunicación asociado con la llamada MPI, se considera que la llamada está asociada a MPI_COMM_SELF y se llama al manejador de errores asociado con MPI_COMM_SELF. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize o cuando se usa el modelo de sesiones exclusivamente), se levanta el manejador de errores inicial. El manejador de errores inicial puede cambiarse llamando a MPI_Comm_set_errhandler en MPI_COMM_SELF cuando se use el modelo del mundo, o al argumento mpi_initial_errhandler de mpiexec o a la clave info de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no hay otro manejador de error adecuado configurado, se llama el manejador de errores MPI_ERRORS_RETURN para funciones de I/O MPI y el manejador de errores MPI_ERRORS_ABORT para todas las otras funciones MPI.

Open MPI incluye tres manejadores de errores predeterminados que pueden ser utilizados:

  • MPI_ERRORS_ARE_FATAL Detiene a todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT Un manejador de error que puede ser invocado en un comunicador, ventana, archivo o sesión. Cuando se invoca en un comunicador, actúa como si se hubiera llamado MPI_Abort en ese comunicador. Si se invoca en una ventana o archivo, actúa como si se hubiera llamado MPI_Abort en un comunicador que contiene el conjunto de procesos en la ventana o archivo correspondiente. Si se invoca en una sesión, detiene solo el proceso local.
  • MPI_ERRORS_RETURN Devuelve el código de error a la aplicación.

Las aplicaciones MPI también pueden implementar sus propios manejadores de errores llamando:

  • MPI_Comm_create_errhandler luego MPI_Comm_set_errhandler
  • MPI_File_create_errhandler luego MPI_File_set_errhandler
  • MPI_Session_create_errhandler luego MPI_Session_set_errhandler o al MPI_Session_init
  • MPI_Win_create_errhandler luego MPI_Win_set_errhandler

Nota: Los programas MPI no garantizan que puedan continuar después de un error.

Ver la página de manuales de MPI para una lista completa de códigos de error MPI.
