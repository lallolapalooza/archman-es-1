DESCRIPCIÓN

\n

MPI_Type_create_struct crea un tipo de datos estructurado. Esta\n rutina reemplaza a MPI_Type_struct, que ahora está obsoleta.

\n

MPI_Type_create_struct es el constructor de tipos más general.\n Generaliza aún más MPI_Type_create_hindexed al permitir que cada bloque\n consista en replicaciones de diferentes tipos de datos.

\n

Ejemplo 1: Sea type1 un mapa de tipo

\n
\n
\n
{(double, 0), (char, 8)}
\n
\n
\n

con extensión 16. Sean B = (2, 1, 3), D = (0, 16, 26) y\n T = (MPI_FLOAT, type1, MPI_CHAR). Entonces, una llamada a\n MPI_Type_create_struct(3, B, D, T, newtype) devuelve un tipo de datos con el mapa de tipo

\n
\n
\n
{\n (float, 0), (float,4),             // 2 float\n (double, 16), (char, 24),          // 1 type1\n (char, 26), (char, 27), (char, 28) // 3 char\n}
\n
\n
\n

Es decir, dos copias de MPI_FLOAT comenzando en 0, seguidas\n de una copia de type1 comenzando en 16, seguidas de tres copias de\n MPI_CHAR, comenzando en 26.

\n

Ejemplo 2:

\n

Un ejemplo de una estructura con solo algunos componentes como parte del\n tipo

\n
\n
\n
struct MyStruct {\n    double x[2], y;\n    char a;\n    int n;\n};\n// crea un nuevo tipo donde solo enviamos x, y y n\nint B[] = {\n    2, // 2 double\n    1, // 1 double\n    1, // 1 int\n    1  // padding de alineación\n};\nMPI_Aint D[] = {\n    offsetof(struct MyStruct, x),\n    offsetof(struct MyStruct, y),\n    offsetof(struct MyStruct, n),\n    sizeof(struct MyStruct)\n};\nMPI_Datatype T[] = {\n    MPI_DOUBLE,\n    MPI_DOUBLE,\n    MPI_INT,\n    MPI_UB\n};\nMPI_Datatype mpi_dt_mystruct;\nMPI_Type_create_struct(4, B, D, T, &mpi_dt_mystruct);\nMPI_Type_commit(&mpi_dt_mystruct);\n// Ahora podemos enviar una estructura (omitiendo a)\nstruct MyStruct values[3];\nif ( rank == 0 ) {\n    // ... inicializa values\n    MPI_Send(values, 3, mpi_dt_mystruct, 1, 0, MPI_COMM_WORLD);\n} else if ( rank == 1 ) {\n    MPI_Recv(values, 3, mpi_dt_mystruct, 0, 0, MPI_COMM_WORLD, MPI_STATUS_IGNORE);\n}
\n
\n
\n

Para más información, véase la sección 5.1.2 del Estándar MPI-4.0.

\n
\n
\n

NOTAS

\n

Si se establece explícitamente un límite superior usando el tipo de\n datos MPI MPI_UB, el índice correspondiente debe ser positivo.

\n

El Estándar MPI-1 originalmente hacía declaraciones vagas sobre el\n relleno y la alineación; esto estaba destinado a permitir la definición\n simple de estructuras que pudieran enviarse con un recuento mayor que uno.\n Por ejemplo,

\n
\n
\n
struct {int a; char b;} foo;
\n
\n
\n

puede tener

\n
\n
\n
sizeof(foo) = sizeof(int) + sizeof(char);
\n
\n
\n

definiendo la extensión de un tipo de datos como que incluye un épsilon,\n lo que habría permitido a una implementación hacer que la extensión fuera\n un tipo de datos MPI para esta estructura igual a 2*sizeof(int). Sin\n embargo, dado que diferentes sistemas podrían definir rellenos diferentes,\n una aclaración al estándar hizo que el épsilon fuera cero. Por lo tanto, si\n define un tipo de datos de estructura y desea enviar o recibir múltiples\n elementos, debe incluir explícitamente una entrada MPI_UB como\n último miembro de la estructura. Véase el ejemplo anterior.

\n
\n
\n

ERRORES

\n

Casi todas las rutinas MPI devuelven un valor de error; las rutinas C como\n resultado de retorno de la función y las rutinas Fortran en el último\n argumento.

\n

Antes de que se devuelva el valor de error, se llama al controlador de\n errores MPI actual asociado con el objeto de comunicación (por ejemplo,\n comunicador, ventana, archivo). Si no hay ningún objeto de comunicación\n asociado con la llamada MPI, entonces la llamada se considera adjunta a\n MPI_COMM_SELF y llamará al controlador de errores MPI asociado. Cuando MPI_COMM_SELF\n no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread,\n después de MPI_Finalize, o cuando se utiliza exclusivamente el Modelo\n de Sesiones) el error eleva el controlador de errores inicial. El controlador\n de errores inicial se puede cambiar llamando a MPI_Comm_set_errhandler\n en MPI_COMM_SELF cuando se utiliza el modelo World, o el argumento CLI\n mpi_initial_errhandler a mpiexec o clave de información a MPI_Comm_spawn/MPI_Comm_spawn_multiple.\n Si no se ha establecido ningún otro controlador de errores apropiado, entonces\n se llama al controlador de errores MPI_ERRORS_RETURN para las funciones de E/S\n MPI y al controlador de errores MPI_ERRORS_ABORT para todas las demás\n funciones MPI.

\n

Open MPI incluye tres controladores de errores predefinidos que pueden\n utilizarse:

\n
\n
    \n
  • MPI_ERRORS_ARE_FATAL Provoca que el programa termine todos los procesos MPI\n conectados.
    • \n
  • MPI_ERRORS_ABORT Un controlador de errores que puede invocarse en un\n comunicador, ventana, archivo o sesión. Cuando se llama en un\n comunicador, actúa como si se hubiera llamado a MPI_Abort en ese\n comunicador. Si se llama en una ventana o archivo, actúa como si se\n hubiera llamado a MPI_Abort en un comunicador que contiene el\n grupo de procesos de la ventana o archivo correspondiente. Si se llama\n en una sesión, solo aborta el proceso local.
    • \n
  • MPI_ERRORS_RETURN Devuelve un código de error a la aplicación.
    • \n
\n
\n

Las aplicaciones MPI también pueden implementar sus propios controladores de\n errores llamando a:

\n
\n
    \n
  • MPI_Comm_create_errhandler luego MPI_Comm_set_errhandler
    • \n
  • MPI_File_create_errhandler luego MPI_File_set_errhandler
    • \n
  • MPI_Session_create_errhandler luego\n MPI_Session_set_errhandler o en MPI_Session_init
    • \n
  • MPI_Win_create_errhandler luego MPI_Win_set_errhandler
    • \n
\n
\n

Tenga en cuenta que MPI no garantiza que un programa MPI pueda continuar\n después de un error.

\n

Consulte la página del manual de MPI para obtener una lista\n completa de los códigos de error de MPI.

\n

Consulte la sección de Manejo de Errores del estándar MPI-3.1 para más\n información.

MPI_Type_create_struct(3)

SINTAXIS

int MPI_Type_create_struct(int count, const int array_of_blocklengths[], const MPI_Aint array_of_displacements[], const MPI_Datatype array_of_types[], MPI_Datatype *newtype)

PARÁMETROS DE ENTRADA

count
Número de bloques de tipos de datos (entero).
array_of_blocklengths
Matriz que contiene el número de elementos de cada tipo de datos en el nuevo tipo (matriz de enteros).
array_of_displacements
Matriz que contiene los desplazamientos de cada bloque con respecto al inicio del tipo derivado (matriz de enteros largos sin signo).
array_of_types
Matriz que contiene los tipos de datos MPI de cada bloque (matriz de `MPI_Datatype`).

PARÁMETROS DE SALIDA

newtype
Nuevo tipo de datos MPI derivado (puntero a `MPI_Datatype`).

DESCRIPCIÓN

La rutina `MPI_Type_create_struct` construye un nuevo tipo de datos MPI derivado basado en una estructura definida por bloques de tipos de datos existentes. El nuevo tipo se crea combinando los tipos de datos especificados en `array_of_types`, donde cada tipo se repite `array_of_blocklengths` veces y se desplaza `array_of_displacements` bytes desde el inicio del tipo. El número de tipos de datos y sus propiedades están definidos por el parámetro `count`.

Es responsabilidad del usuario asegurarse de que los desplazamientos proporcionados en `array_of_displacements` se alinean correctamente con los límites de memoria si es necesario para el hardware subyacente.

NOTAS

Esta rutina es la predecesora de `MPI_Type_create_struct` introducida en MPI-2. Se recomienda utilizar `MPI_Type_create_struct` en lugar de esta rutina para la portabilidad y la compatibilidad con versiones posteriores.

ERRORES

Los errores de creación de tipos generalmente resultan en un error de tipo no recuperable.
