PARÁMETROS DE ENTRADA

  • sendbuf : Dirección de inicio del buffer de envío (elección).
  • sendcount : Número de elementos en el buffer de envío (entero).
  • sendtype : Tipo de datos de los elementos del buffer de envío (manejador).
recvcounts
Arreglo de enteros (de longitud igual al tamaño del grupo) que contiene el número de elementos que se reciben de cada proceso (solo significativo en la raíz).
•
displs
Arreglo de enteros (de longitud igual al tamaño del grupo). La entrada i especifica el desplazamiento relativo a recvbuf en el que se colocan los datos entrantes del proceso i (solo significativo en la raíz).
•
recvtype
Tipo de datos de los elementos del buffer de recepción (solo significativo en la raíz) (manejador).
  • root : Rango del proceso receptor (entero).
  • comm : Comunicador (manejador).
  • info : Información (manejador, solo persistente).

PARÁMETROS DE SALIDA

•
recvbuf
Dirección del buffer de recepción (elección, solo significativa en la raíz).
  • request : Solicitud (manejador, solo no bloqueante).
  • ierror : Solo Fortran: Estado de error (entero).

DESCRIPCIÓN

MPI_Gatherv extiende la funcionalidad de MPI_Gather al permitir un recuento variable de datos de cada proceso, ya que recvcounts es ahora un arreglo. También permite más flexibilidad en cuanto a dónde se colocan los datos en la raíz, al proporcionar el nuevo argumento, displs.

El resultado es como si cada proceso, incluido el proceso raíz, enviara un mensaje a la raíz,

MPI_Send(sendbuf, sendcount, sendtype, root, ...);

y la raíz ejecutara n recepciones,

MPI_Recv(recvbuf + disp[i] * extent(recvtype), recvcounts[i],
         recvtype, i, ...);

Los mensajes se colocan en el buffer de recepción del proceso raíz en orden de rango, es decir, los datos enviados desde el proceso j se colocan en la j-ésima porción del buffer de recepción recvbuf en el proceso raíz. La j-ésima porción de recvbuf comienza en el desplazamiento displs[j] elementos (en términos de recvtype) dentro de recvbuf.

El buffer de recepción se ignora para todos los procesos no raíz.

La firma de tipo implícita por sendcount, sendtype en el proceso i debe ser igual a la firma de tipo implícita por recvcounts[i], recvtype en la raíz. Esto implica que la cantidad de datos enviados debe ser igual a la cantidad de datos recibidos, par a par entre cada proceso y la raíz. Todavía se permiten mapas de tipos distintos entre el remitente y el receptor, como se ilustra en el Ejemplo 2, a continuación.

Todos los argumentos de la función son significativos en el proceso raíz, mientras que en otros procesos, solo los argumentos sendbuf, sendcount, sendtype, root, comm son significativos. Los argumentos root y comm deben tener valores idénticos en todos los procesos.

La especificación de recuentos, tipos y desplazamientos no debe causar que ninguna ubicación en la raíz se escriba más de una vez. Una llamada así es errónea.

Ejemplo 1: Ahora hacer que cada proceso envíe 100 enteros a la raíz, pero colocar cada conjunto (de 100) con un salto de enteros entre sí en el extremo receptor. Usar MPI_Gatherv y el argumento displs para lograr este efecto. Asumir stride >= 100.

MPI_Comm comm;
int gsize, sendarray[100];
int root, *rbuf, stride;
int *displs, i, rcounts;
...
MPI_Comm_size(comm, &gsize);
rbuf = (int)malloc(gsize * stride * sizeof(int));
displs = (int)malloc(gsize * sizeof(int));
rcounts = (int )malloc(gsize * sizeof(int));
for (i=0; i<gsize; ++i) {
  displs[i] = i * stride;
  rcounts[i] = 100;
}
MPI_Gatherv(sendarray, 100, MPI_INT, rbuf, rcounts, displs, MPI_INT,
            root, comm);

Tenga en cuenta que el programa es erróneo si stride < 100.

Ejemplo 2: Igual que el Ejemplo 1 en el lado receptor, pero enviar los 100 enteros de la columna 0 de un arreglo de 100x150 enteros, en C.

int root, *rbuf, stride;

for (i=0; i<gsize; ++i) {

USO DE LA OPCIÓN IN-PLACE

La opción in-place funciona de manera similar a la de MPI_Gather. Cuando el comunicador es un comunicador intra, puede realizarse una operación de recolección in-place (el buffer de salida se usa como buffer de entrada). Use la variable MPI_IN_PLACE como el valor del buffer de envío del proceso raíz. En este caso, sendcount y sendtype se ignoran, y se asume que la contribución del proceso raíz al vector recolectado ya está en el lugar correcto en el buffer de recepción.

Nota: MPI_IN_PLACE es un valor especial; tiene las mismas restricciones de uso que MPI_BOTTOM.

Dado que la opción in-place convierte el buffer de recepción en un buffer de envío y recepción, los enlaces de Fortran que incluyan INTENT deben marcarlos como INOUT, no como OUT.

CUANDO EL COMUNICADOR ES UN COMUNICADOR INTER

Cuando el comunicador es un comunicador inter, el proceso raíz del primer grupo recolecta datos de todos los procesos del segundo grupo. El primer grupo define el proceso raíz. Este proceso usa MPI_ROOT como valor del argumento raíz. Los procesos restantes usan MPI_PROC_NULL como valor del argumento raíz. Todos los procesos del segundo grupo usan el rango del proceso raíz del primer grupo como valor del argumento raíz. El argumento de buffer de envío de los procesos del primer grupo debe ser consistente con el argumento de buffer de recepción del proceso raíz del segundo grupo.

ERRORES

Mayormente, casi todas las rutinas MPI devuelven un valor de error; en las rutinas C, el resultado es el valor de retorno de la función y en las rutinas Fortran, el último argumento.

Antes de que se devuelva el valor de error, se llama al manejador de errores asociado con el objeto de comunicación (por ej., comunicador, ventana, archivo) actual. Si no hay ningún objeto de comunicación asociado con la llamada MPI, se considera que la llamada está asociada a MPI_COMM_SELF y se llama al manejador de errores correspondiente. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se usa exclusivamente el modelo de sesiones), el error activa el manejador de errores inicial. El manejador de errores inicial puede cambiarse llamando a MPI_Comm_set_errhandler en MPI_COMM_SELF cuando se usa el modelo de mundo, o al argumento mpi_initial_errhandler de mpiexec o a la clave mpi_info de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no se configura ningún otro manejador de errores adecuado, se llama al manejador de errores MPI_ERRORS_RETURN para las funciones de E/S de MPI y al manejador de errores MPI_ERRORS_ABORT para todas las demás funciones de MPI.

Open MPI incluye tres manejadores predefinidos que se pueden usar:

  • MPI_ERRORS_ARE_FATAL Causa que el programa termine en todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT Un manejador de error que puede invocarse en un comunicador, ventana, archivo o sesión. Cuando se invoca en un comunicador, actúa como si se hubiera llamado MPI_Abort en ese comunicador. Si se invoca en una ventana o archivo, actúa como si se hubiera llamado MPI_Abort en un comunicador que contiene la lista de procesos en la ventana o archivo correspondiente. Si se invoca en una sesión, detiene solo el proceso local.
  • MPI_ERRORS_RETURN Devuelve un código de error a la aplicación.

Los programas MPI también pueden implementar sus propios manejadores de errores llamando a:

  • MPI_Comm_create_errhandler seguido de MPI_Comm_set_errhandler
  • MPI_File_create_errhandler seguido de MPI_File_set_errhandler
  • MPI_Session_create_errhandler seguido de MPI_Session_set_errhandler o en MPI_Session_init
  • MPI_Win_create_errhandler seguido de MPI_Win_set_errhandler

Nota: MPI no garantiza que un programa MPI pueda continuar después de un error.

Consulte la documentación de la página del manual de MPI para obtener una lista completa de los códigos de error de MPI.

Consulte la sección de manejo de errores del estándar MPI-3.1 para obtener más información.
