Parámetros de entrada

  • sendbuf: Dirección de inicio del búfer de envío.
  • sendcounts: Array de enteros, donde el elemento i especifica el número de elementos a enviar al vecino i.
  • sdispls: Array de enteros, donde el elemento i especifica el desplazamiento (en bytes, offset desde sendbuf) desde el cual enviar datos al vecino i.
  • sendtypes: Array de tipos de datos, donde el elemento i especifica el tipo de dato a utilizar al enviar datos al vecino i.
  • recvcounts: Array de enteros, donde el elemento j especifica el número de elementos a recibir del vecino j.
  • rdispls: Array de enteros, donde el elemento j especifica el desplazamiento (en bytes, offset desde recvbuf) a donde los datos del vecino j deben escribirse.
  • recvtypes: Array de tipos de datos, donde el elemento j especifica el tipo de dato a utilizar al recibir datos del vecino j.
  • comm: Comunicador sobre el cual se realizan las interacciones.
  • info: Información (handle, solo persistente).

Parámetros de salida

  • recvbuf: Dirección del búfer de recepción.
  • request: Petición (handle, solo asincrónica).
  • ierror: Solo en Fortran: Código de error.

Descripción

MPI_Neighbor_alltoallw es una operación colectiva generalizada en la que todos los procesos envían datos a y reciben datos de todos los vecinos. Permite flexibilidad a MPI_Neighbor_alltoallv al permitir al usuario especificar el tipo de dato de bloques individuales (en adición a desplazamiento y cantidad de elementos). Su operación puede pensarse así, donde cada proceso realiza 2n (n siendo el número de vecinos en la topología del comunicador comm) comunicación punto a punto independientes. La topología y el layout de búfer son determinados por la topología del comunicador comm.

MPI_Cart_get(comm, maxdims, dims, periods, coords);
for (dim = 0, i = 0 ; dim < dims ; ++dim) {
    MPI_Cart_shift(comm, dim, 1, &r0, &r1);
    MPI_Isend(sendbuf + sdispls[i]  * extent(sendtype),
              sendcount, sendtypes[i], r0, ..., comm, ...);
    MPI_Irecv(recvbuf + rdispls[i] * extent(recvtype),
              recvcount, recvtypes[i], r0, ..., comm, ...);
    ++i;
    MPI_Isend(sendbuf + sdispls[i] * extent(sendtype),
              sendcount, sendtypes[i], r1, ..., comm, &req[i]);
    MPI_Irecv(recvbuf + rdispls[i] * extent(recvtype),
              recvcount, recvtypes[i], r1, ..., comm, ...);
    ++i;
}
MPI_Wait_all (...);
MPI_Comm_size(comm, &n);
for (i = 0, i < n; i++)
  MPI_Send(sendbuf + sdispls[i], sendcounts[i],
       sendtypes[i], i, ..., comm);
for (i = 0, i < n; i++)
  MPI_Recv(recvbuf + rdispls[i], recvcounts[i],
       recvtypes[i], i, ..., comm);

El proceso j envía el bloque k del búfer local sendbuf al vecino k, lo que coloca los datos en el bloque j del búfer local recvbuf.

Cuando un par de procesos intercambian datos, cada uno puede pasar argumentos diferentes de cantidad de elementos y tipo de dato, siempre que el emisor especifique la misma cantidad de datos (en bytes) que el receptor espera recibir.

Nota: El proceso i puede enviar un diferente número de datos al proceso j que reciba de j. También, un proceso puede enviar datos completamente diferentes y de tipo diferente a diferentes procesos en el comunicador.

Notas

La opción MPI_IN_PLACE para sendbuf no es significativa para esta operación

No se deben escribir más de una vez cualquier ubicación.

Todos los argumentos en todos los procesos son significativos. El argumento comm, en particular, debe describir el mismo comunicador en todos los procesos.

Los desplazamientos sdispls y rdispls se miden en bytes. Compare esto con MPI_Neighbor_alltoallv, donde estos desplazamientos se miden en unidades de sendtype y recvtype, respectivamente.

Errores

Casi todas las rutinas de MPI devuelven un valor de error; rutinas C como el resultado de la función y rutinas Fortran en el último argumento

NAME

MPI_Neighbor_alltoallw — Perform a neighbor all-to-all communication with arbitrary send and receive displacements.

SYNTAX

INPUT PARAMETERS

sendbuf
Beginning of the send buffer (choice).
sendcounts
Number of elements to send to each neighbor (array).
senddispls
Displacements of the data for each neighbor (array of byte offsets).
sendtypes
Datatypes of the send buffers for each neighbor (array).
recvbuf
Beginning of the receive buffer (choice).
recvcounts
Number of elements to receive from each neighbor (array).
recvdispls
Displacements of the data for each neighbor (array of byte offsets).
recvtypes
Datatypes of the receive buffers for each neighbor (array).
comm
Communicator with a topology (handle).

OUTPUT PARAMETERS

IERROR
Fortran only: Fortran integer error code.

The Fortran interface is provided for Fortran 2003 or later, and subject to the F2008 standard, with the following deviations:

  • Integer arguments may be passed by reference.
  • Non-character arguments may be passed by value, subject to the rules of the Fortran language.

DESCRIPTION

MPI_Neighbor_alltoallw performs a neighbor all-to-all communication. It is similar to MPI_Alltoallw, but it only sends to and receives from processes specified by the topology of the communicator.

A process sends data from its send buffer to all of its neighbors. Each neighbor receives data from the sending process. This is done symmetrically: each process receives data from all of its neighbors. The data sent to neighbor i comes from the i-th entry in the send buffer arrays (sendcounts, senddispls, sendtypes). The data received from neighbor j is placed in the j-th entry in the receive buffer arrays (recvcounts, recvdispls, recvtypes).

The communicator must have a Cartesian or graph topology established.

All calls to MPI_Neighbor_alltoallw within a communicator must use the same topology information. Specifically, the arrays sendcounts, senddispls, sendtypes, recvcounts, recvdispls, and recvtypes must all have the same size, and this size must equal the number of neighbors of the calling process in the communicator topology. All processes in the communicator must agree on the neighbors. That is, if process A is a neighbor of process B in the topology, then process B must also be a neighbor of process A.

The sizes of the send and receive buffers must be consistent. For each neighbor i, the send type sendtypes[i] must be compatible with the receive type recvtypes[i]. The number of elements specified by sendcounts[i] and sendtypes[i] must be the same as the number of elements specified by recvcounts[i] and recvtypes[i]. The send displacements are byte offsets from the beginning of the send buffer, and the receive displacements are byte offsets from the beginning of the receive buffer.

The send and receive buffers can be the same. The operation is then an in-place all-to-all communication.

NOTES

The standard specifies that MPI datatypes can be used in the sendtypes and recvtypes arguments. However, MPI does not support the use of arbitrary datatypes in the sendtypes and recvtypes arguments. Only MPI datatypes that are derived from basic types (e.g. MPI_CHAR, MPI_INT, MPI_DOUBLE, etc.) are supported.

The senddispls and recvdispls arguments are byte offsets. The use of MPI_Aint as the type for these arguments in C ensures that they are large enough to hold arbitrary byte offsets.

A process sends data to neighbor i, and receives data from neighbor j. The mapping of send/receive counts, displacements, and types to neighbors depends on the specific topology. For example, in a Cartesian topology, neighbor i might refer to the process in the i-th direction.

ERRORS

When the value of an argument is invalid, or not specified by the user, an error is returned. Before the error value is returned, the current error handler is called. If the error handler returns without returning an error code, then the value MPI_ERR_OTHER is returned. Possible errors for MPI_Neighbor_alltoallw include:

MPI_ERR_COMM
Invalid communicator. No pre-defined errors that match.
MPI_ERR_ARG
Invalid argument. Not a collective communication, or one of the arguments is invalid.
MPI_ERR_TYPE
Invalid datatype. Either a null datatype, or an invalid datatype argument.
MPI_ERR_COUNT
Invalid count. Either a negative count, or a count that is too large for the available address space.
MPI_ERR_DISplacement
Invalid displacement. Either a negative displacement, or a displacement that is too large for the available address space.

Before the error value is returned, the current MPI error handler associated with the communication object (e.g., communicator, window, file) is called. If no communication object is associated with the MPI call, then the call is considered attached to MPI_COMM_SELF and will call the associated MPI error handler. When MPI_COMM_SELF is not initialized (i.e., before MPI_Init/MPI_Init_thread, after MPI_Finalize, or when using the Sessions Model exclusively) the error raises the initial error handler. The initial error handler can be changed by calling MPI_Comm_set_errhandler on MPI_COMM_SELF when using the World model, or the mpi_initial_errhandler CLI argument to mpiexec or info key to MPI_Comm_spawn/MPI_Comm_spawn_multiple. If no other appropriate error handler has been set, then the MPI_ERRORS_RETURN error handler is called for MPI I/O functions and the MPI_ERRORS_ABORT error handler is called for all other MPI functions.

Open MPI includes three predefined error handlers that can be used:

  • MPI_ERRORS_ARE_FATAL Causes the program to abort all connected MPI processes.
  • MPI_ERRORS_ABORT An error handler that can be invoked on a communicator, window, file, or session. When called on a communicator, it acts as if MPI_Abort was called on that communicator. If called on a window or file, acts as if MPI_Abort was called on a communicator containing the group of processes in the corresponding window or file. If called on a session, aborts only the local process.
  • MPI_ERRORS_RETURN Returns an error code to the application.

MPI applications can also implement their own error handlers by calling:

  • MPI_Comm_create_errhandler then MPI_Comm_set_errhandler
  • MPI_File_create_errhandler then MPI_File_set_errhandler
  • MPI_Session_create_errhandler then MPI_Session_set_errhandler or at MPI_Session_init
  • MPI_Win_create_errhandler then MPI_Win_set_errhandler

Note that MPI does not guarantee that an MPI program can continue past an error.
