MPI_DIST_GRAPH_CREATE_ADJACENT(3) Open MPI MPI_DIST_GRAPH_CREATE_ADJACENT(3)

MPI_Dist_graph_create_adjacent — Crea un nuevo comunicador al que se le ha adjuntado información de topología.

SINTAXIS

Sintaxis en C

#include <mpi.h>
int MPI_Dist_graph_create_adjacent(MPI_Comm comm_old, int indegree, const int sources[],
     const int sourceweights[], int outdegree, const int destinations[], const int destweights[],
        MPI_Info info, int reorder, MPI_Comm *comm_dist_graph)

Sintaxis Fortran

USE MPI
! o la forma más antigua: INCLUDE 'mpif.h'
MPI_DIST_GRAPH_CREATE_ADJACENT(COMM_OLD, INDEGREE, SOURCES, SOURCEWEIGHTS, OUTDEGREE,
                DESTINATIONS, DESTWEIGHTS, INFO, REORDER, COMM_DIST_GRAPH, IERROR)
     INTEGER COMM_OLD, INDEGREE, SOURCES(*), SOURCEWEIGHTS(*), OUTDEGREE, DESTINATIONS(*), DESTWEIGHTS(*), INFO
     INTEGER COMM_DIST_GRAPH, IERROR
     LOGICAL REORDER

Sintaxis Fortran 2008

USE mpi_f08
MPI_Dist_Graph_create_adjacent(comm_old, indegree, sources, sourceweights,
             outdegree, destinations, destweights, info, reorder,
             comm_dist_graph, ierror)
     TYPE(MPI_Comm), INTENT(IN) :: comm_old
     INTEGER, INTENT(IN) :: indegree, sources(indegree), outdegree, destinations(outdegree)
     INTEGER, INTENT(IN) :: sourceweights(*), destweights(*)
     TYPE(MPI_Info), INTENT(IN) :: info
     LOGICAL, INTENT(IN) :: reorder
     TYPE(MPI_Comm), INTENT(OUT) :: comm_dist_graph
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARÁMETROS DE ENTRADA

  • comm_old: Comunicador de entrada sin topología (manejador).
  • indegree: Tamaño de los arrays sources y sourceweights (entero no negativo).
  • sources: Rangos de procesos para los cuales el proceso que llama es un destino (array de enteros no negativos).
  • sourceweights: Pesos de las aristas de entrada al proceso que llama (array de enteros no negativos).
  • outdegree: Tamaño de los arrays destinations y destweights (entero no negativo).
  • destinations: Rangos de procesos para los cuales el proceso que llama es un origen (array de enteros no negativos).
  • destweights: Pesos de las aristas de salida del proceso que llama (array de enteros no negativos).
  • info: Pistas sobre optimización e interpretación de pesos (manejador).
  • reorder: El orden de los procesos puede ser reordenado (true) o no (false) (lógico).

PARÁMETROS DE SALIDA

  • comm_dist_graph: Comunicador con topología de grafo distribuido añadida (manejador).
  • ierror: Solo Fortran: estado del error (entero).

DESCRIPCIÓN

MPI_Dist_graph_create_adjacent crea un nuevo comunicador comm_dist_graph con topología de grafo distribuido y devuelve un manejador para el nuevo comunicador. El número de procesos en comm_dist_graph es idéntico al número de procesos en comm_old. Cada proceso proporciona toda la información sobre sus aristas entrantes y salientes en la topología de grafo distribuido virtual. Los procesos que llaman deben asegurarse de que cada arista del grafo se describe en el proceso de origen y en el de destino con los mismos pesos. Si hay múltiples aristas para un par (origen, destino) dado, entonces la secuencia de los pesos de estas aristas no importa. La topología de comunicación completa es la combinación de todas las aristas mostradas en los arrays sources de todos los procesos en comm_old, que debe ser idéntica a la combinación de todas las aristas mostradas en los arrays destinations. Los rangos de origen y destino deben ser rangos de procesos de comm_old. Esto permite una especificación completamente distribuida del grafo de comunicación. Se permiten procesos aislados (es decir, procesos sin aristas salientes ni entrantes, es decir, procesos que han especificado indegree y outdegree como cero y, por lo tanto, no aparecen como rango de origen o destino en la especificación del grafo). La llamada a MPI_Dist_graph_create_adjacent es colectiva.

PESOS

Los pesos se especifican como enteros no negativos y pueden usarse para influir en la estrategia de reasignación de procesos y otras optimizaciones internas de MPI. Por ejemplo, los recuentos aproximados de argumentos de llamadas de comunicación posteriores a lo largo de aristas específicas podrían usarse como sus pesos de arista. La multiplicidad de aristas también puede indicar una comunicación más intensa entre pares de procesos. Sin embargo, el significado exacto de los pesos de arista no está especificado por el estándar MPI y se deja a la implementación. Una aplicación puede proporcionar el valor especial MPI_UNWEIGHTED para el array de pesos para indicar que todas las aristas tienen el mismo peso (efectivamente, ninguno). Es un error proporcionar MPI_UNWEIGHTED para algunos, pero no para todos, los procesos de comm_old. Si el grafo tiene pesos pero indegree o outdegree es cero, entonces MPI_WEIGHTS_EMPTY o cualquier array arbitrario pueden pasarse a sourceweights o destweights respectivamente. Tenga en cuenta que MPI_UNWEIGHTED y MPI_WEIGHTS_EMPTY no son valores de peso especiales; en cambio, son valores especiales para el argumento del array total. En Fortran, MPI_UNWEIGHTED y MPI_WEIGHTS_EMPTY son objetos como MPI_BOTTOM (no utilizables para inicialización o asignación). Consulte la sección 2.5.4 del estándar MPI-3.

ERRORES

Casi todas las rutinas de MPI devuelven un valor de error; las rutinas en C como resultado de retorno de la función y las rutinas en Fortran en el último argumento.

Antes de que se devuelva el valor de error, se llama al controlador de errores de MPI actual asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo). Si no hay un objeto de comunicación asociado con la llamada MPI, entonces la llamada se considera adjunta a MPI_COMM_SELF y llamará al controlador de errores de MPI asociado. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se usa exclusivamente el Modelo de Sesiones), el error genera el controlador de errores inicial. El controlador de errores inicial puede cambiarse llamando a MPI_Comm_set_errhandler en MPI_COMM_SELF cuando se usa el modelo World, o el argumento CLI mpi_initial_errhandler para mpiexec o la clave de información para MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no se ha establecido ningún otro controlador de errores adecuado, entonces se llama al controlador de errores MPI_ERRORS_RETURN para las funciones de E/S de MPI y al controlador de errores MPI_ERRORS_ABORT para todas las demás funciones de MPI.

Open MPI incluye tres controladores de errores predefinidos que se pueden utilizar:

  • MPI_ERRORS_ARE_FATAL Provoca que el programa termine todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT Un controlador de errores que se puede invocar en un comunicador, ventana, archivo o sesión. Cuando se llama en un comunicador, actúa como si se hubiera llamado a MPI_Abort en ese comunicador. Si se llama en una ventana o archivo, actúa como si se hubiera llamado a MPI_Abort en un comunicador que contiene el grupo de procesos en la ventana o archivo correspondiente. Si se llama en una sesión, aborta solo el proceso local.
  • MPI_ERRORS_RETURN Devuelve un código de error a la aplicación.

Las aplicaciones MPI también pueden implementar sus propios controladores de errores llamando a:

  • MPI_Comm_create_errhandler y luego MPI_Comm_set_errhandler
  • MPI_File_create_errhandler y luego MPI_File_set_errhandler
  • MPI_Session_create_errhandler y luego MPI_Session_set_errhandler o en MPI_Session_init
  • MPI_Win_create_errhandler y luego MPI_Win_set_errhandler

Tenga en cuenta que MPI no garantiza que un programa MPI pueda continuar después de un error.

Consulte la página del manual de MPI para obtener una lista completa de los códigos de error de MPI.

Consulte la sección de Manejo de Errores del estándar MPI-3.1 para obtener más información.
