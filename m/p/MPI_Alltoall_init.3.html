PARÁMETROS DE ENTRADA

  • sendbuf: Dirección de inicio del búfer de envío (elección).
  • sendcount: Número de elementos a enviar a cada proceso (entero).
  • sendtype: Tipo de datos de los elementos del búfer de envío (manejador).
  • recvcount: Número de elementos a recibir de cada proceso (entero).
  • recvtype: Tipo de datos de los elementos del búfer de recepción (manejador).
  • comm: Comunicador sobre el cual se intercambiarán los datos (manejador).
  • info: Información (manejador, solo persistente)

PARÁMETROS DE SALIDA

  • recvbuf: Dirección de inicio del búfer de recepción (elección).
  • request: Solicitud (manejador, solo no bloqueante).
  • ierror: Solo Fortran: Estado de error (entero).

DESCRIPCIÓN

MPI_Alltoall es una operación colectiva en la que todos los procesos envían la misma cantidad de datos entre sí y reciben la misma cantidad de datos entre sí. La operación de esta rutina se puede representar de la siguiente manera, donde cada proceso realiza 2n (n siendo el número de procesos en el comunicador comm) comunicaciones punto a punto independientes (incluyendo la comunicación consigo mismo).

MPI_Comm_size(comm, &n);
for (i = 0, i < n; i++)
    MPI_Send(sendbuf + i * sendcount * extent(sendtype),
        sendcount, sendtype, i, ..., comm);
for (i = 0, i < n; i++)
    MPI_Recv(recvbuf + i * recvcount * extent(recvtype),
        recvcount, recvtype, i, ..., comm);

Cada proceso divide su sendbuf local en n bloques, cada uno que contiene sendcount elementos del tipo sendtype, y divide su recvbuf de manera similar según recvcount y recvtype. El proceso j envía el k-ésimo bloque de su sendbuf local al proceso k, que coloca los datos en el j-ésimo bloque de su recvbuf local. La cantidad de datos enviados debe ser igual a la cantidad de datos recibidos, pares por pares, entre cada par de procesos.

CUANDO EL COMUNICADOR ES UN INTER-COMUNICADOR

Cuando el comunicador es un inter-comunicador, la operación de agrupación ocurre en dos fases. Los datos se agrupan de todos los miembros del primer grupo y se reciben por todos los miembros del segundo grupo. Luego, los datos se agrupan de todos los miembros del segundo grupo y se reciben por todos los miembros del primero. La operación exhibe un comportamiento simétrico de dúplex completo.

El primer grupo define el proceso raíz. El proceso raíz usa MPI_ROOT como valor de root. Todos los demás procesos del primer grupo usan MPI_PROC_NULL como valor de root. Todos los procesos del segundo grupo usan el rango del proceso raíz en el primer grupo como valor de root.

Cuando el comunicador es un intra-comunicador, estos grupos son los mismos y la operación ocurre en una sola fase.

USO DE LA OPCIÓN IN-PLACE

Cuando el comunicador es un intra-comunicador, puede realizar una operación de todos a todos en el lugar (el búfer de salida se utiliza como búfer de entrada). Utilice la variable MPI_IN_PLACE como valor de sendbuf. En este caso, se ignoran sendcount y sendtype. Se supone que los datos de entrada de cada proceso están en el área donde ese proceso recibiría su propia contribución al búfer de recepción.

NOTAS

Todos los argumentos en todos los procesos son significativos. El argumento comm, en particular, debe describir el mismo comunicador en todos los procesos.

Hay dos funciones de la biblioteca MPI que son más generales que MPI_Alltoall. MPI_Alltoallv permite la comunicación de todos a todos desde y hacia búferes que no necesitan ser contiguos; diferentes procesos pueden enviar y recibir diferentes cantidades de datos. MPI_Alltoallw expande la funcionalidad de MPI_Alltoallv para permitir el intercambio de datos con diferentes tipos de datos.

ERRORES

Casi todas las rutinas MPI devuelven un valor de error; rutinas C como resultado de retorno de la función y rutinas Fortran en el último argumento.

Antes de que se devuelva el valor de error, se llama al controlador de errores MPI actual asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo). Si no hay ningún objeto de comunicación asociado con la llamada MPI, la llamada se considera adjunta a MPI_COMM_SELF y llamará al controlador de errores MPI asociado. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o al usar exclusivamente el Modelo de Sesiones), el error eleva el controlador de errores inicial. El controlador de errores inicial se puede cambiar llamando a MPI_Comm_set_errhandler en MPI_COMM_SELF cuando se usa el modelo World, o el argumento de CLI mpi_initial_errhandler a mpiexec o la clave info a MPI_Comm_spawn/ MPI_Comm_spawn_multiple. Si no se ha configurado ningún otro controlador de errores apropiado, se llama al controlador de errores MPI_ERRORS_RETURN para las funciones de E/S de MPI y al controlador de errores MPI_ERRORS_ABORT para todas las demás funciones de MPI.

ERRORS

All MPI routines (except MPI_Wtime and MPI_Wtick) return an error code. MPI_ERR_PENDING is not returned by any MPI routine. MPI routines that return an error code as described above will also return the MPI error code of the last error that occurred on the invoked communicator, window, file, or session. All MPI routines that do not return an error code will return MPI_SUCCESS on success and a nonzero error code otherwise. MPI error codes are specified in the MPI man page.

The default error handler for all MPI routines except MPI_Init_thread, MPI_Finalize, and MPI_Abort is MPI_ERRORS_ARE_FATAL. The default error handler for MPI_Init_thread and MPI_Finalize is MPI_ERRORS_RETURN. The default error handler for MPI_Abort is an intrinsic error handler that always returns MPI_ERR_INTERN.

  • MPI_ERRORS_ARE_FATAL Causes the program to abort all connected MPI processes.
  • MPI_ERRORS_ABORT An error handler that can be invoked on a communicator, window, file, or session. When called on a communicator, it acts as if MPI_Abort was called on that communicator. If called on a window or file, acts as if MPI_Abort was called on a communicator containing the group of processes in the corresponding window or file. If called on a session, aborts only the local process.
  • MPI_ERRORS_RETURN Returns an error code to the application.

MPI applications can also implement their own error handlers by calling:

  • MPI_Comm_create_errhandler then MPI_Comm_set_errhandler
  • MPI_File_create_errhandler then MPI_File_set_errhandler
  • MPI_Session_create_errhandler then MPI_Session_set_errhandler or at MPI_Session_init
  • MPI_Win_create_errhandler then MPI_Win_set_errhandler

Note that MPI does not guarantee that an MPI program can continue past an error.

See the MPI man page for a full list of MPI error codes.

See the Error Handling section of the MPI-3.1 standard for more information.
