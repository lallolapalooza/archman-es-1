MPI_Publish_name — Publica un nombre de servicio asociado con un puerto

SINTAXIS

Sintaxis C

#include <mpi.h>
int MPI_Publish_name(const char *service_name, MPI_Info info,
     const char *port_name)

Sintaxis Fortran

USE MPI
! o la forma más antigua: INCLUDE 'mpif.h'
MPI_PUBLISH_NAME(SERVICE_NAME, INFO, PORT_NAME, IERROR)
     CHARACTER*(*)   SERVICE_NAME, PORT_NAME
     INTEGER         INFO, IERROR

Sintaxis Fortran 2008

USE mpi_f08
MPI_Publish_name(service_name, info, port_name, ierror)
     TYPE(MPI_Info), INTENT(IN) :: info
     CHARACTER(LEN=*), INTENT(IN) :: service_name, port_name
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARÁMETROS DE ENTRADA

  • service_name: Un nombre de servicio (cadena).
  • info: Opciones para las funciones de servicio de nombres (manejador).
  • port_name: Un nombre de puerto (cadena).

PARÁMETRO DE SALIDA

•
ierror: Solo Fortran: Estado de error (entero).

DESCRIPCIÓN

Esta rutina publica el par (service_name, port_name) para que una aplicación pueda obtener port_name llamando a MPI_Lookup_name con service_name como argumento. Es un error publicar el mismo service_name dos veces, o usar un argumento port_name que no haya sido previamente abierto por el proceso que llama mediante una llamada a MPI_Open_port.

ARGUMENTOS DE INFO

Se reconocen las siguientes claves para info:

Clave                 Tipo      Descripción
---                   ----      -----------
ompi_global_scope     bool      Si se establece en verdadero, publica el nombre
                                en el ámbito global. Publica en el ámbito local
                                de lo contrario. Ver la sección DE ÁMBITO DE
                                NOMBRES para más detalles.
ompi_unique           bool      Si se establece en verdadero, devuelve un error si
                                el service_name especificado ya existe.
                                Por defecto, sobrescribe cualquier valor preexistente.

Las claves de info de tipo bool son en realidad cadenas, pero se evalúan de la siguiente manera: si el valor de la cadena es un número, se convierte a un entero y se convierte a un booleano (lo que significa que los enteros cero son falsos y los valores distintos de cero son verdaderos). Si el valor de la cadena es "sí" o "verdadero" (sin distinción de mayúsculas y minúsculas), el booleano es verdadero. Si el valor de la cadena es "no" o "falso" (sin distinción de mayúsculas y minúsculas), el booleano es falso. Todos los demás valores de cadena no se reconocen y, por lo tanto, son falsos.

Si no se proporciona ninguna clave de info, la función primero comprobará si se ha especificado un servidor global y está disponible. Si es así, la función de publicación tendrá por defecto el ámbito global primero, seguido del local. De lo contrario, los datos tendrán por defecto publicar con ámbito local.

ÁMBITO DE NOMBRES

Open MPI admite dos ámbitos de nombres: global y local. El ámbito local colocará el par servicio/puerto especificado en un almacén de datos ubicado en el mpirun del trabajo del proceso que llama. Por lo tanto, los datos publicados con ámbito local solo serán accesibles para los procesos en trabajos iniciados por ese mpirun, por ejemplo, procesos en el trabajo del proceso que llama, o en trabajos iniciados a través de MPI_Comm_spawn.

El ámbito global coloca el par servicio/puerto especificado en un almacén de datos ubicado en un servidor central al que pueden acceder todos los trabajos que se ejecutan en el clúster o entorno. Por lo tanto, los datos publicados con ámbito global pueden ser accedidos por múltiples mpiruns y utilizados para MPI_Comm_connect y MPI_Comm_accept entre trabajos.

Tenga en cuenta que las operaciones de ámbito global requieren tanto la presencia del servidor central como que el proceso que llama pueda comunicarse con ese servidor. MPI_Publish_name devolverá un error si se especifica el ámbito global y no se especifica un servidor global o no se puede encontrar.

Open MPI proporciona un servidor llamado ompi-server para admitir operaciones de ámbito global. Consulte su página de manual para obtener una descripción más detallada de las operaciones de almacén/búsqueda de datos.

Como ejemplo del impacto de estas reglas de ámbito, considere el caso en que un trabajo se ha iniciado con mpirun - llame a este trabajo "trabajo1". Un proceso en trabajo1 crea y publica un par servicio/puerto utilizando un ámbito local. Open MPI almacenará estos datos en el almacén de datos dentro de mpirun.

Un proceso en trabajo1 (tal vez el mismo que realizó la publicación, o tal vez otro proceso en el trabajo) llama posteriormente a MPI_Comm_spawn para iniciar otro trabajo (llámelo "trabajo2") bajo este mpirun. Dado que los dos trabajos comparten un mpirun común, ambos trabajos tienen acceso a los datos de ámbito local. Por lo tanto, un proceso en trabajo2 puede realizar una MPI_Lookup_name con un ámbito local para recuperar la información.

Sin embargo, suponga que otro usuario inicia un trabajo usando mpirun - llame a este trabajo "trabajo3". Debido a que los datos de servicio/puerto publicados por trabajo1 especificaron un ámbito local, los procesos en trabajo3 no pueden acceder a esos datos. En contraste, si los datos se hubieran publicado utilizando el ámbito global, entonces cualquier proceso en trabajo3 podría acceder a los datos, siempre que mpirun tuviera conocimiento de cómo contactar al servidor central y el proceso pudiera establecer comunicación con él.

ERRORES

Casi todas las rutinas MPI devuelven un valor de error; rutinas C como resultado de retorno de la función y rutinas Fortran en el último argumento.

Antes de que se devuelva el valor de error, se llama al controlador de errores MPI actual asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo). Si no hay ningún objeto de comunicación asociado con la llamada MPI, entonces la llamada se considera adjunta a MPI_COMM_SELF y llamará al controlador de errores MPI asociado. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se utiliza exclusivamente el Modelo de Sesiones) el error eleva el controlador de errores inicial. El controlador de errores inicial se puede cambiar llamando a MPI_Comm_set_errhandler en MPI_COMM_SELF cuando se utiliza el modelo World, o el argumento CLI mpi_initial_errhandler a mpiexec o clave de info a MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no se ha configurado ningún otro controlador de errores apropiado, se llama al controlador de errores MPI_ERRORS_RETURN para las funciones de E/S MPI y se llama al controlador de errores MPI_ERRORS_ABORT para todas las demás funciones MPI.

Open MPI incluye tres controladores de errores predefinidos que se pueden utilizar:

  • MPI_ERRORS_ARE_FATAL Provoca que el programa aborte todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT Un controlador de errores que puede ser invocado en un comunicador, ventana, archivo o sesión. Cuando se llama en un comunicador, actúa como si se hubiera llamado a MPI_Abort en ese comunicador. Si se llama en una ventana o archivo, actúa como si se hubiera llamado a MPI_Abort en un comunicador que contiene el grupo de procesos en la ventana o archivo correspondiente. Si se llama en una sesión, aborta solo el proceso local.
  • MPI_ERRORS_RETURN Devuelve un código de error a la aplicación.

Las aplicaciones MPI también pueden implementar sus propios controladores de errores llamando a:

  • MPI_Comm_create_errhandler luego MPI_Comm_set_errhandler
  • MPI_File_create_errhandler luego MPI_File_set_errhandler
  • MPI_Session_create_errhandler luego MPI_Session_set_errhandler o en MPI_Session_init
  • MPI_Win_create_errhandler luego MPI_Win_set_errhandler

Tenga en cuenta que MPI no garantiza que un programa MPI pueda continuar después de un error.

Consulte la página del manual de MPI para obtener una lista completa de los códigos de error de MPI.

MPI_Publish_name(3)

NAME

MPI_Publish_name - Publishes a service name.

SYNTAX

C:
    MPI_Publish_name(char *service_name, struct ompi_info_t *info);

INPUT PARAMETERS

service_name
The name of the service to publish. (input)
info
A MPI Info object. This can be MPI_INFO_NULL or an
MPI Info object created with MPI_Info_create. (input)

OUTPUT PARAMETER

None.

DESCRIPTION

This function publishes a service name. The service name is made available to other processes that may want to connect to this service. The info parameter can be used to specify properties of the service. For example, a publisher might specify a particular port number or other connection details. The info parameter can be MPI_INFO_NULL, in which case no additional information is provided.

The exact format and interpretation of the info arguments are implementation-dependent. Refer to the MPI-3.1 standard for more information.

INFO ARGUMENTS

The following info keys are recognized:

hostname
The hostname on which the service is listening. If not specified, the publisher will try to determine this automatically.
port
The port number on which the service is listening. If not specified, the publisher will try to determine this automatically.

NAME SCOPE

This function is not collective. It publishes a name within the scope of the communicator.

ERRORS

This function may fail if the name cannot be published, for example, if the name is already in use or if there are resource limitations. Refer to the MPI-3.1 standard for more information.
