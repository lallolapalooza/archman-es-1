PARÁMETROS DE ENTRADA

  • sendbuf: Búfer de envío (elección).
  • count: Número de elementos en el búfer de entrada (entero).
  • datatype: Tipo de datos de los elementos del búfer de entrada (manejador).
  • op: Operación (manejador).
  • comm: Comunicador (manejador).
  • info: Info (manejador, solo persistente)

PARÁMETROS DE SALIDA

  • recvbuf: Búfer de recepción (elección).
  • request: Solicitud (manejador, solo no bloqueante).
  • ierror: Solo Fortran: Estado de error (entero).

DESCRIPCIÓN

MPI_Scan se utiliza para realizar una reducción de prefijo inclusiva en datos distribuidos entre los procesos que llaman. La operación devuelve, en el recvbuf del proceso con rango i, la reducción (calculada según la función op) de los valores en los sendbufs de los procesos con rangos 0, ..., i (inclusivo). El tipo de operaciones admitidas, sus semánticas y las restricciones en los búferes de envío y recepción son las mismas que para MPI_Reduce.

EJEMPLO

Este ejemplo utiliza una operación definida por el usuario para producir un escaneo segmentado. Un escaneo segmentado toma, como entrada, un conjunto de valores y un conjunto de booleanos, donde los booleanos delimitan los diversos segmentos del escaneo. Por ejemplo,

valores    v1      v2      v3      v4      v5      v6      v7      v8
booleanos  0       0       1       1       1       0       0       1
resultado  v1    v1+v2     v3    v3+v4  v3+v4+v5   v6    v6+v7     v8

El resultado para el rango j es, por lo tanto, la suma v(i) + ... + v(j), donde i es el rango más bajo tal que para todos los rangos n, i <= n <= j, logical(n) = logical(j). El operador que produce este efecto es

      [ u ]     [ v ]     [ w ]
      [   ]  o  [   ]  =  [   ]
      [ i ]     [ j ]     [ j ]
donde
    ( u + v si i = j w = ( ( v si i != j

Tenga en cuenta que este es un operador no conmutativo. El código C que lo implementa se proporciona a continuación.

typedef struct {
        double val;
        int log;
} SegScanPair;
/*
 * la función definida por el usuario
 */
void segScan(SegScanPair *in, SegScanPair *inout, int *len,
        MPI_Datatype *dptr)
{
        int i;
        SegScanPair c;
        for (i = 0; i < *len; ++i) {
                if (in->log == inout->log)
                        c.val = in->val + inout->val;
                else
                        c.val = inout->val;
                c.log = inout->log;
                *inout = c;
                in++;
                inout++;
        }
}

Tenga en cuenta que el argumento inout de la función definida por el usuario corresponde al operando de la derecha del operador. Al usar este operador, debemos tener cuidado de especificar que no es conmutativo, como en lo siguiente:

int                     i, base;
SeqScanPair     a, answer;
MPI_Op          myOp;
MPI_Datatype    type[2] = {MPI_DOUBLE, MPI_INT};
MPI_Aint                disp[2];
int                     blocklen[2] = {1, 1};
MPI_Datatype    sspair;
/*
 * explicar a MPI cómo se define el tipo SegScanPair
 */
MPI_Get_address(a, disp);
MPI_Get_address(a.log, disp + 1);
base = disp[0];
for (i = 0; i < 2; ++i)
        disp[i] -= base;
MPI_Type_struct(2, blocklen, disp, type, &sspair);
MPI_Type_commit(&sspair);
/*
 * crear la operación de usuario de escaneo segmentado
 * no conmutativo - establecer commute (arg 2) a 0
 */
MPI_Op_create((MPI_User_function *)segScan, 0, &myOp);
...
MPI_Scan(a, answer, 1, sspair, myOp, comm);

USO DE LA OPCIÓN IN-PLACE

Cuando el comunicador es un intracommunicator, puede realizar una operación de escaneo en su lugar (el búfer de salida se utiliza como búfer de entrada). Utilice la variable MPI_IN_PLACE como valor del argumento sendbuf. Los datos de entrada se toman del búfer de recepción y se reemplazan por los datos de salida.

NOTAS SOBRE OPERACIONES COLECTIVAS

Las funciones de reducción de tipo MPI_Op no devuelven un valor de error. Como resultado, si las funciones detectan un error, lo único que pueden hacer es llamar a MPI_Abort o omitir silenciosamente el problema. Por lo tanto, si el manejador de errores se cambia de MPI_ERRORS_ARE_FATAL a otra cosa (por ejemplo, MPI_ERRORS_RETURN), es posible que no se indique ningún error.

La razón de esto son los problemas de rendimiento para garantizar que todas las rutinas colectivas devuelvan el mismo valor de error.

ERRORES

Casi todas las rutinas MPI devuelven un valor de error; las rutinas C como el resultado de la función y las rutinas Fortran en el último argumento.

Antes de que se devuelva el valor de error, se llama al manejador de errores MPI actual asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo). Si no hay ningún objeto de comunicación asociado con la llamada MPI, entonces la llamada se considera adjunta a MPI_COMM_SELF y llamará al manejador de errores MPI asociado. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se utilizan exclusivamente los modelos de Sesión) el error eleva el manejador de errores inicial. El manejador de errores inicial se puede cambiar llamando a MPI_Comm_set_errhandler en MPI_COMM_SELF cuando se utiliza el modelo World, o el mpi_initial_errhandl
