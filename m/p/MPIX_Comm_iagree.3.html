Paquete: openmpi

MPIX_Comm_iagree(3) Open MPI MPIX_Comm_iagree(3)

MPIX_Comm_agree, MPIX_Comm_iagree - Acuerdan un valor de flag binario entre todos los procesos vivos y distribuyen el resultado a todos los procesos vivos, incluso después de que se produzcan fallos.

Esto es parte de la extensión ULFM (User Level Fault Mitigation).

SINTAXIS

Sintaxis C

#include <mpi.h>
#include <mpi-ext.h>
int MPIX_Comm_agree(MPI_Comm comm, int *flag)
int MPIX_Comm_iagree(MPI_Comm comm, int *flag, MPI_Request *request)

Sintaxis Fortran

USE MPI
USE MPI_EXT
! o la forma antigua: INCLUDE 'mpif.h'
MPIX_COMM_AGREE(COMM, FLAG, IERROR)
     INTEGER COMM, FLAG, IERROR
MPIX_COMM_IAGREE(COMM, FLAG, REQUEST, IERROR)
     INTEGER COMM, FLAG, REQUEST, IERROR

Sintaxis Fortran 2008

USE mpi_f08
USE mpi_ext_f08
MPIX_Comm_agree(comm, flag, ierror)
     TYPE(MPI_Comm), INTENT(IN) :: comm
     INTEGER, INTENT(INOUT) :: flag
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror
MPIX_COMM_IAGREE(COMM, FLAG, REQUEST, IERROR)
     TYPE(MPI_Comm), INTENT(IN) :: comm
     INTEGER, INTENT(INOUT), ASYNCHRONOUS :: flag
     TYPE(MPI_Request), INTENT(OUT) :: request
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARÁMETROS DE ENTRADA

  • comm: Comunicador (handle).
  • flag: Flags binarios (entero).

PARÁMETROS DE SALIDA

  • flag: Flags binarios reducidos (entero).
  • request: Request (handle, solo no bloqueado).
  • ierror: Solo en Fortran: Estado de error (entero).

DESCRIPCIÓN

Esta comunicación colectiva acuerda el valor entero flag y (implícitamente) el grupo de procesos fallidos en comm.

Una vez completada, todos los procesos no fallidos de MPI han acordado establecer el valor de salida del entero flag en el resultado de una operación de AND bitwise sobre los valores de entrada contribuidos por flag.

MPIX_Comm_iagree es la versión no bloqueada de MPIX_Comm_agree.

FALLOS DE PROCESOS

Cuando un proceso MPI falla antes de contribuir a la operación de acuerdar, el flag se calcula ignorando su contribución, y la operación lanza un error de clase MPIX_ERR_PROC_FAILED.

Cuando se lanza un error de clase MPIX_ERR_PROC_FAILED, es consistentemente lanzado en todos los procesos MPI en el grupo(s) de comm.

Después de que MPIX_Comm_agree lanza un error de clase MPIX_ERR_PROC_FAILED, el grupo producido por una llamada posterior a MPIX_Comm_get_failed en comm contiene a todos los procesos MPI que no contribuyeron al cálculo de flag.

CUANDO EL COMUNICADOR CONTIENE FALLOS RECONOCIDOS

Si todos los procesos MPI en el grupo de comm han reconocido la falla de un proceso MPI (utilizando MPIX_Comm_ack_failed) antes de la llamada a MPIX_Comm_agree (o MPIX_Comm_iagree), el error MPIX_ERR_PROC_FAILED no se lanza cuando el valor de salida de flag ignora la contribución de ese proceso fallido. Nota: esto es una propiedad uniforme: si se encuentra un proceso no contribuyente que no esté reconocido en cualquier proceso vivo de comm, todos los procesos lanzan un error de clase MPIX_ERR_PROC_FAILED.

Ejemplo 1: Usando una combinación de MPIX_Comm_ack_failed y MPIX_Comm_agree, los usuarios pueden propagar y sincronizar el conocimiento de fallos entre todos los procesos MPI en comm.

Comm_get_failed_consistent(MPI_Comm c, MPI_Group * g) {
    int rc; int T=1;
    int size; int num_acked;
    MPI_Group gf;
    int ranges[3] = {0, 0, 1};
    MPI_Comm_size(c, &size);
    do {
        /* esta rutina no es pura: llamar a MPIX_Comm_ack_failed
         * afecta el estado del comunicador c */
        MPIX_Comm_ack_failed(c, size, &num_acked);
        /* simplemente ignora el valor T en este ejemplo */
        rc = MPIX_Comm_agree(c, &T);
    } while( rc != MPI_SUCCESS );
    /* después de este bucle, MPIX_Comm_agree ha devuelto MPI_SUCCESS en
     * todos los procesos, así que todos los procesos han reconocido el mismo
     * conjunto de fallos. Vamos a obtener ese conjunto de fallos en el grupo g.
     */
    if( 0 == num_acked ) {
        *g = MPI_GROUP_EMPTY;
    }
    else {
        MPIX_Comm_get_failed(c, &gf);
        ranges[1] = num_acked - 1;
        MPI_Group_range_incl(gf, 1, ranges, g);
        MPI_Group_free(&gf);
    }
}

CUANDO EL COMUNICADOR ES REVOCADO

Esta función nunca lanza un error de clase MPIX_ERR_REVOKED. El significado definido de MPIX_Comm_agree se mantiene cuando el comunicador comm es revocado, o cuando el grupo de comm contiene procesos MPI fallidos. En particular, MPIX_Comm_agree es una operación colectiva, incluso cuando comm es revocado.

CUANDO EL COMUNICADOR ES UN INTERCOMUNICADOR

Cuando el comunicador es un intercomunicador, el valor de flag es una operación AND bitwise sobre los valores contribuidos por el grupo remoto.

Cuando se lanza un error de clase MPIX_ERR_PROC_FAILED, es consistentemente lanzado en todos los procesos MPI en el grupo(s) de comm, es decir, en ambos el grupo local y el remoto del intercomunicador.

ERRORES

La mayoría de las rutinas MPI devuelven un valor de error; en las rutinas C, el resultado es el valor de retorno de la función, y en las rutinas Fortran, el último argumento es el valor de error.

Antes de devolver el valor de error, se llama al manejador de errores asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo) actual. Si no hay objeto de comunicación asociado con la llamada MPI, se considera que la llamada está asociada a MPI_COMM_SELF y se llama al manejador de errores correspondiente. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se usa el Modelo de Sesiones exclusivamente), el error lanza el manejador de errores inicial. El manejador de errores inicial puede cambiarse llamando a MPI_Comm_set_errhandler sobre MPI_COMM_SELF cuando se use el Modelo del Mundo, o a la clave info de MPI_Comm_spawn/MPI_Comm_spawn_multiple o al argumento mpiexec. Si no hay otro manejador adecuado, se llama al manejador de errores MPI_ERRORS_RETURN para funciones de I/O MPI y al manejador de errores MPI_ERRORS_ABORT para todas las otras funciones MPI.

Open MPI incluye tres manejadores prediseñados que pueden utilizarse:

  • MPI_ERRORS_ARE_FATAL Lanza el programa para abortar todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT Un manejador que puede invocarse en un comunicador, ventana, archivo o sesión. Cuando se invoca en un comunicador, actúa como si se hubiera llamado MPI_Abort en ese comunicador. Si se invoca en una ventana o archivo, actúa como si se hubiera llamado MPI_Abort en un comunicador que contiene el grupo de procesos en la ventana o archivo correspondiente. Si se invoca en una sesión, aborta solo el proceso local.
  • MPI_ERRORS_RETURN Devuelve un código de error a la aplicación.

Las aplicaciones MPI también pueden implementar sus propios manejadores de error llamando:

  • MPI_Comm_create_errhandler luego MPI_Comm_set_errhandler
  • MPI_File_create_errhandler luego MPI_File_set_errhandler
  • MPI_Session_create_errhandler luego MPI_Session_set_errhandler o en MPI_Session_init
  • MPI_Win_create_errhandler luego MPI_Win_set_errhandler

MPIX_Comm_iagree(3) MPI Routines

NAME

MPIX_Comm_iagree - Performs an asynchronous inclusive group-wide agreement on data, detecting and handling process failures.

SYNTAX

C

int MPIX_Comm_iagree(MPI_Comm comm, void *sendbuf, void *recvbuf, int count,
                     MPI_Datatype datatype, MPI_Op op, MPI_Request *request);

Fortran

CALL MPIX_Comm_iagree(comm, sendbuf, recvbuf, count, datatype, op, request, ierr)

Fortran 90

CALL MPIX_Comm_iagree(comm, sendbuf, recvbuf, count, datatype, op, request, ierr)

INPUT PARAMETERS

‐ comm
Communicator with a valid process group.
‐ sendbuf
Starting address of the send buffer (significant only for the root process).
‐ count
Number of elements in the send buffer.
‐ datatype
Datatype of elements in the send buffer.
‐ op
Operation to be applied (e.g., MPI_SUM, MPI_MAX).

OUTPUT PARAMETERS

‐ recvbuf
Starting address of the receive buffer (contains the result of the operation).
‐ request
MPI request handle, used to check for completion and retrieve results.
‐ ierr
(Fortran only) Fortran integer return code.

DESCRIPTION

The MPIX_Comm_iagree routine performs an asynchronous inclusive group-wide agreement operation on data. It is similar to MPI_Allreduce but provides asynchronous behavior and enhanced error handling capabilities, specifically designed to continue execution even if some processes fail.

All processes in the communicator comm must execute this routine. The data from sendbuf on each process is combined using the specified operation op. The final result is distributed to the recvbuf on all processes in the communicator.

The operation is *inclusive*, meaning that the data from all processes in the group is included in the reduction. The op must be a commutative and associative operation. Predefined operations include MPI_SUM, MPI_MAX, MPI_MIN, MPI_PROD, MPI_LAND, MPI_LOR, MPI_LXOR, MPI_BAND, MPI_BOR, MPI_B XOR, MPI_MAXLOC, MPI_MINLOC.

This routine is non-blocking. It returns an MPI_Request handle that can be used later with MPI_Wait or MPI_Test to check for completion and retrieve the results. The request parameter should not be MPI_REQUEST_NULL.

PROCESS FAILURES

A key feature of MPIX_Comm_iagree is its ability to handle process failures. If a process fails during the execution of MPIX_Comm_iagree, the operation may still complete successfully if the remaining processes can reach an agreement without the failed process. The behavior depends on the communicator's properties and the specific failure detection mechanisms in place.

WHEN THE COMMUNICATOR CONTAINS ACKNOWLEDGED FAILURES

If the communicator comm contains processes that have already been acknowledged as failed (e.g., through prior calls to MPIX_Comm_ack_failed), MPIX_Comm_iagree will attempt to proceed with the remaining active processes. If enough processes remain to form a quorum and complete the operation, it will succeed. Otherwise, it may return an error.

WHEN THE COMMUNICATOR IS REVOKED

If the communicator comm has been revoked (e.g., through a call to MPIX_Comm_revoke), subsequent operations on this communicator, including MPIX_Comm_iagree, will typically result in an error, as revoked communicators are no longer valid for communication.

WHEN COMMUNICATOR IS AN INTER-COMMUNICATOR

This routine cannot be used with inter-communicators.

ERRORS

When the communicator is not revoked, MPIX_Comm_iagree might fail if any process in the communicator, other than the one calling the function, fails. If the communicator is corrupted or invalid, MPIX_Comm_iagree will raise an error.

The specific error codes returned depend on the MPI implementation and the nature of the failure. Common MPI error codes include:

  • MPI_ERR_PENDING: The request is still pending.
  • MPI_ERR_BUFFER: Invalid buffer pointer.
  • MPI_ERR_COUNT: Invalid count.
  • MPI_ERR_TYPE: Invalid datatype.
  • MPI_ERR_OP: Invalid operation.
  • MPI_ERR_COMM: Invalid communicator.
  • MPI_ERR_REVOKED: The communicator has been revoked.
  • MPI_ERR_OTHER: Other errors, potentially related to process failures.

It is important to check the return status of MPI_Wait or MPI_Test for detailed error information. You can also configure MPI to abort the job on certain errors, or to allow an MPI program to continue past an error.

See the MPI man page for a full list of MPI error codes.

See the Error Handling section of the MPI-3.1 standard for more information.
