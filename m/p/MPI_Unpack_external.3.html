MPI_Unpack_external — Lee datos desde un formato portable

SINTAXIS

Sintaxis C

#include <mpi.h>
int MPI_Unpack_external(const char datarep[], const void *inbuf,
     MPI_Aint insize, MPI_Aint *position,
     void *outbuf, int outcount,
     MPI_Datatype datatype)

Sintaxis Fortran

USE MPI
! o la forma más antigua: INCLUDE 'mpif.h'
MPI_UNPACK_EXTERNAL(DATAREP, INBUF, INSIZE, POSITION,
     OUTBUF, OUTCOUNT, DATATYPE, IERROR)
     INTEGER         OUTCOUNT, DATATYPE, IERROR
     INTEGER(KIND=MPI_ADDRESS_KIND) INSIZE, POSITION
     CHARACTER*(*)   DATAREP
     <type>          INBUF(*), OUTBUF(*)

Sintaxis Fortran 2008

USE mpi_f08
MPI_Unpack_external(datarep, inbuf, insize, position, outbuf, outcount,
             datatype, ierror)
     CHARACTER(LEN=*), INTENT(IN) :: datarep
     TYPE(*), DIMENSION(..), INTENT(IN) :: inbuf
     TYPE(*), DIMENSION(..) :: outbuf
     INTEGER(KIND=MPI_ADDRESS_KIND), INTENT(IN) :: insize
     INTEGER(KIND=MPI_ADDRESS_KIND), INTENT(INOUT) :: position
     INTEGER, INTENT(IN) :: outcount
     TYPE(MPI_Datatype), INTENT(IN) :: datatype
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARÁMETROS DE ENTRADA

  • datarep: Representación de datos (cadena).
  • inbuf: Inicio del buffer de entrada (elección).
  • insize: Tamaño del buffer de entrada, en bytes (entero).
  • outcount: Número de elementos a desempaquetar (entero).
  • datatype: Tipo de dato de cada elemento de salida (manejador).

PARÁMETRO DE ENTRADA/SALIDA

•
position: Posición actual en el buffer, en bytes (entero).

PARÁMETROS DE SALIDA

  • outbuf: Inicio del buffer de salida (elección).
  • ierror: Solo Fortran: Estado de error (entero).

DESCRIPCIÓN

MPI_Unpack_external desempaqueta datos del formato external32, una representación de datos universal definida por el Foro MPI. Este formato es útil para intercambiar datos entre implementaciones de MPI, o al escribir datos en un archivo.

El buffer de entrada es un área de almacenamiento contigua apuntada por inbuf que contiene insize bytes. El buffer de salida puede ser cualquier buffer de comunicación permitido en MPI_Recv, y se especifica mediante outbuf, outcount y datatype.

El valor de entrada de position es la primera posición en inbuf a la que se leerá para desempaquetar (medida en bytes, no en elementos, relativa al inicio del buffer). Cuando la función retorna, position se incrementa en el tamaño del mensaje empaquetado, de modo que apunte a la primera ubicación en inbuf después del mensaje que fue desempaquetado. De esta manera, puede ser utilizado como entrada para una llamada subsiguiente a MPI_Unpack_external.

NOTAS

Note la diferencia entre MPI_Recv y MPI_Unpack_external: En MPI_Recv, el argumento count especifica el número máximo de elementos que pueden ser recibidos. En MPI_Unpack_external, el argumento outcount especifica el número real de elementos que se desempaquetarán. Con una operación de recepción regular, el tamaño del mensaje entrante determina el número de componentes que se recibirán. Con MPI_Unpack_external, depende del usuario especificar cuántos componentes desempaquetar, ya que el usuario puede desear desempaquetar el mensaje recibido múltiples veces en varios buffers.

Para entender el comportamiento de empaquetar y desempaquetar, es conveniente pensar en la parte de datos de un mensaje como la secuencia obtenida concatenando los valores sucesivos enviados en ese mensaje. La operación de empaquetar almacena esta secuencia en el espacio del buffer, como si enviara el mensaje a ese buffer. La operación de desempaquetar recupera esta secuencia del espacio del buffer, como si recibiera un mensaje de ese buffer. (Es útil pensar en archivos internos de Fortran o sscanf en C para una función similar).

Se pueden empaquetar varios mensajes sucesivamente en una unidad de empaquetado. Esto se logra mediante varias llamadas sucesivas relacionadas a MPI_Pack_external, donde la primera llamada proporciona position=0, y cada llamada sucesiva ingresa el valor de position que fue generado por la llamada anterior, junto con los mismos valores para outbuf y outcount. Esta unidad de empaquetado ahora contiene la información equivalente que habría sido almacenada en un mensaje por una llamada de envío con un buffer de envío que es la "concatenación" de los buffers de envío individuales.

Una unidad de empaquetado se puede enviar usando el tipo MPI_BYTE. Cualquier función de comunicación punto a punto o colectiva puede ser usada para mover la secuencia de bytes que forma la unidad de empaquetado de un proceso a otro. Esta unidad de empaquetado puede ahora ser recibida usando cualquier operación de recepción, con cualquier tipo de dato: Las reglas de concordancia de tipos se relajan para los mensajes enviados con el tipo MPI_BYTE.

Una unidad de empaquetado se puede desempaquetar en varios mensajes sucesivos. Esto se logra mediante varias llamadas sucesivas relacionadas a MPI_Unpack_external, donde la primera llamada proporciona position=0, y cada llamada sucesiva ingresa el valor de position que fue generado por la llamada anterior, y los mismos valores para inbuf e insize.

La concatenación de dos unidades de empaquetado no es necesariamente una unidad de empaquetado; ni una subcadena de una unidad de empaquetado es necesariamente una unidad de empaquetado. Por lo tanto, no se pueden concatenar dos unidades de empaquetado y luego desempaquetar el resultado como una sola unidad de empaquetado; ni se puede desempaquetar una subcadena de una unidad de empaquetado como una unidad de empaquetado separada. Cada unidad de empaquetado que fue creada por una secuencia relacionada de llamadas de empaquetado debe ser desempaquetada como una unidad por una secuencia de llamadas de desempaquetado relacionadas.

ERRORES

Casi todas las rutinas MPI devuelven un valor de error; las rutinas C como resultado del retorno de la función y las rutinas Fortran en el último argumento.

Antes de que se devuelva el valor de error, se llama al controlador de errores MPI actual asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo). Si no hay ningún objeto de comunicación asociado con la llamada MPI, entonces la llamada se considera adjunta a MPI_COMM_SELF y llamará al controlador de errores MPI asociado. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se usa el modelo de Sesiones exclusivamente) el error activa el controlador de errores inicial. El controlador de errores inicial puede ser cambiado llamando a MPI_Comm_set_errhandler en MPI_COMM_SELF cuando se usa el modelo World, o el argumento de línea de comandos mpiexec mpi_initial_errhandler o clave de info a MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no se ha configurado ningún otro controlador de errores apropiado, entonces se llama al controlador de errores MPI_ERRORS_RETURN para las funciones de E/S MPI y al controlador de errores MPI_ERRORS_ABORT para todas las demás funciones MPI.

Open MPI incluye tres controladores de errores predefinidos que se pueden utilizar:

  • MPI_ERRORS_ARE_FATAL Provoca que el programa aborte todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT Un controlador de errores que puede ser invocado en un comunicador, ventana, archivo o sesión. Cuando se llama en un comunicador, actúa como si se hubiera llamado a MPI_Abort en ese comunicador. Si se llama en una ventana o archivo, actúa como si se hubiera llamado a MPI_Abort en un comunicador que contiene el grupo de procesos en la ventana o archivo correspondiente. Si se llama en una sesión, solo aborta el proceso local.
  • MPI_ERRORS_RETURN Devuelve un código de error a la aplicación.

Las aplicaciones MPI también pueden implementar sus propios controladores de errores llamando a:

  • MPI_Comm_create_errhandler luego MPI_Comm_set_errhandler
  • MPI_File_create_errhandler luego MPI_File_set_errhandler
  • MPI_Session_create_errhandler luego MPI_Session_set_errhandler o en MPI_Session_init

NAME

MPI_Unpack_external — Unpack data from an external marshalling buffer

SYNTAX

C:
int MPI_Unpack_external(MPI_Datatype datatype, void *inbuf,
    MPI_Aint *insize, MPI_Aint *buf, void *data);
Fortran:
INTEGER FUNCTION MPI_Unpack_external(datatype, inbuf, insize, buf, data, ierr)
    INTEGER datatype, insize, buf, ierr
    CHARACTER*(*) inbuf, data

INPUT PARAMETERS

C:
  • datatype: Datatype of the data to be unpacked (handle).
  • inbuf: Pointer to the buffer from which data is to be unpacked.
  • insize: Pointer to the size (in bytes) of the buffer.
  • buf: Pointer to the current position in the buffer.
Fortran:
  • datatype: Datatype of the data to be unpacked (handle).
  • inbuf: Pointer to the buffer from which data is to be unpacked.
  • insize: Size of the buffer in bytes.
  • buf: Current position in the buffer.

INPUT/OUTPUT PARAMETER

C:
  • data: Pointer to the location where the unpacked data will be placed.
Fortran:
  • data: Location where the unpacked data will be placed.

OUTPUT PARAMETERS

C:
  • insize: Pointer to the size (in bytes) of the buffer after the data has been unpacked.
  • buf: Pointer to the current position in the buffer after the data has been unpacked.

  • Return value: Command return code. Positive on success, negative on failure.

Fortran:

  • The data parameter contains the unpacked data.

  • Size of the buffer in bytes after the data has been unpacked.

  • Current position in the buffer after the data has been unpacked.

  • Fortran return value: Command return code. Positive on success, negative on failure.

  • ierr: Fortran return code. Positive on success, negative on failure.

DESCRIPTION

MPI_Unpack_external unpacks data from a buffer that was previously packed using MPI_Pack_external. The external representation of the data must be consistent with the data type specified by datatype.

The buf parameter is a pointer to the current position within the buffer. After the call, buf will be updated to point to the position immediately after the unpacked data.

The insize parameter indicates the current size of the buffer. After the call, insize will be updated to reflect the remaining size of the buffer.

The data parameter points to the memory location where the unpacked data will be stored. The size of this location must be sufficient to hold the data of the specified datatype.

NOTES

This function is part of the MPI-2 standard and is intended for use when interoperating with external data representations, such as those generated by other programming languages or systems.

The buf parameter is a pointer to an MPI_Aint type, which is an integer type capable of holding a pointer or a displacement. This is important for correctly handling buffer positions across different architectures.

ERRORS

MPI_Unpack_external can fail if:

  • The buffer is not large enough to contain the unpacked data.
  • The specified datatype is invalid.
  • The buf pointer is not within the bounds of the inbuf.

Standard MPI error handling mechanisms apply. If an error occurs, the MPI library will handle it according to the error handler set for the communicator.

Common error codes include:

  • MPI_ERR_BUFFER: Invalid buffer.
  • MPI_ERR_TYPE: Invalid datatype.
  • MPI_ERR_ARG: Invalid argument.

Note that MPI does not guarantee that an MPI program can continue past an error.

See the MPI man page for a full list of MPI error codes.

See the Error Handling section of the MPI-3.1 standard for more information.
