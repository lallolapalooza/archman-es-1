PARÁMETROS DE ENTRADA

  • sendbuf: Dirección del búfer de envío (elección, significativo solo en la raíz).
  • sendcount: Número de elementos enviados a cada proceso (entero, significativo solo en la raíz).
  • sendtype: Tipo de datos de los elementos del búfer de envío (manejador, significativo solo en la raíz).
  • recvcount: Número de elementos en el búfer de recepción (entero).
  • recvtype: Tipo de datos de los elementos del búfer de recepción (manejador).
  • root: Rango del proceso de envío (entero).
  • comm: Comunicador (manejador).
  • info: Información (manejador, persistente).

PARÁMETROS DE SALIDA

  • recvbuf: Dirección del búfer de recepción (elección).
  • request: Solicitud (manejador, solo no bloqueante).
  • ierror: Solo Fortran: Estado de error (entero).

DESCRIPCIÓN

MPI_Scatter es la operación inversa a MPI_Gather.

El resultado es como si la raíz ejecutara n operaciones de envío,

MPI_Send(sendbuf + i * sendcount * extent(sendtype), sendcount,
         sendtype, i, ...);

y cada proceso ejecutara una recepción,

MPI_Recv(recvbuf, recvcount, recvtype, i, ...).;

Una descripción alternativa es que la raíz envía un mensaje con MPI_Send(sendbuf, sendcount * n, sendtype, ...). Este mensaje se divide en n segmentos iguales, el i-ésimo segmento se envía al i-ésimo proceso del grupo, y cada proceso recibe este mensaje como se describe arriba.

El búfer de envío se ignora para todos los procesos que no son la raíz.

La firma de tipo asociada con sendcount, sendtype en la raíz debe ser igual a la firma de tipo asociada con recvcount, recvtype en todos los procesos (sin embargo, los mapas de tipo pueden ser diferentes). Esto implica que la cantidad de datos enviados debe ser igual a la cantidad de datos recibidos, par a par entre cada proceso y la raíz. Todavía se permiten mapas de tipo distintos entre el remitente y el receptor.

Todos los argumentos de la función son significativos en el proceso root, mientras que en otros procesos, solo los argumentos recvbuf, recvcount, recvtype, root, comm son significativos. Los argumentos root y comm deben tener valores idénticos en todos los procesos.

La especificación de recuentos y tipos no debe causar que ninguna ubicación en la raíz se lea más de una vez.

Fundamento: Aunque no es necesario, la última restricción se impone para lograr la simetría con MPI_Gather, donde la restricción correspondiente (una restricción de escritura múltiple) es necesaria.

Ejemplo: El reverso del Ejemplo 1 en la página del manual de MPI_Gather. Scatter conjuntos de 100 enteros de la raíz a cada proceso en el grupo.

MPI_Comm comm;
int gsize,*sendbuf;
int root, rbuf[100];
...
MPI_Comm_size(comm, &gsize);
sendbuf = (int *)malloc(gsize*100*sizeof(int));
...
MPI_Scatter(sendbuf, 100, MPI_INT, rbuf, 100,
            MPI_INT, root, comm);

USO DE LA OPCIÓN IN-PLACE

Cuando el comunicador es un intracommunicator, puede realizar una operación de scatter in-place (el búfer de salida se utiliza como búfer de entrada). Use la variable MPI_IN_PLACE como valor del recvbuf del proceso raíz. En este caso, se ignoran recvcount y recvtype, y el proceso raíz no envía datos a sí mismo.

Tenga en cuenta que MPI_IN_PLACE es un tipo especial de valor; tiene las mismas restricciones de uso que MPI_BOTTOM.

Dado que la opción in-place convierte el búfer de recepción en un búfer de envío y recepción, una vinculación de Fortran que incluya INTENT debe marcarlos como INOUT, no como OUT.

CUANDO EL COMUNICADOR ES UN INTER-COMUNICADOR

Cuando el comunicador es un inter-comunicador, el proceso raíz en el primer grupo envía datos a todos los procesos en el segundo grupo. El primer grupo define el proceso raíz. Ese proceso utiliza MPI_ROOT como valor de su argumento root. Los procesos restantes utilizan MPI_PROC_NULL como valor de su argumento root. Todos los procesos del segundo grupo utilizan el rango de ese proceso raíz en el primer grupo como el valor de su argumento root. El argumento del búfer de recepción del proceso raíz en el primer grupo debe ser coherente con el argumento del búfer de recepción de los procesos en el segundo grupo.

ERRORES

Casi todas las rutinas MPI devuelven un valor de error; las rutinas C como resultado de retorno de la función y las rutinas de Fortran en el último argumento.

Antes de que se devuelva el valor de error, se llama al controlador de errores MPI actual asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo). Si no hay ningún objeto de comunicación asociado con la llamada MPI, entonces la llamada se considera adjunta a MPI_COMM_SELF y llamará al controlador de errores MPI asociado. NAME

MPI_Scatter — Scatter a buffer.

SYNTAX

        C:
            #include <mpi.h>
            int MPI_Scatter(const void *sendbuf, int sendcount,
                MPI_Datatype sendtype, void *recvbuf, int recvcount,
                MPI_Datatype recvtype, int root, MPI_Comm comm);

        Fortran:
            INCLUDE ’mpif.h’
            SUBROUTINE MPI_SCATTER(SENDBUF, SENDCOUNT, SENDTYPE, RECVBUF,
                RECVCOUNT, RECVTYPE, ROOT, COMM, IERROR)
                INTEGER SENDCOUNT, RECVCOUNT, ROOT, IERROR
                INTEGER SENDTYPE, RECVTYPE, COMM
                CHARACTER*1 SENDBUF(*), RECVBUF(*)
                INTEGER, DIMENSION(*) :: SENDBUF, RECVBUF

        C++:
            #include <mpi.h>
            void MPI::Comm::Scatter(const void* sendbuf, int sendcount,
                MPI::Datatype sendtype, void* recvbuf, int recvcount,
                MPI::Datatype recvtype, int root) const;

INPUT PARAMETERS

comm
Communicator with all participating processes.
recvcount
Number of elements in receive buffer (integer).
recvtype
Datatype of elements in receive buffer.
sendcount
Number of elements in send buffer (integer).
sendtype
Datatype of elements in send buffer.
root
Rank of the sending process in the communicator (integer).

OUTPUT PARAMETERS

recvbuf
Address of receive buffer (choice).
IERROR
(Output) Fortran only: Fortran return code. This argument is the last in the argument list. If return code is MPI_SUCCESS, no error occurred. On input, it is undefined.

DESCRIPTION

The MPI routine MPI_Scatter is used to distribute data from a single process to all processes in a communicator. The root process breaks its contiguous buffer sendbuf into size / comm_size messages, where size is the total size of the buffer in bytes, and comm_size is the number of processes in the communicator. Each process receives one message.

Specifically, the root process receives sendcount elements of type sendtype from its own sendbuf. All other processes receive recvcount elements of type recvtype from the root process’s sendbuf.

The sendtype and recvtype do not need to be the same, but the amount of data sent must equal the amount of data received.

USE OF IN-PLACE OPTION

When the communicator is an MPI_COMM_WORLD or a similar toporogical communicator, you can specify the in-place option for the recvbuf argument. If the communicator is not derived from MPI_COMM_WORLD, the in-place option is not allowed.

The in-place option signifies that the send buffer and receive buffer are the same buffer.

When the in-place option is used, the send buffer address must be the same as the receive buffer address. The sendtype must match the recvtype, and the sendcount must be equal to the recvcount.

WHEN COMMUNICATOR IS AN INTER-COMMUNICATOR

The behavior of MPI_Scatter depends on the interpretation of the root argument.

If root is in the local group, then sendbuf and sendcount refer to the send buffer and its size. The recvbuf and recvcount are specified by the processes in the remote group.

If root is in the remote group, then recvbuf and recvcount refer to the receive buffer and its size. The sendbuf and sendcount are specified by the processes in the local group.

ERRORS

When an MPI function is called, it is an error if the `mpi_errhandler_function` parameter is set to `MPI_ERRORS_INTERNAL` and the underlying MPI implementation detects an internal error. The MPI standard does not guarantee that an MPI program can continue past an error.

When an MPI function is called with an invalid parameter or if an error occurs during the function execution, the error handler attached to the communicator is called. The error handler can be set using MPI_Comm_set_errhandler. The default error handler is MPI_ERRORS_ABORT.

If an error occurs during an MPI I/O function call, and the error handler is set to MPI_ERRORS_RETURN, then the return code is returned to the application. Otherwise, the error handler is invoked.

If an error occurs outside of an MPI initialization or finalization context (i.e. before MPI_Init/MPI_Init_thread, after MPI_Finalize, or when using the Sessions Model exclusively) the error raises the initial error handler. The initial error handler can be changed by calling MPI_Comm_set_errhandler on MPI_COMM_SELF when using the World model, or the mpi_initial_errhandler CLI argument to mpiexec or info key to MPI_Comm_spawn/MPI_Comm_spawn_multiple. If no other appropriate error handler has been set, then the MPI_ERRORS_RETURN error handler is called for MPI I/O functions and the MPI_ERRORS_ABORT error handler is called for all other MPI functions.

Open MPI includes three predefined error handlers that can be used:

  • MPI_ERRORS_ARE_FATAL Causes the program to abort all connected MPI processes.
  • MPI_ERRORS_ABORT An error handler that can be invoked on a communicator, window, file, or session. When called on a communicator, it acts as if MPI_Abort was called on that communicator. If called on a window or file, acts as if MPI_Abort was called on a communicator containing the group of processes in the corresponding window or file. If called on a session, aborts only the local process.
  • MPI_ERRORS_RETURN Returns an error code to the application.

MPI applications can also implement their own error handlers by calling:

  • MPI_Comm_create_errhandler then MPI_Comm_set_errhandler
  • MPI_File_create_errhandler then MPI_File_set_errhandler
  • MPI_Session_create_errhandler then MPI_Session_set_errhandler or at MPI_Session_init
  • MPI_Win_create_errhandler then MPI_Win_set_errhandler

Note that MPI does not guarantee that an MPI program can continue past an error.

See the MPI man page for a full list of MPI error codes.

See the Error Handling section of the MPI-3.1 standard for more information.
