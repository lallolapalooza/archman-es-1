MPI_Buffer_detach(3)

Paquete: openmpi

Licencias: BSD-3-Clause AND LicenseRef-MPICH

MPI_BUFFER_DETACH(3) Open MPI MPI_BUFFER_DETACH(3)

MPI_Buffer_detach — Elimina un búfer existente (para uso en MPI_Bsend, etc.)

SINTAXIS

Sintaxis C

#include <mpi.h>
int MPI_Buffer_detach(void *buf, int *size)

Sintaxis Fortran

USE MPI
! o la forma antigua: INCLUDE 'mpif.h'
MPI_BUFFER_DETACH(BUF, SIZE, IERROR)
    <type>  BUF(*)
    INTEGER SIZE, IERROR

Sintaxis Fortran 2008

USE mpi_f08
MPI_Buffer_detach(buffer_addr, size, ierror)
    USE, INTRINSIC :: ISO_C_BINDING, ONLY
    TYPE(C_PTR), INTENT(OUT) :: buffer_addr
    INTEGER, INTENT(OUT) :: size
    INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARÁMETROS DE SALIDA

  • buf : Dirección del búfer inicial (elección).
  • size : Tamaño del búfer, en bytes (entero).
  • ierror : Solo Fortran: Estado de error (entero).

DESCRIPCIÓN

Desconecta el búfer actualmente asociado con MPI. La llamada devuelve la dirección y el tamaño del búfer desconectado. Esta operación se bloqueará hasta que todos los mensajes en el búfer se hayan transmitido. Al regresar de esta función, el usuario puede reutilizar o liberar el espacio ocupado por el búfer.

Ejemplo: Llamadas para adjuntar y desconectar búferes.

#define BUFFSIZE 10000
int size char *buff;
MPI_Buffer_attach( malloc(BUFFSIZE), BUFFSIZE);
// un búfer de 10000 bytes puede ser usado ahora por MPI_Bsend
MPI_Buffer_detach( &buff, &size); // Tamaño del búfer reducido a cero
MPI_Buffer_attach( buff, size); // Búfer de 10000 bytes disponible de nuevo

NOTAS

La razón por la que MPI_Buffer_detach devuelve la dirección y el tamaño del búfer que se está desconectando es para permitir que bibliotecas anidadas reemplacen y restauren el búfer. Por ejemplo, considere:

int size, mysize, idummy;
void *ptr, *myptr, *dummy;
MPI_Buffer_detach( &ptr, &size );
MPI_Buffer_attach( myptr, mysize );
/* ... código de la biblioteca ... */
MPI_Buffer_detach( &dummy, &idummy );
MPI_Buffer_attach( ptr, size );

Esto es muy similar a la acción de la rutina de señales de UNIX y tiene las mismas fortalezas (es simple) y debilidades (solo funciona para usos anidados).

Para Fortran: El enlace de Fortran para esta rutina es diferente. Debido a que Fortran no tiene punteros, es imposible proporcionar una forma de usar la salida de esta rutina para intercambiar búferes. En este caso, solo se establece el campo de tamaño.

Para C: Aunque las funciones C MPI_Buffer_attach y MPI_Buffer_detach tienen un primer argumento de tipo void*, estos argumentos se utilizan de manera diferente: se pasa un puntero al búfer a MPI_Buffer_attach; se pasa la dirección del puntero a MPI_Buffer_detach, de modo que esta llamada pueda devolver el valor del puntero.

Incluso aunque las funciones C MPI_Buffer_attach y MPI_Buffer_detach tengan un primer argumento de tipo void*, estos argumentos se utilizan de manera diferente: se pasa un puntero al búfer a MPI_Buffer_attach; se pasa la dirección del puntero a MPI_Buffer_detach, de modo que esta llamada pueda devolver el valor del puntero.

ERRORES

Casi todas las rutinas MPI devuelven un valor de error; las rutinas C como resultado de retorno de la función y las rutinas Fortran en el último argumento.

Antes de que se devuelva el valor de error, se llama al manejador de errores MPI actual asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo). Si no hay un objeto de comunicación asociado con la llamada MPI, entonces la llamada se considera adjunta a MPI_COMM_SELF y llamará al manejador de errores MPI asociado. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se utiliza exclusivamente el Modelo de Sesiones) el error eleva el manejador de errores inicial. El manejador de errores inicial se puede cambiar llamando a MPI_Comm_set_errhandler en MPI_COMM_SELF cuando se utiliza el modelo World, o el argumento de línea de comandos mpi_initial_errhandler de mpiexec o la clave de información para MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no se ha establecido ningún otro manejador de errores apropiado, entonces se llama al manejador de errores MPI_ERRORS_RETURN para las funciones de E/S de MPI y al manejador de errores MPI_ERRORS_ABORT para todas las demás funciones de MPI.

Open MPI incluye tres manejadores de errores predefinidos que se pueden utilizar:

  • MPI_ERRORS_ARE_FATAL Hace que el programa abandone todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT Un manejador de errores que puede ser invocado en un comunicador, ventana, archivo o sesión. Cuando se llama en un comunicador, actúa como si se hubiera llamado a MPI_Abort en ese comunicador. Si se llama en una ventana o archivo, actúa como si se hubiera llamado a MPI_Abort en un comunicador que contiene el grupo de procesos de la ventana o archivo correspondiente. Si se llama en una sesión, solo aborta el proceso local.
  • MPI_ERRORS_RETURN Devuelve un código de error a la aplicación.

Las aplicaciones MPI también pueden implementar sus propios manejadores de errores llamando a:

  • MPI_Comm_create_errhandler y luego MPI_Comm_set_errhandler
  • MPI_File_create_errhandler y luego MPI_File_set_errhandler
  • MPI_Session_create_errhandler y luego MPI_Session_set_errhandler o en MPI_Session_init
  • MPI_Win_create_errhandler y luego MPI_Win_set_errhandler

Tenga en cuenta que MPI no garantiza que un programa MPI pueda continuar después de un error.

Consulte la página del manual de MPI para obtener una lista completa de los códigos de error de MPI.

Consulte la sección Manejo de Errores del estándar MPI-3.1 para obtener más información.

Instalación

La instalación de Arch Linux es un proceso directo pero requiere cierto conocimiento. El método recomendado es usar el script de instalación oficial, que se puede encontrar en la imagen ISO de instalación.

El script te guiará a través de los pasos necesarios, como particionar el disco, montar los sistemas de archivos, instalar el sistema base y configurar los paquetes esenciales.

Pasos detallados:

  1. Descargar la imagen ISO más reciente de Arch Linux.
  2. Crear un medio de arranque (USB o DVD).
  3. Arrancar desde el medio de arranque.
  4. Seguir las instrucciones del script de instalación.
  5. Reiniciar el sistema en tu nueva instalación de Arch Linux.

Una vez instalado el sistema base, se recomienda instalar un entorno de escritorio y las aplicaciones que necesites. Puedes encontrar una gran variedad de paquetes en los repositorios oficiales de Arch Linux.

Después de la instalación, deberás configurar tu sistema para que se adapte a tus necesidades. Esto incluye la configuración de la red, la zona horaria, el teclado y la creación de usuarios.

Arch Linux utiliza el sistema de configuración `systemd` para gestionar servicios. Puedes habilitar o deshabilitar servicios utilizando los comandos `systemctl enable` y `systemctl disable`.
