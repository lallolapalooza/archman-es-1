PARÁMETROS DE ENTRADA

  • sendbuf: Búfer de envío (opcional).
  • count: Número de elementos en el búfer de entrada (entero).
  • datatype: Tipo de datos de los elementos del búfer de entrada (manejador).
  • op: Operación (manejador).
  • comm: Comunicador (manejador).
  • info: Información (manejador, solo persistente)

PARÁMETROS DE SALIDA

  • recvbuf: Búfer de recepción (opcional).
  • request: Solicitud (manejador, solo no bloqueante).
  • ierror: Solo Fortran: Estado de error (entero).

DESCRIPCIÓN

MPI_Scan se utiliza para realizar una reducción de prefijo inclusiva en datos distribuidos entre los procesos que llaman. La operación devuelve, en el recvbuf del proceso con rango i, la reducción (calculada según la función op) de los valores de los sendbuf de los procesos con rangos 0, …, i (inclusivo). El tipo de operaciones soportadas, sus semánticas y las restricciones en los búferes de envío y recepción son como para MPI_Reduce.

EJEMPLO

Este ejemplo utiliza una operación definida por el usuario para producir un escaneo segmentado. Un escaneo segmentado toma, como entrada, un conjunto de valores y un conjunto de booleanos, donde los booleanos delimitan los diversos segmentos del escaneo. Por ejemplo,

valores     v1      v2      v3      v4      v5      v6      v7      v8
booleanos   0       0       1       1       1       0       0       1
resultado   v1    v1+v2     v3    v3+v4  v3+v4+v5   v6    v6+v7     v8

El resultado para el rango j es, por lo tanto, la suma v(i) + … + v(j), donde i es el rango más bajo tal que para todos los rangos n, i <= n <= j, booleano(n) = booleano(j). El operador que produce este efecto es

      [ u ]     [ v ]     [ w ]
      [   ]  o  [   ]  =  [   ]
      [ i ]     [ j ]     [ j ]
donde
    ( u + v si i = j w = ( ( v si i != j

Tenga en cuenta que este es un operador no conmutativo. El código C que lo implementa se proporciona a continuación.

typedef struct {
        double val;
        int log;
} SegScanPair;
/*
 * la función definida por el usuario
 */
void segScan(SegScanPair *in, SegScanPair *inout, int *len,
        MPI_Datatype *dptr)
{
        int i;
        SegScanPair c;
        for (i = 0; i < *len; ++i) {
                if (in->log == inout->log)
                        c.val = in->val + inout->val;
                else
                        c.val = inout->val;
                c.log = inout->log;
                *inout = c;
                in++;
                inout++;
        }
}

Tenga en cuenta que el argumento inout a la función definida por el usuario corresponde al operando derecho del operador. Al usar este operador, debemos tener cuidado de especificar que no es conmutativo, como en el siguiente caso:

int                     i, base;
SeqScanPair     a, answer;
MPI_Op          myOp;
MPI_Datatype    type[2] = {MPI_DOUBLE, MPI_INT};
MPI_Aint                disp[2];
int                     blocklen[2] = {1, 1};
MPI_Datatype    sspair;
/*
 * explicar a MPI cómo se define el tipo SegScanPair
 */
MPI_Get_address(a, disp);
MPI_Get_address(a.log, disp + 1);
base = disp[0];
for (i = 0; i < 2; ++i)
        disp[i] -= base;
MPI_Type_struct(2, blocklen, disp, type, &sspair);
MPI_Type_commit(&sspair);
/*
 * crear el op-usuario de escaneo segmentado
 * no conmutativo - establecer commute (arg 2) a 0
 */
MPI_Op_create((MPI_User_function *)segScan, 0, &myOp);
...
MPI_Scan(a, answer, 1, sspair, myOp, comm);

USO DE LA OPCIÓN IN-PLACE

Cuando el comunicador es un intracommunicador, puede realizar una operación de escaneo en su lugar (el búfer de salida se usa como búfer de entrada). Use la variable MPI_IN_PLACE como valor del argumento sendbuf. Los datos de entrada se toman del búfer de recepción y se reemplazan por los datos de salida.

NOTAS SOBRE OPERACIONES COLECTIVAS

Las funciones de reducción de tipo MPI_Op no devuelven un valor de error. En consecuencia, si las funciones detectan un error, todo lo que pueden hacer es llamar a MPI_Abort o omitir silenciosamente el problema. Por lo tanto, si el manejador de errores se cambia de MPI_ERRORS_ARE_FATAL a algo más (por ejemplo, MPI_ERRORS_RETURN), entonces es posible que no se indique ningún error.

La razón de esto son los problemas de rendimiento para garantizar que todas las rutinas colectivas devuelvan el mismo valor de error.

ERRORES

Casi todas las rutinas MPI devuelven un valor de error; las rutinas C como resultado de retorno de la función y las rutinas Fortran en el último argumento.

Antes de que se devuelva el valor de error, se llama al manejador de errores MPI actual asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo). Si no hay ningún objeto de comunicación asociado con la llamada MPI, entonces la llamada se considera adjunta a MPI_COMM_SELF y llamará al manejador de errores MPI asociado. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se usa exclusivamente el Modelo de Sesiones) el error activa el manejador de errores inicial. El manejador de errores inicial se puede cambiar llamando a MPI_Comm_set_errhandler en MPI_COMM_SELF cuando se usa el modelo World, o el argumento CLI mpi_initial_errhandler a mpiexec o clave info a

ERRORS

All MPI functions require that the communicator is valid. All MPI functions require that the communicator is not a null communicator.

If the communicator is invalid or null, then the behavior is undefined.

If the communicator is not consistent among all processes in the group, then the behavior is undefined.

If no other appropriate error handler has been set, then the MPI_ERRORS_RETURN error handler is called for MPI I/O functions and the MPI_ERRORS_ABORT error handler is called for all other MPI functions.

Open MPI includes three predefined error handlers that can be used:

  • MPI_ERRORS_ARE_FATAL Causes the program to abort all connected MPI processes.
  • MPI_ERRORS_ABORT An error handler that can be invoked on a communicator, window, file, or session. When called on a communicator, it acts as if MPI_Abort was called on that communicator. If called on a window or file, acts as if MPI_Abort was called on a communicator containing the group of processes in the corresponding window or file. If called on a session, aborts only the local process.
  • MPI_ERRORS_RETURN Returns an error code to the application.

MPI applications can also implement their own error handlers by calling:

  • MPI_Comm_create_errhandler then MPI_Comm_set_errhandler
  • MPI_File_create_errhandler then MPI_File_set_errhandler
  • MPI_Session_create_errhandler then MPI_Session_set_errhandler or at MPI_Session_init
  • MPI_Win_create_errhandler then MPI_Win_set_errhandler

Note that MPI does not guarantee that an MPI program can continue past an error.

See the MPI man page for a full list of MPI error codes.

See the Error Handling section of the MPI-3.1 standard for more information.
