MPI_Gather, MPI_Igather, MPI_Gather_init - Recopila valores de un grupo de procesos.

PARÁMETROS DE ENTRADA

  • sendbuf : Dirección de inicio del búfer de envío (elección).
  • sendcount : Número de elementos en el búfer de envío (entero).
  • sendtype : Tipo de datos de los elementos del búfer de envío (manejador).
  • recvcount : Número de elementos para cualquier recepción individual (entero, solo significativo en la raíz).
  • recvtype : Tipo de datos de los elementos del búfer de recepción (manejador, solo significativo en la raíz).
  • root : Rango del proceso de recepción (entero).
  • comm : Comunicador (manejador).
  • info : Información (manejador, solo persistente).

PARÁMETROS DE SALIDA

•
recvbuf
Dirección del búfer de recepción (elección, solo significativo en la raíz).
  • request : Solicitud (manejador, solo no bloqueante).
  • ierror : Solo Fortran: Estado de error (entero).

DESCRIPCIÓN

Cada proceso (incluido el proceso raíz) envía el contenido de su búfer de envío al proceso raíz. El proceso raíz recibe los mensajes y los almacena en orden de rango. El resultado es como si cada uno de los n procesos del grupo (incluido el proceso raíz) hubiera ejecutado una llamada a

MPI_Send(sendbuf, sendcount, sendtype, root, ...)

y la raíz hubiera ejecutado n llamadas a

MPI_Recv(recfbuf + i * recvcount * extent(recvtype), recvcount,
         recvtype, i, ...)

donde extent(recvtype) es la extensión del tipo obtenida de una llamada a MPI_Type_extent.

Una descripción alternativa es que los n mensajes enviados por los procesos del grupo se concatenan en orden de rango, y el mensaje resultante es recibido por la raíz como si fuera mediante una llamada a MPI_Recv(recvbuf, recvcount * n, recvtype, ... ).

El búfer de recepción se ignora para todos los procesos que no son raíz.

Se permiten tipos de datos generales y derivados tanto para sendtype como para recvtype. La firma de tipo de sendcount, sendtype en el proceso i debe ser igual a la firma de tipo de recvcount, recvtype en la raíz. Esto implica que la cantidad de datos enviados debe ser igual a la cantidad de datos recibidos, por pares entre cada proceso y la raíz. Todavía se permiten mapas de tipos distintos entre el remitente y el receptor.

Todos los argumentos de la función son significativos en el proceso raíz, mientras que en otros procesos, solo los argumentos sendbuf, sendcount, sendtype, root, comm son significativos. Los argumentos root y comm deben tener valores idénticos en todos los procesos.

La especificación de recuentos y tipos no debe hacer que ninguna ubicación en la raíz se escriba más de una vez. Tal llamada es errónea. Tenga en cuenta que el argumento recvcount en la raíz indica el número de elementos que recibe de cada proceso, no el número total de elementos que recibe.

Ejemplo 1: Recopilar 100 enteros de cada proceso del grupo a la raíz.

MPI_Comm comm;
int gsize, sendarray[100];
int root, *rbuf;
...
MPI_Comm_size( comm, &gsize);
rbuf = (int*)malloc(gsize* 100*sizeof(int));
MPI_Gather( sendarray, 100, MPI_INT, rbuf, 100, MPI_INT, root, comm);

Ejemplo 2: Ejemplo anterior modificado - solo la raíz asigna memoria para el búfer de recepción.

MPI_Comm comm;
int gsize, sendarray[100];
int root, myrank, *rbuf;
...
MPI_Comm_rank( comm, myrank);
if ( myrank == root) {
  MPI_Comm_size( comm, &gsize);
  rbuf = (int *)malloc(gsize * 100*sizeof(int));
}
MPI_Gather( sendarray, 100, MPI_INT, rbuf, 100, MPI_INT, root, comm);

Ejemplo 3: Hacer lo mismo que el ejemplo anterior, pero usar un tipo de datos derivado. Tenga en cuenta que el tipo no puede ser todo el conjunto de gsize * 100 enteros, ya que la coincidencia de tipos se define por pares entre la raíz y cada proceso en la recopilación.

MPI_Comm comm;
int gsize, sendarray[100];
int root, *rbuf;
MPI_Datatype rtype;
...
MPI_Comm_size( comm, &gsize);
MPI_Type_contiguous( 100, MPI_INT, &rtype);
MPI_Type_commit( &rtype );
rbuf = (int*)malloc(gsize* 100*sizeof(int));
MPI_Gather( sendarray, 100, MPI_INT, rbuf, 1, rtype, root, comm);

USO DE LA OPCIÓN IN-PLACE

Cuando el comunicador es un intracommunicator, puede realizar una operación de recopilación in-place (el búfer de salida se utiliza como búfer de entrada). Utilice la variable MPI_IN_PLACE como valor del sendbuf del proceso raíz. En este caso, sendcount y sendtype se ignoran, y se asume que la contribución del proceso raíz al vector recopilado ya está en la ubicación correcta en el búfer de recepción. Tenga en cuenta que MPI_IN_PLACE es un tipo especial de valor; tiene las mismas restricciones de uso que MPI_BOTTOM. Dado que la opción in-place convierte el búfer de recepción en un búfer de envío y recepción, una vinculación de Fortran que incluye INTENT debe marcarlas como INOUT, no como OUT.

CUANDO EL COMUNICADOR ES UN INTER-COMUNICADOR

Cuando el comunicador es un intercomunicador, uno de los grupos (el grupo local del lado A, por ejemplo) debe ser el grupo raíz. Los procesos de este grupo utilizan MPI_IN_PLACE para el búfer de envío y especifican el búfer de recepción donde se recopilarán los datos del otro grupo. Los procesos del otro grupo (el grupo no raíz) utilizan un búfer de envío normal y especifican un búfer de recepción nulo (o cualquier valor que no sea MPI_IN_PLACE).

ERRORES

El evento de error de MPI se puede generar durante esta operación. Para esta operación, el evento de error de MPI puede generarse si el comunicador no es válido o si se produce un error de red.

MPI_GATHER_INIT

Initializa una operación de recopilación de datos no bloqueante

SYNOPSIS

Nombres de funciones:
MPI_Gather_init

   int MPI_Gather_init(const void *sendbuf, int sendcount, MPI_Datatype sendtype,
                       void *recvbuf, int recvcount, MPI_Datatype recvtype,
                       int root, MPI_Comm comm, MPI_Request *request);

INPUT PARAMETERS

• sendbuf
Buffer de envío (declaración en el lado del remitente).
• sendcount
Número de elementos en el buffer de envío (declaración en el lado del remitente).
• sendtype
Tipo de datos de los elementos del buffer de envío (declaración en el lado del remitente).
• recvbuf
Buffer de recepción (declaración en el lado de la raíz).
• recvcount
Número de elementos del tipo de datos de recepción para ser recibidos de cada remitente (declaración en el lado de la raíz).
• recvtype
Tipo de datos de los elementos del buffer de recepción (declaración en el lado de la raíz).
• root
Rango del proceso raíz en el comunicador (declaración en todos los procesos).
• comm
Comunicador del grupo (declaración en todos los procesos).
• request
Handle de solicitud (declaración en todos los procesos).

OUTPUT PARAMETERS

• request
Handle de solicitud (declaración en todos los procesos).

DESCRIPTION

MPI_Gather_init es la versión inicial de MPI_Gather. Esto permite que el usuario cree y comience múltiples operaciones de envío y recepción de forma asíncrona.

La colección de los datos de todos los procesos en el grupo del comunicador comm se realiza en el buffer del proceso raíz.

Cada proceso del grupo envía el buffer de envío sendbuf, que contiene sendcount elementos del tipo sendtype, al proceso raíz. El proceso raíz recibe sendcount elementos del tipo sendtype de cada uno de los N procesos del grupo (incluido él mismo). Los datos recibidos se almacenan en el buffer de recepción del proceso raíz recvbuf. El buffer de recepción debe ser lo suficientemente grande para contener N * sendcount elementos del tipo sendtype. El i-ésimo bloque de datos recibido del proceso i se escribe en la posición que corresponde a recvbuf + i * sendcount * sizeof(sendtype).

Si sendtype es un tipo de datos de tamaño variable, entonces debe ser el mismo tipo de datos en todos los procesos.

En el proceso raíz, sendbuf y sendcount son ignorados.

Los argumentos recvbuf, recvcount y recvtype se especifican en el proceso raíz. El número de elementos de tipo recvtype que recibe cada proceso es recvcount. El tamaño total de los datos recibidos por el proceso raíz es recvcount. El buffer de recepción debe ser lo suficientemente grande para contener recvcount elementos del tipo recvtype.

Si se utiliza un tipo de datos de tamaño variable para recvtype, entonces debe ser el mismo tipo de datos en todos los procesos. El número de elementos recibidos por el proceso raíz es recvcount.

Los parámetros recvbuf, recvcount y recvtype son especificados por todos los procesos, pero sólo son utilizados por el proceso raíz. El valor de recvcount debe ser igual al valor de sendcount. El valor de recvtype debe ser igual al valor de sendtype.

La operación de colección se inicia mediante MPI_Gather_init. La operación real de envío y recepción se puede iniciar mediante una llamada a MPI_Start o MPI_Startall en el handle de solicitud devuelto. La operación de colección se completa mediante una llamada a MPI_Wait o MPI_Waitalldata.

Una llamada a MPI_Gather_init se considera correcta si los parámetros de envío y recepción se especifican correctamente en todos los procesos, y si los parámetros sendtype y recvtype son consistentes entre los procesos, es decir, si el tipo de envío en el remitente es el mismo que el tipo de recepción en el receptor. Además, los buffers de envío y recepción deben ser consistentes. Es decir, para el proceso raíz, el buffer de recepción debe ser capaz de contener todos los datos enviados por los procesos del grupo, y para los procesos remitentes, el buffer de envío debe tener el tamaño especificado por sendcount y sendtype.

USE OF IN-PLACE OPTION

Cuando se especifica el parámetro in-place, sendbuf debe ser igual a recvbuf. El número de elementos especificados por sendcount y sendtype debe ser igual al número de elementos especificados por recvcount y recvtype. El proceso raíz enviará los datos de su propio buffer de envío y los datos recibidos se almacenarán en el mismo buffer. El buffer debe ser lo suficientemente grande para contener el resultado.

WHEN COMMUNICATOR IS AN INTER-COMMUNICATOR

Cuando el comunicador es un inter-comunicador, el proceso raíz en el primer grupo recopila datos de todos los procesos en el segundo grupo. El primer grupo define el proceso raíz. Ese proceso utiliza MPI_ROOT como el valor de su argumento raíz. Los procesos restantes utilizan MPI_PROC_NULL como el valor de su argumento raíz. Todos los procesos del segundo grupo utilizan el rango de ese proceso raíz en el primer grupo como el valor de su argumento raíz. El argumento buffer de envío de los procesos en el primer grupo debe ser consistente con el argumento buffer de recepción del proceso raíz en el segundo grupo.

ERRORS

Casi todas las rutinas de MPI devuelven un valor de error; las rutinas de C como resultado de la función y las rutinas de Fortran en el último argumento.

Antes de que se devuelva el valor de error, se llama al manejador de errores de MPI actual asociado con el objeto de comunicación (por ejemplo, comunicador, ventana, archivo). Si no hay ningún objeto de comunicación asociado con la llamada MPI, entonces la llamada se considera adjunta a MPI_COMM_SELF y llamará al manejador de errores de MPI asociado. Cuando MPI_COMM_SELF no está inicializado (es decir, antes de MPI_Init/MPI_Init_thread, después de MPI_Finalize, o cuando se utiliza exclusivamente el Modelo de Sesiones) el error eleva el manejador de errores inicial. El manejador de errores inicial se puede cambiar llamando a MPI_Comm_set_errhandler en MPI_COMM_SELF cuando se utiliza el modelo World, o el argumento CLI mpi_initial_errhandler a mpiexec o la clave info a MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si no se ha establecido ningún otro manejador de errores apropiado, entonces se llama al manejador de errores MPI_ERRORS_RETURN para las funciones de E/S de MPI y al manejador de errores MPI_ERRORS_ABORT para todas las demás funciones de MPI.

Open MPI incluye tres manejadores de errores predefinidos que se pueden utilizar:

  • MPI_ERRORS_ARE_FATAL Provoca que el programa aborte todos los procesos MPI conectados.
  • MPI_ERRORS_ABORT Un manejador de errores que se puede invocar en un comunicador, ventana, archivo o sesión. Cuando se llama en un comunicador, actúa como si se hubiera llamado a MPI_Abort en ese comunicador. Si se llama en una ventana o archivo, actúa como si se hubiera llamado a MPI_Abort en un comunicador que contiene el grupo de procesos en la ventana o archivo correspondiente. Si se llama en una sesión, aborta sólo el proceso local.
  • MPI_ERRORS_RETURN Devuelve un código de error a la aplicación.

Las aplicaciones MPI también pueden implementar sus propios manejadores de errores llamando a:

  • MPI_Comm_create_errhandler y luego MPI_Comm_set_errhandler
  • MPI_File_create_errhandler y luego MPI_File_set_errhandler
  • MPI_Session_create_errhandler y luego MPI_Session_set_errhandler o en MPI_Session_init
  • MPI_Win_create_errhandler y luego MPI_Win_set_errhandler

Tenga en cuenta que MPI no garantiza que un programa MPI pueda continuar después de un error.

Consulte la página del manual de MPI para obtener una lista completa de los códigos de error de MPI.

Consulte la sección de Manejo de Errores del estándar MPI-3.1 para obtener más información.
