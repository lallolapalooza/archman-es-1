META(5) Manual de formatos de archivo META(5)

NOMBRE

META - [Archivo que especifica metainformación de paquetes OCaml]

GRAMÁTICA

         metafile ::= entrada*
            entrada ::= asignación | adición | subpaquete
       subpaquete ::= "paquete" nombre_paquete '(' metafile ')'
       asignación ::= nombre_variable [ predicados_formales ] '='  valor
         adición ::= nombre_variable [ predicados_formales ] '+=' valor
formal_predicates ::= '(' predicado_formal { ',' predicado_formal } ')'
    nombre_variable ::= nombre
 predicado_formal ::= nombre | '-' nombre
             nombre ::= [ 'A'-'Z' 'a'-'z' '0'-'9' '_' '.' ]+
          nombre_paquete ::= '"' (carácter pero no '.')* '"'
            valor ::= '"' carácter* '"'

DESCRIPCIÓN

Si un directorio de paquete contiene un archivo con el nombre fijo "META" se interpreta según lo descrito aquí. El archivo es una secuencia de entradas que siguen la gramática dada; cada entrada define una variable bajo una cierta condición dada por la lista de predicados formales, o introduce un subpaquete.

Hay una lista de variables predefinidas y una lista de predicados estándar. Estas variables definen: paquetes requeridos, descripción, información de versión, directorios, archivos de archivo y opciones del enlazador. Los predicados denotan circunstancias de la aplicación de las variables: si se utiliza el compilador de bytecode o el nativo, si hay un bucle superior compilado, detalles de la ejecución multihilo, detalles de la creación de perfiles.

DETALLES DEL FORMATO DEL ARCHIVO

El archivo consta de una secuencia de entradas que deben formarse según lo prescrito por la gramática. Los tokens léxicos son nombres, valores e interpunctación como '(', ',' y así sucesivamente. Tenga en cuenta que los saltos de línea no juegan un papel especial, es decir, la definición de una entrada puede darse en más de una línea, o varias definiciones pueden ocurrir en una sola línea. Puede haber comentarios que comienzan con '#' y continúan hasta el final de la línea.

Los nombres son secuencias de los caracteres A-Z, a-z, 0-9 o _. Se permiten nombres que contienen letras mayúsculas y nombres que comienzan con dígitos, pero no se recomiendan.

Los valores se encierran entre comillas dobles. Los valores pueden contener cualquier carácter. Los caracteres " y \ deben ir precedidos por barras invertidas.

Los nombres de paquetes no deben contener el carácter '.' porque se utiliza como delimitador de nombres compuestos.

PAQUETES PRINCIPALES Y SUBPAQUETES

Las asignaciones y adiciones de variables más externas pertenecen al paquete principal. El nombre del paquete principal no se define dentro de META; es el nombre del directorio que contiene META o el sufijo del archivo META (si el nombre del archivo META tiene el formato META.nombre).

La palabra clave package inicia la definición de un subpaquete. No debe haber dos definiciones de este tipo con el mismo nombre. Dentro de los paréntesis, las asignaciones y adiciones de variables se refieren al subpaquete. Está permitido que un subpaquete contenga subpaquetes adicionales.

El nombre del paquete que sigue a package es el nombre local relativo al paquete principal, es decir, no se menciona el nombre del paquete principal. Sin embargo, en todos los demás lugares, el subpaquete debe ir precedido por el nombre del paquete contenedor, separado por un '.'.

Los subpaquetes son independientes del paquete contenedor, excepto que el subpaquete apunta al mismo directorio de instalación que el paquete contenedor (es decir, la ubicación del directorio de instalación se hereda del paquete contenedor).

SEMÁNTICA DE LAS DEFINICIONES DE VARIABLES

Para determinar el valor de una variable, primero se inspeccionan todas las asignaciones y se toma la asignación más específica (si no hay ninguna, se tomará la cadena vacía como valor). En un segundo paso, se recorren todas las adiciones una tras otra en el orden en que aparecen en el archivo, y los valores de todas las adiciones coincidentes se añaden al valor actual. A continuación, se aclara qué asignación es la más específica, qué adiciones coinciden realmente y cómo son los detalles de la adición de valor.

La asignación más específica se selecciona sobre un conjunto de predicados reales, es decir, el conjunto de predicados que se asume que son verdaderos. Los predicados que ocurren en las definiciones de asignaciones y adiciones se denominan predicados formales. Pueden ser positivos o negativos; los últimos van precedidos de un signo '-'. Para determinar el valor después de la evaluación de las asignaciones, se aplican las siguientes reglas:

Una asignación solo puede utilizarse si todos los predicados formales positivos están incluidos en el conjunto de predicados reales, y si todos los predicados formales negativos no están incluidos en el conjunto de predicados reales. Dicha asignación se denomina aplicable. Si no existe tal asignación, la variable no tendrá valor.
Si existe más de una asignación aplicable, se selecciona la definición con el mayor número de predicados formales.
Si todavía existe más de una asignación aplicable, ambas aplicables y con un número máximo de predicados formales, se selecciona la definición que se define primero.

Una adición coincide cuando todos los predicados formales positivos están incluidos en el conjunto de predicados reales, y todos los predicados formales negativos no están incluidos.

El valor de una adición se añade al valor actual con espacios en blanco implícitos como separador.

VARIABLES

Existe un conjunto de variables con significado predefinido:

La variable "directory" redefine la ubicación del directorio del paquete. Normalmente, el archivo META es el primer archivo que se lee en el directorio del paquete, y antes de que se lea cualquier otro archivo, se evalúa la variable "directory" para ver si el directorio del paquete debe cambiarse. El valor de la variable "directory" se determina con un conjunto vacío de predicados reales. El valor debe ser uno de los siguientes: un nombre de ruta absoluto del directorio alternativo, o un nombre de ruta relativo al directorio stdlib de OCaml (escrito "+ruta"), o un nombre de ruta relativo normal (sin sintaxis especial). En este último caso, la interpretación depende de si está contenido en un paquete principal o secundario, y de si está en vigor el diseño de repositorio estándar o el alternativo (ver sitio-lib para estos términos). Para un paquete principal en diseño estándar, el directorio base es el directorio que contiene físicamente el archivo META, y la ruta relativa se interpreta para este directorio base. Para un paquete principal en diseño alternativo, el directorio base es el directorio que contiene físicamente los archivos META.pkg. El directorio base para los subpaquetes es el directorio del paquete contenedor. (En caso de que una definición de subpaquete no tenga una configuración de "directory", el subpaquete simplemente hereda el directorio del paquete contenedor. Al escribir una directiva de "directory" se puede cambiar nuevamente esta ubicación.)
La variable "requires" especifica la lista de paquetes requeridos. Los nombres de los paquetes deben estar separados por espacios en blanco y/o comas. Los nombres deben estar completamente calificados (es decir, cuando se refieren a un subpaquete, se deben anteponer los nombres de todos los paquetes contenedores, separados por '.').
La variable "description" puede incluir una breve descripción del paquete (mostrada por ocamlfind list).
La variable "version" especifica la cadena de versión.
La variable "archive" especifica la lista de archivos de archivo. Estos archivos deben darse como (1) pla

El nombre de la variable "plugin" especifica los archivos de plugin del paquete. Estos pueden cargarse dinámicamente con el módulo Fl_dynload. Los archivos de plugin pueden tener sufijos ".cmo", ".cma" o ".cmxs".
La variable "linkopts" especifica opciones adicionales de vinculación.
La variable "error" puede usarse para señalar condiciones de error. Cuando esta variable es aplicable, el compilador ocaml detiene su ejecución y se imprime un mensaje de error. El mensaje es el valor de la variable.
La variable "warning" puede usarse para señalar advertencias. Cuando esta variable es aplicable, la advertencia se imprime, pero la compilación continúa. El mensaje es el valor de la variable.
La variable "exists_if" puede usarse para desactivar subpaquetes. El valor de "exists_if" es un archivo; el subpaquete está oculto si este archivo no existe. También se puede enumerar varios archivos, y el subpaquete está oculto si ninguno de ellos existe.
La variable "ppx" es un comando que se agrega a la invocación del compilador mediante la opción -ppx (disponible desde OCaml-4.01). Si el comando es relativo a la carpeta actual (por ejemplo, ./cmd), el comando se espera en la carpeta del paquete. Las formas especiales definidas para el caso de "archive" también están disponibles (por ejemplo, @otherpkg/cmd). Los argumentos adicionales pueden especificarse en la invocación de ocamlfind con la opción -ppxopt o la variable "ppxopt".
La variable "ppxopt" es un conjunto de opciones que se añaden a la invocación del rewriter ppx. El contenido de la variable consiste en una o más partes separadas por espacios en blanco. Cada parte consiste en subpartes separadas por comas; la primera subparte indica el paquete que contiene la invocación del rewriter ppx, y las restantes indican las opciones a añadir. Si la opción es un camino relativo a la carpeta actual (por ejemplo, ./foo.cma), el camino se expande relativamente a la carpeta del paquete. Las formas especiales definidas para "archive" también están disponibles (por ejemplo, @otherpkg/foo.cma).

Es posible definir variables adicionales, pero actualmente no hay software que las interprete.

PREDICATES

Hay una lista de predicados estándar:

El predicado "byte" significa que se utiliza el compilador de código bytecode.
El predicado "native" significa que se utiliza el compilador nativo.
El predicado "toploop" significa que el toploop está disponible en el programa vinculado. Este se establece solo cuando el toploop está en ejecución, no cuando se genera.
El predicado "create_toploop" significa que se crea un toploop (usando ocamlmktop).
El predicado "mt" significa que el programa está multi-threaded.
El predicado "mt_posix" significa que, en caso de que "mt" esté establecido, se utilizan las bibliotecas POSIX para implementar hilos.
El predicado "mt_vm" significa que, en caso de que "mt" esté establecido, se utilizan las bibliotecas basadas en VM para implementar hilos.
El predicado "gprof" significa que, en caso de que "native" esté establecido, el programa se compila para perfilado.
El predicado "autolink" significa que ocamlc puede/está haciendo el enlace automático.
El predicado "preprocessor" significa que se escanean las variables META para opciones del preprocessor.
El predicado "syntax" significa que la opción -syntax está presente en la línea de comandos.

Herencia: El predicado "plugin" podría haber sido usado en algunas versiones de findlib para seleccionar archivos cmxs en lugar de cmxa. Esta usabilidad es todavía posible pero se recomienda evitar.

Además de estos predicados, hay predicados de paquete para cada paquete que sea finalmente seleccionado. De hecho, estos tipos de predicados no deben usarse para seleccionar las variables "directory" y "requires", pero son válidos para las otras variables. Los predicados de paquete tienen la forma "pkg_" más el nombre del paquete (con la extensión completamente cualificada).
