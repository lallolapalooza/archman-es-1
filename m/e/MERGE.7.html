NOMBRE

MERGE - inserta, actualiza o elimina condicionalmente filas de una tabla

SINOPSIS

[ WITH consulta_con [, ...] ]
MERGE INTO [ ONLY ] nombre_tabla_destino [ * ] [ [ AS ] alias_destino ]
    USING fuente_datos ON condición_unión
    cláusula_cuándo [...]
    [ RETURNING [ WITH ( { OLD | NEW } AS alias_salida [, ...] ) ]
                { * | expresión_salida [ [ AS ] nombre_salida ] } [, ...] ]
donde fuente_datos es:
    { [ ONLY ] nombre_tabla_origen [ * ] | ( consulta_origen ) } [ [ AS ] alias_origen ]
y cláusula_cuándo es:
    { WHEN MATCHED [ AND condición ] THEN { actualización_merge | eliminación_merge | DO NOTHING } |
      WHEN NOT MATCHED BY SOURCE [ AND condición ] THEN { actualización_merge | eliminación_merge | DO NOTHING } |
      WHEN NOT MATCHED [ BY TARGET ] [ AND condición ] THEN { inserción_merge | DO NOTHING } }
y inserción_merge es:
    INSERT [( nombre_columna [, ...] )]
        [ OVERRIDING { SYSTEM | USER } VALUE ]
        { VALUES ( { expresión | DEFAULT } [, ...] ) | DEFAULT VALUES }
y actualización_merge es:
    UPDATE SET { nombre_columna = { expresión | DEFAULT } |
                 ( nombre_columna [, ...] ) = [ ROW ] ( { expresión | DEFAULT } [, ...] ) |
                 ( nombre_columna [, ...] ) = ( subconsulta
               } [, ...]
y eliminación_merge es:
    DELETE

DESCRIPCIÓN

MERGE realiza acciones que modifican filas en la tabla destino identificada como nombre_tabla_destino, utilizando la fuente_datos. MERGE proporciona una única sentencia SQL que puede condicionalmente INSERTar, UPDATEar o DELETEar filas, una tarea que de otro modo requeriría múltiples sentencias de lenguaje procedural.

Primero, el comando MERGE realiza una unión de fuente_datos a la tabla destino produciendo cero o más filas de cambio candidatas. Para cada fila de cambio candidata, se establece una sola vez el estado de MATCHED, NOT MATCHED BY SOURCE, o NOT MATCHED [BY TARGET], después de lo cual se evalúan las cláusulas WHEN en el orden especificado. Para cada fila de cambio candidata, se ejecuta la primera cláusula que se evalúe como verdadera. No se ejecuta más de una cláusula WHEN para ninguna fila de cambio candidata.

Las acciones de MERGE tienen el mismo efecto que los comandos UPDATE, INSERT o DELETE regulares del mismo nombre. La sintaxis de esos comandos es diferente, notablemente que no hay cláusula WHERE y no se especifica ningún nombre de tabla. Todas las acciones se refieren a la tabla destino, aunque las modificaciones a otras tablas pueden realizarse mediante triggers.

Cuando se especifica DO NOTHING, la fila de origen se omite. Dado que las acciones se evalúan en el orden especificado, DO NOTHING puede ser útil para omitir filas de origen no interesantes antes de un manejo más detallado.

La cláusula RETURNING opcional hace que MERGE calcule y devuelva valor(es) basados en cada fila insertada, actualizada o eliminada. Se puede calcular cualquier expresión que utilice las columnas de la tabla de origen o destino, o la función merge_action(). Por defecto, cuando se realiza una acción INSERT o UPDATE, se utilizan los nuevos valores de las columnas de la tabla destino, y cuando se realiza un DELETE, se utilizan los valores antiguos de las columnas de la tabla destino, pero también es posible solicitar explícitamente valores antiguos y nuevos. La sintaxis de la lista RETURNING es idéntica a la de la lista de salida de SELECT.

No existe un privilegio MERGE separado. Si especifica una acción de actualización, debe tener el privilegio UPDATE sobre la(s) columna(s) de la tabla destino a las que se hace referencia en la cláusula SET. Si especifica una acción de inserción, debe tener el privilegio INSERT sobre la tabla destino. Si especifica una acción de eliminación, debe tener el privilegio DELETE sobre la tabla destino. Si especifica una acción DO NOTHING, debe tener el privilegio SELECT sobre al menos una columna de la tabla destino. También necesitará el privilegio SELECT sobre cualquier columna de la fuente_datos y de la tabla destino a las que se haga referencia en cualquier condición (incluida la condición de unión) o expresión. Los privilegios se prueban una vez al inicio de la sentencia y se verifican ya sea que se ejecuten o no cláusulas WHEN particulares.

MERGE no es compatible si la tabla destino es una vista materializada, una tabla externa, o si tiene alguna regla definida sobre ella.

PARÁMETROS

consulta_con

La cláusula WITH permite especificar una o más subconsultas que pueden ser referenciadas por nombre en la consulta MERGE. Consulte la Sección 7.8 y SELECT(7) para más detalles. Tenga en cuenta que WITH RECURSIVE no es compatible con MERGE.

nombre_tabla_destino

El nombre (opcionalmente calificado por esquema) de la tabla o vista destino en la que fusionar. Si se especifica ONLY antes del nombre de la tabla, las filas coincidentes se actualizan o eliminan solo en la tabla nombrada. Si no se especifica ONLY, las filas coincidentes también se actualizan o eliminan en cualquier tabla que herede de la tabla nombrada. Opcionalmente, se puede especificar * después del nombre de la tabla para indicar explícitamente que se incluyen las tablas descendientes. La palabra clave ONLY y la opción * no afectan a las acciones de inserción, que siempre insertan solo en la tabla nombrada.

Si nombre_tabla_destino es una vista, debe ser automáticamente actualizable sin triggers INSTEAD OF, o debe tener triggers INSTEAD OF para cada tipo de acción (INSERT, UPDATE y DELETE) especificado en las cláusulas WHEN. Las vistas con reglas no son compatibles.

alias_destino

Un nombre sustituto para la tabla destino. Cuando se proporciona un alias, oculta completamente el nombre real de la tabla. Por ejemplo, dada la sentencia MERGE INTO foo AS f, el resto de la sentencia MERGE debe referirse a esta tabla como f y no como foo.

nombre_tabla_origen

El nombre (opcionalmente calificado por esquema) de la tabla, vista o tabla de transición de origen. Si se especifica ONLY antes del nombre de la tabla, se incluyen las filas coincidentes solo de la tabla nombrada. Si no se especifica ONLY, se incluyen las filas coincidentes también de cualquier tabla que herede de la tabla nombrada. Opcionalmente, se puede especificar * después del nombre de la tabla para indicar explícitamente que se incluyen las tablas descendientes.

consulta_origen

Una consulta (sentencia SELECT o sentencia VALUES) que proporciona las filas a fusionar en la tabla destino. Consulte la sentencia SELECT(7) o la sentencia VALUES(7) para una descripción de la sintaxis.

alias_origen

Un nombre sustituto para la fuente de datos. Cuando se proporciona un alias, oculta completamente el nombre real de la tabla o el hecho de que se emitió una consulta.

condición_unión

condición_unión es una expresión que resulta en un valor booleano (similar a una cláusula WHERE) que especifica qué filas en la fuente_datos coinciden con las filas en la tabla destino.

Advertencia
Solo las columnas de la tabla destino que intentan coincidir con las filas de fuente_datos deben aparecer en condición_unión. Las subexpresiones de condición_unión que solo hacen referencia a las columnas de la tabla destino pueden afectar qué acción se toma, a menudo de maneras sorprendentes.

Si se especifican tanto las cláusulas WHEN NOT MATCHED BY SOURCE como WHEN NOT MATCHED [BY TARGET], el comando MERGE realizará una unión COMPLETA entre fuente_datos y la tabla destino. Para que esto funcione, al menos una subexpresión de condición_unión debe usar un operador que pueda soportar una unión hash, o todas las subexpresiones deben usar operadores que puedan soportar una unión de mezcla.

cláusula_cuándo

Se requiere al menos una cláusula WHEN.

La cláusula WHEN puede especificar WHEN MATCHED, WHEN NOT MATCHED BY SOURCE, o WHEN NOT MATCHED [BY TARGET]. Tenga en cuenta que el estándar SQL solo define WHEN MATCHED y WHEN NOT MATCHED (que se define como ninguna fila destino coincidente). WHEN NOT MATCHED BY SOURCE es una extensión al estándar SQL, al igual que la opción de añadir BY TARGET a WHEN NOT MATCHED, para hacer su significado más explícito.

Si la cláusula WHEN especifica WHEN MATCHED y la fila de cambio candidata coincide con una fila en la fuente_datos con una fila en la tabla destino, la cláusula WHEN se ejecuta si la condición está ausente o se evalúa como verdadera.

Si la cláusula WHEN especifica WHEN NOT MATCHED BY SOURCE y la fila de cambio candidata representa una fila en la tabla destino que no coincide con una fila en la fuente_datos, la cláusula WHEN se ejecuta si la condición está ausente o se evalúa como verdadera.

FUENTE_DE_DATOS

Una fuente_de_datos que no coincide con una fila en la tabla de destino, ejecuta el bloque CUANDO si la condición está ausente o se evalúa como verdadera.

condición

Una expresión que devuelve un valor booleano. Si la expresión para un bloque CUANDO devuelve verdadero, la acción de ese bloque se ejecuta para esa fila.

Una condición en un bloque CUANDO COINCIDE puede referirse a columnas en ambas las relaciones de origen y destino. Una condición en un bloque CUANDO NO COINCIDE POR ORIGEN solo puede referirse a columnas de la relación de destino, ya que por definición no hay fila de origen correspondiente. Una condición en un bloque CUANDO NO COINCIDE [POR DESTINO] solo puede referirse a columnas de la relación de origen, ya que por definición no hay fila de destino correspondiente. Solo los atributos del sistema de la tabla de destino son accesibles.

insertar_fusionar

La especificación de una acción INSERTAR que inserta una fila en la tabla de destino. Los nombres de las columnas de la tabla de destino pueden aparecer en cualquier orden. Si no se especifica una lista de nombres de columnas, el valor por defecto es todas las columnas de la tabla en su orden declarado.

Cada columna no presente en la lista explícita o implícita se llenará con un valor por defecto, ya sea su valor predeterminado declarado o NULL si no hay uno.

Si la tabla de destino es una tabla particionada, cada fila se dirige a la partición adecuada y se inserta en ella. Si la tabla de destino es una partición, se produce un error si alguna fila de entrada viola la restricción de partición.

Los nombres de columnas no pueden especificarse más de una vez. Las acciones INSERTAR no pueden contener subconsultas.

Solo se puede especificar una única instrucción VALORES. La instrucción VALORES solo puede referirse a columnas de la relación de origen, ya que por definición no hay fila de destino correspondiente.

actualizar_fusionar

La especificación de una acción ACTUALIZAR que actualiza la fila actual de la tabla de destino. Los nombres de columnas no pueden especificarse más de una vez.

No se permite ni un nombre de tabla ni una instrucción WHERE.

eliminar_fusionar

Especifica una acción ELIMINAR que elimina la fila actual de la tabla de destino. No incluya el nombre de la tabla ni ninguna otra cláusula, ya que se realizaría normalmente con una instrucción ELIMINAR(7).

nombre_columna

El nombre de una columna de la tabla de destino. El nombre de la columna puede ser calificado con un nombre de subcampo o subíndice, si es necesario. (Insertar solo en algunos campos de una columna compuesta deja los otros campos nulos.) No incluya el nombre de la tabla en la especificación de una columna de destino.

SOBRESCRIBIR VALOR DEL SISTEMA

Sin esta cláusula, es un error especificar un valor explícito (diferente de POR DEFECTO) para una columna definida como GENERADO SIEMPRE. Esta cláusula sobreescribe esa restricción.

SOBRESCRIBIR VALOR DEL USUARIO

Si esta cláusula se especifica, cualquier valor proporcionado para columnas definidas como GENERADO POR DEFECTO se ignora y se aplican los valores generados por la secuencia por defecto.

VALORES POR DEFECTO

Todas las columnas se llenan con sus valores por defecto. (No se permite el uso de una cláusula SOBRESCRIBIR en este formato.)

expresión

Una expresión para asignar a la columna. Si se usa en un bloque CUANDO COINCIDE, la expresión puede usar valores de la fila original en la tabla de destino y valores de la fila fuente_de_datos. Si se usa en un bloque CUANDO NO COINCIDE POR ORIGEN, la expresión puede usar solo valores de la fila original en la tabla de destino. Si se usa en un bloque CUANDO NO COINCIDE [POR DESTINO], la expresión puede usar solo valores de la fila fuente_de_datos.

POR DEFECTO

Establece la columna en su valor por defecto (que será NULL si no se ha asignado explícitamente una expresión de valor por defecto).

sub-SELECT

Una subconsulta SELECT que genera tantas columnas de salida como se indiquen en la lista de columnas precedente. La subconsulta debe generar como máximo una única fila. Si genera una fila, sus valores de columna se asignan a las columnas de destino; si no genera ninguna fila, se asignan valores NULL a las columnas de destino. Si se usa en un bloque CUANDO COINCIDE, la subconsulta puede referirse a valores de la fila original en la tabla de destino y a valores de la fila fuente_de_datos. Si se usa en un bloque CUANDO NO COINCIDE POR ORIGEN, la subconsulta puede referirse solo a valores de la fila original en la tabla de destino.

alias_salida

Un nombre opcional que sustituye VIEJO o NUEVO en la lista DEVOLVER.

Por defecto, los valores antiguos de la tabla de destino se pueden devolver escribiendo VIEJO.nombre_columna o VIEJO.*, y los valores nuevos se pueden devolver escribiendo NUEVO.nombre_columna o NUEVO.*. Cuando se proporciona un alias, estos nombres se ocultan y los registros antiguos o nuevos deben referirse usando el alias. Por ejemplo, DEVOLVER CON (VIEJO COMO o, NUEVO COMO n) o o.*, n.*.

expresión_salida

Una expresión que se calcula y devuelve por la instrucción FUSIONAR después de cada fila modificada (sea insertada, actualizada o eliminada). La expresión puede usar cualquier columna de la tabla de origen o la tabla de destino, o la función accion_fusionar() para devolver información adicional sobre la acción ejecutada.

Escribir * devuelve todas las columnas de la tabla de origen, seguidas por todas las columnas de la tabla de destino. Esto suele provocar un gran duplicado, ya que las tablas de origen y destino suelen tener muchas columnas en común. Se puede evitar especificando * con el nombre o alias de la tabla de origen o la tabla de destino.

Un nombre de columna o * también puede ser calificado con VIEJO o NUEVO, o con el correspondiente alias_salida para VIEJO o NUEVO, para devolver valores antiguos o nuevos de la tabla de destino. Un nombre de columna no calificado de la tabla de destino, o una columna de la tabla de destino o * calificada con el nombre o alias de la tabla de destino, devuelve valores nuevos para acciones INSERTAR y ACTUALIZAR, y valores antiguos para acciones ELIMINAR.

nombre_salida

Un nombre para una columna devuelta.

SALIDAS

Después de una completación exitosa, una instrucción FUSIONAR devuelve una etiqueta de comando de la forma

FUSIONAR conteo_total

El conteo_total es el número total de filas modificadas (sea insertadas, actualizadas o eliminadas). Si conteo_total es 0, no se modificaron ninguna fila.

Si la instrucción FUSIONAR contiene una cláusula DEVOLVER, el resultado será similar al de una instrucción SELECCIONAR que contiene las columnas y valores definidos en la lista DEVOLVER, calculados sobre las filas insertadas, actualizadas o eliminadas por la instrucción.

NOTAS

Los siguientes pasos se llevan a cabo durante la ejecución de FUSIONAR.

1. Ejecuta cualquier disparador ANTES DE DECLARACIÓN para todas las acciones especificadas, independientemente de si sus cláusulas CUANDO coinciden.
2. Realiza un join de la tabla de origen a la tabla de destino. La consulta resultante será optimizada normalmente y producirá un conjunto de filas candidatas de modificación. Para cada fila candidata de modificación,
1. Evalúa si cada fila es COINCIDENTE, NO COINCIDENTE POR ORIGEN o NO COINCIDENTE [POR DESTINO].
2. Prueba cada cláusula CUANDO en el orden especificado hasta que una devuelva verdadero.
3. Cuando una cláusula devuelve verdadero, se ejecutan las siguientes acciones:
1. Ejecuta cualquier disparador ANTES DE FILA que se active para el tipo de evento de la acción.
2. Ejecuta la acción especificada, invocando cualquier restricción de tabla de destino.
3. Ejecuta cualquier disparador DESPUÉS DE FILA que se active para el tipo de evento de la acción.

Si la relación de destino es una vista con disparadores EN SU LUGAR DE FILA para el tipo de evento de la acción, se usarán estos disparadores para realizar la acción en su lugar.

3. Ejecuta cualquier disparador DESPUÉS DE DECLARACIÓN para las acciones especificadas, independientemente de si ocurren o no. Esto es similar al comportamiento de una instrucción ACTUALIZAR que modifica ninguna fila.

En resumen, los disparadores de tipo evento (por ejemplo, INSERTAR) se disparan cada vez que se especifica una acción de ese tipo. En contraste, los disparadores a nivel de fila se disparan solo para el tipo de evento específico que se está ejecutando. Por lo tanto, una instrucción FUSIONAR podría disparar disparadores de tipo evento ACTUALIZAR e INSERTAR, incluso aunque solo se hayan disparado disparadores a nivel de fila ACTUALIZAR.

Debes asegurar que el join produzca como máximo una fila candidata de modificación por cada fila de destino. En otras palabras, una fila de destino no debe unir a más de una fila de origen. Si lo hace, solo una de las filas candidatas de modificación se usará para modificar la fila de destino; los intentos posteriores causarán un error. Esto también puede ocurrir si los disparadores a nivel de fila modifican la tabla de destino y las filas modificadas se modifican posteriormente por FUSIONAR. Si la acción repetida es INSERTAR, esto causará una violación de unicidad, mientras que una acción repetida ACTUALIZAR o ELIMINAR causará una violación de cardinalidad; la última es requerida por el estándar SQL. Esta diferencia se diferencia del comportamiento antiguo de joins en instrucciones ACTUALIZAR y ELIMINAR en PostgreSQL, donde los intentos posteriores se ignoran.

Si una cláusula CUANDO omite una sub-cláusula Y, se convierte en la cláusula finalmente alcanzable de este tipo (COINCIDENTE, NO COINCIDENTE POR ORIGEN, o NO COINCIDENTE [POR DESTINO]). Si se especifica una cláusula CUANDO de este tipo más tarde, sería probablemente inalcanzable y se lanzaría un error. Si no se especifica ninguna cláusula finalmente alcanzable de cualquiera de los tipos, podría no haber ninguna acción para una fila candidata de modificación.

El orden en el que se generan las filas a partir del origen se determina de forma indeterminada por defecto. Una consulta_origen puede usarse para especificar un orden consistente, si es necesario, que podría ayudar a evitar bloqueos entre transacciones concurrentes.

Cuando FUSIONAR se ejecuta concurrentemente con otros comandos que modifican la tabla de destino, las reglas de aislamiento de transacciones se aplican normalmente; ver sección 13.2 para una explicación sobre el comportamiento en cada nivel de aislamiento. También podrías considerar usar INSERTAR ... EN CONFLICTO como una alternativa de instrucción que ofrece la capacidad de ejecutar un ACTUALIZAR si ocurre un INSERTAR concurrente. Hay diferencias y restricciones entre las dos instrucciones y no son intercambiables.

NAME

MERGE

merge rows from one table to another

SYNOPSIS

MERGE [ USING source_table ]
    [ ON condition ]
    [ WHEN MATCHED [ AND condition ] THEN action ]
    [ WHEN NOT MATCHED [ BY TARGET ] [ AND condition ] THEN action ]
    [ RETURNING ... ]
MERGE [ USING source_table ]
    [ ON condition ]
    [ WHEN NOT MATCHED [ BY SOURCE ] [ AND condition ] THEN action ]
    [ WHEN MATCHED [ AND condition ] THEN action ]
    [ RETURNING ... ]

DESCRIPTION

The MERGE command allows conditional insertion, update, or deletion of rows in a target table based on the results of comparing it to a source table. It can be used to synchronize two tables.

The basic operation is as follows:

  1. The source table is scanned, and for each row in the source table, the ON condition is evaluated against the target table.

  2. If the ON condition evaluates to true for a source row and a target row, the row is considered a match.

  3. If a match is found, and a WHEN MATCHED clause is present, the condition in that clause is evaluated. If the condition is true, the specified action (e.g., UPDATE or DELETE) is performed on the target row.

  4. If no match is found for a source row, and a WHEN NOT MATCHED [ BY TARGET ] clause is present, the condition in that clause is evaluated. If the condition is true, the specified action (e.g., INSERT) is performed on the target table, using data from the source row.

  5. If a match is found, but no WHEN MATCHED action is performed, and there is a target row that does not have a match in the source table, and a WHEN NOT MATCHED BY SOURCE clause is present, the condition in that clause is evaluated. If the condition is true, the specified action (e.g., DELETE) is performed on the target row.

The MERGE command can perform only one action per row. If multiple WHEN clauses evaluate to true for a given row, the first matching clause is executed, and no further clauses are checked for that row.

The USING clause specifies the source table or query. The ON clause specifies the join condition between the source and target tables.

The WHEN MATCHED clause specifies actions to take when a row in the source table matches a row in the target table (based on the ON condition). An optional condition can further restrict when the action is taken.

The WHEN NOT MATCHED [ BY TARGET ] clause specifies actions to take when a row in the source table does not have a match in the target table. An optional condition can further restrict when the action is taken. Rows inserted using this clause must satisfy all NOT NULL constraints on the target table columns that are not explicitly specified in the INSERT statement.

The WHEN NOT MATCHED BY SOURCE clause specifies actions to take when a row in the target table does not have a match in the source table. This is useful for deleting or updating rows in the target table that are no longer present in the source table. An optional condition can further restrict when the action is taken.

BY TARGET and BY SOURCE are keywords that can be used to clarify the meaning of WHEN NOT MATCHED. WHEN NOT MATCHED BY TARGET is the default if neither is specified. WHEN NOT MATCHED BY SOURCE must be specified explicitly.

The possible actions are INSERT ( column_list ) VALUES ( value_list ), UPDATE SET column_name = expression ..., or DELETE.

The RETURNING clause returns information about the rows affected by the MERGE operation. It can return expressions involving columns from the target table, using special keywords OLD and NEW to refer to the row values before and after the change, respectively. The function merge_action() can also be returned, which indicates the type of action performed (INSERT, UPDATE, or DELETE).

PARAMETERS

source_table

The table or query providing the source data.

condition

A boolean expression used for matching rows between the source and target tables, or for further filtering within WHEN clauses.

action

One of INSERT, UPDATE, or DELETE.

OUTPUTS

The RETURNING clause specifies the columns to be returned for each row affected by the MERGE operation.

NOTES

A MERGE statement must contain at least one WHEN clause.

If WHEN MATCHED is used without a condition, it applies to all rows that match the ON condition.

If WHEN NOT MATCHED is used without a condition, it applies to all rows in the source table that do not match any row in the target table.

If WHEN NOT MATCHED BY SOURCE is used without a condition, it applies to all rows in the target table that do not match any row in the source table.

You cannot use WHEN NOT MATCHED and WHEN NOT MATCHED BY SOURCE in the same MERGE statement.

The MERGE statement supports the WITH clause for common table expressions.

EXAMPLES

Update customer balances based on recent transactions. If a customer does not exist, create a new entry.

MERGE INTO accounts a
USING transactions t
ON t.customer_id = a.customer_id
WHEN MATCHED THEN
  UPDATE SET balance = balance + transaction_value
WHEN NOT MATCHED THEN
  INSERT (customer_id, balance)
  VALUES (t.customer_id, t.transaction_value);

Attempt to insert a new stock item along with the quantity of stock. If the item already exists, instead update the stock count of the existing item. Don't allow entries that have zero stock. Return details of all changes made.

MERGE INTO wines w
USING wine_stock_changes s
ON s.winename = w.winename
WHEN NOT MATCHED AND s.stock_delta > 0 THEN
  INSERT VALUES(s.winename, s.stock_delta)
WHEN MATCHED AND w.stock + s.stock_delta > 0 THEN
  UPDATE SET stock = w.stock + s.stock_delta
WHEN MATCHED THEN
  DELETE
RETURNING merge_action(), w.winename, old.stock AS old_stock, new.stock AS new_stock;

The wine_stock_changes table might be, for example, a temporary table recently loaded into the database.

Update wines based on a replacement wine list, inserting rows for any new stock, updating modified stock entries, and deleting any wines not present in the new list.

MERGE INTO wines w
USING new_wine_list s
ON s.winename = w.winename
WHEN NOT MATCHED BY TARGET THEN
  INSERT VALUES(s.winename, s.stock)
WHEN MATCHED AND w.stock != s.stock THEN
  UPDATE SET stock = s.stock
WHEN NOT MATCHED BY SOURCE THEN
  DELETE;

COMPATIBILITY

This command conforms to the SQL standard.

The WITH clause, BY SOURCE and BY TARGET qualifiers to WHEN NOT MATCHED, DO NOTHING action, and RETURNING clause are extensions to the SQL standard.
