Memoize::Expire(3perl) Guía del programador de Perl Memoize::Expire(3perl)

NOMBRE

Memoize::Expire - Módulo plug-in para la expiración automática de valores memorizados

SINOPSIS

use Memoize;
use Memoize::Expire;
tie my %cache => 'Memoize::Expire',
                   LIFETIME => $tiempo_de_vida,    # En segundos
                   NUM_USES => $n_usos;
memoize 'funcion', SCALAR_CACHE => [HASH => \%cache ];

DESCRIPCIÓN

Memoize::Expire es un módulo plug-in para Memoize. Permite que los valores cacheados de las funciones memorizadas expiren automáticamente. Este manual asume que ya estás familiarizado con el módulo Memoize. Si no es así, deberías estudiar primero ese manual detenidamente, prestando especial atención a la característica HASH.

Memoize::Expire es una capa de software que puedes insertar entre Memoize y cualquier paquete subyacente que implemente la caché. La capa presenta una variable hash cuyos valores expiran cuando se vuelven demasiado viejos, han sido usados demasiadas veces, o ambos. Le dices a "Memoize" que use este hash olvidadizo como su caché en lugar del predeterminado, que es un hash normal.

Para especificar un tiempo límite en tiempo real, proporciona la opción "LIFETIME" con un valor numérico. Los datos cacheados expirarán después de esta cantidad de segundos y se buscarán de nuevo cuando expiren. Cuando un elemento de datos se busca de nuevo, su tiempo de vida se restablece.

Si especificas "NUM_USES" con un argumento de n, cada elemento de datos cacheado será descartado y buscado de nuevo después de la n-ésima vez que lo accedas. Cuando un elemento de datos se busca de nuevo, su número de usos se restablece.

Si especificas ambos argumentos, los datos serán descartados de la caché cuando se cumpla cualquiera de las condiciones de expiración.

Memoize::Expire utiliza un hash real internamente para almacenar los datos cacheados. Puedes usar la opción "HASH" de Memoize::Expire para proporcionar un hash enlazado en lugar del hash ordinario que Memoize::Expire usará normalmente. Puedes usar esta característica para añadir Memoize::Expire como una capa entre un hash persistente en disco y Memoize. Si haces esto, obtienes una caché persistente en disco cuyas entradas expiran automáticamente. Por ejemplo:

#   Memoize
#      |
#   Memoize::Expire  impone la política de expiración de datos
#      |
#   DB_File  implementa la persistencia de datos en un archivo en disco
#      |
#   Archivo en disco
use Memoize;
use Memoize::Expire;
use DB_File;
# Configurar persistencia
tie my %disk_cache => 'DB_File', $filename, O_CREAT|O_RDWR, 0666];
# Configurar política de expiración, proporcionando el hash persistente como objetivo
tie my %cache => 'Memoize::Expire',
                   LIFETIME => $tiempo_de_vida,    # En segundos
                   NUM_USES => $n_usos,
                   HASH => \%disk_cache;
# Configurar memorización, proporcionando el hash persistente expirante para la caché
memoize 'funcion', SCALAR_CACHE => [ HASH => \%cache ];

INTERFAZ

No hay nada especial en Memoize::Expire. Es solo un ejemplo. Si no te gusta la política que implementa, eres libre de escribir tu propio módulo de política de expiración que implemente la política que desees. Aquí te mostramos cómo hacerlo. Supongamos que tu módulo se llamará MyExpirePolicy.

Resumen corto: Necesitas crear un paquete que defina cuatro métodos:

TIEHASH
Construye y devuelve el objeto caché.
EXISTS
Dado un argumento de función, ¿está el valor de función correspondiente en la caché y, si es así, es lo suficientemente reciente como para usarlo?
FETCH
Dado un argumento de función, busca el valor de función correspondiente en la caché y devuélvelo.
STORE
Dado un argumento de función y el valor de función correspondiente, almácenalos en la caché.
CLEAR
(Opcional.) Limpia la caché completamente.

El usuario que quiera que la caché de memorización expire según tu política dirá así:

tie my %cache => 'MyExpirePolicy', args...

Esto invocará
    "MyExpirePolicy->TIEHASH(args)".
    MyExpirePolicy::TIEHASH debería hacer lo que sea apropiado para configurar la
    caché y debería devolver el objeto caché al llamador.


Por ejemplo, MyExpirePolicy::TIEHASH podría crear un objeto que
    contenga un hash normal de Perl (que usará para almacenar los valores
    cacheados) y alguna información adicional sobre los argumentos y la antigüedad
    de los datos y cosas así. Llamemos a este objeto
    "C".


Cuando Memoize necesite comprobar si una entrada ya está en la
    caché, invocará
    "C->EXISTS(key)".
    "key" es el argumento de la función
    normalizado. MyExpirePolicy::EXISTS debería devolver 0 si la clave no está en
    la caché, o si ha expirado, y 1 si hay un valor no expirado en la caché. No
    debería devolver "undef", porque hay un
    error en algunas versiones de Perl que causará un FETCH espurio si el método
    EXISTS devuelve "undef".


Si tu función EXISTS devuelve verdadero, Memoize intentará obtener
    el valor cacheado invocando
    "C->FETCH(key)". MyExpirePolicy::FETCH
    debería devolver el valor cacheado. De lo contrario, Memoize llamará a la
    función memorizada para calcular el valor apropiado, y lo almacenará en la
    caché llamando a "C->STORE(key, value)".


Aquí tienes un ejemplo muy breve de un módulo de política que expira
    cada elemento de la caché después de diez segundos.


package Memoize::TenSecondExpire;
sub TIEHASH {
  my ($package, %args) = @_;
  my $cache = $args{HASH} || {};
  bless $cache => $package;
}
sub EXISTS {
  my ($cache, $key) = @_;
  if (exists $cache->{$key} &&
      $cache->{$key}{EXPIRE_TIME} > time) {
    return 1
  } else {
    return 0;  # NO devolver undef aquí
  }
}
sub FETCH {
  my ($cache, $key) = @_;
  return $cache->{$key}{VALUE};
}
sub STORE {
  my ($cache, $key, $newvalue) = @_;
  $cache->{$key}{VALUE} = $newvalue;
  $cache->{$key}{EXPIRE_TIME} = time + 10;
}


Para usar esta política de expiración, el usuario diría


use Memoize;
tie my %cache10sec => 'Memoize::TenSecondExpire';
memoize 'funcion', SCALAR_CACHE => [HASH => \%cache10sec];


Memoize llamaría entonces a
    "funcion" siempre que un valor cacheado estuviera
    completamente ausente o fuera más antiguo de diez segundos.


Siempre debes admitir un argumento
    "HASH" para
    "TIEHASH" que enlace la caché subyacente
    para que el usuario pueda especificar que la caché también es persistente o
    que tiene alguna otra semántica interesante. El ejemplo anterior demuestra cómo
    hacerlo, al igual que "Memoize::Expire".


Otro módulo de ejemplo, Memoize::Saves, está disponible en una
    distribución separada en CPAN. Implementa una política que te permite
    especificar que ciertos valores de función siempre se buscarán de nuevo. Ver la
    documentación para más detalles.

ALTERNATIVAS

Brent Powers tiene un módulo Memoize::ExpireLRU que fue diseñado para funcionar con Memoize y proporciona la expiración de datos menos usados recientemente. La caché se mantiene en un número fijo de entradas, y cuando llegan nuevos datos, los datos menos usados recientemente se expiran.

El módulo Tie::Cache de Joshua Chamas puede ser útil como gestor de expiración. (Si pruebas esto, por favor, házmelo saber cómo funciona).

Si desarrollas algún gestor de expiración útil que creas que debería distribuirse con Memoize, por favor, házmelo saber.

ADVERTENCIAS

Este módulo es experimental y puede contener errores. Por favor, reporta los errores a la dirección de abajo.

El número de usos se almacena como un entero sin signo de 16 bits, por lo que no puede exceder 65535.

Debido a la granularidad del reloj, los tiempos de expiración pueden ocurrir hasta un segundo antes de lo esperado. Por ejemplo, supón que almacenas un valor con un tiempo de vida de diez segundos y lo almacenas a las 12:00:00.998 de un día determinado. Memoize mirará el reloj y verá las 12:00:00.
