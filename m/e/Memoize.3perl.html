Memoize(3perl) Perl Programmers Reference Guide Memoize(3perl)

NOMBRE

Memoize - Hacer las funciones más rápidas intercambiando espacio por tiempo

SINOPSIS

use Memoize;
memoize('funcion_lenta');
funcion_lenta(argumentos);    # Es más rápida de lo que era antes

Normalmente, esto es todo lo que necesitas saber. Sin embargo, hay muchas opciones disponibles:

memoize(funcion, opciones...);

Las opciones incluyen:

NORMALIZER => funcion
INSTALL => nuevo_nombre
SCALAR_CACHE => 'MEMORY'
SCALAR_CACHE => ['HASH', \%cache_hash ]
SCALAR_CACHE => 'FAULT'
SCALAR_CACHE => 'MERGE'
LIST_CACHE => 'MEMORY'
LIST_CACHE => ['HASH', \%cache_hash ]
LIST_CACHE => 'FAULT'
LIST_CACHE => 'MERGE'

DESCRIPCIÓN

Memorizar una función la hace más rápida al intercambiar espacio por tiempo. Lo hace almacenando en caché los valores de retorno de la función en una tabla. Si llamas a la función de nuevo con los mismos argumentos, "memoize" interviene y te entrega el valor de la tabla, en lugar de dejar que la función calcule el valor de nuevo.

EJEMPLO

Aquí hay un ejemplo extremo. Considera la secuencia de Fibonacci, definida por la siguiente función:

# Calcular números de Fibonacci
sub fib {
  my $n = shift;
  return $n if $n < 2;
  fib($n-1) + fib($n-2);
}

Esta función es muy lenta. ¿Por qué? Para calcular fib(14), primero quiere calcular fib(13) y fib(12), y sumar los resultados. Pero para calcular fib(13), primero tiene que calcular fib(12) y fib(11), y luego vuelve y calcula fib(12) de nuevo, aunque la respuesta sea la misma. Y en ambas ocasiones en que quiere calcular fib(12), tiene que calcular fib(11) desde cero, y luego hacerlo de nuevo cada vez que quiere calcular fib(13). Esta función hace tantas recalcularizaciones de resultados antiguos que tarda mucho tiempo en ejecutarse: fib(14) hace 1.200 llamadas recursivas adicionales a sí misma, para calcular y recalcular cosas que ya había calculado.

Esta función es un buen candidato para la memorización. Si memorizas la función "fib" anterior, calculará fib(14) exactamente una vez, la primera vez que necesite hacerlo, y luego guardará el resultado en una tabla. Luego, si pides fib(14) de nuevo, te dará el resultado de la tabla. Mientras calcula fib(14), en lugar de calcular fib(12) dos veces, lo hace una vez; la segunda vez que necesita el valor, lo obtiene de la tabla. No calcula fib(11) cuatro veces; lo calcula una vez, y lo obtiene de la tabla las siguientes tres veces. En lugar de hacer 1.200 llamadas recursivas a "fib", hace 15. Esto hace que la función sea unas 150 veces más rápida.

Podrías hacer la memorización tú mismo, reescribiendo la función, así:

# Calcular números de Fibonacci, versión memorizada
{ my @fib;
  sub fib {
    my $n = shift;
    return $fib[$n] if defined $fib[$n];
    return $fib[$n] = $n if $n < 2;
    $fib[$n] = fib($n-1) + fib($n-2);
  }
}

O podrías usar este módulo, así:

use Memoize;
memoize('fib');
# El resto de la función fib igual que la versión original.

Esto facilita activar y desactivar la memorización.

Aquí hay un ejemplo aún más simple: escribí un trazador de rayos simple; el programa miraba en cierta dirección, averiguaba qué estaba mirando, y luego convertía el valor de "color" (típicamente una cadena como "rojo") de ese objeto a un valor de píxel rojo, verde y azul, así:

for ($direction = 0; $direction < 300; $direction++) {
  # Averiguar qué objeto está en la dirección $direction
  $color = $object->{color};
  ($r, $g, $b) = @{&ColorToRGB($color)};
  ...
}

Como hay relativamente pocos objetos en una imagen, solo hay unos pocos colores, que se buscan una y otra vez. Memorizar "ColorToRGB" aceleró el programa en varios por ciento.

DETALLES

Este módulo exporta exactamente una función, "memoize". El resto de las funciones en este paquete son Ningún Asunto Tuyo.

Deberías decir

memoize(funcion)

donde "funcion" es el nombre de la función que quieres memorizar, o una referencia a ella. "memoize" devuelve una referencia a la nueva versión memorizada de la función, o "undef" en un error no fatal. Actualmente, no hay errores no fatales, pero podría haber algunos en el futuro.

Si "funcion" era el nombre de una función, entonces "memoize" oculta la versión antigua e instala la nueva versión memorizada bajo el nombre antiguo, de modo que &funcion(...) invoca realmente la versión memorizada.

OPCIONES

Hay algunas opciones opcionales que puedes pasar a "memoize" para cambiar un poco su comportamiento. Para proporcionar opciones, invoca "memoize" así:

memoize(funcion, NORMALIZER => funcion,
                  INSTALL => nuevo_nombre,
                  SCALAR_CACHE => opcion,
                  LIST_CACHE => opcion
                 );

Cada una de estas opciones es opcional; puedes incluir algunas, todas o ninguna.

INSTALL

Si proporcionas un nombre de función con "INSTALL", memoize instalará la nueva versión memorizada de la función bajo el nombre que le des. Por ejemplo,

memoize('fib', INSTALL => 'fastfib')

instala la versión memorizada de "fib" como "fastfib"; sin la opción "INSTALL", habría reemplazado la antigua "fib" con la versión memorizada.

Para evitar que "memoize" instale la versión memorizada en cualquier lugar, usa "INSTALL => undef".

NORMALIZER

Supongamos que tu función se ve así:

# Llamada típica: f('aha!', A => 11, B => 12);
sub f {
  my $a = shift;
  my %hash = @_;
  $hash{B} ||= 2;  # B tiene un valor predeterminado de 2
  $hash{C} ||= 7;  # C tiene un valor predeterminado de 7
  # Hacer algo con $a, %hash
}

Ahora, las siguientes llamadas a tu función son todas completamente equivalentes:

f(OUCH);
f(OUCH, B => 2);
f(OUCH, C => 7);
f(OUCH, B => 2, C => 7);
f(OUCH, C => 7, B => 2);
(etc.)

Sin embargo, a menos que le digas a "Memoize" que estas llamadas son equivalentes, no lo sabrá, y calculará los valores para estas invocaciones de tu función por separado, y las almacenará por separado.

Para evitar esto, proporciona una función "NORMALIZER" que convierta los argumentos del programa en una cadena de forma que los argumentos equivalentes se conviertan en la misma cadena. Una función "NORMALIZER" para "f" anterior podría verse así:

sub normalize_f {
  my $a = shift;
  my %hash = @_;
  $hash{B} ||= 2;
  $hash{C} ||= 7;
  join(',', $a, map ($_ => $hash{$_}) sort keys %hash);
}

Cada una de las listas de argumentos anteriores sale de la función "normalize_f" luciendo exactamente igual, así:

OUCH,B,2,C,7

Le dirías a "Memoize" que use este normalizador así:

memoize('f', NORMALIZER => 'normalize_f');

"memoize" sabe que si la versión normalizada de los argumentos es la misma para dos listas de argumentos, entonces puede buscar de forma segura el valor que calculó para una lista de argumentos y devolverlo como el resultado de llamar a la función con la otra lista de argumentos, incluso si las listas de argumentos parecen diferentes.

El normalizador predeterminado simplemente concatena los argumentos con el carácter 28 en medio. (En ASCII, esto se llama FS o control-\). Esto siempre funciona correctamente para funciones con un solo argumento de cadena, y también cuando los argumentos nunca contienen el carácter 28. Sin embargo, puede confundir ciertas listas de argumentos:

normalizer("a\034", "b")
normalizer("a", "\034b")
normalizer("a\034\034b")

Esos tres se normalizan a la misma cadena (si el delimitador es $\034), por lo que si solo se usara el normalizador predeterminado, "Memoize" pensaría que todas esas llamadas son iguales, aunque no lo sean.

SCALAR_CACHE

Por defecto, "Memoize" almacena en caché los valores de retorno escalares en una tabla interna en memoria. Para funcionar, se basa en el módulo "Storable" para poder almacenar y recuperar los resultados de forma segura, pero en general no debería necesitar usar "Storable" directamente.

Hay varias formas de especificar cómo se debe almacenar en caché un valor escalar:

MEMORY
Los resultados se almacenan en una tabla interna en memoria. Este es el valor predeterminado. Los resultados se guardan en un hash interno de este módulo.
HASH, \%hash
Los resultados se almacenan en el hash que se pasa. Por ejemplo: 

my %my_cache;
memoize('my_func', SCALAR_CACHE => ['HASH', \%my_cache]);

Si la llamada a la función falla, se devuelve el valor predeterminado del hash (normalmente "undef"), y el módulo memoize no lanza una excepción.
FAULT
No se almacena ningún valor escalar en caché. En su lugar, la función siempre se llama. Esto podría ser útil si solo estás utilizando la función para sus efectos secundarios, pero aún así quieres que la función se ejecute cada vez.
MERGE
Si la función devuelve una lista, los elementos de la lista se almacenan en caché individualmente. Esto solo es útil si tu función devuelve una lista con un solo elemento y quieres obtener un ligero aumento de rendimiento.

LIST_CACHE

Funciona igual que "SCALAR_CACHE", excepto que se aplica a valores de retorno de lista. Por defecto, los resultados de lista se almacenan en caché en una tabla de memoria interna.

Actualmente, "LIST_CACHE=>'MERGE'" y "LIST_CACHE=>'FAULT'" son los únicos valores válidos además de los valores predeterminados.

DIAGNÓSTICOS

El módulo memoize emite un error de tipo fatal si se llama a una función que no existe, o si se solicita una caché que no existe.

También emitirá una advertencia si se le pide que almacene en caché una función que devuelve una lista en un contexto escalar, o viceversa.

ERRORES

Los argumentos complejos que contienen referencias anidadas pueden ser problemáticos. Por ejemplo, si llamas a una función con un array de arrays, el normalizador predeterminado podría tener problemas para diferenciarlos.

En general, si la función que estás intentando memorizar toma argumentos que son de tipo referencia, probablemente quieras escribir tu propia función normalizadora para asegurarte de que los argumentos idénticos se normalizan de la misma manera.

Si la función que intentas memorizar devuelve "undef", y estás usando "SCALAR_CACHE=>['HASH', \%cache_hash ]", entonces esa llamada no se almacenará en caché.

>para ejemplo.

Dado que las claves hash son cadenas, el normalizador predeterminado no distinguirá entre "undef" y la cadena vacía. Tampoco funcionará cuando los argumentos de la función sean referencias. Por ejemplo, considere una función "g" que recibe dos argumentos: un número y una referencia a un array de números:

g(13, [1,2,3,4,5,6,7]);

El normalizador predeterminado lo convertirá en algo como "13\034ARRAY(0x436c1f)". Eso estaría bien, excepto que un array de números posterior podría almacenarse en una ubicación diferente aunque contenga los mismos datos. Si esto sucede, "Memoize" pensará que los argumentos son diferentes, aunque sean equivalentes. En este caso, un normalizador como este es apropiado:

sub normalize { join ' ', $_[0], @{$_[1]} }

Para el ejemplo anterior, esto produce la clave "13 1 2 3 4 5 6 7".

Otro uso para los normalizadores es cuando la función depende de datos distintos de los de sus argumentos. Suponga que tiene una función que devuelve un valor que depende de la hora actual del día:

sub on_duty {
  my ($problem_type) = @_;
  my $hour = (localtime)[2];
  open my $fh, "$DIR/$problem_type" or die...;
  my $line;
  while ($hour-- > 0)
    $line = <$fh>;
  }
  return $line;
}

A las 10:23, esta función genera la décima línea de un archivo de datos; a las 15:45 genera la decimoquinta línea en su lugar. Por defecto, "Memoize" solo verá el argumento $problem_type. Para solucionar esto, incluya la hora actual en el normalizador:

sub normalize { join ' ', (localtime)[2], @_ }

El contexto de llamada de la función (contexto escalar o de lista) se propaga al normalizador. Esto significa que si la función memorizada tratará sus argumentos de manera diferente en contexto de lista que en contexto escalar, puede hacer que la función normalizadora seleccione su comportamiento basándose en los resultados de "wantarray". Incluso si se llama en un contexto de lista, un normalizador aún debe devolver una sola cadena.

"SCALAR_CACHE", "LIST_CACHE"

Normalmente, "Memoize" almacena en caché los valores de retorno de su función en una variable hash normal de Perl. Sin embargo, es posible que le gustaría que los valores se almacenen en caché en el disco, de modo que persistan de una ejecución a la siguiente de su programa, o que le gustaría asociar alguna otra semántica interesante con los valores almacenados en caché.

Hay una pequeña complicación en el funcionamiento interno de "Memoize": en realidad hay *dos* cachés, una para valores escalares y otra para valores de lista. Cuando se llama a su función en contexto escalar, su valor de retorno se almacena en caché en un hash, y cuando se llama a su función en contexto de lista, su valor se almacena en caché en el otro hash. Puede controlar el comportamiento de almacenamiento en caché de ambos contextos de forma independiente con estas opciones.

El argumento para "LIST_CACHE" o "SCALAR_CACHE" debe ser una de las siguientes cuatro cadenas:

MEMORY
FAULT
MERGE
HASH

o debe ser una referencia a un array cuyo primer elemento sea una de estas cuatro cadenas, como "[HASH, arguments...]".

"MEMORY"
"MEMORY" significa que los valores de retorno de la función se almacenarán en caché en una variable hash normal de Perl. La variable hash no persistirá después de que el programa salga. Este es el valor predeterminado.
"HASH"
"HASH" le permite especificar que se usará un hash particular que usted proporcione como caché. Puede vincular este hash de antemano para darle el comportamiento que desee.

Un hash vinculado puede tener cualquier semántica. Normalmente se vincula a una base de datos en disco, de modo que los valores almacenados en caché se almacenan en la base de datos y se recuperan de ella cuando sea necesario, y el archivo de disco normalmente persiste después de que su programa salga. Consulte "perltie" para obtener detalles más completos sobre "tie".

Un ejemplo típico es:

use DB_File;
tie my %cache => 'DB_File', $filename, O_RDWR|O_CREAT, 0666;
memoize 'function', SCALAR_CACHE => [HASH => \%cache];

Esto tiene el efecto de almacenar la caché en una base de datos "DB_File" cuyo nombre está en $filename. La caché persistirá después de que el programa salga. La próxima vez que se ejecute el programa, encontrará la caché ya poblada desde la ejecución anterior del programa. O puede poblar forzosamente la caché construyendo un programa por lotes que se ejecuta en segundo plano y puebla el archivo de caché. Luego, cuando ejecute su programa real, la función memorizada será rápida porque todos sus resultados se habrán precalculado.

Otra razón para usar "HASH" es proporcionar su propia variable hash. Luego puede inspeccionar o modificar el contenido del hash para obtener un control más detallado sobre la gestión de la caché.

"TIE"
Esta opción ya no se admite. Solo se documenta para ayudar a depurar programas antiguos que la utilizan. Los programas antiguos deben convertirse para usar la opción "HASH" en su lugar. 
memoize ... ['TIE', PACKAGE, ARGS...]

es simplemente un atajo para

require PACKAGE;
{ tie my %cache, PACKAGE, ARGS...;
  memoize ... [HASH => \%cache];
}
"FAULT"
"FAULT" significa que nunca espera llamar a la función en contexto escalar (o de lista), y que si "Memoize" detecta tal llamada, debe abortar el programa. El mensaje de error es uno de 
`foo' function called in forbidden list context at line ...
`foo' function called in forbidden scalar context at line ...
"MERGE"
"MERGE" normalmente significa que la función memorizada no distingue entre el contexto de lista y el escalar, y que los valores de retorno en ambos contextos deben almacenarse juntos. Tanto "LIST_CACHE => MERGE" como "SCALAR_CACHE => MERGE" significan lo mismo.

Considere esta función:

sub complicated {
  # ... cálculo que consume mucho tiempo de $result
  return $result;
}

La función "complicated" devolverá el mismo $result numérico, independientemente de si se llama en contexto de lista o escalar.

Normalmente, el siguiente código resultará en dos llamadas a "complicated", incluso si "complicated" está memorizado:

$x = complicated(142);
($y) = complicated(142);
$z = complicated(142);

La primera llamada almacenará en caché el resultado, digamos 37, en la caché escalar; la segunda almacenará en caché la lista "(37)" en la caché de lista. La tercera llamada no llama a la función real "complicated"; obtiene el valor 37 de la caché escalar.

Obviamente, la segunda llamada a "complicated" es una pérdida de tiempo, y almacenar su valor de retorno es un desperdicio de espacio. Especificar "LIST_CACHE => MERGE" hará que "memoize" utilice la misma caché para los valores de retorno de contexto escalar y de lista, de modo que la segunda llamada utilice la caché escalar que fue poblada por la primera llamada. "complicated" termina siendo llamada solo una vez, y ambas llamadas posteriores devuelven 37 desde la caché, independientemente del contexto de llamada.

Valores de lista en contexto escalar

Considere esta función:

sub iota { return reverse (1..$_[0]) }

Esta función normalmente devuelve una lista. Suponga que la memoriza y fusiona las cachés:

memoize 'iota', SCALAR_CACHE => 'MERGE';
@i7 = iota(7);
$i7 = iota(7);

Aquí la primera llamada almacena en caché la lista (1,2,3,4,5,6,7). La segunda llamada no tiene mucho sentido. "Memoize" no puede adivinar qué comportamiento debería tener "iota" en contexto escalar sin llamarla realmente en contexto escalar. Normalmente "Memoize" *llamaría* a "iota" en contexto escalar y almacenaría en caché el resultado, pero la opción "SCALAR_CACHE => 'MERGE'" dice que no haga eso, sino que use el valor de caché de contexto de lista en su lugar. Pero no puede devolver una lista de siete elementos en un contexto escalar. En este caso, $i7 recibirá el **primer elemento** del valor de lista almacenado en caché, es decir, 7.

Cachés de disco fusionadas

Otro uso para "MERGE" es cuando desea que ambos tipos de valores de retorno se almacenen en el mismo archivo de disco; esto le ahorra tener que lidiar con dos archivos de disco en lugar de uno. Puede usar una función normalizadora para mantener separados los dos conjuntos de valores de retorno. Por ejemplo:

local $MLDBM::UseDB = 'DB_File';
tie my %cache => 'MLDBM', $filename, ...;
memoize 'myfunc',
  NORMALIZER => 'n',
  SCALAR_CACHE => [HASH => \%cache],
  LIST_CACHE => 'MERGE',
;
sub n {
  my $context = wantarray() ? 'L' : 'S';
  # ... ahora calcula la clave hash a partir de los argumentos ...
  $hashkey = "$context:$hashkey";
}

Esta función normalizadora almacenará los valores de retorno del contexto escalar en el archivo de disco bajo claves que comienzan con "S:", y los valores de retorno del contexto de lista bajo claves que comienzan con "L:".

OTRAS FACILIDADES

"unmemoize"

Existe una función "unmemoize" que puede importar si lo desea. ¿Por qué querría hacerlo? Aquí tiene un ejemplo: suponga que su caché está vinculada a un archivo DBM y desea asegurarse de que la caché se escriba en disco si alguien interrumpe el programa. Si el programa sale normalmente, esto sucederá de todos modos, pero si

alguien presiona control-C o algo y el programa terminará inmediatamente sin sincronizar la base de datos. Así que lo que puedes hacer en su lugar es

$SIG{INT} = sub { unmemoize 'function' };

"unmemoize" acepta una referencia a, o el nombre de una función previamente memoizada, y deshace lo que sea que hizo para proporcionar la versión memoizada en primer lugar, incluyendo hacer que el nombre se refiera a la versión no memoizada si es apropiado. Devuelve una referencia a la versión no memoizada de la función.

Si le pides que desmemoice una función que nunca fue memoizada, lanza un error.

"flush_cache"

flush_cache(function) vaciará las cachés, descartando *todos* los datos cacheados. El argumento puede ser un nombre de función o una referencia a una función. Para un control más fino sobre cuándo se descartan o caducan los datos, consulte la documentación de "Memoize::Expire", incluida en este paquete.

Tenga en cuenta que si la caché es un hash "tied" (ligado), "flush_cache" intentará invocar el método "CLEAR" en el hash. Si no existe un método "CLEAR", esto provocará un error en tiempo de ejecución.

Un enfoque alternativo para vaciar la caché es utilizar la opción "HASH" (ver arriba) para solicitar que "Memoize" utilice una variable de hash particular como su caché. Entonces puede examinar o modificar el hash en cualquier momento de la forma que desee. Puede vaciar la caché usando "%hash = ()".

ADVERTENCIAS

La memoización no es una panacea:

  • No memoice una función cuyo comportamiento dependa del estado del programa distinto de sus propios argumentos, como variables globales, la hora del día o la entrada de archivos. Estas funciones no producirán resultados correctos cuando se memoicen. Para un ejemplo particularmente fácil: 
    sub f {
  time;
}

    Esta función no toma argumentos y, en lo que respecta a "Memoize", siempre devuelve el mismo resultado. "Memoize" está equivocado, por supuesto, y la versión memoizada de esta función llamará a "time" una vez para obtener la hora actual, y devolverá esa misma hora cada vez que la llame después de eso.

  • No memoice una función con efectos secundarios. 
    sub f {
  my ($a, $b) = @_;
  my $s = $a + $b;
  print "$a + $b = $s.\n";
}

    Esta función acepta dos argumentos, los suma e imprime su suma. Su valor de retorno es el número de caracteres que imprimió, pero probablemente no le importó eso. Pero "Memoize" no lo entiende. Si memoiza esta función, obtendrá el resultado esperado la primera vez que le pida que imprima la suma de 2 y 3, pero las llamadas subsiguientes devolverán 1 (el valor de retorno de "print") sin imprimir nada en realidad.

  • No memoice una función que devuelve una estructura de datos que es modificada por su llamador.

    Considere estas funciones: "getusers" devuelve una lista de usuarios de alguna manera, y luego "main" descarta el primer usuario de la lista e imprime el resto:

    sub main {
  my $userlist = getusers();
  shift @$userlist;
  foreach $u (@$userlist) {
    print "User $u\n";
  }
}
sub getusers {
  my @users;
  # Do something to get a list of users;
  \@users;  # Return reference to list.
}

    Si memoiza "getusers" aquí, funcionará correctamente exactamente una vez. La referencia a la lista de usuarios se almacenará en la tabla de memoización. "main" descartará el primer elemento de la lista referenciada. La próxima vez que invoque "main", "Memoize" no llamará a "getusers"; simplemente devolverá la misma referencia a la misma lista que obtuvo la última vez. Pero esta vez la lista ya ha tenido su primer elemento eliminado; "main" eliminará erróneamente otro elemento de ella. La lista se hará cada vez más corta cada vez que llame a "main".

    De manera similar, esto:

    $u1 = getusers();    
$u2 = getusers();    
pop @$u1;

    modificará $u2 así como $u1, porque ambas variables son referencias a la misma matriz. Si "getusers" no hubiera sido memoizada, $u1 y $u2 se habrían referido a matrices diferentes.

  • No memoice una función muy simple.

    Recientemente alguien me mencionó que el módulo Memoize hizo que su programa corriera más lento en lugar de más rápido. Resultó que estaba memoizando la siguiente función:

    sub square {
  $_[0] * $_[0];
}

    Señalé que "Memoize" usa un hash, y que buscar un número en el hash necesariamente tomará mucho más tiempo que una sola multiplicación. Realmente no hay forma de acelerar la función "square".

    La memoización no es mágica.

SOPORTE DE CACHÉ PERSISTENTE

Puedes ligar las tablas de caché a cualquier tipo de hash ligado que desees, siempre y cuando soporte "TIEHASH", "FETCH", "STORE" y "EXISTS". Por ejemplo,

tie my %cache => 'GDBM_File', $filename, O_RDWR|O_CREAT, 0666;
memoize 'function', SCALAR_CACHE => [HASH => \%cache];

funciona bien. Para algunos métodos de almacenamiento, necesitas un poco de pegamento.

"SDBM_File" no proporciona un método "EXISTS", por lo que se incluye en este paquete un módulo de pegamento llamado "Memoize::SDBM_File" que sí lo proporciona. Úsalo en lugar de "SDBM_File" simple para almacenar tu tabla de caché en disco en una base de datos "SDBM_File":

tie my %cache => 'Memoize::SDBM_File', $filename, O_RDWR|O_CREAT, 0666;
memoize 'function', SCALAR_CACHE => [HASH => \%cache];

"NDBM_File" tiene el mismo problema y la misma solución. (Usa "Memoize::NDBM_File" en lugar de NDBM_File simple).

"Storable" no es una clase de hash ligada en absoluto. Puedes usarlo para almacenar un hash en disco y recuperarlo de nuevo, pero no puedes modificar el hash mientras está en disco. Así que si quieres almacenar tu tabla de caché en una base de datos "Storable", usa "Memoize::Storable", que pone una interfaz similar a un hash sobre "Storable". La tabla hash se mantiene en realidad en memoria, y se carga desde tu archivo "Storable" en el momento en que memoizas la función, y se vuelve a guardar en el momento en que desmemoizas la función (o cuando tu programa termina):

tie my %cache => 'Memoize::Storable', $filename;
memoize 'function', SCALAR_CACHE => [HASH => \%cache];
tie my %cache => 'Memoize::Storable', $filename, 'nstore';
memoize 'function', SCALAR_CACHE => [HASH => \%cache];

Incluye la opción "nstore" para que la base de datos "Storable" se escriba en *orden de red*. (Ver Storable para más detalles sobre esto).

La función flush_cache() lanzará un error en tiempo de ejecución a menos que el paquete ligado proporcione un método "CLEAR".

SOPORTE DE CADUCIDAD

Ver Memoize::Expire, que es un módulo "plug-in" que añade funcionalidad de caducidad a Memoize. Si no te gustan los tipos de políticas que implementa Memoize::Expire, es fácil escribir tu propio módulo "plug-in" para implementar la política que desees. Memoize viene con varios ejemplos. Un gestor de caducidad que implementa una política LRU (Least Recently Used) está disponible en CPAN como Memoize::ExpireLRU.

ERRORES

La suite de pruebas es mucho mejor, pero siempre necesita mejora.

Hay algún problema con la forma en que "goto &f" funciona en Perl con hilos, quizás debido al alcance léxico de @_. Este es un error en Perl, y hasta que se resuelva, las funciones memoizadas verán un caller() ligeramente diferente y se ejecutarán un poco más lentamente en perls con hilos que en perls sin hilos.

Algunas versiones de "DB_File" no te permiten almacenar datos bajo una clave de longitud 0. Eso significa que si tienes una función "f" que memoizaste y la caché está en una base de datos "DB_File", entonces el valor de f() ( "f" llamada sin argumentos) no será memoizado. Si esto es un gran problema, puedes proporcionar una función normalizadora que anteponga "x" a cada clave.

NOMBRE

Memoize

SINOPSIS

use Memoize;

DESCRIPCIÓN

Memoize es un módulo de Perl que proporciona una caché para llamadas a funciones. Permite almacenar los resultados de las llamadas a funciones y recuperarlos rápidamente, lo que puede mejorar significativamente el rendimiento al evitar cálculos redundantes.

EJEMPLO

sub foo { return 42; }

DETALLES

Memoize funciona almacenando en caché los resultados de las llamadas a funciones. Cuando se llama a una función, si el resultado ya está en la caché, devuelve el valor almacenado en caché en lugar de recalcularlo. Si el resultado no está en la caché, lo calcula y lo almacena para su uso futuro.

OPCIONES

El módulo proporciona varias opciones para personalizar su comportamiento, como especificar el tipo de caché, la política de caducidad y el normalizador predeterminado.

OTRAS FACILIDADES

Memoize admite instalaciones adicionales como el soporte de caché persistente y el soporte de caducidad, lo que le permite administrar los datos de la caché de manera más efectiva.

ADVERTENCIAS

Algunas advertencias incluyen la necesidad de manejar la invalidación de la caché y el potencial de uso de memoria si no se administra correctamente.

SOPORTE DE CACHÉ PERSISTENTE

Memoize admite el almacenamiento de caché persistente, lo que permite que los datos almacenados en caché sobrevivan a los reinicios del servidor.

SOPORTE DE CADUCIDAD

Memoize incluye soporte de caducidad, lo que le permite establecer un límite de tiempo para que los datos almacenados en caché caduquen después de un cierto período.

ERRORES

Pueden existir algunos errores, y se anima a los usuarios a informarlos a los mantenedores.
