Mail::SpamAssassin::Timeout(3) Documentación de Perl contribuida por el usuario Mail::SpamAssassin::Timeout(3)

NOMBRE

Mail::SpamAssassin::Timeout - tiempos de espera seguros y fiables en perl

SINOPSIS

# código sin tiempo de espera...
my $t = Mail::SpamAssassin::Timeout->new({ secs => 5, deadline => $when });
$t->run(sub {
    # código a ejecutar con un tiempo de espera de 5 segundos...
});
if ($t->timed_out()) {
    # haz algo...
}
# código sin tiempo de espera...

DESCRIPCIÓN

Este módulo proporciona una API segura, fiable y limpia para proporcionar tiempos de espera basados en alarm(2) para código perl.

Ten en cuenta que $SIG{ALRM} se utiliza para proporcionar el tiempo de espera, por lo que esto no interrumpirá coincidencias de expresiones regulares descontroladas.

Se admiten tiempos de espera anidados.

MÉTODOS PÚBLICOS

my $t = Mail::SpamAssassin::Timeout->new({ ... opciones ... });
Constructor. Las opciones incluyen:
secs => $segundos
intervalo de tiempo, en segundos. Opcional; si no se especifica "secs" ni "deadline", no se aplicarán tiempos de espera.
deadline => $timestamp_unix
Marca de tiempo Unix (segundos desde la época) cuando se alcanza un tiempo de espera como último recurso. Opcional; si no se especifica ni secs ni deadline, no se aplicarán tiempos de espera. Si se especifican ambos, prevalece el intervalo más corto de los dos.
$t->run($coderef)
Ejecuta una referencia de código dentro del tiempo de espera actualmente definido.

El tiempo de espera es el definido por los parámetros secs y deadline del constructor.

Devuelve lo que sea que devuelva la subrutina, o "undef" en caso de tiempo de espera agotado. Si el temporizador se agota, "$t->timed_out()" devolverá 1.

El tiempo transcurrido no es acumulativo; múltiples ejecuciones de "run" reiniciarán el tiempo de espera desde el principio. Por otro lado, los temporizadores anidados sí observan los tiempos de espera externos si son más cortos, señalando de nuevo un tiempo de espera al nivel que los estableció, es decir, el código que se ejecuta bajo un temporizador interno no puede exceder el límite de tiempo establecido por un temporizador externo. Al reiniciar un temporizador externo al regresar, se tiene en cuenta el tiempo transcurrido del código en ejecución.

$t->run_and_catch($coderef)
Ejecuta una referencia de código, como en "$t->run()", pero también capturando cualquier llamada die() dentro de la referencia de código.

Devuelve "undef" si no se ejecutó ninguna llamada die() y $@ no estaba establecido, o el valor de $@ si estaba establecido. (El evento de tiempo de espera no cuenta como un die().)

$t->timed_out()
Devuelve 1 si el código más reciente ejecutado en run() agotó el tiempo de espera, o "undef" si no lo hizo.
$t->reset()
Si se llama dentro de una referencia de código run(), hace que el temporizador de alarma actual se restaure a su configuración original (útil después de que nuestra configuración de alarma haya sido sobrescrita por algún módulo subyacente).
