Mail::SPF::Server(3) Documentación de contribuciones de Perl Mail::SPF::Server(3)

Nombre

Mail::SPF::Server - Clase de servidor para procesar solicitudes SPF

VERSIÓN

versión 3.20250505

SINTAXIS

use Mail::SPF;
my $spf_server  = Mail::SPF::Server->new(
    # Opciones por defecto para la explicación de autoridad:
    default_authority_explanation =>
        'Rechazado por el registro SPF.'

DESCRIPCIÓN

Mail::SPF::Server es una clase de servidor para procesar solicitudes SPF. Cada instanciade servidor puede configurarse con parámetros específicos de procesamiento. Además, el resolutor DNS por defecto Net::DNS::Resolver utilizado para hacer búsquedas DNS puede ser reemplazado con un objeto resolutor personalizado.

Constructor

El siguiente constructor se proporciona:

new(%opciones): devuelve Mail::SPF::Server
Creación de una nueva instancia de objeto servidor para procesar solicitudes SPF.

%opciones es una lista de pares clave-valor que representan cualquiera de las siguientes opciones:

default_authority_explanation
Una cadena que denota la explicación de autoridad por defecto (no expandida por macro) que se utilizará si el dominio de autoridad no especifica una cadena de explicación propia. El valor por defecto es: 
'Rechazado por el registro SPF.'

Como se puede ver en el valor por defecto, se soporta un pseudo-macro _scope que se expande en el nombre del ámbito de la identidad. (Nota: No se deben usar macros no estándar en las explicaciones publicadas en DNS.)

hostname
Una cadena que denota el nombre completo del host del sistema que se utilizará para expandir el macro "r" en las explicaciones. El valor por defecto es el nombre del host del sistema configurado.
dns_resolver
Un objeto resolutor DNS opcional. Si no se especifica, se utiliza un nuevo objeto Net::DNS::Resolver. El objeto resolutor puede ser de una clase diferente, pero debe proporcionar una interfaz similar a la de Net::DNS::Resolver — al menos, deben estar disponibles los métodos "send" y "errorstring", y el método "send" debe devolver bien un objeto de clase Net::DNS::Packet, o, en caso de error, undef.
query_rr_types
Tipos de RR a buscar cuando se realizan búsquedas y se seleccionan registros SPF. Los siguientes valores son admitidos:
Mail::SPF::Server->query_rr_type_all
Tipos de RR "TXT" y "SPF".
Mail::SPF::Server->query_rr_type_txt (por defecto)
Solo tipos de RR "TXT".
Mail::SPF::Server->query_rr_type_spf
Solo tipos de RR "SPF".

Hace años Mail::SPF solía buscar por defecto los tipos de RR "SPF" y "TXT", como lo recomienda RFC 4408. La experiencia ha demostrado que una gran parte de los servidores de nombres sufren de daño cerebral severo con respecto al manejo de consultas de tipos de RR desconocidos, como el tipo de RR "SPF". Por esta razón, Mail::SPF ahora busca por defecto solo tipos de RR "TXT". Esto puede ser reemplazado con la opción query_rr_types.

Ver RFC 4408, 3.1.1, para una discusión sobre el tema, así como la descripción del método "select_record".

max_dns_interactive_terms
Un entero que denota el número máximo de términos (mecanismos y modificadores) por cada verificación SPF que realiza búsquedas DNS, según RFC 4408, 10.1, párrafo 6. Si se especifica undef, no hay límite en el número de dichos términos. El valor por defecto es 10, que es el valor definido en RFC 4408.

Un valor mayor que el valor por defecto se desaconseja fuertemente por razones de seguridad. Un valor menor tiene implicaciones con respecto a la previsibilidad de los resultados de SPF. ¡Solo deberías cambiar el valor por defecto si sabes lo que estás haciendo!

max_name_lookups_per_term
Un entero que denota el número máximo de búsquedas DNS por término (mecanismo o modificador), según RFC 4408, 10.1, párrafo 7. Si se especifica undef, no hay límite en el número de búsquedas realizadas. El valor por defecto es 10, que es el valor definido en RFC 4408.

Un valor mayor que el valor por defecto se desaconseja fuertemente por razones de seguridad. Un valor menor tiene implicaciones con respecto a la previsibilidad de los resultados de SPF. ¡Solo deberías cambiar el valor por defecto si sabes lo que estás haciendo!

max_name_lookups_per_mx_mech
max_name_lookups_per_ptr_mech
Un entero que denota el número máximo de búsquedas DNS por mecanismo mx o ptr. El valor por defecto es el valor de la opción "max_name_lookups_per_term". Ver allí para más información y notas de seguridad.
max_void_dns_lookups
Un entero que denota el número máximo de búsquedas DNS "void" por cada verificación SPF, es decir, el número de búsquedas DNS causadas por búsquedas interactivas de tipo RR y macros (tal como se define en RFC 4408, 10.1, párrafos 6 y 7) y que pueden devolver una respuesta vacía con RCODE 0 o RCODE 3 ("NXDOMAIN") antes de que el proceso sea abortado con un resultado de "permerror". Si se especifica undef, no hay un límite más estricto que los límites normales de procesamiento. El valor por defecto es 2.

Específicamente, las búsquedas DNS sujetas a este límite son aquellas causadas por los mecanismos "a", "mx", "ptr" y "exists" y el macro "p".

Un valor de 2 es probable que evite ataques efectivos contra dominios de víctimas de terceros. Sin embargo, un límite definido puede causar resultados de "permerror" incluso con políticas de remitentes inofensivas (muy complejas) donde normalmente se devolverían resultados útiles.

Métodos de clase

Los siguientes métodos de clase se proporcionan:

result_class: devuelve clase
result_class($nombre): devuelve clase
Devuelve una clase descendiente de Mail::SPF::Result determinada a partir del nombre de resultado dado, a través de la clase base de resultados del servidor, o devuelve la clase base de resultados del servidor si no se proporciona un nombre de resultado. Este método también puede utilizarse como un método de instancia.

Nota: No escribas código que invoque métodos de clase en nombres de clases de resultado literales, ya que esto ignoraría cualquier clase derivada de resultado proporcionada por Mail::SPF.

NAME

Mail::SPF::Server - SPF server implementation

SYNOPSIS

 use Mail::SPF;
 use Mail::SPF::Server;
 use Mail::SPF::Request;
 use Mail::SPF::Result;
 my $server = Mail::SPF::Server->new( ... );
 my $request = Mail::SPF::Request->new( ... );
 my $result = $server->process($request);
 if ($result->is_pass) { ... }

DESCRIPTION

This class implements the server side of the SPF protocol as described in RFC 4408.

It is used to implement an SPF checking library, such as Mail::SPF itself.

Constructor

new(%options): returns Mail::SPF::Server
Creates and returns a new server object. The following options are supported:
default_authority_explanation => Mail::SPF::MacroString or string
The default authority explanation string, used when the "explanation" macro is used in an SPF record, but no such explanation is provided. The string is parsed as a Mail::SPF::MacroString object.
dns_resolver => Net::DNS::Resolver object
The DNS resolver object to use for DNS lookups. If omitted, a default resolver is created.
hostname => string
The host name of the local system, used for the "h" macro in SPF records. If omitted, the system's host name is determined using gethostbyname.
max_dns_interactive_terms => integer
The maximum number of DNS lookups allowed per SPF policy evaluation. Defaults to 10. See RFC 4408, 10.1.
max_name_lookups_per_mx_mech => integer
The maximum number of DNS name lookups allowed per invocation of the "mx" mechanism. Defaults to 2. See RFC 4408, 10.1.
max_name_lookups_per_ptr_mech => integer
The maximum number of DNS name lookups allowed per invocation of the "ptr" mechanism. Defaults to 10. See RFC 4408, 10.1.
max_name_lookups_per_term => integer
The maximum number of DNS name lookups allowed per SPF term (mechanism or modifier). Defaults to 2. See RFC 4408, 10.1.
max_void_dns_lookups => integer
The maximum number of "void" DNS lookups allowed per SPF policy evaluation. Defaults to 2. See RFC 4408, 10.1.
query_rr_types => integer
A bitmask determining which DNS RR types to query when looking for SPF records. Defaults to SPF_RR_TYPE_A | SPF_RR_TYPE_TXT, meaning that both SPF records (type 99) and TXT records are queried. Set to SPF_RR_TYPE_SPF to query only SPF records, or SPF_RR_TYPE_TXT to query only TXT records. (SPF_RR_TYPE_SPF and SPF_RR_TYPE_TXT are constants defined in Mail::SPF::Constants).

Class methods

A few utility methods are provided as class methods. These methods are generally intended for use by other Mail::SPF extension modules.

throw_result($name, $request): throws Mail::SPF::Result
throw_result($name, $request, $text): throws Mail::SPF::Result
Throws a Mail::SPF::Result descendant determined from the given result name via the server's inherent result base class, passing an optional result text and associating the given Mail::SPF::Request object with the result object. This method may also be used as an instance method.

Note: Do not write code invoking "throw" on literal result class names as this would ignore any derivative result classes provided by Mail::SPF extension modules.

Instance methods

The following instance methods are provided:

process($request): returns Mail::SPF::Result
Processes the given Mail::SPF::Request object, queries the authoritative domain for an SPF sender policy (see the description of the "select_record" method), evaluates the policy with regard to the given identity and other request parameters, and returns a Mail::SPF::Result object denoting the result of the policy evaluation. See RFC 4408, 4, and RFC 4406, 4, for details.
select_record($request): returns Mail::SPF::Record; throws Mail::SPF::EDNSError, Mail::SPF::ENoAcceptableRecord, Mail::SPF::ERedundantAcceptableRecords, Mail::SPF::ESyntaxError
Queries the authority domain of the given Mail::SPF::Request object for SPF sender policy records and, if multiple records are available, selects the record of the highest acceptable record version that covers the requested scope.

More precisely, the following algorithm is performed (assuming that both "TXT" and "SPF" RR types are being queried):

1.
Determine the authority domain, the set of acceptable SPF record versions, and the identity scope from the given request object.
2.
Query the authority domain for SPF records of the "SPF" DNS RR type, discarding any records that are of an inacceptable version or do not cover the desired scope.

If this yields no SPF records, query the authority domain for SPF records of the "TXT" DNS RR type, discarding any records that are of an inacceptable version or do not cover the desired scope.

If still no acceptable SPF records could be found, throw a Mail::SPF::ENoAcceptableRecord exception.

3.
Discard all records but those of the highest acceptable version found.

If exactly one record remains, return it. Otherwise, throw a Mail::SPF::ERedundantAcceptableRecords exception.

If the querying of either RR type has been disabled via the "new" constructor's "query_rr_types" option, the respective part in step 2 will be skipped.

Mail::SPF::EDNSError exceptions due to DNS look-ups and Mail::SPF::ESyntaxError exceptions due to invalid acceptable records may also be thrown.

get_acceptable_records_from_packet($packet, $rr_type, \@versions, $scope, $domain): returns list of Mail::SPF::Record
Filters from the given Net::DNS::Packet object all resource records of the given RR type and for the given domain name, discarding any records that are not SPF records at all, that are of an inacceptable SPF record version, or that do not cover the given scope. Returns a list of acceptable records.
dns_lookup($domain, $rr_type): returns Net::DNS::Packet; throws Mail::SPF::EDNSTimeout, Mail::SPF::EDNSError
Queries the DNS using the configured resolver for resource records of the desired type at the specified domain and returns a Net::DNS::Packet object if an answer packet was received. Throws a Mail::SPF::EDNSTimeout exception if a DNS time-out occurred. Throws a Mail::SPF::EDNSError exception if an error (other than RCODE 3 AKA "NXDOMAIN") occurred.
count_dns_interactive_term($request): throws Mail::SPF::EProcessingLimitExceeded
Increments by one the count of DNS-interactive mechanisms and modifiers that have been processed so far during the evaluation of the given Mail::SPF::Request object. If this exceeds the configured limit (see the "new" constructor's "max_dns_interactive_terms" option), throws a Mail::SPF::EProcessingLimitExceeded exception.

This method is supposed to be called by the "match" and "process" methods of Mail::SPF::Mech and Mail::SPF::Mod sub-classes before (and only if) they do any DNS look-ups.

count_void_dns_lookup($request): throws Mail::SPF::EProcessingLimitExceeded
Increments by one the count of "void" DNS look-ups that have occurred so far during the evaluation of the given Mail::SPF::Request object. If this exceeds the configured limit (see the "new" constructor's "max_void_dns_lookups" option), throws a Mail::SPF::EProcessingLimitExceeded exception.

This method is supposed to be called by any code after any calls to the "dns_lookup" method whenever (i) no answer records were returned, and (ii) this fact is a possible indication of a DoS attack against a third-party victim domain, and (iii) the number of "void" look-ups is not already constrained otherwise (as for example is the case with the "include" mechanism and the "redirect" modifier). Specifically, this applies to look-ups performed by the "a", "mx", "ptr", and "exists" mechanisms and the "p" macro.

default_authority_explanation: returns Mail::SPF::MacroString
Returns the default authority explanation as a MacroString object. See the description of the "new" constructor's "default_authority_explanation" option.
hostname: returns string
Returns the local system's host name. See the description of the "new" constructor's "hostname" option.
dns_resolver: returns Net::DNS::Resolver or compatible object
Returns the DNS resolver object of the server object. See the description of the "new" constructor's "dns_resolver" option.
query_rr_types: returns integer
Returns a value denoting the RR types for which to query when looking up and selecting SPF records. See the description of the "new" constructor's "query_rr_types" option.
max_dns_interactive_terms: returns integer
max_name_lookups_per_term: returns integer
max_name_lookups_per_mx_mech: returns integer
max_name_lookups_per_ptr_mech: returns integer
max_void_dns_lookups: returns integer
Return the limit values of the server object. See the description of the "new" constructor's corresponding options.
