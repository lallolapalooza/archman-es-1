Paquete: perl-mail-transport-dbx

Licencias: GPL, PerlArtistic

Dbx(3) Documentación de Perl contribuida por el usuario Dbx(3)

NOMBRE

Mail::Transport::Dbx - Analiza buzones de Outlook Express

SINOPSIS

use Mail::Transport::Dbx;
my $dbx = eval { Mail::Transport::Dbx->new("box.mbx") };
die $@ if $@;

for my $i (0 .. $dbx->msgcount - 1) {
    my $msg = $dbx->get($i);
    print $msg->subject;
    ...
}
# más conveniente
for my $msg ($dbx->emails) {
    print $msg->subject;
    ...
}

RESUMEN

Lee archivos dbx (archivos de buzón de Outlook Express)

DESCRIPCIÓN

Mail::Transport::Dbx te da acceso independiente de la plataforma a los archivos dbx de Outlook Express. Extrae subcarpetas, mensajes, etc. de ellos o úsalo para convertir archivos dbx a un formato más portable (como el formato mbox estándar).

Se basa en LibDBX para hacer su trabajo. La mala noticia: LibDBX no sabe nada sobre el endianness de tu máquina, por lo que no funciona en máquinas big-endian como Macintoshs o SUNs. La buena noticia: Hice los parches apropiados para que de hecho funcione incluso en máquinas con el orden de bytes 'equivocado' (excepción: las máquinas con un orden de bytes aún más extraño como las Cray no son compatibles; excepción a la excepción: Si me compras una Cray, prometo arreglarlo. :-).

Debes entender la estructura de los archivos .dbx para usar este módulo correctamente. Outlook Express guarda un par de estos archivos en tu disco duro. Por ejemplo:

Folders.dbx
folder1.dbx
comp.lang.perl.misc.dbx

Lo desagradable de eso es que en realidad hay dos tipos diferentes de tales archivos: uno que contiene los mensajes reales y otro que solo contiene referencias a otros archivos .dbx. Folders.dbx podría considerarse el archivo de nivel superior ya que lista todos los demás archivos .dbx disponibles. En cuanto a folder1.dbx y comp.lang.perl.misc.dbx, aún no puedes saber si contienen mensajes o subcarpetas (aunque comp.lang.perl.misc.dbx probablemente contiene mensajes de grupos de noticias que se tratan como simples correos electrónicos).

Afortunadamente, este módulo te da la información que necesitas. Un enfoque común sería el siguiente:

1) crear un nuevo objeto Mail::Transport::Dbx desde "Folders.dbx"

2) iterar sobre sus elementos usando el método get()
    2.1 si devuelve un Mail::Transport::Dbx::Email  
        => un mensaje
    2.2 si devuelve una Mail::Transport::Dbx::Folder 
        => una carpeta

3) si es mensaje
    3.1 llamar a cualquier método de Mail::Transport::Dbx::Email 
        que necesites

4) si es carpeta
    4.1 llamar a cualquier método de Mail::Transport::Dbx::Folder 
        que necesites
    O
    4.2 llamar a dbx() sobre él para crear un nuevo objeto Mail::Transport::Dbx 
        4.2.1 si dbx() devolvió algo definido
              => volver al punto 2)

Lo confuso es que los archivos .dbx pueden contener referencias a otras carpetas que no existen realmente. Si Outlook Express se usó como cliente de noticias, este es un escenario común ya que Folders.dbx lista todos los grupos de noticias como objetos separados de "Mail::Transport::Dbx::Folder" sin importar si estás suscrito a alguno de ellos o no. Así que, en esencia, llamar a dbx() en una carpeta solo devolverá un nuevo objeto si el archivo .dbx correspondiente existe.

MÉTODOS

Los siguientes son métodos para objetos de Mail::Transport::Dbx:

new(nombre_archivo)
new(referencia_a_manejador_de_archivo)
Pasado ya sea una cadena que sea el nombre del archivo o una referencia a un manejador de archivo ya abierto y legible, new() construirá un objeto Mail::Transport::Dbx a partir de él.

Esto ocurre independientemente de si abres un archivo dbx ordinario o el archivo especial Folders.dbx que contiene una vista general de todas las subcarpetas dbx disponibles.

Si la apertura falla por alguna razón, tu programa se die() instantáneamente, así que asegúrate de envolver el constructor en un eval() y verificar $@:

my $dbx = eval { Mail::Transport::Dbx->new( "file.dbx" ) };
die $@ if $@;

Ten cuidado al usar un manejador de archivo, sin embargo. En Windows, puede que necesites usar binmode() en tu manejador o de lo contrario el stream de tu archivo dbx podría corromperse.

msgcount
Devuelve el número de elementos almacenados en la estructura dbx. Si previamente abriste Folders.dbx, msgcount() devuelve el número de subcarpetas en él. De lo contrario, devuelve el número de mensajes. "msgcount() - 1" es el índice del último elemento.
emails
En contexto de lista, este método devuelve todos los correos electrónicos contenidos en el archivo. En contexto booleano (es decir, escalar) devuelve un valor verdadero si el archivo contiene correos electrónicos y falso si contiene subcarpetas. 
if ($dbx->emails) {
    print "Contiene correos electrónicos";
} else {
    print "Contiene subcarpetas";
}

Esto es útil para iteraciones:

for my $msg ($dbx->emails) {
    ...
}
subfolders
En contexto de lista, este método devuelve todas las subcarpetas del archivo actual como objetos de "Mail::Transport::Dbx::Folder". En contexto booleano (escalar) devuelve verdadero si el archivo contiene subcarpetas y falso si contiene correos electrónicos.

Recuerda que aún tienes que llamar a dbx() en estas subcarpetas si quieres hacer algo útil con ellas:

for my $sub ($dbx->subfolders) {
    if (my $d = $sub->dbx) {
        # $d ahora es un objeto Mail::Transport::Dbx adecuado 
        # con contenido
    } else {
        print "Carpeta secundaria referenciada pero inexistente";
    }
}
get(n)
Obtiene el elemento en la n-ésima posición. El primer elemento está en la posición 0. get() es en realidad un método de fábrica, por lo que devuelve un objeto "Mail::Transport::Dbx::Email" o "Mail::Transport::Dbx::Folder". Esto depende de la carpeta en la que llames a este método: 
my $dbx  = Mail::Transport::Dbx->new( "Folders.dbx" );
my $item = $dbx->get(0);

$item ahora será definitivamente un objeto "Mail::Transport::Dbx::Folder" ya que Folders.dbx no contiene correos electrónicos sino referencias a subcarpetas.

Puedes usar los métodos is_email() e is_folder() para verificar su tipo:

if ($item->is_email) {
    print $item->subject;
} else {
    # es una subcarpeta
    ...
}

En caso de error, este método devuelve un valor indefinido. Verifica "$dbx->errstr" para averiguar qué salió mal.

errstr
Siempre que ocurre un error, errstr() contendrá una cadena que te dará más ayuda sobre qué salió mal.

ADVERTENCIA: Internamente se basa en una variable global, por lo que todos los objetos tendrán la misma cadena de error. Eso significa que solo tiene sentido usarla después de una operación que potencialmente genera un error:

# ejemplo 1
my $dbx = Mail::Transport::Dbx->new("box.dbx")
    or die Mail::Transport::Dbx->errstr;
# ejemplo 2
my $msg = $dbx->get(5) or print $dbx->errstr;
error
Similar a errstr(), solo que devolverá un código de error. Consulta "Constantes exportables/Códigos de error" bajo "EXPORT" para ver los códigos que se pueden devolver.

Los siguientes son los métodos para objetos de Mail::Transport::Dbx::Email:

as_string
Devuelve todo el mensaje (encabezado y cuerpo) como una cadena grande.

my $email = $msg->as_string;
$email =~ s/\015\012/\n/g;

METHODS

as_string
Returns the whole email as a string.

Note that newlines are not always rendered in the same way. This depends on how the email was stored. If you want to be sure that you always get the same output, you should normalize the newlines yourself, e.g. by using s/\cM\cJ/\n/g or s/\cM/\n/g.

For a news-article this method may return "undef". This always happens when the particular articles was only partially downloaded (that is, only header retrieved from the newsserver). There is no way to retrieve this header literally with "header". Methods like "subject" etc. however do work.

header
Returns the header-portion of the whole email.

With respect to newlines the same as described under as_string() applies.

Returns "undef" under the same circumstances as "as_string".

body
Returns the body-portion of the whole email.

With respect to newlines the same as described under as_string() applies.

Returns "undef" under the same circumstances as "as_string".

subject
Returns the subject of the email as a string.
psubject
Returns the processed subject of the email as a string. 'Processed' means that additions such as "Re:" etc. are cut off.
msgid
Returns the message-id of the message as a string.
parents_ids
Returns the message-ids of the parent messages as a string.
sender_name
Returns the name of the sender of this email as a string.
sender_address
Returns the address of the sender of this email as a string.
recip_name
Returns the name of the recipient of this email as a string. This might be your name. ;-)
recip_address
Returns the address of the recipient of this email as a string.
oe_account_name
Returns the Outlook Express account name this message was retrieved with as a string.
oe_account_num
Outlook Express accounts also seem to have a numerical representation. This method will return this as a string (something like "0000001").
fetched_server
Returns the name of the POP server that this message was retrieved from as a string.
rcvd_localtime
This is the exact duplicate of Perl's builtin localtime() applied to the date this message was received. It returns a string in scalar context and a list with nine elements in list context. See 'perldoc -f localtime' for details.
rcvd_gmtime
Same as rcvd_localtime() but returning a date conforming to GMT.
date_received( [format, [len, [gmtime]]] )
This method returns the date this message was received by you as a string. The date returned is calculated according to localtime().

Without additional arguments, the string returned looks something like

Sun Apr 14 02:27:57 2002

The optional first argument is a string describing the format of the date line. It is passed unchanged to strftime(3). Please consult your system's documentation for strftime(3) to see how such a string has to look like. The default string to render the date is "%a %b %e %H:%M:%S %Y".

The optional second argument is the max string length to be returned by date_received(). This parameter is also passed unaltered to strftime(). This method uses 25 as default

The third argument can be set to a true value if you rather want to get a date in GMT. So if you want to get the GMT of the date but want to use the default rendering settings, you will have to provide them yourself:

print $msg->date_received("%a %b %e %H:%M:%S %Y", 25, 1);
is_seen
Returns a true value if this message has already been been seen. False otherwise.
is_email
Always returns true for this kind of object.
is_folder
Always returns false for this kind of object.

The following methods exist for Mail::Transport::Dbx::Folder objects:

dbx
This is a convenience method. It creates a "Mail::Transport::Dbx" object from the folder object. If the folder is only mentioned but not physically existing on your hard-drive (either because you deleted the .dbx file or it was actually never there which especially happens for newsgroup files) "dbx" returns an undefined value.

Please read "DESCRIPTION" again to learn why dbx() can return an undefined value.

num
The index number of this folder. This is the number you passed to "$dbx->get()" to retrieve this folder.
type
According to libdbx.h this returns one of "DBX_TYPE_FOLDER" or "DBX_TYPE_EMAIL". Use it to check whether the folder contains emails or other folders.
name
The name of the folder.
file
The filename of the folder. Use this, to create a new "Mail::Transport::Dbx" object: 
# $folder is a Mail::Transport::Dbx::Folder object
my $new_dbx = Mail::Transport::Dbx->new( $folder->file );

Consider using the dbx() method instead.

This method returns an undefined value if there is no .dbx file belonging to this folder.

id
Numerical id of the folder. Not sure what this is useful for.
parent_id
Numerical id of the parent's folder.
folder_path
Returns the full folder name of this folder as a list of path elements. It's then in your responsibility to join them together by using a delimiter that doesn't show up in any of the elements. ;-) 
print join("/", $_->folder_path), "\n" for $dbx->subfolders;
# could for instance produce a long list, such as:
Outlook Express/news.rwth-aachen.de/de.comp.software.announce
Outlook Express/news.rwth-aachen.de/de.comp.software.misc
...
Outlook Express/Lokale Ordner/test/test1
Outlook Express/Lokale Ordner/test
Outlook Express/Lokale Ordner/Entwürfe
Outlook Express/Lokale Ordner/Gelöschte Objekte
Outlook Express/Lokale Ordner/Gesendete Objekte
Outlook Express/Lokale Ordner/Postausgang
Outlook Express/Lokale Ordner/Posteingang
Outlook Express/Lokale Ordner
Outlook Express/Outlook Express

Note that a slash (as any other character) might not be a safe choice as it could show up in a folder name.

EXPORT

None by default.

Constantes exportables

Si tiene la intención de usar alguna de las siguientes constantes, debe importarlas al usar el módulo. Puede importarlas todas de una vez así:

use Mail::Transport::Dbx qw(:all);

O puede importar solo las que necesite:

use Mail::Transport::Dbx qw(DBX_TYPE_EMAIL DBX_TYPE_FOLDER);
Códigos de error
  • DBX_NOERROR

    No se produjo ningún error.

  • DBX_BADFILE

    La operación de archivo Dbx falló (abrir o cerrar)

  • DBX_DATA_READ

    La lectura de datos del archivo dbx falló

  • DBX_INDEXCOUNT

    Índice fuera de rango

  • DBX_INDEX_OVERREAD

    Se realizó una solicitud de referencia de índice mayor de la que existe

  • DBX_INDEX_UNDERREAD

    El número de índices leídos del archivo dbx es menor de lo esperado

  • DBX_INDEX_READ

    La lectura del puntero de índice del archivo dbx falló

  • DBX_ITEMCOUNT

    La lectura del recuento de elementos del archivo dbx falló

  • DBX_NEWS_ITEM

    El elemento es un artículo de noticias, no un correo electrónico

Tipos Dbx

ADVERTENCIAS

No puedes recuperar el estado interno de los objetos usando "Data::Dumper" o similar, ya que "Mail::Transport::Dbx" utiliza un escalar "bendecido" para mantener una referencia a las estructuras C correspondientes. Esto significa que debes usar los métodos proporcionados para cada objeto. Llama a eso encapsulación fuerte si necesitas un eufemismo.

Actualmente no hay planes para implementar acceso de escritura a archivos .dbx. Dejo eso a los autores de libdbx.
