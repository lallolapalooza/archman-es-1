Mail::SpamAssassin::Plugin::URIDNSBL(3) Documentación de Perl contribuida por el usuario Mail::SpamAssassin::Plugin::URIDNSBL(3)

NOMBRE

URIDNSBL - busca URLs contra listas negras de DNS

SINOPSIS

loadplugin    Mail::SpamAssassin::Plugin::URIDNSBL
uridnsbl      URIBL_SBLXBL    sbl-xbl.spamhaus.org.   TXT

DESCRIPCIÓN

Esto funciona analizando el texto y el HTML de los mensajes en busca de URLs, extrayendo los nombres de host de ellas, y luego consultando varias listas negras de DNS para: direcciones IP de estos hosts (uridnsbl,a) o sus servidores de nombres (uridnsbl,ns), o nombres de dominio de estos hosts (urirhsbl), o nombres de dominio de sus servidores de nombres (urinsrhsbl, urifullnsrhsbl).

CONFIGURACIÓN DEL USUARIO

skip_uribl_checks ( 0 | 1 ) (por defecto: 0)
Activar la configuración skip_uribl_checks deshabilitará el plugin URIDNSBL.

Por defecto, SpamAssassin realizará comprobaciones URIDNSBL. Las listas negras de URI individuales pueden deshabilitarse selectivamente estableciendo la puntuación de una regla correspondiente a 0 o a través del parámetro uridnsbl_skip_domain.

Ver también el parámetro de configuración relacionado skip_rbl_checks, que controla el plugin DNSEval (documentado en la página del manual de Conf).

uridnsbl_skip_domain dominio1 dominio2 ...
Especifica un dominio o varios dominios que deben omitirse en las comprobaciones de URIBL. Esto es muy útil para especificar dominios muy comunes que no aparecerán en las URIBL.

Además del dominio recortado, también se comprueba el nombre de host completo de la lista.

clear_uridnsbl_skip_domain [dominio1 dominio2 ...]
Si no se proporciona ningún argumento, borra toda la lista de dominios declarados hasta el momento por las directivas de configuración uridnsbl_skip_domain. Cualquier directiva uridnsbl_skip_domain posterior comenzará a crear una nueva lista de dominios omitidos.

Cuando se proporciona una lista de dominios como argumentos, solo se eliminan los dominios especificados de la lista de dominios omitidos.

DEFINICIONES DE REGLAS Y CONFIGURACIÓN PRIVILEGIADA

uridnsbl NOMBRE_DE_LA_REGLA zona_dnsbl tipo_de_búsqueda
Especifica una búsqueda. "NOMBRE_DE_LA_REGLA" es el nombre de la regla a utilizar, "zona_dnsbl" es la zona en la que buscar IPs, y "tipo_de_búsqueda" es el tipo de búsqueda (TXT o A). Tenga en cuenta que también debe definir una regla de evaluación de cuerpo que llame a check_uridnsbl() para utilizar esto.

Esto funciona recopilando nombres de dominio de las URLs y consultando listas negras de DNS con una dirección IP de los nombres de host encontrados en las URLs o con las direcciones IP de sus servidores de nombres, de acuerdo con las tflags siguientes:

Si la regla de cuerpo correspondiente tiene una tflag 'a', la lista negra de DNS se consultará con una dirección IP de un host encontrado en las URLs.

Si la regla de cuerpo correspondiente tiene una tflag 'ns', se consultará el DNS para los servidores de nombres (registros NS) de un nombre de dominio encontrado en las URLs, luego estos nombres de servidor de nombres se resolverán a sus direcciones IP, que a su vez se enviarán a la lista negra de DNS.

Las directivas Tflags pueden especificar 'a' o 'ns' o ambas. En ausencia de cualquiera de estas dos banderas, el valor predeterminado es 'ns', que es compatible con las versiones anteriores a la 3.4 de SpamAssassin.

La elección de tflags debe corresponder a la política y el uso esperado de cada lista negra de DNS y normalmente no es una decisión local. Como ejemplo, una lista negra que espera consultas resultantes de una tflag 'a' es una "black_a.txt" ( http://www.uribl.com/datasets.shtml ).

Ejemplo:

uridnsbl        URIBL_SBLXBL    sbl-xbl.spamhaus.org.   TXT
body            URIBL_SBLXBL    eval:check_uridnsbl('URIBL_SBLXBL')
describe        URIBL_SBLXBL    Contiene una URL listada en la lista negra SBL/XBL
tflags          URIBL_SBLXBL    net ns
uridnssub NOMBRE_DE_LA_REGLA zona_dnsbl tipo_de_búsqueda subtest
Especifica una búsqueda de dominio de estilo DNSBL con una subprueba. "NOMBRE_DE_LA_REGLA" es el nombre de la regla a utilizar, "zona_dnsbl" es la zona en la que buscar IPs y "tipo_de_búsqueda" es el tipo de búsqueda (TXT o A).

Las tflags 'ns' y 'a' en una regla de cuerpo correspondiente se reconocen y tienen el mismo significado que en la directiva uridnsbl.

"subtest" es una subprueba a realizar sobre los datos devueltos. La subprueba puede tener una de las siguientes formas: m, n1-n2, o n/m, donde n,n1,n2,m pueden ser: dígitos decimales, 0x seguido de hasta 8 dígitos hexadecimales, o una dirección IPv4 en formato quad-dot. Los registros 'A' (dirección IPv4 punto-punto) devueltos por las búsquedas DNSBL se convierten a un formato numérico (r) y se comparan con la subprueba especificada de la siguiente manera: para un rango n1-n2, lo siguiente debe ser verdadero: (r >= n1 && r <= n3); para una forma n/m, lo siguiente debe ser verdadero: (r & m) == (n & m); para un valor único en formato quad-dot, lo siguiente debe ser verdadero: r == n; para un único valor decimal o hexadecimal, lo siguiente debe ser verdadero:
((r & n) != 0) && ((r & 0xff000000) == 0x7f000000), es decir, dentro de 127.0.0.0/8

Algunos ejemplos típicos de una subprueba son: 127.0.1.2, 127.0.1.20-127.0.1.39, 127.0.1.0/255.255.255.0, 0.0.0.16/0.0.0.16, 0x10/0x10, 16, 0x10.

Tenga en cuenta que, al igual que con "uridnsbl", también debe definir una regla de evaluación de cuerpo que llame a check_uridnsbl() para utilizar esto.

Ejemplo:

uridnssub   URIBL_DNSBL_4    dnsbl.example.org.   A    127.0.0.4
uridnssub   URIBL_DNSBL_8    dnsbl.example.org.   A    8
urirhsbl NOMBRE_DE_LA_REGLA zona_rhsbl tipo_de_búsqueda
Especifica una búsqueda de dominio de estilo RHSBL. "NOMBRE_DE_LA_REGLA" es el nombre de la regla a utilizar, "zona_rhsbl" es la zona en la que buscar nombres de dominio y "tipo_de_búsqueda" es el tipo de búsqueda (TXT o A). Tenga en cuenta que también debe definir una regla de evaluación de cuerpo que llame a check_uridnsbl() para utilizar esto.

Una zona RHSBL es aquella en la que se busca el nombre de dominio, como una cadena de texto; por ejemplo, una URI que utiliza el dominio "foo.com" provocará una búsqueda de "foo.com.uriblzone.net". Tenga en cuenta que los nombres de host se recortan a la porción de dominio en la búsqueda URIBL, por lo que el dominio "foo.bar.com" buscará "bar.com.uriblzone.net", y "foo.bar.co.uk" buscará "bar.co.uk.uriblzone.net". El uso de la tflag "notrim" forzará la búsqueda del nombre de host completo, pero la uribl específica debe admitir este método.

Si una URI consiste en una dirección IP en lugar de un nombre de host, la dirección IP se busca (utilizando el método estándar de cuádruples invertidos) en cada "zona_rhsbl".

Ejemplo:

urirhsbl        URIBL_RHSBL    rhsbl.example.org.   TXT
urirhssub NOMBRE_DE_LA_REGLA zona_rhsbl tipo_de_búsqueda subtest
Especifica una búsqueda de dominio de estilo RHSBL con una subprueba. "NOMBRE_DE_LA_REGLA" es el nombre de la regla a utilizar, "zona_rhsbl" es la zona en la que buscar nombres de dominio y "tipo_de_búsqueda" es el tipo de búsqueda (TXT o A).

"subtest" es una subprueba a realizar sobre los datos devueltos. La subprueba puede tener una de las siguientes formas: m, n1-n2, o n/m, donde n,n1,n2,m pueden ser: dígitos decimales, 0x seguido de hasta 8 dígitos hexadecimales, o una dirección IPv4 en formato quad-dot. Los registros 'A' (dirección IPv4 punto-punto) devueltos por las búsquedas DNSBL se convierten a un formato numérico (r) y se comparan con la subprueba especificada de la siguiente manera: para un rango n1-n2, lo siguiente debe ser verdadero: (r >= n1 && r <= n3); para una forma n/m, lo siguiente debe ser verdadero: (r & m) == (n & m); para un valor único en formato quad-dot, lo siguiente debe ser verdadero: r == n; para un único valor decimal o hexadecimal, lo siguiente debe ser verdadero:

Tenga en cuenta que, al igual que con "urirhsbl", también debe definir una regla de evaluación de cuerpo que llame a check_uridnsbl() para utilizar esto.

Ejemplo:

urirhssub    URIBL_RHSBL_BAD    rhsbl.example.org.   TXT    bad.target.com
check_uridnsbl(NAME_OF_RULE)
Realiza la búsqueda DNSBL especificada por la regla NAME_OF_RULE.

NOMBRE

uridnsbl_name NOMBRE_DE_REGLA rhsbl_zone tipo_de_consulta
Realiza una consulta de dominio estilo RHSBL contra el contenido de los registros NS para cada URI. En otras palabras, una URI que usa el dominio "foo.com" provocará una consulta NS; asumiendo que ese dominio tiene un NS de "ns0.bar.com", eso provocará una consulta de "bar.com.uriblzone.net". Nota que los nombres de host se eliminan tanto del dominio usado en la URI como del dominio en la consulta.

El número máximo de dominios a consultar.

Incluir URIs DKIM en las consultas. Esta opción está documentada en Mail::SpamAssassin::Conf.
uridnsbl_skip_mailto ( 0 / 1) (por defecto: 1)
Omitir enlaces mailto en las consultas de URIs.
