Mail::SpamAssassin::Plugin::URIDetail(3) Documentación de Perl aportada por el usuario Mail::SpamAssassin::Plugin::URIDetail(3)

NOMBRE

URIDetail - prueba URIs usando información detallada de URI

SINOPSIS

Este plugin crea un nuevo tipo de prueba de regla, conocido como "uri_detail". Estas reglas se aplican a todas las URIs encontradas en el mensaje.

loadplugin    Mail::SpamAssassin::Plugin::URIDetail

DEFINICIONES DE REGLAS Y CONFIGURACIONES PRIVILEGIADAS

El formato para definir una regla es el siguiente:

uri_detail SYMBOLIC_TEST_NAME key1 =~ /value1/i  key2 !~ /value2/ ...

Las claves compatibles son:

"raw" es la URI sin procesar antes de cualquier limpieza (por ejemplo, "http://spamassassin.apache%2Eorg/").

"type" es la(s) etiqueta(s) que referenciaron la raw_uri. parsed es un tipo simulado que especifica que la raw_uri fue analizada a partir del texto renderizado.

"cleaned" es una lista que incluye la URI sin procesar y varias versiones limpiadas de la URI sin procesar (http://spamassassin.apache%2Eorg/, https://spamassassin.apache.org/).

"text" es el texto(s) de anclaje (texto entre <a> y </a>) que enlazaron a la URI sin procesar.

"domain" es el(los) dominio(s) encontrados en las URIs limpiadas, recortado hasta el límite del registrador por Mail::SpamAssassin::Util::RegistrarBoundaries(3).

"host" es el(los) host(s) completo(s) en las URIs limpiadas. (Compatible desde SA 3.4.5)

Ejemplo de regla para coincidir con una URI donde la URI sin procesar coincide con "%2Ebar", se encuentra el dominio "bar.com" y el tipo es "a" (una etiqueta de ancla).

uri_detail TEST1 raw =~ /%2Ebar/  domain =~ /^bar\.com$/  type =~ /^a$/

Ejemplo de regla para buscar enlaces sospechosos de "https":

uri_detail FAKE_HTTPS text =~ /\bhttps:/  cleaned !~ /\bhttps:/

Las expresiones regulares deben delimitarse con barras.
