Mail::Message::Construct::Reply(3) Documentación aportada por usuarios de Perl Mail::Message::Construct::Reply(3)

NOMBRE

Mail::Message::Construct::Reply - responder a un mensaje de Mail::Message

SINTAXIS

my Mail::Message $reply = $message->reply;
my $quoted  = $message->replyPrelude($head->get('From'));

DESCRIPCIÓN

La funcionalidad compleja de los objetos Mail::Message se implementa en diferentes archivos que se cargan automáticamente. Este archivo implementa la funcionalidad relacionada con la creación de mensajes de respuesta.

MÉTODOS

Creador de mensaje

$obj->reply(%options)
Empieza a responder a este mensaje. Algunas de las líneas de cabecera de este mensaje se tomarán. Se asignará un message-id. Algunas líneas de cabecera se actualizarán para facilitar la detección de mensajes de discusión (véase Mail::Box::Thread::Manager).

Puedes responder a un mensaje completo o a un fragmento de mensaje. Puedes desechar algunas de las configuraciones por defecto para el mensaje de respuesta inmediatamente, o puedes hacerlo más tarde con "set" en la cabecera.

Las direcciones de correo pueden especificarse como string, o como objeto Mail::Address, o como un array de objetos Mail::Address.

Todas las %options que no se enumeran a continuación y que empiecen con una letra mayúscula, se añadirán como cabeceras adicionales a este mensaje de respuesta.

-Opción         --Predeterminado
 Bcc              undef
 Cc               <'cc' en el actual>
 From             <'to' en el actual>
 Message-ID       <generado de forma única>
 Subject          replySubject()
 To               <'remitente en el actual>
 body             undef
 group_reply      true
 include          'INLINE'
 max_signature    10
 message_type     Mail::Message
 postlude         undef
 prelude          undef
 quote            '> '
 signature        undef
 strip_signature  qr/^--\s/
Bcc => DIRECCIONES
Destinatarios de copia oculta: sus nombres no se publicarán a otros destinatarios de mensajes.
Cc => DIRECCIONES
Los destinatarios de copia oculta, por defecto una copia de la cabecera "Cc" del mensaje original.
From => DIRECCIONES
Identificación de ti, por defecto tomada de la cabecera "To" del mensaje original.
Message-ID => CADENA
Ofrece una CADENA como ID de mensaje específico para la respuesta. Por defecto, se genera uno para ti. Si no hay corchetes alrededor de tu ID, se añadirán.
Subject => CADENA|FUNCIÓN
Imprime el asunto como CADENA, o como resultado de la subrutina especificada por FUNCIÓN. La subrutina se llama pasando el asunto del mensaje original como único argumento. Por defecto, se utiliza Mail::Message::replySubject()
To => DIRECCIONES
El destino de tu mensaje. Por defecto tomado de la cabecera "Reply-To" del mensaje original. Si esa cabecera no está presente, se escanea la línea "From". Si ambas fallan, se devuelve undef: no se genera un mensaje de respuesta.
body => CUERPO
Generalmente, el método reply puede crear un mensaje agradable y suficiente de los cuerpos del mensaje original. En caso de que quieras una reformatción más complicada, puedes crear un cuerpo tú mismo primero y pasarlo a este método "reply". Algunas de las otras opciones a este método se ignoran en este caso.
group_reply => BOOLEANO
¿Los usuarios listados en la cabecera "Cc" (aquellos que recibieron el mensaje al que se responde ahora) también recibirán este mensaje como copia oculta?
include => 'NO'|'INLINE'|'ATTACH'
¿Debe ser incluido este mensaje en el mensaje? Si "NO", no. Con "INLINE" se compone un cuerpo de respuesta. "ATTACH" crea un cuerpo multijerárquico, donde el mensaje original se añade después del cuerpo especificado. Solo se pueden incluir mensajes de texto, por lo que los mensajes binarios o multipart se almacenarán como adjuntos.
max_signature => ENTERO
Se pasa a "stripSignature" en el cuerpo como parámetro "max_lines". Solo efectivo para mensajes de una sola parte.
message_type => CLASE
Crear un mensaje con el tipo solicitado. Por defecto, será un Mail::Message. Esto es correcto, porque cuando se agrega este mensaje a esa carpeta, se convertirá en el tipo de mensaje correcto de la carpeta.
postlude => CUERPO|LÍNEAS
Las líneas (solo una o varias) que se añaden después de las líneas de respuesta citadas. Crea un cuerpo primero. Esto no debe incluir la firma, que tiene su propia opción. La firma se añade después del postlude cuando el mensaje está en INLINE.
prelude => CUERPO|LÍNEAS
Las líneas (solo una o varias) que se añaden antes de las líneas de respuesta citadas. Si nada se especifica, el resultado del método replyPrelude() se usa. Cuando "undef" se especifica, no se añade un prelude.
quote => FUNCIÓN|CADENA
Modifica las líneas de una respuesta "INLINE" con FUNCIÓN, o anteponiendo una CADENA a cada línea. La rutina especificada por FUNCIÓN se llama cuando la línea está en $_.

Por defecto, se agrega '> ' antes de cada línea. Especifica undef para desactivar la cita. Esta opción se procesa después de que el cuerpo haya sido descrito.

signature => CUERPO|MENSAJE
La firma que se añade en caso de una respuesta multijerárquica. El tipo de mime del cuerpo de la firma debe indicar que se usa así. Sin embargo, en modo INLINE, el cuerpo se tomará, se añadirá una línea con '-- ' antes de él, y se añadirá tras la epígrafe.
strip_signature => REGEXP|CADENA|FUNCIÓN
Elimina la firma del emisor. El valor de esta opción se pasa a "stripSignature" en el cuerpo como parámetro "max_lines". Solo efectivo para mensajes de una sola parte.

Cuando se encuentra un cuerpo multijerárquico y el mensaje se incluye en ATTACH, las partes que parezcan firmas se eliminarán. Si solo queda un mensaje, se añadirá como adjunto único, de lo contrario se genera un multipart. El valor de esta opción no importa, siempre que esté presente. Véase Mail::Message::Body::Multipart.

» ejemplo:

my $reply = $msg->reply(
  prelude         => "No spam, please!\n\n",
  postlude        => "\nGreetings\n",
  strip_signature => 1,
  signature       => $my_pgp_key,
  group_reply     => 1,
  'X-Extra'       => 'additional header',
);
$obj->replyPrelude( [CADENA|$field|$address|ARRAY-de-cosas] )
Produce una lista de líneas (normalmente solo una), que se anteponen al cuerpo citado del mensaje. "CADENA" debe cumplir con la especificación RFC822 de direcciones de correo, y suele ser el contenido de una cabecera "To" o "From". Si se especifica un $field, el cuerpo del campo debe cumplir con la especificación. Sin argumento - o cuando el argumento es "undef" - se produce una línea ligeramente diferente.

Un ejemplo característico de la salida es:

my $prelude = $msg->replyPrelude(
      'From' => $user,
    );
    print $prelude;

crear un asunto para un mensaje que sea una respuesta a este uno. Esta rutina intenta contar el nivel de respuesta en el campo de asunto y transformarlo en un formato estándar. Por favor, contribuya mejoras.

» ejemplo:

subject                 --> Re: subject
Re: subject             --> Re[2]: subject
Re[X]: subject          --> Re[X+1]: subject

subject (Forw)          --> Re[2]: subject

DIAGNÓSTICOS

Error: No se puede incluir fuente de respuesta como $include.
Alternativa desconocida para la opción "include" de reply(). Las opciones válidas son "NO", "INLINE" y "ATTACH". Convertido por reply()
