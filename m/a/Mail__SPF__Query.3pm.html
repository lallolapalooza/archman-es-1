NOMBRE

Mail::SPF::Query - Consulta el sistema de políticas de envío (SPF) para un IP, email, HELO

VERSIÓN

1.999.1

SINOPSIS

my $query = new Mail::SPF::Query (ip => "127.0.0.1", sender=>'foo@example.com', helo=>"somehost.example.com", trusted=>0, guess=>0);
my ($result,           # pass | fail | softfail | neutral | none | error | unknown [mechanism]
    $smtp_comment,     # "please see http://www.openspf.org/why.html?..."  when rejecting, return this string to the SMTP client
    $header_comment,   # prepend_header("Received-SPF" => "$result ($header_comment)")
    $spf_record,       # "v=spf1 ..." original SPF record for the domain
   ) = $query->result();
if    ($result eq "pass") { "Domain es no falsificado. Aplicar RHSBL y filtros de contenido." }
elsif ($result eq "fail") { "Domain es falsificado. Rechazar o guardar en spambox." }

RESUMEN

El protocolo SPF depende de dominios de envío para describir sus remitentes designados en DNS. Dada una dirección de correo, Mail::SPF::Query determina la legitimidad de un IP del cliente SMTP.

DESCRIPCIÓN

Hay dos formas de usar Mail::SPF::Query. Tu elección depende de si el dominio que tu servidor es MX para tiene secondary MXes que tu servidor no conoce.

La primera y más común forma, llamando result(), es adecuada cuando todo el correo es recibido directamente desde el originador de MTA. Si los dominios que recibes no tienen secondary MXes, esta forma es adecuada. Esta forma se describe en el SYNOPSIS arriba. Esta es la situación común.

La segunda forma es más compleja, pero funciona cuando tu servidor recibe correo de secondary MXes. Esta realiza chequeos al manejar cada destinatario. Si el mensaje viene de un válido MX secondary para un destinatario, entonces el SPF check no se realiza, y se devuelve un pass inmediatamente. Para hacer esto, llama result2() y message_result2() en lugar de result().

Si no conoces qué es un secondary MX, probablemente no tengas uno. Usa la primera forma.

Puedes probar Mail::SPF::Query en la línea de comandos con el siguiente comando:

perl -MMail::SPF::Query -le 'print for Mail::SPF::Query->new(
    helo => shift, ipv4 => shift, sender => shift)->result' \
    helohost.example.com 1.2.3.4 user@example.com

ERRORES

Mail::SPF::Query intenta implementar el esquema SPF (ver "SEE ALSO") tan cerca como sea posible dada que M:S:Q ha sido la primera implementación de SPF y ha cambiado con el esquema SPF a lo largo del tiempo. Como resultado, M:S:Q tiene diversos defectos conocidos que no pueden ser corregidos con un esfuerzo razonable:

  • No se puede consultar separadamente HELO y MAIL FROM. M:S:Q no está diseñado para soportar la consulta separada de las identidades HELO y MAIL FROM. Pasar la identidad HELO como el argumento "sender" para un chequeo HELO puede generalmente funcionar pero podría producir resultados inesperados.
  • Sin soporte para IPv6. IPv6 no está soportado. Las mecánicas "ip6" en los registros SPF y en todo el resto son simplemente ignoradas.
  • El explicación de resultados puede no ser adecuada para resultados de política local. Si el resultado fue causado por algo otros que un registro SPF real (es decir, política local, sobrescripciones, etc.), y no se especificó un valor "default_explanation" personalizado, el comentario de dominio o el explicación de M:S:Q por defecto será devuelto. Ten en cuenta que en este caso, el comentario puede no explicar correctamente la razón para tal resultado artificial.

CARACTERÍSTICAS NO ESTÁNDAR

De su larga historia, M:S:Q tiene algunas características antiguas que no son parte del esquema oficial SPF, principalmente procesamiento de mejor suposición y verificación de credenciales de forwarders confiables. Por favor, ten cuidado cuando uses estas características no estándar o cuando reproduzcaslas en tu propia implementación de SPF, ya que pueden producir resultados inesperados.

MÉTODOS

"Mail::SPF::Query->new()"

my $query = eval { new Mail::SPF::Query (
    ip          => '127.0.0.1',
    sender      => 'foo@example.com',
    helo        => 'host.example.com',
    # Parámetros opcionales:
    debug       => 1, debuglog => sub { print STDERR "@_\n" },
    local       => 'extra mechanisms',
    trusted     => 1,                   # procesamiento de forwarders confiables
    guess       => 1,                   # procesamiento de mejor suposición si no hay registro SPF
    default_explanation => 'Please see http://spf.my.isp/spferror.html for details',
    max_lookup_count    => 10,          # número total de includes/redirects
    sanitize    => 0,                   # no sanitizar todos los strings devueltos
    myhostname  => 'foo.example.com',   # prepended a header_comment
    override    => {   'example.net' => 'v=spf1 a mx -all',
                     '*.example.net' => 'v=spf1 a mx -all' },
    fallback    => {   'example.org' => 'v=spf1 a mx -all',
                     '*.example.org' => 'v=spf1 a mx -all' }
) };
if ($@) { warn "bad input to Mail::SPF::Query: $@" }

Establece "trusted=>1" para activar el "trusted-forwarder.org" de verificación de credenciales. La mecánica "include:spf.trusted-forwarder.org" se usa justo antes de un "-all" o "?all". Las circunstancias precisas son un poco más complejas, pero se maneja bien el caso de "v=spf1 -all" — es decir, "trusted-forwarder.org" no se verifica. Este es un feature no estándar.

Establece "guess=>1" para activar el procesamiento de mejor suposición automático. Este usará el registro SPF mejor suposicionado cuando no se puede encontrar en el DNS. Nota que solo puede devolver "pass" o "neutral". Los flags "trusted" y "local" también funcionan cuando se utiliza el "best_guess". Este es un feature no estándar.

Establece "local=>'include:local.domain'" para incluir un proceso adicional antes de un "-all" o "?all". El procesamiento local ocurre justo antes del procesamiento de forwarders confiables. Este es un feature no estándar.

Establece "default_explanation" a una cadena que se utilizará si no hay una explicación específica en el registro SPF. El valor predeterminado se dirige al usuario a una página en www.openspf.org con el siguiente mensaje:

Please see http://www.openspf.org/why.html?sender=%{S}&ip=%{I}&receiver=%{R}

Nota: los argumentos de nombres de dominio en override y fallback deben estar en minúsculas.

Establece "sanitize" a 0 para no sanitizar todos los strings devueltos. Alternativamente, pasa una referencia de función y esta función se utilizará para sanitizar los valores devueltos. La función debe tomar un argumento único y devolver una cadena que contiene el resultado sanitizado.

Establece "debug=>1" para ver las consultas.

Establece "override" para definir registros SPF para dominios que publican pero quieres reemplazar aún así. Los caracteres de wildcard son soportados. Este es un feature no estándar.

Establece "fallback" para definir registros SPF ficticios para dominios que aún no publican. Los caracteres de wildcard son soportados. Este es un feature no estándar.

Nota: los argumentos de nombres de dominio en override y fallback deben estar en minúsculas.

$query->result()

my ($result,           # pass | fail | softfail | neutral | none | error | unknown [mechanism]
    $smtp_comment,     # "please see http://www.openspf.org/why.html?..."  when rejecting, return this string to the SMTP client
    $header_comment,   # prepend_header("Received-SPF" => "$result ($header_comment)")
    $spf_record,       # "v=spf1 ..." original SPF record for the domain
   ) = $query->result();

Esta es la forma común de uso, donde se llama a result() para obtener el resultado del SPF.

NOMBRE

Mail::SPF::Query - SPF verification methods

SINOPSIS

  use Mail::SPF;

  my $query = new Mail::SPF::Query (ip     => '192.0.2.1',
                                    sender => 'sender@example.com',
                                    helo   => 'helo.example.com');

  my ($result, $smtp_comment, $header_comment, $spf_record, $detail) = $query->result();
  # Or:
  # my ($result, $smtp_comment, $header_comment, $spf_record) = $query->result2('recipient@example.com');

  # Or for multiple recipients:
  # my ($result, $smtp_comment, $header_comment, $spf_record) = $query->result2('recipient@example.com', 'recipient2@example.org');

  # Or check overall message status after result2:
  # my ($result, $smtp_comment, $header_comment, $spf_record) = $query->message_result2();

  # For a guess when no SPF record exists:
  # my ($result, $smtp_comment, $header_comment) = $query->best_guess();

  # See Mail::SPF::Query for usage of the Guess and Trusted options

DESCRIPCIÓN

The SPF protocol is a way for a domain administrator to specify which mail servers are authorized to send mail for that domain. The SPF protocol is defined in RFC 4408.

This module implements the SPF verification mechanism. It is intended to be used by Mail Transfer Agents (MTAs) when receiving mail. The MTA instantiates a Mail::SPF::Query object, supplying the connecting IP address, the sender identity (usually the envelope sender, but possibly the header sender), and the HELO/EHLO argument.

The MTA then calls one of the result methods to determine the SPF status of the sender. The result can be used to decide whether to accept, reject, or flag the incoming message.

"$query->result()"

my ($result, $smtp_comment, $header_comment, $spf_record, $detail) = $query->result();

$result será uno de "pass", "fail", "softfail", "neutral", "none", "error" o "unknown [...]":

"pass"
La dirección IP del cliente es un remitente de correo autorizado para el remitente. El correo debe ser aceptado sujeto a la política local con respecto al remitente.
"fail"
La dirección IP del cliente no es un remitente de correo autorizado, y el remitente desea que rechace la transacción por temor a falsificación.
"softfail"
La dirección IP del cliente no es un remitente de correo autorizado, pero el remitente prefiere que acepte la transacción porque no está absolutamente seguro de que todos sus usuarios envíen correos a través de servidores aprobados. El estado de "softfail" se utiliza a menudo durante la implementación inicial de registros SPF por parte de un dominio.
"neutral"
El remitente no hace ninguna afirmación sobre el estado de la IP del cliente.
"none"
No hay ningún registro SPF para este dominio.
"error"
La consulta DNS encontró un error temporal durante el procesamiento.
"unknown [...]"
El dominio tiene un error de configuración en los datos publicados o define un mecanismo que esta biblioteca no entiende. Si los datos contenían un mecanismo no reconocido, se presentará después de "unknown". Debe probar el valor desconocido usando una expresión regular "/^unknown/" en lugar de "eq "unknown"".

Los resultados se almacenan en caché internamente durante un valor predeterminado de 120 segundos. Puede llamar a "->result()" repetidamente; las búsquedas posteriores no accederán a su DNS.

"smtp_comment" debe mostrarse al cliente SMTP.

"header_comment" va en un encabezado "Received-SPF", de la siguiente manera:

Received-SPF: $result ($header_comment)

"spf_record" muestra el registro SPF original obtenido para la consulta. Si no hay ningún registro SPF, estará en blanco. De lo contrario, comenzará con "v=spf1" y contendrá los mecanismos SPF y similares que describen el dominio.

Tenga en cuenta que las cadenas devueltas por este método (y la mayoría de los otros métodos) están (al menos parcialmente) bajo el control del dominio del remitente. Esto significa que, si el remitente es un atacante, se puede suponer que el contenido es hostil. Los diversos métodos que devuelven estas cadenas se aseguran de que (por defecto) las cadenas devueltas solo contengan caracteres en el rango de 32 a 126. Este comportamiento se puede cambiar estableciendo "sanitize" a 0 para desactivar la sanitización completamente. También puede establecer "sanitize" a una referencia de función para realizar una sanitización personalizada. En particular, suponga que "smtp_comment" podría contener un carácter de nueva línea.

"detail" es un hash de todos los elementos de resultado anteriores, más datos adicionales devueltos por el resultado SPF.

¿Por qué la extraña duplicación? Al principio, result() devolvía un solo valor, el $result. Luego llegaron $smtp_comment y $header_comment. Luego $spf_record. Después de un cierto número de resultados posicionales, tiene más sentido tener un hash. Pero no queríamos romper la compatibilidad con versiones anteriores, así que declaramos que el quinto resultado sería un hash y los futuros valores de retorno irían allí.

Las claves del hash son:

result
smtp_comment
header_comment
header_pairs
spf_record
modifiers

"$query->result2()"

my ($result, $smtp_comment, $header_comment, $spf_record) = $query->result2('recipient@domain', 'recipient2@domain');

result2() hace todo lo que hace result(), pero primero comprueba si el sistema de envío es un servidor MX secundario reconocido para el (los) destinatario (s). Si es así, devuelve "pass" y no realiza la consulta SPF. Tenga en cuenta que el sistema de envío puede ser un servidor MX secundario para algunos (pero no todos) los destinatarios de un mensaje con varios destinatarios, por lo que result2 toma una lista de argumentos. Ver también message_result2().

Esta es una característica no estándar. Esta característica también está obsoleta, porque la exención de retransmisiones confiables, como los servidores MX secundarios, debería ser realizada por el software que utiliza esta biblioteca antes de realizar una verificación SPF.

$result será uno de "pass", "fail", "neutral [...]", o "unknown". Ver result() arriba para los significados.

Si tiene servidores MX secundarios y si no puede incluirlos explícitamente en la lista blanca antes de que ocurran las pruebas SPF, puede usar este método en lugar de result(), llamándolo tantas veces como haya destinatarios, o simplemente proporcionando todos los destinatarios a la vez.

"smtp_comment" se puede mostrar al cliente SMTP.

Por ejemplo:

my $query = new Mail::SPF::Query (ip => "127.0.0.1",
                                  sender=>'foo@example.com',
                                  helo=>"somehost.example.com");
...
my ($result, $smtp_comment, $header_comment);
($result, $smtp_comment, $header_comment) = $query->result2('recip1@example.com');
# return suitable error code based on $result eq 'fail' or not
($result, $smtp_comment, $header_comment) = $query->result2('recip2@example.org');
# return suitable error code based on $result eq 'fail' or not
($result, $smtp_comment, $header_comment) = $query->message_result2();
# return suitable error if $result eq 'fail'
# prefix message with "Received-SPF: $result ($header_comment)"

"$query->message_result2()"

my ($result, $smtp_comment, $header_comment, $spf_record) = $query->message_result2();

message_result2() devuelve un estado general para el mensaje después de cero o más llamadas a result2(). Siempre será el último estado devuelto por result2(), o el estado devuelto por result() si result2() nunca fue llamado.

$result será uno de "pass", "fail", "neutral [...]", o "error". Ver result() arriba para los significados.

"$query->best_guess()"

my ($result, $smtp_comment, $header_comment) = $query->best_guess();

Cuando un dominio no publica un registro SPF, esta biblioteca puede producir una suposición informada de todos modos.

Finge que el dominio definió mecanismos A, MX y PTR, además de algunos otros. El conjunto predeterminado de directivas es

a/24 mx/24 ptr

Ese conjunto predeterminado devolverá "pass" o "neutral".

Si desea experimentar con un valor predeterminado diferente, puede pasarlo como argumento: "$query->best_guess("a mx ptr")"

Esta es una característica no estándar. Este método también está obsoleto. Debe establecer "guess=>1" en el método new() en su lugar.

"$query->trusted_forwarder()"

my ($result, $smtp_comment, $header_comment) = $query->best_guess();

Es posible que el mensaje provenga de una retransmisión conocida como buena como "acm.org" o "pobox.com". Durante el período de transición, muchos servicios legítimos pueden parecer falsificar una dirección de remitente: por ejemplo, un sitio web de noticias puede tener un enlace "envíame este artículo por correo electrónico".

El dominio "trusted-forwarder.org" es una lista blanca de hosts conocidos que retransmiten correo o realizan falsificaciones benignas del remitente del sobre:

include:spf.trusted-forwarder.org

Esto devolverá "pass" o "neutral".

Esta es una característica no estándar. Este método también está obsoleto. Debe establecer "trusted=>1" en el método new() en su lugar.

"$query->sanitize('string')"

Esto aplica las reglas de sanitización para el objeto de consulta particular. Estas reglas están controladas por el parámetro "sanitize" del método c<new()>.

strict_sanitize('string')

Esto asegura que todos los caracteres de la cadena devuelta sean imprimibles. Todos los espacios en blanco se convierten en espacios, y todos los demás caracteres no imprimibles se convierten en signos de interrogación. Esto probablemente es demasiado agresivo para muchas aplicaciones.

Esta función se utiliza por defecto cuando se pasa la opción "sanitize" al método new().

Esta función no es un método de clase.
