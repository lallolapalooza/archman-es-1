NOMBRE

Mail::SpamAssassin::Plugin::DKIM - realiza pruebas de verificación DKIM

SINOPSIS

loadplugin Mail::SpamAssassin::Plugin::DKIM [/ruta/a/DKIM.pm]

Teniendo en cuenta las firmas de cualquier dominio firmante:

full   DKIM_SIGNED           eval:check_dkim_signed()
full   DKIM_VALID            eval:check_dkim_valid()
full   DKIM_VALID_AU         eval:check_dkim_valid_author_sig()
full   DKIM_VALID_EF         eval:check_dkim_valid_envelopefrom()

Teniendo en cuenta las firmas ARC (Authenticated Received Chain, RFC 8617) de cualquier dominio firmante:

full   ARC_SIGNED            eval:check_arc_signed()
full   ARC_VALID             eval:check_arc_valid()

Teniendo en cuenta las firmas de dominios firmantes especificados solamente: (las comillas pueden omitirse en nombres de dominio que consisten únicamente en letras, dígitos, puntos y guiones)

full   DKIM_SIGNED_MY1       eval:check_dkim_signed('dom1','dom2',...)
full   DKIM_VALID_MY1        eval:check_dkim_valid('dom1','dom2',...)
full   DKIM_VALID_AU_MY1     eval:check_dkim_valid_author_sig('d1','d2',...)
full   __DKIM_DEPENDABLE     eval:check_dkim_dependable()

Prácticas de Firma de Dominio del Autor (ADSP) de cualquier dominio del autor:

header DKIM_ADSP_NXDOMAIN    eval:check_dkim_adsp('N')
header DKIM_ADSP_ALL         eval:check_dkim_adsp('A')
header DKIM_ADSP_DISCARD     eval:check_dkim_adsp('D')
header DKIM_ADSP_CUSTOM_LOW  eval:check_dkim_adsp('1')
header DKIM_ADSP_CUSTOM_MED  eval:check_dkim_adsp('2')
header DKIM_ADSP_CUSTOM_HIGH eval:check_dkim_adsp('3')

Prácticas de Firma de Dominio del Autor (ADSP) de dominios del autor especificados solamente:

header DKIM_ADSP_MY1         eval:check_dkim_adsp('*','dom1','dom2',...)
describe DKIM_SIGNED   El mensaje tiene una firma DKIM o DK, no necesariamente válida
describe DKIM_VALID    El mensaje tiene al menos una firma DKIM o DK válida
describe DKIM_VALID_AU El mensaje tiene una firma DKIM o DK válida del dominio del autor
describe DKIM_VALID_EF El mensaje tiene una firma DKIM o DK válida del dominio del remitente
describe __DKIM_DEPENDABLE     Una falla de validación no atribuible a truncamiento
describe DKIM_ADSP_NXDOMAIN    Dominio no en DNS y sin firma válida del dominio del autor
describe DKIM_ADSP_ALL         El dominio firma todo el correo, sin firma válida del dominio del autor
describe DKIM_ADSP_DISCARD     El dominio firma todo el correo y sugiere descartar el correo sin firma válida del dominio del autor, sin firma válida del dominio del autor
describe DKIM_ADSP_CUSTOM_LOW  adsp_override es CUSTOM_LOW, sin firma válida del dominio del autor
describe DKIM_ADSP_CUSTOM_MED  adsp_override es CUSTOM_MED, sin firma válida del dominio del autor
describe DKIM_ADSP_CUSTOM_HIGH adsp_override es CUSTOM_HIGH, sin firma válida del dominio del autor

Para compatibilidad con versiones anteriores a la 3.3.0, los siguientes son sinónimos:

ANTIGUO: eval:check_dkim_verified = NUEVO: eval:check_dkim_valid
ANTIGUO: eval:check_dkim_signall  = NUEVO: eval:check_dkim_adsp('A')
ANTIGUO: eval:check_dkim_signsome = NUEVO: redundante, semánticamente siempre verdadero

La regla eval __DKIM_DEPENDABLE merece una explicación. La regla devuelve verdadero cuando las firmas son proporcionadas por un llamador, O BIEN cuando las firmas son obtenidas por este plugin Y o bien no hay firmas O BIEN una regla __TRUNCATED fue falsa. En otras palabras: __DKIM_DEPENDABLE es verdadero cuando las firmas fallidas no pueden ser atribuidas al truncamiento del mensaje al alimentar un mensaje a SpamAssassin. Se puede consultar para prevenir falsos positivos en mensajes grandes pero truncados con una implementación rudimentaria de ADSP mediante reglas hechas a mano.

DESCRIPCIÓN

Este plugin de SpamAssassin implementa búsquedas DKIM como se describe en la RFC 4871, así como búsquedas históricas de DomainKeys, como se describe en la RFC 4870, gracias al soporte para ambos tipos de firmas por versiones más recientes del módulo Mail::DKIM.

Requiere el módulo CPAN "Mail::DKIM" para operar. ¡Muchas gracias a Jason Long por ese módulo!

ETIQUETAS

Las siguientes etiquetas se añaden al conjunto, disponibles para su uso en informes, campos de encabezado, otros plugins, etc.:

_DKIMIDENTITY_
  Identificador de Agente o Usuario (AUID) (la etiqueta 'i') de firmas válidas;
_DKIMDOMAIN_
  Identificador de Dominio Firmante (SDID) (la etiqueta 'd') de firmas válidas;
_DKIMSELECTOR_
  Selector DKIM (la etiqueta 's') de firmas válidas;

Las identidades y dominios de las firmas que fallaron la verificación no se incluyen en estas etiquetas. Los duplicados se eliminan (por ejemplo, cuando hay una o más firmas válidas del mismo firmante, solo una copia llega a una etiqueta). Tenga en cuenta que puede haber más de una firma en un mensaje; actualmente se proporcionan como una lista separada por espacios, aunque este comportamiento puede cambiar.

CONFIGURACIÓN DEL USUARIO

welcomelist_from_dkim autor@example.com [dominio-firmante]
Anteriormente whitelist_from_dkim, que funcionará de forma intercambiable hasta la versión 4.1.

Funciona de manera similar a welcomelist_from, excepto que además de coincidir una dirección de autor (From) con el patrón en el primer parámetro, el mensaje también debe llevar una firma válida de Domain Keys Identified Mail (DKIM) realizada por un dominio firmante (SDID, es decir, la etiqueta d=) que sea aceptable para nosotros.

Solo se permite una entrada welcomelist por línea, como en "welcomelist_from_rcvd". Se permiten múltiples líneas "welcomelist_from_dkim". Se permiten caracteres de estilo globbing de archivos para la dirección From (el primer parámetro), al igual que con "welcomelist_from_rcvd".

El segundo parámetro (el dominio firmante) no acepta comodines de estilo globbing de archivos completos, aunque se reconoce un prefijo simple '*.' (o simplemente '.') a un nombre de dominio e implica cualquier subdominio del dominio especificado (pero no el dominio en sí).

Si no se especifica ningún parámetro de dominio firmante, la única firma aceptable será una Firma de Dominio del Autor (a veces llamada firma de primera parte), que es una firma donde el dominio firmante (SDID) de una firma coincide con el dominio de la dirección del autor (es decir, la dirección en un campo de encabezado From).

Dado que esta lista de bienvenida requiere que se realice una verificación DKIM, las pruebas de red deben estar habilitadas.

Ejemplos de listas de bienvenida basadas en una firma de dominio del autor (primera parte):

welcomelist_from_dkim joe@example.com
welcomelist_from_dkim *@corp.example.com
welcomelist_from_dkim *@*.example.com

Ejemplos de listas de bienvenida basadas en firmas de terceros:

welcomelist_from_dkim jane@example.net      example.org
welcomelist_from_dkim rick@info.example.net example.net
welcomelist_from_dkim *@info.example.net    example.net
welcomelist_from_dkim *@*                   mail7.remailer.example.com
welcomelist_from_dkim *@*                   *.remailer.example.com
def_welcomelist_from_dkim autor@example.com [dominio-firmante]
Anteriormente def_whitelist_from_dkim, que funcionará de forma intercambiable hasta la versión 4.1.

Igual que "welcomelist_from_dkim", pero se usa para las entradas de lista de bienvenida predeterminadas en la distribución de SpamAssassin. La puntuación de la lista de bienvenida es menor, ya que a menudo son objetivos de abuso de los remitentes públicos que firman su correo.

NOMBRE

spamass-milter - un filtro de correo para Sendmail 8.13+ que implementa los protocolos DKIM y ADSP.

SINOPSIS

spamass-milter [-46] [-a address] [-b socket] [-c configpath] [-d] [-e] [-f pidfile] [-g group] [-h] [-i inetd-address] [-l logfacility] [-m max-retries] [-p port] [-r reject-text] [-s socket] [-t timeout] [-u user] [-v] [-w pidfile] [-x configpath]

DESCRIPCIÓN

spamass-milter es un milter (filtro de correo) para la familia de MTA Sendmail que implementa los protocolos DKIM y ADSP. Fue escrito como un reemplazo para el milter `milter-spamd` de Mark H. Storer, pero es más moderno y maneja DKIM y ADSP de manera más independiente.

spamass-milter lee la configuración principal de SpamAssassin, pero también tiene sus propios parámetros de configuración. Consulte la sección de configuración de SpamAssassin para ver la lista completa de opciones.

spamass-milter puede ser invocado directamente o a través de `inetd`.

Para obtener una lista de los comandos de configuración más utilizados, consulte la sección de CONFIGURACIÓN DE USUARIO más abajo.

ETIQUETAS

Las siguientes etiquetas se pueden utilizar en las reglas de SpamAssassin para verificar los resultados del escaneo de DKIM y ADSP.

check_dkim_valid([domain])
Verifica si un correo electrónico tiene una firma DKIM válida. Si se proporciona un argumento domain, verifica si la firma DKIM pertenece a ese dominio específico. El dominio se puede especificar como un dominio exacto (por ejemplo, `example.com`) o como un comodín que coincida con subdominios (por ejemplo, `*.example.com`). Si no se proporciona ningún argumento, verifica si hay alguna firma DKIM válida presente en el correo electrónico. Devuelve 1 si es válido, 0 en caso contrario.
check_dkim_author_sig([domain])
Similar a check_dkim_valid, pero se centra específicamente en la firma del dominio del autor (el dominio en el encabezado `From:`). Si se proporciona un argumento domain, verifica si la firma DKIM del autor pertenece a ese dominio específico. Si no se proporciona ningún argumento, verifica si la firma DKIM del autor es válida. Devuelve 1 si es válido, 0 en caso contrario.
check_adsp_signing_practices([domain])
Consulta las prácticas de firma del dominio del autor según lo definido por ADSP (RFC 5617). Si se proporciona un argumento domain, consulta las prácticas de firma para ese dominio específico. Las prácticas de firma devueltas son:
NXDOMAIN
El dominio no existe en DNS.
UNKNOWN
El dominio puede o no firmar el correo electrónico. Este es el valor predeterminado si el dominio existe en DNS pero no se encuentra ningún registro ADSP.
ALL
Todo el correo electrónico del dominio se firma con una firma de dominio de autor.
DISCARDABLE
Todo el correo electrónico del dominio se firma con una firma de dominio de autor. Además, si llega un mensaje sin una firma de dominio de autor válida, el dominio anima al destinatario a descartarlo.
CUSTOM_LOW
Una configuración personalizada que indica un nivel bajo de confianza.
CUSTOM_MED
Una configuración personalizada que indica un nivel medio de confianza.
CUSTOM_HIGH
Una configuración personalizada que indica un nivel alto de confianza.
Si no se proporciona ningún argumento, consulta las prácticas de firma para el dominio del autor del correo electrónico. Devuelve la cadena de prácticas de firma o una cadena vacía si no se encuentran las prácticas de firma.

CONFIGURACIÓN DEL USUARIO

Los siguientes parámetros de configuración se pueden utilizar en los archivos de configuración de SpamAssassin (por ejemplo, en el archivo ~/.spamassassin/local.cf o en /etc/mail/spamassassin/local.cf).

bayes_ignore_header nombre-encabezado
Ignora los correos electrónicos que tengan el encabezado especificado nombre-encabezado. Útil para evitar que los correos electrónicos de listas de correo o servicios similares se utilicen para entrenar la base de datos bayesiana.
blacklist_filename nombre-archivo
Especifica un archivo que contiene una lista de direcciones de remitentes que se deben considerar como no confiables. Los correos electrónicos de estos remitentes se marcarán como spam. Este archivo debe contener un remitente por línea. El nombre de archivo puede ser un nombre de archivo absoluto o relativo al directorio de configuración de SpamAssassin. Los archivos son de solo lectura y su contenido se comprueba en busca de cambios en intervalos regulares (que se pueden controlar con config_lookup_interval).
whitelist_filename nombre-archivo
Especifica un archivo que contiene una lista de direcciones de remitentes que se deben considerar confiables. Los correos electrónicos de estos remitentes no se marcarán como spam. Este archivo debe contener un remitente por línea. El nombre de archivo puede ser un nombre de archivo absoluto o relativo al directorio de configuración de SpamAssassin. Los archivos son de solo lectura y su contenido se comprueba en busca de cambios en intervalos regulares (que se pueden controlar con config_lookup_interval).
unwelcomelisting nombre-archivo
Similar a blacklist_filename, pero se utiliza para la funcionalidad de "no bienvenida". Los correos electrónicos de remitentes en este archivo siempre se considerarán spam, incluso si otras reglas sugieren lo contrario. El formato es el mismo que el de blacklist_filename.
welcomelisting nombre-archivo
Similar a whitelist_filename, pero se utiliza para la funcionalidad de "bienvenida". Los correos electrónicos de remitentes en este archivo siempre se considerarán no spam, incluso si otras reglas sugieren lo contrario. El formato es el mismo que el de whitelist_filename.
unwelcomelisting_level score
Establece la puntuación mínima para que se aplique la regla unwelcomelisting. El valor predeterminado es -100. Esto significa que la regla siempre se aplica si el remitente está en la lista de no bienvenida.
welcomelisting_level score
Establece la puntuación mínima para que se aplique la regla welcomelisting. El valor predeterminado es -100. Esto significa que la regla siempre se aplica si el remitente está en la lista de bienvenida.
unwelcomelisting_message mensaje
Establece el mensaje que se adjunta a los correos electrónicos que se marcan como spam debido a la regla unwelcomelisting. El valor predeterminado es "Undesired sender".
welcomelisting_message mensaje
Establece el mensaje que se adjunta a los correos electrónicos que se marcan como no spam debido a la regla welcomelisting. El valor predeterminado es "Desired sender".
unwelcomelisting_header nombre-encabezado
Solo se debe especificar en el comando unwelcomelisting.
unwelcomelisting_domain dominio
Solo se debe especificar en el comando unwelcomelisting.
welcomelisting_header nombre-encabezado
Solo se debe especificar en el comando welcomelisting.
welcomelisting_domain dominio
Solo se debe especificar en el comando welcomelisting.
unwelcomelisting_regex patrón-regex
Solo se debe especificar en el comando unwelcomelisting.
welcomelisting_regex patrón-regex
Solo se debe especificar en el comando welcomelisting.

Útil para eliminar entradas predeterminadas no deseadas de una configuración distribuida mediante una configuración local o específica del sitio o mediante "user_prefs".

adsp_override dominio [prácticas-de-firma]
Actualmente, pocos dominios publican sus prácticas de firma (RFC 5617 - ADSP), en parte porque el RFC de ADSP es bastante nuevo, en parte porque creen que casi ningún destinatario se molesta en comprobarlo y, en parte, por miedo a que algunos destinatarios pierdan correos debido a problemas en sus procedimientos de validación de firmas o a la manipulación de correos por parte de remitentes de correo fuera de su control.

Sin embargo, los destinatarios podrían beneficiarse de conocer las prácticas de firma de un dominio de envío (del autor), por ejemplo, para reconocer correos electrónicos falsificados que dicen ser de ciertos dominios que son objetivos populares de phishing, como las instituciones financieras. Desafortunadamente, dado que las prácticas de firma rara vez se publican o son débiles, es difícil justificarlas buscando en DNS.

Para superar este problema del huevo o la gallina, el mecanismo "adsp_override" permite a los destinatarios que usan SpamAssassin anular las prácticas ADSP publicadas o predeterminadas para ciertos dominios. Esto hace posible especificar manualmente prácticas de firma más fuertes (o más débiles) de las que un dominio de firma está dispuesto a publicar (explícita o predeterminadamente), y también ahorra una consulta DNS.

Tenga en cuenta que ADSP (publicado o anulado) solo se consulta para mensajes que no contienen una firma DKIM válida del dominio del autor.

Según RFC 5617, las prácticas de firma pueden ser una de las siguientes: "unknown", "all" y "discardable".

"unknown": El dominio puede firmar algunos o todos los correos electrónicos; los mensajes del dominio pueden o no tener una Firma de Dominio de Autor. Este es el valor predeterminado si un dominio existe en DNS pero no se encuentra ningún registro ADSP.

"all": Todo el correo electrónico del dominio se firma con una Firma de Dominio de Autor.

"discardable": Todo el correo electrónico del dominio se firma con una Firma de Dominio de Autor. Además, si llega un mensaje sin una Firma de Dominio de Autor válida, el dominio anima al destinatario (o destinatarios) a descartarlo.

La consulta ADSP también puede determinar que un dominio está "fuera de ámbito", es decir, el dominio no existe (NXDOMAIN) en el DNS.

Para anular las prácticas de firma de un dominio en un archivo de configuración de SpamAssassin, especifique una directiva "adsp_override" para cada dominio de envío que se vaya a anular.

Su primer argumento es un nombre de dominio. El dominio del autor se compara con él, la coincidencia no distingue entre mayúsculas y minúsculas. Esta no es una expresión regular ni un comodín de estilo globbing de archivos, pero todavía hay comodines limitados disponibles: si este argumento comienza con un "*." (o es un simple "*"), el dominio del autor coincide si es un subdominio (a uno o más niveles) del argumento. De lo contrario (sin asterisco inicial), la coincidencia debe ser exacta (no un subdominio).

Un segundo parámetro opcional es una de las siguientes palabras clave (sin distinción entre mayúsculas y minúsculas): "nxdomain", "unknown", "all", "discardable", "custom_low", "custom_med", "custom_high".

La ausencia de este segundo parámetro implica "discardable". Si un dominio no está listado por una directiva "adsp_override" ni publica explícitamente ningún registro ADSP, entonces se implica "unknown" para dominios válidos y "nxdomain" para dominios que no existen en DNS. (Nota: la validez del dominio solo se verifica con versiones de Mail::DKIM 0.37 o posteriores (en realidad desde 0.36_5), "nxdomain" nunca aparecería con versiones anteriores).

La configuración fuerte "discardable" es útil para dominios que se sabe que siempre firman sus correos electrónicos y siempre los envían directamente a los destinatarios (no a listas de correo), y son objetivos frecuentes de intentos de phishing, como las instituciones financieras. El valor "discardable" también es apropiado para dominios que se sabe que nunca envían ningún correo electrónico.

Cuando un mensaje no contiene una firma válida del dominio del autor (el dominio en un campo de encabezado From), las prácticas de firma relacionadas con el dominio del autor determinan cuál de las siguientes reglas se activa y contribuye con su puntuación: DKIM_ADSP_NXDOMAIN, DKIM_ADSP_ALL, DKIM_ADSP_DISCARD, DKIM_ADSP_CUSTOM_LOW, DKIM_ADSP_CUSTOM_MED, DKIM_ADSP_CUSTOM_HIGH. No más de una de estas reglas puede activarse para mensajes que tienen un autor (pero véase más abajo). Los tres últimos solo pueden resultar de unas 'prácticas de firma' según se indica en una directiva "adsp_override" (no de una consulta DNS), y pueden servir como un medio conveniente para proporcionar una puntuación diferente si las puntuaciones asignadas a DKIM_ADSP_ALL o DKIM_ADSP_DISCARD no se consideran adecuadas para algunos dominios.

RFC 5322 permite que un mensaje tenga más de un autor: pueden listarse varias direcciones en un solo campo de encabezado From. RFC 5617 define que un mensaje con varios autores tiene varias prácticas de firma de dominio, pero no prescribe cómo deben combinarse. En presencia de múltiples prácticas de firma, más de una de las reglas DKIM_ADSP_* puede activarse.

Como precaución contra la activación de reglas DKIM_ADSP_* cuando existe una razón local conocida para un fallo en la verificación de la firma, las prácticas ADSP del dominio se consideran 'unknown' cuando las consultas DNS están deshabilitadas o una consulta DNS encontró un problema temporal al obtener una clave pública del dominio del autor. Del mismo modo, ADSP se considera 'unknown' cuando este plugin realizó su propia verificación de firma (las firmas no fueron pasadas a SA por un llamador) y se activó una metarregla __TRUNCATED, lo que indica que el llamador pasó intencionalmente un mensaje truncado a SpamAssassin, lo que fue una razón probable para un fallo en la verificación de la firma.

Ejemplo:

adsp_override *.mydomain.example.com   discardable
adsp_override *.neversends.example.com discardable
adsp_override ebay.com
adsp_override *.ebay.com
adsp_override ebay.co.uk
adsp_override *.ebay.co.uk
adsp_override paypal.com
adsp_override *.paypal.com
adsp_override amazon.com
adsp_override ealerts.bankofamerica.com

dkim_minimum_key_bits n (predeterminado: 1024)
El tamaño más pequeño de una clave de firma (en bits) para que una firma válida se considere para la lista de bienvenida. Además, la función eval check_dkim_valid() devolverá falso en claves cortas cuando se llame con dominios listados explícitamente, y la función eval check_dkim_valid_author_sig() devolverá falso en claves cortas (independientemente de sus argumentos). Establecer la opción en 0 deshabilita la comprobación del tamaño de la clave.

Tenga en cuenta que la opción no tiene efecto cuando la función eval check_dkim_valid() se llama sin argumentos (como en una regla DKIM_VALID). La mera presencia de alguna firma válida en un mensaje no tiene valor reputacional (sin estar asociada con un dominio en particular), independientemente de su tamaño de clave; cualquiera puede anteponer su propia firma a una copia de algún correo de terceros y reenviarlo, lo que no lo hace más confiable que sin dicha firma. Esta es también la razón por la que una regla DKIM_VALID tiene una puntuación cercana a cero, es decir, un golpe de regla es solo informativo. Esta opción también se evalúa en las comprobaciones de firmas ARC.

NOMBRE

Mail::SpamAssassin::Plugin::DKIM - Verificación DKIM y firma de correos electrónicos

SINOPSIS

use Mail::SpamAssassin::Plugin::DKIM;

DESCRIPCIÓN

Este módulo es un plugin para SpamAssassin que proporciona la verificación de la firma DKIM (DomainKeys Identified Mail) y la posibilidad de firmar los correos salientes con DKIM.

DKIM es un método de autenticación de correo electrónico diseñado para detectar la suplantación de identidad de correo electrónico al proporcionar un marco para que una organización asuma la responsabilidad de un dominio de remitente publicado en la clave DNS de ese dominio.

CONFIGURACIÓN

Para habilitar este plugin, agregue la siguiente línea a su archivo de configuración de SpamAssassin (por ejemplo, local.cf):

loadplugin Mail::SpamAssassin::Plugin::DKIM

También puede configurar varias opciones relacionadas con DKIM en su archivo de configuración.

OPCIONES

  • dkim_sign_domains: Una lista de dominios para los que firmar los correos salientes.
  • dkim_sign_key_file: La ruta al archivo de clave privada para la firma DKIM.
  • dkim_sign_key_selector: El selector de clave DKIM a usar.
  • dkim_verify: Habilita/deshabilita la verificación de firmas DKIM entrantes (por defecto: 1).
  • dkim_sign: Habilita/deshabilita la firma de correos salientes (por defecto: 0).

Ejemplo de configuración:

loadplugin Mail::SpamAssassin::Plugin::DKIM
dkim_sign_domains mydomain.com
dkim_sign_key_file /etc/mail/dkim.private
dkim_sign_key_selector default
dkim_sign 1

DEPURACIÓN

Puede habilitar la depuración para este plugin agregando la siguiente línea a su archivo de configuración:

add_log_code dkim _info.

Esto generará información detallada sobre el proceso de verificación y firma DKIM.
