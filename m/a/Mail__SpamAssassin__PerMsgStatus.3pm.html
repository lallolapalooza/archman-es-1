Paquete: spamassassin

Licencias: APACHE

Mail::SpamAssassin::PerMsgStatus(3) Documentación de Perl aportada por el usuario Mail::SpamAssassin::PerMsgStatus(3)

NOMBRE

Mail::SpamAssassin::PerMsgStatus - estado por mensaje (spam o no-spam)

SINOPSIS

my $spamtest = Mail::SpamAssassin->new({
  'rules_filename'      => '/etc/spamassassin.rules',
  'userprefs_filename'  => $ENV{HOME}.'/.spamassassin/user_prefs'
});
my $mail = $spamtest->parse();
my $status = $spamtest->check ($mail);
my $rewritten_mail;
if ($status->is_spam()) {
  $rewritten_mail = $status->rewrite_mail ();
}
...

DESCRIPCIÓN

El método check() de Mail::SpamAssassin devuelve un objeto de esta clase. Este objeto encapsula todo el estado por mensaje.

MÉTODOS

$status->check ()
Ejecuta las reglas de SpamAssassin contra el mensaje al que apunta el objeto.
$status->learn()
Después de que un mensaje de correo haya sido revisado, se puede llamar a este método. Si la puntuación está fuera de un cierto rango alrededor del umbral, es decir, si el mensaje se juzga más o menos definitivamente como spam o no-spam, se introducirá en los sistemas de aprendizaje de SpamAssassin (actualmente el clasificador bayesiano ingenuo), de modo que correos similares en el futuro sean detectados.
$score = $status->get_autolearn_points()
Devuelve la puntuación del mensaje tal como se calculó para el auto-aprendizaje. Se ignoran ciertas pruebas: 
- reglas con tflags establecidas a 'learn' (las reglas bayesianas)
- reglas con tflags establecidas a 'userconf' (reglas de bienvenida/bloqueo de usuario, etc.)
- reglas con tflags establecidas a 'noautolearn'

También tenga en cuenta que el auto-aprendizaje se produce utilizando las puntuaciones del conjunto de puntuaciones 0 o 1, dependiendo de qué conjunto de puntuaciones se utilice durante la revisión del mensaje. Es probable que las puntuaciones de revisión y auto-aprendizaje del mensaje sean diferentes.

$score = $status->get_head_only_points()
Devuelve la puntuación del mensaje tal como se calculó para el auto-aprendizaje, ignorando todas las reglas excepto las basadas en encabezados.
$score = $status->get_learned_points()
Devuelve la puntuación del mensaje tal como se calculó para el auto-aprendizaje, ignorando todas las reglas excepto las basadas en aprendizaje.
$score = $status->get_body_only_points()
Devuelve la puntuación del mensaje tal como se calculó para el auto-aprendizaje, ignorando todas las reglas excepto las basadas en el cuerpo.
$score = $status->get_autolearn_force_status()
Devuelve si la puntuación de un mensaje incluyó reglas marcadas como autolearn_force.
$rule_names = $status->get_autolearn_force_names()
Devuelve una lista separada por comas de nombres de reglas si la puntuación de un mensaje incluyó reglas marcadas como autolearn_force.
$isspam = $status->is_spam ()
Después de que un mensaje de correo haya sido revisado, se puede llamar a este método. Devolverá 1 para el correo determinado como probablemente spam, 0 si no parece spam.
$list = $status->get_names_of_tests_hit ()
Después de que un mensaje de correo haya sido revisado, se puede llamar a este método. Devolverá una cadena separada por comas, que enumera todos los nombres simbólicos de las pruebas que fueron activadas por el correo.
$list = $status->get_names_of_tests_hit_with_scores_hash ()
Después de que un mensaje de correo haya sido revisado, se puede llamar a este método. Devolverá un puntero a una tabla hash para pares de reglas y puntuaciones para todos los nombres simbólicos de las pruebas y las puntuaciones individuales de las pruebas que fueron activadas por el correo.
$list = $status->get_names_of_tests_hit_with_scores ()
Después de que un mensaje de correo haya sido revisado, se puede llamar a este método. Devolverá una cadena separada por comas de pares regla=puntuación para todos los nombres simbólicos de las pruebas y las puntuaciones individuales de las pruebas que fueron activadas por el correo.
$list = $status->get_names_of_subtests_hit ()
Después de que un mensaje de correo haya sido revisado, se puede llamar a este método. Devolverá una cadena separada por comas, que enumera todos los nombres simbólicos de las pruebas de los sub-tests de meta-reglas que fueron activadas por el correo. Los sub-tests son las reglas normalmente ocultas, que puntúan 0 y tienen nombres que comienzan con dos guiones bajos, utilizadas en meta-reglas.

Si se pasa un parámetro de collapsed o dbg, la salida será un array condensado de sub-tests con múltiples aciertos reducidos a una sola entrada.

Si se pasa el parámetro de dbg, la salida será una cadena condensada de sub-tests con múltiples aciertos reducidos a una sola entrada con el número de aciertos entre paréntesis. También se añade información al final sobre los múltiples aciertos.

$num = $status->get_score ()
Después de que un mensaje de correo haya sido revisado, se puede llamar a este método. Devolverá la puntuación del mensaje.
$num = $status->get_required_score ()
Después de que un mensaje de correo haya sido revisado, se puede llamar a este método. Devolverá la puntuación requerida para que un correo sea considerado spam.
$num = $status->get_autolearn_status ()
Después de que un mensaje de correo haya sido revisado, se puede llamar a este método. Devolverá una de las siguientes cadenas dependiendo de si el correo fue auto-aprendido o no: "ham", "no", "spam", "disabled", "failed", "unavailable".

Si también está marcado con auto_learn_force, incluirá el estado y las reglas activadas. Por ejemplo: "autolearn_force=yes (AUTOLEARNTEST_BODY)"

$report = $status->get_report ()
Entrega un "informe de spam" sobre el mensaje de correo revisado. Este contiene detalles de cuántas reglas de detección de spam activó.

El informe se devuelve como una cadena de varias líneas, con las líneas separadas por caracteres "\n".

$preview = $status->get_content_preview ()
Proporciona una "vista previa" del contenido.

Esto se devuelve como una cadena de varias líneas, con las líneas separadas por caracteres "\n", que contiene una muestra de texto plano segura y completamente decodificada de las primeras líneas del cuerpo del mensaje.

$msg = $status->get_message()
Devuelve el objeto que representa el mensaje que se está escaneando.
$status->rewrite_mail ()
Reescribe el mensaje de correo. Esto añadirá como mínimo encabezados y, como máximo, encapsulará MIME el texto del mensaje, para reflejar su estado de spam o no-spam. La función devolverá un escalar del mensaje reescrito.

Las modificaciones reales dependen de la configuración (ver "Mail::SpamAssassin::Conf" para más información).

Las modificaciones posibles son las siguientes:

Modificación de líneas To:, From: y Subject: en correos spam
Dependiendo de la configuración, las líneas To: y From: pueden tener un comentario RFC 2822 definido por el usuario añadido para el correo spam. La línea de asunto puede tener una cadena definida por el usuario antepuesta para el correo spam.
Encabezados X-Spam-* para todos los correos
Dependiendo de la configuración, se añadirán cero o más encabezados cuyos nombres comiencen por "X-Spam-" al correo dependiendo de si es spam o ham.
Mensaje spam con report_safe
Si report_safe se establece como verdadero (1), los mensajes spam se encapsulan en su propio adjunto MIME message/rfc822 sin realizar modificaciones.

Si report_safe se establece como falso (0), el mensaje solo tendrá los encabezados anteriores añadidos/modificados.

$status->action_depends_on_tags($tags, $code, @args)
Encola la referencia de subrutina proporcionada $code, para que se ejecute cuando todas las etiquetas especificadas estén disponibles. Las $tags pueden ser un escalar simple - un nombre de etiqueta, o una referencia a una lista de nombres de etiquetas. La subrutina &$code cuando se llame recibirá un objeto "permessagestatus" como su primer argumento, seguido de la lista opcional proporcionada @args.
$status->set_tag($tagname, $value)
Establece una etiqueta de plantilla, como se usa en "add_header", plantillas de informes, etc. Esta API está destinada a ser utilizada por plugins. Los nombres de las etiquetas se convertirán internamente a una representación en mayúsculas. Los nombres de las etiquetas deben constar solo de caracteres [A-Z0-9_] y no deben contener guiones bajos consecutivos. Además, el nombre no debe comenzar ni terminar con un guion bajo, ya que ese es el formato de etiquetado de plantilla.

$value = $status->set_tag($tagname, $value)
Associate a value with a template tag name. $value puede ser un escalar simple (cadena o número), o una referencia a un array, en cuyo caso el método público get_tag unirá los elementos del array usando un espacio como separador, devolviendo una sola cadena para compatibilidad con versiones anteriores.

$value también puede ser una referencia a una subrutina, que se evaluará cada vez que se expanda la plantilla. El primer argumento pasado por get_tag a una subrutina llamada será un objeto PerMsgStatus (el objeto de este módulo), seguido de argumentos opcionales proporcionados por un llamador a get_tag.

Tenga en cuenta que Perl admite closures, lo que significa que las variables establecidas en el ámbito del llamador se pueden acceder dentro de esta "sub". Por ejemplo:

my $text = "hello world!";
$status->set_tag("FOO", sub {
          my $pms = shift;
          return $text;
        });

Consulte las secciones "TEMPLATE TAGS" y "CAPTURING TAGS USING REGEX NAMED CAPTURE GROUPS" de "Mail::SpamAssassin::Conf" para obtener más detalles sobre cómo se utilizan las etiquetas de plantilla.

$string = $status->get_tag($tagname)
Obtener el valor actual de una etiqueta de plantilla, como se usa en "add_header", plantillas de informes, etc. Esta API está pensada para ser utilizada por plugins. Los nombres de las etiquetas se convertirán internamente a una representación en mayúsculas.

Consulte las secciones "TEMPLATE TAGS" y "CAPTURING TAGS USING REGEX NAMED CAPTURE GROUPS" de "Mail::SpamAssassin::Conf" para obtener más detalles sobre cómo se utilizan las etiquetas de plantilla.

"undef" se devolverá si no se ha definido una etiqueta con ese nombre.

$string = $status->get_tag_raw($tagname, @args)
Similar a "get_tag", pero mantiene el nombre de una etiqueta sin cambios (no la pone en mayúsculas) y no convierte los valores de etiquetas de tipo arrayref en una sola cadena.
$status->set_spamd_result_item($subref)
Establecer una entrada para la línea de resultados de spamd. $subref debe ser una referencia de código para una subrutina que devolverá una cadena en formato 'nombre=VALOR', similar a las otras entradas en la línea de resultados de spamd: 
Jul 17 14:10:47 radish spamd[16670]: spamd: result: Y 22 - ALL_NATURAL,
DATE_IN_FUTURE_03_06,DIET_1,DRUGS_ERECTILE,DRUGS_PAIN,
TEST_FORGED_YAHOO_RCVD,TEST_INVALID_DATE,TEST_NOREALNAME,
TEST_NORMAL_HTTP_TO_IP,UNDISC_RECIPS scantime=0.4,size=3138,user=jm,
uid=1000,required_score=5.0,rhost=localhost,raddr=127.0.0.1,
rport=33153,mid=<9PS291LhupY>,autolearn=spam

"nombre" y "VALOR" no deben contener los caracteres "=" o ",", ya que es importante que estas líneas de registro sean fáciles de analizar.

La referencia de código será llamada por spamd después de que el mensaje haya sido escaneado y el método PerMsgStatus::check() haya devuelto.

$status->finish ()
Indicar que este objeto $status ha terminado y puede ser destruido.

Si está utilizando SpamAssassin en un entorno persistente, o comprobando muchos mensajes de correo de una fábrica "Mail::SpamAssassin", este método debe ser llamado para asegurar que la recolección de basura de Perl limpiará los objetos de estado antiguos.

$name = $status->get_current_eval_rule_name()
Devolver el nombre de la regla de evaluación que se está ejecutando actualmente. Se devuelve "undef" si no se está ejecutando ninguna regla de evaluación. Útil para que los plugins determinen el nombre de la regla actual mientras están dentro de una llamada de prueba eval.
$status->get_decoded_body_text_array ()
Devuelve el cuerpo del mensaje, con las codificaciones base64 o quoted-printable decodificadas, y las partes no de texto o los adjuntos no en línea eliminados.

Este es el mismo texto resultante que se utiliza en las reglas 'rawbody'.

Se devuelve como un array de cadenas, y cada cadena es un trozo de 2-4kB del cuerpo, dividido por límites si es posible.

$status->get_decoded_stripped_body_text_array ()
Devuelve el cuerpo del mensaje, decodificado (como se describe en get_decoded_body_text_array()), con HTML renderizado y con espacios en blanco normalizados.

Este es el mismo texto resultante que se utiliza en las reglas 'body'.

Siempre renderizará text/html.

Se devuelve como un array de cadenas, y cada cadena representa un 'párrafo'. Los párrafos, en correos electrónicos de texto plano, son bloques de texto de varias líneas separados por dobles saltos de línea.

$status->get (header_name [, default_value])
Devuelve las cabeceras del mensaje, pseudo-cabeceras, nombres, direcciones de correo electrónico u otros valores analizados establecidos por los modificadores. "header_name" es el nombre de una cabecera de correo como 'Subject', 'To', etc., o una pseudo/metadato-cabecera como 'ALL', 'X-Spam-Relays-Untrusted', etc.

Debe llamarse en contexto de lista desde SpamAssassin 4.0. Esto permite devolver varios valores para todos los tipos de cabeceras y modificadores.

Si se llama en contexto escalar (estilo anterior a 4.0), solo se devuelve el primer valor para modificadores como ":addr" o ":name".

Si se proporciona "default_value", se utilizará si la "header_name" solicitada no existe. Esto es principalmente útil cuando se llama en contexto escalar para establecer 'undef' en lugar del valor de retorno legado '' cuando la cabecera no existe.

Añadir el modificador ":raw" al nombre de la cabecera inhibirá la decodificación de cadenas codificadas en quoted-printable o base-64.

Añadir el modificador ":addr" al nombre de la cabecera devolverá todas las direcciones de correo electrónico encontradas en la cabecera. Es principalmente aplicable a los campos de cabecera 'From', 'Sender', 'To', 'Cc' junto con sus contrapartes 'Resent-*', y el 'Return-Path'. Por ejemplo, todos los siguientes resultarán en "example@foo" (y "example@bar"):

example@foo
example@foo (Foo Blah), <example@bar>
example@foo, example@bar
display: example@foo (Foo Blah), example@bar ;
Foo Blah <example@foo>
"Foo Blah" <example@foo>
"'Foo Blah'" <example@foo>

Añadir el modificador ":name" al nombre de la cabecera devolverá todos los "nombres de visualización" del campo de cabecera. Al igual que con ":addr", es principalmente aplicable a los campos de cabecera 'From', 'Sender', 'To', 'Cc' junto con sus contrapartes 'Resent-*', y el 'Return-Path'. Por ejemplo, todos los siguientes resultarán en "Foo Blah" (y "Bar Baz"). También se elimina un nivel de comillas simples, ya que se ve a menudo.

example@foo (Foo Blah)
example@foo (Foo Blah), "Bar Baz" <example@bargt
display: example@foo (Foo Blah), example@bar ;
Foo Blah <example@foo>
"Foo Blah" <example@foo>
"'Foo Blah'" <example@foo>

Añadir ":host" al nombre de la cabecera devolverá la primera cadena que parezca un nombre de host y que termine con un TLD válido. Primero intenta encontrar una coincidencia después del carácter @ (posible correo electrónico), luego de cualquier parte de la cabecera. Un uso normal de esto sería, por ejemplo, 'From:addr:host' para devolver la porción del nombre de host de una dirección From.

Añadir ":domain" al nombre de la cabecera implica ":host", pero devolverá solo la parte del dominio del nombre de host, como lo devuelve RegistryBoundaries::trim_domain().

Añadir ":ip" al nombre de la cabecera devolverá la primera cadena de dirección IPv4 o IPv6 encontrada. Se podría usar, por ejemplo, como 'X-Originating-IP:ip'.

Añadir ":revip" al nombre de la cabecera implica ":ip", pero devolverá la IP encontrada en orden inverso (generalmente para uso de DNSBL).

Añadir el modificador ":first" al nombre de la cabecera devolverá solo la primera cabecera (la superior), en caso de que haya varias. De manera similar, ":last" seleccionará la última. Estos solo afectan la selección física de la línea de cabecera. Si la cabecera seleccionada se analiza más a fondo con ":addr" o similar, puede devolver varios resultados si la cabecera seleccionada contiene varias direcciones.

Hay varias pseudo-cabeceras especiales que pueden especificarse:

"ALL" se puede usar para referirse al texto de todas las cabeceras del mensaje. Cada cabecera se decodifica y se desenrolla a una sola línea, a menos que se llame con :raw.
"ALL-TRUSTED" se puede usar para referirse al texto de todas las cabeceras del mensaje que solo pudieron haber sido añadidas por relés de confianza.
"ALL-INTERNAL" se puede usar para referirse al texto de todas las cabeceras del mensaje que solo pudieron haber sido añadidas por relés internos.
"ALL-UNTRUSTED" se puede usar para referirse al texto de todas las cabeceras del mensaje que pueden haber sido añadidas por relés no confiables. Para hacer esta pseudo-cabecera más útil para reglas de cabecera, se incluye la cabecera 'Received' que fue añadida por el último relé de confianza, aunque pueda ser de confianza.
"ALL-EXTERNAL" se puede usar para referirse al texto de todas las cabeceras del mensaje que pueden haber sido añadidas por relés externos. Al igual que "ALL-UNTRUSTED", se incluye la cabecera 'Received' añadida por el último relé interno.
"ToCc" se puede usar para referirse al contenido de las cabeceras 'To' y 'Cc'.
"EnvelopeFrom" es la dirección utilizada en la fase 'MAIL FROM:' de la transacción SMTP que entregó este mensaje

$status->get_uri_list ()
Returns an array of all unique URIs found in the message. It takes a combination of the URIs found in the rendered (decoded and HTML stripped) body and the URIs found when parsing the HTML in the message. Will also set $status->{uri_list} (the array as returned by this function).

The returned array will include the "raw" URI as well as "slightly cooked" versions. For example, the single URI 'http://%77&#00119;%77.example.com/' will get turned into: ( 'http://%77&#00119;%77.example.com/', 'http://www.example.com/' )

$status->get_uri_detail_list ()
Returns a hash reference of all unique URIs found in the message and various data about where the URIs were found in the message. It takes a combination of the URIs found in the rendered (decoded and HTML stripped) body and the URIs found when parsing the HTML in the message. Will also set $status->{uri_detail_list} (the hash reference as returned by this function).

The hash format looks something like this:

raw_uri => {
  types => { a => 1, img => 1, parsed => 1, domainkeys => 1,
             unlinked => 1, schemeless => 1 },
  cleaned => [ canonicalized_uri ],
  anchor_text => [ "click here", "no click here" ],
  domains => { domain1 => 1, domain2 => 1 },
  hosts => { host1 => domain1, host2 => domain2 },
}

"raw_uri" is whatever the URI was in the message itself (http://spamassassin.apache%2Eorg/). Uris parsed from text will be prefixed with scheme if missing (http://, mailto: etc). HTML uris are as found.

"types" is a hash of the HTML tags (lowercase) which referenced the raw_uri. parsed is a faked type which specifies that the raw_uri was seen in the rendered text. domainkeys is defined when raw_uri was found from DK/DKIM d= field. unlinked is defined when it's assumed that MUA will not linkify uri (found in body without scheme or www. prefix). schemeless is always added for uris without scheme, regardless of linkifying (i.e. email address found in body without mailto:).

"cleaned" is an array of the raw and canonicalized version of the raw_uri (http://spamassassin.apache%2Eorg/, https://spamassassin.apache.org/).

"anchor_text" is an array of the anchor text (text between <a> and </a>), if any, which linked to the URI.

"domains" is a hash of the domains found in the canonicalized URIs.

"hosts" is a hash of unstripped hostnames found in the canonicalized URIs as hash keys, with their domain part stored as a value of each hash entry.

$status->add_uri_detail_list ($raw_uri, $types, $source, $valid_domain)
Adds values to internal uri_detail_list. When used from Plugins, recommended to call from parsed_metadata (along with register_method_priority, -10) so other Plugins calling get_uri_detail_list() will see it.

"raw_uri" is the URI to be added. The only required parameter.

"types" is an optional hash reference, contents are added to uri_detail_list->{types} (see get_uri_detail_list for known keys). parsed is default is no hash given. nocanon does not run uri_list_canonicalize (no redirector, uri fixing). noclean skips adding uri_detail_list->{cleaned}, so it would not be used in "uri" rule checks, but domain/hosts would still be used for URIBL/RBL purposes.

"source" is an optional simple string, only used for debug logging purposes to identify where uri originates from (default: "parsed").

"valid_domain" is an optional boolean (0/1). If true, uri will not be added unless hostname/domain is in valid format and contains a valid TLD. (default: 0)

$status->got_hit ($rulename, $desc_prepend [, name => value, ...])
Register a hit against a rule in the ruleset.

There are two mandatory arguments. These are $rulename, the name of the rule that fired, and $desc_prepend, which is a short string that will be prepended to the rules "describe" string in output reports.

In addition, callers can supplement that with the following optional data:

score => $num
Optional: the score to use for the rule hit. If unspecified, the value from the "Mail::SpamAssassin::Conf" object's "{scores}" hash will be used (a configured score), and in its absence the "defscore" option value.
defscore => $num
Optional: the score to use for the rule hit if neither the option "score" is provided, nor a configured score value is provided.
value => $num
Optional: the value to assign to the rule; the default value is 1. tflags multiple rules use values of greater than 1 to indicate multiple hits. This value is accessible to meta rules.
ruletype => $type
Optional, but recommended: the rule type string. This is used in the "hit_rule" plugin call, called by this method. If unset, 'unknown' is used.
tflags => $string
Optional: a string, i.e. a space-separated list of additional tflags to be appended to an existing list of flags in $self->{conf}->{tflags}, such as: "nice noautolearn multiple". No syntax checks are performed.
description => $string
Optional: a custom rule description string. This is used in the "hit_rule" plugin call, called by this method. If unset, the static description is used.

Backward compatibility: the two mandatory arguments have been part of this API since SpamAssassin 2.x. The optional "name=>value" pairs, however, are a new addition in SpamAssassin 3.2.0.

$status->rule_ready ($rulename [, $no_async])
Mark an asynchronous rule ready, so it can be considered for meta rule evaluation. Asynchronous rule is a rule whose eval-function returns undef, marking that it's not ready yet, expecting results later. $status->rule_ready() must be called later to mark it ready, alternatively $status->got_hit() also does this. If neither is called, then any meta rule that depends on this rule might not evaluate.

Optional boolean $no_async skips checking if there are pending async DNS lookups for the rule.

$status->test_log ($text [, $rulename])
Add $text log entry for a hit rule in final message REPORT/SUMMARY.

Usually called just before got_hit(), to describe for example what URI the rule matched on. Optional $rulename argument is recommended to make sure log is written to correct rule. If rulename is not provided, get_current_eval_rule_name() is used as fallback.

Can be called multiple times per rule for additional entries.

$status->create_fulltext_tmpfile (fulltext_ref)
This function creates a temporary file containing the passed scalar reference data. If no scalar is passed, full/pristine message text is assumed. This is typically used by external programs like pyzor and dccproc, to avoid hangs due to buffering issues.

All tempfiles are automatically cleaned up by PerMsgStatus destructor.

$status->delete_fulltext_tmpfile (tmpfile)
Will cleanup after a $status->create_fulltext_tmpfile() call. Deletes the temporary file and uncaches the filename. Generally there no need to call this, PerMsgStatus destructor cleans up all tmpfiles.
