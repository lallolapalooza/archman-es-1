NAME

Mail::SpamAssassin::BayesStore::Redis - Redis-based Bayes storage module

DESCRIPTION

This module implements a Redis-based Bayes storage module.

Apache SpamAssassin v3.4.0 introduces support for maintaining a Bayes database on a Redis server, either run locally or accessed over the network. Similar to SQL backends, the database can be concurrently used by several hosts running SpamAssassin.

The current implementation only supports a global database, i.e. per-user databases are not supported. Redis server 2.6.* supports access via IPv4 or via a Unix socket, starting with Redis version 2.8.0 IPv6 is also supported. Note that Redis server offers only limited control, hence it is recommended that Redis server is assigned only to the loopback interface, or use other mechanisms to limit access, e.g. local firewall rules.

The Redis backend for Bayes can include Lua scripting support on the Redis server for efficient use, improving performance. Lua support is available from Redis server version 2.6. Without Lua support, the Redis backend uses traditional pipelined (batched) commands, so it should work with Redis server version 2.4 (untested, although not recommended for high load sites).

Expiration of tokens and message 'seen' entries is left to the Redis server. There is no provision for manually expiring a database, hence it is recommended to leave the default 'bayes_auto_expire' value to its default 1 (i.e. enabled).

Example configuration:

bayes_store_module  Mail::SpamAssassin::BayesStore::Redis
bayes_sql_dsn       server=127.0.0.1:6379;password=foo;database=2
bayes_token_ttl 21d
bayes_seen_ttl   8d
bayes_auto_expire 1

A Redis server with Lua support (2.6 or higher) is recommended for performance reasons.

The bayes_sql_dsn variable has been hijacked for our purposes:

bayes_sql_dsn
  Optional configuration parameters that affect a connection to a Redis server.
  This is a semicolon-separated list of option=value pairs, where an option can be: server, password, database. Unrecognized options are silently ignored.
  The value of the 'server' option specifies a socket which a Redis server is listening on. It can be an absolute path of a Unix socket or a host:port pair, where a host can be an IPv4 or IPv6 address or a hostname.
  An IPv6 address must be enclosed in brackets, e.g. [::1]:6379 (IPv6 support on a Redis server is available from version 2.8.0).
  The value of the 'database' option can be a non-negative (small) integer, which is passed to the Redis server with a SELECT instruction and chooses a subdatabase database index. The default index is 0.
  Example: server=localhost:6379;password=foo;database=2
bayes_token_ttl
  Controls expiration of tokens (value in SECONDS, passed as-is to Redis) when bayes_auto_expire is true. Default is 3 weeks (but check Mail::SpamAssassin::Conf.pm to be sure).
bayes_seen_ttl
  Controls expiration of 'seen' entry (value in SECONDS, passed as-is to Redis) when bayes_auto_expire is true. Default is 8 days (but check Mail::SpamAssassin::Conf.pm to be sure).

Expiration is done internally by Redis using the *_ttl settings mentioned above, but only if bayes_auto_expire is true (which is the default). This is why --force-expire etc. have no effect, and token and atime values show up as zero in statistics.

LIMITATIONS: Only global Bayes storage is implemented, per-user Bayes storage is not available at the moment. Backup (sa-learn --backup, or --dump) of a large database might not be possible if all the keys do not fit into process memory.
