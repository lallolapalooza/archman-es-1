NOMBRE

Mail::IMAPClient - Una API para cliente IMAP

SINTAXIS

use Mail::IMAPClient;
my $imap = Mail::IMAPClient->new(
  Server   => 'localhost',
  User     => 'username',
  Password => 'password',
  Ssl      => 1,
  Uid      => 1,
);
my $folders = $imap->folders
  or die "Lista de carpetas error: ", $imap->LastError, "\n";
print "Carpetas: @$folders\n";
$imap->select( $Opt{folder} )
  or die "Seleccionar '$Opt{folder}' error: ", $imap->LastError, "\n";
$imap->fetch_hash("FLAGS", "INTERNALDATE", "RFC822.SIZE")
  or die "Obtener hash '$Opt{folder}' error: ", $imap->LastError, "\n";
$imap->logout
  or die "Salir error: ", $imap->LastError, "\n";

DESCRIPCIÓN

Este módulo proporciona métodos que implementan el protocolo IMAP para interactuar con almacenes de mensaje IMAP.

El módulo se usa construyendo o instanciando un objeto de tipo IMAPClient a través del método constructor new. Una vez instanciado el objeto, el método connect es llamado implícitamente o explícitamente. A ese punto se disponen de métodos que implementan los comandos de cliente IMAP según el RFC 3501. Al finalizar la operación, el método logout del objeto debe llamarse.

Esta documentación no debe reemplazar a RFC 3501 ni a otros RFC relacionados con IMAP.

Nota: Esta documentación usa el término carpeta en lugar de mailbox usado en RFC 3501. Esta documentación reserva el uso del término mailbox para referirse a un conjunto de carpetas propiedad de un id específico de IMAP.

Estado de Conexión

RFC 3501 define cuatro estados posibles para una conexión IMAP: no autenticado, autenticado, seleccionado y desconectado. Estos corresponden a las constantes IMAPClient "Conectado", "Autenticado", "Seleccionado" y "Sin Conexión", respectivamente. Estas constantes pueden usarse junto con el método Status para determinar el estado de un objeto IMAPClient y su sesión subyacente.

Nota: Un objeto IMAPClient puede estar en el estado "Sin Conexión" tanto antes de la conexión al servidor como después de que ésta haya terminado. Esta diferencia se distingue ligeramente de RFC 3501, que no define un estado previo a la conexión. Para una discusión sobre los métodos disponibles para examinar el estado del objeto IMAPClient, vea la sección etiquetada "Métodos de Estado".

Mecanismos de Autenticación Avanzada

RFC 3501 define dos comandos para autenticarse en un servidor IMAP:

LOGIN
LOGIN es para autenticación de texto plano.
AUTHENTICATE
AUTHENTICATE para autenticación más avanzada y/o segura.

Mail::IMAPClient soporta los siguientes mecanismos de autenticación:

DIGEST-MD5
DIGEST-MD5 requiere los módulos Authen::SASL y Digest::MD5. Consulte también "Autenticación".
CRAM-MD5
CRAM-MD5 requiere el módulo Digest::HMAC_MD5.
PLAIN (SASL)
PLAIN (SASL) permite el uso opcional del parámetro "Proxy". RFC 4616 documenta este formato para SASL PLAIN: 
message = [authzid] UTF8NUL authcid UTF8NUL passwd

Cuando "Proxy" está definido, "User" se usa como 'authzid' y "Proxy" como 'authcid'. De otro modo, "User" se usa como 'authcid'.

NTLM
NTLM requiere el módulo Authen::NTLM. Consulte también "Dominio".

Errores

Si intentas una operación que resulte en un error, puedes recuperar el texto del mensaje de error usando el método LastError. Sin embargo, el método LastError es un método del objeto (no un método de clase) y solo puede usarse una vez que el objeto ha sido creado correctamente. En casos donde el objeto no ha sido creado correctamente, la variable $@ está establecida con un mensaje de error.

Mail::IMAPClient resetea $@ y LastError antes de muchas solicitudes IMAP, por lo que los valores solo tienen un breve tiempo de vida. LastError siempre contendrá información de error hasta que otro error se encuentre, se emita otro comando IMAP o se lo clare en explícitamente.

Nota: El uso de $@ está sujeto a cambios en futuras versiones, por lo que es mejor usar LastError para verificar errores una vez que se ha creado el objeto Mail::IMAPClient.

Los errores en el método new pueden impedir que tu objeto nunca sea creado. Si los parámetros Server, User y Password son proporcionados a new, intentará llamar a connect y login. Cualquier método podría fallar y causar que el llamado a new devuelva "undef", con la variable $@ establecida con un mensaje de error.

ADVERTENCIA: (debido a comportamiento antiguo de la API) en errores, muchos métodos pueden devolver undef independientemente del contexto LIST/SCALAR. Por lo tanto, es wise to usar más métodos en contexto escalar. Sin embargo, verifica LastError para detalles sobre errores.

Transacciones

RFC 3501 requiere que cada línea en una conversación IMAP esté precedida de un etiqueta. Una conversación típica consiste en el cliente emitiendo una cadena de comandos con prefijo de etiqueta, y el servidor respondiendo con una o más líneas de salida. Las líneas de salida incluirán un código de estado de completitud del comando original, precedido por la misma etiqueta.

El módulo IMAPClient utiliza un contador simple para asegurar que cada comando del cliente sea emitido con un valor de etiqueta único. Este valor de etiqueta se refiere al número de transacción del módulo IMAPClient. Se mantiene un historial de transacciones mediante el objeto IMAPClient, documentando cada transacción. El método Transaction devuelve el número de la última transacción, y puede usarse para recuperar líneas de texto del historial del objeto.

El parámetro Clear se usa para controlar el tamaño del historial de sesión, para evitar que sesiones largas usen demasiado memoria. Consulta la discusión sobre el parámetro Clear para más información.

El método Report devuelve el historial de toda la sesión IMAP desde la conexión inicial o para las últimas transacciones Clear. Esto proporciona un registro completo de la conversación, incluyendo las cadenas de comandos del cliente y respuestas del servidor, y es un excelente herramienta de depuración así como una fuente útil de datos brutos para el parsing personalizado.

MÉTODOS DE CLASE

Hay varios métodos que pueden invocarse como métodos de clase. Generalmente, pueden invocarse también como métodos de objeto. Nota: si el método new es llamado como un método de objeto, el objeto devuelto es idéntico al que se hubiera devuelto si new hubiera sido llamado como un método de clase. No te da una copia del objeto original.

new

Ejemplo:

my $imap = Mail::IMAPClient->new(%args)
  or die "new fallido: $@\n";

El método new crea una nueva instancia de un objeto IMAPClient.

Si el parámetro Server se pasa como argumento a new, entonces new llamará implícitamente al método connect, colocando el nuevo objeto en el estado Conectado. Si también se proporcionan valores de User y Password, entonces connect llamará a login, y el objeto resultante se devolverá desde new en el estado Autenticado.

CLASS METHODS

Class methods are invoked against the class itself, rather than an object created by "new". They are used for configuration or to retrieve information that isn't specific to any one IMAP session.

new

Example:

my $imap = Mail::IMAPClient->new(
    Server   => $host,
    User     => $id,
    Password => $pass,
    Port     => $port,
    Ssl      => 1,
    Folder   => "INBOX",
) or die "Cannot connect to $host as $id: $@";

The new method is the constructor for the IMAPClient class. If it is passed arguments then those arguments will be treated as a list of key=>value pairs. The key should be one of the parameters as documented under "Parameters" below.

If the "Server" parameter is supplied then the IMAPClient object is created in the Authenticated state.

If the "Server" parameter is not supplied then the IMAPClient object is created in the Unconnected state.

If the new method is passed arguments then those arguments will be treated as a list of key=>value pairs. The key should be one of the parameters as documented under "Parameters" below.

Here are some examples:

use Mail::IMAPClient;

# returns an unconnected Mail::IMAPClient object:
my $imap = Mail::IMAPClient->new;
# ...
# intervening code using the 1st object, then:
# (returns a new, authenticated Mail::IMAPClient object)
$imap = Mail::IMAPClient->new(
    Server   => $host,
    User     => $id,
    Password => $pass,
    Clear    => 5,   # Unnecessary since '5' is the default
    # ...            # Other key=>value pairs go here
) or die "Cannot connect to $host as $id: $@";

See also "Parameters", "connect" and "login" for more information on how to manually connect and login after new.

Quote

Example:

$imap->search( HEADER => 'Message-id' => \$imap->Quote($msg_id) );

The Quote method accepts a value as an argument and returns its argument as a correctly quoted string or a literal string. Since version 3.17 Mail::IMAPClient automatically quotes search arguments we use a SCALARREF so search will not modify or re-quote the value returned by Quote.

Note this method should not be used on folder names for Mail::IMAPClient methods, since methods that accept folder names as an argument will quote the folder name arguments automatically.

If you are getting unexpected results when running methods with values that have (or might have) embedded spaces, double quotes, braces, or parentheses, then calling Quote may be necessary. This method should not be used with arguments that are wrapped in quotes or parens if those quotes or parens are required by RFC3501. For example, if the RFC requires an argument in this format:

( argument )

and the argument is (or might be) "pennies (from heaven)", then one could use:

$argument = "(" . $imap->Quote($argument) . ")"

Of course, the fact that sometimes these characters are sometimes required delimiters is precisely the reason you must quote them when they are not delimiting.

However, there are times when a method fails unexpectedly and may require the use of Quote to work. Should this happen, you can probably file a bug/enhancement request for Mail::IMAPClient to safeguard the particular call/case better.

An example is RFC822 Message-id's, which usually don't contain quotes or parens. When dealing with these it is usually best to take proactive, defensive measures from the very start and use Quote.

Range

Example:

my $parsed = $imap->parse_headers(
    $imap->Range( $imap->messages ), "Date", "Subject"
);

The Range method will condense a list of message sequence numbers or message UID's into the most compact format supported by RFC3501. It accepts one or more arguments, each of which can be:

a) a message number,
b) a comma-separated list of message numbers,
c) a colon-separated range of message numbers (i.e. "$begin:$end")
d) a combination of messages and message ranges, separated by commas (i.e. 1,3,5:8,10), or
e) a reference to an array whose elements are like a) through d).

The Range method returns a Mail::IMAPClient::MessageSet object. The object uses overload and if treated as a string it will act like a string. This means you can ignore its objectivity and just treat it like a string whose value is your message set expressed in compact format.

This method provides an easy way to add or remove messages from a message set.

For more information see Mail::IMAPClient::MessageSet.

Rfc3501_date

Example:

$Rfc3501_date = $imap->Rfc3501_date($seconds);
# or:
$Rfc3501_date = Mail::IMAPClient->Rfc3501_date($seconds);

The Rfc3501_date method accepts one input argument, a number of seconds since the epoch date. It returns an RFC3501 compliant date string for that date (as required in date-related arguments to SEARCH, such as "since", "before", etc.).

Rfc3501_datetime

Example:

$date = $imap->Rfc3501_datetime($seconds);
# or:
$date = Mail::IMAPClient->Rfc3501_datetime($seconds);

The Rfc3501_datetime method accepts one or two arguments: a obligatory timestamp and an optional zone. The zone shall be formatted as "[+-]\d{4}", and defaults to +0000. The timestamp follows the definition of the output of the platforms specific "time", usually in seconds since Jan 1st 1970. However, you have to correct the number yourself for the zone.

Rfc822_date

Example:

$Rfc822_date = $imap->Rfc822_date($seconds);
# or:
$Rfc822_date = Mail::IMAPClient->Rfc822_date($seconds);

The Rfc822_date method accepts one input argument, a number of seconds since the epoch date. It returns an RFC822 compliant date string for that date (without the 'Date:' prefix). Useful for putting dates in message strings before calling "append", "search", etc.

Strip_cr

Examples:

my $stripped = $imap->Strip_cr($string);
# or:
my @list = $imap->some_imap_method;
@list = $imap->Strip_cr(@list);
# or:
my $list = [ $imap->some_imap_method ];   # returns an array ref
$list = $imap->Strip_cr($list);

The Strip_cr method strips carriage returns from input and returns the new string to the caller. This method accepts one or more lines of text as arguments, and returns those lines with all <CR><LF> sequences changed to <LF>. Any input argument with no carriage returns is returned unchanged. If the first argument (not counting the class name or object reference) is an array reference, then members of that array are processed as above and subsequent arguments are ignored. If the method is called in scalar context then an array reference is returned instead of an array of results.

NOTE: Strip_cr does not remove new line characters.

OBJECT METHODS

Object methods must be invoked against objects created via the "new" method and cannot be invoked as class methods.

There object methods typically fall into one of two categories. There are mailbox methods which participate in the IMAP session's conversation (i.e. they issue IMAP client commands) and object control methods which do not result in IMAP commands but which may affect later commands or provide details of previous ones.

This object control methods can be further broken down into two types, Parameter accessor methods, which affect the behavior of future mailbox methods, and "Status Methods", which report on the affects of previous mailbox methods.

Methods that do not result in new IMAP client commands being issued (such as the "Transaction", "Status", and "History" methods) all begin with an uppercase letter, to distinguish them from methods that do correspond to IMAP client commands. Class methods and eponymous parameter methods likewise begin with an uppercase letter because they also do not correspond to an IMAP client command.

As a general rule, mailbox control methods return "undef" on failure and something besides "undef" when they succeed. This rule is modified in the case of methods that return search results. When called in a list context, searches that do not find matching results return an empty list. When called in a scalar context, searches with no hits return 'undef' instead of an array reference. If you want to know why you received no hits, you should check "LastError" or $@, which will be empty if the search was successful but had no matching results but populated with an error message if the search encountered a problem (such as invalid parameters).

A number of IMAP commands do not have corresponding Mail::IMAPClient methods. Patches are welcome. In the pre-2.99 releases of this module, they were automatically created (AUTOLOAD), but that was very error-prone and stalled the progress of this module.

append

Ejemplo:

my $new_msg_uid = $imap->append(
    $folder,
    $flags,
    $date,
    $message
) or die "Could not append: ", $imap->LastError;

El método append añade una mensaje a la carpeta especificada. Nota: los corchetes en el ejemplo indican argumentos opcionales; no significan que el argumento debe ser una referencia de array.

Argumentos:

$folder
el nombre de la carpeta a la que se añade la mensaje
$flags

Un argumento opcional que consiste en una lista de flags como se describe en RFC2060 (sección 5.3). El valor "\\Seen" se usa a menos que se especifique lo contrario.

Ejemplo:

my @flags = ( "\\Flagged", "\\Deleted" );
    $imap->append($folder, \@flags, undef, $message);
$date
Un argumento opcional de fecha RFC3501 para establecer como fecha interna. Debe estar en el formato descrito para date_time en RFC3501, es decir, "dd-Mon-yyyy hh:mm:ss +0000".

Si quieres especificar una fecha/hora pero no quieres ningún indicador, especifica undef como el tercer ($flags) argumento.

Devuelve:

error: undef
En caso de error, undef puede devolverse independientemente del contexto LIST/SCALAR. Comprueba "LastError" para detalles.
success: UID o $imap
Con UIDPLUS, el UID de la nueva mensaje se devuelve; de lo contrario, un valor verdadero (actualmente $self) se devuelve.

Para proteger contra "bare newlines", append insertará un retorno de carro antes de cualquier nueva línea que sea "bare".

append_file

Ejemplo:

my $new_msg_uid = $imap->append_file(
    $folder,
    $file,
    [ undef, $flags, $date ] # opcional
) or die "Could not append_file: ", $imap->LastError;

El método append_file añade una mensaje a la carpeta especificada. Nota: los corchetes en el ejemplo indican argumentos opcionales; no significan que el argumento debe ser un referencia de array.

Argumentos:

$folder
el nombre de la carpeta a la que se añade la mensaje
$file
un nombre de archivo, handle de archivo o referencia de SCALAR que contiene un mensaje RFC822-formatted
undef
un argumento obsoleto usado como placeholder de compatibilidad
$flags
El argumento opcional se trata igual que append_string.
$date
El argumento opcional se trata igual que append_string (fecha RFC3501), excepto que si $date es "1" (uno), entonces se usará la fecha de modificación (mtime) del archivo.

Devuelve:

error: undef
En error, undef puede devolverse independientemente del contexto LIST/SCALAR. Comprueba "LastError" para detalles.
success: UID o $imap
Con UIDPLUS, el UID de la nueva mensaje se devuelve; de lo contrario, un valor verdadero (actualmente $self) se devuelve.

Para proteger contra "bare newlines", append_file insertará un retorno de carro antes de cualquier nueva línea que sea "bare".

El método append_file proporciona un mecanismo para agregar mensajes grandes sin tener que almacenar el archivo completo en memoria.

Nota de versión: En 2.x se permitía un tercer argumento opcional para usar como "input_record_separator", pero este argumento se ignora / no se soporta desde 3.x.

authenticate

Ejemplo:

$imap->authenticate( $authentication_mechanism, $coderef )
  or die "Could not authenticate: ", $imap->LastError;

Este método implementa el comando AUTHENTICATE del cliente IMAP. Puede llamarse directamente o puede llamarse por "login" si el parámetro "Authmechanism" está establecido en algo diferente a "LOGIN".

El método authenticate acepta dos argumentos, un tipo de autenticación (por ejemplo CRAM-MD5) y una referencia de código o procedimiento para ejecutar para obtener una respuesta. El método authenticate asume que el tipo de autenticación especificado en el primer argumento sigue un flujo de desafío-respuesta. El método authenticate emite el comando AUTHENTICATE del cliente IMAP y recibe un desafío de la servidor. El desafío (sin prefijo de etiqueta o caracteres encadenados + pero en el original de codificación base64) se pasa como el único argumento al código o procedimiento referenciado en el segundo argumento. El valor devuelto por el código del segundo argumento se escribe al servidor como es, excepto que un <CR><LF> se agrega si es necesario.

Si uno o ambos argumentos no están especificados en la llamada a authenticate pero sus parámetros correspondientes han sido establecidos ("Authmechanism" y "Authcallback"), entonces los valores de los parámetros se utilizan. Los argumentos proporcionados a la llamada al método, sin embargo, sobreponen los valores de parámetros.

Si no especificas un segundo argumento y no has establecido el parámetro "Authcallback", entonces el primer argumento debe ser uno de los mecanismos de autenticación que Mail::IMAPClient ha construido en su propio soporte.

Ver también el método "login", que es la forma más sencilla de autenticación definida por RFC3501.

before

Ejemplo:

my @msgs = $imap->before($Rfc3501_date)
  or warn "No messages found before $Rfc3501_date.\n";

El método before funciona como el método "since", a continuación, excepto que devuelve una lista de mensajes cuyas fechas internas son antes que la fecha proporcionada como el argumento al método before.

body_string

Ejemplo:

my $string = $imap->body_string($msgId)
  or die "body_string failed: ", $imap->LastError;

El método body_string acepta un número de mensaje (o un UID de mensaje, si el parámetro "Uid" está establecido en true) como argumento y devuelve el cuerpo del mensaje como una cadena. El valor devuelto contiene el cuerpo completo del mensaje en una variable escalar sin los encabezados del mensaje.

bodypart_string

Ejemplo:

my $string = $imap->bodypart_string(
    $msgid, $part_number, $length, $offset
) or die "Could not get bodypart string: ", $imap->LastError;

El método bodypart_string acepta un número de mensaje (o un UID de mensaje, si el parámetro "Uid" está establecido en true) y una parte del mensaje como argumentos y devuelve el cuerpo del mensaje como una cadena. El valor devuelto contiene el cuerpo completo del mensaje (o, opcionalmente, una parte del cuerpo) en una variable escalar.

Si se proporciona un tercer argumento opcional, éste es el número de bytes a recuperar. (El valor predeterminado es el cuerpo completo del mensaje). Si se proporciona un cuarto argumento opcional, éste es el desplazamiento dentro del cuerpo a partir del cual se debe comenzar la recuperación. El valor predeterminado es el desplazamiento 0, o el principio del cuerpo del mensaje.

Si especificas un desplazamiento sin especificar un largo, el desplazamiento se ignorará y el cuerpo completo se devolverá.

bodypart_string devolverá "undef" si encuentra un error.

capability

Ejemplo:

my $features = $imap->capability
  or die "Could not determine capability: ", $imap->LastError;

El método capability devuelve un array (o arrayref en contexto escalar) de capacidades como se devuelve por el comando CAPABILITY del cliente IMAP. Si el comando CAPABILITY del cliente IMAP falla por cualquier razón, el método capability devolverá "undef". Las capacidades soportadas se guardan en el cliente, sin embargo, este caché se elimina después de que la conexión se establezca en Authenticated y cuando se llama a "starttls".

Ver también "has_capability".

close

Ejemplo:

$imap->close or die "Could not close: $@\n";

El método close se usa para cerrar la carpeta actual seleccionada mediante el comando CLOSE del cliente IMAP. Según RFC3501, el comando CLOSE realiza un EXPUNGE implícito, lo que significa que cualquier mensaje marcado como \Deleted (es decir, con el método "delete_message") ahora será eliminado. Si no has eliminado ningún mensaje, close puede pensarse como un "unselect".

Nota: este cierre la carpeta actual seleccionada, no la sesión IMAP.

Ver también "delete_message", "expunge", y RFC3501.

compress

Ejemplo:

$imap->compress or die "Could not enable RFC4978 compression: $@\n";

El método compress acepta ningún argumento. Este método se utiliza para instruir al servidor para usar la extensión DEFLATE (RFC1951) de compresión. Consulta la atribución "Compress" para saber cómo especificar los argumentos durante el proceso de inicialización.

Nota de versión: el método fue agregado en Mail::IMAPClient 3.30.

connect

Ejemplo:

$imap->connect or die "Could not connect: $@\n";

El método connect conecta un objeto imap al servidor. Devuelve "undef" si falla en la conexión. Si valores están disponibles para los parámetros "User" y "Password" al momento de invocar connect, entonces connect llamará al método "login" después de la conexión y devolverá el resultado del método "login" al llamador de connect. Si ninguno de los parámetros "User" o "Password" está disponible, pero la conexión al servidor se establece correctamente, connect devolverá un puntero al objeto IMAPClient.

El parámetro "Server" debe ser establecido (durante la invocación de método "new" o mediante el método "Server" del objeto) antes de invocar connect. Cuando el parámetro es un caminho absoluto de archivo, se abrirá un UNIX socket. Si el parámetro "Server" se proporciona al método "new", entonces connect se llama implícitamente durante la construcción del objeto.

El método connect establece el estado del objeto a "Connected" si se conecta correctamente al servidor. Devuelve "undef" en caso de falla.

create

Ejemplo:

$imap->create($new_folder)
  or die "Could not create $new_folder: $@\n";

El método create acepta un argumento, el nombre de una carpeta (o lo que RFC3501 llama un "mailbox") a crear. Si especificas otros argumentos a la método create y tu servidor permite argumentos adicionales a la comandos CREATE IMAP cliente, los argumentos adicionales serán pasados al servidor.

Ejemplo:

my $date = $imap->date($msg);

El método date acepta un argumento, un número de secuencia de mensaje (o un número de UID si el parámetro "Uid" está set a un valor verdadero). Devuelve la fecha del mensaje según el encabezado RFC822 "Date: " del mensaje, sin la preposición "Date: ".

El método date es un abreviado para:

my $date = $imap->get_header($msg,"Date");

Ejemplo:

$imap->delete($folder) or die "Could not delete $folder: $@\n";

El método delete acepta un argumento, el nombre de una carpeta a eliminar. Devuelve un valor verdadero en caso de éxito y "undef" en caso de error.

deleteacl

Ejemplo:

$imap->deleteacl( $folder, $userid )
  or die "Could not delete acl: $@\n";

El método deleteacl acepta dos argumentos, el nombre de una carpeta y un usuario id (o identificador de autenticación, para usar el lenguaje de RFC2086). Ver RFC2086 para más información. (Este es un poco experimental y su implementación podría cambiar.)

delete_message

Ejemplo:

my @msgs = $imap->seen;
scalar(@msgs) and $imap->delete_message(\@msgs)
  or die "Could not delete_message: $@\n";

El ejemplo anterior podría también ser escrito así:

# contexto de scalars retorna un ref a array
my $msgs = scalar($imap->seen);
scalar(@$msgs) and $imap->delete_message($msgs)
  or die "Could not delete_message: $@\n";

O, como una línea única:

$imap->delete_message( scalar($imap->seen) )
  or warn "Could not delete_message: $@\n";
# solo da un aviso en caso de error
# debido a que no hay mensajes 'seen' en el 1er lugar!

El método delete_message acepta una lista de argumentos. Si el parámetro "Uid" no está set a un valor verdadero, cada elemento en la lista debe ser:

  • un número de secuencia de mensaje,
  • una lista separada por comas de números de secuencia de mensaje,
  • un referencia a un array de números de secuencia de mensaje,

Si el parámetro "Uid" está set a un valor verdadero, cada elemento en la lista debe ser:

  • un número de UID,
  • una lista separada por comas de números de UID,
  • un referencia a un array de números de UID.

Los mensajes identificados por los números de secuencia o UID serán eliminados. Si es exitoso, delete_message devuelve el número de mensajes que fue indicado para eliminar. Sin embargo, dado que la eliminación se realiza mediante la opción +FLAGS.SILENT del comandos STORE IMAP cliente, no se puede garantizar que la eliminación sea exitosa para cada mensaje. Así, el método delete_message sacrifica la precisión por la velocidad. Generalmente, aunque un mensaje en una lista de mensajes no sea eliminado, es porque ya fue eliminado, lo cual es lo que deseas, así que por qué preocuparte? Si hay un error más grave, como el servidor responde con "NO" o "BAD" o, si quieres, "BYE", entonces delete_message devolverá "undef".

Si necesitas resultados garantizados, usa el comandos STORE IMAP cliente (vía el método predeterminado) y usa la opción +FLAGS (\Deleted), y luego parsea tus resultados manualmente.

Ejemplo:

$imap->store( $msg_id, '+FLAGS (\Deleted)' );
my @results = $imap->History( $imap->Transaction );
  ...           # código para parsear la salida va aquí

(Frankamente no veo la necesidad de preocuparme por todo eso; si un mensaje no se elimina, es casi siempre porque ya no está allí, lo cual es lo que deseas. Pero 'tu mileage may vary' y todo eso.)

El objeto IMAPClient debe estar en el estado "Selected" para usar el método delete_message.

NOTA: Todos los mensajes identificados en los argumentos (solo uno o más) deben estar en la carpeta actualmente seleccionada. La no cumplir con esta exigencia probablemente resultará en el mensaje incorrecto ser eliminado.

ADICIONAL NOTA: Al traducir el protocolo IMAP, eliminar un mensaje no realmente lo elimina. De hecho, si quieres asegurarte de que el mensaje haya sido eliminado, necesitas expulsar la carpeta (vía el método "expunge", que se implementa mediante el método predeterminado). O al menos, cierra la carpeta. Este es generalmente considerado una característica, ya que después de eliminar un mensaje puedes cambiar de opinión y desloguearlo cualquier tiempo antes de tu "expunge" o "close".

Ver también: el método "delete" para eliminar una carpeta, el método "expunge" para expulsar una carpeta, el método "restore_message" para desloguear un mensaje, y el método "close" (implementado aquí mediante el método predeterminado) para cerrar una carpeta. ¿No olvides RFC3501?

done

Ejemplo:

my $tag = $imap->idle or warn "idle failed: $@\n";
doSomethingA();
my $idlemsgs = $imap->idle_data() or warn "idle_data error: $@\n";

El método done dice al servidor IMAP que termine la ejecución del comando IDLE. El único argumento es el tag (identificador) recibido de la anterior llamada a "idle". Si tag no se especifica, se asume un tag basado en el atributo Count como el tag a buscar en la respuesta del servidor.

fetch

Usage:

$imap->fetch( [$seq_set|ALL], @msg_data_items )

Example:

my $output = $imap->fetch(@args) or die "Could not fetch: $@\n"

El método fetch implementa el comando del cliente IMAP FETCH. Acepta una lista de argumentos, que se convertirán en una lista de argumentos separados por espacios para el comando del cliente IMAP FETCH. Si no se proporcionan argumentos, fetch realiza un FETCH ALL. Si el parámetro "Uid" se establece en un valor verdadero, el primer argumento se tratará como un UID o una lista de UID, lo que significa que se ejecutará el comando del cliente IMAP UID FETCH en lugar de FETCH. (Sería una muy buena idea en este punto revisar RFC3501).

Si se llama en contexto de array, fetch devolverá un array de líneas de salida. Las líneas de salida se devolverán tal como se recibieron del servidor, por lo que tu script tendrá que estar preparado para analizar las partes que necesitas. La única excepción son las cadenas literales, que se insertarán en la línea de salida en el punto en que se encontraron (sin el indicador de campo literal {nnn}). Consulte RFC3501 para obtener una descripción de los campos literales.

Si fetch se llama en un contexto escalar, en su lugar se devolverá una referencia a un array (como se describe anteriormente) en lugar de todo el array.

fetch devuelve "undef" en caso de fallo. Inspecciona "LastError" o $@ para obtener una explicación de tu error.

fetch_hash

Usage:

$imap->fetch_hash( [$seq_set|ALL], @msg_data_items, [\%msg_by_ids] )

Examples:

 my $hashref = $imap->fetch_hash("RFC822.SIZE")
OR
 my $hashref = {}
 $imap->fetch_hash( "RFC822.SIZE", $hashref )
 print "Msg #$_ is $hashref->{$_}->{'RFC822.SIZE'} bytes\n" for (keys %$hashref)

El método fetch_hash acepta una lista de atributos de mensaje para ser recuperados (como se describe en RFC3501). Devuelve un hash cuyas claves son todos los mensajes de la carpeta seleccionada actualmente y cuyos valores son pares clave-valor de palabras clave de recuperación y el valor del mensaje para esa palabra clave (ver ejemplo de salida a continuación).

Si fetch_hash se llama en contexto escalar, devuelve una referencia al hash en lugar del hash mismo. Si el último argumento es una referencia a un hash, entonces esa referencia a un hash se utilizará como el lugar donde se almacenan los resultados (y esa referencia se devolverá al completarse con éxito). Si el último argumento no es una referencia, se tratará como uno de los atributos de FETCH y se creará un nuevo hash y se devolverá (ya sea por valor o por referencia, dependiendo del contexto en el que se llamó a fetch_hash).

Por ejemplo, si tienes una carpeta con 3 mensajes y quieres el tamaño y la fecha interna de cada uno de ellos, puedes hacer lo siguiente:

use Mail::IMAPClient;
use Data::Dumper;
# ... otro código va aquí
$imap->select($folder);
my $hash = $imap->fetch_hash( "RFC822.SIZE", "INTERNALDATE" );
# (Igual que:
#  my $hash = $imap->fetch_hash("RFC822.SIZE");
#  $imap->fetch_hash( "INTERNALDATE", $hash );
# ).
print Data::Dumper->Dumpxs( [$hash], ['$hash'] )

Esto resultaría en una salida de Data::Dumper similar a la siguiente:

$hash = {
    '1' => {
               'INTERNALDATE' => '21-Sep-2002 18:21:56 +0000',
               'RFC822.SIZE' => '1586',
           },
    '2' => {
               'INTERNALDATE' => '22-Sep-2002 11:29:42 +0000',
               'RFC822.SIZE' => '1945',
           },
    '3' => {
               'INTERNALDATE' => '23-Sep-2002 09:16:51 +0000',
               'RFC822.SIZE' => '134314',
           }
  }

Por sí solo, este método puede ser útil para tareas como obtener el tamaño de cada mensaje en una carpeta. Emite un comando y recibe una respuesta (posiblemente larga!) del servidor.

Si la solicitud de recuperación hace que el servidor devuelva datos en una lista entre paréntesis, los datos dentro de la lista entre paréntesis pueden ser escapados a través del método Escape(). Usa el método Unescape() para obtener los valores sin procesar en este caso.

flags

Example:

my $flags = $imap->flags($msgid)
  or die "flags failed: $@\n"

El método flags implementa el comando del cliente IMAP FETCH para listar las banderas de un solo mensaje. Acepta un argumento, un número de secuencia de mensaje (o un UID de mensaje, si el parámetro "Uid" es verdadero), y devuelve un array (o una referencia a un array, si se llama en contexto escalar) que lista las banderas que se han establecido. Los nombres de las banderas se proporcionan con barras invertidas iniciales.

A partir de la versión 1.11, puedes proporcionar ya sea una lista de IDs de mensajes o una referencia a un array de IDs de mensajes (lo que significa ya sea un número de secuencia, si el parámetro Uid es falso, o UIDs de mensajes, si el parámetro Uid es verdadero) en lugar de proporcionar un solo número de secuencia de mensaje o UID. Si lo haces, el valor de retorno no será un array o una referencia a un array; en su lugar, será una referencia a un hash, con cada clave siendo un número de secuencia de mensaje (o UID) y cada valor siendo una referencia a un array de banderas establecidas para ese mensaje.

Por ejemplo, si deseas mostrar las banderas de cada mensaje en la carpeta donde guardas correos electrónicos relacionados con tus planes de dominación mundial, podrías hacer algo como esto:

use Mail::IMAPClient;
my $imap = Mail::IMAPClient->new(
    Server   => $imaphost,
    User     => $login,
    Password => $pass,
    Uid      => 1,        # opcional
);
$imap->select($folder);
# obtener las banderas de cada mensaje en mi carpeta 'World Domination'
$flaghash = $imap->flags( scalar( $imap->search("ALL") ) );
# bombear a través de las claves de hash ordenadas para imprimir resultados:
for my $k ( sort { $flaghash->{$a} <=> $flaghash->{$b} } keys %$flaghash ) {
    # imprimir: Mensaje 1: \Flag1, \Flag2, \Flag3
    print "Message $k:\t", join( ", ", @{$flaghash->{$k}} ), "\n";
}

folders

Example:

$imap->folders or die "Could not list folders: $@\n"

El método folders devuelve un array que lista las carpetas disponibles. Solo tendrá éxito si el objeto está en los estados Authenticated o Selected.

El método folders acepta un argumento opcional, que es un prefijo. Si se proporciona un prefijo al método folders, entonces solo se devolverán las carpetas que comiencen con ese prefijo.

Por ejemplo:

print join( ", ", $imap->folders ), ".\n"
# Imprime:
# INBOX, Sent, Projects, Projects/Completed, Projects/Ongoing, Projects Software.
print join( ", ", $imap->folders("Projects") ), ".\n"
# Imprime:
# Projects, Projects/Completed, Projects/Ongoing, Projects Software.
print join( ", ", $imap->folders("Projects" . $imap->separator) ), ".\n"
# Imprime:
# Projects/Completed, Projects/Ongoing

Tenga en cuenta que la documentación sugería anteriormente que si solo desea listar las subcarpetas de una carpeta (y no la carpeta en sí), necesita incluir el carácter separador de jerarquía (tal como lo devuelve el método "separator"). Sin embargo, esto no coincide con el comportamiento de la implementación existente, por lo que deberá excluir manualmente la carpeta principal de los resultados.

folders_hash

my @fhashes = $imap->folders_hash
  or die "Could not get list of folder hashes.\n"

El método folders_hash acepta un argumento opcional, que es un prefijo. Si se proporciona un prefijo al método folders_hash, entonces solo se devolverán las carpetas que comiencen con ese prefijo.

Se devuelve un array (o una referencia a un array) de hashes que contiene información sobre las carpetas solicitadas. Cada hash contiene tres claves (name, attrs, delim) y se ve así:

{
  name  => 'Mail/Box/Name',
  attrs => [ '\Marked', '\HasNoChildren' ],
  delim => '/',
}

Los servidores IMAP que implementan RFC6154 devuelven atributos para ser utilizados para identificar buzones de correo especiales (carpetas).

my $sattr_re = /\A\\(?:All|Archive|Drafts|Flagged|Junk|Sent|Trash)\Z/;
foreach my $fhash (@fhashes) {
    next unless defined $fhash->{name};
    my @special = grep { $sattr_re } @{ $fhash->{attrs} };
    print("special: $fhash->{name} : @special\n") if (@special);
}

has_capability

Ejemplo:

my $has_feature = $imap->has_capability($feature)
  or die "Could not do has_capability($feature): $@\n";

Devuelve:

"undef"
Si la llamada bajo la capa "capability" falla, se devuelve "undef".
"" o "()"
Si el servidor no tiene la capacidad solicitada, se devuelve una cadena vacía ("" en contexto escalar) o una lista vacía ("()" en contexto lista).
un valor true
Si el servidor tiene la capacidad solicitada, se devuelve un valor true. El valor true depende del resultado del servidor para la capacidad solicitada. El valor se devuelve como una referencia a un array en contexto escalar o un array en contexto lista. El dato devuelto es útil para entender más sobre las capacidades específicas. Por ejemplo, considera el siguiente ejemplo de respuesta de CAPABILITY del servidor: 
* CAPABILITY IMAP4rev1 SORT SORT=DISPLAY I18NLEVEL=1 AUTH=PLAIN AUTH=XTEST

Los resultados se devuelven como se muestra en los comentarios al final:

$c = $imap->has_capability("IMAP4rev1");    # [ "IMAP4rev1" ]
@c = $imap->has_capability("IMAP4rev1");    # ( "IMAP4rev1" )
$c = $imap->has_capability("SORT");         # [ "DISPLAY" ]
@c = $imap->has_capability("SORT=DISPLAY"); # ( "SORT=DISPLAY" )
$c = $imap->has_capability("AUTH");         # [ "PLAIN", "XTEST" ]
@c = $imap->has_capability("AUTH");         # ( "PLAIN", "XTEST" )
$c = $imap->has_capability("AUTH=XTEST");   # [ "AUTH=XTEST" ]
@c = $imap->has_capability("AUTH=XTEST");   # ( "AUTH=XTEST" )
$c = $imap->has_capability("AUTH=NADA");    # ''
@c = $imap->has_capability("AUTH=NADA");    # ()
$c = $imap->has_capability("NADA");         # ''
@c = $imap->has_capability("NADA");         # ()

idle

Ejemplo:

my $tag = $imap->idle or warn "idle failed: $@\n";
doSomethingA();
my $idlemsgs = $imap->idle_data() or warn "idle_data error: $@\n";
doSomethingB();
my $results = $imap->done($tag) or warn "Error from done: $@\n";

El método idle envía al servidor IMAP que el cliente está listo para aceptar mensajes de actualización de carpeta (en la carpeta seleccionada) sin solicitud. Este método solo es válido en servidores que soportan la extensión IMAP IDLE; consulta RFC2177 para más detalles.

El método idle no acepta argumentos y devuelve el tag (identificador) enviado por el cliente para este comando. Este tag debe ser proporcionado como argumento a la función done cuando se termine el comando IDLE.

En caso de error, se devuelve "undef" y se establece "LastError".

El método idle_data puede utilizarse una vez que el comando idle ha sido exitoso. Sin embargo, no se pueden realizar operaciones de carpeta hasta que el comando idle se termine llamando a done. No hacerlo resultará en un error y el comando idle será terminado generalmente por el servidor.

idle_data

Uso:

# se puede especificar un tiempo de espera opcional en segundos
$imap->idle_data( [$timeout] )

Ejemplo:

my $tag = $imap->idle or warn "idle failed: $@\n";
doSomethingA();
my $idlemsgs = $imap->idle_data() or warn "idle_data error: $@\n";

El método idle_data puede utilizarse para aceptar cualquier mensaje de actualización de carpeta sin solicitud que haya sido enviado por el servidor durante un comando idle. Este método no envía ningún comando al servidor; simplemente espera y devuelve los datos del servidor al llamador.

El método idle_data acepta un argumento opcional $timeout y devuelve una lista (o una referencia a una lista si se llama en contexto escalar) con los mensajes del servidor.

Por defecto, se usa un tiempo de espera de 0 segundos (no bloqueante). Internamente, el tiempo de espera se pasa a select en perlfunc. El tiempo de espera controla cuánto tiempo se bloquea la llamada a select si no hay mensajes esperando a ser leídos del servidor.

En caso de error, se devuelve "undef" y se establece "LastError".

namespace

Ejemplo:

my $refs = $imap->namespace
  or die "namespace failed: $@\n";

El método namespace ejecuta el comando IMAP NAMESPACE (según se define en RFC 2342). Cuando se llama en contexto de lista, devuelve una lista de tres referencias. Cada referencia se ve así:

[
  [ $prefix_1, $separator_1 ],
  [ $prefix_2, $separator_2 ],
  [ $prefix_n, $separator_n ],
]

La primera referencia proporciona una lista de prefijos y caracteres separadores para los espacios de nombres personales disponibles. La segunda referencia proporciona una lista de prefijos y caracteres separadores para los espacios de nombres compartidos disponibles. La tercera referencia proporciona una lista de prefijos y caracteres separadores para los espacios de nombres públicos disponibles.

Si alguno de los tres espacios de nombres no está disponible en el servidor actual, se devuelve un 'undef' en lugar de una referencia. Así, por ejemplo, si las carpetas compartidas no eran compatibles con el servidor pero los espacios de nombres personales y públicos estaban ambos disponibles (con un espacio de nombres cada uno), el valor devuelto podría parecerse a esto:

[ [ "", "/" ] , undef, [ "#news", "." ] ];

Si el método namespace se llama en contexto escalar, devuelve una referencia a la lista de tres referencias mencionada anteriormente, creando así una única estructura que se imprimiría de forma agradable algo así como esto:

$VAR1 = [
    [
        [ $user_prefix_1, $user_separator_1 ],
        [ $user_prefix_2, $user_separator_2 ],
        [ $user_prefix_n, $user_separator_n ],
    ],                    # o undef
    [
        [ $shared_prefix_1, $shared_separator_1 ],
        [ $shared_prefix_2, $shared_separator_2 ],
        [ $shared_prefix_n, $shared_separator_n ],
    ],                    # o undef
    [
        [ $public_prefix_1, $public_separator_1 ],
        [ $public_prefix_2, $public_separator_2 ],
        [ $public_prefix_n, $public_separator_n ],
    ],                    # o undef
];

      (ORCPT rfc822;big.shot@bigco.com); Fri, 18 Jun 1999 16:29:05 +0000 (GMT)
      /, q/
      from someplace ([999.9.99.99]) by smtp-relay.bigco.com (PMDF V5.2-31 #38473)

Los valores reales devueltos son solo cadenas de palabras separadas por espacios y con saltos de línea y retornos de carro eliminados. Si el primer argumento es una referencia a un arreglo de números de secuencia de mensajes (o UID's si "Uid" es verdadero), entonces parse_headers se ejecutará contra cada mensaje en el arreglo. En este caso, el valor de retorno es un hash, en el que la clave es el número de secuencia del mensaje (o UID) y el valor es una referencia a un hash como se describe anteriormente.

Un ejemplo de uso de parse_headers para imprimir la fecha y el asunto de cada mensaje en su carpeta de demostración podría verse así:

use Mail::IMAPClient;
my $imap = Mail::IMAPClient->new(
    Server => $imaphost, User => $login, Password => $pass, Uid => 1
);
$imap->select("demo");
my $msgs = $imap->search("ALL");
for my $h (
 # obtener el Asunto y la Fecha de cada mensaje en la carpeta "demo"
 # el primer argumento es una referencia a un arreglo que lista todos los mensajes en la
 # carpeta (que es lo que devuelve el método $imap->search("ALL")
 # cuando se llama en contexto escalar y los argumentos restantes
 # son los campos a parsear. La clave es el número de mensaje, que
 # en este caso no nos importa:
  values %{ $imap->parse_headers( $msgs , "Subject", "Date") } )
{
    # $h es el valor de cada elemento en el ref del hash devuelto
    # de parse_headers, y $h también es una referencia a un hash.
    # Solo imprimiremos la primera ocurrencia de cada campo porque
    # no esperamos más de una línea Date: o Subject: por
    # mensaje.
    print map { "$_:\t$h->{$_}[0]\n"} keys %$h;
}

search

Example:

my @msgs = $imap->search( "Unseen" )
  or die "search failed: $@\n";

The search method accepts a list of arguments, which are all passed on to the IMAP client command SEARCH. The arguments are taken as a list in the normal perl fashion. In other words, "$imap->search(@args)" is precisely equivalent to "$imap->search( $args[0], $args[1], ..., $args[n] )". This is the simplest, and most direct, way to invoke the IMAP SEARCH command.

Alternatively, you can specify arguments as scalar references (SCALAR). In this case, the values of those scalar references are passed along as-is.

The search arguments can be:

  • any of the standard IMAP SEARCH keyvalues, quoted as necessary.
  • a reference to an array of strings, each of which will be passed along as a separate argument to the IMAP server.
  • a reference to a scalar, which will be passed along as-is.

Note that it is your responsibility to ensure that the data sent in these cases is properly escaped/quoted):

  • specify a single string/argument in the call to search.
  • specify args as scalar references (SCALAR) and the values of those SCALAR refs will be passed along as-is.

The search method returns an array containing sequence numbers of messages that passed the SEARCH IMAP client command's search criteria. If the "Uid" parameter is true then the array will contain message UID's. If search is called in scalar context then a pointer to the array will be passed, instead of the array itself. If no messages meet the criteria then search returns an empty list (when in list context) or "undef" (in scalar context).

Since a valid, successful search can legitimately return zero matches, you may wish to distinguish between a search that correctly returns zero hits and a search that has failed for some other reason (i.e. invalid search parameters). Therefore, the $@ variable will always be cleared before the SEARCH command is issued to the server, and will thus remain empty unless the server gives a BAD or NO response to the SEARCH command.

sentsince

Example:

my @msgs = $imap->sentsince($Rfc3501_date)
  or warn "Could not find any messages sent since $Rfc3501_date: $@\n";

The sentsince method accepts one argument, a date in either epoch time format (seconds since 1/1/1970, or as output by time and as accepted by localtime) or in the date_text format as defined in RFC3501 (dd-Mon-yyyy, where Mon is the English-language three-letter abbreviation for the month).

It searches for items in the currently selected folder for messages sent since the day whose date is provided as the argument. It uses the RFC822 Date: header to determine the sentsince date. (Actually, it the server that uses the Date: header; this documentation just assumes that the date is coming from the Date: header because that's what RFC3501 dictates.)

In the case of arguments supplied as a number of seconds, the returned result list will include items sent on or after that day, regardless of whether they arrived before the specified time on that day. The IMAP protocol does not support searches at a granularity finer than a day, so neither do I. On the other hand, the only thing I check for in a date_text argument is that it matches the pattern "/\d\d-\D\D\D-\d\d\d\d/" (notice the lack of anchors), so if your server lets you add something extra to a date_text string then so will Mail::IMAPClient.

If you'd like, you can use the "Rfc3501_date" method to convert from epoch time (as returned by time) into an RFC3501 date specification.

SORT

Example:

my @msgs = $imap->sort(@args);
warn "Error in sort: $@\n" if $@;

The sort method is just like the "search" method, only different. It implements the SORT extension as described in https://tools.ietf.org/html/rfc5256. It would be wise to use the "has_capability" method to verify that the SORT capability is available on your server before trying to use the sort method. If you forget to check and you're connecting to a server that doesn't have the SORT capability then sort will return undef. "LastError" will then say you are "BAD". If your server doesn't support the SORT capability then you'll have to use "search" and then sort the results yourself.

The first argument to sort is a space-delimited list of sorting criteria. The Internet Draft that describes SORT requires that this list be wrapped in parentheses, even if there is only one sort criterion. If you forget the parentheses then the sort method will add them. But you have to forget both of them, or none. This isn't CMS running under VM!

The second argument is a character set to use for sorting. Different character sets use different sorting orders, so this argument is important. Since all servers must support UTF-8 and US-ASCII if they support the SORT capability at all, you can use one of those if you don't have some other preferred character set in mind.

The rest of the arguments are searching criteria, just as you would supply to the "search" method. These are all documented in RFC3501. If you just want all of the messages in the currently selected folder returned to you in sorted order, use ALL as your only search criterion.

The sort method returns an array containing sequence numbers of messages that passed the SORT IMAP client command's search criteria. If the "Uid" parameter is true then the array will contain message UIDs. If sort is called in scalar context then a pointer to the array will be passed, instead of the array itself. The message sequence numbers or unique identifiers are ordered according to the sort criteria specified. The sort criteria are nested in the order specified; that is, items are sorted first by the first criterion, and within the first criterion they are sorted by the second criterion, and so on.

The sort method will clear $@ before attempting the SORT operation just as the "search" method does.

UIDVALIDITY

Example:

my $validity = $imap->uidvalidity($folder)
  or die "uidvalidity failed: $@\n";

The uidvalidity method accepts one argument, the name of a folder, and returns the numeric string that is the unique identifier validity value for the folder.

SEE

Example:

my @msgs = $imap->see( $folder );

The see method is a shorthand for:

$imap->select($folder, {seen => 1});

It selects the specified folder and marks all messages as seen. It returns the list of sequence numbers of messages that were selected.

If the Uid parameter is true, then UIDs will be returned instead of message sequence numbers.

SELECT

Example:

my $count = $imap->select( 'INBOX' )
  or die "Could not select INBOX: $@\n";

The select method selects a specified folder (or mailbox) to be the currently active folder. This is necessary before you can perform most operations, such as search, expunge, or fetch messages. The select method returns the number of messages in the folder.

The IMAPClient object must not be connected to a folder when calling this method.

The select method accepts optional arguments that control how the folder is selected. These arguments are passed as a hash reference. The following options are supported:

seen
If true, all messages in the folder will be marked as seen. Defaults to false.
uidvalidity
If true, the UIDVALIDITY command will be issued, and the results stored in the $imap->{'uidvalidity'} attribute. Defaults to false.
uidnext
If true, the UIDNEXT command will be issued, and the results stored in the $imap->{'uidnext'} attribute. Defaults to false.
uid
If true, the UID command will be issued for all messages, and the results stored in the $imap->{'uid'} attribute. Defaults to false.

Example with options:

my $count = $imap->select( 'INBOX', { uidvalidity => 1, uidnext => 1 } )
  or die "Could not select INBOX: $@\n";

sendmail

Example:

$imap->sendmail(...) or die ...;

The sendmail method is a wrapper around the standard Perl sendmail function. It takes the same arguments, and passes them directly to the underlying sendmail call.

Note that this method is intended for use with Mail::IMAPClient's Mbox.pm module, and is generally not useful otherwise.

server_welcome_message

Example:

my $welcome = $imap->server_welcome_message;

Returns the server's welcome message, which is typically the first line of text sent by the server after the connection is established.

set_flag

Example:

$imap->set_flag( $msg, '\Seen' );

The set_flag method adds the specified flag to the message. This method accepts a message sequence number (or UID if Uid is true) and a flag name. Multiple flags can be specified.

This method is a wrapper around the store method.

set_flags

Example:

$imap->set_flags( $msg_list, '\Seen', '\Answered' );

The set_flags method adds the specified flags to the messages. This method accepts a list of message sequence numbers (or UIDs if Uid is true) and one or more flag names.

This method is a wrapper around the store method.

set_quota_root

Example:

$imap->set_quota_root('INBOX', 'bytes', 1000000);

The set_quota_root method allows you to set the quota for a given quota root. This method takes the quota root name, the resource type (e.g., 'bytes' or 'messages'), and the quota limit as arguments.

Note that this method requires the QUOTA extension to be enabled on the server.

socket

Example:

my $sock = $imap->socket;

Returns the IO::Socket object used for the connection.

socket_read

Example:

my $bytesread = $imap->socket_read($buffer, $maxlen, $timeout) or die ...;

Reads up to $maxlen bytes from the socket into $buffer. Takes an optional $timeout argument. Returns the number of bytes read, or undef on error.

socket_write

Example:

my $byteswritten = $imap->socket_write($data) or die ...;

Writes the contents of $data to the socket. Returns the number of bytes written, or undef on error.

sort_criteria

Example:

my $criteria = $imap->sort_criteria();

Returns the list of sort criteria currently in effect for the IMAPClient object.

sort_folder

Example:

my @sorted_folders = $imap->sort_folder( $folder_list, $criteria );

Sorts a list of folder names according to the specified criteria. The $criteria argument should be a string like "DATE" or "SIZE".

This method is primarily intended for use with the folders method, to sort the list of available folders.

starttls_args

Example:

my $args = $imap->starttls_args;

Returns the arguments that will be used when calling IO::Socket::SSL::start_SSL during a starttls operation.

unmark

Ejemplo:

$imap->unmark(@msgs) o die "Error al desmarcar: $@\\n";

El método unmark acepta una lista de uno o más números de mensaje o una sola referencia a un array de uno o más números de mensaje como su argumento. Luego, elimina el \Flagged para esos mensajes (o mensajes). Claramente, si el parámetro Uid está establecido a un valor verdadero, esos números de mensaje deben ser realmente identificadores únicos de mensaje.

Nota: Escribir $imap->unmark(@msgs) es solo un abreviado para especificar $imap->unset_flag("Flagged",@msgs).

Nota también: El \Flagged es solo uno de muchos posibles flags. Esta es un poco confusa, pero tendrás que acostumbrarte a la idea de que entre los flags reservados en RFC3501 hay un nombre \Flagged. No hay un significado específico para este flag; significa lo que el propietario de la carpeta (o delegado) quiere que signifique cuando está activo.

unseen

Ejemplo:

my @unread = $imap->unseen o warn "No se encontraron mensajes no vistos: $@\\n";

El método unseen realiza una búsqueda IMAP SEARCH UNSEEN contra la carpeta seleccionada y devuelve un array de números de mensaje de mensajes que aún no se han visto (es decir, su \Seen flag no está establecido). Si el parámetro Uid es verdadero, se devolverá un array de identificadores de mensaje. Si se llama en contexto escalar, se devolverá un puntero al array (en lugar del array mismo).

unseen_count

Ejemplo:

foreach my $f ($imap->folders) {
    print "El carpeta $f tiene ",
      $imap->unseen_count($f)||0, " mensajes no vistos.\n";};

El método unseen_count acepta el nombre de una carpeta como argumento y devuelve el número de mensajes no vistos en esa carpeta. Si no se proporciona ningún argumento de carpeta, devuelve el número de mensajes no vistos en la carpeta actualmente seleccionada.

unset_flag

Ejemplo:

$imap->unset_flag("\Seen", @msgs)
  o die "unset_flag falló: $@\\n";

El método unset_flag acepta el nombre de un flag como su primer argumento y una lista de uno o más números de mensaje, o una sola referencia a un array de uno o más números de mensaje, como su segundo argumento. Luego, elimina el flag especificado para esos mensajes (o mensajes). Claramente, si el parámetro Uid está establecido a un valor verdadero, esos números de mensaje deben ser realmente identificadores únicos de mensaje, como se espera.

Además, bloqueó el desarrollo adicional de este módulo, porque las personas no contribuían sus extensiones privadas al implementación del protocolo.

subscribe($folder)

my @raw = $imap->SEARCH("SUBJECT","Whatever...");

$imap->search("SUBJECT","Whatever...");
my @raw = $imap->Results;

Parámetros

Existen varios parámetros que influyen en el comportamiento de un objeto IMAPClient. Cada uno se establece especificando un par de valor durante la invocación del método new:

my $imap = Mail::IMAPClient->new ( parameter  => "value",
    parameter2 => "value",
    ...
);

Los parámetros también pueden ser establecidos después de la instanciación del objeto usando el método accesorio eponímico así:

my $imap = Mail::IMAPClient->new;
   $imap->parameter( "value");
   $imap->parameter2("value");

Los métodos accesores eponímicos también pueden usarse sin argumentos para obtener el valor actual del parámetro así:

my $imap = Mail::IMAPClient->new;
   $imap->parameter( "value");
   $imap->parameter2("value");
  ...    # Un gran bloque de código Perl increíble, omitido por brevedad
my $forgot  = $imap->parameter;
my $forgot2 = $imap->parameter2;

Nota: En estos ejemplos uso 'parameter' y 'parameter2' como nombres genéricos de parámetros. El objeto IMAPClient no realmente tiene parámetros llamados 'parameter' y 'parameter2'. En cambio, los parámetros disponibles son:

Authmechanism

Ejemplo:

$imap->Authmechanism("CRAM-MD5");
# o
my $authmech = $imap->Authmechanism();

Si se especifica, el Authmechanism hace que el mecanismo de autenticación especificado sea usado siempre que login sea invocado por Mail::IMAPClient. Si el valor especificado para el parámetro Authmechanism no es un mecanismo de autenticación válido para tu servidor, nunca podrás iniciar sesión de nuevo para el resto de tu script Perl, probablemente. Así que podrías querer comprobar, como así:

my $authmech = "CRAM-MD5";
$imap->has_capability($authmech) y $imap->Authmechanism($authmech);

De hecho, si sabes que tu servidor soporta tu mecanismo de autenticación favorito, sabes, así que puedes incluir tu Authmechanism con tu llamada new, como así:

my $imap = Mail::IMAPClient->new(
    User    => $user,
    Passord => $passord,
    Server  => $server,
    Authmechanism  => $authmech,
    %etc
);

Si el parámetro Authmechanism se proporciona pero Authcallback no es, entonces debes soportar uno de los mecanismos de autenticación que Mail::IMAPClient soporta "de forma predeterminada" (como CRAM-MD5).

Authcallback

Ejemplo:

$imap->Authcallback( \&callback );

Esto especifica una callback por defecto a la mecánica de autenticación por defecto (ver "Authmechanism" anterior). juntos, estos dos métodos reemplazan llamadas automáticas a login con llamadas automáticas que parecen así (alguno):

$imap->authenticate($imap->Authmechanism,$imap->Authcallback);

Si Authmechanism se proporciona pero Authcallback no es, entonces debes soportar uno de los mecanismos de autenticación que Mail::IMAPClient soporta "de forma predeterminada" (como CRAM-MD5).

Authuser

El parámetro Authuser se usa por el mecanismo de autenticación DIGEST-MD5.

Normalmente cuando autentificas el nombre de usuario especificado en el parámetro User se usa. Sin embargo, cuando se utiliza el mecanismo de autenticación DIGEST-MD5, el Authuser puede usarse para especificar un nombre de usuario diferente para el inicio de sesión.

Esta puede ser útil para marcar mensajes como vistos para el Authuser si no sabes la contraseña del usuario, ya que el estado visto suele ser un estado por usuario.

Buffer

Ejemplo:

$Buffer = $imap->Buffer();
# o:
$imap->Buffer($new_value);

El parámetro Buffer establece el tamaño de un bloque de I/O. Es ignorado hasta que Fast_io esté establecido a un valor verdadero (el valor por defecto). Si se usa el método migrate, su valor debería ser el número de bytes a intentar leer en una operación de lectura. El valor por defecto es 4096.

Cuando se usa el método migrate, puedes lograr mejoras en el throughput ajustando este número hacia arriba. Sin embargo, esto también implica un costo de memoria, así que si lo estableces demasiado alto, podrías perder todas las ventajas del algoritmo de fragmentación migrate de este método. Tu programa puede terminar con un error de memoria y tendrás que culparte a ti mismo.

Nota: Aunque se menciona anteriormente, el parámetro Buffer afecta el comportamiento del método migrate, independientemente de si tienes Fast_io activo. Confía en mí, no quieres migrar cientos de mensajes de correo sin usar I/O bufferizado!

Clear

Ejemplo:

$Clear = $imap->Clear();
# o:
$imap->Clear($integer);

El nombre de este parámetro, por razones históricas, es un poco descriptivo. Debería llamarse Wrap, porque especifica cuántas transacciones se almacenan en el buffer de historial empaquetado. Pero no siempre funcionó así; el buffer usado para limpiar se actualmente se limpiaba. El nombre, sin embargo, permanece el mismo por razones de compatibilidad retroactiva.

Clear especifica que el buffer de historial del objeto debe ser empapado después de cada n transacciones, donde n es el valor especificado para el parámetro Clear. Llamando al método eponímico Clear sin argumentos devolverá el valor actual del parámetro.

Clear

El parámetro Clear controla la limpieza automática del búfer de historial de comandos.

Cuando se establece en un valor mayor que 1, el búfer de historial se borrará después de que el número especificado de transacciones se haya completado. Por ejemplo, si Clear se establece en 5, el búfer se borrará después de cada quinta transacción. El propósito de esto es conservar memoria. Se debe tener en cuenta que esto no es el mismo que borrar completamente el búfer. Se mantendrá la transacción más reciente, lo que significa que el búfer nunca estará completamente vacío, excepto cuando se llame al método new. Establecer Clear en un valor que no sea 0 o 1 (y mayor que el valor actual de las transacciones) retrasará la limpieza del búfer de historial pero no impedirá el desbordamiento del búfer de historial.

El ajuste de Clear a 0 desactiva el desbordamiento automático del búfer de historial, y el ajuste a 1 desactiva la funcionalidad del búfer de historial (excepto la última transacción, que no se puede deshabilitar sin romper el módulo IMAPClient). El ajuste de Clear a 0 no provocará una limpieza inmediata del búfer de historial; el ajuste a 1 (o cualquier otro número) sí lo hará (excepto, por supuesto, esa inevitable última transacción).

El valor predeterminado de Clear se establece en cinco (5) para conservar memoria.

Compress

Si se establece, Mail::IMAPClient intenta habilitar el uso de la extensión RFC4978 COMPRESS DEFLATE. Esto requiere que el servidor admita esta CAPACIDAD. Este atributo se puede establecer en un valor verdadero para habilitar o en un ARRAYREF para controlar los argumentos utilizados en la llamada a Compress::Zlib::deflateInit().

Mail::IMAPClient utilizará automáticamente Compress::Zlib para comprimir/descomprimir los datos hacia/desde el servidor. Este atributo se utiliza en el método "login".

Ver también "compress" y "capability".

Debug

$Debug = $imap->Debug();

Debug_fh

Ejemplo:

$Debug_fh = $imap->Debug_fh();
# o:
$imap->Debug_fh($fileHandle);

Especifica el manejador de archivo al que se debe imprimir la información de depuración. Puede ser una referencia a un objeto manejador de archivo o un glob de manejador de archivo. El valor predeterminado es imprimir información de depuración en STDERR.

Por ejemplo, puede:

use Mail::IMAPClient;

my $dh = IO::File->new(">debugging.output")
  or die "No se puede abrir debugging.output: $!\n";

    User=>$user, Password=>$pass, Server=>$server, Debug=>1, Debug_fh => $dh
);

que es lo mismo que:

use Mail::IMAPClient;
use IO::File;
# establecer $user, $pass y $server aquí
my $imap = Mail::IMAPClient->new(
    User     => $user,
    Password => $pass,
    Server   => $server,
    Debug    => "yes, please",
    Debug_fh => IO::File->new(">debugging.output")
      || die "No se puede abrir debugging.output: $!\n"
);

También puede:

use Mail::IMAPClient;
# establecer $user, $pass y $server aquí
open(DBG, ">debugging.output")
  or die "No se puede abrir debugging.output: $!\n";
my $imap = Mail::IMAPClient->new(
  User=>$user, Password=>$pass, Server=>$server, Debug=> 1, Debug_fh => *DBG
);

Especificar este parámetro no es muy útil a menos que "Debug" se establezca en un valor verdadero.

Maxtemperrors

$Maxtemperrors = $imap->Maxtemperrors();

Ejemplo:

$Password = $imap->Password();

Peek

Ejemplo:

$Peek = $imap->Peek();
# o:

El valor predeterminado es establecer el flag de visto cada vez que se recupera el cuerpo de un mensaje, pero no cuando solo se recuperan las cabeceras. Pasar undef al método epónimo Peek restablecerá el parámetro Peek a su estado prístino y predeterminado.

Ejemplo:

$Port = $imap->Port();
# o:
$imap->Port($new_value);

Especifica el puerto en el que está escuchando el servidor IMAP. Este argumento se puede proporcionar con la llamada al método "new" o por separado llamando al método de objeto "Port".

Prewritemethod

El parámetro Prewritemethod debe contener una referencia a una subrutina que realice "cosas especiales" con los datos antes de enviarlos al servidor IMAP (como cifrado o firma).

Este método se llamará inmediatamente antes de enviar un comando del cliente IMAP al servidor. Su primer argumento es una referencia al objeto Mail::IMAPClient y el segundo argumento es una cadena que contiene el comando que se enviará al servidor. Tu Prewritemethod debe devolver una cadena que haya sido firmada o cifrada o lo que sea; esta cadena devuelta es lo que realmente se enviará al servidor.

Si tu Prewritemethod devuelve un valor de cadena vacío, el comando no se enviará al servidor. Esto puede ser útil para implementar comprobaciones de seguridad o para filtrar comandos no deseados.

Ejemplo:

sub my_prewrite_handler {
    my ($imap_obj, $command) = @_;
    # Hacer algo con el comando aquí
    # Por ejemplo, registrarlo o modificarlo
    print STDERR "Sending command: $command\n";
    return $command; # Devolver el comando modificado o el original
}
my $imap = Mail::IMAPClient->new(
    # ... otros parámetros ...
    Prewritemethod => \&my_prewrite_handler
);

ReadWriteTimeout

El parámetro ReadWriteTimeout establece un tiempo de espera en segundos para las operaciones de lectura y escritura en el socket. Si una operación de lectura o escritura tarda más que este tiempo, se lanzará una excepción. Si se establece en undef (valor predeterminado), no habrá tiempo de espera en las operaciones de E/S.

Este parámetro es útil para evitar que los scripts se queden colgados indefinidamente si la conexión del servidor se congela o se vuelve no receptiva.

Ejemplo:

$imap->ReadWriteTimeout(30); # Establecer un tiempo de espera de 30 segundos

Socket

El parámetro Socket permite que el usuario proporcione un socket ya conectado al servidor IMAP. Si se proporciona, el módulo no intentará establecer una conexión por sí mismo. Esto es útil para escenarios más avanzados donde el manejo de sockets personalizado es necesario.

Cuando se usa el parámetro Socket, el atributo Fast_io se ignora porque se supone que el socket proporcionado ya está configurado adecuadamente para E/S de red.

Ejemplo:

use IO::Socket;
my $sock = IO::Socket::INET->new(
    PeerAddr => "imap.example.com:143",
    Proto    => "tcp",
    # ... otras opciones de socket ...
) or die "No se puede crear el socket: $@";
my $imap = Mail::IMAPClient->new(
    Socket => $sock,
    # ... otros parámetros ...
);

Ssl

Ejemplo:

$Ssl = $imap->Ssl();
# o:
$imap->Ssl($true_or_false);

Especifica si se debe utilizar una conexión SSL/TLS segura para comunicarse con el servidor IMAP. Si se establece en un valor verdadero, Mail::IMAPClient utilizará el módulo Net::SSL para establecer una conexión segura. El puerto predeterminado para conexiones SSL/TLS suele ser 993.

Este parámetro se puede establecer al crear un nuevo objeto Mail::IMAPClient o llamando al método Ssl más tarde.

Si se establece en un valor verdadero y el módulo Net::SSL no está instalado, se producirá un error.

Ssl_version

Este parámetro se pasa directamente a la llamada a Net::SSL->new() y permite controlar la versión de SSL/TLS utilizada para la conexión segura. Los valores posibles incluyen TLSv1, SSLv3, etc. Si no se especifica, se utiliza la versión predeterminada de Net::SSL.

Ejemplo:

my $imap = Mail::IMAPClient->new(
    Server => "imap.example.com",
    Ssl    => 1,
    Ssl_version => "TLSv1_2" # Usar TLS 1.2
);

Timeout

Este parámetro especifica el tiempo de espera en segundos para las operaciones de conexión y las respuestas del servidor. Si el servidor no responde dentro del tiempo especificado, se producirá un error. El valor predeterminado es 60 segundos.

Ejemplo:

$imap->Timeout(10); # Establecer un tiempo de espera de 10 segundos

User

Ejemplo:

$User = $imap->User();
# o:
$imap->User($new_value);

Especifica el nombre de usuario a utilizar al iniciar sesión en el servidor IMAP. Este parámetro se puede proporcionar durante la llamada al método new o por separado llamando al método de objeto User.

Si Server, User y Password se proporcionan todos a la llamada del método "new", entonces el objeto recién instanciado se conectará al host especificado en Server (en el puerto especificado en Port o en el puerto predeterminado 143) y luego iniciará sesión como el usuario especificado en el parámetro User (usando la contraseña proporcionada en el parámetro Password). RawSocket

Ejemplo:

$socket = $imap->RawSocket;
# o:
$imap->RawSocket($socketh);

El método RawSocket puede utilizarse para obtener el handle del socket de la conexión actual (por ejemplo, para realizar I/O en la conexión que aún no está soportada por Mail::IMAPClient) o para reemplazar el socket actual por un nuevo handle (por ejemplo, un handle SSL, ver IO::Socket::SSL, pero asegúrate de ver también el método "Socket").

Si proporcionas un handle de socket por ti mismo, ya sea haciendo algo como:

$imap = Mail::IMAPClient->new(RawSocket => $sock, User => ... );

o haciendo algo como:

$imap = Mail::IMAPClient->new(User => $user,
            Password => $pass, Server => $host);
# blah blah blah
$imap->RawSocket($ssl);

entonces serás responsable de establecer la conexión y autenticarte, ya sea mediante el método "login" o el más elegante "authenticate", o, dado que sabes tanto, simplemente haciendo I/O directo contra el socket hasta estar logueado. Si realizas alguna de estas acciones, también debes establecer el parámetro "State" tú mismo para reflejar el estado actual del objeto (es decir, Conectado, Autenticado, etc.).

Nota: No se realizará ninguna operación en el socket cuando se llame este método. En particular, después de que se establezca la conexión TCP al servidor IMAP, el protocolo exige que el servidor envíe un mensaje de saludo inicial, y tendrás que manejar este mensaje explícitamente antes de realizar cualquier otra operación, por ejemplo, intentar llamar a "login". El aviso es: Caveat emptor.

Para un enfoque más DWIM para establecer el socket, ve "Socket".

Readmethod

Ejemplo:

$imap->Readmethod(   # IMAP, HANDLE, BUFFER, LENGTH, OFFSET
    sub {
        my ( $self, $handle, $buffer, $count, $offset ) = @_;
        my $rc = sysread( $handle, $$buffer, $count, $offset );
        # hacer algo útil aquí...
    }
);

El método Readmethod debe contener una referencia a una subrutina que reemplazará a sysread. La subrutina recibirá los siguientes argumentos: primero el objeto Mail::IMAPClient utilizado. Segundo, una referencia a un socket. Tercero, una referencia a una variable escalar en la que se leerán los datos (BUFFER). Los datos ubicados aquí deben ser "datos finales", por lo que si estás descifrando o eliminando firmas, asegúrate de hacerlo antes de insertar datos en este buffer. Cuarto, el número de bytes solicitados a leer; la LONGITUD de la solicitud. Quinto, el OFFSET en el BUFFER donde se deben leer los datos. Si no se especifica, debe tener un valor predeterminado de cero.

Nota: Este método reemplaza completamente las lecturas de la conexión al servidor, por lo que si defines uno de estos, tu subrutina tendría que realizar realmente la lectura. Es para cosas como esta que tenemos el parámetro "Socket" y el método accesor epónimo.

Tu Readmethod probablemente necesitará saber más de lo dicho para realizar lo que hace. Se recomienda que empaquetes toda la información relevante en un hash y almacenes una referencia a este hash en un lugar donde tu método pueda acceder a él, posiblemente en el objeto Mail::IMAPClient mismo.

Ver también "Prewritemethod".

La subrutina recibirá los siguientes argumentos: primero el objeto Mail::IMAPClient utilizado. Segundo, una referencia a un socket. Tercero, un valor de tiempo de espera que se usa como valor de tiempo de espera predeterminado para CORE::select(). Dependiendo de los cambios/funcionalidades introducidas por cambios en Readmethod, puede ser necesario aquí.

Socket

Ejemplo:

$Socket = $imap->Socket();
# o:
$imap->Socket($socket_fh);

El método Socket puede utilizarse para obtener el handle del socket de la conexión actual. Esto puede ser necesario para realizar I/O en la conexión que aún no está soportada por Mail::IMAPClient) o para reemplazar el socket actual por un nuevo handle (por ejemplo, un handle SSL, ver IO::Socket::SSL).

Si proporcionas un handle de socket por ti mismo, ya sea haciendo algo como:

o haciendo algo como:

$imap = Mail::IMAPClient->new(
  User => $user, Password => $pass, Server => $host
);
$imap->Socket($ssl);

entonces serás responsable de establecer la conexión, es decir, asegúrate de que $ssl en el ejemplo sea un socket válido y conectado.

Este método se utiliza principalmente para proporcionar una sustitución de caída en IO::Socket::(INET|IP), utilizada por "connect" por defecto. De hecho, este método es llamado por "connect" mismo después de haber establecido una conexión adecuada de IO::Socket::(INET|IP) al servidor de destino; por esta razón, este método también realiza las operaciones normales asociadas con "connect", es decir:

  • lectura del mensaje de saludo inicial del servidor;
  • llamada a "login" si las condiciones se aplican (ver "connect" para más detalles);
  • dejar el objeto Mail::IMAPClient en un estado adecuado.

Por estas razones, el siguiente ejemplo funcionará "sin tener que configurarlo":

my $imap = Mail::IMAPClient->new
 ( User     => 'your-username',
   Password => 'your-password',
   Socket   => IO::Socket::SSL->new
   (  Proto    => 'tcp',
      PeerAddr => 'some.imap.server',
      PeerPort => 993, # puerto estándar de IMAP sobre SSL
   ),
);

Si necesitas más control sobre el socket, por ejemplo, si tienes que implementar un método de autenticación más complejo, ve "RawSocket".

Uid

Ejemplo:

$Uid = $imap->Uid();
# o:
$imap->Uid($verdadero_o_falso);

Si "Uid" se establece a un valor verdadero (es decir, 1), el comportamiento de los métodos "fetch", "search", "copy" y "store" (y sus derivados) se cambia para que los argumentos que de otro modo serían números de secuencia de mensaje se traten como UID de mensaje y para que los valores de retorno (en el caso del método "search" y sus derivados) que normalmente serían números de secuencia de mensaje sean en su lugar UID de mensaje.

Internamente, esto se implementa como un interruptor que, si se activa, hace que los métodos que de otro modo emitirían un comando de cliente IMAP FETCH, STORE, SEARCH o COPY emitan en su lugar UID FETCH, UID STORE, UID SEARCH o UID COPY, respectivamente. La principal diferencia entre los números de secuencia de mensaje y los UID de mensaje es que, según RFC3501, los UID no deben cambiar durante una sesión y no deben cambiar entre sesiones, y nunca deben reutilizarse. Los números de secuencia no tienen la misma garantía y, de hecho, pueden reutilizarse de inmediato.

Dado que los nombres de las carpetas también tienen un identificador único (UIDVALIDITY), que se proporciona cuando la carpeta se "selecciona" o "examina" o al hacer algo como "$imap->status($folder,"UIDVALIDITY")", es posible identificar de forma única cada mensaje en el servidor, aunque normalmente no necesitarás preocuparte por ello.

Los métodos actualmente afectados por la activación del flag "Uid" son:

copy            fetch
search          store
message_string  message_uid
body_string     flags
move            size
parse_headers   thread

Ten en cuenta que si por alguna razón solo quieres que el parámetro "Uid" esté activado para un solo comando, puedes elegir entre los siguientes dos fragmentos, que son equivalentes:

Ejemplo 1:

$imap->Uid(1);
my @uids = $imap->search('SUBJECT',"Just a silly test"); #
$imap->Uid(0);

Ejemplo 2:

my @uids;
foreach $r ($imap->UID("SEARCH","SUBJECT","Just a silly test") {
    chomp $r;
    $r =~ s/\r$//;
    $r =~ s/^\*\s+SEARCH\s+// or next;
    push @uids, grep(/\d/,(split(/\s+/,$r)));
}

En el segundo ejemplo, usamos el método predeterminado para emitir el comando de cliente IMAP UID, teniendo cuidado de usar un nombre de método en mayúsculas para no llamar inadvertidamente al método accesor "Uid". Luego, analizamos manualmente los UID de los mensajes, ya que no contamos con el beneficio del método "search" incorporado que lo hace por nosotros.

Por favor, ten mucho cuidado al activar y desactivar el parámetro "Uid" a lo largo de un script. Si pierdes la pista de si tienes el parámetro "Uid" activado, podrías hacer algo lamentable, como eliminar el mensaje equivocado. Recuerda, como todos los métodos accesores epónimos, el método Uid sin argumentos devolverá el valor actual del parámetro "Uid", así que hazte un favor y compruébalo. El enfoque más seguro es probablemente activarlo al principio (o simplemente dejar que esté activado por defecto) y luego dejarlo activado. (Recuerda que dejarlo desactivado puede causar problemas si los cambios en el contenido de una carpeta provocan una resecuenciación).

Por defecto, el parámetro "Uid" está activado.

Métodos de Estado

Hay varios métodos de objeto que devuelven el estado del objeto. Se pueden usar en cualquier momento para comprobar el estado de un objeto IMAPClient, pero son particularmente útiles para determinar la causa del fallo cuando se intenta una conexión e inicio de sesión como parte de una única invocación del método "new". Los métodos de estado son:

Escaped_history

Ejemplo:

my @history = $imap->Escaped_history;

El método Escaped_history es casi idéntico al método History. Sin embargo, a diferencia del método History, la salida del servidor transmitida literalmente se encerrará entre comillas dobles, con todas las comillas dobles y barras invertidas escapadas. Si se llama en un contexto escalar, Escaped_history devuelve una referencia de array en lugar de un array.

Escaped_history es útil si estás recuperando la salida y procesándola manualmente, y dependes de los caracteres especiales mencionados anteriormente para delimitar los datos. No es útil cuando recuperas contenidos de mensajes; utiliza message_string o body_string para eso.

Escaped_results

Ejemplo:

my @results = $imap->Escaped_results;

El método Escaped_results es casi idéntico al método Results. Sin embargo, a diferencia del método Results, la salida del servidor transmitida literalmente se encerrará entre comillas dobles, con todas las comillas dobles y barras invertidas escapadas. Si se llama en un contexto escalar, Escaped_results devuelve una referencia de array en lugar de un array.

Escaped_results es útil si estás recuperando la salida y procesándola manualmente, y dependes de los caracteres especiales mencionados anteriormente para delimitar los datos. No es útil cuando recuperas contenidos de mensajes; utiliza message_string o body_string para eso.

History

Ejemplo:

my @history = $imap->History;

El método History es casi idéntico al método "Results". Sin embargo, a diferencia del método "Results", el comando IMAP que se emitió para crear los resultados que se devuelven no se incluye en los resultados devueltos. Si se llama en un contexto escalar, History devuelve una referencia de array en lugar de un array.

IsUnconnected

devuelve un valor verdadero si el objeto se encuentra actualmente en un estado "Desconectado".

IsConnected

devuelve un valor verdadero si el objeto se encuentra actualmente en un estado "Conectado", "Autenticado" o "Seleccionado".

IsAuthenticated

devuelve un valor verdadero si el objeto se encuentra actualmente en un estado "Autenticado" o "Seleccionado".

IsSelected

devuelve un valor verdadero si el objeto se encuentra actualmente en un estado "Seleccionado".

LastError

Internamente, LastError se implementa de manera similar a un parámetro (como se describe en "Parámetros", arriba). Hay un atributo *LastError* y un método accesor epónimo que devuelve la cadena de texto *LastError* que describe la última condición de error encontrada por el servidor.

Ten en cuenta que algunos errores son más graves que otros, por lo que el valor de *LastError* solo es significativo si encuentras una condición de error que no te gusta. Por ejemplo, si utilizas el método "exists" para comprobar si una carpeta existe y la carpeta no existe, se registrará un mensaje de error en *LastError*, aunque no sea un error particularmente grave. Por otro lado, si no usaste "exists" y simplemente intentaste "seleccionar" una carpeta inexistente, entonces "select" devolvería "undef" después de establecer *LastError* en algo como "NO SELECT failed: Can't open mailbox "mailbox": no such mailbox". En este punto, sería útil imprimir el contenido de *LastError* al morir.
