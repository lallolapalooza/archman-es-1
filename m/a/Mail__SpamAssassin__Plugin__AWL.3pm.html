NOMBRE

Mail::SpamAssassin::Plugin::AWL - Normaliza puntuaciones mediante la lista de bienvenida automática

SINOPSIS

Para probar esto, añade o descomenta esta línea en init.pre:

loadplugin     Mail::SpamAssassin::Plugin::AWL

Usa el archivo 60_awl.cf proporcionado (es decir, no tienes que hacer nada) o añade estas líneas a un archivo .cf:

header AWL             eval:check_from_in_auto_welcomelist()
describe AWL           From: la dirección está en la lista de bienvenida automática
tflags AWL             userconf noautolearn
priority AWL           1000

DESCRIPCIÓN

Este módulo de plugin proporciona soporte para la lista de bienvenida automática. Realiza un seguimiento de la puntuación media de SpamAssassin para los remitentes. Los remitentes se rastrean utilizando una combinación de su dirección De: y su dirección IP. Luego, utiliza esa puntuación media para reducir la variabilidad en la puntuación de un mensaje a otro y modifica la puntuación final acercando el resultado a la media histórica. Esto mejora la precisión del filtrado para la mayoría del correo electrónico.

ETIQUETAS DE PLANTILLA

Este módulo de plugin añade las siguientes "etiquetas" que se pueden usar como marcadores de posición en ciertas opciones. Consulte "Mail::SpamAssassin::Conf" para obtener más información sobre ETIQUETAS DE PLANTILLA.

_AWL_             Modificador AWL
_AWLMEAN_         Puntuación media en la que se basa la modificación AWL
_AWLCOUNT_        Número de mensajes en los que se basa la modificación AWL
_AWLPRESCORE_     Puntuación antes de AWL

PREFERENCIAS DEL USUARIO

Las siguientes opciones se pueden usar tanto en archivos de configuración a nivel de sitio ("local.cf") como específicos del usuario ("user_prefs") para personalizar cómo SpamAssassin maneja los mensajes de correo electrónico entrantes.

use_auto_welcomelist ( 0 | 1 ) (predeterminado: 1)
Anteriormente use_auto_whitelist, que funcionará de forma intercambiable hasta la versión 4.1.

Si se deben utilizar listas de bienvenida automáticas. Las listas de bienvenida automáticas rastrean la puntuación a largo plazo para cada remitente y luego desplazan la puntuación de los nuevos mensajes hacia esa media a largo plazo. Esto puede aumentar o disminuir la puntuación de los mensajes, dependiendo del comportamiento a largo plazo del corresponsal específico.

Para obtener más información sobre el sistema de lista de bienvenida automática, consulte la sección "Automatic Welcomelist System" del archivo README. La lista de bienvenida automática no está destinada a ser un reemplazo de propósito general para las entradas de lista de bienvenida estáticas añadidas a sus archivos de configuración.

Tenga en cuenta que se ignoran ciertas pruebas al determinar la puntuación final del mensaje:

- reglas con tflags establecidos a 'noautolearn'
auto_welcomelist_factor n (predeterminado: 0.5, rango [0..1])
Anteriormente auto_whitelist_factor, que funcionará de forma intercambiable hasta la versión 4.1.

Cuánto de la media a largo plazo para el remitente se debe regresar una puntuación. Básicamente, el algoritmo es rastrear la puntuación media a largo plazo de los mensajes para el remitente ("mean"), y luego una vez que hemos calculado completamente la puntuación para este mensaje ("score"), calculamos la puntuación final para el mensaje como:

"finalscore" = "score" + ("mean" - "score") * "factor"

Así que si "factor" = 0.5, nos moveremos la mitad del camino entre la puntuación calculada y la media. Si "factor" = 0.3, nos moveremos aproximadamente 1/3 del camino desde la puntuación hacia la media. "factor" = 1 significa usar simplemente la media a largo plazo; "factor" = 0 significa usar simplemente la puntuación calculada.

auto_welcomelist_ipv4_mask_len n (predeterminado: 16, rango [0..32])
Anteriormente auto_whitelist_ipv4_mask_len, que funcionará de forma intercambiable hasta la versión 4.1.

La base de datos AWL solo guarda el número especificado de bits más significativos de una dirección IPv4 en sus campos, de modo que diferentes direcciones IP individuales dentro de una subred que pertenecen al mismo propietario se gestionan bajo un único registro de base de datos. Como no tenemos información disponible sobre los rangos de direcciones asignados a los remitentes, esta longitud de máscara CIDR es solo una aproximación. El valor predeterminado es 16 bits, que corresponde a una antigua clase B. Aumente el número si se desea una granularidad más fina, por ejemplo, a 24 (clase C) o 32. Se permite un valor 0, pero no es particularmente útil, ya que trataría a todo Internet como una sola organización. El número no tiene por qué ser múltiplo de 8, se permite cualquier división.

auto_welcomelist_ipv6_mask_len n (predeterminado: 48, rango [0..128])
Anteriormente auto_whitelist_ipv6_mask_len, que funcionará de forma intercambiable hasta la versión 4.1.

La base de datos AWL solo guarda el número especificado de bits más significativos de una dirección IPv6 en sus campos, de modo que diferentes direcciones IP individuales dentro de una subred que pertenecen al mismo propietario se gestionan bajo un único registro de base de datos. Como no tenemos información disponible sobre los rangos de direcciones asignados a los remitentes, esta longitud de máscara CIDR es solo una aproximación. El valor predeterminado es 48 bits, que corresponde a un rango de direcciones comúnmente asignado a organizaciones individuales (más pequeñas). Aumente el número para una granularidad más fina, por ejemplo, a 64 o 96 o 128, o disminuya para rangos más amplios, por ejemplo, 32. Se permite un valor 0, pero no es particularmente útil, ya que trataría a todo Internet como una sola organización. El número no tiene por qué ser múltiplo de 4, se permite cualquier división.

user_awl_sql_override_username
Utilizado por la implementación de almacenamiento SQLBasedAddrList.

Si se establece esta opción, el módulo SQLBasedAddrList reemplazará el nombre de usuario establecido con el valor proporcionado. Esto puede ser útil para implementar bases de datos de listas de bienvenida automáticas globales o basadas en grupos.

auto_welcomelist_distinguish_signed
Anteriormente auto_whitelist_distinguish_signed, que funcionará de forma intercambiable hasta la versión 4.1.

Utilizado por la implementación de almacenamiento SQLBasedAddrList.

Si se establece esta opción, el módulo SQLBasedAddrList mantendrá entradas de base de datos separadas para direcciones de correo electrónico validadas por DKIM y para las no validadas. Un requisito previo al establecer esta opción es que exista un campo awl.signedby en una tabla SQL, de lo contrario, las operaciones SQL fallarán (que es la razón por la que necesitamos esta opción, para la compatibilidad con el esquema de base de datos anterior a la versión 3.3.0). También se debe habilitar un plugin DKIM, ya que de lo contrario no hay ningún beneficio al activar esta opción.

Configuración del administrador

auto_welcomelist_db directorio/base de datos
Previously auto_whitelist_db which will work interchangeably until 4.1.

El nombre del archivo o directorio que contiene la base de datos de la lista de bienvenida automática (AWL). Si este parámetro no se establece, las listas de bienvenida automática se almacenan en un archivo llamado "auto_whitelist" en el directorio "~/.spamassassin" con modo 0700. Para el uso de SpamAssassin a nivel de sistema, es posible que desee compartir esto entre todos los usuarios, aunque no se recomienda.

auto_welcomelist_db_modules Módulo ... (predeterminado: ver más abajo)
Anteriormente auto_whitelist_db_modules, que funcionará indistintamente hasta la versión 4.1.

Qué módulos de base de datos se deben utilizar para el archivo de base de datos de almacenamiento de la lista de bienvenida automática. Se utilizará el primer módulo nombrado que se pueda cargar desde la ruta de inclusión de perl. El formato es:

MóduloPreferido SegundoMejor TerceroMejor ...

es decir, una lista de nombres de módulos perl separados por espacios. El valor predeterminado es:

DB_File GDBM_File SDBM_File

NDBM_File ya no es compatible, ya que parece tener errores que impiden su uso para el AWL (ver error 4353 de SpamAssassin).

auto_welcomelist_file_mode (predeterminado: 0700)
Anteriormente auto_whitelist_file_mode, que funcionará indistintamente hasta la versión 4.1.

Los bits de modo de archivo utilizados para el directorio o archivo de la lista de bienvenida automática.

Asegúrese de especificar esto utilizando los bits de modo 'x' establecidos, ya que también se puede utilizar para crear directorios. Sin embargo, si se crea un archivo, el archivo resultante no tendrá bits de ejecución establecidos (umask se establece en 0111).

user_awl_dsn DBI:tipo_base_datos:nombre_base_datos:host:puerto
Utilizado por la implementación de almacenamiento SQLBasedAddrList.

Esto establecerá el DSN utilizado para conectarse. Ejemplo: "DBI:mysql:spamassassin:localhost"

user_awl_sql_username nombre_usuario
Utilizado por la implementación de almacenamiento SQLBasedAddrList.

El nombre de usuario autorizado para conectarse al DSN anterior.

user_awl_sql_password contraseña
Utilizado por la implementación de almacenamiento SQLBasedAddrList.

La contraseña para el nombre de usuario de la base de datos, para el DSN anterior.

user_awl_sql_table nombre_tabla
Utilizado por la implementación de almacenamiento SQLBasedAddrList.

La tabla en la que se almacenan las listas de bienvenida automática de los usuarios, para el DSN anterior.
