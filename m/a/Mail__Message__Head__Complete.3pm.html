NOMBRE

Mail::Message::Head::Complete - la cabecera de un mensaje

HERENCIA

  es una Mail::Reporter

SINOPSIS

my $head = Mail::Message::Head::Complete->new;
Ver Mail::Message::Head

DESCRIPCIÓN

Un mensaje electrónico puede estar en diversos estados: no leído, parcialmente leído y completamente leído. Esta clase almacena un mensaje en el que todas las líneas de cabecera son conocidas con certeza.

Acceso a la cabecera

Extendida por "Acceso a la cabecera" en Mail::Message::Head.

$obj->add( $field | $line | <$name, $body, [$attrs]> )
Añade un campo a la cabecera. Si se añade un campo más de una vez, todos los valores se almacenan en la cabecera, en el orden en que se añadieron.

Cuando se especifica un objeto de $field (instancia de Mail::Message::Field), ese será añadido. Otra posibilidad es especificar una línea de cabecera directa $line, o una línea de cabecera bien dividida en $name y $body, en cuyo caso se llama al constructor del campo.

Las especificaciones de $line o $body que terminan con un salto de línea se consideran correctamente envueltas. Las líneas que no terminan con un salto de línea se envuelven cuando sean necesarias: se añaden saltos de línea donde sea necesario. Se recomienda que MailBox realice el envoltorio por usted.

El valor devuelto por este método es el objeto Mail::Message::Field creado (o especificado).

Ejemplo:

my $head  = Mail::Message::Head->new;
$head->add('Subject: hi!');
$head->add(From => 'me@home');
my $field = Mail::Message::Field->new('To: you@there');
$head->add($field);
my Mail::Message::Field $s = $head->add(Sender => 'I');
$obj->addListGroup($object)
Un grupo de listas es un conjunto de campos de cabecera que contienen datos sobre una lista de correo que se utilizó para enviar el mensaje. Véase Mail::Message::Head::ListGroup para detalles sobre la implementación de $object.

Cuando tienes un grupo de listas preparado, puedes añadirlo más tarde usando este método. Obtendrás tu copia privada de los datos del grupo de listas en el retorno, ya que el mismo grupo puede ser utilizado para múltiples mensajes.

Estas líneas de cabecera no tienen nada que ver con el sentido del usuario de las acciones de "reply" o "forward": estas líneas trazan el mecanismo de transporte de correo.

Ejemplo de añadir un grupo de listas a una cabecera:

Estas líneas de cabecera no tienen nada que ver con las acciones de "reply" o "forward" del usuario: estas líneas trazan el mecanismo de transporte de correo.

Sin embargo... es fácil distraer este proceso. Ejemplo:
my $msg = ....; # cabecera ref-count = 1 + 0 = 1

undef $s; # ref-count = 0: limpieza

$obj->resentGroups()
Devuelve una lista de objetos Mail::Message::Head::ResentGroup, cada uno representando un punto intermedio en la transmisión del mensaje en el orden de las cabeceras: el más reciente primero. Vea también addResentGroup() y removeResentGroups().

Un grupo de resent contiene una serie de cabeceras cuyos nombres empiezan con "Resent-*". Antes de la primera línea "Resent" se muestra información de tipo "trace", que está compuesta por un opcional "Return-Path" y un campo obligatorio "Received".

$obj->reset($name, @fields)
Reemplaza los valores de las cabeceras nombradas por $name con los valores especificados en la lista de @fields. Una sola nombre puede corresponder a múltiples cabeceras repetidas. LEA el aviso importante en removeField().

La eliminación de campos que forman parte de uno de los grupos de cabeceras predefinidos no es una idea inteligente. Puedes eliminar estos campos como grupo, juntos. Por ejemplo, las líneas 'Received' son parte de grupos de resent, 'X-Spam' es parte de un grupo de spam, y "List-Post" pertenece a un grupo de listas. Puedes eliminar un grupo completo con Mail::Message::Head::FieldGroup::delete(), o con métodos proporcionados por Mail::Message::Head::Partial.

Si FIELDS está vacío, los campos correspondientes a $name se eliminarán. La posición de los campos eliminados en el orden de la cabecera se recuerda. Los campos con el mismo nombre que se agregan después aparecerán en la posición recubierta. Esto es equivalente al método delete().

» ejemplo:

# reducir el número de líneas 'Keywords' a las últimas 5
my @keywords = $head->get('Keywords');
$head->reset('Keywords', @keywords[-5..-1]) if @keywords > 5;
# reducir el número de líneas 'Received' a solo la última agregada
my @rgs = $head->resentGroups;
shift @rgs;     # mantiene esta (más reciente es agregada en frente)
$_->delete foreach @rgs;
$obj->set( $field | $line | <$name, $body, [$attrs]> )
El método "set" es similar al método add() y acepta los mismos opciones. Sin embargo, los valores existentes de las cabeceras se eliminan antes de añadir un nuevo valor. LEA el aviso importante en removeField().
$obj->spamDetected()
Retorna si alguna de las grupos de spam define un informe sobre el spam. Si no hay cabeceras en el mensaje relacionadas con software de detección de spam, se devuelve "undef". Las grupos de spam que reportan spam se devuelven.

» ejemplo:

   or call_spamassassin($message);

En contexto escalar, con exactamente un NAME especificado, se devuelve este grupo. Con más $names o sin $names, se devuelve una lista (que por defecto devuelve el largo en contexto escalar).

NAME

Mail::Message::Head - interface to the header part of a mail message

SYNOPSIS

  use Mail::Message::Head;

  # Create a new, empty header
  my $head = Mail::Message::Head->new;

  # Read header from a file handle
  $head->read($fh);

  # Get the full header
  my $text = $head->text;

  # Access individual fields
  $head->get('Subject');
  $head->get('From');

  # Add or change fields
  $head->set('Subject', 'my new subject');
  $head->add('Cc', 'someone@example.com');

  # Remove fields
  $head->delete('Subject');

DESCRIPTION

The Mail::Message::Head object represents the header part of a mail message. The header consists of a sequence of fields, each identified by a field name and containing a field body. The fields are generally stored in memory as a list of Mail::Message::Field objects.

This class provides methods to access and manipulate these fields.

The Mail::Message::Head class inherits from Mail::Message::Body. This is a bit confusing, but it has a reason. The header is structured like a body: a sequence of lines. The methods for accessing the structure of the body are therefore inherited. For instance, the header can be read from and written to file handles.

It also inherits from Mail::Reporter for error reporting.

Access to the header

The header can be treated as a list of fields. The order of the fields is significant for some applications (like sorting messages based on when they were received).

$obj->add( NAME, VALUE )
Add a new field NAME with VALUE to the end of the header. If the field already exists, it is NOT replaced.
$obj->append( NAME, VALUE )
Add a new field NAME with VALUE to the end of the header. If the field already exists, it is NOT replaced.
$obj->at( $index )
Return the field at the specified index (starting from 0).

Create a header object from a list of fields. Each field can be a Mail::Message::Field object, or a pair of name/value strings. The fields are added in the order they are given.
$obj->clear()
Remove all fields from the header.
$obj->delete( NAME )
Remove all fields with the given NAME from the header. Returns the number of fields removed.
$obj->fields()
Return a list of all field objects in the header, in the order they appear.
$obj->file( FILENAME )
Read the header from the file FILENAME. If the file does not exist, then an empty header is created.

Set the field NAME to VALUE. If the field already exists, it is replaced. If it does not exist, it is added to the end of the header. This method is an alias for reset().

$obj->recvstamp()
Returns an indication about when the message was sent, but only using the "Date" field in the header as last resort: we do not trust the sender of the message to specify the correct date. See timestamp() when you do trust the sender.

Many spam producers fake a date, which mess up the order of receiving things. The timestamp which is produced is derived from the Received headers, if they are present, and "undef" otherwise.

The timestamp is encoded as "time" is on your system (see perldoc -f time), and as such usable for the "gmtime" and "localtime" methods.

» example: of time-sorting folders with received messages

my $folder = $mgr->open('InBox');
my @messages = sort {$a->recvstamp <=> $b->recvstamp}
                  $folder->messages;

» example: of time-sorting messages of mixed origin

my $folder = $mgr->open('MyFolder');
# Pre-calculate timestamps to be sorted (for speed)
my @stamps = map +[ ($_->timestamp || 0), $_ ],
  $folder->messages;
my @sorted =
  map { $_->[1] }      # get the message for the stamp
    sort {$a->[0] <=> $b->[0]}   # stamps are numerics
       @stamps;
$obj->timestamp()
Returns an indication about when the message was sent, with as little guessing as possible. In this case, the date as specified by the sender is trusted. See recvstamp() when you do not want to trust the sender.

The timestamp is encoded as "time" is on your system (see perldoc -f time), and as such usable for the "gmtime" and "localtime" methods.

$any->messageIdPrefix( [$prefix, [$hostname]|CODE] )
When options are provided, it sets a new way to create message-ids, as used by createMessageId(). You have two choices: either by providing a $prefix and optionally a $hostname, or a "CODE" reference.

The "CODE" reference will be called with the header as first argument. You must ensure yourself that the returned value is RFC compliant.

The $prefix defaults to "mailbox-$$", the $hostname defaults to the return of Net::Domains's function hostfqdn(), or when not installed, the Sys::Hostname's function hostname(). Inbetween the two, a nano-second time provided by Time::HiRes is used. If that module is not available, "time" is called at the start of the program, and incremented for each newly created id.

In any case, a subroutine will be created to be used. A reference to that will be returned. When the method is called without arguments, but no subroutine is defined yet, one will be created.
