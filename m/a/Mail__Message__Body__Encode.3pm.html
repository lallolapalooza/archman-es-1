NOMBRE

Mail::Message::Body::Encode - organizar las codificaciones generales de mensajes

SINTAXIS

my Mail::Message $msg = ...;
my $decoded = $msg->decoded;
my $encoded = $msg->encode(mime_type => 'image/gif',
    transfer_encoding => 'base64');
my $body = $msg->body;
my $decoded = $body->decoded;
my $encoded = $body->encode(transfer_encoding => '7bit');

DESCRIPCIÓN

Gestiona las codificaciones de los cuerpos de mensajes cuando el programa principal lo solicita. Esta paquete agrega funcionalidad a la clase Mail::Message::Body cuando se llamen los métodos decoded() o encode().

Cuatro tipos de codificaciones se manejan (en el orden correcto)

  • codificación de líneas

    Diversos sistemas operativos tienen diferentes ideas sobre cómo codificar la terminación de línea. UNIX usa un carácter LF, el Macintosh usa un CR, y el Windows usa un CR/LF. Los mensajes transportados a través de Internet siempre usan el separador CRLF.

  • codificación de transferencia

    Los mensajes transmitidos por Internet deben ser ASCII pura. Los caracteres complicados y archivos binarios (como imágenes y archivados) deben codificarse durante la transmisión para una representación ASCII.

    La implementación de los codificadores y decodificadores necesarios se encuentra en el conjunto de paquetes Mail::Message::TransferEnc. La página manual relacionada enumera las codificaciones de transferencia soportadas.

  • traducción de tipos MIME

    No se ha implementado aún

  • conversión de caracteres de conjunto

Codifica (traduce) un Mail::Message::Body en un formato diferente. Ver la descripción anterior. Las opciones que no se especifican no activan conversiones. 
-Opción           --Valor por defecto

Aplica solo cuando el mime_type es textual.

Si el conjunto de caracteres se especifica explícitamente (por ejemplo "iso-8859-10"), el dato se interpreta como bytes (blob), no como texto. Sin embargo, en caso de "PERL", se considera como una representación interna de caracteres (o latin1 o Perl's utf8 - no el mismo que utf-8), por lo que no deberías saber.

charset_detect => CODE
[3.013] Cuando el cuerpo no tiene una especificación explícita de conjunto de caracteres, el RFC dice que es "us-ascii". En realidad, esto no es "verdadero": es simplemente un conjunto de caracteres desconocido. Esto sucede a menudo cuando se incluyen archivos de texto como adjunto, por ejemplo un adjunto de pieza.

Si quieres ser más inteligente que el detector por defecto de conjunto de caracteres, puedes proporcionar tu propia función para este parámetro. La función recibirá el cuerpo transferido. Puedes cambiar el algoritmo por defecto globalmente mediante charsetDetectAlgorithm().

mime_type => STRING|FIELD
Convierte en el tipo especificado de MIME, que puede especificarse como STRING o FIELD. El FIELD es un objeto Mail::Message::Field, que representa un MIME header "Content-Type". El STRING debe ser válido contenido para tal header, y se convertirá en un objeto FIELD.

El FIELD puede contener atributos. Generalmente, tiene un atributo "charset", que explica el CHARSET del contenido después de la decodificación de contenido transferido. El parámetro "charset" actualizará o añadirá este atributo. De otro modo (esperando en raras ocasiones), el CHARSET se autodetecta cuando el cuerpo se decodifica.

result_type => CLASE
El tipo de cuerpo a crear cuando el cuerpo se cambia para cumplir la solicitud de re-codificación. También se utilizará como etapa intermedia en el proceso de traducción (si es necesario). CLASE debe heredar de Mail::Message::Body.

Mail::Message::Body::Encode - Perl manual page

NAME

Mail::Message::Body::Encode - create a body part with encoded content

SYNOPSIS

  use Mail::Message::Body::Encode;

  # Create a new body part object with encoded content
  my $body = Mail::Message::Body::Encode->new(
      type    => 'text/plain',
      charset => 'utf-8',
      content => "This is a test.\n",
  );

  # Get the encoded content
  my $encoded_content = $body->getEncodedContent();

  # Get the content-transfer-encoding
  my $encoding = $body->transferEncoding();

  # Change the transfer encoding
  $body->transferEncoding('base64');

  # Get the decoded content
  my $decoded_content = $body->getDecodedContent();

  # Create a filename for the body part
  my $filename = $body->suggestFilename( $directory );

  # Check if the content is binary or text
  if ($body->isBinary) {
      print "Content is binary\n";
  }
  if ($body->isText) {
      print "Content is text\n";
  }

DESCRIPTION

This class creates a message body part where the content is encoded, for example using Quoted-Printable or Base64. The encoding is determined from the Mail::Mime::Type.

When the content is text, then the character set is also important. When not specified, utf-8 is used.

METHODS

$body->new( %args )
Create a new body part object. Arguments are:
content => $string
The content to be encoded.
type => $mime_type
The MIME type of the content (e.g. text/plain). Defaults to text/plain.
charset => $charset
The character set of the content. Defaults to utf-8.
transfer-encoding => $encoding
The transfer encoding to use. If not specified, it is determined by Mail::Mime::Type.
$obj->transferEncoding()
Returns the name of the transfer encoding used for this body part, e.g. "quoted-printable" or "base64".
$obj->transferEncoding( $encoding )
Set the transfer encoding to $encoding. This will re-encode the content.
$obj->getEncodedContent()
Returns the content encoded with the transfer encoding.
$obj->getDecodedContent()
Returns the content decoded.
$obj->suggestFilename( [$directory] )
Suggest a filename for the content. When $directory is given, a filename is composed from the content-type and the content-transfer-encoding. This is useful when creating multipart messages.

The function searches for the existence of filename hints in the headers (like Content-Disposition) and uses the Content-Type and Content-Transfer-Encoding headers. When a filename is found in the headers, the basename of that name is returned, potentially modified by the character encoding.

When no filename is found, a name is generated based on the content-type. For example, text/plain becomes plain.txt, and image/png becomes image.png.

When a $directory is provided, the function will try to find an unused filename by appending a number if the suggested name already exists. The search is limited to the specified $directory.

Example:

        # Suggest a filename in the current directory
        my $filename = $body->suggestFilename();

        # Suggest a filename in /tmp, creating a unique name if necessary
        my $filename = $body->suggestFilename( '/tmp' );

The function returns the suggested filename, or undef if no filename could be determined.

The function also searches for the filename and name attributes. Without $directory, the name found will be returned unmodified.

When a $directory is given, a filename is composed. For security reasons, only the basename of the found name gets used and many potentially dangerous characters removed. If no name was found, or when the found name is already in use, then an unique name is generated.

Don't forget to read RFC6266 section 4.3 for the security aspects in your email application.

$obj->isBinary()
Returns "true" when the un-encoded message is binary data. This information is retrieved from knowledge provided by MIME::Types.
$obj->isText()
Returns "true" when the un-encoded message contains printable text.

Internals

$any->addTransferEncHandler( $name, <$class|$object> )
Relate the NAMEd transfer encoding to an OBJECTs or object of the specified $class. In the latter case, an object of that $class will be created on the moment that one is needed to do encoding or decoding.

The $class or $object must extend Mail::Message::TransferEnc. It will replace existing class and object for this $name.

$obj->getTransferEncHandler($type)
Get the transfer encoder/decoder which is able to handle $type, or return "undef" if there is no such handler.
