NAME

Math::BigFloat - paquete para cálculos matemáticos de punto flotante de tamaño arbitrario

SYNOPSIS

use Math::BigFloat;
# Métodos de configuración (pueden usarse como métodos de clase y de instancia)
Math::BigFloat->accuracy($n);       # establece la precisión
Math::BigFloat->accuracy();         # obtén la precisión
Math::BigFloat->precision($n);      # establece el número de cifras
Math::BigFloat->precision();        # obtén el número de cifras
Math::BigFloat->round_mode($m);     # establece el modo de redondeo, debe ser
                                    # 'even', 'odd', '+inf', '-inf',
                                    # 'zero', 'trunc', o 'common'

Math::BigFloat->div_scale($n);      # establece la precisión de redondeo
Math::BigFloat->div_scale();        # obtén la precisión de redondeo
Math::BigFloat->trap_inf($b);       # bloquea o no las infinitudes

DESCRIPTION

Este módulo implementa aritmética de punto flotante de precisión arbitraria (es decir, números con una cantidad ilimitada de dígitos). Los números se almacenan internamente en notación científica como un signo, un entero (mantisa) y un entero (exponente).

La precisión se controla mediante el método de clase accuracy y precision.

Accuracy vs. Precision

El método accuracy() establece el número de dígitos que se conservarán DESPUÉS del punto decimal. El método precision() establece el número total de dígitos significativos que se conservarán. Si ambos están configurados, la configuración más restrictiva es la que prevalece.

Los cálculos que requieren más precisión de la que se permite se redondearán de acuerdo con el modo de redondeo actual.

El modo de redondeo se puede establecer con el método round_mode(). Los modos válidos son:

even
Redondea al dígito par más cercano.
odd
Redondea al dígito impar más cercano.
+inf
Redondea hacia infinito positivo.
-inf
Redondea hacia infinito negativo.
zero
Redondea hacia cero.
trunc
Redondea hacia cero (lo mismo que zero).
common
Redondea a la mitad hacia arriba (esto es lo mismo que +inf para números positivos y -inf para números negativos).

Por defecto, la precisión es 0 (lo que significa que no se conserva ninguna cifra después del punto decimal, es decir, se obtienen enteros). El modo de redondeo por defecto es even.

Si se establece la precisión con div_scale($n), los cálculos de división se redondearán a $n$ dígitos después del punto decimal.

Los métodos de configuración pueden llamarse como métodos de clase (por ejemplo, Math::BigFloat->accuracy(20)) o como métodos de instancia (por ejemplo, $x->accuracy(20)).

Cuando se llama como método de clase, la configuración se aplica globalmente a todos los objetos futuros creados por new(), y cualquier objeto existente que no haya tenido su precisión establecida explícitamente (es decir, que haya sido creado con new() o se le haya asignado un valor numérico). Cuando se llama como método de instancia, la configuración solo se aplica a ese objeto específico.

Por ejemplo:

    Math::BigFloat->accuracy(50);     # Globalmente, todos los nuevos objetos tendrán precisión 50
    $x = Math::BigFloat->new(100);    # $x tendrá precisión 50
    $x->accuracy(20);                # Ahora $x tiene precisión 20
    $y = Math::BigFloat->new(200);    # $y tiene precisión 50
    print $x->accuracy(), "\n";       # Imprime 20
    print $y->accuracy(), "\n";       # Imprime 50

Los métodos que modifican un objeto devuelven una referencia a ese objeto, lo que permite encadenar métodos. Por ejemplo:

    $x = Math::BigFloat->new(10)->badd(5)->bmul(2); # $x es ahora 30

Algunos métodos, como new(), badd(), bsub(), etc., pueden aceptar argumentos que no son de Math::BigFloat. Estos argumentos se convertirán a Math::BigFloat antes de realizar la operación.

Todos los métodos numéricos devuelven un nuevo objeto Math::BigFloat y no modifican el objeto invocado, excepto aquellos que terminan con = o están explicitamente documentados como modificadores.

Por ejemplo, si llamas $x->badd($y), obtendrás el resultado de la suma como un nuevo objeto, mientras que $x->badd($y)->= modificará $x$.

El módulo Math::BigFloat soporta las siguientes bibliotecas de backend:

  • Math::BigInt::FastCalc (recomendado)

  • Math::BigInt::GMP (si está instalado)

  • Cálculos nativos de Perl (más lento)

La biblioteca de backend se elige automáticamente, pero se puede anular estableciendo la variable $Math::BigFloat::USE_FAST_CALC a 1 o 0 antes de cargar el módulo.

Tenga en cuenta que Math::BigFloat internamente utiliza Math::BigInt para la mantisa y el exponente.

Si está utilizando la biblioteca GMP y necesita realizar cálculos con números de punto flotante que no son de tamaño arbitrario, es posible que desee echar un vistazo a la biblioteca Math::Double.

DESCRIPCIÓN

Math::BigFloat ofrece soporte para números de punto flotante de precisión arbitraria. También se proporciona sobrecarga para operadores de Perl.

Todas las operaciones (incluyendo operaciones básicas de matemáticas) se sobrecargan si declaras tus números de punto flotante de precisión arbitraria como

$x = Math::BigFloat->new('12_3.456_789_123_456_789E-2');

Las operaciones con operadores sobrecargados preservan los argumentos, lo cual es lo que esperas.

Entrada

Valores de entrada a estas rutinas pueden ser cualquier número escalar o cadena que parezca un número. Cualquier valor aceptado por Perl como constante numérica literal se acepta aquí.

  • El espaciado de inicio y fin de línea se ignora.
  • Los ceros de inicio y fin se ignoran, excepto para números de punto flotante con exponente binario, en cuyo caso el número se interpreta como un número de punto flotante octal. Por ejemplo, "01.4p+0" da 1.5, "00.4p+0" da 0.5, pero "0.4p+0" da NaN. Y aunque "0377" da 255, "0377p0" da 255.
  • Si la cadena tiene un prefijo "0x" o "0X", se interpreta como un número hexadecimal.
  • Si la cadena tiene un prefijo "0o" o "0O", se interpreta como un número octal. También se interpreta un literal de punto flotante con prefijo "0" como número octal.
  • Si la cadena tiene un prefijo "0b" o "0B", se interpreta como un número binario.
  • Los caracteres subrayados están permitidos de la misma manera que en las constantes numéricas literales.
  • Si la cadena no puede ser interpretada, se devuelve NaN.
  • Para números de punto flotante hexadecimal, octal y binario, el exponente debe estar separado del significado (mantisa) por la letra "p" o "P", no "e" o "E" como en los números decimales.

Salida

Valores de salida son generalmente objetos Math::BigFloat.

Los operadores booleanos is_zero(), is_one(), is_inf(), etc. devuelven verdadero o falso.

Los operadores de comparación bcmp() y bacmp() devuelven -1, 0, 1, o undef.

MÉTODOS

Math::BigFloat soporta todos los métodos que Math::BigInt soporta, excepto que calcula resultados no enteros cuando es posible. Por favor consulta Math::BigInt para una descripción completa de cada método. A continuación, se muestran solo las diferencias más importantes:

Métodos de configuración

accuracy()
$x->accuracy(5);           # local para $x
CLASS->accuracy(5);        # global para todos los miembros de CLASS
                           # Nota: Esto también aplica a new()!
$A = $x->accuracy();       # leer la precisión que afecta a $x
$A = CLASS->accuracy();    # leer la precisión global

Establece o obtiene la precisión global o local, es decir, cuántos dígitos significativos tiene los resultados. Si estableces una precisión global, esto también aplica a new()!

Advertencia! La precisión está fija, por ejemplo, una vez que creaste un número bajo el influjo de "CLASS->accuracy($A)", todos los resultados de operaciones matemáticas con ese número también se redondean.

En la mayoría de los casos, deberías redondear los resultados explícitamente usando uno de los métodos round() en Math::BigInt, bround() en Math::BigInt o bfround() en Math::BigInt, o pasando la precisión deseada como parámetro adicional a la operación matemática:

my $x = Math::BigInt->new(30000);
my $y = Math::BigInt->new(7);
print scalar $x->copy()->bdiv($y, 2);           # imprimir 4300
print scalar $x->copy()->bdiv($y)->bround(2);   # imprimir 4300
precision()
$x->precision(-2);        # local para $x, redondea al segundo dígito a la derecha de la coma
                          # $x->precision(2);         # mismo, redondea al segundo dígito a la izquierda de la coma
                          # CLASS->precision(5);      # Global para todos los miembros de CLASS
                          # Esto también aplica a new()!
                          # CLASS->precision(-5);     # mismo
                          $P = CLASS->precision();  # leer precisión global
                          $P = $x->precision();     # leer precisión que afecta a $x

from_hex()
$x -> from_hex("0x1.921fb54442d18p+1");

Interpreta el input como una cadena hexadecimal. El prefijo ("0x", "x", ignorando mayúsculas y minúsculas) es opcional. Una sola barra de subrayado ("_") puede colocarse entre dos dígitos. Si el input es inválido, se devuelve NaN. El exponente está en base 2 usando dígitos decimales.

Si se llama como un método de instancia, el valor se asigna al invocand.

Interpreta el input como una cadena octal. Una sola barra de subrayado ("_") puede colocarse entre dos dígitos. Si el input es inválido, se devuelve NaN. El exponente está en base 2 usando dígitos decimales.

Si se llama como un método de instancia, el valor se asigna al invocand.

from_bin()
$x -> from_bin("0b1.1001p-4");

Interpreta el input como una cadena binaria. Un prefijo ("0b" o "b", ignorando mayúsculas y minúsculas) es opcional. Una sola barra de subrayado ("_") puede colocarse entre dos dígitos. Si el input es inválido, se devuelve NaN. El exponente está en base 2 usando dígitos decimales.

Si se llama como un método de instancia, el valor se asigna al invocand.

Interpreta el input como una cadena de bytes, asumiendo un orden de bytes de endianness. El output siempre es un número entero no negativo y finito.

Ver from_bytes() en Math::BigInt.

from_ieee754()
Interpreta el input como un valor codificado según IEEE754-2008. El input puede ser dado como una cadena de bytes, cadena hexadecimal o cadena binaria. El input se asume que está en orden de bytes de endianness.
# Both $dbl, $xr, $xh, and $xb below are 3.141592...
$dbl = unpack "d>", "\x40\x09\x21\xfb\x54\x44\x2d\x18";
$raw = "\x40\x09\x21\xfb\x54\x44\x2d\x18";          # raw bytes
$xr  = Math::BigFloat->from_ieee754($raw, "binary64");
$hex = "400921fb54442d18";
$xh  = Math::BigFloat->from_ieee754($hex, "binary64");
$bin = "0100000000001001001000011111101101010100010001000010110100011000";
$xb  = Math::BigFloat->from_ieee754($bin, "binary64");

Los formatos soportados son todos los formatos IEEE754 binarios: "binary16", "binary32", "binary64", "binary128", "binary160", "binary192", "binary224", "binary256", etc. donde el número de bits es un múltiplo de 32 para todos los formatos mayores que "binary128". Las alias son "half" ("binary16"), "single" ("binary32"), "double" ("binary64"), "quadruple" ("binary128"), "octuple" ("binary256"), y "sexdecuple" ("binary512").

Ver también to_ieee754().

from_base()
$x = Math::BigFloat->from_base(10, 2, 3);

Interpreta el input como un número en base 2, 3, 4, 5, 6, 7, 8, 9 o 10. El segundo parámetro es el sistema de numeración que se usa.

Métodos aritméticos

bdiv()
$x->bdiv($y);               # establece $x al cociente
($q, $r) = $x->bdiv($y);    # también el resto

Es un alias de "bfdiv()".

bmod()
$x->bmod($y);

Devuelve $x módulo $y. Cuando $x es finito, y $y es finito y distinto de cero, el resultado es idéntico al resto después de una división hacia abajo (división F). Si, además, tanto $x como $y son enteros, el resultado es idéntico al resultado del operador % de Perl.

bfdiv()
$q = $x->bfdiv($y);
($q, $r) = $x->bfdiv($y);

En contexto escalar, divide $x entre $y y devuelve el resultado a la precisión o exactitud solicitada o a la precisión por defecto. En contexto de lista, realiza una división hacia abajo (división F), devolviendo un entero $q y un resto $r

$q = floor($x / $y)
$r = $x - $q * $y

de modo que la siguiente relación siempre se cumple

$x = $q * $y + $r

El resto (módulo) es igual a lo que devuelve "$x->bmod($y)".

binv()
$x->binv();

Invierte el valor de $x, es decir, calcula 1/$x.

bmuladd()
$x->bmuladd($y,$z);

Multiplica $x por $y, y luego suma $z al resultado.

Este método se añadió en la v1.87 de Math::BigInt (junio de 2007).

Calcula la expresión "e ** $x" donde "e" es el número de Euler.

Este método se añadió en la v1.82 de Math::BigInt (abril de 2007).

EXACTITUD Y PRECISIÓN

Ver también: Rounding.

Math::BigFloat soporta tanto precisión (redondeo a un cierto lugar antes o después del punto) como exactitud (redondeo a un cierto número de dígitos). Para una documentación completa, ejemplos y consejos sobre estos temas, consulte la sección amplia sobre redondeo en Math::BigInt.

Dado que cosas como sqrt(2) o "1 / 3" deben presentarse con una exactitud limitada, ya que de lo contrario una operación consumiría todos los recursos, cada operación produce no más que el número solicitado de dígitos.

Si no hay una precisión o exactitud global establecida, **y** la operación en cuestión no se llamó con una precisión o exactitud solicitada, **y** la entrada $x no tiene ninguna exactitud o precisión establecida, entonces se utilizará un parámetro de reserva. Por razones históricas, se llama "div_scale" y se puede acceder a él a través de:

$d = Math::BigFloat->div_scale();       # consultar
Math::BigFloat->div_scale($n);          # establecer a $n dígitos

El valor por defecto de "div_scale" es 40.

En caso de que el resultado de una operación tenga más dígitos de los especificados, se redondea. El modo de redondeo adoptado es el modo por defecto, o el proporcionado a la operación después de la escala:

$x = Math::BigFloat->new(2);
Math::BigFloat->accuracy(5);              # 5 dígitos máx.
$y = $x->copy()->bdiv(3);                 # da 0.66667
$y = $x->copy()->bdiv(3,6);               # da 0.666667
$y = $x->copy()->bdiv(3,6,undef,'odd');   # da 0.666667
Math::BigFloat->round_mode('zero');
$y = $x->copy()->bdiv(3,6);               # también dará 0.666667

Tenga en cuenta que "Math::BigFloat->accuracy()" y "Math::BigFloat->precision()" establecen las variables globales, y por lo tanto **cualquier** número recién creado estará sujeto al redondeo global **inmediatamente**. Esto

s significa que en los ejemplos anteriores, el 3 como argumento de "bdiv()" también obtendrá una precisión de 5.

Es menos confuso calcular el resultado completamente y luego redondearlo explícitamente, o usar los parámetros adicionales de las funciones matemáticas de la siguiente manera:

use Math::BigFloat;
$x = Math::BigFloat->new(2);
$y = $x->copy()->bdiv(3);
print $y->bround(5),"\n";               # da 0.66667
o
use Math::BigFloat;
$x = Math::BigFloat->new(2);
$y = $x->copy()->bdiv(3,5);             # da 0.66667
print "$y\n";

Redondeo

bfround ( +$scale )
Redondea al lugar $scale a la izquierda del '.', contando desde el punto. El primer dígito se numera como 1.
bfround ( -$scale )
Redondea al lugar $scale a la derecha del '.', contando desde el punto.
bfround ( 0 )
Redondea a un entero.
bround ( +$scale )
Preserva la precisión a $scale dígitos desde la izquierda (también conocidos como dígitos significativos) y rellena el resto con ceros. Si el número está entre 1 y -1, los dígitos significativos se cuentan a partir del primer cero después del '.'
bround ( -$scale ) y bround ( 0 )
Estos son efectivamente inoperantes.

Todas las funciones de redondeo toman como segundo parámetro un modo de redondeo de uno de los siguientes: 'even', 'odd', '+inf', '-inf', 'zero', 'trunc' o 'common'.

El modo de redondeo predeterminado es 'even'. Usando "Math::BigFloat->round_mode($round_mode);" se puede obtener y establecer el modo predeterminado para redondeos posteriores. El uso de "$Math::BigFloat::$round_mode" ya no es compatible. El segundo parámetro de las funciones de redondeo anula temporalmente el valor predeterminado.

El método "as_int()" devuelve un BigInt a partir de un Math::BigFloat. Utiliza 'trunc' como modo de redondeo para que sea equivalente a:

$x = 2.5;
$y = int($x) + 2;

Puede anular esto pasando el modo de redondeo deseado como parámetro a "as_int()":

$x = Math::BigFloat->new(2.5);
$y = $x->as_number('odd');      # $y = 3

LITERALES NUMERICOS

Después de "use Math::BigFloat ':constant'" todos los literales numéricos en el ámbito dado se convierten en objetos "Math::BigFloat". Esta conversión ocurre en tiempo de compilación.

Por ejemplo,

perl -MMath::BigFloat=:constant -le 'print 2e-150'

imprime el valor exacto de 2e-150. Tenga en cuenta que sin la conversión de constantes la expresión 2e-150 se calcula utilizando escalares de Perl, lo que conduce a un resultado impreciso.

Tenga en cuenta que las cadenas no se ven afectadas, por lo que

use Math::BigFloat qw/:constant/;
$y = "1234567890123456789012345678901234567890"
        + "123456789123456789";

no le dará lo que espera. Necesita un explícito Math::BigFloat->new() alrededor de al menos uno de los operandos. También debe entrecomillar las constantes grandes para evitar la pérdida de precisión:

use Math::BigFloat;
$x = Math::BigFloat->new("1234567889123456789123456789123456789");

Sin las comillas, Perl convierte el número grande a una constante de punto flotante en tiempo de compilación, y luego convierte el resultado a un objeto Math::BigFloat en tiempo de ejecución, lo que resulta en un resultado impreciso.

Literales de punto flotante hexadecimales, octales y binarios

Perl (y este módulo) acepta literales de punto flotante hexadecimales, octales y binarios, pero úselos con cuidado con las versiones de Perl anteriores a la v5.32.0, ya que algunas versiones de Perl dan silenciosamente el resultado incorrecto. A continuación se muestran algunos ejemplos de diferentes formas de escribir el número decimal 314.

Literales de punto flotante hexadecimales:

0x1.3ap+8         0X1.3AP+8
0x1.3ap8          0X1.3AP8
0x13a0p-4         0X13A0P-4

Literales de punto flotante octales (con prefijo "0"):

01.164p+8         01.164P+8
01.164p8          01.164P8
011640p-4         011640P-4

Literales de punto flotante octales (con prefijo "0o") (requiere v5.34.0):

0o1.164p+8        0O1.164P+8
0o1.164p8         0O1.164P8
0o11640p-4        0O11640P-4

Literales de punto flotante binarios:

0b1.0011101p+8    0B1.0011101P+8
0b1.0011101p8     0B1.0011101P8
0b10011101000p-2  0B10011101000P-2

Biblioteca de matemáticas

Las operaciones matemáticas con los números las realiza (por defecto) un módulo llamado Math::BigInt::Calc. Esto equivale a decir:

use Math::BigFloat lib => "Calc";

Puede cambiar esto usando:

use Math::BigFloat lib => "GMP";

Nota: Los paquetes de propósito general no deben ser explícitos sobre la biblioteca a utilizar; deje que el autor del script decida cuál es la mejor.

Nota: La palabra clave 'lib' advertirá cuando la biblioteca solicitada no se haya podido cargar. Para suprimir la advertencia, use 'try' en su lugar:

use Math::BigFloat try => "GMP";

Si su script trabaja con números enormes y Calc es demasiado lento para ellos, también puede forzar la carga de una de estas bibliotecas y si ninguna de ellas se puede utilizar, el código fallará:

use Math::BigFloat only => "GMP,Pari";

Lo siguiente primero intentaría encontrar Math::BigInt::Foo, luego Math::BigInt::Bar, y cuando esto también falla, volvería a Math::BigInt::Calc:

use Math::BigFloat lib => "Foo,Math::BigInt::Bar";

Consulte la documentación de la biblioteca de bajo nivel correspondiente para obtener más detalles.

Consulte Math::BigInt para obtener más detalles sobre el uso de una biblioteca de bajo nivel diferente.

EXPORTACIÓN

"Math::BigFloat" no exporta nada por defecto, pero puede exportar el método "bpi()":

use Math::BigFloat qw/bpi/;
print bpi(10), "\n";
Modificación y =
Cuidado con: 
$x = Math::BigFloat->new(5);
$y = $x;

No hará lo que usted piensa, por ejemplo, hacer una copia de $x. En su lugar, solo hace una segunda referencia al mismo objeto y la almacena en $y. Por lo tanto, cualquier cosa que modifique $x modificará $y (excepto los operadores matemáticos sobrecargados), y viceversa. Consulte Math::BigInt para obtener detalles y cómo evitar eso.

precision() vs. accuracy()
Una dificultad común es usar "precision()" cuando se quiere redondear un resultado a un cierto número de dígitos: 
use Math::BigFloat;
Math::BigFloat->precision(4);           # no hace lo que crees que hace
my $x = Math::BigFloat->new(12345);     # redondea $x a "12000"!
print "$x\n";                           # imprime "12000"
my $y = Math::BigFloat->new(3);         # redondea $y a "0"!
print "$y\n";                           # imprime "0"
$z = $x / $y;                           # 12000 / 0 => NaN!
print "$z\n";
print $z->precision(),"\n";             # 4

Reemplazar "precision()" con "accuracy()" probablemente tampoco sea lo que usted quiere:

use Math::BigFloat;
Math::BigFloat->accuracy(4);          # habilita el redondeo global:
my $x = Math::BigFloat->new(123456);  # redondeado inmediatamente
                                      #   a "12350"
print "$x\n";                         # imprime "123500"
my $y = Math::BigFloat->new(3);       # redondeado a "3
print "$y\n";                         # imprime "3"
print $z = $x->copy()->bdiv($y),"\n"; # 41170
print $z->accuracy(),"\n";            # 4

Lo que usted quiere usar en su lugar es:

use Math::BigFloat;
my $x = Math::BigFloat->new(123456);    # sin redondeo
print "$x\n";                           # imprime "123456"
my $y = Math::BigFloat->new(3);         # sin redondeo
print "$y\n";                           # imprime "3"
print $z = $x->copy()->bdiv($y,4),"\n"; # 41150
print $z->accuracy(),"\n";              # undef

Además de calcular lo que esperaba, el último ejemplo tampoco "contamina" el resultado con una configuración de precisión o exactitud, lo que influiría en cualquier operación posterior.
