Nombre

Mail::Message::Field::Full - construir una línea inteligente en una cabecera de mensaje

Herencia

Sintaxis

# Entender la complejidad de una cabecera de mensaje ...
my $fast = $msg->head->get('subject');
my $full = Mail::Message::Field::Full->from($fast);
my $full = $msg->head->get('subject')->study;  # mismo
my $full = $msg->head->study('subject');       # mismo
my $full = $msg->study('subject');             # mismo
# ... o construir una cabecera de mensaje compleja por ti
my $f = Mail::Message::Field::Full->new('To');
my $f = Mail::Message::Field::Full->new('Subject: hi!');
my $f = Mail::Message::Field::Full->new(Subject => 'hi!');

Descripción

Esta es la implementación completa de una cabecera de mensaje: tiene una comprensión completa de todas las cabeceras predefinidas. Estos objetos serán bastante lentos, ya que las cabeceras pueden ser muy complejas. Por supuesto, esta clase entrega el resultado óptimo, pero con un coste significativo en la performance y el consumo de memoria. ¿Estás dispuesto a aceptarlo?

Esta clase soporta la descripción común de cabeceras de mensaje según RFC2822 (antes RFC822), las extensiones con respecto a las codificaciones de caracteres según RFC2047 y las extensiones en la especificación de idioma y el envío de parámetros largos según RFC2231. Si no necesitas los últimos dos, entonces Mail::Message::Field::Fast y Mail::Message::Field::Flex son suficientes para tu aplicación.

RFC5322 (https://www.rfc-editor.org/rfc/rfc5322.html) describe una lista larga de sintaxis obsoleta para cabeceras de mensaje estructuradas. Esto se refiere principalmente a prohibir los espacios en blanco y la doble línea en lugares inusuales. Esto coincide con el comportamiento natural de MailBox.

$class->from($field, %options)
Convierte cualquier $field (un objeto Mail::Message::Field) en un nuevo objeto Mail::Message::Field::Full. Esta conversión se realiza de forma muy directa: el string generado por el objeto original se parsea nuevamente. Generalmente, el string que se parsea es exactamente la línea (o líneas) encontradas en el origen de entrada, lo cual es una buena cosa, ya que los campos de mensaje completos son más cuidadosos con el contenido real.

%options se pasan al constructor (vea new()). En cualquier caso, algunas extensiones de esta clase de campo Full se devuelven. Depende de qué campo se crea, qué clase se obtiene.

Ejemplo:

my $fast = $msg->head->get('subject');
my $full = Mail::Message::Field::Full->from($fast);
my $full = $msg->head->get('subject')->study;  # mismo
my $full = $msg->head->study('subject');       # mismo
my $full = $msg->study('subject');             # mismo
$class->new(($line | $name, [$body], @attributes), %options)
Crear un objeto de campo correctamente es un trabajo muy trabajoso, porque hay tanta libertad en las RFCs, pero también tantas restricciones. La mayoría de los campos están implementados, pero si tienes tu propio campo (y no quieres contribuirlo a MailBox), simplemente llama a new en tu propio paquete.

Tienes la elección de instanciar el objeto como cadena o en partes preparadas:

  • new($line, %options)

    Pasar un $line como puede ser encontrado en un archivo: una línea (posiblemente doblada) que termina en un newline.

  • new($name, [$body], @attributes, %options)

    Un conjunto de valores que forman la línea.

El $name es un nombre de cabecera bien formado (puedes usar wellformedName() para asegurarte de la mayúscula). El $body es una cadena, un objeto o un array de objetos. En caso de objetos, deben ajustarse al constructor del campo. Los tipos aceptados pueden variar. La lista de atributos opcional contiene objetos de tipo Mail::Message::Field::Attribute. Finalmente, hay algunas opciones. Mejora base, ver "Constructores" en Mail::Message::Field.

$any->decode(STRING, %options)
Decodifica la "STRING" codificada del campo a una cadena utf8. La "STRING" de entrada forma parte de un campo de cabecera, y como tal, puede contener palabras codificadas en el formato "=?...?.?...?=" definido por RFC2047. La "STRING" puede contener múltiples partes codificadas, tal vez usando diferentes conjuntos de caracteres.

Tenga cuidado: DEBE primero interpretar el campo en partes, como frases y comentarios, y luego decodificar cada parte por separado, de lo contrario el texto decodificado puede interferir con sus caracteres de marcado.

Tenga cuidado: la información de idioma, que se define en RFC2231, se ignora.

Las codificaciones con juegos de caracteres desconocidos se dejan sin tocar [requiere v2.085, de lo contrario se produce un error]. Los caracteres desconocidos dentro de un juego de caracteres se reemplazan por un '?'.

-Opción --Defecto
 is_text  true
is_text => BOOLEAN
La codificación del texto es ligeramente más complicada que la codificación de datos estructurados, porque contiene espacios. Los espacios visibles deben ignorarse entre dos palabras codificadas en el texto, pero no cuando una palabra codificada sigue o precede a una palabra no codificada. Las frases y los comentarios son textos.

» ejemplo:

print Mail::Message::Field::Full->decode('=?iso-8859-1?Q?J=F8rgen?=');

Mail::Message::Field::Full(3pm) - Mail::Message::Field::Full man page

NAME

Mail::Message::Field::Full - represents a full mail message field

INHERITANCE

Extends Mail::Message::Field.

SYNOPSIS

  use Mail::Message::Field::Full;

  # Create a new field object
  my $field1 = Mail::Message::Field::Full->new('Content-Type', 'text/plain; charset=US-ASCII');
  my $field2 = Mail::Message::Field::Full->new(
      name     => 'Subject',
      value    => 'The quick brown fox',
      # For folding:
      parent   => $message,
      fieldnum => 3,
  );

  # Get information
  my $name  = $field->name;
  my $value = $field->value;

  # Extract parts of the value
  my ($phrase, $rest) = $field->consumePhrase( q[<"the quoted part" <someone@example.org> >> some text] );

  # Production
  my $text = $field->produceBody; # Get the field formatted for output
  $field->beautify;               # Force reformatting when needed later

DESCRIPTION

This class represents a single field of a mail message. It inherits most of its functionality from Mail::Message::Field. The key difference is that this class expects to store the exact content of the field, including surrounding white-space and folding.

When you create a Field::Full object, it is initialized with the exact text as found in the source of the message. Methods like name() and value() extract the relevant parts from this text. This approach preserves the original formatting of the field, which is important for headers that are rarely seen, like 'Resent-Bcc'.

For fields where structure is important, like Content-Type or From, you should use a more specific subclass of Field.

OVERLOADED

call()
This method is overloaded to provide access to the field's value. It is the same as calling value().
eq()
String equality comparison.
ne()
String inequality comparison.
lt()
String less-than comparison.
le()
String less-than-or-equal comparison.
gt()
String greater-than comparison.
ge()
String greater-than-or-equal comparison.
cmp()
String comparison.

METHODS

$obj->beautify( [$boolean] )
When called without arguments, returns true if the field content is already formatted for output. When called with a true value, it marks the field as formatted. When called with a false value, it marks the field as not formatted, forcing a reformat when produceBody() is called.
$obj->consumePhrase(STRING)
Parses the beginning of "STRING". It expects that the value of the field starts with a phrase. A phrase is defined as a sequence of characters enclosed in angle brackets (<>) or quotes (""). These delimiters can be escaped with a backslash (\). The optional quotes are ignored. Be warned that "" will return an empty, valid phrase.

» example:

my ($phrase, $rest) = $field->consumePhrase( q["hi!" <sales@example.com>] );
$obj->parse(STRING)
Get the detailed information from "STRING", and store the data found in the field object. The accepted input is very field type dependent. Unstructured fields do no parsing whatsoever.
$obj->produceBody()
Produce the text for the field, based on the information stored within the field object.

Usually, you wish the exact same line as was found in the input source of a message. But when you have created a field yourself, it should get formatted. You may call beautify() on a preformatted field to enforce a call to this method when the field is needed later.

DIAGNOSTICS

Warning: Field content is not numerical: $content
The numeric value of a field is requested (for instance the "Lines" or "Content-Length" fields should be numerical), however the data contains weird characters. Cast by toInt()
Error: Field name too long (max $length), in '$name'
It is not specified in the RFCs how long a field name can be, but at least it should be a few characters shorter than the line wrap. Cast by fold()
Warning: Illegal character in charset '$charset'
The field is created with an utf8 string which only contains data from the specified character set. However, that character set can never be a valid name because it contains characters which are not permitted. Cast by encode()
Warning: Illegal character in field name $name
A new field is being created which does contain characters not permitted by the RFCs. Using this field in messages may break other e-mail clients or transfer agents, and therefore mutulate or extinguish your message. Cast by consume()
Warning: Illegal character in language '$lang'
The field is created with data which is specified to be in a certain language, however, the name of the language cannot be valid: it contains characters which are not permitted by the RFCs. Cast by encode()
Warning: Illegal encoding '$encoding', used 'q'
The RFCs only permit base64 ("b " or "B ") or quoted-printable ("q" or "Q") encoding. Other than these four options are illegal. Cast by encode()
Error: Package $package does not implement $method.
Fatal error: the specific package (or one of its superclasses) does not implement this method where it should. This message means that some other related classes do implement this method however the class at hand does not. Probably you should investigate this and probably inform the author of the package. Cast by notImplemented()
