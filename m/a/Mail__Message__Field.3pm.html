NOMBRE

Mail::Message::Field - una línea de encabezado de un mensaje

HERENCIA

Mail::Message::Field
  es un Mail::Reporter
Mail::Message::Field es extendido por
  Mail::Message::Field::Fast
  Mail::Message::Field::Flex
  Mail::Message::Field::Full

SINOPSIS

my $field = Mail::Message::Field->new(From => 'fish@tux.aq');
print $field->name;
print $field->body;
print $field->comment;
print $field->content;  # cuerpo & comentario
$field->print(\*OUT);
print $field->string;
print "$field\n";
print $field->attribute('charset') || 'us-ascii';

DESCRIPCIÓN

Esta implementación sigue las directrices de rfc2822 lo más cerca posible, y puede producir una salida diferente a las implementaciones basadas en el obsoleto rfc822. Sin embargo, la salida antigua seguirá siendo aceptada.

Estos objetos almacenan una línea de encabezado y facilitan rutinas de acceso a la información oculta en ella. Además, puede que quieras echar un vistazo a los métodos añadidos de un mensaje:

my @from    = $message->from;
my $sender  = $message->sender;
my $subject = $message->subject;
my $msgid   = $message->messageId;
my @to      = $message->to;
my @cc      = $message->cc;
my @bcc     = $message->bcc;
my @dest    = $message->destinations;
my $other   = $message->get('Reply-To');

Extiende "DESCRIPTION" en Mail::Reporter.

SOBRECARGADOS

sobrecarga: "" stringificación
Produce el cuerpo desplegado del campo, que puede ser lo que esperas. Esto es lo que hace que el objeto de campo parezca una cadena simple. La cadena se produce mediante unfoldedBody().

» ejemplo:

print $msg->get('subject');  # vía sobrecarga
print $msg->get('subject')->unfoldedBody; # lo mismo
my $subject = $msg->get('subject') || 'tu correo';
print "Re: $subject\n";
sobrecarga: 0+ numificación
Cuando el campo es numérico, se devolverá el valor. El resultado se produce mediante toInt(). Si el valor no es correcto, se produce un 0, para simplificar los cálculos.
sobrecarga: <=> comparación numérica
Compara el contenido numérico del campo con otra cosa.

» ejemplo:

if($msg->get('Content-Length') > 10000) ...
if($msg->size > 10000) ... ; # lo mismo, pero mejor
sobrecarga: bool booleano
Siempre "verdadero", para que sea posible decir if($field).
sobrecarga: cmp comparación de cadenas
Compara el cuerpo desplegado de un campo con otro campo o una cadena, usando el "cmp" incorporado.

El campo

$any->isStructured()
Algunos campos se describen en los RFC como estructurados: con una sintaxis bien descrita. Estos campos tienen ideas comunes sobre comentarios y similares, lo que no comparten con campos no estructurados, como el campo "Subject".

» ejemplo:

my $field = Mail::Message::Field->new(From => 'me');
if($field->isStructured)
Mail::Message::Field->isStructured('From');
$obj->length()
Devuelve la longitud total del campo en caracteres, que incluye el nombre del campo, el cuerpo y los caracteres de plegado.
$obj->nrLines()
Devuelve el número de líneas necesarias para mostrar esta línea de encabezado.
$obj->print( [$fh] )
Imprime toda la línea de encabezado en el manejador de archivo especificado. Una línea puede resultar en más de una línea impresa, debido al plegado de líneas largas. El $fh es el manejador seleccionado por defecto.
$obj->size()
Devuelve el número de bytes necesarios para mostrar esta línea de encabezado. Igual que length().
$obj->string( [$wrap] )
Devuelve el campo como una cadena. Por defecto, esto devuelve lo mismo que folded(). Sin embargo, el opcional $wrap provocará que se vuelva a plegar (sin cambiar el plegado almacenado dentro del campo).
$obj->toDisclose()
Devuelve si este campo puede ser revelado a otras personas, por ejemplo, al enviar el mensaje a otra parte. Devuelve una condición de "verdadero" o "falso". Ver también Mail::Message::Head::Complete::printUndisclosed().

Acceso al nombre

$obj->Name()
Devuelve el nombre de este campo en su capitalización original. Ver también name().
$obj->name()
Devuelve el nombre de este campo, con todos los caracteres en minúsculas para facilitar la comparación. Ver también Name().
$obj->wellformedName( [STRING] )
(Método de instancia, método de clase) Como método de instancia, el nombre del campo actual se formatea correctamente y se devuelve. Cuando se utiliza una "STRING", se formatea esa.

» ejemplo:

print Mail::Message::Field->Name('content-type')
  # -->  Content-Type
my $field = $head->get('date');
print $field->Name;
  # -->  Date

Acceso al cuerpo

$obj->body()
Este método puede no ser lo que buscas: foldedBody() y unfoldedBody() son probablemente donde estás buscando. Estos devolverán el contenido completo de un campo, incluso cuando está estructurado.

Devuelve el cuerpo del campo. Cuando este campo está estructurado, se eliminará todo lo que esté detrás del primer punto y coma (";"). En cualquier caso, la cadena se desplegará. Si el campo está estructurado se define mediante isStructured().

$obj->folded()
Devuelve la versión plegada de todo el encabezado. Cuando el encabezado es más corto que la longitud de plegado, se devuelve una lista de una línea. De lo contrario, se devolverán más líneas, todas excepto la primera comenzando con al menos un espacio. Ver también foldedBody() para obtener la misma información sin el nombre del campo.

En contexto escalar, las líneas se entregan en una sola cadena, lo que es un poco más rápido porque así es como se almacenan internamente...

» ejemplo:

my @lines = $field->folded;
print $field->folded;
print scalar $field->folded; # más rápido
$obj->foldedBody( [$body] )

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

Devuelve el cuerpo como un conjunto de líneas. En contexto escalar, esta será una línea que contiene saltos de línea. Tenga cuidado con los saltos de línea cuando realice coincidencias de patrones en el resultado de este método.

El argumento opcional $body cambia el cuerpo del campo. El plegado del argumento debe ser correcto.

$any->stripCFWS( [STRING] )
Elimina los comentarios y los espacios en blanco de plegado de la "STRING". Sin cadena y solo como método de instancia, se elimina y se devuelve el unfoldedBody().

ADVERTENCIA: Esta operación solo está permitida para campos de encabezado estructurados (que están definidos por las diversas RFC como tales. No querrá que se eliminen partes dentro de llaves que se encuentran en la línea del asunto, por ejemplo.

$obj->unfoldedBody( [$body, [$wrap]] )
Devuelve el cuerpo como una única línea, donde se elimina toda la información de plegado (si está disponible). Esta línea tampoco terminará en un salto de línea.

El argumento opcional $body cambia el cuerpo del campo. El plegado correcto se realiza antes de la asignación. El $wrap puede especificarse para forzar un tamaño de plegado.

» ejemplo:

my $body = $field->unfoldedBody;
print "$field";   # a través de sobrecarga

Acceso al contenido

$obj->addresses()
Devuelve una lista de objetos Mail::Address, que representan las direcciones de correo electrónico que se encuentran en esta línea de encabezado.

» ejemplo:

my @addr = $message->head->get('to')->addresses;
my @addr = $message->to;
$obj->attribute( $name, [$value] )
Obtiene el valor de un atributo, opcionalmente después de establecerlo en un nuevo valor. Los atributos forman parte de algunos campos de encabezado y se esconden en el campo de comentarios. Si el atributo no existe, se devuelve "undef". El atributo todavía está codificado.

» ejemplo:

my $field = Mail::Message::Field->new(
 'Content-Type: text/plain; charset="us-ascii"');
print $field->attribute('charset');
  # --> us-ascii
print $field->attribute('bitmap') || 'no'
  # --> no
$field->atrribute(filename => '/tmp/xyz');
$field->print;
  # --> Content-Type: text/plain; charset="us-ascii";
  #       filename="/tmp/xyz"
  # Plegado automáticamente y sin duplicados.
$obj->attributes()
Devuelve una lista de pares clave-valor, donde los valores aún no se han decodificado. Las claves pueden aparecer más de una vez.

» ejemplo:

my @pairs = $head->get('Content-Disposition')->attributes;
$obj->comment( [STRING] )
Devuelve el comentario desplegado (parte después de un punto y coma) en una línea de encabezado estructurada. Opcionalmente, después de establecerlo primero en una nueva "STRING". Cuando se especifica "undef" como "STRING", se elimina el comentario. Si el campo está estructurado se define mediante isStructured().

La parte del comentario de un campo de encabezado a menudo contiene "atributos". A menudo es preferible utilizar attribute() sobre ellos.

$obj->study()
Estudia el campo de encabezado en detalle: activa el análisis completo y la comprensión detallada del contenido de los campos. Mail::Message::Field::Fast y los objetos Mail::Message::Field::Fast se transformarán en cualquier objeto Mail::Message::Field::Full.

» ejemplo:

my $subject = $msg->head->get('subject')->study;
my $subject = $msg->head->study('subject');  # lo mismo
my $subject = $msg->study('subject');        # lo mismo
$any->toDate( [$time] )
Convierte una marca de tiempo en un formato de fecha compatible con rfc2822. Esto difiere de la salida predeterminada de "localtime" en contexto escalar. Sin argumento, se utiliza "localtime" para obtener la hora actual. $time puede especificarse como un número (como el resultado de time()) y como una lista (como la producida por c<localtime()> en contexto de lista).

Asegúrese de tener configurada correctamente su zona horaria, especialmente cuando este script se ejecuta automáticamente.

» ejemplo:

my $now = time;
Mail::Message::Field->toDate($now);
Mail::Message::Field->toDate(time);
Mail::Message::Field->toDate(localtime);
Mail::Message::Field->toDate;      # lo mismo
# devuelve algo como:
#     Wed, 28 Aug 2002 10:40:25 +0200
$obj->toInt()
Devuelve el valor relacionado con este campo como un entero. Se realiza una comprobación para determinar si es correcto.

Internos

$obj->consume( $line | <$name,<$body|$objects>> )
Acepta una línea completa de campo $line, o un par con el $name del campo y el $body. En este último caso, los datos de $body pueden especificarse como un array de $objects que se convierten a cadena. Devuelve un par bien formateado de dos cadenas: el nombre del campo y un cuerpo plegado.

Este método es llamado por new(), y generalmente no por un programa de aplicación. Los detalles sobre la conversión de los $objects a contenido de campo se explican en "Especificación de datos de campo".

$obj->defaultWrapLength( [$length] )
Cualquier campo de cualquier encabezado para cualquier mensaje tendrá este plegado predeterminado. Esto se mantiene en una variable global. Sin un $length especificado, se devuelve el valor actual. El valor predeterminado es 78.
$any->fold( $name, $body, [$maxchars] )
Hace que el campo de encabezado con $name se pliegue en varias líneas. El ajuste se realiza insertando saltos de línea antes de un espacio en blanco en el $body, de modo que ninguna línea supere los $maxchars y cada línea sea lo más larga posible.

Las RFC solicitan plegar en lugares convenientes, pero esta solicitud se ignora principalmente porque haría que el plegado fuera demasiado lento.

$obj->setWrapLength( [$length] )
Fuerza el ajuste de este campo a la longitud especificada de $length caracteres. El ajuste se realiza con fold() y los resultados se almacenan dentro del objeto de campo.

» ejemplo: volver a plegar el campo

$field->setWrapLength(99);
$obj->stringifyData(STRING|ARRAY|$objects)
Este método implementa la traducción de objetos proporcionados por el usuario a campos ASCII. El proceso se explica en "Especificación de datos de campo".
$obj->unfold(STRING)
La acción inversa de fold(): todas las líneas que forman el cuerpo de un campo se unen en una sola eliminando todos los terminadores de línea (incluso el último). También se eliminan los posibles espacios en blanco iniciales en la primera línea.

DETALLES

Sintaxis del campo

Los campos se almacenan en el encabezado de un mensaje, que está representado por objetos Mail::Message::Head. Un campo es una combinación de un nombre, un cuerpo y atributos. Especialmente el término "cuerpo" es motivo de confusión: a veces los atributos se consideran parte del cuerpo.

El nombre del campo va seguido de dos puntos ("":"", sin espacios antes, pero con un espacio después). Cada atributo va precedido de un punto y coma separado (";"). Los nombres de los campos no distinguen entre mayúsculas y minúsculas y no pueden contener espacios.

» Ejemplo: de campos

Campos correctos:

Field: hi!
Content-Type: text/html; charset=latin1

Campos incorrectos, pero aceptados:

Field : incorrecto, espacio antes de los dos puntos
Field:                 # incorrecto, vacío
Field:no es bueno, se prefiere el espacio después de los dos puntos
One Two: incorrecto, espacio en el nombre

Campos plegados

Los campos que son largos pueden plegarse para ocupar más de una línea. El límite real para las líneas en los mensajes es de solo 998 caracteres, sin embargo, líneas tan largas no son fáciles de leer sin el soporte de una aplicación. Por lo tanto, rfc2822

Plegado de campos

El estándar RFC2822 (que define la sintaxis de los mensajes) especifica explícitamente que las líneas de campo pueden reformatearse en múltiples líneas de campo sin cambio de significado, añadiendo caracteres de nueva línea a cualquier campo antes de un espacio en blanco o tabulación.

Normalmente, las líneas se reformatean para crear líneas de un máximo de 78 caracteres. Algunas aplicaciones se esfuerzan más por plegar en puntos convenientes, como antes de los atributos. Especialmente el campo "Received" a menudo se pliega manualmente en un diseño agradable. En la mayoría de los casos, sin embargo, se prefiere producir líneas lo más largas posible pero con un máximo de 78.

TENGA CUIDADO de que todos los campos pueden ser sometidos a plegado, y que normalmente querrá el valor desplegado.

» Ejemplo: de plegado de campos

Subject: this is a short line, and not folded
Subject: this subject field is much longer, and therefore
 folded into multiple
 lines, although one more than needed.

Campos estructurados

El RFC2822 describe explícitamente un gran número de campos de encabezado. Estos campos tienen un significado definido. Para algunos de los campos, como el campo "Subject", el significado es directo: el contenido en sí. Estos campos son los *Campos no estructurados*.

Otros campos tienen una sintaxis interna bien definida porque su contenido es necesario para las aplicaciones de correo electrónico. Por ejemplo, el campo "To" contiene direcciones que deben ser entendidas por todas las aplicaciones de la misma manera. Estos son los *Campos estructurados*, vea isStructured().

Comentarios en campos

Los campos estructurados pueden contener comentarios, que son fragmentos de texto encerrados entre paréntesis. Estos comentarios pueden colocarse casi en cualquier lugar de la línea y deben ser ignorados por la aplicación. No todas las aplicaciones son capaces de manejar comentarios correctamente en todas las circunstancias.

» Ejemplo: de comentarios en campos

To: mailbox (Mail::Box mailinglist) <mailbox@overmeer.net>
Date: Thu, 13 Sep 2001 09:40:48 +0200 (CEST)
Subject: goodbye (was: hi!)

En la primera línea, el texto "Mail::Box mailinglist" se utiliza como comentario. Tenga en cuenta que el RFC2822 establece explícitamente que los comentarios en las especificaciones de direcciones de correo electrónico no deben considerarse que contengan información útil.

En la segunda línea, la zona horaria se especifica como comentario. El formato del campo "Date" no tiene forma de indicar la zona horaria del remitente, sino que solo contiene la diferencia de zona horaria con respecto a UTC, sin embargo, se podría decidir añadir esto como comentario. Las aplicaciones deben ignorar estos datos porque el campo "Date" está estructurado.

El último campo no está estructurado. El texto entre paréntesis es una parte integral de la línea de asunto.

Obtener un campo

Tantas como programas haya manejando correo electrónico, tantas variaciones en el acceso a la información del encabezado son solicitadas. Tenga cuidado con la forma en que accede a los datos: lea las variaciones descritas aquí y decida qué solución se adapta mejor a sus necesidades.

Usando el campo get()

La interfaz get() se copia de otros módulos de Perl que pueden manejar mensajes de correo electrónico. Muchas aplicaciones que simplemente reemplazan los objetos Mail::Internet por objetos Mail::Message funcionarán sin modificaciones.

Hay más de un método get. Los resultados exactos dependen de cuál get utilice. Cuando se llama a Mail::Message::get(), obtendrá el contenido desplegado, despojado de comentarios, despojado de atributos del campo como una cadena. Las codificaciones de juegos de caracteres seguirán en la cadena. Si el mismo nombre de campo aparece más de una vez en el encabezado, solo se devuelve el último valor.

Cuando se llama a Mail::Message::Head::get() en contexto escalar, se devuelve el último campo con el nombre especificado como objeto de campo. Este objeto se convierte en cadena al contenido desplegado del campo, incluyendo atributos y comentarios. En contexto de lista, todas las apariciones del campo en el encabezado se devuelven como objetos.

TENGA CUIDADO de que algunas líneas parecen únicas, pero no lo son según el RFC oficial. Por ejemplo, los campos "To" pueden aparecer más de una vez. Si su programa llama a get('to') en contexto escalar, se pierde información.

» Ejemplo: de uso de get()

print $msg->get('subject') || 'no subject';
print $msg->head->get('subject') || 'no subject';
my @to = $msg->head->get('to');

Usando el campo study()

Como el nombre "study" ya implica, esta forma de acceder a los campos es mucho más minuciosa pero también más lenta. El "estudio" de un campo es como un "get", pero proporciona un fácil acceso al contenido del campo y maneja la decodificación de juegos de caracteres correctamente.

El método Mail::Message::study() solo devolverá el último campo con ese nombre como objeto. Mail::Message::Head::study() y Mail::Message::Field::study() devuelven todos los campos cuando se usan en contexto de lista.

» Ejemplo: de uso de study()

print $msg->study('subject') || 'no subject';
my @rec  = $msg->head->study('Received');
my $from = $msg->head->get('From')->study;
my $from = $msg->head->study('From');  # same
my @addr = $from->addresses;

Usando grupos reenviados

Algunos campos pertenecen juntos en un grupo de campos. Por ejemplo, un conjunto de líneas se utiliza para definir un paso en el proceso de transporte de correo. Cada paso añade una línea "Received", y opcionalmente algunas líneas "Resent-*" y "Return-Path". Estos grupos de líneas deben permanecer juntos y en orden cuando se procesa el encabezado del mensaje.

El objeto "Mail::Message::Head::ResentGroup" simplifica el acceso a estos campos relacionados. Estos grupos reenviados pueden ser eliminados como un todo, o construidos correctamente.

» Ejemplo: de uso de grupos reenviados

my $rgs = $msg->head->resentGroups;
$rgs[0]->delete if @rgs;
$msg->head->removeResentGroups;

Los datos del campo

Hay muchas maneras de obtener la información de los campos como objeto, y también hay muchas maneras de procesar estos datos dentro del campo.

Acceso al campo

  • string()

    Devuelve el texto del cuerpo exactamente como se imprimirá en el archivo cuando se llame a print(), por lo tanto, nombre, cuerpo principal y atributos.

  • foldedBody()

    Devuelve el texto del cuerpo, como string(), pero sin el nombre del campo.

  • unfoldedBody()

    Devuelve el texto del cuerpo, como foldedBody(), pero con todos los saltos de línea eliminados. Esta es la forma normal de obtener el contenido de los campos no estructurados. Las codificaciones de juegos de caracteres seguirán presentes. Los campos se convierten en cadena a su representación desplegada.

  • stripCFWS()

    Devuelve el texto de los campos estructurados, donde los saltos de línea y los comentarios se eliminan de la cadena. Este es un buen punto de partida para analizar el campo, por ejemplo, para encontrar direcciones de correo electrónico en ellos.

  • Mail::Message::Field::Full::decodedBody()

    Los campos estudiados pueden producir el texto desplegado decodificado en cadenas utf8. Este es un proceso costoso, pero la única forma correcta de obtener los datos del campo. Más útil para personas que no viven en el espacio ASCII.

  • Campos estudiados

    Los campos estudiados tienen métodos potentes para proporcionar formas de acceder y producir el contenido de campos (estructurados) exactamente como lo prescriben los RFC involucrados.

Usando acceso simplificado a campos

Algunos campos se acceden con tanta frecuencia que existen métodos de soporte para proporcionar acceso simplificado. Todos estos métodos se llaman directamente sobre un mensaje.

» Ejemplo: de acceso simplificado a campos

print $message->subject;
print $message->get('subject') || '';  # same
my @from = $message->from; # returns addresses
$message->reply->send if $message->sender;

El método "sender" devolverá la dirección especificada en el campo "Sender", o la primera nombrada en el campo "From". Devolverá "undef" en caso de que no se conozca ninguna dirección.

Especificando datos de campo

Los datos de campo pueden ser cualquier cosa, muy dependiente del tipo de campo en cuestión. Si decide construir los campos con mucho cuidado a través de alguna extensión de Mail::Message::Field::Full (como a través de objetos Mail::Message::Field::Addresses), entonces tendrá protección incorporada. Sin embargo, puede crear rotundamente cualquier objeto Mail::Message::Field basado en algunos datos.

Al crear un campo, puede especificar una cadena, un objeto o una matriz de cadenas y objetos. Por el momento, los objetos solo se utilizan para ayudar a la construcción de direcciones de correo electrónico, sin embargo, puede añadir algunos propios.

Las siguientes reglas (implementadas en stringifyData()) se observan dado que el argumento es:

  • una cadena

    La cadena debe seguir las (complicadas) reglas del rfc2822, y se convierte en contenido de campo como se especifica. Cuando la cadena no termina con un salto de línea ("\n"), se plegará según las reglas estándar.

  • un objeto Mail::Address

    El objeto Perl más utilizado para analizar y producir líneas de dirección. Este objeto no entiende las codificaciones de juegos de caracteres en frases.

  • un objeto Mail::Identity

    Como parte de la distribución User::Identity, este objeto tiene una comprensión completa del significado de una dirección de correo electrónico, relacionada con una persona. Se implementan todas las características definidas por rfc2822.

Mail::Message::Field(3pm)

NAME

Mail::Message::Field - implement a single message header field

INHERITANCE

Mail::Message::Field

  • Mail::Reporter

SYNOPSIS

  use Mail::Message::Field;
  use Mail::Message;

  my $field = Mail::Message::Field->new( 'Subject: hi!' );
  my $field = Mail::Message::Field->new( 'Subject', 'hi!' );
  my $field = Mail::Message::Field->new( Subject => 'hi!' );

  print $field->name;      # ==> Subject
  print $field->print;     # ==> Subject: hi!

  my $msg = Mail::Message->build( Subject => 'a test' );
  print $msg->get('Subject')->print;

DESCRIPTION

A message header field is a name-value pair. This module implements the object for a single field. The name and value can be extracted and presented. The field can be modified.

The values are stored internally in an array. The default representation is a comma-separated list of the elements in the array.

See METHODS for more details.

OVERLOADED

stringification
Returns the full field line, like "Subject: hi!".

METHODS

new(NAME, VALUE?)
new(FIELD_STRING)
new(HASHREF)
Constructor. Creates a new field object.
  • NAME: the name of the field (e.g. "Subject"). Case is ignored during comparison, but the original case is kept.
  • VALUE: the content of the field. This can be a scalar or an array reference.
  • FIELD_STRING: a string containing the full field line (e.g. "Subject: hi!").
  • HASHREF: a hash reference where the key is the field name and the value is the field content.
name([NAME])
Get or set the name of the field. The name is normalized to the first character uppercase and the rest lowercase. It is stored internally in that format.
value([VALUE])
Get or set the value of the field. This returns an array reference containing all the values that are part of this field.
print([FILEHANDLE])
Print the field to the given filehandle. Defaults to STDOUT. The output is formatted according to RFC 5322.
set(NAME, VALUE)
Set the field name and value. This replaces the current field name and value.
add(NAME, VALUE)
Add a value to an existing field name. If the field name doesn't exist, it is created. If the field name exists, the new value is appended to the existing values.
get(NAME)
Get the value of a specific field name. If the field name does not exist, it returns undef. The value is returned as an array reference.
del(NAME)
Delete a field name and its value. If the field name doesn't exist, nothing happens.
keys()
Return a list of all field names present in the message.
study()
Upgrade the field object to a more specific implementation based on its content. This is usually done automatically when needed.
flush()
Rebuild the internal representation of the field. This is useful after modifications.
isField(NAME)
Check if a field with the given NAME exists.

DETAILS

The Mail::Message::Field object stores its values in an array. When you access the values using value(), you get an array reference. If you want to join the elements into a comma-separated list, you have to do it yourself.

» Example: specifying simple field data

my $f = Mail::Message::Field->new(Subject => 'hi!');
my $b = Mail::Message->build(Subject => 'monkey');

» Example: s specifying e-mail addresses for a field

use Mail::Address;
my $fish = Mail::Address->new('Mail::Box', 'fish@tux.aq');
print $fish->format;   # ==> Mail::Box <fish@tux.aq>
my $exa  = Mail::Address->new(undef, 'me@example.com');
print $exa->format;    # ==> me@example.com
my $b = $msg->build(To => "you@example.com");
my $b = $msg->build(To => $fish);
my $b = $msg->build(To => [ $fish, $exa ]);
my @all = ($fish, "you@example.com", $exa);
my $b = $msg->build(To => \@all);
my $b = $msg->build(To => [ "xyz", @all ]);

» Example: specifying identities for a field

use User::Identity;
my $patrik = User::Identity->new(
  name      => 'patrik',
  full_name => "Patrik Fältström",  # from rfc
  charset   => "ISO-8859-1",
);
$patrik->add(email => "him@home.net");
my $b = $msg->build(To => $patrik);
$b->get('To')->print;
  # ==> =?ISO-8859-1?Q?Patrik_F=E4ltstr=F6m?=
  #     <him@home.net>

Field class implementation

For performance reasons only, there are three types of fields: the fast, the flexible, and the full understander:

  • Mail::Message::Field::Fast

    "Fast" objects are not derived from a "Mail::Reporter". The consideration is that fields are so often created, and such a small objects at the same time, that setting-up a logging for each of the objects is relatively expensive and not really useful. The fast field implementation uses an array to store the data: that will be faster than using a hash. Fast fields are not easily inheritable, because the object creation and initiation is merged into one method.

  • Mail::Message::Field::Flex

    The flexible implementation uses a hash to store the data. The new() and "init" methods are split, so this object is extensible.

  • Mail::Message::Field::Full

    With a full implementation of all applicable RFCs (about 5), the best understanding of the fields is reached. However, this comes with a serious memory and performance penalty. These objects are created from fast or flex header fields when study() is called.

DIAGNOSTICS

Warning: Field content is not numerical: $content
The numeric value of a field is requested (for instance the "Lines" or "Content-Length" fields should be numerical), however the data contains weird characters. Cast by toInt()
Error: Field name too long (max $length), in '$name'
It is not specified in the RFCs how long a field name can be, but at least it should be a few characters shorter than the line wrap. Cast by fold()
Warning: Illegal character in field name $name
A new field is being created which does contain characters not permitted by the RFCs. Using this field in messages may break other e-mail clients or transfer agents, and therefore mutulate or extinguish your message. Cast by consume()
Error: Package $package does not implement $method.
Fatal error: the specific package (or one of its superclasses) does not implement this method where it should. This message means that some other related classes do implement this method however the class at hand does not. Probably you should investigate this and probably inform the author of the package. Cast by notImplemented()
