HERENCIA

Mail::Box::MH
  es una Mail::Box::Dir
  es una Mail::Box
  es una Mail::Reporter

SINOPSIS

mi $folder = Mail::Box::MH->new(folder => $ENV{MAIL}, ...);

Cómo funcionan las carpetas MH

Las carpetas de tipo MH utilizan un directorio para almacenar los mensajes de una carpeta. Cada mensaje se almacena en un archivo separado. Esto parece útil, porque los cambios en una carpeta solo modifican unos pocos de estos archivos pequeños, a diferencia de las carpetas basadas en archivos donde los cambios en una carpeta provocan la reescritura de archivos de carpeta enormes.

Sin embargo, las carpetas basadas en MH tienen un rendimiento muy bajo si necesita información de encabezado de todos los mensajes. Por ejemplo, si desea tener conocimiento completo sobre todos los hilos de mensajes (ver Mail::Box::Thread::Manager) en la carpeta, requiere leer todas las líneas de encabezado en todos los archivos de mensajes. Y, por lo general, se desea leer sus mensajes en hilos.

Por lo tanto, cada mensaje se escribe en un archivo separado. Los nombres de archivo son números, que se cuentan a partir de 1. Junto a estos archivos de mensajes, un directorio puede contener un archivo llamado ".mh_sequences", que almacena etiquetas relacionadas con los mensajes. Además, un directorio de carpetas puede contener subdirectorios, que se consideran subcarpetas.

Esta implementación

Esta implementación soporta el archivo ".mh-sequences" y las subcarpetas. Además de esto, se realizan considerables esfuerzos para evitar la lectura de cada archivo de mensaje. Esto debería aumentar el rendimiento de la distribución MailBox sobre otros módulos de Perl que pueden leer carpetas.

Los tipos de carpetas que almacenan sus mensajes cada uno en un archivo, juntos en un directorio, son malos para el rendimiento. Considere que desea conocer los temas de todos los mensajes, mientras navega por una carpeta con su cliente de lectura de correo. Esto causaría que se lean todos los archivos de mensajes.

Mail::Box::MH tiene dos formas de intentar mejorar el rendimiento. Puede usar un archivo de índice y usar la carga retardada. La combinación funciona aún mejor. Ambos se explican en las siguientes secciones.

Un archivo de índice

Si especifica new(keep_index), entonces todas las líneas de encabezado de todos los mensajes de la carpeta que se han leído una vez, también se escribirán en un archivo de índice dedicado (un archivo por carpeta). El nombre de archivo predeterminado es ".index"

Sin embargo, los archivos de índice no son compatibles con ningún otro lector que admita MH (que yo sepa). Si lee las carpetas con dicho cliente, no causará conflictos irrecuperables con este archivo de índice, sino que, como mucho, será perjudicial para el rendimiento.

Si no usa (o no quiere usar) un archivo de índice, la carga retardada puede salvarle el día.

DIAGNÓSTICOS

Error: No se puede añadir mensaje sin bloqueo en $folder.
Es imposible añadir uno o más mensajes a la carpeta que no está abierta, porque su bloqueo falla. La carpeta puede estar en uso por otra aplicación, o es posible que necesite especificar algunas opciones relacionadas con el bloqueo (ver new()). Emitido por appendMessages()
Error: No se puede crear la carpeta MH $name: $!
Por alguna razón, es imposible crear la carpeta. Compruebe los permisos y el $name de la carpeta. ¿Existe la ruta al directorio que se va a crear? Emitido por create()
Advertencia: No se puede crear la subcarpeta $name para $self: $!
Emitido por openSubFolder()
Error: No se puede escribir la carpeta $name sin bloqueo.
Es imposible obtener un bloqueo en la carpeta, lo que significa que los cambios no se pueden realizar. Es posible que necesite ajustar las opciones relacionadas con el bloqueo que están disponibles al crear la carpeta. Emitido por writeMessages()
Advertencia: Cambios no escritos en la carpeta de solo lectura $self.
Ha abierto la carpeta en modo de solo lectura, lo que se establece por defecto con new(access), ha realizado modificaciones y ahora desea cerrarla. Establezca close(force) si desea anular el modo de acceso, o cierre la carpeta con close(write) establecido en "NEVER". Emitido por close()
Error: Fallo al copiar un mensaje.
Por alguna razón, por ejemplo, disco lleno, eliminado por un proceso externo o protección de lectura, es imposible copiar uno de los mensajes. La copia continuará para los demás mensajes. Emitido por copyTo()
Error: La carpeta de destino $name no se puede escribir.
La carpeta a la que se copian los mensajes no está abierta con acceso de escritura (ver new(access)). Esto no tiene relación con el permiso de escritura en la carpeta que controla su sistema operativo. Emitido por copyTo()
Advertencia: Mensajes diferentes con id $msgid
El id del mensaje se descubre más de una vez dentro de la misma carpeta, pero el contenido del mensaje parece ser diferente. Esto no debería ser posible: cada mensaje debe ser único. Emitido por messageId()
Error: La carpeta $name está abierta en modo de solo lectura
No puede escribir en esta carpeta a menos que la haya abierto para escribir o añadir con new(access), o si la opción "force" está establecida en "true". Emitido por write()
Error: Carpeta $name no eliminada: no se puede escribir.
La carpeta debe abrirse con acceso de escritura a través de new(access), de lo contrario, se rechazará su eliminación. Por lo tanto, puede tener acceso de escritura según el sistema operativo, pero eso no significa automáticamente que este método "delete" se lo permita. La observación inversa también es válida. Emitido por delete()
Error: Intervalo de tiempo no válido '$timespan' especificado.
La cadena no sigue las reglas estrictas de la sintaxis del intervalo de tiempo que se permite como parámetro. Emitido por timespan2seconds()
Advertencia: El id de mensaje '$msgid' no contiene un dominio.
Según las RFC, los id de mensaje deben contener una parte aleatoria única, luego un "@" y luego un nombre de dominio. Esto se hace para evitar la creación de dos mensajes con el mismo id. La advertencia surge cuando falta el "@" en la cadena. Emitido por messageId()
Error: El paquete $package no implementa $method.
Error fatal: el paquete específico (o una de sus superclases) no implementa este método donde debería. Este mensaje significa que otras clases relacionadas implementan este método, pero la clase en cuestión no lo hace. Probablemente debería investigar esto y, posiblemente, informar al autor del paquete. Emitido por notImplemented()
Error: No se puede crear la subcarpeta $name de $folder.
La copia incluye las subcarpetas, pero por alguna razón no fue posible copiar una de ellas. La copia continuará para todas las demás subcarpetas. Emitido por copyTo()
Error: No se puede escribir el mensaje para $folder a $filename: $!
No se pudo escribir el nuevo mensaje en su nuevo archivo, por la razón específica. Emitido por appendMessages()
Error: Falló la escritura de la carpeta $name
Por alguna razón (probablemente recibió más mensajes de error sobre este problema) es imposible escribir la carpeta, aunque debería hacerlo porque se realizaron cambios. Emitido por write()

Mail::Box::MH(3pm) - Perl programmmación manual

NOMBRE

Mail::Box::MH - interfaz para el sistema de correo MH

SINÓPSIS

 use Mail::Box::MH;

 # Crear un objeto de buzón para el sistema MH
 my $box = Mail::Box::MH->new(
     folder => '/ruta/a/tu/buzon',
     create => 1,
 );

 # Leer el contenido de un mensaje
 my $msg = $box->get(1);
 my $content = $msg->get;

 # Añadir un mensaje
 $box->add(new Mail::Message);

 # Eliminar un mensaje
 $box->delete(1);

 # Cerrar el buzón
 $box->close;

DESCRIPCIÓN

El módulo Mail::Box::MH implementa una interfaz para interactuar con los buzones de correo del sistema MH (Mail Handling).

DESCRIPCIÓN FUNCIONAL

Este módulo proporciona una forma de leer, escribir, añadir y eliminar mensajes de correo dentro de un buzón en formato MH.

Se pueden especificar opciones al crear un nuevo buzón, como la ruta al directorio del buzón y si se debe crear si no existe.

Las operaciones comunes de buzón como obtener, añadir y eliminar mensajes están disponibles a través de los métodos del objeto buzón.

DEPENDENCIAS

Este módulo depende de:

  • Mail::Box
  • Mail::Message

EXPORTA

Este módulo no exporta ninguna función o variable por defecto.

DIAGNÓSTICOS

Los errores se reportarán utilizando el mecanismo estándar de Perl (die). Los mensajes de error indicarán la naturaleza del problema, por ejemplo, si un directorio de buzón no existe o si se produce un error al escribir en el sistema de archivos.
