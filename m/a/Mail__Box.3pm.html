NOMBRE

Mail::Box - gestionar un buzón, una carpeta con mensajes

HERENCIA

Mail::Box
  es un Mail::Reporter
Mail::Box es extendido por
  Mail::Box::Dir
  Mail::Box::File
  Mail::Box::Net

SINOSIS

use Mail::Box::Manager;
my $mgr    = Mail::Box::Manager->new;
my $folder = $mgr->open(folder => $ENV{MAIL}, ...);
print $folder->name;
# Obtener el primer mensaje.
print $folder->message(0);
# Eliminar el tercer mensaje
$folder->message(3)->delete;
# Obtener el número de mensajes en contexto escalar.
my $emails = $folder->messages;
# Iterar sobre los mensajes.
foreach ($folder->messages) {...} # todos los mensajes
foreach (@$folder) {...}          # todos los mensajes
$folder->addMessage(Mail::Box::Message->new(...));

Interfaz enlazada (Tied-interface):

tie my(@inbox), 'Mail::Box::Tie::ARRAY', $inbox;
# Cuatro veces lo mismo:
$inbox[3]->print;                 # enlazado
$folder->[3]->print;              # carpeta sobrecargada
$folder->message(3)->print;       # usual
print $folder->[3];               # mensaje sobrecargado
tie my(%inbox), 'Mail::Box::Tie::HASH', $inbox;
# Dos veces lo mismo
$inbox{$msgid}->print;            # enlazado
$folder->messageId($msgid)->print;# usual

DESCRIPCIÓN

Un Mail::Box::Manager crea objetos "Mail::Box". Pero eso ya lo sabías, porque empezaste con la página del manual Mail::Box-Overview. Esa página es de lectura **obligatoria**, ¡lo siento!

Esta es una versión de mantenimiento para la interfaz antigua. Lee https://github.com/markov2/perl5-Mail-Box/wiki/ cómo moverte hacia la versión 4.

"Mail::Box" es la clase base para acceder a varios tipos de buzones (carpetas) de manera uniforme. Los varios tipos de carpetas difieren en cómo almacenan sus mensajes, pero con algo de esfuerzo esas diferencias podrían ocultarse tras una API general. Por ejemplo, algunas carpetas almacenan muchos mensajes en un solo archivo, mientras que otras almacenan cada mensaje en un archivo separado dentro del mismo directorio.

Ningún objeto en tu programa será de tipo "Mail::Box": solo se utiliza como clase base para los tipos de carpetas reales. Ve Mail::Box::Mbox, Mail::Box::MH, Mail::Box::IMAP4, etc.

Extiende "DESCRIPCIÓN" en Mail::Reporter.

SOBRECARGADO

sobrecarga: "" conversion a cadena
Los objetos de carpeta se convierten a su nombre como cadena. Esto simplifica especialmente las sentencias de impresión y la ordenación.

» ejemplo: usar carpeta sobrecargada como cadena

# Tres líneas con sobrecarga: cmp, @{}, y "" respectivamente
foreach my $folder (sort @folders)
{   my $msgcount = @$folder;
    print "$folder contiene $msgcount mensajes\n";
}
sobrecarga: @{} uso como ARRAY
Cuando la carpeta se usa como si fuera una referencia a un array, mostrará los mensajes, como lo harían messages() y message().

» ejemplo: usar carpeta sobrecargada como array

my $msg = $folder->[3];
my $msg = $folder->message(3);          # lo mismo
foreach my $msg (@$folder) ...
foreach my $msg ($folder->messages) ... # lo mismo
sobrecarga: cmp comparación de cadenas
Las carpetas se comparan basándose en su nombre. Las reglas de ordenación son las del "cmp" incorporado.

access => $modo
Derechos de acceso a la carpeta. Las carpetas se abren solo para lectura (¡lo que significa protegidas contra escritura!) por defecto. El $modo puede ser
'r': solo lectura (por defecto)
'a': añadir
'rw': lectura-escritura
'd': eliminar

Estos MODOS no tienen relación con los modos que se usan realmente para abrir los archivos de la carpeta dentro de este módulo. Por ejemplo, si especificas "rw" y abres la carpeta, solo se requiere permiso de lectura sobre el archivo de la carpeta.

Advertencia: escribir en una carpeta MBOX puede crear un nuevo archivo para reemplazar la carpeta antigua. Los permisos y el propietario del archivo pueden ser modificados por esto.

body_delayed_type => CLASE
Los cuerpos que se retardan: que se leerán del archivo cuando sea necesario, pero no antes.
body_type => CLASE|CODIGO
Cuando se leen mensajes de un archivo de carpeta, las cabeceras se almacenarán en un objeto "head_type". Para el cuerpo, sin embargo, hay un rango de opciones sobre el tipo, todas las cuales se describen en Mail::Message::Body.

Especifica una referencia a un CÓDIGO que produzca el tipo de cuerpo a crear, o una CLASE del cuerpo que se use cuando el cuerpo no es multipart o anidado. En caso de una referencia a código, la estructura de cabecera se pasa como primer argumento a la rutina.

No devuelvas un tipo de cuerpo retardado (como "::Delayed"), porque eso lo determina la opción "extract" al abrir la carpeta. Incluso los mensajes retardados requerirán algún tipo de cuerpo real cuando eventualmente se analicen. Los multipart y mensajes anidados también están fuera de tu control.

Por ejemplo:

$mgr->open('InBox', body_type => \&which_body);
sub which_body($) {
    my $head = shift;
    my $size = $head->guessBodySize || 0;
    my $type = $size > 100000 ? 'File' : 'Lines';
    "Mail::Message::Body::$type";
}

El valor por defecto depende del tipo de carpeta de correo, aunque el valor por defecto general es Mail::Message::Body::Lines. Por favor, consulta las páginas de manual aplicables.

coerce_options => ARRAY
Mantener la información de configuración para los mensajes que se adaptan al tipo de carpeta especificado, comenzando con un tipo de carpeta diferente (o incluso sin carpeta).

Mail::Box->new()

Create a new Mail::Box object. The following options are supported:

access => STRING
What kind of access do you want to the folder? Possible values are:
"r"
Read-only. The folder must exist.
"w"
Write-only. The folder may be created.
"a"
Append-only. The folder may be created.
"rw"
Read and Write. The folder may be created.
"a+"
Append, Read and Write. The folder may be created.
The default is "r". Access is checked when the folder is opened. When you want to create a folder that does not exist, you must use at least "w".

When you use the folder as a reference to a message (e.g. when you receive a folder object by calling Mail::Folder::message()), the access is already set and cannot be changed.

allow_empty_paths => BOOLEAN
Does the folder allow empty path names for sub-folders? Default is no.
attachment_type => CLASS
The default type of objects which are to be created for message attachments.
box_type => CLASS
The actual implementation class for the folder. By default this is derived from the class name. For example, a Mail::Box::NNTP object will use Mail::Box::NNTP::Folder.
charset => STRING
Set the default charset for message bodies and headers. For example: "UTF-8" or "ISO-8859-1".
close_policy => STRING
Defines when to close the folder. Possible values:
"auto"
Close the folder automatically when it is no longer used (default).
"manual"
Close the folder manually using the close() method.
create => BOOLEAN
Automatically create the folder when it does not exist yet. This will only work when access is granted for writing or appending to the folder.

Be careful: you may create a different folder type than you expect unless you explicitly specify Mail::Box::Manager::open(type).

extract => INTEGER | CODE | METHOD | 'LAZY'| 'ALWAYS'
Defines when to parse (process) the content of the message. When the header of a message is read, you may want to postpone the reading of the body: header information is more often needed than the body data, so why parse it always together? The cost of delaying is not too high, and with some luck you may never need parsing the body.

If you supply an INTEGER to this option, bodies of those messages with a total size less than that number will be extracted from the folder only when necessary. Messages where the size (in the "Content-Length" field) is not included in the header, like often the case for multiparts and nested messages, will not be extracted by default.

If you supply a CODE reference, that subroutine is called every time that the extraction mechanism wants to determine whether to parse the body or not. The subroutine is called with the following arguments:

CODE->(FOLDER, HEAD)

where FOLDER is a reference to the folder we are reading. HEAD refers to the Mail::Message::Head::Complete head of the message at hand. The routine must return a "true" value (extract now) or a "false" value (be lazy, do not parse yet). Think about using the Mail::Message::Head::guessBodySize() and Mail::Message::guessTimestamp() on the header to determine your choice.

The third possibility is to specify the NAME of a method. In that case, for each message is called:

FOLDER->NAME(HEAD)

Where each component has the same meaning as described above.

The fourth way to use this option involves constants: with "LAZY" all messages will be delayed. With "ALWAYS" you enforce unconditional parsing, no delaying will take place. The latter is usuful when you are sure you always need all the messages in the folder.

$folder->new(extract => 'LAZY');  # Very lazy
$folder->new(extract => 10000);   # Less than 10kB
# same, but implemented yourself
$folder->new(extract => &large);
sub large($) {
   my ($f, $head) = @_;
   my $size = $head->guessBodySize;
   defined $size ? $size < 10000 : 1
};
# method call by name, useful for Mail::Box
# extensions. The example selects all messages
# sent by you to be loaded without delay.
# Other messages will be delayed.
$folder->new(extract => 'sent_by_me');
sub Mail::Box::send_by_me($) {
    my ($self, $header) = @_;
    $header->get('from') =~ m/\bmy\@example.com\b/i;
}
field_type => CLASS
The type of the fields to be used in a header. Must extend Mail::Message::Field.
fix_headers => BOOLEAN
Broken MIME headers usually stop the parser: all lines not parsed are added to the body of the message. With this flag set, the erroneous line is added to the previous header field and parsing is continued. See Mail::Box::Parser::Perl::new(fix_header_errors).
folder => FOLDERNAME
Which folder to open (for reading or writing). When used for reading (the "access" option set to "r" or "a") the mailbox should already exist and must be readable. The file or directory of the mailbox need not exist if it is opened for reading and writing ("rw"). Write-permission is checked when opening an existing mailbox.

The folder name can be preceded by a "=", to indicate that it is named relative to the directory specified in new(folderdir). Otherwise, it is taken as relative or absolute path.

folderdir => $directory
Where are folders to be found by default? A folder-name may be preceded by a equals-sign ("=", a "mutt" convension) to explicitly state that the folder is located below the default directory. For example: in case "folderdir => '/tmp'" and "folder => '=abc'", the name of the folder-file is '/tmp/abc'. Each folder type has already some default set.
head_delayed_type => CLASS
The headers which are delayed: which will be read from file when it is needed, but not before.
head_type => CLASS
The type of header which contains all header information. Must extend Mail::Message::Head::Complete.
keep_dups => BOOLEAN
Indicates whether or not duplicate messages within the folder should be retained. A message is considered to be a duplicate if its message-id is the same as a previously parsed message within the same folder. If this option is "false" (the default) such messages are automatically deleted, because it is considered useless to store the same message twice.
lock_file => $file
The name of the $file which is used to lock. This must be specified when locking is to be used.
lock_timeout => $seconds
When the lock file is older than the specified number of $seconds, it is considered a mistake. The original lock is released, and accepted for this folder.
lock_type => CLASS|STRING|ARRAY
The type of the locker object. This may be the full name of a CLASS which extends Mail::Box::Locker, or one of the known locker types "DotLock", "Flock", "FcntlLock", "Mutt", "NFS", "POSIX", or "NONE". If an ARRAY is specified, then a Multi locker is built which uses the specified list.
lock_wait => $seconds
How many $seconds to wait before failing on opening this folder.
locker => OBJECT
An OBJECT which extends Mail::Box::Locker, and will handle folder locking replacing the default lock behavior.
log => LEVEL
manager => $manager
A reference to the object which manages this folder -- typically an Mail::Box::Manager instance.
message_type => CLASS
What kind of message objects are stored in this type of folder. The default is constructed from the folder class followed by "::Message". For instance, the message type for "Mail::Box::POP3" is "Mail::Box::POP3::Message"
multipart_type => CLASS
The default type of objects which are to be created for multipart message bodies.
remove_when_empty => BOOLEAN
Determines whether to remove the folder file or directory automatically when the write would result in a folder without messages nor sub-folders.
save_on_exit => BOOLEAN
Sets the policy for saving the folder when it is closed. A folder can be closed manually (see close()) or in a number of implicit ways, including on the moment the program is terminated.
trace => LEVEL
trusted => BOOLEAN
Flags whether to trust the data in the folder or not. Folders which reside in your "folderdir" will be trusted by default (even when the names if not specified staring with "="). Folders which are outside the folderdir or read from STDIN (Mail::Message::Construct::read()) are not trused by default, and require some extra checking.

If you do not check encodings of received messages, you may print binary data to the screen, which is a security risk.

La carpeta

$obj->addMessage($message, %options)
Añade un mensaje a la carpeta. Un mensaje suele ser un objeto Mail::Box::Message o una subclase del mismo. El mensaje no debe estar en otra carpeta cuando utilices este método. En caso de que lo esté, utiliza Mail::Box::Manager::moveMessage() o Mail::Box::Manager::copyMessage() a través del gestor.

Los mensajes con ID que ya existen en esta carpeta no se añaden.

TEN CUIDADO, las etiquetas de los mensajes pueden perderse al mover un mensaje de un tipo de carpeta a otro. Se intenta traducir las etiquetas, pero hay muchas diferencias en la interpretación por parte de las aplicaciones.

-Opción--Por defecto
 share   <no utilizado>
share => BOOLEANO
Intenta compartir el recurso físico del mensaje actual con el mensaje indicado. A veces es posible compartir mensajes entre diferentes tipos de carpetas. Cuando compartir no es posible, esta opción simplemente se ignora.

Compartir el recurso es bastante peligroso y solo está disponible para un número limitado de tipos de carpetas, por el momento solo algunas carpetas Mail::Box::Dir; estos mensajes basados en archivos pueden ser enlazados (en plataformas que lo soporten). El enlace puede romperse cuando un mensaje se modifica en una de las carpetas... pero quizás no, dependiendo de los tipos de carpetas involucrados.

» ejemplo:

$folder->addMessage($msg);
$folder->addMessages($msg1, $msg2, ...);
$obj->addMessages(@messages)
Añade un conjunto de objetos de mensaje a la carpeta abierta a la vez. Para algunos tipos de carpetas, esto puede ser más rápido que añadirlos uno a uno.

» ejemplo:

$folder->addMessages($msg1, $msg2, ...);
$class->appendMessages(%options)
Añade uno o más mensajes a una carpeta sin abrir. Normalmente, este método es llamado por Mail::Box::Manager::appendMessage(), en cuyo caso se comprueba la corrección del tipo de carpeta.

Para algunos tipos de carpetas es necesario abrir la carpeta antes de que pueda ser utilizada para añadir. Esto puede ser rápido, pero también muy lento (depende de la implementación). Todas las %options pasadas también se utilizarán para abrir la carpeta, si es necesario.

-Opción  --Por defecto
 folder    <requerido>
 message   undef
 messages  undef
 share     <C<falso>>
folder => NOMBRE_CARPETA
El nombre de la carpeta a la que se van a añadir los mensajes. La implementación de la carpeta evitará abrirla cuando sea posible, ya que consume recursos.
message => MENSAJE
messages => ARRAY-DE-MENSAJES
Una referencia a un MENSAJE o una referencia a un ARRAY de MENSAJES, que pueden ser de cualquier tipo. Los mensajes se convertirán primero al tipo de mensaje correcto para que encajen en la carpeta y luego se añadirán a ella.
share => BOOLEANO
Intenta compartir el almacenamiento físico del mensaje. Solo disponible para un número limitado de tipos de carpetas, de lo contrario no hace nada.

» ejemplo:

my $message = Mail::Message->new(...);
Mail::Box::Mbox->appendMessages(
  folder    => '=xyz',
  message   => $message,

 );

mejor:

$obj->close(%options)
Cierra la carpeta, lo que normalmente implica escribir los cambios. Devolverá "falso" si se requiere escritura pero falla. Por favor, comprueba este resultado.

ADVERTENCIA: Al mover mensajes de una carpeta a otra, asegúrate de escribir la carpeta de destino antes de escribir y cerrar la carpeta de origen. De lo contrario, puedes perder datos si el sistema falla o si hay problemas de software.

-Opción      --Por defecto
 force         falso
 save_deleted  falso
 write         'MODIFIED'
force => BOOLEANO
Anula la configuración de new(access) que se especificó al abrir la carpeta. Esta opción solo tiene efecto si su valor es VERDADERO. NOTA: La escritura en la carpeta puede no estar permitida por el sistema operativo, en cuyo caso incluso "force" no ayudará.
save_deleted => BOOLEANO
También escribe los mensajes que se marcaron para ser eliminados en su carpeta. La marca de eliminación se conserva (cuando es posible), lo que significa que al volver a abrir la carpeta se pueden eliminar los mensajes de forma permanente. Ver write(save_deleted).
write => 'ALWAYS'|'NEVER'|'MODIFIED'
Especifica si la carpeta debe ser escrita. Como se puede esperar, "ALWAYS" significa siempre (incluso si no hay cambios), "NEVER" significa que los cambios en la carpeta se perderán, y "MODIFIED" solo guarda la carpeta si hay algún cambio.

» ejemplo:

my $f = $mgr->open('spam', access => 'rw')
    or die "No se pudo abrir spam: $!\n";
$f->message(0)->delete
    if $f->messages;
$f->close
    or die "No se pudo escribir $f: $!\n";
$obj->copyTo($folder, %options)
Copia los mensajes de la carpeta a una nueva carpeta. La nueva carpeta puede ser de un tipo diferente. 
-Opción       --Por defecto
 delete_copied  <C<falso>>
 select         'ACTIVE'
 share          <no utilizado>
 subfolders     <dependiente del tipo de carpeta>
delete_copied => BOOLEANO
Marca los mensajes de la carpeta de origen para ser eliminados justo después de ser copiados. La eliminación solo tendrá efecto cuando se cierre la carpeta de origen.
select => 'ACTIVE'|'DELETED'|'ALL'|ETIQUETA|!ETIQUETA|FILTRO
Qué mensajes deben copiarse. Ver la descripción de messages() sobre cómo funciona esto.
share => BOOLEANO
Intenta compartir el mensaje entre las carpetas. Algunos tipos de carpetas Mail::Box::Dir lo soportan creando un enlace duro (en UNIX/Linux).
subfolders => BOOLEANO|'FLATTEN'|'RECURSE'
Cómo manejar las subcarpetas. Cuando es "falso" (0 o "undef"), las subcarpetas simplemente se ignoran. Con "FLATTEN", los mensajes de las subcarpetas se incluyen en la copia principal. "RECURSE" copia recursivamente también las subcarpetas. Por defecto, cuando la carpeta de destino soporta subcarpetas, se usa "RECURSE", de lo contrario "FLATTEN". Un valor de "true" seleccionará el valor por defecto.

» ejemplo:

my $mgr  = Mail::Box::Manager->new;
my $imap = $mgr->open(type => 'imap', host => ...);
my $mh   = $mgr->open(type => 'mh', folder => '/tmp/mh',
    create => 1, access => 'w');
$imap->copyTo($mh, delete_copied => 1);
$mh->close; $imap->close;
$obj->delete(%options)
Elimina el archivo de carpeta o directorio de carpeta especificado (dependiendo del tipo de carpeta) del disco. Por supuesto, ESTO ES PELIGROSO: "puede" perder datos. Devuelve un valor "true" en caso de éxito.

ADVERTENCIA: Al mover mensajes de una carpeta a otra, asegúrate de escribir la carpeta de destino antes de eliminar la carpeta de origen. De lo contrario, puedes perder datos si el sistema falla o si hay problemas de software.

-Opción   --Por defecto
 recursive  1
recursive => BOOLEANO

» ejemplo: eliminar una carpeta abierta

my $folder = Mail::Box::Mbox->new(folder => 'InBox', access => 'rw');
... otro código ...
$folder->delete;

» ejemplo: eliminar una carpeta cerrada

my $folder = Mail::Box::Mbox->new(folder => 'INBOX', access => 'd');
$folder->delete;
$obj->organization()
Devuelve cómo está organizada la carpeta: como un solo "FILE" con muchos mensajes, un "DIRECTORY" con un mensaje por archivo, o por un servidor "REMOTE".
$obj->size()
Devuelve el tamaño de la carpeta en bytes, sin contar los mensajes eliminados. El error en el resultado presentado puede ser de hasta un 10%, porque la representación en memoria de los mensajes no siempre es la misma que el tamaño cuando se escriben.
$obj->update(%options)
Lee nuevos mensajes de la carpeta, que se recibieron después de abrirla. Esto es bastante peligroso y no debería ser posible: las carpetas que están abiertas están bloqueadas. Sin embargo, algunas aplicaciones no utilizan bloqueos o el tipo incorrecto de bloqueos. Este método lee los cambios (no siempre a prueba de fallos) e los incorpora a la administración de la carpeta abierta.

Las %options son valores adicionales que se pasan al método updateMessages() que realiza el trabajo real aquí.

$obj->url()
Representa la carpeta como una cadena URL (Localizador Universal de Recursos). Puedes pasar dicha URL como nombre de carpeta a Mail::Box::Manager::open().

» ejemplo:

print $folder->url;
# puede resultar en
#   mbox:/var/mail/markov   o
#   pop3://user:password@pop.aol.com:101

Marcas de carpeta

Los mensajes

$obj->current( [$number|$message|$message_id] )
Algunos lectores de correo electrónico mantienen un mensaje actual, que representa el mensaje utilizado más recientemente. Este método devuelve [después de haber establecido] el mensaje actual. Puedes especificar un $number para seleccionar ese número de mensaje como actual, o un $message/$message_id (a menos que la cabecera ya esté cargada, en cuyo caso no será reconocida).
$obj->find($message_id)
Similar a messageId(), este método busca un mensaje con el $message_id, devolviendo el objeto de mensaje correspondiente. Sin embargo, "find" provocará que se procese un mensaje no procesado en la carpeta hasta que se encuentre el message-id. La carpeta se revisará de atrás hacia adelante.
$obj->findFirstLabeled( $label, [BOOLEAN, [$msgs]] )
Busca el primer mensaje con esa $label con la configuración correcta. El "BOOLEAN" indica si se busca cualquier valor "true" o cualquier valor "false" en el ARRAY de $msgs. Por defecto, se busca un valor "true". Cuando un mensaje no tiene la etiqueta solicitada, se considera "false".
$obj->message( $index, [$message] )
Obtiene o establece un mensaje con un índice determinado. Los mensajes marcados para eliminación se cuentan. Los índices negativos empiezan desde el final de la carpeta.
$obj->messageId( $message_id, [$message] )
Con un argumento, devuelve el mensaje en la carpeta con el $message_id. Si se pasa un objeto de mensaje como segundo argumento (opcional), el mensaje se almacenará primero en la carpeta, reemplazando cualquier mensaje con el mismo $message_id. (El $message_id del mensaje $message no necesita coincidir con $message_id).

!!AVISO!!: Cuando los encabezados de los mensajes se procesan de forma diferida, el mensaje podría estar en la carpeta pero aún no procesado en memoria. $obj->scanForMessages($message, $message_ids, $timespan, $window)
Empiezas con un $message y buscas una serie de mensajes relacionados con él. Por ejemplo, mensajes que aparezcan en los campos de encabezado 'In-Reply-To' y 'Reference' de ese mensaje. Estos mensajes se conocen por sus $message_ids y quieres encontrarlos en la carpeta.

Cuando todos los identificadores de mensaje son conocidos, la búsqueda es simple: se encuentran en un hash plano usando messageId(). Pero Mail::Box es perezoso cuando puede serlo, por lo que muchos mensajes pueden no haber sido leídos todavía desde el archivo y esa es la situación preferida, ya que ahorra tiempo y memoria.

No es inteligente buscar los mensajes de delante a atrás en la carpeta: hay una mayor probabilidad de que el mensaje relacionado esté cerca. Por lo tanto, este método empieza a revisar la carpeta desde el $message especificado, hacia el frente de la carpeta.

El $timespan se puede usar para terminar la búsqueda basándose en el tiempo del mensaje. Cuando se use la constante "EVER" como $timespan, la búsqueda no estará limitada por eso. Cuando se especifique un número entero, se usará como tiempo absoluto en ticks de tiempo según la función "time" de tu sistema. En otros casos, se pasa a timespan2seconds() para determinar el umbral de tiempo relativo al tiempo del mensaje.

El $window se usa para limitar el número de mensajes a revisar como un entero o la cadena constante "ALL".

Los identificadores de mensaje que no se encontraron durante la búsqueda se devuelven. Se advierte de que un identificador de mensaje podría ser ya conocido y por eso no se encuentra: verifica primero.

DETAILS

Different kinds of folders

In general, there are three classes of folders: those who group messages per file, those who group messages in a directory, and those do not provide direct access to the message data. These folder types are each based on a different base class.

  • File based folders Mail::Box::File

    File based folders maintain a folder (a set of messages) in one single file. The advantage is that your folder has only one single file to access, which speeds-up things when all messages must be accessed at once.

    One of the main disadvantages over directory based folders is that you have to construct some means to keep all message apart. For instance MBOX adds a message separator line between the messages in the file, and this line can cause confusion with the message's contents.

    Where access to all messages at once is faster in file based folders, access to a single message is (much) slower, because the whole folder must be read. However, in directory based folders you have to figure-out which message you need, which may be a hassle as well.

    Examples of file based folders are MBOX, DBX, and NetScape.

  • Directory based folders Mail::Box::Dir

    In stead of collecting multiple messages in one file, you can also put each message in a separate file and collect those files in a directory to represent a folder.

    The main disadvantages of these folders are the enormous amount of tiny files you usually get in your file-system. It is extremely slow to search through your whole folder, because many files have to be opened to do so.

    The best feature of this organization is that each message is kept exactly as it was received, and can be processed with external scripts as well: you do not need any mail user agent (MUA).

    Examples of directory organized folders are MH, Maildir, EMH and XMH.

  • Network (external) folders Mail::Box::Net

    Where both types described before provide direct access to the message data, maintain these folder types the message data for you: you have to request for messages or parts of them. These folders do not have a filename, file-system privileges and system locking to worry about, but typically require a hostname, folder and message IDs, and authorization.

    Examples of these folder types are the popular POP and IMAP, and database oriented message storage.

Available folder types

  • Mail::Box::Dbx (read only)

    Dbx files are created by Outlook Express. Using the external (optional) Mail::Transport::Dbx module, you can read these folders, even when you are running MailBox on a UNIX/Linux platform.

    Writing and deleting messages is not supported by the library, and therefore not by MailBox. Read access is enough to do folder conversions, for instance.

  • Mail::Box::IMAP4 (partially)

    The IMAP protocol is very complex. Some parts are implemented to create (sub-optimal but usable) IMAP clients. Besides, there are also some parts for IMAP servers present. The most important lacking feature is support for encrypted connections.

  • Mail::Box::Maildir

    Maildir folders have a directory for each folder. A folder directory contains "tmp", "new", and "cur" sub-directories, each containing messages with a different purpose. Files with new messages are created in "tmp", then moved to "new" (ready to be accepted). Later, they are moved to the "cur" directory (accepted). Each message is one file with a name starting with timestamp. The name also contains flags about the status of the message.

    Maildir folders can not be used on Windows by reason of file-name limitations on that platform.

  • Mail::Box::Mbox

    A folder type in which all related messages are stored in one file. This is a very common folder type for UNIX.

  • Mail::Box::MH

    This folder creates a directory for each folder, and a message is one file inside that directory. The message files are numbered sequentially on order of arrival. A special ".mh_sequences" file maintains flags about the messages.

  • Mail::Box::POP3 (read/delete only)

    POP3 is a protocol which can be used to retrieve messages from a remote system. After the connection to a POP server is made, the messages can be looked at and removed as if they are on the local system.

  • Mail::Box::Netzwert

    The Netzwert folder type is optimized for mailbox handling on a cluster of systems with a shared NFS storage. The code is not released under GPL (yet)

Other folder types are on the (long) wishlist to get implemented. Please, help implementing more of them.

NAME

Mail::Box - Base class for mail folder access

INHERITANCE

Mail::Box is a base class. It is inherited by Mail::Box::Folder, Mail::Box::IMAP, Mail::Box::Local, and Mail::Box::NNTP.

SYNOPSIS

 use Mail::Box;
 my $box = Mail::Box->new()
      or die "Cannot create mailbox: $@";

 # List available folders
 my @folders = $box->list;

 # Open a specific folder
 my $folder = $box->open(folder => 'INBOX')
      or die "Cannot open INBOX: $@";

 # Access messages
 my $msgcount = $folder->messages;
 for my $i (1 .. $msgcount) {
     my $message = $folder->message($i);
     # ... process message ...
 }

 # Close the folder and update mailbox
 $folder->close;
 $box->close;

DESCRIPTION

This module provides the basic interface for accessing mailboxes. Mailboxes can be implemented in various ways, like local mbox files, Maildir directories, IMAP servers, or NNTP newsgroups. All implementations share this common interface.

The main tasks are:

  • Listing available mail folders.
  • Opening and closing folders.
  • Accessing messages within a folder.
  • Creating, deleting, and moving messages and folders.

OVERLOADED

The following methods are overloaded:

""
Stringifies the mailbox object. Returns the name of the default folder.
""
The boolean context test indicates whether the mailbox object is valid (i.e., connected).

METHODS

The following methods are available:

new(%args)
Constructor. Takes optional arguments to configure the mailbox access (e.g., host, port, username, password).
new(folder => $folder_name)
Opens the specified folder directly. Shorthand for new()->open(folder => $folder_name).
open(%args)
Opens a specific folder. Takes arguments like folder, readonly, etc.
close()
Closes the mailbox connection.
list()
Returns a list of available folder names.
folder()
Returns the currently open folder object, or undef if none is open.

Retrieves a specific message from the currently open folder.

append(%args)
Appends a new message to the mailbox.
delete(%args)
Deletes a message or a folder.
copyTo(%args)
Copies messages or folders to another location.
rename(%args)
Renames a folder.
create(%args)
Creates a new folder.
destroy()
Destroys the mailbox object and closes the connection.

DETAILS

The Mail::Box module acts as a dispatcher to the actual mailbox implementation. The constructor Mail::Box->new() inspects the arguments and selects the appropriate subclass (e.g., Mail::Box::Local for local files, Mail::Box::IMAP for IMAP servers).

The open() method can take a folder name. If the folder name contains special characters or needs specific interpretation, it should be passed as an argument. For example, open(folder => 'INBOX.Sent').

The messageId() method is used internally to parse message IDs. It expects the ID to be a string starting with '@'.

Error: Unable to create subfolder $name of $folder.
The copy includes the subfolders, but for some reason it was not possible to copy one of these. Copying will proceed for all other sub-folders. Cast by copyTo()
Error: Writing folder $name failed
For some reason (you probably got more error messages about this problem) it is impossible to write the folder, although you should because there were changes made. Cast by write()
