Mail::DKIM::AuthorDomainPolicy(3) Documentación de contribuciones de Perl Mail::DKIM::AuthorDomainPolicy(3)

NOMBRE

Mail::DKIM::AuthorDomainPolicy - representa un registro de políticas de firmado de dominio (ADSP)

VERSIÓN

versión 1.20240923

DESCRIPCIÓN

El registro de políticas de firmado de dominios (ADSP) puede publicarse por cualquier dominio para ayudar a un receptor a saber qué hacer cuando encuentre un mensaje no firmado que afirme ser de ese dominio.

El registro se publica como un registro TXT en _adsp._domainkey.DOMAIN donde DOMAIN es el dominio del correo electrónico "From" del mensaje.

Más detalles sobre este registro pueden encontrarse leyendo el propio esquema en http://tools.ietf.org/html/rfc5617.

CONSTRUCTORES

fetch()

Busca un registro de ADSP en DNS.

my $policy = Mail::DKIM::AuthorDomainPolicy->fetch(
          Protocol => 'dns',
          Author => 'jsmith@example.org',
        );

Si el registro de ADSP se encuentra y parece válido, se construirá un objeto que contenga la información de ese registro y se lo devolverá. Si el registro de ADSP está vacío o simplemente no existe, se devolverá un objeto que represente la política por defecto. (Ver también is_implied_default_policy()). Si ocurre un error DNS (por ejemplo, SERVFAIL o timeout), este método se detendrá.

new()

Crea un objeto de política por defecto.

my $policy = Mail::DKIM::AuthorDomainPolicy->new;

parse()

Construye un registro de ADSP a partir de una cadena.

my $policy = Mail::DKIM::AuthorDomainPolicy->parse(
        String => 'dkim=all',
        Domain => 'aaa.example',
    );

MÉTODOS

apply()

Aplica la política a los resultados de un verificador de DKIM.

my $result = $policy->apply($dkim_verifier);

El llamador debe proporcionar una instancia de Mail::DKIM::Verifier, una cual ya ha sido alimentada con el mensaje a verificar.

Los resultados posibles son:

aceptar
El mensaje se aprueba por la política de firmado del emisor.
rechazar
El mensaje se rechaza por la política de firmado del emisor. Puede considerarse muy sospechosa.
neutral
El mensaje no es aceptado ni rechazado por la política de firmado del emisor. Puede considerarse sospechosa.

Nota: en el futuro, estos valores pueden convertirse:

none
No se publica ningún registro de ADSP.
pass
Una firma pasando está presente.
fail
El registro de ADSP es "all" y no se encuentra una firma pasando.
discard
El registro de ADSP es "discardable" y no se encuentra una firma pasando.
nxdomain
El dominio no existe en DNS.
temperror
Error temporal ocurrió.
permerror
Error no temporal ocurrió.

is_implied_default_policy()

Determine si esta política implica la política por defecto.

my $is_implied = $policy->is_implied_default_policy;

Si usted fetch la política para un dominio específico, pero ese dominio no tiene una política publicada, entonces la política por defecto está en vigor. Use este método para detectar cuando ocurre esto.

location()

Dice dónde la política fue obtenida.

Si la política es dominio-wide, este será el dominio donde la política fue publicada.

Si la política es específica del usuario, TBD.

Si no hay ninguna política publicada para el dominio y la política por defecto fue devuelta, el location será "undef".

policy()

Obtiene o establece la política de firmado de salida (dkim=) del ente.

my $sp = $policy->policy;

La política de firma de salida para el ente. Valores posibles son:

"unknown"
El valor por defecto. El ente puede firmar algunos o todos los correos.
"all"
Todo el correo de este dominio se espera que esté firmado, usando una firma de autor válida, pero el autor no sugiere descartar el correo sin una firma válida.
"discardable"
Todo el correo de este dominio se espera que esté firmado, usando una firma de autor válida, y el autor es tan confiado que el servidor de correo del receptor pueda descartar automáticamente el correo sin firma.
"NXDOMAIN"
El dominio está fuera del alcance, es decir, el dominio no existe en DNS.

signall()

True si la política es "all".

signall_discardable()

True si la política es "strict".

BUGS

•
Sección 4.3 del esquema dice que debe hacer una consulta en el propio dominio para ver si existe. Esta clase no lo está haciendo, es decir, podría reportar NXDOMAIN porque _adsp._domainkey.example.org no existe, pero no debe tratarse de manera similar que example.org no exista.

r.domain-policy.5

r.domain-policy — Política de dominio para las operaciones de subversión.

r.domain-policy (5) es un archivo de configuración de texto plano que se utiliza para especificar las reglas que rsync utilizará para decidir si debe o no acceder a un dominio o recurso compartido particular.

El archivo consta de una o más directivas, cada una en su propia línea. Los comentarios se indican con el carácter '#'.

DIRECTIVAS

deny — Denegar el acceso a un dominio o recurso compartido específico.

allow — Permitir el acceso a un dominio o recurso compartido específico.

La sintaxis para las directivas deny y allow es la siguiente: 

deny|allow <dominio>[/<recurso_compartido>]

Donde:

  • <dominio> es el nombre de dominio o la dirección IP del servidor de destino.
  • <recurso_compartido> es el nombre del recurso compartido en el servidor de destino. Si se omite, la directiva se aplica a todos los recursos compartidos en el dominio.

Las reglas se evalúan en orden. La primera regla que coincida con el dominio o recurso compartido de destino determinará si se permite o se deniega el acceso. Si ninguna regla coincide, el acceso se permite por defecto.

EJEMPLOS

Denegar el acceso a todos los recursos compartidos en ejemplo.com: 

deny ejemplo.com

Denegar el acceso al recurso compartido datos en 192.168.1.100: 

deny 192.168.1.100/datos

Permitir el acceso a todos los recursos compartidos en respaldos.ejemplo.org, a menos que se denieguen explícitamente en otra parte: 

allow respaldos.ejemplo.org

Denegar el acceso a un recurso compartido específico pero permitir todo lo demás: 

deny mi_servidor/secreto
allow *
