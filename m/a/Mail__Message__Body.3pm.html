NOMBRE

Mail::Message::Body - los datos del cuerpo de un mensaje

HERENCIA

DESCRIPCIÓN

La funcionalidad de codificación y decodificación de un Mail::Message::Body se implementa en el paquete Mail::Message::Body::Encode. Ese paquete se carga automáticamente cuando necesitan tener lugar la codificación y decodificación de mensajes. Los métodos para construir y procesar simplemente objetos de cuerpo se implementan en Mail::Message::Body::Construct.

El cuerpo de un mensaje (un objeto Mail::Message) se almacena en uno de los muchos tipos de cuerpo. La funcionalidad de cada tipo de cuerpo es equivalente, pero hay diferencias de rendimiento. Cada tipo de cuerpo tiene su propia documentación con detalles sobre su implementación.

Extiende "DESCRIPCIÓN" en Mail::Reporter.

SOBRECARGADO

sobrecarga: "" conversión a cadena
Devuelve el cuerpo como una cadena —lo que activará la finalización— a menos que se llame para producir una cadena para "Carp". Esto último para evitar recursiones profundas.

» ejemplo: conversión a cadena del cuerpo

print $msg->body;   # implícito por print
my $body = $msg->body;
my $x    = "$body"; # explícito por interpolación
sobrecarga: '==' comparación numérica
compara si dos referencias apuntan al mismo mensaje. Esto solo produce resultados correctos si ambos argumentos son referencias de mensaje dentro de la misma carpeta.

» ejemplo: uso de comparación numérica en un cuerpo

my $skip = $folder->message(3);
foreach my $msg (@$folder)
{   next if $msg == $skip;
    $msg->send;
}
sobrecarga: @{} dirigido como array
Cuando un objeto de cuerpo se utiliza como una referencia de array, se devuelven las líneas del cuerpo. Esto es lo mismo que usar lines().

» ejemplo: usar un cuerpo como array

print $body->lines->[1];  # segunda línea
print $body->[1];         # igual
my @lines = $body->lines;
my @lines = @$body;       # igual
sobrecarga: bool verdadero/falso
Siempre devuelve un valor "verdadero", lo cual es necesario para que los objetos sobrecargados se utilicen como en if($body). De lo contrario, se necesitaría "if(defined $body)" para evitar un error en tiempo de ejecución.

based_on => CUERPO
La información sobre las codificaciones debe tomarse del CUERPO especificado, a menos que se especifique lo contrario.
charset => CHARSET|'PERL'|<undef>
Define el juego de caracteres que se utiliza en los datos. Solo útil en combinación con un "mime_type" que hace referencia a "text" de alguna forma, que no contenga ya un charset explícito. Este campo no distingue mayúsculas y minúsculas.

Cuando se proporciona un CHARSET conocido y el mime_type dice "text", se espera que los datos sean octetos crudos en esa codificación particular (ver Encode). Cuando se proporciona 'PERL', los datos están en la codificación interna de Perl; ya sea cp1252 o utf8. Más detalles en "Codificación de caracteres PERL"

checked => BOOLEAN
Si la información añadida ha sido verificada para no contener octetos ilegales con respecto a la codificación de transferencia y el tipo mime. Si no se verifica, y luego se establece como cuerpo para un mensaje, se hará.
content_id => CADENA
En el contenido MIME "multipart/related", se requiere el "content_id" para permitir el acceso al contenido relacionado a través de un descriptor "cid:<...>" de una disposición inline.

Se supone que un "Content-ID" es globalmente único. Como tal, es común añadir "@computadora.dominio" al final de alguna cadena única. Como otro contenido en el contenedor "multipart/related" también necesita saber cuál es este "Content-ID", esto debe dejarse a la imaginación de la persona que crea el contenido (por ahora).

Como campo de encabezado MIME, se espera que la cadena "Content-ID" esté entre corchetes angulares.

data => ARRAY-DE-LÍNEAS | CADENA
El contenido del cuerpo. La única forma de establecer el contenido de un cuerpo es durante la creación del cuerpo. Por lo tanto, si desea modificar el contenido de un mensaje, necesita crear un nuevo cuerpo con el nuevo contenido y añadirlo al cuerpo. La razón detrás de esto es que las codificaciones correctas y la información del cuerpo deben ser garantizadas. Evita sus problemas al calcular el número de líneas en el cuerpo y verificar si los caracteres erróneos están encerrados en texto.

Especifique una referencia a un ARRAY de líneas, cada una terminada por un salto de línea. O una CADENA que puede contener múltiples líneas, separadas y terminadas por un salto de línea.

Información informal sobre el contenido del cuerpo. Los datos se relacionan con el campo "Content-Description". Especifique una CADENA que se convertirá en el contenido del campo, o un CAMPO real.

Options

content_id => STRING|FIELD
The id of the body part. See also contentId().

The content-id is a unique reference, used for example to link to inline objects in HTML e-mail.

charset => STRING
The character set for the data in the body. For example: "UTF-8" or "ISO-8859-1".

This value is used in the "Content-Type" header field. When adding a body part which is a text-based file (e.g. "text/plain" or "text/html"), it is important to specify the character set of the text.

content_description => STRING|FIELD
See description().
disposition => STRING|FIELD
The disposition type for the body part. See also disposition().

This corresponds to the "Content-Disposition" field. Specify a STRING which will become the field content, or a real FIELD.

The content of this field is specified in RFC 1806. The body of the field can be "inline", to indicate that the body is intended to be displayed automatically upon display of the message. Use "attachment" to indicate that they are separate from the main body of the mail message, and that their display should not be automatic, but contingent upon some further action of the user.

The "filename" attribute specifies a name to which is suggested to the reader of the message when it is extracted.

[3.017] RFC9078 adds type "reaction". This part content is restricted to a single line of emoji's. For this kind, you need to pass the FIELD here, as well as mime-type "text/plain".

eol => 'CR'|'LF'|'CRLF'|'NATIVE'
Convert the message into having the specified string as line terminator for all lines in the body. "NATIVE" is used to represent the "\n" on the current platform and will be translated in the applicable one.

BE WARNED that folders with a non-native encoding may appear on your platform, for instance in Windows folders handled from a UNIX system. The eol encoding has effect on the size of the body!

file => FILENAME|FILEHANDLE|IOHANDLE
Read the data from the specified file, file handle, or object of type "IO::Handle".
filename => FILENAME
[3.001] Overrule/set filename for content-disposition
language => STRING|ARRAY|LIST|FIELD
[3.017] RFC3282 "Content-Language" field, containing a comma separated list of language codes.
log => LEVEL
message => MESSAGE
The message where this body belongs to.
mime_type => STRING|FIELD|MIME
The type of data which is added. You may specify a content of a header line as STRING, or a FIELD object. You may also specify a MIME::Type object. In any case, it will be kept internally as a real field (a Mail::Message::Field object). This relates to the "Content-Type" header field.

A mime-type specification consists of two parts: a general class ("text", "image", "application", etc) and a specific sub-class. Examples for specific classes with "text" are "plain", "html", and "xml". This field is case-insensitive but case preserving. The default mime-type is "text/plain",

modified => BOOLEAN
Whether the body is flagged modified, directly from its creation.
trace => LEVEL
transfer_encoding => STRING|FIELD
The encoding that the data has. If the data is to be encoded, than you will have to call encode() after the body is created. That will return a new encoded body. This field is case-insensitive and relates to the "Content-Transfer-Encoding" field in the header.

» example:

my $body = Mail::Message::Body::String->new(file => \*IN,
   mime_type => 'text/html; charset="ISO-8859-1"');
my $body = Mail::Message::Body::Lines->new(data => ["first\n", $second],
   charset => 'ISO-10646', transfer_encoding => 'none');
my $body = Mail::Message::Body::Lines->new(data => \@lines,
   transfer_encoding => 'base64');
my $body = Mail::Message::Body::Lines->new(file => 'picture.gif',
   mime_type => 'image/gif', content_id => '<12345@example.com>',
   disposition => 'inline');

Acceso al contenido

$obj->endsOnNewline()
Devuelve si la última línea del cuerpo termina con un salto de línea (que se convierte en CRLF en el transporte). Un cuerpo vacío devolverá "true" ya que el salto de línea proviene de la línea anterior.
$obj->file()
Devuelve el contenido del cuerpo como un archivo de lectura. El flujo devuelto puede ser un archivo real o un archivo simulado en cualquier forma que Perl pueda soportar. Aunque no puedas escribir en el archivo de lectura, podrás leer de él.

ADVERTENCIA: Aunque el archivo de lectura soporta la escritura, no escribas en él. Si lo haces, es posible que algunas de las variables internas del objeto Mail::Message::Body no se actualicen.

$obj->lines()
Devuelve el contenido del cuerpo como una lista de líneas (en contexto LIST) o una referencia a un array de líneas (en contexto SCALAR). En contexto SCALAR, el array de líneas se almacena en caché para evitar copias innecesarias y proporcionar acceso rápido para mensajes grandes.

Para obtener solo el número de líneas en el cuerpo, usa el método nrLines(), que es generalmente más eficiente.

ADVERTENCIA: Para algunos tipos de cuerpos, la referencia apuntará al original. No cambies el contenido al que se apunta. Si lo haces, es posible que algunas de las variables internas esenciales del objeto Mail::Message::Body no se actualicen.

Ejemplo:

my @lines    = $body->lines;     # copia de líneas
my $line3    = ($body->lines)[3] # solo una copia
print $lines[0];
my $linesref = $body->lines;     # referencia a originales
my $line3    = $body->lines->[3] # solo una copia (más rápida)
print $linesref->[0];
print $body->[0];                # por sobrecarga
$obj->print( [$fh] )
Imprime el cuerpo en el archivo $fh (por defecto al manejador seleccionado). Se puede usar un objeto IO::File o cualquier objeto con un método print(). No se devuelve nada.
$obj->printEscapedFrom($fh)
Imprime el cuerpo en el archivo $fh pero todas las líneas que comienzan con 'From ' (opcionalmente precedidas por >) tendrán un > añadido delante. No se devuelve nada.
$obj->string()
Devuelve el contenido del cuerpo como una variable escalar (una única cadena). Esta es una copia de la información interna.

Ejemplo:

my $text = $body->string;
print "Cuerpo: $body\n";     # por sobrecarga
$obj->stripTrailingNewline()
Elimina el salto de línea de la última línea, o la última línea si no contiene más que un salto de línea.
$obj->write(%options)
Escribe el contenido del cuerpo a un archivo. ¡Se te recomienda desencriptar el cuerpo antes de escribirlo!

use File::Temp;
my $fn = tempfile;
$message->decoded->write(filename => $fn)

use File::Temp;
my $dir = tempdir; mkdir $dir or die;
my $fn  = $message->body->dispositionFilename($dir);
$message->decoded->write(filename => $fn)
   or die "No se pudo escribir a $fn: $!\n";

$obj->modified( [BOOLEAN] )
Cambia la bandera de modificación del cuerpo. Esto forzará la escritura del cuerpo a un archivo de buzón cuando se cierre. Es bastante peligroso cambiar el cuerpo: el mismo cuerpo puede ser compartido entre mensajes dentro de tu programa.

Mueve el registro del mensaje a una nueva ubicación a través de $distance. Esto se llama cuando el mensaje se escribe a una nueva versión del mismo archivo de buzón.
$obj->read( $parser, $head, $bodytype, [$chars, [$lines]] )
Lee el cuerpo con el $parser desde un archivo. La implementación de este método difiere entre los tipos de cuerpo. El $bodytype es un nombre de clase o una referencia a una rutina que puede producir un nombre de clase, y se usa en cuerpos multipart para determinar el tipo del cuerpo para cada parte.

El argumento $chars es el número estimado de bytes en el cuerpo, o "undef" si no se conoce. Esta información puede derivarse del encabezado ($Content-Length) o del tamaño del archivo.

El segundo argumento es el número estimado de líneas del cuerpo. Es menos útil que $chars pero puede ser útil para determinar si el separador de mensajes es confiable. Este valor se puede encontrar en el campo "Lines" del encabezado.

NOMBRE

Mail::Message::Body - manejo de mensajes de correo electrónico y MIME

HERENCIA

    Mail::Message::Body
        Mail::Message::Body::Byte
        Mail::Message::Body::File
        Mail::Message::Body::Message
        Mail::Message::Body::Text

SINOPSIS

  use Mail::Message::Body;

  # Crear un cuerpo vacío
  my $body = Mail::Message::Body->new;

  # Leer de un archivo
  my $body_file = Mail::Message::Body->new(file => '~/mail.txt');
  print $body_file->content;

  # Leer de una cadena
  my $body_text = Mail::Message::Body->new(text => "Hola\n");

  # Crear un cuerpo MIME
  my $body_mime = Mail::Message::Body->new(
      type    => 'multipart/mixed',
      parts   => [ $body_text, $body_file ],
  );

  # Escribir a un archivo
  $body_mime->write_to('/tmp/output.mail');

DESCRIPCION

El módulo Mail::Message::Body es la clase base para representar el cuerpo de un mensaje de correo electrónico. Proporciona una interfaz común para acceder y manipular el contenido del cuerpo, ya sea que se trate de texto plano, datos binarios o una estructura MIME compleja.

Las subclases manejan diferentes tipos de contenido:

  • Mail::Message::Body::Text: para cuerpos de texto plano.
  • Mail::Message::Body::Byte: para cuerpos binarios.
  • Mail::Message::Body::File: para cuerpos almacenados en archivos.
  • Mail::Message::Body::Message: para representar sub-mensajes MIME (por ejemplo, mensajes adjuntos).

La clase Mail::Message::Body en sí misma se utiliza principalmente para representar cuerpos compuestos, como multipart/mixed, multipart/alternative, etc.

MÉTODOS

new()
Crea una nueva instancia de Mail::Message::Body. Los argumentos aceptados incluyen:
  • file: la ruta a un archivo que contiene el cuerpo del mensaje.
  • text: una cadena que contiene el cuerpo del mensaje.
  • bytes: una cadena de bytes que contiene el cuerpo del mensaje.
  • content_type: el tipo de contenido MIME (por ejemplo, text/plain, multipart/mixed).
  • content_transfer_encoding: la codificación de transferencia de contenido (por ejemplo, quoted-printable, base64).
  • parts: una lista de cuerpos de mensaje hijos, utilizada para cuerpos multipart.
content()
Devuelve el contenido del cuerpo. Si el cuerpo es multipart, devuelve una lista de los cuerpos hijos.
content_type()
Devuelve el tipo de contenido MIME del cuerpo.
content_transfer_encoding()
Devuelve la codificación de transferencia de contenido del cuerpo.
decode()
Decodifica el contenido del cuerpo según su content_transfer_encoding.
encode()
Codifica el contenido del cuerpo según su content_transfer_encoding.
parts()
Devuelve una lista de los cuerpos de mensaje hijos. Solo aplicable a cuerpos multipart.
add_part()
Añade un cuerpo de mensaje hijo a un cuerpo multipart.
write_to()
Escribe el contenido del cuerpo a un archivo.

DETALLES

El manejo de la codificación de transferencia de contenido (como quoted-printable y base64) se realiza automáticamente cuando se accede o se escribe el contenido.

Para cuerpos compuestos (multipart), la estructura MIME se representa mediante la lista de parts.

DIAGNÓSTICOS

Los errores comunes incluyen problemas al leer o escribir archivos, tipos de contenido MIME no válidos o estructuras multipart mal formadas.
