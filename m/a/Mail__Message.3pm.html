Sintaxis

use Mail::Box::Manager;
my $mgr    = Mail::Box::Manager->new;
my $folder = $mgr->open(folder => 'InBox');
my $msg    = $folder->message(2);    # $msg es un Mail::Message ahora
my $subject = $msg->subject;         # Asunto del mensaje
my @cc      = $msg->cc;              # Lista de Mail::Address
my Mail::Message::Head $head = $msg->head;
my Mail::Message::Body $body = $msg->decoded;
$msg->decoded->print($outfile);
# Enviar un correo simple
Mail::Message->build(
  To             => 'you@example.com',
  From           => 'me@example.com',
  Subject        => 'Mi asunto',
  data           => 'Contenido de texto plano'
)->send(via => 'postfix');
my $reply_msg = Mail::Message->reply(...);
my $frwd_msg  = Mail::Message->forward(...);

Descripción

Un objeto "Mail::Message" contiene información de mensaje en formato MIME, según RFC2822. Todo lo que no está especificado en relación con la almacenamiento de mensajes en carpetas de correo (folders) se implementa en esta clase. Las métodos relacionados con las carpetas se implementan en la extensión Mail::Box::Message.

Esta es una versión de mantenimiento para la interfaz antigua. Lea https://github.com/markov2/perl5-Mail-Box/wiki/ sobre cómo moverse hacia la versión 4.

Los métodos principales son get(), para obtener información de un campo de encabezado de mensaje, y decoded(), para obtener el contenido intencional de un mensaje. Hay muchas más funciones que pueden ayudar a su programa.

La manipulación de mensajes complejas, como la construcción de respuestas y salidas, se implementa en paquetes separados que se autoadquieren en esta clase. Esto significa que puede usar estos métodos como si pertenecieran a esta clase. Estos paquetes agregan funcionalidad a objetos de mensaje de todos los tipos.

Constructor

Extiende "Constructor" en Mail::Reporter.

$obj->clone(%options)
Crea una copia de este mensaje. Se devuelve un objeto "Mail::Message". Los encabezados y el cuerpo, el log y el nivel de traza se toman. Las etiquetas se copian con el mensaje, pero los flags de borrado y modificados no son.

DE ALERTA: cualquier copia de un mensaje (o de un parte) será siempre un objeto "Mail::Message". Por ejemplo, el clone de un Mail::Box::Message está desvinculado de la carpeta original. Cuando se use Mail::Box::addMessage() con el mensaje copiado, el clone se convertirá automáticamente en el tipo correcto para ser agregado.

Ver también Mail::Box::Message::copyTo() y Mail::Box::Message::moveTo().

-Option      --Valor por defecto
 shallow       false
 shallow_body  false
 shallow_head  false
shallow => BOOLEAN
Al hacer una copia shallow, los encabezados y el cuerpo del mensaje no se clonan, pero se compartan. Esto puede ser peligroso: por ejemplo, en algunos tipos de carpeta, los campos de encabezado se usan para almacenar flags de carpeta. Si uno de ambos clones shallow cambia los flags, eso actualizará el encabezado y así se verá en ambos.

Hay situaciones donde una copia shallow puede usarse de forma segura. Por ejemplo, cuando se usa Mail::Box::Message::moveTo() y estás seguro de que el mensaje original no puede volverse inaccesible después del movimiento.

shallow_body => BOOLEAN
Un buen criterio, porque no se permite modificar el cuerpo de un mensaje: solo se puede establecer un nuevo cuerpo con body().
shallow_head => BOOLEAN
Solo el encabezado se reutiliza, no el cuerpo. Esto puede ser un mal criterio, ya que los campos de encabezado pueden ser actualizados, por ejemplo, cuando los etiquetas cambian.

El mensaje

$obj->container()
Si el mensaje es parte de otro mensaje, "container" devuelve la referencia al cuerpo que contiene.

» ejemplo:

my Mail::Message $msg = ...
unless $msg->body->isMultipart or return;
my $part   = $msg->body->part(2);
$part->body->isMultipart or return;
my $nested = $part->body->part(3);
$nested->container;  # devuelve $msg->body
$nested->toplevel;   # devuelve $msg
$msg->container;     # devuelve undef
$msg->toplevel;      # devuelve $msg
$msg->isPart;        # devuelve false
$part->isPart;       # devuelve true
$obj->endsOnNewline()
[3.018] Devuelve "true" cuando el mensaje impreso tiene un final con "\n". En algunos casos raros, no es así. Por ejemplo, cuando el cuerpo se lee de un archivo que no tenía nuevo salto al final.
$obj->isDummy()
Mensajes dummy se utilizan para llenar huecos en listas de enlaces, donde solo se conoce el mensaje-id, pero no la ubicación del cabecero del cuerpo.

Este método también está disponible para objetos de tipo Mail::Message::Dummy, donde devuelve "true". En cualquier extensión de "Mail::Message", devuelve "false".

$obj->isPart()
Devuelve "true" si el mensaje es una parte de otro mensaje. Esto es el caso para extensiones de "Mail::Message" de tipo Mail::Message::Part.
$obj->messageId()
Obtiene el identificador del mensaje. Cada mensaje tiene un identificador único. Este id se usa principalmente para reconocer hilos de discusión.
$obj->partNumber()
Devuelve una cadena que representa la ubicación de esta parte. En caso de que el mensaje principal sea solo un mensaje, devuelve "undef". Cuando es multipart, devuelve '1' hasta el número de multipartes. Una parte multi-nivel puede devolver por ejemplo '2.5.1'.

Generalmente, esta cadena es muy corta. El número sigue el diseño de IMAP4, ver RFC2060 sección 6.4.5.

$obj->print( [$fh] )
Imprime el mensaje en el archivo de entrada $fh, que se comporta como el archivo seleccionado. Sin encapsulación en algunos carpetas.
$message->print(\*STDERR); # a la salida de error
$message->print; # a la salida seleccionada 
my $out = IO::File->new('out', 'w');
$message->print($out);      # sin encapsulación: sin carpeta
$message->write($out);      # con encapsulación: es carpeta.
$obj->send( [$mailer], %options )
Envía el mensaje a cualquier lugar fuera de este programa Perl. Devuelve "false" si el envío falla incluso después de intentos.

El parámetro opcional $mailer es un objeto Mail::Transport::Send. Si no se especifica, se crea un objeto y se mantiene como default para los siguientes mensajes.

Los parámetros %options son específicos del mailer, y una mezcla de lo que es posible para crear el objeto mailer y el envío en sí. Por eso, vea para opciones posibles Mail::Transport::Send::new() y Mail::Transport::Send::send(). Este objeto también ofrece un método trySend() para más control bajo.

» ejemplo:

$message->send;

es corto (pero menos flexible) para

my $mailer = Mail::Transport::SMTP->new(@smtpopts);
$mailer->send($message, @sendopts);

Ver ejemplos/send.pl en la distribución de Mail::Box.

» ejemplo:

$message->send(via => 'sendmail')
$obj->size()
Devuelve una aproximación del tamaño en bytes del mensaje completo. En muchas ocasiones, las funciones que procesan el mensaje más adelante, por ejemplo send() o print(), necesitan agregar/alterar líneas de cabecera o agregar caracteres de CR, por lo que el tamaño es solo una estimación con un margen de pocos porcentaje del resultado real.

La computación asume que cada línea de fin se representa por un carácter (como UNIX, MacOS y algunos Cygwin), y no por dos (como Windows y algunos Cygwin). Si escribiste el mensaje en un sistema que usa CR y LF para finalizar una línea (todas las versiones de Windows), el resultado en ese archivo será al menos nrLines() mayor que lo que devuelve este método.

$obj->toplevel()
Devuelve un referencia al mensaje principal, que será el mensaje actual si el mensaje no está contenido en otro mensaje.
$obj->write( [$fh] )
Escribe el mensaje en el archivo de entrada $fh, que se comporta como el archivo seleccionado, con toda la información necesaria para colocarlo correctamente en un archivo de carpeta.

En la mayoría de los casos, el resultado de "write" será el mismo que con print(). La única excepción es para mensajes de carpeta Mbox, que se imprimirán con su línea 'From ' inicial y una línea vacía final. Cada línea del cuerpo de su mensaje que comienza con 'From ' tendrá un '>' añadido delante.

La cabecera

$obj->bcc()
Devuelve las direcciones que se especifican en la cabecera "Bcc" (o líneas). Un listado de objetos Mail::Address es devuelto. "Bcc" significa Blind Carbon Copy: destinatarios del mensaje que no están listados en los mensajes realmente enviados. Por lo tanto, esta cabecera será vacía para mensajes recibidos, pero puede estar presente en los mensajes que construiste tú.
$obj->cc()
Devuelve las direcciones que se especifican en la cabecera "Cc" (o líneas). Un listado de objetos Mail::Address es devuelto. "Cc" significa Carbon Copy: las personas que reciben el mensaje informativo suelen no esperar una respuesta sobre su contenido.
$obj->date()
El método ha sido eliminado debido a razones de consistencia. Use timestamp() o "$msg->head->get('Date')".
$obj->destinations()
Devuelve una lista de objetos Mail::Address que contienen la información combinada de los direcciones activas "To", "Cc" y "Bcc". Las direcciones duplicadas son eliminadas si se detectan.
$obj->from()
Devuelve las direcciones de envío del mensaje. Es posible tener más de una dirección especificada en el campo "From" del mensaje, según la especificación. Por lo tanto, se devuelve una lista de objetos Mail::Address, que suele tener longitud 1.

Si necesitas solo una dirección de un emisor, por ejemplo, para crear una línea "original message by" en el cuerpo de un mensaje forwarding construido, usa sender().

» ejemplo: usando from() para obtener todas las direcciones de emisor

my @from = $message->from;
$obj->get($fieldname)
Devuelve el valor almacenado en la cabecera con el nombre especificado. El $fieldname es insensible al caso. El cuerpo unfolded de la cabecera es devuelto, sin atributos. Vea Mail::Message::Field::body().

Si la cabecera tiene múltiples apariciones, solo se devuelve la última instancia. Si necesitas un manejo más complejo de cabeceras, llama a Mail::Message::Head::get() por ti. Ve study() cuando quieras ser inteligente, haciendo el trabajo más lento pero más preciso.

» ejemplo: el corto get() para cabeceras

print $msg->get('Content-Type'), "\n";

Es equivalente a:

print $msg->head->get('Content-Type')->body, "\n";
$obj->guessTimestamp()
Devuelve una estimación del tiempo en que se envió este mensaje. La función guessTimestamp() se utiliza para estimar el tiempo de envío del mensaje.

El cuerpo

$obj->body( [$body] )
Devuelve el cuerpo de este mensaje. PRECAUCIÓN: esto devuelve un objeto que puede estar codificado: usa decoded() para obtener un cuerpo con datos utilizables.

Con opciones, se establece un nuevo $body para este mensaje. Esto no es para uso normal, salvo que entiendas las consecuencias: cambias el contenido del mensaje sin cambiar el identificador de mensaje. La forma correcta es a través de

$message = Mail::Message->buildFromBody($body);  # o
$message = Mail::Message->build($body);          # o
$message = $origmsg->forward(body => $body);

El $body debe ser un (sub-)clase de Mail::Message::Body. En este caso, la información del cuerpo especificado se copia en los encabezados. El cuerpo objeto será codificado si es necesario, ya que los mensajes escritos a archivo o transmitidos no deben contener datos binarios. El cuerpo convertido se devuelve.

Si $body es "undef", el cuerpo actual del mensaje se desglosará del mensaje. Todas las relaciones se cortarán. El cuerpo se devuelve y puede conectarse a otro mensaje.

» ejemplo:

my $body      = $msg->body;
my @encoded   = $msg->body->lines;
my $new       = Mail::Message::Body->new(mime_type => 'text/html');
my $converted = $msg->body($new);
$obj->contentType()
Devuelve la línea de encabezado de tipo de contenido, o "text/plain" si no está definida. Los parámetros se quitan.
$obj->decoded(%options)
Decodifica el cuerpo de este mensaje y devuélvelo como un objeto de cuerpo. Es un atajo para "$msg->body->decoded". Todas las %options se pasan.
$obj->encode(%options)
Encripta el mensaje en un cierto formato. Consulta los detalles en la página de manual dedicada a Mail::Message::Body::Encode. Las %options que se pueden especificar aquí son las del método Mail::Message::Body::encode().
$obj->isMultipart()
Verifica si este mensaje es un mensaje multipart (tiene adjuntos). Para encontrar esto, se necesita al menos el encabezado del mensaje; no es necesario leer el cuerpo para detectarlo.
$obj->isNested()
Devuelve "true" para mensajes de tipo "message/rfc822" y partes de mensaje.
$obj->parts( [<'ALL'|'ACTIVE'|'DELETED'|'RECURSE'|$filter>] )
Devuelve las partes de este mensaje. Podría ser un poco inusual: devuelve el mensaje mismo si no es multipart.

Generalmente, el término parte se usa con mensajes multipart: mensajes encapsulados en el cuerpo de un mensaje. Para abstraer este concepto: este método devuelve todas las combinaciones de encabezado-cuerpo que se encuentran dentro de este mensaje, excepto los envoltorios de multipart y message/rfc822. Los objetos devueltos son "Mail::Message" y "Mail::Message::Part".

La opción por defecto es '"ALL"', que devuelve el mensaje mismo para mensajes simples, el contenido anidado de un objeto message/rfc822, o las partes de un multipart sin recursión. En caso de '"RECURSE"', se recopilan las partes de los multipart recursivamente. Esta opción no puede combinarse con las otras opciones, que quizás desees: en este caso, tienes que probar por ti mismo.

'"ACTIVE"' y '"DELETED"' verifican el flag eliminado en mensajes y partes. El $filter es un código de referencia que se llama para cada parte del mensaje; cada parte como '"RECURSE"' devuelve.

» ejemplo:

my @parts = $msg->parts;           # $msg no es multipart: devuelve ($msg)
my $parts = $msg->parts('ACTIVE'); # devuelve ($msg)
$msg->delete;
my @parts = $msg->parts;           # devuelve ($msg)
my $parts = $msg->parts('ACTIVE'); # devuelve ()

Banderas

$obj->delete()
Marca el mensaje como para eliminar, que es un atajo para
$msg->label(deleted => time); La eliminación real solo ocurre durante una sincronización de la carpeta. Consulta deleted() también.

El tiempo de la eliminación actual se almacena como valor, pero no siempre se mantiene en la carpeta (depende de la implementación). Cuando el mismo mensaje se elimina varias veces, el primer tiempo de eliminación se mantiene.

» ejemplo:

$message->delete;
$message->deleted(1);  # exactamente lo mismo
$message->label(deleted => 1);
delete $message;
$obj->deleted( [BOOLEAN] )
Establece la bandera de eliminación para este mensaje. Sin argumento, el método devuelve lo mismo que isDeleted(), que es preferible. Cuando se le da un valor "true", se llama a delete().

» ejemplo:

$message->deleted(1);          # eliminar
$message->delete;              # eliminar (preferido)
$message->deleted(0);          # desactivar
if($message->deleted) {...}    # verificar
if($message->isDeleted) {...}  # verificar (preferido)
$obj->isDeleted()
Es un atajo para
$msg->label('deleted')

Para algunos tipos de carpetas, podrás obtener el tiempo de eliminación en el retorno. Esto depende de la implementación.

» ejemplo:

next if $message->isDeleted;
if(my $when = $message->isDeleted) {
   print scalar localtime $when;
}

METHODS

$obj->label( [LABEL] )
The label information is stored within the message object. This method retrieves or sets the value of the $label, opcionalmente después de establecer algunos valores. En caso de establecer valores, usted especifica los pares clave-valor "PAIRS".

Las etiquetas se utilizan para almacenar información sobre el manejo del mensaje dentro de la carpeta. Indicadores sobre si un mensaje fue leído, respondido o programado para su eliminación.

Algunas etiquetas se toman de las líneas "Status" y "X-Status" de la cabecera. Tipos de carpetas como MH definen un archivo de etiquetas separado, y Maildir agrega letras al nombre del archivo del mensaje. Pero las etiquetas de MailBox son siempre las mismas.

» ejemplo:

print $message->label('seen');
if($message->label('seen')) {...};
$message->label(seen => 1);
$message->label(deleted => 1);  # same as $message->delete
$obj->labels()
Devuelve todas las etiquetas conocidas. En contexto ESCALAR, devuelve el conocimiento como referencia a un hash. Esta es una referencia a los datos originales, pero *no* debe cambiar esos datos directamente: ¡llame a "label" para realizar cambios!

En contexto de LISTA, obtiene una lista de nombres que están definidos. Tenga en cuenta que no todos evaluarán a "true", aunque la mayoría lo harán.

$obj->labelsToStatus()
Cuando las etiquetas fueron cambiadas, eso puede afectar a las líneas de cabecera "Status" y/o "X-Status" de los mensajes mbox. Lea sobre la relación entre estos campos y las etiquetas en el capítulo DETAILS.

El método solo afectará cuidadosamente al resultado de modified() cuando haya un cambio real de indicadores, por lo que no para cada llamada a label().

$obj->modified( [BOOLEAN] )
Devuelve (opcionalmente después de establecer) si este mensaje está marcado como modificado. Ver isModified().
$obj->statusToLabels()
Actualiza las etiquetas de acuerdo a las líneas de estado en la cabecera. Ver la descripción en el capítulo DETAILS.

Internos

$obj->clonedFrom()
Devuelve el mensaje que es el original de este mensaje, cuando este fue creado por una operación clone().
$class->coerce($message, %options)
Coacciona un $message a un Mail::Message. En algunas ocasiones, por ejemplo, al agregar un mensaje a una carpeta, esta coerción se llama automáticamente para asegurar que se almacene el tipo de mensaje correcto.

El mensaje coaccionado se devuelve si tiene éxito, de lo contrario "undef". El mensaje coaccionado puede ser una versión re-bendecida del mensaje original o un nuevo objeto. En caso de que el mensaje necesite ser especializado, por ejemplo, de un Mail::Message general a un Mail::Box::Mbox::Message, no se necesita copia. Sin embargo, para coaccionar un objeto Mail::Internet a un Mail::Message, se producirá mucha copia y conversión.

Los Mensajes válidos que pueden ser coaccionados a objetos Mail::Message son de tipo

  • Cualquier tipo de Mail::Box::Message
  • Objetos MIME::Entity, usando Mail::Message::Convert::MimeEntity
  • Objetos Mail::Internet, usando Mail::Message::Convert::MailInternet
  • Objetos Email::Simple, usando Mail::Message::Convert::EmailSimple
  • Objetos Email::Abstract

Los Mail::Message::Part, que son extensiones de "Mail::Message", también pueden ser coaccionados directamente desde un Mail::Message::Body.

» ejemplo:

my $folder  = Mail::Box::Mbox->new;
my $message = Mail::Message->build(...);
my $coerced = Mail::Box::Mbox::Message->coerce($message);
$folder->addMessage($coerced);

Reemplazo más simple para las dos líneas anteriores:

my $coerced = $folder->addMessage($message);
$obj->isDelayed()
Comprueba si el mensaje está retrasado (aún no leído del archivo). Devuelve "true" o "false", dependiendo del tipo de cuerpo.
$obj->readBody( $parser, $head, [$bodytype] )
Lee el cuerpo de un mensaje. El $parser es el acceso al archivo de la carpeta, y la $head ya ha sido leída. La información de la $head se utiliza para crear expectativas sobre la longitud del mensaje, pero también para determinar el tipo MIME y las codificaciones de los datos del cuerpo.

El $bodytype determina qué tipo de cuerpo se creará y por defecto es el valor especificado por new(body_type). $bodytype puede ser el nombre de una clase de cuerpo, o una referencia a una rutina que devuelve la clase del cuerpo cuando se le pasa la $head como único argumento.

$obj->readFromParser( $parser, [$bodytype] )
Lee un mensaje del archivo. El $parser está abierto en el archivo. Primero se llama a readHead(), y la cabecera se almacena en el mensaje. Luego se llama a readBody(), para producir un cuerpo. El cuerpo también se agrega al mensaje sin realizar decodificaciones.

El $bodytype opcional puede ser una clase de cuerpo o una referencia a un código que devuelve una clase de cuerpo basada en la cabecera.

$obj->readHead( $parser, [$class] )
Lee una cabecera en un objeto de la $class especificada. La $class por defecto es new(head_type). El $parser es el acceso al archivo de la carpeta.
$obj->recursiveRebuildPart($part, %options)
Heredado, ver "Internos" en Mail::Message::Construct::Rebuild
$obj->storeBody($body)
Donde el método body() se puede usar para establecer y obtener un cuerpo, con todas las comprobaciones necesarias, este método agrega simplemente el cuerpo especificado al mensaje. Sin conversiones, sin comprobaciones.
$obj->takeMessageId( [STRING] )
Toma el message-id de la "STRING", o crea uno cuando se especifica "undef". Si no se proporciona "STRING" ni "undef", se solicita la cabecera actual del mensaje para obtener el valor del campo 'Message-ID'.

Los ángulos (si están presentes) se eliminan del id.

DETALLES

Estructura de un Mensaje

Un mensaje compatible con MIME se construye a partir de dos partes: la *cabecera* y el *cuerpo*.

*La cabecera*

La cabecera es una lista de campos, algunos abarcando más de una línea ( *plegada* ) cada uno contando algo sobre el mensaje. Información almacenada

Implementación del objeto Mensaje

La idea general sobre la estructura de un mensaje es

Mail::Message
 |  |
 |  `- tiene-uno--Mail::Message::Body
 |
 `---- tiene-uno--Mail::Message::Head
                 |
                 `- tiene-muchos--Mail::Message::Field

Sin embargo: hay unos 7 tipos de objetos de cuerpo, 3 tipos de cabeceras y 3 tipos de campos. No suele verse demasiado de estos tipos, ya que son creados solo por razones de rendimiento y pueden usarse todo lo mismo, excepto los cuerpos multipart.

Un cuerpo multipart es o bien un objeto Mail::Message::Body::Multipart (tipo mime "multipart/*") o un objeto Mail::Message::Body::Nested (tipo mime "message/rfc822"). Estos cuerpos son más complejos:

Mail::Message::Body::Multipart
 |
 `- tiene-muchos--Mail::Message::Part
              |  |
              |  `- tiene-uno--Mail::Message::Body
              |
              `---- tiene-uno--Mail::Message::Head

Antes de intentar reconstruir multipart o mensajes anidados por ti mismo, mejor mira en Mail::Message::Construct::Rebuild.

Implementación de la clase Mensaje

La estructura de clases de mensajes es muy cercana a la de carpetas. Por ejemplo, una instancia Mail::Box::File::Message se relaciona con una carpeta Mail::Box::File.

Como nivel adicional de herencia, tiene un Mail::Message, que es un mensaje sin ubicación. Y hay un caso especial de mensaje: Mail::Message::Part es un mensaje encapsulado en un cuerpo multipart.

Los tipos de mensajes son:

Mail::Box::Mbox::Message            Mail::Box::POP3::Message
|  Mail::Box::Dbx::Message      Mail::Box::IMAP4::Message  |
|  |                                                    |  |
Mail::Box::File::Message             Mail::Box::Net::Message
        |                                      |
        |       Mail::Box::Maildir::Message    |
        |       |   Mail::Box::MH::Message     |
        |       |   |                          |
        |       Mail::Box::Dir::Message        |
        |                |                     |
        `------------.   |   .-----------------'
                     |   |   |
                  Mail::Box::Message    Mail::Message::Part
                         |                     |
                         |       .-------------'
                         |       |
                     Mail::Reporter (clase base general)

Más del 90% de las características de carpeta se implementan en Mail::Box, por lo que están disponibles para todas las tipologías de carpeta. A veces, características que aparecen solo en ciertas tipologías de carpeta se simulan en carpetas que no las tienen, como el soporte de carpetas anidadas en MBOX.

Dos tipos de mensajes extraños se definen: el Mail::Message::Dummy, que filma huecos en listas de nodos de Mail::Box::Thread::Node, y un Mail::Box::Message::Destructed, que es un mensaje intencionalmente destruido para reducir el consumo de memoria.

Etiquetas

Los etiquetados (también llamados "Flags") se utilizan para indicar alguna condición especial en el mensaje, principalmente relacionada con problemas organizativos: ¿cuáles mensajes ya están leídos o deben ser eliminados. Hay una relación muy fuerte entre etiquetas y los usuarios.

La principal complicación es que cada tipo de carpeta tiene su propia forma de almacenar las etiquetas. Para dar una idea: las carpetas MBOX usan "Status" y "X-Status" como campos de cabecera, el MH usa un archivo ".mh-sequences", el MAILDIR codifica las etiquetas en el nombre del mensaje y el IMAP las incluye como parte del protocolo.

Además, algunos tipos de carpeta pueden almacenar etiquetas con nombres definidos por el usuario, mientras que otros no tienen esa característica. Algunas carpetas tienen etiquetas en mayúsculas, otras no. Consulta la documentación de la página de man para conocer los detalles específicos del tipo de mensaje que tienes.

Etiquetas prediseñadas

Para estandarizar las tipologías de carpeta, MailBox ha definido las siguientes etiquetas, que pueden usarse con los métodos label() y labels() de todos los tipos de mensajes:

  • deleted

    Este mensaje se marca como eliminado una vez que la carpeta se cierra. Ten en cuenta que el concepto de 'borrar' en el contexto de una carpeta es solo un indicador, y no implica una acción inmediata! Esto significa que el espacio de memoria utilizado por Perl para almacenar el mensaje no se libera inmediatamente (ve destruct() si lo necesitas).

    Los métodos delete(), deleted() y isDeleted() son cortafuegos para gestionar el etiqueta "delete" (como en MailBox 2.052).

  • draft

    El usuario ha preparado este mensaje, pero no lo ha enviado aún (aún). Esta etiqueta no se agrega automáticamente a un mensaje por parte de MailBox, y tiene solo un significado en aplicaciones de usuario.

  • flagged

    Un mensaje puede ser marcado para alguna razón, por ejemplo, como resultado de una búsqueda de spam en una carpeta. El método Mail::Box::messages() puede usarse para recoger todos estos mensajes marcados de la carpeta.

    Probablemente es más útil usar un nombre comprensible (como "spam") para estas selecciones, aunque estas etiquetas definidas por el usuario no se pueden almacenar en todas las tipologías de carpeta.

  • old

    El mensaje ya estaba en la carpeta cuando se abrió por última vez, por lo que no se añadió recientemente a la carpeta. Esta etiqueta nunca se establecerá automáticamente por MailBox, ya que podría conflictar con la idea del usuario sobre qué es "viejo".

  • passed

    No se usa mucho o se mantiene, esta etiqueta indica que el mensaje fue rechazado o enviado a otro usuario.

  • replied

    El usuario (o aplicación) ha respondido al remitente del mensaje, como respuesta a este. Esta etiqueta se establece automáticamente si usas reply(), pero no con forward() o bounce().

  • seen

    Cuando esta etiqueta está activa, el destinatario del mensaje ha consumido el mensaje. Un agente de correo (MUA) establecerá esta etiqueta cuando el usuario abra el mensaje una vez.

Campos de Estado y X-Status

Las carpetas Mbox no tienen medios especiales para almacenar información sobre los mensajes (excepto la línea separadora del mensaje), y por eso tienen que revertir a añadir campos a la cabecera del mensaje cuando algo especial ocurre. Esta característica también está activa en POP3, aunque si funciona depende del servidor POP. Un agente de correo (MUA) establecerá esta etiqueta cuando el usuario abra el mensaje una vez.

Campos de Estado y X-Status

Las carpetas Mbox no tienen medios especiales para almacenar información sobre los mensajes (excepto la línea separadora del mensaje), y por eso tienen que revertir a añadir campos a la cabecera del mensaje cuando algo especial ocurre. Esta característica también está activa en POP3, aunque si funciona depende del servidor POP.

Todas las aplicaciones que pueden manejar carpetas mbox respaldan los campos "Status" y "X-Status". El siguiente es el uso de codificación:

Flag   Field       Label
R      Status   => seen    (Read)
O      Status   => old     (not recent)
A      X-Status => replied (Answered)
F      X-Status => flagged

No hay una etiqueta especial para "deleted", que más otros carpetas soportan: los mensajes marcados como eliminados nunca se escriben en un archivo de carpeta cuando se cierra.
