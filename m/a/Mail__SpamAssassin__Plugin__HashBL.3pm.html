NOMBRE

HashBL - Consulta de listas de bloqueos DNS (y no hashados)

SYNOPSIS

loadplugin Mail::SpamAssassin::Plugin::HashBL
# Ejemplos de uso no funcionales (sustituir xxx.example.invalid con una lista real)
# Consultas documentadas en el siguiente apartado
header   HASHBL_EMAIL eval:check_hashbl_emails('ebl.example.invalid')
describe HASHBL_EMAIL Mensaje contiene dirección de correo electrónico encontrada en EBL
tflags   HASHBL_EMAIL net
# Cambiar googlemail.com a gmail.com, aplicado antes de acl/welcomelist
hashbl_email_domain_alias gmail.com googlemail.com
# Solo consulta gmail.com
hashbl_acl_freemail gmail.com
header   HASHBL_OSENDR eval:check_hashbl_emails('rbl.example.invalid/A', 'md5/max=10/shuffle', 'X-Original-Sender', '^127\.', 'freemail')
describe HASHBL_OSENDR Mensaje contiene dirección de correo electrónico encontrada en HASHBL
tflags   HASHBL_OSENDR net
body     HASHBL_BTC eval:check_hashbl_bodyre('btcbl.example.invalid', 'sha1/max=10/shuffle', '\b([13][a-km-zA-HJ-NP-Z1-9]{25,34})\b')
describe HASHBL_BTC Mensaje contiene dirección de Bitcoin encontrada en BTCBL
tflags   HASHBL_BTC net
header   HASHBL_URI eval:check_hashbl_uris('rbl.example.invalid', 'sha1', '^127\.', 'X-Some-ID')
describe HASHBL_URI Mensaje contiene URI encontrado en rbl
tflags   HASHBL_URI net
body     HASHBL_ATTACHMENT eval:check_hashbl_attachments('attbl.example.invalid', 'sha256')
describe HASHBL_ATTACHMENT Mensaje contiene archivo adjunto encontrado en attbl
tflags   HASHBL_ATTACHMENT net
# Capturar etiqueta usando la función de captura de regex de SA 4.0
header   __X_SOME_ID X-Some-ID =~ /^(?<XSOMEID>\d{10,20})$/
# Consultar la valor de la etiqueta como es, desde un DNSBL
header   HASHBL_TAG eval:check_hashbl_tag('idbl.example.invalid/A', 'raw', 'XSOMEID', '^127.')

DESCRIPCIÓN

Este plugin soporta varios tipos de consultas de listas de bloqueos DNS (hashadas o no hashadas).

OPTS comunes que aplican a todas las funciones:
raw      sin hash, consulta como es (puede romperse si el valor no es un nombre de dominio válido)
md5      hash con MD5
sha1     hash con SHA1
sha256   hash con SHA256 codificado en Base32
case     mantén el caso antes de hash, por defecto es mayúsculas
max=x    número máximo de consultas (por defecto es 10 si no se especifica)
shuffle  si el máximo se excede, mezcla las consultas antes de truncar a límite

Las opciones múltiples pueden separarse con un slash.

Si OPTS está vacío o no se especifica, se usa el valor por defecto, como documentado por cada tipo de consulta. Si se definen opciones, todos los requisitos deben ser explícitamente definidos.

regla de cabecera check_hashbl_emails('bl.example.invalid/A', 'OPTS', 'HEADERS', '^127\.')
Verifica direcciones de correo de listas de bloqueo DNS. Nota: se puede especificar el cuerpo junto con las cabeceras para buscar direcciones de correo en el cuerpo del mensaje. El tipo de regla debe ser "header".

El tipo de consulta DNS puede agregarse a la lista con /A (por defecto) o /TXT.

El valor por defecto de OPTS es sha1/notag/noquote/max=10/shuffle.

Otras opciones soportadas:

nodot    elimina puntos en el nombre de usuario de la dirección de correo
notag    elimina etiquetas en el nombre de usuario de la dirección de correo
nouri    ignora direcciones de correo dentro de uris
noquote  ignora direcciones de correo dentro de < > o posibles citaciones
user     solo consulta el parte de usuario de la dirección de correo
host     solo consulta el parte de host de la dirección de correo
domain   solo consulta el parte de dominio de la dirección de correo (parte de host + eliminar dominio)

Los HEADERS por defecto son ALLFROM/Reply-To/body.

HEADERS se refiere a una lista separada por guiones de cabeceras a procesar:

ALL           todas las cabeceras
ALLFROM       todas las cabeceras From como devuelto por $pms->all_from_addrs()
EnvelopeFrom  cabecera de envío (Return-Path etc)
<HeaderName>  cualquier cabecera como se usa con reglas de cabecera o $pms->get()
body          todas las direcciones de correo encontradas en el cuerpo del mensaje

Si HEADERS está vacío ('') o no se especifica, se usa el valor por defecto.

Un subtest regexp opcional para coincidir con el respuesta DNS (por defecto: '^127\.').

Para el bloqueo público de correo, vea: http://msbl.org/ebl.html

# Ejemplo de uso, ver https://msbl.org/ebl.html antes de usarlo
header   HASHBL_EMAIL eval:check_hashbl_emails('ebl.msbl.org')
describe HASHBL_EMAIL Mensaje contiene dirección de correo encontrado en EBL
tflags   HASHBL_EMAIL net

El regex por defecto para coincidir y capturar correos puede ser sobrescrito con "hashbl_email_regex". Además, el welcomelist por defecto puede cambiarse con "hashbl_email_welcomelist". Solo cambie si conoce lo que está haciendo, vea el código fuente del plugin para los valores por defecto. Ejemplo: hashbl_email_regex \S+@\S+.com

regla de cabecera check_hashbl_uris('bl.example.invalid/A', 'OPTS', '^127\.')
Verifica todos los URI's parseados del mensaje de lista de bloqueo DNS.

El tipo de consulta DNS puede agregarse a la lista con /A (por defecto) o /TXT.

El valor por defecto de OPTS es sha1/max=10/shuffle.

Un subtest regexp opcional para coincidir con el respuesta DNS (por defecto: '^127\.').

regla body check_hashbl_bodyre('bl.example.invalid/A', 'OPTS', '\b(match)\b', '^127\.')
Busca en el cuerpo del mensaje una coincidencia de regex y consulta el texto capturado. La regex debe tener un solo capturador ( ) para el texto ($1). El tipo de regla debe ser "body" o "rawbody".

El tipo de consulta DNS puede agregarse a la lista con /A (por defecto) o /TXT.

El valor por defecto de OPTS es sha1/max=10/shuffle.

Otras opciones soportadas:

num      elimina los caracteres que no son números

Un subtest regexp opcional para coincidir con el respuesta DNS (por defecto: '^127\.').

regla de cabecera check_hashbl_tag('bl.example.invalid/A', 'OPTS', 'TAGNAME', '^127\.')
Consulta el valor de la etiqueta _TAGNAME_ de SpamAssassin desde la lista de bloqueo DNS.

El tipo de consulta DNS puede agregarse a la lista con /A (por defecto) o /TXT.

El valor por defecto de OPTS es sha1/max=10/shuffle.

Otras opciones soportadas:

ip        solo consulta si el valor es una dirección IPv4/IPv6 válida
ipv4      solo consulta si el valor es una dirección IPv4 válida
ipv6      solo consulta si el valor es una dirección IPv6 válida
revip     invierte la dirección IP antes de la consulta
fqdn      solo consulta si el valor es una dirección FQDN (es_fqdn_valid)
tld       solo consulta si el valor tiene un TLD válido (es_domain_valid)
trim      elimina el nombre del hostname hasta el dominio (trim_domain)
Si se activan ambos ip/ipv4/ipv6 y fqdn/tld, solo se necesita uno de ellos para coincidir. Ambos fqdn y tld son necesarios para un check completo de FQDN+TLD.

Un subtest regexp opcional para coincidir con el respuesta DNS (por defecto: '^127\.').

regla de cabecera check_hashbl_attachments('bl.example.invalid/A', 'OPTS', '^127\.')
Verifica todos los archivos adjuntos (mimeparts) de mensaje de lista de bloqueo DNS.

El tipo de consulta DNS puede agregarse a la lista con /A (por defecto) o /TXT.

El valor por defecto de OPTS es sha1/max=10/shuffle.

Otras opciones soportadas:

minsize=x  pasa por alto cualquier parte menor de x bytes
maxsize=x  pasa por alto cualquier parte mayor de x bytes

Un subtest regexp opcional para coincidir con el respuesta DNS (por defecto: '^127\.').

Los nombres de archivos específicos de adjuntos pueden ser omitidos con "hashbl_ignore". Ejemplo: hashbl_ignore safe.pdf

Los tipos mime específicos de adjuntos pueden ser omitidos con "hashbl_ignore". Ejemplo: hashbl_ignore text/plain

valor de hashbl_ignore [value...]
Omite cualquier consulta si el valor de hash o el valor original (por ejemplo, correo electrónico) coincide. Se pueden especificar múltiples valores separados por espacios. La coincidencia es insensible al caso.

Cualquier host o su dominio parte que coincida con uridnsbl_skip_domains también se omite por defecto.

DESCRIPCIÓN

Este plugin permite usar bases de datos de listas negras de hash (HashBL) con SpamAssassin. Las listas negras de hash son listas de hashes de mensajes que se han identificado como spam. Al comparar el hash de un mensaje entrante con los hashes de las listas negras, se puede determinar si el mensaje es probable que sea spam.
