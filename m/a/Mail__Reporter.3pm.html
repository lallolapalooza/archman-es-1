SINOPSIS

$folder->log(WARNING => 'vete');
print $folder->trace;        # nivel actual
$folder->trace('PROGRESS');  # establecer nivel
print $folder->errors;
print $folder->report('PROGRESS');

DESCRIPCIÓN

La clase "Mail::Reporter" es la clase base para todas las clases, excepto Mail::Message::Field::Fast porque se volvería lenta... Esta clase base se utiliza durante la inicialización de los objetos, y para configurar y registrar mensajes de error.

MÉTODOS

La clase "Mail::Reporter" es la base para casi todos los demás objetos. Puede almacenar y reportar problemas, y contiene el constructor general new().

Constructores

$class->new(%options)
Este contenedor de errores es también el constructor base para todos los módulos, (siempre que no haya necesidad de otro objeto base) El constructor siempre acepta las siguientes %options relacionadas con los reportes de errores. 
-Opción--Por defecto
 log     'WARNINGS'
 trace   'WARNINGS'
log => NIVEL
Los mensajes de registro que tengan una prioridad mayor o igual al nivel especificado se almacenan internamente y se pueden recuperar más tarde. El valor por defecto global para esta opción se puede cambiar con defaultTrace().

Los niveles conocidos son "INTERNAL", "ERRORS", "WARNINGS", "PROGRESS", "NOTICES" "DEBUG" y "NONE". El nivel "PROGRESS" se relaciona con la lectura y escritura de carpetas. "NONE" hará que solo se registren los errores "INTERNAL". Por cierto: "ERROR" es un alias de "ERRORS", al igual que "WARNING" es un alias de "WARNINGS", y "NOTICE" de "NOTICES".

trace => NIVEL
Los mensajes de rastreo que tengan un nivel mayor o igual al nivel especificado se imprimen directamente usando warn. El valor por defecto global para esta opción se puede cambiar con defaultTrace().

Atributos

$obj->logSettings()
Devuelve una lista de pares "(clave =" valor)>" que se pueden usar para inicializar un nuevo objeto con las mismas configuraciones de registro que este.

» ejemplo:

$head->new($folder->logSettings);

Manejo de errores

$obj->AUTOLOAD()
Por defecto, produce una advertencia agradable si las subclases no pueden resolver un método.
$obj->addReport($object)
Añade el reporte de otro $object al reporte de este objeto. Esto es útil cuando las acciones complejas usan objetos temporales que no se devuelven a la aplicación principal pero de los cuales la aplicación principal querría conocer cualquier problema.
$any->defaultTrace( [$level]|[$loglevel, $tracelevel]|[$level, $callback] )
Reporta el nivel de registro y rastreo por defecto que se utiliza para los objetos como una lista de dos elementos. Cuando no se establece explícitamente, ambos se establecen en "WARNINGS".

Este método tiene tres usos diferentes. Cuando se especifica un argumento, ese $level se establece tanto para el nivel de registro como para el nivel de rastreo.

Con dos argumentos, el segundo determina qué configuración desea. Si el segundo argumento es una referencia CODE, instala una $callback. El nivel de registro se establecerá en NONE, y todas las advertencias producidas en su programa se pasarán a la función $callback. Esa función recibirá el nivel del problema, el objeto o la clase que reporta el problema y el texto del problema pasados como argumentos.

En cualquier caso, se devuelven dos valores: el primero es el nivel de registro, el segundo representa el nivel de rastreo. Ambos son variables especiales: en contexto numérico entregan un valor (el valor utilizado internamente) y en contexto de cadena el nombre de la cadena. Tenga en cuenta que la cadena siempre está en forma singular.

» ejemplo: estableciendo niveles de registro

my ($loglevel, $tracelevel) = Mail::Reporter->defaultTrace;
Mail::Reporter->defaultTrace('NOTICES');
my ($l, $t) = Mail::Reporter->defaultTrace('WARNINGS', 'DEBUG');
print $l;     # imprime "WARNING"  (¡sin S!)
print $l+0;   # imprime "4"
print "Auch" if $l >= $self->logPriority('ERROR');
Mail::Reporter->defaultTrace('NONE');  # silenciar todos los reportes
$folder->defaultTrace('DEBUG');   # ¡Aún configurado como valor por defecto global!
$folder->trace('DEBUG');          # valor por defecto local

» ejemplo: instalando una callback

Mail::Reporter->defaultTrace
$obj->errors()
Equivalente a "<$folder-"report('ERRORS')>>
$any->log( [$level, [$strings]] )
Como método de instancia, esta función tiene tres propósitos diferentes. Sin argumentos, devuelve un escalar que contiene el número que se utiliza internamente para representar el nivel de registro actual, y la representación textual de la cadena al mismo tiempo. Consulte el método "dualvar" de Scalar::Util para obtener una explicación.

Con un argumento, se establece un nuevo nivel de detalle de registro (especifique un número de una de las cadenas predefinidas). Con más argumentos, es un reporte que puede necesitar ser registrado o rastreado.

Como método de clase, solo se puede pasar un mensaje. El valor de configuración global establecido con defaultTrace() se utiliza para decidir si el mensaje se muestra o se ignora.

Cada entrada de registro tiene un $level y una cadena de texto que se construirá uniendo los $strings. Si no hay una nueva línea, se agregará.

» ejemplo:

print $message->log;      # puede imprimir "NOTICE"
print $message->log +0;   # puede imprimir "3"
$message->log('ERRORS');  # establece un nuevo nivel, devuelve el valor numérico
$message->log(WARNING => "Este mensaje es demasiado grande.");
$folder ->log(NOTICE  => "No se puede leer del archivo $filename.");
$manager->log(DEBUG   => "¡Hola!", reverse sort @l);
Mail::Message->log(ERROR => 'Desconocido');
$any->logPriority($level)
Un nivel de error (registro o rastreo) tiene más de una representación: un valor numérico y una o más cadenas. Por ejemplo, 4, 'WARNING' y 'WARNINGS' son todas lo mismo. Puede especificar cualquiera de ellas y, a cambio, obtener una dualvar (consulte el método "dualvar" de Scalar::Util) que contiene el número y la forma singular.

Cuanto mayor sea el número, más importante será el mensaje. Solo los mensajes sobre problemas "INTERNAL" son más importantes que "NONE"

» ejemplo:

my $r = Mail::Reporter->logPriority('WARNINGS');
my $r = Mail::Reporter->logPriority('WARNING');    # igual
my $r = Mail::Reporter->logPriority(4);            # igual, obsoleto

$obj->notImplemented()
Un caso especial de log(), que registra un "INTERNAL"-error y luego falla. Esto es usado por los escritores de extensiones.
$obj->report( [$level] )
Obtener reportes registrados, como una lista de cadenas. Si se especifica un $level, se devuelve el registro para ese nivel.

En caso de que no se especifique un $level, se obtienen todos los mensajes, cada uno como una referencia a una tupla con el nivel y el mensaje.

» ejemplo:

my @warns = $message->report('WARNINGS');
# llamada indirectamente anterior con
my @warns = $msg->warnings;
print $folder->report('ERRORS');
if($folder->report('DEBUG')) {...}
my @reports = $folder->report;
foreach (@reports) {
   my ($level, $text) = @$_;
   print "$level report: $text";
}
$obj->reportAll( [$level] )
Reportar todos los mensajes que fueron producidos por este objeto y todos los objetos que son mantenidos por este objeto. Esto devolverá una lista de tríos, cada uno conteniendo una referencia al objeto que capturó el reporte, el nivel del reporte y el mensaje.

» ejemplo:

my $folder = Mail::Box::Manager->new->open(folder => 'inbox');
my @reports = $folder->reportAll;
foreach (@reports) {
   my ($object, $level, $text) = @$_;
   if($object->isa('Mail::Box')) {
      print "Folder $object: $level: $message";
   } elsif($object->isa('Mail::Message') {
      print "Message ".$object->seqnr.": $level: $message";
   }
}
$obj->trace( [$level] )
Cambiar el nivel de $level de rastreo del objeto. Cuando no se especifican argumentos, solo se devuelve el nivel actual. Se devolverá en un escalar que contiene tanto el número que se usa internamente para representar el nivel, como la cadena que lo representa. Ver logPriority().
$obj->warnings()
Equivalente a "<$folder-"report('WARNINGS')>>

DIAGNÓSTICOS

Error: El paquete $package no implementa $method.
Error fatal: el paquete específico (o una de sus superclases) no implementa este método donde debería. Este mensaje significa que otras clases relacionadas implementan este método, pero la clase en cuestión no lo hace. Probablemente deberías investigar esto y, posiblemente, informar al autor del paquete. Lanzado por notImplemented()
