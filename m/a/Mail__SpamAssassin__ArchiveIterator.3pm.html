NOMBRE

Mail::SpamAssassin::ArchiveIterator - encontrar y procesar mensajes uno por uno

SINOPSIS

my $iter = Mail::SpamAssassin::ArchiveIterator->new(
  {
    'opt_max_size' => 500 * 1024,  # 0 implica sin límite
    'opt_cache' => 1,
  }
);
$iter->set_functions( \&wanted, sub { } );
eval { $iter->run(@ARGV); };
sub wanted {
  my($class, $filename, $recv_date, $msg_array) = @_;
  ...
}

DESCRIPCIÓN

El módulo Mail::SpamAssassin::ArchiveIterator recorrerá un conjunto de archivos mbox, mbx y directorios (un mensaje por archivo) y generará una lista de mensajes. Luego llamará las subrutinas "wanted_sub" y "result_sub" adecuadamente según cada mensaje.

MÉTODOS

$item = Mail::SpamAssassin::ArchiveIterator->new( [ { opt => val, ... } ] )
Construye un objeto "Mail::SpamAssassin::ArchiveIterator". Puedes pasar los pares clave-valor siguientes al constructor. Los pares son opcionales, a menos que se indique lo contrario.
opt_max_size
El valor de la opción opt_max_size determina un límite (en bytes) por encima del cual un mensaje se considera grande y se omite por ArchiveIterator.

Un valor 0 implica sin límite de tamaño, todos los mensajes se examinan. Un valor indefinido implica un límite por defecto de 500 KiB.

opt_all
Al establecer esta opción a verdadero, implícitamente establece opt_max_size a 0, es decir, sin límite de tamaño de mensaje, todos los mensajes se procesan por ArchiveIterator. Para compatibilidad con versiones antiguas de SpamAssassin que carecían de la opción opt_max_size.
opt_scanprob
Escanea mensajes de forma aleatoria con una probabilidad de N, donde N varía de 0.0 (ningún mensaje escaneado) a 1.0 (todos los mensajes escaneados). El valor por defecto es 1.0.

Este ajuste puede especificarse por separado para cada objetivo.

opt_before
Únicamente si los mensajes recibidos son después de la fecha dada. Valores negativos son un desplazamiento desde el tiempo actual, por ejemplo -86400 = últimas 24 horas; o como parseado por Time::ParseDate (por ejemplo '-6 meses').

Este ajuste puede especificarse por separado para cada objetivo.

opt_after
Similar a opt_before, pero los mensajes se usan solo si son posteriores a la fecha dada.

Este ajuste puede especificarse por separado para cada objetivo.

opt_want_date
Establece 1 (por defecto) si quieres que la fecha recibida sea incluida en la llamada "wanted_sub". Establece 0 para evitar esto; es buena idea establecerlo a 0 si es posible, ya que impone un costo de rendimiento.
opt_skip_empty_messages
Establece 1 si quieres omitir mensajes corruptos o de 0 bytes. El valor por defecto es 0.
opt_cache
Establece 0 (por defecto) si no quieres utilizar información cacheada para acelerar ArchiveIterator. Establece 1 para habilitar. Este ajuste requiere también "opt_cachedir".
opt_cachedir
Establece la ruta del directorio donde quieres almacenar la información cacheada para "opt_cache", si no quieres mezclarla con los archivos de entrada (lo cual es el predeterminado). El directorio debe ser legible y escribible.
wanted_sub
Referencia a una subrutina que procesa los datos del mensaje. A menudo se establece mediante set_functions(). La subrutina recibirá 5 valores: clase (escalar), nombre de archivo (escalar), fecha recibida (escalar), contenido del mensaje (referencia a array, una línea por elemento), y el formato del mensaje ('f' para archivo, 'm' para mbox, 'b' para mbx).

Nota: Si "opt_want_date" está establecido a 0, el valor escalar de fecha recibida será indefinido.

result_sub
Referencia a una subrutina que procesa los resultados de "wanted_sub" para cada mensaje procesado. A menudo se establece mediante set_functions(). La subrutina recibirá 3 valores: clase (escalar), resultado (escalar, devuelto por "wanted_sub"), y fecha recibida (escalar).

Nota: Si "opt_want_date" está establecido a 0, el valor escalar de fecha recibida será indefinido.

scan_progress_sub
Referencia a una subrutina que se llama de forma intermitente durante la fase de 'scan' de la verificación masiva. No se garantiza con qué frecuencia podría ocurrir.
opt_from_regex
Permite flexibilidad en la especificación del separador de From en formato mbox.

El valor por defecto es la expresión regular:

/^From \S+ ?(\S\S\S \S\S\S .?\d .?\d:\d\d:\d\d \d{4}|.?\d-\d\d-\d{4}_\d\d:\d\d:\d\d_)/

Algunos programas de SpamAssassin como sa-learn usarán la opción de configuración 'mbox_format_from_regex' para sobrescribir la expresión regular por defecto.

set_functions( \&wanted_sub, \&result_sub )
Establece las subrutinas usadas para el procesamiento de mensajes (wanted_sub) y el reporte de resultados. Para más información, ver new() anterior.
run ( @target_paths )
Genera la lista de mensajes a procesar, luego ejecuta cada mensaje a través de la subrutina configurada para wanted.

Los archivos comprimidos se detectan y descomprimen automáticamente, independientemente del tipo de archivo. Los formatos soportados son "gzip", "bzip2", "xz", "lz4", "lzip", "lzo". El gzip se descomprime mediante el módulo IO::Zlib, mientras que otros usan sus herramientas específicas (bzip2/xz/lz4/lzip/lzop). Los archivos comprimidos de tipo mailbox/mbox no son soportados.

La matriz de directorios target_paths debe tener un elemento por cada ruta en el siguiente formato: "class:format:raw_location", o una referencia a un diccionario con pares clave-valor y una clave 'target' con un valor en ese formato.

Los pares clave-valor que pueden usarse son: opt_scanprob, opt_after, opt_before. Para más información sobre su efecto, ver la documentación del método new.

run() devuelve 0 en caso de error (por ejemplo, no poder abrir un archivo) y 1 en caso de no haber errores.

class
Es 'h' para ham o 's' para spam. Si la clase es de más de un carácter, se truncará. Si está vacío, se considera 'h' como valor predeterminado.
format
Es el formato de raw_location. "dir" es un directorio con archivos individuales de mensajes, "file" es un archivo con un mensaje único, "mbox" es un archivo mbox, o "mbx" es un directorio mbx.

"detect" también puede usarse. Esto asume "mbox" para cualquier archivo cuyo camino contenga el patrón "/\.mbox/i", "file" cualquier cosa que no sea un directorio, o "directory" de lo contrario.

raw_location
Ruta de archivo o directorio. Se permite el uso de globbing con el estilo de glob de csh (ver
