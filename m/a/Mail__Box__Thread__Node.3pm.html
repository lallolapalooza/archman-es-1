NOMBRE

Mail::Box::Thread::Node - un nodo en un hilo de mensajes

HERENCIA

Mail::Box::Thread::Node
  es un Mail::Reporter

SINOPSIS

my $node = Mail::Box::Thread::Node->new;
$node->addMessage($message);
...

DESCRIPCIÓN

El objeto "Mail::Box::Thread::Node" mantiene un nodo en la lista enlazada de hilos. Cada nodo contiene un mensaje y una lista de sus respuestas. Además, se refiere a su propio ancestro y contiene información sobre la confiabilidad de esa relación.

Para complicar un poco las cosas, dado que el gestor de hilos puede mantener múltiples carpetas y fusionar su contenido, puedes encontrar el mismo mensaje en varias carpetas. Todas las versiones del mismo mensaje (basadas en el ID del mensaje) se almacenan en el mismo nodo.

Extiende "DESCRIPTION" en Mail::Reporter.

El nodo del hilo

$obj->addMessage($message)
Añade un mensaje al nodo del hilo. Si el nodo contiene un mensaje ficticio, este es reemplazado. De lo contrario, el mensaje se añade al final de la lista.
$obj->expand( [BOOLEAN] )
Devuelve si esta (parte de la) carpeta debe mostrarse expandida o no. Esto se hace simplemente con una etiqueta, lo que significa que la mayoría de los tipos de carpetas pueden almacenar esto.
$obj->message()
Obtiene el mensaje que está almacenado en este nodo del hilo. NOTA: el mismo mensaje puede estar ubicado en varias carpetas al mismo tiempo, y estas carpetas pueden ser controladas por el mismo gestor de hilos.

En contexto escalar, este método devuelve la primera instancia del mensaje que no está borrado. Si todas las instancias están marcadas para ser borradas, obtendrás el primer mensaje borrado. Cuando las carpetas abiertas solo contienen referencias al mensaje, pero ninguna instancia, obtendrás un mensaje ficticio (ver Mail::Message::Dummy).

En contexto de lista, se devuelven todas las instancias del mensaje que se han encontrado.

» ejemplo:

my $threads = $mgr->threads(folders => [$draft, $sent]);
my $node    = $draft->message(1)->thread;
foreach my $instance ($node->message) {
   print "Encontrado en ", $instance->folder, ".\n";
}
print "El asunto es ", $node->message->subject, ".\n";

El orden del hilo

$obj->followUps()
Devuelve la lista de respuestas a este nodo del hilo. Esta lista puede contener mensajes analizados, no analizados y ficticios.
$obj->followedBy($threads)
Registra que las $threads son respuestas a este mensaje. Estas respuestas no necesitan estar relacionadas entre sí de ninguna manera aparte de compartir el mismo padre.

Definir la misma relación más de una vez no causará que la información se duplique.

$obj->follows($thread, $quality)
Registra que el hilo actual es una respuesta al $thread especificado. La $quality de la relación se especifica mediante el segundo argumento. El método devuelve "undef" si el enlace no se acepta para evitar referencias circulares.

La relación puede especificarse más de una vez, pero solo se utiliza la relación más segura. Por ejemplo, si se especifica una respuesta (el $quality es igual a "REPLY"), las llamadas posteriores al método follow no tendrán ningún efecto. Si se llama a "follows" con una $quality que coincide con la calidad actual, el nuevo hilo anula el anterior.

NAME

Mail::Box::Thread::Node - representation of a message in a thread

INHERITANCE

Mail::Box::Thread::Node is an Mail::Box::Base object.

SYNOPSIS

  # This is an internal class used by Mail::Box::Thread
  # You will not create instances of this class directly.
  # The methods are available on the objects returned by
  # Mail::Box::Thread->new(...) or Mail::Box::Thread->newFromFile(...)

DESCRIPTION

This class represents one node (message) in a thread. A thread is a collection of related messages. This class provides access to the message itself, but also to the structure of the thread (which messages are replies to which).

The thread structure is built by analysing the message headers (like 'In-Reply-To' and 'References') and sometimes by content analysis.

Methods of this class are usually called on the result of Mail::Box::Thread methods.

METHODS

$obj->child()
Returns the first child node. This is the first message that directly replies to this message.
$obj->children()
Returns a list of all child nodes. These are all messages that directly reply to this message.
$obj->dummy()
Returns true when this node is a dummy, meaning that the message itself is not present in the mailbox, but is referenced by other messages. This can happen when messages are moved between folders.
$obj->followUps()
Returns a list of all messages that follow this one in the thread. This is a recursive list. The list can be very long.
$obj->message()
Returns the actual message object (an instance of Mail::Message) for this node. This method returns undef when the node is a dummy.
$obj->parent()
Returns the parent node, which is the message this one is a reply to. Returns undef for the root of a thread.
$obj->repliedTo([$max_confidence])
Returns the message this node is a reply to. Returns undef if this message is the first message in a thread.

The optional $max_confidence argument can be used to limit the search. If set to 'REFERENCE', only messages found via the 'References' header are returned. If set to 'REPLY' (the default), also messages found via the 'In-Reply-To' header are returned. The heuristic 'GUESS' is never used when searching for the parent.

In list context, this method returns a second string value indicating the confidence that the messages are related. When extended thread discovery is enabled, then some heuristics are applied to determine if messages are related. Values for the STRING may be:

  • 'REPLY'

    This relation was directly derived from an in-reply-to message header field. The relation has a high confidence.

  • 'REFERENCE'

    This relation is based on information found in a Reference message header field. One message may reference a list of messages which precede it in the thread. The heuristic attempts to determine relationships between messages assuming that the references are in order. This relation has a lower confidence.

  • 'GUESS'

    The relation is a big guess, with low confidence. It may be based on a subject which seems to be related, or commonalities in the message's body.

More constants may be added later.

» example:

my $question = $answer->repliedTo;
my ($question, $quality) = $answer->repliedTo;
if($question && $quality eq 'REPLY') { ... };
$obj->sortedFollowUps( [$prepare, [$compare]] )
Returns the list of followUps(), but sorted. By default sorting is based on the estimated time of the reply. See startTimeEstimate().

On the whole thread

Some convenience methods are added to threads, to simplify retrieving information from it.

$obj->endTimeEstimate()
Returns a guess as to when the thread has ended (although you never know for sure whether there fill follow messages in the future).
$obj->ids()
Returns all the ids in the thread starting at the current thread node.

» example:

$newfolder->addMessages($folder->ids($thread->ids));
$folder->delete($thread->ids);
$obj->numberOfMessages()
Number of messages in the thread starting at the current thread node, but not counting the dummies.
$obj->recurse(CODE)
Execute a function for all sub-threads. If the subroutine returns "true", sub-threads are visited recursively. Otherwise, the current branch traversal is aborted. The routine is called with the thread-node as the only argument.
$obj->startTimeEstimate()
Returns a guess as to when the thread was started. Each message contains various date specifications (each with various uncertainties resulting from timezones and out-of-sync clocks). One of these date specifications is used as the timestamp for the message. If the node contains a dummy message the lowest timestamp of the replies is returned. Otherwise the estimated timestamp of the node's message is returned.
$obj->threadMessages()
Returns all the messages in the thread starting at the current thread node. This list will not include dummies.

» example:

my @t = $folder->message(3)->threadStart->threadMessages;
$obj->threadToString( [CODE] )
Translate a thread into a string. The string will contain at least one line for each message which was found, but tries to fold dummies. This is useful for debugging, but most message readers will prefer to implement their own thread printer.

The optional "CODE" argument is a reference to a routine which will be called for each message in the thread. The routine will be called with the message as the first argument. The default shows the subject of the message. In the first example below, this routine is called seven times.

» example:

print $node->threadToString;

may result in

Subject of this message
|- Re: Subject of this message
|-*- Re: Re: Subject of this message
| |- Re(2) Subject of this message
| |- [3] Re(2) Subject of this message
| `- Re: Subject of this message (reply)
`- Re: Subject of this message

The * represents a missing message (a "dummy" message). The [3] presents a folded thread with three messages.

» example:

print $node->threadToString(\&show);
sub show($) {
   my $message = shift;
   my $subject = $message->head->get('subject');
   length $subject ? $subject : '<no subject>';
}
$obj->totalSize()
Returns the sum of the size of all the messages in the thread.
