Mail::SPF::Request(3) Documentación de Perl contribuida por el usuario Mail::SPF::Request(3)

NOMBRE

Mail::SPF::Request - Clase de solicitud SPF

VERSIÓN

version 3.20250505

SINOPSIS

use Mail::SPF;
my $request = Mail::SPF::Request->new(
    versions    => [1, 2],              # opcional
    scope       => 'mfrom',             # o 'helo', 'pra'
    identity    => 'fred@example.com',
    ip_address  => '192.168.0.1',
    helo_identity                       # opcional,
                => 'mta.example.com'    #   para expansión de macros %{h}
);
my @versions    = $request->versions;
my $scope       = $request->scope;
my $authority_domain
                = $request->authority_domain;
my $identity    = $request->identity;   # 'localpart@domain' o 'domain'
my $domain      = $request->domain;
my $localpart   = $request->localpart;
my $ip_address  = $request->ip_address;     # dirección IPv4 o IPv6
my $ip_address_v6                           # dirección IPv6 nativa o
                = $request->ip_address_v6;  #   dirección IPv6 mapeada a IPv4
my $helo_identity                           # identidad HELO adicional
                = $request->helo_identity;  #   para alcances que no son HELO
my $record      = $request->record;
    # el registro seleccionado durante el procesamiento de la solicitud, puede ser undef
$request->state(field => 'value');
my $value = $request->state('field');

DESCRIPCIÓN

Un objeto de la clase Mail::SPF::Request representa una solicitud SPF.

Constructores

Se proporcionan los siguientes constructores:

new(%options): devuelve Mail::SPF::Request
Crea un nuevo objeto de solicitud SPF. La solicitud se considera la solicitud raíz para cualquier sub-solicitud posterior (ver el constructor "new_sub_request").

%options es una lista de pares clave/valor que representan cualquiera de las siguientes opciones:

versions
Una referencia a un *array* de *enteros* que enumera las versiones de los registros SPF que se pueden utilizar para la verificación SPF. Solo se usarán aquellas versiones de registro que cubran el alcance deseado. Se debe especificar al menos una versión aplicable. Para una única versión de registro, se puede especificar un escalar simple en lugar de una referencia de array. Por defecto, todas las versiones que cubren el alcance deseado (ver abajo); por defecto, [1, 2] para el alcance por defecto de 'mfrom'.

Las siguientes versiones son compatibles:

1
Usar registros "v=spf1".
2
Usar registros "spf2.0".

Ejemplo: Un valor de 1 (o [1]) significa que solo se deben usar registros "v=spf1" para la verificación SPF. Si al mismo tiempo se especifica un alcance de 'pra', se lanzará una excepción *Mail::SPF::EInvalidScope* ya que los registros "v=spf1" no cubren el alcance PRA.

scope
Una cadena que denota el alcance de autorización de la identidad que debe verificarse. Por defecto es 'mfrom'. Los siguientes valores de alcance son compatibles:
'helo'
La identidad dada es el parámetro "HELO" de una transacción SMTP (RFC 2821) y debe verificarse contra registros SPF que cubran el alcance "helo" ("v=spf1"). Ver la especificación SPFv1 (RFC 4408) para la definición formal del alcance "HELO".
'mfrom'
La identidad dada es el parámetro "MAIL FROM" de una transacción SMTP (RFC 2821), y debe verificarse contra registros SPF que cubran el alcance "mfrom" ("v=spf1" y "spf2.0/mfrom"). Ver la especificación SPFv1 (RFC 4408) para la definición formal del alcance "MAIL FROM".

Nota: En el caso de un parámetro de transacción SMTP "MAIL FROM" vacío ("MAIL FROM:<>"), la identidad verificada será postmaster@nombre_helo según lo especificado en RFC 7208.

'pra'
La identidad dada es la "Dirección del Responsable Presunto" de un mensaje de Internet (RFC 2822) y debe verificarse contra registros SPF que cubran el alcance "pra" ("spf2.0/pra"). Ver la especificación PRA (RFC 4407) para la definición formal del alcance PRA.
authority_domain
Una cadena que denota el nombre de dominio que debe consultarse para obtener registros de política del remitente. Por defecto es el dominio de la opción "identity". Normalmente no hay necesidad de especificar la opción "authority_domain".
identity
Requerido. Una cadena que denota la identidad del remitente cuya autorización debe verificarse. Este es un nombre de dominio para el alcance "helo", y una dirección de correo electrónico para los alcances "mfrom" y "pra".

Nota: No se debe pasar una identidad vacía, en el caso de un parámetro de transacción SMTP "MAIL FROM" vacío ("<MAIL FROM:<" >>), la identidad verificada será postmaster@nombre_helo según lo especificado en RFC 7208.

ip_address
Requerido para verificaciones con los alcances "helo", "mfrom" y "pra". Ya sea una cadena o un objeto NetAddr::IP que denote la dirección IP del host que reclama la identidad que se está verificando. Puede ser una dirección IPv4 o IPv6. Una dirección IPv6 mapeada a IPv4 (por ejemplo, '::ffff:192.168.0.1') se trata como una dirección IPv4.
helo_identity
Una cadena que denota el parámetro SMTP "HELO" en el caso de que la identidad principal sea de un alcance distinto de "helo". Esta identidad se utiliza entonces meramente para la expansión de macros "%{h}" durante la evaluación de políticas de la identidad principal. Por defecto es undef, que se expandirá a 'unknown'. Si la identidad principal es del alcance "helo", esta opción no se utiliza.
new_sub_request(%options): devuelve Mail::SPF::Request
Debe invocarse en un objeto de solicitud existente. Crea un nuevo objeto de sub-solicitud clonando la solicitud invocada, que se considera la super-solicitud de la nueva solicitud. Las opciones especificadas (ver el constructor "new") anulan los parámetros de la super-solicitud. Normalmente no hay necesidad de especificar ninguna opción *además* de la opción "authority_domain".

Métodos de instancia

Se proporcionan los siguientes métodos de instancia:

root_request: devuelve Mail::SPF::Request
Devuelve la raíz de la cadena de super-solicitudes de la solicitud. Específicamente, devuelve la solicitud misma si no tiene super-solicitudes.
super_request: devuelve Mail::SPF::Request
Devuelve la super-solicitud de la solicitud, o undef si no existe ninguna.
versions: devuelve
