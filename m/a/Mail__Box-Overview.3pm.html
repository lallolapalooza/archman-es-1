Mail::Box-Overview(3) Documentación Perl aportada por el usuario Mail::Box-Overview(3)

NOMBRE

Mail::Box-Overview - objetos utilizados por Mail::Box

DESCRIPCIÓN

Introducción

El paquete MailBox es un conjunto de clases para acceder y gestionar carpetas de correo de manera independiente de la carpeta. Este paquete es una alternativa a los paquetes "Mail::Folder" y "MIME::*". Abstrae los detalles de los mensajes, el almacenamiento de mensajes y los hilos de mensajes, al tiempo que proporciona un mejor rendimiento que los paquetes de correo antiguos. Está destinado a proporcionar un conjunto de herramientas orientadas a objetos para todo tipo de aplicaciones de correo electrónico, como Agentes de Usuario de Correo (MUA) y programas de filtrado de correo.

Este paquete es modular: partes de él se pueden utilizar independientemente del resto. Por ejemplo, Mail::Box::Manager puede determinar automáticamente que una carpeta está en formato Mbox y devolver un objeto de la clase Mail::Box::Mbox, o el programa de usuario puede omitir el gestor y crear objetos Mail::Box::Mbox directamente. Del mismo modo, si el programa de usuario solo está manipulando un solo mensaje, un Mail::Message.

El paquete Mail::Box tiene características especiales para ayudar a los MUA a acceder rápidamente a los datos de la carpeta en orden aleatorio. Realmente no te beneficiarás (ni tampoco serás más lento) si necesitas la carpeta completa secuencialmente.

Puede que quieras echar un vistazo a los scripts de ejemplo en el directorio "scripts".

Distribuciones

Hasta MailBox v2, todos los módulos "Mail::*" se publicaron como una única distribución. A partir de la v3, hay algunas distribuciones separadas en un intento de reducir las dependencias:

  • Mail::Message
  • Mail::Transport
  • Mail::Box
  • Mail::Box::IMAP4
  • Mail::Box::POP3
  • Mail::Box::Parser::C

Los nombres de las clases no siempre son ideales: el espacio de nombres 'Mail' en CPAN está bastante lleno.

Las relaciones de clase

Los objetos Mail::Box::Manager desempeñan un papel central en cualquier programa que se construya con MailBox. Cada programa creará un gestor y luego abrirá carpetas a través de ese gestor. Además de las carpetas, el gestor también se puede utilizar para descubrir hilos de mensajes: secuencias de mensajes con sus seguimientos.

                     <tiene-un>      Mail::Box::Mbox
Mail::Box::Manager <---------*    (Mail::Box::MH)
       ^                :         (Mail::Box::Maildir)
       |           (mantiene)    (Mail::Box::POP3)
       |                :
       |                :
       `---------------------*  Mail::Box::Thread::Manager
                    (<tiene-un>)

Cada carpeta mantiene una lista de mensajes. Se hace mucho esfuerzo para ocultar las diferencias entre los tipos de carpetas y los tipos de mensajes. Tu programa puede utilizarse para carpetas MBOX, MH, Maildir y POP3 sin ningún cambio (siempre que te atengas a las reglas).

Mail::Box::Mbox  <-----------* Mail::Box::Mbox::Message
       |             <tiene-un>            |
       | <es-un>                          | <es-un>
       |                                |
   Mail::Box     ............. Mail::Box::Message
                                        |
                                        | <es-un>
                                        |
                                  Mail::Message
                                       / \
                                      <tiene-un>
                                     /     \
                          Mail::Message   Mail::Message
                            ::Body            ::Head

La situación para las carpetas MH y Maildir es un poco más complicada, ya que tienen un nivel adicional de abstracción intermedio: Mail::Box::Dir. La carpeta POP3 tiene una intermedia Mail::Box::Net.

MailBox utiliza activamente la herencia. Para las carpetas, la estructura es exactamente como se muestra para las relaciones de clase de Mensaje:

MB::MH::Message              MB::POP3::Message
MB::Maildir::Message         MB::IMAP4::Message
      \                              /
       \      MB::Mbox::Message     /
        \             |            /
         \    MB::File::Message   /
          \           |          /
    MB::Dir::Message  |   MB::Net::Message
                \     |     /
                 \    |    /
              Mail::Box::Message
                      |
                 Mail::Message

Cualquier Mensaje tiene la estructura de Mail::Message

                              MM::Head::Complete
                                      |
Mail::Message                        es-un
      |                               |
      `---tiene-un---> Mail::Message::Head::Partial
      |             `-- tiene muchos --> MM::Field::Fast
      |             `-- tiene muchos --> MM::Field::Full
      |
      `---tiene-un---> Mail::Message::Body
                    | uno de:
                    `--- MMB::Lines
                    `--- MMB::String
                    `--- MMB::File
                    `--- MMB::Nested
                    |     `--- uno ---> MM:Message
                    `--- MMB::Multipart
                          `--- muchos --> MM::Part
                                   es-un Mail::Message

La cabecera no siempre se conoce completamente, por ejemplo, a través de IMAP o cuando el mensaje se encuentra en un archivo. Básicamente, solo se almacenan en caché los Campos utilizados hasta que se necesita toda la cabecera para adiciones, eliminaciones o cambios.

Los Campos "Completos" tienen un manejo muy detallado y perfecto de los RFC. Los obtendrás a través de los métodos study(). El campo Rápido por defecto es descuidado: solo cadenas de texto.

El Gestor

El gestor de buzones Mail::Box::Manager encapsula los problemas de gestión de carpetas. Mantiene un conjunto de carpetas de correo abiertas (buzones) y proporciona métodos para abrirlas y cerrarlas, mover mensajes eficientemente entre carpetas y añadir mensajes eficientemente a carpetas. Contiene objetos Mail::Box que pueden ser de diferentes tipos. La mayoría de los tipos de carpetas se pueden detectar automáticamente.

El gestor principal también gestiona objetos detectores de hilos de mensajes y les informa cuando el contenido de una carpeta ha cambiado. Esta clase de gestor es la única que instanciarás tú mismo: los objetos de todas las demás clases te serán proporcionados por tu gestor de carpetas.

Se te recomienda encarecidamente que utilices este objeto, pero a menudo puedes prescindir de él y abrir un tipo de carpeta específico directamente.

Los Mensajes

Mail::Message
Una clase base que define una interfaz para manipular la cabecera y el cuerpo de un mensaje. Existen varios tipos de objetos de cabecera (Mail::Message::Head) y un montón de tipos de objetos de cuerpo (Mail::Message::Body).

El paquete Mail::Message::Construct se carga cuando se deben realizar tareas más complejas en los mensajes, como crear respuestas, rebotes o un mensaje reenviado. Estas funcionalidades se describen y implementan en el archivo ::Construct, pero se añaden automáticamente al espacio de nombres Mail::Message cuando se utilizan.

Los tipos de mensajes que son ajenos a MailBox pueden utilizarse en el entorno MailBox: hay algunos convertidores implementados a través de Mail::Message::Convert. En particular, se soportan los populares Mail::Internet y MIME::Entity.

Mail::Box::Message
Una clase base abstracta que define una interfaz para mensajes de correo que se almacenan en cualquier carpeta. Hereda de Mail::Message y añade la idea básica de ubicación a un mensaje.
Mail::Message::Body
Esta es la clase base para todos los cuerpos de mensaje. Describe lo que puedes hacer con cualquier tipo de cuerpo. Los tipos de cuerpo difieren en la forma en que conservan el contenido del cuerpo durante la ejecución de tu programa.

Un caso especial de los tipos de cuerpo es Mail::Message::Body::Multipart, que contiene un conjunto de objetos Mail::Message::Part. Estos son como mensajes normales, excepto que están contenidos en otro mensaje. El tipo de cuerpo Mail::Message::Body::Nested es comparable, pero contiene un solo mensaje: se utilizan para las codificaciones de mensajes "message/rfc822".

Mail::Box-Overview(3pm) — Perl Mail-Box module

NAME

Mail::Box::Overview - Overview of the Mail::Box distribution

DESCRIPTION

This distribution contains a lot of classes that work together. This document gives an overview.

The Message types

Mail::Message
This is the base class for all messages. It provides a standard interface to access the message components (head, body). The message object itself is immutable. All changes result in a new message object.
Mail::Message::Body
The body of a message. This is a list of lines. The lines are stored in Perl objects. The base class has no knowledge of the content. Specific implementations can be created to interpret the content.
Mail::Message::Head
The header for a single message. Maintains a set of Mail::Message::Field objects, each containing one header line. Fields are the only objects which have no logging and tracing facilities, purely for reasons of performance.

The header object has three sub-classes: the Mail::Message::Head::Complete version knows all lines for sure, Mail::Message::Head::Subset maintains an unknown subset of lines, and the Mail::Message::Head::Delayed has no lines yet but knows where to get them.

The latter two will automatically get the missing header lines from the mailbox files when needed, and so transform into a "::Complete" header. It is fully transparent to the user of MailBox in which shape the header really is on the moment.

The Folder types

Mail::Box
A base class that defines a standard interface for mail boxes which is independent of mailbox type. Objects of this class contain a Mail::Box::Locker and a list of Mail::Box::Message objects.
Mail::Box::Dir
The base class for all folders which use a directory organization: each message is a separate entity (file) grouped in a directory. Each Mail::Box::Dir::Message represents one message, one such entity.
Mail::Box::Net
The base class for all folders which have the messages outside direct reach of the MailBox library, for instance on a remote system, or in a database.
Mail::Box::Mbox
This class derives from Mail::Box, and implements its interface for mbox-style folders. It maintains a set of Mail::Box::Mbox::Message objects, which are derived from a Mail::Box::Message.

Mbox-style folders have one file containing multiple messages per folder. When folders get large, access tends to get slow.

Mail::Box::MH
This class derives from Mail::Box::Dir, and implements its interface for MH-style folders. It maintains a set of Mail::Box::MH::Message objects, which are derived from a Mail::Box::Dir::Message.

MH-style folders are represented by a directory, where each message is stored in a separate file. The message files are sequentially numbered. It is fast to open one single message, but hard to get an overview.

Mail::Box::MH::Index
The base class for MH mailbox indexes which provides methods for reading, writing, and managing message indexes. These indexes are used to speed-up access to directory based folders.
Mail::Box::MH::Labels
Also for efficiency reasons, a separate file is maintained which contains flags about the messages. This file for instance lists new files. This way, the MH message files do not have to be opened to find that out.
Mail::Box::Maildir
Like the MH folder type, this class derives from Mail::Box::Dir. It implements its interface for Maildir-style folders. It maintains a set of Mail::Box::Maildir::Message objects, which are derived from a Mail::Box::Dir::Message.
Mail::Box::POP3
Implements the POP3 protocol based on Mail::Box::Net. The Mail::Transport::POP3 implementation handles the protocol details. In this kind of folders, you can only read and delete messages.

Various Other Classes

Mail::Box::Thread::Manager
Maintains a set of message-threads over one or more folders. A message-thread is a start message with all the replies on it. And the replies on replies, and so on. This object is used to construct the thread for a set of open folders.

This object maintains linked lists of Mail::Box::Thread::Node objects. Mail::Message::Dummy's fill-up some holes.

Mail::Box::Locker
Provides a folder locking interface which is inherited by the Mail::Box class. Currently it supports dot-file locking ("filename.lock"), flock filehandle locking, and locking over NFS. Each is implemented in a separate class. A multi-locker, using a set of lock-methods at the same time is also available.
Mail::Box::Search
The set of search packages implement various search techniques in an uniformal way. Although implementing your own search algorithm is simple in general, in practice multiparts, encodings, and mime-types complicate things.
Mail::Box::Parser
The parser reads messages, and transforms them into data-structures such that the content of header and body can be used within the program. The first parser is implemented in pure Perl. A second parser is under development, and will written in C, to gain speed.
Mail::Box::Tie
Provides hash (Mail::Box::Tie::HASH) or array tied (Mail::Box::Tie::ARRAY) access to any mail folder derived from Mail::Box. This beautifies your code in some applications.
Mail::Transport
Various ways of sending and receiving messages are implemented. Sending is possible via external programs, like "mail", "Mailx", "sendmail", or autonomously with direct SMTP. Receiving is currently only implemented via POP3.
Mail::Reporter
A debugging and logging class which is inherited by most of the Mail:: modules. For each object, you can say what log and error reports must be kept or directly presented to the user. This way you can decide to have Mail::Box report about problems, or do it all yourself.

All classes are written to be extensible.
