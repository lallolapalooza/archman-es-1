Mail::Box::Manager(3) Documentación contribuida por usuarios de Perl Mail::Box::Manager(3)

NOMBRE

Mail::Box::Manager - gestionar una serie de carpetas

HEREDAD

Mail::Box::Manager
  es un Mail::Reporter
Mail::Box::Manager es extendido por
  Mail::Box::Manage::User

SINOPSIS

use Mail::Box::Manager;
my $mgr     = new Mail::Box::Manager;
# Crear objetos de carpeta.
my $folder   = $mgr->open(folder => $ENV{MAIL});
my $message1 = $folder->message(0);
$mgr->copyMessage('Draft', $message);
my @messages = $folder->message(0,3);
$mgr->moveMessage('Outbox', @messages, create => 1 );
$mgr->close($folder);
# Crear detectores de hilos (ver Mail::Box::Thread::Manager)
my $t       = $mgr->discoverThreads($inbox, $outbox);
my $threads = $mgr->discoverThreads(folder => $folder);
foreach my $thread ($threads->all)
{   $thread->print;
}
$mgr->registerType(mbox => 'Mail::Box::MyType');

DESCRIPCIÓN

El gestor mantiene el seguimiento de carpetas abiertas y objetos de mensaje-hilo. No es obligatorio usar este objeto (puedes crear directamente una Mail::Box::Mbox si lo prefieres), pero crearás código más portátil y seguro si lo haces.

Agrega uno o más nuevos tipos de carpeta @typedefs a la lista de tipos conocidos. El orden es importante: cuando abres un archivo sin especificar su tipo, el gestor comenzará probando primero el último listado de tipos agregado.

El directorio, o directorios, donde están las carpetas. El gestor "Mail::Box::Manager" puede autodetectar los tipos de carpeta existentes. Gestionar carpetas abiertas

$obj->close($folder, %options)
Quita la carpeta especificada del índice de carpetas abiertas. Indirectamente, actualizará los archivos en disco si es necesario (depende de la flag Mail::Box::new(save_on_exit) para cada carpeta). Las opciones %options se pasan a Mail::Box::close() de la carpeta.

También se pueden cerrar la carpeta directamente. El gestor se informará sobre este evento y tomará acciones adecuadas.

-Opción       --Valor por defecto
 close_by_self  <C<false>>
close_by_self => BOOLEAN
Usada internamente para evitar confusiones sobre cómo se inició el cierre. No cambies esto.

ejemplo:

my $inbox = $mgr->open('inbox');
$mgr->close($inbox);
$inbox->close;        # alternativa
$obj->closeAllFolders(%options)
"closeAllFolders" llama a close() para cada carpeta gestionada por este objeto. Se llama justo antes de que el programa termine (antes de la limpieza global).
$obj->isOpenFolder($folder)
Devuelve "true" si la carpeta $folder está actualmente abierta.
$obj->open( [$foldername], %options )
Abre una carpeta cuyo nombre se especifica como primer parámetro o con la opción de flag "folder". El tipo de carpeta se autodetecta, no se especifica el "type".

El "open" acepta opciones para el gestor, que se describen aquí, pero también puede tener opciones adicionales para el tipo de carpeta. Para una descripción de las opciones de carpeta, consulta las opciones del constructor Mail::Box::new() para cada tipo de carpeta de correo.

-Opción      --Valor por defecto
 authenticate  'AUTO'
 create        false
 folder        $ENV{MAIL}
 folderdir     '.'
 type          <primero, usualmente 'mbox'>
authenticate => $type|\@types|'AUTO'
El autenticado del Mail::Box::Manager se ejecuta automáticamente, pero se puede especificar. La opción "authenticate" se usa para determinar el tipo de carpeta que se usará.

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

$type de autenticación a utilizar, o un ARRAY de @types que el cliente prefiere. El servidor puede proporcionar preferencias también, y ese orden se mantendrá. Esta opción solo es compatible con un pequeño subconjunto de tipos de carpetas, especialmente con POP e IMAP.
create => BOOLEAN
Crea la carpeta si no existe. Por defecto, esto no se hace. La opción "type" especifica qué tipo de carpeta se crea.
folder => $name|$url
Qué carpeta abrir, especificada por $name o $url especial. El formato de URL se compone como 
type://username:password@hostname:port/foldername

Al igual que las URL reales, todos los campos son opcionales y tienen valores predeterminados inteligentes, siempre que la cadena comience con un tipo de carpeta conocido. No todos los tipos de carpetas admiten todas estas opciones, pero al menos se separan. Tenga en cuenta que los caracteres especiales en la contraseña deben estar correctamente codificados en la URL.

Cuando especifica algo que no coincide con el formato de URL, se pasa directamente al método "new" de la carpeta que se abre.

folderdir => DIRECTORY
El directorio donde se suelen almacenar las carpetas.
type => $foldertypename|$foldertype
Especifica el tipo de carpeta. Si no especifica esta opción al abrir una carpeta para lectura, el administrador verifica todos los tipos de carpetas registrados en orden para poder abrir la carpeta. Si abre una carpeta nueva para escritura, el valor predeterminado será el tipo registrado más recientemente. (Si agrega más de un tipo a la vez, se utiliza el primero de la lista).

Actualmente, los tipos son "mbox", "mh", "maildir", "pop3", "pop3s", "imap4", y "imap4s". También puede usar los nombres "pop", "pops", "imap", y "imaps".

» ejemplo: abrir carpetas a través del administrador

my $jack  = $manager->open(folder => '=jack', type => 'mbox');
my $rcvd  = $manager->open('myMail',
   type => 'Mail::Box::Mbox', access => 'rw');
my $inbox = $manager->open('Inbox')
   or die "No se puede abrir la Bandeja de entrada.\n";
my $pop   = 'pop3://myself:secret@pop3.server.com:120/x';
my $send  = $manager->open($url);
my $send  = $manager->open(folder => '/x',
  type => 'pop3', username => 'myself', password => 'secret'
  server_name => 'pop3.server.com', server_port => '120');
$obj->openFolders()
Devuelve una lista de todas las carpetas abiertas.

Gestionar carpetas existentes

$obj->delete($foldername, %options)
Elimina la carpeta nombrada. Las %options son las mismas que para open().

La eliminación de una carpeta puede llevar tiempo. Dependiendo del tipo de carpeta, la carpeta debe leerse primero. Para algunos tipos de carpetas, esto será rápido.

-Option   --Default
 recursive  <predeterminado de la carpeta>
recursive => BOOLEAN
Algunas carpetas solo se pueden eliminar recursivamente, otras tienen más flexibilidad.

Mover mensajes a carpetas

$obj->appendMessage( [$folder|$foldername], $messages, %options )
Agrega uno o más mensajes a una carpeta (por lo tanto, también se define appendMessages()). Puede especificar un $foldername o una carpeta abierta como primer argumento. Cuando el nombre es el de una carpeta abierta, se trata como si se especificara el objeto carpeta, y no se accede directamente a los archivos de la carpeta. También puede especificar el nombre de la carpeta como parte de la lista de opciones.

Si se agrega un mensaje a una carpeta ya abierta, solo se agrega a la estructura internamente en el programa. Los datos no se escribirán en disco hasta que se realice una escritura de esa carpeta. Cuando se da el nombre de una carpeta no abierta, la carpeta se abre, los mensajes se almacenan en disco y luego la carpeta se cierra.

Un mensaje debe ser una instancia de Mail::Message. El tipo de mensaje real no tiene por qué coincidir con el tipo de carpeta; la carpeta intentará resolver las diferencias con una pérdida mínima de información. Los mensajes transformados (cómo se escribieron realmente) se devuelven como una lista.

Las %options son una lista de clave/valor, que se agregan a (anulando) las opciones predeterminadas para el tipo de carpeta detectado.

» ejemplo:

$mgr->appendMessage('=send', $message, folderdir => '/');
$mgr->appendMessage($received, $inbox->messages);
my @appended = $mgr->appendMessages($inbox->messages, folder => 'Drafts');
$_->label(seen => 1) for @appended;
$obj->copyMessage( [$folder|$foldername], @messages, %options )
Copia @messages de una carpeta a otra. Si la carpeta de destino ya está abierta, se utiliza Mail::Box::copyTo(). De lo contrario, se llama a Mail::Box::appendMessages().

Debe especificar el nombre de una carpeta o un objeto carpeta como primer argumento, o en la lista de opciones. Las opciones son las mismas que las que se pueden especificar al abrir una carpeta.

-Option--Default
 share   false
share => BOOLEAN
Intenta compartir el almacenamiento físico de los mensajes. Los tipos de carpetas pueden ser diferentes, pero todo depende de la carpeta real a la que se copia el mensaje. Se ignora silenciosamente cuando no es posible compartir.

» ejemplo:

my $drafts = $mgr->open(folder => 'Drafts');
my $outbox = $mgr->open(folder => 'Outbox');
$mgr->copyMessage($outbox, $drafts->message(0));
my @messages = $drafts->message(1,2);
$mgr->copyMessage('=Trash', @messages,
   folderdir => '/tmp', create => 1);
$mgr->copyMessage($drafts->message(1), create => 1,
   folder => '=Drafts' folderdir => '/tmp');
$obj->moveMessage( [$folder|$foldername], @messages, %options )
Mueve @message de una $folder a otra.

TENGA EN CUENTA que las eliminaciones de una carpeta solo se realizan cuando la carpeta se cierra, por lo que el mensaje solo se marca para ser eliminado en la carpeta de origen abierta.

TENGA EN CUENTA que las etiquetas de los mensajes pueden perderse cuando un mensaje se mueve de un tipo de carpeta a otro. Se intenta traducir las etiquetas, pero hay muchas diferencias en la interpretación por parte de las aplicaciones.

$mgr->moveMessage($received, $inbox->message(1))

es equivalente a

 $mgr->copyMessage($received, $inbox->message(1), share => 1);
 $inbox->message(1)->delete;
-Option--Default
 share   true
share => BOOLEAN

-Option --Default

» ejemplo:

DETALLES

En muchos lugares de la documentación se puede leer que es útil tener un objeto gestor. Hay dos de ellos: el Mail::Box::Manager, que mantiene un conjunto de carpetas abiertas, y una extensión del mismo: el Mail::Box::Manage::User.

Gestión de carpetas abiertas

Es útil comenzar su programa creando un objeto gestor de carpetas, un Mail::Box::Manager. El objeto se encarga de algunas cargas:

  • autodetectar el tipo de carpeta que se está utilizando.

    • Esto significa que su aplicación puede ser completamente independiente del tipo de carpeta.

  • cargar automáticamente los módulos requeridos

    • Hay tantos módulos involucrados en MailBox que es útil tener una carga perezosa de código. El gestor sabe qué módulos pertenecen a cada tipo de carpeta.

  • evitar aperturas duplicadas

    • Los errores de programación pueden hacer que la misma carpeta se abra dos veces. El resultado podría ser muy destructivo. Por lo tanto, el gestor realiza un seguimiento de todas las carpetas abiertas y evita que la misma carpeta se abra por segunda vez.

  • cerrar carpetas al limpiar

    • Cuando el programa finaliza, el gestor cerrará limpiamente todas las carpetas que aún estén abiertas. Esto es necesario, ya que la secuencia de autodestrucción de Perl funciona en un orden impredecible.

  • detección de hilos de mensajes

    • MailBox puede descubrir hilos de mensajes que abarcan múltiples carpetas. Cualquier conjunto de carpetas abiertas puede agruparse en un árbol de respuestas sobre respuestas sobre respuestas. Cuando se cierra una carpeta, se eliminará automáticamente de los hilos, y una nueva carpeta se puede agregar dinámicamente a la estructura.

El gestor realmente simplifica las cosas y, por lo tanto, debería ser la base de todos los programas. Sin embargo, es posible escribir programas útiles sin él.

Gestión de un usuario

Un paso más allá es el objeto Mail::Box::Manage::User (desde MailBox v2.057), que no solo rastrea las carpetas abiertas, sino que también recopila información sobre las carpetas no abiertas.

La clase de usuario, como su nombre indica, está dirigida a la gestión de un solo usuario. Donde Mail::Box::Manager abrirá cualquier conjunto de archivos de carpetas, probablemente de varios usuarios, la clase de usuario desea un directorio raíz de carpetas.

En muchos aspectos, el gestor de usuarios simplifica la tarea para servidores basados en usuarios y otras aplicaciones centradas en el usuario al establecer valores predeterminados inteligentes.

DIAGNÓSTICOS

Error: La carpeta $name ya está abierta.
No se puede solicitar al gestor una carpeta que ya está abierta. En algunas versiones anteriores (antes de MailBox 2.049), esto estaba permitido, pero el comportamiento cambió, ya que se esperan muchos efectos secundarios desagradables. Por ejemplo, un Mail::Box::update() en un manejador de carpetas influiría en el segundo, probablemente de forma inesperada. Lanzado por open()
Error: La carpeta $name no es un Mail::Box; no se puede agregar un mensaje.
La carpeta donde se debe adjuntar el mensaje es un objeto que no es un tipo de carpeta que extienda Mail::Box. Probablemente, ni siquiera es una carpeta. Lanzado por appendMessage()
Advertencia: La carpeta no existe, no se pudo abrir la carpeta $type $name.
La carpeta no existe y no se permite su creación (ver open(create)) o no tuvo éxito. Si no tiene derechos de acceso suficientes a la carpeta (por ejemplo, contraseña incorrecta para POP3), esta advertencia también se producirá.

El gestor intentó abrir una carpeta del tipo especificado. Puede ser útil especificar explícitamente el tipo de su carpeta con la opción "type". Probablemente habrá otra advertencia o mensaje de error relacionado con este informe que proporcionará más detalles sobre su causa. También puede echar un vistazo a new(autodetect) y new(folder_types). Lanzado por open()

Advertencia: El tipo de carpeta $type es desconocido, se usará la autodetección.
El tipo de carpeta especificado (ver open(type), posiblemente derivado del nombre de la carpeta cuando se especifica como URL) no es conocido por el gestor. Esto puede significar que olvidó requerir la extensión Mail::Box que implementa este tipo de carpeta, pero probablemente sea un error tipográfico. Por lo general, el gestor es capaz de averiguar qué tipo usar por sí mismo. Lanzado por open()
Error: URL de carpeta ilegal '$url'.
El nombre de la carpeta se especificó como URL, pero no según la sintaxis. Consulte decodeFolderURL() para obtener una descripción de la sintaxis. Lanzado por open()
Error: No se especificó nombre de carpeta para abrir.
open() necesita un nombre de carpeta como primer argumento (antes de la lista de opciones), o con la opción "folder" dentro de la lista. Si no se encontró ningún nombre, se verifica la variable de entorno MAIL. Si ni siquiera eso da como resultado una carpeta utilizable, entonces se produce este error. El error puede ser causado por una lista de opciones de longitud impar accidental. Lanzado por open()
Error: El paquete $package no implementa $method.
Error fatal: el paquete específico (o una de sus superclases) no implementa este método donde debería. Este mensaje significa que otras clases relacionadas implementan este método, pero la clase en cuestión no. Probablemente debería investigar esto y probablemente informar al autor del paquete. Lanzado por notImplemented()
Error: Use appendMessage() para agregar mensajes que no están en una carpeta.
No necesita copiar este mensaje en la carpeta, ya que no comparte el mensaje entre carpetas. Lanzado por copyMessage()
Advertencia: Use moveMessage() o copyMessage() para mover entre carpetas abiertas.
El mensaje ya forma parte de una carpeta y ahora debe adjuntarse a una carpeta diferente. Debe decidir entre copiar o mover, ambos clonarán el mensaje (no el cuerpo, ya que son inmutables). Lanzado por appendMessage()
Advertencia: Nunca se creará una carpeta $name sin tener acceso de escritura.
Ha establecido open(create), pero solo quiere leer la carpeta. Crear solo es útil para carpetas que tienen modos de acceso de escritura o adjuntar (ver Mail::Box::new(access)). Lanzado por open()
