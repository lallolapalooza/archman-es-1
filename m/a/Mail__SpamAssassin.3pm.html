NOMBRE

Mail::SpamAssassin - Motor de detección y marcado de spam

SINOSIS

my $spamtest = Mail::SpamAssassin->new();
my $mail = $spamtest->parse($message);
my $status = $spamtest->check($mail);
if ($status->is_spam()) {
  $message = $status->rewrite_mail();
}
else {
  ...
}
...
$status->finish();
$mail->finish();
$spamtest->finish();

DESCRIPCIÓN

Mail::SpamAssassin es un módulo para identificar spam utilizando varios métodos, incluyendo análisis de texto, listas de bloqueo en tiempo real basadas en internet, análisis estadístico y algoritmos de hash basados en internet.

Usando su base de reglas, emplea una amplia gama de pruebas heurísticas en las cabeceras y el cuerpo del correo para identificar el "spam", también conocido como correo masivo no solicitado. Una vez identificado como spam, el correo puede ser etiquetado como spam para su posterior filtrado utilizando la aplicación del agente de usuario de correo propio del usuario o en el agente de transferencia de correo.

Si desea utilizar una herramienta de filtrado de línea de comandos, pruebe las herramientas "spamassassin" o "spamd"/"spamc" proporcionadas.

MÉTODOS

$t = Mail::SpamAssassin->new( { opt => val, ... } )
Construye un nuevo objeto "Mail::SpamAssassin". Puede pasar una referencia a un hash al constructor que puede contener los siguientes pares de atributo-valor.
debug
Estas son las opciones de depuración utilizadas para determinar el nivel de registro. Existe para permitir que se habiliten o deshabiliten secciones de mensajes de depuración (llamadas "instalaciones"). Si es una cadena, se trata como una lista separada por comas de las instalaciones de depuración. Si es una referencia a un hash, entonces las claves se tratan como la lista de instalaciones de depuración y si es una referencia a un array, entonces los elementos se tratan como la lista de instalaciones de depuración.

También hay dos casos especiales: (1) si el caso especial de "info" se pasa como una instalación de depuración, entonces todos los mensajes informativos se habilitan; (2) si el caso especial de "all" se pasa como una instalación de depuración, entonces todas las instalaciones de depuración se habilitan.

rules_filename
El nombre de archivo/directorio desde donde cargar las reglas de identificación de spam. (opcional)
site_rules_filename
El nombre de archivo/directorio desde donde cargar las reglas de identificación de spam específicas del sitio. (opcional)
userprefs_filename
El nombre de archivo desde donde cargar las preferencias. (opcional)
userstate_dir
El directorio donde se almacena el estado del usuario. (opcional)
config_tree_recurse
Establecer en 1 para recorrer recursivamente los directorios al leer archivos de configuración, en lugar de leer solo un nivel. (opcional, por defecto 0)
config_text
El texto de todas las reglas y preferencias. Si prefiere no cargar las reglas de archivos, léalas usted mismo y establezca esto en su lugar. Como resultado, esto anulará la configuración de "rules_filename", "site_rules_filename" y "userprefs_filename".
pre_config_text
Similar a "config_text", este texto se coloca antes de config_text para permitir una anulación de los archivos de configuración.
post_config_text
Similar a "config_text", este texto se coloca después de config_text para permitir una anulación de los archivos de configuración.
force_ipv4
Si se establece en 1, las pruebas de DNS u otras pruebas de red preferirán IPv4 y no intentarán utilizar IPv6. Úselo si las pruebas existentes para la disponibilidad de IPv6 producen resultados incorrectos o fallos.
force_ipv6
Para simetría con force_ipv4: si se establece en 1, las pruebas de DNS u otras pruebas de red preferirán IPv6 y no intentarán utilizar IPv4. Algunos complementos pueden ignorar esta configuración y utilizar la familia de protocolos con la que se sientan cómodos.
require_rules
Si se establece en 1, init() fallará si no se pudieron cargar reglas válidas. Este es el comportamiento predeterminado cuando es llamado por "spamassassin" o "spamd".
languages_filename
Si desea poder utilizar la regla de adivinación de idioma "UNWANTED_LANGUAGE_BODY", y está utilizando "config_text" en lugar de "rules_filename", "site_rules_filename" y "userprefs_filename", necesitará establecer esto. Debería ser la ruta al archivo languages que normalmente se encuentra en el directorio rules de SpamAssassin.
local_tests_only
Si se establece en 1, no se realizarán pruebas que requieran acceso a internet. (por defecto: 0)
need_tags
La opción proporciona una forma de evitar un procesamiento más costoso cuando se sabe de antemano que cierta información no será necesaria para un llamador.

El valor de la opción puede ser una cadena (una lista separada por comas de nombres de etiquetas) o una referencia a una lista de nombres de etiquetas individuales. Un llamador puede proporcionar la lista de antemano, especificando su intención de recopilar más tarde la información a través de llamadas a $pms->get_tag(). Si el nombre de una etiqueta comienza con 'NO' (sin distinguir mayúsculas y minúsculas), indica que un llamador no estará interesado en dicha etiqueta, aunque no hay garantía de que esto ahorre recursos, ni de que el valor de la etiqueta esté vacío. Actualmente, ninguna etiqueta integrada comienza con 'NO'. Una entrada posterior anula la anterior, por ejemplo, ASN,NOASN,ASN,TIMING,NOASN es equivalente a TIMING,NOASN.

Para compatibilidad con versiones anteriores, todas las etiquetas disponibles a partir de la versión 3.2.4 estarán disponibles por defecto (a menos que se deshabiliten con NOtag), incluso si no se solicitan a través de la opción need_tags. Las versiones futuras pueden proporcionar nuevas etiquetas disponibles condicionalmente.

Actualmente, la única etiqueta que debe solicitarse explícitamente es 'TIMING'. No solicitarla puede ahorrar uno o dos milisegundos; sirve principalmente para ilustrar el uso de need_tags.

Ejemplo:
need_tags => 'TIMING,noLANGUAGES,RELAYCOUNTRY,ASN,noASNCIDR', o:
need_tags => [qw(TIMING noLANGUAGES RELAYCOUNTRY ASN noASNCIDR)],

ignore_site_cf_files
Si se establece en 1, se ignorarán todos los archivos de reglas que se encuentren en el directorio "site_rules_filename". Los archivos *.pre (utilizados para cargar complementos) que se encuentren en el directorio "site_rules_filename" seguirán utilizándose. (por defecto: 0)
dont_copy_prefs
Si se establece en 1, el archivo de preferencias del usuario no se creará si no existe. (por defecto: 0)
save_pattern_hits
Si se establece en 1, los patrones que coinciden se pueden recuperar del objeto "Mail::SpamAssassin::PerMsgStatus". Se utiliza para depuración.
home_dir_for_helpers
Si se establece, la variable de entorno HOME se establecerá en este valor al utilizar aplicaciones de prueba que requieran sus datos de configuración, como Razor, Pyzor y DCC.
username
Si se establece, el atributo "username" utilizará este como el nombre del usuario actual. De lo contrario, el valor predeterminado se toma del entorno de ejecución (es decir, la UID efectiva de este proceso bajo UNIX).

parse($message, $parse_now [, $suppl_attrib])
Parses the message and returns a "Mail::SpamAssassin::Message" object with just the headers parsed. When this function is called, there are two optional parameters that can be passed: $message is, by default, undefined (which will use STDIN), a scalar - a string containing a full message, a reference to such a string, an array ref to a message with one line per element, or a glob reference or IO::File object containing the entire message content; and $parse_now, which specifies whether or not to build a MIME tree at parse time or later, as needed.

The $parse_now parameter defaults to false (0). This allows SpamAssassin to not have to build the internal node tree if the information will not be used. This is useful, for example, when running "spamassassin -d", which only needs the raw header and body, which is always parsed and stored by this function.

The optional $suppl_attrib parameter allows a caller to pass additional information about a message to SpamAssassin. It defaults to undefined, or a reference to a hash where each key-value pair provides some additional attributes of the message, typically information that cannot be inferred from the message itself, or is difficult to do so, or would represent unnecessary work for SpamAssassin to obtain. The argument is stored in the "Mail::SpamAssassin::Message" object as "suppl_attrib", thus accessible to the rest of the code and to plugins. The exact list of attributes may evolve over time, and any unknown attributes should be ignored. Examples of attributes include: SMTP send-to information, a flag that a message provided by a caller was truncated due to size limit, an already-verified list of DKIM signature objects, or perhaps a list of pre-scored rule hits from a caller, representing another way for a caller to provide meta-information (instead of having to insert bogus headers to pass info), or perhaps just pure rule hits.

For more information, please see the documentation for "Mail::SpamAssassin::Message" and "Mail::SpamAssassin::Message::Node".

$status = $f->check ($mail)
Checks a message, encapsulated in a "Mail::SpamAssassin::Message" object, to determine if it is spam or not.

Returns a "Mail::SpamAssassin::PerMsgStatus" object that can be used to test or manipulate the message.

Note: The "Mail::SpamAssassin" object can be reused for subsequent messages without affecting this check; in OO terminology, the "Mail::SpamAssassin" object is a "factory".

$status = $f->check_message_text ($mailtext)
Checks a message, encapsulated in a plain text string $mailtext, to determine if it is spam or not.

This is identical to the check() function above.

$status = $f->learn ($mail, $id, $isspam, $forget)
Learns from a message, encapsulated in a "Mail::SpamAssassin::Message" object.

If $isspam is defined, the message is assumed to be spam, otherwise it will be learned as not spam.

If $forget is defined, the message attributes will be removed from both the spam and not-spam learning databases.

The $id is an optional message identification string, used internally for tagging the message. If it is "undef", the message-Id from the message will be used. It should be unique to this message.

Returns a "Mail::SpamAssassin::PerMsgLearner" object that can be used to manipulate the learning process for each message.

Note: The "Mail::SpamAssassin" object can be reused for subsequent messages without affecting this check; in OO terminology, the "Mail::SpamAssassin" object is a "factory".

learn() and check() can be run with the same factory. You must call init_learner() before using this function.

$f->report_as_spam ($mail, $options)
Informa un correo, encapsulado en un objeto "Mail::SpamAssassin::Message", como spam verificado por humanos. Esto enviará el mensaje de correo a bases de datos de bloqueo de spam en vivo y colaborativas, permitiendo que otros usuarios bloqueen este mensaje.

También enviará el correo al aprendiz bayesiano de SpamAssassin.

Opciones es una referencia opcional a un hash de opciones. Actualmente, estas pueden ser:

dont_report_to_pyzor
Inhibe el informe de spam a Pyzor.
dont_report_to_razor
Inhibe el informe de spam a Razor.
dont_report_to_spamcop
Inhibe el informe de spam a SpamCop.
$f->revoke_as_spam ($mail, $options)
Revoca un correo, encapsulado en un objeto "Mail::SpamAssassin::Message", como correo no deseado (no spam) verificado por humanos. Esto revocará el mensaje de correo de las bases de datos de bloqueo de spam colaborativas y en vivo, permitiendo que otros usuarios bloqueen este mensaje.

También enviará el correo al aprendiz bayesiano de SpamAssassin como no spam.

Opciones es una referencia opcional a un hash de opciones. Actualmente, estas pueden ser:

dont_report_to_razor
Inhibe la revocación de spam a Razor.

$f->read_scoreonly_config ($filename)
Lee un archivo de configuración y analiza las preferencias del usuario a partir de él.

$f->compile_now ($use_user_prefs, $keep_userstate)
Compila todos los patrones, carga todos los archivos de configuración y carga todos los módulos Perl posiblemente requeridos.

Normalmente, Mail::SpamAssassin utiliza la evaluación perezosa cuando es posible, pero si planea usar fork() o iniciar un nuevo hilo de intérprete Perl para procesar un mensaje, esto no es óptimo, ya que cada proceso/hilo tendrá que realizar estas acciones.

Llame a esta función en el hilo o proceso principal para realizar las acciones de inmediato, de modo que los subprocesos no tengan que hacerlo.

Si $use_user_prefs es 0, esto inicializará la configuración de SpamAssassin sin leer el archivo de configuración por usuario y asumirá que llamará a "read_scoreonly_config" en un momento posterior.

Si $keep_userstate es verdadero, compile_now() revertirá cualquier opción de configuración que tenga un valor predeterminado con __userstate__ después de init(), y luego volverá a cambiar la opción antes de regresar. Esto le permite cambiar $ENV{'HOME'} a un directorio temporal, hacer que compile_now() cree los archivos necesarios allí sin alterar los archivos reales tal como fueron modificados por una opción de configuración. Por defecto, esto está deshabilitado.

$f->copy_config ( [ $source ], [ $dest ] )
Se utiliza para que los demonios mantengan la configuración de un objeto Mail::SpamAssassin persistente correcta si cambian entre usuarios. Pase una referencia a un array asociativo como $source o $dest, y establezca el otro en 'undef' para que el objeto utilice su configuración actual. Es decir: 
# crea objeto con configuración
my $spamtest = Mail::SpamAssassin->new( ... );
# respalda la configuración en %conf_backup
my %conf_backup;
$spamtest->copy_config(undef, \%conf_backup) ||
  die "config: error returned from copy_config!\n";
... haz cosas, quizás modifica la configuración, etc ...
# restaura la configuración original
$spamtest->copy_config(\%conf_backup, undef) ||
  die "config: error returned from copy_config!\n";

Nota: el contenido de los arrays asociativos debe ser considerado opaco por el código que llama.
