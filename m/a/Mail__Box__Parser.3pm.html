SYNOPSIS

El objeto no se instancia por sí mismo

DESCRIPCIÓN

El "Mail::Box::Parser" gestiona la lectura de carpetas. Normalmente, no necesitas saber nada sobre este módulo, excepto las opciones que están relacionadas con este código.

Actualmente hay tres implementaciones de este módulo:

  • Mail::Box::Parser::C

    Un parser rápido escrito en "C". Este paquete está disponible como módulo independiente en CPAN, debido a que la distribución del módulo a través de CPAN no puede manejar archivos XS que no estén en la raíz del árbol del módulo. Si tienes un compilador de C disponible en tu sistema, se usará automáticamente.

  • Mail::Box::Parser::Perl

    Un parser más lento cuando el mensaje está en un archivo, como mbox, que solo utiliza Perl. Este módulo es ligeramente más lento y realiza menos verificaciones y recuperaciones.

  • Mail::Box::Parser::Lines

    Útil cuando el mensaje ya está en memoria. Si planeas usarlo tú mismo, probablemente necesitarás usar Mail::Message::Construct::Read.

$any->defaultParserType( [$class] )
Devuelve el parser que se usará para parsear todos los siguientes mensajes, posiblemente estableciendo el parser usando el argumento opcional. En general, el parser se autodetecta; el parser basado en "C" se usará cuando sea posible, y el parser basado en Perl se usará de lo contrario.

Parsing

$obj->bodyAsFile( $fh [$chars, [$lines]] )
Intenta leer el cuerpo de un mensaje desde el archivo, y escribe inmediatamente el cuerpo en el archivo de salida. Opcionalmente, se puede pasar el número de caracteres predicho y/o líneas predichas que se leerán. Estos valores pueden ser "undef" y pueden estar equivocados.

El retorno es una lista de tres escalares: la ubicación del cuerpo (comienzo y fin) y el número de líneas en el cuerpo.

$obj->bodyAsList( [$chars, [$lines]] )
Intenta leer el cuerpo de un mensaje desde el archivo. Opcionalmente, se puede pasar el número de caracteres predicho y/o líneas predichas que se leerán. Estos valores pueden ser "undef" y pueden estar equivocados.

El retorno es una lista de escalares, cada uno conteniendo una línea (incluyendo el separador de línea), precedidos por dos enteros que representan la ubicación en el archivo donde esta parte del cuerpo comenzó y terminó.

$obj->bodyAsString( [$chars, [$lines]] )
Intenta leer el cuerpo de un mensaje desde el archivo. Opcionalmente, se puede pasar el número de caracteres predicho y/o líneas predichas que se leerán. Estos valores pueden ser "undef" y pueden estar equivocados.

El retorno es una lista de tres escalares: la ubicación en el archivo donde comienza el cuerpo, donde termina el cuerpo y el string completo del cuerpo.

$obj->bodyDelayed( [$chars, [$lines]] )
Intenta leer el cuerpo de un mensaje desde el archivo, pero el dato se descarta. Opcionalmente, se puede pasar el número de caracteres predicho y/o líneas predichas que se descartan. Estos valores pueden ser "undef" y pueden estar equivocados.

El retorno es una lista de cuatro escalares: la ubicación del cuerpo (comienzo y fin), el tamaño del cuerpo y el número de líneas en el cuerpo. El número de líneas puede ser "undef".

$obj->lineSeparator()
Devuelve el carácter o caracteres que se utilizan para separar las líneas en el archivo de carpeta. Esto se basa en la primera línea del archivo. Los sistemas UNIX usan una sola LF para separar las líneas. Las máquinas Windows usan un CR y una LF. El Mac usa un CR.
$obj->readHeader()
Lee todo el encabezado del mensaje y lo devuelve como una lista de pares de campo-valor. Debe tener en cuenta que algunos campos pueden aparecer más de una vez.

El primer elemento representa la ubicación en el archivo donde comienza el encabezado. La siguiente es la lista de campos de encabezado y sus valores.

Ejemplo:

my ($where, @header) = $parser->readHeader;
$obj->stop()
Detiene el parser.

Administrando separadores

Los diversos métodos de "separadores" se usan por Mail::Message::Body::Multipart para detectar partes, y por los carpetas basadas en archivos para marcar dónde comienza una nueva mensaje.

$obj->activeSeparator()
$obj->popSeparator()
Quita el separador más reciente de la lista mantenida por el parser. Esta función devuelve "undef" cuando no hay más separadores.
$obj->pushSeparator(STRING|Regexp)
Añade una línea de separador. Los separadores indican a el parser dónde detener la lectura. Una línea famosa es la línea "From", que se usa en carpetas de tipo Mbox para separar mensajes. Sin embargo, también se usan los separadores para dividir mensajes en partes (archivos adjuntos).

El especificado "STRING" se usa como la línea de separador.

NAME

Mail::Box::Parser - parse mail messages

INHERITANCE

Extends Mail::Message::Parser.

SYNOPSIS

  use Mail::Box::Parser;

  my $parser = Mail::Box::Parser->new('filename' => '~/mail/inbox');
  my @messages = $parser->messages;
  for my $message (@messages) {
    print $message->subject, "\n";
  }

  # Using a file handle
  open my $fh, "<", $filename or die "$filename: $!";
  my $parser = Mail::Box::Parser->new(file => $fh);
  my @messages = $parser->messages;
  close $fh;

  # Process one message
  my $parser = Mail::Box::Parser->new(file => $fh);
  my $message = $parser->next;
  if ($message) {
    print $message->from, "\n";
  }

DESCRIPTION

This is a parser for mail messages. It supports the parsing of messages from a file, a directory of files, or an array of strings.

The parser processes the messages in FIFO order. Each message is parsed into a Mail::Message object.

Separators

A separator is a line that marks the end of one message and the start of another. When processing a mailbox file, messages are typically separated by lines starting with characters like "From". The Mail::Box::Parser can be configured to recognize custom separators.

The default separator is a line starting with "From " followed by a space. This is a common format for Unix mailbox files. You can change this by passing a separator option to new():

  my $parser = Mail::Box::Parser->new(
      filename => '~/mail/inbox',
      separator => qr/^-- message (\d+) --$/,
  );

If the separator is a string, it must match the start of the line exactly. If it is a regular expression, it must match the entire line.

METHODS

$obj->new( [...options] )
Constructor for the parser. See Mail::Message::Parser for details.
$obj->addSeparator($regex)
Add a new separator pattern. The pattern is a regular expression that describes the start of the separator-line. The Regexp can specify a more complicated format.

$obj->readSeparator(%options)
Read the currently active separator (the last one which was pushed). The line (or "undef") is returned. Blank-lines before the separator lines are ignored.

The return are two scalars, where the first gives the location of the separator in the file, and the second the line which is found as separator. A new separator is activated using pushSeparator().

$obj->stripGt()

DIAGNOSTICS

Error: Filename or handle required to create a parser.
A message parser needs to know the source of the message at creation. These sources can be a filename (string), file handle object, or GLOB. See new(filename) and new(file). Cast by new()
Error: Package $package does not implement $method.
Fatal error: the specific package (or one of its superclasses) does not implement this method where it should. This message means that some other related classes do implement this method however the class at hand does not. Probably you should investigate this and probably inform the author of the package. Cast by notImplemented()
Warning: Unexpected end of header in $source: $line
While parsing a message from the specified source (usually a file name), the parser found a syntax error. According to the MIME specification in the RFCs, each header line must either contain a colon, or start with a blank to indicate a folded field. Apparently, this header contains a line which starts on the first position, but not with a field name.

By default, parsing of the header will be stopped. If there are more header lines after the erroneous line, they will be added to the body of the message. In case of new(fix_header_errors) set, the parsing of the header will be continued. The erroneous line will be added to the preceding field. Cast by readHeader()
