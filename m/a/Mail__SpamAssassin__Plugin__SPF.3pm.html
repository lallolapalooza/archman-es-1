Mail::SpamAssassin::Plugin::SPF(3) Documentación de Perl aportada por el usuario Mail::SpamAssassin::Plugin::SPF(3)

NOMBRE

Mail::SpamAssassin::Plugin::SPF - realiza pruebas de verificación SPF

SINOPSIS

loadplugin     Mail::SpamAssassin::Plugin::SPF

DESCRIPCIÓN

Este plugin verifica un mensaje contra los registros del Marco de Política del Remitente (SPF) publicados por los propietarios del dominio en DNS para luchar contra la falsificación de direcciones de correo electrónico y facilitar la identificación de spams.

Se recomienda usar un filtro MTA (pypolicyd-spf / spf-engine etc), para que este plugin pueda reutilizar los resultados de las cabeceras Received-SPF y/o Authentication-Results tal cual. De lo contrario, el rendimiento podría verse afectado, las búsquedas DNS realizadas por este plugin no son asíncronas. Esas cabeceras también ayudarán cuando SpamAssassin no pueda detectar correctamente EnvelopeFrom.

AJUSTES DE USUARIO

welcomelist_from_spf usuario@ejemplo.com
Anteriormente whitelist_from_spf, que funcionará indistintamente hasta la versión 4.1.

Funciona de manera similar a welcomelist_from, excepto que, además de coincidir con una dirección de remitente, se debe pasar una verificación contra el registro SPF del dominio. El primer parámetro es una dirección para incluir en la lista de bienvenida, y el segundo es una cadena para que coincida con el rDNS del relé.

Al igual que welcomelist_from, se admiten varias direcciones por línea, separadas por espacios. También se admiten varias líneas "welcomelist_from_spf".

Las cabeceras verificadas para las direcciones de welcomelist_from_spf son las mismas cabeceras utilizadas para las verificaciones SPF (Envelope-From, Return-Path, X-Envelope-From, etc).

Dado que esta lista de bienvenida requiere una verificación SPF, las pruebas de red deben estar habilitadas. También se requiere que su ruta de confianza esté configurada correctamente. Consulte la sección sobre "trusted_networks" para obtener más información sobre las rutas de confianza.

por ejemplo:

welcomelist_from_spf joe@ejemplo.com fred@ejemplo.com
welcomelist_from_spf *@ejemplo.com
def_welcomelist_from_spf usuario@ejemplo.com
Anteriormente def_whitelist_from_spf, que funcionará indistintamente hasta la versión 4.1.

Igual que "welcomelist_from_spf", pero se utiliza para las entradas predeterminadas de la lista de bienvenida en la distribución de SpamAssassin. La puntuación de la lista de bienvenida es menor, ya que a menudo son objetivos de suplantación de identidad por spammers.

unwelcomelist_from_spf usuario@ejemplo.com
Anteriormente unwhitelist_from_spf, que funcionará indistintamente hasta la versión 4.1.

Se utiliza para eliminar una entrada de "welcomelist_from_spf" o "def_welcomelist_from_spf". La dirección de correo electrónico especificada debe coincidir exactamente con la dirección utilizada anteriormente.

Útil para eliminar entradas predeterminadas no deseadas de una configuración distribuida por una configuración local o específica del sitio o por "user_prefs".

AJUSTES DE ADMINISTRADOR

spf_timeout n (predeterminado: 5)
Cuántos segundos esperar a que se complete una consulta SPF, antes de que el escaneo continúe sin el resultado SPF. Un valor numérico se puede sufijar opcionalmente con una unidad de tiempo (s, m, h, d, w, que indican segundos (predeterminado), minutos, horas, días, semanas).
ignore_received_spf_header (0|1) (predeterminado: 0)
Por defecto, para evitar búsquedas DNS innecesarias, el plugin intentará utilizar los resultados SPF encontrados en cualquier cabecera "Received-SPF" que encuentre en el mensaje que solo pudo haber sido añadida por un relé interno.

Establezca esta opción a 1 para ignorar cualquier cabecera "Received-SPF" presente y hacer que el plugin realice la verificación SPF por sí mismo.

Tenga en cuenta que, a menos que el plugin encuentre una "identity=helo", o alguna identidad no soportada, asumirá que el resultado es un resultado de verificación SPF mfrom. Las únicas identidades soportadas son "mfrom", "mailfrom" y "helo".

use_newest_received_spf_header (0|1) (predeterminado: 0)
Por defecto, al utilizar cabeceras "Received-SPF", el plugin intentará usar las cabeceras "Received-SPF" más antiguas (la más abajo) añadidas por relés internos de las que pueda parsear resultados, ya que son las más probables de ser precisas. Esto se hace para que si tiene una configuración de correo entrante donde uno de sus MXes principales no conoce un MX secundario (o sus MXes no conocen algún tipo de relé de reenvío que SA considera confiable+interno) pero SA conoce el límite real del dominio (configuración de internal_networks), SA utilizará los resultados que son más precisos.

Utilice esta opción para empezar con las cabeceras "Received-SPF" más nuevas (la más arriba), trabajando hacia abajo hasta que se parseen exitosamente los resultados.

has_check_for_spf_errors
Añade una verificación de capacidad para "if can()" para check_for_spf_permerror, check_for_spf_temperror, check_for_spf_helo_permerror y check_for_spf_helo_permerror
has_check_spf_skipped_noenvfrom
Añade una verificación de capacidad para "if can()" para check_spf_skipped_noenvfrom
check_spf_skipped_noenvfrom
Verifica si las comprobaciones SPF se han omitido porque no se pudo determinar EnvelopeFrom.
