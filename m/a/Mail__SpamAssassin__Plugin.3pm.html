NOMBRE

Mail::SpamAssassin::Plugin - Clase base del plugin de SpamAssassin

SINOPSIS

Configuración de SpamAssassin:

loadplugin MyPlugin /path/to/myplugin.pm

Código Perl:

package MyPlugin;
use Mail::SpamAssassin::Plugin;
our @ISA = qw(Mail::SpamAssassin::Plugin);
sub new {
  my ($class, $mailsa) = @_;
  # el boilerplate perlobj usual para crear un objeto de subclase
  $class = ref($class) || $class;
  my $self = $class->SUPER::new($mailsa);
  bless ($self, $class);
  # luego registrar una regla eval, si se desea...
  $self->register_eval_rule ("check_for_foo");
  # y devolver el nuevo objeto plugin
  return $self;
}
...métodos...
1;

DESCRIPCIÓN

Esta es la clase base para los plugins de SpamAssassin; todos los plugins deben ser objetos que implementen esta clase.

Esta clase proporciona métodos stub (sin operación) para todas las llamadas que un plugin puede recibir. Se espera que tu plugin sobrescriba uno o más de estos stubs para realizar sus acciones.

SpamAssassin implementa una cadena de plugins; cada evento de llamada se pasa a cada uno de los objetos de plugin registrados en turno. Cualquier plugin puede llamar a "$self->inhibit_further_callbacks()" para bloquear la entrega de ese evento a los plugins posteriores en la cadena. Esto es útil si el plugin ha manejado el evento y no habrá necesidad de que los plugins posteriores lo manejen también.

Si buscas escribir una simple regla eval, salta directamente a register_eval_rule(), abajo.

INTERFAZ

En todas las APIs de plugin a continuación, "options" se refiere a una referencia a un hash que contiene pares de nombre-valor. Esto se utiliza para garantizar la compatibilidad futura, en el sentido de que podemos agregar nuevas opciones en el futuro sin afectar a los objetos construidos para una versión anterior de la API.

Por ejemplo, así sería cómo imprimir el elemento "line" en un método parse_config():

sub parse_config {
  my ($self, $opts) = @_;
  print "MyPlugin: parse_config got ".$opts->{line}."\n";
}

MÉTODOS

Los siguientes métodos pueden ser sobrescritos por las subclases para manejar eventos.

$plugin = MyPluginClass->new ($mailsaobject)
Constructor. Los plugins que necesiten registrarse a sí mismos deberán definir los suyos propios; el constructor de la superclase predeterminado funcionará bien para los plugins que solo sobrescriban un método.

Nota: las subclases deben proporcionar el $mailsaobject al constructor de la superclase, así:

my $self = $class->SUPER::new($mailsaobject);

Nota sobre el ciclo de vida: los plugins que necesiten almacenar estado por escaneo no deben almacenarlo en el objeto Plugin; en su lugar, esto debe almacenarse en el objeto PerMsgStatus, ver check_start() abajo. También se recomienda que la configuración se almacene en el objeto Conf; ver parse_config().

$plugin->parse_config ( { options ... } )
Analiza una línea de configuración que aún no se ha manejado. "options" es una referencia a un hash que contiene estas opciones:
line
La línea de texto de configuración a analizar. Se le han quitado los espacios en blanco al principio y al final, y los comentarios.
key
La clave de configuración; es decir, la primera "palabra" de la línea.
value
El valor de configuración; todo lo que sigue a la primera "palabra" y el espacio en blanco posterior.
conf
El objeto "Mail::SpamAssassin::Conf" en el cual se debe almacenar la información de configuración.
user_config
Un booleano: 1 si se está leyendo la configuración de un usuario, 0 si se están leyendo los archivos de configuración a nivel de sistema.

Si la línea de configuración fue una configuración manejada por este plugin, la implementación del método debe llamar a "$self->inhibit_further_callbacks()".

Si la configuración no es manejada por este plugin, el método debe devolver 0 para que un plugin posterior pueda manejarla, o para que SpamAssassin pueda mostrar un mensaje de advertencia al usuario si ningún plugin la entiende.

Nota sobre el ciclo de vida: se sugiere que la configuración se almacene en el objeto "Mail::SpamAssassin::Conf" en uso, en lugar del propio objeto plugin. Esto se puede encontrar como "$plugin->{main}->{conf}", o como "conf" en el hash de referencia $options arriba. Al almacenarlo en "conf", esto permite que la precedencia de configuración por usuario y a nivel de sistema se maneje correctamente.

$plugin->finish_parsing_start ( { options ... } )
Indica que la configuración a nivel de sistema se ha leído completamente, pero las estructuras de datos internas aún no se han creado. Es posible usar esta llamada para modificar dinámicamente la configuración ya leída o agregar nuevas opciones de configuración.

"options" es una referencia a un hash que contiene estas opciones:

conf
El objeto "Mail::SpamAssassin::Conf" en el cual se debe almacenar la información de configuración.

Nota: no hay garantías de que las estructuras de datos internas de SpamAssassin no cambien de una versión a otra. En particular, para esta llamada de plugin, si modificas las estructuras de datos de reglas en un plugin de terceros, todas las apuestas están canceladas hasta que exista una API para modificar esos datos de configuración.

$plugin->finish_parsing_end ( { options ... } )
Indica que el análisis de la configuración a nivel de sistema acaba de finalizar y SpamAssassin está casi listo para comprobar los mensajes.

"options" es una referencia a un hash que contiene estas opciones:

conf
El objeto "Mail::SpamAssassin::Conf" en el cual se debe almacenar la información de configuración.

Nota: no hay garantías de que las estructuras de datos internas de SpamAssassin no cambien de una versión a otra. En particular, para esta llamada de plugin, si modificas las estructuras de datos de reglas en un plugin de terceros, todas las apuestas están canceladas hasta que exista una API para modificar esos datos de configuración.

$plugin->user_conf_parsing_start ( { options ... } )
Indica que la configuración por usuario se ha leído completamente, pero no se ha convertido a estructuras de datos internas. Es posible usar esta llamada para modificar dinámicamente la configuración ya leída o agregar nuevas opciones de configuración.

Si "allow_user_rules" está habilitado en la configuración, es posible que se hayan agregado reglas adicionales desde que se llamó a la invocación de la llamada de plugin "finish_parsing_start".

conf
El objeto "Mail::SpamAssassin::Conf" en el cual se debe almacenar la información de configuración.

Nota: no hay garantías de que las estructuras de datos internas de SpamAssassin no cambien de una versión a otra. En particular, para esta llamada de plugin, si modificas las estructuras de datos de reglas en un plugin de terceros, todas las apuestas están canceladas hasta que exista una API para modificar esos datos de configuración.

$plugin->user_conf_parsing_end ( { options ... } )
Señala que el análisis de la configuración por usuario acaba de finalizar y SpamAssassin está casi listo para revisar mensajes. Si "allow_user_rules" está habilitado en la configuración, es posible que se hayan agregado reglas adicionales desde que se llamó a la invocación del hook del plugin "finish_parsing_end".

"options" es una referencia a un hash que contiene estas opciones:

conf
El objeto "Mail::SpamAssassin::Conf" en el que se deben almacenar los datos de configuración.

Nota: no hay garantía de que las estructuras de datos internas de SpamAssassin no cambien de una versión a otra. En particular para este hook de plugin, si modifica las estructuras de datos de reglas en un plugin de terceros, todas las apuestas están perdidas hasta que exista una API para modificar esos datos de configuración.

$plugin->signal_user_changed ( { options ... } )
Señala que el usuario actual ha cambiado a uno nuevo.
username
El nombre de usuario del nuevo usuario.
user_dir
El directorio de inicio del nuevo usuario. (equivalente a "~".)
userstate_dir
El directorio de almacenamiento del nuevo usuario. (equivalente a "~/.spamassassin".)
$plugin->services_authorized_for_username ( { options ... } )
Valida que un nombre de usuario dado esté autorizado para usar ciertos servicios.

Para autorizar a un usuario, el plugin debe primero verificar que puede manejar cualquiera de los servicios pasados al método y luego establecer el valor de cada servicio permitido en verdadero (o cualquier valor no negativo).

Los servicios actualmente soportados son: bayessql

username
Un nombre de usuario
services
Referencia a un hash que contiene los servicios que desea verificar.

{

'bayessql' => 0

}

conf
El objeto "Mail::SpamAssassin::Conf" en el que se deben almacenar los datos de configuración.
$plugin->compile_now_start ( { options ... } )
Esto se llama al principio de Mail::SpamAssassin::compile_now() para que los plugins puedan realizar cualquier inicialización necesaria para SpamAssassin multiproceso (como spamd o mass-check -j).
use_user_prefs
El valor de la opción $use_user_prefs en compile_now().
keep_userstate
El valor de la opción $keep_userstate en compile_now().
$plugin->compile_now_finish ( { options ... } )
Esto se llama al final de Mail::SpamAssassin::compile_now() para que los plugins puedan realizar cualquier inicialización necesaria para SpamAssassin multiproceso (como spamd o mass-check -j).
use_user_prefs
El valor de la opción $use_user_prefs en compile_now().
keep_userstate
El valor de la opción $keep_userstate en compile_now().
$plugin->check_start ( { options ... } )
Señala que una operación de verificación de mensajes está comenzando.
permsgstatus
El objeto de contexto "Mail::SpamAssassin::PerMsgStatus" para este escaneo.

Nota de ciclo de vida: se recomienda que las reglas que necesiten rastrear el estado de las pruebas por escaneo almacenen ese estado en este objeto, no en el objeto del plugin en sí, ya que el objeto del plugin se compartirá entre todos los escáneres activos.

El mensaje que se está escaneando es accesible a través de la API "$permsgstatus->get_message()"; también hay una serie de otras APIs públicas en ese objeto. Ver el perldoc de "Mail::SpamAssassin::PerMsgStatus".

$plugin->check_main ( { options ... } )
Señala que un mensaje debe ser verificado. Tenga en cuenta que las implementaciones de este hook deben devolver 1.
permsgstatus
El objeto de contexto "Mail::SpamAssassin::PerMsgStatus" para este escaneo.
$plugin->check_tick ( { options ... } )
Se llama periódicamente durante una operación de verificación de mensajes. Una devolución de llamada configurada para este método es un buen lugar para ejecutar un bucle de eventos que maneje eventos de red activados en un método "parse_metadata", por ejemplo.
permsgstatus
El objeto de contexto "Mail::SpamAssassin::PerMsgStatus" para este escaneo.
$plugin->check_dnsbl ( { options ... } )
Se llama cuando se están iniciando búsquedas DNSBL u otras búsquedas de red, lo que implica una prioridad de ejecución actual de -100. Este es el lugar para iniciar sus propias búsquedas de red iniciadas asincrónicamente.
permsgstatus
El objeto de contexto "Mail::SpamAssassin::PerMsgStatus" para este escaneo.
$plugin->check_post_dnsbl ( { options ... } )
Se llama después de que se hayan recopilado los resultados de DNSBL. Este es un buen lugar para recopilar sus propias búsquedas de red iniciadas asincrónicamente.
permsgstatus
El objeto de contexto "Mail::SpamAssassin::PerMsgStatus" para este escaneo.
$plugin->check_cleanup ( { options ... } )
Se llama justo antes de que finalice la verificación del mensaje y antes del posible autoaprendizaje. Esto garantiza que siempre se llamará, a diferencia de check_tick y check_post_dnsbl. Se utiliza para limpiar devoluciones de llamada pendientes o hijos creados, última oportunidad para que las reglas se activen.
permsgstatus
El objeto de contexto "Mail::SpamAssassin::PerMsgStatus" para este escaneo.
$plugin->check_post_learn ( { options ... } )
Se llama después de que el autoaprendizaje haya ocurrido (o no). Si desea realizar un aprendizaje adicional, independientemente de si ocurre o no el autoaprendizaje, este es el lugar para hacerlo.
permsgstatus
El objeto de contexto "Mail::SpamAssassin::PerMsgStatus" para este escaneo. La puntuación actual, los nombres de las reglas que se activaron, etc. se pueden recuperar utilizando las APIs públicas de este objeto.
$plugin->check_end ( { options ... } )
Señala que una operación de verificación de mensajes ha finalizado y los resultados están a punto de ser devueltos al llamador.
permsgstatus
El objeto de contexto "Mail::SpamAssassin::PerMsgStatus" para este escaneo. La puntuación actual, los nombres de las reglas que se activaron, etc. se pueden recuperar utilizando las APIs públicas de este objeto.
$plugin->finish_tests ( { options ... } )
Se llama a través de "Mail::SpamAssassin::finish". Esto debería limpiar cualquier prueba que un plugin haya agregado al espacio de nombres.

En ciertas circunstancias, los plugins pueden encontrar útil compilar funciones perl del conjunto de reglas sobre la marcha. Es importante eliminarlas una vez que el objeto "Mail::SpamAssassin" se elimina, sin embargo, y esta API lo permite.

Cada plugin es responsable de sus propias funciones perl generadas.

conf
El objeto "Mail::SpamAssassin::Conf" en el que se deben almacenar los datos de configuración.

Ver también la API auxiliar "register_generated_rule_method", más adelante.

$plugin->extract_metadata ( { options ... } )
Señala que un mensaje se está extrayendo para obtener metadatos. Algunos plugins pueden desear agregar sus propios metadatos también.
msg
El objeto "Mail::SpamAssassin::Message" para este mensaje.
permsgstatus
El objeto de contexto "Mail::SpamAssassin::PerMsgStatus" para este escaneo.
$plugin->parsed_metadata ( { options ... } )
Señala que los metadatos de un mensaje han sido analizados y ahora pueden ser accedidos por el plugin.
permsgstatus
El objeto de contexto "Mail::SpamAssassin::PerMsgStatus" para este escaneo.
$plugin->start_rules ( { options ... } )
Se llama antes de probar un conjunto de reglas de un tipo y prioridad determinados.

APIS AUXILIARES

Estos métodos proporcionan una API para que los plugins se registren y reciban eventos específicos, o controlen el comportamiento de la cadena de devolución de llamadas.

$plugin->register_eval_rule ($nameofevalsub, $ruletype)
Los plugins que implementan una prueba de evaluación necesitarán llamar a esto, para que SpamAssassin llame al objeto cuando se encuentre esa prueba de evaluación. Consulte la sección REGISTRO DE REGLAS DE EVALUACIÓN para obtener detalles completos.

Desde la versión 4.0, se puede especificar un $ruletype opcional para garantizar que la función de evaluación no se pueda llamar con un tipo de regla incorrecto desde la configuración, por ejemplo, si el usuario utiliza "header FOO eval:foobar()" en lugar de "body FOO eval:foobar()". Una discrepancia resultará en un error de lint. $ruletype puede ser uno de:

$Mail::SpamAssassin::Conf::TYPE_HEAD_EVALS
$Mail::SpamAssassin::Conf::TYPE_BODY_EVALS  (permite tanto body como rawbody)
$Mail::SpamAssassin::Conf::TYPE_RAWBODY_EVALS
$Mail::SpamAssassin::Conf::TYPE_FULL_EVALS
$plugin->register_generated_rule_method ($nameofsub)
En ciertas circunstancias, los plugins pueden encontrar útil compilar funciones perl desde el conjunto de reglas, sobre la marcha. Es importante eliminarlos una vez que el objeto "Mail::SpamAssassin" sea eliminado, sin embargo, y esta API lo permite.

Una vez que se ha generado el método $nameofsub, llame a esta API con el nombre del método (incluyendo el ámbito completo del paquete). Esto indica que es un fragmento temporal de código generado, construido a partir del conjunto de reglas de SpamAssassin, y cuando se llame a Mail::SpamAssassin::finish(), el método será destruido.

Esta API se añadió en SpamAssassin 3.2.0.

$plugin->register_method_priority($methodname, $priority)
Indica que el método llamado $methodname en el objeto actual tiene una prioridad de devolución de llamada de $priority.

Esto es utilizado por el manejador de plugins para determinar el orden relativo de las devoluciones de llamada; los plugins con prioridades numéricas más bajas se llaman antes que los plugins con prioridades numéricas más altas. Cada método puede tener un valor de prioridad diferente. El valor predeterminado es 0. El orden de las devoluciones de llamada a métodos con igual prioridad no está definido.

Típicamente, solo necesita preocuparse por esto si necesita asegurarse de que el método de su plugin se llame antes que la implementación de ese método en otro plugin. Debe llamarse desde el constructor de su plugin.

Esta API se añadió en SpamAssassin 3.2.0.

$plugin->inhibit_further_callbacks()
Indica al manejador de plugins que inhiba las llamadas a otros plugins en la cadena de plugins para la devolución de llamada actual. Se utiliza con frecuencia al analizar configuraciones utilizando parse_config().

REGISTRO

Mail::SpamAssassin::Plugin::dbg($message)
Muestra un mensaje de depuración $message, si el objeto SpamAssassin se está ejecutando con la depuración activada.

NOTA: Esta función no está disponible en el espacio de nombres del paquete de plugins generales y no se puede llamar a través de $self->dbg(). Si un plugin desea mostrar información de depuración, debe llamar a Mail::SpamAssassin::Plugin::dbg($msg).

Mail::SpamAssassin::Plugin::info($message)
Muestra un mensaje informativo $message, si el objeto SpamAssassin se está ejecutando con mensajes informativos activados.

NOTA: Esta función no está disponible en el espacio de nombres del paquete de plugins generales y no se puede llamar a través de $self->info(). Si un plugin desea mostrar información de depuración, debe llamar a Mail::SpamAssassin::Plugin::info($msg).

En general, es mejor que los plugins utilicen el módulo "Mail::SpamAssassin::Logger" para importar "dbg" e "info" directamente, de la siguiente manera:

use Mail::SpamAssassin::Logger;
dbg("some message");
info("some other message");

REGISTRO DE REGLAS DE EVALUACIÓN

Los plugins que implementan una prueba de evaluación deben registrar los métodos que se pueden llamar desde las reglas en los archivos de configuración, en el constructor de la clase del plugin.

Por ejemplo,

$plugin->register_eval_rule ('check_for_foo', $Mail::SpamAssassin::Conf::TYPE_HEAD_EVALS)

hará que "$plugin->check_for_foo()" sea llamado para la siguiente regla de SpamAssassin:

header   FOO_RULE     eval:check_for_foo()

Mail::SpamAssassin::Plugin

DESCRIPCIÓN

Este plugin es un objeto que permite ejecutar reglas de prueba evaluada (eval) en el contexto de SpamAssassin.

INTERFAZ

El plugin se registra como un objeto de prueba evaluada (eval) que se puede invocar en el contexto de SpamAssassin.

El plugin puede invocar métodos de prueba evaluada (eval) que se pueden registrar como reglas de prueba.

El plugin puede invocar apis de auxilio que se pueden registrar como reglas de prueba.

LOGGING

El plugin puede registrar logs de prueba evaluada (eval) que se pueden registrar como reglas de prueba.

REGISTRAR REGLAS DE PRUEBA EVALUADA

El plugin puede registrar reglas de prueba evaluada (eval) que se pueden invocar en el contexto de SpamAssassin.

ARGS ESTANDAR PARA LAS REGLAS

El plugin se registra con los mismos argumentos que un objeto de prueba evaluada (eval) estándar. Las reglas diferentes reciben información distinta.
