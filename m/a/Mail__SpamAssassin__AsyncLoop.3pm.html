NAME

Mail::SpamAssassin::AsyncLoop - bucle asincrónico de eventos para operaciones largas

DESCRIPCIÓN

Un bucle asincrónico de eventos utilizado para operaciones largas, realizadas "en el background" durante la operación Mail::SpamAssassin::check(), como consultas de listas de bloques DNS.

MÉTODOS

$ent = $async->bgsend_and_start_lookup($name, $type, $class, $ent, $cb, %options)
Inicia consultas asincrónicas de DNS. Este es el único método oficial admitido para plugins desde la versión 4.0.0. No use separadamente bgsend y start_lookup.

Automáticamente merge consultas duplicadas, solo inicia una y llama a todos los callbacks relacionados con el resultado.

$name (requerido)
Nombre de la consulta.
$type (requerido)
Tipos de consulta, como A, TXT, NS, etc.
$class (requerido/deprecated)
Obsoleto, ignorado, se establece como undef.
$ent es un referencia hash obligatoria que contiene los siguientes elementos:
$ent->{rulename} (requerido)
El nombre de la regla que inició y/o depende de esta consulta. Es obligatorio para que las dependencias de reglas funcionen correctamente. Puede ser un único nombre de regla o un array de múltiples nombres de reglas.
$ent->{type} (opcional)
Una cadena, típicamente un término de un solo palabra, utilizada para describir el tipo de consulta en los mensajes de log, como "DNSBL", "URIBL-A". Si no se define, el valor por defecto es el mismo que el de $type.
$ent->{zone} (opcional)
Una especificación de zona (generalmente un nombre de zona DNS - como host, dominio o RBL) que puede usarse como clave para buscar configuraciones por zona. No tiene significado implícito en este módulo. Actualmente se usa para obtener tiempos por zona (de rbl_timeout). Por defecto, es $name.
$ent->{timeout_initial} (opcional)
Un valor inicial de tiempo transcurrido en segundos en el que estamos dispuestos a esperar una respuesta (en segundos, valor flotante también es válido). Cuando el tiempo transcurrido desde que comenzó la consulta excede el valor de timeout_initial y no hay otras consultas para esperar, la consulta se aborta. El valor real de timeout se encuentra entre timeout_initial y gradualmente se acerca a timeout_min (ver siguiente parámetro).

Si el llamador no proporciona este parámetro o su valor es undefined, se establece un valor inicial por defecto mediante la variable de configuración rbl_timeout.

Si el valor del parámetro timeout_initial es menor que timeout_min, el timeout inicial se establece en timeout_min.

$ent->{timeout_min} (opcional)
Un límite inferior (en segundos) a lo que se acerca el valor real cuando el número de consultas completadas se acerca al número de consultas iniciadas. Por defecto, es 0.2 * timeout_initial.
$ent->{key}, $ent->{id} (obsoleto)
Obsoleto, ignorado, se genera automáticamente desde 4.0.0.
$ent->{YOUR_OWN_ITEM}
Valores/objetos personalizados que puedas pasar a la callback de respuesta.
$cb (requerido)
Función de callback para la respuesta, llamada como $cb->($ent, $pkt). $ent es el mismo objeto que se llamó con bgsend_and_start_lookup. $pkt es el objeto de paquete para la respuesta, objetos Net::DNS:RR pueden encontrarse en $pkt->answer.
%options (requerido)
Un hash de opciones. Solo se soporta y es requerida la opción master_deadline: 
master_deadline => $pms->{master_deadline}
$ent = $async->start_lookup($ent, $master_deadline)
USO DEPRECATED desde 4.0.0, por favor usa bgsend_and_start_lookup.
$ent = $async->get_lookup($key)
DEPRECATED desde 4.0.0. No usar.
$async->log_lookups_timing()
Registro de tiempos ordenados para todas las consultas completadas.
$alldone = $async->complete_lookups()
Realizar un pase de las consultas pendientes para ver si alguna ha sido completada. Los callbacks de consultas completadas se llamarán desde poll_responses().

Si no hay consultas pendientes o demasiado tiempo ha pasado desde que se devolvieron resultados, se devuelve 1, de lo contrario 0.

$async->abort_remaining_lookups()
Abortar consultas pendientes.
$async->set_response_packet($id, $pkt, $key, $timestamp)
Para uso interno, no llamar desde plugins.

Registrar una "paquete de respuesta" para una consulta específica. $id es el identificador de la consulta, y debe coincidir con el "id" proporcionado en start_lookup(). $pkt es el objeto de paquete de respuesta. Un parámetro $key identifica un elemento en la tabla hash %{$self->{pending_lookups}} donde el objeto que generó esta consulta puede encontrarse, y a través del cual se puede obtener información adicional sobre la consulta.

El paquete de respuesta del resolutor de DNS $pkt será disponible para un subproceso de callback a través de su argumento y también en $ent->{response_packet}.

$async->report_id_complete($id,$key,$key,$timestamp)
DEPRECATED desde 4.0.0. No usar.

Legacy. Equivalentes a $self->set_response_packet($id,undef,$key,$timestamp), es decir, proporcionar undef como paquete de respuesta. Registrar que una consulta ha completado y no es más "pendiente". $id es el identificador de la consulta, y debe coincidir con el "id" proporcionado en start_lookup().

Debe llamarse uno o el otro de set_response_packet() o report_id_complete(), pero no ambos.

$time = $async->last_poll_responses_time()
Obtener el tiempo de la última llamada a poll_responses() (que se llama desde complete_lookups()). Si poll_responses() nunca fue llamada o abort_remaining_lookups() ha sido llamada, last_poll_responses_time() devolverá undef.
