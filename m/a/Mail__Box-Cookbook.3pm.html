NOMBRE

Mail::Box-Cookbook - Ejemplos de cómo usar Mail::Box

DESCRIPCIÓN

El paquete Mail::Box es una suite de clases para acceder y gestionar carpetas de correo de forma independiente de la carpeta. Este manual demuestra algunas aplicaciones sencillas. Por favor, contribuya con ejemplos y correcciones. También puede ser útil echar un vistazo a los programas incluidos en los directorios "scripts/" y "examples/" de la distribución.

El Administrador

Para más detalles sobre todos los paquetes que participan en la suite Mail::Box, debe leer Mail::Box-Overview. Pero no necesita saber mucho si quiere usar la suite Mail::Box.

Por favor, use el administrador para abrir sus carpetas. Ciertamente se beneficiará de ello. El administrador se encarga de detectar qué tipo de carpeta está usando y qué carpetas están abiertas. Esto último evita la reapertura accidental de una carpeta ya abierta.

El script "examples/open.pl" contiene principalmente:

my $mgr    = Mail::Box::Manager->new;
my $folder = $mgr->open($filename);
foreach my $message ($folder->messages) {
    print $message->get('Subject') || '<no subject>', "\n";
}
$folder->close;

que muestra todas las funciones más importantes. Listará todos los asuntos de los mensajes de la carpeta indicada. Así, aunque el número de paquetes incluidos en el módulo Mail::Box es enorme, solo se necesita poco para programas normales.

En lugar de llamar a "close" en la carpeta, también puede llamar a:

$mgr->closeAllFolders;

Si olvida cerrar una carpeta, los cambios no se guardarán. Esto puede cambiar en el futuro.

Mensajes multipartos

En los primeros días de Internet, los mensajes multipartos eran muy raros. Sin embargo, en los últimos años, una gran parte de todos los mensajes transmitidos tienen archivos adjuntos. Esto hace que el manejo de los cuerpos de los mensajes sea un poco más difícil: cuando un mensaje contiene más de una parte, ¿cuál es la parte más importante para leer?

Para complicar las cosas, los multipartos pueden anidarse: cada parte puede ser un multiparte por sí misma. Esto significa que los programas que manejan el contenido del mensaje deben ser recursivos o saltarse los multipartos.

La parte central del script "examples/multipart.pl" dice:

foreach my $message ($folder->messages) {
    show_type($message);
}
show_type($) {
    my $msg = shift;
    print $msg->get('Content-Type'), "\n";
    if($msg->isMultipart) {
        foreach my $part ($msg->parts) {
            show_type($part);
        }
    }
}

Cada parte es un mensaje en sí mismo. Tiene una cabecera y un cuerpo. Un mensaje multiparte tiene un cuerpo especial: contiene una lista de partes y opcionalmente también un preámbulo y un epílogo, que son respectivamente los textos antes y después de las partes. Estos textos pueden ser ignorados, ya que solo describen cómo se creó el multiparte.

Filtro

El objetivo es seleccionar unos pocos mensajes de una carpeta y moverlos a otra. El script "examples/takelarge.pl" demuestra cómo lograr esto. Advertencia: ¡reemplazará su carpeta de entrada!

Como extracto de la parte crucial:

my $inbox = $mgr->open('inbox', access => 'rw');
my $large = $mgr->open('large', access => 'a', create => 1);
foreach my $message ($inbox->messages) {
    next if $message->size < $size;
    $mgr->moveMessage($large, $message);
}
$inbox->close;
$large->close;

La "inbox" se abre para lectura y escritura: primero lee todos los mensajes y luego escribe de nuevo la carpeta más pequeña sin los mensajes movidos. La carpeta "large" se crea si el archivo no existe todavía. En cualquier caso, los mensajes se añadirán al final de la carpeta.

El administrador es necesario para mover el mensaje: para anular el registro del mensaje en la primera carpeta y volver a registrarlo en la segunda. Puede mover más mensajes a la vez, si lo desea. Si mueve a una carpeta que no está abierta, es mejor hacerlo así: será más rápido:

my @move = grep {$_->size >= $size} $inbox->messages;
$mgr->moveMessage($large, @move);

En este ejemplo, el "size" del mensaje determina si el mensaje se mueve o no. Por supuesto, hay muchos otros criterios que puede utilizar. Por ejemplo, use "timestamp" para encontrar mensajes viejos:

use constant YEAR => 365 * 24 * 60 * 60;
my $now = time;
my @old = grep {$_->timestamp - $now > YEAR} $inbox->messages;
$mgr->moveMessage($oldbox, @old);

Crear una respuesta

El complejo tratamiento de mensajes se implementa en Mail::Message::Construct y se carga automáticamente cuando es necesario. Es suficiente llamar simplemente a "reply" en cualquier mensaje:

my $folder  = ...;
my $message = $folder->message(8);
my $reply   = $message->reply;
$folder->addMessage($reply);
$reply->print;

El método es bastante complejo, como demuestra "examples/reply.pl", en el que se muestra la construcción de un mensaje de respuesta.

Se pueden crear tres tipos de mensajes de respuesta: uno que no incluye el mensaje original en absoluto (NO), luego uno que inserta el mensaje original citado (INLINE) y, como tercera posibilidad, el mensaje original como archivo adjunto (ATTACH).

El parámetro "include" selecciona el tipo de respuesta. Cuando responde a mensajes binarios o multipartos, INLINE se promocionará automáticamente a ATTACH. Por defecto, el texto de la firma del remitente original será eliminado. Los mensajes multipartos se limpiarán de los archivos adjuntos que califiquen como firma. En caso de que un multiparte (después de la limpieza) solo contenga una parte, y se solicite INLINE, se 'aplanará': la respuesta puede ser de una sola parte.

Consulte los parámetros que se pueden pasar a reply en Mail::Message::Construct. Para una respuesta de una sola parte, el retorno será

preámbulo
original citado
epílogo
--
firma

Un cuerpo multiparte será

parte 1: preámbulo
        [ ver archivo adjunto ]
        epílogo
parte 2: multiparte original limpiado
parte 3: firma

Construir un mensaje

Hay tres formas de crear un mensaje que no sea una respuesta:

  • Mail::Message::buildFromBody()

    Empiece creando un cuerpo y transfórmelo en un mensaje.

  • Mail::Message::build()

    cree todo el mensaje a la vez.

  • Mail::Message::read()

    lea un mensaje de un handle de archivo, un escalar o un array de líneas.

Los tres métodos están implementados en Mail::Message::Construct. Por favor, hágase un favor y dé preferencia a los métodos "build*" sobre "read", porque son mucho más potentes. Use "read" solo cuando tenga el mensaje en STDIN o un array de líneas proporcionado por un programa externo.

Muy importante recordar a partir de ahora: la información sobre el contenido del cuerpo (las líneas "Content-*" en la cabecera) se almacena dentro del objeto del cuerpo, mientras el cuerpo no esté contenido en un objeto de mensaje.

Por ejemplo, el método "decoded" del método $message devuelve el cuerpo decodificado del $message. Es un objeto de cuerpo en sí mismo, pero fuera de un mensaje real. Entonces, puede que quiera jugar con él, concatenando algunos textos: de nuevo resultando en un nuevo cuerpo. Cada cuerpo contiene la información correcta de "Content-*". Luego, finalmente, crea un mensaje especificando el cuerpo y líneas de cabecera adicionales. En ese momento necesita especificar las direcciones de origen y destino (las líneas "From" y "To"). En ese momento, el cuerpo se codificará automáticamente para ser aceptable para las carpetas de correo y los programas de transmisión.

Mail::Box-Cookbook

DESCRIPCIÓN

Mail::Box-Cookbook es un libro de cocina para el módulo Mail::Box, que proporciona guía y ejemplos para crear mensajes en Perl. El módulo se enfoca en la creación de mensajes con estructura y formato adecuado, permitiendo el manejo de datos en formato MIME, transfer encoding y otros aspectos relevantes.
