NOMBRE

SNMP - Módulo de Extensión 'SNMP' de Perl5 para el paquete SNMP de Net-SNMP.

SINOPSIS

use SNMP;
...
$sess = new SNMP::Session(DestHost => localhost, Community => public);
$val = $sess->get('sysDescr.0');
...
$vars = new SNMP::VarList([sysDescr,0], [sysContact,0], [sysLocation,0]);
@vals = $sess->get($vars);
...
$vb = new SNMP::Varbind();
do {
   $val = $sess->getnext($vb);
   print "@{$vb}\n";
} until ($sess->{ErrorNum});
...
$SNMP::save_descriptions = 1;
SNMP::initMib(); # asumiendo que mib no está cargado aún
print "$SNMP::MIB{sysDescr}{description}\n";

DESCRIPCIÓN

Nota: El módulo Perl SNMP 5.0 que viene con net-snmp 5.0 y superior es diferente a las versiones anteriores en varios aspectos. Lo más importante es que se comporta como una aplicación net-snmp adecuada y llama a init_snmp correctamente, lo que significa que leerá archivos de configuración y usará esos valores predeterminados donde sea apropiado, analizará automáticamente archivos MIB, etc. Esto probablemente afectará a tus aplicaciones Perl si, por ejemplo, tienes valores predeterminados configurados en tu archivo snmp.conf (ya que el módulo Perl ahora utilizará esos valores predeterminados). La documentación, sin embargo, lamentablemente aún no se ha actualizado (aparte de esta nota), ni la implementación del uso predeterminado de read_config está completamente completa.

Las operaciones básicas del protocolo SNMP son proporcionadas por este módulo a través de una interfaz orientada a objetos para modularidad y facilidad de uso. La clase principal es SNMP::Session, que encapsula los aspectos persistentes de una conexión entre la aplicación de gestión y el agente gestionado. Internamente, la clase se implementa como una referencia de hash bendecida. Esta clase proporciona llamadas al método 'get', 'getnext', 'set', 'fget' y 'fgetnext'. Los métodos toman una variedad de formatos de argumentos de entrada y admiten operación síncrona y asíncrona a través de una API polimórfica (es decir, el comportamiento del método varía según los argumentos pasados, ver abajo).

SNMP::Session

$sess = new SNMP::Session(DestHost => 'host', ...)

Los siguientes argumentos pueden pasarse a new como un hash.

Opciones Básicas

DestHost
Nombre de host o dirección IP del agente SNMP con el que deseas hablar. Especificado en direcciones de agente con formato Net-SNMP. Estas direcciones típicamente se ven como una de las siguientes: 
localhost
tcp:localhost
tls:localhost
tls:localhost:9876
udp6:[::1]:9876
unix:/some/path/to/file/socket

El valor predeterminado es 'localhost'.

Version
Versión SNMP a utilizar.

El valor predeterminado se toma de la configuración de la biblioteca, probablemente 3 [1, 2 (igual que 2c), 2c, 3].

Timeout
El número de microsegundos a esperar antes de reenviar una solicitud.

El valor predeterminado es '1000000'

Retries
El número de veces que se reintentará una solicitud.

El valor predeterminado es '5'

RetryNoSuch
Si se habilitan los errores NOSUCH en los PDU de 'get', se repararán, eliminando el varbind en error y reenviándolo; se devolverá undef para todos los varbinds NOSUCH. Cuando se establece en '0', esta función está deshabilitada y la solicitud get completa fallará en cualquier error NOSUCH (se aplica solo a v1).

El valor predeterminado es '0'.

Opciones SNMPv3/TLS

OurIdentity
Nuestra identidad X.509 a utilizar, que debe ser una huella digital o el nombre del archivo que contiene el certificado.
TheirIdentity
La identidad del servidor remoto a la que conectarse, especificada como una huella digital o un nombre de archivo. Se debe especificar uno de estos, o el nombre de host a continuación junto con una ancla de confianza.
TheirHostname
El nombre de host del servidor remoto esperado. Si su certificado fue firmado por una CA, su nombre de host presentado en el certificado debe coincidir con este valor o la conexión no se establecerá (para evitar ataques de man-in-the-middle).
TrustCert
Un certificado de confianza para usar como ancla de confianza (como un certificado de CA) para verificar el certificado de un servidor remoto. Si se utiliza un certificado de CA para validar un certificado, el parámetro TheirHostname también debe especificarse para garantizar que su nombre de host presentado en el certificado coincida.

Opciones SNMPv3/USM

SecName
El nombre de seguridad SNMPv3 a utilizar (principalmente para SNMPv3 con USM).

El valor predeterminado es 'initial'.

SecLevel
El nivel de seguridad SNMPv3 a utilizar [noAuthNoPriv, authNoPriv, authPriv] (v3)

El valor predeterminado es 'noAuthNoPriv'.

SecEngineId
El engineID de seguridad SNMPv3 a utilizar (si el modelo de seguridad snmpv3 lo necesita; por ejemplo, USM). El formato es como una cadena sin el prefijo '0x'. Por lo tanto, si snmptrapd.conf tiene "-e 0x8000000001020304", usa SecEngineId => '8000000001020304'.

El valor predeterminado es <ninguno>, engineID de seguridad y se sondeará si no se proporciona (v3)

ContextEngineId
El engineID de contexto SNMPv3 a utilizar.

El valor predeterminado es el <ninguno> y se establecerá ya sea al valor SecEngineId si está configurado o se descubrirá, o se descubrirá de otras maneras si se usa TLS (descubrimiento basado en RFC5343).

Context
El nombre de contexto SNMPv3 a utilizar.

El valor predeterminado es '' (una cadena vacía)

AuthProto
El protocolo de autenticación SNMPv3/USM a utilizar [MD5, SHA].

El valor predeterminado es 'MD5'.

AuthPass
La frase de contraseña de autenticación SNMPv3/USM a utilizar.

predeterminado <ninguno>, frase de contraseña de autenticación

PrivProto
El protocolo de privacidad SNMPv3/USM a utilizar [DES, AES].

El valor predeterminado es 'DES'.

PrivPass
La frase de contraseña de privacidad SNMPv3/USM a utilizar.

predeterminado <ninguno>, frase de contraseña de privacidad (v3)

AuthMasterKey
PrivMasterKey
AuthLocalizedKey
PrivLocalizedKey
Claves de usuario USM SNMPv3 especificadas directamente (se usan si deseas especificar las claves en lugar de derivarlas de una contraseña como se mencionó anteriormente).

Opciones SNMPv1 y SNMPv2c

Community
Para SNMPv1 y SNMPv2c, el nombre de comunidad en texto plano a utilizar.

El valor predeterminado es 'public'.

Otras Opciones de Configuración

Se puede usar un <obj> especial, '*', para aplicar a todos los <obj>s, se llama a la sub suministrada para traducir el valor a un nuevo formato. La sub se llama pasando el Varbind

as the arg
TypeFormats
por defecto 'undef', utilizado por 'fget[next]', contiene una referencia a un hash de formateadores de valor de salida, (ej. {<tipo> => <sub-ref>, ... }, la subrutina proporcionada se llama para traducir el valor a un nuevo formato, a menos que un VarFormat coincida primero (ej. $sess->{TypeFormats}{INTEGER} = \&mapEnum(); aunque esto se puede hacer de manera más eficiente habilitando $SNMP::use_enums o el parámetro de creación de sesión 'UseEnums')
UseLongNames
por defecto al valor de SNMP::use_long_names en el momento de la creación de la sesión. se establece en un valor distinto de cero para que los <tags> para los métodos 'getnext' se generen con la convención de nombres MIB más larga (ej. system.sysDescr vs solo sysDescr)
UseSprintValue
por defecto al valor de SNMP::use_sprint_value en el momento de la creación de la sesión. se establece en un valor distinto de cero para que los valores de retorno para los métodos 'get' y 'getnext' se formateen con la función snprint_value de la biblioteca. Esto dará como resultado que ciertos tipos de datos se devuelvan en un formato no canónico. Nota: los valores devueltos con esta opción activada pueden no ser apropiados para operaciones 'set' (ver discusión de formatos de valor en la sección de descripción de <vars>)
UseEnums
por defecto al valor de SNMP::use_enums en el momento de la creación de la sesión. se establece en un valor distinto de cero para que los valores de retorno enteros se conviertan a identificadores de enumeración si es posible, estos valores también serán aceptables cuando se proporcionen a operaciones 'set'
UseNumeric
por defecto al valor de SNMP::use_numeric en el momento de la creación de la sesión. se establece en un valor distinto de cero para que los <tags> para los métodos get se devuelvan como OIDs numéricos en lugar de descripciones. UseLongNames se establecerá para que el OID completo se devuelva al llamador.
BestGuess
por defecto al valor de SNMP::best_guess en el momento de la creación de la sesión. esta configuración controla cómo se analizan los <tags>. establecerlo en 0 causa una búsqueda regular. establecerlo en 1 causa una coincidencia de expresión regular (definida como -Ib en snmpcmd) y establecerlo en 2 causa una búsqueda de acceso aleatorio (definida como -IR en snmpcmd).
NonIncreasing
por defecto al valor de SNMP::non_increasing en el momento de la creación de la sesión. esta configuración controla si un OID no creciente durante bulkwalk causará un error. establecerlo en 0 causa el comportamiento predeterminado (que puede, en agentes con muy mal rendimiento, resultar en un bucle sin fin). establecerlo en 1 causa un error (OID no creciente) cuando ocurre este error.
ErrorStr
solo lectura, contiene el mensaje de error asociado con la última solicitud
ErrorNum
solo lectura, contiene el snmp_err o el estado de la última solicitud
ErrorInd
solo lectura, contiene el índice de error snmp cuando es apropiado

DestAddr

SessPtr

RemotePort

Métodos de SNMP::Session

$sess->update(<fields>)
Actualiza el objeto SNMP::Session con los valores de los campos pasados como una lista de hash (similar a new(<fields>)) (¡ADVERTENCIA! no implementado completamente)
$sess->get(<vars> [,<callback>])
realiza SNMP GET, se aceptan múltiples formatos de <vars>. para operación síncrona, <vars> se actualizará con el valor(es) y tipo(s) y también devolverá el(los) valor(es) recuperado(s). Si se proporciona <callback>, el método operará de forma asíncrona.
$sess->fget(<vars> [,<callback>])
realiza SNMP GET como 'get' y formatea los valores de acuerdo con los manejadores especificados en $sess->{VarFormats} y $sess->{TypeFormats}
$sess->getnext(<vars> [,<callback>])
realiza SNMP GETNEXT, se aceptan múltiples formatos de <vars>, devuelve el(los) valor(es) recuperado(s), <vars> pasados como argumentos se actualizan para indicar el siguiente <obj>,<iid>,<val> y <type> lexicográficos.

Nota: el formato simple de <vars> de cadena (ej., 'sysDescr.0') no se actualiza. Si se proporciona <callback>, el método operará de forma asíncrona.

$sess->fgetnext(<vars> [,<callback>])
realiza SNMP GETNEXT como getnext y formatea los valores de acuerdo con los manejadores especificados en $sess->{VarFormats} y $sess->{TypeFormats}
$sess->set(<vars> [,<callback>])
realiza SNMP SET, se aceptan múltiples formatos de <vars>. el campo de valor en todos los formatos de <vars> debe estar en un formato canónico (es decir, formato bien conocido) para garantizar una traducción inequívoca a los valores de datos MIB de SNMP (ver discusión del formato de valor canónico en la sección de descripción de <vars>), devuelve snmp_errno. Si se proporciona <callback>, el método operará de forma asíncrona.
$sess->getbulk(<non-repeaters>, <max-repeaters>, <vars>)
realiza un SNMP GETBULK, de la lista de Varbinds, se obtiene la siguiente instancia lexicográfica para las primeras n Varbinds definidas por <non-repeaters>. Para las Varbinds restantes, se obtienen m instancias lexicográficas de cada una de las Varbinds restantes, donde m es <max-repeaters>.
$sess->bulkwalk(<non-repeaters>, <max-repeaters>, <vars> [,<callback>])
Realiza un "bulkwalk" de la lista de Varbinds. Esto se hace enviando una solicitud GETBULK (ver getbulk() arriba) para las Varbinds. Para cada variable solicitada, la respuesta se examina para ver si la siguiente instancia lexicográfica ha salido del subárbol solicitado. Se ignoran las instancias adicionales devueltas para esta variable, y se considera que el recorrido de ese subárbol está completo.

Si algún subárbol no se completó cuando se alcanzó el final de las respuestas, se compone otra solicitud, que consta de las variables restantes. Este proceso se repite hasta que todos los subárboles se hayan completado, o se hayan intercambiado demasiados paquetes (para evitar bucles).

El método bulkwalk() devuelve una matriz que contiene una matriz de Varbinds, una por cada variable solicitada, en el orden de las solicitudes de variables. En caso de error, bulkwalk() devuelve undef y establece $sess->ErrorStr y $sess->ErrorNum. Si se proporciona una devolución de llamada, bulkwalk() devuelve el ID de la solicitud SNMP y regresa inmediatamente. La devolución de llamada se llamará con la lista de argumentos proporcionada y la lista de variables devueltas.

Nota: Dado que el cliente debe "descubrir" que el árbol está completo comparando las variables devueltas con las que se solicitaron, existe una posible "trampa" al usar el valor max-repeaters. Considere el siguiente código para imprimir una lista de interfaces y recuentos de bytes:

$numInts = $sess->get('ifNumber.0');
($desc, $in, $out) = $sess->bulkwalk(0, $numInts,
              [['ifDescr'], ['ifInOctets'], ['ifOutOctets']]);
for $i (0..($numInts - 1)) {
    printf "Interfaz %4s: %s inOctets, %s outOctets\n",
              $$desc[$i]->val, $$in[$i]->val, $$out[$i]->val;
}

Este código generará *dos* solicitudes al agente: la primera para obtener los valores de la interfaz y la segunda para descubrir que toda la información estaba en el primer paquete. Para evitar esto, use '$numInts + 1' para el valor max_repeaters. Esto le pide al agente que incluya una variable adicional (no relacionada) que señale el final del subárbol, lo que permite a bulkwalk() determinar que la solicitud está completa.

$results = $sess->gettable(<OID TABLA>, <OPCIONES>)
Esto recuperará una tabla completa de datos y devolverá una referencia de hash a esos datos. La referencia de hash devuelta tendrá los índices de los sufijos OID para los datos del índice como clave. El valor de cada entrada será otro hash que contiene los datos para una fila determinada. Las claves de ese hash serán los nombres de las columnas y los valores serán los datos.

Ejemplo:

#!/usr/bin/perl
use SNMP;
use Data::Dumper;
my $s = new SNMP::Session(DestHost => 'localhost');
print Dumper($s->gettable('ifTable'));

En mi máquina produce:

$VAR1 = {
          '6' => {
                   'ifMtu' => '1500',
                   'ifPhysAddress' => 'PV',
                   # ...
                   'ifInUnknownProtos' => '0'
                 },
          '4' => {
                   'ifMtu' => '1480',
                   'ifPhysAddress' => '',
                   # ...
                   'ifInUnknownProtos' => '0'
                 },
          # ...
         };

Por defecto, intentará realizar la recuperación más optimizada posible. Solicitará varias columnas a la vez y utilizará GETBULK si es posible. Se pueden especificar algunas opciones pasando un hash de *OPCIONES* que contenga varios parámetros:

noindexes => 1
Instruye al código a no analizar los índices y colocar los resultados en el segundo hash. Si no necesita los datos del índice, esto será más rápido.
columns => [ colname1, ... ]
Esto especifica qué columnas recopilar. Por defecto, intentará recopilar todas las columnas definidas en la tabla MIB.
repeat => COUNT
Especifica una cuenta de repetición de GETBULK COUNT. Es decir, solicitará esta cantidad de varbinds por columna al usar la operación GETBULK. Reducir esto significará paquetes más pequeños que pueden ayudar a atravesar algunos sistemas. Por defecto, este valor se calcula e intenta adivinar lo que cabrá en todos los resultados dentro de 1000 bytes. Este cálculo es bastante seguro, esperemos, pero puede aumentar o disminuir el número usando esta opción si se desea. En redes con pérdidas, querrá asegurarse de que los paquetes no se fragmenten y reducir este valor es una forma de ayudar a ello.
predeterminado '0', controla el nivel de salida de depuración dentro del módulo SNMP y libsnmp

nivel 1 más snmp_set_do_debugging(1)

$SNMP::dump_packet

SNMP::register_debug_tokens()
Permite registrar uno o más tokens de depuración, al igual que la opción -D de snmpd. Cada token de depuración habilita un grupo de sentencias de depuración. Un ejemplo: SNMP::register_debug_tokens("tdomain,netsnmp_unix");

%SNMP::MIB

un hash enlazado para acceder a la información MIB analizada. Después de que la MIB ha sido cargada, este hash permite el acceso a los metadatos de la MIB analizada (es decir, la estructura de la MIB (esquema)). El hash devuelve referencias bendecidas a objetos SNMP::MIB::NODE que representan un único atributo MIB. Los nodos se pueden obtener con múltiples formatos de 'clave': el nombre de la hoja (por ejemplo, sysDescr) o un nombre completamente/parcialmente calificado (por ejemplo, system.sysDescr) o un OID numérico completamente calificado. El objeto nodo devuelto admite los siguientes campos:

objectID
OID decimal con puntos completamente calificado
label
identificador textual de la hoja (por ejemplo, 'sysDescr')
subID
componente OID numérico de la hoja de objectID (por ejemplo, '1')
moduleID
identificador textual del módulo (por ejemplo, 'RFC1213-MIB')
parent
nodo padre
children
referencia de matriz de nodos hijos
nextNode
siguiente nodo léxico (¡ERROR! no devuelve en orden léxico)
type
devuelve el tipo de aplicación (ver getType para los valores)
access
devuelve ACCESS (ReadOnly, ReadWrite, WriteOnly, NoAccess, Notify, Create)
status
devuelve STATUS (Mandatory, Optional, Obsolete, Deprecated)
syntax
devuelve 'textualConvention' si está definido, de lo contrario 'type'
textualConvention
devuelve TEXTUAL-CONVENTION
TCDescription
devuelve el campo DESCRIPTION de TEXTUAL-CONVENTION.
units
devuelve UNITS
hint
devuelve HINT
enums
devuelve referencia hash {tag => num, ...}
ranges
devuelve referencia de matriz de referencia hash [{low => num, high => num}, ...]
description
devuelve DESCRIPTION ($SNMP::save_descriptions debe establecerse antes de la inicialización/análisis de MIB)
reference
devuelve la cláusula REFERENCE
indexes
devuelve los objetos de la cláusula INDEX
implied
devuelve verdadero si el último objeto de INDEX es IMPLICIT

Funciones MIB

&SNMP::setMib(<archivo>)
permite el análisis dinámico de la mib y la especificación explícita del archivo mib independientemente de las variables de entorno. llamado sin argumentos actúa como initMib, cargando las MIB indicadas por las variables de entorno (ver documentación de la api mib de Net-SNMP). pasar un segundo argumento distinto de cero fuerza la liberación de la mib anterior y su reemplazo (Nota: el segundo argumento no funciona ya que la liberación de la Mib anterior es más compleja que antes).
&SNMP::initMib()
llama a la función init_mib de la biblioteca si la Mib aún no se ha cargado; no hace nada si la Mib ya está cargada. analizará directorios y cargará módulos de acuerdo con las variables de entorno descritas en la documentación de Net-SNMP. (ver man mib_api, MIBDIRS, MIBS, MIBFILE(S), etc.)
&SNMP::addMibDirs(<dir>,...)
llama a add_mibdir de la biblioteca para cada directorio proporcionado. provocará que el directorio(s) se agregue a la lista interna y esté disponible para su búsqueda en llamadas posteriores a loadModules
&SNMP::addMibFiles(<archivo>,...)
llama a la función read_mib de la biblioteca. El(los) archivo(s) proporcionado(s) se leerá(n) y todas las definiciones de módulos Mib contenidas en él(ellos) se agregarán a la estructura del árbol mib interno
&SNMP::loadModules(<mod>,...)
llama a la función read_module de la biblioteca. El(los) módulo(s) proporcionado(s) se buscará(n) en los mibdirs actuales y se agregará(n) a la estructura del árbol mib interno. Pasar el <mod> especial, 'ALL', provocará la carga de todos los módulos conocidos.
&SNMP::unloadModules(<mod>,...)
*No Implementado*
&SNMP::translateObj(<var>[,arg,[arg]])
convertirá una etiqueta de objeto de texto a un OID y viceversa. Cualquier sufijo iid se conservará numéricamente. El comportamiento predeterminado al convertir un OID numérico a formato de texto es devolver solo el identificador de la hoja (por ejemplo, 'sysDescr'), pero cuando $SNMP::use_long_names no es cero o se proporciona un segundo argumento distinto de cero, devolverá un identificador textual más largo. Un tercer argumento opcional distinto de cero hará que el nombre del módulo se anteponga al nombre de texto (por ejemplo, 'SNMPv2-MIB::sysDescr'). Al convertir un objeto de texto, se utiliza la opción $SNMP::best_guess. Si no se carga ninguna MIB al llamar y $SNMP::auto_init_mib está habilitado, la MIB se cargará. Devolverá 'undef' en caso de fallo.
&SNMP::getType(<var>)
devuelve el tipo de datos SNMP para el identificador textual dado OBJECTID, OCTETSTR, INTEGER, NETADDR, IPADDR, COUNTER GAUGE, TIMETICKS, OPAQUE, o undef
&SNMP::mapEnum(<var>)
convierte un valor entero a una etiqueta de enumeración definida en Mib o convierte una etiqueta a entero dependiendo de la entrada. la función devolverá el valor entero o etiqueta correspondiente para un atributo y valor MIB dados. La función detectará en qué dirección realizar la conversión. Se admiten varios formatos de argumento
$val = SNMP::mapEnum($varbind);
donde $varbind es SNMP::Varbind o equivalente. nota: $varbind se actualizará
$val = SNMP::mapEnum('ipForwarding', 'forwarding');
$val = SNMP::mapEnum('ipForwarding', 1);

Solución de Problemas

Si ocurren problemas, hay varias áreas en las que se puede buscar para acotar las posibilidades.

El primer paso debe ser probar la instalación de Net-SNMP independientemente de la interfaz Perl5 SNMP.

Intente ejecutar las aplicaciones de la distribución Net-SNMP.

Asegúrese de que su agente (snmpd) se esté ejecutando y configurado correctamente con acceso de lectura-escritura para la comunidad que está utilizando.

Asegúrese de que sus MIBs estén instaladas y que las variables de entorno estén configuradas adecuadamente (ver man mib_api)

Asegúrese de eliminar las instalaciones antiguas de net-snmp y de que las cabeceras y bibliotecas de instalaciones antiguas de CMU no se utilicen por error.

Si el problema ocurre durante la compilación/enlace, verifique que la biblioteca snmp que se está enlazando sea realmente la biblioteca Net-SNMP (ha habido conflictos de nombres con bibliotecas snmp existentes).

Verifique también que los archivos de cabecera sean correctos y estén actualizados.

A veces, es necesario compilar la biblioteca Net-SNMP con 'position-independent-code' habilitado (específicamente HPUX).

Si no puede resolver el problema, puede publicar en comp.lang.perl.modules o net-snmp-users@net-snmp-users@lists.sourceforge.net

SNMP(3pm)

NAME

SNMP - Perl interface to the Net-SNMP library

SYNOPSIS

use SNMP;

# SNMPv1/v2c session
my $session = SNMP::Session->new(
    -hostname   => 'some.host.name',
    -community  => 'public',
    -version    => '2c', # or '1'
    -port       => 161,
    -timeout    => 5,
    -retries    => 2,
);

my ($varbindlist) = $session->get_request(
    -varbindlist => ['.1.3.6.1.2.1.1.1.0'] # sysDescr.0
);

# SNMPv3 session
my $session = SNMP::Session->new(
    -hostname   => 'some.host.name',
    -version    => '3',
    -port       => 161,
    -timeout    => 5,
    -retries    => 2,
    -username   => 'someuser',
    -authprotocol => 'MD5',
    -authkey    => 'somepassword',
    -privprotocol => 'DES',
    -privkey    => 'someotherpassword',
);

# Trap session
my $trap = SNMP::TrapSession->new(
    -hostname => 'some.host.name',
    -port     => 162,
);

$trap->trap_request(
    -trap       => 'coldStart', # Or use OID
    -varbindlist => [ # Mandatory
        ['SNMPv2-MIB', 'sysUpTime', 0, 'TimeTicks', 12345],
        ['SNMPv2-MIB', 'snmpTrapOID', 0, 'OID', '.1.3.6.1.4.1.9.1.1.1'],
    ],
);

# Other functions
my $oids = SNMP->oid_lex_sort(@oids);
my $str = SNMP->oid_to_string($oid);
my $oid = SNMP->string_to_oid($str);

DESCRIPTION

This module provides a Perl interface to the Net-SNMP library. It allows Perl programs to perform SNMP operations like GET, GETNEXT, SET, WALK, and TRAP transmissions.

The module exports two main classes: SNMP::Session for performing SNMP requests and SNMP::TrapSession for sending SNMP traps.

It also provides utility functions for OID manipulation and access to MIB information.

SNMP::Session

The SNMP::Session class is used to establish an SNMP session and perform various SNMP operations.

new

Creates a new SNMP session object. It takes a hash of options:

  • -hostname: The hostname or IP address of the target SNMP agent. (Required)
  • -community: The SNMP community string. Used for SNMPv1 and v2c. (Required for v1/v2c)
  • -version: The SNMP version to use ('1', '2c', or '3'). Defaults to '2c'.
  • -port: The UDP port to connect to. Defaults to 161.
  • -timeout: The timeout in seconds for each retry. Defaults to 5.
  • -retries: The number of retries to attempt. Defaults to 2.
  • -username: Username for SNMPv3 authentication.
  • -authprotocol: Authentication protocol for SNMPv3 (e.g., 'MD5', 'SHA').
  • -authkey: Password for SNMPv3 authentication.
  • -privprotocol: Privacy protocol for SNMPv3 (e.g., 'DES', 'AES').
  • -privkey: Password for SNMPv3 privacy.
  • -nonsecLevel: Security level for SNMPv3 (noAuthNoPriv, authNoPriv, authPriv).

get_request

Performs an SNMP GET request.

my ($varbindlist) = $session->get_request(
    -varbindlist => \@varbinds
);

@varbinds is an array of OIDs or variable names. Returns a reference to an array of OID-value pairs.

getnext_request

Performs an SNMP GETNEXT request.

my ($varbindlist) = $session->getnext_request(
    -varbindlist => \@varbinds
);

Similar to get_request.

set_request

Performs an SNMP SET request.

my ($varbindlist) = $session->set_request(
    -varbindlist => \@varbinds
);

@varbinds is an array of OID-value pairs to set. Returns a reference to an array of OID-value pairs indicating success or failure.

get_bulk_request

Performs an SNMP GETBULK request (SNMPv2c and v3 only).

my ($varbindlist) = $session->get_bulk_request(
    -varbindlist => \@varbinds,
    -nonrepeaters => 0,
    -maxrepetitions => 10
);

Returns a reference to an array of OID-value pairs.

walk_request

Performs an SNMP WALK operation.

my ($varbindlist) = $session->walk_request(
    -varbindlist => \@varbinds
);

Returns a reference to an array of all OID-value pairs in the specified subtree.

error

Returns the last error message.

my $error_msg = $session->error();

SNMP::TrapSession

The SNMP::TrapSession class is used to send SNMP traps.

new

Creates a new trap session object. It takes a hash of options:

  • -hostname: The hostname or IP address of the trap receiver. (Required)
  • -port: The UDP port to send traps to. Defaults to 162.
  • -version: The SNMP version to use ('1', '2c', or '3'). Defaults to '2c'.
  • -community: The community string to use.
  • SNMPv3 options are also supported similar to SNMP::Session.

trap_request

Sends an SNMP trap.

my $status = $trap->trap_request(
    -trap       => $trap_oid_or_name,
    -varbindlist => \@varbinds
);

-trap specifies the trap type (e.g., 'coldStart', 'warmStart', or an OID). @varbinds is a required array of OID-value pairs to include in the trap.

The function returns a status code indicating success or failure.

Acceptable variable formats:

When passing variable bindings to the methods, you can use several formats:

  • [ OID_string, value ]: e.g., ['.1.3.6.1.2.1.1.1.0', 'My System Description']
  • [ MIB_module, MIB_name, instance, value ]: e.g., ['SNMPv2-MIB', 'sysDescr', 0, 'My System Description']
  • [ MIB_module, MIB_name, instance, type, value ]: e.g., ['SNMPv2-MIB', 'sysDescr', 0, 'STRING', 'My System Description']

Value types can be specified as strings like 'STRING', 'INTEGER', 'OID', 'IPADDRESS', 'GAUGE', 'COUNTER', 'TIMETICKS', etc.

Acceptable callback formats

Callbacks can be used for asynchronous operations. The callback function will be called with the result of the operation.

sub my_callback {
    my ($session, $result) = @_;
    if ($session->error()) {
        print "Error: " . $session->error() . "\n";
    } else {
        # Process $result
    }
}
$session->get_request(-varbindlist => \@oids, -callback => \&my_callback);

SNMP package variables and functions

The SNMP module also exports some utility functions and variables directly:

  • SNMP::error: Returns the last global error message.
  • SNMP::version: Returns the version of the Net-SNMP library linked against.
  • SNMP::use_cached_mib_modules(1): Enables/disables MIB module caching.
  • SNMP::load_mib( module1, module2, ... ): Explicitly loads MIB modules.

%SNMP::MIB

Provides access to loaded MIB information.

get_mib_identifier

Retrieves information about a MIB object.

my $mib_info = SNMP::MIB::get_mib_identifier('sysDescr');
# $mib_info might contain: { name => 'sysDescr', module => 'SNMPv2-MIB', oid => '.1.3.6.1.2.1.1.1', syntax => 'DisplayString', max_access => 'read-only', status => 'mandatory' }

MIB Functions

  • SNMP::MIB::mib2string( $oid ): Converts an OID to its symbolic name.
  • SNMP::MIB::mib2oid( $symbolic_name ): Converts a symbolic name to its OID.

Exported SNMP utility functions

  • SNMP::oid_lex_sort(@oids): Lexicographically sorts an array of OIDs.
  • SNMP::oid_to_string($oid): Converts an OID array reference to a string.
  • SNMP::string_to_oid($string): Converts an OID string to an array reference.

Trouble Shooting

If you encounter issues, check the following:

  • Ensure the Net-SNMP libraries are correctly installed and accessible.
  • Verify network connectivity to the target host.
  • Check firewall rules.
  • Correctly specify community strings or SNMPv3 credentials.
  • Ensure MIB files are available if using symbolic names.
  • Use SNMP::Session->error() to get specific error messages.
