NOMBRE

Smokeping::probes::TelnetJunOSPing - Sonda TelnetJunOSPing de Juniper JunOS para SmokePing

SINOPSIS

*** Probes ***
+TelnetJunOSPing
forks = 5
offset = 50%
packetsize = 100
step = 300
timeout = 15
# Las siguientes variables se pueden anular en cada sección de destino
/^influx_.+/ = influx_location = En el sótano
junospass = contraseña # obligatorio
junosuser = usuario # obligatorio
pings = 5
psource = 192.168.2.129
source = 192.168.2.1 # obligatorio
# [...]
*** Targets ***
probe = TelnetJunOSPing # si esta debe ser la sonda predeterminada
# [...]
+ mi_destino
# probe = TelnetJunOSPing # si la sonda predeterminada es otra
host = mi.host
/^influx_.+/ = influx_location = En el sótano
junospass = contraseña # obligatorio
junosuser = usuario # obligatorio
pings = 5
psource = 192.168.2.129
source = 192.168.2.1 # obligatorio

DESCRIPCIÓN

Integra Juniper JunOS como una sonda en smokeping. Utiliza el protocolo telnet para ejecutar un ping desde un dispositivo JunOS (origen) a otro dispositivo (host). Esta sonda utiliza básicamente el "ping extendido" de Juniper JunOS. Tiene la opción de especificar desde qué interfaz se origina el ping.

VARIABLES

Variables admitidas específicas de la sonda:

forks
Ejecuta este número de procesos concurrentes como máximo.

Valor de ejemplo: 5

Valor predeterminado: 5

offset
Si ejecuta muchas sondas concurrentemente, es posible que desee evitar que toquen su red al mismo tiempo. Usando el parámetro de desplazamiento específico de la sonda, puede cambiar el momento en que se ejecutará cada sonda. El desplazamiento se especifica en % del intervalo total, o alternativamente como 'random', y se usa el desplazamiento de la sección 'General' si no se especifica nada aquí. Tenga en cuenta que esto NO influye en los RRD en sí, es solo una cuestión de cuándo se inicia la adquisición de datos. (Esta variable solo es aplicable si la variable 'concurrentprobes' está establecida en la sección 'General'.)

Valor de ejemplo: 50%

packetsize
La opción (opcional) packetsize permite configurar el tamaño del paquete para los pings enviados.

Valor predeterminado: 100

step
Duración del intervalo base que esta sonda debe usar, si es diferente del especificado en la sección 'Database'. Tenga en cuenta que el paso en los archivos RRD es fijo cuando se generan originalmente, y si cambia el parámetro de paso después, deberá eliminar los archivos RRD antiguos o convertirlos de alguna manera. (Esta variable solo es aplicable si la variable 'concurrentprobes' está establecida en la sección 'General'.)

Valor de ejemplo: 300

timeout
Cuánto tarda un 'ping' individual como máximo.

Valor de ejemplo: 15

Valor predeterminado: 5

Variables admitidas específicas del destino:

/^influx_.+/
Esta es una etiqueta que se enviará a influxdb y no tiene impacto en la medición de la sonda. El nombre de la etiqueta se enviará sin el prefijo "influx_", que se reemplazará con "tag_". Las etiquetas se pueden utilizar para filtrar.

Valor de ejemplo: influx_location = En el sótano

junospass
La opción junospass permite especificar la contraseña del nombre de usuario especificado con la opción junosuser.

Valor de ejemplo: contraseña

Esta configuración es obligatoria.

junosuser
La opción junosuser permite especificar un nombre de usuario que tenga capacidad de ping en el dispositivo JunOS.

Valor de ejemplo: usuario

Esta configuración es obligatoria.

pings
Cuántos pings se enviarán a cada destino, si es diferente del valor global especificado en la sección Database. Tenga en cuenta que el número de pings en los archivos RRD es fijo cuando se generan originalmente, y si cambia este parámetro posteriormente, deberá eliminar los archivos RRD antiguos o convertirlos de alguna manera.

Valor de ejemplo: 5

psource
La opción (opcional) psource especifica una dirección IP o interfaz alternativa desde la cual desea originar sus pings. Los enrutadores pueden tener muchas, muchas direcciones IP e interfaces. Cuando hace ping desde un enrutador, tiene la capacidad de elegir desde qué interfaz y/o qué dirección IP se origina el ping. Especificar una IP/interfaz no especifica necesariamente la interfaz desde la cual saldrá el ping, pero especificará de qué dirección parecerán provenir los paquetes. Si se omite esta opción, el dispositivo JunOS originará el paquete automáticamente basándose en el enrutamiento y/o las métricas. Si esto no tiene sentido para usted, simplemente omítalo.

Valor de ejemplo: 192.168.2.129

source
La opción source especifica el dispositivo JunOS al que nos conectamos por telnet. Esta es una dirección IP de un dispositivo JunOS para la cual usted/su servidor: 1) Tiene la capacidad de conectarse por telnet. 2) Tiene un nombre de usuario y contraseña válidos.

Valor de ejemplo: 192.168.2.1

Esta configuración es obligatoria.

NOTAS

Configuración de JunOS

El dispositivo JunOS debe tener configurado un nombre de usuario/contraseña, así como la capacidad de conectarse a VTY(s).

Algunos dispositivos JunOS tienen un máximo de 5 VTY disponibles, así que tenga cuidado de no alcanzar un límite con la variable 'forks'.

Requisitos

Este módulo requiere el módulo Net::Telnet para perl. Normalmente se incluye en la mayoría de los sistemas operativos más recientes que incluyen perl.

Depuración

Hay un código de depuración MUY rudimentario incorporado en este módulo (se basa en el código de depuración incluido en Net::Telnet). Registrará información en tres archivos: "TIPreturn", "TIPoutlog" y "TIPdump". Estos archivos se escribirán en su directorio de trabajo actual (CWD). Puede cambiar los nombres de estos archivos por algo más significativo para usted.

Autenticación de contraseña

Debe tener en cuenta que el método de autenticación de telnet utiliza transmisiones de texto plano... lo que significa que sin medidas de seguridad de red adecuadas, alguien podría interceptar su nombre de usuario y contraseña en la red. Puede que intente incorporar SSH en una versión futura de este módulo, pero es muy poco probable. Ahora mismo, SSH añade una gran sobrecarga de procesamiento a un enrutador y no es increíblemente fácil de implementar en perl.

Habiendo dicho esto, no tenga demasiado miedo de telnet. Recuerde, el módulo original JunOSPing utilizaba RSH, que es aún más aterrador de usar desde una perspectiva de seguridad.

Tamaño del paquete de ping

La página del manual de FPing dice lo siguiente sobre el tamaño del paquete de ping:

Número de bytes de datos de ping a enviar. El tamaño mínimo (normalmente 12) deja espacio para los datos que fping necesita para hacer su trabajo (número de secuencia, marca de tiempo). El tamaño de datos recibido reportado incluye la cabecera IP (normalmente 20 bytes) y la cabecera ICMP (8 bytes), por lo que el tamaño total mínimo es de 40 bytes. El valor predeterminado es 56, como en ping. El máximo es el tamaño máximo teórico del datagrama IP (64K), aunque la mayoría de los sistemas lo limitan a un número más pequeño y dependiente del sistema.
