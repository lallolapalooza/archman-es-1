NOMBRE

Smokeping::probes::TCPPing - Sonda TCPPing para SmokePing

SINOPSIS

*** Sondas ***
+TCPPing
binary = /usr/bin/tcpping # obligatorio
forks = 5
offset = 50%
step = 300
timeout = 15
# Las siguientes variables pueden ser anuladas en cada sección de destino
/^influx_.+/ = influx_location = En el sótano
pings = 5
port = 80
# [...]
*** Destinos ***
probe = TCPPing # si esta debe ser la sonda predeterminada
# [...]
+ mi_destino
# probe = TCPPing # si la sonda predeterminada es otra
host = mi.host
/^influx_.+/ = influx_location = En el sótano
pings = 5
port = 80

DESCRIPCIÓN

Integra TCPPing como sonda en smokeping. La variable binary debe apuntar a tu copia del programa TCPPing. Si aún no está instalado en tu sistema, puedes obtenerlo de https://github.com/deajan/tcpping.

La opción (opcional) port te permite configurar el puerto para los pings enviados. El manual de TCPPing dice lo siguiente sobre este tema:

El problema es que con el uso generalizado de firewalls en la Internet moderna, muchos de los paquetes que traceroute(8) envía terminan siendo filtrados, haciendo imposible rastrear completamente la ruta hasta el destino. Sin embargo, en muchos casos, estos firewalls permiten paquetes TCP entrantes a puertos específicos que los hosts detrás del firewall están escuchando. Al enviar paquetes TCP SYN en lugar de paquetes UDP o ICMP ECHO, tcptraceroute puede eludir los filtros de firewall más comunes.

Cabe señalar que tcptraceroute nunca establece completamente una conexión TCP con el host de destino. Si el host no está escuchando conexiones entrantes, responderá con un RST indicando que el puerto está cerrado. Si el host responde con un SYN|ACK, se sabe que el puerto está abierto, y el kernel en el que se ejecuta tcptraceroute envía un RST para cerrar la conexión sin completar el apretón de manos de tres vías. Esta es la misma técnica de escaneo semiabierto que nmap(1) usa cuando se le pasa la opción -sS.

VARIABLES

Variables admitidas específicas de la sonda:

binary
La ubicación de tu script tcpping.

Valor de ejemplo: /usr/bin/tcpping

Esta configuración es obligatoria.

forks
Ejecuta este número de procesos concurrentes como máximo

Valor de ejemplo: 5

Valor predeterminado: 5

offset
Si ejecutas muchas sondas concurrentemente, es posible que desees evitar que golpeen tu red al mismo tiempo. Usando el parámetro de desplazamiento específico de la sonda, puedes cambiar el momento en que se ejecutará cada sonda. El desplazamiento se especifica en % del intervalo total, o alternativamente como 'random', y se usa el desplazamiento de la sección 'General' si no se especifica nada aquí. Ten en cuenta que esto NO influye en los rrds en sí, es solo una cuestión de cuándo se inicia la adquisición de datos. (Esta variable solo es aplicable si la variable 'concurrentprobes' está configurada en la sección 'General'.)

Valor de ejemplo: 50%

step
Duración del intervalo base que esta sonda debe usar, si es diferente del especificado en la sección 'Database'. Ten en cuenta que el paso en los archivos RRD se fija cuando se generan originalmente, y si cambias el parámetro step después, tendrás que eliminar los archivos RRD antiguos o convertirlos de alguna manera. (Esta variable solo es aplicable si la variable 'concurrentprobes' está configurada en la sección 'General'.)

Valor de ejemplo: 300

timeout
Cuánto tiempo tarda un 'ping' individual como máximo

Valor de ejemplo: 15

Valor predeterminado: 5

Variables admitidas específicas del destino:

/^influx_.+/
Esta es una etiqueta que se enviará a influxdb y no tiene impacto en la medición de la sonda. El nombre de la etiqueta se enviará sin el prefijo "influx_", que se reemplazará por "tag_" en su lugar. Las etiquetas se pueden usar para filtrar.

Valor de ejemplo: influx_location = En el sótano

pings
Cuántos pings se deben enviar a cada destino, si es diferente del valor global especificado en la sección Database. Ten en cuenta que el número de pings en los archivos RRD se fija cuando se generan originalmente, y si cambias este parámetro después, tendrás que eliminar los archivos RRD antiguos o convertirlos de alguna manera.

Valor de ejemplo: 5

port
El puerto TCP que la sonda debe medir.

Valor de ejemplo: 80
