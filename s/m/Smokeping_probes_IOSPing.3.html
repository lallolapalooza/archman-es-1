NOMBRE

Smokeping::probes::IOSPing - Sonda IOS de Cisco para SmokePing

SINOPSIS

*** Sondas ***
+IOSPing
binary = /usr/bin/rsh # obligatorio
forks = 5
offset = 50%
packetsize = 56
step = 300
timeout = 15
# Las siguientes variables se pueden anular en cada sección de destino
/^influx_.+/ = influx_location = En el sótano
ioshost = mi.router.cisco # obligatorio
iosint = Ethernet 1/0
iosuser = admin
pings = 5
# [...]
*** Destinos ***
probe = IOSPing # si esta debe ser la sonda predeterminada
# [...]
+ mi_destino
# probe = IOSPing # si la sonda predeterminada es otra
host = mi.host
/^influx_.+/ = influx_location = En el sótano
ioshost = mi.router.cisco # obligatorio
iosint = Ethernet 1/0
iosuser = admin
pings = 5

DESCRIPCIÓN

Integra Cisco IOS como una sonda en smokeping. Utiliza el protocolo rsh / remsh para ejecutar un ping desde un dispositivo IOS.

VARIABLES

Variables específicas de la sonda admitidas:

binary
La opción binary especifica la ruta del binario que se utilizará para conectarse al dispositivo IOS. Los binarios comúnmente utilizados son /usr/bin/rsh y /usr/bin/remsh, aunque cualquier script o binario debería funcionar si se puede llamar como 
/ruta/a/binario [ -l usuario ] router ping

para producir el diálogo de ping de IOS en stdin y stdout.

Valor de ejemplo: /usr/bin/rsh

Esta configuración es obligatoria.

forks
Ejecuta este número de procesos concurrentes como máximo

Valor de ejemplo: 5

Valor predeterminado: 5

offset
Si ejecuta muchas sondas concurrentemente, puede que desee evitar que golpeen su red al mismo tiempo. Usando el parámetro de desplazamiento específico de la sonda, puede cambiar el momento en que se ejecutará cada sonda. El desplazamiento se especifica en % del intervalo total, o alternativamente como 'random', y se utiliza el desplazamiento de la sección 'General' si no se especifica nada aquí. Tenga en cuenta que esto NO influye en los RRD en sí, es solo una cuestión de cuándo se inicia la adquisición de datos. (Esta variable solo es aplicable si la variable 'concurrentprobes' está configurada en la sección 'General'.)

Valor de ejemplo: 50%

packetsize
La opción (opcional) packetsize le permite configurar el tamaño del paquete para los pings enviados.

Valor predeterminado: 56

step
Duración del intervalo base que debe utilizar esta sonda, si es diferente del especificado en la sección 'Database'. Tenga en cuenta que el paso en los archivos RRD se fija cuando se generan originalmente, y si cambia el parámetro de paso después, tendrá que eliminar los archivos RRD antiguos o convertirlos de alguna manera. (Esta variable solo es aplicable si la variable 'concurrentprobes' está configurada en la sección 'General'.)

Valor de ejemplo: 300

timeout
Cuánto tarda un solo 'ping' como máximo

Valor de ejemplo: 15

Valor predeterminado: 5

Variables específicas del destino admitidas:

/^influx_.+/
Esta es una etiqueta que se enviará a influxdb y no tiene impacto en la medición de la sonda. El nombre de la etiqueta se enviará sin el prefijo "influx_", que se reemplazará por "tag_" en su lugar. Las etiquetas se pueden utilizar para filtrar.

Valor de ejemplo: influx_location = En el sótano

ioshost
La opción ioshost especifica el dispositivo IOS que debe utilizarse para el ping.

Valor de ejemplo: mi.router.cisco

Esta configuración es obligatoria.

iosint
La opción (opcional) iosint permite especificar la dirección de origen o interfaz en el dispositivo IOS. El valor debe ser una dirección IP o un nombre de interfaz como "Ethernet 1/0". Si se omite esta opción, el dispositivo IOS elegirá la dirección IP de la interfaz de salida a utilizar.

Valor de ejemplo: Ethernet 1/0

iosuser
La opción (opcional) iosuser permite especificar el nombre de usuario remoto del dispositivo IOS. Si se omite esta opción, el nombre de usuario predeterminado es el usuario predeterminado utilizado por el comando remsh (generalmente el usuario que ejecuta el comando remsh, es decir, el usuario que ejecuta SmokePing).

Valor de ejemplo: admin

pings
Cuántos pings se deben enviar a cada destino, si es diferente del valor global especificado en la sección Database. Tenga en cuenta que el número de pings en los archivos RRD se fija cuando se generan originalmente, y si cambia este parámetro después, tendrá que eliminar los archivos RRD antiguos o convertirlos de alguna manera.

Valor de ejemplo: 5

NOTAS

Configuración IOS

El dispositivo IOS debe tener rsh habilitado y una confianza apropiada definida, por ejemplo:

!
ip rcmd rsh-enable
ip rcmd remote-host smoke 192.168.1.2 smoke enable
!

Algunos dispositivos IOS tienen un máximo de 5 VTYs disponibles, así que tenga cuidado de no alcanzar un límite con la variable 'forks'.

Autenticación de contraseña

No es posible utilizar la autenticación de contraseña con rsh o remsh debido a limitaciones fundamentales del protocolo.

Tamaño del paquete ping

La página del manual de FPing tiene lo siguiente sobre el tema del tamaño del paquete ping:

Número de bytes de datos de ping a enviar. El tamaño mínimo (normalmente 12) deja espacio para los datos que fping necesita para hacer su trabajo (número de secuencia, marca de tiempo). El tamaño de los datos recibidos reportados incluye la cabecera IP (normalmente 20 bytes) y la cabecera ICMP (8 bytes), por lo que el tamaño total mínimo es de 40 bytes. El valor predeterminado es 56, como en ping. El máximo es el tamaño máximo teórico del datagrama IP (64K), aunque la mayoría de los sistemas lo limitan a un número más pequeño y dependiente del sistema.
