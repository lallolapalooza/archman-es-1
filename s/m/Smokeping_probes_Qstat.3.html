NOMBRE

Smokeping::probes::Qstat - Sonda Qstat para SmokePing

SINOPSIS

*** Sondas ***
+Qstat
binary = /usr/bin/quakestatba # obligatorio
forks = 5
game = nexuizs
mininterval = 0.1
offset = 50%
port = 27970
sourceaddress = 192.168.0.1
sourceport = 9923-9943
step = 300
timeout = 15
# Las siguientes variables pueden ser anuladas en cada sección de destino
/^influx_.+/ = influx_location = En el sótano
pings = 5
# [...]
*** Destinos ***
probe = Qstat # si esta debe ser la sonda predeterminada
# [...]
+ mi_destino
# probe = Qstat # si la sonda predeterminada es otra
host = mi.servidor
/^influx_.+/ = influx_location = En el sótano
pings = 5

DESCRIPCIÓN

Integra Qstat como una sonda en smokeping. La variable binary debe apuntar a tu copia del programa Qstat.

Asegúrate de configurar tus pings a 10, la mayoría de los servidores Quake parecen limitar después de 10 pings rápidos.

Configura el parámetro game para una de las opciones válidas para comprobar un tipo diferente

VARIABLES

Variables específicas de la sonda admitidas:

binary
La ubicación de tu binario quakestat.

Ejemplo de valor: /usr/bin/quakestatba

Esta configuración es obligatoria.

forks
Ejecutar este número de procesos concurrentes como máximo.

Ejemplo de valor: 5

Valor predeterminado: 5

game
Qué tipo de juego comprobar, del flag -default de quakestat.

Ejemplo de valor: nexuizs

Valor predeterminado: q3s

mininterval
La cantidad mínima de tiempo entre el envío de un paquete ping al destino.

Ejemplo de valor: 0.1

Valor predeterminado: 0.5

offset
Si ejecutas muchas sondas concurrentemente, es posible que desees evitar que golpeen tu red al mismo tiempo. Usando el parámetro de offset específico de la sonda, puedes cambiar el momento en que se ejecutará cada sonda. El offset se especifica en % del intervalo total, o alternativamente como 'random', y se utiliza el offset de la sección 'General' si no se especifica nada aquí. Ten en cuenta que esto NO influye en los propios rrds, es solo una cuestión de cuándo se inicia la adquisición de datos. (Esta variable solo es aplicable si la variable 'concurrentprobes' está configurada en la sección 'General'.)

Ejemplo de valor: 50%

port
El puerto del servidor de juegos a comprobar. También puede ser anulado añadiendo :port al parámetro host en la configuración del Destino.

Ejemplo de valor: 27970

sourceaddress
El parámetro "-srcip" de quakestat. De quakestat(1):

Enviar paquetes usando esta dirección IP

Ejemplo de valor: 192.168.0.1

sourceport
El parámetro "-srcport" de quakestat. De quakestat(1):

Enviar paquetes desde estos puertos de red

Ejemplo de valor: 9923-9943

step
Duración del intervalo base que esta sonda debe usar, si es diferente del especificado en la sección 'Database'. Ten en cuenta que el paso en los archivos RRD se fija cuando se generan originalmente, y si cambias el parámetro step después, tendrás que eliminar los archivos RRD antiguos o convertirlos de alguna manera. (Esta variable solo es aplicable si la variable 'concurrentprobes' está configurada en la sección 'General'.)

Ejemplo de valor: 300

timeout
Cuánto tiempo toma un 'ping' individual como máximo.

Ejemplo de valor: 15

Valor predeterminado: 5

Variables específicas de destino admitidas:

/^influx_.+/
Esta es una etiqueta que se enviará a influxdb y no tiene impacto en la medición de la sonda. El nombre de la etiqueta se enviará sin el prefijo "influx_", que será reemplazado por "tag_" en su lugar. Las etiquetas se pueden usar para filtrar.

Ejemplo de valor: influx_location = En el sótano

pings
Cuántos pings se deben enviar a cada destino, si es diferente del valor global especificado en la sección Database. Ten en cuenta que el número de pings en los archivos RRD se fija cuando se generan originalmente, y si cambias este parámetro después, tendrás que eliminar los archivos RRD antiguos o convertirlos de alguna manera.

Ejemplo de valor: 5
