NOMBRE

Smokeping::probes::SipSak - prueba de servidor sip

RESUMEN

Esta sonda envía mensajes OPTIONS a un servidor sip probando la latencia.

SINOPSIS

*** Probes ***
+SipSak
binary = /usr/bin/sipsak
forks = 5
offset = 50%
step = 300
timeout = 15
# Las siguientes variables se pueden sobrescribir en cada sección de destino
/^influx_.+/ = influx_location = En el sótano
keep_second = yes
params = --numeric --password=mysecret
pings = 5
port = 5061
sipsak_timeout = 2
user = nobody
# [...]
*** Targets ***
probe = SipSak # si esta debe ser la sonda predeterminada
# [...]
+ mytarget
# probe = SipSak # si la sonda predeterminada es otra
host = my.host
/^influx_.+/ = influx_location = En el sótano
keep_second = yes
params = --numeric --password=mysecret
pings = 5
port = 5061
sipsak_timeout = 2
user = nobody

DESCRIPCIÓN

La sonda utiliza la herramienta sipsak de http://sipsak.org/ para medir la latencia del servidor sip enviando un mensaje OPTIONS.

El comando sipsak admite un gran número de parámetros adicionales para afinar su funcionamiento. Utilice la variable params para configurarlos.

VARIABLES

Variables específicas de la sonda admitidas:

binary
La ubicación de su ejecutable echoping.

Valor predeterminado: /usr/bin/sipsak

forks
Ejecutar este número de procesos concurrentes como máximo.

Valor de ejemplo: 5

Valor predeterminado: 5

offset
Si ejecuta muchas sondas concurrentemente, es posible que desee evitar que golpeen su red al mismo tiempo. Usando el parámetro de offset específico de la sonda, puede cambiar el punto en el tiempo en que se ejecutará cada sonda. El offset se especifica en % del intervalo total, o alternativamente como 'random', y se utiliza el offset de la sección 'General' si no se especifica nada aquí. Tenga en cuenta que esto NO influye en los RRD en sí, es solo una cuestión de cuándo se inicia la adquisición de datos. (Esta variable solo es aplicable si la variable 'concurrentprobes' está establecida en la sección 'General'.)

Valor de ejemplo: 50%

step
Duración del intervalo base que esta sonda debe usar, si es diferente del especificado en la sección 'Database'. Tenga en cuenta que el paso en los archivos RRD se fija cuando se generan originalmente, y si cambia el parámetro de paso después, tendrá que eliminar los archivos RRD antiguos o convertirlos de alguna manera. (Esta variable solo es aplicable si la variable 'concurrentprobes' está establecida en la sección 'General'.)

Valor de ejemplo: 300

timeout
Cuánto tarda un solo 'ping' como máximo.

Valor de ejemplo: 15

Valor predeterminado: 5

Variables específicas del destino admitidas:

/^influx_.+/
Esta es una etiqueta que se enviará a influxdb y no tiene impacto en la medición de la sonda. El nombre de la etiqueta se enviará sin el prefijo "influx_", que se reemplazará con "tag_" en su lugar. Las etiquetas se pueden usar para filtrar.

Valor de ejemplo: influx_location = En el sótano

keep_second
Si OPTIONS es implementado realmente por el servidor, SipSak recibirá dos respuestas. Si esta opción está establecida, el tiempo de la segunda y final respuesta se tendrá en cuenta.

Valor de ejemplo: yes

params
Opciones adicionales de sipsak. Las opciones se dividirán por espacios.

Valor de ejemplo: --numeric --password=mysecret

pings
Cuántos pings se deben enviar a cada destino, si es diferente del valor global especificado en la sección Database. Tenga en cuenta que el número de pings en los archivos RRD se fija cuando se generan originalmente, y si cambia este parámetro después, tendrá que eliminar los archivos RRD antiguos o convertirlos de alguna manera.

Valor de ejemplo: 5

port
Usa un puerto no predeterminado para la conexión sip.

Valor de ejemplo: 5061

sipsak_timeout
Tiempo de espera para sipsak en segundos (fraccional).

Valor predeterminado: 2

user
Usuario a utilizar para la conexión sip.

Valor de ejemplo: nobody
