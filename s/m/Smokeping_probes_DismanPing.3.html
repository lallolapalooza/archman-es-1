NOMBRE

Smokeping::probes::DismanPing - Sonda DISMAN-PING-MIB para SmokePing

SINTAXIS

*** Sondas ***
+DismanPing
offset = 50%
pings = 15
step = 300
# Las siguientes variables se pueden anular en cada sección de destino
/^influx_.+/ = influx_location = En el sótano
ownerindex = smokeping
packetsize = 56
pinghost = pinger@router.example.com # obligatorio
pingsrc = 192.0.2.9
# [...]
*** Destinos ***
probe = DismanPing # si esta debe ser la sonda predeterminada
# [...]
+ mitarget
# probe = DismanPing # si la sonda predeterminada es otra cosa
host = mi.host
/^influx_.+/ = influx_location = En el sótano
ownerindex = smokeping
packetsize = 56
pinghost = pinger@router.example.com # obligatorio
pingsrc = 192.0.2.9

DESCRIPCIÓN

Utiliza DISMAN-PING-MIB para hacer que un sistema remoto envíe sondas.

VARIABLES

Variables específicas de la sonda admitidas:

offset
Si ejecuta muchas sondas simultáneamente, es posible que desee evitar que lleguen a su red al mismo tiempo. Usando el parámetro offset específico de la sonda, puede cambiar el punto en el tiempo en que se ejecutará cada sonda. El offset se especifica en % del intervalo total, o alternativamente como 'random', y se utiliza el offset de la sección 'General' si no se especifica nada aquí. Tenga en cuenta que esto NO influye en los RRD en sí, es solo una cuestión de cuándo se inicia la adquisición de datos. (Esta variable solo es aplicable si la variable 'concurrentprobes' está establecida en la sección 'General'.)

Ejemplo de valor: 50%

pings
Cuántos pings se deben enviar a cada destino. Tenga en cuenta que el valor máximo para DismanPing MIP es 15, que es menor que el predeterminado de SmokePing, por lo que esta clase tiene su propio valor predeterminado. Si su sección Database especifica un valor inferior a 15, también debe establecerlo para esta sonda. Tenga en cuenta que el número de pings en los archivos RRD se fija cuando se generan originalmente, y si cambia este parámetro después, tendrá que eliminar los archivos RRD antiguos o convertirlos de alguna manera.

Ejemplo de valor: 15

Valor predeterminado: 15

step
Duración del intervalo base que debe usar esta sonda, si es diferente del especificado en la sección 'Database'. Tenga en cuenta que el paso en los archivos RRD se fija cuando se generan originalmente, y si cambia el parámetro step después, tendrá que eliminar los archivos RRD antiguos o convertirlos de alguna manera. (Esta variable solo es aplicable si la variable 'concurrentprobes' está establecida en la sección 'General'.)

Ejemplo de valor: 300

Variables específicas del destino admitidas:

/^influx_.+/
Esta es una etiqueta que se enviará a influxdb y no tiene impacto en la medición de la sonda. El nombre de la etiqueta se enviará sin el prefijo "influx_", que se reemplazará con "tag_" en su lugar. Las etiquetas se pueden usar para filtrar.

Ejemplo de valor: influx_location = En el sótano

ownerindex
El OwnerIndex SNMP a usar al configurar la prueba. Al usar VACM, puede mapear a un Nombre de Seguridad o Nombre de Grupo de la entidad que ejecuta la prueba.

Por defecto, se establecerá en

Ejemplo de valor: smokeping

packetsize
El parámetro packetsize le permite configurar el tamaño del paquete para los pings enviados. El mínimo es 8, el máximo 65507. Use el mismo número que con fping si desea que los mismos tamaños de paquete se utilicen en la red.

Valor predeterminado: 56

pinghost
El parámetro pinghost (obligatorio) especifica el sistema remoto que ejecutará los pings, así como la cadena de comunidad SNMP en el dispositivo.

Ejemplo de valor: pinger@router.example.com

Esta configuración es obligatoria.

pingsrc
El parámetro pingsrc (opcional) especifica la dirección de origen a utilizar para los pings. Si se especifica, este parámetro debe identificar una dirección IP asignada a pinghost.

Ejemplo de valor: 192.0.2.9

NOTAS

NOMBRES DE MENÚ

Esta sonda utiliza el nombre del menú de una prueba como parte del índice único. Si el nombre del menú tiene más de 32 caracteres, se utilizan los últimos 32 caracteres para el índice. Las colisiones *no* se detectan y simplemente causan que los resultados de una prueba se utilicen para todos los nombres que colisionan.

CONFIGURACIÓN

Esta sonda requiere acceso de lectura/escritura a pingCtlTable. También requiere acceso de solo lectura a pingResultsTable y pingHistoryTable. La DISMAN-PING-MIB está estructurada de manera que es posible restringir por pingCtlOwnerIndex. Esta sonda utiliza un pingCtlOwnerIndex de "SP en hostname" como ownerindex por defecto; use ownerindex para configurar esto si es necesario.

EJEMPLO DE CONFIGURACIÓN JUNOS

Esta configuración permite a la comunidad "pinger" acceso de lectura/escritura a la DISMAN-PING-MIB completa, pero solo cuando se origina desde el administrador en 192.0.2.134.

snmp {
    view pingMIB {
        oid .1.3.6.1.2.1.80 include;
    }
    community pinger {
        view pingMIB;
        authorization read-write;
        clients {
            192.0.2.134/32;
        }
    }
}

NOTA SOBRE EJEMPLOS DE CONFIGURACIÓN

Esta configuración permite a la comunidad "pinger" acceso completo a la DISMAN-PING-MIB. Hay información en la descripción de pingCtlOwnerIndex en RFC 4560 (http://tools.ietf.org/html/rfc4560) sobre el uso de vacmViewTreeFamilyTable para restringir aún más el acceso. El autor no ha probado este método.
