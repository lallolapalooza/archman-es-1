NOMBRE

Smokeping::probes::TacacsPlus - una sonda de autenticación TacacsPlus para SmokePing

DESCRIPCIÓN GENERAL

Mide la latencia de autenticación TacacsPlus para SmokePing

SINOPSIS

*** Sondas ***
+TacacsPlus
forks = 5
offset = 50%
passwordfile = /some/place/secret
secretfile = /another/place/secret
step = 300
# Las siguientes variables se pueden anular en cada sección de destino
/^influx_.+/ = influx_location = En el sótano
authtype = CHAP
mininterval = 1
password = test-password
pings = 5
port = 49
secret = test-secret
username = test-user # obligatorio
# [...]
*** Destinos ***
probe = TacacsPlus # si esta debe ser la sonda predeterminada
# [...]
+ mytarget
# probe = TacacsPlus # si la sonda predeterminada es otra
host = my.host
/^influx_.+/ = influx_location = En el sótano
authtype = CHAP
mininterval = 1
password = test-password
pings = 5
port = 49
secret = test-secret
username = test-user # obligatorio

DESCRIPCIÓN

Esta sonda mide la latencia de autenticación TacacsPlus para SmokePing.

El nombre de usuario a probar se especifica en la variable `username', específica de la sonda o del destino, siendo la del destino la que anula la de la sonda.

La contraseña se puede especificar (en orden de precedencia, siendo la última la que anula la anterior) en la variable específica de la sonda `password', en un archivo externo o en la variable específica del destino `password'. La ubicación de este archivo se indica en la variable específica de la sonda `passwordfile'. Consulte Smokeping::probes::passwordchecker(3pm) para el formato de este archivo (resumen: tríos separados por dos puntos de la forma `<host>:<nombre de usuario>:<contraseña>')

El protocolo TacacsPlus requiere un secreto compartido entre el servidor y el cliente. Este secreto se puede especificar (en orden de precedencia, siendo la última la que anula la anterior) en la variable específica de la sonda `secret', en un archivo externo o en la variable específica del destino `secret'. Este archivo externo se localiza mediante la variable específica de la sonda `secretfile', y debe contener pares separados por espacios en blanco de la forma `<host> <secreto>'. Los comentarios y las líneas en blanco son aceptables.

El tipo de autenticación TacacsPlus predeterminado es ASCII. PAP y CHAP también están disponibles. Consulte la documentación de Authen::TacacsPlus para obtener más información;

La sonda intenta ser cortés con el servidor y no envía solicitudes de autenticación con más frecuencia que una vez cada X segundos, donde X es el valor de la variable específica del destino "min_interval" (1 por predeterminado).

VARIABLES

Variables específicas de la sonda admitidas:

forks
Ejecutar este número de procesos concurrentes como máximo

Valor de ejemplo: 5

Valor predeterminado: 5

offset
Si ejecuta muchas sondas concurrentemente, puede que desee evitar que golpeen su red al mismo tiempo. Usando el parámetro de desplazamiento específico de la sonda, puede cambiar el punto en el tiempo en que se ejecutará cada sonda. El desplazamiento se especifica en % del intervalo total, o alternativamente como 'aleatorio', y se utiliza el desplazamiento de la sección 'General' si no se especifica nada aquí. Tenga en cuenta que esto NO influye en los rrds en sí, es solo una cuestión de cuándo se inicia la adquisición de datos. (Esta variable solo es aplicable si la variable 'concurrentprobes' está configurada en la sección 'General'.)

Valor de ejemplo: 50%

passwordfile
Ubicación del archivo que contiene nombres de usuario y contraseñas.

Valor de ejemplo: /some/place/secret

secretfile
Un archivo que contiene los secretos compartidos de TacacsPlus para los destinos. Debe contener pares separados por espacios en blanco de la forma `<host> <secreto>'. Los comentarios y las líneas en blanco son aceptables.

Valor de ejemplo: /another/place/secret

step
Duración del intervalo base que esta sonda debe usar, si es diferente del especificado en la sección 'Database'. Tenga en cuenta que el paso en los archivos RRD se fija cuando se generan originalmente, y si cambia el parámetro de paso después, tendrá que eliminar los archivos RRD antiguos o convertirlos de alguna manera. (Esta variable solo es aplicable si la variable 'concurrentprobes' está configurada en la sección 'General'.)

Valor de ejemplo: 300

Variables específicas del destino admitidas:

/^influx_.+/
Esta es una etiqueta que se enviará a influxdb y no tiene impacto en la medición de la sonda. El nombre de la etiqueta se enviará sin el prefijo "influx_", que se reemplazará con "tag_". Las etiquetas se pueden usar para filtrar.

Valor de ejemplo: influx_location = En el sótano

authtype
El tipo de autenticación TacacsPlus: ASCII (predeterminado), CHAP, PAP

Valor de ejemplo: CHAP

Valor predeterminado: ASCII

mininterval
El intervalo mínimo entre cada solicitud de autenticación enviada, en segundos (posiblemente fraccionarios).

Valor predeterminado: 1

password
La contraseña del usuario, si no está presente en el archivo de contraseñas.

Valor de ejemplo: test-password

pings
Cuántos pings se enviarán a cada destino, si es diferente del valor global especificado en la sección Database. Tenga en cuenta que el número de pings en los archivos RRD se fija cuando se generan originalmente, y si cambia este parámetro después, tendrá que eliminar los archivos RRD antiguos o convertirlos de alguna manera.

Valor de ejemplo: 5

port
El puerto TacacsPlus a utilizar

Valor de ejemplo: 49

Valor predeterminado: 49

secret
El secreto compartido de TacacsPlus para el destino, si no está presente en el archivo de secretos.

Valor de ejemplo: test-secret

timeout
Tiempo de espera en segundos para las consultas TacacsPlus.

Valor predeterminado: 5

username
El nombre de usuario a probar.

Valor de ejemplo: test-user

Esta configuración es obligatoria.
