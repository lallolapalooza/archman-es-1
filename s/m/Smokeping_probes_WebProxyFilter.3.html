NOMBRE

Smokeping::probes::WebProxyFilter - prueba el rendimiento y la función del filtro del proxy web.

DESCRIPCIÓN GENERAL

Esta sonda prueba si tu proxy web de filtrado está funcionando correctamente. Tomando de una lista de sitios web prohibidos, intenta establecer una conexión con cada uno de ellos y registra una 'pérdida' cuando tiene éxito.

Si deseas probar la disponibilidad de un sitio web, utiliza la sonda EchoPingHttp.

SINOPSIS

*** Sondas ***
+WebProxyFilter
forks = 5
maxsize = 2000
min_interval = 0.1
offset = 50%
step = 300
timeout = 15
useragent = SmokePing/2.x (Sonda WebProxyFilter)
# Las siguientes variables pueden ser anuladas en cada sección de destino
/^influx_.+/ = influx_location = En el sótano
deny_re = Acceso Prohibido
more_hosts = www.playboy.com, www.our-competition.com
pings = 5
timeout = 2
# [...]
*** Destinos ***
probe = WebProxyFilter # si esta debe ser la sonda predeterminada
# [...]
+ mi_destino
# probe = WebProxyFilter # si la sonda predeterminada es otra
host = mi.host
/^influx_.+/ = influx_location = En el sótano
deny_re = Acceso Prohibido
more_hosts = www.playboy.com, www.our-competition.com
pings = 5
timeout = 2

DESCRIPCIÓN

La sonda utiliza el módulo LWP::UserAgent para recuperar una serie de páginas web. Espera recibir la página de 'sitio prohibido' de los firewalls. Cualquier otra respuesta (o una pérdida real) se registra como una pérdida y puede usarse para activar una alarma.

La sonda intenta ser cortés con el firewall y espera al menos X segundos entre el inicio de las transferencias de archivos, donde X es el valor de la variable específica de la sonda `min_interval` (1 por defecto).

Muchas variables pueden especificarse ya sea en la sonda o en la definición del destino; la variable específica del destino anulará la variable específica de la sonda.

VARIABLES

Variables específicas de la sonda admitidas:

forks
Ejecuta este número de procesos concurrentes como máximo.

Valor de ejemplo: 5

Valor predeterminado: 5

maxsize
Cuánta de la página web debe recuperarse.

Valor predeterminado: 2000

min_interval
El intervalo mínimo entre cada GET iniciado en segundos.

Valor de ejemplo: 0.1

Valor predeterminado: 1

offset
Si ejecutas muchas sondas concurrentemente, es posible que desees evitar que golpeen tu red al mismo tiempo. Usando el parámetro de offset específico de la sonda puedes cambiar el punto en el tiempo en que se ejecutará cada sonda. El offset se especifica en % del intervalo total, o alternativamente como 'random', y se utiliza el offset de la sección 'General' si no se especifica nada aquí. Ten en cuenta que esto NO influye en los rrds en sí, es solo una cuestión de cuándo se inicia la adquisición de datos. (Esta variable solo es aplicable si la variable 'concurrentprobes' está configurada en la sección 'General'.)

Valor de ejemplo: 50%

step
Duración del intervalo base que debe utilizar esta sonda, si es diferente del especificado en la sección 'Database'. Ten en cuenta que el paso en los archivos RRD se fija cuando se generan originalmente, y si cambias el parámetro de paso después, tendrás que eliminar los archivos RRD antiguos o de alguna manera convertirlos. (Esta variable solo es aplicable si la variable 'concurrentprobes' está configurada en la sección 'General'.)

Valor de ejemplo: 300

timeout
Cuánto tiempo tarda un 'ping' individual como máximo.

Valor de ejemplo: 15

Valor predeterminado: 5

useragent
El navegador web que pretendemos ser, por si el FW está interesado.

Valor predeterminado: SmokePing/2.x (Sonda WebProxyFilter)

Variables específicas de destino admitidas:

/^influx_.+/
Esta es una etiqueta que se enviará a influxdb y no tiene impacto en la medición de la sonda. El nombre de la etiqueta se enviará sin el prefijo "influx_", que se reemplazará con "tag_" en su lugar. Las etiquetas se pueden usar para filtrar.

Valor de ejemplo: influx_location = En el sótano

deny_re
Expresión regular que coincide con la respuesta de 'denegación' del firewall.

Valor de ejemplo: Acceso Prohibido

more_hosts
Una lista separada por comas de sitios web prohibidos para probar, además del especificado en la variable host. Los sitios web se probarán uno tras otro en una ronda, lo que significa que mientras las sondas normales ejecutan la misma prueba varias veces seguidas, esta alterará la página web con cada ronda. La razón de esto es que, aunque intentamos recuperar páginas web remotas, la respuesta vendrá del firewall cada vez, por lo que matamos dos pájaros de un tiro. Primero probamos la latencia del firewall y segundo nos aseguramos de que su filtro funcione correctamente.

Valor de ejemplo: www.playboy.com, www.our-competition.com

pings
¿Cuántos pings se enviarán a cada destino, si es diferente del valor global especificado en la sección Database? Ten en cuenta que el número de pings en los archivos RRD se fija cuando se generan originalmente, y si cambias este parámetro después, tendrás que eliminar los archivos RRD antiguos o de alguna manera convertirlos.

Valor de ejemplo: 5

timeout
Tiempo de espera en segundos para que la prueba se complete.

Valor de ejemplo: 2

Valor predeterminado: 2

ERRORES

Esta sonda es algo poco ortodoxa, ya que considera la recuperación exitosa de una página web prohibida como una pérdida.
