NOMBRE

Smokeping::probes::CiscoRTTMonDNS.pm - Sonda para SmokePing

SINOPSIS

*** Sondas ***
+CiscoRTTMonDNS
forks = 5
offset = 50%
step = 300
timeout = 15
# Las siguientes variables se pueden anular en cada sección de destino
/^influx_.+/ = influx_location = En el sótano
ioshost = RTTcommunity@Myrouter.foobar.com.au # obligatorio
iosint = 10.33.22.11
name = www.foobar.com.au # obligatorio
pings = 5
timeout = 15
# [...]
*** Destinos ***
probe = CiscoRTTMonDNS # si esta debe ser la sonda predeterminada
# [...]
+ mi_destino
# probe = CiscoRTTMonDNS # si la sonda predeterminada es otra
host = mi.host
/^influx_.+/ = influx_location = En el sótano
ioshost = RTTcommunity@Myrouter.foobar.com.au # obligatorio
iosint = 10.33.22.11
name = www.foobar.com.au # obligatorio
pings = 5
timeout = 15

DESCRIPCIÓN

Una sonda para smokeping, que utiliza la funcionalidad MIB ciscoRttMon ("Service Assurance Agent", "SAA") de Cisco IOS para medir el tiempo (recursivo, tipo A) de las consultas DNS a un servidor DNS.

VARIABLES

Variables compatibles específicas de la sonda:

forks
Ejecutar este número de procesos concurrentes como máximo

Valor de ejemplo: 5

Valor predeterminado: 5

offset
Si ejecuta muchas sondas concurrentemente, es posible que desee evitar que golpeen su red al mismo tiempo. Usando el parámetro de desplazamiento específico de la sonda, puede cambiar el momento en que se ejecutará cada sonda. El desplazamiento se especifica en % del intervalo total, o alternativamente como 'aleatorio', y se utiliza el desplazamiento de la sección 'General' si no se especifica nada aquí. Tenga en cuenta que esto NO influye en los RRD en sí, es solo una cuestión de cuándo se inicia la adquisición de datos. (Esta variable solo es aplicable si la variable 'concurrentprobes' está configurada en la sección 'General'.)

Valor de ejemplo: 50%

step
Duración del intervalo base que esta sonda debe usar, si es diferente del especificado en la sección 'Database'. Tenga en cuenta que el paso en los archivos RRD es fijo cuando se generan originalmente, y si cambia el parámetro de paso posteriormente, deberá eliminar los archivos RRD antiguos o convertirlos de alguna manera. (Esta variable solo es aplicable si la variable 'concurrentprobes' está configurada en la sección 'General'.)

Valor de ejemplo: 300

timeout
Cuánto tarda un solo 'ping' como máximo

Valor de ejemplo: 15

Valor predeterminado: 5

Variables compatibles específicas del destino:

/^influx_.+/
Esta es una etiqueta que se enviará a influxdb y no tiene impacto en la medición de la sonda. El nombre de la etiqueta se enviará sin el prefijo "influx_", que se reemplazará con "tag_" en su lugar. Las etiquetas se pueden utilizar para filtrar.

Valor de ejemplo: influx_location = En el sótano

ioshost
El parámetro (obligatorio) ioshost especifica el router Cisco, que enviará las solicitudes DNS, así como la cadena de comunidad SNMP en el router.

Valor de ejemplo: RTTcommunity@Myrouter.foobar.com.au

Esta configuración es obligatoria.

iosint
El parámetro (opcional) iosint es la dirección de origen de los paquetes DNS. Esta debe ser una de las direcciones IP activas (!) del router para obtener resultados. IOS busca la dirección del host de destino en la tabla de reenvío y luego utiliza las interfaces listadas allí para enviar los paquetes DNS. Por defecto, IOS utiliza la dirección IP (principal) de la interfaz de envío como dirección de origen para los paquetes originados por el router.

Valor de ejemplo: 10.33.22.11

name
El parámetro (obligatorio) name es el nombre DNS a resolver.

Valor de ejemplo: www.foobar.com.au

Esta configuración es obligatoria.

pings
Cuántos pings se enviarán a cada destino, si es diferente del valor global especificado en la sección Database. Tenga en cuenta que el número de pings en los archivos RRD es fijo cuando se generan originalmente, y si cambia este parámetro posteriormente, deberá eliminar los archivos RRD antiguos o convertirlos de alguna manera.

Valor de ejemplo: 5

timeout
Cuánto tarda un solo 'ping' RTTMonDNS como máximo más 10 segundos de margen. Dado que controlamos nuestro propio tiempo de espera, el único propósito de esto es evitar que el método de ping de basefork nos elimine.

Valor de ejemplo: 15

Valor predeterminado: 15

AUTORES

Joerg.Kummer at Roche.com

NOTAS

Parámetro host

El parámetro host especifica el servidor DNS que utilizará el router.

VERSIONES IOS

Esta sonda solo funciona con IOS 12.0(3)T o superior. Se recomienda probarla primero en routers menos críticos.

INSTALACIÓN

Para instalar esta sonda, copie ciscoRttMonMIB.pm a ($SMOKEPINGINSTALLDIR)/lib/Smokeping y CiscoRTTMonDNS.pm a ($SMOKEPINGINSTALLDIR)/lib/Smokeping/probes.

Los routers deben configurarse para permitir acceso SNMP de lectura/escritura. Es suficiente:

snmp-server community RTTCommunity RW

Si desea ser un poco más restrictivo con el acceso de escritura SNMP al router, considere configurar algo como esto

access-list 2 permit 10.37.3.5
snmp-server view RttMon ciscoRttMonMIB included
snmp-server community RTTCommunity view RttMon RW 2

La configuración anterior otorga acceso SNMP de lectura/escritura solo a 10.37.3.5 (el host de smokeping) y solo al árbol MIB ciscoRttMon. La sonda no necesita acceso a variables SNMP fuera del árbol RttMon.

ERRORES

La sonda realiza consultas DNS innecesarias, es decir, más de las configuradas en la variable "pings", porque la MIB RTTMon solo permite establecer un tiempo total para todas las consultas en una ejecución de medición (una "vida"). Actualmente, la sonda establece la duración de la vida en "pings"*5+3 segundos (5 segundos es el valor de tiempo de espera codificado en esta sonda).
