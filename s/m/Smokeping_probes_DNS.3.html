NOMBRE

Smokeping::probes::DNS - Sonda de Servicio de Nombres para SmokePing

SINOPSIS

*** Sondas ***
+DNS
binary = /usr/bin/dig # obligatorio
forks = 5
offset = 50%
step = 300
timeout = 15
# Las siguientes variables se pueden sobrescribir en cada sección de destino
/^influx_.+/ = influx_location = En el sótano
lookup = www.example.org
pings = 5
server = ns1.someisp.net
# [...]
*** Destinos ***
probe = DNS # si esta debe ser la sonda predeterminada
# [...]
+ mi_destino
# probe = DNS # si la sonda predeterminada es otra
host = mi.host
/^influx_.+/ = influx_location = En el sótano
lookup = www.example.org
pings = 5
server = ns1.someisp.net

DESCRIPCIÓN

Integra dig como una sonda en smokeping. La variable binary debe apuntar a su copia del programa dig. Si aún no está instalado en su sistema, debe instalar bind-utils >= 9.0.0.

La sonda consulta al host dado n veces para obtener su nombre. Donde n es la cantidad especificada en el Archivo de configuración.

VARIABLES

Variables específicas de la sonda admitidas:

binary
La ubicación de su binario de dig.

Valor de ejemplo: /usr/bin/dig

Esta configuración es obligatoria.

forks
Ejecutar este número de procesos concurrentes como máximo

Valor de ejemplo: 5

Valor predeterminado: 5

offset
Si ejecuta muchas sondas concurrentemente, puede que quiera evitar que golpeen su red todas al mismo tiempo. Usando el parámetro offset específico de la sonda puede cambiar el punto en el tiempo en que se ejecutará cada sonda. Offset se especifica en % del intervalo total, o alternativamente como 'random', y el offset de la sección 'General' se usa si no se especifica nada aquí. Tenga en cuenta que esto NO influye en los propios RRD, es solo una cuestión de cuándo se inicia la adquisición de datos. (Esta variable solo es aplicable si la variable 'concurrentprobes' está configurada en la sección 'General'.)

Valor de ejemplo: 50%

step
Duración del intervalo base que esta sonda debe usar, si es diferente del especificado en la sección 'Database'. Tenga en cuenta que el paso en los archivos RRD es fijo cuando se generan originalmente, y si cambia el parámetro step posteriormente, tendrá que eliminar los archivos RRD antiguos o convertirlos de alguna manera. (Esta variable solo es aplicable si la variable 'concurrentprobes' está configurada en la sección 'General'.)

Valor de ejemplo: 300

timeout
Cuánto tiempo tarda un único 'ping' como máximo

Valor de ejemplo: 15

Valor predeterminado: 5

Variables específicas del destino admitidas:

/^influx_.+/
Esta es una etiqueta que se enviará a influxdb y no tiene impacto en la medida de la sonda. El nombre de la etiqueta se enviará sin el prefijo "influx_", que se reemplazará con "tag_" en su lugar. Las etiquetas se pueden usar para filtrar.

Valor de ejemplo: influx_location = En el sótano

lookup
Nombre del host a buscar en el dns.

Valor de ejemplo: www.example.org

pings
Cuántos pings se deben enviar a cada destino, si es diferente del valor global especificado en la sección Database. Tenga en cuenta que el número de pings en los archivos RRD es fijo cuando se generan originalmente, y si cambia este parámetro posteriormente, tendrá que eliminar los archivos RRD antiguos o convertirlos de alguna manera.

Valor de ejemplo: 5

server
Nombre del servidor dns a utilizar.

Valor de ejemplo: ns1.someisp.net
