NOMBRE

Smokeping::probes::CiscoRTTMonEchoICMP - Sonda para SmokePing

SINOPSIS

*** Sondas ***
+CiscoRTTMonEchoICMP
forks = 5
offset = 50%
step = 300
timeout = 15
# Las siguientes variables se pueden anular en cada sección de destino
/^influx_.+/ = influx_location = En el sótano
ioshost = RTTcommunity@Myrouter.foobar.com.au # obligatorio
iosint = 10.33.22.11
packetsize = 56
pings = 5
timeout = 15
tos = 160
vrf = INTERNET
# [...]
*** Destinos ***
probe = CiscoRTTMonEchoICMP # si esta debe ser la sonda predeterminada
# [...]
+ mytarget
# probe = CiscoRTTMonEchoICMP # si la sonda predeterminada es otra
host = my.host
/^influx_.+/ = influx_location = En el sótano
ioshost = RTTcommunity@Myrouter.foobar.com.au # obligatorio
iosint = 10.33.22.11
packetsize = 56
pings = 5
timeout = 15
tos = 160
vrf = INTERNET

DESCRIPCIÓN

Una sonda para smokeping, que utiliza la funcionalidad MIB ciscoRttMon ("Service Assurance Agent", "SAA") de Cisco IOS para medir los tiempos de ida y vuelta de eco ICMP ("ping") entre un router Cisco y cualquier dirección IP.

VARIABLES

Variables admitidas específicas de la sonda:

forks
Ejecutar este número de procesos concurrentes como máximo

Valor de ejemplo: 5

Valor predeterminado: 5

offset
Si ejecuta muchas sondas concurrentemente, es posible que desee evitar que golpeen su red al mismo tiempo. Usando el parámetro de desplazamiento específico de la sonda, puede cambiar el momento en que se ejecutará cada sonda. El desplazamiento se especifica en % del intervalo total, o alternativamente como 'aleatorio', y se utiliza el desplazamiento de la sección 'General' si no se especifica nada aquí. Tenga en cuenta que esto NO influye en los RRD en sí, es solo una cuestión de cuándo se inicia la adquisición de datos. (Esta variable solo es aplicable si la variable 'concurrentprobes' está configurada en la sección 'General'.)

Valor de ejemplo: 50%

step
Duración del intervalo base que esta sonda debe usar, si es diferente del especificado en la sección 'Database'. Tenga en cuenta que el paso en los archivos RRD es fijo cuando se generan originalmente, y si cambia el parámetro de paso después, deberá eliminar los archivos RRD antiguos o convertirlos de alguna manera. (Esta variable solo es aplicable si la variable 'concurrentprobes' está configurada en la sección 'General'.)

Valor de ejemplo: 300

timeout
Cuánto tarda como máximo un único 'ping'

Valor de ejemplo: 15

Valor predeterminado: 5

Variables admitidas específicas del destino:

/^influx_.+/
Esta es una etiqueta que se enviará a influxdb y no tiene impacto en la medición de la sonda. El nombre de la etiqueta se enviará sin el prefijo "influx_", que se reemplazará con "tag_" en su lugar. Las etiquetas se pueden usar para filtrar.

Valor de ejemplo: influx_location = En el sótano

ioshost
El parámetro (obligatorio) ioshost especifica el router Cisco que ejecutará los pings, así como la cadena de comunidad SNMP en el router.

Valor de ejemplo: RTTcommunity@Myrouter.foobar.com.au

Esta configuración es obligatoria.

iosint
El parámetro (opcional) iosint es la dirección de origen para los pings enviados. Esta debe ser una de las direcciones IP activas (!) del router para obtener resultados. IOS busca la dirección del host de destino en la tabla de reenvío y luego utiliza las interfaces listadas allí para enviar los paquetes de ping. Por defecto, IOS utiliza la dirección IP (principal) en la interfaz de envío como dirección de origen para un ping. Las versiones MIB RTTMon anteriores a IOS 12.0(3)T no admitían este parámetro.

Valor de ejemplo: 10.33.22.11

packetsize
El parámetro packetsize le permite configurar el tamaño del paquete para los pings enviados. El mínimo es 8, el máximo 16392. Utilice el mismo número que con fping, si desea que se utilicen los mismos tamaños de paquete en la red.

Valor predeterminado: 56

pings
Cuántos pings se deben enviar a cada destino, si es diferente del valor global especificado en la sección Database. Tenga en cuenta que el número de pings en los archivos RRD es fijo cuando se generan originalmente, y si cambia este parámetro después, deberá eliminar los archivos RRD antiguos o convertirlos de alguna manera.

Valor de ejemplo: 5

timeout
Cuánto tarda como máximo un único ping RTTMonEcho ICMP más 10 segundos de margen. Como controlamos nuestro propio tiempo de espera, el único propósito de esto es no ser eliminados por el método de ping de basefork.

Valor de ejemplo: 15

Valor predeterminado: 15

tos
El parámetro (opcional) tos especifica el valor del byte ToS en la cabecera IP de los pings. Multiplique los valores DSCP por 4 y los valores de precedencia por 32 para calcular los valores ToS a configurar, por ejemplo, ToS 160 corresponde a un valor DSCP de 40 y un valor de precedencia de 5. Las versiones MIB RTTMon anteriores a IOS 12.0(3)T no admitían este parámetro.

Valor de ejemplo: 160

Valor predeterminado: 0

vrf
El nombre de la VPN en el que se utilizará la operación RTT. Para la operación RTT normal, este campo no debe configurarse. El agente utilizará este campo para identificar la tabla de enrutamiento VPN para esta operación.

Valor de ejemplo: INTERNET

NOTAS

VERSIONES DE IOS

Se recomienda encarecidamente utilizar esta sonda con routers que ejecuten IOS 12.0(3)T o superior y probarla primero en routers menos críticos. Logré bloquear un router con 12.0(9) de forma bastante consistente (en la jerga de IOS, 12.0(9) es un código más antiguo que 12.0(3)T). No observé bloqueos en versiones de IOS más altas, pero mensajes en el router como el siguiente, cuando múltiples procesos accedían concurrentemente al mismo router (este caso fue IOS 12.1(12b)):

Aug 20 07:30:14: %RTT-3-SemaphoreBadUnlock: %RTR: Attempt to unlock semaphore by wrong RTR process 70, locked by 78

Aug 20 07:35:15: %RTT-3-SemaphoreInUse: %RTR: Could not obtain a lock for RTR. Process 80

INSTALACIÓN

Para instalar esta sonda, copie los archivos ciscoRttMonMIB.pm a ($SMOKEPINGINSTALLDIR)/lib/Smokeping y CiscoRTTMonEchoICMP.pm a ($SMOKEPINGINSTALLDIR)/lib/Smokeping/probes. Se requiere la versión V0.97 o superior de SNMP_Session.pm de Simon Leinen.

Los routers deben configurarse para permitir el acceso SNMP de lectura/escritura. Es suficiente:

snmp-server community RTTCommunity RW

Si desea ser un poco más restrictivo con el acceso de escritura SNMP al router, considere configurar algo como esto:

access-list 2 permit 10.37.3.5
snmp-server view RttMon ciscoRttMonMIB included
snmp-server community RTTCommunity view RttMon RW 2

La configuración anterior otorga lectura/escritura SNMP solo a 10.37.3.5 (el host de smokeping) y solo al árbol MIB ciscoRttMon. La sonda no necesita acceso a variables SNMP fuera del árbol RttMon.

ERRORES

La sonda envía pings innecesarios, es decir, más de los configurados en la variable "pings", porque la MIB RTTMon solo permite establecer un tiempo total para todos los pings en una ejecución de medición (una "vida"). Actualmente, la sonda establece la duración de la vida en "pings"*5+3 segundos (5 segundos es el tiempo de espera del ping codificado en esta sonda).
