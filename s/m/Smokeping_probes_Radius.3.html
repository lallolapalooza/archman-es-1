NOMBRE

Smokeping::probes::Radius - una sonda de autenticación RADIUS para SmokePing

DESCRIPCION GENERAL

Mide la latencia de autenticación RADIUS para SmokePing

SINOPSIS

*** Sondas ***
+Radius
forks = 5
offset = 50%
passwordfile = /some/place/secret
secretfile = /another/place/secret
step = 300
# Las siguientes variables pueden ser anuladas en cada sección de destino
/^influx_.+/ = influx_location = En el sótano
allowreject = true
mininterval = 1
nas_ip_address = 10.1.2.3
password = test-password
pings = 5
port = 1645
secret = test-secret
timeout = 5
username = test-user # obligatorio
# [...]
*** Destinos ***
probe = Radius # si esta debe ser la sonda predeterminada
# [...]
+ mytarget
# probe = Radius # si la sonda predeterminada es otra
host = my.host
/^influx_.+/ = influx_location = En el sótano
allowreject = true
mininterval = 1
nas_ip_address = 10.1.2.3
password = test-password
pings = 5
port = 1645
secret = test-secret
timeout = 5
username = test-user # obligatorio

DESCRIPCION

Esta sonda mide la latencia de autenticación RADIUS (RFC 2865) para SmokePing.

El nombre de usuario a probar se especifica en la variable `username', ya sea específica de la sonda o específica del destino, con la variable específica del destino anulando la específica de la sonda.

La contraseña se puede especificar (en orden de precedencia, con la última anulando la anterior) en la variable específica de la sonda `password', en un archivo externo o en la variable específica del destino `password'. La ubicación de este archivo se indica en la variable específica de la sonda `passwordfile'. Consulte Smokeping::probes::passwordchecker(3pm) para el formato de este archivo (resumen: tríos separados por dos puntos de la forma `<host>:<username>:<password>')

El protocolo RADIUS requiere un secreto compartido entre el servidor y el cliente. Este secreto se puede especificar (en orden de precedencia, con la última anulando la anterior) en la variable específica de la sonda `secret', en un archivo externo o en la variable específica del destino `secret'. Este archivo externo se localiza mediante la variable específica de la sonda `secretfile', y debe contener pares separados por espacios en blanco de la forma `<host> <secret>'. Los comentarios y las líneas en blanco son aceptables.

Si la variable opcional específica de la sonda `nas_ip_address' se especifica, su valor se inserta en las solicitudes de autenticación como el atributo RADIUS `NAS-IP-Address'.

La sonda intenta ser amable con el servidor y no envía solicitudes de autenticación con una frecuencia mayor a una vez cada X segundos, donde X es el valor de la variable específica del destino "min_interval" (1 por defecto).

VARIABLES

Variables específicas de la sonda admitidas:

forks
Ejecutar este número de procesos concurrentes como máximo

Valor de ejemplo: 5

Valor predeterminado: 5

offset
Si ejecutas muchas sondas concurrentemente, puede que quieras evitar que golpeen tu red al mismo tiempo. Usando el parámetro offset específico de la sonda, puedes cambiar el punto en el tiempo en que se ejecutará cada sonda. El offset se especifica en % del intervalo total, o alternativamente como 'random', y se usa el offset de la sección 'General' si nada se especifica aquí. Ten en cuenta que esto NO influye en los propios rrds, es solo una cuestión de cuándo se inicia la adquisición de datos. (Esta variable solo es aplicable si la variable 'concurrentprobes' está establecida en la sección 'General'.)

Valor de ejemplo: 50%

passwordfile
Ubicación del archivo que contiene nombres de usuario y contraseñas.

Valor de ejemplo: /some/place/secret

secretfile
Un archivo que contiene los secretos compartidos de RADIUS para los destinos. Debe contener pares separados por espacios en blanco de la forma `<host> <secret>'. Los comentarios y las líneas en blanco son aceptables.

Valor de ejemplo: /another/place/secret

step
Duración del intervalo base que esta sonda debe usar, si es diferente al especificado en la sección 'Database'. Ten en cuenta que el paso en los archivos RRD se fija cuando se generan originalmente, y si cambias el parámetro de paso después, tendrás que eliminar los archivos RRD antiguos o convertirlos de alguna manera. (Esta variable solo es aplicable si la variable 'concurrentprobes' está establecida en la sección 'General'.)

Valor de ejemplo: 300

Variables específicas del destino admitidas:

/^influx_.+/
Esta es una etiqueta que se enviará a influxdb y no tiene impacto en la medición de la sonda. El nombre de la etiqueta se enviará sin el prefijo "influx_", que será reemplazado por "tag_". Las etiquetas se pueden usar para filtrar.

Valor de ejemplo: influx_location = En el sótano

allowreject
Tratar las respuestas de "rechazo" como OK

Valor de ejemplo: true

mininterval
El intervalo mínimo entre cada solicitud de autenticación enviada, en segundos (posiblemente fraccionales).

Valor predeterminado: 1

nas_ip_address
El atributo RADIUS NAS-IP-Address para las solicitudes de autenticación. No es necesario en todas partes.

Valor de ejemplo: 10.1.2.3

password
La contraseña del usuario, si no está presente en el archivo de contraseñas.

Valor de ejemplo: test-password

pings
Cuántos pings se enviarán a cada destino, si es diferente del valor global especificado en la sección Database. Ten en cuenta que el número de pings en los archivos RRD se fija cuando se generan originalmente, y si cambias este parámetro después, tendrás que eliminar los archivos RRD antiguos o convertirlos de alguna manera.

Valor de ejemplo: 5

port
El puerto RADIUS a utilizar

Valor de ejemplo: 1645

secret
El secreto compartido de RADIUS para el destino, si no está presente en el archivo de secretos.

Valor de ejemplo: test-secret

timeout
Tiempo de espera en segundos para las consultas RADIUS.

Valor predeterminado: 5

username
El nombre de usuario a probar.

Valor de ejemplo: test-user

Esta configuración es obligatoria.

DESCRIPTION

The Radius probe allows Smokeping to measure the performance of RADIUS authentication servers. It sends a RADIUS Access-Request packet to the server and measures the time it takes to receive an Access-Accept or Access-Reject.

The probe works by sending a standard RADIUS Access-Request packet to the specified host and port. The server's response time is measured and recorded. This allows you to monitor the latency and availability of your RADIUS infrastructure.

VARIABLES

The following variables can be set to configure the Radius probe:

  • host: The hostname or IP address of the RADIUS server. (Required)
  • port: The UDP port on which the RADIUS server is listening. Defaults to 1812.
  • secret: The shared secret used to authenticate with the RADIUS server. (Required)
  • timeout: The maximum time in seconds to wait for a response from the RADIUS server. Defaults to 5.
  • nas_ip_address: The IP address of the Network Access Server (NAS) that the probe should emulate. If not set, a default IP address will be used.
  • calling_station_id: The calling station ID to be sent in the Access-Request.
  • called_station_id: The called station ID to be sent in the Access-Request.
  • user_name: The username to be used in the Access-Request.
