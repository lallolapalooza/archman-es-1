NOMBRE

Smokeping::probes::CiscoRTTMonTcpConnect - Sonda para SmokePing

SINOPSIS

*** Sondas ***
+CiscoRTTMonTcpConnect
forks = 5
offset = 50%
step = 300
timeout = 15
# Las siguientes variables pueden ser anuladas en cada sección de destino
/^influx_.+/ = influx_location = En el sótano
ioshost = RTTcommunity@Myrouter.foobar.com.au # obligatorio
iosint = 10.33.22.11
pings = 5
port = 80
timeout = 15
tos = 160
# [...]
*** Destinos ***
probe = CiscoRTTMonTcpConnect # si esta debe ser la sonda predeterminada
# [...]
+ mytarget
# probe = CiscoRTTMonTcpConnect # si la sonda predeterminada es otra
host = my.host
/^influx_.+/ = influx_location = En el sótano
ioshost = RTTcommunity@Myrouter.foobar.com.au # obligatorio
iosint = 10.33.22.11
pings = 5
port = 80
timeout = 15
tos = 160

DESCRIPCIÓN

Una sonda para smokeping, que utiliza la funcionalidad MIB ciscoRttMon ("Service Assurance Agent", "SAA") de Cisco IOS para medir los tiempos de conexión TCP entre un router Cisco y un servidor TCP. El valor medido es el tiempo para establecer una sesión TCP, es decir, el tiempo entre el paquete TCP inicial "SYN" del router y el paquete "SYN ACK" del host. El router termina la sesión TCP inmediatamente después de la recepción de "SYN ACK" con un paquete "FIN".

VARIABLES

Variables específicas de la sonda admitidas:

forks
Ejecuta este número de procesos concurrentes como máximo

Valor de ejemplo: 5

Valor predeterminado: 5

offset
Si ejecutas muchas sondas concurrentemente, es posible que desees evitar que impacten tu red al mismo tiempo. Usando el parámetro offset específico de la sonda, puedes cambiar el punto en el tiempo en que se ejecutará cada sonda. El offset se especifica en % del intervalo total, o alternativamente como 'random', y se utiliza el offset de la sección 'General' si no se especifica nada aquí. Ten en cuenta que esto NO influye en los RRD en sí, es solo una cuestión de cuándo se inicia la adquisición de datos. (Esta variable solo es aplicable si la variable 'concurrentprobes' está establecida en la sección 'General'.)

Valor de ejemplo: 50%

step
Duración del intervalo base que esta sonda debe usar, si es diferente del especificado en la sección 'Database'. Ten en cuenta que el paso en los archivos RRD se fija cuando se generan originalmente, y si cambias el parámetro de paso después, tendrás que eliminar los archivos RRD antiguos o convertirlos de alguna manera. (Esta variable solo es aplicable si la variable 'concurrentprobes' está establecida en la sección 'General'.)

Valor de ejemplo: 300

timeout
Cuánto tiempo tarda un 'ping' individual como máximo

Valor de ejemplo: 15

Valor predeterminado: 5

Variables específicas del destino admitidas:

/^influx_.+/
Esta es una etiqueta que se enviará a influxdb y no tiene impacto en la medición de la sonda. El nombre de la etiqueta se enviará sin el prefijo "influx_", que se reemplazará por "tag_". Las etiquetas se pueden usar para filtrar.

Valor de ejemplo: influx_location = En el sótano

ioshost
El parámetro (obligatorio) ioshost especifica el router Cisco, que establecerá las conexiones TCP, así como la cadena de comunidad SNMP en el router.

Valor de ejemplo: RTTcommunity@Myrouter.foobar.com.au

Esta configuración es obligatoria.

iosint
El parámetro (opcional) iosint es la dirección de origen para las conexiones TCP. Debe ser una de las direcciones IP activas (!) del router para obtener resultados. IOS busca la dirección del host de destino en la tabla de reenvío y luego utiliza las interfaces listadas allí para enviar los paquetes TCP. Por defecto, IOS utiliza la dirección IP (primaria) en la interfaz de envío como dirección de origen para una conexión.

Valor de ejemplo: 10.33.22.11

pings
Cuántos pings se deben enviar a cada destino, si es diferente del valor global especificado en la sección Database. Ten en cuenta que el número de pings en los archivos RRD se fija cuando se generan originalmente, y si cambias este parámetro después, tendrás que eliminar los archivos RRD antiguos o convertirlos de alguna manera.

Valor de ejemplo: 5

port
El parámetro (opcional) port te permite configurar el puerto TCP de destino en el host. El valor predeterminado es el puerto http 80.

Valor predeterminado: 80

timeout
Cuánto tiempo tarda un 'ping' RTTMon TcpConnect individual como máximo más 10 segundos de margen. Dado que controlamos nuestro propio timeout, el único propósito de esto es evitar que el método ping de basefork nos elimine.

Valor de ejemplo: 15

Valor predeterminado: 15

tos
El parámetro (opcional) tos especifica el valor del byte ToS en la cabecera IP de los paquetes del router. Multiplica los valores DSCP por 4 y los valores de Precedencia por 32 para calcular los valores ToS a configurar, por ejemplo, ToS 160 corresponde a un valor DSCP de 40 y un valor de Precedencia de 5. Ten en cuenta que esto no influirá en el valor ToS en los paquetes enviados por el host.

Valor de ejemplo: 160

Valor predeterminado: 0

Joerg.Kummer at Roche.com

NOTAS

VERSIÓN IOS

Esta sonda solo funciona con Cisco IOS 12.0(3)T o superior. Se recomienda probarla primero en routers menos críticos.

INSTALACIÓN

Para instalar esta sonda, copia ciscoRttMonMIB.pm a ($SMOKEPINGINSTALLDIR)/Smokeping/lib y CiscoRTTMonTcpConnect.pm a ($SMOKEPINGINSTALLDIR)/lib/Smokeping/probes. Se requiere la versión V0.97 o superior de SNMP_Session.pm de Simon Leinen.

Los routers deben estar configurados para permitir acceso SNMP de lectura/escritura. Es suficiente:

snmp-server community RTTCommunity RW

Si deseas ser un poco más restrictivo con el acceso de escritura SNMP al router, considera configurar algo como esto:

access-list 2 permit 10.37.3.5
snmp-server view RttMon ciscoRttMonMIB included
snmp-server community RTTCommunity view RttMon RW 2

La configuración anterior otorga acceso SNMP de lectura/escritura solo a 10.37.3.5 (el host de smokeping) y solo al árbol MIB ciscoRttMon. La sonda no necesita acceso a variables SNMP fuera del árbol RttMon.

ERRORES

La sonda establece conexiones innecesarias, es decir, más de las configuradas en la variable "pings", porque la MIB RTTMon solo permite establecer un tiempo total para todas las conexiones en una ejecución de medición (una "vida"). Actualmente, la sonda establece la duración de la vida en "pings"*5+3 segundos (5 segundos es el valor de timeout codificado en esta sonda).

NAME

Smokeping_probes_CiscoRTTMonTcpConnect - Cisco RTTMon TCP Connect probe module

SYNOPSIS

    <probe>
        pointer = CiscoRTTMonTcpConnect
        title = Cisco RTTMon TCP Connect
        host = <target>
        . . .
    </probe>

DESCRIPTION

The Cisco RTTMon TCP Connect probe module uses the Cisco RTTMon MIB to measure network latency and packet loss. It works by sending a TCP SYN packet to a specified port on the target host and measuring the time it takes to receive a SYN-ACK response. This can be used to monitor the availability and performance of network devices that support SNMP and the RTTMon MIB.

VARIABLES

The following variables can be configured within the probe section:

  • host: The target hostname or IP address of the device to monitor.

  • port: The TCP port to connect to on the target host. Defaults to 80 (HTTP).

  • community: The SNMP community string to use for accessing the device. Defaults to 'public'.

  • version: The SNMP version to use (1, 2c, or 3). Defaults to '2c'.

  • timeout: The timeout in seconds for the SNMP request. Defaults to 5.

AUTHORS

S. Moonesamy <sm6@earth.li>

NOTES

This probe requires SNMP to be enabled on the target device and the RTTMon MIB to be supported.

BUGS

No known bugs.
