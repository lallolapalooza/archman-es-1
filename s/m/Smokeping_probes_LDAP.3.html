NAME

Smokeping::probes::LDAP - un probe LDAP para SmokePing

OVERVIEW

Medida de la latencia de búsqueda LDAP para SmokePing

SYNOPSIS

*** Probes ***
+LDAP
forks = 5
offset = 50%
passwordfile = /some/place/secret
step = 300
# El siguiente conjunto de variables puede ser sobreescrito en cada sección de destino
/^influx_.+/ = influx_location = En el sótano
attrs = uid,someotherattr
base = dc=foo,dc=bar
binddn = uid=testuser,dc=foo,dc=bar
filter = uid=testuser # obligatorio
mininterval = 1
password = mypass
pings = 5
port = 389
scheme = ldap
scope = one
start_tls = 1
timeout = 10
verify = optional
version = 3
# [...]
*** Destinos ***
probe = LDAP # si esto debe ser el probe por defecto
# [...]
+ mytarget
# probe = LDAP # si el probe por defecto es algo diferente
host = my.host
/^influx_.+/ = influx_location = En el sótano
attrs = uid,someotherattr
base = dc=foo,dc=bar
binddn = uid=testuser,dc=foo,dc=bar
filter = uid=testuser # obligatorio
mininterval = 1
password = mypass
pings = 5
port = 389
scheme = ldap
scope = one
start_tls = 1
timeout = 10
verify = optional
version = 3

DESCRIPTION

Este probe mide la latencia de la consulta LDAP para SmokePing. La consulta se especifica mediante la variable de sección de destino filter y, opcionalmente, mediante la variable de sección de destino base. Los atributos consultados pueden especificarse en la lista separada por comas attrs.

El puerto TCP del servidor LDAP y la versión LDAP a usar pueden especificarse mediante las variables port y version.

El probe puede emitir el comando starttls para convertir la conexión en modo criptográfico, si se instruye mediante la variable start_tls. Esto requiere la instalación del módulo perl IO::Socket::SSL.

El probe también puede opcionalmente realizar un bind autenticado LDAP, si la variable binddn está presente. La contraseña a usar puede especificarse mediante la variable de sección de destino password o en un archivo externo. La ubicación de este archivo se especifica mediante la variable de sección de probe passwordfile. Consulte Smokeping::probes::passwordchecker(3pm) para el formato de este archivo (resumen: tripletas separadas por punto y coma de la forma <host> <bind-dn> <password>).

El probe intenta ser amigable con el servidor y no envía solicitudes de autenticación más frecuentemente que cada X segundos, donde X es el valor de la variable de sección de destino mininterval (1 por defecto).

VARIABLES

Variables soportadas en la sección de probe:

forks
Se ejecutan tantos procesos concurrentes como máximo

Valor de ejemplo: 5

Valor por defecto: 5

offset
Si se ejecutan muchos probes concurrentes, puede ser útil evitar que todos acaben golpeando su red al mismo tiempo. Usando el parámetro de offset de la sección de destino, puedes cambiar el momento en el que se ejecutarán los probes. El offset se especifica en porcentaje del intervalo total, o alternativamente como 'random', y se usa si no se especifica aquí. Nota que esto no influye en los rrds, es solo un asunto de cuándo se inicia la adquisición de datos. (Esta variable es solo aplicable si la variable 'concurrentprobes' está definida en la sección general.)

Valor de ejemplo: 50%

passwordfile
Ubicación del archivo que contiene los usuarios y sus contraseñas.

Valor de ejemplo: /some/place/secret

step
Duración del intervalo base que este probe debería utilizar, si es diferente de la especificada en la sección base. Nota que el paso en los archivos rrds es fijo cuando se generan originalmente, y si cambias este parámetro después, tendrás que eliminar los archivos rrds antiguos o convertirlos de alguna manera. (Esta variable es solo aplicable si la variable 'concurrentprobes' está definida en la sección general.)

Valor de ejemplo: 300

Variables soportadas en la sección de destino:

/^influx_.+/
Esta es una etiqueta que se envía a influxdb y no tiene influencia en la medición del probe. El nombre de la etiqueta se envía sin el prefijo "influx_", que se reemplaza por "tag_". Las etiquetas pueden usarse para filtrado.

Valor de ejemplo: influx_location = En el sótano

attrs
Los atributos consultados.

Valor de ejemplo: uid,someotherattr

base
La base a usarse en la consulta LDAP

Valor de ejemplo: dc=foo,dc=bar

binddn
Si se encuentra, autenticar el bind LDAP con esta DN.

Valor de ejemplo: uid=testuser,dc=foo,dc=bar

filter
La consulta real a hacer

Valor de ejemplo: uid=testuser

Este valor es obligatorio.

mininterval
El intervalo mínimo entre cada consulta enviada, en segundos (puede ser fraccionario).

Valor por defecto: 1

password
La contraseña a usar, si no se encuentra en <passwordfile>.

Valor de ejemplo: mypass

pings
¿Cuántos pings deben enviarse a cada destino, si es diferente del valor global especificado en la sección base. Nota que el número de pings en los archivos rrds es fijo cuando se generan originalmente, y si cambias este parámetro después, tendrás que eliminar los archivos rrds antiguos o convertirlos de alguna manera.

Valor de ejemplo: 5

port
El puerto TCP del servidor LDAP

Valor de ejemplo: 389

scheme
El esquema LDAP a usar: ldap, ldaps o ldapi

Valor de ejemplo: ldap

Valor por defecto: ldap

scope
El alcance de la consulta. Puede ser 'base', 'one' o 'sub'. Véase la documentación de Net::LDAP para más detalles.

Valor de ejemplo: one

Valor por defecto: sub

start_tls
Si se establece como verdadero, encripta la conexión con el comando starttls. Desactivado por defecto.

Valor de ejemplo: 1

timeout
El tiempo de timeout de la consulta LDAP en segundos.

Valor de ejemplo: 10

Valor por defecto: 5

verify
El nivel de verificación TLS. Puede ser 'none', 'optional', 'require'. Véase la documentación de Net::LDAPS para más detalles.

Valor de ejemplo: optional

Valor por defecto: require

version
La versión LDAP a usar.

Valor de ejemplo: 3

BUGS

Debería haber una forma de especificar opciones TLS, como los certificados involucrados, etc.

El probe tiene un método inusual de trabajar alrededor del hecho de que la clase IO::Socket::SSL deje de funcionar si start_tls() se llama más de una vez en el mismo programa. Sin embargo, funciona para mí (tm).
