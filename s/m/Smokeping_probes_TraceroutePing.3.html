NOMBRE

Smokeping::probes::TraceroutePing - usar traceroute para obtener RTT para un router

SINOPSIS

*** Probes ***
+TraceroutePing
binary = /usr/bin/traceroute # obligatorio
binaryv6 = /usr/bin/traceroute6
forks = 5
offset = 50%
step = 300
timeout = 15
# Las siguientes variables se pueden sobrescribir en cada sección de destino
/^influx_.+/ = influx_location = En el sótano
desthost = www.example.com # obligatorio
host = www-net-router.example.com # obligatorio
maxttl = 15
minttl = 11
pings = 5
wait = 3
# [...]
*** Targets ***
probe = TraceroutePing # si este debe ser el probe predeterminado
# [...]
+ mytarget
# probe = TraceroutePing # si el probe predeterminado es otro
host = my.host
/^influx_.+/ = influx_location = En el sótano
desthost = www.example.com # obligatorio
host = www-net-router.example.com # obligatorio
maxttl = 15
minttl = 11
pings = 5
wait = 3

DESCRIPCIÓN

Integra traceroute estándar como una sonda (probe) en smokeping. El caso de uso para esta sonda son gateways que no responden a paquetes TCP/UDP/ICMP dirigidos a ellos, pero sí devuelven paquetes ICMP TTL_EXCEEDED para paquetes traceroute a un host al que enrutan. Se utiliza mejor en situaciones donde el enrutamiento para la ruta es estático o casi estático; intentar usarlo en redes con enrutamiento cambiante producirá malos resultados. El mejor lugar para usar esta sonda es en enlaces de primera y última milla, que son más propensos a tener enrutamiento estático y también más propensos a tener firewalls que ignoran ICMP ECHO_REQUEST.

La variable de sonda obligatoria binary debe contener una ruta ejecutable para traceroute.

La variable de sonda opcional binaryv6 establece una ruta ejecutable para tu traceroute IPv6. Si se establece en el mismo valor que binary, TraceroutePing usará el flag -6 al ejecutar traceroute para direcciones IPv6. Si esta variable no está configurada, TraceroutePing intentará encontrar un traceroute IPv6 funcional. Primero intentará añadir "6" a la ruta en binary, luego intentará incluir el flag "-6" en un comando de prueba. Ten en cuenta que Linux parece tener una amplia variedad de implementaciones de traceroute IPv6. Mi máquina Ubuntu 14.04 tiene /usr/sbin/traceroute6 de iputils, pero /usr/bin/traceroute (de Dmitry Butskoy) acepta el flag -6 y es en realidad una mejor implementación. Puede que necesites dejar que TraceroutePing lo autodetecte, o experimentar para encontrar el mejor traceroute.

La variable de destino obligatoria desthost debe nombrar un host de destino para la sonda. El host de destino en sí no es de interés y no se recopilan datos sobre él, su único propósito es enrutar el tráfico más allá de tu objetivo real. La selección de un destino justo después de tu objetivo, con enrutamiento estático o fuertemente preferido a través de tu objetivo, obtendrá mejores datos.

La variable de destino obligatoria host debe nombrar el host de destino para la sonda. Este es el router para el que deseas recopilar datos RTT. Esta variable debe ser el nombre de búsqueda inversa válido del router o su dirección IP. Se prefiere usar la dirección IP, ya que nos permite decirle a traceroute que evite las búsquedas DNS.

Las variables de destino minttl y maxttl se pueden usar para describir el rango de recuentos de saltos esperados hasta host. En rutas más largas o rutas a través de gateways que no responden o que terminan en hosts que no responden, esto reduce el tiempo que tarda esta sonda en ejecutarse. Estos tienen un valor predeterminado de 1 y 30.

La variable de destino wait establece el tiempo de espera de la sonda traceroute en segundos. Esto tiene un valor predeterminado de 1, en lugar del valor tradicionalmente más alto utilizado por el traceroute de LBL. Los programas de traceroute a menudo imponen un límite inferior a este valor.

VARIABLES

Variables específicas de la sonda admitidas:

binary
La ubicación de tu binario traceroute.

Valor de ejemplo: /usr/bin/traceroute

Esta configuración es obligatoria.

binaryv6
La ubicación de tu binario traceroute IPv6.

Valor de ejemplo: /usr/bin/traceroute6

forks
Ejecuta este número de procesos concurrentes como máximo.

Valor de ejemplo: 5

Valor predeterminado: 5

offset
Si ejecutas muchas sondas concurrentemente, es posible que desees evitar que golpeen tu red al mismo tiempo. Usando el parámetro de desplazamiento específico de la sonda, puedes cambiar el punto en el tiempo en que se ejecutará cada sonda. El desplazamiento se especifica en % del intervalo total, o alternativamente como 'random', y se utiliza el desplazamiento de la sección 'General' si no se especifica nada aquí. Ten en cuenta que esto NO influye en los RRD en sí, es solo una cuestión de cuándo se inicia la adquisición de datos. (Esta variable solo es aplicable si la variable 'concurrentprobes' está configurada en la sección 'General'.)

Valor de ejemplo: 50%

step
Duración del intervalo base que debe usar esta sonda, si es diferente al especificado en la sección 'Database'. Ten en cuenta que el paso en los archivos RRD es fijo cuando se generan originalmente, y si cambias el parámetro de paso después, tendrás que eliminar los archivos RRD antiguos o convertirlos de alguna manera. (Esta variable solo es aplicable si la variable 'concurrentprobes' está configurada en la sección 'General'.)

Valor de ejemplo: 300

timeout
Cuánto tiempo tarda un 'ping' individual como máximo.

Valor de ejemplo: 15

Valor predeterminado: 5

Variables específicas de destino admitidas:

/^influx_.+/
Esta es una etiqueta que se enviará a influxdb y no tiene impacto en la medición de la sonda. El nombre de la etiqueta se enviará sin el prefijo "influx_", que se reemplazará con "tag_" en su lugar. Las etiquetas se pueden usar para filtrar.

Valor de ejemplo: influx_location = En el sótano

desthost
Host de destino final para los paquetes traceroute. No tiene que ser alcanzable a menos que también sea tu host.

Valor de ejemplo: www.example.com

Esta configuración es obligatoria.

host
Host de interés a monitorear. Debe ser el nombre de búsqueda inversa del host o una dirección IP.

Valor de ejemplo: www-net-router.example.com

Esta configuración es obligatoria.

maxttl
TTL máximo. Establecer en el número máximo de saltos esperados al host.

Valor de ejemplo: 15

minttl
TTL mínimo. Establecer en el número mínimo de saltos esperados al host.

Valor de ejemplo: 11

pings
Cuántos pings se deben enviar a cada destino, si es diferente del valor global especificado en la sección Database. Ten en cuenta que el número de pings en los archivos RRD es fijo cuando se generan originalmente, y si cambias este parámetro después, tendrás que eliminar los archivos RRD antiguos o convertirlos de alguna manera.

Valor de ejemplo: 5

wait
Tiempo de espera. El valor de tiempo de espera para las sondas de traceroute, en segundos.

Valor de ejemplo: 3
