NOMBRE

Smokeping::probes::AnotherDNS - Sonda DNS alternativa

SINOPSIS

*** Sondas ***
+AnotherDNS
forks = 5
offset = 50%
step = 300
# Las siguientes variables se pueden sobrescribir en cada sección de destino
/^influx_.+/ = influx_location = En el sótano
authoritative = 0
expect_text = 192.168.50.60
ipversion = 4
lookup = www.example.org
mininterval = 0.5
pings = 5
port = 53
protocol = udp
recordtype = A
require_answers = 0
require_noerror = 0
require_nxdomain = 0
timeout = 5
# [...]
*** Destinos ***
probe = AnotherDNS # si esta debe ser la sonda predeterminada
# [...]
+ mi_destino
# probe = AnotherDNS # si la sonda predeterminada es otra
host = mi.servidor
/^influx_.+/ = influx_location = En el sótano
authoritative = 0
expect_text = 192.168.50.60
ipversion = 4
lookup = www.example.org
mininterval = 0.5
pings = 5
port = 53
protocol = udp
recordtype = A
require_answers = 0
require_noerror = 0
require_nxdomain = 0
timeout = 5

DESCRIPCIÓN

Similar a DNS, pero usa Net::DNS y Time::HiRes en lugar de dig. Esta sonda *no* reintenta la solicitud tres veces antes de considerarse "perdida", como hacen dig y otros resolvedores por defecto. Si opera como servidor de nombres en caché, BIND (y quizás otros) esperan que los clientes reintenten la solicitud si la respuesta no está en la caché. Por lo tanto, pregunte al servidor de nombres por algo de lo que sea autoritativo si desea medir correctamente la pérdida de paquetes de red.

Si tiene una red y un servidor de nombres realmente rápidos, notará que esta sonda informa el tiempo de consulta en resolución de microsegundos. :-)

VARIABLES

Variables específicas de la sonda admitidas:

forks
Ejecutar este número de procesos concurrentes como máximo

Valor de ejemplo: 5

Valor predeterminado: 5

offset
Si ejecuta muchas sondas concurrentemente, puede que desee evitar que incidan en su red todas al mismo tiempo. Usando el parámetro de desplazamiento específico de la sonda, puede cambiar el punto en el tiempo en que se ejecutará cada sonda. El desplazamiento se especifica en % del intervalo total, o alternativamente como 'random', y se usa el desplazamiento de la sección 'General' si no se especifica nada aquí. Tenga en cuenta que esto *no* influye en los RRD en sí, es solo una cuestión de cuándo se inicia la adquisición de datos. (Esta variable solo es aplicable si la variable 'concurrentprobes' está configurada en la sección 'General').

Valor de ejemplo: 50%

step
Duración del intervalo base que esta sonda debe usar, si es diferente del indicado en la sección 'Database'. Tenga en cuenta que el paso en los archivos RRD es fijo cuando se generan originalmente y, si cambia el parámetro de paso después, deberá eliminar los archivos RRD antiguos o convertirlos de alguna manera. (Esta variable solo es aplicable si la variable 'concurrentprobes' está configurada en la sección 'General').

Valor de ejemplo: 300

Variables específicas del destino admitidas:

/^influx_.+/
Esta es una etiqueta que se enviará a influxdb y no tiene impacto en la medición de la sonda. El nombre de la etiqueta se enviará sin el prefijo "influx_", que se reemplazará por "tag_". Las etiquetas se pueden usar para filtrar.

Valor de ejemplo: influx_location = En el sótano

authoritative
Enviar consultas no recursivas y requerir respuestas autoritativas.

Valor predeterminado: 0

expect_text
Una cadena que debe estar presente en la respuesta DNS. Esto se puede usar para verificar que un registro A contiene la dirección IP esperada, un registro PTR refleja el nombre de host esperado, etc. Si la consulta devuelve varios registros, cualquier coincidencia única pasará la prueba.

Valor de ejemplo: 192.168.50.60

ipversion
El protocolo IP utilizado. Los valores posibles son "4" y "6". Se pasa a echoping(1) como las opciones "-4" o "-6".

Valor de ejemplo: 4

Valor predeterminado: 4

lookup
Nombre del host a buscar en el DNS.

Valor de ejemplo: www.example.org

mininterval
Tiempo mínimo entre el envío de dos consultas de búsqueda en segundos (posiblemente fraccionarios).

Valor predeterminado: 0.5

pings
Cuántos pings se deben enviar a cada destino, si es diferente del valor global especificado en la sección Database. Tenga en cuenta que el número de pings en los archivos RRD es fijo cuando se generan originalmente y, si cambia este parámetro después, deberá eliminar los archivos RRD antiguos o convertirlos de alguna manera.

Valor de ejemplo: 5

port
El puerto UDP a usar.

Valor predeterminado: 53

protocol
El protocolo de red a usar.

Valor predeterminado: udp

recordtype
Tipo de registro a buscar.

Valor predeterminado: A

require_answers
Contar solo las respuestas con un número de respuestas >= este valor.

Valor predeterminado: 0

require_noerror
Contar solo las respuestas con estado de respuesta NOERROR.

Valor predeterminado: 0

require_nxdomain
Establecer en 1 si NXDOMAIN debe interpretarse como éxito en lugar de fracaso. Esto invierte el comportamiento normal de la sonda. Los usos de ejemplo incluyen probar un firewall DNS, verificar que la IP de un servidor de correo no esté listada en un DNSBL, u otros escenarios donde NXDOMAIN es deseado.

Valor de ejemplo: 0

Valor predeterminado: 0

timeout
Tiempo de espera para una sola solicitud en segundos.

Valor predeterminado: 5
