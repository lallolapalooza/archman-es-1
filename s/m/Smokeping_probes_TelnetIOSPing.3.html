NOMBRE

Smokeping::probes::TelnetIOSPing - Sonda Cisco IOS para SmokePing

SINOPSIS

*** Sondas ***
+TelnetIOSPing
forks = 5
offset = 50%
packetsize = 56
step = 300
timeout = 15
# Las siguientes variables se pueden sobrescribir en cada sección de destino
/^influx_.+/ = influx_location = En el sótano
iospass = contraseña # obligatorio
iosuser = usuario # obligatorio
pings = 5
psource = 192.168.2.129
source = 192.168.2.1 # obligatorio
vrf = VRF1
# [...]
*** Destinos ***
probe = TelnetIOSPing # si esta debe ser la sonda predeterminada
# [...]
+ mi_destino
# probe = TelnetIOSPing # si la sonda predeterminada es otra
host = mi.host
/^influx_.+/ = influx_location = En el sótano
iospass = contraseña # obligatorio
iosuser = usuario # obligatorio
pings = 5
psource = 192.168.2.129
source = 192.168.2.1 # obligatorio
vrf = VRF1

DESCRIPCIÓN

Integra Cisco IOS como una sonda en smokeping. Utiliza el protocolo telnet para ejecutar un ping desde un dispositivo IOS (fuente) a otro dispositivo (host). Esta sonda básicamente utiliza el "ping extendido" del Cisco IOS. Tiene la opción de especificar desde qué interfaz se origina el ping también.

VARIABLES

Variables específicas de la sonda admitidas:

forks
Ejecuta este número de procesos concurrentes como máximo

Valor de ejemplo: 5

Valor predeterminado: 5

offset
Si ejecutas muchas sondas concurrentemente, es posible que desees evitar que golpeen tu red al mismo tiempo. Usando el parámetro de offset específico de la sonda, puedes cambiar el punto en el tiempo en que se ejecutará cada sonda. El offset se especifica en % del intervalo total, o alternativamente como 'random', y se utiliza el offset de la sección 'General' si no se especifica nada aquí. Ten en cuenta que esto NO influye en los archivos rrds en sí, es solo una cuestión de cuándo se inicia la adquisición de datos. (Esta variable solo es aplicable si la variable 'concurrentprobes' está configurada en la sección 'General'.)

Valor de ejemplo: 50%

packetsize
La opción (opcional) packetsize le permite configurar el tamaño del paquete para los pings enviados.

Valor predeterminado: 56

step
Duración del intervalo base que esta sonda debe usar, si es diferente del especificado en la sección 'Database'. Ten en cuenta que el paso en los archivos RRD se fija cuando se generan originalmente, y si cambias el parámetro step después, tendrás que eliminar los archivos RRD antiguos o convertirlos de alguna manera. (Esta variable solo es aplicable si la variable 'concurrentprobes' está configurada en la sección 'General'.)

Valor de ejemplo: 300

timeout
Cuánto tarda un solo 'ping' como máximo

Valor de ejemplo: 15

Valor predeterminado: 5

Variables específicas del destino admitidas:

/^influx_.+/
Esta es una etiqueta que se enviará a influxdb y no tiene impacto en la medición de la sonda. El nombre de la etiqueta se enviará sin el prefijo "influx_", que se reemplazará con "tag_". Las etiquetas se pueden usar para filtrar.

Valor de ejemplo: influx_location = En el sótano

iospass
La opción iospass le permite especificar la contraseña para el nombre de usuario especificado con la opción iosuser.

Valor de ejemplo: contraseña

Esta configuración es obligatoria.

iosuser
La opción iosuser le permite especificar un nombre de usuario que tenga capacidad de ping en el dispositivo IOS.

Valor de ejemplo: usuario

Esta configuración es obligatoria.

pings
Cuántos pings se deben enviar a cada destino, si es diferente del valor global especificado en la sección Database. Ten en cuenta que el número de pings en los archivos RRD se fija cuando se generan originalmente, y si cambias este parámetro después, tendrás que eliminar los archivos RRD antiguos o convertirlos de alguna manera.

Valor de ejemplo: 5

psource
La opción (opcional) psource especifica una dirección IP o interfaz alternativa desde la que desea originar sus pings. Los routers pueden tener muchas direcciones IP e interfaces. Cuando haces ping desde un router, tienes la capacidad de elegir desde qué interfaz y/o qué dirección IP se origina el ping. Especificar una IP/interfaz no especifica necesariamente la interfaz desde la que saldrán los paquetes de ping, pero sí especificará de qué dirección parecerán provenir los paquetes. Si se omite esta opción, el dispositivo IOS originará el paquete automáticamente según el enrutamiento y/o las métricas. Si esto no tiene sentido para usted, simplemente déjelo fuera.

Valor de ejemplo: 192.168.2.129

source
La opción source especifica el dispositivo IOS al que nos conectamos por telnet. Esta es una dirección IP de un dispositivo IOS que usted/su servidor: 1) Tiene la capacidad de hacer telnet 2) Tiene un nombre de usuario y contraseña válidos

Valor de ejemplo: 192.168.2.1

Esta configuración es obligatoria.

vrf
La opción vrf permite especificar la vrf para el ping

Valor de ejemplo: VRF1

NOTAS

Configuración de IOS

El dispositivo IOS debe tener configurado un nombre de usuario/contraseña, así como la capacidad de conectarse a las VTY. por ejemplo:

!
username smokeping privilege 5 password 0 SmokepingPassword
!
line vty 0 4
 login local
 transport input telnet
!

Algunos dispositivos IOS tienen un máximo de 5 VTY disponibles, así que ten cuidado de no alcanzar un límite con la variable 'forks'.

Requisitos

Este módulo requiere el módulo Net::Telnet para perl. Generalmente se incluye en la mayoría de los sistemas operativos más recientes que incluyen perl.

Depuración

Hay código de depuración MUY rudimentario incorporado en este módulo (se basa en el código de depuración incorporado en Net::Telnet). Registrará información en tres archivos: "TIPreturn", "TIPoutlog" y "TIPdump". Estos archivos se escribirán en su directorio de trabajo actual (CWD). Puede cambiar los nombres de estos archivos por algo con más significado para usted.

Autenticación de contraseña

Se te debe advertir que el método de autenticación de telnet utiliza transmisiones de texto plano... lo que significa que sin las medidas de seguridad de red adecuadas, alguien podría capturar tu nombre de usuario y contraseña de la red. Puede que intente incorporar SSH en una futura versión de este módulo, pero es muy poco probable. En este momento, SSH añade una gran sobrecarga de procesamiento a un router y no es increíblemente fácil de implementar en perl.

Habiendo dicho esto, no tengas demasiado miedo de telnet. Recuerda que el módulo original IOSPing usaba RSH, que es aún más aterrador de usar desde una perspectiva de seguridad.

Tamaño del paquete de ping

El manual de FPing dice lo siguiente sobre el tema del tamaño del paquete de ping:

Número de bytes de datos de ping a enviar. El tamaño mínimo (normalmente 12) deja espacio para los datos que fping necesita para hacer su trabajo (número de secuencia, marca de tiempo). El tamaño de los datos recibidos reportados incluye la cabecera IP (normalmente 20 bytes) y la cabecera ICMP (8 bytes), por lo que el tamaño total mínimo es de 40 bytes. El valor por defecto es 56, como en ping. El máximo es teóric
