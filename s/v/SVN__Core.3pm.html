SVN__Core(3pm)

native::Core(3) Documentación de Perl aportada por el usuario native::Core(3)

NOMBRE

SVN::Core - Módulo central de los enlaces Perl de subversion

SINOPSIS

use SVN::Core; # realiza apr_initialize y cleanup por ti
# crea un pool raíz y establécelo como pool por defecto para uso posterior
my $pool = SVN::Pool->new_default;
sub algo {
    # crea un subpool del pool por defecto actual
    my $pool = SVN::Pool->new_default_sub;
    # algunas operaciones svn...
    # $pool se destruye y el pool por defecto anterior
    # se restaura cuando el ámbito léxico de $pool termina
}
# svn_stream_t como manejador de entrada/salida nativo de Perl
my $stream = $txn->root->apply_text('trunk/filea', undef);
print $stream $text;
close $stream;
# manejador de entrada/salida nativo de Perl como svn_stream_t
SVN::Repos::dump_fs($repos, \*STDOUT, \*STDERR,
                    0, $repos->fs->youngest_rev, 0);

DESCRIPCIÓN

SVN::Core implementa funciones de alto nivel de las funciones fundamentales de subversion.

FUNCIONES

SVN::Core::auth_open([auth proveedor array]);
Toma una referencia a un array de proveedores de autenticación y devuelve un auth_baton. Si usas proveedores de solicitud (prompt providers), no puedes usar esta función, sino que debes usar auth_open_helper.
SVN::Core::auth_open_helper([auth proveedor array]);
Los proveedores de solicitud devuelven dos valores en lugar de uno. El segundo parámetro es una referencia a lo que se les pasó como callback. auth_open_helper divide estos argumentos, pasando los objetos proveedor a auth_open, que le da un auth_baton, y colocando los otros en un array. El primer valor de retorno de esta función es el auth_baton, el segundo es una referencia a un array que contiene las referencias a los callbacks.

Estos arrays de callbacks deben almacenarse en el objeto al que se adjunta el auth_baton.

OTROS OBJETOS

svn_stream_t - SVN::Stream

Puedes usar manejadores de E/S nativos de Perl (incluyendo globs de E/S) como svn_stream_t en funciones de subversion. Los svn_stream_t devueltos también se traducen a manejadores de E/S de Perl, por lo que puedes acceder a ellos con print, read, etc. regulares.

Ten en cuenta que algunas funciones toman un stream para leer o escribir, pero no cierran el stream mientras aún mantienen la referencia al manejador de E/S. En este caso, el manejador no se destruirá correctamente. Siempre debes configurar el pool por defecto correcto antes de llamar a dichas funciones.

svn_pool_t - SVN::Pool

Los enlaces de Perl simplifican significativamente el uso de pools, al tiempo que permiten un ajuste manual.

Para las funciones que requieren un pool como último argumento (que son casi todas las funciones de subversion), el argumento del pool es opcional. Se utiliza el pool por defecto si se omite. Cuando se carga "SVN::Core", crea un nuevo pool por defecto, que también está disponible en "SVN::Core->gpool".

Para las funciones de callback que proporcionan un pool a tu subrutina, también puedes usar $pool->default para que sea el pool por defecto en el ámbito.

Métodos

new([$parent])
Crea un nuevo pool. El pool es un pool raíz si no se proporciona $parent.
new_default([$parent])
Crea un nuevo pool. El pool es un pool raíz si no se proporciona $parent. Establece el nuevo pool como pool por defecto.
new_default_sub
Crea un nuevo subpool del pool por defecto actual, y establece el pool resultante como el nuevo pool por defecto.
clear
Limpia el pool.
DESTROY
Destruye el pool. Si el pool era el pool por defecto, restaura el pool por defecto anterior. Esto normalmente se llama automáticamente cuando el objeto SVN::Pool ya no se utiliza y es destruido por el recolector de basura de Perl.

svn_error_t - SVN::Error

Por defecto, los enlaces de Perl manejan las excepciones por ti. El manejador por defecto automáticamente causa un error (croaks) con un mensaje de error apropiado. Esto es probablemente suficiente para scripts simples, pero un uso más complejo puede requerir el manejo de errores.

Puedes anular el manejador de excepciones por defecto cambiando la variable $SVN::Error::handler. Esta variable contiene una referencia a una subrutina de Perl que debe ser llamada siempre que una función svn devuelva un error. A esta subrutina se le pasará un objeto svn_error_t. Su valor de retorno se ignora.

Si estableces $SVN::Error::handler a undef, entonces cada llamada devolverá un objeto svn_error_t como su primer retorno en caso de error, seguido de los valores de retorno normales. Si no hay error, no se devolverá un svn_error_t y solo se devolverán los valores de retorno normales. Al usar este modo, debes tener cuidado de llamar solo a funciones en contexto de array. Por ejemplo: my ($ci) = $ctx->mkdir('http://svn/foo'); En este caso $ci será un objeto svn_error_t si ocurre un error y un objeto svn_client_commit_info en caso contrario. Si omites los paréntesis alrededor de $ci (contexto escalar) será el objeto commit_info, que en caso de error será undef.

Si planeas usar manejo explícito de excepciones, es útil comprender el sistema de manejo de excepciones que utiliza la API C. Puedes encontrar información sobre él en el archivo HACKING y en la documentación de la API. Revisar la implementación de SVN::Error::croak_on_error y SVN::Error::expanded_message también puede ser útil.

$svn_error_t->apr_err()
Valor de error de APR, posiblemente un error personalizado de SVN.
$svn_error_t->message()
Detalles del productor del error.
$svn_error_t->child()
Objeto svn_error_t del error que está siendo envuelto.
$svn_error_t->pool()
El pool que contiene este error y cualquier error hijo que envuelva.
$svn_error_t->file()
Archivo fuente donde se originó el error.
$svn_error_t->line()
Línea fuente donde se originó el error.
SVN::Error::strerror($apr_status_t)
Devuelve la descripción en inglés del código de estado.
$svn_error_t->strerror()
Devuelve la descripción en inglés del código de estado apr_err establecido en el $svn_error_t. Esto es una abreviatura de: SVN::Error::strerror($svn_error_t->apr_err());
SVN::Error::create($apr_err, $child, $message);
Devuelve un nuevo objeto svn_error_t con el estado de error especificado en $apr_err, el hijo como $child, y el mensaje de error de $message.
SVN::Error::quick_wrap($child, $new_msg); o $child->quick_wrap($new_msg);
Una forma rápida y sencilla de crear una excepción envuelta con tu propio mensaje antes de lanzarla por la pila.

$child es el objeto svn_error_t que quieres envolver y $new_msg es el nuevo string de error que quieres establecer.

SVN::Error::compose($chain, $new_error); o $chain->compose($new_error);
Añade new_err al final de la cadena de errores de $chain.

La cadena $new_err se copiará en el pool de $chain y se destruirá, por lo que $new_err mismo se vuelve inválido después de esta función.

SYNOPSIS

use SVN::Error;

DESCRIPTION

This module provides the Subversion error handling mechanism as a Perl API.

The primary object passed around is svn_error_t. The Subversion API functions often return this type of object on failure, and undef on success.

You will need to call SVN::Error::clear() on any error objects you receive, or you will leak memory. The bindings also provide convenience functions to handle this for you.

The default error handler is SVN::Error::croak_on_error. This is set via the global variable $SVN::Error::handler.

The SVN::Error::hook_handler is called just before $SVN::Error::handler is called. If the hook handler returns an error, then the handler is not called.

SVN::Error::clear($svn_error_t); or $svn_error_t->clear();

Libera la memoria utilizada por $svn_error_t, así como todos sus ancestros y descendientes.

Debes llamar a esta función en cada objeto svn_error_t que obtengas o filtrarás memoria.

SVN::Error::expanded_message($svn_error_t) or $svn_error_t->expanded_message()
Devuelve el mensaje de error rastreando el objeto svn_error_t y sus hijos, concatenando los mensajes de error. Así es como los manejadores de excepciones internos obtienen sus mensajes de error.
SVN::Error::is_error($value)
Devuelve verdadero si el valor es de tipo svn_error. Devuelve falso si el valor es cualquier otra cosa o indefinido. Esto es útil para ver si una llamada ha devuelto un error.
SVN::Error::croak_on_error
Manejador de errores predeterminado. Toma un svn_error_t y extrae los mensajes de error de él y colapsa con esos mensajes.

Se puede usar de dos maneras. La primera se detalla arriba como establecerlo como el manejador automático de excepciones estableciendo $SVN::Error::handler.

La segunda es si tienes $SVN::Error::handler establecido a undef como un envoltorio para llamadas en las que deseas colapsar cuando hay un error, pero no quieres escribir un manejador de errores explícito. Por ejemplo:

my $rev = SVN::Error::croak_on_error($ctx->checkout($url,$path,'HEAD',1));

Si no hay error, croak_on_error devolverá los argumentos que se le pasaron sin cambios.

SVN::Error::confess_on_error
Lo mismo que croak_on_error excepto que dará una traza de pila más detallada, incluyendo llamadas internas dentro de la implementación de los enlaces de perl. Esto es útil cuando estás haciendo trabajo de desarrollo en los propios enlaces.
SVN::Error::ignore_error
Esto es útil para envolver llamadas alrededor de las cuales deseas ignorar cualquier error potencial. Comprueba si el primer parámetro es un error y, si lo es, lo borra. Luego devuelve los otros parámetros.

svn_depth_t - SVN::Depth

Un enum de las siguientes constantes:

$SVN::Depth::unknown
Profundidad indeterminada o ignorada. En algunos contextos, esto significa que el cliente debe elegir una profundidad predeterminada adecuada. El servidor generalmente lo tratará como $SVN::Depth::infinity.
$SVN::Depth::exclude
Excluir (es decir, no descender dentro) del directorio D.

Nota: En Subversion 1.5, $SVN::Depth::exclude no es compatible en ningún lugar del código del lado del cliente (Wc/Client/etc); solo es compatible como argumento para las funciones set_path en los reporteros Ra y Repos. (Esto permitirá que las versiones futuras de Subversion ejecuten actualizaciones, etc., contra servidores 1.5 con el comportamiento adecuado de $SVN::Depth::exclude, una vez que tengamos la oportunidad de implementar soporte del lado del cliente para $SVN::Depth::exclude).

$SVN::Depth::empty
Solo el directorio D nombrado, sin entradas.

Las actualizaciones no incluirán ningún archivo ni subdirectorio que no esté ya presente.

$SVN::Depth::files
D + sus archivos hijos, pero no subdirectorios.

Las actualizaciones incluirán cualquier archivo que no esté ya presente, pero no subdirectorios.

$SVN::Depth::immediates
D + hijos inmediatos (D y sus entradas).

Las actualizaciones incluirán cualquier archivo o subdirectorio que no esté ya presente; las entradas de this_dir de esos subdirectorios tendrán depth-empty.

$SVN::Depth::infinity
D + todos los descendientes (recursión completa desde D).

Las actualizaciones incluirán cualquier archivo o subdirectorio que no esté ya presente; las entradas de this_dir de esos subdirectorios tendrán depth-infinity. Equivalente al comportamiento de actualización predeterminado anterior a 1.5.

DESCRIPCIÓN

Los objetos de esta clase contienen información sobre las barreras colocadas en archivos de un repositorio. Tiene los siguientes métodos de acceso:

path
La ruta completa al archivo que está bloqueado, comenzando con un tildé ("/").
token
Una cadena que contiene el token de bloqueo, que es un URI único.
owner
El nombre de usuario que posee el bloqueo.
comment
Un comentario asociado al bloqueo, o undef si no hay uno.
is_dav_comment
Verdadero si el comentario fue hecho por un cliente DAV genérico.
creation_date
Fecha en la que se creó el bloqueo, como el número de microsegundos desde 00:00:00 1 de enero 1970 UTC. Divide por 1_000_000 para obtener un valor de time_t.
expiration_date
¿ Cuándo el bloqueo se vencerá? Tiene el valor '0' si el bloqueo nunca se vencerá.
