NOMBRE

SVN::Ra - Funciones de acceso remoto de Subversion

SINOPSIS

use SVN::Core;
use SVN::Ra;
my $ra = SVN::Ra->new('file:///tmp/svntest');
print $ra->get_latest_revnum;

DESCRIPCIÓN

SVN::Ra envuelve las funciones orientadas a objetos "svn_ra_plugin_t", proporcionando acceso a un repositorio de Subversion a través de una URL, utilizando el módulo de acceso al repositorio apropiado.

SVN::Ra

SVN::Ra->new(...)

El constructor crea un objeto RA y llama a "open" para él. Sus parámetros son un hash de opciones o un único valor que contiene la URL del repositorio. Las opciones válidas son:

url
La URL del repositorio.
auth
Se puede proporcionar un "auth_baton" al objeto SVN::RA. Por defecto es un "auth_provider" con un "username_provider". Consulte SVN::Client para saber cómo crear "auth_baton".
pool
El pool que la sesión RA debe usar. Las funciones miembro también se llamarán con este pool. Por defecto es un pool raíz recién creado.
config
El hash de configuración que se puede obtener llamando a SVN::Core::config_get_config(undef).
callback
El espacio de nombres "ra_callback" a usar. Por defecto es SVN::Ra::Callbacks.

Los siguientes ejemplos harán lo mismo, con todos los argumentos opcionales tomando sus valores por defecto:

my $ra = SVN::Ra->new('file:///tmp/repos');
my $ra = SVN::Ra->new(url => 'file:///tmp/repos');

MÉTODOS

Por favor, consulte la sección svn_ra.h de la API de Subversion. Las funciones miembro de "svn_ra_plugin_t" se pueden llamar como métodos de objetos SVN::Ra, omitiendo los argumentos "session_baton" y "pool".

$ra->change_rev_prop($revnum, $name, $value)
Establece la propiedad de revisión (no versionada) $name a $value en la revisión $revnum, o elimina la propiedad si $value es indefinido. 
$ra->change_rev_prop(123, 'svn:log', 'Nuevo mensaje de registro.');

Por supuesto, esto solo funcionará si hay un hook "pre-revprop-change" disponible.

$ra->check_path($path, $revnum)
Tipo de nodo en $path en la revisión $revnum. Un número que coincide con una de estas constantes: $SVN::Node::none, $SVN::Node::file, $SVN::Node::dir, $SVN::Node::unknown.
$ra->do_diff($revision, $target, $recurse, $ignore_ancestry, $versus_url, $editor)
$ra->do_diff2($revision, $target, $recurse, $ignore_ancestry, $text_deltas, $versus_url, $editor)
Ambos devuelven un SVN::Ra::Reporter con el que se puede describir una copia de trabajo. Luego llamará a métodos en $editor para indicar las diferencias entre el repositorio y la copia de trabajo.

El método "do_diff2" se añadió en Subversion 1.4. Añade la opción $text_deltas, que si es falsa deshabilita la generación de deltas de texto en el editor. Con "do_diff" los deltas de texto siempre se generan.

my $reporter = $ra->do_diff(1, '', 1, 0, $repos_url,
                            MyEditor->new);
$reporter->set_path(...);
$reporter->finish_report;
$ra->do_status($target, $revision, $recurse, $editor)
Devuelve un SVN::Ra::Reporter al que se puede describir el estado de una copia de trabajo. Luego llamará a métodos en $editor para describir el estado actual de la copia de trabajo en comparación con el repositorio.
$ra->do_switch($revnum, $target, $recurse, $repos_url, $editor)
Devuelve un SVN::Ra::Reporter con el que se puede describir una copia de trabajo. Luego llamará a métodos en $editor para indicar cómo ajustar la copia de trabajo para cambiarla a la revisión $revnum de $repos_url.
$ra->do_update($revision_to_update_to, $target, $recurse, $editor)
Devuelve un objeto SVN::Ra::Reporter. Llame a métodos en el reporter para describir el estado actual de su copia de trabajo (o lo que sea que esté actualizando). Después de llamar al método finish_report() del reporter, Subversion generará llamadas a su $editor para describir las diferencias entre lo que ya tiene y el estado del repositorio en $revision_to_update_to.

Para actualizar a la última revisión, pase $SVN::Core::INVALID_REVNUM como primer argumento.

$target debe ser la ruta a la parte del repositorio que le interesa. No se le proporcionará información sobre cambios fuera de esta ruta. Si desea todo, pase una cadena vacía.

Si $recurse es verdadero y el objetivo es un directorio, actualice recursivamente; de lo contrario, actualice solo el objetivo y sus entradas inmediatas, pero no sus subdirectorios (si los hay).

Todas las rutas son relativas a la URL utilizada para abrir $ra.

El llamador no puede realizar ninguna operación RA utilizando $ra antes de finalizar el informe, y no puede realizar ninguna operación RA utilizando $ra desde dentro de las operaciones de edición de $editor.

Este ejemplo muestra la actualización más simple, donde el cliente le dice al reporter que no tiene nada con lo que empezar:

my $reporter = $ra->do_update($revnum, '', 1, MyEditor->new);
$reporter->set_path('', 0, 1, undef);
$reporter->finish_report;

    El llamador no puede invocar ninguna operación RA usando $ra desde dentro de la función de devolución de llamada. Pueden funcionar en algunas situaciones, pero no está garantizado.

    El primer argumento puede ser una cadena única o una referencia a una matriz de cadenas. Cada uno de estos indica una ruta en el repositorio que te interesa.     $limit es un número que indica el número máximo de veces que se debe llamar a la función de recepción callback(). Si es 0, no habrá límite.

    • Nombre del usuario que realizó el cambio, o undef si no se conoce.

    • Mensaje de registro como una sola cadena, o undef.
    • Un objeto de grupo (pool).

    $ra->get_log('', 1, $ra->get_latest_revnum, 0, 1, 0,

sub log_callback
{
    my ($paths, $revnum, $user, $datetime, $logmsg) = @_;
    print "$datetime - $user - r$revnum\n";
    while (my ($path, $changes) = each %$paths) {
        print $changes->action, " $path\n";
        if ($changes->copyfrom_path) {
            print " from ", $changes->copyfrom_path,
                  " r", $changes->copyfrom_rev, "\n"
        }
    }
    print "\n";
}

    SVN::Ra

    Raw SVN access functions.

    NAME

    SVN::Ra - Raw SVN access functions.

    SYNOPSIS

      use SVN::Ra;

  # Access repository
  my $ra = SVN::Ra->open("svn://svn.example.com/repo",
                         "username", "password",
                         $auth_baton);
  $ra->close();

  # Get info about a file
  my ($info, $rev) = $ra->stat("/trunk/README");

  # Get diff
  $ra->do_diff($rev1, $rev2, \&diff_callback);

  # Update
  $ra->do_update($rev, \&reporter);

  # Switch
  $ra->do_switch($rev, \&reporter);

  # Get log messages
  $ra->get_log($rev1, $rev2, \&log_callback);

  # Lock/Unlock
  my $token = $ra->lock("/trunk/config.txt");
  $ra->unlock("/trunk/config.txt", $token);

  # Other methods...

    DESCRIPTION

    This module provides Perl bindings for the Subversion libsvn_ra library. It allows you to perform remote Subversion operations such as checking status, getting diffs, updating, switching, and retrieving log messages.

    The methods in this module typically take callback subroutines. These callbacks are invoked by the SVN::Ra module when Subversion needs to get information from your client, such as when describing the state of your working copy.

    Note:

    The SVN::Ra module requires the Subversion client libraries to be installed on your system.

    SVN::Ra::Reporter

    The SVN::Ra methods "do_diff", "do_status", "do_switch", and "do_update" all return a SVN::Ra::Reporter object, which can be used to describe the working copy (or other available data) which the client has. Subversion uses this to figure out what new information should be provided through a tree delta editor.

    Objects of this class are actually simple wrappers around underlying "svn_ra_reporter2_t" objects and their associated baton.

    METHODS

    $reporter->set_path($path, $revision, $start_empty, $lock_token, $pool)
    Describe a working copy $path as being at a particular $revision.

    If $start_empty is true and $path is a directory, the implementor should assume the directory has no entries or properties.

    This will override any previous set_path() calls made on parent paths. $path is relative to the URL specified in "SVN::Ra->open()" or "SVN::Ra->new()".

    If $lock_token is not undef, it is the lock token for $path in the WC.

    All temporary allocations are done in $pool.

    $reporter->delete_path($path, $pool)
    Describe a working copy $path as missing.

    All temporary allocations are done in $pool.

    $reporter->link_path($path, $url, $revision, $start_empty, $lock_token, $pool)
    Like set_path(), but differs in that $path in the working copy (relative to the root of the report driver) isn't a reflection of $path in the repository (relative to the URL specified when opening the RA layer), but is instead a reflection of a different repository $url at $revision.

    If $start_empty is true and $path is a directory, the implementor should assume the directory has no entries or props.

    If $lock_token is not undef, it is the lock token for $path in the WC.

    All temporary allocations are done in $pool.

    $reporter->finish_report($pool)
    Call this when the state report is finished; any directories or files not explicitly 'set' are assumed to be at the baseline revision originally passed into do_update(). No other reporting functions, including abort_report(), should be called after calling this function.
    $reporter->abort_report($pool)
    If an error occurs during a report, this method should cause the filesystem transaction to be aborted and cleaned up. No other reporting methods should be called after calling this method.

    SVN::Ra::Callbacks

    This is the wrapper class for "svn_ra_callback_t". To supply custom callbacks to SVN::Ra, subclass this class and override the member functions.
