NOMBRE

SVN::Client - Funciones cliente de Subversion

SINOPSIS

use SVN::Client;
my $client = new SVN::Client();
# configurar para manejar la autenticación igual que el cliente de línea de comandos
my $config_dir = undef; # usar ubicación predeterminada
my $config = SVN::Core::config_get_config($config_dir);
my $config_category = $cfg->{SVN::Core::CONFIG_CATEGORY_CONFIG};
$client->auth(
  SVN::Core::cmdline_create_auth_baton(0,           # no interactivo
                                       undef,       # nombre de usuario
                                       undef,       # contraseña
                                       $config_dir,
                                       0,           # sin caché de autenticación
                                       0,           # no confiar en el certificado del servidor
                                       $config_category,
                                       undef)       # callback de cancelación
);
# Usar el primer argumento como destino y canonizarlo antes de usarlo
my $target;
if (SVN::Core::path_is_url($ARGV[0])) {
  $target = SVN::Core::uri_canonicalize($ARGV[0]);
} else {
  $target = SVN::Core::dirent_canonicalize($ARGV[0]);
}
# obtener la última revisión del destino
$client->cat(\*STDOUT, $target, 'HEAD');

DESCRIPCIÓN

SVN::Client envuelve las funciones de más alto nivel proporcionadas por Subversion para lograr tareas específicas en una API orientada a objetos. Los métodos son similares a las funciones proporcionadas por la API de C y, como tales, la documentación de esta puede ser útil para comprender esta interfaz.

Hay algunas diferencias notables con la API de C. La mayoría de las llamadas a funciones de C toman un puntero svn_client_ctx_t como el penúltimo parámetro. Las llamadas a métodos de Perl toman un objeto SVN::Client como el primer parámetro. Esto permite la invocación de métodos para que las funciones sean posibles. Por ejemplo, lo siguiente es equivalente:

SVN::Client::add($client,$path, $recursive, $pool);
$client->add($path, $recursive, $pool);

Muchas de las llamadas a la API de C también toman un puntero apr_pool_t como su último argumento. Los enlaces de Perl generalmente se encargan de esto por usted y no necesita pasar un parámetro de pool. Sin embargo, aún puede pasar un parámetro de pool como el último parámetro para anular el manejo automático de esto por usted.

Los usuarios de esta interfaz no deben manipular directamente los valores hash subyacentes, sino que deben utilizar los métodos de atributo respectivos. Muchos de estos métodos de atributo hacen otras cosas, especialmente al establecer un atributo, además de simplemente manipular el valor en el hash.

NOTAS SOBRE PARÁMETROS

Los métodos cliente descritos a continuación toman una variedad de parámetros. Muchos de ellos son similares. Los métodos que aceptan los parámetros nombrados a continuación seguirán las reglas a continuación o se notarán de otra manera en la descripción del método.

$client
Un objeto SVN::Client que obtienes del constructor.
$url
Esta es una URL a un repositorio de Subversion.
$path
Esta es una ruta a un archivo o directorio en el sistema de archivos local. Las rutas deben ser canonizadas antes de pasarlas a las API de Subversion. Las rutas en el sistema de archivos local se llaman dirents y se pueden canonizar llamando a "SVN::Core::dirent_canonicalize".
$paths
Este argumento puede ser un único $path (como se define arriba) o una referencia a una matriz de ellos.
$target
Esta es una ruta a un archivo o directorio en una copia de trabajo o una URL a un archivo o directorio en un repositorio de Subversion. Tanto las rutas como las URL deben ser canonizadas antes de pasarlas a las API de Subversion. Las rutas en el sistema de archivos local se llaman dirents y se pueden canonizar llamando a "SVN::Core::dirent_canonicalize". Las URL se pueden canonizar llamando a "SVN::Core::uri_canonicalize".
$targets
Este argumento puede ser un único $target (como se define arriba) o una referencia a una matriz de ellos.
$revision
Esto especifica una revisión en el repositorio de Subversion. Puede especificar una revisión de varias maneras. La más fácil y obvia es proporcionar directamente el número de revisión. También puede usar las cadenas (también conocidas como palabras clave de revisión) 'HEAD', 'BASE', 'COMMITTED' y 'PREV', que tienen los mismos significados que en el cliente de línea de comandos. Al hacer referencia a una copia de trabajo, puede usar la cadena 'WORKING' para hacer referencia a la BASE más cualquier modificación local. Se puede usar "undef" para especificar una revisión no especificada. También puede pasar una fecha especificando la fecha entre llaves '{}'. Los formatos de fecha aceptados son los mismos que acepta el cliente de línea de comandos. Finalmente, se acepta un objeto "_p_svn_opt_revision_t" (que puede haber sido devuelto por alguna función de Subversion).
$recursive $nonrecursive.
Un parámetro booleano que especifica si la acción debe seguir los directorios. Solo debe ser 1 o 0. $recursive significa que 1 significa descender en los directorios, 0 significa no hacerlo. $nonrecursive tiene el significado inverso.
$pool
Pool es siempre una opción de parámetro. Si desea pasar un parámetro de pool, debe ser un objeto SVN::Pool o apr_pool_t.

$client->add($targets, $force, $add_parents, $no_ignore, $pool);
Schedule files and directories for addition to version control.

If $targets contains no paths (zero elements), then does nothing and immediately returns without error.

If $force is TRUE, then any local modifications to existing versioned files will be ignored and the files will be added as they are. Unversioned items will be added.

Do not add any file or directory (or recurse into any directory) that is unversioned and found by recursion (as opposed to being the explicit target $path) and whose name matches the svn:ignore property on its parent directory or the global-ignores list in $client->config. If $no_ignore is TRUE, do include such files and directories. (Note that an svn:ignore property can influence this behaviour only when recursing into an already versioned directory with $force).

If $add_parents is TRUE, recurse up $path's directory and look for a versioned directory. If found, add all intermediate paths between it and $path. If not found return $SVN::Error::NO_VERSIONED_PARENT.

Important: this is a scheduling operation. No changes will happen to the repository until a commit occurs. This scheduling can be removed with $client->revert().

No return.

$client->blame($target, $start, $end, \&receiver, $pool);
Invoke \&receiver subroutine on each line-blame item associated with revision $end of $target, using $start as the default source of all blame.

An Error will be raised if either $start or $end is undef.

No return.

The blame receiver subroutine receives the following arguments: $line_no, $revision, $author, $date, $line, $pool

$line_no is the line number of the file (starting with 0). The line was last changed in revision number $revision by $author on $date and the contents were $line.

The blame receiver subroutine can return an svn_error_t object to return an error. All other returns will be ignored. You can create an svn_error_t object with SVN::Error::create().

$client->cat(\*FILEHANDLE, $target, $revision, $pool);
Outputs the content of the file identified by $target and $revision to the FILEHANDLE. FILEHANDLE is a reference to a filehandle.

If $target is not a local path and if $revision is 'PREV' (or some other kind that requires a local path), then an error will be raised, because the desired revision can not be determined.

$client->checkout($url, $path, $revision, $recursive, $pool);
Similar to $client->checkout2(), but with $peg_revision always set to undef (unspecified) and $ignore_externals always set to FALSE.
$client->checkout2($url, $path, $peg_revision, $revision, $recursive, $ignore_externals, $pool);
Similar to $client->checkout3(), but with $allow_unver_obstructions always set to FALSE, and $depth set according to $recurse: if $recurse is TRUE, $depth is $SVN::Depth::infinity, if $recurse is FALSE, set $depth to $SVN::Depth::files.
$client->checkout3($url, $path, $preg_revision, $revision, $depth, $ignore_externals, $allow_unver_obstructions, $pool);
Checkout a working copy of $url at $revision using $path as the root directory of the newly checked out working copy.

The $peg_revision sets the revision at which the path in the $url is treated as representing.

$revision must be a number, 'HEAD', or a date. If $revision does not meet these requirements the $SVN::Error::CLIENT_BAD_REVISION is raised.

$depth is one of the constants in SVN::Depth and specifies the depth of the operation. If set to $SVN::Depth::unknown, then behave as if for $SVN::Depth::infinity, except in the case of resuming a previous checkout of $path (i.e. updating) in which case use the depth of the existing working copy.

$ignore_exteranls if set to TRUE the operation will ignore external definitions.

$allow_unver_obstructions if set to TRUE the operation will tolerate existing unversioned items that obstruct incoming paths. Only obstructions of the same type (file or dir) as the added item are tolerated. The text of obstructing files is left as-is, effectively treating it as a user modification after the checkout. Working properties of obstructing items are set equal to the base properties. If set to FALSE, then abort if there are any unversioned obstructing items.

Returns the value of the revision actually checked out of the repository.

$client->cleanup($dir, $pool);
Recursively cleanup a working copy directory, $dir, finishing any incomplete operations, removing lockfiles, etc.
$client->commit($targets, $nonrecursive, $pool);
Commit files or directories referenced by target. Will use the log_msg callback to obtain the log message for the commit.

If $targets contains no paths (zero elements), then does nothing and immediately returns without error.

Calls the notify callback as the commit progresses with any of the following actions: $SVN::Wc::Notify::Action::commit_modified, $SVN::Wc::Notify::Action::commit_added, $SVN::Wc::Notify::Action::commit_deleted, $SVN::Wc::Notify::Action::commit_replaced, $SVN::Wc::Notify::Action::commit_postfix_txdelta.

Use $nonrecursive to indicate that subdirectories of directory targets should be ignored.

Returns a svn_client_commit_info_t object. If the revision member of the commit information object is $SVN::Core::INVALID_REVNUM and no error was raised, then the commit was a no-op; nothing needed to be committed.

$client->copy($src_target, $src_revision, $dst_target, $pool);
Copies $src_target to $dst_target.

$src_target must be a file or directory under version control, or the URL of a versioned item in the repository. If $src_target is a URL, $src_revision is used to choose the revision from which to copy the $src_target. $dst_path must be a file or directory under version control, or a repository URL, existing or not.

If $dst_target is a URL, immediately attempt to commit the copy action to the repository. The log_msg callback will be called to query for a commit log message. If the commit succeeds, return a svn_client_commit_info_t object.

If $dst_target is not a URL, then this is just a variant of $client->add(), where the $dst_path items are scheduled for addition as copies. No changes will happen to the repository until a commit occurs. This scheduling can be removed with $client->revert(). undef will be returned in this case.

Calls the notify callback for each item added at the new location, passing the new, relative path of the added item.

$client->delete($targets, $force, $pool);
Delete items from a repository or working copy.

If the paths in $targets are URLs, immediately attempt to commit a deletion of the URLs from the repository. The log_msg callback will be called to query for a commit log message. If the commit succeeds, return a svn_client_commit_info_t object. Every path must belong to the same repository.

Else, schedule the working copy paths in $targets for removal from the repository. Each path's parent must be under revision control. This is just a scheduling operation. No changes will happen to the repository until a commit occurs. This scheduling can be removed with $client->revert(). If a path is a file it is immediately removed from the working copy. If the path is a directory it will remain in the working copy but all the files, and all unversioned items it contains will be removed. If $force is not set then this operation will fail if any path contains locally modified and/or unversioned items. If $force is set such items will be deleted.

The notify callback is called for each item deleted with the path of the deleted item.

Has no return.

$client->diff($diff_options, $target1, $revision1, $target2, $revision2, $recursive, $ignore_ancestry, $no_diff_deleted, $outfile, $errfile, $pool);
Produces diff output which describes the delta between $target1 at $revision1 and $target2 at $revision2. They both must represent the same node type (i.e. they most both be directories or files). The revisions must not be undef.

Prints the output of the diff to the filename or filehandle passed as $outfile, and any errors to the filename or filehandle passed as $errfile.

Use $ignore_ancestry to control whether or not items being diffed will be checked for relatedness first. Unrelated items are typically transmitted to the editor as a deletion of one thing and the addition of another, but if this flag is true, unrelated items will be diffed as if they were related.

If $no_diff_deleted is true, then no

diff output will be generated on deleted files.

$diff_options es una referencia a un array de argumentos adicionales para pasar al proceso diff invocado para comparar archivos. Por lo general, solo querrás usar [] para pasar un array vacío y obtener un diff de contexto unificado (como `diff -u`).

No tiene retorno.

$client->diff_summarize($target1, $revision1, $target2, $revision2, $recursive, $ignore_ancestry, \&summarize_func, $pool);
Produce un resumen de diff que lista los elementos cambiados entre $target1 en la revisión $revision1 y $target2 en la revisión $revision2 sin crear deltas de texto. $target1 y $target2 pueden ser rutas de copia de trabajo o URLs.

La función puede reportar falsos positivos si $ignore_ancestry es falso, ya que un archivo podría haber sido modificado entre dos revisiones pero aún tener el mismo contenido.

Llama a \&summarize_func con una estructura svn_client_diff_summarize_t que describe la diferencia.

Consulta diff() para una descripción de los otros parámetros.

No tiene retorno.

$client->export($from, $to, $revision, $force, $pool);
Exporta el contenido de un repositorio subversión o de una copia de trabajo subversión a un directorio 'limpio' (es decir, un directorio sin directorios administrativos).

$from es la ruta a la copia de trabajo en disco o una URL al repositorio que deseas exportar.

$to es la ruta al directorio donde deseas crear el árbol exportado.

$revision es la revisión que debe ser exportada, la cual solo se usa al exportar desde un repositorio. Puede ser undef en caso contrario.

La función de notificación será llamada para los elementos exportados.

Devuelve el valor de la revisión realmente exportada o $SVN::Core::INVALID_REVNUM para exportaciones locales.

$client->import($path, $url, $nonrecursive, $pool);
Importa el archivo o directorio $path al directorio del repositorio $url en la revisión HEAD.

Si algunos componentes de $url no existen, se crearán los directorios padres según sea necesario.

Si $path es un directorio, el contenido de ese directorio se importa directamente al directorio identificado por $url. Nota que el directorio $path en sí no se importa; es decir, el nombre base de $path no es parte de la importación.

Si $path es un archivo, entonces el nombre del directorio de $url es el directorio que recibe la importación. El nombre base de $url es el nombre del archivo en el repositorio. En este caso, si $url ya existe, se producirá un error.

La función de notificación (si está definida) se llamará a medida que la importación progrese, con cualquiera de las siguientes acciones: $SVN::Wc::Notify::Action::commit_added, $SVN::Wc::Notify::Action::commit_postfix_txdelta.

Usa $nonrecursive para indicar que los directorios importados no deben recursar en ningún subdirectorio que puedan tener.

Utiliza la función de callback log_msg para determinar el mensaje de registro para el commit cuando sea necesario.

Devuelve un objeto svn_client_commit_info_t.

$client->info($path_or_url, $peg_revision, $revision, \&receiver, $recurse);
Invoca \&receiver pasándole información sobre $path_or_url para la revisión $revision. La información devuelta es metadatos generados por el sistema, no el tipo de metadatos de "propiedad" creados por los usuarios. Para métodos disponibles en el objeto pasado a \&receiver, **ver svn_info_t**.

Si ambos argumentos de revisión son svn_opt_revision_unspecified o NULL, entonces la información se extraerá únicamente de la copia de trabajo; no se realizarán conexiones de red.

De lo contrario, la información se extraerá de un repositorio. La revisión de nodo real seleccionada se determina por $path_or_url tal como existe en $peg_revision. Si $peg_revision es undef, entonces por defecto es HEAD para URLs o WORKING para objetivos de WC.

Si $path_or_url no es una ruta local, entonces si $revision es PREV (o algún otro tipo que requiera una ruta local), se devolverá un error, ya que la revisión deseada no puede ser determinada.

Utiliza el baton de autenticación almacenado en caché en ctx para autenticarse contra el repositorio.

Si $recurse es verdadero (y $path_or_url es un directorio) esta será una operación recursiva, invocando $receiver en cada hijo.

my $receiver = sub {
    my( $path, $info, $pool ) = @_;
    print "Current revision of $path is ", $info->rev, "\n";
};
$client->info( 'foo/bar.c', undef, 'WORKING', $receiver, 0 );
$client->log5($targets, $peg_revision, $revision_ranges, $limit, $discover_changed_paths, $strict_node_history, $include_merged_revisions, $revprops, \&log_entry_receiver, $pool);
Invoca "log_entry_receiver" en cada mensaje de registro de cada rango de revisión en $revision_ranges por turnos, inclusivo (pero nunca invoca "log_entry_receiver" en un mensaje de registro dado más de una vez).

$targets es una referencia a un array de o bien una URL seguida de cero o más rutas relativas, o 1 ruta de copia de trabajo, para las cuales se desean mensajes de registro. Si el array contiene solo un elemento, puedes establecer $targets a este elemento en su lugar. "log_entry_receiver" se invoca solo en mensajes cuyas revisiones involucraron un cambio en alguna ruta en $targets.

$peg_revision indica en qué revisión $targets son válidas. Si $peg_revision es "undef", por defecto es 'HEAD' para URLs o 'WORKING' para rutas de WC.

$revision_ranges es un único *rango de revisión* o una referencia a un array de ellos. Un *rango de revisión* puede especificarse como una referencia a un array de dos elementos "[$start, $end]" de $revisions o un objeto SVN::Core::svn_opt_revision_range_t. Ejemplos:

$revision_ranges = ['HEAD', 1];
$revision_ranges = [[2, 3], [5, 8], [13, 21]];

Si $limit no es cero, solo invoca "log_entry_receiver" en los primeros $limit registros.

Si $discover_changed_paths es verdadero, entonces el campo *changed_paths2* en el argumento $log_entry para "log_entry_receiver" se poblará en cada invocación. *Nota:* Los campos *text_modified* y *props_modified* de la estructura *changed_paths2* pueden tener el valor $SVN::Tristate::unknown si el repositorio no informa esa información.

Si $strict_node_history es verdadero, el historial de copias (si existe) no será recorrido al recopilar los mensajes de registro para cada objetivo.

Si $include_merged_revisions es verdadero, también se devolverá información de registro para revisiones que se hayan fusionado a $targets.

Si $revprops es "undef", recupera todas las propiedades de revisión. De lo contrario, $revpros debe ser una referencia a un array de nombres de propiedades y solo se recuperarán estas propiedades (es decir, ninguna si el array está vacío).

Usa $pool para cualquier asignación temporal.

Llama a la subrutina de notificación con una señal $SVN::Wc::Notify::Action::skip en cualquier $targets no versionado.

El "log_entry_receiver" toma los siguientes argumentos: "$log_entry, $pool". $log_entry es un objeto SVN::Core::svn_log_entry_t.

$client->log4($targets, $peg_revision, $start, $end, $limit, $discover_changed_paths, $strict_node_history, $include_merged_revisions, $revprops, \&log_entry_receiver, $pool);
Similar a "$client->log5()", pero toma parámetros explícitos $start y $end en lugar de $revision_ranges.

Obsoleto.

$client->log3($targets, $peg_revision, $start, $end, $limit, $discover_changed_paths, $strict_node_history, \&log_message_receiver, $pool);
Similar a "$client->log4()", pero usando "log_message_receiver" en lugar de "log_entry_receiver". Además, $include_merged_revisions es falso y $revprops es [qw( svn:author svn:date and svn:log )].

El "log_message_receiver" toma los siguientes argumentos: "$changed_paths, $revision, $author, $date, $message, $pool". Se llama una vez por cada mensaje de registro $message de la revisión $revision en la fecha $date por el autor $author. $author, $date o $message pueden ser "undef".

Si $changed_paths está definido, hace referencia a un hash con las claves de cada ruta confirmada en $revision; los valores son objetos SVN::Core::svn_log_changed_path_t.

Obsoleto.

$client->log2($targets, $start, $end, $limit, $discover_changed_paths, $strict_node_history, \&log_message_receiver, $pool);
Similar a "$client->log3()", pero con $peg_revision establecido a "undef".

Obsoleto.

$client->log($targets, $start, $end, $discover_changed_paths, $strict_node_history, \&log_message_receiver, $pool);
Similar a "$client->log2()", pero con $limit establecido a 0.

Caso especial para repositorios en la revisión 0: Si $start es 'HEAD' y $end es 1, maneja un repositorio vacío (sin revisiones) de forma especial: en lugar de generar un error porque se solicita la revisión 1 cuando la revisión más alta es 0, simplemente invoca "log_message_receiver" en la revisión 0, pasando "undef" a $changed_paths y cadenas vacías para el autor y la fecha. Esto se debe a que esa combinación particular de $start y $end suele indicar el caso común de invocación de log; el usuario quiere ver todos los mensajes de log desde el más reciente al más antiguo, donde el commit más antiguo es la revisión 1. Eso funciona bien, excepto que no hay commits en el repositorio, de ahí este caso especial.

Obsoleto.

$client->ls($target, $revision, $recursive, $pool);
Devuelve un hash de objetos svn_dirent_t para $target en $revision.

Si $target es un directorio, devuelve las entradas de todo el contenido del directorio. Si $recursive es verdadero, recorrerá recursivamente los subdirectorios en $target.

Si $target es un archivo, solo devuelve una entrada para el archivo.

Si $target no existe, genera el error $SVN::Error::FS_NOT_FOUND.

$client->merge($src1, $rev1, $src2, $rev2, $target_wcpath, $recursive, $ignore_ancestry, $force, $dry_run, $pool);
Fusiona cambios de $src1/$rev1 a $src2/$rev2 en la ruta de la copia de trabajo $target_wcpath.

$src1 y $src2 son URLs que se refieren a entradas en el repositorio, o rutas a entradas en la copia de trabajo.

Por 'fusionar', entendemos: aplicar diferencias de archivos y programar adiciones y eliminaciones cuando sea apropiado.

$src1 y $src2 deben representar el mismo tipo de nodo; es decir, si $src1 es un directorio, $src2 también debe serlo, y si $src1 es un archivo, $src2 también debe serlo.

Si $rev1 o $rev2 es undef, genera el error $SVN::Error::CLIENT_BAD_REVISION.

Si $recursive es verdadero (y las URLs son directorios), aplica los cambios recursivamente; de lo contrario, solo aplica los cambios en el directorio actual.

Usa $ignore_ancestry para controlar si los elementos que se comparan se verificarán primero en busca de relaciones. Los elementos no relacionados suelen transmitirse al editor como una eliminación de una cosa y la adición de otra, pero si esta bandera es verdadera, los elementos no relacionados se compararán como si estuvieran relacionados.

Si $force no está establecido y la fusión implica eliminar elementos modificados localmente o no versionados, la operación generará un error. Si $force está establecido, dichos elementos se eliminarán.

Llama a la función de notificación una vez por cada destino fusionado, pasando la ruta local del destino.

Si $dry_run es verdadero, la fusión se lleva a cabo y se proporciona la retroalimentación completa de notificación, pero la copia de trabajo no se modifica.

No tiene retorno.

$client->mkdir($targets, $pool);
Similar a $client->mkdir2() excepto que devuelve un objeto svn_client_commit_info_t en lugar de un objeto svn_commit_info_t.
$client->mkdir2($targets, $pool);
Similar a $client->mkdir3(), pero con $make_parents siempre FALSE, y $revprop_hash siempre undef.
$client->mkdir3($targets, $make_parents, $revprop_hash, $pool);
Similar a $client->mkdir4(), pero devuelve un objeto svn_commit_info_t en lugar de hacerlo a través de una función de callback.
$client->mkdir4($targets, $make_parents, $revprop_hash, \&commit_callback, $pool);
Crea un directorio, ya sea en un repositorio o en una copia de trabajo.

Si $targets contiene URLs, intenta inmediatamente confirmar la creación de los directorios en $targets en el repositorio. Devuelve un objeto svn_client_commit_info_t.

De lo contrario, crea los directorios en disco e intenta programarlos para su adición. En este caso, devuelve undef.

Si $make_parents es TRUE, crea también cualquier directorio padre inexistente.

Si no es undef, $revprop_hash es una referencia a una tabla hash que contiene propiedades de revisión personalizadas adicionales (nombres de propiedad mapeados a cadenas) que se establecerán en la nueva revisión en caso de que sea una operación de commit. Este hash no puede contener propiedades estándar de Subversion.

Llama a la función de callback de mensaje de log para consultar un mensaje de log de commit cuando se necesite.

Llama a la función de callback de notificación cuando el directorio ha sido creado (exitosamente) en la copia de trabajo, con la ruta del nuevo directorio. Tenga en cuenta que esto solo se llama para elementos añadidos a la copia de trabajo.

Si \&commit_callback no es undef, entonces por cada commit exitoso, llama a \&commit_callback con el objeto svn_commit_info_t para el commit.

$client->move($src_path, $src_revision, $dst_path, $force, $pool);
Mueve $src_path a $dst_path.

$src_path debe ser un archivo o directorio bajo control de versiones, o la URL de un elemento versionado en el repositorio.

Si $src_path es una URL de repositorio:

* $dst_path también debe ser una URL de repositorio (existente o no).

* $src_revision se utiliza para elegir la revisión de la que copiar $src_path.

* Se llamará a la función de callback log_msg para el mensaje de log del commit.

* La operación de mover se confirmará inmediatamente. Si el commit tiene éxito, devuelve un objeto svn_client_commit_info_t.

Si $src_path es una ruta de copia de trabajo

* $dst_path también debe ser una ruta de copia de trabajo (existente o no).

* $src_revision se ignora y puede ser undef. No se llamará a la función de callback log_msg.

* Esta es una operación de programación. No se realizarán cambios en el repositorio hasta que ocurra un commit. Esta programación se puede eliminar con $client->revert(). Si $src_path es un archivo, se elimina inmediatamente de la copia de trabajo. Si $src_path es un directorio, permanecerá en la copia de trabajo pero se eliminarán todos los archivos y elementos no versionados que contenga.

* Si $src_path contiene elementos modificados localmente y/o no versionados y $force no está establecido, la copia generará un error. Si $force está establecido, dichos elementos se eliminarán.

La función de callback de notificación se llamará dos veces por cada elemento movido, una para indicar la eliminación del nodo movido y otra para indicar la adición de la nueva ubicación del nodo.

$client->propget($propname, $target, $revision, $recursive, $pool);
Devuelve una referencia a un hash que contiene rutas o URLs, prefijadas por $target (una copia de trabajo o URL), de elementos para los cuales la propiedad $propname está establecida, y cuyos valores representan el valor de la propiedad $propname en esa ruta.
$client->proplist($target, $revision, $recursive, $pool);
Devuelve una referencia a un array de objetos svn_client_proplist_item_t.

Para cada elemento, el miembro node_name del objeto proplist_item contiene el nombre relativo a la misma base que $target.

Si $revision es undef, entonces se obtienen las propiedades de la copia de trabajo, si $target es una copia de trabajo, o de la cabeza del repositorio si $target es una URL. De lo contrario, se obtienen las propiedades como de $revision.

Si $recursive es falso, o $target es un archivo, el array devuelto solo contendrá un único elemento. De lo contrario, contendrá una entrada por cada entrada versionada debajo (e incluyendo) $target.

Si $target no se encuentra, genera el error $SVN::Error::ENTRY_NOT_FOUND.

$client->propset($propname, $propval, $target, $recursive, $pool);
Establece $propname a $propval en $target (una ruta de copia de trabajo o URL).

Si $recursive es verdadero, entonces $propname se establecerá recursivamente en $target y todos sus hijos. Si $recursive es falso, y $target es un directorio, $propname se establecerá **solo** en $target.

Un $propval de undef eliminará la propiedad.

Si $propname es una propiedad controlada por svn (es decir, con prefijo svn:), entonces el llamador es responsable de asegurar que $propval esté codificado en UTF8 y use saltos de línea LF.

$client->relocate($dir, $from, $to, $recursive, $pool);
Modifica un directorio de copia de trabajo $dir, cambiando cualquier URL de repositorio que comience con $from para que comience con $to en su lugar, recursivamente en los subdirectorios
Si $recursive es verdadero.

No tiene retorno.

$client->resolved($path, $recursive, $pool);
Elimina el estado "conflicto" en un camino de trabajo.

Esto no resuelve conflictos semánticamente; solo permite que $path se confirme en el futuro. Los detalles de implementación son opacos. Si $recursive está establecido, recurre debajo de $path, buscando conflictos para resolver.

Si $path no está en un estado de conflicto al principio, no hace nada.

Si el estado de conflicto de $path se elimina, llama al callback de notificación con $path.

$client->revert($paths, $recursive, $pool);
Restaura la versión original de un camino de trabajo $paths, es decir, deshace cualquier modificación local.

Para cada ruta en $paths, si es un directorio y $recursive es verdadero, esta será una operación recursiva.

$client->revprop_get($propname, $url, $revision, $pool);
Devuelve dos valores, el primero de los cuales es el valor de $propname en la rama $revision del repositorio representado por $url. El segundo valor es la revisión real consultada.

Nota: Aunque es diferente de su homólogo $client->propget(), esta rutina no afecta el camino de trabajo en absoluto; es una operación pura de red que consulta una propiedad **no versionada** asociada a una rama. Esto puede usarse para consultar mensajes de log, fechas, autores, etc.

$client->revprop_list($url, $revision, $pool);
Devuelve dos valores, el primero de los cuales es una referencia a un hash que contiene las propiedades asociadas a $revision en el repositorio representado por $url. El segundo valor es la revisión real consultada.

Nota: Aunque es diferente de su homólogo $client->proplist(), esta rutina no lee un camino de trabajo en absoluto; es una operación pura de red que lee propiedades **no versionadas** asociadas a una rama.

$client->revprop_set($propname, $propval, $url, $revision, $force, $pool);
Establece $propname en $propval en la rama $revision del repositorio representado por $url.

Devuelve la revisión afectada. Un $propval de undef eliminará la propiedad.

Si $force es verdadero, permite nuevas líneas en la propiedad del autor.

Si $propname es una propiedad controlada por SVN (es decir, precedida por svn:), el usuario debe asegurarse de que el valor esté codificado en UTF8 y use LF.

Nota: Aunque es diferente de su homólogo $client->propset(), esta rutina no afecta el camino de trabajo en absoluto; es una operación pura de red que cambia una propiedad **no versionada** asociada a una rama. Esto puede usarse para ajustar mensajes de log, fechas, autores, etc. Debe tener cuidado: es una operación destructiva, con el efecto de reemplazar cualquier valor existente con el nuevo, sin forma de recuperar el valor anterior.

También nota que, a menos que el administrador cree un hook pre-revprop-change en el repositorio, esta función fallará.

$client->status($path, $revision, \&status_func, $recursive, $get_all, $update, $no_ignore, $pool);
Similar a $client->status2(), pero con ignore_externals siempre establecido en FALSE, y con status_func recibiendo un objeto svn_wc_status2_t en lugar de un svn_wc_status_t.
$client->status2($path, $revision, \&status_func, $recursive, $get_all, $update, $no_ignore, $ignore_externals, $pool);
Similar a $client->status3(), pero con los cambios de lista pasados como undef, y con recursivo en lugar de profundidad.
$client->status3($path, $revision, \&status_func, $depth, $get_all, $update, $no_ignore, $ignore_externals, $changelists, $pool);
Similar a $client->status4(), sin el parámetro pool en la función de callback y el retorno de la función es ignorado.
$client->status4($path, $revision, \&status_func, $depth, $get_all, $update, $no_ignore, $ignore_externals, $changelists, $pool);
Da como entrada $path a un directorio de trabajo (o un único archivo), llama a status_func() con un conjunto de objetos svn_wc_status2_t que describen el estado de $path y sus hijos.

Si $recursive es verdadero, recurre completamente, sino solo los hijos inmediatos.

Si $get_all está establecido, obtén todos los registros; de lo contrario, obtén solo los registros 'interesantes' (modificaciones locales y/o desactualizados).

Si $update está establecido, contacta con el repositorio y actualiza los objetos de estado con información sobre la desactualización (respecto a $revision). También devuelve el valor de la revisión real con la que se comparó el camino de trabajo. (El retorno será undef si $update no está establecido).

Salvo que ignore_externals esté establecido, la función recurre a las definiciones de externos después de manejar el objetivo principal, si existen. La función llama al callback de notificación con el acción $SVN::Wc::Notify::Action::status_external antes de procesar cada definición de externos, y con el acción $SVN::Wc::Notify::Action::status_completed después de cada uno.

$changelists es una referencia a un array de nombres de cambios de lista, utilizado como un filtro restrictivo en los items cuyos estados se reportan; es decir, no reporta estado sobre ningún item hasta que sea miembro de esos cambios de lista. Si changelists es vacío (o totalmente indefinido), no hay filtrado por cambios de lista.

La función status_func toma los siguientes parámetros: $path, $status, $pool

$path es el camino de archivo o directorio cuyo estado se reporta. $status es un objeto svn_wc_status2_t. $pool es un objeto apr_pool_t que se limpia entre invocaciones a la callback.

El retorno de la función status_func puede ser un objeto svn_error_t creado por SVN::Error::create para propagar un error hacia arriba.

$client->switch($path, $url, $revision, $recursive, $pool);
Cambia el camino de trabajo $path a $url en la rama $revision.

$revision debe ser un número, 'HEAD' o una fecha, de lo contrario lanza el error $SVN::Error::CLIENT_BAD_REVISION.

Llama al callback de notificación en los caminos afectados por el cambio. También invoca el callback para archivos que podrían ser restaurados desde la base textual porque fueron removidos del camino de trabajo.

Resumen del propósito: Esto se usa normalmente para cambiar un directorio de trabajo a otra línea de desarrollo, como una rama o una etiqueta. Cambiar un directorio existente es más eficiente que verificar la descarga de $url desde cero.

Devuelve el valor de la revisión a la que se cambió el camino de trabajo.

$client->update($path, $revision, $recursive, $pool)
Similar a $client->update2(), excepto que acepta solo un objetivo en $path, devuelve una sola revisión y $ignore_externals siempre está establecido en FALSE.
$client->update2($paths, $revision, $recursive, $ignore_externals, $pool)
Similar a $client->update3(), pero con $allow_unver_obstructions siempre establecido en FALSE, $depth_is_sticky a FALSE, y $depth establecido según $recursive: si $recursive es TRUE, establece $depth a $SVN::Depth::infinity, si $recursive es FALSE, establece $depth a $SVN::Depth::files.
$client->update3($paths, $revision, $depth, $depth_is_sticky, $ignore_externals, $allow_unver_obstructions, $pool)
Similar a $client->update4(), pero con $make_parents siempre establecido en FALSE y $adds_as_modification establecido a TRUE.
$client->update4($paths, $revision, $depth, $depth_is_sticky, $ignore_externals, $allow_unver_obstructions, $adds_as_modification, $make_parents)
Actualiza los caminos de trabajo $paths a $revision.

$paths es una referencia a un array de caminos a actualizar. Los caminos no versionados que son hijos directos de un camino versionado causan una actualización que intenta añadir ese camino; otros caminos no versionados son ignorados.

$revision debe ser un número, 'HEAD' o una fecha, de lo contrario lanza el error $SVN::Error::CLIENT_BAD_REVISION.

Los caminos en $paths pueden ser de múltiples caminos de trabajo de múltiples repositorios, pero incluso si todos provienen del mismo repositorio, no hay garantía de que la revisión representada por 'HEAD' permanezca la misma que cada camino sea actualizado.

Si $ignore_externals está establecido, no se procesarán las definiciones de externos como parte de esta operación.

Si $depth es $SVN::Depth::infinity, actualiza recursivamente todo. Si es $SVN::Depth::immediates o $SVN::Depth::files, actualiza cada objetivo y sus entradas de archivos, pero no sus subdirectorios. Si es $SVN::Depth::empty, actualiza exactamente cada objetivo, de forma no recursiva (es decir, actualiza las propiedades del objetivo).

Si $depth es $SVN::Depth::unknown, toma la profundidad del camino de trabajo de $paths y se comporta como se describe en el resto.

Si $depth_is_sticky está establecido y $depth es verdadero, establece $depth según el valor de $paths y se comporta como se describe en el resto.

$profundidad no es $SVN::Depth::unknown, entonces además de actualizar las rutas, también establece su valor de profundidad ambiental pegajoso a $profundidad.

Si $allow_unver_obstructions es TRUE entonces la actualización tolera elementos no versionados existentes que obstruyen rutas añadidas. Solo se toleran obstrucciones del mismo tipo (archivo o directorio) que el elemento añadido. El texto de los archivos obstructores se deja tal cual, tratándolo efectivamente como una modificación del usuario después de la actualización. Las propiedades de trabajo de los elementos obstructores se establecen igual que las propiedades base. Si $allow_unver_obstructions es FALSE entonces la actualización abortará si hay algún elemento no versionado que obstruya.

Si $adds_as_modification es TRUE, una adición local en la misma ruta que una adición entrante del mismo tipo de nodo resulta en un nodo normal con una posible modificación local, en lugar de un conflicto de árbol.

Si $make_parents es TRUE, crea también los directorios padres inexistentes al checkout con profundidad=empty.

Llama al callback de notificación por cada elemento manejado por la actualización, y también por los archivos restaurados desde la base de texto.

Devuelve una referencia a un array de números de revisión, donde cada elemento se establece a la revisión a la que $revisión se resolvió para el elemento correspondiente de $rutas.

$client->url_from_path($target, $pool); o SVN::Client::url_from_path($target, $pool);
Devuelve la URL para $target.

Si $target ya es una URL, devuelve $target.

Si $target es un elemento versionado, devuelve la URL de entrada de $target.

Si $target no está versionado (no tiene entrada), devuelve undef.

$client->uuid_from_path($path, $adm_access, $pool);
Devuelve el uuid del repositorio para la copia de trabajo $path, asignado en $pool.

Usa $adm_access para recuperar el uuid del archivo de entrada de $path; si no está presente en la entrada, entonces llama a $client->uuid_from_url() para recuperarlo, usando la URL de la entrada.

Nota: La única razón por la que esta función recurre a $client->uuid_from_url es por compatibilidad. Las copias de trabajo antiguas pueden no tener uuids en los archivos de entrada.

Nota: Este método probablemente no funcione bien en este momento sin mucho esfuerzo, porque SVN::Wc está incompleto y requiere un objeto adm_access de él.

$client->uuid_from_url($url, $pool);
Devuelve el uuid del repositorio para la url.

MÉTODOS DE ATRIBUTO

Los siguientes métodos de atributo te permiten establecer o recuperar varias configuraciones. Todos ellos toman valor(es) para establecer el atributo y devuelven el nuevo valor del atributo, o ningún parámetro que devuelve el valor actual.

$client->auth(SVN::Client::get_username_provider());
Proporciona acceso al auth_baton en el svn_client_ctx_t adjunto al objeto SVN::Client.

Este método aceptará un array o una referencia a un array de valores devueltos por las funciones del proveedor de autenticación, ver "PROVEEDORES DE AUTENTICACIÓN", que convertirá en un auth_baton para ti. Este es el método preferido para establecer el auth_baton.

También aceptará un escalar que hace referencia a un _p_svn_auth_baton_t, como los devueltos por SVN::Core::auth_open y SVN::Core::auth_open_helper.

$client->notify(\&notify);
Establece el callback de notificación para el contexto del cliente a una referencia de código que proporcionas. Siempre devuelve la referencia de código actualmente establecida.

La subrutina apuntada por esta referencia será llamada cuando se realice un cambio en la copia de trabajo. El valor de retorno de esta función se ignora. Su único propósito es notificarte del cambio.

La subrutina recibirá 6 parámetros. El primer parámetro será la ruta del archivo cambiado (absoluta o relativa al cwd). El segundo es un entero que especifica el tipo de acción realizada. Ver SVN::Wc para una lista de los posibles valores de acción y lo que significan. El tercero es un entero que especifica el tipo de nodo de la ruta, que puede ser: $SVN::Node::none, $SVN::Node::file, $SVN::Node::dir, $SVN::Node::unknown. El cuarto parámetro es el tipo mime del archivo o undef si el tipo mime es desconocido (siempre será undef para directorios). El quinto parámetro es el estado del archivo, nuevamente ver SVN::Wc para una lista de los posibles estados. El sexto y último parámetro es el número de revisión numérico del archivo cambiado. El número de revisión será -1 excepto cuando la acción es $SVN::Wc::Notify::Action::update_completed.

$client->log_msg(\&log_msg)
Establece el callback de log_msg para el contexto del cliente a una referencia de código que proporcionas. Siempre devuelve la referencia de código actualmente establecida.

La subrutina apuntada por esta referencia de código será llamada para obtener el mensaje de log para cualquier operación que confirme una revisión en el repositorio.

Recibe 4 parámetros. El primer parámetro es una referencia a un valor escalar en el cual el callback debe colocar el log_msg. Si deseas cancelar el commit, puedes establecer este escalar a undef. El 2do valor es una ruta a cualquier archivo temporal que pueda contener ese mensaje de log, o undef si no existe tal archivo (sin embargo, si log_msg es undef, este valor es indefinido). El mensaje de log **DEBE** ser una cadena UTF8 con separadores de línea LF. El 3er parámetro es una referencia a un array de objetos svn_client_commit_item3_t, que pueden estar completa o solo parcialmente rellenados, dependiendo del tipo de operación de commit. El 4to y último parámetro será un pool.

Si la función desea devolver un error, debe devolver un objeto svn_error_t creado con SVN::Error::create. Cualquier otro valor de retorno se interpretará como SVN_NO_ERROR.

$client->cancel(\&cancel)
Establece el callback de cancelación para el contexto del cliente a una referencia de código que proporcionas. Ver "CALLBACK DE CANCELACIÓN" a continuación para obtener detalles. Siempre devuelve la referencia de código actualmente establecida.
$client->pool(new SVN::Pool);
Método que establece u obtiene el pool por defecto que se pasa a las llamadas de método que requieren un pool, pero a las cuales no se les pasó explícitamente uno.

Ver SVN::Core para más información sobre cómo se gestionan los pools en esta interfaz.

$client->config(SVN::Core::config_get_config(undef));
Método que permite el acceso al miembro de configuración del svn_client_ctx_t. Acepta un hash de Perl para establecer, que es lo que devuelven funciones como SVN::Core:config_get_config().

Devolverá un escalar _p_arp_hash_t. Esta es una situación temporal. El valor de retorno no es particularmente útil. En el futuro, este valor estará ligado al hash real utilizado por la API C.
