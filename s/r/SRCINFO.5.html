NOMBRE

SRCINFO - Información sobre las fuentes de los paquetes basados en ALPM.

DESCRIPCIÓN

El formato SRCINFO es un formato textual que describe los metadatos de las fuentes de los paquetes. Dichos archivos se nombran .SRCINFO y se ubican en la raíz de los repositorios de fuentes desde los cuales se construyen los paquetes basados en ALPM. El formato SRCINFO es utilizado por aplicaciones como software de gestión de repositorios y front-ends web personalizados para evaluar y presentar la información de las fuentes de los paquetes.

Formato General

Un archivo SRCINFO consta de una serie de líneas, cada una proporcionando información sobre un aspecto de las fuentes de uno o varios paquetes (ver alpm-split-package para información sobre paquetes divididos). Las líneas que comienzan con un signo ‘#’ se tratan como comentarios y siempre se ignoran. Las líneas vacías siempre se ignoran. El espacio en blanco inicial siempre se ignora.

Salvo que se indique lo contrario, la información contenida en un archivo SRCINFO se considera cubierta por el conjunto de los 95 caracteres ASCII imprimibles[1].

El formato del archivo distingue entre cabeceras de sección que introducen secciones específicas y asignaciones de palabras clave que pueden utilizarse en esas secciones. Cada línea codifica información que representa una cabecera de sección o una asignación de palabra clave.

El formato SRCINFO requiere la definición de un único pkgbase y una o más secciones pkgname. Mientras que la sección pkgbase contiene metadatos compartidos por todos los paquetes construidos a partir de un PKGBUILD, las secciones pkgname se utilizan para declarar metadatos de paquetes y proporcionar reemplazos que son específicos para cada paquete respectivo.

Cabeceras de sección

Todas las cabeceras de sección consisten en una clave, seguida inmediatamente por un espacio en blanco, un signo ‘=’, otro espacio en blanco y un valor.

La cabecera de sección para una sección pkgbase debe usar la palabra ‘pkgbase’ como clave y una base de paquetes alpm como valor. Debe existir exactamente una cabecera de sección de este tipo al principio de un archivo SRCINFO.

La cabecera de sección para una sección pkgname debe usar la palabra ‘pkgname’ como clave y un nombre de paquete alpm como valor. Debe existir al menos una cabecera de sección de este tipo en un archivo SRCINFO (una por cada paquete construido a partir de un PKGBUILD), pero solo después de una cabecera de sección pkgbase.

Secciones

La sección pkgbase debe contener al menos las asignaciones para las palabras clave pkgver y pkgrel, y por lo demás puede contener todas las demás asignaciones de palabras clave conocidas. Las asignaciones de palabras clave presentes en esta sección también se aplican a todas las secciones pkgname.

Una sección pkgname puede tener cero o más asignaciones de palabras clave. No debe contener asignaciones para las palabras clave epoch, pkgver, pkgrel o validpgpkeys, ni ninguna asignación de palabra clave que represente declaraciones de dependencias de compilación o de prueba (ver alpm-package-relation para más detalles), declaraciones de origen (ver alpm-package-source para más detalles) o declaraciones de suma de verificación (ver alpm-package-source-checksum para más detalles). Las asignaciones de palabras clave en una sección pkgname solo se aplican al paquete específico que describe la sección. Más específicamente, todas las asignaciones de palabras clave en una sección pkgname se utilizan para desestablecer, extender o reemplazar las asignaciones de palabras clave encontradas en la sección pkgbase. Se aplican las siguientes reglas:

•
Una palabra clave que ha sido previamente definida en la sección pkgbase y puede usarse en una sección pkgname puede ser
  • desestablecida asignándole un valor vacío (por ejemplo, la sección pkgbase define depends = bash y la sección pkgname define depends =), o
  • reemplazada definiéndola de nuevo (por ejemplo, la sección pkgbase define depends = bash y la sección pkgname define depends = zsh).
•
Todas las palabras clave que permiten múltiples asignaciones y que pueden usarse en una sección pkgname pueden extenderse agregando primero todas las asignaciones de palabras clave encontradas en la sección pkgbase y luego agregando asignaciones de palabras clave adicionales en una sección pkgname (por ejemplo, la sección pkgbase define depends = bash y la sección pkgname define depends = bash y depends = bash-completion).

Pueden aplicarse reglas adicionales dependiendo de la palabra clave.

Palabras clave

Todas las asignaciones de palabras clave se definen como una clave de la siguiente lista, seguida inmediatamente por un espacio en blanco, un signo ‘=’, otro espacio en blanco y un valor.

Por defecto, puede haber exactamente una asignación de palabra clave por palabra clave en un SRCINFO. Como excepción a esta regla, las palabras clave arch, backup, checkdepends, conflicts, depends, groups, license, makedepends, optdepends, options, provides, replaces, así como las palabras clave relacionadas con el origen noextract, source, validpgpkeys, b2sums, md5sums, sha1sums, sha224sums, sha256sums, sha384sums, sha512sums y cksums, pueden proporcionarse cero o más veces.

Por defecto, las asignaciones de palabras clave se aplican a todas las arquitecturas alpm objetivo. Algunas palabras clave también pueden proporcionarse de forma específica para la arquitectura agregando un signo ‘_’, seguido directamente de una arquitectura alpm (todas excepto any): ver cada sección de palabra clave para más detalles. Estas asignaciones de palabras clave específicas de la arquitectura solo se aplican a la arquitectura que se dirige.

pkgdesc

La descripción del paquete. Esta asignación de palabra clave puede proporcionarse cero o una vez en el pkgbase y/o en cada sección pkgname. El valor es una cadena UTF-8, de cero o más caracteres de longitud (por ejemplo, Un proyecto utilizado para algo). Las descripciones de paquetes no deben tener espacios en blanco al principio o al final, no deben contener caracteres de espacio en blanco excepto el espacio “ “ y no deben tener espacios sucesivos.

No existen reglas específicas sobre el valor, pero se sugiere que sea “corto” y que no contenga el nombre del paquete (ver alpm-package-name).

pkgver

El componente de versión del paquete pkgver para el(los) paquete(s) (ver alpm-pkgver para más información sobre el valor esperado). Esta asignación de palabra clave debe proporcionarse una vez, exclusivamente en la sección pkgbase.

El valor es un alpm-pkgver (por ejemplo, 1.0.0 o 1:1.0.0).

pkgrel

El componente de versión del paquete pkgrel para el(los) paquete(s) (ver alpm-pkgrel para más detalles sobre el valor esperado).

Esta asignación de palabra clave debe proporcionarse una vez, exclusivamente en la sección pkgbase.

epoch

El componente opcional de versión del paquete epoch para el(los) paquete(s) (ver alpm-epoch para más detalles sobre el valor esperado).

Esta asignación de palabra clave puede proporcionarse cero o una vez, exclusivamente en la sección pkgbase.

url

La URL del proyecto del paquete. Esta asignación de palabra clave puede proporcionarse cero o una vez en el pkgbase y/o en cada sección pkgname.

El valor es una URL válida o una cadena vacía (por ejemplo, https://example.org).

install

El nombre de un scriptlet de instalación alpm que se utiliza para acciones previas y posteriores al instalar, actualizar o desinstalar un paquete. Esta asignación de palabra clave puede proporcionarse cero o una vez en el pkgbase

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

y/o en cada sección de pkgname.

El valor debe ser una cadena UTF-8 que represente una ruta de archivo relativa (por ejemplo, scriptlet.install).

changelog

El nombre del archivo que contiene información del registro de cambios de un paquete. Esta asignación de palabra clave puede proporcionarse cero o una vez en la sección pkgbase y/o en cada sección pkgname.

El valor debe ser una cadena UTF-8 que represente una ruta de archivo relativa (por ejemplo, pkg.changelog).

arch

Una arquitectura que se aplica a una sección pkgname. Esta asignación de palabra clave puede proporcionarse una o más veces en la sección pkgbase y cero o más veces en cada sección pkgname.

El valor es una alpm-architecture (por ejemplo, x86_64 o any). Las siguientes reglas se aplican si esta palabra clave se usa varias veces:

  • cada valor debe ser único
  • si se usa el valor any, no se puede usar ningún otro valor junto con él, ya que implica que un pkgname puede usarse en cualquier arquitectura (lo que lógicamente excluye que solo se use en una arquitectura específica)

groups

Una cadena arbitraria que denota un grupo a nivel de distribución al que pertenece el paquete (ver alpm-package-group). Los grupos son utilizados, por ejemplo, por los administradores de paquetes para agrupar paquetes y permitir su instalación masiva, o por otro software para mostrar información sobre estos paquetes relacionados.

Esta asignación de palabra clave puede proporcionarse cero o más veces tanto en la sección pkgbase como en cada sección pkgname. El valor se representa mediante una cadena UTF-8. Aunque es posible usar una cadena UTF-8, se recomienda encarecidamente depender en su lugar del formato alpm-package-name para el valor, ya que los administradores de paquetes pueden usar groups para instalar un grupo completo de paquetes.

license

Una licencia que se aplica a los paquetes. Esta asignación de palabra clave puede proporcionarse cero o más veces tanto en la sección pkgbase como en cada sección pkgname. El valor representa un identificador de licencia, que es una cadena de longitud distinta de cero (por ejemplo, GPL). Aunque no se aplican restricciones específicas al valor aparte de su longitud, se recomienda encarecidamente depender de las expresiones de licencia SPDX (por ejemplo, GPL-3.0-or-later o Apache-2.0 OR MIT). Consulte la Lista de Licencias SPDX[5] para obtener más información.

checkdepends

Una dependencia para ejecutar pruebas del proyecto de origen del paquete. Se puede especificar un checkdepends específico de la arquitectura utilizando una palabra clave que consiste en 'checkdepends', seguida directamente por un signo de guion bajo y seguida directamente por una alpm-architecture (se pueden usar todas las alpm-architectures excepto any), por ejemplo, checkdepends_aarch64.

Esta asignación de palabra clave puede proporcionarse cero o más veces, exclusivamente en la sección pkgbase. El valor es una alpm-package-relation de tipo dependencia de prueba (por ejemplo, example o example=1.0.0).

makedepends

Una dependencia en tiempo de compilación del paquete (componente virtual o paquete). Se puede especificar un makedepends específico de la arquitectura utilizando una palabra clave que consiste en 'makedepends', seguida directamente por un signo de guion bajo y seguida directamente por una alpm-architecture (se pueden usar todas las alpm-architectures excepto any), por ejemplo, makedepends_aarch64.

Esta asignación de palabra clave puede proporcionarse cero o más veces, exclusivamente en la sección pkgbase. El valor es una alpm-package-relation de tipo dependencia de compilación (por ejemplo, example o example=1.0.0).

depends

Una dependencia en tiempo de ejecución del paquete (componente virtual o paquete). Se puede especificar un depends específico de la arquitectura utilizando una palabra clave que consiste en 'depends', seguida directamente por un signo de guion bajo y seguida directamente por una alpm-architecture (se pueden usar todas las alpm-architectures excepto any), por ejemplo, depends_aarch64.

Esta asignación de palabra clave puede proporcionarse cero o más veces tanto en la sección pkgbase como en cada sección pkgname. El valor es una alpm-package-relation de tipo dependencia en tiempo de ejecución (por ejemplo, example o example=1.0.0).

optdepends

Una dependencia opcional del paquete (componente virtual o paquete). Se puede especificar un optdepends específico de la arquitectura utilizando una palabra clave que consiste en 'optdepends', seguida directamente por un signo de guion bajo y seguida directamente por una alpm-architecture (se pueden usar todas las alpm-architectures excepto any), por ejemplo, optdepends_aarch64.

Esta asignación de palabra clave puede proporcionarse cero o más veces tanto en la sección pkgbase como en cada sección pkgname. El valor es una alpm-package-relation de tipo dependencia opcional (por ejemplo, example o example: esta es una descripción).

provides

Otro componente virtual o paquete que el paquete proporciona. Se puede especificar un provides específico de la arquitectura utilizando una palabra clave que consiste en 'provides', seguida directamente por un signo de guion bajo y seguida directamente por una alpm-architecture (se pueden usar todas las alpm-architectures excepto any), por ejemplo, provides_aarch64.

Esta asignación de palabra clave puede proporcionarse cero o más veces tanto en la sección pkgbase como en cada sección pkgname. El valor es una alpm-package-relation de tipo provisión (por ejemplo, example o example=1.0.0).

conflicts

Otro componente virtual o paquete con el que el paquete entra en conflicto. Se puede especificar un conflicts específico de la arquitectura utilizando una palabra clave que consiste en 'conflicts', seguida directamente por un signo de guion bajo y seguida directamente por una alpm-architecture (se pueden usar todas las alpm-architectures excepto any), por ejemplo, conflicts_aarch64.

Esta asignación de palabra clave puede proporcionarse cero o más veces tanto en la sección pkgbase como en cada sección pkgname. El valor es una alpm-package-relation de tipo conflicto (por ejemplo, example o example=1.0.0).

replaces

Otro componente virtual o paquete que el paquete reemplaza durante la instalación. Se puede especificar un replaces específico de la arquitectura utilizando una palabra clave que consiste en 'replaces', seguida directamente por un signo de guion bajo y seguida directamente por una alpm-architecture (se pueden usar todas las alpm-architectures excepto any), por ejemplo, replaces_aarch64.

Esta asignación de palabra clave puede proporcionarse cero o más veces tanto en la sección pkgbase como en cada sección pkgname. El valor es una alpm-package-relation de tipo reemplazo (por ejemplo, example o example=1.0.0).

noextract

Un nombre de archivo fuente local (ver alpm-package-source) de un archivo que no debe extraerse durante la compilación del paquete. Cada valor debe representar el nombre de archivo local válido de una asignación de palabra clave source existente (por ejemplo, source = https://example.org/project-1.0.0.tar.gz y noextract = project-1.0.0.tar.gz). Un archivo que coincida con el nombre de archivo proporcionado no se extraerá automáticamente durante la compilación del paquete, incluso si es un archivo comprimido (por ejemplo, example.tar.gz o example.zip).

Esta asignación de palabra clave puede proporcionarse cero o más veces, exclusivamente en la sección pkgbase.

options

Una opción utilizada por la herramienta de compilación del paquete (es decir, makepkg, los valores predeterminados se definen en OPTIONS de makepkg.conf) al compilar el paquete. Esta asignación de palabra clave puede proporcionarse cero o más veces, ya sea en la sección pkgbase o en una sección pkgname.

El valor debe ser una palabra única, opcionalmente prefijada por un solo '!', que indica la negación de la opción (por ejemplo, debug o !debug). Si la asignación de palabra clave se utiliza en una sección pkgname, el valor de la primera aparición puede estar vacío, lo que indica que para el paquete respectivo, ninguna de las options definidas en la sección pkgbase se aplica.

backup

Una ruta de archivo relativa de un archivo en un paquete determinado, que denota un archivo para que el administrador de paquetes mantenga copias de seguridad en caso de que cambie o se elimine durante una acción de actualización del paquete (consulte los archivos '.pacnew' y '.pacsave' de pacman). Esta asignación de palabra clave puede proporcionarse cero o más veces tanto en la sección pkgbase como en cada sección pkgname. El valor debe ser una ruta de archivo Unix relativa válida (por ejemplo, etc/package.conf).

source

Una fuente (remota o local) utilizada en el proceso de empaquetado del paquete(s) (ver alpm-package-source para más detalles sobre las permitidas.

value), que se extraen automáticamente si representan archivos comprimidos (a menos que exista un valor noextract que coincida con el nombre del archivo). Una fuente específica de arquitectura se puede especificar usando una palabra clave que consista en "source", seguida directamente por un signo "_", seguido directamente por una alpm-architecture (se pueden usar todas las alpm-architectures excepto any), por ejemplo source_aarch64.

Esta asignación de palabra clave puede proporcionarse cero o más veces, exclusivamente en la sección pkgbase.

validpgpkeys

Una huella digital de OpenPGP[2] que puede usarse para la validación de firmas de OpenPGP[3] creadas para una o más fuentes de paquetes alpm (es decir, una asignación de palabra clave source).

Esta asignación de palabra clave puede proporcionarse cero o más veces, exclusivamente en la sección pkgbase. Debe usarse al menos una vez si

  • un valor de fuente de paquete alpm utiliza el fragmento de URL signed
  • o si hay una fuente de paquete alpm que termina en .sig, que es igual a otra sin esa extensión de archivo
  • o si hay una fuente de paquete alpm que termina en .sign, que coincide con otra sin esa extensión de archivo y se eliminan todas las extensiones de archivo específicas del algoritmo de compresión (por ejemplo, .xz o .zst)

El valor es una cadena hexadecimal de 40 caracteres (por ejemplo, 0123456789abcdef0123456789abcdef01234567) opcionalmente separada por espacios en blanco (por ejemplo, 0123 4567 89ab cdef 0123 4567 89ab cdef 0123 4567). Aunque es posible, se desaconseja firmemente utilizar la representación de ID de clave OpenPGP[4] obsoleta y no única, una cadena hexadecimal de 16 caracteres (por ejemplo, 89abcdef01234567)

md5sums

Un resumen de hash MD5[6] de un archivo proporcionado por nombre en un valor source, o la cadena especial ‘SKIP’ (ver alpm-package-source-checksum para más detalles sobre el valor permitido). Se puede especificar un md5sums específico de la arquitectura utilizando una palabra clave que consista en ‘md5sums’, seguida directamente por un signo ‘_’, seguido directamente por una alpm-architecture (se pueden usar todas las alpm-architectures excepto any), por ejemplo, md5sums_aarch64.

Esta asignación de palabra clave puede proporcionarse cero o más veces, exclusivamente en la sección pkgbase. Si se utiliza, SRCINFO debe contener tantas asignaciones de palabra clave md5sums como asignaciones de palabra clave source (lo mismo se aplica a la variante específica de arquitectura de esta palabra clave). El orden de las asignaciones de palabra clave source asociadas dicta el orden de las asignaciones de palabra clave md5sums (es decir, la primera asignación de palabra clave md5sums proporciona datos para la primera asignación de palabra clave source, etc.).

sha1sums

Un resumen de hash SHA-1[7] de un archivo proporcionado por nombre en un valor source, o la cadena especial ‘SKIP’ (ver alpm-package-source-checksum para más detalles sobre el valor permitido). Se puede especificar un sha1sums específico de la arquitectura utilizando una palabra clave que consista en ‘sha1sums’, seguida directamente por un signo ‘_’, seguido directamente por una alpm-architecture (se pueden usar todas las alpm-architectures excepto any), por ejemplo, sha1sums_aarch64.

Esta asignación de palabra clave puede proporcionarse cero o más veces, exclusivamente en la sección pkgbase. Si se utiliza, SRCINFO debe contener tantas asignaciones de palabra clave sha1sums como asignaciones de palabra clave source (lo mismo se aplica a la variante específica de arquitectura de esta palabra clave). El orden de las asignaciones de palabra clave source asociadas dicta el orden de las asignaciones de palabra clave sha1sums (es decir, la primera asignación de palabra clave sha1sums proporciona datos para la primera asignación de palabra clave source, etc.).

NAME

SRCINFO - Arch Linux Package build information file

DESCRIPTION

The SRCINFO file is a key-value configuration file generated by makepkg(8) that contains metadata about a package build. It is used by tools such as pacman(8) and AUR helpers to process and interact with packages. The file can describe a single package or multiple split packages within a single package base.

Keywords are case-sensitive and may be specified multiple times. Values can be strings, lists of strings, or lists of architecture-specific strings. Comments start with a # and extend to the end of the line. Blank lines are ignored. Whitespace is significant.

Keywords

backup
Files or directories to be backed up by pacman(8) when upgrading a package. Can be specified multiple times. Supports wildcards. See pacman.conf(5) for syntax.
b2sums
BLAKE2 checksums of source files. See NOTES 9. Can be specified multiple times, each corresponding to a source file in order. Can also include the checksum of patches.
checkdepends
Packages that must be installed for the package to be built and checked. Can be specified multiple times.
conflicts
Packages that conflict with this package. Can be specified multiple times. See alpm-package-relation(7) for syntax.
depends
Packages that must be installed for this package to be run. Can be specified multiple times. See alpm-package-relation(7) for syntax.
depends_arch
Architecture-specific dependencies. For example, depends_x86_64. Can be specified multiple times.
groups
Package groups that this package belongs to. Can be specified multiple times.
license
Software licenses of the package. Can be specified multiple times. See NOTES 5 for a list of identifiers.
makedepends
Packages that must be installed for the package to be built. Can be specified multiple times.
md5sums
MD5 checksums of source files. See NOTES 6. Can be specified multiple times, each corresponding to a source file in order. Can also include the checksum of patches.
optdepends
Optional dependencies. The format is "pkgname [dependency description]". The dependency description is optional. Can be specified multiple times.
package
The name of the split package. If not specified, it defaults to the pkgbase name.
pkgbase
The base name of the package. Used to group split packages.
pkgdesc
A short description of the package.
pkgname
The name of the package. This keyword is used to define the start of a split package definition. It overrides the pkgbase for the current split package.
pkgrel
The package release number. Incremented for package updates that do not change the upstream version.
pkgver
The upstream package version.
provides
Virtual packages or capabilities provided by this package. Can be specified multiple times. See alpm-package-relation(7) for syntax.
replaces
Packages that this package replaces. Can be specified multiple times. See alpm-package-relation(7) for syntax.
sha1sums
SHA-1 checksums of source files. See NOTES 7. Can be specified multiple times, each corresponding to a source file in order. Can also include the checksum of patches.
sha256sums
SHA-256 checksums of source files. See NOTES 8. Can be specified multiple times, each corresponding to a source file in order. Can also include the checksum of patches.
sha384sums
SHA-384 checksums of source files. See NOTES 8. Can be specified multiple times, each corresponding to a source file in order. Can also include the checksum of patches.
sha512sums
SHA-512 checksums of source files. See NOTES 8. Can be specified multiple times, each corresponding to a source file in order. Can also include the checksum of patches.
source
URLs or local paths to the source files. Can be specified multiple times, each corresponding to a checksum in the checksum arrays.
url
The URL of the upstream project homepage.

Package base and split packages

A package base defines a set of metadata that is common to all split packages derived from it. Split packages are defined within the same SRCINFO file by subsequent pkgname definitions. Each pkgname section can override or extend keywords defined in the pkgbase section.

pkgbase = example
  pkgdesc = A project that does something
  pkgver = 1.0.0
  pkgrel = 1
  license = GPL-3.0-or-later
  depends = glibc
  depends = gcc-libs
  source = https://example.org/example-1.0.0.tar.gz
  sha512sums = 8b41e1b78ad11521113c52ff182a1b8e0a195754aa527fcd00a411620b46f20ffffb8088ccf85497121ad4499e0845b876f6dd6640088a2f0b2d8a600bdf4c0c
  b2sums = cb79bf658b69dff0acf721232455a461598dd26ed42047bd0362e7fbd796093145a694c1a6bcdcf5bf7f866d78f009c14bf456be0f944283829a6e33cedf2aef
  checkdepends = other-extra-test-tool
  makedepends = cmake
  makedepends = python-sphinx
  optdepends = python: for special-python-script.py
  optdepends = example-docs: for documentation
  provides = some-component
  conflicts = conflicting-package<1.0.0
  replaces = other-package>0.9.0-3
  backup = etc/example/config.toml
pkgname = extra-test-tool
  # overrides the pkgdesc for the extra-test-tool package
  pkgdesc = A project that does something - testing utilities
  groups = package-group
  # extends the license for the extra-test-tool package
  license = LGPL-3.0-or-later

The above example represents a SRCINFO file that describes two split packages (see alpm-split-package(7) for more details). Both pkgname sections override the pkgdesc keyword assignment. The first pkgname section additionally extends the license keyword specification from the pkgbase section and adds further package-specific keyword assignments (e.g. replaces, groups, conflicts, provides, backup, optdepends). The second pkgname section overrides the license keyword assignment and unsets the depends keyword assignment.

Package data, per architecture

The following minimal PKGBUILD defines a package for two alpm-architectures.

pkgname=example
pkgver=0.1.0
pkgrel=1
pkgdesc="An example package"
arch=(x86_64 aarch64)
url="https://example.org"
license=(GPL-3.0-or-later)
depends=(bash)
depends_x86_64=(zsh)
package() {
  pkgdesc+=" - extra info"
  depends_x86_64+=(nushell)
  depends_aarch64=(sh)
}

This PKGBUILD is represented by the following SRCINFO:

pkgbase = example
  pkgdesc = An example package
  pkgver = 0.1.0
  pkgrel = 1
  url = https://example.org
  arch = x86_64
  arch = aarch64
  license = GPL-3.0-or-later
  depends = bash
  depends_x86_64 = zsh
pkgname = example
  pkgdesc = An example package - extra info
  depends_x86_64 = zsh
  depends_x86_64 = nushell
  depends_aarch64 = sh

Depending on targeted alpm-architecture, the package data will differ when fully resolving all keywords.

For aarch64:

  • pkgdesc = An example package - extra info
  • pkgver = 0.1.0
  • pkgrel = 1
  • url = https://example.org
  • arch = aarch64
  • license = GPL-3.0-or-later
  • depends = bash
  • depends = sh

For x86_64:

  • pkgdesc = An example package - extra info
  • pkgver = 0.1.0
  • pkgrel = 1
  • url = https://example.org
  • arch = x86_64
  • license = GPL-3.0-or-later
  • depends = bash
  • depends = zsh
  • depends = nushell
