SRP_VBASE_new(3ssl)

Paquete: openssl

Licencias: Apache-2.0

SRP_VBASE_NEW(3ssl) OpenSSL SRP_VBASE_NEW(3ssl)

NOMBRE

SRP_VBASE_new, SRP_VBASE_free, SRP_VBASE_init, SRP_VBASE_add0_user, SRP_VBASE_get1_by_user, SRP_VBASE_get_by_user - Funciones para crear y gestionar una pila de información de verificador de usuario SRP

SINOPSIS

#include <openssl/srp.h>

Las siguientes funciones han sido obsoletas desde OpenSSL 3.0 y pueden ocultarse por completo definiendo OPENSSL_API_COMPAT con un valor de versión adecuado, ver openssl_user_macros(7):

SRP_VBASE *SRP_VBASE_new(char *seed_key);
void SRP_VBASE_free(SRP_VBASE *vb);
int SRP_VBASE_init(SRP_VBASE *vb, char *verifier_file);
int SRP_VBASE_add0_user(SRP_VBASE *vb, SRP_user_pwd *user_pwd);
SRP_user_pwd *SRP_VBASE_get1_by_user(SRP_VBASE *vb, char *username);
SRP_user_pwd *SRP_VBASE_get_by_user(SRP_VBASE *vb, char *username);

DESCRIPCIÓN

Todas las funciones descritas en esta página están obsoletas. No hay funciones de reemplazo disponibles en este momento.

La función SRP_VBASE_new() asigna una estructura para almacenar información del verificador SRP del lado del servidor. Si seed_key no es NULL, se almacena una copia y se utiliza para generar parámetros ficticios para usuarios que no se encuentran mediante SRP_VBASE_get1_by_user(). Esto permite al servidor ocultar el hecho de que no tiene un verificador para un nombre de usuario particular, como se describe en la sección 2.5.1.3 'Unknown SRP' de RFC 5054. La cadena 'seed_key' debe contener datos binarios aleatorios terminados en NUL (¡por lo tanto, los datos aleatorios no deben contener bytes NUL!).

La función SRP_VBASE_free() libera la estructura vb. Si vb es NULL, no se hace nada.

La función SRP_VBASE_init() analiza la información de un archivo de verificador y rellena la estructura vb. El archivo de verificador es un archivo de texto que contiene múltiples entradas, cuyo formato es: flag base64(verifier) base64(salt) username gNid userinfo(opcional) donde el flag puede ser 'V' (válido) o 'R' (revocado). Tenga en cuenta que la codificación base64 utilizada aquí no es estándar, por lo que se recomienda utilizar openssl-srp(1) para generar este archivo.

La función SRP_VBASE_add0_user() agrega la información del verificador user_pwd a la estructura vb. Consulte SRP_user_pwd_new(3) para crear y rellenar este registro. La biblioteca toma posesión de user_pwd, el llamador no debe liberarlo.

La función SRP_VBASE_get1_by_user() devuelve la información de la contraseña para el usuario cuyo nombre de usuario coincide con username. Reemplaza a la obsoleta SRP_VBASE_get_by_user(). Si no se encuentra ningún usuario coincidente, pero se han establecido una 'seed_key' y parámetros gN predeterminados, se genera información de autenticación ficticia a partir de la 'seed_key', lo que permite al servidor ocultar el hecho de que no tiene un verificador para un nombre de usuario en particular. Al usar SRP como mecanismo de autenticación TLS, esto hará que el handshake proceda normalmente, pero el primer cliente será rechazado con una alerta de "bad_record_mac", como si la contraseña fuera incorrecta. Si no se encuentra ningún usuario coincidente y la 'seed_key' no está establecida, se devuelve NULL. La propiedad del puntero devuelto se libera al llamador, debe ser liberado con SRP_user_pwd_free().

VALORES DE RETORNO

SRP_VBASE_init() devuelve SRP_NO_ERROR (0) en caso de éxito y un valor positivo en caso de error. Los códigos de error son SRP_ERR_OPEN_FILE si el archivo no se pudo abrir, SRP_ERR_VBASE_INCOMPLETE_FILE si el archivo no se pudo analizar, SRP_ERR_MEMORY en caso de error de asignación de memoria y SRP_ERR_VBASE_BN_LIB para valores de parámetros decodificados inválidos.

SRP_VBASE_add0_user() devuelve 1 en caso de éxito y 0 en caso de error.

VER TAMBIÉN

openssl-srp(1), SRP_create_verifier(3), SRP_user_pwd_new(3), SSL_CTX_set_srp_password(3)

HISTORIA

La función SRP_VBASE_add0_user() se agregó en OpenSSL 3.0.

Todas las demás funciones se agregaron en OpenSSL 1.0.1.

Todas estas funciones quedaron obsoletas en OpenSSL 3.0.
