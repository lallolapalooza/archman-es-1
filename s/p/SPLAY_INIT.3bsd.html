DESCRIPCIÓN

Estas macros definen estructuras de datos para diferentes tipos de árboles: árboles splay y árboles rojo-negros.

En las definiciones de macros, TYPE es la etiqueta de nombre de una estructura definida por el usuario que debe contener un campo llamado FIELD, de tipo SPLAY_ENTRY o RB_ENTRY. El argumento HEADNAME es la etiqueta de nombre de una estructura definida por el usuario que debe declararse utilizando las macros SPLAY_HEAD() o RB_HEAD(). El argumento NAME tiene que ser un prefijo de nombre único para cada árbol que se defina.

Los prototipos de las funciones se declaran con SPLAY_PROTOTYPE, RB_PROTOTYPE, o RB_PROTOTYPE_STATIC. Los cuerpos de las funciones se generan con SPLAY_GENERATE, RB_GENERATE, o RB_GENERATE_STATIC. Véanse los ejemplos a continuación para una mayor explicación de cómo se utilizan estas macros.

ÁRBOLES SPLAY

Un árbol splay es una estructura de datos autoorganizada. Cada operación sobre el árbol provoca un splay. El splay mueve el nodo solicitado a la raíz del árbol y lo reequilibra parcialmente.

Esto tiene el beneficio de que la localidad de las solicitudes produce búsquedas más rápidas, ya que los nodos solicitados se mueven a la parte superior del árbol. Por otro lado, cada búsqueda provoca escrituras en memoria.

El Teorema de Balance limita el tiempo total de acceso para m operaciones e n inserciones en un árbol inicialmente vacío como O((m + n)lg n). El costo amortizado para una secuencia de m accesos a un árbol splay es O(lg n).

Un árbol splay está encabezado por una estructura definida por la macro SPLAY_HEAD(). Una estructura SPLAY_HEAD se declara de la siguiente manera:

SPLAY_HEAD(NOMBRE_ENCABEZADO, TIPO) encabezado;

donde NOMBRE_ENCABEZADO es el nombre de la estructura que se va a definir, y struct TIPO es el tipo de los elementos que se insertarán en el árbol.

La macro SPLAY_ENTRY() declara una estructura que permite conectar elementos en el árbol.

Para utilizar las funciones que manipulan la estructura del árbol, sus prototipos deben declararse con la macro SPLAY_PROTOTYPE(), donde NOMBRE es un identificador único para este árbol en particular. El argumento TIPO es el tipo de la estructura que está siendo administrada por el árbol. El argumento CAMPO es el nombre del elemento definido por SPLAY_ENTRY().

Los cuerpos de las funciones se generan con la macro SPLAY_GENERATE(). Toma los mismos argumentos que la macro SPLAY_PROTOTYPE(), pero debe usarse solo una vez.

Finalmente, el argumento CMP es el nombre de una función utilizada para comparar los nodos del árbol entre sí. La función toma dos argumentos de tipo struct TYPE *. Si el primer argumento es menor que el segundo, la función devuelve un valor menor que cero. Si son iguales, la función devuelve cero. De lo contrario, debería devolver un valor mayor que cero. La función de comparación define el orden de los elementos del árbol.

La macro SPLAY_INIT() inicializa el árbol al que se hace referencia mediante encabezado.

El árbol splay también puede inicializarse estáticamente utilizando la macro SPLAY_INITIALIZER() de la siguiente manera:

SPLAY_HEAD(NOMBRE_ENCABEZADO, TIPO) encabezado = SPLAY_INITIALIZER(&encabezado);

La macro SPLAY_INSERT() inserta el nuevo elemento elm en el árbol. En caso de éxito, se devuelve NULL. Si ya existe un elemento coincidente en el árbol, la inserción se aborta y se devuelve un puntero al elemento existente.

La macro SPLAY_REMOVE() elimina el elemento elm del árbol al que apunta encabezado. En caso de éxito, se devuelve un puntero al elemento eliminado. Se devuelve NULL si elm no está presente en el árbol.

La macro SPLAY_FIND() se puede utilizar para encontrar un elemento particular en el árbol.

struct TIPO buscar, *res;
buscar.clave = 30;
res = SPLAY_FIND(NOMBRE, &encabezado, &buscar);

Las macros SPLAY_ROOT(), SPLAY_MIN(), SPLAY_MAX(), y SPLAY_NEXT() se pueden utilizar para recorrer el árbol:

para (np = SPLAY_MIN(NOMBRE, &encabezado); np != NULL; np = SPLAY_NEXT(NOMBRE, &encabezado, np))

O, para mayor simplicidad, se puede usar la macro SPLAY_FOREACH():

SPLAY_FOREACH(np, NOMBRE, &encabezado)

La macro SPLAY_EMPTY() debe usarse para verificar si un árbol splay está vacío.

ÁRBOLES ROJO-NEGRO

Un árbol rojo-negro es un árbol de búsqueda binaria con el color del nodo como atributo adicional. Cumple un conjunto de condiciones:

  1. cada ruta de búsqueda desde la raíz hasta una hoja consta del mismo número de nodos negros,
  2. cada nodo rojo (excepto la raíz) tiene un padre negro,
  3. cada nodo hoja es negro.

Cada operación en un árbol rojo-negro está limitada a O(lg n). La altura máxima de un árbol rojo-negro es 2lg (n+1).

Un árbol rojo-negro está encabezado por una estructura definida por la macro RB_HEAD(). Una estructura RB_HEAD se declara de la siguiente manera:

RB_HEAD(NOMBRE_ENCABEZADO, TIPO) encabezado;

donde NOMBRE_ENCABEZADO es el nombre de la estructura que se va a definir, y struct TIPO es el tipo de los elementos que se insertarán en el árbol.

La macro RB_ENTRY() declara una estructura que permite conectar elementos en el árbol.

Para utilizar las funciones que manipulan la estructura del árbol, sus prototipos deben declararse con las macros RB_PROTOTYPE() o RB_PROTOTYPE_STATIC(), donde NOMBRE es un identificador único para este árbol en particular. El argumento TIPO es el tipo de la estructura que está siendo administrada por el árbol. El argumento CAMPO es el nombre del elemento definido por RB_ENTRY().

RB_HEAD(HEADNAME, TYPE) head = RB_INITIALIZER(&head);

DESCRIPCIÓN

El macro RB_INIT() inicializa el árbol rojo-negro referido por el head. El macro RB_INITIALIZER() inicializa un árbol rojo-negro de forma estática, como se muestra:

RB_HEAD(HEADNAME, TYPE) head = RB_INITIALIZER(&head);

El árbol rojo-negro puede también ser inicializado de forma estática utilizando la macro RB_INITIALIZER() como se muestra:

RB_HEAD(HEADNAME, TYPE) head = RB_INITIALIZER(&head);

El macro RB_INSERT() inserta el elemento nuevo elm en el árbol. En caso de éxito, se devuelve NULL. Si ya existe un elemento con el mismo valor en el árbol, la inserción se aborta y se devuelve un puntero al elemento existente.

El macro RB_REMOVE() elimina el elemento elm del árbol referido por head. El macro RB_REMOVE() devuelve elm.

Los macros RB_FIND() y RB_NFIND() se pueden utilizar para encontrar un elemento específico en el árbol. El macro RB_FIND() busca el nodo con el mismo valor de clave que elm. El macro RB_NFIND() busca el primer nodo que sea mayor o igual que la clave de búsqueda.

struct TYPE find, *res;
find.key = 30;
res = RB_FIND(NAME, &head, &find);

Los macros RB_ROOT(), RB_MIN(), RB_MAX(), RB_NEXT(), RB_PREV() se pueden utilizar para recorrer el árbol:

for (np = RB_MIN(NAME, &head); np != NULL; np = RB_NEXT(NAME, &head, np))

O, para simplicidad, se pueden utilizar las macros RB_FOREACH() o RB_FOREACH_REVERSE():

RB_FOREACH(np, NAME, &head)

Los macros RB_FOREACH_SAFE() y RB_FOREACH_REVERSE_SAFE() recorren el árbol referido por head en una dirección forward o reverse, asignando cada elemento a np. Sin embargo, a diferencia de sus versiones no seguras, permiten el borrado de np y la liberación de memoria dentro del ciclo de manera segura sin interferir con el recorrido.

El macro RB_EMPTY() debe utilizarse para verificar si un árbol rojo-negro está vacío.

EJEMPLOS

El siguiente ejemplo muestra cómo declarar un árbol rojo-negro que contiene enteros. Los valores se insertan en él y los contenidos del árbol se imprimen en orden. Por último, se imprime la estructura interna del árbol.

#include <sys/tree.h>
#include <err.h>
#include <stdio.h>
#include <stdlib.h>

struct node {
	RB_ENTRY(node) entry;
	int i;
};

int intcmp(struct node *, struct node *);
void print_tree(struct node *);

int
intcmp(struct node *e1, struct node *e2)
{
	return (e1->i < e2->i ? -1 : e1->i > e2->i);
}

RB_HEAD(inttree, node) head = RB_INITIALIZER(&head);
RB_PROTOTYPE(inttree, node, entry, intcmp)
RB_GENERATE(inttree, node, entry, intcmp)

int testdata[] = {
	20, 16, 17, 13, 3, 6, 1, 8, 2, 4, 10, 19, 5, 9, 12, 15, 18,
	7, 11, 14
};

void
print_tree(struct node *n)
{
	struct node *left, *right;

	if (n == NULL) {
		printf("nil");
		return;
	}
	left = RB_LEFT(n, entry);
	right = RB_RIGHT(n, entry);
	if (left == NULL && right == NULL)
		printf("%d", n->i);
	else {
		printf("%d(", n->i);
		print_tree(left);
		printf(",&");
		print_tree(right);
		printf(")");
	}
}

int
main(void)
{
	int i;
	struct node *n;

	for (i = 0; i < sizeof(testdata) / sizeof(testdata[0]); i++) {
		if ((n = malloc(sizeof(struct node))) == NULL)
			err(1, NULL);
		n->i = testdata[i];
		RB_INSERT(inttree, &head, n);
	}

	RB_FOREACH(n, inttree, &head) {
		printf("%d\n", n->i);
	}
	print_tree(RB_ROOT(&head));
	printf("\n");
	return (0);
}

HISTORIA

Los macros de árbol rojo-negro se introdujeron por primera vez en FreeBSD 4.6.

NOTAS

La siguiente forma de liberar un árbol es un error común:

SPLAY_FOREACH(var, NAME, &head) {
	SPLAY_REMOVE(NAME, &head, var);
	free(var);
}
free(head);

Dado que var se libera, la macro FOREACH() refiere a un puntero que puede haber sido reasignado ya. El código correcto necesita una variable adicional.

for (var = SPLAY_MIN(NAME, &head); var != NULL; var = nxt) {
	nxt = SPLAY_NEXT(NAME, &head, var);
	SPLAY_REMOVE(NAME, &head, var);
	free(var);
}
