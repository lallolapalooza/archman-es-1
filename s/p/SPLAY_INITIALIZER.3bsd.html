DESCRIPCIÓN

Estas macros definen estructuras de datos para diferentes tipos de árboles: árboles splay y árboles rojo-negro.

En las definiciones de macros, TYPE es el nombre de etiqueta de una estructura definida por el usuario que debe contener un campo llamado FIELD, de tipo SPLAY_ENTRY o RB_ENTRY. El argumento HEADNAME es el nombre de etiqueta de una estructura definida por el usuario que debe declararse usando las macros SPLAY_HEAD() o RB_HEAD(). El argumento NAME tiene que ser un prefijo de nombre único para cada árbol que se defina.

Los prototipos de las funciones se declaran con SPLAY_PROTOTYPE, RB_PROTOTYPE, o RB_PROTOTYPE_STATIC. Los cuerpos de las funciones se generan con SPLAY_GENERATE, RB_GENERATE, o RB_GENERATE_STATIC. Consulte los ejemplos a continuación para obtener más explicaciones sobre cómo se utilizan estas macros.

ÁRBOLES SPLAY

Un árbol splay es una estructura de datos autoorganizada. Cada operación en el árbol provoca un splay. El splay mueve el nodo solicitado a la raíz del árbol y lo reequilibra parcialmente.

Esto tiene el beneficio de que la localidad de las solicitudes permite búsquedas más rápidas, ya que los nodos solicitados se mueven a la parte superior del árbol. Por otro lado, cada búsqueda provoca escrituras en la memoria.

El Teorema de Equilibrio limita el tiempo total de acceso para m operaciones y n inserciones en un árbol inicialmente vacío como O((m + n)lg n). El costo amortizado para una secuencia de m accesos a un árbol splay es O(lg n).

Un árbol splay está encabezado por una estructura definida por la macro SPLAY_HEAD(). Una estructura SPLAY_HEAD se declara de la siguiente manera:

SPLAY_HEAD(NOMBRE_CABECERA, TIPO) cabecera;

donde NOMBRE_CABECERA es el nombre de la estructura a definir y la estructura TIPO es el tipo de los elementos a insertar en el árbol.

La macro SPLAY_ENTRY() declara una estructura que permite conectar elementos en el árbol.

Para utilizar las funciones que manipulan la estructura del árbol, sus prototipos deben declararse con la macro SPLAY_PROTOTYPE(), donde NAME es un identificador único para este árbol particular. El argumento TIPO es el tipo de la estructura que está siendo gestionada por el árbol. El argumento FIELD es el nombre del elemento definido por SPLAY_ENTRY().

Los cuerpos de las funciones se generan con la macro SPLAY_GENERATE(). Toma los mismos argumentos que la macro SPLAY_PROTOTYPE(), pero solo debe usarse una vez.

Finalmente, el argumento CMP es el nombre de una función utilizada para comparar nodos del árbol entre sí. La función toma dos argumentos de tipo struct TYPE *. Si el primer argumento es menor que el segundo, la función devuelve un valor menor que cero. Si son iguales, la función devuelve cero. De lo contrario, debería devolver un valor mayor que cero. La función de comparación define el orden de los elementos del árbol.

La macro SPLAY_INIT() inicializa el árbol referenciado por head.

El árbol splay también se puede inicializar estáticamente utilizando la macro SPLAY_INITIALIZER() de la siguiente manera:

SPLAY_HEAD(NOMBRE_CABECERA, TIPO) cabecera = SPLAY_INITIALIZER(&cabecera);

La macro SPLAY_INSERT() inserta el nuevo elemento elm en el árbol. En caso de éxito, se devuelve NULL. Si ya existe un elemento correspondiente en el árbol, la inserción se aborta y se devuelve un puntero al elemento existente.

La macro SPLAY_REMOVE() elimina el elemento elm del árbol apuntado por head. En caso de éxito, se devuelve un puntero al elemento eliminado. Se devuelve NULL si elm no está presente en el árbol.

La macro SPLAY_FIND() se puede utilizar para encontrar un elemento particular en el árbol.

struct TIPO find, *res;
find.key = 30;
res = SPLAY_FIND(NOMBRE, &cabecera, &find);

Las macros SPLAY_ROOT(), SPLAY_MIN(), SPLAY_MAX(), y SPLAY_NEXT() se pueden utilizar para recorrer el árbol:

for (np = SPLAY_MIN(NOMBRE, &cabecera); np != NULL; np = SPLAY_NEXT(NOMBRE, &cabecera, np))

O, para mayor simplicidad, se puede usar la macro SPLAY_FOREACH():

SPLAY_FOREACH(np, NOMBRE, &cabecera)

La macro SPLAY_EMPTY() debe usarse para verificar si un árbol splay está vacío.

ÁRBOLES ROJO-NEGRO

Un árbol rojo-negro es un árbol de búsqueda binario con el color del nodo como un atributo adicional. Cumple un conjunto de condiciones:

  1. cada ruta de búsqueda desde la raíz hasta una hoja consta del mismo número de nodos negros,
  2. cada nodo rojo (excepto la raíz) tiene un padre negro,
  3. cada nodo hoja es negro.

Cada operación en un árbol rojo-negro está limitada a O(lg n). La altura máxima de un árbol rojo-negro es 2lg (n+1).

Un árbol rojo-negro está encabezado por una estructura definida por la macro RB_HEAD(). Una estructura RB_HEAD se declara de la siguiente manera:

RB_HEAD(NOMBRE_CABECERA, TIPO) cabecera;

donde NOMBRE_CABECERA es el nombre de la estructura a definir y la estructura TIPO es el tipo de los elementos a insertar en el árbol.

La macro RB_ENTRY() declara una estructura que permite conectar elementos en el árbol.

Para utilizar las funciones que manipulan la estructura del árbol, sus prototipos deben declararse con las macros RB_PROTOTYPE() o RB_PROTOTYPE_STATIC(), donde NAME es un identificador único para este árbol particular. El argumento TYPE es el tipo de la estructura que está siendo gestionada por el árbol. El argumento FIELD es el nombre del elemento definido por RB_ENTRY().

ÁRBOLES ROJO-NEGRO

Los árboles rojo-negro se definen en el archivo de cabecera <sys/tree.h>. Las estructuras de datos de los árboles rojo-negro se basan en el algoritmo descrito en el libro de Introducción a los Algoritmos (Introduction to Algorithms) de Cormen, Leiserson, Rivest y Stein. La implementación se basa en las macros de árbol publicadas en el BSD magazine.

Para usar los árboles rojo-negro, primero debe definir la estructura del nodo y la cabeza del árbol. Los árboles rojo-negro requieren que el tipo de nodo sea un tipo agregado que contenga un campo RB_ENTRY que contendrá punteros a los nodos del árbol. La cabeza del árbol es una estructura que contiene un puntero al primer nodo del árbol. El uso de RB_PROTOTYPE y RB_GENERATE es obligatorio para la inicialización y generación de código para su árbol.

El uso de RB_PROTOTYPE es obligatorio para cada tipo de árbol que se defina. Su uso es para declarar las funciones que serán generadas por RB_GENERATE. RB_GENERATE debe ser llamado una vez para cada tipo de árbol. Al igual que con RB_PROTOTYPE, esta macro debe ser llamada solo una vez.

Finalmente, el argumento CMP es el nombre de una función utilizada para comparar los nodos de los árboles entre sí. La función recibe dos argumentos de tipo struct TYPE *. Si el primer argumento es menor que el segundo, la función devuelve un valor menor que cero. Si son iguales, la función devuelve cero. De lo contrario, debería devolver un valor mayor que cero. La función de comparación define el orden de los elementos del árbol.

La macro RB_INIT() inicializa el árbol al que apunta head.

El árbol rojo-negro también se puede inicializar estáticamente usando la macro RB_INITIALIZER() de la siguiente manera:

RB_HEAD(HEADNAME, TYPE) head = RB_INITIALIZER(&head);

La macro RB_INSERT() inserta el nuevo elemento elm en el árbol. En caso de éxito, se devuelve NULL. Si ya existe un elemento coincidente en el árbol, la inserción se aborta y se devuelve un puntero al elemento existente.

La macro RB_REMOVE() elimina el elemento elm del árbol al que apunta head. RB_REMOVE() devuelve elm.

Las macros RB_FIND() y RB_NFIND() se pueden usar para encontrar un elemento particular en el árbol. RB_FIND() encuentra el nodo con la misma clave que elm. RB_NFIND() encuentra el primer nodo mayor o igual que la clave de búsqueda.

struct TYPE find, *res;
find.key = 30;
res = RB_FIND(NAME, &head, &find);

Las macros RB_ROOT(), RB_MIN(), RB_MAX(), RB_NEXT(), y RB_PREV() se pueden usar para recorrer el árbol:

for (np = RB_MIN(NAME, &head); np != NULL; np = RB_NEXT(NAME, &head, np))

O, para mayor simplicidad, se pueden usar las macros RB_FOREACH() o RB_FOREACH_REVERSE():

RB_FOREACH(np, NAME, &head)

Las macros RB_FOREACH_SAFE() y RB_FOREACH_REVERSE_SAFE() recorren el árbol al que apunta head en una dirección hacia adelante o inversa respectivamente, asignando cada elemento en turno a np. Sin embargo, a diferencia de sus contrapartes inseguras, permiten tanto la eliminación de np como su liberación dentro del bucle de forma segura sin interferir con el recorrido.

La macro RB_EMPTY() debe usarse para verificar si un árbol rojo-negro está vacío.

EJEMPLOS

El siguiente ejemplo demuestra cómo declarar un árbol rojo-negro que contiene enteros. Los valores se insertan en él y el contenido del árbol se imprime en orden. Por último, se imprime la estructura interna del árbol.

#include <sys/tree.h>
#include <err.h>
#include <stdio.h>
#include <stdlib.h>

struct node {
	RB_ENTRY(node) entry;
	int i;
};

int	intcmp(struct node *, struct node *);
void	print_tree(struct node *);

int
intcmp(struct node *e1, struct node *e2)
{
	return (e1->i < e2->i ? -1 : e1->i > e2->i);
}

RB_HEAD(inttree, node) head = RB_INITIALIZER(&head);
RB_PROTOTYPE(inttree, node, entry, intcmp)
RB_GENERATE(inttree, node, entry, intcmp)

int testdata[] = {
	20, 16, 17, 13, 3, 6, 1, 8, 2, 4, 10, 19, 5, 9, 12, 15, 18,
	7, 11, 14
};

void
print_tree(struct node *n)
{
	struct node *left, *right;

	if (n == NULL) {
		printf("nil");
		return;
	}
	left = RB_LEFT(n, entry);
	right = RB_RIGHT(n, entry);
	if (left == NULL && right == NULL)
		printf("%d", n->i);
	else {
		printf("%d(", n->i);
		print_tree(left);
		printf(",");
		print_tree(right);
		printf(")");
	}
}

int
main(void)
{
	int i;
	struct node *n;

	for (i = 0; i < sizeof(testdata) / sizeof(testdata[0]); i++) {
		if ((n = malloc(sizeof(struct node))) == NULL)
			err(1, NULL);
		n->i = testdata[i];
		RB_INSERT(inttree, &head, n);
	}

	RB_FOREACH(n, inttree, &head) {
		printf("%d\n", n->i);
	}
	print_tree(RB_ROOT(&head));
	printf("\n");
	return (0);
}

HISTORIA

NOTAS

Intentar liberar un árbol de la siguiente manera es un error común:

SPLAY_FOREACH(var, NAME, &head) {
	SPLAY_REMOVE(NAME, &head, var);
	free(var);
}
free(head);

Dado que var se libera, la macro FOREACH() hace referencia a un puntero que puede haber sido reasignado previamente. Un código correcto necesita una segunda variable.

for (var = SPLAY_MIN(NAME, &head); var != NULL; var = nxt) {
	nxt = SPLAY_NEXT(NAME, &head, var);
	SPLAY_REMOVE(NAME, &head, var);
	free(var);
}
