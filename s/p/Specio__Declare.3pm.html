Specio::Declare(3) Documentación de Perl contribuida por el usuario Specio::Declare(3)

NOMBRE

Specio::Declare - Rutinas de declaración de Specio

VERSIÓN

versión 0.53

SINOPSIS

package MyApp::Type::Library;
use parent 'Specio::Exporter';
use Specio::Declare;
use Specio::Library::Builtins;
declare(
    'Foo',
    parent => t('Str'),
    where  => sub { $_[0] =~ /foo/i },
);
declare(
    'ArrayRefOfInt',
    parent => t( 'ArrayRef', of => t('Int') ),
);
my $even = anon(
    parent => t('Int'),
    inline => sub {
        my $type      = shift;
        my $value_var = shift;
        return $value_var . ' % 2 == 0';
    },
);
coerce(
    t('ArrayRef'),
    from  => t('Foo'),
    using => sub { [ $_[0] ] },
);
coerce(
    $even,
    from  => t('Int'),
    using => sub { $_[0] % 2 ? $_[0] + 1 : $_[0] },
);
# El nombre de Specio es DateTime
any_isa_type('DateTime');
# El nombre de Specio es DateTimeObject
object_isa_type( 'DateTimeObject', class => 'DateTime' );
any_can_type(
    'Duck',
    methods => [ 'duck_walk', 'quack' ],
);
object_can_type(
    'DuckObject',
    methods => [ 'duck_walk', 'quack' ],
);
enum(
    'Colors',
    values => [qw( blue green red )],
);
intersection(
    'HashRefAndArrayRef',
    of => [ t('HashRef'), t('ArrayRef') ],
);
union(
    'IntOrArrayRef',
    of => [ t('Int'), t('ArrayRef') ],
);

DESCRIPCIÓN

Este paquete exporta un conjunto de ayudantes para la declaración de tipos. La importación de este paquete también hace que cree una subrutina "t" en el paquete que lo llama.

SUBRUTINAS

Este módulo exporta las siguientes subrutinas.

t('nombre')

Esta subrutina le permite acceder a cualquier tipo que haya declarado hasta ahora, así como a cualquier tipo que haya importado de otra biblioteca de tipos.

Si pasa un nombre desconocido, lanza una excepción.

declare(...)

Esta subrutina declara un tipo con nombre. El primer argumento es el nombre del tipo, seguido de un conjunto de parámetros clave/valor:

  • parent => $type

    El padre debe ser otro objeto de tipo. Específicamente, puede ser cualquier cosa que realice el rol Specio::Constraint::Role::Interface. El padre puede ser un tipo nombrado o anónimo.

  • where => sub { ... }

    Esta es una subrutina que define la restricción de tipo. Se le pasará un solo argumento, el valor a comprobar, y debe devolver verdadero o falso para indicar si el valor es válido para el tipo.

    Este parámetro es mutuamente exclusivo con el parámetro "inline".

  • inline => sub { ... }

    Esta es una subrutina que se llama para generar código en línea para validar el tipo. La generación en línea puede ser mucho más rápida que simplemente proporcionar una subrutina con el parámetro "where", pero a menudo es más complicada de hacer correctamente.

    El generador en línea se llama como un método en el tipo con un argumento. Este argumento es una cadena que contiene el nombre de la variable a usar en el código generado. Típicamente, esto es algo como '$_[0]' o '$value'.

    La subrutina del generador en línea debe devolver una cadena de código que represente un solo término, y no debe terminar con punto y coma. Esto permite que el código insertado se incluya de forma segura en una declaración "if", por ejemplo. Puede usar bloques "do { }" y ternarios para que todo quede en un solo término. No asigne a la variable que está comprobando. Este único término debe evaluarse como verdadero o falso.

    Se espera que el generador en línea incluya código para implementar tanto el tipo actual como todos sus padres. Típicamente, la forma más fácil de hacerlo es escribir una subrutina algo como esto:

    sub {
    my $self = shift;
    my $var  = shift;
    return $self->parent->inline_check($var)
        . ' y más código de comprobación va aquí';
}

    O, de forma más concisa:

    sub { $_[0]->parent->inline_check( $_[1] ) . 'más código que comprueba $_[1]' }

    El parámetro "inline" es mutuamente exclusivo con el parámetro "where".

  • message_generator => sub { ... }

    Una subrutina para generar un mensaje de error cuando falla la comprobación del tipo. El mensaje predeterminado dice algo como "La validación falló para el tipo llamado Int declarado en el paquete Specio::Library::Builtins (.../Specio/blib/lib/Specio/Library/Builtins.pm) en la línea 147 en la subrutina llamada (eval) con el valor 1.1".

    Puede anular esto para proporcionar algo más específico sobre la forma en que falló el tipo.

    La subrutina que proporcione se llamará como un método en el tipo con dos argumentos. El primero es la descripción del tipo (la parte del mensaje anterior que comienza con "tipo llamado Int ..." y termina con "... en la subrutina llamada (eval)". Esta descripción indica qué es la cosa y dónde se definió.

    El segundo argumento es el valor que falló la comprobación del tipo, después de cualquier coerción que se haya podido aplicar.

anon(...)

Esta subrutina declara un tipo anónimo. Es idéntica a "declare" excepto que espera una lista de parámetros clave/valor sin un nombre de tipo como primer parámetro.

coerce(...)

Esto declara una coerción de un tipo a otro. El primer argumento debe ser un objeto que realice el rol Specio::Constraint::Role::Interface. Este puede ser un tipo nombrado o anónimo. Este tipo es al que se realiza la coerción.

Los argumentos restantes son parámetros clave/valor:

  • from => $type

    Este debe ser un objeto que realice el rol Specio::Constraint::Role::Interface. Este es el tipo del que estamos haciendo la coerción. Nuevamente, puede ser un tipo nombrado o anónimo.

  • using => sub { ... }

    Esta es una subrutina que define la coerción de tipo. Se le pasará un solo argumento, el valor a coaccionar. Debe devolver un nuevo valor del tipo al que se realiza esta coerción.

    Este parámetro es mutuamente exclusivo con el parámetro "inline".

  • inline => sub { ... }

    Esta es una subrutina que se llama para generar código en línea para realizar la coerción.

    El generador en línea se llama como un método en el tipo con un argumento. Este argumento es una cadena que contiene el nombre de la variable a usar en el código generado. Típicamente, esto es algo como '$_[0]' o '$value'.

    La subrutina del generador en línea debe devolver una cadena de código que represente un solo término, y no debe terminar con punto y coma. Esto permite que el código insertado se incluya de forma segura en una declaración "if", por ejemplo. Puede usar bloques "do { }" y ternarios para que todo quede en un solo término. Este único término debe evaluarse como el nuevo valor.

AYUDANTES DE DECLARACIÓN

Este módulo también exporta algunos ayudantes para declarar ciertos tipos de tipos:

any_isa_type, object_isa_type

El ayudante "any_isa_type" crea un tipo que acepta un nombre de clase o un objeto de esa clase. El ayudante "object_isa_type" crea un tipo que solo acepta un objeto de esa clase.

class_type

Este auxiliar crea un tipo que acepta un nombre de clase o un objeto que es una instancia de la clase dada. El primer argumento es un nombre de tipo. Los argumentos restantes son pares clave/valor. Actualmente solo hay la clave "class", que debe ser un nombre de clase. Este es el nombre de clase que requiere el tipo.

El argumento del nombre del tipo puede omitirse para crear un tipo anónimo.

También puedes pasar solo un argumento, en cuyo caso ese se usará tanto como el nombre del tipo como la clase para la restricción a verificar.

does_type, object_does_type

El auxiliar "does_type" crea un tipo que acepta un nombre de clase o un objeto que cumple el rol dado. El auxiliar "object_does_type" crea un tipo que solo acepta un objeto que cumple el rol dado.

Estas subrutinas toman un nombre de tipo como primer argumento. Los argumentos restantes son pares clave/valor. Actualmente solo está la clave "role", que debe ser un nombre de rol. Este es el nombre de clase que requiere el tipo.

Esto debería funcionar (espero) con roles creados por Moose, Mouse y Moo (usando Role::Tiny).

El argumento del nombre del tipo puede omitirse para crear un tipo anónimo.

También puedes pasar solo un argumento, en cuyo caso ese se usará tanto como el nombre del tipo como el rol para la restricción a verificar.

any_can_type, object_can_type

El auxiliar "any_can_type" crea un tipo que acepta un nombre de clase o un objeto con los métodos dados. El auxiliar "object_can_type" crea un tipo que solo acepta un objeto con los métodos dados.

Estas subrutinas toman un nombre de tipo como primer argumento. Los argumentos restantes son pares clave/valor. Actualmente solo está la clave "methods", que puede ser una cadena o una referencia de array de cadenas. Estas cadenas son los métodos requeridos para el tipo.

El argumento del nombre del tipo puede omitirse para crear un tipo anónimo.

enum

Esto crea un tipo que acepta una cadena que coincide con una lista dada de valores aceptables.

El primer argumento es el nombre del tipo. Los argumentos restantes son pares clave/valor. Actualmente solo está la clave "values". Debe ser una referencia de array de valores de cadena aceptables.

El argumento del nombre del tipo puede omitirse para crear un tipo anónimo.

intersection

Esto crea un tipo que es la intersección de dos o más tipos. Una unión solo acepta valores que coinciden con todos sus tipos subyacentes.

El primer argumento es el nombre del tipo. Los argumentos restantes son pares clave/valor. Actualmente solo está la clave "of". Debe ser una referencia de array de tipos.

El argumento del nombre del tipo puede omitirse para crear un tipo anónimo.

union

Esto crea un tipo que es la unión de dos o más tipos. Una unión acepta cualquiera de sus tipos subyacentes.

El primer argumento es el nombre del tipo. Los argumentos restantes son pares clave/valor. Actualmente solo está la clave "of". Debe ser una referencia de array de tipos.

El argumento del nombre del tipo puede omitirse para crear un tipo anónimo.

TIPOS PARAMETRIZADOS

Puedes crear un tipo parametrizado llamando a "t" con parámetros adicionales, así:

my $arrayref_of_int = t( 'ArrayRef', of => t('Int') );
my $arrayref_of_hashref_of_int = t(
    'ArrayRef',
    of => t(
        'HashRef',
        of => t('Int'),
    ),
);

La subrutina "t" asume que si recibe más de un argumento, debe buscar el tipo nombrado y llamar a "$type->parameterize(...)" con los argumentos adicionales.

Si el tipo nombrado no puede ser parametrizado, lanza un error.

También puedes llamar a "$type->parameterize" directamente si es necesario. Ver Specio::Constraint::Parameterizable para más detalles.
