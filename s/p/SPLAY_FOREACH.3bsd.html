DESCRIPCIÓN

Estas macros definen estructuras de datos para diferentes tipos de árboles: árboles splay y árboles rojo-negro.

En las definiciones de macros, TYPE es la etiqueta de nombre de una estructura definida por el usuario que debe contener un campo llamado FIELD, del tipo SPLAY_ENTRY o RB_ENTRY. El argumento HEADNAME es la etiqueta de nombre de una estructura definida por el usuario que debe declararse utilizando las macros SPLAY_HEAD() o RB_HEAD(). El argumento NAME tiene que ser un prefijo de nombre único para cada árbol que se defina.

Los prototipos de funciones se declaran con SPLAY_PROTOTYPE, RB_PROTOTYPE, o RB_PROTOTYPE_STATIC. Los cuerpos de las funciones se generan con SPLAY_GENERATE, RB_GENERATE, o RB_GENERATE_STATIC. Consulte los ejemplos a continuación para obtener más explicaciones sobre cómo se utilizan estas macros.

ÁRBOLES SPLAY

Un árbol splay es una estructura de datos auto-organizativa. Cada operación en el árbol provoca un splay. El splay mueve el nodo solicitado a la raíz del árbol y lo reequilibra parcialmente.

Esto tiene el beneficio de que la localidad de las solicitudes acelera las búsquedas, ya que los nodos solicitados se mueven a la parte superior del árbol. Por otro lado, cada búsqueda provoca escrituras en memoria.

El Teorema de Balance limita el tiempo total de acceso para m operaciones e n inserciones en un árbol inicialmente vacío como O((m + n)lg n). El costo amortizado para una secuencia de m accesos a un árbol splay es O(lg n).

Un árbol splay está encabezado por una estructura definida por la macro SPLAY_HEAD(). Una estructura SPLAY_HEAD se declara de la siguiente manera:

SPLAY_HEAD(HEADNAME, TYPE) head;

donde HEADNAME es el nombre de la estructura a definir, y struct TYPE es el tipo de los elementos que se insertarán en el árbol.

La macro SPLAY_ENTRY() declara una estructura que permite que los elementos se conecten en el árbol.

Para utilizar las funciones que manipulan la estructura del árbol, sus prototipos deben declararse con la macro SPLAY_PROTOTYPE(), donde NAME es un identificador único para este árbol en particular. El argumento TYPE es el tipo de la estructura que está siendo gestionada por el árbol. El argumento FIELD es el nombre del elemento definido por SPLAY_ENTRY().

Los cuerpos de las funciones se generan con la macro SPLAY_GENERATE(). Toma los mismos argumentos que la macro SPLAY_PROTOTYPE(), pero solo debe usarse una vez.

Finalmente, el argumento CMP es el nombre de una función utilizada para comparar los nodos de los árboles entre sí. La función toma dos argumentos de tipo struct TYPE *. Si el primer argumento es menor que el segundo, la función devuelve un valor menor que cero. Si son iguales, la función devuelve cero. De lo contrario, debe devolver un valor mayor que cero. La función de comparación define el orden de los elementos del árbol.

La macro SPLAY_INIT() inicializa el árbol al que hace referencia head.

El árbol splay también se puede inicializar estáticamente utilizando la macro SPLAY_INITIALIZER() de la siguiente manera:

SPLAY_HEAD(HEADNAME, TYPE) head = SPLAY_INITIALIZER(&head);

La macro SPLAY_INSERT() inserta el nuevo elemento elm en el árbol. En caso de éxito, se devuelve NULL. Si ya existe un elemento coincidente en el árbol, la inserción se aborta y se devuelve un puntero al elemento existente.

La macro SPLAY_REMOVE() elimina el elemento elm del árbol apuntado por head. En caso de éxito, se devuelve un puntero al elemento eliminado. Se devuelve NULL si elm no está presente en el árbol.

La macro SPLAY_FIND() se puede utilizar para encontrar un elemento particular en el árbol.

struct TYPE find, *res;
find.key = 30;
res = SPLAY_FIND(NAME, &head, &find);

Las macros SPLAY_ROOT(), SPLAY_MIN(), SPLAY_MAX(), y SPLAY_NEXT() se pueden utilizar para recorrer el árbol:

for (np = SPLAY_MIN(NAME, &head); np != NULL; np = SPLAY_NEXT(NAME, &head, np))

O, para simplificar, se puede usar la macro SPLAY_FOREACH():

SPLAY_FOREACH(np, NAME, &head)

La macro SPLAY_EMPTY() debe usarse para verificar si un árbol splay está vacío.

ÁRBOLES ROJO-NEGRO

Un árbol rojo-negro es un árbol de búsqueda binario con el color del nodo como un atributo adicional. Cumple un conjunto de condiciones:

  1. cada ruta de búsqueda desde la raíz hasta una hoja consta del mismo número de nodos negros,
  2. cada nodo rojo (excepto la raíz) tiene un padre negro,
  3. cada nodo hoja es negro.

Cada operación en un árbol rojo-negro está limitada a O(lg n). La altura máxima de un árbol rojo-negro es 2lg (n+1).

Un árbol rojo-negro está encabezado por una estructura definida por la macro RB_HEAD(). Una estructura RB_HEAD se declara de la siguiente manera:

RB_HEAD(HEADNAME, TYPE) head;

donde HEADNAME es el nombre de la estructura a definir, y struct TYPE es el tipo de los elementos que se insertarán en el árbol.

La macro RB_ENTRY() declara una estructura que permite que los elementos se conecten en el árbol.

Para utilizar las funciones que manipulan la estructura del árbol, sus prototipos deben declararse con las macros RB_PROTOTYPE() o RB_PROTOTYPE_STATIC(), donde NAME es un identificador único para este árbol en particular. El argumento TYPE es el tipo de la estructura que está siendo gestionada por el árbol. El argumento FIELD es el nombre del elemento definido por RB_ENTRY().

DESCRIPCIÓN

Los árboles de tipo RB_TREE son árboles de búsqueda binaria auto-balanceables. Son similares a los SPLAY_TREEs, pero utilizan el algoritmo de balanceo de árboles rojo-negros en lugar del de splay. Los árboles rojo-negros ofrecen garantías de rendimiento más consistentes que los árboles de splay, garantizando que las operaciones de inserción, eliminación y búsqueda tengan una complejidad temporal logarítmica en el peor de los casos. Sin embargo, los árboles rojo-negros tienden a ser más lentos en la práctica que los árboles de splay debido a un mayor número de operaciones de rebalanceo.

La definición de un árbol de tipo RB_TREE toma tres argumentos: NAME, TYPE y CMP.

NAME
El nombre único que se usará para esta implementación de árbol. Este nombre se usará como prefijo para todas las funciones y macros de árbol.
TYPE, ENTRY_FIELD
El tipo de estructura de los nodos del árbol. TYPE es el nombre de la estructura, y ENTRY_FIELD es el nombre del campo dentro de la estructura TYPE que contendrá el puntero al nodo del árbol. Este campo debe ser del tipo RB_ENTRY(TYPE).
CMP
El nombre de una función utilizada para comparar los nodos de los árboles entre sí. La función toma dos argumentos de tipo struct TYPE *. Si el primer argumento es menor que el segundo, la función devuelve un valor menor que cero. Si son iguales, la función devuelve cero. De lo contrario, debería devolver un valor mayor que cero. La función de comparación define el orden de los elementos del árbol.

Los árboles rojo-negros se definen usando las macros RB_PROTOTYPE y RB_GENERATE. RB_PROTOTYPE debe usarse en los archivos de encabezado y RB_GENERATE en un archivo .c.

Al igual que con las macros SPLAY_TREE, el uso de RB_PROTOTYPE y RB_GENERATE para la misma definición de árbol solo debe hacerse una vez.

Finalmente, el argumento CMP es el nombre de una función utilizada para comparar los nodos de los árboles entre sí. La función toma dos argumentos de tipo struct TYPE *. Si el primer argumento es menor que el segundo, la función devuelve un valor menor que cero. Si son iguales, la función devuelve cero. De lo contrario, debería devolver un valor mayor que cero. La función de comparación define el orden de los elementos del árbol.

La macro RB_INIT() inicializa el árbol referenciado por head.

El árbol rojo-negro también se puede inicializar estáticamente utilizando la macro RB_INITIALIZER() de esta manera:

RB_HEAD(HEADNAME, TYPE) head = RB_INITIALIZER(&head);

La macro RB_INSERT() inserta el nuevo elemento elm en el árbol. En caso de éxito, se devuelve NULL. Si ya existe un elemento coincidente en el árbol, la inserción se interrumpe y se devuelve un puntero al elemento existente.

La macro RB_REMOVE() elimina el elemento elm del árbol apuntado por head. RB_REMOVE() devuelve elm.

Las macros RB_FIND() y RB_NFIND() se pueden usar para encontrar un elemento particular en el árbol. RB_FIND() encuentra el nodo con la misma clave que elm. RB_NFIND() encuentra el primer nodo mayor o igual que la clave de búsqueda.

struct TYPE find, *res;
find.key = 30;
res = RB_FIND(NAME, &head, &find);

Las macros RB_ROOT(), RB_MIN(), RB_MAX(), RB_NEXT() y RB_PREV() se pueden usar para recorrer el árbol:

for (np = RB_MIN(NAME, &head); np != NULL; np = RB_NEXT(NAME, &head, np))

O, para mayor simplicidad, se pueden usar las macros RB_FOREACH() o RB_FOREACH_REVERSE():

RB_FOREACH(np, NAME, &head)

Las macros RB_FOREACH_SAFE() y RB_FOREACH_REVERSE_SAFE() recorren el árbol referenciado por head en una dirección hacia adelante o hacia atrás respectivamente, asignando cada elemento en turno a np. Sin embargo, a diferencia de sus contrapartes inseguras, permiten tanto la eliminación de np como su liberación dentro del bucle de forma segura sin interferir con el recorrido.

La macro RB_EMPTY() debe usarse para verificar si un árbol rojo-negro está vacío.
