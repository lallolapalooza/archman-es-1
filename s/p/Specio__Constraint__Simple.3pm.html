Specio::Constraint::Simple(3) Documentación de Perl aportada por el usuario Specio::Constraint::Simple(3)

NOMBRE

Specio::Constraint::Simple - Clase para tipos simples (no parametrizados o especializados)

VERSIÓN

versión 0.53

SINOPSIS

my $str = t('Str');
print $str->name; # Str
my $parent = $str->parent;
if ( $str->value_is_valid($value) ) { ... }
$str->validate_or_die($value);
my $code = $str->inline_coercion_and_check('$_[0]');

DESCRIPCIÓN

Esta clase implementa restricciones de tipo simples, restricciones sin propiedades especiales o parametrización.

En realidad, no contiene código real propio. Toda la implementación la proporciona el rol Specio::Constraint::Role::Interface, pero la API principal para las restricciones de tipo se documenta aquí.

Todas las demás clases de restricciones de tipo en esta distribución implementan esta API, excepto donde se indique lo contrario.

API

Esta clase proporciona los siguientes métodos.

Specio::Constraint::Simple->new(...)

Esto crea una nueva restricción. Acepta los siguientes parámetros con nombre:

  • name => $name

    Este es el nombre del tipo. El nombre es opcional, pero si se proporciona debe ser una cadena.

  • parent => $type

    El tipo padre. Debe ser un objeto que implemente el rol Specio::Constraint::Role::Interface.

    Este parámetro es opcional.

  • constraint => sub { ... }

    Una referencia a una subrutina que implementa la restricción. Se llamará como método del objeto y se le pasará un solo argumento, el valor a comprobar.

    Debería devolver verdadero o falso para indicar si el valor coincide con la restricción.

    Este parámetro es mutuamente excluyente con "inline_generator".

    También puedes pasar esta opción con la clave "where" en la lista de parámetros.

  • inline_generator => sub { ... }

    Debería ser una referencia a una subrutina que devuelve una cadena que contiene un solo término. Este código no debe terminar con un punto y coma. Este código debe implementar la restricción.

    El generador se llamará como método de la restricción con un solo argumento. Ese argumento es el nombre de la variable que se está convirtiendo, algo como '$_[0]' o '$var'.

    Se espera que el generador en línea incluya código para implementar tanto el tipo actual como todos sus padres. Típicamente, la forma más fácil de hacer esto es escribir una subrutina como esta:

    sub {
    my $self = shift;
    my $var  = shift;
    return $_[0]->parent->inline_check( $_[1] )
        . ' and more checking code goes here';
}

    Este parámetro es mutuamente excluyente con "constraint".

    También puedes pasar esta opción con la clave "inline" en la lista de parámetros.

  • inline_environment => {}

    Debería ser una referencia a un hash de nombres de variables (con sigilos) y valores para esa variable. Los valores deben ser referencias a los valores de las variables.

    Este entorno se utilizará al compilar la restricción como parte de una subrutina. Las variables nombradas se capturarán como clausuras en la subrutina generada, utilizando Eval::Closure.

    Debería ser muy raro necesitar configurar esto en el constructor. Es más probable que una subclase de tipo especial necesite proporcionar valores que genera internamente.

    Si configuras esto, eres responsable de generar nombres de variables que no entren en conflicto con nada más en el código en línea.

    Este parámetro tiene como valor predeterminado una referencia a un hash vacío.

  • message_generator => sub { ... }

    Una subrutina para generar un mensaje de error cuando la verificación del tipo falla. El mensaje predeterminado dice algo como "La validación falló para el tipo llamado Int declarado en el paquete Specio::Library::Builtins (.../Specio/blib/lib/Specio/Library/Builtins.pm) en la línea 147 en la sub llamada (eval) con valor 1.1".

    Puedes anular esto para proporcionar algo más específico sobre la forma en que falló el tipo.

    La subrutina que proporciones se llamará como una subrutina, no como un método, con dos argumentos. El primero es la descripción del tipo (la parte del mensaje anterior que comienza con "tipo llamado Int..." y termina con "... en la sub llamada (eval)". Esta descripción dice qué es la cosa y dónde se definió.

    El segundo argumento es el valor que falló la verificación del tipo, después de cualquier conversión que se haya podido aplicar.

    También puedes pasar esta opción con la clave "message" en la lista de parámetros.

  • declared_at => $declared_at

    Este parámetro debe ser un objeto Specio::DeclaredAt.

    Este parámetro es obligatorio.

Es posible crear un tipo sin una restricción propia.

$type->name

Devuelve el nombre del tipo tal como se pasó al constructor.

$type->parent

Devuelve el tipo padre pasado al constructor. Si el tipo no tiene padre, esto devuelve "undef".

$type->is_anon

Devuelve falso para tipos con nombre, verdadero en caso contrario.

$type->is_a_type_of($other_type)

Dado un objeto de tipo, esto devuelve verdadero si el tipo sobre el que se llama este método es un descendiente de ese tipo o es ese tipo.

$type->is_same_type_as($other_type)

Dado un objeto de tipo, esto devuelve verdadero si el tipo sobre el que se llama este método es el mismo que ese tipo.

$type->coercions

Devuelve una lista de objetos Specio::Coercion que pertenecen a esta restricción.

$type->coercion_from_type($name)

Dado un nombre de tipo, este método devuelve un objeto Specio::Coercion que convierte desde ese tipo, si existe tal conversión.

$type->validate_or_die($value)

Este método no hace nada si el valor es válido. Si no lo es, lanza una Specio::Exception.

$type->value_is_valid($value)

Devuelve verdadero o falso dependiendo de si el $value pasa la restricción de tipo.

$type->has_real_constraint

Esto devuelve verdadero si el tipo se creó con un parámetro "constraint" o "inline_generator". Esto se utiliza internamente para omitir las comprobaciones de tipo para tipos que en realidad no implementan una restricción.

Esto devuelve una cadena que describe el tipo. Incluye el nombre del tipo y dónde

Specio::Constraint::Simple 0.53 man page

NAME

Specio::Constraint::Simple - A simple constraint type

VERSION

0.53

SYNOPSIS

  package My::Role;
  use Specio::Constraint::Simple;

  # Example of a simple type that validates if something is a string
  my $string_type = Specio::Constraint::Simple->new(
    name        => 'String',
    description => 'A string',
    subtypes    => [],
    check       => sub {
      my ($value) = @_;
      return blessed($value) && $value->isa('Str');
    },
  );

  # Example of a type that validates if something is an integer
  my $int_type = Specio::Constraint::Simple->new(
    name        => 'Integer',
    description => 'An integer',
    subtypes    => [],
    check       => sub {
      my ($value) = @_;
      return blessed($value) && $value->isa('Int');
    },
  );

DESCRIPTION

This is a generic constraint class that is useful for creating simple types with a single check sub. It is the base class for most of the built-in types in Specio.

It is generally not recommended that you subclass this class. Instead, you should use the new constructor directly as shown in the SYNOPSIS.

When you create a new type using this class, you pass in a single "check" subroutine. This subroutine is responsible for validating the value. It takes the value as its only argument and should return true if the value is valid, and false otherwise.

The constructor also takes optional name and description arguments. These are used to provide human-readable information about the type. If the type is anonymous, the name will default to "anonymous type".

The subtypes argument is an array ref of other Specio types. This is used for composite types, and is generally not used with this class.

API

$type->name

This returns the name of the type. If the type was declared, you will get something like 'type named Foo declared in package My::Lib (lib/My/Lib.pm) at line 42'. If the type is anonymous the name will be "anonymous type".

$type->id

This is a unique id for the type as a string. This is useful if you need to make a hash key based on a type, for example. This should be treated as an essentially arbitrary and opaque string, and could change at any time in the future. If you want something human-readable, use the "$type->description" method.

$type->add_coercion($coercion)

This adds a new Specio::Coercion to the type. If the type already has a coercion from the same type as the new coercion, it will throw an error.

$type->has_coercion_from_type($other_type)

This method returns true if the type can coerce from the other type.

$type->coerce_value($value)

This attempts to coerce a value into a new value that matches the type. It checks all of the type's coercions. If it finds one which has a "from" type that accepts the value, it runs the coercion and returns the new value.

If it cannot find a matching coercion it returns the original value.

$type->inline_coercion_and_check($var)

Given a variable name, this returns a string of code and an environment hash that implements all of the type's coercions as well as the type check itself.

This will throw an exception unless both the type and all of its coercions are inlinable.

The generated code will throw a Specio::Exception if the type constraint fails. If the constraint passes, then the generated code returns the (possibly coerced) value.

The return value is a two-element list. The first element is the code. The second is a hash reference containing variables which need to be in scope for the code to work. This is intended to be passed to Eval::Closure's "eval_closure" subroutine.

The returned code is a single "do { }" block without a terminating semicolon.

$type->inline_assert($var)

Given a variable name, this generates code that implements the constraint and throws an exception if the variable does not pass the constraint.

The return value is a two-element list. The first element is the code. The second is a hash reference containing variables which need to be in scope for the code to work. This is intended to be passed to Eval::Closure's "eval_closure" subroutine.

$type->inline_check($var)

Given a variable name, this returns a string of code that implements the constraint. If the type is not inlinable, this method throws an error.

$type->inline_coercion($var)

Given a variable name, this returns a string of code and an environment hash that implements all of the type's coercions. It does not check that the resulting value is valid.

This will throw an exception unless all of the type's coercions are inlinable.

The return value is a two-element list. The first element is the code. The second is a hash reference containing variables which need to be in scope for the code to work. This is intended to be passed to Eval::Closure's "eval_closure" subroutine.

The returned code is a single "do { }" block without a terminating semicolon.

$type->inline_environment()

This returns a hash defining the variables that need to be closed over when inlining the type. The keys are full variable names like '$foo' or '@bar'. The values are references to a variable of the matching type.

$type->coercion_sub

This method returns a sub ref that takes a single argument and applied all relevant coercions to it. This sub ref will use Sub::Quote if all the type's coercions are inlinable.

This method exists primarily for the benefit of Moo.

OVERLOADING

All constraints implement the following overloads:

Subroutine De-referencing

This is done for the benefit of Moo. The returned subroutine uses Sub::Quote if the type constraint is inlinable.

Stringification

For non-anonymous types, this will be the type's name. For anonymous types, a string like "__ANON__(Str)" is generated. However, this string should not be expected to be stable across releases, so don't use it for things like equality checks!

Boolification

This always returns true.

String Equality (eq)

This calls "$type->is_same_type_as($other)" to compare the two types.

ROLES

This role does the Specio::Constraint::Role::Interface and Specio::Role::Inlinable roles.
