NOMBRE

SPI_prepare - prepara una sentencia, sin ejecutarla todavía

SINOPSIS

SPIPlanPtr SPI_prepare(const char * command, int nargs, Oid * argtypes)

DESCRIPCIÓN

SPI_prepare crea y devuelve una sentencia preparada para el comando especificado, pero no ejecuta el comando. La sentencia preparada puede ser ejecutada posteriormente repetidamente usando SPI_execute_plan.

Cuando el mismo comando o uno similar se va a ejecutar repetidamente, generalmente es ventajoso realizar el análisis sintáctico solo una vez, y además puede ser ventajoso reutilizar un plan de ejecución para el comando. SPI_prepare convierte una cadena de comando en una sentencia preparada que encapsula los resultados del análisis sintáctico. La sentencia preparada también proporciona un lugar para almacenar en caché un plan de ejecución si se considera que generar un plan personalizado para cada ejecución no es útil.

Un comando preparado puede generalizarse escribiendo parámetros ($1, $2, etc.) en lugar de lo que serían constantes en un comando normal. Los valores reales de los parámetros se especifican cuando se llama a SPI_execute_plan. Esto permite que el comando preparado se use en una gama más amplia de situaciones de las que sería posible sin parámetros.

La sentencia devuelta por SPI_prepare solo se puede usar en la invocación actual de la función C, ya que SPI_finish libera la memoria asignada para dicha sentencia. Pero la sentencia se puede guardar por más tiempo utilizando las funciones SPI_keepplan o SPI_saveplan.

ARGUMENTOS

const char * command

cadena de comando

int nargs

número de parámetros de entrada ($1, $2, etc.)

Oid * argtypes

puntero a un array que contiene los OIDs de los tipos de datos de los parámetros

VALOR DE RETORNO

SPI_prepare devuelve un puntero no nulo a un SPIPlan, que es una estructura opaca que representa una sentencia preparada. En caso de error, se devolverá NULL y SPI_result se establecerá en uno de los mismos códigos de error utilizados por SPI_execute, excepto que se establecerá en SPI_ERROR_ARGUMENT si command es NULL, o si nargs es menor que 0, o si nargs es mayor que 0 y argtypes es NULL.

NOTAS

Si no se definen parámetros, se creará un plan genérico en el primer uso de SPI_execute_plan, y se usará también para todas las ejecuciones posteriores. Si hay parámetros, los primeros usos de SPI_execute_plan generarán planes personalizados que son específicos para los valores de parámetros proporcionados. Después de suficientes usos de la misma sentencia preparada, SPI_execute_plan construirá un plan genérico y, si este no es mucho más costoso que los planes personalizados, comenzará a usar el plan genérico en lugar de planificar de nuevo cada vez. Si este comportamiento predeterminado no es adecuado, puede alterarlo pasando la bandera CURSOR_OPT_GENERIC_PLAN o CURSOR_OPT_CUSTOM_PLAN a SPI_prepare_cursor, para forzar el uso de planes genéricos o personalizados respectivamente.

Aunque el objetivo principal de una sentencia preparada es evitar el análisis sintáctico y la planificación repetidos de la sentencia, PostgreSQL forzará el reanálisis y la replanificación de la sentencia antes de usarla siempre que los objetos de base de datos utilizados en la sentencia hayan sufrido cambios definicionales (DDL) desde el uso anterior de la sentencia preparada. Además, si el valor de search_path cambia de un uso a otro, la sentencia se analizará de nuevo utilizando el nuevo search_path. (Este último comportamiento es nuevo a partir de PostgreSQL 9.3). Consulte PREPARE(7) para obtener más información sobre el comportamiento de las sentencias preparadas.

Esta función solo debe llamarse desde una función C conectada.

SPIPlanPtr se declara como un puntero a un tipo de estructura opaca en spi.h. No es aconsejable intentar acceder a su contenido directamente, ya que esto hace que su código sea mucho más propenso a romperse en futuras revisiones de PostgreSQL.

El nombre SPIPlanPtr es algo histórico, ya que la estructura de datos ya no contiene necesariamente un plan de ejecución.
