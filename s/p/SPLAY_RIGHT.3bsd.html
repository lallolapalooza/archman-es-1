DESCRIPCIÓN

Estas macros definen estructuras de datos para diferentes tipos de árboles: árboles splay y árboles rojo-negros.

En las definiciones de macros, TYPE es la etiqueta de nombre de una estructura definida por el usuario que debe contener un campo llamado FIELD, de tipo SPLAY_ENTRY o RB_ENTRY. El argumento HEADNAME es la etiqueta de nombre de una estructura definida por el usuario que debe declararse usando las macros SPLAY_HEAD() o RB_HEAD(). El argumento NAME tiene que ser un prefijo de nombre único para cada árbol que se defina.

Los prototipos de las funciones se declaran con SPLAY_PROTOTYPE, RB_PROTOTYPE, o RB_PROTOTYPE_STATIC. Los cuerpos de las funciones se generan con SPLAY_GENERATE, RB_GENERATE, o RB_GENERATE_STATIC. Consulte los ejemplos a continuación para obtener más explicaciones sobre cómo se utilizan estas macros.

ÁRBOLES SPLAY

Un árbol splay es una estructura de datos autoorganizativa. Cada operación en el árbol provoca un splay. El splay mueve el nodo solicitado a la raíz del árbol y lo reequilibra parcialmente.

Esto tiene el beneficio de que la localidad de la solicitud provoca búsquedas más rápidas, ya que los nodos solicitados se mueven a la parte superior del árbol. Por otro lado, cada búsqueda provoca escrituras en la memoria.

El Teorema del Equilibrio limita el tiempo total de acceso para m operaciones e n inserciones en un árbol inicialmente vacío como O((m + n)lg n). El costo amortizado para una secuencia de m accesos a un árbol splay es O(lg n).

Un árbol splay está encabezado por una estructura definida por la macro SPLAY_HEAD(). Una estructura SPLAY_HEAD se declara de la siguiente manera:

SPLAY_HEAD(NOMBRE_DEL_ENCABEZADO, TIPO) encabezado;

donde NOMBRE_DEL_ENCABEZADO es el nombre de la estructura a definir, y struct TIPO es el tipo de los elementos que se insertarán en el árbol.

La macro SPLAY_ENTRY() declara una estructura que permite conectar elementos en el árbol.

Para utilizar las funciones que manipulan la estructura del árbol, sus prototipos deben declararse con la macro SPLAY_PROTOTYPE(), donde NAME es un identificador único para este árbol en particular. El argumento TIPO es el tipo de la estructura que se está gestionando en el árbol. El argumento FIELD es el nombre del elemento definido por SPLAY_ENTRY().

Los cuerpos de las funciones se generan con la macro SPLAY_GENERATE(). Toma los mismos argumentos que la macro SPLAY_PROTOTYPE(), pero solo debe usarse una vez.

Finalmente, el argumento CMP es el nombre de una función utilizada para comparar los nodos de los árboles entre sí. La función toma dos argumentos de tipo struct TYPE *. Si el primer argumento es menor que el segundo, la función devuelve un valor menor que cero. Si son iguales, la función devuelve cero. De lo contrario, debería devolver un valor mayor que cero. La función de comparación define el orden de los elementos del árbol.

La macro SPLAY_INIT() inicializa el árbol al que se hace referencia en head.

El árbol splay también se puede inicializar estáticamente utilizando la macro SPLAY_INITIALIZER() de la siguiente manera:

SPLAY_HEAD(NOMBRE_DEL_ENCABEZADO, TIPO) encabezado = SPLAY_INITIALIZER(&encabezado);

La macro SPLAY_INSERT() inserta el nuevo elemento elm en el árbol. En caso de éxito, se devuelve NULL. Si ya existe un elemento coincidente en el árbol, la inserción se aborta y se devuelve un puntero al elemento existente.

La macro SPLAY_REMOVE() elimina el elemento elm del árbol al que apunta head. En caso de éxito, se devuelve un puntero al elemento eliminado. Se devuelve NULL si elm no está presente en el árbol.

La macro SPLAY_FIND() se puede usar para encontrar un elemento particular en el árbol.

struct TIPO buscar, *res;
buscar.clave = 30;
res = SPLAY_FIND(NOMBRE, &encabezado, &buscar);

Las macros SPLAY_ROOT(), SPLAY_MIN(), SPLAY_MAX(), y SPLAY_NEXT() se pueden usar para recorrer el árbol:

para (np = SPLAY_MIN(NOMBRE, &encabezado); np != NULL; np = SPLAY_NEXT(NOMBRE, &encabezado, np))

O, para simplificar, se puede usar la macro SPLAY_FOREACH():

SPLAY_FOREACH(np, NOMBRE, &encabezado)

La macro SPLAY_EMPTY() debe usarse para verificar si un árbol splay está vacío.

ÁRBOLES ROJO-NEGROS

Un árbol rojo-negro es un árbol de búsqueda binario con el color del nodo como atributo adicional. Cumple un conjunto de condiciones:

  1. cada ruta de búsqueda desde la raíz hasta una hoja consta del mismo número de nodos negros,
  2. cada nodo rojo (excepto la raíz) tiene un padre negro,
  3. cada nodo hoja es negro.

Cada operación en un árbol rojo-negro está limitada a O(lg n). La altura máxima de un árbol rojo-negro es 2lg (n+1).

Un árbol rojo-negro está encabezado por una estructura definida por la macro RB_HEAD(). Una estructura RB_HEAD se declara de la siguiente manera:

RB_HEAD(NOMBRE_DEL_ENCABEZADO, TIPO) encabezado;

donde NOMBRE_DEL_ENCABEZADO es el nombre de la estructura a definir, y struct TIPO es el tipo de los elementos que se insertarán en el árbol.

La macro RB_ENTRY() declara una estructura que permite conectar elementos en el árbol.

Para utilizar las funciones que manipulan la estructura del árbol, sus prototipos deben declararse con las macros RB_PROTOTYPE() o RB_PROTOTYPE_STATIC(), donde NAME es un identificador único para este árbol en particular. El argumento TIPO es el tipo de la estructura que se está gestionando en el árbol. El argumento FIELD es el nombre del elemento definido por RB_ENTRY().

Los cuerpos de las funciones se generan con las macros RB_GENERATE() o RB_GENERATE_STATIC(). Estas macros toman los mismos argumentos que las macros RB_PROTOTYPE() y RB_PRORB_PROTOTYPE_STATIC(), pero solo deben usarse una vez.

Al igual que con los árboles splay, el argumento CMP es el nombre de una función utilizada para comparar los nodos de los árboles entre sí.

La macro RB_INIT() inicializa el árbol al que se hace referencia en head.

La macro RB_INSERT() inserta el nuevo elemento elm en el árbol. En caso de éxito, se devuelve un puntero al elemento insertado. Si ya existe un elemento coincidente en el árbol, la inserción se aborta y se devuelve un puntero al elemento existente.

La macro RB_REMOVE() elimina el elemento elm del árbol al que apunta head. En caso de éxito, se devuelve un puntero al elemento eliminado. Se devuelve NULL si elm no está presente en el árbol.

La macro RB_FIND() se puede usar para encontrar un elemento particular en el árbol.

struct TIPO buscar, *res;
buscar.clave = 30;
res = RB_FIND(NOMBRE, &encabezado, &buscar);

Las macros RB_ROOT(), RB_MIN(), RB_MAX(), y RB_NEXT() se pueden usar para recorrer el árbol:

para (np = RB_MIN(NOMBRE, &encabezado); np != NULL; np = RB_NEXT(NOMBRE, &encabezado, np))

O, para simplificar, se puede usar la macro RB_FOREACH():

RB_FOREACH(np, NOMBRE, &encabezado)

La macro RB_EMPTY() debe usarse para verificar si un árbol rojo-negro está vacío.

La macro RB_LEFT() devuelve el hijo izquierdo del nodo elm.

La macro RB_RIGHT() devuelve el hijo derecho del nodo elm.

La macro RB_PARENT() devuelve el padre del nodo elm.

DESCRIPTION

These macros implement a red-black tree data structure. A red-black tree is a binary search tree where each node has a color, red or black, and a specific set of rules to maintain balance:

  • Every node is either red or black.
  • The root is black.
  • Every leaf (NIL) is black.
  • If a node is red, then both its children are black.
  • For each node, all simple paths from the node to descendant leaves contain the same number of black nodes.

The red-black tree macros are designed to be easy to use by requiring minimal boilerplate code. They operate on trees where nodes are embedded within a larger structure. The tree itself is managed by a head structure, which is typically a pointer to a structure containing pointers to the root node and other tree metadata.

Before using the red-black tree macros, you must define the tree head and the structure of the nodes that will be stored in the tree. The node structure must contain a field of type RB_ENTRY(TYPE). This field is used internally by the tree macros to link nodes.

The RB_HEAD() macro declares the tree head structure. HEADNAME is the name to be given to the tree head structure, and TYPE is the name of the structure that will be stored in the tree.

The RB_PROTOTYPE() macro declares the tree head structure and the comparison function. HEADNAME is the name of the tree head structure, TYPE is the name of the node structure, field is the name of the RB_ENTRY member within the node structure, and CMP is the name of the comparison function.

The RB_GENERATE() macro defines the tree head structure and the comparison function. It should be used in exactly one source file. It is similar to RB_PROTOTYPE(), but it also generates the implementation of the tree functions.

The CMP argument is the name of a function used to compare trees' nodes with each other. The function takes two arguments of type struct TYPE *. If the first argument is smaller than the second, the function returns a value smaller than zero. If they are equal, the function returns zero. Otherwise, it should return a value greater than zero. The compare function defines the order of the tree elements.

The RB_INIT() macro initializes the tree referenced by head.

The red-black tree can also be initialized statically by using the RB_INITIALIZER() macro like this:

RB_HEAD(HEADNAME, TYPE) head = RB_INITIALIZER(&head);

The RB_INSERT() macro inserts the new element elm into the tree. Upon success, NULL is returned. If a matching element already exists in the tree, the insertion is aborted, and a pointer to the existing element is returned.

The RB_REMOVE() macro removes the element elm from the tree pointed by head. RB_REMOVE() returns elm.

The RB_FIND() and RB_NFIND() macros can be used to find a particular element in the tree. RB_FIND() finds the node with the same key as elm. RB_NFIND() finds the first node greater than or equal to the search key.

struct TYPE find, *res;
find.key = 30;
res = RB_FIND(NAME, &head, &find);

The RB_ROOT(), RB_MIN(), RB_MAX(), RB_NEXT(), and RB_PREV() macros can be used to traverse the tree:

for (np = RB_MIN(NAME, &head); np != NULL; np = RB_NEXT(NAME, &head, np))

Or, for simplicity, one can use the RB_FOREACH() or RB_FOREACH_REVERSE() macros:

RB_FOREACH(np, NAME, &head)

The macros RB_FOREACH_SAFE() and RB_FOREACH_REVERSE_SAFE() traverse the tree referenced by head in a forward or reverse direction respectively, assigning each element in turn to np. However, unlike their unsafe counterparts, they permit both the removal of np as well as freeing it from within the loop safely without interfering with the traversal.

The RB_EMPTY() macro should be used to check whether a red-black tree is empty.

EXAMPLES

The following example demonstrates how to declare a red-black tree holding integers. Values are inserted into it and the contents of the tree are printed in order. Lastly, the internal structure of the tree is printed.

#include <sys/tree.h>
#include <err.h>
#include <stdio.h>
#include <stdlib.h>

struct node {
	RB_ENTRY(node) entry;
	int i;
};

int	intcmp(struct node *, struct node *);
void	print_tree(struct node *);

int
intcmp(struct node *e1, struct node *e2)
{
	return (e1->i < e2->i ? -1 : e1->i > e2->i);
}

RB_HEAD(inttree, node) head = RB_INITIALIZER(&head);
RB_PROTOTYPE(inttree, node, entry, intcmp)
RB_GENERATE(inttree, node, entry, intcmp)

int testdata[] = {
	20, 16, 17, 13, 3, 6, 1, 8, 2, 4, 10, 19, 5, 9, 12, 15, 18,
	7, 11, 14
};

void
print_tree(struct node *n)
{
	struct node *left, *right;

	if (n == NULL) {
		printf("nil");
		return;
	}
	left = RB_LEFT(n, entry);
	right = RB_RIGHT(n, entry);
	if (left == NULL && right == NULL)
		printf("%d", n->i);
	else {
		printf("%d(", n->i);
		print_tree(left);
		printf(",");
		print_tree(right);
		printf(")");
	}
}

int
main(void)
{
	int i;
	struct node *n;

	for (i = 0; i < sizeof(testdata) / sizeof(testdata[0]); i++) {
		if ((n = malloc(sizeof(struct node))) == NULL)
			err(1, NULL);
		n->i = testdata[i];
		RB_INSERT(inttree, &head, n);
	}

	RB_FOREACH(n, inttree, &head) {
		printf("%d\n", n->i);
	}
	print_tree(RB_ROOT(&head));
	printf("\n");
	return (0);
}

NOTES

Trying to free a tree in the following way is a common error:

SPLAY_FOREACH(var, NAME, &head) {
	SPLAY_REMOVE(NAME, &head, var);
	free(var);
}
free(head);

Since var is free'd, the FOREACH() macro refers to a pointer that may have been reallocated already. Proper code needs a second variable.

for (var = SPLAY_MIN(NAME, &head); var != NULL; var = nxt) {
	nxt = SPLAY_NEXT(NAME, &head, var);
	SPLAY_REMOVE(NAME, &head, var);
	free(var);
}
