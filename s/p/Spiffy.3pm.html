NOMBRE

Spiffy - Spiffy Perl Interface Framework For You (Marco de Interfaz Spiffy de Perl Para Ti)

SINOPSIS

package Keen;
use Spiffy -Base;
field 'mirth';
const mood => ':-)';
sub happy {
    if ($self->mood eq ':-(') {
        $self->mirth(-1);
        print "Cheer up!";
    }
    super;
}

DESCRIPCIÓN

"Spiffy" es un marco de trabajo y metodología para programar orientado a objetos (OO) en Perl. Spiffy combina las mejores partes de Exporter.pm, base.pm, mixin.pm y SUPER.pm en una única clase base mágica. Intenta corregir todos los detalles y defectos de la programación OO tradicional en Perl, de una manera limpia, directa y (quizás algún día) estándar.

Spiffy toma ideas de otros lenguajes OO como Python, Ruby, Java y Perl 6. También añade algunos trucos propios.

Si echas un vistazo a CPAN, hay un montón de módulos relacionados con OO. Al iniciar un nuevo proyecto, necesitas elegir el conjunto de módulos que tenga más sentido, y luego necesitas usar esos módulos en cada una de tus clases. Spiffy, en cambio, tiene todo lo que probablemente necesitarás en un módulo, y solo necesitas usarlo una vez en una de tus clases. Si haces de Spiffy.pm la clase base de la clase más base de tu proyecto, Spiffy pasará automáticamente toda su magia a todas tus subclases. ¡Quizás eventualmente olvides que lo estás usando!

La diferencia más llamativa entre Spiffy y otras clases base de orientación a objetos de Perl, es que tiene la capacidad de exportar cosas. Si creas una subclase de Spiffy, todas las cosas que Spiffy exporta serán exportadas automáticamente por tu subclase, además de cualquier otra cosa que quieras exportar. Y si alguien crea una subclase de tu subclase, todas esas cosas se exportarán automáticamente, y así sucesivamente. Piensa en ello como "Exportación Heredada", y utiliza la sintaxis familiar de especificación de Exporter.pm.

Para usar Spiffy o cualquier subclase de Spiffy como clase base de tu clase, especificas el argumento "-base" al comando "use".

use MySpiffyBaseModule -base;

También puedes usar la sintaxis tradicional "use base 'MySpiffyBaseModule';" y todo funcionará exactamente igual. La única advertencia es que Spiffy.pm debe estar cargado previamente. Eso es porque Spiffy redirige base.pm sobre la marcha para hacer todas las magias de Spiffy.

Spiffy tiene soporte para mixins al estilo Ruby con roles al estilo Perl6. Al igual que con "base", puedes usar cualquiera de las siguientes invocaciones:

use mixin 'MySpiffyBaseModule';
use MySpiffyBaseModule -mixin;

La segunda versión solo funcionará si la clase que se está mezclando es una subclase de Spiffy. La primera versión funcionará en todos los casos, siempre que Spiffy ya haya sido cargado.

Para limitar los métodos que se mezclan, usa roles. (Pista: funcionan igual que una lista de Exporter):

use MySpiffyBaseModule -mixin => qw(:basics x y !foo);

En Perl orientado a objetos casi todas las subrutinas son métodos. Cada método recibe el objeto pasado como su primer argumento. Eso significa que prácticamente cada subrutina comienza con la línea:

my $self = shift;

Spiffy proporciona un mecanismo de filtro simple y opcional para insertar esa línea por ti, resultando en un código más limpio. Si calculas que un método promedio tiene 10 líneas de código, ¡eso es el 10% de tu código! Para activar esta opción, simplemente usa la opción "- Base" en lugar de la opción "-base", o añade la opción "-selfless". Si el filtrado de código te da náuseas, no uses la característica. Personalmente, la encuentro adictiva en mi búsqueda por escribir código limpio, mantenible y reluciente.

Una característica útil de Spiffy es que exporta dos funciones: "field" y "const" que se pueden usar para declarar los atributos de tu clase, y generar automáticamente métodos accesores para ellos. La única diferencia entre las dos funciones es que los atributos "const" no se pueden modificar; por lo tanto, el accesorio es mucho más rápido.

Un aspecto interesante de la programación OO es cuando un método llama al mismo método de una clase padre. Esto generalmente se conoce como llamar a un método super. La facilidad de Perl para hacer esto es bastante fea:

sub cleanup {
    my $self = shift;
    $self->scrub;
    $self->SUPER::cleanup(@_);
}

Spiffy lo hace, er, súper fácil llamar a métodos super. Simplemente usa la función "super". No necesitas pasarle ningún argumento porque los pasa automáticamente. Aquí está la misma función con Spiffy:

sub cleanup {
    $self->scrub;
    super;
}

Spiffy tiene un método especial para parsear argumentos llamado "parse_arguments", que también usa para parsear sus propios argumentos. Declaras qué argumentos son booleanos (singleton) y cuáles son pares, con dos métodos especiales llamados "boolean_arguments" y "paired_arguments". Parse arguments extrae los booleanos y pares y los devuelve en un hash anónimo, seguido de una lista de los argumentos no coincidentes.

Finalmente, Spiffy puede exportar algunas funciones de depuración "WWW", "XXX", "YYY" y "ZZZ". Cada una de ellas produce un volcado de YAML de sus argumentos. WWW advierte la salida, XXX muere con la salida, YYY imprime la salida y ZZZ confiesa la salida. Si YAML no se adapta a tus necesidades, puedes cambiar todos los volcados al formato Data::Dumper con la opción "-dumper".

¡Eso es Spiffy!

EXPORTACIÓN

Spiffy implementa una idea completamente nueva en Perl. Módulos que actúan tanto como clases orientadas a objetos y que además exportan funciones. Pero lleva el concepto de Exporter.pm un paso más allá; recorre toda la ruta @ISA de una clase y respeta las especificaciones de exportación de cada módulo. Dado que Spiffy llama al módulo Exporter para hacer esto, puedes usar todas las características de interfaz sofisticadas que tiene Exporter, incluyendo etiquetas y negación.

Spiffy considera que todos los argumentos que no comienzan con un guion componen la especificación de exportación.

package Vehicle;
use Spiffy -base;
our $SERIAL_NUMBER = 0;
our @EXPORT = qw($SERIAL_NUMBER);
our @EXPORT_BASE = qw(tire horn);
package Bicycle;
use Vehicle -base, '!field';
$self->inflate(tire);

En este caso, "Bicycle->isa('Vehicle')" y también todas las cosas que "Vehicle" y "Spiffy" exportan, irán a "Bicycle", excepto "field".

La exportación puede ser muy útil cuando has diseñado un sistema con cientos de clases, y quieres que todas tengan acceso a algunas funciones o constantes

o variables. Simplemente expórtalas en tu clase base principal y cada subclase

obtendrá las funciones que necesita.

Puedes hacer casi todo lo que hace Exporter porque Spiffy delega el trabajo a Exporter (después de añadir algo de magia Spiffy). Spiffy ofrece una variable @EXPORT_BASE que es como @EXPORT, pero solo para usos que emplean "-base".

MIXINS Y ROLES

Si has hecho mucha programación OO en Perl probablemente has usado Herencia Múltiple (HM), y si has hecho mucha HM probablemente te has topado con problemas y dolores de cabeza raros. Algunos lenguajes como Ruby, intentan resolver problemas de HM usando una técnica llamada mixins. Básicamente, todas las clases de Ruby usan solo Herencia Simple (HS), y luego *mezclan* funcionalidad de otros módulos si la necesitan.

Los Mixins pueden ser pensados a un nivel simplista como *importar* los métodos de otra clase en tu subclase. Pero desde un punto de vista de implementación, esa no es la mejor manera de hacerlo. Spiffy hace lo que hace Ruby. Crea una clase anónima vacía, importa todo en esa clase, y luego encadena la nueva clase en tu cadena ISA de HS. En otras palabras, si dices:

package AAA;
use BBB -base;
use CCC -mixin;
use DDD -mixin;

Terminas con una cadena de herencia simple de clases como esta:

AAA << AAA-DDD << AAA-CCC << BBB;

MIXIN

"AAA-DDD" y "AAA-CCC" son los nombres de paquete reales de las clases generadas. Lo bueno de este estilo es que mezclar CCC no anula ningún método en AAA, y DDD no entra en conflicto con AAA ni con CCC. Si mezclaras un método en CCC que también estuviera en AAA, aún podrías acceder a él usando "super".

Cuando Spiffy mezcla CCC, extrae todos los métodos de CCC que no empiezan con un guion bajo. En realidad, va más allá. Si CCC es una subclase, extraerá todos los métodos que CCC "puede" hacer a través de la herencia. Esto es muy potente, quizás demasiado potente.

Para limitar lo que mezclas, Spiffy toma prestado el concepto de Roles de Perl6. Sin embargo, el término rol se usa de forma más flexible en Spiffy. Es muy parecido a una lista de importación que usa el módulo Exporter, y puedes usar grupos (etiquetas) y negación. Si el primer elemento de tu lista usa negación, Spiffy comenzará con todos los métodos que tu clase mixin pueda hacer.

use EEE -mixin => qw(:tools walk !run !:sharp_tools);

En este ejemplo, "walk" y "run" son métodos que EEE puede hacer, y "tools" y "sharp_tools" son roles de la clase EEE. ¿Cómo define la clase EEE estos roles? Muy simplemente, define métodos llamados "_role_tools" y "_role_sharp_tools" que devuelven listas de más métodos. (¡Y posiblemente otros roles!) Lo bueno aquí es que, dado que los roles son solo métodos, también pueden ser heredados. ¡Toma eso, Perl6!

FILTRADO

Usando el flag "-Base" en lugar de "-base", nunca necesitarás escribir la línea:

my $self = shift;

Esta instrucción se añade a cada subrutina en tu clase mediante un filtro de origen. La magia es simple y rápida, por lo que hay poca penalización de rendimiento por crear código limpio a la par con Ruby y Python.

package Example;
use Spiffy -Base;
sub crazy {
    $self->nuts;
}
sub wacky { }
sub new() {
    bless [], shift;
}

es exactamente lo mismo que:

package Example;
use Spiffy -base;
use strict;use warnings;
sub crazy {my $self = shift;
    $self->nuts;
}
sub wacky {my $self = shift; }
sub new {
    bless [], shift;
}
;1;

Observa que los paréntesis vacíos después de la subrutina "new" evitan que se le añada un $self. También observa que el código adicional se añade a las líneas existentes para asegurar que los números de línea no se alteren.

"-Base" también activa los pragmas strict y warnings, y añade esa molesta línea '1;' a tu módulo.

MÉTODOS PRIVADOS

Spiffy ahora tiene soporte para métodos privados cuando usas el mecanismo de filtrado '-Base'. Simplemente declara las subs con la palabra clave "my" y llámalas con un '$' delante. Así:

package Keen;
use SomethingSpiffy -Base;
# método público normal
sub swell {
    $self->$stinky;
}
# método léxico privado. No se puede llamar desde fuera de este archivo.
my sub stinky {
    ...
}

DEPURACIÓN SPIFFY

La función XXX es muy útil para la depuración porque puedes insertarla en casi cualquier lugar y volcará tus datos en YAML limpio y ordenado. Toma la siguiente instrucción:

my @stuff = grep { /keen/ } $self->find($a, $b);

Si tienes un problema con esta instrucción, puedes depurarla de alguna de las siguientes maneras:

XXX my @stuff = grep { /keen/ } $self->find($a, $b);
my @stuff = XXX grep { /keen/ } $self->find($a, $b);
my @stuff = grep { /keen/ } XXX $self->find($a, $b);
my @stuff = grep { /keen/ } $self->find(XXX $a, $b);

XXX es fácil de insertar y eliminar. También es una tradición marcar áreas de código dudosas con XXX. Esto hará que los volcadores de depuración sean fáciles de detectar si olvidas quitarlos.

WWW y YYY son útiles porque vuelcan sus argumentos y luego devuelven los argumentos. De esta manera puedes insertarlos en muchos lugares y aún así el código se ejecutará como antes. Usa ZZZ cuando necesites morir con un volcado YAML y un rastreo de pila completo.

Las funciones de depuración se exportan por defecto si usas la opción "-base", pero solo si previamente has usado la opción "-XXX". Para exportar las 4 funciones usa la etiqueta de exportación:

use SomeSpiffyModule ':XXX';

Para forzar que las funciones de depuración usen Data::Dumper en lugar de YAML:

use SomeSpiffyModule -dumper;

FUNCIONES SPIFFY

Esta sección describe las funciones que Spiffy exporta. Las funciones "field", "const", "stub" y "super" solo se exportan cuando usas las opciones "-base" o "-Base".

field
Define métodos accesores para un campo de tu clase: 
package Example;
use Spiffy -Base;
field 'foo';
field bar => [];
sub lalala {
    $self->foo(42);
    push @{$self->{bar}}, $self->foo;
}

El primer parámetro pasado a "field" es el nombre del atributo que se está definiendo. Los accesores pueden recibir un valor predeterminado opcional. Este valor se devolverá si no se ha establecido ningún valor para el campo en el objeto.

const
const bar => 42;

La función "const" es similar a <field> excepto que es inmutable. Tampoco almacena datos en el objeto. Probablemente siempre querrás dar un valor predeterminado a una "const", de lo contrario, el método generado será algo inútil.

stub
stub 'cigar';

La función "stub" genera un método que morirá con un mensaje apropiado. La idea es que las subclases deben implementar estos métodos para que los métodos stub no sean llamados.

super
Si esta función se llama sin argumentos, llamará al mismo método en el que se encuentra, más arriba en el árbol ISA, pasándole todos los mismos argumentos. Si se llama con argumentos, usará esos argumentos con $self al principio. En otras palabras, simplemente funciona como esperas. 
sub foo {
    super;             # Igual que $self->SUPER::foo(@_);
    super('hello');    # Igual que $self->SUPER::foo('hello');
    $self->bar(42);
}
sub new() {
    my $self = super;
    $self->init;
    return $self;
}

"super" simplemente no hará nada si no hay un método super. Finalmente, "super" hace lo correcto en los subrutinas AUTOLOAD.

MÉTODOS

Esta sección enumera todos los métodos que cualquier subclase de Spiffy hereda automáticamente.

mixin
Un método para mezclar una clase en tiempo de ejecución. Toma los mismos argumentos que "use mixin ...". Hace que la clase destino sea un mixin de la que llama. 
$self->mixin('SomeClass');
$object->mixin('SomeOtherClass' => 'some_method');
parse_arguments
Este método toma una lista de argumentos y los agrupa en pares. Permite argumentos booleanos que pueden o no tener un valor (con un valor predeterminado de 1). El método devuelve una referencia hash de todos los pares como claves y valores en el hash. Cualquier argumento que no se pueda emparejar, se devuelve como una lista. Aquí tienes un ejemplo: 
sub boolean_arguments { qw(-has_spots -is_yummy) }
sub paired_arguments { qw(-name -size) }
my ($pairs, @others) = $self->parse_arguments(
    'red', 'white',
    -name => 'Ingy',
    -has_spots =>
    -size => 'large',
    'black',
    -is_yummy => 0,
);

Después de esta llamada, $pairs contendrá:

{
    -name => 'Ingy',
    -has_spots => 1,
    -size => 'large',
    -is_yummy => 0,
}

y @others contendrá 'red', 'white', y 'black'.

boolean_arguments
Devuelve la lista de argumentos que se reconocen como booleanos. Anula este método para definir tu propia lista.
paired_arguments
Devuelve la lista de argumentos que se reconocen como emparejados. Anula este método para definir tu propia lista.

ARGUMENTOS

Cuando usas el módulo Spiffy o una subclase de él, puedes pasarle una lista de argumentos. Estos argumentos se analizan usando el método "parse_arguments" descrito anteriormente. El argumento especial "-base" se usa para hacer que el paquete actual sea una subclase del módulo Spiffy que se está utilizando.

Cualquier parámetro no emparejado actúa como una lista de importación normal; al igual que las que se usan con el módulo Exporter.

USANDO SPIFFY CON BASE.PM

La forma correcta de usar un módulo Spiffy como clase base es con el parámetro "-base" para la declaración "use". Esto difiere de los módulos típicos donde querrías "use base".

package Something;
use Spiffy::Module -base;
use base 'NonSpiffy::Module';

SINOPSIS

package Algo;

use base 'Spiffy::Module';
use base 'NonSpiffy::Module';

"use base" también es muy útil cuando tu clase no es un módulo real (un archivo separado) sino solo un paquete en algún archivo que ya ha sido cargado.

"base" funcionará ya sea que la clase sea un módulo o no, mientras que la sintaxis "base" no puede funcionar de esa manera, ya que "use" siempre intenta cargar un módulo.

base.pm Advertencias

Para que Spiffy funcione con base.pm, se jugó un truco sucio. Spiffy intercambia "base::import" con su propia versión. Si los módulos base no son Spiffy, Spiffy llama al base::import original. Si los módulos base son Spiffy, entonces Spiffy hace lo suyo.

Hay dos advertencias.

Spiffy debe cargarse primero.
Si Spiffy no está cargado y se invoca "use base" en un módulo Spiffy, Spiffy morirá con un mensaje útil indicando al autor que lea esta documentación. Esto se debe a que Spiffy necesitaba realizar el intercambio de importación de antemano.
Si obtienes este error, simplemente agrega una declaración como esta al principio de tu código:
use Spiffy ();
No mezclar
"base.pm" puede tomar múltiples argumentos. Y esto funciona con Spiffy siempre que todas las clases base sean Spiffy, o todas sean no-Spiffy. Si se mezclan, Spiffy morirá. En este caso, simplemente usa declaraciones separadas de "use base".
