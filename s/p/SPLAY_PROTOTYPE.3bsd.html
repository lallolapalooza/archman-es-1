DESCRIPCIÓN

Estas macros definen estructuras de datos para diferentes tipos de árboles: árboles splay y árboles rojo-negros.

En las definiciones de macros, TYPE es la etiqueta de nombre de una estructura definida por el usuario que debe contener un campo llamado FIELD, de tipo SPLAY_ENTRY o RB_ENTRY. El argumento HEADNAME es la etiqueta de nombre de una estructura definida por el usuario que debe declararse utilizando las macros SPLAY_HEAD() o RB_HEAD(). El argumento NAME debe ser un prefijo de nombre único para cada árbol que se defina.

Los prototipos de función se declaran con SPLAY_PROTOTYPE, RB_PROTOTYPE, o RB_PROTOTYPE_STATIC. Los cuerpos de las funciones se generan con SPLAY_GENERATE, RB_GENERATE, o RB_GENERATE_STATIC. Consulte los ejemplos a continuación para obtener más explicaciones sobre cómo se utilizan estas macros.

ÁRBOLES SPLAY

Un árbol splay es una estructura de datos autoorganizada. Cada operación en el árbol provoca un splay. El splay mueve el nodo solicitado a la raíz del árbol y lo reequilibra parcialmente.

Esto tiene el beneficio de que la localidad de las solicitudes acelera las búsquedas, ya que los nodos solicitados se mueven a la parte superior del árbol. Por otro lado, cada búsqueda provoca escrituras en memoria.

El Teorema de Balance limita el tiempo total de acceso para m operaciones y n inserciones en un árbol inicialmente vacío como O((m + n)lg n). El costo amortizado para una secuencia de m accesos a un árbol splay es O(lg n).

Un árbol splay está encabezado por una estructura definida por la macro SPLAY_HEAD(). Una estructura SPLAY_HEAD se declara de la siguiente manera:

SPLAY_HEAD(HEADNAME, TYPE) head;

donde HEADNAME es el nombre de la estructura a definir y struct TYPE es el tipo de los elementos a insertar en el árbol.

La macro SPLAY_ENTRY() declara una estructura que permite conectar elementos en el árbol.

Para usar las funciones que manipulan la estructura del árbol, sus prototipos deben declararse con la macro SPLAY_PROTOTYPE(), donde NAME es un identificador único para este árbol en particular. El argumento TYPE es el tipo de la estructura que está siendo administrada por el árbol. El argumento FIELD es el nombre del elemento definido por SPLAY_ENTRY().

Los cuerpos de las funciones se generan con la macro SPLAY_GENERATE(). Toma los mismos argumentos que la macro SPLAY_PROTOTYPE(), pero solo debe usarse una vez.

Finalmente, el argumento CMP es el nombre de una función utilizada para comparar los nodos del árbol entre sí. La función toma dos argumentos de tipo struct TYPE *. Si el primer argumento es menor que el segundo, la función devuelve un valor menor que cero. Si son iguales, la función devuelve cero. De lo contrario, debería devolver un valor mayor que cero. La función de comparación define el orden de los elementos del árbol.

La macro SPLAY_INIT() inicializa el árbol referenciado por head.

El árbol splay también puede inicializarse estáticamente utilizando la macro SPLAY_INITIALIZER() de la siguiente manera:

SPLAY_HEAD(HEADNAME, TYPE) head = SPLAY_INITIALIZER(&head);

La macro SPLAY_INSERT() inserta el nuevo elemento elm en el árbol. En caso de éxito, se devuelve NULL. Si un elemento coincidente ya existe en el árbol, la inserción se aborta y se devuelve un puntero al elemento existente.

La macro SPLAY_REMOVE() elimina el elemento elm del árbol apuntado por head. En caso de éxito, se devuelve un puntero al elemento eliminado. Se devuelve NULL si elm no está presente en el árbol.

La macro SPLAY_FIND() se puede utilizar para encontrar un elemento particular en el árbol.

struct TYPE find, *res;
find.key = 30;
res = SPLAY_FIND(NAME, &head, &find);

Las macros SPLAY_ROOT(), SPLAY_MIN(), SPLAY_MAX(), y SPLAY_NEXT() se pueden utilizar para recorrer el árbol:

for (np = SPLAY_MIN(NAME, &head); np != NULL; np = SPLAY_NEXT(NAME, &head, np))

O, para mayor simplicidad, se puede usar la macro SPLAY_FOREACH():

SPLAY_FOREACH(np, NAME, &head)

La macro SPLAY_EMPTY() debe usarse para verificar si un árbol splay está vacío.

ÁRBOLES ROJO-NEGROS

Un árbol rojo-negro es un árbol de búsqueda binario con el color del nodo como un atributo adicional. Cumple un conjunto de condiciones:

  1. cada ruta de búsqueda desde la raíz hasta una hoja consta del mismo número de nodos negros,
  2. cada nodo rojo (excepto la raíz) tiene un padre negro,
  3. cada nodo hoja es negro.

Cada operación en un árbol rojo-negro está limitada a O(lg n). La altura máxima de un árbol rojo-negro es 2lg (n+1).

Un árbol rojo-negro está encabezado por una estructura definida por la macro RB_HEAD(). Una estructura RB_HEAD se declara de la siguiente manera:

RB_HEAD(HEADNAME, TYPE) head;

donde HEADNAME es el nombre de la estructura a definir y struct TYPE es el tipo de los elementos a insertar en el árbol.

La macro RB_ENTRY() declara una estructura que permite conectar elementos en el árbol.

Para usar las funciones que manipulan la estructura del árbol, sus prototipos deben declararse con las macros RB_PROTOTYPE() o RB_PROTOTYPE_STATIC(), donde NAME es un identificador único para este árbol en particular. El argumento TYPE es el tipo de la estructura que está siendo administrada por el árbol. El argumento FIELD es el nombre del elemento definido por RB_ENTRY().

DESCRIPTION

These macros provide an implementation of splay trees. Splay trees are binary search trees that automatically keep the most frequently accessed elements at the root of the tree.

The tree implementation is generic and can hold any type of data. The user must provide the structure type, the name of the tree head, the entry field within the structure, and a comparison function.

The following macros are provided:

SPLAY_PROTOTYPE
This macro should be used in header files to declare the prototypes for the tree functions. It takes the tree name, the structure type, the name of the entry field within the structure, and the comparison function as arguments. For example: 
struct node;
RB_PROTOTYPE(NAME, TYPE, field, CMP)
This should be used in the header file that declares the structures and functions that use the tree.
SPLAY_GENERATE
This macro should be used in exactly one source file. It generates the tree functions. It takes the same arguments as SPLAY_PROTOTYPE. For example: 
RB_GENERATE(NAME, TYPE, field, CMP)
This should be placed in the source file that defines the structures and functions that use the tree.
SPLAY_HEAD
This macro declares a tree head structure. It takes the tree name and the structure type as arguments. For example: 
SPLAY_HEAD(NAME, TYPE) head;
This declares a variable named head of type struct NAME, which is the head of a splay tree of TYPE elements.
SPLAY_INIT
This macro initializes the tree pointed to by head. It should be called before any other tree operations are performed on the tree. This macro is typically used for dynamically allocated trees.
SPLAY_INITIALIZER
This macro can be used to initialize a tree statically. For example: 
SPLAY_HEAD(NAME, TYPE) head = SPLAY_INITIALIZER(&head);
This initializes the tree head head.
SPLAY_INSERT
This macro inserts the element elm into the tree pointed to by head. If an element with the same key already exists in the tree, the insertion is aborted and a pointer to the existing element is returned. Otherwise, NULL is returned.
SPLAY_REMOVE
This macro removes the element elm from the tree pointed to by head. It returns the removed element.
SPLAY_FIND
This macro finds an element in the tree with the same key as elm. It returns a pointer to the found element, or NULL if no such element is found.
SPLAY_MIN
This macro returns a pointer to the smallest element in the tree, or NULL if the tree is empty.
SPLAY_MAX
This macro returns a pointer to the largest element in the tree, or NULL if the tree is empty.
SPLAY_NEXT
This macro returns a pointer to the next element in the tree in ascending order, or NULL if elm is the largest element.
SPLAY_PREV
This macro returns a pointer to the previous element in the tree in ascending order, or NULL if elm is the smallest element.
SPLAY_ROOT
This macro returns a pointer to the root element of the tree, or NULL if the tree is empty.
SPLAY_FOREACH
This macro iterates over all elements in the tree in ascending order. The variable p is assigned each element in turn. 
SPLAY_FOREACH(p, NAME, &head) {
	/* process p */
}
This macro is unsafe if the tree is modified during iteration. Use SPLAY_FOREACH_SAFE instead.
SPLAY_FOREACH_SAFE
This macro is similar to SPLAY_FOREACH, but it is safe to modify the tree during iteration. The variable n is assigned the next element before p is processed. 
SPLAY_FOREACH_SAFE(p, NAME, &head, n) {
	/* process p */
	SPLAY_REMOVE(NAME, &head, p);
	free(p);
}
SPLAY_EMPTY
This macro returns true if the tree is empty, false otherwise.
SPLAY_LEFT
Returns the left child of the node elm.
SPLAY_RIGHT
Returns the right child of the node elm.

The CMP argument is the name of a function used to compare trees' nodes with each other. The function takes two arguments of type struct TYPE *. If the first argument is smaller than the second, the function returns a value smaller than zero. If they are equal, the function returns zero. Otherwise, it should return a value greater than zero. The compare function defines the order of the tree elements.

RED-BLACK TREES

The interface for red-black trees is identical to that of splay trees, with the exception of the macro names, which start with RB_ instead of SPLAY_.

The RB_PROTOTYPE and RB_GENERATE macros take the same arguments as their SPLAY_ counterparts. The RB_HEAD, RB_INIT, RB_INITIALIZER, RB_INSERT, RB_REMOVE, RB_FIND, RB_NFIND, RB_ROOT, RB_MIN, RB_MAX, RB_NEXT, RB_PREV, RB_FOREACH, RB_FOREACH_SAFE, RB_FOREACH_REVERSE_SAFE, and RB_EMPTY macros are also available with the RB_ prefix.

The RB_PROTOTYPE and RB_GENERATE macros should be used only once in a project, usually in a source file. The other macros can be used multiple times.

Finally, the CMP argument is the name of a function used to compare trees' nodes with each other. The function takes two arguments of type struct TYPE *. If the first argument is smaller than the second, the function returns a value smaller than zero. If they are equal, the function returns zero. Otherwise, it should return a value greater than zero. The compare function defines the order of the tree elements.

The RB_INIT() macro initializes the tree referenced by head.

The red-black tree can also be initialized statically by using the RB_INITIALIZER() macro like this:

RB_HEAD(HEADNAME, TYPE) head = RB_INITIALIZER(&head);

The RB_INSERT() macro inserts the new element elm into the tree. Upon success, NULL is returned. If a matching element already exists in the tree, the insertion is aborted, and a pointer to the existing element is returned.

The RB_REMOVE() macro removes the element elm from the tree pointed by head. RB_REMOVE() returns elm.

The RB_FIND() and RB_NFIND() macros can be used to find a particular element in the tree. RB_FIND() finds the node with the same key as elm. RB_NFIND() finds the first node greater than or equal to the search key.

struct TYPE find, *res;
find.key = 30;
res = RB_FIND(NAME, &head, &find);

The RB_ROOT(), RB_MIN(), RB_MAX(), RB_NEXT(), and RB_PREV() macros can be used to traverse the tree:

for (np = RB_MIN(NAME, &head); np != NULL; np = RB_NEXT(NAME, &head, np))

Or, for simplicity, one can use the RB_FOREACH() or RB_FOREACH_REVERSE() macros:

RB_FOREACH(np, NAME, &head)

The macros RB_FOREACH_SAFE() and RB_FOREACH_REVERSE_SAFE() traverse the tree referenced by head in a forward or reverse direction respectively, assigning each element in turn to np. However, unlike their unsafe counterparts, they permit both the removal of np as well as freeing it from within the loop safely without interfering with the traversal.

The RB_EMPTY() macro should be used to check whether a red-black tree is empty.

EXAMPLES

The following example demonstrates how to declare a red-black tree holding integers. Values are inserted into it and the contents of the tree are printed in order. Lastly, the internal structure of the tree is printed.

#include <sys/tree.h>
#include <err.h>
#include <stdio.h>
#include <stdlib.h>

struct node {
	RB_ENTRY(node) entry;
	int i;
};

int	intcmp(struct node *, struct node *);
void	print_tree(struct node *);

int
intcmp(struct node *e1, struct node *e2)
{
	return (e1->i < e2->i ? -1 : e1->i > e2->i);
}

RB_HEAD(inttree, node) head = RB_INITIALIZER(&head);
RB_PROTOTYPE(inttree, node, entry, intcmp)
RB_GENERATE(inttree, node, entry, intcmp)

int testdata[] = {
	20, 16, 17, 13, 3, 6, 1, 8, 2, 4, 10, 19, 5, 9, 12, 15, 18,
	7, 11, 14
};

void
print_tree(struct node *n)
{
	struct node *left, *right;

	if (n == NULL) {
		printf("nil");
		return;
	}
	left = RB_LEFT(n, entry);
	right = RB_RIGHT(n, entry);
	if (left == NULL && right == NULL)
		printf("%d", n->i);
	else {
		printf("%d(", n->i);
		print_tree(left);
		printf(",");
		print_tree(right);
		printf(")");
	}
}

int
main(void)
{
	int i;
	struct node *n;

	for (i = 0; i < sizeof(testdata) / sizeof(testdata[0]); i++) {
		if ((n = malloc(sizeof(struct node))) == NULL)
			err(1, NULL);
		n->i = testdata[i];
		RB_INSERT(inttree, &head, n);
	}

	RB_FOREACH(n, inttree, &head) {
		printf("%d\n", n->i);
	}
	print_tree(RB_ROOT(&head));
	printf("\n");
	return (0);
}

NOTES

Trying to free a tree in the following way is a common error:

SPLAY_FOREACH(var, NAME, &head) {
	SPLAY_REMOVE(NAME, &head, var);
	free(var);
}
free(head);

Since var is free'd, the FOREACH() macro refers to a pointer that may have been reallocated already. Proper code needs a second variable.

for (var = SPLAY_MIN(NAME, &head); var != NULL; var = nxt) {
	nxt = SPLAY_NEXT(NAME, &head, var);
	SPLAY_REMOVE(NAME, &head, var);
	free(var);
}
