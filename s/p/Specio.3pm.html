Nombre

Specio - Restricciones y coerciones para Perl

Versión

versión 0.53

Sintaxis

package MyApp::Type::Library;
use Specio::Declare;
use Specio::Library::Builtins;
declare(
    'PositiveInt',
    parent => t('Int'),
    inline => sub {
        $_[0]->parent->inline_check( $_[1] )
            . ' && ( '
            . $_[1]
            . ' > 0 )';
    },
);
# o ...
declare(
    'PositiveInt',
    parent => t('Int'),
    where  => sub { $_[0] > 0 },
);
declare(
    'ArrayRefOfPositiveInt',
    parent => t(
        'ArrayRef',
        of => t('PositiveInt'),
    ),
);
coerce(
    'ArrayRefOfPositiveInt',
    from  => t('PositiveInt'),
    using => sub { [ $_[0] ] },
);
any_can_type(
    'Duck',
    methods => [ 'duck_walk', 'quack' ],
);
object_isa_type('MyApp::Person');

Descripción

La distribución "Specio" proporciona clases para representar restricciones de tipo y coerciones, así como azúcar sintáctico para declararlas.

Nota: Este no es un sistema de tipos adecuado para Perl. Nada en esta distribución hará que el intérprete de Perl empiece a verificar el tipo de un valor al asignarlo a una variable. De hecho, no hay forma integrada de aplicar un tipo a una variable.

En su lugar, puedes verificar explícitamente un valor contra un tipo, y opcionalmente coaccionar valores a ese tipo.

¿Qué es un tipo?

Desde su núcleo, un tipo es simplemente una restricción. Una restricción es código que verifica un valor y devuelve verdadero o falso. La mayoría de las restricciones se representan mediante objetos de tipo Specio::Constraint::Simple. Sin embargo, hay otras clases de restricciones para tipos especializados.

Los tipos pueden ser nombrados o anónimos, y cada tipo puede tener un tipo padre. La restricción de un tipo es opcional ya que a veces quieres crear un subtipo nombrado de algún tipo existente sin añadir restricciones adicionales.

Las restricciones pueden ser expresadas tanto en términos de una referencia de subrutina simple como en términos de una referencia de subrutina de generador en línea. La primera es más fácil de escribir, pero la segunda es preferida porque permite una optimización mejorada.

Un tipo también puede tener una referencia opcional de subrutina de generador para mensajes. Puedes usar esto para proporcionar un mensaje más inteligente cuando un valor no pasa la restricción, aunque el mensaje por defecto debería bastar para la mayoría de los casos.

Finalmente, puedes asociar una serie de coerciones con un tipo. Una coerción es una referencia de subrutina (o generador en línea, como las restricciones), que toma un valor de un tipo y lo transforma en un valor que coincide con el tipo de la coerción.

Tipos incorporados

Esta distribución viene con un conjunto de tipos incorporados que representan los tipos proporcionados por el propio intérprete de Perl. Estos están organizados en una jerarquía así:

Item
    Bool
    Maybe (de `a)
    Undef
    Defined
        Value
            Str
                Num
                    Int
                ClassName
        Ref
            ScalarRef (de `a)
            ArrayRef (de `a)
            HashRef (de `a)
            CodeRef
            RegexpRef
            GlobRef
            FileHandle
            Object

El tipo "Item" acepta cualquier valor.

El tipo "Bool" solo acepta "undef", 0 o 1.

El tipo "Undef" solo acepta "undef".

El tipo "Defined" acepta cualquier valor, excepto "undef".

Los tipos "Num" y "Int" son más estrictos que Perl en los números. Específicamente, no aceptan espacios en el número, ni aceptan "Nan", "Inf" o "Infinity".

El tipo "ClassName" verifica que el nombre sea válido y que la clase esté cargada.

El tipo "FileHandle" acepta un globo, un archivo de entrada o cualquier cosa que sea IO::Handle.

Todos los tipos aceptan objetos sobrecargados que soporten la operación requerida. Ver detalles más abajo.

Sobrecarga

La sobrecarga de Perl está terriblemente mal implementada y no tiene mucho sentido.

Sin embargo, al igual que en Moose, todas las restricciones de tipo permiten objetos sobrecargados donde sea apropiado. Para tipos donde la sobrecarga sea útil, especificamos explícitamente que el objeto provee la sobrecarga de tipo que esperamos. No simplemente intentamos usar el objeto como el tipo en cuestión y esperar que funcione. Esto significa que estas comprobaciones efectivamente ignoran el "fallback" del objeto sobrecargado. En otras palabras, un objeto que sobrecarga la conversión a cadena no pasará la comprobación del tipo "Bool" a menos que también sobrecargue la conversión a booleano.

La mayoría de los tipos no comprueban que el método sobrecargado devuelva algo que coincida con la restricción. Esto podría cambiar en el futuro.

El tipo "Bool" acepta un objeto que implementa la sobrecarga "bool".

El tipo "Str" acepta un objeto que implementa la sobrecarga de cadena ("q{""}").

El tipo "Num" acepta un objeto que implementa la sobrecarga numérica ("'0+'}"). El tipo "Int" lo hace también, pero comprobará que la sobrecarga devuelva un entero real.

El tipo "ClassName" acepta un objeto con sobrecarga de cadena que devuelva un nombre de clase.

Para complicar las cosas, el tipo "Value" nunca acepta un objeto, aunque algunos de sus subtipos lo harán.

Los diversos tipos de referencia aceptan objetos que proporcionan la sobrecarga adecuada. Los tipos de referencia "FileHandle" aceptan un objeto que sobrecarga el globo si el globo devuelto es un archivo abierto.

Tipos parametrizables

Cualquier tipo seguido de un tipo de parámetro "of `a" en la jerarquía anterior puede ser parametrizado. El parámetro es él mismo un tipo, así que puedes decir que quieres un "ArrayRef de Int" o incluso un "ArrayRef de HashRef de ScalarRef de Clase".

Cuando son parametrizados, los tipos "ScalarRef" y "ArrayRef" verifican que los valores a los que se refieren coincidan con el parámetro del tipo. Para el tipo "HashRef", el parámetro se aplica a los valores (los índices nunca se verifican).

Maybe

El tipo "Maybe" es un tipo especial parametrizable. Permite que el valor sea "undef" o un valor. Sin embargo, por sí solo es inútil, ya que es equivalente a "Maybe de Item", que es equivalente a "Item". Cuando se parametriza, acepta "undef" o el tipo de su parámetro.

Esto es útil para atributos o parámetros opcionales. Sin embargo, probablemente sea mejor que simplemente no pases el parámetro en tu código. Esto generalmente hace que una API sea más simple.

Registros e importación

Los tipos son locales a cada paquete donde se utilizan. Cuando importas tipos de otras bibliotecas, en realidad estás haciendo una copia de ese tipo. Esto significa que un tipo llamado "Foo" en un paquete puede no ser el mismo que "Foo" en otro paquete. Esto tiene el potencial de causar confusión, pero también evita la acción mágica en
