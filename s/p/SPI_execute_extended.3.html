SPI_execute_extended(3)

Paquete: postgresql

Licencias: PostgreSQL

SPI_EXECUTE_EXTENDED(3) Documentación de PostgreSQL 18.1 SPI_EXECUTE_EXTENDED(3)

NOMBRE

SPI_execute_extended - ejecuta un comando con parámetros fuera de línea

SINOPSIS

int SPI_execute_extended(const char *command,
                         const SPIExecuteOptions * options)

DESCRIPCIÓN

SPI_execute_extended ejecuta un comando que puede incluir referencias a parámetros suministrados externamente. El texto del comando se refiere a un parámetro como $n, y el objeto options->params (si se suministra) proporciona valores e información de tipo para cada uno de dichos símbolos. Varias opciones de ejecución también se pueden especificar en la estructura options.

Normalmente, el objeto options->params debería marcar cada parámetro con la bandera PARAM_FLAG_CONST, ya que siempre se utiliza un plan único para la consulta.

Si options->dest no es NULL, las tuplas de resultado se pasan a ese objeto a medida que son generadas por el ejecutor, en lugar de acumularse en SPI_tuptable. Utilizar un objeto DestReceiver proporcionado por el llamador es particularmente útil para consultas que pueden generar muchas tuplas, ya que los datos se pueden procesar sobre la marcha en lugar de acumularse en memoria.

ARGUMENTOS

const char * command

cadena de comando

const SPIExecuteOptions * options

estructura que contiene argumentos opcionales

Los llamadores siempre deben poner a cero toda la estructura options y luego rellenar los campos que deseen establecer. Esto garantiza la compatibilidad futura del código, ya que cualquier campo que se agregue a la estructura en el futuro se definirá para comportarse de manera compatible con versiones anteriores si están a cero. Los campos de options disponibles actualmente son:

ParamListInfo params

estructura de datos que contiene tipos y valores de parámetros de consulta; NULL si no hay ninguno

bool read_only

true para ejecución de solo lectura

bool allow_nonatomic

true permite la ejecución no atómica de sentencias CALL y DO (pero este campo se ignora a menos que se haya pasado la bandera SPI_OPT_NONATOMIC a SPI_connect_ext)

bool must_return_tuples

si es true, genera un error si la consulta no es del tipo que devuelve tuplas (esto no prohíbe el caso en el que, de hecho, devuelve cero tuplas)

uint64 tcount

número máximo de filas a devolver, o 0 para ningún límite

DestReceiver * dest

objeto DestReceiver que recibirá cualquier tupla emitida por la consulta; si es NULL, las tuplas de resultado se acumulan en una estructura SPI_tuptable, como en SPI_execute

ResourceOwner owner

Este campo está presente para consistencia con SPI_execute_plan_extended, pero se ignora, ya que el plan utilizado por SPI_execute_extended nunca se guarda.

VALOR DE RETORNO

El valor de retorno es el mismo que para SPI_execute.

Cuando options->dest es NULL, SPI_processed y SPI_tuptable se establecen como en SPI_execute. Cuando options->dest no es NULL, SPI_processed se establece en cero y SPI_tuptable se establece en NULL. Si se requiere un recuento de tuplas, el objeto DestReceiver del llamador debe calcularlo.
