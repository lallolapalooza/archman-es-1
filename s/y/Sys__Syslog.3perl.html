Sys::Syslog(3perl) Guía de programación para Perl Sys::Syslog(3perl)

NOMBRE

Sys::Syslog - Interfaz Perl para las llamadas syslog(3) de UNIX

VERSIÓN

Esta es la documentación de la versión 0.36

SINOPSIS

use Sys::Syslog;                        # todas excepto setlogsock()
use Sys::Syslog qw(:standard :macros);  # funciones & macros estándar
openlog($ident, $logopt, $facility);    # ¡no olvides esto!
syslog($priority, $format, @args);
$oldmask = setlogmask($mask_priority);
closelog();

DESCRIPCIÓN

"Sys::Syslog" es una interfaz para el programa syslog(3) de UNIX. Llama a syslog() con una prioridad de cadena y una lista de argumentos printf() al igual que syslog(3).

EXPORTACIÓN

"Sys::Syslog" exporta las siguientes etiquetas de "Exporter":

  • ":standard" exporta las funciones estándar de syslog(3): 
    openlog closelog setlogmask syslog
  • ":extended" exporta las funciones específicas de Perl para syslog(3): 
    setlogsock
  • ":macros" exporta los símbolos correspondientes a la mayoría de las macros de tu syslog(3) y a las funciones LOG_UPTO() y LOG_MASK(). Véase "CONSTANTES" para las constantes admitidas y su significado.

Por defecto, "Sys::Syslog" exporta los símbolos de la etiqueta ":standard".

FUNCIONES

openlog($ident, $logopt, $facility)
Abre el syslog. $ident se antepone a cada mensaje. $logopt contiene cero o más de las opciones detalladas a continuación. $facility especifica la parte del sistema sobre la que informar, por ejemplo "LOG_USER" o "LOG_LOCAL0": véase "Instalaciones" para una lista de instalaciones conocidas, y tu documentación de syslog(3) para las instalaciones disponibles en tu sistema. Consulta "VER TAMBIÉN" para enlaces útiles. La instalación se puede proporcionar como una cadena o una macro numérica.

Esta función fallará si no puede conectarse al demonio syslog.

Ten en cuenta que openlog() ahora acepta tres argumentos, al igual que openlog(3).

Debes usar openlog() antes de llamar a syslog().

Opciones

  • "cons" - Esta opción se ignora, ya que el mecanismo de conmutación por error bajará automáticamente a la consola si todos los demás medios fallan.
  • "ndelay" - Abre la conexión inmediatamente (normalmente, la conexión se abre cuando se registra el primer mensaje).
  • "noeol" - Cuando se establece en verdadero, no se añadirá un carácter de fin de línea ("\n") al mensaje. Esto puede ser útil para algunos demonios syslog. Añadido en "Sys::Syslog" 0.29.
  • "nofatal" - Cuando se establece en verdadero, openlog() y syslog() solo emitirán advertencias en lugar de morir si no se puede establecer la conexión con el syslog. Añadido en "Sys::Syslog" 0.15.
  • "nonul" - Cuando se establece en verdadero, no se añadirá un carácter "NUL" ("\0") al mensaje. Esto puede ser útil para algunos demonios syslog. Añadido en "Sys::Syslog" 0.29.
  • "nowait" - No esperes a los procesos hijos que puedan haberse creado mientras se registraba el mensaje. (La biblioteca C de GNU no crea un proceso hijo, por lo que esta opción no tiene efecto en Linux).
  • "perror" - Escribe también el mensaje en la salida de error estándar además del registro del sistema. Añadido en "Sys::Syslog" 0.22.
  • "pid" - Incluye el PID con cada mensaje.

Ejemplos

Abre el syslog con las opciones "ndelay" y "pid", y con la instalación "LOCAL0":

openlog($name, "ndelay,pid", "local0");

Lo mismo, pero esta vez usando la macro correspondiente a "LOCAL0":

openlog($name, "ndelay,pid", LOG_LOCAL0);
syslog($priority, $message)
syslog($priority, $format, @args)
Si $priority lo permite, registra $message o "sprintf($format, @args)" con la adición de que %m en $message o $format se reemplaza por "$!" (el último mensaje de error).

$priority puede especificar un nivel, o un nivel y una instalación. Los niveles y las instalaciones se pueden proporcionar como cadenas o como macros. Al usar el mecanismo "eventlog", las prioridades "DEBUG" y "INFO" se mapean al tipo de evento "informational", "NOTICE" y "WARNING" a "warning" y "ERR" a "EMERG" a "error".

Si no usaste openlog() antes de usar syslog(), syslog() intentará adivinar el $ident extrayendo el prefijo más corto de $format que termina en dos puntos (":").

Ejemplos

# nivel informativo
syslog("info", $message);
syslog(LOG_INFO, $message);
# nivel informativo, instalación Local0
syslog("info|local0", $message);
syslog(LOG_INFO|LOG_LOCAL0, $message);
Nota
Las versiones v0.07 y anteriores de "Sys::Syslog" pasaban el $message como cadena de formato a sprintf() incluso cuando no se proporcionaban argumentos de formato. Si el código que llama a syslog() podría ejecutarse con versiones anteriores de este módulo, asegúrate de llamar a la función como "syslog($priority, "%s", $message)" en lugar de "syslog($priority, $message)". Esto protege contra secuencias de formato hostiles que podrían aparecer si $message contuviera datos contaminados.
setlogmask($mask_priority)
Establece la máscara de registro para el proceso actual en $mask_priority y devuelve la máscara antigua. Si el argumento de máscara es 0, la máscara de registro actual no se modifica. Véase "Niveles" para la lista de niveles disponibles. Puedes usar la función LOG_UPTO() para permitir todos los niveles hasta una prioridad dada (pero solo acepta las macros numéricas como argumentos).

Ejemplo

# Solo registrar mensajes de nivel ERROR o superior
my $old_mask = setlogmask(LOG_ERR);
# ... o registrar mensajes de nivel NOTICE, WARNING, ERR, CRIT, ALERT, EMERG
my $old_mask = setlogmask(LOG_UPTO(LOG_EMERG));
# restaurar la máscara antigua si es necesario
setlogmask($old_mask);
closelog()
Cierra el descriptor de archivo para el registro.
setlogsock($socktype)
Esta es una extensión de Perl de la llamada syslog(3). Permite seleccionar qué tipo de socket se utilizará para enviar mensajes syslog. Los valores posibles para $socktype son:
unix
Socket de dominio UNIX (el valor por defecto).
inet
Socket de Internet (TCP/UDP).

Si setlogsock() tiene éxito, devolverá verdadero. Si falla, devolverá falso y podrías querer examinar $!.

Si quieres usar setlogsock(), debes importarla explícitamente usando "use Sys::Syslog qw(:extended)".

Advertencia: La mayoría de las instalaciones de syslog no se configuran para escuchar en sockets de Internet. Si seleccionas "inet" y tu demonio syslog no está configurado para ello, los mensajes no se registrarán.

  • LOG_LOCAL1 - Reservado para uso local 1.

Options (para openlog())

  • LOG_CONS - Escribir en la consola si no se puede enviar.

  • LOG_NOWAIT - No esperar a los procesos hijos.

  • LOG_MASK($prio) - Crea una máscara de bits que incluye solo la prioridad especificada.

Funciones de ayuda

LOG_MASK($prio)
Crea una máscara de bits que solo incluye la prioridad especificada.
LOG_UPTO($prio)
Crea una máscara de bits que incluye todas las prioridades hasta e incluyendo la especificada.

VER TAMBIÉN

syslog(3), openlog(3), setlogmask(3), closelog(3)

DIAGNÓSTICOS

Las funciones de "Sys::Syslog" usan die() para informar de errores que impiden que el módulo funcione, como por ejemplo no poder conectarse al demonio syslog. Si se especifica la opción "nofatal" en openlog(), los errores fatales se convierten en advertencias.

ERRORES

Los errores relacionados con la transmisión de mensajes a la instalación syslog se informan como advertencias si la opción "nofatal" se ha establecido en openlog(). Si no, el módulo morirá.

No hay forma de determinar qué instalaciones están disponibles en el sistema. Si necesitas asegurarte de que la instalación que estás usando realmente existe, deberás comprobarlo tú mismo.

El soporte de "eventlog" (para Windows) no es algo que se pueda hacer con el módulo estándar Sys::Syslog. Necesitarás un módulo diferente para eso.

DESCRIPCIÓN

Este módulo proporciona una interfaz para el registro de mensajes del sistema utilizando la llamada al sistema syslog. Es una interfaz para el módulo C Sys::Syslog.

Las funciones principales son:

openlog()
Abre una conexión al registrador de mensajes del sistema.

El primer argumento, $ident, es un identificador que se antepondrá a cada mensaje registrado. Si se omite, se utiliza el nombre base del script en ejecución.

El segundo argumento, $option, es una máscara de bits que especifica las opciones a utilizar. Las opciones disponibles son:

  • "cons" - Envía mensajes a la consola además de al registro del sistema.
  • "ndelay" - Abre la conexión al registrador del sistema inmediatamente, en lugar de hacerlo a la primera llamada a syslog.
  • "nowait" - Si se utiliza "ndelay", syslog siempre devolverá inmediatamente, en lugar de esperar a que se procese el mensaje.
  • "pid" - Incluye el PID del proceso en cada mensaje.
  • "log" - Envía mensajes al archivo de registro del sistema (comportamiento predeterminado).

El tercer argumento, $facility, especifica la naturaleza del mensaje que se está registrando. Si se omite, se utiliza "user". Las instalaciones disponibles son:

  • "user"
  • "kernel"
  • "mail"
  • "daemon"
  • "auth"
  • "lpr"
  • "news"
  • "uucp"
  • "cron"
  • "authpriv"
  • "ftp"
  • "local0" a "local7"

El valor de retorno es true si la operación tuvo éxito, "undef" en caso contrario.

Ejemplos

Abrir registro con las opciones predeterminadas:

openlog('mi_programa');

Abrir registro con PID y la instalación "mail":

openlog('mi_programa', 'pid', 'mail');

Abrir registro con opciones de consola y sin espera, y la instalación "daemon":

openlog('mi_programa', 'cons,nowait', 'daemon');
syslog()
Envía un mensaje al registrador de mensajes del sistema.

El primer argumento, $priority, especifica la prioridad del mensaje. Puede ser un solo nivel de prioridad o una combinación de instalación y nivel de prioridad, separados por una barra vertical (|). Los niveles de prioridad disponibles son:

  • "emerg" (o "panic")
  • "alert"
  • "crit"
  • "err" (o "error")
  • "warning" (o "warn")
  • "notice"
  • "info"
  • "debug"

Los argumentos siguientes son una cadena de formato y sus argumentos, similar a printf.

El valor de retorno es true si la operación tuvo éxito, "undef" en caso contrario.

Ejemplos

Registrar un mensaje de información:

syslog('info', 'Este es un mensaje de información.');

Registrar un mensaje de advertencia con formato:

syslog('warning', 'El valor es %d.', $valor);

Registrar un mensaje crítico desde la instalación "mail":

syslog('mail|crit', 'Error de procesamiento de correo.');

Registrar un mensaje de depuración con el PID del proceso incluido (si "pid" se usó en openlog):

syslog('debug', 'Procesando solicitud %d', $request_id);
setlogmask()
Establece la máscara de prioridad para las llamadas futuras a syslog(). Devuelve la máscara de prioridad anterior.

La máscara de prioridad controla qué niveles de mensajes se registrarán. Solo se registrarán los mensajes cuya prioridad esté incluida en la máscara.

Ejemplos

Registrar solo errores:

setlogmask( LOG_MASK(LOG_ERR) );

Registrar todo excepto mensajes informativos:

setlogmask( ~(LOG_MASK(LOG_INFO)) );

Registrar mensajes críticos, errores y advertencias:

setlogmask( LOG_MASK(LOG_CRIT)
        | LOG_MASK(LOG_ERR)
        | LOG_MASK(LOG_WARNING) );

Registrar todos los mensajes hasta depuración:

setlogmask( LOG_UPTO(LOG_DEBUG) );
setlogsock()
Establece el tipo y las opciones del socket que se utilizarán para la próxima llamada a openlog() o syslog(). Devuelve true si tiene éxito, "undef" si falla.

Al ser específico de Perl, esta función ha evolucionado con el tiempo. Actualmente se puede llamar de la siguiente manera:

  • setlogsock($sock_type)
  • "setlogsock($sock_type, $stream_location)" (añadido en Perl 5.004_02)
  • "setlogsock($sock_type, $stream_location, $sock_timeout)" (añadido en "Sys::Syslog" 0.25)
  • setlogsock(\%options) (añadido en "Sys::Syslog" 0.28)

Las opciones disponibles son:

  • "type" - equivalente a $sock_type, selecciona el tipo de socket (o "mecanismo"). Se puede pasar una referencia a una matriz para especificar varios mecanismos a intentar, en el orden dado.
  • "path" - equivalente a $stream_location, establece la ubicación del stream. Por defecto, la ubicación estándar de Unix o "_PATH_LOG".
  • "timeout" - equivalente a $sock_timeout, establece el tiempo de espera del socket en segundos. Por defecto es 0 en todos los sistemas excepto Mac OS X, donde se establece en 0.25 segundos.
  • "host" - establece el nombre de host al que se enviarán los mensajes. Por defecto es el host local.
  • "port" - establece el puerto TCP o UDP al que conectarse. Por defecto es el primer puerto syslog estándar disponible en el sistema.

Los mecanismos disponibles son:

  • "native" - utiliza las funciones C nativas de tu biblioteca syslog(3) (añadido en "Sys::Syslog" 0.15).
  • "eventlog" - envía mensajes al registrador de eventos Win32 (solo Win32; añadido en "Sys::Syslog" 0.19).
  • "tcp" - se conecta a un socket TCP, en el servicio "syslog/tcp" o "syslogng/tcp". Ver también las opciones "host", "port" y "timeout".
  • "udp" - se conecta a un socket UDP, en el servicio "syslog/udp". Ver también las opciones "host", "port" y "timeout".
  • "inet" - se conecta a un socket INET, TCP o UDP, intentados en ese orden. Ver también las opciones "host", "port" y "timeout".
  • "unix" - se conecta a un socket de dominio Unix (en algunos sistemas a un dispositivo de caracteres especial). El nombre de dicho socket se proporciona mediante la opción "path" o, si se omite, el valor devuelto por la macro "_PATH_LOG" (si tu sistema la define), /dev/log o /dev/conslog, el que sea escribible.
  • "stream" - se conecta al stream indicado por la opción "path" o, si se omite, el valor devuelto por la macro "_PATH_LOG" (si tu sistema la define), /dev/log o /dev/conslog, el que sea escribible. Por ejemplo, los sistemas Solaris e IRIX pueden preferir "stream" en lugar de "unix".
  • "pipe" - se conecta a la tubería nombrada indicada por la opción "path" o, si se omite, al valor devuelto por la macro "_PATH_LOG" (si tu sistema la define), o /dev/log (añadido en "Sys::Syslog" 0.21). HP-UX es un sistema que utiliza una tubería nombrada de este tipo.
  • "console" - envía mensajes directamente a la consola, como para la opción "cons" de openlog().

El valor predeterminado es intentar "native", "tcp", "udp", "unix", "pipe", "stream", "console". En sistemas con la API Win32, se añadirá "eventlog" como primer mecanismo a intentar si "Win32::EventLog" está disponible.

Proporcionar un valor no válido para $sock_type provocará un "croak".

Ejemplos

Seleccionar el mecanismo de socket UDP:

setlogsock("udp");

Enviar mensajes utilizando el mecanismo de socket TCP en un puerto personalizado:

setlogsock({ type => "tcp", port => 2486 });

Enviar mensajes a un host remoto utilizando el mecanismo de socket TCP:

setlogsock({ type => "tcp", host => $loghost });

Intentar los mecanismos nativo, socket UDP y luego dominio Unix:

setlogsock(["native", "udp", "unix"]);
Nota
Ahora que el mecanismo "native" está soportado por "Sys::Syslog" y seleccionado por defecto, se desaconseja el uso de la función setlogsock() porque otros mecanismos son menos portátiles entre sistemas operativos. Se recomienda a los autores de módulos y programas que utilizan esta función, especialmente su forma de "culto a la carga" setlogsock("unix"), que eliminen cualquier ocurrencia de la misma a menos que quieran usar específicamente un mecanismo determinado (como TCP o UDP para conectarse a un host remoto).
closelog()
Cierra el archivo de registro y devuelve true si tiene éxito.

LAS REGLAS DE SYS::SYSLOG

La Primera Regla de Sys::Syslog es: No llames a setlogsock.

La Segunda Regla de Sys::Syslog es: **No** llames a setlogsock.

La Tercera Regla de Sys::Syslog es: El programa se bloquea, "die"s, llama a closelog, el registro ha terminado.

La Cuarta Regla de Sys::Syslog es: Una instalación, una prioridad.

La Quinta Regla de Sys::Syslog es: Un registro a la vez.

La Sexta Regla de Sys::Syslog es: No syslog antes de openlog.

La Séptima Regla de Sys::Syslog es: Los registros continuarán mientras sea necesario.

La Octava y Última Regla de Sys::Syslog es: Si este es tu primer uso de Sys::Syslog, debes leer la documentación.

EJEMPLOS

Un ejemplo:

openlog($program, 'cons,pid', 'user');
syslog('info', '%s', 'este es otro test');
syslog('mail|warning', 'this is a better test: %d', time);
closelog();
syslog('debug', 'this is the last test');

Otro ejemplo:

openlog("$program $$", 'ndelay', 'user');
syslog('notice', 'fooprogram: this is really done');

Ejemplo de uso de %m:

$! = 55;
syslog('info', 'problem was %m');   # %m == $! en syslog(3)

Registrar en el puerto UDP en $remotehost en lugar de registrar localmente:

setlogsock("udp", $remotehost);
openlog($program, 'ndelay', 'user');
syslog('info', 'something happened over here');
