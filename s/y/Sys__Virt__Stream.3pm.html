Sys::Virt::Stream(3pm) Documentación de Perl Contribuida por el Usuario Sys::Virt::Stream(3pm)

NOMBRE

Sys::Virt::Stream - Representar y gestionar un flujo de libvirt

DESCRIPCIÓN

El módulo "Sys::Virt::Stream" representa un flujo gestionado por el monitor de la máquina virtual.

MÉTODOS

mi $st Sys::Virt::Stream->new($conn, $flags);
Crea un nuevo flujo de datos, listo para ser utilizado con una API basada en flujos. El parámetro opcional $flags puede ser utilizado para configurar el flujo como no bloqueante.
$st->abort()
Aborta la E/S en el flujo. O esta función o "finish" debe ser llamada en cualquier flujo que haya sido activado.
$st->finish()
Completa la E/S en el flujo. O esta función o "abort" debe ser llamada en cualquier flujo que haya sido activado.
$rv = $st->recv($data, $nbytes, $flags=0)
Recibe hasta $nbytes de datos, copiándolos en $data. Devuelve el número de bytes leídos, o -3 si se alcanza un hueco y $flags contiene RECV_STOP_AT_HOLE, o -2 si la E/S se bloquearía, o -1 en caso de error. El parámetro $flags acepta las siguientes banderas:
Sys::Virt::Stream::RECV_STOP_AT_HOLE
Si esta bandera está establecida, la función "recv" dejará de leer del flujo si ha alcanzado un hueco. En ese caso, se devuelve -3 y "recv_hole" debería ser llamada para obtener el tamaño del hueco.
$rv = $st->send($data, $nbytes)
Envía hasta $nbytes de datos, copiándolos desde $data. Devuelve el número de bytes enviados, o -2 si la E/S se bloquearía, o -1 en caso de error.
$rv = $st->recv_hole($flags=0)
Determina la cantidad de espacio vacío (en bytes) a crear en el archivo de destino del flujo al subir o bajar archivos con relleno disperso. Esta es la contraparte de "send_hole". El parámetro opcional $flags actualmente no se utiliza y por defecto es cero si se omite.
$st->send_hole($length, $flags=0)
En lugar de transmitir espacio vacío del archivo, este método indica al destino del flujo que cree $length bytes de espacio vacío. Este método se utilizaría al subir o bajar archivos con relleno disperso para evitar la copia innecesaria de espacio vacío del archivo. El parámetro opcional $flags actualmente no se utiliza y por defecto es cero si se omite.
$st->recv_all($handler)
Recibe todos los datos disponibles del flujo, invocando a $handler para procesar los datos. El parámetro $handler debe ser una función que espere tres argumentos: el objeto de flujo $st, un escalar que contenga los datos recibidos y un recuento de bytes de datos. La función debería devolver el número de bytes procesados, o -1 en caso de error.
$st->send_all($handler)
Envía todos los datos producidos por $handler al flujo. El parámetro $handler debe ser una función que espere tres argumentos: el objeto de flujo $st, un escalar que debe ser llenado con datos y un recuento máximo de bytes de datos deseado. La función debería devolver el número de bytes llenados, 0 al final del archivo, o -1 en caso de error.
$st->sparse_recv_all($handler, $hole_handler)
Recibe todos los datos disponibles del flujo disperso, invocando a $handler para procesar los datos. El parámetro $handler debe ser una función que espere tres argumentos: el objeto de flujo $st, un escalar que contenga los datos recibidos y un recuento de bytes de datos. La función debería devolver el número de bytes procesados, o -1 en caso de error. El segundo argumento $hole_handler es una función que espera dos argumentos: el flujo $st y un escalar, un número que describe el tamaño del hueco en el flujo (en bytes). Se espera que $hole_handler devuelva un número no negativo en caso de éxito (generalmente 0) y un número negativo (generalmente -1) en caso contrario.
$st->sparse_send_all($handler, $hole_handler, $skip_handler)
Envía todos los datos producidos por $handler al flujo. El parámetro $handler debe ser una función que espere tres argumentos: el objeto de flujo $st, un escalar que debe ser llenado con datos y un recuento máximo de bytes de datos deseado. La función debería devolver el número de bytes llenados, 0 al final del archivo, o -1 en caso de error. El segundo argumento $hole_handler es una función que espera solo un argumento $st y devuelve una matriz de dos elementos ($in_data, $section_len) donde $in_data tiene un valor de cero o no cero si el archivo subyacente está en un hueco o en una sección de datos, respectivamente. $section_len es el número de bytes restantes en la sección actual del archivo subyacente. Finalmente, el tercer argumento $skip_handler es una función que espera dos argumentos $st y $length y que mueve el cursor en el archivo subyacente $length bytes. Se espera que $skip_handler devuelva un número no negativo en caso de éxito (generalmente 0) y un número negativo (generalmente -1) en caso contrario.
$st->add_callback($events, $coderef)
Registra una devolución de llamada para que sea invocada cada vez que el flujo tenga uno o más eventos del máscara $events establecidos. $coderef debe ser una subrutina que espere 2 parámetros: el objeto $st original y la nueva máscara de $events.
$st->update_callback($events)
Cambia la máscara de eventos para una devolución de llamada registrada previamente a $events.
$st->remove_callback();
Elimina una devolución de llamada registrada previamente.

CONSTANTES

Sys::Virt::Stream::NONBLOCK
Crea un flujo que no se bloqueará al realizar E/S.
Sys::Virt::Stream::EVENT_READABLE
El flujo tiene datos disponibles para leer sin bloquear.
Sys::Virt::Stream::EVENT_WRITABLE
El flujo tiene la capacidad de escribir datos sin bloquear.
Sys::Virt::Stream::EVENT_ERROR
Ocurrió un error en el flujo.
Sys::Virt::Stream::EVENT_HANGUP
El extremo remoto del flujo se cerró.
