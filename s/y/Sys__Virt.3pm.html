NAME

Sys::Virt - Represent and manage a libvirt hypervisor connection

SYNOPSIS

my $conn = Sys::Virt->new(uri => $uri);
my @domains = $conn->list_domains();
foreach my $dom (@domains) {
  print "Domain ", $dom->get_id, " ", $dom->get_name, "\n";
}

DESCRIPTION

El módulo Sys::Virt ofrece una ligera binding a los APIs de gestión de máquinas virtuales libvirt. Esto permite gestionar máquinas que se ejecutan dentro de contenedores virtuales arbitrarios con una API consistente.

CALLBACK HANDLING

Cada rutina de registro de callbacks devuelve un $callbackID (excepto para "domain_event_register" y "register_close_callback"). Este valor devuelto debe ser mantenido y utilizado para el desregistro de callbacks.

IMPORTANT: Todos los callbacks deben ser desregistrados (incluyendo los registrados usando "domain_event_register" y "register_close_callback"); fallar en hacerlo impide que el objeto "Sys::Virt" sea recolectado como basura y que la conexión a "libvirtd" se cierre.

ERROR HANDLING

Cualquier operación en el API de Sys::Virt que tenga escenarios de error generará una instancia de la clase Sys::Virt::Error. Para capturar estos errores, simplemente envuelva el método en un bloque eval:

eval { my $conn = Sys::Virt->new(uri => $uri); };
if ($@) {
  print STDERR "No se pudo abrir la conexión a $addr" . $@->message . "\n";
}

Para detalles del contenido de los objetos de error, consulte la página de ayuda de Sys::Virt::Error.

METHODS

my $conn = Sys::Virt->new(uri => $uri, readonly => $ro, flags => $flags);
Conectarse al host de virtualización identificado por "uri". El parámetro "uri" puede ser omitido, en cuyo caso se utilizará la conexión por defecto para el hipervisor local de Xen. Algunos ejemplos de URI incluyen:
xen:///
Kernel Xen en el equipo local
test:///default
Driver en memoria dummy para test suites
qemu:///system
Driver global para QEMU / KVM virtualización
qemu:///session
Driver por usuario para QEMU virtualización
qemu+tls://somehost/system
Driver global para QEMU en "somehost" usando seguridad TLS
xen+tcp://somehost/
Driver Xen en "somehost" usando seguridad TCP / SASL

Para más detalles, consulte "http://libvirt.org/uri.html"

Si el parámetro opcional "readonly" se proporciona, se intentará una conexión no privilegiada al hipervisor. Si no se proporciona, se utilizará por defecto una conexión completamente privilegiada. Si el aplicación que llama no está corriendo con root, puede ser necesario proporcionar callbacks de autenticación.

Si el parámetro opcional "auth" se establece en un valor no cero, se habilitará la autenticación durante la conexión usando los callbacks de autenticación por defecto. Los callbacks por defecto piden credenciales en la consola, por lo que no son adecuados para aplicaciones gráficas. Para aplicaciones gráficas, debe proporcionar un implementación personalizada. El parámetro "credlist" debe ser un arreglo de referencias a objetos de tipo credencial que se soportan. Los valores de las constantes de credencial en este módulo pueden usarse como valores en este arreglo. El parámetro "callback" debe ser una referencia a una función que reciba los datos necesarios para recoger las credenciales. Cuando se invoca, se le pasará un único parámetro, un arreglo de credenciales solicitadas. Los elementos del arreglo son referencias a objetos de tipo credencial, con claves "type" que indican el tipo de credencial, "prompt" que da un mensaje de usuario descriptivo, y "challenge" que da el nombre de la credencial requerida. El resultado debe ser obtenido del usuario y devuelto estableciendo la clave "result". Esta clave puede ya estar establecida con un resultado predeterminado si aplica.

Como ejemplo simple, devolviendo credenciales fijas:

my $uri  = "qemu+tcp://192.168.122.1/system";
my $username = "test";
my $password = "123456";
my $con = Sys::Virt->new(uri => $uri,
                         auth => 1,
                         credlist => [
                           Sys::Virt::CRED_AUTHNAME,
                           Sys::Virt::CRED_PASSPHRASE,
                         ],
                         callback =>
     sub {
           my $creds = shift;
           foreach my $cred (@{$creds}) {
              if ($cred->{type} == Sys::Virt::CRED_AUTHNAME) {
                  $cred->{result} = $username;
              }
              if ($cred->{type} == Sys::Virt::CRED_PASSPHRASE) {
                  $cred->{result} = $password;
              }
           }
           return 0;
     });

Para compatibilidad con versiones anteriores, el parámetro "address" se acepta como un símbolo equivalente al parámetro "uri". La utilización del parámetro "uri" se recomienda para todos los nuevos códigos escritos.

Se asignará el mismo número de páginas en cada nodo NUMA en el rango $start a $end inclusive. El parámetro $flags acepta dos constantes
Sys::Virt::NODE_ALLOC_PAGES_ADD
El número de páginas solicitadas se añadirá a la reserva de páginas enormes existente.
Sys::Virt::NODE_ALLOC_PAGES_SET
La reserva de páginas enormes se establecerá exactamente en el número solicitado

NAME

Sys::Virt - Perl interface to libvirt

SYNOPSIS

 use Sys::Virt;

 my $conn = Sys::Virt->new(URI => 'qemu:///system')
   or die "Failed to connect to hypervisor\n";

 my @domains = $conn->listDomains;
 foreach my $domain (@domains) {
   printf "Domain '%s' is %s\n",
     $domain->getName,
     $domain->isAlive ? 'alive' : 'shut off';
 }

 my $dom = $conn->lookupDomainByName('my-vm');
 if ($dom) {
   $dom->create;
 }

DESCRIPTION

This module provides a Perl API for interacting with the libvirt virtualization management library. It allows Perl programs to manage virtual machines, storage, and networks, as well as query host system information.

CALLBACK HANDLING

Libvirt uses callbacks to notify the application about events such as domain status changes, connection closures, or media being inserted/removed. The Sys::Virt module allows you to register Perl subroutines as callbacks.

When registering a callback, you must pass a coderef and optionally an opaque pointer (data) which will be passed to the coderef when the callback is invoked.

Callbacks are invoked synchronously. This means that the libvirt event loop will not proceed until the callback has returned. Be careful not to perform long-running operations within a callback, as this can block the event loop and lead to degraded performance or timeouts.

The following callback types are supported:

domain-callback
Called when a domain's state changes (e.g. started, stopped, paused).
network-callback
Called when a virtual network's state changes.
storagepool-callback
Called when a storage pool's state changes.
nwfilter-callback
Called when a network filter's state changes.
secret-callback
Called when a secret's state changes.
nodedev-callback
Called when a node device's state changes.
stream-callback
Called when data is available on a stream or the stream is closed.
connect-close-callback
Called when the connection to the hypervisor is closed.
connect-domain-event-callback
Called for various domain-related events.

ERROR HANDLING

The Sys::Virt module uses standard Perl error handling. Most methods will return an undefined value or an empty list on failure, and set $@ to a Sys::Virt::Error object. You can use die or warn on $@ to check for errors.

Alternatively, you can use the setErrnoHandler method to register a custom error handler subroutine.
