Syntax::Keyword::Try(3pm) Documentación de Contribución de Usuarios de Perl Syntax::Keyword::Try(3pm)

NOMBRE

"Syntax::Keyword::Try" - una sintaxis de "try/catch/finally" para perl

SINOPSIS

use Syntax::Keyword::Try;
sub foo {
   try {
      attempt_a_thing();
      return "success";
   }
   catch ($e) {
      warn "It failed - $e";
      return "failure";
   }
}

DESCRIPCIÓN

Este módulo proporciona un plugin de sintaxis que implementa semánticas de manejo de excepciones en un formato familiar para los usuarios de otros lenguajes, basado en un bloque etiquetado con la palabra clave "try", seguido de al menos un bloque "catch" o "finally".

Además de proporcionar una sintaxis útil para este comportamiento, este módulo también sirve para contener varios ejemplos de código sobre cómo implementar plugins de análisis sintáctico y manipular árboles de opciones para proporcionar nueva sintaxis y comportamientos al código perl.

Una sintaxis similar a la de este módulo ahora se ha agregado al núcleo de perl, a partir de la versión 5.34.0. Si está escribiendo código nuevo, se recomienda que en su lugar utilice el módulo Feature::Compat::Try, ya que habilitará la función principal en esas versiones de perl compatibles, recurriendo a "Syntax::Keyword::Try" en versiones de perl anteriores.

CARACTERÍSTICAS EXPERIMENTALES

Algunas de las características de este módulo están actualmente marcadas como experimentales. Provocarán advertencias en la categoría "experimental", a menos que se silencien.

Puede silenciar esto con "no warnings 'experimental'", pero eso silenciará todas las advertencias experimentales, lo que podría ocultar otras involuntariamente. Para un enfoque más detallado, puede usar la línea de importación de este módulo para silenciar selectivamente solo las advertencias de este módulo:

use Syntax::Keyword::Try qw( try :experimental(typed) );
use Syntax::Keyword::Try qw( try :experimental );  # todo lo anterior

No olvide importar el símbolo principal "try" en sí, para activar la sintaxis.

PALABRAS CLAVE

try

try {
   SENTENCIAS...
}
...

Una declaración "try" proporciona el cuerpo principal del código que se invocará y debe ir seguida de una declaración "catch", una declaración "finally", o ambas.

La ejecución de la declaración "try" en sí comienza desde el bloque dado a la declaración y continúa hasta que lanza una excepción o se completa exitosamente al llegar al final del bloque. Lo que suceda a continuación dependerá de la presencia de una declaración "catch" o "finally" inmediatamente después.

El cuerpo de un bloque "try {}" puede contener una expresión "return". Si se ejecuta, dicha expresión hará que la función contenedora completa devuelva el valor proporcionado. Esto es diferente de un bloque simple "eval {}", en cuyo caso solo "eval" devolvería, no la función completa.

El cuerpo de un bloque "try {}" puede contener expresiones de control de bucle ("redo", "next", "last") que tendrán su efecto habitual en cualquier bucle del que forme parte el bloque "try {}".

Las reglas de análisis para el conjunto de sentencias (el bloque "try" y su asociado "catch" y "finally") son tales que se analizan como una sentencia autocontenida. Debido a esto, no es necesario terminar con un punto y coma.

Aunque se analiza como una sentencia y no como una expresión, un bloque "try" aún puede producir un valor si aparece como la última sentencia en su bloque "sub" o "do" contenedor. Por ejemplo:

my $result = do {
   try { attempt_func() }
   catch ($e) { "Fallback Value" }
};

Tenga en cuenta (especialmente para los usuarios de Try::Tiny y similares) que el bloque "try {}" en sí mismo no necesariamente detiene las excepciones lanzadas dentro de él de propagarse hacia afuera. Es la presencia de un bloque posterior "catch {}" lo que hace que esto suceda. Un "try" con solo un "finally" y sin "catch" aún propagará las excepciones a los llamadores como de costumbre.

catch

...
catch ($var) {
   SENTENCIAS...
}

o

...
catch {
   SENTENCIAS...
}

Una declaración "catch" proporciona un bloque de código a la declaración "try" anterior que se invocará en caso de que el bloque principal de código lance una excepción. Opcionalmente, se puede proporcionar una nueva variable léxica para almacenar la excepción. Si no se proporciona, el bloque "catch" puede inspeccionar la excepción lanzada mirando en $@ en su lugar.

La presencia de esta declaración "catch" hace que cualquier excepción lanzada por el bloque "try" anterior no sea fatal para el código circundante. Si el bloque "catch" desea manejar opcionalmente algunas excepciones pero no otras, puede volver a lanzarla (o lanzar otra excepción) llamando a "die" de la manera habitual.

Al igual que con "try", el cuerpo de un bloque "catch {}" también puede contener una expresión "return", que como antes, tiene su significado habitual, haciendo que la función contenedora completa devuelva el valor dado. El cuerpo también puede contener expresiones de control de bucles ("redo", "next" o "last") que también tienen su efecto habitual.

Si no se proporciona una declaración "catch", entonces cualquier excepción lanzada por el bloque "try" se lanzará al llamador de la manera habitual.

catch (Tipado)

...
catch ($var isa Class) { ... }
...
catch ($var =~ m/^Regexp match/) { ... }

Experimental; desde la versión 0.15.

Opcionalmente, se pueden proporcionar múltiples declaraciones catch, donde a cada bloque se le da una condición de guardado, para controlar si atrapará o no valores de excepción particulares. El uso de esta sintaxis provocará una advertencia de la categoría "experimental" en versiones de perl compatibles, a menos que se silencie importando la etiqueta :experimental(typed) (ver arriba).

Se admiten dos tipos de condición:

  • catch ($var isa Class)

    El bloque se invoca solo si la excepción capturada es un objeto bendecido y deriva del nombre del paquete dado.

    En la versión 5.32 de Perl y posteriores, esta prueba de condición se implementa utilizando el mismo tipo de op que proporciona la sintaxis principal "$var isa Class" y funciona exactamente de la misma manera.

    En versiones anteriores de perl, se emula mediante una función de compatibilidad. Actualmente, esta función no respeta una sobrecarga del método "->isa" en la instancia de excepción. Por lo general, esto no debería ser un problema, ya que los tipos de clase de excepción rara vez proporcionan dicho método.

  • catch ($var =~ m/regexp/)

    El bloque se invoca solo si la excepción capturada es una cadena que coincide con el regexp dado.

Cuando se captura una excepción, cada condición se prueba en el orden en que están escritas, hasta que se encuentra un caso coincidente.

FINALLY

...
finally {
   STATEMENTS...
}

Una declaración "finally" proporciona un bloque de código que se ejecutará independientemente de si el bloque "try" anterior se completó con éxito, lanzó una excepción, o si un bloque "catch" manejó una excepción o no.

Si el bloque "try" (o un bloque "catch") contiene una expresión "return", "redo", "next" o "last", el bloque "finally" aún se ejecutará antes de que el control pase de la sentencia try/catch/finally completa.

En el caso de que se lance una excepción dentro del bloque "try", el bloque "finally" se ejecutará, y luego la excepción se relanzará (a menos que un bloque "catch" hubiera manejado la excepción y no la hubiera relanzado).

Por el contrario, si el bloque "try" se completa normalmente, o si un bloque "catch" se ejecuta y luego se sale de la estructura completa mediante una declaración "return", entonces el bloque "finally" se ejecutará, y luego se ejecutará la propia declaración de salida.

TRY, CATCH, Y FINALLY

Esta sintaxis está basada en el módulo Try::Tiny de CPAN, pero implementada como una característica nativa del analizador léxico de Perl. En versiones de Perl anteriores a la 5.34.0, se accede a esta sintaxis a través de la siguiente directiva:

    use Syntax::Keyword::Try;

A partir de la versión 5.34.0 de Perl, esta sintaxis está disponible mediante la siguiente directiva:

    use feature 'try';

En ambos casos, la sintaxis básica se presenta como un bloque de código que puede ser seguido opcionalmente por uno o más bloques catch y un bloque finally opcional.

    try {
        STATEMENTS...
    }
    catch (...) {
        STATEMENTS...
    }
    catch (...) {
        STATEMENTS...
    }
    finally {
        STATEMENTS...
    }

El bloque try se ejecuta primero. Si se lanza una excepción dentro del bloque try y coincide con la condición de un bloque catch, se invoca ese bloque catch correspondiente y no se prueba ninguna otra condición. Si no se encuentra ningún bloque catch coincidente y hay un bloque default (incondicional) al final, se invoca este último. Si no existe tal bloque, la excepción se propaga al ámbito de llamada.

finally

...
finally {
   STATEMENTS...
}

Una sentencia "finally" proporciona un bloque de código a la sentencia "try" precedente (o par "try/catch") que se ejecuta después, tanto en caso de ejecución normal como de excepción lanzada. Este bloque de código puede usarse para proporcionar cualquier operación de limpieza que pueda ser requerida por el código anterior.

Debido a que se ejecuta durante una operación de limpieza de pila, un bloque "finally {}" no puede provocar que la función que lo contiene retorne, ni alterar el valor de retorno de la misma. Tampoco puede ver la matriz de argumentos @_ de la función que lo contiene (aunque, al tener ámbito de bloque dentro de la función, seguirá compartiendo cualquier variable léxica normal declarada hasta ese momento). Está protegido de perturbar el valor de $@. Si el código del bloque "finally {}" lanza una excepción, esta se imprimirá como una advertencia y se descartará, dejando en $@ la excepción original, si existía.

OTROS MÓDULOS

Ya existen bastantes módulos en CPAN que proporcionan una sintaxis similar a "try/catch" para Perl.

  • Try
  • TryCatch
  • Try::Tiny
  • Syntax::Feature::Try

Además, el propio núcleo de perl incorporó una sintaxis "try/catch" basada en este módulo a partir de la versión 5.34.0. Está disponible como "use feature 'try'".

Se comparan aquí, por característica:

Plugin de sintaxis real

Al igual que Try y Syntax::Feature::Try, este módulo se implementa como un plugin de sintaxis real, lo que le permite proporcionar nuevas reglas de análisis sintáctico no disponibles para funciones simples. Lo más notable aquí es que la combinación resultante no necesita terminar con un punto y coma.

La característica principal "feature 'try'" también se implementa como sintaxis nativa real en el analizador de Perl.

En comparación, Try::Tiny es perl puro y proporciona su funcionalidad utilizando funciones regulares de Perl; como tal, su sintaxis requiere el punto y coma final.

TryCatch es un híbrido que utiliza Devel::Declare para analizar el árbol de sintaxis.

@_ en un bloque try o catch

Debido a que el código del bloque "try" y "catch" está contenido en un bloque real en lugar de una subrutina anónima completa, invocarlo no interfiere con la matriz de argumentos @_. El código dentro de estos bloques puede interactuar con la matriz de la función que lo contiene como antes.

Esta característica es única entre estos módulos; ninguno de los otros listados tiene esta capacidad.

La característica principal "feature 'try'" también se comporta de esta manera.

"return" en un bloque try o catch

Al igual que TryCatch y Syntax::Feature::Try, la sentencia "return" tiene su efecto habitual dentro de una subrutina que contiene la sintaxis proporcionada por este módulo. Es decir, hace que la "sub" que lo contiene retorne.

También se comporta de esta manera utilizando la característica principal "feature 'try'".

En comparación, el uso de Try o Try::Tiny significa que una sentencia "return" solo saldrá del bloque "try".

"next"/"last"/"redo" en un bloque try o catch

Las palabras clave de control de bucle "next", "last" y "redo" tienen su efecto habitual en los bucles contenidos dinámicamente.

Estos también funcionan bien al usar la característica principal "feature 'try'".

Syntax::Feature::Try documenta que estos no funcionan allí. Los otros módulos no hacen ninguna declaración al respecto.

Semántica de Valor

Al igual que Try y Syntax::Feature::Try, la sintaxis proporcionada por este módulo solo funciona como una sentencia a nivel de sintaxis y no como una expresión. No se puede asignar el resultado de un bloque "try". Una solución común es envolver la sentencia "try/catch" dentro de un bloque "do", donde su expresión final puede ser capturada y utilizada como un valor.

El mismo envoltorio de bloque "do" también funciona para la característica principal "feature 'try'".

En comparación, el comportamiento implementado por Try::Tiny puede usarse como una expresión con valor, como la asignación a una variable o el retorno al llamador de la función que lo contiene.

"try" sin "catch"

Al igual que Syntax::Feature::Try, la sintaxis proporcionada por este módulo permite que un bloque "try" sea seguido solo por un bloque "finally", sin "catch". En este caso, las excepciones lanzadas por el código contenido en el "try" no se suprimen, sino que se propagan normalmente a los llamadores. Esto coincide con el comportamiento familiar para los programadores de Java o C++.

En comparación, el código proporcionado por Try y Try::Tiny siempre suprime la propagación de excepciones incluso sin un bloque "catch" real.

El módulo TryCatch no permite un bloque "try" no seguido por "catch".

La característica principal "feature 'try'" no implementa "finally" en absoluto, y también requiere que cada bloque "try" sea seguido por un "catch".

"catch" Tipado

Try y Try::Tiny no intentan realizar ningún tipo de despacho tipado para distinguir tipos de excepciones capturadas por bloques "catch".

Del mismo modo, la característica principal "feature 'try'" actualmente no proporciona esta capacidad, aunque sigue siendo un área de trabajo de diseño en curso.

TryCatch y Syntax::Feature::Try intentan proporcionar una especie de despacho tipado donde diferentes clases de excepciones son capturadas por diferentes bloques de código, o propagadas completamente a los llamadores.

Este módulo proporciona tal capacidad, a través de la sintaxis actualmente experimental "catch (VAR cond...)".

Los pensamientos de diseño continúan en el ticket de RT https://rt.cpan.org/Ticket/Display.html?id=123918.

CON OTROS MÓDULOS

Future::AsyncAwait

A partir de la versión 0.10 de "Future::AsyncAwait" y la versión 0.07 de Syntax::Keyword::Try, las pruebas de integración entre módulos afirman que los bloques básicos "try/catch" dentro de una "async sub" funcionan correctamente, incluyendo aquellos que intentan "return" desde dentro de "try".

use Future::AsyncAwait;
use Syntax::Keyword::Try;
async sub attempt
{
   try {
      await func();
      return "success";
   }
   catch {
      return "failed";
   }
}

PROBLEMAS

La seguridad de hilos en el momento de la carga no puede asegurarse antes de perl 5.16

En las versiones perl 5.16 y superiores, este módulo es seguro para hilos.

En la versión perl 5.14, este módulo es seguro para hilos siempre que se invoque "use" antes de que se creen hilos adicionales.

Sin embargo, al usar 5.14, existe una condición de carrera si este módulo se carga tarde en el inicio del programa, después de que se hayan creado hilos adicionales. Esto lleva a la posibilidad de que se inicie varias veces de forma concurrente, lo que crea condiciones de carrera al modificar estructuras internas y probablemente conduce a un error de segmentación, ya sea durante la carga o poco después, cuando se compila más código.

Como solución alternativa, para cualquier programa de este tipo que cree múltiples hilos, cargue código adicional (como plugins descubiertos dinámicamente) y deba ejecutarse en 5.14, debe asegurarse de

use Syntax::Keyword::Try;

temprano en el inicio, antes de que genere hilos adicionales.

(Ver también https://rt.cpan.org/Public/Bug/Display.html?id=123547)

$@ no se localiza mediante "try do" antes de perl 5.24
