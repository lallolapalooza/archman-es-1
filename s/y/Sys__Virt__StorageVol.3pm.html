NOMBRE

Sys::Virt::StorageVol - Representar y gestionar un volumen de almacenamiento de libvirt

DESCRIPCIÓN

El módulo "Sys::Virt::StorageVol" representa un volumen de almacenamiento gestionado por libvirt. Un volumen de almacenamiento siempre está asociado a un contenedor de almacenamiento ("Sys::Virt::StoragePool").

MÉTODOS

mi $nombre = $vol->get_name()
Devuelve una cadena con un nombre único local del volumen de almacenamiento
mi $nombre = $vol->get_key()
Devuelve una cadena con una clave única global del volumen de almacenamiento
mi $nombre = $vol->get_path()
Devuelve una cadena con una ruta de archivo única local del volumen de almacenamiento
mi $xml = $vol->get_xml_description()
Devuelve un documento XML que contiene una descripción completa de la configuración del volumen de almacenamiento
$vol->delete($flags)
Elimina inmediatamente el volumen de almacenamiento, liberando sus recursos de almacenamiento. El parámetro "flags" indica cualquier acción especial a realizar al eliminar el volumen.
$vol->resize($newcapacity, $flags=0)
Modifica el tamaño del volumen de almacenamiento. El valor $newcapacity tiene su significado dependiendo del parámetro $flags. Si $flags especifica "RESIZE_DELTA", el $newcapacity es relativo al tamaño actual. Si $flags especifica "RESIZE_SHRINK", el valor $newcapacity es el espacio a eliminar
$vol->wipe($flags = 0)
Limpia los datos del volumen de almacenamiento para evitar la pérdida de información futura. El parámetro "flags" no se usa actualmente y se comporta como 0.
$vol->wipe_pattern($algorithm, $flags = 0)
Limpia los datos del volumen de almacenamiento para evitar la pérdida de información futura. El parámetro $algorithm especifica el patrón de datos utilizado para borrar los datos, y debe ser una de las CONSTANTES de PATRÓN DE BORRADO mencionadas más adelante. El parámetro "flags" no se usa actualmente y se comporta como 0.
mi $info = $vol->get_info($flags = 0)
Obtiene información en tiempo real del volumen de almacenamiento. El valor $info es una referencia a un hash que contiene tres claves. "type" indica si el volumen es un archivo o un dispositivo de bloque. "capacity" proporciona el tamaño lógico máximo del volumen. "allocation" proporciona el uso físico actual del volumen. La asignación puede ser menor que el tamaño de capacidad para volúmenes dispersos (sparse), o puede crecer bajo demanda. La asignación también puede ser mayor que el tamaño de capacidad, si hay un sobredimensionamiento de metadatos para el formato del volumen. El parámetro $flags puede tomar uno de los siguientes valores:
Sys::Virt::StorageVol::USE_ALLOCATION
Devuelve el tamaño de asignación actual
Sys::Virt::StorageVol::GET_PHYSICAL
Devuelve el tamaño físico en asignación
$vol->download($st, $offset, $length, $flags=0);
Descarga datos desde $vol usando el flujo $st. Si $offset y $length no son cero, restringe los datos a la región de bytes especificada del volumen de almacenamiento. El parámetro $flags acepta los siguientes valores:
Sys::Virt::StorageVol::VOL_DOWNLOAD_SPARSE_STREAM
Si este flag está establecido en @flags, se permite la transmisión de agujeros. Esto asume que se está utilizando el flujo $st con la combinación de "sparse_recv_all" o "recv($flags = VIR_STREAM_RECV_STOP_AT_HOLE)" para aceptar los agujeros enviados por el servidor.
$vol->upload($st, $offset, $length, $flags=0);
Sube datos a $vol usando el flujo $st. Si $offset y $length no son cero, restringe los datos a la región de bytes especificada del volumen de almacenamiento. El parámetro $flags acepta los siguientes valores:
Sys::Virt::StorageVol::VOL_UPLOAD_SPARSE_STREAM
Si este flag está establecido en $flags, se permite la transmisión de agujeros. Esto asume que se está utilizando el flujo $st con la combinación de "sparse_send_all" o "send_hole" para preservar la esparsidad de la fuente de archivos.

Sys::Virt::StorageVol(3pm)

NAME

Sys::Virt::StorageVol - Interface to libvirt storage volumes

DESCRIPTION

This module provides an object-oriented interface to the libvirt storage volume API.

A storage volume is a virtual disk image file, block device, logical volume, etc, that can be attached to a virtual machine. Storage volumes are created within storage pools.

METHODS

The following methods are available on a Sys::Virt::StorageVol object:

StorageVol()
Constructor, used internally by Sys::Virt::StoragePool methods.
StoragePool()
Return the Sys::Virt::StoragePool object that this volume belongs to.
Name()
Return the name of the storage volume.
Path()
Return the path to the storage volume.
Key()
Return the unique key (UUID) of the storage volume.
UUID()
Return the UUID of the storage volume.
Disk()
Return the disk information for the volume, suitable for use in a virtual machine domain XML configuration.
Info()
Return a hash containing information about the storage volume:
  • domain: The number of active domains using this volume.
  • allocation: The amount of allocated space for this volume (in bytes).
  • capacity: The maximum capacity of this volume (in bytes).
  • physical: The amount of physical space used by this volume (in bytes).
Resize($capacity, $flags)
Resize the storage volume to the specified capacity. The $flags argument is optional and can be a combination of the VOLUME_RESIZE_* constants. See below.
Delete($flags)
Delete the storage volume. The $flags argument is optional and can be a combination of the VOLUME_DELETE_* constants. See below.
Wipe($flags)
Wipe the storage volume, securely erasing all data. The $flags argument is optional and can be a combination of the VOLUME_WIPE_* constants. See below.

CONSTANTS

The following constants are available for use with the methods above:

DELETE CONSTANTS

Sys::Virt::StorageVol::DELETE_ZEROED
Zero out current allocated blocks when deleting the volume
Sys::Virt::StorageVol::DELETE_WITH_SNAPSHOTS
Delete snapshots associated with the volume

WIPE ALGORITHM CONSTANTS

The following constants specify the algorithm for erasing data

Sys::Virt::StorageVol::WIPE_ALG_BSI
9-pass method recommended by the German Center of Security in Information Technologies
Sys::Virt::StorageVol::WIPE_ALG_DOD
4-pass Dod 5220.22-M section, 8-306 procedure
Sys::Virt::StorageVol::WIPE_ALG_GUTMANN
The canonical 35-pass sequence
Sys::Virt::StorageVol::WIPE_ALG_NNSA
4-pass NNSA Policy Letter NAP-14.1-C (XVI-8)
Sys::Virt::StorageVol::WIPE_ALG_PFITZNER7
7-pass random
Sys::Virt::StorageVol::WIPE_ALG_PFITZNER33
33-pass random
Sys::Virt::StorageVol::WIPE_ALG_RANDOM
1-pass random
Sys::Virt::StorageVol::WIPE_ALG_SCHNEIER
7-pass method described by Bruce Schneier in "Applied Cryptography" (1996)
Sys::Virt::StorageVol::WIPE_ALG_ZERO
1-pass, all zeroes
Sys::Virt::StorageVol::WIPE_ALG_TRIM
1-pass, trim all data on the volume by using TRIM or DISCARD

VOLUME RESIZE CONSTANTS

The following constants control how storage volumes can be resized

Sys::Virt::StorageVol::RESIZE_ALLOCATE
Fully allocate the extra space required during resize
Sys::Virt::StorageVol::RESIZE_DELTA
Treat the new capacity as a delta to the current capacity
Sys::Virt::StorageVol::RESIZE_SHRINK
Treat the new capacity as an amount to remove from the capacity
