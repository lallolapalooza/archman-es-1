NOMBRE

Sub::HandlesVia::Manual::WithMoo - usando Sub::HandlesVia con Moo

SINOPSIS

package Kitchen {
  use Moo;
  use Sub::HandlesVia;
  use Types::Standard qw( ArrayRef Str );

  has food => (
    is          => 'ro',
    isa         => ArrayRef[Str],
    handles_via => 'Array',
    default     => sub { [] },
    handles     => {
      'add_food'    => 'push',
      'find_food'   => 'grep',
    },
  );
}

MANUAL

Sub::HandlesVia permite delegar métodos de tu clase a los valores de los atributos de tus objetos.

Conceptualmente, te permite definir "$object->push_number($n)" como un acceso directo para "$object->numbers->push($n)" excepto que "$object->numbers" es un arrayref, por lo que no tiene métodos que puedas llamar sobre él como "push".

Deberías poder usar Sub::HandlesVia como un reemplazo directo para MooX::HandlesVia, que proporciona una característica similar, aunque tiene una implementación más limitada. Sub::HandlesVia respeta las restricciones de tipo, además de que puede mutar valores no de referencia.

¿Qué métodos se pueden delegar?

La opción "handles_via" indica qué biblioteca de métodos debería estar disponible. Los valores válidos incluyen Array, Blessed, Bool, Code, Counter, Enum, Hash, Number, Scalar y String.

Se puede proporcionar un arrayref para "handles_via", aunque muchas de las opciones son conceptualmente contradictorias.

handles_via => [ 'Number', 'Scalar' ]

Posibles errores de orden de carga

A diferencia de Moose, Moo no ofrece realmente mucha API para extensiones. Como resultado, la mayoría de los módulos que proporcionan extensiones lo hacen envolviendo las palabras clave de Moo (especialmente "has"). Sub::HandlesVia no es una excepción a esto. Si estás utilizando múltiples extensiones de Moo, puede que necesites ajustar el orden en que las importas ("use") para que funcionen correctamente juntas. En algunas combinaciones, ¡puede que no haya un orden que funcione completamente!

Algunos módulos conocidos que deben importarse *antes* de Sub::HandlesVia si los estás usando: MooX::Should.

Algunos módulos conocidos que deben importarse *después* de Sub::HandlesVia si los estás usando: MooX::ProtectedAttributes.

Algunos módulos conocidos que entran en conflicto con Sub::HandlesVia: ¡ninguno hasta ahora!
