NOMBRE

Sub::Exporter::Tutorial - una guía amigable para exportar con Sub::Exporter

VERSIÓN

versión 0.991

DESCRIPCIÓN

¿Qué es un Exportador?

Cuando "usas" un módulo, primero se requiere, y luego se llama a su método "import". La documentación de Perl nos dice que las dos líneas siguientes son equivalentes:

use Module LIST;
BEGIN { require Module; Module->import(LIST); }

El método llamado "import" es el exportador del módulo, exporta funciones y variables al espacio de nombres de su llamador.

Los Fundamentos de Sub::Exporter

Sub::Exporter construye un exportador personalizado que luego puede ser instalado en tu módulo. Construye este método basándose en la configuración pasada a su método "setup_exporter".

Un caso de uso muy básico podría verse así:

package Addition;
use Sub::Exporter;
Sub::Exporter::setup_exporter({ exports => [ qw(plus) ]});
sub plus { my ($x, $y) = @_; return $x + $y; }

Esto significaría que cuando alguien usara tu módulo Addition, podría tener su rutina "plus" importada en su paquete:

use Addition qw(plus);
my $z = plus(2, 2); # esto funciona, porque ahora plus está en el paquete principal

La sintaxis para configurar el exportador, arriba, es un poco verbosa, así que para el caso simple de solo nombrar algunas exportaciones, puedes escribir esto:

use Sub::Exporter -setup => { exports => [ qw(plus) ] };

...lo cual es lo mismo que el ejemplo original -- excepto que ahora el exportador se construye e instala en tiempo de compilación. Bueno, y que escribiste menos.

Usando Grupos de Exportación

Puedes especificar grupos enteros de cosas que deberían ser exportables juntas. Estos se llaman grupos. El exportador los llama etiquetas. Para especificar grupos, simplemente pasa una clave "groups" en la configuración de tu exportador:

package Food;
use Sub::Exporter -setup => {
  exports => [ qw(apple banana beef fluff lox rabbit) ],
  groups  => {
    fauna  => [ qw(beef lox rabbit) ],
    flora  => [ qw(apple banana) ],
  }
};

Ahora, para importar toda esa deliciosa carne extranjera, tu consumidor solo necesita escribir:

use Food qw(:fauna);
use Food qw(-fauna);

Cualquiera de las dos opciones anteriores es aceptable. Un dos puntos es más tradicional, pero las palabras desnudas con un dos puntos inicial no pueden ser entrecomilladas por una flecha gorda. Veremos por qué eso importa más adelante.

Los grupos pueden contener otros grupos. Si incluyes un nombre de grupo (con el guion o dos puntos inicial) en una definición de grupo, se expandirá recursivamente cuando se llame al exportador. El exportador **no** se recursará en el mismo grupo dos veces mientras expande grupos.

Hay dos grupos especiales: "all" y "default". El grupo "all" está definido para ti y contiene todas las subs exportables. Puedes redefinirlo, si quieres exportar solo un subconjunto cuando se solicitan todas las exportaciones. El grupo "default" es el conjunto de rutinas a exportar cuando no se solicita nada específico. Por defecto, no hay grupo "default".

Renombrando Tus Importaciones

A veces quieres importar algo, pero no te gusta el nombre con el que se importa. Sub::Exporter puede renombrar tus importaciones por ti. Si quisieras importar "lox" del paquete Food, pero no te gusta el nombre, podrías escribir esto:

use Food lox => { -as => 'salmon' };

Ahora obtendrías la rutina "lox", pero se llamaría salmon en tu paquete. También puedes renombrar grupos enteros usando la opción "prefix":

use Food -fauna => { -prefix => 'cute_little_' };

Ahora puedes llamar a tu rutina "cute_little_rabbit". (También puedes llamar "cute_little_beef", pero eso apenas parece tan atractivo).

Cuando defines grupos, puedes incluir renombramientos.

use Sub::Exporter -setup => {
  exports => [ qw(apple banana beef fluff lox rabbit) ],
  groups  => {
    fauna  => [ qw(beef lox), rabbit => { -as => 'coney' } ],
  }
};

Un prefijo en un grupo como ese hace lo correcto. Aquí es cuando es útil usar un guion en lugar de dos puntos para indicar un grupo: puedes poner una flecha gorda entre el grupo y sus argumentos, entonces.

use Food -fauna => { -prefix => 'lovely_' };
eat( lovely_coney ); # esto funciona

Los prefijos también se aplican recursivamente. Eso significa que este código funciona:

use Sub::Exporter -setup => {
  exports => [ qw(apple banana beef fluff lox rabbit) ],
  groups  => {
    fauna   => [ qw(beef lox), rabbit => { -as => 'coney' } ],
    allowed => [ -fauna => { -prefix => 'willing_' }, 'banana' ],
  }
};
...
use Food -allowed => { -prefix => 'any_' };
$dinner = any_willing_coney; # ¡mmm!

Los grupos también pueden recibir un argumento "-suffix".

Finalmente, si el argumento "-as" para una rutina exportada es una referencia a un escalar, una referencia a la rutina se colocará en ese escalar.

Construyendo Subrutinas a Medida

A veces, quieres exportar cosas que no tienes a mano. Podrías querer ofrecer rutinas personalizadas construidas según las especificaciones de tu consumidor; ¡eso es solo un buen negocio! Con Sub::Exporter, esto es fácil.

Para ofrecer subrutinas a medida, necesitas proporcionar un generador cuando configures tu exportador. Un generador es solo una rutina que devuelve una nueva rutina. perlref habla de estas cuando discute las clausuras y las plantillas de funciones. El ejemplo canónico de un generador construye un incrementador único; aquí te mostramos cómo harías eso con Sub::Exporter;

package Package::Counter;
use Sub::Exporter -setup => {
  exports => [ counter => sub { my $i = 0; sub { $i++ } } ],
  groups  => { default => [ qw(counter) ] },
};

Ahora cualquiera puede usar tu módulo Package::Counter y recibirá un "counter" en su paquete. Contará hacia arriba de uno en uno, y nunca interferirá con el contador de nadie más.

Esto no es muy útil, sin embargo, a menos que el consumidor pueda explicar lo que quiere. Esto se hace, en parte, proporcionando argumentos al importar. El siguiente ejemplo muestra cómo un generador puede tomar y usar argumentos:

package Package::Counter;
sub _build_counter {
  my ($class, $name, $arg) = @_;
  $arg ||= {};
  my $i = $arg->{start} || 0;
  return sub { $i++ };
}
use Sub::Exporter -setup => {
  exports => [ counter => \'_build_counter' ],
  groups  => { default => [ qw(counter) ] },
};

Ahora, el consumidor puede (si quiere) especificar un valor inicial para su contador:

use Package::Counter counter => { start => 10 };

Los argumentos para un grupo se pasan a los generadores de rutinas en ese grupo, pero los argumentos de Sub::Exporter —cualquier cosa que comience con un guion— nunca se pasan. Cuando los grupos están anidados, los argumentos se fusionan a medida que se expanden los grupos.

Observa también que, en el ejemplo anterior, dimos una referencia al *nombre* de un método en lugar de a la *implementación* de un método. Al dar el nombre en lugar de la subrutina, hacemos posible que las subclases de nuestro módulo "Package::Counter" reemplacen el método "_build_counter".

Cuando se llama a un generador, se le pasan cuatro parámetros:

  • el invocante sobre el cual se llamó al exportador
  • el nombre de la exportación que se está generando (no el nombre con el que se está instalando)
  • los argumentos proporcionados para la rutina
  • la colección de argumentos genéricos

El cuarto elemento es la última característica importante que no se ha cubierto.

NAME

Sub::Exporter::Tutorial - A tutorial for Sub::Exporter

VERSION

0.991

DESCRIPTION

This is a tutorial for Sub::Exporter. You probably want to see the full documentation.

This tutorial will cover how to use Sub::Exporter to export routines.

Exports

The simplest case is exporting a few routines:

    package MyModule
    use Sub::Exporter -setup => {
        exports => [ qw(foo bar baz) ],
    };
    sub foo { ... }
    sub bar { ... }
    sub baz { ... }

This will export subroutines named foo, bar, and baz. When a user writes:

    use MyModule qw(foo bar);

...the routines foo and bar will be available to the user.

You can also provide names for the exported routines:

    package MyModule
    use Sub::Exporter -setup => {
        exports => {
            FOO => 'foo',
            BAR => 'bar',
            BAZ => 'baz',
        },
    };
    sub foo { ... }
    sub bar { ... }
    sub baz { ... }

Now, a user can write:

    use MyModule FOO BAR;

...and get the foo and bar subroutines, but they will be called FOO and BAR in the user's package.

You can also use generators for exports. Generators are subroutines that create other subroutines. They are passed the usual import arguments, and must return a hashref of name to code reference.

    package MyModule
    use Sub::Exporter -setup => {
        exports => [ \&generate_foo, \&generate_bar ],
    };
    sub generate_foo {
        my ($consumer_package, $arg_hash_ref, $call_site_export_list) = @_;
        return { FOO => sub { print "foo\n" } };
    }
    sub generate_bar {
        my ($consumer_package, $arg_hash_ref, $call_site_export_list) = @_;
        return { BAR => sub { print "bar\n" } };
    }

Now, a user can write:

    use MyModule;

...and get the FOO and BAR subroutines.

If you want to provide arguments to the generators, you can do so:

    package MyModule
    use Sub::Exporter -setup => {
        exports => [ \&generate_foo ],
    };
    sub generate_foo {
        my ($consumer_package, $arg_hash_ref, $call_site_export_list) = @_;
        my $text = delete $arg_hash_ref->{text} || 'default';
        return {
            FOO => sub { print "$text\n" },
        };
    }

Now, a user can write:

    use MyModule generate_foo => { text => 'hello' };

...and get a subroutine named FOO that prints "hello".

Groups

Groups allow you to export multiple routines at once. They are defined similarly to exports, but they return a hashref of names to routines, or a list of names.

    package MyModule
    use Sub::Exporter -setup => {
        groups => {
            DEFAULT => [ qw(foo bar) ],
            ALL     => [ qw(foo bar baz qux) ],
        },
    };
    sub foo { ... }
    sub bar { ... }
    sub baz { ... }
    sub qux { ... }

Now, a user can write:

    use MyModule;

...which is equivalent to:

    use MyModule DEFAULT;

...which exports foo and bar. Or they can write:

    use MyModule ALL;

...which exports foo, bar, baz, and qux.

You can also use generators for groups. These generators are passed all the usual data, and must return a hashref of names to routines.

    package MyModule
    use Sub::Exporter -setup => {
        groups => {
            DEFAULT => \&generate_default_group,
            ALL     => [ qw(foo bar baz qux) ],
        },
    };
    sub generate_default_group {
        my ($consumer_package, $arg_hash_ref, $call_site_export_list) = @_;
        return {
            FOO => sub { print "foo\n" },
            BAR => sub { print "bar\n" },
        };
    }

Now, use MyModule; will export FOO and BAR.

Generators for groups can also take arguments:

    package MyModule
    use Sub::Exporter -setup => {
        groups => {
            DEFAULT => \&generate_default_group,
        },
    };
    sub generate_default_group {
        my ($consumer_package, $arg_hash_ref, $call_site_export_list) = @_;
        my $prefix = delete $arg_hash_ref->{prefix} || '';
        return {
            FOO => sub { print "${prefix}foo\n" },
            BAR => sub { print "${prefix}bar\n" },
        };
    }

Now, a user can write:

    use MyModule DEFAULT => { prefix => 'X-' };

...and get FOO and BAR that print "X-foo\n" and "X-bar\n" respectively.

You can also use "-prefix" and "-suffix" arguments to modify the names of exported routines:

    package MyModule
    use Sub::Exporter -setup => {
        groups => {
            DEFAULT => [ qw(foo bar) ],
        },
    };
    sub foo { ... }
    sub bar { ... }

Now, a user can write:

    use MyModule DEFAULT => -prefix => 'X-';

...and get routines named X-foo and X-bar.

Argument Collectors

Sometimes you will want to accept arguments once that can then be available to any subroutine that you're going to export. To do this, you specify collectors, like this:

package Menu::Airline
use Sub::Exporter -setup => {
  exports =>  ... ,
  groups  =>  ... ,
  collectors => [ qw(allergies ethics) ],
};

Collectors look like normal exports in the import call, but they don't do anything but collect data which can later be passed to generators. If the module was used like this:

use Menu::Airline allergies => [ qw(peanuts) ], ethics => [ qw(vegan) ];

...the consumer would get a salad. Also, all the generators would be passed, as their fourth argument, something like this:

{ allerges => [ qw(peanuts) ], ethics => [ qw(vegan) ] }

Generators may have arguments in their definition, as well. These must be code refs that perform validation of the collected values. They are passed the collection value and may return true or false. If they return false, the exporter will throw an exception.

Generating Many Routines in One Scope

Sometimes it's useful to have multiple routines generated in one scope. This way they can share lexical data which is otherwise unavailable. To do this, you can supply a generator for a group which returns a hashref of names and code references. This generator is passed all the usual data, and the group may receive the usual "-prefix" or "-suffix" arguments.
