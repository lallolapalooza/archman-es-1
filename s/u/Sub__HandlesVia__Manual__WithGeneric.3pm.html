Sub::HandlesVia::Manual::WithGeneric(3) Documentación Perl aportada por el usuario Sub::HandlesVia::Manual::WithGeneric(3)

NOMBRE

Sub::HandlesVia::Manual::WithGeneric - usar Sub::HandlesVia con clases Perl genéricas

MANUAL

Sub::HandlesVia te permite delegar métodos de tu clase a los valores de los atributos de tus objetos.

Conceptualmente, te permite definir que "$objeto->push_numero($n)" sea un atajo para "$objeto->numeros->push($n)", excepto que "$objeto->numeros" es un arrayref, por lo que no tiene métodos que puedas llamar sobre él como "push".

Para Moose y Mouse, Sub::HandlesVia puede usar sus protocolos de metaobjetos para obtener la definición de un atributo e instalar los métodos que necesita. Para Moo, puede envolver "has" y hacer sus cosas de esa manera. Para otras clases, necesitas ser más explícito y decirle qué métodos delegar a qué atributos.

package Cocina {

  # constructor
  sub new {
    my ( $class, %arg ) = @_;
    $arg{comida} ||= [];
    return bless( \%arg, $class );
  }

  # getter/setter para `comida`
  sub comida {
    (@_ == 1) ? $_[0]{comida} : ( $_[0]{comida} = $_[1] );
  }

  use Sub::HandlesVia qw( delegaciones );

  delegaciones(
    atributo   => 'comida'
    maneja_via => 'Array',
    maneja     => {
      'agregar_comida'    => 'push',
      'buscar_comida'   => 'grep',
    },
  );
}

Establecer "atributo" a "comida" significa que cuando Sub::HandlesVia necesite obtener la lista de comida, llamará a "$cocina->comida" y cuando necesite establecer la lista de comida, llamará a "$cocina->comida($valor)". Si tienes métodos getter y setter separados, simplemente haz:

atributo   => [ 'obtener_comida', 'establecer_comida' ],

O si no tienes ningún accesor y quieres que Sub::HandlesVia acceda directamente al hashref subyacente:

atributo   => '{comida}',

O tal vez tienes un setter, pero quieres usar acceso a hashref para el getter:

atributo   => [ '{comida}', 'establecer_comida' ],

O tal vez todavía quieres acceso directo para el getter, pero tu objeto es un arrayref bendecido en lugar de un hashref bendecido:

atributo   => [ '[7]', 'establecer_comida' ],

O tal vez tus necesidades son locamente únicas:

atributo   => [ \&getter, \&setter ],

Los coderefs reciben la instancia como su primer argumento, y el setter también recibe un valor para establecer.

¡Realmente, no creo que haya ningún sistema de objetos para el que esto no funcione!

Si proporcionas un arrayref con un getter y un setter, también es posible proporcionar un tercer argumento que sea un coderef o una cadena que se llamará como método si se necesita "restablecer" el valor. Esto puede pensarse como un valor predeterminado o un constructor.

(La función "delegaciones" también se puede importar en clases Moo/Mouse/Moose, en cuyo caso el "atributo" debe ser el mismo nombre de atributo que pasaste a "has". No puedes usar un arrayref, coderef, clave de hash o índice de array.)
