NOMBRE

Sub::HandlesVia::Manual::Advanced - documentación avanzada miscelánea

MANUAL

La siguiente información se aplica independientemente de la herramienta OO que estés utilizando.

Encadenamiento de métodos

Supongamos que tienes lo siguiente

handles_via => 'Array',
handles     => {
  'add_food'    => 'push',
  'find_food'   => 'grep',
  'remove_food' => 'pop',
},

Ahora "$kitchen->remove_food" eliminará el último alimento de la lista y lo devolverá. ¿Pero qué pasa si no nos importa qué alimento se eliminó? Solo queremos eliminar el alimento y descartarlo. Puedes hacer esto:

handles_via => 'Array',
handles     => {
  'add_food'    => 'push',
  'find_food'   => 'grep',
  'remove_food' => 'pop...',
},

Ahora el método "remove_food" devolverá el objeto cocina en lugar de devolver el alimento. Esto lo hace adecuado para encadenar llamadas a métodos:

# elimina los tres alimentos más recientes
$kitchen->remove_food->remove_food->remove_food;

Delegar a CodeRefs

Puedes delegar a coderefs:

handles_via => 'Array',
handles    => {
  'find_healthiest' => sub { my $foods = shift; ... },
}

Delegar a Métodos Nombrados

La biblioteca de manejadores Sub::HandlesVia::HandlerLibrary::Blessed permite delegar a métodos nombrados de un objeto bendecido.

isa         => InstanceOf['HTTP::Tiny'],
handles_via => 'Blessed',
handles     => {
  'http_get'   => 'get',
  'http_post'  => 'post',
},

Sin embargo, en Moo, Moose, Mouse y Mite, este tipo de delegación está incorporado, ¡así que ni siquiera necesitas Sub::HandlesVia!

isa         => InstanceOf['HTTP::Tiny'],
handles     => {
  'http_get'   => 'get',
  'http_post'  => 'post',
},

Aun así, la biblioteca de manejadores Sub::HandlesVia::HandlerLibrary::Blessed puede seguir siendo útil si deseas utilizar otras características de Sub::HandlesVia como el encadenamiento, o si estás utilizando otra herramienta OO.

Un ejemplo de combinación de delegación a métodos nombrados con delegación de estilo "rasgo nativo"... digamos que "FoodList" es una clase donde las instancias son referencias a arrays bendecidas de cadenas.

isa         => InstanceOf['FoodList'],
handles_via => 'Array', 'Blessed',
handles     => {
  'find_food'             => 'grep',
  'find_healthiest_food'  => 'find_healthiest',
},

Ahora "$kitchen->find_food($coderef)" hace esto (lo que rompe la encapsulación ):

my @result = grep $coderef->(), @{ $kitchen->food };

Pero como "find_healthiest" no es uno de los métodos que ofrece Sub::HandlesVia::HandlerList::Array, Sub::HandlesVia asume que quieres llamarlo en la referencia a array como un método apropiado, así que "$kitchen->find_healthiest_food" hace esto:

$kitchen->food->find_healthiest

Puede ser útil ser explícito sobre qué métodos deseas delegar a un array de estilo "rasgo nativo" y cuáles son métodos nombrados que se llamarán en un objeto bendecido:

isa         => InstanceOf['FoodList'],
handles_via => [ 'Array', 'Blessed' ],
handles     => {
  'find_food'             => 'Array->grep',
  'find_healthiest_food'  => 'Blessed->find_healthiest',
},

Ver "Delegar a Múltiples Bibliotecas de Manejadores".

Argumentos Currificados

Toda esta charla de comida me da hambre, pero por mucho que me gustaría comerme un curry ahora mismo, ese no es el tipo de currificación del que estamos hablando.

handles_via => 'Array',
handles     => {
  'get_food'   => 'get',
},

"$kitchen->get_food(0)" devolverá el primer elemento de la lista. "$kitchen->get_food(1)" devolverá el segundo elemento de la lista. Y así sucesivamente.

handles_via => 'Array',
handles     => {
  'first_food'   => [ 'get' => 0 ],
  'second_food'  => [ 'get' => 1 ],
},

Creo que ya sabes qué hace esto. ¿Verdad?

Y sí, la currificación funciona con coderefs.

handles_via => 'Array',
handles     => {
  'blargy'       => [ sub { ... }, @curried ],
},

Comprobación de Argumentos más Flexible

Sub::HandlesVia intenta ser estricto por defecto. Por ejemplo, si tu atributo especifica "isa => ArrayRef[Int]", entonces tu método que delega a "push" comprobará que sus argumentos son enteros.

Puedes indicarle que sea menos riguroso al comprobar los argumentos del método usando el prefijo "~":

handles_via => 'Array',
handles     => {
  'find_food'   => '~grep',
},

Delegar a Múltiples Bibliotecas de Manejadores

A veces puedes desear elegir métodos para delegar de múltiples bibliotecas de manejadores. Esto es posible estableciendo "handles_via" a un arrayref.

isa         => ArrayRef|HashRef,
handles_via => [ 'Array', 'Hash' ],
handles     => {
  the_keys     => 'keys',
  ship_shape   => 'sort_in_place',
}

Aquí tienes un atributo que podría ser un arrayref o un hashref. Cuando es un arrayref, "$object->ship_shape" funcionará bien, pero "$object->the_keys" fallará estrepitosamente.

Aun así, este tipo de cosas *pueden* tener cierto sentido si tienes un objeto que sobrecarga tanto "@{}" como "%{}".

En particular, la biblioteca Sub::HandlesVia::HandlerLibrary::Scalar a menudo tiene sentido combinarla con otras bibliotecas porque las cadenas, enteros, números, booleanos e incluso arrayrefs, hashrefs y coderefs, son todos escalares.

A veces, un nombre de método será ambiguo. Por ejemplo, hay un método "get" tanto para hashes como para arrays. En este caso, ganará el de array porque lo listaste primero en "handles_via".

Pero puedes ser específico:

isa         => ArrayRef|HashRef,
handles_via => [ 'Array', 'Hash' ],
handles     => {
  get_by_index => 'Array->get',
  get_by_key   => 'Hash->get',
}
