Paquete: perl-sub-uplevel

Licencias: GPL, PerlArtistic

Sub::Uplevel(3) Documentación de Perl aportada por el usuario Sub::Uplevel(3)

NOMBRE

Sub::Uplevel - aparentemente ejecuta una función en un marco de pila superior

VERSIÓN

versión 0.2800

SINOPSIS

use Sub::Uplevel;
sub foo {
    print join " - ", caller;
}
sub bar {
    uplevel 1, \&foo;
}
#linea 11
bar();    # principal - foo.plx - 11

DESCRIPCIÓN

Al igual que la función uplevel() de Tcl, pero no tan peligrosa. La idea es simplemente engañar a caller(). Todas las partes realmente traviesas de uplevel() de Tcl se evitan.

ESTO NO ES ALGO QUE QUIERAS HACER TODOS LOS DÍAS

uplevel
uplevel $num_frames, \&func, @args;

Hace que la función dada piense que se está ejecutando $num_frames niveles más arriba que el nivel de pila actual. Así, cuando usen caller($frames) en realidad darán caller($frames + $num_frames) para ellos.

"uplevel(1, \&some_func, @_)" es efectivamente "goto &some_func" pero no sales inmediatamente de la subrutina actual. Así que, mientras que no puedes hacer esto:

sub wrapper {
    print "Antes\n";
    goto &some_func;
    print "Después\n";
}

puedes hacer esto:

sub wrapper {
    print "Antes\n";
    my @salida = uplevel 1, &some_func;
    print "Después\n";
    return @salida;
}

"uplevel" tiene la capacidad de emitir una advertencia si $num_frames es mayor que la profundidad actual de la pila de llamadas, aunque esta advertencia está deshabilitada y compilada por defecto ya que la verificación es relativamente costosa.

Para habilitar la verificación para depuración o pruebas, debes establecer el global $Sub::Uplevel::CHECK_FRAMES a verdadero antes de cargar Sub::Uplevel por primera vez de la siguiente manera:

#!/usr/bin/perl

BEGIN {
    $Sub::Uplevel::CHECK_FRAMES = 1;
}
use Sub::Uplevel;

Establecer o cambiar el global después de que el módulo haya sido cargado no tendrá ningún efecto.

EJEMPLO

La razón principal por la que escribí este módulo es para poder escribir envoltorios alrededor de funciones y que no fueran conscientes de que han sido envueltas.

use Sub::Uplevel;
my $original_foo = \&foo;
*foo = sub {
    my @output = uplevel 1, $original_foo;
    print "foo() devolvió:  @output";
    return @output;
};

Si este código te asusta, no deberías usar este módulo.

ERRORES y ADVERTENCIAS

Bueno, la mala noticia es que uplevel() es aproximadamente 5 veces más lento que una llamada a función normal. ¿Implementación XS, alguien? También ralentiza cada invocación de caller(), independientemente de si uplevel() está en efecto.

Sub::Uplevel anula temporalmente CORE::GLOBAL::caller durante el alcance de cada llamada a uplevel. Hace todo lo posible para funcionar con cualquier CORE::GLOBAL::caller existente previamente (tanto cuando Sub::Uplevel se carga por primera vez como dentro de cada llamada a uplevel), como desde Contextual::Return o Hook::LexWrap.

Sin embargo, si usas rutinariamente varios módulos que anulan CORE::GLOBAL::caller, probablemente estés pidiendo problemas.

Deberías cargar Sub::Uplevel lo antes posible dentro de tu programa. Como con toda sobrecarga de CORE::GLOBAL, la sobrecarga no afectará a los módulos que ya se hayan compilado antes de la sobrecarga. Un módulo que a menudo se carga inevitablemente antes que Sub::Uplevel es Exporter. Para recompilar forzosamente Exporter (y Exporter::Heavy) después de cargar Sub::Uplevel, úsalo con la etiqueta ":aggressive":

use Sub::Uplevel qw/:aggressive/;

La función privada Sub::Uplevel::_force_reload() puede recibir una lista de módulos adicionales para recargar si ":aggressive" no es lo suficientemente agresivo. Recargar módulos puede romper cosas, así que solo usa esto como último recurso.

A partir de la versión 0.20, Sub::Uplevel requiere Perl 5.6 o superior.
