Sub::Exporter(3) Documentación de Contribución de Usuarios de Perl Sub::Exporter(3)

NOMBRE

Sub::Exporter - un exportador sofisticado para rutinas creadas a medida

VERSIÓN

versión 0.991

SINOPSIS

Sub::Exporter debe usarse en dos lugares. Primero, en un módulo que exporta:

# en el módulo que exporta:
package Text::Tweaker;
use Sub::Exporter -setup => {
  exports => [
    qw(squish titlecase), # siempre funciona igual
    reformat => \&build_reformatter, # generador para construir la función exportada
    trim     => \&build_trimmer,
    indent   => \&build_indenter,
  ],
  collectors => [ 'defaults' ],
};

Luego, en un módulo que importa:

# en el módulo que importa:
use Text::Tweaker
  'squish',
  indent   => { margin => 5 },
  reformat => { width => 79, justify => 'full', -as => 'prettify_text' },
  defaults => { eol => 'CRLF' };

Con esta configuración, el módulo importador termina con tres rutinas: "squish", "indent" y "prettify_text". Las dos últimas han sido construidas según las especificaciones del importador, no son solo copias del código del paquete que exporta.

DESCRIPCIÓN

¡ATENCIÓN! Si no estás familiarizado con Exporter o la exportación, ¡lee primero Sub::Exporter::Tutorial!

¿Por qué Generadores?

El mayor beneficio de Sub::Exporter sobre los exportadores existentes (incluyendo el ubicuo Exporter.pm) es su capacidad para construir nuevos coderefs para exportar, en lugar de simplemente exportar código idéntico al encontrado en el paquete que exporta.

Si los consumidores del módulo obtienen una rutina que funciona así:

use Data::Analyze qw(analyze);
my $value = analyze($data, $tolerance, $passes);

y constantemente pasan solo uno o dos conjuntos de valores diferentes para los argumentos que no son $data, tu código puede beneficiarse de Sub::Exporter. Escribiendo un simple generador, puedes permitirles hacer esto en su lugar:

use Data::Analyze
  analyze => { tolerance => 0.10, passes => 10, -as => analyze10 },
  analyze => { tolerance => 0.15, passes => 50, -as => analyze50 };
my $value = analyze10($data);

El paquete con el generador para eso se vería algo así:

package Data::Analyze;
use Sub::Exporter -setup => {
  exports => [
    analyze => \&build_analyzer,
  ],
};
sub build_analyzer {
  my ($class, $name, $arg) = @_;
  return sub {
    my $data      = shift;
    my $tolerance = shift || $arg->{tolerance};
    my $passes    = shift || $arg->{passes};
    analyze($data, $tolerance, $passes);
  }
}

El usuario de tu módulo ahora tiene que hacer menos trabajo para beneficiarse de ello, y recuerda, ¡a menudo eres tu propio usuario! Invertir en subrutinas personalizadas es una inversión en pereza futura.

Esto también evita una forma común de fealdad vista en muchos módulos: la configuración a nivel de paquete. Es decir, podrías haber visto algo como lo anterior implementado así:

use Data::Analyze qw(analyze);
$Data::Analyze::default_tolerance = 0.10;
$Data::Analyze::default_passes    = 10;

Esto puede ahorrar tiempo hasta que tengas varios módulos usando Data::Analyze. Como solo hay una configuración global, se pisan unos a otros y tu código comienza a tener errores misteriosos.

Los generadores también pueden permitirte exportar métodos de clase para ser llamados como subrutinas:

package Data::Methodical;
use Sub::Exporter -setup => { exports => { some_method => \&_curry_class } };
sub _curry_class {
  my ($class, $name) = @_;
  return sub { $class->$name(@_); };
}

Debido a la forma en que funcionan los exportadores y Sub::Exporter, cualquier paquete que herede de Data::Methodical puede heredar su exportador y anular su "some_method". Si un usuario importa "some_method" de ese paquete, recibirá una subrutina que llama al método en la subclase, en lugar de en Data::Methodical mismo. Ten en cuenta que si reconfiguras Sub::Exporter en un paquete que hereda de Data::Methodical, por supuesto, reemplazarás por completo el exportador de Data::Methodical. "import" es un método y está oculto por los mismos medios que cualquier otro método.

Otras Personalizaciones

Construir rutinas personalizadas con generadores no es la única forma en que Sub::Exporter permite al código importador refinar su uso de las rutinas exportadas. También pueden ser renombradas para evitar colisiones de nombres.

Considera el siguiente código:

# este programa determina a qué círculo del infierno serás condenado
use Morality qw(sin virtue); # para calcular la maldad
use Math::Trig qw(:all);     # para tratar con círculos

El programador ha importado inadvertidamente dos rutinas "sin". La solución, en módulos basados en Exporter.pm, sería importar solo una y luego llamar a la otra por su nombre completamente calificado. Alternativamente, el importador podría escribir una rutina que hiciera eso, o podría jugar con los typeglobs.

Mucho más fácil de escribir:

# este programa determina a qué círculo del infierno serás condenado
use Morality qw(virtue), sin => { -as => 'offense' };
use Math::Trig -all => { -prefix => 'trig_' };

y tener a disposición "offense" y "trig_sin", por no mencionar "trig_cos" y "trig_tan".

CONFIGURACIÓN DEL EXPORTADOR

Puedes configurar un exportador para tu paquete usando Sub::Exporter de esta manera:

package Tools;
use Sub::Exporter
  -setup => { exports => [ qw(function1 function2 function3) ] };

Esta es la forma más sencilla de usar el exportador y es básicamente equivalente a esto:

package Tools;
use base qw(Exporter);
our @EXPORT_OK = qw(function1 function2 function3);

Cualquier uso básico de Sub::Exporter se verá así:

package Tools;
use Sub::Exporter -setup => \%config;

Las siguientes claves son válidas en %config:

exports - una lista de rutinas para proporcionar para exportación; cada rutina puede
          ser seguida por un generador
groups  - una lista de grupos para proporcionar para exportación; cada uno debe ser seguido por
          ya sea (a) una lista de exportaciones, posiblemente con argumentos para cada
          exportación, o (b) un generador
collectors - una lista de nombres en los que se recopilan valores para su uso en
             la generación de rutinas; cada nombre puede ser seguido por un validador

Además de las opciones básicas anteriores, se pueden pasar algunas opciones más avanzadas:

into_level - hasta qué nivel de la pila de llamadas buscar un objetivo (por defecto 0)
into       - un objetivo explícito (paquete) en el que exportar rutinas

En otras palabras: Sub::Exporter instala una rutina "import" que, cuando se llama, exporta rutinas al espacio de nombres de la que llama. Las opciones "into" y "into_level" cambian dónde se instalan esas rutinas exportadas.

generator  - una función de devolución de llamada utilizada para producir el código que será instalado
             por defecto: Sub::Exporter::default_generator
installer  - una función de devolución de llamada utilizada para instalar el código producido por el generador
             por defecto: Sub::Exporter::default_installer

Para obtener información sobre cómo se utilizan estas funciones de devolución de llamada, consulte la documentación de "default_generator" y "default_installer".

Configuración de Exportación

La lista "exports" puede proporcionarse como una referencia de matriz o una referencia de hash. La lista se p

procesado de tal manera que lo siguiente es equivalente:

{ exports => [ qw(foo bar baz), quux => \&quux_generator ] }
{ exports =>
  { foo => undef, bar => undef, baz => undef, quux => \&quux_generator } }

Los generadores son código que devuelve referencias a código. Se les llama con cuatro parámetros:

 $class - la clase cuya exportación ha sido llamada (la clase que exporta)
 $name  - el nombre de la exportación para la que se está construyendo la rutina
\%arg   - los argumentos pasados para esta exportación
\%col   - las colecciones para esta importación

Dada la configuración en el "SYNOPSIS", la siguiente declaración "use":

use Text::Tweaker
  reformat => { -as => 'make_narrow', width => 33 },
  defaults => { eol => 'CR' };

resultaría en la siguiente llamada a &build_reformatter:

my $code = build_reformatter(
  'Text::Tweaker',
  'reformat',
  { width => 33 }, # observa que -as no se pasa
  { defaults => { eol => 'CR' } },
);

La referencia a código devuelta ($code) se instalaría entonces como "make_narrow" en el paquete que la llama.

En lugar de proporcionar una referencia a código en la configuración, se puede proporcionar una referencia a un nombre de método. Este método se llamará entonces en el invocante del método "import". (En este caso, no pasamos el parámetro $class, ya que sería redundante).

Configuración de Grupo

La lista "groups" puede pasarse en las mismas formas que "exports". Los grupos deben tener valores para ser significativos, los cuales pueden listar exportaciones que conforman el grupo (opcionalmente con argumentos) o pueden proporcionar una manera de construir el grupo.

El caso más simple es el primero: una definición de grupo es una lista de exportaciones. Aquí está el ejemplo que podría ir en el exportador en el "SYNOPSIS".

groups  => {
  default    => [ qw(reformat) ],
  shorteners => [ qw(squish trim) ],
  email_safe => [
    'indent',
    reformat => { -as => 'email_format', width => 72 }
  ],
},

Los grupos se importan especificando su nombre precedido por un guión o un dos puntos. Esta línea de código importaría el grupo "shorteners":

use Text::Tweaker qw(-shorteners);

Los argumentos pasados a un grupo al importar se fusionan con las opciones de los grupos y se pasan a cualquier generador relevante. Los grupos pueden contener otros grupos, pero las estructuras de grupos en bucle se ignoran.

El otro valor posible para una definición de grupo, una referencia a código, permite que un generador construya varias rutinas exportables simultáneamente. Esto es útil cuando muchas rutinas deben compartir variables léxicas encerradas. La referencia a código debe devolver una referencia de hash. Las claves se utilizarán como nombres de exportación y los valores son las subs que se exportarán.

Este ejemplo muestra un uso simple del generador de grupos.

package Data::Crypto;
use Sub::Exporter -setup => { groups => { cipher => \&build_cipher_group } };
sub build_cipher_group {
  my ($class, $group, $arg) = @_;
  my ($encode, $decode) = build_codec($arg->{secret});
  return { cipher => $encode, decipher => $decode };
}

Las rutinas "cipher" y "decipher" se construyen en un grupo porque se construyen juntas por código que encierra su secreto en su entorno.

Grupos Predeterminados

Si un módulo que utiliza Sub::Exporter se usa con la declaración "use" sin argumentos, intentará exportar el grupo llamado "default". Si ese grupo no ha sido configurado específicamente, estará vacío y no sucederá nada.

También se crea otro grupo si no está definido: "all". El grupo "all" contiene todas las exportaciones de la lista de exportaciones.

Configuración de Colector

La entrada "collectors" en la configuración del exportador da nombres que, cuando se encuentran en la llamada de importación, sus valores se recopilan y se pasan a cada generador.

Por ejemplo, el generador "build_analyzer" que vimos anteriormente podría reescribirse como:

sub build_analyzer {
  my ($class, $name, $arg, $col) = @_;
  return sub {
    my $data      = shift;
    my $tolerance = shift || $arg->{tolerance} || $col->{defaults}{tolerance};
    my $passes    = shift || $arg->{passes}    || $col->{defaults}{passes};
    analyze($data, $tolerance, $passes);
  }
}

Eso permitiría al importador especificar valores predeterminados globales para sus importaciones:

use Data::Analyze
  'analyze',
  analyze  => { tolerance => 0.10, -as => analyze10 },
  analyze  => { tolerance => 0.15, passes => 50, -as => analyze50 },
  defaults => { passes => 10 };
my $A = analyze10($data);     # equivalente a analyze($data, 0.10, 10);
my $C = analyze50($data);     # equivalente a analyze($data, 0.15, 50);
my $B = analyze($data, 0.20); # equivalente a analyze($data, 0.20, 10);

Si se proporcionan valores en la lista "collectors" durante la configuración del exportador, deben ser referencias a código y se utilizan para validar los valores del importador. El validador se llama cuando se encuentra la colección y, si devuelve falso, se lanza una excepción. Podríamos asegurarnos de que nadie intente establecer un valor de datos global fácilmente:

collectors => { defaults => sub { return (exists $_[0]->{data}) ? 0 : 1 } }

Las referencias a código de colector también se pueden usar como ganchos para realizar acciones arbitrarias antes de que se exporte algo.

Cuando se llama a la referencia a código, se le pasa el valor de la colección y un hashref que contiene las siguientes entradas:

name        - el nombre del colector
config      - la configuración del exportador (hashref)
import_args - los argumentos pasados al exportador, sin las colecciones (aref)
class       - el paquete en el que se llamó al importador
into        - el paquete en el que se exportarán las exportaciones

Los colectores con nombres en mayúsculas (es decir, compuestos por guiones bajos o letras mayúsculas de la A a la Z) están reservados para uso especial. El único colector especial implementado actualmente es "INIT", cuyo gancho (si está presente en la configuración del exportador) siempre se ejecuta antes que cualquier otro gancho.

LLAMANDO AL EXPORTADOR

Los argumentos para el exportador (es decir, los argumentos después del nombre del módulo en una declaración "use") se analizan de la siguiente manera:

Primero, los colectores recopilan cualquier colección encontrada en los argumentos. Se puede dar cualquier tipo de referencia como valor para un colector. Para cada colección dada en los argumentos, se llama a su validador (si lo hay).

A continuación, se expanden los grupos. Si el grupo está implementado por un generador de grupos, se llama al generador. Hay dos argumentos especiales que, si se dan a un grupo, tienen un significado especial:

-prefix - una cadena para anteponer a cualquier exportación importada de este grupo
-suffix - una cadena para añadir a cualquier exportación importada de este grupo

Finalmente, se llaman los generadores de exportaciones individuales y todas las subs, generadas o de otro tipo, se instalan en el paquete que las llama. Solo hay un argumento especial para los generadores de exportaciones:

-as     - dónde instalar la sub exportada

Normalmente, "-as" contendrá un nombre alternativo para la rutina. Sin embargo, puede contener una referencia a un escalar. Si ese es el caso, se colocará una referencia a la rutina generada en el escalar al que hace referencia "-as". No se instalará en el paquete que llama.

Argumentos Especiales del Exportador

El exportador generado acepta algunas opciones especiales, que pueden pasarse como primer argumento, en un hashref.

Estas opciones son:

into_level
into
generator
installer

Estas anulan las opciones de configuración con el mismo nombre descritas en "EXPORTER CONFIGURATION".

SUBRUTINAS

setup_exporter

Esta rutina construye e instala una rutina "import". Se llama con un argumento, un hashref que contiene la configuración del exportador. Utilizando esto, construye un exportador y lo instala en el paquete que llama con el nombre "import." Además de la configuración normal del exportador, se pueden pasar algunos argumentos con nombre en el hashref:

into       - en qué paquete se instalará el exportador
into_level - a qué nivel superior de la pila se instalará el exportador
as         - qué nombre se le dará al exportador instalado

Por defecto, el exportador se instala con el nombre "import" en el llamador inmediato de "setup_exporter". En otras palabras, si su paquete llama a "setup_exporter" sin proporcionar ninguno de los tres argumentos anteriores, tendrá instalada una rutina "import".

Proporcionar tanto "into" como "into_level" lanzará una excepción.

El exportador es construido por "build_exporter".

build_exporter

Dada una configuración de exportador estándar, esta rutina construye y devuelve un exportador, es decir, una subrutina que puede instalarse como un método de clase para realizar exportaciones a petición.

Normalmente, este método es llamado por "setup_exporter", que luego instala el exportador como la rutina de importación de un paquete.

default_generator

Este es el generador predeterminado de Sub::Exporter. Toma fragmentos de configuración que se han recopilado durante la importación y los convierte en una referencia a código que se puede instalar.

my $code = default_generator(\%arg);
