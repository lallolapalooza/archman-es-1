NOMBRE

SET_SESSION_AUTHORIZATION - establece el identificador de usuario de sesión y el identificador de usuario actual de la sesión actual

SINOPSIS

SET [ SESSION | LOCAL ] SESSION AUTHORIZATION nombre_usuario
SET [ SESSION | LOCAL ] SESSION AUTHORIZATION DEFAULT
RESET SESSION AUTHORIZATION

DESCRIPCIÓN

Este comando establece el identificador de usuario de sesión y el identificador de usuario actual de la sesión SQL actual a nombre_usuario. El nombre de usuario puede escribirse como un identificador o como un literal de cadena. Usando este comando, es posible, por ejemplo, convertirse temporalmente en un usuario sin privilegios y más tarde volver a ser un superusuario.

El identificador de usuario de sesión se establece inicialmente como el nombre de usuario (posiblemente autenticado) proporcionado por el cliente. El identificador de usuario actual normalmente es igual al identificador de usuario de sesión, pero podría cambiar temporalmente en el contexto de funciones SECURITY DEFINER y mecanismos similares; también puede ser cambiado por SET ROLE. El identificador de usuario actual es relevante para la verificación de permisos.

El identificador de usuario de sesión solo puede cambiarse si el usuario de sesión inicial (el usuario autenticado) tiene el privilegio de superusuario. De lo contrario, el comando se acepta solo si especifica el nombre de usuario autenticado.

Los modificadores SESSION y LOCAL actúan igual que para el comando SET regular.

Las formas DEFAULT y RESET restablecen los identificadores de usuario de sesión y actual al nombre de usuario autenticado originalmente. Cualquier usuario puede ejecutar estas formas.

NOTAS

SET SESSION AUTHORIZATION no se puede usar dentro de una función SECURITY DEFINER.

EJEMPLOS

SELECT SESSION_USER, CURRENT_USER;
 session_user | current_user
--------------+--------------
 peter        | peter
SET SESSION AUTHORIZATION 'paul';
SELECT SESSION_USER, CURRENT_USER;
 session_user | current_user
--------------+--------------
 paul         | paul

COMPATIBILIDAD

El estándar SQL permite que otras expresiones aparezcan en lugar del literal nombre_usuario, pero estas opciones no son importantes en la práctica. PostgreSQL permite la sintaxis de identificador ("nombredeusuario"), lo que SQL no hace. SQL no permite este comando durante una transacción; PostgreSQL no hace esta restricción porque no hay razón para ello. Los modificadores SESSION y LOCAL son una extensión de PostgreSQL, al igual que la sintaxis RESET.

Los privilegios necesarios para ejecutar este comando se dejan definidos por la implementación según el estándar.
