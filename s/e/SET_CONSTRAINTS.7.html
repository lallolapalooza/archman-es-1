NOMBRE

SET_CONSTRAINTS - establecer el momento de verificación de restricciones para la transacción actual

SINOPSIS

SET CONSTRAINTS { ALL | nombre [, ...] } { DEFERRED | IMMEDIATE }

DESCRIPCIÓN

SET CONSTRAINTS establece el comportamiento de la verificación de restricciones dentro de la transacción actual. Las restricciones IMMEDIATE se verifican al final de cada sentencia. Las restricciones DEFERRED no se verifican hasta el commit de la transacción. Cada restricción tiene su propio modo IMMEDIATE o DEFERRED.

Al crearse, una restricción recibe una de tres características: DEFERRABLE INITIALLY DEFERRED, DEFERRABLE INITIALLY IMMEDIATE, o NOT DEFERRABLE. La tercera clase es siempre IMMEDIATE y no se ve afectada por el comando SET CONSTRAINTS. Las dos primeras clases inician cada transacción en el modo indicado, pero su comportamiento puede ser modificado dentro de una transacción por SET CONSTRAINTS.

SET CONSTRAINTS con una lista de nombres de restricciones cambia el modo solo de esas restricciones (que deben ser todas diferibles). Cada nombre de restricción puede ser calificado por esquema. La ruta de búsqueda de esquemas actual se utiliza para encontrar el primer nombre coincidente si no se especifica ningún nombre de esquema. SET CONSTRAINTS ALL cambia el modo de todas las restricciones diferibles.

Cuando SET CONSTRAINTS cambia el modo de una restricción de DEFERRED a IMMEDIATE, el nuevo modo entra en vigor retroactivamente: cualquier modificación de datos pendiente que debería haber sido verificada al final de la transacción se verifica en su lugar durante la ejecución del comando SET CONSTRAINTS. Si se viola alguna de estas restricciones, SET CONSTRAINTS falla (y no cambia el modo de la restricción). Por lo tanto, SET CONSTRAINTS puede usarse para forzar la verificación de restricciones en un punto específico de una transacción.

Actualmente, solo las restricciones UNIQUE, PRIMARY KEY, REFERENCES (clave externa) y EXCLUDE se ven afectadas por esta configuración. Las restricciones NOT NULL y CHECK siempre se verifican inmediatamente cuando se inserta o modifica una fila (no al final de la sentencia). Las restricciones de unicidad y exclusión que no han sido declaradas DEFERRABLE también se verifican inmediatamente.

El disparo de triggers declarados como "constraint triggers" también está controlado por esta configuración; se disparan al mismo tiempo que se debe verificar la restricción asociada.

NOTAS

Debido a que PostgreSQL no requiere que los nombres de restricciones sean únicos dentro de un esquema (sino solo por tabla), es posible que haya más de una coincidencia para un nombre de restricción especificado. En este caso, SET CONSTRAINTS actuará sobre todas las coincidencias. Para un nombre no calificado por esquema, una vez que se han encontrado una o más coincidencias en algún esquema de la ruta de búsqueda, no se buscarán esquemas que aparezcan más tarde en la ruta.

Este comando solo altera el comportamiento de las restricciones dentro de la transacción actual. Emitirlo fuera de un bloque de transacción emite una advertencia y, de lo contrario, no tiene ningún efecto.

COMPATIBILIDAD

Este comando cumple con el comportamiento definido en el estándar SQL, excepto por la limitación de que, en PostgreSQL, no se aplica a las restricciones NOT NULL y CHECK. Además, PostgreSQL verifica inmediatamente las restricciones de unicidad no diferibles, no al final de la sentencia como sugeriría el estándar.
