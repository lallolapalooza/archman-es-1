SET ROLE(7) Documentación de PostgreSQL 18.1 SET ROLE(7)

NOMBRE

SET_ROLE - establece el identificador de usuario actual de la sesión actual

SINOPSIS

SET [ SESION | LOCAL ] ROLE nombre_de_rol
SET [ SESION | LOCAL ] ROLE NINGUNO
RESET ROLE

DESCRIPCIÓN

Este comando establece el identificador de usuario actual de la sesión SQL actual a nombre_de_rol. El nombre del rol se puede escribir como un identificador o como un literal de cadena. Después de SET ROLE, la comprobación de permisos para los comandos SQL se realiza como si el rol nombrado hubiera sido el que se conectó originalmente. Tenga en cuenta que SET ROLE y SET SESSION AUTHORIZATION son excepciones; la comprobación de permisos para ellos continúa utilizando el usuario de sesión actual y el usuario de sesión inicial (el usuario autenticado), respectivamente.

El usuario de sesión actual debe tener la opción SET para el nombre_de_rol especificado, ya sea directa o indirectamente a través de una cadena de membresías con la opción SET. (Si el usuario de sesión es un superusuario, se puede seleccionar cualquier rol).

Los modificadores SESION y LOCAL actúan de la misma manera que para el comando SET normal.

SET ROLE NINGUNO establece el identificador de usuario actual al identificador de usuario de sesión actual, según lo devuelto por session_user. RESET ROLE establece el identificador de usuario actual al ajuste especificado en el momento de la conexión mediante las opciones de línea de comandos, ALTER ROLE o ALTER DATABASE, si existen dichos ajustes. De lo contrario, RESET ROLE establece el identificador de usuario actual al identificador de usuario de sesión actual. Estas formas pueden ser ejecutadas por cualquier usuario.

NOTAS

Usando este comando, es posible añadir privilegios o restringir los propios privilegios. Si al rol de usuario de sesión se le han concedido membresías CON HERENCIA VERDADERA, automáticamente tiene todos los privilegios de cada rol de ese tipo. En este caso, SET ROLE efectivamente elimina todos los privilegios excepto aquellos que el rol de destino posee directamente o hereda. Por otro lado, si al rol de usuario de sesión se le han concedido membresías CON HERENCIA FALSA, los privilegios de los roles concedidos no se pueden acceder por defecto. Sin embargo, si el rol fue concedido CON SET VERDADERO, el usuario de sesión puede usar SET ROLE para eliminar los privilegios asignados directamente al usuario de sesión y adquirir en su lugar los privilegios disponibles para el rol nombrado. Si el rol fue concedido CON HERENCIA FALSA, SET FALSO, entonces los privilegios de ese rol no se pueden ejercer ni con ni sin SET ROLE.

SET ROLE tiene efectos comparables a SET SESSION AUTHORIZATION, pero las comprobaciones de privilegios involucradas son muy diferentes. Además, SET SESSION AUTHORIZATION determina qué roles son admisibles para comandos SET ROLE posteriores, mientras que cambiar roles con SET ROLE no cambia el conjunto de roles permitidos para un SET ROLE posterior.

SET ROLE no procesa las variables de sesión especificadas por la configuración de ALTER ROLE del rol; esto solo ocurre durante el inicio de sesión.

SET ROLE no se puede utilizar dentro de una función SECURITY DEFINER.

EJEMPLOS

SELECT SESSION_USER, CURRENT_USER;
 session_user | current_user
--------------+--------------
 peter        | peter
SET ROLE 'paul';
SELECT SESSION_USER, CURRENT_USER;
 session_user | current_user
--------------+--------------
 peter        | paul

COMPATIBILIDAD

PostgreSQL permite la sintaxis de identificador ("nombre_de_rol"), mientras que el estándar SQL requiere que el nombre del rol se escriba como un literal de cadena. SQL no permite este comando durante una transacción; PostgreSQL no impone esta restricción porque no hay razón para hacerlo. Los modificadores SESION y LOCAL son una extensión de PostgreSQL, al igual que la sintaxis RESET.
