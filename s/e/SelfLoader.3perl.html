SelfLoader(3perl) Guía de referencia del programador de Perl SelfLoader(3perl)

NOMBRE

SelfLoader - cargar funciones solo bajo demanda

SINOPSIS

paquete FOOBAR;
usar SelfLoader;
... (código de inicialización)
__DATA__
sub {....

DESCRIPCIÓN

Este módulo indica a sus usuarios que las funciones del paquete FOOBAR se cargarán automáticamente a partir del token "__DATA__". Ver también "Autoloading" en perlsub.

El token __DATA__

El token "__DATA__" indica al compilador de perl que el código perl para la compilación ha finalizado. Todo lo que sigue al token "__DATA__" está disponible para ser leído a través del manejador de archivo FOOBAR::DATA, donde FOOBAR es el nombre del paquete actual cuando se alcanza el token "__DATA__". Esto funciona igual que "__END__" en el paquete 'main', pero para otros módulos, los datos después de "__END__" no son automáticamente recuperables, mientras que los datos después de "__DATA__" sí lo son. El token "__DATA__" no se reconoce en versiones de perl anteriores a la 5.001m.

Tenga en cuenta que es posible tener tokens "__DATA__" en el mismo paquete en múltiples archivos, y que el último token "__DATA__" en un paquete determinado que es encontrado por el compilador es el que es accesible por el manejador de archivo. Esto también se aplica a "__END__" y main, es decir, si el programa 'main' tiene un "__END__", pero un módulo 'require'd (no 'use'd) por ese programa tiene una declaración 'package main;' seguida de un '"__DATA__"', entonces el manejador de archivo "DATA" se establece para acceder a los datos después del "__DATA__" en el módulo, _no_ a los datos después del token "__END__" en el programa 'main', ya que el compilador encuentra el archivo 'require'd más tarde.

Autoloading de SelfLoader

SelfLoader funciona haciendo que el usuario coloque el token "__DATA__" *después* del código perl que necesita ser compilado y ejecutado en el momento del 'require', pero *antes* de las declaraciones de subrutinas que pueden cargarse más tarde, generalmente porque es posible que nunca se llamen.

SelfLoader leerá del manejador de archivo FOOBAR::DATA para cargar los datos después de "__DATA__", y cargará cualquier subrutina cuando se llame. Los costos son el análisis único de los datos después de "__DATA__", y un retraso de carga para la _primera_ llamada de cualquier función cargada automáticamente. Los beneficios (con suerte) son una fase de compilación acelerada, sin necesidad de cargar funciones que nunca se usan.

SelfLoader dejará de leer de "__DATA__" si encuentra el token "__END__", tal como esperaría. Si está presente el token "__END__", y va seguido del token DATA, entonces SelfLoader deja el manejador de archivo FOOBAR::DATA abierto en la línea después de ese token.

SelfLoader exporta la subrutina "AUTOLOAD" al paquete que usa SelfLoader, y esta carga la subrutina llamada cuando se llama por primera vez.

No hay ninguna ventaja en poner subrutinas que _siempre_ se llamarán después del token "__DATA__".

Autoloading y léxicas del paquete

Una declaración 'my $pack_lexical' hace que la variable $pack_lexical sea local _solo_ al archivo hasta el token "__DATA__". Las subrutinas declaradas en otro lugar _no_ pueden ver estos tipos de variables, al igual que si declarara subrutinas en el paquete pero en otro archivo, estas no podrían ver dichas variables.

Por lo tanto, específicamente, las funciones cargadas automáticamente no pueden ver las léxicas del paquete (esto se aplica tanto a SelfLoader como a Autoloader). El pragmatismo "vars" proporciona una alternativa a la definición de globales a nivel de paquete que serán visibles para las rutinas cargadas automáticamente. Consulte la documentación de vars en la sección de pragmatismos de perlmod.

SelfLoader y AutoLoader

SelfLoader puede reemplazar a AutoLoader; simplemente cambie 'use AutoLoader' por 'use SelfLoader' (aunque tenga en cuenta que SelfLoader exporta la función AUTOLOAD; pero si tiene su propio AUTOLOAD y está usando también AutoLoader, probablemente sepa lo que está haciendo), y el token "__END__" por "__DATA__". Necesitará la versión de perl 5.001m o posterior para usar esto (versión 5.001 con todos los parches hasta el parche m).

No es necesario heredar de SelfLoader.

SelfLoader funciona de manera similar a AutoLoader, pero recoge las subs de después del token "__DATA__" en lugar del directorio 'lib/auto'. Hay una ganancia de mantenimiento al no necesitar ejecutar AutoSplit en el módulo al instalarlo, y una ganancia en tiempo de ejecución al no necesitar seguir abriendo y cerrando archivos para cargar subs. Hay una pérdida en tiempo de ejecución al necesitar analizar el código después del token "__DATA__". Los detalles de AutoLoader y otra perspectiva de estas distinciones se pueden encontrar en la documentación de ese módulo.

__DATA__, __END__, y el manejador de archivo FOOBAR::DATA

Esta sección solo es relevante si desea usar "FOOBAR::DATA" junto con SelfLoader.

Los datos después del token "__DATA__" en un módulo se leen utilizando el manejador de archivo FOOBAR::DATA. "__END__" todavía se puede usar para denotar el final de la sección "__DATA__" si va seguido del token DATA; esto es compatible con SelfLoader. El manejador de archivo "FOOBAR::DATA" se deja abierto si se encuentra un "__END__" seguido de un DATA, con el manejador de archivo posicionado al inicio de la línea después del token "__END__". Si no hay un token "__END__" presente, o un token "__END__" sin un token DATA en la misma línea, entonces el manejador de archivo se cierra.

SelfLoader lee desde donde sea la posición actual del manejador de archivo "FOOBAR::DATA", hasta el fin de archivo (EOF) o "__END__". Esto significa que si desea usar ese manejador de archivo (y *solo* si lo desea), debería

1. Poner todas sus declaraciones de subrutinas inmediatamente después del token "__DATA__" y poner sus propios datos después de esas declaraciones, utilizando el token "__END__" para marcar el final de las declaraciones de subrutinas. También debe asegurarse de que SelfLoader lea primero llamando a 'SelfLoader->load_stubs();', o usando una función que se cargue automáticamente;

o

2. Debería leer primero el manejador de archivo "FOOBAR::DATA", dejando el manejador abierto y posicionado en la primera línea de declaraciones de subrutinas.

Podría concebiblemente hacer ambas cosas.

Clases y métodos heredados

Para módulos que no son clases, esta sección no es relevante. Esta sección solo es relevante si tiene métodos que podrían ser heredados.

Una "stub" (o declaración anticipada) de subrutina se ve como

sub stub;

es decir, es una declaración de subrutina sin el cuerpo de la subrutina. Para módulos que no son clases, no hay una necesidad real de "stubs" en lo que respecta a la carga automática.
