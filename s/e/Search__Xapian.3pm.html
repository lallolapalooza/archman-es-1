Search__Xapian(3pm)

Paquete: perl-search-xapian

Licencias: PerlArtistic, GPL

Xapian(3) Documentación de Perl aportada por el usuario Xapian(3)

NOMBRE

Search::Xapian - Frontend XS de Perl para la biblioteca de búsqueda C++ Xapian.

SINOPSIS

use Search::Xapian;
my $db = Search::Xapian::Database->new( '[DATABASE DIR]' );
my $enq = $db->enquire( '[QUERY TERM]' );
printf "Ejecutando consulta '%s'\n", $enq->get_query()->get_description();
my @matches = $enq->matches(0, 10);
print scalar(@matches) . " resultados encontrados\n";
foreach my $match ( @matches ) {
  my $doc = $match->get_document();
  printf "ID %d %d%% [ %s ]\n", $match->get_docid(), $match->get_percent(), $doc->get_data();
}

DESCRIPCIÓN

Este módulo envuelve la mayoría de los métodos de la mayoría de las clases de Xapian. Las clases y métodos faltantes deberían añadirse en el futuro. También proporciona una interfaz simplificada y más "perlish" para algunas operaciones comunes, como se demuestra anteriormente.

Hay algunas lagunas en la documentación POD para las clases envueltas, pero puedes leer la documentación de la API C++ de Xapian en https://xapian.org/docs/apidoc/html/annotated.html para obtener detalles sobre estas. Alternativamente, echa un vistazo al código en los ejemplos y pruebas.

Si quieres usar Search::Xapian y el módulo threads juntos, asegúrate de estar usando Search::Xapian >= 1.0.4.0 y Perl >= 5.8.7. A partir de 1.0.4.0, Search::Xapian usa CLONE_SKIP para asegurarse de que los objetos wrapper de Perl no se copien a nuevos hilos; sin esto, los objetos C++ subyacentes pueden destruirse más de una vez.

Si encuentras problemas, o tienes algún comentario, sugerencia, parche, etc., por favor envía un correo a la lista de correo Xapian-discuss (cuyos detalles se pueden encontrar en https://xapian.org/lists).

EXPORTACIÓN

Ninguna por defecto.

:db

DB_OPEN
Abre una base de datos, falla si la base de datos no existe.
DB_CREATE
Crea una nueva base de datos, falla si la base de datos existe.
DB_CREATE_OR_OPEN
Abre una base de datos existente, sin destruir datos, o crea una nueva base de datos si no existe.
DB_CREATE_OR_OVERWRITE
Sobrescribe la base de datos si existe.

:ops

OP_AND
Coincide si ambas subconsultas se cumplen.
OP_OR
Coincide si alguna de las subconsultas se cumple.
OP_AND_NOT
Coincide si la subconsulta izquierda se cumple pero la derecha no.
OP_XOR
Coincide si la consulta izquierda o derecha se cumple, pero no ambas.
OP_AND_MAYBE
Coincide si la izquierda se cumple, pero usa los pesos de ambas.
OP_FILTER
Similar a OP_AND, pero solo pondera usando la consulta izquierda.
OP_NEAR
Coincide si las palabras están cerca unas de otras. La ventana debe especificarse como un parámetro de "Search::Xapian::Query::Query", pero por defecto es el número de términos en la lista.
OP_PHRASE
Coincide como una frase (Todas las palabras en orden).
OP_ELITE_SET
Selecciona un conjunto de élite de las subconsultas y realiza una consulta con ellas combinadas como una consulta OR.
OP_VALUE_RANGE
Filtra por una prueba de rango en un valor de documento.

:qpflags

FLAG_DEFAULT
Esto proporciona la configuración por defecto de los indicadores de QueryParser, permitiéndote añadir fácilmente indicadores a los predeterminados.
FLAG_BOOLEAN
Soporta AND, OR, etc y subexpresiones entre paréntesis.
FLAG_LOVEHATE
Soporta + y -.
FLAG_PHRASE
Soporta frases entre comillas.
FLAG_BOOLEAN_ANY_CASE
Soporta AND, OR, etc aunque no estén en MAYÚSCULAS.
FLAG_WILDCARD
Soporta truncamiento a la derecha (por ejemplo, Xap*).
FLAG_PURE_NOT
Permite consultas como 'NOT apples'.

Estos requieren el uso de una lista de todos los documentos de la base de datos, lo que puede ser costoso, por lo que esta función no está habilitada por defecto.

FLAG_PARTIAL
Habilita la coincidencia parcial.

La coincidencia parcial hace que el analizador trate la consulta como una búsqueda "introducida parcialmente". Esto tratará automáticamente la última palabra como una coincidencia con comodín, a menos que vaya seguida de un espacio en blanco, para producir resultados más estables en búsquedas interactivas.

FLAG_SPELLING_CORRECTION
FLAG_SYNONYM
FLAG_AUTO_SYNONYMS
FLAG_AUTO_MULTIWORD_SYNONYMS

:qpstem

STEM_ALL
Aplica la raíz a todos los términos.
STEM_NONE
No aplica la raíz a ningún término.
STEM_SOME
Aplica la raíz a algunos términos, de manera compatible con Omega (las palabras en mayúsculas y las de las frases no se aplican la raíz).

:enq_order

ENQ_ASCENDING
Los docids se ordenan en orden ascendente (por defecto)
ENQ_DESCENDING
Los docids se ordenan en orden descendente
ENQ_DONT_CARE
Los docids se ordenan en el orden más eficiente para el backend

:standard

Standard es db + ops + qpflags + qpstem

Funciones de versión

major_version
Devuelve la versión principal de la biblioteca C++ Xapian que se está utilizando. Por ejemplo, para Xapian 1.0.9 devolvería 1.
minor_version
Devuelve la versión menor de la biblioteca C++ Xapian que se está utilizando. Por ejemplo, para Xapian 1.0.9 devolvería 0.
revision
Devuelve la revisión de la biblioteca C++ Xapian que se está utilizando. Por ejemplo, para Xapian 1.0.9 devolvería 9. En una serie de lanzamientos estables, las bibliotecas Xapian con las mismas versiones principal y menor suelen ser compatibles con ABI, por lo que esto a menudo no coincidirá con el tercer componente de $Search::Xapian::VERSION (que es la versión de los wrappers XS de Search::Xapian).

Search::Xapian::ValueWrapper(3pm)

NAME

Search::Xapian::ValueWrapper - Value wrappers

SYNOPSIS

    use Search::Xapian;

    my $dw = Search::Xapian::DoubleWrapper->new;
    my $s = $dw->sortable_serialise($number);
    my $n = $dw->sortable_unserialise($s);

    # Example:
    my $number = 123.456;
    my $s = $dw->sortable_serialise($number);
    print "Serialised: $s\n"; # Serialised: 404e5574000000000000000000000000
    my $n = $dw->sortable_unserialise($s);
    print "Unserialised: $n\n"; # Unserialised: 123.456

    my $number2 = -123.456;
    my $s2 = $dw->sortable_serialise($number2);
    print "Serialised: $s2\n"; # Serialised: C04e5574000000000000000000000000
    my $n2 = $dw->sortable_unserialise($s2);
    print "Unserialised: $n2\n"; # Unserialised: -123.456

DESCRIPTION

The Search::Xapian::DoubleWrapper class provides methods for converting floating point numbers to and from strings such that the string representation preserves the sort order of the original numbers. This is useful for implementing numeric range restrictions.

The string representation is guaranteed to be identical for numbers which compare equal, and lexicographically ordered according to the numeric values of the original numbers.

The conversion is platform independent.

The string format is as follows:

A 32-byte hexadecimal string, representing the IEEE 754 double-precision floating point number in big-endian byte order.

Note that the implementation of sortable_serialise has been changed from the original Xapian C++ code. It used to use a struct hack to reinterpret the double as an unsigned long long. This is not portable and can have undefined behaviour. It has been replaced by a method which uses bit manipulation and conversion to ensure portability. This means that serialised strings from older versions of this module may not be recognised.

This indicates that the function is safe to be called from within a database access thread.

:ops

This indicates that the function is safe to be called from within an operator.

:qpstem

:standard

Version functions

sortable_serialise NUMBER
Convert a floating point number to a string, preserving sort order.

This method converts a floating point number to a string, suitable for using as a value for numeric range restriction, or for use as a sort key.

The conversion is platform independent.

The conversion attempts to ensure that, for any pair of values supplied to the conversion algorithm, the result of comparing the original values (with a numeric comparison operator) will be the same as the result of comparing the resulting values (with a string comparison operator). On platforms which represent doubles with the precisions specified by IEEE_754, this will be the case: if the representation of doubles is more precise, it is possible that two very close doubles will be mapped to the same string, so will compare equal.

Note also that both zero and -zero will be converted to the same representation: since these compare equal, this satisfies the comparison constraint, but it's worth knowing this if you wish to use the encoding in some situation where this distinction matters.

Handling of NaN isn't (currently) guaranteed to be sensible.

sortable_unserialise SERIALISED_NUMBER
Convert a string encoded using sortable_serialise back to a floating point number.

This expects the input to be a string produced by sortable_serialise(). If the input is not such a string, the value returned is undefined (but no error will be thrown).

The result of the conversion will be exactly the value which was supplied to sortable_serialise() when making the string on platforms which represent doubles with the precisions specified by IEEE_754, but may be a different (nearby) value on other platforms.
