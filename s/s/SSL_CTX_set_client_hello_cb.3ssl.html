NOMBRE

SINOPSIS

typedef int (*SSL_client_hello_cb_fn)(SSL *s, int *al, void *arg);
void SSL_CTX_set_client_hello_cb(SSL_CTX *c, SSL_client_hello_cb_fn *f,
                                 void *arg);
int SSL_client_hello_isv2(SSL *s);
unsigned int SSL_client_hello_get0_legacy_version(SSL *s);
size_t SSL_client_hello_get0_random(SSL *s, const unsigned char **out);
size_t SSL_client_hello_get0_session_id(SSL *s, const unsigned char **out);
size_t SSL_client_hello_get0_ciphers(SSL *s, const unsigned char **out);
size_t SSL_client_hello_get0_compression_methods(SSL *s,
                                                 const unsigned char **out);
int SSL_client_hello_get1_extensions_present(SSL *s, int **out,
                                             size_t *outlen);
int SSL_client_hello_get_extension_order(SSL *s, uint16_t *exts,
                                         size_t *num_exts);
int SSL_client_hello_get0_ext(SSL *s, unsigned int type, const unsigned char **out,
                              size_t *outlen);

DESCRIPCIÓN

SSL_CTX_set_client_hello_cb() establece la función de callback, que se llama automáticamente durante las primeras etapas del procesamiento de ClientHello en el servidor. El argumento proporcionado al establecer el callback se devuelve al callback en tiempo de ejecución. Un callback que devuelve error (0) provocará la terminación de la conexión, y los callbacks que devuelven error deben indicar qué valor de alerta se debe enviar en el parámetro al. Un callback también puede devolver un valor negativo para suspender el handshake, y la función de handshake devolverá inmediatamente. SSL_get_error(3) devolverá SSL_ERROR_WANT_CLIENT_HELLO_CB para indicar que el handshake fue suspendido. Es responsabilidad del callback de ClientHello almacenar información sobre el estado de la última llamada si es necesario para continuar. En la siguiente llamada a la función de handshake, se volverá a llamar al callback de ClientHello y, si devuelve éxito, el procesamiento normal del handshake continuará a partir de ese punto.

SSL_client_hello_isv2() indica si el ClientHello se transportó en un registro SSLv2 y tiene el formato SSLv2. El formato SSLv2 tiene diferencias sustanciales con el formato SSLv3 normal, incluyendo el uso de tres bytes por suite de cifrado y no permitiendo extensiones. Además, el campo 'challenge' del formato SSLv2 se expone a través de SSL_client_hello_get0_random(), rellenado hasta SSL3_RANDOM_SIZE bytes con ceros si es necesario. Para ClientHellos en formato SSLv2, SSL_client_hello_get0_compression_methods() devuelve una lista ficticia que solo incluye el método de compresión nulo, ya que el formato SSLv2 no incluye un mecanismo para negociar la compresión.

SSL_client_hello_get0_random(), SSL_client_hello_get0_session_id(), SSL_client_hello_get0_ciphers() y SSL_client_hello_get0_compression_methods() proporcionan acceso a los campos correspondientes de ClientHello, devolviendo la longitud del campo y, opcionalmente, estableciendo un puntero de salida a los octetos de ese campo.

De manera similar, SSL_client_hello_get0_ext() proporciona acceso a extensiones individuales del ClientHello por extensión. Para el valor del tipo de protocolo de extensión proporcionado, el valor y la longitud de la extensión se devuelven en los parámetros de salida (si están presentes).

SSL_client_hello_get1_extensions_present() se puede usar antes de SSL_client_hello_get0_ext(), para determinar qué extensiones están presentes en el ClientHello antes de consultarlas. Los parámetros out y outlen son obligatorios, y en caso de éxito el llamador debe liberar el almacenamiento asignado para *out usando OPENSSL_free(). El contenido de *out es un array de enteros que contiene el valor numérico de los tipos de extensión TLS en el orden en que aparecen en el ClientHello. *outlen contiene el número de elementos en el array. En situaciones en las que el ClientHello no tiene extensiones, la función devolverá éxito con *out establecido a NULL y *outlen establecido a 0.

SSL_client_hello_get_extension_order() es similar a SSL_client_hello_get1_extensions_present(), sin asignación interna de memoria. Cuando se llama con exts establecido a NULL, devuelve el número de extensiones (por ejemplo, para asignar almacenamiento para una llamada posterior). De lo contrario, *exts se rellena con los valores de ExtensionType en el orden en que las extensiones correspondientes aparecieron en el ClientHello. *num_exts es un parámetro de entrada/salida, utilizado como entrada para suministrar el tamaño del almacenamiento asignado por el llamador, y como salida para indicar cuántos valores de ExtensionType se escribieron. Si el *num_exts de entrada es menor que el número de extensiones en cuestión, eso se trata como un error. Una llamada posterior con exts establecido a NULL puede recuperar el tamaño de almacenamiento necesario. Un ClientHello que no contuvo extensiones se trata como éxito, con *num_exts establecido a 0.

NOTAS

El callback de ClientHello proporciona una gran cantidad de posibilidades para que el código de la aplicación afecte al handshake TLS. Un uso principal del callback es permitir que el servidor examine la extensión de indicación del nombre del servidor proporcionada por el cliente para seleccionar un certificado apropiado para presentar, y realizar otros ajustes de configuración relevantes para ese nombre de servidor y su configuración. Dichos cambios de configuración pueden incluir el intercambio del puntero SSL_CTX asociado, la modificación de la lista de versiones TLS permitidas por el servidor, el cambio de la lista de cifrados del servidor en respuesta a la lista de cifrados del cliente, etc.

También se recomienda que las aplicaciones utilicen un callback de ClientHello y no utilicen un callback de nombre de servidor, para evitar un comportamiento inesperado que ocurre debido al orden relativo de procesamiento entre cosas como la reanudación de sesión y el callback histórico de nombre de servidor.

La familia de funciones SSL_client_hello_* solo puede ser llamada desde código que se ejecuta dentro de un callback de ClientHello.

VALORES DE RETORNO

El callback de ClientHello proporcionado por la aplicación devuelve SSL_CLIENT_HELLO_SUCCESS en caso de éxito, SSL_CLIENT_HELLO_ERROR en caso de error, y SSL_CLIENT_HELLO_RETRY para suspender el procesamiento.

SSL_client_hello_isv2() devuelve 1 para ClientHellos en formato SSLv2 y 0 en caso contrario.

SSL_client_hello_get0_random(), SSL_client_hello_get0_session_id(), SSL_client_hello_get0_ciphers() y SSL_client_hello_get0_compression_methods() devuelven la longitud de los campos correspondientes de ClientHello. Si se devuelve cero, no se debe asumir que el puntero de salida es válido.

SSL_client_hello_get0_ext() devuelve 1 si la extensión de tipo 'type' está presente, y 0 en caso contrario.

SSL_client_hello_get1_extensions_present() devuelve 1 en caso de éxito y 0 en caso de error.

SSL_client_hello_get_extension_order() devuelve 1 en caso de éxito y 0 en caso de error.

SSL_CTX_set_client_hello_cb(3ssl)

OpenSSL

NAME

SSL_CTX_set_client_hello_cb, SSL_set_client_hello_cb - callback for client hello

SYNOPSIS

In openssl/ssl.h: 

typedef int (*SSL_client_hello_cb_fn)(SSL *ssl, int *al,
                                     void *arg);

int SSL_CTX_set_client_hello_cb(SSL_CTX *ctx,
                                SSL_client_hello_cb_fn callback,
                                void *arg);
int SSL_set_client_hello_cb(SSL *ssl,
                            SSL_client_hello_cb_fn callback,
                            void *arg);

DESCRIPTION

The client hello callback is invoked when an SSL_CTX or SSL object is configured to handle an incoming Client Hello message. This can be used to dynamically change the set of acceptable ciphers or other parameters based on the Client Hello message.

The callback function is invoked just before the Client Hello message is processed.

The callback function should return one of the following values:

1
The callback successfully processed the Client Hello message. The processing continues as usual.
0
An error occurred. The connection is terminated.
-1
The callback wants to retry. This is only useful if the callback itself is waiting for some external event. It should not be used in normal circumstances.

The al parameter is a pointer to the alert value that will be sent to the peer. It should be set by the callback if it wants to send an alert.

The arg parameter is a user-defined pointer that was passed to SSL_CTX_set_client_hello_cb().

SSL_CTX_set_client_hello_cb() sets the callback for all SSL objects created from the given ctx.

SSL_set_client_hello_cb() sets the callback for the given ssl object. This overrides the callback set for the SSL_CTX.

NOTES

This callback is only invoked for incoming connections, i.e. on the server side.

The callback is invoked after the Client Hello message has been received, but before it has been processed. This means that the ssl object is not yet fully initialized, and some functions may not be available. Specifically, you cannot call functions that rely on the connection being established, such as SSL_get_peer_certificate().

The callback can be used to:

  • Dynamically select a certificate based on the Client Hello message.
  • Modify the set of acceptable ciphers.
  • Perform other custom processing of the Client Hello message.

RETURN VALUES

SSL_CTX_set_client_hello_cb() and SSL_set_client_hello_cb() return 1 on success, and 0 on failure.

SEE ALSO

SSL_CTX(3ssl), SSL(3ssl), SSL_use_certificate(3ssl), SSL_set_ciphers(3ssl)

HISTORY

The client hello callback was introduced in OpenSSL 1.1.0.
