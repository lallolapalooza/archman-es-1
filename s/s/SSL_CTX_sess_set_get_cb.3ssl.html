SSL_CTX_sess_set_get_cb(3ssl)

Paquete: openssl

Licencias: Apache-2.0

SSL_CTX_SESS_SET_GET_CB(3ssl) OpenSSL SSL_CTX_SESS_SET_GET_CB(3ssl)

NOMBRE

SSL_CTX_sess_set_new_cb, SSL_CTX_sess_set_remove_cb, SSL_CTX_sess_set_get_cb, SSL_CTX_sess_get_new_cb, SSL_CTX_sess_get_remove_cb, SSL_CTX_sess_get_get_cb - proporcionar funciones de devolución de llamada para el almacenamiento en caché de sesiones externas del lado del servidor

SINOPSIS

#include <openssl/ssl.h>
void SSL_CTX_sess_set_new_cb(SSL_CTX *ctx,
                             int (*new_session_cb)(SSL *, SSL_SESSION *));
void SSL_CTX_sess_set_remove_cb(SSL_CTX *ctx,
                                void (*remove_session_cb)(SSL_CTX *ctx,
                                                          SSL_SESSION *));
void SSL_CTX_sess_set_get_cb(SSL_CTX *ctx,
                             SSL_SESSION (*get_session_cb)(SSL *,
                                                           const unsigned char *,
                                                           int, int *));
int (*SSL_CTX_sess_get_new_cb(SSL_CTX *ctx))(struct ssl_st *ssl,
                                             SSL_SESSION *sess);
void (*SSL_CTX_sess_get_remove_cb(SSL_CTX *ctx))(struct ssl_ctx_st *ctx,
                                                 SSL_SESSION *sess);
SSL_SESSION *(*SSL_CTX_sess_get_get_cb(SSL_CTX *ctx))(struct ssl_st *ssl,
                                                      const unsigned char *data,
                                                      int len, int *copy);

DESCRIPCIÓN

SSL_CTX_sess_set_new_cb() establece la función de devolución de llamada que se llama cada vez que se negocia una nueva sesión.

SSL_CTX_sess_set_remove_cb() establece la función de devolución de llamada que se llama cada vez que el motor SSL elimina una sesión. Por ejemplo, esto puede ocurrir porque una sesión se considera defectuosa o ha quedado obsoleta debido a la superación del valor de tiempo de espera.

SSL_CTX_sess_set_get_cb() establece la función de devolución de llamada que se llama cada vez que un cliente TLS propuso reanudar una sesión pero la sesión no pudo ser encontrada en la caché de sesiones interna (ver SSL_CTX_set_session_cache_mode(3)). (Solo servidor TLS).

SSL_CTX_sess_get_new_cb(), SSL_CTX_sess_get_remove_cb(), y SSL_CTX_sess_get_get_cb() recuperan los punteros de función establecidos por las funciones de devolución de llamada de configuración correspondientes. Si no se ha establecido una función de devolución de llamada, se devuelve el puntero NULL.

NOTAS

Para permitir el almacenamiento en caché de sesiones externas, la sincronización con la caché de sesiones interna se realiza a través de funciones de devolución de llamada. Dentro de estas funciones de devolución de llamada, las sesiones se pueden guardar en disco o colocar en una base de datos utilizando la interfaz d2i_SSL_SESSION(3).

La new_session_cb() se llama cada vez que se ha negociado una nueva sesión y el almacenamiento en caché de sesiones está habilitado (ver SSL_CTX_set_session_cache_mode(3)). A la new_session_cb() se le pasan la conexión ssl y la naciente sesión ssl sess. Dado que las sesiones son objetos contados por referencia, el recuento de referencias de la sesión se incrementa antes de la devolución de llamada, en nombre de la aplicación. Si la devolución de llamada devuelve 0, la sesión se eliminará inmediatamente de la caché interna y se liberará el recuento de referencias. Si la devolución de llamada devuelve 1, la aplicación conserva la referencia (para una entrada en la "caché de sesiones externa" mantenida por la aplicación) y es responsable de llamar a SSL_SESSION_free() cuando la referencia de la sesión ya no se utiliza.

Tenga en cuenta que en TLSv1.3, las sesiones se establecen después de que se completa el handshake principal. El servidor decide cuándo enviar al cliente la información de la sesión y esto puede ocurrir algún tiempo después del final del handshake (o no en absoluto). Esto significa que las aplicaciones deben esperar que la función new_session_cb() se invoque durante el handshake (para <= TLSv1.2) o después del handshake (para TLSv1.3). También es posible en TLSv1.3 que se establezcan múltiples sesiones con una sola conexión. En estos casos, la función new_session_cb() se invocará varias veces.

En TLSv1.3, se recomienda que cada objeto SSL_SESSION se utilice solo una vez para la reanudación. Una forma de garantizar esto es que las aplicaciones llamen a SSL_CTX_remove_session(3) después de que una sesión haya sido utilizada.

La remove_session_cb() se llama cada vez que el motor SSL elimina una sesión de la caché interna. Esto puede ocurrir cuando la sesión se elimina porque está caducada o cuando una conexión no se cerró limpiamente. También ocurre para todas las sesiones en la caché de sesiones interna cuando se llama a SSL_CTX_free(3). A la remove_session_cb() se le pasan el ctx y la sesión ssl sess. No proporciona ninguna retroalimentación.

La get_session_cb() solo se llama en servidores SSL/TLS y se le da el ID de sesión propuesto por el cliente. La get_session_cb() siempre se llama, incluso cuando el almacenamiento en caché de sesiones estaba deshabilitado. A la get_session_cb() se le pasan la conexión ssl y el ID de sesión de longitud length en la ubicación de memoria data. Al establecer el parámetro copy en 1, la devolución de llamada puede requerir que el motor SSL incremente el recuento de referencias del objeto SSL_SESSION; establecer copy en 0 hace que el recuento de referencias no cambie. Si la get_session_cb() no escribe en copy, el recuento de referencias se incrementa y la sesión debe liberarse explícitamente con SSL_SESSION_free(3).

VALORES DE RETORNO

SSL_CTX_sess_get_new_cb(), SSL_CTX_sess_get_remove_cb() y SSL_CTX_sess_get_get_cb() devuelven respectivamente diferentes punteros de función de devolución de llamada.
