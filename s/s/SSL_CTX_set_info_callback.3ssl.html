SSL_CTX_set_info_callback(3ssl)

Paquete: openssl

Licencias: Apache-2.0

SSL_CTX_SET_INFO_CALLBACK(3ssl) OpenSSL SSL_CTX_SET_INFO_CALLBACK(3ssl)

NOMBRE

SSL_CTX_set_info_callback, SSL_CTX_get_info_callback, SSL_set_info_callback, SSL_get_info_callback - manejar la llamada de información para conexiones SSL

SINOPSIS

#include <openssl/ssl.h>
void SSL_CTX_set_info_callback(SSL_CTX *ctx,
                               void (*callback) (const SSL *ssl, int type, int val));
void (*SSL_CTX_get_info_callback(SSL_CTX *ctx)) (const SSL *ssl, int type, int val);
void SSL_set_info_callback(SSL *ssl,
                           void (*callback) (const SSL *ssl, int type, int val));
void (*SSL_get_info_callback(const SSL *ssl)) (const SSL *ssl, int type, int val);

DESCRIPCIÓN

SSL_CTX_set_info_callback() establece la función de llamada, que puede ser utilizada para obtener información de estado para objetos SSL creados a partir de ctx durante la configuración y uso de la conexión. La configuración para ctx se ve anulada por la configuración para un objeto SSL específico, si se especifica. Cuando callback es NULL, no se utiliza ninguna función de llamada.

SSL_set_info_callback() establece la función de llamada, que puede ser utilizada para obtener información de estado para ssl durante la configuración y uso de la conexión. Cuando callback es NULL, se utiliza la configuración de llamada actualmente válida para ctx. ssl NO DEBE ser NULL.

SSL_CTX_get_info_callback() devuelve un puntero a la función de llamada de información actualmente establecida para ctx.

SSL_get_info_callback() devuelve un puntero a la función de llamada de información actualmente establecida para ssl.

NOTAS

Durante la configuración de una conexión y su uso, es posible obtener información de estado del motor SSL/TLS. Cuando se establece, una función de llamada de información se invoca cada vez que ocurre un evento significativo, como: el cambio de estado, la aparición de una alerta o un error.

La función de llamada se invoca como callback(SSL *ssl, int where, int ret). El argumento where especifica información sobre dónde (en qué contexto) se llamó a la función de llamada. Si ret es 0, ocurrió una condición de error. Si se maneja una alerta, se establece SSL_CB_ALERT y ret especifica la información de la alerta.

where es una máscara de bits compuesta por los siguientes bits:

SSL_CB_LOOP
La llamada se ha invocado para indicar un cambio de estado u otro evento significativo de la máquina de estados. Esto puede significar que la llamada se invoque más de una vez por estado en algunas situaciones.
SSL_CB_EXIT
La llamada se ha invocado para indicar la salida de una función de negociación. Esto ocurrirá después del final de una negociación, pero también puede ocurrir en otros momentos, como en caso de error o cuando la E/S podría bloquearse y se está utilizando no bloqueante.
SSL_CB_READ
La llamada se ha invocado durante la operación de lectura.
SSL_CB_WRITE
La llamada se ha invocado durante la operación de escritura.
SSL_CB_ALERT
La llamada se ha invocado debido a que se envió o recibió una alerta.
SSL_CB_READ_ALERT (SSL_CB_ALERT|SSL_CB_READ)
SSL_CB_WRITE_ALERT (SSL_CB_ALERT|SSL_CB_WRITE)
SSL_CB_ACCEPT_LOOP (SSL_ST_ACCEPT|SSL_CB_LOOP)
SSL_CB_ACCEPT_EXIT (SSL_ST_ACCEPT|SSL_CB_EXIT)
SSL_CB_CONNECT_LOOP (SSL_ST_CONNECT|SSL_CB_LOOP)
SSL_CB_CONNECT_EXIT (SSL_ST_CONNECT|SSL_CB_EXIT)
SSL_CB_HANDSHAKE_START
La llamada se ha invocado porque se inicia una nueva negociación. También ocurre al reanudar una negociación después de una pausa para manejar datos tempranos.
SSL_CB_HANDSHAKE_DONE
La llamada se ha invocado porque una negociación ha finalizado. También ocurre si la negociación se pausa para permitir el intercambio de datos tempranos.

La información del estado actual se puede obtener utilizando la familia de funciones SSL_state_string(3).

La información de ret se puede evaluar utilizando la familia de funciones SSL_alert_type_string(3).

VALORES DE RETORNO

SSL_set_info_callback() no proporciona información de diagnóstico.

SSL_get_info_callback() devuelve la configuración actual.

EJEMPLOS

La siguiente función de llamada de ejemplo imprime cadenas de estado, información sobre las alertas que se están manejando y mensajes de error en el BIO bio_err.

void apps_ssl_info_callback(const SSL *s, int where, int ret)
{
    const char *str;
    int w = where & ~SSL_ST_MASK;
    if (w & SSL_ST_CONNECT)
        str = "SSL_connect";
    else if (w & SSL_ST_ACCEPT)
        str = "SSL_accept";
    else
        str = "undefined";
    if (where & SSL_CB_LOOP) {
        BIO_printf(bio_err, "%s:%s\n", str, SSL_state_string_long(s));
    } else if (where & SSL_CB_ALERT) {
        str = (where & SSL_CB_READ) ? "read" : "write";
        BIO_printf(bio_err, "SSL3 alert %s:%s:%s\n", str,
                   SSL_alert_type_string_long(ret),
                   SSL_alert_desc_string_long(ret));
    } else if (where & SSL_CB_EXIT) {
        if (ret == 0) {
            BIO_printf(bio_err, "%s:failed in %s\n",
                       str, SSL_state_string_long(s));
        } else if (ret < 0) {
            BIO_printf(bio_err, "%s:error in %s\n",
                       str, SSL_state_string_long(s));
        }
    }
}
