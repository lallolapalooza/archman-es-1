SSL_CTX_set_session_cache_mode(3ssl)

Paquete: openssl

Licencias: Apache-2.0

SSL_CTX_SET_SESSION_CACHE_MODE(3ssl) OpenSSL SSL_CTX_SET_SESSION_CACHE_MODE(3ssl)

NOMBRE

SSL_CTX_set_session_cache_mode, SSL_CTX_get_session_cache_mode - habilitar/deshabilitar el almacenamiento en caché de sesiones

SINOPSIS

#include <openssl/ssl.h>
long SSL_CTX_set_session_cache_mode(SSL_CTX ctx, long mode);
long SSL_CTX_get_session_cache_mode(SSL_CTX ctx);

DESCRIPCIÓN

SSL_CTX_set_session_cache_mode() habilita/deshabilita el almacenamiento en caché de sesiones estableciendo el modo de operación para ctx a <mode>.

SSL_CTX_get_session_cache_mode() devuelve el modo de caché actualmente en uso.

NOTAS

La biblioteca OpenSSL puede almacenar/recuperar sesiones SSL/TLS para su reutilización posterior. Las sesiones se pueden mantener en memoria para cada ctx; si se mantienen varios objetos SSL_CTX, las sesiones son únicas para cada objeto SSL_CTX.

Para reutilizar una sesión, un cliente debe enviar el id de la sesión al servidor. Solo puede enviar exactamente un id. El servidor luego acepta reutilizar la sesión o inicia un handshake completo (para crear una nueva sesión).

Un servidor buscará la sesión en su almacenamiento de sesiones interno. Si la sesión no se encuentra en el almacenamiento interno o las búsquedas en el almacenamiento interno se han desactivado (SSL_SESS_CACHE_NO_INTERNAL_LOOKUP), el servidor intentará el almacenamiento externo si está disponible.

Dado que un cliente puede intentar reutilizar una sesión destinada a uso en un contexto diferente, el servidor debe establecer el contexto del id de la sesión (ver SSL_CTX_set_session_id_context(3)).

Los siguientes modos y modificadores de caché de sesiones están disponibles:

SSL_SESS_CACHE_OFF
No se realiza ningún almacenamiento en caché de sesiones para el cliente o el servidor.
SSL_SESS_CACHE_CLIENT
Las sesiones del cliente se añaden al caché de sesiones. Como no hay una manera fiable para que la biblioteca OpenSSL sepa si una sesión debe ser reutilizada o cuál sesión elegir (debido a la capa BIO abstracta, el motor SSL no tiene detalles sobre la conexión), la aplicación debe seleccionar la sesión a reutilizar utilizando la función SSL_set_session(3). Esta opción no está activada por defecto.
SSL_SESS_CACHE_SERVER
Las sesiones del servidor se añaden al caché de sesiones. Cuando un cliente propone una sesión para reutilizarla, el servidor busca la sesión correspondiente (primero) en el caché de sesiones interno (a menos que se establezca SSL_SESS_CACHE_NO_INTERNAL_LOOKUP), luego (segundo) en el caché externo si está disponible. Si se encuentra la sesión, el servidor intentará reutilizarla. Este es el valor predeterminado.
SSL_SESS_CACHE_BOTH
Habilita SSL_SESS_CACHE_CLIENT y SSL_SESS_CACHE_SERVER al mismo tiempo.
SSL_SESS_CACHE_NO_AUTO_CLEAR
Normalmente, el caché de sesiones se revisa en busca de sesiones caducadas cada 255 conexiones utilizando la función SSL_CTX_flush_sessions(3). Dado que esto puede provocar un retraso que no se puede controlar, la eliminación automática se puede deshabilitar y SSL_CTX_flush_sessions(3) puede ser llamada explícitamente por la aplicación.
SSL_SESS_CACHE_NO_INTERNAL_LOOKUP
Al establecer esta bandera, las operaciones de reanudación de sesiones en un servidor SSL/TLS no buscarán automáticamente las sesiones en el caché interno, incluso si las sesiones se almacenan allí automáticamente. Si se utilizan callbacks de almacenamiento en caché de sesiones externos, esta bandera garantiza que todas las búsquitas se dirijan al caché externo. Dado que la búsqueda automática solo se aplica a los servidores SSL/TLS, la bandera no tiene efecto en los clientes.
SSL_SESS_CACHE_NO_INTERNAL_STORE
Dependiendo de la presencia de SSL_SESS_CACHE_CLIENT y/o SSL_SESS_CACHE_SERVER, las sesiones negociadas en un handshake SSL/TLS pueden almacenarse en caché para su posible reutilización. Normalmente, una nueva sesión se añade al caché interno, así como a cualquier almacenamiento en caché de sesiones externo (callback) que esté configurado para SSL_CTX. Esta bandera evitará que las sesiones se almacenen en el caché interno (aunque la aplicación puede añadirlas manualmente usando SSL_CTX_add_session(3)). Nota: en cualquier servidor SSL/TLS donde esté configurado el almacenamiento externo en caché, cualquier búsqueda exitosa de sesiones en el caché externo (es decir, para solicitudes de reanudación de sesión) normalmente se copiaría en el caché local antes de que continúe el procesamiento; esta bandera también evita estas adiciones al caché interno.
SSL_SESS_CACHE_NO_INTERNAL
Habilita SSL_SESS_CACHE_NO_INTERNAL_LOOKUP y SSL_SESS_CACHE_NO_INTERNAL_STORE al mismo tiempo.
SSL_SESS_CACHE_UPDATE_TIME
Actualiza la marca de tiempo de la sesión cuando se utiliza, aumentando la vida útil de la sesión. El tiempo de espera de la sesión se aplica al último uso, en lugar de a la hora de creación.

El modo predeterminado es SSL_SESS_CACHE_SERVER.

VALORES DE RETORNO

SSL_CTX_set_session_cache_mode() devuelve el modo de caché establecido previamente.

SSL_CTX_get_session_cache_mode() devuelve el modo de caché actualmente establecido.
