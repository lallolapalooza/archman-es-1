SSL_CTX_set_ct_validation_callback(3ssl)

Paquete: openssl

Licencias: Apache-2.0

SSL_CTX_SET_CT_VALIDATION_CALLBACK(3ssl) OpenSSL SSL_CTX_SET_CT_VALIDATION_CALLBACK(3ssl)

NOMBRE

ssl_ct_validation_cb, SSL_enable_ct, SSL_CTX_enable_ct, SSL_disable_ct, SSL_CTX_disable_ct, SSL_set_ct_validation_callback, SSL_CTX_set_ct_validation_callback, SSL_ct_is_enabled, SSL_CTX_ct_is_enabled - controlar la política de validación de Transparencia de Certificados

SINOPSIS

#include <openssl/ssl.h>
typedef int (*ssl_ct_validation_cb)(const CT_POLICY_EVAL_CTX *ctx,
                                   const STACK_OF(SCT) *scts, void *arg);
int SSL_enable_ct(SSL *s, int validation_mode);
int SSL_CTX_enable_ct(SSL_CTX *ctx, int validation_mode);
int SSL_set_ct_validation_callback(SSL *s, ssl_ct_validation_cb callback,
                                   void *arg);
int SSL_CTX_set_ct_validation_callback(SSL_CTX *ctx,
                                       ssl_ct_validation_cb callback,
                                       void *arg);
void SSL_disable_ct(SSL *s);
void SSL_CTX_disable_ct(SSL_CTX *ctx);
int SSL_ct_is_enabled(const SSL *s);
int SSL_CTX_ct_is_enabled(const SSL_CTX *ctx);

DESCRIPCIÓN

SSL_enable_ct() y SSL_CTX_enable_ct() habilitan el procesamiento de marcas de tiempo de certificados firmados (SCTs) ya sea para una conexión SSL dada o para todas las conexiones que comparten el contexto SSL dado, respectivamente. Esto se logra estableciendo un callback de validación CT incorporado. El comportamiento del callback está determinado por el argumento validation_mode, que puede ser SSL_CT_VALIDATION_PERMISSIVE o SSL_CT_VALIDATION_STRICT, como se describe a continuación.

Si validation_mode es igual a SSL_CT_VALIDATION_STRICT, entonces en un handshake TLS completo con el modo de verificación establecido en SSL_VERIFY_PEER, si el par no presenta SCTs válidos, el handshake se abortará. Si el modo de verificación es SSL_VERIFY_NONE, el handshake continuará a pesar de la falta de SCTs válidos. Sin embargo, en ese caso, si el estado de verificación antes del callback incorporado era X509_V_OK, se establecerá en X509_V_ERR_NO_VALID_SCTS después del callback. Las aplicaciones pueden llamar a SSL_get_verify_result(3) para verificar el estado al completar el handshake, incluso después de la reanudación de la sesión, ya que el estado de verificación forma parte del estado guardado de la sesión. Ver SSL_set_verify(3), <SSL_get_verify_result(3)>, SSL_session_reused(3).

Si validation_mode es igual a SSL_CT_VALIDATION_PERMISSIVE, entonces el handshake continúa y el estado de verificación no se modifica, independientemente del estado de validación de cualquier SCT. La aplicación aún puede inspeccionar el estado de validación de los SCTs al completar el handshake. Tenga en cuenta que con la reanudación de la sesión no se presentarán SCTs durante el handshake. Por lo tanto, en aplicaciones que retrasan la aplicación de la política de SCT hasta después de completar el handshake, dichas verificaciones de SCT retardadas solo deben realizarse cuando la sesión no se reanuda.

SSL_set_ct_validation_callback() y SSL_CTX_set_ct_validation_callback() registran un callback personalizado que puede implementar una política diferente a cualquiera de las anteriores. Este callback puede examinar los SCTs del par y determinar si son suficientes para permitir que la conexión continúe. El handshake TLS se aborta si el modo de verificación no es SSL_VERIFY_NONE y el callback devuelve un resultado no positivo.

Se puede pasar un argumento de datos arbitrario para el callback, arg, al configurar el callback. Este se pasará al callback cada vez que se invoque. La propiedad de este contexto permanece con el llamador.

Si no se establece ningún callback, no se solicitarán SCTs y no se realizará la validación de Transparencia de Certificados.

No se invocará ningún callback cuando el par no presente un certificado, por ejemplo, empleando una suite de cifrado anónima (aNULL). En ese caso, el handshake continúa como lo haría si no se hubiera solicitado ningún callback. Los callbacks tampoco se invocan cuando la cadena de certificados del par no es válida o se valida a través de registros TLSA de DANE-TA(2) o DANE-EE(3) que utilizan una PKI X.509 privada, o ninguna PKI X.509 en absoluto, respectivamente. Se espera que los clientes que requieren SCTs no hayan habilitado cifrados aNULL ni hayan especificado la verificación del servidor a través de registros TLSA de DANE-TA(2) o DANE-EE(3).

SSL_disable_ct() y SSL_CTX_disable_ct() desactivan el procesamiento de CT, ya sea habilitado a través de los callbacks incorporados o personalizados, estableciendo un callback NULL. Estos pueden implementarse como macros.

SSL_ct_is_enabled() y SSL_CTX_ct_is_enabled() devuelven 1 si el procesamiento de CT está habilitado a través de SSL_enable_ct() o un callback personalizado no nulo, y 0 en caso contrario.

NOTAS

Cuando se habilita el procesamiento de SCT, se habilitará el "OCSP stapling". Esto se debe a que una posible fuente de SCTs es la respuesta OCSP de un servidor.

La hora devuelta por SSL_SESSION_get_time_ex() se utilizará para evaluar si las SCTs presentadas tienen marcas de tiempo que están en el futuro (y por lo tanto son inválidas).

RESTRICCIONES

La validación de Transparencia de Certificados no se puede habilitar y, por lo tanto, no se puede establecer un callback si se ha registrado un manejador de extensiones de cliente personalizado para manejar las extensiones SCT (TLSEXT_TYPE_signed_certificate_timestamp).

VALORES DE RETORNO

SSL_enable_ct(), SSL_CTX_enable_ct(), SSL_CTX_set_ct_validation_callback() y SSL_set_ct_validation_callback() devuelven 1 si el callback se establece correctamente. Devuelven 0 si ocurre un error, por ejemplo, si se ha configurado un manejador de extensiones de cliente personalizado para manejar las SCTs.

SSL_disable_ct() y SSL_CTX_disable_ct() no devuelven un resultado.

SSL_CTX_ct_is_enabled() y SSL_ct_is_enabled() devuelven un 1 si se establece un callback de validación CT no nulo, o 0 si no se establece ningún callback (o equivalentemente, un callback NULL).
