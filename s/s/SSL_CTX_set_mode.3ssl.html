SSL_CTX_set_mode(3ssl)

Paquete: openssl

Licencias: Apache-2.0

SSL_CTX_SET_MODE(3ssl) OpenSSL SSL_CTX_SET_MODE(3ssl)

NOMBRE

SSL_CTX_set_mode, SSL_CTX_clear_mode, SSL_set_mode, SSL_clear_mode, SSL_CTX_get_mode, SSL_get_mode - manipular el modo del motor SSL

SINOPSIS

#include <openssl/ssl.h>
long SSL_CTX_set_mode(SSL_CTX *ctx, long mode);
long SSL_CTX_clear_mode(SSL_CTX *ctx, long mode);
long SSL_set_mode(SSL *ssl, long mode);
long SSL_clear_mode(SSL *ssl, long mode);
long SSL_CTX_get_mode(SSL_CTX *ctx);
long SSL_get_mode(SSL *ssl);

DESCRIPCIÓN

SSL_CTX_set_mode() agrega el modo establecido por máscara de bits en mode a ctx. Las opciones ya establecidas previamente no se borran. SSL_CTX_clear_mode() elimina el modo establecido por máscara de bits en mode de ctx.

SSL_set_mode() agrega el modo establecido por máscara de bits en mode a ssl. Las opciones ya establecidas previamente no se borran. SSL_clear_mode() elimina el modo establecido por máscara de bits en mode de ssl.

SSL_CTX_get_mode() devuelve el modo establecido para ctx.

SSL_get_mode() devuelve el modo establecido para ssl.

NOTAS

Los siguientes cambios de modo están disponibles:

SSL_MODE_ENABLE_PARTIAL_WRITE
Permite que SSL_write_ex(..., n, &r) devuelva con 0 < r < n (es decir, informe de éxito cuando solo se ha escrito un registro). Esto funciona de manera similar para SSL_write(). Cuando no está configurado (por defecto), SSL_write_ex() o SSL_write() solo informarán de éxito una vez que se haya escrito el bloque completo. Una vez que SSL_write_ex() o SSL_write() devuelvan éxito, se habrán escrito r bytes y la próxima llamada a SSL_write_ex() o SSL_write() solo debe enviar los n-r bytes restantes, imitando el comportamiento de write().

Este modo no se puede habilitar mientras se está en medio de una operación de escritura incompleta.

SSL_MODE_ACCEPT_MOVING_WRITE_BUFFER
Hace posible reintentar SSL_write_ex() o SSL_write() con una ubicación de búfer cambiada (el contenido del búfer debe permanecer igual). Esto no es el valor por defecto para evitar la idea errónea de que SSL_write() no bloqueante se comporta como write() no bloqueante.
SSL_MODE_AUTO_RETRY
Durante las operaciones normales, es posible que se necesiten enviar o recibir registros que no son de datos de aplicación de los que la aplicación no es consciente. Si se procesó un registro que no es de datos de aplicación, SSL_read_ex(3) y SSL_read(3) pueden devolver un error e indicar la necesidad de reintentar con SSL_ERROR_WANT_READ. Si se procesó un registro de este tipo, el indicador SSL_MODE_AUTO_RETRY hace que intente procesar el siguiente registro en lugar de devolver.

En un entorno no bloqueante, las aplicaciones deben estar preparadas para manejar operaciones incompletas de lectura/escritura. Establecer SSL_MODE_AUTO_RETRY para un BIO no bloqueante procesará registros que no son de datos de aplicación hasta que no haya más datos disponibles o se haya procesado un registro de datos de aplicación.

En un entorno bloqueante, las aplicaciones no siempre están preparadas para lidiar con las funciones que devuelven informes intermedios, como solicitudes de reintento, y establecer el indicador SSL_MODE_AUTO_RETRY hará que las funciones solo devuelvan después de procesar con éxito un registro de datos de aplicación o un error.

Desactivar SSL_MODE_AUTO_RETRY puede ser útil con BIOs bloqueantes en caso de que se utilicen en combinación con algo como select() o poll(). De lo contrario, la llamada a SSL_read() o SSL_read_ex() podría bloquearse cuando se envió un registro que no es de datos de aplicación y no se enviaron datos de aplicación.

SSL_MODE_RELEASE_BUFFERS
Cuando ya no necesitamos un búfer de lectura o un búfer de escritura para un SSL dado, liberamos la memoria que estábamos usando para contenerlo. Usar este indicador puede ahorrar alrededor de 34k por conexión SSL inactiva. Este indicador no tiene efecto en las conexiones SSL v2 ni en las conexiones DTLS.
SSL_MODE_SEND_FALLBACK_SCSV
Envía TLS_FALLBACK_SCSV en el ClientHello. Debe ser establecido solo por aplicaciones que se reconectan con una versión de protocolo degradada; vea draft-ietf-tls-downgrade-scsv-00 para más detalles.

NO HABILITE ESTO si su aplicación intenta una conexión normal. Úselo solo en reintentos de fallback explícitos, siguiendo las instrucciones en draft-ietf-tls-downgrade-scsv-00.

SSL_MODE_ASYNC
Habilita el procesamiento asíncrono. Las operaciones de E/S TLS pueden indicar un reintento con SSL_ERROR_WANT_ASYNC con este modo activado si se utiliza un motor compatible con asincronía para realizar operaciones criptográficas. Vea SSL_get_error(3).
SSL_MODE_DTLS_SCTP_LABEL_LENGTH_BUG
Versiones anteriores de OpenSSL tenían un error en el cálculo de la longitud de la etiqueta utilizada para calcular el secreto compartido del par de puntos finales. El error era que el cero terminador se incluía en la longitud de la etiqueta. Establecer esta opción habilita este comportamiento para permitir la interoperabilidad con implementaciones defectuosas. Tenga en cuenta que establecer esta opción rompe la interoperabilidad con implementaciones correctas. Esta opción solo se aplica a DTLS sobre SCTP.

Todos los modos están desactivados por defecto, excepto SSL_MODE_AUTO_RETRY, que está activado por defecto desde 1.1.1.

VALORES DEVUELTOS

SSL_CTX_set_mode() y SSL_set_mode() devuelven la nueva máscara de bits de modo después de agregar mode.

SSL_CTX_get_mode() y SSL_get_mode() devuelven la máscara de bits actual.

VER TAMBIÉN

ssl(7), SSL_read_ex(3), SSL_read(3), SSL_write_ex(3) o SSL_write(3), SSL_get_error(3)

HISTORIA

SSL_MODE_ASYNC se añadió en OpenSSL 1.1.0.

NAME

SSL_CTX_set_mode - configurar modos de la cadena de certificados

SYNOPSIS

#include <openssl/ssl.h>

long SSL_CTX_set_mode(SSL_CTX *ctx, long mode);
long SSL_CTX_set_options(SSL_CTX *ctx, long options);
long SSL_CTX_clear_options(SSL_CTX *ctx, long options);
long SSL_CTX_set_flags(SSL_CTX *ctx, long flags);
long SSL_CTX_clear_flags(SSL_CTX *ctx, long flags);

DESCRIPTION

El método SSL_CTX_set_mode() establece varios modos que controlan el comportamiento de una struct SSL_CTX. Ver SSL_CTX_set_options para una lista de opciones disponibles y modos.

La función SSL_CTX_set_options() establece varias opciones en el struct SSL_CTX. La función SSL_CTX_clear_options() desactiva las opciones dadas en el struct SSL_CTX. La función SSL_CTX_set_flags() establece varias banderas en el struct SSL_CTX. La función SSL_CTX_clear_flags() desactiva las banderas dadas en el struct SSL_CTX. Las opciones son un conjunto de bits que modifican el comportamiento de OpenSSL.

RETURN VALUES

Las funciones SSL_CTX_set_mode(), SSL_CTX_set_options(), SSL_CTX_clear_options(), SSL_CTX_set_flags() y SSL_CTX_clear_flags() devuelven el valor anterior de los modos/opciones/banderas establecidos en el struct SSL_CTX.

NOTES

Las siguientes opciones están disponibles:

SSL_MODE_AUTO_RETRY
Hace que las operaciones de lectura y escritura que devuelven SSL_ERROR_WANT_READ o SSL_ERROR_WANT_WRITE intenten automáticamente la operación de nuevo. Esto puede ser útil en aplicaciones de un solo hilo para evitar tener que gestionar explícitamente estas condiciones de error. Sin embargo, puede causar problemas si el programa no puede proporcionar datos o consumir datos rápidamente, ya que puede entrar en un bucle infinito.
SSL_MODE_ENABLE_PARTIAL_WRITE
Permite escrituras parciales. Si una operación de escritura no puede escribir todos los datos solicitados en una sola llamada, no fallará, sino que devolverá el número de bytes que se pudieron escribir. El usuario es entonces responsable de llamar a SSL_write() de nuevo con los datos restantes.
SSL_MODE_ACCEPT_MOVING_WRITE_BUFFER
Permite que el búfer de escritura se mueva durante una operación de escritura. Esto puede ser útil en algunas situaciones, pero puede ser peligroso si no se maneja correctamente.
SSL_MODE_RELEASE_BUFFERS
Libera los búferes de lectura y escritura una vez que se han utilizado. Esto puede ayudar a reducir el uso de memoria en aplicaciones de larga duración.
SSL_MODE_SEND_FALLBACK_SCSV
Envía el valor SCSV de fallback en las ofertas de TLS. Esto ayuda a prevenir ataques de downgrade.
SSL_MODE_VERIFY_OPTIONAL
Hace que la verificación de certificados sea opcional. Esto significa que el cliente no necesita proporcionar un certificado al servidor, pero si lo hace, se verificará.
SSL_MODE_NO_AUTO_CHAIN
Desactiva la construcción automática de cadenas de certificados. En su lugar, se debe proporcionar la cadena completa.

Las siguientes opciones están disponibles para SSL_CTX_set_options(), SSL_CTX_clear_options(), SSL_CTX_set_flags() y SSL_CTX_clear_flags():

SSL_OP_CIPHER_RC4_MD5
Habilita RC4 con MD5. Esto está obsoleto y no se recomienda su uso.
SSL_OP_CISCO_ANYCONNECT
Habilita la compatibilidad con Cisco AnyConnect.
SSL_OP_COOKIE_EXCHANGE
Habilita el intercambio de cookies. Esto se utiliza en algunas implementaciones de DTLS.
SSL_OP_CRYPTOPRO_TLSEXT
Habilita la extensión TLSEXT de CryptoPro.
SSL_OP_DONT_INSERT_EMPTY_FRAGMENTS
Evita la inserción de fragmentos vacíos. Esto puede mejorar el rendimiento en algunas situaciones.
SSL_OP_EPHEMERAL_RND_SEQ
Habilita la secuencia aleatoria efímera. Esto se utiliza en algunas implementaciones de TLS.
SSL_OP_NO_SESSION_CACHE
Deshabilita la caché de sesiones. Esto significa que se establecerá una nueva sesión en cada conexión.
SSL_OP_NO_TICKETS
Deshabilita las sesiones de ticket. Esto significa que no se utilizarán tickets de sesión.
SSL_OP_TLS_DIVERSIFY_SERVER_NAME
Diversifica el nombre del servidor TLS. Esto puede ayudar a proteger contra ataques de denegación de servicio.
SSL_OP_TLS_ROLLBACK_BUG
Soluciona un error en TLS que puede permitir ataques de reversión.
SSL_OP_TLS_BLOCK_HOST_REDUCE_DECRYPTION
Bloquea la descifración de reducción de host TLS.
SSL_OP_NETSCAPE_CHALLENGE_BUG
Soluciona un error en Netscape que puede causar problemas con los desafíos.
SSL_OP_NETSCAPE_DEMO_REUSE_CERT_TYPE_BUG
Soluciona un error en Netscape que puede causar problemas con la reutilización de certificados.
SSL_OP_NETSCAPE_REUSE_CIPHER_CHANGE_BUG
Soluciona un error en Netscape que puede causar problemas con el cambio de cifrado.
SSL_OP_MICROSOFT_BIG_SSL_BIGNUM_BUG
Soluciona un error en Microsoft que puede causar problemas con los números grandes.
SSL_OP_MICROSOFT_BROWSER_COMPATIBILITYMODE
Habilita el modo de compatibilidad del navegador de Microsoft.
SSL_OP_MSIE_SSLV2_RSA_PADDING
Habilita el relleno RSA SSLv2 de MSIE.
SSL_OP_SSLEAY_080
Habilita SSLv3 para SSLeay 0.8.0.
SSL_OP_TLS_ROLLBACK_ATTACK_INVALID_RECORD
Mitiga los ataques de reversión TLS con registros no válidos.
SSL_OP_ALLOW_UNSAFE_LEGACY_RENEGOTIATION
Permite la renegociación insegura heredada. Esto puede ser necesario para la compatibilidad con sistemas más antiguos, pero no se recomienda su uso.
SSL_OP_ALL
Habilita todas las opciones disponibles.

EXAMPLE

Para habilitar SSL_MODE_AUTO_RETRY:

SSL_CTX_set_mode(ctx, SSL_MODE_AUTO_RETRY);

Para establecer múltiples opciones:

SSL_CTX_set_options(ctx, SSL_OP_NO_SESSION_CACHE | SSL_OP_NO_TICKETS);

Para limpiar una opción:

SSL_CTX_clear_options(ctx, SSL_OP_CISCO_ANYCONNECT);

HISTORY

La función SSL_CTX_set_mode() fue añadida en OpenSSL 0.9.8.

Las funciones SSL_CTX_set_options(), SSL_CTX_clear_options(), SSL_CTX_set_flags() y SSL_CTX_clear_flags() fueron añadidas en OpenSSL 1.0.0.
