SSL_CTX_set_domain_flags(3ssl)

Paquete: openssl

Licencias: Apache-2.0

SSL_CTX_SET_DOMAIN_FLAGS(3ssl) OpenSSL SSL_CTX_SET_DOMAIN_FLAGS(3ssl)

NOMBRE

SSL_CTX_set_domain_flags, SSL_CTX_get_domain_flags, SSL_get_domain_flags, SSL_DOMAIN_FLAG_SINGLE_THREAD, SSL_DOMAIN_FLAG_MULTI_THREAD, SSL_DOMAIN_FLAG_THREAD_ASSISTED, SSL_DOMAIN_FLAG_BLOCKING, SSL_DOMAIN_FLAG_LEGACY_BLOCKING - controlar el modelo de concurrencia utilizado por un dominio QUIC

SINOPSIS

#include <openssl/ssl.h>
#define SSL_DOMAIN_FLAG_SINGLE_THREAD
#define SSL_DOMAIN_FLAG_MULTI_THREAD
#define SSL_DOMAIN_FLAG_LEGACY_BLOCKING
#define SSL_DOMAIN_FLAG_BLOCKING
#define SSL_DOMAIN_FLAG_THREAD_ASSISTED
int SSL_CTX_set_domain_flags(SSL_CTX *ctx, uint64_t flags);
int SSL_CTX_get_domain_flags(SSL_CTX *ctx, uint64_t *flags);
int SSL_get_domain_flags(SSL *ssl, uint64_t *flags);

DESCRIPCIÓN

SSL_CTX_set_domain_flags() y SSL_CTX_get_domain_flags() establecen y obtienen las banderas del dominio QUIC en un SSL_CTX utilizando un SSL_METHOD QUIC. Estas banderas determinan el modelo de concurrencia que se utiliza para un dominio QUIC. Una introducción detallada a estos conceptos se puede encontrar en openssl-quic-concurrency(7).

Las aplicaciones pueden usar cualquiera de las banderas aquí:

SSL_DOMAIN_FLAG_SINGLE_THREAD
Especificar esta bandera configura el Modelo de Concurrencia de un Solo Hilo (SCM).
SSL_DOMAIN_FLAG_MULTI_THREAD
Especificar esta bandera configura el Modelo de Concurrencia Contenida (CCM) (a menos que también se especifique SSL_DOMAIN_FLAG_THREAD_ASSISTED).

Si OpenSSL se compiló sin soporte de hilos, esto es idéntico a SSL_DOMAIN_FLAG_SINGLE_THREAD.

SSL_DOMAIN_FLAG_THREAD_ASSISTED
Especificar esta bandera configura el Modelo de Concurrencia Asistido por Hilo (TACM). Implica SSL_DOMAIN_FLAG_MULTI_THREAD y SSL_DOMAIN_FLAG_BLOCKING.

Este modelo de concurrencia no está disponible si OpenSSL se compiló sin soporte de hilos, en cuyo caso intentar configurarlo resultará en un error.

SSL_DOMAIN_FLAG_BLOCKING
Habilita soporte fiable para llamadas de E/S bloqueantes, asignando los recursos del sistema operativo necesarios para realizarlo. Si se especifica esta bandera, se ignora SSL_DOMAIN_FLAG_LEGACY_BLOCKING.
SSL_DOMAIN_FLAG_LEGACY_BLOCKING
Habilita el modo de compatibilidad de bloqueo heredado. Ver "Soporte de Bloqueo Heredado" en openssl-quic-concurrency(7).

Las combinaciones de banderas mutuamente excluyentes resultan en un error (por ejemplo, combinar SSL_DOMAIN_FLAG_SINGLE_THREAD y SSL_DOMAIN_FLAG_MULTI_THREADED).

Dado que se debe elegir exactamente un modelo de concurrencia, las banderas del dominio no se pueden establecer en 0 y intentar hacerlo resultará en un error.

Cambiar estas banderas usando SSL_CTX_set_domain_flags() no tiene efecto en los dominios QUIC que ya han sido creados.

El conjunto predeterminado de banderas de dominio establecidas en un SSL_CTX recién creado puede variar según la versión de OpenSSL, el SSL_METHOD elegido y el entorno operativo. Ver openssl-quic-concurrency(7) para más detalles. Una aplicación puede recuperar las banderas de dominio predeterminadas llamando a SSL_CTX_get_domain_flags() inmediatamente después de construir un SSL_CTX.

SSL_get_domain_flags() recupera las banderas de dominio que son efectivas para un dominio QUIC cuando se llama en cualquier objeto SSL QUIC bajo ese dominio.

VALORES DE RETORNO

SSL_CTX_set_domain_flags(), SSL_CTX_get_domain_flags() y SSL_get_domain_flags() devuelven 1 en caso de éxito y 0 en caso de fallo.

SSL_CTX_set_domain_flags() falla si se llama con un conjunto de banderas que son inconsistentes o que no pueden ser soportadas dado el entorno actual.

SSL_CTX_set_domain_flags() y SSL_CTX_get_domain_flags() fallan si se llaman en un SSL_CTX que no está utilizando un SSL_METHOD QUIC.

SSL_get_domain_flags() falla si se llama en un objeto SSL no QUIC.

VER TAMBIÉN

SSL_new_domain(3), openssl-quic-concurrency(7)

HISTORIA

Estas funciones se añadieron en OpenSSL 3.5.
