SSL_CTX_set_tlsext_servername_callback(3ssl)

Paquete: openssl

Licencias: Apache-2.0

SSL_CTX_SET_TLSEXT_SERVERNAME_CALLBACK(3ssl) OpenSSL SSL_CTX_SET_TLSEXT_SERVERNAME_CALLBACK(3ssl)

NOMBRE

SSL_CTX_set_tlsext_servername_callback, SSL_CTX_set_tlsext_servername_arg, SSL_get_servername, SSL_get_servername_type, SSL_set_tlsext_host_name - manejar la indicación del nombre del servidor (SNI)

SINOPSIS

#include <openssl/ssl.h>
long SSL_CTX_set_tlsext_servername_callback(SSL_CTX *ctx,
                                  int (*cb)(SSL *s, int *al, void *arg));
long SSL_CTX_set_tlsext_servername_arg(SSL_CTX *ctx, void *arg);
const char *SSL_get_servername(const SSL *s, const int type);
int SSL_get_servername_type(const SSL *s);
int SSL_set_tlsext_host_name(const SSL *s, const char *name);

DESCRIPCIÓN

La funcionalidad proporcionada por la devolución de llamada de nombre de servidor está en gran medida reemplazada por la devolución de llamada de ClientHello, que se puede configurar usando SSL_CTX_set_client_hello_cb(). Sin embargo, incluso donde se utiliza la devolución de llamada de ClientHello, la devolución de llamada de nombre de servidor sigue siendo necesaria para reconocer el nombre del servidor solicitado por el cliente.

SSL_CTX_set_tlsext_servername_callback() establece la devolución de llamada de aplicación cb utilizada por un servidor para realizar cualquier acción o configuración requerida basada en la extensión de nombre de servidor recibida en la conexión entrante. Cuando cb es NULL, SNI no se utiliza.

La devolución de llamada de nombre de servidor debe devolver uno de los siguientes valores:

SSL_TLSEXT_ERR_OK
Esto se utiliza para indicar que el nombre del servidor solicitado por el cliente ha sido aceptado. Típicamente un servidor llamará SSL_set_SSL_CTX() en la devolución de llamada para configurar una configuración diferente para el nombre del servidor seleccionado en este caso.
SSL_TLSEXT_ERR_ALERT_FATAL
En este caso, el nombre del servidor solicitado por el cliente no es aceptado y el handshake se abortará. El valor de la alerta a utilizar debe almacenarse en la ubicación apuntada por el parámetro al de la devolución de llamada. Por defecto, este valor se inicializa a SSL_AD_UNRECOGNIZED_NAME.
SSL_TLSEXT_ERR_ALERT_WARNING
Si se devuelve este valor, el nombre del servidor no es aceptado por el servidor. Sin embargo, el handshake continuará y enviará una alerta de advertencia en su lugar. El valor de la alerta debe almacenarse en la ubicación apuntada por el parámetro al, como se indicó anteriormente para SSL_TLSEXT_ERR_ALERT_FATAL. Tenga en cuenta que TLSv1.3 no admite alertas de advertencia, por lo que si se ha negociado TLSv1.3, este valor de retorno se trata de la misma manera que SSL_TLSEXT_ERR_NOACK.
SSL_TLSEXT_ERR_NOACK
Este valor de retorno indica que el nombre del servidor no es aceptado por el servidor. No se envían alertas y el servidor no reconocerá el nombre del servidor solicitado.

SSL_CTX_set_tlsext_servername_arg() establece un argumento específico del contexto para pasar a la devolución de llamada (a través del parámetro arg) para este SSL_CTX.

El comportamiento de SSL_get_servername() depende de un número de factores diferentes. Tenga en cuenta en particular que en TLSv1.3 el nombre del servidor se negocia en cada handshake. En TLSv1.2, el nombre del servidor solo se negocia en los handshakes iniciales y no en los handshakes de reanudación.

En el cliente, antes del handshake
Si se ha establecido un nombre de servidor mediante una llamada a SSL_set_tlsext_host_name(), devolverá ese nombre de servidor.

Si no se ha establecido ninguno, pero se está intentando una reanudación de TLSv1.2 y la sesión del handshake original tenía un nombre de servidor aceptado por el servidor, entonces devolverá ese nombre de servidor.

De lo contrario, devuelve NULL.

En el cliente, durante o después del handshake y se produjo una reanudación de TLSv1.2 (o inferior)
Si la sesión del handshake original tenía un nombre de servidor aceptado por el servidor, entonces devolverá ese nombre de servidor.

De lo contrario, devuelve el nombre de servidor establecido mediante SSL_set_tlsext_host_name() o NULL si no se llamó.

En el cliente, durante o después del handshake y no se produjo una reanudación de TLSv1.2 (o inferior)
Devolverá el nombre de servidor establecido mediante SSL_set_tlsext_host_name() o NULL si no se llamó.
En el servidor, antes del handshake
La función siempre devolverá NULL antes del handshake.
En el servidor, después de haber procesado la extensión de nombre de servidor y se produjo una reanudación de TLSv1.2 (o inferior)
Si el servidor aceptó un nombre de servidor en el handshake original, entonces devolverá ese nombre de servidor, o NULL en caso contrario.
En el servidor, después de haber procesado la extensión de nombre de servidor y no se produjo una reanudación de TLSv1.2 (o inferior)
La función devolverá el nombre de servidor solicitado por el cliente en este handshake o NULL si no se solicitó ninguno.

Tenga en cuenta que la devolución de llamada de ClientHello se ejecuta antes de que se procese la extensión de nombre de servidor del cliente. Las devoluciones de llamada de nombre de servidor, certificado y ALPN se ejecutan después de que se procesa la extensión de nombre de servidor del cliente.

SSL_get_servername_type() devuelve el tipo de nombre de servidor o -1 si no hay ningún nombre de servidor presente. Actualmente, el único tipo admitido (definido en RFC3546) es TLSEXT_NAMETYPE_host_name.

SSL_set_tlsext_host_name() establece la extensión ClientHello de indicación del nombre del servidor para que contenga el valor name. El tipo de extensión de indicación del nombre del servidor se establece en TLSEXT_NAMETYPE_host_name (definido en RFC3546).

NOTAS

Varias devoluciones de llamada se ejecutan durante el procesamiento de ClientHello, incluidas las devoluciones de llamada de ClientHello, ALPN y nombre de servidor. La devolución de llamada de ClientHello se ejecuta primero, luego la devolución de llamada de nombre de servidor y, finalmente, la devolución de llamada de ALPN.

La función SSL_set_tlsext_host_name() solo debe llamarse en objetos SSL que actuarán como clientes; de lo contrario, el name configurado se ignorará.

VALORES DE RETORNO

SSL_CTX_set_tlsext_servername_callback() y SSL_CTX_set_tlsext_servername_arg() siempre devuelven 1 indicando éxito. SSL_set_tlsext_host_name() devuelve 1 en caso de éxito, 0 en caso de error.

VER TAMBIÉN

ssl(7), SSL_CTX_set_alpn_select_cb(3), SSL_get0_alpn_selected(3), SSL_CTX_set_client_hello_cb(3)

HISTORIA

SSL_get_servername() históricamente proporcionó algunos resultados inesperados en ciertos casos extremos. Esto se ha corregido a partir de OpenSSL 1.1.1e.

Antes de 1.1.1e, cuando el cliente solicitaba un nombre de servidor en un handshake inicial de TLSv1.2, el servidor lo aceptaba, y luego el cliente reanudaba con éxito pero establecía un nombre de servidor explícito diferente en el segundo handshake, entonces al ser llamado por el cliente, devolvía el nombre de servidor del segundo handshake. Esto ahora ha cambiado para devolver el nombre de servidor solicitado en el handshake original.

También antes de 1.1.1e, si el cliente enviaba un nombre de servidor en el primer handshake pero el servidor no lo aceptaba, y luego ocurría un segundo handshake donde la reanudación de TLSv1.2 era exitosa, entonces al ser llamado por el servidor devolvía el nombre de servidor solicitado en el handshake original. Esto ahora ha cambiado a NULL.
