SSL_CTX_set_generate_session_id(3ssl)

Paquete: openssl

Licencias: Apache-2.0

SSL_CTX_SET_GENERATE_SESSION_ID(3ssl) OpenSSL SSL_CTX_SET_GENERATE_SESSION_ID(3ssl)

NOMBRE

SSL_CTX_set_generate_session_id, SSL_set_generate_session_id, SSL_has_matching_session_id, GEN_SESSION_CB - manipula la generación de IDs de sesión SSL (solo servidor)

SINOPSIS

#include <openssl/ssl.h>
typedef int (*GEN_SESSION_CB)(SSL *ssl, unsigned char *id,
                              unsigned int *id_len);
int SSL_CTX_set_generate_session_id(SSL_CTX *ctx, GEN_SESSION_CB cb);
int SSL_set_generate_session_id(SSL *ssl, GEN_SESSION_CB, cb);
int SSL_has_matching_session_id(const SSL *ssl, const unsigned char *id,
                                unsigned int id_len);

DESCRIPCIÓN

SSL_CTX_set_generate_session_id() establece la función de callback para generar nuevos IDs de sesión para sesiones SSL/TLS para ctx como cb.

SSL_set_generate_session_id() establece la función de callback para generar nuevos IDs de sesión para sesiones SSL/TLS para ssl como cb.

SSL_has_matching_session_id() comprueba si una sesión con el ID id (de longitud id_len) ya está contenida en la caché interna de sesiones del contexto padre de ssl.

NOTAS

Cuando se establece una nueva sesión entre cliente y servidor, el servidor genera un ID de sesión. El ID de sesión es una secuencia arbitraria de bytes. La longitud del ID de sesión está entre 1 y 32 bytes. El ID de sesión no es crítico para la seguridad, pero debe ser único para el servidor. Además, el ID de sesión se transmite en claro al reutilizar la sesión, por lo que no debe contener información confidencial.

Sin una función de callback establecida, un servidor OpenSSL generará un ID de sesión único a partir de números pseudoaleatorios de la longitud máxima posible. Utilizando la función de callback, el ID de sesión puede modificarse para contener información adicional, como por ejemplo un ID de host, para mejorar el balanceo de carga o las técnicas de caché externas.

La función de callback recibe un puntero a la ubicación de memoria donde colocar id y un puntero a la longitud máxima permitida id_len. El búfer en la ubicación id solo está garantizado que tenga el tamaño id_len. La función de callback solo tiene permitido generar un ID más corto y reducir id_len; la función de callback **nunca debe** aumentar id_len o escribir en la ubicación id excediendo el límite dado.

La ubicación id se rellena con 0x00 antes de llamar a la función de callback, por lo que la función de callback solo puede rellenar parte de la longitud posible y dejar id_len sin cambios, manteniendo la reproducibilidad.

Dado que las sesiones deben distinguirse, los IDs de sesión deben ser únicos. Sin la función de callback se utiliza un número aleatorio, de modo que la probabilidad de generar el mismo ID de sesión es extremadamente pequeña (2^256 para SSLv3/TLSv1). Para asegurar la unicidad del ID de sesión generado, la función de callback debe llamar a SSL_has_matching_session_id() y generar otro ID si ocurre un conflicto. Si no se resuelve un conflicto de ID, el handshake fallará. Si la aplicación codifica, por ejemplo, un ID de host único, un número de proceso único y un número de secuencia único en el ID de sesión, la unicidad podría lograrse fácilmente sin añadir aleatoriedad (sin embargo, se debe tener cuidado de no filtrar información confidencial de esta manera). Si la aplicación no puede garantizar la unicidad, se recomienda utilizar la longitud máxima id_len y rellenar los bytes no utilizados para codificar información especial con datos aleatorios para evitar colisiones.

SSL_has_matching_session_id() solo consultará la caché de sesiones interna, no la externa. Dado que el ID de sesión se genera antes de que se complete el handshake, no se añade inmediatamente a la caché. Si otro hilo está utilizando la misma caché de sesiones interna, puede ocurrir una condición de carrera en la que otro hilo genere el mismo ID de sesión. Las colisiones también pueden ocurrir al usar una caché de sesiones externa, ya que la caché externa no se comprueba con SSL_has_matching_session_id() y se aplica la misma condición de carrera.

La función de callback debe devolver 0 si no puede generar un ID de sesión por cualquier motivo y devolver 1 en caso de éxito.

VALORES DE RETORNO

SSL_CTX_set_generate_session_id() y SSL_set_generate_session_id() devuelven 1 en caso de éxito y 0 en caso de fallo.

SSL_has_matching_session_id() devuelve 1 si ya existe otra sesión con el mismo ID en la caché, o 0 en caso contrario.

EJEMPLOS

La función de callback que se muestra generará un ID de sesión con el prefijo de servidor dado y rellenará el resto con bytes pseudoaleatorios:

const char session_id_prefix = "www-18";
#define MAX_SESSION_ID_ATTEMPTS 10
static int generate_session_id(SSL *ssl, unsigned char *id,
                               unsigned int *id_len)
{
    unsigned int count = 0;
    do {
        RAND_pseudo_bytes(id, *id_len);
        /*
         * Prefija el session_id con el prefijo requerido. NB: Si nuestro
         * prefijo es demasiado largo, se recorta - pero habrá efectos peores
         * de todos modos, por ejemplo, el servidor solo podría crear 1
         * ID de sesión (es decir, ¡el prefijo!) por lo que todas las futuras
         * negociaciones de sesión fallarán debido a conflictos.
         */
        memcpy(id, session_id_prefix, strlen(session_id_prefix) < *id_len ?
                                      strlen(session_id_prefix) : *id_len);
    } while (SSL_has_matching_session_id(ssl, id, *id_len)
              && ++count < MAX_SESSION_ID_ATTEMPTS);
    if (count >= MAX_SESSION_ID_ATTEMPTS)
        return 0;
    return 1;
}
