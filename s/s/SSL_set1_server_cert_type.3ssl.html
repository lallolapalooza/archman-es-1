SSL_set1_server_cert_type(3ssl)

Paquete: openssl

Licencias: Apache-2.0

SSL_SET1_SERVER_CERT_TYPE(3ssl) OpenSSL SSL_SET1_SERVER_CERT_TYPE(3ssl)

NOMBRE

SSL_set1_client_cert_type, SSL_set1_server_cert_type, SSL_CTX_set1_client_cert_type, SSL_CTX_set1_server_cert_type, SSL_get0_client_cert_type, SSL_get0_server_cert_type, SSL_CTX_get0_client_cert_type, SSL_CTX_get0_server_cert_type - soporte para el tipo de certificado (RFC7250)

SINOPSIS

#include <openssl/ssl.h>
int SSL_set1_client_cert_type(SSL *s, const unsigned char *val, size_t len);
int SSL_set1_server_cert_type(SSL *s, const unsigned char *val, size_t len);
int SSL_CTX_set1_client_cert_type(SSL_CTX *ctx, const unsigned char *val, size_t len);
int SSL_CTX_set1_server_cert_type(SSL_CTX *ctx, const unsigned char *val, size_t len);
int SSL_get0_client_cert_type(const SSL *s, unsigned char **val, size_t *len);
int SSL_get0_server_cert_type(const SSL *s, unsigned char **val, size_t *len);
int SSL_CTX_get0_client_cert_type(const SSL_CTX *ctx, unsigned char **val, size_t *len);
int SSL_CTX_get0_server_cert_type(const SSL_CTX *s, unsigned char **val, size_t *len);

DESCRIPCIÓN

Las funciones SSL_set1_client_cert_type() y SSL_CTX_set1_client_cert_type() establecen los valores para la extensión del tipo de certificado de cliente. Las funciones SSL_get0_client_cert_type() y SSL_CTX_get0_client_cert_type() recuperan los valores locales que se utilizarán en la extensión del tipo de certificado de cliente.

Las funciones SSL_set1_server_cert_type() y SSL_CTX_set1_server_cert_type() establecen los valores para la extensión del tipo de certificado de servidor. Las funciones SSL_get0_server_cert_type() y SSL_CTX_get0_server_cert_type() recuperan los valores locales que se utilizarán en la extensión del tipo de certificado de servidor.

NOTAS

Las extensiones de tipo de certificado se utilizan para negociar el tipo de certificado que se utilizará en el handshake. Estas extensiones permiten que cada lado sepa lo que su interlocutor puede aceptar.

El tipo de certificado del cliente se envía desde el cliente al servidor para indicar los tipos de certificado que el cliente puede presentar. Los valores se configuran en orden de preferencia. En el servidor, esta configuración determina qué tipos de certificado está dispuesto a aceptar el servidor. El servidor elige finalmente qué tipo solicitar (si lo hay) de los valores que son mutuamente compatibles. Por defecto (si no se especifican configuraciones explícitas), solo se admiten certificados X.509.

El tipo de certificado del servidor se envía desde el cliente al servidor para indicar qué tipos de certificado acepta el cliente. Los valores se configuran en orden de preferencia. En el servidor, esta configuración determina qué tipos de certificado está dispuesto a presentar el servidor. El servidor elige finalmente qué tipo utilizar de los valores que son mutuamente compatibles. Por defecto (si no se especifican configuraciones explícitas), solo se admiten certificados X.509.

Tener RPK especificado primero significa que ese lado intentará enviar (o solicitar) RPK si su interlocutor también admite RPK, de lo contrario se utilizará un certificado X.509 si ambos lo han especificado (o no han configurado estas opciones).

Los dos valores admitidos en la matriz val son:

TLSEXT_cert_type_x509
Que corresponde a un certificado X.509 utilizado normalmente en TLS.
TLSEXT_cert_type_rpk
Que corresponde a una clave pública en bruto.

Si val se establece en un valor distinto de NULL, la extensión se envía en el handshake. Si val se establece en un valor NULL (y len es 0), la extensión se deshabilita. El valor predeterminado es NULL, lo que significa que la extensión no se envía y se utilizan certificados X.509 en el handshake.

Las claves públicas en bruto pueden utilizarse en lugar de certificados cuando se especifican en el tipo de certificado y se negocian. Las claves públicas en bruto no tienen sujeto, emisor, fechas de validez ni firma digital.

Utilice las funciones SSL_get_negotiated_client_cert_type(3) y SSL_get_negotiated_server_cert_type(3) para obtener los valores negociados del tipo de certificado (al concluir el handshake, o en callbacks que ocurren después de que se haya procesado el TLS ServerHello).

VALORES DE RETORNO

Todas las funciones devuelven 1 en caso de éxito y 0 en caso de fallo.

La memoria devuelta por las funciones get0 no debe liberarse.

EJEMPLOS

Para usar claves públicas en bruto en el servidor, configure el SSL_CTX y SSL de la siguiente manera:

SSL_CTX *ctx;
SSL *ssl;
unsigned char cert_type[] = { TLSEXT_cert_type_rpk, TLSEXT_cert_type_x509 };
EVP_PKEY *rpk;
/* Asignar rpk a un EVP_PKEY desde un archivo u otro medio */
if ((ctx = SSL_CTX_new(TLS_server_method())) == NULL)
    /* error */
if ((ssl = SSL_new(ctx)) == NULL)
    /* error */
if (!SSL_set1_server_cert_type(ssl, cert_type, sizeof(cert_type)))
    /* error */
/* No es necesario especificar un certificado al usar claves públicas en bruto */
if (!SSL_use_PrivateKey(ssl, rpk))
    /* error */
/* Realizar operaciones SSL_accept() */

Para conectarse a este servidor, configure el SSL_CTX y SSL del cliente de la siguiente manera:

/* Función de conexión */
SSL_CTX *ctx;
SSL *ssl;
const char *dane_tlsa_domain = "smtp.example.com";
unsigned char cert_type[] = { TLSEXT_cert_type_rpk, TLSEXT_cert_type_x509 };
EVP_PKEY *rpk;
int verify_result;
/* Asignar rpk a un EVP_PKEY desde un archivo u otro medio */
if ((ctx = SSL_CTX_new(TLS_client_method())) == NULL)
    /* error */
if (SSL_CTX_dane_enable(ctx) <= 0)
    /* error */
if ((ssl = SSL_new(ctx)) == NULL)
    /* error */
/*
 * El argumento `dane_tlsa_domain` establece el nombre de host SNI predeterminado.
 * Puede establecerse en NULL al habilitar DANE en el lado del servidor.
 */
if (SSL_dane_enable(ssl, dane_tlsa_domain) <= 0)
    /* error */
if (!SSL_set1_server_cert_type(ssl, cert_type, sizeof(cert_type)))
    /* error */
if (!SSL_add_expected_rpk(ssl, rpk))
    /* error */
/* Realizar handshake SSL_connect() y manejar errores aquí */
/* Opcional: verificar el RPK del par */
verify_result = SSL_get_verify_result(ssl);
if (verify_result == X509_V_OK) {
    /* La clave pública en bruto del servidor coincidió con el registro TLSA */
} else if (verify_result == X509_V_ERR_DANE_NO_MATCH) {
    /*
     * La clave pública en bruto del servidor, o la clave pública en el
     * certificado, no coincidió con el registro TLSA
     */
} else if (verify_result == X509_V_ERR_RPK_UNTRUSTED) {
    /*
     * No hay registros TLSA del tipo correcto disponibles para verificar la
     * clave pública en bruto del servidor. Esto no sucedería en este ejemplo,
     * ya que se está configurando un registro TLSA.
     */
} else {
    /* Algún otro error de verificación */
}

Para validar claves públicas en bruto de clientes, el código del ejemplo del cliente puede necesitar ser incorporado en el lado del servidor.
