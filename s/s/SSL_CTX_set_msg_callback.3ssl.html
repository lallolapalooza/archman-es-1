SSL_CTX_set_msg_callback(3ssl)

Paquete: openssl

Licencias: Apache-2.0

SSL_CTX_SET_MSG_CALLBACK(3ssl) OpenSSL SSL_CTX_SET_MSG_CALLBACK(3ssl)

NOMBRE

SSL_CTX_set_msg_callback, SSL_CTX_set_msg_callback_arg, SSL_set_msg_callback, SSL_set_msg_callback_arg, SSL_trace - instalar una función de devolución de llamada para observar mensajes del protocolo

SINOPSIS

#include <openssl/ssl.h>
void SSL_CTX_set_msg_callback(SSL_CTX *ctx,
                              void (*cb)(int write_p, int version,
                                         int content_type, const void *buf,
                                         size_t len, SSL *ssl, void *arg));
void SSL_CTX_set_msg_callback_arg(SSL_CTX *ctx, void *arg);
void SSL_set_msg_callback(SSL *ssl,
                          void (*cb)(int write_p, int version,
                                     int content_type, const void *buf,
                                     size_t len, SSL *ssl, void *arg));
void SSL_set_msg_callback_arg(SSL *ssl, void *arg);
void SSL_trace(int write_p, int version, int content_type,
               const void *buf, size_t len, SSL *ssl, void *arg);

DESCRIPCIÓN

SSL_CTX_set_msg_callback() o SSL_set_msg_callback() se pueden usar para definir una función de devolución de llamada de mensajes cb para observar todos los mensajes del protocolo SSL/TLS/QUIC (como mensajes de handshake) que se reciben o envían, así como otros eventos que ocurren durante el procesamiento. SSL_CTX_set_msg_callback_arg() y SSL_set_msg_callback_arg() se pueden usar para establecer el argumento arg para la función de devolución de llamada, que está disponible para uso arbitrario de la aplicación.

SSL_CTX_set_msg_callback() y SSL_CTX_set_msg_callback_arg() especifican configuraciones predeterminadas que se copiarán a nuevos objetos SSL por SSL_new(3). SSL_set_msg_callback() y SSL_set_msg_callback_arg() modifican la configuración real de un objeto SSL. Usar un puntero NULL para cb deshabilita la devolución de llamada de mensajes.

Cuando la biblioteca SSL/TLS/QUIC llama a cb, los argumentos de la función tienen el siguiente significado:

write_p
Esta bandera es 0 cuando se ha recibido un mensaje del protocolo y 1 cuando se ha enviado un mensaje del protocolo.
version
La versión del protocolo según la cual el mensaje del protocolo es interpretado por la biblioteca, como TLS1_3_VERSION, TLS1_2_VERSION, OSSL_QUIC1_VERSION etc. Para el tipo de contenido pseudo SSL3_RT_HEADER (ver NOTAS abajo) este valor será el campo decodificado version/legacy_version de la cabecera del registro.
content_type
Este es uno de los valores de tipo de contenido definidos en la especificación del protocolo (SSL3_RT_CHANGE_CIPHER_SPEC, SSL3_RT_ALERT, SSL3_RT_HANDSHAKE; pero nunca SSL3_RT_APPLICATION_DATA porque la devolución de llamada solo se llamará para mensajes del protocolo). Alternativamente, puede ser un tipo de contenido "pseudo". Estos tipos de contenido pseudo se usan para señalar algún otro evento en el procesamiento de datos (ver NOTAS abajo).
buf, len
buf apunta a un búfer que contiene el mensaje del protocolo u otros datos (en el caso de tipos de contenido pseudo), que consta de len bytes. El búfer ya no es válido después de que la función de devolución de llamada haya regresado.
ssl
El objeto SSL que recibió o envió el mensaje.
arg
El argumento definido por el usuario definido opcionalmente por SSL_CTX_set_msg_callback_arg() o SSL_set_msg_callback_arg().

La función SSL_trace() se puede usar como una devolución de llamada preescrita en una llamada a SSL_CTX_set_msg_callback() o SSL_set_msg_callback(). Requiere que un BIO se establezca como argumento de devolución de llamada a través de SSL_CTX_set_msg_callback_arg() o SSL_set_msg_callback_arg(). Establecer esta devolución de llamada hará que la información de rastreo de diagnóstico legible por humanos sobre una conexión SSL/TLS/QUIC se escriba en el BIO.

NOTAS

Los mensajes del protocolo se pasan a la función de devolución de llamada después de la descifrado y la recopilación de fragmentos, donde corresponda. (Por lo tanto, los límites de los registros no son visibles).

Si el procesamiento de un mensaje del protocolo recibido resulta en un error, es posible que la función de devolución de llamada no se llame. Por ejemplo, la función de devolución de llamada nunca verá mensajes que se consideren demasiado grandes para ser procesados.

Debido a la negociación automática de la versión del protocolo, version no es necesariamente la versión del protocolo utilizada por el remitente del mensaje: si un servidor solo SSL 3.0 recibe un mensaje ClientHello de TLS 1.0, version será SSL3_VERSION.

Los valores de tipo de contenido pseudo se pueden enviar en varios momentos durante el procesamiento de datos. Los siguientes tipos de contenido pseudo están definidos actualmente:

SSL3_RT_HEADER
Se usa cuando se envía o recibe un registro TLS. El buf contiene solo los bytes de la cabecera del registro.
SSL3_RT_INNER_CONTENT_TYPE
Se usa cuando se envía o recibe un registro TLSv1.3 cifrado. En los registros TLSv1.3 cifrados, el tipo de contenido en la cabecera del registro es siempre SSL3_RT_APPLICATION_DATA. El tipo de contenido real para el registro está contenido en un tipo de contenido "interno". El buf contiene el byte del tipo de contenido "interno" codificado.
SSL3_RT_QUIC_DATAGRAM
Se usa cuando se envía o recibe un datagrama QUIC.
SSL3_RT_QUIC_PACKET
Se usa cuando se envía o recibe un paquete QUIC.
SSL3_RT_QUIC_FRAME_FULL
Se usa cuando se envía o recibe un frame QUIC. Esto solo se usa para frames que no son de datos de control o de stream. Se suministran todos los datos del frame QUIC.
SSL3_RT_QUIC_FRAME_HEADER
Se usa cuando se envía o recibe un frame de stream o de control QUIC. Solo se suministran los datos de la cabecera del frame QUIC.
SSL3_RT_QUIC_FRAME_PADDING
Se usa cuando se envía o recibe una secuencia de uno o más frames de relleno QUIC. Un frame de relleno consta de un solo byte y es común tener múltiples frames de este tipo en una secuencia. En lugar de suministrar cada frame individualmente, la devolución de llamada suministrará todos los frames de relleno a la vez a través de este tipo de contenido pseudo.

VALORES DE RETORNO

SSL_CTX_set_msg_callback(), SSL_CTX_set_msg_callback_arg(), SSL_set_msg_callback() y SSL_set_msg_callback_arg() no devuelven valores.

VER TAMBIÉN

ssl(7), SSL_new(3)

HISTORIA

El tipo de contenido pseudo SSL3_RT_INNER_CONTENT_TYPE se agregó en OpenSSL 1.1.1.

Los tipos de contenido pseudo SSL3_RT_QUIC_DATAGRAM, SSL3_RT_QUIC_PACKET, SSL3_RT_QUIC_FRAME_FULL, SSL3_RT_QUIC_FRAME_HEADER y SSL3_RT_QUIC_FRAME_PADDING se agregaron en OpenSSL 3.2.

En versiones anteriores a OpenSSL 3.0, cb se llamaba con 0 como version para el tipo de contenido pseudo SSL3_RT_HEADER para registros TLS.

En versiones anteriores a OpenSSL 3.2, cb se llamaba con 0 como version para el tipo de contenido pseudo SSL3_RT_HEADER para registros DTLS.

SSL_CTX_set_msg_callback(3ssl)

NAME

SSL_CTX_set_msg_callback, SSL_CTX_get_msg_callback - set and get the SSL message callback

SYNOPSIS

#include <openssl/ssl.h>

void SSL_CTX_set_msg_callback(SSL_CTX *ctx,
                              void (*callback)(int, int, void *, int, void *, void *));

SSL_CTX_msg_callback_func *SSL_CTX_get_msg_callback(const SSL_CTX *ctx);

DESCRIPTION

The SSL message callback is a callback function that gets invoked by OpenSSL when certain SSL events occur. The callback function is set using SSL_CTX_set_msg_callback(). The callback function is of type SSL_CTX_msg_callback_func, which is defined as:

typedef void (*SSL_CTX_msg_callback_func)(int write_p, int version, int content_type, const void *buf, size_t len, void *arg);
  • write_p: Is 1 if the message is being written, and 0 if it is being read.
  • version: The SSL/TLS protocol version of the message. This is a numerical value, e.g. TLS1_2_VERSION.
  • content_type: The content type of the message. This is a numerical value, e.g. TLS1_RT_HANDSHAKE.
  • buf: A pointer to the message data.
  • len: The length of the message data.
  • arg: The arbitrary argument passed to SSL_CTX_set_msg_callback().

The SSL_CTX_get_msg_callback() function retrieves the currently set message callback function.

NOTES

The message callback is called for all SSL records processed by OpenSSL. This includes handshake messages, application data, alerts, etc. The callback is called before the data is processed or sent. This can be useful for debugging or for implementing custom logic based on SSL/TLS traffic.

The message callback should not block or perform any operations that could interfere with the SSL/TLS handshake or data transfer. It should be as fast as possible.

The callback is called with the arg pointer that was passed to SSL_CTX_set_msg_callback().

RETURN VALUES

SSL_CTX_get_msg_callback() returns the currently set message callback function, or NULL if no callback is set.

SEE ALSO

SSL_CTX_new(3ssl), SSL_set_msg_callback(3ssl)

HISTORY

The callback mechanism was introduced in OpenSSL 1.0.1.
