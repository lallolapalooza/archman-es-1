SSL_CTX_use_psk_identity_hint(3ssl)

Paquete: openssl

Licencias: Apache-2.0

SSL_CTX_USE_PSK_IDENTITY_HINT(3ssl) OpenSSL SSL_CTX_USE_PSK_IDENTITY_HINT(3ssl)

NOMBRE

SSL_psk_server_cb_func, SSL_psk_find_session_cb_func, SSL_CTX_use_psk_identity_hint, SSL_use_psk_identity_hint, SSL_CTX_set_psk_server_callback, SSL_set_psk_server_callback, SSL_CTX_set_psk_find_session_callback, SSL_set_psk_find_session_callback - establecer la pista de identidad PSK a usar

SINOPSIS

#include <openssl/ssl.h>
typedef int (*SSL_psk_find_session_cb_func)(SSL *ssl,
                                            const unsigned char *identity,
                                            size_t identity_len,
                                            SSL_SESSION **sess);
void SSL_CTX_set_psk_find_session_callback(SSL_CTX *ctx,
                                           SSL_psk_find_session_cb_func cb);
void SSL_set_psk_find_session_callback(SSL *s, SSL_psk_find_session_cb_func cb);
typedef unsigned int (*SSL_psk_server_cb_func)(SSL *ssl,
                                               const char *identity,
                                               unsigned char *psk,
                                               unsigned int max_psk_len);
int SSL_CTX_use_psk_identity_hint(SSL_CTX *ctx, const char *hint);
int SSL_use_psk_identity_hint(SSL *ssl, const char *hint);
void SSL_CTX_set_psk_server_callback(SSL_CTX *ctx, SSL_psk_server_cb_func cb);
void SSL_set_psk_server_callback(SSL *ssl, SSL_psk_server_cb_func cb);

DESCRIPCIÓN

Una aplicación de servidor que desee usar PSKs de TLSv1.3 debe establecer una devolución de llamada utilizando SSL_CTX_set_psk_find_session_callback() o SSL_set_psk_find_session_callback() según corresponda.

La función de devolución de llamada recibe un puntero a la conexión SSL en ssl y una identidad en identity de longitud identity_len. La función de devolución de llamada debe identificar un objeto SSL_SESSION que proporcione los detalles del PSK y almacenarlo en *sess. El objeto SSL_SESSION debe, como mínimo, establecer la clave maestra, la suite de cifrado y la versión del protocolo. Consulte SSL_CTX_set_psk_use_session_callback(3) para obtener más detalles.

También es posible que la devolución de llamada tenga éxito pero no suministre un PSK. En este caso, no se utilizará ningún PSK, pero el handshake continuará. Para hacer esto, la devolución de llamada debe retornar con éxito y asegurarse de que *sess sea NULL.

Las pistas de identidad no son relevantes para TLSv1.3. Una aplicación de servidor que desee utilizar suites de cifrado PSK para TLSv1.2 y versiones anteriores puede llamar a SSL_CTX_use_psk_identity_hint() para establecer la pista de identidad PSK NUL-terminada dada hint para el objeto de contexto SSL ctx. SSL_use_psk_identity_hint() establece la pista de identidad PSK NUL-terminada dada hint para el objeto de conexión SSL ssl. Si hint es NULL, se elimina la pista actual de ctx o ssl.

En el caso de que la pista de identidad PSK sea NULL, el servidor no envía el mensaje ServerKeyExchange al cliente.

Una aplicación de servidor que desee utilizar PSKs para TLSv1.2 y versiones anteriores debe proporcionar una función de devolución de llamada que se llama cuando el servidor recibe el mensaje ClientKeyExchange del cliente. El propósito de la función de devolución de llamada es validar la identidad PSK recibida y obtener la clave precompartida utilizada durante la fase de configuración de la conexión. La devolución de llamada se establece utilizando las funciones SSL_CTX_set_psk_server_callback() o SSL_set_psk_server_callback(). La función de devolución de llamada recibe la conexión en el parámetro ssl, la identidad PSK NUL-terminada enviada por el cliente en el parámetro identity, y un búfer psk de longitud max_psk_len bytes donde se almacenará la clave precompartida.

La devolución de llamada para uso en TLSv1.2 también funcionará en TLSv1.3, aunque se recomienda utilizar SSL_CTX_set_psk_find_session_callback() o SSL_set_psk_find_session_callback() para este propósito en su lugar. Si se ha negociado TLSv1.3, OpenSSL primero comprobará si se ha establecido una devolución de llamada a través de SSL_CTX_set_psk_find_session_callback() o SSL_set_psk_find_session_callback() y la utilizará con preferencia. Si no hay ninguna devolución de llamada de este tipo presente, comprobará si se ha establecido una devolución de llamada a través de SSL_CTX_set_psk_server_callback() o SSL_set_psk_server_callback() y la utilizará. En este caso, el resumen del handshake se establecerá por defecto en SHA-256 para cualquier PSK devuelto. Los intercambios de datos tempranos de TLSv1.3 solo son posibles en conexiones PSK con la devolución de llamada SSL_psk_find_session_cb_func, y no son posibles con la devolución de llamada SSL_psk_server_cb_func.

Una conexión establecida a través de un PSK TLSv1.3 aparecerá como si se hubiera producido una reanudación de sesión, de modo que SSL_session_reused(3) devolverá true.

VALORES DE RETORNO

SSL_CTX_use_psk_identity_hint() y SSL_use_psk_identity_hint() devuelven 1 en caso de éxito, 0 en caso contrario.

Los valores de retorno de la devolución de llamada del servidor TLSv1.2 y anteriores se interpretan de la siguiente manera:

0
No se encontró la identidad PSK. Se enviará un mensaje de alerta "unknown_psk_identity" y la configuración de la conexión fallará.
>0
Se encontró la identidad PSK y la devolución de llamada del servidor ha proporcionado el PSK con éxito en el parámetro psk. El valor de retorno es la longitud de psk en bytes. Es un error devolver un valor mayor que max_psk_len.

Si no se encontró la identidad PSK pero la devolución de llamada indica al protocolo que continúe de todos modos, la devolución de llamada debe proporcionar algunos datos aleatorios a psk y devolver la longitud de los datos aleatorios, de modo que la conexión falle con decryption_error antes de que se complete por completo.

La devolución de llamada SSL_psk_find_session_cb_func debe devolver 1 en caso de éxito o 0 en caso de fallo. En caso de fallo, la configuración de la conexión falla.

NOTAS

No se conocen problemas de seguridad al compartir el mismo PSK entre TLSv1.2 (o inferior) y TLSv1.3. Sin embargo, la RFC tiene esta nota de precaución:

"Aunque no se conoce ninguna forma en la que el mismo PSK pueda producir una salida relacionada en ambas versiones, solo se ha realizado un análisis limitado. Las implementaciones pueden garantizar la seguridad contra la salida relacionada entre protocolos no reutilizando PSKs entre TLS 1.3 y TLS 1.2."
