SSL_CTX_add1_chain_cert(3ssl)

Paquete: openssl

Licencias: Apache-2.0

SSL_CTX_ADD1_CHAIN_CERT(3ssl) OpenSSL SSL_CTX_ADD1_CHAIN_CERT(3ssl)

NOMBRE

SSL_CTX_set0_chain, SSL_CTX_set1_chain, SSL_CTX_add0_chain_cert, SSL_CTX_add1_chain_cert, SSL_CTX_get0_chain_certs, SSL_CTX_clear_chain_certs, SSL_set0_chain, SSL_set1_chain, SSL_add0_chain_cert, SSL_add1_chain_cert, SSL_get0_chain_certs, SSL_clear_chain_certs, SSL_CTX_build_cert_chain, SSL_build_cert_chain, SSL_CTX_select_current_cert, SSL_select_current_cert, SSL_CTX_set_current_cert, SSL_set_current_cert - procesamiento adicional de certificados de cadena

SINOPSIS

#include <openssl/ssl.h>
int SSL_CTX_set0_chain(SSL_CTX *ctx, STACK_OF(X509) *sk);
int SSL_CTX_set1_chain(SSL_CTX *ctx, STACK_OF(X509) *sk);
int SSL_CTX_add0_chain_cert(SSL_CTX *ctx, X509 *x509);
int SSL_CTX_add1_chain_cert(SSL_CTX *ctx, X509 *x509);
int SSL_CTX_get0_chain_certs(SSL_CTX *ctx, STACK_OF(X509) **sk);
int SSL_CTX_clear_chain_certs(SSL_CTX *ctx);
int SSL_set0_chain(SSL *ssl, STACK_OF(X509) *sk);
int SSL_set1_chain(SSL *ssl, STACK_OF(X509) *sk);
int SSL_add0_chain_cert(SSL *ssl, X509 *x509);
int SSL_add1_chain_cert(SSL *ssl, X509 *x509);
int SSL_get0_chain_certs(SSL *ssl, STACK_OF(X509) **sk);
int SSL_clear_chain_certs(SSL *ssl);
int SSL_CTX_build_cert_chain(SSL_CTX *ctx, flags);
int SSL_build_cert_chain(SSL *ssl, flags);
int SSL_CTX_select_current_cert(SSL_CTX *ctx, X509 *x509);
int SSL_select_current_cert(SSL *ssl, X509 *x509);
int SSL_CTX_set_current_cert(SSL_CTX *ctx, long op);
int SSL_set_current_cert(SSL *ssl, long op);

DESCRIPCIÓN

SSL_CTX_set0_chain() y SSL_CTX_set1_chain() establecen la cadena de certificados asociada con el certificado actual de ctx a sk.

SSL_CTX_add0_chain_cert() y SSL_CTX_add1_chain_cert() añaden el certificado individual x509 a la cadena asociada con el certificado actual de ctx.

SSL_CTX_get0_chain_certs() recupera la cadena asociada con el certificado actual de ctx.

SSL_CTX_clear_chain_certs() borra cualquier cadena existente asociada con el certificado actual de ctx. (Esto se implementa llamando a SSL_CTX_set0_chain() con sk establecido a NULL).

SSL_CTX_build_cert_chain() construye la cadena de certificados para ctx. Normalmente utiliza el almacén de cadenas o el almacén de verificación si el almacén de cadenas no está establecido. Si la función tiene éxito, la cadena construida reemplazará cualquier cadena existente. El parámetro flags puede ser establecido a SSL_BUILD_CHAIN_FLAG_UNTRUSTED para usar certificados de cadena existentes como CAs no confiables, SSL_BUILD_CHAIN_FLAG_NO_ROOT para omitir la CA raíz de la cadena construida, SSL_BUILD_CHAIN_FLAG_CHECK para usar todos los certificados de cadena existentes solo para construir la cadena (efectivamente comprobándolos y reordenándolos si es necesario), la bandera SSL_BUILD_CHAIN_FLAG_IGNORE_ERROR ignora cualquier error durante la verificación: si la bandera SSL_BUILD_CHAIN_FLAG_CLEAR_ERROR también está establecida, los errores de verificación se borran de la cola de errores. Los detalles del proceso de construcción de la cadena se describen en "Certification Path Building" en openssl-verification-options(1).

Cada una de estas funciones opera sobre el certificado de entidad final *actual* (es decir, servidor o cliente). Este es el último certificado cargado o seleccionado en la estructura ctx correspondiente.

SSL_CTX_select_current_cert() selecciona x509 como el certificado de entidad final actual, pero solo si x509 ya ha sido cargado en ctx usando una función como SSL_CTX_use_certificate().

SSL_set0_chain(), SSL_set1_chain(), SSL_add0_chain_cert(), SSL_add1_chain_cert(), SSL_get0_chain_certs(), SSL_clear_chain_certs(), SSL_build_cert_chain(), SSL_select_current_cert() y SSL_set_current_cert() son similares excepto que se aplican a la estructura SSL ssl.

SSL_CTX_set_current_cert() cambia el certificado actual a un valor basado en el argumento op. Actualmente op puede ser SSL_CERT_SET_FIRST para usar el primer certificado válido o SSL_CERT_SET_NEXT para establecer el siguiente certificado válido después del certificado actual. Estas dos operaciones pueden usarse para iterar sobre todos los certificados en una estructura SSL_CTX.

SSL_set_current_cert() también soporta la opción SSL_CERT_SET_SERVER. Si ssl es un servidor y ha enviado un certificado a un cliente conectado, esta opción establece ese certificado como el certificado actual y devuelve 1. Si el conjunto de cifrado negociado es anónimo (y por lo tanto no se enviará ningún certificado) se devuelve 2 y el certificado actual no se modifica. Si ssl no es un servidor o no se ha enviado un certificado, se devuelve 0 y el certificado actual no se modifica.

Todas estas funciones se implementan como macros. Las que contienen un 1 incrementan el contador de referencias del certificado o cadena suministrado, por lo que debe liberarse en algún momento después de la operación. Las que contienen un 0 no incrementan los contadores de referencias y el certificado o cadena suministrado *NO DEBE* liberarse después de la operación.

NOTAS

Las cadenas asociadas con una estructura SSL_CTX se copian a cualquier estructura SSL cuando se llama a SSL_new(). Las estructuras SSL no se verán afectadas por ninguna cadena modificada posteriormente en la estructura SSL_CTX padre.

Se puede establecer una cadena por cada tipo de clave soportado por un servidor. Así, por ejemplo, un certificado RSA y uno DSA pueden (y a menudo lo harán) tener cadenas diferentes.

Las funciones SSL_CTX_build_cert_chain() y SSL_build_cert_chain() se pueden usar para verificar la configuración de la aplicación y asegurar que las CAs subordinadas necesarias se envíen en el orden correcto. Las aplicaciones mal configuradas que envían cadenas de certificados incorrectas a menudo causan problemas con los pares.

Por ejemplo, una aplicación puede añadir cualquier conjunto de certificados usando SSL_CTX_use_certificate_chain_file() y luego llamar a SSL_CTX_build_cert_chain() con la opción SSL_BUILD_CHAIN_FLAG_CHECK para verificarlas y reordenarlas.

Las aplicaciones pueden emitir advertencias no fatales al verificar cadenas estableciendo la bandera SSL_BUILD_CHAIN_FLAG_IGNORE_ERRORS y comprobando el valor de retorno.

Llamar a SSL_CTX_build_cert_chain() o SSL_build_cert_chain() es más eficiente que la construcción automática de cadenas, ya que solo se realiza una vez. La construcción automática de cadenas se realiza en cada nueva sesión.

Si se añaden certificados usando estas funciones, no se utilizarán los certificados añadidos mediante SSL_CTX_add_extra_chain_cert().

VALORES DE RETORNO

SSL_set_current_cert() con SSL_CERT_SET_SERVER devuelve 1 en caso de éxito, 2 si no se utiliza ningún certificado de servidor porque el conjunto de cifrado es anónimo y 0 en caso de error.

SSL_CTX_build_cert_chain() y SSL_build_cert_chain() devuelven 1 en caso de éxito y 0 en caso de error. Si la bandera SSL_BUILD_CHAIN_FLAG_IGNORE_ERROR y ocurre un error de verificación, se devuelve 2.

Todas las demás funciones devuelven 1 en caso de éxito y 0 en caso de error.

VER TAMBIÉN
