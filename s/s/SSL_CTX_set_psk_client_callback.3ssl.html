SSL_CTX_set_psk_client_callback(3ssl)

Paquete: openssl

Licencias: Apache-2.0

SSL_CTX_SET_PSK_CLIENT_CALLBACK(3ssl) OpenSSL SSL_CTX_SET_PSK_CLIENT_CALLBACK(3ssl)

NOMBRE

SSL_psk_client_cb_func, SSL_psk_use_session_cb_func, SSL_CTX_set_psk_client_callback, SSL_set_psk_client_callback, SSL_CTX_set_psk_use_session_callback, SSL_set_psk_use_session_callback - establecer la función de devolución de llamada del cliente PSK

SINOPSIS

#include <openssl/ssl.h>
typedef int (*SSL_psk_use_session_cb_func)(SSL *ssl, const EVP_MD *md,
                                           const unsigned char **id,
                                           size_t *idlen,
                                           SSL_SESSION **sess);
void SSL_CTX_set_psk_use_session_callback(SSL_CTX *ctx,
                                          SSL_psk_use_session_cb_func cb);
void SSL_set_psk_use_session_callback(SSL *s, SSL_psk_use_session_cb_func cb);
typedef unsigned int (*SSL_psk_client_cb_func)(SSL *ssl,
                                               const char *hint,
                                               char *identity,
                                               unsigned int max_identity_len,
                                               unsigned char *psk,
                                               unsigned int max_psk_len);
void SSL_CTX_set_psk_client_callback(SSL_CTX *ctx, SSL_psk_client_cb_func cb);
void SSL_set_psk_client_callback(SSL *ssl, SSL_psk_client_cb_func cb);

DESCRIPCIÓN

Una aplicación cliente que desee utilizar PSKs de TLSv1.3 debe usar SSL_CTX_set_psk_use_session_callback() o SSL_set_psk_use_session_callback() según corresponda. Estas funciones no se pueden usar para PSKs de TLSv1.2 e inferiores.

La función de devolución de llamada recibe un puntero a la conexión SSL en ssl.

La primera vez que se llama a la función de devolución de llamada para una conexión, el parámetro md es NULL. En algunas circunstancias, la función de devolución de llamada se llamará una segunda vez. En ese caso, el servidor ya habrá especificado una suite de cifrado a utilizar y el PSK debe ser compatible con el resumen de esa suite de cifrado. El resumen se proporcionará en md. El PSK devuelto por la función de devolución de llamada puede ser diferente entre la primera y la segunda vez que se llama.

Al finalizar con éxito, la función de devolución de llamada debe almacenar un puntero a un identificador para el PSK en *id. La longitud del identificador en bytes debe almacenarse en *idlen. La memoria apuntada por *id sigue siendo propiedad de la aplicación y debe ser liberada por esta según sea necesario en cualquier momento después de que la negociación se complete.

Además, la función de devolución de llamada debe almacenar un puntero a un objeto SSL_SESSION en *sess. Este se utiliza como base para el PSK y debe tener, como mínimo, los siguientes campos establecidos:

La clave maestra
Esto se puede establecer mediante una llamada a SSL_SESSION_set1_master_key(3).
Una suite de cifrado
Solo el resumen de negociación asociado con la suite de cifrado es relevante para el PSK (el servidor puede negociar cualquier suite de cifrado que sea compatible con el resumen). La aplicación puede usar cualquier suite de cifrado TLSv1.3. Si md no es NULL, el resumen de negociación de la suite de cifrado debe ser el mismo. La suite de cifrado se puede establecer mediante una llamada a <SSL_SESSION_set_cipher(3)>. El resumen de negociación de un objeto SSL_CIPHER se puede verificar usando <SSL_CIPHER_get_handshake_digest(3)>.
La versión del protocolo
Esto se puede establecer mediante una llamada a SSL_SESSION_set_protocol_version(3) y debe ser TLS1_3_VERSION.

Además, el valor máximo de datos tempranos debe establecerse mediante una llamada a SSL_SESSION_set_max_early_data(3) si el PSK se utilizará para enviar datos tempranos.

Alternativamente, una SSL_SESSION creada a partir de una negociación anterior que no sea PSK también se puede utilizar como base para un PSK.

La propiedad del objeto SSL_SESSION se transfiere a la biblioteca OpenSSL, por lo que la aplicación no debe liberarla.

También es posible que la función de devolución de llamada tenga éxito pero no proporcione un PSK. En este caso, no se enviará ningún PSK al servidor, pero la negociación continuará. Para hacer esto, la función de devolución de llamada debe retornar con éxito y asegurarse de que *sess sea NULL. Los contenidos de *id y *idlen se ignoran.

Una aplicación cliente que desee utilizar suites de cifrado PSK para TLSv1.2 e inferiores debe proporcionar una función de devolución de llamada diferente. Esta función se llamará cuando el cliente esté enviando el mensaje ClientKeyExchange al servidor.

El propósito de la función de devolución de llamada es seleccionar la identidad PSK y la clave precompartida a utilizar durante la fase de configuración de la conexión.

La función de devolución de llamada se establece utilizando las funciones SSL_CTX_set_psk_client_callback() o SSL_set_psk_client_callback(). La función de devolución de llamada recibe la conexión en el parámetro ssl, una sugerencia de identidad PSK terminada en NULL enviada por el servidor en el parámetro hint, un búfer identity de longitud max_identity_len bytes (incluyendo el terminador NULL) donde debe almacenarse la identidad resultante terminada en NULL, y un búfer psk de longitud max_psk_len bytes donde debe almacenarse la clave precompartida resultante.

La función de devolución de llamada para uso en TLSv1.2 también funcionará en TLSv1.3, aunque se recomienda usar SSL_CTX_set_psk_use_session_callback() o SSL_set_psk_use_session_callback() para este propósito en su lugar. Si se ha negociado TLSv1.3, OpenSSL primero verificará si se ha establecido una función de devolución de llamada a través de SSL_CTX_set_psk_use_session_callback() o SSL_set_psk_use_session_callback() y la usará con preferencia. Si no hay tal función de devolución de llamada presente, verificará si se ha establecido una función de devolución de llamada a través de SSL_CTX_set_psk_client_callback() o SSL_set_psk_client_callback() y la usará. En este caso, el valor de hint siempre será NULL y el resumen de negociación por defecto será SHA-256 para cualquier PSK devuelto. Los intercambios de datos tempranos de TLSv1.3 son posibles en conexiones PSK solo con la función de devolución de llamada SSL_psk_use_session_cb_func, y no son posibles con la función de devolución de llamada SSL_psk_client_cb_func.

NOTAS

Tenga en cuenta que el parámetro hint proporcionado a la función de devolución de llamada puede ser NULL.

Una conexión establecida a través de un PSK TLSv1.3 aparecerá como si se hubiera producido una reanudación de sesión, por lo que SSL_session_reused(3) devolverá true.

No se conocen problemas de seguridad al compartir el mismo PSK entre TLSv1.2 (o inferior) y TLSv1.3. Sin embargo, la RFC tiene esta nota de precaución:

"Si bien no se conoce ninguna forma en que el mismo PSK pueda producir una salida relacionada en ambas versiones, solo se ha realizado un análisis limitado. Las implementaciones pueden garantizar la seguridad contra salidas relacionadas entre protocolos al no reutilizar PSKs entre TLS 1.3 y TLS 1.2."

VALORES DE RETORNO

Los valores de retorno de la función de devolución de llamada SSL_psk_client_cb_func se interpretan de la siguiente manera:

En caso de éxito (la función de devolución de llamada encontró una identidad PSK y una clave precompartida para usar), se devuelve la longitud (> 0) de psk en bytes.

En caso contrario o en caso de errores, la función de devolución de llamada debe devolver 0. En este caso, la configuración de la conexión falla.

La función de devolución de llamada SSL_psk_use_session_cb_func debe devolver 1 en caso de éxito o 0 en caso de fallo. En caso de fallo, la configuración de la conexión falla.
