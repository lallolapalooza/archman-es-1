SSL_set1_host(3ssl)

Paquete: openssl

Licencias: Apache-2.0

SSL_SET1_HOST(3ssl) OpenSSL SSL_SET1_HOST(3ssl)

NOMBRE

SSL_set1_host, SSL_add1_host, SSL_set_hostflags, SSL_get0_peername - parámetros de verificación del servidor SSL

SINOPSIS

#include <openssl/ssl.h>
int SSL_set1_host(SSL *s, const char *host);
int SSL_add1_host(SSL *s, const char *host);
void SSL_set_hostflags(SSL *s, unsigned int flags);
const char *SSL_get0_peername(SSL *s);

DESCRIPCIÓN

Estas funciones configuran las comprobaciones del nombre de host del servidor en el cliente SSL.

SSL_set1_host() establece en los parámetros de verificación de s el nombre DNS esperado o la dirección IP a host, borrando cualquier dirección IP y nombre de host previamente especificado. Si host es NULL o una cadena vacía, no se realizan comprobaciones de dirección IP y nombre de host en el certificado del par. Cuando se especifica un host no vacío, la verificación del certificado comprueba automáticamente el nombre de host del par mediante X509_check_host(3) con los flags especificados a través de SSL_set_hostflags(). Los clientes que habilitan la autenticación DANE TLSA mediante SSL_dane_enable(3) deben dejar que esa función establezca el identificador de referencia principal del par, y no deben llamar a SSL_set1_host().

SSL_add1_host() añade host como un identificador de referencia adicional que puede coincidir con el certificado del par. Se conservan todos los nombres de host anteriores establecidos mediante SSL_set1_host() o SSL_add1_host(). La adición de una dirección IP solo está permitida si no se ha establecido ninguna dirección IP previamente. No se realiza ningún cambio si host es NULL o está vacío. Cuando se configuran una dirección IP y/o múltiples nombres de host, se considera que el par está verificado cuando cualquiera de estos coincide. Esta función es necesaria para DANE TLSA en presencia de indirecta de nombres de servicio a través de registros CNAME, MX o SRV, según se especifica en las RFC 7671, 7672 y 7673.

Se recomienda a los clientes TLS que utilicen SSL_set1_host() o SSL_add1_host() para la validación del nombre de host o la dirección IP del servidor, así como SSL_set_tlsext_host_name(3) para el Indicador de Nombre de Servidor (SNI), que también puede ser crucial para el enrutamiento correcto de la solicitud de conexión.

SSL_set_hostflags() establece los flags que se pasarán a X509_check_host(3) cuando las comprobaciones de nombre sean aplicables; por defecto, el valor de flags es 0. Consulte X509_check_host(3) para ver la lista de flags disponibles y su significado.

SSL_get0_peername() devuelve el nombre DNS o el CommonName del sujeto del certificado del par que coincidió con uno de los identificadores de referencia. Cuando no se deshabilita la coincidencia de comodines, el nombre que coincide en el certificado del par puede ser un nombre comodín. Cuando uno de los identificadores de referencia configurados mediante SSL_set1_host() o SSL_add1_host() comienza con ".", lo que indica un prefijo de dominio padre en lugar de un nombre fijo, el nombre del par que coincide puede ser un subdominio del identificador de referencia. La cadena devuelta es asignada por la biblioteca y ya no es válida una vez que el identificador ssl asociado se borra o se libera, o tiene lugar una renégociación. Las aplicaciones no deben liberar el valor de retorno.

Se aconseja a los clientes SSL que utilicen estas funciones en lugar de llamar explícitamente a X509_check_host(3). Las comprobaciones de nombre de host pueden estar fuera de alcance con el uso de certificado RFC 7671 DANE-EE(3), y la comprobación interna se suprimirá según corresponda cuando DANE esté habilitado.

VALORES DE RETORNO

SSL_set1_host() y SSL_add1_host() devuelven 1 en caso de éxito y 0 en caso de fallo.

SSL_set_hostflags() no devuelve nada.

SSL_get0_peername() devuelve NULL si la verificación del nombre del par no es aplicable (como con RFC 7671 DANE-EE(3)), o si no se encontró ningún nombre de par de confianza. En caso contrario, devuelve el nombre del par coincidente. Para determinar si la verificación tuvo éxito, llame a SSL_get_verify_result(3).

EJEMPLOS

Supongamos que "smtp.example.com" es el host MX del dominio "example.com". Las llamadas siguientes organizarán la coincidencia del nombre de host MX o del nombre de dominio de destino en el certificado del servidor SMTP. Se admiten comodines, pero deben coincidir con toda la etiqueta. Se recupera el nombre real que coincide en el certificado (que podría ser un comodín), y debe ser copiado por la aplicación si se va a conservar más allá de la vida útil de la conexión SSL.

SSL_set_hostflags(ssl, X509_CHECK_FLAG_NO_PARTIAL_WILDCARDS);
if (!SSL_set1_host(ssl, "smtp.example.com"))
    /* error */
if (!SSL_add1_host(ssl, "example.com"))
    /* error */
/* XXX: Realizar SSL_connect() handshake y manejar errores aquí */
if (SSL_get_verify_result(ssl) == X509_V_OK) {
    const char *peername = SSL_get0_peername(ssl);
    if (peername != NULL)
        /* Las comprobaciones de nombre estaban en ámbito y coincidieron con peername */
}
