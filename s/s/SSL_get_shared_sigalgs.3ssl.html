Licencias: Apache-2.0

SSL_GET_SHARED_SIGALGS(3ssl) OpenSSL SSL_GET_SHARED_SIGALGS(3ssl)

NOMBRE

SSL_get_shared_sigalgs, SSL_get_sigalgs - obtener algoritmos de firma soportados

SINOPSIS

#include <openssl/ssl.h>
int SSL_get_shared_sigalgs(SSL *s, int idx,
                           int *psign, int *phash, int *psignhash,
                           unsigned char *rsig, unsigned char *rhash);
int SSL_get_sigalgs(SSL *s, int idx,
                    int *psign, int *phash, int *psignhash,
                    unsigned char *rsig, unsigned char *rhash);

DESCRIPCIÓN

SSL_get_shared_sigalgs() devuelve información sobre los algoritmos de firma compartidos soportados por el par s. El parámetro idx indica el índice del algoritmo de firma compartido a devolver, comenzando desde cero. El NID del algoritmo de firma se escribe en *psign, el NID del hash en *phash y los NIDs de firma y hash en *psignhash. Los valores brutos de firma y hash se escriben en *rsig y *rhash.

SSL_get_sigalgs() es similar a SSL_get_shared_sigalgs(), excepto que devuelve información sobre todos los algoritmos de firma soportados por s en el orden en que fueron enviados por el par.

VALORES DE RETORNO

SSL_get_shared_sigalgs() y SSL_get_sigalgs() devuelven el número de algoritmos de firma o 0 si el parámetro idx está fuera de rango.

NOTAS

Estas funciones suelen llamarse con fines de depuración (para informar de las preferencias del par) o cuando una aplicación desea un control más detallado sobre la selección de certificados. La mayoría de las aplicaciones se basarán en el manejo interno y no necesitarán llamarlas.

Si una aplicación solo está interesada en el algoritmo de firma compartido de mayor preferencia, simplemente puede establecer idx en cero.

Cualquiera o todos los parámetros psign, phash, psignhash, rsig o rhash pueden establecerse en NULL si el valor no es necesario. Estableciéndolos todos en NULL y estableciendo idx en cero, se puede determinar el número total de algoritmos de firma: que puede ser cero.

Estas funciones deben llamarse después de que el par haya enviado una lista de algoritmos de firma soportados: después de un client hello (para servidores) o una solicitud de certificado (para clientes). Pueden (por ejemplo) llamarse en la función de devolución de llamada del certificado.

Actualmente, solo TLS 1.2, TLS 1.3 y DTLS 1.2 soportan algoritmos de firma. Si estas funciones se llaman en una versión anterior de TLS o DTLS, se devuelve cero.

Los algoritmos de firma compartidos devueltos por SSL_get_shared_sigalgs() están ordenados según la configuración y las preferencias del par.

Los valores brutos corresponden a la forma en el cable tal como se define en RFC5246 et al. Los NIDs son equivalentes de OpenSSL. Por ejemplo, si el par envió sha256(4) y rsa(1), entonces *rhash sería 4, *rsign 1, *phash NID_sha256, *psig NID_rsaEncryption y *psignhash NID_sha256WithRSAEncryption.

Si un algoritmo de firma no se reconoce, los NIDs correspondientes se establecerán en NID_undef. Esto puede deberse a que el valor no se soporta, no es una combinación apropiada (por ejemplo, MD5 y DSA) o el algoritmo de firma no utiliza un hash (por ejemplo, Ed25519).
