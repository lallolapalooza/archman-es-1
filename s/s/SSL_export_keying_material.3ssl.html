SSL_export_keying_material(3ssl)

Paquete: openssl

Licencias: Apache-2.0

SSL_EXPORT_KEYING_MATERIAL(3ssl) OpenSSL SSL_EXPORT_KEYING_MATERIAL(3ssl)

NOMBRE

SSL_export_keying_material, SSL_export_keying_material_early - obtener material de clave para uso de la aplicación

SINOPSIS

#include <openssl/ssl.h>
int SSL_export_keying_material(SSL *s, unsigned char *out, size_t olen,
                               const char *label, size_t llen,
                               const unsigned char *context,
                               size_t contextlen, int use_context);
int SSL_export_keying_material_early(SSL *s, unsigned char *out, size_t olen,
                                     const char *label, size_t llen,
                                     const unsigned char *context,
                                     size_t contextlen);

DESCRIPCIÓN

Durante la creación de una conexión TLS o DTLS se establece material de clave compartido entre los dos puntos finales. Las funciones SSL_export_keying_material() y SSL_export_keying_material_early() permiten a una aplicación utilizar parte de este material de clave para sus propios fines de acuerdo con RFC5705 (para TLSv1.2 y anteriores) o RFC8446 (para TLSv1.3).

SSL_export_keying_material() deriva material de clave utilizando el exporter_master_secret establecido en el handshake.

SSL_export_keying_material_early() solo es utilizable con TLSv1.3, y deriva material de clave utilizando el early_exporter_master_secret (como se define en el RFC de TLS 1.3). Para el cliente, el early_exporter_master_secret solo está disponible cuando el cliente intenta enviar datos 0-RTT. Para el servidor, solo está disponible cuando el servidor acepta datos 0-RTT.

Una aplicación puede necesitar establecer de forma segura el contexto dentro del cual se utilizará este material de clave. Por ejemplo, esto puede incluir identificadores para la sesión de la aplicación, algoritmos o parámetros de la aplicación, o la vida útil del contexto. El valor del contexto se deja a la aplicación, pero debe ser el mismo en ambos lados de la comunicación.

Para una conexión SSL dada s, se escribirán olen bytes de datos en out. El contexto específico de la aplicación debe suministrarse en la ubicación apuntada por context y debe tener contextlen bytes de longitud. La provisión de un contexto es opcional. Si el contexto debe omitirse por completo, entonces use_context debe establecerse en 0. De lo contrario, debe ser cualquier otro valor. Si use_context es 0, los valores de context y contextlen se ignoran. Tenga en cuenta que en TLSv1.2 y anteriores, un contexto de longitud cero se trata de manera diferente a la ausencia de contexto, y resultará en material de clave diferente. En TLSv1.3, un contexto de longitud cero es lo mismo que la ausencia de contexto y resultará en el mismo material de clave.

Se debe proporcionar una etiqueta específica de la aplicación en la ubicación apuntada por label y debe tener llen bytes de longitud. Típicamente, este será un valor del Registro de Etiquetas de Exportador de IANA (https://www.iana.org/assignments/tls-parameters/tls-parameters.xhtml#exporter-labels). Alternativamente, las etiquetas que comienzan con "EXPERIMENTAL" están permitidas por el estándar para ser utilizadas sin registro. TLSv1.3 impone una longitud máxima de etiqueta de 249 bytes.

Tenga en cuenta que esta función solo está definida para TLSv1.0 y superiores, y DTLSv1.0 y superiores. Intentar usarla en SSLv3 resultará en un error.

VALORES DE RETORNO

SSL_export_keying_material() devuelve 0 o -1 en caso de error, o 1 en caso de éxito.

SSL_export_keying_material_early() devuelve 0 en caso de error o 1 en caso de éxito.

VER TAMBIÉN

ssl(7)

HISTORIA

La función SSL_export_keying_material_early() se añadió en OpenSSL 1.1.1.
