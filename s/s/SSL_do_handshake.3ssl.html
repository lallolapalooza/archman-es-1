SSL_DO_HANDSHAKE(3ssl) OpenSSL SSL_DO_HANDSHAKE(3ssl)

NOMBRE

SSL_do_handshake - realizar un handshake TLS/SSL

SINOPSIS

#include <openssl/ssl.h>
int SSL_do_handshake(SSL *ssl);

DESCRIPCIÓN

SSL_do_handshake() esperará a que se produzca un handshake SSL/TLS. Si la conexión está en modo cliente, se iniciará el handshake. Las rutinas de handshake pueden tener que ser establecidas explícitamente de antemano utilizando SSL_set_connect_state(3) o SSL_set_accept_state(3).

NOTAS

El comportamiento de SSL_do_handshake() depende del BIO subyacente.

Si el BIO subyacente es bloqueante, SSL_do_handshake() solo retornará una vez que el handshake se haya completado o se haya producido un error.

Si el BIO subyacente es no bloqueante, SSL_do_handshake() también retornará cuando el BIO subyacente no haya podido satisfacer las necesidades de SSL_do_handshake() para continuar el handshake. En este caso, una llamada a SSL_get_error() con el valor de retorno de SSL_do_handshake() producirá SSL_ERROR_WANT_READ o SSL_ERROR_WANT_WRITE. El proceso que llama debe entonces repetir la llamada después de tomar las acciones apropiadas para satisfacer las necesidades de SSL_do_handshake(). La acción depende del BIO subyacente. Al usar un socket no bloqueante, no hay nada que hacer, pero se puede usar select() para verificar la condición requerida. Al usar un BIO de almacenamiento en búfer, como un par de BIOs, los datos deben escribirse en o recuperarse del BIO antes de poder continuar.

VALORES DE RETORNO

Los siguientes valores de retorno pueden ocurrir:

0
El handshake TLS/SSL no fue exitoso, pero se cerró de forma controlada y según las especificaciones del protocolo TLS/SSL. Llame a SSL_get_error() con el valor de retorno ret para averiguar la razón.
1
El handshake TLS/SSL se completó con éxito, se ha establecido una conexión TLS/SSL.
<0
El handshake TLS/SSL no fue exitoso porque ocurrió un error fatal a nivel de protocolo o se produjo un fallo de conexión. El cierre no fue limpio. También puede ocurrir si se necesita acción para continuar la operación para BIOs no bloqueantes. Llame a SSL_get_error() con el valor de retorno ret para averiguar la razón.
