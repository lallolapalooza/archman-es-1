SSL_set_default_stream_mode(3ssl)

Paquete: openssl

Licencias: Apache-2.0

SSL_SET_DEFAULT_STREAM_MODE(3ssl) OpenSSL SSL_SET_DEFAULT_STREAM_MODE(3ssl)

NOMBRE

SSL_set_default_stream_mode, SSL_DEFAULT_STREAM_MODE_NONE, SSL_DEFAULT_STREAM_MODE_AUTO_BIDI, SSL_DEFAULT_STREAM_MODE_AUTO_UNI - gestionar el stream por defecto para una conexión QUIC

SINOPSIS

#include <openssl/ssl.h>
#define SSL_DEFAULT_STREAM_MODE_NONE
#define SSL_DEFAULT_STREAM_MODE_AUTO_BIDI
#define SSL_DEFAULT_STREAM_MODE_AUTO_UNI
int SSL_set_default_stream_mode(SSL *conn, uint32_t mode);

DESCRIPCIÓN

Un objeto SSL de conexión QUIC puede tener un stream por defecto adjunto. Un stream por defecto es un stream QUIC al que se redirigen las llamadas a SSL_read(3) y SSL_write(3) realizadas en un objeto SSL de conexión QUIC. El manejo de streams por defecto permite que las aplicaciones antiguas utilicen QUIC de forma similar a una conexión TLS tradicional.

Cuando no está deshabilitado, se crea automáticamente un stream por defecto en una conexión saliente una vez que se llama a SSL_read(3) o SSL_write(3).

Un stream QUIC debe ser explícitamente designado como iniciado por el cliente o iniciado por el servidor de antemano. Esto corresponde en general a si un protocolo de aplicación implica que el cliente transmita primero, o el servidor transmita primero. Como tal, si se llama a SSL_read(3) primero (antes de cualquier llamada a SSL_write(3)) después de establecer una conexión, OpenSSL esperará a que el servidor abra el primer stream iniciado por el servidor y luego lo vinculará como el stream por defecto. Por el contrario, si se llama a SSL_write(3) antes de cualquier llamada a SSL_read(3), OpenSSL asume que el cliente desea transmitir primero, crea un stream iniciado por el cliente y lo vincula como el stream por defecto.

Por defecto, el stream creado por defecto es bidireccional. Si se desea un stream unidireccional, o si la aplicación desea deshabilitar la funcionalidad de stream por defecto, SSL_set_default_stream_mode() (discutido a continuación) se puede usar para lograr esto.

Cuando un objeto SSL de conexión QUIC no tiene ningún stream por defecto asociado actualmente, por ejemplo, porque la funcionalidad de stream por defecto fue deshabilitada, las llamadas a funciones que requieren un stream en el objeto SSL de conexión QUIC (por ejemplo, SSL_read(3) y SSL_write(3)) fallarán.

Se recomienda que las nuevas aplicaciones y las aplicaciones que dependen de múltiples streams renuncien al uso de la funcionalidad de stream por defecto, que está pensada para aplicaciones antiguas.

SSL_set_default_stream_mode() se puede usar para configurar o deshabilitar el manejo de streams por defecto. Solo se puede llamar en un objeto SSL de conexión QUIC antes de que se cree cualquier stream por defecto. Si se usa, se recomienda llamarlo inmediatamente después de llamar a SSL_new(3), antes de iniciar una conexión. El argumento mode puede ser una de las siguientes opciones:

SSL_DEFAULT_STREAM_MODE_AUTO_BIDI
Esta es la configuración por defecto. Si se llama a SSL_write(3) antes de cualquier llamada a SSL_read(3), se crea un stream bidireccional iniciado por el cliente y se vincula como stream por defecto. Si se llama a SSL_read(3) antes de cualquier llamada a SSL_write(3), OpenSSL espera un stream entrante del par (haciendo que SSL_read(3) se bloquee si la conexión está en modo de bloqueo) y luego vincula ese stream como el stream por defecto. Tenga en cuenta que este stream entrante puede ser bidireccional o unidireccional; por lo tanto, esta configuración no garantiza la presencia de un stream bidireccional cuando se llama a SSL_read(3) primero. Para determinar el tipo de un stream después de una llamada a SSL_read(3), use SSL_get_stream_type(3).
SSL_DEFAULT_STREAM_MODE_AUTO_UNI
En este modo, si se llama a SSL_write(3) antes de cualquier llamada a SSL_read(3), se crea un stream unidireccional iniciado por el cliente y se vincula como stream por defecto. El comportamiento es idéntico al de SSL_DEFAULT_STREAM_MODE_AUTO_BIDI. El comportamiento cuando se llama a SSL_read(3) antes de cualquier llamada a SSL_write(3) no cambia.
SSL_DEFAULT_STREAM_MODE_NONE
Se inhibe la creación del stream por defecto. Este es el modo de operación recomendado. Las llamadas a SSL_read(3) y SSL_write(3) no se pueden realizar directamente en el objeto SSL de conexión QUIC. Debe obtener streams usando SSL_new_stream(3) o SSL_accept_stream(3) para comunicarse con el par.

No se creará automáticamente un stream por defecto en un objeto SSL de conexión QUIC si el modo de stream por defecto está configurado en SSL_DEFAULT_STREAM_MODE_NONE.

SSL_set_incoming_stream_policy(3) interactúa significativamente con la funcionalidad de stream por defecto.

VALORES DE RETORNO

SSL_set_default_stream_mode() devuelve 1 si tiene éxito y 0 en caso de fallo.

SSL_set_default_stream_mode() falla si se llama después de que ya se haya establecido un stream por defecto.

Estas funciones fallan si se llaman en un objeto SSL de stream QUIC o en un objeto SSL no-QUIC.

VER TAMBIÉN
