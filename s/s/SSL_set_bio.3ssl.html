SSL_set_bio(3ssl)

Paquete: openssl

Licencias: Apache-2.0

SSL_SET_BIO(3ssl) OpenSSL SSL_SET_BIO(3ssl)

NOMBRE

SSL_set_bio, SSL_set0_rbio, SSL_set0_wbio - conectar el objeto SSL con un BIO

SINOPSIS

#include <openssl/ssl.h>
void SSL_set_bio(SSL *ssl, BIO *rbio, BIO *wbio);
void SSL_set0_rbio(SSL *s, BIO *rbio);
void SSL_set0_wbio(SSL *s, BIO *wbio);

DESCRIPCIÓN

SSL_set0_rbio() conecta el BIO rbio para las operaciones de lectura del objeto ssl. El motor SSL hereda el comportamiento de rbio. Si el BIO no es bloqueante, entonces el objeto ssl también tendrá comportamiento no bloqueante. Esta función transfiere la propiedad de rbio a ssl. Será liberado automáticamente usando BIO_free_all(3) cuando se libere el ssl. Al llamar a esta función, cualquier rbio existente que se hubiera establecido previamente también será liberado mediante una llamada a BIO_free_all(3) (esto incluye el caso en que el rbio se establece con el mismo valor que anteriormente).

Si se utiliza un BIO personalizado, rbio debe implementar BIO_meth_set_read_ex(3) o BIO_meth_set_read(3).

SSL_set0_wbio() funciona de la misma manera que SSL_set0_rbio() excepto que conecta el BIO wbio para las operaciones de escritura del objeto ssl. Tenga en cuenta que si el rbio y el wbio son los mismos, entonces SSL_set0_rbio() y SSL_set0_wbio() toman posesión de una referencia cada uno. Por lo tanto, puede ser necesario incrementar el número de referencias disponibles usando BIO_up_ref(3) antes de llamar a las funciones set0.

Si se utiliza un BIO personalizado, wbio debe implementar BIO_meth_set_write_ex(3) o BIO_meth_set_write(3). Adicionalmente, debe implementar BIO_flush(3) usando BIO_CTRL_FLUSH y BIO_meth_set_ctrl(3). Si vaciar no es necesario con wbio, BIO_flush(3) debería devolver uno y no hacer nada.

SSL_set_bio() es similar a SSL_set0_rbio() y SSL_set0_wbio() excepto que conecta tanto el rbio como el wbio al mismo tiempo, y transfiere la propiedad de rbio y wbio a ssl de acuerdo con el siguiente conjunto de reglas:

  • Si ni el rbio ni el wbio han cambiado respecto a sus valores previos, no se hace nada.
  • Si los parámetros rbio y wbio son diferentes y ambos son diferentes a sus valores establecidos previamente, se consume una referencia para el rbio y una referencia para el wbio.
  • Si los parámetros rbio y wbio son iguales y el rbio no es igual al valor establecido previamente, se consume una referencia.
  • Si los parámetros rbio y wbio son iguales y el rbio es igual al valor establecido previamente, no se consumen referencias adicionales.
  • Si los parámetros rbio y wbio son diferentes y el rbio es igual al valor establecido previamente, se consume una referencia para el wbio y no se consumen referencias para el rbio.
  • Si los parámetros rbio y wbio son diferentes y el wbio es igual al valor establecido previamente y los valores antiguos de rbio y wbio eran iguales entre sí, se consume una referencia para el rbio y no se consumen referencias para el wbio.
  • Si los parámetros rbio y wbio son diferentes y el wbio es igual al valor establecido previamente y los valores antiguos de rbio y wbio eran diferentes entre sí, se consume una referencia para el rbio y una referencia para el wbio.

Debido a esta complejidad, esta función debe evitarse; use SSL_set0_rbio() y SSL_set0_wbio() en su lugar.

Donde se establece un nuevo BIO en un objeto SSL de conexión QUIC, el modo bloqueante se deshabilitará en ese objeto SSL si el BIO no puede soportar el modo bloqueante. Si posteriormente se establece otro BIO en el objeto SSL que pueda soportar el modo bloqueante, el modo bloqueante no se volverá a habilitar automáticamente. Para más información, véase SSL_set_blocking_mode(3).

VALORES DE RETORNO

SSL_set_bio(), SSL_set0_rbio() y SSL_set0_wbio() no pueden fallar.

VER TAMBIÉN

SSL_get_rbio(3), SSL_connect(3), SSL_accept(3), SSL_shutdown(3), ssl(7), bio(7)

HISTORIA

SSL_set0_rbio() y SSL_set0_wbio() se añadieron en OpenSSL 1.1.0.
