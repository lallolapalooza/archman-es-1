SSL_CTX_load_verify_locations(3ssl)

Paquete: openssl

Licencias: Apache-2.0

SSL_CTX_LOAD_VERIFY_LOCATIONS(3ssl) OpenSSL SSL_CTX_LOAD_VERIFY_LOCATIONS(3ssl)

NOMBRE

SSL_CTX_load_verify_dir, SSL_CTX_load_verify_file, SSL_CTX_load_verify_store, SSL_CTX_set_default_verify_paths, SSL_CTX_set_default_verify_dir, SSL_CTX_set_default_verify_file, SSL_CTX_set_default_verify_store, SSL_CTX_load_verify_locations - establecer ubicaciones predeterminadas para certificados de CA de confianza

SINOPSIS

#include <openssl/ssl.h>
int SSL_CTX_load_verify_dir(SSL_CTX *ctx, const char *CApath);
int SSL_CTX_load_verify_file(SSL_CTX *ctx, const char *CAfile);
int SSL_CTX_load_verify_store(SSL_CTX *ctx, const char *CAstore);
int SSL_CTX_set_default_verify_paths(SSL_CTX *ctx);
int SSL_CTX_set_default_verify_dir(SSL_CTX *ctx);
int SSL_CTX_set_default_verify_file(SSL_CTX *ctx);
int SSL_CTX_set_default_verify_store(SSL_CTX *ctx);
int SSL_CTX_load_verify_locations(SSL_CTX *ctx, const char *CAfile,
                                  const char *CApath);

DESCRIPCIÓN

SSL_CTX_load_verify_locations(), SSL_CTX_load_verify_dir(), SSL_CTX_load_verify_file(), SSL_CTX_load_verify_store() especifican las ubicaciones para ctx, donde se encuentran los certificados de CA para fines de verificación. Los certificados disponibles a través de CAfile, CApath y CAstore son de confianza. ctx NO DEBE ser NULL.

Los detalles del proceso de verificación de certificados y de comprobación de cadenas se describen en "Validación de rutas de certificación" en openssl-verification-options(1).

SSL_CTX_set_default_verify_paths() especifica que se deben utilizar las ubicaciones predeterminadas desde las cuales se cargan los certificados de CA. Hay un directorio predeterminado, un archivo predeterminado y un almacén predeterminado. El directorio de certificados de CA predeterminado se llama certs en el directorio predeterminado de OpenSSL, y este es también el almacén predeterminado. Alternativamente, se puede definir la variable de entorno SSL_CERT_DIR para anular esta ubicación. El archivo de certificados de CA predeterminado se llama cert.pem en el directorio predeterminado de OpenSSL. Alternativamente, se puede definir la variable de entorno SSL_CERT_FILE para anular esta ubicación. ctx NO DEBE ser NULL.

SSL_CTX_set_default_verify_dir() es similar a SSL_CTX_set_default_verify_paths() excepto que solo se utiliza el directorio predeterminado.

SSL_CTX_set_default_verify_file() es similar a SSL_CTX_set_default_verify_paths() excepto que solo se utiliza el archivo predeterminado.

SSL_CTX_set_default_verify_store() es similar a SSL_CTX_set_default_verify_paths() excepto que solo se utiliza el almacén predeterminado.

NOTAS

Si CAfile no es NULL, apunta a un archivo de certificados de CA en formato PEM. El archivo puede contener varios certificados de CA identificados por

-----BEGIN CERTIFICATE-----
... (certificado de CA en codificación base64) ...
-----END CERTIFICATE-----

secuencias. Antes, entre y después de los certificados se permite texto que se puede utilizar, por ejemplo, para descripciones de los certificados.

El CAfile se procesa en la ejecución de la función SSL_CTX_load_verify_locations().

Si CApath no es NULL, apunta a un directorio que contiene certificados de CA en formato PEM. Los archivos contienen cada uno un certificado de CA. Los archivos se buscan por el valor hash del nombre del sujeto de la CA, que por lo tanto debe estar disponible. Si existen varios certificados de CA con el mismo valor hash de nombre, la extensión debe ser diferente (por ejemplo, 9d66eef0.0, 9d66eef0.1, etc.). La búsqueda se realiza en el orden del número de extensión, independientemente de otras propiedades de los certificados. Utilice la utilidad c_rehash para crear los enlaces necesarios.

Los certificados en CApath solo se buscan cuando son necesarios, por ejemplo, al construir la cadena de certificados o al realizar realmente la verificación del certificado del par.

Al buscar certificados de CA para la construcción de cadenas, la biblioteca OpenSSL buscará certificados adecuados primero en CAfile, luego en CApath. Los detalles del proceso de construcción de cadenas se describen en "Construcción de cadenas de certificación" en openssl-verification-options(1).

Si CAstore no es NULL, es una URI a un almacén, que puede representar un único contenedor o un catálogo completo de contenedores. Aparte de que CAstore no sea necesariamente un archivo o directorio local, generalmente se trata de la misma manera que un CApath.

En modo servidor, al solicitar un certificado de cliente, el servidor debe enviar la lista de CAs de las cuales aceptará certificados de cliente. Esta lista no se ve influenciada por el contenido de CAfile o CApath y debe establecerse explícitamente utilizando la familia de funciones SSL_CTX_set_client_CA_list(3).

Al construir su propia cadena de certificados, un cliente/servidor OpenSSL intentará completar los certificados faltantes desde CAfile/CApath, si la cadena de certificados no se especificó explícitamente (ver SSL_CTX_add_extra_chain_cert(3), SSL_CTX_use_certificate(3).

ADVERTENCIAS

Si hay varios certificados de CA que coinciden con el nombre, el identificador de clave y la condición del número de serie, solo se examinará el primero. Esto puede dar lugar a resultados inesperados si el mismo certificado de CA está disponible con fechas de caducidad diferentes. Si se produce un error de verificación de "certificado caducado", no se buscará ningún otro certificado. Asegúrese de no mezclar certificados caducados con otros válidos.

VALORES DE RETORNO

Para SSL_CTX_load_verify_locations los siguientes valores de retorno pueden ocurrir:

0
La operación falló porque CAfile y CApath son NULL o el procesamiento en una de las ubicaciones especificadas falló. Compruebe la pila de errores para averiguar el motivo.
1
La operación tuvo éxito.

SSL_CTX_set_default_verify_paths(), SSL_CTX_set_default_verify_dir() y SSL_CTX_set_default_verify_file() devuelven 1 en caso de éxito o 0 en caso de fallo. Una ubicación predeterminada faltante todavía se trata como un éxito.

EJEMPLOS

Generar un archivo de certificado de CA con texto descriptivo a partir de los certificados de CA ca1.pem ca2.pem ca3.pem:

#!/bin/sh
rm CAfile.pem
for i in ca1.pem ca2.pem ca3.pem ; do
    openssl x509 -in $i -text >> CAfile.pem
done

Preparar el directorio /some/where/certs que contiene varios certificados de CA para su uso como CApath:

cd /some/where/certs
c_rehash .
