NOMBRE

SSL_CTX_set_alpn_protos, SSL_set_alpn_protos, SSL_CTX_set_alpn_select_cb, SSL_CTX_set_next_proto_select_cb, SSL_CTX_set_next_protos_advertised_cb, SSL_select_next_proto, SSL_get0_alpn_selected, SSL_get0_next_proto_negotiated - gestionar la negociación de protocolos de capa de aplicación (ALPN)

SINOPSIS

#include <openssl/ssl.h>
int SSL_CTX_set_alpn_protos(SSL_CTX *ctx, const unsigned char *protos,
                            unsigned int protos_len);
int SSL_set_alpn_protos(SSL *ssl, const unsigned char *protos,
                        unsigned int protos_len);
void SSL_CTX_set_alpn_select_cb(SSL_CTX *ctx,
                                int (*cb) (SSL *ssl,
                                           const unsigned char **out,
                                           unsigned char *outlen,
                                           const unsigned char *in,
                                           unsigned int inlen,
                                           void *arg), void *arg);
void SSL_get0_alpn_selected(const SSL *ssl, const unsigned char **data,
                            unsigned int *len);
void SSL_CTX_set_next_protos_advertised_cb(SSL_CTX *ctx,
                                           int (*cb)(SSL *ssl,
                                                     const unsigned char **out,
                                                     unsigned int *outlen,
                                                     void *arg),
                                           void *arg);
void SSL_CTX_set_next_proto_select_cb(SSL_CTX *ctx,
                              int (*cb)(SSL *s,
                                        unsigned char **out,
                                        unsigned char *outlen,
                                        const unsigned char *in,
                                        unsigned int inlen,
                                        void *arg),
                              void *arg);
int SSL_select_next_proto(unsigned char **out, unsigned char *outlen,
                          const unsigned char *server,
                          unsigned int server_len,
                          const unsigned char *client,
                          unsigned int client_len);
void SSL_get0_next_proto_negotiated(const SSL *s, const unsigned char **data,
                            unsigned *len);

DESCRIPCIÓN

SSL_CTX_set_alpn_protos() y SSL_set_alpn_protos() son utilizados por el cliente para establecer la lista de protocolos disponibles para la negociación. protos debe estar en formato de lista de protocolos, descrito a continuación. La longitud de protos se especifica en protos_len. Establecer protos_len a 0 borra cualquier lista existente de protocolos ALPN y no se enviará ninguna extensión ALPN al servidor.

SSL_CTX_set_alpn_select_cb() establece la función de callback de la aplicación cb utilizada por un servidor para seleccionar qué protocolo usar para la conexión entrante. Cuando cb es NULL, ALPN no se utiliza. El valor de arg es un puntero que se pasa a la función de callback de la aplicación.

cb es la función de callback definida por la aplicación. Los parámetros in, inlen son un vector en formato de lista de protocolos. El valor del vector out, outlen debe establecerse al valor de un solo protocolo seleccionado del vector in, inlen. El buffer out puede apuntar directamente a in, o a un buffer que sobreviva al handshake. El parámetro arg es el puntero establecido a través de SSL_CTX_set_alpn_select_cb().

SSL_select_next_proto() es una función auxiliar utilizada para seleccionar protocolos. Implementa la selección de protocolos estándar. Se espera que esta función se llame desde la función de callback de la aplicación cb. Los datos del protocolo en server, server_len y client, client_len deben estar en el formato de lista de protocolos descrito a continuación. El primer elemento de la lista server, server_len que coincide con un elemento en la lista client, client_len se selecciona y se devuelve en out, outlen. El valor de out apuntará a server o a client, por lo que debe copiarse inmediatamente. La lista del cliente debe incluir al menos una entrada de protocolo válida (no vacía) en la lista.

La función auxiliar SSL_select_next_proto() puede ser útil tanto desde la función de callback de ALPN como desde la de NPN (descrita a continuación). Si no se encuentra una coincidencia, el primer elemento en client, client_len se devuelve en out, outlen y se devuelve OPENSSL_NPN_NO_OVERLAP. Esto puede ser útil al implementar la función de callback de NPN. En el caso de ALPN, el valor devuelto en out y outlen debe ignorarse si se ha devuelto OPENSSL_NPN_NO_OVERLAP desde SSL_select_next_proto().

SSL_CTX_set_next_proto_select_cb() establece una función de callback cb que se llama cuando un cliente necesita seleccionar un protocolo de la lista proporcionada por el servidor, y un puntero de argumento definido por el usuario arg que se pasará a esta función de callback. Para la función de callback en sí, out debe establecerse para apuntar al protocolo seleccionado (que puede estar dentro de in). La longitud del nombre del protocolo debe escribirse en outlen. Los protocolos anunciados por el servidor se proporcionan en in e inlen. La función de callback puede asumir que in es sintácticamente válido. El cliente debe seleccionar un protocolo (aunque puede ser un protocolo vacío, de longitud cero). Es fatal para la conexión si esta función de callback devuelve un valor distinto de SSL_TLSEXT_ERR_OK o si se selecciona el protocolo de longitud cero. El parámetro arg es el puntero establecido a través de SSL_CTX_set_next_proto_select_cb().

SSL_CTX_set_next_protos_advertised_cb() establece una función de callback cb que se llama cuando un servidor TLS necesita una lista de protocolos admitidos para la Negociación de Próximo Protocolo. La lista devuelta debe estar en formato de lista de protocolos, descrita a continuación. La lista se devuelve estableciendo out para que apunte a ella y outlen a su longitud. Esta memoria no se modificará, pero SSL conserva una referencia a ella. La función de callback debe devolver SSL_TLSEXT_ERR_OK si desea anunciar. De lo contrario, ninguna extensión de este tipo se incluirá en el ServerHello.

SSL_get0_alpn_selected() devuelve un puntero al protocolo seleccionado en data con longitud len. No está terminado en NUL. data se establece en NULL y len se establece en 0 si no se ha seleccionado ningún protocolo. data no debe liberarse.

SSL_get0_next_proto_negotiated() establece data y len para que apunten al protocolo solicitado por el cliente para esta conexión. Si el cliente no solicitó ningún protocolo o NPN no está habilitado, entonces data se establece en NULL y len en 0. Tenga en cuenta que el cliente puede solicitar cualquier protocolo que elija. El valor devuelto desde esta función no necesita ser un miembro de la lista de protocolos admitidos proporcionada por la función de callback.

La funcionalidad NPN no se puede utilizar con objetos SSL QUIC. El uso de ALPN es obligatorio cuando se utilizan objetos SSL QUIC. SSL_CTX_set_next_protos_advertised_cb() y SSL_CTX_set_next_proto_select_cb() no tienen efecto si se llaman en un contexto SSL QUIC.

NOTAS

Las listas de protocolos deben estar en formato de cable, que se define como un vector de cadenas de bytes de longitud prefijada de 8 bits, no vacías. El byte de prefijo de longitud no se incluye en la longitud. Cada cadena está limitada a 255 bytes. Una longitud de cadena de bytes de 0 es inválida. Una cadena de bytes truncada es inválida. La longitud del vector no está en el vector en sí, sino en una variable separada.

Ejemplo:

unsigned char vector[] = {
    6, 's', 'p', 'd', 'y', '/', '1',
    8, 'h', 't', 't', 'p', '/', '1', '.', '1'
};
unsigned int length = sizeof(vector);

La función de callback de ALPN se ejecuta después de la función de callback del nombre del servidor; ya que esa función de callback del nombre del servidor puede actualizar el SSL_CTX y, posteriormente, la función de callback de ALPN.

Si no se propone ningún ALPN en el ClientHello, la función de callback de ALPN no se invoca.

VALORES DE RETORNO

SSL_CTX_set_alpn_protos() y SSL_set_alpn_protos() devuelven 0 en caso de éxito y un valor distinto de 0 en caso de error. ADVERTENCIA: estas funciones invierten la convención del valor de retorno.

SSL_select_next_proto() devuelve uno de los siguientes:

OPENSSL_NPN_NEGOTIATED
Se encontró una coincidencia y se devuelve en out, outlen.
OPENSSL_NPN_NO_OVERLAP
No se encontró ninguna coincidencia. El primer elemento en client, client_len se devuelve en out, outlen (o NULL y 0 en el caso en que el primer elemento en.

NOMBRE

SSL_CTX_set_alpn_select_cb, SSL_CTX_set_alpn_protos - Configurar el protocolo de selección ALPN

SINOPSIS

  #include <openssl/ssl.h>


int SSL_CTX_set_alpn_select_cb(SSL_CTX *ctx,
     int (*cb)(SSL *ssl, const unsigned char **out,
     unsigned int *outlen, const unsigned char *in,
     unsigned int inlen, void *arg),
     void *arg);


int SSL_CTX_set_alpn_protos(SSL_CTX *ctx, const unsigned char *protos,
     unsigned int protoslen);

DESCRIPCIÓN

La extensión ALPN (Application-Layer Protocol Negotiation) permite al cliente y al servidor negociar protocolos de capa de aplicación sobre TLS. Es una extensión del tipo Server Name Indication (SNI).

SSL_CTX_set_alpn_select_cb() establece una función de devolución de llamada que se invocará cuando se reciba la extensión ALPN del cliente. El cliente envía una lista de protocolos de aplicación que admite en el campo in y inlen. La función de devolución de llamada debe seleccionar un protocolo de la lista del cliente y establecer el puntero out para que apunte a los bytes del protocolo seleccionado y outlen a su longitud. El protocolo seleccionado debe ser uno de los protocolos proporcionados por el cliente. Si no se puede seleccionar ningún protocolo, los campos out y outlen deben establecerse en NULL y 0, respectivamente.

El parámetro arg se puede usar para pasar datos adicionales a la función de devolución de llamada.

SSL_CTX_set_alpn_protos() establece la lista de protocolos que el servidor anuncia que admite. La lista protos debe ser una secuencia de longitudes de protocolo seguidas de los bytes del protocolo. Por ejemplo, para anunciar "http/1.1" y "spdy/2", protos contendría 8 (longitud de "http/1.1") seguido de los bytes de "http/1.1", seguido de 6 (longitud de "spdy/2") seguido de los bytes de "spdy/2". El parámetro protoslen es la longitud total en bytes de la lista de protocolos.

NOTAS

La selección de ALPN solo se realiza si el cliente y el servidor admiten ambos ALPN. Si el cliente no envía la extensión ALPN, o si el servidor no está configurado para anunciarla, la extensión ALPN no se incluirá en el ServerHello.

Si se establece una función de devolución de llamada con SSL_CTX_set_alpn_select_cb(), llama implícitamente a SSL_CTX_set_alpn_protos() con la lista de protocolos devuelta por la función de devolución de llamada.

La lista de protocolos pasada a SSL_CTX_set_alpn_protos() debe ser de un formato específico. Cada entrada de protocolo debe ir precedida de un byte que indique la longitud de ese protocolo. Por ejemplo, para anunciar el protocolo "h2" y "http/1.1", la cadena sería `\x02h2\x08http/1.1`.

Si el cliente selecciona un protocolo mediante ALPN, este se puede obtener mediante SSL_get0_alpn_selected().

La función de devolución de llamada ALPN solo se llamará si el protocolo de transporte es TCP.

Para usar ALPN, tanto el cliente como el servidor deben estar compilados con la biblioteca OpenSSL 1.0.2 o posterior.

VALORES DE RETORNO

Ambas funciones devuelven 1 si tienen éxito, o 0 si se produce un error. Un valor de retorno de 0 puede ocurrir si, por ejemplo, la memoria no se puede asignar (para SSL_CTX_set_alpn_select_cb()) o si la lista de protocolos proporcionada a SSL_CTX_set_alpn_protos() tiene un formato incorrecto (por ejemplo, una entrada de protocolo es demasiado larga).

La función de devolución de llamada ALPN establecida mediante SSL_CTX_set_alpn_select_cb() debe devolver uno de los siguientes:

SSL_TLSEXT_ERR_OK
Protocolo ALPN seleccionado.
SSL_TLSEXT_ERR_ALERT_FATAL
No hubo superposición entre la lista proporcionada por el cliente y la configuración del servidor.
SSL_TLSEXT_ERR_NOACK
Protocolo ALPN no seleccionado, por ejemplo, porque no hay protocolos ALPN configurados para esta conexión.

La función de devolución de llamada establecida usando SSL_CTX_set_next_proto_select_cb() debería devolver SSL_TLSEXT_ERR_OK si tiene éxito. Cualquier otro valor es fatal para la conexión.

La función de devolución de llamada establecida usando SSL_CTX_set_next_protos_advertised_cb() debería devolver SSL_TLSEXT_ERR_OK si desea anunciar. De lo contrario, no se incluirá dicha extensión en el ServerHello.
