SSL_handle_events(3ssl)

Paquete: openssl

Licencias: Apache-2.0

SSL_HANDLE_EVENTS(3ssl) OpenSSL SSL_HANDLE_EVENTS(3ssl)

NOMBRE

SSL_handle_events - avanzar la máquina de estados asíncrona y realizar E/S de red

SINOPSIS

#include <openssl/ssl.h>
int SSL_handle_events(SSL *ssl);

DESCRIPCIÓN

SSL_handle_events() realiza cualquier procesamiento interno que esté pendiente en un objeto SSL. Las operaciones exactas realizadas por SSL_handle_events() varían según el tipo de protocolo que se esté utilizando con el objeto SSL dado. Por ejemplo, SSL_handle_events() puede manejar eventos de tiempo de espera que han vencido, o puede intentar, en la medida de lo posible actualmente, realizar operaciones de E/S de red en uno de los BIO subyacentes al objeto SSL.

El principal caso de uso para SSL_handle_events() es permitir que una aplicación que utiliza OpenSSL en modo no bloqueante le dé a OpenSSL una oportunidad de manejar eventos de temporizador, o de responder a la disponibilidad de nuevos datos para leer de un BIO subyacente, o de responder a la oportunidad de escribir datos pendientes en un BIO subyacente.

SSL_handle_events() solo se puede utilizar con los siguientes tipos de objetos SSL:

Objetos SSL DTLS
Utilizar SSL_handle_events() en un objeto SSL que se está utilizando con un método DTLS permite manejar adecuadamente los eventos de tiempo de espera. Esto es equivalente a una llamada a DTLSv1_handle_timeout(3). Dado que SSL_handle_events() maneja un superconjunto de los casos de uso de DTLSv1_handle_timeout(3), debe preferirse para aplicaciones nuevas que no requieran soporte para OpenSSL 3.1 o anterior.

Al usar DTLS, una aplicación debe llamar a SSL_handle_events() según lo indicado por las llamadas a SSL_get_event_timeout(3); el manejo de eventos no se realiza automáticamente mediante llamadas a otras funciones SSL como SSL_read(3) o SSL_write(3). Tenga en cuenta que esto es diferente a QUIC, que también realiza el manejo de eventos implícitamente; véase más adelante.

Objetos SSL de conexión QUIC
Utilizar SSL_handle_events() en un objeto SSL que representa una conexión QUIC permite manejar adecuadamente los eventos de tiempo de espera, así como procesar los datos de red entrantes y escribir los datos de red salientes en cola, si el BIO subyacente tiene la capacidad de aceptarlos.

Normalmente, cuando una aplicación utiliza un objeto SSL en modo bloqueante, no necesita llamar a SSL_handle_events() porque OpenSSL realiza el "ticking" internamente de forma automática. Sin embargo, si una aplicación utiliza una conexión QUIC en modo no bloqueante, debe como mínimo asegurarse de que SSL_handle_events() se llama periódicamente para permitir el manejo de eventos de tiempo de espera. Una aplicación puede averiguar cuándo necesita llamar a SSL_handle_events() para este propósito (si es que alguna vez) llamando a SSL_get_event_timeout(3).

Llamar a SSL_handle_events() en un objeto SSL de conexión QUIC que se está utilizando en modo bloqueante no es necesario a menos que no se realicen llamadas de E/S (como SSL_read(3) o SSL_write(3)) al objeto durante un período de tiempo considerable. Siempre que al menos una llamada al objeto SSL esté bloqueando, no se necesita ninguna llamada de este tipo. Sin embargo, SSL_handle_events() puede usarse opcionalmente en un objeto de conexión QUIC si se desea.

Con el modo de operación asistido por hilos OSSL_QUIC_client_thread_method(3), es innecesario llamar a SSL_handle_events(), ya que el hilo de asistencia maneja los eventos de la conexión QUIC.

Llamar a SSL_handle_events() en cualquier otro tipo de objeto SSL no tiene ningún efecto. Esto se considera un caso de éxito.

Tenga en cuenta que SSL_handle_events() sustituye a la función anterior DTLSv1_handle_timeout(3) para todos los casos de uso.

VALORES DE RETORNO

Devuelve 1 en caso de éxito y 0 en caso de fallo.

VER TAMBIÉN

SSL_get_event_timeout(3), DTLSv1_handle_timeout(3), ssl(7)

HISTORIA

La función SSL_handle_events() se añadió en OpenSSL 3.2.
