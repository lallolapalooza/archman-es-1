SSL_set_async_callback(3ssl)

Paquete: openssl

Licencias: Apache-2.0

SSL_SET_ASYNC_CALLBACK(3ssl) OpenSSL SSL_SET_ASYNC_CALLBACK(3ssl)

NOMBRE

SSL_CTX_set_async_callback, SSL_CTX_set_async_callback_arg, SSL_set_async_callback, SSL_set_async_callback_arg, SSL_get_async_status, SSL_async_callback_fn - gestionar operaciones asíncronas

SINOPSIS

#include <openssl/ssl.h>
typedef int (*SSL_async_callback_fn)(SSL *s, void *arg);
int SSL_CTX_set_async_callback(SSL_CTX *ctx, SSL_async_callback_fn callback);
int SSL_CTX_set_async_callback_arg(SSL_CTX *ctx, void *arg);
int SSL_set_async_callback(SSL *s, SSL_async_callback_fn callback);
int SSL_set_async_callback_arg(SSL *s, void *arg);
int SSL_get_async_status(SSL *s, int *status);

DESCRIPCIÓN

SSL_CTX_set_async_callback() establece una función de devolución de llamada asíncrona. Todos los objetos SSL generados a partir de este SSL_CTX obtendrán esta devolución de llamada. Si un motor admite el mecanismo de devolución de llamada, se llamará automáticamente si se ha establecido SSL_MODE_ASYNC y un motor capaz de asincronía completa una operación criptográfica para notificar a la aplicación que reanude el flujo de trabajo pausado.

SSL_CTX_set_async_callback_arg() establece el argumento de devolución de llamada.

SSL_set_async_callback() permite a una aplicación establecer una devolución de llamada en un objeto SSL asíncrono, de modo que cuando un motor complete una operación criptográfica, se llamará a la devolución de llamada para notificar a la aplicación que reanude el flujo de trabajo pausado.

SSL_set_async_callback_arg() establece un argumento para el objeto SSL cuando se llama a la devolución de llamada anterior.

SSL_get_async_status() devuelve el estado del motor. Esta función facilita la comunicación del motor a la aplicación. Durante una sesión SSL, las operaciones criptográficas se envían a un motor. El estado del motor es muy útil para que una aplicación sepa si la operación se ha enviado correctamente. Si el motor no admite este método de devolución de llamada adicional, se devolverá ASYNC_STATUS_UNSUPPORTED. Consulte ASYNC_WAIT_CTX_set_status() para obtener una descripción de todos los valores de estado.

Un ejemplo de las funciones anteriores sería el siguiente:

1.
La aplicación establece la devolución de llamada asíncrona y los datos de devolución de llamada en una conexión SSL llamando a SSL_set_async_callback().
2.
La aplicación establece SSL_MODE_ASYNC y realiza una llamada SSL asíncrona.
3.
OpenSSL envía la solicitud asíncrona al motor. Si se produce una reintentación en este momento, se establecerá el estado dentro de ASYNC_WAIT_CTX y se llamará a la función de devolución de llamada asíncrona (ir al Paso 7).
4.
El motor OpenSSL pausa el trabajo actual y regresa, para que la aplicación pueda continuar procesando otras conexiones.
5.
En un momento posterior (probablemente a través de un mecanismo de sondeo o una interrupción), el motor será consciente de que la solicitud asíncrona ha terminado de procesarse.
6.
El motor llamará a la devolución de llamada de la aplicación pasando los datos de devolución de llamada como parámetro.
7.
La función de devolución de llamada debería ejecutarse. Nota: es un requisito que la función de devolución de llamada sea pequeña y no bloqueante, ya que se ejecutará en el contexto de un mecanismo de sondeo o una interrupción.
8.
Es responsabilidad de la aplicación, a través de la función de devolución de llamada, programar la nueva llamada a la función asíncrona de OpenSSL y continuar procesando.
9.
La función de devolución de llamada tiene la opción de verificar el estado devuelto a través de SSL_get_async_status() para determinar si ocurrió una reintentación en lugar de que se enviara la solicitud, lo que permite un procesamiento diferente si es necesario.

VALORES DE RETORNO

SSL_CTX_set_async_callback(), SSL_set_async_callback(), SSL_CTX_set_async_callback_arg(), SSL_CTX_set_async_callback_arg() y SSL_get_async_status() devuelven 1 en caso de éxito o 0 en caso de error.
