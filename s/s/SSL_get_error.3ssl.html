Paquete: openssl

SSL_GET_ERROR(3ssl) OpenSSL SSL_GET_ERROR(3ssl)

NOMBRE

SSL_get_error - obtener el código de resultado para la operación de E/S TLS/SSL

SINOPSIS

#include <openssl/ssl.h>
int SSL_get_error(const SSL *ssl, int ret);

DESCRIPCIÓN

SSL_get_error() devuelve un código de resultado (adecuado para la sentencia `switch` de C) para una llamada anterior a SSL_connect(), SSL_accept(), SSL_do_handshake(), SSL_read_ex(), SSL_read(), SSL_peek_ex(), SSL_peek(), SSL_shutdown(), SSL_write_ex() o SSL_write() en ssl. El valor devuelto por esa función de E/S TLS/SSL debe pasarse a SSL_get_error() en el parámetro ret.

Además de ssl y ret, SSL_get_error() inspecciona la cola de errores de OpenSSL del hilo actual. Por lo tanto, SSL_get_error() debe usarse en el mismo hilo que realizó la operación de E/S TLS/SSL, y no deben aparecer otras llamadas a funciones de OpenSSL entre medias. La cola de errores del hilo actual debe estar vacía antes de intentar la operación de E/S TLS/SSL, o SSL_get_error() no funcionará de manera fiable.

NOTAS

Algunas implementaciones TLS no envían una alerta `close_notify` al cerrar.

En un EOF inesperado, las versiones anteriores a OpenSSL 3.0 devolvían SSL_ERROR_SYSCALL, no se añadía nada a la pila de errores y `errno` era 0. Desde OpenSSL 3.0, el error devuelto es SSL_ERROR_SSL con un error significativo en la pila de errores (el código de razón de error SSL_R_UNEXPECTED_EOF_WHILE_READING). Este código de razón de error puede usarse para tomar decisiones de control de flujo (consulte la página del manual de ERR_GET_REASON(3) para obtener más detalles sobre esto).

VALORES DE RETORNO

Actualmente pueden ocurrir los siguientes valores de retorno:

SSL_ERROR_NONE
La operación de E/S TLS/SSL se completó. Este código de resultado se devuelve si y solo si ret > 0.
SSL_ERROR_ZERO_RETURN
El par TLS/SSL ha cerrado la conexión para escritura enviando la alerta `close_notify`. No se pueden leer más datos. Tenga en cuenta que SSL_ERROR_ZERO_RETURN no indica necesariamente que el transporte subyacente se haya cerrado.

Este error también puede aparecer cuando la opción SSL_OP_IGNORE_UNEXPECTED_EOF está configurada. Consulte SSL_CTX_set_options(3) para obtener más detalles.

SSL_ERROR_WANT_READ, SSL_ERROR_WANT_WRITE
La operación no se completó y puede ser reintentada más tarde.

Para objetos SSL que no son QUIC, SSL_ERROR_WANT_READ se devuelve cuando la última operación fue una operación de lectura de un BIO no bloqueante. Significa que no había suficientes datos disponibles en ese momento para completar la operación. Si más tarde el BIO subyacente tiene datos disponibles para leer, la misma función puede ser llamada de nuevo.

SSL_read() y SSL_read_ex() también pueden establecer SSL_ERROR_WANT_READ cuando todavía hay datos sin procesar disponibles en la capa SSL o BIO, incluso para un BIO bloqueante. Consulte SSL_read(3) para más información.

Para objetos SSL que no son QUIC, SSL_ERROR_WANT_WRITE se devuelve cuando la última operación fue una escritura a un BIO no bloqueante y no pudo enviar todos los datos al BIO. Cuando el BIO esté listo para escribir de nuevo, la misma función puede ser llamada de nuevo.

Tenga en cuenta que el reintento puede volver a provocar una condición de SSL_ERROR_WANT_READ o SSL_ERROR_WANT_WRITE. No hay un límite superior fijo para el número de iteraciones que pueden ser necesarias hasta que se produzca un progreso visible a nivel de protocolo de aplicación.

Para objetos SSL QUIC, el significado de SSL_ERROR_WANT_READ y SSL_ERROR_WANT_WRITE tiene semánticas diferentes pero en gran medida compatibles. Dado que QUIC implementa su propio control de flujo y utiliza datagramas UDP, las condiciones de contrapresión en términos de que el BIO subyacente proporcione E/S de red no son directamente relevantes para las circunstancias en las que se producen estos errores. En particular, SSL_ERROR_WANT_WRITE indica que el búfer de envío interno de OpenSSL para un flujo QUIC determinado se ha llenado. Del mismo modo, SSL_ERROR_WANT_READ indica que el búfer de recepción interno de OpenSSL para un flujo QUIC determinado está vacío.

Es seguro llamar a SSL_read() o SSL_read_ex() cuando hay más datos disponibles, incluso si la llamada que estableció este error fue una SSL_write() o SSL_write_ex(). Sin embargo, si la llamada fue una SSL_write() o SSL_write_ex(), debería ser llamada de nuevo para continuar enviando los datos de la aplicación. Si obtiene SSL_ERROR_WANT_WRITE de SSL_write() o SSL_write_ex(), no debe realizar ninguna otra operación que pueda desencadenar E/S aparte de repetir la llamada anterior a SSL_write().

Para BIOs de sockets (por ejemplo, cuando se usó SSL_set_fd()), se puede usar select() o poll() en el socket subyacente para averiguar cuándo se debe reintentar la función de E/S TLS/SSL.

Advertencia: Cualquier función de E/S TLS/SSL puede llevar a cualquiera de SSL_ERROR_WANT_READ y SSL_ERROR_WANT_WRITE. En particular, SSL_read_ex(), SSL_read(), SSL_peek_ex() o SSL_peek() pueden querer escribir datos y SSL_write() o SSL_write_ex() pueden querer leer datos. Esto se debe principalmente a que los handshakes TLS/SSL pueden ocurrir en cualquier momento durante el protocolo (iniciados por el cliente o el servidor); SSL_read_ex(), SSL_read(), SSL_peek_ex(), SSL_peek(), SSL_write_ex() y SSL_write() manejarán cualquier handshake pendiente.

SSL_ERROR_WANT_CONNECT, SSL_ERROR_WANT_ACCEPT
La operación no se completó; la misma función de E/S TLS/SSL debe ser llamada de nuevo más tarde. El BIO subyacente aún no estaba conectado al par y la llamada se bloquearía en connect()/accept(). La función SSL debe ser llamada de nuevo cuando la conexión se establezca. Estos mensajes solo pueden aparecer con un BIO BIO_s_connect() o BIO_s_accept(), respectivamente. Para averiguar cuándo se ha establecido la conexión correctamente, en muchas plataformas se puede usar select() o poll() para escribir en el descriptor de archivo del socket.
SSL_ERROR_WANT_X509_LOOKUP
La operación no se completó porque un callback de aplicación configurado por SSL_CTX_set_client_cert_cb() ha pedido ser llamado de nuevo. La función de E/S TLS/SSL debe ser llamada de nuevo más tarde. Los detalles dependen de la aplicación.
SSL_ERROR_WANT_ASYNC
La operación no se completó porque un motor asíncrono todavía está procesando datos. Esto solo ocurrirá si el modo se ha establecido en SSL_MODE_ASYNC usando SSL_CTX_set_mode(3) o SSL_set_mode(3) y se está utilizando un motor compatible con asíncronos. Una aplicación puede determinar si el motor ha completado su procesamiento usando select() o poll() en el descriptor de archivo de espera asíncrona. Este descriptor de archivo está disponible llamando a SSL_get_all_async_fds(3) o SSL_get_changed_async_fds(3). La función de E/S TLS/SSL debe ser llamada de nuevo más tarde. La función debe ser llamada desde el mismo hilo desde el que se realizó la llamada original.
SSL_ERROR_WANT_ASYNC_JOB
El trabajo asíncrono no pudo iniciarse porque no había trabajos asíncronos disponibles en el pool (consulte ASYNC_init_thread(3)). Esto solo ocurrirá si el modo se ha establecido en SSL_MODE_ASYNC usando SSL_CTX_set_mode(3) o SSL_set_mode(3) y se ha establecido un límite máximo en el pool de trabajos asíncronos a través de una llamada a ASYNC_init_thread(3). La aplicación debe reintentar la operación después de un tiempo actual.

VALORES DE RETORNO

SSL_ERROR_WANT_ASYNC
La operación no se completó porque se está ejecutando una operación asíncrona para el hilo actual.
SSL_ERROR_WANT_CLIENT_HELLO_CB
La operación no se completó porque una llamada de retorno de aplicación establecida por SSL_CTX_set_client_hello_cb() solicitó ser llamada de nuevo. La función de E/S TLS/SSL debe ser llamada de nuevo más tarde. Los detalles dependen de la aplicación.
SSL_ERROR_SYSCALL
Ocurrió un error de E/S irrecuperable y fatal. La cola de errores de OpenSSL puede contener más información sobre el error. Para E/S de sockets en sistemas Unix, consulte errno para obtener detalles. Si este error ocurre, no se deben realizar más operaciones de E/S en la conexión y no se debe llamar a SSL_shutdown().

Este valor también puede ser devuelto para otros errores, consulte la cola de errores para obtener detalles.

SSL_ERROR_SSL
Ocurrió un error fatal e irrecuperable en la biblioteca SSL, generalmente un error de protocolo. La cola de errores de OpenSSL contiene más información sobre el error. Si este error ocurre, no se deben realizar más operaciones de E/S en la conexión y no se debe llamar a SSL_shutdown().

HISTORIA

El código de error SSL_ERROR_WANT_ASYNC se añadió en OpenSSL 1.1.0. El código de error SSL_ERROR_WANT_CLIENT_HELLO_CB se añadió en OpenSSL 1.1.1.
