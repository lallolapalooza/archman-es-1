SSL_CTX_set_tlsext_status_cb(3ssl)

Paquete: openssl

Licencias: Apache-2.0

SSL_CTX_SET_TLSEXT_STATUS_CB(3ssl) OpenSSL SSL_CTX_SET_TLSEXT_STATUS_CB(3ssl)

NOMBRE

SSL_CTX_set_tlsext_status_cb, SSL_CTX_get_tlsext_status_cb, SSL_CTX_set_tlsext_status_arg, SSL_CTX_get_tlsext_status_arg, SSL_CTX_set_tlsext_status_type, SSL_CTX_get_tlsext_status_type, SSL_set_tlsext_status_type, SSL_get_tlsext_status_type, SSL_get_tlsext_status_ocsp_resp, SSL_set_tlsext_status_ocsp_resp, SSL_get0_tlsext_status_ocsp_resp_ex, SSL_set0_tlsext_status_ocsp_resp_ex - Funciones de Solicitud de Estado de Certificado OCSP

SINOPSIS

#include <openssl/tls1.h>
long SSL_CTX_set_tlsext_status_cb(SSL_CTX *ctx, int (*callback)(SSL *, void *));
long SSL_CTX_get_tlsext_status_cb(SSL_CTX *ctx, int (**callback)(SSL *, void *));
long SSL_CTX_set_tlsext_status_arg(SSL_CTX *ctx, void *arg);
long SSL_CTX_get_tlsext_status_arg(SSL_CTX *ctx, void **arg);
long SSL_CTX_set_tlsext_status_type(SSL_CTX *ctx, int type);
long SSL_CTX_get_tlsext_status_type(SSL_CTX *ctx);
long SSL_set_tlsext_status_type(SSL *s, int type);
long SSL_get_tlsext_status_type(SSL *s);
long SSL_get_tlsext_status_ocsp_resp(ssl, unsigned char **resp);
long SSL_set_tlsext_status_ocsp_resp(ssl, unsigned char *resp, int len);
long SSL_get0_tlsext_status_ocsp_resp_ex(ssl, STACK_OF(OCSP_RESPONSE) **resp);
long SSL_set0_tlsext_status_ocsp_resp_ex(ssl, STACK_OF(OCSP_RESPONSE) *resp);

DESCRIPCIÓN

Una aplicación cliente puede solicitar que un servidor envíe respuesta(s) de estado OCSP (también conocido como OCSP stapling). Para hacerlo, el cliente debe llamar a la función SSL_CTX_set_tlsext_status_type() antes de la creación de cualquier objeto SSL. Alternativamente, una aplicación puede llamar a la función SSL_set_tlsext_status_type() en un objeto SSL individual antes del inicio del handshake. Actualmente, el único tipo soportado es TLSEXT_STATUSTYPE_ocsp. Este valor debe pasarse en el argumento type. Llamar a SSL_CTX_get_tlsext_status_type() devolverá el tipo TLSEXT_STATUSTYPE_ocsp previamente establecido mediante SSL_CTX_set_tlsext_status_type() o -1 si no está establecido.

Para versiones de TLS anteriores a 1.3, el servidor solo envía una única respuesta de estado OCSP. TLS 1.3 especifica que el servidor puede enviar respuestas de estado OCSP para toda la cadena (OCSP multi-stapling).

El cliente debe proporcionar adicionalmente una función de callback para decidir qué hacer con la(s) respuesta(s) OCSP devuelta(s) llamando a SSL_CTX_set_tlsext_status_cb(). La función de callback debe determinar si la(s) respuesta(s) OCSP devuelta(s) son aceptables o no. A la función de callback se le pasará como argumento el valor previamente establecido mediante una llamada a SSL_CTX_set_tlsext_status_arg(). Tenga en cuenta que la función de callback no se llamará en el caso de un handshake donde ocurra la reanudación de sesión (porque no hay certificados intercambiados en dicho handshake). La función de callback previamente establecida mediante SSL_CTX_set_tlsext_status_cb() puede recuperarse llamando a SSL_CTX_get_tlsext_status_cb(), y el argumento llamando a SSL_CTX_get_tlsext_status_arg().

En el lado del cliente, SSL_get_tlsext_status_type() puede utilizarse para determinar si el cliente ha llamado previamente a SSL_set_tlsext_status_type(). Devolverá TLSEXT_STATUSTYPE_ocsp si se ha llamado o -1 en caso contrario. En el lado del servidor, SSL_get_tlsext_status_type() puede utilizarse para determinar si el cliente solicitó OCSP stapling. Si el cliente lo solicitó, esta función devolverá TLSEXT_STATUSTYPE_ocsp, o -1 en caso contrario.

Una única respuesta devuelta por el servidor (TLS < 1.3) puede obtenerse mediante una llamada a SSL_get_tlsext_status_ocsp_resp(). El valor *resp se actualizará para apuntar a los datos de respuesta OCSP y el valor de retorno será la longitud de esos datos. Típicamente, una función de callback obtendría un objeto OCSP_RESPONSE de estos datos mediante una llamada a la función d2i_OCSP_RESPONSE(). Si el servidor no ha proporcionado ningún dato de respuesta, *resp será NULL y el valor de retorno de SSL_get_tlsext_status_ocsp_resp() será -1.

Una aplicación de servidor también debe llamar a la función SSL_CTX_set_tlsext_status_cb() si desea poder proporcionar a los clientes una respuesta OCSP (única) para el certificado del servidor. Típicamente, la función de callback del servidor obtendría el certificado del servidor que se está enviando de vuelta al cliente mediante una llamada a SSL_get_certificate(); recuperaría la respuesta OCSP relacionada a enviar de vuelta; y luego establecería esos datos de respuesta llamando a SSL_set_tlsext_status_ocsp_resp(). Se debe proporcionar un puntero a los datos de respuesta en el argumento resp, y la longitud de esos datos debe estar en el argumento len.

En el caso de multi-stapling, las respuestas a ser devueltas por el servidor pueden obtenerse mediante una llamada a SSL_get0_tlsext_status_ocsp_resp_ex(). El valor *resp se actualizará para apuntar a la pila de respuestas OCSP y el valor de retorno será el número de respuestas en la pila. Se espera que las respuestas OCSP en la pila estén en el mismo orden que los certificados en la cadena. Si no hay ninguna respuesta OCSP disponible para un certificado en la cadena, un elemento NULL en la pila representará esto. Típicamente, una función de callback obtendría un OCSP_RESPONSE de la pila mediante una llamada a sk_OCSP_RESPONSE_pop. Si el servidor no ha proporcionado ningún dato de respuesta, *resp será NULL y el valor de retorno de SSL_get0_tlsext_status_ocsp_resp_ex() será -1.

Una aplicación de servidor también debe llamar a la función SSL_CTX_set_tlsext_status_cb() si desea poder proporcionar a los clientes respuestas de Estado de Certificado OCSP, donde TLS 1.3 permite el multi-stapling, es decir, proporcionar respuestas para todos los certificados en la cadena del certificado del servidor (excluyendo el certificado raíz de la CA). Los certificados enviados de vuelta al cliente y para los cuales se deben adquirir respuesta(s) OCSP podrían obtenerse mediante una llamada a SSL_get_certificate() resp. SSL_get0_chain_certs(). Las respuesta(s) OCSP se establecen entonces llamando a SSL_set0_tlsext_status_ocsp_resp_ex(). Se debe proporcionar una pila de respuestas OCSP en el argumento resp. Se espera que las respuestas OCSP en la pila estén en el mismo orden que los certificados en la cadena. Si no hay ninguna respuesta OCSP disponible para un certificado en la cadena, un elemento NULL en la pila representará esto.

VALORES DE RETORNO

La función de callback, cuando se utiliza en el lado del cliente, debe devolver un valor negativo en caso de error; 0 si la respuesta no es aceptable (en cuyo caso el handshake fallará) o un valor positivo si es aceptable.

La función de callback, cuando se utiliza en el lado del servidor, debe devolver SSL_TLSEXT_ERR_OK (lo que significa que la respuesta OCSP que se ha establecido debe devolverse), SSL_TLSEXT_ERR_NOACK (lo que significa que no se debe devolver ninguna respuesta OCSP) o SSL_TLSEXT_ERR_ALERT_FATAL (lo que significa que ha ocurrido un error fatal).

SSL_CTX_set_tlsext_status_cb(), SSL_CTX_set_tlsext_status_arg(), SSL_CTX_set_tlsext_status_type(), SSL_set_tlsext_status_type(), SSL_set_tlsext_status_ocsp_resp() devuelven 0 en caso de error o 1 en caso de éxito. SSL_set0_tlsext_status_ocsp_resp_ex() siempre devolverá 1.

SSL_CTX_get_tlsext_status_type() devuelve el valor previamente establecido por SSL_CTX_set_tlsext_status_type(), o -1 si no está establecido.

SSL_get_tlsext_status_ocsp_resp() devuelve la longitud de los datos de respuesta OCSP o -1 si no hay datos de respuesta OCSP.

SSL_get0_tlsext_status_ocsp_resp_ex() devuelve el número de respuestas OCSP en la pila o -1 si no hay datos de respuesta OCSP.

SSL_get_tlsext_status_type() devuelve TLSEXT_STATUSTYPE_ocsp en el lado del cliente si SSL_set_tlsext_status_type() se llamó previamente, o en el lado del servidor si el cliente solicitó OCSP stapling. De lo contrario, se devuelve -1.
