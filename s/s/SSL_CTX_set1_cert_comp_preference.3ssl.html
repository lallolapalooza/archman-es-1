SSL_CTX_set1_cert_comp_preference(3ssl)

Paquete: openssl

Licencias: Apache-2.0

SSL_CTX_SET1_CERT_COMP_PREFERENCE(3ssl) OpenSSL SSL_CTX_SET1_CERT_COMP_PREFERENCE(3ssl)

NOMBRE

SSL_CTX_set1_cert_comp_preference, SSL_set1_cert_comp_preference, SSL_CTX_compress_certs, SSL_compress_certs, SSL_CTX_get1_compressed_cert, SSL_get1_compressed_cert, SSL_CTX_set1_compressed_cert, SSL_set1_compressed_cert - Funciones de compresión de certificados

SINOPSIS

#include <openssl/ssl.h>
int SSL_CTX_set1_cert_comp_preference(SSL_CTX *ctx, int *algs, size_t len);
int SSL_set1_cert_comp_preference(SSL *ssl, int *algs, size_t len);
int SSL_CTX_compress_certs(SSL_CTX *ctx, int alg);
int SSL_compress_certs(SSL *ssl, int alg);
size_t SSL_CTX_get1_compressed_cert(SSL_CTX *ctx, int alg, unsigned char **data,
                                    size_t *orig_len);
size_t SSL_get1_compressed_cert(SSL *ssl, int alg, unsigned char **data,
                                size_t *orig_len);
int SSL_CTX_set1_compressed_cert(SSL_CTX *ctx, int alg,
                                 unsigned char *comp_data,
                                 size_t comp_length, size_t orig_length);
int SSL_set1_compressed_cert(SSL *ssl, int alg, unsigned char *comp_data,
                             size_t comp_length, size_t orig_length);

DESCRIPCIÓN

Estas funciones controlan la característica de compresión de certificados. La compresión de certificados solo está disponible para TLSv1.3 según se define en RFC8879.

SSL_CTX_set1_cert_comp_preference() y SSL_set1_cert_comp_preference() se utilizan para especificar los algoritmos de compresión preferidos. El argumento algs es una matriz de algoritmos y length es el número de elementos en la matriz algs. Solo los algoritmos habilitados en la biblioteca se aceptarán en algs, los algoritmos desconocidos en algs se ignoran. En caso de error, el orden de preferencia permanece sin modificar.

Los siguientes algoritmos de compresión (argumentos alg) pueden ser utilizados:

  • TLSEXT_comp_cert_brotli
  • TLSEXT_comp_cert_zlib
  • TLSEXT_comp_cert_zstd

El orden anterior es también el orden de preferencia por defecto. Si no se especifica un orden de preferencia, se envía el orden de preferencia por defecto al par y se utilizará el orden de preferencia del par recibido al comprimir un certificado. De lo contrario, se envía el orden de preferencia configurado al par y se utiliza para filtrar el orden de preferencia del par.

SSL_CTX_compress_certs() y SSL_compress_certs() se utilizan para precomprimir todos los certificados configurados en un objeto SSL_CTX/SSL con el algoritmo alg. Si alg es 0, los certificados se comprimen con los algoritmos especificados en la lista de preferencias. Llamar a estas funciones en un objeto SSL_CTX/SSL del cliente resultará en un error, ya que solo los certificados del servidor pueden ser precomprimidos.

SSL_CTX_get1_compressed_cert() y SSL_get1_compressed_cert() se utilizan para obtener el certificado precomprimido que se estableció más recientemente y que puede almacenarse para su uso posterior. Llamar a estas funciones en un objeto SSL_CTX/SSL del cliente resultará en un error, ya que solo los certificados del servidor pueden ser precomprimidos. Los argumentos data y orig_len son obligatorios.

Los datos del certificado comprimido pueden pasarse a SSL_CTX_set1_compressed_cert() o SSL_set1_compressed_cert() para proporcionar una versión precomprimida del certificado que se estableció más recientemente. Este certificado precomprimido solo puede ser utilizado por un servidor.

NOTAS

Cada lado de la conexión envía su lista de preferencias de algoritmos de compresión a su par, indicando el soporte para certificados comprimidos. La lista de preferencias recibida se filtra por la lista de preferencias configurada (es decir, se guarda la intersección). Dado que la lista por defecto incluye todos los algoritmos habilitados, no especificar una preferencia permitirá cualquier algoritmo habilitado por el par. El orden de preferencias del par filtrado se utiliza para determinar qué algoritmo usar al enviar un certificado comprimido.

Solo los certificados del servidor pueden ser precomprimidos. Llamar a cualquiera de estas funciones (excepto SSL_CTX_set1_cert_comp_preference()/SSL_set1_cert_comp_preference()) en un objeto SSL_CTX/SSL del cliente devolverá un error. Los certificados del cliente se comprimen bajo demanda, ya que los datos de contexto únicos del servidor se comprimen junto con el certificado.

Para SSL_CTX_set1_cert_comp_preference() y SSL_set1_cert_comp_preference(), el argumento len es el tamaño del argumento algs en bytes.

El certificado comprimido devuelto por SSL_CTX_get1_compressed_cert() y SSL_get1_compressed_cert() es el último certificado establecido en el objeto SSL_CTX/SSL. El certificado es copiado por la función y el llamador debe liberar *data usando OPENSSL_free().

Los datos del certificado comprimido establecidos por SSL_CTX_set1_compressed_cert() y SSL_set1_compressed_cert() se copian en el objeto SSL_CTX/SSL.

SSL_CTX_compress_certs() y SSL_compress_certs() devuelven un error en las siguientes condiciones:

  • Si no se han configurado certificados.
  • Si el algoritmo especificado alg no está habilitado.
  • Si alg es 0 y no hay algoritmos de compresión habilitados.

El envío de certificados comprimidos puede ser deshabilitado en una conexión a través de la opción SSL_OP_NO_TX_CERTIFICATE_COMPRESSION. La recepción de certificados comprimidos puede ser deshabilitada en una conexión a través de la opción SSL_OP_NO_RX_CERTIFICATE_COMPRESSION.

VALORES DE RETORNO

SSL_CTX_set1_cert_comp_preference(), SSL_set1_cert_comp_preference(), SSL_CTX_compress_certs(), SSL_compress_certs(), SSL_CTX_set1_compressed_cert(), y SSL_set1_compressed_cert() devuelven 1 en caso de éxito y 0 en caso de error.

SSL_CTX_get1_compressed_cert() y SSL_get1_compressed_cert() devuelven la longitud de la memoria asignada en caso de éxito y 0 en caso de error.

VER TAMBIÉN

SSL_CTX_set_options(3), SSL_CTX_use_certificate(3)
