SSL_CTX_set_read_ahead(3ssl)

Paquete: openssl

Licencias: Apache-2.0

SSL_CTX_SET_READ_AHEAD(3ssl) OpenSSL SSL_CTX_SET_READ_AHEAD(3ssl)

NOMBRE

SSL_CTX_set_read_ahead, SSL_CTX_get_read_ahead, SSL_set_read_ahead, SSL_get_read_ahead, SSL_CTX_get_default_read_ahead - gestionar si se leen tantos bytes de entrada como sea posible

SINOPSIS

#include <openssl/ssl.h>
void SSL_set_read_ahead(SSL *s, int yes);
int SSL_get_read_ahead(const SSL *s);
SSL_CTX_set_read_ahead(SSL_CTX *ctx, int yes);
long SSL_CTX_get_read_ahead(SSL_CTX *ctx);
long SSL_CTX_get_default_read_ahead(SSL_CTX *ctx);

DESCRIPCIÓN

SSL_CTX_set_read_ahead() y SSL_set_read_ahead() establecen si debemos leer tantos bytes de entrada como sea posible (para lecturas no bloqueantes) o no. Por ejemplo, si OpenSSL requiere actualmente x bytes, pero hay y bytes disponibles en el BIO subyacente (donde y > x), entonces OpenSSL leerá los y bytes en su búfer (siempre que el búfer sea lo suficientemente grande) si la lectura anticipada está activada, o x bytes en caso contrario. Establecer el parámetro yes a 0 desactiva la lectura anticipada; otros valores la activan. SSL_CTX_set_default_read_ahead() es idéntico a SSL_CTX_set_read_ahead().

SSL_CTX_get_read_ahead() y SSL_get_read_ahead() indican si la lectura anticipada se ha establecido o no. SSL_CTX_get_default_read_ahead() es idéntico a SSL_CTX_get_read_ahead().

Estas funciones no se pueden utilizar con objetos SSL QUIC. SSL_set_read_ahead() no tiene ningún efecto si se llama en un objeto SSL QUIC.

NOTAS

Estas funciones no tienen impacto cuando se utilizan con DTLS. Los valores de retorno para SSL_CTX_get_read_head() y SSL_get_read_ahead() no están definidos para DTLS. Establecer read_ahead puede afectar al comportamiento de la función SSL_pending() (ver SSL_pending(3)).

Dado que SSL_read() puede devolver SSL_ERROR_WANT_READ para datos no aplicables, y SSL_has_pending() no puede distinguir entre datos procesados y no procesados, se recomienda que si la lectura anticipada está activada, SSL_MODE_AUTO_RETRY no se desactive usando SSL_CTX_clear_mode(). Esto evitará obtener SSL_ERROR_WANT_READ cuando todavía haya un registro completo disponible que no haya sido procesado.

Si la aplicación desea continuar utilizando el transporte subyacente (por ejemplo, conexión TCP) después de que la conexión SSL haya finalizado usando SSL_shutdown(), la lectura anticipada debe desactivarse. De lo contrario, la estructura SSL podría leer datos que no debería.

VALORES DE RETORNO

SSL_get_read_ahead() y SSL_CTX_get_read_ahead() devuelven 0 si la lectura anticipada está desactivada y un valor distinto de cero en caso contrario.

VER TAMBIÉN

ssl(7), SSL_pending(3)
