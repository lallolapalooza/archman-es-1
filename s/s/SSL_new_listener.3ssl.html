SSL_new_listener(3ssl)

Paquete: openssl

Licencias: Apache-2.0

SSL_NEW_LISTENER(3ssl) OpenSSL SSL_NEW_LISTENER(3ssl)

NOMBRE

SSL_new_listener, SSL_new_listener_from, SSL_is_listener, SSL_get0_listener, SSL_listen, SSL_accept_connection, SSL_get_accept_connection_queue_len, SSL_new_from_listener, SSL_ACCEPT_CONNECTION_NO_BLOCK - interfaz de objeto SSL para aceptación de conexiones abstractas

SINOPSIS

#include <openssl/ssl.h>
SSL *SSL_new_listener(SSL_CTX *ctx, uint64_t flags);
SSL *SSL_new_listener_from(SSL *ssl, uint64_t flags);
int SSL_is_listener(SSL *ssl);
SSL *SSL_get0_listener(SSL *ssl);
int SSL_listen(SSL *ssl);
#define SSL_ACCEPT_CONNECTION_NO_BLOCK
SSL *SSL_accept_connection(SSL *ssl, uint64_t flags);
size_t SSL_get_accept_connection_queue_len(SSL *ssl);
SSL *SSL_new_from_listener(SSL *ssl, uint64_t flags);

DESCRIPCIÓN

La función SSL_new_listener() crea un objeto SSL oyente. Los objetos SSL oyentes están especializados para aceptar conexiones de red de forma agnóstica al protocolo. No se pueden utilizar, por ejemplo, para enviar o recibir datos utilizando SSL_write_ex(3) o SSL_read_ex(3). En general, solo las funciones expresamente documentadas como compatibles con un objeto SSL oyente están disponibles.

La función SSL_new_listener_from() crea un objeto SSL oyente que está subordinado a un objeto SSL de dominio QUIC ssl. Ver SSL_new_domain(3) y openssl-quic-concurrency(7) para obtener detalles sobre los objetos SSL de dominio QUIC.

Un objeto SSL oyente admite las siguientes operaciones:

  • Operaciones estándar de conteo de referencias y liberación, como SSL_up_ref(3) y SSL_free(3);
  • Operaciones de configuración de BIO de red, como SSL_set_bio(3);
  • APIs de procesamiento de eventos y habilitación de sondeo como SSL_handle_events(3), SSL_get_event_timeout(3), SSL_get_rpoll_descriptor(3), SSL_get_wpoll_descriptor(3), SSL_net_read_desired(3) y SSL_net_write_desired(3);
  • Ciertos parámetros configurables descritos en SSL_get_value_uint(3) (ver SSL_get_value_uint(3) para detalles);
  • Aceptación de conexiones de red utilizando las funciones documentadas en esta página del manual, como SSL_accept_connection().

El flujo de trabajo básico para usar un objeto oyente es el siguiente:

  • Crear un nuevo objeto oyente usando SSL_new_listener() con un SSL_CTX que use un SSL_METHOD compatible (como OSSL_QUIC_server_method(3));
  • Configurar los BIOs de red apropiados usando SSL_set_bio(3) en el objeto SSL oyente;
  • Configurar el modo de bloqueo usando SSL_set_blocking_mode(3);
  • Aceptar conexiones en un bucle llamando a SSL_accept_connection(). Cada objeto SSL devuelto es una conexión válida que puede usarse de forma normal.

La función SSL_is_listener() devuelve 1 si y solo si un objeto SSL es un objeto SSL oyente.

La función SSL_get0_listener() devuelve un objeto oyente que está relacionado con el objeto SSL dado, si existe. Para un objeto oyente, es el mismo objeto (la función devuelve su argumento). Para un objeto de conexión que fue creado por un objeto oyente, se devuelve ese objeto oyente. Si el argumento ssl es un objeto SSL que no es un objeto oyente y que no desciende de un objeto oyente (por ejemplo, una conexión obtenida usando SSL_accept_connection()) o indirectamente de un objeto oyente (por ejemplo, un objeto SSL de flujo QUIC obtenido usando SSL_accept_stream() llamado en una conexión obtenida usando SSL_accept_connection()) el valor devuelto es NULL. Ver NOTAS abajo para advertencias relacionadas con conexiones SSL pendientes en la cola de aceptación de un oyente QUIC.

La función SSL_listen() comienza a monitorear el oyente ssl en busca de conexiones entrantes. Se deben haber configurado BIOs apropiados antes de llamar a SSL_listen(), junto con cualquier otra configuración necesaria para el objeto SSL oyente. Normalmente no es necesario llamar a SSL_listen() porque se llamará automáticamente en la primera llamada a SSL_accept_connection(). Sin embargo, SSL_listen() puede llamarse explícitamente si se desea controlar precisamente cuándo comienza el proceso de escucha, o para asegurar que no ocurran errores al empezar a escuchar conexiones. Después de una llamada exitosa a SSL_listen() (o SSL_accept_connection()). La función SSL_listen() es idempotente, las llamadas subsiguientes en el mismo objeto ssl no tienen efecto. Esta llamada solo se admite en objetos SSL oyentes.

La llamada SSL_accept_connection() solo se admite en un objeto SSL oyente y acepta una nueva conexión entrante. Se crea y se devuelve un nuevo objeto SSL que representa la conexión aceptada en caso de éxito. Si no hay una conexión entrante disponible y el objeto SSL oyente está configurado en modo no bloqueante, se devuelve NULL.

El nuevo objeto SSL devuelto por SSL_accept_connection() puede haber completado o no su handshake en el momento en que se devuelve. Opcionalmente, puede usar la función SSL_is_init_finished(3) para determinar esto. Puede llamar a las funciones SSL_accept(3), SSL_do_handshake(3) o SSL_handle_events(3) para avanzar el estado del objeto SSL hacia la finalización del handshake. Otras funciones de "E/S" también pueden avanzar implícitamente el estado del handshake, como SSL_poll(3), SSL_read(3) y SSL_write(3).

La bandera SSL_ACCEPT_CONNECTION_NO_BLOCK puede especificarse a SSL_accept_connection(). Si se especifica, la llamada no se bloquea incluso si el objeto SSL oyente está configurado en modo bloqueante.

La llamada SSL_get_accept_connection_queue_len() devuelve el número de conexiones pendientes en la cola del oyente ssl. SSL_accept_connection() devuelve la siguiente conexión pendiente, eliminándola de la cola. El recuento de conexiones devuelto es un valor puntual, el número real de conexiones que se devolverán en última instancia puede ser diferente.

Actualmente, los objetos SSL oyentes solo son compatibles con el uso de servidor QUIC a través de OSSL_QUIC_server_method(3), o uso solo de cliente QUIC a través de OSSL_QUIC_client_method(3) o OSSL_QUIC_client_thread_method(3) (ver "USO SOLO DE CLIENTE"). Se espera que la interfaz de oyente, que proporciona una API abstracta para la aceptación de conexiones, se expanda para admitir otros protocolos, como TLS sobre TCP, TCP simple o DTLS en el futuro.

SSL_listen() y SSL_accept_connection() son funciones de "E/S", lo que significa que actualizan el valor devuelto por SSL_get_error(3) si fallan.

USO SOLO DE CLIENTE

También es posible utilizar la interfaz de oyente sin aceptar ninguna conexión y sin escuchar conexiones. Esto puede ser útil en circunstancias en las que sea deseable que múltiples conexiones compartan los mismos recursos de red subyacentes. Por ejemplo, múltiples conexiones de cliente QUIC salientes podrían utilizar el mismo socket UDP subyacente.

Para deshabilitar la validación de direcciones del cliente en un objeto SSL oyente, la bandera SSL_LISTENER_FLAG_NO_VALIDATE puede pasarse en el campo de banderas tanto de SSL_new_listener() como de SSL_new_listener_from(). Tenga en cuenta que esta bandera solo afecta al envío de tramas de reintento para la validación de la dirección del servidor. Es posible que todavía se comuniquen tokens desde el servidor a través de tramas NEW_TOKEN, que aún se validarán al recibirlas en conexiones futuras. Tenga en cuenta que esta configuración no se recomienda y puede ser peligrosa en entornos no confiables. No realizar la validación de direcciones expone al servidor a clientes maliciosos que pueden abrir un gran número de conexiones y nunca realizar transacciones de datos en ellas (aproximadamente equivalente a un ataque de inundación SYN de TCP), lo cual la validación de direcciones mitiga.

">La función SSL_new_from_listener() crea una conexión de cliente bajo un objeto SSL de escucha dado. Para QUIC, también es posible utilizar SSL_new_from_listener(), lo que resulta en un punto final de red UDP que tiene conexiones tanto entrantes como salientes.

El argumento flags de SSL_new_from_listener() está reservado y debe establecerse en 0.

VALORES DE RETORNO

SSL_new_listener() y SSL_new_listener_from() devuelven un nuevo objeto SSL de escucha o NULL en caso de fallo.

SSL_is_listener() devuelve 1 si su argumento ssl es un objeto de escucha, 0 en caso contrario.

SSL_get0_listener() devuelve un puntero a un objeto SSL (potencialmente al mismo objeto sobre el que se llama) o NULL.

SSL_listen() devuelve 1 en caso de éxito o 0 en caso de fallo.

SSL_accept_connection() devuelve un puntero a un nuevo objeto SSL en caso de éxito o NULL en caso de fallo. En caso de éxito, el llamante asume la propiedad de la referencia.

SSL_get_accept_connection_queue_len() devuelve un valor no negativo, o 0 si la cola está vacía, o si se llama a un tipo de objeto SSL no soportado.

SSL_new_from_listener() devuelve un puntero a un nuevo objeto SSL en caso de éxito o NULL en caso de fallo. En caso de éxito, el llamante asume la propiedad de la referencia.

NOTAS

SSL_get0_listener() se comporta de manera algo diferente en las devoluciones de llamada SSL para conexiones QUIC. Como las conexiones QUIC inician operaciones de enlace TLS antes de que sean aceptadas a través de SSL_accept_connection(), una aplicación puede recibir devoluciones de llamada para dichas conexiones pendientes antes de la aceptación a través de SSL_accept_connection(). Dado que la asociación del oyente se lleva a cabo durante el proceso de aceptación, antes de ser devuelta por SSL_accept_connection(), las llamadas a SSL_get0_listener() realizadas desde dichas devoluciones de llamada SSL devolverán NULL. Esto se puede utilizar como un indicador dentro de la devolución de llamada de que el objeto SSL referenciado aún no ha sido aceptado.
