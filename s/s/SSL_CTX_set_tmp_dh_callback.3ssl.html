SSL_CTX_set_tmp_dh_callback(3ssl)

Paquete: openssl

Licencias: Apache-2.0

SSL_CTX_SET_TMP_DH_CALLBACK(3ssl) OpenSSL SSL_CTX_SET_TMP_DH_CALLBACK(3ssl)

NOMBRE

SSL_CTX_set_dh_auto, SSL_set_dh_auto, SSL_CTX_set0_tmp_dh_pkey, SSL_set0_tmp_dh_pkey, SSL_CTX_set_tmp_dh_callback, SSL_CTX_set_tmp_dh, SSL_set_tmp_dh_callback, SSL_set_tmp_dh - gestionar claves DH para intercambio de claves efímero

SINOPSIS

#include <openssl/ssl.h>
long SSL_CTX_set_dh_auto(SSL_CTX *ctx, int onoff);
long SSL_set_dh_auto(SSL *s, int onoff);
int SSL_CTX_set0_tmp_dh_pkey(SSL_CTX *ctx, EVP_PKEY *dhpkey);
int SSL_set0_tmp_dh_pkey(SSL *s, EVP_PKEY *dhpkey);

Las siguientes funciones han sido marcadas como obsoletas desde OpenSSL 3.0, y pueden ser ocultadas completamente definiendo OPENSSL_API_COMPAT con un valor de versión adecuado, ver openssl_user_macros(7):

void SSL_CTX_set_tmp_dh_callback(SSL_CTX *ctx,
                                 DH *(*tmp_dh_callback)(SSL *ssl, int is_export,
                                                        int keylength));
long SSL_CTX_set_tmp_dh(SSL_CTX *ctx, DH *dh);
void SSL_set_tmp_dh_callback(SSL *ctx,
                             DH *(*tmp_dh_callback)(SSL *ssl, int is_export,
                                                    int keylength));
long SSL_set_tmp_dh(SSL *ssl, DH *dh);

DESCRIPCIÓN

Las funciones descritas en esta página son relevantes solo para los servidores.

Algunos cifrarios pueden usar el intercambio de claves Diffie-Hellman (DH) efímero. En estos casos, los datos de la sesión se negocian utilizando la clave DH efímera/temporal y la clave proporcionada y certificada por la cadena de certificados solo se utiliza para firmar. Los cifrarios anónimos (sin clave de servidor permanente) también utilizan claves DH efímeras.

El uso del intercambio de claves DH efímero proporciona secreto perfecto hacia adelante, ya que la conexión solo puede descifrarse cuando se conoce la clave DH. Al generar una clave DH temporal dentro de la aplicación del servidor que se pierde al salir de la aplicación, se vuelve imposible para un atacante descifrar sesiones pasadas, incluso si obtienen la clave normal (certificada), ya que esta clave solo se utilizó para firmar.

Para realizar un intercambio de claves DH, el servidor debe usar un grupo DH (parámetros DH) y generar una clave DH. El servidor siempre generará una nueva clave DH durante la negociación.

Como la generación de parámetros DH consume mucho tiempo, una aplicación no debe generar los parámetros sobre la marcha. Los parámetros DH se pueden reutilizar, ya que la clave real se genera de nuevo durante la negociación.

Típicamente, las aplicaciones deberían usar parámetros DH conocidos que tengan soporte integrado en OpenSSL. Las macros SSL_CTX_set_dh_auto() y SSL_set_dh_auto() configuran OpenSSL para usar los parámetros DH integrados por defecto para los objetos SSL_CTX y SSL respectivamente. Pasar un valor de 2 o 1 en el parámetro onoff lo activa. Si el parámetro onoff se establece en 2, forzará que el tamaño de la clave DH sea 1024 si el nivel de seguridad de SSL_CTX o SSL SSL_CTX_set_security_level(3) es 0 o 1. Pasar un valor de 0 lo desactiva. La configuración predeterminada está desactivada.

Si los parámetros DH "automáticos" están activados, los parámetros se seleccionarán para que sean consistentes con el tamaño de la clave asociada al certificado del servidor. Si no hay certificado (por ejemplo, para cifrarios PSK), será coherente con el tamaño de la clave de cifrado simétrico negociada.

Las aplicaciones pueden proporcionar sus propios parámetros DH en lugar de usar los valores integrados. Este enfoque no se recomienda y las aplicaciones deberían preferir usar el soporte de parámetros integrados descrito anteriormente. Las aplicaciones que deseen proporcionar sus propios parámetros DH deberían llamar a SSL_CTX_set0_tmp_dh_pkey() o SSL_set0_tmp_dh_pkey() para proporcionar los parámetros para el SSL_CTX o SSL respectivamente. Los parámetros deben proporcionarse en el argumento dhpkey como un EVP_PKEY que contenga parámetros DH. La propiedad del valor dhpkey se transfiere al objeto SSL_CTX o SSL como resultado de esta llamada, por lo que el llamante no debe liberarlo si la llamada a la función tiene éxito.

Las macros obsoletas SSL_CTX_set_tmp_dh() y SSL_set_tmp_dh() hacen lo mismo que SSL_CTX_set0_tmp_dh_pkey() y SSL_set0_tmp_dh_pkey(), excepto que los parámetros DH se proporcionan en un objeto DH en el argumento dh, y la propiedad del objeto DH la retiene la aplicación. Las aplicaciones deberían usar parámetros "automáticos" en su lugar, o llamar a SSL_CTX_set0_tmp_dh_pkey() o SSL_set0_tmp_dh_pkey() según corresponda.

Una aplicación puede especificar los parámetros DH a través de una función de devolución de llamada utilizando las funciones SSL_CTX_set_tmp_dh_callback() o SSL_set_tmp_dh_callback() para establecer la devolución de llamada para el objeto SSL_CTX o SSL respectivamente. Estas funciones están obsoletas. Las aplicaciones deberían usar parámetros "automáticos" en su lugar, o especificar los parámetros a través de SSL_CTX_set0_tmp_dh_pkey() o SSL_set0_tmp_dh_pkey() según corresponda.

La devolución de llamada se invocará durante una conexión cuando se requieran parámetros DH. El objeto SSL para la conexión actual se proporciona como argumento. Las versiones anteriores de OpenSSL usaban los argumentos is_export y keylength para controlar la generación de parámetros para cifrarios de exportación y no de exportación. OpenSSL moderno no admite cifrarios de exportación, por lo que estos argumentos no se utilizan y pueden ser ignorados por la devolución de llamada. La devolución de llamada debe devolver los parámetros a utilizar en un objeto DH. La propiedad del objeto DH la retiene la aplicación y debería liberarse más tarde.

VALORES DE RETORNO

Todas estas funciones/macros devuelven 1 para éxito o 0 en caso de error.
