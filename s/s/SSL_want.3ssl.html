SSL_want(3ssl)

Paquete: openssl

Licencias: Apache-2.0

SSL_WANT(3ssl) OpenSSL SSL_WANT(3ssl)

NOMBRE

SSL_want, SSL_want_nothing, SSL_want_read, SSL_want_write, SSL_want_x509_lookup, SSL_want_retry_verify, SSL_want_async, SSL_want_async_job, SSL_want_client_hello_cb - obtener información de estado de la operación de E/S TLS/SSL

SINOPSIS

#include <openssl/ssl.h>
int SSL_want(const SSL *ssl);
int SSL_want_nothing(const SSL *ssl);
int SSL_want_read(const SSL *ssl);
int SSL_want_write(const SSL *ssl);
int SSL_want_x509_lookup(const SSL *ssl);
int SSL_want_retry_verify(const SSL *ssl);
int SSL_want_async(const SSL *ssl);
int SSL_want_async_job(const SSL *ssl);
int SSL_want_client_hello_cb(const SSL *ssl);

DESCRIPCIÓN

SSL_want() devuelve información de estado para el objeto SSL ssl. ssl NO DEBE ser NULL.

Las otras llamadas SSL_want_*() son atajos para los estados posibles devueltos por SSL_want().

NOTAS

SSL_want() examina la información de estado interna del objeto SSL. Sus valores de retorno son similares a los de SSL_get_error(3). A diferencia de SSL_get_error(3), que también evalúa la cola de errores, la información se obtiene examinando solo una bandera de estado interna. Por lo tanto, los resultados solo deben utilizarse para la operación normal en E/S no bloqueante. Las condiciones de error no se manejan y deben tratarse utilizando SSL_get_error(3).

El resultado devuelto por SSL_want() siempre debe ser consistente con el resultado de SSL_get_error(3).

VALORES DE RETORNO

Los siguientes valores de retorno pueden ocurrir actualmente para SSL_want():

SSL_NOTHING
No hay datos para escribir o leer.
SSL_WRITING
Hay datos en el búfer SSL que deben escribirse en la capa BIO subyacente para completar la operación SSL_*() real. Una llamada a SSL_get_error(3) debería devolver SSL_ERROR_WANT_WRITE.
SSL_READING
Se deben leer más datos de la capa BIO subyacente para completar la operación SSL_*() real. Una llamada a SSL_get_error(3) debería devolver SSL_ERROR_WANT_READ.
SSL_X509_LOOKUP
La operación no se completó porque una función de devolución de llamada de aplicación establecida por SSL_CTX_set_client_cert_cb() solicitó ser llamada de nuevo. Una llamada a SSL_get_error(3) debería devolver SSL_ERROR_WANT_X509_LOOKUP.
SSL_RETRY_VERIFY
La operación no se completó porque una función de devolución de llamada de verificación de certificado solicitó ser llamada de nuevo a través de SSL_set_retry_verify(3). Una llamada a SSL_get_error(3) debería devolver SSL_ERROR_WANT_RETRY_VERIFY.
SSL_ASYNC_PAUSED
Una operación asíncrona se completó parcialmente y luego se pausó. Véase SSL_get_all_async_fds(3). Una llamada a SSL_get_error(3) debería devolver SSL_ERROR_WANT_ASYNC.
SSL_ASYNC_NO_JOBS
El trabajo asíncrono no pudo iniciarse porque no había trabajos asíncronos disponibles en el grupo (véase ASYNC_init_thread(3)). Una llamada a SSL_get_error(3) debería devolver SSL_ERROR_WANT_ASYNC_JOB.
SSL_CLIENT_HELLO_CB
La operación no se completó porque una función de devolución de llamada de aplicación establecida por SSL_CTX_set_client_hello_cb() solicitó ser llamada de nuevo. Una llamada a SSL_get_error(3) debería devolver SSL_ERROR_WANT_CLIENT_HELLO_CB.

SSL_want_nothing(), SSL_want_read(), SSL_want_write(), SSL_want_x509_lookup(), SSL_want_retry_verify(), SSL_want_async(), SSL_want_async_job() y SSL_want_client_hello_cb() devuelven 1 cuando la condición correspondiente es verdadera o 0 de lo contrario.

CONSIDERACIONES ESPECÍFICAS DE QUIC

Para QUIC, estas funciones se relacionan solo con la capa de handshake TLS.

VER TAMBIÉN

ssl(7), SSL_get_error(3)

HISTORIA

La función SSL_want_client_hello_cb() y el valor de retorno SSL_CLIENT_HELLO_CB se añadieron en OpenSSL 1.1.1.

SSL_want_retry_verify() se añadió en OpenSSL 3.0.
