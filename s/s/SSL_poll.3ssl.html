SSL_poll(3ssl)

Paquete: openssl

Licencias: Apache-2.0

SSL_POLL(3ssl) OpenSSL SSL_POLL(3ssl)

NOMBRE

SSL_poll, SSL_POLL_EVENT_NONE, SSL_POLL_EVENT_F, SSL_POLL_EVENT_EL, SSL_POLL_EVENT_EC, SSL_POLL_EVENT_ECD, SSL_POLL_EVENT_ER, SSL_POLL_EVENT_EW, SSL_POLL_EVENT_R, SSL_POLL_EVENT_W, SSL_POLL_EVENT_IC, SSL_POLL_EVENT_ISB, SSL_POLL_EVENT_ISU, SSL_POLL_EVENT_OSB, SSL_POLL_EVENT_OSU, SSL_POLL_EVENT_RW, SSL_POLL_EVENT_RE, SSL_POLL_EVENT_WE, SSL_POLL_EVENT_RWE, SSL_POLL_EVENT_E, SSL_POLL_EVENT_IS, SSL_POLL_EVENT_ISE, SSL_POLL_EVENT_I, SSL_POLL_EVENT_OS, SSL_POLL_EVENT_OSE, SSL_POLL_FLAG_NO_HANDLE_EVENTS - determinar o esperar condiciones de disponibilidad para uno o más objetos consultables

SINOPSIS

#include <openssl/ssl.h>
#define SSL_POLL_EVENT_NONE        0
#define SSL_POLL_EVENT_F           /* F   (Fallo) */
#define SSL_POLL_EVENT_EL          /* EL  (Excepción en Listener) */
#define SSL_POLL_EVENT_EC          /* EC  (Excepción en Conexión) */
#define SSL_POLL_EVENT_ECD         /* ECD (Excepción en Conexión Drenada) */
#define SSL_POLL_EVENT_ER          /* ER  (Excepción en Lectura) */
#define SSL_POLL_EVENT_EW          /* EW  (Excepción en Escritura) */
#define SSL_POLL_EVENT_R           /* R   (Legible) */
#define SSL_POLL_EVENT_W           /* W   (Escribible) */
#define SSL_POLL_EVENT_IC          /* IC  (Conexión entrante) */
#define SSL_POLL_EVENT_ISB         /* ISB (Stream entrante: Bidi) */
#define SSL_POLL_EVENT_ISU         /* ISU (Stream entrante: Uni) */
#define SSL_POLL_EVENT_OSB         /* OSB (Stream saliente: Bidi) */
#define SSL_POLL_EVENT_OSU         /* OSU (Stream saliente: Uni) */
#define SSL_POLL_EVENT_RW          /* R   | W               */
#define SSL_POLL_EVENT_RE          /* R   | ER              */
#define SSL_POLL_EVENT_WE          /* W   | EW              */
#define SSL_POLL_EVENT_RWE         /* RE  | WE              */
#define SSL_POLL_EVENT_E           /* EL  | EC  | ER  | EW  */
#define SSL_POLL_EVENT_IS          /* ISB | ISU             */
#define SSL_POLL_EVENT_ISE         /* IS  | EC              */
#define SSL_POLL_EVENT_I           /* IS                    */
#define SSL_POLL_EVENT_OS          /* OSB | OSU             */
#define SSL_POLL_EVENT_OSE         /* OS  | EC              */
typedef struct ssl_poll_item_st {
    BIO_POLL_DESCRIPTOR desc;
    uint64_t            events, revents;
} SSL_POLL_ITEM;
#define SSL_POLL_FLAG_NO_HANDLE_EVENTS
int SSL_poll(SSL_POLL_ITEM         *items,
             size_t                num_items,
             size_t                stride,
             const struct timeval  *timeout,
             uint64_t              flags,
             size_t                *result_count);

DESCRIPCIÓN

SSL_poll() permite determinar las condiciones de disponibilidad de los recursos representados por una o más estructuras BIO_POLL_DESCRIPTOR. En particular, se puede utilizar para consultar las condiciones de disponibilidad de objetos SSL de conexión QUIC y objetos SSL de stream QUIC en una sola llamada. También se puede utilizar para bloquear hasta que al menos uno de los recursos dados esté disponible.

Una llamada a SSL_poll() especifica un array de estructuras SSL_POLL_ITEM, cada una de las cuales designa un recurso cuya disponibilidad se está consultando, y un conjunto de flags de evento que indican los eventos específicos de disponibilidad que el llamante interesa en relación con el recurso especificado.

Los campos de SSL_POLL_ITEM son los siguientes:

desc
El recurso cuya disponibilidad se está consultando, representado por un BIO_POLL_DESCRIPTOR. Actualmente, este debe ser un descriptor de poll de tipo BIO_POLL_DESCRIPTOR_TYPE_SSL, que representa un puntero a un objeto SSL, y el objeto SSL debe ser un objeto SSL de conexión QUIC o un objeto SSL de stream QUIC.

Si un SSL_POLL_ITEM tiene un tipo de descriptor de poll de BIO_POLL_DESCRIPTOR_TYPE_NONE, o el puntero al objeto SSL es NULL, la entrada del array SSL_POLL_ITEM se ignora y revents se establecerá en 0 al regresar.

events
Este es el conjunto de cero o más eventos sobre los que el llamante está interesado en obtener información en relación con el recurso descrito por desc. Es una colección de cero o más flags de SSL_POLL_EVENT. Consulte "TIPOS DE EVENTOS" para obtener una descripción de cada uno de los tipos de evento.
revents
Después de que SSL_poll() regrese, este es el conjunto de cero o más eventos que son realmente aplicables al recurso descrito por desc. Al igual que con events, es una colección de cero o más flags de SSL_POLL_EVENT.

revents no necesita ser un subconjunto de los eventos especificados en events, ya que algunos tipos de eventos se definen como siempre habilitados (no enmascarables). Consulte "TIPOS DE EVENTOS" para obtener más información.

Para usar SSL_poll(), llámelo con un array de estructuras SSL_POLL_ITEM. El array solo necesita permanecer asignado durante la duración de la llamada. num_items debe establecerse en el número de entradas del array y stride debe establecerse en sizeof(SSL_POLL_ITEM).

El argumento timeout especifica el tiempo de espera a usar y, implícitamente, si se debe usar SSL_poll() en modo bloqueante o no bloqueante:

  • Si timeout es NULL, la función se bloquea indefinidamente hasta que al menos un recurso esté listo.
  • Si timeout no es NULL y apunta a un struct timeval que se establece en cero, la función opera en modo no bloqueante y regresa inmediatamente con información de disponibilidad.
  • Si timeout no es NULL y apunta a un struct timeval que se establece en un valor distinto de cero, la función se bloquea durante el intervalo especificado o hasta que al menos uno de los recursos especificados esté listo, lo que ocurra primero.

La implementación actual de SSL_poll() es un subconjunto de la funcionalidad que eventualmente estará disponible. Para obtener más información, consulte "LIMITACIONES".

Los siguientes flags están definidos actualmente para el argumento flags:

SSL_POLL_FLAG_NO_HANDLE_EVENTS
Este flag indica que el procesamiento interno de la máquina de estados no debe realizarse en un intento de generar nuevos eventos de disponibilidad. Solo se informarán los eventos de disponibilidad existentes.

Si este flag se usa en modo no bloqueante (con un tiempo de espera de cero), no se realiza ningún procesamiento interno de la máquina de estados.

Si este flag se usa en modo bloqueante (por ejemplo, con timeout establecido en NULL), el procesamiento de eventos no ocurre a menos que la función se bloquee.

El argumento result_count es opcional. Si no es NULL, se utiliza para mostrar el número de entradas en el array que tienen campos revents distintos de cero cuando la llamada a SSL_poll() regresa; consulte "VALORES DE RETORNO" para obtener detalles.

TIPOS DE EVENTOS

La interfaz SSL_poll() informa cero o más tipos de eventos en un recurso dado, representados por una máscara de bits.

Todos los tipos de eventos son de activación por nivel y representan una condición de disponibilidad o una excepción permanente; como tal, después de que SSL_poll() informa un evento para un recurso, este continuará siendo informado en futuras llamadas a SSL_poll() hasta que la condición deje de estar vigente. Un llamante debe enmascarar el bit del tipo de evento dado en futuras llamadas a SSL_poll() si no desea recibir notificaciones repetidas y no ha causado que la condición de disponibilidad subyacente (por ejemplo, consumir todos los datos disponibles usando SSL_read_ex(3) después de que se informa SSL_POLL_EVENT_R) se desactive.

Algunos tipos de eventos no tienen sentido en un tipo de recurso dado. En este caso, especificar ese tipo de evento en events es una operación nula y se ignorará, y el evento dado nunca se informará en revents.

El fallo del propio mecanismo de polling se considera distinto de una condición de excepción en un recurso que se consultó correctamente. Consulte SSL_POLL_EVENT_F y "VALORES DE RETORNO" para obtener detalles.

En general, una aplicación siempre debería escuchar los tipos de eventos que corresponden a condiciones de excepción si está escuchando los tipos de eventos correspondientes que no son de excepción (por ejemplo, SSL_POLL_EVENT_EC y SSL_POLL_EVENT_ER para SSL_POLL_EVENT_R), ya que no hacerlo probablemente no sea un diseño sólido.

Algunos tipos de eventos no son enmascarables y pueden informarse en revents independientemente de si se solicitaron en events.

Los siguientes tipos de eventos son compatibles:

SSL_POLL_EVENT_F
Este evento indica un fallo general del mecanismo de polling. No está asociado con un recurso específico en el array de entrada. Si se devuelve este evento, la llamada a SSL_poll() habrá fallado de alguna manera. El valor retornado por la función indica la naturaleza del fallo. Este evento no es enmascarable.
SSL_POLL_EVENT_E
Este es un evento genérico de excepción que se puede aplicar a cualquier recurso. Representa una condición de error permanente o una excepción en el recurso subyacente. El tipo específico de excepción se comunica a través de otros flags de evento más específicos (por ejemplo, SSL_POLL_EVENT_ER y SSL_POLL_EVENT_EW). Este evento no es enmascarable.
SSL_POLL_EVENT_R
Este evento indica que el recurso es legible. El llamante puede llamar a una función de lectura (por ejemplo, SSL_read_ex(3)) para leer datos del recurso. Este evento es enmascarable.
SSL_POLL_EVENT_W
Este evento indica que el recurso es escribible. El llamante puede llamar a una función de escritura (por ejemplo, SSL_write(3)) para escribir datos en el recurso. Este evento es enmascarable.
SSL_POLL_EVENT_IC
Este evento indica una conexión entrante. Esto solo se aplica a los objetos SSL de escucha y significa que una nueva conexión está esperando ser aceptada. Este evento es enmascarable.
SSL_POLL_EVENT_IS
Este evento indica que un stream entrante está disponible. Esto se aplica a los objetos SSL de conexión QUIC. Puede ser un stream Bidi (SSL_POLL_EVENT_ISB) o un stream Uni (SSL_POLL_EVENT_ISU). Este evento es enmascarable.
SSL_POLL_EVENT_OS
Este evento indica que un stream saliente está disponible. Esto se aplica a los objetos SSL de conexión QUIC. Puede ser un stream Bidi (SSL_POLL_EVENT_OSB) o un stream Uni (SSL_POLL_EVENT_OSU). Este evento es enmascarable.

Los siguientes eventos son combinaciones de eventos anteriores, o representan subconjuntos más específicos de ellos:

SSL_POLL_EVENT_EL
Excepción en el listener. No enmascarable.
SSL_POLL_EVENT_EC
Excepción en la conexión. No enmascarable.
SSL_POLL_EVENT_ECD
Excepción en la conexión drenada. No enmascarable.
SSL_POLL_EVENT_ER
Excepción en la lectura. No enmascarable.
SSL_POLL_EVENT_EW
Excepción en la escritura. No enmascarable.
SSL_POLL_EVENT_RW
Legible y escribible. Enmascarable.
SSL_POLL_EVENT_RE
Legible o excepción en lectura. No enmascarable.
SSL_POLL_EVENT_WE
Escribible o excepción en escritura. No enmascarable.
SSL_POLL_EVENT_RWE
Legible, escribible o excepción en lectura/escritura. No enmascarable.
SSL_POLL_EVENT_ISE
Stream entrante (Bidi o Uni) o excepción en conexión. No enmascarable.
SSL_POLL_EVENT_ISB
Stream entrante Bidi. Enmascarable.
SSL_POLL_EVENT_ISU
Stream entrante Uni. Enmascarable.
SSL_POLL_EVENT_OSE
Stream saliente (Bidi o Uni) o excepción en conexión. No enmascarable.
SSL_POLL_EVENT_OSB
Stream saliente Bidi. Enmascarable.
SSL_POLL_EVENT_OSU
Stream saliente Uni. Enmascarable.

VALORES DE RETORNO

SSL_poll() devuelve el número total de elementos en el array que tienen un campo revents distinto de cero. Esto puede ser útil como una comprobación rápida para determinar si se procesó algún evento.

Si se devuelve 0, significa que no se activó ningún evento (posiblemente debido a un tiempo de espera agotado en modo no bloqueante).

Si se devuelve un valor negativo, indica un error. La llamada a SSL_get_error(3) se puede usar para determinar la naturaleza del error.

Si result_count no es NULL, entonces, al regresar, contendrá el número de elementos en el array de entrada que tienen un campo revents distinto de cero.

Si se devuelve SSL_POLL_EVENT_F en el campo revents de algún elemento, indica un fallo en el propio mecanismo de polling. En este caso, el valor devuelto por SSL_poll() será negativo y SSL_get_error(3) debería usarse para determinar la naturaleza del error. Si SSL_POLL_EVENT_F se notifica junto con otros eventos, esto indica que algunos eventos se notificaron correctamente antes de que ocurriera el fallo.

LIMITACIONES

La implementación actual de SSL_poll() solo admite objetos SSL de tipo QUIC. No se puede utilizar para consultar objetos SSL de tipo tradicional.

Solo se admiten los siguientes tipos de descriptor de poll:

  • BIO_POLL_DESCRIPTOR_TYPE_SSL: para objetos SSL QUIC.

El parámetro stride siempre debe ser sizeof(SSL_POLL_ITEM).

Los siguientes flags del argumento flags son compatibles: SSL_POLL_FLAG_NO_HANDLE_EVENTS.

Los siguientes tipos de evento son compatibles: SSL_POLL_EVENT_NONE, SSL_POLL_EVENT_F, SSL_POLL_EVENT_EC, SSL_POLL_EVENT_ER, SSL_POLL_EVENT_EW, SSL_POLL_EVENT_R, SSL_POLL_EVENT_W, SSL_POLL_EVENT_IC, SSL_POLL_EVENT_ISB, SSL_POLL_EVENT_ISU, SSL_POLL_EVENT_OSB, SSL_POLL_EVENT_OSU, SSL_POLL_EVENT_RW, SSL_POLL_EVENT_RE, SSL_POLL_EVENT_WE, SSL_POLL_EVENT_RWE, SSL_POLL_EVENT_E, SSL_POLL_EVENT_IS, SSL_POLL_EVENT_ISE, SSL_POLL_EVENT_I, SSL_POLL_EVENT_OS, SSL_POLL_EVENT_OSE.

Todos los demás tipos de descriptor de poll y flags de evento no son soportados y su uso resultará en un error.

NAME

SSL_poll

SYNOPSIS

 int SSL_poll(SSL_POLL_ITEM *items, size_t item_count,
-    const struct timeval *timeout, size_t *result_count);

DESCRIPTION

The SSL_poll() function is used to poll a list of SSL objects for I/O events. The items parameter is a pointer to an array of SSL_POLL_ITEM structures, each of which contains a descriptor for an SSL object and a bitmask of events that are of interest.

The item_count parameter specifies the number of elements in the items array.

The timeout parameter specifies the maximum time to wait for an event. If timeout is NULL, SSL_poll() will block indefinitely until an event occurs. If timeout points to a struct timeval with all members set to zero, SSL_poll() will return immediately without blocking.

The result_count parameter is an output parameter that will be set to the number of items in the items array for which events occurred.

On successful return, the revents field of each SSL_POLL_ITEM structure in the items array will be updated to indicate the events that occurred. The caller can then examine these fields to determine which SSL objects have events pending.

The following event types may be returned in the revents field:

SSL_POLL_EVENT_F
Polling failure. This event is raised when a resource could not be polled. It is distinct from an exception condition reported on a resource which was successfully polled and represents a failure of the polling process itself in relation to a resource. This may mean that SSL_poll() does not support the kind of resource specified.

Where this event is raised on at least one item in items, SSL_poll() will return 0 and the ERR stack will contain information pertaining to the first item in items with SSL_POLL_EVENT_F set. See "RETURN VALUES" for more information.

This event type may be raised even if it was not requested in events; specifying this event type in events does nothing.

SSL_POLL_EVENT_EL
Error at listener level. This event is raised when a listener has failed, for example if a network BIO has encountered a permanent error.

This event is never raised on objects which are not listeners, but its occurrence will cause SSL_POLL_EVENT_EC to be raised on all dependent connections.

SSL_POLL_EVENT_EC
Error at connection level. This event is raised when a connection has failed. In particular, it is raised when a connection begins terminating.

This event is never raised on objects which are not connections.

SSL_POLL_EVENT_ECD
Error at connection level (drained). This event is raised when a connection has finished terminating, and has reached the terminated state. This event will generally occur after an interval of time passes after the SSL_POLL_EVENT_EC event is raised on a connection.

This event is never raised on objects which are not connections.

SSL_POLL_EVENT_ER
Error in read direction. For QUIC, this is raised only in the event that a stream has a read part and that read part has been reset by the peer (for example, using a RESET_STREAM frame).
SSL_POLL_EVENT_EW
Error in write direction. For QUIC, this is raised only in the event that a stream has a write part and that write part has been reset by the peer using a STOP_SENDING frame.
SSL_POLL_EVENT_R
Readable. This event is raised when a QUIC stream SSL object (or a QUIC connection SSL object with a default stream attached) has application data waiting to be read using SSL_read_ex(3), or a FIN event as represented by SSL_ERROR_ZERO_RETURN waiting to be read.

It is not raised in the event of the receiving part of the QUIC stream being reset by the peer; see SSL_POLL_EVENT_ER.

SSL_POLL_EVENT_W
Writable. This event is raised when a QUIC stream SSL object (or a QUIC connection SSL object with a default stream attached) could accept more application data using SSL_write_ex(3).

This event is never raised by a receive-only stream.

This event is never raised by a stream which has had its send part concluded normally (as with SSL_stream_conclude(3)) or locally reset (as with SSL_stream_reset(3)).

This event does not guarantee that a subsequent call to SSL_write_ex(3) will succeed.

SSL_POLL_EVENT_IC
This event, which is only raised by a QUIC listener SSL object, is raised when one or more incoming QUIC connections are available to be accepted using SSL_accept_connection(3).
SSL_POLL_EVENT_ISB
This event, which is only raised by a QUIC connection SSL object, is raised when one or more incoming bidirectional streams are available to be accepted using SSL_accept_stream(3).
SSL_POLL_EVENT_ISU
This event, which is only raised by a QUIC connection SSL object, is raised when one or more incoming unidirectional streams are available to be accepted using SSL_accept_stream(3).
SSL_POLL_EVENT_OSB
This event, which is only raised by a QUIC connection SSL object, is raised when QUIC stream creation flow control currently permits at least one additional bidirectional stream to be locally created.
SSL_POLL_EVENT_OSU
This event, which is only raised by a QUIC connection SSL object, is raised when QUIC stream creation flow control currently permits at least one additional unidirectional stream to be locally created.

LIMITATIONS

SSL_poll() as presently implemented has the following limitation:

•
Only BIO_POLL_DESCRIPTOR structures with type BIO_POLL_DESCRIPTOR_TYPE_SSL, referencing QUIC listener, connection or stream SSL objects, are supported.

This limitation may be revised in a future release of OpenSSL.

RETURN VALUES

SSL_poll() returns 1 on success and 0 on failure.

Unless the items pointer itself is invalid, SSL_poll() will always initialise the revents fields of all items in the input array upon returning, even if it returns failure.

If result_count is non-NULL, it is always written with the number of items in the array with nonzero revents fields, even if the SSL_poll() call returns failure.

It is possible for result_count to be written as 0 even if the SSL_poll() call returns success, namely if no events were output but the polling process was successful (e.g. in nonblocking usage) or timed out.

It is possible for result_count to be written as a nonzero value if the SSL_poll() call returns failure, for example due to SSL_POLL_EVENT_F events, or because some events were detected and output before encountering a failure condition while processing a subsequent entry in the items array.

If at least one SSL_POLL_EVENT_F event is output, SSL_poll() is guaranteed to return 0 and guaranteed to place at least one ERR on the error stack describing the first SSL_POLL_EVENT_F output. Detailed information on any additional SSL_POLL_EVENT_F events is not available. SSL_poll() may or may not return more than one SSL_POLL_EVENT_F event at once.

"Normal" events representing exceptional I/O conditions which do not constitute a failure of the SSL_poll() mechanism itself are not considered errors by SSL_poll() and are instead represented using their own event type; see "EVENT TYPES" for details.

The caller can establish the meaning of the SSL_poll() return and output values as follows:

  • If SSL_poll() returns 1 and result_count is zero, the operation timed out before any resource was ready.
  • If SSL_poll() returns 1 and result_count is nonzero, that many events were output.
  • If SSL_poll() returns 0 and result_count is zero, the caller has made a basic usage error; check the ERR stack for details.
  • If SSL_poll() returns 0 and result_count is nonzero, inspect the items array for SSL_POLL_ITEM structures with the SSL_POLL_EVENT_F event type raised in revents. The entries added to the ERR stack (of which there is guaranteed to be at least one) reflect the cause of the failure of the first item in items with SSL_POLL_EVENT_F raised. Note that there may be events other than SSL_POLL_EVENT_F output for items which come before the first item with SSL_POLL_EVENT_F raised, and additional SSL_POLL_EVENT_F events may or may not have been output, both of which which will be reflected in result_count.

HISTORY

SSL_poll() was added in OpenSSL 3.3.

Before 3.5, SSL_poll() did not support blocking operation and would fail if called with a NULL timeout parameter or a timeout parameter pointing to a struct timeval which was not zero.

Before 3.5, the SSL_POLL_EVENT_EL and SSL_POLL_EVENT_IC event types were not present.
