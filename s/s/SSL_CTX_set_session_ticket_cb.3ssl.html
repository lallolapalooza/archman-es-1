SSL_CTX_set_session_ticket_cb(3ssl)

Paquete: openssl

Licencias: Apache-2.0

SSL_CTX_SET_SESSION_TICKET_CB(3ssl) OpenSSL SSL_CTX_SET_SESSION_TICKET_CB(3ssl)

NOMBRE

SSL_CTX_set_session_ticket_cb, SSL_SESSION_get0_ticket_appdata, SSL_SESSION_set1_ticket_appdata, SSL_CTX_generate_session_ticket_fn, SSL_CTX_decrypt_session_ticket_fn - gestiona los datos de aplicación de tickets de sesión

SINOPSIS

#include <openssl/ssl.h>
typedef int (*SSL_CTX_generate_session_ticket_fn)(SSL *s, void *arg);
typedef SSL_TICKET_RETURN (*SSL_CTX_decrypt_session_ticket_fn)(SSL *s, SSL_SESSION *ss,
                                                               const unsigned char *keyname,
                                                               size_t keyname_len,
                                                               SSL_TICKET_STATUS status,
                                                               void *arg);
int SSL_CTX_set_session_ticket_cb(SSL_CTX *ctx,
                                  SSL_CTX_generate_session_ticket_fn gen_cb,
                                  SSL_CTX_decrypt_session_ticket_fn dec_cb,
                                  void *arg);
int SSL_SESSION_set1_ticket_appdata(SSL_SESSION *ss, const void *data, size_t len);
int SSL_SESSION_get0_ticket_appdata(SSL_SESSION *ss, void **data, size_t *len);

DESCRIPCIÓN

SSL_CTX_set_set_session_ticket_cb() establece las devoluciones de llamada de la aplicación gen_cb y dec_cb que utiliza un servidor para establecer y obtener datos de aplicación almacenados con una sesión, y colocados en un ticket de sesión. Cualquiera de las funciones de devolución de llamada puede establecerse en NULL. El valor de arg se pasa a las devoluciones de llamada.

gen_cb es la devolución de llamada definida por la aplicación que se invoca cuando se va a crear un ticket de sesión. La aplicación puede llamar a SSL_SESSION_set1_ticket_appdata() en este momento para agregar datos de aplicación al ticket de sesión. El valor de arg es el mismo que se pasó a SSL_CTX_set_session_ticket_cb(). La devolución de llamada gen_cb se define como de tipo SSL_CTX_generate_session_ticket_fn.

dec_cb es la devolución de llamada definida por la aplicación que se invoca después de que se haya intentado descifrar el ticket de sesión y cualquier dato de aplicación del ticket de sesión esté disponible. Si el descifrado del ticket fue exitoso, el argumento ss contiene los datos de la sesión. Los argumentos keyname y keyname_len identifican la clave utilizada para descifrar el ticket de sesión. El argumento status es el resultado del descifrado del ticket. Consulte la sección "NOTAS" a continuación para obtener más detalles. El valor de arg es el mismo que se pasó a SSL_CTX_set_session_ticket_cb(). La devolución de llamada dec_cb se define como de tipo SSL_CTX_decrypt_session_ticket_fn.

SSL_SESSION_set1_ticket_appdata() establece los datos de la aplicación especificados por data y len en ss, que luego se colocan en cualquier ticket de sesión generado. Se puede llamar en cualquier momento antes de que se cree un ticket de sesión para actualizar los datos que se colocarán en el ticket de sesión. Sin embargo, dado que las sesiones y los tickets son creados por el handshake, se proporciona gen_cb para notificar a la aplicación que se va a generar un ticket de sesión.

SSL_SESSION_get0_ticket_appdata() asigna data a los datos de aplicación del ticket de sesión y asigna len a la longitud de los datos de aplicación del ticket de sesión de ss. Los datos de la aplicación se pueden establecer a través de SSL_SESSION_set1_ticket_appdata() o mediante un ticket de sesión. Se asignará NULL a data y 0 a len si no hay datos de aplicación del ticket de sesión. SSL_SESSION_get0_ticket_appdata() se puede llamar en cualquier momento después de que se haya creado una sesión. Se proporciona dec_cb para notificar a la aplicación que se acaba de descifrar un ticket de sesión.

NOTAS

Cuando se invoca la devolución de llamada dec_cb, el SSL_SESSION ss aún no se ha asignado al SSL s. El status indica el resultado del descifrado del ticket. La devolución de llamada debe verificar el valor de status antes de realizar cualquier acción, ya que se llama incluso si el descifrado del ticket falla.

Los argumentos keyname y keyname_len para dec_cb se pueden utilizar para identificar la clave que se utilizó para cifrar el ticket de sesión.

El argumento status puede ser cualquiera de estos valores:

SSL_TICKET_EMPTY
Ticket vacío presente. No se utilizarán datos del ticket y se debe enviar un nuevo ticket al cliente. Esto solo ocurre en TLSv1.2 o inferior. En TLSv1.3 no es válido que un cliente envíe un ticket vacío.
SSL_TICKET_NO_DECRYPT
El ticket no se pudo descifrar. No se utilizarán datos del ticket y se debe enviar un nuevo ticket al cliente.
SSL_TICKET_SUCCESS
Un ticket se descifró correctamente, cualquier dato de aplicación del ticket de sesión debería estar disponible. No se debe enviar un nuevo ticket al cliente.
SSL_TICKET_SUCCESS_RENEW
Igual que SSL_TICKET_SUCCESS, pero se debe enviar un nuevo ticket al cliente.

El valor de retorno puede ser cualquiera de estos valores:

SSL_TICKET_RETURN_ABORT
El handshake debe abortarse, ya sea debido a un error o a alguna política. Tenga en cuenta que en TLSv1.3 un cliente puede enviar más de un ticket en un solo handshake. Por lo tanto, que un ticket sea inaceptable no significa que todos lo sean. Por esta razón, esta opción debe usarse con precaución.
SSL_TICKET_RETURN_IGNORE
No usar un ticket (si había uno disponible). No enviar un ticket renovado al cliente.
SSL_TICKET_RETURN_IGNORE_RENEW
No usar un ticket (si había uno disponible). Enviar un ticket renovado al cliente.

Si la devolución de llamada no desea cambiar el comportamiento predeterminado del ticket, debe devolver este valor si status es SSL_TICKET_EMPTY o SSL_TICKET_NO_DECRYPT.

SSL_TICKET_RETURN_USE
Usar el ticket. No enviar un ticket renovado al cliente. Es un error que la devolución de llamada devuelva este valor si status tiene un valor distinto de SSL_TICKET_SUCCESS o SSL_TICKET_SUCCESS_RENEW.

Si la devolución de llamada no desea cambiar el comportamiento predeterminado del ticket, debe devolver este valor si status es SSL_TICKET_SUCCESS.

SSL_TICKET_RETURN_USE_RENEW
Usar el ticket. Enviar un ticket renovado al cliente. Es un error que la devolución de llamada devuelva este valor si status tiene un valor distinto de SSL_TICKET_SUCCESS o SSL_TICKET_SUCCESS_RENEW.

Si la devolución de llamada no desea cambiar el comportamiento predeterminado del ticket, debe devolver este valor si status es SSL_TICKET_SUCCESS_RENEW.

Si status tiene el valor SSL_TICKET_EMPTY o SSL_TICKET_NO_DECRYPT, no habrá datos de sesión disponibles y la devolución de llamada no debe usar el argumento ss. Si status tiene el valor SSL_TICKET_SUCCESS o SSL_TICKET_SUCCESS_RENEW, la aplicación puede llamar a SSL_SESSION_get0_ticket_appdata() utilizando la sesión proporcionada en el argumento ss para recuperar los datos de la aplicación.

Cuando se invoca la devolución de llamada gen_cb, la función SSL_get_session() se puede utilizar para recuperar el SSL_SESSION para SSL_SESSION_set1_ticket_appdata().

Por defecto, en TLSv1.2 e inferiores, no se emite un nuevo ticket de sesión en una reanudación exitosa y, por lo tanto, gen_cb no se llamará. En TLSv1.3, el comportamiento predeterminado es emitir siempre un nuevo ticket en la reanudación. En ambos casos, este comportamiento se puede cambiar si hay una devolución de llamada de clave de ticket en uso (consulte SSL_CTX_set_tlsext_ticket_key_cb(3)).

VALORES DE RETORNO

Las funciones SSL_CTX_set_session_ticket_cb(), SSL_SESSION_set1_ticket_appdata() y SSL_SESSION_get0_ticket_appdata() devuelven 1 en caso de éxito y 0 en caso de error.

La devolución de llamada gen_cb debe devolver 1 para continuar

SSL_CTX_set_session_ticket_cb(3ssl) — Manual pages

NAME

SSL_CTX_set_session_ticket_cb, SSL_SESSION_set1_ticket_appdata, SSL_SESSION_get_ticket_appdata - configurar callbacks para el cifrado de tickets de sesión

SYNOPSIS

#include <openssl/ssl.h>
int SSL_CTX_set_session_ticket_cb(SSL_CTX *ctx,
SSL_SESSION_ticket_state_cb *callback,
void *arg);
int SSL_SESSION_set1_ticket_appdata(SSL_SESSION *session,
const unsigned char *data,
size_t len);
int SSL_SESSION_get_ticket_appdata(SSL_SESSION *session,
unsigned char **data);

DESCRIPTION

Los tickets de sesión son un mecanismo que permite a los clientes reanudar sesiones SSL/TLS con un servidor sin tener que realizar una negociación completa de parámetros de clave de sesión. Cuando se utiliza la funcionalidad de tickets de sesión, el servidor necesita ser capaz de cifrar y descifrar los tickets de sesión. El callback SSL_SESSION_ticket_state_cb se utiliza para este propósito. El callback se llama tanto cuando se genera un ticket de sesión para enviar a un cliente, como cuando se recibe un ticket de sesión de un cliente.

La función SSL_CTX_set_session_ticket_cb configura el callback que se utilizará para cifrar y descifrar los tickets de sesión para el SSL_CTX dado.

El argumento callback es un puntero a una función de tipo SSL_SESSION_ticket_state_cb que tiene la siguiente firma:

typedef int SSL_SESSION_ticket_state_cb(SSL *ssl,
SSL_SESSION *session,
SSL_CTX *ctx);

La función de callback debe devolver 1 si la operación se realizó correctamente y 0 si se produjo un error. Si se devuelve 0, se enviará una alerta INTERNAL_ERROR al cliente.

El argumento arg es un puntero de usuario que se pasa al callback. Puede ser utilizado para pasar datos o un puntero a una estructura que contenga datos necesarios para el callback, como las claves de cifrado.

Dentro del callback:

  • Si el ticket de sesión necesita ser cifrado (es decir, SSL_get_session_secret_cb() devuelve un valor no NULL), se debe llamar a SSL_SESSION_set1_ticket_appdata() para establecer los datos cifrados. El campo session->ticket contendrá los datos de la sesión cifrados, y el campo session->tlsext_tick_lifetime_hint contendrá la sugerencia de tiempo de vida del ticket.
  • Si el ticket de sesión necesita ser descifrado (es decir, SSL_get_session_secret_cb() devuelve NULL), se debe llamar a SSL_SESSION_get_ticket_appdata() para obtener los datos cifrados del ticket. Los datos recuperados deben ser descifrados por el callback. Si el descifrado es exitoso, la información descifrada se puede establecer en el objeto SSL_SESSION.

La función SSL_SESSION_set1_ticket_appdata() establece datos de aplicación (a menudo los datos cifrados del ticket) en un objeto SSL_SESSION. Los datos se copian. La longitud de los datos es len.

La función SSL_SESSION_get_ticket_appdata() recupera los datos de aplicación previamente establecidos con SSL_SESSION_set1_ticket_appdata(). Los datos se devuelven en el argumento de salida `data`, que apunta a la memoria asignada. El llamador es responsable de liberar esta memoria usando OPENSSL_free().

NOTES

El callback SSL_SESSION_ticket_state_cb es responsable de la gestión segura de las claves de cifrado utilizadas para cifrar y descifrar los tickets de sesión. No se deben utilizar claves codificadas en el código. En su lugar, las claves deben cargarse desde un medio seguro.

Se recomienda encarecidamente la rotación periódica de las claves de cifrado para mitigar el riesgo de compromiso de claves.

Si el callback de sesión de tickets está configurado en NULL, OpenSSL no habilitará los tickets de sesión. Esto puede hacerse intencionadamente para deshabilitar la funcionalidad de tickets de sesión.

RETURN VALUES

La función SSL_CTX_set_session_ticket_cb() devuelve 1 si la operación se realizó correctamente y 0 en caso de error. Un retorno de 0 terminará la conexión con una alerta INTERNAL_ERROR.

El callback dec_cb debe devolver un valor como se describe en "NOTES" arriba.

SEE ALSO

ssl(7), SSL_get_session(3)
