SSL_CONF_cmd(3ssl)

Paquete: openssl

Licencias: Apache-2.0

SSL_CONF_CMD(3ssl) OpenSSL SSL_CONF_CMD(3ssl)

NOMBRE

SSL_CONF_cmd_value_type, SSL_CONF_cmd - enviar comando de configuración

SINOPSIS

#include <openssl/ssl.h>
int SSL_CONF_cmd(SSL_CONF_CTX *ctx, const char *option, const char *value);
int SSL_CONF_cmd_value_type(SSL_CONF_CTX *ctx, const char *option);

DESCRIPCIÓN

La función SSL_CONF_cmd() realiza la operación de configuración option con el parámetro opcional value en ctx. Su propósito es simplificar la configuración de aplicaciones de estructuras SSL_CTX o SSL al proporcionar un marco común para opciones de línea de comandos o archivos de configuración.

SSL_CONF_cmd_value_type() devuelve el tipo de valor al que se refiere option.

COMANDOS DE LÍNEA DE COMANDOS SOPORTADOS

Actualmente, los nombres de option soportados para líneas de comandos (es decir, cuando el indicador SSL_CONF_FLAG_CMDLINE está establecido) se enumeran a continuación. Nota: todos los nombres de option distinguen entre mayúsculas y minúsculas. A menos que se indique lo contrario, los comandos pueden ser utilizados tanto por clientes como por servidores y el parámetro value no se utiliza. El prefijo por defecto para los comandos de línea de comandos es - y eso se refleja a continuación.

-bugs
Se establecen varias soluciones alternativas para errores, igual que establecer SSL_OP_ALL.
-no_comp
Deshabilita el soporte para compresión SSL/TLS, igual que establecer SSL_OP_NO_COMPRESSION. A partir de OpenSSL 1.1.0, la compresión está desactivada por defecto.
-comp
Habilita el soporte para compresión SSL/TLS, igual que borrar SSL_OP_NO_COMPRESSION. Este comando se introdujo en OpenSSL 1.1.0. A partir de OpenSSL 1.1.0, la compresión está desactivada por defecto. La compresión TLS solo se puede utilizar en nivel de seguridad 1 o inferior. A partir de OpenSSL 3.2.0 y posteriores, el nivel de seguridad por defecto es 2, por lo que esta opción no tendrá ningún efecto sin cambiar también el nivel de seguridad. Consulte SSL_CTX_set_security_level(3).
-no_ticket
Deshabilita el soporte para tickets de sesión, igual que establecer SSL_OP_NO_TICKET.
-serverpref
Utiliza el orden de preferencia del servidor y no del cliente al determinar qué suite de cifrado, algoritmo de firma o curva elíptica (TLS 1.2) o grupo (TLS 1.3) utilizar para una conexión entrante. Equivalente a SSL_OP_SERVER_PREFERENCE. Solo utilizado por servidores.
-client_renegotiation
Permite a los servidores aceptar la renegociación iniciada por el cliente. Equivalente a establecer SSL_OP_ALLOW_CLIENT_RENEGOTIATION. Solo utilizado por servidores.
-legacy_renegotiation
Permite el uso de la renegociación heredada insegura. Equivalente a establecer SSL_OP_ALLOW_UNSAFE_LEGACY_RENEGOTIATION.
-no_renegotiation
Deshabilita todos los intentos de renegociación en (D)TLSv1.2 y anteriores, igual que establecer SSL_OP_NO_RENEGOTIATION.
-no_resumption_on_reneg
Establece SSL_OP_NO_SESSION_RESUMPTION_ON_RENEGOTIATION. Solo utilizado por servidores.
-legacy_server_connect, -no_legacy_server_connect
Permite o prohíbe el uso de la conexión de servidor heredada insegura solo para clientes OpenSSL. Equivalente a establecer o borrar SSL_OP_LEGACY_SERVER_CONNECT.
-prioritize_chacha
Prioriza los cifrados ChaCha cuando el cliente tiene un ChaCha20 en la parte superior de su lista de preferencias. Esto generalmente indica el uso de un cliente sin aceleración de hardware AES (por ejemplo, móvil). Equivalente a SSL_OP_PRIORITIZE_CHACHA. Solo utilizado por servidores. Requiere -serverpref.
-allow_no_dhe_kex
En TLSv1.3, permite un modo de intercambio de claves no basado en (ec)dhe en la reanudación. Esto significa que no habrá secreto directo para la sesión reanudada.
-prefer_no_dhe_kex
En TLSv1.3, al reanudar, permite que el servidor prefiera un modo de intercambio de claves no basado en (ec)dhe sobre uno basado en (ec)dhe. Requiere -allow_no_dhe_kex. Equivalente a SSL_OP_PREFER_NO_DHE_KEX. Solo utilizado por servidores.
-strict
Habilita el manejo de protocolos en modo estricto. Equivalente a establecer SSL_CERT_FLAG_TLS_STRICT.
-sigalgs algs
Esto establece los algoritmos de firma soportados para TLSv1.2 y TLSv1.3. Para clientes, este valor se utiliza directamente para la extensión de algoritmos de firma soportados. Para servidores, se utiliza para determinar qué algoritmos de firma soportar.

El argumento algs debe ser una lista separada por dos puntos de algoritmos de firma en orden de preferencia decreciente de la forma algoritmo+hash o esquema_de_firma. Para los proveedores por defecto que se distribuyen con OpenSSL, algoritmo es uno de RSA, DSA o ECDSA y hash es un nombre corto de OID de algoritmo soportado como SHA1, SHA224, SHA256, SHA384 o SHA512. esquema_de_firma es uno de los esquemas de firma definidos en TLSv1.3, especificado usando el nombre IETF, por ejemplo, ecdsa_secp256r1_sha256, ed25519, o rsa_pss_pss_sha256. Proveedores adicionales pueden hacer disponibles algoritmos adicionales a través de la capacidad TLS-SIGALG. Los nombres de los esquemas de firma y los nombres de los algoritmos de clave pública (pero no los nombres de hash) en la forma algoritmo+hash no distinguen entre mayúsculas y minúsculas. Consulte provider-base(7).

Si esta opción no está establecida, todos los algoritmos de firma soportados por todos los proveedores activados son permisibles.

Nota: los algoritmos que especifican un esquema de firma PKCS#1 v1.5 (ya sea usando RSA como el algoritmo o usando uno de los identificadores rsa_pkcs1_*) se ignoran en TLSv1.3 y no se negociarán.

-client_sigalgs algs
Esto establece los algoritmos de firma soportados asociados con la autenticación del cliente para TLSv1.2 y TLSv1.3. Para servidores, algs se utiliza en el campo signature_algorithms de un mensaje CertificateRequest. Para clientes, se utiliza para determinar qué algoritmo de firma usar con el certificado del cliente. Si un servidor no solicita un certificado, esta opción no tiene ningún efecto.

La sintaxis de algs es idéntica a la de -sigalgs. Si no está establecida, se utilizará el valor establecido para -sigalgs en su lugar.

-groups grupos
Esto establece los grupos soportados. Para clientes, los grupos se envían utilizando la extensión de grupos soportados. Para servidores, se utiliza para determinar qué grupo usar. Esta configuración afecta a los grupos utilizados para las firmas (en TLSv1.2 y anteriores) y el intercambio de claves.

En su forma más simple, el argumento grupos es una lista separada por dos puntos de grupos. Los nombres preferidos son los listados en el registro IANA de Grupos Soportados de TLS https://www.iana.org/assignments/tls-parameters/tls-parameters.xhtml#tls-parameters-8.

Para algunos grupos, OpenSSL soporta alias adicionales. Dicho alias podría ser un nombre NIST (por ejemplo, P-256), un nombre de OID de OpenSSL (por ejemplo, prime256v1), o algún otro nombre de uso común. Los nombres de grupo no distinguen entre mayúsculas y minúsculas en OpenSSL 3.5 y posteriores. La lista debe estar en orden de preferencia, con el grupo más preferido primero.

El primer grupo listado también se utilizará para la key_share enviada por un cliente en un ClientHello de TLSv1.3.

Los comandos a continuación enumeran los nombres IANA para TLS 1.2 y TLS 1.3, respectivamente:

$ openssl list -tls1_2 -tls-groups
$ openssl list -tls1_3 -tls-groups

-curves grupos
Este es un sinónimo del comando -groups.
-named_curve curva
Esto establece la curva temporal utilizada para modos ECDH efímeros. Esto solo es aplicable en TLS 1.0 y 1.1, y no debe usarse con versiones de protocolo posteriores.

El argumento curva es un nombre de curva o el valor especial auto que elige una curva apropiada basada en las preferencias del cliente y del servidor. La curva puede ser el nombre NIST (por ejemplo, P-256) o un nombre OID de OpenSSL (por ejemplo, prime256v1). Incluso con TLS 1.0 y 1.1, el valor predeterminado de "auto" es fuertemente recomendado sobre la elección de una curva específica. Los nombres de curva no distinguen entre mayúsculas y minúsculas en OpenSSL 3.5 y posteriores.

-tx_cert_comp
Habilita el soporte para enviar certificados comprimidos TLSv1.3.
-no_tx_cert_comp
Deshabilita el soporte para enviar certificados comprimidos TLSv1.3.
-rx_cert_comp
Habilita el soporte para recibir certificados comprimidos TLSv1.3.
-no_rx_cert_comp
Deshabilita el soporte para recibir certificados comprimidos TLSv1.3.
-comp
-cipher ciphers
Establece la lista de suites de cifrado de TLSv1.2 y anteriores a ciphers. Esta lista se combinará con cualquier suite de cifrado TLSv1.3 configurada. Nota: actualmente no se realiza ninguna verificación de sintaxis de ciphers a menos que una estructura SSL o SSL_CTX esté asociada con ctx.
-ciphersuites ciphers1.3
Establece las suites de cifrado disponibles para TLSv1.3 al valor. Esta es una lista separada por dos puntos de nombres de suites de cifrado TLSv1.3 en orden de preferencia. Esta lista se combinará con cualquier suite de cifrado TLSv1.2 y anteriores configurada. Ver openssl-ciphers(1) para más información.
-min_protocol minprot, -max_protocol maxprot
Establece el protocolo mínimo y máximo admitido. Actualmente los valores de protocolo admitidos son SSLv3, TLSv1, TLSv1.1, TLSv1.2, TLSv1.3 para TLS; DTLSv1, DTLSv1.2 para DTLS, y None para sin límite. Si no se especifica el límite inferior o el superior, entonces solo se aplica el otro límite, si se especifica. Si su aplicación admite tanto TLS como DTLS, puede especificar cualquiera de estas opciones dos veces, una vez con un límite para TLS y otra vez con un límite apropiado para DTLS. Para restringir las versiones de protocolo admitidas, utilice estos comandos en lugar de los comandos alternativos obsoletos a continuación.
-record_padding padding
Controla el uso del relleno de la capa de registros TLSv1.3. padding es una cadena de la forma "número[,número]" donde el primer número (requerido) es el tamaño del bloque de relleno (en octetos) para datos de aplicación, y el segundo número opcional es el tamaño del bloque de relleno para mensajes de saludo y alerta. Si se omite el segundo número opcional, se aplicará el mismo relleno a todos los mensajes.

El relleno intenta rellenar los registros TLSv1.3 para que sean un múltiplo de la longitud establecida al enviar. Un valor de 0 o 1 desactiva el relleno según corresponda. De lo contrario, los valores deben ser >1 o <=16384.

-debug_broken_protocol
Ignorado.
-no_middlebox
Desactiva la "compatibilidad con middlebox", como se describe a continuación.

Opciones Adicionales

Las siguientes opciones son aceptadas por SSL_CONF_cmd(), pero no son procesadas por los comandos OpenSSL.

-cert archivo
Intenta usar archivo como el certificado para el contexto apropiado. Actualmente utiliza SSL_CTX_use_certificate_chain_file() si se establece una estructura SSL_CTX o SSL_use_certificate_file() con tipo de archivo PEM si se establece una estructura SSL. Esta opción solo se admite si las operaciones de certificado están permitidas.
-key archivo
Intenta usar archivo como la clave privada para el contexto apropiado. Esta opción solo se admite si las operaciones de certificado están permitidas. Nota: si no se establece ninguna opción -key, la clave privada no se carga a menos que se establezca el indicador SSL_CONF_FLAG_REQUIRE_PRIVATE.
-dhparam archivo
Intenta usar archivo como el conjunto de parámetros DH temporales para el contexto apropiado. Esta opción solo se admite si las operaciones de certificado están permitidas.
-no_ssl3, -no_tls1, -no_tls1_1, -no_tls1_2, -no_tls1_3
Deshabilita el soporte del protocolo para SSLv3, TLSv1.0, TLSv1.1, TLSv1.2 o TLSv1.3 estableciendo las opciones correspondientes SSL_OP_NO_SSLv3, SSL_OP_NO_TLSv1, SSL_OP_NO_TLSv1_1, SSL_OP_NO_TLSv1_2 y SSL_OP_NO_TLSv1_3 respectivamente. Estas opciones están obsoletas, use -min_protocol y -max_protocol en su lugar.
-anti_replay, -no_anti_replay
Cambia la protección contra repetición, activada o desactivada respectivamente. Con la protección contra repetición activada, OpenSSL detectará automáticamente si un ticket de sesión se ha utilizado más de una vez, se ha negociado TLSv1.3 y los datos tempranos están habilitados en el servidor. Se fuerza un saludo completo si un ticket de sesión se utiliza por segunda vez o en ocasiones posteriores. La protección anti-repetición está activada por defecto a menos que se anule mediante un archivo de configuración y solo es utilizada por los servidores. Las medidas anti-repetición son necesarias para el cumplimiento de la especificación TLSv1.3. Algunas aplicaciones pueden mitigar los riesgos de repetición de otras maneras y, en tales casos, la funcionalidad incorporada de OpenSSL no es necesaria. Desactivar la protección anti-repetición es equivalente a SSL_OP_NO_ANTI_REPLAY.

COMANDOS DE ARCHIVO DE CONFIGURACIÓN SOPORTADOS

Actualmente, los nombres de opción admitidos para archivos de configuración (es decir, cuando se establece el indicador SSL_CONF_FLAG_FILE) se enumeran a continuación. Todos los nombres de opción de archivo de configuración no distinguen entre mayúsculas y minúsculas, por lo que signaturealgorithms se reconoce al igual que SignatureAlgorithms. A menos que se indique lo contrario, los nombres de valor tampoco distinguen entre mayúsculas y minúsculas.

Nota: el prefijo del comando (si se establece) altera los valores de opción reconocidos.

CipherString
Establece la lista de suites de cifrado para TLSv1.2 y anteriores a valor. Esta lista se combinará con cualquier suite de cifrado TLSv1.3 configurada. Nota: actualmente no se realiza ninguna verificación de sintaxis de valor a menos que una estructura SSL o SSL_CTX esté asociada con ctx.
Ciphersuites
Establece las suites de cifrado disponibles para TLSv1.3 a valor. Esta es una lista separada por dos puntos de nombres de suites de cifrado TLSv1.3 en orden de preferencia. Esta lista se combinará con cualquier suite de cifrado TLSv1.2 y anteriores configurada. Ver openssl-ciphers(1) para más información.
Certificate
Intenta usar el archivo valor como el certificado para el contexto apropiado. Actualmente utiliza SSL_CTX_use_certificate_chain_file() si se establece una estructura SSL_CTX o SSL_use_certificate_file() con tipo de archivo PEM si se establece una estructura SSL. Esta opción solo se admite si las operaciones de certificado están permitidas.
PrivateKey
Intenta usar el archivo valor como la clave privada para el contexto apropiado. Esta opción solo se admite si las operaciones de certificado están permitidas. Nota: si no se establece ninguna opción PrivateKey, la clave privada no se carga a menos que se establezca SSL_CONF_FLAG_REQUIRE_PRIVATE.
ChainCAFile, ChainCAPath, VerifyCAFile, VerifyCAPath
Estas opciones indican un archivo o directorio utilizado para construir cadenas de certificados o verificar cadenas de certificados. Estas opciones solo se admiten si las operaciones de certificado están permitidas.
RequestCAFile
Esta opción indica un archivo que contiene un conjunto de certificados en formato PEM. Los nombres de asunto de los certificados se envían al par en la extensión certificate_authorities para TLS 1.3 (en ClientHello o CertificateRequest) o en una solicitud de certificado para versiones anteriores o TLS.
ServerInfoFile
Intenta usar el archivo valor en la extensión "serverinfo" utilizando la función SSL_CTX_use_serverinfo_file.
DHParameters
Intenta usar el archivo valor como el conjunto de parámetros DH temporales para el contexto apropiado. Esta opción solo se admite si las operaciones de certificado están permitidas.
RecordPaddingControla el uso del padding en la capa de registro TLSv1.3. El valor es una cadena de la forma "número[,número]" donde el primer número (requerido) es el tamaño del bloque de padding (en octetos) para los datos de la aplicación, y el segundo número (opcional) es el tamaño del bloque de padding para los mensajes de handshake y alerta. Si se omite el segundo número, se aplica el mismo padding a todos los mensajes.

El padding intenta rellenar los registros TLSv1.3 de forma que sean múltiplos de la longitud establecida en la emisión. Un valor de 0 o 1 desactiva el padding en lo relevante. De lo contrario, los valores deben ser >1 o <=16384.

SignatureAlgorithms
Establece los algoritmos de firma soportados en TLSv1.2 y TLSv1.3. Para clientes, este valor se usa directamente en la extensión de algoritmos de firma. Para servidores, se usa para determinar qué algoritmos de firma se soportan.

El argumento value debe ser una lista separada por dos puntos de algoritmos de firma en orden decreciente de preferencia, con el formato algorithm+hash o signature_scheme. Para los proveedores por defecto de OpenSSL, algorithm es uno de RSA, DSA o ECDSA y hash es un nombre corto de un algoritmo OID soportado, como SHA1, SHA224, SHA256, SHA384 o SHA512. signature_scheme es uno de los esquemas de firma definidos en TLSv1.3, especificados mediante el nombre IANA, como ecdsa_secp256r1_sha256, ed25519 o rsa_pss_pss_sha256. Los nombres de algoritmo de firma y algoritmos de clave pública (pero no los nombres de hash) en el formato algorithm+hash no distinguen mayúsculas de minúsculas. Otros proveedores pueden ofrecer más algoritmos de firma a través de la capacidad TLS_SIGALG. Ver "CAPABILITIES" en provider-base(7).

Si esta opción no está configurada, se permiten todos los algoritmos de firma soportados por todos los proveedores activos.

Nota: Los algoritmos que especifican un esquema de firma PKCS#1 v1.5 (a través de RSA como algorithm o mediante uno de los identificadores rsa_pkcs1_*) son ignorados en TLSv1.3 y no se negociarán.

ClientSignatureAlgorithms
Establece los algoritmos de firma asociados con la autenticación del cliente en TLSv1.2 y TLSv1.3. Para los servidores, el valor se usa en el campo signature_algorithms de un mensaje CertificateRequest. Para los clientes, se usa para determinar qué algoritmo de firma usar con el certificado del cliente. Si un servidor no solicita un certificado, esta opción no tiene efecto.

La sintaxis del valor value es idéntica a SignatureAlgorithms. Si no está configurada, se utilizará el valor establecido en SignatureAlgorithms.

Groups
Establece los grupos soportados. Para los clientes, los grupos se envían mediante la extensión de grupos soportados. Para los servidores, se usa para determinar qué grupo usar. Este ajuste afecta a los grupos utilizados para firmas (en TLSv1.2 y versiones anteriores) y el intercambio de claves. El primer grupo mencionado también se usa para la key_share enviada por un cliente en un ClientHello de TLSv1.3.

El argumento groups es una lista separada por dos puntos de grupos. Los nombres preferidos son los listados en el registro IANA TLS Supported Groups https://www.iana.org/assignments/tls-parameters/tls-parameters.xhtml#tls-parameters-8. Para algunos grupos, OpenSSL soporta alias adicionales. Dichos alias pueden ser nombres NIST (ejemplo P-256), nombres OID de OpenSSL (ejemplo prime256v1) o nombres comunes. Los nombres de grupo no distinguen mayúsculas de minúsculas en OpenSSL 3.5 y versiones posteriores. La lista debe estar en orden de preferencia, con el grupo más preferido primero.

Las siguientes instrucciones muestran los grupos disponibles para TLS 1.2 y TLS 1.3, respectivamente:

$ openssl list -tls1_2 -tls-groups
$ openssl list -tls1_3 -tls-groups

Una sintaxis alternativa mejorada que permite enviar múltiples key shares a los clientes y priorizar algunos grupos sobre otros se describe en SSL_CTX_set1_groups_list(3). Dado que TLS 1.2 no tiene key shares ni mecanismo de retry hello, con TLS 1.2 la sintaxis mejorada es equivalente a una lista ordenada de grupos, como en la forma simple anterior.

Curves
Es un sinónimo del comando "Groups".
MinProtocol
Establece la versión mínima soportada de SSL, TLS o DTLS.

Los valores actualmente soportados son SSLv3, TLSv1, TLSv1.1, TLSv1.2, TLSv1.3, DTLSv1 y DTLSv1.2. Los límites SSL y TLS se aplican solo a contextos basados en TLS, mientras que los límites DTLS se aplican solo a contextos basados en DTLS. El comando puede repetirse con una instancia estableciendo un límite TLS y otra un límite DTLS. El valor None se aplica a ambos tipos de contexto y deshabilita los límites.

MaxProtocol
Establece la versión máxima soportada de SSL, TLS o DTLS.

Los valores actualmente soportados son SSLv3, TLSv1, TLSv1.1, TLSv1.2, TLSv1.3, DTLSv1 y DTLSv1.2. Los límites SSL y TLS se aplican solo a contextos basados en TLS, mientras que los límites DTLS se aplican solo a contextos basados en DTLS. El comando puede repetirse con una instancia estableciendo un límite TLS y otra un límite DTLS. El valor None se aplica a ambos tipos de contexto y deshabilita los límites.

Protocol
Se puede usar para habilitar o deshabilitar ciertas versiones de protocolo SSL, TLS o DTLS.

El argumento value es una lista separada por comas de protocolos soportados para habilitar o deshabilitar. Si un protocolo está precedido por -, esa versión se deshabilita.

Por defecto, todas las versiones de protocolo están habilitadas. Para que esta configuración tenga efecto, se debe deshabilitar al menos una versión. Habilitar solo algunas versiones no deshabilita las otras versiones.

Los valores actualmente soportados son SSLv3, TLSv1, TLSv1.1, TLSv1.2, TLSv1.3, DTLSv1 y DTLSv1.2. El valor especial ALL se refiere a todas las versiones soportadas.

Esta configuración no puede habilitar protocolos que se deshabilitan con MinProtocol o MaxProtocol, pero puede deshabilitar protocolos que aún estén permitidos por ellos.

El comando Protocol es frágil y obsoleto; no se debe usar. Use MinProtocol y MaxProtocol en su lugar. Si se usa Protocol, asegúrese de que el rango de protocolos habilitados no tenga "huecos", por ejemplo, si SSLv3 y TLSv1.2 están habilitados, asegúrese de dejar TLSv1.1 habilitado.

Options
El argumento value es una lista separada por comas de varias banderas para establecer. Si una cadena de bandera está precedida por -, se deshabilita. Ver la función SSL_CTX_set_options(3) para más detalles sobre las banderas individuales.

Cada opción se lista a continuación. Donde una operación está activada por defecto, se necesita la sintaxis -flag para deshabilitarla.

SessionTicket: soporte de tickets de sesión, activado por defecto. Inverso de SSL_OP_NO_TICKET: es decir, -SessionTicket es lo mismo que establecer SSL_OP_NO_TICKET.

Compression: soporte de compresión SSL/TLS, desactivado por defecto. Inverso de SSL_OP_NO_COMPRESSION.

EmptyFragments: uso de fragmentos vacíos como medida contra una vulnerabilidad de SSL 3.0/TLS 1.0 que afecta a los cifrados CBC. Se establece por defecto. Inverso de SSL_OP_DONT_INSERT_EMPTY_FRAGMENTS.

Bugs: habilita varias correcciones de errores. Es lo mismo que SSL_OP_ALL.

DHSingle: habilita claves DH únicas, activado por defecto. Inverso de SSL_OP_DH_SINGLE. Solo usado por servidores.

ECDHSingle: habilita claves ECDH únicas, activado por defecto. Inverso de SSL_OP_ECDH_SINGLE. Solo usado por servidores.

ServerPreference: usa la preferencia del servidor sobre la preferencia del cliente al determinar qué suite de cifrado, algoritmo de firma o curva (TLS 1.2) o grupo (TLS 1.3) usar para una conexión entrante. Equivalente a SSL_OP_SERVER_PREFERENCE. Solo usado por servidores.

PrioritizeChaCha: prioriza los cifrados ChaCha cuando el cliente tiene un cifrado ChaCha20 en la parte superior de su lista de preferencias. Esto suele indicar un cliente móvil en uso. Equivalente a SSL_OP_PRIORITIZE_CHACHA. Solo usado por servidores.

NoResumptionOnRenegotiation: establece la bandera SSL_OP_NO_SESSION_RESUMPTION_ON_RENEGOTIATION. Solo usado por servidores.

NoRenegotiation: deshabilita todos los intentos de renegociación en TLSv1.2 y anteriores, lo mismo que establecer SSL_OP_NO_RENEGOTIATION.

UnsafeLegacyRenegotiation: permite el uso de renegociación heredada insegura. Equivalente a SSL_OP_ALLOW_UNSAFE_LEGACY_RENEGOTIATION.

UnsafeLegacyServerConnect: permite el uso de renegociación heredada insegura para clientes OpenSSL solamente. Equivalente a SSL_OP_LEGACY_SERVER_CONNECT.

EncryptThenMac: uso de la extensión encrypt-then-mac, activado por defecto. Inverso de SSL_OP_NO_ENCRYPT_THEN_MAC: es decir, -EncryptThenMac es lo mismo que establecer SSL_OP_NO_ENCRYPT_THEN_MAC.

AllowNoDHEKEX: en TLSv1.3 permite un modo de intercambio de claves no-(ec)dhe en la reanudación. Esto significa que no habrá forward secrecy para la sesión reanudada. Equivalente a SSL_OP_ALLOW_NO_DHE_KEX.

PreferNoDHEKEX: en TLSv1.3, en la reanudación, permite al servidor preferir un modo de intercambio de claves no-(ec)dhe sobre un modo (ec)dhe. Requiere AllowNoDHEKEX. Equivalente a SSL_OP_PREFER_NO_DHE_KEX. Solo usado por servidores.

MiddleboxCompat: si se establece, se envían mensajes dummy Change Cipher Spec (CCS) en TLSv1.3. Este efecto hace que TLSv1.3 se parezca más a TLSv1.2, para que los middleboxes que no entienden TLS se comporten correctamente.

v1.3 no cerrará la conexión. Esta opción está establecida por defecto. Una futura versión de OpenSSL podría no establecer esta opción por defecto. Equivalente a SSL_OP_ENABLE_MIDDLEBOX_COMPAT.

AntiReplay: Si se establece, OpenSSL detectará automáticamente si se ha utilizado un ticket de sesión más de una vez, si se ha negociado TLSv1.3 y si los datos iniciales están habilitados en el servidor. Se fuerza una conexión completa si se utiliza un ticket de sesión por segunda vez o posteriormente. Esta opción está establecida por defecto y solo la utilizan los servidores. Las medidas anti-repetición son necesarias para cumplir con la especificación TLSv1.3. Algunas aplicaciones pueden mitigar los riesgos de repetición de otras maneras y, en tales casos, la funcionalidad incorporada de OpenSSL no es necesaria. Deshabilitar anti-repetición es equivalente a establecer SSL_OP_NO_ANTI_REPLAY.

ExtendedMasterSecret: utiliza la extensión Extended Master Secret, habilitada por defecto. Inverso de SSL_OP_NO_EXTENDED_MASTER_SECRET: es decir, -ExtendedMasterSecret es lo mismo que establecer SSL_OP_NO_EXTENDED_MASTER_SECRET.

CANames: utiliza la extensión de nombres CA, habilitada por defecto. Inverso de SSL_OP_DISABLE_TLSEXT_CA_NAMES: es decir, -CANames es lo mismo que establecer SSL_OP_DISABLE_TLSEXT_CA_NAMES.

KTLS: Habilita KTLS si se ha compilado el soporte y si es compatible con los cifrados y extensiones negociados. Equivalente a SSL_OP_ENABLE_KTLS.

StrictCertCheck: Habilita la comprobación estricta de certificados. Equivalente a establecer SSL_CERT_FLAG_TLS_STRICT con SSL_CTX_set_cert_flags().

TxCertificateCompression: soporta el envío de certificados comprimidos, habilitado por defecto. Inverso de SSL_OP_NO_TX_CERTIFICATE_COMPRESSION: es decir, -TxCertificateCompression es lo mismo que establecer SSL_OP_NO_TX_CERTIFICATE_COMPRESSION.

RxCertificateCompression: soporta la recepción de certificados comprimidos, habilitado por defecto. Inverso de SSL_OP_NO_RX_CERTIFICATE_COMPRESSION: es decir, -RxCertificateCompression es lo mismo que establecer SSL_OP_NO_RX_CERTIFICATE_COMPRESSION.

KTLSTxZerocopySendfile: utiliza el modo TX zerocopy de sendfile(), que proporciona una mejora de rendimiento cuando se utiliza con la descarga de hardware KTLS. Tenga en cuenta que se pueden transmitir registros TLS no válidos si el archivo se modifica mientras se envía. Esta opción no tiene ningún efecto si KTLS no está habilitado. Equivalente a SSL_OP_ENABLE_KTLS_TX_ZEROCOPY_SENDFILE. Esta opción solo se aplica a Linux. KTLS sendfile en FreeBSD no ofrece una opción para deshabilitar zerocopy y siempre se ejecuta en este modo.

IgnoreUnexpectedEOF: Equivalente a SSL_OP_IGNORE_UNEXPECTED_EOF. Solo debe habilitar esta opción si el protocolo que se ejecuta sobre TLS puede detectar un ataque de truncamiento por sí mismo y si la aplicación está comprobando dicho ataque de truncamiento.

VerifyMode
El argumento value es una lista separada por comas de flags a establecer.

Peer habilita la verificación del par: solo para clientes.

Request solicita pero no requiere un certificado del cliente. Solo para servidores.

Require solicita y requiere un certificado del cliente: se produce un error si el cliente no presenta un certificado. Solo para servidores.

Once solicita un certificado de un cliente solo en la conexión inicial: no al renegociar. Solo para servidores.

RequestPostHandshake configura la conexión para que admita solicitudes pero no requiera un certificado del cliente después de la conexión. No se solicitará un certificado durante la conexión inicial. La aplicación del servidor debe proporcionar un mecanismo para solicitar un certificado después de la conexión. Solo para servidores. Solo TLSv1.3.

RequiresPostHandshake configura la conexión para que admita solicitudes y requiera un certificado del cliente después de la conexión: se produce un error si el cliente no presenta un certificado. No se solicitará un certificado durante la conexión inicial. La aplicación del servidor debe proporcionar un mecanismo para solicitar un certificado después de la conexión. Solo para servidores. Solo TLSv1.3.

ClientCAFile, ClientCAPath
Un archivo o directorio de certificados en formato PEM cuyos nombres se utilizan como el conjunto de nombres aceptables para las CA de clientes. Solo para servidores. Esta opción solo se admite si se permiten operaciones de certificados.

TIPOS DE COMANDOS SOPORTADOS

La función SSL_CONF_cmd_value_type() devuelve actualmente uno de los siguientes tipos:

SSL_CONF_TYPE_UNKNOWN
La cadena option no se reconoce; este valor de retorno se puede usar para indicar errores de sintaxis.
SSL_CONF_TYPE_STRING
El valor es una cadena sin estructura específica.
SSL_CONF_TYPE_FILE
El valor es un nombre de archivo.
SSL_CONF_TYPE_DIR
El valor es un nombre de directorio.
SSL_CONF_TYPE_NONE
La cadena de valor no se utiliza, por ejemplo, una opción de línea de comandos que no toma ningún argumento.

NOTAS

El orden de las operaciones es importante. Esto se puede utilizar para establecer valores predeterminados o valores que no se pueden anular. Por ejemplo, si una aplicación llama:

SSL_CONF_cmd(ctx, "Protocol", "-SSLv3");
SSL_CONF_cmd(ctx, userparam, uservalue);

deshabilitará el soporte de SSLv3 por defecto, pero el usuario puede anularlo. Sin embargo, si la secuencia de llamadas es:

SSL_CONF_cmd(ctx, userparam, uservalue);
SSL_CONF_cmd(ctx, "Protocol", "-SSLv3");

SSLv3 se deshabilita **siempre** y los intentos de anular esto por parte del usuario se ignoran.

Al comprobar el código de retorno de SSL_CONF_cmd() es posible consultar si una option dada es reconocida, esto es útil si los valores de SSL_CONF_cmd() se mezclan con operaciones adicionales específicas de la aplicación.

Por ejemplo, una aplicación podría llamar a SSL_CONF_cmd() y si devuelve -2 (comando no reconocido) continuar con el procesamiento de comandos específicos de la aplicación.

Las aplicaciones también pueden usar SSL_CONF_cmd() para procesar líneas de comandos, aunque normalmente se utiliza la función de utilidad SSL_CONF_cmd_argv() en su lugar. Una forma de hacerlo es establecer el prefijo en un valor apropiado usando SSL_CONF_CTX_set1_prefix(), pasar el argumento actual a option y el siguiente argumento a value (que puede ser NULL).

En este caso, si el valor de retorno es positivo, se utiliza para saltar ese número de argumentos ya que han sido procesados por SSL_CONF_cmd(). Si se devuelve -2, no se reconoce option y se pueden comprobar argumentos específicos de la aplicación en su lugar. Si se devuelve -3, falta un argumento requerido y se indica un error. Si se devuelve 0, se produjo algún otro error y esto se puede informar al usuario.

La función SSL_CONF_cmd_value_type() puede ser utilizada por las aplicaciones para comprobar la existencia de un comando o para realizar comprobaciones de sintaxis adicionales o traducciones del valor del comando. Por ejemplo, si el valor de retorno es SSL_CONF_TYPE_FILE, una aplicación podría traducir un nombre de ruta relativo a un nombre de ruta absoluto.

VALORES DE RETORNO

SSL_CONF_cmd() devuelve 1 si el valor de option es reconocido y value **NO** se utiliza, y 2 si tanto option como value se utilizan. En otras palabras, devuelve el número de argumentos procesados. Esto es útil al procesar líneas de comandos.

Un valor de retorno de -2 significa que option no es reconocido.

Un valor de retorno de -3 significa que option es reconocido y el comando requiere un valor, pero value es NULL.

Un código de retorno de 0 indica que tanto option como value son válidos pero ocurrió un error al intentar realizar la operación: por ejemplo, debido a un error en la sintaxis de value; en este caso, la cola de errores puede proporcionar información adicional.

EJEMPLOS

Establecer algoritmos de firma compatibles:

SSL_CONF_cmd(ctx, "SignatureAlgorithms", "ECDSA+SHA256:RSA+SHA256:DSA+SHA256");

Hay varias formas de seleccionar los protocolos compatibles.

Esto establece la versión mínima del protocolo en TLSv1 y, por lo tanto, deshabilita SSLv3. Esta es la forma recomendada de deshabilitar protocolos.

SSL_CONF_cmd(ctx, "MinProtocol", "TLSv1");

Lo siguiente también deshabilita SSLv3:

SSL_CONF_cmd(ctx, "Protocol", "-SSLv3");

Lo siguiente primero habilitará todos los protocolos y luego deshabilitará SSLv3. Si no se deshabilitaron protocolos antes, esto tiene el mismo efecto que "-SSLv3", pero si se deshabilitaron algunos protocolos, los re-habilitará antes de deshabilitar SSLv3.

SSL_CONF_cmd(ctx, "Protocol", "ALL,-SSLv3");

Solo habilita TLSv1.2:

SSL_CONF_cmd(ctx, "MinProtocol", "TLSv1.2");
SSL_CONF_cmd(ctx, "MaxProtocol", "TLSv1.2");

Esto también solo habilita TLSv1.2:

SSL_CONF_cmd(ctx, "Protocol", "-ALL,TLSv1.2");

Deshabilita los tickets de sesión TLS:

SSL_CONF_cmd(ctx, "Options", "-SessionTicket");

Habilita la compresión:

SSL_CONF_cmd(ctx, "Options", "Compression");

Establece las curvas compatibles en P-256, P-384:

SSL_CONF_cmd(ctx, "Curves", "P-256:P-384");

NAME

SSL_CONF_cmd, SSL_CONF_cmd_value_type, SSL_CONF_get_cmd_details, SSL_CONF_get_number, SSL_CONF_get_string, SSL_CONF_parse_cmd_lines, SSL_CONF_set1_conf, SSL_CONF_set_conf, SSL_CONF_use_certificate, SSL_CONF_use_certificate_chain, SSL_CONF_use_ciphers, SSL_CONF_use_curve, SSL_CONF_use_disk, SSL_CONF_use_key, SSL_CONF_use_pkcs12, SSL_CONF_warn - SSL configuration functions

SYNOPSIS

#include <openssl/ssl.h>
#include <openssl/conf.h>

int SSL_CONF_cmd(SSL_CTX *ctx, const char *cmd, const char *value);
int SSL_CONF_cmd_value_type(const char *cmd);
int SSL_CONF_get_cmd_details(const char *cmd, const SSL_CONF_CMD **cmd_details);
long SSL_CONF_get_number(const char *value);
const char *SSL_CONF_get_string(const char *value, char **dest);
int SSL_CONF_parse_cmd_lines(SSL_CTX *ctx, char **lines, size_t num_lines,
                             unsigned int flags, unsigned int *seen);
int SSL_CONF_set1_conf(SSL_CTX *ctx, const CONF *conf);
int SSL_CONF_set_conf(SSL_CTX *ctx, CONF *conf);
int SSL_CONF_use_certificate(SSL_CTX *ctx, const char *file);
int SSL_CONF_use_certificate_chain(SSL_CTX *ctx, const char *file);
int SSL_CONF_use_ciphers(SSL_CTX *ctx, const char *str);
int SSL_CONF_use_curve(SSL_CTX *ctx, const char *curve_name);
int SSL_CONF_use_disk(SSL_CTX *ctx, const char *path);
int SSL_CONF_use_key(SSL_CTX *ctx, const char *file);
int SSL_CONF_use_pkcs12(SSL_CTX *ctx, const char *file,
                        const char *password);
int SSL_CONF_warn(SSL_CTX *ctx, const char *cmd, const char *value);

DESCRIPTION

The SSL_CONF_cmd function is a general purpose function for setting configuration options within an SSL_CTX structure. The cmd parameter is a string identifying the command to execute, and value is the string parameter to that command. Commands are processed in the order they are given.

The SSL_CONF_cmd_value_type function returns the type of value expected by the command cmd. See the section "SUPPORTED COMMAND TYPES" for a list of types.

The SSL_CONF_get_cmd_details function returns details about the command cmd. The pointer cmd_details is filled with a pointer to an SSL_CONF_CMD structure containing information about the command, such as its name, number, and expected value type.

The SSL_CONF_get_number function parses the string value as a base-10 integer and returns its value. If the string cannot be parsed as a number, it returns 0.

The SSL_CONF_get_string function copies the string value into a dynamically allocated buffer and returns a pointer to it. The caller is responsible for freeing the returned buffer using OPENSSL_free. If the argument dest is not NULL, then the returned string is copied to *dest, and *dest is also freed. This behaviour is to support the conversion of a configuration file value into a command parameter.

The SSL_CONF_parse_cmd_lines function parses an array of strings lines, each representing a command line, and applies them to the given ctx. The flags parameter can be used to modify behaviour. The seen parameter is an optional pointer to an unsigned int which will be filled with a bitmask of commands that were successfully processed.

The SSL_CONF_set1_conf and SSL_CONF_set_conf functions allow the configuration of an SSL_CTX to be set from a CONF structure. The former takes a copy of the CONF structure, while the latter uses the provided one directly. The caller is responsible for managing the lifetime of the CONF structure.

The SSL_CONF_use_certificate, SSL_CONF_use_key, SSL_CONF_use_certificate_chain, and SSL_CONF_use_pkcs12 functions are convenience functions for loading certificates and keys. They are equivalent to calling SSL_CONF_cmd with the appropriate command name and value.

The SSL_CONF_use_ciphers function sets the cipher list for the SSL_CTX. The format of the cipher string is documented in ciphers(5).

The SSL_CONF_use_curve function sets the curve name for the SSL_CTX.

The SSL_CONF_use_disk function sets the directory for storing session data.

The SSL_CONF_warn function is intended for internal use and can be used to issue warnings about commands that are not recognised or have no effect.

NOTES

The functions SSL_CONF_cmd, SSL_CONF_use_certificate, SSL_CONF_use_key, SSL_CONF_use_certificate_chain, SSL_CONF_use_pkcs12, SSL_CONF_use_ciphers, SSL_CONF_use_curve, SSL_CONF_use_disk, and SSL_CONF_warn are not thread-safe when operating on the same SSL_CTX. They should not be called concurrently from multiple threads.

The command names are case-insensitive.

The SSL_CONF_cmd function processes commands and their values. The value parameter is interpreted according to the command type.

The SSL_OP_NO_SSL2 option is deprecated and has no effect since OpenSSL 1.1.0.

The UnsafeLegacyServerConnect option is no longer set by default from OpenSSL 3.0.

The TxCertificateCompression and RxCertificateCompression options were added in OpenSSL 3.2.

PreferNoDHEKEX was added in OpenSSL 3.3.

OpenSSL 3.5 introduces support for post-quantum (PQ) TLS key exchange via the MLKEM512, MLKEM768 and MLKEM1024 TLS groups. These are based on the underlying ML-KEM-512, ML-KEM-768 and ML-KEM-1024 algorithms from FIPS 203.

OpenSSL 3.5 also introduces support for three hybrid ECDH PQ key exchange TLS groups: X25519MLKEM768, SecP256r1MLKEM768 and SecP384r1MLKEM1024. They offer CPU performance comparable to the associated ECDH group, though at the cost of significantly larger key exchange messages. The third group, SecP384r1MLKEM1024 is substantially more CPU-intensive, largely as a result of the high CPU cost of ECDH for the underlying P-384 group. Also its key exchange messages at close to 1700 bytes are larger than the roughly 1200 bytes for the first two groups.

As of OpenSSL 3.5 key exchange group names are case-insensitive.

RETURN VALUES

The configuration functions return 1 on success and 0 or a negative value on failure. The specific error codes are not defined, but checking for a return value of 1 is sufficient.

EXAMPLES

Set the cipher list and certificate file for an SSL_CTX:

SSL_CTX *ctx;
int ret;

ctx = SSL_CTX_new(TLS_server_method());
if (ctx == NULL)
    /* Handle error */

ret = SSL_CONF_cmd(ctx, "CipherString", "DEFAULT:@SECLEVEL=2");
if (ret <= 0) {
    fprintf(stderr, "Error setting cipher string\n");
    /* Handle error */
}

ret = SSL_CONF_cmd(ctx, "CertFile", "/path/to/cert.pem");
if (ret <= 0) {
    fprintf(stderr, "Error setting certificate file\n");
    /* Handle error */
}

ret = SSL_CONF_cmd(ctx, "KeyFile", "/path/to/key.pem");
if (ret <= 0) {
    fprintf(stderr, "Error setting key file\n");
    /* Handle error */
}

Parse commands from an array of strings:

SSL_CTX *ctx;
char *cmds[] = {
    "CipherString:DEFAULT:@SECLEVEL=2",
    "CertFile=/path/to/cert.pem",
    "KeyFile=/path/to/key.pem"
};
int ret;

ctx = SSL_CTX_new(TLS_server_method());
if (ctx == NULL)
    /* Handle error */

ret = SSL_CONF_parse_cmd_lines(ctx, cmds, OSSL_NELEM(cmds), 0, NULL);
if (ret <= 0) {
    fprintf(stderr, "Error parsing command lines\n");
    /* Handle error */
}
