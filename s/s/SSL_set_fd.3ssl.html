SSL_set_fd(3ssl)

Paquete: openssl

Licencias: Apache-2.0

SSL_SET_FD(3ssl) OpenSSL SSL_SET_FD(3ssl)

NOMBRE

SSL_set_fd, SSL_set_rfd, SSL_set_wfd - conectar el objeto SSL con un descriptor de archivo

SINOPSIS

#include <openssl/ssl.h>
int SSL_set_fd(SSL *ssl, int fd);
int SSL_set_rfd(SSL *ssl, int fd);
int SSL_set_wfd(SSL *ssl, int fd);

DESCRIPCIÓN

SSL_set_fd() establece el descriptor de archivo fd como la instalación de entrada/salida para el lado TLS/SSL (cifrado) de ssl. fd típicamente será el descriptor de archivo del socket de una conexión de red.

Al realizar la operación, se crea automáticamente un BIO de socket para la interfaz entre ssl y fd. El BIO y, por lo tanto, el motor SSL heredan el comportamiento de fd. Si fd no es bloqueante, el ssl también tendrá un comportamiento no bloqueante.

Cuando se utiliza en un objeto SSL de conexión QUIC, se crea automáticamente un BIO de datagrama en lugar de un BIO de socket. Estas funciones fallan si se llaman en un objeto SSL de flujo QUIC.

Si ya había un BIO conectado a ssl, se llamará a BIO_free() (tanto para el lado de lectura como para el de escritura, si son diferentes).

SSL_set_rfd() y SSL_set_wfd() realizan la acción respectiva, pero solo para el canal de lectura o el canal de escritura, que pueden configurarse de forma independiente.

VALORES DE RETORNO

Los siguientes valores de retorno pueden ocurrir:

0
La operación falló. Compruebe la pila de errores para averiguar por qué.
1
La operación tuvo éxito.

NOTAS

En Windows, un manejador de socket es un tipo de dato de 64 bits (UINT_PTR), lo que provoca una advertencia del compilador (conversión de 'SOCKET' a 'int', posible pérdida de datos) al pasar el manejador de socket a SSL_set_*fd(). Por el momento, esta advertencia se puede ignorar de forma segura, porque aunque la documentación de Microsoft afirma que el límite superior es INVALID_SOCKET-1 (2^64 - 2), en la práctica la implementación actual de socket() devuelve un índice en la tabla de manejadores del kernel, cuyo tamaño está limitado a 2^24.
