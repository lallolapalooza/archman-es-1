DESCRIPCIÓN

SSL_CTX_new_ex() crea un nuevo objeto SSL_CTX, que contiene varias configuraciones y datos relevantes para el establecimiento de sesiones SSL/TLS o DTLS. Estos son heredados posteriormente por el objeto SSL que representa una sesión activa. El parámetro method especifica si el contexto se usará para el lado del cliente, del servidor o ambos; para más detalles, véase la sección "NOTAS" más abajo. El contexto de biblioteca libctx (véase OSSL_LIB_CTX(3)) se usa para proporcionar los algoritmos criptográficos necesarios para la sesión. Cualquier algoritmo criptográfico utilizado por los objetos SSL creados a partir de este SSL_CTX se obtendrá de libctx utilizando la cadena de consulta de propiedades propq (véase "ALGORITHM FETCHING" en crypto(7). Los parámetros libctx o propq, o ambos, pueden ser NULL.

SSL_CTX_new() hace lo mismo que SSL_CTX_new_ex() excepto que se utiliza el contexto de biblioteca predeterminado y no se especifica ninguna cadena de consulta de propiedades.

Un objeto SSL_CTX tiene un contador de referencias. Crear un objeto SSL_CTX por primera vez incrementa el contador de referencias. Liberar el SSL_CTX (usando SSL_CTX_free) lo decrementa. Cuando el contador de referencias llega a cero, se liberan la memoria o los recursos asignados al objeto SSL_CTX. SSL_CTX_up_ref() incrementa el contador de referencias de una estructura SSL_CTX existente.

Un objeto SSL_CTX no debe modificarse después de usarse para crear ningún objeto SSL o desde múltiples hilos simultáneamente, ya que la implementación no proporciona serialización de acceso para estos casos.

NOTAS

En el establecimiento de la sesión, por defecto, no se realiza ninguna verificación de credenciales del par. Esto debe solicitarse explícitamente, normalmente usando SSL_CTX_set_verify(3). Para verificar certificados del par, se pueden configurar muchas opciones usando varias funciones como SSL_CTX_load_verify_locations(3) y SSL_CTX_set1_param(3).

La implementación SSL/(D)TLS utiliza la función X509_STORE_CTX_set_default(3) para preparar las comprobaciones para X509_PURPOSE_SSL_SERVER en el lado del cliente y X509_PURPOSE_SSL_CLIENT en el lado del servidor. La función X509_VERIFY_PARAM_set_purpose(3) puede usarse, también en conjunción con SSL_CTX_get0_param(3), para anular el propósito por defecto de la sesión.

El objeto SSL_CTX utiliza method como método de conexión. Hay tres variantes de método disponibles: un método genérico (para uso del cliente o del servidor), un método solo para servidor y un método solo para cliente.

El parámetro method de SSL_CTX_new_ex() y SSL_CTX_new() puede ser uno de los siguientes:

TLS_method(), TLS_server_method(), TLS_client_method()
Estos son los métodos SSL/TLS de propósito general y flexibles en versión. La versión real del protocolo utilizada se negociará a la versión más alta soportada mutuamente por el cliente y el servidor. Los protocolos soportados son SSLv3, TLSv1, TLSv1.1, TLSv1.2 y TLSv1.3. Las aplicaciones deben usar estos métodos y evitar los métodos específicos de versión descritos a continuación, que están obsoletos.
SSLv23_method(), SSLv23_server_method(), SSLv23_client_method()
Estas funciones ya no existen; han sido renombradas a TLS_method(), TLS_server_method() y TLS_client_method() respectivamente. Actualmente, las llamadas a funciones antiguas se renombran a las correspondientes nuevas mediante macros de preprocesador, para garantizar que el código existente que utiliza los nombres de funciones antiguas todavía se compila. Sin embargo, el uso de los nombres de funciones antiguas está obsoleto y el código nuevo debería llamar a las nuevas funciones en su lugar.
TLSv1_2_method(), TLSv1_2_server_method(), TLSv1_2_client_method()
Una conexión TLS/SSL establecida con estos métodos solo entenderá el protocolo TLSv1.2. Estos métodos están obsoletos.
TLSv1_1_method(), TLSv1_1_server_method(), TLSv1_1_client_method()
Una conexión TLS/SSL establecida con estos métodos solo entenderá el protocolo TLSv1.1. Estos métodos están obsoletos.
TLSv1_method(), TLSv1_server_method(), TLSv1_client_method()
Una conexión TLS/SSL establecida con estos métodos solo entenderá el protocolo TLSv1. Estos métodos están obsoletos.
SSLv3_method(), SSLv3_server_method(), SSLv3_client_method()
Una conexión TLS/SSL establecida con estos métodos solo entenderá el protocolo SSLv3. El protocolo SSLv3 está obsoleto y no debe usarse.
DTLS_method(), DTLS_server_method(), DTLS_client_method()
Estos son los métodos DTLS flexibles en versión. Los protocolos actualmente soportados son DTLS 1.0 y DTLS 1.2.
DTLSv1_2_method(), DTLSv1_2_server_method(), DTLSv1_2_client_method()
Estos son los métodos específicos de versión para DTLSv1.2. Estos métodos están obsoletos.
DTLSv1_method(), DTLSv1_server_method(), DTLSv1_client_method()
Estos son los métodos específicos de versión para DTLSv1. Estos métodos están obsoletos.

SSL_CTX_new() inicializa la lista de cifradores, la configuración de la caché de sesiones, las devoluciones de llamada, las claves y los certificados, y las opciones a sus valores predeterminados.

TLS_method(), TLS_server_method(), TLS_client_method(), DTLS_method(), DTLS_server_method() y DTLS_client_method() son los métodos flexibles en versión. Todos los demás métodos solo soportan una versión específica del protocolo. Use los métodos flexibles en versión

SSL_CTX_new(3ssl) — Manual de OpenSSL

NOMBRE

SSL_CTX_new, SSL_CTX_new_ex - crear un contexto SSL/TLS

SINOPSIS

#include <openssl/ssl.h>

SSL_CTX *SSL_CTX_new(const SSL_METHOD *meth);
SSL_CTX *SSL_CTX_new_ex(const SSL_METHOD *meth, STACK_OF(OPENSSL_STRING) *callbacks);

DESCRIPCIÓN

La función SSL_CTX_new() asigna y devuelve un objeto SSL_CTX, que contiene diversas configuraciones que son comunes a todas las conexiones SSL/TLS creadas a partir de él. El parámetro meth especifica los métodos SSL/TLS que se utilizarán y cómo deben configurarse. En la actualidad, los métodos siguientes están disponibles:

  • SSLv23_method(), SSLv23_server_method() y SSLv23_client_method(): Estos métodos permiten la negociación automática del protocolo SSL/TLS y se utilizan para admitir tanto SSLv3 como TLSv1.x y versiones posteriores. El sufijo indica si el método se utiliza para un servidor, un cliente o para un uso genérico (negociación).
  • TLS_method(), TLS_server_method() y TLS_client_method(): Estos métodos son los métodos preferidos en OpenSSL 1.1.0 y versiones posteriores. Son similares a SSLv23_method, SSLv23_server_method y SSLv23_client_method, pero excluyen implícitamente los protocolos anteriores a TLSv1.0. El comportamiento exacto se define mediante las opciones SSL_CTX_set_options.
  • SSLv3_method(), SSLv3_server_method() y SSLv3_client_method(): Estos métodos solo admiten el protocolo SSLv3. Ya no se recomiendan y su uso puede ser un riesgo de seguridad.
  • TLSv1_method(), TLSv1_server_method() y TLSv1_client_method(): Estos métodos solo admiten el protocolo TLSv1.0.
  • TLSv1_1_method(), TLSv1_1_server_method() y TLSv1_1_client_method(): Estos métodos solo admiten el protocolo TLSv1.1.
  • TLSv1_2_method(), TLSv1_2_server_method() y TLSv1_2_client_method(): Estos métodos solo admiten el protocolo TLSv1.2.
  • TLSv1_3_method(), TLSv1_3_server_method() y TLSv1_3_client_method(): Estos métodos solo admiten el protocolo TLSv1.3.

En OpenSSL 1.1.0 y versiones posteriores, los métodos que anteriormente admitían varios protocolos (por ejemplo, SSLv23_method) se han modificado para que tengan un comportamiento predeterminado más seguro. En particular, los métodos TLS_method, TLS_server_method y TLS_client_method deshabilitan implícitamente SSLv2, SSLv3 y TLSv1.0. Los métodos SSLv23_* todavía negocian entre SSLv3 y TLSv1.x, pero ya no intentan negociar SSLv2. Todos los métodos específicos de versión (por ejemplo, TLSv1_2_method) siguen funcionando como antes, pero se desaconsejan en favor de los métodos TLS_method* junto con la configuración de opciones apropiada.

La función SSL_CTX_new_ex() es una extensión para permitir la configuración de callbacks específicos. Los callbacks se pasan en un STACK_OF(OPENSSL_STRING) y se utilizan para personalizar el comportamiento del contexto SSL/TLS.

Después de crear un contexto SSL_CTX, puedes configurarlo adicionalmente con varias funciones, como SSL_CTX_set_min_proto_version(3), SSL_CTX_set_max_proto_version(3), SSL_CTX_set_options(3), SSL_CTX_use_certificate_file(3), SSL_CTX_use_PrivateKey_file(3), etc.

Una vez que hayas terminado con el objeto SSL_CTX, debes liberarlo con SSL_CTX_free(3).

NOTAS

La funcionalidad específica de SSLv2 se eliminó en OpenSSL 1.1.0. Los métodos SSLv2_method, SSLv2_server_method y SSLv2_client_method ya no están disponibles. Los métodos SSLv23_* ya no intentan negociar SSLv2.

Se recomienda usar los métodos TLS_method, TLS_server_method y TLS_client_method en lugar de los métodos SSLv23_* si el soporte para SSLv3 no es estrictamente necesario. Estos métodos excluyen implícitamente SSLv2, SSLv3 y TLSv1.0, lo que proporciona un comportamiento predeterminado más seguro.

Si deseas limitar los protocolos admitidos para los métodos flexibles de versión, puedes utilizar las funciones SSL_CTX_set_min_proto_version(3), SSL_set_min_proto_version(3), SSL_CTX_set_max_proto_version(3) y SSL_set_max_proto_version(3). Usando estas funciones es posible elegir, por ejemplo, TLS_server_method() y poder negociar con todos los clientes posibles, pero permitiendo solo protocolos más nuevos como TLS 1.0, TLS 1.1, TLS 1.2 o TLS 1.3.

La lista de protocolos disponibles también se puede limitar utilizando las opciones SSL_OP_NO_SSLv3, SSL_OP_NO_TLSv1, SSL_OP_NO_TLSv1_1, SSL_OP_NO_TLSv1_3, SSL_OP_NO_TLSv1_2 y SSL_OP_NO_TLSv1_3 de las funciones SSL_CTX_set_options(3) o SSL_set_options(3), pero este enfoque no se recomienda. Los clientes deben evitar crear "huecos" en el conjunto de protocolos que admiten. Al deshabilitar un protocolo, asegúrate de deshabilitar también todos los protocolos anteriores o todos los protocolos posteriores. En los clientes, cuando se deshabilita una versión de protocolo sin deshabilitar *todas* las versiones de protocolo anteriores, el efecto es deshabilitar también todas las versiones de protocolo posteriores.

El protocolo SSLv3 está obsoleto y, en general, no debe utilizarse. Las aplicaciones normalmente deberían usar SSL_CTX_set_min_proto_version(3) para establecer el protocolo mínimo en al menos TLS1_VERSION.

VALORES DEVUELTOS

NULL
Falló la creación de un nuevo objeto SSL_CTX. Comprueba la pila de errores para averiguar el motivo.
Puntero a un objeto SSL_CTX
El valor devuelto apunta a un objeto SSL_CTX asignado.

SSL_CTX_up_ref() devuelve 1 para éxito y 0 para fallo.

VER TAMBIÉN

SSL_CTX_set_options(3), SSL_CTX_free(3), X509_STORE_CTX_set_default(3), SSL_CTX_set_verify(3), SSL_CTX_set1_param(3), SSL_CTX_get0_param(3), SSL_connect(3), SSL_accept(3), SSL_CTX_set_min_proto_version(3), ssl(7), SSL_set_connect_state(3)

HISTORIA

El soporte para SSLv2 y los correspondientes métodos SSLv2_method(), SSLv2_server_method() y SSLv2_client_method() se eliminaron en OpenSSL 1.1.0.

SSLv23_method(), SSLv23_server_method() y SSLv23_client_method() fueron marcados como obsoletos y se añadieron los métodos preferidos TLS_method(), TLS_server_method() y TLS_client_method() en OpenSSL 1.1.0.

Todos los métodos específicos de versión fueron marcados como obsoletos en OpenSSL 1.1.0.

SSL_CTX_new_ex() se añadió en OpenSSL 3.0.
