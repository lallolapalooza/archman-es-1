SSL_CTX_set_cert_cb(3ssl)

Paquete: openssl

Licencias: Apache-2.0

SSL_CTX_SET_CERT_CB(3ssl) OpenSSL SSL_CTX_SET_CERT_CB(3ssl)

NOMBRE

SSL_CTX_set_cert_cb, SSL_set_cert_cb - maneja la función de devolución de llamada de certificado

SINOPSIS

#include <openssl/ssl.h>
void SSL_CTX_set_cert_cb(SSL_CTX *c, int (*cert_cb)(SSL *ssl, void *arg),
                         void *arg);
void SSL_set_cert_cb(SSL *s, int (*cert_cb)(SSL *ssl, void *arg), void *arg);

DESCRIPCIÓN

SSL_CTX_set_cert_cb() y SSL_set_cert_cb() establecen la función de devolución de llamada cert_cb, el valor arg es un puntero que se pasa a la devolución de llamada de la aplicación.

Cuando cert_cb es NULL, no se utiliza ninguna función de devolución de llamada.

cert_cb es la devolución de llamada definida por la aplicación. Se llama antes de que un certificado sea utilizado por un cliente o servidor. La devolución de llamada puede entonces inspeccionar la estructura ssl pasada y establecer o borrar cualquier certificado apropiado. Si la devolución de llamada es exitosa, **DEBE** devolver 1 incluso si no se han establecido certificados. Se devuelve un cero en caso de error, lo que abortará el handshake con una alerta de error interno fatal. Un valor de retorno negativo suspenderá el handshake y la función de handshake devolverá inmediatamente. SSL_get_error(3) devolverá SSL_ERROR_WANT_X509_LOOKUP para indicar que el handshake fue suspendido. La próxima llamada a la función de handshake volverá a llamar a cert_cb. Es trabajo de cert_cb almacenar información sobre el estado de la última llamada, si es necesario continuar.

NOTAS

Una aplicación normalmente llamará a SSL_use_certificate() y SSL_use_PrivateKey() para establecer el certificado de entidad final y la clave privada. Puede agregar certificados intermedios y opcionalmente de la CA raíz usando SSL_add1_chain_cert().

También puede llamar a SSL_certs_clear() para eliminar cualquier certificado asociado con el objeto SSL.

La funcionalidad de devolución de llamada de certificado reemplaza la funcionalidad (en gran parte rota) proporcionada por la antigua interfaz de devolución de llamada de certificado de cliente. Se llama **SIEMPRE** incluso si ya está establecido un certificado, por lo que la devolución de llamada puede modificar o eliminar el certificado existente.

Una devolución de llamada más avanzada podría examinar los parámetros del handshake y establecer la cadena apropiada. Por ejemplo, un cliente heredado que solo soporta TLSv1.0 podría recibir una cadena de certificados firmada usando SHA1, mientras que un cliente TLSv1.2 o posterior que anuncie soporte para SHA256 podría recibir una cadena usando SHA256.

Se realizan comprobaciones de seguridad normales en cualquier certificado establecido por la devolución de llamada. Por lo tanto, si se establece una cadena EC para una curva que el cliente no soporta, **NO** se usará.

VALORES DE RETORNO

SSL_CTX_set_cert_cb() y SSL_set_cert_cb() no devuelven valores.
