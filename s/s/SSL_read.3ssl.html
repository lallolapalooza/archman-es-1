SSL_read(3ssl)

Paquete: openssl

Licencias: Apache-2.0

SSL_READ(3ssl) OpenSSL SSL_READ(3ssl)

NOMBRE

SSL_read_ex, SSL_read, SSL_peek_ex, SSL_peek - leer bytes de una conexión TLS/SSL

SINOPSIS

#include <openssl/ssl.h>
int SSL_read_ex(SSL *ssl, void *buf, size_t num, size_t *readbytes);
int SSL_read(SSL *ssl, void *buf, int num);
int SSL_peek_ex(SSL *ssl, void *buf, size_t num, size_t *readbytes);
int SSL_peek(SSL *ssl, void *buf, int num);

DESCRIPCIÓN

SSL_read_ex() y SSL_read() intentan leer num bytes de ssl especificado en el búfer buf. En caso de éxito, SSL_read_ex() almacenará el número de bytes realmente leídos en *readbytes.

SSL_peek_ex() y SSL_peek() son idénticos a SSL_read_ex() y SSL_read() respectivamente, excepto que no se eliminan bytes del BIO subyacente durante la lectura, de modo que una llamada posterior a SSL_read_ex() o SSL_read() devolverá al menos los mismos bytes.

NOTAS

En los párrafos siguientes, una "función de lectura" se define como una de SSL_read_ex(), SSL_read(), SSL_peek_ex() o SSL_peek().

Si es necesario, una función de lectura negociará una sesión TLS/SSL, si no se realizó explícitamente mediante SSL_connect(3) o SSL_accept(3). Si el par solicita una renegociación, se realizará de forma transparente durante la operación de la función de lectura. El comportamiento de las funciones de lectura depende del BIO subyacente.

Para que la negociación transparente tenga éxito, el ssl debe haber sido inicializado en modo cliente o servidor. Esto se hace llamando a SSL_set_connect_state(3) o SSL_set_accept_state() antes de la primera invocación de una función de lectura.

Las funciones de lectura funcionan basándose en los registros SSL/TLS. Los datos se reciben en registros (con un tamaño máximo de registro de 16 kB). Solo cuando se ha recibido completamente un registro, se puede procesar (descifrado y comprobación de integridad). Por lo tanto, los datos que no se recuperaron en la última llamada de lectura aún pueden estar almacenados en búfer dentro de la capa SSL y se recuperarán en la próxima llamada de lectura. Si num es mayor que el número de bytes almacenados en búfer, las funciones de lectura devolverán los bytes almacenados en búfer. Si no hay más bytes en el búfer, las funciones de lectura activarán el procesamiento del siguiente registro. Solo cuando el registro se haya recibido y procesado completamente, las funciones de lectura devolverán indicando éxito. Se devolverá como máximo el contenido de un registro. Dado que el tamaño de un registro SSL/TLS puede superar el tamaño máximo del paquete de la capa subyacente (por ejemplo, TCP), puede ser necesario leer varios paquetes de la capa de transporte antes de que el registro esté completo y la llamada de lectura pueda tener éxito.

Si SSL_MODE_AUTO_RETRY se ha desactivado y se ha procesado un registro que no son datos de aplicación, la función de lectura puede devolver y establecer el error en SSL_ERROR_WANT_READ. En este caso, todavía puede haber datos sin procesar disponibles en el BIO. Si la lectura anticipada se estableció mediante SSL_CTX_set_read_ahead(3), también puede haber datos sin procesar disponibles en el SSL. Este comportamiento se puede controlar mediante la llamada a SSL_CTX_set_mode(3).

Si el BIO subyacente es de bloqueo, una función de lectura solo devolverá una vez que la operación de lectura se haya completado o se haya producido un error, excepto cuando se ha procesado un registro que no son datos de aplicación y SSL_MODE_AUTO_RETRY no está establecido. Tenga en cuenta que si SSL_MODE_AUTO_RETRY está establecido y solo hay disponibles datos que no son de aplicación, la llamada se colgará.

Si el BIO subyacente es de no bloqueo, una función de lectura también devolverá cuando el BIO subyacente no pudo satisfacer las necesidades de la función para continuar la operación. En este caso, una llamada a SSL_get_error(3) con el valor de retorno de la función de lectura generará SSL_ERROR_WANT_READ o SSL_ERROR_WANT_WRITE. Dado que en cualquier momento es posible que se necesiten enviar datos que no son de aplicación, una función de lectura también puede provocar operaciones de escritura. El proceso de llamada debe repetir la llamada después de tomar las medidas adecuadas para satisfacer las necesidades de la función de lectura. La acción depende del BIO subyacente. Al utilizar un socket de no bloqueo, no hay nada que hacer, pero se puede usar select() para comprobar la condición requerida. Al utilizar un BIO de búfer, como un par de BIO, los datos deben escribirse o recuperarse del BIO antes de poder continuar.

SSL_pending(3) se puede utilizar para saber si hay bytes en búfer disponibles para su recuperación inmediata. En este caso, la función de lectura se puede llamar sin bloquear o sin recibir realmente nuevos datos del socket subyacente.

Cuando se utiliza con un objeto SSL QUIC, llamar a una función de E/S como SSL_read() permite que se realicen operaciones de eventos de red internas. Es importante que este procesamiento se realice regularmente. Si una aplicación no está utilizando el modo asistido por hilos, una aplicación debe asegurarse de que una función de E/S como SSL_read() se llame regularmente, o alternativamente asegurarse de que SSL_handle_events() se llame regularmente. Consulte openssl-quic(7) y SSL_handle_events(3) para obtener más información.

VALORES DE RETORNO

SSL_read_ex() y SSL_peek_ex() devolverán 1 para el éxito o 0 para el fracaso. Éxito significa que se han leído 1 o más bytes de datos de aplicación de la conexión SSL. Fracaso significa que no se pudieron leer bytes de la conexión SSL. Los fallos pueden ser reintentables (por ejemplo, estamos esperando más bytes que entregar por la red) o no reintentables (por ejemplo, un error fatal de red). En caso de fallo, llame a SSL_get_error(3) para averiguar el motivo, que indica si la llamada es reintentable o no.

Para SSL_read() y SSL_peek(), pueden ocurrir los siguientes valores de retorno:

> 0
La operación de lectura fue exitosa. El valor de retorno es el número de bytes leídos de la conexión TLS/SSL.
<= 0
La operación de lectura no fue exitosa, ya sea porque la conexión se cerró, se produjo un error o el proceso de llamada debe tomar medidas. Llame a SSL_get_error(3) con el valor de retorno ret para averiguar el motivo.

La documentación anterior indicaba una diferencia entre 0 y -1, y que -1 era reintentable. En su lugar, debe llamar a SSL_get_error() para averiguar si es reintentable.
