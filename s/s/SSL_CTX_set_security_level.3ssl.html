                                                 void *other, void *ex));

DESCRIPCIÓN

Las funciones SSL_CTX_set_security_level() y SSL_set_security_level() establecen el nivel de seguridad a level. Si no se establece, se utiliza el nivel de seguridad predeterminado de la biblioteca.

Las funciones SSL_CTX_get_security_level() y SSL_get_security_level() recuperan el nivel de seguridad actual.

SSL_CTX_set_security_callback(), SSL_set_security_callback(), SSL_CTX_get_security_callback() y SSL_get_security_callback() obtienen o establecen la llamada de retorno de seguridad asociada con ctx o s. Si no se establece, se utiliza una llamada de retorno de seguridad predeterminada. El significado de los parámetros y el comportamiento de las llamadas de retorno predeterminadas se describe a continuación.

SSL_CTX_set0_security_ex_data(), SSL_set0_security_ex_data(), SSL_CTX_get0_security_ex_data() y SSL_get0_security_ex_data() establecen el puntero de datos adicionales pasado al parámetro ex de la llamada de retorno. Este valor se pasa a la llamada de retorno tal cual y puede establecerse en cualquier valor útil específico de la aplicación.

COMPORTAMIENTO PREDETERMINADO DE LA LLAMADA DE RETORNO

Si una aplicación no establece su propia llamada de retorno de seguridad, se utiliza la llamada de retorno predeterminada. Está destinada a proporcionar valores predeterminados sensatos. El significado de cada nivel se describe a continuación.

Nivel 0
Todo está permitido. Esto mantiene la compatibilidad con versiones anteriores de OpenSSL.
Nivel 1
El nivel de seguridad corresponde a un mínimo de 80 bits de seguridad. Se excluyen los parámetros que ofrecen menos de 80 bits de seguridad. Como resultado, se prohíben las claves RSA, DSA y DH de menos de 1024 bits y las claves ECC de menos de 160 bits. También se prohíben las suites de cifrado que utilizan MD5 para la MAC. También se prohíben las suites de cifrado que utilizan CCM con una etiqueta de autenticación de 64 bits. Tenga en cuenta que las firmas que utilizan SHA1 y MD5 también están prohibidas en este nivel, ya que tienen menos de 80 bits de seguridad. Además, SSLv3, TLS 1.0, TLS 1.1 y DTLS 1.0 están deshabilitados en este nivel.
Nivel 2
Nivel de seguridad establecido en 112 bits de seguridad. Como resultado, se prohíben las claves RSA, DSA y DH de menos de 2048 bits y las claves ECC de menos de 224 bits. Además de las exclusiones del nivel 1, se prohíbe cualquier suite de cifrado que utilice RC4. La compresión está deshabilitada.
Nivel 3
Nivel de seguridad establecido en 128 bits de seguridad. Como resultado, se prohíben las claves RSA, DSA y DH de menos de 3072 bits y las claves ECC de menos de 256 bits. Además de las exclusiones del nivel 2, se prohíben las suites de cifrado que no ofrecen secreto directo (forward secrecy). Las entradas de sesión están deshabilitadas.
Nivel 4
Nivel de seguridad establecido en 192 bits de seguridad. Como resultado, se prohíben las claves RSA, DSA y DH de menos de 7680 bits y las claves ECC de menos de 384 bits. Se prohíben las suites de cifrado que utilizan SHA1 para la MAC.
Nivel 5
Nivel de seguridad establecido en 256 bits de seguridad. Como resultado, se prohíben las claves RSA, DSA y DH de menos de 15360 bits y las claves ECC de menos de 512 bits.

NOTAS

El nivel de seguridad predeterminado se puede configurar al compilar OpenSSL estableciendo -DOPENSSL_TLS_SECURITY_LEVEL=level. Si no se establece, se utiliza 2.

El framework de seguridad deshabilita o rechaza parámetros inconsistentes con el nivel de seguridad establecido. En el pasado, esto era difícil ya que las aplicaciones tenían que establecer una serie de parámetros distintos (cifrados admitidos, curvas admitidas, algoritmos de firma admitidos) para lograr este fin y algunos casos (tamaño de parámetros DH, por ejemplo) no se podían verificar en absoluto.

Al establecer un nivel de seguridad apropiado, se puede evitar gran parte de esta complejidad.

Los límites de bits de seguridad afectan a todos los parámetros relevantes, incluidos los algoritmos de cifrado de suites de cifrado, las curvas ECC admitidas, los algoritmos de firma admitidos, los tamaños de parámetros DH, los tamaños de claves de certificado y los algoritmos de firma. Este límite se aplica sin importar otras configuraciones personalizadas que haya establecido una aplicación; por lo tanto, si la suite de cifrado se establece en ALL, solo se permiten las suites de cifrado consistentes con el nivel de seguridad.

Consulte SP800-57 para ver cómo se relacionan los límites de seguridad con algoritmos individuales.

Algunos niveles de seguridad requieren tamaños de clave grandes para algoritmos de clave pública que no son ECC, lo que puede degradar gravemente el rendimiento. Por ejemplo, 256 bits de seguridad requieren el uso de claves RSA de al menos 15360 bits de tamaño.

Algunas restricciones se pueden manejar sin problemas: por ejemplo, las suites de cifrado que ofrecen seguridad insuficiente no son enviadas por el cliente y no serán seleccionadas por el servidor. Otras restricciones, como el tamaño de la clave del certificado del par o el tamaño del parámetro DH, abortarán el handshake con una alerta fatal.

Los intentos de establecer certificados o parámetros con seguridad insuficiente también se bloquean. Por ejemplo, intentar establecer un certificado que utiliza una clave RSA de 512 bits o un certificado con una firma con un resumen SHA1 en el nivel 1 mediante SSL_CTX_use_certificate(). Las aplicaciones que no comprueban los valores de retorno de error se comportarán de forma incorrecta: por ejemplo, podría parecer que un certificado no se ha establecido en absoluto porque había sido rechazado.

VALORES DE RETORNO

SSL_CTX_set_security_level() y SSL_set_security_level() no devuelven valores.

SSL_CTX_get_security_level() y SSL_get_security_level() devuelven un entero que representa el nivel de seguridad con SSL_CTX o SSL, respectivamente.

SSL_CTX_set_security_callback() y SSL_set_security_callback() no devuelven valores.

SSL_CTX_get_security_callback() y SSL_get_security_callback() devuelven el puntero a la llamada de retorno de seguridad o NULL si la llamada de retorno no está establecida.

SSL_CTX_get0_security_ex_data() y SSL_get0_security_ex_data() devuelven el puntero de datos adicionales o NULL si los datos ex no están establecidos.
