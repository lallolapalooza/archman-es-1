SSL_CTX_set_split_send_fragment(3ssl)

Paquete: openssl

Licencias: Apache-2.0

SSL_CTX_SET_SPLIT_SEND_FRAGMENT(3ssl) OpenSSL SSL_CTX_SET_SPLIT_SEND_FRAGMENT(3ssl)

NOMBRE

SSL_CTX_set_max_send_fragment, SSL_set_max_send_fragment, SSL_CTX_set_split_send_fragment, SSL_set_split_send_fragment, SSL_CTX_set_max_pipelines, SSL_set_max_pipelines, SSL_CTX_set_default_read_buffer_len, SSL_set_default_read_buffer_len, SSL_CTX_set_tlsext_max_fragment_length, SSL_set_tlsext_max_fragment_length, SSL_SESSION_get_max_fragment_length - Controlar la configuración del tamaño del fragmento y las operaciones de pipelining

SINOPSIS

#include <openssl/ssl.h>
long SSL_CTX_set_max_send_fragment(SSL_CTX *ctx, long);
long SSL_set_max_send_fragment(SSL *ssl, long m);
long SSL_CTX_set_max_pipelines(SSL_CTX *ctx, long m);
long SSL_set_max_pipelines(SSL_CTX *ssl, long m);
long SSL_CTX_set_split_send_fragment(SSL_CTX *ctx, long m);
long SSL_set_split_send_fragment(SSL *ssl, long m);
void SSL_CTX_set_default_read_buffer_len(SSL_CTX *ctx, size_t len);
void SSL_set_default_read_buffer_len(SSL *s, size_t len);
int SSL_CTX_set_tlsext_max_fragment_length(SSL_CTX *ctx, uint8_t mode);
int SSL_set_tlsext_max_fragment_length(SSL *ssl, uint8_t mode);
uint8_t SSL_SESSION_get_max_fragment_length(const SSL_SESSION *session);

DESCRIPCIÓN

Algunos motores son capaces de procesar múltiples operaciones criptográficas simultáneas. Esta capacidad podría ser utilizada para paralelizar el procesamiento de una sola conexión. Por ejemplo, una sola escritura puede dividirse en múltiples registros y cada uno se cifra de forma independiente y en paralelo. Nota: esto solo funcionará en TLS1.1+. No hay soporte en SSLv3, TLSv1.0 o DTLS (cualquier versión). Esta capacidad se conoce como "pipelining" dentro de OpenSSL.

Para beneficiarse de la capacidad de pipelining. Necesitas tener un motor que proporcione cifrados que soporten esto. El motor "dasync" de OpenSSL proporciona cifrados basados en AES128-SHA que tienen esta capacidad. Sin embargo, estos son solo para fines de desarrollo y prueba.

SSL_CTX_set_max_send_fragment() y SSL_set_max_send_fragment() establecen el parámetro max_send_fragment para los objetos SSL_CTX y SSL respectivamente. Este valor restringe la cantidad de bytes de texto plano que se enviarán en cualquier registro SSL/TLS. Por defecto, su valor es SSL3_RT_MAX_PLAIN_LENGTH (16384). Estas funciones solo aceptarán un valor en el rango de 512 a SSL3_RT_MAX_PLAIN_LENGTH.

SSL_CTX_set_max_pipelines() y SSL_set_max_pipelines() establecen el número máximo de pipelines que se utilizarán en un momento dado. Este valor se aplica tanto al pipelining de "lectura" como al de "escritura". Por defecto, solo se utilizará un pipeline (es decir, operación normal no paralela). El número de pipelines configurado debe estar en el rango de 1 a SSL_MAX_PIPELINES (32). Establecer este valor a un número mayor que 1 activará automáticamente la "lectura anticipada" (ver SSL_CTX_set_read_ahead(3)). Esto se explica con más detalle a continuación. OpenSSL solo usará más de un pipeline si se negocia una suite de cifrado que utiliza un cifrado capaz de pipeline proporcionado por un motor.

El pipelining opera de manera ligeramente diferente para leer datos cifrados que para escribir datos cifrados. SSL_CTX_set_split_send_fragment() y SSL_set_split_send_fragment() definen cómo se dividen los datos en pipelines al escribir datos cifrados. El número de pipelines utilizados se determinará por la cantidad de datos proporcionada a la llamada SSL_write_ex() o SSL_write() dividida por split_send_fragment.

Por ejemplo, si split_send_fragment se establece en 2000 y max_pipelines es 4:

SSL_write/SSL_write_ex llamado con 0-2000 bytes == 1 pipeline utilizado

SSL_write/SSL_write_ex llamado con 2001-4000 bytes == 2 pipelines utilizados

SSL_write/SSL_write_ex llamado con 4001-6000 bytes == 3 pipelines utilizados

SSL_write/SSL_write_ex llamado con 6001+ bytes == 4 pipelines utilizados

split_send_fragment debe ser siempre menor o igual a max_send_fragment. Por defecto, se establece para ser igual a max_send_fragment. Esto significará que siempre se crearán la misma cantidad de registros que se habrían creado en el caso no paralelo, aunque los datos se distribuirán de manera diferente. En el caso paralelo, los datos se repartirán por igual entre los pipelines.

El pipelining de lectura se controla de una manera ligeramente diferente que con el pipelining de escritura. Al leer, estamos limitados por la cantidad de registros que el par (y la red) pueden proporcionarnos de una vez. Cuantos más registros podamos obtener de una vez, más oportunidades tendremos de paralelizar el procesamiento. Como se señaló anteriormente, al establecer max_pipelines a un valor mayor que uno, se activa automáticamente la lectura anticipada. El parámetro read_ahead hace que OpenSSL intente leer tantos datos como sea posible en el búfer de lectura que la red pueda proporcionar y que quepa en el búfer. Sin esto, los datos se leen en el búfer de lectura un registro a la vez. Cuantos más datos se puedan leer, más oportunidades habrá para paralelizar el procesamiento a costa de un mayor uso de memoria por conexión. Establecer read_ahead puede afectar el comportamiento de la función SSL_pending() (ver SSL_pending(3)). Además, el tamaño por defecto del búfer de lectura interno se multiplica por el número de pipelines disponibles para asegurar que podamos leer múltiples registros de una vez. Por lo tanto, esto puede tener un impacto significativo en el uso de memoria.

Las funciones SSL_CTX_set_default_read_buffer_len() y SSL_set_default_read_buffer_len() controlan el tamaño del búfer de lectura que se utilizará. El parámetro len establece el tamaño del búfer. El valor solo se utilizará si es mayor que el valor predeterminado que se habría utilizado de todos modos. El valor predeterminado normal depende de varios factores, pero será de al menos SSL3_RT_MAX_PLAIN_LENGTH + SSL3_RT_MAX_ENCRYPTED_OVERHEAD (16704) bytes.

SSL_CTX_set_tlsext_max_fragment_length() establece el modo de negociación de longitud máxima de fragmento predeterminado a través del valor mode para ctx. Esta configuración afecta solo a las instancias SSL creadas después de que se llama a esta función. Afecta al lado del cliente, ya que solo su lado puede iniciar el uso de esta extensión.

SSL_set_tlsext_max_fragment_length() establece el modo de negociación de longitud máxima de fragmento a través del valor mode para ssl. Esta configuración se utilizará durante un handshake cuando se intercambien extensiones entre el cliente y el servidor. Por lo tanto, solo afecta a las sesiones SSL creadas después de que se llama a esta función. Afecta al lado del cliente, ya que solo su lado puede iniciar el uso de esta extensión.

SSL_SESSION_get_max_fragment_length() obtiene la longitud máxima del fragmento negociada en session.

Estas funciones no se pueden utilizar con objetos SSL QUIC. SSL_set_max_send_fragment(), SSL_set_max_pipelines(), SSL_set_split_send_fragment(), SSL_set_default_read_buffer_len() y SSL_set_tlsext_max_fragment_length() fallan si se llaman en un objeto SSL QUIC.

VALORES DE RETORNO

Todas las funciones que no son void devuelven 1 en caso de éxito y 0 en caso de fallo.

NOTAS

El soporte para la extensión de Longitud Máxima de Fragmento es opcional en el lado del servidor. Si el servidor no soporta esta extensión, SSL_SESSION_get_max_fragment_length() devolverá: TLSEXT_max_fragment_length_DISABLED.

Los siguientes modos están disponibles:

TLSEXT_max_fragment_length_DISABLED
Deshabilita la Negociación de Longitud Máxima de Fragmento (por defecto).
TLSEXT_max_fragment_length_512
Establece la Longitud Máxima de Fragmento a 512 bytes.
TLSEXT_max_fragment_length_1024
Establece la Longitud Máxima de Fragmento a 1024.
TLSEXT_max_fragment_length_2048
Establece la Longitud Máxima de Fragmento a 2048.
TLSEXT_max_fragment_length_4096
Establece la Longitud Máxima de Fragmento a 4096.

Con la excepción de SSL_CTX_set_default_read_buffer_len() SSL_set_default_read_buffer_len(), SSL_CTX_set_tlsext_max_fragment_length(), SSL_set_tlsext_max_fragment_length() y SSL_SESSION_get_max_fragment_length(), todas estas funciones se implementan utilizando macros.
