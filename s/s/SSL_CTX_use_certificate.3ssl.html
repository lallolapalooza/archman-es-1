NOMBRE

SSL_CTX_use_certificate, SSL_CTX_use_certificate_ASN1, SSL_CTX_use_certificate_file, SSL_use_certificate, SSL_use_certificate_ASN1, SSL_use_certificate_file, SSL_CTX_use_certificate_chain_file, SSL_use_certificate_chain_file, SSL_CTX_use_PrivateKey, SSL_CTX_use_PrivateKey_ASN1, SSL_CTX_use_PrivateKey_file, SSL_CTX_use_RSAPrivateKey, SSL_CTX_use_RSAPrivateKey_ASN1, SSL_CTX_use_RSAPrivateKey_file, SSL_use_PrivateKey_file, SSL_use_PrivateKey_ASN1, SSL_use_PrivateKey, SSL_use_RSAPrivateKey, SSL_use_RSAPrivateKey_ASN1, SSL_use_RSAPrivateKey_file, SSL_CTX_check_private_key, SSL_check_private_key, SSL_CTX_use_cert_and_key, SSL_use_cert_and_key - cargar datos de certificado y clave

int SSL_CTX_use_PrivateKey(SSL_CTX *ctx, EVP_PKEY *pkey);

DESCRIPCIÓN

Estas funciones cargan los certificados y claves privadas en el objeto SSL_CTX o en el objeto SSL, respectivamente.

Las funciones SSL_CTX_* cargan los certificados y claves en el objeto SSL_CTX ctx. La información se pasa a los objetos SSL ssl creados a partir de ctx con SSL_new(3) mediante copia, por lo que los cambios aplicados a ctx no se propagan a los objetos SSL ya existentes.

Las funciones SSL_* cargan certificados y claves en un objeto específico de SSL. La información se mantiene cuando se llama a SSL_clear(3) para este objeto SSL.

SSL_CTX_use_certificate() carga el certificado x en ctx, SSL_use_certificate() carga x en ssl. Los demás certificados necesarios para formar la cadena de certificados completa pueden especificarse usando la función SSL_CTX_add_extra_chain_cert(3). En caso de éxito, el contador de referencias de x se incrementa.

SSL_CTX_use_certificate_ASN1() carga el certificado ASN1 codificado en la ubicación de memoria d (con longitud len) en ctx, SSL_use_certificate_ASN1() carga el certificado ASN1 codificado en ssl.

SSL_CTX_use_certificate_file() carga el primer certificado almacenado en file en ctx. El formato type del certificado debe especificarse a partir de los tipos conocidos, como SSL_FILETYPE_PEM y SSL_FILETYPE_ASN1. SSL_use_certificate_file() carga el certificado desde file en ssl. Véase la sección NOTAS sobre por qué SSL_CTX_use_certificate_chain_file() debe ser preferido.

SSL_CTX_use_certificate_chain_file() carga una cadena de certificados desde file en ctx. Los certificados deben estar en formato PEM y deben estar ordenados comenzando con el certificado del sujeto (real cliente o servidor), seguido por los certificados de CA intermedios si los hay, y finalizando en el certificado más alto (raíz). SSL_use_certificate_chain_file() es similar, pero carga la cadena de certificados en ssl.

SSL_CTX_use_PrivateKey() agrega pkey como clave privada a ctx. ctx DEBE SER NO NULO. SSL_CTX_use_RSAPrivateKey() agrega la clave privada rsa de tipo RSA a ctx. SSL_use_PrivateKey() agrega pkey como clave privada a ssl; SSL_use_RSAPrivateKey() agrega rsa como clave privada de tipo RSA a ssl. Si una certificación ya fue establecida y la clave privada no pertenece a la certificación, se devuelve un error. Para cambiar una [certificación/clave] de forma SSL_use_certificate() o SSL_CTX_use_certificate() antes de establecer la clave privada con SSL_CTX_use_PrivateKey() o SSL_use_PrivateKey(). En caso de éxito, el contador de referencias de pkey/rsa se incrementa.

SSL_CTX_use_cert_and_key() y SSL_use_cert_and_key() asignan el certificado X.509 x, clave privada key, y certificado chain a los correspondientes ssl o ctx. El argumento pkey debe ser la clave privada de la certificación X.509 x. Si el argumento override es 0, entonces x, pkey y chain son establecidos solo si todos fueron previamente establecidos. Si override es distinto de 0, entonces el certificado, clave privada y cadena de certificados se establecen siempre. Si pkey es NULL, entonces la clave pública de x se usa como clave privada. Esto se utiliza con hardware (a través del interfaz ENGINE) que almacena la clave privada de forma segura, de modo que no pueda ser accedida por OpenSSL. El contador de referencias de la clave pública se incrementa (dos si no hay clave privada); no se copia ni duplica. Esto permite que todas las verificaciones de clave privada se completen sin asignar un clave privada real mediante SSL_CTX_use_PrivateKey(), etc.

SSL_CTX_use_PrivateKey_ASN1() agrega la clave privada de tipo pk almacenada en la ubicación de memoria d (longitud len) a ctx. SSL_CTX_use_RSAPrivateKey_ASN1() agrega la clave privada de tipo RSA almacenada en la ubicación de memoria d (longitud len) a ctx. SSL_use_PrivateKey_ASN1() y SSL_use_RSAPrivateKey_ASN1() agrega la clave privada a ssl.

SSL_CTX_use_PrivateKey_file() agrega la primera clave privada encontrada en file a ctx. El formato type de la clave privada debe especificarse a partir de los tipos conocidos, como SSL_FILETYPE_PEM y SSL_FILETYPE_ASN1. SSL_CTX_use_RSAPrivateKey_file() agrega la primera clave privada RSA encontrada en file a ctx. SSL_use_PrivateKey_file() agrega la primera clave privada encontrada en file a ssl; SSL_use_RSAPrivateKey_file() agrega la primera clave privada RSA encontrada a ssl. ctx DEBE SER NO NULO.

SSL_CTX_check_private_key() verifica la consistencia de una clave privada con la certificación correspondiente cargada en ctx. Si hay más de un par de clave/certificación (RSA/DSA) instalado, se verifica el último par instalado. Si, por ejemplo, el último par fue un certificado o clave RSA, se verifica el par clave RSA/certificado. SSL_check_private_key() realiza la misma verificación para ssl. Si no hay un par de clave/certificación especificado explícitamente para este ssl, se verifica el último par agregado a ctx.

NOTAS

La base de certificados interna de OpenSSL puede almacenar varias parejas de clave privada/certificado. El certificado utilizado depende del cifrado seleccionado, véase también SSL_CTX_set_cipher_list(3).

Cuando se leen certificados y claves privadas desde un archivo, los archivos de tipo SSL_FILETYPE_ASN1 (también conocidos como DER, codificación binaria) pueden contener solo un certificado o clave privada, por lo que SSL_CTX_use_certificate_chain_file() es solo aplicable al formato PEM. Los archivos de tipo SSL_FILETYPE_PEM pueden contener más de un elemento.

SSL_CTX_use_certificate_chain_file() carga el primer certificado encontrado en el archivo a la base de certificados. Los otros certificados se agregan a la base de certificados de cadenas de certificados mediante SSL_CTX_add1_chain_cert(3). Nota: versiones de OpenSSL antiguas (antes de 1.0.2) tenían solo una base de cadena de certificados para todos los certificados.

NAME

SSL_CTX_use_certificate, SSL_CTX_use_certificate_file, SSL_CTX_use_RSAPrivateKey, SSL_CTX_use_RSAPrivateKey_file, SSL_CTX_use_PrivateKey, SSL_CTX_use_PrivateKey_file, SSL_CTX_use_serverinfo, SSL_CTX_use_serverinfo_file

configure the certificate and private key for a context

SYNOPSIS

#include <openssl/ssl.h>
int SSL_CTX_use_certificate(SSL_CTX *ctx, X509 *x);
int SSL_CTX_use_certificate_file(SSL_CTX *ctx, const char *file, int type);
int SSL_CTX_use_RSAPrivateKey(SSL_CTX *ctx, RSA *rsa);
int SSL_CTX_use_RSAPrivateKey_file(SSL_CTX *ctx, const char *file, int type);
int SSL_CTX_use_PrivateKey(SSL_CTX *ctx, EVP_PKEY *pkey);
int SSL_CTX_use_PrivateKey_file(SSL_CTX *ctx, const char *file, int type);
int SSL_CTX_use_serverinfo(SSL_CTX *ctx, const char *data, size_t len);
int SSL_CTX_use_serverinfo_file(SSL_CTX *ctx, const char *file);

DESCRIPTION

These functions configure the certificate and private key that are used by the SSL/TLS library.

The certificate file specified by file must contain a PEM or DER encoded certificate. The private key file must contain a PEM or DER encoded private key.

The type parameter specifies the format of the file, and it can be SSL_FILETYPE_PEM or SSL_FILETYPE_ASN1 (DER).

SSL_CTX_use_certificate() and SSL_CTX_use_RSAPrivateKey() and SSL_CTX_use_PrivateKey() set the certificate and private key from memory.

SSL_CTX_use_certificate_file(), SSL_CTX_use_RSAPrivateKey_file() and SSL_CTX_use_PrivateKey_file() set the certificate and private key from a file.

SSL_CTX_use_serverinfo() and SSL_CTX_use_serverinfo_file() can be used to load server information which may be used for OCSP stapling. The format is specific to OpenSSL.

The certificate and private key are associated with the SSL_CTX object. For each new SSL object created from this SSL_CTX, the certificate and private key are copied.

The certificate chain can be set using SSL_CTX_use_certificate_chain_file(). See SSL_CTX_add_extra_chain_cert(3).

NOTES

The certificate file may contain multiple certificates. In that case, the first certificate is used as the main certificate, and the rest are added to the trusted certificate store.

If the certificate file contains multiple certificates, they are implicitly added to the chain of trusted certificates. This is also true for the SSL_CTX_use_certificate_file() function.

It is generally recommended to use SSL_CTX_use_certificate_chain_file() to specify the certificate chain. This function loads the certificate from the given file, and prepends any CA certificates from the same file to the list of certificates to be sent to the peer.

For OpenSSL versions 1.0.2 and later, there is a separate chain store for each type of certificate. SSL_CTX_use_certificate_chain_file() should be used instead of the SSL_CTX_use_certificate_file() function in order to allow the use of complete certificate chains even when no trusted CA storage is used or when the CA issuing the certificate shall not be added to the trusted CA storage.

If additional certificates are needed to complete the chain during the TLS negotiation, CA certificates are additionally looked up in the locations of trusted CA certificates, see SSL_CTX_load_verify_locations(3).

The private keys loaded from file can be encrypted. In order to successfully load encrypted keys, a function returning the passphrase must have been supplied, see SSL_CTX_set_default_passwd_cb(3). (Certificate files might be encrypted as well from the technical point of view, it however does not make sense as the data in the certificate is considered public anyway.)

All of the functions to set a new certificate will replace any existing certificate of the same type that has already been set. Similarly all of the functions to set a new private key will replace any private key that has already been set. Applications should call SSL_CTX_check_private_key(3) or SSL_check_private_key(3) as appropriate after loading a new certificate and private key to confirm that the certificate and key match.

RETURN VALUES

On success, the functions return 1. Otherwise check out the error stack to find out the reason.
