SSL_free(3ssl)

Paquete: openssl

Licencias: Apache-2.0

SSL_FREE(3ssl) OpenSSL SSL_FREE(3ssl)

NOMBRE

SSL_free - liberar una estructura SSL asignada

SINOPSIS

#include <openssl/ssl.h>
void SSL_free(SSL *ssl);

DESCRIPCIÓN

SSL_free() decrementa el contador de referencias de ssl, y elimina la estructura SSL apuntada por ssl y libera la memoria asignada si el contador de referencias ha alcanzado 0. Si ssl es NULL, no se hace nada.

NOTAS

SSL_free() también llama a los procedimientos de liberación() para elementos afectados indirectamente, si procede: el BIO de almacenamiento en búfer, los BIO de lectura y escritura, las listas de cifrado creadas específicamente para este ssl, la SSL_SESSION. No libere explícitamente estos elementos liberados indirectamente antes o después de llamar a SSL_free(), ya que intentar liberar cosas dos veces puede provocar fallos en el programa.

La sesión SSL tiene contadores de referencias de dos usuarios: el objeto SSL, cuyo contador de referencias se elimina con SSL_free(), y la caché de sesiones interna. Si la sesión se considera errónea, porque SSL_shutdown(3) no fue llamada para la conexión y SSL_set_shutdown(3) no se utilizó para establecer el estado SSL_SENT_SHUTDOWN, la sesión también se eliminará de la caché de sesiones según lo requerido por RFC2246.

Cuando se utiliza para liberar un objeto SSL de flujo QUIC, las partes de envío y recepción correspondientes del flujo se reinician a menos que esas partes ya se hayan concluido normalmente:

  • Si el flujo tiene una parte de envío (es decir, si es bidireccional o un flujo unidireccional iniciado localmente) y esa parte no se ha concluido mediante una llamada a SSL_stream_conclude(3) o SSL_stream_reset(3) en el objeto SSL del flujo QUIC, una llamada a SSL_free() reinicia automáticamente la parte de envío del flujo como si se hubiera llamado a SSL_stream_reset(3) con un código de error de aplicación QUIC de 0.
  • Si el flujo tiene una parte de recepción (es decir, si es bidireccional o un flujo unidireccional iniciado remotamente), y el par aún no ha concluido esa parte del flujo normalmente (por ejemplo, mediante una llamada a SSL_stream_conclude(3) en su propio extremo), una llamada a SSL_free() solicita automáticamente el reinicio de la parte de recepción del flujo utilizando un marco QUIC STOP_SENDING con un código de error de aplicación QUIC de 0. Tenga en cuenta que, según el protocolo QUIC, esto hará que el par reinicie esa parte del flujo a su vez (que es su parte de envío).

Un objeto SSL de flujo QUIC mantiene una referencia a un objeto SSL de conexión QUIC internamente, por lo tanto, un objeto SSL de flujo QUIC y su objeto SSL de conexión QUIC padre se pueden liberar en cualquier orden.

VALORES DE RETORNO

SSL_free() no proporciona información diagnóstica.

SSL_new(3), SSL_clear(3), SSL_shutdown(3), SSL_set_shutdown(3), ssl(7)
