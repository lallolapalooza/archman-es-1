NOMBRE

SSL_accept - espera a que un cliente TLS/SSL inicie un handshake TLS/SSL

SINOPSIS

#include <openssl/ssl.h>
int SSL_accept(SSL *ssl);

DESCRIPCIÓN

SSL_accept() espera a que un cliente TLS/SSL inicie el handshake TLS/SSL. El canal de comunicación debe haber sido previamente establecido y asignado a ssl mediante la configuración de un BIO subyacente.

NOTAS

El comportamiento de SSL_accept() depende del BIO subyacente.

Si el BIO subyacente es de tipo bloqueante, SSL_accept() solo retornará una vez que el handshake haya finalizado o se haya producido un error.

Si el BIO subyacente es de tipo no bloqueante, SSL_accept() también retornará cuando el BIO subyacente no pueda satisfacer las necesidades de SSL_accept() para continuar el handshake, indicando el problema mediante el valor de retorno -1. En este caso, una llamada a SSL_get_error() con el valor de retorno de SSL_accept() devolverá SSL_ERROR_WANT_READ o SSL_ERROR_WANT_WRITE. El proceso llamador deberá entonces repetir la llamada después de tomar las acciones adecuadas para satisfacer las necesidades de SSL_accept(). La acción depende del BIO subyacente. Al utilizar un socket no bloqueante, no hay nada que hacer, pero se puede usar select() para comprobar la condición requerida. Al utilizar un BIO de búfer, como un par de BIOs, se deben escribir o recuperar datos del BIO antes de poder continuar.

VALORES DE RETORNO

Los siguientes valores de retorno pueden ocurrir:

0
El handshake TLS/SSL no tuvo éxito pero se cerró de forma controlada y según las especificaciones del protocolo TLS/SSL. Llame a SSL_get_error() con el valor de retorno ret para averiguar el motivo.
1
El handshake TLS/SSL se completó con éxito, se ha establecido una conexión TLS/SSL.
<0
El handshake TLS/SSL no tuvo éxito porque ocurrió un error fatal a nivel de protocolo o un fallo de conexión. El cierre no fue limpio. También puede ocurrir si se necesita una acción para continuar la operación en BIOs no bloqueantes. Llame a SSL_get_error() con el valor de retorno ret para averiguar el motivo.
