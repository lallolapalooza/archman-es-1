SSL_alert_type_string(3ssl)

Paquete: openssl

Licencias: Apache-2.0

SSL_ALERT_TYPE_STRING(3ssl) OpenSSL SSL_ALERT_TYPE_STRING(3ssl)

NOMBRE

SSL_alert_type_string, SSL_alert_type_string_long, SSL_alert_desc_string, SSL_alert_desc_string_long - obtener descripción textual de información de alerta

SINOPSIS

#include <openssl/ssl.h>
const char *SSL_alert_type_string(int value);
const char *SSL_alert_type_string_long(int value);
const char *SSL_alert_desc_string(int value);
const char *SSL_alert_desc_string_long(int value);

DESCRIPCIÓN

SSL_alert_type_string() devuelve una cadena de una letra que indica el tipo de alerta especificada por value.

SSL_alert_type_string_long() devuelve una cadena que indica el tipo de alerta especificada por value.

SSL_alert_desc_string() devuelve una cadena de dos letras como forma corta que describe la razón de la alerta especificada por value.

SSL_alert_desc_string_long() devuelve una cadena que describe la razón de la alerta especificada por value.

NOTAS

Cuando una parte de una comunicación SSL/TLS quiere informar a la contraparte sobre una situación especial, envía una alerta. La alerta se envía como un mensaje especial y no influye en el flujo normal de datos (a menos que su contenido resulte en la cancelación de la comunicación).

Una alerta de advertencia se envía cuando ocurre una condición de error no fatal. La alerta "close notify" se envía como una alerta de advertencia. Otros ejemplos de errores no fatales son los errores de certificado ("certificate expired", "unsupported certificate"), para los cuales se puede enviar una alerta de advertencia. (Sin embargo, la parte emisora puede decidir enviar un error fatal.) La parte receptora puede cancelar la conexión a su discreción al recibir una alerta de advertencia.

Varios mensajes de alerta deben enviarse como mensajes de alerta fatales según lo especificado por la RFC de TLS. Una alerta fatal siempre conduce a un aborto de la conexión.

VALORES DE RETORNO

Las siguientes cadenas pueden ocurrir para SSL_alert_type_string() o SSL_alert_type_string_long():

"W"/"warning"
"F"/"fatal"
"U"/"unknown"
Esto indica que no hay soporte disponible para este tipo de alerta. Probablemente value no contiene un mensaje de alerta correcto.

Las siguientes cadenas pueden ocurrir para SSL_alert_desc_string() o SSL_alert_desc_string_long():

"CN"/"close notify"
La conexión debe cerrarse. Esta es una alerta de advertencia.
"UM"/"unexpected message"
Se recibió un mensaje inapropiado. Esta alerta es siempre fatal y nunca debería observarse en la comunicación entre implementaciones correctas.
"BM"/"bad record mac"
Esta alerta se devuelve si se recibe un registro con un MAC incorrecto. Este mensaje es siempre fatal.
"DF"/"decompression failure"
La función de descompresión recibió una entrada incorrecta (por ejemplo, datos que se expandirían a una longitud excesiva). Este mensaje es siempre fatal.
"HF"/"handshake failure"
La recepción de un mensaje de alerta handshake_failure indica que el emisor no pudo negociar un conjunto aceptable de parámetros de seguridad dadas las opciones disponibles. Este es un error fatal.
"NC"/"no certificate"
Un cliente, al que se le pidió que enviara un certificado, no envía un certificado (solo SSLv3).
"BC"/"bad certificate"
Un certificado estaba corrupto, contenía firmas que no verificaban correctamente, etc.
"UC"/"unsupported certificate"
Un certificado era de un tipo no soportado.
"CR"/"certificate revoked"
Un certificado fue revocado por su emisor.
"CE"/"certificate expired"
Un certificado ha expirado o no es válido actualmente.
"CU"/"certificate unknown"
Surgió algún otro problema (no especificado) al procesar el certificado, lo que lo hizo inaceptable.
"IP"/"illegal parameter"
Un campo en el handshake estaba fuera de rango o era inconsistente con otros campos. Esto es siempre fatal.
"DC"/"decryption failed"
Un TLSCiphertext se descifró de una manera inválida: o no era un múltiplo par de la longitud del bloque o sus valores de relleno, cuando se verificaron, no eran correctos. Este mensaje es siempre fatal.
"RO"/"record overflow"
Se recibió un registro TLSCiphertext que tenía una longitud superior a 2^14+2048 bytes, o un registro descifrado a un registro TLSCompressed con más de 2^14+1024 bytes. Este mensaje es siempre fatal.
"CA"/"unknown CA"
Se recibió una cadena de certificados válida o una cadena parcial, pero el certificado no fue aceptado porque no se pudo localizar el certificado de la CA o no se pudo corresponder con una CA conocida y confiable. Este mensaje es siempre fatal.
"AD"/"access denied"
Se recibió un certificado válido, pero cuando se aplicó el control de acceso, el emisor decidió no proceder con la negociación. Este mensaje es siempre fatal.
"DE"/"decode error"
Un mensaje no pudo ser decodificado porque algún campo estaba fuera del rango especificado o la longitud del mensaje era incorrecta. Este mensaje es siempre fatal.
"CY"/"decrypt error"
Una operación criptográfica del handshake falló, incluyendo la incapacidad de verificar correctamente una firma, descifrar un intercambio de claves o validar un mensaje de finalización.
"ER"/"export restriction"
Se detectó una negociación que no cumplía con las restricciones de exportación; por ejemplo, intentar transferir una clave RSA efímera de 1024 bits para el método de handshake RSA_EXPORT. Este mensaje es siempre fatal.
"PV"/"protocol version"
La versión del protocolo que el cliente ha intentado negociar es reconocida, pero no es compatible. (Por ejemplo, las versiones antiguas del protocolo podrían evitarse por razones de seguridad). Este mensaje es siempre fatal.
"IS"/"insufficient security"
Devuelto en lugar de handshake_failure cuando una negociación ha fallado específicamente porque el servidor requiere cifrados más seguros que los soportados por el cliente. Este mensaje es siempre fatal.
"IE"/"internal error"
Un error interno no relacionado con la contraparte o la corrección del protocolo hace imposible continuar (como una falla de asignación de memoria). Este mensaje es siempre fatal.
"US"/"user canceled"
Este handshake se está cancelando por alguna razón no relacionada con una falla del protocolo. Si el usuario cancela una operación después de que el handshake se completa, es más apropiado simplemente cerrar la conexión enviando un close_notify. A esta alerta debería seguirle un close_notify. Este mensaje es generalmente una advertencia.
"NR"/"no renegotiation"
Enviado por el cliente en respuesta a una solicitud de saludo o por el servidor en respuesta a un saludo de cliente después del handshake inicial. Cualquiera de los dos conduciría normalmente a una renegociación; cuando eso no es apropiado, el receptor debe responder con esta alerta; en ese momento, el solicitante original puede decidir si continuar con la conexión. Un caso en el que esto sería apropiado sería cuando un servidor ha generado un proceso para satisfacer una solicitud; el proceso podría recibir parámetros de seguridad (longitud de clave, autenticación, etc.) al inicio y podría ser difícil comunicar cambios en estos parámetros después de ese punto. Este mensaje es siempre una advertencia.
"UP"/"unknown PSK identity"
Enviado por el servidor para indicar que no reconoce una identidad PSK o una identidad SRP.
"UK"/"unknown"
Esto indica que no hay descripción disponible para este tipo de alerta. Probablemente value no contiene un mensaje de alerta correcto.

SSL_alert_type_string_no_desc

SSL_alert_type_string_no_desc, SSL_alert_desc_string_no_desc - an alert message type or description string

SYNOPSIS

#include <openssl/ssl.h>

const char *SSL_alert_type_string_no_desc(int value);
const char *SSL_alert_desc_string_no_desc(int value);

DESCRIPTION

SSL_alert_type_string_no_desc() returns a string representation of the alert message type specified by value. The possible values for the alert type are defined in ssl.h as SSL_AD_CLOSESOCKET, SSL_AD_ALERT_WARNING, SSL_AD_ALERT_FATAL, SSL_AD_RECORD_MAX_్‌DATA_ERROR, SSL_AD_PARSE_ERROR, SSL_AD_DECRYPTION_FAILED, SSL_AD_RECORD_OVERFLOW, SSL_AD_UNEXPECTED_MESSAGE, SSL_AD_BAD_RECORD_MAC, SSL_AD_PROTOCOL_VERSION, SSL_AD_DECODE_ERROR, SSL_AD_DECRYPTION_FAILED, SSL_AD_HANDSHAKE_FAILURE, SSL_AD_CERTIFICATE_UNAUTHORISED, SSL_AD_CERTIFICATE_EXPIRED, SSL_AD_CERTIFICATE_REVOKED, SSL_AD_CERTIFICATE_UNKNOWN, SSL_AD_ILLEGAL_PARAMETER, SSL_AD_PROTOCOL_VERSION, SSL_AD_DECODE_ERROR, SSL_AD_DECRYPTION_FAILED, SSL_AD_HANDSHAKE_FAILURE, SSL_AD_CERTIFICATE_UNAUTHORISED, SSL_AD_CERTIFICATE_EXPIRED, SSL_AD_CERTIFICATE_REVOKED, SSL_AD_CERTIFICATE_UNKNOWN, SSL_AD_ILLEGAL_PARAMETER.

SSL_alert_desc_string_no_desc() returns a string representation of the alert message description specified by value.

These functions are intended for debugging and not for use in production code.

NOTES

If an unknown value is passed to either function, then the string "UNKNOWN" is returned.

RETURN VALUES

A pointer to a string representation of the alert message type or description. This string must not be modified or freed.
