SSL_CTX_set1_sigalgs(3ssl)

Paquete: openssl

Licencias: Apache-2.0

SSL_CTX_SET1_SIGALGS(3ssl) OpenSSL SSL_CTX_SET1_SIGALGS(3ssl)

NOMBRE

SSL_CTX_set1_sigalgs, SSL_set1_sigalgs, SSL_CTX_set1_sigalgs_list, SSL_set1_sigalgs_list, SSL_CTX_set1_client_sigalgs, SSL_set1_client_sigalgs, SSL_CTX_set1_client_sigalgs_list, SSL_set1_client_sigalgs_list - establecer algoritmos de firma soportados

SINOPSIS

#include <openssl/ssl.h>
long SSL_CTX_set1_sigalgs(SSL_CTX *ctx, const int *slist, long slistlen);
long SSL_set1_sigalgs(SSL *ssl, const int *slist, long slistlen);
long SSL_CTX_set1_sigalgs_list(SSL_CTX *ctx, const char *str);
long SSL_set1_sigalgs_list(SSL *ssl, const char *str);
long SSL_CTX_set1_client_sigalgs(SSL_CTX *ctx, const int *slist, long slistlen);
long SSL_set1_client_sigalgs(SSL *ssl, const int *slist, long slistlen);
long SSL_CTX_set1_client_sigalgs_list(SSL_CTX *ctx, const char *str);
long SSL_set1_client_sigalgs_list(SSL *ssl, const char *str);

DESCRIPCIÓN

SSL_CTX_set1_sigalgs() y SSL_set1_sigalgs() establecen los algoritmos de firma soportados para ctx o ssl. El array slist de longitud slistlen debe consistir en pares de NIDs correspondientes a los algoritmos de digest y clave pública.

SSL_CTX_set1_sigalgs_list() y SSL_set1_sigalgs_list() establecen los algoritmos de firma soportados para ctx o ssl. El parámetro str debe ser una cadena nula terminada que consista en una lista separada por dos puntos de elementos, donde cada elemento es una combinación de un algoritmo de clave pública y un digest separados por +, o un nombre de esquema de firma al estilo TLS 1.3, como rsa_pss_pss_sha256. Los nombres de los esquemas de firma y los nombres de los algoritmos de clave pública (pero no los nombres de los digests) en el formato algorithm+hash no distinguen entre mayúsculas y minúsculas. Si a una entrada de la lista le precede el carácter "?", se ignorará si falta una implementación.

SSL_CTX_set1_client_sigalgs(), SSL_set1_client_sigalgs(), SSL_CTX_set1_client_sigalgs_list() y SSL_set1_client_sigalgs_list() establecen los algoritmos de firma relacionados con la autenticación del cliente; de lo contrario, son idénticos a SSL_CTX_set1_sigalgs(), SSL_set1_sigalgs(), SSL_CTX_set1_sigalgs_list() y SSL_set1_sigalgs_list().

Todas estas funciones se implementan como macros. El parámetro del algoritmo de firma (array de enteros o cadena) no se libera: la aplicación debe liberarlo, si es necesario.

NOTAS

Si una aplicación desea permitir la configuración de algoritmos de firma como una de las muchas opciones configurables por el usuario, debería considerar usar la API SSL_CONF, más flexible, en su lugar.

Los algoritmos de firma establecidos por un cliente se utilizan directamente en la firma soportada en el mensaje client hello.

Los algoritmos de firma soportados establecidos por un servidor no se envían al cliente, sino que se utilizan para determinar el conjunto de algoritmos de firma compartidos y (si las preferencias del servidor se establecen con SSL_OP_SERVER_PREFERENCE) su orden.

Los algoritmos de firma de autenticación del cliente establecidos por un servidor se envían en un mensaje de solicitud de certificado si la autenticación del cliente está habilitada; de lo contrario, no se utilizan.

Del mismo modo, los algoritmos de firma de autenticación del cliente establecidos por un cliente se utilizan para determinar el conjunto de algoritmos de firma compartidos para la autenticación del cliente.

Los algoritmos de firma ni se anunciarán ni se utilizarán si el nivel de seguridad los prohíbe (por ejemplo, SHA1 si el nivel de seguridad es 4 o superior).

Actualmente, se soportan los NIDs de digest NID_md5, NID_sha1, NID_sha224, NID_sha256, NID_sha384 y NID_sha512, y los NIDs de algoritmo de clave pública EVP_PKEY_RSA, EVP_PKEY_RSA_PSS, EVP_PKEY_DSA y EVP_PKEY_EC.

Los valores de nombres cortos o largos para los digests se pueden utilizar en una cadena (por ejemplo, "MD5", "SHA1", "SHA224", "SHA256", "SHA384", "SHA512") y los nombres de algoritmos de clave pública "RSA", "RSA-PSS", "DSA" o "ECDSA".

Los nombres de esquemas de firma de TLS 1.3 (como "rsa_pss_pss_sha256") también se pueden utilizar con las formas _list de la API.

El uso de MD5 como digest está fuertemente desaconsejado debido a debilidades de seguridad.

VALORES DE RETORNO

Todas estas funciones devuelven 1 en caso de éxito y 0 en caso de fallo.

EJEMPLOS

Establecer algoritmos de firma soportados a SHA256 con ECDSA y SHA256 con RSA usando un array:

const int slist[] = {NID_sha256, EVP_PKEY_EC, NID_sha256, EVP_PKEY_RSA};
SSL_CTX_set1_sigalgs(ctx, slist, 4);

Establecer algoritmos de firma soportados a SHA256 con ECDSA y SHA256 con RSA usando una cadena:

SSL_CTX_set1_sigalgs_list(ctx, "ECDSA+SHA256:RSA+SHA256");

VER TAMBIÉN

ssl(7), SSL_get_shared_sigalgs(3), SSL_CONF_CTX_new(3)

HISTORIA

El soporte para ignorar algoritmos de firma desconocidos en SSL_CTX_set1_sigalgs_list(), SSL_set1_sigalgs_list(), SSL_CTX_set1_client_sigalgs_list() y SSL_set1_client_sigalgs_list() se añadió en OpenSSL 3.3.
