SSL_COMP_add_compression_method(3ssl)

Paquete: openssl

Licencias: Apache-2.0

SSL_COMP_ADD_COMPRESSION_METHOD(3ssl) OpenSSL SSL_COMP_ADD_COMPRESSION_METHOD(3ssl)

NOMBRE

SSL_COMP_add_compression_method, SSL_COMP_get_compression_methods, SSL_COMP_get0_name, SSL_COMP_get_id, SSL_COMP_free_compression_methods - manejar métodos de compresión integrados de SSL/TLS

SINOPSIS

#include <openssl/ssl.h>
int SSL_COMP_add_compression_method(int id, COMP_METHOD *cm);
STACK_OF(SSL_COMP) *SSL_COMP_get_compression_methods(void);
const char *SSL_COMP_get0_name(const SSL_COMP *comp);
int SSL_COMP_get_id(const SSL_COMP *comp);

La siguiente función ha sido deprecada desde OpenSSL 1.1.0, y puede ocultarse por completo definiendo OPENSSL_API_COMPAT con un valor de versión adecuado, véase openssl_user_macros(7):

void SSL_COMP_free_compression_methods(void);

DESCRIPCIÓN

SSL_COMP_add_compression_method() añade el método de compresión cm con el identificador id a la lista de métodos de compresión disponibles. Esta lista se mantiene globalmente para todas las operaciones SSL dentro de esta aplicación. No se puede establecer para objetos SSL_CTX o SSL específicos.

SSL_COMP_get_compression_methods() devuelve una pila de todos los métodos de compresión disponibles o NULL en caso de error.

SSL_COMP_get0_name() devuelve el nombre del método de compresión comp.

SSL_COMP_get_id() devuelve el id del método de compresión comp.

SSL_COMP_free_compression_methods() libera cualquier recurso adquirido para mantener la tabla interna de métodos de compresión.

NOTAS

El estándar TLS (o SSLv3) permite la integración de métodos de compresión en la comunicación. Sin embargo, RFC de TLS no especifica métodos de compresión ni sus identificadores correspondientes, por lo que actualmente no existe una forma compatible de integrar la compresión con pares desconocidos. Por lo tanto, actualmente no se recomienda integrar la compresión en las aplicaciones. Las aplicaciones para uso no público pueden acordar ciertos métodos de compresión. El uso de diferentes métodos de compresión con el mismo identificador provocará un fallo en la conexión.

Un cliente OpenSSL que hable un protocolo que permita la compresión (SSLv3, TLSv1) enviará incondicionalmente la lista de todos los métodos de compresión habilitados con SSL_COMP_add_compression_method() al servidor durante el handshake. A diferencia de los mecanismos para establecer una lista de cifrados, no hay un método disponible para restringir la lista de métodos de compresión por conexión.

Un servidor OpenSSL comparará los identificadores listados por un cliente con sus propios métodos de compresión y activará incondicionalmente la compresión cuando se encuentre un identificador coincidente. No hay forma de restringir la lista de métodos de compresión compatibles por conexión.

Si se habilitan durante la compilación, la biblioteca OpenSSL tendrá disponibles los siguientes métodos de compresión:

COMP_zlib()
COMP_brotli()
COMP_brotli_oneshot()
COMP_zstd()
COMP_zstd_oneshot()

VALORES DE RETORNO

SSL_COMP_add_compression_method() puede devolver los siguientes valores:

0
La operación se completó correctamente.
1
La operación falló. Consulte la cola de errores para averiguar el motivo.

SSL_COMP_get_compression_methods() devuelve la pila de métodos de compresión o NULL en caso de error.

SSL_COMP_get0_name() devuelve el nombre del método de compresión o NULL en caso de error.

SSL_COMP_get_id() devuelve el nombre del método de compresión o -1 en caso de error.

VER TAMBIÉN

ssl(7)

HISTORIA

La función SSL_COMP_free_compression_methods() fue deprecada en OpenSSL 1.1.0. Las funciones SSL_COMP_get0_name() y SSL_comp_get_id() se añadieron en OpenSSL 1.1.0d.
