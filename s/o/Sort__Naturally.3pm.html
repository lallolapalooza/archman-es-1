NOMBRE

Sort::Naturally -- ordena lexicográficamente, pero ordena las partes numéricas numéricamente

SINOPSIS

@them = nsort(qw(
 foo12a foo12z foo13a foo 14 9x foo12 fooa foolio Foolio Foo12a
));
print join(' ', @them), "\n";

Imprime:

9x 14 foo fooa foolio Foolio foo12 foo12a Foo12a foo12z foo13a

(O "foo12a" + "Foo12a" y "foolio" + "Foolio" podrían intercambiarse, dependiendo de tu configuración regional.)

DESCRIPCIÓN

Este módulo exporta dos funciones, "nsort" y "ncmp"; se utilizan para implementar mi idea de un algoritmo de "ordenación natural". Bajo la ordenación natural, las subcadenas numéricas se comparan numéricamente y otros caracteres de palabra se comparan lexicográficamente.

Así es como defino la ordenación natural:

  • Las subcadenas de caracteres de palabra no numéricas se ordenan lexicográficamente, sin distinción entre mayúsculas y minúsculas: "Foo" viene entre "fish" y "fowl".
  • Las subcadenas numéricas se ordenan numéricamente: "100" viene después de "20", no antes.
  • Las subcadenas \W (ni caracteres de palabra ni dígitos) se ignoran.
  • Nuestro uso de \w, \d, \D y \W depende de la configuración regional: Sort::Naturally utiliza una declaración "use locale".
  • Al comparar dos cadenas, donde una subcadena numérica en un lugar *no* está junto a una subcadena numérica en otro, el no numérico siempre va primero. Esto se disfraza leyendo y pretendiendo que la falta de una subcadena numérica tiene el valor -1, de la siguiente manera: 
    foo       =>  "foo",  -1
foobar    =>  "foo",  -1,  "bar"
foo13     =>  "foo",  13,
foo13xyz  =>  "foo",  13,  "xyz"

    Eso es para que "foo" venga antes de "foo13", que venga antes de "foobar".

  • El inicio de una cadena es excepcional: los componentes iniciales no-\W (no de palabra, no de dígito) se ignoran, y los números vienen *antes* que las letras.
  • Defino "subcadena numérica" solo como secuencias que coinciden con m/\d+/ -- la notación científica, las comas, los decimales, etc., no se ven. Si tus datos tienen separadores de miles en los números ("20,000 Leagues Under The Sea" o "20.000 leguas de viaje submarino"), considera eliminarlos antes de pasarlos a "nsort" o "ncmp".

La función nsort

Esta función toma una lista de cadenas y devuelve una copia de la lista, ordenada.

Esto es lo que la mayoría de la gente querrá usar:

@stuff = nsort(...lista...);

Cuando nsort necesita comparar subcadenas no numéricas, utiliza la función "lc" de Perl en el ámbito de un <use locale>. Y cuando nsort necesita convertir cosas a minúsculas, utiliza la función "lc" de Perl en el ámbito de un <use locale>. Si quieres que nsort use otras funciones en su lugar, puedes especificarlas en un arrayref como primer argumento para nsort:

@stuff = nsort( [
                  \&comparador_de_cadenas, # opcional
                  \&funcion_a_minusculas  # opcional
                ],
                ...lista...
              );

Si quieres especificar un comparador de cadenas pero no un conversor a minúsculas, entonces la lista de opciones es "[\&comparador, '']" o "[\&comparador]". Si quieres especificar ningún comparador de cadenas pero sí un conversor a minúsculas, entonces la lista de opciones es "['', \&conversor_a_minusculas]".

Cualquier comparador que especifiques se llama como "$comparador->($izquierda, $derecha)" y, como un reemplazo normal de Perl para "cmp", debe devolver -1, 0 o 1 dependiendo de si el argumento izquierdo es menor que, igual a o mayor que el argumento derecho en orden de cadenas.

Cualquier función conversora a minúsculas que especifiques se llama como "$convertido = $conversor_a_minusculas->($original)". La rutina no debe modificar su $_[0].

La función ncmp

A menudo, al ordenar valores no de cadena como estos:

@objects_sorted = sort { $a->tag cmp $b->tag } @objects;

...o incluso en una transformación de Schwartz, como esta:

@strings =
  map $_->[0]
  sort { $a->[1] cmp $b->[1] }
  map { [$_, make_a_sort_key_from($_) ]
  @_
;

...podrías querer algo que reemplace no a "sort", sino a "cmp". Para eso es la función "ncmp" de Sort::Naturally. Llámala con la sintaxis "ncmp($izquierda, $derecha)" en lugar de "$izquierda cmp $derecha", pero por lo demás es un buen reemplazo:

@objects_sorted = sort { ncmp($a->tag,$b->tag) } @objects;
@strings =
  map $_->[0]
  sort { ncmp($a->[1], $b->[1]) }
  map { [$_, make_a_sort_key_from($_) ]
  @_
;

Al igual que con "nsort", que puede aceptar un comparador de cadenas y/o un conversor a minúsculas diferentes, puedes hacer lo mismo con "ncmp", pasando un arrayref como primer argumento:

ncmp( [
        \&comparador_de_cadenas, # opcional
        \&funcion_a_minusculas  # opcional
      ],
      $izquierda, $derecha
    )

Puedes obtener comparadores de cadenas de Sort::ArbBiLex.

NOTAS

  • ¡Este módulo no es un sustituto de Sort::Versions! Si solo necesitas una ordenación de versiones adecuada, ¡usa *ese*!
  • Si necesitas algo que funcione *más o menos* como las funciones de este módulo, pero no exactamente igual, considera explorar el código fuente de este módulo y adaptar lo que veas. Además de las funciones que se compilan realmente en este módulo, después del POD, hay varios intentos alternativos míos de rutinas de ordenación natural, que no se compilan como parte del módulo, pero que podrían resultarte útiles. Todas deberían ser implementaciones *funcionales* de algoritmos ligeramente diferentes (todas basadas en el "nsort" de Martin Pool) que eventualmente descarté a favor de mi algoritmo. Si tienes que ordenar naturalmente conjuntos de datos *muy grandes* y la ordenación se está volviendo ridículamente lenta, podrías considerar probar una de esas funciones descartadas: tengo la sensación de que podrían ser más rápidas en conjuntos de datos grandes. Compáralas con tus datos y compruébalo. (A menos que *necesites* la velocidad, no te molestes. Consejo: sustituye "sort" por "nsort" en tu código y, a menos que tu programa acelere drásticamente, no es la ordenación lo que ralentiza las cosas. Pero si es "nsort" lo que ralentiza las cosas, considera simplemente: 
    if(@set >= ALGÚN_NÚMERO_MUY_GRANDE) {
  no locale; # vroom vroom
  @sorted = sort(@set);  # feh, suficiente
} elsif(@set >= ALGÚN_NÚMERO_GRANDE) {
  use locale;
  @sorted = sort(@set);  # feh, suficiente
} else {
  # pero mantenlo bonito para casos normales
  @sorted = nsort(@set);
}
  • Si adaptas las rutinas de este módulo, envíame un correo; me interesaría escucharlo.
