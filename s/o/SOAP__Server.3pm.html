SOAP::Server(3) Documentación de Perl contribuida por usuarios SOAP::Server(3)

NOMBRE

SOAP::Server - proporciona el marco básico para que las clases de servidor específicas del transporte se basen en él

DESCRIPCIÓN

La clase SOAP::Server proporciona el marco básico para que las clases de servidor específicas del transporte se basen en él. Tenga en cuenta que en ninguno de los ejemplos de código proporcionados con SOAP::Lite se utiliza esta clase directamente. En cambio, está diseñada para ser una superclase dentro de clases de implementación más específicas. Los métodos proporcionados por SOAP::Server en sí son:

MÉTODOS

nuevo(opcional pares clave/valor)
$servidor = SOAP::Server->new(%opciones);

Crea un nuevo objeto de la clase. Se configuran varios valores de instancia predeterminados y, al igual que muchos de los constructores de este módulo, la mayoría de los métodos de clase descritos aquí se pueden pasar en la llamada de construcción proporcionando el nombre seguido del parámetro (o una referencia de matriz si hay varios parámetros).

acción(opcional nuevo valor)
$accion = $servidor->acción

Recupera o establece el valor del atributo de acción en el objeto del servidor. Este atributo se utiliza al mapear la solicitud a un espacio de nombres o rutina apropiados. Por ejemplo, la biblioteca HTTP establece el atributo al valor del encabezado SOAPAction cuando comienza el procesamiento de la solicitud, de modo que el método find_target descrito más adelante pueda recuperar el valor para compararlo con la configuración del servidor. Devuelve el objeto mismo al establecer el atributo.

miuri(opcional nuevo valor)
$servidor->miuri("http://localhost:9000/SOAP");

Obtiene o establece el atributo myuri. Esto especifica la URI específica a la que el servidor está respondiendo las solicitudes (que puede ser diferente del valor especificado en action o en el encabezado SOAPAction).

serializador(opcional nuevo valor)
deserializador(opcional nuevo valor)
$serializador = $servidor->serializador;
$servidor->deserializador($nuevo_objeto_deser);

Al igual que con los objetos cliente, estos métodos proporcionan acceso directo a los objetos de serialización y deserialización que el objeto servidor utiliza para transformar la entrada y salida desde y hacia XML. En general, hay poca o ninguna necesidad de establecer explícitamente estos a nuevos valores.

opciones(opcional nuevo valor)
$servidor->opciones({limite_compresion => 10000});

Establece (o recupera) las opciones actuales del servidor como una referencia a una tabla hash. Actualmente, solo se utiliza una opción dentro de las bibliotecas de SOAP::Lite:

limite_compresion
Se espera que el valor de esta opción sea un valor numérico. Si se establece y si la biblioteca Compress::Zlib está disponible para su uso, los mensajes cuyo tamaño en bytes supere este valor se comprimirán para su transmisión. Ambos extremos de la conversación deben admitir esto y tenerlo habilitado.

Se pueden definir y pasar otras opciones utilizando este mecanismo. Tenga en cuenta que establecer las opciones utilizando este accesorio requiere pasar una referencia completa de tabla hash. Para establecer solo uno o algunos valores, recupere el valor de referencia actual y utilícelo para establecer la(s) clave(s).

despachar_con(opcional nuevo valor)
$servidor->despachar_con($nueva_tabla);

Representa una de las dos formas en que un objeto SOAP::Server (o derivado) puede especificar mapeos de solicitudes entrantes a subrutinas o espacios de nombres del lado del servidor. El valor del atributo es una referencia a una tabla hash. Para establecer el atributo, debe pasar una nueva referencia de tabla hash. Las claves de la tabla hash son cadenas de URI (URI literales o los valores potenciales del encabezado SOAPAction), y los valores correspondientes son el nombre de una clase o una referencia a un objeto. Las solicitudes que llegan para una URI que se encuentra en la tabla se enrutan a la clase especificada o a través del objeto especificado.

despachar_a(opcional lista de nuevos valores)
$servidor->despachar_a($dir, 'Módulo', 'Mod::método');

Esta es la forma más tradicional de especificar módulos y paquetes para enrutar solicitudes. También es un accesorio, pero devuelve una lista de valores cuando se llama sin argumentos (en lugar de uno solo). Se espera que cada elemento de la lista de valores que se pasa a este método sea una de las cuatro cosas:

Ruta del directorio
Si el valor es una ruta de directorio, todos los módulos ubicados en esa ruta están disponibles para uso remoto.
Nombre del paquete
Cuando el valor es un nombre de paquete (sin incluir un nombre de método específico), todas las rutinas dentro del paquete están disponibles de forma remota.
Nombre del método calificado completamente
Alternativamente, cuando el valor es un nombre calificado por paquete de una subrutina o método, esa rutina específica se pone a disposición. Esto permite al servidor poner a disposición métodos seleccionados sin abrir todo el paquete.
Referencia al objeto
Si el valor es una referencia a un objeto, el objeto en sí mismo enruta la solicitud.

La lista de valores mantenidos por la tabla dispatch_to solo se compara después de consultar la tabla de mapeo de URI del atributo dispatch_with. Si la URI de la solicitud o el encabezado SOAPAction no se mapean a una configuración específica, la ruta especificada por el encabezado de acción (o en ausencia, la URI) se convierte en un nombre de paquete y se compara con este conjunto de valores.

objetos_por_referencia(opcional lista de nuevos valores)
$servidor->objetos_por_referencia(qw(Mi:: Clase));

Esto también devuelve una lista de valores al recuperar el valor del atributo actual, en lugar de un solo valor.

Este método no especifica directamente clases para el enrutamiento de solicitudes, sino que modifica el comportamiento del enrutamiento para las clases especificadas. Las clases que se proporcionan como argumentos a este método se marcan para ser tratadas como productoras de objetos persistentes. Al cliente se le da una representación de objeto que contiene solo un identificador en un objeto local con una persistencia predeterminada de 600 segundos inactivos. Cada operación en el objeto restablece el temporizador inactivo a cero. Esta facilidad se considera experimental en la versión actual de SOAP::Lite.

Una variable global/"constante" permite a los desarrolladores especificar el tiempo que se mantendrá un objeto. El valor predeterminado es de 600 segundos inactivos. Este valor se puede cambiar usando el siguiente código:

$SOAP::Constants::OBJS_BY_REF_KEEPALIVE = 1000;
en_accion(opcional nuevo valor)
$servidor->en_accion(sub { ...nuevo código });

Obtiene o establece la referencia a una subrutina que se utiliza para ejecutar el gancho on_action. Donde el código cliente utiliza este gancho para construir los datos de la solicitud de acción (como para un encabezado SOAPAction), el servidor utiliza el gancho on_action para realizar pruebas de último momento en la propia solicitud, antes de que se enrute a un destino final. Cuando se llama, a la rutina del gancho se le pasan tres argumentos:

acción
La URI de acción en sí, recuperada del método action descrito anteriormente.
uri_metodo
La URI del espacio de nombres XML con el que está etiquetado el nombre del método.
nombre_metodo
El nombre del método que está siendo llamado por la solicitud.

NOMBRE

SOAP::Server::Parameters

DESCRIPCIÓN

Esta clase proporciona dos métodos, pero el propósito principal desde el punto de vista del desarrollador es permitir a clases que un servidor SOAP expone heredar de ella. Cuando una clase hereda de la clase SOAP::Server::Parameters, la lista de parámetros que se pasan a un método llamado incluye la peticion deserializada en forma de objeto SOAP::SOM. Este parámetro se pasa al final de la lista de argumentos, dando a los métodos la opción de ignorarlo salvo que lo necesiten.

La clase proporciona dos subrutinas (no métodos), para recuperar parámetros de la clase SOAP::SOM. Estas son diseñadas para ser llamadas sin referencia de objeto en la lista de parámetros, pero con una referencia de array (como el primer parámetro). El resto de la lista de argumentos espera ser la lista de parámetros del propio método, incluyendo el objeto SOAP::SOM al final de la lista. Las rutinas pueden ser útiles para entender si un aplicativo desea heredar de la nueva clase.

byNameOrOrder(order, lista de parámetros, sobre)
@args = SOAP::Server::Parameters::byNameOrOrder ([qw(a b)], @_);

Usando la lista de nombres de argumento proporcionada en el argumento inicial como una referencia de array, esta rutina devuelve una lista de los valores de los parámetros correspondientes a los nombres dados, en ese orden. Si ninguno de los nombres dados en la referencia de array inicial existe en la lista de parámetros, los valores se devuelven en el orden en que ya existen en la lista de parámetros. En este caso, el número de valores devueltos puede diferir de la longitud de la lista de parámetros solicitadas.

byName(order, lista de parámetros, sobre)
@args = SOAP::Server::Parameters::byName ([qw(a b c)], @_);

Actúa de manera similar a la anterior, con la diferencia de que siempre devuelve tantos valores como se solicitan, incluso si algunos (o todos) no existen. Los parámetros que no existen en la lista de parámetros se devuelven como valores indefinidos (undef).

EJEMPLO

El siguiente es un ejemplo de una web service CGI basado en Perl que utiliza un módulo que hereda de la clase SOAP::Server::Parameters. Esto permite que los métodos de esa clase accedan al entrada por nombre.

#!/usr/bin/perl
use SOAP::Transport::HTTP;
SOAP::Transport::HTTP::CGI
  ->dispatch_to('C2FService')
  ->handle;
BEGIN {
  package C2FService;
  use vars qw(@ISA);
  @ISA = qw(Exporter SOAP::Server::Parameters);
  use SOAP::Lite;
  sub c2f {
    my $self = shift;
    my $envelope = pop;
    my $temp = $envelope->dataof("//c2f/temperature");
    return SOAP::Data->name('convertedTemp' => (((9/5)*($temp->value)) + 32));
  }
}
