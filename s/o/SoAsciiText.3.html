Descripción detallada

La clase SoAsciiText representa texto plano en 3D.

El texto se representa mediante geometría de polígonos 3D.

La dimensión de la representación geométrica del texto está determinada por el campo SoFont::size de un nodo SoFont precedente en la jerarquía de la escena, que especifica el tamaño en unidades de coordenadas. Este valor establece el tamaño aproximado de las letras. El valor predeterminado si no se usan nodos SoFont es 10.

La complejidad de los glifos se controla mediante un nodo SoComplexity precedente con el Type establecido en OBJECT_SPACE. Tenga en cuenta que el tipo de fuente 3D predeterminado no se verá afectado por el nodo SoComplexity.

Este nodo es diferente del nodo SoText2 en que rotará, escalará, trasladará, etc. como otros tipos de geometría en la escena. Es diferente del nodo SoText3 en que representa el texto "plano", es decir, no extruye las fuentes para darles profundidad.

DESCRIPTION


The SoAsciiText node creates and renders
    text strings as a collection of 2D primitives. It is intended to be used to
    render text in 2D scenes, or for adding annotations to 3D scenes.


The text is drawn using a built-in bitmap font. The characters
    are generated using the SoBitmapFont class.


The origin of the text is located at the baseline of the first line
    of text. The coordinates are specified in the local coordinate system.


The text strings are defined by the string
    field. Each string in the multiple value field will be rendered on a
    separate line.


The spacing field controls the vertical
    spacing between the baselines of two consecutive horizontal lines. The
    default value is 1.0, which means that it is equal to the vertical size of
    the highest character in the bitmap alphabet.


The justification field determines the
    horizontal alignment of the text strings. See the SoAsciiText::Justification
    enumeration for details.


The width field defines the width of each
    line. The text is scaled to be within the specified units. The size of the
    characters will remain the same; only the X-positions are scaled. When
    width <= 0, the width value is ignored and the text
    rendered as normal.


If you want to render text that is not in the XY plane, you should
    use SoText3. If you want to use TrueType fonts, you
    should use SoText2.


Below is an example of how to create a text node:


    SoAsciiText {
        string [ "This is line 1",
                 "This is line 2" ]
        spacing 1.2
        justification CENTER
        width 0
    }



In examinerviewer the Inventor file looks something like this:

Member Data Documentation




SoMFString SoAsciiText::string


The set of strings to render. Each string in the multiple value
    field will be rendered on a separate line.


The default value of the field is a single empty string.






SoSFFloat SoAsciiText::spacing


Vertical spacing between the baselines of two consecutive
    horizontal lines. Default value is 1.0, which means that it is equal to the
    vertical size of the highest character in the bitmap alphabet.






SoSFEnum SoAsciiText::justification


Determines horizontal alignment of text strings.


If justification is set to SoAsciiText::LEFT, the left edge
    of the first string is at the origin and all strings are aligned with their
    left edges. If set to SoAsciiText::RIGHT, the right edge of the first
    string is at the origin and all strings are aligned with their right edges.
    Otherwise, if set to SoAsciiText::CENTER, the center of the first
    string is at the origin and all strings are aligned with their centers. The
    origin is always located at the baseline of the first line of text.


Default value is SoAsciiText::LEFT.






SoMFFloat SoAsciiText::width


Defines the width of each line. The text is scaled to be within
    the specified units. The size of the characters will remain the same; only
    the X-positions are scaled. When width <= 0, the width value is ignored
    and the text rendered as normal. The exact width of the rendered text
    depends not only on the width field, but also on the maximum character width
    in the rendered string. The string will be attempted to fit within the
    specified width, but if it is unable to do so, it uses the largest character
    in the string as the width. If fewer widths are specified than the number of
    strings, the strings without matching widths are rendered with default
    width.
