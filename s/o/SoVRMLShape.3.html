Description

The SoVRMLShape node holds geometry and geometry appearance nodes.

The Shape node has two fields, appearance and geometry, which are used to create rendered objects in the world. The appearance field contains an SoVRMLAppearance node that specifies the visual attributes (e.g., material and texture) to be applied to the geometry. The geometry field contains a geometry node. The specified geometry node is rendered with the specified appearance nodes applied. See 4.6.3, Shapes and geometry (http://www.web3d.org/documents/specifications/14772/V2.0/part1/concepts.html#4.6.3), and SoVRMLAppearance, for more information.

4.14, Lighting model (http://www.web3d.org/documents/specifications/14772/V2.0/part1/concepts.html#4.14), contains details of the VRML lighting model and the interaction between Appearance nodes and geometry nodes. If the geometry field is NULL, the object is not drawn.

The renderCaching and boundingBoxCaching fields control whether the geometry and its bounding box will be cached between traversals. The default is AUTO for both.

Fields

SoSFNode appearance
Contains an SoVRMLAppearance node specifying the material, texture, and other visual attributes to be applied to the geometry. If this field is NULL, the default appearance is used.
SoSFNode geometry
Contains a geometry node (e.g., SoVRMLBox, SoVRMLSphere, SoVRMLIndexedFaceSet) describing the shape of the object. If this field is NULL, the object is not drawn.
SoSFEnum renderCaching
Controls whether the geometry is cached. Legal values are:
OFF
Never cache.
ON
Always cache.
AUTO
Use heuristics to determine whether to cache.
The default value is AUTO.
SoSFEnum boundingBoxCaching
Controls whether the bounding box is cached. Legal values are the same as for renderCaching. The default value is AUTO.

SbBool affectsState (void) const [virtual]
Returns TRUE if the node could have any effect on the state during traversal.
If it returns FALSE, no data in the traversal state will change from the pre-traversal state to the post-traversal state. The SoSeparator node will for instance return FALSE, as it pushes and pops the state before and after traversal of its children. All SoShape nodes will also return FALSE, as just pushing out geometry data to the rendering engine won't affect the actual rendering state.
The default method returns TRUE, on a "better safe than sorry" philosophy.

void SoVRMLShape::copyContents (const SoFieldContainer * from, SbBool copyconnections) [virtual]

Realiza una copia profunda de todos los datos de from a esta instancia, excepto las referencias al escenario externo si copyconnections es falso.

Este es el método que debe ser sobrescrito por nodos de extensión, motores, draggers, etc., que necesitan manejar datos internos no automatizados.

Para copiar nodos desde código de aplicación, no llames a esta función directamente, sino usa el método SoNode::copy():

SoNode * mynewnode = templatenode->copy();

Lo mismo aplica para motores.

Asegúrate de que cuando sobrescribas el método copyContents() en tu clase de extensión, también lo llames hacia arriba en la jerarquía de superclases, como copyContents() en SoNode y SoFieldContainer. Deberías hacer algo como:

void
MyCoinExtensionNode::copyContents(const SoFieldContainer * from,
                                  SbBool copyconnections)
{
  // deja que las superclases hagan su trabajo (copiar campos, copiar el nombre de la instancia, etc.)
  SoNode::copyContents(from, copyconnections);
  // [..luego copia los datos internos..]
}
