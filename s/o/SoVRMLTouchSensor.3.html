Descripción Detallada

La clase SoVRMLTouchSensor rastrea la posición del puntero y envía eventos basados en la interacción del usuario.

La documentación detallada de la clase SoVRMLTouchSensor se toma verbatim de la norma VRML97 (ISO/IEC 14772-1:1997). Es copyright The Web3D Consortium y se usa con permiso del Consorcio:

TouchSensor {
  exposedField SFBool  enabled TRUE
  eventOut     SFVec3f hitNormal_changed
  eventOut     SFVec3f hitPoint_changed
  eventOut     SFVec2f hitTexCoord_changed
  eventOut     SFBool  isActive
  eventOut     SFBool  isOver
  eventOut     SFTime  touchTime
}

Un nodo TouchSensor rastrea la posición y el estado del dispositivo de entrada y detecta cuando el usuario señala en la geometría contenida en el nodo de grupo padre del TouchSensor. Un nodo TouchSensor puede ser habilitado o deshabilitado enviando un evento con valor TRUE o FALSE. Si el nodo TouchSensor está deshabilitado, no rastrea la entrada del usuario ni envía eventos.

El TouchSensor genera eventos cuando el dispositivo de entrada señala hacia cualquier nodo de geometría que sea hijo del grupo padre del TouchSensor. Para más detalles sobre el uso del dispositivo de entrada para activar el TouchSensor, véase 4.6.7.5, Activación y manipulación de sensores (http://www.web3d.org/documents/specifications/14772/V2.0/part1/concepts.html#4.6.7.5),.

El eventoOut isOver refleja el estado del dispositivo de entrada con respecto a si está señalando hacia el nodo de geometría del TouchSensor. Cuando el dispositivo de entrada cambia de estado desde una posición donde su orientación no interseca ninguna de las geometrías del TouchSensor hasta una donde sí interseca la geometría, se genera un evento isOver TRUE. Cuando el dispositivo de entrada se mueve de una posición donde su orientación interseca la geometría hasta otra donde no lo hace, o alguna otra geometría se obstaculiza la geometría del TouchSensor, se genera un evento isOver FALSE. Estos eventos se generan solo cuando el dispositivo de entrada ha movido y cambiado el estado de "sobre". Los eventos no se generan si la geometría misma está animando y moviéndose debajo del dispositivo de entrada.

Mientras el usuario mueve el dispositivo de entrada sobre la geometría del TouchSensor, se determina la posición de intersección (si existe) entre el dispositivo de entrada y la geometría. Cada movimiento del dispositivo de entrada, mientras isOver es TRUE, genera eventos hitPoint_changed, hitNormal_changed y hitTexCoord_changed. Los eventos hitPoint_changed contienen el punto 3D en la superficie de la geometría subyacente, dado en el sistema de coordenadas del TouchSensor node. Los eventos hitNormal_changed contienen el vector normal de la superficie en el punto de intersección. Los eventos hitTexCoord_changed contienen las coordenadas de textura de esa superficie en el punto de intersección. Los valores de hitTexCoord_changed y hitNormal_changed se calculan adecuadamente para el asociado shape.

Si isOver es TRUE, el usuario puede activar el dispositivo de entrada para que el TouchSensor genere eventos isActive (por ejemplo, presionando el botón principal del mouse). Cuando el TouchSensor genera un evento isActive TRUE, lo captura todo el evento de movimiento del dispositivo de entrada hasta que se libere y genera un evento isActive FALSE (otros sensores de dispositivos de entrada no generarán eventos durante este tiempo). El movimiento del dispositivo de entrada mientras isActive es TRUE se denomina un "drag". Si se está usando un dispositivo de entrada 2D, los eventos isActive reflejan el estado del botón principal asociado al dispositivo (es decir, isActive es TRUE cuando el botón principal está presionado y FALSE cuando se libera). Si se está usando un dispositivo de entrada 3D, los eventos isActive generalmente reflejan si el dispositivo de entrada está dentro (o en contacto con) la geometría del TouchSensor.

El campo touchTime del eventoOut se genera cuando se cumplen las tres condiciones siguientes:

  • El dispositivo de entrada estaba señalando hacia la geometría cuando se activó (isActive es TRUE).
  • El dispositivo de entrada está actualmente señalando hacia la geometría (isOver es TRUE).
  • El dispositivo de entrada está desactivado (evento isActive FALSE también se genera).

Más información sobre este comportamiento se describe en 4.6.7.3, Sensores de dispositivos de entrada (http://www.web3d.org/documents/specifications/14772/V2.0/part1/concepts.html#4.6.7.3), 4.6.7.4, Sensores de arrastre (http://www.web3d.org/documents/specifications/14772/V2.0/part1/concepts.html#4.6.7.4), y 4.6.7.5, Activación y manipulación de sensores (http://www.web3d.org/documents/specifications/14772/V2.0/part1/concepts.html#4.6.7.5).

El resto de esta documentación de clase no proviene de la documentación de la norma VRML97, pero fue escrita específicamente para la documentación de la API Coin3D.


Aquí está un ejemplo pequeño que muestra el uso de la clase SoVRMLTouchSensor. Haga clic en SoVRMLSphere para encender SoVRMLPointLight:

#VRML V2.0 utf8
Group {
   children [
      Transform {
         children [
            DEF light PointLight {
               intensity 1
               on FALSE
            }
            Transform {
               translation -2 0 -2
               children [
                  Shape {
                     appearance Appearance {
                        material Material {
                           diffuseColor 1 0 1
                           specularColor 1 1 1
                           shininess 0.9
                        }
                     }
                     geometry Sphere { }
                  }
                  DEF touchsensor TouchSensor { }
               ]
            }
         ]
      }
   ]
   ROUTE touchsensor.isActive TO light.set_on
}

DESCRIPTION

The VRML Touch Sensor node enables the user to interactively move objects within a VRML scene.

When the user clicks on a child geometry of the Touch Sensor, the sensor becomes active and generates events. The events generated are:

  • isActive: TRUE when the user clicks on the geometry, FALSE when the mouse button is released.
  • isOver: TRUE when the pointer moves onto the geometry, FALSE when it moves away.
  • hitPoint_changed: The point in object space where the pointer intersected the geometry.
  • hitNormal_changed: The object space normal of the geometry at the intersection point.
  • hitTexCoord_changed: The object space texture coordinate at the intersection point.
  • touchTime: The time at which the touch event occurred.

The Touch Sensor node needs to be enabled by setting the enabled field to TRUE.

The Touch Sensor node can be used to implement interactive objects in a VRML scene, such as buttons, levers, or movable objects.
