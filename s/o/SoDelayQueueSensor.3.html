Descripción detallada

La clase SoDelayQueueSensor es la clase base abstracta para sensores programados por prioridad.

Los sensores de cola de retardo se invocan ante diversos eventos *no* relacionados con ocurrencias temporales. Consulta la documentación de las subclases para ver qué tipos de eventos pueden ser supervisados por los tipos de sensores incorporados.

Los valores de prioridad pueden utilizarse para encolar eventos según su importancia, de modo que los sensores se activen en la secuencia deseada.

La cola de sensores de retardo (es decir, instancias de subclases de SoDelayQueueSensor) se procesará tan pronto como el sistema de tiempo de ejecución esté inactivo, o si está continuamente ocupado, se procesará dentro de un período de tiempo fijo.

Este intervalo de tiempo es, por defecto, 1/12 de segundo, pero puede controlarse con la interfaz SoSensorManager::setDelaySensorTimeout().

Documentación de funciones miembro

void SoDelayQueueSensor::setPriority (uint32_t pri)

Establece la prioridad de este sensor en la cola de programación. Cuando se procesan los sensores, los sensores de alta prioridad se activarán antes que los de baja prioridad.

Ten en cuenta que un número bajo significa una alta prioridad. Un sensor con prioridad 5 se activará antes que un sensor con prioridad 6.

Los sensores con prioridad 0 tienen un significado especial en Coin/Inventor. Se denominan sensores inmediatos y se activarán inmediatamente después de que finalice la cadena de notificación actual. Los sensores de prioridad 0 deben usarse con precaución, ya que podrían provocar un mal rendimiento si realizas algún procesamiento en la función de devolución de llamada del sensor.

Esta configuración no afecta a las invocaciones de devolución de llamada de eliminación de SoDataSensor, que siempre son inmediatas.

NAME

SoDelayQueueSensor - A sensor that queues events to be processed later

SYNOPSIS

Inherits from SoSensor.

Reimplemented in SoDataSensor, and SoFieldSensor.

Detailed Description

A SoDelayQueueSensor is a sensor that can be used to queue up events for later processing. This is useful when you want to perform some action, but not immediately. For example, you might want to update the scene graph after a certain amount of time has passed, or after a certain number of other events have occurred.

The sensor can be scheduled to be triggered after a specified delay, or when a specific event occurs. When the sensor is triggered, its action is performed.
