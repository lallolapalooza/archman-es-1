SbBool SoVRMLParent::affectsState (void ) const [virtual]

Devuelve TRUE si el nodo pudiera tener algún efecto en el estado durante el recorrido.

Si devuelve FALSE, ningún dato en el estado de recorrido cambiará del estado pre-recorrido al estado post-recorrido. El nodo SoSeparator, por ejemplo, devolverá FALSE, ya que empuja y saca el estado antes y después del recorrido de sus hijos. Todos los nodos SoShape también devolverán FALSE, ya que solo empujar datos de geometría al motor de renderizado no afectará el estado de renderizado real.

El método predeterminado devuelve TRUE, bajo la filosofía de "mejor prevenir que curar".

void SoVRMLParent::copyContents (const SoFieldContainer * from, SbBool copyconnections) [protected], [virtual]

Realiza una copia profunda de todos los datos de from en esta instancia, excepto las referencias externas al grafo de escena si copyconnections es FALSE.

Este es el método que debe ser anulado por las subclases de nodos de extensión / motores / arrastradores / etc. que necesiten tener en cuenta los datos internos que no se manejan automáticamente.

Para copiar nodos desde el código de la aplicación, no debe invocar esta función directamente, sino llamar a la función SoNode::copy():

SoNode * mynewnode = templatenode->copy();

Lo mismo ocurre con los motores.

Asegúrese de que al anular el método copyContents() en su clase de extensión, también llame hacia arriba a su superclase en la jerarquía de herencia, ya que copyContents() en, por ejemplo, SoNode y SoFieldContainer realiza un trabajo importante. Debería ser algo así:

void
MyCoinExtensionNode::copyContents(const SoFieldContainer * from,
                                  SbBool copyconnections)
{
  // deja que las superclases hagan lo suyo (copiar campos, copiar
  // nombre de instancia, etc.)
  SoNode::copyContents(from, copyconnections);
  // [..luego copiar datos internos..]
}
