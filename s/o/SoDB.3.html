Descripción Detallada

La clase SoDB se encarga de los datos globales internos.

•
!

Esta clase recopila varios métodos para inicializar, establecer y acceder a datos globales comunes de la biblioteca Coin.

Todos los métodos en SoDB son estáticos.

Asegúrese de llamar a SoDB::init() (directamente o indirectamente a través del método init() de la biblioteca de conexión GUI) antes de utilizar cualquier otra clase de Coin.

Documentación de Tipos de Miembro

typedef SbBool SoDB::ProgressCallbackType(const SbName &itemid, float fraction, SbBool interruptible, void *userdata)

Las funciones de callback de progreso del código cliente deben ser funciones estáticas de este tipo.

El argumento itemid es un identificador de texto único que indica qué se está procesando (úselo para cualquier texto informativo de la barra de progreso de la GUI), y fraction es un valor en el rango [0, 1] que indica hasta dónde ha llegado el proceso. Si la tarea se interrumpe exitosamente, se invocará el callback una última vez con fraction establecido en -1.0.

El valor de retorno es una indicación de bandera de interrupción del código cliente. Tenga en cuenta que el proceso que se está ejecutando solo puede interrumpirse si la bandera interruptible está activada.

Consulte SoDB::addProgressCallback() para obtener documentación completa sobre cómo funciona el mecanismo de notificación de progreso.

Documentación de Funciones Miembro

void SoDB::init (void ) [static]

Inicializa el sistema Coin. Esto debe hacerse como la primera cosa antes de empezar a usar la biblioteca, de lo contrario es probable que vea un accidente temprano.

void SoDB::finish (void ) [static]

Invoque este método como la última llamada del código de la aplicación, para activar una limpieza de todos los recursos estáticos usados por la biblioteca Coin.

Esto generalmente no es necesario para aplicaciones ejecutables autónomas, ya que el sistema operativo se encargará de la limpieza después de que el proceso finalice.

Sin embargo, puede ser necesario invocar este método para evitar fugas en entornos de ejecución "especiales", como si la biblioteca Coin se usara, por ejemplo, como un plugin de navegador, o algún otro tipo de componente que pueda iniciarse, apagarse y reiniciarse varias veces.

SoSeparator * SoDB::readAll (SoInput * in) [static]

Lee todas las graficas de in y las devuelve bajo un nodo SoSeparator. Si el archivo contiene solo una grafica bajo un nodo SoSeparator (lo cual es la forma más común de construir y exportar graficas de escena), no se crea un nodo extra SoSeparator raíz, pero el nodo raíz devuelto será el nodo más alto de la grafica del archivo.

El contador de referencias del nodo raíz separador devuelto por este método será cero. Los otros nodos en la grafica devuelta tendrán contadores de referencias según el número de relaciones padre-hijo, como usual.

La forma común de cargar, trabajar con y luego devolver los recursos de memoria de graficas de escena suele ser así:

// [snip]
SoInput in;
if (!in.openFile(filename)) { exit(1); }
SoSeparator * root = SoDB::readAll(&in);
if (!root) { exit(1); }
// nodo raíz devuelto por SoDB::readAll() tiene inicialmente cero
// contador de referencias, así que reféralo antes de comenzar a usarlo
// para evitar la destrucción prematura.
root->ref();
// [haz lo que quieras aquí -- ató la escena a un visualizador o cualquier cosa)
// Vuelve a decrementar el contador de referencias del nodo raíz para provocar la destrucción de la escena.
root->unref();
// (Cuando se auto-destruye, el nodo raíz también desreferenciará sus nodos hijos, que también se auto-destuyen, y así recursivamente hacia la jerarquía de la escena hasta que la escena completa se auto-destruya y así devuelva todos los recursos de memoria que usó.)

Devuelve NULL en caso de error.

Nota: una operación común después de importar una grafica de escena es extraer los punteros de memoria de algunos de los nodos importados para su manejo adicional. Esto puede realizarse mediante la función SoNode::getByName() (que es la opción más fácil) o mediante una instancia de la clase SoSearchAction (que es más compleja pero también más flexible).

SbBool SoDB::registerHeader (const SbString & headerstring, SbBool isbinary, float ivversion, SoDBHeaderCB * precallback, SoDBHeaderCB * postcallback, void * userdata = NULL) [static]

Registra una cadena de encabezado que debería ser reconocida por SoInput durante la importación de archivos. Este es una manera conveniente para los usuarios de bibliotecas registrar sus propios formatos de archivos VRML o derivados de Coin.

Establece isbinary a TRUE si el archivo debe leerse como datos binarios, y establece ivversion para indicar la versión de la biblioteca Coin que se necesita para leer el archivo.

Los callbacks precallback y postcallback se llamarán antes y después de la importación del formato personalizado.

Si headerstring no puede aceptarse como un encabezado de formato válido para archivos Coin, se devolverá FALSE. Una encabezado válido debe comenzar con un '#' y no exceder los 80 caracteres.

SoField * SoDB::getGlobalField (const SbName & name) [static]

Si existe un campo global con el nombre dado, devuelve un puntero a él. Si no hay un campo con este nombre, devuelve NULL.

De interés particular es el campo global de tiempo real establecido por la biblioteca durante la inicialización. Este campo se usa como fuente de campo para todos los objetos de animación autónomos dentro de la biblioteca, como por ejemplo el SoTimeCounter o el SoRotor nodo.

void SoDB::addProgressCallback (ProgressCallbackType * func, void * userdata) [static]

El concepto detrás de la información de progreso en Coin es que cualquier proceso interno que pueda tardar mucho tiempo en completarse (como, por ejemplo, la importación de archivos para escenas enormes) puede transmitir información de progreso llamando a una devolución de llamada de progreso configurada por el código de la aplicación cliente.

La firma de la función de devolución de llamada de progreso del cliente debe coincidir con SoDB::ProgressCallbackType.

El mecanismo funciona al garantizar que todas las notificaciones de progreso desde Coin deben:

1.
Usar un ID de texto único para identificar el proceso que informa el progreso (por ejemplo, "Importación de archivo" para la lectura de archivos SoDB::readAll() / SoInput, "Exportación de archivo" para SoOutput / SoWriteAction, etc.). Este es el nombre itemid que se pasa a la devolución de llamada de progreso.
2.
La primera invocación de la devolución de llamada del usuario se realizará con un valor fraction exacto de 0.0.
3.
La última invocación se realizará con un valor fraction exacto de 1.0.
4.
Una excepción a la última punto es que si el proceso se aborta, se realizará una invocación final con un valor fraction de -1.0.

Una cosa importante a tener en cuenta sobre el mecanismo es que los procesos con devoluciones de llamada de progreso pueden estar ejecutándose dentro de otros procesos que utilizan la funcionalidad de devolución de llamada de progreso. La información de progreso tendrá que considerarse "apilada", y el código cliente debe ser consciente de esto y tratarlo adecuadamente.

Esta función es una extensión para Coin y no está disponible en la API original de SGI Open Inventor v2.1.

void SoDB::readlock (void ) [static]

Coloca un bloqueo de lectura en el mutex global de SoDB. Esto se puede usar para sincronizar entre hilos que leen/escriben gráficos de escena de Coin.

Si llamas a esta función, debes asegurarte de llamar también a SoDB::readunlock(). Si no lo haces, es posible que tu aplicación se bloquee.

Todas las acciones de Coin tienen un bloqueo de lectura en el mutex global de SoDB mientras recorren el gráfico de escena.
