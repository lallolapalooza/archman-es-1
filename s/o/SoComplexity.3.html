Descripción detallada

La clase SoComplexity es un tipo de nodo que se utiliza para establecer el equilibrio entre calidad y rendimiento.

Al insertar nodos SoComplexity en el grafo de escena, puede controlar la precisión con la que se renderizan las formas complejas y la calidad del mapeo de texturas utilizado para la geometría en la escena.

Los nodos de forma como SoCone, SoSphere, SoCylinder y otros, se renderizarán con menos polígonos y mejorarán así el rendimiento, si el valor de complejidad del estado de recorrido se establece en un valor más bajo.

Utilizando el campo SoComplexity::type, también puede optar por renderizar el grafo de escena (o partes de él) simplemente como cuadros delimitadores de alambre. Esto mejorará mucho el rendimiento de la renderización y, en ocasiones, se puede utilizar en situaciones particulares en las que la capacidad de respuesta es más importante que la apariencia.

El mapeo de texturas se puede realizar de una manera costosa pero atractiva, o de una manera rápida que no es tan atractiva modificando el valor del campo SoComplexity::textureQuality. Al establecer el campo SoComplexity::textureQuality en un valor de 0.0, también puede desactivar completamente el mapeo de texturas.

FORMATO DE ARCHIVO/VALORES PREDETERMINADOS:

Complexity {
    type OBJECT_SPACE
    value 0.5
    textureQuality 0.5
}

Detailed Description

The SoComplexity node controls the complexity of rendering. It has two fields, value and textureQuality, that influence how geometry and textures are rendered.

value controls the overall complexity of the scene. A value of 1.0 means full complexity (best appearance, slowest rendering), while 0.0 means lowest complexity (worst appearance, fastest rendering). The complexity can be used to dynamically simplify the scene graph for faster rendering, for example, when the camera is far away from objects.

textureQuality controls the quality of texture mapping. A value of 1.0 means best quality (highest resolution textures, potentially slower rendering), while 0.0 means lowest quality (lowest resolution textures, potentially faster rendering). This field influences the behavior of the SoTexture2 node.

The SoComplexity node works by affecting the rendering state. When an SoAction traverses the scene graph, it will query the current SoComplexity node (if any) and adjust its rendering parameters accordingly.

It is important to note that the SoComplexity node only affects subsequent nodes in the scene graph. Therefore, its position in the scene graph matters. For example, to affect texture quality, an SoComplexity node should be placed before any SoTexture2 nodes.

Member Data Documentation

SoSFEnum SoComplexity::type

Set rendering type. Default value is SoComplexity::OBJECT_SPACE.

SoSFFloat SoComplexity::value

Complexity value, valid settings range from 0.0 (worst appearance, best performance) to 1.0 (optimal appearance, lowest rendering speed). Default value for the field is 0.5.

Note that without any SoComplexity nodes in the scene graph, geometry will render as if there was a SoComplexity node present with SoComplexity::value set to 1.0.

SoSFFloat SoComplexity::textureQuality

Sets the quality value for texture mapping. Valid range is from 0.0 (texture mapping off, rendering will be much faster for most platforms) to 1.0 (best quality, rendering might be slow).

The same value for this field on different platforms can yield varying results, depending on the quality of the underlying rendering hardware.

Note that this field influences the behavior of the SoTexture2 node, not the shape nodes. There is an important consequence of this that the application programmer need to know about: you need to insert your SoComplexity node(s) before the SoTexture2 node(s) in the scene graph for them to have any influence on the textured shapes.
