Descripción Detallada

La clase SoCache es la superclase para todas las clases de caché internas.

Organiza el conteo de referencias para hacer posible compartir instancias de caché. También organiza una lista de elementos que afectan al caché. Si algún elemento ha cambiado desde que se creó el caché, el caché queda invalidado.

El algoritmo de prueba de elementos en Coin funciona de la siguiente manera:

Cada elemento que se lee antes de ser escrito cuando se crea el caché se almacena en la lista de elementos del SoCache. Esto se hace para detectar cuándo algo fuera del caché cambia.

Por ejemplo: tienes un nodo SoCoordinate3 fuera de un SoSeparator, pero un SoIndexedFaceSet dentro del SoSeparator. Si el SoSeparator crea una caché, el SoIndexedFaceSet leerá SoCoordinateElement, y como SoCoordinateElement no ha sido establecido después de que se abrió la caché, el elemento se almacena en la lista de dependencias de la caché.

En el siguiente frame, el SoSeparator prueba si la caché es válida y luego prueba todos los elementos de dependencia. Si uno de los elementos no coincide, la caché no es válida y no se puede utilizar.

Eso es lo básico. Hay algunos pasos que debes seguir al crear una caché para que las dependencias funcionen. En resumen, debes hacerlo así:

SbBool storedinvalid = SoCacheElement::setInvalid(FALSE);
state->push();
SoMyCache * cache = new SoMyCache(state);
cache->ref();
SoCacheElement::set(state, cache);
buildMyCache();
state->pop();
SoCacheElement::setInvalid(storedinvalid);

Primero, reinicias y almacenas el valor antiguo del flag de invalidación de la caché. Luego, empujas el estado para que la caché pueda detectar cuándo algo fuera de la caché cambia (y para poder cambiar el elemento de la caché). Luego, creas la caché; no olvides referenciarla. Finalmente, estableces el elemento actual de la caché y construyes la caché. Después de construir la caché, sacas el estado y restauras el valor del flag de invalidación.

Cuando construyes la caché, todos los elementos que se leen se copian en la caché (usando SoElement::copyMatchInfo()), y estos elementos copiados se utilizan para probar la validez de la caché (en SoCache::isValid()).

No tienes que añadir manualmente las dependencias de los elementos. Estas se recogen automáticamente cuando se crea la caché. Esto se maneja en SoElement::getConstElement().

Si quieres que la caché se invalide cuando un campo dentro de tu nodo cambia, es común sobrescribir el método notify() y llamar a SoCache::invalidate() cuando se llama al método notify() de tu nodo. Mira por ejemplo SoShape::notify().

Además, no debes borrar la caché en tu método notify(). Debes esperar hasta la próxima vez que se necesite la caché antes de desreferenciar la caché antigua.
