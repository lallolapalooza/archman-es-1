Descripción Detallada

La clase SoVRMLViewpoint es una clase de cámara de perspectiva.

La documentación detallada de la clase se toma textualmente del estándar VRML97 (ISO/IEC 14772-1:1997). Tiene derechos de autor del Web3D Consortium y se utiliza con permiso del Consortium:

Viewpoint {
  eventIn      SFBool     set_bind
  exposedField SFFloat    fieldOfView    0.785398  # (0,inf)
  exposedField SFBool     jump           TRUE
  exposedField SFRotation orientation    0 0 1 0   # [-1,1],(-inf,inf)
  exposedField SFVec3f    position       0 0 10    # (-inf,inf)
  field        SFString   description    ""
  eventOut     SFTime     bindTime
  eventOut     SFBool     isBound
}

El nodo Viewpoint define una ubicación específica en el sistema de coordenadas local desde la cual el usuario puede ver la escena. Los nodos Viewpoint son nodos hijos enlazables (ver 4.6.10, Nodos hijos enlazables: http://www.web3d.org/documents/specifications/14772/V2.0/part1/concepts.html#4.6.10) y por lo tanto existe una pila de nodos Viewpoint en el navegador en la cual el nodo Viewpoint superior en la pila es el nodo Viewpoint activo actual. Si se envía un valor TRUE al evento set_bind de un nodo Viewpoint, este se mueve a la parte superior de la pila de nodos Viewpoint y se activa. Cuando un nodo Viewpoint está en la parte superior de la pila, la vista del usuario se re-padrina conceptualmente como un hijo del nodo Viewpoint. Todos los cambios posteriores en el sistema de coordenadas del nodo Viewpoint cambian la vista del usuario (por ejemplo, cambios en cualquier nodo de transformación ancestral o en los campos de posición u orientación del nodo Viewpoint). Enviar un evento set_bind FALSE elimina el nodo Viewpoint de la pila y produce eventos isBound FALSE y bindTime. Si el nodo Viewpoint extraído está en la parte superior de la pila de viewpoints, la vista del usuario se re-padrina a la siguiente entrada en la pila. Se pueden encontrar más detalles sobre las pilas de enlaces en 4.6.10, Nodos hijos enlazables (http://www.web3d.org/documents/specifications/14772/V2.0/part1/concepts.html#4.6.10). Cuando un nodo Viewpoint se mueve a la parte superior de la pila, el nodo Viewpoint superior existente envía un evento isBound FALSE y se empuja hacia abajo en la pila.

Un autor puede mover automáticamente la vista del usuario a través del mundo enlazando al usuario a un nodo Viewpoint y luego animando el nodo Viewpoint o las transformaciones por encima de él. Los navegadores permitirán que la vista del usuario se navegue en relación con el sistema de coordenadas definido por el nodo Viewpoint (y las transformaciones por encima de él) incluso si las transformaciones del nodo Viewpoint o sus ancestros se están animando.

El evento out bindTime envía el tiempo en el que el nodo Viewpoint se enlaza o desenlaza. Esto puede ocurrir:

  • durante la carga;
  • cuando se envía un evento set_bind al nodo Viewpoint;
  • cuando el navegador se enlaza al nodo Viewpoint a través de su interfaz de usuario descrita a continuación.

Los campos de posición y orientación del nodo Viewpoint especifican ubicaciones relativas en el sistema de coordenadas local. La posición es relativa al origen del sistema de coordenadas (0,0,0), mientras que la orientación especifica una rotación relativa a la orientación predeterminada. En la posición y orientación predeterminadas, el espectador está en el eje Z mirando hacia el eje -Z hacia el origen con +X a la derecha y +Y hacia arriba. Los nodos Viewpoint se ven afectados por la jerarquía de transformación.

Los tipos de navegación (ver SoVRMLNavigationInfo) que requieren una definición de un vector hacia abajo (por ejemplo, seguimiento del terreno) utilizarán el eje Y negativo del sistema de coordenadas del nodo Viewpoint enlazado actualmente. Del mismo modo, los tipos de navegación que requieren una definición de un vector hacia arriba utilizarán el eje Y positivo del sistema de coordenadas del nodo Viewpoint enlazado actualmente. El campo de orientación del nodo Viewpoint no afecta la definición de los vectores hacia abajo o hacia arriba. Esto permite al autor separar la dirección de visualización de la dirección de la gravedad.

El campo jump especifica si la vista del usuario "salta" a la posición y orientación de un nodo Viewpoint enlazado o permanece sin cambios. Este salto es instantáneo y discontinuo, ya que no se realizan colisiones y no se comprueban nodos ProximitySensor entre el punto de inicio y el punto de finalización del salto. Si la posición del usuario antes del salto está dentro de un ProximitySensor, el exitTime de ese sensor enviará la misma marca de tiempo que el evento bindIn. Del mismo modo, si la posición del usuario después del salto está dentro de un ProximitySensor, el enterTime de ese sensor enviará la misma marca de tiempo que el evento bindIn. Independientemente del valor de jump en el momento del enlace, la transformación de visualización relativa entre la vista del usuario y el nodo Viewpoint actual se almacenará con el nodo Viewpoint actual para su uso posterior al desenganchar (es decir, al extraer el nodo Viewpoint de la pila de enlaces de un nodo Viewpoint con jump TRUE). Lo siguiente resume las reglas de la pila de enlaces (ver 4.6.10, Nodos hijos enlazables: http://www.web3d.org/documents/specifications/14772/V2.0/part1/concepts.html#4.6.10) con reglas adicionales relacionadas con los nodos Viewpoint (mostradas en negrita):

  • Durante la lectura, el primer nodo Viewpoint encontrado se enlaza empujándolo a la parte superior de la pila de nodos Viewpoint. Si se especifica un nombre de nodo Viewpoint en la URL que se está leyendo, este nodo Viewpoint con nombre se considera el primer nodo Viewpoint encontrado. Los nodos contenidos dentro de nodos SoVRMLInline, dentro de las cadenas pasadas al método Browser.createVrmlFromString(), o dentro de archivos pasados al método Browser.createVrmlFromURL() (ver 4.12.10, Interfaz de script del navegador: http://www.web3d.org/documents/specifications/14772/V2.0/part1/concepts.html#4.12.10) no son candidatos para el primer nodo Viewpoint encontrado. El primer nodo dentro de una instancia de prototipo es un candidato válido para el primer nodo Viewpoint encontrado. El primer nodo Viewpoint encontrado envía un evento isBound TRUE.
    • Cuando un nodo Viewpoint recibe un evento set_bind TRUE,
    •
    Si no está en la cima de la pila: La transformación relativa desde el nodo Viewpoint superior de la pila hasta la vista del usuario se almacena con el nodo Viewpoint superior de la pila actual. El nodo superior de la pila actual envía un evento isBound FALSE. El nuevo nodo se mueve a la cima de la pila y se convierte en el nodo Viewpoint actualmente enlazado. El nuevo nodo Viewpoint (superior de la pila) envía un evento isBound TRUE. Si jump es TRUE para el nuevo nodo Viewpoint, la vista del usuario se "salta" instantáneamente para que coincida con los valores en los campos de posición y orientación del nuevo nodo Viewpoint.
    •
    Si el nodo ya está en la cima de la pila, este evento no tiene ningún efecto.
    •
    Cuando un nodo Viewpoint en la pila recibe un evento set_bind FALSE, se elimina de la pila. Si estaba en la cima de la pila,
    •
    envía un evento isBound FALSE,
    •
    el siguiente nodo en la pila se convierte en el nodo Viewpoint actualmente enlazado (es decir, se extrae) y emite un evento isBound TRUE,
    •
    si el valor de su campo jump es TRUE, la vista del usuario se "salta" instantáneamente a la posición y orientación del siguiente nodo Viewpoint en la pila con la transformación relativa almacenada de este siguiente nodo Viewpoint aplicada.
    • Si un nodo no presente en la pila recibe un evento set_bind FALSE, el evento se ignora y no se envían eventos isBound.
    • Cuando un nodo reemplaza a otro nodo en la cima de la pila, los eventos isBound TRUE y FALSE de los dos nodos se envían simultáneamente (es decir, con marcas de tiempo idénticas).
    • Si se elimina un nodo enlazado, se comporta como si hubiera recibido un evento set_bind FALSE.

    El campo jump puede cambiar después de que un nodo Viewpoint esté enlazado. Las reglas descritas anteriormente siguen aplicándose. Si jump era TRUE cuando el nodo Viewpoint se enlazó, pero cambió a FALSE antes de que se enviara el set_bind FALSE, el nodo Viewpoint no se desenfoca durante el unbind. Si jump era FALSE cuando el nodo Viewpoint se enlazó, pero cambió a TRUE antes de que se enviara el set_bind FALSE, el nodo Viewpoint realiza el desenfoque durante el unbind.

    Tenga en cuenta que existen otros dos mecanismos que resultan en el enlace de un nuevo Viewpoint:

    • El campo url de un nodo Anchor especifica un "#NombreViewpoint".
    • Un script invoca el método loadURL() y el argumento URL especifica un "#NombreViewpoint".

    Ambos mecanismos anulan el valor del campo jump del nodo Viewpoint especificado ("#NombreViewpoint") y asumen que jump es TRUE al enlazar al nuevo Viewpoint. El comportamiento de la transición del visor al Viewpoint recién enlazado depende del valor del campo type del nodo NavigationInfo actualmente enlazado (ver SoVRMLNavigationInfo).

    El campo fieldOfView especifica un ángulo de visión mínimo preferido desde este punto de vista en radianes. Un campo de visión pequeño corresponde aproximadamente a un teleobjetivo; un campo de visión grande corresponde aproximadamente a un gran angular. El campo de visión debe ser mayor que cero y menor que . El valor de fieldOfView representa el ángulo de visión mínimo en cualquier eje de dirección perpendicular a la vista. Por ejemplo, un navegador con una proyección de visualización rectangular debe tener la siguiente relación:

        display width    tan(FOVhorizontal/2)
    -------------- = -----------------
    display height   tan(FOVvertical/2)

    donde el menor de ancho y alto de la pantalla determina qué ángulo es igual a fieldOfView (el ángulo mayor se calcula utilizando la relación descrita anteriormente). El ángulo mayor no debe exceder y puede forzar que el ángulo menor sea menor que fieldOfView para mantener la relación de aspecto.

    El campo description especifica una descripción textual del nodo Viewpoint. Esto puede ser utilizado por interfaces de usuario específicas del navegador. Si el campo description de un Viewpoint está vacío, se recomienda que el navegador no presente este Viewpoint en su interfaz de usuario específica del navegador.

    La sintaxis URL ".../scene.wrl#NombreViewpoint" especifica la vista inicial del usuario al cargar "scene.wrl" para que sea el primer nodo Viewpoint en el archivo VRML que aparece como DEF NombreViewpoint Viewpoint {...}. Esto anula el primer nodo Viewpoint en el archivo VRML como la vista inicial del usuario, y se envía un mensaje set_bind TRUE al nodo Viewpoint llamado "NombreViewpoint". Si no se encuentra el nodo Viewpoint llamado "NombreViewpoint", el navegador deberá utilizar el primer nodo Viewpoint en el archivo VRML (es decir, el comportamiento predeterminado normal). La sintaxis URL "#NombreViewpoint" (es decir, sin nombre de archivo) especifica un punto de vista dentro del archivo VRML existente. Si se carga esta URL (por ejemplo, el campo url del nodo Anchor o el método loadURL() es invocado por un nodo Script), se enlaza el nodo Viewpoint llamado "NombreViewpoint" (se envía un evento set_bind TRUE a este nodo Viewpoint).

    Los resultados no están definidos si un nodo Viewpoint se enlaza y es hijo de un LOD, Switch, o cualquier nodo o prototipo que deshabilite a sus hijos. Si se enlaza un nodo Viewpoint que resulta en una colisión con geometría, el navegador deberá realizar sus ajustes de navegación autodefinidos como si el usuario hubiera navegado hasta este punto (ver SoVRMLCollision).

SoVRMLViewpoint — Open Inventor VRML Viewpoint node.

NAME

SoVRMLViewpoint — Open Inventor VRML Viewpoint node.

SYNOPSIS

The SoVRMLViewpoint node specifies a viewpoint in the VRML scene.

A viewpoint defines a position and orientation from which the scene can be viewed. It also supports camera parameters such as the field of view and the near and far clipping planes.

The SoVRMLViewpoint node is derived from the SoViewpoint node, so it inherits all of its fields and behavior.

The following fields are specific to the SoVRMLViewpoint node:

  • jump: A boolean value that specifies whether the viewpoint should cause the camera to jump directly to the viewpoint's position and orientation. If jump is TRUE, the camera will immediately move to the viewpoint. If jump is FALSE, the camera will smoothly interpolate to the viewpoint over time.
  • fieldOfView: A float value that specifies the field of view of the camera in degrees. This value determines how much of the scene is visible from the current viewpoint. A smaller value results in a narrower field of view (like a telephoto lens), while a larger value results in a wider field of view (like a wide-angle lens).
  • nearDistance: A float value that specifies the distance to the near clipping plane. Objects closer to the camera than this distance will not be rendered.
  • farDistance: A float value that specifies the distance to the far clipping plane. Objects farther from the camera than this distance will not be rendered.
  • position: A 3D vector that specifies the position of the viewpoint in world coordinates.
  • orientation: A quaternion that specifies the orientation of the viewpoint in world coordinates.

Detailed Description

The SoVRMLViewpoint node is used to define a specific camera position and orientation within a 3D scene. It allows you to set up predefined views that users can switch to, enhancing navigation and exploration of the virtual environment.

Key characteristics of the SoVRMLViewpoint node include:

  • Predefined Views: You can define multiple SoVRMLViewpoint nodes in a scene to offer users a selection of interesting perspectives.
  • Camera Control: It directly controls the camera's position, orientation, field of view, and clipping planes, providing fine-grained control over what is visible and how it is rendered.
  • VRML Compatibility: As the name suggests, this node is designed to be compatible with the Virtual Reality Modeling Language (VRML) standard, ensuring interoperability with VRML viewers and tools.
  • Jump Behavior: The jump field is particularly useful for instant transitions between viewpoints, which can be important for certain types of interactive experiences.

Example Usage:

SoVRMLViewpoint {
    position 0 1 5
    orientation 0 0 1 0
    fieldOfView 45
    nearDistance 0.1
    farDistance 1000
    jump TRUE
}

In this example, a viewpoint is created at the position (0, 1, 5) with no rotation. The field of view is set to 45 degrees, and the near and far clipping planes are set to 0.1 and 1000 units, respectively. The jump field is set to TRUE, meaning that when this viewpoint is activated, the camera will instantly move to this position and orientation.
