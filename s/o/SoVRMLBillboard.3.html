DESCRIPCIÓN

El nodo SoVRMLBillboard es una extensión del nodo SoGroup. Su propósito es rotar todos sus nodos hijos para que siempre miren al observador (el punto de vista).

El atributo SoVRMLBillboard se aplica al nodo hijo que le sigue. En un archivo VRML, esto puede ser especificado con un campo especial, llamado el nodo.

Este nodo no tiene campos propios; su comportamiento se define completamente por su función.

Para que un nodo sea un nodo de "cartelera", debe ser el primer nodo después del nodo billboard. Si este primer nodo es un grupo, todos los nodos dentro de ese grupo se verán afectados por el billboard. Un nodo billboard puede tener cualquier número de hijos, pero solo el primer nodo (o grupo de nodos) se verá afectado. Los nodos subsiguientes después de la primera rama no se verán afectados por el billboard.

El nodo SoVRMLBillboard rotará para encarar al punto de vista en cada fotograma, antes de que se renderice la escena. Las rotaciones se realizan alrededor del eje Y.

Esto se usa comúnmente para cosas como texto 2D en un mundo 3D, para que siempre sea visible para el usuario.

El nodo SoVRMLBillboard es una clase abstracta. En VRML, los nodos de cartelera se implementan típicamente como nodos normales que tienen un campo adicional llamado “children”. Los nodos de cartelera se utilizan de forma natural en VRML, pero como son tan útiles, se han incluido en la biblioteca Coin.

No se puede crear directamente una instancia de SoVRMLBillboard. En su lugar, debe utilizar un nodo derivado, como SoVRMLBillboard.

La clase SoVRMLBillboard se hereda de la clase base SoVRMLParent, que proporciona la funcionalidad para manejar hijos. Para más información sobre cómo manejar hijos, consulte la página del manual de SoVRMLParent.

Para información sobre el manejo de acciones, consulte SoAction.

Descripción Detallada

La clase SoVRMLBillboard se utiliza para rotar geometría hacia el punto de vista.

La documentación detallada de la clase se toma textualmente del estándar VRML97 (ISO/IEC 14772-1:1997). Es copyright del Web3D Consortium, y se utiliza con permiso del Consorcio:

Billboard {
  eventIn      MFNode   addChildren
  eventIn      MFNode   removeChildren
  exposedField SFVec3f  axisOfRotation 0 1 0     # (-inf, inf)
  exposedField MFNode   children       []
  field        SFVec3f  bboxCenter     0 0 0     # (-inf, inf)
  field        SFVec3f  bboxSize       -1 -1 -1  # (0, inf) or -1,-1,-1
}

El nodo Billboard es un nodo de agrupación que modifica su sistema de coordenadas para que el eje Z local del nodo Billboard apunte hacia el espectador. El nodo Billboard tiene hijos que pueden ser otros nodos hijos. El campo axisOfRotation especifica qué eje se utilizará para realizar la rotación. Este eje se define en el sistema de coordenadas local. Cuando el campo axisOfRotation no es (0, 0, 0), los siguientes pasos describen cómo rotar el billboard para que mire al espectador:

•
a. Calcular el vector desde el origen del nodo Billboard hasta la posición del espectador. Este vector se llama vector billboard-a-espectador.
•
b. Calcular el plano definido por el axisOfRotation y el vector billboard-a-espectador.
•
c. Rotar el eje Z local del billboard hacia el plano de b., pivotando alrededor del axisOfRotation.

Cuando el campo axisOfRotation se establece en (0, 0, 0), se indica el caso especial de alineación con el espectador. En este caso, el objeto rota para mantener el eje Y local del billboard paralelo al eje Y del espectador. Este caso especial se distingue estableciendo el axisOfRotation en (0, 0, 0). Los siguientes pasos describen cómo alinear el eje Y del billboard con el eje Y del espectador:

•
d. Calcular el vector billboard-a-espectador.
•
e. Rotar el eje Z del billboard para que sea colineal con el vector billboard-a-espectador y apuntando hacia la posición del espectador.
•
f. Rotar el eje Y del billboard para que sea paralelo y esté orientado en la misma dirección que el eje Y del espectador.

Si el axisOfRotation y la línea billboard-a-espectador son coincidentes, el plano no se puede establecer y la rotación resultante del billboard no está definida. Por ejemplo, si el axisOfRotation se establece en (0,1,0) (eje Y) y el espectador vuela sobre el billboard y mira directamente hacia abajo por el eje Y, los resultados no están definidos. Múltiples instancias de nodos Billboard (DEF/USE) funcionan como se espera: cada instancia rota en su sistema de coordenadas único para mirar al espectador. La subsección 4.6.5, Nodos de agrupación e hijos (http://www.web3d.org/documents/specifications/14772/V2.0/part1/concepts.html#4.6.5), proporciona una descripción de los campos y eventos 'children', 'addChildren' y 'removeChildren'. Los campos bboxCenter y bboxSize especifican un cuadro límite que encierra a los hijos del nodo Billboard. Esto es una pista que puede utilizarse para fines de optimización. Los resultados no están definidos si el cuadro límite especificado es menor que el cuadro límite real de los hijos en cualquier momento. Un valor predeterminado de bboxSize, (-1, -1, -1), implica que el cuadro límite no está especificado y, si es necesario, deberá ser calculado por el navegador. Una descripción de th

e bboxCenter y bboxSize están contenidos en 4.6.4, Bounding boxes (http://www.web3d.org/documents/specifications/14772/V2.0/part1/concepts.html#4.6.4),

El siguiente ejemplo de escena VRML es una simple ilustración de cómo SoVRMLBillboard::axisOfRotation restringe la rotación alrededor del vector dado:

#VRML V2.0 utf8
Transform {
   translation -2 0 0
   children [
      Billboard {
        children [ Box { } ]
      }
   ]
}
Transform {
   translation 2 0 0
   children [
      Billboard {
        axisOfRotation 0 1 0
        children [ Box { } ]
      }
   ]
}
Transform {
   translation 0 -2 0
   children [ Box { size 10 0.1 10 } ]
}
