Descripción Detallada

La clase SoNodeKitListPart es un nodo de contenedor.

Este nodo es básicamente un nodo de contenedor con estas diferencias versus otros nodos de grupo:

1.
Es posible crear una lista de los tipos de nodo que son permitidos como hijos.
2.
Se puede seleccionar libremente qué tipo de comportamiento de nodo de grupo deseas que este contenedor tenga. El comportamiento por defecto es actuar como un SoGroup nodo, pero con el uso de SoNodeKitListPart::setContainerType(), puedes cambiar el comportamiento para que actúe como un separador, un switch o cualquier otro tipo de nodo que herede SoGroup.

Puede ser necesario obtener el nodo de contenedor, por ejemplo, para cambiar SoSwitch::whichChild si el nodo de contenedor es un SoSwitch. El nodo de contenedor está ubicado en la primera posición de sus hijos, es decir, (*getChildren())[0]. Nota que getNumChildren() devuelve 0, mientras que getChildren()->getLength() devuelve 1 después de la inicialización. El primero devuelve sus nodos internos de grupo, mientras que el segundo devuelve todos los nodos que contienen el nodo de contenedor.

SoGroup, SoSeparator, SoSwitch

Detailed Description

A node which is a list of other nodes. This class is intended as a base class for nodes which contain a list of other nodes. It inherits functionality for managing children from SoNode.

The node itself doesn't contain any fields, but it manages a list of children.

The primary purpose of this class is to simplify the implementation of compound nodes.

A specific example is the SoNodeKit class, which uses this class to manage its list of component nodes.

void SoNodeKitListPart::copyContents (const SoFieldContainer * from, SbBool copyconnections) [protected], [virtual]

Makes a deep copy of all data of from into this instance, except external scene graph references if copyconnections is FALSE.

This is the method that should be overridden by extension node / engine / dragger / whatever subclasses which need to account for internal data that are not handled automatically.

For copying nodes from application code, you should not invoke this function directly, but rather call the SoNode::copy() function:

SoNode * mynewnode = templatenode->copy();

The same also goes for engines.

Make sure that when you override the copyContents() method in your extension class that you also make it call upwards to its parent superclass in the inheritance hierarchy, as copyContents() in for instance SoNode and SoFieldContainer does important work. It should go something like this:

void
MyCoinExtensionNode::copyContents(const SoFieldContainer * from,
                                  SbBool copyconnections)
{
  // let parent superclasses do their thing (copy fields, copy
  // instance name, etc.)
  SoNode::copyContents(from, copyconnections);
  // [..then copy internal data..]
}
