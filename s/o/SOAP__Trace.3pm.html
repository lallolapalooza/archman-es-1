SOAP::Trace(3) Documentación aportada por usuarios de Perl SOAP::Trace(3)

NOMBRE

SOAP::Trace - utilizado solo para gestionar y manipular el rastreo de ejecución en tiempo real dentro del kit de herramientas

DESCRIPCIÓN

Esta clase no tiene métodos ni objetos. Se utiliza solo para gestionar y manipular el rastreo de ejecución en tiempo real dentro del kit de herramientas. En ausencia de métodos, esta sección revisa los eventos que pueden ser configurados y las formas de configurarlos.

SINOPSIS

El rastreo se habilita mediante la importación del método SOAP::Lite. Esto se hace normalmente en la compilación, aunque puede hacerse explícitamente llamando a import directamente. Los comandos para configurar el rastreo empiezan con la palabra clave +trace. Alternativamente, +debug también puede usarse; son intercambiables. Después de la palabra clave inicial, se pueden especificar una o más de las señales detalladas aquí, opcionalmente con un callback para manejarlos. Cuando se especifican múltiples señales para ser manejadas por un único callback, es suficiente listar todas ellas primero, seguida finalmente por el callback, como en:

use SOAP::Lite +trace =>
  method => fault => \&message_level,
  trace => objects => \&lower_level;

En el fragmento, la referencia a message_level se instala como callback para las señales method y fault, mientras que lower_level se instala para las señales trace y object. Si no se proporcionan callbacks explícitamente, la acción de rastreo por defecto es registrar un mensaje en el descriptor de archivo STDOUT de Perl. Los callbacks deben esperar uno o más argumentos pasados, aunque el tipo de los argumentos varía según la señal.

Cualquier señal puede deshabilitarse prefijando el nombre con un guion, como -result. Esto es útil con la pseudosignal "all" que es una abreviatura de la lista completa de señales. El siguiente fragmento deshabilita solo las dos señales, mientras aún habilita el resto:

SOAP::Lite->import(+trace => all => -result => -parameters);

Si la palabra clave +trace (o +debug) se usa sin señales especificadas, habilita todas las señales (como si todas fueran implícitas).

Las señales y su significado siguen. Cada una también lleva una nota sobre si la señal es relevante para una aplicación servidor, cliente o ambas.

SEÑALES DE RASTREO

transport Solo cliente
Se desencadena en la capa de transporte justo antes de enviar una solicitud y inmediatamente después de recibir una respuesta. Cada vez que la señal se envía, el único argumento para el callback es el objeto relevante. En solicitudes, este es un objeto HTTP::Request; para respuestas, es un objeto HTTP::Response.
dispatch Solo servidor
Se desencadena con el nombre completo del método que se está ejecutando, justo antes de pasar el control al método. Actualmente está desactivado en SOAP::Lite 0.55.
result Solo servidor
Se desencadena después de que el método ha sido ejecutado y recibe los resultados devueltos desde el método como una lista. Los valores de resultado no han sido serializados cuando se envía esta señal.
parameters Solo servidor
Se desencadena antes de que el método se ejecute realmente, con los datos que se espera para la llamada. Los parámetros del método se envían como una lista, después de haber sido deserializados en datos Perl.
headers Solo servidor
Esta señal debería ser para desencadenarse en los encabezados de un mensaje entrante, pero no está implementada desde SOAP::Lite 0.55.
objects Cliente o servidor
Destaca cuando se instancian o destruyen objetos. Se desencadena en los métodos new y DESTROY de las clases de SOAP::Lite.
method Cliente o servidor
Se desencadena con la lista de argumentos cuando se invoca el método envelope de SOAP::Serializer con un argumento inicial de método. El string inicial en sí no se pasa al callback.
fault Cliente o servidor
Como con la señal method anterior, excepto que esta señal se desencadena cuando SOAP::Serializer::envelope se invoca con un argumento inicial de fault.
freeform Cliente o servidor
Similar a las dos anteriores, esta señal se desencadena cuando se invoca el método SOAP::Serializer::envelope con un parámetro inicial de freeform. Esta sintaxis se usa cuando el método está creando objetos SOAP::Data a partir de datos de entrada libres.
trace Cliente o servidor
Se desencadena en el punto de entrada de muchas de las funciones más significativas. No todas las funciones dentro de las clases de SOAP::Lite desencadenan esta señal. Aquellas que lo hacen son principalmente las funciones visibles descritas en las descripciones de interfaz de las clases.
debug Cliente o servidor
Utilizada en los módulos de transporte para rastrear el contenido de las solicitudes y respuestas (como strings ordinarios, no como objetos) en diferentes puntos.

EJEMPLOS

SELECCIONAR LAS SEÑALES A RASTREAR

El siguiente fragmento de código habilita el rastreo para todas las señales:

use SOAP::Lite +trace => 'all';

Puedes deshabilitar el rastreo para un conjunto de señales especificando el nombre de la señal con un guion. Por lo tanto, si deseas habilitar el rastreo para todas las señales excepto las señales de transporte, usarías el código siguiente:

use SOAP::Lite +trace => [ qw(all -transport) ];

REGISTRAR SEÑALES EN UN ARCHIVO

Opcionalmente, puedes proporcionar una subrutina o callback a cada señal de rastreo que declares. Cada vez que se recibe una señal, se pasa al callback correspondiente. Por ejemplo, el siguiente código registra todas las señales de fault en un archivo llamado fault.log:

use SOAP::Lite +trace => [ fault => \&log_faults ];
sub log_faults {
  open LOGFILE,">fault.log";
  print LOGFILE, $_[0] . "\n";
  close LOGFILE;
}

También puedes usar un único callback para múltiples señales con el código siguiente:

use SOAP::Lite +trace => [ method, fault => \&log ];

REGISTRAR LOS CONTENIDOS DE LOS MENSAJES

La señal transport es única en que la señal no es una cadena de texto, sino el objeto HTTP::Request que se envía (antes de ser enviado) o el objeto HTTP::Response (inmediatamente después de haber sido recibido). El siguiente ejemplo muestra cómo usar esto:

use SOAP::Lite +trace => [ transport => \&log_message ];
sub log_message {
  my ($in) = @_;
  if (class($in) eq "HTTP::Request") {
    # hacer algo...
    print $in->contents; # ...ejemplo
  } elsif (class($in) eq "HTTP::Response") {
    # hacer algo
  }
}

ON_DEBUG

El método "on_debug" está disponible, como en:

use SOAP::Lite;
my $client = SOAP::Lite
  ->uri($NS)
  ->proxy($HOST)
  ->on_debug( sub { print @_; } );
