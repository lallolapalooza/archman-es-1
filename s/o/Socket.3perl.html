NOMBRE

"Socket" - constantes de red y funciones de soporte

SINOPSIS

"Socket" es un módulo de bajo nivel utilizado por, entre otras cosas, la familia de módulos IO::Socket. Los siguientes ejemplos demuestran algunos usos de bajo nivel, pero un programa práctico probablemente usaría la API de nivel superior proporcionada por "IO::Socket" o similar en su lugar.

use Socket qw(PF_INET SOCK_STREAM pack_sockaddr_in inet_aton);
socket(my $socket, PF_INET, SOCK_STREAM, 0)
    or die "socket: $!";
my $port = getservbyname "echo", "tcp";
connect($socket, pack_sockaddr_in($port, inet_aton("localhost")))
    or die "connect: $!";
print $socket "Hello, world!\n";
print <$socket>;

Ver también la sección "EJEMPLOS".

DESCRIPCIÓN

Este módulo proporciona una variedad de constantes, manipuladores de estructuras y otras funciones relacionadas con la red basada en sockets. Los valores y funciones proporcionados son útiles cuando se utilizan junto con funciones principales de Perl como socket(), setsockopt() y bind(). También proporciona varias otras funciones de soporte, principalmente para tratar con conversiones de direcciones de red entre formas legibles por humanos y binarias nativas, y para operaciones de resolución de nombres de host.

Algunas constantes y funciones son exportadas por defecto por este módulo; pero por compatibilidad retroactiva, los símbolos añadidos recientemente no se exportan por defecto y deben solicitarse explícitamente. Cuando se proporciona una lista de importación a la línea "use Socket", las exportaciones por defecto no se importan automáticamente. Por lo tanto, es una buena práctica listar siempre explícitamente todos los símbolos requeridos.

Además, se proporcionan algunas constantes comunes de "nueva línea" de sockets: las constantes "CR", "LF" y "CRLF", así como $CR, $LF y $CRLF, que se mapean a "\015", "\012" y "\015\012". Si no desea utilizar los caracteres literales en sus programas, utilice las constantes aquí proporcionadas. No se exportan por defecto, pero se pueden importar individualmente y con la etiqueta de exportación ":crlf":

use Socket qw(:DEFAULT :crlf);
$sock->print("GET / HTTP/1.0$CRLF");

Todo el subsistema getaddrinfo() se puede exportar usando la etiqueta ":addrinfo"; esto exporta las funciones getaddrinfo() y getnameinfo(), y todas las constantes "AI_*", "NI_*", "NIx_*" y "EAI_*".

CONSTANTES

En cada uno de los siguientes grupos, puede haber muchas más constantes proporcionadas que solo las dadas como ejemplos en el encabezado de la sección. Si el encabezado termina en "...", esto significa que es probable que haya más; las constantes exactas proporcionadas dependerán del sistema operativo y de las cabeceras encontradas en tiempo de compilación.

PF_INET, PF_INET6, PF_UNIX, ...

Constantes de familia de protocolos para usar como primer argumento a socket() o el valor de la opción de socket "SO_DOMAIN" o "SO_FAMILY".

AF_INET, AF_INET6, AF_UNIX, ...

Constantes de familia de direcciones utilizadas por las estructuras de direcciones de socket, para pasar a funciones como inet_pton() o getaddrinfo(), o que son devueltas por funciones como sockaddr_family().

SOCK_STREAM, SOCK_DGRAM, SOCK_RAW, ...

Constantes de tipo de socket para usar como segundo argumento a socket(), o el valor de la opción de socket "SO_TYPE".

SOCK_NONBLOCK. SOCK_CLOEXEC

Atajos específicos de Linux para especificar las banderas "O_NONBLOCK" y "FD_CLOEXEC" durante una llamada socket(2).

socket( my $sockh, PF_INET, SOCK_DGRAM|SOCK_NONBLOCK, 0 )

SOL_SOCKET

Constante de nivel de opción de socket para setsockopt() y getsockopt().

SO_ACCEPTCONN, SO_BROADCAST, SO_ERROR, ...

Constantes de nombre de opción de socket para setsockopt() y getsockopt() en el nivel "SOL_SOCKET".

IP_OPTIONS, IP_TOS, IP_TTL, ...

Constantes de nombre de opción de socket para opciones de socket IPv4 en el nivel "IPPROTO_IP".

IP_PMTUDISC_WANT, IP_PMTUDISC_DONT, ...

Constantes de valor de opción de socket para la opción de socket "IP_MTU_DISCOVER".

IPTOS_LOWDELAY, IPTOS_THROUGHPUT, IPTOS_RELIABILITY, ...

Constantes de valor de opción de socket para la opción de socket "IP_TOS".

MSG_BCAST, MSG_OOB, MSG_TRUNC, ...

Constantes de bandera de mensaje para send() y recv().

SHUT_RD, SHUT_RDWR, SHUT_WR

Constantes de dirección para shutdown().

INADDR_ANY, INADDR_BROADCAST, INADDR_LOOPBACK, INADDR_NONE

Constantes que dan las direcciones especiales "AF_INET" para comodín, difusión, bucle local y direcciones inválidas.

Normalmente equivalente a inet_aton('0.0.0.0'), inet_aton('255.255.255.255'), inet_aton('localhost') y inet_aton('255.255.255.255') respectivamente.

IPPROTO_IP, IPPROTO_IPV6, IPPROTO_TCP, ...

Constantes de protocolo IP para usar como tercer argumento a socket(), el argumento de nivel para getsockopt() o setsockopt(), o el valor de la opción de socket "SO_PROTOCOL".

TCP_CORK, TCP_KEEPALIVE, TCP_NODELAY, ...

Constantes de nombre de opción de socket para opciones de socket TCP en el nivel "IPPROTO_TCP".

IN6ADDR_ANY, IN6ADDR_LOOPBACK

Constantes que dan las direcciones especiales "AF_INET6" para comodín y bucle local.

Normalmente equivalente a inet_pton(AF_INET6, "::") y inet_pton(AF_INET6, "::1") respectivamente.

MANIPULADORES DE ESTRUCTURAS

Las siguientes funciones convierten entre listas de valores Perl y cadenas binarias empaquetadas que representan estructuras.

$familia = sockaddr_familia $sockaddr

Toma una dirección de socket empaquetada (como la devuelta por pack_sockaddr_in(), pack_sockaddr_un() o las funciones integradas de Perl getsockname() y getpeername()). Devuelve la etiqueta de familia de direcciones. Esta será una de las constantes "AF_*", como "AF_INET" para direcciones "sockaddr_in" o "AF_UNIX" para una "sockaddr_un". Puede usarse para determinar qué desempaquetar para una sockaddr de tipo desconocido.

$sockaddr = pack_sockaddr_in $puerto, $direccion_ip

Toma dos argumentos, un número de puerto y una cadena opaca (como la devuelta por inet_aton(), o una v-string). Devuelve la estructura "sockaddr_in" con esos argumentos empaquetados y "AF_INET" rellenado. Para sockets de dominio de Internet, esta estructura es normalmente lo que necesita para los argumentos en bind(), connect() y send().

Un argumento $puerto indefinido se toma como cero; una $direccion_ip indefinida se considera un error fatal.

($puerto, $direccion_ip) = unpack_sockaddr_in $sockaddr

Toma una estructura "sockaddr_in" (como la devuelta por pack_sockaddr_in(), getpeername() o recv()). Devuelve una lista de dos elementos: el puerto y una cadena opaca que representa la dirección IP (puede usar inet_ntoa() para convertir la dirección al formato numérico de cuatro puntos). Fallará si la estructura no representa una dirección "AF_INET".

En contexto escalar, devolverá solo la dirección IP.

$sockaddr = sockaddr_in $puerto, $direccion_ip

($puerto, $direccion_ip) = sockaddr_in $sockaddr

Un envoltorio de pack_sockaddr_in() o unpack_sockaddr_in(). En contexto de lista, desempaqueta su argumento y devuelve una lista que consiste en el puerto y la dirección IP. En contexto escalar, empaqueta sus argumentos de puerto y dirección IP como una "sockaddr_in" y la devuelve.

Proporcionado en gran medida por compatibilidad heredada; es mejor usar explícitamente pack_sockaddr_in() o unpack_sockaddr_in().

$sockaddr = pack_sockaddr_in6 $puerto, $direccion_ip6, [$id_escopo, [$info_flujo]]

Toma de dos a cuatro argumentos, un número de puerto, una cadena opaca (como la devuelta por inet_pton()), opcionalmente un número de ID de ámbito y, opcionalmente, un número de etiqueta de flujo. Devuelve la estructura "sockaddr_in6" con esos argumentos empaquetados y "AF_INET6" rellenado. Equivalente IPv6 de pack_sockaddr_in().

Un argumento $puerto indefinido se toma como cero; una $direccion_ip6 indefinida se considera un error fatal.

($puerto, $direccion_ip6, $id_escopo, $info_flujo) = unpack_sockaddr_in6 $sockaddr

Toma una estructura "sockaddr_in6". Devuelve una lista de cuatro elementos: el número de puerto, una cadena opaca que representa la dirección IPv6, el ID de ámbito y la etiqueta de flujo. (Puede usar inet_ntop() para convertir la dirección al formato de cadena habitual). Fallará si la estructura no representa una dirección "AF_INET6".

En contexto escalar, devolverá solo la dirección IP.

$sockaddr = sockaddr_in6 $puerto, $direccion_ip6, [$id_escopo, [$info_flujo]]

($puerto, $direccion_ip6, $id_escopo, $info_flujo) = sockaddr_in6 $sockaddr

Un envoltorio de pack_sockaddr_in6() o unpack_sockaddr_in6(). En contexto de lista, desempaqueta su argumento según unpack_sockaddr_in6(). En contexto escalar, empaqueta sus argumentos según pack_sockaddr_in6().

Proporcionado en gran medida por compatibilidad heredada; es mejor usar explícitamente pack_sockaddr_in6() o unpack_sockaddr_in6().

$sockaddr = pack_sockaddr_un $ruta

Toma un argumento, una ruta de nombre de archivo. Devuelve la estructura "sockaddr_un" con esa ruta empaquetada con "AF_UNIX" rellenado. Para sockets "PF_UNIX", esta estructura es normalmente lo que necesita para los argumentos en bind(), connect() y send().

($ruta) = unpack_sockaddr_un $sockaddr

Toma una estructura "sockaddr_un" (como la devuelta por pack_sockaddr_un(), getpeername() o recv()). Devuelve una lista de un elemento: la ruta del nombre de archivo. Fallará si la estructura no representa una dirección "AF_UNIX".

$sockaddr = sockaddr_un $ruta

($ruta) = sockaddr_un $sockaddr

Un envoltorio de pack_sockaddr_un() o unpack_sockaddr_un(). En contexto de lista, desempaqueta su argumento y devuelve una lista que consiste en la ruta del nombre de archivo. En contexto escalar, empaqueta su ruta de nombre de archivo como una "sockaddr_un" y la devuelve.

Proporcionado en gran medida por compatibilidad heredada; es mejor usar explícitamente pack_sockaddr_un() o unpack_sockaddr_un().

Estos solo se admiten si su sistema tiene <sys/un.h>.

$ip_mreq = pack_ip_mreq $dir_multicast, $interfaz

Toma una dirección multicast IPv4 y opcionalmente una dirección de interfaz (o "INADDR_ANY"). Devuelve la estructura "ip_mreq" con esos argumentos empaquetados. Adecuado para usar con las opciones de socket "IP_ADD_MEMBERSHIP" y "IP_DROP_MEMBERSHIP".

($dir_multicast, $interfaz) = unpack_ip_mreq $ip_mreq

Toma una estructura "ip_mreq". Devuelve una lista de dos elementos; la dirección multicast IPv4 y la dirección de la interfaz.

$ip_mreq_fuente = pack_ip_mreq_fuente $dir_multicast, $fuente, $interfaz

Toma una dirección multicast IPv4, una dirección de origen y opcionalmente una dirección de interfaz (o "INADDR_ANY"). Devuelve la estructura "ip_mreq_source" con esos argumentos empaquetados. Adecuado para usar con las opciones de socket "IP_ADD_SOURCE_MEMBERSHIP" y "IP_DROP_SOURCE_MEMBERSHIP".

($dir_multicast, $fuente, $interfaz) = unpack_ip_mreq_fuente $ip_mreq

Toma una estructura "ip_mreq_source". Devuelve una lista de tres elementos; la dirección multicast IPv4, la dirección de origen y la dirección de la interfaz.

$ipv6_mreq = pack_ipv6_mreq $dir_multicast6, $indice_interfaz

Toma una dirección multicast IPv6 y un número de interfaz. Devuelve la estructura "ipv6_mreq" con esos argumentos empaquetados. Adecuado para usar con las opciones de socket "IPV6_ADD_MEMBERSHIP" y "IPV6_DROP_MEMBERSHIP".

($dir_multicast6, $indice_interfaz) = unpack_ipv6_mreq $ipv6_mreq

Toma una estructura "ipv6_mreq". Devuelve una lista de dos elementos; la dirección IPv6 y un número de interfaz.

FUNCIONES

DIRECCIONES

$ip_address = inet_aton $string

Toma una cadena que representa el nombre de un host, o una representación textual de una dirección IP y la traduce a una estructura de dirección binaria empaquetada adecuada para pasar a pack_sockaddr_in(). Si se le pasa un nombre de host que no se puede resolver, devuelve "undef". Para hosts multihogar (hosts con más de una dirección), se devuelve la primera dirección encontrada.

Para portabilidad, no asuma que el resultado de inet_aton() tiene un ancho de 32 bits, es decir, que contendría solo la dirección IPv4 en orden de red.

Esta función, exclusiva para IPv4, se proporciona en gran medida por razones de legado. El código nuevo debería usar getaddrinfo() o inet_pton() en su lugar para soporte IPv6.

$string = inet_ntoa $ip_address

Toma una estructura de dirección binaria empaquetada, como la devuelta por unpack_sockaddr_in() (o una v-cadena que representa los cuatro octetos de la dirección IPv4 en orden de red) y la traduce a una cadena con el formato "d.d.d.d", donde las "d" son números menores que 256 (la notación normal de cuatro números decimales separados por puntos para direcciones de Internet, legible por humanos).

Esta función, exclusiva para IPv4, se proporciona en gran medida por razones de legado. El código nuevo debería usar getnameinfo() o inet_ntop() en su lugar para soporte IPv6.

$address = inet_pton $family, $string

Toma una familia de direcciones (como "AF_INET" o "AF_INET6") y una cadena que contiene una representación textual de una dirección en esa familia, y la traduce a una estructura de dirección binaria empaquetada.

Ver también getaddrinfo() para una función más potente y flexible para buscar direcciones de socket dadas nombres de host o direcciones textuales.

$string = inet_ntop $family, $address

Toma una familia de direcciones y una estructura de dirección binaria empaquetada, y la traduce a una representación textual legible por humanos de la dirección; típicamente en formato "d.d.d.d" para "AF_INET" o formato "hhhh:hhhh::hhhh" para "AF_INET6".

Ver también getnameinfo() para una función más potente y flexible para convertir direcciones de socket en representaciones textuales legibles por humanos.

($err, @result) = getaddrinfo $host, $service, [$hints]

Dada una combinación de nombre de host y nombre de servicio, esta función intenta resolver el nombre del host en una lista de direcciones de red, y el nombre del servicio en un protocolo y número de puerto, y luego devuelve una lista de estructuras de dirección adecuadas para conectarse a él mediante connect().

Dada solo un nombre de host, esta función intenta resolverlo en una lista de direcciones de red, y luego devuelve una lista de estructuras de dirección que representan estas direcciones.

Dado solo un nombre de servicio, esta función intenta resolverlo en un protocolo y número de puerto, y luego devuelve una lista de estructuras de dirección que lo representan, adecuadas para unirse a ellas mediante bind(). Este uso debe combinarse con la bandera "AI_PASSIVE"; ver más abajo.

No se genera ningún error si no se proporciona ningún nombre.

Si está presente, $hints debe ser una referencia a un hash, donde se reconocen las siguientes claves:

flags => INT
Un campo de bits que contiene constantes "AI_*"; ver más abajo.
family => INT
Restringe la generación de direcciones solo a esta familia de direcciones.
socktype => INT
Restringe la generación de direcciones solo a este tipo de socket.
protocol => INT
Restringe la generación de direcciones solo para este protocolo.

El valor de retorno será una lista; el primer valor será una indicación de error, seguido de una lista de estructuras de dirección (si no ocurrió ningún error).

El valor de error será un dualvar; comparable a las constantes de error "EAI_*", o imprimible como un mensaje de error legible por humanos. Si no ocurrió ningún error, será numéricamente cero y una cadena vacía.

Cada valor en la lista de resultados será una referencia a un hash que contiene los siguientes campos:

family => INT
La familia de direcciones (por ejemplo, "AF_INET")
socktype => INT
El tipo de socket (por ejemplo, "SOCK_STREAM")
protocol => INT
El protocolo (por ejemplo, "IPPROTO_TCP")
addr => STRING
La dirección en una cadena empaquetada (como la devuelta por pack_sockaddr_in())
canonname => STRING
El nombre canónico del host si se proporcionó la bandera "AI_CANONNAME", o "undef" en caso contrario. Este campo solo estará presente en la primera dirección devuelta.

Las siguientes constantes de bandera se reconocen en el hash $hints. Pueden existir otras constantes de bandera proporcionadas por el sistema operativo.

AI_PASSIVE
Indica que esta resolución es para una unión local (bind()) para un socket pasivo (es decir, en escucha), en lugar de un socket activo (es decir, de conexión).
AI_CANONNAME
Indica que el llamador desea que se complete el campo del nombre de host canónico ("canonname") del resultado.
AI_NUMERICHOST
Indica que el llamador pasará una dirección numérica, en lugar de un nombre de host, y que getaddrinfo() no debe realizar una operación de resolución en este nombre. Esta bandera evitará una operación de búsqueda en red posiblemente lenta, y en su lugar devolverá un error si se pasa un nombre de host.

($err, $hostname, $servicename) = getnameinfo $sockaddr, [$flags, [$xflags]]

Dada una dirección de socket empaquetada (como la devuelta por getsockname(), getpeername(), o devuelta por getaddrinfo() en un campo "addr"), devuelve el nombre de host y el nombre de servicio simbólico que representa. $flags puede ser una máscara de bits de constantes "NI_*", o por defecto 0 si no se especifica.

El valor de retorno será una lista; el primer valor será una condición de error, seguido del nombre de host y el nombre del servicio.

El valor de error será un dualvar; comparable a las constantes de error "EAI_*", o imprimible como un mensaje de error legible por humanos. Los nombres de host y servicio serán cadenas simples.

Las siguientes constantes de bandera se reconocen como $flags. Pueden existir otras constantes de bandera proporcionadas por el sistema operativo.

NI_NUMERICHOST
Solicita que se devuelva directamente una representación de cadena legible por humanos de la dirección numérica, en lugar de realizar una operación de resolución de nombres que pueda convertirla en un nombre de host. Esto también evitará operaciones de E/S de red potencialmente bloqueantes.
NI_NUMERICSERV
Solicita que el número de puerto se devuelva directamente como una representación numérica en lugar de realizar una operación de resolución de nombres que pueda convertirlo en un nombre de servicio.
NI_NAMEREQD
Si una operación de resolución de nombres no puede proporcionar un nombre, esta bandera hará que getnameinfo() indique un error, en lugar de devolver la representación numérica como una cadena legible por humanos.
NI_DGRAM
Indica que la dirección del socket se relaciona con un socket "SOCK_DGRAM", para los servicios cuyo nombre difiere entre los protocolos TCP y UDP.

Las siguientes constantes pueden proporcionarse como $xflags.

NIx_NOHOST
Indica que el llamador no está interesado en el nombre de host del resultado, por lo que no tiene que ser convertido. Se devolverá "undef" como nombre de host.
NIx_NOSERV
Indica que el llamador no está interesado en el nombre del servicio del resultado, por lo que no tiene que ser convertido. Se devolverá "undef" como nombre de servicio.
