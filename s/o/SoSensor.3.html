Descripción detallada

La clase SoSensor es la clase base abstracta para todos los sensores.

Los sensores son un mecanismo en Coin para programar tareas que se ejecutarán ante eventos específicos. Los eventos en cuestión pueden ser puntos particulares en el tiempo o cambios en entidades del grafo de escena.

Consulta la documentación de las subclases para obtener información sobre los tipos exactos de eventos que pueden activar las devoluciones de llamada de los sensores.

Para la mayoría de las tareas en las que los programadores de aplicaciones pueden usar sensores, también es posible lograr los mismos resultados utilizando motores. Sin embargo, existen algunas diferencias importantes entre sensores y motores:

Los motores se consideran parte del grafo de escena y se escriben en archivos durante las operaciones de exportación de SoWriteAction. Los sensores, por otro lado, no se incluyen en las operaciones de exportación.

Los motores básicamente conectan campos (y vienen con mucha funcionalidad incorporada para combinar y convertir entradas y salidas), solo decides qué motor quieres, conectas las entradas y salidas y te olvidas de él. Los sensores son mucho más flexibles en lo que puedes hacer cuando se activan, ya que el control se transfiere internamente de Coin a tus funciones de devolución de llamada registradas.

NAME

SoSensor — abstract sensor base class

Description

This class is the abstract base class for all sensors in the Open Inventor API. A sensor is an object that monitors a specific condition and then performs an action when that condition is met.

The condition that triggers a sensor can be one of several types:

  • An alarm condition, which is triggered by the application programmer.     (See SoAlarmSensor.)
  • A field's value changing.     (See SoFieldSensor.)
  • A node's value changing.     (See SoNodeSensor.)
  • An explicit timer event.     (See SoTimerSensor.)

The base class provides the fundamental sensor functionality, such as enabling/disabling, setting the callback routine, and handling the internal sensor state.

Subclasses of SoSensor implement specific triggering mechanisms.

The sensors are managed by the Open Inventor database. When a sensor is triggered, it is added to a queue of pending sensors. The Open Inventor engine invokes the sensors' callback routines when the engine evaluates the scene graph.

The callback routine is typically a member function of an application class, and it is called with the SoSensor object that triggered it and the application-specific data that was passed to the sensor.

Since SoSensor is an abstract base class, you will never create instances of it directly. Instead, you will create instances of its concrete subclasses.

Note: This class is the equivalent of the Open Inventor class SoSensor.

void SoSensor::attach ( SoNode * node )

Attaches the sensor to the given node. The sensor will be triggered if the node changes in a way that the sensor is sensitive to (e.g. SoNodeSensor).

void SoSensor::detach ( void )

Detaches the sensor from any node it might be attached to.

void SoSensor::disable ( void )

Disables the sensor. Disabled sensors will not trigger until they are enabled again.

void SoSensor::enable ( void )

Enables the sensor. Sensors are enabled by default when created.

void SoSensor::enable ( SbBool flag )

Enables or disables the sensor based on the value of flag.

SbBool SoSensor::isEnabled ( void )

Returns TRUE if the sensor is currently enabled.

void SoSensor::setFunction ( SoSensorCB * func )

Sets the callback function to be invoked when the sensor is triggered. A value of NULL disables the callback.

void SoSensor::setFunctionData ( void * data )

Sets the data that will be passed to the callback function when the sensor is triggered.

void SoSensor::initClass ( void ) [static]

Sets up initialization for static data for the sensors. Called by SoDB::init().
