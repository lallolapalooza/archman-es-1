DESCRIPCIÓN DETALLADA

La clase SoSFTrigger es la clase "void" utilizada para detectar cambios en los campos.

Conecte este campo a un campo maestro (o salida de motor) para detectar cuándo el campo maestro cambia su valor.

Esto es útil si desea activar automáticamente una actualización desde el nodo o motor (u otro contenedor de campos) del que forma parte este campo, cada vez que otro campo cambie, y no le interese particularmente el valor real del campo maestro.

NAME

SoSFTrigger — field class for triggering notifications

SYNOPSIS

  SoSFTrigger

Inherits from SoField.

Detailed Description

This class is used to create fields that trigger notifications without carrying any specific value. It's primarily used for internal purposes, like signaling changes within the Coin library or triggering actions in sensors when other events occur. The field's value is not explicitly stored; instead, methods like setValue() and touch() are used to initiate the notification process.

The SoSFTrigger field is typically created and managed internally by Coin during the initialization of the library (from SoDB::init()) to set up the type system.

Trigger a notification sequence.

At the end of a notification sequence, all "immediate" sensors (i.e. sensors set up with a zero priority) are triggered.

void SoSFTrigger::touch (void ) [virtual]

Notify the field as well as the field's owner / container that it has been changed.

Touching a field which is part of any component (engine or node) in a scene graph will lead to a forced redraw. This is useful if you have been doing several updates to the field wrapped in a pair of enableNotify() calls to notify the field's auditors that its value has changed.
