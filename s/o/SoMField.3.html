Descripción detallada

La clase SoMField es la clase base para campos que pueden contener múltiples valores.

Todos los tipos de campos que pueden contener más de un valor heredan de esta clase. SoMField es una clase abstracta.

Utilice setValue(), setValues() o set1Value() para establecer los valores de los campos que heredan de SoMField, y utilice getValues() o el operador índice [] para leer los valores. Código de ejemplo:

SoText2 * textnode = new SoText2;
textnode->ref();
// Estableciendo valores de campo múltiple. /////////////////////////////
// Establece el primer valor del campo SoMFString del nodo SoText2.
// El array de campos se truncará para contener solo este valor individual.
textnode->string.setValue("Morten");
// Contenido completo del SoMFString es: [ "Morten" ]
// El método setValue() y el operador = son intercambiables,
// por lo que esta línea de código hace lo mismo que la línea anterior.
textnode->string = "Peder";
// El contenido completo del SoMFString es ahora: [ "Peder" ]
// Establece el valor en el índice 2. Si el array de valores del campo contenía
// menos de 3 elementos antes de esta llamada, primero se expandirá para contener
// 3 elementos.
textnode->string.set1Value(2, "Lars");
// Contenido completo del SoMFString es: [ "Peder", <indefinido>, "Lars" ]
// Esto establece 3 valores del array, comenzando en el índice 5. Si el
// contenedor del array tenía menos de 8 elementos antes de la llamada a setValues(),
// el array se expandirá primero.
SbString s[3] = { "Eriksen", "Blekken", "Aas" };
textnode->string.setValues(5, sizeof(s) / sizeof(s[0]), s);
// Contenido completo del SoMFString es ahora:
//     [ "Peder", <indefinido>, "Lars", <indefinido>, <indefinido>,
//       "Eriksen", "Blekken", "Aas" ]
// Nótese también que la llamada a setValues()

no truncará un campo
// contenedor si lo usas para cambiar un subconjunto al principio:
SbString n[4] = { "Dixon", "Adams", "Bould", "Winterburn" };
textnode->string.setValues(0, sizeof(n) / sizeof(n[0]), n);
// Contenido completo del SoMFString es ahora:
//     [ "Dixon", "Adams", "Bould", "Winterburn", <undefined>,
//       "Eriksen", "Blekken", "Aas" ]
// Inspeccionando valores de múltiples campos. //////////////////////////
// Esto leerá el segundo elemento (contando desde cero) del
// campo multivalor y lo colocará en "val".
SbString val = textnode->string[2];
// Nos da un puntero al array que el campo de múltiples valores
// está usando para almacenar los valores. Ten en cuenta que el valor de retorno es
// "const", por lo que solo puedes leer del array, no escribir en
// él.
const SbString * vals = textnode->string.getValues(0);
// Modificando valores de múltiples campos. ///////////////////////////
// Por supuesto, puedes modificar los valores de múltiples campos usando los
// métodos set- y get- que se muestran arriba, pero cuando trabajas con
// grandes conjuntos de datos, esto será ineficaz. Usa esta técnica en su lugar:
SbString * modvals = textnode->string.startEditing();
// ... muchas modificaciones al array "modvals" aquí ...
// Llamar al método finishEditing() es necesario para que el
// grafo de escena se actualice (y se vuelva a renderizar).
textnode->string.finishEditing();

La razón por la que es más eficaz agrupar muchas modificaciones dentro de startEditing() / finishEditing() es porque evitamos el flujo de mensajes de notificación que de otro modo se enviarían por cada modificación realizada. En su lugar, solo habrá una notificación sobre los cambios, desencadenada por la llamada a finishEditing().

La forma correcta de preasignar un número específico de valores de campo en un bloque es usar el método SoMField::setNum(), por ejemplo, antes de usar los métodos startEditing() y finishEditing(). Los valores de campo no estarán inicializados después de expandir el campo con la llamada a setNum().

Ten en cuenta que el código de tu aplicación debe tener cuidado de no hacer cosas tontas durante una notificación desencadenada por setValues(). Si tienes código que se parece, por ejemplo, a esto:

// actualizar el conjunto de índices de coordenadas al principio de, por ejemplo,
// el campo coordIndex de un SoIndexedFaceSet...
ifs->coordIndex.setValues(0, runner->numIndices, runner->indices);
// ..luego truncar para asegurar que tenga el tamaño correcto.
ifs->coordIndex.setNum(runner->numIndices);

Como setValues() puede dejar algunos elementos al final del array que normalmente pueden ser índices no válidos después de ejecutar la primera instrucción, algo puede salir mal durante la notificación si tienes código de aplicación que monitorea los cambios, y el código de la aplicación luego, por ejemplo, desencadena una acción o algo que intenta usar el campo coordIndex antes de que se actualice a su tamaño correcto con la llamada a setNum().

(La notificación puede en este caso, como siempre, ser desactivada temporalmente para estar seguro:

somefield.enableNotify(FALSE);
somefield.setValues(...);
somefield.setNum(...);
somefield.enableNotify(TRUE);
somefield.touch();

Esto garantizará que el par setValues() y setNum() se ejecuten como una operación atómica).

Cuando los nodos, motores u otros tipos de contenedores de campos se escriben en un archivo, sus campos de múltiples valores se escriben en el siguiente formato:

containerclass {
  fieldname [ valor0, valor1, valor2, ...]
  ...
}

..así, por ejemplo, un nodo Coordinate3 que proporciona 6 coordenadas de vértice en forma de valores SbVec3f en su campo "point" para, por ejemplo, un faceset, lineset o pointset:

Coordinate3 {
   point [
      -1 1 0, -1 -1 0, 1 -1 0,
      0 2 -1, -2 0 -1, 0 -2 -1,
   ]
}

Algunos campos admiten el intercambio de datos de la aplicación a través del método setValuesPointer(). setValuesPointer() permite establecer el puntero de datos directamente en el campo. Normalmente (cuando se usa setValues()), Coin hace una copia de tus datos, por lo que este método puede ser muy útil si tu aplicación necesita los datos internamente y solo estás usando Coin para la visualización. Código de ejemplo:

myapp->calculateCoordinates(SOME_LARGE_VALUE);
SbVec3f * mycoords = myapp->getCoordinates();
SoCoordinate3 * mynode = myapp->getCoordinateNode();
mynode->point.setValuesPointer(SOME_LARGE_VALUE, mycoords);

Ten en cuenta que tu campo debe ser un campo de solo lectura cuando estableces los datos de esta manera. Si escribes en el campo, los valores de tu array de aplicación serán sobrescritos. Si añades valores al campo, se asignará un nuevo array y los datos se copiarán en él antes de añadir los nuevos valores. El puntero del array se descartará entonces.

También ten en cuenta que siempre que cambies algún valor en el array, debes notificar manualmente a Coin llamando a SoField::touch(). Para nuestro ejemplo:

SbVec3f * mycoords = myapp->getCoordinate();
myapp->updateCoordinate(mycoords);
SoCoordinate3 * mynode = myapp->getCoordinateNode();
mynode->point.touch(); // esto notificará a Coin que el campo ha cambiado

Puedes usar SoMField::enableDeleteValues() para que Coin elimine el puntero del array cuando el campo se destruya o cuando se descarte el puntero del array porque ya no se necesita (por ejemplo, cuando se cambia el tamaño del array). El array se eliminará usando el operador delete[] de C++, por lo que si lo usas, tu array debe ser asignado usando el operador new[] de C++.

SoMField::enableDeleteValues() solo es compatible con versiones posteriores de TGS Inventor y no recomendamos su uso. Puede tener resultados indefinidos en la plataforma Microsoft Windows. Asignar memoria en la aplicación y destruirla en una DLL puede ser algo malo, causando fallos misteriosos, si no tienes mucho cuidado con cómo se enlazan tu aplicación y las DLLs a la biblioteca C subyacente.

void SoMField::setNum (const int numarg)

Establece el número de valores a num.

Si el número actual de valores es mayor que num, el array de valores se truncará desde el final. Pero si num es mayor, el array se expandirá automáticamente (y se asignarán valores aleatorios a los nuevos elementos del array).

void SoMField::deleteValues (int start, int numarg = -1) [virtual]

Elimina elementos de valor desde el índice start hasta e incluyendo el índice start + num - 1.

Los elementos con índices mayores que el último elemento eliminado se moverán hacia abajo en el array de valores.

Si num es igual a -1, elimina desde el índice start hasta el final del array.

Reimplementado en SoMFEngine, SoMFNode y SoMFPath.

void SoMField::insertSpace (int start, int numarg) [virtual]

Inserta num "espacios" para nuevos elementos de valor desde start. Los elementos ya presentes desde start se moverán "hacia arriba" en el array extendido.

Reimplementado en SoMFEngine, SoMFNode y SoMFPath.

void SoMField::enableDeleteValues (void ) [virtual]

Se puede usar para hacer que Coin elimine el puntero del array establecido a través de una llamada a setValuesPointer(). Consulte la documentación de SoMField para obtener información sobre la función setValuesPointer().
