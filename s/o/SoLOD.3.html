Descripción Detallada

La clase SoLOD se utiliza para elegir un hijo basándose en la distancia entre el espectador y el objeto.

La documentación de la clase nodo SoLOD sería lo suficientemente similar a la de SoLevelOfDetail como para remitirle a que consulte primero esa. Explicará los principios generales de lo que es un mecanismo de nivel de detalle, y por qué y cómo usarlo.

(La principal diferencia entre SoLOD y SoLevelOfDetail es que SoLOD utiliza la técnica más rápida de "distancia al espectador" para implementar la funcionalidad de nivel de detalle, en contraposición a la técnica más correcta (pero potencialmente más lenta) de "área de bbox proyectada" utilizada por SoLevelOfDetail.)

Aquí tienes un ejemplo simulado (en estilo de formato de archivo Inventor, pero fácilmente convertible a código) que muestra cómo usar este nodo:

LOD {
   range [ 10, 20, 30, 40 ]
   Sphere { }
   Cylinder { }
   Cone { }
   Cube { }
   Info { }
}

Para el sub-grafo de escena anterior, cuando el objeto LOD está a menos de 10 unidades de distancia de la cámara de punto de vista, se mostrará un SoSphere. Para distancias de 10 a 20 unidades, esto se cambiará a SoCylinder, y así sucesivamente. Para distancias de *más* de 40 unidades desde la cámara, se recorrerá / renderizará un nodo SoInfo, es decir, no se mostrará nada. (Este es un "truco" común que se utiliza para optimizar la renderización cuando los modelos se alejan lo suficiente de la cámara como para querer eliminarlos por completo).

Tenga en cuenta que al usar una SoOrthographicCamera en los visores de examen de las bibliotecas SoQt, SoWin y SoXt, parecerá que el nodo SoLOD no funciona al usar la funcionalidad de "Zoom". Lo que sucede es que una SoOrthographicCamera no se mueve realmente, el efecto de "zoom" se logra simplemente cambiando su ajuste de altura de vista (es decir, el valor del campo SoOrthographicCamera::height), pero su posición permanece constante. Por lo tanto, la distancia a la cámara no cambiará, lo que significa que SoLOD elegirá el mismo hijo, sin importar cuánto se haga "zoom".

(El nodo SoLevelOfDetail utiliza el área del espacio de pantalla del objeto para decidir cuándo cambiar de hijo, por lo que ese nodo aún funcionará con SoOrthographicCamera.)

SoLOD(3) - Coin

NAME

SoLOD

Level Of Detail node

SYNOPSIS

Inherits from SoGroup.

class SoLOD : public SoGroup

Nodes that contain children and want to switch to a different child (or no child at all) depending on the distance from the viewer.

The node contains a list of distance ranges, which correspond to the children of the node. The node will traverse only one child, which child it chooses depends on the distance between the viewer and the object. If the distance is zero, the first child is chosen. If the distance is greater than the first range value, the second child is chosen, etc. If the distance is greater than the last range value, the last child is chosen.

The distance is calculated between the viewer's position and the node's center point. The node's center point can be adjusted with the center field.

The distance ranges are specified by the range field. The ranges are defined in terms of squared distances, making the calculations faster.

For a detailed description of the range field, see the documentation of the SoLOD class in the Coin documentation.

If there are N children, the range field should contain N-1 values. The N-1 values define N-1 intervals.

The intervals are defined as follows:

    [0, range[0]*range[0]]    : child[0]
    (range[0]*range[0], range[1]*range[1]] : child[1]
    ...
    (range[N-2]*range[N-2], infinity) : child[N-1]

where N is the number of children.

Note that the range field is a SoMFFloat, which means that multiple values can be set. The values set in the range field are squared by the node before they are used.

If the range field is empty, the node will behave as a normal SoGroup node.



Example:


    // Assuming node has 3 children: child0, child1, child2
    SoLOD {
        range [ 10.0, 20.0 ] # Squared distances are 100.0 and 400.0
        center 0 0 0
        children [
            child0,
            child1,
            child2
        ]
    }



This LOD node will:


    

  • Traverse child0 if distance^2 <= 100.0
    • 

  • Traverse child1 if 100.0 < distance^2 <= 400.0
    • 

  • Traverse child2 if distance^2 > 400.0
    • 



Default values:


    range [ 0.0 ]
    center 0 0 0



For more details on how the distance is calculated, see the
    SoLOD::whichToTraverse() method documentation.

Fields




SoMFFloat range


The distance ranges which decides when to use each child for traversal /
    rendering. See usage example in main class documentation of SoLOD
    for an explanation of how this vector should be set up correctly. By default
    this vector just contains a single value 0.0f.


SoSFVec3f center


This vector represents an offset within the object from the geometric center
    point to the center point the application programmer would actually like the
    distance between the viewer and the object to be calculated from. Default
    value is [0, 0, 0]. It is usually not necessary to change this field.
