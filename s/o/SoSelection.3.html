La clase SoSelection gestiona

Documentation del Nodo SoSelection

Este nodo almacena una lista de nodos seleccionados.

Insertar un nodo SoSelection en tu gráfico de escena te permite permitir al usuario "seleccionar" con el botón izquierdo del ratón para seleccionar/deseleccionar objetos debajo del nodo SoSelection.

Usar una SoBoxHighlightRenderAction o una SoLineHighlightRenderAction para renderizar gráficos de escena que contengan nodos SoSelection proporciona una forma conveniente de proporcionar retroalimentación visual sobre las selecciones al usuario de la aplicación.

Ten cuidado con una suposición errónea común sobre este nodo: que la escena se volverá a renderizar automáticamente cada vez que el usuario seleccione objetos. Este no es el caso, el programador de la aplicación debe programar él mismo un redibujado. Una forma sencilla de lograr esto es llamar a SoNode::touch() en el nodo SoSelection en la función de devolución de llamada de selección / deselección.

A continuación se proporciona un "esqueleto" para el uso básico de los nodos SoSelection:

extern SoSeparator * make_scenegraph( void );
static SoSelection * selection = NULL;
// Función de devolución de llamada activada para selección / deselección.
void made_selection( void * userdata, SoPath * path )
{
  (void)fprintf( stdout, "%sselected %s\n",
                 userdata == (void *)1L ? "" : "de",
                 path->getTail()->getTypeId().getName().getString() );
  selection->touch(); // para redibujar
}
// *************************************************************************
// Imprime un aviso rápido de instrucciones en stdout.
void show_instructions( void )
{
  (void)fprintf( stdout, "\nEste programa de ejemplo demuestra el uso del tipo de nodo SoSelection.\n" );
  (void)fprintf( stdout, "\nInstrucciones rápidas:\n\n" );
  (void)fprintf( stdout, "  * seleccionar con el botón izquierdo del ratón\n" );
  (void)fprintf( stdout, "  * mantén SHIFT para seleccionar múltiples objetos\n" );
  (void)fprintf( stdout, "  * presiona ESC para alternar entre modo de vista y selección\n" );
  (void)fprintf( stdout, "\n" );
}
// *************************************************************************
int main( int argc, char ** argv )
{
  QWidget * window = SoQt::init( argv[0] );
  show_instructions();
  selection = new SoSelection;
  selection->policy = SoSelection::SHIFT;
  selection->ref();
  selection->addChild( make_scenegraph() );
  selection->addSelectionCallback( made_selection, (void *)1L );
  selection->addDeselectionCallback( made_selection, (void *)0L );
  SoQtExaminerViewer * examinerviewer = new SoQtExaminerViewer( window );
  examinerviewer->setSceneGraph( selection );
  examinerviewer->setGLRenderAction( new SoBoxHighlightRenderAction );
  examinerviewer->setViewing( FALSE );
  examinerviewer->show();
  SoQt::show( window );
  SoQt::mainLoop();
  delete examinerviewer;
  selection->unref();
  return 0;
}

Este nodo no se inicializa en SoDB::init(), ya que es parte del kit de interacción "add-on". Antes de usar este nodo, deberías llamar a SoInteraction::init(). Si estás usando uno de los toolkits gráficos estándar (SoXt / SoQt / SoWin), SoInteraction::init() será llamado por ti desde el método So[Xt|Qt|Win]::init() y no tendrás que preocuparte por ello.

Con respecto al uso de múltiples nodos SoSelection al mismo tiempo en el mismo gráfico de escena: esto es posible, pero no es sencillo. Los visores estándar proporcionados por SoQt, SoWin, etc., solo esnifan un nodo SoSelection (parte de la API heredada de InventorXt de SGI), por lo que los cambios de selección en otros no activan redibujados. En otras palabras, no ves necesariamente lo que está sucediendo. Tendrás que conectarte manualmente y activar redibujados tú mismo.

También ten en cuenta que al tener múltiples nodos SoSelection activos al mismo tiempo en el gráfico de escena, los recorridos SoHandleEventAction que pretendes para el cambio de selección en un nodo SoSelection también afectarán a todos los demás nodos SoSelection en la escena, generalmente deseleccionando todo debajo de ellos ya que estarás haciendo clic fuera de los objetos seleccionables. Por lo tanto, también tendrás que anular manualmente ese comportamiento, si deseas que el cambio de selección en un nodo SoSelection no afecte a los demás.

Documentación de Enumeración de Miembros

enum SoSelection::Policy

Enum para diferentes políticas de selección.

Enumerador

SINGLE
Solo se puede seleccionar un objeto a la vez. Cuando el usuario selecciona un nuevo objeto, la selección anterior se deseleccionará. Si el usuario hace clic en nada, la selección actual se deseleccionará.

Ten en cuenta que si una nueva selección coincide con una ya presente en la lista de selección, no se realizarán devoluciones de llamada de notificación de deselección ni de selección para esa ruta de selección.

TOGGLE
Seleccionar un objeto alterna su estado de selección.
SHIFT
Igual que SINGLE, pero cuando se presiona la tecla shift, la política de selección cambiará a TOGGLE.
DISABLE
Deshabilita el manejo de selecciones.

void SoSelection::setPickFilterCallback (SoSelectionPickCB * f, void * userData = NULL, const SbBool callOnlyIfSelectable = TRUE)

Establece la llamada de retorno del filtro de selección. Esta llamada de retorno se invocará cuando una ruta esté a punto de ser añadida o eliminada de la lista de objetos seleccionados. La función de llamada de retorno debe devolver una ruta de reemplazo que se utilizará en lugar de la ruta seleccionada. La ruta devuelta será referenciada, copiada y luego desreferenciada de nuevo por el nodo SoSelection.

Si no se establece ninguna llamada de retorno (por defecto), se utilizará la ruta seleccionada para seleccionar/deseleccionar.

Valores de retorno posibles de la llamada de retorno:

  • NULL: simula que no se seleccionó nada. Esto borrará la selección para la política SINGLE. La acción de manejo de eventos se detendrá.
  • Una ruta: la ruta será seleccionada/deseleccionada. La acción de manejo de eventos se detendrá.
  • Una ruta que contenga solo el nodo de selección: igual que NULL, pero la acción no se detendrá.
  • Una ruta vacía o una ruta que no contenga el nodo de selección: la selección será ignorada.

Si callOnlyIfSelectable es TRUE, la llamada de retorno solo se invocará si el nodo de selección está en la ruta seleccionada.

Detailed Description

The SoSelection node keeps track of a list of scene graph paths. It can be used to implement selection mechanisms in an application.

The node supports a number of selection policies which determine how the list of paths is modified upon interaction. The policies are:

  • SHIFT: If the mouse button is pressed, the path will be added to the selection list. If the mouse button is released, the path will be removed from the selection list.
  • ADD: The path will always be added to the selection list.
  • REMOVE: The path will always be removed from the selection list.
  • TOGGLE: If the path is already in the selection list, it will be removed. Otherwise, it will be added.

The default policy is SHIFT.

SoSelection is also able to perform actions based on events passed to its handleEvent() method. This is primarily used internally by the selection node to handle mouse events when an SoHandleEventAction is traversed.

The node supports callbacks for selection, deselection, start and finish of selection operations, and general changes to the selection list.

The node supports an optional pick callback. This callback is invoked when the SoSelection node is picked during an SoPickAction. The callback function receives a pointer to an SoSelection node, and the user data specified when the callback was added.
