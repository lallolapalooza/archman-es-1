Descripción Detallada

La clase SoGetBoundingBoxAction calcula las cajas delimitadoras para nodos y subgrafos.

Si esta acción se aplica a una ruta o raíz de grafo de escena, calculará la caja delimitadora y el punto central de la geometría contenida en la escena.

No tiene que aplicar una SoGetBoundingBoxAction a la raíz de una escena. Al usar la acción, obtendrá la caja delimitadora del nodo al que la está aplicando y su subárbol en el grafo de escena (si lo hay).

La caja delimitadora calculada estará en las coordenadas locales de ese subárbol. Si se aplica a un nodo raíz del grafo de escena, la caja delimitadora calculada estará en coordenadas globales.

El uso de cajas delimitadoras es ubicuo dentro de la biblioteca Coin. Es necesario para la ejecución correcta y para mejoras de rendimiento durante el renderizado, la selección, el almacenamiento en caché, la eliminación, etc.

Los nodos SoSeparator están cacheados agresivamente los resultados de los cálculos de cajas delimitadoras, de modo que solo se recálculan cuando el grafo de escena enraizado debajo de cualquier nodo SoSeparator ha sido modificado. Esto significa que aplicar esta acción a grafos de escena, o partes de grafos de escena, debería ser muy rápido en ejecuciones sucesivas para partes "estáticas" de la escena.

Tenga en cuenta que el algoritmo utilizado no está garantizado que siempre proporcione una caja delimitadora exacta: combina cajas delimitadoras en pares y extiende una de ellas para contener la otra. Dado que las cajas no tienen por qué ser paralelas a los ejes principales, la nueva caja podría no encajar perfectamente en la caja no extendida (su sistema de coordenadas ha sido cambiado).

Tenga en cuenta también que lo que se devuelve de getBoundingBox() se proyectará para que esté orientado a lo largo de los ejes principales, lo que a menudo puede hacer que sea bastante más grande de lo que era antes de la proyección. Para que el código del cliente obtenga la mejor caja delimitadora que Coin puede calcular (y que generalmente será exacta), debe usar el método getXfBoundingBox() después de haber aplicado SoGetBoundingBoxAction.

Constructor & Destructor Documentación

SoGetBoundingBoxAction::SoGetBoundingBoxAction (const SbViewportRegion & vp)

Constructor.

Aunque parece innecesario pasar un argumento de región de ventana para calcular las cajas de borde, hay una buena razón: algunos nodos de forma requieren conocer la región de ventana para calcular su caja de borde — estos incluyen SoText2 y SoImage, entre otros.

Lo particular de estas formas es que son formas 2D fundamentales, pero se renderizan en la superficie de la pantalla como si fueran en una escena 3D. (Esta es posible porque podemos coincidir el valor de profundidad de cada píxel con las formas 3D en la escena.)

Para calcular una caja de borde precisa de una forma renderizada en 2D en la superficie de la pantalla, debes "deproyectar" el área de pantalla que ocupa a una rectángulo 2D colocada a una profundidad determinada en la escena. Esta operación "deproyectar" requiere conocer las dimensiones de la región de ventana.

También hay formas 3D como por ejemplo SoNurbsSurface que pueden sufrir una distorsión ligeramente si hay un nodo SoComplexity en la jerarquía de la escena con SoComplexity::value establecido a SCREEN_SPACE. Además, es necesario conocer la región de ventana para determinar correctamente la caja de borde de esas formas.

Tú suele querer pasar una región de ventana igual a la disposición del área de canvas actual. Si tienes un observador o una So@Gui@RenderArea disponible, puedes obtener la data de la región de ventana simplemente haciendo

const SbViewportRegion & vpreg = viewer->getViewportRegion();

(Si no tienes un observador o una área de renderización disponible en tu aplicación en el punto donde quieres obtener la caja de borde, probablemente no importe mucho lo que asignes a ella. La precisión de la caja de borde podría ser ligeramente incorrecta frente a la apariencia real de la escena, pero esto suele ser inobservable.)

NAME

SoGetBoundingBoxAction — Action to compute bounding box of scene graph

SYNOPSIS

#include <Inventor/actions/SoGetBoundingBoxAction.h>

Inherits SoAction.

Virtual methods overriding SoAction::beginTraversal():
  void  beginTraversal(SoNode * node) [protected, virtual]

Detailed Description

This is an action that computes the bounding box of a scene graph. The method SoAction::apply() is used to initiate the computation. The bounding box can then be retrieved by calling getBoundingBox(). The action also computes the center of the bounding box, which can be retrieved by calling getCenter().

The bounding box computation can be reset by calling setResetPath().

setResetPath (SoNode * node, const SoGetBoundingBoxAction::ResetType type)

Sets the reset path for the bounding box computation.

If node is not NULL, the bounding box calculation will be reset to the given node. If node is NULL, the reset path is determined by type.

RESET_TO_NODE: Resets the bounding box calculation to the start node of the traversal.

RESET_TO_PARENT: Resets the bounding box calculation to the parent of the current node.

The default is RESET_NONE, which means the bounding box is computed for the entire scene graph starting from the root.

void SoGetBoundingBoxAction::beginTraversal (SoNode * node) [protected], [virtual]

This virtual method is called from SoAction::apply(), and is the entry point for the actual scene graph traversal.

It can be overridden to initialize the action at traversal start, for specific initializations in the action subclasses inheriting SoAction.

Default method just calls traverse(), which any overridden implementation of the method must do too (or call SoAction::beginTraversal()) to trigger the scene graph traversal.
