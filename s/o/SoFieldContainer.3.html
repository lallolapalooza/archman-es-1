Descripción Detallada

La clase SoFieldContainer es una clase base para todas las clases que contienen campos.

Las clases que contienen campos en Coin son las clases de nodo y motor, por lo que todas ellas son sub-clases de SoFieldContainer.

SoFieldContainer proporciona métodos para leer, escribir, comparar por igualdad, realizar operaciones de copia, etc. en campos.

SbBool SoFieldContainer::enableNotify (const SbBool enable)

Este método establece si la notificación se propagará al cambiar los valores de los campos contenidos. Se devuelve el valor anterior del indicador.

La notificación está activada por defecto. Desactivar la notificación automática puede ser útil para optimizar el rendimiento. Durante series de actualizaciones, es posible que desee evitar la propagación de notificaciones en cada cambio de valor de campo si realiza muchas de ellas. Así es como debería manejar esos casos:

SbBool autonotify = node->enableNotify(FALSE);
// ...
// Realice modificaciones en los campos de "node" aquí.
// ...
node->enableNotify(autonotify);
node->touch();

void SoFieldContainer::copyContents (const SoFieldContainer * from, SbBool copyconnections) [virtual]

Hace una copia profunda de todos los datos de from a este instante, a menos que copyconnections sea FALSE y no se hagan referencias externas al escenario.

Este es el método que debería ser sobrescrito por las subclases de nodos / motores / draggers / etc. que necesitan manejar datos internos que no se manejan automáticamente.

Para copiar nodos desde código de aplicación, no invoques directamente este método, sino usa la función SoNode::copy():

SoNode * mynewnode = templatenode->copy();

Lo mismo aplica a los motores.

Asegúrate de que cuando sobrescribas el método copyContents() en tu clase de extensión, también lo llames hacia arriba en la jerarquía de superclases, ya que copyContents() en, por ejemplo, SoNode y SoFieldContainer realiza tareas importantes.

void SoFieldContainer::copyContents (const SoFieldContainer * from, SbBool copyconnections)

This method is intended to be reimplemented by derived classes. It is called from SoFieldContainer::copy() after the fields of the field container has been copied. Derived classes should implement this method to copy any internal data that is not stored in fields.

For example, a derived class might implement it like this:

void
MyCoinExtensionNode::copyContents(const SoFieldContainer * from,
                                  SbBool copyconnections)
{
  // let parent superclasses do their thing (copy fields, copy
  // instance name, etc.)
  SoNode::copyContents(from, copyconnections);
  // [..then copy internal data..]
}

SoFieldContainer * SoFieldContainer::findCopy (const SoFieldContainer * orig, const SbBool copyconnections) [static]

Returns a copy of orig.

If no copy has been made earlier when the function is called, a copy is made on-the-fly (which is the reason we need to pass along the copyconnections flag).

This method will also run the copyContents() method on the copy, if it hasn't been run already. Note that if you call copyContents() on the copy outside of this method, this will go undetected and the guts of orig will be copied multiple times into its copy.

If copyContents() is called directly (instead of using copy()), it is assumed that the user only wants to copy the field values, and we just return NULL here. This is done to match how it's done in SGI Inventor.

void SoFieldContainer::getFieldsMemorySize (size_t & managed, size_t & unmanaged) const [virtual]

Returns the data array sizes of the SoFieldData-registered multi-fields. The managed argument returns the size of the fields that Coin manages the memory for, and the unmanaged argument returns the size of the data in the multi-fields controlled by the application through SoMField::setValuesPointer() which Coin will not delete.

Data that is kept in the object memory chunk (that is included when you do sizeof(object)) is not included in these values - only the memory that is managed in additional memory chunks from the object chunk is returned.

Extension field types that are not known to the plain Coin library are not accounted for. This function is therefore virtual, so such extension field types can be added to the numbers for extension nodes.

This method is used for memory profiling purposes.

SbBool SoFieldContainer::readInstance (SoInput * in, unsigned short flags) [protected], [virtual]

This method is mainly intended for internal use during file import operations.

It reads a definition of an instance from the input stream in. The input stream state points to the start of a serialized / persistent representation of an instance of this class type.

TRUE or FALSE is returned, depending on if the instantiation and configuration of the new object of this class type went OK or not. The import process should be robust and handle corrupted input streams by returning FALSE.

flags is used internally during binary import when reading user extension nodes, group nodes or engines.
