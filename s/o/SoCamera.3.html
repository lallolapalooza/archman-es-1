Descripción Detallada

La clase SoCamera es la clase base abstracta para nodos de definición de cámara.

Para poder ver una escena, es necesario tener una cámara en el grafo de escena. Un nodo de cámara configurará las matrices de proyección y de vista para la renderización de la geometría en la escena.

Este nodo solo define la interfaz abstracta al recopilar campos comunes que todos los nodos de tipo cámara necesitan. Utilice las subclases de cámara no abstractas dentro de un grafo de escena. Las que forman parte por defecto de la biblioteca Coin son SoPerspectiveCamera y SoOrthographicCamera, que utilizan las dos proyecciones diferentes indicadas por su nombre.

Tenga en cuenta que los componentes de visor de las bibliotecas de unión GUI de Coin (SoXt, SoQt, SoWin, etc.) insertarán automáticamente una cámara en un grafo de escena si no se ha definido ninguna.

Es posible tener más de una cámara en un grafo de escena. Un truco común es, por ejemplo, utilizar una segunda cámara para mostrar geometría estática o geometría superpuesta (por ejemplo, para pantallas heads-up ("HUD")), como se muestra en este código de ejemplo:

#include <Inventor/Qt/SoQt.h>
#include <Inventor/Qt/viewers/SoQtExaminerViewer.h>
#include <Inventor/nodes/SoNodes.h>
int
main(int argc, char ** argv)
{
  QWidget * mainwin = SoQt::init(argv[0]);
  SoSeparator * root = new SoSeparator;
  root->ref();
  // Añade una cámara y un cono rojo. La primera cámara encontrada en el
  // grafo de escena por el SoQtExaminerViewer será capturada e
  // inicializada automáticamente.
  root->addChild(new SoPerspectiveCamera);
  SoMaterial * material = new SoMaterial;
  material->diffuseColor.setValue(1.0, 0.0, 0.0);
  root->addChild(material);
  root->addChild(new SoCone);
  // Configura una segunda cámara para la geometría restante. Esta cámara
  // no será capturada ni influenciada por el visor, por lo que la
  // geometría se mantendrá estática.
  SoPerspectiveCamera * pcam = new SoPerspectiveCamera;
  pcam->position = SbVec3f(0, 0, 5);
  pcam->nearDistance = 0.1;
  pcam->farDistance = 10;
  root->addChild(pcam);
  // Añade un cono verde para demostrar geometría estática.
  SoMaterial * greenmaterial = new SoMaterial;
  greenmaterial->diffuseColor.setValue(0, 1.0, 0.0);
  root->addChild(greenmaterial);
  root->addChild(new SoCone);
  SoQtExaminerViewer * viewer = new SoQtExaminerViewer(mainwin);
  viewer->setSceneGraph(root);
  viewer->show();
  SoQt::show(mainwin);
  SoQt::mainLoop();
  delete viewer;
  root->unref();
  return 0;
}

NOTA: El soporte para múltiples cámaras en Coin es limitado, y los problemas con múltiples cámaras se considerarán corregidos caso por caso.

virtual SbViewVolume SoCamera::getViewVolume (float useaspectratio = 0.0f) const [pure virtual]

Devuelve el volumen de vista total cubierto por la cámara bajo la configuración actual.

Este volumen de vista no se ajusta para tener en cuenta el mapeo de la región de visualización. Si desea el mismo volumen de vista que el utilizado durante la renderización, debería usar getViewVolume(SbViewportRegion & vp, const SbMatrix & mm), o hacer algo como esto:

SbViewVolume vv;
float aspectratio = myviewport.getViewportAspectRatio();
switch (camera->viewportMapping.getValue()) {
case SoCamera::CROP_VIEWPORT_FILL_FRAME:
case SoCamera::CROP_VIEWPORT_LINE_FRAME:
case SoCamera::CROP_VIEWPORT_NO_FRAME:
  vv = camera->getViewVolume(0.0f);
  break;
case SoCamera::ADJUST_CAMERA:
  vv = camera->getViewVolume(aspectratio);
  if (aspectratio < 1.0f) vv.scale(1.0f / aspectratio);
  break;
case SoCamera::LEAVE_ALONE:
  vv = camera->getViewVolume(0.0f);
  break;
default:
  assert(0 && "unknown viewport mapping");
  break;
}

Además, para los mapeos de región de visualización RECORTADOS, la región de visualización podría cambiarse si la relación de aspecto de la región de visualización no es igual a la relación de aspecto de la cámara. Consulte el código fuente de SoCamera::getView() (método privado) para ver cómo se hace esto.

Implementado en SoFrustumCamera, SoOrthographicCamera y SoPerspectiveCamera.

void SoCamera::viewAll (SoNode *const sceneroot, const SbViewportRegion & vpregion, const float slack = 1.0f)

Posiciona la cámara de modo que toda la geometría de la escena de sceneroot quede contenida en el volumen de vista de la cámara, manteniendo constante la orientación de la cámara.

Encuentra el cuadro delimitador de la escena y llama a SoCamera::viewBoundingBox(). Se calculará una esfera delimitadora a partir del cuadro delimitador de la escena, por lo que la cámara "verá todo" incluso cuando la escena se rote, de cualquier manera.

El argumento slack proporciona un factor de multiplicación para la distancia que se supone que la cámara se aleja del punto medio de sceneroot.

Un valor menor que 1.0 para el argumento slack hará que la cámara se acerque a la escena, un valor de 1.0 la posicionará justo fuera de la esfera delimitadora de la escena, y un valor mayor que 1.0 dará "slack adicional" frente a la esfera delimitadora de la escena.

void SoCamera::setStereoAdjustment (float adjustment)

Establece el ajuste estéreo. Esta es la distancia entre el "ojo" izquierdo y derecho al realizar renderizado estéreo.

Al realizar renderizado estéreo, Coin renderizará dos vistas, una para el ojo izquierdo y otra para el ojo derecho. El ajuste estéreo es, de forma algo simplificada, cuánto se traslada la cámara a lo largo del eje X local entre la vista izquierda y la derecha.

La distancia por defecto es 0.1, que se elige porque es la distancia aproximada entre los ojos humanos.

Para crear un efecto estéreo agradable y visible, el programador de la aplicación a menudo tendrá que ajustar este valor. Si todo lo que quiere hacer es examinar objetos 3D simples e independientes, es posible calcular un desplazamiento estéreo basado en el cuadro delimitador del modelo 3D (o reducir el tamaño del modelo a un tamaño apropiado).

Sin embargo, si tiene una escena grande, en la que desea moverse por la escena y ver en estéreo diferentes objetos a medida que se acerca a ellos, no puede calcular el desplazamiento estéreo basándose en el cuadro delimitador de la escena, sino que debe utilizar un desplazamiento estéreo basado en la escala de los objetos/detalles individuales que desea examinar.

Tenga en cuenta que es importante establecer una distancia focal sensata al realizar renderizado estéreo. Consulte setBalanceAdjustment() para obtener información sobre cómo la distancia focal afecta al renderizado estéreo.

DESCRIPTION

This class defines the interface for camera nodes in Coin. It is an abstract base class and must be inherited from.

Camera nodes are responsible for defining the viewpoint onto the scene graph. They define parameters such as position, orientation, field of view (field of view, frustum, etc.), near and far clipping planes.

The camera node itself does not perform any rendering. Instead, camera nodes are traversed by render actions like SoGLRenderAction, SoCallbackAction, SoGetMatrixAction, etc., which use the camera parameters to perform their respective tasks.

The camera's position and orientation are defined in world coordinates. The viewing volume is defined in camera coordinates.

The abstract base class defines common parameters such as position, orientation, focal distance, and near and far clipping planes. It also defines virtual methods for action traversals, most of which are reimplemented from SoNode.

The concrete camera nodes derived from this class are SoPerspectiveCamera (for perspective projection) and SoOrthographicCamera (for orthographic projection).

SoSFRotation SoCamera::orientation

Camera orientation specified as a rotation value from the default orientation where the camera is pointing along the negative Z-axis, with "up" along the positive Y-axis.

E.g., to rotate the camera to point along the X-axis:

mycamera->orientation.setValue(SbRotation(SbVec3f(0, 1, 0), M_PI / 2.0f));

For queries, e.g. to get the current "up" and "look at" vectors of the camera:

SbRotation camrot = mycamera->orientation.getValue();
SbVec3f upvec(0, 1, 0); // init to default up vector
camrot.multVec(upvec, upvec);
SbVec3f lookat(0, 0, -1); // init to default view direction vector
camrot.multVec(lookat, lookat);

SoSFFloat SoCamera::nearDistance

Distance from camera position to the near clipping plane in the camera's view volume.

Default value is 1.0. Value must be larger than 0.0, or it will not be possible to construct a valid viewing volume (for perspective rendering, at least).

If you use one of the viewer components from the So[Xt|Qt|Win|Gtk] GUI libraries provided Kongsberg Oil & Gas Technologies, they will automatically update this value for the scene camera according to the scene bounding box. Ditto for the far clipping plane.

See also

SoCamera::farDistance

SoSFFloat SoCamera::farDistance

Distance from camera position to the far clipping plane in the camera's view volume.

Default value is 10.0. Must be larger than the SoCamera::nearDistance value, or it will not be possible to construct a valid viewing volume.

Note that the range [nearDistance, farDistance] decides the dynamic range of the z-buffer in the underlying polygon-rendering rasterizer. What this means is that if the near and far clipping planes of the camera are wide apart, the possibility of visual artifacts will increase. The artifacts will manifest themselves in the form of flickering of primitives close in depth.

It is therefore a good idea to keep the near and far clipping planes of your camera(s) as closely fitted around the geometry of the scene graph as possible.

See also

SoCamera::nearDistance, SoPolygonOffset
