The SoGeoOrigin class is used to specify an absolute geographic location against which geometry is referenced.

FILE FORMAT/DEFAULTS:

GeoOrigin {
  geoSystem ["GD", "WE"]
  geoCoords 0 0 0
}

A common problem when working with geographic data is the reduced floating point precision that is often obtained. UTM coordinates are often in the range of 10^5 to 10^6 and this leaves very little precision for details at that position.

SoGeo nodes are useful when you want to keep your data in its original system, but still get good rendering precision.

Coin needs a local Cartesian coordinate system when rendering. When an SoGeoOrigin node is used, Coin will create a coordinate system at the position of the SoGeoOrigin and all geometries (and the camera) in the scene tree will be projected into this system. The coordinate system will always have the Z-axis pointing up from the ground. The Y-axis will point toward the north pole, and the X-axis will be found by the right-hand rule.

A scene tree should contain only one GeoOrigin node, and all geometries in the scene tree will be rendered with respect to this position. This means that precision will be best if the GeoOrigin position is as close as possible to the camera position. If you are moving around in a large area, it may be a good idea to also move the GeoOrigin position instead of the camera.

To place geometries in the scene tree, you can use either an SoGeoSeparator node or an SoGeoCoordinate node. When using an SoGeoSeparator node, all geometries within that separator will be rendered with respect to its geographic coordinate system position and orientation, and then you will use regular shapes and regular SoCoordinate3 nodes to specify the data (the coordinates of the points in an SoCoordinate3 should be offset to the position of the SoGeoSeparator).

The SoGeoCoordinate node can contain double precision geo coordinates, and this node internally recalculates the double precision matrix to a single precision matrix relative to the SoGeoOrigin node.

A note on UTM projections: Since it is quite common to assume a flat surface when working with UTM data, it is possible to provide a FLAT keyword for UTM coordinate systems:

GeoOrigin {
  geoSystem [ "UTM", "Z17", "FLAT" ]
  geoCoords  846889 4313850 0
}

NAME

SoGeoOrigin — specifies the origin of a geographic coordinate system

SYNOPSIS

#include <Inventor/nodes/SoGeoOrigin.h>

Inheritance:
SoNode >
SoSeparator >
SoGeoOrigin

Included nodes:
SoGeoOrigin

Fields:
    geoCoords, geoSystem

Detailed Description

This node specifies the origin of a geographic coordinate system. It is used to translate geographic coordinates into the local coordinate system of the scene graph.

The geoCoords field specifies the coordinates of the origin in the given coordinate system, and the geoSystem field specifies the coordinate system itself.

Member Data Documentation

SoSFVec3d SoGeoOrigin::geoCoords

Used for specifying the geographic coordinates. For the GD system this should be <latitude> <longitude> <elevation>. For UTM it is <easting> <northing> <elevation>, and for GC it is simply <x> <y> <z>.

SoMFString SoGeoOrigin::geoSystem

Used to specify a spatial reference frame. Coin currently supports three different systems. Support for more systems might be added in the future.

•
“GD” - The Geodetic system (latitude/longitude).
•
“UTM” - Universal Transverse Mercator coordinate system. The second string should be the zone, encoded as “Z<n>”.
•
“GC” - Earth-fixed Geocentric with respect to the WGS84 ellipsoid.

The “GD” and “UTM” systems can, for future support, have an ellipsoid specification. The default is “WE” which is the WGS84 ellipsoid, the only ellipsoid currently supported in Coin.
