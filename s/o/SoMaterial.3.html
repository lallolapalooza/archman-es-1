Descripción Detallada

La clase SoMaterial es un tipo de nodo para configurar valores de material para la geometría de la escena.

Después de recorrer un nodo SoMaterial, los nodos de forma subsiguientes con geometría en el grafo de escena utilizarán los valores del "pool" de materiales del estado de recorrido configurado a partir de nodos de este tipo.

Para obtener información detallada sobre los diversos componentes, consulte el modelo de color de OpenGL, presentado en el capítulo "Colores y Coloreado" (capítulo 2.13 en la especificación de OpenGL 1.4).

Tenga en cuenta que los valores de un nodo de material *reemplazarán* los valores anteriores del estado de recorrido, *no* se acumularán. Ese es el caso incluso cuando, por ejemplo, los cambios de material son *implícitos* en un archivo iv, como se ilustra en el siguiente ejemplo:

También tenga en cuenta que el soporte para múltiples valores en ambientColor, emissiveColor, specularColor y shininess fue obsoleto en Open Inventor 2.1. La razón de este cambio de diseño fue impulsada por el rendimiento, ya que es relativamente lento cambiar las propiedades del material de OpenGL. Sin embargo, cambiar el valor del color difuso es rápido, por lo que todavía es posible tener múltiples valores de diffuseColor y transparency.

#Inventor V2.1 ascii
Material { ambientColor 1 0 0 }
Cone { }
Translation { translation 5 0 0 }
Material { }
Sphere { }

(La SoSphere no "heredará" el SoMaterial::ambientColor del primer nodo SoMaterial, aunque no esté explícitamente establecido en el segundo nodo de material. Se utilizará el valor predeterminado de SoMaterial::ambientColor.)

Tenga en cuenta que los nodos importados como parte de un archivo VRML V1.0 tienen un caso especial, donde los campos SoMaterial::ambientColor, SoMaterial::diffuseColor y SoMaterial::specularColor contienen valores cero, y SoMaterial::emissiveColor contiene uno o más valores. Los valores en SoMaterial::emissiveColor deben tratarse como iluminación precalculada, y los otros campos deben ser ignorados.

Puede detectar este caso comprobando los valores de los elementos del material cuando el grafo de escena se recorre utilizando una SoCallbackAction. SoDiffuseColorElement, SoAmbientColorElement y SoSpecularColorElement contendrán un valor con un color completamente negro (0.0f, 0.0f, 0.0f), SoShininessElement contendrá un valor de 0.0f y SoEmissiveColorElement contendrá uno o más valores. Esto se hace para que la renderización funcione correctamente en sistemas que no prueban este caso específico.

Solo debe comprobar este caso cuando esté recorriendo un grafo de escena de tipo VRML V1.0, por supuesto. Consulte SoNode::getNodeType() para obtener información sobre cómo se pueden probar los nodos para determinar si han sido importados o configurados de otro modo como de tipo VRML1 en comparación con tipo Inventor.

Cuando el grafo de escena se renderiza utilizando una SoGLRenderAction, los elementos se establecerán de manera diferente para optimizar la renderización. El SoDiffuseColorElement se establecerá en los valores de SoMaterial::emissiveColor, y el modelo de luz se establecerá en SoLightModel::BASE_COLOR.

Los valores de SoMaterial::transparency siempre se tratarán normalmente.

Aquí hay un ejemplo de uso muy simple:

#Inventor V2.1 ascii
Separator {
   Coordinate3 {
      point [ 0 0 0, 1 0 0, 1 1 0 ]
   }
   Material {
      diffuseColor [ 1 0 0, 1 1 0, 0 0 1 ]
   }
   MaterialBinding {
      value PER_VERTEX
   }
   IndexedFaceSet {
      coordIndex [ 0, 1, 2, -1 ]
   }
}

FORMATO DE ARCHIVO/VALORES PREDETERMINADOS:

Material {
    ambientColor 0.2 0.2 0.2
    diffuseColor 0.8 0.8 0.8

Detailed Description

This node defines the material properties of the subsequent geometry within the scene graph. Materials define how objects reflect light, and are typically used to give surfaces different visual characteristics like color, shininess, and transparency.

The node has fields for:

  • Ambient color: The color of the object under ambient light.
  • Diffuse color: The color of the object under direct light.
  • Specular color: The color of specular highlights (shiny spots).
  • Emissive color: The color emitted by the object itself (glow).
  • Shininess: Controls the size and intensity of specular highlights.
  • Transparency: Controls the opacity of the object.

All color fields are of type SoMFColor, but only the first color in the list is used. The shininess and transparency fields are of type SoMFFloat, and again, only the first value is used.

Member Data Documentation

SoMFColor SoMaterial::ambientColor

Ambient material part color values. Will by default contain a single color value of [0.2, 0.2, 0.2] (i.e. dark gray).

The ambient part of the material is not influenced by any light sources, and should be thought of conceptually as the constant, but small contribution of light to a scene "seeping in" from everywhere.

(Think of the ambient contribution in the context that there's always photons fizzing around everywhere -- even in a black room without light sources, for instance).

Only the first value in this field will be used. All other values will be ignored.

See also

SoEnvironment::ambientIntensity

SoMFColor SoMaterial::diffuseColor

Diffuse material part color values. This field is by default initialized to contain a single color value of [0.8, 0.8, 0.8] (light gray).

The diffuse part is combined with the light emitted from the scene's light sources.

Traditional Open Inventor uses the same override bit for both diffuse color and transparency. To get around this problem if you need to override one without the other, set the environment variable "COIN_SEPARATE_DIFFUSE_TRANSPARENCY_OVERRIDE". This is a Coin extension, and will not work on other Open Inventor implementations.

SoMFColor SoMaterial::specularColor

Specular material part color values. Defaults to a single color value of [0, 0, 0] (black).

Only the first value in this field will be used. All other values will be ignored.

SoMFColor SoMaterial::emissiveColor

The color of the light "emitted" by the subsequent geometry, independent of lighting / shading.

Defaults to contain a single color value of [0, 0, 0] (black, i.e. no contribution).

Only the first value in this field will be used. All other values will be ignored.

SoMFFloat SoMaterial::shininess

Shininess values. Decides how the light from light sources are distributed across the geometry surfaces. Valid range is from 0.0 (which gives a dim appearance), to 1.0 (glossy-looking surfaces).

Defaults to contain a single value of 0.2.

Only the first value in this field will be used. All other values will be ignored.

SoMFFloat SoMaterial::transparency

Transparency values. Valid range is from 0.0 (completely opaque, which is the default) to 1.0 (completely transparent, i.e. invisible).

Defaults to contain a single value of 0.0.

Traditional Open Inventor uses the same override bit for both transparency and diffuse color. To get around this problem if you need to override one without the other, set the environment variable "COIN_SEPARATE_DIFFUSE_TRANSPARENCY_OVERRIDE". This is a Coin extension, and will not work on other Open Inventor implementations.
