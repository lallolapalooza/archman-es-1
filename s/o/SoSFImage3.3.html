Descripción Detallada

La clase SoSFImage3 se usa para almacenar imágenes 3D (volumétricas).

La clase SoSFImage3 proporciona almacenamiento para mapas de imágenes 3D en línea. Las imágenes 3D en Coin se usan principalmente para soporte de mapeo de texturas 3D.

Las instancias de SoSFImage3 pueden ser exportadas e importadas como cualquier otra clase de campo en Coin.

Los componentes de una SoSFImage3 son: sus dimensiones de imagen (ancho, alto y profundidad), el número de bytes utilizados para describir cada píxel (número de componentes) y un búfer de píxeles asociado. El tamaño del búfer de píxeles será ancho*alto*profundidad*componentes.

Para mapas de texturas, los componentes / bytes-por-píxel se traducen de la siguiente manera: usar 1 para un mapa de imagen en escala de grises, 2 para escala de grises + opacidad (es decir, valor alfa), 3 para RGB (1 byte cada uno para rojo, verde y azul) y 4 componentes significa 3 bytes para RGB + 1 byte de valor de opacidad (también conocido como RGBA).

Este campo es serializable en el formato de archivo Inventor / Coin de la siguiente manera:

NOMBRECAMPO X Y Z C 0xRRGGBBAA 0xRRGGBBAA ...

"X", "Y" y "Z" son las dimensiones de la imagen a lo largo de los ejes dados, "C" es el número de componentes en la imagen. El número de especificaciones de color de píxel 0xRRGGBBAA debe igualar el número exacto de píxeles, que es X*Y*Z. Cada parte del valor de color del píxel está en el rango 0x00 a 0xff (hexadecimal, 0 a 255 decimal).

Para imágenes de 3 componentes, el formato de píxel es 0xXXRRGGBB, donde el byte en el valor de color del píxel marcado como "XX" se ignora y se puede omitir.

Para imágenes de 2 componentes, el formato de píxel es 0xXXXXGGAA, donde los bytes en los valores de color del píxel marcados como "XX" se ignoran y se pueden omitir. "GG" es la parte que proporciona un valor de escala de grises y "AA" es para la opacidad.

Para imágenes de 1 componente, el formato de píxel es 0xXXXXXXGG, donde los bytes en los valores de color del píxel marcados como "XX" se ignoran y se pueden omitir.

Los píxeles se leen ordenados en filas a lo largo de X (ancho), columnas a lo largo de Y (alto, de abajo hacia arriba) y planos Z (profundidad, de adelante hacia atrás).

Aquí hay un ejemplo simple de la serialización del formato de archivo, para una imagen RGB de 2x2x2 dentro de un nodo SoTexture3:

Texture3 {
  images 2 2 2 3
  0x000000 0x00ff00
  0xff0000 0xffff00
  0x000000 0x0000ff
  0x00ff00 0x00ffff
}

La imagen anterior está coloreada en negro+verde en la primera línea y rojo+amarillo en la segunda línea en el primer plano Z. El segundo plano Z está coloreado en negro+azul en la primera línea y verde+cian en la segunda línea.

NAME

SoSFImage3

3D image field

SYNOPSIS

#include <Inventor/fields/SoSFImage3.h>

Inherits SoField.

DESCRIPTION

This field is an extension for Coin, and it is not available in the original SGI Open Inventor v2.1 API.

See also

SoTexture3, SoSFImage

Since

Coin 2.0

TGS Inventor 2.6
