SOAP::Serializer(3) Documentación de Perl contribuida por el usuario SOAP::Serializer(3)

NOMBRE

SOAP::Serializer - el medio por el cual el toolkit gestiona la expresión de datos como XML

DESCRIPCIÓN

La clase SOAP::Serializer es el medio por el cual el toolkit gestiona la expresión de datos como XML. El objeto que una instancia de SOAP::Lite usa por defecto suele ser suficiente para la tarea, sin necesidad de que la aplicación cree el suyo propio. El propósito principal de esta clase es proporcionar un lugar para que las aplicaciones extiendan el serializador definiendo métodos adicionales para manejar nuevos tipos de datos.

MÉTODOS

new(pares clave/valor opcionales)
$serialize = SOAP::Serializer->new( );

Este es el método constructor de la clase. Además de crear un objeto básico e inicializarlo con valores por defecto, el constructor también puede tomar nombres y valores para la mayoría de los métodos accesores que la clase soporta.

envelope(método, argumentos de datos)
$serialize->envelope(fault => $fault_obj);

Proporciona el propósito central de la clase SOAP::Serializer. Crea el sobre SOAP completo basado en la entrada que se le pasa. Los argumentos de datos pasados en la lista de parámetros al método se dividen en dos sublistas: cualquier parámetro que sean objetos SOAP::Header o derivados de ellos va a una lista, mientras que el resto va a la otra. Los objetos no cabecera se utilizan como contenido del cuerpo del mensaje, siendo el cuerpo en sí mismo en gran medida dependiente del valor del primer argumento de la lista. Se espera que este argumento sea una cadena y debe ser uno de los siguientes:

contexto
$serialize->context->packager();

Esto proporciona acceso al contexto de llamada de "SOAP::Serializer". En un contexto del lado del cliente, a menudo significa una referencia a una instancia de SOAP::Lite. En un contexto del lado del servidor, significa una referencia a una instancia de SOAP::Server.

método
El sobre se está creando para encapsular una llamada a método estilo RPC.
respuesta
El mensaje que se está creando es el de una respuesta derivada de una llamada a método estilo RPC.
fallo
Para este especificador, el sobre que se está creando es para transmitir un fallo.
freeform
Este identificador se utiliza como estilo de codificación de caso general para mensajes que no encajan en ninguno de los casos anteriores. Los argumentos se codifican en la etiqueta Body del sobre sin ningún tipo de sensibilidad al contexto.

Cualquier valor distinto de estos cuatro da como resultado un error.

prefijo_sobre(valor opcional)
$serialize->envprefix('env');

Obtiene o establece el prefijo que etiqueta el espacio de nombres del sobre SOAP. Esto tiene por defecto SOAP-ENV.

prefijo_codificación(valor opcional)
$serialize->envprefix('enc');

Obtiene o establece el prefijo que etiqueta el espacio de nombres de codificación SOAP. Por defecto es SOAP-ENC.

versión_soap(valor opcional)
$serialize->soapversion('1.2');

Si no se proporciona ningún parámetro, devuelve la versión actual de SOAP que se utiliza como base para serializar mensajes. Si se proporciona un parámetro, intenta establecerlo como la versión de SOAP que se está utilizando. El valor debe ser 1.1 o 1.2. Cuando se establece la versión de SOAP, el paquete selecciona nuevas URNs para los espacios de sobres y codificación y también llama al método xmlschema para establecer la definición del esquema apropiada.

xmlschema(valor opcional)
$serialize->xmlschema($xml_schema_1999);

Obtiene o establece la URN del esquema que se está utilizando para expresar la estructura del XML generado por el serializador. Si se establece el valor, la entrada debe ser la URN completa del nuevo esquema y se comprueba contra la lista de esquemas SOAP conocidos.

registrar_ns
La subrutina registrar_ns permite a los usuarios registrar un espacio de nombres global con el Sobre SOAP. El primer parámetro es el espacio de nombres, el segundo parámetro a esta subrutina es un prefijo opcional. Si no se proporciona un prefijo, se generará automáticamente uno para usted. Todos los espacios de nombres registrados con el serializador se declaran en el elemento <soap:Envelope />.
encontrar_prefijo
La subrutina encontrar_prefijo toma un espacio de nombres como parámetro y devuelve el prefijo asignado a ese espacio de nombres. Esto elimina la necesidad de declarar y redeclarar espacios de nombres dentro de un sobre. Esta subrutina es especialmente útil para determinar el prefijo correcto al asignar un tipo a un elemento SOAP::Data. Un buen ejemplo de cómo podría usarse esto es el siguiente: 
SOAP::Data->name("foo" => $inputParams{'foo'})
   ->type($client->serializer->find_prefix('urn:Foo').':Foo');

TIPOS DE DATOS PERSONALIZADOS

Al serializar un objeto, o una referencia a hash bendecida, a XML, "SOAP::Serializer" primero comprueba si se ha definido una subrutina para el nombre de clase correspondiente. Por ejemplo, en el siguiente código, "SOAP::Serializer" comprobará si se ha definido una subrutina llamada "as_MyModule__MyPackage". Si es así, pasará $foo a esa subrutina junto con otros datos conocidos sobre el elemento "SOAP::Data" que se está codificando.

$foo = MyModule::MyPackage->new;
my $client = SOAP::Lite
   ->uri($NS)
   ->proxy($HOST);
$som = $client->someMethod(SOAP::Data->name("foo" => $foo));

REQUISITOS DE SUBRUTINA as_TypeName

Convención de nomenclatura
La subrutina siempre debe ir precedida por "as_" seguida del nombre del tipo. El nombre del tipo debe tener todos los dos puntos (':') sustituidos por un guion bajo ('_').
Entrada
La entrada a "as_TypeName" tendrá al menos un parámetro y como máximo cuatro. El primer parámetro siempre será el valor o el objeto a codificar. Los tres parámetros siguientes dependen del contexto del valor/objeto que se está codificando.

Si el valor/objeto que se está codificando formaba parte de un objeto "SOAP::Data" (como en el ejemplo anterior), entonces el segundo, tercer y cuarto parámetro serán el nombre del elemento "SOAP::Data", el tipo y el conjunto de atributos respectivamente. Si, por el contrario, el valor/objeto que se está codificando *no* forma parte de un objeto "SOAP::Data", como en el código siguiente:

$foo = MyModule::MyPackage->new;
my $client = SOAP::Lite
   ->uri($NS)
   ->proxy($HOST);
$som = $client->someMethod($foo);

Entonces el segundo y tercer parámetro serán el nombre de la clase del valor/objeto que se está codificando (por ejemplo, "MyModule::MyPackage" en el ejemplo anterior), y el cuarto parámetro será un hash vacío.

Salida
La subrutina de codificación debe devolver un array que contenga tres elementos: 1) el nombre del elemento XML, 2) un hash que contenga los atributos que se colocarán en el elemento, y 3) el valor del elemento.

SOAP::Serializer(3pm)

NAME

SOAP::Serializer - Object serialization

SYNOPSIS

  use SOAP::Lite;
  my $s = SOAP::Serializer->new;
  my $xml = $s->serialize(SOAP::Data->name("foo" => "bar"));
  my $xml = $s->serialize($obj);
  my $xml = $s->serialize(SOAP::Data->name("int" => 10)->type('int'));
  my $xml = $s->serialize(SOAP::Data->name("uri" => 'http://}')->type('uriReference'));

DESCRIPTION

The "SOAP::Serializer" class is responsible for the serialization of Perl data structures into the SOAP protocol's native XML format. It is capable of handling all of the basic data types as well as complex data structures like arrays and hashes. It also supports the extensibility of the SOAP protocol by allowing users to define their own custom data types.

The serialization process is fairly straightforward. First, "SOAP::Serializer" checks to see if the object being serialized has been explicitly typed. If it has, then "SOAP::Serializer" checks to see if there is an "as_TypeName" subroutine defined for that type. If such a subroutine exists, it is called to perform the serialization. If not, then "SOAP::Serializer" attempts to automatically determine the type of the object based on its value and internal type lookup tables.

If the type has not been explicitly stated, and if a type cannot be automatically determined, then "SOAP::Serializer" will attempt to serialize the object based on one of Perl's basic types: REF, SCALAR, ARRAY or HASH.

For a complete list of data types supported by default and their corresponding type precedence values, see Table 1 - Autotyping Precedence.

METHODS

new
Creates and returns a new "SOAP::Serializer" object.
serialize
Takes a single argument, which should be a "SOAP::Data" object or a plain Perl value, and returns its XML representation.
deserialize
Takes a single argument, which should be an XML string representing a SOAP-encoded value, and returns the corresponding Perl value.
typelookup
Returns the hash used for type lookup. This hash can be modified to add new custom data types.

CUSTOM DATA TYPES

One of the powerful features of "SOAP::Lite" is its ability to support custom data types. This is achieved through the use of the "SOAP::Serializer::typelookup" hash and the "as_TypeName" subroutines.

as_TypeName SUBROUTINE REQUIREMENTS

In order for a custom data type to be recognized and serialized by "SOAP::Serializer", the following criteria must be met:

  1. Explicit Typing: The "SOAP::Data" object must be explicitly typed using the "type" method, e.g.: 

      $data = SOAP::Data->name('myCustomType' => $value)->type('myCustomType');
  2. Encoding Subroutine: An encoding subroutine named "as_myCustomType" must be defined. This subroutine takes the following arguments:
    • $self: The serializer object.
    • $value: The value to be serialized.
    • $name: The name of the element.
    • $type: The explicit type name.
    • $attr: A hash reference containing any attributes.
    The subroutine must return an array reference containing three elements: the element name, a hash reference of attributes, and the element value. 

      sub SOAP::Serializer::as_myCustomType {
      my ($self, $value, $name, $type, $attr) = @_;
      return [$name, {'xsi:type' => $type, %$attr}, $value];
  }
  3. Type Lookup Registration: The new type must be registered in the "SOAP::Serializer::typelookup" hash. This involves specifying a precedence value, a test subroutine, and the name of the encoding subroutine. 

      $s->typelookup->{myCustomType} = [1, \&myCustomTypeTest, 'as_myCustomType'];
    The test subroutine (e.g., "myCustomTypeTest") takes a single argument (the value to be tested) and returns 1 if the value is of the custom type, and 0 otherwise. 

      sub SOAP::Serializer::myCustomTypeTest {
      my ($value) = @_;
      return 1 if (defined $value and ref($value) eq 'MyCustomClass');
      return 0;
  }
    The precedence value is a number that determines the order in which type tests are performed. Lower numbers indicate higher precedence.

AUTOTYPING

When a "SOAP::Data" object is not explicitly typed, "SOAP::Serializer" attempts to determine the type automatically. This process is called autotyping.

Autotyping is performed by iterating through the "SOAP::Serializer::typelookup" hash in order of precedence. For each entry in the hash, the corresponding test subroutine is called with the value of the "SOAP::Data" object. If the test subroutine returns true, the type is considered detected, and the corresponding encoding subroutine is used.

If no test subroutine returns true, "SOAP::Serializer" falls back to serializing the object based on Perl's intrinsic types (REF, SCALAR, ARRAY, HASH).

It's important to note that if a type hasn't been declared explicitly, SOAP::Lite must "guess" at the object's type. This is because the only form of introspection that Perl provides (through the use of the "ref" subroutine) does not provide enough information to "SOAP::Serializer" to allow SOAP::Lite to determine the exact type of an element being serialized.

To work around this limitation, the "SOAP::Serializer::typelookup" hash was created. This hash is populated with all the data types that the current "SOAP::Serializer" can auto detect. Users and developers are free to modify the contents of this hash allowing them to register new data types with the system.

When "SOAP::Serializer" is asked to encode an object into XML, it goes through the following steps. First, "SOAP::Serializer" checks to see if a type has been explicitly stated for the current object. If a type has been provided "SOAP::Serializer" checks to see if an "as_TypeName" subroutine as been defined for that type. If such a subroutine exists, then "SOAP::Serializer" passes the object to it to be encoded. If the subroutine does not exist, or the type has not been provided, then "SOAP::Serializer" must attempt to "guess" the type of the object being serialized.

To do so, "SOAP::Serializer" runs in sequence a set of tests stored in the "SOAP::Serializer::typelookup" hash. "SOAP::Serializer" continues to run each test until one of the tests returns true, indicating that the type of the object has been detected. When the type of the object has been detected, then "SOAP::Serializer" passes the object to the encoding subroutine that corresponds with the test that was passed. If all the tests fail, and the type was not determined, then "SOAP::Serializer" will as a last resort encode the object based on one of the four basic data types known to Perl: REF, SCALAR, ARRAY and HASH.

REGISTERING A NEW DATA TYPE

To register a new data type that can be automatically detected by "SOAP::Lite" and then serialized into XML, the developer must provide the following four things:

  • The name of the new data type.
  • A subroutine that is capable of detecting whether a value passed to it is of the corresponding data type.
  • A number representing the test subroutine's precedence relative to all the other types' test subroutinestypes. See Table 1 - Autotyping Precedence.
  • A subroutine that is capable of providing "SOAP::Serializer" with the information necessary to serialize an object of the corresponding data type into XML.

EXAMPLE 1

If, for example, you wish to create a new datatype called "uriReference" for which you would like Perl values to be automatically detected and serialized into, then you follow these steps.

Step 1: Write a Test Subroutine

The test subroutine will have passed to it by "SOAP::Serializer" a value to be tested. The test subroutine must return 1 if the value passed to it is of the corresponding type, or else it must return 0.

sub SOAP::Serializer::uriReferenceTest {
  my ($value) = @_;
  return 1 if ($value =~ m!^http://!);
  return 0;
}

Step 2: Write an Encoding Subroutine

The encoding subroutine provides "SOAP::Serializer" with the data necessary to encode the value passed to it into XML. The encoding subroutine name's should be of the following format: "as_"<Type Name>.

The encoding subroutine will have passed to it by "SOAP::Serializer" four parameters: the value to be encoded, the name of the element being encoded, the assumed type of the element being encoded, and a reference to a hash containing the attributes of the element being encoded. The encoding subroutine must return an array representing the encoded datatype. "SOAP::Serializer" will use the contents of this array to generate the corresponding XML of the value being encoded, or serialized. This array contains the following 3 elements: the name of the XML element, a hash containing the attributes to be placed into the element, and the value of the element.

sub SOAP::Serializer::as_uriReference {
  my $self = shift;
  my($value, $name, $type, $attr) = @_;
  return [$name, {'xsi:type' => 'xsd:uriReference', %$attr}, $value];
}

Step 3: Register the New Data Type

To register the new data type, simply add the type to the "SOAP::Serializer::typelookup" hash using the type name as the key, and an array containing the precedence value, the test subroutine, and the encoding subroutine.

$s->typelookup->{uriReference}
    = [11, \&uriReferenceTest, 'as_uriReference'];

Tip: As a short hand, you could just as easily use an anonymous test subroutine when registering the new datatype in place of the "urlReferenceTest" subroutine above. For example:

$s->typelookup->{uriReference}
    = [11, sub { $_[0] =~ m!^http://! }, 'as_uriReference'];

Once complete, "SOAP::Serializer" will be able to serialize the following "SOAP::Data" object into XML:

$elem = SOAP::Data->name("someUri" => 'http://yahoo.com')->type('uriReference');

"SOAP::Serializer" will also be able to automatically determine and serialize the following untyped "SOAP::Data" object into XML:

$elem = SOAP::Data->name("someUri" => 'http://yahoo.com');
