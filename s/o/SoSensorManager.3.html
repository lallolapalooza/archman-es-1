Descripción detallada

La clase SoSensorManager maneja las colas de sensores.

Hay dos tipos principales de sensores en Coin, sensores de "retraso" y sensores de "temporizador":

•
Los sensores de retraso se activan cuando la aplicación está inactiva. Además, para evitar la inacción en aplicaciones que están continuamente ocupadas, la cola de sensores de retraso también tiene un tiempo de espera que, al alcanzarse, vaciará la cola de todos modos.
•
Los sensores de temporizador se configuran para activarse en momentos específicos y absolutos.

Cada uno de estos dos tipos tiene su propia cola, que es manejada por SoSensorManager. Las colas se mantienen en orden ordenado por SoSensorManager, ya sea según el tiempo de activación (para sensores de temporizador) o por prioridad (para sensores de retraso).

SoSensorManager proporciona métodos para gestionar estas colas, mediante la inserción y eliminación de sensores, y el procesamiento (vaciado) de las colas.

El mecanismo de sensores es crucial en Coin para una serie de características importantes, especialmente la programación automática de redibujado ante cambios, y para hacer posible la configuración de animaciones en el grafo de escena que no necesitan ninguna contabilidad adicional por parte del código de la aplicación.

SoSensorManager generalmente debe considerarse como una clase interna en la API de Coin. Solo es interesante para los programadores de aplicaciones al implementar nuevas bibliotecas específicas del sistema de ventanas (como las bibliotecas SoQt, SoXt, SoGtk, SoWin o Sc21 de Kongsberg Oil & Gas Technologies) o wrappers. Entonces hay que configurar código para vaciar las colas en los intervalos correctos. Para obtener información detallada sobre cómo hacerlo, le aconsejamos que consulte la implementación de dichos mecanismos en las bibliotecas So* que proporciona SIM.

Tenga en cuenta que antes de Coin 2.3.1, los sensores con la misma prioridad (o el mismo tiempo de activación para los sensores SoTimerQueue) se procesaban LIFO. Esto ha cambiado ahora a FIFO para ser compatible con SGI Inventor.

void SoSensorManager::processDelayQueue (SbBool isidle)

Activa todas las entradas de la cola de retraso en orden de prioridad.

El indicador isidle indica si el procesamiento ocurre porque la aplicación está inactiva o porque se alcanzó el tiempo de espera de la cola de retraso.

Un sensor de cola de retraso con prioridad > 0 solo puede activarse una vez durante una llamada a esta función. Si un sensor de retraso se reprograma durante processDelayQueue(), no se procesa hasta la próxima vez que se llama a esta función. Esto se hace para evitar un bucle infinito mientras se procesan los sensores.

Un sensor de cola de retraso con prioridad 0 se denomina sensor inmediato.

Detailed Description

The sensor manager is responsible for managing sensors. Sensors are used to trigger actions when certain events occur. The sensor manager maintains three queues of sensors: immediate sensors, delay sensors, and timer sensors.

Immediate sensors have priority 0 and are processed first. Delay sensors have a priority greater than 0. Timer sensors are processed based on their timeout value. The sensor manager ensures that these sensors are processed in a timely manner.

There is only one instance of the sensor manager, which can be accessed using the static method SoSensorManager::getSensorManager().

void SoSensorManager::setDelaySensorTimeout (const SbTime & t)

Delay sensors are usually triggered only when the system is idle. But when there are continuous updates to the scene graph, there's a possibility that the delay queue will starve and sensors are never triggered. To make sure this won't happen, this is a timeout value for the delay queue. When this timeout has been reached, the sensors in the delay queue gets processed before other sensors and events. This method will let the user set this timeout value.

The default value is 1/12 of a second.

Specifying a zero time will disable the timeout, opening for potential delay queue starvation.

int SoSensorManager::doSelect (int nfds, void * readfds, void * writefds, void * exceptfds, struct timeval * usertimeout)

NOTE: THIS METHOD IS OBSOLETED. DON'T USE IT.

This is a wrapper around the standard select(2) call, which will make sure the sensor queues are updated while waiting for any action to happen on the given file descriptors.

The void* arguments must be valid pointers to fd_set structures. We've changed this from the original SGI Inventor API to avoid messing up the header file with system specific includes.
