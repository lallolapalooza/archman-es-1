Descripción Detallada

La clase SoPath es una clase contenedora para descripciones de rutas de recorrido.

Los objetos SoPath contienen una lista de punteros a SoNode y una lista de índices de hijos. Los índices son necesarios para desambiguar situaciones donde un nodo utiliza el mismo nodo como hijo múltiples veces.

Las rutas pueden exportarse e importarse desde/hacia archivos, al igual que otros objetos derivados de SoBase. Lea la documentación del método write() para ver cuál es el formato del archivo.

Es importante conocer la diferencia entre esta clase y SoFullPath al trabajar con rutas. SoPath::getTail() retornará el primer nodo en la ruta que no herede de SoGroup, y getLength() retorna el número de nodos hasta este nodo.

Si necesita la longitud real de la ruta, o el nodo de cola real, debe convertir la ruta a SoFullPath.

Documentación de funciones miembro

Operador de asignación, copia el camino rhs a este. No forma parte de la API original de Open Inventor.

SoType SoPath::getTypeId (void ) const [virtual]

Devuelve la identificación del tipo de un objeto derivado de una clase que hereda de SoBase. Se utiliza para la verificación de tipos en tiempo de ejecución y el casting descendente. Ejemplo de uso:

void foo(SoNode * node)
{
  if (node->getTypeId() == SoFile::getClassTypeId()) {
    SoFile * filenode = (SoFile *)node;  // casteo descendente seguro, se conoce el tipo
  }
}

Para desarrolladores de aplicaciones que deseen extender la biblioteca con nuevos nodos, motores, kits de nodos, draggers u otros: deben sobrescribir este método en todas las subclases. Esto generalmente se hace como parte de la configuración del sistema de tipos completo para clases extendidas, lo que se realiza comúnmente a través de los macros definidos, por ejemplo, en Inventor/nodes/SoSubNode.h (SO_NODE_INIT_CLASS y SO_NODE_CONSTRUCTOR para clases de nodo), Inventor/engines/SoSubEngine.h (para clases de motor) y así sucesivamente.

Para más información sobre cómo escribir extensiones de Coin, consulte la documentación de las superclases de nivel superior para cada grupo de clases.

Detailed Description

A path is a sequence of indices specifying a node within the scene graph.

For example, if a scene graph is:

Separator {
  Transform { }
  Cube { }
}

Then the path to the Cube node is specified by the index sequence { 1 }.

If the scene graph is:

Separator {
  Transform { }
  Group {
    Sphere { }
    Cube { }
  }
}

Then the path to the Cube node is specified by the index sequence { 1, 1 }.

Paths are used to identify nodes and subgraphs. They are often used in conjunction with SoNode::getChild() and related methods.

Paths are also used for navigating the scene graph during actions. For example, SoSearchAction will return paths to all nodes matching a given criteria. Path can be used to find children, parent, and to navigate up and down the scene graph.

Note that paths are immutable by default. If you need to modify a path, you should make a copy first.

int SoPath::getDepth () const

Returns the number of indices in the path. This is equivalent to the depth of the node in the scene graph.

SoNode * SoPath::getNode (int index) const

Returns the node at the given index in the path. The index is zero-based. Returns NULL if the index is out of bounds.

Returns the index of the last node in the path. This is equivalent to the depth minus one.

SbBool SoPath::isDeleting () const

Returns TRUE if the path is currently being deleted. This can happen during scene graph traversal when nodes are removed.

void SoPath::removeIndex (SoNode *const parent, const int oldindex)

This method is called when a node in the path chain has a child removed, to update the index of its child.

oldindex was the index of the removed child. If oldindex is lower than or equal to the index value of the child node stored in the path, the path is updated accordingly.

void SoPath::replaceIndex (SoNode *const parent, const int index, SoNode *const newchild)

This method is called when a node newchild replaces a node in the path. index is the position of the child which has been replaced.

SbBool SoPath::isRelevantNotification (SoNotList *const l) const

Return TRUE if the notification chain l will affect the path. l will affect the path either if the notification is in the path (the notification started on a field in a node in the path), or off the path (the notification started in a non-separator node that is left of the path's node).

void SoPath::write (SoWriteAction * action) [virtual]

This method is used to write the contents of an SoPath.

A path is written as:

Path {
  HEAD-NODE-OF-SUBGRAPH
  NUMBER-OF-INDICES
  INDEX0
  INDEX1
  ...
}

[The rest of the documentation for this method only explains the reason behind a mismatch in behavior between the original Open Inventor and Coin. Don't read it if you're not taking a particular interest. (Short version: we do SoPath export in a somewhat more inefficient way to avoid the potential for bugs).]

Note that unlike Open Inventor, we write the complete subgraph below the head node. Only writing the parts of the subgraph affecting the state for nodes within the path is error prone if a subgraph is written out as part of path before it is written out "properly". Consider writing a scene graph which looks like this (in memory):

DEF top_sep Separator {
  Cone { }
  DEF a_sphere Sphere { }
  Cube { }
}
DEF path_switch PathSwitch {
  path Path {
    ...path from "top_sep" to "a_sphere"...
  }
}

..if we now do:

SoSeparator * root = new SoSeparator;
root->addChild([ptr to path_switch]);
root->addChild([ptr to top_sep]);
SoWriteAction wa;
wa.apply(root);

..we would get the scene graph exported like this:

Separator {
  DEF path_switch PathSwitch {
    path Path {
      DEF top_sep Separator {
        DEF a_sphere Sphere {
        }
      }
      1
      0
    }
  }
  USE top_sep
}

..and as you can see, both the Cone and the Cube nodes have vanished, as they were not important for the part per se, and not written as part of it.

This is why we do full subgraph export for head nodes in paths.

void SoPath::auditPath (const SbBool flag) [protected]

Set whether or not to audit the nodes in the path to detect changes.
