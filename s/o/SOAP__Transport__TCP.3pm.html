SOAP::Transport::TCP - Soporte de transporte TCP para SOAP::Lite

SOAP::Transport::TCP

Las clases proporcionadas por este módulo implementan métodos de comunicación TCP/IP directos tanto para clientes como para servidores.

Las conexiones no utilizan HTTP ni ningún otro protocolo de alto nivel. Estas clases se seleccionan cuando el objeto cliente o servidor que se está creando utiliza una URI de punto final que comienza con tcp://. Tanto las clases cliente como servidor admiten el uso de Secure Socket Layer si está disponible. Si alguno de los parámetros para un método `new` de cualquiera de las clases comienza con `SSL_` (como `SSL_server` en lugar de `Server`), la clase intenta cargar el paquete IO::Socket::SSL y usarlo para crear objetos socket.

Ambas clases siguientes capturan métodos que están destinados a los objetos socket y los pasan, lo que permite llamadas como $client->accept( ) sin incluir la clase socket en el árbol de herencia.

SOAP::Transport::TCP::Client

Hereda de: SOAP::Client.

La clase cliente TCP define solo dos métodos relevantes además de `new` y `send_receive`. Estos métodos son:

SSL(valor booleano opcional new)
if ($client->SSL) # Ejecutar solo si está en modo SSL

Refleja el atributo que denota si el objeto cliente está usando sockets SSL para comunicaciones.

io_socket_class
($client->io_socket_class)->new(%options);

Devuelve el nombre de la clase a utilizar al crear objetos socket para uso interno en las comunicaciones. Tal como está implementado, devuelve uno de `IO::Socket::INET` o `IO::Socket::SSL`, dependiendo del valor de retorno del método `SSL` anterior.

Si una aplicación crea una subclase que hereda de esta clase cliente, cualquiera de los métodos es un objetivo probable para la sobreescritura.

El método `new` se comporta de manera idéntica a la mayoría de las otras clases, excepto que detecta la presencia de valores dirigidos a SSL en la lista de parámetros y establece el método `SSL` apropiadamente si están presentes.

El método `send_receive` crea un socket de la clase apropiada y se conecta al punto final configurado. Luego, establece el socket en E/S no bloqueante, envía el mensaje, cierra el extremo cliente de la conexión (evitando escrituras adicionales) y lee la respuesta del servidor. El objeto socket se descarta después de que la respuesta y los códigos de estado apropiados se establecen en el objeto cliente.

SOAP::Transport::TCP::Server

Hereda de: SOAP::Server.

La clase servidor también define los mismos dos métodos adicionales que en la clase cliente:

SSL(valor booleano opcional new)
if ($client->SSL) # Ejecutar solo si está en modo SSL

Refleja el atributo que denota si el objeto cliente está usando sockets SSL para comunicaciones.

io_socket_class
($client->io_socket_class)->new(%options);

Devuelve el nombre de la clase a utilizar al crear objetos socket para uso interno en las comunicaciones. Tal como está implementado, devuelve uno de `IO::Socket::INET` o `IO::Socket::SSL`, dependiendo del valor de retorno del método `SSL` anterior. El método `new` también gestiona la selección automática de SSL de la misma manera que lo hace la clase cliente.

El método `handle` en esta implementación de servidor no está diseñado para ser llamado una vez con cada nueva solicitud. Más bien, se llama sin argumentos, momento en el cual entra en un bucle infinito de espera de una conexión, lectura de la solicitud, enrutamiento de la solicitud y envío de la respuesta serializada. Esto continúa hasta que el propio proceso se interrumpe por una señal no capturada o un medio similar.
