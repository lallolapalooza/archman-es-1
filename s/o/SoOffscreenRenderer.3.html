Descripción Detallada

La clase SoOffscreenRenderer se utiliza para renderizar escenas a búferes fuera de pantalla.

Si desea renderizar a un búfer de memoria en lugar de un contexto OpenGL en pantalla, utilice esta clase. Renderizar a un búfer de memoria puede utilizarse para generar mapas de texturas sobre la marcha, o para guardar instantáneas de la escena en archivos de disco (como mapas de bits de píxeles o como archivos PostScript para enviarlos a una impresora compatible con PostScript).

Aquí hay un ejemplo de uso muy simple, solo el código directamente relacionado con SoOffscreenRenderer:

SoOffscreenRenderer myRenderer(vpregion);
SoNode * root = myViewer->getSceneManager()->getSceneGraph();
SbBool ok = myRenderer.render(root);
unsigned char * imgbuffer = myRenderer.getBuffer();
// [luego usar el búfer de imagen en una textura, o escribirlo en un archivo, o lo que sea]

Y aquí un ejemplo completo e independiente con una cámara en movimiento guardando varios fotogramas en disco como JPGs:

#include <Inventor/SoDB.h>
#include <Inventor/SoOffscreenRenderer.h>
#include <Inventor/engines/SoInterpolateVec3f.h>
#include <Inventor/nodes/SoCube.h>
#include <Inventor/nodes/SoDirectionalLight.h>
#include <Inventor/nodes/SoPerspectiveCamera.h>
#include <Inventor/nodes/SoSeparator.h>
#include <iostream>
int main()
{
  // Inicializar Coin
  SoDB::init();
  // El nodo raíz
  SoSeparator * root = new SoSeparator;
  root->ref();
  // Es obligatorio tener al menos una luz para el renderizador fuera de pantalla
  SoDirectionalLight * light = new SoDirectionalLight;
  root->addChild(light);
  // Es obligatorio tener al menos una cámara para el renderizador fuera de pantalla
  SoPerspectiveCamera * camera = new SoPerspectiveCamera;
  SbRotation cameraRotation = SbRotation::identity();
  cameraRotation *= SbRotation(SbVec3f(1, 0, 0), -0.4f);
  cameraRotation *= SbRotation(SbVec3f(0, 1, 0), 0.4f);
  camera->orientation = cameraRotation;
  root->addChild(camera);
  // Algo para mostrar... Una caja
  SoCube * cube = new SoCube;
  root->addChild(cube);
  // Configurar las dos posiciones de cámara entre las que queremos mover la cámara
  SoInterpolateVec3f * interpolate = new SoInterpolateVec3f;
  interpolate->input0 = SbVec3f(2, 2, 9);
  interpolate->input1 = SbVec3f(2, 2, 5);
  camera->position.connectFrom(&interpolate->output);
  // Configurar el renderizador fuera de pantalla
  SbViewportRegion vpRegion(400, 300);
  SoOffscreenRenderer offscreenRenderer(vpRegion);
  // Cuántos fotogramas renderizar para el video
  int frames = 5;
  std::cout << "Escribiendo " << frames << " fotogramas..." << std::endl;
  for (int i = 0; i < frames; i++) {
    // Actualizar la posición de la cámara
    interpolate->alpha = float(i) / (frames - 1);
    // Renderizar la escena
    SbBool ok = offscreenRenderer.render(root);
    // Guardar la imagen en disco
    SbString filename = SbString("coinvideo-") + (i + 1) + ".jpg";
    if (ok) {
      offscreenRenderer.writeToFile(filename.getString(), "jpg");
    } else {
      std::cout << "Error al guardar imagen: " << filename.getString() << std::endl;
      break;
    }
  }
  std::cout << "¡Hecho!" << std::endl;
  root->unref();
  return 0;
}

Tenga en cuenta que SoOffscreenRenderer potencialmente asigna una cantidad considerable de recursos, tanto de OpenGL como de recursos generales del sistema, para cada instancia. Por lo tanto, es muy recomendable intentar reutilizar instancias de SoOffscreenRenderer, en lugar de construir y destruir una nueva instancia, por ejemplo, para cada fotograma al generar imágenes para video.

El renderizado fuera de pantalla se realiza internamente a través de un contexto fuera de pantalla GLX (es decir, OpenGL en X11), WGL (es decir, OpenGL en Win32), AGL (OpenGL estilo antiguo en Mac OS X) o CGL (estilo nuevo en Mac OS X).

Si el controlador de OpenGL soporta la extensión pbuffer, se detecta y se utiliza para proporcionar renderizado fuera de pantalla acelerado por hardware.

Los datos de píxeles se obtienen del búfer de OpenGL con glReadPixels(), con los argumentos de formato y tipo establecidos en GL_RGBA y GL_UNSIGNED_BYTE, respectivamente. Esto significa que la resolución máxima es de 32 bits, 8 bits para cada uno de los componentes R/G/B/A.

Un uso particular de SoOffscreenRenderer es hacer que renderice fotogramas para ser utilizados en la construcción de películas. La técnica general para hacer esto es iterar sobre las siguientes acciones:

  • mover la cámara a la posición correcta para el fotograma
  • actualizar el campo global realTime (ver explicación a continuación)
  • invocar el SoOffscreenRenderer
  • volcar la escena renderizada al archivo

.. luego usa alguna herramienta o biblioteca externa para construir el archivo de película, por ejemplo en formato MPEG, a partir del conjunto de archivos volcados al disco del proceso iterativo anterior.

El código iría algo así (estilo pseudocódigo). Primero, debemos evitar que la propia biblioteca Coin realice cualquier actualización automática del campo realTime, por lo que la inicialización de tu aplicación para Coin debería verse algo así:

[...] = SoQt::init([...]); // o SoWin::init() o SoDB::init()
// ..y luego inmediatamente:
// Controlamos el campo realTime nosotros mismos, para que las animaciones dentro de la escena
// sigan el "tiempo de película" y no el "tiempo de reloj de pared".
SoDB::enableRealTimeSensor(FALSE);
SoSceneManager::enableRealTimeUpdate(FALSE);
SoSFTime * realtime = SoDB::getGlobalField("realTime");
realtime->setValue(0.0);

Tenga en cuenta que es importante que el campo realTime se inicialice con tu tiempo de inicio *antes* de configurar cualquier motor u otra entidad en el sistema que utilice el campo realTime.

Luego, para el bucle de renderizado, algo como:

for (int i=0; i < NRFRAMES; i++) {
  // [...reposicionar la cámara aquí, si es necesario...]
  // renderizar
  offscreenrend->render(root);
  // volcar a archivo
  SbString framefile;
  framefile.sprintf("frame%06d.rgb", i);
  offscreenrend->writeToRGB(framefile.getString());
  // avanzar el "tiempo actual" por el valor de fotogramas por segundo, que
  // es 24 fps i

Detailed Description

A renderer that draws scenes into off-screen memory buffers. This class is useful if you want to render a scene and save the output to a file, or process the pixel data before displaying it.

The renderer can be configured to render to an off-screen buffer that is associated with an OpenGL texture map. This is done by passing an instance of SoGLRenderToTextureAction to the constructor.

If SoGLRenderToTextureAction is not used, the renderer will create its own off-screen buffer. This buffer can be retrieved using getSoImage().

By default, the renderer will try to use hardware acceleration (e.g. pbuffers or FBOs) to render the scene. If this fails, it will fall back to software rendering.

The writeToFile() method can be used to save the rendered image to a file. The supported file formats depend on the installed image writing modules.

Note that writeToFile() does not automatically append the file extension to the filename. You must specify the full filename as the first argument.

The class also provides methods to control the use of pbuffers (setPbufferEnable() and getPbufferEnable()). However, these are mainly for API compatibility with other toolkits, as Coin manages pbuffer usage internally and automatically falls back to software rendering if needed.

Control whether or not SoOffscreenRenderer can use the "pbuffer" feature of OpenGL to render the scenes with hardware acceleration.

This is a dummy function in Coin, provided for API compatibility reasons, as it is really superfluous:

Coin has internal heuristics to figure out if pbuffers are available and can be allocated and used for the SoOffscreenRenderer. The SoOffscreenRenderer will also automatically fall back on "soft" buffers if it cannot use pbuffers (or any other hardware accelerated rendering technique).
