Descripción Detallada

La clase SoTransform es el tipo de nodo de transformación "todo terreno".

Al igual que SoMatrixTransform, los nodos de este tipo brindan al programador de aplicaciones la máxima flexibilidad al especificar transformaciones de geometría en un grafo de escena. Si desea establecer y mantener los diversos componentes de la matriz de transformación en entidades separadas, este tipo de nodo es preferible, sin embargo.

El orden de las operaciones es: primero se realiza el escalado, luego la rotación y finalmente la traslación.

FORMATO DE ARCHIVO/VALORES PREDETERMINADOS:

Transform {
    translation 0 0 0
    rotation 0 0 1  0
    scaleFactor 1 1 1
    scaleOrientation 0 0 1  0
    center 0 0 0
}

Detailed Description

The SoTransform node defines a transformation in 3D space. This includes translation, rotation, scaling, and scaling orientation.

The transformation is defined by the following sequence of operations:

  1. Rotate by scaleOrientation.
  2. Scale by scaleFactor.
  3. Translate by translation.

All other transformations are implicitly handled by setMatrix() which sets the transformation to an arbitrary matrix.

All transformations are performed relative to the center point.

If the scaleOrientation field is not the identity rotation, then the center field is used for rotating the object before scaling. Then the translation is applied.

The default value for all fields is the identity transformation (zero translation, zero rotation, unity scale).

SoSFRotation SoTransform::rotation

The rotation part of the transformation.

Note that there is one very common mistake that is easy to make when setting the value of a an SoSFRotation field, and that is to inadvertently use the wrong SbRotation constructor. This example should clarify the problem:

mytransformnode->rotation.setValue(0, 0, 1, 1.5707963f);

The programmer clearly tries to set a PI/2 rotation around the Z-axis, but this will fail, as the SbRotation constructor invoked above is the one that takes as arguments the 4 floats of a quaternion. What the programmer almost certainly wanted to do was to use the SbRotation constructor that takes a rotation vector and a rotation angle, which is invoked like this:

mytransformnode->rotation.setValue(SbVec3f(0, 0, 1), 1.5707963f);
