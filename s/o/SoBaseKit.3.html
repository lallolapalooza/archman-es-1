Descripción detallada

La clase SoBaseKit es la superclase de nivel superior para los nodekits.

Los nodekits son colecciones de nodos y otros nodekits (de ahora en adelante, los nodekits que forman parte de algún otro nodekit solo se referirán como nodos o partes, ver catálogos y partes), organizados de una manera conveniente para su uso. Un nodekit hereda de SoNode y, por lo tanto, puede insertarse en un grafo de escena como cualquier otro nodo.

La organización de los nodos y nodekits de algún nodekit se realiza a través de catálogos. El catálogo de un nodekit describe los nodos que pueden ser miembros del nodekit. Estos miembros se llaman partes. Por lo tanto, un nodekit tiene un catálogo que describe las partes que ofrece al usuario.

Cada parte del catálogo tiene algunos valores que dicen algo sobre la parte en sí y sobre el rol que desempeña en el grafo de escena. Esos valores son:

Nombre
El nombre de la parte.
Tipo
El tipo de nodo de la parte.
Tipo Predeterminado
Si el tipo de la parte es una superclase abstracta, este valor contendrá la subclase predeterminada utilizada por esta parte.
¿Se crea por defecto?
Contiene TRUE si la parte debe ser instanciada cuando se instancia el nodekit, de lo contrario, la parte se mantiene vacía hasta que se establezca por alguno de los medios aplicables.
Nombre del Padre
El nombre de la parte que es el padre de esta parte.
Hermana Derecha
El nombre de la parte que está inmediatamente a la derecha de esta parte en el grafo de escena del nodekit.
¿Es una lista?
Contiene TRUE si la parte es una lista, de lo contrario es FALSE. Ver SoNodeKitListPart para más información sobre listas de nodekits.
Tipo de Contenedor de Lista
El tipo de nodo de grupo utilizado para contener los elementos si la parte es una lista.
Tipo de Elemento de Lista
Los tipos de nodos que se permiten contener en esta parte si la parte es una lista.
¿Es pública?
Contiene TRUE si la parte debe ser públicamente accesible, de lo contrario contiene FALSE.

Los nodekits utilizan instanciación perezosa al crear sus partes. Esto significa que los nodos que componen las partes del nodekit solo se crean cuando son necesarios. Si "Se crea por defecto?" es TRUE, entonces la parte se crea cuando se instancia el propio nodekit. Si no, las partes se crean cuando se solicitan a través de SoBaseKit::getPart() o la macro SO_GET_PART(), o se crean con SoBaseKit::set(). Además, si una parte se establece con SoBaseKit::setPart() o la macro SO_SET_PART(), las partes previamente no creadas por encima de la parte establecida en la jerarquía, se crean automáticamente.

Las ventajas de utilizar nodekits para representar un grafo de escena son muchas.

  • Dado que un nodekit recopila nodos en una sola unidad, se convierte en una capa de abstracción adicional para el programador de aplicaciones. Dicha capa puede representar un modelo de un ser humano como una unidad donde las subunidades como brazos, piernas, texturas, etc. están contenidas dentro. Por lo tanto, podemos instanciar un modelo de un humano creando una instancia del nodekit, en lugar de h crear una cantidad potencialmente grande de nodos necesarios para dicho modelo.
  • Una parte del kit de nodos no tiene una configuración específica. Una parte de forma puede, por ejemplo, ser intercambiada con cualquier otra forma, ya que son del mismo tipo. Si el kit de nodos de un humano tiene una parte llamada "cabeza" que es del tipo SoShape, puede que por defecto sea una esfera. Pero si el programador piensa que un cubo encaja mejor, se puede configurar la parte "cabeza" a un cubo en su lugar, o tal vez un conjunto de formas que represente un modelo complejo de cabeza.
  • Los kits de nodos pueden tener catálogos tan simples o complejos como sea necesario. Los nodos incluidos en el kit de nodos pueden, si es necesario, representar todo el rango de características de Inventor. Una parte puede ser tan fácilmente de un tipo de kit de nodos, haciendo posible crear jerarquías de kits de nodos. Teniendo un kit de nodos de un humano, podría ser factible tener sub-kits de nodos que describan las diferentes partes del cuerpo.
  • Los kits de nodos son una forma eficiente de crear gráficos de escena. Si alguna parte de ellos no es necesaria en el momento de la instanciación del kit de nodos, no se crean. Por lo tanto, las partes solo se crean cuando son necesarias, ya sea por la aplicación u otra parte.
  • El código de la aplicación se vuelve más pequeño y fácil de leer, ya que los kits de nodos proporcionan rutinas sencillas para crear y configurar partes.
  • Se pueden crear nuevos kits de nodos mediante subclasificación para obtener configuraciones sencillas de gráficos de escena que se ajusten mejor a la aplicación.

El uso de un kit de nodos es sencillo. A continuación, se presenta un ejemplo de código que muestra un uso simple de SoShapeKit.

#include <Inventor/Qt/SoQt.h>
#include <Inventor/Qt/viewers/SoQtExaminerViewer.h>
#include <Inventor/nodekits/SoShapeKit.h>
#include <Inventor/nodes/SoSeparator.h>
#include <Inventor/nodes/SoCube.h>
int
main(int argc, char ** argv)
{
  QWidget * window = SoQt::init(argv[0]);
  SoQtExaminerViewer * viewer = new SoQtExaminerViewer(window);
  // Instanciando un kit de formas, creando por defecto una esfera simple.
  SoShapeKit * shapekit = new SoShapeKit;
  // Intercambiando la esfera por un cubo.
  shapekit->setPart("shape", new SoCube);
  // Configurando el cubo para que se renderice en color rojo. El kit de formas
  // tiene un SoAppearanceKit como una de sus partes. La parte "material"
  // utilizada para configurar el color de la forma, realmente pertenece al
  // kit de apariencia. Si se usa SoShapeKit::set(), comprobará si alguno de
  // sus sub-kits tiene una parte con el nombre dado, y delegará la configuración
  // al kit correcto.
  shapekit->set("material", "diffuseColor 1 0 0");
  SoSeparator * newroot = new SoSeparator;
  newroot->ref();
  newroot->addChild(shapekit);
  viewer->setSceneGraph(newroot);
  viewer->show();
  SoQt::show(window);
  SoQt::mainLoop();
  delete viewer;
  newroot->unref();
  return 0;
}

A continuación, se presenta un ejemplo completo de una extensión de kit de nodos. El kit de nodos es un kit que escala automáticamente una forma para que tenga el mismo tamaño en píxeles de pantalla, sin importar la distancia a la que se encuentre de la cámara. Esto es útil para gráficos de marcadores. La forma por defecto es un cubo, pero el programador puede configurarla a cualquier forma o subgrafo de escena.

// Copyright (C) Kongsberg Oil & Gas Technologies. All rights reserved.
//  La clase ShapeScale se utiliza para escalar una forma basándose en
//  su tamaño proyectado.
//
//  Este nodekit se puede insertar en su gráfico de escena para añadir,
//  por ejemplo, marcadores 3D que tendrán un tamaño proyectado constante.
//
//  La forma del marcador se almacena en la parte "shape". Se puede utilizar
//  cualquier tipo de nodo, incluso nodos de grupo con varias formas, pero
//  la forma del marcador debe ser aproximadamente de tamaño unitario, y
//  con una posición central en (0, 0, 0).
//  SoSFFloat ShapeScale::active
//  Activa o desactiva el escalado. Valor por defecto es TRUE.
//  SoSFFloat ShapeScale::projectedSize
//  El tamaño proyectado solicitado de la forma. Valor por defecto es 5.0.
#include "ShapeScale.h"
#include <Inventor/actions/SoGLRenderAction.h>
#include <Inventor/nodes/SoShape.h>
#include <Inventor/nodes/SoScale.h>
#include <Inventor/nodes/SoCube.h>
#include <Inventor/nodes/SoSeparator.h>
#include <Inventor/elements/SoViewVolumeElement.h>
#include <Inventor/elements/SoViewportRegionElement.h>
#include <Inventor/elements/SoModelMatrixElement.h>
SO_KIT_SOURCE(ShapeScale);
//  Constructor.
ShapeScale::ShapeScale(void)
{
  SO_KIT_CONSTRUCTOR(ShapeScale);
  SO_KIT_ADD_FIELD(active, (TRUE));
  SO_KIT_ADD_FIELD(projectedSize, (5.0f));
  SO_KIT_ADD_CATALOG_ENTRY(topSeparator, SoSeparator, FALSE, this, \x0, FALSE);
  SO_KIT_ADD_CATALOG_ABSTRACT_ENTRY(shape, SoNode, SoCube, TRUE, topSeparator, \x0, TRUE);
  SO_KIT_ADD_CATALOG_ENTRY(scale, SoScale, FALSE, topSeparator, shape, FALSE);
  SO_KIT_INIT_INSTANCE();
}
// Destructor.
ShapeScale::~ShapeScale()
{
}
// Inicializa esta clase. Llamar antes de usarla.
void
ShapeScale::initClass(void)
{
  SO_KIT_INIT_CLASS(ShapeScale, SoBaseKit, "BaseKit");
}
static void
update_scale(SoScale * scale, const SbVec3f & v)
{
  // Solo escribir en el campo cuando el escalado ha cambiado.
  if (scale->scaleFactor.getValue() != v) {
    scale->scaleFactor = v;
  }
}
// Sobreescrito para (re)inicializar el escalado antes de renderizar el marcador.
void
ShapeScale::GLRender(SoGLRenderAction * action)
{
  SoState * state = action->getState();
  SoScale * scale = (SoScale*) this->getAnyPart(SbName("scale"), TRUE);
  if (!this->active.getValue()) {
    update_scale(scale, SbVec3f(1.0f, 1.0f, 1.0f));
  }
  else {
    const SbViewportRegion & vp = SoViewportRegionElement::get(state);
    const SbViewVolume & vv = SoViewVolumeElement::get(state);
    SbVec3f center(0.0f, 0.0f, 0.0f);
    float nsize = this->projectedSize.getValue() / float(vp.getViewportSizePixels()[1]);
    SoModelMatrixElement::get(state).multVecMatrix(center, center); // transformar a WCS
    float scalefactor = vv.getWorldToScreenScale(center, nsize);
    update_scale(scale, SbVec3f(scalefactor, scalefactor, scalefactor));
  }
  inherited::GLRender(action);
}

// Devuelve un valor aleatorio entre 0.0f y 1.0f.
static float
normalized_rand(void)
{
  return float(rand())/float(RAND_MAX);
}
static SoSeparator *
construct_new_marker(const SbVec3f & v)
{
  SoSeparator * markerroot = new SoSeparator;
  SoTranslation * t = new SoTranslation;
  t->translation = v;
  markerroot->addChild(t);
  ShapeScale * kit = new ShapeScale;
  kit->active = TRUE;
  kit->projectedSize = 5.0f;
  // crear el marcador
  SoSeparator * markersep = new SoSeparator;
  SoBaseColor * mat = new SoBaseColor;
  mat->rgb.setValue(normalized_rand(), normalized_rand(), normalized_rand());
  markersep->addChild(mat);
  // la forma del marcador debe ser de tamaño unitario, con centro en (0.0f, 0.0f, 0.0f)
  SoCube * cube = new SoCube;
  cube->width = 1.0f;
  cube->height = 1.0f;
  cube->depth = 1.0f;
  markersep->addChild(cube);
  kit->setPart("shape", markersep);
  markerroot->addChild(kit);
  return markerroot;

SoNode * SoBaseKit::getAnyPart (const SbName & partname, SbBool makeifneeded, SbBool leafcheck = FALSE, SbBool publiccheck = FALSE) [protected], [virtual]

Devuelve la parte del catálogo del partname dado.

Si la parte partname no está en el catálogo del nodekit, devuelve NULL.

Si la parte está especificada en el catálogo, pero aún no se ha creado, la función creará la parte (si makeifneeded es TRUE) o simplemente devolverá NULL (si makeifneeded es FALSE).

Si leafcheck es TRUE, solo se devolverá un puntero a la parte si es una hoja en el catálogo (de lo contrario, se devolverá NULL).

Si publiccheck es TRUE, solo se devolverá un puntero a la parte si es una parte pública del catálogo (de lo contrario, se devolverá NULL).

El argumento de entrada partname debe proporcionarse como una "ruta" de nombres de partes del catálogo hasta la parte hoja deseada. La sintaxis para especificar "rutas" de partname es la siguiente (dada en Forma Backus-Naur (BNF)):

BNF:
partname = singlename | compoundname
compoundname = singlename | compoundname.singlename
singlename = singlepartname | singlelistelementname
singlelistelementname = singlelistname[idx]
singlepartname es el nombre de una parte ("ordinaria", nodekit o lista)
singlelistname es el nombre de una parte que es una lista
idx es un valor entero

es una parte no hoja y es de tipo SoGroup y todos los campos tienen sus valores predeterminados
