Detailed Description

A path switch is a switch node which uses the path provided in its path field to decide which of its children is to be activated. The path can be set up to match any portion of the scenegraph that is currently being traversed.

The path field is an SoSFPath. It is initialized to an empty path, which will match any path. If you set it to a non-empty path, only scenegraphs that contain the specified path will have their children traversed.

A path is specified as a sequence of node indices relative to the root of the scenegraph. For example, the path (3, 1, 4) means to traverse to the 3rd child of the root node, then to the 1st child of that node, and finally to the 4th child of that node. The switch node itself will not be part of the path.

If the current path of traversal matches the specified path, then the switch node will delegate the traversal to its children. Otherwise, it will not traverse any children.

Note that a path switch is mainly useful when traversing parts of the scenegraph, for example, when using the SoGetBoundingBoxAction or when rendering.

The path field can be set to NULL. This will cause the switch node to never activate its children.

The path field can be set to an empty path. This will cause the switch node to always activate its children (unless overridden by another switch node further up in the scenegraph).

The path needs not be a full path back to the root node. It may be any portion of the currently traversed path.

Member Function Documentation

virtual void SoPathSwitch::getBoundingBox (SoAction * action, SbBox3f & box, SbVec3f & center)

Action method for SoGetBoundingBoxAction.

This method is overridden to check if the action's current path matches the switch's path field. If it matches, the method proceeds as normal and traverses the children. Otherwise, the children are skipped.

Note that this method is also used by SoCallbackAction and other traversal actions. For these, it is not relevant to check the path, so the original implementation from SoSwitch is used.

Member Data Documentation

SoSFPath SoPathSwitch::path

The path that must match the current action path. A NULL path will never match. An empty path will always match. The path should go up to (not including) the SoPathSwitch node, but need not go all the way back to the root node.
