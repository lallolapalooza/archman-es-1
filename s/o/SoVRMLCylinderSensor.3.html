Descripción Detallada

La clase SoVRMLCylinderSensor mapea el movimiento del puntero en rotaciones alrededor del eje Y.

La documentación detallada de la clase se toma textualmente del estándar VRML97 (ISO/IEC 14772-1:1997). Tiene derechos de autor del Consorcio Web3D, y se usa con permiso del Consorcio:

CylinderSensor {
  exposedField SFBool     autoOffset TRUE
  exposedField SFFloat    diskAngle  0.262       # (0,/2)
  exposedField SFBool     enabled    TRUE
  exposedField SFFloat    maxAngle   -1          # [-2,2]
  exposedField SFFloat    minAngle   0           # [-2,2]
  exposedField SFFloat    offset     0           # (-inf, inf)
  eventOut     SFBool     isActive
  eventOut     SFRotation rotation_changed
  eventOut     SFVec3f    trackPoint_changed
}

El nodo CylinderSensor mapea el movimiento del puntero (por ejemplo, un ratón o un varita) en una rotación sobre un cilindro invisible que está alineado con el eje Y del sistema de coordenadas local. El CylinderSensor usa la geometría descendente del nodo padre para determinar si es susceptible de generar eventos.

El campo expuesto `enabled` habilita y deshabilita el nodo CylinderSensor. Si es TRUE, el sensor reacciona adecuadamente a los eventos del usuario. Si es FALSE, el sensor no rastrea la entrada del usuario ni envía eventos. Si `enabled` recibe un evento FALSE y `isActive` es TRUE, el sensor se deshabilita y desactiva, y emite un evento `isActive` FALSE. Si `enabled` recibe un evento TRUE, el sensor se habilita y está listo para la activación del usuario.

Un nodo CylinderSensor genera eventos cuando el dispositivo de puntero se activa mientras el puntero indica cualquier nodo de geometría descendente del grupo padre del sensor. Consulte 4.6.7.5, Activación y manipulación de sensores (http://www.web3d.org/documents/specifications/14772/V2.0/part1/concepts.html#4.6.7.5), para más detalles sobre cómo usar el dispositivo de puntero para activar el CylinderSensor.

Tras la activación del dispositivo de puntero mientras se indica la geometría del sensor, se envía un evento `isActive` TRUE. El ángulo agudo inicial entre el vector de dirección y el eje Y local del nodo CylinderSensor determina si se utilizan los lados del cilindro invisible o las tapas (discos) para la manipulación. Si el ángulo inicial es menor que `diskAngle`, la geometría se trata como un disco infinitamente grande situado en el plano Y=0 local y coincidente con el punto de intersección inicial. El movimiento de arrastre se mapea en una rotación alrededor del vector del eje +Y local del sistema de coordenadas del sensor. El vector perpendicular desde el punto de intersección inicial hasta el eje Y define una rotación cero alrededor del eje Y. Para cada posición subsiguiente del vector de dirección, se envía un evento `rotation_changed` que es igual a la suma de la rotación alrededor del vector del eje +Y (desde la intersección inicial hasta la nueva intersección) más el valor de `offset`. Los eventos `trackPoint_changed` reflejan la posición de arrastre sin ajustar en la superficie de este disco. Cuando el dispositivo de puntero se desactiva y `autoOffset` es TRUE, `offset` se establece al último valor de `rotation_changed` y se genera un evento `offset_changed`. Consulte 4.6.7.4, Sensores de arrastre (http://www.web3d.org/documents/specifications/14772/V2.0/part1/concepts.html#4.6.7.4), para una descripción más general de los campos `autoOffset` y `offset`.

Si el ángulo agudo inicial entre el vector de dirección y el eje Y local del nodo CylinderSensor es mayor o igual que `diskAngle`, entonces el sensor se comporta como un cilindro. La distancia más corta entre el punto de intersección (entre el vector de dirección y la geometría del sensor) y el eje Y del sistema de coordenadas local del grupo padre determina el radio de un cilindro invisible utilizado para mapear el movimiento del dispositivo de puntero y marca el valor de rotación cero. Para cada posición subsiguiente del vector de dirección, se envía un evento `rotation_changed` que es igual a la suma de la rotación diestra desde la intersección original alrededor del vector del eje +Y más el valor de `offset`. Los eventos `trackPoint_changed` reflejan la posición de arrastre sin ajustar en la superficie del cilindro invisible. Cuando el dispositivo de puntero se desactiva y `autoOffset` es TRUE, `offset` se establece al último ángulo de rotación y se genera un evento `offset_changed`. Hay más detalles disponibles en 4.6.7.4, Sensores de arrastre (http://www.web3d.org/documents/specifications/14772/V2.0/part1/concepts.html#4.6.7.4).

Cuando el sensor genera un evento `isActive` TRUE, captura todos los eventos de movimiento posteriores del puntero

Detailed Description

This sensor detects dragging motions on the surface of a virtual cylinder. It outputs events corresponding to the cylinder's axis and rotation. The primary use of this sensor is for implementing 3D rotation controls. It is part of the VRML 2.0 specification.

The cylinder sensor is activated when the user presses and holds down the pointing device button (e.g., mouse button) while the pointer is within the sensor's active region. While the button is held down, the sensor generates `isActive TRUE` events. Any motion of the pointing device during this time is considered a "drag." The sensor deactivates and generates an `isActive FALSE` event when the pointing device button is released. Other pointing-device sensors are inactive during the drag.

When the cylinder sensor is activated (`isActive TRUE`), it outputs `trackPoint_changed` and `rotation_changed` events. These events are interpreted based on the sensor's local coordinate system at the time of activation. `trackPoint_changed` represents the intersection points of the user's motion with an invisible cylinder or disk. `rotation_changed` represents the rotation around the cylinder's axis.

The behavior of the sensor can be influenced by the `diskAngle` field. If the initial motion angle is less than `diskAngle`, the sensor behaves like a disk, where motion is tracked on a flat plane. If the angle is greater than or equal to `diskAngle`, it behaves like a cylinder, tracking motion on the curved surface. The `minAngle` and `maxAngle` fields limit the range of rotation events. If `minAngle` is greater than `maxAngle`, rotation events are not clamped. The range for these fields is [-2, 2].

For 2D pointing devices (like a mouse), `isActive` typically reflects the state of the primary button (pressed = TRUE, released = FALSE). For 3D pointing devices (like a 3D mouse or wand), `isActive` indicates whether the pointer is within or in contact with the sensor's geometry.

The interpretation of dragging off the cylinder while activated can vary among browsers. Some might clamp all values to the cylinder's surface and continue rotation, while others might have different behaviors.

Further details on sensor behavior can be found in the VRML 2.0 specification, specifically in sections 4.6.7.3 (Pointing-device sensors), 4.6.7.4 (Drag sensors), and 4.6.7.5 (Activating and manipulating sensors).

While the pointing device is activated, trackPoint_changed and rotation_changed events are output and are interpreted from pointing device motion based on the sensor's local coordinate system at the time of activation. trackPoint_changed events represent the unclamped intersection points on the surface of the invisible cylinder or disk. If the initial angle results in cylinder rotation (as opposed to disk behaviour) and if the pointing device is dragged off the cylinder while activated, browsers may interpret this in a variety of ways (e.g., clamp all values to the cylinder and continuing to rotate as the point is dragged away from the cylinder). Each movement of the pointing device while isActive is TRUE generates trackPoint_changed and rotation_changed events. The minAngle and maxAngle fields clamp rotation_changed events to a range of values. If minAngle is greater than maxAngle, rotation_changed events are not clamped.

The minAngle and maxAngle fields are restricted to the range [-2, 2]. More information about this behaviour is described in 4.6.7.3, Pointing-device sensors, 4.6.7.4, Drag sensors (http://www.web3d.org/documents/specifications/14772/V2.0/part1/concepts.html#4.6.7.4), and 4.6.7.5 (http://www.web3d.org/documents/specifications/14772/V2.0/part1/concepts.html#4.6.7.5), Activating and manipulating sensors.
