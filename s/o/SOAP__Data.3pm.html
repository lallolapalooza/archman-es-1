SOAP::Data(3) Documentación de Contribución de Usuario de Perl SOAP::Data(3)

NOMBRE

SOAP::Data - esta clase proporciona los medios para manipular y controlar explícitamente todos los aspectos de la forma en que los datos de Perl se expresan como entidades de datos SOAP.

DESCRIPCIÓN

La clase SOAP::Data proporciona los medios para manipular y controlar explícitamente todos los aspectos de la forma en que los datos de Perl se expresan como entidades de datos SOAP. La mayoría de los métodos son accesores, que como los de SOAP::Lite están diseñados para devolver el valor actual si no se pasa uno nuevo, mientras que devuelven la referencia al objeto en caso contrario (permitiendo llamadas encadenadas a métodos). Tenga en cuenta que la mayoría de los accesores (excepto value) aceptan un nuevo valor para el objeto de datos como segundo argumento.

MÉTODOS

new(opcionales pares clave/valor)
$obj = SOAP::Data->new(name => 'idx', value => 5);

Este es el constructor de la clase. Casi todos los atributos relacionados con la clase se pueden pasar al constructor como pares clave/valor. Este método no se usa a menudo directamente porque los objetos SOAP::Data generalmente se crean para uso temporal. Está disponible para aquellas situaciones que lo requieren.

name(nuevo nombre, valor opcional)
$obj->name('index');

Obtiene o establece el valor actual del nombre, tal como lo considera el objeto. El nombre es lo que el serializador utilizará para la etiqueta al generar el XML para este objeto. Es lo que se convertirá en el accesor para el elemento de datos. Opcionalmente, el valor del objeto puede actualizarse si se pasa como segundo argumento.

type(nuevo tipo, valor opcional)
$obj->type('int');

Obtiene o establece el tipo asociado con el valor actual en el objeto. Esto es útil para aquellos casos en los que el objeto SOAP::Data se utiliza para especificar explícitamente el tipo de datos que de otro modo se interpretaría como un tipo diferente por completo (como percibir la cadena 123 como un entero, en lugar de ello). Permite establecer el valor del objeto, si se pasa como segundo argumento al método.

uri(nuevo uri, valor opcional)
$obj->uri('http://www.perl.com/SOAP');

Obtiene o establece la URI que se utilizará como espacio de nombres para la entidad XML resultante, si se desea una. Esto no establece la etiqueta para el espacio de nombres. Si no se proporciona mediante el método prefix, se genera automáticamente cuando es necesario. También permite establecer el valor del objeto, si se pasa como segundo argumento al método.

prefix(nuevo prefijo, valor opcional)
$obj->prefix('perl');

Proporciona el prefijo, o etiqueta, para usar al asociar el objeto de datos con un espacio de nombres específico. También permite establecer el valor del objeto, si se pasa como segundo argumento al método.

attr(referencia hash de atributos, valor opcional)
$obj->attr({ attr1 => 'value' });

Permite establecer atributos arbitrarios en el objeto de datos. Tenga en cuenta el requisito de que cualquier atributo no conocido nativamente por SOAP debe estar cualificado por espacio de nombres. También permite establecer el valor del objeto, si se pasa como segundo argumento al método.

value(nuevo valor)
$obj->value(10);

Recupera el valor actual encapsulado por el objeto, o lo establece explícitamente.

Los últimos cuatro métodos son atajos de conveniencia para los atributos que SOAP admite. Cada uno también permite la inclusión de un nuevo valor, como argumento opcional.

actor(nuevo actor, valor opcional)
$obj->actor($new_actor_name);

Obtiene o establece el valor del atributo actor; útil solo cuando el objeto genera una entidad para la cabecera del mensaje.

mustUnderstand(booleano, valor opcional)
$obj->mustUnderstand(0);

Manipula el atributo mustUnderstand, que indica al procesador SOAP si es necesario que comprenda la entidad en cuestión.

encodingStyle(nueva codificación URN, valor opcional)
$obj->encodingStyle($soap_11_encoding);

Este método es más probable que se utilice en lugares fuera de la creación de la cabecera. Establece encodingStyle, que especifica una codificación diferente de la que se utilizaría por defecto.

root(booleano, valor opcional)
$obj->root(1);

Cuando la aplicación debe especificar explícitamente qué elemento de datos se considera el elemento raíz para generar el modelo de objeto, este método proporciona el acceso al atributo root.

DETECCIÓN DE TIPOS

El serializador de SOAP::Lite detectará el tipo de cualquier escalar que se pase como valor del objeto SOAP::Data. Dado que Perl es de tipo flexible, el serializador solo puede detectar tipos basándose en un conjunto predefinido de expresiones regulares. Por lo tanto, la detección de tipos no siempre es precisa al 100%. En tal caso, puede que necesite establecer explícitamente el tipo del elemento que se está codificando. Por ejemplo, por defecto, el siguiente código se serializará como un entero:

$elem = SOAP::Data->name('idx')->value(5);

Sin embargo, si necesita serializar esto en un long, el siguiente código lo hará:

$elem = SOAP::Data->name('idx')->value(5)->type('long');

EJEMPLOS

TIPOS SIMPLES

El siguiente ejemplo producirá el mismo XML:

$elem1 = SOAP::Data->new(name => 'idx', value => 5);
$elem2 = SOAP::Data->name('idx' => 5);
$elem3 = SOAP::Data->name('idx')->value(5);

TIPOS COMPLEJOS

Una pregunta común es cómo crear elementos XML anidados usando SOAP::Lite. El siguiente ejemplo demuestra cómo:

SOAP::Data->name('foo' => \SOAP::Data->value(
    SOAP::Data->name('bar' => '123')));

El código anterior producirá el siguiente XML:

<foo>
  <bar>123</bar>
</foo>

ARREGLOS

El siguiente código:

$elem1 = SOAP::Data->name('item' => 123)->type('SomeObject');
$elem2 = SOAP::Data->name('item' => 456)->type('SomeObject');
push(@array,$elem1);
push(@array,$elem2);
my $client = SOAP::Lite
    ->readable(1)
    ->uri($NS)
    ->proxy($HOST);
$temp_elements = SOAP::Data
    ->name("CallDetails" => \SOAP::Data->value(
          SOAP::Data->name("elem1" => 'foo'),
          SOAP::Data->name("elem2" => 'baz'),
          SOAP::Data->name("someArray" => \SOAP::Data->value(
              SOAP::Data->name("someArrayItem" => @array)
                        ->type("SomeObject"))
                   )->type("ArrayOf_SomeObject" ))
->type("SomeObject");
$response = $client->someMethod($temp_elements);

Producirá el siguiente XML:

<?xml version="1.0" encoding="UTF-8"?>
<SOAP-ENV:Envelope
    xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
    xmlns:SOAP-ENC="http://schemas.xmlsoap.org/soap/encoding/"
    xmlns:SOAP-ENV="http://schemas.xmlsoap.org/soap/envelope/"
    xmlns:xsd="http://www.w3.org/2001/XMLSchema"
    xmlns:namesp2="http://namespaces.soaplite.com/perl"
    SOAP-ENV:encodingStyle="http://schemas.xmlsoap.org/soap/encoding/">
  <SOAP-ENV:Body>
    <namesp1:someMethod xmlns:namesp1="urn:TemperatureService">
      <CallDetails xsi:type="namesp2:SomeObject">

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

    <elem1 xsi:type="xsd:string">foo</elem1>
    <elem2 xsi:type="xsd:string">baz</elem2>
    <someArray xsi:type="namesp2:ArrayOf_SomeObject">
      <item xsi:type="namesp2:SomeObject">123</item>
      <item xsi:type="namesp2:SomeObject">456</item>
    </someArray>
  </CallDetails>
</namesp1:test>

En el código anterior, la variable @array puede ser un array de cualquier cosa. Si se pasa un array de números, SOAP::Lite lo serializará correctamente. Si, sin embargo, necesitas codificar un array de tipos complejos, simplemente pasa un array de otros objetos SOAP::Data y estarás listo.

COMPOSICIÓN DE MENSAJES USANDO XML CRUDO

En algunas circunstancias, puede que necesites codificar un mensaje usando texto XML crudo y sin serializar. Para instanciar un objeto SOAP::Data usando XML crudo, haz lo siguiente:

$xml_content = "<foo><bar>123</bar></foo>";
$elem = SOAP::Data->type('xml' => $xml_content);

El serializador de SOAP::Lite simplemente toma cualquier texto que se le pase y lo inserta en el elemento SOAP::Data codificado tal cual. El texto de entrada NO se valida para asegurar que sea XML válido, ni el elemento SOAP::Data resultante se valida para asegurar que producirá XML válido. Por lo tanto, es responsabilidad del desarrollador asegurarse de que cualquier dato XML utilizado de esta manera sea válido y resulte en un documento XML válido.

MÚLTIPLES ESPACIOS DE NOMBRES

Al trabajar con tipos complejos, puede ser necesario declarar múltiples espacios de nombres. El siguiente código demuestra cómo hacerlo:

$elem = SOAP::Data->name("myElement" => "myValue")
                  ->attr( { 'xmlns:foo2' => 'urn:Foo2',
                            'xmlns:foo3' => 'urn:Foo3' } );

Esto producirá el siguiente XML:

<myElement xmlns:foo2="urn:Foo2" xmlns:foo3="urn:Foo3">myValue</myElement>
