Descripción Detallada

La clase SoGLRenderAction renderiza el grafo de escena con llamadas OpenGL.

Aplicar este método a un nodo raíz para un grafo de escena, ruta o lista de rutas renderizará toda la geometría contenida dentro de esa instancia en el contexto actual de OpenGL.

Documentación de Enumeración de Miembro

enum SoGLRenderAction::TransparencyType

Varios ajustes sobre cómo renderizar objetos transparentes en la escena. Algunos ajustes proporcionarán una renderización más rápida, mientras que otros le darán una renderización de mejor calidad.

Tenga en cuenta que la renderización correcta de múltiples objetos transparentes a menudo falla, porque para ser 100% correcta, todos los polígonos deben renderizarse en orden ordenado, y los polígonos no pueden interactuar entre sí. En un grafo de escena dinámico, a menudo es imposible garantizar que ningún polígono interactúe, y encontrar un algoritmo que ordene correctamente los polígonos para todos los casos posibles es muy difícil y consume tiempo.

El modo de transparencia de mayor calidad en el Open Inventor original de SGI / TGS es SoGLRenderAction::SORTED_OBJECT_BLEND, donde todos los objetos transparentes se renderizan en orden en un pase de renderización después de todos los objetos opacos. Sin embargo, este modo no ordena los polígonos, y si tiene un objeto donde un polígono A está detrás de otro polígono B, la transparencia solo será correcta si A se renderiza antes que B. Para otros ángulos de cámara, donde B está detrás de A, la transparencia no será correcta.

En Coin, tenemos un nuevo modo de transparencia que resuelve algunos de estos problemas: SoGLRenderAction::SORTED_OBJECT_SORTED_TRIANGLE_BLEND. Además de ordenar los objetos, todos los polígonos dentro de cada objeto también se ordenan de atrás hacia adelante al renderizar. Pero, si tiene objetos que interactúan y/o polígonos que interactúan, incluso este modo de transparencia fallará. Además, debido a la ordenación de polígonos, este modo de transparencia es bastante lento. Sin embargo, es posible acelerar las cosas usando el nodo SoTransparencyType, que le permite establecer diferentes modos de transparencia para diferentes partes del grafo de escena. Si solo tiene unos pocos objetos donde necesita ordenar los polígonos, puede usar SoGLRenderAction::SORTED_OBJECT_SORTED_TRIANGLE_BLEND para esos, y por ejemplo SoGLRenderAction::SORTED_OBJECT_BLEND para todos los demás objetos transparentes.

El modo de transparencia de mayor calidad en Coin es SoGLRenderAction::SORTED_LAYERS_BLEND. También es el único modo que anula todos los demás modos en el grafo de escena.

(Una nota importante sobre este modo: hemos recibido informes de usuarios que algunos controladores de OpenGL, posiblemente para algunos sistemas Mac OS X, degradan significativamente el rendimiento de la renderización. Así que tenga cuidado y pruebe su aplicación en una amplia variedad de sistemas en tiempo de ejecución al usar SoGLRenderAction::SORTED_LAYERS_BLEND).

SoTransparencyType

Enumerador

SCREEN_DOOR
Los triángulos transparentes se renderizan con un patrón de tramado. Este es un modo de transparencia rápido (en la mayoría de las tarjetas gráficas) pero de no muy alta calidad.

Una característica particular de este modo es que se garantiza que siempre renderiza las partes transparentes de la escena correctamente con respecto al orden de profundidad interno de objetos/polígonos, algo que no sucede con ningún otro modo de transparencia.

Los polígonos renderizados solo con texturas transparentes no se muestran como transparentes cuando se usa este modo. La razón es que el modo SoGLRenderAction::SCREEN_DOOR funciona en polígonos, no en píxeles. Para renderizar polígonos con patrón de tramado, se debe insertar un nodo de material en el grafo de escena con su campo de transparencia establecido.

ADD
Los objetos transparentes se renderizan usando mezcla alfa aditiva. La mezcla aditiva probablemente se usa principalmente para crear efectos de transparencia especiales. El nuevo color del píxel se calcula como el color del píxel actual más el color del píxel de origen multiplicado por el valor alfa del píxel de origen.
DELAYED_ADD
Los objetos transparentes se renderizan usando mezcla alfa aditiva, en un segundo pase de renderización con actualizaciones del búfer de profundidad desactivadas.
SORTED_OBJECT_ADD
Los objetos transparentes se renderizan usando mezcla alfa aditiva. Los objetos opacos se renderizan primero, y los objetos transparentes se renderizan de atrás hacia adelante con actualizaciones del z-buffer deshabilitadas.
BLEND
Los objetos transparentes se renderizan usando mezcla alfa multiplicativa.

La mezcla alfa multiplicativa es el tipo de mezcla que se usa con más frecuencia para renderizar objetos transparentes. El nuevo valor de píxel se calcula como el color del píxel antiguo multiplicado por uno menos el valor alfa de origen, más el color del píxel de origen multiplicado por el valor alfa de origen.

Recomendamos que use este modo de transparencia si solo tiene un objeto transparente en su escena y sabe que se renderizará después de los objetos opacos.

DELAYED_BLEND
Los objetos transparentes se renderizan usando mezcla alfa multiplicativa, en un segundo pase de renderización con actualizaciones del búfer de profundidad desactivadas.

Use este tipo de transparencia cuando tenga un objeto transparente, o varios objetos transparentes que sepa que nunca se superpondrán (cuando se proyectan en la pantalla). Dado que los objetos transparentes se renderizan después de los opacos, no tendrá que preocuparse por colocar los objetos transparentes al final de su grafo de escena. Por supuesto, no será tan rápido como el tipo de transparencia SoGLRenderAction::BLEND, ya que el grafo de escena se recorre dos veces.

SORTED_OBJECT_BLEND
Los objetos transparentes se renderizan usando mezcla alfa multiplicativa, Los objetos opacos se renderizan primero, y los objetos transparentes se renderizan de atrás hacia adelante con actualizaciones del z-buffer deshabilitadas.

Use este modo de transparencia cuando tenga varios objetos transparentes que sepa que podrían superponerse (cuando se proyectan en la pantalla). Este método requerirá 1 + num_objetos_transparentes pases de renderización. Se utiliza la traversa de ruta al renderizar objetos transparentes, por supuesto, pero aún puede ser lento si tiene muchos cambios de estado antes de su objeto transparente. Al usar este modo, recomendamos colocar los objetos transparentes lo más pronto posible en el grafo de escena para minimizar la sobrecarga de traversa.

SORTED_OBJECT_SORTED_TRIANGLE_ADD
Este tipo de transparencia es una extensión de Coin en comparación con la API original de SGI Open Inventor.

Los objetos transparentes se renderizan de atrás hacia adelante, y los triángulos en cada objeto se ordenan de atrás hacia adelante antes de renderizar.

Consulte la descripción de SoGLRenderAction::SORTED_OBJECT_SORTED_TRIANGLE_BLEND para obtener más información sobre este tipo de transparencia.

SORTED_OBJECT_SORTED_TRIANGLE_BLEND
Este tipo de transparencia es una extensión de Coin en comparación con la API original de SGI Open Inventor.

Los objetos transparentes se renderizan de atrás hacia adelante, y los triángulos en cada objeto se ordenan de atrás hacia adelante antes de renderizar.

Use este tipo de transparencia cuando tenga uno (o más) objetos transparentes donde sepa que los triángulos podrían superponerse dentro del objeto. Este tipo de transparencia puede ser muy lento si tiene un objeto con muchos triángulos, ya que todos los triángulos deben ordenarse antes de renderizar, y se utiliza un bucle de renderización no optimizado al renderizar. Las líneas y los puntos no se ordenan antes de renderizar. Se renderizan como en el tipo de transparencia normal SoGLRenderAction::SORTED_OBJECT_BLEND.

Tenga en cuenta que este modo de transparencia no garantiza una renderización de transparencia "correcta". Es casi imposible encontrar un algoritmo que ordene correctamente los triángulos en todos los casos, y los triángulos que se intersecan no se manejan. Además, dado que cada objeto se maneja por separado, dos objetos que se intersecan darán como resultado una transparencia incorrecta.

NONE
Este tipo de transparencia es una extensión de Coin en comparación con la API de Open Inventor.

Desactiva la transparencia para los objetos, incluso si la transparencia se establece usando un nodo SoMaterial.

SORTED_LAYERS_BLEND
Este tipo de transparencia es una extensión de Coin en comparación con la API original de SGI Open Inventor.

Al usar este tipo de transparencia, SoGLRenderAction renderizará objetos transparentes normales e intersecantes correctamente, independientemente del orden de renderización. Es el único modo de renderización de tipo de transparencia que garantiza hacerlo.

Este modo es diferente de todos los demás modos en que anula los nodos SoTransparencyType en el grafo de escena; todos los objetos se dibujan usando SoGLRenderAction::SORTED_LAYERS_BLEND.

Actualmente hay dos rutas de código separadas para este modo. Ambas rutas se basan en gran medida en extensiones de OpenGL. El primer método se basa en extensiones que solo están disponibles en chipsets NVIDIA (GeForce3 y posteriores, excepto GeForce4 MX). Estas extensiones son GL_NV_texture_shader, GL_NV_texture_rectangle o GL_EXT_texture_rectangle, GL_NV_register_combiners, GL_ARB_shadow y GL_ARB_depth_texture. Tenga en cuenta que este tipo de transparencia ocupa las cuatro unidades de textura en la tarjeta NVIDIA para todos los pases de renderización, excepto el primero. Por lo tanto, las superficies texturizadas solo estarán texturizadas si no están ocluidas por otra superficie transparente.

El segundo método utiliza la extensión GL_ARB_fragment_program. Esta extensión es actualmente compatible con la familia GeForceFX y la Radeon 9500 y

Descripción

Esta clase es la clase base para la mayoría de las acciones de renderizado. Coin utiliza el *depth peeling* para renderizar transparencia correctamente, independientemente del orden de los objetos. La técnica se basa en el renderizado en múltiples pasadas. Con cada pasada sucesiva, se elimina una capa de profundidad. El número de pasadas determina hasta qué punto se renderizarán las superficies transparentes. Un mayor número de pasadas conduce a una menor tasa de fotogramas, pero a una mayor calidad en escenas con muchas superficies transparentes.

El número de pasadas se puede especificar mediante SoGLRenderAction::setSortedLayersNumPasses() o permitiendo que las variables de entorno COIN_NUM_SORTED_LAYERS_PASSES u OIV_NUM_SORTED_LAYERS_PASSES especifiquen el número de pasadas. El número de pasadas por defecto es '4'.

El modo SoGLRenderAction::SORTED_LAYERS_BLEND es una forma especial de *depth peeling* que se basa en *fragment programs* para optimizar el renderizado. Esta técnica es más rápida que el método puro de NVIDIA. El método de *fragment program* se elegirá automáticamente si es posible. Tenga en cuenta que se debe tener cuidado de no colocar el plano cercano demasiado cerca de la cámara debido a la falta de control de precisión de punto flotante en los *fragment programs*. Hacerlo puede provocar la pérdida de precisión en los bordes y "dientes de sierra" en la geometría transparente.

La configuración de la variable de entorno COIN_SORTED_LAYERS_USE_NVIDIA_RC a '1' forzará el uso de la ruta de código anterior en lugar de la última, incluso si está disponible.

Debe ser el contexto de renderizado actual un buffer de profundidad de >= 24 bits y un canal alfa de 8 bits para que este modo de mezcla se active realmente. Si el lienzo de renderizado actual no tiene estas propiedades, Coin recurrirá a un modo de manejo de transparencia más simple. Si está utilizando una de las bibliotecas de enlace del sistema de ventanas proporcionadas por Kongsberg Oil & Gas Technologies, por ejemplo, SoXt, SoQt o SoWin, deberá habilitar esto explícitamente en su visor. Consulte la documentación de la API del método setAlphaChannel() de SoXtGLWidget, SoQtGLWidget o SoWinGLWidget.

La detección de si el modo SoGLRenderAction::SORTED_LAYERS_BLEND puede ser utilizado o no se realizará automáticamente internamente en Coin. Si una o más de las condiciones necesarias enumeradas anteriormente no están disponibles, se utilizará SoGLRenderAction::SORTED_OBJECT_BLEND como tipo de transparencia en su lugar.

Para poder renderizar transparencia correctamente independientemente del orden de los objetos, hay que renderizar en múltiples pasadas. Esta técnica se basa en *depth peeling*, que elimina capas de profundidad con cada pasada sucesiva. Por lo tanto, el número de pasadas es una indicación de cuán profundo en la escena se renderizarán las superficies transparentes con transparencia. Un número mayor conducirá a una menor tasa de fotogramas, pero a una mayor calidad para escenas con muchas superficies transparentes. El número de pasadas por defecto es '4'. Este número se puede especificar utilizando SoGLRenderAction::setSortedLayersNumPasses() o permitiendo que las variables de entorno COIN_NUM_SORTED_LAYERS_PASSES o OIV_NUM_SORTED_LAYERS_PASSES especifiquen el número de pasadas.

Una presentación más detallada del algoritmo está escrita por Cass Everitt en NVIDIA;

"Interactive Order-Independent Transparency" https://www.nvidia.com/en-us/drivers/Interactive-Order-Transparency/

void SoGLRenderAction::setAbortCallback (SoGLRenderAbortCB *const func, void *const userdata)

Sets the abort callback. The abort callback is called by the action for each node during traversal to check for abort conditions.

The callback method should return one of the SoGLRenderAction::AbortCode enum values to indicate how the action should proceed further.

Since the client SoGLRenderAbortCB callback function only has a single void* argument for the userdata, one has to do some additional work to find out which node the callback was made for. One can do this by for instance passing along the action pointer as userdata, and then call the SoGLRenderAction::getCurPath() method. The tail of the path will then be the last traversed node. Like this:

// set up so we can abort or otherwise intervene with the render
// traversal:
myRenderAction->setAbortCallback(MyRenderCallback, myRenderAction);
// [...]
SoGLRenderAction::AbortCode
MyRenderCallback(void * userdata)
{
  SoGLRenderAction * action = (SoGLRenderAction *)userdata;
  SoNode * lastnode = action->getCurPath()->getTail();
  // [...]
  return SoGLRenderAction::CONTINUE;
}

DESCRIPTION

This class extends SoAction to provide OpenGL rendering.

The SoGLRenderAction class adds OpenGL-specific features to the generic SoAction class. Its primary use is to render a scene graph to an OpenGL window. It traverses the scene graph and issues OpenGL commands to draw the geometry. It also handles state management, lighting, texturing, and transparency.

It is the base class for specific rendering actions like SoOffscreenRenderer.

The action supports several methods for controlling rendering behavior, including:

  • Setting rendering modes (e.g., for transparency).
  • Controlling the rendering order of transparent objects.
  • Handling remote rendering.
  • Adding custom callbacks for pre-rendering or sorting.

The action also provides methods for querying the current rendering state, such as the current pass number or whether transparent objects are being rendered.

The enumeration TransparencyType defines various methods for handling transparency, including different types of depth peeling (RTED) and sorted layer blending. For certain transparency types like RTED_OBJECT_, transparent objects are rendered in a separate pass. For other transparency types, transparent objects are rendered in the same pass as opaque objects.

void SoGLRenderAction::addPreRenderCallback (SoGLPreRenderCB * func, void * userdata)

Adds a callback which is invoked right before the scene graph traversal starts. All necessary GL initialization is then done (e.g. the viewport is correctly set), and this callback can be useful to, for instance, clear the viewport before rendering, or draw a bitmap in the background before rendering etc.

The callback is only invoked once (before the first rendering pass) when multi pass rendering is enabled.

Please note that SoSceneManager usually adds a callback to clear the GL buffers in SoSceneManager::render(). So, if you plan to for instance draw an image in the color buffer using this callback, you should make sure that the scene manager doesn't clear the buffer. This can be done either by calling SoSceneManager::render() with both arguments FALSE, or, if you're using one of our GUI toolkits (SoXt/SoQt/SoGtk/SoWin), call setClearBeforeRender() on the viewer.

This method is an extension versus the Open Inventor API.

Sets the strategy used for sorting transparent objects.

The CUSTOM_CALLBACK strategy enables the user to supply a callback which is called for each transparent shape. This strategy can be used if the built in sorting strategies aren't sufficient.

The callback should return a floating point value to be used when sorting the objects in Coin. This floating point value is interpreted as a distance to the camera, and objects with higher values will be sorted behind objects with lower values.

The callback will supply the SoGLRenderAction instance, and the path to the current object can be found using SoAction::getCurPath().

Detailed Description
This action renders a scene graph using OpenGL. It is the most commonly used action in Coin. It traverses the scene graph and issues OpenGL commands to draw the objects.

The action maintains the OpenGL state and manages the rendering pipeline. It supports features like material properties, textures, lights, cameras, and transformations.

Key features include:

  • OpenGL state management
  • Scene graph traversal for rendering
  • Support for various rendering techniques (e.g., immediate mode, display lists)
  • Integration with camera nodes for view transformations
  • Handling of lighting and material properties
  • Texture mapping
