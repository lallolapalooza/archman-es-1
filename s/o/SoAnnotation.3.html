Descripción detallada

El nodo SoAnnotation dibuja toda la geometría de sus hijos encima de otra geometría.

Este nodo de tipo grupo utiliza renderizado diferido en combinación con la desactivación del búfer z para permitir que sus hijos rendericen su geometría de forma transparente encima de la otra geometría en la escena.

Dado que el búfer z debe desactivarse, la geometría de los hijos no se renderizará ordenada de atrás hacia adelante, sino en el orden en que están presentes en el grafo de escena.

FORMATO DE ARCHIVO/VALORES PREDETERMINADOS:

Annotation {
    renderCaching AUTO
    boundingBoxCaching AUTO
    renderCulling AUTO
    pickCulling AUTO
}

Detailed Description

The SoAnnotation node is intended to be used as a base class for nodes that define annotations. Annotations are objects that are rendered in the scene graph, but are typically not part of the main geometry of the scene. Examples of annotations include text labels, coordinate axes, rulers, or compasses.

An SoAnnotation node behaves like an SoNode, but it provides specific traversal methods for rendering actions. When an SoAction traverses the scene graph and encounters an SoAnnotation node, it may invoke different rendering routines depending on whether the node is part of the path being traversed (IN_PATH), or if it is off the path (OFF_PATH).

This allows for specialized rendering of annotations, such as rendering them with different styles or at different times compared to the main scene geometry. For example, an annotation might be rendered in a different color, or it might be rendered always on top of other objects.

The SoAnnotation node itself does not define any visual appearance. It serves as a base class, and derived classes must implement their specific rendering logic.

The SoAnnotation node is derived from SoNode, inheriting all its properties and behaviors. It overrides the GLRenderBelowPath, GLRenderInPath, and GLRenderOffPath methods to provide a mechanism for specialized rendering during the OpenGL rendering process.

GLRenderBelowPath

void SoAnnotation::GLRenderBelowPath neo_SoAnnotation (SoGLRenderAction * action) neo_SoAnnotation ([virtual])

SGI Open Inventor v2.1 obsoleted support for SoGLRenderAction::addMethod(). Instead, GLRender() might be called directly, and to optimize traversal, the SoSeparator node calls GLRenderBelowPath whenever the path code is BELOW_PATH or NO_PATH (path code is guaranteed not to change). To be compatible with SGI's Inventor (and thereby also TGS') we have chosen to follow their implementation in this respect.

SoSeparator::GLRenderBelowPath() does not traverse its children using SoChildList::traverse(), but calls GLRenderBelowPath() directly for all its children.

Reimplemented from SoNode.
