Descripción Detallada

La clase SoDataSensor es la clase base abstracta para sensores que monitorizan cambios en un grafo de escena.

Si necesitas saber cuándo cambia una entidad particular (como un campo o un nodo), se pueden usar sub-clases de SoDataSensor para monitorizar la entidad y notificarte cuando cambie.

void SoDataSensor::setDeleteCallback (SoSensorCB * function, void * data = NULL)

Si un objeto monitorizado por un sensor de datos es eliminado, la función de callback dada será llamada con los datos de usuario dados.

La configuración de prioridad del sensor no afecta al callback de eliminación. Se llamará inmediatamente, antes de que el objeto sea eliminado.

SoNode * SoDataSensor::getTriggerNode (void ) const

Devuelve un puntero al nodo que causa que el sensor se active, o NULL si no hubo tal nodo.

También se devolverá NULL para sensores que no son sensores inmediatos (es decir, con prioridad igual a 0), ya que el resultado podría ser engañoso (los sensores no inmediatos podrían haber sido programados y reprogramados varias veces, por lo que no habría un único nodo responsable de la activación del sensor).

El resultado solo es válido dentro del alcance de un trigger(), por lo que si necesitas usar el puntero fuera del callback de tu sensor, debes almacenarlo.

SoField * SoDataSensor::getTriggerField (void ) const

Devuelve un puntero al campo que causa que el sensor se active, o NULL si el cambio no se originó en un campo.

Solo válido para sensores inmediatos (devolverá NULL en caso contrario), por la misma razón descrita para SoDataSensor::getTriggerNode().

El resultado solo es válido dentro del alcance de un trigger(), por lo que si necesitas usar el puntero fuera del callback de tu sensor, debes almacenarlo.

SoPath * SoDataSensor::getTriggerPath (void ) const

Devuelve un puntero al camino desde el nodo bajo la vigilancia de este sensor (ya sea directa o indirectamente a través de un watch de campo) hasta el nodo que causó que el sensor se activara.

Solo funcionará para sensores en modo inmediato, por la misma razón explicada en getTriggerNode().

El camino resultante solo es válido dentro del alcance de trigger(), por lo que si necesitas usar el camino fuera de tu callback de sensor, debes almacenar el puntero y llamar a SoPath::ref() para evitar su destrucción al final de SoDataSensor::trigger().

void SoDataSensor::setTriggerPathFlag (SbBool flag)

Esta bandera indica si se debe consultar la ruta cuando un nodo activa el sensor de datos.

Esta bandera se proporciona porque encontrar una ruta de nodo a través de un grafo de escena es una operación costosa.

Detailed Description

This sensor class is designed to monitor changes in Coin scene graph data, typically in response to changes in the graph itself.

The primary purpose of SoDataSensor is to provide a way to hook into the scene graph update mechanism and be notified when specific nodes or fields within the scene graph are modified.

When a SoDataSensor is triggered, it can provide information about what caused the trigger, such as the node and/or field that changed.

This class is often used as a base class for more specialized sensors, such as SoFieldSensor, which specifically monitors changes to individual fields.

The methods provided by SoDataSensor allow you to:

Query trigger information:
Determine which node, field, or child was modified.
Control sensor behavior:
Enable, disable, or remove the sensor.

The SoDataSensor class extends the functionality of SoDelayQueueSensor by adding the ability to track the source of the change that caused the sensor to become active.
