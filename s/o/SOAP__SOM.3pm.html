SOAP::SOM(3) Documentación de Perl aportada por el usuario SOAP::SOM(3)

NOMBRE

SOAP::SOM - proporciona acceso a los valores contenidos en la Respuesta SOAP

DESCRIPCIÓN

Los objetos de la clase SOAP::SOM generalmente no son instanciados directamente por una aplicación. Más bien, son devueltos por la deserialización de un mensaje. En otras palabras, los desarrolladores casi nunca harán esto:

$som = SOAP::SOM->new;

Los objetos SOAP::SOM son devueltos por una llamada a SOAP::Lite en un contexto de cliente. Por ejemplo:

my $client = SOAP::Lite
    ->readable(1)
    ->uri($NS)
    ->proxy($HOST)
$som = $client->someMethod();

MÉTODOS

new(mensaje)
$som = SOAP::SOM->new($mensaje_como_xml);

Como se dijo, la necesidad de crear realmente un objeto de esta clase debería ser muy rara. Sin embargo, si surge la necesidad, se debe seguir la sintaxis. El único argumento para new debe ser un documento XML válido que el analizador entienda como una respuesta SOAP.

El siguiente grupo de métodos proporciona la recuperación general de datos del objeto SOAP::SOM. El modelo para esto es una forma abreviada de XPath. Después de este grupo hay métodos que están orientados a la recuperación específica de elementos solicitados comúnmente.

match(ruta)
$som->match('/Envelope/Body/[1]');

Este método establece los punteros internos dentro de la estructura de datos para que los métodos de recuperación que siguen tengan acceso a los datos deseados. En la ruta de ejemplo, la coincidencia se realiza contra la entidad del método, que es la primera etiqueta hija del cuerpo en una respuesta SOAP. La enumeración de los hijos de un contenedor comienza en 1 en esta sintaxis, no en 0. El valor devuelto depende del contexto de la llamada. Si la llamada se realiza en un contexto booleano (como "if ($som->match($path))"), el valor devuelto es un booleano que indica si la ruta solicitada coincidió en absoluto. De lo contrario, se devuelve una referencia a un objeto. El objeto devuelto también es una instancia de SOAP::SOM, pero es más pequeño, conteniendo el subconjunto del árbol del documento que coincidió con la expresión.

valueof(nodo)
$res = $som->valueof('[1]');

Cuando el objeto SOAP::SOM ha coincidido con una ruta internamente con el método match, este método permite la recuperación de los datos dentro de cualquiera de los nodos coincidentes. Los datos vuelven como datos nativos de Perl, no como una instancia de clase (ver dataof). En un contexto escalar, este método devuelve solo el primer elemento de un conjunto de nodos coincidentes. En un contexto de matriz, se devuelven todos los elementos. Suponiendo que la llamada anterior ocurre después de la llamada anterior a match, recupera la entidad de resultado de la respuesta del método que está contenida en $som, ya que este es el primer elemento hijo en una etiqueta de respuesta de método.

dataof(nodo)
$resobj = $som->dataof('[1]');

Realiza la misma operación que el método valueof anterior, excepto que los datos se dejan en su forma SOAP::Data, en lugar de ser deserializados. Esto permite un acceso completo a todos los atributos que fueron serializados junto con los datos, como el espacio de nombres y la codificación.

headerof(nodo)
$resobj = $som->headerof('[1]');

Actúa de forma muy similar a dataof, excepto que devuelve un objeto de la clase SOAP::Header (cubierto más adelante en este capítulo), en lugar de SOAP::Data. Esta es la interfaz preferida para manipular las entidades de encabezado en un mensaje.

namespaceuriof(nodo)
$ns = $som->namespaceof('[1]');

Recupera el URI del espacio de nombres que rige el nodo solicitado. Tenga en cuenta que los espacios de nombres se heredan, por lo que este método devolverá el valor relevante, incluso si se deriva de un nodo padre u otro ancestro.

Los siguientes métodos proporcionan un acceso más directo al sobre del mensaje. Todos estos métodos devuelven alguna forma de valor de Perl, la mayoría de las veces una referencia a un hash, cuando se llaman. El contexto también es relevante: en un contexto escalar solo se devuelve el primer nodo coincidente, mientras que en un contexto de matriz, se devuelven todos los nodos coincidentes. Cuando se llama como un método estático o como una función regular (como "SOAP::SOM::envelope"), cualquiera de los siguientes métodos devuelve la cadena XPath que se utiliza con el método match para recuperar los datos.

root
$root = $som->root;

Devuelve el valor del elemento raíz como una referencia a un hash. Se comporta exactamente como lo hace "$som-"valueof('/')>.

envelope
$envelope = $som->envelope;

Recupera el elemento "Envelope" del mensaje, devolviéndolo a él y sus datos como una referencia a un hash. Las claves en el hash serán Header y Body (más cualquier elemento opcional que pueda estar presente en un sobre SOAP 1.1), cuyos valores serán el encabezado y el cuerpo serializados, respectivamente.

header
$header = $som->header;

Recupera la porción del encabezado del sobre como una referencia a un hash. Todos los datos dentro de él habrán sido deserializados. Si se desean los atributos del encabezado, la forma estática del método se puede combinar con match para obtener el encabezado como un objeto SOAP::Data:

$header = $som->match(SOAP::SOM::header)->dataof;
headers
@hdrs = $som->headers;

Recupera el conjunto de nodos de valores con encabezados deserializados dentro del contenedor Header. Esto es diferente del método header anterior en que devuelve todo el encabezado como una sola estructura, y este devuelve los elementos hijos como una matriz. En otras palabras, las siguientes expresiones producen la misma estructura de datos:

$header = ($som->headers)[0];
$header = $som->valueof(SOAP::SOM::header.'/[1]');
body
$body = $som->body;

Recupera el cuerpo del mensaje como una referencia a un hash. Las etiquetas de entidad actúan como claves, con su contenido deserializado proporcionando los valores.

fault
if ($som->fault) { die $som->fault->faultstring }

Actúa tanto como una prueba booleana para saber si ocurrió un error, como una forma de recuperar la entidad Fault del cuerpo del mensaje como una referencia a un hash. Si el mensaje contiene un error, los siguientes cuatro métodos (faultcode, faultstring, faultactor y faultdetail) pueden usarse para recuperar las partes respectivas del error (que también están disponibles en la referencia al hash como claves). Si fault en un contexto booleano es verdadero, los métodos "result", "paramsin", "paramsout" y "method" devuelven "undef".

faultcode
$code = $som->faultcode;

Devuelve el elemento faultcode del error si hay un error; de lo contrario, undef.

faultstring
$string = $som->faultstring;

Devuelve el elemento faultstring del error si hay un error; de lo contrario, undef.

faultactor
$actor = $som->faultactor;

NAME

SOAP::SOM - SOAP Object Message

DESCRIPTION

SOAP::SOM is a class for representing a SOAP message as a Perl object. It is returned from SOAP::Lite's proxy calls, and is used to inspect the returned message. The name SOM stands for SOAP Object Message.

The SOAP::SOM object provides methods for inspecting the SOAP message, retrieving its contents, and determining if the message contains a fault.

METHODS

fault
my $bool = $som->fault;

Returns true if the SOAP message contains a fault, and false otherwise. This is the primary way to check if a call failed.

faultcode
my $code = $som->faultcode;

Returns the fault code from a SOAP fault. Returns undef if the message is not a fault.

faultstring
my $string = $som->faultstring;

Returns the fault string from a SOAP fault. Returns undef if the message is not a fault.

faultactor
my $actor = $som->faultactor;

Returns the fault actor from a SOAP fault. Returns undef if the message is not a fault, or if no fault actor was specified.

detail
my $detail = $som->detail;

Returns the detail element of a SOAP fault. The detail element can contain arbitrary XML, so this method returns the detail as a hash reference if it contains an array of elements, or as a scalar string if it's a single element. If the message is not a fault, or if the fault does not contain a detail element, it returns undef. The specification for the detail portion of a fault calls for it to contain a series of element tags, so the application may expect a hash reference as a return value when detail information is available (and undef otherwise).

method
$method = $som->method

Retrieves the "method" element of the message, as a hash reference. This includes all input parameters when called on a request message or all result/output parameters when called on a response message. If there is a fault present in the message, it returns undef.

result
$value = $som->result;

Returns the value that is the result of a SOAP response. The value will be already deserialized into a native Perl datatype.

paramsin
@list = $som->paramsin;

Retrieves the parameters being passed in on a SOAP request. If called in a scalar context, the first parameter is returned. When called in a list context, the full list of all parameters is returned. Each parameter is a hash reference, following the established structure for such return values.

paramsout
@list = $som->paramsout;

Returns the output parameters from a SOAP response. These are the named parameters that are returned in addition to the explicit response entity itself. It shares the same scalar/list context behavior as the paramsin method.

paramsall
@list = $som->paramsall;

Returns all parameters from a SOAP response, including the result entity itself, as one array.

parts()
Return an array of "MIME::Entity"'s if the current payload contains attachments, or returns undefined if payload is not MIME multipart.
is_multipart()
Returns true if payload is MIME multipart, false otherwise.

EXAMPLES

ACCESSING ELEMENT VALUES

Suppose for the following SOAP Envelope:

<Envelope>
  <Body>
    <fooResponse>
      <bar>abcd</bar>
    </fooResponse>
  </Body>
</Envelope>

And suppose you wanted to access the value of the bar element, then use the following code:

my $soap = SOAP::Lite
    ->uri($SOME_NS)
    ->proxy($SOME_HOST);
my $som = $soap->foo();
print $som->valueof('//fooResponse/bar');

ACCESSING ATTRIBUTE VALUES

Suppose the following SOAP Envelope:

<Envelope>
  <Body>
    <c2fResponse>
      <convertedTemp test="foo">98.6</convertedTemp>
    </c2fResponse>
  </Body>
</Envelope>

Then to print the attribute 'test' use the following code:

print "The attribute is: " .
  $som->dataof('//c2fResponse/convertedTemp')->attr->{'test'};

ITERATING OVER AN ARRAY

Suppose for the following SOAP Envelope:

<Envelope>
  <Body>
    <catalog>
      <product>
        <title>Programming Web Service with Perl</title>
        <price>$29.95</price>
      </product>
      <product>
        <title>Perl Cookbook</title>
        <price>$49.95</price>
      </product>
    </catalog>
  </Body>
</Envelope>

If the SOAP Envelope returned contained an array, use the following code to iterate over the array:

for my $t ($som->valueof('//catalog/product')) {
  print $t->{title} . " - " . $t->{price} . "\n";
}

DETECTING A SOAP FAULT

A SOAP::SOM object is returned by a SOAP::Lite client regardless of whether the call succeeded or not. Therefore, a SOAP Client is responsible for determining if the returned value is a fault or not. To do so, use the fault() method which returns 1 if the SOAP::SOM object is a fault and 0 otherwise.

my $som = $client->someMethod(@parameters);
if ($som->fault) {
  print $som->faultdetail;
} else {
  # do something
}

PARSING ARRAYS OF ARRAYS

The most efficient way To parse and to extract data out of an array containing another array encoded in a SOAP::SOM object is the following:

$xml = <<END_XML;
<foo>
  <person>
    <foo>123</foo>
    <foo>456</foo>
  </person>
  <person>
    <foo>789</foo>
    <foo>012</foo>
  </person>
</foo>
END_XML
my $som = SOAP::Deserializer->deserialize($xml);
my $i = 0;
foreach my $a ($som->dataof("//person/*")) {
    $i++;
    my $j = 0;
    foreach my $b ($som->dataof("//person/[$i]/*")) {
        $j++;
        # do something
    }
}
