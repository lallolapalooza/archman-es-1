Descripción Detallada

La clase SoField es la clase base abstracta de nivel superior para campos.

Los campos son el mecanismo utilizado en Coin para encapsular tipos de datos básicos para detectar cambios realizados en ellos, y para proporcionar instalaciones de conversión, importación y exportación.

Casi todas las propiedades públicas en los nodos se almacenan en campos, al igual que las entradas y salidas de los motores. Por lo tanto, los campos pueden verse como el principal mecanismo para que los nodos del grafo de escena y los motores expongan su API pública.

Forzar la modificación de datos para que pase a través de una interfaz de función pública, ocultando al mismo tiempo los miembros de datos, hace posible detectar y reaccionar automáticamente a los cambios en las estructuras de datos configuradas por el programador de la aplicación.

Por ejemplo, el comportamiento predeterminado al cambiar el valor de un campo en un nodo del grafo de escena es que habrá automáticamente una cadena de notificaciones: desde el campo hasta el nodo propietario, desde ese nodo hasta su nodo padre, y así sucesivamente hasta el nodo raíz de nivel superior, donde se señalará la necesidad de una actualización de renderizado a la aplicación.

(Este mecanismo de notificación es la característica subyacente que hace que la biblioteca Coin se clasifique como una API de grafo de escena de "orientada a datos".

Las consecuencias prácticas de esto es que la renderización y muchas otras acciones de procesamiento se programan por defecto para que solo ocurran cuando algo ha cambiado en las estructuras de datos retenidas, haciendo que la biblioteca Coin, en circunstancias normales, sea mucho menos intensiva en CPU que las API de grafo de escena de "orientadas a la aplicación", como por ejemplo SGI IRIS Performer, que renderizan continuamente incluso cuando nada ha cambiado en las estructuras de datos o en la ventana del visor de la cámara.)

Almacenar los miembros de datos como campos también proporciona otras conveniencias para el programador de la aplicación:

•
Los campos se pueden conectar a otros campos. Esto permite, por ejemplo, tener escenas que se autoactualizan, es decir, se pueden configurar escenas donde las entidades reaccionan automáticamente a los cambios en otras entidades. Esto también proporciona un mecanismo necesario para tener escenas que se autoaniman, ya que es posible conectar cualquier campo al campo global llamado realTime, proporcionando un temporizador de reloj de pared.
•
Al conectar campos entre sí, Coin tiene mecanismos integrados para convertir automáticamente entre diferentes tipos de campos.
•
Los campos proporcionan persistencia para las operaciones de importación (y exportación) del grafo de escena. Esto incluye animar entidades, por lo que las animaciones se pueden almacenar en archivos con formato Inventor ordinario.
•
Los campos proporcionan características de introspección: tienen un sistema de tipos, al igual que los nodos y las acciones, tienen nombres, y también es posible averiguar qué nodo, motor u otra entidad posee un campo.
•
Los campos pueden contener múltiples valores. Los campos multivalor vienen con una abstracción de interfaz mucho mayor que los arrays estándar de C/C++.

Nota: hay algunas clases de campos que han quedado obsoletas en la API de Open Inventor. Son: SoSFLong, SoSFULong, SoMFLong y SoMFULong. Debería usar estas clases en su lugar (respectivamente): SoSFInt32, SoSFUInt32, SoMFInt32 y SoMFUInt32.

SbBool SoField::connectFrom (SoField * master, SbBool append = FALSE)

Connect this field as a slave to the given field master. If append is TRUE, the new connection is added to the existing connections. If append is FALSE, all previous connections are first destroyed, and this new connection is the only one.

NOTE: This implies that if you want to connect a field to multiple masters, you must use append=TRUE for subsequent connections. Otherwise, you will lose the connection to any field you connected to beforehand.

Any connections to master fields beforehand, these are all broken up if append is FALSE.

Call with notnotify if you want to avoid the initial notification of connected auditors (a.k.a. slaves).

Function will return TRUE unless:

•
If the field connected from has a different type from the field connected to, a field converter is inserted. For some combinations of fields no such conversion is possible, and we'll return FALSE.
•
If this field is already connected to the master, we will return FALSE.

void SoField::touch (void ) [virtual]

Notify the field as well as the field's owner / container that it has been changed.

Touching a field which is part of any component (engine or node) in a scene graph will lead to a forced redraw. This is useful if you have been doing several updates to the field wrapped in a pair of enableNotify() calls to notify the field's auditors that its value has changed.

void SoField::fieldConnected (const SoField * tofield, int numconnections)

This method is called by Coin whenever this field is connected to another field. The default method does nothing.

tofield is the field that is connected to this field. numconnections is the difference in the number of connections made (i.e. if stuff is disconnected, numconnections will be a negative number).

The default method is empty. Override in subclasses if you want do something special on connections/disconnections.

void SoField::fixCopy (SbBool copyconnections) [virtual]

This method is internally called after SoField::copyFrom() during scene graph copies, and should do the operations necessary for fixing up the field instance after it has gotten a new value.

The default method in the SoField superclass does nothing.

The application programmer should normally not need to consider this method, unless he constructs a complex field type which contains new references to container instances (i.e. nodes or engines). Overriding this method is then necessary to update the reference pointers, as they could have been duplicated during the copy operation.

Reimplemented in SoMFEngine, SoMFNode, SoMFPath, SoSFEngine, SoSFNode, and SoSFPath.

SbBool SoField::referencesCopy (void ) const [virtual]

Returns TRUE if this field has references to any containers in the scene graph which are also duplicated during the copy operation.

Note that this method only is valid to call during copy operations.

See also the note about the relevance of the fixCopy() method for application programmers, as it is applicable on this method as well.

Reimplemented in SoMFEngine, SoMFNode, SoMFPath, SoSFEngine, SoSFNode, and SoSFPath.

Detailed Description

This is the base class for all fields in Coin. Fields are used to store data within an SoNode and to connect nodes to each other (and to engines, interpolators, etc.).

A field is defined by its type (e.g. SoSFNode, SoSFString, SoSFFloat, etc.) and a value. Fields can be read from and written to file-like objects using SoInput and SoOutput.

Fields can be connected to other fields, engines or interpolators. This means that the value of one field can be automatically updated when the value of the master source changes.

There are two types of fields:

SF
Single-valued fields. These fields store a single value of a specific type.
MF
Multi-valued fields. These fields store an array of values of a specific type.

Fields are also classified by their access level:

public
Fields that can be accessed and modified directly by application code.
protected
Fields that are intended for internal use by the field's class and its subclasses. These are typically not meant to be called directly by application code, but are part of the class's implementation.

This man page documents the protected virtual methods of the SoField base class. These methods are primarily used internally by Coin for managing fields, their values, and their connections.
