SD_EVENT_SIGNAL_PROCMASK(3) sd_event_add_signal SD_EVENT_SIGNAL_PROCMASK(3)

NOMBRE

sd_event_add_signal, sd_event_source_get_signal, sd_event_signal_handler_t, SD_EVENT_SIGNAL_PROCMASK - Añadir un evento de señal de proceso a un bucle de eventos

SINTAXIS

#include <systemd/sd-event.h>
typedef struct sd_event_source sd_event_source;
SD_EVENT_SIGNAL_PROCMASK

typedef int (*sd_event_signal_handler_t)(sd_event_source *s, const struct signalfd_siginfo *si, void *userdata);

int sd_event_add_signal(sd_event *event, sd_event_source **source, int signal, sd_event_signal_handler_t handler, void *userdata);

int sd_event_source_get_signal(sd_event_source *source);

DESCRIPCIÓN

sd_event_add_signal() añade un nuevo evento de señal de proceso a un bucle de eventos. El objeto del bucle de eventos se especifica en el parámetro event, y el objeto de la fuente de eventos se devuelve en el parámetro source. El parámetro signal especifica la señal numérica a manejar (ver signal(7)).

El parámetro handler es una función que se llama cuando se recibe la señal, o NULL. La función manejadora recibirá el puntero userdata, que puede ser elegido libremente por el llamador. La manejadora también recibirá un puntero a una estructura signalfd_siginfo que contiene información sobre la señal recibida. Para más información, vea signalfd(2). La manejadora puede devolver un valor negativo para indicar un error (ver abajo), otros valores se ignoran. Si handler es NULL, se usará una manejadora predeterminada que llama a sd_event_exit(3).

Solo se puede instalar una manejadora para una señal específica. La señal debe estar bloqueada en todos los hilos antes de llamar a esta función (usando sigprocmask(2) o pthread_sigmask(3)). Para conveniencia, si el flag especial SD_EVENT_SIGNAL_PROCMASK se pone a OR en la señal especificada, la señal se automatizará como necesaria por el hilo de ejecución actual. Nota: Esto solo funciona correctamente si la señal ya está bloqueada en todos los otros hilos del proceso, o si no hay otros hilos en el momento de la invocación.

Por defecto, la fuente de eventos está siempre activa (SD_EVENT_ON), pero esto puede cambiarse con sd_event_source_set_enabled(3). Si la manejadora de función devuelve un código de error negativo, se desactivará después de la invocación, incluso si el modo SD_EVENT_ON fue solicitado previamente, o causará que el bucle de eventos se cierre, ver sd_event_source_set_exit_on_failure(3).

Para destruir un objeto de fuente de eventos, use sd_event_source_unref(3), pero tenga en cuenta que el objeto de fuente de eventos se eliminará del bucle de eventos solo cuando todas las referencias al objeto hayan terminado. Para asegurarse de que una fuente de eventos no se active incluso si está referenciada, desactive la fuente usando sd_event_source_set_enabled(3) con SD_EVENT_OFF.

Si el segundo parámetro de sd_event_add_signal() es NULL, no se devuelve una referencia al objeto de fuente de eventos. En este caso, la fuente de eventos se considera "flotante" y se destruirá implícitamente cuando el propio bucle de eventos se destruya.

Si el parámetro handler de sd_event_add_signal() es NULL, y la fuente de eventos se activa, se considera una solicitud para salir del bucle de eventos. En este caso, el parámetro userdata, casteado como un entero, se pasa como código de salida a sd_event_exit(3).

sd_event_source_get_signal() devuelve el número de señal configurado de una fuente de eventos creada previamente con sd_event_add_signal(). El objeto de la fuente de eventos se usa como parámetro source.

VALOR DE RETORNO

En caso de éxito, estas funciones devuelven 0 o un valor positivo. En caso de error, devuelven un código de error negativo.

Errores

Los errores devueltos pueden indicar los siguientes problemas:

-ENOMEM

No hay suficiente memoria para crear un objeto.

-EINVAL

Se pasó un argumento inválido.

-EBUSY

Ya hay una manejadora instalada para esta señal o la señal no estaba bloqueada previamente.

-ESTALE

El bucle de eventos ya fue terminado.

-ECHILD

El bucle de eventos fue creado en un proceso, librería o módulo diferente.

-EDOM

El objeto de fuente de eventos no es una fuente de señal de proceso.

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que puede compilarse y enlazarse con pkg-config(1).

El código descrito aquí usa getenv(3), que se declara no ser seguro para multihilo. Esto significa que el código que llama a estas funciones debe evitar usar setenv(3) desde un hilo paralelo. Se recomienda llamar a setenv() solo desde un punto temprano del programa cuando no se han iniciado otros hilos.

HISTORIA

sd_event_add_signal(), sd_event_signal_handler_t(), y sd_event_source_get_signal() se añadieron en la versión 217.
