DESCRIPCIÓN

sd_bus_add_object_vtable() se utiliza para declarar atributos para la ruta de objeto path conectada a la conexión de bus bus bajo la interfaz interface. La tabla vtable puede contener declaraciones de propiedades utilizando SD_BUS_PROPERTY() o SD_BUS_WRITABLE_PROPERTY(), declaraciones de métodos utilizando SD_BUS_METHOD(), SD_BUS_METHOD_WITH_NAMES(), SD_BUS_METHOD_WITH_OFFSET(), o SD_BUS_METHOD_WITH_NAMES_OFFSET(), y declaraciones de señales utilizando SD_BUS_SIGNAL_WITH_NAMES() o SD_BUS_SIGNAL(), ver abajo. El parámetro userdata contiene un puntero que se pasará a varias funciones de devolución de llamada. Puede especificarse como NULL si no se necesita ningún valor. A una interfaz se le puede adjuntar cualquier número de vtables.

sd_bus_add_fallback_vtable() es similar a sd_bus_add_object_vtable(), pero se utiliza para registrar atributos de "fallback". Al buscar una declaración de atributo, se comprueban primero las rutas de objetos de bus registradas con sd_bus_add_object_vtable(). Si no se encuentra ninguna coincidencia, se comprueban las vtables de fallback para cada prefijo de la ruta del objeto de bus, es decir, se eliminan sucesivamente los últimos componentes separados por barras. Esto permite que la vtable se utilice para un número arbitrario de objetos creados dinámicamente.

El parámetro find es una función que se utiliza para localizar el objeto de destino basándose en la ruta del objeto de bus path. Debe devolver 1 y establecer el parámetro de salida ret_found si se encuentra el objeto, devolver 0 si no se encontró el objeto y devolver un código de error negativo estilo errno o inicializar la estructura de error ret_error en caso de error. El puntero pasado en ret_found se utilizará como parámetro userdata para las funciones de devolución de llamada (con el desplazamiento de los desplazamientos offset tal como se especifica en las entradas de la vtable).

sd_bus_add_object() adjunta una devolución de llamada directamente a la ruta de objeto path. A una ruta de objeto se le puede adjuntar cualquier número de devoluciones de llamada. Cada devolución de llamada se antepone a la lista de devoluciones de llamada que siempre se llaman en orden. sd_bus_add_fallback() es similar a sd_bus_add_object() pero se aplica a rutas de fallback.

sd_bus_add_filter() instala una devolución de llamada que se invoca para cada mensaje D-Bus entrante. Los filtros se pueden utilizar para manejar la lógica común a todos los mensajes recibidos por un servicio (por ejemplo, autenticación o autorización).

Cuando se recibe una solicitud, se llaman secuencialmente las devoluciones de llamada asociadas hasta que una devolución de llamada devuelve un entero distinto de cero. Devuelva cero desde una devolución de llamada para dar a otras devoluciones de llamada la oportunidad de procesar la solicitud. Las devoluciones de llamada se llaman en el siguiente orden: primero, se llaman las devoluciones de llamada globales instaladas con sd_bus_add_filter(). Segundo, se llaman las devoluciones de llamada adjuntas directamente a la ruta del objeto de solicitud, seguidas de las devoluciones de llamada de métodos D-Bus adjuntas a la ruta del objeto de solicitud y al miembro. Finalmente, se llaman las devoluciones de llamada de propiedades adjuntas a la ruta del objeto de solicitud, la interfaz y el miembro. Si la devolución de llamada final devuelve cero, se envía una respuesta de error.

Tenga en cuenta que puede devolver un entero positivo desde una función de devolución de llamada de método sin enviar una respuesta inmediatamente. Esto informa a sd-bus que la función de devolución de llamada asumirá la responsabilidad de responder a la solicitud sin obligar a la función de devolución de llamada a producir una respuesta de inmediato. Esto permite que una función de devolución de llamada realice cualquier operación asíncrona necesaria para construir una respuesta. Sin embargo, si la producción de una respuesta lleva demasiado tiempo, la llamada al método expirará en el llamante. Esto solo está disponible para métodos y no para propiedades.

Si se invocó una función de devolución de llamada para manejar una solicitud que espera una respuesta y la función de devolución de llamada devuelve un valor negativo, el valor se interpreta como un código de error negativo al estilo errno y se envía de vuelta al llamante como un error de D-Bus como si se hubiera llamado a sd_bus_reply_method_errno(3). Además, todas las funciones de devolución de llamada toman un parámetro de salida sd_bus_error que se puede usar para proporcionar información de error más detallada. Si ret_error se establece cuando la función de devolución de llamada finaliza, el error de D-Bus correspondiente se envía de vuelta al llamante como si se hubiera llamado a sd_bus_reply_method_error(3). Cualquier error almacenado en ret_error tiene prioridad sobre cualquier valor negativo devuelto por la misma función de devolución de llamada al determinar qué error enviar de vuelta al llamante. Utilice sd_bus_error_set(3) o una de sus variantes para establecer ret_error y devolver un entero negativo desde una función de devolución de llamada con una única llamada a función. Para enviar una respuesta de error después de que una función de devolución de llamada haya finalizado, utilice sd_bus_reply_method_errno(3) o una de sus variantes.

Para todas las funciones, se crea internamente una ranura de coincidencia. Si el parámetro de salida slot es NULL, se crea un objeto de ranura "flotante", vea sd_bus_slot_set_floating(3). De lo contrario, se devuelve un puntero al objeto de ranura. En ese caso, la referencia al objeto de ranura debe liberarse cuando ya no se necesite la tabla vtable, vea sd_bus_slot_unref(3).

El array sd_bus_vtable

El array consiste en las estructuras de tipo sd_bus_vtable, pero nunca debe llenarse manualmente, sino a través de una de las siguientes macros:

SD_BUS_VTABLE_START(flags), SD_BUS_VTABLE_END

Estos deben ser siempre el primer y el último elemento. El parámetro flags se puede usar para establecer atributos que se aplican a todo el array; vea la sección "Flags" a continuación.

SD_BUS_METHOD_WITH_ARGS_OFFSET(), SD_BUS_METHOD_WITH_ARGS()

Declara un método D-Bus con el nombre member, argumentos args y resultado result. args espera una secuencia de pares de tipo/nombre de argumento envueltos en la macro SD_BUS_ARGS(). Los elementos en los índices pares de esta lista describen los tipos de los argumentos del método. La firma del parámetro del método es la concatenación de todas las literales de cadena en los índices pares de args. Si un método no tiene parámetros, pase SD_BUS_NO_ARGS a args. Los elementos en los índices impares describen los nombres de los argumentos del método. result espera una secuencia de pares de tipo/nombre envueltos en la macro SD_BUS_RESULT() en el mismo formato que SD_BUS_ARGS(). La firma del resultado del método es la concatenación de todas las literales de cadena en los índices pares de result. Si un método no tiene resultado, pase SD_BUS_NO_RESULT a result. Tenga en cuenta que se espera que los tipos de argumento sean literales de cadena entre comillas y los nombres de argumento sean literales de cadena sin comillas. Vea abajo para un ejemplo completo.

La función manejadora handler debe ser de tipo sd_bus_message_handler_t. Se llamará para manejar los mensajes entrantes que llaman a este método. Recibe un puntero que es el parámetro userdata pasado a la función de registro desplazado por offset bytes. Esto puede usarse para pasar punteros a diferentes campos en la misma estructura de datos a diferentes métodos en la misma tabla vtable. Para enviar una respuesta desde handler, llame a sd_bus_reply_method_return(3) con el mensaje con el que se invocó la función de devolución de llamada. El parámetro flags es una combinación de flags.

SD_BUS_METHOD_WITH_ARGS() es un atajo para llamar a SD_BUS_METHOD_WITH_ARGS_OFFSET() con un desplazamiento de cero.

SD_BUS_METHOD_WITH_NAMES_OFFSET(), SD_BUS_METHOD_WITH_NAMES(), SD_BUS_METHOD_WITH_OFFSET(), SD_BUS_METHOD()

Declara un método D-Bus con el nombre member, firma de parámetros signature, firma de resultado result. Los parámetros in_names y out_names especifican los nombres de argumento de los argumentos de entrada y salida en la firma de la función. in_names y out_names deben crearse usando la macro SD_BUS_PARAM(), vea abajo. En todos los demás aspectos, esta macro se comporta exactamente igual que SD_BUS_METHOD_WITH_ARGS_OFFSET().

SD_BUS_METHOD_WITH_NAMES(), SD_BUS_METHOD_WITH_OFFSET() y SD_BUS_METHOD() son variantes que especifican un desplazamiento cero (el parámetro userdata se pasa sin cambios), dejan los nombres sin establecer (es decir, sin nombres de parámetro) o ambos.

Prefiera usar SD_BUS_METHOD_WITH_ARGS_OFFSET() y SD_BUS_METHOD_WITH_ARGS() sobre estas macros, ya que permiten especificar los tipos y nombres de los argumentos uno al lado del otro, lo que es menos propenso a errores que especificar primero todos los tipos de argumentos y luego todos los nombres de argumentos.

SD_BUS_SIGNAL_WITH_ARGS()

Declara una señal D-Bus con el nombre member y argumentos args. args espera una secuencia de pares de tipo/nombre de argumento envueltos en la macro SD_BUS_ARGS(). Los elementos en los índices pares de esta lista describen los tipos de los argumentos de la señal. La firma del parámetro de la señal es la concatenación de todas las literales de cadena en los índices pares de args. Si una señal no tiene parámetros, pase SD_BUS_NO_ARGS a args. Los elementos en los índices impares describen los nombres de los argumentos de la señal. El parámetro flags es una combinación de flags. Vea abajo para un ejemplo completo.

SD_BUS_SIGNAL_WITH_NAMES(), SD_BUS_SIGNAL()

Declara una señal D-Bus con el nombre member, firma de parámetros signature y nombres de argumentos names. names debe crearse usando la macro SD_BUS_PARAM(), vea abajo. El parámetro flags es una combinación de flags, vea abajo.

SD_BUS_SIGNAL() es equivalente a SD_BUS_SIGNAL_WITH_NAMES() con el parámetro names sin establecer (es decir, sin nombres de parámetro).

Prefiera usar SD_BUS_SIGNAL_WITH_ARGS() sobre estas macros, ya que permite especificar los tipos y nombres de los argumentos uno al lado del otro, lo que es menos propenso a errores que especificar primero todos los tipos de argumentos y luego todos los nombres de argumentos.

SD_BUS_WRITABLE_PROPERTY(), SD_BUS_PROPERTY()

Declara una propiedad D-Bus con el nombre member y firma de valor signature. Los parámetros get y set son los métodos de obtención y establecimiento. Se llaman con un puntero que es el parámetro userdata pasado a la función de registro desplazado por offset bytes. Esto se puede usar para pasar punteros a diferentes campos en la misma estructura de datos a diferentes establecedores y obtendedores en la misma tabla vtable. El parámetro flags es una combinación de flags, vea abajo.

Los métodos de establecimiento y obtención pueden omitirse (especificarse como NULL), si la propiedad es uno de los tipos básicos o "as" en caso de propiedades de solo lectura. En esos casos, los parámetros userdata y offset deben apuntar juntos a una variable válida del tipo correspondiente. Se proporcionará un método de establecimiento y obtención predeterminado, que simplemente copia el argumento entre esta variable y el mensaje.

SD_BUS_PROPERTY() se utiliza para definir una propiedad de solo lectura.

SD_BUS_PARAM()

Los nombres de los parámetros deben envolverse en esta macro, vea el ejemplo a continuación.

Flags

El parámetro flags se utiliza para especificar una combinación de anotaciones D-Bus[1].

SD_BUS_VTABLE_DEPRECATED

Marcar esta entrada vtable como obsoleta usando la anotación org.freedesktop.DBus.Deprecated en los datos de introspección. Si se especifica para SD_BUS_VTABLE_START(), la anotación se aplica a la interfaz contenedora.

SD_BUS_VTABLE_HIDDEN

Ocultar esta entrada vtable. No se mostrará en los datos de introspección. Si se especifica para SD_BUS_VTABLE_START(), todas las entradas del array se ocultarán.

SD_BUS_VTABLE_METHOD_NO_REPLY

Marcar esta entrada vtable como un método que no devolverá una respuesta usando la anotación org.freedesktop.DBus.Method.NoReply en los datos de introspección.

SD_BUS_VTABLE_PROPERTY_CONST, SD_BUS_VTABLE_PROPERTY_EMITS_CHANGE, SD_BUS_VTABLE_PROPERTY_EMITS_INVALIDATION

Estas tres flags corresponden a diferentes valores de la anotación org.freedesktop.DBus.Property.EmitsChangedSignal, que especifica si la señal org.freedesktop.DBus.Properties.PropertiesChanged se emite cada vez que cambia la propiedad. SD_BUS_VTABLE_PROPERTY_CONST corresponde a const y significa que la propiedad nunca cambia durante la vida útil del objeto al que pertenece, por lo que no es necesario emitir ninguna señal. SD_BUS_VTABLE_PROPERTY_EMITS_CHANGE corresponde a true y significa que se emite la señal. SD_BUS_VTABLE_PROPERTY_EMITS_INVALIDATION corresponde a invalidates y significa que se emite la señal, pero el valor no se incluye en la señal.

SD_BUS_VTABLE_PROPERTY_EXPLICIT

Marcar esta entrada de propiedad vtable como que requiere una solicitud explícita para que se muestre el valor (generalmente porque el valor es grande o lento de calcular). Esta entrada no se puede combinar con SD_BUS_VTABLE_PROPERTY_EMITS_CHANGE y no se mostrará en las listas de propiedades por defecto (por ejemplo, busctl introspect). Esto corresponde a la anotación org.freedesktop.systemd1.Explicit en los datos de introspección.

SD_BUS_VTABLE_SENSITIVE

Marcar esta entrada de método vtable como que procesa datos sensibles. Cuando se establece, los mensajes de llamada de método entrantes y sus mensajes de respuesta salientes se marcan como sensibles usando sd_bus_message_sensitive(3), de modo que se borran de la memoria cuando se liberan.

SD_BUS_VTABLE_ABSOLUTE_OFFSET

Marcar esta entrada de método o propiedad vtable para que el puntero de datos de usuario pase
El acceso a esta entrada de vtable se permitirá si el proceso que llama tiene la capacidad capability, como se describe en sd_bus_query_sender_privilege(3). Si se usa para SD_BUS_VTABLE_START(), proporciona un valor predeterminado para todas las entradas en el array. Si no se especifica, se verifica por defecto CAP_SYS_ADMIN para cada entrada individual o para el array completo. Véase capabilities(7) para información sobre las capacidades.

Nota: Las entradas de vtable pueden marcarse como no privilegiadas y el bus completo puede marcarse como confiable, véase la discusión sobre SD_BUS_VTABLE_UNPRIVILEGED más abajo.

SD_BUS_VTABLE_UNPRIVILEGED

Marcar esta entrada de vtable como no privilegiada. El acceso a entradas privilegiadas está limitado a usuarios con capacidades adecuadas, como se describe arriba. En la práctica, muchas entradas de vtable se marcan como no privilegiadas, y pueden estar abiertas a todo el mundo o la decisión de permitir el acceso se toma más tarde, por ejemplo, delegando a polkit[2].

El bus completo puede marcarse como confiable, en cuyo caso las anotaciones en el nivel de entrada se ignoran, véase sd_bus_set_trusted(3).

Cuando no se especifica, se mostrará en los datos de introspección la anotación org.freedesktop.systemd1.Privileged con valor "true".

SD_BUS_VTABLE_UNPRIVILEGED no puede aplicarse a propiedades de solo lectura, pero el acceso (a ambos tipos de propiedades) siempre es ilimitado.

Ejemplos

Ejemplo 1. Crear un simple listener en el bus

/* SPDX-License-Identifier: MIT-0 */
#define _GNU_SOURCE 1
#include <errno.h>
#include <stdbool.h>
#include <stddef.h>
#include <stdlib.h>
#include <stdio.h>
#include <systemd/sd-bus.h>
#define _cleanup_(f) __attribute__((cleanup(f)))
typedef struct object {
  char *name;
  uint32_t number;
} object;
static int method(sd_bus_message *m, void *userdata, sd_bus_error *error) {
  int r;
  printf("Got called with userdata=%p\n", userdata);
  if (sd_bus_message_is_method_call(m,
                                    "org.freedesktop.systemd.VtableExample",
                                    "Method4"))
    return 1;
  const char *string;
  r = sd_bus_message_read(m, "s", &string);
  if (r < 0) {
    fprintf(stderr, "sd_bus_message_read() failed: %s\n", strerror(-r));
    return 0;
  }
  r = sd_bus_reply_method_return(m, "s", string);
  if (r < 0) {
    fprintf(stderr, "sd_bus_reply_method_return() failed: %s\n", strerror(-r));
    return 0;
  }
  return 1;
}
static const sd_bus_vtable vtable[] = {
        SD_BUS_VTABLE_START(0),
        SD_BUS_METHOD(
            "Method1", "s", "s", method, 0),
        SD_BUS_METHOD_WITH_NAMES_OFFSET(
            "Method2",
            "so", SD_BUS_PARAM(string) SD_BUS_PARAM(path),
            "s", SD_BUS_PARAM(returnstring),
            method, offsetof(object, number),
            SD_BUS_VTABLE_DEPRECATED),
        SD_BUS_METHOD_WITH_ARGS_OFFSET(
            "Method3",
            SD_BUS_ARGS("s", string, "o", path),
            SD_BUS_RESULT("s", returnstring),
            method, offsetof(object, number),
            SD_BUS_VTABLE_UNPRIVILEGED),
        SD_BUS_METHOD_WITH_ARGS(
            "Method4",
            SD_BUS_NO_ARGS,
            SD_BUS_NO_RESULT,
            method,
            SD_BUS_VTABLE_UNPRIVILEGED),
        SD_BUS_SIGNAL(
            "Signal1",
            "so",
            0),
        SD_BUS_SIGNAL_WITH_NAMES(
            "Signal2",
            "so", SD_BUS_PARAM(string) SD_BUS_PARAM(path),
            0),
        SD_BUS_SIGNAL_WITH_ARGS(
            "Signal3",
            SD_BUS_ARGS("s", string, "o", path),
            0),
        SD_BUS_WRITABLE_PROPERTY(
            "AutomaticStringProperty", "s", NULL, NULL,
            offsetof(object, name),
            SD_BUS_VTABLE_PROPERTY_EMITS_CHANGE),
        SD_BUS_WRITABLE_PROPERTY(
            "AutomaticIntegerProperty", "u", NULL, NULL,
            offsetof(object, number),
            SD_BUS_VTABLE_PROPERTY_EMITS_INVALIDATION),
        SD_BUS_VTABLE_END
};
int main(int argc, char **argv) {
  _cleanup_(sd_bus_flush_close_unrefp) sd_bus *bus = NULL;
  int r;
  sd_bus_default(&bus);
  object object = { .number = 666 };
  object.name = strdup("name");
  if (!object.name) {
    fprintf(stderr, "OOM\n");
    return EXIT_FAILURE;
  }
  r = sd_bus_add_object_vtable(bus, NULL,
                               "/org/freedesktop/systemd/VtableExample",
                               "org.freedesktop.systemd.VtableExample",
                               vtable,
                               &object);
  if (r < 0) {
    fprintf(stderr, "sd_bus_add_object_vtable() failed: %s\n", strerror(-r));
    return EXIT_FAILURE;
  }
  r = sd_bus_request_name(bus,
                          "org.freedesktop.systemd.VtableExample",
                          0);
  if (r < 0) {
    fprintf(stderr, "sd_bus_request_name() failed: %s\n", strerror(-r));
    return EXIT_FAILURE;
  }
  for (;;) {
    r = sd_bus_wait(bus, UINT64_MAX);
    if (r < 0) {
      fprintf(stderr, "sd_bus_wait() failed: %s\n", strerror(-r));
      return EXIT_FAILURE;
    }
    r = sd_bus_process(bus, NULL);
    if (r < 0) {
      fprintf(stderr, "sd_bus_process() failed: %s\n", strerror(-r));
      return EXIT_FAILURE;
    }
  }
  r = sd_bus_release_name(bus, "org.freedesktop.systemd.VtableExample");
  if (r < 0) {
    fprintf(stderr, "sd_bus_release_name() failed: %s\n", strerror(-r));
    return EXIT_FAILURE;
  }
  free(object.name);
  return 0;
}

VALOR DE RETORNO

En éxitos, sd_bus_add_object_vtable() y sd_bus_add_fallback_vtable() devuelven un número no negativo. En errores, devuelven un código de error negativo.

Errores

Los errores devueltos pueden indicar los siguientes problemas:

-EINVAL

Un parámetro requerido es NULL o inválido. Se ha pasado un interfaz D-Bus reservado como el parámetro interface.

-ENOPKG

El bus no puede resolverse.

-ECHILD

El bus fue creado en un proceso, biblioteca o módulo diferente.

-ENOMEM

Falló la asignación de memoria.

-EPROTOTYPE

Se ha llamado a sd_bus_add_object_vtable() y sd_bus_add_fallback_vtable() para el mismo objeto del bus con la misma ruta, lo cual no está permitido.

-EEXIST

Este vtable ya fue registrado para esta interface y path.

These functions implement the D-Bus object model and messaging API. They allow programs to implement D-Bus services, communicate with other D-Bus services, and manage D-Bus names.

RETURN VALUE

NOTES

All functions listed here are thread-safe, but use of getenv(3) is declared to be not thread-safe. This means that the code calling these functions must not call setenv(3) from a parallel thread. It is recommended to only do calls to setenv() from an early phase of the program when no other threads have been started.
