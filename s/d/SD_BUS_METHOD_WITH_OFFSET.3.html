DESCRIPCIÓN

sd_bus_add_object_vtable() se utiliza para declarar atributos para la ruta de objeto path conectada a la conexión de bus bus bajo la interfaz interface. La tabla vtable puede contener declaraciones de propiedad usando SD_BUS_PROPERTY() o SD_BUS_WRITABLE_PROPERTY(), declaraciones de método usando SD_BUS_METHOD(), SD_BUS_METHOD_WITH_NAMES(), SD_BUS_METHOD_WITH_OFFSET() o SD_BUS_METHOD_WITH_NAMES_OFFSET(), y declaraciones de señal usando SD_BUS_SIGNAL_WITH_NAMES() o SD_BUS_SIGNAL(), véase a continuación. El parámetro userdata contiene un puntero que se pasará a varias funciones de callback. Puede especificarse como NULL si no se necesita un valor. Una interfaz puede tener cualquier número de vtables asociadas a ella.

sd_bus_add_fallback_vtable() es similar a sd_bus_add_object_vtable(), pero se utiliza para registrar atributos de "vuelta" (fallback). Cuando se busca una declaración de atributo, las rutas de objeto registradas con sd_bus_add_object_vtable() se analizan primero. Si no se encuentra una coincidencia, se analizan las vtables de respaldo para cada prefijo de la ruta de objeto del bus, es decir, se eliminan sucesivamente los componentes de la ruta separada por puntos. Esto permite que el vtable se use para objetos dinámicamente creados en cualquier número.

El parámetro find es una función que se utiliza para localizar el objeto objetivo basado en la ruta de objeto del bus path. Debe devolver 1 y establecer el parámetro de salida ret_found si el objeto se encuentra, devolver 0 si no se encuentra y devolver un código de error errno-style o inicializar el estructura de error ret_error en caso de error. El puntero pasado en ret_found se utilizará como el parámetro userdata para las funciones de callback (offseteado según los offsetes especificados en las entradas de vtable).

sd_bus_add_object() adjunta un callback directamente a la ruta de objeto path. Una ruta de objeto puede tener cualquier número de callbacks asociados. Cada callback se prepone a la lista de callbacks que siempre se llaman en orden. sd_bus_add_fallback() es similar a sd_bus_add_object() pero aplica a rutas de "vuelta".

sd_bus_add_filter() instala un callback que se llama para cada mensaje de D-Bus que entra. Los filtros se pueden usar para manejar lógica común a todos los mensajes recibidos por un servicio (por ejemplo, autenticación o autorización).

Cuando se recibe una solicitud, cualquier callback asociado se llama secuencial
