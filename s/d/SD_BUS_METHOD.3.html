DESCRIPCIÓN

sd_bus_add_object_vtable() se utiliza para declarar atributos para la ruta de objeto path conectada a la conexión de bus bus bajo la interfaz interface. La tabla vtable puede contener declaraciones de propiedades usando SD_BUS_PROPERTY() o SD_BUS_WRITABLE_PROPERTY(), declaraciones de métodos usando SD_BUS_METHOD(), SD_BUS_METHOD_WITH_NAMES(), SD_BUS_METHOD_WITH_OFFSET(), o SD_BUS_METHOD_WITH_NAMES_OFFSET(), y declaraciones de señales usando SD_BUS_SIGNAL_WITH_NAMES() o SD_BUS_SIGNAL(), ver abajo. El parámetro userdata contiene un puntero que se pasará a varias funciones de devolución de llamada. Puede especificarse como NULL si no se necesita ningún valor. Una interfaz puede tener cualquier número de vtables adjuntas a ella.

sd_bus_add_fallback_vtable() es similar a sd_bus_add_object_vtable(), pero se utiliza para registrar atributos de "fallback". Al buscar una declaración de atributo, se comprueban primero las rutas de objetos de bus registradas con sd_bus_add_object_vtable(). Si no se encuentra ninguna coincidencia, se comprueban las vtables de fallback para cada prefijo de la ruta del objeto de bus, es decir, eliminando sucesivamente los últimos componentes separados por barras. Esto permite que la vtable se utilice para un número arbitrario de objetos creados dinámicamente.

El parámetro find es una función que se utiliza para localizar el objeto de destino basándose en la ruta del objeto de bus path. Debe devolver 1 y establecer el parámetro de salida ret_found si se encuentra el objeto, devolver 0 si no se encontró el objeto, y devolver un código de error negativo estilo errno o inicializar la estructura de error ret_error en caso de error. El puntero pasado en ret_found se utilizará como parámetro userdata para las funciones de devolución de llamada (desplazado por los desplazamientos offset según lo especificado en las entradas de la vtable).

sd_bus_add_object() adjunta una devolución de llamada directamente a la ruta de objeto path. Una ruta de objeto puede tener cualquier número de devoluciones de llamada adjuntas a ella. Cada devolución de llamada se antepone a la lista de devoluciones de llamada que siempre se llaman en orden. sd_bus_add_fallback() es similar a sd_bus_add_object() pero se aplica a rutas de fallback en su lugar.

sd_bus_add_filter() instala una devolución de llamada que se invoca para cada mensaje D-Bus entrante. Los filtros se pueden utilizar para manejar lógica común a todos los mensajes recibidos por un servicio (por ejemplo, autenticación o autorización).

Cuando se recibe una solicitud, se llaman secuencialmente las devoluciones de llamada asociadas hasta que una devolución de llamada devuelve un entero distinto de cero. Devuelva cero desde una devolución de llamada para dar a otras devoluciones de llamada la oportunidad de procesar la solicitud. Las devoluciones de llamada se llaman en el siguiente orden: primero, se llaman las devoluciones de llamada globales instaladas con sd_bus_add_filter(). Segundo, se llaman las devoluciones de llamada adjuntas directamente a la ruta del objeto de solicitud, seguidas de las devoluciones de llamada de métodos D-Bus adjuntas a la ruta del objeto de solicitud, interfaz y miembro. Finalmente, se llaman las devoluciones de propiedad adjuntas a la ruta del objeto de solicitud, interfaz y miembro. Si la devolución de llamada final devuelve cero, se envía una respuesta de error

Tenga en cuenta que puede devolver un entero positivo desde una función de devolución de llamada de método sin enviar una respuesta inmediatamente. Esto informa a sd-bus que la función de devolución de llamada se hará responsable de responder a la solicitud sin forzar a la función de devolución de llamada a producir una respuesta de inmediato. Esto permite que una función de devolución de llamada realice cualquier número de operaciones asíncronas necesarias para construir una respuesta. Sin embargo, si la producción de una respuesta lleva demasiado tiempo, la llamada al método expirará en el llamador. Esto solo está disponible para métodos y no para propiedades.

Si se invocó una función de devolución de llamada para manejar una solicitud que espera una respuesta y la función de devolución de llamada devuelve un valor negativo, el valor se interpreta como un código de error negativo estilo errno y se envía de vuelta al llamador como un error de D-Bus como si se hubiera llamado a sd_bus_reply_method_errno(3). Además, todas las funciones de devolución de llamada toman un parámetro de salida sd_bus_error que se puede usar para proporcionar información de error más detallada. Si ret_error se establece cuando la función de devolución de llamada finaliza, el error de D-Bus correspondiente se envía de vuelta al llamador como si se hubiera llamado a sd_bus_reply_method_error(3). Cualquier error almacenado en ret_error tiene prioridad sobre cualquier valor negativo devuelto por la misma función de devolución de llamada al determinar qué error enviar de vuelta al llamador. Utilice sd_bus_error_set(3) o una de sus variantes para establecer ret_error y devolver un entero negativo desde una función de devolución de llamada con una sola llamada a función. Para enviar una respuesta de error después de que una función de devolución de llamada haya finalizado, utilice sd_bus_reply_method_errno(3) o una de sus variantes.

Para todas las funciones, se crea internamente una ranura de coincidencia. Si el parámetro de salida slot es NULL, se crea un objeto de ranura "flotante", consulte sd_bus_slot_set_floating(3). De lo contrario, se devuelve un puntero al objeto de ranura. En ese caso, la referencia al objeto de ranura debe liberarse cuando la vtable ya no sea necesaria, consulte sd_bus_slot_unref(3).

El array sd_bus_vtable

El array consta de estructuras de tipo sd_bus_vtable, pero nunca debe rellenarse manualmente, sino a través de una de las siguientes macros:

SD_BUS_VTABLE_START(flags), SD_BUS_VTABLE_END

Estos deben ser siempre el primer y último elemento. El parámetro flags se puede utilizar para establecer atributos que se aplican a todo el array; consulte la sección "Flags" a continuación.

SD_BUS_METHOD_WITH_ARGS_OFFSET(), SD_BUS_METHOD_WITH_ARGS()

Declara un método D-Bus con el nombre member, argumentos args y resultado result. args espera una secuencia de pares tipo/nombre de argumento encapsulados en la macro SD_BUS_ARGS(). Los elementos en índices pares en esta lista describen los tipos de los argumentos del método. La firma del parámetro del método es la concatenación de todos los literales de cadena en los índices pares de args. Si un método no tiene parámetros, pase SD_BUS_NO_ARGS a args. Los elementos en índices impares describen los nombres de los argumentos del método. result espera una secuencia de pares tipo/nombre encapsulados en la macro SD_BUS_RESULT() en el mismo formato que SD_BUS_ARGS(). La firma del resultado del método es la concatenación de todos los literales de cadena en los índices pares de result. Si un método no tiene resultado, pase SD_BUS_NO_RESULT a result. Tenga en cuenta que se espera que los tipos de argumento sean literales de cadena entre comillas y los nombres de argumento se espera que sean literales de cadena sin comillas. La función de manejo handler debe ser de tipo sd_bus_message_handler_t. Se llamará para manejar los mensajes entrantes que llamen a este método. Recibe un puntero que es el parámetro userdata pasado a la función de registro compensado por offset bytes. Esto se puede utilizar para pasar punteros a diferentes campos en la misma estructura de datos a diferentes métodos en la misma vtable. Para enviar una respuesta desde handler, llame a sd_bus_reply_method_return(3) con el mensaje con el que se invocó la función de devolución de llamada. El parámetro flags es una combinación de flags.

SD_BUS_METHOD_WITH_ARGS() es una abreviatura para llamar a SD_BUS_METHOD_WITH_ARGS_OFFSET() con un desplazamiento de cero.

SD_BUS_METHOD_WITH_NAMES_OFFSET(), SD_BUS_METHOD_WITH_NAMES(), SD_BUS_METHOD_WITH_OFFSET(), SD_BUS_METHOD()

Declara un método D-Bus con el nombre member, firma de parámetros signature, firma de resultado result. Los parámetros in_names y out_names especifican los nombres de los argumentos de entrada y salida en la firma de la función. in_names y out_names deben crearse usando la macro SD_BUS_PARAM(), consulte a continuación. En todos los demás aspectos, esta macro se comporta exactamente igual que SD_BUS_METHOD_WITH_ARGS_OFFSET().

SD_BUS_METHOD_WITH_NAMES(), SD_BUS_METHOD_WITH_OFFSET() y SD_BUS_METHOD() son variantes que especifican un desplazamiento cero (el parámetro userdata se pasa sin cambios), dejan los nombres sin establecer (es decir, sin nombres de parámetro), o ambos.

Prefiera usar SD_BUS_METHOD_WITH_ARGS_OFFSET() y SD_BUS_METHOD_WITH_ARGS() sobre estas macros, ya que permiten especificar los tipos y nombres de los argumentos uno al lado del otro, lo que es menos propenso a errores que primero especificar todos los tipos de argumentos seguido de la especificación de todos los nombres de argumentos.

SD_BUS_SIGNAL_WITH_NAMES(), SD_BUS_SIGNAL()

Declara una señal D-Bus con el nombre member, firma de parámetros signature y nombres de argumentos names. names debe crearse usando la macro SD_BUS_PARAM(), consulte a continuación. El parámetro flags es una combinación de flags, consulte a continuación.

SD_BUS_WRITABLE_PROPERTY(), SD_BUS_PROPERTY()

Declara una propiedad D-Bus con el nombre member y firma de valor signature. Los parámetros get y set son los métodos de obtención y establecimiento. Se llaman con un puntero que es el parámetro userdata pasado a la función de registro compensado por offset bytes. Esto puede usarse para pasar punteros a diferentes campos en la misma estructura de datos a diferentes configuradores y obtentores en la misma vtable. El parámetro flags es una combinación de flags, consulte a continuación.

El configurador y el obtentor pueden omitirse (especificarse como NULL), si la propiedad es de uno de los tipos básicos o "as" en caso de propiedades de solo lectura. En esos casos, los parámetros userdata y offset deben apuntar juntos a una variable válida del tipo correspondiente. Se proporcionará un configurador y obtentor predeterminados, que simplemente copian el argumento entre esta variable y el mensaje.

SD_BUS_PROPERTY() se utiliza para definir una propiedad de solo lectura.

Los nombres de los parámetros deben encapsularse en esta macro, consulte el ejemplo a continuación.

Flags

El parámetro flags se utiliza para especificar una combinación de **Anotaciones D-Bus**[1].

SD_BUS_VTABLE_DEPRECATED

Marca esta entrada de vtable como obsoleta usando la anotación org.freedesktop.DBus.Deprecated en los datos de introspección. Si se especifica para SD_BUS_VTABLE_START(), la anotación se aplica a la interfaz envolvente.

SD_BUS_VTABLE_HIDDEN

Oculta esta entrada de vtable. No se mostrará en los datos de introspección. Si se especifica para SD_BUS_VTABLE_START(), todas las entradas del array se ocultan.

SD_BUS_VTABLE_METHOD_NO_REPLY

Marca esta entrada de vtable como un método que no devolverá una respuesta usando la anotación org.freedesktop.DBus.Method.NoReply en los datos de introspección.

SD_BUS_VTABLE_PROPERTY_CONST, SD_BUS_VTABLE_PROPERTY_EMITS_CHANGE, SD_BUS_VTABLE_PROPERTY_EMITS_INVALIDATION

Estos tres flags corresponden a diferentes valores de la anotación org.freedesktop.DBus.Property.EmitsChangedSignal, que especifica si la señal org.freedesktop.DBus.Properties.PropertiesChanged se emite cada vez que la propiedad cambia. SD_BUS_VTABLE_PROPERTY_CONST corresponde a const y significa que la propiedad nunca cambia durante la vida útil del objeto al que pertenece, por lo que no es necesario emitir ninguna señal. SD_BUS_VTABLE_PROPERTY_EMITS_CHANGE corresponde a true y significa que se emite la señal. SD_BUS_VTABLE_PROPERTY_EMITS_INVALIDATION corresponde a invalidates y significa que se emite la señal, pero el valor no se incluye en la señal.

SD_BUS_VTABLE_PROPERTY_EXPLICIT

Marca esta entrada de propiedad vtable como que requiere una solicitud explícita para que se muestre el valor (generalmente porque el valor es grande o lento de calcular). Esta entrada no se puede combinar con SD_BUS_VTABLE_PROPERTY_EMITS_CHANGE, y no se mostrará en las listas de propiedades por defecto (por ejemplo, busctl introspect). Corresponde a la anotación org.freedesktop.systemd1.Explicit en los datos de introspección.

SD_BUS_VTABLE_SENSITIVE

Marca esta entrada de método vtable como que procesa datos sensibles. Cuando se establece, los mensajes de llamada de método entrantes y sus mensajes de respuesta salientes se marcan como sensibles usando sd_bus_message_sensitive(3), para que se borren de la memoria cuando se liberan.

SD_BUS_VTABLE_ABSOLUTE_OFFSET

DESCRIPTION

The vtable-based API for registering object methods and properties is designed to be simpler than the traditional method handler registration. The vtable is an array of sd_bus_vtable structures. Each structure describes a single D-Bus method, signal, or property, and how it is implemented. The array must be terminated with a special sentinel entry, SD_BUS_VTABLE_END.

The members of the sd_bus_vtable structure are set using specific macros. See sd-bus.h(3) for the precise definition of the structure.

Available Macros

SD_BUS_VTABLE_START(flags)

This macro initializes the vtable array. It should be the first entry. The flags parameter is unused and should be set to 0.

SD_BUS_VTABLE_END

This macro terminates the vtable array. It should be the last entry.

SD_BUS_METHOD(name, args, reply, func, flags)

Registers a method implementation.
name
The name of the D-Bus method.
args
A string describing the argument types, or SD_BUS_NO_ARGS.
reply
A string describing the reply types, or SD_BUS_NO_RESULT.
func
The handler function pointer. It must be of type int (*func)(sd_bus_message *m, void *userdata, sd_bus_error *error).
flags
A combination of SD_BUS_VTABLE_* flags. Currently, only SD_BUS_VTABLE_DEPRECATED and SD_BUS_VTABLE_UNPRIVILEGED are recognized.
See also SD_BUS_METHOD_WITH_OFFSET(), SD_BUS_METHOD_WITH_NAMES(), and SD_BUS_METHOD_WITH_ARGS().

SD_BUS_METHOD_WITH_OFFSET(name, args, reply, func, offset, flags)

Same as SD_BUS_METHOD(), but the handler function func will be called with the user data pointer adjusted by offset. The user data pointer is the pointer passed to sd_bus_add_object_vtable() or sd_bus_add_fallback_vtable().

SD_BUS_METHOD_WITH_NAMES(name, args, arg_names, reply, reply_names, func, flags)

Same as SD_BUS_METHOD(), but allows specifying names for arguments and return values.
arg_names
A comma-separated list of argument names, or SD_BUS_NO_ARGS.
reply_names
A comma-separated list of return value names, or SD_BUS_NO_RESULT.
Argument names are useful for introspection and for calling methods using keyword arguments. Use the macros SD_BUS_PARAM() and SD_BUS_RESULT() to construct the argument and result name lists.

SD_BUS_METHOD_WITH_NAMES_OFFSET(name, args, arg_names, reply, reply_names, func, offset, flags)

Combines the functionality of SD_BUS_METHOD_WITH_NAMES() and SD_BUS_METHOD_WITH_OFFSET().

SD_BUS_METHOD_WITH_ARGS(name, args, reply, func, flags)

Same as SD_BUS_METHOD(), but takes arguments for argument and return value names directly.

SD_BUS_METHOD_WITH_ARGS_OFFSET(name, args, reply, func, offset, flags)

Combines the functionality of SD_BUS_METHOD_WITH_ARGS() and SD_BUS_METHOD_WITH_OFFSET().

SD_BUS_SIGNAL(name, args, flags)

Declares a signal. This entry itself does not implement the signal emission; it just declares the signal's existence and signature for introspection. Use sd_bus_emit_signal() or related functions to emit the signal.
name
The name of the D-Bus signal.
args
A string describing the argument types, or SD_BUS_NO_ARGS.
flags
A combination of SD_BUS_VTABLE_* flags. Currently, only SD_BUS_VTABLE_DEPRECATED is recognized.
See also SD_BUS_SIGNAL_WITH_NAMES() and SD_BUS_SIGNAL_WITH_ARGS().

SD_BUS_SIGNAL_WITH_NAMES(name, args, arg_names, flags)

Same as SD_BUS_SIGNAL(), but allows specifying names for arguments.

SD_BUS_SIGNAL_WITH_ARGS(name, args, flags)

Same as SD_BUS_SIGNAL(), but takes arguments for argument names directly.

SD_BUS_WRITABLE_PROPERTY(name, type, get_func, set_func, offset, flags)

Declares a writable property.
name
The name of the property.
type
The D-Bus type string of the property.
get_func
The handler function pointer for reading the property. It must be of type int (*get_func)(sd_bus_message *m, void *userdata, sd_bus_error *error). If NULL, the property is read from the memory at offset. Can be SD_BUS_PROPERTY_GET to use the default get implementation, see sd-bus.h(3). Can be SD_BUS_PROPERTY_GET_UNPRIVILEGED to use the default get implementation and mark the property as unprivileged.
set_func
The handler function pointer for writing the property. It must be of type int (*set_func)(sd_bus_message *m, void *userdata, sd_bus_error *error). If NULL, the property is written to the memory at offset. Can be SD_BUS_PROPERTY_SET to use the default set implementation, see sd-bus.h(3).
offset
The offset of the property in the user data structure. This is only used when get_func and set_func are NULL or SD_BUS_PROPERTY_GET. Note that when get_func is SD_BUS_PROPERTY_GET and set_func is SD_BUS_PROPERTY_SET, the offset is used to find the member within the structure passed as userdata.
flags
A combination of SD_BUS_VTABLE_* flags. Recognized flags include SD_BUS_VTABLE_PROPERTY_EMITS_CHANGE, SD_BUS_VTABLE_PROPERTY_EMITS_INVALIDATION, SD_BUS_VTABLE_DEPRECATED, and SD_BUS_VTABLE_UNPRIVILEGED.
See also SD_BUS_READONLY_PROPERTY(), SD_BUS_WRITABLE_PROPERTY_WITH_NAMES(), and SD_BUS_WRITABLE_PROPERTY_WITH_ARGS().

SD_BUS_READONLY_PROPERTY(name, type, get_func, offset, flags)

Declares a read-only property. It is a shorthand for SD_BUS_WRITABLE_PROPERTY() where set_func is NULL.

SD_BUS_WRITABLE_PROPERTY_WITH_NAMES(name, type, args, arg_names, reply, reply_names, get_func, set_func, offset, flags)

Same as SD_BUS_WRITABLE_PROPERTY(), but allows specifying names for arguments and return values. This is mostly useful when get_func or set_func are not NULL.

SD_BUS_READONLY_PROPERTY_WITH_NAMES(name, type, args, arg_names, reply, reply_names, get_func, offset, flags)

Same as SD_BUS_READONLY_PROPERTY(), but allows specifying names for arguments and return values.

SD_BUS_WRITABLE_PROPERTY_WITH_ARGS(name, type, args, reply, get_func, set_func, offset, flags)

Same as SD_BUS_WRITABLE_PROPERTY(), but takes arguments for argument and return value names directly.

SD_BUS_READONLY_PROPERTY_WITH_ARGS(name, type, args, reply, get_func, offset, flags)

Same as SD_BUS_READONLY_PROPERTY(), but takes arguments for argument and return value names directly.

SD_BUS_PROPERTY_GET(...)

Macro used for the get_func argument of SD_BUS_WRITABLE_PROPERTY() and similar macros. It selects the default implementation for getting a property's value from the memory location specified by offset. The arguments are the same as for SD_BUS_METHOD().

SD_BUS_PROPERTY_GET_UNPRIVILEGED(...)

Similar to SD_BUS_PROPERTY_GET(), but marks the property as unprivileged.

SD_BUS_PROPERTY_SET(...)

Macro used for the set_func argument of SD_BUS_WRITABLE_PROPERTY() and similar macros. It selects the default implementation for setting a property's value to the memory location specified by offset. The arguments are the same as for SD_BUS_METHOD().

SD_BUS_PARAM(name)

Helper macro to construct argument name lists for SD_BUS_METHOD_WITH_NAMES(), SD_BUS_SIGNAL_WITH_NAMES(), and SD_BUS_WRITABLE_PROPERTY_WITH_NAMES().

SD_BUS_RESULT(name)

Helper macro to construct return value name lists for SD_BUS_METHOD_WITH_NAMES().

SD_BUS_ARGS(type, name, ...)

Helper macro to construct argument lists for SD_BUS_METHOD_WITH_ARGS(), SD_BUS_SIGNAL_WITH_ARGS(), and SD_BUS_WRITABLE_PROPERTY_WITH_ARGS().

SD_BUS_NO_ARGS

Used instead of an argument type string when a method or signal takes no arguments.

SD_BUS_NO_RESULT

Used instead of a result type string when a method does not return any values.

SD_BUS_VTABLE_DEPRECATED

Marks the vtable entry as deprecated. This will be reflected in the introspection data.

SD_BUS_VTABLE_CAPABILITY(capability)

Access to this vtable entry will be allowed if the calling process has the capability capability, as described in sd_bus_query_sender_privilege(3). If used for SD_BUS_VTABLE_START(), provides a default for all entries in the array. If not specified, either for an individual entry or the whole array, CAP_SYS_ADMIN is checked by default. See capabilities(7) for information about capabilities.

Note that vtable entries may be marked as unprivileged and the whole bus may be marked as trusted, see the discussion of SD_BUS_VTABLE_UNPRIVILEGED below.

SD_BUS_VTABLE_UNPRIVILEGED

Mark this vtable entry as unprivileged. Access to privileged entries is limited to users with appropriate capabilities as described above. In practice many vtable entries are marked as unprivileged, and either are open to everyone, or the decision whether to allow access is taken later, e.g. by delegating to polkit[2].

The whole bus may be marked as trusted, in which case annotations at the entry level are ignored, see sd_bus_set_trusted(3).

When not specified, the org.freedesktop.systemd1.Privileged annotation with value "true" will be shown in introspection data.

SD_BUS_VTABLE_UNPRIVILEGED may not be applied to read-only properties, but read access (to both read-only and writable properties) is always unrestricted.

Note that this page describes checks implemented in the D-Bus client. The D-Bus server has an additional policy that may permit or deny connections, see "CONFIGURATION FILE" in dbus-daemon(1).

Example 1. Create a simple listener on the bus

/* SPDX-License-Identifier: MIT-0 */
#define _GNU_SOURCE 1
#include <errno.h>
#include <stdbool.h>
#include <stddef.h>
#include <stdlib.h>
#include <stdio.h>
#include <systemd/sd-bus.h>
#define _cleanup_(f) __attribute__((cleanup(f)))
typedef struct object {
  char *name;
  uint32_t number;
} object;
static int method(sd_bus_message *m, void *userdata, sd_bus_error *error) {
  int r;
  printf("Got called with userdata=%p\n", userdata);
  if (sd_bus_message_is_method_call(m,
                                    "org.freedesktop.systemd.VtableExample",
                                    "Method4"))
    return 1;
  const char *string;
  r = sd_bus_message_read(m, "s", &string);
  if (r < 0) {
    fprintf(stderr, "sd_bus_message_read() failed: %s\n", strerror(-r));
    return 0;
  }
  r = sd_bus_reply_method_return(m, "s", string);
  if (r < 0) {
    fprintf(stderr, "sd_bus_reply_method_return() failed: %s\n", strerror(-r));
    return 0;
  }
  return 1;
}
static const sd_bus_vtable vtable[] = {
        SD_BUS_VTABLE_START(0),
        SD_BUS_METHOD(
            "Method1", "s", "s", method, 0),
        SD_BUS_METHOD_WITH_NAMES_OFFSET(
            "Method2",
            "so", SD_BUS_PARAM(string) SD_BUS_PARAM(path),
            "s", SD_BUS_PARAM(returnstring),
            method, offsetof(object, number),
            SD_BUS_VTABLE_DEPRECATED),
        SD_BUS_METHOD_WITH_ARGS_OFFSET(
            "Method3",
            SD_BUS_ARGS("s", string, "o", path),
            SD_BUS_RESULT("s", returnstring),
            method, offsetof(object, number),
            SD_BUS_VTABLE_UNPRIVILEGED),
        SD_BUS_METHOD_WITH_ARGS(
            "Method4",
            SD_BUS_NO_ARGS,
            SD_BUS_NO_RESULT,
            method,
            SD_BUS_VTABLE_UNPRIVILEGED),
        SD_BUS_SIGNAL(
            "Signal1",
            "so",
            0),
        SD_BUS_SIGNAL_WITH_NAMES(
            "Signal2",
            "so", SD_BUS_PARAM(string) SD_BUS_PARAM(path),
            0),
        SD_BUS_SIGNAL_WITH_ARGS(
            "Signal3",
            SD_BUS_ARGS("s", string, "o", path),
            0),
        SD_BUS_WRITABLE_PROPERTY(
            "AutomaticStringProperty", "s", NULL, NULL,
            offsetof(object, name),
            SD_BUS_VTABLE_PROPERTY_EMITS_CHANGE),
        SD_BUS_WRITABLE_PROPERTY(
            "AutomaticIntegerProperty", "u", NULL, NULL,
            offsetof(object, number),
            SD_BUS_VTABLE_PROPERTY_EMITS_INVALIDATION),
        SD_BUS_VTABLE_END
};
int main(int argc, char **argv) {
  _cleanup_(sd_bus_flush_close_unrefp) sd_bus *bus = NULL;
  int r;
  sd_bus_default(&bus);
  object object = { .number = 666 };
  object.name = strdup("name");
  if (!object.name) {
    fprintf(stderr, "OOM\n");
    return EXIT_FAILURE;
  }
  r = sd_bus_add_object_vtable(bus, NULL,
                               "/org/freedesktop/systemd/VtableExample",
                               "org.freedesktop.systemd.VtableExample",
                               vtable,
                               &object);
  if (r < 0) {
    fprintf(stderr, "sd_bus_add_object_vtable() failed: %s\n", strerror(-r));
    return EXIT_FAILURE;
  }
  r = sd_bus_request_name(bus,
                          "org.freedesktop.systemd.VtableExample",
                          0);
  if (r < 0) {
    fprintf(stderr, "sd_bus_request_name() failed: %s\n", strerror(-r));
    return EXIT_FAILURE;
  }
  for (;;) {
    r = sd_bus_wait(bus, UINT64_MAX);
    if (r < 0) {
      fprintf(stderr, "sd_bus_wait() failed: %s\n", strerror(-r));
      return EXIT_FAILURE;
    }
    r = sd_bus_process(bus, NULL);
    if (r < 0) {
      fprintf(stderr, "sd_bus_process() failed: %s\n", strerror(-r));
      return EXIT_FAILURE;
    }
  }
  r = sd_bus_release_name(bus, "org.freedesktop.systemd.VtableExample");
  if (r < 0) {
    fprintf(stderr, "sd_bus_release_name() failed: %s\n", strerror(-r));
    return EXIT_FAILURE;
  }
  free(object.name);
  return 0;
}

RETURN VALUE

On success, sd_bus_add_object_vtable() and sd_bus_add_fallback_vtable() return a non-negative integer. On failure, they return a negative errno-style error code.

Errors

Returned errors may indicate the following problems:

-EINVAL

One of the required parameters is NULL or invalid. A reserved D-Bus interface was passed as the interface parameter.

-ENOPKG

The bus cannot be resolved.

-ECHILD

The bus was created in a different process, library or module instance.

-ENOMEM

Memory allocation failed.

-EPROTOTYPE

sd_bus_add_object_vtable() and sd_bus_add_fallback_vtable() have been both called for the same bus object path, which is not allowed.

-EEXIST

This vtable has already been registered for this interface and path.
