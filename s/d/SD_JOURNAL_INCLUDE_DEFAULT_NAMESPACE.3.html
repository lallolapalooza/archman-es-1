SD_JOURNAL_OPEN(3) sd_journal_open SD_JOURNAL_OPEN(3)

NAME

sd_journal_open, sd_journal_open_directory, sd_journal_open_directory_fd, sd_journal_open_files, sd_journal_open_files_fd, sd_journal_open_namespace, sd_journal_close, sd_journal, SD_JOURNAL_LOCAL_ONLY, SD_JOURNAL_RUNTIME_ONLY, SD_JOURNAL_SYSTEM, SD_JOURNAL_CURRENT_USER, SD_JOURNAL_OS_ROOT, SD_JOURNAL_ALL_NAMESPACES, SD_JOURNAL_INCLUDE_DEFAULT_NAMESPACE, SD_JOURNAL_TAKE_DIRECTORY_FD - Abrir el sistema journal para lectura

SYNOPSIS

#include <systemd/sd-journal.h>

int sd_journal_open(sd_journal **ret, int flags);

int sd_journal_open_namespace(sd_journal **ret, const char *namespace, int flags);

int sd_journal_open_directory(sd_journal **ret, const char *path, int flags);

int sd_journal_open_directory_fd(sd_journal **ret, int fd, int flags);

int sd_journal_open_files(sd_journal **ret, const char **paths, int flags);

int sd_journal_open_files_fd(sd_journal **ret, int fds[], unsigned n_fds, int flags);

void sd_journal_close(sd_journal *j);

DESCRIPTION

sd_journal_open() abre el journal de sistema para lectura. Buscará automáticamente todos los archivos de journal y los intercalará automáticamente al lecturar. El primer argumento toma un puntero a un sd_journal pointer, que, en caso de éxito, contendrá un objeto de contexto de journal. El segundo argumento es un campo de flags, que puede consistir en los siguientes flags ORados: SD_JOURNAL_LOCAL_ONLY asegura que solo se abran los archivos de journal generados en el propio equipo. SD_JOURNAL_RUNTIME_ONLY asegura que solo se abran los archivos de journal volátiles, excluyendo aquellos almacenados en almacenamiento persistente. SD_JOURNAL_SYSTEM hará que se abran los archivos de journal de servicios de sistema y el kernel (en contraste con los procesos de usuario). SD_JOURNAL_CURRENT_USER hará que se abran los archivos de journal del usuario actual. Si no se especifica SD_JOURNAL_SYSTEM ni SD_JOURNAL_CURRENT_USER, se abrirán todos los tipos de archivos de journal.

sd_journal_open_namespace() es similar a sd_journal_open(), pero toma un parámetro adicional namespace que especifica qué espacio de nombre a operar. Si se especifica como NULL, la llamada es idéntica a sd_journal_open(). Si no se especifica NULL, solo se accederá a los datos del espacio de nombre especificado. Esta llamada entiende dos flags adicionales: si se especifica SD_JOURNAL_ALL_NAMESPACES, el parámetro namespace se ignora y se accederá a todos los espacios de nombre definidos simultáneamente; si se especifica SD_JOURNAL_INCLUDE_DEFAULT_NAMESPACE, el espacio de nombre especificado y el espaciode nombre por defecto se accederán, pero no otros (este flag no tiene efecto cuando namespace se pasa como NULL). Para detalles sobre los espacios de nombre de journal, ve systemd-journald.service(8).

sd_journal_open_directory() es similar a sd_journal_open(), pero toma un camino de directorio absoluto como argumento. Todos los archivos de journal en este directorio se abrirán y se intercalarán automáticamente. Esta llamada también toma un argumento de flags. Los parámetros de flags aceptados por esta llamada son SD_JOURNAL_OS_ROOT, SD_JOURNAL_SYSTEM y SD_JOURNAL_CURRENT_USER. Si SD_JOURNAL_OS_ROOT se especifica, los archivos de journal se buscan bajo la ruta usual /var/log/journal y /run/log/journal, en lugar de directamente debajo de la ruta especificada. Los otros dos flags limitan qué archivos se abren, lo mismo que en sd_journal_open().

sd_journal_open_directory_fd() es similar a sd_journal_open_directory(), pero toma una referencia a un directorio en el sistema de archivos como argumento en lugar de una ruta de sistema absoluta. Además de los flags aceptados por sd_journal_open_directory(), esta función también acepta SD_JOURNAL_TAKE_DIRECTORY_FD. Si SD_JOURNAL_TAKE_DIRECTORY_FD se especifica, la función tomará propiedad del archivo descriptor especificado con éxito, y será cerrado por sd_journal_close(), por lo que el llamador del función no debe cerrar el archivo descriptor. Cuando el flag no está especificado, sd_journal_close() no cerrará el descriptor, por lo que el llamador debe cerrarlo después de sd_journal_close().

sd_journal_open_files() es similar a sd_journal_open(), pero toma un listado de rutas de archivos terminado en NULL para abrir. Todos los archivos se abrirán y se intercalarán automáticamente. Esta llamada también toma un argumento de flags, pero debe pasarse como 0 ya que no se entienden los flags en esta llamada. Por favor, notar que en el caso de un journal vivo, esta función es solo útil para depuración, ya que los archivos de journal individuales pueden ser rotados en cualquier momento y la apertura de archivos específicos es inherentemente racia.

sd_journal_open_files_fd() es similar a sd_journal_open_files(), pero toma un array de descriptores de archivo que deben referir a archivos de journal, en lugar de un array de rutas de sistema. Pasar el array de descriptores como segundo argumento, y el número de entradas del array en el tercer argumento. El parámetro de flags debe pasar como 0.

Objetos de sd_journal no pueden usarse en el hijo después de un fork. Las funciones que toman un objeto de journal como argumento (sd_journal_next() y otros) devolverán -ECHILD después de un fork.

sd_journal_close() cerrará el contexto de journal asignado con sd_journal_open() o sd_journal_open_directory() y liberará sus recursos.

Al abrir el journal, solo se abrirán los archivos de journal accesibles al usuario que llama. Si los archivos de journal no son accesibles al usuario, este se ignorará silenciosamente.

Ver sd_journal_next(3) para un ejemplo de cómo iterar por el journal después de abrirlo con sd_journal_open().

El objeto de contexto de journal devuelto por sd_journal_open() refiere un archivo de journal específico como entrada actual, similar a un índice de archivo en un sistema de archivos clásico, pero sin posiciones absolutas. Puede ser alterado con sd_journal_next(3) y sd_journal_seek_head(3) y llamadas relacionadas. La posición actual de la entrada puede ser exportada en strings de cursor, como accesible con sd_journal_get_cursor(3). Los strings de cursor pueden usarse globalmente para identificar de manera estable una entrada de journal específica y luego buscar a esa entrada (o si la entrada específica no está localmente disponible, a su entrada más cercana en el tiempo) sd_journal_seek_cursor(3).

La notificación de cambios en el journal está disponible a través de sd_journal_get_fd() y llamadas relacionadas.

RETURN VALUE

Las llamadas sd_journal_open(), sd_journal_open_directory(), y sd_journal_open_files() devuelven 0 en caso de éxito o un código de error en estilo de errno. sd_journal_close() devuelve nada.

NOTES

Todas las funciones mencionadas aquí son thread-agnostic y solo un único hilo puede operar en un objeto dado en cualquier momento. Diferentes hilos pueden acceder al mismo objeto en diferentes momentos. Se pueden usar múltiples objetos independientes en paralelo desde diferentes hilos.

Las funciones descritas aquí están disponibles como una biblioteca compartida, que puede compilarse y vincularse con el archivo libsystemd usando pkg-config(1).

HISTORY

sd_journal_open(), sd_journal_open_directory(), y sd_journal_close() fueron agregados en la versión 187.

sd_journal_open_files() fue agregado en la versión 205.

sd_journal_open_directory_fd() y sd_journal_open_files_fd() fueron agregados en la versión 230.

sd_journal_open_namespace() fue agregado en la versión 245.
