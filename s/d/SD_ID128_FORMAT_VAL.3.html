DESCRIPCIÓN

sd-id128.h es parte de libsystemd(3) y proporciona APIs para generar, convertir y comparar valores de ID de 128 bits. Los valores de ID de 128 bits procesados y generados por estas APIs son una generalización de los UUIDs de OSF como definido por RFC 4122[1] pero utilizan un formato de cadena más simple. Estas funciones no imponen ninguna estructura en los IDs utilizados, a diferencia de los UUIDs de OSF o los GUIDs de Microsoft, pero son mayormente compatibles con esos tipos de IDs.

Un ID de 128 bits se implementa como la siguiente unión:

typedef union sd_id128 {
  uint8_t bytes[16];
  uint64_t qwords[2];
} sd_id128_t;

Esta unión permite acceder al ID de 128 bits como 16 bytes separados o dos palabras de 64 bits. Generalmente es más seguro acceder a los componentes del ID por su matriz de 8 bits para evitar problemas de endianidad. Esta unión está pensada para ser pasada por valor (a diferencia de pasar por referencia) y puede ser manipulada directamente por los clientes.

Se definen un par de macros para denotar y decodificar IDs de 128 bits:

SD_ID128_MAKE() se utiliza para escribir un ID constante en el código fuente. Un modismo comúnmente utilizado es asignar un nombre a un ID usando esta macro:

#define SD_MESSAGE_COREDUMP SD_ID128_MAKE(fc,2e,22,bc,6e,e6,47,b6,b9,07,29,ab,34,a2,50,b1)

SD_ID128_NULL define un ID que consiste únicamente en bytes NUL (es decir, todos los bits a cero).

SD_ID128_ALLF define un ID que consiste únicamente en bytes 0xFF (es decir, todos los bits a uno).

SD_ID128_MAKE_STR() es similar a SD_ID128_MAKE(), pero crea una expresión const char* que puede ser utilizada convenientemente en formatos de mensajes y similares:

#include <stdio.h>
#define SD_MESSAGE_COREDUMP_STR SD_ID128_MAKE_STR(fc,2e,22,bc,6e,e6,47,b6,b9,07,29,ab,34,a2,50,b1)
int main(int argc, char **argv) {
  puts("Match for coredumps: MESSAGE_ID=" SD_MESSAGE_COREDUMP_STR);
}

SD_ID128_CONST_STR() convierte IDs constantes en cadenas constantes para su salida. El siguiente código de ejemplo mostrará la cadena "fc2e22bc6ee647b6b90729ab34a250b1":

int main(int argc, char *argv[]) {
  puts("Match for coredumps: %s", SD_ID128_CONST_STR(SD_MESSAGE_COREDUMP));
}

SD_ID128_FORMAT_STR y SD_ID128_FORMAT_VAL() se utilizan para formatear un ID en una cadena de formato printf(3), como se muestra en el siguiente ejemplo:

int main(int argc, char *argv[]) {
  sd_id128_t id;
  id = SD_ID128_MAKE(ee,89,be,71,bd,6e,43,d6,91,e6,c5,5d,eb,03,02,07);
  printf("The ID encoded in this C file is " SD_ID128_FORMAT_STR ".\n", SD_ID128_FORMAT_VAL(id));
  return 0;
}

SD_ID128_UUID_FORMAT_STR y SD_ID128_MAKE_UUID_STR() son similares a SD_ID128_FORMAT_STR y SD_ID128_MAKE_STR(), pero incluyen guiones separadores para cumplir con la "representación canónica de UUID[2]". Forman la cadena basándose en las reglas de la variante 1 de RFC4122[1], es decir, convirtiendo desde el orden de bytes Big Endian. Esto coincide con el comportamiento de la mayoría de la infraestructura del espacio de usuario de Linux. Probablemente sea mejor evitar UUIDs de otras variantes para evitar ambigüedades innecesarias. Todos los IDs de 128 bits generados por las APIs de sd-id128 cumplen estrictamente con UUIDs de la variante 1, versión 4, según RFC 4122.

sd_id128_equal() compara dos IDs de 128 bits:

int main(int argc, char *argv[]) {
  sd_id128_t a, b, c;
  a = SD_ID128_MAKE(ee,89,be,71,bd,6e,43,d6,91,e6,c5,5d,eb,03,02,07);
  b = SD_ID128_MAKE(f2,28,88,9c,5f,09,44,15,9d,d7,04,77,58,cb,e7,3e);
  c = a;
  assert(sd_id128_equal(a, c));
  assert(!sd_id128_equal(a, b));
  return 0;
}

sd_id128_string_equal() es similar a sd_id128_equal(), pero el primer ID está formateado como const char*. Las mismas restricciones se aplican que al primer argumento de sd_id128_from_string().

sd_id128_is_null() comprueba si un ID consiste únicamente en bytes NUL:

assert(sd_id128_is_null(SD_ID128_NULL));

De manera similar, sd_id128_is_allf() comprueba si un ID consiste únicamente en bytes 0xFF (todos los bits a uno):

assert(sd_id128_is_allf(SD_ID128_ALLF));

sd_id128_in_set_sentinel() toma una lista de IDs y devuelve verdadero si el primer argumento es igual a alguno de los argumentos subsiguientes. La lista de argumentos está terminada por un centinela SD_ID128_NULL, que debe estar presente.

sd_id128_in_set() es una función de conveniencia que toma una lista de IDs y devuelve verdadero si el primer argumento es igual a alguno de los argumentos subsiguientes:

int main(int argc, char *argv[]) {
  sd_id12_t a = SD_ID128_MAKE(ee,89,be,71,bd,6e,43,d6,91,e6,c5,5d,eb,03,02,07);
  assert(sd_id128_in_set(a, a));
  assert(sd_id128_in_set(a, a, a));
  assert(!sd_id128_in_set(a));
  assert(!sd_id128_in_set(a,
                          SD_ID128_MAKE(f2,28,88,9c,5f,09,44,15,9d,d7,04,77,58,cb,e7,3e)
                          SD_ID128_MAKE(2f,88,28,5f,9c,44,09,9d,d7,15,77,04,bc,85,7e,e3)
                          SD_ID128_ALLF));
  return 0;
}

sd_id128_in_set() se define como una macro sobre sd_id128_in_set_sentinel(), añadiendo automáticamente el centinela SD_ID128_NULL. Dado que sd_id128_in_set_sentinel() utiliza SD_ID128_NULL como centinela, SD_ID128_NULL no puede colocarse de otro modo en la lista de argumentos.

sd_id128_in_setv() es similar a sd_id128_in_set_sentinel(), pero toma un argumento de tipo varargs de struct.

Se pueden generar nuevos IDs aleatorios con el comando new de systemd-id128(1).

Consulta sd_id128_to_string(3), sd_id128_randomize(3) y sd_id128_get_machine(3) para obtener información sobre otras APIs relacionadas.

NAME

sd_id128_equal, sd_id128_string_equal, sd_id128_is_null, sd_id128_is_allf, sd_id128_in_setv, sd_id128_in_set_sentinel, sd_id128_in_set - Comparar y comprobar identidades de 128 bits

SYNOPSIS

#include <systemd/sd-id128.h>

int sd_id128_equal(const sd_id128_t a, const sd_id128_t b);
int sd_id128_string_equal(const char *a, const char *b);
int sd_id128_is_null(const sd_id128_t id);
int sd_id128_is_allf(const sd_id128_t id);
int sd_id128_in_setv(const sd_id128_t id, size_t n, const sd_id128_t *set);
int sd_id128_in_set_sentinel(const sd_id128_t id, ...);
int sd_id128_in_set(const sd_id128_t id, const sd_id128_t *set);

DESCRIPTION

Estas funciones se utilizan para comparar dos identificadores de 128 bits (un tipo de datos opaco que representa un UUID o un GUID) entre sí o para comprobar si un identificador se encuentra dentro de un conjunto de identificadores.

La estructura sd_id128_t es un tipo opaco que representa un identificador de 128 bits. Se puede inicializar a partir de una cadena formateada (véase sd_id128_to_string(3)) o mediante funciones como sd_id128_randomize(3) o sd_id128_get_machine(3).

sd_id128_equal() compara dos identificadores de 128 bits a y b. Devuelve un valor distinto de cero si son iguales, y cero en caso contrario.

sd_id128_string_equal() compara dos cadenas que representan identificadores de 128 bits. Devuelve un valor distinto de cero si son iguales, y cero en caso contrario. Admite los mismos formatos que sd_id128_to_string(3).

sd_id128_is_null() comprueba si el identificador dado id es el identificador nulo (todos los bits a cero). Devuelve un valor distinto de cero si es nulo, y cero en caso contrario.

sd_id128_is_allf() comprueba si el identificador dado id es el identificador "all-f" (todos los bits a uno). Devuelve un valor distinto de cero si es "all-f", y cero en caso contrario.

sd_id128_in_setv() comprueba si el identificador id está presente en el conjunto de identificadores especificado por set, que contiene n elementos. Devuelve un valor distinto de cero si se encuentra, y cero en caso contrario.

sd_id128_in_set_sentinel() es similar a sd_id128_in_setv(), pero el conjunto de identificadores termina con un sentinel especial que se pasa como último argumento de la lista de argumentos variable. Actualmente, no hay ningún sentinel definido para este propósito, por lo que esta función no es útil por sí sola. Se prevé que pueda ser utilizada en el futuro si se define un sentinel apropiado.

sd_id128_in_set() es una forma conveniente de llamar a sd_id128_in_setv() para un conjunto de identificadores conocido. Se espera que set sea un puntero a un array de sd_id128_t, donde el último elemento del array debe ser el identificador nulo (todos los bits a cero) como sentinel. Devuelve un valor distinto de cero si se encuentra id en el conjunto (sin incluir el sentinel), y cero en caso contrario.

Todas estas funciones que devuelven un entero devuelven un valor distinto de cero si la condición se cumple y cero en caso contrario. En caso de error, devuelven un valor negativo.

Es importante tener en cuenta que estas funciones pueden utilizar internamente la llamada al sistema getenv(3). La llamada a getenv(3) no es segura para subprocesos en algunas implementaciones. Por lo tanto, el código que llama a estas funciones no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda realizar las llamadas a setenv() solo en una fase temprana del programa, cuando aún no se han iniciado otros hilos.

NOTES
