SD_JOURNAL_GET_FD(3) sd_journal_get_fd SD_JOURNAL_GET_FD(3)

NOMBRE

sd_journal_get_fd, sd_journal_get_events, sd_journal_get_timeout, sd_journal_process, sd_journal_wait, sd_journal_reliable_fd, SD_JOURNAL_NOP, SD_JOURNAL_APPEND, SD_JOURNAL_INVALIDATE - Interfaz de notificación de cambios en el journal

SINOPSIS

#include <systemd/sd-journal.h>

int sd_journal_get_fd(sd_journal *j);

int sd_journal_get_events(sd_journal *j);

int sd_journal_get_timeout(sd_journal *j, uint64_t *timeout_usec);

int sd_journal_process(sd_journal *j);

int sd_journal_wait(sd_journal *j, uint64_t timeout_usec);

int sd_journal_reliable_fd(sd_journal *j);

DESCRIPCIÓN

sd_journal_get_fd() devuelve un descriptor de archivo que puede ser consultado de forma asíncrona en un bucle de eventos externo y que se activa tan pronto como el journal cambia, porque se añadieron nuevas entradas o archivos, se produjo una rotación, o se eliminaron archivos, etc. El descriptor de archivo es adecuado para su uso en poll(2). Utilice sd_journal_get_events() para obtener una máscara de eventos a la que prestar atención. La llamada toma un argumento: el objeto de contexto del journal. Tenga en cuenta que no todos los sistemas de archivos son capaces de generar los eventos necesarios para que las activaciones de este descriptor de archivo se noten de inmediato. En particular, los sistemas de archivos de red no generan eventos de cambio de archivo adecuados en todos los casos. Casos como estos se pueden detectar con sd_journal_reliable_fd(), más abajo. sd_journal_get_timeout() se asegurará en estos casos de que las activaciones ocurran con suficiente frecuencia para que los cambios sean notados, aunque con cierta latencia.

sd_journal_get_events() devolverá la máscara de poll() a esperar. Esta función devolverá una combinación de POLLIN y POLLOUT y similares para rellenar el campo ".events" de struct pollfd.

sd_journal_get_timeout() devolverá un valor de tiempo de espera para su uso en poll(). Esto devuelve un valor en microsegundos desde la época de CLOCK_MONOTONIC para agotar el tiempo de espera de poll() en timeout_usec. Consulte clock_gettime(2) para obtener detalles sobre CLOCK_MONOTONIC. Si no hay tiempo de espera, se rellenará con (uint64_t) -1. Tenga en cuenta que poll() toma un tiempo de espera relativo en milisegundos en lugar de un tiempo de espera absoluto en microsegundos. Para convertir el tiempo de espera absoluto 'us' en 'ms' relativos, utilice código como el siguiente:

uint64_t t;
int msec;
sd_journal_get_timeout(m, &t);
if (t == (uint64_t) -1)
  msec = -1;
else {
  struct timespec ts;
  uint64_t n;
  clock_gettime(CLOCK_MONOTONIC, &ts);
  n = (uint64_t) ts.tv_sec * 1000000 + ts.tv_nsec / 1000;
  msec = t > n ? (int) ((t - n + 999) / 1000) : 0;
}

El código anterior no realiza ninguna comprobación de errores por brevedad. El entero msec calculado se puede pasar directamente como parámetro de tiempo de espera de poll().

Después de cada activación de poll(), es necesario llamar a sd_journal_process() para procesar los eventos. Esta llamada también indicará qué tipo de cambio se ha detectado (ver más abajo; tenga en cuenta que son posibles activaciones espurias).

Una alternativa síncrona para usar sd_journal_get_fd(), sd_journal_get_events(), sd_journal_get_timeout() y sd_journal_process() es sd_journal_wait(). Esperará síncronamente hasta que el journal cambie. El tiempo máximo que esta llamada duerme puede controlarse con el parámetro timeout_usec. Pase (uint64_t) -1 para esperar indefinidamente. Internamente, esta llamada simplemente combina sd_journal_get_fd(), sd_journal_get_events(), sd_journal_get_timeout(), poll() y sd_journal_process() en una sola.

sd_journal_reliable_fd() puede utilizarse para comprobar si los eventos de activación del descriptor de archivo devuelto por sd_journal_get_fd() se sabe que se activan rápidamente. En ciertos sistemas de archivos donde los eventos de cambio de archivo del sistema operativo no están disponibles (como NFS), los cambios deben ser consultados repetidamente y, por lo tanto, solo se detectan con una latencia considerable. Esta llamada devolverá un valor positivo si los cambios del journal se detectan rápidamente y cero si es necesario consultarlos. Tenga en cuenta que generalmente no es necesario invocar esta función directamente, ya que sd_journal_get_timeout() solicitará tiempos de espera apropiados de todos modos.

Tenga en cuenta que ninguna de las interfaces de notificación de cambios anteriores informa los cambios al instante. Se introducen latencias por múltiples razones: como se mencionó, ciertos backends de almacenamiento requieren sondeos basados en tiempo, en otros casos, las activaciones se optimizan agrupando eventos, y el sistema operativo introduce latencias adicionales de planificación de E/S/CPU.

VALOR DE RETORNO

sd_journal_get_fd() devuelve un descriptor de archivo válido en caso de éxito o un código de error negativo estilo errno.

sd_journal_get_events() devuelve una combinación de POLLIN, POLLOUT y similares en caso de éxito o un código de error negativo estilo errno.

sd_journal_reliable_fd() devuelve un entero positivo si el descriptor de archivo devuelto por sd_journal_get_fd() activará las activaciones inmediatamente para todos los cambios del journal. Devuelve 0 si puede haber una latencia involucrada.

sd_journal_process() y sd_journal_wait() devuelven un código de error negativo estilo errno, o uno de SD_JOURNAL_NOP, SD_JOURNAL_APPEND o SD_JOURNAL_INVALIDATE en caso de éxito:

•Si se devuelve SD_JOURNAL_NOP, el journal no ha cambiado desde la última invocación.
•Si se devuelve SD_JOURNAL_APPEND, se han añadido nuevas entradas al final del journal. En este caso, es suficiente seguir leyendo en la ubicación final anterior del journal para leer las entradas recién añadidas.
•Si se devuelve SD_JOURNAL_INVALIDATE, se han añadido o eliminado archivos del journal del conjunto de archivos del journal observados (por ejemplo, debido a rotación o limpieza), y por lo tanto, las entradas pueden haber aparecido o desaparecido en lugares arbitrarios del flujo de registro, posiblemente antes o después del final anterior del flujo de registro. Si se devuelve SD_JOURNAL_INVALIDATE, las UI de vista en vivo que quieran reflejar en pantalla el estado preciso de los datos del registro en disco probablemente deberían actualizar toda su pantalla (en relación con el cursor de la entrada de registro en la parte superior de la pantalla). Los programas que solo estén interesados en un flujo de datos de registro estrictamente secuencial pueden tratar SD_JOURNAL_INVALIDATE de la misma manera que SD_JOURNAL_APPEND, ignorando así cualquier cambio en la vista del registro anterior al antiguo final del flujo de registro.

SEGURIDAD DE SEÑALES

En general, sd_journal_get_fd(), sd_journal_get_events() y sd_journal_get_timeout() no son "seguras para señales asíncronas" en el sentido de signal-safety(7). Sin embargo, solo la primera llamada a cualquiera de estas tres funciones realiza operaciones inseguras, por lo que las llamadas subsiguientes son seguras.

sd_journal_process() y sd_journal_wait() no son seguras. sd_journal_reliable_fd() es segura.

NOTAS

Todas las funciones aquí descritas son independientes de hilos y solo un único hilo puede operar en un objeto dado en cualquier momento. Diferentes hilos pueden acceder al mismo objeto en diferentes momentos. Se pueden utilizar múltiples objetos independientes desde diferentes hilos en paralelo.

Las funciones descritas aquí están disponibles como una biblioteca compartida, que puede ser compilada y enlazada con el archivo libsystemd de pkg-config(1).

sd_journal_wait(3) - systemd manual pages

NAME

sd_journal_wait, sd_journal_process, sd_journal_get_fd, sd_journal_get_events, sd_journal_get_timeout, sd_journal_reliable_fd - Esperar y procesar entradas del journal

SYNOPSIS

#include <systemd/sd-journal.h>

int sd_journal_wait(sd_journal *j, uint64_t timeout);
int sd_journal_process(sd_journal *j);
int sd_journal_get_fd(sd_journal *j);
int sd_journal_get_events(sd_journal *j);
int sd_journal_get_timeout(sd_journal *j, uint64_t *timeout);
int sd_journal_reliable_fd(sd_journal *j);

DESCRIPTION

Estas funciones se utilizan para esperar y procesar nuevas entradas en el journal de systemd. El journal de systemd es un sistema de registro de eventos que recopila mensajes de todas las partes del sistema y del kernel. Con estas funciones, una aplicación puede ser notificada cuando hay nuevas entradas disponibles y luego leerlas.

sd_journal_wait() espera hasta que haya nuevas entradas disponibles en el journal especificado por j o hasta que expire el tiempo de espera. Si timeout es 0, la función retorna inmediatamente. Si timeout es (uint64_t)-1, la función esperará indefinidamente. Si timeout es un valor positivo, se interpretará como un número de microsegundos.

sd_journal_process() procesa cualquier entrada nueva que haya llegado desde la última llamada a esta función o desde que se abrió el journal. Retorna el número de entradas nuevas procesadas. Este número puede ser 0 si no hay nuevas entradas.

sd_journal_get_fd() retorna un descriptor de archivo que se puede utilizar para esperar nuevas entradas utilizando mecanismos como poll(2) o select(2). El descriptor de archivo se activará cuando haya nuevas entradas disponibles o cuando se necesite procesar el journal (por ejemplo, para vaciar buffers o manejar eventos de rotación de archivos).

sd_journal_get_events() retorna los eventos de poll(2) que se deben registrar para el descriptor de archivo devuelto por sd_journal_get_fd(). Normalmente, esto será POLLIN, indicando que hay datos de entrada disponibles. Puede devolver 0 si no hay eventos que esperar.

sd_journal_get_timeout() obtiene el tiempo de espera predeterminado para la espera de nuevas entradas. El valor se devuelve en microsegundos en el argumento timeout. Si el valor es (uint64_t)-1, significa que la espera debe ser indefinida.

sd_journal_reliable_fd() retorna un descriptor de archivo que es fiable para esperar eventos. A diferencia de sd_journal_get_fd(), este descriptor de archivo se activará de forma más predecible y es menos propenso a falsos positivos. Se debe usar preferentemente si la fiabilidad es crítica.

RETURN VALUE

sd_journal_wait() retorna un valor no negativo en caso de éxito, indicando el número de entradas nuevas disponibles. En caso de error, retorna un valor negativo que indica un código de error.

sd_journal_process() retorna el número de entradas nuevas procesadas o un valor negativo en caso de error.

sd_journal_get_fd(), sd_journal_get_events() y sd_journal_reliable_fd() retornan un descriptor de archivo válido en caso de éxito, o -1 en caso de error.

sd_journal_get_timeout() retorna 0 en caso de éxito, o un valor negativo en caso de error.

Los códigos de error pueden ser:

-ENOMEM
No hay suficiente memoria disponible.
-EBADFD
El descriptor de journal no es válido.
-ECHILD
El proceso ha sido bifurcado (forked) y el descriptor de journal ya no es utilizable.
-EPIPE
La tubería de comunicación con el servicio de journal se ha roto.
-EACCES
Permisos insuficientes para acceder al journal.
-EAGAIN
La operación no está disponible temporalmente (por ejemplo, si el journal está siendo rotado).

SIGNAL SAFETY

sd_journal_process(), sd_journal_get_fd(), sd_journal_get_events(), sd_journal_get_timeout() y sd_journal_reliable_fd() son seguros para usar en manejadores de señales. Sin embargo, sd_journal_wait() no lo es.

NOTES

Las funciones sd_journal_wait(), sd_journal_process(), sd_journal_get_fd() y sd_journal_reliable_fd() permiten implementar un bucle de E/S asíncrono para leer el journal. Normalmente, se utiliza un descriptor de archivo obtenido con sd_journal_get_fd() o sd_journal_reliable_fd() junto con poll(2) o un mecanismo similar para esperar nuevas entradas. Una vez que se notifica al descriptor de archivo, se llama a sd_journal_process() para leer las nuevas entradas.

sd_journal_wait() puede ser una alternativa más simple a la combinación de sd_journal_get_fd() y poll(2) si no se necesita un control fino sobre el tiempo de espera o los eventos.

El descriptor de archivo devuelto por sd_journal_get_fd() y sd_journal_reliable_fd() no debe cerrarse explícitamente por el usuario. La gestión de este descriptor de archivo es responsabilidad de la biblioteca de systemd.

El tiempo de espera devuelto por sd_journal_get_timeout() se puede utilizar para configurar un temporizador en poll(2). Si el tiempo de espera es (uint64_t)-1, el tiempo de espera en poll(2) debe ser -1 (espera indefinida).

Después de una llamada a fork(2), el descriptor de journal ya no es válido en el proceso hijo. Se debe abrir un nuevo descriptor de journal en el proceso hijo si se desea acceder al journal.

EXAMPLES

Ejemplo básico para leer entradas del journal de forma continua:

#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <systemd/sd-journal.h>

int main(int argc, char *argv[]) {
    sd_journal *j = NULL;
    sd_journal_open(&j, SD_JOURNAL_LOCAL_ONLY);
    sd_journal_seek_tail(j);
    while (sd_journal_next(j) == 1) {
        // Saltarse entradas antiguas hasta llegar a la más reciente
    }
    while (1) {
        sd_journal_wait(j, (uint64_t) -1);
        sd_journal_process(j);
        const char *data;
        size_t length;
        while (sd_journal_get_data(j, "MESSAGE", (const void **)&data, &length) > 0) {
            printf("%.*s\n", (int) length, data);
        }
    }
    sd_journal_close(j);
    return 0;
}

Ejemplo usando poll() para esperar cambios:

/* SPDX-License-Identifier: MIT-0 */
#define _GNU_SOURCE 1
#include <poll.h>
#include <time.h>
#include <systemd/sd-journal.h>

int wait_for_changes(sd_journal *j) {
  uint64_t t;
  int msec;
  struct pollfd pollfd;

  sd_journal_get_timeout(j, &t);
  if (t == (uint64_t) -1)
    msec = -1;
  else {
    struct timespec ts;
    uint64_t n;
    clock_gettime(CLOCK_MONOTONIC, &ts);
    n = (uint64_t) ts.tv_sec * 1000000 + ts.tv_nsec / 1000;
    msec = t > n ? (int) ((t - n + 999) / 1000) : 0;
  }

  pollfd.fd = sd_journal_get_fd(j);
  pollfd.events = sd_journal_get_events(j);
  poll(&pollfd, 1, msec);

  return sd_journal_process(j);
}

HISTORY

sd_journal_reliable_fd() se añadió en la versión 196.

sd_journal_get_events() y sd_journal_get_timeout() se añadieron en la versión 201.
