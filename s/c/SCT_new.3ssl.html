DESCRIPCIÓN

Las Marcas de Tiempo Firmadas de Certificados (SCTs) se definen en RFC 6962, Sección 3.2. Constituyen una promesa de un registro de Transparencia de Certificados (CT) de registrar públicamente un certificado. Al verificar criptográficamente que un registro efectivamente emitió una SCT, se puede obtener cierta confianza en que el certificado es públicamente conocido.

Se puede crear una representación interna de una SCT de una de dos maneras. La primera opción es crear una SCT en blanco, usando SCT_new(), y luego poblarla usando:

  • SCT_set_version() para establecer la versión de la SCT.

    Actualmente solo se admite SCT_VERSION_V1.

  • SCT_set_log_entry_type() para establecer el tipo de certificado para el que se emitió la SCT:

    CT_LOG_ENTRY_TYPE_X509 para un certificado normal. CT_LOG_ENTRY_TYPE_PRECERT para un pre-certificado.

  • SCT_set0_log_id() o SCT_set1_log_id() para establecer el LogID del registro CT del que proviene la SCT.

    El primero toma posesión, mientras que el segundo realiza una copia. Véase RFC 6962, Sección 3.2 para la definición de LogID.

  • SCT_set_timestamp() para establecer la hora en que se emitió la SCT (tiempo en milisegundos desde la Época Unix).
  • SCT_set_signature_nid() para establecer el NID de la firma.
  • SCT_set0_signature() o SCT_set1_signature() para establecer el valor de firma crudo.

    El primero toma posesión, mientras que el segundo realiza una copia.

  • SCT_set0_extensions() o SCT_set1_extensions para proporcionar extensiones de SCT.

    El primero toma posesión, mientras que el segundo realiza una copia.

Alternativamente, la SCT se puede pre-poblar a partir de los siguientes datos usando SCT_new_from_base64():

  • La versión de la SCT (actualmente solo se admite SCT_VERSION_V1).
  • El LogID (ver RFC 6962, Sección 3.2), codificado en base64.
  • El tipo de certificado para el que se emitió la SCT: CT_LOG_ENTRY_TYPE_X509 para un certificado normal. CT_LOG_ENTRY_TYPE_PRECERT para un pre-certificado.
  • La hora en que se emitió la SCT (tiempo en milisegundos desde la Época Unix).
  • Las extensiones de SCT, codificadas en base64.
  • La firma de la SCT, codificada en base64.

SCT_set_source() se puede usar para registrar dónde se encontró la SCT (extensión TLS, extensión de certificado X.509 o respuesta OCSP). Esto no es necesario para verificar la SCT.

SCT_free() libera la SCT especificada. Si el argumento es NULL, no se hace nada.

SCT_LIST_free() libera la pila especificada de SCTs. Si el argumento es NULL, no se hace nada.

NOTAS

Algunos de los setters devuelven int en lugar de void. Todos devolverán 1 en caso de éxito, 0 en caso de fallo. No realizarán cambios en caso de fallo.

Todos los setters restablecerán el estado de validación de la SCT a SCT_VALIDATION_STATUS_NOT_SET (ver SCT_validate(3)).

SCT_set_source() llamará a SCT_set_log_entry_type() si el tipo de certificado para el que se emitió la SCT se puede inferir de dónde se encontró la SCT. Por ejemplo, una SCT encontrada en una extensión X.509 debe haber sido emitida para un pre-certificado.

SCT_set_source() no rechazará valores desconocidos.

VALORES DE RETORNO

SCT_set_version() devuelve 1 si la versión especificada es compatible, 0 en caso contrario.

SCT_set_log_entry_type() devuelve 1 si el tipo de entrada de registro especificado es compatible, 0 en caso contrario.

SCT_set0_log_id() y SCT_set1_log_id devuelven 1 si el LogID especificado es un hash SHA-256 válido, 0 en caso contrario. Adicionalmente, SCT_set1_log_id devuelve 0 si falla malloc.

SCT_set_signature_nid devuelve 1 si el NID especificado es compatible, 0 en caso contrario.

SCT_set1_extensions y SCT_set1_signature devuelven 1 si el búfer proporcionado se copia correctamente, 0 en caso contrario (es decir, si falla malloc).

SCT_set_source devuelve 1 en caso de éxito, 0 en caso contrario.

VER TAMBIÉN

ct(7), SCT_validate(3), OBJ_nid2obj(3)
