Descripción detallada

el elemento SCXML <transition>.

El elemento <transition> se utiliza para invocar código ejecutable y transicionar desde los estados activos actuales en una máquina de estados a un nuevo conjunto de estados activos.

Por estados activos plurales, se entiende que todos los estados padre de los estados activos también están activos al mismo tiempo, lo cual es útil al organizar transiciones <transition> activadas por eventos comunes. Poner transiciones en el elemento raíz <scxml> significa que siempre están activas.

También tienes el concepto de estados paralelos en SCXML. Esto no está aún soportado en Coin SCXML.

Se aceptan los siguientes atributos:

  • event
  • cond
  • target
  • anchor - no soportado

El atributo event especifica el evento para el cual se activará la transición, si el elemento <transition> se encuentra en un estado activo. El atributo event puede especificarse con coincidencia de comodines usando "*", pero con las siguientes restricciones:

  • "*" debe estar al final de la coincidencia del nombre del evento.
  • "*" debe coincidir con palabras completas separadas por puntos.

Ejemplo 1: event="*"

Ejemplo 2: event="error.*"

El atributo cond se puede usar para especificar condiciones adicionales que deben cumplirse para que se active la <transition>. El lenguaje de expresión de la condición depende del perfil que utilice la máquina de estados SCXML.

El perfil "minimum" solo especifica una función, que es la función In({ID}). In() se evalúa como TRUE si la máquina de estados se encuentra actualmente en el estado con el ID dado.

El perfil "x-coin" implementa una serie de expresiones que se evalúan como un valor de verdad. Mientras esté en desarrollo, documentar el lenguaje de expresiones parece demasiado engorroso, por lo que esa parte tendrá que esperar. El código fuente puede hablar por sí mismo. Ver Coin/src/scxml/eval-coin-tab.y.

El atributo target especifica los estados de destino a los que transicionar. Si se hubieran implementado estados paralelos, podrías especificar varios estados en este atributo, pero por ahora solo puedes especificar un estado de destino. Si se omite target, la transición no cambia el estado activo y solo ejecutará las partes ejecutables que contiene. Si target es el id del estado en el que se encuentra la <transition>, el estado se saldrá/exitirá y luego se volverá a entrar. Para los subestados activos, esto significa que también se saldrán, por supuesto.

El atributo anchor no está soportado.

Los elementos <transition> pueden contener elementos SCXML ejecutables como hijos XML, es decir, <if> /<elseif> / <else>, <assign>, <send>, <event>, <log>.

Detailed Description

Class for representing an SCXML transition element. See the SCXML specification for details on the semantics of transitions.

A transition element is used to specify the possible transitions from one state to another. Transitions can be triggered by events or by conditions.

The search() function can be used for finding elements by attribute name and value. The isEventMatch() function can be used for finding transitions that matches a specific event. The evaluateCondition() function evaluates the transition's condition, and execute() executes the transition's executable content (if any).

Note: The search() method is inherited from ScXMLElt, but it needs to be reimplemented to support searching for child elements.

A transition may specify a target state using the `target` attribute. If the `target` attribute is omitted, the state machine remains in the current state after the transition.

A transition may also specify a condition using the `cond` attribute. If the `cond` attribute is present, the transition is only taken if the condition evaluates to true.

A transition may specify an event using the `event` attribute. If the `event` attribute is present, the transition is only taken if the specified event is received.

The `type` attribute is used to specify the type of transition. The possible values are `normal`, `parallel`, and `external`. The default value is `normal`.

The `sendid` attribute is used to specify the ID of a send event that triggers the transition. If the `sendid` attribute is present, the transition is only taken if a send event with the specified ID is received.

Transitions can also have executable content, specified using `onentry` and `onexit` elements. These elements contain SCXML executable content that is executed when the state is entered or exited, respectively.

A transition without a condition is called a "conditionless" transition. Such a transition should always be taken.

A transition without a target is called a "targetless" transition. When a targetless transition is taken, the state machine's state does not change.

A transition that references its own container state is called a "self-referencing" transition. When a self-referencing transition is taken, the state machine exits the state and then reenters it.

The isTargetLess() method returns whether the transition is targetless.

The isSelfReferencing() method returns whether the transition is self-referencing.

The isConditionLess() method returns whether the transition is conditionless.

The isEventMatch() method checks if the transition matches the given event.

The evaluateCondition() method evaluates the condition of the transition.

The execute() method executes the executable content of the transition.

The search() method searches for an element with the given attribute name and value.

The handleXMLAttributes() method handles the XML attributes of the transition element.

The copyContents() method copies the contents of another transition element.

Note that the base class implementation of search() is not sufficient and needs to be reimplemented by subclasses to traverse child elements.

Also note that the base class implementation of handleXMLAttributes() does nothing and just returns TRUE. Subclasses may override this method to handle specific attributes.

The isEventMatch() method should be reimplemented to check for event matching.

The evaluateCondition() method should be reimplemented to evaluate the condition.

The execute() method should be reimplemented to execute the transition's executable content.

This class implements the ScXMLElt interface.

The use of protected members is generally discouraged in favor of private members. However, the Coin library has a long history and many classes use protected members.

The following methods are reimplemented from ScXMLElt:

handleXMLAttributes()

copyContents()

search()

isEventMatch()

evaluateCondition()

execute()

The search() method is used to search for elements within the SCXML structure. It takes an attribute name and an attribute value as input and returns a pointer to the first element that matches the criteria, or NULL if no such element is found. The base class implementation does not search child elements, so it must be reimplemented in subclasses that have child elements.

The ScXMLElt::getTypeId() method returns the type ID of the element. This can be used for dynamic casting.

SbBool ScXMLTransitionElt::isConditionLess (void ) const

Returns whether this is a conditionless SCXML transition or not.

SbBool ScXMLTransitionElt::isTargetLess (void ) const

Returns whether this is a transition without a target setting or not.

When a targetless transition is taken, the state machine's state does not change. This differs from setting the target to its own state, which will cause the state machine to leave the state and reenter it again.

SbBool ScXMLTransitionElt::isSelfReferencing (void ) const

Returns whether this transition is referencing its container or not.

If TRUE, this means you should end up in the same state as you started with when doing this transition. Note however that as opposed to a targetless transition, this transition should actually exit the state and then reenter it again. Executable content will be invoked after exiting the state, before reentering.
