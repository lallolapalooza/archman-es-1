Combinadores

val id : 'a -> 'a

id es la función identidad. Para cualquier argumento x , id x es x .

val const : 'a -> 'b -> 'a

const c es una función que siempre devuelve el valor c . Para cualquier argumento x , (const c) x es c .

val compose : ('b -> 'c) -> ('a -> 'b) -> 'a -> 'c

compose f g es una composición de funciones donde se aplica primero g y luego f . Para cualquier argumento f , g y x , compose f g x es f (g x) .

Desde 5.2

val flip : ('a -> 'b -> 'c) -> 'b -> 'a -> 'c

flip f invierte el orden de los argumentos de la función binaria f . Para cualquier argumento x e y , (flip f) x y es f y x .

val negate : ('a -> bool) -> 'a -> bool

negate p es la negación de la función predicado p . Para cualquier argumento x , (negate p) x es not (p x) .

Manejo de excepciones

val protect : finally:(unit -> unit) -> (unit -> 'a) -> 'a

protect ~finally work invoca work () y luego finally () antes de que work () devuelva su valor o una excepción. En este último caso, la excepción se vuelve a lanzar después de que finally () se ejecute. Si finally () lanza una excepción, se lanza la excepción Fun.Finally_raised en su lugar.

protect se puede usar para forzar invariantes locales ya sea que work () se ejecute normalmente o lance una excepción. Sin embargo, no protege contra excepciones inesperadas lanzadas dentro de finally () como Out_of_memory , Stack_overflow , o excepciones asíncronas lanzadas por manejadores de señales (por ejemplo, Sys.Break ).

Nota: Es un error de programación si otras clases de excepciones son lanzadas por finally , ya que cualquier excepción lanzada en work () se perderá en caso de una excepción Fun.Finally_raised . Por lo tanto, se debe tener cuidado de manejar esas excepciones dentro de finally .

exception Finally_raised of exn

Finally_raised exn es lanzada por protect ~finally work cuando finally lanza una excepción exn . Esta excepción denota una excepción inesperada o un error de programación. Como regla general, no se debe capturar una excepción Finally_raised excepto como parte de un manejador de captura general.

Ejemplos

Combinadores

Fun.combinators proporciona una forma ligera y a veces más legible de crear funciones anónimas, que se utiliza mejor como argumentos de corta duración en lugar de definiciones independientes. Los ejemplos a continuación demostrarán esto principalmente con el módulo List .

[id]

List.init con el índice mismo

  # List.init 3 Fun.id;;
  - : int list = [0; 1; 2]

Usando List.filter_map en una lista de option int para filtrar elementos Option.t.None

  # List.filter_map Fun.id [None; Some 2; Some 3; None; Some 5];;
  - : int list = [2; 3; 5]

Distribuir condicionalmente funciones de tipo foo -> foo o tomarlas como argumentos es otro lugar donde id puede ser útil. Considere una función de registro primitiva que imprime una cadena pero ofrece a su usuario la opción de preformatear la cadena antes de imprimir, por ejemplo, para insertar una marca de tiempo

  let log ?(preformat : string -> string = Fun.id) message =
    print_endline (preformat message)

Siempre que podamos construir cierres (closures), id se usa a menudo para el caso base como una operación nula. Considere una función que encadena una lista de funciones unarias:

  let rec chain = function
    | [] -> Fun.id
    | f :: fs -> fun x -> f (chain fs x)

[const]

List.init una lista de ceros

  # List.init 3 (Fun.const 0);;
  - : int list = [0; 0; 0]

Un predicado que lo permite todo y que podría pasarse a cualquier función de filtrado, por ejemplo, List.filter para deshabilitar el filtrado y recuperar todos los valores

  # List.filter (Fun.const true) [1; 2; 3];;
  - : int list = [1; 2; 3]

Tenga en cuenta que aplicar const (...) evalúa la expresión (...) una vez y devuelve una función que solo tiene el resultado de esta evaluación. Para demostrar esto, considere si (...) fuera una llamada a Random.bool () :

List.init n (Fun.const (Random.bool())) para cualquier n > 0 tendrá exactamente dos resultados posibles,

- [true; true; ...; true]

- [false; false; ...; false]

mientras que List.init n (fun _ -> Random.bool()) tendrá 2^n resultados posibles, porque el efecto de aleatoriedad se realiza con cada elemento.

Para usos más reales, considere String.spellcheck con una distancia máxima constante de 2, en lugar de la distancia máxima variable predeterminada

  let spellcheck known_words word =
    let dict_iter yield = List.iter yield known_words in
    String.spellcheck ~max_dist:(Fun.const 2) dict_iter word

[flip]

Usando flip para invertir el comparador pasado a List.sort , que ordena en orden opuesto

  # List.sort (Fun.flip Int.compare) [5; 3; 9; 0; 1; 6; 8];;
  - : int list = [9; 8; 6; 5; 3; 1; 0]

Invertir una lista acumulando una nueva lista usando List.fold_left , que espera que el acumulador sea el primer argumento de la función que se le pasa. Pasamos List.cons que tiene la lista como segundo argumento, por lo que flip es útil aquí

  # List.fold_left (Fun.flip List.cons) [] [1; 2; 3];;
  - : int list = [3; 2; 1]

Curiosamente, flip puede funcionar con funciones que no son binarias, invirtiendo los dos primeros argumentos y dejando el resto en orden. Esto se debe a que una función que toma n+2 argumentos es, conceptualmente, una función binaria que devuelve una función que toma n argumentos. Dada una función f : a -> b -> c -> d :

- flip f tendrá el tipo b -> a -> c -> d

- fun x -> flip (f x) tendrá el tipo a -> c -> b -> d

Usar flip con funciones no binarias de esta manera no se recomienda, debido a su impacto negativo en la legibilidad y el razonamiento.

[negate]

Principalmente se usa para invertir un predicado en una función que espera uno, como List.find_all y funciones similares

Encontrar todas las listas que no están vacías usando List.is_empty

  # List.find_all (Fun.negate List.is_empty) [[0]; [1; 2; 3]; []; [4; 5]];;
  - : int list list = [[0]; [1; 2; 3]; [4; 5]]

A partir de una lista dada de rutas, encontrar todas las rutas que no están ocupadas usando Sys.file_exists

  # List.find_all (Fun.negate Sys.file_exists);;
  - : string list -> string list = <fun>

[compose]

List.map en elementos de par con una función en el segundo elemento

  # List.map (Fun.compose String.length snd) [1, "one"; 2, "two"; 3, "three"];;
  - : int list = [3; 3; 5]

Una posible implementación de Fun.negate

  let negate f = Fun.compose not f

Del Fun.hid , compose podría haberse utilizado en la rama recursiva

  let rec chain = function
    | [] -> Fun.id
    | f :: fs -> Fun.compose f (chain fs)
O incluso de forma más concisa 
  let chain fs = List.fold_right Fun.compose fs Fun.id

podría ser usado para condensar la definición de la función de manera que quede

  # Fun.compose
      (String.spellcheck ~max_dist:(Fun.const 2))
      (Fun.flip List.iter)
    ;;
  - : string list -> string -> string list = <fun>

Como se puede ver aquí, esto afecta considerablemente la legibilidad y la capacidad de razonar sobre la función. Ni String.spellcheck ni Fun.flip son unarias, por lo que hay una interacción no trivial con la aplicación parcial en esta definición.

En general, se desaconseja el uso intensivo de estos combinadores en OCaml, no solo porque pueden afectar rápidamente la legibilidad y el razonamiento, sino también porque las funciones producidas suelen estar en forma de valor, por lo tanto, sujetas a la Restricción de Valor (ver la sección 6.1.2 del manual).
