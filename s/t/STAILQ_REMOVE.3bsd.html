DESCRIPCIÓN

Las macros SLIST_*, STAILQ_*, LIST_* y TAILQ_* proporcionan implementaciones de listas enlazadas simples, colas de fin enlazadas simples, listas doblemente enlazadas y colas de fin doblemente enlazadas, respectivamente. Estas macros son implementadas en el código fuente de BSD y se proporcionan como parte de la biblioteca libbsd para compatibilidad con sistemas que no las tienen incorporadas. Las implementaciones originales se encuentran en el código fuente de FreeBSD. La interfaz es la misma que la de las implementaciones originales.

Las listas enlazadas simples solo tienen un puntero hacia el siguiente elemento. Las colas de fin enlazadas simples también solo tienen un puntero hacia el siguiente elemento, pero además mantienen un puntero hacia el último elemento, permitiendo así inserciones eficientes al final de la cola. Las listas y colas de fin doblemente enlazadas tienen punteros hacia el siguiente y el elemento anterior.

Se espera que las estructuras de datos de los elementos de la lista contengan un campo de enlace apropiado, definido usando la macro SLIST_ENTRY, STAILQ_ENTRY, LIST_ENTRY, o TAILQ_ENTRY. Por ejemplo:

struct my_item { int data; SLIST_ENTRY(my_item) pointers; };

Los campos de enlace para las listas doblemente enlazadas tienen dos punteros: le_next y le_prev. Los campos de enlace para las colas de fin doblemente enlazadas tienen tres punteros: tqe_next, tqe_prev, y tqe_tail (este último apunta al último elemento de la cola). Los campos de enlace para las listas y colas de fin enlazadas simples tienen un solo puntero: slh_next.

Una cabecera de lista se define usando la macro SLIST_HEAD, STAILQ_HEAD, LIST_HEAD, o TAILQ_HEAD. Por ejemplo:

SLIST_HEAD(my_list_head, my_item);

Esto define una estructura llamada my_list_head que contiene un puntero al primer elemento de la lista. Para las colas de fin enlazadas simples y las colas de fin doblemente enlazadas, la cabecera también contiene un puntero al último elemento.

MACROS SLIST_*

SLIST_CONCAT(head1, head2, type, sclnk)
Concatena la cola head2 al final de la cola head1. La cola head2 se deja vacía. type es el nombre del tipo del elemento de la lista y sclnk es el nombre del campo de enlace dentro del elemento.
SLIST_EMPTY(head)
Devuelve verdadero si la cola head está vacía, falso en caso contrario.
SLIST_FIRST(head)
Devuelve un puntero al primer elemento de la cola head, o NULL si la cola está vacía.
SLIST_FOREACH(var, head, sclnk)
Itera sobre cada elemento en la cola head. var será un puntero al elemento actual en cada iteración. sclnk es el nombre del campo de enlace.
SLIST_FOREACH_FROM(var, head, sclnk)
Similar a SLIST_FOREACH, pero continúa desde el elemento actual.
SLIST_FOREACH_FROM_SAFE(var, head, sclnk, temp_var)
Itera sobre cada elemento en la cola head de forma segura para la eliminación de elementos durante la iteración. var apunta al elemento actual. temp_var se utiliza para almacenar temporalmente el siguiente elemento para prevenir la pérdida del puntero al siguiente elemento si el elemento actual es eliminado.
SLIST_FOREACH_SAFE(var, head, sclnk, temp_var)
Similar a SLIST_FOREACH_FROM_SAFE, pero itera desde el principio de la cola.
SLIST_HEAD_INITIALIZER(head)
Devuelve un valor inicializador para una cabecera de cola estática.
SLIST_INIT(head)
Inicializa una cola vacía.
SLIST_INSERT_AFTER(listelm, elm, sclnk)
Inserta el elemento elm después del elemento listelm en la cola. sclnk es el nombre del campo de enlace.
SLIST_INSERT_HEAD(head, elm, sclnk)
Inserta el elemento elm al principio de la cola head. sclnk es el nombre del campo de enlace.
SLIST_NEXT(elm, sclnk)
Devuelve un puntero al siguiente elemento de la cola después de elm. sclnk es el nombre del campo de enlace.
SLIST_REMOVE(head, elm, type, sclnk)
Elimina el elemento elm de la cola head. type es el nombre del tipo del elemento y sclnk es el nombre del campo de enlace.
SLIST_REMOVE_AFTER(elm, sclnk)
Elimina el elemento que sigue a elm de la cola. sclnk es el nombre del campo de enlace.
SLIST_REMOVE_HEAD(head, sclnk)
Elimina y devuelve el primer elemento de la cola head. sclnk es el nombre del campo de enlace.
SLIST_SWAP(head1, head2, type)
Intercambia el contenido de las colas head1 y head2. type es el nombre del tipo del elemento.

DESCRIPCIÓN

Estas macros definen y operan sobre cuatro tipos de estructuras de datos que pueden ser usadas tanto en código fuente C como C++:

  1. Listas enlazadas dobles (doubly linked lists)
  2. Listas enlazadas simples (singly-linked lists)
  3. Colas de cola simples (singly-linked tail queues)
  4. Colas de cola dobles (tail queues)
Las cuatro estructuras soportan la siguiente funcionalidad:
  1. Inserción de una nueva entrada al principio de la lista.
  2. Inserción de una nueva entrada después de cualquier elemento en la lista.
  3. Eliminación en O(1) de una entrada del principio de la lista.
  4. Recorrido hacia adelante a través de la lista.
  5. Intercambio del contenido de dos listas.

Las listas enlazadas simples son las más sencillas de las cuatro estructuras de datos y solo soportan la funcionalidad anterior. Las listas enlazadas simples son ideales para aplicaciones con grandes conjuntos de datos y pocas o ninguna eliminación, o para implementar una cola LIFO (Last-In, First-Out). Las listas enlazadas simples añaden la siguiente funcionalidad:

  1. Eliminación en O(n) de cualquier entrada en la lista.
  2. Concatenación en O(n) de dos listas.

Las colas de cola simples añaden la siguiente funcionalidad:

  1. Las entradas pueden ser añadidas al final de una lista.
  2. Eliminación en O(n) de cualquier entrada en la lista.
  3. Pueden ser concatenadas.
Sin embargo:
  1. Todas las inserciones en la lista deben especificar la cabeza de la lista.
  2. Cada entrada de cabeza requiere dos punteros en lugar de uno.
  3. El tamaño del código es aproximadamente un 15% mayor y las operaciones se ejecutan aproximadamente un 20% más lentas que las listas enlazadas simples.

Las colas de cola simples son ideales para aplicaciones con grandes conjuntos de datos y pocas o ninguna eliminación, o para implementar una cola FIFO (First-In, First-Out).

Todos los tipos de estructuras de datos doblemente enlazadas (listas y colas de cola) permiten adicionalmente:

  1. Inserción de una nueva entrada antes de cualquier elemento en la lista.
  2. Eliminación en O(1) de cualquier entrada en la lista.
Sin embargo:
  1. Cada elemento requiere dos punteros en lugar de uno.
  2. El tamaño del código y el tiempo de ejecución de las operaciones (excepto la eliminación) es aproximadamente el doble que el de las estructuras de datos enlazadas simples.

Las listas enlazadas dobles son las más sencillas de las estructuras de datos doblemente enlazadas. Añaden la siguiente funcionalidad sobre las anteriores:

  1. Concatenación en O(n) de dos listas.
  2. Pueden ser recorridas hacia atrás.
Sin embargo:
  1. Para recorrer hacia atrás, se debe especificar una entrada para comenzar el recorrido y la lista en la que está contenida.

Las colas de cola añaden la siguiente funcionalidad:

  1. Las entradas pueden ser añadidas al final de una lista.
  2. Pueden ser recorridas hacia atrás, de cola a cabeza.
  3. Pueden ser concatenadas.
Sin embargo:
  1. Todas las inserciones y eliminaciones de listas deben especificar la cabeza de la lista.
  2. Cada entrada de cabeza requiere dos punteros en lugar de uno.
  3. El tamaño del código es aproximadamente un 15% mayor y las operaciones se ejecutan aproximadamente un 20% más lentas que las listas enlazadas simples.

En las definiciones de macros, TYPE es el nombre de una estructura definida por el usuario. La estructura debe contener un campo llamado NAME que sea del tipo SLIST_ENTRY, STAILQ_ENTRY, LIST_ENTRY, o TAILQ_ENTRY. En las definiciones de macros, CLASSTYPE es el nombre de una clase definida por el usuario. La clase debe contener un campo llamado NAME que sea del tipo SLIST_CLASS_ENTRY, STAILQ_CLASS_ENTRY, LIST_CLASS_ENTRY, o TAILQ_CLASS_ENTRY. El argumento HEADNAME es el nombre de una estructura definida por el usuario que debe ser declarada usando las macros SLIST_HEAD, SLIST_CLASS_HEAD, STAILQ_HEAD, STAILQ_CLASS_HEAD, LIST_HEAD, LIST_CLASS_HEAD, TAILQ_HEAD, o TAILQ_CLASS_HEAD. Consulte los ejemplos a continuación para una mayor explicación de cómo se utilizan estas macros.

LISTAS ENLAZADAS SIMPLES

Una lista enlazada simple está encabezada por una estructura definida por la macro SLIST_HEAD. Esta estructura contiene un único puntero al primer elemento de la lista. Los elementos están enlazados simplemente para una mínima sobrecarga de espacio y manipulación de punteros, a expensas de una eliminación O(n) para elementos arbitrarios. Se pueden añadir nuevos elementos a la lista después de un elemento existente o al principio de la lista. Una estructura SLIST_HEAD se declara de la siguiente manera:

SLIST_HEAD(HEADNAME, TYPE) head;

donde HEADNAME es el nombre de la estructura a definir, y TYPE es el tipo de los elementos a enlazar en la lista. Un puntero a la cabeza de la lista puede ser declarado más tarde como:

struct HEADNAME *headp;

(Los nombres head y headp son seleccionables por el usuario.)

La macro SLIST_HEAD_INITIALIZER se evalúa como un inicializador para la lista head.

La macro SLIST_CONCAT concatena la lista encabezada por head2 al final de la encabezada por head1, eliminando todas las entradas de la primera. Se debe evitar el uso de esta macro ya que recorre la totalidad de la lista head1. Se debe usar una cola de cola simple si esta macro es necesaria en rutas de código de alto uso o para operar en listas largas.

La macro SLIST_EMPTY se evalúa como verdadera si no hay elementos en la lista.

La macro SLIST_ENTRY declara una estructura que conecta los elementos en la lista.

La macro SLIST_FIRST devuelve el primer elemento de la lista o NULL si la lista está vacía.

La macro SLIST_FOREACH recorre la lista referenciada por head en dirección hacia adelante, asignando cada elemento en turno a var.

La macro SLIST_FOREACH_FROM se comporta idénticamente a SLIST_FOREACH cuando var es NULL, de lo contrario trata var como un elemento SLIST encontrado previamente y comienza el bucle en var en lugar del primer elemento en la SLIST referenciada por head.

La macro SLIST_FOREACH_SAFE recorre la lista referenciada por head en dirección hacia adelante, asignando cada elemento en turno a var. Sin embargo, a diferencia de SLIST_FOREACH(), aquí está permitido eliminar var así como liberarlo desde dentro del bucle de forma segura sin interferir con el recorrido.

La macro SLIST_FOREACH_FROM_SAFE se comporta idénticamente a SLIST_FOREACH_SAFE cuando var es NULL, de lo contrario trata var como un elemento SLIST encontrado previamente y comienza el bucle en var en lugar del primer elemento en la SLIST referenciada por head.

La macro SLIST_INIT inicializa la lista referenciada por head.

La macro SLIST_INSERT_HEAD inserta el nuevo elemento elm al principio de la lista.

La macro SLIST_INSERT_AFTER inserta el nuevo elemento elm después del elemento listelm.

La macro SLIST_NEXT devuelve el siguiente elemento en la lista después de elm.

La macro SLIST_REMOVE elimina la entrada elm de la lista.

La macro SLIST_SWAP intercambia el contenido de las listas head1 y head2.

    SLIST_HEAD_INITIALIZER(head);

struct entry {
	...
	SLIST_ENTRY(entry) entries;	/* Lista enlazada simplemente. */
	...
} *n1, *n2, *n3, *np;

free(n3);
					/* Recorrido hacia adelante. */
SLIST_FOREACH(np, &head, entries)
	np-> ...
					/* Recorrido seguro hacia adelante. */
SLIST_FOREACH_SAFE(np, &head, entries, np_temp) {
	np->do_stuff();
	...
	SLIST_REMOVE(&head, np, entry, entries);
	free(np);

while (!SLIST_EMPTY(&head)) {		/* Eliminación de la lista. */
	n1 = SLIST_FIRST(&head);
	SLIST_REMOVE_HEAD(&head, entries);
	free(n1);

La macro TAILQ_FOREACH_FROM se comporta idénticamente a TAILQ_FOREACH cuando var es NULL, de lo contrario, trata a var como un elemento de TAILQ previamente encontrado y comienza el bucle en var en lugar del primer elemento en la TAILQ referenciada por head.

La macro TAILQ_FOREACH_REVERSE_FROM se comporta idénticamente a TAILQ_FOREACH_REVERSE cuando var es NULL, de lo contrario, trata a var como un elemento de TAILQ previamente encontrado y comienza el bucle inverso en var en lugar del último elemento en la TAILQ referenciada por head.

Las macros TAILQ_FOREACH_SAFE y TAILQ_FOREACH_REVERSE_SAFE recorren la lista referenciada por head en dirección hacia adelante o inversa respectivamente, asignando cada elemento en turno a var. Sin embargo, a diferencia de sus contrapartes inseguras, TAILQ_FOREACH y TAILQ_FOREACH_REVERSE hacen posible tanto remover var como liberarlo dentro del bucle de forma segura sin interferir con el recorrido.

La macro TAILQ_FOREACH_FROM_SAFE se comporta idénticamente a TAILQ_FOREACH_SAFE cuando var es NULL, de lo contrario, trata a var como un elemento de TAILQ previamente encontrado y comienza el bucle en var en lugar del primer elemento en la TAILQ referenciada por head.

La macro TAILQ_FOREACH_REVERSE_FROM_SAFE se comporta idénticamente a TAILQ_FOREACH_REVERSE_SAFE cuando var es NULL, de lo contrario, trata a var como un elemento de TAILQ previamente encontrado y comienza el bucle inverso en var en lugar del último elemento en la TAILQ referenciada por head.

La macro TAILQ_INIT inicializa la cola de cola referenciada por head.

La macro TAILQ_INSERT_HEAD inserta el nuevo elemento elm al principio de la cola de cola.

La macro TAILQ_INSERT_TAIL inserta el nuevo elemento elm al final de la cola de cola.

La macro TAILQ_INSERT_AFTER inserta el nuevo elemento elm después del elemento listelm.

La macro TAILQ_INSERT_BEFORE inserta el nuevo elemento elm antes del elemento listelm.

La macro TAILQ_LAST devuelve el último elemento de la cola de cola. Si la cola de cola está vacía, el valor de retorno es NULL.

La macro TAILQ_NEXT devuelve el siguiente elemento de la cola de cola, o NULL si este elemento es el último.

La macro TAILQ_PREV devuelve el elemento anterior de la cola de cola, o NULL si este elemento es el primero.

La macro TAILQ_REMOVE elimina el elemento elm de la cola de cola.

La macro TAILQ_SWAP intercambia el contenido de head1 y head2.

DIAGNÓSTICOS

Al depurar queue(3), puede ser útil rastrear los cambios en la cola. Para habilitar el rastreo, defina la macro QUEUE_MACRO_DEBUG_TRACE en tiempo de compilación.

También puede ser útil sobrescribir los punteros que han sido desvinculados de una cola, para detectar su uso después de la eliminación. Para habilitar la sobrescritura de punteros, defina la macro QUEUE_MACRO_DEBUG_TRASH en tiempo de compilación. La macro QMD_IS_TRASHED(void *ptr) devuelve verdadero si ptr ha sido sobrescrito por la opción QUEUE_MACRO_DEBUG_TRASH.
