Accesos no sincronizados

Los accesos no sincronizados a una tabla hash pueden provocar un estado inválido de la tabla hash. Por lo tanto, los accesos concurrentes a una tabla hash deben sincronizarse (por ejemplo, con un Mutex.t ).

Interfaz genérica

type (!'a, !'b) t

El tipo de tablas hash desde el tipo 'a al tipo 'b .

val create : ?random:bool -> int -> ('a, 'b) t

Hashtbl.create n crea una tabla hash nueva y vacía, con un tamaño inicial mayor o igual al tamaño sugerido n . Para obtener mejores resultados, n debe ser del orden del número esperado de elementos que habrá en la tabla. La tabla crece según sea necesario, por lo que n es solo una estimación inicial. Si n es muy pequeño o negativo, se ignora y se utiliza un tamaño predeterminado pequeño.

El parámetro opcional ~random (un booleano) controla si la organización interna de la tabla hash se aleatoriza en cada ejecución de Hashtbl.create o es determinista en todas las ejecuciones.

Una tabla hash creada con ~random establecido en false utiliza una función hash fija ( Hashtbl.hash ) para distribuir las claves entre los cubos. Como consecuencia, las colisiones entre claves ocurren de forma determinista. En aplicaciones orientadas a la web u otras aplicaciones sensibles a la seguridad, un usuario malintencionado puede explotar los patrones de colisión deterministas para crear un ataque de denegación de servicio: el atacante envía entradas diseñadas para crear muchas colisiones en la tabla, lo que ralentiza la aplicación.

Una tabla hash creada con ~random establecido en true utiliza la función hash con semilla Hashtbl.seeded_hash con una semilla elegida aleatoriamente en el momento de la creación de la tabla hash. De hecho, la función hash utilizada se selecciona aleatoriamente entre 2^{30} funciones hash diferentes. Todas estas funciones hash tienen diferentes patrones de colisión, lo que hace ineficaz el ataque de denegación de servicio descrito anteriormente. Sin embargo, debido a la aleatorización, enumerar todos los elementos de la tabla hash usando Hashtbl.fold o Hashtbl.iter ya no es determinista: los elementos se enumeran en órdenes diferentes en ejecuciones diferentes del programa.

Si no se proporciona ningún parámetro ~random , las tablas hash se crean en modo no aleatorizado por defecto. Este valor predeterminado se puede cambiar programáticamente llamando a Hashtbl.randomize o estableciendo el indicador R en la variable de entorno OCAMLRUNPARAM .

Antes de 4.00 el parámetro ~random no estaba presente y todas las tablas hash se creaban en modo no aleatorizado.

val clear : ('a, 'b) t -> unit

Vacía una tabla hash. Utilice reset en lugar de clear para reducir el tamaño de la tabla de cubos a su tamaño inicial.

val reset : ('a, 'b) t -> unit

Vacía una tabla hash y reduce el tamaño de la tabla de cubos a su tamaño inicial.

Desde 4.00

val copy : ('a, 'b) t -> ('a, 'b) t

Devuelve una copia de la tabla hash dada.

val add : ('a, 'b) t -> 'a -> 'b -> unit

Hashtbl.add tbl key data agrega una asociación de key a data en la tabla tbl .

Advertencia: Las asociaciones anteriores para key no se eliminan, sino que simplemente se ocultan. Es decir, después de realizar Hashtbl.remove tbl key , la asociación anterior para key , si existe, se restaura. (Mismo comportamiento que con las listas de asociación).

Si desea el comportamiento clásico de reemplazo de elementos, consulte Hashtbl.replace .

val find : ('a, 'b) t -> 'a -> 'b

Hashtbl.find tbl x devuelve la asociación actual de x en tbl , o lanza Not_found si no existe tal asociación.

val find_opt : ('a, 'b) t -> 'a -> 'b option

Hashtbl.find_opt tbl x devuelve la asociación actual de x en tbl , o None si no existe tal asociación.

Desde 4.05

val find_all : ('a, 'b) t -> 'a -> 'b list

Hashtbl.find_all tbl x devuelve la lista de todos los datos asociados con x en tbl . La asociación actual se devuelve primero, luego las asociaciones anteriores, en orden inverso de introducción en la tabla.

val mem : ('a, 'b) t -> 'a -> bool

Hashtbl.mem tbl x comprueba si x está asociado en tbl .

val remove : ('a, 'b) t -> 'a -> unit

Hashtbl.remove tbl x elimina la asociación actual de x en tbl , restaurando la asociación anterior si existe. No hace nada si x no está asociado en tbl .

val replace : ('a, 'b) t -> 'a -> 'b -> unit

Hashtbl.replace tbl key data reemplaza la asociación actual de key en tbl por una asociación de key a data . Si key no está asociado en tbl , se agrega una asociación de key a data a tbl . Esto es funcionalmente equivalente a Hashtbl.remove tbl key seguido de Hashtbl.add tbl key data .

val iter : ('a -> 'b -> unit) -> ('a, 'b) t -> unit

Hashtbl.iter f tbl aplica f a todas las asociaciones en la tabla tbl . f recibe la clave como primer argumento y el valor asociado como segundo argumento. Cada asociación se presenta exactamente una vez a f .

El orden en el que las asociaciones se pasan a f no está especificado. Sin embargo, si la tabla contiene varias asociaciones para la misma clave, se pasan a f en orden inverso de introducción, es decir, la asociación más reciente se pasa primero.

Si la tabla hash se creó en modo no aleatorizado, el orden en el que se enumeran las asociaciones es reproducible entre ejecuciones sucesivas del programa, e incluso entre versiones menores de OCaml. Para tablas hash aleatorizadas, el orden de enumeración es completamente aleatorio.

El comportamiento no está especificado si la tabla hash es modificada por f durante la iteración.

val filter_map_inplace : ('a -> 'b -> 'b option) -> ('a, 'b) t -> unit

Hashtbl.filter_map_inplace f tbl aplica f a todas las asociaciones en la tabla tbl y actualiza cada asociación según el resultado de f . Si f devuelve None , la asociación se descarta. Si devuelve Some new_val , la asociación se actualiza para asociar la clave con new_val .

Otros comentarios para Hashtbl.iter también se aplican.

Desde 4.03

val fold : ('a -> 'b -> 'acc -> 'acc) -> ('a, 'b) t -> 'acc -> 'acc

Hashtbl.fold f tbl init calcula (f kN dN ... (f k1 d1 init)...) , donde k1 ... kN son las claves de todas las asociaciones en tbl , y d1 ... dN son los valores asociados. Cada asociación se presenta exactamente una vez a f .

El orden en el que las asociaciones se pasan a f no está especificado. Sin embargo, si la tabla contiene varias asociaciones para la misma clave, se pasan a f en orden inverso de introducción, es decir, la asociación más reciente se pasa primero.

Si la tabla hash se creó en modo no aleatorizado, el orden en el que se enumeran las asociaciones es reproducible entre ejecuciones sucesivas del programa, e incluso entre versiones menores de OCaml. Para tablas hash aleatorizadas, el orden de enumeración es completamente aleatorio.

El comportamiento no está especificado si la tabla hash es modificada por f durante la iteración.

val length : ('a, 'b) t -> int

Hashtbl.length tbl devuelve el número de asociaciones en tbl . Tarda un tiempo constante. Las asociaciones múltiples se cuentan una vez cada una, por lo que Hashtbl.length da el número de veces que Hashtbl.iter llama a su primer argumento.

val randomize : unit -> unit

Después de una llamada a Hashtbl.randomize() , las tablas hash se crean en modo aleatorizado por defecto: Hashtbl.create devuelve tablas hash aleatorizadas, a menos que se proporcione el parámetro opcional ~random:false . Se puede lograr el mismo efecto estableciendo el parámetro R en la variable de entorno OCAMLRUNPARAM .

val to_seq : ('a, 'b) t -> ('a * 'b) Seq.t

El comportamiento no está especificado si la tabla se modifica durante la iteración.

Interfaz functorial

La interfaz functorial permite el uso de funciones de hash y comparación específicas, ya sea por razones de rendimiento o seguridad, o porque las claves no son hasheables o comparables con los builtins polimórficos.

Por ejemplo, se podría querer especializar una tabla para claves de enteros:

      module IntHash =
        struct
          type t = int
          let equal i j = i=j
          let hash i = i land max_int
        end
      module IntHashtbl = Hashtbl.Make(IntHash)
      let h = IntHashtbl.create 17 in
      IntHashtbl.add h 12 "hello"

Esto crea un nuevo módulo IntHashtbl con un nuevo tipo 'a de tablas de int a 'a. En este ejemplo, h contiene valores de string por lo que su tipo es string IntHashtbl.t.

Nota: El nuevo tipo 'a IntHashtbl.t no es compatible con el tipo ('a,'b) Hashtbl.t de la interfaz genérica. Por ejemplo, Hashtbl.length h no compilaría, debes usar IntHashtbl.length.

module Make : (H : HashedType) -> sig end

Un functor que construye una implementación de la estructura de tabla hash. El functor Hashtbl.Make devuelve una estructura que contiene un tipo key de claves y un tipo 'a t de tablas asociativas que vinculan datos de tipo 'a a claves de tipo key. Las operaciones son similares a las de la interfaz genérica, pero utilizan las funciones de hash y comparación especificadas en el argumento del functor H en lugar de las comparaciones y hashings genéricos. Dado que la función de hash no tiene semilla, la operación create de la estructura resultante siempre devuelve tablas hash no aleatorizadas.

Las funciones de hash polimórficas

val hash : 'a -> int

Hashtbl.hash x asocia un número entero no negativo a cualquier valor de cualquier tipo. Se garantiza que si x = y o Stdlib.compare x y = 0, entonces hash x = hash y. Además, hash siempre termina, incluso en estructuras cíclicas.

val seeded_hash : int -> 'a -> int

Una variante de Hashtbl.hash parametrizada adicionalmente por una semilla entera.

Desde 4.00

val hash_param : int -> int -> 'a -> int

Hashtbl.hash_param meaningful total x calcula un valor hash para x, con las mismas propiedades que para hash. Los dos parámetros adicionales meaningful y total ofrecen un control más preciso sobre el hash. El hash realiza un recorrido de amplitud en profundidad, de izquierda a derecha, de la estructura x, deteniéndose después de que se hayan visto meaningful nodos significativos o después de que se hayan visto total nodos (significativos o no). Si el valor de total especificado por el usuario excede un valor determinado, actualmente 256, entonces se mantiene en ese valor. Los nodos significativos son: enteros; números de punto flotante; cadenas; caracteres; booleanos; y constructores constantes. Valores mayores de meaningful y total significan que se consideran más nodos para calcular el valor hash final, y por lo tanto, las colisiones son menos probables. Sin embargo, el hash es más lento. Los parámetros meaningful y total regulan el equilibrio entre precisión y velocidad. Como valores predeterminados, Hashtbl.hash y Hashtbl.seeded_hash toman meaningful = 10 y total = 100.

val seeded_hash_param : int -> int -> int -> 'a -> int

Variante de Hashtbl.hash_param parametrizada adicionalmente por una semilla entera. Uso: Hashtbl.seeded_hash_param meaningful total seed x.

Contando Elementos

Dada una secuencia de elementos (aquí, una Seq.t), queremos contar cuántas veces aparece cada elemento distinto en la secuencia. Una forma sencilla de hacerlo, asumiendo que los elementos son comparables y hasheables, es utilizar una tabla hash que mapea los elementos a su número de ocurrencias.

A continuación, se ilustra esta idea utilizando una secuencia de caracteres (tipo char). Utilizamos una Char_tbl especializada para char.

    # module Char_tbl = Hashtbl.Make(struct
        type t = char
        let equal = Char.equal
        let hash = Hashtbl.hash
      end)
    (*  contar ocurrencias distintas de caracteres en [seq] *)
    #

let count_chars (seq : char Seq.t) : _ list =
        let counts = Char_tbl.create 16 in
        Seq.iter
          (fun c ->
            let count_c =
              Char_tbl.find_opt counts c
              |> Option.value ~default:0
            in
            Char_tbl.replace counts c (count_c + 1))
          seq;
        (* turn into a list *)
        Char_tbl.fold (fun c n l -> (c,n) :: l) counts []
          |> List.sort (fun (c1,_)(c2,_) -> Char.compare c1 c2)
