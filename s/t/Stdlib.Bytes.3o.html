val length : bytes -> int

Devuelve la longitud (número de bytes) del argumento.

val get : bytes -> int -> char

get s n devuelve el byte en el índice n de s .

Genera Invalid_argument si n no es un índice válido en s .

val set : bytes -> int -> char -> unit

set s n c modifica s en su lugar, reemplazando el byte en el índice n con c .

Genera Invalid_argument si n no es un índice válido en s .

val create : int -> bytes

create n devuelve una nueva secuencia de bytes de longitud n . La secuencia no está inicializada y contiene bytes arbitrarios.

Genera Invalid_argument si n < 0 o n > Sys.max_string_length .

val make : int -> char -> bytes

make n c devuelve una nueva secuencia de bytes de longitud n , rellenada con el byte c .

Genera Invalid_argument si n < 0 o n > Sys.max_string_length .

val init : int -> (int -> char) -> bytes

init n f devuelve una secuencia de bytes nueva de longitud n , con el carácter i inicializado al resultado de f i (en orden de índice creciente).

Genera Invalid_argument si n < 0 o n > Sys.max_string_length .

val empty : bytes

Una secuencia de bytes de tamaño 0.

val copy : bytes -> bytes

Devuelve una nueva secuencia de bytes que contiene los mismos bytes que el argumento.

val of_string : string -> bytes

Devuelve una nueva secuencia de bytes que contiene los mismos bytes que la cadena dada.

val to_string : bytes -> string

Devuelve una nueva cadena que contiene los mismos bytes que la secuencia de bytes dada.

val sub : bytes -> int -> int -> bytes

sub s pos len devuelve una nueva secuencia de bytes de longitud len , que contiene la sub-secuencia de s que comienza en la posición pos y tiene longitud len .

Genera Invalid_argument si pos y len no designan un rango válido de s .

val sub_string : bytes -> int -> int -> string

Igual que Bytes.sub pero devuelve una cadena en lugar de una secuencia de bytes.

val extend : bytes -> int -> int -> bytes

extend s left right devuelve una nueva secuencia de bytes que contiene los bytes de s , con left bytes no inicializados precediéndola y right bytes no inicializados siguiéndola. Si left o right es negativo, entonces se eliminan bytes (en lugar de añadirse) del lado correspondiente de s .

val fill : bytes -> int -> int -> char -> unit

fill s pos len c modifica s en su lugar, reemplazando len caracteres con c , comenzando en pos .

Genera Invalid_argument si pos y len no designan un rango válido de s .

val blit : bytes -> int -> bytes -> int -> int -> unit

blit src src_pos dst dst_pos len copia len bytes de la secuencia de bytes src , comenzando en el índice src_pos , a la secuencia de bytes dst , comenzando en el índice dst_pos . Funciona correctamente incluso si src y dst son la misma secuencia de bytes, y los intervalos de origen y destino se superponen.

Genera Invalid_argument si src_pos y len no designan un rango válido de src , o si dst_pos y len no designan un rango válido de dst .

val blit_string : string -> int -> bytes -> int -> int -> unit

blit_string src src_pos dst dst_pos len copia len bytes de la cadena src , comenzando en el índice src_pos , a la secuencia de bytes dst , comenzando en el índice dst_pos .

val concat : bytes -> bytes list -> bytes

Genera Invalid_argument si el resultado es mayor que Sys.max_string_length bytes.

val iter : (char -> unit) -> bytes -> unit

iter f s aplica la función f en turno a todos los bytes de s . Es equivalente a f (get s 0); f (get s 1); ...; f (get s
(length s - 1)); () .

val iteri : (int -> char -> unit) -> bytes -> unit

Igual que Bytes.iter , pero la función se aplica al índice del byte como primer argumento y al byte en sí como segundo argumento.

val map : (char -> char) -> bytes -> bytes

map f s aplica la función f en turno a todos los bytes de s (en orden de índice creciente) y almacena los bytes resultantes en una nueva secuencia que se devuelve como resultado.

val mapi : (int -> char -> char) -> bytes -> bytes

mapi f s llama a f con cada carácter de s y su índice (en orden de índice creciente) y almacena los bytes resultantes en una nueva secuencia que se devuelve como resultado.

Conversiones inseguras (para usuarios avanzados)

Esta sección describe funciones de conversión inseguras y de bajo nivel entre bytes y string . No copian los datos internos; utilizadas incorrectamente, pueden romper el invariante de inmutabilidad de las cadenas. Están disponibles para autores de bibliotecas expertas, pero para la mayoría de los propósitos, deberías usar Bytes.to_string y Bytes.of_string , que siempre son correctas, en su lugar.

val unsafe_to_string : bytes -> string

Convierte inseguramente una secuencia de bytes en una cadena.

Para razonar sobre el uso de unsafe_to_string , es conveniente considerar una disciplina de "propiedad". Un fragmento de código que manipula algunos datos "posee" esos datos; hay varios modos de propiedad disjunta, incluyendo:

- Propiedad única: los datos pueden ser accedidos y modificados

- Propiedad compartida: los datos tienen varios propietarios, que solo pueden acceder a ellos, no modificarlos.

La propiedad única es lineal: pasar los datos a otro fragmento de código significa ceder la propiedad (no podemos volver a escribir los datos). Un propietario único puede decidir hacer que los datos sean compartidos (renunciando a los derechos de modificación sobre ellos), pero los datos compartidos no pueden volver a ser propiedad única.

unsafe_to_string s solo se puede usar cuando el llamador posee la secuencia de bytes s , ya sea de forma única o como datos inmutables compartidos. El llamador cede la propiedad de s y obtiene la propiedad de la cadena resultante.

Hay dos casos de uso válidos que respetan esta disciplina de propiedad:

1. Crear una cadena inicializando y modificando una secuencia de bytes que nunca se cambia después de la inicialización.

let string_init len f : string =
  let s = Bytes.create len in
  for i = 0 to len - 1 do Bytes.set s i (f i) done;
  Bytes.unsafe_to_string s

Esta función es segura porque la secuencia de bytes s nunca será accedida o modificada después de que se llame a unsafe_to_string . El código de string_init cede la propiedad de s y devuelve la propiedad de la cadena resultante a su llamador.

Tenga en cuenta que sería inseguro si s se pasara como un parámetro adicional a la función f , ya que podría escapar de esta manera y ser modificado en el futuro: string_init cedería la propiedad de s para pasarla a f , y no podría llamar a unsafe_to_string de forma segura.

Hemos proporcionado las funciones String.init , String.map y String.mapi para cubrir la mayoría de los casos de construcción de nuevas cadenas. Deberías preferirlas sobre to_string o unsafe_to_string siempre que sea aplicable.

2. Dar temporalmente la propiedad de una secuencia de bytes a una función que espera una cadena de propiedad única y devuelve la propiedad, para que podamos modificar la secuencia nuevamente después de que la llamada haya terminado.

let bytes_length (s : bytes) =
  String.length (Bytes.unsafe_to_string s)

En este caso de uso, no prometemos que s nunca será modificada después de la llamada a bytes_length s . La función String.length toma prestada temporalmente la propiedad única de la secuencia de bytes (y la ve como una string ), pero devuelve esta propiedad al llamador, que puede asumir que s sigue siendo una secuencia de bytes válida después de la llamada. Tenga en cuenta que esto solo es correcto porque sabemos que String.length no captura su argumento: podría escapar por un canal lateral como un combinador de memoización.

El llamador no puede modificar s mientras la cadena está prestada (ha cedido temporalmente la propiedad). Esto afecta a los programas concurrentes, pero también a las funciones de orden superior: si String.length devolviera un cierre para ser llamado más tarde, s no debería ser modificada hasta que este cierre se aplique por completo y devuelva la propiedad.

val unsafe_of_string : string -> bytes

Convierte inseguramente una cadena compartida en una secuencia de bytes que no debe ser modificada.

La misma disciplina de propiedad que hace que unsafe_to_string sea correcta se aplica a unsafe_of_string : puedes usarla si eras el propietario del valor string , y poseerás el bytes devuelto en el mismo modo.

En la práctica, la propiedad única de los valores de cadena es extremadamente difícil de razonar correctamente. Siempre debes asumir que las cadenas son compartidas, nunca de propiedad única.

Por ejemplo, las literales de cadena son implícitamente compartidas por el compilador, por lo que nunca las posees de forma única.

let incorrect = Bytes.unsafe_of_string "hello"
let s = Bytes.of_string "hello"

La primera declaración es incorrecta, porque la literal de cadena "hello" podría ser compartida por el compilador con otras partes del programa, y modificar incorrect es un error. Siempre debes usar la segunda versión, que realiza una copia y, por lo tanto, es correcta.

Asumir propiedad única de cadenas que no son literales de cadena, pero que están (en parte) construidas a partir de literales de cadena, también es incorrecto. Por ejemplo, modificar unsafe_of_string ("foo" ^ s) podría modificar la cadena compartida "foo" (asumiendo una representación similar a cuerda de cadenas). De forma más general, las funciones que operan sobre cadenas asumirán propiedad compartida, no preservarán la propiedad única. Por lo tanto, es incorrecto asumir propiedad única del resultado de unsafe_of_string .

se utiliza como una secuencia de bytes inmutable. Esto posiblemente sea útil para la migración incremental de programas de bajo nivel que manipulan secuencias inmutables de bytes (por ejemplo Marshal.from_bytes ) y que previamente utilizaban el tipo string con este propósito.

val split_on_char : char -> bytes -> bytes list

split_on_char sep s devuelve la lista de todas las sub-secuencias (posiblemente vacías) de s que están delimitadas por el carácter sep. Si s está vacío, el resultado es la lista singleton [empty].

La salida de la función está especificada por los siguientes invariantes:

-La lista no está vacía.

-La concatenación de sus elementos utilizando sep como separador devuelve una secuencia de bytes igual a la entrada ( Bytes.concat (Bytes.make 1 sep)
(Bytes.split_on_char sep s) = s ).

-Ninguna secuencia de bytes en el resultado contiene el carácter sep.

Codificación/decodificación binaria de enteros

Las funciones de esta sección codifican y decodifican enteros binariamente a y desde secuencias de bytes.

Todas las funciones siguientes lanzan Invalid_argument si el espacio necesario en el índice i para decodificar o codificar el entero no está disponible.

La codificación little-endian (respectivamente, big-endian) significa que los bytes menos (respectivamente, más) significativos se almacenan primero. Big-endian también se conoce como orden de bytes de red. La codificación native-endian es little-endian o big-endian dependiendo de Sys.big_endian.

Los enteros de 32 y 64 bits se representan mediante los tipos int32 y int64, que pueden interpretarse como números con signo o sin signo.

Los enteros de 8 y 16 bits se representan mediante el tipo int, que tiene más bits que la codificación binaria. Estos bits adicionales se manejan de la siguiente manera:

-Las funciones que decodifican enteros de 8 o 16 bits con signo (respectivamente, sin signo) representados por valores int extienden el signo (respectivamente, rellenan con ceros) su resultado.

-Las funciones que codifican enteros de 8 o 16 bits representados por valores int truncan su entrada a sus bytes menos significativos.

NAME

Stdlib.Bytes — mutable byte sequences

Description

The Bytes module provides mutable byte sequences. These are similar to strings, but they are mutable.

This module is available from version 4.08.0 of OCaml.

Creation of byte sequences

val of_string : string -> bytes

Convert a string to a byte sequence.

val to_string : bytes -> string

Convert a byte sequence to a string.

val make : int -> char -> bytes

make n c returns a byte sequence of length n, with all characters equal to c.

val create : int -> bytes

create n returns a new byte sequence of length n. The initial contents are undefined.

val init : int -> (int -> char) -> bytes

init n f returns a new byte sequence of length n, the k-th character of which is defined by f k.

val copy : bytes -> bytes

Return a copy of the argument.

val of_channel : in_channel -> int -> bytes

Read n bytes from the given input channel and return them as a new byte sequence. Raise End_of_file if the end of the input channel is reached before n bytes have been read.

val of_gen : int -> (int -> char) -> bytes

Create a byte sequence of length n. The characters are generated by calling the function f with indices from 0 to n-1.

Basic operations

val length : bytes -> int

Return the length (number of characters) of the given byte sequence.

val get : bytes -> int -> char

Return the character at index i in the byte sequence b. The index i must be between 0 and 1-length b, inclusive.

val set : bytes -> int -> char -> unit

Set the character at index i in the byte sequence b to the value c. The index i must be between 0 and 1-length b, inclusive.

Subsequences and concatenation

val sub : bytes -> int -> int -> bytes

Extract a sub-sequence of b starting at index i and containing n characters.

val blit : bytes -> int -> bytes -> int -> int -> unit

blit src s_ofs dst d_ofs len copies len characters from src starting at index s_ofs to the byte sequence dst starting at index d_ofs. The source and destination regions must not overlap.

val unsafe_blit : bytes -> int -> bytes -> int -> int -> unit

Same as blit, but the behaviour is undefined if the source and destination regions overlap.

val concat : bytes -> bytes list -> bytes

Concatenate a list of byte sequences, with a given byte sequence as separator.

Searching for subsequences

val rfind_char : bytes -> char -> int -> int

Return the index of the last occurrence of character c in byte sequence b. The search is performed from right to left, starting at index i. Return -1 if c is not found.

val find_char : bytes -> char -> int -> int

Return the index of the first occurrence of character c in byte sequence b. The search is performed from left to right, starting at index i. Return -1 if c is not found.

Modification of byte sequences

val fill : bytes -> int -> int -> char -> unit

Fill the byte sequence b with character c, from index i, for n characters.

val clear : bytes -> unit

Fill the byte sequence b with the null character ('\000').

Other operations

val uppercase : bytes -> bytes

Return a new byte sequence equivalent to b, with all lowercase letters converted to uppercase.

val lowercase : bytes -> bytes

Return a new byte sequence equivalent to b, with all uppercase letters converted to lowercase.

Octet sequences

val to_list : bytes -> char list

Convert a byte sequence to a list of characters.

val of_list : char list -> bytes

Convert a list of characters to a byte sequence.

Byte sequences and concurrency safety

Care must be taken when concurrently accessing byte sequences from multiple domains: accessing a byte sequence will never crash a program, but unsynchronized accesses might yield surprising (non-sequentially-consistent) results.

Atomicity

Every byte sequence operation that accesses more than one byte is not atomic. This includes iteration and scanning.

For example, consider the following program:

let size = 100_000_000
let b = Bytes.make size  ' '
let update b f ()  =
  Bytes.iteri (fun i x -> Bytes.set b i (Char.chr (f (Char.code x)))) b
let d1 = Domain.spawn (update b (fun x -> x + 1))
let d2 = Domain.spawn (update b (fun x -> 2 * x + 1))
let () = Domain.join d1; Domain.join d2
the bytes sequence b may contain a non-deterministic mixture of '!' , 'A' , 'B' , and 'C' values.

After executing this code, each byte of the sequence b is either '!' , 'A' , 'B' , or 'C' . If atomicity is required, then the user must implement their own synchronization (for example, using Mutex.t ).

Data races

If two domains only access disjoint parts of a byte sequence, then the observed behaviour is the equivalent to some sequential interleaving of the operations from the two domains.

A data race is said to occur when two domains access the same byte without synchronization and at least one of the accesses is a write. In the absence of data races, the observed behaviour is equivalent to some sequential interleaving of the operations from different domains.

Whenever possible, data races should be avoided by using synchronization to mediate the accesses to the elements of the sequence.

Indeed, in the presence of data races, programs will not crash but the observed behaviour may not be equivalent to any sequential interleaving of operations from different domains. Nevertheless, even in the presence of data races, a read operation will return the value of some prior write to that location.

Mixed-size accesses

Another subtle point is that if a data race involves mixed-size writes and reads to the same location, the order in which those writes and reads are observed by domains is not specified. For instance, the following code write sequentially a 32-bit integer and a char to the same index

let b = Bytes.make 10 '\000'
let d1 = Domain.spawn (fun () -> Bytes.set_int32_ne b 0 100; b.[0] <- 'd' )

In this situation, a domain that observes the write of 'd' to b. 0 is not guaranteed to also observe the write to indices 1 , 2 , or 3 .
