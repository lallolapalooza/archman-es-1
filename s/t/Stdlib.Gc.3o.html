Los contadores de gestión de memoria se devuelven en un stat registro. Estos contadores dan valores para el programa completo.

La cantidad total de memoria asignada por el programa desde que se inició es (en palabras) minor_words + major_words - promoted_words . Multiplica por el tamaño de palabra (4 en un sistema 32-bit, 8 en un sistema 64-bit) para obtener el número de bytes.

Los parámetros de la GC se proporcionan como un registro de control. Tenga en cuenta que estos parámetros también se pueden inicializar estableciendo la variable de entorno OCAMLRUNPARAM. Consulte la documentación de ocamlrun.

val stat : unit -> stat

Devuelve los valores actuales de los contadores de gestión de memoria en un registro stat que representa las estadísticas totales de memoria del programa. Las métricas heap_chunks, free_blocks, largest_free y stack_size actualmente no están disponibles en OCaml 5: sus valores de campo devueltos son, por lo tanto, 0. Esta función provoca una recolección mayor completa.

val quick_stat : unit -> stat

Devuelve un registro con los valores actuales de los contadores de gestión de memoria como stat. A diferencia de stat, quick_stat no realiza una recolección mayor completa y, por lo tanto, es mucho más rápido. Sin embargo, quick_stat informa los contadores muestreados en la última recolección menor o al final del último ciclo de recolección mayor (el que sea más reciente). Por lo tanto, las estadísticas de memoria devueltas por quick_stat no son instantáneamente precisas.

val counters : unit -> float * float * float

Devuelve (minor_words, promoted_words, major_words) para el dominio actual o dominios anteriores. Esta función es tan rápida como quick_stat.

val minor_words : unit -> float

Número de palabras asignadas en el montón menor por este dominio o dominios anteriores. Este número es preciso en programas de bytecode, pero solo una aproximación en programas compilados a código nativo.

En código nativo, esta función no asigna.

val get : unit -> control

Devuelve los valores actuales de los parámetros de la GC en un registro control.

Los campos major_heap_increment, max_overhead, allocation_policy y window_size actualmente no están disponibles en OCaml 5: sus valores de campo devueltos son, por lo tanto, 0.

Precaución con accesos no sincronizados. Los parámetros de la GC son un estado global mutable.

val set : control -> unit

set r cambia los parámetros de la GC de acuerdo con el registro control r. El uso normal es: Gc.set { (Gc.get()) with Gc.verbose = 0x00d }

Los campos major_heap_increment, max_overhead, allocation_policy y window_size actualmente no están disponibles en OCaml 5: por lo tanto, establecerlos no tiene ningún efecto.

Precaución con accesos no sincronizados. Los parámetros de la GC son un estado global mutable.

val minor : unit -> unit

Desencadena una recolección menor.

val major_slice : int -> int

major_slice n Realiza una recolección menor y una porción de recolección mayor. n es el tamaño de la porción: la GC realizará el trabajo suficiente para liberar (en promedio) n palabras de memoria. Si n = 0, la GC intentará realizar el trabajo suficiente para asegurar que la próxima porción automática no tenga trabajo que hacer. Esta función devuelve un entero no especificado (actualmente: 0).

val major : unit -> unit

Realiza una recolección menor y finaliza el ciclo de recolección mayor actual.

val full_major : unit -> unit

Realiza una recolección menor, finaliza el ciclo de recolección mayor actual y realiza un ciclo nuevo completo. Esto liberará todos los bloques actualmente inalcanzables.

val compact : unit -> unit

Realiza una recolección mayor completa y compacta el montón. Tenga en cuenta que la compactación del montón es una operación larga.

val print_stat : out_channel -> unit

Imprime los valores actuales de los contadores de gestión de memoria (en formato legible por humanos) del programa total en el canal de argumento.

val allocated_bytes : unit -> float

Devuelve el número de bytes asignados por este dominio y potencialmente por un dominio anterior. Se devuelve como un float para evitar problemas de desbordamiento con int en máquinas de 32 bits.

val get_minor_free : unit -> int

Devuelve el tamaño actual del espacio libre dentro del montón menor de este dominio.

val finalise : ('a -> unit) -> 'a -> unit

finalise f v registra f como una función de finalización para v. v debe estar asignado en el montón. f se llamará con v como argumento en algún momento entre la primera vez que v se vuelve inalcanzable (incluido a través de punteros débiles) y el momento en que v es recolectado por la GC. Se pueden registrar varias funciones para el mismo valor, o incluso varias instancias de la misma función. Cada instancia se llamará una vez (o nunca, si el programa termina antes de que v se vuelva inalcanzable).

La GC llamará a las funciones de finalización en el orden de desasignación. Cuando varios valores se vuelven inalcanzables al mismo tiempo (es decir, durante el mismo ciclo de GC), las funciones de finalización se llamarán en orden inverso a las llamadas correspondientes a finalise. Si finalise se llama en el mismo orden en que se asignan los valores, significa que cada valor se finaliza antes que los valores de los que depende. Por supuesto, esto se vuelve falso si se introducen dependencias adicionales mediante asignaciones.

En presencia de varios hilos de OCaml, se debe asumir que cualquier finalizador particular puede ejecutarse en cualquiera de los hilos.

Todo lo que sea alcanzable desde la clausura de las funciones de finalización se considera alcanzable, por lo que el siguiente código no funcionará como se espera:

- let v = ... in Gc.finalise (fun _ -> ...v...) v

En su lugar, debe asegurarse de que v no esté en la clausura de la función de finalización escribiendo:

- let f = fun x -> ... let v = ... in Gc.finalise f v

La función f puede usar todas las características de OCaml, incluidas las asignaciones que hacen que el valor sea nuevamente alcanzable. También puede entrar en un bucle infinito (en este caso, las otras funciones de finalización no se llamarán durante la ejecución de f, a menos que llame a finalise_release). Puede llamar a finalise en v u otros valores para registrar otras funciones o incluso a sí misma. Puede generar una excepción; en este caso, la excepción interrumpirá lo que sea que el programa estuviera haciendo cuando se llamó a la función.

finalise generará Invalid_argument si no se garantiza que v esté asignado en el montón. Algunos ejemplos de valores que no están asignados en el montón son enteros, constructores constantes, booleanos, la matriz vacía, la lista vacía, el valor unit. La lista exacta de lo que está asignado en el montón o no depende de la implementación. Algunos valores constantes pueden estar asignados en el montón pero nunca desasignados durante la vida del programa, por ejemplo, una lista de constantes enteras; esto también depende de la implementación. Tenga en cuenta que los valores de tipo float a veces se asignan y a veces no, por lo que finalizarlos es inseguro, y finalise también generará Invalid_argument para ellos. Los valores de tipo 'a Lazy.t (para cualquier 'a) son como float en este aspecto, excepto que el compilador a veces los optimiza de manera que impide que finalise los detecte. En este caso, no generará Invalid_argument, pero aún así debe evitar llamar a finalise en valores perezosos.

Se garantiza que los resultados de llamar a String.make, Bytes.make, Bytes.create, Array.make y ref estén asignados en el montón y no sean constantes, excepto cuando el argumento de longitud es 0.

val finalise_last : (unit -> unit) -> 'a -> unit

igual que Gc.finalise excepto que el valor no se pasa como argumento. Por lo tanto, no puede usar el valor dado para el cálculo de la función de finalización. El beneficio es que la función se llama después de que el valor es inalcanzable por última vez en lugar de la primera vez. Por lo tanto, a diferencia de Gc.finalise, el valor nunca será alcanzable ni se usará nuevamente. En particular, todos los punteros débiles y ephemerons que contenían este valor como clave o dato se anulan antes de ejecutar la función de finalización. Además, las funciones de finalización adjuntas con Gc.finalise siempre se llaman antes que las funciones de finalización adjuntas con Gc.finalise_last.

val finalise_release : unit -> unit

Una función de finalización puede llamar a finalise_release para indicarle a la GC que puede lanzar la siguiente función de finalización sin esperar a que la actual regrese.

type alarm

Una alarma es una pieza de datos que llama a una función de usuario al final de un ciclo de GC mayor. Las siguientes funciones se proporcionan para crear y eliminar alarmas.

val create_alarm : (unit -> unit) -> alarm

create_alarm f hará que f se llame al final de los ciclos de GC mayores, no causados por f, comenzando con el ciclo actual o el siguiente. f se ejecutará en el mismo dominio que creó la alarma, hasta que el dominio termine o se llame a delete_alarm. Se devuelve un valor de tipo alarm que puede usar para llamar a delete_alarm.

No se garantiza que la alarma de GC se ejecute al final de cada ciclo de GC mayor, pero sí se garantiza que se ejecutará eventualmente.

Como ejemplo, aquí hay una forma rudimentaria de interrumpir una función si el consumo de memoria del programa excede un límite dado en MB, adecuado para su uso en el toplevel:

let run_with_memory_limit (limit : int) (f : unit -> 'a) : 'a =
  let limit_memory () =
    let mem = Gc.(quick_stat ()).heap_words in
    if mem / (1024 * 1024) > limit / (Sys.word_size / 8) then
      raise Out_of_memory
  in
  let alarm = Gc.create_alarm limit_memory in
  Fun.protect f ~finally:(fun () -> Gc.delete_alarm alarm ; Gc.compact ())

val delete_alarm : alarm -> unit

delete_alarm a detendrá las llamadas a la función asociada con a. Volver a llamar a delete_alarm a no tiene ningún efecto.

module Memprof : sig end

Memprof es un motor de perfilado que muestrea aleatoriamente palabras de memoria asignadas. Cada palabra asignada tiene una probabilidad de ser muestreada igual a una tasa de muestreo configurable. Una vez que se muestrea un bloque, se rastrea. Un bloque rastreado desencadena una devolución de llamada definida por el usuario tan pronto como se asigna, se promueve o se desasigna.

Gc

NAME

Gc - control the garbage collector

Module

Stdlib

Documentation

The functions in this module allow you to control the garbage collector. The OCaml garbage collector is a generational garbage collector with a specific mechanism to handle the allocation of large objects (see Section 2.13.2 of the manual).

The GC is designed to work in a steady-state memory usage. If you know that your program will experience phases of significant memory usage increase, it is advisable to use the functions ramp_up and ramp_down.

The GC can be used to implement low-overhead memory profilers.

Note: this API is EXPERIMENTAL. It may change without prior notice.

type suspended_collection_work

val ramp_up : (unit -> 'a) -> 'a * suspended_collection_work

This function takes a function f and executes it in a "ramp-up" phase. This phase informs the GC that the program's live memory usage is expected to increase significantly. This is useful to avoid unnecessary GC work during periods of high allocation.

During a ramp-up phase, the GC suspends some of its collection work. The amount of suspended work is returned as the second element of the tuple. If this suspended work is not later resumed using ramp_down, the memory allocated during the ramp-up phase might not be reclaimed until the program terminates.

If the function f raises an exception, the ramp-up phase is aborted, the suspended collection work is resumed, and the exception is re-raised.

If the function f performs an effect that is not handled, an Effect.Unhandled exception is raised instead of the effect being propagated.

val ramp_down : suspended_collection_work -> unit

This function resumes collection work that was suspended by a previous call to ramp_up. It should be called when the memory allocated during the ramp-up phase is no longer needed.
