val rename : string -> string -> unit

Renombra un archivo o directorio. rename oldpath newpath renombra el archivo o directorio llamado oldpath , dándole newpath como su nuevo nombre, moviéndolo entre (directorios padre) si es necesario. Si ya existe un archivo llamado newpath , su contenido se reemplazará con el de oldpath . Dependiendo del sistema operativo, los metadatos (permisos, propietario, etc.) de newpath pueden conservarse o reemplazarse por los de oldpath .

val command : string -> int

Ejecuta el comando de shell dado y devuelve su código de salida.

El argumento de Sys.command es generalmente el nombre de un comando seguido de cero, uno o varios argumentos, separados por espacios en blanco. El argumento dado es interpretado por un shell: ya sea el shell de Windows cmd.exe para los puertos Win32 de OCaml, o el shell POSIX sh para otros puertos. Puede contener comandos integrados del shell como echo , y también caracteres especiales como redirecciones de archivo > y < , que serán tenidos en cuenta por el shell.

Por el contrario, los espacios en blanco o los caracteres especiales del shell que ocurran en los nombres de los comandos o en sus argumentos deben citarse o escaparse para que el shell no los interprete. Las reglas de citación varían entre el shell POSIX y el shell de Windows. Filename.quote_command realiza la citación adecuada dado un nombre de comando, una lista de argumentos y redirecciones de archivo opcionales.

val readdir : string -> string array

Devuelve los nombres de todos los archivos presentes en el directorio dado. Los nombres que denotan el directorio actual y el directorio padre ( "." y ".." en Unix) no se devuelven. Cada cadena en el resultado es un nombre de archivo en lugar de una ruta completa. No hay garantía de que las cadenas de nombres en el array resultante aparezcan en ningún orden específico; no se garantiza, en particular, que aparezcan en orden alfabético.

val io_buffer_size : int

Tamaño de los búferes C utilizados por el sistema de tiempo de ejecución y las primitivas de E/S de la biblioteca unix .

Las primitivas que leen o escriben en valores de tipo string o bytes generalmente utilizan un búfer intermedio de este tamaño para evitar mantener el bloqueo de dominio.

Manejo de señales

type signal = int

El tipo para números de señal.

OCaml utiliza números negativos para proporcionar un número independiente de la plataforma para las señales reconocidas por OCaml. Los números positivos son siempre el valor dependiente de la plataforma para una señal dada. La función Sys.signal_of_int convierte números dependientes de la plataforma conocidos a otros independientes, y Sys.signal_to_int hace lo contrario.

Desde 5.4

type signal_behavior =
| Signal_default
| Signal_ignore
| Signal_handle of (signal -> unit)

Qué hacer al recibir una señal:

- Signal_default : tomar el comportamiento por defecto (normalmente: abortar el programa)

- Signal_ignore : ignorar la señal

- Signal_handle f : llamar a la función f , dándole el número de señal como argumento.

val signal : signal -> signal_behavior -> signal_behavior

Establece el comportamiento del sistema al recibir una señal dada. El primer argumento es el número de señal. Devuelve el comportamiento previamente asociado a la señal. Si el número de señal no es válido (o no está disponible en su sistema), se lanza una excepción Invalid_argument.

Si se utiliza un número de señal dependiente de la plataforma, se convertirá a una señal independiente de la plataforma usando Sys.signal_of_int antes de llamar al manejador.

val set_signal : signal -> signal_behavior -> unit

Igual que Sys.signal pero se ignora el valor de retorno.

exception Break

Excepción lanzada ante interrupción interactiva si Sys.catch_break está habilitado.

val catch_break : bool -> unit

catch_break controla si la interrupción interactiva (ctrl-C) termina el programa o lanza la excepción Break. Llame a catch_break true para habilitar el lanzamiento de Break, y catch_break false para permitir que el sistema termine el programa ante una interrupción del usuario.

Dentro de programas multihilo, la excepción Break surgirá en cualquiera de los hilos activos, y seguirá surgiendo ante interrupciones interactivas posteriores hasta que todos los hilos terminen. Utilice máscaras de señal de Thread.sigmask para dirigir la interrupción hacia un hilo específico.

val ocaml_version : string

ocaml_version es la versión de OCaml. Es una cadena con el formato "major.minor[.patchlevel][(+|~)additional-info]", donde major, minor y patchlevel son enteros, y additional-info es una cadena arbitraria. La parte [.patchlevel] estuvo ausente antes de la versión 3.08.0 y se volvió obligatoria a partir de la versión 3.08.0. La parte [(+|~)additional-info] puede estar ausente.

val development_version : bool

true si esta es una versión de desarrollo, false en caso contrario.

Optimización

val opaque_identity : 'a -> 'a

A efectos de optimización, opaque_identity se comporta como una función desconocida (y por lo tanto, posiblemente con efectos secundarios).

En tiempo de ejecución, opaque_identity desaparece por completo. Sin embargo, evita que el argumento sea recolectado por el recolector de basura hasta la ubicación donde habría ocurrido la llamada.

Un uso típico de esta función es evitar que cálculos puros sean optimizados en bucles de benchmarking. Por ejemplo:

      for _round = 1 to 100_000 do
        ignore (Sys.opaque_identity (my_pure_computation ()))
      done
