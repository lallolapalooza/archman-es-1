Módulo Buffer

Acceso no sincronizado

El acceso no sincronizado a un buffer puede llevar a un estado inválido del buffer. Por lo tanto, los accesos concurrentes a un buffer deben estar sincronizados (por ejemplo, con un Mutex.t ).

type t

El tipo abstracto de buffers.

val create : int -> t

create n devuelve un nuevo buffer, inicialmente vacío. El parámetro n es el tamaño inicial de la secuencia de bytes interna que almacena el contenido del buffer. Dicha secuencia de bytes se reasigna automáticamente cuando se almacenan más de n caracteres en el buffer, pero se reduce de nuevo a n caracteres cuando se llama a reset. Para un mejor rendimiento, n debe ser del mismo orden de magnitud que el número de caracteres que se espera almacenar en el buffer (por ejemplo, 80 para un buffer que contiene una línea de salida). Nada malo ocurrirá si el buffer crece más allá de ese límite, sin embargo. En caso de duda, tome n = 16 por ejemplo. Si n no está entre 1 y Sys.max_string_length , se recortará a ese intervalo.

val contents : t -> string

Devuelve una copia del contenido actual del buffer. El buffer en sí no se modifica.

val to_bytes : t -> bytes

Devuelve una copia del contenido actual del buffer. El buffer en sí no se modifica.

val sub : t -> int -> int -> string

Buffer.sub b off len devuelve una copia de len bytes del contenido actual del buffer b , comenzando en el desplazamiento off.

Lanza Invalid_argument si off y len no designan un rango válido de b.

val blit : t -> int -> bytes -> int -> int -> unit

Buffer.blit src srcoff dst dstoff len copia len caracteres del contenido actual del buffer src , comenzando en el desplazamiento srcoff a dst , comenzando en el carácter dstoff.

Desde 3.11.2

Lanza Invalid_argument si srcoff y len no designan un rango válido de src , o si dstoff y len no designan un rango válido de dst.

val nth : t -> int -> char

Obtiene el n-ésimo carácter del buffer.

Lanza Invalid_argument si el índice está fuera de los límites.

val length : t -> int

Devuelve el número de caracteres contenidos actualmente en el buffer.

val clear : t -> unit

Vacía el buffer.

val reset : t -> unit

Vacía el buffer y desasigna la secuencia de bytes interna que almacena el contenido del buffer, reemplazándola con la secuencia de bytes interna inicial de longitud n que fue asignada por Buffer.create n. Para buffers de larga duración que pueden haber crecido mucho, reset permite una recuperación más rápida del espacio utilizado por el buffer.

val output_buffer : out_channel -> t -> unit

output_buffer oc b escribe el contenido actual del buffer b en el canal de salida oc.

val truncate : t -> int -> unit

truncate b len trunca la longitud de b a len. Nota: la secuencia de bytes interna no se acorta.

Desde 4.05

Lanza Invalid_argument si len < 0 o len > length b.

val add_substitute : t -> (string -> string) -> string -> unit

add_substitute b f s añade el patrón de cadena s al final del buffer b con sustitución. El proceso de sustitución busca referencias de variables en el patrón y sustituye cada referencia de variable con su valor, obtenido al aplicar la asignación f al nombre de la variable. Dentro del patrón de cadena, una referencia de variable es un $ no escapado seguido inmediatamente por un nombre de variable, que es uno de los siguientes:

-una secuencia no vacía de caracteres alfanuméricos o _,

-una secuencia arbitraria de caracteres encerrada entre un par de paréntesis o corchetes correspondientes. Un carácter $ escapado es un $ que sigue inmediatamente a un carácter de barra invertida; los dos caracteres juntos representan un $ simple.

val add_buffer : t -> t -> unit

add_buffer b1 b2 añade el contenido actual del buffer b2 al final del buffer b1. b2 no se modifica.

val add_channel : t -> in_channel -> int -> unit

add_channel b ic n lee como máximo n caracteres del canal de entrada ic y los almacena al final del buffer b.

Lanza End_of_file si el canal contiene menos de n caracteres. En este caso, los caracteres aún se añaden al buffer, para evitar la pérdida de datos.

Codificación binaria de enterosLas funciones de esta sección añaden codificaciones binarias de enteros a buffers.

La codificación de endianness (resp. big-endian) implica que los bytes menos significativos (resp. más significativos) se almacenan primero. El big-endian también se conoce como orden de bytes de red. La codificación nativa de endianness es de tipo little-endian o big-endian según el valor de Sys.big_endian.
Los enteros de 32 y 64 bits se representan mediante los tipos int32 y int64, que pueden interpretarse tanto como números enteros negativos como positivos.
Los enteros de 8 y 16 bits se representan mediante el tipo int, que tiene más bits que la codificación binaria. Las funciones que codifican estos valores truncan sus entradas a sus bytes más significativos.
