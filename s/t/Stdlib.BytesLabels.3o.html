val length : bytes -> int

Devuelve la longitud (número de bytes) del argumento.

val get : bytes -> int -> char

get s n devuelve el byte en el índice n del argumento s.

Lanza Invalid_argument si n no es un índice válido en s.

val set : bytes -> int -> char -> unit

set s n c modifica s en su lugar, reemplazando el byte en el índice n con c.

Lanza Invalid_argument si n no es un índice válido en s.

val create : int -> bytes

create n devuelve una nueva secuencia de bytes de longitud n. La secuencia no está inicializada y contiene bytes arbitrarios.

Lanza Invalid_argument si n < 0 o n > Sys.max_string_length.

val make : int -> char -> bytes

make n c devuelve una nueva secuencia de bytes de longitud n, rellenada con el byte c.

Lanza Invalid_argument si n < 0 o n > Sys.max_string_length.

val init : int -> f:(int -> char) -> bytes

init n f devuelve una nueva secuencia de bytes de longitud n, con el carácter i inicializado con el resultado de f i (en orden de índice creciente).

Lanza Invalid_argument si n < 0 o n > Sys.max_string_length.

val empty : bytes

Una secuencia de bytes de tamaño 0.

val copy : bytes -> bytes

Devuelve una nueva secuencia de bytes que contiene los mismos bytes que el argumento.

val of_string : string -> bytes

Devuelve una nueva secuencia de bytes que contiene los mismos bytes que la cadena dada.

val to_string : bytes -> string

Devuelve una nueva cadena que contiene los mismos bytes que la secuencia de bytes dada.

val sub : bytes -> pos:int -> len:int -> bytes

sub s ~pos ~len devuelve una nueva secuencia de bytes de longitud len, que contiene la sub-secuencia de s que comienza en la posición pos y tiene longitud len.

Lanza Invalid_argument si pos y len no designan un rango válido de s.

val sub_string : bytes -> pos:int -> len:int -> string

Igual que BytesLabels.sub pero devuelve una cadena en lugar de una secuencia de bytes.

val extend : bytes -> left:int -> right:int -> bytes

extend s ~left ~right devuelve una nueva secuencia de bytes que contiene los bytes de s, con left bytes no inicializados añadidos al principio y right bytes no inicializados añadidos al final. Si left o right son negativos, entonces se eliminan bytes (en lugar de añadirse) del lado correspondiente de s.

Lanza Invalid_argument si la longitud resultante es negativa o mayor que Sys.max_string_length bytes.

val fill : bytes -> pos:int -> len:int -> char -> unit

fill s ~pos ~len c modifica s en su lugar, reemplazando len caracteres con c, comenzando en pos.

Lanza Invalid_argument si pos y len no designan un rango válido de s.

val blit : src:bytes -> src_pos:int -> dst:bytes -> dst_pos:int -> len:int -> unit

blit ~src ~src_pos ~dst ~dst_pos ~len copia len bytes de la secuencia de bytes src, comenzando en el índice src_pos, a la secuencia de bytes dst, comenzando en el índice dst_pos. Funciona correctamente incluso si src y dst son la misma secuencia de bytes, y los intervalos de origen y destino se superponen.

Lanza Invalid_argument si src_pos y len no designan un rango válido de src, o si dst_pos y len no designan un rango válido de dst.

blit_string ~src ~src_pos ~dst ~dst_pos ~len copia len bytes de la cadena src, comenzando en el índice src_pos, a la secuencia de bytes dst, comenzando en el índice dst_pos.

val iter : f:(char -> unit) -> bytes -> unit

iter ~f s aplica la función f en turno a todos los bytes de s. Es equivalente a f (get s 0); f (get s 1); ...; f (get s
(length s - 1)); ().

val iteri : f:(int -> char -> unit) -> bytes -> unit

Igual que BytesLabels.iter, pero la función se aplica al índice del byte como primer argumento y al byte mismo como segundo argumento.

val map : f:(char -> char) -> bytes -> bytes

map ~f s aplica la función f en turno a todos los bytes de s (en orden de índice creciente) y almacena los bytes resultantes en una nueva secuencia que se devuelve como resultado.

val mapi : f:(int -> char -> char) -> bytes -> bytes

mapi ~f s llama a f con cada carácter de s y su índice (en orden de índice creciente) y almacena los bytes resultantes en una nueva secuencia que se devuelve como resultado.

Conversiones inseguras (para usuarios avanzados)

Esta sección describe funciones de conversión inseguras y de bajo nivel entre bytes y string. No copian los datos internos; usadas incorrectamente, pueden romper el invariante de inmutabilidad en las cadenas. Están disponibles para autores de bibliotecas expertas, pero para la mayoría de los propósitos deberías usar BytesLabels.to_string y BytesLabels.of_string, que siempre son correctas, en su lugar.

val unsafe_to_string : bytes -> string

Convierte inseguramente una secuencia de bytes en una cadena.

Para razonar sobre el uso de unsafe_to_string, es útil considerar una disciplina de "propiedad". Un fragmento de código que manipula algún dato lo "posee"; hay varios modos de propiedad disjuntos, incluyendo:

- Propiedad única: el dato puede ser accedido y mutado

- Propiedad compartida: el dato tiene varios propietarios, que solo pueden accederlo, no mutarlo.

La propiedad única es lineal: pasar el dato a otro fragmento de código significa ceder la propiedad (no podemos volver a escribir el dato). Un propietario único puede decidir hacer que el dato sea compartido (renunciando a los derechos de mutación sobre él), pero los datos compartidos no pueden volver a ser de propiedad única.

unsafe_to_string s solo se puede usar cuando el llamador posee la secuencia de bytes s, ya sea de forma única o como datos inmutables compartidos. El llamador cede la propiedad de s y adquiere la propiedad de la cadena resultante.

Hay dos casos de uso válidos que respetan esta disciplina de propiedad:

1. Creación de una cadena inicializando y mutando una secuencia de bytes que nunca se modifica después de realizar la inicialización.

let string_init len f : string =
  let s = Bytes.create len in
  for i = 0 to len - 1 do Bytes.set s i (f i) done;
  Bytes.unsafe_to_string s

Esta función es segura porque la secuencia de bytes s nunca será accedida o mutada después de que se llame a unsafe_to_string. El código string_init cede la propiedad de s y devuelve la propiedad de la cadena resultante a su llamador.

Ten en cuenta que sería inseguro si s fuera pasado como un parámetro adicional a la función f, ya que podría escaparse de esta manera y ser mutado en el futuro; string_init cedería la propiedad de s para pasarlo a f y no podría llamar a unsafe_to_string de forma segura.

Hemos proporcionado las funciones String.init, String.map y String.mapi para cubrir la mayoría de los casos de construcción de nuevas cadenas. Deberías preferirlas sobre to_string o unsafe_to_string siempre que sea aplicable.

2. Ceder temporalmente la propiedad de una secuencia de bytes a una función que espera una cadena de propiedad única y devuelve la propiedad, para que podamos mutar la secuencia nuevamente después de que la llamada termine.

let bytes_length (s : bytes) =
  String.length (Bytes.unsafe_to_string s)

En este caso de uso, no prometemos que s nunca será mutado después de la llamada a bytes_length s. La función String.length toma prestada temporalmente la propiedad única de la secuencia de bytes (y la ve como una string), pero devuelve esta propiedad al llamador, que puede asumir que s sigue siendo una secuencia de bytes válida después de la llamada. Ten en cuenta que esto solo es correcto porque sabemos que String.length no captura su argumento; podría escapar por un canal lateral como un combinador de memoización.

El llamador no puede mutar s mientras la cadena está prestada (ha cedido temporalmente la propiedad). Esto afecta a los programas concurrentes, pero también a las funciones de orden superior: si String.length devolviera un cierre para ser llamado más tarde, s no debería ser mutado hasta que este cierre se aplique completamente y devuelva la propiedad.

val unsafe_of_string : string -> bytes

Convierte inseguramente una cadena compartida a una secuencia de bytes que no debe ser mutada.

La misma disciplina de propiedad que hace que unsafe_to_string sea correcto se aplica a unsafe_of_string: puedes usarla si eras el propietario del valor string, y poseerás el bytes resultante en el mismo modo.

En la práctica, la propiedad única de los valores de cadena es extremadamente difícil de razonar correctamente. Siempre debes asumir que las cadenas son compartidas, nunca de propiedad única.

Por ejemplo, las cadenas literales son implícitamente compartidas por el compilador, por lo que nunca las posees de forma única.

let incorrect = Bytes.unsafe_of_string "hello"
let s = Bytes.of_string "hello"

La primera declaración es incorrecta, porque la cadena literal "hello" podría ser compartida por el compilador con otras partes del programa, y mutar incorrect es un error. Siempre debes usar la segunda versión, que realiza una copia y por lo tanto es correcta.

Asumir propiedad única de cadenas que no son cadenas literales, pero que están (parcialmente) construidas a partir de cadenas literales, también es incorrecto. Por ejemplo, mutar unsafe_of_string ("foo" ^ s) podría mutar la cadena compartida "foo", asumiendo una representación de cadenas tipo cuerda (rope). Más generalmente, las funciones que operan en cadenas asumirán propiedad compartida, no preservan la propiedad única. Por lo tanto, es incorrecto asumir propiedad única del resultado.
