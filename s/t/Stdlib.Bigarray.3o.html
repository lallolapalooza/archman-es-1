Tipos de elementos

Los Bigarrays pueden contener elementos de los siguientes tipos:

-números de punto flotante de media precisión IEEE (16 bits) ( Bigarray.float16_elt ),

-números de punto flotante de precisión simple IEEE (32 bits) ( Bigarray.float32_elt ),

-números de punto flotante de precisión doble IEEE (64 bits) ( Bigarray.float64_elt ),

-números complejos de punto flotante de precisión simple IEEE (2 * 32 bits) ( Bigarray.complex32_elt ),

-números complejos de punto flotante de precisión doble IEEE (2 * 64 bits) ( Bigarray.complex64_elt ),

-enteros de 8 bits (con signo o sin signo) ( Bigarray.int8_signed_elt o Bigarray.int8_unsigned_elt ),

-enteros de 16 bits (con signo o sin signo) ( Bigarray.int16_signed_elt o Bigarray.int16_unsigned_elt ),

-enteros OCaml (con signo, 31 bits en arquitecturas de 32 bits, 63 bits en arquitecturas de 64 bits) ( Bigarray.int_elt ),

-enteros con signo de 32 bits ( Bigarray.int32_elt ),

-enteros con signo de 64 bits ( Bigarray.int64_elt ),

-enteros con signo nativos de la plataforma (32 bits en arquitecturas de 32 bits, 64 bits en arquitecturas de 64 bits) ( Bigarray.nativeint_elt ).

Cada tipo de elemento se representa a nivel de tipo mediante uno de los tipos *_elt definidos a continuación (definidos con un único constructor en lugar de tipos abstractos por razones técnicas de inyectividad).

A cada tipo de elemento se asocia un tipo OCaml, que es el tipo de los valores OCaml que se pueden almacenar en el Bigarray o leer de él. Este tipo no es necesariamente el mismo que el tipo de los elementos de la matriz: por ejemplo, un Bigarray cuyos elementos son de tipo float32_elt contiene flotantes de precisión simple de 32 bits, pero leer o escribir uno de sus elementos desde OCaml utiliza el tipo OCaml float , que son flotantes de precisión doble de 64 bits.

El tipo GADT ('a, 'b) kind captura esta asociación de un tipo OCaml 'a para los valores leídos o escritos en el Bigarray, y de un tipo de elemento 'b que representa el contenido real del Bigarray. Sus constructores listan todas las asociaciones posibles de tipos OCaml con tipos de elementos y se reexportan a continuación por razones de compatibilidad retroactiva.

El uso de un tipo de dato algebraico generalizado (GADT) permite escribir funciones polimórficas bien tipadas cuyo tipo de retorno depende del tipo de argumento, como:

  let zero : type a b. (a, b) kind -> a = function
    | Float32 -> 0.0 | Complex32 -> Complex.zero
    | Float64 -> 0.0 | Complex64 -> Complex.zero
    | Float16 -> 0.0
    | Int8_signed -> 0 | Int8_unsigned -> 0
    | Int16_signed -> 0 | Int16_unsigned -> 0
    | Int32 -> 0l | Int64 -> 0L
    | Int -> 0 | Nativeint -> 0n
    | Char -> '\000'

Como se muestra en los tipos de los valores anteriores, los Bigarrays de tipo float16_elt , float32_elt y float64_elt se acceden utilizando el tipo OCaml float . Los Bigarrays de tipos complejos complex32_elt , complex64_elt se acceden con el tipo OCaml Complex.t . Los Bigarrays de tipos enteros se acceden utilizando el tipo entero OCaml más pequeño lo suficientemente grande como para representar los elementos de la matriz: int para Bigarrays enteros de 8 y 16 bits, así como Bigarrays de enteros OCaml; int32 para Bigarrays enteros de 32 bits; int64 para Bigarrays enteros de 64 bits; y nativeint para Bigarrays enteros nativos de la plataforma. Finalmente, los Bigarrays de tipo int8_unsigned_elt también se pueden acceder como matrices de caracteres en lugar de matrices de enteros pequeños, utilizando el valor de tipo char en lugar de int8_unsigned .

Disposiciones de matrices

| C_layout_typ

Ver Bigarray.fortran_layout .

type fortran_layout =
| Fortran_layout_typ

Para facilitar la interoperabilidad con código C y Fortran existente, esta biblioteca admite dos disposiciones de memoria diferentes para los Bigarrays, una compatible con las convenciones de C, la otra compatible con las convenciones de Fortran.

En la disposición de estilo C, los índices de la matriz comienzan en 0, y las matrices multidimensionales se organizan en formato de orden de fila. Es decir, para una matriz bidimensional, todos los elementos de la fila 0 son contiguos en memoria, seguidos por todos los elementos de la fila 1, etc. En otras palabras, los elementos de la matriz en (x,y) y (x, y+1) son adyacentes en memoria.

En la disposición de estilo Fortran, los índices de la matriz comienzan en 1, y las matrices multidimensionales se organizan en orden de columna

The module Bigarray defines the low-level interface to bigarrays.
For most applications, you should use the modules Bigarray.Array1 ,
Bigarray.Array2 , or Bigarray.Array3 , which provide
arrays of fixed dimension.



The bigarray library provides arrays that can be used to store
    elements of any OCaml type. They offer efficient access to data and can be
    used to interface with external libraries written in C or Fortran.



Bigarrays are multi-dimensional arrays. The number of dimensions,
    the type of the elements and the memory layout can be specified.



The element type of a bigarray is represented by a type
    parameter 'a. The memory layout is represented by a
    type parameter 'b. The memory kind is represented by
    a type parameter 'c.



The memory layout can be either:



    

  • C layout: the array is row-major. For a two-dimensional array,
        all elements of row 0 are contiguous in memory, followed by all
        elements of row 1, etc. In other terms, the array elements at
        (x,y) and (x, y+1) are adjacent in memory.
    • 

  • Fortran layout: the array is column-major. For a two-dimensional
        array, all elements of column 0 are contiguous in memory, followed by
        all elements of column 1, etc. In other terms, the array elements at
        (x,y) and (x+1, y) are adjacent in memory.
    • 




Each layout style is identified at the type level by the phantom
    types Bigarray.c_layout and Bigarray.fortran_layout
    respectively.

Supported layouts

The GADT type 'a layout represents one of the two supported memory layouts: C-style or Fortran-style. Its constructors are re-exported as values below for backward-compatibility reasons.

type 'a layout =
| C_layout : c_layout layout
| Fortran_layout : fortran_layout layout

Re-shaping Bigarrays

val reshape : ('a, 'b, 'c) Genarray.t -> int array -> ('a, 'b, 'c) Genarray.t

reshape b [|d1;...;dN|] converts the Bigarray b to a N -dimensional array of dimensions d1 ... dN . The returned array and the original array b share their data and have the same layout. For instance, assuming that b is a one-dimensional array of dimension 12, reshape b [|3;4|] returns a two-dimensional array b' of dimensions 3 and 4. If b has C layout, the element (x,y) of b' corresponds to the element x * 3 + y of b . If b has Fortran layout, the element (x,y) of b' corresponds to the element x + (y - 1) * 4 of b . The returned Bigarray must have exactly the same number of elements as the original Bigarray b . That is, the product of the dimensions of b must be equal to i1 * ... * iN . Otherwise, Invalid_argument is raised.

Bigarrays and concurrency safety

Care must be taken when concurrently accessing bigarrays from multiple domains: accessing a bigarray will never crash a program, but unsynchronized accesses might yield surprising (non-sequentially-consistent) results.

Atomicity

Every bigarray operation that accesses more than one array element is not atomic. This includes slicing, bliting, and filling bigarrays.

For example, consider the following program:

open Bigarray
let size = 100_000_000
let a = Array1.init Int C_layout size (fun _ -> 1)
let update f a () =
  for i = 0 to size - 1 do a.{i} <- f a.{i} done
let d1 = Domain.spawn (update (fun x -> x + 1) a)
let d2 = Domain.spawn (update (fun x -> 2 * x + 1) a)
let () = Domain.join d1; Domain.join d2

After executing this code, each field of the bigarray a is either 2 , 3 , 4 or 5 . If atomicity is required, then the user must implement their own synchronization (for example, using Mutex.t ).

Data races

If two domains only access disjoint parts of the bigarray, then the observed behaviour is the equivalent to some sequential interleaving of the operations from the two domains.

A data race is said to occur when two domains access the same bigarray element without synchronization and at least one of the accesses is a write. In the absence of data races, the observed behaviour is equivalent to some sequential interleaving of the operations from different domains.

Whenever possible, data races should be avoided by using synchronization to mediate the accesses to the bigarray elements.

Indeed, in the presence of data races, programs will not crash but the observed behaviour may not be equivalent to any sequential interleaving of operations from different domains.

Tearing

Bigarrays have a distinct caveat in the presence of data races: concurrent bigarray operations might produce surprising values due to tearing. More precisely, the interleaving of partial writes and reads might create values that would not exist with a sequential execution. For instance, at the end of

let res = Array1.init Complex64 c_layout size (fun _ -> Complex.zero)
let d1 = Domain.spawn (fun () -> Array1.fill res Complex.one)
let d2 = Domain.spawn (fun () -> Array1.fill res Complex.i)
let () = Domain.join d1; Domain.join d2

the res bigarray might contain values that are neither Complex.i nor Complex.one (for instance 1 + i ).
