type 'a t = 'a array

Un alias para el tipo de arrays.

val length : 'a array -> int

Devuelve la longitud (número de elementos) del array dado.

val get : 'a array -> int -> 'a

get a n devuelve el elemento número n del array a . El primer elemento tiene el número 0. El último elemento tiene el número length a - 1 . También puedes escribir a.(n) en lugar de get a n .

Raises Invalid_argument si n está fuera del rango 0 a (length a - 1) .

val set : 'a array -> int -> 'a -> unit

set a n x modifica el array a in situ, reemplazando el elemento número n con x . También puedes escribir a.(n) <- x en lugar de set a n x .

Raises Invalid_argument si n está fuera del rango 0 a length a - 1 .

val make : int -> 'a -> 'a array

make n x devuelve un nuevo array de longitud n , inicializado con x . Todos los elementos de este nuevo array son inicialmente físicamente iguales a x (en el sentido del predicado == ). Consecuentemente, si x es mutable, se comparte entre todos los elementos del array, y modificar x a través de una de las entradas del array modificará todas las demás entradas al mismo tiempo.

Raises Invalid_argument si n < 0 o n > Sys.max_array_length . Si el valor de x es un número de punto flotante, entonces el tamaño máximo es solo Sys.max_array_length / 2 .

val create_float : int -> float array

create_float n devuelve un nuevo array de floats de longitud n , con datos no inicializados.

Since 4.03

val init : int -> (int -> 'a) -> 'a array

init n f devuelve un nuevo array de longitud n , con el elemento número i inicializado al resultado de f i . En otras palabras, init n f tabula los resultados de f aplicados en orden a los enteros 0 a n-1 .

Raises Invalid_argument si n < 0 o n > Sys.max_array_length . Si el tipo de retorno de f es float , entonces el tamaño máximo es solo Sys.max_array_length / 2 .

val make_matrix : int -> int -> 'a -> 'a array array

make_matrix dimx dimy e devuelve un array bidimensional (un array de arrays) con primera dimensión dimx y segunda dimensión dimy . Todos los elementos de esta nueva matriz son inicialmente físicamente iguales a e . El elemento ( x,y ) de una matriz m se accede con la notación m.(x).(y) .

Raises Invalid_argument si dimx o dimy es negativo o mayor que Sys.max_array_length . Si el valor de e es un número de punto flotante, entonces el tamaño máximo es solo Sys.max_array_length / 2 .

val init_matrix : int -> int -> (int -> int -> 'a) -> 'a array array

init_matrix dimx dimy f devuelve un array bidimensional (un array de arrays) con primera dimensión dimx y segunda dimensión dimy , donde el elemento en el índice ( x,y ) se inicializa con f x y . El elemento ( x,y ) de una matriz m se accede con la notación m.(x).(y) .

Since 5.2

Raises Invalid_argument si dimx o dimy es negativo o mayor que Sys.max_array_length . Si el tipo de retorno de f es float , entonces el tamaño máximo es solo Sys.max_array_length / 2 .

val append : 'a array -> 'a array -> 'a array

append v1 v2 devuelve un nuevo array que contiene la concatenación de los arrays v1 y v2 .

Raises Invalid_argument si length v1 + length v2 > Sys.max_array_length .

val concat : 'a array list -> 'a array

Igual que Array.append , pero concatena una lista de arrays.

val sub : 'a array -> int -> int -> 'a array

sub a pos len devuelve un nuevo array de longitud len , que contiene los elementos del número pos al pos + len - 1 del array a .

Raises Invalid_argument si pos y len no designan un subarray válido de a ; es decir, si pos < 0 , o len < 0 , o pos + len > length a .

val copy : 'a array -> 'a array

copy a devuelve una copia de a , es decir, un nuevo array que contiene los mismos elementos que a .

val fill : 'a array -> int -> int -> 'a -> unit

fill a pos len x modifica el array a in situ, almacenando x en los elementos del número pos al pos + len - 1 .

Raises Invalid_argument si pos y len no designan un subarray válido de a .

val blit : 'a array -> int -> 'a array -> int -> int -> unit

blit src src_pos dst dst_pos len copia len elementos del array src , comenzando en el elemento número src_pos , al array dst , comenzando en el elemento número dst_pos . Funciona correctamente incluso si src y dst son el mismo array, y los fragmentos de origen y destino se solapan.

Raises Invalid_argument si src_pos y len no designan un subarray válido de src , o si dst_pos y len no designan un subarray válido de dst .

val to_list : 'a array -> 'a list

to_list a devuelve la lista de todos los elementos de a .

val of_list : 'a list -> 'a array

of_list l devuelve un nuevo array que contiene los elementos de l .

Raises Invalid_argument si la longitud de l es mayor que Sys.max_array_length .

Ordenación y barajado

val sort : ('a -> 'a -> int) -> 'a array -> unit

Ordena un array en orden ascendente según una función de comparación. La función de comparación debe devolver 0 si sus argumentos se comparan como iguales, un entero positivo si el primero es mayor y un entero negativo si el primero es menor (ver más abajo para una especificación completa). Por ejemplo, compare es una función de comparación adecuada. Después de llamar a sort, el array se ordena in situ en orden ascendente. Se garantiza que sort se ejecuta en espacio de heap constante y (como máximo) espacio de pila logarítmico.

La implementación actual utiliza Heap Sort. Se ejecuta en espacio de pila constante.

Especificación de la función de comparación: Sean a el array y cmp la función de comparación. Lo siguiente debe ser cierto para todos los x, y, z en a:

- cmp x y > 0 si y solo si cmp y x < 0

- si cmp x y >= 0 y cmp y z >= 0 entonces cmp x z >= 0

Cuando sort devuelve, a contiene los mismos elementos que antes, reordenados de tal manera que para todos los índices i y j válidos de a:

- cmp a.(i) a.(j) >= 0 si i >= j

val stable_sort : ('a -> 'a -> int) -> 'a array -> unit

Igual que Array.sort, pero el algoritmo de ordenación es estable (es decir, los elementos que se comparan como iguales conservan su orden original) y no se garantiza que se ejecute en espacio de heap constante.

La implementación actual utiliza Merge Sort. Utiliza un array temporal de longitud n/2, donde n es la longitud del array. Generalmente es más rápido que la implementación actual de Array.sort.

val fast_sort : ('a -> 'a -> int) -> 'a array -> unit

Igual que Array.sort o Array.stable_sort, el que sea más rápido en entradas típicas.

val shuffle : rand:(int -> int) -> 'a array -> unit

shuffle rand a permuta aleatoriamente los elementos de a usando rand para la aleatoriedad. La distribución de las permutaciones es uniforme.

rand debe ser tal que una llamada a rand n devuelva un número aleatorio uniformemente distribuido en el rango [ 0 ; n-1 ]. Random.int puede usarse para esto (no olvides Random.self_init el generador).

Arrays y seguridad en concurrencia

Se debe tener cuidado al acceder a arrays de forma concurrente desde múltiples dominios: el acceso a un array nunca provocará un bloqueo del programa, pero los accesos no sincronizados pueden producir resultados sorprendentes (no consistentes secuencialmente).

Atomicidad

Cada operación de array que accede a más de un elemento del array no es atómica. Esto incluye la iteración, el escaneo, la ordenación, la división y la combinación de arrays.

Por ejemplo, considere el siguiente programa:

let size = 100_000_000
let a = Array.make size 1
let d1 = Domain.spawn (fun () ->
   Array.iteri (fun i x -> a.(i) <- x + 1) a
)
let d2 = Domain.spawn (fun () ->
  Array.iteri (fun i x -> a.(i) <- 2 * x + 1) a
)
let () = Domain.join d1; Domain.join d2

Después de ejecutar este código, cada campo del array a es o bien 2, 3, 4 o 5. Si se requiere atomicidad, el usuario debe implementar su propia sincronización (por ejemplo, utilizando Mutex.t).

Condiciones de carrera de datos

Si dos dominios solo acceden a partes disjuntas del array, entonces el comportamiento observado es equivalente a alguna intercalación secuencial de las operaciones de los dos dominios.

Se dice que ocurre una condición de carrera de datos cuando dos dominios acceden al mismo elemento del array sin sincronización y al menos uno de los accesos es una escritura. En ausencia de condiciones de carrera de datos, el comportamiento observado es equivalente a alguna intercalación secuencial de las operaciones de diferentes dominios.

Siempre que sea posible, se deben evitar las condiciones de carrera de datos utilizando sincronización

NAME

Stdlib.Array

Module

Array

Documentation

This module provides functions for creating and manipulating arrays.

Arrays are mutable, fixed-size, indexed data structures. All elements of an array must have the same type.

The operations on arrays are not atomic. In the presence of concurrent accesses to the same array from multiple threads (or domains), data races can occur. The float arrays section describes the specific caveats related to float arrays. For other types, the behavior is described in the Atomic operations section.

Atomic operations

Accessing array elements using the standard operators (e.g. `a.(i)`) is not atomic with respect to other accesses to the same array. This means that in the presence of data races, the observed behavior may not be equivalent to any sequential interleaving of operations from different domains.

However, if all accesses to an array are either reads or writes of a single element (i.e. no Array.blit or Array.copy), and if the element type is not a float array, then the accesses are effectively atomic. This means that a read operation will always return the value of some prior write to that location, and a write operation will be observed as atomic by other threads. The order of these accesses is not guaranteed, but it will correspond to some sequential interleaving of the operations.

It is the user's responsibility to mediate the accesses to the array elements.

Indeed, in the presence of data races, programs will not crash but the observed behaviour may not be equivalent to any sequential interleaving of operations from different domains. Nevertheless, even in the presence of data races, a read operation will return the value of some prior write to that location (with a few exceptions for float arrays).

Float arrays

Float arrays have two supplementary caveats in the presence of data races.

First, the blit operation might copy an array byte-by-byte. Data races between such a blit operation and another operation might produce surprising values due to tearing: partial writes interleaved with other operations can create float values that would not exist with a sequential execution.

For instance, at the end of

let zeros = Array.make size 0.
let max_floats = Array.make size Float.max_float
let res = Array.copy zeros
let d1 = Domain.spawn (fun () -> Array.blit zeros 0 res 0 size)
let d2 = Domain.spawn (fun () -> Array.blit max_floats 0 res 0 size)
let () = Domain.join d1; Domain.join d2
the res array might contain values that are neither 0. nor max_float .

Second, on 32-bit architectures, getting or setting a field involves two separate memory accesses. In the presence of data races, the user may observe tearing on any operation.
