Desde 3.11.2

val concat : string -> string -> string

concat dir file devuelve un nombre de archivo que designa el archivo file en el directorio dir.

val is_relative : string -> bool

Devuelve true si el nombre de archivo es relativo al directorio actual, false si es absoluto (es decir, en Unix, comienza con /).

val is_implicit : string -> bool

Devuelve true si el nombre de archivo es relativo y no comienza con una referencia explícita al directorio actual ( ./ o ../ en Unix), false si comienza con una referencia explícita al directorio raíz o al directorio actual.

val check_suffix : string -> string -> bool

check_suffix name suff devuelve true si el nombre de archivo name termina con el sufijo suff.

En los puertos de Windows (incluido Cygwin), la comparación no distingue entre mayúsculas y minúsculas, y se basa en String.lowercase_ascii. Tenga en cuenta que esto no coincide exactamente con la interpretación de la equivalencia de nombres de archivo que no distingue entre mayúsculas y minúsculas de Windows.

val chop_suffix : string -> string -> string

chop_suffix name suff elimina el sufijo suff del nombre de archivo name.

Provoca Invalid_argument si name no termina con el sufijo suff.

val chop_suffix_opt : suffix:string -> string -> string option

chop_suffix_opt ~suffix filename elimina el sufijo del filename si es posible, o devuelve None si el nombre de archivo no termina con el sufijo.

En los puertos de Windows (incluido Cygwin), la comparación no distingue entre mayúsculas y minúsculas, y se basa en String.lowercase_ascii. Tenga en cuenta que esto no coincide exactamente con la interpretación de la equivalencia de nombres de archivo que no distingue entre mayúsculas y minúsculas de Windows.

Desde 4.08

val extension : string -> string

extension name es el sufijo más corto ext de name0 donde:

- name0 es el sufijo más largo de name que no contiene un separador de directorios;

- ext comienza con un punto;

- ext está precedido por al menos un carácter que no sea un punto en name0.

Si dicho sufijo no existe, extension name es la cadena vacía.

Desde 4.04

val remove_extension : string -> string

Devuelve el nombre de archivo dado sin su extensión, tal como se define en Filename.extension. Si la extensión está vacía, la función devuelve el nombre de archivo dado.

El siguiente invariante se mantiene para cualquier nombre de archivo s:

remove_extension s ^ extension s = s

Desde 4.04

val chop_extension : string -> string

Igual que Filename.remove_extension, pero provoca Invalid_argument si el nombre dado tiene una extensión vacía.

val basename : string -> string

Divide un nombre de archivo en nombre de directorio / nombre de archivo base. Si name es un nombre de archivo válido, entonces concat (dirname name) (basename name) devuelve un nombre de archivo equivalente a name. Además, después de establecer el directorio actual en dirname name (con Sys.chdir), las referencias a basename name (que es un nombre de archivo relativo) designan el mismo archivo que name antes de la llamada a Sys.chdir.

Esta función cumple con la especificación de POSIX.1-2008 para la utilidad basename.

val dirname : string -> string

Ver Filename.basename. Esta función cumple con la especificación de POSIX.1-2008 para la utilidad dirname.

val null : string

null es "/dev/null" en POSIX y "NUL" en Windows. Representa un archivo en el sistema operativo que descarta todas las escrituras y devuelve fin de archivo en las lecturas.

Desde 4.10

val temp_file : ?temp_dir:string -> string -> string -> string

temp_file prefix suffix devuelve el nombre de un archivo temporal nuevo en el directorio temporal. El nombre base del archivo temporal se forma concatenando prefix, luego un número entero elegido adecuadamente, y luego suffix. El argumento opcional temp_dir indica el directorio temporal a usar, que por defecto es el resultado actual de Filename.get_temp_dir_name. El archivo temporal se crea vacío, con permisos 0o600 (legible y escribible solo por el propietario del archivo). Se garantiza que el archivo será diferente de cualquier otro archivo que existiera cuando se llamó a temp_file.

Antes de 3.11.2 no había argumento opcional ?temp_dir

Provoca Sys_error si no se pudo crear el archivo.

val open_temp_file : ?mode:open_flag list -> ?perms:int -> ?temp_dir:string -> string -> string -> string * out_channel

Igual que Filename.temp_file, pero devuelve tanto el nombre de un archivo temporal nuevo como un canal de salida abierto (atómico) en este archivo. Esta función es más segura que temp_file: no hay riesgo de que el archivo temporal sea modificado (p. ej., reemplazado por un enlace simbólico) antes de que el programa lo abra. El argumento opcional mode es una lista de indicadores adicionales para controlar la apertura del archivo. Puede contener uno o varios de Open_append, Open_binary y Open_text. El valor predeterminado es [Open_text] (abrir en modo texto). El archivo se crea con permisos perms (por defecto, legible y escribible solo por el propietario del archivo, 0o600).

Antes de 4.03 no había argumento opcional ?perms

Antes de 3.11.2 no había argumento opcional ?temp_dir

Provoca Sys_error si no se pudo abrir el archivo.

val temp_dir : ?temp_dir:string -> ?perms:int -> string -> string -> string

temp_dir prefix suffix crea y devuelve el nombre de un directorio temporal nuevo con permisos perms (por defecto 0o700) dentro de temp_dir. El nombre base del directorio temporal se forma concatenando prefix, luego un número entero elegido adecuadamente, y luego suffix. El argumento opcional temp_dir indica el directorio temporal a usar, que por defecto es el resultado actual de Filename.get_temp_dir_name. El directorio temporal se crea vacío, con permisos 0o700 (legible, escribible y accesible solo por el propietario del archivo). Se garantiza que el directorio será diferente de cualquier otro directorio que existiera cuando se llamó a temp_dir.

Si temp_dir no existe, esta función no lo crea. En su lugar, provoca Sys_error.

Desde 5.1

Provoca Sys_error si no se pudo crear el directorio.

val get_temp_dir_name : unit -> string

El nombre del directorio temporal: en Unix, el valor de la variable de entorno TMPDIR, o "/tmp" si la variable no está establecida.

En Windows, el valor devuelto por GetTempPath2 (si está disponible) o GetTempPath.

El directorio temporal se puede cambiar con Filename.set_temp_dir_name.

En Windows, antes de OCaml 5.4, devolvería el valor de la variable de entorno TEMP, o "." si la variable no estaba establecida.

Desde 4.00

val set_temp_dir_name : string -> unit

Cambia el directorio temporal devuelto por Filename.get_temp_dir_name y utilizado por Filename.temp_file y Filename.open_temp_file. El directorio temporal es un valor local al dominio que se hereda en dominios hijos.

2025-11-01 OCamldoc

quote_command

La versión citada de un nombre de archivo, adecuada para usar como uno de los argumentos en una línea de comandos, escapando todos los caracteres meta. Atención: bajo Windows, el resultado será solo adecuado para programas que sigan las convenciones de quoting estándar de Windows.

val quote_command : string -> ?stdin:string -> ?stdout:string -> ?stderr:string -> string list -> string

quote_command cmd args devuelve una línea de comandos citada, adecuada para usarse como argumento a Sys.command, Unix.system y las funciones Unix.open_process.

La cadena cmd es el comando a ejecutar. La lista args es la lista de argumentos a pasar a este comando. Puede ser vacía.

Los argumentos opcionales ?stdin, ?stdout y ?stderr son nombres de archivos usados para redirigir la entrada estándar, salida estándar o error estándar del comando. Si se especifica ~stdin:f, se realiza una redirección < f y la entrada estándar del comando lee del archivo f. Si se especifica ~stdout:f, se realiza una redirección > f y la salida estándar del comando se escribe en el archivo f. Si se especifica ~stderr:f, se realiza una redirección 2> f y el error estándar del comando se escribe en el archivo f. Si se especifican ambos ~stdout:f y ~stderr:f con el mismo nombre f, se realiza una redirección 2>&1 para que las salidas estándar y estándar de error del comando se integren y se redirijan al mismo archivo f.

Bajo Unix y Cygwin, el comando, los argumentos y las redirecciones si existen se citan usando Filename.quote y se concatenan. Bajo Win32, se realizan citas adicionales según lo requiera el shell cmd.exe llamado por Sys.command.

Since 4.10

Raises Failure si el comando no puede ser citado en la plataforma actual.
