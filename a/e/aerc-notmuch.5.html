AERC-NOTMUCH(5) Manual de formatos de archivo AERC-NOTMUCH(5)

NOMBRE

aerc-notmuch - configuración de notmuch para aerc(1)

SINOPSIS

aerc soporta el uso del sistema de correo notmuch como backend, para una indexación y búsqueda rápidas.

Para que esto esté habilitado, aerc debe ser compilado con soporte para notmuch. Consulte las instrucciones de instalación para más detalles.

CONFIGURACIÓN

La configuración básica de Notmuch puede hacerse interactivamente con el comando :new-account.

En accounts.conf (ver aerc-accounts(5)), las siguientes opciones específicas de notmuch están disponibles:

check-mail-cmd = <comando>

Comando a ejecutar junto con la opción check-mail.

Ejemplo:

check-mail-cmd = mbsync -a

check-mail-timeout = <duración>

Tiempo de espera para el check-mail-cmd. El comando se detendrá si no se completa en este intervalo y se mostrará un error. Aumente desde el valor predeterminado si ocurren errores repetidos.

Predeterminado: 10s

source = notmuch://<ruta>

El source indica la ruta al directorio que contiene su base de datos de notmuch (normalmente una carpeta .notmuch/).

La parte de la ruta de la URL después de notmuch:// debe ser una ruta absoluta prefijada con / o una ruta relativa a su directorio personal prefijada con ~. Por ejemplo:

source = notmuch:///home/yo/mail

source = notmuch://~/mail

query-map = <archivo>

Ruta a un archivo que contiene un mapeo de nombre de visualización a consulta de notmuch en el formato <NOMBRE>=<CONSULTA>.

Se pueden especificar múltiples entradas, una por línea. Las líneas que comienzan con # se ignoran y sirven como comentarios.

ej. inbox=tag:inbox and not tag:archived

exclude-tags = <etiqueta1,etiqueta2,etiqueta3...>

Lista separada por comas de etiquetas que serán excluidas de los resultados de la consulta, a menos que se mencionen explícitamente en la consulta.

Esto puede ser útil, por ejemplo, si usa una etiqueta de archivo o spam.

maildir-store = <ruta>

Ruta al almacén maildir que contiene los archivos de mensajes que respaldan la base de datos de notmuch. A menudo es la misma que la ruta de la base de datos de notmuch. Si se especifica, aerc utilizará esta opción para listar las carpetas disponibles y habilitar comandos como :delete y :archive.

N.B.: aerc seguirá mostrando mensajes y no archivos (bajo notmuch, un solo mensaje puede estar representado por varios archivos), lo que hace que la semántica de ciertos comandos como move sea ambigua. Use multi-file-strategy para indicarle a aerc cómo resolver estas ambigüedades.

maildir-account-path = <ruta>

Ruta a la cuenta maildir relativa al maildir-store.

Esto podría usarse para lograr el comportamiento tradicional de maildir de una pestaña por cuenta. La nota sobre maildir-store también se aplica a esta opción.

multi-file-strategy = <estrategia>

Estrategia para operaciones de archivo (por ejemplo, mover, copiar, eliminar) en mensajes que están respaldados por varios archivos. Valores posibles:
  • refuse (predeterminado): Rechazar la acción.
  • act-all: Actuar sobre todos los archivos.
  • act-one: Actuar sobre uno de los archivos, elegido arbitrariamente, y ignorar
el resto.
  • act-one-delete-rest: Similar a act-one, pero elimina los archivos restantes.
  • act-dir: Actuar sobre todos los archivos dentro de la carpeta actual e ignorar
el resto.
Tenga en cuenta que esta estrategia solo funciona dentro de los directorios de
maildir; en otros directorios, se comporta como refuse.
•
act-dir-delete-rest: Similar a act-dir, pero elimina los archivos restantes.

Tenga en cuenta que la estrategia no tiene efecto en las operaciones entre cuentas. Copiar un mensaje entre cuentas siempre copiará un solo archivo, elegido arbitrariamente. Mover un mensaje entre cuentas siempre copiará un solo archivo, elegido arbitrariamente, y se negará a eliminar múltiples archivos de la cuenta de origen.

USO

Notmuch muestra un comportamiento ligeramente diferente al de, por ejemplo, imap. Algunos comandos tienen una semántica ligeramente diferente y se mencionan a continuación:

cf <consulta notmuch>

El comando de cambio de carpeta permite consultas notmuch arbitrarias. Realizar un comando :cf realizará una nueva consulta notmuch de nivel superior.

filter <consulta notmuch>

El comando de filtro para backends de notmuch acepta consultas notmuch arbitrarias. Aplica la consulta al conjunto de mensajes que se muestran en la lista de mensajes. Esto se puede usar para realizar filtros/consultas sucesivas. Es equivalente a realizar un conjunto de consultas concatenadas con "and".
