NOMBRE

aerc-imap - Configuración IMAP para aerc(1)

SINOPSIS

aerc implementa el protocolo IMAP según lo especificado por RFC 3501, con las siguientes extensiones IMAP:

  • IDLE (RFC 2177)
  • LIST-STATUS (RFC 5819)
  • X-GM-EXT-1 (Gmail)

CONFIGURACIÓN

La configuración básica de IMAP se puede realizar interactivamente con el comando :new-account.

En accounts.conf (ver aerc-accounts(5)), las siguientes opciones específicas de IMAP están disponibles:

source = <esquema>://<nombredeusuario>[:<contraseña>]@<nombredelservidor>[:<puerto>]?[<parametros_oauth2>]

Recuerde que todos los campos deben estar codificados en URL. El símbolo @, cuando está codificado en URL, es %40.

Los posibles valores de <esquema> son:

imap

IMAP con STARTTLS

imap+insecure

IMAP sin STARTTLS

imaps

IMAP con TLS/SSL

imaps+insecure

IMAP con TLS/SSL, omitiendo la verificación del certificado

imaps+oauthbearer

IMAP con TLS/SSL usando Autenticación OAUTHBEARER

<parametros_oauth2>:

Si se especifican y se proporciona un token_endpoint, la contraseña configurada se utiliza como token de actualización para obtener un token de acceso. Si se omite token_endpoint, el intercambio de token de actualización se omite y la contraseña actúa como un token de acceso en su lugar.

  • token_endpoint (opcional)
  • client_id (opcional)
  • client_secret (opcional)
  • scope (opcional)

Ejemplo:

imaps+oauthbearer://...?token_endpoint=https://...&client_id=

imaps+xoauth2

IMAP con TLS/SSL usando Autenticación XOAUTH2. Los parámetros son los mismos que OAUTHBEARER.

source-cred-cmd = <comando>

Especifica el comando a ejecutar para obtener la contraseña de la cuenta IMAP. Este comando se ejecutará usando sh -c comando. Si se especifica una contraseña en la opción source, la contraseña tendrá prioridad sobre este comando.

Ejemplo:

source-cred-cmd = pass hostname/username

connection-timeout = <duración>

Retraso máximo para establecer una conexión con el servidor IMAP. Ver https://pkg.go.dev/time#ParseDuration.

Por defecto: 90s

keepalive-period = <duración>

El intervalo entre el último paquete de datos enviado (los simples ACKs no se consideran datos) y la primera sonda keepalive. Una vez que la conexión se marca como que necesita keepalive, este contador no se utiliza más. Ver https://pkg.go.dev/time#ParseDuration.

Por defecto, se utilizan la configuración del socket TCP del sistema.

keepalive-probes = <int>

El número de sondas no reconocidas a enviar antes de considerar la conexión muerta y notificar a la capa de aplicación.

Por defecto, se utilizan la configuración del socket TCP del sistema. Si se especifica keepalive-period, esta opción se establece por defecto en 3 sondas.

Esta opción solo es compatible con Linux. En otras plataformas, se ignorará.

keepalive-interval = <duración>

El intervalo entre las sondas keepalive subsecuentes, independientemente de lo que la conexión haya intercambiado en el ínterin. Las fracciones de segundo se truncan.

Por defecto, se utilizan la configuración del socket TCP del sistema. Si se especifica keepalive-period, esta opción se establece por defecto en 3s.

Esta opción solo es compatible con Linux. En otras plataformas, se ignorará.

check-mail-include = <carpeta1,carpeta2, carpeta3...>

Especifica la lista de carpetas separadas por comas a incluir al comprobar si hay correo nuevo con :check-mail. Los nombres prefijados con ~ se interpretan como expresiones regulares. Esta configuración se ignora si su servidor IMAP soporta el comando LIST-STATUS, en cuyo caso se comprobarán todas las carpetas.

Por defecto, se incluyen todas las carpetas.

check-mail-exclude = <carpeta1, carpeta2, carpeta3...>

Especifica la lista de carpetas separadas por comas a excluir al comprobar si hay correo nuevo con :check-mail. Los nombres prefijados con ~ se interpretan como expresiones regulares. Esta configuración se ignora si su servidor IMAP soporta el comando LIST-STATUS, en cuyo caso se comprobarán todas las carpetas. Tenga en cuenta que esto anula cualquier cosa de check-mail-include.

Por defecto, no se excluyen carpetas.

cache-headers = true|false

Si se establece en true, las cabeceras se almacenarán en caché. Las cabeceras en caché se guardarán en $XDG_CACHE_HOME/aerc, que por defecto es ~/.cache/aerc.

Por defecto: false

cache-max-age = <duración>

Define la edad máxima de los archivos en caché. Nota: la unidad de tiempo más larga en la que se puede especificar cache-max-age es horas. Establecer en 0 para deshabilitar la limpieza de la caché.

Por defecto: 720h (30 días)

idle-timeout = <duración>

El tiempo que el cliente esperará a que el servidor envíe cualquier actualización final antes de que se cierre el IDLE.

Por defecto: 10s

idle-debounce = <duración>

Especifica la duración desde el último comando del cliente hasta que el idler comience.

Por defecto: 10ms

expunge-policy = auto|low-to-high|stable

Especifica la política de borrado utilizada al borrar múltiples mensajes en un solo lote. auto intenta detectarla automáticamente y será correcta la mayoría de las veces. low-to-high especifica que el servidor elimina los mensajes en orden de número de secuencia creciente (esto es lo que hacen GMail o FastMail, y será manejado correctamente por la detección automática). stable especifica que el servidor no muta los números de secuencia recibidos (esto es lo que hacen Dovecot o WorkMail, y no se detecta de forma fiable automáticamente).

Por defecto: auto
