aerc-patch - gestión local de parches para aerc(

1
)

SINOPSI

S

aerc proporciona soporte para gestionar conjuntos de parches locales. En un flujo de trabajo de desarrollo de software basado en correo electrónico, normalmente existen muchas series de parches diferentes aplicadas localmente para pruebas y revisión. Gestionar el repositorio local puede ser un desafío. Con el sistema de gestión local de parches, aerc facilita este proceso de

registro.

Al aplicar un conjunto de parches, aerc crea una etiqueta para esos commits. Con esta etiqueta, el conjunto de parches puede ser rastreado y posteriormente eliminado si es necesario. Los parches se almacenan en una estructura d

e datos de proyecto que también lleva la cuenta del directorio donde se encuentra el repositor
io. Múltiples bases de código pueden ser rastreadas definiendo un proyecto separado para cada una.

S

Los siguientes subcomandos de :patch son

soportados:

:patch init [-f] [<proyec

to>]
Crea un nuevo proyecto <proyecto>. Si <proyecto> no está definido, aerc usará el último elemento de la ruta del directorio actual. También realiza una búsqueda de un repositorio soportado en el directorio actual.

-f: Sobrescribe un

proyecto
existente.

:patch list [-a]
:patch ls [-a

]
Lista el proyecto actual con los conjuntos de parches rastreados.

-a: Lista todos

los pr

:patch apply [-c <cmd>] [-w <commit-ish>] <etiquet

a>
Aplica el/los mensaje(s) seleccionado(s) al repositorio del proyecto actual. Utiliza el comando :pipe para esto y lleva la cuenta del parche aplicado.

Las autocompletaciones para la <etiqueta> están disponibles basadas en las líneas de asunto de los mensajes seleccionados o

marcados.

-c <cmd>: Aplica parches con el <cmd> proporcionado. Cualquier ocurrencia de '%r' en la cadena de comando será reemplazada por el directorio raíz del proyecto actual. Ten en cuenta que este enfoque no se recomienda en general y solo debe usarse para propósitos muy específicos, es decir, cuando un mantenedor aplica un conjunto de parches a través de un script separado para manejar los trailers de

git.

aerc propondrá autocompletaciones para la <etiqueta> basadas en las líneas de asunto de los mensajes seleccionados o

marcados.

Ejemplo

: 
:patch apply
-c "git -C %r
am -3" fix_v2

-w <commit-ish>: Crea un árbol de trabajo vinculado para el proyecto actual en <commit-ish> y aplica los parches al árbol de trabajo vinculado. Se crea un nuevo proyecto para almacenar la información del árbol de trabajo. Cuando este proyecto es eliminado, el árbol de trabajo también será

eliminado.

CÓMO

EMPEZAR

Asegúrate de tener un proyecto inicializado (ver :patch

init).

Ahora, hay dos formas de poner parches bajo el sistema de gestión local de

parches:
•
Aplicar parches con el comando :patch apply. Esto creará automáticam
ente una nueva etiqueta p
ara los commits aplicados.
•
Usar :patch rebase. Si existen algunos parches locales en el historial de commits que deberían ser gestionados por aerc, puedes ejecutar :patch rebase <commit-ish> y establecer <commit-ish> en el commit anterior al primer parche que quieras incluir. Para un repositorio git que tiene un upstream llamado origin, ejecutarías :patch reba
se ori
gin/m
aster.

EJEMPL

O

El siguiente ejemplo demuestra cómo gestionar los conjuntos de parches

locales.

Primero, se necesita inicializar un proyecto. Esto se hace cambiando al directorio de trabajo donde se encuentra el repositorio del proyecto. Para este ejemplo, asumamos que tenemos un proyecto llamado bar en el directorio /home/user/foo/bar

. 
:cd /home/user/foo/b
a
r

y luego creando un nuevo proyecto

con 
:pat
ch
init

Si no se proporciona un nombre a :patch init, aerc usará el último elemento de la ruta del directorio de trabajo (aquí: bar

).

Ahora el seguimiento de parches está listo para funcionar. Ve a la lista de mensajes, marca una serie de parches y

aplícala: 
:patch
apply
fix_v2

Esto aplicará el conjunto de parches seleccionado y asignará la etiqueta fix_v2 a esos commits. La etiqueta ayuda a mantener los commits agrupados, y será útil cuando queramos eliminar este conjunto de parches exacto en un momento

posterior.

Con :patch list puedes verificar que el conjunto de parches fue aplicado

correctamente.

Si hay un cambio en el repositorio subyacente (por ejemplo, haciendo rebase al upstream), los hashes de los commits locales aplicados pueden cambiar. :patch list puede detectar tal cambio y entonces propondrá hacer rebase de los datos internos. Para hacer esto,

ejecuta 
:pat
ch re
base

Esto abrirá un editor donde puedes ajustar las etiquetas correctas de nuevo. También podrías cambiar el punto de rebase proporcionando un argumento opcional (por ejemplo, un hash de commit, o incluso HEAD~3 o origin/master, etc.)

.

Para eliminar un conjunto de parches, usa la etiqueta que fue asignada durante la

aplicación: 
:patch
drop
fix_v2

Y para eliminar los datos del proyecto en aerc

: 
:pat
ch u
nlink
bar
