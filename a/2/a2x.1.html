a2x - Un gestor de cadena de herramientas

para AsciiDoc (convierte archivos de te

SINOPSI

a2x [OPCIONES] ARCHIVO_FUEN

T

DESCRIPCIÓ

N

Un gestor de cadena de herramientas DocBook que traduce un archivo de texto AsciiDoc ARCHIVO_FUENTE a PDF, EPUB, DVI, PS, LaTeX, XHTML (página única o dividida en trozos), página de manual, HTML Help o formatos de texto plano usando asciidoc(1) y otras aplicaciones (vea la sección REQUISITOS). ARCHIVO_FUENTE también puede ser un

archivo DocBook con
una extensión .xml.

OPCIONE

S

-a, --attribute=ATRIBUT

O
Establece el valor del atributo de asciidoc(1) (atajo para --asciidoc-opts="-a ATRIBUTO" opción). Esta opción puede especificarse más de una
vez.

--asciidoc-opts=OPCIONES_ASCIIDO

C
Opciones adicionales de asciidoc(1). Esta opción puede especificarse más de una
vez.

--conf-file=ARCHIVO_CON

F
Carga el archivo de configuración. Vea la sección ARCHIVOS DE
CONFIGURACIÓN.

-D, --destination-dir=DIR_DESTIN

O
Directorio de salida. Por defecto es el directorio de ARCHIVO_FUENTE. Esta opción solo es aplicable a los formatos de salida basados en HTML y páginas de manual (chunked, epub, htmlhelp, xhtml, manpag
e).

-d, --doctype=TIPO_DO

C
Tipo de documento DocBook: article, manpage o book. El tipo de documento por defecto es article a menos que el formato sea manpage (en cuyo caso el valor por defecto es manpag
e).

-b, --backend=BACKEN

D
BACKEND es el nombre de un plugin de backend instalado. Cuando se especifica esta opción a2x intenta cargar un archivo con el nombre a2x-backend.py del directorio del plugin BACKEND. Luego convierte el ARCHIVO_FUENTE a un archivo de salida con formato BACKEND usando una función global definida en a2x-backend.py llamada to_BACKEND
.

-f, --format=FORMAT

O
Formatos de salida: chunked, docbook, dvi, epub, htmlhelp, manpage, pdf (por defecto), ps, tex, text, xhtml. El valor del atributo AsciiDoc a2x-format se establece en FORMATO
.

-h,

--help
Imprime la sintaxis de la línea de comandos y las opciones del programa en
stdout.

--icon

s
Usa imágenes de iconos de admonición o navegación en los documentos de salida. El comportamiento por defecto es usar texto en lugar de
iconos.

--icons-dir=RUT

A
Una ruta (relativa a los archivos de salida) que contiene iconos de admonición y navegación. Por defecto es images/icons. La opción --icons es implícita si se usa esta
opción.

-k, --keep-artifact

s
No borra los archivos temporales de
compilación.

--lyn

x
Usa lynx(1) (en realidad: el navegador basado en texto definido por la variable de configuración LYNX) al generar la salida con formato de texto. El comportamiento por defecto es usar w3m(1) (en realidad: el navegador basado en texto definido por la variable de configuración W3M)
.

-L,

--no-xmllint
No comprueba la salida de asciidoc con xmllint
(1).

---epubchec

k
Comprueba la salida EPUB con epubcheck
(1).

-n,

--dry-run
No hace nada, solo imprime lo que se habría
hecho.

-r, --resource=ESPEC_RECURS

O
Especifica un recurso. Esta opción puede especificarse más de una vez. Vea la sección RECURSOS para más
detalles.

-m, --resource-manifest=ARCHIV

O
ARCHIVO contiene una lista de recursos (uno por línea). Las entradas del manifiesto ARCHIVO se formatean igual que los argumentos de la opción --resource. Se permiten variables de entorno y directorios de inicio con
tilde.

--stylesheet=HOJA_ESTILO

S
Una lista de nombres de archivos de hojas de estilo CSS delimitados por espacios que se usan para dar estilo a la salida HTML generada por las Hojas de Estilo XSL de DocBook. Por defecto es docbook-xsl.css. Las hojas de estilo se procesan en el orden de la lista. Las hojas de estilo deben residir en una ubicación válida de archivo de recurso. Se aplica a los formatos HTML: xhtml, epub, chunked, htmlhelp
formatos.

-v,

--verbose
Imprime detalles de operación en stderr. Una segunda -v opción aplica la opción verbosa a los comandos de la cadena de
herramientas.

--versio

n
Imprime la versión del programa en
stdout.

--xsltproc-opts=OPCIONES_XSLTPRO

C
Opciones adicionales de xsltproc(1). Esta opción puede especificarse más de una
vez.

--xsl-file=ARCHIVO_XS

L
Sobreescribe la hoja de estilo XSL integrada con la hoja de estilo XSL personalizada ARCHIVO_XSL
.

--fo

p
Usa FOP para generar PDFs. El comportamiento por defecto es usar dblatex(1). La opción --fop es implícita si se usa la opción --fop
-opts.

--fop-opts=OPCIONES_FO

P
Opciones adicionales de fop(1). Si se especifica esta opción, se usa FOP para generar PDFs. Esta opción puede especificarse más de una
vez.

--dblatex-opts=OPCIONES_DBLATE

X
Opciones adicionales de dblatex(1). Esta opción puede especificarse más de una
vez.

--backend-opts=OPCIONES_BACKEN

D
Opciones para el plugin de backend especificado por la opción --backend. Esta opción puede especificarse más de una
vez.

Las opciones también se pueden establecer en el archivo fuente AsciiDoc. Si ARCHIVO_FUENTE contiene una línea de comentario que comienza con // a2x: entonces el resto de la línea se tratará como opciones de línea de comandos de a2x. Por

ejemplo: 
// a2x default options.
//    a2x: -dbook --epubcheck
// Suppress revision history in dblatex outputs. //
a2x: --dblatex-opts "-P latex.output.revhistory=0"
•Las opciones que abarcan varias de estas líneas de comentario se
concatenarán.
•Pueden aparecer cero o más caracteres de espacio en blanco entre el // inicial y a2x
:.
•Las opciones de la línea de comandos
tienen prioridad sobre las opciones
establecidas en el archivo fuente.

ARCHIVOS DE

SALIDA

Los archivos de salida se escriben en el directorio especificado por la opción --destination-dir. Si no se establece la opción --destination-dir, los archivos de salida se escriben en el directorio de ARCHIVO_FUENTE

.

Los archivos de salida tienen el mismo nombre que el ARCHIVO_FUENTE pero con una extensión de nombre de archivo apropiada: .html para xhtml; .epub para epub; .hhp para htmlhelp; .pdf para pdf; .text para text, .xml para docbook. Por convención, las páginas de manual no tienen la extensión .man (solo el número de sección de la página de manual). Los nombres de directorio de HTML dividido en trozos tienen una extensión .chunked; los nombres de directorio de HTML Help dividido en trozos tienen una extensión .

htmlhelp.

Los archivos existentes con el mismo nombre se

sobreescriben.

Además de generar los archivos HTML, los xhtml, epub, chunked y htmlhelp formatos aseguran que los archivos de recurso se c

opien en sus ubicaciones correc
tas en el directorio de destino.

RECURSO

S

Los recursos son archivos (típicamente CSS e imágenes) que son requeridos por las salidas basadas en HTML (xhtml, epub, chunked, htmlhelp formatos). a2x escanea los archivos HTML generados y construye una lista de los archivos CSS e imágenes requeridos. Los archivos de recurso adicionales pueden especificarse explícitamente usando la opción --res

ource.

a2x busca los archivos de recurso en las siguientes ubicaciones en el siguiente

orden:
1.El directorio de ARCHI
VO_FUENTE.
2.Los directorios de recurso especificados por la opción --resource (buscados recursivamente)
.
3.Los directorios de recurso especificados por la opción --resource-manifest (buscados recursivamente en el orden en que aparecen en el archivo de manifiesto)
.
4.Los directorios de imágenes y hojas de estilo estándar en el

RECURSOS

Los directorios de configuración de asciidoc(1) (buscados recursivamente).

5. El directorio de destino.

Cuando se encuentra un archivo de recursos, se copia al directorio de destino relativo correcto. Los subdirectorios de destino que falten se crean automáticamente.

Existen dos mecanismos distintos para especificar recursos adicionales:

1. Un directorio de recursos que se buscará recursivamente para encontrar archivos de recursos faltantes.
2. Un archivo de recursos que se copiará al directorio de destino de salida.

Los recursos se especifican con valores de opción --resource que pueden ser uno de los siguientes formatos:

<directorio_recurso>
<archivo_recurso>[=<archivo_destino>]
.<ext>=<mimetype>

Donde:

<directorio_recurso>

Especifica un directorio (absoluto o relativo a SOURCE_FILE) que se busca recursivamente para encontrar archivos de recursos faltantes. Para eliminar ambigüedades, el nombre de <directorio_recurso> debe terminar con un carácter separador de directorios.

<archivo_recurso>

Especifica un archivo de recursos (absoluto o relativo a SOURCE_FILE) que se copiará a <archivo_destino>. Si no se especifica <archivo_destino>, será el mismo que <archivo_recurso>.

<archivo_destino>

Especifica el destino del archivo fuente copiado. La ruta de <archivo_destino> es relativa al directorio de destino (no se permiten rutas absolutas). La ubicación del directorio de destino depende del FORMATO de salida (ver la sección ARCHIVOS DE SALIDA para más detalles):

chunked, htmlhelp

El directorio de salida fragmentada.

epub

El directorio OEBPS archivado.

xhtml

El DESTINATION_DIR de salida.

.<ext>=<mimetype>

Al agregar recursos a archivos EPUB, el mimetype se infiere de la extensión del <archivo de destino>. Si no se puede adivinar el mimetype, se produce un error. La sintaxis de recurso .<ext>=<mimetype> se puede usar para establecer explícitamente los mimetypes. <ext> es la extensión del nombre del archivo, <mimetype> es el tipo MIME correspondiente.

Ejemplos de opciones de recursos:

--resource ../images/
--resource doc/README.txt=README.txt
--resource ~/images/tiger.png=images/tiger.png
--resource .ttf=application/x-font-ttf

EJEMPLOS

a2x -f pdf doc/source-highlight-filter.txt

Genera el archivo doc/source-highlight-filter.pdf.

a2x -f xhtml -D ../doc --icons -r ../images/ team.txt

Crea el archivo HTML ../doc/team.html, utiliza iconos de admonición y busca recursivamente en el directorio ../images/ cualquier recurso faltante.

a2x -f manpage doc/asciidoc.1.txt

Genera la página man doc/asciidoc.1.

REQUISITOS

a2x utiliza los siguientes programas:

•Asciidoc: https://asciidoc.org/
•xsltproc: (todos los formatos excepto texto): http://xmlsoft.org/XSLT/
•Hojas de estilo XSL DocBook (todos los formatos excepto texto): https://github.com/docbook/xslt10-stylesheets
•dblatex (formatos pdf, dvi, ps, tex): http://dblatex.sourceforge.net/
•FOP (formato pdf — generador de archivos PDF alternativo): https://xmlgraphics.apache.org/fop/
•w3m (formato de texto): http://w3m.sourceforge.net/index.en.html
•Lynx (formato de texto — generador de archivos de texto alternativo): https://invisible-island.net/lynx/
•epubcheck (formato epub — validador de archivos EPUB): https://github.com/w3c/epubcheck

Consulte también el último archivo README.

ARCHIVOS DE CONF

Un archivo de configuración contiene código Python ejecutable que anula los parámetros de configuración globales en a2x.py. Los archivos de configuración opcionales se cargan en el siguiente orden:

1.a2x.conf del directorio que contiene el ejecutable a2x.py.
2.a2x.conf del directorio de configuración global de AsciiDoc. Omita este paso si estamos ejecutando una copia instalada localmente (no a nivel de sistema).
3.a2x.conf del directorio de configuración $HOME/.asciidoc de AsciiDoc.
4. El CONF_FILE especificado en la opción --conf-file.

Estos son los valores de opción predeterminados del archivo de configuración:

# Diccionario opcional de variables de entorno que se pasa a
# los programas en ejecución. Si se establece en None, se utiliza el
# entorno existente.
ENV = None
# Ejecutables externos.
ASCIIDOC = 'asciidoc'
XSLTPROC = 'xsltproc'
DBLATEX = 'dblatex'         # Generación de pdf.
FOP = 'fop'                 # Generación de pdf (opción --fop).
W3M = 'w3m'                 # Generador principal de archivos de texto.
LYNX = 'lynx'               # Generador alternativo de archivos de texto.
XMLLINT = 'xmllint'         # Establecer en '' para deshabilitar.
EPUBCHECK = 'epubcheck'     # Establecer en '' para deshabilitar.
# Opciones predeterminadas de ejecutables externos.
ASCIIDOC_OPTS = ''
BACKEND_OPTS = ''
DBLATEX_OPTS = ''
FOP_OPTS = ''
LYNX_OPTS = '-dump'
W3M_OPTS = '-dump -cols 70 -T text/html -no-graph'
XSLTPROC_OPTS = ''

Tenga en cuenta que es posible redefinir W3M y LYNX para usar navegadores diferentes basados en texto, por ejemplo, links: http://links.twibright.com/ o elinks: http://elinks.or.cz/. LYNX_OPTS y W3M_OPTS se pueden usar para pasar opciones al navegador seleccionado. Si se definen, anulan los valores predeterminados correspondientes enumerados anteriormente (así que no olvide incluir la opción -dump en su definición: esto es obligatorio al menos con w3m, lynx, links y elinks para enviar el texto formateado a la salida estándar).
