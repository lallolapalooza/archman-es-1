apccontrol(8) — Arch Linux

NAME

apccontrol — apcupsd event handling script

SYNOPSIS

/etc/apcupsd/apccontrol

DESCRIPTION

The apccontrol script is executed by apcupsd whenever a specific event occurs. The script is responsible for taking the appropriate action based on the event received.

The following events are generated by apcupsd and passed as the first argument to apccontrol:

onbattery
apcupsd genera este evento cuando la red eléctrica falla y la UPS cambia a alimentación por batería.

Acción predeterminada: envía "UPS está en modo batería" a wall y entra en un bucle de espera/salida. El script responderá enviando un mensaje de correo electrónico a root y ejecutando el comando wall(1) para notificar a todos los usuarios conectados. Después de este evento, apcupsd comenzará a contar el tiempo de ejecución restante de la batería.

offbattery
apcupsd genera este evento cuando la energía de la red eléctrica se restaura y la UPS sale del modo de batería.

Acción predeterminada: envía "UPS ya no está en modo batería" a wall y sale. El script responderá enviando un mensaje de correo electrónico a root y ejecutando el comando wall(1).

cansend
apcupsd genera este evento cuando ya no puede comunicarse con la UPS. Esto generalmente ocurre cuando la conexión serial o USB falla.

Acción predeterminada: envía "No se puede enviar a la UPS" a wall y sale. El script responderá enviando un mensaje de correo electrónico a root y ejecutando el comando wall(1).

commstarted
apcupsd genera este evento cuando restablece la comunicación con la UPS después de una interrupción.

Acción predeterminada: envía "Comunicación con la UPS restablecida" a wall y sale. El script responderá enviando un mensaje de correo electrónico a root y ejecutando el comando wall(1).

update
apcupsd genera este evento cada vez que recibe nueva información de la UPS. Esto puede ocurrir varias veces por minuto.

Acción predeterminada: no hace nada.

lowbattery
apcupsd genera este evento cuando la carga de la batería de la UPS cae por debajo del umbral especificado por la directiva lowbatt en el archivo de configuración.

Acción predeterminada: envía "Batería baja en la UPS" a wall y sale. El script responderá enviando un mensaje de correo electrónico a root y ejecutando el comando wall(1).

powerout
apcupsd genera este evento cuando el sistema pierde energía de la red eléctrica. Este evento es similar a onbattery, pero ocurre antes de que la UPS cambie a energía de batería.

Acción predeterminada: no hace nada.

timeout
apcupsd genera este evento cuando expira el tiempo especificado por la directiva de configuración TIMEOUT mientras la UPS está en modo de batería como resultado de un corte de energía de la red eléctrica. Esta directiva de configuración no se usa normalmente con UPS inteligentes que, en cambio, dependerían del tiempo de ejecución restante más confiable (MINUTES) o del nivel de batería (BATTERYLEVEL).

Acción predeterminada: envía "Se superó el límite de tiempo de ejecución de la batería de la UPS. Realizando apagado." a wall y luego sale. Después de este evento, apcupsd generará inmediatamente un evento doshutdown.

startselftest
apcupsd genera este evento cuando detecta el inicio de una autoprueba de la UPS.

Acción predeterminada: no hace nada.

endselftest
apcupsd genera este evento cuando detecta el final de una autoprueba de la UPS.

Acción predeterminada: no hace nada.

CUSTOMISING EVENT ACTIONS

No modifique apccontrol directamente, ya que será sobrescrito la próxima vez que actualice a una nueva versión de apcupsd.

La forma recomendada de personalizar una acción de evento es simplemente crear un programa o script ejecutable con el mismo nombre que el evento y colocar ese archivo en el directorio /etc/apcupsd. Ahora, cuando ocurra el evento seleccionado, apccontrol ejecutará su programa o script.

Si desea que apccontrol también ejecute su acción predeterminada para el evento seleccionado, su programa o script debe salir con un estado de salida de 0 (cero).

Si no desea que apccontrol ejecute su acción predeterminada para el evento seleccionado, su programa o script debe salir con un estado de salida de 99. Tenga en cuenta que si anula completamente la acción predeterminada, debe asegurarse del apagado adecuado de su computadora si esto es necesario.

Algunos scripts de ejemplo (changeme, commfailure, commok, offbattery y onbattery) que envían correos electrónicos a root en lugar de transmitir mensajes a todos los usuarios conectados se pueden encontrar en /etc/apcupsd después de una instalación y también en el directorio platforms/etc del código fuente de apcupsd.
