DESCRIPCIÓ

RUTA DE LA

IMAGEN:

Cuando Apptainer construye el contenedor, la salida puede ser uno de unos pocos

formatos: 
  predeterminado: El formato de imagen de solo lectura comprimida de Apptainer (predeterminado)
  sandbox:       Esto es un contenedor de lectura-escritura dentro de una estructura de
directorios

nota: Es un flujo de trabajo común usar el modo "sandbox" para el desarrollo del
contenedor, y luego construirlo como una imagen de Apptainer predeterminada para producción
El formato predeterminado es

inmutable.

ESPECIFICACIÓN DE

CONSTRUCCIÓN:

El destino de la especificación de construcción es un archivo de definición (def), una imagen local, o un URI que puede
usarse para crear un contenedor de Apptainer. Existen varios formatos de destino local
diferentes

: 
  archivo def  : Esta es una receta para construir un contenedor (ejemplos más abajo)
  directorio:  Una estructura de directorios que contiene un sistema de archivos (ch)root
  imagen:      Una imagen local en su máquina (se convertirá a sif si
               es un formato
antiguo)

Los destinos también pueden ser remotos y definidos por un URI de los siguientes

formatos: 
  library://  una biblioteca de imágenes (sin predeterminado)
  docker://   un registro Docker/OCI (predeterminado Docker Hub)
  shub://     un registro de Apptainer (predeterminado Singularity Hub)
  oras://     un registro OCI que almacena archivos SIF usando
ORAS

Archivos

temporales:

La ubicación utilizada para los directorios temporales es '/tmp' por defecto, pero
puede ser sobrescrita por la variable de entorno TMPDIR, y esta puede ser
sobrescrita por la variable de entorno APPTAINER_TMPDIR. El
directorio temporal utilizado durante una construcción debe estar en un sistema de archivos que
tenga suficiente espacio para contener toda la imagen del contenedor, sin comprimir,
incluyendo cualquier archivo temporal que se cree y luego se elimine
durante la construcción. Puede necesitar establecer APPTAINER_TMPDIR o TMPDIR cuando
construya un contenedor grande

en un sistema que tenga un sis
tema de archivos /tmp pequeño.

OPCIONE

S

--arch="amd64" arquitectura para la que

construir

--arch-variant="" variante de arquitectura para la que

construir

--authfile="" archivo de autenticación estilo Docker para usar al escribir/leer credenciales de registro

OCI

-B, --bind=[] especificación de ruta de enlace de usuario. La especificación tiene el formato src[:dest[:opts]], donde src y dest son rutas de fuera y de dentro. Si dest no se proporciona, se establece igual a src. Las opciones de montaje ('opts') pueden especificarse como 'ro' (solo lectura) o 'rw' (lectura/escritura, que es el predeterminado). Se pueden dar múltiples rutas de enlace con una lista separada por

comas.

--build-arg=[] define variable=value para reemplazar entradas {{ variable }} en el archivo de definición de

construcción

--build-arg-file="" especifica un archivo que contiene líneas variable=value para reemplazar '{{ variable }}' con value en los archivos de definición de

construcción

--disable-cache[=false] no usar la caché o crear

caché

--docker-host="" especificar un host de demonio Docker

personalizado

--docker-login[=false] iniciar sesión en un Repositorio Docker interactivament

e

-e, --encrypt[=false] construir una imagen con un sistema de archivos

cifrado

-f, --fakeroot[=false] construir con la apariencia de ejecutarse como root (predeterminado al construir desde un archivo de definición sin

privilegios)

--fix-perms[=false] asegurar que el propietario tenga permisos rwX en todo el contenido del contenedor para fuentes

oci/docker

-F, --force[=false] sobrescribir un archivo de imagen si

existe

-h, --help[=false] ayuda para

build

--json[=false] interpretar la definición de construcción como

JSON

--library="" URL de la Biblioteca de

contenedores

--mksquashfs-args="" argumentos adicionales para pasar a mksquashfs al crear archivos

SIF

--mount=[] especificación de montaje, p. ej. 'type=bind,source=/opt,destination=/hostopt'

.

--no-cleanup[=false] NO limpiar el paquete después de una construcción fallida, puede ser útil para la

depuración

--no-https[=false] usar http en lugar de https para URIs docker:// oras:// y library:///..

.

-T, --notest[=false] construir sin ejecutar pruebas en la sección

%test

--nv[=false] inyectar bibliotecas Nvidia del host durante la construcción para las secciones post y

test

--nvccli[=false] usar nvidia-container-cli para la configuración de GPU

(experimental)

--passphrase[=false] pedir una frase de contraseña de

cifrado

--pem-path="" introducir una ruta a una clave RSA con formato PEM para un contenedor

cifrado

--rocm[=false] inyectar bibliotecas Rocm del host durante la construcción para las secciones post y

test

-s, --sandbox[=false] construir la imagen en formato sandbox (estructura de directorios

chroot)

--section=[all] ejecutar solo sección(es) específica(s) del archivo de definición (setup, post, files, environment, test, labels,

none)

-u, --update[=false] ejecutar la definición sobre un contenedor existente (omite la

cabecera)

--userns[=false] construir sin usar setuid incluso si está

disponible

--warn-unused-build-args[=false] muestra una advertencia en lugar de un mensaje fatal cuando los argumentos de construcción no coinciden

exactamente

--writable-tmpfs[=false] durante la sección %test, hace que el sistema de archivos sea

accesible como lectura-escritura con datos no
persistentes (solo con soporte de overlay)

EJEMPL

O 
  ARCHIVO DEF SO OPERATIVO:
      Biblioteca:
          Bootstrap: library
          From: debian:9
      Docker:
          Bootstrap: docker
          From: tensorflow/tensorflow:latest
          IncludeCmd: yes # Usar el CMD como script de ejecución en lugar de ENTRYPOINT
      Singularity Hub:
          Bootstrap: shub
          From: singularityhub/centos
      YUM/RHEL:
          Bootstrap: yum
          OSVersion: 7
          MirrorURL: http://mirror.centos.org/centos-%{OSVERSION}/%{OSVERSION}/os/x86_64/
          Include: yum
      SUSE:
          Bootstrap: zypper # en un sistema SLE se usa el registro del host de construcción
          Include: zypper
      openSUSE:
          Bootstrap: zypper
          MirrorURL: http://download.opensuse.org/distribution/openSUSE-stable/repo/oss
          Include: zypper
      Debian/Ubuntu:
          Bootstrap: debootstrap
          OSVersion: trusty
          MirrorURL: http://us.archive.ubuntu.com/ubuntu/
      Imagen Local:
          Bootstrap: localimage
          From: /home/dave/starter.img
      Scratch:
          Bootstrap: scratch # Poblar el contenedor con un rootfs mínimo en %setup
  SECCIONES DEL ARCHIVO DE DEFINICIÓN:
  Las siguientes secciones se presentan en el orden de procesamiento, con la excepción
  de que labels y environment también pueden manipularse en %post.
      %pre
          echo "Este es un scriptlet que se ejecutará en el host, como root, antes de"
          echo "que el contenedor haya sido inicializado. Esta sección no se usa comúnmente."
      %setup
          echo "Este es un scriptlet que se ejecutará en el host, como root, después de"
          echo "que el contenedor haya sido inicializado. Para instalar cosas en el contenedor"
          echo "referencie la ubicación del sistema de archivos con $APPTAINER_ROOTFS."
      %files
          /ruta/en/host/archivo.txt /ruta/en/contenedor/archivo.txt
          archivo_relativo.txt /ruta/en/contenedor/archivo_relativo.txt
      %post
          echo "Esta sección de scriptlet se ejecutará desde dentro del contenedor después de"
          echo "que la base de inicialización haya sido creada y configurada."
      %environment
          LUKE=buenchico
          VADER=malchico
          HAN=algunchico
          export HAN VADER LUKE
      %test
          echo "Defina cualquier comando de prueba que deba ejecutarse después de que el contenedor haya sido"
          echo "construido. Este scriptlet se ejecutará desde dentro del contenedor en ejecución"
          echo "como el usuario root. Preste atención al valor de salida/retorno de este scriptlet"
          echo "ya que cualquier código de salida distinto de cero se asumirá como un fallo."
          exit 0
      %runscript
          echo "Defina acciones para el contenedor que se ejecutarán con el comando run o"
          echo "cuando se ejecute el contenedor."
      %startscript
          echo "Defina acciones que el contenedor realizará cuando se inicie como una instancia."
      %labels
          HELLO MOTO
          CLAVE VALOR
      %help
          Este es un archivo de texto que se mostrará con el comando run-help.
  COMANDOS:
      Construir un archivo sif a partir de un archivo de receta de Apptainer:
          $ apptainer build /tmp/debian0.sif /ruta/a/debian.def
      Construir una imagen sif desde la Biblioteca:
          $ apptainer build /tmp/debian1.sif library://debian:latest
      Construir una base sandbox desde DockerHub, hacer cambios en e
lla y luego construir el sif $ apptainer build --sandbox /tmp/debian docker://debian:latest $ ap
ptainer exec --writable /tmp/debian apt-get install python $ apptainer build /tmp/debian2.sif /tmp/debian
