AppConfig::File(3) Documentación de Perl aportada por el usuario AppConfig::File(3)

NOMBRE

AppConfig::File - Módulo de Perl5 para leer archivos de configuración.

SINOPSIS

use AppConfig::File;
my $state   = AppConfig::State->new(\%cfg1);
my $cfgfile = AppConfig::File->new($state, $file);
$cfgfile->parse($file);            # leer archivo de configuración

DESCRIPCIÓN GENERAL

AppConfig::File es un módulo de Perl5 que lee archivos de configuración y usa su contenido para actualizar los valores de las variables en un objeto AppConfig::State.

AppConfig::File se distribuye como parte del paquete AppConfig.

DESCRIPCIÓN

USANDO EL MÓDULO AppConfig::File

Para importar y usar el módulo AppConfig::File, la siguiente línea debe aparecer en su script de Perl:

use AppConfig::File;

AppConfig::File se usa automáticamente si usted usa el módulo AppConfig y crea un objeto AppConfig::File a través del file() método.

AppConfig::File está implementado usando métodos orientados a objetos. Se crea e inicializa un nuevo objeto AppConfig::File usando el métodonew() de AppConfig::File->. Esto devuelve una referencia a un nuevo objeto AppConfig::File. Se debe pasar una referencia a un objeto AppConfig::State como el primer parámetro:

my $state   = AppConfig::State->new();
my $cfgfile = AppConfig::File->new($state);

Esto creará y devolverá una referencia a un nuevo objeto AppConfig::File.

LEYENDO ARCHIVOS DE CONFIGURACIÓN

El método parse() se usa para leer un archivo de configuración y hacer que el contenido actualice el ESTADO (STATE) en consecuencia.

$cfgfile->parse($file);

Se pueden especificar varios archivos y se leerán por turno.

$cfgfile->parse($file1, $file2, $file3);

El método devolverá un valor undef si encuentra algún error al abrir los archivos. Retornará inmediatamente sin procesar ningún otro archivo. Por defecto, la opción PEDANTIC en el objeto AppConfig::State, $self->{ STATE }, está desactivada y cualquier error de análisis (variables inválidas, valores no validados, etc.) generará advertencias, pero no hará que el método retorne. Una vez procesados todos los archivos, el método devolverá 1 si todos los archivos se procesaron sin advertencias o 0 si se generó una o más advertencias. Cuando la opción PEDANTIC está activada, el método genera una advertencia y retorna inmediatamente un valor de 0 en cuanto encuentra cualquier error de análisis.

Los valores de las variables en los archivos de configuración pueden expandirse dependiendo del valor de su opción EXPAND, como se determina desde el objeto App::State. Vea AppConfig::State para más información sobre la expansión de variables.

FORMATO DEL ARCHIVO DE CONFIGURACIÓN

Un archivo de configuración puede contener líneas en blanco y comentarios que se ignoran. Los comentarios comienzan con un '#' como primer carácter en una línea o después de uno o más espacios en blanco, y continúan hasta el final de la línea.

# esto es un comentario
foo = bar               # esto también
url = index.html#hello  # esto también, pero no el '#welcome'

Observe cómo la parte '#welcome' de la URL no se trata como un comentario porque no la precede un carácter de espacio en blanco.

Las líneas largas pueden continuarse en la siguiente línea terminando la primera línea con un '\'.

callsign = alpha bravo camel delta echo foxtrot golf hipowls \
           india juliet kilo llama mike november oscar papa  \
           quebec romeo sierra tango umbrella victor whiskey \
           x-ray yankee zebra

Las variables que son indicadores simples y no esperan un argumento (ARGCOUNT = ARGCOUNT_NONE) pueden especificarse sin ningún valor. Se establecerán con el valor 1, ignorando cualquier valor explícitamente especificado (excepto "0" y "off"). La variable también puede especificarse con el prefijo "no" para establecer implícitamente la variable en 0.

verbose                              # activado (1)
verbose = 1                          # activado (1)
verbose = 0                          # desactivado (0)
verbose off                          # desactivado (0)
verbose on                           # activado (1)
verbose mumble                       # activado (1)
noverbose                            # desactivado (0)

Las variables que esperan un argumento (ARGCOUNT = ARGCOUNT_ONE) se establecerán con lo que siga al nombre de la variable, hasta el final de la línea actual. Se puede insertar un signo igual entre la variable y el valor para mayor claridad.

room = /home/kitchen     
room   /home/bedroom

Cada redefinición posterior del valor de la variable sobrescribe el valor anterior.

print $config->room();               # imprime "/home/bedroom"

Las variables pueden definirse para aceptar múltiples valores (ARGCOUNT = ARGCOUNT_LIST). Cada definición posterior de la variable añade el valor a la lista de valores previamente establecidos para la variable.

drink = coffee
drink = tea

Se devuelve una referencia a una lista de valores cuando se solicita la variable.

my $beverages = $config->drinks();
print join(", ", @$beverages);      # imprime "coffee, tea"

Las variables también pueden definirse como listas hash (ARGCOUNT = ARGCOUNT_HASH). Cada definición posterior crea una nueva clave y valor en el array hash.

alias l="ls -CF"
alias h="history"

Se devuelve una referencia al hash cuando se solicita la variable.

my $aliases = $config->alias();
foreach my $k (keys %$aliases) {
    print "$k => $aliases->{ $k }\n";
}

Un gran bloque de texto puede definirse usando el estilo de cita "heredoc" de Perl.

scalar = <<BOUNDARY_STRING
line 1
line 2: Los espacios/saltos de línea dentro de un documento HERE se conservan.
line 3: El último salto de línea (\n) se elimina.
BOUNDARY_STRING
hash   key1 = <<'FOO'
  * Las comillas (['"]) alrededor de la cadena delimitadora simplemente se ignoran.
  * Si las variables en el documento HERE se expanden o no depende de la opción EXPAND de la variable o de la configuración global.
FOO
hash = key2 = <<"_bar_"
El texto dentro del documento HERE se conserva tal cual.
# los comentarios se tratan como texto normal.
Lo mismo aplica para la continuación de línea. \
_bar_

Tenga en cuenta que no puede usar un documento HERE como clave en un hash o como nombre de una variable.

El prefijo '-' puede usarse para restablecer una variable a su valor por defecto y el prefijo '+' puede usarse para establecerla en 1

-verbose
+debug

Expansión de variables, variables de entorno y tilde (directorio de inicio) Los valores de las variables pueden contener referencias a otras variables de AppConfig, variables de entorno y/o directorios de inicio de los usuarios. Estas se expandirán dependiendo del valor EXPAND de cada variable o del valor GLOBAL EXPAND.

Se pueden aplicar tres tipos diferentes de expansión:

bin = ~/bin          # expandir '~' al directorio de inicio si EXPAND_UID
tmp = ~abw/tmp       # como arriba, pero directorio de inicio para el usuario 'abw'
perl = $bin/perl     # expandir el valor de la variable 'bin' si EXPAND_VAR
ripl = $(bin)/ripl   # como arriba con paréntesis explícitos
home = ${HOME}       # expandir la variable de entorno HOME si EXPAND_ENV

Vea AppConfig::State para más información sobre la expansión de valores de variables.

Los archivos de configuración pueden tener variables organizadas en bloques. Un encabezado de bloque, que consiste en el nombre del bloque entre corchetes, introduce un bloque de configuración. El nombre del bloque y un guion bajo se anteponen entonces a los nombres de todas las variables referenciadas posteriormente en ese bloque. El bloque continúa hasta la siguiente definición de bloque o hasta el final del archivo actual.

[block1]
foo = 10             # block1_foo = 10
[block2]
foo = 20             # block2_foo = 20
