NOMBRE

apptainer-shell - Ejecuta un shell dentro de un contenedor

SINOPSIS

apptainer shell [opciones_shell...]

DESCRIPCIÓN

apptainer shell soporta los siguientes formatos:

*.sif Formato de Imagen Singularity (SIF). Nativo de Singularity
(3.0+) y Apptainer (v1.0.0+)

*.sqsh Formato SquashFS. Nativo de Singularity 2.4+

*.img Formato ext3. Nativo de versiones de Singularity < 2.4.

directorio/ formato sandbox. Directorio que contiene un sistema de archivos raíz válido
y opcionalmente metadatos de Apptainer.

instance://* Una instancia local en ejecución de un contenedor. (Ver el grupo
de comandos instance.)

library://* Un contenedor SIF alojado en una Biblioteca (ninguna por defecto)

docker://* Un contenedor Docker/OCI alojado en Docker Hub o en otro
registro OCI.

shub://* Un contenedor alojado en Singularity Hub.

oras://* Un contenedor SIF alojado en un registro OCI que soporta
la especificación OCI Registry As Storage (ORAS).

OPCIONES

--add-caps="" una lista de capacidades separadas por comas para añadir

--allow-setuid[=false] permite binarios setuid en el contenedor (solo root)

--app="" establece una aplicación para ejecutar dentro de un contenedor

--apply-cgroups="" aplica cgroups desde un archivo para los procesos del contenedor (solo root)

--authfile="" archivo de autenticación estilo Docker para usar al escribir/leer credenciales de registro OCI

-B, --bind=[] una especificación de ruta de enlace de usuario. La especificación tiene el formato src[:dest[:opts]], donde src y dest están fuera e dentro de las rutas. Si no se especifica dest, se establece igual a src. Las opciones de montaje (opts) pueden especificarse como 'ro' (solo lectura) o 'rw' (lectura/escritura, que es el valor predeterminado). Se pueden dar múltiples rutas de enlace mediante una lista separada por comas.

--blkio-weight=0 peso relativo de entrada/salida de bloque en el rango 10-1000, 0 para deshabilitar

--blkio-weight-device=[] peso relativo de entrada/salida de bloque específico del dispositivo

-e, --cleanenv[=false] limpia el entorno antes de ejecutar el contenedor

--compat[=false] aplica configuraciones para una mayor compatibilidad con OCI/Docker. Infiere --containall, --no-init, --no-umask, --no-eval, --writable-tmpfs.

-c, --contain[=false] usa un /dev mínimo y vacía otros directorios (por ejemplo, /tmp y $HOME) en lugar de compartir sistemas de archivos desde tu host

-C, --containall[=false] contiene no solo sistemas de archivos, sino también PID, IPC y entorno

--cpu-shares=-1 cuotas de CPU para el contenedor

--cpus="" Número de CPUs disponibles para el contenedor

--cpuset-cpus="" Lista de CPUs del host disponibles para el contenedor

--cpuset-mems="" Lista de nodos de memoria del host disponibles para el contenedor

--cwd="" directorio de trabajo inicial para el proceso payload dentro del contenedor (sinónimo de --pwd)

--disable-cache[=false] no usar ni crear caché

--dns="" lista de servidores DNS separados por comas para añadir en resolv.conf

--docker-host="" especifica un host de demonio Docker personalizado

--docker-login[=false] inicia sesión en un Repositorio Docker interactivamente

--drop-caps="" una lista de capacidades separadas por comas para eliminar

--env=[] pasa la variable de entorno al proceso contenido

--env-file=[] pasa variables de entorno desde un archivo al proceso contenido

-f, --fakeroot[=false] ejecuta el contenedor con la apariencia de ejecución como root

--fusemount=[] una especificación de montaje de sistema de archivos FUSE de la forma ': ' - donde es 'container' o 'host', especificando dónde se realizará el montaje ('container-daemon' o 'host-daemon' ejecutarán el proceso FUSE de forma desvinculada). es la ruta al ejecutable FUSE, más las opciones para el montaje. es la ubicación en el contenedor donde se adjuntará el montaje FUSE. Por ejemplo, 'container:sshfs 10.0.0.1:/ /sshfs'. Implica --pid.

-h, --help[=false] ayuda para shell

-H, --home="/build" una especificación de directorio personal. La especificación puede ser una ruta src o un par src:dest. src es la ruta de origen del directorio personal fuera del contenedor y dest anula el directorio personal dentro del contenedor.

--hostname="" establece el nombre de host del contenedor

-i, --ipc[=false] ejecuta el contenedor en un nuevo espacio de nombres IPC

--keep-privs[=false] permite que el usuario root conserve privilegios en el contenedor (solo root)

--memory="" límite de memoria en bytes

--memory-reservation="" límite blando de memoria en bytes

--memory-swap="" límite de swap, usa -1 para swap ilimitado

--mount=[] una especificación de montaje, por ejemplo, 'type=bind,source=/opt,destination=/hostopt'.

-n, --net[=false] ejecuta el contenedor en un nuevo espacio de nombres de red (configura una interfaz de red bridge por defecto)

--netns-path="" une al espacio de nombres de red en la ruta especificada (como root, o si está permitido en apptainer.conf)

--network="" especifica el tipo de red deseado separado por comas, cada red activará una interfaz dedicada dentro del contenedor

--network-args=[] especifica argumentos de red para pasar a los plugins CNI

--no-eval[=false] no evalúa variables de entorno ni CMD/ENTRYPOINT/ARGS del contenedor OCI en el shell

--no-home[=false] NO monta el directorio personal del usuario si /home no es el directorio de trabajo actual

--no-https[=false] usa http en lugar de https para URIs docker://, oras:// y library:///...

--no-init[=false] NO inicia el proceso shim con --pid

--no-mount=[] deshabilita una o más opciones 'mount xxx' establecidas en apptainer.conf y/o especifica una ruta de destino absoluta para deshabilitar una entrada de ruta de enlace, o 'bind-paths' para deshabilitar todas las entradas de ruta de enlace.

--no-pid[=false] no ejecuta el contenedor en un nuevo espacio de nombres PID

--no-privs[=false] elimina todos los privilegios del usuario root en el contenedor)

--no-umask[=false] no propaga umask al contenedor, establece umask predeterminada 0022

--nv[=false] habilita soporte Nvidia

--nvccli[=false] usa nvidia-container-cli para la configuración de GPU (experimental)

--oom-kill-disable[=false] Deshabilita el asesino OOM

-o, --overlay=[] usa una imagen overlayFS para almacenamiento persistente de datos o como capa de solo lectura del contenedor

--passphrase[=false] solicita una contraseña de cifrado

--pem-path="" introduce la ruta a una clave RSA en formato PEM para un contenedor cifrado

-p, --pid[=false] ejecuta el contenedor en un nuevo espacio de nombres PID

--pids-limit=0 Límite del número de PIDs del contenedor, usa -1 para ilimitado

--rocm[=false] habilita soporte Rocm experimental

-S, --scratch=[] incluye un directorio scratch dentro del contenedor que está enlazado a un directorio temporal (usa -W para forzar la ubicación)

--security=[] habilita características de seguridad (SELinux, Apparmor, Seccomp)

--sharens[=false] comparte el espacio de nombres y la imagen con otros contenedores lanzados desde el mismo proceso padre

-s, --shell="" ruta al programa a utilizar para el shell interactivo

--unsquash[=false] convierte el archivo SIF a una sandbox temporal antes de ejecutar

-u, --userns[=false] ejecuta el contenedor en un nuevo espacio de nombres de usuario

--uts[=false] ejecuta el contenedor en un nuevo espacio de nombres UTS

-W, --workdir="" directorio de trabajo a utilizar para /tmp, /var/tmp y $HOME (si también se usó -c/--contain)

-w, --writable[=false] por defecto, todos los contenedores Apptainer son de solo lectura. Esta opción hace que el sistema de archivos sea accesible como lectura/escritura.

--writable-tmpfs[=false] hace que el sistema de archivos sea accesible como lectura/escritura con datos no persistentes (solo con soporte overlay)

EJEMPLO

  $ apptainer shell /tmp/Debian.sif
  Apptainer/Debian.sif> pwd
  /home/gmk/test
  Apptainer/Debia

NAME

apptainer-shell — invoke an interactive shell within an Apptainer container

SYNOPSIS

apptainer shell [OPTIONS] CONTAINER[:[CONTAINER_PATH]]

apptainer shell [OPTIONS] instance://INSTANCE_NAME

DESCRIPTION

This command invokes an interactive shell within an Apptainer container. This allows you to execute commands inside the container as if you were logged into the environment.

You can specify the container image file or a remote container URL. You can also specify an instance name to interact with a running instance.

By default, apptainer shell starts a shell in the container's default working directory. You can change this using the -C or --chdir option.

If you need to modify the container, you must use the --writable or -w option when running apptainer shell. Note that modifying containers is generally discouraged for reproducibility. It's better to build new container images with your changes.

OPTIONS

-C, --chdir
Change directory to CONTAINER_PATH inside the container before starting the shell.
-e, --env-file
Print container environment variables loaded from the specified file. Not applicable for shell command.
-N, --no-eval
Do not evaluate shell arguments. Useful when the shell arguments contain special characters.
-u, --user
Run container processes with the specified username or UID. If not specified, the username or UID from the host is used.
-w, --writable
Make the container filesystem writable. This is required to modify the container.
--help
Print usage message.

EXAMPLE

Start an interactive shell in a container and change the directory to /app:

$ apptainer shell -C /app Debian.sif
Apptainer/Debian.sif:/app>

Start an interactive shell in a container, making it writable:

$ apptainer shell -w Debian.sif
Apptainer/home/gmk>
Apptainer/home/gmk> exit

Start an interactive shell in a running instance named my_instance:

$ apptainer shell instance://my_instance
Apptainer container:~>

Show running processes inside the container (run this command from within the container shell):

Apptainer container:~> ps -ef
  UID        PID  PPID  C STIME TTY          TIME CMD
 ubuntu       1     0  0 20:00 ?        00:00:00 /usr/local/bin/apptainer/bin/appinit
 ubuntu       2     0  0 20:01 pts/8    00:00:00 /bin/bash --norc
 ubuntu       3     2  0 20:02 pts/8    00:00:00 ps -ef
