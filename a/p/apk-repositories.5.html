apk-repositories(5) Manual de formatos de archivo apk-repositories(5)

NOMBRE

/etc/apk/repositories
/etc/apk/repositories.d/*.list
/lib/apk/repositories.d/*.list
lista de repositorios de paquetes

DESCRIPCIÓN

apk(8) carga definiciones de repositorios desde los archivos mencionados anteriormente.

Primero se carga el archivo repositories. Luego se procesan las rutas de repositories.d si no se utilizó la opción --repositories-file. Los directorios se enumeran en el orden mencionado anteriormente. Una vez que se ve un archivo .list con un nombre dado, se ignora cualquier archivo del mismo nombre en directorios posteriores.

FORMATO DEL ARCHIVO

Cada línea sigue una de las siguientes sintaxis:

# comentario

Una línea de comentario que se ignora.

set [-default] clave=valor

Establece la variable llamada clave al valor dado.

La clave se limita a letras, números y el carácter de subrayado (_), y debe comenzar con una letra. Los nombres de variables con prefijo APK_ están reservados para variables integradas y no pueden ser definidos por el usuario.

Se realiza una expansión de variable en el valor antes de la asignación.

Si se especifica la opción -default, el valor de la clave no se modifica si ya existe.

Actualmente, las siguientes variables están definidas:

•
APK_ARCH, la arquitectura principal de la base de datos

ndx [@tag] url
[v2|v3] [@tag] url [componente...]

Si una declaración de repositorio omite el campo de tipo, este toma por defecto el tipo definido en el último comando default, o si está ausente, toma v2 (o ndx si url termina en .adb o .tar.gz). Si el formato es v3 o el nombre de archivo ndx termina en .adb, se requiere un archivo de índice en formato v3.

El @tag opcional puede estar presente para indicar que el repositorio no debe usarse por defecto. Consulte apk-world(5) sobre cómo habilitar la instalación de paquetes de repositorios etiquetados.

Se realiza una expansión de variable en las porciones de url y componente individualmente en el momento de analizar la línea.

La url se refiere a un archivo de índice o a una ruta de repositorio. Los esquemas admitidos actualmente son:

  • http://
  • https://
  • file://
  • ruta de sistema de archivos absoluta (debe comenzar con `/`)

La lista de componente especifica una lista de componentes del repositorio. Si se especifica, la línea se expande a varias URLs: una para cada componente, y el componente se agrega a la url. Especificar un componente con el tipo ndx no es válido.

EJEMPLOS

Para definir una lista de repositorios proporcionada por la distribución, la distribución puede enviar, por ejemplo, /lib/apk/repositories.d/distribution.list con el siguiente contenido:

set -default distro_mirror=https://example.com/distro
v3 ${distro_mirror} main community

En /etc/apk/repositories.d/00-vars.list, el espejo puede ser reemplazado con:

set distro_mirror=https://mirror.example.com/distro

DISEÑO DEL REPOSITORIO

Si el tipo es ndx, el diseño y la resolución de rutas son los siguientes:

  • url es una URL al archivo de índice
  • base_url es url con el último componente eliminado
  • ruta de paquete predeterminada: $base_url/$nombre-$version.apk

De lo contrario, el tipo es uno de los tipos de repositorio, y la resolución de rutas funciona de la siguiente manera:

  • url es el base_url al repositorio
  • índice (v3) está en $base_url/$arch/Packages.adb
  • índice (v2) está en $base_url/$arch/APKINDEX.tar.gz
  • ruta de paquete predeterminada: $base_url/$arch/$nombre-$version.apk

Si el archivo de índice tiene un pkgname-spec establecido, se utiliza para construir la ruta del paquete. De lo contrario, se utiliza la ruta de paquete predeterminada según las reglas anteriores.

CREACIÓN DE ÍNDICES Y REPOSITORIOS

Consulte apk-mkndx(8) sobre cómo crear archivos de índice y apk-adbsign(8) sobre cómo modificar firmas.

Para el formato de índice heredado, consulte apk-index(8) para archivos de índice, abuild-keygen(1) para obtener información sobre la generación de claves, abuild-sign(1) para obtener información sobre el uso de estas claves para firmar archivos.

apk-verify(8) puede verificar archivos de índice y paquetes tanto del estilo nuevo como del antiguo.

ACTUALIZACIÓN DEL ÍNDICE DEL CLIENTE

apk(8) descarga y almacena el índice de cada repositorio en una caché local en /etc/apk/cache o /var/cache/apk. Consulte apk-cache(5) para más detalles.

Consulte apk-keys(5) sobre cómo el cliente necesita configurarse para verificar las firmas del índice.
