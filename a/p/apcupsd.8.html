APCUPSD(8) Manual del Administrador del Sistema APCUPSD(8)

NOMBRE

apcupsd — un demonio para controlar la mayoría de los SAI APC

SINOPSIS

apcupsd [-b] [-d nivel | --debug nivel] [-f archivo | --config-file archivo] [-P archivo | --pid-file archivo] [-p | --kill-on-powerfail | -t | --term-on-powerfail] [-R]

apcupsd [-k | --killpower | --hibernate | -o | --power-off]

apcupsd [-h | --help]

apcupsd [-V | --version]

DESCRIPCIÓN

apcupsd controla la operación de la mayoría de los SAI (Sistema de Alimentación Ininterrumpida) de American Power Conversion Corp (APC). Durante un corte de energía, apcupsd informa a los usuarios sobre la pérdida de energía de la red eléctrica y que puede ocurrir un apagado. Si la energía de la red eléctrica no se restaura, se producirá un apagado del sistema cuando la batería se agote, expire un tiempo de espera especificado, se alcance un porcentaje de carga de batería especificado o expire un tiempo de ejecución de batería especificado (basado en cálculos internos del SAI y determinado por las tasas de consumo de energía). Si la energía de la red eléctrica se restaura antes de que se cumpla alguna de estas condiciones de apagado, apcupsd informará de ello y, en general, se cancelará el apagado. Consulte la sección Notas de Implementación más abajo para conocer situaciones en las que el apagado puede no ser cancelado.

El significado de las opciones de línea de comandos es el siguiente:

-b
Ejecutar en primer plano, no separarse y convertirse en un demonio.
-d nivel --debug nivel
Establece el nivel de salida de depuración, donde el nivel es un número mayor que cero.
-f archivo --config-file archivo
Carga el archivo de configuración especificado. El archivo de configuración predeterminado es /etc/apcupsd/apcupsd.conf. Debe modificarse al ejecutar más de una copia de apcupsd en el mismo ordenador para controlar varios SAI.
-k | --killpower | --hibernate
Apaga el SAI en modo de hibernación después de un retraso de 10 segundos. Esta opción normalmente solo la usa el propio apcupsd para apagar el SAI después de que el apagado del sistema se haya completado casi por completo. En modo de hibernación, el SAI volverá a suministrar energía al sistema cuando regrese la energía de la red.
-o | --power-off
Apaga completamente el SAI. El SAI no suministrará energía al sistema cuando regrese la energía de la red.
-P archivo --pid-file archivo
Crea el archivo de ID de proceso especificado. El valor predeterminado es /var/run/apcupsd.pid. Debe modificarse al ejecutar más de una copia de apcupsd en el mismo ordenador para controlar varios SAI.
-p --kill-on-powerfail
apcupsd ordena al SAI que se apague en modo de hibernación justo antes de que apcupsd inicie el apagado del sistema. Esto depende del retraso de apagado seguro de un Smart-UPS, que debe ser lo suficientemente largo para permitir que el sistema se apague completamente antes de que el SAI corte la energía al sistema y entre en modo de hibernación. Este retraso de apagado seguro es un valor programable almacenado en la memoria EEPROM de un Smart-UPS que se puede cambiar usando apctest(8). En modo de hibernación, el SAI volverá a suministrar energía al sistema cuando regrese la energía de la red. Consulte apcupsd.conf(5) para un método alternativo que utiliza la directiva de configuración KILLDELAY y el único método disponible cuando se utiliza un Back-UPS u otro SAI que opera en modo de señalización simple.
-t --term-on-powerfail
apcupsd sale inmediatamente cuando emite el comando de apagado del sistema. Este comportamiento es útil para aquellos sistemas donde no es posible insertar comandos de apcupsd en un script de detención para emitir el comando killpower. Sin esta opción, apcupsd esperará la señal SIGTERM del proceso de apagado del sistema antes de salir.
-R
Pone un SAI que se ejecuta en modo de señalización inteligente por defecto (por ejemplo, un Smart-UPS) en modo de señalización simple.
-v --version
Imprime el número de versión de apcupsd y la ayuda del programa.
-h --help
Imprime la ayuda del programa.

El demonio apcupsd soporta un modo de red llamado Servidor de Información de Red (NIS) —no relacionado con NIS/YP de Sun— en el cual el demonio sirve información de estado y eventos a clientes a través de una red. Consulte la sección "Running The Network Information Server" del manual de apcupsd para obtener más información y detalles de configuración sobre este modo.

El demonio apcupsd también soporta un Smart-UPS en modo SNMP, siempre que una tarjeta APC Web/SNMP o APC PowerNet SNMP esté instalada en la SmartSlot del SAI. Para obtener más información y detalles de configuración sobre este modo, consulte la sección "Support for SNMP UPSes" del manual de apcupsd.

NOTAS DE IMPLEMENTACIÓN

El apagado se realiza mediante llamadas al script /etc/apcupsd/apccontrol por parte del demonio apcupsd. En consecuencia, no son necesarios cambios en /etc/inittab en Linux, ya que no hay comunicación entre el demonio y el proceso init(1). La instalación del demonio modifica el script de detención para que al final del proceso de apagado, el demonio se re-ejecute para apagar el SAI en modo de hibernación.

En algunos sistemas operativos (por ejemplo, FreeBSD) no hay un script de detención, por lo que se debe modificar apccontrol para que el demonio apague el SAI después de un retraso. Las alternativas son usar el comando --kill-on-powerfail en la línea de comandos de apcupsd o consultar apcupsd.conf(5) para ver los detalles de la directiva de configuración KILLDELAY.

CONFIGURACIÓN

Es casi seguro que será necesario personalizar la información de configuración en el archivo de configuración /etc/apcupsd/apcupsd.conf para adaptarla a su configuración y al comportamiento deseado del SAI.

Para obtener información sobre las directivas de configuración y el formato del archivo de configuración, consulte apcupsd.conf(5).

FORMATO DEL ARCHIVO DE DATOS

Si la directiva de configuración DATATIME está establecida en un valor distinto de cero, apcupsd registrará un registro de datos en el intervalo definido por la directiva DATATIME. Este registro de datos está en un formato similar al formato del archivo de datos del software APC PowerChute.

FORMATO DEL INFORME DE ESTADO

El formato de salida del informe de estado es ASCII simple. Generalmente hay una sola pieza de información en cada línea de salida. El contenido varía según el modelo de UPS utilizado y, en algunos casos, la versión del firmware. Este informe de estado también se escribe opcionalmente en el /etc/apcupsd/apcupsd.status archivo. Consulte apcaccess(8) para obtener detalles completos sobre la salida del informe de estado.

ARCHIVOS

/etc/apcupsd/apcupsd.conf archivo de configuración predeterminado

/var/run/apcupsd.pid archivo de ID de proceso predeterminado

/var/log/apcupsd.status archivo de estado opcional

/var/log/apcupsd.events archivo de eventos predeterminado
