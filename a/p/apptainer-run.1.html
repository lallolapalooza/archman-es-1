NAME

\n

apptainer-run - Ejecuta el comando predeterminado definido por el usuario dentro de un contenedor

\n
\n
\n

SYNOPSIS

\n

apptainer run [opciones de ejecución...] [args...]

\n
\n
\n

DESCRIPTION

\n

Este comando iniciará un contenedor Apptainer y ejecutará un script de ejecución (runscript)\n
\nsi uno está definido para ese contenedor. El script de ejecución es un archivo de metadatos dentro\n
\ndel contenedor que contiene comandos shell. Si el archivo está presente (y\n
\nes ejecutable), este comando ejecutará automáticamente ese archivo dentro del contenedor.\n Todos los argumentos que sigan al nombre del contenedor se pasarán\n
\ndirectamente al script de ejecución.

\n

apptainer run acepta los siguientes formatos de contenedor:

\n

*.sif Formato de Imagen de Singularity (SIF). Nativo de Singularity\n
\n(3.0+) y Apptainer (v1.0.0+)

\n

*.sqsh Formato SquashFS. Nativo de Singularity 2.4+

\n

*.img Formato ext3. Nativo de versiones de Singularity < 2.4.

\n

directorio/ formato sandbox. Directorio que contiene un sistema de archivos raíz válido\n
\ny opcionalmente metadatos de Apptainer.

\n

instance://* Una instancia local en ejecución de un contenedor. (Ver el grupo de\n
\ncomandos instance.)

\n

library://* Un contenedor SIF alojado en una Biblioteca (sin predeterminar)

\n

docker://* Un contenedor Docker/OCI alojado en Docker Hub u otro\n
\nregistro OCI.

\n

shub://* Un contenedor alojado en Singularity Hub.

\n

oras://* Un contenedor SIF alojado en un registro OCI que soporta\n
\nespecificación OCI Registry As Storage (ORAS).

\n
\n
\n

OPTIONS

\n

--add-caps="" una lista de capacidades separada por comas para agregar

\n

--allow-setuid[=false] permite binarios setuid en el contenedor (solo root)

\n

--app="" establece una aplicación a ejecutar dentro de un contenedor

\n

--apply-cgroups="" aplica cgroups desde un archivo para los procesos del contenedor (solo root)

\n

--authfile="" archivo de autenticación estilo Docker a usar para escribir/leer credenciales de registro OCI

\n

-B, --bind=[] una especificación de ruta de enlace de usuario. La especificación tiene el formato src[:dest[:opts]], donde src y dest están fuera y dentro de las rutas. Si no se proporciona dest, se establece igual a src. Las opciones de montaje ('opts') pueden especificarse como 'ro' (solo lectura) o 'rw' (lectura/escritura, que es el predeterminado). Se pueden especificar múltiples rutas de enlace mediante una lista separada por comas.

\n

--blkio-weight=0 peso relativo de E/S de bloque en el rango 10-1000, 0 para deshabilitar

\n

--blkio-weight-device=[] peso relativo de E/S de bloque específico del dispositivo

\n

-e, --cleanenv[=false] limpia el entorno antes de ejecutar el contenedor

\n

--compat[=false] aplica configuraciones para una mayor compatibilidad OCI/Docker. Infiere --containall, --no-init, --no-umask, --no-eval, --writable-tmpfs.

\n

-c, --contain[=false] usa /dev mínimo y vacía otros directorios (por ejemplo, /tmp y $HOME) en lugar de compartir sistemas de archivos del host

\n

-C, --containall[=false] contiene no solo sistemas de archivos, sino también PID, IPC y entorno

\n

--cpu-shares=-1 comparticiones de CPU para el contenedor

\n

--cpus="" Número de CPUs disponibles para el contenedor

\n

--cpuset-cpus="" Lista de CPUs del host disponibles para el contenedor

\n

--cpuset-mems="" Lista de nodos de memoria del host disponibles para el contenedor

\n

--cwd="" directorio de trabajo inicial para el proceso payload dentro del contenedor (sinónimo de --pwd)

\n

--disable-cache[=false] no usar ni crear caché

\n

--dns="" lista de servidores DNS separados por comas para agregar a resolv.conf

\n

--docker-host="" especifica un host de daemon Docker personalizado

\n

--docker-login[=false] inicia sesión en un Repositorio Docker interactivamente

\n

--drop-caps="" una lista de capacidades separada por comas para eliminar

\n

--env=[] pasa la variable de entorno al proceso contenido

\n

--env-file=[] pasa las variables de entorno desde un archivo al proceso contenido

\n

-f, --fakeroot[=false] ejecuta el contenedor con la apariencia de estar ejecutándose como root

\n

--fusemount=[] una especificación de montaje de sistema de archivos FUSE del formato ': ' - donde es 'container' o 'host', especificando dónde se realizará el montaje ('container-daemon' o 'host-daemon' ejecutarán el proceso FUSE desvinculado). es la ruta al ejecutable FUSE, más opciones de montaje. es la ubicación en el contenedor a la que se adjuntará el montaje FUSE. Por ejemplo, 'container:sshfs 10.0.0.1:/ /sshfs'. Implica --pid.

\n

-h, --help[=false] ayuda para run

\n

-H, --home="/build" una especificación del directorio home. La especificación puede ser una ruta src o un par src:dest. src es la ruta de origen del directorio home fuera del contenedor y dest reemplaza el directorio home dentro del contenedor.

\n

--hostname="" establece el nombre de host del contenedor

\n

-i, --ipc[=false] ejecuta el contenedor en un nuevo espacio de nombres IPC

\n

--keep-privs[=false] permite que el usuario root mantenga privilegios en el contenedor (solo root)

\n

--memory="" límite de memoria en bytes

\n

--memory-reservation="" límite suave de memoria en bytes

\n

--memory-swap="" límite de swap, usa -1 para swap ilimitado

\n

--mount=[] una especificación de montaje, por ejemplo, 'type=bind,source=/opt,destination=/hostopt'.

\n

-n, --net[=false] ejecuta el contenedor en un nuevo espacio de nombres de red (configura una interfaz de red bridge por defecto)

\n

--netns-path="" se une al espacio de nombres de red en la ruta especificada (como root, o si se permite en apptainer.conf)

\n

--network="" especifica el tipo de red deseado separado por comas, cada red activará una interfaz dedicada dentro del contenedor

\n

--network-args=[] especifica los argumentos de red a pasar a los plugins CNI

\n

--no-eval[=false] no evalúa shell para variables de entorno o CMD/ENTRYPOINT/ARGS del contenedor OCI

\n

--no-home[=false] NO monta el directorio home del usuario si /home no es el directorio de trabajo actual

\n

--no-https[=false] usa http en lugar de https para las URIs docker://, oras:// y library:///...

\n

--no-init[=false] NO inicia el proceso shim con --pid

\n

--no-mount=[] deshabilita una o más opciones 'mount xxx' establecidas en apptainer.conf y/o especifica una ruta de destino absoluta para deshabilitar una entrada de ruta de enlace, o 'bind-paths' para deshabilitar todas las entradas de ruta de enlace.

\n

--no-pid[=false] no ejecuta el contenedor en un nuevo espacio de nombres PID

\n

--no-privs[=false] elimina todos los privilegios del usuario root en el contenedor)

\n

--no-umask[=false] no propaga umask al contenedor, establece umask predeterminada 0022

\n

--nv[=false] habilita soporte Nvidia

\n

--nvccli[=false] usa nvidia-container-cli para la configuración de GPU (experimental)

\n

--oom-kill-disable[=false] Deshabilita el asesino OOM

\n

-o, --overlay=[] usa una imagen overlayFS para almacenamiento persistente de datos o como capa de solo lectura del contenedor

\n

--passphrase[=false] solicita una contraseña de cifrado

\n

--pem-path="" introduce una ruta a una clave RSA con formato PEM para un contenedor cifrado

\n

-p, --pid[=false] ejecuta el contenedor en un nuevo espacio de nombres PID

\n

--pids-limit=0 limita el número de PIDs del contenedor, usa -1 para ilimitado

\n

--rocm[=false] habilita soporte experimental Rocm

\n

--runscript-timeout="" establece la duración del tiempo de espera para el script de ejecución (predeterminado 1m)

\n

-S, --scratch=[] incluye un directorio scratch dentro del contenedor que está vinculado a un directorio temporal (usa -W para forzar la ubicación)

\n

--security=[] habilita características de seguridad (SELinux, Apparmor, Seccomp)

\n

--sharens[=false] comparte el espacio de nombres y la imagen con otros contenedores lanzados desde el mismo proceso padre

\n

--unsquash[=false] convierte el archivo SIF a un sandbox temporal antes de ejecutar

\n

-u, --userns[=false] ejecuta el contenedor en un nuevo espacio de nombres de usuario

\n

--uts[=false] ejecuta el contenedor en un nuevo espacio de nombres UTS

\n

-W, --workdir="" directorio de trabajo a utilizar para /tmp, /var/tmp y $HOME (si también se usó -c/--contain)

\n

-w, --writable[=f" } ] falso] De forma predeterminada, todos los contenedores de Apptainer están disponibles como de solo lectura. Esta opción hace que el sistema de archivos sea accesible como de lectura/escritura

.

--writable-tmpfs[=false] hace que el sistema de archivos sea accesible como de

lectura/escritura con datos no persiste
ntes (solo con soporte de superposición)
