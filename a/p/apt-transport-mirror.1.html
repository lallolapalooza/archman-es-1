Este transporte de APT no implementa por sí mismo un protocolo para acceder a repositorios locales o remotos, sino que obtiene una lista de espejos (mirrorlist) y redirige todas las peticiones a los espejos elegidos de esta lista,apt-tran. La funcionalidad básica ha estado disponible desde apt 0.7.24, pero estuvo indocumentada hasta apt 1.6, que contenía una reescritura completa del transporte y sus características soportadas. Tenga en cuenta que un transporte nunca es llamado directamente por un usuario, sino que es usado
del usuario.

Si la obtención de un archivo a través de un espejo falla, el método asegura que se intente automáticamente otro espejo posible de la lista hasta que el archivo sea obtenido o no queden espejos en la lista, manejando de forma transparente los

tiempos de inactividad del servidor y problemas similares.

Las implicaciones de seguridad del transporte dependen de las consideraciones de

seguridad asociadas con el transporte usado para obtener la lista de espejos y lo
s transportes involucrados en el acceso a los espejos elegidos por el transporte.

Este transporte no tiene opciones de configuración en la actualidad. La selección del espejo se basa enteramente en los espejos ofrecidos en la lista de espejos y los archivos que APT necesita obtener. Formato de la lista de

espejos

Una lista de espejos contiene una o más líneas, cada una especificando un URI para un espejo. Las líneas vacías y aquellas que comienzan con un carácter de almohadilla (#) se ignoran. Un URI siempre comienza con un esquema de URI que define el transporte usado para este espejo. Si, por ejemplo, el URI comienza con http:, el transporte responsable

es

apt-tra

nsport-
http(1)

el cual puede tener requisitos específicos para el formato de la parte restante

del URI.

Los metadatos sobre un espejo pueden darse en la misma línea, separados del URI por un tabulador. Múltiples elementos de metadatos pueden a su vez separarse por tabuladores o espacios. (Esta es una característica avanzada solo disponible con apt >= 1.6. Las versiones anteriores de apt fallarán al analizar listas de espejos que usen esta característica.

)

Desde apt 1.6 también se soporta el uso de listas de espejos comprimidas. Tenga en cuenta que el nombre de archivo de la lista de espejos debe especificar el algoritmo de compresión usado; no hay autodetección basada en el contenido

del archivo.

Selección de espejos por metadatos Como se especifica en el formato, un espejo puede tener metadatos adicionales adjuntos para evitar que un espejo sea seleccionado para obtener un archivo que no coincida con estos metadatos. De esta manera la lista de espejos puede, por ejemplo, contener espejos parciales que sirvan solo ciertas arquitecturas y APT elegirá automáticamente un espejo diferente para archivos que requieran una arquitectura no listada. Se soportan límites para la arquitectura (arch), el nombre en clave del lanzamiento (codename), el componente del repositorio en el que está el archivo (component), el idioma al que aplica el archivo (lang), el nombre de la suite del lanzamiento (suite) y el tipo de archivo

(type).

Orden de respaldo para los

espejos

Si no se da una prioridad para un espejo a través de la clave de metadatos priority, el orden en el que se contactan los espejos es aleatorio. Si un conjunto determinado de espejos debe ser intenta

do antes que cualquier otro de otro conjunto, se puede establecer explícitamente una prioridad. Los espejos con el número más bajo se intentan primero. Los espejos que no tienen una prioridad e
xplícita establecida tienen como valor por defecto el número más alto posible y por lo tanto se intentan en último lugar. La elección entre espejos con la misma prioridad es de nuevo aleatoria.

Transportes permitidos en una lista de

espejos

La disponibilidad y elección de transportes en una lista de espejos está limitada por cómo el cliente APT está accediendo a la lista de espejos. Si se usa un transporte local como

file o copy, la lista de espejos también puede incluir fuentes locales, mientras que una lista de espejos accedida vía http no puede. Adicionalmente, una lista de espejos no pu
ede contener otra lista de espejos u otros transportes envolventes (como apt-transport-tor). Vea la documentación de estos transportes para saber cómo usarlos con el método mirror.

Tenga en cuenta que las versiones de apt anteriores a 1.6 no soportan ningún transporte que no sea

http.
