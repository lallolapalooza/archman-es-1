DESCRIPCIÓ

N

/etc/apt/apt.conf es el archivo de configuración principal compartido por todas las herramientas del conjunto de herramientas APT, aunque no es el único lugar donde se pueden establecer opciones. El conjunto también comparte un analizador de línea de comandos común para proporcionar un entorno

uniforme.

Cuando una herramienta APT se inicia, leerá los archivos de configuración en el siguiente

orden:
1.el archivo especificado por la variable de entorno APT_CONFIG (si
existe)
2.todos los archivos en Dir::Etc::Parts en orden alfanumérico ascendente que no tengan extensión de nombre de archivo o que tengan "conf" como extensión y que solo contengan caracteres alfanuméricos, guion (-), guion bajo (_) y punto (.). De lo contrario, APT imprimirá un aviso de que ha ignorado un archivo, a menos que ese archivo coincida con un patrón en la lista de configuración Dir::Ignore-Files-Silently - en cuyo caso será ignorado silenciosamente
.
3.el archivo de configuración principal especificado por Dir::Etc::
main
4.todas las opciones establecidas en el subárbol de configuración específico del binario se mueven a la raíz del
árbol.
5.las opciones de la línea de comandos se aplica
n para anular las directivas de configuración
o para cargar aún más archivos de configuración.

SINTAXI

S

El archivo de configuración está organizado en un árbol con opciones organizadas en grupos funcionales. La especificación de la opción se da con una notación de doble dos puntos; por ejemplo, APT::Get::Assume-Yes es una opción dentro del grupo de herramientas APT, para la herramienta Get. Las opciones no heredan de sus grupos

padre.

Sintácticamente, el lenguaje de configuración está modelado después de lo que las herramientas ISC como bind y dhcp usan. Las líneas que comienzan con // se tratan como comentarios (ignorados), así como todo el texto entre /* y */, igual que los comentarios de C/C++. Las líneas que comienzan con # también se tratan como comentarios. Cada línea es de la forma APT::Get::Assume-Yes "true";. Las comillas y el punto y coma final son obligatorios. El valor debe estar en una sola línea, y no hay ningún tipo de concatenación de cadenas. Los valores no deben incluir barras invertidas ni comillas adicionales. Los nombres de las opciones están compuestos por caracteres alfanuméricos y los caracteres "/-:._+". Se puede abrir un nuevo ámbito con llaves de curva,

así: 
APT {
  Get {
    Assume-Yes "true";
    Fix-Broken "true";
  };
}
;

con saltos de línea colocados para hacerlo más legible. Se pueden crear listas abriendo un ámbito e incluyendo una sola cadena entre comillas seguida de un punto y coma. Se pueden incluir múltiples entradas, separadas por un punto y

coma. 
DPkg::Pre-Install-Pkgs {"/usr/sbin/dpkg-preconfigure --apt";
}
;

En general, el archivo de configuración de ejemplo /usr/share/doc/apt/examples/configure-index es una buena guía de cómo debería

verse.

Las mayúsculas y minúsculas no son significativas en los nombres de los elementos de configuración, así que en el ejemplo anterior podrías usar dpkg::pre-install-pkgs

.

Los nombres de los elementos de configuración son opcionales si se define una lista, como se puede ver en el ejemplo de DPkg::Pre-Install-Pkgs anterior. Si no especificas un nombre, una nueva entrada simplemente añadirá una nueva opción a la lista. Si especificas un nombre, puedes anular la opción de la misma manera que cualquier otra opción reasignando un nuevo valor a la

opción.

Se definen dos comandos especiales: #include (que está obsoleto y no es compatible con implementaciones alternativas) y #clear. #include incluirá el archivo dado, a menos que el nombre del archivo termine en una barra diagonal, en cuyo caso se incluirá todo el directorio. #clear se usa para borrar una parte del árbol de configuración. El elemento especificado y todos sus descendientes son borrados. (Ten en cuenta que estas líneas también deben terminar con un punto y coma.

)

El comando #clear es la única forma de borrar una lista o un ámbito completo. Reabrir un ámbito (o usar la sintaxis descrita a continuación con un :: adjunto) no anulará las entradas escritas previamente. Las opciones solo se pueden anular asignándoles un nuevo valor - las listas y los ámbitos no se pueden anular, solo se pueden

borrar.

Todas las herramientas APT aceptan una opción -o que permite especificar una directiva de configuración arbitraria en la línea de comandos. La sintaxis es un nombre de opción completo (APT::Get::Assume-Yes, por ejemplo) seguido de un signo de igualdad y luego el nuevo valor de la opción. Para añadir un nuevo elemento a una lista, añade un :: al final del nombre de la lista. (Como podrías sospechar, la sintaxis de ámbito no se puede usar en la línea de comandos.

)

Ten en cuenta que añadir elementos a una lista usando :: solo funciona para un elemento por línea, y que no debes usarlo en combinación con la sintaxis de ámbito (que añade :: implícitamente). Usar ambas sintaxis juntas desencadenará un error del que algunos usuarios lamentablemente dependen: una opción con el nombre inusual "::" que actúa como cualquier otra opción con un nombre. Esto introduce muchos problemas; por un lado, los usuarios que escriben múltiples líneas en esta sintaxis incorrecta con la esperanza de añadir a una lista lograrán lo contrario, ya que solo se usará la última asignación para esta opción "::". Las versiones futuras de APT

generarán errores y dejarán de funcionar si encuentran este uso indebido, así que por f
avor corrige tales declaraciones ahora mientras APT no se queja explícitamente de ellas.

Compresso

r
Este ámbito define qué formatos de compresión están soportados, cómo se puede realizar la compresión y descompresión si el soporte para este formato no está integrado directamente en apt, y un valor de costo que indica lo costoso que es comprimir algo en este formato. Immediate-Configu

re
Por defecto está activada, lo que hará que APT instale los paquetes esenciales e importantes lo antes posible en una operación de instalación/actualización, para limitar el efecto de una llamada

dpkg(1) fallida. Si esta opción está desactivada, APT trata un paquete importante de la misma manera que un paquete extra: entre el desempaquetado del paquete A y su configuración puede haber muchas otras llamadas de desempaquetado o configuración para otros paquetes no relacionados B, C, etc. Si estas

causan que la llamada a

satisfecha.

El marcador de configuración inmediata también se aplica en el caso potencialmente problemático de dependencias circulares, ya que una dependencia con el marcador inmediata es equivalente a una Pre-Dependencia. En teoría, esto permite a APT reconocer una situación en la que no puede realizar la configuración inmediata, abortar y sugerir al usuario que la opción se desactive temporalmente para permitir que la operación continúe. Nótese el uso de la palabra "teoría" aquí; en el mundo real este problema se ha encontrado raramente, en versiones de distribución no estables, y fue causado por dependencias incorrectas del paquete en cuestión o por un sistema en un estado ya roto; por lo tanto, no debería desactivar esta opción a ciegas, ya que el escenario mencionado anteriormente no es el único problema

que puede ayudar a prevenir en primer lugar.
Antes de ejecutar una operación grande como dist-upgrade con esta opción desactivada, debería intentar instalar explícitamente el paquete que APT no puede configurar inmediatamente; pero asegúrese de informar también de su problema a su distribución y al equipo de APT con el enlace de error (bug) de abajo, para que puedan trabajar en mejorar o corregir el proceso de actualización. Índices

Gzip
Al descargar índices comprimidos con gzip (Packages, Sources o Translations), mantenerlos comprimidos con gzip localmente en lugar de descomprimirlos. Esto ahorra bastante espacio en disco a costa de más requisitos de CPU al construir las cachés de paquetes locales. Por defecto es
false.

Idioma

s
La subsección Languages controla qué archivos Translation se descargan y en qué orden APT intenta mostrar las traducciones de descripciones. APT intentará mostrar la primera descripción disponible en el idioma que se liste primero. Los idiomas se pueden definir con sus códigos de idioma cortos o largos. Tenga en cuenta que no todos los archivos proporcionan archivos Translation para todos los idiomas; los códigos de idioma largos son especialmente raros.

La lista predeterminada incluye "environment" y "en". "environment" tiene un significado especial aquí: se reemplazará en tiempo de ejecución con los códigos de idioma extraídos de la variable de entorno LC_MESSAGES. También se asegurará de que estos códigos no se incluyan dos veces en la lista. Si LC_MESSAGES está establecido a "C", solo se usará el archivo Translation-en (si está disponible). Para forzar a APT a no usar ningún archivo Translation, use la configuración Acquire::Languages=none. "none" es otro código de significado especial que detendrá la búsqueda de un archivo Translation adecuado. Esto le dice a APT que descargue estas traducciones también, sin usarlas realmente a menos que el entorno especifique los idiomas. Así que la siguiente configuración de ejemplo resultará en el orden "en, de" en un entorno inglés o "de, en" en uno alemán. Tenga en cuenta que "fr" se descarga, pero no se usa a menos que APT se use en un entorno francés (donde el orden sería "fr, de, en")

. 
Acquire::Languages { "environment"; "de"; "en"; "none"; "fr";

DIRECTORIOS

La sección Dir::State contiene directorios relacionados con la información de estado local. lists es el directorio donde se colocan las listas de paquetes descargadas y status es el nombre del archivo de estado dpkg(1). preferences es el nombre del archivo de preferencias de APT. Dir::State contiene el directorio predeterminado para prefijar todos los subelementos si no comienzan con / o .

/.

Dir::Cache contiene ubicaciones relacionadas con la información de caché local, como las dos cachés de paquetes srcpkgcache y pkgcache, así como la ubicación donde colocar los archivos descargados, Dir::Cache::archives. La generación de cachés se puede desactivar estableciendo pkgcache o srcpkgcache en "". Esto ralentizará el inicio pero ahorrará espacio en disco. Probablemente sea preferible desactivar el pkgcache en lugar del srcpkgcache. Al igual que Dir::State, el directorio predeterminado está contenido en Dir::

Cache

Dir::Etc contiene la ubicación de los archivos de configuración, sourcelist da la ubicación de la lista de fuentes y main es el archivo de configuración predeterminado (la configuración no tiene efecto, a menos que se haga desde el archivo de configuración especificado por APT_CONF

IG).

La configuración Dir::Parts lee todos los fragmentos de configuración en orden léxico desde el directorio especificado. Después de esto, se carga el archivo de configuración

principal.

Los programas binarios son indicados por Dir::Bin. Dir::Bin::Methods especifica la ubicación de los manejadores de métodos y gzip, bzip2, lzma, dpkg, apt-get dpkg-source dpkg-buildpackage y apt-cache especifican la ubicación de los respectivos

programas.

El elemento de configuración RootDir tiene un significado especial. Si se establece, todas las rutas serán relativas a RootDir, incluso las rutas que se especifican de forma absoluta. Así, por ejemplo, si RootDir se establece en /tmp/staging y Dir::State::status se establece en /var/lib/dpkg/status, entonces el archivo de estado se buscará en /tmp/staging/var/lib/dpkg/status. Si desea prefijar solo las rutas relativas, establezca Dir en su

lugar.

La lista Ignore-Files-Silently se puede utilizar para especificar qué archivos APT debe ignorar silenciosamente al analizar l

os archivos en los directorios de fragmentos. Por defecto, un archivo que termine en .disabled, ~, .bak o .dpkg-[a-z]+ se ig
nora silenciosamente. Como se ve en el último valor predeterminado, estos patrones pueden usar sintaxis de expresión regular.

Pre-Install-Pkg

Esta es una lista de comandos de shell para ejecutar antes de invocar a dpkg(1). Al igual que options, esto debe especificarse en notación de lista. Los comandos se invocan en orden usando /bin/sh; si alguno falla, APT se abortará. APT pasará los nombres de archivo de todos los archivos .deb que va a instalar a los comandos, uno por línea en el descriptor de archivo solicitado, que por defecto es la entrada estándar.

La versión 2 de este protocolo envía más información a través del descriptor de archivo solicitado: una línea con el texto VERSION 2, el espacio de configuración de APT y una lista de acciones de paquetes con información de nombre de archivo y

versión.

Cada línea de directiva de configuración tiene la forma clave=valor. Los caracteres especiales (signos igual, saltos de línea, caracteres no imprimibles, comillas y signos de porcentaje en la clave, y saltos de línea, caracteres no imprimibles y signos de porcentaje en el valor) se codifican con %. Las listas se representan mediante múltiples líneas clave::=valor con la misma clave. La sección de configuración termina con una línea en

blanco.

Las líneas de acción de paquete consisten en cinco campos en la versión 2: nombre del paquete (sin calificación de arquitectura incluso si es foráneo), versión antigua, dirección del cambio de versión (< para actualizaciones, > para degradaciones, = para sin cambio), versión nueva, acción. Los campos de versión son "-" para ninguna versión en absoluto (por ejemplo, al instalar un paquete por primera vez; ninguna versión se trata como anterior a cualquier versión real, por lo que es una actualización, indicada como - < 1.23.4). El campo de acción es "**CONFIGURE**" si el paquete se está configurando, "**REMOVE**" si se está eliminando, o el nombre de archivo de un archivo .deb si se está desempaquetando

.

En la versión 3, después de cada campo de versión sigue la arquitectura de esa versión, que es "-" si no hay versión, y un campo que muestra el tipo MultiArch "same", "foreign", "allowed" o "none". Tenga en cuenta que "none" es un nombre de tipo incorrecto que se mantiene solo para ser compatible, debería leerse como "no" y se anima a los usuarios a que admitan

ambos.

La versión del protocolo a utilizar para el comando cmd se puede elegir estableciendo DPkg::Tools::options::cmd::Version en consecuencia, siendo la predeterminada la versión 1. Si APT no admite la versión solicitada, enviará la información en la versión más alta que

admite.

El descriptor de archivo a utilizar para enviar la información se puede solicitar con DPkg::Tools::options::cmd::InfoFD que por defecto es 0 para la entrada estándar y está disponible desde la versión 0.9.11. La compatibilidad con la opción se puede detectar buscando la variable de entorno APT_HOOK_INFO_FD que contiene el número del des

criptor de archivo util
izado como confirmación.
