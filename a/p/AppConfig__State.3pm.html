DESCRIPCIÓN

GENERAL

AppConfig::State es un módulo de Perl5 para manejar variables de configuración global para programas perl. Mantiene el estado de un número arbitrario de variables, manejando valores predeterminados, alias, validación, devoluciones de llamada de actualización y argumentos de opción para su uso por otros módulos AppConfig::

*.

stribuye como parte de
l paquete AppConfig.

USAR EL MÓDULO AppConfig::

State

Para importar y usar el módulo AppConfig::State, la siguiente línea debe aparecer en su script de

Perl: 
use AppConfig::
State;

El módulo AppConfig::State se carga automáticamente por el constructor new() del módulo

AppConfig.

AppConfig::State está implementado utilizando métodos orientados a objetos. Se crea e inicializa un nuevo objeto AppConfig::State utilizando el método new(). Esto devuelve una referencia a un nuevo objeto AppConfig::

State. 
my $state = AppConfig::State->new()
;

Esto creará una referencia a un nuevo AppConfig::State con todas las opciones de configuración establecidas en sus valores predeterminados. Puede inicializar el objeto pasando una referencia a un array hash que contenga opciones de

configuración: 
$state = AppConfig::State->new( {
    CASE      => 1,
    ERROR     => \&my_error,
} )
;

El constructor new() del módulo AppConfig pasa automáticamente todos los parámetros al constructor new() de AppConfig::State. Por lo tanto, cualquier valor de configuración global y definiciones de variables para AppConfig::State también son aplicables a

AppConfig.

Se pueden especificar las siguientes opciones de

configuración.
CA
SE
Determina si los nombres de las variables se tratan con distinción de mayúsculas y minúsculas. Cualquier valor distinto de cero hace que las mayúsculas y minúsculas sean significativas al nombrar variables. Por defecto, CASE está establecido en 0 y por lo tanto "Variable", "VARIABLE" y "VaRiAbLe" se tratan todas como
"variable".
CREA
TE
Por defecto, CREATE está desactivado, lo que significa que todas las variables accedidas a través de set() (lo que incluye el acceso a través de un alias como "$state->variable($value)" que delega en set()) deben haber sido definidas previamente a través de define(). Cuando CREATE está establecido en 1, llamar a set($variable, $value) en una variable que no existe hará que se cree automáticamente.

Cuando CREATE está establecido en cualquier otro valor distinto de cero, se asume que es un patrón de expresión regular. Si el nombre de la variable coincide con la expresión regular, la variable se crea. Esto se puede usar para especificar bloques de archivos de configuración en los que se deben crear variables,

por ejemplo: 
$state = AppConfig::State->new( {
    CREATE => '^define_',
} );

En un archivo de

configuración: 
[define]
name = fred           # define_name se crea automáticamente
[other]
name = john           # other_name no - se genera una
advertencia

Tenga en cuenta que un patrón de expresión regular especificado en

CREATE se aplica al nombre real de la variable en lugar de c
ualquier alias por el que se pueda acceder a las variables.
PEDANT
IC
La opción PEDANTIC determina qué acción debe tomar el archivo de configuración (AppConfig::File) o el analizador de argumentos (AppConfig::Args) al encontrar una condición de advertencia (típicamente causada al intentar establecer una variable no declarada). Si PEDANTIC está establecido en cualquier valor verdadero, los métodos de análisis devolverán inmediatamente un valor de 0 al encontrar tal condición. Si PEDANTIC no está establecido, el método continuará analizando el resto del(los) archivo(s) o argumentos actuales, devolviendo 0 cuando esté completo.

Si no se encuentran advertencias ni errores, el método devuelve

1.

En el caso de un error del sistema (por ejemplo, incapacidad

para abrir un archivo), el método devuelve undef inm
ediatamente, independientemente de la opción PEDANTIC.
ERR
OR
Especifica una rutina de manejo de errores definida por el usuario. Cuando se llama al manejador, se pasa una cadena de formato como primer parámetro, seguido de cualquier valor adicional, según printf(3C)
.
DEB
UG
Activa o desactiva la depuración cuando se establece en 1 o 0 respectivamente. La depuración también se puede activar llamando a _debug() como método de objeto ("$state->_debug(1)") o como función de paquete (AppConfig::State::_debug(1)), pasando un valor verdadero/falso para establecer el estado de depuración en consecuencia. La variable de paquete $AppConfig::State::DEBUG también se puede establecer directamente.

El método _debug() devuelve el valor de depuración actual. Si se pasa un nuevo valor, el valor interno se actualiza, pero se devuelve el valor

anterior.

Tenga en cuenta que cualquier objeto AppConfig::File o App::Config::Args que se instancien con u

na referencia a un App::State heredarán los valores DEBUG (y también PEDANTIC) del estado en ese
momento. Los cambios posteriores en el valor de depuración de AppConfig::State no les afectarán.

La opción GLOBAL permite establecer valores predeterminados para las opciones DEFAULT, ARGCOUNT, EXPAND, VALIDATE y ACTION para cualquier variable definida posteriormente. 
$state = AppConfig::State->new({
    GLOBAL => {
        DEFAULT  => '<undef>',     # valor predeterminado para nuevas variables
        ARGCOUNT => 1,             # las variables esperan un argumento
        ACTION   => \&my_set_var,  # devolución de llamada cuando se establecen las variables
} });

Cualquier atributo especificado explícitamente cuando se define una variable anulará cualquier valor

GLOBAL.

VALIDA
TE
Cada variable puede tener definida una subrutina o una expresión regular que se utiliza para validar el valor previsto de una variable antes de que se establezca.

Si VALIDATE está definido como una expresión regular, se aplica al valor y se considera válido si el patrón coincide. En este caso, la variable se establece entonces en el nuevo valor. Se genera un mensaje de advertencia si la coincidencia del patrón

falla.

VALIDATE también puede definirse como una referencia a una subrutina que recibe como argumentos el nombre de la variable y su valor previsto. La subrutina debe devolver 1 o 0 para indicar que el valor es válido o no válido, respectivamente. Un valor no válido causará que se genere un mensaje de error de

advertencia.

Si la variable VALIDATE GLOBAL está establecida (véase GLOBAL en la descripción anterior), entonces este valor se utilizará como VALIDATE predeterminado para cada variable a menos que se especifique lo

contrario. 
$state->define("age", {
        VALIDATE => '\d+',
    });
$state->define("pin", {
        VALIDATE => \&check_pin,
});
ACTI
ON
La opción ACTION permite vincular una subrutina a una variable como una devolución de llamada que se ejecuta cada vez que se establece la variable. A ACTION se le pasa una referencia al objeto AppConfig::State, el nombre de la variable y el valor de la variable.

La rutina ACTION se puede utilizar, por ejemplo, para post-procesar datos de variables, actualizar el valor de alguna otra variable dependiente, generar un mensaje de advertencia,

etc.

Ejem

plo: 
$state->define("foo", { ACTION => \&my_notify });
sub my_notify {
    my $state = shift;
    my $var   = shift;
    my $val   = shift;
    print "$variable set to $value";
}
$state->foo(42);        # imprime "foo set
to 42"

esde dentro de la función ACT

ya que la función ACT

DEFINICIÓN DE VARIABLES USANDO EL FORMATO

COMPACTO

Las variables pueden definirse en un formato compacto que permite especificar cualquier valor de ALIAS y ARGS como parte del nombre de la variable. Esto está diseñado para imitar el comportamiento del módulo Getopt::Long de Johan

Vromans.

Los alias de una variable deben especificarse después del nombre de la variable, separados por barras verticales, '|'. Cualquier parámetro ARGS debe añadirse después del nombre de la variable y/o de los

alias.

Los siguientes ejemplos son

equivalentes: 
$state->define("foo", { 
        ALIAS =>
[ 'bar', 'baz' ], ARGS => '=i',
}); $state->define("foo|bar|baz=i");

LECTURA Y MODIFICACIÓN DE LOS VALORES DE LAS

VARIABLES

AppConfig::State define dos métodos para manipular los valores de las

variables: 
set($variable, $value);
get($variable)
;

Ambas funciones toman el nombre de la variable como primer parámetro y set() toma un parámetro adicional que es el nuevo valor para la variable. set() devuelve 1 o 0 para indicar una actualización exitosa o fallida del valor de la variable. Si hay una rutina ACTION asociada con la variable nombrada, el valor devuelto se pasará de vuelta desde set(). El función get() devuelve el valor actual de la

variable.

Una vez definidas, las variables se pueden acceder directamente como métodos de objeto donde el nombre del método es el mismo que el nombre de la variable. Es

decir, 
$state->set("verbose", 1)
;

es equivalente

a 
$state->verbose(1)
;

Sin parámetros, se devuelve el valor actual de la variable. Si se especifica un parámetro, la variable se establece en ese valor y se devuelve el resultado de la operación set()

. 
$state->age(29);
# establece 'age' e
n 29, devuelve 1 (ok)

VARLIS

T

El método varlist() se puede utilizar para extraer un número de variables en un array hash. El primer parámetro debe ser una expresión regular que se utiliza para hacer coincidir con los nombres de las

variables. 
my %vars = $state->varlist("^file");   # todas las variables
"file*"

Se puede especificar un segundo parámetro (cualquier valor verdadero) para indicar que la parte del nombre de la variable que coincide con la expresión regular debe eliminarse al copiarse en el hash de

destino. 
$state->file_name("/tmp/file");
$state->file_path("/foo:/
bar:/baz"); my %vars = $state->varlist("^file_", 1); # %v
ars: # name => /tmp/file # path => "/foo:/bar:/baz"

MÉTODOS

INTERNOS

Los métodos internos (privados) de la clase AppConfig::State se enumeran a

continuación.

No están destinados a un uso regular y los usuarios potenciales deben considerar el hecho de que nada sobre la implementación interna está garantizado para permanecer igual. Dicho esto, la clase AppConfig::State está destinada a coexistir y trabajar con una serie de otros módulos y estos se consideran clases "amigas". Estos métodos se proporcionan, en parte, como servicios para ellos. Con esta cooperación reconocida en mente, es seguro asumir cierta estabilidad en esta interfaz

central.

El método _varname() se puede utilizar para determinar el nombre real de una variable a partir de un

alias: 
$varname->_varname($alias)
;

Tenga en cuenta que todos los métodos que toman un nombre de variable, incluidos los enumerados a continuación, pueden aceptar un alias y resolverlo automáticamente al nombre de variable correcto. No es necesario llamar a _varname() explícitamente para hacer la expansión de alias. El método _varname() plegará todos los nombres de variables a minúsculas a menos que la sensibilidad de MAYÚSCULAS/minúsculas (CASE) esté

establecida.

El método _exists() se puede utilizar para comprobar si una variable ha sido

definida: 
$state->_exists($varname);re>

El método _default() se puede usar para restablecer una variable a
    su valor 
predeterminado:

$state->_default($varname)
;

El método _expand() se puede usar para determinar el valor EXPAND
    de una 
variable:

print "$varname EXPAND: ", $state->_expand($varname), 
"\n";

El método _argcount() devuelve el valor del atributo ARGCOUNT
    de una 
variable:

print "$varname ARGCOUNT: ", $state->_argcount($varname), 
"\n";

El método _validate() se puede usar para determinar si un nuevo
    valor para una variable cumple con cualquier criterio de validación especificado para él. El
    nombre de la variable y el valor previsto deben pasarse. El método devuelve un
    valor verdadero/falso dependiendo de si la validación tuvo éxito o 
no:

print "OK\n" if $state->_validate($varname, $value)
;

El método _pedantic() se puede llamar para determinar el

El método _debug() se puede usar para activar o desactivar la depuración
