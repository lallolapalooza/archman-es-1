Esta página del manual documenta brevemente el

comando

appstreamcli compose. La herram

ienta

appstreamcli compose se utiliza para construir catálogos de metadatos AppStream a partir de árboles de directorios. La herramienta también realizará muchas acciones relacionadas de generación de metadatos, como redimensionar iconos y capturas de pantalla, así como fusionar datos de archivos de entrada de escritorio referenciados, además de información sobre el estado de la traducción. Por lo tanto, la herramienta proporciona una forma rápida de probar cómo puede verse los metadatos finales procesados de una aplicación que se envía a los usuarios. También proporciona una manera de generar fácilmente datos AppStream para proyectos que no necesitan un generador de datos más complejo como appstream-generator. Para que el c

omando

appstreamcli compose esté disponible, es posible que primero necesite instalar el módulo compose opcional para appstreamcli. Para obtener más información sobre el proyecto AppStream y los demás componentes que forman parte de él, eche un vistazo a las páginas de

AppStream en

Freedesktop.org[1]. OPCI

NOMBRE Establece el identificador de origen de los datos AppStream. Este puede ser un valor como

--result-roo

DIR Establece el directorio al que se exporta toda la salida generada que se despliega en la máquina de un usuario. Si este parámetro no está establecido y solo tenemos un directorio para

procesar, usamos ese directorio como ruta de salida predeterminada.
Si tanto

--result-root para establecer una ubicación de salida). --icons-di

--hints-di
r

DIR Establece un directorio donde se guardan los informes de sugerencias generados durante el procesamiento de metadatos. Si este parámetro no está establecido,

--media-di
r

DIR Si se establece, crea un directorio con contenido multimedia (iconos, capturas de pantalla, ...) que se puede servir a través de un servidor web. Los metadatos se extenderán

para incluir información sobre estos medios remotos.
--media-baseur
l

URL La URL bajo la cual se servirá el contenido de un directorio

establecido a través de
--media-dir. Este valor debe establecerse si se crea un directorio de medios. --prefi
x

DIR Establece el prefijo predeterminado que se utiliza en los directorios procesados. Si no se establece

ninguno explícitamente, se asume /usr.
--print-repor
t

MODO Imprime el informe de sugerencias de problemas (que se exporta como documento

HTML y YAML cuando
--hints-dir fue establecido) en la consola en forma de texto. Se admiten varios modos de impresión:

on-error solo imprime un informe corto si la ejecución falló (predeterminado), short genera un informe abreviado que siempre se imprime y full resulta en un informe detallado que se imprime. --no-par

tial-
urls

Si se establece, todas las URL en los datos generados serán absolutas y media_baseurl no se utilizará. Esto hace que cambiar el espejo de medios sea más difícil sin regenerar todos los datos y generalmente no se recomienda, para aumentar la

flexibilidad.
--icon-polic
y

CADENA-DE-POLÍTICA Anula la política de iconos existente con una personalizada. La política de iconos establece cómo deben tratarse los iconos de diferentes tamaños. Pueden estar solo en la caché de iconos, ser un icono remoto en la ubicación de medios o estar tanto en caché como disponibles en

la ubicación remota.
La cadena de política de iconos está compuesta por declaraciones %{size}x%{size}@%{scale}=%{state} separadas por comas. El tamaño y la escala son los del icono respectivo, con la escala permitiendo omitirse si es 1. El estado puede ser remote, cached o cached-remote.

Por defecto, se selecciona una política

de

48x48=cached,48x48@2=cached,64x64=

cached,64x64@2=cached,128x128=cach
ed-remote,128x128@2=cached-remote.

--allow-custom NOMBRES-DE-CLAVE-CUSTO

M
Por defecto, todas las entradas personalizadas establecidas en los datos de entrada MetaInfo se eliminan. Este indicador permite crear una lista blanca de claves personalizadas para que se propaguen a los datos de salida del catálogo final. Los nombres de las claves personalizadas deben proporcionarse como una lista separada por
comas.
