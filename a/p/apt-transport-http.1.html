NOMBRE

apt-transport-http - Transporte APT para descargar vía el Protocolo de Transferencia de Hipertexto (HTTP)

DESCRIPCIÓN

Este transporte APT permite el uso de repositorios accedidos a través del Protocolo de Transferencia de Hipertexto (HTTP). Está disponible por defecto y es probablemente el más usado de todos los transportes. Tenga en cuenta que un usuario nunca llama directamente a un transporte, sino que las herramientas APT lo usan basándose en la configuración del usuario.

HTTP es un protocolo de transporte no cifrado, lo que significa que toda la comunicación con el servidor (o proxy) remoto puede ser observada por un atacante con la capacidad suficiente, comúnmente referido como "man in the middle" (MITM). Sin embargo, dicho atacante *no* puede modificar la comunicación para comprometer la seguridad de su sistema, ya que el modelo de seguridad de datos de APT es independiente del método de transporte elegido. Esto se explica en detalle en apt-secure(8). Una descripción general de los métodos de transporte disponibles se encuentra en sources.list(5).

OPCIONES

Se pueden configurar varias opciones en un archivo apt.conf(5) para modificar su comportamiento, desde la configuración del proxy hasta soluciones para limitaciones específicas del servidor.

Configuración de Proxy

La variable de entorno http_proxy es compatible para la configuración a nivel de sistema. Los proxies específicos para APT se pueden configurar a través de la opción Acquire::http::Proxy. Los proxies que solo deben usarse para hosts específicos se pueden especificar a través de Acquire::http::Proxy::host. Se puede lograr un control aún más detallado a través de la autodetectión de proxy, detallada más adelante. Todas estas opciones utilizan el formato URI esquema://[[usuario][:contraseña]@]host[:puerto]/. Los esquemas URI compatibles son socks5h (SOCKS5 con resolución DNS remota), http y https. Los detalles de autenticación se pueden proporcionar a través de apt_auth.conf(5) en lugar de incluirlos directamente en la URI.

Las diversas opciones de configuración de APT admiten el valor especial DIRECT, lo que significa que no se debe usar ningún proxy. La variable de entorno no_proxy también es compatible para el mismo propósito.

Además, se proporcionan tres configuraciones para el control de caché con cachés de proxy compatibles con HTTP/1.1: Acquire::http::No-Cache indica al proxy que no utilice su respuesta en caché bajo ninguna circunstancia. Acquire::http::Max-Age establece la antigüedad máxima permitida (en segundos) de un archivo de índice en la caché del proxy. Acquire::http::No-Store especifica que el proxy no debe almacenar los archivos de archivo solicitados en su caché, lo que se puede usar para evitar que el proxy contamine su caché con (grandes) archivos .deb.

Configuración Automática de Proxy

Acquire::http::Proxy-Auto-Detect se puede utilizar para especificar un comando externo para descubrir el proxy HTTP a usar. El primer y único parámetro es una URI que denota el host a contactar, para permitir la configuración específica del host. APT espera que el comando envíe el proxy a la salida estándar como una sola línea en el formato URI especificado anteriormente o la palabra DIRECT si no se debe usar ningún proxy. Ninguna salida indica que se deben usar las configuraciones genéricas de proxy.

Tenga en cuenta que la autodetectión no se utilizará para un host si ya está configurado un proxy específico para el host a través de Acquire::http::Proxy::host.

Consulte los paquetes squid-deb-proxy-client(1) y auto-apt-proxy(1) para ver implementaciones de ejemplo.

Esta opción tiene prioridad sobre el nombre de opción obsoleto Acquire::http::ProxyAutoDetect.

Configuración de Conexión

La opción Acquire::http::Timeout establece el temporizador de tiempo de espera utilizado por el método; este valor se aplica tanto a la conexión como al tiempo de espera de los datos.

El ancho de banda utilizado se puede limitar con Acquire::http::Dl-Limit, que acepta valores enteros en kilobytes por segundo. El valor predeterminado es 0, lo que desactiva el límite e intenta utilizar todo el ancho de banda disponible. Tenga en cuenta que esta opción deshabilita implícitamente la descarga de varios servidores al mismo tiempo.

La configuración Acquire::http::Pipeline-Depth se puede usar para habilitar el pipelining HTTP (RFC 2616, sección 8.1.2.2), lo que puede ser beneficioso, por ejemplo, en conexiones de alta latencia. Especifica cuántas solicitudes se envían en una tubería. APT intenta detectar y solucionar problemas de servidores web y proxies que no funcionan correctamente en tiempo de ejecución, pero si sabe que el suyo no cumple con la especificación HTTP/1.1, el pipelining se puede deshabilitar estableciendo el valor en 0. Está habilitado por defecto con el valor 10.

Acquire::http::AllowRedirect controla si APT seguirá las redirecciones, lo cual está habilitado por defecto.

Acquire::http::User-Agent se puede usar para establecer un Agente de Usuario diferente para el método de descarga http, ya que algunos proxies solo permiten el acceso a los clientes si el cliente utiliza un identificador conocido.

Acquire::http::SendAccept está habilitado por defecto y envía un campo de encabezado Accept: text/* al servidor para solicitudes sin extensiones de archivo, para evitar que el servidor intente la negociación de contenido.

EJEMPLOS

Acquire::http {
	Proxy::example.org "DIRECT";
	Proxy "socks5h://apt:pass@127.0.0.1:9050";
	Proxy-Auto-Detect "/usr/local/bin/apt-http-proxy-auto-detect";
	No-Cache "true";
	Max-Age "3600";
	No-Store "true";
	Timeout "10";
	Dl-Limit "42";
	Pipeline-Depth "0";
	AllowRedirect "false";
	User-Agent "Mi APT-HTTP";
	SendAccept "false";
};
