NOMBRE

apptainer-instance-start - Inicia una instancia nombrada de la imagen de contenedor dada

SINOPSIS

apptainer instance start [opciones de inicio...] [argumentos del script de inicio...]

DESCRIPCIÓN

El comando instance start permite crear una nueva instancia nombrada a partir de una
imagen de contenedor existente que comenzará a ejecutarse en segundo plano. Si se define un
script de inicio en los metadatos del contenedor, los comandos de ese script
también se ejecutarán con el comando instance start. Opcionalmente, puede
pasar argumentos al script de inicio.

apptainer instance start acepta los siguientes formatos de contenedor:

*.sif Formato de imagen Singularity (SIF). Nativo de Singularity
(3.0+) y Apptainer (v1.0.0+)

*.sqsh Formato SquashFS. Nativo de Singularity 2.4+

*.img Formato ext3. Nativo de las versiones de Singularity < 2.4.

directory/ Formato sandbox. Directorio que contiene un sistema de archivos raíz válido
y, opcionalmente, metadatos de Apptainer.

instance://* Una instancia local en ejecución de un contenedor. (Ver el grupo de comandos
instance.)

library://* Un contenedor SIF alojado en una Biblioteca (sin valor predeterminado)

docker://* Un contenedor Docker/OCI alojado en Docker Hub u otro
registro OCI.

shub://* Un contenedor alojado en Singularity Hub.

oras://* Un contenedor SIF alojado en un registro OCI que admite
la especificación OCI Registry As Storage (ORAS).

OPCIONES

--add-caps="" una lista de capacidades separada por comas para añadir

--allow-setuid[=false] permite binarios setuid en el contenedor (solo root)

--app="" establece una aplicación para ejecutar dentro de un contenedor

--apply-cgroups="" aplica cgroups desde un archivo para los procesos del contenedor (solo root)

--authfile="" archivo de autenticación estilo Docker para usar al escribir/leer credenciales del registro OCI

-B, --bind=[] una especificación de ruta de enlace de usuario. La especificación tiene el formato src[:dest[:opts]], donde src y dest son rutas externas e internas. Si no se proporciona dest, se establece igual a src. Las opciones de montaje ('opts') se pueden especificar como 'ro' (solo lectura) o 'rw' (lectura/escritura, que es el valor predeterminado). Se pueden indicar varias rutas de enlace mediante una lista separada por comas.

--blkio-weight=0 peso relativo de Block IO en el rango 10-1000, 0 para deshabilitar

--blkio-weight-device=[] peso relativo de Block IO específico del dispositivo

--boot[=false] ejecuta /sbin/init para iniciar el contenedor (solo root)

-e, --cleanenv[=false] limpia el entorno antes de ejecutar el contenedor

--compat[=false] aplica configuraciones para una mayor compatibilidad OCI/Docker. Infiere --containall, --no-init, --no-umask, --no-eval, --writable-tmpfs.

-c, --contain[=false] usa un /dev mínimo y vacía otros directorios (por ejemplo, /tmp y $HOME) en lugar de compartir sistemas de archivos del host

-C, --containall[=false] contiene no solo sistemas de archivos, sino también PID, IPC y entorno

--cpu-shares=-1 comparticiones de CPU para el contenedor

--cpus="" número de CPUs disponibles para el contenedor

--cpuset-cpus="" lista de CPUs del host disponibles para el contenedor

--cpuset-mems="" lista de nodos de memoria del host disponibles para el contenedor

--disable-cache[=false] no usa ni crea caché

--dmtcp-launch="" checkpoint para que dmtcp guarde el estado del proceso del contenedor (experimental)

--dmtcp-restart="" checkpoint para que dmtcp lo use para reiniciar el proceso del contenedor (experimental)

--dns="" lista de servidores DNS separados por comas para añadir en resolv.conf

--docker-host="" especifica un host de demonio Docker personalizado

--docker-login[=false] inicia sesión en un Repositorio Docker interactivamente

--drop-caps="" una lista de capacidades separada por comas para descartar

--env=[] pasa una variable de entorno al proceso contenido

--env-file=[] pasa variables de entorno desde un archivo al proceso contenido

-f, --fakeroot[=false] ejecuta el contenedor con la apariencia de ejecutarse como root

--fusemount=[] una especificación de montaje de sistema de archivos FUSE del tipo ': ' - donde es 'container' o 'host', especificando dónde se realizará el montaje ('container-daemon' o 'host-daemon' ejecutarán el proceso FUSE de forma independiente). es la ruta al ejecutable FUSE, más las opciones para el montaje. es la ubicación dentro del contenedor donde se adjuntará el montaje FUSE. Por ejemplo: 'container:sshfs 10.0.0.1:/ /sshfs'. Implica --pid.

-h, --help[=false] ayuda para start

-H, --home="/build" una especificación de directorio home. La especificación puede ser una ruta src o un par src:dest. src es la ruta de origen del directorio home fuera del contenedor y dest anula el directorio home dentro del contenedor.

--hostname="" establece el nombre de host del contenedor

-i, --ipc[=false] ejecuta el contenedor en un nuevo espacio de nombres IPC

--keep-privs[=false] permite al usuario root conservar privilegios en el contenedor (solo root)

--memory="" límite de memoria en bytes

--memory-reservation="" límite blando de memoria en bytes

--memory-swap="" límite de swap, usa -1 para swap ilimitado

--mount=[] una especificación de montaje, por ejemplo, 'type=bind,source=/opt,destination=/hostopt'.

-n, --net[=false] ejecuta el contenedor en un nuevo espacio de nombres de red (configura una interfaz de red bridge por defecto)

--netns-path="" se une al espacio de nombres de red en la ruta especificada (como root, o si está permitido en apptainer.conf)

--network="" especifica el tipo de red deseado separado por comas, cada red activará una interfaz dedicada dentro del contenedor

--network-args=[] especifica argumentos de red para pasar a los plugins CNI

--no-eval[=false] no evalúa shell para variables de entorno o CMD/ENTRYPOINT/ARGS del contenedor OCI

--no-home[=false] NO monta el directorio home del usuario si /home no es el directorio de trabajo actual

--no-https[=false] usa http en lugar de https para las URIs docker://, oras:// y library:///...

--no-init[=false] NO inicia el proceso shim con --pid

--no-mount=[] deshabilita una o más opciones 'mount xxx' establecidas en apptainer.conf y/o especifica una ruta de destino absoluta para deshabilitar una entrada de ruta de enlace, o 'bind-paths' para deshabilitar todas las entradas de ruta de enlace.

--no-privs[=false] descarta todos los privilegios del usuario root en el contenedor)

--no-umask[=false] no propaga umask al contenedor, establece una umask predeterminada de 0022

--nv[=false] habilita soporte Nvidia

--nvccli[=false] usa nvidia-container-cli para la configuración de GPU (experimental)

--oom-kill-disable[=false] Deshabilita el killer OOM

-o, --overlay=[] usa una imagen overlayFS para almacenamiento persistente de datos o como capa de solo lectura del contenedor

--passphrase[=false] solicita una frase de contraseña de cifrado

--pem-path="" introduce una ruta a una clave RSA en formato PEM para un contenedor cifrado

--pid-file="" escribe el PID de la instancia en el archivo con el nombre dado

--pids-limit=0 limita el número de PIDs del contenedor, usa -1 para ilimitado

--rocm[=false] habilita el soporte Rocm experimental

-S, --scratch=[] incluye un directorio scratch dentro del contenedor que está enlazado a un directorio temporal (usa -W para forzar la ubicación)

--security=[] habilita características de seguridad (SELinux, Apparmor, Seccomp)

--unsquash[=false] convierte el archivo SIF a un sandbox temporal antes de ejecutar

-u, --userns[=false] ejecuta el contenedor en un nuevo espacio de nombres de usuario

--uts[=false] ejecuta el contenedor en un nuevo espacio de nombres UTS

-W, --workdir="" directorio de trabajo a ser usado para /tmp, /var/tmp y $HOME (si también se usó -c/--contain)

-w, --writable[=false] por defecto, todos los contenedores de Apptainer son accesibles como solo lectura. Esta opción hace que el sistema de archivos sea accesible

como lectura/escritura.

--writable-tmpfs[=false] hace que el sistema de archivos sea accesible como lectura/escritura con datos no persistentes (solo con soporte de overlay)

EJEMPLO

  $ apptainer instance start /tmp/my-sql.sif mysql
  $ apptainer shell instance://mysql
  Apptainer my-sql.sif> pwd
  /home/mibauer/mysql
  Apptainer my-sql.sif> ps
  PID TTY          TIME CMD
    1 pts/0    00:00:00 appinit
    2 pts/0    00:00:00 bash
    3 pts/0    00:00:00 ps
  Apptainer my-sql.sif>
  $ apptainer instance stop /tmp/my-sql.sif mysql
  Stopping /tmp/my-sql.sif mysql
