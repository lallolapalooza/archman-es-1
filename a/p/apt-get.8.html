DESCRIPCIÓ

N

apt-get es la herramienta de línea de comandos para el manejo de paquetes, y puede considerarse el "back-end" del usuario para otras herramientas que usan la biblioteca APT. Existen varias interfaces de "front-end", como aptitude(8), synaptic(8) y wajig(

1).

A menos que se proporcione la opción -h, o --help, debe estar presente uno de los siguientes

comandos.

updat

e
update se usa para resincronizar los archivos de índice de paquetes desde sus fuentes. Los índices de los paquetes disponibles se obtienen de la(s) ubicación(es) especificada(s) en /etc/apt/sources.list. Por ejemplo, al usar un archivo de Debian, este comando recupera y escanea los archivos Packages.gz, de modo que la información sobre paquetes nuevos y actualizados esté disponible. Siempre se debe realizar un update antes de un upgrade o dist-upgrade. Tenga en cuenta que el indicador de progreso general será incorrecto, ya que el tamaño de los archivos de paquetes no se puede conocer de
antemano.

upgrad

e
upgrade se usa para instalar las versiones más recientes de todos los paquetes actualmente instalados en el sistema desde las fuentes enumeradas en /etc/apt/sources.list. Los paquetes actualmente instalados con nuevas versiones disponibles se recuperan y actualizan; en ningún caso se eliminan paquetes actualmente instalados, ni se recuperan e instalan paquetes que no estén ya instalados. Las nuevas versiones de los paquetes actualmente instalados que no se pueden actualizar sin cambiar el estado de instalación de otro paquete se dejarán en su versión actual. Primero se debe realizar un update para que apt-get sepa que hay nuevas versiones de paquetes disponibles.

Cuando se proporciona un paquete como

argumento, el paquete se instalar
á antes de la acción de actualización.

dist-upgrad

e
dist-upgrade, además de realizar la función de upgrade, también maneja inteligentemente los cambios de dependencias con nuevas versiones de paquetes; apt-get tiene un sistema de resolución de conflictos "inteligente", e intentará actualizar los paquetes más importantes a expensas de los menos importantes si es necesario. Por lo tanto, el comando dist-upgrade puede eliminar algunos paquetes. El archivo /etc/apt/sources.list contiene una lista de ubicaciones desde las cuales recuperar los archivos de paquetes deseados. Véase también apt_preferences(5) para un mecanismo para anular la configuración general para paquetes individuales.

Cuando se proporciona un paquete como

argumento, el paquete se instalar
á antes de la acción de actualización.

dselect-upgrad

e
dselect-upgrade se usa en conjunto con el front-end tradicional de empaquetado de Debian, dselect(1). dselect-upgrade sigue los cambios realizados por dselect(1) en el campo Status de los paquetes disponibles, y realiza las acciones necesarias para realizar ese estado (por ejemplo, la eliminación de paquetes antiguos y la instalación de paquetes nuevos)
.

instal

l
install va seguido de uno o más paquetes deseados para instalar o actualizar. Cada paquete es un nombre de paquete, no un nombre de archivo completamente calificado (por ejemplo, en un sistema Debian, apt-utils sería el argumento proporcionado, no apt-utils_3.1.12_amd64.deb). Todos los paquetes requeridos por el/los paquete(s) especificado(s) para la instalación también se recuperarán e instalarán. El archivo /etc/apt/sources.list se usa para localizar los paquetes deseados. Si se agrega un guion al nombre del paquete (sin espacio intermedio), el paquete identificado se eliminará si está instalado. De manera similar, un signo más puede usarse para designar un paquete a instalar. Estas últimas funciones pueden usarse para anular las decisiones tomadas por el sistema de resolución de conflictos de apt-get.

Se puede seleccionar una versión específica de un paquete para la instalación siguiendo el nombre del paquete con un signo igual y la versión del paquete a seleccionar. Esto hará que esa versión se localice y seleccione para la instalación. Alternativamente, se puede seleccionar una distribución específica siguiendo el nombre del paquete con una barra y la versión de la distribución o el nombre del archivo (stable, testing, unstable)

.

Ambos mecanismos de selección de versiones pueden degradar paquetes y deben usarse con

cuidado.

Este es también el objetivo a usar si desea actualizar uno o más paquetes ya instalados sin actualizar todos los paquetes que tiene en su sistema. A diferencia del objetivo "upgrade", que instala la versión más reciente de todos los paquetes actualmente instalados, "install" instalará la versión más reciente de solo el/los paquete(s) especificado(s). Simplemente proporcione el nombre del/los paquete(s) que desea actualizar, y si hay una versión más nueva disponible, esta (y sus dependencias, como se describió anteriormente) se descargarán e

instalarán.

Finalmente, el mecanismo de apt_preferences(5) le permite crear una política de instalación alternativa para paquetes

individuales.

Si ningún paquete coincide con la expresión dada y la expresión contiene uno de '.', '?' o '*', se asume que es una expresión regular POSIX, y se aplica a todos los nombres de paquetes en la base de datos. Cualquier coincidencia se instala (o se elimina). Tenga en cuenta que la coincidencia se realiza por subcadena, por lo que 'lo.*' coincide con 'how-lo' y 'lowest'. Si esto no es deseado, ancle la expresión regular con un carácter '^' o '$', o cree una expresión regular más

específica.

El uso de expresiones regulares como alternativa está obsoleto en APT 2.0, se ha eliminado en apt(8), excepto para expresiones ancladas, y se eliminará de apt-get(8) en una versión futura. Use apt-patterns(7

) en su
lugar.

reinstal

l
reinstall es un alias para install
--reinstall.

remov

e
remove es idéntico a install excepto que los paquetes se eliminan en lugar de instalarse. Tenga en cuenta que eliminar un paquete deja sus archivos de configuración en el sistema. Si se agrega un signo más al nombre del paquete (sin espacio intermedio), el paquete identificado se instalará en lugar de
eliminarse.

purg

e
purge es idéntico a remove excepto que los paquetes se eliminan y se purgan (cualquier archivo de configuración también se elimina)
.

sourc

e
source hace que apt-get recupere paquetes fuente. APT examinará los paquetes disponibles para decidir qué paquete fuente recuperar. Luego encontrará y descargará en el directorio actual la versión más nueva disponible de ese paquete fuente, respetando la versión predeterminada, establecida con la opción APT::Default-Release, la opción -t o por paquete con la sintaxis pkg/release, si es posible.

Los argumentos se interpretan como nombres de paquetes binarios y fuente. Vea la opción --only-source si desea cambiar

eso.

Los paquetes fuente se rastrean por separado de los paquetes binarios mediante líneas deb-src en el archivo sources.list(5). Esto significa que necesitará agregar una línea de este tipo para cada repositorio del que desee obtener fuentes; de lo contrario, probablemente obtendrá versiones fuente incorrectas (demasiado antiguas/demasiado nuevas) o ninguna en

absoluto.

Si se especifica la opción --compile, el paquete se compilará a un binario .deb usando dpkg-buildpackage para la arquitectura definida por la opción --host-architecture. Si se especifica --download-only, el paquete fuente no se

descomprimirá.

Se puede recuperar una versión fuente específica posponiendo el nombre de la fuente con un signo iguals y luego la versión a obtener, similar al mecanismo utilizado para los archivos de paquete. Esto permite la correspondencia exacta del nombre y versión del paquete fuente, habilitando implícitamente la opción APT::Get::

Only-Source.

Tenga en cuenta que los paquetes fuente no se instalan ni se rastrean en la base de datos de dpkg como los paquetes binarios; simplemente se desca

rgan en el directorio actual,
como los tarballs de código fuente.

build-de

p
build-dep hace que apt-get instale o elimine paquetes en un intento de satisfacer las dependencias de compilación para un paquete fuente. Por defecto, las dependencias se satisfacen para compilar el paquete de forma nativa. Si se desea, se puede especificar una arquitectura de host con la opción --host-architecture en su lugar.

Los argumentos se interpretan como nombres de paquetes binarios o de origen. Vea la opción --only-source

si desea ca
mbiar eso.

satisf

y
satisfy hace que apt-get satisfaga las cadenas de dependencia dadas. Las cadenas de dependencia pueden tener perfiles de compilación y una lista de restricciones de arquitectura como en las dependencias de compilación. Opcionalmente, pueden ir precedidas de "Conflicts: " para no satisfacer la cadena de dependencia. Se pueden especificar múltiples cadenas del mismo tipo.

Ejemplo: apt-get satisfy "foo" "Conflicts: bar" "baz (>> 1.0) | bar (= 2.0),

moo"

El operador heredado '</>

' no está soportado, use
'<=/>=' en su lugar.

chec

k
check es una herramienta de diagnóstico; actualiza la caché de paquetes y comprueba si hay dependencias
rotas.

downloa

d
download descargará el paquete binario dado en el directorio actual. La autenticidad de los datos del paquete se asegura como de
costumbre.

clea

n
clean limpia el repositorio local de los archivos de paquete obtenidos. Elimina todo excepto el archivo de bloqueo de /var/cache/apt/archives/ y /var/cache/apt/archives/partial/
.

autoclean (y el alias auto-clean desde la versión 1.

1)
Al igual que clean, autoclean limpia el repositorio local de archivos de paquete obtenidos. La diferencia es que solo elimina los archivos de paquete que ya no se pueden descargar y son en gran medida inútiles. Esto permite mantener una caché durante un largo período sin que crezca fuera de control. La opción de configuración APT::Clean-Installed evitará que los paquetes instalados sean borrados si se establece en
off.

distclean (y el alias dist-

clean)
distclean elimina todos los archivos bajo /var/lib/apt/lists excepto Release, Release.gpg e InRelease. Se puede usar, por ejemplo, al finalizar imágenes distribuidas a los usuarios. Los archivos de versión se conservan por razones de seguridad, para prevenir varios tipos de
ataques.

autoremove (y el alias auto-remove desde la versión 1.

1)
autoremove se usa para eliminar paquetes que fueron instalados automáticamente para satisfacer dependencias de otros paquetes y que ahora ya no son
necesarios.

autopurg

e
Al igual que autoremove, pero autopurge también elimina los archivos de configuración. Este es un atajo para autoremove
--purge.

changelo

g
changelog intenta descargar el changelog de un paquete y lo muestra a través de sensible-pager. Por defecto, muestra el changelog para la versión que está instalada. Sin embargo, puede especificar las mismas opciones que para el comando ins
tall.

indextarget

s
Muestra por defecto un listado con formato deb822 de información sobre todos los archivos de datos (también conocidos como objetivos de índice) que apt-get update descargaría. Admite una opción --format para modificar el formato de salida así como acepta líneas de la salida por defecto para filtrar los registros. El comando se usa principalmente como una interfaz para herramientas externas que trabajan con APT para obtener información así como nombres de arch
ivo para los archivos descargados, para que puedan usarlos en lugar de descargarlos de nuevo por su cuenta. La documentación detallada se
omite aquí y en su lugar se puede encontrar en el archivo /usr/share/doc/apt/acquire-additional-files.md.gz incluido en el paquete apt-doc.

OPCIONE

S

Todas las opciones de la línea de comandos se pueden establecer usando el archivo de configuración, las descripciones indican la opción de configuración a establecer. Para opciones booleanas, puede anular el archivo de configuración usando algo como -f-,--no-f, -f=no o varias otras

variaciones.

--no-install-recommend

s
No considerar los paquetes recomendados como una dependencia para instalar. Elemento de configuración: APT::Install-Recommends
.

--install-suggest

s
Considerar los paquetes sugeridos como una dependencia para instalar. Elemento de configuración: APT::Install-Suggests
.

-d, --download-onl

y
Solo descargar; los archivos de paquete solo se obtienen, no se desempaquetan ni se instalan. Elemento de configuración: APT::Get::
Download-Only.

-f, --fix-broke

n
Arreglar; intenta corregir un sistema con dependencias rotas en el lugar. Esta opción, cuando se usa con install/remove, puede omitir cualquier paquete para permitir a APT deducir una solución probable. Si se especifican paquetes, estos deben corregir completamente el problema. La opción a veces es necesaria cuando se ejecuta APT por primera vez; APT en sí no permite que existan dependencias de paquetes rotas en un sistema. Es posible que la estructura de dependencias de un sistema esté tan corrupta como para requerir una intervención manual (lo que generalmente significa usar dpkg --remove para eliminar algunos de los paquetes problemáticos). El uso de esta opción junto con -m puede producir un error en algunas situaciones. Elemento de configuración: APT::Get::
Fix-Broken.

-m, --ignore-missing, --fix-missin

g
Ignorar paquetes faltantes; si los paquetes no se pueden obtener o fallan la comprobación de integridad después de la obtención (archivos de paquete corruptos), retener esos paquetes y manejar el resultado. El uso de esta opción junto con -f puede producir un error en algunas situaciones. Si un paquete está seleccionado para instalación (particularmente si se menciona en la línea de comandos) y no se pudo descargar, se retendrá silenciosamente. Elemento de configuración: APT::Get::
Fix-Missing.

--no-downloa

d
Deshabilita la descarga de paquetes. Esto se usa mejor con --ignore-missing para forzar a APT a usar solo los .debs que ya ha descargado. Elemento de configuración: APT::Get::
Download.

-q, --quie

t
Silencioso; produce una salida adecuada para el registro, omitiendo los indicadores de progreso. Más q's producirán más silencio hasta un máximo de 2. También puede usar -q=# para establecer el nivel de silencio, anulando el archivo de configuración. Tenga en cuenta que el nivel de silencio 2 implica -y; nunca debe usar -qq sin un modificador de no-acción como -d, --print-uris o -s, ya que APT puede decidir hacer algo que no esperaba. Elemento de configuración:
quiet.

-s, --simulate, --just-print, --dry-run, --recon, --no-ac

t
Sin acción; realiza una simulación de los eventos que ocurrirían basándose en el estado actual del sistema pero no cambia realmente el sistema. El bloqueo se deshabilitará (Debug::NoLocking) por lo que el estado del sistema podría cambiar mientras apt-get está en ejecución. Las simulaciones también pueden ser ejecutadas por usuarios no root que podrían no tener acceso de lectura a toda la configuración de apt, distorsionando la simulación. Un aviso que expresa esta advertencia también se muestra por defecto para usuarios no root (APT::Get::Show-User-Simulation-Note). Elemento de configuración: APT::Get::Simulate.

Las ejecuciones simuladas imprimen una serie de líneas, cada una representando una operación de dpkg: configure (Conf), remove (Remv) o unpack (Inst). Los corchetes indican paqu

etes rotos, y los corchetes vacíos indican i
nterrupciones que no tienen consecuencias (raro).

-y, --yes, --assume-ye

s
Sí automático a las preguntas; asume "sí" como respuesta a todas las preguntas y se ejecuta de forma no interactiva. Si ocurre una situación no deseada, como cambiar un paquete retenido, intentar instalar un paquete no autenticado o eliminar un paquete esencial, entonces apt-get abortará. Elemento de configuración: APT::Get::
Assume-Yes.

--assume-n

o
"No" automático a todas las preguntas. Elemento de configuración: APT::Get::
Assume-No.

--no-show-upgrade

d
No mostrar una lista de todos los paquetes que van a ser actualizados. Elemento de configuración: APT::Get::
Show-Upgraded.

-V, --verbose-version

s
Mostrar las versiones completas para los paquetes actualizados e instalados. Elemento de configuración: APT::Get::
Show-Versions.

--no-list-column

s
Mostrar las listas de paquetes sin organizarlas en columnas. Por defecto, las listas de paquetes se imprimen al estilo del comando "ls". Elemento de configuración: APT::Get::
List-Columns.

--commen

t
Añadir el valor dado al campo Comment: en history.log Elemento de configuración: APT::History::
Comment.

-a, --host-architectur

e
Esta opción controla la arquitectura para la que se construyen los paquetes por apt-get source --compile y cómo se satisfacen las dependencias de compilación cruzada. Por defecto no está establecida, lo que significa que la arquitectura de host es la misma que la arquitectura de compilación (que está definida por APT::Architecture). Elemento de configuración: APT::Get::Host-Architecture
.

-P, --build-profile

s
Esta opción controla los perfiles de compilación activados para los que se construye un paquete fuente por apt-get source --compile y cómo se satisfacen las dependencias de compilación. Por defecto, no hay ningún perfil de compilación activo. Más de un perfil de compilación se puede activar a la vez concatenándolos con una coma. Elemento de configuración: APT::

-b, --compile, --buil

d
Compilar paquetes fuente después de descargarlos. Elemento de configuración: APT::Get::
Compile.

--ignore-hol

d
Ignorar las retenciones de paquetes; esto hace que apt-get ignore una retención colocada en un paquete. Esto puede ser útil en conjunto con dist-upgrade para anular un gran número de retenciones no deseadas. Elemento de configuración: APT::
Ignore-Hold.

--with-new-pkg

s
Permitir la instalación de nuevos paquetes cuando se usa en conjunto con upgrade. Esto es útil si la actualización de un paquete instalado requiere que se instalen nuevas dependencias. En lugar de retener el paquete, upgrade actualizará el paquete e instalará las nuevas dependencias. Tenga en cuenta que upgrade con esta opción nunca eliminará paquetes, solo permitirá añadir nuevos. Elemento de configuración: APT::Get::Upgrade-Allow-New
.

--no-upgrad

e
No actualizar paquetes; cuando se usa en conjunto con install, no-upgrade evitará que los paquetes en la línea de comandos sean actualizados si yaya instalado. Elemento de configuración: APT::Get::
Upgrade.

--only-upgrad

e
No instalar paquetes nuevos; cuando se usa en combinación con install, only-upgrade solo instalará actualizaciones para paquetes ya instalados e ignorará las solicitudes de instalar paquetes nuevos. Elemento de configuración: APT::Get::
Only-Upgrade.

--allow-downgrade

s
Esta es una opción peligrosa que hará que apt continúe sin preguntar si está realizando degradaciones. No debe usarse excepto en situaciones muy especiales. ¡Usarla puede destruir potencialmente su sistema! Elemento de configuración: APT::Get::allow-downgrades. Introducido en APT 1.
1.

--allow-remove-essentia

l
Forzar sí; esta es una opción peligrosa que hará que apt continúe sin preguntar si está eliminando elementos esenciales. No debe usarse excepto en situaciones muy especiales. ¡Usarla puede destruir potencialmente su sistema! Elemento de configuración: APT::Get::allow-remove-essential. Introducido en APT 1.
1.

--allow-change-held-package

s
Forzar sí; esta es una opción peligrosa que hará que apt continúe sin preguntar si está cambiando paquetes retenidos. No debe usarse excepto en situaciones muy especiales. ¡Usarla puede destruir potencialmente su sistema! Elemento de configuración: APT::Get::allow-change-held-packages. Introducido en APT 1.
1.

--force-ye

s
Forzar sí; esta es una opción peligrosa que hará que apt continúe sin preguntar si está haciendo algo potencialmente dañino. No debe usarse excepto en situaciones muy especiales. ¡Usar force-yes puede destruir potencialmente su sistema! Elemento de configuración: APT::Get::force-yes. Esta opción está obsoleta y ha sido reemplazada por --allow-unauthenticated , --allow-downgrades , --allow-remove-essential , --allow-change-held-packages en la versión 1.
1.

--print-uri

s
En lugar de obtener los archivos para instalarlos, se imprimen sus URI. Cada URI tendrá la ruta, el nombre del archivo de destino, el tamaño y el hash MD5 esperado. ¡Tenga en cuenta que el nombre del archivo a escribir no siempre coincidirá con el nombre del archivo en el sitio remoto! Esto también funciona con los comandos source y update. Cuando se usa con el comando update, el MD5 y el tamaño no se incluyen, y corresponde al usuario descomprimir cualquier archivo comprimido. Elemento de configuración: APT::Get::
Print-URIs.

--purg

e
Usar purge en lugar de remove para todo lo que vaya a ser eliminado. Un asterisco ("*") se mostrará junto a los paquetes que están programados para ser purgados. remove --purge es equivalente al comando purge. Elemento de configuración: APT::Get::
Purge.

--reinstal

l
Reinstalar paquetes que ya están instalados y en la versión más reciente. Elemento de configuración: APT::Get::
ReInstall.

--list-cleanu

p
Esta opción está activada por defecto; use --no-list-cleanup para desactivarla. Cuando está activada, apt-get gestionará automáticamente el contenido de /var/lib/apt/lists para asegurarse de que los archivos obsoletos sean borrados. La única razón para desactivarla es si cambia frecuentemente su lista de fuentes. Elemento de configuración: APT::Get::
List-Cleanup.

-S, --snapsho

t
Esta opción controla la instantánea elegida para archivos con Snapshot: enable en la entrada de la fuente. Por ejemplo, -S 20220102T030405Z selecciona una instantánea del 2 de enero de 2022 a las 03:04:05 UTC. Elemento de configuración: APT::Snapshot; véase también la página del manual sources.list(5)
.

-t, --target-release, --default-releas

e
Esta opción controla la entrada por defecto para el motor de políticas; crea un pin por defecto con prioridad 990 usando la cadena de versión especificada. Esto anula la configuración general en /etc/apt/preferences. Los paquetes con pin específico no se ven afectados por el valor de esta opción. En resumen, esta opción le permite tener un control sencillo sobre la distribución desde la que se obtendrán los paquetes. Algunos ejemplos comunes podrían ser -t '2.1*', -t unstable o -t sid. Elemento de configuración: APT::Default-Release; véase también la página del manual apt_preferences(5)
.

--trivial-onl

y
Realizar solo operaciones que sean 'triviales'. Lógicamente esto puede considerarse relacionado con --assume-yes; donde --assume-yes responderá sí a cualquier prompt, --trivial-only responderá no. Elemento de configuración: APT::Get::
Trivial-Only.

--mark-aut

o
Después de una instalación exitosa, marcar todos los paquetes recién instalados como instalados automáticamente, lo que hará que cada uno de los paquetes sea eliminado cuando ya no haya paquetes instalados manualmente que dependan de este paquete. Esto equivale a ejecutar apt-mark auto para todos los paquetes instalados. Elemento de configuración: APT::Get::
Mark-Auto.

--no-remov

e
Si se van a eliminar paquetes, apt-get aborta inmediatamente sin preguntar. Elemento de configuración: APT::Get::
Remove.

--auto-remove, --autoremov

e
Si el comando es install o remove, entonces esta opción actúa como si se ejecutara el comando autoremove, eliminando paquetes de dependencia no utilizados. Elemento de configuración: APT::Get::AutomaticRemove
.

--only-sourc

e
Solo tiene significado para los comandos source y build-dep. Indica que los nombres de fuente dados no deben ser mapeados a través de la tabla binaria. Esto significa que si se especifica esta opción, estos comandos solo aceptarán nombres de paquetes fuente como argumentos, en lugar de aceptar nombres de paquetes binarios y buscar el paquete fuente correspondiente. Elemento de configuración: APT::Get::
Only-Source.

--cli-versio

n
Solicita una versión específica de la CLI. Este es un patrón que toma una versión MAJOR.MINOR. Puede omitir la versión MINOR, en cuyo caso se usará el nivel menor más reciente soportado.

Las pistas de versión se presentan como sigue: La versión 3.2 tiene versiones equivalentes 0.32, 1.22 y 2.12, implementando nuevas características para sus versiones mayores

especificadas.

Un caso especial es el patrón de versión X.9: Una versión como 2.9 es seguida por 3.0, pero 2.10 sigue directamente a 2.8; dado que usamos números de versión impares como series de desarrollo (2.9 es la serie de desarrollo 3.0)

.

Esta característica ha sidose introdujo en APT 3.1.10, y reemplaza la configuración específica del binario. Puede usar APT::Version para un efecto similar en binarios más antiguos, por ejemplo, use -o APT::Version=2 para hacer que apt(8) se comporte como la serie 2.

x.
