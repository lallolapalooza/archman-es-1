RESUME

N

AppConfig es un módulo de Perl5 para gestionar la información de configuración de la aplicación. Mantiene el estado de cualquier número de variables y proporciona métodos para analizar archivos de configuración, argumentos de la línea de comandos y parámetros de scripts

CGI.

Los valores de las variables pueden establecerse mediante archivos de configuración. Las variables pueden ser indicadores (On/Off), tomar un solo valor o tomar múltiples valores almacenados como lista o hash. El número de argumentos que una variable espera está determinado por su configuración cuando se

define. 
# indicadores
verbose 
nohelp
debug = On
# valor único
home  = /home/abw/
# valor de lista múltiple
file = /tmp/file1
file = /tmp/file2
# valor de hash múltiple
book  camel = Programming Perl
book  llama = Learning
Perl

El prefijo '-' se puede usar para restablecer una variable a su valor predeterminado y el prefijo '+' se puede usar para establecerla en

1 
-verbose
+debug

Se pueden aplicar expansiones de variables, variables de entorno y tilde (directorio home) (selectivamente, si es necesario) a los valores leídos de los archivos de

configuración: 
home = ~                    # directorio home
nntp = ${NNTPSERVER}        # variable de entorno
html = $home/html           # variables internas
img  =
$html/images

Los archivos de configuración pueden organizarse en bloques al estilo de los archivos "INI" de

Win32. 
[file]
site = kfs
src  = ~/websrc/docs/$site
lib  = ~/websrc/lib
dest = ~/public_html/$site
[page]
header = $lib/header
footer =
$lib/footer

También puede usar la sintaxis "heredoc" de Perl para definir un bloque grande de texto en un archivo de

configuración. 
multiline = <<FOOBAR
line 1
line 2
FOOBAR
paths  exe  = "${PATH}:${HOME}/.bin"
paths  link = <<'FOO'
${LD_LIBARRAY_PATH}:${HOME}/lib
FOO

Las variables también pueden establecerse analizando argumentos de la línea de

comandos. 
myapp -verbose -site kfs -file f1 -file
f2

AppConfig proporciona un método simple (args()) para analizar argumentos de la línea de comandos. Un segundo método (getopt()) permite un procesamiento de argumentos más complejo mediante la delegación al módulo Getopt::Long de Johan

Vroman.

AppConfig también permite establecer variables mediante parámetros pasados a un script CGI a través de la URL (método GET)

. 
http://www.nowhere.com/cgi-bin/myapp?
verbose&site=kf
s

USAR EL MÓDULO

AppConfig

Para importar y usar el módulo AppConfig, la siguiente línea debe aparecer en su script de

Perl: 
use
AppConfig;

Para importar constantes definidas por el módulo AppConfig, especifique el nombre de uno o más de los conjuntos de constantes o etiquetas como parámetros a "use"

use AppConfig qw(:expand :argcount)

Vea "DEFINICIÓN DE CONSTANTES" más abajo para más información sobre los conjuntos de etiquetas de constantes definidos por

AppConfig.

AppConfig está implementado utilizando métodos orientados a objetos. Se crea e inicializa un nuevo objeto AppConfig utilizando el método new(). Esto devuelve una referencia a un nuevo objeto

AppConfig. 
my $config = AppConfig->new()
;

Esto creará y devolverá una referencia a un nuevo objeto

AppConfig.

Al hacerlo, el objeto AppConfig también crea una referencia interna a un objeto AppConfig::State en el que almacenar el estado de las variables. Todos los argumentos pasados al constructor de AppConfig se pasan directamente al constructor de AppConfig::

State.

El primer parámetro (opcional) puede ser una referencia a un array hash que contenga información de

configuración. 
my $config = AppConfig->new( {
        CASE   => 1,
        ERROR  => \&my_error,
        GLOBAL => { 
                DEFAULT  => "<unset>", 
                ARGCOUNT => ARGCOUNT_ONE,
            },
    } )
;

Vea AppConfig::State para los detalles completos de las opciones de configuración disponibles. Estas son,

brevemente:

.
CREA
TE
Se usa para indicar que las variables no definidas deben crearse automáticamente (predeterminado: desactivado)
.
GLOB
AL
Referencia a un array hash de valores globales utilizados por defecto al definir variables. Los valores globales válidos son DEFAULT, ARGCOUNT, EXPAND, VALIDATE y
ACTION.

Se usa para indicar que las rutinas de análisis de la línea de comandos y de archivos de configuración deben retornar inmediatamente al encontrar un
error.

).

Los parámetros siguientes pueden ser definiciones de variables. Estos se pasan al método define(), descrito más abajo en "DEFINIR

DEFINICIÓN DE

VARIABLES

El método define() (delegado a AppConfig::State) se utiliza para predeclarar una variable y especificar su

configuración. 
$config->define("foo")
;

Las variables también pueden definirse directamente desde el constructor AppConfig new(

). 
my $config = AppConfig->new("foo")
;

En ambos ejemplos anteriores, se define una nueva variable llamada "foo". También se puede pasar una referencia a un hash array para especificar la información de configuración de la

variable: 
$config->define("foo", {
        DEFAULT   => 99,
        ALIAS     => 'metavar1',
    })
;

Los elementos de configuración especificados en la opción GLOBAL del constructor del módulo se aplican de forma predeterminada cuando se crean las variables. p.

ej. 
my $config = AppConfig->new( { 
    GLOBAL => {
        DEFAULT  => "<undef>",
        ARGCOUNT => ARGCOUNT_ONE,
    }
} );
$config->define("foo");
$config->define("bar", { ARGCOUNT => ARGCOUNT_NONE } )
;

es equivalente

a: 
my $config = AppConfig->new();
$config->define( "foo", {
    DEFAULT  => "<undef>",
    ARGCOUNT => ARGCOUNT_ONE,
} );
$config->define( "bar", 
    DEFAULT  => "<undef>",
    ARGCOUNT => ARGCOUNT_NONE,
} )
;

Se pueden definir múltiples variables en la misma llamada a define(). Los hashes de configuración para las variables pueden

omitirse. 
$config->define("foo", "bar" => { ALIAS = "boozer" }, "baz")
;

resumen:

Uno o más (referencia de lista o "lista|como|esto") nombres alternativos para la

Especifica el número y tipo de argumentos que espera la variable. DEFINICIÓN DE FORMATO

COMPACTO

Las variables pueden especificarse utilizando un formato compacto. Este es idéntico al formato de especificación de Getopt::Long y tiene la

forma: 
"nombre|alias|alias<argopts>
"

El primer elemento indica el nombre de la variable y se pueden añadir valores ALIAS posteriores, cada uno separado por una barra vertical

'|'.

El elemento <argopts> indica el valor de ARGCOUNT y puede ser uno de los

siguientes: 
!                  ARGCOUNT_NONE
=s                 ARGCOUNT_ONE
=s@                ARGCOUNT_LIST
=s%
ARGCOUNT_HASH

Se pueden especificar construcciones adicionales admitidas por Getopt::Long en lugar del elemento "=s" (p. ej. "=f"). El elemento <argopts> completo se almacena en el parámetro ARGS de la variable y se pasa intacto a Getopt::Long cuando se llama al método getopt()

.

Los siguientes ejemplos demuestran el uso del formato compacto, con sus especificaciones completas

equivalentes: 
$config->define("foo|bar|baz!");
$config->define(
        "foo" => { 
            ALIAS    => "bar|baz", 
            ARGCOUNT => ARGCOUNT_NONE,
        });
$config->define("name=s");
$config->define(
        "name" => { 
            ARGCOUNT => ARGCOUNT_ONE,
        });
$config->define("file|filelist|f=s@");
$config->define(
        "file" => { 
            ALIAS    => "filelist|f", 
            ARGCOUNT => ARGCOUNT_LIST,
        });
$config->define("user|u=s%");
$config->define(
        "user" => { 
            ALIAS    => "u", 
            ARGCOUNT => ARGCOUNT_HASH,
        })
;

Se pueden especificar opciones de configuración adicionales mediante una referencia de hash, como es habitual. El formato de definición compacto anulará cualquier valor de configuración proporcionado para ARGS y

ARGCOUNT. 
$config->define("file|filelist|f=s@", { VALIDATE => \&check_file }
)
;

LECTURA Y MODIFICACIÓN DE VALORES DE

VARIABLES

AppConfig define dos métodos (a través de AppConfig::State) para manipular los valores de las

variables 
set($variable, $value);
get($variable)
;

Una vez definidas, las variables pueden accederse directamente como métodos del objeto, donde el nombre del método es el mismo que el nombre de la variable. es

decir, 
$config->set("verbose", 1)
;

es equivalente

a 
$config->verbose(1)
;

Tenga en cuenta que AppConfig define los siguientes

métodos: 
new();
file();
args();
getopt()
;

Y también, mediante delegación a AppConfig::

State: 
define()
get()
set()
varlist()

Si define una variable con uno de los nombres anteriores, no podrá acceder a ella directamente como un método del objeto. es

decir, 
$config->file()
;

Esto llamará al método file(), en lugar de devolver el valor de la variable 'file'. Puede solucionar esto llamando explícitamente a get() y set() en una variable cuyo nombre entre en

conflicto: 
$config->get('file')
;

o definiendo un alias "seguro" mediante el cual se pueda acceder a la

variable: 
    $config->define("file", { ALIAS => "fileopt" });
o
    $config->define("file|fileopt");
    ...
    $config->fileopt()
;

Sin parámetros, se devuelve el valor actual de la variable. Si se especifica un parámetro, la variable se establece en ese valor y se devuelve el resultado de la operación set()

. 
$config->age(29);        # establece 'age' en 29, devuelve 1 (ok)
print $config->age();    # imprime
"29"

El método varlist() se puede utilizar para extraer un número de variables en un hash array. El primer parámetro debe ser una expresión regular que se utilizará para hacer coincidir los nombres de las

variables. 
my %vars = $config->varlist("^file");   # todas las variables
"file*"

Se puede especificar un segundo parámetro (cualquier valor verdadero) para indicar que la parte del nombre de la variable que coincide con la expresión regular debe eliminarse al copiarse en el hash de

destino. 
$config->file_name("/tmp/file");
$config->file_path("/foo:
/bar:/baz"); my %vars = $config->varlist("^file_", 1); # %
vars: # name => /tmp/file # path => "/foo:/bar:/baz"

LECTURA DE ARCHIVOS DE

CONFIGURACIÓN

El módulo AppConfig proporciona una interfaz simplificada para leer archivos de configuración con el módulo AppConfig::File. El método file() carga automáticamente el módulo AppConfig::File y crea un objeto para procesar el archivo o archivos de configuración. Las variables almacenadas en el AppConfig::State interno se actualizan automáticamente con los valores especificados en el archivo de

configuración. 
$config->file($filename)
;

Se pueden pasar múltiples archivos a file() y deben indicar el nombre del archivo o ser una referencia a un manejador de archivo abierto o

glob. 
$config->file($filename, $filehandle, \*STDIN, ...)
;

El archivo puede contener líneas en blanco y comentarios (prefijados con '#') que se ignoran. Las líneas de continuación pueden marcarse terminando la línea con una

'\'. 
# este es un comentario
callsign = alpha bravo camel delta echo foxtrot golf hipowls \
           india juliet kilo llama mike november oscar papa  \
           quebec romeo sierra tango umbrella victor whiskey \
           x-ray yankee
zebra

Las variables que son indicadores simples y no esperan un argumento (ARGCOUNT = ARGCOUNT_NONE) pueden especificarse sin ningún valor. Se establecerán con el valor 1, ignorando cualquier valor especificado explícitamente (excepto "0" y "off"). La variable también puede especificarse con el prefijo "no" para establecer implícitamente la variable en

0. 
verbose                              # encendido (1)
verbose = 1                          # encendido (1)
verbose = 0                          # apagado (0)
verbose off                          # apagado (0)
verbose on                           # encendido (1)
verbose mumble                       # encendido (1)
noverbose                            # apagado
(0)

Las variables que esperan un argumento (ARGCOUNT = ARGCOUNT_ONE) se establecerán en lo que siga al nombre de la variable, hasta el final de la línea actual (incluyendo cualquier línea de continuación). Se puede insertar un signo igual opcional entre la variable y el valor para claridad

. 
room = /home/kitchen
room
/home/bedroom

Cada redefinición subsiguiente del valor de la variable sobrescribe el valor

anterior. 
print $config->room();               # imprime
"/home/bedroom"

Las variables pueden definirse para aceptar múltiples valores (ARGCOUNT = ARGCOUNT_LIST). Cada definición subsiguiente de la variable añade el valor a la lista de valores previamente establecidos para la

variable. 
drink = coffee
drink =
tea

Se devuelve una referencia a una lista de valores cuando se solicita la

variable. 
my $beverages = $config->drink();
print join(", ", @$beverages);      # imprime "coffee,
tea"

Las variables también pueden definirse como listas hash (ARGCOUNT = ARGCOUNT_HASH). Cada definición subsiguiente crea una nueva clave y valor en el array

hash. 
alias l="ls -CF"
alias
e="emacs"

Se devuelve una referencia al hash cuando se solicita la

variable. 
my $aliases = $config->alias();
foreach my $k (keys %$aliases) {
    print "$k => $aliases->{ $k }\n";
}

El prefijo '-' se puede usar para restablecer una variable a su valor predeterminado y el prefijo '+' se puede usar para establecerla en

1 
-verb
ose +
debug

VARIABLE

EXPANSIÓN

Los valores de las variables pueden contener referencias a otras variables AppConfig, variables de entorno y/o directorios de inicio de los usuarios. Estos se expandirán dependiendo del valor EXPAND de cada variable o del valor EXPAND

GLOBAL.

Se pueden aplicar tres tipos diferentes de

expansión: 
bin = ~/bin          # expandir '~' al directorio de inicio si EXPAND_UID
tmp = ~abw/tmp       # como arriba, pero directorio de inicio del usuario 'abw'
perl = $bin/perl     # expandir valor de la variable 'bin' si EXPAND_VAR
ripl = $(bin)/ripl   # como arriba con paréntesis explícitos
home = ${HOME}       # expandir variable de entorno HOME si
EXPAND_ENV

Consulte AppConfig::State para obtener más información sobre la expansión de valores de

variables.

Los archivos de configuración pueden tener variables organizadas en bloques. Un encabezado de bloque, que consiste en el nombre del bloque entre corchetes, introduce un bloque de configuración. El nombre del bloque y un guion bajo se anteponen entonces a los nombres de todas las variables referenciadas posteriormente en ese bloque. El bloque continúa hasta la siguiente definición de bloque o hasta el final del archivo

actual. 
[block1]
foo = 10             #
block1_foo = 10 [block2] foo =
20 # block2_foo = 20

ANÁLISIS DE OPCIONES DE LÍNEA DE

COMANDOS

Hay dos métodos para procesar las opciones de la línea de comandos. El primero, args(), es una implementación pequeña y eficiente que ofrece funcionalidad básica. El segundo, getopt(), ofrece una funcionalidad más potente y completa al delegar la tarea al módulo Getopt::Long de Johan Vroman. El compromiso entre args() y getopt() es esencialmente uno de velocidad/tamaño contra flexibilidad. Úselos según corresponda. Ambos implementan carga de módulos bajo demanda y no tienen sobrecosto hasta que se

usan.

El método args() se usa para analizar opciones simples de la línea de comandos. Carga automáticamente el módulo AppConfig::Args y crea un objeto para procesar los argumentos de la línea de comandos. Las variables almacenadas en el AppConfig::State interno se actualizan automáticamente con los valores especificados en los

argumentos.

Al método se le debe pasar una referencia a una lista de argumentos a analizar. Se usa el array @ARGV si args() se llama sin

parámetros. 
$config->args(\@myargs);
$config->args();               # usa
@ARGV

Los argumentos se leen y se extraen del array hasta que se encuentra el primero que no tiene el prefijo '-' o '--'. En ese punto, el método devuelve 1 para indicar éxito, dejando cualquier argumento sin procesar restante en la

lista.

Cada argumento debe ser el nombre o alias de una variable con el prefijo '-' o '--'. Los argumentos que no tienen ese prefijo (y no son un parámetro adicional de un argumento anterior) provocarán que se emita una advertencia. Si la opción PEDANTIC está establecida, el método devolverá 0 inmediatamente. Con PEDANTIC sin establecer (predeterminado), el método continuará analizando el resto de los argumentos, devolviendo 0 cuando

termine.

Si la variable es un indicador simple (ARGCOUNT = ARGCOUNT_NONE), se establece en el valor 1. La variable puede tener el prefijo "no" para establecer su valor en

0. 
myprog -verbose --debug -notaste     # $config->verbose(1)
                                     # $config->debug(1)
                                     # $config->
taste(0)

Las variables que esperan un argumento adicional (ARGCOUNT != 0) se establecerán en el valor del argumento que las

sigue. 
myprog -f /tmp/myfile                # $config->file('/tmp/file')
;

Las variables que esperan múltiples valores (ARGCOUNT = ARGCOUNT_LIST o ARGCOUNT_HASH) tendrán valores sucesivos añadidos cada vez que se encuentre la

opción. 
myprog -file /tmp/foo -file /tmp/bar # $config->file('/tmp/foo')
                                     # $config->file('/tmp/bar')
# file => [ '/tmp/foo', '/tmp/bar' ]
myprog -door "jim=Jim Morrison" -door "ray=Ray Manzarek"
                                # $config->door("jim=Jim Morrison");
                                # $config->door("ray=Ray Manzarek");
# door => { 'jim' => 'Jim Morrison', 'ray' => 'Ray Manzarek'
}

Consulte AppConfig::Args para obtener más detalles sobre el análisis de argumentos de la línea de

comandos.

El método getopt() proporciona una forma de usar la potencia y flexibilidad del módulo Getopt::Long para analizar argumentos de la línea de comandos y tener los valores internos del objeto AppConfig actualizados automáticamente

.

El primer parámetro (que no es una referencia a lista) puede contener una serie de cadenas de configuración para pasar a Getopt::Long::Configure. Se puede pasar adicionalmente una referencia a una lista de argumentos o se usa @ARGV por

defecto. 
$config->getopt();                       # usa @ARGV
$config->getopt(\@myargs);
$config->getopt(qw(auto_abbrev debug));  # usa @ARGV
$config->getopt(qw(debug), \@myargs)
;

Consulte Getopt::Long para conocer los detalles de las opciones de configuración

disponibles.

El método getopt() construye una cadena de especificación para cada variable interna y luego inicializa Getopt::Long con estos valores. La cadena de especificación se construye a partir del nombre, cualquier alias (delimitado por una barra vertical '|') y el valor del parámetro

ARGS. 
$config->define("foo", {
    ARGS  => "=i",
    ALIAS => "bar|baz",
});
# Especificación de Getopt::Long:
"foo|bar|baz=i"

Los errores y advertencias generados por el módulo Getopt::Long son capturados y manejados por el manejador de errores de AppConfig. Este puede ser una rutina definida por el usuario instalada con la opción de configuración

ERROR.

Tenga en cuenta que la interfaz AppConfig::Getopt aún es exp

erimental y puede no ser 100% operativa. Esto se debe casi sin du
da a problemas en AppConfig::Getopt más que en Getopt::Long.

ANÁLISIS DE PARÁMETROS

CGI

El método cgi() proporciona una interfaz al módulo AppConfig::CGI para actualizar los valores de las variables basándose en los parámetros añadidos a la URL para un script CGI. Esto se conoce comúnmente como el método "GET" de CGI. El método "POST" de CGI no está actualmente

soportado.

Las definiciones de parámetros se separan del nombre del script CGI con un signo de interrogación y entre sí con ampersands. Donde las variables tienen valores específicos, estos se añaden a la variable con un signo de

igualdad: 
http://www.here.com/cgi-bin/myscript?foo=bar&baz=qux&verbose
    # $config->foo('bar');
    # $config->baz('qux');
    # $config->verbose(1)
;

Ciertos valores especificados en una URL deben escaparse de la manera apropiada (consulte las especificaciones CGI en http://www.w3c.org/ para obtener todos los detalles). El módulo AppConfig::CGI descodifica automáticamente la cadena de consulta CGI para restaurar los parámetros a sus valores

previstos. 
http://where.com/mycgi?title=%22The+Wrong+Trousers%22
# $config->title('"The Wrong Trousers"')
;

Por favor, sea considerado con las implicaciones de seguridad de proporcionar acceso de escritura a variables de script a través de

CGI. 
http://rebel.alliance.com/cgi-bin/...
    .../send_report?file=%2Fetc%2Fpasswd&email=darth%40empire.
com

Para evitar cualquier cambio accidental o malicioso de variables "privadas", defina solo las variables "públicas" antes de llamar al método cgi() (o cualquier otro). Se pueden definir posteriormente más variables que no pueden ser influenciadas por los parámetros

CGI. 
$config->define('verbose', 'debug')
$config->cgi();
# solo puede establecer verbose y debug $c
onfig->define('email', 'file'); $config->file($cfgfile
); # puede establecer verbose, debug, email + file
