NOMBRE

apt_auth.conf - Archivo de configuración de inicio de sesión para fuentes y proxies de APT

DESCRIPCIÓN

Los archivos de configuración de APT como sources.list(5) o apt.conf(5) necesitan ser accesibles para todos los que usan las herramientas de apt en el sistema para tener acceso a toda la información relacionada con los paquetes, como los paquetes disponibles en un repositorio. La información de inicio de sesión necesaria para conectarse a un proxy o para descargar datos de un repositorio, por otro lado, no siempre debe ser accesible por todos y, por lo tanto, no puede colocarse en un archivo con permisos de archivo legibles por todos.

El archivo auth.conf de APT, /etc/apt/auth.conf, y los archivos .conf dentro de /etc/apt/auth.conf.d pueden usarse para almacenar información de inicio de sesión en un formato similar a netrc con permisos de archivo restrictivos.

FORMATO SIMILAR A NETRC

El formato definido aquí es similar al formato del archivo ~/.netrc utilizado por ftp(1) y programas similares que interactúan con servidores. Es un formato simple basado en tokens, y los siguientes tokens son reconocidos; Los tokens desconocidos serán ignorados. Los tokens pueden separarse por espacios, tabulaciones o saltos de línea.

machine [protocolo://]nombre_host[:puerto][/ruta]

Las entradas se buscan buscando el token machine que coincida con el nombre de host de la URI para la cual APT necesita información de inicio de sesión. Ampliando el formato netrc, se puede especificar un número de puerto. Si no se proporciona puerto, el token coincide para todos los puertos. De manera similar, la ruta es opcional y solo es necesaria y útil si varios repositorios con diferentes información de inicio de sesión residen en el mismo servidor. Un token de máquina con una ruta coincide si la ruta en la URI comienza con la ruta dada en el token. Una vez que se realiza una coincidencia, se procesan los tokens subsiguientes, deteniéndose al final del archivo o al encontrar otro token de machine.

Si no se especifica el protocolo, la entrada solo coincide con https y tor+https.

login nombre

El nombre de usuario a utilizar.

password cadena

La contraseña a utilizar.

EJEMPLO

Proporcionar información de inicio de sesión para un usuario llamado apt con la contraseña debian para la entrada de sources.list(5)

deb https://example.org/debian trixie main

se podría hacer directamente en la entrada:

deb https://apt:debian@example.org/debian trixie main

Alternativamente, se podría usar una entrada como la siguiente en el archivo auth.conf:

machine example.org
login apt
password debian

O alternativamente en una sola línea:

machine example.org login apt password debian

Si necesita ser más específico, todas estas líneas también se aplicarán a la entrada de ejemplo:

machine example.org/deb login apt password debian
machine example.org/debian login apt password debian
machine example.org/debian/ login apt password debian

Por otro lado, ninguna de las siguientes líneas se aplicará:

machine example.org:443 login apt password debian
machine example.org/deb/ login apt password debian
machine example.org/ubuntu login apt password debian
machine example.orga login apt password debian
machine example.net login apt password debian

NOTAS

El soporte básico para esta característica está presente desde la versión 0.7.25, pero no estuvo documentado durante años. La documentación se añadió en la versión 1.5, cambiando también la implementación ligeramente. Para máxima compatibilidad retroactiva, debería evitar múltiples tokens de máquina con el mismo nombre de host, pero si necesita múltiples, todos deberían tener una ruta especificada en el token de máquina.

La información de inicio de sesión en auth.conf es más flexible que la de sources.list. Por ejemplo, la información de inicio de sesión se puede especificar solo para partes de un repositorio, o si la entrada de sources.list redirige a otro lugar, se puede proporcionar información de inicio de sesión para el destino de la redirección.
