Esto se logra construyendo un objeto compartido dinámico (DSO) a partir de uno o más archivos de código fuente u objetosfiles que luego pueden cargarse en el servidor Apache en tiempo de ejecución mediante la directiva LoadModule

de mod_so.

Así que para usar este mecanismo de extensión, su plataforma debe soportar la característica DSO y su binario de Apache httpd debe haber sido compilado con el módulo mod_so. Laherramienta apxsse queja automáticamente si no es el caso. Puede verificar esto usted mismo ejecutando manualmente el comando $ httpd -lEl módulo mod_so debería ser parte de la lista mostrada. Si estos requisitos se cumplen, puede extender fácilmente la funcionalidad de su servidor Apache instalando sus propios módulos con el mecanismo DSO con la ayuda de estaherramienta apxs :$ apxs -i -a -c mod_foo.c gcc -fpic -DSHARED_MODULE -I/path/to/apache/include -c mod_foo.c ld -Bshareable -o mod_foo.so mod_foo.o cp mod_foo.so /path/to/apache/modules/mod_foo.so chmod 755 /path/to/apache/modules/mod_foo.so [activating module `foo' in /path/to/apache/etc/httpd.conf] $ apachectl restart /path/to/apache/sbin/apachectl restart: httpd not running, trying to start [Tue Mar 31 11:27:55 1998] [debug] mod_so.c(303): loaded module foo_module /path/to/apache/sbin/apachectl restart: httpd started $ _Los argumentos file

EJEMPLOS

Supongamos que tiene un módulo de Apache llamado mod_foo.c disponible que debería extender la funcionalidad del servidor de Apache. Para lograr esto, primero debe compilar el código fuente C en un objeto compartido adecuado para cargarse en el servidor de Apache en tiempo de ejecución mediante el siguiente comando:

      $ apxs -c mod_foo.c
      /path/to/libtool --mode=compile gcc ... -c mod_foo.c
      /path/to/libtool --mode=link gcc ... -o mod_foo.la mod_foo.slo
      $ _

Luego debe actualizar la configuración de Apache asegurándose de que esté presente una directiva LoadModule para cargar este objeto compartido. Para simplificar este paso apxs proporciona una forma automática de instalar el objeto compartido en su directorio "modules" y actualizar el httpd.conf archivo en consecuencia. Esto se puede lograr ejecutando:

      $ apxs -i -a mod_foo.la
      /path/to/instdso.sh mod_foo.la /path/to/apache/modules
      /path/to/libtool --mode=install cp mod_foo.la /path/to/apache/modules
      ...
      chmod 755 /path/to/apache/modules/mod_foo.so
      [activating module `foo' in /path/to/apache/conf/httpd.conf]
      $ _

De esta manera se añade a la configuración una línea llamada

      LoadModule foo_module modules/mod_foo.so

si aún no está presente. Si desea tener esto deshabilitado por defecto, use la -A opción, es decir

      $ apxs -i -A mod_foo.c

Para una prueba rápida del mecanismo apxs, puede crear una plantilla de módulo de Apache de ejemplo más un Makefile correspondiente mediante:

      $ apxs -g -n foo
      Creating [DIR]  foo
      Creating [FILE] foo/Makefile
      Creating [FILE] foo/modules.mk
      Creating [FILE] foo/mod_foo.c
      Creating [FILE] foo/.deps
      $ _

Luego puede compilar inmediatamente este módulo de ejemplo en un objeto compartido y cargarlo en el servidor de Apache:

      $ cd foo
      $ make all reload
      apxs -c mod_foo.c
      /path/to/libtool --mode=compile gcc ... -c mod_foo.c
      /path/to/libtool --mode=link gcc ... -o mod_foo.la mod_foo.slo
      apxs -i -a -n "foo" mod_foo.la
      /path/to/instdso.sh mod_foo.la /path/to/apache/modules
      /path/to/libtool --mode=install cp mod_foo.la /path/to/apache/modules
      ...
      chmod 755 /path/to/apache/modules/mod_foo.so
      [activating module `foo' in /path/to/apache/conf/httpd.conf]
      apachectl restart
      /path/to/apache/sbin/apachectl restart: httpd not running, trying to start
      [Tue Mar 31 11:27:55 1998] [debug] mod_so.c(303): loaded module foo_module
      /path/to/apache/sbin/apachectl restart: httpd started
      $ _
