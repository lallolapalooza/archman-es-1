NOMBRE

apt - interfaz de línea de comandos

SINOPSIS

apt [-h] [-o=cadena_de_configuración] [-c=archivo_de_configuración] [-t=versión_objetivo] [-a=arquitectura] {list | search | show | update | installpaquete[{=número_de_versión_del_paquete| /versión_objetivo}]... | removepaquete... | upgrade | full-upgrade | edit-sources | {-v | --version} | {-h | --help}}

DESCRIPCIÓN

apt proporciona una interfaz de línea de comandos de alto nivel para el sistema de gestión de paquetes. Está destinada a ser una interfaz para el usuario final y habilita algunas opciones mejor adaptadas para uso interactivo por defecto en comparación con herramientas APT más especializadas como apt-get(8) y apt-cache(8).

Al igual que apt en sí misma, su página man está destinada a ser una interfaz para el usuario final y como tal solo menciona los comandos y opciones más utilizados, en parte para no duplicar información en múltiples lugares y en parte para evitar abrumar a los lectores con una abundancia de opciones y detalles.

update (apt-get(8))

update se utiliza para descargar información de paquetes de todas las fuentes configuradas. Otros comandos operan sobre estos datos para, por ejemplo, realizar actualizaciones de paquetes o buscar y mostrar detalles sobre todos los paquetes disponibles para la instalación.

upgrade (apt-get(8))

upgrade se utiliza para instalar las actualizaciones disponibles de todos los paquetes actualmente instalados en el sistema desde las fuentes configuradas a través de sources.list(5). Se instalarán nuevos paquetes si es necesario para satisfacer dependencias, pero los paquetes existentes nunca serán eliminados. Si una actualización para un paquete requiere la eliminación de un paquete instalado, la actualización para este paquete no se realiza.

Cuando se proporciona un paquete como argumento, el paquete será instalado antes de la acción de actualización.

full-upgrade (apt-get(8))

full-upgrade realiza la función de upgrade pero eliminará paquetes actualmente instalados si esto es necesario para actualizar el sistema como un todo.

Cuando se proporciona un paquete como argumento, el paquete será instalado antes de la acción de actualización.

install, reinstall, remove, purge (apt-get(8))

Realiza la acción solicitada en uno o más paquetes especificados mediante regex(7), glob(7) o coincidencia exacta. La acción solicitada puede ser anulada para paquetes específicos añadiendo un más (+) al nombre del paquete para instalar este paquete o un menos (-) para eliminarlo.

Se puede seleccionar una versión específica de un paquete para la instalación añadiendo al nombre del paquete un signo igual (=) y la versión del paquete a seleccionar. Alternativamente, se puede seleccionar la versión de una versión (release) específica añadiendo al nombre del paquete una barra diagonal (/) y el nombre en clave (trixie, forky, sid ...) o el nombre de la suite (stable, testing, unstable). Esto también seleccionará versiones de esta versión para las dependencias de este paquete si es necesario para satisfacer la solicitud.

Eliminar un paquete elimina todos los datos empaquetados, pero generalmente deja atrás archivos de configuración de usuario pequeños (y modificados), en caso de que la eliminación fuera un accidente. Simplemente emitiendo una solicitud de instalación para el paquete eliminado accidentalmente restaurará su funcionamiento como antes en ese caso. Por otro lado, puedes deshacerte de estos restos llamando a purge incluso en paquetes ya eliminados. Ten en cuenta que esto no afecta a ningún dato o configuración almacenada en tu directorio de inicio.

autoremove (apt-get(8))

autoremove se utiliza para eliminar paquetes que fueron instalados automáticamente para satisfacer dependencias de otros paquetes y que ahora ya no son necesarios porque las dependencias cambiaron o el/los paquete(s) que los necesitaban fueron eliminados mientras tanto.

Debes verificar que la lista no incluya aplicaciones que hayas llegado a querer aunque alguna vez se instalaron solo como una dependencia de otro paquete. Puedes marcar tal paquete como instalado manualmente usando apt-mark(8). Los paquetes que has instalado explícitamente a través de install tampoco son nunca propuestos para eliminación automática.

satisfy (apt-get(8))

satisfy satisface cadenas de dependencias, como se usan en Build-Depends. También maneja conflictos, anteponiendo a un argumento "Conflicts: ".

Ejemplo: apt satisfy "foo, bar (>= 1.0)" "Conflicts: baz, fuzz"

why, why-not

Estos comandos imprimen el camino de razonamiento del solucionador. Son similares a los comandos equivalentes de aptitude para muchos casos de uso, pero son diferentes en que imprimen la razón real que el solucionador eligió en lugar del camino potencial más fuerte.

El why comando determina por qué un paquete instalado está instalado. Esto proporciona una retroalimentación razonable sobre por qué un paquete instalado automáticamente está instalado; para un paquete instalado manualmente no se da ninguna otra razón. Si el paquete no está instalado, no se puede determinar ninguna razón.

El why-not comando determina por qué se determinó que un paquete no es instalable. Esto puede no siempre arrojar un resultado, incluso si un paquete es desinstalable.

Ambos comandos toman un solo argumento, el nombre de un paquete.

search (apt-cache(8))

search se puede usar para buscar el término(s) dado regex(7) en la lista de paquetes disponibles y mostrar las coincidencias. Esto puede ser útil, por ejemplo, si estás buscando paquetes que tengan una característica específica. Si estás buscando un paquete que incluya un archivo específico, prueba apt-file(1).

show (apt-cache(8))

Muestra información sobre el/los paquete(s) dado(s) incluyendo sus dependencias, tamaño de instalación y descarga, fuentes de las que el paquete está disponible, la descripción del contenido del paquete y mucho más. Puede ser útil, por ejemplo, mirar esta información antes de permitir que apt(8) elimine un paquete o mientras buscas nuevos paquetes para instalar.

list

list es algo similar a dpkg-query --list en que puede mostrar una lista de paquetes que satisfacen ciertos criterios. Soporta patrones glob(7) para hacer coincidir nombres de paquetes, apt-patterns(7), así como opciones para listar instalados (--installed), actualizables (--upgradeable) o todas las versiones disponibles (--all-versions).

edit-sources (en desarrollo)

edit-sources te permite editar tus sources.list(5) archivos en tu editor de texto preferido mientras también proporciona comprobaciones básicas de coherencia.

showsrc, depends, rdepends, policy (resumido en apt-cache(8))

source, build-dep, download, changelog, clean, distclean, autoclean (resumido en apt-get(8))

USO EN SCRIPTS Y DIFERENCIAS CON OTRAS HERRAMIENTAS APT

La apt(8) línea de comandos está diseñada como una herramienta para el usuario final y puede cambiar de comportamiento entre versiones. Aunque intenta no romper la compatibilidad con versiones anteriores, esto tampoco está garantizado si un cambio parece beneficioso para el uso interactivo.

Todas las características de apt(8) están disponibles también en herramientas APT dedicadas como apt-get(8) y apt-cache(8) . apt(8) solo cambia el valor por defecto de algunas opciones (ver apt.conf(5) y específicamente el alcance Binary). Por lo tanto, deberías preferir usar estos comandos (potencialmente con algunas opciones adicionales habilitadas) en tus scripts, ya que mantienen la compatibilidad con versiones anteriores tanto como sea posible.
