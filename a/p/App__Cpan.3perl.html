SINOPSI

S 
# con argumentos y sin interruptores, instala los módulos especificados
cpan nombre_del_módulo [ nombre_del_módulo ... ]
# con interruptores, instala módulos con comportamiento adicional
cpan [-cfFimtTw] nombre_del_módulo [ nombre_del_módulo ... ]
# usar local::lib
cpan -I nombre_del_módulo [ nombre_del_módulo ... ]
# anulación única del servidor espejo para usar espejos más rápidos
cpan -p ...
# solo con el punto, instala desde la distribución en el
# directorio actual
cpan .
# sin argumentos, inicia el shell de CPAN.pm
cpan
# sin argumentos, pero con algunos interruptores
cpan
[-ahpruvACDLOPX
]

DESCRIPCIÓ

N

Este script proporciona una interfaz de comandos (no un shell) para CPAN. En el momento utiliza CPAN.pm para hacer el trabajo, pero no es un ejecutor de comandos de una sola vez para CPAN.

pm.

Opcione

s
-
a
Crea un autobundle de CPAN.pm con CPAN::Shell->
autobundle.
-A módulo [ módulo ..
. ]
Muestra los mantenedores principales de los módulos
especificados.
-c
módulo
Ejecuta un `make clean` en los directorios del módulo
especificado.
-C módulo [ módulo ..
. ]
Muestra los archivos Changes de los módulos
especificados
-D módulo [ módulo ..
. ]
Muestra los detalles del módulo. Imprime una línea para cada módulo desactualizado (es decir, módulos instalados localmente pero que tienen versiones más nuevas en CPAN). Cada línea tiene tres columnas: nombre del módulo, versión local y versión de
CPAN.
-
f
Fuerza la acción especificada, cuando normalmente habría fallado. Use esto para instalar un módulo incluso si sus pruebas fallan. Cuando use esta opción, -i no es opcional para instalar un módulo cuando necesite forzarlo: 
% cpan -f -i Module:
:
Foo
-
F
Desactiva los intentos de CPAN.pm de bloquear cualquier cosa. Debería tener cuidado con esto, ya que podría terminar con varios scripts intentando manipular el mismo directorio. Esto no es tanto una preocupación si está cargando una configuración especial con "-j", y esa configuración establece sus propios directorios de
trabajo.
-g módulo [ módulo ..
. ]
Descarga al directorio actual la última distribución del
módulo.
-G módulo [ módulo ..
. ]
NO IMPLEMENTADO

Descarga al directorio actual la última distribución de los módulos, desempaqueta cada distribución y crea un repositorio git para cada

distribución.

Si desea esta característica, consulte la distribución "Git::CPAN::Patch"

de Yanick
Champoux.
-
h
Imprime un mensaje de ayuda y sale. Cuando especifica "-h", ignora todas las demás opciones y
argumentos.
-i módulo [ módulo ..
. ]
Instala los módulos especificados. Sin otros interruptores, este interruptor se
sobreentiende.
-
I
Carga "local::lib" (piense en "-I" para cargar rutas de lib). Qué lástima que "-l" ya estaba
ocupado.
-j Config.
pm
Carga el archivo que tiene los datos de configuración de CPAN. Este debería tener el mismo formato que el archivo estándar CPAN/Config.pm, que define $CPAN::Config como un hash anónimo.

Si el archivo no existe, "cpan" termina

con
error.
-
J
Vuelca la configuración en el mismo formato que usa CPAN.pm. Esto es útil para verificar la configuración, así como para usar el volcado como punto de partida para una nueva configuración
personalizada.
-
l
Lista todos los módulos instalados con sus
versiones
-L autor [ autor ...
]
Lista los módulos de los autores
especificados.
-
m
Compila (make) los módulos
especificados.
-M espejo1,espejo2,
...
Una lista de servidores espejo separada por comas para usar solo en esta ejecución. La opción "-P" puede encontrarlos
automáticamente.
-
n
Realiza una ejecución de prueba, pero no instala nada realmente. (no
implementado)
-
O
Muestra los módulos
desactualizados.
-
p
Hace ping a los servidores espejo configurados e imprime un
informe
-

Encuentra los mejores servidores espejo que podría estar usando y los usa para la sesión
actual.
-
r
Recompila los módulos cargados dinámicamente con CPAN::Shell->
recompile.
-
s
Ingresa al shell de CPAN.pm. Este comando hace esto automáticamente si no especifica ningún
argumento.
-t módulo [ módulo ..
. ]
Ejecuta un `make test` en los módulos
especificados.
-
T
No prueba los módulos. Simplemente los

-

-

Imprime la versión del script y la versión de CPAN.pm, y luego
sale.
-

Imprime información detallada sobre el cliente
cpan.

Encuentra coincidencias cercanas a los módulos nombrados que cree que podría haber escrito mal. Esto requiere la instalación opcional de Text::Levenshtein o Text::Levenshtein::

Ejemplo

s 
# imprimir un mensaje de ayuda
cpan -h
# imprimir los números de versión
cpan -v
# crear un autobundle
cpan -a
# recompilar módulos
cpan -r
# actualizar todos los módulos instalados cpan -u # instalar módulos ( el -i solo es opcional ) cpan -i Netscape::Booksmarks Business::ISBN #
forzar la instalación de módulos ( debe usar -i ) cpan -fi CGI::Minimal URI # instalar módulos pero sin probarlos cpan -Ti CGI::Minimal URI

entorno

Hay varios componentes en CPAN.pm que usan variables de entorno. Las herramientas de compilación, ExtUtils::MakeMaker y Module::Build usan algunas, mientras que otras son importantes para los niveles superiores a ellos. Algunas de estas están especificadas por el Perl Toolchain

Gang:

Consenso de Lancaster: https://github.com/Perl-Toolchain-Gang/toolchain-site/blob/master/lancaster-consensus.

Asume que nadie está prestando atención y omite las indicaciones para las distribuciones que lo hacen correctamente. cpan(1) establece esto en 1 a menos que ya tenga un valor (incluso si ese valor es falso)
.
PERL_MM_USE_DEFA
ULT
Usa la respuesta predeterminada para las preguntas con indicación. cpan(1) establece esto en 1 a menos que ya tenga un valor (incluso si ese valor es falso)
.
CPAN_OP

Al igual que con "PERL5OPT", una cadena de opciones adicionales de cpan(1) para añadir a las que especifique en la línea de
comandos.

El nivel de registro a utilizar, con el registrador integrado y mínimo o Log::Log4perl si está instalado. Los valores posibles son los mismos que los niveles de "Log::Log4perl": "TRACE", "DEBUG", "INFO", "WARN", "ERROR" y "FATAL". El valor predeterminado es "INFO
".
