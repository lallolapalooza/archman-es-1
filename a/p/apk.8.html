apk(8) Manual del Administrador del Sistema apk(8)

NOMBRE

apk - Alpine Package Keeper

SINOPSIS

apk [<opciones globales>...] comando [<opciones>...] [<argumentos>...]

DESCRIPCIÓN

apk gestiona los paquetes instalados en el sistema. El conjunto de restricciones de nivel superior sobre los paquetes del sistema se denomina el mundo (véase apk-world(5)).

apk admite varios subcomandos para consultar y manipular el mundo y los repositorios de paquetes.

Todos los comandos de apk que modifican la base de datos se registran en /var/log/apk.log.

De forma predeterminada, apk no es interactivo. Véase ARCHIVOS o --interactive para cambiar este valor predeterminado y hacerlo interactivo.

Solo opciones globales deben especificarse antes del comando. Por compatibilidad con versiones anteriores, se realiza un intento de mejor esfuerzo para analizar las opciones específicas de la aplicación antes del comando, pero esto está obsoleto y sujeto a ser eliminado.

SINTAXIS DE OPCIONES

El argumento BOOL para las opciones es 'yes' o 'no'. El argumento AUTO para las opciones es 'yes', 'no' o 'auto'. El valor predeterminado para estos argumentos es específico de cada opción.

Para las opciones con un argumento AUTO o BOOL , el argumento debe especificarse con el formato --option=argumento (es decir, el formato --option argumento no es compatible). Además, están disponibles los siguientes alias:

  • --option equivale a --option=yes
  • --no-option equivale a --option=no

OPCIONES GLOBALES

Las siguientes opciones están disponibles para todos los comandos.

--allow-untrusted

Instalar paquetes con una firma no fiable o sin firma.

--arch ARQUITECTURA

Anular temporalmente las arquitecturas. La primera --arch proporcionada se utilizará como arquitectura principal. Se utilizará para determinar las rutas desde donde descargar los índices de paquetes. Las arquitecturas adicionales especifican paquetes compatibles que se considerarán para la instalación.

Cuando se usa con --root, la arquitectura también se guardará.

--cache[=BOOL]

Cuando está deshabilitado, evita el uso de cualquier ruta de caché local.

--cache-dir DIRECTORIO_CACHÉ

Anular temporalmente el directorio de caché. DIRECTORIO_CACHÉ se trata como relativo a RAÍZ.

--cache-max-age EDAD

EDAD máxima (en minutos) que un índice puede permanecer en la caché antes de ser actualizado. 0 significa actualizar siempre.

--cache-packages[=BOOL]

Almacenar una copia de los paquetes en la caché en el momento de la instalación. Se habilita automáticamente si /etc/apk/cache existe como enlace simbólico.

--cache-predownload[=BOOL]

Descargar los paquetes necesarios a la caché antes de comenzar a confirmar una transacción. Requiere que la caché esté configurada para funcionar. Implica --cache-packages.

--check-certificate[=BOOL]

Cuando está deshabilitado, omite la validación del certificado del servidor HTTPS.

--force, -f

Habilitar las opciones --force-* seleccionadas (obsoleto).

--force-binary-stdout

Continuar incluso si se van a imprimir datos binarios en el terminal.

--force-broken-world

PELIGROSO: Eliminar las restricciones del mundo hasta que se encuentre una solución sin conflictos. Esto no permite la instalación de paquetes con dependencias insatisfiables y está destinado principalmente a ser utilizado en el arranque de initramfs y está implícito en --initramfs-diskless-boot. El propósito principal es permitir que los sistemas que se ejecutan desde tmpfs arranquen si el medio fue actualizado y algunos paquetes ya no están disponibles en la nueva versión.

APK intentará determinar las restricciones del mundo que causan que los paquetes tengan dependencias conflictivas y comenzará a deshabilitar las restricciones del mundo en este orden hasta que quede un conjunto de restricciones satisfactorio. El uso de esta opción en hardwared disk la instalación probablemente resultará en la eliminación inesperada de algunos paquetes. Si no está seguro, úselo con --interactive o --simulate primero.

--force-missing-repositories

Continúa incluso si algunos de los índices de los repositorios no están disponibles.

--force-no-chroot

Deshabilita chroot para scripts. Esto se puede usar para la creación de rootfs cuando chroot no está disponible. Los scripts que se ejecutan fuera de un entorno chroot pueden modificar y dañar el sistema anfitrión.

--force-non-repository

Continúa incluso si los paquetes pueden perderse al reiniciar. Esto puede suceder al ejecutar en modo run-from-tmpfs e instalar un paquete no perteneciente al repositorio.

--force-old-apk

Continúa incluso si los paquetes utilizan características no compatibles.

--force-overwrite

Sobrescribe archivos en otros paquetes.

--force-refresh

No utiliza archivos en caché (locales o de proxy).

--help, -h

Imprime la lista de todos los comandos con sus descripciones.

--interactive[=AUTO]

Determina si se pueden hacer preguntas antes de realizar ciertas operaciones. En modo auto, el modo interactivo se habilita si se ejecuta en una tty. Por defecto es no, o auto si /etc/apk/interactive existe.

--keys-dir KEYSDIR

Anula los directorios de claves de confianza del sistema por defecto. Si se especifica, solo se procesa este directorio. El KEYSDIR se trata de forma relativa a ROOT.

--legacy-info[=BOOL]

Imprime la salida del applet "info" en formato heredado o en el nuevo formato "query". Por defecto es no, pero el valor por defecto está sujeto a cambios a yes en una futura versión.

--logfile[=BOOL]

Si se desactiva, deshabilita la escritura del archivo de registro.

--network[=BOOL]

Si se desactiva, no utiliza la red. Se utilizan los paquetes de los repositorios de red en la caché.

--preserve-env[=BOOL]

Permite pasar el entorno del usuario a los scripts (excluyendo las variables que comienzan con APK_, que están reservadas).

--pretty-print[=AUTO]

Determina si la salida debe ser estilizada para ser legible por humanos. Por defecto es auto, que se resuelve a yes si se ejecuta en una tty.

--preupgrade-depends DEPS

Agrega o modifica dependencias de preactualización. Las dependencias de preactualización se utilizan para hacer coincidir los paquetes instalados que son elegibles para la preactualización. Por ejemplo, 'apk-tools' siempre preactualizará el paquete 'apk-tools', pero 'baselayout<2' preactualizará 'baselayout' solo si la versión instalada de baselayout es menor que 2 y hay una actualización disponible. Ver también apk-upgrade(8).

--print-arch

Imprime la arquitectura por defecto y sale.

--progress[=AUTO]

Habilita o deshabilita la barra de progreso. Por defecto es auto, que se resuelve a yes si se ejecuta en una tty.

--progress-fd FD

Escribe el progreso al descriptor de archivo especificado.

--purge[=BOOL]

Elimina la configuración modificada y los paquetes en caché. Habilita la eliminación de archivos de configuración modificados al desinstalar paquetes. En la acción de limpieza de caché, esto habilita la eliminación de paquetes en caché innecesarios (paquetes desinstalados en instalaciones tmpfs o todos los paquetes en instalaciones de disco).

--quiet, -q

Imprime menos información.

--repositories-file REPOFILE

Anula los repositorios del sistema, ver apk-repositories(5). La especificación de esta opción anula el procesamiento normal del archivo de repositorios y el directorio repositories.d. El REPOFILE dado es relativo al directorio de inicio desde apk 2.12.0_rc2.

--repository, -X REPO

Especifica un repositorio de paquetes adicional. Los comandos especificados en apk-repositories(5) no se analizan (use --repository-config para eso). Además, se aceptan rutas relativas y se interpretan como relativas al directorio de inicio.

--repository-config REPOCONFIG

Especifica una configuración de repositorio de paquetes adicional. El REPOCONFIG se analiza exactamente de la misma manera que si se hubiera leído de un archivo .list especificado en apk-repositories(5).

--root, -p ROOT

Gestiona el sistema de archivos en ROOT.

--root-tmpfs[=AUTO]

Especifica si ROOT es un sistema de archivos temporal. Por defecto es auto, que determina el tipo de sistema de archivos automáticamente.

Esto afecta a:

  • lectura y creación del índice 'installed' en la caché
  • eliminación de paquetes en la caché
  • comprobaciones de seguridad para no instalar paquetes que no pertenezcan al repositorio

--sync[=AUTO]

Determina si las cachés del sistema de archivos deben grabarse en disco. Por defecto es auto, que se resuelve a yes si no se especifica --root, la base de datos no está en modo de usuario y se ejecuta en el espacio de nombres de proceso raíz (no en contenedor).

--timeout TIME

Establece un tiempo de espera para las conexiones de red si no se produce ningún progreso en TIME segundos. El valor por defecto es 60 segundos.

--update-cache, -U

Alias de '--cache-max-age 0'.

--uvol-manager UVOL

Especifica la ubicación del ejecutable del gestor de volúmenes uvol de OpenWRT.

--verbose, -v

Imprime más información (se puede especificar dos veces).

--version, -V

Imprime la versión del programa y sale.

--wait TIME

Espera TIME segundos para obtener un bloqueo exclusivo del repositorio antes de fallar.

OPCIONES DE CONFIRMACIÓN

Las siguientes opciones están disponibles para todos los comandos que confirman la base de datos.

--clean-protected[=BOOL]

Si se deshabilita, evita la creación de archivos .apk-new en directorios de configuración.

--commit-hooks[=BOOL]

Si se deshabilita, omite los scripts de gancho pre/post (pero no otros scripts).

--initramfs-diskless-boot

Utilizado por initramfs al recrear el root tmpfs. Esto habilita opciones de fuerza seleccionadas para minimizar fallos, y deshabilita los ganchos de confirmación, entre otras características.

--overlay-from-stdin

Lee la lista de archivos superpuestos desde stdin. Normalmente, esto se usa solo durante initramfs al arrancar una instalación run-from-tmpfs.

--scripts[=BOOL]

Si se deshabilita, evita la ejecución de todos los scripts. Útil para extraer una imagen del sistema para una arquitectura diferente en un ROOT alternativo.

--simulate[=BOOL], -s

Simula la operación solicitada sin realizar ningún cambio. La base de datos se abre en modo de solo lectura y se deshabilita la actualización automática de los índices. Es posible que desee ejecutar "apk update" antes de ejecutar una simulación para asegurarse de que se realiza con índices de repositorio actualizados.

OPCIONES DE GENERACIÓN

Las siguientes opciones están disponibles para todos los comandos que generan archivos APKv3.

--compression, -C ALGORITHM[:LEVEL]

Comprime el archivo con el ALGORITHM y LEVEL dados. Algoritmos soportados:
  • none
  • deflate (nivel 1-9)
  • zstd (nivel 1-22)

--sign-key KEYFILE

Firma el archivo con una clave privada en el KEYFILE especificado.

ENTORNO

APK_CONFIG

Anula el nombre del archivo de configuración por defecto. Ver /etc/apk/config

LANG

Se utiliza para determinar si UTF-8 es compatible y establecer el carácter de progreso por defecto en consecuencia.

SOURCE_DATE_EPOCH

Ver apk-index(8).

TERM

Se utiliza para determinar si la terminal es tonta o no. La barra de progreso no se habilita en terminales tontas por defecto.

Variables para configurar libfetch integrado

FETCH_BIND_ADDRESS

Una dirección IP local a la que libfetch enlazará todos los sockets que cree. Puede ser útil para el enrutamiento de origen.

NETRC

Especifica el archivo .netrc a leer para secretos de autenticación. Si no se establece, por defecto es $HOME/.netrc.

HTTP_AUTH
HTTP_REFERER
HTTP_USER_AGENT

Especifica un encabezado de autorización, referer o agente de usuario de nivel HTTP personalizado.

HTTP_PROXY, http_proxy
HTTPS_PROXY, https_proxy
Si se establecen, estas variables deben contener la URL del proxy para conexiones http

y https respectivamente.

HTTP_PROXY_AUTH

Especifica un encabezado Proxy-Authorization de HTTP. Solo se utiliza si la conexión se establece a través de un proxy HTTP configurado.

NO_PROXY, no_proxy

Lista separada por comas de extensiones de dominio o direcciones IP en notación CIDR para las cuales *no* se debe usar un proxy. Esto se utiliza explícitamente para comparar solo la parte del nombre de host de la URL. Es decir, especificar una dirección IP o un bloque CIDR no coincidirá con un nombre DNS que se resuelva a la dirección IP.

SSL_CLIENT_CERT_FILE
SSL_CLIENT_KEY_FILE

Anula el nombre del archivo predeterminado del certificado de cliente SSL y la clave privada correspondiente.

SSL_NO_VERIFY_HOSTNAME

Si se establece en cualquier valor, deshabilita la verificación del nombre del certificado del servidor.

Entorno para los scripts que APK ejecuta

Entorno para los scripts que ejecuta APK

Normalmente apk ejecutará scripts con un entorno saneado y mínimo que contiene solo PATH PATH. Véase también --preserve-env para pasar variables de entorno adicionales.

Antes de ejecutar un script, apk establecerá el directorio de trabajo como ROOT y realizará un chroot a menos que se especifique --force-no-chroot . En ambos casos, el directorio de trabajo del script debe tratarse como la raíz del sistema.

Las variables de entorno definidas por APK son las siguientes:

APK_PACKAGE

Nombre del paquete (solo scripts de paquetes).

APK_SCRIPT

Se establece en uno de los tipos de scripts de paquete o de commit. Utilice esto para determinar el tipo de gancho del script si es necesario. El nombre de archivo ($0) no es fiable ya que apk prefiere ejecutar los scripts de paquete desde un archivo memfd.

FILES

Archivos de configuración

/etc/apk/config
/lib/apk/config

Opciones globales predeterminadas. Solo se lee y analiza el primer archivo existente en la lista anterior. El archivo en /lib está destinado a ser para las opciones predeterminadas de la distribución, que pueden ser luego anuladas por el usuario con el archivo en /etc. Véase también APK_CONFIG variable de entorno.

Un archivo de configuración contiene una opción larga por línea. Por ejemplo:

no-cache
timeout 120

/etc/apk/interactive

Si este archivo existe, por defecto --interactive será auto.

Archivos de configuración (relativos a --root)

/etc/apk/arch

La arquitectura de CPU para esta base de datos. Véase apk-package(5) sección sobre el campo de metadatos del paquete arch para la lista.

/etc/apk/cache

Se espera que sea un enlace simbólico al directorio que apk usará como caché de paquetes. Véase también apk-cache(5) y apk-cache(8).

/etc/apk/commit_hooks.d/*
/lib/apk/commit_hooks.d/*

Scripts de gancho que se ejecutan antes de que se haya escrito nada en el sistema de archivos y después de que todos los cambios se hayan confirmado. Al script ejecutado se le pasa como argumento el nombre de la etapa (pre-commit o post-commit). Si el script devuelve un fallo durante la etapa pre-commit , la confirmación se aborta.

Véase también la sección ENTORNO para las variables de entorno.

Si se especifica la opción --no-scripts o --no-commit-hooks , estos scripts de gancho no se ejecutarán.

/etc/apk/keys
/lib/apk/keys

Directorios para claves de firma de confianza. Los directorios se enumeran en el orden mencionado anteriormente. Una vez que se ve un nombre de archivo dado, cualquier archivo del mismo nombre en directorios posteriores se ignora.

/etc/apk/protected_paths.d/*.list

Archivos de configuración para especificar cómo tratar los cambios en máscaras de directorios o archivos especificados. El formato del archivo está documentado más a fondo en apk-protected_paths(5).

/etc/apk/repositories
/etc/apk/repositories.d/*.list
/lib/apk/repositories.d/*.list

Archivos de configuración para especificar repositorios. Los directorios se enumeran en el orden mencionado anteriormente. Una vez que se ve un nombre de archivo dado, cualquier archivo del mismo nombre en directorios posteriores se ignora. Véase apk-repositories(5) para más detalles.

/etc/apk/world

Requisitos y restricciones de nivel superior sobre lo que debe instalarse. Véase apk-world(5) para más detalles.

Archivos de configuración para libfetch integrado

/etc/apk/ca.pem

Paquete de almacén de certificados CA para verificar certificados del servidor. Si no está presente, se usa el almacén CA del sistema predeterminado.

/etc/apk/crl.pem

Almacén CRL contra el que comprobar los certificados del servidor.

/etc/apk/cert.key

Clave privada del certificado del cliente.

/etc/apk/cert.pem

Certificado del cliente a usar para la autenticación.

Archivos del sistema

/lib/apk/db/lock

Un archivo de bloqueo utilizado para permitir solo una transacción de escritura concurrente en el sistema.

/lib/apk/db/installed

Base de datos de paquetes instalados y su contenido.

/lib/apk/db/scripts.tar
/lib/apk/db/scripts.tar.gz

Colección de todos los scripts de paquetes de los paquetes actualmente instalados.

/lib/apk/db/triggers

Lista de reglas de ganchos para los paquetes actualmente instalados.

/lib/apk/db-uvol

Enlace simbólico de la base de datos o un directorio con una estructura similar a /lib/apk/db/, pero que se usa para el contenido del paquete cuando se gestiona usando el gestor de volúmenes uvol de OpenWRT.

/lib/apk/exec

Directorio temporal para la extracción y ejecución de scripts de paquetes y ganchos.

/var/log/apk.log

Archivo de registro de los cambios realizados en el sistema.
