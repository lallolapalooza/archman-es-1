PROTOCOL

O

Hay dos protocolos en uso por ampctld, el Protocolo Predeterminado y el Protocolo de Respuesta

Extendida.

El Protocolo Predeterminado está destinado principalmente para la comunicación entre las funciones de la biblioteca Hamlib y ampctld (“NET ampctl”, disponible usando el modelo de amplificador ‘2’)

.

El Protocolo de Respuesta Extendida está destinado a ser usado con scripts u otros programas que interactúen directamente con ampctld ya que se proporciona una retroalimentación

consistente.

Protocolo

Predeterminado

El Protocolo Predeterminado es intencionalmente simple. Los comandos se ingresan en una sola línea con cualquier valor necesario. En la práctica, se obtienen resultados confiables terminando cada cadena de comando con un carácter de nueva línea,

‘\n’.

Ejemplo de comandos para establecer frecuencia y modo (código Perl (texto escrito en negrita))

: 


print $socket "F 14250000\n";
print $socket "\\set_powerstat 1\n"; # escape leading
'\'

Se enviará una respuesta de una línea como respuesta a comandos set, “RPRT x\n” donde x es el código de error de Hamlib con ‘0’ indicando éxito del

comando.

Las respuestas de ampctld comandos get son valores de texto y coinciden con los mismos tokens usados en los comandos set. Cada valor se devuelve en su propia línea. En caso de error se devuelve la cadena “RPRT x\n” donde x es el código de error de

Hamlib.

Ejemplo de obtención de frecuencia (código Perl)

: 


print $socket "f\n";
"14250000\n"

La mayoría de las funciones get devuelven de uno a tres valores. Una excepción notable es el comando dump_caps que devuelve muchas líneas de pares clave:valor

.

Este protocolo es utilizado principalmente por el backend “NET ampctl” (ampctl modelo 2) que permite a las aplicaciones ya escritas para la API C de Hamlib aprovechar ampctld sin la necesidad de reescribir el código de la aplicación. Un usuario de una aplicación puede seleccionar el modelo de amplificador 2 (“NET ampctl”) y luego establecer amp_pathname a “localhost:4531” u otro host de red:puerto (establecido por las -T/-t opciones, respec

tivamente
, arriba).

Protocolo de Respuesta

Extendida

El protocolo de Respuesta Extendida agrega varias reglas a las cadenas devueltas por ampctld y agrega una regla para la sintaxis del

comando.

1. El comando recibido por ampctld se ecoa con su nombre de comando largo seguido del(los) valor(es) (si los hay) recibidos del cliente terminado por el separador de respuesta especificado como el primer registro de la

respuesta.

2. El último registro de cada bloque es la cadena “RPRT x\n” donde x es el valor de retorno numérico de la función del backend de Hamlib que fue llamada por el

comando.

3. Cualquier registro que consista en valores de datos devueltos por el backend del amplificador es precedido por una cadena seguida inmediatamente por dos puntos, luego un espacio y luego el valor terminado por el separador de respuesta. p. ej. “Frequency: 14250000\n” cuando el comando fue precedido por

‘+’.

4. Todos los comandos recibidos serán reconocidos por ampctld con registros de las reglas 1 y 2. Los registros de la regla 3 solo se devuelven cuando se deben devolver valores de datos al

cliente.

Un ejemplo de respuesta a un comando set_frequency enviado desde el prompt de shell (note el ‘+’ precedido)

: 


$ echo "+F 14250000" | nc -w 1 localhost 4531
set_freq: 14250000
RPRT
0

En este caso, el nombre largo del comando y los valores se devuelven en la primera línea y la segunda línea contiene el marcador de fin de bloque y el valor de retorno numérico del backend del amplificador que indica

éxito.

Un ejemplo de respuesta a una consulta get

_freq: 


$ echo "+\get_freq" | nc -w 1 localhost 4531
get_freq:
Frequency(Hz): 14250000
RPRT
0
Nota: El ‘\’ sigue siendo necesario para el nombre
del comando largo in
cluso con el carácter ERP.

En este caso, como no se pasa ningún valor a ampctld, la primera línea consiste solo en el nombre largo del comando. La última línea muestra que el comando fue procesado exitosamente por el backend del

amplificador.

Invocar el Protocolo de Respuesta Extendida requiere anteponer a un comando un carácter de puntuación. Como se muestra en los ejemplos arriba, anteponer un carácter ‘+’ al comando resulta en que las respuestas sean separadas por un carácter de nueva línea (‘\n’). Cualquier otro carácter de puntuación reconocido por la función C ispunct() excepto ‘\’, ‘?’, o ‘_’ hará que ese carácter se convierta en el separador de respuesta y toda la respuesta estará en una sola

línea.

DIAGNÓSTICO

S

La -v, --verbose opción permite que se emitan diferentes niveles de diagnósticos a stderr y corresponden a -v para BUG, -vv para ERR, -vvv para WARN, -vvvv para VERBOSE, o -vvvvv para TRACE

.

Un nivel de verbosidad dado es útil para proporcionar la información de depuración necesaria a la dirección de correo electrónico a continuación. Por ejemplo, la salida TRACE muestra todos de los valores enviados a y recibidos del amplificador, lo cual es muy útil para el desarrollo de la biblioteca del backend del amplificador y puede ser solicitado por los

desarrolladores
.

SEGURIDA

D

No hay autenticación alguna; NO deje este puerto TCP abierto al público en Internet. Por favor, pregunte si se necesita una seguridad más fuerte o considere usar un túnel de Shell Seguro (ssh(1))

.

Dado que ampctld no necesita ningún permiso mayor que ampctl, es aconsejable no iniciar ampctld como “root” o con otra cuenta de usuario d

el sistema para limitar cu
alquier vulnerabilidad.

ERRORE

S

El demonio no se desengancha ni pasa a segundo plano por sí

mismo.

No hay método para salir del demonio, por lo que se debe usar el comando kill(1) para

terminarlo.

Múltiples clientes usando el demonio pueden experimentar contención con el amplificador

conectado.
