AMPCTL(1) Utilidades Hamlib AMPCTL(1)

NOMBRE

ampctl - controlar amplificadores de radio

SINOPSIS

ampctl [-hiIlLuV] [-m id] [-r dispositivo] [-s velocidad] [-t caracter] [-C parm=valor] [-v[-Z]] [comando|-]

DESCRIPCIÓN

Controla amplificadores de radio. ampctl acepta comandos de la línea de comandos, así como en modo interactivo si no se proporcionan en la línea de comandos.

Tenga en cuenta que Hamlib es software de nivel BETA. Si bien muchas bibliotecas de backend carecen de soporte completo para amplificadores, las funciones básicas suelen estar bien soportadas.

Por favor, informe de errores y proporcione comentarios en la dirección de correo electrónico indicada en la sección ERRORES a continuación. Se agradecen parches y mejoras de código enviados a la misma dirección.

OPCIONES

Este programa sigue la sintaxis habitual de línea de comandos de GNU. Las opciones cortas que toman un argumento pueden tener el valor inmediatamente después o separado por un espacio. Las opciones largas que comienzan con dos guiones (‘-’) requieren un ‘=’ entre la opción y cualquier argumento.

Aquí hay un resumen de las opciones compatibles:

-m, --modelo=id
Selecciona el número de modelo del amplificador.
Ver lista de modelos (use “ampctl -l”).
Nota: ampctl (o software de terceros que utilice la API C) utilizará el modelo de amplificador 2 para NET ampctl (comunicándose con ampctld).
-r, --archivo-amplificador=dispositivo
Usa dispositivo como el nombre del archivo del puerto conectado al amplificador.
A menudo un puerto serie, pero podría ser un adaptador USB a serie. Típicamente /dev/ttyS0, /dev/ttyS1, /dev/ttyUSB0, etc. en Linux, COM1, COM2, etc. en MS Windows. Las variantes BSD y Mac OS/X tienen sus propias designaciones. Consulte la documentación de su sistema.
-s, --velocidad-serie=velocidad
Establece la velocidad serie a velocidad baudios.
Utiliza la velocidad serie máxima de las capacidades del backend del amplificador (establecida por -m arriba) como valor predeterminado.
-t, --terminador-comando-envio=caracter
Cambia el caracter de terminación para el protocolo de texto al usar el comando send_cmd.
El valor predeterminado es ASCII CR (‘0x0D’). Los caracteres no imprimibles de ASCII se pueden proporcionar como el número ASCII en formato hexadecimal precedido por “0x”. Puede pasar una cadena vacía para no tener carácter de terminación. La cadena “-1” indica a ampctl que cambie al protocolo binario.
Por ejemplo, para especificar un terminador de comando para comandos de texto estilo Kenwood, pase “-t ';'” a ampctl. Ver EJEMPLO abajo.
-L, --mostrar-configuración
Lista todos los parámetros de configuración para el amplificador definido con -m arriba.
-C, --establecer-configuración=parm=valor[,parm=valor]
Establece el (los) parámetro(s) de configuración del amplificador, por ejemplo, stop_bits=2.
Utilice la opción -L anterior para obtener una lista de los parámetros de configuración para un número de modelo dado.
-u, --volcar-capacidades
Vuelca las capacidades para el amplificador definido con -m arriba y sale.
-l, --listar
Lista todos los números de modelo de amplificador definidos en Hamlib y sale.
La lista está ordenada por número de modelo.
Nota: En Linux, la lista se puede desplazarse hacia atrás usando Shift-PageUp/Shift-PageDown, o usando las barras de desplazamiento de un terminal virtual en X o la ventana de cmd en Windows. La salida se puede canalizar a more(1) o less(1), por ejemplo, “ampctl -l | more”.
-i, --leer-historial
Lee el historial de comandos y argumentos previamente guardado desde un archivo (predeterminado $HOME/.ampctl_history) para la sesión actual.
Disponible cuando ampctl está compilado con soporte Readline (ver READLINE abajo).
Nota: Para leer un archivo de historial almacenado en otro directorio, establezca la variable de entorno AMPCTL_HIST_DIR, por ejemplo, “AMPCTL_HIST_DIR=~/tmp ampctl -i”. Cuando AMPCTL_HIST_DIR no está configurado, se utiliza el valor de HOME.
-I, --guardar-historial
Escribe el historial de comandos y argumentos de la sesión actual (y de sesiones anteriores, si se proporciona la opción -i) en un archivo (predeterminado $HOME/.ampctl_history) al final de la sesión actual.
Los comandos completos con argumentos se guardan como una sola línea para ser recuperados y utilizados o editados. Disponible cuando ampctl está compilado con soporte Readline (ver READLINE abajo).
Nota: Para escribir un archivo de historial en otro directorio, establezca la variable de entorno AMPCTL_HIST_DIR, por ejemplo, “AMPCTL_HIST_DIR=~/tmp ampctl -IRq. Cuando AMPCTL_HIST_DIR no está configurado, se utiliza el valor de HOME.
-v, --verboso
Establece el modo verboso, acumulativo (ver DIAGNÓSTICOS abajo).
-Z, --sellos-tiempo-depuración
Habilita sellos de tiempo para los mensajes de depuración.
Úselo solo en combinación con la opción -v, ya que no genera salida por sí solo.
-h, --ayuda
Muestra un resumen de estas opciones y sale.
-V, --versión
Muestra la versión de ampctl y sale.
-
Detiene el procesamiento de opciones y lee comandos de la entrada estándar.
Ver Entrada Estándar abajo.

Nota: Algunas opciones pueden no estar implementadas por un backend determinado y devolverán un error. Esto es más probable que ocurra con las opciones --establecer-configuración y --mostrar-configuración.

Tenga en cuenta que el backend para el amplificador a controlar, o el amplificador en sí, puede no soportar algunos comandos. En ese caso, la operación fallará con un código de error de Hamlib.

COMANDOS

Los comandos se pueden introducir como un solo carácter o como un nombre de comando largo. Los comandos no van precedidos de un guion como las opciones. Se pueden escribir en modo interactivo o proporcionar como argumento(s) en modo de interfaz de línea de comandos. En modo interactivo, los comandos y sus argumentos se pueden introducir en una sola línea:


F 14250000

Dado que la mayoría de las operaciones de Hamlib tienen un método set y uno get, una letra mayúscula se usará a menudo para un método set, mientras que la letra minúscula correspondiente se refiere al método get. Cada operación también tiene un nombre largo; en modo interactivo, anteponga una barra invertida, ‘\’, para introducir un nombre de comando largo.

Ejemplo: Use “\volcar_capacidades” para ver qué capacidades soportan este amplificador y backend.

Nota: El backend para el amplificador a controlar, o el amplificador en sí, puede no soportar algunos comandos. En ese caso, la operación fallará con un mensaje de error de Hamlib.

ampctl Comandos

Se incluye un resumen de los comandos a continuación (En el caso de los comandos set, la cadena entrecomillada e itálica se reemplaza por el valor en la descripción. En el caso de los comandos get, la cadena entrecomillada e itálica es el nombre de la clave del valor devuelto):

Q|q, salir de ampctl
Sale de ampctl en modo interactivo.
Cuando ampctl está controlando el amplificador directamente, cerrará el backend y el puerto del amplificador. Cuando ampctl está conectado a ampctld (modelo de amplificador 2), la conexión TCP/IP a ampctld se cierra y ampctld permanece en ejecución, disponible para otra conexión de red TCP/IP.
F, set_freq 'Frecuencia'
Establece la 'Frecuencia', en Hz.
La frecuencia puede ser un valor de punto flotante o entero.
f, get_freq
Obtiene la 'Frecuencia', en Hz.
Devuelve un valor entero.
l, get_level 'Nivel'
Obtiene el 'Valor del Nivel'.
Devuelve el Valor del Nivel como un flotante o entero para el token de Nivel proporcionado.
Nota: Pasar un ‘?’ (consulta) como primer argumento en lugar de un token de Nivel devolverá una lista separada por espacios de los tokens de nivel de obtención compatibles con el backend del amplificador. Utilice esto para determinar los niveles admitidos de un backend de amplificador determinado.
w, send_cmd 'Cmd'
Envía una cadena de comando raw al amplificador.
Esto es útil para probar y depurar comandos y respuestas del amplificador al desarrollar un backend.
Para protocolos binarios, ingrese valores como \0xAA\0xBB. Espere una 'Respuesta' del amplificador que probablemente será un bloque binario o una cadena ASCII dependiendo del protocolo del amplificador (consulte la documentación de control por computadora de su amplificador).
El terminador de comando, establecido por la opción send-cmd-term anterior, terminará cada cadena de comando enviada al amplificador. Este carácter no debe formar parte de la cadena de entrada.
dump_state
Devuelve cierta información de estado sobre el backend del amplificador.
1, dump_caps
No es un comando remoto real del amplificador, simplemente vuelca las capacidades, es decir, lo que el backend sabe sobre este modelo y lo que puede hacer.
TODO: Asegurarse de que esto esté en un formato consistente para que pueda ser leído en un hash, diccionario, etc. Se solicitan informes de errores.
Nota: Este comando generará muchas líneas de salida, así que tenga mucho cuidado si usa un array de longitud fija. Por ejemplo, ejecutar este comando contra el backend Dummy resulta en una serie de líneas de salida de texto.
_, get_info
Devuelve información del backend del amplificador.
R, reset 'Reset'
Realiza el 'Reset' del amplificador.
El reinicio es un valor entero: ‘0’ = Ninguno, ‘1’ = Reinicio de memoria, ‘2’ = Reinicio de fallo, ‘3’ = Reinicio del amplificador.
set_powerstat 'Estado de Energía'
Establece el 'Estado de Energía'.
Estado de Energía es un valor entero: ‘0’ = Apagado, ‘1’ = Encendido, ‘2’ = En espera (entrar en modo de espera), ‘4’ = Operando (salir del modo de espera).
get_powerstat
Obtiene el 'Estado de Energía' como en set_powerstat anterior.
Y, set_ant 'Antena' 'Opción'
Establece la 'Antena' y la 'Opción'.
El número es el # de antena basado en 1 (‘1’, ‘2’, ‘3’, ...).

1 = A/1
2 = B/2
3 = C/3

READLINE

Si los archivos de desarrollo de la biblioteca Readline se encuentran en tiempo de configuración, ampctl se compilará condicionalmente con soporte de Readline para la entrada de comandos y argumentos. Las asignaciones de teclas de comandos de Readline están en sus valores predeterminados como se describe en el manual de Readline. ampctl establece el nombre “ampctl” que se puede usar en Construcciones de Inicialización Condicional en el Archivo de Inicialización de Readline ($HOME/.inputrc por defecto) para asignaciones de teclas personalizadas específicas de ampctl.

El historial de comandos está disponible con soporte de Readline como se describe en el manual de historial de Readline. Los comandos y las cadenas de argumentos se almacenan como líneas únicas incluso cuando se solicitan los argumentos de entrada individualmente. Los comandos y argumentos no se validan y se almacenan tal como se escribieron, con los valores separados por un solo espacio.

Normalmente, el historial de la sesión no se guarda; sin embargo, el uso de las opciones -i/--read-history o -I/--save-history al iniciar ampctl hará que se lea cualquier historial guardado previamente y/o se escriba el historial de la sesión actual y cualquier sesión anterior (suponiendo que se den las opciones -i y -I juntas) al cerrar ampctl. Cada opción es mutuamente excluyente, es decir, cualquiera de ellas se puede dar por separado o en combinación. Esto es útil para guardar un conjunto de comandos y luego leerlos más tarde, pero sin escribir el historial modificado para un conjunto consistente de comandos de prueba en modo interactivo, por ejemplo.

El historial se almacena en $HOME/.ampctl_history por defecto, aunque el directorio de destino puede cambiarse estableciendo la variable de entorno AMPCTL_HIST_DIR. Cuando AMPCTL_HIST_DIR no está establecido, se utiliza el valor de la variable de entorno HOME en su lugar. Solo se puede cambiar el directorio de destino en este momento.

Si no se encuentra soporte de Readline en tiempo de configuración, se utiliza el controlador de comandos interno original. Readline no se utiliza para los comandos de ampctl introducidos en la línea de comandos, independientemente de si el soporte de Readline está incorporado o no.

Nota: El soporte de Readline no está incluido en las compilaciones binarias para MS Windows de 32 o 64 bits proporcionadas por el Proyecto Hamlib. Ejecutar ampctl en la plataforma MS Windows en la shell ‘cmd’ proporciona historial de línea de comandos de la sesión, sin embargo, no se guarda en disco entre sesiones.

DIAGNÓSTICOS

La opción -v, --verbose permite diferentes niveles de diagnósticos que se emiten a stderr y corresponden a -v para BUG, -vv para ERR, -vvv para WARN, -vvvv para VERBOSE, o -vvvvv para TRACE.

Un nivel de verbosidad dado es útil para proporcionar la información de depuración necesaria a la dirección de correo electrónico a continuación. Por ejemplo, la salida TRACE muestra todos los valores enviados y recibidos del amplificador, lo cual es muy útil para el desarrollo de bibliotecas de backend de amplificadores y puede ser solicitado por los desarrolladores.

ESTADO DE SALIDA

ampctl sale con:

0
si todas las operaciones se completaron normalmente;
1
si hubo una opción o argumento de línea de comandos inválido;
2
si Hamlib devolvió un error.

EJEMPLOS

Inicie ampctl para un Elecraft KPA-1500 usando un adaptador USB a serie en Linux en modo interactivo:


$ ampctl -m 201 -r /dev/ttyUSB1

Inicie ampctl para un Elecraft KPA-1500 usando COM1 en MS Windows mientras genera salida TRACE a stderr:


> ampctl -m 201 -r COM1 -vvvvv

Conéctese a un ampctld en ejecución con el modelo de amplificador 2 (“NET ampctl”) en el host local y especifique el puerto TCP, estableciendo la frecuencia y el modo:


$ ampctl -m 2 -r localhost:4531 F 7253500
