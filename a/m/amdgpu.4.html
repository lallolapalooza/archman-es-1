AMDGPU(4) Manual de controladores de dispositivos AMDGPU(4)

NOMBRE

amdgpu - controlador de vídeo para GPU AMD RADEON

SINOPSIS

Sección "Device"
  Identifier "devname"
  Driver "amdgpu"
...
EndSection

DESCRIPCIÓN

amdgpu es un controlador de Xorg para tarjetas de vídeo basadas en AMD RADEON con las siguientes características:

•
Soporte para profundidades de píxel de 8, 15, 16, 24 y 30 bits;
•
Soporte de RandR hasta la versión 1.4;
•
Aceleración 3D;

HARDWARE SOPORTADO

El controlador amdgpu soporta tarjetas de vídeo de las familias SI y posteriores.

DETALLES DE CONFIGURACIÓN

Consulte xorg.conf(5) para detalles generales de configuración. Esta sección solo cubre detalles de configuración específicos de este controlador.

Se admiten las siguientes Opciones del controlador:

Option "SWcursor" "boolean"
Selecciona el cursor por software.
El valor por defecto es off.
Option "Accel" "boolean"
Habilita o deshabilita toda la aceleración por hardware.
El valor por defecto es on.
Option "ZaphodHeads" "string"
Especifica la(s) salida(s) de RandR a usar con el modo zaphod para una instancia particular del controlador. Si usa esta opción, debe usarla para todas las instancias del controlador.
Por ejemplo: Option "ZaphodHeads" "LVDS,VGA-0" asignará las salidas xrandr LVDS y VGA-0 a esta instancia del controlador.
Option "DRI" "integer"
Define el nivel máximo de DRI a habilitar. Los valores válidos son 2 para DRI2 o 3 para DRI3. El valor por defecto es 3 para DRI3 si la versión de Xorg es >= 1.18.3, de lo contrario 2 para DRI2.
Option "EnablePageFlip" "boolean"
Habilita el cambio de página (page flipping) de DRI2.
El valor por defecto es on.
Option "TearFree" "boolean"
Establece el valor por defecto de la propiedad 'TearFree' por salida, que controla la prevención de desgarros (tearing) usando el mecanismo de cambio de página por hardware. TearFree está activado para cualquier CRTC asociado con una o más salidas con TearFree activado. Se necesitan asignar dos búferes de exploración separados para cada CRTC con TearFree activado. Si se establece esta opción, el valor por defecto de la propiedad será 'on' u 'off' en consecuencia. Si no se establece esta opción, el valor por defecto de la propiedad es auto, lo que significa que TearFree está activado para salidas rotadas, salidas con transformaciones RandR aplicadas, para salidas secundarias de RandR 1.4, y si 'VariableRefresh' está habilitado; de lo contrario, está desactivado.
Option "VariableRefresh" "boolean"
Habilita el soporte para activar la frecuencia variable en los CRTCs de la pantalla cuando una aplicación adecuada está haciendo flip a través de la extensión Present.
El valor por defecto es off.
Option "AsyncFlipSecondaries" "boolean"
Usa flips asíncronos para las salidas de vídeo secundarias en configuraciones de múltiples pantallas. Si una pantalla tiene múltiples monitores conectados y se usa el cambio de página de DRI3, entonces solo uno de los monitores tendrá su cambio de página sincronizado con el vblank para una presentación sin desgarros. Este es el monitor que se usa para la sincronización y marca de tiempo de la presentación, generalmente el que cubre el área de píxeles más grande de la pantalla. Todos los otros monitores ("Secundarios") no sincronizarán sus cambios. Esto puede causar algunos desgarros en estos monitores, pero previene una ralentización permanente o periódica o un molesto temblor de las animaciones si no todas las salidas de vídeo están funcionando sincronizadas entre sí y con la misma frecuencia de actualización. No hay una solución perfecta aparte de salidas perfectamente sincronizadas, pero esta opción puede dar resultados preferibles si los monitores en una configuración de múltiples pantallas reflejan o clonan entre sí.
El valor por defecto es off.
Option "AccelMethod" "string"
Establecer esta opción en none deshabilita el uso de la arquitectura de aceleración glamor. En ese caso, todo el renderizado 2D lo realiza la CPU, pero la aceleración por hardware de 3D y vídeo puede seguir funcionando. Esto es principalmente útil para el desarrollo de controladores OpenGL.
El valor por defecto es usar glamor.

Se admite la siguiente Opción del controlador para glamor:

Option "ShadowPrimary" "boolean"
Esta opción habilita un búfer llamado "shadow primary" para un acceso rápido de la CPU a los datos de píxeles, y búferes de exploración separados para cada controlador de pantalla (CRTC). Esto puede mejorar el rendimiento para algunas cargas de trabajo 2D, potencialmente a expensas de otras cargas de trabajo (por ejemplo, 3D, vídeo). Tenga en cuenta particularmente que habilitar esta opción actualmente deshabilita el cambio de página.
El valor por defecto es off.
