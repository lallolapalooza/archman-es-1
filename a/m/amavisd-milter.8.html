NOMBRE

amavisd-milter - milter de sendmail para amavis

SINOPSIS

amavisd-milter [-Bfhv] [-d nivel-debug] [-D entrega-a-traves-de] [-m max-conexiones] [-M max-espera] [-p archivo-pid] [-P] [-q cola] [-s socket] [-t tiempo-espera] [-S socket] [-T tiempo-espera] [-w directorio]

DESCRIPCIÓN

El amavisd-milter es un milter (filtro de correo) de sendmail para amavis 2.4.3 y superior y sendmail 8.13 y superior.

Con el amavisd-milter, está disponible toda la funcionalidad de amavis, incluyendo la adición de campos de encabezado con información de spam y virus, la modificación del asunto, la adición de extensiones de dirección y la eliminación de ciertos destinatarios de la entrega, al tiempo que se entrega el mismo mensaje al resto.

Para más información puede visitar el sitio web de amavisd-milter:

https://github.com/prehor/amavisd-milter

Opciones

Las opciones son las siguientes:

-B
Utiliza la macro milter {daemon_name} como nombre del banco de políticas (ver BANCOS DE POLÍTICAS más abajo).
-d nivel-debug
Establece el nivel de depuración. Los rastreos de depuración se vuelven más detallados a medida que aumenta el nivel de depuración. El máximo es 9.
-D entrega-a-traves-de
Establece el atributo de solicitud de AM.PDP delivery_care_of a client (por defecto) o server.

Cuando se utiliza el método client, el amavisd-milter es responsable de reenviar el mensaje a los destinatarios. Este método no permite la modificación personalizada de encabezados o cuerpos.

Cuando se utiliza el método server, amavis es responsable de reenviar el mensaje a los destinatarios y puede personalizar los encabezados y el cuerpo de los mensajes. La variable $forward_method en amavisd.conf debe apuntar a un lugar que esté dispuesto a aceptar el mensaje sin más comprobaciones en amavis.

-f
Ejecuta amavisd-milter en primer plano (es decir, no se demoniza). Imprime mensajes de depuración en la terminal.
-h
Imprime la página de ayuda y sale.
-m max-conexiones
Máximo de conexiones concurrentes de amavis (por defecto 0 = número ilimitado de conexiones). Debe ser el mismo que la variable $max_servers en amavisd.conf.
-M tiempo-espera
Tiempo de espera para el procesamiento del mensaje en segundos (por defecto 300 segundos = 5 minutos). Debe ser menor que el tiempo de espera para una respuesta al punto final (.) que termina un mensaje en el MTA de envío. Sendmail usa el valor por defecto de 1 hora, postfix 10 minutos y qmail 20 minutos. El valor recomendado es inferior a 10 minutos.

Si utiliza otros milters (especialmente los que consumen mucho tiempo), el tiempo de espera debe ser suficiente para procesar el mensaje en todos los milters.

-p archivo-pid
Utiliza este archivo pid.
-P
Cuando amavis falle, el mensaje se pasará sin ser verificado.
-q cola
Establece la cola de socket entrante utilizada por listen(2). Si no se establece o se establece en cero, se utiliza el valor predeterminado del sistema operativo.
-s socket
Socket de comunicación entre sendmail y amavisd-milter. El protocolo que se habla a través de este socket es MILTER (Mail FILTER). Debe tener el mismo valor que la macro INPUT_MAIL_FILTER en sendmail.mc.

El socket debe tener el formato proto:dirección:

•
{unix|local}:/ruta/al/archivo - Una tubería con nombre.
•
inet:puerto@{nombre-host|dirección-ip} - Un socket IPV4.
•
inet6:puerto@{nombre-host|dirección-ip} - Un socket IPV6.
-S socket
Socket de comunicación entre amavisd-milter y amavis. El protocolo que se habla a través de este socket es AM.PDP (AMavis Policy Delegation Protocol). Debe tener el mismo valor que la variable $unix_socketname en amavisd.conf.

El socket debe tener el formato proto:dirección:

•
{unix|local}:/ruta/al/archivo - Una tubería con nombre.
•
inet:puerto@{nombre-host|dirección-ip} - Un socket IPV4.
•
inet6:puerto@{nombre-host|dirección-ip} - Un socket IPV6.
-t tiempo-espera
Tiempo de espera de la conexión de sendmail en segundos (por defecto 600 = 10 minutos). Debe tener el mismo valor que la macro INPUT_MAIL_FILTER en sendmail.mc y debe ser mayor o igual que el tiempo de espera de la conexión de amavis.

Si utiliza otros milters (especialmente los que consumen mucho tiempo), el tiempo de espera debe ser suficiente para procesar el mensaje en todos los milters.

-T tiempo-espera
Tiempo de espera de la conexión de amavis en segundos (por defecto 600 = 10 minutos). Debe ser suficiente para procesar el mensaje en amavis. Normalmente, es una buena idea establecerlos al mismo valor que el tiempo de espera de la conexión de sendmail.
-v
Reporta el número de versión y sale.
-w directorio
Establece el directorio de trabajo.

BANCOS DE POLÍTICAS

Si la opción -B está activada, amavisd-milter utiliza el valor de la macro milter {daemon_name} como el nombre del banco de políticas de amavis. Normalmente, esta macro milter se establece con el nombre del MTA.

Cuando un cliente remoto es autenticado, amavisd-milter utiliza la información de autenticación como el nombre de los bancos de políticas de amavis:

SMTP_AUTH
El cliente remoto ha sido autenticado.
SMTP_AUTH_<MECH>
El mecanismo de autenticación del cliente remoto.
SMTP_AUTH_<MECH>_<BITS>
El número de bits utilizados para la clave del cifrado simétrico cuando el mecanismo de autenticación lo utiliza.

EJEMPLOS

Configuración de amavis

En el archivo amavisd.conf establezca el protocolo y el socket de amavis a:

$protocol = "AM.PDP";                      # Usar protocolo AM.PDP
$unix_socketname = "$MYHOME/amavisd.sock"; # Escuchar en socket Unix
### $inet_socket_port = 10024;             # No escuchar en puerto TCP

Luego reinicie el demonio amavisd.

Configuración de Postfix

Añada las siguientes entradas a Postfix main.cf*:

smtpd_milters = local:<AMAVISD_MILTER.SOCK>
milter_connect_macros = j {client_name} {daemon_name} v
milter_protocol = 6

Luego reinicie el demonio Postfix.

Configuración de sendmail

Añada las siguientes entradas al archivo sendmail.mc:

define(`confMILTER_MACROS_CONNECT',
  confMILTER_MACROS_CONNECT`, {client_resolve}')
define(`confMILTER_MACROS_ENVFROM',
  confMILTER_MACROS_ENVFROM`, r, b')
INPUT_MAIL_FILTER(`amavisd-milter',
  `S=local:<AMAVISD_MILTER.SOCK>, F=T, T=S:10m;R:10m;E:10m')

Luego reconstruya el archivo sendmail.cf, instálelo y reinicie el demonio sendmail.

Ejecutando amavisd-milter

Este ejemplo asume que amavis se está ejecutando como el usuario vscan. El nombre real se muestra en la variable $daemon_user en amavisd.conf.

Limitando la máxima cantidad de conexiones concurrentes a amavisd

Para limitar la máxima cantidad de conexiones concurrentes a amavis, ejecute amavisd-milter con estas opciones:

su - vscan -c "amavisd-milter -m 4"

Solución de problemas

Para solucionar problemas, ejecute amavisd-milter en primer plano y establezca el nivel de depuración al valor apropiado:

su - vscan -c "amavisd-milter -f -d 4"

Los niveles de depuración son:

•
1 - No son errores, sino estados inesperados (abortación de conexión, etc.).
•
2 - Estados principales en el procesamiento de mensajes.
•
3 - Todos los mensajes de depuración de amavisd-milter.
•
4-9 - Depuración de la comunicación milter (establezca smfi_setdbg a 1-6).
