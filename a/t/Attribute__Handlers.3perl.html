DESCRIPCIÓ

N

Este módulo, cuando es heredado por un paquete, permite que la clase de ese paquete defina subrutinas manejadoras de atributos para atributos específicos. A las variables y subrutinas definidas posteriormente en ese paquete, o en paquetes derivados de ese paquete, se les pueden asignar atributos con los mismos nombres que las subrutinas manejadoras de atributos, las cuales serán entonces llamadas en una de las fases de compilación (es decir, en un bloque "BEGIN", "CHECK", "INIT" o "END"). (Los bloques "UNITCHECK" no corresponden a una fase de compilación global, por lo que no se pueden especificar aquí.

)

Para crear un manejador, definirlo como una subrutina con el mismo nombre que el atributo deseado, y declarar la subrutina en sí misma con el atributo ":ATTR". Por

ejemplo: 
package LoudDecl;
use Attribute::Handlers;
sub Loud :ATTR {
    my ($package, $symbol, $referent, $attr, $data, $phase,
        $filename, $linenum) = @_;
    print STDERR
        ref($referent), " ",
        *{$symbol}{NAME}, " ",
        "($referent) ", "fue declarada ",
        "y se le atribuyó el atributo ${attr} ",
        "con datos ($data)\n",
        "en la fase $phase\n",
        "en el archivo $filename en la línea $linenum\n";
}

Esto crea un manejador para el atributo ":Loud" en la clase LoudDecl. A partir de ahí, cualquier subrutina declarada con un atributo ":Loud" en la clase

LoudDecl: 
package LoudDecl;
sub foo: Loud {...
}

hace que se invoque el manejador anterior, y se le

pasan:
[0
]
el nombre del paquete en el que fue
declarada;
[1
]
una referencia a la entrada de la tabla de símbolos (typeglob) que contiene la
subrutina;
[2
]
una referencia a la
subrutina;
[3
]
el nombre del
atributo;
[4
]
cualquier dato asociado con ese
atributo;
[5
]
el nombre de la fase en la que se está invocando el
manejador;
[6
]
el nombre del archivo en el que se está invocando el
manejador;
[7
]
el número de
línea en e
ste archivo.

Del mismo modo, declarar cualquier variable con el atributo ":Loud" dentro del

paquete: 
package LoudDecl;
my $foo :Loud;
my @foo :Loud;
my %foo :
Loud;

hará que se llame al manejador con una lista de argumentos similar (excepto, por supuesto, que $_[2] será una referencia a la variable)

.

El argumento del nombre del paquete será típicamente el nombre de la clase en la que fue declarada la subrutina, pero también puede ser el nombre de una clase derivada (ya que los manejadores se heredan)

.

Si a una variable léxica se le asigna un atributo, no hay una tabla de símbolos a la que pertenezca, por lo que el argumento de la tabla de símbolos ($_[1]) se establece en la cadena 'LEXICAL' en ese caso. Del mismo modo, asignar un atributo a una subrutina anónima resulta en un argumento de la tabla de símbolos de 'ANON'

.

El argumento de datos pasa el valor (si lo hay) asociado con el atributo. Por ejemplo, si &foo hubiera sido

declarada: 
sub foo :Loud("sube el volumen a 11, tío!") {...
}

entonces se pasaría una referencia a un arreglo que contiene la cadena "sube el volumen a 11, tío!" como el último

argumento.

Attribute::Handlers hace esfuerzos considerables para convertir el argumento de datos ($_[4]) a una forma utilizable antes de pasarlo al manejador (pero ver "Manejadores de atributos no interpretativos"). Si esos esfuerzos tienen éxito, los datos interpretados se pasan en una referencia a un arreglo; si fallan, los datos en bruto se pasan como una cadena. Por ejemplo, todas

estas: 
sub foo :Loud(till=>ears=>are=>bleeding) {...}
sub foo :Loud(qw/till ears are bleeding/) {...}
sub foo :Loud(qw/till, ears, are, bleeding/) {...}
sub foo :Loud(till,ears,are,bleeding) {...
}

hacen que se pase "['till','ears','are','bleeding']" como el argumento de datos del manejador. Mientras

que: 
sub foo :Loud(['till','ears','are','bleeding']) {...
}

hace que se pase "[ ['till','ears','are','bleeding'] ]"; la referencia a un arreglo especificada en los datos siendo pasada dentro de la referencia a un arreglo estándar que indica una interpretación

exitosa.

Sin embargo, si los datos no se pueden analizar como Perl válido, se pasan como una cadena sin interpretar. Por

ejemplo: 
sub foo :Loud(my,ears,are,bleeding) {...}
sub foo :Loud(qw/my ears are bleeding) {...
}

hacen que se pasen las cadenas 'my,ears,are,bleeding' y 'qw/my ears are bleeding' respectivamente como el argumento de

datos.

Si no se asocia ningún valor con el atributo, se pasa "un

def".

Léxicos

tipados

Independientemente del paquete en el que se declare, si a una variable léxica se le asigna un atributo, el manejador que se invoca es el que pertenece al paquete al que está tipada. Por ejemplo, las siguientes

declaraciones: 
package OtherClass;
my LoudDecl $loudobj : Loud;
my LoudDecl @loudobjs : Loud;
my LoudDecl %loudobjex :
Loud;

hacen que se invoque el manejador LoudDecl::Loud (incluso si OtherClass también define un manejador para los atributos ":Lo

ud"
).

Manejadores de atributos específicos de

tipo

Si se declara un manejador de atributos y se le da al especificador ":ATTR" el nombre de un tipo incorporado ("SCALAR", "ARRAY", "HASH" o "CODE"), el manejador solo se aplica a declaraciones de ese tipo. Por ejemplo, la siguiente

definición: 
package LoudDecl;
sub RealLoud :ATTR(SCALAR) { print "¡Auuuuugh!"
}

crea un manejador de atributos que se aplica solo a

escalares: 
package Painful;
use base LoudDecl;
my $metal : RealLoud;           # invoca &LoudDecl::RealLoud
my @metal : RealLoud;           # error: atributo desconocido
my %metal : RealLoud;           # error: atributo desconocido
sub metal : RealLoud {...}      # error: atributo
desconocido

Por supuesto, puedes declarar manejadores separados para estos tipos también (pero necesitarás especificar "no warnings 'redefine'" para hacerlo sin advertencias)

: 
package LoudDecl;
use Attribute::Handlers;
no warnings 'redefine';
sub RealLoud :ATTR(SCALAR) { print "¡Auuuuugh!" }

sub RealLoud :ATTR(ARRAY) { print "Urrrrrrrrrr!" }
sub RealLoud :ATTR(HASH) { print "Arrrrrgggghhhhhh!" }
sub RealLoud :ATTR(CODE) { croak "Real loud sub torpedoed"
}

También puedes indicar explícitamente que un único manejador está destinado a ser usado para todos los tipos de referentes

así: 
package LoudDecl;
use Attribute::Handlers;
sub SeriousLoud :ATTR(ANY) { warn "Hearing loss imminent"
}

(Es decir, ATTR(ANY) es un sinónimo de ":AT

TR"
).

Manejadores de atributos no

interpretativos

Ocasionalmente, los esfuerzos intensos que Attribute::Handlers hace para convertir el argumento de datos ($_[4]) a una forma utilizable antes de pasarlo al manejador se interponen en el

camino.

Puedes desactivar esa ansiedad por ayudar declarando un manejador de atributos con la palabra clave "RAWDATA". Por

ejemplo: 
sub Raw          : ATTR(RAWDATA) {...}
sub Nekkid       : ATTR(SCALAR,RAWDATA) {...}
sub Au::Naturale : ATTR(RAWDATA,ANY) {...
}

Entonces el manejador no hace absolutamente ningún intento de interpretar los datos que recibe y simplemente los pasa como una

cadena: 
my $power : Raw(1..10
0); # el mane
jador recibe "1..100"

Manejadores de atributos específicos de

fase

Por defecto, los manejadores de atributos se llaman al final de la fase de compilación (en un bloque "CHECK"). Esto parece ser óptimo en la mayoría de los casos porque la mayoría de las cosas que pueden ser definidas están definidas en ese punto, pero nada ha sido

ejecutado.

Sin embargo, es posible configurar manejadores de atributos que sean llamados en otros puntos de la compilación o ejecución del programa, declarando explícitamente la fase (o fases) en las que deseas que el manejador de atributos sea llamado. Por

ejemplo: 
sub Early    :ATTR(SCALAR,BEGIN) {...}
sub Normal   :ATTR(SCALAR,CHECK) {...}
sub Late     :ATTR(SCALAR,INIT) {...}
sub Final    :ATTR(SCALAR,END) {...}
sub Bookends :ATTR(SCALAR,BEGIN,END) {...
}

Como indica el último ejemplo, un manejador puede ser configurado para ser (re)llamado en dos o más fases. El nombre de la fase se pasa como el argumento final del

manejador.

Ten en cuenta que los manejadores de atributos que están programados para la fase "BEGIN" se manejan tan pronto como el atributo es detectado (es decir, antes de que cualquier bloque "BEGIN" definido posteri

ormente sea
ejecutado).

Atributos como interfaces de

"tie"

Los atributos proporcionan una excelente e intuitiva interfaz a través de la cual atar (tie) variables. Por

ejemplo: 
use Attribute::Handlers;
use Tie::Cycle;
sub UNIVERSAL::Cycle : ATTR(SCALAR) {
    my ($package, $symbol, $referent, $attr, $data, $phase) = @_;
    $data = [ $data ] unless ref $data eq 'ARRAY';
    tie $$referent, 'Tie::Cycle', $data;
}
# y a partir de entonces...
package main;
my $next : Cycle('A'..'Z');     # $next es ahora una variable atada
while (<>) {
    print $next;
}

Ten en cuenta que, debido a que el atributo "Cycle" recibe sus argumentos en la variable $data, si al atributo se le da una lista de argumentos, $data consistirá en una única referencia a un arreglo; de lo contrario, consistirá directamente en el único argumento. Dado que Tie::Cycle requiere que sus valores cíclicos se pasen como una referencia a un arreglo, esto significa que necesitamos envolver los argumentos que no son referencias a arreglos en un constructor de

arreglos: 
$data = [ $data ] unless ref $data eq
'ARRAY';

Sin embargo, típicamente, las cosas son al revés: la clase atable (tieable) espera sus argumentos como una lista aplanada, así que el atributo se ve

como: 
sub UNIVERSAL::Cycle : ATTR(SCALAR) {
    my ($package, $symbol, $referent, $attr, $data, $phase) = @_;
    my @data = ref $data eq 'ARRAY' ? @$data : $data;
    tie $$referent, 'Tie::Whatever', @data;
}

Este patrón de software es tan ampliamente aplicable que Attribute::Handlers proporciona una forma de automatizarlo: especificando 'autotie' en la sentencia "use Attribute::Handlers". Así, el ejemplo de ciclado podría escribirse también

así: 
use Attribute::Handlers autotie => { Cycle => 'Tie::Cycle' };
# y a partir de entonces...
package main;
my $next : Cycle(['A'..'Z']);     # $next es ahora una variable atada
while (<>) {
    print $next;
}

Ten en cuenta que ahora tenemos que pasar los valores cíclicos como una referencia a un arreglo, ya que el mecanismo "autotie" pasa a "tie" una lista de argumentos como una lista (como en el ejemplo de Tie::Whatever), no como una referencia a un arreglo (como en el ejemplo original de Tie::Cycle al comienzo de esta sección)

.

El argumento después de 'autotie' es una referencia a un hash en el cual cada clave es el nombre de un atributo a ser creado, y cada valor es la clase a la cual las variables a las que se les asigne ese atributo deben ser

atadas.

Ten en cuenta que ya no es necesario importar el módulo Tie::Cycle -- Attribute::Handlers se encarga de eso automáticamente. Incluso puedes pasar argumentos a la subrutina "import" del módulo, añadiéndolos al nombre de la clase. Por

ejemplo: 
use Attribute::Handlers
     autotie => { Dir => 'Tie::Dir qw(DIR_UNLINK)' }
;

Si el nombre del atributo no está calificado, el atributo se instala en el paquete actual. De lo contrario, se instala en el paquete del

calificador: 
package Here;
use Attribute::Handlers autotie => {
     Other::Good => Tie::SecureHash, # atributo tie instalado en Other::
             Bad => Tie::Taxes,      # atributo tie instalado en Here::
 UNIVERSAL::Ugly => Software::Patent # atributo tie instalado en todas partes
}
;

Los autoties se usan más comúnmente en el módulo al que realmente atan, y necesitan exportar sus atributos a cualquier módulo que los llame. Para facilitar esto, Attribute::Handlers reconoce una "pseudo-clase" especial -- "__CALLER__", que puede ser especificada como el calificador de un

atributo: 
package Tie::Me::Kangaroo::Down::Sport;
use Attribute::Handlers autotie =>
     { '__CALLER__::Roo' => __PACKAGE__ }
;

Esto causa que Attribute::Handlers defina el atributo "Roo" en el paquete que importa el módulo Tie::Me::Kangaroo::Down::

Sport.

Ten en cuenta que es importante poner entre comillas el identificador __CALLER__::Roo porque un error en perl 5.8 se negará a analizarlo y causará un error

desconocido.

Pasando el objeto atado a "tie

"

Ocasionalmente es importante pasar una referencia al objeto que está siendo atado a TIESCALAR, TIEHASH, etc. que lo

ata.

El mecanismo "autotie" soporta esto también. El siguiente

código: 
use Attribute::Handlers autotieref => { Selfish => Tie::Selfish };
my $var : Selfish(@args)
;

tiene el mismo efecto

que: 
tie my $var, 'Tie::Selfish',
@args;

Pero cuando "autotieref" es usado en lugar de "autotie"

: 
use Attribute::Handlers autotieref => { Selfish => Tie::Selfish };
my $var : Selfish(@args)
;

el efecto es pasar a la llamada "tie" una referencia extra a la variable que está siendo

atada: 
tie my $va
r, 'Tie::Se
lfish', \$v
ar, @args;

UTILIDAD

Este módulo ofrece una única función de utilidad, findsym

().
finds
ym 
my $symbol = Attribute::Handlers::findsym($package, $referent)
;

La función busca en la tabla de símbolos de $package el typeglob para $referent, que es una referencia a una variable o subrutina (SCALAR, ARRAY, HASH o CODE). Si encuentra el typeglob, lo devuelve. De lo contrario, devuelve undef. Ten en cuenta que "findsym" memoriza los typeglob que ha encontrado

previamente, por lo que las
llamadas posteriores con los
mismos argumentos de
berían ser mucho más rápidas.

DIAGNÓSTICO

S
"Bad attribute type: ATTR(%s)
"
Se especificó un manejador de atributos con un :ATTR(ref_type), pero el tipo de referente que estaba definido para manejar no era uno de los cinco permitidos: "SCALAR", "ARRAY", "HASH", "CODE" o "ANY
".
"Attribute handler %s doesn't handle %s
attributes"
Se definió un manejador para atributos del nombre especificado, pero no para el tipo de declaración especificado. Normalmente se encuentra al intentar aplicar un manejador de atributos "VAR" a una subrutina, o un manejador de atributos "SCALAR" a algún otro tipo de
variable.
"Declaration of %s attribute in package %s may clash with future reserved
word"
Se declaró un manejador para un atributo con un nombre todo en minúsculas. Un atributo con un nombre todo en minúsculas podría tener un significado para Perl mismo algún día, aunque la mayoría aún no lo tiene. Usa un nombre de atributo con mayúsculas y minúsculas, en su
lugar.
"Can't have two ATTR specifiers on one
subroutine"
Simplemente no se puede, ¿vale? En su lugar, pon todas las especificaciones juntas con comas entre ellas en una sola ATTR(especificación)
.
"Can't autotie a
%s"
Solo puedes declarar autoties para los tipos "SCALAR", "ARRAY" y "HASH". Son las únicas cosas (aparte de los typeglob -- que no se pueden declarar) que Perl puede asociar (tie)
.
"Internal error: %s symbol went
missing"
Algo está podrido en el estado del programa. Una subrutina con atributos dejó de existir entre el punto en que se declaró y el punto en el que su(s) manejador(es) de atributos habrían sido
llamados.
"Won't be able to apply END
handler"
Has definido un manejador END para un atribut
o que se está aplicando a una variable
léxica. Dado que la variable puede no estar di
sponible durante END, esto no sucederá.
