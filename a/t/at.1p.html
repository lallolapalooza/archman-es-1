This page is intended to document the common POSIX features of the `at' utility. Other features may be found in the man pages published by your specific system vendor.

NAME

at, batch, atq, atrm - execute commands at a later time

SYNOPSIS

#include <time.h>

at [-d] [-f input_file] [-m] [-q queue] [-t time_spec] [job...]

at [-c] [-t time_spec] [job...]

atq [-u]

atrm job...

batch

DESCRIPTION

The at utility is a command-line utility that schedules commands to be run at a specified time. The batch utility is similar to at, but it runs jobs when system load level permits.

The atq utility displays the user's pending job queue. The atrm utility removes jobs from the queue.

The at command reads commands from standard input or from the file specified by the -f option. These commands are scheduled to be executed at the time specified by the time_spec operand.

The format of the time_spec is described in the OPERANDS section.

The at utility submits the commands to the atd daemon, which executes them at the appropriate time. The atd daemon is typically started at system boot time and remains active, checking the pending job queue periodically.

The atq command displays the job number, the month, the day of the month, the time of day, and the queue for each job scheduled for the current user.

The atrm command removes the specified jobs from the queue. The jobs are identified by their job numbers as displayed by atq.

The batch utility reads commands from standard input and schedules them to be run when the system load level is less than a specified threshold. The default load threshold varies between systems, but it is typically 0.7.

OPTIONS

The at utility supports the following options:

-c
Used with a job number, this option prints the job's commands to standard output without removing them from the queue. This option is useful for viewing the contents of a job.
-d
Remove the specified jobs from the queue. This option is equivalent to using the atrm utility.
-f input_file
Read the job commands from the specified input_file instead of standard input. If input_file is a regular file, at reads from it. If input_file is a FIFO, at reads from it until it is closed.
-m
When the job completes, send a mail message to the user who submitted the job, even if there was no output from the job. By default, mail is only sent if there is output.
-q queue
Place the job in the specified queue. The default queue is `a'. Different queues may have different priorities or restrictions. The atd daemon is typically configured with different queues (e.g., `b', `c', etc.) for different purposes.
-t time_spec
Specifies the time at which the job should be run. The time_spec operand must be in the format `[[CC]YY]MMDDhhmm[.SS]', where:
[CC]YY
The century and two-digit year.
MM
The month (01-12).
DD
The day of the month (01-31).
hh
The hour (00-23).
mm
The minute (00-59).
[.SS]
Optional seconds (00-60). A value of 60 is allowed for leap seconds.

The -t option provides a standardized way to specify the time, independent of the various time formats that might be accepted by the default specification method.

The atq utility supports the following option:

-u
Display the job queue for all users, not just the current user. This option may require appropriate privileges.

OPERANDS

The operands for the at command specify the time at which the commands should be executed. The format is flexible and can include various combinations of times, dates, and relative expressions. Here are some examples:

now

       Execute the job immediately (or as soon as the system load permits).

midnight, noon, <am>, <pm

       Specify a time of day. For example, `midnight', `noon', `10:00am',
       `3:00pm'.

<hour>:

       Specify a time of day. For example, `08:00', `17:30'.

<month>

       Specify a month. For example, `Jan', `February'.

<day_of_week>

       Specify a day of the week. For example, `Mon', `Tuesday'.

<month> <day_number> [<year>]

       Specify a specific date. For example, `Jan 24', `February 14
       2024'.

<day_of_week> <month> <day_number> [<year>]

       Specify a specific day of the week and date. For example, `Mon
       Jan 24', `Tuesday February 14 2024'.

now + count time_units

       Specify a time relative to the current time. For example, `now + 1
       hour', `now + 3 days', `now + 1 week'. time_units can be
       `minutes', `hours', `days', `weeks', `months', `years'.

<time> next <day_of_week>

       Specify the next occurrence of a particular day of the week. For
       example, `10:00am next Friday'.

When a date and time are specified, the at command determines whether the specified time has already passed for the current day. If it has, the job is scheduled for the same time on the next day (or the next occurrence of the specified day of the week).

The job operands for atrm and -c are job identifiers, which are typically integers assigned by the atd daemon.

STDIN

The standard input to at is the set of commands to be executed. If the -f option is not specified, at reads commands from standard input until end-of-file (EOF) is encountered.

When using shell redirection, the commands must be terminated by the delimiter specified in the here-document. For example:

at 10:00 AM tomorrow << EOF
ls -l /tmp
echo "Done" > /tmp/done.log
EOF

Note that the delimiter must be on a line by itself. If the delimiter is quoted (e.g., `EOF', `"EOF"'), the shell does not perform any interpretation on the characters between the quotes; it is treated literally. If the delimiter is unquoted (e.g., `EOF'), the shell interprets the characters between the delimiter and the newline, and all tabs are converted to spaces. Special characters, such as `$', `\', and backquotes (`'`), are interpreted unless the delimiter is quoted.

If the shell interpreter needs to be invoked, the user must include it as part of the script, such as:

$ at 1800
myshell myscript
EOT
job ... at ...
$

EXAMPLES

1. This sequence can be used at a terminal:

at -m 0730 tomorrow
sort < file >outfile
EOT

2. This sequence, which demonstrates redirecting standard error to a pipe, is useful in a command procedure (the sequence of output redirection specifications is significant):

at now + 1 hour <<!
diff file1 file2 2>&1 >outfile | mailx mygroup
!

3. To have a job reschedule itself, at can be invoked from within the at-job. For example, this daily processing script named my.daily runs every day (although crontab is a more appropriate vehicle for such work):

# my.daily runs every day
daily processing
at now tomorrow < my.daily

RATIONALE

The at utility reads from standard input the commands to be executed at a later time. It may be useful to redirect standard output and standard error within the specified commands.

The -t time option was added as a new capability to support an internationalized way of specifying a time for execution of the submitted job.

Early proposals added a ``jobname'' concept as a way of giving submitted jobs names that are meaningful to the user submitting them. The historical, system-specified at_job_id gives no indication of what the job is. Upon further reflection, it was decided that the benefit of this was not worth the change in historical interface. The at functionality is useful in simple environments, but in large or complex situations, the functionality provided by the Batch Services option is more suitable.

The -q option historically has been an undocumented option, used mainly by the batch utility.

The System V -m option was added to provide a method for informing users that an at-job had completed. Otherwise, users are only informed when output to standard error or standard output are not redirected.

The behavior of at <now> was changed in an early proposal from being unspecified to submitting a job for potentially immediate execution. Historical BSD at implementations support this. Historical System V implementations give an error in that case, but a change to the System V versions should have no backwards-compatibility ramifications.

On BSD-based systems, a -u user option has allowed those with appropriate privileges to access the work of other users. Since this is primarily a system administration feature and is not universally implemented, it has been omitted. Similarly, a specification for the output format for a user with appropriate privileges viewing the queues of other users has been omitted.

The -f file option from System V is used instead of the BSD method of using the last operand as the pathname. The BSD method is ambiguous—does:

at 1200 friday

mean the same thing if there is a file named friday in the current directory?

The at_job_id is composed of a limited character set in historical practice, and it is mandated here to invalidate systems that might try using characters that require shell quoting or that could not be easily parsed by shell scripts.

The at utility varies between System V and BSD systems in the way timezones are used. On System V systems, the TZ variable affects the at-job submission times and the times displayed for the user. On BSD systems, TZ is not taken into account. The BSD behavior is easily achieved with the current specification. If the user wishes to have the timezone default to that of the system, they merely need to issue the at command immediately following an unsetting or null assignment to TZ. For example:

TZ= at noon ...

gives the desired BSD result.

While the yacc-like grammar specified in the OPERANDS section is lexically unambiguous with respect to the digit strings, a lexical analyzer would probably be written to look for and return digit strings in those cases. The parser could then check whether the digit string returned is a valid day_number, year_number, and so on, based on the context.
