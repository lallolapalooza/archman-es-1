es un servidor TFTP (RFC1350). Por defecto, es iniciado por inetd en la mayoría de los sistemas, pero puede ejecutarse como un demonio independiente. Este servidor es multihilo y soporta todas las opciones descritas en RFC2347 (extensión de opciones), RFC2348 (blksize), RFC2349 (tsize y timeout) y RFC2090 (opción de multicast). También soporta mtftp tal como se

define en la especificación PXE.

Este programa soporta tanto la sintaxis de línea de comandos habitual de GNU, con opciones largas que comienzan con dos guiones ('-'), como opciones cortas. A continuación se incluye una

descripción de las opciones.

-t, --tftpd-timeout

<valor>
Número de segundos de inactividad antes de que el servidor salga. Este valor solo tiene sentido cuando el servidor es iniciado por inetd. En modo demonio, el servidor nunca sale. El valor por defecto
es 300 segundos.
-r, --retry-timeout
<valor>
Cuántos segundos esperar una respuesta antes de retransmitir un paquete. El valor por defecto es 5 segundos. Esto puede ser anulado por el cliente TFTP con la
opción 'timeout'.
-m, --maxthread
<valor>
Número máximo de hilos concurrentes permitidos. El valor por defecto
es 100.
-v, --verbose[=valor
]
Aumentar o establecer el nivel de registro. Sin argumentos, aumentará en uno el valor actual. El valor por defecto es LOG_NOTICE, consulte syslog(3) para los niveles de registro. El rango de valores válidos va de 0
(LOG_EMERG) a 7 (LOG_DEBUG).
--trac
e
Cuando el nivel de verbosidad está establecido en 7, esto mostrará información de depuración para
cada paquete enviado o recibido desde la red.
--no-timeou

--no-tsiz

Asumiendo que el archivo es /var/log/atftpd.log, simplemente ejecute: "touch /var/log/atftpd.log" y luego "chown nobody.nogroup /var/log/atftpd.log". Especificar la dirección IP a la que atftpd se enlaza. Útil cuando se especifica --daemon. Por defecto, se enlaza a todas las interfaces. Solo se puede especificar una dirección, el servidor solo puede escuchar en una o en todas las

--mcast-t
tl
Especificar el TTL a usar para el datagrama multicast. Por defecto se usa un valor de 1. Tenga en cuenta que el TTL tiene un significado especial en multicast ya que se usa para determinar el alcance de los paquetes. El valor de 1 significa que los paquetes no abandonan la red local, consulte ip(4). El alcance también puede ser determinado por la dirección como se describe en la
RFC2365.
--mcast-ad

Especificar el rango de direcciones IP a usar para la transferencia multicast. La cadena de formato puede comprender un rango y una lista de valores: "239.255.0.0-31,128-132,200". El valor por defecto es "239.255.0.0-255". Este rango de direcciones es propuesto en la RFC2365 para alcance
local.
--mcast-po
rt
Especificar el puerto UDP a usar para la transferencia multicast. La cadena de formato puede contener un rango y una lista de números de puerto: "1758-2000,8000-9000". El valor por defecto es
"1758".

<archivo>

fuente.

<puerto>

--no-source-port-check
ing
En algunos casos específicos de redes que usan balanceadores de carga u otro equipo que realiza NAT (traducción de direcciones de red), es necesario deshabilitar la comprobación del puerto de origen porque el número de puerto ha sido traducido. Si desea usar esta función, debe saber por qué la necesita y sus implicaciones. Tenga en cuenta que esta opción viola la RFC1350. Esta opción solo tiene efecto para transferencias no
multicast.
--prevent-s
as
Aborda la situación del Síndrome del Aprendiz de Mago (Sorcerer's Apprentice Syndrome) tal como lo requiere la RFC 1350. Esta RFC requiere que se rechacen las respuestas repetidas a un solo paquete. Por lo tanto, un bloque solo se retransmitirá en caso de tiempo de espera. Por compatibilidad con versiones anteriores, el valor por defecto sigue siendo ignorar esta RFC. Así, los bloques se transmiten en cada
petición.
--mcast-switch-cli
ent
Esta opción permite al servidor proceder con el siguiente cliente multicast tan pronto como el cliente actual agote su tiempo de espera. Cuando el cliente maestro actual falla al enviar un acuse de recibo (ACK) al servidor, el servidor enviará un acuse de recibo de opción (OACK) al cliente maestro con el campo MC (cliente maestro) establecido a falso y enviará un OACK al siguiente cliente multicast con MC establecido a verdadero. Sin esta opción, el servidor reintentará el cliente maestro actual hasta 5 veces y luego lo marcará como completado, procediendo con el

path
Este es el directorio raíz utilizado por el servidor TFTP. Todos los archivos solicitados por un cliente TFTP deben residir en este directorio. Si no se especifica, el directorio por defecto es /tftpboot. Dado que atftpd se ejecuta como el usuario nobody, el permiso del directorio debe configurarse correctamente para permitir la lectura y escritura de archivos.

ESTADÍSTICAS (STATS)

A partir de la versión 0.2, el servidor recopila algunas estadísticas. Actualmente, el servidor calcula la carga del sistema, el tiempo entre conexiones y algunas estadicas de hilos como el número de archivos enviados, recibidos, el número de abortos... Para ver estas estadísticas en los registros, necesita establecer --verbose=6 (LOG_NOTICE) o superior.

SEGURIDAD (SECURITY)

TFTP en sí mismo no tiene ninguna disposición para la seguridad. No hay autenticación de usuario y los clientes TFTP obtienen acceso a todos los archivos dentro del directorio raíz especificado para los que el servidor tiene permiso.

Se puede obtener cierto nivel de seguridad usando el soporte libwrap de atftp. Añadiendo una entrada adecuada a /etc/hosts.allow y /etc/hosts.deny se restringirá el acceso a hosts de confianza. El nombre del demonio a usar en estos archivos es in.tftpd.

PCRE

El servidor atftpd proporciona una forma de reemplazar dinámicamente el nombre del archivo solicitado por uno nuevo basado en expresiones regulares compatibles con Perl. Los pares de patrón/reemplazo se leen de los archivos especificados. Al recibir una solicitud de lectura, el servidor intentará primero abrir el nombre de archivo solicitado. Si falla, entonces buscará un reemplazo basado en el contenido del archivo de patrones. Si esto también falla, se enviará un error al cliente. Esta función está disponible solo para solicitudes de lectura. No tiene sentido hacer esta sustitución para clientes que escriben archivos en el servidor.

MTFTP

El nombre mtftp se refiere a tftp multicast como lo define la especificación PXE. Consulte pxespec.txt para obtener la fuente de la especificación. Tenga en cuenta que esto no es lo mismo que RFC2090. El arranque compatible con PXE implementa mtftp, no RFC2090.
