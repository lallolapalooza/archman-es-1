DESCRIPCIÓ

N

El programa atop es un monitor interactivo para ver la carga en un sistema Linux. Cada intervalo segundos (por defecto: 10 segundos) se recopila información sobre la ocupación de recursos a nivel de sistema (CPUs, memoria, discos e interfaces de red) y a nivel de cgroup (versión 2). Además, se recopila información sobre los procesos y hilos que son responsables de la utilización de las CPUs, la memoria y los discos. La carga de red por proceso se muestra solo cuando se ha instalado el módulo del kernel netatop o el módulo BPF n

etato
p-bpf.

MODO

GEMELO

Con el indicador -t puedes ejecutar atop de forma interactiva en 'modo gemelo'. Este modo permite ejecutar una medición en vivo con la posibilidad de revisar y analizar una muestra anterior. Mientras tanto, la medición en vivo

continúa.

Cuando se inicia en modo gemelo, atop genera un proceso hijo que recopila los contadores y los escribe en un archivo temporal sin procesar. El proceso padre lee los contadores del archivo temporal sin procesar y los presenta al usuario. La lectura del proceso padre se mantiene al ritmo de las muestras escritas por el proceso hijo en las mediciones en

vivo.

Mientras la recopilación continúa por parte del proceso hijo, se puede presionar la tecla 'r', la tecla 'b' o la tecla 'T' para revisar muestras anteriores. El proceso padre pausa implícitamente la medición en vivo al presionar una de estas teclas o al presionar explícitamente la tecla 'z' (pausa)

.

Después de navegar por las muestras anteriores con las teclas 't' (siguiente muestra), 'T' (muestra anterior), 'r' (reiniciar al inicio de la medición), 'Z' (avance rápido hasta el final de la medición) y 'b' (saltar a la marca de tiempo), la medición en vivo puede continuar presionando la tecla 'z' (reanudar después de la pausa)

.

El archivo temporal sin procesar se escribirá en el directorio /tmp por defecto. Opcionalmente, se puede añadir la ruta absoluta de un directorio alternativo detrás del indicador -t (por ejemplo, cuando no hay suficiente espacio en el directorio /tmp). En cualquier caso, el proceso padre terminará el proceso hijo

cuando finalice la medición y el archivo
temporal sin procesar será eliminado.

MODO DE GRÁFICOS DE BARRAS

En el modo de gráficos de barras, la información general del sistema se muestra como gráficos de barras en la mitad superior de la pantalla. La mitad inferior está reservada para la información de cgroup o de proceso. Cuando la información no cabe en la pantalla, se aplica un principio de reducción de la información por defecto.

CPUs
En el modo de gráficos de barras, los gráficos de barras para las CPUs reflejan el porcentaje de ocupación para cada CPU. Por cada CPU, se muestran dos barras que representan el porcentaje de ocupación general y el porcentaje de ocupación por sistema/usuario.

Por defecto, la barra superior representa el uso del sistema y la barra inferior el uso del usuario. Cuando no hay suficiente espacio horizontal para mostrar todas las CPUs, se muestran solo las CPUs más ocupadas por muestra.

Se dibuja una línea roja en el gráfico de barras como umbral crítico. Por defecto, este valor es del 90% y puede ser modificado por la opción 'cpucritperc' en el archivo de configuración (ver página man separada atoprc). Si este valor se establece a cero, no se dibujará ninguna línea de umbral.

Memory
En el modo de gráficos de barras, se muestra un gráfico de barras para la memoria (total, utilizada, libre, caché/buffer). Para la memoria se muestra una línea horizontal que indica el umbral crítico de memoria utilizada. Por defecto, este valor es del 90% y puede ser modificado por la opción 'memcritperc' en el archivo de configuración (ver página man separada atoprc). Si este valor se establece a cero, no se dibujará ninguna línea de umbral.
Disks
Para cada disco se muestra el porcentaje de ocupación como una barra.
Cuando no hay suficiente espacio horizontal para mostrar todos los discos, solo se mostrarán los discos más ocupados por muestra.

Por defecto, las categorías de consumo de disco se muestran con diferentes colores en las barras, marcadas con un carácter 'R' (lectura) y 'W' (escritura).
La parte superior de la barra puede consistir en un color sin marcar que representa una categoría 'neutral'. Supongamos que la unidad de escala es 5% por línea y el porcentaje de ocupación total es 54% que consiste en dos categorías del 27%. Las dos categorías se redondearán al 25% (5 líneas de 5% cada una), pero el porcentaje de ocupación total se redondeará al 55% (11 líneas de 5%). Entonces, la línea superior representará una categoría 'neutral'.
Al presionar la tecla 'H' o al iniciar atop con el indicador '-H', no se muestran categorías.

Se dibuja una línea roja en el gráfico de barras como umbral crítico. Por defecto, este valor es del 90% y puede ser modificado por la opción 'dskcritperc' en el archivo de configuración (ver página man separada atoprc). Si este valor se establece a cero, no se dibujará ninguna línea de umbral.

Interfaces
Para cada interfaz de red no virtual se muestra un gráfico de barras doble con una escala dedicada que refleja la tasa de tráfico. Una de las barras muestra la tasa de transmisión ('TX') y la otra barra la tasa de recepción ('RX'). La escala de tráfico de cada interfaz de red permanece en su nivel más alto. Todas las escalas de interfaz se pueden restablecer durante la medición presionando la tecla 'L'.

La mayoría de las veces, la velocidad real (ancho de banda máximo) de las interfaces de red no se conoce, por ejemplo, en el caso de las interfaces de red de máquinas virtuales. Por lo tanto, no es posible mostrar la utilización de la interfaz como un porcentaje. Sin embargo, cuando se conoce la velocidad real de una interfaz, se mostrará debajo del gráfico de barras correspondiente.

Cuando no hay suficiente espacio horizontal para mostrar todas las interfaces de red, solo se mostrarán las interfaces más ocupadas por muestra.

Por lo general, los gráficos de barras no se ordenarán por porcentaje de ocupación cuando haya suficiente espacio horizontal. Sin embargo, después de cambiar del modo de texto al modo de gráfico de barras, los gráficos de barras podrían haberse ordenado ya que esto era necesario para la presentación en modo de texto. El siguiente intervalo en modo de gráfico de barras muestra las barras de nuevo sin ordenar, a menos que el ancho de la ventana sea insuficiente para todas las barras.

Para las CPUs, discos y recursos de memoria también se muestra un gráfico de barras con dos barras que reflejan los valores PSI 'some' (S) y 'full' (F). El porcentaje 'some' (S) indica el tiempo en el que al menos algunas tareas se detuvieron en un recurso determinado. El porcentaje 'full' (F) indica el tiempo en el que todas las tareas no inactivas se detuvieron en este recurso simultáneamente, lo que tuvo un grave impacto en el rendimiento.
Para algunas distribuciones de Linux, el soporte PSI puede estar deshabilitado por defecto. En ese caso, debe pasar psi=1 en la línea de comandos del kernel durante el arranque.

El resto de esta página del manual describe principalmente la información que se muestra en modo de texto. Cuando ciertas descripciones también se aplican al modo de gráfico de barras, se mencionará explícitamente.

MODO DE TEXTO EN GENERAL

Con cada intervalo se muestra información sobre la ocupación de recursos a nivel de sistema (CPU, memoria, discos y capas de red) en la parte superior de la pantalla. Cuando un recurso no ha sido utilizado durante el intervalo, la línea se suprime a menos que la tecla 'f' esté activa.

En la parte inferior de la pantalla se muestra información a nivel de cgroup (tecla 'G') o a nivel de proceso (teclas 'g', 'c', 's', 'm', 'd', 'n', 'v', 'u' o 'p'). Por defecto, solo se muestran los cgroups sin procesos asignados en el propio cgroup ni en los cgroups inferiores, a menos que la tecla 'a' (todos) esté activa. Por defecto, solo se muestran los procesos que estuvieron activos durante el intervalo, a menos que la tecla 'a' (todos) esté activa.
Los intervalos se repiten hasta que se alcanza el número de muestras (especificado como argumento del comando), o hasta que se presiona la tecla 'q' en modo interactivo.

Cuando se inicia atop, comprueba si el canal de salida estándar está conectado a una pantalla o a un archivo/tubería. En el primer caso, produce códigos de control de pantalla (a través de la biblioteca ncurses) y se comporta de forma interactiva. En el segundo caso, produce una salida de texto plano.

En modo interactivo, la salida de atop se escala dinámicamente a las dimensiones actuales de la pantalla/ventana.
Si la ventana se redimensiona horizontalmente, las columnas se añadirán o eliminarán automáticamente. Para este propósito, cada columna tiene un peso particular. Se mostrarán las columnas con los pesos más altos que quepan en el ancho actual.
Si la ventana se redimensiona verticalmente, se añadirán o eliminarán líneas de la lista de procesos/hilos automáticamente.

En modo interactivo, la salida de atop se puede controlar presionando teclas particulares. Sin embargo, también es posible especificar dicha tecla como un indicador en la línea de comandos. En ese caso, atop cambia al modo indicado de antemano. Este modo se puede modificar nuevamente de forma interactiva. Especificar dicha tecla como indicador es especialmente útil cuando se ejecuta atop con salida a una tubería o archivo (no interactivamente). Estos indicadores son los mismos que las teclas que se pueden presionar en modo interactivo (ver sección COMANDOS INTERACTIVOS).
Hay indicadores adicionales disponibles para admitir el almacenamiento de datos de atop en formato raw (ver sección ALMACENAMIENTO DE DATOS RAW).

Por defecto, atop produce su salida a pantalla completa a menos que se pase un indicador para dirigir la salida a un registro raw (-w) o dirigir la salida en formato analizable (-P) o salida JSON (-J). Sin embargo, es posible producir salida a pantalla completa mientras la salida también se dirige de otra manera. En ese caso, se debe pasar explícitamente un indicador que se relacione con la salida a pantalla completa (como -g) en la línea de comandos.

La línea de estado en la pantalla inicial muestra si atop se ejecuta con vista restringida (como usuario no privilegiado) o vista sin restringir (como usuario privilegiado). En caso de vista restringida, atop no tiene los privilegios (ni identidad root ni las capacidades necesarias) para recuperar todos los valores de contador a nivel de sistema y a nivel de proceso.

CONTABILIDAD DE PROCESOS

Con cada intervalo, atop lee la administración del kernel para obtener información sobre todos los procesos en ejecución. Sin embargo, es probable que los procesos hayan terminado durante el intervalo. Estos procesos podrían haber consumido recursos del sistema durante este intervalo antes de terminar. Por lo tanto, atop intenta leer los registros de contabilidad de procesos que contienen la información de contabilidad de los procesos terminados y también informa sobre estos procesos. Solo cuando el mecanismo de contabilidad de procesos en el kernel está activado, el kernel escribe dicho registro de contabilidad de procesos en un archivo por cada proceso que termina.

Hay varias formas para que atop acceda a los registros de contabilidad de procesos (se prueban en este orden):

1.
Cuando la variable de entorno ATOPACCT está establecida, especifica el nombre del archivo de contabilidad de procesos. En ese caso, la contabilidad de procesos para este archivo debe haber sido activada de antemano. Antes de abrir este archivo para leer, atop renuncia a sus privilegios de root (si los tiene).
Cuando esta variable de entorno está presente pero su contenido está vacío, la contabilidad de procesos no se utilizará en absoluto.
2.
¡Esta es la forma preferida de manejar los registros de contabilidad de procesos!
Cuando el demonio atopacctd está activo, ha activado el mecanismo de contabilidad de procesos en el kernel y transfiere los registros de contabilidad originales a archivos sombra. En ese caso, atop renuncia a sus privilegios de root y abre el archivo sombra actual para leer.
Esta forma es preferible, ya que el demonio atopacctd mantiene el control total del tamaño del archivo de contabilidad de procesos original escrito por el kernel y los archivos sombra leídos por el (los) proceso(s) atop.

El servicio atopacct se activará antes que el servicio atop para permitir que atop detecte que la contabilidad de procesos es gestionada por el demonio atopacctd. Como servicio de bifurcación, atopacctd se encarga de que todos los directorios y archivos se inicialicen antes de que el proceso padre muera. El proceso hijo continúa como el demonio.

Para más información, consulte la página man de atopacctd.

3.
Cuando el demonio atopacctd no está activo, atop verifica si el mecanismo de contabilidad de procesos se ha activado a través del paquete separado psacct o acct (el nombre del paquete depende de la distribución de Linux). En ese caso, uno de los archivos /var/log/pacct, /var/account/pacct o /var/log/account/pacct se utiliza como archivo de contabilidad de procesos y atop abre este archivo para leer.
4.
Como última posibilidad, atop intenta activar el mecanismo de contabilidad de procesos (requiere privilegios de root) utilizando el archivo /var/cache/atop.d/atop.acct (que será escrito por el kernel, y leído por el propio atop). La contabilidad de procesos permanece activa mientras al menos un proceso atop esté vivo. Siempre que el último proceso atop se detiene (ya sea presionando 'q' o con 'kill -15'), desactiva nuevamente el mecanismo de contabilidad de procesos. Por lo tanto, nunca debe terminar atop con 'kill -9', ya que de lo contrario no tendrá la oportunidad de detener la contabilidad de procesos. Como resultado, el archivo de contabilidad puede consumir mucho espacio en disco después de un tiempo.
Para evitar que el archivo de contabilidad de procesos consuma demasiado espacio en disco, atop verifica al final de cada muestra si el tamaño del archivo de contabilidad de procesos excede las 200 MiB y si este proceso atop es el único que está utilizando el archivo actualmente. En ese caso, el archivo se trunca a un tamaño de cero.

Tenga en cuenta que se requieren privilegios de root para activar/desactivar la contabilidad de procesos en el kernel. Puede iniciar atop como usuario root o especificar privilegios setuid-root al archivo ejecutable. En este último caso, atop activa la contabilidad de procesos y renuncia a los privilegios de root nuevamente.
Si atop no se ejecuta con privilegios de root, no muestra información sobre procesos finalizados. Indica esta situación con el mensaje 'no procacct' en la esquina superior derecha (en lugar del contador que muestra el número de procesos salidos).

Cuando durante un intervalo muchos procesos han terminado, atop puede crecer enormemente en memoria al leer todos los registros de contabilidad de procesos

PROCINFO FILE FORMAT

atop can write its collected information to a file for later analysis. This file can be read by atop itself in batch mode (option -r) or by the atoprecover script.

The file has a binary format. The first record contains the system information and the column headers. The subsequent records contain the resource consumption for the system and for every process. The records are stored per interval.

The maximal size of the file is 50 MiB. This can be modified by the configuration parameter MAXCOLLECTSIZE in the configuration file (see separate atoprc man page). When this size is reached, the oldest records are overwritten by new records.

To avoid excessive growth atop will never read more than 50 MiB with process information from the process accounting file per interval (approx. 54000 finished processes). In interactive mode a warning is given whenever processes have been skipped for this reason.

COLORS

For the resource consumption on system level, atop uses colors in text mode to indicate that a critical occupation percentage has been (almost) reached. A critical occupation percentage means that is likely that this load causes a noticeable negative performance influence for applications using this resource. The critical percentage depends on the type of resource: e.g. the performance influence of a disk with a busy percentage of 80% might be more noticeable for applications/users than a CPU with a busy percentage of 90%.

Currently atop uses the following default values to calculate a weighted percentage per resource:

 Processor
A busy percentage of 90% or higher is considered 'critical' (also in bar graph mode).
 Disk
A busy percentage of 90% or higher is considered 'critical'.
 Network
A busy percentage of 90% or higher for the load of an interface is considered 'critical'.
 Memory
An occupation percentage of 90% is considered 'critical'. Notice that this occupation percentage is the accumulated memory consumption of the kernel (including slab) and all processes. The memory for the page cache ('cache' and 'buff' in the MEM-line) and the reclaimable part of the slab ('slrec') is not implied!
If the number of pages swapped out ('swout' in the PAG-line) is larger than 10 per second, the memory resource is considered 'critical'. A value of at least 1 per second is considered 'almost critical'.
If the committed virtual memory exceeds the limit ('vmcom' and 'vmlim' in the SWP-line), the SWP-line is colored due to overcommitting the system.
 Swap
An occupation percentage of 80% is considered 'critical' because swap space might be completely exhausted in the near future. It is not critical from a performance point-of-view.

These default values can be modified in the configuration file (see separate atoprc man page).

When a resource exceeds its critical occupation percentage, the concerning values in the screen line are colored red by default.
When a resource exceeds (by default) 80% of its critical percentage (so it is almost critical), the concerning values in the screen line are colored cyan by default. This 'almost critical percentage' (one value for all resources) can be also modified in the configuration file (see separate atoprc man page).
The default colors red and cyan can be modified in the configuration file as well (see separate atoprc man page).

With the key 'x' (or flag -x), the use of colors can be suppressed in text mode. The use of colors is however mandatory in case of bar graph mode.

NETATOP OR NETATOP-BPF MODULE

Per-process and per-thread network activity can be measured by the netatop kernel module or the netatop-bpf BPF module that can be separately installed.
When atop has been started with the '-K' flag, it verifies if the netatop or netatop-bpf module is currently active. If so, atop obtains the relevant network counters from this module for each interval and shows the number of sent and received packets per process/thread in the generic screen. Besides, detailed counters can be requested by pressing the 'n' key.
When the netatopd daemon is running in combination with the netatop module, atop also reads the network counters of exited processes that are logged by this daemon (comparable with process accounting).

More information about the optional netatop kernel module and the netatopd daemon can be found in the concerning man-pages and on the website mentioned at the end of this manual page.

GPU STATISTICS GATHERING

GPU statistics can be gathered by atopgpud which is a separate data collection daemon process. It gathers cumulative utilization counters of every Nvidia GPU in the system, as well as utilization counters of every process that uses a GPU. When atop has been started with the '-k' flag, it reads these GPU utilization counters with every interval when the daemon is active.

The atopgpud daemon is written in Python, so a Python interpreter should be installed on the target system. For the gathering of the statistics, the pynvml module is used by the daemon. Be sure that this module is installed on the target system before activating the daemon, by running the command pip as root user:

  pip install nvidia-ml-py

The atopgpud daemon is installed by default as part of the atop package, but it is not automatically enabled. The daemon can be enabled and started now by running the following commands (as root):

  systemctl enable atopgpu

INTERACTIVE COMMANDS

When running atop interactively (no output redirection), keys can be pressed to control the output. In general, lower case keys can be used to show other information for the active processes while certain upper case keys can be used to influence the sort order of the active process/thread list. Some of these keys can also be used to switch from bar graph mode to particular detailed process information in text mode.

g
Show generic output (default).

Per process the following fields are shown in case of a window-width of 80 positions: process-id, CPU consumption during the last interval in system and user mode, the virtual and resident memory growth of the process.
The data transfer per process for read/write on disk can only be shown when atop runs with root privileges.
When the optional module netatop or netatop-bpf is loaded, the data transfer for send/receive of network packets is shown for each process.
The last columns contain the state, the occupation percentage for the chosen resource (default: CPU) and the process name.

When more than 80 positions are available, other information is added.

Per process the following fields are shown in case of a window width of 80 positions: process-id, minor and major memory faults, size of virtual shared text, total virtual process size, total resident process size, virtual and resident growth during last interval, memory occupation percentage and process name.

When more than 80 positions are available, other information is added.

For memory consumption, always all processes are shown (also the processes that were not active during the interval).

When atop runs with root privileges, the following fields are shown: process-id, amount of data read from disk, amount of data written to disk, amount of data that was written but has been withdrawn again (WCANCL), disk occupation percentage and process name.

Para almacenar estadísticas de nivel de sistema y de proceso para análisis a largo
plazo (por ejemplo, para comprobar la carga del sistema y los procesos activos que se ejecutaron ayer entre las 3:00 y las 4:00 PM),

-w seguido del nombre del archivo. Si este archivo ya existe y se reconoce como un archivo de datos en

bruto,

atop añadirá nuevas muestras al archivo (empezando con una muestra que refleje la actividad desde el arranque). Si el archivo no existe, se creará. Toda la información sobre la actividad del sistema, los procesos y los hilos se almacena en el archivo en bruto. El intervalo (por defecto: 10 segundos) y el número de muestras (por defecto: infinito) se pueden pasar como últimos argumentos. En lugar del número de muestras, se puede usar el indicador -S para indicar que
atop debe terminar de todos modos
antes de la medianoche. Un archivo en bruto se puede leer y visualizar de nuevo con el indicador -r seguido del nombre del archivo. Si no se especifica ningún nombre de archivo, se abre el

archivo

/var/log/atop/atop_ YYYYMMDD para la entrada (donde YYYYMMDD son dígitos que representan la fecha actual). Si se especifica un nombre de archivo en el formato YYYYMMDD (que representa cualquier fecha válida), se abre el archivo/var/log/atop/atop_ YYYYMMDD. Si se especifica un nombre de archivo con el nombre simbólico y, se abre el registro diario de ayer (esto se puede repetir, por lo que 'yyyy' indica el registro de hace cuatro días). Si se usa el nombre de archivo-, se leerá de stdin. Las muestras del archivo se pueden ver interactivamente usando la tecla 't' para mostrar la siguiente muestra, la tecla 'T' para mostrar la muestra anterior, la tecla 'b' para saltar a un momento particular, la tecla 'r' para rebobinar al inicio del archivo o la tecla 'Z' para avanzar rápidamente hasta el final del archivo. SALIDA

La línea de encabezado siempre muestra el nombre del host, la fecha y hora de finalización cuando se tomó la muestra, las opciones que están activas actualmente (solo en modo texto) y el tiempo transcurrido (duración) de la muestra. El verbo 'PAUSED' se mostrará detrás de la hora cuando atop esté actualmente en pausa con la tecla

'z'.

La primera muestra muestra la actividad de nivel de sistema desde el arranque (el tiempo transcurrido en el encabezado muestra el tiempo desde el arranque)

.

En modo texto, atop primero muestra las líneas relacionadas con la actividad de nivel de sistema para cada muestra. SALIDA ANALIZABLE

Con el indicador -P seguido de una lista de una o más etiquetas (separadas por comas), se produce una salida analizable para cada muestra. Las etiquetas que se pueden especificar para las estadísticas a nivel de sistema corresponden a las etiquetas (el primer verbo de cada línea) que se pueden encontrar en la salida interactiva: "CPU", "cpu", "CPL", "GPU", "MEM", "SWP", "PAG", "PSI", "LVM", "MDD", "DSK", "NFM", "NFC", "NFS", "NET", "IFB", "LLC", "NUM" y "NUC".

Para las estadísticas a nivel de cgroup, está disponible la etiqueta "CGR".

Para las estadísticas a nivel de proceso, hay etiquetas especiales disponibles: "PRG" (general), "PRC" (CPU), "PRE" (GPU), "PRM" (memoria), "PRD" (disco, pero requiere privilegios especiales) y "PRN" (red, solo si el módulo opcional netatop o netatop-bpf está instalado).
Con la etiqueta "ALL", se muestran todas las estadísticas a nivel de sistema y proceso.

El comando y la línea de comandos en la salida analizable pueden contener espacios y, por lo tanto, por defecto están rodeados por paréntesis. Sin embargo, dado que un espacio a menudo se utiliza como separador entre los campos para las herramientas de análisis, con el indicador adicional -Z es posible intercambiar los espacios en el comando (línea) por guiones bajos y omitir los paréntesis.

Para cada intervalo, se muestran todas las líneas solicitadas, después de lo cual atop muestra una línea que solo contiene la etiqueta "SEP" como separador antes de que se generen las líneas para la siguiente muestra.
Cuando una muestra contiene los valores desde el arranque, atop muestra una línea que solo contiene la etiqueta "RESET" antes de que se generen las líneas para esta muestra.

La primera parte de cada línea de salida consta de los siguientes seis campos: etiqueta (el nombre de la etiqueta), host (el nombre de esta máquina), epoch (la hora de este intervalo como número de segundos desde el 1-1-1970), fecha (fecha de este intervalo en formato YYYY/MM/DD), hora (hora de este intervalo en formato HH:MM:SS) e intervalo (número de segundos transcurridos para este intervalo).

Los campos subsiguientes de cada línea de salida dependen de la etiqueta:

CPU
