Tcl inclut une

L'emplacement de la bibliothèque Tcl est renvoyé par la commande info library. En plus de la bibliothèque Tcl, chaque application aura normalement sa propre bibliothèque de procédures de support ; l'emplacement de cette bibliothèque est normalement donné par la valeur de la $ app _library variable globale, où app est le nom de l'application. Cette commande examine les répertoires du chemin de recherche actuel (donné par la variable d'environnement PATH) lors de sa recherche d'un fichier exécutable nommé cmd. Sur les plateformes Windows, la recherche est étendue avec les mêmes répertoires et extensions de fichiers que ceux utilisés par exec. Auto_execok se souvient des informations des recherches précédentes dans un tableau nommé auto_execs ; cela évite la recherche de chemin lors des appels futurs pour le même cmd. La commande auto_reset peut être utilisée pour forcer auto_execok à oublier ses informations en cache. auto_import pattern Auto_import est invoqué lors d'un namespace import

Si c'est le cas, les commandes sont chargées afin qu'elles soient disponibles pour l'interpréteur lors de la création des liens d'importation. Si les commandes ne se trouvent pas dans une bibliothèque chargée automatiquement, auto_import ne fait rien. La correspondance de motif est effectuée selon les règles de correspondance de namespace import. auto_load cmd Cette commande tente de

Le chemin de chargement automatique est donné par la variable globale auto_path si elle existe. S'il n'existe pas de variable auto_path, alors la variable d'environnement TCLLIBPATH est utilisée, si elle existe. Sinon, le chemin de chargement automatique ne consiste qu'en le répertoire de la bibliothèque Tcl. Dans chaque répertoire du chemin de chargement automatique, il doit y avoir un fichier tclIndex qui décrit une ou plusieurs commandes définies dans ce répertoire et un script à évaluer pour charger chacune des commandes. Le fichier tclIndex devrait être généré avec la commande auto_mkindex. Si cmd est trouvé dans un fichier d'index, alors le script approprié est évalué pour créer la commande. La commande auto_load renvoie 1 si cmd a été créée avec succès. La commande renvoie 0 s'il n'y avait pas d'entrée d'index pour cmd ou si le script n'a pas réellement défini cmd (par exemple parce que les informations d'index sont obsolètes). Si une erreur se produit lors du traitement du script, alors cette erreur est renvoyée. Auto_load ne lit les informations d'index qu'une seule fois et les enregistre dans le tableau auto_index ; les appels futurs à auto_load vérifient la présence de cmd dans le tableau plutôt que de relire les fichiers d'index. Les informations d'index en cache peuvent être supprimées avec la commande auto_reset. Cela forcera la prochaine commande auto_load à recharger la base de données d'index depuis le disque. auto_mkindex dir

auto_qualify command
namespace
Calcule une liste de noms entièrement qualifiés pour command. Cette liste reflète le chemin qu'un interpréteur Tcl standard suit pour les recherches de commandes : d'abord il cherche la commande dans l'espace de noms courant, puis dans l'espace de noms global. En conséquence, si command est relative et namespace n'est pas ::, la liste renvoyée a deux éléments : command délimité par namespace, comme s'il s'agissait d'une commande dans l'espace de noms namespace ; et command comme s'il s'agissait d'une commande dans l'espace de noms global. Sinon, si soit command est absolu (il commence par ::), soit namespace est ::, la liste ne contient que command comme s'il s'agissait d'une commande dans l'e

varNameEste es un procedimiento de búsqueda estándar para que lo usen las extensiones durante su inicialización. Llaman a este procedimiento para buscar su biblioteca de scripts en varios directorios estándar. El último componente del nombre del directorio de la biblioteca es normalmente basenameversion (por ejemplo, tk8.0), pero podría ser “library” cuando está en las jerarquías de compilación. El archivo initScript se cargará en el intérprete una vez que se encuentre. El directorio en el que se encuentra este archivo se almacena en la variable global varName. Si esta variable ya está definida (por ejemplo, por código C durante la inicialización de la aplicación), entonces no se realiza ninguna búsqueda.
