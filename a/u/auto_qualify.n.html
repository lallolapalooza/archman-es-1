INTRODUCCIÓN

Tcl incluye una biblioteca de procedimientos Tcl para funciones comúnmente necesarias. Los procedimientos definidos en la biblioteca de Tcl son genéricos y adecuados para su uso por muchas aplicaciones diferentes. La ubicación de la biblioteca de Tcl es devuelta por el info library comando. Además de la biblioteca de Tcl, cada aplicación normalmente tendrá su propia biblioteca de procedimientos de soporte; la ubicación de esta biblioteca normalmente se da por el valor de la $app_library variable global, donde app es el nombre de la aplicación. Por ejemplo, la ubicación de la biblioteca de Tk se guarda en la variable tk_library.

Para acceder a los procedimientos en la biblioteca de Tcl, una aplicación debe cargar el archivo init.tcl en la biblioteca, por ejemplo con el comando de Tcl

source [file join [info library] init.tcl]

Si el procedimiento de biblioteca Tcl_Init es invocado desde el procedimiento Tcl_AppInit de una aplicación, esto ocurre automáticamente. El código en init.tcl definirá el procedimiento unknown y hará que los otros procedimientos se carguen bajo demanda usando el mecanismo de auto-carga definido a continuación.

PROCEDIMIENTOS DE COMANDO

Se proporcionan los siguientes procedimientos en la biblioteca de Tcl:

auto_execok cmd
Determina si existe un archivo ejecutable o una función incorporada del shell con el nombre cmd. Si es así, devuelve una lista de argumentos que deben pasarse a exec para ejecutar el archivo ejecutable o la función incorporada del shell nombrada por cmd. Si no, devuelve una cadena vacía. Este comando examina los directorios en la ruta de búsqueda actual (dada por la variable de entorno PATH) en su búsqueda de un archivo ejecutable llamado cmd. En plataformas Windows, la búsqueda se amplía con los mismos directorios y extensiones de archivo que usa exec. Auto_execok recuerda información sobre búsquedas anteriores en un array llamado auto_execs; esto evita la búsqueda de la ruta en futuras llamadas para el mismo cmd. El comando auto_reset puede usarse para forzar a auto_execok a olvidar su información en caché.
auto_import pattern
Auto_import se invoca durante namespace import para ver si los comandos importados especificados por pattern residen en una biblioteca de auto-carga. Si es así, los comandos se cargan para que estén disponibles para el intérprete al crear los enlaces de importación. Si los comandos no residen en una biblioteca de auto-carga, auto_import no hace nada. La coincidencia de patrones se realiza de acuerdo con las reglas de coincidencia de namespace import.
auto_load cmd
Este comando intenta cargar la definición para un comando de Tcl llamado cmd. Para hacer esto, busca en una ruta de auto-carga, que es una lista de uno o más directorios. La ruta de auto-carga es dada por la variable global auto_path si existe. Si no existe la variable auto_path , entonces se usa la variable de entorno TCLLIBPATH, si existe. De lo contrario, la ruta de auto-carga consiste solo en el directorio de la biblioteca de Tcl. Dentro de cada directorio en la ruta de auto-carga debe haber un archivo tclIndex que describe uno o más comandos definidos en ese directorio y un script para evaluar para cargar cada uno de los comandos. El archivo tclIndex debe generarse con el comando auto_mkindex . Si cmd se encuentra en un archivo de índice, entonces se evalúa el script apropiado para crear el comando. El comando auto_load devuelve 1 si cmd se creó correctamente. El comando devuelve 0 si no había una entrada de índice para cmd o si el script no definió realmente cmd (por ejemplo, porque la información del índice está desactualizada). Si ocurre un error mientras se procesa el script, entonces se devuelve ese error. Auto_load solo lee la información del índice una vez y la guarda en el array auto_index; las futuras llamadas a auto_load buscan cmd en el array en lugar de releer los archivos de índice. La información del índice en caché puede eliminarse con el comando auto_reset. Esto forzará al siguiente comando auto_load a recargar la base de datos del índice desde el disco.
auto_mkindex dir pattern pattern ...
Genera un índice adecuado para su uso por auto_load. El comando busca en dir todos los archivos cuyos nombres coincidan con cualquiera de los argumentos pattern (la coincidencia se hace con el comando glob ), genera un índice de todos los procedimientos de comandos de Tcl definidos en todos los archivos coincidentes y almacena la información del índice en un archivo llamado tclIndex en dir. Si no se da ningún patrón, se asumirá el patrón *.tcl . Por ejemplo, el comando
auto_mkindex foo *.tcl

leerá todos los archivos .tcl en el subdirectorio foo y generará un nuevo archivo de índice foo/tclIndex.

Auto_mkindex analiza los scripts de Tcl cargándolos en un intérprete hijo y monitoreando los comandos proc y namespace que se ejecutan. Las extensiones pueden usar el paquete auto_mkindex_parser (no documentado) para registrar otros comandos que pueden contribuir al índice de auto_load. Tendrás que leer auto.tcl para ver cómo funciona esto.

Auto_mkindex_old (que tiene la misma sintaxis que auto_mkindex) analiza los scripts de Tcl de una manera relativamente poco sofisticada: si alguna línea contiene la palabra “proc” como sus primeros caracteres, se asume que es una definición de procedimiento y se toma la siguiente palabra de la línea como el nombre del procedimiento. Las definiciones de procedimientos que no aparecen de esta manera (por ejemplo, tienen espacios antes del proc) no serán indexadas. Si tu script contiene código “peligroso”, como código de inicialización global o nombres de procedimientos con caracteres especiales como $, *, [ o ], es más seguro usar auto_mkindex_old.

auto_reset
Destruye toda la información en caché por auto_execok y auto_load. Esta información se volverá a leer del disco la próxima vez que se necesite. Auto_reset también elimina cualquier procedimiento listado en el índice de auto-carga, de modo que se cargarán copias nuevas de ellos la próxima vez que se usen.
auto_qualify command namespace
Calcula una lista de nombres completamente calificados para command. Esta lista refleja el camino que sigue un intérprete estándar de Tcl para las búsquedas de comandos: primero busca el comando en el espacio de nombres actual, y luego en el espacio de nombres global. En consecuencia, si command es relativo y namespace no es ::, la lista devuelta tiene dos elementos: command con ámbito de namespace, como si fuera un comando en el namespace namespace; y command como si fuera un comando en el espacio de nombres global. De lo contrario, si command es absoluto (comienza con ::), o namespace es ::, la lista contiene solo command como si fuera un comando en el espacio de nombres global.

Auto_qualify es usado por las instalaciones de auto-carga en Tcl, tanto para producir índices de auto-carga como pkgIndex.tcl, y para realizar la auto-carga real de funciones en tiempo de ejecución.
