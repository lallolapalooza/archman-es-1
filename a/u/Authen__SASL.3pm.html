NOMBRE

Authen::SASL - Marco de autenticación SASL

VERSIÓN

versión 2.1900

SINOPSIS

use Authen::SASL;
$sasl = Authen::SASL->new(
  mechanism => 'CRAM-MD5 PLAIN ANONYMOUS',
  callback => {
    pass => \&fetch_password,
    user => $user,
  }
);

DESCRIPCIÓN

SASL es un mecanismo genérico de autenticación utilizado por varios protocolos de red. Authen::SASL proporciona un marco de implementación que todos los protocolos deberían poder compartir.

El marco permite que se conecten diferentes implementaciones de la clase de conexión. En el momento de escribir esto había dos de estos complementos.

Authen::SASL::Perl
Este módulo implementa varios mecanismos y está implementado enteramente en Perl.
Authen::SASL::XS
Este módulo usa la biblioteca C de Cyrus SASL (se admiten tanto la versión 1 como la 2).
Authen::SASL::Cyrus
Este módulo es el predecesor de Authen::SASL::XS.

Hasta la versión 2.16, Authen::SASL::Cyrus se cargaba como una alternativa a Authen::SASL::XS.

De forma predeterminada, Authen::SASL intenta cargar primero Authen::SASL::XS, seguido de Authen::SASL::Perl en caso de fallo. Si desea cambiar el orden o desea usar específicamente solo una implementación, simplemente haga

use Authen::SASL qw(Perl);

o si tiene otro módulo de complemento que soporte la API de Authen::SASL

use Authen::SASL qw(My::SASL::Plugin);

CONSTRUCTOR

new ( OPCIONES )
El constructor puede llamarse con o sin argumentos. Pasar argumentos es simplemente un atajo para llamar a los métodos "mechanism" y "callback" .
callback => { NOMBRE => VALOR, NOMBRE => VALOR, ... }
Establece las devoluciones de llamada. Consulte el método callback para más detalles.
mechanism => NOMBRES
mech => NOMBRES
Establece la lista de mecanismos para elegir. Consulte el método mechanism para más detalles.
debug => VALOR
Establece el valor de bits del nivel de depuración a "VALOR"

La salida de depuración se enviará a "STDERR". Los bits de este valor son:

1   Muestra mensajes de depuración en los módulos Perl para los mecanismos.
    (Actualmente solo se usa en GSSAPI)
4   Con capas de seguridad activas, muestra información sobre los paquetes leídos.
8   Con capas de seguridad activas, muestra información sobre los paquetes escritos.

El valor predeterminado es 0.

MÉTODOS

mechanism ( )
Devuelve la lista actual de mecanismos
mechanism ( NOMBRES )
Establece la lista de mecanismos para elegir. "NOMBRES" debe ser una cadena de nombres separados por espacios.
callback ( NOMBRE )
Devuelve la devolución de llamada actual asociada con "NOMBRE".
callback ( NOMBRE => VALOR, NOMBRE => VALOR, ... )
Establece las devoluciones de llamada dadas a los valores dados
client_new ( SERVICIO, HOST, SEGURIDAD )
Crea y devuelve un nuevo objeto de conexión para una conexión del lado del cliente.
server_new ( SERVICIO, HOST, OPCIONES )
Crea y devuelve un nuevo objeto de conexión para una conexión del lado del servidor.
error ( )
Devuelve cualquier error de la última conexión

La Clase de Conexión

server_start ( DESAFÍO )
server_start comienza la autenticación usando el mecanismo elegido. Si el mecanismo no es soportado por el SASL instalado, falla. Debido a que para algunos mecanismos el cliente tiene que iniciar la negociación, puede dar el desafío del cliente como un parámetro.
server_step ( DESAFÍO )
server_step realiza el siguiente paso en el proceso de negociación. El primer parámetro que da es el desafío/respuesta del cliente.
client_start ( )
El paso inicial a realizar. Devuelve el valor inicial para pasar al servidor o una lista vacía en caso de error.
client_step ( DESAFÍO )
Este método se llama cuando una respuesta del servidor lo requiere. DESAFÍO es el valor del servidor. Devuelve el siguiente valor a pasar al servidor o una lista vacía en caso de error.
need_step ( )
Devuelve verdadero si el mecanismo seleccionado requiere otro paso antes de completarse (error o éxito).
answer ( NOMBRE )
El método devolverá el valor devuelto por la última llamada a la devolución de llamada NOMBRE
property ( NOMBRE )
Devuelve el valor de la propiedad asociado con "NOMBRE".
property ( NOMBRE => VALOR, NOMBRE => VALOR, ... )
Establece las propiedades nombradas a sus valores asociados.
service ( )
Devuelve el argumento de servicio que se pasó a los métodos *_new.
host ( )
Devuelve el argumento de host que se pasó a los métodos *_new.
mechanism ( )
Devuelve el nombre del mecanismo elegido.
is_success ( )
Una vez need_step() devuelve falso, entonces puede comprobar si la autenticación tuvo éxito llamando a este método, que devuelve un valor booleano.

Devoluciones de Llamada

Hay tres formas diferentes en las que se puede pasar una devolución de llamada

CODEREF
Si el valor pasado es una referencia de código, entonces, cuando sea necesario, se llamará y el objeto de conexión se pasará como primer argumento. En adición, algunas devoluciones de llamada pueden recibir argumentos adicionales.
ARRAYREF
Si el valor pasado es una referencia de arreglo, el primer elemento del arreglo debe ser una referencia de código. Cuando se llama a la devolución de llamada, la referencia de código se llamará con el objeto de conexión pasado como primer argumento y todos los demás valores del arreglo pasados después.
ESCALAR
Todos los demás valores pasados se usarán directamente. Es decir, es lo mismo que pasar una referencia de código que, cuando se llama, devuelve el valor.
