DESCRIPCIÓ

N

Introducció

n

La directiva autodie es muy inteligente a la hora de trabajar con las funciones incorporadas de Perl. El comportamiento de estas funciones está fijo, y "autodie" sabe exactamente cómo intentan señalar un

fallo.

Pero, ¿qué pasa con las subrutinas definidas por el usuario en los módulos? Si usas "autodie" en una subrutina definida por el usuario, asume el siguiente comportamiento para demostrar un

fallo:
  • Un valor falso, en contexto
    • escalar
  • Una lista vacía, en contexto de
    • lista
  • Una lista que conti
    • ene un solo undef, e
n contexto de lista

Todos los demás valores de retorno (incluyendo la lista del único cero, y la lista que contiene una sola cadena vacía) se consideran exitosos. Sin embargo, el código del mundo real no siempre es tan fácil. Quizás el código con el que estás trabajando devuelve una cadena que contiene la palabra "FAIL" al fallar, o una lista de dos elementos que contiene "(undef, "mensaje de error humano")". Para hacer que autodie funcione con este tipo de subrutinas, tenemos la interfaz de p

istas.

La interfaz de pistas permite proporcionar pistas a "autodie" sobre cómo debe detectar el fallo de las subrutinas definidas por el usuario. Aunque estas pueden ser proporcionadas por el usuario final de "autodie", idealmente se escriben en el propio módulo, o en un módulo auxiliar o una subclase de "autodie" e

n sí
mismo.

¿Qué son las

pistas?

Una pista es una subrutina o un valor que se comprueba contra el valor de retorno de una subrutina con autodie. Si la coincidencia devuelve verdadero, "autodie" considera que la subrutina ha

fallado.

Si la pista proporcionada es una subrutina, entonces "autodie" pasará el valor de retorno completo a esa subrutina. Si la pista es un objeto regexp, entonces "autodie" lo hará coincidir contra el valor de retorno. Si la pista es undef, el valor de retorno debe ser undef. En las versiones de Perl 5.10 y superiores, se puede proporcionar cualquier otro valor y se hará una coincidencia inteligente contra el valor proporcionado. Sin embargo, los valores de coincidencia inteligente como estos están

obsoletos.

Se pueden proporcionar pistas tanto para el contexto escalar como para el de lista. Ten en cuenta que una subrutina con autodie nunca verá un contexto nulo, ya que "autodie" siempre necesita capturar el valor de retorno para examinarlo. Las subrutinas con autodie llamadas en contexto nulo

actúan como si se llamaran en un contexto escalar, pero su v
alor de retorno se descarta después de haber sido comprobado.

Ejemplos de

pistas

Las pistas pueden consistir en referencias a subrutinas, objetos que sobrecargan la coincidencia inteligente, expresiones regulares y, dependiendo de la versión de Perl, posiblemente otras cosas. Puedes especificar pistas diferentes para cómo se debe identificar el fallo en los contextos escalar y de

lista.

Estos ejemplos se aplican para su uso en la subrutina "AUTODIE_HINTS" y al llamar a "autodie::hints->set_hi

nts_for()".

Las pistas específicas de contexto más comunes

son: 
# Los fallos escalares siempre devuelven undef:
    {  scalar => sub { !defined($_[0]) }  }
# Los fallos escalares devuelven cualquier valor falso [expectación por defecto]:
    {  scalar => sub { ! $_[0] }  }
# Los fallos escalares siempre devuelven cero explícitamente:
    {  scalar => sub { defined($_[0]) && $_[0] eq '0' }  }
# Los fallos de lista siempre devuelven una lista vacía:
    {  list => sub { !@_ }  }
# Los fallos de lista devuelven () o (undef) [expectación por defecto]:
    {  list => sub { ! @_ || @_ == 1 && !defined $_[0] }  }
# Los fallos de lista devuelven () o un solo valor falso:
    {  list => sub { ! @_ || @_ == 1 && !$_[0] }  }
# Los fallos de lista devuelven (undef, "alguna cadena")
    {  list => sub { @_ == 2 && !defined $_[0] }  }
# Un foo() fallido devuelve 'FAIL' o '_FAIL' en contexto escalar,
#                    devuelve (-1) en contexto de lista...
autodie::hints->set_hints_for(
    \&foo,
    {
        scalar => qr/^ _? FAIL $/xms,
        list   => sub { @_ == 1 && $_[0] eq -1 },
    }
);
# Un foo() fallido devuelve 0 en todos los contextos...
autodie::hints->set_hints_for(
    \&foo,
    {
        scalar => sub { defined($_[0]) && $_[0] == 0 },
        list   => sub { @_ == 1 && defined($_[0]) && $_[0] == 0 },
    }
)
;

Esta construcción "en todos los contextos" es muy común y se puede abreviar usando la clave 'fail'. Esto establece tanto la pista "scalar" como la "list" al mismo

valor: 
# Un foo() fallido devuelve 0 en todos los contextos...
autodie::hints->set_hints_for(
    \&foo,
    {
        fail => sub { @_ == 1 and defined $_[0] and $_[0] == 0 }
    }
);
# Un think_positive() fallido devuelve un número negativo en caso de fallo...
autodie::hints->set_hints_for(
    \&think_positive,
    {
        fail => sub { $_[0] < 0 }
    }
);
# Un my_system() fallido devuelve un valor distinto de cero en caso de fallo...
autodie::hints->set_hints_for(
    \&my_system,
    {
        fail => sub { $_[0] != 0 }
    }
)
;

Establecimiento manual de pistas desde tu

programa

Si estás usando un módulo que devuelve algo especial en caso de fallo, puedes crear manualmente pistas para cada una de las subrutinas deseadas. Una vez que se especifican las pistas, están disponibles para todos los archivos y módulos cargados a partir de ese momento, por lo que puedes mover este trabajo a un módulo y seguirá

funcionando. 
use Some::Module qw(foo bar);
use autodie::hints;
autodie::hints->set_hints_for(
        \&foo,
        {
                scalar => SCALAR_HINT,
                list   => LIST_HINT,
        }
);
autodie::hints->set_hints_for(
        \&bar,
        { fail => SOME_HINT, }
)
;

Es posible pasar como primer argumento una referencia a una subrutina (recomendado) o un nombre de subrutina completamente calificado. Esto significa que puedes establecer pistas en módulos que podrían car

garse: 
use autodie::hints;
autodie::hints->set_hints_for(
        'Some::Module:bar', { fail => SCALAR_HINT, }
)
;

Esta técnica es más útil cuando tienes un proyecto que usa muchos módulos de terceros. Puedes definir todas tus posibles pistas en un solo lugar. Esto incluso puede estar en una subclase de autodie. Por

ejemplo: 
package my::autodie;
use parent qw(autodie);
use autodie::hints;
autodie::hints->set_hints_for(...);
1;

Ahora puedes "use my::autodie", lo que funcionará igual que el "autodie" estándar, pero ahora es conscien

te de las pistas q
ue hayas establecido.

Añadiendo pistas a tu

módulo

"autodie" proporciona una interfaz pasiva que te permite declarar pistas para tu módulo. Estas pistas serán encontradas y usadas por "autodie" si se carga, pero de lo contrario no tienen ningún efecto (o dependencias) sin autodie. Para establecerlas, tu módulo necesita declarar que implementa el rol "autodie::hints::provider". Esto se puede hacer escribiendo tu propio método "DOES", usando un sistema como "Class::DOES" para hacer el trabajo pesado por ti, o declarando una %DOESpaquete variable con una clave "autodie::hints::provider" y un valor verdadero correspondiente

.

Ten en cuenta que comprobar un hash %DOES es un atajo exclusivo de "autodie". Otros módulos no utilizan este mecanismo para comprobar roles, aunque puedes usar el módulo "Class::DOES" de CPAN para

permitirlo.

Además, debes definir una subrutina "AUTODIE_HINTS" que devuelva una referencia a un hash que contenga las pistas para tus

subrutinas: 
package Your::Module;
# Podemos usar Class::DOES de CPAN para declarar la adhesión
# a un rol.
use Class::DOES 'autodie::hints::provider' => 1;
# Alternativamente, podemos declarar el rol en %DOES. Ten en cuenta
# que esta es una optimización específica de autodie, aunque Class::DOES
# puede usarse para promover esto a una declaración de rol real.
our %DOES = ( 'autodie::hints::provider' => 1 );
# Finalmente, debemos definir las pistas en sí mismas.
sub AUTODIE_HINTS {
    return {
        foo => { scalar => HINTS, list => SOME_HINTS },
        bar => { scalar => HINTS, list => MORE_HINTS },
        baz => { fail => HINTS },
    }
}

Esto permite que tu código establezca pistas sin depender de que "autodie" y "autodie::hints" estén cargados, o incluso instalados. De esta manera, tu código puede hacer lo correcto cuando "autodie" está instalado, pero no ne

cesita depender de
él para funcionar.

Insistir en las

pistas

Cuando una subrutina definida por el usuario es envuelta por "autodie", usará las pistas si están disponibles, y de lo contrario recurre al comportamiento por defecto descrito en la introducción de este documento. Esto puede ser problemático si esperamos que exista una pista, pero (por cualquier razón) no se ha

cargado.

Podemos pedirle a autodie que insista en que se use una pista anteponiendo un signo de exclamación al nombre de la subrutina. Un signo de exclamación solo indica que todas las subrutinas después de él deben tener pistas

declaradas. 
# foo() y bar() deben tener sus pistas definidas
use autodie qw( !foo !bar baz );
# Todo debe tener pistas (recomendado).
use autodie qw( ! foo bar baz );
# bar() y baz() deben tener sus pistas definidas
use autodie qw( foo ! bar baz );
# Habilitar autodie para todas las funciones incorporadas soportadas por Perl,
# así como para foo(), bar() y baz(). Todo debe
# tener pistas.
use autodie qw( ! :all foo bar baz )
;

Si no hay pistas disponibles para las subrutinas especificadas, esto causará un error en tiempo de compilación. Insistir en las pistas para las funciones incorporadas de Perl (por ejemplo, "open" y "close") siempre es

exitoso.

Insistir en las pistas es muy reco

menda
ble.
