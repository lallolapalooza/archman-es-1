NOMBRE

auth_krb5 - autenticador Kerberos v5 de nnrpd

SINOPSIS

auth_krb5 [-i instancia]

DESCRIPCIÓN

Este programa realiza la autenticación para nnrpd contra un KDC de Kerberos v5. Esta NO es una autenticación Kerberos real usando tickets de servicio; en su lugar, se usa un nombre de usuario y una contraseña para intentar obtener un TGT de Kerberos v5 para confirmar que son válidos. Como tal, este autenticador asume que a nnrpd se le ha proporcionado el nombre de usuario y la contraseña del usuario, y por lo tanto no es tan seguro como la autenticación Kerberos real. Generalmente, solo debe usarse con NNTP sobre TLS para proteger la contraseña del espionaje.

Normalmente, no querrás usar este autenticador. En su lugar, usa ckpasswd con soporte PAM y configura la pila PAM de nnrpd para usar un módulo PAM de Kerberos. Un módulo PAM de Kerberos completo es más sofisticado sobre cómo valida las contraseñas y tiene una gama mucho más amplia de opciones que este autenticador.

OPCIONES

-i instancia
Si se proporciona esta opción, instancia se usará como la instancia del principal recibido de nnrpd y la autenticación se realizará contra ese principal en lugar del principal base. En otras palabras, un principal como "usuario", cuando se pasa a auth_krb5 invocado con "-i nntp", se transformará en "usuario/nntp" antes de intentar la autenticación Kerberos.

Dado que dar la contraseña a nnrpd no es tan seguro como la autenticación Kerberos normal, esta opción admite una configuración en la que a todos los usuarios se les da una instancia separada solo para la autenticación de noticias con su propia contraseña, para que la contraseña de su cuenta regular no se exponga a través de NNTP.

EJEMPLO

El siguiente fragmento de readers.conf(5) le dice a nnrpd que autentique a los usuarios intentando obtener TGTs de Kerberos v5 para ellos, agregando una instancia de "nntp" a los nombres de usuario antes de hacerlo:

auth kerberos {
    auth: "auth_krb5 -i nntp"
}
access kerberos {
    users: "*/nntp"
    newsgroups: example.*
}

Se concede acceso a los grupos example.* para todos los usuarios que se autentiquen correctamente.

ERRORES

Actualmente, se rechaza cualquier nombre de usuario que contenga información de realm (que contenga "@"). Esto es para evitar que alguien proporcione un nombre de usuario que corresponda a un principal en otro realm al que tiene acceso y obtenga acceso al servidor de noticias a través de él. Sin embargo, esto es algo que la gente puede desear hacer en algunas circunstancias, por lo que debería haber una mejor manera de manejarlo (como, quizás, una lista de realms aceptables o una bandera -r que especifique el realm en el que intentar la autenticación).

No está claro cuál es la acción correcta a tomar cuando el nombre de usuario proporcionado contiene una "/" y también se proporcionó -i. En este momento, auth_krb5 creará un principal Kerberos mal formado con instancias múltiples e intentará autenticarse contra él, lo que fallará pero quizás no con el mejor mensaje de error.
