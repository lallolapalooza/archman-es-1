AUSEARCH(8) System Administration Utilities AUSEARCH(8)

NAME

ausearch - una herramienta para consultar los registros del demonio de auditoría

SYNOPSIS

ausearch [opciones]

DESCRIPTION

ausearch es una herramienta que puede consultar los registros del demonio de auditoría basándose en diferentes criterios de búsqueda. La utilidad ausearch también puede recibir entrada desde la entrada estándar, siempre que la entrada sean los datos brutos del registro. Cada opción de línea de comandos dada forma una declaración "y". Por ejemplo, buscar con -m y -ui significa devolver eventos que tengan tanto el tipo solicitado como coincidan con el ID de usuario dado. Una excepción son las opciones -m y -n; se permiten múltiples tipos de registro y nodos en una búsqueda que devolverán cualquier nodo y registro coincidentes.

También debe tenerse en cuenta que cada excursión de llamada al sistema desde el espacio de usuario al núcleo y de regreso al espacio de usuario tiene un ID de evento único. Cualquier evento auditable que se active durante este viaje comparte este ID para que puedan correlacionarse.

Diferentes partes del núcleo pueden agregar registros suplementarios. Por ejemplo, un evento de auditoría en la llamada al sistema "open" también hará que el núcleo emita un registro PATH con el nombre del archivo. La utilidad ausearch presentará todos los registros que componen un evento juntos. Esto podría significar que, aunque busque un tipo específico de registro, los eventos resultantes pueden contener registros SYSCALL.

También tenga en cuenta que no todos los tipos de registro tienen la información solicitada. Por ejemplo, un registro PATH no tiene un nombre de host o un loginuid.

OPTIONS

-a, --event id-evento-auditoría
Busca un evento basándose en el ID de evento dado. Los mensajes siempre comienzan con algo como msg=audit(1116360555.329:2401771). El ID del evento es el número después de los ':'. Todos los eventos de auditoría que se registran a partir de la llamada al sistema de una aplicación tienen el mismo ID de evento de auditoría. Una segunda llamada al sistema realizada por la misma aplicación tendrá un ID de evento diferente. De esta manera son únicos.
--arch CPU
Busca eventos basándose en una arquitectura de CPU específica. Si no conoce la arquitectura de su máquina pero desea usar la tabla de llamadas al sistema de 32 bits y su máquina admite 32 bits, también puede usar b32 para la arquitectura. Lo mismo ocurre con la tabla de llamadas al sistema de 64 bits, puede usar b64. La arquitectura de su máquina se puede encontrar ejecutando 'uname -m'.
-c, --comm nombre-comm
Busca un evento basándose en el nombre comm dado. El nombre comm es el nombre del ejecutable de la estructura de tareas.
--debug
Escribe los eventos malformados que se omiten a stderr.
--checkpoint archivo-checkpoint
Punto de control de la salida entre invocaciones sucesivas de ausearch, de modo que solo se impriman los eventos no emitidos previamente en invocaciones posteriores.

Un evento de auditoría consta de uno o más registros. Al procesar eventos, ausearch define los eventos como completos o incompletos. Un evento completo es un evento de registro único o uno cuyo tiempo de evento ocurrió 2 segundos antes en comparación con el evento que se está procesando actualmente.

Se logra un punto de control registrando el último evento completo emitido junto con el número de dispositivo y el inodo del archivo en el que apareció el último evento completo en archivo-checkpoint. En una invocación posterior, ausearch cargará estos datos de punto de control y, mientras procesa los archivos de registro, descartará todos los eventos completos hasta que coincida con el punto de control. En ese momento, comenzará a emitir eventos completos.

Si el archivo o el último evento con punto de control no se encuentran, se producirá uno de una serie de errores y ausearch terminará. Consulte ESTADO DE SALIDA para obtener más detalles.

--eoe-timeout segundos
Establece el tiempo de espera para el análisis del final del evento. Consulte end_of_event_timeout en auditd.conf(5) para obtener más detalles. Tenga en cuenta que establecer este valor anulará cualquier valor configurado que se encuentre en /etc/auditd/auditd.conf.
-e, --exit código-de-salida-o-errno
Busca un evento basándose en el código de salida o errno de la llamada al sistema dado.
--escape opción
Esta opción determina si la salida se escapa para hacer que el contenido sea más seguro para ciertos usos. Las opciones son raw, tty, shell y shell_quote. Cada modo incluye los caracteres del modo anterior y escapa más caracteres. Es decir, shell incluye todos los caracteres escapados por tty y añade más. tty es el valor predeterminado.
--extra-keys 
Cuando el modo format es csv, esta opción agregará una columna final con información de clave si existe para el evento. Esto solo ocurriría en registros SYSCALL que fueran el resultado de activar una regla de auditoría que define una clave.
--extra-labels 
Cuando el modo format es csv, esta opción agregará columnas de información sobre las etiquetas del sujeto y el objeto cuando existan.
--extra-obj2 
Cuando el modo format es csv, esta opción agregará columnas de información sobre un segundo objeto cuando exista. Es raro que un segundo objeto sea parte de un registro. Algunos ejemplos son cuando un archivo se renombra de un nombre a otro o cuando un dispositivo se monta en una ruta.
--extra-time 
Cuando el modo format es csv, esta opción agregará columnas de información sobre el tiempo desglosado para facilitar la subselección.
-f, --file nombre-archivo
Busca un evento basándose en el nombre de archivo dado. El argumento coincidirá con archivos normales, así como con sockets af_unix.
--format opción
Los eventos que coinciden con los criterios de búsqueda se formatean utilizando esta opción. Los formatos admitidos son: raw, default, interpret, csv y text. La opción raw se describe en la opción de línea de comandos --raw. La opción default es lo que se obtiene cuando no se pasan opciones de formato. Incluye una línea como separador visual que indica la marca de tiempo y luego siguen los registros del evento. La opción interpret se explica en la opción de línea de comandos -i. La opción csv genera los resultados de la búsqueda como un evento normalizado en formato de valor separado por comas (CSV) adecuado para su importación en programas analíticos. La opción text convierte el evento en una oración en inglés que es más fácil de entender que otras opciones, pero esto se hace a costa de la pérdida de detalles. En la mayoría de los casos, esto está perfectamente bien, ya que el evento original conserva toda la información original.
-ga, --gid-all id-grupo-todo
Busca un evento con el ID de grupo efectivo o el ID de grupo que coincida con el ID de grupo dado.
-ge, --gid-effective id-grupo-efectivo
Busca un evento con el ID de grupo efectivo o nombre de grupo dado.
-gi, --gid id-grupo
Busca un evento con el ID de grupo o nombre de grupo dado.
-h, --help
Ayuda
-hn, --host nombre-host
Busca un evento con el nombre de host dado. El nombre de host puede ser un nombre de host, un nombre de dominio completamente calificado o una dirección de red numérica. Consulte también el comando --node que busca en el campo node.

checkpoint significa ausearch utilizará la marca de tiempo encontrada dentro de un archivo de punto de control (checkpoint) válido, ignorando el inodo, dispositivo, número de serie, nodo y tipo de evento también encontrados dentro de un archivo de punto de control. Esencialmente, esta es la acción de recuperación en caso de que una invocación de ausearch con una opción de punto de control falle con un estado de salida de 10, 11 o 12. Podría usarse en un script de shell algo así

como: 


ausearch --checkpoint /etc/audit/auditd_checkpoint.txt -i
_au_status=$?
if test ${_au_status} eq 10 -o ${_au_status} eq 11 -o ${_au_status} eq 12
then
  ausearch --checkpoint /etc/audit/auditd_checkpoint.txt --start checkpoint
-i fi

La opción de hora de arranque es una función de conveniencia y tiene limitaciones. La hora que calcula se basa en la hora actual menos /proc/uptime. Si después del arranque el reloj del sistema ha sido ajustado, quizás por ntp, entonces el cálculo puede ser incorrecto. En ese caso, necesitará especificar completamente la hora.
