CONSEJOS DE

RENDIMIENTO

Las reglas de llamadas al sistema (syscall) se evalúan para cada llamada al sistema de cada programa. Si tiene 10 reglas de llamadas al sistema, cada programa de su sistema se retrasará durante una llamada al sistema mientras el sistema de auditoría evalúa cada regla. Demasiadas reglas de llamadas al sistema perjudicarán el rendimiento. Intente combinar tantas como pueda siempre que el filtro, la acción, la clave y los campos sean idénticos. Por

ejemplo: 
auditctl -a always,exit -F arch=b64 -S openat -F
success=0 
auditctl -a always,exit -F arch=b64 -S truncate -F
success=0

podría reescribirse como una sola

regla: 
auditctl -a always,exit -F arch=b64 -S openat -S truncate -F
success=0

Además, intente usar la auditoría del sistema de archivos siempre que sea práctico. Esto mejora el rendimiento. Por ejemplo, si quisiera capturar todas las aperturas y truncados fallidos como arriba, pero solo le preocuparan los archivos en /etc y no le importaran /usr o /sbin, es posible usar esta

regla: 
auditctl -a always,exit -F arch=b64 -S openat,truncate -F dir=/etc -F
success=0

Esto tendrá un rendimiento más alto ya que el kernel no lo evaluará en cada y cada l

lamada al sistema. Será manejado por el código de auditoría del sistema de archivos y
solo se comprobará en las llamadas al sistema relacionadas con el sistema de archivos.

DESHABILITADO POR

DEFECTO

En muchos sistemas, auditd está configurado para instalar una regla -a never,task por defecto. Esta regla hace que cada nuevo proceso omita todo el procesamiento de reglas de auditoría. Esto se hace generalmente para evitar una pequeña sobrecarga de rendimiento impuesta por la auditoría de llamadas al sistema. Si desea usar auditd, necesita eliminar esa regla eliminando 10-no-audit.rules y añadiendo 10-base-config.rules al directorio de reglas de

auditoría.

Si ha definido reglas de auditoría que no coinciden

cuando deberían, compruebe auditctl -l para asegu
rarse de que no hay ninguna regla never,task allí.
