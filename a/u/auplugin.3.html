AUPLUGIN(3) API de auditoría de Linux AUPLUGIN(3)

NOMBRE

auplugin_init, auplugin_stop, auplugin_event_loop, auplugin_event_feed - ayudantes de procesamiento de eventos de plugin

SINOPSIS

#include <auplugin.h>

int auplugin_init(int inbound_fd, unsigned queue_size, int q_flags, const char *path);
void auplugin_stop(void);
void auplugin_event_loop(auplugin_callback_ptr callback);
int auplugin_event_feed(auparse_callback_ptr callback, unsigned timer_interval, auplugin_timer_callback_ptr timer_cb);

DESCRIPCIÓN

auplugin_init inicializa el framework de plugins. El parámetro inbound_fd especifica el descriptor de archivo que proporcionará los mensajes de auditoría, típicamente la entrada estándar. El argumento queue_size controla el número máximo de eventos que pueden ser encolados para su procesamiento. El parámetro q_flags selecciona almacenamiento en memoria o respaldado por archivo usando las constantes AUPLUGIN_Q_* definidas en auplugin.h. Si q_flags incluye AUPLUGIN_Q_IN_FILE, path especifica el archivo de respaldo. Cualquier evento ya presente en el archivo se encola al inicio para que los plugins reanuden el procesamiento de registros previamente no manejados. La biblioteca mantiene un estado global para su cola e hilos de trabajo. Solo se admite una instancia de plugin, por lo que los llamadores no deben invocar auplugin_init() concurrentemente desde múltiples hilos. La función retorna 0 en caso de éxito o -1 si la inicialización falla.

auplugin_stop señala al framework para que termine. Normalmente se llama desde un manejador de SIGTERM u otra lógica de apagado.

auplugin_event_loop inicia un hilo de trabajo para entregar los eventos encolados a la función callback proporcionada, un registro a la vez. La función se bloquea en el llamador hasta que se invoca auplugin_stop.

auplugin_event_feed se comporta de manera similar a auplugin_event_loop, excepto que los eventos encolados se alimentan a libauparse. El callback proporcionado debe coincidir con el tipo auparse_callback_ptr. El parámetro timer_interval especifica cuántos segundos esperará el hilo de trabajo por nuevos registros. Un valor de 0 deshabilita la lógica del temporizador. Cuando el intervalo expira, se llama a auparse_feed_age_events para vaciar los eventos envejecidos. Si timer_cb no es NULL, se invoca con el intervalo antes del vaciado. Pasar un timer_cb de NULL mantiene el comportamiento por defecto de llamar solo a auparse_feed_age_events. La función retorna 0 en caso de éxito o -1 si libauparse no pudo ser inicializado.

Los plugins pueden consultar estadísticas de la cola con auplugin_queue_depth, auplugin_queue_max_depth y auplugin_queue_overflow. Registre una función de devolución de llamada con auplugin_register_stats_callback e invóquela usando auplugin_report_stats.

MANEJO DE SEÑALES

Los plugins deben establecer manejadores de señales con sigaction(2) antes de entrar en el bucle de eventos. El manejador de SIGTERM debe llamar a auplugin_stop() para apagar el hilo de trabajo. Los manejadores para otras señales, como SIGHUP o SIGUSR1, deben establecer banderas globales que se procesan en las devoluciones de llamada de eventos o temporizador.

Ejemplo:

static volatile sig_atomic_t reload;
static void handler(int sig)
{
    if (sig == SIGTERM)
        auplugin_stop();
    else if (sig == SIGHUP)
        reload = 1;
}
