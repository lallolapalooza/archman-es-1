DESCRIPCIÓ

N

audisp-remote.conf es el archivo que controla la configuración del subsistema de registro remoto de auditoría. Las opciones disponibles son las

siguientes:
remote_serv
er
Esta es una cadena de caracteres de una sola palabra que es el nombre de host o dirección del servidor remoto al que este complemento enviará la información de registro. Puede ser la dirección numérica o un nombre de host
resoluble.
po
rt
Esta opción es un entero sin signo que indica a qué puerto conectarse en la máquina
remota.
local_po
rt
Esta opción es un entero sin signo que indica desde qué puerto local conectarse en la máquina local. Si no se especifica (el valor predeterminado) o se establece en la palabra any, se utiliza cualquier puerto no privilegiado disponible. Este es un mecanismo de seguridad para evitar que aplicaciones de espacio de usuario no confiables inyecten eventos en el demonio de auditoría. Debería establecerlo en un puerto no utilizado < 1024 para asegurarse de que solo los usuarios privilegiados puedan vincularse a ese puerto. Luego, también establezca tcp_client_ports en el archivo auditd.conf de agregación para que coincida con los puertos desde los que se conectan los
clientes.
transpo
rt
Este parámetro le indica a la aplicación de registro remoto cómo enviar eventos al sistema remoto. Las opciones válidas son TCP y KRB5. Si se establece en TCP, la aplicación de registro remoto simplemente realizará una conexión normal de texto sin cifrar al sistema remoto. Si se establece en KRB5, se utilizará Kerberos 5 para la autenticación y el cifrado. El valor predeterminado es
TCP.
mo
de
Este parámetro le indica a la aplicación de registro remoto qué estrategia usar para enviar registros al sistema remoto. Los valores válidos son immediate y forward. Si se establece en immediate, la aplicación de registro remoto intentará enviar eventos inmediatamente después de recibirlos. forward significa que almacenará los eventos en disco y luego intentará enviar los registros. Si no se puede establecer la conexión, encolará los registros hasta que pueda conectarse al sistema remoto. La profundidad de la cola está controlada por la opción queue_
depth.
queue_fi
le
Ruta de un archivo utilizado para la cola de eventos si mode está establecido en forward. El valor predeterminado es /var/spool/audit/re
mote.log.
queue_dep
th
Esta opción es un entero sin signo que determina cuántos registros pueden ser almacenados en búfer en disco o en memoria antes de considerarlo un fallo de envío. Este parámetro afecta al modo forward de la opción mode y a la encolación interna para interrupciones temporales de la red. La profundidad predeterminada es
2048.
form
at
Este parámetro le indica a la aplicación de registro remoto qué formato de datos se utilizará para los mensajes enviados por la red. El valor predeterminado es managed, el cual agrega algo de sobrecarga para asegurar que cada mensaje sea manejado correctamente en el extremo remoto, y para recibir mensajes de estado del servidor remoto. Si se proporciona ascii en su lugar, cada mensaje es una simple línea de texto ASCII sin sobrecarga alguna. El formato ascii es un protocolo muy simplista. Si hay algún problema de red, hará que audisp-remote termine. Auditd puede o no reiniciarlo en el siguiente evento. Si se necesita algo más robusto, use el formato managed. Si mode está establecido en forward, format debe ser manage
d.
network_retry_t
ime
El tiempo, en segundos, entre reintentos cuando se detecta un error de red. Tenga en cuenta que esta pausa se aplica a partir del segundo intento, para así evitar retrasos innecesarios si una reconexión es suficiente para solucionar el problema. El valor predeterminado es 1
segundo.
max_tries_per_rec
ord
El número máximo de veces que se intenta entregar cada mensaje. El valor mínimo es uno, ya que incluso una entrega completamente exitosa requiere al menos un intento. Si se hacen demasiados intentos, se realiza la acción network_failure_action. El valor predeterminado es
3.
max_time_per_rec
ord
La cantidad máxima de tiempo, en segundos, dedicada a intentar entregar cada mensaje. Tenga en cuenta que tanto esto como max_tries_per_record deberían establecerse, ya que cada intento puede tardar mucho en agotarse el tiempo de espera. El valor predeterminado es 5 segundos. Si se usa demasiado tiempo en un mensaje, se realiza la acción network_failure_act
ion.
heartbeat_time
out
Este parámetro determina cada cuántos segundos el cliente debe enviar un evento de latido (heartbeat) al servidor remoto. Esto se utiliza para que tanto el cliente como el servidor sepan que cada extremo está vivo y no ha terminado de una manera que no cerró la conexión de forma limpia. Este valor debe coordinarse con la configuración tcp_client_max_idle del servidor. El valor predeterminado es 0, lo que desactiva el envío de
latidos.
network_failure_act
ion
Este parámetro le indica al sistema qué acción tomar siempre que haya un error detectado al enviar eventos de auditoría al sistema remoto. Los valores válidos son ignore, syslog, exec, warn_once, suspend, single, halt y stop. Si se establece en ignore, la aplicación de registro remoto no hace nada. Si se envió un evento, se desencola. Syslog significa que emitirá una advertencia a syslog. Si se envió un evento, se desencola. Este es el valor predeterminado. exec /ruta-al-script ejecutará el script. No se pueden pasar parámetros al script. Si se envió un evento, se desencola. warn_once_continue es como syslog excepto que solo se coloca un mensaje en syslog hasta que un evento se transfiere con éxito. warn_once es como warn_once_continue excepto que el evento no se desencola. Suspend hará que la aplicación de registro remoto deje de enviar registros al sistema remoto. La aplicación de registro seguirá viva. Si se envió un evento, no se desencola. La opción single hará que la aplicación de registro remoto ponga el sistema informático en modo de usuario único. Si se envió un evento, no se desencola. La opción stop hará que la aplicación de registro remoto termine, pero deja otros complementos en ejecución. Si se envió un evento, no se desencola. La opción halt hará que la aplicación de registro remoto apague el sistema informático. Si se envió un evento, no se desencola. El valor predeterminado es
stop.
disk_low_act
ion
Del mismo modo, este parámetro le indica al sistema qué acción tomar si el extremo remoto señala un error de disco bajo. El valor predeterminado es
ignore.
disk_full_act
ion
Del mismo modo, este parámetro le indica al sistema qué acción tomar si el extremo remoto señala un error de disco lleno. El valor predeterminado es
warn_once.
disk_error_act
ion
Del mismo modo, este parámetro le indica al sistema qué acción tomar si el extremo remoto señala un error de disco. El valor predeterminado es
warn_once.
remote_ending_act
ion
Del mismo modo, este parámetro le indica al sistema qué acción tomar si se pierde la conexión de red. Esta acción tiene una opción adicional, reconnect, que le indica al complemento remoto intentar reconectarse al servidor al recibir el siguiente registro de auditoría. Si se estaba enviando un evento cuando algo activó esta acción, no se desencola. Si no tiene éxito al reconectarse, el registro de auditoría podría perderse. El valor predeterminado es reconectar (reconnect)
.
generic_error_act
ion
Del mismo modo, este parámetro le indica al sistema qué acción tomar si el extremo remoto señala un error que no reconocemos. El valor predeterminado es registrarlo en
syslog.
generic_warning_act
ion
Del mismo modo, este parámetro le indica al sistema qué acción tomar si el extremo remoto señala una advertencia que no reconocemos. El valor predeterminado es registrarla en
syslog.
audisp-remote.conf(5) — auditd remote logging configuration

NAME

audisp-remote.conf — auditd remote logging configuration file

DESCRIPTION

The audisp-remote.conf file is used to configure the audisp-remote plugin, which is part of the auditd daemon. This plugin is responsible for forwarding audit records to a remote syslog server.

The configuration file consists of tags and their associated values. Each tag is on its own line, followed by the value. Some tags may have values that are lists separated by whitespace.

The following tags are recognized:

queue_error_action
Igualmente, este parámetro indica al sistema qué acción tomar si hay un problema al trabajar con una cola de registros local. El valor predeterminado es `stop`.
overflow_action
Este parámetro indica al sistema qué acción tomar si la cola de eventos interna se desborda. Los valores válidos son ignore, syslog, suspend, single y halt. Si se establece en ignore, la aplicación de registro remota no hace nada. Syslog significa que emitirá una advertencia a syslog. Este es el valor predeterminado. Suspend hará que la aplicación de registro remota deje de enviar registros al sistema remoto. La aplicación de registro seguirá activa. La opción single hará que la aplicación de registro remota ponga el sistema informático en modo de un solo usuario. La opción halt hará que la aplicación de registro remota apague el sistema informático.
startup_failure_action
Este parámetro indica al sistema qué acción tomar siempre que haya un error al conectarse al sistema remoto durante el inicio. Normalmente, esto es benigno, ya que el comportamiento predeterminado del plugin es intentar reconectarse hasta que tenga éxito. Pero puede haber ocasiones en las que desee hacer algo diferente. Los valores válidos son ignore, syslog, exec, warn_once y warn_once_continue. Si se establece en ignore, la aplicación de registro remota no hace nada. Syslog significa que emitirá una advertencia a syslog. Exec /ruta/a/script ejecutará el script. No puede pasar parámetros al script. Warn_once es como syslog excepto que solo se envía un mensaje a syslog hasta que se transfiere un evento con éxito. Warn_once_continue es como warn_once excepto que ignora el problema. Este es el valor predeterminado.
enable_krb5
Esta opción está obsoleta. Utilice la opción transport para habilitar el soporte de Kerberos. Si esta opción sigue a la opción de configuración de transporte, anulará la configuración del transporte. Este sería el comportamiento esperado normal para la compatibilidad con versiones anteriores. Si se establece en yes, se utilizará Kerberos 5 para la autenticación y el cifrado. El valor predeterminado es no. Tenga en cuenta que el cifrado solo se puede utilizar con conexiones gestionadas, no con texto sin formato ASCII.
krb5_principal
Si se especifica, este es el principal esperado para el servidor. El cliente y el servidor utilizarán el principal especificado para negociar el cifrado. El formato de krb5_principal es como somenombre/nombredehost, consulte la página del manual auditd.conf para obtener más detalles. Si no se especifica, se utilizan los valores krb5_client_name y remote_server.
krb5_client_name
Esto especifica la parte del nombre del propio principal del cliente. Si no se especifica, el valor predeterminado es "auditd". El resto del principal consistirá en el nombre de dominio completamente calificado del host y el reino Kerberos predeterminado, de la siguiente manera: auditd/host14.example.com@EXAMPLE.COM (suponiendo que proporcionó "auditd" como krb_client_name). Tenga en cuenta que el cliente y el servidor deben tener el mismo nombre de principal y reino.
krb5_key_file
Ubicación de la clave para el principal de este cliente. Tenga en cuenta que el archivo de claves debe ser propiedad de root y tener permisos 0400. El valor predeterminado es /etc/audisp/audisp-remote.key

NOTES

Especificar un puerto local puede dificultar el reinicio del subsistema de auditoría debido a que la conexión anterior está en estado TIME_WAIT, si está reconectando hacia y desde los mismos hosts y puertos que antes.

La lógica de fallos de red funciona de la siguiente manera: El primer intento de entrega normalmente funciona sin problemas. Si no lo hace, se realiza un segundo intento inmediatamente, quizás después de reconectarse al servidor. Si el segundo intento también falla, audispd-remote se detiene durante el tiempo configurado e intenta nuevamente. Continúa pausando y reintentando hasta que se haya realizado demasiados intentos o haya expirado el tiempo permitido. Tenga en cuenta que estos tiempos rigen la cantidad máxima de tiempo permitida para que el servidor remoto se reinicie, si desea mantener el registro a través de un reinicio.

Se recomienda establecer un valor grande para `q_depth` en auditd.conf si se utiliza este plugin. También establezca un `q_depth` aún mayor en audisp-remote.conf. También establezca `heartbeat_timeout` en un valor distinto de cero, pero coordínelo con el servidor para que sea la mitad del tamaño de la configuración `tcp_client_max_idle` del servidor. Esto es necesario para obtener reintentos en un tiempo razonable si la red tiene un problema.
