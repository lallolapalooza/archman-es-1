NOMBRE

Authen::NTLM - Un módulo de autenticación NTLM

SINOPSIS

use Mail::IMAPClient;
use Authen::NTLM;
my $imap = Mail::IMAPClient->new(Server=>'imaphost');
ntlm_user($username);
ntlm_password($password);
$imap->authenticate("NTLM", Authen::NTLM::ntlm);
:
$imap->logout;
ntlm_reset;
:

o

ntlm_password($password);

);

DESCRIPCIÓN

Este módulo proporciona métodos para usar la autenticación NTLM. Puede
ser utilizado como un método de autenticación con el módulo Mail::IMAPClient
para realizar el mecanismo de desafío/respuesta para conexiones NTLM
o puede ser utilizado por sí solo para autenticación NTLM con otros
protocolos (p. ej., HTTP).
La implementación es una portación directa del código de F<fetchmail>
que, a su vez, ha basado su implementación NTLM en F<samba>. Como
tal, este código no es especialmente eficiente, sin embargo, tardará una
fracción de segundo en negociar un inicio de sesión en una PII, lo cual
probablemente sea suficiente para la mayoría de las situaciones.

FUNCIONES

ntlm_domain()
Establece el dominio a usar en los mensajes de autenticación NTLM.
Devuelve el nuevo dominio. Sin argumento, esta función
devuelve la entrada del dominio actual.
ntlm_user()
Establece el nombre de usuario a usar en los mensajes de autenticación NTLM.
Devuelve el nuevo nombre de usuario. Sin argumento, esta función
devuelve la entrada del nombre de usuario actual.
ntlm_password()
Establece la contraseña a usar en los mensajes de autenticación NTLM.
Devuelve la nueva contraseña. Sin argumento, esta función
devuelve la entrada de la contraseña actual.
ntlm_reset()
Reinicia la máquina de estados de desafío/respuesta NTLM para que la próxima
llamada a C<ntlm()> produzca un mensaje de conexión inicial.
ntlm()
Genera una respuesta a un desafío. El protocolo NTLM implica un
desafío inicial vacío del servidor que requiere una respuesta de mensaje
que contenga el nombre de usuario y el dominio (que pueden estar vacíos).
La primera llamada a C<ntlm()> genera este primer mensaje ignorando
cualquier argumento.
La segunda vez que se llama, se asume que el argumento es
la cadena de desafío enviada por el servidor. Esta contendrá 8
bytes de datos que se utilizan en las funciones DES para generar las
cadenas de autenticación de respuesta. El resultado de la llamada es
la cadena de autenticación final.
Si se llama a C<ntlm_reset()>, la siguiente llamada a C<ntlm()>
iniciará el proceso nuevamente, permitiendo múltiples autenticaciones dentro
de una aplicación.
ntlmv2()
Utiliza la autenticación NTLM v2.

API DE OBJETOS

new %options
Crea un objeto que acepta las siguientes opciones: "user", "host", "domain", "password", "version".
challenge [$challenge]
Si no se proporciona $challenge, se genera la cadena de desafío de primera etapa. De lo contrario, se genera el desafío de tercera etapa, donde se asume que $challenge se extrae de la segunda etapa del intercambio NTLM. El resultado de la llamada es la cadena de autenticación final.
