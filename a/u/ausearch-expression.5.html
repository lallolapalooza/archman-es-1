AUSEARCH-EXPRESSION(5) Auditoría de Linux AUSEARCH-EXPRESSION(5)

NOMBRE

ausearch-expression - formato de expresión de búsqueda de auditoría

DESCRIPCIÓN GENERAL

Esta página del manual describe el formato de las "expresiones de ausearch". El análisis y la evaluación de estas expresiones es proporcionado por libauparse y es común a las aplicaciones que utilizan esta biblioteca.

ESTRUCTURA LÉXICA

El espacio en blanco (espacio ASCII, tabulador y caracteres de nueva línea) entre los tokens se ignora. Se reconocen los siguientes tokens:

Puntuación
( ) \
Operadores lógicos
! && ||
Operadores de comparación
< <= == > >= !== i= i!= r= r!=
Cadenas sin comillas
Cualquier secuencia no vacía de letras ASCII, dígitos y el _ símbolo.
Cadenas con comillas
Una secuencia de caracteres rodeada por las " comillas. El carácter \ inicia una secuencia de escape. Las únicas secuencias de escape definidas son \\ y \". La semántica de otras secuencias de escape no está definida.
Expresiones regulares
Una secuencia de caracteres rodeada por los caracteres / . El carácter \ inicia una secuencia de escape. Las únicas secuencias de escape definidas son \\ y \/. La semántica de otras secuencias de escape no está definida.

En cualquier lugar donde sea válida una cadena sin comillas, también es válida una cadena con comillas, y viceversa. En particular, los nombres de campo pueden especificarse usando cadenas con comillas, y los valores de campo pueden especificarse usando cadenas sin comillas.

SINTAXIS DE LA EXPRESIÓN

La expresión primaria tiene una de las siguientes formas:

campo operador-de-comparación valor

\regexp cadena-o-regexp

campo es una cadena, que especifica el primer campo con ese nombre dentro del registro de auditoría actual, o el carácter de escape \ seguido de una cadena, que especifica un campo virtual con el nombre especificado (los campos virtuales se definen en una sección posterior).

campo es una cadena. operador especifica la comparación a realizar

r= r!=
Obtener la cadena "raw" (cruda) de campo, y compararla con valor. Para los campos en los registros de auditoría, la cadena "raw" es la cadena exacta almacenada en el registro de auditoría (con todo el escape y la codificación de caracteres no imprimibles sin modificar); las aplicaciones pueden leer la cadena "raw" usando auparse_get_field_str(3). Cada campo virtual puede definir una cadena "raw". Si campo no está presente o no define una cadena "raw", el resultado de la comparación es falso (independientemente del operador).
i= i!=
Obtener la cadena "interpreted" (interpretada) de campo, y compararla con valor. Para los campos en los registros de auditoría, la cadena "interpreted" es una interpretación "legible para el usuario" del valor del campo; las aplicaciones pueden leer la cadena "interpreted" usando auparse_interpret_field(3). Cada campo virtual puede definir una cadena "interpreted". Si campo no está presente o no define una cadena "interpreted", el resultado de la comparación es falso (independientemente del operador).
< <= == > >= !==
Evaluar el "value" (valor) de campo, y compararlo con valor. Un "value" puede definirse para cualquier campo o campo virtual, pero actualmente no se define ningún "value" para ningún campo de registro de auditoría. Las reglas de análisis de valor para compararlo con el "value" de campo son específicas para cada campo. Si campo no está presente, el resultado de la comparación es falso (independientemente del operador). Si campo no define un "value", se informa un error al analizar la expresión.

En el caso especial de \regexp regexp-o-cadena, el registro de auditoría actual se toma como una cadena (sin interpretar los valores de los campos), y se compara con regexp-o-cadena. regexp-o-cadena es una expresión regular extendida, usando un token de cadena o regexp (en otras palabras, delimitada por " o /).

Si E1 y E2 son expresiones válidas, entonces ! E1, E1 && E2, y E1 || E2 también son expresiones válidas, con la semántica y prioridades de evaluación habituales de C. Tenga en cuenta que ! campo op valor se interpreta como !(campo op valor), no como (!campo) op valor.

CAMPOS VIRTUALES

Se definen los siguientes campos virtuales:

\timestamp
El valor es la marca de tiempo del evento actual. valor debe tener el formato: 


ts:segundos.mili

donde segundos y mili son números decimales que especifican la parte de segundos y milisegundos de la marca de tiempo, respectivamente.

\timestamp_ex
Esto es similar a \timestamp pero también incluye el número de serie del evento. valor debe tener el formato: 


ts:segundos.mili:serie

donde serie es un número decimal que especifica el número de serie del evento.

\record_type
El valor es el tipo del registro actual. valor es el nombre del tipo de registro, o un número decimal que especifica el tipo.

SEMÁNTICA

La expresión en su conjunto se aplica a un solo registro. La expresión es verdadera para un evento especificado si es verdadera para cualquier registro asociado con el evento.

EJEMPLOS

Como demostración de la semántica del manejo de campos faltantes, la siguiente expresión es verdadera si campo está presente:

(campo r= "") || (campo r!= "")

y la misma expresión rodeada por !( y ) es verdadera si campo no está presente.

DIRECCIONES FUTURAS

Pueden definirse nuevas secuencias de escape para cadenas con comillas.

Para los campos virtuales actualmente definidos que no definen una cadena "raw" o "interpreted", puede añadirse la definición. Por lo tanto, no confíe en el hecho de que comparar la cadena "raw" o "interpreted" del campo con cualquier valor sea falso.

Pueden añadirse nuevos formatos de constantes de valor para el campo virtual \timestamp .

NAME

ausearch-expression - Augeas rule expression syntax

OVERVIEW

The ausearch command is used to query the audit log files. The query criteria can be specified in a simple string format, or in a more complex expression format. This man page describes the expression syntax.

The expression syntax is based on the Augeas rule syntax.

LEXICAL STRUCTURE

Expressions are composed of tokens. The tokens are either:

  • Keywords (e.g., type, msgno, end)
  • Identifiers (e.g., SYSCALL, AVC, fd)
  • Operators (e.g., =, !=, <, >, &, |, ~)
  • Literals (e.g., "open", 123, 0xabc)
  • Punctuation (e.g., (, ), ,)

Whitespace is generally ignored, except within string literals.

EXPRESSION SYNTAX

Expressions are composed of predicates that are combined using logical operators. A predicate is a comparison between a field and a value.

The general syntax is: 

predicate ::= field op value
          | field op field
          | EXISTS field
          | NOT field

op ::= = | != | < | <= | > | >= | ~ | !~

field ::= IDENTIFIER | STRING | NUMBER | VIRTUAL_FIELD
value ::= IDENTIFIER | STRING | NUMBER | VIRTUAL_FIELD

Logical operators:

  • AND (or &&)
  • OR (or ||)
  • NOT (or !)

Parentheses can be used to group expressions.

Example: 

type=SYSCALL msgno=13 AND fd>2

VIRTUAL FIELDS

Virtual fields are not directly present in the audit log records, but are derived from them. They provide a more convenient way to query certain information.

Examples:

  • arch: The architecture of the system.
  • pid: The process ID.
  • uid: The user ID.
  • gid: The group ID.
  • auid: The audit user ID.
  • subj_user, subj_role, subj_type, subj_sec: SELinux subject context.
  • obj_user, obj_role, obj_type, obj_sec: SELinux object context.

SEMANTICS

Fields are matched case-insensitively.

String comparisons are exact.

Numeric comparisons are standard numerical comparisons.

The ~ operator performs a regular expression match.

The !~ operator performs a negated regular expression match.

The EXISTS operator checks if a field is present in the record.

The NOT operator negates the result of a predicate or an expression.

EXAMPLES

Find all syscall records: 

ausearch -X "type=SYSCALL"

Find all AVC denial messages: 

ausearch -X "type=AVC AND class=process AND reason=denied"

Find all records related to process ID 123: 

ausearch -X "pid=123"

Find all records where a file was opened with read permissions: 

ausearch -X "syscall=open AND success=yes AND key=read"

FUTURE DIRECTIONS

The expression syntax is still under development. Future versions may introduce new fields, operators, and features.

AUTHOR

The ausearch command and its expression syntax were developed by the Linux Audit Project.
