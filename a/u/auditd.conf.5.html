AUDITD.CONF(5) Utilidades de Administración del Sistema AUDITD.CONF(5)

NOMBRE

auditd.conf - archivo de configuración del demonio de auditoría

DESCRIPCIÓN

El archivo /etc/audit/auditd.conf contiene información de configuración específica para el demonio de auditoría. Cada línea debe contener una palabra clave de configuración, un signo igual y luego la información de configuración apropiada. Todas las opciones y valores no distinguen entre mayúsculas y minúsculas. Las palabras clave reconocidas se enumeran y describen a continuación. Cada línea debe limitarse a 160 caracteres o se omitirá la línea. Puede agregar comentarios al archivo comenzando la línea con un carácter '#'.

local_events
Esta palabra clave sí/no especifica si se incluyen o no eventos locales. Normalmente quieres eventos locales, por lo que el valor predeterminado es sí. Los casos en los que establecería esto en no son cuando desea agregar eventos solo de la red. Por el momento, esto es útil si el demonio de auditoría se está ejecutando en un contenedor. Esta opción solo se puede establecer una vez al iniciar el demonio. Recargar el archivo de configuración no tiene efecto.
log_file
Esta palabra clave especifica la ruta completa al archivo de registro donde se almacenarán los registros de auditoría. Debe ser un archivo regular. La ruta predeterminada es /var/log/audit/audit.log si no se establece explícitamente.
write_logs
Esta palabra clave sí/no determina si se escriben registros en el disco. Normalmente lo quieres, por lo que el valor predeterminado es sí.
log_format
El formato del registro describe cómo se debe almacenar la información en el disco. Hay 2 opciones: raw (crudo) y enriched (enriquecido). Si se establece en RAW, los registros de auditoría se almacenarán en un formato exactamente como el kernel lo envía. La opción ENRICHED resolverá toda la información de uid, gid, syscall, arquitectura y dirección de socket antes de escribir el evento en el disco. Esto ayuda a comprender los eventos creados en un sistema pero informados/analizados en otro sistema. La opción NOLOG ahora está obsoleta. Si estaba configurando este formato, ahora debería establecer la opción write_logs en no.
log_group
Esta palabra clave especifica el grupo que se aplica a los permisos del archivo de registro. El valor predeterminado es root. El nombre del grupo puede ser numérico o escrito.
priority_boost
Este es un número no negativo que le dice al demonio de auditoría cuánto impulso de prioridad debe tomar. El valor predeterminado es 4. Ningún cambio es 0.
flush
Los valores válidos son none (ninguno), incremental, incremental_async, data y sync. Si se establece en none, no se realiza ningún esfuerzo especial para volcar los registros de auditoría al disco. Si se establece en incremental, el parámetro freq se utiliza para determinar con qué frecuencia se emite un volcado explícito al disco. El parámetro incremental_async es muy similar a incremental excepto que el volcado se realiza de forma asíncrona para un mayor rendimiento. El parámetro data le dice al demonio de auditoría que mantenga la porción de datos del archivo de disco sincronizada en todo momento. La opción sync le dice al demonio de auditoría que mantenga tanto los datos como los metadatos completamente sincronizados con cada escritura en el disco. El valor predeterminado es incremental_async.
freq
Este es un número no negativo que le dice al demonio de auditoría cuántos registros escribir antes de emitir un comando explícito de volcado al disco. Este valor solo es válido cuando la palabra clave flush está establecida en incremental o incremental_async.
num_logs
Esta palabra clave especifica el número de archivos de registro a conservar si se da "rotate" como el max_log_file_action. Si el número es < 2, los registros no se rotan. Este número debe ser 999 o menos. El valor predeterminado es 0, lo que significa que no hay rotación. A medida que aumenta el número de archivos de registro que se rotan, es posible que deba aumentar la configuración de la cola del kernel, ya que lleva más tiempo rotar los archivos. Esto generalmente se hace en /etc/audit/audit.rules. Si la rotación de registros está configurada para ocurrir, el demonio verificará el exceso de registros y los eliminará para mantener el espacio en disco disponible. La verificación del exceso de registros solo se realiza al inicio y cuando una reconfiguración resulta en una verificación de espacio.
name_format
Esta opción controla cómo se insertan los nombres de los nodos de la computadora en el flujo de eventos de auditoría. Tiene las siguientes opciones: none (ninguno), hostname (nombre del host), fqd (nombre de dominio completamente calificado), numeric (numérico) y user (usuario). None significa que no se inserta ningún nombre de computadora en el evento de auditoría. hostname es el nombre devuelto por la llamada al sistema gethostname. fqd significa que toma el nombre del host y lo resuelve con DNS para obtener un nombre de dominio completamente calificado de esa máquina. Numeric es similar a fqd excepto que resuelve la dirección IP de la máquina. Para usar esta opción, es posible que desee probar que 'hostname -i' o 'domainname -i' devuelven una dirección numérica. Además, esta opción no se recomienda si se usa dhcp, ya que podría tener direcciones diferentes con el tiempo para la misma máquina. User es una cadena definida por el administrador de la opción name. El valor predeterminado es none.
name
Esta es la cadena definida por el administrador que identifica la máquina si user se da como la opción name_format.
max_log_file
Esta palabra clave especifica el tamaño máximo del archivo en mebibytes (MiB). Cuando se alcanza este límite, se activará una acción configurable. El valor proporcionado debe ser numérico.
max_log_file_action
Este parámetro le dice al sistema qué acción tomar cuando el sistema ha detectado que se ha alcanzado el límite de tamaño máximo del archivo. Los valores válidos son ignore (ignorar), syslog, exec (ejecutar), suspend (suspender), rotate (rotar) y keep_logs (conservar registros). Si se establece en ignore, el demonio de auditoría no hace nada. syslog significa que emitirá una advertencia a syslog. exec /ruta-a-script ejecutará el script. No se pueden pasar parámetros al script. El script también es responsable de indicar al demonio auditd que reanude el registro una vez que haya completado su acción. Esto se puede hacer agregando auditdctl --signal resume al script. Tenga en cuenta también que el registro se detiene mientras se ejecuta este script. Lo que sea que haga debe ser muy rápido porque los eventos se están acumulando en el kernel. El script DEBE eliminar o renombrar /var/log/audit/audit.log o cuando se reanude el registro, volverá a ejecutar el script. suspend hará que el demonio de auditoría deje de escribir registros en el disco. El demonio seguirá activo. La opción rotate hará que el demonio de auditoría rote los registros. Cabe señalar que los registros con números más altos son más antiguos que los registros con números más bajos. Esta es la misma convención utilizada por la utilidad logrotate. La opción keep_logs es similar a rotate, excepto que no utiliza la configuración num_logs. Esto evita que se sobrescriban los registros de auditoría. El efecto es que los registros se acumulan y no se eliminan, lo que activará space_left_action si el volumen se llena. Esto se usa mejor en combinación con un script externo utilizado para archivar registros de forma periódica.
verify_email
Esta opción determina si la dirección de correo electrónico dada en action_mail_acct se verifica para ver si se puede resolver el nombre de dominio. Esta opción debe proporcionarse antes de action_mail_acct o se utilizará el valor predeterminado de sí.
action_mail_acct
Esta opción debe contener una dirección de correo electrónico o alias válido. Las direcciones pueden usar subdirecciones de estilo RFC 5233 con el carácter '+'. Los caracteres permitidos son alfanuméricos, '@', '.', '-', '_' y '+'. La dirección predeterminada es root. Si la dirección de correo electrónico no es local a la máquina, debe asegurarse de tener el correo electrónico configurado correctamente en su máquina y red. Esta opción requiere que exista /usr/lib/sendmail en la máquina. Muchos clientes lo proporcionan como un enlace simbólico.
space_left
Si el espacio libre en el sistema de archivos que contiene log_file cae por debajo de este valor, el demonio de auditoría toma la acción especificada por space_left_action. Si el valor de space_left se especifica como un número entero, se interpreta

Si el valor se especifica como un número entre 1 y 99 seguido de un signo de porcentaje (por ejemplo, 5%), el demonio de auditoría calcula el tamaño absoluto en mebibytes basándose en el tamaño del sistema de archivos que contiene log_file. Los valores válidos son ignore, syslog, rotate, email, exec, suspend, y single. Si se establece en ignore, el demonio de auditoría no hace nada. syslog significa que emitirá una advertencia a syslog. rotate rotará los registros, descartando los más antiguos para liberar espacio. Las notificaciones de espacio en disco siguen una progresión de tres etapas. El space_left_action es la marca de agua baja y sirve como la primera advertencia de que el espacio en disco está bajando. No se recomienda detener el sistema en esta etapa, ya que impide que los administradores tomen medidas correctivas. La siguiente etapa, admin_space_left_action, indica un nivel de emergencia donde se requiere acción inmediata para liberar espacio en disco. Los administradores deben configurar respuestas críticas para este nivel. Finalmente, el disk_full_action ocurre cuando el disco está completamente lleno. En esta etapa, el sistema puede haberse detenido ya, y las medidas preventivas configuradas en etapas anteriores determinarán el comportamiento

NOTA

S

En un entorno CAPP, la pista de auditoría se considera tan importante que se debe denegar el acceso a los recursos del sistema si no se puede crear una pista de auditoría. En este entorno, se sugeriría que /var/log/audit esté en su propia partición. Esto es para asegurar que la detección de espacio sea precisa y que ningún otro proceso venga y consuma parte de

él.

El parámetro flush debe establecerse en sync o

data.

Max_log_file y num_logs deben ajustarse para que obtenga el uso completo de su partición. Debe tenerse en cuenta que cuanto más archivos deban rotarse, más tiempo se tarda en volver a recibir eventos de auditoría. Max_log_file_action debe establecerse en

keep_logs.

Space_left debe establecerse en un número que le dé al administrador suficiente tiempo para reaccionar a cualquier mensaje de alerta y realizar algún mantenimiento para liberar espacio en disco. Esto normalmente implicaría ejecutar el informe aureport -t y mover los registros más antiguos a un área de archivo. El valor de space_left depende del sitio, ya que la tasa a la que se generan los eventos varía con cada implementación. Se recomienda establecer space_left_action en email. Si necesita algo como una trampa snmp, puede usar la opción exec para enviar

una.

Admin_space_left debe establecerse en la cantidad de espacio en disco en la partición de auditoría necesaria para que se registren las acciones de administración. Admin_space_left_action se establecería en single para que el uso de la máquina se restrinja solo a la

consola.

La acción disk_full_action se activa cuando ya no queda espacio en la partición. Todo el acceso debe terminarse ya que no existe más capacidad de auditoría. Esto se puede establecer en single o

halt.

La acción disk_error_action debe establecerse en syslog, single o halt dependiendo de sus políticas locales con respecto al manejo de malfunctions de

hardware.

Especificar un único puerto de cliente permitido puede dificultar que el cliente reinicie su subsistema de auditoría, ya que no podrá recrear una conexión con las mismas direcciones y puertos del host hasta que el estado TIME_WAIT de cierre de conexión

expire.

Los eventos de auditd están compuestos por uno o más registros. El sistema auditd no puede garantizar que el conjunto de registros que componen un evento ocurrirá de forma atómica, es decir, el flujo tendrá registros entrelazados de diferentes eventos, es

decir

event0_record0
event1_record0
event2_record0
event1_record3
event2_record1
event1_record4
event3_record0

El sistema auditd no garantiza que los registros que componen un evento aparezcan en orden. Por lo tanto, al procesar flujos de eventos, necesitamos mantener una lista de eventos con su propia lista de registros, por lo tanto, procesamiento de eventos de Lista de Listas (LOL)

.
