La directiva "autodie" proporciona una manera conveniente de reemplazar funciones que normalmente devuelven false en caso de fallo con equivalentes que lanzan una excepción en caso de

La directiva "autodie" tiene ámbito léxico, lo que significa que las funciones y subrutinas alteradas con "autodie" solo cambiarán su comportamiento hasta el final del bloque, archivo o "eval" que los c

ontiene.

Si "system" se especifica como un argumento para "autodie", entonces usa IPC::System::Simple para hacer el trabajo

EXCEPCIONE

S

Las excepciones producidas por la directiva "autodie" son miembros de la clase autodie::exception. La manera preferida de trabajar con estas excepciones bajo Perl 5.10 es la

siguiente: 
eval {
    use autodie;
    open(my $fh, '<', $some_file);
    my @records = <$fh>;
    # Hacer cosas con @records...
    close($fh);
};
if ($@ and $@->isa('autodie::exception')) {
    if ($@->matches('open')) { print "Error from open\n";   }
    if ($@->matches(':io' )) { print "Non-open, IO error."; }
} elsif ($@) {
    # Una excepción que no es de autodie.
}

NAME

autodie — make built-in functions die on error

SYNOPSIS

    use autodie;
    use autodie qw(open close unlink);
    use autodie     (
        :all,
        open    => 0,
        close   => 1,
        unlink  => 1,
        'system' => 'STRICT',
        'exec'   => 'LENIENT',
    );
    use autodie qw(:system 1);
    no autodie;
    no autodie qw(open unlink);

DESCRIPTION

The autodie module is a convenience module that makes many Perl built-in functions die when they would normally return false (and set $!). This is the same behaviour as use File::Spec::Unix; use Fatal qw(...);, but with less typing.

The module exports nothing by default. It is imported with keywords, eg use autodie; which imports the default set of functions, or use autodie qw(open close unlink); which imports only those functions. You can also import a category, such as :all (all functions), :system" (system, exec, exec), :io (open, close, print, printf, say, sysopen, sysread, syswrite, seek, tell, binmode, select, fileno, mkdir, rmdir, chdir, chmod, chown), :file" (unlink, rename, utime), :net (socket, accept, connect, bind, listen), :fs" (stat, lstat, chmod, chown, mkdir, rmdir, link, symlink, readlink, chdir, rename, unlink, umask), :sh" (system, exec, fork, pipe, open, close), :strict" (all functions, except for those explicitly disabled), or :system" (system, exec, exec), :io" (open, close, print, printf, say, sysopen, sysread, syswrite, seek, tell, binmode, select, fileno, mkdir, rmdir, chdir, chmod, chown), :file" (unlink, rename, utime), :net" (socket, accept, connect, bind, listen), :fs" (stat, lstat, chmod, chown, mkdir, rmdir, link, symlink, readlink, chdir, rename, unlink, umask), :sh" (system, exec, fork, pipe, open, close), :strict" (all functions, except for those explicitly disabled), or :safe" (all functions). You can disable specific functions with a zero value, eg use autodie qw(open => 0); You can also enable specific functions with a non-zero value, eg use autodie qw(open => 1);.

You can also pass flags to modify the behaviour of autodie. These flags must be provided as named arguments, not as barewords. Eg:

    use autodie (:system => 1); # enable system, exec, wait, waitpid etc.

You can also pass a scalar value to override the default exception handler. For example, to use the exception handler from Fatal::Error:

    use autodie (:all => &Fatal::Error);

Or to use the exception handler from autodie::exception:

    use autodie (:all => &autodie::exception);

Or to use your own custom exception handler:

    sub my_die { die "Bad thing: $_[0]\n" }
    use autodie (:all => \&my_die);

To disable autodie for a specific block of code, use no autodie;.

    use autodie;
    # ... code that might die ...
    {
        no autodie;
        # ... code that might die, but won't ...
    }
    # ... code that might die, and will ...

To disable autodie for specific functions within a block:

    use autodie;
    # ... code that might die ...
    {
        no autodie qw(open unlink);
        # ... open and unlink won't die ...
    }
    # ... open and unlink will die ...

EXCEPTIONS

autodie uses autodie::exception by default. You can change this by passing a hash argument to autodie:

    use autodie (:all => &My::ExceptionHandler);

The exception handler will be called with the same arguments as the built-in function would have received, and it should return the same value as the built-in function would have returned on success. If the built-in function would have died, the exception handler will be called with a single argument: the error message string.

CATEGORIES

The following categories are available:

:all
All functions that autodie knows about.
:io
Input/Output functions: open, close, print, printf, say, sysopen, sysread, syswrite, seek, tell, binmode, select, fileno, mkdir, rmdir, chdir, chmod, chown.
:fs
Filesystem functions: stat, lstat, chmod, chown, mkdir, rmdir, link, symlink, readlink, chdir, rename, unlink, umask.
:net
Networking functions: socket, accept, connect, bind, listen.
:sh
Shell functions: system, exec, fork, pipe, open, close.
:system
System functions: system, exec, wait, waitpid, exec.
:file
File functions: unlink, rename, utime.
:strict
All functions, except those explicitly disabled. By default, open and close are disabled. You can enable them explicitly:
    use autodie qw(:strict open close);

Or disable functions that you don't want:

    use autodie qw(:strict unlink => 0);

:safe

All functions that autodie knows about, including open and close.

FUNCTION SPECIFIC NOTES

This section describes notes specific to certain functions.

open

By default, autodie does not install an exception handler for open. This is because the most common use of open is in list context, where it returns a filehandle which autodie cannot intercept.

To enable autodie for open, you must explicitly request it:

    use autodie qw(open);

This will only affect calls to open in scalar context:

    my $fh = open(my $filename, '<'); # dies if open fails
    print $fh "hello\n";
    
    open(my $filename, '>') or die $!; # Does not die automatically

Note that autodie does not intercept open when it is used to create a directory handle. Use opendir instead.

close

By default, autodie does not install an exception handler for close. This is because the most common use of close is in list context, where it returns a boolean which autodie cannot intercept.

To enable autodie for close, you must explicitly request it:

    use autodie qw(close);

This will only affect calls to close in scalar context:

    close($fh);       # dies if close fails
    close($fh) or die $!; # Does not die automatically

GOTCHAS

Perl built-ins are implemented in C, and autodie uses caller() to determine the calling package. If you use autodie inside a module, and then call the autodied function from your main script, autodie will think it's in your main script, not your module.

To work around this, you can import autodie into a specific namespace:

    package MyModule;
    use autodie;
    # ...

Or you can import autodie explicitly into the current namespace:

    package MyModule;
    use MyModule::autodie; # Assuming you created this file
    # ...

The autodie module will not wrap functions that are called via goto &{$subref}.

The chdir function has a special case. If you call chdir 'some/dir', it will be treated as a bareword filehandle, and if use strict is in effect, it will be a syntax error. Without use strict, it will be interpreted as a filename.

Without autodie (and assuming BAREWORD is an open filehandle/dirhandle) this is a valid call to chdir. But under autodie, "chdir" will behave like it had the prototype ";$" and thus BAREWORD will be a syntax error (under "use strict". Without strict, it will interpreted as a filename).

DIAGNOSTICS

:void cannot be used with lexical scope
The ":void" option is supported in Fatal, but not "autodie". To workaround this, "autodie" may be explicitly disabled until the end of the current block with "no autodie". To disable autodie for only a single function (eg, open) use "no autodie qw(open)".

"autodie" performs no checking of called context to determine whether to throw an exception; the explicitness of error handling with "autodie" is a deliberate feature.

No user hints defined for %s
You've insisted on hints for user-subroutines, either by pre-pending a "!" to the subroutine name itself, or earlier in the list of arguments to "autodie". However the subroutine in question does not have any hints available.

See also "DIAGNOSTICS" in Fatal.

Tips and Tricks

Importing autodie into another namespace than "caller"

It is possible to import autodie into a different namespace by using Import::Into. However, you have to pass a "caller depth" (rather than a package name) for this to work correctly.

BUGS

"Used only once" warnings can be generated when "autodie" or "Fatal" is used with package filehandles (eg, "FILE"). Scalar filehandles are strongly recommended instead.

When using "autodie" or "Fatal" with user subroutines, the declaration of those subroutines must appear before the first use of "Fatal" or "autodie", or have been exported from a module. Attempting to use "Fatal" or "autodie" on other user subroutines will result in a compile-time error.

Due to a bug in Perl, "autodie" may "lose" any format which has the same name as an autodying built-in or function.

"autodie" may not work correctly if used inside a file with a name that looks like a string eval, such as eval (3).

autodie and string eval

Due to the current implementation of "autodie", unexpected results may be seen when used near or with the string version of eval. None of these bugs exist when using block eval.

Under Perl 5.8 only, "autodie" does not propagate into string "eval" statements, although it can be explicitly enabled inside a string "eval".

Under Perl 5.10 only, using a string eval when "autodie" is in effect can cause the autodie behaviour to leak into the surrounding scope. This can be worked around by using a "no autodie" at the end of the scope to explicitly remove autodie's effects, or by avoiding the use of string eval.

None of these bugs exist when using block eval. The use of "autodie" with block eval is considered good practice.
