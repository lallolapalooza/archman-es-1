autodie::exception(3perl) Guía del programador de Perl autodie::exception(3perl)

NOMBRE

autodie::exception - Excepciones de funciones de autodiección.

SINOPSIS

eval {
    use autodie;
    open(my $fh, '<', 'some_file.txt');
    ...
};
if (my $E = $@) {
    say "¡Ups!  ",$E->caller," tuvo problemas: $@";
}

DESCRIPCIÓN

Cuando una función habilitada para autodie falla, genera un objeto "autodie::exception". Este objeto puede ser interrogado para obtener información adicional sobre el error ocurrido.

Este documento se divide en dos secciones; aquellos métodos que son más útiles para el desarrollador final, y aquellos métodos para cualquiera que desee subclass o familiarizarse mucho con "autodie::exception".

Métodos Comunes

Estos métodos están diseñados para ser utilizados en el manejo diario de excepciones.

Los siguientes asumen que el error ha sido copiado a un escalar separado:

if ($E = $@) {
    ...
}

Esto no es obligatorio, pero se recomienda en caso de que se llame a algún código que pueda restablecer o alterar $@.

args

my $array_ref = $E->args;

Proporciona una referencia a los argumentos pasados a la subrutina que falló.

function

my $sub = $E->function;

La subrutina (incluyendo el paquete) que lanzó la excepción.

file

my $file = $E->file;

El archivo en el que ocurrió el error (ej., "myscript.pl" o "MyTest.pm").

package

my $package = $E->package;

El paquete desde el cual se llamó a la subrutina excepcional.

caller

my $caller = $E->caller;

La subrutina que llamó al código excepcional.

line

my $line = $E->line;

La línea en "$E->file" donde se llamó al código excepcional.

context

my $context = $E->context;

El contexto en el que la subrutina fue llamada por autodie; generalmente el mismo contexto en el que llamaste a la subrutina de autodiección. Este puede ser 'list', 'scalar', o indefinido (desconocido). Nunca será 'void', ya que "autodie" siempre captura el valor de retorno de una forma u otra.

Para algunas funciones principales que siempre devuelven un valor escalar independientemente de su contexto (ej., "chown"), este podría ser 'scalar', incluso si usaste un contexto de lista.

return

my $return_value = $E->return;

El valor o valores devueltos por la subrutina fallida. Cuando la subrutina fue llamada en un contexto de lista, esta siempre será una referencia a un array que contiene los resultados. Cuando la subrutina fue llamada en un contexto escalar, este será el escalar real devuelto.

errno

my $errno = $E->errno;

El valor de $! en el momento en que ocurrió la excepción.

NOTA: Este método dejará la clase principal "autodie::exception" y pasará a ser parte de un rol en el futuro. Solo debes llamar a "errno" para excepciones donde $! se habría establecido razonablemente en caso de fallo.

eval_error

my $old_eval_error = $E->eval_error;

El contenido de $@ inmediatamente después de que autodie activara una excepción. Esto puede ser útil al tratar con módulos como Text::Balanced que establecen (pero no lanzan) $@ en caso de error.

matches

if ( $e->matches('open') ) { ... }
if ( 'open' ~~ $e ) { ... }

"matches" se utiliza para determinar si una excepción dada coincide con un rol particular.

Una excepción se considera que coincide con una cadena si:

  • Para una cadena que no comienza con dos puntos, la cadena coincide exactamente con el paquete y la subrutina que lanzó la excepción. Por ejemplo, "MyModule::log". Si la cadena no contiene un nombre de paquete, se asume "CORE::".
  • Para una cadena que comienza con dos puntos, si la subrutina que lanza la excepción tiene ese comportamiento. Por ejemplo, la subrutina "CORE::open" tiene ":file", ":io" y ":all".

    Ver "CATEGORIES" en autodie para más información.

    En Perl 5.10 y superior, el uso de smart-match ("~~") con un objeto "autodie::exception" utilizará "matches" internamente. Este módulo solía recomendar el uso de smart-match con el objeto de excepción en el lado izquierdo, pero en futuras versiones de Perl es probable que deje de funcionar. El uso de smart-match de esta clase solo debe usarse con el objeto de excepción en el lado derecho. Tener el objeto de excepción en el lado derecho es a prueba de futuro y portable a versiones antiguas de Perl, desde la 5.10. Tenga en cuenta que esta característica solo se puede confiar cuando se tiene la certeza de que el objeto de excepción es realmente un objeto "autodie::exception"; no es más capaz que una llamada explícita al método "matches".

Métodos Avanzados

Los siguientes métodos, aunque utilizables desde cualquier lugar, están principalmente destinados a desarrolladores que deseen subclassizar "autodie::exception", escribir código que registre mensajes de error personalizados o, de otro modo, trabajar estrechamente con el modelo de "autodie::exception".

register

autodie::exception->register( 'CORE::open' => \&mysub );

El método "register" permite el registro de un manejador de mensajes para una subrutina dada. Se debe usar el nombre completo de la subrutina, incluido el paquete.

Los manejadores de mensajes registrados recibirán el objeto "autodie::exception" como primer parámetro.

add_file_and_line

say "Problema ocurrido",$@->add_file_and_line;

Devuelve la cadena " at %s line %d", donde %s se reemplaza con el nombre del archivo y %d con el número de línea.

Principalmente destinado para ser utilizado por manejadores de formato.

stringify

say "El error fue: ",$@->stringify;

Formatea el error como una cadena legible por humanos. Normalmente no hay razón para llamar a esto directamente, ya que se usa automáticamente si un objeto "autodie::exception" se usa alguna vez como cadena.

Las clases hijas pueden sobrescribir este método para cambiar cómo se convierten en cadenas.

format_default

my $error_string = $E->format_default;

Esto produce la cadena de error predeterminada para la excepción dada, sin usar ningún manejador de mensajes registrado. Está destinado principalmente a ser llamado desde un manejador de mensajes cuando se les ha pasado una excepción que no quieren formatear.

Las clases hijas pueden sobrescribir este método para cambiar cómo se formatean los mensajes predeterminados.

new

my $error = autodie::exception->new(
    args => \@_,
    function => "CORE::open",
    errno => $!,
    context => 'scalar',
    return => undef,
);

Crea un nuevo objeto "autodie::exception". Normalmente llamado directamente desde una función de autodiección. El argumento "function" es obligatorio, es la función que estábamos intentando llamar y que generó la excepción. El parámetro "args" es opcional.

El valor de "errno" es opcional. En versiones de "autodie::exception" 1.99 y anteriores, el código intentaba usar automáticamente el valor actual de $!, pero esto no era confiable y ya no se soporta.
