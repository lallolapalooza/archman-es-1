DESCRIPCIÓ

N

El módulo "Authen::Radius" proporciona una clase simple que le permite en

viar/recibir solicitudes/respuest
as Radius a/desde un servidor Radius.

CONSTRUCTO

R
new ( Host => HOST, Secret => SECRET [, TimeOut => TIMEOUT] [,Service => SERVICE] [, Debug => Bool] [, LocalAddr => hostname[:port]] [,Rfc3579MessageAuth => Bool] [,NodeList= NodeListArrayRef]
)
Crea y devuelve una referencia bendecida a un objeto Radius, o undef en caso de fallo. El estado de error se puede obtener con "Authen::Radius::get_error" (código de error) o "Authen::Radius::strerror" (cadena de error detallada).

El "Service" por defecto es "radius", la alternativa es "radius-acct". Si no especifica el puerto en "Host" como "hostname:puerto", se usará el puerto especificado en su /etc/services. Si no hay nada allí, y tampoco especificó el puerto, el valor predeterminado es 1645 para "radius" y 1813 para "radius-a

cct".

El parámetro opcional "Debug" con un valor "verdadero" de Perl activa la depuración (modo detallado)

.

El parámetro opcional "LocalAddr" puede contener la dirección de enlace local de IP/host desde la que se envían los paquetes

RADIUS.

El parámetro opcional "Rfc3579MessageAuth" con un valor "verdadero" de Perl activa la generación de Message-Authenticator para Access-Request (RFC3579, sección 3.2). El Message-Authenticator se genera siempre para los paquetes

Status-Server.

El parámetro opcional "NodeList" puede contener una referencia de Perl a un array, que contiene una lista de nodos de clúster Radius. Cada nodo de la lista se puede especificar usando un nombre de host o una IP (con un número de puerto opcional), es decir, 'radius1.mytel.com' o 'radius.myhost.com:1812'. Un clúster Radius contiene un conjunto de servidores Radius, en cualquier momento dado solo se considera que un servidor está "activo" (por lo que las solicitudes se envían a este servidor). ¿Cómo se determina el nodo activo? Inicialmente, además del parámetro "NodeList", puede proporcionar el parámetro "Host" y especificar qué servidor debe convertirse en el primer nodo activo. Si este parámetro está ausente,

o el nodo activo actual ya no responde, se realizar
á el proceso de "descubrimiento": se enviará una s
olicitud a todos los nodos y la comunicación conse
cutiva continuará con el nodo que responda primero.

load_dictionary ( [ DICTIONARY ], [format => 'freeradius' | 'gnuradius']
)
Carga las definiciones en el archivo de diccionario Radius especificado (formato estándar Livingston radiusd). Intenta cargar "/etc/raddb/dictionary" cuando no se especifica ningún argumento, o termina con error. Se debe especificar "format" si el diccionario tiene otro formato (actualmente soportados: FreeRADIUS y GNU Radius)

NOTA: necesita cargar un diccionario válido si planea enviar solicitudes RADIUS con atributos distintos de "User-Name"/"Passwo

rd
".
check_pwd ( USERNAME, PASSWORD [,NASIPADDRESS]
)
Comprueba con el servidor RADIUS si la "PASSWORD" especificada es válida para el usuario "USERNAME". A menos que se especifique "NASIPADDRESS", el script intentará determinar su dirección IP local (dirección IP para el socket RADIUS) y este valor se colocará en el atributo NAS-IP-Address. Este método es en realidad un envoltorio para las llamadas posteriores a "clear_attributes", "add_attributes", "send_packet" y "recv_packet". Devuelve 1 si la "PASSWORD" es correcta, o undef en caso
contrario.
add_attributes ( { Name => NAME, Value => VALUE [, Type => TYPE] [, Vendor => VENDOR] [, Tag => TAG ] }, ..
. )
Añade cualquier número de atributos Radius al objeto Radius actual. Los atributos se especifican como una lista de hashes anónimos. Pueden tener "Name" con su nombre de diccionario (siempre que se haya cargado primero un diccionario), o con sus valores de tipo de atributo Radius sin procesar. El par "Type" debe especificarse al añadir atributos que no están en el diccionario (o cuando no se cargó ningún diccionario). Los valores para "TYPE" pueden ser '"string"', '"integer"', '"ipaddr"', '"ipv6addr"', '"ipv6prefix"', '"ifid"' o '"avpair"'. El "VENDOR" puede ser el nombre del proveedor del diccionario o su identificador entero. Para atributos etiquetados (RFC2868), la etiqueta se puede especificar en "Name" usando el formato 'Name:Tag', o usando el par "Tag". Se espera que el valor de TAG sea un entero, dentro del rango [1:31] (el valor cero no está soportado)
.
get_attribut
es
Devuelve una lista de referencias a hashes anónimos con los siguientes pares clave/valor : { Name => NAME, Code => RAWTYPE, Value => VALUE, RawValue => RAWVALUE, Vendor => VENDOR, Tag => TAG, AttrName => NAME }. Cada hash representa un atributo en el objeto actual. Los pares "Name" y "Value" contendrán valores tal como los tradujo el diccionario (si se cargó uno). Los pares "Code" y "RawValue" siempre contienen el tipo de atributo sin procesar y el valor tal como se recibieron del servidor. Si algún atributo no existe en el diccionario o el tipo de atributo no está especificado, entonces el "Value" correspondiente es indefinido y "Name" se establece al ID del atributo (valor de "Code"). Para un atributo etiquetado (RFC2868), incluirá la etiqueta en el "NAME" como 'Name:Tag'. El nombre original se almacena en "AttrName". También el valor de la etiqueta se almacena en "Tag" (undef para atributos no etiquetados)
.

send_packet ( REQUEST_TYPE, RETRANSMIT
)
Empaqueta un paquete Radius basado en el secreto actual y los atributos y lo envía al servidor con un tipo de solicitud de "REQUEST_TYPE". Los métodos exportados "REQUEST_TYPE" son "ACCESS_REQUEST", "ACCESS_ACCEPT", "ACCESS_REJECT", "ACCESS_CHALLENGE", "ACCOUNTING_REQUEST", "ACCOUNTING_RESPONSE", "ACCOUNTING_STATUS", "STATUS_SERVER", "DISCONNECT_REQUEST", "DISCONNECT_ACCEPT", "DISCONNECT_REJECT", "COA_REQUEST", "COA_ACCEPT", "COA_REJECT", "COA_ACK", y "COA_NAK". Devuelve el número de bytes enviados, o undef en caso de fallo.

Si se proporciona el parámetro RETRANSMIT y contiene un valor distinto de cero

, se considera que estamos reenviando la solicitud, que ya fue enviada previam
ente. En este caso se utiliza el valor anterior del identificador del paquete.
recv_packet ( DETECT_BAD_ID
)
Recibe un paquete de respuesta Radius. Devuelve el tipo de respuesta Radius (vea los valores posibles para "REQUEST_TYPE" en el método "send_packet") o undef en caso de fallo. Tenga en cuenta que el fallo puede deberse a un recv() fallido o a un autenticador de respuesta Radius incorrecto. Utilice "get_error" para averiguarlo.

Si se proporciona el parámetro DETECT_BAD_ID y contiene un valor distinto de cero, se realiza el cálculo del identificador del paquete antes de la comprobación del autenticador y se devuelve el error EBADID en el caso de que el identificador del paquete de la respuesta no coincida con el de la solicitud. Si DETECT_BAD_ID no se proporciona o contiene un valor cero, se devuelve EBADAUTH en

tal
