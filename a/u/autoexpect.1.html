autoexpect(1)

Paquete: expect

Licencias: custom

AUTOEXPECT(1) Manual de Comandos Generales AUTOEXPECT(1))

NOMBRE

autoexpect - genera un script de Expect observando una sesión

SINOPSIS

autoexpect [ args ] [ programa args... ]

INTRODUCCIÓN

autoexpect te observa interactuando con otro programa y crea un script de Expect que reproduce tus interacciones. Para scripts lineales, autoexpect ahorra una cantidad considerable de tiempo en comparación con escribir scripts a mano. Incluso si eres un experto en Expect, encontrarás conveniente usar autoexpect para automatizar las partes más mecánicas de las interacciones. Es mucho más fácil cortar/pegar trozos de scripts de autoexpect que escribirlos desde cero. Y si eres un principiante, podrías salirte con la tuya aprendiendo poco más sobre Expect que cómo llamar a autoexpect.

La forma más sencilla de usar autoexpect es llamarlo desde la línea de comandos sin argumentos. Por ejemplo:

% autoexpect

De forma predeterminada, autoexpect genera un shell para ti. Dado un nombre de programa y argumentos, autoexpect genera ese programa. Por ejemplo:

% autoexpect ftp ftp.cme.nist.gov

Una vez que tu programa generado esté en ejecución, interactúa normalmente. Cuando hayas salido del shell (o del programa que especificaste), autoexpect creará un nuevo script para ti. De forma predeterminada, autoexpect escribe el nuevo script en "script.exp". Puedes anular esto con el indicador -f seguido de un nuevo nombre de script.

El siguiente ejemplo ejecuta "ftp ftp.cme.nist.gov" y almacena el script de Expect resultante en el archivo "nist".

% autoexpect -f nist ftp ftp.cme.nist.gov
Es importante entender que autoexpect no garantiza un script funcional porque necesariamente tiene que adivinar ciertas cosas, y ocasionalmente se equivoca. Sin embargo, normalmente es muy fácil identificar y corregir estos problemas. Los problemas típicos son:
•
Sincronización (Timing). Un número sorprendentemente grande de programas (rn, ksh, zsh, telnet, etc.) y dispositivos (por ejemplo, módems) ignoran las pulsaciones de teclas que llegan "demasiado rápido" después de los prompts. Si encuentras que tu nuevo script se cuelga en un punto, intenta añadir un sleep corto justo antes del send anterior.

Puedes forzar este comportamiento en todo momento anulando la variable "force_conservative" cerca del principio del script generado. Este modo "conservador" hace que autoexpect pause automáticamente brevemente (una décima de segundo) antes de enviar cada carácter. Esto calma a todos los programas que conozco.

Este modo conservador es útil si solo quieres asegurarte rápidamente de que el problema es de sincronización (o si realmente no te importa qué tan rápido se ejecute el script). Este mismo modo se puede forzar antes de la generación del script usando el indicador -c.

Afortunadamente, estos puntos de sincronización son raros. Por ejemplo, telnet ignora caracteres solo después de entrar en su secuencia de escape. Los módems solo ignoran caracteres inmediatamente después de conectarse a ellos por primera vez. Algunos programas muestran este comportamiento todo el tiempo pero normalmente tienen un interruptor para desactivarlo. Por ejemplo, el indicador -T de rn desactiva este comportamiento.

El siguiente ejemplo inicia autoexpect en modo conservador.

autoexpect -c
El indicador -C define una tecla para alternar el modo conservador. El siguiente ejemplo inicia autoexpect (en modo no conservador) con ^L como alternador. (Ten en cuenta que el ^L se introduce literalmente, es decir, introduce un control-L real). 
autoexpect -C ^L
El siguiente ejemplo inicia autoexpect en modo conservador con ^L como alternador. 
autoexpect -c -C ^L
•
Eco. Muchos programas hacen eco de los caracteres. Por ejemplo, si escribes "more" en un shell, lo que autoexpect realmente ve es: 
tú escribiste 'm',
el ordenador escribió 'm',
tú escribiste 'o',
el ordenador escribió 'o',
tú escribiste 'r',
el ordenador escribió 'r',
...

Sin conocimiento específico del programa, es imposible saber si estás esperando ver cada carácter con eco antes de escribir el siguiente. Si autoexpect ve caracteres con eco, asume que puede enviarlos todos como un grupo en lugar de intercalarlos de la manera en que aparecían originalmente. Esto hace que el script sea más agradable de leer. Sin embargo, podría concebiblemente ser incorrecto si realmente tuvieras que esperar ver cada carácter con eco.

•
Cambio. Autoexpect registra cada carácter de la interacción en el script. Esto es deseable porque te da la capacidad de hacer juicios sobre qué es importante y qué puede reemplazarse con una coincidencia de patrón.

Por otro lado, si usas comandos cuya salida difiere de una ejecución a otra, los scripts generados no serán correctos. Por ejemplo, el comando "date" siempre produce una salida diferente. Así que usar el comando date mientras ejecutas autoexpect es una forma segura de producir un script que requerirá edición para funcionar.

El indicador -p pone a autoexpect en "modo prompt". En este modo, autoexpect solo buscará la última línea de la salida del programa, que normalmente es el prompt. Esto maneja el problema de date (ver arriba) y la mayoría de los demás.

El siguiente ejemplo inicia autoexpect en modo prompt.

autoexpect -p
El indicador -P define una tecla para alternar el modo prompt. El siguiente ejemplo inicia autoexpect (en modo no prompt) con ^P como alternador. Ten en cuenta que el ^P se introduce literalmente, es decir, introduce un control-P real. 
autoexpect -P ^P
El siguiente ejemplo inicia autoexpect en modo prompt con ^P como alternador. 
autoexpect -p -P ^P

OTROS INDICADORES

El -quiet indicador desactiva los mensajes informativos producidos por autoexpect.

El -Q indicador nombra un carácter de cita que puede usarse para introducir caracteres que autoexpect consumiría de otro modo porque se usan como alternadores.

El siguiente ejemplo muestra varios indicadores con la cita usada para proporcionar una forma de introducir los alternadores literalmente.

autoexpect -P ^P -C ^L -Q ^Q

ESTILO

No sé si existe un "estilo" para los programas de Expect, pero autoexpect definitivamente no debe tomarse como modelo de estilo. Por ejemplo, autoexpect usa características de Expect que están destinadas específicamente para la generación automática de scripts. Así que no intentes escribir fielmente scripts que parezcan como si hubieran sido generados por autoexpect. Esto no es útil.

Por otro lado, los scripts de autoexpect sí muestran algunas cosas valiosas. Por ejemplo, puedes ver cómo cualquier cadena debe citarse para usarse en un script Tcl simplemente pasando las cadenas por autoexpect.
