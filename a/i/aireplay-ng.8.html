AIREPLAY-NG(8) Manual del Administrador del Sistema AIREPLAY-NG(8)

NOMBRE

aireplay-ng - inyecta paquetes en una red inalámbrica para generar tráfico

SINOPSIS

aireplay-ng [opciones] <interfaz de retransmisión>

DESCRIPCIÓN

aireplay-ng se utiliza para inyectar/retransmitir tramas. La función principal es generar tráfico para su uso posterior en aircrack-ng para descifrar las claves WEP y WPA-PSK. Existen diferentes ataques que pueden provocar desautenticaciones con el propósito de capturar datos del enlace WPA, autenticaciones falsas, retransmisión interactiva de paquetes, inyección de solicitudes ARP manipuladas manualmente y reinyección de solicitudes ARP. Con la herramienta packetforge-ng es posible crear tramas arbitrarias.

aireplay-ng admite la inyección/monitorización con una sola tarjeta de red.

Esta característica requiere parchear el controlador.

OPCIONES

-H, --help
Muestra la pantalla de ayuda.
Opciones de filtro:
-b <bssid>
Dirección MAC del punto de acceso.
-d <dmac>
Dirección MAC de destino.
-s <smac>
Dirección MAC de origen.
-m <len>
Longitud mínima del paquete.
-n <len>
Longitud máxima del paquete.
-u <type>
Control de trama, campo de tipo.
-v <subt>
Control de trama, campo de subtipo.
-t <tods>
Control de trama, bit "To" DS (0 o 1).
-f <fromds>
Control de trama, bit "From" DS (0 o 1).
-w <iswep>
Control de trama, bit WEP (0 o 1).
-D
Desactiva la detección de AP.
Opciones de retransmisión:
-x <nbpps>
Número de paquetes por segundo.
-p <fctrl>
Establece la palabra de control de trama (hex).
-a <bssid>
Establece la dirección MAC del punto de acceso.
-c <dmac>
Establece la dirección MAC de destino.
-h <smac>
Establece la dirección MAC de origen.
-g <nb_packets>
Cambia el tamaño del búfer circular (predeterminado: 8 paquetes). El mínimo es 1.
-F
Elige el primer paquete coincidente.
-e <essid>
Ataque de autenticación falsa: Establece el SSID de destino (ver abajo). Para SSID que contienen caracteres especiales, ver https://www.aircrack-ng.org/doku.php?id=faq#how_to_use_spaces_double_quote_and_single_quote_etc_in_ap_names
-o <npackets>
Ataque de autenticación falsa: Establece el número de paquetes para cada intento de autenticación y asociación (Predeterminado: 1). 0 significa automático
-q <seconds>
Ataque de autenticación falsa: Establece el tiempo entre paquetes de mantenimiento en modo de autenticación falsa.
-Q
Ataque de autenticación falsa: Envía solicitudes de reasociación en lugar de realizar una autenticación y asociación completas después de cada período de retardo.
-y <prga>
Ataque de autenticación falsa: Especifica el archivo de secuencia de claves para la autenticación falsa de clave compartida.
-T n
Ataque de autenticación falsa: Sale si la autenticación falsa falla 'n' veces.
-j
Ataque de retransmisión ARP: inyecta paquetes FromDS (ver abajo).
-k <IP>
Ataque de fragmentación: Establece la IP de destino en los fragmentos.
-l <IP>
Ataque de fragmentación: Establece la IP de origen en los fragmentos.
-B
Opción de prueba: prueba de velocidad de bits.
Opciones de origen:
-i <iface>
Captura paquetes desde esta interfaz.
-r <file>
Extrae paquetes de este archivo pcap.
Opciones varias:
-R
desactiva el uso de /dev/rtc.

--ignore-negative-one si el canal de la interfaz no puede ser determinado, ignora la discrepancia, necesario para cfg80211 sin parchear

--deauth-rc <rc>, -Z <rc> Proporciona un código de razón al realizar una desautenticación (entre 0 y 255). Por defecto, se usa 7: Trama de clase 3 recibida de un STA no asociado. 0 es un valor reservado. Las explicaciones de los códigos de razón se pueden encontrar en el estándar IEEE802.11 o en https://mrncciew.com/2014/10/11/802-11-mgmt-deauth-disassociation-frames/

Modos de ataque:
-0 <count>, --deauth=<count>
Este ataque envía paquetes de desautenticación a uno o más clientes que están actualmente asociados con un punto de acceso en particular. Desautenticar clientes puede hacerse por varias razones: Recuperar un ESSID oculto. Este es un ESSID que no se está emitiendo. Otro término para esto es "encubierto" o Capturar enlaces WPA/WPA2 forzando a los clientes a reautenticarse o Generar solicitudes ARP (los clientes Windows a veces vacían su caché ARP al desconectarse). Por supuesto, este ataque es totalmente inútil si no hay cliente inalámbrico asociado o en autenticaciones falsas.
-1 <delay>, --fakeauth=<delay>
El ataque de autenticación falsa le permite realizar los dos tipos de autenticación WEP (Sistema Abierto y Clave Compartida) además de asociarse con el punto de acceso (AP). Esto solo es útil cuando necesita una dirección MAC asociada en varios ataques de aireplay-ng y actualmente no hay ningún cliente asociado. Debe tenerse en cuenta que el ataque de autenticación falsa NO genera ningún paquete ARP. La autenticación falsa no se puede usar para autenticar/asociarse con Puntos de Acceso WPA/WPA2.
-2, --interactive
Este ataque le permite elegir un paquete específico para retransmitir (inyectar). El ataque puede obtener paquetes para retransmitir de dos fuentes. La primera es un flujo en vivo de paquetes de su tarjeta inalámbrica. La segunda es de un archivo pcap. Leer de un archivo es una característica a menudo pasada por alto de aireplay-ng. Esto le permite leer paquetes de otras sesiones de captura o muy a menudo, varios ataques generan archivos pcap para un fácil reutilización. Un uso común es leer un archivo que contiene un paquete que creó con packetforge-ng.
-3, --arpreplay
El clásico ataque de retransmisión de solicitudes ARP es la forma más efectiva de generar nuevos vectores de inicialización (IV), y funciona de manera muy fiable. El programa escucha un paquete ARP y luego lo retransmite de vuelta al punto de acceso. Esto, a su vez, hace que el punto de acceso repita el paquete ARP con un nuevo IV. El programa retransmite el mismo paquete ARP una y otra vez. Sin embargo, cada paquete ARP repetido por el punto de acceso tiene un nuevo IV. Son todos estos nuevos IV los que le permiten determinar la clave WEP.
-4, --chopchop
Este ataque, cuando tiene éxito, puede descifrar un paquete de datos WEP sin conocer la clave. Incluso puede funcionar contra WEP dinámico. Este ataque no recupera la clave WEP en sí, sino que simplemente revela el texto plano. Sin embargo, algunos puntos de acceso no son vulnerables a este ataque. Algunos pueden parecer vulnerables al principio pero en realidad descartan paquetes de datos más cortos que 60 bytes. Si el punto de acceso descarta paquetesorta que 42 bytes, aireplay-ng intenta adivinar el resto de los datos faltantes, en la medida en que las cabeceras son predecibles. Si se captura un paquete IP, además verifica si la suma de comprobación de la cabecera es correcta después de adivinar las partes faltantes de la misma. Este ataque requiere al menos un paquete de datos WEP.
-5, --fragment
Este ataque, cuando tiene éxito, puede obtener 1500 bytes de PRGA (algoritmo de generación de números pseudoaleatorios). Este ataque no recupera la clave WEP en sí, sino que simplemente obtiene la PRGA. La PRGA puede entonces usarse para generar paquetes con packetforge-ng, los cuales a su vez se utilizan para diversos ataques de inyección. Requiere al menos un paquete de datos recibido del punto de acceso para iniciar el ataque.
-6, --caffe-latte
En general, para que un ataque funcione, el atacante debe estar en el rango de un AP y de un cliente conectado (falso o real). Los ataques Caffe Latte permiten reunir suficientes paquetes para descifrar una clave WEP sin la necesidad de un AP, solo necesita un cliente en rango.
-7, --cfrag
Este ataque convierte paquetes IP o ARP de un cliente en una solicitud ARP contra el cliente. Este ataque funciona especialmente bien contra redes ad-hoc. También puede usarse contra clientes softAP y clientes de AP normales.
-8, --migmode
Este ataque funciona contra puntos de acceso Cisco Aironet configurados en WPA Migration Mode, lo cual permite que tanto clientes WPA como WEP se asocien a un punto de acceso usando el mismo Service Set Identifier (SSID). El programa escucha un paquete ARP de difusión encapsulado en WEP, modifica sus bits para convertirlo en un ARP que proviene de la dirección MAC del atacante y lo retransmite al punto de acceso. Esto, a su vez, hace que el punto de acceso repita el paquete ARP con un nuevo IV y también reenvíe la respuesta ARP al atacante con un nuevo IV. El programa retransmite el mismo paquete ARP una y otra vez. Sin embargo, cada paquete ARP repetido por el punto de acceso tiene un nuevo IV, al igual que la respuesta ARP reenviada al atacante por el punto de acceso. Son todos estos nuevos IVs los que le permiten determinar la clave WEP.
-9, --test
Prueba la inyección y la calidad.

FRAGMENTACIÓN VERSUS CHOPCHOP

Fragmentación:

Ventajas
- Puede obtener la longitud completa del paquete de 1500 bytes XOR. Esto significa que posteriormente puede crear bastante bien cualquier tamaño de paquete.
- Puede funcionar donde chopchop no lo hace
- Es extremadamente rápido. Produce el flujo XOR extremadamente rápido cuando tiene éxito.

Desventajas
- La configuración para ejecutar el ataque está más sujeta a los controladores de dispositivo. Por ejemplo, Atheros no genera los paquetes correctos a menos que la tarjeta inalámbrica esté configurada con la dirección MAC que está suplantando.
- Necesita estar físicamente más cerca del punto de acceso, ya que si se pierden paquetes, el ataque falla.

Chopchop

Ventaja
- Puede funcionar donde frag no funciona.

Desventajas
- No puede usarse contra todos los puntos de acceso.
- Los bits XOR máximos están limitados a la longitud del paquete contra el que aplica chopchop.
- Mucho más lento que el ataque de fragmentación.
