after(n)

Paquete: tcl

Licencias: TCL

after(n) Comandos integrados de Tcl after(n)

NOMBRE

after - Ejecutar un comando después de un retraso de tiempo

SINOPSIS

after ms

after ms ?script script script ...?

after cancel id

after cancel script script script ...

after idle ?script script script ...?

after info ?id?

DESCRIPCIÓN

Este comando se utiliza para retrasar la ejecución del programa o para ejecutar un comando en segundo plano en algún momento futuro. Tiene varias formas, dependiendo del primer argumento del comando:

after ms
Ms debe ser un entero que represente un tiempo en milisegundos. Un número negativo se trata como 0. El comando duerme durante ms milisegundos y luego regresa. Mientras el comando está durmiendo, la aplicación no responde a los eventos.
after ms ?script script script ...?
En esta forma, el comando regresa inmediatamente, pero organiza la ejecución de un comando Tcl ms milisegundos después como un manejador de eventos. El comando se ejecutará exactamente una vez, en el momento dado. El comando retrasado se forma concatenando todos los argumentos script de la misma manera que el comando concat. El comando se ejecutará a nivel global (fuera del contexto de cualquier procedimiento Tcl). Si ocurre un error al ejecutar el comando retrasado, el error en segundo plano será reportado por el comando registrado con interp bgerror. El comando after devuelve un identificador que se puede usar para cancelar el comando retrasado usando after cancel. Un valor de ms de 0 (o negativo) pone en cola el evento inmediatamente con prioridad sobre otros tipos de eventos (si no se instala con un proc de eventos, que esperará la próxima ronda de eventos).
after cancel id
Cancela la ejecución de un comando retrasado que se programó previamente. Id indica qué comando debe cancelarse; debe haber sido el valor de retorno de un comando after anterior. Si el comando dado por id ya se ha ejecutado, el comando after cancel no tiene ningún efecto.
after cancel script script ...
Este comando también cancela la ejecución de un comando retrasado. Los argumentos script se concatenan con separadores de espacio (igual que en el comando concat). Si hay un comando pendiente que coincide con la cadena, se cancela y nunca se ejecutará; si no hay un comando de este tipo pendiente actualmente, el comando after cancel no tiene ningún efecto.
after idle script ?script script ...?
Concatena los argumentos script con separadores de espacio (igual que en el comando concat), y organiza la evaluación del script resultante más tarde como una llamada de retorno inactiva. El script se ejecutará exactamente una vez, la próxima vez que se ingrese al bucle de eventos y no haya eventos que procesar. El comando devuelve un identificador que se puede usar para cancelar el comando retrasado usando after cancel. Si ocurre un error al ejecutar el script, el error en segundo plano será reportado por el comando registrado con interp bgerror.
after info ?id?
Este comando devuelve información sobre los manejadores de eventos existentes. Si no se proporciona el argumento id, el comando devuelve una lista de los identificadores de todos los manejadores de eventos existentes creados por el comando after para este intérprete. Si se proporciona id, especifica un manejador existente; id debe haber sido el valor de retorno de alguna llamada anterior a after y no debe haberse activado todavía ni haberse cancelado. En este caso, el comando devuelve una lista con dos elementos. El primer elemento de la lista es el script asociado con id, y el segundo elemento es idle o timer para indicar qué tipo de manejador de eventos es.

Las formas after ms y after idle del comando asumen que la aplicación está orientada a eventos: los comandos retrasados no se ejecutarán a menos que la aplicación entre en el bucle de eventos. En aplicaciones que no están orientadas a eventos normalmente, como tclsh, se puede entrar en el bucle de eventos con los comandos vwait y update.

EJEMPLOS

Esto define un comando para que Tcl no haga nada durante N segundos:

proc sleep {N} {
    after [expr {int($N * 1000)}]
}

Esto organiza la ejecución del comando wake_up dentro de ocho horas (siempre que el bucle de eventos esté activo en ese momento):

after [expr {1000 * 60 * 60 * 8}] wake_up

El siguiente comando se puede usar para realizar cálculos de larga duración (como se representa aquí mediante ::my_calc::one_step, que se supone que devuelve un booleano indicando si se debe realizar otro paso) de forma paso a paso, aunque el propio cálculo debe organizarse de manera que pueda funcionar por pasos. Esta técnica es extra cuidadosa para garantizar que el bucle de eventos no se bloquee por la reprogramación de los pasos de procesamiento (organizando que el siguiente paso se realice utilizando un evento de temporizador ya activado solo cuando la cola de eventos se haya drenado) y es útil cuando se desea garantizar que una GUI Tk siga siendo responsiva durante una tarea lenta.

proc doOneStep {} {
    if {[::my_calc::one_step]} {
        after idle [list after 0 doOneStep]
    }
}
doOneStep
