  -o dir        - directorio de salida para los hallazgos del fuzzer
  Ajustes de control de ejecución:
  -P estrategia - establecer la estrategia de mutación fija: explore (enfocarse
                  en nueva cobertura), exploit (enfocarse en provocar fallos).
                  También puedes establecer un número de segundos tras los
                  cuales, sin ningún hallazgo, cambia al modo exploit, y
                  vuelve al modo explore con nueva cobertura (predeterminado:
                  1000)
  -p horario    - los horarios de potencia calculan una puntuación de
                  rendimiento para una semilla: explore (predeterminado), fast,
                  exploit, seek, rare, mmopt, coe, lin, quad -- ver
                  docs/FAQ.md para más información
  -f archivo    - ubicación leída por el programa en fuzz (predeterminado:
                  stdin o @@)
  -t msec       - tiempo de espera para cada ejecución (auto-escalado,
                  predeterminado: 1000 ms). Añade un '+' para auto-calcular el
                  tiempo de espera, siendo el valor el máximo.
  -m megs       - límite de memoria para el proceso hijo (0 MB, 0 = sin límite
                  [predeterminado])
  -O            - usar instrumentación solo de binario (modo FRIDA)
  -Q            - usar instrumentación solo de binario (modo QEMU)
  -U            - usar instrumentación basada en unicorn (modo Unicorn)
  -W            - usar instrumentación basada en qemu con Wine (modo Wine)
  -X            - usar fuzzing de VM (modo NYX - modo independiente)
  -Y            - usar fuzzing de VM (modo NYX - modo de múltiples instancias)
  Ajustes del mutador:
  -a tipo       - formato de entrada objetivo, "text" o "binary"
                  (predeterminado: genérico)
  -g longitud_mínima - establecer la longitud mínima de la entrada de fuzz
                       generada (predeterminado: 1)
  -G longitud_máxima - establecer la longitud máxima de la entrada de fuzz
                       generada (predeterminado: 1048576)
  -L minutos    - usar el modo MOpt(imize) y establecer el límite de tiempo
                  para entrar en el modo pacemaker (minutos sin nuevos
                  hallazgos). 0 = inmediatamente, -1 = inmediatamente y junto
                  con la mutación normal. Nota: esta opción generalmente no es
                  muy efectiva
  -u            - habilitar el empalme de casos de prueba
  -c programa   - habilitar CmpLog especificando un binario compilado para
                  ello. Si usas QEMU/FRIDA o el objetivo de fuzzing está
                  compilado para CmpLog, usa '-c 0'. Para deshabilitar CmpLog
                  usa '-c -'.
  -l opciones_cmplog - valores de configuración de CmpLog (p. ej. "2ATR"):
                  1=archivos pequeños, 2=archivos más grandes
                  (predeterminado), 3=todos los archivos, A=resolución
                  aritmética, T=resolución transformacional, X=resolución de
                  transformación extrema, R=bytes de colorización aleatorios.
  Ajustes de comportamiento del fuzzing:
  -Z            - selección secuencial de la cola en lugar de aleatoria
                  ponderada
  -N            - no desvincular el archivo de entrada de fuzzing (para
                  dispositivos, etc.)
  -n            - fuzzear sin instrumentación (modo no instrumentado)
  -x archivo_diccionario - diccionario del fuzzer (ver README.md, se puede
                  especificar hasta 4 veces)
  -w binario_saneador - especificar los binarios instrumentados con
                  sanitizadores adicionales, se puede especificar varias veces.
                  Leer docs/SAND.md para detalles.
  Ajustes de prueba:
  -s semilla    - usar una semilla fija para el RNG
  -V segundos   - fuzzear durante un tiempo especificado y luego terminar
                  (¡solo tiempo de fuzzing!)
  -E ejecuciones - fuzzear durante un número aprox. total de ejecuciones y
                  luego terminar. Nota: no es preciso y puede tener varias
                  ejecuciones más.
  Otros:
  -M/-S id      - modo distribuido (-M establece -Z y desactiva el
                  recortamiento). Ver
                  docs/fuzzing_in_depth.md#c-using-multiple-cores para
                  recomendaciones efectivas para fuzzing en paralelo.
  -R ruta       - sincronizar con un directorio de cola de otro fuzzer (requiere
                  -M, se puede especificar hasta 32 veces)
  -z            - omitir el fuzzing determinista mejorado (nota: los antiguos
                  indicadores -d y -D se ignoran.)
  -T texto      - texto de banner para mostrar en la pantalla
  -I comando    - ejecutar este comando/script cuando se encuentre un nuevo
                  fallo
  -C            - modo de exploración de fallos (la cosa del conejo peruano)
  -b id_cpu     - vincular el proceso de fuzzing al núcleo de CPU especificado
                  (0-...)
  -e ext        - extensión de archivo para el archivo de entrada de prueba de
                  fuzz (si es necesario)
  Variables de entorno utilizadas:
  LD_BIND_LAZY: no establecer la variable de entorno LD_BIND_NOW para el
                objetivo
  ASAN_OPTIONS: ajustes personalizados para ASAN (debe contener
                abort_on_error=1 y symbolize=0)
  MSAN_OPTIONS: ajustes personalizados para MSAN (debe contener exitcode=86 y
                symbolize=0)
  AFL_AUTORESUME: reanudar el fuzzing si el directorio especificado por -o ya
                  existe
  AFL_BENCH_JUST_ONE: ejecutar el objetivo solo una vez
  AFL_BENCH_UNTIL_CRASH: salir pronto cuando se haya encontrado la primera
                         entrada que provoca un fallo
  AFL_CMPLOG_ONLY_NEW: no ejecutar cmplog en los casos de prueba iniciales
                       (¡bueno para reanudaciones!)
  AFL_CRASH_EXITCODE: código de salida del hijo opcional a interpretar como
                      fallo
  AFL_CUSTOM_MUTATOR_LIBRARY: librería con afl_custom_fuzz() para mutar
                              entradas
  AFL_CUSTOM_MUTATOR_ONLY: evitar los mutadores internos de AFL++
  AFL_CYCLE_SCHEDULES: después de completar un ciclo, cambiar a un horario -p
                       diferente
  AFL_DEBUG: salida de depuración adicional para el recortamiento en modo
             Python
  AFL_DEBUG_CHILD: no suprimir stdout/stderr del objetivo
  AFL_DISABLE_REDUNDANT: deshabilitar cualquier elemento de la cola que sea
                         redundante
  AFL_DISABLE_TRIM: deshabilitar el recortamiento de casos de prueba
  AFL_DUMB_FORKSRV: usar el servidor de bifurcación sin retroalimentación del
                    objetivo
  AFL_EXIT_WHEN_DONE: salir cuando se hayan ejecutado todas las entradas y no
                      se encuentren nuevos hallazgos
  AFL_EXIT_ON_TIME: salir cuando no se encuentre nueva cobertura dentro del
                    tiempo especificado
  AFL_EXIT_ON_SEED_ISSUES: salir ante cualquier tipo de problemas con las
                           semillas
  AFL_EXPAND_HAVOC_NOW: habilitar inmediatamente el modo expand havoc
                        (predeterminado: después de 60 minutos y un ciclo sin
                        hallazgos)
  AFL_FAST_CAL: limitar la etapa de calibración a tres ciclos para acelerar
  AFL_FORCE_UI: forzar la muestra de la pantalla de estado (para consolas
                virtuales)
  AFL_FORKSRV_INIT_TMOUT: tiempo empleado esperando al servidor de bifurcación
                          durante el inicio (en ms)
  AFL_HANG_TMOUT: sobreescribir el valor de tiempo de espera (en milisegundos)
  AFL_I_DONT_CARE_ABOUT_MISSING_CRASHES: no advertir sobre los manejadores de
                                         volcados de memoria
  AFL_IGNORE_PROBLEMS: no abortar el fuzzing si se detecta una configuración
                       incorrecta
  AFL_IGNORE_PROBLEMS_COVERAGE: si se establece además de AFL_IGNORE_PROBLEMS -
                               ignorar también esas librerías para la cobertura
  AFL_IGNORE_SEED_PROBLEMS: omitir los fallos y tiempos de espera en las
                            semillas en lugar de salir
  AFL_IGNORE_TIMEOUTS: no procesar ni guardar ningún tiempo de espera
  AFL_IGNORE_UNKNOWN_ENVS: no advertir sobre variables de entorno desconocidas
  AFL_IMPORT_FIRST: sincronizar e importar casos de prueba de otras instancias
                    del fuzzer primero
  AFL_INPUT_LEN_MIN/AFL_INPUT_LEN_MAX: como -g/-G, establecen la longitud
                                       mínima/máxima del fuzz producido
  AFL_PIZZA_MODE: 1 - forzar el modo pizza, -1 - deshabilitar para el 1 de
                  abril, 0 (predeterminado) - activar el 1 de abril
  AFL_KILL_SIGNAL: ID de señal entregada a los procesos hijos en caso de tiempo
                   de espera, etc. (predeterminado: SIGKILL)
  AFL_FORK_SERVER_KILL_SIGNAL: Señal de terminación para el servidor de
                               bifurcación (predeterminado: SIGTERM). Si no
                               está establecida y AFL_KILL_SIGNAL lo está, se
                               usará ese valor.
  AFL_MAP_SIZE: el tamaño de memoria compartida para ese objetivo. debe ser >=
                el tamaño para el que fue compilado el objetivo
  AFL_MAX_DET_EXTRAS: si hay más entradas en la lista del diccionario que este
                      valor, se seleccionan aleatoriamente en lugar de usar
                      todas. El valor predeterminado es 200.
  AFL_NO_AFFINITY: no buscar un núcleo de CPU sin usar para el fuzzing
  AFL_TRY_AFFINITY: intentar vincular a un núcleo sin usar, pero no fallar si
                    no tiene éxito
  AFL_NO_ARITH: omitir mutaciones aritméticas en la etapa determinista
  AFL_NO_AUTODICT: no cargar un diccionario automático ofrecido compilado en un
                   objetivo
  AFL_NO_CPU_RED: evitar el color rojo para mostrar un uso muy alto de CPU
  AFL_NO_FORKSRV: ejecutar el objetivo mediante execve en lugar de usar el
                  servidor de bifurcación
  AFL_NO_SNAPSHOT: no usar la función de instantánea (si el módulo del kernel
                   de instantánea está cargado)
  AFL_NO_STARTUP_CALIBRATION: sin calibración inicial de la semilla, empezar a
                              fuzzear de inmediato
  AFL_NO_WARN_INSTABILITY: sin advertencias sobre problemas de inestabilidad en
                           la calibración de inicio
  AFL_NO_UI: desactivar la pantalla de estado
  AFL_NYX_AUX_SIZE: tamaño del búfer auxiliar de Nyx. Debe ser un múltiplo de
                    4096. Incrementa este valor si los informes de fallos están
                    truncados. El valor predeterminado es 4096.
  AFL_NYX_DISABLE_SNAPSHOT_MODE: deshabilitar el modo instantánea (debe ser
                                 soportado por el agente)
  AFL_NYX_LOG: enviar los mensajes de hprintf de NYX a otro archivo
  AFL_NYX_REUSE_SNAPSHOT: reutilizar una instantánea raíz de Nyx existente
  AFL_PATH: ruta a los binarios de soporte de AFL
  AFL_PYTHON_MODULE: mutar y recortar entradas con el módulo de Python
                     especificado
  AFL_QUIET: suprimir los mensajes de estado del servidor de bifurcación
  AFL_POST_PROCESS_KEEP_ORIGINAL: guardar el archivo como estaba antes del
                                  post-procesamiento en la cola, pero ejecutar
                                  el post-procesado
  AFL_PRELOAD: ajustes de LD_PRELOAD / DYLD_INSERT_LIBRARIES para el objetivo
  AFL_TARGET_ENV: pasar variables de entorno adicionales al objetivo
  AFL_SHUFFLE_QUEUE: reordenar la cola de entrada aleatoriamente al inicio
  AFL_SKIP_BIN_CHECK: omitir las comprobaciones de compatibilidad de afl, también
                      deshabilita el tamaño automático del mapa
  AFL_SKIP_CPUFREQ: no advertir sobre la variabilidad del reloj de la CPU
  AFL_STATSD: habilita la recopilación de métricas de StatsD
  AFL_STATSD_HOST: cambiar el host de statsd predeterminado (predeterminado:
                   127.0.0.1)
  AFL_STATSD_PORT: cambiar el puerto de statsd predeterminado (predeterminado:
                   8125)
  AFL_STATSD_TAGS_FLAVOR: establecer el formato de las etiquetas de statsd
                          (predeterminado: deshabilitar etiquetas). Formatos
                          soportados: dogstatsd, librato, signalfx, influxdb
  AFL_NO_FASTRESUME: no leer ni escribir un archivo de reanudación rápida resumen del archivo
AFL_NO_SYNC: desactiva toda la sincronización
AFL_SYNC_TIME: tiempo de sincronización entre instancias de fuzzing (en minutos)
AFL_FINAL_SYNC: sincronizar una última vez al salir (¡retrasará la salida!)
AFL_NO_CRASH_README: no crear un README en el directorio de crashes
AFL_TESTCACHE_SIZE: usar una caché para los casos de prueba, mejora el rendimiento (en MB)
AFL_TMPDIR: directorio a usar para la generación de archivos de entrada (se recomienda ramdisk)
AFL_EARLY_FORKSERVER: forzar un forkserver temprano en un objetivo afl-clang-fast/
                      afl-clang-lto/afl-gcc-fast
AFL_PERSISTENT: hacer cumplir el modo persistente (si __AFL_LOOP está en una librería compartida)
AFL_DEFER_FORKSRV: hacer cumplir el forkserver diferido (__AFL_INIT está en una librería compartida)
AFL_FUZZER_STATS_UPDATE_INTERVAL: intervalo para actualizar el archivo fuzzer_stats en
                                  segundos (predeterminado: 60, mínimo: 1)
Compilado con soporte para el módulo de Python 3.13.5, ver docs/custom_mutators.md
Compilado sin soporte para AFL_PERSISTENT_RECORD.
Compilado con soporte para shmat.
