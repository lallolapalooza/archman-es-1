NOMBRE

afp_client- Monta, desmonta y controla sesiones de Apple Filing Protocol (AFP) utilizando la infraestructura FUSE.

SINOPSIS

afp_client mount|status|unmount|suspend|resume|exit [opciones]

DESCRIPCIÓN

El comando afp_client te permite realizar algunas funciones básicas para acceder a volúmenes AFP, como montar, desmontar, obtener estado, suspender y reanudar.

No confundir con afpcmd; afp_client se utiliza solo para el cliente FUSE, en conjunción con afpfsd(1). afpcmd es un cliente de transferencia de archivos en modo batch. Ambos utilizan las bibliotecas afpfs-ng.

afp_mount(1) es normalmente un enlace simbólico a afp_client. Solo maneja comandos de montaje con una URL AFP completamente formada.

COMANDOS

mount
El nombre de la interfaz. Suele ser un nombre de controlador seguido de un número de unidad, por ejemplo eth0 para la primera interfaz Ethernet.
mount [opciones de montaje] nodo
Utilizando la autenticación y la información del servidor proporcionadas con las opciones de montaje, monta el sistema de archivos remoto en el nodo. Para más información, consulta las "opciones de montaje" más adelante en esta página del manual. Si prefieres usar la sintaxis de URL AFP, consulta mount_afp(1) para más información.
unmount nodo
Elimina el montaje AFP que está actualmente conectado a nodo
status
Muestra información de estado de todos los servidores conectados. Esto proporcionará información sobre la dirección IP de los servidores conectados, las descripciones del servidor (tipo de máquina, nombre de máquina, firma, mensaje de inicio de sesión) y los volúmenes disponibles. También proporciona estadísticas y otros detalles. Esto es crucial para la depuración.
suspend
Suspende pero no desmonta las conexiones actuales a todos los servidores actualmente conectados. Actualmente no soportado.
resume
Reanuda todas las conexiones de servidor suspendidas. Actualmente no soportado. Habilita o deshabilita el modo promiscuo de la interfaz. Si se selecciona, todos los paquetes de la red serán recibidos por la interfaz.

-p, --pass <contraseña>

-o, --port <puerto>
Usa el puerto TCP <puerto> en lugar del predeterminado, 548.

Úsalo si el volumen al que accedes usa una contraseña de volumen (una forma de protección muy débil ya que se transfiere en texto plano). Si especificas un '-' como contraseña, se te pedirá. Esto te permite usar una contraseña sin tener que exponerla en la línea de comandos.

-v, --version <AFP versión>
Especifica la versión AFP que se usará para un montaje. Para AFP 2.2, usa '22', para 3.2, usa '32', etc. Por defecto, afpfs-ng elegirá la versión AFP más alta compartida entre el cliente y el servidor. afpfs-ng soporta AFP 2.0 hasta 3.2. -a, --uam <uam> Establece el método de autenticación, a uno de:

No User Authent

Cleartxt Passwrd

Randnum Exchange

2-Way Randnum Exchange

DHCAST128

Client Krb v2

DHX2

Si no especificas un UAM, se elegirá el más seguro común tanto para el servidor como para el cliente (afpfs-ng).

-m, --map <uam>
Establece el método utilizado para mapear UID y GID locales a los del servidor. Los valores posibles son:

Common user directory Esto debería usarse en un entorno donde se espera que el UID y el GID del cliente y el servidor coincidan perfectamente. Un ejemplo de esto es donde existe un servidor NIS o Open Directory.

Login ids Úsalo cuando quieras que todos los archivos parezcan ser propiedad del uid y gid del nombre de usuario que usaste para tu información de autenticación.
