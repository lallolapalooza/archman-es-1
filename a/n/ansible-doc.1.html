Nombre

ansible-doc - herramienta de documentación de plugins

SINOPSIS

uso: ansible-doc [-h] [--version] [-v] [-M RUTA_MÓDULO]
[--playbook-dir BASEDIR] [-t {become,cache,callback,cliconf,connection,httpapi,inventory,lookup,netconf,shell,vars,module,strategy,test,filter,role,keyword}] [-j] [-r RUTA_ROLES] [-e PUNTO_ENTRADA | -s | -F | -l | --metadata-dump] [--no-fail-on-errors] [plugin ...]

DESCRIPCIÓN

muestra información sobre los módulos instalados en las bibliotecas de Ansible. Muestra una lista concisa de plugins y sus descripciones cortas, proporciona una impresión de sus cadenas de DOCUMENTACIÓN, y puede crear un breve "fragmento" que se puede pegar en un playbook.

OPCIONES COMUNES

Plugin

--metadata-dump

Solo para uso interno Exporta metadatos json para todas las entradas, ignora otras opciones.

--no-fail-on-errors

Solo para uso interno Solo se usa para --metadata-dump. No fallar ante errores. Informar el mensaje de error en el JSON en su lugar.

--playbook-dir 'BASEDIR'

Dado que esta herramienta no utiliza playbooks, se usa esto como un directorio de playbook sustituto. Esto establece la ruta relativa para muchas funciones, incluidas roles/ group_vars/ etc.

--version

muestra el número de versión del programa, la ubicación del archivo de configuración, la ruta de búsqueda de módulos configurada, la ubicación del módulo, la ubicación del ejecutable y sale

-F, --list_files

Muestra los nombres de los plugins y sus archivos de origen sin resúmenes (implica --list). Un argumento proporcionado se utilizará para filtrar, puede ser un espacio de nombres o un nombre de colección completo.

-M, --module-path

añade prefijo a la(s) ruta(s) separada(s) por dos puntos a la biblioteca de módulos (por defecto={{ ANSIBLE_HOME ~ ""/plugins/modules:/usr/share/ansible/plugins/modules"" }}). Este argumento se puede especificar varias veces.

-e 'PUNTO_ENTRADA', --entry-point 'PUNTO_ENTRADA'

Selecciona el punto de entrada para el(los) rol(es).

-h, --help

muestra este mensaje de ayuda y sale

-j, --json

Cambia la salida a formato json.

-l, --list

Lista los plugins disponibles. Un argumento proporcionado se utilizará para filtrar, puede ser un espacio de nombres o un nombre de colección completo.

-r, --roles-path

La ruta al directorio que contiene tus roles. Este argumento se puede especificar varias veces.

-s, --snippet

Muestra un fragmento de playbook para estos tipos de plugins: inventory, lookup, module

-t 'TIPO', --type 'TIPO'

Elige qué tipo de plugin (por defecto es "module"). Los tipos de plugin disponibles son: ('become', 'cache', 'callback', 'cliconf', 'connection', 'httpapi', 'inventory', 'lookup', 'netconf', 'shell', 'vars', 'module', 'strategy', 'test', 'filter', 'role', 'keyword')

-v, --verbose

Hace que Ansible imprima más mensajes de depuración. Añadir múltiples -v aumentará la verbosidad, los plugins integrados actualmente evalúan hasta -vvvvvv. Un nivel razonable para empezar es -vvv, la depuración de la conexión podría requerir -vvvv. Este argumento se puede especificar varias veces.

AMBIENTE

Se pueden especificar las siguientes variables de entorno.

ANSIBLE_LIBRARY -- Sobrescribe la ruta predeterminada de la biblioteca de módulos de ansible

ANSIBLE_CONFIG -- Especifica la ubicación de reemplazo para el archivo de configuración de ansible

Hay muchas más disponibles para la mayoría de las opciones en ansible.cfg

Para una lista completa, consulta https://docs.ansible.com/. o utiliza el comando ansible-config.

ARCHIVOS

/etc/ansible/ansible.cfg -- Archivo de configuración, se usa si está presente

~/.ansible.cfg -- Archivo de configuración del usuario, sobrescribe la configuración predeterminada si está presente

./ansible.cfg -- Archivo de configuración local (en el directorio de trabajo actual) se asume que es 'específico del proyecto' y sobrescribe el resto si está presente.

Como se mencionó anteriormente, la variable de entorno ANSIBLE_CONFIG sobrescribirá todas las demás.
