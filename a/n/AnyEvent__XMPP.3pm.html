NOMBRE

AnyEvent::XMPP - Una implementación del protocolo XMPP

VERSIÓN

Versión 0.55

SINOPSIS

use AnyEvent::XMPP::Connection;

o:

use AnyEvent::XMPP::IM::Connection;

o:

use AnyEvent::XMPP::Client;

DESCRIPCIÓN

Este es el módulo principal del marco de trabajo del protocolo cliente XMPP AnyEvent::XMPP (tal como se describe en RFC 3920 y RFC 3921).

AnyEvent::XMPP::Connection es una implementación de flujo "XML" conforme a la RFC 3920 para clientes, que maneja la conexión TCP hasta el enlazado de recursos. Y proporciona acceso de bajo nivel a los nodos XML del flujo XML junto con algunos métodos de alto nivel para enviar las estanzas XML predefinidas.

AnyEvent::XMPP::IM::Connection es un módulo de más alto nivel, que se deriva de AnyEvent::XMPP::Connection. Maneja toda la funcionalidad de cliente de mensajería instantánea descrita en la RFC 3921.

AnyEvent::XMPP::Client es una clase de cliente multi-cuenta. Gestiona conexiones a múltiples cuentas XMPP e intenta ofrecer una bonita interfaz de alto nivel para la comunicación XMPP.

Para una lista de "Extensiones soportadas" véase más abajo.

También hay otros módulos en esta distribución, por ejemplo: AnyEvent::XMPP::Util, AnyEvent::XMPP::Writer, AnyEvent::XMPP::Parser y aquellos que olvidé :-) Esos módulos podrían ser útiles y/o requeridos si quiere usar este marco de trabajo para XMPP.

Véase también AnyEvent::XMPP::Writer para una discusión sobre lo roto que está el XML en la especificación XMPP.

Si tiene alguna pregunta o busca ayuda, mire más abajo en "SOPORTE".

REQUISITOS

Una de las principales desventajas que veo para AnyEvent::XMPP es la larga lista de módulos requeridos para hacerlo funcionar.

AnyEvent
Para los eventos de E/S, temporizadores, TCP, TLS, DNS y el buffer de E/S.
Object::Event
El antiguo módulo AnyEvent::XMPP::Event ha sido externalizado al módulo Object::Event para proporcionar una forma más genérica para que más otros módulos registren y llamen a callbacks de eventos.
XML::Writer
Para escribir "XML".
XML::Parser::Expat
Para analizar cosas "XML" parciales.
MIME::Base64
Para la autenticación SASL
Authen::SASL
Para la autenticación SASL
Net::LibIDN
Para perfiles stringprep para manejar JIDs.
Digest::SHA
Para la autenticación de componentes y la autenticación de estilo antiguo.

Y sí, todo esto es esencial para la comunicación XMPP. Aunque 'mensajería instantánea' y 'presencia' es un problema bastante simple, XMPP de alguna manera tuvo éxito en hacer la tarea lo suficientemente complicada como para mantenerme ocupado durante mucho tiempo. Pero todo ese tiempo no fue solo por la tecnología requerida para ponerlo en marcha, en su mayor parte fue por todos los raros, arreglos y "XML" mal aplicado en el protocolo que complicaron el asunto.

CONJUNTO DE PRUEBAS

Si es un desarrollador y quiere probar un servidor o quizás solo si este módulo pasa algunas pruebas básicas, podría querer ejecutar el conjunto de pruebas para desarrolladores.

Este conjunto de pruebas no está habilitado por defecto porque requiere algo de interacción humana para configurarlo, por favor vea AnyEvent::XMPP::TestClient para pistas sobre el procedimiento de configuración del conjunto de pruebas.

Escribí el conjunto de pruebas en su mayoría porque quería asegurarme de que no había roto algo esencial antes de un lanzamiento. Las pruebas no cubren todo y no planeo escribir una prueba para cada función en la API, eso ralentizaría considerablemente el desarrollo para mí. Pero espero que algunos errores graves que detienen el lanzamiento sean prevenidos con este conjunto de pruebas.

Las pruebas también son útiles si quiere probar una implementación de servidor. Pero hay quizás, por supuesto, problemas de conformidad con AnyEvent::XMPP en sí, así que si encuentra algo donde AnyEvent::XMPP no se conforma a las RFCs o XEPs de XMPP, consulte la sección ERRORES más abajo.

Si encuentra un servidor que no maneja algo correctamente pero necesita interactuar con él, tiene libertad para implementar soluciones alternativas y enviarme un parche, o incluso preguntarme si podría querer investigar el problema (no puedo garantizar nada aquí, pero quiero que este módulo sea lo más interoperable posible. Pero si la implementación de una solución alternativa para algún software no conforme complicará demasiado el código, probablemente no la implementaré.).

Por supuesto, si encuentra un error en alguna implementación de servidor, no olvide presentar un informe de error a ellos, un arreglos menos en AnyEvent::XMPP significa más tiempo para la corrección de errores y mejoras y nuevas características.

¿Por qué (todavía) otro módulo XMPP?

La característica principal destacada de este módulo en comparación con los otros módulos XMPP (también conocidos como Jabber) que existen es el soporte para AnyEvent. AnyEvent le permite usar este módulo junto con otros programas y bibliotecas basados en eventos de E/S (es decir, Gtk2 o Event).

Los otros módulos a menudo solo pueden integrarse en esas aplicaciones o bibliotecas usando hilos. Decidí escribir este módulo porque creo que CPAN carece de un módulo XMPP basado en eventos. Los hilos son, desafortunadamente, no son una alternativa en Perl en este momento debido a la funcionalidad de hilos limitada que proporcionan y el impacto global en la velocidad. También creo que un simple marco de E/S basado en eventos podría ser un poco más fácil de manejar que los

hilos.

Otra cosa era que no me gustaban las APIs de los otros módulos. En AnyEvent::XMPP intento proporcionar módulos de bajo nivel para hablar XM

PP como se define en RFC 3920 y RFC 3921 (véase también AnyEvent::XMPP::Connection y AnyEvent::XMPP::IM::Connection). Pero también intento
proporcionar una API de alto nivel para un uso más fácil en tareas de mensajería instantánea y clientes (por ejemplo, AnyEvent::XMPP::Client).
