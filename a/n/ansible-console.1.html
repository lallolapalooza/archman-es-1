ansible-console(1) Comandos de administración del sistema ansible-console(1)

Nombre

ansible-console - Consola REPL para ejecutar tareas de Ansible.

SINOPSIS

uso: ansible-console [-h] [--version] [-v] [-b]
[--become-method MÉTODO_BECOME] [--become-user USUARIO_BECOME] [-K | --become-password-file ARCHIVO_CONTRASEÑA_BECOME] [-i INVENTARIO] [--list-hosts] [-l SUBSET] [--flush-cache] [--private-key ARCHIVO_CLAVE_PRIVADA] [-u USUARIO_REMOTO] [-c CONEXIÓN] [-T TIEMPO_ESPERA] [--ssh-common-args ARGUMENTOS_COMUNES_SSH] [--sftp-extra-args ARGUMENTOS_EXTRA_SFTP] [--scp-extra-args ARGUMENTOS_EXTRA_SCP] [--ssh-extra-args ARGUMENTOS_EXTRA_SSH] [-k | --connection-password-file ARCHIVO_CONTRASEÑA_CONEXIÓN] [-C] [-D] [--vault-id IDS_VAULT] [-J | --vault-password-file ARCHIVOS_CONTRASEÑA_VAULT] [-f FORKS] [-M RUTA_MÓDULO] [--playbook-dir DIRECTORIO_BASE] [-e VARS_EXTRA] [--task-timeout TIEMPO_ESPERA_TAREA] [--step] [patrón]

DESCRIPCIÓN

Una REPL que permite ejecutar tareas ad-hoc contra un inventario elegido desde una bonita shell con autocompletado integrado (basado en ansible-shell de dominis).

Admite varios comandos, y puede modificar su configuración en tiempo de ejecución:

  • cd [patrón]: cambia el host/grupo (puede usar patrones de host, por ejemplo: app*.dc*:!app01*)
  • list: lista los hosts disponibles en la ruta actual
  • list groups: lista los grupos incluidos en la ruta actual
  • become: activa/desactiva el indicador become
  • !: fuerza el módulo shell en lugar del módulo ansible (!yum update -y)
  • verbosity [num]: establece el nivel de verbosidad
  • forks [num]: establece el número de forks
  • become_user [usuario]: establece el usuario become
  • remote_user [usuario]: establece el usuario remoto
  • become_method [método]: establece el método de escalada de privilegios
  • check [bool]: activa/desactiva el modo de verificación
  • diff [bool]: activa/desactiva el modo diff
  • timeout [entero]: establece el tiempo de espera de las tareas en segundos (0 para deshabilitar)
  • help [comando/módulo]: muestra la documentación del comando o módulo
  • exit: sale de ansible-console

OPCIONES COMUNES

patrón de host

--become-method 'MÉTODO_BECOME'

método de escalada de privilegios a usar (por defecto=sudo), usa ansible-doc -t become -l para listar las opciones válidas.

--become-password-file 'ARCHIVO_CONTRASEÑA_BECOME', --become-pass-file 'ARCHIVO_CONTRASEÑA_BECOME'

Archivo de contraseña para becoming

--become-user 'USUARIO_BECOME'

ejecutar operaciones como este usuario (por defecto=root)

--connection-password-file 'ARCHIVO_CONTRASEÑA_CONEXIÓN', --conn-pass-file 'ARCHIVO_CONTRASEÑA_CONEXIÓN'

Archivo de contraseña de conexión

--flush-cache

borra la caché de hechos para cada host en el inventario

--list-hosts

muestra una lista de los hosts que coinciden; no ejecuta nada más

--playbook-dir 'DIRECTORIO_BASE'

Dado que esta herramienta no utiliza playbooks, úsala como un directorio de playbook sustituto. Esto establece la ruta relativa para muchas funciones, incluidas roles/ group_vars/ etc.

--private-key 'ARCHIVO_CLAVE_PRIVADA', --key-file 'ARCHIVO_CLAVE_PRIVADA'

usa este archivo para autenticar la conexión

--scp-extra-args 'ARGUMENTOS_EXTRA_SCP'

especifica argumentos adicionales para pasar solo a scp (por ejemplo, -l)

--sftp-extra-args 'ARGUMENTOS_EXTRA_SFTP'

especifica argumentos adicionales para pasar solo a sftp (por ejemplo, -f, -l)

--ssh-common-args 'ARGUMENTOS_COMUNES_SSH'

especifica argumentos comunes para pasar a sftp/scp/ssh (por ejemplo, ProxyCommand)

--ssh-extra-args 'ARGUMENTOS_EXTRA_SSH'

especifica argumentos adicionales para pasar solo a ssh (por ejemplo, -R)

--step

un paso a la vez: confirma cada tarea antes de ejecutarla

--task-timeout 'TIEMPO_ESPERA_TAREA'

establece el límite de tiempo de espera de la tarea en segundos, debe ser un entero positivo.

--vault-id

la identidad del vault a usar. Este argumento puede especificarse múltiples veces.

--vault-password-file, --vault-pass-file

archivo de contraseña del vault

--version

muestra el número de versión del programa, la ubicación del archivo de configuración, la ruta de búsqueda de módulos configurada, la ubicación del módulo, la ubicación del ejecutable y sale

-C, --check

no realice ningún cambio; en su lugar, intente predecir algunos de los cambios que podrían ocurrir

-D, --diff

al cambiar archivos y plantillas (pequeños), muestra las diferencias en esos archivos; funciona muy bien con --check

-J, --ask-vault-password, --ask-vault-pass

pregunta por la contraseña del vault

-K, --ask-become-pass

pregunta por la contraseña de escalada de privilegios

-M, --module-path

precede rutas separadas por dos puntos a la biblioteca de módulos (por defecto={{ ANSIBLE_HOME ~ "/plugins/modules:/usr/share/ansible/plugins/modules" }}). Este argumento puede especificarse múltiples veces.

-T 'TIEMPO_ESPERA', --timeout 'TIEMPO_ESPERA'

anula el tiempo de espera de la conexión en segundos (el valor por defecto depende de la conexión)

-b, --become

ejecuta operaciones con become (no implica solicitar contraseña)

-c 'CONEXIÓN', --connection 'CONEXIÓN'

tipo de conexión a usar (por defecto=ssh)

-e, --extra-vars

establece variables adicionales como clave=valor o YAML/JSON, si el nombre del archivo comienza con @. Este argumento puede especificarse múltiples veces.

-f 'FORKS', --forks 'FORKS'

especifica el número de procesos paralelos a usar (por defecto=5)

-h, --help

muestra este mensaje de ayuda y sale

-i, --inventory, --inventory-file

especifica la ruta del host de inventario o una lista de hosts separados por comas. Este argumento puede especificarse múltiples veces.

-k, --ask-pass

pregunta por la contraseña de conexión

-l 'SUBSET', --limit 'SUBSET'

limita aún más los hosts seleccionados a un patrón adicional

-u 'USUARIO_REMOTO', --user 'USUARIO_REMOTO'

conéctate como este usuario (por defecto=None)

-v, --verbose

Hace que Ansible imprima más mensajes de depuración. Añadir múltiples -v aumentará la verbosidad, los plugins integrados actualmente evalúan hasta -vvvvvv. Un nivel razonable para empezar es -vvv, la depuración de conexiones podría requerir -vvvv. Este argumento puede especificarse múltiples veces.

ARGUMENTOS

patrón-de-host

El nombre de un grupo en el inventario, un comodín similar a shell que selecciona hosts en el inventario o cualquier combinación de los dos separados por comas.

ENTORNO

Se pueden especificar las siguientes variables de entorno.

ANSIBLE_INVENTORY -- Anula las fuentes de inventario de ansible predeterminadas

ANSIBLE_LIBRARY -- Anula la ruta de la biblioteca de módulos de ansible predeterminada

ANSIBLE_CONFIG -- Especifica la ubicación de anulación para el archivo de configuración de ansible

Hay muchas más disponibles para la mayoría de las opciones en ansible.cfg

Para una lista completa, consulte https://docs.ansible.com/. o use el comando ansible-config .

ARCHIVOS

/etc/ansible/hosts -- Archivo de inventario predeterminado

/etc/ansible/ansible.cfg -- Archivo de configuración, se usa si está presente

~/.ansible.cfg -- Archivo de configuración del usuario, anula la configuración predeterminada si está presente

./ansible.cfg -- Archivo de configuración local (en el directorio de trabajo actual) se asume que es 'específico del proyecto' y anula al resto si está presente.

Como se mencionó anteriormente, la variable de entorno ANSIBLE_CONFIG anulará todas las demás.
