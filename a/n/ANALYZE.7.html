ANALYZE - recopila

estadísticas sobre
una base de datos

SINOPSI

S 
ANALYZE [ ( opción [, ...] ) ] [ tabla_y_columnas [, ...] ]
donde opción puede ser una de:
    VERBOSE [ booleano ]
    SKIP_LOCKED [ booleano ]
    BUFFER_USAGE_LIMIT tamaño
y tabla_y_columnas es:
    [ ONLY ] nombre_de_tabla [ * ] [ ( nombre_de_columna [, ...] )
]

DESCRIPCIÓ

N

ANALYZE recopila estadísticas sobre el contenido de las tablas en la base de datos y almacena los resultados en el catálogo del sistema pg_statistic. Posteriormente, el planificador de consultas utiliza estas estadísticas para ayudar a determinar los planes de ejecución más eficientes para las

consultas.

Sin una lista de tabla_y_columnas, ANALYZE procesa cada tabla y vista materializada en la base de datos actual que el usuario actual tenga permiso para analizar. Con una lista, ANALYZE procesa solo esas tablas. Además, es posible indicar una lista de nombres de col

umnas para una tabla, en cuyo caso solo se
recopilan las estadísticas de esas columnas.

PARÁMETRO

S

VERBOS

E
Habilita la visualización de mensajes de progreso a nivel
INFO.

SKIP_LOCKE

D
Especifica que ANALYZE no debe esperar a que se liberen bloqueos conflictivos al comenzar a trabajar en una relación: si una relación no puede bloquearse inmediatamente sin esperar, la relación se omite. Tenga en cuenta que incluso con esta opción, ANALYZE aún puede bloquearse al abrir los índices de la relación o al obtener filas de muestra de particiones, tablas hijas de herencia y algunos tipos de tablas externas. Además, aunque ANALYZE normalmente procesa todas las particiones de las tablas particionadas especificadas, esta opción hará que ANALYZE omita todas las particiones si hay un bloqueo conflictivo en la tabla
particionada.

BUFFER_USAGE_LIMI

T
Especifica el tamaño del búfer circular de estrategia de acceso a búfer (Buffer Access Strategy) para ANALYZE. Este tamaño se utiliza para calcular el número de búferes compartidos que se reutilizarán como parte de esta estrategia. 0 desactiva el uso de una estrategia de acceso a búfer. Cuando no se especifica esta opción, ANALYZE usa el valor de vacuum_buffer_usage_limit. Valores más altos pueden permitir que ANALYZE se ejecute más rápidamente, pero tener un valor demasiado grande puede causar que se expulsen demasiadas páginas útiles de los búferes compartidos. El valor mínimo es 128 kB y el valor máximo es 16
GB.

boolean

o
Especifica si la opción seleccionada debe activarse o desactivarse. Puede escribir TRUE, ON o 1 para habilitar la opción, y FALSE, OFF o 0 para deshabilitarla. El valor booleano también puede omitirse, en cuyo caso se asume
TRUE.

tamañ

o
Especifica una cantidad de memoria en kilobytes. Los tamaños también pueden especificarse como una cadena que contiene el tamaño numérico seguido de cualquiera de las siguientes unidades de memoria: B (bytes), kB (kilobytes), MB (megabytes), GB (gigabytes) o TB (terabytes)
.

nombre_de_tabl

a
El nombre (posiblemente calificado por esquema) de una tabla específica a analizar. Si se omite, se analizan todas las tablas normales, tablas particionadas y vistas materializadas en la base de datos actual (pero no las tablas externas). Si se especifica ONLY antes del nombre de la tabla, solo se analiza esa tabla. Si no se especifica ONLY, se analiza la tabla y todas sus tablas hijas de herencia o particiones (si las hay). Opcionalmente, se puede especificar * después del nombre de la tabla para indicar explícitamente que deben analizarse las tablas hijas de herencia (o particiones)
.

nombre_de_column

a
El nombre de una columna es
pecífica a analizar. Por def
ecto, todas las columnas.

SALIDA

S

Cuando se especifica VERBOSE, ANALYZE emite mensajes de progreso para indicar qué tabla se está procesan

do actualmente. También se imprime
n varias estadísticas sobre las tablas.

NOTA

S

Para analizar una tabla, normalmente se debe tener el privilegio MAINTAIN sobre la tabla. Sin embargo, a los propietarios de bases de datos se les permite analizar todas las tablas de sus bases de datos, excepto los catálogos compartidos. ANALYZE omitirá cualquier tabla para la que el usuario que llama no tenga permiso para

analizar.

Las tablas externas solo se analizan cuando se seleccionan explícitamente. No todos los conectores de datos externos (foreign data wrappers) admiten ANALYZE. Si el conector de la tabla no admite ANALYZE, el comando imprime una advertencia y no hace

nada.

En la configuración predeterminada de PostgreSQL, el demonio autovacuum (vea la Sección 24.1.6) se encarga del análisis automático de las tablas cuando se cargan por primera vez con datos y a medida que cambian durante la operación normal. Cuando autovacuum está deshabilitado, es una buena idea ejecutar ANALYZE periódicamente, o justo después de realizar cambios importantes en el contenido de una tabla. Las estadísticas precisas ayudarán al planificador a elegir el plan de consulta más apropiado y, por lo tanto, mejorarán la velocidad del procesamiento de consultas. Una estrategia común para bases de datos de lectura mayoritaria es ejecutar VACUUM y ANALYZE una vez al día durante un momento de baja utilización. (Esto no será suficiente si hay una actividad intensa de actualizaciones.

)

Mientras ANALYZE se está ejecutando, el search_path se cambia temporalmente a pg_catalog,

pg_temp.

ANALYZE solo requiere un bloqueo de lectura sobre la tabla objetivo, por lo que puede ejecutarse en paralelo con otra actividad no DDL sobre la

tabla.

Las estadísticas recopiladas por ANALYZE suelen incluir una lista de algunos de los valores más comunes en cada columna y un histograma que muestra la distribución aproximada de datos en cada columna. Una o ambas pueden omitirse si ANALYZE las considera poco interesantes (por ejemplo, en una columna de clave única, no hay valores comunes) o si el tipo de datos de la columna no admite los operadores apropiados. Hay más información sobre las estadísticas en el Capítulo

24.

Para tablas grandes, ANALYZE toma una muestra aleatoria del contenido de la tabla, en lugar de examinar cada fila. Esto permite analizar incluso tablas muy grandes en una pequeña cantidad de tiempo. Sin embargo, tenga en cuenta que las estadísticas son solo aproximadas y cambiarán ligeramente cada vez que se ejecute ANALYZE, incluso si el contenido real de la tabla no cambió. Esto podría resultar en pequeños cambios en los costos estimados del planificador mostrados por EXPLAIN. En situaciones raras, este no determinismo causará que las elecciones de planes de consulta del planificador cambien después de ANALYZE. Para evitar esto, aumente la cantidad de estadísticas recopiladas por ANALYZE, como se describe a

continuación.

El alcance del análisis se puede controlar ajustando la variable de configuración default_statistics_target, o columna por columna estableciendo el objetivo de estadísticas por columna con ALTER TABLE ... ALTER COLUMN ... SET STATISTICS. El valor objetivo establece el número máximo de entradas en la lista de valores más comunes y el número máximo de intervalos (bins) en el histograma. El valor objetivo predeterminado es 100, pero esto puede ajustarse hacia arriba o hacia abajo para equilibrar la precisión de las estimaciones del planificador contra el tiempo que toma ANALYZE y la cantidad de espacio ocupado en pg_statistic. En particular, establecer el objetivo de estadísticas en cero desactiva la recopilación de estadísticas para esa columna. Podría ser útil hacerlo para columnas que nunca se usan como parte de las cláusulas WHERE, GROUP BY u ORDER BY de las consultas, ya que el planificador no tendrá uso para las estadísticas de esas

columnas.

El mayor objetivo de estadísticas entre las columnas que se están analizando determina el número de filas de la tabla que se muestrean para preparar las estadísticas. Aumentar el objetivo causa un aumento proporcional en el tiempo y el espacio necesarios para hacer ANALYZE

.

Uno de los valores estimados por ANALYZE es el número de valores distintos que aparecen en cada columna. Debido a que solo se examina un subconjunto de las filas, esta estimación a veces puede ser bastante inexacta, incluso con el objetivo de estadísticas más grande posible. Si esta inexactitud conduce a malos planes de consulta, se puede determinar un valor más preciso manualmente y luego instalarlo con ALTER TABLE ... ALTER COLUMN ... SET (n_distinct = ...)

.

Si la tabla que se está analizando tiene hijos de herencia, ANALYZE recopila dos conjuntos de estadísticas: uno sobre las filas solo de la tabla padre, y un segundo que incluye las filas tanto de la tabla padre como de todos sus hijos. Este segundo conjunto de estadísticas es necesario al planificar consultas que procesan el árbol de herencia como un todo. Sin embargo, el demonio autovacuum solo considerará inserciones o actualizaciones en la tabla padre misma al decidir si desencadenar un análisis automático para esa tabla. Si esa tabla rara vez recibe inserciones o actualizaciones, las estadísticas de herencia no estarán actualizadas.e a menos que ejecute ANALYZE manualmente. Por defecto, ANALYZE también recopilará y actualizará recursivamente las estadísticas de cada tabla hija de herencia. La palabra clave ONLY puede usarse para deshabilitar

esto.

Para las tablas particionadas, ANALYZE recopila estadísticas mediante el muestreo de filas de todas las particiones. Por defecto, ANALYZE también recopilará y actualizará recursivamente las estadísticas de cada partición. La palabra clave ONLY puede usarse para deshabilitar

esto.

El demonio autovacuum no procesa las tablas particionadas, ni procesa los padres de herencia si solo se modifican los hijos. Generalmente es necesario ejecutar periódicamente un ANALYZE manual para mantener las estadísticas de la jerarquía de la tabla

actualizadas.

Si alguna de las tablas hijas o particiones son tablas remotas cuyos conectores de datos remotos no admiten ANALYZE, esas tablas se ignoran al recopilar las estadísticas de

herencia.

Si la tabla que se está analizando está completamente vacía, ANALYZE no registrará nuevas estadísticas para esa tabla. Se conservarán las estadísticas

existentes.

Cada proceso backend que ejecute ANALYZE informará de su progreso en la vista pg_stat_progress

_analyze. Consulte la Sección 27.
4.1 para obtener más detalles.

COMPATIBILIDA

D

SQL.

compatible: 
ANALYZE [ VERBOSE ] [ table_and_columns [, ...
]
