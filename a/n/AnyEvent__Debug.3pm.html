AnyEvent::Debug(3) Documentación de Perl aportada por el usuario AnyEvent::Debug(3)

NOMBRE

AnyEvent::Debug - utilidades de depuración para AnyEvent

SINOPSIS

use AnyEvent::Debug;
# crear un shell interactivo dentro del programa
my $shell = AnyEvent::Debug::shell "unix/", "/home/schmorp/myshell";
# luego en el shell: "socat readline /home/schmorp/myshell"

DESCRIPCIÓN

Este módulo proporciona funcionalidad que, se espera, sea útil para depurar.

Por el momento, "solo" se ha implementado un shell interactivo. Este shell le permite "conectarse por telnet" de forma interactiva a su programa y ejecutar código Perl, por ejemplo para inspeccionar variables globales.

FUNCIONES

$shell = AnyEvent::Debug::shell $host, $service
Esta función se enlaza al host y al puerto de servicio dados y devuelve un objeto shell, que determina el tiempo de vida del shell. Se acepta cualquier número de conexiones en el puerto, y le proporcionarán un shell muy primitivo que simplemente ejecuta cada línea que usted introduce.

Todos los comandos se ejecutarán de forma "bloqueante" con el socket "select"ed para la salida. Para una interfaz menos "bloqueante", consulte Coro::Debug.

Los comandos se ejecutarán en el "AnyEvent::Debug::shell" paquete, que actualmente tiene "help" y algunos otros comandos, y puede ser modificado libremente por todos los shells. El código se evalúa bajo "use strict 'subs'".

Cada shell tiene un contexto de registro ($LOGGER) que se adjunta a $AnyEvent::Log::COLLECT), lo cual es especialmente útil para recopilar mensajes de depuración y traza.

Como guía general de programación, considere los aspectos beneficiosos de usar más variables globales ("our") que locales ("my") en el ámbito del paquete: Anteriormente, todos mis módulos tendían a ocultar variables internas dentro de variables "my" , para que los usuarios no pudieran acceder a ellas accidentalmente. Tener acceso interactivo a sus programas cambió eso: tener variables internas todavía en el ámbito global significa que puede depurarlas más fácilmente.

Como no se realiza ninguna autenticación, en la mayoría de los casos es mejor no usar un puerto TCP, sino un socket de dominio unix, que puede colocarse donde usted pueda acceder, pero otros no:

our $SHELL = AnyEvent::Debug::shell "unix/", "/home/schmorp/shell";

Luego puede usar una herramienta para conectarse al shell, como la versátil "socat", que además puede darle soporte de readline:

socat readline /home/schmorp/shell
# o:
cd /home/schmorp; socat readline unix:shell

Socat incluso puede darle un historial persistente:

socat readline,history=.anyevent-history unix:shell

Enlazar en 127.0.0.1 (o "::1") podría ser una alternativa menos segura pero aún no totalmente insegura (en máquinas de un solo usuario) para permitirle usar otras herramientas, como telnet:

our $SHELL = AnyEvent::Debug::shell "127.1", "1357";

Y luego:

telnet localhost 1357
AnyEvent::Debug::wrap [$level]
Establece el nivel de instrumentación/envoltura de todos los observadores que se creen después de esta llamada. Si no se ha especificado $level , entonces alterna entre 0 y 1.

El nivel de envoltura predeterminado es 0, o lo que especifique $ENV{PERL_ANYEVENT_DEBUG_WRAP} .

Un nivel de 0 desactiva la envoltura, es decir, AnyEvent funciona normalmente, y en su modo más eficiente.

Un nivel de 1 o superior activa la envoltura, que reemplaza todos los observadores por objetos AnyEvent::Debug::Wrapped, almacena la ubicación donde se creó un observador y envuelve la devolución de llamada para registrar todas las invocaciones en el nivel de registro "trace" si el trazado está habilitado para el observador. El estado inicial del trazado al crear un observador se toma de la variable global $AnyEvent:Debug::TRACE. El valor predeterminado de esa variable es 1, pero puede tener sentido establecerla en 0 y luego hacer "local $AnyEvent::Debug::TRACE = 1" en un bloque donde cree observadores "interesantes". El trazado también puede activarse y desactivarse más tarde llamando al método "trace" del observador.

El envoltorio también contará cuántas veces se invocó la devolución de llamada y registrará hasta diez errores de ejecución con sus correspondientes retrotrazas. También registrará errores de ejecución en el nivel de registro "error".

Para ver los mensajes de traza, puede invocar su programa con "PERL_ANYEVENT_VERBOSE=9", o puede usar AnyEvent::Log para desviar los mensajes de traza de la manera que prefiera (la sección EJEMPLOS en AnyEvent::Log tiene algunos ejemplos).

Un nivel de 2 hace todo lo que hace el nivel 1 , pero también almacena una retrotraza completa de la ubicación donde se creó el observador, lo que ralentiza considerablemente la creación de observadores.

Cada observador envuelto se vinculará a %AnyEvent::Debug::Wrapped, con su dirección como clave. El comando "wl" en el shell de depuración se puede usar para listar observadores.

La instrumentación puede aumentar el tamaño de cada observador múltiples veces y, especialmente cuando se involucran retrotrazas, también ralentiza mucho la creación de observadores.

Además, activar y desactivar la instrumentación no recuperará el rendimiento completo que tenía antes de la envoltura (las funciones AE::xxx, por ejemplo, seguirán siendo más lentas).

Si está desarrollando su programa, considere también usar AnyEvent::Strict para comprobar errores comunes.

AnyEvent::Debug::path2mod $path
Intenta reemplazar una ruta (por ejemplo, el nombre de archivo devuelto por caller) por un nombre de módulo. Devuelve la ruta sin cambios si falla.

Ejemplo:

print AnyEvent::Debug::path2mod "/usr/lib/perl5/AnyEvent/Debug.pm";
# podría imprimir "AnyEvent::Debug"
AnyEvent::Debug::cb2str $cb
Usando varios trucos, intenta convertir una devolución de llamada (por ejemplo, una referencia de código) en una cadena más útil.

Muy útil si depura un programa y tiene alguna devolución de llamada, pero quiere saber dónde en el programa está realmente definida la devolución de llamada.

AnyEvent::Debug::backtrace [$skip]
Crea una retrotraza (en realidad un objeto AnyEvent::Debug::Backtrace que puede convertir a cadena), no muy diferente a lo que haría el módulo Carp. A diferencia del módulo Carp, resuelve algunas referencias (como devoluciones de llamada) a cadenas más amigables para el usuario, tiene un formato de salida más conciso y, lo más importante: no filtra memoria como un loco.

La razón por la que crea un objeto es para ahorrar tiempo, ya que el formateo se puede hacer en un momento posterior. Aun así, crear una retrotraza es una operación relativamente lenta.

LA CLASE AnyEvent::Debug::Wrapped

Todos los observadores creados mientras el nivel de envoltura no sea cero serán envueltos dentro de un objeto AnyEvent::Debug::Wrapped. La dirección del observador envuelto se convertirá en su ID - cada observador se almacenará en $AnyEvent::Debug::Wrapped{$id}.

Estos objetos envoltorio se pueden convertir a cadena y tienen algunos métodos definidos en ellos.

Para depurar, por supuesto, puede ser útil inspeccionar estos objetos, por lo que esto está documentado aquí, pero esto podría cambiar en cualquier momento en versiones futuras.

Cada objeto es un hash relativamente estándar con los siguientes miembros:

type   => nombre del método usado para crear el observador (p. ej. C<io>, C<timer>).
w      => el observador real
rfile  => referencia al nombre del archivo en el que se creó el observador
line   => número de línea donde se creó
sub    => nombre de la función (o una cadena especial) que creó el observador
cur    => si se creó dentro de la devolución de llamada de otro observador, esta es la representación en cadena del otro observador
now    => la marca de tiempo (AE::now) cuando se creó el observador
arg    => los argumentos utilizados para crear el observador (sin C<cb>)
cb     => la devolución de llamada original utilizada para crear el observador
called => el número de veces que se llamó a la devolución de llamada

Cada objeto soporta los siguientes métodos (advertencia: estos solo están disponibles en observadores envueltos, por lo que son más adecuados para uso interactivo a través de la shell de depuración).

$w->id
Devuelve el id numérico del observador, tal como se usa en la shell de depuración.
$w->verbose
Devuelve una descripción textual multilínea del observador, incluyendo las primeras diez excepciones capturadas al ejecutar la devolución de llamada.
$w->trace ($on)
Habilita ($on es verdadero) o deshabilita ($on es falso) el rastreo en este observador.

Para obtener mensajes de rastreo, tanto la configuración global de registro debe tener los mensajes de rastreo habilitados para el contexto "AnyEvent::Debug" y el rastreo debe estar habilitado para el observador envuelto.

Para habilitar los mensajes de rastreo globalmente, la forma más sencilla es iniciar el programa con "PERL_ANYEVENT_VERBOSE=9" en el entorno.

El rastreo para cada observador individual está habilitado de forma predeterminada (a menos que $AnyEvent::Debug::TRACE se haya establecido en falso).
