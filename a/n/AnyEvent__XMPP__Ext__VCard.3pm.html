NOMBRE

AnyEvent::XMPP::Ext::VCard - VCards (XEP-0054 y XEP-0084)

SINOPSIS

use AnyEvent::XMPP::Ext::VCard;
my $vcard = AnyEvent::XMPP::Ext::VCard->new;
$con->reg_cb (
   stream_ready => sub { $vcard->hook_on ($con) }
);
$vcard->retrieve ($con, 'elmex@jabber.org', sub {
   my ($jid, $vcard, $error) = @_;
   if ($error) {
      warn "no se pudo obtener la vcard para elmex@jabber.org: " . $error->string . "\n";
   } else {
      print "Apodo vCard para elmex@jabber.org: ".$vcard->{NICKNAME}."\n";
      print "Hash del avatar para elmex@jabber.org: ".$vcard->{_avatar_hash}."\n";
   }
});
$vcard->store ($con, undef, { NICKNAME => 'net-xmpp2' }, sub {
   my ($error) = @_;
   if ($error) {
      warn "la subida falló: " . $error->string . "\n";
   } else {
      print "subida exitosa\n";
   }
});
$disco->enable_feature ($vcard->disco_feature);

DESCRIPCIÓN

Esta extensión maneja la configuración y la obtención de la VCard y de los avatares basados en VCard.

Por ejemplo, consulta la suite de pruebas de AnyEvent::XMPP.

MÉTODOS

new (%args)
Crea una nueva extensión de vcard. Puede recibir un "cache" argumento, que debe ser un hash vinculado capaz de guardar las vcards obtenidas. Si no se establece ningún "cache" se usará un hash interno y las vcards se obtendrán cada vez que el programa se reinicie. Las claves serán los JIDs desnudos con stringprep de las personas de las que obtuvimos una vcard y el valor será una estructura de datos hash/array sin ciclos que representa la vcard.

Sobre esta estructura de datos consulta más abajo en ESTRUCTURA DE LA VCARD.

Si deseas soportar avatares correctamente, asegúrate de conectar la conexión mediante el "hook_on" método.

hook_on ($con, $dont_retrieve_vcard)
$con debe ser un objeto de la clase AnyEvent::XMPP::Connection (o derivada). Una vez que la extensión de vCard ha sido conectada a una conexión, añadirá la información del avatar a todas las estanzas de presencia salientes.

IMPORTANTE: Necesitas conectar la conexión ANTES de que esta haya sido conectada. La estanza de presencia inicial necesita contener la información de que soportamos avatares. La vcard se obtendrá automáticamente si la sesión no había comenzado ya. De lo contrario, tendrás que obtener la vcard manualmente si la conectas después de que se haya recibido el "session_ready" evento. Puedes evitar la obtención automática dando un valor verdadero en $dont_retrieve_vcard. Sin embargo, simplemente asegúrate de conectar en cualquier conexión antes de que sea conectada si deseas ofrecer soporte de avatar en ella.

Lo mejor probablemente sea hacerlo así:

my $vcard = AnyEvent::XMPP::Ext::VCard->new;
$con->reg_cb (
   stream_ready => sub { $vcard->hook_on ($con) }
);
my_vcard ($con)
Este método devuelve la vcard para la cuenta conectada por $con. Esto solo funciona si la vcard fue (exitosamente) obtenida. Si la conexión fue conectada, la vcard fue automáticamente obtenida.

Alternativamente $con también puede ser una cadena que representa el JID de una cuenta.

cache ([$newcache])
Consulta también "new" sobre el significado de los hashes de caché. Si no se da ningún argumento, se devuelve la caché actual.
store ($con, $vcard, $cb)
Este método almacenará tu $vcard en el servidor conectado. $cb se llama cuando ocurrió un error o el almacenamiento fue exitoso. Si ocurrió un error, el primer argumento no es indefinido y contiene un objeto AnyEvent::XMPP::Error::IQ.

$con debería ser un AnyEvent::XMPP::Connection o un objeto de alguna clase derivada.

$vcard tiene una estructura de datos como se describe más abajo en ESTRUCTURA DE LA VCARD.

retrieve ($con, $jid, $cb)
Este método obtendrá la vCard para $jid a través de la conexión $con. Si $jid es indefinido, se obtiene la vCard de ti mismo. El callback $cb se llama cuando ocurrió un error o la vcard fue obtenida. El primer argumento del callback será el JID al que pertenece la vCard, el segundo argumento es la vCard misma (como se describe en ESTRUCTURA DE LA VCARD más abajo) y el tercer argumento es el error, si ocurrió uno (undef en caso contrario).

ESTRUCTURA DE LA VCARD

Dado que actualmente no hay implementaciones DOM agradables en Perl y yo desapruebo fuertemente la API DOM en general, este módulo tiene una simple estructura de datos de Perl sin ciclos para representar la vCard.

Primero un ejemplo: Un hash de vCard obtenido puede verse así:

{
  'URL' => ['http://www.ta-sa.org/'],
  'ORG' => [{
             'ORGNAME' => 'nethype GmbH'
           }],
  'N' => [{
           'FAMILY' => 'Redeker'
         }],
  'EMAIL' => ['elmex@ta-sa.org'],
  'BDAY' => ['1984-06-01'],
  'FN' => ['Robin'],
  'ADR' => [
     {
       HOME => undef,
       'COUNTRY' => 'Alemania'
     },
     {
        WORK => undef,
        COUNTRY => 'Alemania',
        LOCALITY => 'Karlsruhe'
     }
  ],
  'NICKNAME' => ['elmex'],
  'ROLE' => ['Programador']
}

Las claves representan el elemento de nivel superior de una vCard, los valores son siempre referencias a arrays que contienen uno o más valores para la clave. Si el valor es una referencia a hash, su valor no será una referencia a array sino que será undef o valores simples.

Los valores de las claves de nivel superior son todas referencias a arrays porque campos como "ADR" pueden ocurrir múltiples veces.

Consulta XEP-0054 para una explicación de lo que significan o contienen estos campos.

Hay campos especiales en esta estructura para manejar avatares: "_avatar" contiene los datos binarios para la imagen del avatar. "_avatar_hash" contiene el hash sha1 codificado en hexadecimal de los datos binarios de la imagen. "_avatar_type" contiene el tipo mime de el avatar.

Si deseas almacenar la vcard, solo tienes que establecer "_avatar" y "_avatar_type" si deseas almacenar un avatar.
