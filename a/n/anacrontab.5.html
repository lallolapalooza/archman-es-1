ANACRONTAB(5) Formatos de archivo ANACRONTAB(5)

NOMBRE

/etc/anacrontab - archivo de configuración para Anacron

DESCRIPCIÓN

El archivo de configuración /etc/anacrontab describe los trabajos controlados por anacron(8). Puede contener tres tipos de líneas: líneas de descripción de trabajo, asignaciones de entorno o líneas vacías.

Las líneas de descripción de trabajo pueden tener el siguiente formato:


periodo en días retardo en minutos identificador-de-trabajo comando

La variable periodo en días especifica la frecuencia de ejecución de un trabajo en días. Esta variable puede representarse por un entero o una macro (@daily, @weekly, @monthly), donde @daily denota el mismo valor que el entero 1, @weekly el mismo que 7, y @monthly especifica que el trabajo se ejecuta una vez al mes, independientemente de la duración del mes.

La variable retardo en minutos especifica el número de minutos que anacron espera, si es necesario, antes de ejecutar un trabajo. Esta variable se representa por un entero donde 0 significa ningún retardo.

La variable identificador-de-trabajo especifica un nombre único de un trabajo que se utiliza en los archivos de registro.

La variable comando especifica el comando a ejecutar. El comando puede ser un comando como ls /proc >> /tmp/proc o un comando para ejecutar un script personalizado.

Las líneas de asignación de entorno pueden tener el siguiente formato:


VAR=VALOR

Se eliminan los espacios alrededor de VAR. No se permiten espacios alrededor de VALOR (a menos que se quieran como parte del valor). La asignación especificada entra en vigor desde la siguiente línea hasta el final del archivo, o hasta la siguiente asignación de la misma variable.

La variable START_HOURS_RANGE define un intervalo (en horas) durante el cual se pueden ejecutar los trabajos programados. En caso de que se pierda este intervalo de tiempo, por ejemplo, debido a un corte de energía, los trabajos programados no se ejecutarán ese día.

La variable RANDOM_DELAY denota el número máximo de minutos que se añadirán al retardo en minutos especificado para cada trabajo. Un RANDOM_DELAY establecido a 12 añadiría, aleatoriamente, entre 0 y 12 minutos al retardo en minutos para cada trabajo en ese anacrontab en particular. Cuando se establece a 0, no se añade retardo aleatorio.

Si MAILTO está definido (y no está vacío), se envía un correo a la dirección especificada, de lo contrario, se utiliza el usuario del sistema.

Si MAILFROM está definido (y no está vacío), se utiliza como la dirección del remitente del sobre, de lo contrario, se utiliza el usuario del sistema.

(Nota: Tanto las variables MAILFROM como MAILTO se expanden, por lo que establecerlas como en el siguiente ejemplo funciona como se espera: MAILFROM=cron-$USER@cron.com ($USER se reemplaza por el usuario del sistema) )

Si NO_MAIL_OUTPUT está definido (y no está vacío), los descriptores de salida estándar y de error de los procesos de trabajo no se redirigen y se envían por correo.

Las líneas vacías son líneas en blanco, líneas que solo contienen espacios en blanco, o líneas con espacios en blanco seguidos de un '#' seguido de un comentario arbitrario.

Puedes continuar una línea en la siguiente línea añadiendo un '\' al final de la misma.

En caso de que quieras deshabilitar Anacron, añade una línea con 0anacron, que es el nombre del script que ejecuta Anacron, en el archivo /etc/cron.hourly/jobs.deny.

EJEMPLO

Este ejemplo muestra cómo configurar un trabajo de Anacron similar en funcionalidad a /etc/crontab que inicia todos los trabajos regulares entre las 6:00 y las 8:00 solamente. Se especifica un RANDOM_DELAY que puede ser de hasta 30 minutos. Los trabajos se ejecutarán de forma serializada en una cola donde cada trabajo se inicia solo después de que el anterior ha finalizado.

# variables de entorno
SHELL=/bin/sh
PATH=/sbin:/bin:/usr/sbin:/usr/bin
MAILTO=root
RANDOM_DELAY=30
# Los trabajos de Anacron comenzarán entre las 6 am y las 8 am.
START_HOURS_RANGE=6-8
# el retardo será de 5 minutos + RANDOM_DELAY para cron.daily
1		5	cron.daily		nice run-parts /etc/cron.daily
7		0	cron.weekly		nice run-parts /etc/cron.weekly
@monthly	0	cron.monthly		nice run-parts /etc/cron.monthly
