NOMBRE

AnyEvent::Socket - cosas útiles de IPv4 e IPv6. también sockets de dominio unix. y cosas.

SINOPSIS

use AnyEvent::Socket;

tcp_connect "gameserver.deliantra.net", 13327, sub {
   my ($fh) = @_
      or die "gameserver.deliantra.net connect failed: $!";

   # disfruta de tu manejador de archivo
};

# un servidor tcp simple
tcp_server undef, 8888, sub {
   my ($fh, $host, $port) = @_;

   syswrite $fh, "The internet is full, $host:$port. Go away!\015\012";
};

DESCRIPCIÓN

Este módulo implementa varias funciones de utilidad para manejar direcciones de protocolo de internet y sockets, de la manera más transparente y sencilla posible.

Todas las funciones documentadas sin "AnyEvent::Socket::" el prefijo se exportan por defecto.

$ipn = parse_ipv4 $dotted_quad
Intenta analizar la dirección IPv4 de cuatro octetos (dotted quad) proporcionada y devolverla en forma de octetos (o undef cuando no está en un formato analizable). Soporta todas las formas especificadas por POSIX (por ejemplo, 10.0.0.1, 10.1, "10.0x020304", 0x12345678 o 0377.0377.0377.0377).
$ipn = parse_ipv6 $textual_ipv6_address
Intenta analizar la dirección IPv6 proporcionada y devolverla en forma de octetos (o undef cuando no está en un formato analizable).

Debería soportar todas las formas especificadas por RFC 2373 (y adicionalmente todas las formas IPv4 soportadas por parse_ipv4). Ten en cuenta que los scope-ids no están soportados (y no se analizarán).

Esta función funciona de manera similar a "inet_pton AF_INET6, ...".

Ejemplo:

print unpack "H*", parse_ipv6 "2002:5345::10.0.0.1";
# => 2002534500000000000000000a000001
print unpack "H*", parse_ipv6 "192.89.98.1";
# => 00000000000000000000ffffc0596201
$token = parse_unix $hostname
Esta función existe principalmente por simetría con las otras "parse_protocol" funciones - toma un nombre de host y, si es "unix/", devuelve un token de dirección especial, de lo contrario "undef".

El único uso para esta función probablemente sea detectar si un nombre de host coincide con lo que AnyEvent usa para los sockets de dominio unix.

$ipn = parse_address $ip
Combina "parse_ipv4", "parse_ipv6" y "parse_unix" en una sola función. La dirección aquí se refiere a la dirección del host (no la dirección del socket) en forma de red (binaria).

Si $text es "unix/", entonces esta función devuelve un token especial reconocido por las otras funciones de este módulo para significar "socket de dominio UNIX".

Si $text a analizar es una dirección IPv4 simple o una IPv4 mapeada en IPv6 (:ffff::<ipv4>), entonces se tratará como una dirección IPv4 y se devolverán cuatro octetos. Si no quieres eso, tienes que llamar a "parse_ipv4" y/o "parse_ipv6" manualmente (esta última siempre devuelve una dirección IPv6 de 16 octetos para direcciones IPv4 mapeadas).

Ejemplo:

print unpack "H*", parse_address "10.1.2.3";
# => 0a010203
$ipn = AnyEvent::Socket::aton $ip
Igual que "parse_address", pero no exportada (piensa en "Socket::inet_aton" pero sin resolución de nombres).
($name, $aliases, $proto) = getprotobyname $name
Funciona como la función incorporada del mismo nombre, excepto que se esfuerza por funcionar incluso en plataformas rotas (bueno, eso es windows), donde getprotobyname es tradicionalmente muy poco fiable.

Ejemplo: obtener el número de protocolo para TCP (usualmente 6)

($host, $service) = parse_hostport $string[, $default_service]
Dividir una cadena de la forma "hostname:port" es un problema común. Desafortunadamente, simplemente dividir por los dos puntos hace difícil especificar direcciones IPv6 y no soporta la sintaxis menos común pero bien estandarizada "[ip literal]" .

Esta función intenta hacer este trabajo de una mejor manera, soporta (al menos) los siguientes formatos, donde "port" puede ser un número de puerto numérico o un nombre de servicio, o una cadena "name=port" , y las partes " port" y ":port" son opcionales. Además, en todas partes donde se soporta una dirección IP también se soporta un nombre de host o una dirección de socket de dominio unix (ver "parse_unix"), y las cadenas que comienzan con "/" también se interpretarán como sockets de dominio unix.

hostname:port    p.ej. "www.linux.org", "www.x.de:443", "www.x.de:https=443",
ipv4:port        p.ej. "198.182.196.56", "127.1:22"
ipv6             p.ej. "::1", "affe::1"
[ipv4or6]:port   p.ej. "[::1]", "[10.0.1]:80"
[ipv4or6] port   p.ej. "[127.0.0.1]", "[www.x.org] 17"
ipv4or6 port     p.ej. "::1 443", "10.0.0.1 smtp"
unix/:path       p.ej. "unix/:/path/to/socket"
/path            p.ej. "/path/to/socket"

También soporta establecer un valor por defecto para el nombre de servicio de una manera sencilla usando $default_service si no se detectó ningún servicio. Si no se detectó ningún servicio ni se especificó un valor por defecto, entonces esta función devuelve la lista vacía. Lo mismo sucede cuando se detecta un error de análisis, como un nombre de host con dos puntos en él (la función es bastante indulgente, sin embargo).

Ejemplo:

print join ",", parse_hostport "localhost:443";
# => "localhost,443"
print join ",", parse_hostport "localhost", "https";
# => "localhost,https"
print join ",", parse_hostport "[::1]";
# => "," (lista vacía)
print join ",", parse_hostport "/tmp/debug.sock";
# => "unix/", "/tmp/debug.sock"

$text = format_address $ipn
Convierte una dirección del host en formato de red (p.ej. 4 octetos para IPv4 o 16 octetos para IPv6) a forma textual.

Devuelve "unix/" para sockets de dominio UNIX.

Esta función funciona de manera similar a "inet_ntop AF_INET || AF_INET6, ...", excepto que detecta automáticamente el tipo de dirección.

$guard = tcp_server $host, $service, $accept_cb[, $prepare_cb]
Crea y enlaza un socket de flujo a la dirección de host y puerto dados, establece la bandera SO_REUSEADDR (si aplica) y llama a "listen". A diferencia de lo que implica el nombre, esta función también puede enlazar en sockets de dominio UNIX.

Para sockets de internet, $host debe ser una dirección IPv4 o IPv6 (o "undef", en cuyo caso se enlaza a 0 o a "::", dependiendo de si el protocolo preferido es IPv4 o IPv6, y posiblemente a ambos en versiones futuras, según corresponda).

Para enlazar a la dirección comodín IPv4, usa 0, para enlazar a la dirección comodín IPv6, usa "::".

El puerto se especifica mediante $service, que debe ser un nombre de servicio o un número de puerto numérico (o 0 o "undef", en cuyo caso se usará un puerto efímero).

Para sockets de dominio UNIX, $host debe ser "unix/" y $service debe ser la ruta absoluta del socket. Esta función intentará "unlink" el socket antes de intentar enlazarlo, y intentará desvincularlo después de dejar de usarlo. Ver CONSIDERACIONES DE SEGURIDAD, más abajo.

Para cada nueva conexión que pueda ser "accept"ada, llama a "$accept_cb->($fh, $host, $port)" con el manejador de archivo (en modo no bloqueante) como primer argumento, y el host y puerto del par como segundo y tercer argumentos (ver "tcp_connect" para detalles).

Lanza un error fatal ante cualquier error que pueda detectar antes del listen.

En contexto no anónimo, esta función devuelve un objeto guardia cuyo ciclo de vida está ligado al servidor TCP: si el objeto es destruido, el servidor se detendrá y el socket de escucha será limpiado/desvinculado (las conexiones ya aceptadas no se verán afectadas).

Cuando se llama en contexto anónimo, AnyEvent mantendrá el socket de escala vivo internamente. En este caso, no hay garantía de que el socket de escucha sea limpiado o desvinculado.

En todos los casos, cuando la función retorna al llamador, el socket está enlazado y en estado de escucha.

Si necesitas más control sobre el socket de escucha, puedes proporcionar un "$prepare_cb->($fh, $host, $port)", que se llama justo antes de la "listen ()" llamada, con el manejador de archivo de escucha como primer argumento, y la dirección IP y el número de puerto del endpoint local del socket como segundo y tercer argumentos.

Debe devolver la longitud de la cola de escucha (o 0 para el valor por defecto).

Nota para usuarios de IPv6: El comportamiento conforme a RFC para sockets IPv6 que escuchan en "::" es enlazar a las direcciones IPv6 e IPv4 por defecto en hosts de doble pila. Desafortunadamente, solo GNU/Linux parece implementar esto correctamente, así que si quieres tanto sockets de escucha IPv4 como IPv6, debes crear el socket IPv6 primero y luego intentar enlazar el socket IPv4, pero ignorando cualquier "EADDRINUSE" error.

Igual que "tcp_server", excepto que no llama a "accept" en un bucle por ti, sino que simplemente pasa el socket de escucha al $done_cb. Esto es útil cuando quieres tener una configuración conveniente para tu socket de escucha, pero quieres hacer el "accept"tú mismo, por ejemplo, en otro proceso.

tcp_nodelay $fh, $enable
Habilita (o deshabilita) la opción de socket "TCP_NODELAY" (también conocida como algoritmo de Nagle). Devuelve falso en caso de error, verdadero en caso contrario.
tcp_congestion $fh, $algorithm
Establece el algoritmo de evitación de congestión TCP (mediante la opción de socket "TCP_CONGESTION" ). El valor por defecto es específico del sistema operativo, pero usualmente es "reno". Otras opciones disponibles típicas incluyen "cubic", "lp", "bic", "highspeed", "htcp", "hybla", "illinois", "scalable", "vegas", "veno", "westwood" y "yeah".

CONSIDERACIONES DE SEGURIDAD

Este módulo es bastante poderoso, con ese poder viene la capacidad de abusar también: Si aceptas "nombres de host" y puertos de fuentes no confiables, ten en cuenta que esto puede ser abusado para borrar archivos (host="unix/"). Esto no es realmente un problema con este módulo, sin embargo, ya que aceptar ciegamente cualquier dirección y protocolo e intentar enlazar un servidor o conectarse a él es dañino en general.
