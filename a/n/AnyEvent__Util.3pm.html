portable_pipe
Llamar a "pipe" en Perl es portable - excepto que no funciona realmente en las plataformas Windows de porquería (al menos no con la mayoría de los perls - el perl de cygwin notablemente funciona bien): En Windows, en realidad obtienes dos manejadores de archivo con los que no puedes usar select.

Esta función te da una tubería que funciona incluso en la plataforma Windows rota (creando un par de sockets TCP en Windows, así que no esperes ninguna velocidad de eso) y usando "pipe" en todas partes

más.

bidireccional.

fork_call { CODE } @args, $cb->
(@res)
Ejecuta el bloque de código dado de forma asíncrona, mediante un fork. Todo lo que el bloque devuelva se transferirá al proceso que llama (serializando y deserializando vía Storable).

Si hay algún error, entonces el $cb se llamará sin ningún argumento. En ese caso, o bien $@ contiene la excepción (y $! es irrelevante), o bien $! contiene un número de error. En todos los demás casos, $@ será "undef"in

ido.

El bloque de código no debe llamar nunca a una función de sondeo de eventos ni usar programación basada en eventos que pueda hacer que se ejecuten callbacks registrados en el proceso

padre.

Advertencias de Win32: Debido a los perls nativos de Windows infinitamente malos y rotos (no hay una manera limpia de salir de un proceso hijo en esa plataforma que no mate también al padre), tienes que asegurarte de que tu programa principal no salga mientras haya algún "fork_calls" todavía en progreso, de lo contrario el programa no saldrá. Además, en la mayoría de las plataformas Windows se fugará algo de memoria por cada invocación. Estamos abiertos a mejoras que no requieran trucos

con XS.

Ten en cuenta que el fork puede ser costoso en programas grandes (RSS 200MB+). En Windows, es terriblemente lento, no esperes más de 5..20 forks/s en esa plataforma de porquería (ten en cuenta que esto usa los pseudo-hilos de perl, así que evítalos como la

peste).

Ejemplo: E/S de disco asíncrona para pobres (mejor usar AnyEvent::IO junto con

IO::AIO). 
fork_call {
   open my $fh, "</etc/passwd"
      or die "passwd: $!";
   local $/;
   <$fh>
} sub {
   my ($passwd) = @_;
...
};

$guard = guard { CODE
}
Esta función crea un objeto especial que, al ser destruido, ejecutará el bloque de código.

Esto es a menudo útil en código de estilo de paso de continuación para limpiar algún recurso sin importar dónde salgas de un

proceso.

El módulo Guard se usará para implementar esta función, si está disponible. De lo contrario, se usa una implementación en perl

puro.

Aunque se permite que el código lance excepciones en condiciones inusuales, no está definido si esta excepción será reportada (en este momento, tanto el módulo Guard como la implementación en perl puro de AnyEvent intentan reportar el error y continuar)

cancel

AnyEvent::Util::close_all_fds_except
@fds
Esta función rara vez usada simplemente cierra todos los descriptores de archivo (o intenta hacerlo) del proceso actual excepto los dados como argumentos.

Cuando quieras iniciar un servidor de fondo de larga duración, a menudo es beneficioso hacer esto, ya que demasiadas bibliotecas C son demasiado estúpidas como para marcar sus descriptores de archivo internos como

close-on-exec.

Se espera que la función sea llamada justo antes de una llamada a "exec

".

Ejemplo: cerrar todos los descriptores de archivo

excepto 0, 1, 2.

2,

AnyEvent::Util::idn_nameprep $idn[,
$display]
Implementa el algoritmo de normalización nameprep de IDNA. O en realidad el algoritmo UTS#46. O tal vez algo similar - la realidad es complicada entre IDNA2003, UTS#46 e IDNA2008. Si $display es verdadero, entonces el nombre se prepara para visualización, de lo contrario se prepara para búsqueda (predeterminado).

Si no tiene idea de lo que esto significa, mire "idn_to_ascii" en su

lugar.

Esta función está diseñada para evitar el uso de muchos recursos - usa aproximadamente 1MB de RAM (

la mayor parte de esto se debe a Unicode::Normalize). Además, los nombres que ya son "simples" sol
o se verificarán para una validez básica, sin la sobrecarga del procesamiento completo de nameprep.
$domainname = AnyEvent::Util::idn_to_ascii
$idn
Convierte la cadena unicode dada ($idn, nombre de dominio internacional, por ejemplo, 日本語。ＪＰ) a un nombre de dominio puramente ASCII (esto generalmente se llama la transformación "IDN ToAscii"). Esta transformación es idempotente, lo que significa que puede llamarla por si acaso y hará lo correcto.

A diferencia de algunas otras implementaciones de "ToAscii", esta trabaja con nombres de dominio completos y nunca debería fallar - si no puede convertir el nombre, lo retornará sin

cambios.

Esta función es un amalgama de IDNA2003, UTS#46 e IDNA2008 - intenta ser razonablemente compa

tible con otras implementaciones, razonablemente segura, tanto como los IDNs pueden ser seguro
s, y razonablemente eficiente cuando se enfrenta a IDNs que ya son nombres DNS válidos.
$idn = AnyEvent::Util::idn_to_unicode
$idn
Convierte la cadena unicode dada ($idn, nombre de dominio internacional, por ejemplo, 日本語。ＪＰ, www.deliantra.net, www.xn--l-0ga.de) a forma unicode (esto generalmente se llama la transformación "IDN ToUnicode"). Esta transformación es idempotente, lo que significa que puede llamarla por si acaso y hará lo correcto.

A diferencia de algunas otras implementaciones de "ToUnicode", esta trabaja con nombres de dominio completos y nunca debería fallar - si no puede convertir el nombre, lo retornará sin

cambios.

Esta función es un amalgama de IDNA2003, UTS#46 e IDNA2008 - intenta ser razonablemente compatible con otras implementaciones, razonablemente segura, tanto como los IDNs pueden ser seguros, y razonablemente eficiente cuando se enfrenta a IDNs que ya son nombres DNS
