ansible-playbook(1) Comandos de administración del sistema ansible-playbook(1)

Nombre

ansible-playbook - Ejecuta playbooks de Ansible, ejecutando las tareas definidas en los hosts de destino.

SINOPSIS

uso: ansible-playbook [-h] [--version] [-v] [--private-key PRIVATE_KEY_FILE]
[-u REMOTE_USER] [-c CONNECTION] [-T TIMEOUT] [--ssh-common-args SSH_COMMON_ARGS] [--sftp-extra-args SFTP_EXTRA_ARGS] [--scp-extra-args SCP_EXTRA_ARGS] [--ssh-extra-args SSH_EXTRA_ARGS] [-k | --connection-password-file CONNECTION_PASSWORD_FILE] [--force-handlers] [-b] [--become-method BECOME_METHOD] [--become-user BECOME_USER] [-K | --become-password-file BECOME_PASSWORD_FILE] [-t TAGS] [--skip-tags SKIP_TAGS] [-C] [-D] [-i INVENTORY] [--list-hosts] [-l SUBSET] [--flush-cache] [-e EXTRA_VARS] [--vault-id VAULT_IDS] [-J | --vault-password-file VAULT_PASSWORD_FILES] [-f FORKS] [-M MODULE_PATH] [--syntax-check] [--list-tasks] [--list-tags] [--step] [--start-at-task START_AT_TASK] playbook [playbook ...]

DESCRIPCIÓN

la herramienta para ejecutar playbooks de Ansible, que son un sistema de configuración y despliegue multinodo. Consulte la página principal del proyecto (https://docs.ansible.com) para más información.

OPCIONES COMUNES

Playbook(s)

--become-method 'BECOME_METHOD'

método de escalada de privilegios a usar (predeterminado=sudo), use ansible-doc -t become -l para listar las opciones válidas.

--become-password-file 'BECOME_PASSWORD_FILE', --become-pass-file 'BECOME_PASSWORD_FILE'

Archivo de contraseña de escalada de privilegios

--become-user 'BECOME_USER'

ejecutar operaciones como este usuario (predeterminado=root)

--connection-password-file 'CONNECTION_PASSWORD_FILE', --conn-pass-file 'CONNECTION_PASSWORD_FILE'

Archivo de contraseña de conexión

--flush-cache

borrar la caché de hechos para cada host en el inventario

--force-handlers

ejecutar manejadores incluso si una tarea falla

--list-hosts

muestra una lista de hosts coincidentes; no ejecuta nada más

--list-tags

listar todas las etiquetas disponibles

--list-tasks

listar todas las tareas que se ejecutarían

--private-key 'PRIVATE_KEY_FILE', --key-file 'PRIVATE_KEY_FILE'

usar este archivo para autenticar la conexión

--scp-extra-args 'SCP_EXTRA_ARGS'

especificar argumentos adicionales para pasar solo a scp (por ejemplo, -l)

--sftp-extra-args 'SFTP_EXTRA_ARGS'

especificar argumentos adicionales para pasar solo a sftp (por ejemplo, -f, -l)

--skip-tags

ejecutar solo las jugadas y tareas cuyas etiquetas no coincidan con estos valores. Este argumento puede especificarse varias veces.

--ssh-common-args 'SSH_COMMON_ARGS'

especificar argumentos comunes para pasar a sftp/scp/ssh (por ejemplo, ProxyCommand)

--ssh-extra-args 'SSH_EXTRA_ARGS'

especificar argumentos adicionales para pasar solo a ssh (por ejemplo, -R)

--start-at-task 'START_AT_TASK'

iniciar el playbook en la tarea que coincida con este nombre

--step

un paso a la vez: confirmar cada tarea antes de ejecutarla

--syntax-check

realizar una comprobación de sintaxis en el playbook, pero no ejecutarlo

--vault-id

la identidad de bóveda a usar. Este argumento puede especificarse varias veces.

--vault-password-file, --vault-pass-file

archivo de contraseña de bóveda

--version

mostrar el número de versión del programa, la ubicación del archivo de configuración, la ruta de búsqueda de módulos configurada, la ubicación del módulo, la ubicación del ejecutable y salir

-C, --check

no hacer ningún cambio; en su lugar, intentar predecir algunos de los cambios que puedan ocurrir

-D, --diff

al cambiar archivos y plantillas (pequeños), mostrar las diferencias en esos archivos; funciona muy bien con --check

-J, --ask-vault-password, --ask-vault-pass

pedir la contraseña de bóveda

-K, --ask-become-pass

pedir la contraseña de escalada de privilegios

-M, --module-path

anteponer ruta(s) separada(s) por dos puntos a la biblioteca de módulos (predeterminado={{ ANSIBLE_HOME ~ "/plugins/modules:/usr/share/ansible/plugins/modules" }}). Este argumento puede especificarse varias veces.

-T 'TIMEOUT', --timeout 'TIMEOUT'

anular el tiempo de espera de conexión en segundos (el valor predeterminado depende de la conexión)

-b, --become

ejecutar operaciones con escalada de privilegios (no implica solicitud de contraseña)

-c 'CONNECTION', --connection 'CONNECTION'

tipo de conexión a usar (predeterminado=ssh)

-e, --extra-vars

establecer variables adicionales como clave=valor o YAML/JSON, si es un nombre de archivo, anteponer @. Este argumento puede especificarse varias veces.

-f 'FORKS', --forks 'FORKS'

especificar el número de procesos paralelos a usar (predeterminado=5)

-h, --help

mostrar este mensaje de ayuda y salir

-i, --inventory, --inventory-file

especificar la ruta del archivo de inventario o una lista de hosts separada por comas. Este argumento puede especificarse varias veces.

-k, --ask-pass

pedir la contraseña de conexión

-l 'SUBSET', --limit 'SUBSET'

limitar aún más los hosts seleccionados a un patrón adicional

-t, --tags

ejecutar solo las jugadas y tareas etiquetadas con estos valores. Este argumento puede especificarse varias veces.

-u 'REMOTE_USER', --user 'REMOTE_USER'

conectarse como este usuario (predeterminado=None)

-v, --verbose

Hace que Ansible imprima más mensajes de depuración. Agregar múltiples -v aumentará la verbosidad, los plugins integrados actualmente evalúan hasta -vvvvvv. Un nivel razonable para empezar es -vvv, la depuración de la conexión podría requerir -vvvv. Este argumento puede especificarse varias veces.

INVENTARIO

Ansible almacena los hosts en los que potencialmente puede operar en un inventario. Este puede ser un archivo YAML, un archivo tipo ini, un script, un directorio, una lista, etc. Para opciones adicionales, consulte la documentación en https://docs.ansible.com/.

ENTORNO

Se pueden especificar las siguientes variables de entorno.

ANSIBLE_INVENTORY -- Anula las fuentes de inventario predeterminadas de ansible

ANSIBLE_LIBRARY -- Anula la ruta de la biblioteca de módulos predeterminada de ansible

ANSIBLE-CONFIG

ANSIBLE_CONFIG -- Specify override location for the ansible config file

Many more are available for most options in ansible.cfg

For a full list check https://docs.ansible.com/. or use the ansible-config command.

ARCHIVOS

/etc/ansible/hosts -- Archivo de inventario predeterminado

/etc/ansible/ansible.cfg -- Archivo de configuración, se usa si está presente

~/.ansible.cfg -- Archivo de configuración del usuario, anula la configuración predeterminada si está presente

./ansible.cfg -- Archivo de configuración local (en el directorio de trabajo actual) se asume que es 'específico del proyecto' y anula el resto si está presente.

Como se mencionó anteriormente, la variable de entorno ANSIBLE_CONFIG anulará todas las demás.
