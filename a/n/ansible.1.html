NAME

ansible - Ansible ad-hoc command and module utility

SYNOPSIS

ansible [pattern] -m module_name -a arguments

ansible [pattern] -m module_name --args arguments

ansible-config [options]

ansible-inventory [options]

ansible-playbook [options] playbook.yml

ansible-galaxy [options]

ansible-doc [options] [module-name ...]

ansible-console [options]

ansible-vault [options] [command]

ansible-pull [options]

DESCRIPTION

Ansible is a simple, powerful, and secure automation engine. It can be used to perform ad-hoc tasks, manage configuration, orchestrate complex workflows, and more. Ansible works over SSH by default and does not require any agents to be installed on the remote systems.

This manual page primarily describes the ansible command, which is used for running ad-hoc Ansible modules.

Other Ansible commands include:

  • ansible-config: Manage Ansible configuration settings.
  • ansible-inventory: Manage Ansible inventory sources.
  • ansible-playbook: Run Ansible playbooks.
  • ansible-galaxy: Manage Ansible roles and collections.
  • ansible-doc: Display Ansible module documentation.
  • ansible-console: An interactive Ansible command-line interface.
  • ansible-vault: Manage Ansible encrypted files and secrets.
  • ansible-pull: Run Ansible playbooks using a pull model.

COMMON OPTIONS

The following options are common to many Ansible commands:

  • -i INVENTORY_FILE, --inventory-file INVENTORY_FILE: Specify an inventory file or host list. Default is /etc/ansible/hosts.
  • -l SUBSET, --limit SUBSET: Further limit the subset of hosts to execute the module against.
  • -f FRACTION, --forks FRACTION: Specify the number of parallel processes to use. Default is 5.
  • -m MODULE_NAME, --module-name MODULE_NAME: The module to run. Default is 'command'.
  • -a ARGUMENTS, --args ARGUMENTS: The arguments to pass to the module.
  • -u REMOTE_USER, --user REMOTE_USER: Run tasks as this user on the remote nodes.
  • -k, --ask-pass: Ask for the remote user's password.
  • -K, --ask-become-pass: Ask for the privilege escalation password.
  • -b, --become: Execute the module with privilege escalation (e.g., sudo).
  • -D, --diff: Show differences in the output when using modules that can diff.
  • -v, --verbose: Increase verbosity. Can be specified multiple times.
  • -h, --help: Show help message and exit.

INVENTORY

Ansible uses an inventory to determine which hosts to manage. The default inventory file is located at /etc/ansible/hosts. You can specify a different inventory file using the -i option.

Inventory can be defined in static files (INI or YAML format) or dynamically using inventory scripts or plugins.

ENVIRONMENT

Ansible respects the following environment variables:

ANSIBLE_HOST_KEY_CHECKING -- Turn off or on host key checking. (Default: True)

ANSIBLE_REMOTE_USER -- Override the default remote user when connecting to hosts.

ANSIBLE_BECOME -- Override the default for privilege escalation. (Default: False)

ANSIBLE_BECOME_METHOD -- Override the default privilege escalation method. (Default: sudo)

ANSIBLE_BECOME_USER -- Override the default user for privilege escalation. (Default: root)

ANSIBLE_CONNECTION -- Override the default connection plugin. (Default: smart)

ANSIBLE_TIMEOUT -- Override the default connection timeout. (Default: 10)

ANSIBLE_PRIVATE_KEY_FILE -- Override the default SSH private key file.

ANSIBLE_HOSTS -- Override the default ansible inventory sources

ANSIBLE_LIBRARY -- Override the default ansible module library path

ANSIBLE_CONFIG -- Specify override location for the ansible config file

Many more are available for most options in ansible.cfg

For a full list check https://docs.ansible.com/. or use the ansible-config command.

FILES

/etc/ansible/hosts -- Default inventory file

/etc/ansible/ansible.cfg -- Config file, used if present

~/.ansible.cfg -- User config file, overrides the default config if present

./ansible.cfg -- Local config file (in current working directory) assumed to be 'project specific' and overrides the rest if present.

As mentioned above, the ANSIBLE_CONFIG environment variable will override all others.
