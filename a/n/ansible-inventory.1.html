ansible-inventory(1) Comandos de administración del sistema ansible-inventory(1)

Nombre

ansible-inventory - Muestra la información del inventario de Ansible, por defecto usa el formato JSON del script de inventario

SINOPSIS

uso: ansible-inventory [-h] [--version] [-v] [-i INVENTORY] [-l SUBSET]
[--flush-cache] [--vault-id VAULT_IDS] [-J | --vault-password-file VAULT_PASSWORD_FILES] [--playbook-dir BASEDIR] [-e EXTRA_VARS] [--list] [--host HOST] [--graph] [-y] [--toml] [--vars] [--export] [--output OUTPUT_FILE] [group]

DESCRIPCIÓN

utilizado para mostrar o volcar el inventario configurado tal como lo ve Ansible

OPCIONES COMUNES

El nombre de un grupo en el inventario, relevante al usar --graph

--export

Al hacer --list, representa de una manera optimizada para exportar, no como una representación exacta de cómo Ansible lo ha procesado

--flush-cache

limpia la caché de hechos para cada host en el inventario

--graph

crea un gráfico del inventario, si se proporciona un patrón debe ser un nombre de grupo válido. Ignorará el límite

--host 'HOST'

Muestra la información de un host específico, funciona como script de inventario. Ignorará el límite

--list

Muestra la información de todos los hosts, funciona como script de inventario

--output 'OUTPUT_FILE'

Al hacer --list, envía el inventario a un archivo en lugar de a la pantalla

--playbook-dir 'BASEDIR'

Dado que esta herramienta no usa playbooks, usa esto como directorio de playbooks sustituto. Esto establece la ruta relativa para muchas características incluyendo roles/ group_vars/ etc.

--toml

Usa el formato TOML en lugar del JSON predeterminado, ignorado para --graph

--vars

Añade variables al gráfico, ignorado a menos que se use con --graph

--vault-id

la identidad del bóveda a usar. Este argumento puede especificarse múltiples veces.

--vault-password-file, --vault-pass-file

archivo de contraseña del bóveda

--version

muestra el número de versión del programa, la ubicación del archivo de configuración, la ruta de búsqueda de módulos configurada, la ubicación de los módulos, la ubicación del ejecutable y sale

-J, --ask-vault-password, --ask-vault-pass

pide la contraseña del bóveda

-e, --extra-vars

establece variables adicionales como clave=valor o YAML/JSON, si es un nombre de archivo antepóngale @. Este argumento puede especificarse múltiples veces.

-h, --help

muestra este mensaje de ayuda y sale

-i, --inventory, --inventory-file

especifica la ruta del inventario o una lista de hosts separada por comas. Este argumento puede especificarse múltiples veces.

-l 'SUBSET', --limit 'SUBSET'

limita aún más los hosts seleccionados a un patrón adicional

-v, --verbose

Hace que Ansible imprima más mensajes de depuración. Añadir múltiples -v aumentará la verbosidad, los plugins integrados actualmente evalúan hasta -vvvvvv. Un nivel razonable para empezar es -vvv, la depuración de la conexión podría requerir -vvvv. Este argumento puede especificarse múltiples veces.

-y, --yaml

Usa el formato YAML en lugar del JSON predeterminado, ignorado para --graph

ARGUMENTOS

group

El nombre de un grupo en el inventario, relevante al usar --graph

INVENTORY

Ansible almacena los hosts en los que potencialmente puede operar en un inventario. Este puede ser un archivo YAML, un archivo tipo ini, un script, un directorio, una lista, etc. Para opciones adicionales, consulte la documentación en https://docs.ansible.com/.

ENTORNO

Se pueden especificar las siguientes variables de entorno.

ANSIBLE_INVENTORY -- Anula las fuentes de inventario predeterminadas de ansible

ANSIBLE_CONFIG -- Especifica la ubicación de anulación para el archivo de configuración de ansible

Hay muchas más disponibles para la mayoría de las opciones en ansible.cfg

Para una lista completa, consulte https://docs.ansible.com/. o use el comando ansible-config .

ARCHIVOS

/etc/ansible/hosts -- Archivo de inventario predeterminado

/etc/ansible/ansible.cfg -- Archivo de configuración, usado si está presente

~/.ansible.cfg -- Archivo de configuración del usuario, anula la configuración predeterminada si está presente

./ansible.cfg -- Archivo de configuración local (en el directorio de trabajo actual) se asume que es 'específico del proyecto' y anula al resto si está presente.

Como se mencionó anteriormente, la variable de entorno ANSIBLE_CONFIG anulará a todas las demás.

    ansible-inventory

    ansible-inventory - Manage Ansible inventory plugins

    SYNOPSIS

    ansible-inventory [OPTIONS] [INVENTORY_SOURCE]

    DESCRIPTION

    The ansible-inventory command can be used to get a list of inventory sources and to manage Ansible inventory plugins. This command requires that the Ansible inventory plugins are installed and available to Ansible.

    OPTIONS

    --list
    List all available inventory sources.
    --yaml
    Output the inventory in YAML format.
    --json
    Output the inventory in JSON format.
    --toml
    Output the inventory in TOML format.
    -i INVENTORY_SOURCE --inventory INVENTORY_SOURCE
    Specify the inventory source to use. This can be a file path, a directory, or a URL.
    --plugin PLUGIN_NAME
    Specify the name of the inventory plugin to use.
    -h --help
    Show the help message and exit.

    EXAMPLES 

    
# List all available inventory sources
ansible-inventory --list

# Get inventory from a file in YAML format
ansible-inventory -i inventory.yaml --yaml

# Get inventory from a directory in JSON format
ansible-inventory -i inventory_dir --json

# Get inventory from a URL using the aws_ec2 plugin
ansible-inventory -i "aws_ec2:///" --plugin aws_ec2 --json

    RETURN VALUE

    Returns 0 on success, and non-zero on failure.

    FILES

    /etc/ansible/ansible.cfg
    Ansible configuration file.
    ~/.ansible.cfg
    User-specific Ansible configuration file.
