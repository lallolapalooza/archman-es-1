NOMBRE

alpm - Gestión de Paquetes de Arch Linux.

DESCRIPCIÓN

Arch Linux Package Management (ALPM), describe el proceso de obtención de las fuentes de proyectos upstream, opcionalmente su compilación, empaquetado en un formato de paquete dedicado (ver alpm-package) y distribución de esos archivos de paquete a los usuarios de la distribución Arch Linux[1].

El formato utilizado para la distribución de software como artefactos binarios precompilados es de acceso abierto y se documenta a alto nivel en las siguientes secciones. Aparte de Arch Linux[1] puede encontrar uso en otras distribuciones o en otras plataformas.

Descargo de responsabilidad

A lo largo de este documento el término “repositorio” aparece en diferentes contextos:

  • alpm-source-repo: Un repositorio (por ejemplo, un repositorio git) que contiene scripts de compilación de paquetes PKGBUILD, a partir de los cuales se compilan uno o varios archivos alpm-package. Además de los scripts de compilación de paquetes, un alpm-source-repo puede contener también un archivo SRCINFO, que proporciona una colección de metadatos sobre los datos definidos en el archivo PKGBUILD.
  • alpm-repo: Un repositorio (por ejemplo, un directorio servido por un servidor web) que proporciona archivos alpm-package, firmas digitales y archivos alpm-repo-db que definen el estado del alpm-repo. Cada alpm-repo-db contiene metadatos específicos relacionados con el paquete (es decir, alpm-repo-desc y alpm-repo-files).

En resumen, alpm-source-repo es la ubicación desde la que se compilan los archivos alpm-package, mientras que alpm-repo es la ubicación donde se almacenan esos archivos posteriormente.

Compilación a partir de fuentes

Los archivos de datos del paquete, como binarios u otros artefactos de datos, se crean a partir de un alpm-source-repo. Este proceso se abstrae utilizando herramientas dedicadas de compilación de paquetes como makepkg, que dependen de scripts de compilación de paquetes basados en bash, los PKGBUILD.

Los scripts de compilación de paquetes definen el entorno en el que se crean y utilizan los paquetes. Esto incluye sus entradas de origen, dependencias de compilación, en tiempo de ejecución y de prueba, así como todos los pasos necesarios para la creación de archivos de datos, su prueba e instalación. Los scripts de compilación de paquetes también proporcionan metadatos sobre los paquetes, como nombre, versión, descripción, grupos, fuentes o sumas de verificación. Las herramientas de compilación automatizan los pasos de descarga y verificación de entradas de origen locales o upstream, la aplicación de cualquier modificación requerida (por ejemplo, parches), la llamada a los sistemas de compilación respectivos, la ejecución de pruebas y la instalación de los binarios resultantes u otros artefactos de datos en una ubicación desde la que se crea un archivo de paquete.

La herramienta makepkg es capaz de registrar metadatos relevantes del entorno del sistema actual en un archivo BUILDINFO. Basándose en este archivo, se puede configurar de nuevo un entorno idéntico, lo que es un requisito previo para las compilaciones reproducibles[2].

Generalmente, es deseable crear un archivo alpm-package en un entorno aislado que pueda configurarse de forma reproducible (por ejemplo, chroots, contenedores o máquinas virtuales) y que solo contenga las diversas dependencias de un paquete (ver alpm-package-relation). Sin embargo, makepkg por sí solo no puede garantizar que un entorno de compilación solo contenga paquetes que satisfagan las diversas dependencias de un paquete. Es por eso que la herramienta canónica de empaquetado de Arch Linux, pkgctl, crea entornos de chroot limpios con la ayuda de systemd-nspawn y ejecuta makepkg dentro de ellos.

Descarga, verificación y autenticación

Las entradas (es decir, las fuentes) de un script de compilación de paquetes pueden ser archivos locales o remotos o datos en sistemas de control de versiones. Después de la descarga, se verifican utilizando resúmenes de hash bloqueados opcionales (ver alpm-package-source-checksum) para los archivos respectivos. Este es un bloque de construcción fundamental para las compilaciones reproducibles[2] y permite detectar vectores de ataque a la cadena de suministro[3] que dependen de la alteración de archivos fuente. Además, cada entrada puede autenticarse mediante una firma criptográfica.

Modificación

A veces es necesario modificar las entradas de compilación de paquetes para corregir problemas con los propios archivos de entrada o para adaptarse al comportamiento específico del entorno en el que se supone que deben utilizarse. La aplicación de parches es un escenario común y generalmente se realiza en un paso de preparación después de la descarga, verificación y autenticación de las entradas.

Compilación

El siguiente paso después de la posible modificación de las entradas de origen es generar archivos de datos para el archivo alpm-package. Esto puede incluir la compilación de archivos binarios, traducciones, recursos, datos planos o cualquier otro tipo de archivo que pueda incluirse en un paquete. Dependiendo de la entrada de origen y del lenguaje de programación, pueden ser necesarias diversas herramientas para compilar artefactos binarios a partir del código fuente.

Pruebas

Después de una compilación exitosa, se ejecutan todas las pruebas disponibles del proyecto respectivo para garantizar que el proyecto dado pueda integrarse con el sistema contra el que se compiló.

Instalación

Finalmente, todos los archivos de datos del paquete generados se instalan en un directorio de salida vacío, ya sea utilizando el sistema de compilación del proyecto o manualmente. Durante este paso, la herramienta de compilación de paquetes también crea los archivos de metadatos requeridos, como BUILDINFO, PKGINFO y ALPM-MTREE.

Cuando se crean más de un alpm-package a partir de un PKGBUILD, se crean tantos directorios de salida como paquetes haya. Para obtener información sobre la creación de varios paquetes a partir de un solo PKGBUILD, consulte alpm-split-package.

Creación de paquetes

Se crea un archivo alpm-package por cada directorio de salida después de la compilación a partir de fuentes, las pruebas y la instalación. Los archivos de paquete son archivos tar opcionalmente comprimidos, que contienen todos los archivos que se han instalado en el directorio de salida vacío, un alpm-install-scriptlet opcional y los archivos de metadatos específicos de ALPM BUILDINFO, PKGINFO y ALPM-MTREE.

Una vez creado un paquete, puede ser firmado digitalmente. ALPM actualmente soporta firmas OpenPGP[4] desacopladas para este propósito. Con la ayuda de firmas digitales, la autenticidad de un archivo de paquete puede verificarse posteriormente utilizando el certificado OpenPGP[5] del empaquetador.

Mantenimiento de repositorios de paquetes

Un alpm-repo es una colección de archivos alpm-package únicos en versiones específicas y una alpm-repo-db que describe este estado particular. Cada archivo de paquete se describe mediante un archivo alpm-repo-desc en el alpm-repo-db. Este archivo se crea a partir de una combinación de los datos PKGINFO de los archivos de paquete, la firma digital opcional

naturaleza y los metadatos del archivo del paquete en

sí.

Los repositorios de paquetes se mantienen con la ayuda de herramientas dedicadas como repo-add. Para servir configuraciones de repositorio más complejas y evolucionadas, permitiendo al mismo tiempo el acceso a un conjunto más amplio de mantenedores de paquetes, Arch Linux se basa en dbscri

pts[6].

Instalación de

paquetes

Los paquetes basados en ALPM se instalan utilizando software de gestión de paquetes como pacman. Aunque los paquetes pueden instalarse y actualizarse individualmente, se utilizan principalmente a través de repositorios de paquetes. Para ello, el software de gestión de paquetes descarga el archivo alpm-repo-db de cada alpm-repo que está configurado para usar. Basándose en sus datos, puede comparar el estado de todos los repositorios de paquetes especificados y sus archivos de paquetes con el estado de un sistema local. Si se detectan versiones más nuevas de los paquetes en el alpm-repo-db, el software de gestión de paquetes descarga estos nuevos archivos de paquetes y los

instala.

La instalación de un archivo de paquete implica varias

cosas:
  • La eliminación de todos los archivos del sistema de archivos, que son proporcionados por la versión del paquete previamente
    • instalada.
  • La adición de todos los archivos al sistema de archivos, que son proporcionados por la nueva versión del
    • paquete.
  • La actualización de los
    • metadatos del sistema,
que rastrean qué versión
de un paquete dado está actualmente instalada.
