(5) Formatos de Archivo Manual (5)

NOMBRE

alpm-repo-files - Formato de archivo para listar los archivos y directorios contenidos en un alpm-package.

DESCRIPCIÓN

El formato alpm-repo-files es un formato textual que lista los directorios y archivos contenidos en un único alpm-package.

Tales archivos se nombran files y se encuentran en archivos alpm-repo-db, así como en las estructuras de bases de datos de libalpm. Son creados por el software de gestión de repositorios de paquetes (como dbscripts [1]). El software de gestión de paquetes (por ejemplo, pacman) los utiliza para listar y consultar las rutas de los directorios y archivos contenidos en un archivo de paquete.

Formato General

Un archivo alpm-repo-files es un archivo codificado en UTF-8 y delimitado por saltos de línea. Existe en dos estilos diferentes (uno para alpm-db y otro para alpm-repo-db), que varían ligeramente.

El archivo generalmente contiene una única cabecera de sección y cero o más entradas de sección. Las líneas vacías se ignoran. Los comentarios no son compatibles.

La primera línea debe ser la cadena literal %FILES%, que representa la cabecera de la sección. Tenga en cuenta que, cuando se utiliza en el contexto de una alpm-db, el archivo puede estar completamente vacío si no rastrea ninguna ruta. Este puede ser el caso, por ejemplo, al dirigirse a un alpm-meta-package.

Todas las líneas subsiguientes se interpretan como entradas de sección, una por línea, ordenadas léxicamente. Cada entrada de sección representa una ruta de archivo o directorio única. Las siguientes reglas de formato se aplican a las rutas:

  • Los directorios siempre se listan con una barra inclinada al final (/).
  • Todas las rutas son relativas a la raíz del sistema (es decir, /usr/bin/foo se representa como usr/bin/foo).

Tenga en cuenta que, cuando se utiliza en el contexto de una alpm-db, el archivo generalmente contiene una línea vacía al final si rastrea al menos una ruta.

EJEMPLOS

El siguiente es un ejemplo de un archivo alpm-repo-files para un paquete llamado foo:

%FILES%
usr/
usr/bin/
usr/bin/foo
usr/share/
usr/share/bash-completion/
usr/share/bash-completion/completions/
usr/share/bash-completion/completions/foo
usr/share/doc/
usr/share/doc/foo/
usr/share/doc/foo/README.md
usr/share/fish/
usr/share/fish/vendor_completions.d/
usr/share/fish/vendor_completions.d/foo.fish
usr/share/licenses/
usr/share/licenses/foo/
usr/share/licenses/foo/LICENSE-MIT
usr/share/zsh/
usr/share/zsh/site-functions/
usr/share/zsh/site-functions/_foo

El paquete instalado contendrá un binario (usr/bin/foo), un archivo README (usr/share/doc/foo/README.md) y un archivo de licencia (usr/share/licenses/foo/LICENSE-MIT), entre otros archivos como scripts de finalización para varios shells.
