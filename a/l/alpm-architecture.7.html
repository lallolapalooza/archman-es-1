NOMBRE

architecture - definición de arquitectura para paquetes basados en ALPM.

DESCRIPCIÓN

El formato architecture es un formato de cadena personalizado que contiene arquitecturas de conjuntos de instrucciones de CPU[1] y otros identificadores, y se utiliza para representar la arquitectura de paquetes basados en ALPM. Este formato se utiliza en scripts de compilación o en formatos de archivo para metadatos de paquetes (por ejemplo, en PKGBUILD, BUILDINFO, PKGINFO) para describir la arquitectura de un paquete o la arquitectura de los paquetes dependientes.

El formato architecture comprende valores definidos por convención. Los valores son palabras clave personalizadas, la mayoría de las cuales se derivan directamente de arquitecturas de conjuntos de instrucciones de CPU[1] o de microarquitecturas específicas.

El valor architecture debe estar cubierto por el conjunto de caracteres alfanuméricos y ‘_’.

EJEMPLOS

Los valores de architecture a continuación se relacionan con arquitecturas de conjuntos de instrucciones de CPU o microarquitecturas específicas y se pueden usar para especificar una arquitectura de paquete. Esto generalmente significa que los paquetes de una architecture específica solo se pueden usar en un contexto particular.

"any"

Un paquete puede usarse en cualquier hardware, ya que su contenido no es específico de ninguna arquitectura.

"x86_64"

Un paquete solo se puede usar en hardware compatible con la instrucción x86-64[2] versión 1 y superior (ver niveles de microarquitectura x86-64[3]).

"x86_64_v2"

Un paquete solo se puede usar en hardware compatible con la instrucción x86-64[2] versión 2 y superior (ver niveles de microarquitectura x86-64[3]).

"x86_64_v3"

Un paquete solo se puede usar en hardware compatible con la instrucción x86-64[2] versión 3 y superior (ver niveles de microarquitectura x86-64[3]).

"x86_64_v4"

Un paquete solo se puede usar en hardware compatible con la instrucción x86-64[2] versión 4 y superior (ver niveles de microarquitectura x86-64[3]).

"i686"

Un paquete solo se puede usar en hardware compatible con la instrucción IA-32[4] versión 6 (también conocida como P6[5], o ‘i686’). Esta arquitectura se considera heredada.

"i486"

Un paquete solo se puede usar en hardware compatible con la instrucción IA-32[4] versión 4 (también conocida como i486[6]). Esta arquitectura se considera heredada.

"pentium4"

Un paquete solo se puede usar en hardware compatible con la microarquitectura Pentium 4[7]. Esta arquitectura se considera heredada.

"armv7"

Un paquete solo se puede usar en hardware compatible con la familia de arquitecturas ARMv7[8]. Esta arquitectura se considera heredada.

"armv8"

Un paquete solo se puede usar en hardware compatible con la familia de arquitecturas ARMv8[9].

"aarch64"

Un paquete solo se puede usar en hardware compatible con AArch6410.

"riscv64"

Un paquete solo se puede usar en hardware compatible con la variante de 64 bits de la arquitectura del conjunto de instrucciones RISC-V[12] (ISA[13]).

"loong64"

Un paquete solo se puede usar en hardware compatible con la variante de 64 bits de la arquitectura del conjunto de instrucciones LoongArch[14] (ISA[13]).
