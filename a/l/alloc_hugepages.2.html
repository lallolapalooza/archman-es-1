alloc_hugepages(2) Manual de llamadas al sistema alloc_hugepages(2)

NOMBRE

alloc_hugepages, free_hugepages - asignar o liberar páginas grandes

SINOPSIS

void *syscall(tamaño_t tamaño;
              SYS_alloc_hugepages, int clave,
              void dirección[tamaño], tamaño_t tamaño,
              int prot, int bandera);
int syscall(SYS_free_hugepages, void *dirección);

Nota: glibc no proporciona envolturas para estas llamadas al sistema, lo que hace necesario el uso de syscall(2).

DESCRIPCIÓN

Las llamadas al sistema alloc_hugepages() y free_hugepages() se introdujeron en Linux 2.5.36 y se eliminaron de nuevo en Linux 2.5.54. Solo existieron en i386 e ia64 (cuando se compilaron con CONFIG_HUGETLB_PAGE). En Linux 2.4.20, existen los números de llamada al sistema, pero las llamadas fallan con el error ENOSYS.

En i386, el hardware de gestión de memoria conoce las páginas ordinarias (4 KiB) y las páginas grandes (2 o 4 MiB). De manera similar, ia64 conoce páginas grandes de varios tamaños. Estas llamadas al sistema sirven para mapear páginas grandes en la memoria del proceso o liberarlas. Las páginas grandes están bloqueadas en memoria y no se intercambian.

El argumento clave es un identificador. Cuando es cero, las páginas son privadas y no son heredadas por los hijos. Cuando es positivo, las páginas se comparten con otras aplicaciones que usan la misma clave y son heredadas por los procesos hijos.

El argumento dirección de free_hugepages() indica qué página se está liberando: fue el valor de retorno de una llamada a alloc_hugepages(). (La memoria se libera realmente cuando todos los usuarios la han liberado). El argumento dirección de alloc_hugepages() es una sugerencia que el kernel puede seguir o no. Las direcciones deben estar correctamente alineadas.

El argumento tamaño es el tamaño del segmento requerido. Debe ser un múltiplo del tamaño de la página grande.

El argumento prot especifica la protección de memoria del segmento. Es uno de PROT_READ, PROT_WRITE, PROT_EXEC.

El argumento bandera se ignora, a menos que clave sea positivo. En ese caso, si bandera es IPC_CREAT, se crea un nuevo segmento de página grande cuando no existe ninguno con la clave dada. Si esta bandera no está establecida, se devuelve ENOENT cuando no existe ningún segmento con la clave dada.

VALOR DE RETORNO

En caso de éxito, alloc_hugepages() devuelve la dirección virtual asignada, y free_hugepages() devuelve cero. En caso de error, se devuelve -1 y se establece errno para indicar el error.

ERRORES

ENOSYS
La llamada al sistema no es compatible con este kernel.

ARCHIVOS

/proc/sys/vm/nr_hugepages
Número de páginas hugetlb configuradas. Se puede leer y escribir.
/proc/meminfo
Proporciona información sobre el número de páginas hugetlb configuradas y su tamaño en las tres variables HugePages_Total, HugePages_Free, Hugepagesize.

ESTÁNDARES

Linux en procesadores Intel.

HISTORIA

Estas llamadas al sistema han desaparecido; solo existieron en Linux 2.5.36 hasta Linux 2.5.54.

NOTAS

Ahora se puede usar el sistema de archivos hugetlbfs en su lugar. La memoria respaldada por páginas grandes (si la CPU las soporta) se obtiene utilizando mmap(2) para mapear archivos en este sistema de archivos virtual.

El número máximo de páginas grandes se puede especificar usando el parámetro de arranque hugepages=.
