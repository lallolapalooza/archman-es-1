ALTER_COLLATION(7)

Paquete: postgresql

Licencias: PostgreSQL

ALTERCOLLATION(7) Documentación de PostgreSQL 18.1 ALTERCOLLATION(7)

NOMBRE

ALTER_COLLATION - cambia la definición de una colación

SINOPSIS

ALTER COLLATION nombre REFRESH VERSION
ALTER COLLATION nombre RENAME TO nuevo_nombre
ALTER COLLATION nombre OWNER TO { nuevo_propietario | CURRENT_ROLE | CURRENT_USER | SESSION_USER }
ALTER COLLATION nombre SET SCHEMA nuevo_esquema

DESCRIPCIÓN

ALTER COLLATION cambia la definición de una colación.

Debe ser propietario de la colación para usar ALTER COLLATION. Para cambiar el propietario, debe poder usar SET ROLE al nuevo rol propietario, y ese rol debe tener el privilegio CREATE en el esquema de la colación. (Estas restricciones garantizan que cambiar el propietario no haga nada que no pudiera hacer al eliminar y recrear la colación. Sin embargo, un superusuario puede alterar la propiedad de cualquier colación de todos modos).

PARÁMETROS

nombre

El nombre (opcionalmente calificado por esquema) de una colación existente.

nuevo_nombre

El nuevo nombre de la colación.

nuevo_propietario

El nuevo propietario de la colación.

nuevo_esquema

El nuevo esquema para la colación.

REFRESH VERSION

Actualiza la versión de la colación. Ver Notas más abajo.

NOTAS

Cuando se crea un objeto de colación, la versión específica del proveedor de la colación se registra en el catálogo del sistema. Cuando se utiliza la colación, la versión actual se compara con la versión registrada y se emite una advertencia cuando hay una discrepancia, por ejemplo:

ADVERTENCIA:  la colación "xx-x-icu" tiene una discrepancia de versión
DETALLE:  La colación en la base de datos se creó usando la versión 1.2.3.4, pero el sistema operativo proporciona la versión 2.3.4.5.
PISTA:  Reconstruya todos los objetos afectados por esta colación y ejecute ALTER COLLATION pg_catalog."xx-x-icu" REFRESH VERSION, o compile PostgreSQL con la versión correcta de la biblioteca.

Un cambio en las definiciones de colación puede provocar la corrupción de índices y otros problemas porque el sistema de base de datos se basa en que los objetos almacenados tengan un cierto orden de clasificación. Generalmente, esto debe evitarse, pero puede ocurrir en circunstancias legítimas, como al actualizar el sistema operativo a una nueva versión mayor o al usar pg_upgrade para actualizar a binarios de servidor enlazados con una versión más reciente de ICU. Cuando esto sucede, todos los objetos que dependen de la colación deben ser reconstruidos, por ejemplo, usando REINDEX. Cuando esto se haga, la versión de la colación puede ser actualizada usando el comando ALTER COLLATION ... REFRESH VERSION. Esto actualizará el catálogo del sistema para registrar la versión actual de la colación y hará que la advertencia desaparezca. Tenga en cuenta que esto no verifica si todos los objetos afectados se han reconstruido correctamente.

Al usar colaciones proporcionadas por libc, la información de versión se registra en sistemas que usan la biblioteca C de GNU (la mayoría de los sistemas Linux), FreeBSD y Windows. Al usar colaciones proporcionadas por ICU, la información de versión es proporcionada por la biblioteca ICU y está disponible en todas las plataformas.


Nota

Al usar la biblioteca C de GNU para colaciones, la versión de la biblioteca C se usa como un sustituto de la versión de la colación. Muchas distribuciones de Linux cambian las definiciones de colación solo al actualizar la biblioteca C, pero este enfoque es imperfecto, ya que los mantenedores son libres de portar definiciones de colación más nuevas a versiones anteriores de la biblioteca C.

Al usar Windows para colaciones, la información de versión solo está disponible para colaciones definidas con etiquetas de idioma BCP 47, como en-US.

Para la colación predeterminada de la base de datos, hay un comando análogo ALTER DATABASE ... REFRESH COLLATION VERSION.

La siguiente consulta se puede usar para identificar todas las colaciones en la base de datos actual que necesitan ser actualizadas y los objetos que dependen de ellas:

SELECT pg_describe_object(refclassid, refobjid, refobjsubid) AS "Colación",
       pg_describe_object(classid, objid, objsubid) AS "Objeto"
  FROM pg_depend d JOIN pg_collation c
       ON refclassid = 'pg_collation'::regclass AND refobjid = c.oid
  WHERE c.collversion <> pg_collation_actual_version(c.oid)
  ORDER BY 1, 2;

EJEMPLOS

Para renombrar la colación de_DE a german:

ALTER COLLATION "de_DE" RENAME TO german;

Para cambiar el propietario de la colación en_US a joe:

ALTER COLLATION "en_US" OWNER TO joe;

COMPATIBILIDAD

No existe una sentencia ALTER COLLATION en el estándar SQL.

VER TAMBIÉN
