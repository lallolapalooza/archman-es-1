NOMBRE

soname - representación y uso de datos soname en empaquetado basado en ALPM.

DESCRIPCIÓN

Los Sonames[1] son un mecanismo para asegurar la compatibilidad binaria entre objetos compartidos y sus consumidores (es decir, otros archivos ELF[2]). Más específicamente, los datos del soname se codifican en el campo SONAME de la sección dinámica en los archivos de objeto compartido y normalmente denotan información específica sobre la versión del archivo objeto. Los archivos ELF[2] pueden enlazar dinámicamente contra versiones específicas de objetos compartidos y declarar esta dependencia con la ayuda del campo NEEDED en su sección dinámica.

Las cadenas que representan la información de soname se pueden utilizar en las relaciones de paquetes alpm de tipo provision y dependencia en tiempo de ejecución para permitir configuraciones estrictas de dependencias de paquetes basadas en la compatibilidad ABI.

El formato alpm-soname existe en múltiples versiones. La información en este documento es para la versión 2, que es la versión actual, reemplaza a alpm-sonamev1 y se introdujo con el lanzamiento de pacman 6.1.0 el 2024-03-04.

FORMATO

La representación de la información de soname tiene lugar exclusivamente en formatos de archivo que pueden contener datos dinámicos específicos del entorno de compilación, como PKGINFO.

En estos archivos, los datos de soname se refieren utilizando el siguiente formato, que consta de datos derivados de la ubicación de un archivo de objeto compartido, así como de información codificada en él: Una cadena de prefijo, seguida directamente de un ‘:’, seguida directamente de un soname (por ejemplo, lib:libexample.so.1).

Aquí, la cadena de prefijo lib denota el nombre de uso (definido arbitrariamente a nivel de distribución y utilizado por herramientas de compilación de paquetes como makepkg) para un directorio de búsqueda (por ejemplo, /usr/lib) en el que se encuentra el archivo de objeto compartido. Consulte LIB_DIRS en makepkg.conf para ver cómo funcionan las asignaciones de prefijo en makepkg.

El soname representa datos que se encuentran en la sección dinámica de un archivo de objeto compartido (ver readelf para detalles). Dependiendo de si los datos del soname se utilizan en una relación de paquete alpm de tipo provision o de tipo dependencia en tiempo de ejecución, esto se refiere al campo SONAME o al campo NEEDED en la sección dinámica, respectivamente.

USO

Un paquete puede depender de un soname específico con la ayuda de una relación de paquete alpm de tipo dependencia en tiempo de ejecución, si otro paquete proporciona ese soname exacto en su relación de paquete alpm de tipo provision.

Más específicamente, una dependencia de soname de un paquete se basa en los datos del soname de un archivo de objeto compartido proporcionado por uno de sus paquetes dependientes.

Una herramienta de compilación de paquetes (por ejemplo, makepkg) deriva automáticamente la información del soname de los archivos ELF[2] en el entorno de compilación basándose en las siguientes reglas:

  • Si el paquete que se está compilando proporciona un objeto compartido en uno de los directorios de búsqueda configurados, se extrae el valor del campo SONAME en la sección dinámica del archivo ELF[2]. Junto con el prefijo asignado al directorio de búsqueda dado, estos datos se agregan como una provision a los datos PKGINFO para el paquete (por ejemplo, provides = lib:libexample.so.1, si el prefijo para /usr/lib es lib y el archivo de objeto compartido que codifica el soname libexample.so.1 está presente en /usr/lib).
  • Si el paquete que se está compilando produce un archivo ELF[2] que enlaza dinámicamente contra un objeto compartido disponible en el entorno de compilación, se extrae el valor del campo NEEDED en la sección dinámica del archivo ELF[2] que se enlaza. Si un paquete que contiene el archivo de objeto compartido que codifica los datos del soname está presente en el entorno de compilación y los datos PKGINFO del paquete exponen este hecho en una relación de paquete alpm de tipo provision (es decir, provides = lib:libexample.so.1), se hace uso de estos datos. Junto con el prefijo asignado al directorio de búsqueda dado del archivo de objeto compartido que proporciona el soname necesario, estos datos se agregan como una dependencia en tiempo de ejecución a los datos PKGINFO para el paquete que se está compilando (por ejemplo, depend = lib:libexample.so.1, si el prefijo para /usr/lib es lib y el archivo de objeto compartido que codifica el soname libexample.so.1 está presente en /usr/lib).

Para los implementadores, se recomienda encarecidamente hacer que este comportamiento sea configurable, ya que la detección de soname puede fallar o depender de datos de soname que pueden no ser aconsejables bajo ciertas condiciones. Consulte OPCIONES de makepkg.conf para obtener detalles sobre la función autodeps y LIB_DIRS de makepkg.conf para obtener detalles sobre las definiciones de prefijo y directorio de búsqueda para makepkg.

EJEMPLOS

Los siguientes ejemplos demuestran cómo exponer y utilizar la información de soname en el empaquetado basado en ALPM.

Los ejemplos asumen la compilación con makepkg con la función autodeps habilitada. Además, se espera que el array LIB_DIRS en makepkg.conf anteponga el directorio de búsqueda /usr/lib con lib.

Proporcionando un soname

El siguiente ejemplo de PKGBUILD para un paquete llamado example se utiliza para compilar e instalar un proyecto upstream que contiene un objeto compartido.

pkgname=example
pkgver=1.0.0
pkgrel=1
pkgdesc="Una biblioteca de ejemplo"
arch=(x86_64)
url="https://example.org/library.html"
license=(MIT)
depends=(glibc)
source=("https://example.org/$pkgname-$pkgver.tar.gz")
sha256sums=(7d865e959b2466918c9863afca942d0fb89d7c9ac0c99bafc3749504ded97730)
build() {
  make -C $pkgname-$pkgver
}
package() {
  make DESTDIR="$pkgdir" install -C $pkgname-$pkgver
}

Este ejemplo asume que el proyecto da como resultado la instalación de los siguientes archivos en el sistema de archivos:

/usr/lib/libexample.so -> libexample.so.1
/usr/lib/libexample.so.1 -> libexample.so.1.0.0
/usr/lib/libexample.so.1.0.0

Aquí, el archivo /usr/lib/libexample.so.1.0.0 codifica el soname libexample.so.1. Además, este ejemplo asume que el directorio /usr/lib se asigna al prefijo lib.

Después de compilar desde la fuente, el archivo de paquete resultante para example contiene el siguiente archivo PKGINFO:

pkgname = example
pkgver = 1.0.0-1
pkgdesc = Una biblioteca de ejemplo
url = https://example.org/library.html
builddate = 1729181726
packager = Your Name <your.name@example.org>
size = 181849963
arch = x86_64
license = MIT
provides = lib:libexample.so.1
depend = glibc

Dependiendo de un soname

El siguiente PKGBUILD para un paquete llamado application se utiliza para compilar un proyecto upstream que depende del paquete example del ejemplo anterior. Más específicamente, el paquete resultante depende del objeto compartido libexample.so que es proporcionado por el paquete example.

pkgname=application
pkgver=1.0.0
pkgrel=1
pkgdesc="Una aplicación de ejemplo"
arch=(x86_64)
url="https://example.org/application.html"
license=(MIT)
depends=(
  glibc
  example
)
source=("https://example.org/$pkgname-$pkgver.tar.gz")
sha256sums=(b5bb9d8014a0f9b1d61e21e796d78dccdf1352f23cd32812f4850b878ae4944c)
build() {
  make -C $pkgname-$pkgver
}
package() {
  make DESTDIR="$pkgdir" install -C $pkgname-$pkgver
}
