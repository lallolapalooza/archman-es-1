NOMBRE

ALTER_SUBSCRIPTION - cambia la definición de una suscripción

SINOPSIS

ALTER SUBSCRIPTION name CONNECTION 'conninfo'
ALTER SUBSCRIPTION name SET PUBLICATION publication_name [, ...] [ WITH ( publication_option [= value] [, ... ] ) ]
ALTER SUBSCRIPTION name ADD PUBLICATION publication_name [, ...] [ WITH ( publication_option [= value] [, ... ] ) ]
ALTER SUBSCRIPTION name DROP PUBLICATION publication_name [, ...] [ WITH ( publication_option [= value] [, ... ] ) ]
ALTER SUBSCRIPTION name REFRESH PUBLICATION [ WITH ( refresh_option [= value] [, ... ] ) ]
ALTER SUBSCRIPTION name ENABLE
ALTER SUBSCRIPTION name DISABLE
ALTER SUBSCRIPTION name SET ( subscription_parameter [= value] [, ... ] )
ALTER SUBSCRIPTION name SKIP ( skip_option = value )
ALTER SUBSCRIPTION name OWNER TO { new_owner | CURRENT_ROLE | CURRENT_USER | SESSION_USER }
ALTER SUBSCRIPTION name RENAME TO new_name

DESCRIPCIÓN

ALTER SUBSCRIPTION puede cambiar la mayoría de las propiedades de la suscripción que se pueden especificar en CREATE SUBSCRIPTION (CREATE_SUBSCRIPTION(7)).

Debe ser propietario de la suscripción para usar ALTER SUBSCRIPTION. Para renombrar una suscripción o cambiar el propietario, debe tener el permiso CREATE en la base de datos. Además, para cambiar el propietario, debe poder ejecutar SET ROLE al nuevo rol propietario. Si la suscripción tiene password_required=false, solo los superusuarios pueden modificarla.

Al refrescar una publicación, eliminamos las relaciones que ya no forman parte de la publicación y también eliminamos los slots de sincronización de tablas si los hay. Es necesario eliminar estos slots para que se liberen los recursos asignados para la suscripción en el host remoto. Si debido a una interrupción de la red o algún otro error, PostgreSQL no puede eliminar los slots, se reportará un error. Para proceder en esta situación, el usuario necesita reintentar la operación o desasociar el slot de la suscripción y eliminar la suscripción como se explica en DROP SUBSCRIPTION (DROP_SUBSCRIPTION(7)).

Comandos ALTER SUBSCRIPTION ... REFRESH PUBLICATION, ALTER SUBSCRIPTION ... {SET|ADD|DROP} PUBLICATION ... con la opción refresh como true, ALTER SUBSCRIPTION ... SET (failover = true|false) y ALTER SUBSCRIPTION ... SET (two_phase = false) no pueden ejecutarse dentro de un bloque de transacción.

Comandos ALTER SUBSCRIPTION ... REFRESH PUBLICATION y ALTER SUBSCRIPTION ... {SET|ADD|DROP} PUBLICATION ... con la opción refresh como true tampoco pueden ejecutarse cuando la suscripción tiene habilitado el commit en dos fases (two_phase), a menos que copy_data sea false. Consulte la columna subtwophasestate de pg_subscription para conocer el estado real de dos fases.

PARÁMETROS

name

El nombre de una suscripción cuyas propiedades se van a alterar.

CONNECTION 'conninfo'

Esta cláusula reemplaza la cadena de conexión establecida originalmente por CREATE SUBSCRIPTION (CREATE_SUBSCRIPTION(7)). Consulte allí para más información.

SET PUBLICATION publication_name
ADD PUBLICATION publication_name
DROP PUBLICATION publication_name

Estas formas cambian la lista de publicaciones suscritas. SET reemplaza la lista completa de publicaciones con una nueva lista, ADD agrega publicaciones adicionales a la lista de publicaciones y DROP elimina las publicaciones de la lista de publicaciones. Permitimos especificar publicaciones inexistentes en las variantes ADD y SET para que los usuarios puedan agregarlas más adelante. Consulte CREATE SUBSCRIPTION (CREATE_SUBSCRIPTION(7)) para más información. Por defecto, este comando también actuará como REFRESH PUBLICATION.

publication_option especifica opciones adicionales para esta operación. Las opciones soportadas son:

refresh (booleano)

Cuando es false, el comando no intentará refrescar la información de las tablas. REFRESH PUBLICATION debe ejecutarse por separado. El valor por defecto es true.

Además, se pueden especificar las opciones descritas bajo REFRESH PUBLICATION para controlar la operación de refresco implícita.

REFRESH PUBLICATION

Obtiene la información de tablas faltante del publicador. Esto iniciará la replicación de tablas que se agregaron a las publicaciones suscritas desde CREATE SUBSCRIPTION o la última invocación de REFRESH PUBLICATION.

refresh_option especifica opciones adicionales para la operación de refresco. Las opciones soportadas son:

copy_data (booleano)

Especifica si copiar los datos preexistentes en las publicaciones a las que se está suscribiendo cuando comienza la replicación. El valor por defecto es true.

Las tablas suscritas previamente no se copian, incluso si la cláusula WHERE del filtro de filas de una tabla ha sido modificada desde entonces.

Consulte Notas para detalles de cómo copy_data = true puede interactuar con el parámetro origin.

Consulte el parámetro binary de CREATE SUBSCRIPTION para detalles sobre la copia de datos preexistentes en formato binario.

ENABLE

Habilita una suscripción previamente deshabilitada, iniciando el trabajador de replicación lógica al final de la transacción.

DISABLE

Deshabilita una suscripción en ejecución, deteniendo el trabajador de replicación lógica al final de la transacción.

SET ( subscription_parameter [= value] [, ... ] )

Esta cláusula altera parámetros establecidos originalmente por CREATE SUBSCRIPTION (CREATE_SUBSCRIPTION(7)). Consulte allí para más información. Los parámetros que se pueden alterar son slot_name, synchronous_commit, binary, streaming, disable_on_error, password_required, run_as_owner, origin, failover y two_phase. Solo un superusuario puede establecer password_required = false.

Al alterar el slot_name, los valores de las propiedades failover y two_phase del slot nombrado pueden diferir de los parámetros counterpart failover y two_phase especificados en la suscripción. Al crear el slot, asegúrese de que las propiedades del slot failover y two_phase coincidan con sus parámetros counterpart de la suscripción. De lo contrario, el slot en el publicador puede comportarse de manera diferente a lo que dicen estas opciones de suscripción: por ejemplo, el slot en el publicador podría ser sincronizado con los standbys incluso cuando la opción failover de la suscripción está deshabilitada, o podría estar deshabilitado para la sincronización incluso cuando la opción failover de la suscripción está habilitada.

Los parámetros failover y two_phase solo se pueden alterar cuando la suscripción está deshabilitada.

Al alterar two_phase de true a false, el proceso backend reporta un error si se encuentran transacciones preparadas realizadas por el trabajador de replicación lógica (desde que el parámetro two_phase era true). Puede resolver las transacciones preparadas en el nodo publicador, o revertirlas manualmente en el suscriptor, y luego intentarlo de nuevo. Las transacciones preparadas por el trabajador de replicación lógica correspondientes a una suscripción particular tienen el siguiente patrón: “pg_gid_%u_%u” (parámetros: suscripción oid, id de transacción remota xid). Para resolver tales transacciones manualmente, necesita revertir todas las transacciones preparadas con los IDs de suscripción correspondientes en sus nombres. Las aplicaciones pueden verificar pg_prepared_xacts para encontrar las transacciones preparadas requeridas. Después de que la opción two_phase se cambie de true a false, el publicador replicará las transacciones de nuevo cuando se confirmen.

SKIP ( skip_option = value )

Omite la aplicación de todos los cambios de la transacción remota. Si los datos entrantes violan alguna restricción, la replicación lógica se detendrá hasta que se resuelva. Usando el comando ALTER SUBSCRIPTION ... SKIP , el trabajador de replicación lógica omite todos los cambios de modificación de datos dentro de la transacción. Esta opción no tiene efecto sobre las transacciones que ya están preparadas al habilitar two_phase en el suscriptor. Después de que el trabajador de replicación lógica omite exitosamente la transacción o termina una transacción, el LSN (almacenado en pg_subscription.subskiplsn) se limpia. Consulte la Sección 29.7 para los detalles de los conflictos de replicación lógica.

skip_option especifica opciones para esta operación. La opción soportada es:

lsn (pg_lsn)

Especifica el LSN de finalización de la transacción remota cuyos cambios deben ser omitidos por el trabajador de replicación lógica. El LSN de finalización es el LSN en la que la transacción se confirma o se prepara. No se admite omitir subtransacciones individuales. Establecer NONE restablece el LSN.

new_owner

El nombre de usuario del nuevo propietario de la suscripción.

new_name

El nuevo nombre para la suscripción.

Al especificar un parámetro de tipo booleano, se puede omitir la parte valor , lo que equivale a especificar TRUE.

EJEMPLOS

Cambiar la publicación suscrita por una suscripción a insert_only:

ALTER SUBSCRIPTION mysub SET PUBLICATION insert_only;

Deshabilitar (detener) la suscripción:

ALTER SUBSCRIPTION mysub DISABLE;

COMPATIBILIDAD

ALTER SUBSCRIPTION es una extensión de PostgreSQL.
