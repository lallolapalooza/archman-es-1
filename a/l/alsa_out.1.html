NOMBRE

alsa_in, alsa_out - Clientes Jack que realizan E/S con una interfaz de audio alternativa

SINOPSIS

alsa_in [opciones]
alsa_out [opciones]

DESCRIPCIÓN

Un cliente JACK que abre una interfaz de audio especificada (diferente a la utilizada por el servidor JACK, si la hay) y mueve datos de audio entre sus puertos JACK y la interfaz. alsa_in proporcionará datos desde la interfaz (potencialmente para captura); alsa_out le entregará datos (para reproducción).

La interfaz de audio utilizada por alsa_in/alsa_out no necesita estar sincronizada con el backend de JACK (o el hardware que pueda estar utilizando). alsa_in/alsa_out intenta remuestrear el flujo de salida en un intento de compensar la deriva entre los dos relojes.

A partir de jack-0.116.3, esto funciona casi perfectamente. Se tarda un poco en alcanzar la estabilidad absoluta de la frecuencia de remuestreo. Así que dale unos minutos (de todos modos, está pensado para ejecutarse permanentemente).

OPCIONES

-j nombre_cliente_jack

Establece el nombre del cliente.
-d dispositivo_alsa

Usa esta tarjeta de sonido.
-v

Verboso, imprime el coeficiente de remuestreo y otros parámetros útiles para la depuración, cada 500 ms. También informa de xruns suaves.
-i

Instrumentación. Esto registra los 4 parámetros importantes del algoritmo de control de frecuencia de muestreo cada 1 ms. Puedes redirigir esto a un archivo y graficarlo. Solo debería ser necesario si no funciona como se espera y necesitamos ajustar algunos de los parámetros oscuros para que funcione. Búscame en irc.freenode.org #jack para configurarlo correctamente.
-c canales

Establece el número de canales.
-r frecuencia_muestreo

Establece la frecuencia de muestreo. El programa remuestrea según sea necesario. Así que puedes conectar un jackd de 44100 a una tarjeta de sonido que solo soporte 48000. (por defecto es la frecuencia de muestreo de Jack)
-p tamaño_periodo

Establece el tamaño del período. No está relacionado con el tamaño del período de jackd. A veces afecta la calidad de las mediciones de retardo. Establecer esto por debajo del tamaño del período de jackd solo funcionará si usa un número mayor de períodos.
-n num_periodos

Establece el número de períodos. Ver nota para tamaño_periodo.
-q calidad

Establece la calidad del remuestreador de 0 a 4. Puede reducir significativamente el uso de CPU.
-m max_diff

El valor cuando ocurre un xrun suave. Básicamente, la ventana en la que el puntero DMA puede fluctuar. No creo que sea necesario jugar con esto más.
-t retraso_objetivo

El retraso que alsa_io debería intentar alcanzar. Igual que para max_diff. Se configurará en función de -p y -n, lo que generalmente es suficiente.
-s tamaño_array_suavizado

Este parámetro controla el tamaño del array utilizado para suavizar la medición del retardo. Su valor predeterminado es 256. Si utilizas un tamaño de período bastante bajo, puedes reducir un poco el uso de la CPU disminuyendo este parámetro. Sin embargo, la mayor parte del tiempo de CPU se dedica al remuestreo, por lo que esto no será mucho.
-C Límite de control P

Si tienes una tarjeta PCI, el valor predeterminado (15) de este parámetro es demasiado alto para -p64 -n2... Establecerlo en 5 debería solucionar eso. Ten en cuenta que establecer este parámetro demasiado bajo permite que el ruido de alta frecuencia en la medición del retardo se transmita a la frecuencia de remuestreo, por lo que esto podría degradar la calidad de la salida. (pero es un valor umbral, y ha sido elegido para enmascarar el ruido de una tarjeta USB, que tiene una amplitud 50 veces mayor que la de una tarjeta PCI, por lo que 5 no te supondrá ninguna pérdida de calidad en una tarjeta PCI)
-S nombre_servidor

Servidor al que conectarse. Esta opción permite adjuntarse a un servidor jack2 con nombre.
