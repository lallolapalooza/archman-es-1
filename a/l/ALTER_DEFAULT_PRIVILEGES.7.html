NAME

ALTER_DEFAULT_PRIVILEGES - definir privilegios de acceso por defecto

SYNOPSIS

ALTER DEFAULT PRIVILEGES
    [ FOR { ROLE | USER } target_role [, ...] ]
    [ IN SCHEMA schema_name [, ...] ]
    abbreviated_grant_or_revoke
donde abbreviated_grant_or_revoke es uno de:
GRANT { { SELECT | INSERT | UPDATE | DELETE | TRUNCATE | REFERENCES | TRIGGER | MAINTAIN }
    [, ...] | ALL [ PRIVILEGES ] }
    ON TABLES
    TO { [ GROUP ] role_name | PUBLIC } [, ...] [ WITH GRANT OPTION ]
GRANT { { USAGE | SELECT | UPDATE }
    [, ...] | ALL [ PRIVILEGES ] }
    ON SEQUENCES
    TO { [ GROUP ] role_name | PUBLIC } [, ...] [ WITH GRANT OPTION ]
GRANT { EXECUTE | ALL [ PRIVILEGES ] }
    ON { FUNCTIONS | ROUTINES }
    TO { [ GROUP ] role_name | PUBLIC } [, ...] [ WITH GRANT OPTION ]
GRANT { USAGE | ALL [ PRIVILEGES ] }
    ON TYPES
    TO { [ GROUP ] role_name | PUBLIC } [, ...] [ WITH GRANT OPTION ]
GRANT { { USAGE | CREATE }
    [, ...] | ALL [ PRIVILEGES ] }
    ON SCHEMAS
    TO { [ GROUP ] role_name | PUBLIC } [, ...] [ WITH GRANT OPTION ]
GRANT { { SELECT | UPDATE }
    [, ...] | ALL [ PRIVILEGES ] }
    ON LARGE OBJECTS
    TO { [ GROUP ] role_name | PUBLIC } [, ...] [ WITH GRANT OPTION ]
REVOKE [ GRANT OPTION FOR ]
    { { SELECT | INSERT | UPDATE | DELETE | TRUNCATE | REFERENCES | TRIGGER | MAINTAIN }
    [, ...] | ALL [ PRIVILEGES ] }
    ON TABLES
    FROM { [ GROUP ] role_name | PUBLIC } [, ...]
    [ CASCADE | RESTRICT ]
REVOKE [ GRANT OPTION FOR ]
    { { USAGE | SELECT | UPDATE }
    [, ...] | ALL [ PRIVILEGES ] }
    ON SEQUENCES
    FROM { [ GROUP ] role_name | PUBLIC } [, ...]
    [ CASCADE | RESTRICT ]
REVOKE [ GRANT OPTION FOR ]
    { EXECUTE | ALL [ PRIVILEGES ] }
    ON { FUNCTIONS | ROUTINES }
    FROM { [ GROUP ] role_name | PUBLIC } [, ...]
    [ CASCADE | RESTRICT ]
REVOKE [ GRANT OPTION FOR ]
    { USAGE | ALL [ PRIVILEGES ] }
    ON TYPES
    FROM { [ GROUP ] role_name | PUBLIC } [, ...]
    [ CASCADE | RESTRICT ]
REVOKE [ GRANT OPTION FOR ]
    { { USAGE | CREATE }
    [, ...] | ALL [ PRIVILEGES ] }
    ON SCHEMAS
    FROM { [ GROUP ] role_name | PUBLIC } [, ...]
    [ CASCADE | RESTRICT ]
REVOKE [ GRANT OPTION FOR ]
    { { SELECT | UPDATE }
    [, ...] | ALL [ PRIVILEGES ] }
    ON LARGE OBJECTS
    FROM { [ GROUP ] role_name | PUBLIC } [, ...]
    [ CASCADE | RESTRICT ]

DESCRIPTION

ALTER DEFAULT PRIVILEGES le permite establecer los privilegios que se aplicarán a los objetos creados en el futuro. (No afecta a los privilegios asignados a objetos que ya existen.) Los privilegios pueden establecerse globalmente (es decir, para todos los objetos creados en la base de datos actual) o solo para los objetos creados en esquemas especificados.

Aunque puedes cambiar tus propios privilegios por defecto y los de los roles de los que eres miembro, en el momento de la creación de objetos, las nuevas permisos de objeto solo están afectados por los privilegios por defecto del rol actual, y no se heredan de ningún rol al que pertenece el rol actual.

Como se explica en la Sección 5.8, los privilegios por defecto para cualquier tipo de objeto normalmente conceden todos los privilegios concedibles al propietario del objeto y pueden conceder algunos privilegios a PUBLIC también. Sin embargo, este comportamiento puede cambiarse alterando los privilegios por defecto globales con ALTER DEFAULT PRIVILEGES.

Actualmente, solo se pueden alterar los privilegios para esquemas, tablas (incluyendo vistas y tablas externas), secuencias, funciones, tipos (incluyendo dominios) y objetos grandes. Para este comando, las funciones incluyen agregados y procedimientos. Las palabras FUNCIONES y ROUTINES son equivalentes en este comando. (ROUTINES es preferido en el futuro como el término estándar para funciones y procedimientos juntos. En las versiones anteriores de PostgreSQL, solo se permitía la palabra FUNCIONES. No es posible establecer privilegios por defecto para funciones y procedimientos por separado).

Los privilegios por defecto que se especifican por esquema se añaden a lo que sean los privilegios por defecto globales para el tipo de objeto particular. Esto significa que no puedes revocar privilegios por esquema si se conceden globalmente (ya sea por defecto o según un comando anterior ALTER DEFAULT PRIVILEGES que no especificara un esquema). La revocación por esquema solo es útil para revertir los efectos de una concesión anterior por esquema.

Parameters

target_role

Cambiar los privilegios por defecto para los objetos creados por el target_role, o el rol actual si no se especifica.

schema_name

El nombre de un esquema existente. Si se especifica, los privilegios por defecto se alteran para los objetos creados posteriormente en ese esquema. Si se omite IN SCHEMA, se alteran los privilegios por defecto globales. IN SCHEMA no se permite al establecer privilegios para esquemas y objetos grandes, ya que los esquemas no pueden anidarse y los objetos grandes no pertenecen a un esquema.

role_name

El nombre de un rol existente para el que conceder o revocar privilegios. Este parámetro y todos los demás parámetros en abbreviated_grant_or_revoke actúan como se describe en GRANT(7) o REVOKE(7), excepto que se están estableciendo permisos para una clase completa de objetos en lugar de objetos específicos con nombres.

NOTES

Utiliza el comando \ddp de psql(1) para obtener información sobre las asignaciones existentes de privilegios por defecto. El significado de la visualización del privilegio es el mismo que se explica para \dp en la Sección 5.8.

Si deseas eliminar un rol para el cual se han alterado los privilegios por defecto, es necesario revertir los cambios en sus privilegios por defecto o utilizar DROP OWNED BY para eliminar la entrada de privilegios por defecto para el rol.

EXAMPLES

Conceder el privilegio SELECT a todos para todas las tablas (y vistas) que crees posteriormente en el esquema myschema, y permitir al rol webuser INSERT en ellas:

ALTER DEFAULT PRIVILEGES IN SCHEMA myschema GRANT SELECT ON TABLES TO PUBLIC;
ALTER DEFAULT PRIVILEGES IN SCHEMA myschema GRANT INSERT ON TABLES TO webuser;

Deshacer lo anterior, de modo que las tablas creadas posteriormente no tengan más permisos que los normales:

ALTER DEFAULT PRIVILEGES IN SCHEMA myschema REVOKE SELECT ON TABLES FROM PUBLIC;
ALTER DEFAULT PRIVILEGES IN SCHEMA myschema REVOKE INSERT ON TABLES FROM webuser;

Eliminar el permiso de ejecución PÚBLICO que normalmente se concede en funciones, para todas las funciones creadas posteriormente por el rol admin:

ALTER DEFAULT PRIVILEGES FOR ROLE admin REVOKE EXECUTE ON FUNCTIONS FROM PUBLIC;

Sin embargo, ten en cuenta que no puedes lograr ese efecto con un comando limitado a un solo esquema. Este comando no tiene efecto, a menos que esté deshaciendo una concesión coincidente:

ALTER DEFAULT PRIVILEGES IN SCHEMA public REVOKE EXECUTE ON FUNCTIONS FROM PUBLIC;

Esto es porque los privilegios por defecto por esquema solo pueden añadir privilegios a la configuración global, no eliminar privilegios concedidos por ella.

COMPATIBILITY

No existe una sentencia ALTER DEFAULT PRIVILEGES en el estándar SQL.
