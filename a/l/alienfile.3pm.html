SINOPSI

S

Enfoque "hazlo tú

mismo": 
use alienfile;

probe [ 'pkg-config --exists libarchive' ];

share {

  start_url 'http://libarchive.org/downloads/libarchive-3.2.2.tar.gz';

  # se usará el primero que tenga éxito
  download [ 'wget %{.meta.start_url}' ];
  download [ 'curl -o %{.meta.start_url}' ];

  extract [ 'tar xf %{.install.download}' ];

  build [
    # Nota: no funcionará en Windows, es mejor usar el plugin Build::Autoconf
    # si necesitas soporte para Windows
    './configure --prefix=%{.install.prefix} --disable-shared',
    '%{make}',
    '%{make} install',
  ];
}

gather [
  [ 'pkg-config', '--modversion', 'libarchive', \'%{.runtime.version}' ],
  [ 'pkg-config', '--cflags',     'libarchive', \'%{.runtime.cflags}'  ],
  [ 'pkg-config', '--libs',       'libarchive', \'%{.runtime.libs}'    ],
]
;

Con plugins (mejor)

: 
use alienfile;

plugin 'PkgConfig' => 'libarchive';

share {
  start_url 'http://libarchive.org/downloads/';
  plugin Download => (
    filter => qr/^libarchive-.*\.tar\.gz$/,
    version => qr/([0-9\.]+)/,
  );
  plugin Extract => 'tar.gz';
  plugin 'Build::Autoconf';
  plugin 'Gather::IsolateDynamic';
  build [
    '%{configure}',
    '%{make}',
    '%{make} install',
  ];
}
;

DESCRIPCIÓ

N

Un alienfile es una receta usada por Alien::Build para buscar bibliotecas del sistema o descargar desde Internet, y compilar el código fuente de esas bibliotecas. Este documento ac

túa como referencia para el sistema alienfile, pero si estás empezando a escribir tu propio Alien deberías leer Alien::Build::Manual::AlienAuthor, que te enseñará cómo escribir tu
propio Alien completo usando alienfile + Alien::Build + ExtUtils::MakeMaker. Debe prestarse especial atención a la sección "una nota sobre bibliotecas dinámicas vs. estáticas".

NAME

alienfile - DSL for declaring alien libraries

VERSION

2.84

SYNOPSIS

 use alienfile;

 package Alien::MyLibrary;

 share {
  source {
   url "http://example.com/mylibrary-1.0.tar.gz";
   sha256 "addb...addb";
  };
  ...
 };

 sys {
  build { ... };
 };

 # Prefer local build over download
 prefer {
  build { ... };
 };

 # Add build steps for FFI
 share {
  ffi {
   build { ... };
  };
 };

DESCRIPTION

The alienfile is a Domain Specific Language (DSL) for Alien::Build that makes it easy to declare how to build and install alien libraries.

The alienfile is processed by Alien::Build::Manual::alienfile.

The alienfile supports a share and a sys block. The share block is for instructions that apply to both shared and static builds. The sys block is for instructions that only apply to system libraries.

In addition to the blocks there are also directives that can be used to modify the behaviour of the build process, and to declare build steps.

See Alien::Build::Manual::Sections for a list of all the sections that can be defined in an alienfile.

DIRECTIVES

source

share {
  source {
   url "http://example.com/mylibrary-1.0.tar.gz";
   sha256 "addb...addb";
   alias "mylibrary";
   dest "lib/mylibrary";
   verbose 1;
   archive "mylibrary.tar.gz";
   autoreconf 1;
   configure_args "-no-cygwin", "--disable-shared";
   # or
   configure &code;
   # or
   configure \@commandlist;
   # or
   configure {
    my $c = shift;
    $c->program("autoreconf");
    $c->program("configure", "--disable-shared");
   };
  };
 };

Specifies where to get the alien library from. This can be a URL, a local file path, or a directory. The contents of the source block are passed to Alien::Build::Source.

Currently supported directives are:

url
The URL of the source code archive.
alias
An alias for the source archive. This is used to name the archive file.
sha256
The SHA256 checksum of the source code archive.
dest
The destination directory for the extracted source code.
verbose
Enable verbose output from the build process.
archive
The name of the archive file.
autoreconf
Run autoreconf before configure. Defaults to 0.
configure
Specify the configure arguments. Can be a code reference or a command list. The code reference will be called with a Configure object.

patch

share {
  patch \&code;
  patch \@commandlist;
};

sys {
  patch \&code;
  patch \@commandlist;
};

Instructions for the patch stage. May be either a code reference, or a command list. In the root block of the alienfile it will trigger in both share and system build. In the share or sys block it will only trigger in the corresponding build.

build

share {
  build \&code;
  build \@commandlist;
};

sys {
  build \&code;
  build \@commandlist;
};

Instructions for the build stage. May be either a code reference, or a command list. In the root block of the alienfile it will trigger in both share and system build. In the share or sys block it will only trigger in the corresponding build.

build_ffi_package

share {
  build_ffi_package {
    package "MyLibrary::FFI";
    source { ... };
    build { ... };
  };
};

Build an FFI package. This is similar to a normal build block, but it also takes a package argument, which specifies the name of the FFI package to be built.

A separate build needs to be done for FFI.

gather

gather \&code;
gather \@commandlist;

share {
  gather \&code;
  gather \@commandlist;
};

sys {
  gather \&code;
  gather \@commandlist;
};

Instructions for the gather stage. May be either a code reference, or a command list. In the root block of the alienfile it will trigger in both share and system build. In the share or sys block it will only trigger in the corresponding build.

gather_ffi

share {
  gather_ffi \&code;
  gather_ffi \@commandlist;
}

[DEPRECATED]

Gather specific to "build_ffi". Not usually necessary.

ffi

share {
  ffi {
    patch \&code;
    patch \@commandlist;
    build \&code;
    build \@commandlist;
    gather \&code;
    gather \@commandlist;
  }
}

Specify patch, build or gather stages related to FFI.

meta_prop

my $hash = meta_prop;

Get the meta_prop hash reference.

meta

my $meta = meta;

Returns the meta object for your alienfile. For methods that can be used on the meta object, see "META METHODS" in Alien::Build.

log

log($message);

Prints the given log to stdout.

test

share {
  test \&code;
  test \@commandlist;
};
sys {
  test \&code;
  test \@commandlist;
};

Run the tests

before

before $stage => \&code;

Execute the given code before the given stage. Stage should be one of "probe", "download", "fetch", "decode", "prefer", "extract", "patch", "build", "test", and "gather".

The before directive is only legal in the same blocks as the stage would normally be legal in. For example, you can't do this:

use alienfile;

sys {
  before 'build' => sub {
    ...
  };
};

Because a "build" wouldn't be legal inside a "sys" block.

after

after $stage => \&code;

Execute the given code after the given stage. Stage should be one of "probe", "download", "fetch", "decode", "prefer", "extract", "patch", "build", "test", and "gather".

The after directive is only legal in the same blocks as the stage would normally be legal in. For example, you can't do this:

use alienfile;

sys {
  after 'build' => sub {
    ...
  };
};

Because a "build" wouldn't be legal inside a "sys" block.
