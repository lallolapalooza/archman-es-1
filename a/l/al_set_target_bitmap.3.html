al_set_target_bitmap(3) Manual de funciones de la biblioteca al_set_target_bitmap(3)

NOMBRE

al_set_target_bitmap - API de Allegro 5

SINOPSIS

#include <allegro5/allegro.h>
void al_set_target_bitmap(ALLEGRO_BITMAP *bitmap)

DESCRIPCIÓN

Esta función selecciona el mapa de bits al que se dibujarán todas las operaciones de dibujo subsiguientes en el hilo que la llama. Para volver a dibujar en una pantalla, establezca el búfer de reserva de la pantalla como el mapa de bits de destino, utilizando al_get_backbuffer(3). Como conveniencia, también puede usar al_set_target_backbuffer(3).

Cada mapa de bits de allegro mantiene dos matrices de transformación asociadas con él para dibujar en el mapa de bits. Hay una matriz de vista y una matriz de proyección. Cuando llama a al_set_target_bitmap, estas se harán actuales para el mapa de bits, afectando los estados globales de OpenGL y DirectX según el controlador en uso.

Cada mapa de bits de video está vinculado a una pantalla. Cuando se establece un mapa de bits de video como mapa de bits de destino, la pantalla a la que pertenece el mapa de bits se hace automáticamente "actual" para el hilo que llama (si no es actual ya). Entonces, dibujar otros mapas de bits que están vinculados a la misma pantalla puede acelerarse por hardware.

Una única pantalla no puede ser actual para varios hilos simultáneamente. Si necesita liberar una pantalla, para que no sea actual para el hilo que llama, llame a al_set_target_bitmap(NULL);

Establecer un mapa de bits de memoria como mapa de bits de destino no cambiará qué pantalla es actual para el hilo que llama.

En algunas plataformas, Allegro hace copias de seguridad de forma automática del contenido de los mapas de bits de video porque pueden perderse ocasionalmente (consulte la discusión en la documentación de al_create_bitmap(3)). Si está recreando completamente el contenido del mapa de bits con frecuencia (por ejemplo, cada fotograma), obtendrá un rendimiento mucho mejor creando el mapa de bits de destino con la bandera ALLEGRO_NO_PRESERVE_TEXTURE.

Nota de OpenGL:

Los objetos de búfer de fotogramas (FBO) permiten a OpenGL dibujar directamente en un mapa de bits, lo cual es muy rápido. Cuando se utiliza una pantalla OpenGL, si se cumplen todas las siguientes condiciones, se creará un FBO para usarlo con el mapa de bits:

•
La extensión de OpenGL GL_EXT_framebuffer_object está disponible.
•
El mapa de bits no es un mapa de bits de memoria.
•
El mapa de bits no está bloqueado actualmente.

En Allegro 5.0.0, tenía que tener cuidado, ya que un FBO se mantenía hasta que se destruía el mapa de bits o llamaba explícitamente a al_remove_opengl_fbo(3) en el mapa de bits, desperdiciando recursos. En versiones más recientes, los FBO se liberarán automáticamente cuando el mapa de bits ya no sea el mapa de bits de destino, *a menos que* haya llamado a al_get_opengl_fbo(3) para obtener el ID del FBO.

En el siguiente ejemplo, no se creará ningún FBO:

lock = al_lock_bitmap(bitmap);
al_set_target_bitmap(bitmap);
al_put_pixel(x, y, color);
al_unlock_bitmap(bitmap);

Lo anterior permite usar al_put_pixel(3) en un mapa de bits bloqueado sin crear un FBO.

Sin embargo, en este ejemplo se crea un FBO:

al_set_target_bitmap(bitmap);
al_draw_line(x1, y1, x2, y2, color, 0);

Se utilizará un comando de OpenGL para dibujar directamente la línea en la textura asociada del mapa de bits.
