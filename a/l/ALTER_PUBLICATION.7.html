ALTER_PUBLICATION(7)

Paquete: postgresql

Licencias: PostgreSQL

ALTER PUBLICATION(7) Documentación de PostgreSQL 18.1 ALTER PUBLICATION(7)

NOMBRE

ALTER_PUBLICATION - cambia la definición de una publicación

SINOPSIS

ALTER PUBLICATION name ADD publication_object [, ...]
ALTER PUBLICATION name SET publication_object [, ...]
ALTER PUBLICATION name DROP publication_object [, ...]
ALTER PUBLICATION name SET ( publication_parameter [= value] [, ... ] )
ALTER PUBLICATION name OWNER TO { new_owner | CURRENT_ROLE | CURRENT_USER | SESSION_USER }
ALTER PUBLICATION name RENAME TO new_name
donde publication_object es uno de:
    TABLE [ ONLY ] table_name [ * ] [ ( column_name [, ... ] ) ] [ WHERE ( expression ) ] [, ... ]
    TABLES IN SCHEMA { schema_name | CURRENT_SCHEMA } [, ... ]

DESCRIPCIÓN

El comando ALTER PUBLICATION puede cambiar los atributos de una publicación.

Las tres primeras variantes cambian qué tablas/esquemas forman parte de la publicación. La cláusula SET reemplazará la lista de tablas/esquemas en la publicación con la lista especificada; las tablas/esquemas existentes que estaban presentes en la publicación serán eliminadas. Las cláusulas ADD y DROP añadirán y eliminarán una o más tablas/esquemas de la publicación. Nótese que añadir tablas/esquemas a una publicación a la que ya se está suscrito requerirá una acción ALTER SUBSCRIPTION ... REFRESH PUBLICATION en el lado suscriptor para que surta efecto. Nótese también que DROP TABLES IN SCHEMA no eliminará ninguna tabla de esquema que haya sido especificada usando FOR TABLE/ ADD TABLE, y la combinación de DROP con una cláusula WHERE no está permitida.

La cuarta variante de este comando listada en la sinopsis puede cambiar todas las propiedades de la publicación especificadas en CREATE PUBLICATION (CREATE_PUBLICATION(7)). Las propiedades no mencionadas en el comando conservan sus ajustes anteriores.

Las variantes restantes cambian el propietario y el nombre de la publicación.

Debes ser el propietario de la publicación para usar ALTER PUBLICATION. Añadir una tabla a una publicación requiere además ser propietario de esa tabla. El ADD TABLES IN SCHEMA y SET TABLES IN SCHEMA a una publicación requiere que el usuario que invoca sea un superusuario. Para cambiar el propietario, debes poder hacer SET ROLE al nuevo rol propietario, y ese rol debe tener el privilegio CREATE en la base de datos. Además, el nuevo propietario de una publicación FOR ALL TABLES o FOR TABLES IN SCHEMA debe ser un superusuario. Sin embargo, un superusuario puede cambiar la propiedad de una publicación independientemente de estas restricciones.

No se admite añadir/establecer cualquier esquema cuando la publicación también publica una tabla con una lista de columnas, y viceversa.

PARÁMETROS

name

El nombre de una publicación existente cuya definición se va a alterar.

table_name

Nombre de una tabla existente. Si se especifica ONLY antes del nombre de la tabla, solo se ve afectada esa tabla. Si no se especifica ONLY, se ven afectadas la tabla y todas sus tablas descendientes (si las hay). Opcionalmente, se puede especificar * después del nombre de la tabla para indicar explícitamente que se incluyen las tablas descendientes.

Opcionalmente, se puede especificar una lista de columnas. Consulta CREATE PUBLICATION (CREATE_PUBLICATION(7)) para más detalles. Nótese que no se admite una suscripción que tenga varias publicaciones en las que la misma tabla se haya publicado con diferentes listas de columnas. Consulta Advertencia: Combinación de listas de columnas de múltiples publicaciones para más detalles sobre los problemas potenciales al alterar las listas de columnas.

Si se especifica la cláusula WHERE opcional, las filas para las cuales la expression se evalúe como falsa o nula no serán publicadas. Nótese que se requieren paréntesis alrededor de la expresión. La expression se evalúa con el rol utilizado para la conexión de replicación.

schema_name

Nombre de un esquema existente.

SET ( publication_parameter [= value] [, ... ] )

Esta cláusula altera los parámetros de la publicación establecidos originalmente por CREATE PUBLICATION (CREATE_PUBLICATION(7)). Consulta ahí para más información.

Precaución
Alterar el parámetro publish_via_partition_root puede llevar a pérdida o duplicación de datos en el suscriptor porque cambia la identidad y el esquema de las tablas publicadas. Nótese que esto solo ocurre cuando se especifica una tabla raíz de partición como destino de replicación.

Este problema se puede evitar absteniéndose de modificar las tablas hoja de partición después del ALTER PUBLICATION ... SET hasta que se ALTER SUBSCRIPTION ... REFRESH PUBLICATION se haya ejecutado y refrescando solo usando la opción copy_data = off.

new_owner

El nombre de usuario del nuevo propietario de la publicación.

new_name

El nuevo nombre para la publicación.

EJEMPLOS

Cambiar la publicación para que solo publique borrados y actualizaciones:

ALTER PUBLICATION noinsert SET (publish = 'update, delete');

Añadir algunas tablas a la publicación:

ALTER PUBLICATION mypublication ADD TABLE users (user_id, firstname), departments;

Cambiar el conjunto de columnas publicadas para una tabla:

ALTER PUBLICATION mypublication SET TABLE users (user_id, firstname, lastname), TABLE departments;

Añadir los esquemas marketing y sales a la publicación sales_publication:

ALTER PUBLICATION sales_publication ADD TABLES IN SCHEMA marketing, sales;

Añadir las tablas users, departments y el esquema production a la publicación production_publication:

ALTER PUBLICATION production_publication ADD TABLE users, departments, TABLES IN SCHEMA production;

COMPATIBILIDAD

ALTER PUBLICATION es una extensión de PostgreSQL.
