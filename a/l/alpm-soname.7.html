Las cadenas que representan información soname pueden usarse en relaciones de paquetes alpm de tipo provisión y dependencia de tiempo de ejecución para permitir configuraciones estrictas de dependencias de paquetes basadas en compatibilidad ABI. El formato alpm-soname existe en múltiples versiones. La información en este documento es para la versión 2, que es la versión actual, reemplaza alpm-sonamev1 y fue introducida con el lanzamiento de pacman 6.1.0 el 20

24-03-04.

FORMATO La representación de la información soname tiene lugar exclusivamente en formatos de archivo que pueden contener datos dinámicos específicos del entorno de compilación, como PKGINFO [[62]]. En estos archivos, los datos soname se refieren utilizando el siguiente formato, que consiste en datos derivados de la ubicación de un archivo de objeto compartido [[67]], así como información codificada en él: una

cadena

prefijo [[69]], seguida directamente por un ‘:’, seguido directamente por un soname (por ejemplo, lib:libexample.so.1 [[73]]

). Aquí, la c

li

b

ejemplo,

/usr/lib [[82]]) en el que se encuentra el archivo de objeto compartido [[84]]. Consulte LIB_DIRS en makepkg.conf para saber cómo funcionan las asignaciones de prefijo en makepkg [[92]]. El soname representa datos encontrados en la sección dinámica de un archivo de objeto compa

rtido (consulte

readelf para más detalles). Dependiendo de si los datos soname se usan en una relación de paquete alpm de tipo provisión o de tipo dependencia de tiempo de ejecución [[109]], esto se refiere al campo SONAME o al campo NEEDED en la sección dinámica [[115]], respectivamente. USO Un paquete puede depender de un soname específico con la ayuda de

Más específicamente, una dependencia soname de un paquete se basa en los datos soname de un archivo de objeto compartido proporcionado por uno de sus paquetes dependientes. Si un paquete que contiene el archivo de objeto compartido que codifica los datos soname está presente en el entorno de compilación y los datos PKGINFO del paquete exponen este hecho en una relación de paquete alpm de tipo provisión (es

Junto con el prefijo asignado al directorio de búsqueda dado del archivo de objeto compartido que proporciona el soname necesario, estos datos se añaden como una dependencia de tiempo de ejecución a los datos PKGINFO del paquete que se está construyendo (por ejemplo, depend = lib:libexample.so.1 [[220]], si el prefijo para /usr/lib es lib y el archivo de objeto compartido que codifica el soname libexample.so.1 está presente en /usr/lib [[233]]). A los implementadores se les recomienda encarecidamente hacer que este comportamiento sea configurable, ya que la detección de soname puede fallar o depender de datos soname que pueden no ser aconsejables bajo ciertas condiciones.
