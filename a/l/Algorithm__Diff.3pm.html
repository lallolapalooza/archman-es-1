Algorithm::Diff(3) Documentación de Perl aportada por el usuario Algorithm::Diff(3)

NOMBRE

Algorithm::Diff - Calcula diferencias `inteligentes' entre dos archivos / listas

SINOPSIS

require Algorithm::Diff;
# Este ejemplo produce salida 'diff' tradicional:
my $diff = Algorithm::Diff->new( \@seq1, \@seq2 );
$diff->Base( 1 );   # Devuelve números de línea, no índices
while(  $diff->Next()  ) {
    next   if  $diff->Same();
    my $sep = '';
    if(  ! $diff->Items(2)  ) {
        printf "%d,%dd%d\n",
            $diff->Get(qw( Min1 Max1 Max2 ));
    } elsif(  ! $diff->Items(1)  ) {
        printf "%da%d,%d\n",
            $diff->Get(qw( Max1 Min2 Max2 ));
    } else {
        $sep = "---\n";
        printf "%d,%dc%d,%d\n",
            $diff->Get(qw( Min1 Max1 Min2 Max2 ));
    }
    print "< $_"   for  $diff->Items(1);
    print $sep;
    print "> $_"   for  $diff->Items(2);
}
# Interfaces alternativas:
use Algorithm::Diff qw(
    LCS LCS_length LCSidx
    diff sdiff compact_diff
    traverse_sequences traverse_balanced );
@lcs    = LCS( \@seq1, \@seq2 );
$lcsref = LCS( \@seq1, \@seq2 );
$count  = LCS_length( \@seq1, \@seq2 );
( $seq1idxref, $seq2idxref ) = LCSidx( \@seq1, \@seq2 );
# Interfaces complicadas:
@diffs  = diff( \@seq1, \@seq2 );
@sdiffs = sdiff( \@seq1, \@seq2 );
@cdiffs = compact_diff( \@seq1, \@seq2 );
traverse_sequences(
    \@seq1,
    \@seq2,
    {   MATCH     => \&callback1,
        DISCARD_A => \&callback2,
        DISCARD_B => \&callback3,
    },
    \&key_generator,
    @extra_args,
);
traverse_balanced(
    \@seq1,
    \@seq2,
    {   MATCH     => \&callback1,
        DISCARD_A => \&callback2,
        DISCARD_B => \&callback3,
        CHANGE    => \&callback4,
    },
    \&key_generator,
    @extra_args,
);

INTRODUCCIÓN

(por Mark-Jason Dominus)

Una vez leí un artículo escrito por los autores de "diff"; dijeron que trabajaron muy duro en el algoritmo hasta que encontraron el correcto.

Creo que lo que terminaron usando (y espero que alguien me corrija, porque no estoy muy seguro de esto) fue el método de `subsecuencia común más larga'. En el problema de LCS (subsecuencia común más larga), tienes dos secuencias de elementos:

a b c d f g h j q z
a b c d e f g i j k r x y z

y quieres encontrar la secuencia de elementos más larga que está presente en ambas secuencias originales en el mismo orden. Es decir, quieres encontrar una nueva secuencia S que se puede obtener de la primera secuencia eliminando algunos elementos, y de la segunda secuencia eliminando otros elementos. También quieres que S sea lo más larga posible. En este caso S es

a b c d f g j z

A partir de ahí es solo un pequeño paso para obtener una salida similar a diff:

e   h i   k   q r x y
+   - +   +   - + + +

Este módulo resuelve el problema de LCS. También incluye una función predefinida para generar salida similar a "diff".

Podría parecer por el ejemplo de arriba que la LCS de dos secuencias es siempre bastante obvia, pero ese no es siempre el caso, especialmente cuando las dos secuencias tienen muchos elementos repetidos. Por ejemplo, considera

a x b y c z p d q
a b c a x b y c z

Un enfoque ingenuo podría empezar emparejando el "a" y el "b" que aparecen al principio de cada secuencia, así:

a x b y c         z p d q
a   b   c a b y c z

Esto encuentra la subsecuencia común "a b c z". Pero en realidad, la LCS es "a x b y c z":

      a x b y c z p d q
a b c a x b y c z

o

a       x b y c z p d q
a b c a x b y c z

USO

(Ver también el archivo README y varios scripts de ejemplo incluidos con este módulo.)

Este módulo ahora proporciona una interfaz orientada a objetos que usa menos memoria y es más fácil de usar que la mayoría de las interfaces procedimentales anteriores. También sigue proporcionando varias funciones exportables. Trataremos estas en orden ascendente de dificultad: "LCS", "LCS_length", "LCSidx", interfaz OO, "prepare", "diff", "sdiff", "traverse_sequences", y "traverse_balanced".

"LCS"

Dadas referencias a dos listas de elementos, LCS devuelve un array que contiene su subsecuencia común más larga. En contexto escalar, devuelve una referencia a una lista de ese tipo.

@lcs    = LCS( \@seq1, \@seq2 );
$lcsref = LCS( \@seq1, \@seq2 );

"LCS" puede recibir un tercer parámetro opcional; este es una referencia CODE a una función de generación de claves. Ver "FUNCIONES DE GENERACIÓN DE CLAVES".

@lcs    = LCS( \@seq1, \@seq2, \&keyGen, @args );
$lcsref = LCS( \@seq1, \@seq2, \&keyGen, @args );

Los parámetros adicionales, si los hay, se pasarán a la rutina de generación de claves.

"LCS_length"

Es igual que "LCS" excepto que solo devuelve la longitud de la subsecuencia común más larga. Esto proporciona una mejora de rendimiento de aproximadamente un 9% en comparación con "LCS".

"LCSidx"

Igual que "LCS" excepto que devuelve referencias a dos arrays. El primer array contiene los índices en @seq1 donde se encuentran los elementos de la LCS. El segundo array contiene los índices en @seq2 donde se encuentran los elementos de la LCS.

Por lo tanto, las siguientes tres listas contendrán los mismos valores:

my( $idx1, $idx2 ) = LCSidx( \@seq1, \@seq2 );
my @list1 = @seq1[ @$idx1 ];
my @list2 = @seq2[ @$idx2 ];
my @list3 = LCS( \@seq1, \@seq2 );

"new"

$diff = Algorithm::Diff->new( \@seq1, \@seq2 );
$diff = Algorithm::Diff->new( \@seq1, \@seq2, \%opts );

"new" calcula el conjunto más pequeño de adiciones y eliminaciones necesario para convertir la primera secuencia en la segunda y los registra compactamente en el objeto.

Usas el objeto para iterar sobre bloques (hunks), donde cada bloque representa una sección contigua de elementos que deben ser añadidos, eliminados, reemplazados o dejados sin cambios.

El siguiente resumen de todos los métodos se parece mucho a código Perl pero algunos de los símbolos tienen significados diferentes:

[ ]     Encierra argumentos opcionales
:       Va seguido del valor por defecto de un argumento opcional
|       Separa resultados de retorno alternativos

Resumen de métodos:

$obj        = Algorithm::Diff->new( \@seq1, \@seq2, [ \%opts ] );
$pos        = $obj->Next(  [ $count : 1 ] );
$revPos     = $obj->Prev(  [ $count : 1 ] );
$obj        = $obj->Reset( [ $pos : 0 ] );
$copy       = $obj->Copy(  [ $pos, [ $newBase ] ] );
$oldBase    = $obj->Base(  [ $newBase ] );

Ten en cuenta que todos los siguientes métodos "die" si se usan en un objeto que está "reset" (no apuntando actualmente a ningún bloque).

$bits       = $obj->Diff(  );
@items|$cnt = $obj->Same(  );
@items|$cnt = $obj->Items( $seqNum );
@idxs |$cnt = $obj->Range( $seqNum, [ $base ] );
$minIdx     = $obj->Min(   $seqNum, [ $base ] );
$maxIdx     = $obj->Max(   $seqNum, [ $base ] );
@values     = $obj->Get(   @names );

Pasar "undef" como un argumento opcional siempre se trata igual que si no se hubiera pasado ningún argumento.

"Next"
$pos = $diff->Next();    # Moverse hacia adelante 1 bloque
$pos = $diff->Next( 2 ); # Moverse hacia adelante 2 bloques
$pos = $diff->Next(-5);  # Moverse hacia atrás 5 bloques

"Next" mueve el objeto para apuntar al siguiente bloque. El objeto comienza en estado "reset", lo que significa que no apunta a ningún bloque. Si el objeto está reseteado, entonces Next() se mueve al primer bloque.

"Next" devuelve un valor verdadero si y solo si el movimiento no pasó del último fragmento. Así que Next(0) devolverá verdadero si y solo si el objeto no está reiniciado.

En realidad, "Next" devuelve la nueva posición del objeto, que es un número entre 1 y el número de fragmentos (inclusive), o devuelve un valor falso.

"Prev"
Prev($N) es casi idéntico a Next(-$N); se mueve al $N-ésimo fragmento anterior. En un objeto 'reiniciado', Prev() [y Next(-1)] se mueven al último fragmento.

La posición devuelta por "Prev" es relativa al final de los fragmentos; -1 para el último fragmento, -2 para el penúltimo, etc.

"Reset"
$diff->Reset();     # Reinicia la posición del objeto
$diff->Reset($pos); # Se mueve al fragmento especificado
$diff->Reset(1);    # Se mueve al primer fragmento
$diff->Reset(-1);   # Se mueve al último fragmento

"Reset" devuelve el objeto, así que, por ejemplo, podrías usar "$diff->Reset()->Next(-1)" para obtener el número de fragmentos.

"Copy"
$copy = $diff->Copy( $newPos, $newBase );

"Copy" devuelve una copia del objeto. La copia y el objeto original comparten la mayoría de sus datos, así que hacer copias consume muy poca memoria. La copia mantiene su propia posición (separada de la original), que es el propósito principal de las copias. También mantiene su propia base.

Por defecto, la posición de la copia comienza siendo la misma que la posición del objeto original. Pero "Copy" acepta un argumento opcional para establecer la nueva posición, así que los siguientes tres fragmentos de código son equivalentes:

$copy = $diff->Copy($pos);
$copy = $diff->Copy();
$copy->Reset($pos);
$copy = $diff->Copy()->Reset($pos);

"Copy" acepta un segundo argumento opcional para establecer la base de la copia. Si deseas cambiar la base de la copia pero dejar la posición igual que en el original, aquí hay dos formas equivalentes:

$copy = $diff->Copy();
$copy->Base( 0 );
$copy = $diff->Copy(undef,0);

Aquí hay dos formas equivalentes de obtener una copia "reiniciada":

$copy = $diff->Copy(0);
$copy = $diff->Copy()->Reset();
"Diff"
$bits = $obj->Diff();

"Diff" devuelve un valor verdadero si y solo si el fragmento actual contiene elementos que son diferentes entre las dos secuencias. En realidad devuelve uno de los siguientes 4 valores:

3
"3==(1|2)". Este fragmento contiene elementos de @seq1 y los elementos de @seq2 que deberían reemplazarlos. Tanto la secuencia 1 como la 2 contienen elementos modificados, por lo que se establecen los bits 1 y 2.
2
Este fragmento solo contiene elementos de @seq2 que deberían insertarse (no elementos de @seq1). Solo la secuencia 2 contiene elementos modificados, por lo que solo se establece el bit 2.
1
Este fragmento solo contiene elementos de @seq1 que deberían eliminarse (no elementos de @seq2). Solo la secuencia 1 contiene elementos modificados, por lo que solo se establece el bit 1.
0
Esto significa que los elementos en este fragmento son los mismos en ambas secuencias. Ni la secuencia 1 ni la 2 contienen elementos modificados, por lo que no se establecen ni el bit 1 ni el bit 2.
"Same"
"Same" devuelve un valor verdadero si y solo si el fragmento actual contiene elementos que son los mismos en ambas secuencias. En realidad devuelve la lista de elementos si son iguales o una lista vacía si no lo son. En un contexto escalar, devuelve el tamaño de la lista.
"Items"
$count = $diff->Items(2);
@items = $diff->Items($seqNum);

"Items" devuelve los (número de) elementos de la secuencia especificada que forman parte del fragmento actual.

Si el fragmento actual contiene solo inserciones, entonces "$diff->Items(1)" devolverá una lista vacía (0 en un contexto escalar). Si el fragmento actual contiene solo eliminaciones, entonces "$diff->Items(2)" devolverá una lista vacía (0 en un contexto escalar).

Si el fragmento contiene reemplazos, entonces tanto "$diff->Items(1)" como "$diff->Items(2)" devolverán listas diferentes y no vacías.

De lo contrario, el fragmento contiene elementos idénticos y todo lo siguiente devolverá las mismas listas:

@items = $diff->Items(1);
@items = $diff->Items(2);
@items = $diff->Same();
"Range"
$count = $diff->Range( $seqNum );
@indices = $diff->Range( $seqNum );
@indices = $diff->Range( $seqNum, $base );

"Range" es como "Items" excepto que devuelve una lista de índices a los elementos en lugar de los elementos mismos. Por defecto, el índice del primer elemento (en cada secuencia) es 0 pero esto puede cambiarse llamando al método "Base" . Así que, por defecto, los siguientes dos fragmentos devuelven las mismas listas:

@list = $diff->Items(2);
@list = @seq2[ $diff->Range(2) ];

También puedes especificar la base a usar como segundo argumento. Así que los siguientes dos fragmentos siempre devuelven las mismas listas:

@list = $diff->Items(1);
@list = @seq1[ $diff->Range(1,0) ];
"Base"
$curBase = $diff->Base();
$oldBase = $diff->Base($newBase);

"Base" establece y/o devuelve la base actual (usualmente 0 o 1) que se usa cuando solicitas información de rango. La base es 0 por defecto para que la información de rango se devuelva como índices de matriz. Puedes establecer la base en 1 si prefieres reportar números de línea tradicionales.

"Min"
$min1 = $diff->Min(1);
$min = $diff->Min( $seqNum, $base );

"Min" devuelve el primer valor que "Range" devolvería (dado los mismos argumentos) o devuelve "undef" si "Range" devolvería una lista vacía.

"Max"
"Max" devuelve el último valor que "Range" devolvería o "undef".
"Get"
( $n, $x, $r ) = $diff->Get(qw( min1 max1 range1 ));
@values = $diff->Get(qw( 0min2 1max2 range2 same base ));

"Get" devuelve uno o más valores escalares. Pasas una lista de los nombres de los valores que quieres que se devuelvan. Cada nombre debe coincidir con una de las siguientes expresiones regulares:

/^(-?\d+)?(min|max)[12]$/i
/^(range[12]|same|diff|base)$/i

El 1 o 2 después de un nombre indica para qué secuencia quieres la información (y donde se permite, es obligatorio). El número opcional antes de "min" o "max" es la base a usar. Así que se cumplen las siguientes igualdades:

$diff->Get('min1') == $diff->Min(1)
$diff->Get('0min2') == $diff->Min(2,0)

Usar "Get" en un contexto escalar cuando has pasado más de un nombre es un error fatal ("die" se llama).

"prepare"

Dada una referencia a una lista de elementos, "prepare" devuelve una referencia a un hash que puede usarse al comparar esta secuencia con otras secuencias con "LCS" o "LCS_length".

$prep = prepare( \@seq1 );
for $i ( 0 .. 10_000 )
{
    @lcs = LCS( $prep, $seq[$i] );
    # haz algo útil con @lcs
}

"prepare" puede recibir un tercer parámetro opcional; este es una referencia CODE a una función de generación de claves. Ver "FUNCIONES DE GENERACIÓN DE CLAVES".

$prep = prepare( \@seq1, \&keyGen );
for $i ( 0 .. 10_000 )
{
    @lcs = LCS( $seq[$i], $prep, \&keyGen );
    # haz algo útil con @lcs
}

Usar "prepare" proporciona una mejora de rendimiento de aproximadamente un 50% al llamar a LCS muchas veces en comparación con no preparar.

"diff"

@diffs     = diff( \@seq1, \@seq2 );
$diffs_ref = diff( \@seq1, \@seq2 );

"diff" calcula el conjunto más pequeño de adiciones y eliminaciones necesario para convertir la primera secuencia en la segunda, y devuelve una descripción de estos cambios. La descripción es una lista de fragmentos; cada fragmento representa una sección contigua de elementos que deberían agregarse, eliminarse o reemplazarse. (Los fragmentos que contienen elementos sin cambios no se incluyen.)

El valor de retorno de "diff" es una lista de fragmentos, o, en contexto escalar, una referencia a dicha lista. Si no hay diferencias, la lista estará vacía.

Aquí hay un ejemplo. Llamar a "diff" para las siguientes dos secuencias:

a b c e h j l m n p
b c d e f j k l m r s t

produciría la siguiente lista:

(
  [ [ '-', 0, 'a' ] ],
  [ [ '+', 2, 'd' ] ],
  [ [ '-', 4, 'h' ],
    [ '+', 4, 'f' ] ],
  [ [ '+', 6, 'k' ] ],
  [ [ '-',  8, 'n' ],
    [ '-',  9, 'p' ],
    [ '+',  9, 'r' ],
    [ '+', 10, 's' ],
    [ '+', 11, 't' ] ],
)

Hay cinco fragmentos aquí. El primer fragmento dice que la "a" en la posición 0 de la primera secuencia debería eliminarse ("-"). El segundo fragmento dice que la "d" en la posición 2 de la segunda secuencia debería insertarse ("+"). El tercer fragmento dice que la "h" en la posición 4 de la primera secuencia debería quitarse y reemplazarse con la "f" de la posición 4 de la segunda secuencia. Y así sucesivamente.

"diff" puede recibir un tercer parámetro opcional; esta es una referencia CODE a una función de generación de claves. Ver "KEY GENERATION FUNCTIONS".

Parámetros adicionales, si los hay, se pasarán a la rutina de generación de claves.

"sdiff"

@sdiffs     = sdiff( \@seq1, \@seq2 );
$sdiffs_ref = sdiff( \@seq1, \@seq2 );

"sdiff" calcula todos los componentes necesarios para mostrar dos secuencias y sus diferencias minimizadas lado a lado, igual que la utilidad de Unix sdiff lo hace:

same             same
before     |     after
old        <     -
-          >     new

Devuelve una lista de referencias a arreglos, cada una apuntando a un arreglo de instrucciones de visualización. En contexto escalar devuelve una referencia a tal lista. Si no hay diferencias, la lista tendrá una entrada por elemento, cada una indicando que el elemento no fue modificado.

Las instrucciones de visualización consisten en tres elementos: Un indicador de modificador ("+": Elemento añadido, "-": Elemento eliminado, "u": Elemento sin modificar, "c": Elemento cambiado) y el valor de los elementos antiguo y nuevo, para mostrarse lado a lado.

Un "sdiff" de las siguientes dos secuencias:

a b c e h j l m n p
b c d e f j k l m r s t

resulta en

( [ '-', 'a', ''  ],
  [ 'u', 'b', 'b' ],
  [ 'u', 'c', 'c' ],
  [ '+', '',  'd' ],
  [ 'u', 'e', 'e' ],
  [ 'c', 'h', 'f' ],
  [ 'u', 'j', 'j' ],
  [ '+', '',  'k' ],
  [ 'u', 'l', 'l' ],
  [ 'u', 'm', 'm' ],
  [ 'c', 'n', 'r' ],
  [ 'c', 'p', 's' ],
  [ '+', '',  't' ],
)

"sdiff" puede recibir un tercer parámetro opcional; esta es una referencia CODE a una función de generación de claves. Ver "KEY GENERATION FUNCTIONS".

Parámetros adicionales, si los hay, se pasarán a la rutina de generación de claves.

"compact_diff"

"compact_diff" es muy parecido a "sdiff" excepto que devuelve una descripción mucho más compacta que consiste en una sola lista plana de índices. Un ejemplo ayuda a explicar el formato:

my @a = qw( a b c   e  h j   l m n p      );
my @b = qw(   b c d e f  j k l m    r s t );
@cdiff = compact_diff( \@a, \@b );
# Returns:
#   @a      @b       @a       @b
#  start   start   values   values
(    0,      0,   #       =
     0,      0,   #    a  !
     1,      0,   #  b c  =  b c
     3,      2,   #       !  d
     3,      3,   #    e  =  e
     4,      4,   #    f  !  h
     5,      5,   #    j  =  j
     6,      6,   #       !  k
     6,      7,   #  l m  =  l m
     8,      9,   #  n p  !  r s t
    10,     12,   #
);

Las entradas 0, 2, 4, etc. son todos índices en @seq1 (@a en el ejemplo anterior) indicando dónde comienza un bloque. Las entradas 1, 3, 5, etc. son todos índices en @seq2 (@b en el ejemplo anterior) indicando dónde comienza el mismo bloque.

Así que cada par de índices (excepto el último par) describe dónde comienza un bloque (en cada secuencia). Como cada bloque debe terminar en el elemento justo antes del elemento que comienza el siguiente bloque, el siguiente par de índices puede usarse para determinar dónde termina el bloque.

Así, las primeras 4 entradas (0..3) describen el primer bloque. Las entradas 0 y 1 describen dónde comienza el primer bloque (y por lo tanto siempre son ambas 0). Las entradas 2 y 3 describen dónde comienza el siguiente bloque, por lo que restando 1 de cada una nos dice dónde termina el primer bloque. Es decir, el primer bloque contiene los elementos $diff[0] a través de "$diff[2] - 1" de la primera secuencia y contiene los elementos $diff[1] a través de "$diff[3] - 1" de la segunda secuencia.

En otras palabras, el primer bloque consiste en las siguientes dos listas de elementos:

           #  1st pair     2nd pair
           # of indices   of indices
@list1 = @a[ $cdiff[0] .. $cdiff[2]-1 ];
@list2 = @b[ $cdiff[1] .. $cdiff[3]-1 ];
           # Hunk start   Hunk end

Note que los bloques siempre alternarán entre aquellos que son parte de la LCS (aquellos que contienen elementos sin cambios) y aquellos que contienen cambios. Esto significa que todo lo que necesitamos saber es si el primer bloque es un bloque 'same' (igual) o 'diff' (diferente) y podemos determinar cuáles de los otros bloques contienen elementos 'same' o elementos 'diff'.

Por convención, siempre hacemos que el primer bloque contenga elementos sin cambios. Así que el 1º, 3º, 5º, etc. bloques (todos los bloques de número impar si comienzas a contar desde 1) todos contienen elementos sin cambios. Y el 2º, 4º, 6º, etc. bloques (todos los bloques de número par si comienzas a contar desde 1) todos contienen elementos cambiados.

Dado que @a y @b no comienzan con el mismo valor, el primer bloque en nuestro ejemplo está vacío (de lo contrario violaríamos la convención anterior). Note que los primeros 4 valores de índice en nuestro ejemplo son todos cero. Inserte estos valores en nuestro bloque de código anterior y obtenemos:

@hunk1a = @a[ 0 .. 0-1 ];
@hunk1b = @b[ 0 .. 0-1 ];

Y "0..-1" devuelve la lista vacía.

Mueva hacia abajo un par de índices (2..5) y obtenemos los rangos de desplazamiento para el segundo bloque, que contiene elementos cambiados.

Dado que @diff[2..5] contiene (0,0,1,0) en nuestro ejemplo, el segundo bloque consiste en estas dos listas de elementos:

    @hunk2a = @a[ $cdiff[2] .. $cdiff[4]-1 ];
    @hunk2b = @b[ $cdiff[3] .. $cdiff[5]-1 ];
# or
    @hunk2a = @a[ 0 .. 1-1 ];
    @hunk2b = @b[ 0 .. 0-1 ];
# or
    @hunk2a = @a[ 0 .. 0 ];
    @hunk2b = @b[ 0 .. -1 ];
# or
    @hunk2a = ( 'a' );
    @hunk2b = ( );

Es decir, eliminaríamos el elemento 0 ('a') de @a.

Dado que @diff[4..7] contiene (1,0,3,2) en nuestro ejemplo, el tercer bloque consiste en estas dos listas de elementos:

    @hunk3a = @a[ $cdiff[4] .. $cdiff[6]-1 ];
    @hunk3a = @b[ $cdiff[5] .. $cdiff[7]-1 ];
# or
    @hunk3a = @a[ 1 .. 3-1 ];
    @hunk3a = @b[ 0 .. 2-1 ];
# or
    @hunk3a = @a[ 1 .. 2 ];
    @hunk3a = @b[ 0 .. 1 ];
# or
    @hunk3a = qw( b c );
    @hunk3a = qw( b c );

Note que este tercer bloque contiene elementos sin cambios como nuestra convención exige.

Puede continuar este proceso hasta que alcance los últimos dos índices, que siempre serán el número de elementos en cada secuencia. Esto es necesario para que restando uno de cada uno obtenga los índices de los últimos elementos en cada secuencia.

"traverse_sequences"

"traverse_sequences" solía ser la instalación más general proporcionada por este módulo (la nueva interfaz OO es más poderosa y mucho más fácil de usar).

Imagine que hay dos flechas. La flecha A apunta a un elemento de la secuencia A, y la flecha B apunta a un elemento de la secuencia B. Al inicio, las flechas apuntan a los primeros elementos de las respectivas secuencias. "traverse_sequences" avanzará las flechas a través de las secuencias un elemento a la vez, llamando a una función de callback especificada por el usuario antes de cada avance. Avanzará las flechas de tal manera que si hay elementos iguales $A[$i] y $B[$j] que son iguales y que son parte de la LCS, habrá algún momento durante la ejecución de "traverse_sequences" cuando la flecha A esté apuntando a $A[$i] y la flecha B esté apuntando a $B[$j]. Cuando esto suceda, "traverse_sequences" llamará a la función de callback "MATCH" y luego avanzará ambas flechas.

De lo contrario, una de las flechas está apuntando a un elemento de su secuencia que no es parte de la LCS. "traverse_sequences" avanzará esa flecha y llamará a la "DISCARD_A" o a la "DISCARD_B" función de callback, dependiendo de qué flecha avanzó. Si ambas flechas apuntan a elementos que no son parte de la LCS, entonces "traverse_sequences" avanzará una de ellas y llamará a la función de callback apropiada, pero no se especifica a cuál llamará.

Los argumentos de "traverse_sequences" son las dos secuencias a recorrer, y un hash que especifica las funciones de callback, como esto:

traverse_sequences(
    \@seq1, \@seq2,
    {   MATCH => $callback_1,
        DISCARD_A => $callback_2,
        DISCARD_B => $callback_3,
    }
);

Los callbacks para MATCH, DISCARD_A y DISCARD_B son invocados con al menos los índices de las dos flechas como sus argumentos. No se espera que devuelvan ningún valor. Si un callback se omite de la tabla, no se llama.

Los callbacks para A_FINISHED y B_FINISHED son invocados con al menos el índice correspondiente en A o B.

Si la flecha A alcanza el final de su secuencia antes que la flecha B, "traverse_sequences" llamará al callback "A_FINISHED" cuando avance la flecha B, si hay tal función; si no, llamará a "DISCARD_B" en su lugar. De manera similar si la flecha B termina primero. "traverse_sequences" devuelve cuando ambas flechas están en los finales de sus respectivas secuencias. Devuelve verdadero en éxito y falso en fallo. Actualmente no hay manera de fallar.

"traverse_sequences" puede recibir un cuarto parámetro opcional; esta es una referencia CODE a una función de generación de claves. Ver "KEY GENERATION FUNCTIONS".

Parámetros adicionales, si los hay, se pasarán a la función de generación de claves.

Si desea pasar parámetros adicionales a sus callbacks, pero no necesita una función de generación de claves personalizada, puede obtener la predeterminada pasando undef:

traverse_sequences(
    \@seq1, \@seq2,
    {   MATCH => $callback_1,
        DISCARD_A => $callback_2,
        DISCARD_B => $callback_3,
    },
    undef,     # default key-gen
    $myArgument1,
    $myArgument2,
    $myArgument3,
);

"traverse_sequences" no tiene un valor de retorno útil; se espera que usted conecte el comportamiento apropiado con las funciones de callback.

"traverse_balanced" es una alternativa a "traverse_sequences". Utiliza un algoritmo diferente para iterar a través de las entradas en el LCS calculado. En lugar de adherirse a un lado y mostrar los cambios de elementos solo como inserciones y eliminaciones, saltará de un lado a otro entre las dos secuencias e informará de cambios que ocurren como eliminaciones en un lado seguidas inmediatamente por una inserción en el otro lado.

Además de los "DISCARD_A", "DISCARD_B"y "MATCH" callbacks soportados por "traverse_sequences", "traverse_balanced" soporta un "CHANGE" callback que indica que un elemento fue "reemplazado" por otro:

traverse_balanced(
    \@seq1, \@seq2,
    {   MATCH => $callback_1,
        DISCARD_A => $callback_2,
        DISCARD_B => $callback_3,
        CHANGE    => $callback_4,
    }
);

Si no se especifica un "CHANGE" callback, "traverse_balanced" mapeará los "CHANGE" eventos a las acciones "DISCARD_A" y "DISCARD_B" , por lo tanto resultando en un comportamiento similar al de "traverse_sequences" con un orden diferente de eventos.

"traverse_balanced" podría ser un poco más lento que "traverse_sequences", perceptible solo al procesar cantidades masivas de datos.

La "sdiff" función de este módulo está implementada como una llamada a "traverse_balanced".

"traverse_balanced" no tiene un valor de retorno útil; se espera que usted proporcione el comportamiento apropiado con las funciones callback.

FUNCIONES DE GENERACIÓN DE CLAVES

La mayoría de las funciones aceptan un parámetro extra opcional. Este es una referencia CODE a una función de generación de claves (hashing) que debería devolver una cadena que identifique de manera única a un elemento dado. Debería ser el caso de que si dos elementos se consideran iguales, sus claves deberían ser las mismas (y viceversa). Si no se proporciona una función de generación de claves, la clave será el elemento como cadena.

Por defecto, las comparaciones usarán "eq" y los elementos serán convertidos en claves usando el operador de conversión a cadena por defecto '""'.

Donde esto es importante es cuando está comparando algo diferente de cadenas. Si es el caso de que tiene múltiples objetos diferentes que deberían considerarse iguales, debería proporcionar una función de generación de claves. De lo contrario, tiene que asegurarse de que sus arreglos contengan referencias únicas.

Por ejemplo, considere este ejemplo:

package Person;
sub new
{
    my $package = shift;
    return bless { name => '', ssn => '', @_ }, $package;
}
sub clone
{
    my $old = shift;
    my $new = bless { %$old }, ref($old);
}
sub hash
{
    return shift()->{'ssn'};
}
my $person1 = Person->new( name => 'Joe', ssn => '123-45-6789' );
my $person2 = Person->new( name => 'Mary', ssn => '123-47-0000' );
my $person3 = Person->new( name => 'Pete', ssn => '999-45-2222' );
my $person4 = Person->new( name => 'Peggy', ssn => '123-45-9999' );
my $person5 = Person->new( name => 'Frank', ssn => '000-45-9999' );

Si hiciera esto:

my $array1 = [ $person1, $person2, $person4 ];
my $array2 = [ $person1, $person3, $person4, $person5 ];
Algorithm::Diff::diff( $array1, $array2 );

todo funcionaría bien (cada uno de los objetos sería convertido en una cadena como "Person=HASH(0x82425b0)" para la comparación).

Pero si hiciera esto:

my $array1 = [ $person1, $person2, $person4 ];
my $array2 = [ $person1, $person3, $person4->clone(), $person5 ];
Algorithm::Diff::diff( $array1, $array2 );

$person4 y $person4->clone() (que tienen el mismo nombre y SSN) serían vistos como objetos diferentes. Si quisiera que se consideraran equivalentes, tendría que pasar una función de generación de claves:

my $array1 = [ $person1, $person2, $person4 ];
my $array2 = [ $person1, $person3, $person4->clone(), $person5 ];
Algorithm::Diff::diff( $array1, $array2, \&Person::hash );

Esto usaría el campo 'ssn' en cada Person como clave de comparación, y por lo tanto consideraría a $person4 y $person4->clone() como iguales.

También puede pasar parámetros adicionales a la función de generación de claves si lo desea.
