¿Qué son Alien, Alien::Base y Alien::

Build?

Alien es un espacio de nombres de Perl para definir dependencias en CPAN para bibliotecas y herramientas que no son "nativas" de CPAN. Para una descripción estilo manifiesto del Porq

ué y el Cómo, véase Alien. Alien::Base es una clase base para el tiempo de ejecución de Alien. Alien::Build es una herramienta para sondear el sistema operativo en busca de biblioteca
s y herramientas existentes, y para descargar, compilar e instalar paquetes. alienfile es un formato de receta para describir cómo sondear, descargar, compilar e instalar un paquete.

¿Cómo compilo un paquete que usa sistema de

compilación

autocon

f

Usa el plugin autoconf (Alien::Build::Plugin::Build::Autoconf). Si tu paquete proporciona un archivo pkg-config ".pc", también puedes usar el plugin PkgConfig (Alien::Build::Plugin::PkgConfig::Negotiate). Usa el plugin autoconf (Alien::Build::Plugin::Build::Autoconf). Si tu paquete proporciona un archivo pkg-config ".pc", también puedes usar el plugin PkgConfig (Alien::Build::Plugin::PkgConfig::Negotiate)

. 
use alienfile
plugin PkgConfig => 'libfoo';
share {
  start_url => 'http://example.org/dist';
  plugin Download => (
    version => qr/libfoo-([0-9\.])\.tar\.gz$/,
  );
  plugin Extract => 'tar.gz';
  plugin 'Build::Autoconf';
}
;

Si necesitas proporcionar flags personalizados a configure, puedes hacerlo

también: 
share {
  plugin 'Build::Autoconf';
  build [
    '%{configure} --disable-shared --enable-foo',
    '%{make}',
    '%{make} install',
  ];
}
;

Si tu paquete requiere GNU Make, usa "%{gmake}" en lugar de "%{make

}".

autoconf sin script

configure

Un número de proyectos de código abierto usan autotools, pero no proporcionan el script "configure". Cuando alienizas este tipo de paquetes tienes algunas

opciones:
compilar configure usando
autotools
El Alien Alien::Autotools está diseñado para proporcionar autotools para compilar tales paquetes desde el código fuente. La ventaja es que esta es la forma en que los desarrolladores originales pretenden que se compile su paquete. La desventaja es que también añade más prerequisitos a tu Alien. La parte positiva es que si requieres este Alien en el bloque "share" (como deberías), entonces estos prerequisitos solo se añadirán durante una instalación share cuando se necesiten.

Por favor, consulta la documentación de

Alien::Autotools para detalles sobre
cómo se puede usar en tu alienfile.
parchear el paquete localmente antes de
compilar
Puedes usar la directiva "patch" en alienfile para parchear el paquete alienizado localmente antes de compilar. Esto a veces puede ser difícil porque Autotools usa marcas de tiempo para decidir qué necesita ser recompilado, y parchear a veces puede confundirlo haciéndole pensar que más necesita ser recompilado de lo que realmente
necesita.
compilar configure y
tarball
También puedes compilar el script configure durante el desarrollo de tu alien, generar el tarball y
proporcionarlo en algún lugar como GitHub y usarlo como el origen en lugar del origen original. Es
to normalmente debería ser un último recurso si los otros dos métodos resultan demasiado difíciles.

estilo

autoconf

Si ves un error como

este: 
Unknown option
"--with-pic".

Es porque el plugin autoconf usa la opción "--with-pic" por defecto, ya que tiene sentido la mayoría de las veces, y autoconf normalmente ignora opciones que no reconoce. Algunos sistemas de compilación estilo autoconf fallan cuando ven una opción que no reconocen. Puedes desactivar este comportamiento para estos

paquetes: 
plugin 'Build::Autoconf' => (
  with_pic => 0,
)
;

Otra cosa sobre el plugin autoconf es que usa "DESTDIR" para hacer una instalación en dos etapas. Si ves un error como "nothing was installed into destdir", eso significa que tu paquete no soporta "DESTDIR". Deberías usar en su lugar el plugin MSYS y usar una secuencia de comandos para hacer la compilación

así: 
share {
  plugin 'Build::MSYS';
  build [
    # ejecutar explícitamente configure con "sh" asegurará que
    # funcione en windows así como en UNIX.
    'sh configure --prefix=%{.install.prefix} --disable-shared',
    '%{make}',
    '%{make} install',
  ];
}
;

CMak

e

Hay un alien Alien::cmake3 que proporciona "cmake" 3.x o mejor (Se prefiere al más antiguo Alien::CMake). Aunque se recomienda que uses el plugin "cmake" (Alien::Build::Plugin::Build::CMake) en lugar de usar Alien::cmake3. plugin "cmake" (Alien::Build::Plugin::Build::CMake) en lugar de usar Alien::

cmake3. 
use alienfile;

share {
  plugin 'Build::CMake';
  build [
    # este es el paso de compilación por defecto, si no especificas uno.
    [ '%{cmake}',
        @{ meta->prop->{plugin_build_cmake}->{args} },
        # ... pon argumentos extra de cmake aquí ...
        '.'
    ],
    '%{make}',
    '%{make} install',
  ];
}
;

Makefiles

estándar

Alien::Build proporciona un ayudante ("%{make}") para el "make" que es usado por Perl y ExtUtils::MakeMaker (EUMM). Desafortunadamente el "make" soportado por Perl y EUMM en Windows ("nmake" y "dmake") no es ampliamente soportado por la mayoría de proyectos de código abierto. (Afortunadamente los perls y EUMM recientes soportan GNU Make en windows ahora)

.

Puedes usar el plugin "make" (Alien::Build::Plugin::Build::Make) para decirle al sistema Alien::Build qué make requiere el proyecto que estás

alienizando. 
plugin 'Build::Make' => 'umake';
# umake hace que %{make} sea GNU Make o BSD Make en Unix y GNU Make en Windows.
build {
  build [
    # Puedes usar el compilador y cflags de configuración de Perl usando el ayudante %{perl.config...}
    [ '%{make}', 'CC=%{perl.config.cc}', 'CFLAGS=%{perl.config.cccdlflags} %{perl.config.optimize}' ],
    [ '%{make}', 'install', 'PREFIX=%{.install.prefix}' ],
  ],
}
;

Algunos proyectos de código abierto requieren GNU Make, y puedes especificar eso, y Alien::gmake se añadirá en plataformas que no lo tengan

ya. 
plugin 'Build::Make' => 'gmake';
.
.
.

¿Cómo sondeo un paquete que usa

pkg-config?

Usa el plugin "pkg-config" (Alien::Build::Plugin::PkgConfig::Negotiate)

: 
use alienfile;
plugin 'PkgConfig' => (
  pkg_name => 'libfoo',
)
;

Sondeará por una versión del sistema de la biblioteca. También añadirá las propiedades apropiadas "version" "cflags" y "libs" en una instalación "system" o "sha

re
".

¿Cómo especifico un requisito de versión mínima o exacta para paquetes que usan

pkg-config?

Los varios plugins de pkg-config soportan todos los campos atleast_version, exact_version y maximum_version, que tienen el mismo significado que la interfaz de línea de comandos de

"pkg-config": 
use alienfile;

plugin 'PkgConfig', pkg_name => 'foo', atleast_version => '1.2.
3';

o 
usalienfile;

plugin 'PkgCo
nfig', pkg_name => foo, e
xact_version => '1.2.3';

¿Cómo puedo buscar un paquete que utiliza múltiples archivos .

pc?

Cada uno de los plugins "PkgConfig" tomará una referencia de array en lugar de una

cadena: 
use alienfile;

plugin 'PkgConfig' => ( pkg_name => [ 'foo', 'bar', 'baz' ] )
;

El primer "pkg_name" proporcionado será utilizado por defecto una vez que tu alien esté instalado. Para obtener la configuración de "foo" y "bar" puedes usar el método alt de Alien::

Base: 
use Alien::libfoo;

$cflags = Alien::libfoo->cflags;               # compiler fl
ags for 'foo' $cflags = Alien::libfoo->alt('bar')->cflags ; # compiler flags for
'bar' $cflags = Alien::libfoo->alt('baz')->cflags ; # compiler flags for 'baz'

¿Cómo crear un módulo Alien para paquetes que no soportan

pkg-config?

Paquetes que proporcionan un script de

configuración

Muchos paquetes proporcionan un comando que puedes usar para obtener la versión, flags de compilación y enlace apropiados. Para esos paquetes puedes simplemente usar los comandos en tu alienfile. Algo como

esto: 
use alienfile;

probe [ 'foo-config --version' ];

share {
  ...

  build [
    '%{make} PREFIX=%{.runtime.prefix}',
    '%{make} install PREFIX=%{.runtime.prefix}',
  ];
};

gather [
  [ 'foo-config', '--version', \'%{.runtime.version}' ],
  [ 'foo-config', '--cflags',  \'%{.runtime.cflags}'  ],
  [ 'foo-config', '--libs',    \'%{.runtime.libs}'    ],
]
;

Paquetes que requieren una prueba de

compilación

Algunos paquetes simplemente esperan que sepas que "-lfoo" funcionará. Para esos puedes usar el plugin "cbuilder" (Alien::Build::Plugin::Probe::CBuilder)

. 
use alienfile;
plugin 'Probe::CBuilder' => (
  cflags => '-I/opt/libfoo/include',
  libs   => '-L/opt/libfoo/lib -lfoo',
);

share {
  ...
  gather sub {
    my($build) = @_;
    my $prefix = $build->runtime_prop->{prefix};
    $build->runtime_prop->{cflags} = "-I$prefix/include ";
    $build->runtime_prop->{libs}   = "-L$prefix/lib -lfoo ";
  };
}

Este plugin compilará un pequeño programa con estos flags y probará que funciona. (También hay opciones para proporcionar un programa que pueda realizar pruebas simples para asegurar

que la biblioteca funciona). Si la prueba funciona, establecerá los flags de compilación y enlace. (También hay opciones para extraer la versión del programa de prueba). Si haces una
instalación compartida, necesitarás establecer los flags de compilación y enlace tú mismo en el paso de recopilación, si no estás usando un plugin de compilación que haga eso por ti.

¿Puedo/debo escribir un módulo Alien orientado a

herramientas?

Ciertamente. La intención original era proporcionar bibliotecas, pero las herramientas también son bastante realizables usando el conjunto de herramientas Alien::Build. Un buen ejemplo de cómo hacer esto es Alien::nasm. Querrás usar el 'Probe::

CommandLine': 
use alienfile;

plugin 'Probe::CommandLine' => (
  command => 'gzip',
)
;

¿Cómo parcheo paquetes que necesitan

alteraciones?

Si tienes un archivo diff puedes usar

patch: 
use alienfile;

probe sub { 'share' }; # replace with appropriate probe

share {
  ...
  patch [ '%{patch} -p1 < %{.install.patch}/mypatch.diff' ];
  build [ ... ] ;
}

..
.

También puedes parchear usando Perl si es más

fácil: 
use alienfile;

probe sub { 'share' };

share {
  ...
  patch sub {
    my($build) = @_;
    # make changes to source prior to build
  };
  build [ ... ];
}
;

¡Los flags que produce un plugin son

incorrectos!

A veces, los flags de compilación o enlace que el plugin PkgConfig genera no son del todo correctos. (Frecuentemente esto es realmente porque un mantenedor del paquete está proporcionando un archivo ".pc" defectuoso). (Otros plugins también pueden tener problemas). Podrías reemplazar el paso "gather" del plugin, pero una mejor manera es proporcionar una subrutina de retorno de llamada para que se invoque después de que el paso de recopilación esté completo. Puedes hacer esto con la directiva "after" del

alienfile: 
use alienfile;

plugin 'PkgConfig' => 'libfoo';

share {
  ...
  after 'gather' => sub {
    my($build) = @_;
    $build->runtime_prop->{libs}        .= " -lbar";        # libfoo also requires libbar
    $build->runtime_prop->{libs_static} .= " -lbar -lbaz";  # libfoo also requires libbaz under static linkage
  };
}
;

A veces solo necesitas hacer esto en ciertas plataformas. Puedes ajustar la lógica basándote en $^O apropiada

mente. 
use alienfile;

plugin 'PkgConfig' => 'libfoo';

share {
  ...
  after 'gather' => sub {
    my($build) = @_;
    if($^O eq 'MSWin32') {
      $build->runtime_prop->{libs} .= " -lpsapi";
    }
  };
}
;
