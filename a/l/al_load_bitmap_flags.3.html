al_load_bitmap_flags(3) Manual de Funciones de Librería al_load_bitmap_flags(3)

NOMBRE

al_load_bitmap_flags - API de Allegro 5

SINOPSIS

#include <allegro5/allegro.h>
ALLEGRO_BITMAP *al_load_bitmap_flags(const char *filename, int flags)

DESCRIPCIÓN

Carga un archivo de imagen en un nuevo ALLEGRO_BITMAP(3). El tipo de archivo se determina mediante al_identify_bitmap(3), usando la extensión como fallback en caso de que la identificación no sea posible.

Devuelve NULL en caso de error.

El parámetro flags puede ser una combinación de las siguientes constantes:

ALLEGRO_NO_PREMULTIPLIED_ALPHA
Por defecto, Allegro pre-multiplica el canal alfa de una imagen con los datos de color de la imagen al cargarla. Típicamente se vería así:
r = get_float_byte();
g = get_float_byte();
b = get_float_byte();
a = get_float_byte();
r = r * a;
g = g * a;
b = b * a;
set_image_pixel(x, y, r, g, b, a);

La razón de esto se puede ver en el ejemplo de Allegro ex_premulalpha, es decir, usar alfa pre-multiplicado da resultados de color más precisos en algunos casos. Para usar la mezcla alfa con imágenes cargadas con alfa pre-multiplicado, usarías el modo de mezcla predeterminado, que se establece con al_set_blender(ALLEGRO_ADD, ALLEGRO_ONE, ALLEGRO_INVERSE_ALPHA).

Al establecer la bandera ALLEGRO_NO_PREMULTIPLIED_ALPHA se asegurará que las imágenes no se carguen con alfa pre-multiplicado, sino que se carguen con valores de color directos de la imagen. Esto se vería así:

r = get_float_byte();
g = get_float_byte();
b = get_float_byte();
a = get_float_byte();
set_image_pixel(x, y, r, g, b, a);

Para dibujar una imagen así usando mezcla alfa regular, usarías al_set_blender(ALLEGRO_ADD, ALLEGRO_ALPHA, ALLEGRO_INVERSE_ALPHA) para establecer el mezclador correcto. Esto tiene algunas advertencias. Primero, como se mencionó anteriormente, dibujar una imagen así puede resultar en una mezcla de colores menos precisa (al dibujar una imagen con filtrado lineal activado, los bordes serán más oscuros de lo que deberían ser). Segundo, el comportamiento es algo confuso, lo que se explica en el siguiente ejemplo.

// Cargar y crear bitmaps con un canal alfa
al_set_new_bitmap_format(ALLEGRO_PIXEL_FORMAT_ANY_32_WITH_ALPHA);
// Cargar algún bitmap con alfa
bmp = al_load_bitmap("some_alpha_bitmap.png");
// Dibujaremos en este búfer y luego dibujaremos este búfer en la pantalla
tmp_buffer = al_create_bitmap(SCREEN_W, SCREEN_H);
// Establecer el búfer como objetivo y limpiarlo
al_set_target_bitmap(tmp_buffer);
al_clear_to_color(al_map_rgba_f(0, 0, 0, 1));
// Dibujar el bitmap en el búfer temporal
al_draw_bitmap(bmp, 0, 0, 0);
// Finalmente, dibujar el búfer en la pantalla
// La salida se verá incorrecta (puede requerir una inspección cercana
// dependiendo del bitmap; también puede ser muy obvia)
al_set_target_bitmap(al_get_backbuffer(display));
al_draw_bitmap(tmp_buffer, 0, 0, 0);

Para explicarlo mejor, si tienes un píxel con alfa 0.5, y estás usando (ALLEGRO_ADD, ALLEGRO_ALPHA, ALLEGRO_INVERSE_ALPHA) para mezclar, la fórmula es:

a = da * dst + sa * src

Se expande a:

result_a = dst_a * (1-0.5) + 0.5 * 0.5

Por lo tanto, si dibujas la imagen en el búfer temporal, se mezcla una vez resultando en un alfa de 0.75, y luego se dibuja de nuevo en la pantalla, mezclándose de la misma manera, resultando en un píxel con un alfa de 0.1875.

ALLEGRO_KEEP_INDEX
Carga los índices de paleta de archivos .bmp y .pcx de 8 bits en lugar de los colores rgb. Desde 5.1.0.
ALLEGRO_KEEP_BITMAP_FORMAT
Fuerza que el ALLEGRO_BITMAP(3) resultante use el mismo formato que el archivo.

Esto aún no se respeta.

Nota: la librería principal Allegro no soporta ningún formato de archivo de imagen por defecto. Debes usar el addon allegro_image, o registrar tu propio manejador de formato.
