DESCRIPCIÓ

N

ALTER DOMAIN cambia la definición de un dominio existente. Existen varias

subformas:

SET/DROP

DEFAULT
Estas formas establecen o eliminan el valor predeterminado de un dominio. Tenga en cuenta que los valores predeterminados solo se aplican a los comandos INSERT posteriores; no afectan a las filas que ya existen en una tabla que utilice el
dominio.

SET/DROP NOT

NULL
Estas formas cambian si un dominio está marcado para permitir valores NULL o para rechazar valores NULL. Solo puede utilizar SET NOT NULL cuando las columnas que utilizan el dominio no contienen valores
nulos.

ADD restricción_de_dominio [ NOT VALID

]
Esta forma añade una nueva restricción a un dominio. Cuando se añade una nueva restricción a un dominio, todas las columnas que utilizan ese dominio serán comprobadas contra la restricción recién añadida. Estas comprobaciones pueden suprimirse añadiendo la nueva restricción con la opción NOT VALID; la restricción puede hacerse válida más tarde utilizando ALTER DOMAIN ... VALIDATE CONSTRAINT. Las filas insertadas o actualizadas recientemente siempre se comprueban contra todas las restricciones, incluso las marcadas como NOT VALID. NOT VALID solo se acepta para restricciones
CHECK.

DROP CONSTRAINT [ IF EXISTS

]
Esta forma elimina restricciones de un dominio. Si se especifica IF EXISTS y la restricción no existe, no se lanza ningún error. En este caso se emite un aviso en su
lugar.

RENAME

CONSTRAINT
Esta forma cambia el nombre de una restricción de un
dominio.

VALIDATE

CONSTRAINT
Esta forma valida una restricción añadida previamente como NOT VALID, es decir, verifica que todos los valores en las columnas de la tabla del tipo de dominio satisfagan la restricción
especificada.

OWNE

R
Esta forma cambia el propietario del dominio al usuario
especificado.

RENAM

E
Esta forma cambia el nombre del
dominio.

SET

SCHEMA
Esta forma cambia el esquema del dominio. Cualquier restricción asociada con el dominio se mueve también al nuevo
esquema.

Debe ser el propietario del dominio para utilizar ALTER DOMAIN. Para cambiar el esquema de un dominio, también debe tener el privilegio CREATE sobre el nuevo esquema. Para cambiar el propietario, debe poder realizar SET ROLE al nuevo rol propietario, y ese rol debe tener el privilegio CREATE sob

re el esquema del dominio. (Estas restricciones garantizan que cambiar el propietario no haga nada que no podría hacer eli
minando y recreando el dominio. Sin embargo, un superusuario puede cambiar la propiedad de cualquier dominio de todos modos.)

NOTA

S

Aunque ALTER DOMAIN ADD CONSTRAINT intenta verificar que los datos almacenados existentes satisfacen la nueva restricción, esta comprobación no es infalible, porque el comando no puede "ver" las filas de la tabla que se insertan o actualizan recientemente y aún no se han confirmado. Si existe el riesgo de que operaciones concurrentes inserten datos incorrectos, la manera de proceder es añadir la restricción con la opción NOT VALID, confirmar ese comando, esperar hasta que todas las transacciones iniciadas antes de esa confirmación hayan terminado, y luego emitir ALTER DOMAIN VALIDATE CONSTRAINT para buscar datos que violen la restricción. Este método es fiable porque una vez que la restricción se ha confirmado, se garantiza que todas las nuevas transacciones la aplicarán contra nuevos valores del tipo de

dominio.

Actualmente, ALTER DOMAIN ADD CONSTRAINT, ALTER DOMAIN VALIDATE CONSTRAINT, y ALTER DOMAIN SET NOT NULL fallarán si el dominio nombrado o cualquier dominio derivado se utiliza dentro de una columna de tipo contenedor (una columna compuesta, d

e array o de rango) en cualquier tabla de la base de datos. Deberían mejorarse ev
entualmente para poder verificar la nueva restricción para tales valores anidados.

COMPATIBILIDA

D

ALTER DOMAIN se ajusta al estándar SQL, excepto por las variantes OWNER, RENAME, SET SCHEMA y VALIDATE CONSTRAINT, que son

extensiones de PostgreSQL. La cláusula NOT VALID de la vari
