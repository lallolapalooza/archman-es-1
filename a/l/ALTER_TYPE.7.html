DESCRIPCIÓ

N

ALTER TYPE cambia la definición de un tipo existente. Existen varias

subformas:

OWNE

R
Esta forma cambia el propietario del
tipo.

RENAM

E
Esta forma cambia el nombre del
tipo.

SET

SCHEMA
Esta forma mueve el tipo a otro
esquema.

RENAME

ATTRIBUTE
Esta forma solo es utilizable con tipos compuestos. Cambia el nombre de un atributo individual del
tipo.

ADD

ATTRIBUTE
Esta forma añade un nuevo atributo a un tipo compuesto, usando la misma sintaxis que CREATE T
YPE.

DROP ATTRIBUTE [ IF EXISTS

]
Esta forma elimina un atributo de un tipo compuesto. Si se especifica IF EXISTS y el atributo no existe, no se lanza ningún error. En este caso, se emite un aviso en su
lugar.

ALTER ATTRIBUTE ... SET DATA

TYPE
Esta forma cambia el tipo de un atributo de un tipo
compuesto.

ADD VALUE [ IF NOT EXISTS ] [ BEFORE | AFTER

]
Esta forma añade un nuevo valor a un tipo enum. La posición del nuevo valor en el ordenamiento del enum puede especificarse como BEFORE o AFTER uno de los valores existentes. De lo contrario, el nuevo elemento se añade al final de la lista de valores.

Si se especifica IF EXISTS, no es un error si el tipo ya contiene el

nuevo valor: se emite un aviso pero no se realiza ninguna otra acción.
De lo contrario, ocurrirá un error si el nuevo valor ya está presente.

RENAME

VALUE
Esta forma cambia el nombre de un valor de un tipo enum. La posición del valor en el ordenamiento del enum no se ve afectada. Ocurrirá un error si el valor especificado no está presente o si el nuevo nombre ya está
presente.

SET ( property = value [, ... ]

)
Esta forma solo es aplicable a tipos base. Permite el ajuste de un subconjunto de las propiedades del tipo base que pueden establecerse en CREATE TYPE. Específicamente, estas propiedades pueden cambiarse:
•RECEIVE puede establecerse al nombre de una función de entrada binaria, o a NONE para eliminar la función de entrada binaria del tipo. Usar esta opción requiere privilegio de
superusuario.
•SEND puede establecerse al nombre de una función de salida binaria, o a NONE para eliminar la función de salida binaria del tipo. Usar esta opción requiere privilegio de
superusuario.
•TYPMOD_IN puede establecerse al nombre de una función de entrada de modificador de tipo, o a NONE para eliminar la función de entrada de modificador de tipo del tipo. Usar esta opción requiere privilegio de
superusuario.
•TYPMOD_OUT puede establecerse al nombre de una función de salida de modificador de tipo, o a NONE para eliminar la función de salida de modificador de tipo del tipo. Usar esta opción requiere privilegio de
superusuario.
•ANALYZE puede establecerse al nombre de una función de recopilación de estadísticas específica del tipo, o a NONE para eliminar la función de recopilación de estadísticas del tipo. Usar esta opción requiere privilegio de
superusuario.
•SUBSCRIPT puede establecerse al nombre de una función manejadora de subíndices específica del tipo, o a NONE para eliminar la función manejadora de subíndices del tipo. Usar esta opción requiere privilegio de
superusuario.
•STORAGE puede establecerse a plain, extended, external, o main (vea la Sección 66.2 para más información sobre lo que significan estos). Sin embargo, cambiar de plain a otra configuración requiere privilegio de superusuario (porque requiere que las funciones C del tipo todas sean compatibles con TOAST), y cambiar a plain desde otra configuración no está permitido en absoluto (ya que el tipo puede tener valores TOASTeados presentes en la base de datos). Nótese que cambiar esta opción no cambia por sí misma ningún dato almacenado, solo establece la estrategia TOAST por defecto que se usará para las columnas de tabla creadas en el futuro. Vea ALTER TABLE (ALTER_TABLE(7)) para cambiar la estrategia TOAST de columnas de tabla
existentes.

Vea CREATE TYPE (CREATE_TYPE(7)) para más detalles sobre estas propiedades del tipo. Nótese que, cuando sea apropiado, un cambi

o en estas propiedades para un tipo base se propagar
á automáticamente a los dominios basados en ese tipo.

Las acciones ADD ATTRIBUTE, DROP ATTRIBUTE y ALTER ATTRIBUTE pueden combinarse en una lista de múltiples alteraciones para aplicar en paralelo. Por ejemplo, es posible añadir varios atributos y/o alterar el tipo de varios atributos en un solo

comando.

Debes ser el propietario del tipo para usar ALTER TYPE. Para cambiar el esquema de un tipo, también debes tener el privilegio CREATE en el nuevo esquema. Para alterar el propietario, debes poder hacer SET ROLE al nuevo rol propietario, y ese rol debe tener el privilegio CREATE en el esquema del tipo. (Estas restricciones garantizan que alterar

el propietario no hace nada que no podrías hacer eliminando y recreando el tipo. Sin embargo, un superusuario puede alterar la propiedad de cualquier ti
po de todos modos.) Para añadir un atributo o alterar el tipo de un atributo, también debes tener el privilegio USAGE en el tipo de datos del atributo.

NOTA

S

Si ALTER TYPE ... ADD VALUE (la forma que añade un nuevo valor a un tipo enum) se ejecuta dentro de un bloque de transacción, el nuevo valor no puede usarse hasta después de que la transacción haya sido

confirmada.

Las comparaciones que involucran un valor de enum añadido a veces serán más lentas que las comparaciones que involucran solo a miembros originales del tipo enum. Esto generalmente solo ocurrirá si se usa BEFORE o AFTER para establecer la posición de ordenamiento del nuevo valor en algún lugar que no sea el final de la lista. Sin embargo, a veces sucederá aunque el nuevo valor se añada al final (esto ocurre si el contador de OID "dio la vuelta" desde la creación original del tipo enum). La ralentización generalmente es insignificante; pero si importa, se puede recuperar el rendimiento óptimo eliminando y recreandong el tipo enum,

o volcando y restaura
ndo la base de datos.
