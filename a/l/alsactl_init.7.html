NOMBRE

alsactl_init - gestión de control alsa - inicialización

DESCRIPCIÓN

"alsactl init" proporciona una inicialización específica de la tarjeta de sonido.

CONFIGURACIÓN

Todos los archivos de configuración de "alsactl init" se colocan en el directorio /usr/share/alsa/init/. El archivo de configuración de nivel superior es /usr/share/alsa/init/00main. El archivo de nivel superior predeterminado también se puede especificar usando el parámetro -i o --initfile de la herramienta alsactl. Cada archivo consta de un conjunto de líneas de texto. Todas las líneas vacías o las líneas que comienzan con '#' serán ignoradas.

Archivos de reglas

Las reglas de "alsactl init" se leen de los archivos ubicados en /usr/share/alsa/init/*. El archivo de configuración de nivel superior es /usr/share/alsa/init/00main. Cada línea en el archivo de reglas contiene al menos un par clave-valor. Hay dos tipos de claves: claves de coincidencia y claves de asignación. Si todas las claves de coincidencia coinciden con su valor, la regla se aplica y las claves de asignación reciben el valor especificado.

Una regla puede consistir en una lista de uno o más pares clave-valor separados por una coma. Cada clave tiene una operación distinta, dependiendo del operador utilizado. Los operadores válidos son:

==

Comparar por igualdad.

!=

Comparar por desigualdad.

=

Asignar un valor a una clave. Las claves que representan una lista se restablecen y solo se asigna este único valor.

+=

Añadir el valor a una clave que contiene una lista de entradas.

:=

Asignar un valor a una clave de forma definitiva; se prohíben cambios posteriores, lo que puede usarse para evitar cambios por reglas posteriores.

Los siguientes nombres de clave se pueden usar para comparar con las propiedades del dispositivo:

CARDINDEX

Coincide con el índice de la tarjeta del controlador ALSA.

CTL{atributo}

Establecer o probar un atributo de control universal. Atributos posibles:

numid

Identificación numérica del control.

iface, interface

Nombre de la interfaz de control (CARD, HWEDEP, MIXER, PCM, RAWMIDI, TIMER, SEQUENCER)

subdev, subdevice

Número de subdispositivo.

name

Nombre del control

index

Índice del control

type

Tipo de control (BOOLEAN, INTEGER, INTEGER64, ENUMERATED, BYTES, IEC958)

attr, attribute

Atributos (almacenados en una cadena - usar caracteres de coincidencia * y ?):

r

el control es legible

w

el control es escribible

v

el control es volátil

i

el control está inactivo

l

el control está bloqueado

R

el control es TLV legible

W

el control es TLV escribible

C

el control es TLV comandable

o

el proceso es propietario de este control

u

control creado en el espacio de usuario

owner

Número de PID del proceso propietario del control

count

Recuento de valores del control

min

Rango de valores - valor mínimo

max

Rango de valores - valor máximo

step

Rango de valores - valor de paso

dBmin

Rango de valores - valor de dB mínimo

dBmax

Rango de valores - valor de dB máximo

items

Valor enumerado - número de elementos de texto

enums

Valor enumerado - lista de nombres de texto almacenados entre el carácter '|'

value

Valor del control almacenado en una cadena delimitada por comas (,).

do_search

Buscar un control. Se devuelve el valor "1" si se encontró un control. La clave CTL{name} puede contener caracteres de coincidencia * y ?. Un índice de control se puede especificar como primer argumento comenzando desde cero (por ejemplo, CTL{do_search 2}="1").

do_count

Buscar controles y devolver el recuento total de los que coinciden. La clave CTL{name} puede contener caracteres de coincidencia * y ?.

CONFIG{sysfs_device}

La ruta relativa al subsistema sysfs que especifica el directorio raíz de un dispositivo de tarjeta de sonido. Normalmente, debería establecerse en "/class/sound/card$cardinfo{card}/device".

ATTR{nombre_de_archivo}

Coincidir con los valores de los atributos sysfs del dispositivo de tarjeta de sonido. La ruta relativa al árbol sysfs debe definirse mediante la clave CONFIG{sysfs_device}. El espacio en blanco al final de los valores de los atributos se ignora, si el valor de coincidencia especificado no contiene espacio en blanco al final. Dependiendo del tipo de operador, esta clave también se usa para establecer el valor de un atributo sysfs.

ENV{clave}

Coincidir con el valor de una variable de entorno. Se pueden especificar hasta cinco claves ENV por regla. Dependiendo del tipo de operador, esta clave también se usa para exportar una variable al entorno.

PROGRAM

Ejecutar un programa externo. La clave es verdadera si el programa retorna sin el código de salida cero. Todo el entorno del evento está disponible para el programa ejecutado. La salida del programa impresa en stdout está disponible para la clave RESULT.

Hay disponibles varios comandos incorporados:

__ctl_search

Buscar un control. La clave CTL{name} puede contener caracteres de coincidencia * y ?. Un índice de control se puede especificar como primer argumento comenzando desde cero (por ejemplo, PROGRAM="__ctl_search 2").

__ctl_count

Buscar controles y devolver el recuento total de los que coinciden. La clave CTL{name} puede contener caracteres de coincidencia * y ?.

RESULT

Coincidir con la cadena devuelta por la última llamada a PROGRAM. Esta clave se puede usar en la misma regla o en cualquier regla posterior después de una llamada a PROGRAM.

La mayoría de los campos admiten un emparejamiento de patrones al estilo del shell. Se admiten los siguientes caracteres de patrón:

*

Coincide con cero o cualquier número de caracteres.

?

Coincide con cualquier carácter único.

[]

Coincide con cualquier carácter único especificado dentro de los corchetes. Por ejemplo, la cadena de patrón 'tty[SR]' coincidiría con 'ttyS' o 'ttyR'. Los rangos también se admiten dentro de esta coincidencia con el carácter '-'. Por ejemplo, para coincidir con el rango de todos los dígitos, se usaría el patrón [0-9]. Si el primer carácter que sigue a '[' es un '!', se coinciden con todos los caracteres que no estén incluidos.

Las siguientes claves pueden recibir valores asignados:

CTL{numid}, CTL{iface}, CTL{device}, CTL{subdev}, CTL{name}, CTL{index},

Seleccionar el elemento de control universal.

CTL{value}

El valor se establece (escribe) también en el dispositivo de control de la tarjeta de sonido y la clave RESULT se establece en el código de errno. El resultado de la operación de establecimiento es siempre verdadero (lo que significa continuar con la siguiente clave en la línea).

CTL{values}

El valor se establece (escribe) también en el dispositivo de control de la tarjeta de sonido (todos los valores de control se establecen en el valor especificado) y la clave RESULT se establece en el código de errno. El resultado de la operación de establecimiento es siempre verdadero (lo que significa continuar con la siguiente clave en la línea).

CTL{write}

El valor se establece (escribe) también en el dispositivo de control de la tarjeta de sonido (todos los valores de control se establecen en el valor especificado). El resultado de la operación de establecimiento es verdadero cuando la operación tiene éxito (lo que significa continuar con la siguiente clave en la línea).

ENV{clave}

Exportar una variable al entorno. Dependiendo del tipo de operador, esta clave también se usa para comparar con una variable de entorno.

RESULT

Establecer la variable RESULT. Tenga en cuenta que PROGRAM también establece esta variable.

NOMBRE

alsactl_init - alsactl initialization file format

DESCRIPCIÓN

The initialization file contains a list of commands that are executed by alsactl during the device initialization.

COMMANDS

The syntax of the commands is: 

      LABEL[#]* command [arguments]
The command can be preceded by one or more labels. Labels are case-sensitive strings followed by a colon (:). Commands are case-sensitive strings. Arguments are separated by spaces. Comments can be started by a hash character (#). Comments can be on the same line as the command or on a separate line.

The following commands are supported:

PROGRAM

Execute external program. The return code of the program is stored in the $result variable.

RESULT

Store the program result in a variable. The variable is named by the "key" argument.

CTL{key}

Read or write control interface values.

PRIO{key}

Read or write priority values.

CARDINFO{key}

Read card information. The key is the name of the device.

SENDMSG{message}

Send a message to the sound card driver. The message is a comma separated list of values.

SETVAR

Set internal variable. These variables are available for use in rules. It is possible to set only global variables. Setting this variable manually might be useful to change code execution order (included files).

LABEL

Named label where a GOTO can jump to.

GOTO

Jumps to the next LABEL with a matching name. The goto cannot jump backward.

INCLUDE

Include the specified filename or files in specified directory.

When a directory is specified, only the files with the extension ".conf" are read. Also they are read in the alphabetical order. Thus it's highly recommended to use some number prefix (e.g. "01-something.conf") to assure the order of execucions.

ACCESS

Check if specified file or directory exists

CONFIG{sysfs_device}

The relative path to sysfs subsystem specifying the root directory of a soundcard device. Usually, it should be set to "/class/sound/card$cardinfo{card}/device".

PRINT

PRINT value to stdout.

ERROR

PRINT value to stderr.

EXIT

Exit immediately and set program exit code to value (should be integer). If value is "return" string, parser leaves current included file and returns to parent configuration file.

The PROGRAM, RESULT, CTL{value}, PRINT, ERROR, EXIT, CONFIG{} fields support simple printf-like string substitutions. It allows the use of the complete environment set by earlier matching rules. For all other fields, substitutions are applied while the individual rule is being processed. The available substitutions are:

$cardinfo{attribute}, %i{attribute}

See CARDINFO{} for more details.

$ctl{attribute}, %C{attribute}

See CTL{} for more details.

$attr{file}, %s{file}

The value of a sysfs attribute found at the device, where all keys of the rule have matched. If the attribute is a symlink, the last element of the symlink target is returned as the value.

$env{key}, %E{key}

The value of an environment variable.

$result, %c

The string returned by the external program requested with PROGRAM. A single part of the string, separated by a space character may be selected by specifying the part number as an attribute: %c{N}. If the number is followed by the '+' char this part plus all remaining parts of the result string are substituted: %c{N+}

$sysfsroot, %r

Root directory where sysfs file-system is mounted. Ususally, this value is just "/sys".

$config{key}, %g{key}

The value of a configuration variable. See CONFIG{} for more details.

%%

The '%' character itself.

$$

The '$' character itself.

The count of characters to be substituted may be limited by specifying the format length value. For example, '%3s{file}' will only insert the first three characters of the sysfs attribute
