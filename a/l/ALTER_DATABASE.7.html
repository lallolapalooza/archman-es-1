ALTER_DATABASE(7)

Paquete: postgresql

Licencias: PostgreSQL

ALTER DATABASE(7) Documentación de PostgreSQL 18.1 ALTER DATABASE(7)

NOMBRE

ALTER DATABASE - modificar una base de datos

SINOPSIS

ALTER DATABASE nombre [ [ WITH ] opción [ ... ] ]
donde opción puede ser:
    ALLOW_CONNECTIONS allowconn
    CONNECTION LIMIT connlimit
    IS_TEMPLATE istemplate
ALTER DATABASE nombre RENAME TO nuevo_nombre
ALTER DATABASE nombre OWNER TO { nuevo_propietario | CURRENT_ROLE | CURRENT_USER | SESSION_USER }
ALTER DATABASE nombre SET TABLESPACE nuevo_tablespace
ALTER DATABASE nombre REFRESH COLLATION VERSION
ALTER DATABASE nombre SET parámetro_configuración { TO | = } { valor | DEFAULT }
ALTER DATABASE nombre SET parámetro_configuración FROM CURRENT
ALTER DATABASE nombre RESET parámetro_configuración
ALTER DATABASE nombre RESET ALL

DESCRIPCIÓN

ALTER DATABASE cambia los atributos de una base de datos.

La primera forma cambia ciertas configuraciones por base de datos. (Ver más abajo para detalles.) Solo el propietario de la base de datos o un superusuario puede cambiar estas configuraciones.

La segunda forma cambia el nombre de la base de datos. Solo el propietario de la base de datos o un superusuario puede renombrar una base de datos; los propietarios que no son superusuarios también deben tener el privilegio CREATEDB. La base de datos actual no se puede renombrar. (Conéctese a una base de datos diferente si necesita hacer eso.)

La tercera forma cambia el propietario de la base de datos. Para cambiar el propietario, debe poder ejecutar SET ROLE al nuevo rol propietario, y debe tener el privilegio CREATEDB. (Tenga en cuenta que los superusuarios tienen todos estos privilegios automáticamente.)

La cuarta forma cambia el tablespace predeterminado de la base de datos. Solo el propietario de la base de datos o un superusuario puede hacer esto; también debe tener el privilegio de crear para el nuevo tablespace. Este comando mueve físicamente cualquier tabla o índice en el tablespace predeterminado antiguo de la base de datos al nuevo tablespace. El nuevo tablespace predeterminado debe estar vacío para esta base de datos, y nadie puede estar conectado a la base de datos. Las tablas e índices en tablespaces no predeterminados no se ven afectados. El método utilizado para copiar archivos al nuevo tablespace se ve afectado por la configuración de file_copy_method.

Las formas restantes cambian el predeterminado de la sesión para una variable de configuración en tiempo de ejecución para una base de datos PostgreSQL. Cada vez que se inicie una nueva sesión en esa base de datos, el valor especificado se convertirá en el valor predeterminado de la sesión. El predeterminado específico de la base de datos anula cualquier configuración presente en postgresql.conf o que se haya recibido de la línea de comandos de postgres. Solo el propietario de la base de datos o un superusuario puede cambiar los predeterminados de la sesión para una base de datos. Ciertas variables no se pueden configurar de esta manera, o solo pueden ser configuradas por un superusuario.

PARÁMETROS

nombre

El nombre de la base de datos cuyos atributos se van a modificar.

allowconn

Si es falso, nadie puede conectarse a esta base de datos.

connlimit

Cuántas conexiones concurrentes se pueden hacer a esta base de datos. -1 significa sin límite.

istemplate

Si es verdadero, entonces esta base de datos puede ser clonada por cualquier usuario con privilegios CREATEDB; si es falso, entonces solo los superusuarios o el propietario de la base de datos pueden clonarla.

nuevo_nombre

El nuevo nombre de la base de datos.

nuevo_propietario

El nuevo propietario de la base de datos.

nuevo_tablespace

El nuevo tablespace predeterminado de la base de datos.

Esta forma del comando no se puede ejecutar dentro de un bloque de transacción.

REFRESH COLLATION VERSION

Actualiza la versión de la intercalación de la base de datos. Ver Notas para más información.

parámetro_configuración
valor

Establece el valor predeterminado de la sesión de esta base de datos para el parámetro de configuración especificado al valor dado. Si valor es DEFAULT o, de forma equivalente, se utiliza RESET, se elimina la configuración específica de la base de datos, por lo que la configuración predeterminada a nivel de sistema se heredará en nuevas sesiones. Utilice RESET ALL para borrar todas las configuraciones específicas de la base de datos. SET FROM CURRENT guarda el valor actual de la sesión del parámetro como el valor específico de la base de datos.

Consulte SET(7) y el Capítulo 19 para más información sobre los nombres y valores de los parámetros permitidos.

NOTAS

También es posible vincular un valor predeterminado de sesión a un rol específico en lugar de a una base de datos; consulte ALTER ROLE (ALTER_ROLE(7)). La configuración específica del rol anula la específica de la base de datos si hay un conflicto.

EJEMPLOS

Para deshabilitar los escaneos de índices por defecto en la base de datos test:

ALTER DATABASE test SET enable_indexscan TO off;

COMPATIBILIDAD

La sentencia ALTER DATABASE es una extensión de PostgreSQL.

VER TAMBIÉN
