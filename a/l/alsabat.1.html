DESCRIPCIÓ

N

ALSABAT (ALSA Basic Audio Tester) es una utilidad sencilla de línea de comandos destinada a ayudar a automatizar las pruebas del controlador de audio y del servidor de sonido con poca interacción humana. ALSABAT se puede utilizar para probar la calidad del audio, realizar pruebas de estrés de funciones y probar el audio antes y después de cambios en el estado de gestión de energía (PM)

.

El diseño de ALSABAT es relativamente simple. ALSABAT reproduce un flujo de audio y captura el mismo flujo en un lazo de retorno (loopback) digital o analógico. A continuación, compara el flujo capturado con el original utilizando una FFT (Transformada Rápida de Fourier) para determinar si el caso de prueba pasa o

falla.

ALSABAT puede ejecutarse completamente en la máquina de destino que se está probando (modo independiente o standalone) o puede ejecutarse en modo cliente/servidor, donde el cliente alsabat se ejecuta en el objetivo y se ejecuta como servidor en una máquina de prueba separada. El modo cliente/servidor todavía requiere alguna interacción manual para la sincronización, pero esto se está desarrollando activamente para futuras

versiones.

La configuración de pruebas de hardware puede requerir el uso de un cable analógico que conecte las máquinas de destino y de prueba, o un cable para crear un lazo de retorno analógico si no hay un modo de lazo de retorno disponible en el hardware de sonido que se está probando. Se puede usar un cable de lazo de retorno analógico para conectar las clavijas de "entrada de línea" (line in) y "salida de línea" (line out) para crear un lazo de retorno. Si solo están disponibles clavijas de auriculares y micrófono (o una clavija combinada), se puede usar el siguiente circuito simple para crear un lazo de retorno

analógico:

https://source.android.com/devices/audio/loopback.

html

Si tinyalsa está instalado en el sistema, el usuario puede elegir tinyalsa como biblioteca backend de alsabat, con la opción de configuración "--enable-alsabat-backend-tiny

"
.

-

-

Selecciona el dispositivo PCM de

-
f
Formato de muestreo
Los formatos de muestreo reconocidos son: U8 S16_LE S24_3LE S32_LE
Algunos de estos pueden no estar disponibles en el hardware seleccionado
Los atajos de formato disponibles son: 
-f cd (16 bits little endian, 44100, estéreo) [-f S16_LE -c2 -r44100]
-f dat (16 bits little endian, 48000, estéreo) [-f S16_LE -c2 -r48100]
Si no se especifica un formato, se usa
S16_LE.
-
c
El número de canales. El valor predeterminado es un canal. Los valores válidos en el momento son 1
o 2.
-
r
Frecuencia de muestreo en Hertz. La frecuencia predeterminada es 44100 Hertz. Los valores válidos dependen del soporte del
hardware.
-
n
Duración de la señal generada. El valor puede ser cualquiera de las dos formas:
1. Entero decimal, significa número de tramas (frames);
2. Número de punto flotante con el sufijo 's', significa número de segundos.
El valor predeterminado es 2
segundos.
-
k
Valor k sigma para el análisis.
La función de análisis lee datos de un archivo WAV, ejecuta una FFT sobre los datos para obtener la magnitud de los vectores de frecuencia, y luego calcula el valor promedio y la desviación estándar de los vectores de frecuencia. Después de eso, definimos un umbral:
umbral = k * desviación_estándar + valor_medio
Las frecuencias con una amplitud mayor que el umbral serán reconocidas como un pico, y la frecuencia con el valor de pico más grande será reconocida como una frecuencia detectada.
ALSABAT luego compara la frecuencia detectada con la frecuencia objetivo para decidir si la detección pasa o falla.
El valor predeterminado es
3.0.
-
F
Frecuencia objetivo para la generación y el análisis de la señal, en Hertz. El valor predeterminado es 997.0 Hertz. El rango válido es (DC_THRESHOLD, 40% * Frecuencia de muestreo)
.
-
p
Número total de períodos para reproducir o
capturar.
--log
=#
Escribe la salida de stderr y stdout en este archivo de
registro.
--file
=#
Archivo WAV de entrada para la
reproducción.
--saveplay
=#
Archivo WAV de destino para guardar el contenido de la prueba de
captura.
--loc
al
Modo de lazo de retorno interno. Reproducción, captura y análisis internos solo dentro de ALSABAT. Esto está destinado a que los desarrolladores prueben nuevas características de ALSABAT, ya que no se enruta audio fuera de
ALSABAT.
--standalo
ne
Añade soporte para el modo independiente (standalone), donde ALSABAT se ejecutará en una máquina diferente a la que se está probando. En el modo independiente, los datos de sonido se pueden generar, reproducir y capturar como en el modo normal, pero no se analizarán. El ALSABAT compilado sin soporte para libfftw3 siempre está en modo independiente. El ALSABAT en modo normal también puede omitir el análisis de datos usando la opción
"--standalone".
--roundtriplate
ncy
Prueba de latencia de ida y vuelta (round trip). La latencia de audio es el retardo de tiempo a medida que una señal de audio pasa a través de un sistema. Hay muchos tipos de métricas de latencia de audio. Una métrica útil es la latencia de ida y vuelta, que es la suma de la latencia de salida y la latencia de
entrada.
--snr-db
=#
Umbral de detección de ruido en SNR (dB). 26dB indica un 5% de ruido en amplitud. ALSABAT devolverá un error si el SNR de la señal es menor que el
umbral.
--snr-pc
=#
Umbral de detección de ruido en porc
entaje de amplitud de ruido (%). ALS
ABAT devolverá un error si la amplit
ud del ruido es mayor que el umbral.
