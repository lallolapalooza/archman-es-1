al_create_bitmap(3) Manual de Funciones de Biblioteca al_create_bitmap(3)

NOMBRE

al_create_bitmap - API de Allegro 5

SINOPSIS

#include <allegro5/allegro.h>
ALLEGRO_BITMAP *al_create_bitmap(int w, int h)

DESCRIPCIÓN

Crea un nuevo mapa de bits utilizando el formato y las marcas de mapa de bits para el hilo actual. La copia entre mapas de bits de formatos diferentes, o la copia entre mapas de bits de memoria y mapas de bits de pantalla puede ser lenta.

A menos que establezca la marca ALLEGRO_MEMORY_BITMAP, el mapa de bits se crea para la pantalla actual. La copia a otra pantalla puede ser lenta.

Si se crea un mapa de bits de pantalla, puede haber limitaciones en las dimensiones permitidas. Por ejemplo, un backend de DirectX u OpenGL suele tener un tamaño máximo de textura permitido, por lo que si la creación del mapa de bits falla para dimensiones muy grandes, es posible que desee volver a intentarlo con un mapa de bits más pequeño. Algunas plataformas también dictan un tamaño mínimo de textura, que es relevante si planea usar este mapa de bits con el complemento de primitivas. Si intenta crear un mapa de bits más pequeño que este, esta llamada no fallará, pero el mapa de bits devuelto será una sección de un mapa de bits más grande con el tamaño mínimo. El tamaño mínimo que funcionará en todas las plataformas es de 32 por 32. Hay un interruptor experimental para desactivar este relleno editando la configuración del sistema (consulte la clave min_bitmap_size en al_get_system_config(3)).

Algunas plataformas no admiten directamente mapas de bits de pantalla cuyas dimensiones no sean potencias de dos. Allegro maneja esto creando un mapa de bits más grande con dimensiones que son potencias de dos y luego devolviendo una sección de ese mapa de bits con las dimensiones que solicitó. Esto puede ser relevante si planea usar este mapa de bits con el complemento de primitivas, pero no debería ser un problema de lo contrario.

Si crea un mapa de bits sin que ALLEGRO_MEMORY_BITMAP esté configurado, pero no hay una pantalla actual, se creará un mapa de bits de memoria temporal en su lugar. Más tarde puede convertir todos esos mapas de bits a mapas de bits de video y asignarlos a una pantalla llamando a al_convert_memory_bitmaps(3).

En algunas plataformas, el contenido de los mapas de bits de video puede perderse cuando su aplicación pierde el foco. Allegro tiene un mecanismo interno para restaurar el contenido de estos mapas de bits de video, pero no es infalible (a veces el contenido de los mapas de bits puede perderse permanentemente) y tiene implicaciones de rendimiento. Si está utilizando un mapa de bits como un búfer intermedio, este mecanismo puede ser ineficiente. En ese caso, si no desea que Allegro administre el contenido del mapa de bits por usted, puede desactivar este mecanismo creando el mapa de bits con la marca ALLEGRO_NO_PRESERVE_TEXTURE. El contenido del mapa de bits se pierde cuando recibe los eventos ALLEGRO_EVENT_DISPLAY_LOST y ALLEGRO_EVENT_DISPLAY_HALT_DRAWING y debería restaurarse cuando recibe el evento ALLEGRO_EVENT_DISPLAY_FOUND y cuando llama a al_acknowledge_drawing_resume(3) (después del evento ALLEGRO_EVENT_DISPLAY_RESUME_DRAWING). Puede usar esos eventos para implementar su propio mecanismo de restauración de contenido de mapas de bits si el de Allegro no funciona lo suficientemente bien para usted (por ejemplo, puede recargarlos todos desde el disco).

Nota: El contenido de un mapa de bits recién creado no está definido; debe borrar el mapa de bits o asegurarse de que todos los píxeles se sobrescriban antes de dibujarlo.

Cuando haya terminado de usar el mapa de bits, debe llamar a al_destroy_bitmap(3) para liberar cualquier recurso asignado para él.
