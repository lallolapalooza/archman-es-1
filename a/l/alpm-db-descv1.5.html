alpm-db-desc - Formato de archivo para la representación de metadatos de paquetes basados en ALPM (versión

1)
.

DESCRIPCIÓ

N

El formato alpm-db-desc es un formato de texto que representa los metadatos de un solo paquete. Cada archivo describe varias propiedades de un paquete, incluyendo su nombre, versión, dependencias, tamaño, información de licencia, y más. Para una lista completa de propiedades, consulte secciones

.

Un sistema operativo que depende de Arch Linux Package Management mantiene una base de datos local de libalpm con un archivo alpm-db-desc por paquete, cada uno nombrado desc y ubicado en un directorio único, por

paquete.

La acumulación de todos los archivos alpm-db-desc en una base de datos de libalpm describe el estado actual del sistema (es decir, qué paquetes se han instalado cuándo, bajo qué circunstancias). Más específicamente, el software de gestión de paquetes como pacman y herramientas relacionadas usan este formato de archivo, por ejemplo, para resolver dependencias y para mostrar información de

paquetes.

Los datos en un archivo alpm-db-desc se derivan de un alpm-package. Aquí, la mayoría de los metadatos provienen de los datos PKGINFO del

paquete.

El formato de archivo alpm-db-desc no debe confundirse con el formato de archivo alpm-repo-desc, que se usa en el contexto de una alpm-repo-db y lleva un conjunto diferente de metadatos, pero generalmente también se llama desc

.

El formato alpm-db-desc existe en múltiples versiones. Este documento describe la versión 1, que es una versión legada y ha estado disponible desde el lanzamiento de pacman 5.1.0 el 2018-05-28. Para la última especificación, consulte alpm-db-desc

.

Formato

General

Un archivo alpm-db-desc es un archivo delimitado por saltos de línea y codificado en UTF-8 que consta de una serie de secciones

.

Cada sección comienza con una línea de encabezado de sección única. La línea de encabezado de sección va seguida de una o más líneas con un valor específico de la sección cada una. Todos los valores específicos de la sección deben consistir en caracteres ASCII imprimibles[1] a menos que se indique lo contrario. Una sección termina cuando se encuentra otra línea de encabezado de sección o se alcanza el final del

archivo.

Las líneas vací

as entre seccio
nes se ignoran.

Seccione

s

Cada línea de encabezado de sección contiene el nombre de la sección en mayúsculas, rodeado de signos de porcentaje (por ejemplo, %NAME%). Los nombres de sección sirven como clave para cada valor específico de l

a sección.

Cada sección permite un solo valor específico de la sección, siguiendo la línea de encabezado de sección. Como excepción a esta regla, las secciones %LICENSE%, %GROUPS%, %DEPENDS%, %OPTDEPENDS%, %REPLACES%, %CONFLICTS% y %PROVIDES% pueden tener más de un valor específico

de la
sección.

%NAME

%

Un alpm-package-name, que representa el nombre de un paquete (por ejemplo, exam

ple
).

%VERSION

%

Un alpm-package-version (completo o completo con época) que representa la versión de un paquete (por ejemplo, 1.0-

1
).

%BASE

%

Un alpm-package-base que representa la base del paquete del cual proviene un paquete. El valor puede ser el mismo que el de la sección %NAM

E
%.

%DESC

%

La descripción del paquete. El valor es una cadena UTF-8, de cero o más caracteres de longitud (por ejemplo, Un proyecto usad

o para
algo).

%URL

%

La URL del proyecto del paquete. El valor es una URL válida o una cadena vacía (por ejemplo, https://ex

ample.
org).

%ARCH

%

La arquitectura del paquete (consulte alpm-architecture para más información). El valor debe estar cubierto por el conjunto de caracteres alfanuméricos y ‘_‘ (por ejemplo, x86_64 o an

y)
.

%BUILDDATE

%

La fecha en la que comenzó la compilación del paquete. El valor debe ser numérico y representar los segundos desde la época, también conocido como ‘tiempo Unix’ (por ejemplo, 172918

172
6).

%INSTALLDATE

%

La fecha en la que el paquete se instaló en el sistema. El valor debe ser numérico y representar los segundos desde la época, también conocido como ‘tiempo Unix’ (por ejemplo, 172918

172
6).

%PACKAGER

%

El ID de usuario de la entidad que compiló el paquete. El valor está destinado a ser usado para búsquedas de identidad y representa un ID de usuario OpenPGP[2]. Como tal, el valor es una cadena codificada en UTF-8, que convencionalmente se compone de un nombre y una dirección de correo electrónico, lo que se alinea con el formato descrito en RFC 28223

.

%SIZE

%

El tamaño opcional del contenido del paquete (sin comprimir y sin empaquetar) en bytes. El valor es un entero no negativo que representa el tamaño absoluto del contenido del paquete, con múltiples archivos enlazados de forma dura contados solo una vez (por ejemplo, 181849963). Si el paquete no tiene tamaño (por ejemplo, porque es un alpm-meta-package) la

sección se
omite.

%GROUPS

%

Un alpm-package-group que denota un grupo de distribución en el que se encuentra el paquete. Los valores pueden estar presentes una o más veces. Si el paquete no está en un grupo, la sección se

omite.

El valor está representado por una cadena UTF-8. Aunque es posible usar una cadena UTF-8, se recomienda encarecidamente confiar en el formato alpm-package-name para el valor en su lugar, ya que los gestores de paquetes

pueden usar un grupo de paquetes para i
nstalar un grupo entero de paquetes.

%REASON

%

Un valor opcional que representa la razón por la que el paquete está instalado. El valor debe ser un entero no

negativo:
  • 0: Instalado
    • explícitamente
  • 1: Instalado com
    • o una dep
endencia

Si el paquete está instalado explícitamente (valor 0), la secci

ón se
omite.

%LICENSE

%

Un conjunto opcional de identificadores de licencia que aplican al paquete. Los valores pueden estar presentes una o más veces. Si no hay identificador de licencia, la sección se

omite.

Cada valor representa un identificador de licencia, que es una cadena de longitud no cero (por ejemplo, GPL). Aunque no se imponen restricciones específicas para el valor aparte de su longitud, se recomienda encarecidamente confiar en expresiones de licencia SPDX (por ejemplo, GPL-3.0-or-later o Apache-2.0 OR MIT). Consulte Lista de Licencias SPDX[

4] para más
información.

%VALIDATION

%

El método de validación utilizado durante la instalación del paquete asegurando su autenticidad. El valor debe ser uno de los

siguientes:
  • none: La integridad y autenticidad del paquete no se
    • valida.
  • md5: El paquete se valida contra un resumen de hash MD-5 que acompaña en una alpm-repo-db que pertenece al repositorio desde el cual se instala el
    • paquete.
  • sha256: El paquete se valida contra unnying SHA-256 hash digest in the alpm-repo-db that belongs to the repository from which the package is
    • installed.
  • pgp: The package’s authenticity and integrity is validated using a detached OpenPGP signature[5] and a system-wide collection of OpenPGP ce
    • rtif
icate
s[6].

%REPLACES

%

Another virtual component or package, that the package replaces upon installation. Values may be present one or more times. If the package does not replace anything, the section is omitted. The value is an alpm-package-relation of type replacement (e.g. example or example=1.0.

0)
.

%DEPENDS

%

A run-time dependency of the package (virtual component or package). Values may be present one or more times. If the package has no run-time dependency, the section is omitted. The value is an alpm-package-relation of type run-time dependency (e.g. example or example=1.0.

0)
.

%OPTDEPENDS

%

An optional dependency of the package (virtual component or package). Values may be present one or more times. If the package has no optional dependency, the section is omitted. The value is an alpm-package-relation of type optional dependency (e.g. example or example: this is

a descr
iption).

%

Another virtual component or package, that the package conflicts with. Values may be present one or more times. If the package does not conflict with anything, the section is omitted. The value is an alpm-package-relation of type conflict (e.g. example or example=1.0.

0)
.

%PROVIDES

%

Another virtual component or package, that the package provides. Values may be present one or more times. If the package does not provide anything, the section is omitted. The value is an alpm-package-relation of type provision (e.g. example or exampl
