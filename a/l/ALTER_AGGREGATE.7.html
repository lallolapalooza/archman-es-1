ALTER_AGGREGATE(7)

Paquete: postgresql

Licencias: PostgreSQL

ALTER AGGREGATE(7) Documentación de PostgreSQL 18.1 ALTER AGGREGATE(7)

NOMBRE

ALTER_AGGREGATE - cambia la definición de una función agregada

SINOPSIS

ALTER AGGREGATE nombre ( firma_agregada ) RENAME TO nuevo_nombre
ALTER AGGREGATE nombre ( firma_agregada )
                OWNER TO { nuevo_propietario | CURRENT_ROLE | CURRENT_USER | SESSION_USER }
ALTER AGGREGATE nombre ( firma_agregada ) SET SCHEMA nuevo_esquema
donde firma_agregada es:
* |
[ modo_arg ] [ nombre_arg ] tipo_arg [ , ... ] |
[ [ modo_arg ] [ nombre_arg ] tipo_arg [ , ... ] ] ORDER BY [ modo_arg ] [ nombre_arg ] tipo_arg [ , ... ]

DESCRIPCIÓN

ALTER AGGREGATE cambia la definición de una función agregada.

Debes ser propietario de la función agregada para usar ALTER AGGREGATE. Para cambiar el esquema de una función agregada, también debes tener el privilegio CREATE en el nuevo esquema. Para cambiar el propietario, debes poder ejecutar SET ROLE al nuevo rol propietario, y ese rol debe tener el privilegio CREATE en el esquema de la función agregada. (Estas restricciones garantizan que la alteración del propietario no haga nada que no pudieras hacer eliminando y recreando la función agregada. Sin embargo, un superusuario puede alterar la propiedad de cualquier función agregada de todos modos).

PARÁMETROS

nombre

El nombre (opcionalmente calificado por el esquema) de una función agregada existente.

modo_arg

El modo de un argumento: IN o VARIADIC. Si se omite, el valor predeterminado es IN.

nombre_arg

El nombre de un argumento. Ten en cuenta que ALTER AGGREGATE en realidad no presta atención a los nombres de los argumentos, ya que solo los tipos de datos de los argumentos son necesarios para determinar la identidad de la función agregada.

tipo_arg

Un tipo de dato de entrada sobre el cual opera la función agregada. Para referenciar una función agregada de cero argumentos, escribe * en lugar de la lista de especificaciones de argumentos. Para referenciar una función agregada de conjunto ordenado, escribe ORDER BY entre las especificaciones de argumentos directos y agregados.

nuevo_nombre

El nuevo nombre de la función agregada.

nuevo_propietario

El nuevo propietario de la función agregada.

nuevo_esquema

El nuevo esquema para la función agregada.

NOTAS

La sintaxis recomendada para referenciar un conjunto ordenado agregado es escribir ORDER BY entre las especificaciones de argumentos directos y agregados, en el mismo estilo que en CREATE AGGREGATE. Sin embargo, también funcionará omitir ORDER BY y simplemente unir las especificaciones de argumentos directos y agregados en una sola lista. En esta forma abreviada, si se usó VARIADIC "any" tanto en la lista de argumentos directos como en la agregada, escribe VARIADIC "any" solo una vez.

EJEMPLOS

Para renombrar la función agregada myavg para el tipo integer a my_average:

ALTER AGGREGATE myavg(integer) RENAME TO my_average;

Para cambiar el propietario de la función agregada myavg para el tipo integer a joe:

ALTER AGGREGATE myavg(integer) OWNER TO joe;

Para mover el conjunto ordenado agregado mypercentile con argumento directo de tipo float8 y argumento agregado de tipo integer al esquema myschema:

ALTER AGGREGATE mypercentile(float8 ORDER BY integer) SET SCHEMA myschema;

Esto también funcionará:

ALTER AGGREGATE mypercentile(float8, integer) SET SCHEMA myschema;

COMPATIBILIDAD

No existe la sentencia ALTER AGGREGATE en el estándar SQL.

VER TAMBIÉN
