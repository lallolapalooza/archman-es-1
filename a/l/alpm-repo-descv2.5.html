(5) Manual de Formatos de Archivo (5)

NOMBRE

alpm-repo-desc - Formato de archivo para la representación de metadatos de paquetes basados en ALPM en repositorios de paquetes (versión 2).

DESCRIPCIÓN

El alpm-repo-desc es un formato textual que representa los metadatos de un paquete individual en una versión específica en un repositorio. Cada archivo describe varias propiedades de un alpm-package , incluyendo su nombre, versión, dependencias, tamaño, información de licencia y más. Para una lista completa de propiedades, consulte sus secciones.

La acumulación de todos los archivos alpm-repo-desc en una alpm-repo-db describe el estado actual del repositorio (es decir, qué paquetes están disponibles en qué versión).

Un sistema operativo que depende de Arch Linux Package Management (Gestión de Paquetes de Arch Linux) mantiene uno o más archivos alpm-repo-db , los cuales contienen cada uno un archivo alpm-repo-desc por paquete, cada uno nombrado desc y ubicado en un directorio único por paquete. Más específicamente, el software de gestión de paquetes como pacman y herramientas relacionadas utilizan este formato de archivo, por ejemplo, para resolver dependencias y mostrar información del paquete de archivos alpm-package en repositorios.

Los datos en un archivo alpm-repo-desc se derivan de un alpm-package. Gran parte de sus metadatos proviene de los datos PKGINFO del paquete. Un archivo alpm-repo-desc es generalmente creado por software que gestiona un alpm-repo, como repo-add.

El formato de archivo descrito en este documento no debe confundirse con el formato de archivo alpm-db-desc , que se utiliza en el contexto de una base de datos libalpm y contiene un conjunto diferente de metadatos, pero que generalmente también se llama desc.

El formato alpm-repo-desc existe en múltiples versiones. La información en este documento es para la versión 2, que es la versión actual y se introdujo con el lanzamiento de pacman 6.1.0 el 2024-03-04.

Formato general

Un archivo alpm-repo-desc es un archivo codificado en UTF-8, delimitado por saltos de línea, que consta de una serie de secciones.

Cada sección comienza con una línea de encabezado de secciónúnica. La línea de encabezado de sección va seguida de una o más líneas con un valor específico de la sección cada una. Todos los valores específicos de la sección deben consistir en caracteres ASCII imprimibles[1] a menos que se indique lo contrario. Una sección termina cuando se encuentra otra línea de encabezado de sección o se alcanza el final del archivo.

Las líneas vacías entre secciones se ignoran.

Cambios desde la última versión

La sección %MD5SUM% ha sido eliminada. La sección %PGPSIG% se ha hecho opcional.

Secciones

Cada línea de encabezado de sección contiene el nombre de la sección en mayúsculas, rodeado de signos de porcentaje (por ejemplo, %NAME%). Los nombres de sección sirven como clave para cada valor específico de la sección.

Cada sección permite un solo valor específico de la sección, siguiendo la línea de encabezado de sección. Como excepción a esta regla, las secciones %LICENSE%, %GROUPS%, %CHECKDEPENDS%, %DEPENDS%, %OPTDEPENDS%, %REPLACES%, %CONFLICTS% y %PROVIDES% pueden tener más de un valor específico de la sección.

%FILENAME%

El nombre de archivo del alpm-package (por ejemplo, example-1.2.3-any.pkg.tar.zst).

%NAME%

Un alpm-package-name, que representa el nombre de un paquete (por ejemplo, example).

%BASE%

Un alpm-package-base que representa la base del paquete del cual proviene un paquete. Si un paquete no es un alpm-split-package, el valor es el mismo que el de la sección %NAME% . Si un paquete es un alpm-split-package, el valor puede ser diferente al de la sección %NAME% .

%VERSION%

Un alpm-package-version (completo o completo con época) que representa la versión de un paquete (por ejemplo, 1.0-1).

%DESC%

La descripción del paquete. El valor es una cadena UTF-8, de cero o más caracteres de longitud (por ejemplo, A project used for something).

%GROUPS%

Un alpm-package-group que denota un grupo de distribución en el que se encuentra el paquete. Puede haber uno o más valores. Si el paquete no está en un grupo, la sección se omite.

El valor está representado por una cadena UTF-8. Aunque es posible usar una cadena UTF-8, se recomienda encarecidamente confiar en el formato alpm-package-name para el valor, ya que los gestores de paquetes pueden usar un grupo de paquetes para instalar un grupo entero de paquetes.

%CSIZE%

El tamaño del alpm-package comprimido en bytes. El valor es un entero no negativo (por ejemplo, 1818463).

%ISIZE%

El tamaño del contenido del paquete (descomprimido y desempaquetado) en bytes. El valor es un entero no negativo que representa el tamaño absoluto del contenido del paquete, contando los archivos con múltiples enlaces duros solo una vez (por ejemplo, 181849963).

%SHA256SUM%

El resumen hash SHA-256[3] del archivo alpm-package . La cadena consta de 64 caracteres hexadecimales (por ejemplo, b5bb9d8014a0f9b1d61e21e796d78dccdf1352f23cd32812f4850b878ae4944c).

%PGPSIG%

La firma OpenPGPbase64 [4] para el archivoopcional codificada en alpm-package (por ejemplo, iHUEABYKAB0WIQRizHP4hOUpV7L92IObeih9mi7GCAUCaBZuVAAKCRCbeih9mi7GCIlMAP9ws/jU4f580ZRQlTQKvUiLbAZOdcB7mQQj83hD1Nc/GwD/WIHhO1/OQkpMERejUrLo3AgVmY3b4/uGhx9XufWEbgE=). La herramienta para crear el archivo alpm-repo-desc puede optar por no incluir la representación de la firma, en cuyo caso la sección se omite.

%URL%

La URL del proyecto del paquete. El valor es una URL válida o una cadena vacía (por ejemplo, https://example.org).

%LICENSE%

Un conjunto opcional de identificadores de licencia que se aplican al paquete. Puede haber uno o más valores. Si no hay identificador de licencia, la sección se omite.

Cada valor representa un identificador de licencia, que es una cadena de longitud no cero (por ejemplo, GPL). Aunque no se imponen restricciones específicas para el valor aparte de su longitud, se recomienda encarecidamente confiar en las expresiones de licencia SPDX (por ejemplo, GPL-3.0-or-later o Apache-2.0 OR MIT). Consulte la SPDX License List[6] para más información.

%ARCH%

La arquitectura del paquete (consulte alpm-architecture para más información). El valor debe estar cubierto por el conjunto de caracteres alfanuméricos y ‘_‘ (por ejemplo, x86_64 o any).

%BUILDDATE%

La fecha en la que comenzó la compilación del paquete. El valor debe ser numérico y representar los segundos desde la época, también conocido como ‘tiempo Unix’ (por ejemplo, 1729181726).

%PACKAGER%

El ID de usuario de la entidad que construyó el paquete. El valor está destinado a ser utilizado para búsquedas de identidad y representa un ID de usuario de OpenPGP[7]. Como tal, el valor es una cadena codificada en UTF-8, que se compone convencionalmente de un nombre y una dirección de correo electrónico, lo que se ajusta al formato descrito en RFC 28228.

%REPLACES%

Otro componente virtual o paquete, que el paquete reemplaza al instalarse. Puede haber uno o más valores. Si el paquete no reemplaza nada, la sección se omite. El valor es una alpm-package-relation de tipo replacement (por ejemplo, example o example=1.0.0).

%CONFLICTS%

Otro componente virtual o paquete, con el que el paquete entra en conflicto. Puede haber uno o más valores. Si el paquete no entra en conflicto con nada, la sección se omite. El valor es una alpm-package-relation de tipo conflict (por ejemplo, example o example=1.0.0).

%PROVIDES%

Otro componente virtual o paquete, que el paquete proporciona. Puede haber uno o más valores. Si el paquete no proporciona nada, la sección se omite. El valor es una alpm-package-relation de tipo provision (por ejemplo, example o example=1.0.0).

%DEPENDS%

Una dependencia en tiempo de ejecución del paquete (componente virtual o paquete). Puede haber uno o más valores. Si el paquete no tiene ninguna dependencia en tiempo de ejecución, la sección se omite. El valor es una alpm-package-relation de tipo run-time dependency (por ejemplo, example o example=1.0.0).

%OPTDEPENDS%

Una dependencia opcional del paquete (componente virtual o paquete). Puede haber uno o más valores. Si el paquete no tiene ninguna dependencia opcional, la sección se omite. El valor es una alpm-package-relation de tipo optional dependency (por ejemplo, example o example: this is a description).

%MAKEDEPENDS%

Una dependencia para compilar el software upstream del paquete. Puede haber uno o más valores. Si el paquete no tiene ninguna dependencia de compilación, la sección se omite. El valor es una alpm-package-relation de tipo build dependency (por ejemplo, example o example=1.0.0).

%CHECKDEPENDS%

Una dependencia para ejecutar las pruebas del proyecto upstream del paquete. Puede haber uno o más valores. Si el paquete no tiene ninguna dependencia de prueba, la sección se omite. El valor es una alpm-package-relation de tipo test dependency (por ejemplo, example o example=1.0.0).
