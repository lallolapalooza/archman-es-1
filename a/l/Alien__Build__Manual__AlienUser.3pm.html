N

Este documento está destinado a un usuario de un módulo Alien basado en Alien::Base. Aunque está orientado específicamente a subclases de Alien::Base, puede contener algunas indicaciones útiles para Alien en

general.

Ejemplos completos y funcionales de cómo usar un módulo Alien también se incluyen con Alien::Build en el directorio "example/user" de la distribución. Esos ejemplos usan Alien::xz, que utiliza alienfile + Alien::Build + Alien::

Base.

La siguiente documentación asumirá que estás intentando usar un Alien llamado "Alien::Foo" que proporciona la biblioteca "libfoo" y la herramienta de línea de comandos "foo". Muchos Aliens solo proporcionarán una u

otra.

La mejor interfaz para usar aliens basados en Alien::Base es Alien::Base::Wrapper. Esto te permite combinar múltiples aliens juntos y maneja una serie de casos borde oscuros que usar Aliens directamente no maneja. Además, a partir de la versión 0.64, Alien::Base::Wrapper viene incluido con Alien::Build y Alien::Base de todos modos, por lo que no es una dependencia

adicional.

A continuación se presentan los casos de uso

principales.

ExtUtils::

MakeMaker 
use ExtUtils::MakeMaker;
use Alien::Base::Wrapper ();

WriteMakefile(
  Alien::Base::Wrapper->new('Alien::Foo')->mm_args2(
    NAME => 'FOO::XS',
    ...
  ),
)
;

Alien::Base::Wrapper tomará un hash de argumentos de "WriteMakefile" e insertará los indicadores de compilación y enlace apropiados por ti. Esto se recomienda sobre hacerlo tú mismo, ya que la invocación exacta para hacer que EUMM funcione es difícil de

acertar.

El método "mm_args2" también establecerá tu "CONFIGURE_REQUIRES" para Alien::Base::Wrapper, ExtU

tils::MakeMaker y cualqui
er alien que especifiques.

Module::

Build 
use Module::Build;
use Alien::Base::Wrapper qw( Alien::Foo !export );
use Alien::Foo;

my $build = Module::Build->new(
  ...
  configure_requires => {
    'Alien::Base::Wrapper' => '0',
    'Alien::Foo'           => '0',
    ...
  },
  Alien::Base::Wrapper->mb_args,
  ...
);

$build->create_build_script
;

Para Module::Build también puedes usar Alien::Base::Wrapper, pero tendrás que especificar el "configure_requ

ires" t
ú mismo.

FFI::

Platypus

Requiere "Alien::Foo"

siempre: 
use FFI::Platypus;
use Alien::Foo;

my $ffi = FFI::Platypus->new(
  lib => [ Alien::Foo->dynamic_libs ],
)
;

Usa "Alien::Foo" en modo de

respaldo: 
use FFI::Platypus;
use FFI::CheckLib 0.28 qw( find_lib_or_die );
use Alien::Foo;

my $ffi = FFI::Platypus->new(
  lib => [ find_lib_or_die lib => 'foo', alien => ['Alien::Foo'] ],
)
;

Si vas a requerir siempre un Alien, puedes simplemente llamar a "dynamic_libs" y pasarlo al método lib de FFI::Platypus. Deberías considerar usar FFI::CheckLib para usar el Alien en modo de respaldo en su lugar. De esta manera solo necesitas instalar el Alien si el sistema no lo

proporciona.

Para que el modo de respaldo func

ione correctamente, necesitas us
ar FFI::CheckLib 0.28 o superior.

ENTORN

O
ALIEN_INSTALL_T
YPE
Aunque la forma recomendada para que un consumidor use un Alien basado en Alien::Base es declararlo como una dependencia estática de configuración y compilación, algunos consumidores pueden preferir recurrir a usar un Alien solo cuando el propio consumidor no puede detectar el paquete necesario. En algunos casos, el consumidor puede querer que el usuario opte por usar un Alien antes de requerirlo.

Para mantener la interfaz consistente entre los Aliens, el consumidor del Alien de respaldo con opt-in puede recurrir al Alien si la variable de entorno "ALIEN_INSTALL_TYPE" está establecida a cualquier valor. La razón es que al establecer esta variable de entorno, el usuario es consciente de que los módulos Alien pueden instalarse y ha indicado su consentimiento. La implementación real de esto, por su naturaleza, tendría que estar en el módulo CPAN

consumidor.

Este comportamiento debería documentarse en el POD del

consumidor.
