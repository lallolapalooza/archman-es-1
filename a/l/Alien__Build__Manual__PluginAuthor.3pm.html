Pseudocódigo estilo Perl sobre cómo se llaman los

plugins: 
my $probe;
my $override = override();

if($override eq 'system') {

  $probe = probe();

  if($probe ne 'system') {
    die 'system tool or library not found';
  }

}

elsif($override eq 'default') {
  $probe = probe();

} else { # $override eq 'share'
  # note that in this instance the
  # probe hook is never called
  $probe = 'share';
}

if($probe eq 'system') {
  gather_system();

} else { # $probe eq 'share'

  download();
  extract();
  patch();
  build();
  gather_share();

  # Check to see if there isa build_ffi hook
  if(defined &build_ffi) {
    patch_ffi();
    build_ffi();
    gather_ffi();
  }
}

# By default this just returns the value of $ENV{ALIEN_INSTALL_TYPE}
sub override {
  return $ENV{ALIEN_INSTALL_TYPE};
}

# Default download implementation; can be
# replaced by specifying a different download
# hook.  See Alien::Build::Plugin::Core::Download
# for detailed implementation.
sub download {

  my $response = fetch();

  if($response->{type} eq 'html' || $response->{type} eq 'dir_listing') {
    # decode will transform an HTML listing (html) or a FTP directory
    # listing (dir_listing) into a regular list
    $response = decode($response);
  }

  if($response->{type} eq 'list') {

    # prefer will filter bad entries in the list
    # and sort them so that the first one is
    # the one that we want
    $response = prefer($response);

    my $first_preferred = $res->{list}->[0];

    # prefer can sometimes infer the version from the
    # filename.
    if(defined $first_preferred->{version}) {
      # not a hook
      runtime_prop->{version} = $first_preferred->{version};
    }

    $response = fetch($first_preferred);

  }

  if($response->{type} eq 'file') {
    # not a hook
    write_file_to_disk $response;
  }
}

DESCRIPCIÓ

N

Este documento explica cómo escribir plugins de Alien::Build usando la clase base Alien::Build::

Plugin.

Escribir

plugins

Los plugins usan Alien::Build::Plugin, que establece la clase base apropiada y te proporciona el constructor de propiedades "has". "has" toma dos argumentos, el nombre de la propiedad y el valor por defecto. (Al igual que con Moose y Moo, deberías usar una referencia a código para especificar valores por defecto que no sean cadenas). No establezcas esto directamente como la clase base de tu

plugin: 
use parent qw( Alien::Build::Plugin );  # wrong
use Alien::Build::Plugin;               #
right

El único método que necesitas implementar es "init". Desde este método puedes añadir hooks para cambiar el comportamiento de la receta del alienfile. Este es un ejemplo muy simple de un hook de sondeo (probe), con la lógica real del sondeo

eliminada: 
sub init
{
  my($self, $meta) = @_;
  $meta->register_hook(
    probe => sub {
      my($build) = @_;
      if( ... )
      {
        return 'system';
      }
      else
      {
        return 'share';
      }
    },
  );
}

Los hooks reciben la instancia de Alien::Build

como su primer argumento y, dependiendo de
l hook, pueden recibir argumentos adicionales.

Modificar

hooks

También puedes modificar hooks usando "before_hook", "around_hook" y "after_hook", de manera similar a los modificadores de

Moose: 
sub init
{
  my($self, $meta) = @_;

  $meta->before_hook(
    build => sub {
      my($build) = @_;
      $build->log('this runs before the build');
    },
  );

  $meta->after_hook(
    build => sub {
      my($build) = @_;
      $build->log('this runs after the build');
    },
  );

  $meta->around_hook(
    build => sub {
      my $orig = shift;

      # around hooks are useful for setting environment variables
      local $ENV{CPPFLAGS} = '-I/foo/include';

      $orig->(@_);
    },
  );
}

plugins

ejemplo: 
use Test::V0;

  use alienfile;

    ar
g1 => 'override for arg1', arg2 => [ 'something', 'else' ], ); ... }; # you can interrogate $build, it is an ins
tance of L<Alien::Build>. my $alien = alien_build_ok; # you can interrogate $alien, it is an instance of L<Alien::Base>.

Plugins

negociadores

Un plugin negociador (Negotiator) normalmente no implementa nada por sí mismo, sino que elige el mejor plugin para lograr un objetivo

particular.

El plugin "mejor" puede variar en algunos casos dependiendo de la plataforma o de las herramientas disponibles. Por ejemplo, el negociador de descarga podría elegir usar el plugin de obtención (fetch) que depende del comando de línea "curl", o podría elegir el plugin de obtención que depende del módulo de Perl HTTP::Tiny, dependiendo de la plataforma y de lo que ya esté instalado. (Para que cualquiera de los dos sea útil, tienen que soportar SSL)

.

Por convención, el plugin negociador se nombra algo como "Alien::Build::Plugin::*::Negotiate", pero normalmente se invoca sin el sufijo "::Negotiate". Por

ejemplo: 
plugin 'Download'; # is short for Alien::Build::Plugin::Download::
Negotiator

Aquí tienes un ejemplo simple de un negociador que elige "curl" si ya está instalado y HTTP::Tiny en caso contrario. (El plugin de descarga real es mucho más inteligente y complicado que esto, pero este es un buen ejemplo simplificado)

. 
package Alien::Build::Plugin::Download::Negotiate;

use strict;
use warnings;
use Alien::Build::Plugin;
use File::Which qw( which );

sub init
{
  my($self, $meta) = @_;

  if(which('curl')) {
    $meta->apply_plugin('Fetch::Curl');
  } else {
    $meta->apply_plugin('Fetch::HTTPTiny');
  }
}

Hook

s

El resto de este documento es una referencia de los hooks que puedes registrar. En general, puedes registrar cualquier hook

que desees, pero se debe tener cuidado, ya que algunos hooks tienen un comportamiento por defecto que se anulará cuando
registres un hook. Los hooks se presentan en orden alfabético. El orden de ejecución se muestra en el diagrama de flujo
anterior (si estás navegando la versión HTML de este documento), o en el pseudocódigo estilo Perl de la sección de sinopsis.

HOOK

S

Hook

build 
$meta->register_hook( build => sub {
  my($build) = @_;
  ...
})
;

Esto realiza la compilación principal del proyecto alienizado y lo instala en el área de preparación (staging). El directorio actual es la raíz de la compilación. Necesitas ejecutar las herramientas que el proyecto requiera e instalarlas en "$build-"install_prop->{prefix}> ("%{.install

.pref
ix}").

Hook

build_ffi 
$meta->register_hook( build_ffi => sub {
  my($build) = @_;
  ...
})
;

Esto es lo mismo que build,

excepto que se activa solo
en una compilación FFI.

Hook

decode 
$meta->register_hook( decode => sub {
  my($build, $res) = @_;
  ...
}

Este hook toma una referencia de hash de respuesta del gancho "fetch" anterior con un tipo de "html" o "dir_listing" y la convierte en una referencia de hash de respuesta de tipo "list". En resumen, toma una respuesta de listado de archivos HTML o FTP de un gancho fetch y la convierte en una lista de nombres de archivos y enlaces que puede ser u

sada por el gancho prefer para elegir el archivo correcto a descargar. Consulte el ga
ncho fetch para la especificación de las referencias de hash de entrada y respuesta.

gancho

check_digest 
# implement the well known FOO-92 digest
$meta->register_hook( check_digest => sub {
  my($build, $file, $algorithm, $digest) = @_;
  if($algorithm ne 'FOO92') {
    return 0;
  }
  my $actual = foo92_hex_digest($file);
  if($actual eq $digest) {
    return 1;
  } else {
    die "Digest FOO92 does not match: got $actual, expected $digest";
  }
})
;

Este gancho debe verificar si el $file dado (el formato es el mismo que el usado por el gancho fetch) coincide con el $digest dado usando el $algorithm dado. Si el plugin no soporta el algoritmo dado, entonces debe devolver un valor falso. Si el d

igest no coincide, debe lanzar una excepción. Si el
digest coincide, debe devolver un valor verdadero.

clean_instal

l 
$meta->register_hook( clean_install => sub {
  my($build) = @_;
})
;

Este gancho le permite eliminar archivos de la ubicación final de instalación antes de que los archivos sean instalados por la capa de instalador (ejemplos: Alien::Build::MM, Alien::Build::MB o App::af). Este gancho no es llamado por defecto, y debe ser habilitado a través de la interfaz de la capa de instalador (ejemplo: "clean_install" en Alien::Build::MM)

.

Este gancho NO DEBE eliminar el directorio "_alien" o su contenido de la ubicación de

instalación.

La implementación por defecto elimina todos los archivos EXCEPTO el directorio "_alien

" y su c
ontenido.

gancho

download 
$meta->register_hook( download => sub {
  my($build) = @_;
  ...
})
;

Este gancho se usa para descargar desde internet el código fuente. Ya sea como un archivo (como tar, zip, etc), o como un directorio de archivos ("git clone", etc). Cuando el gancho es llamado, el directorio de trabajo actual será un nuevo directorio vacío, por lo que puede guardar la descarga en el directorio actual. Si guarda un solo archivo en el directorio, Alien::Build asumirá que es un archivo, el cual será procesado por el gancho extract. Si guarda múltiples archivos, Alien::Build asumirá que el directorio actual es la raíz del código fuente. Si no se guardan archivos en absoluto, se lanzará una excepción con un diagnóstico

apropiado.

Nota: Si registra este gancho, entonces los ganchos fetch, decode y prefer N

O serán llamados, a menos que usted los
llame usted mismo desde este gancho.

gancho

extract 
$meta->register_hook( extract => sub {
  my($build, $archive) = @_;
  ...
})
;

Este gancho se usa para extraer un archivo que ya ha sido descargado. Alien::Build ya tiene plugins para los formatos de archivo más comunes, por lo que probablemente solo necesitará esto para añadir soporte para formatos de archivo nuevos o poco comunes. Cuando este gancho es llamado, el directorio d

e trabajo actual será un nuevo directorio vacío, por lo que puede guardar el contenido del archivo en el directorio actual. Si se escribe un solo directorio en el directorio actual, Alien::Build asumirá que ese es el directorio raíz del paquete. Si están presentes múltiples archivos y/o directori
os, eso indicará que el directorio de trabajo actual es la raíz del paquete. La lógica típicamente maneja correctamente el comportamiento por defecto para tar (donde los paquetes típicamente se extraen a un subdirectorio) y para zip (donde los paquetes típicamente se extraen al directorio actual).

gancho

fetch 
package Alien::Build::Plugin::MyPlugin;

use strict;
use warnings;
use Alien::Build::Plugin;
use Carp ();

has '+url' => sub { Carp::croak "url is required property" };

sub init
{
  my($self, $meta) = @_;

  $meta->register_hook( fetch => sub {
    my($build, $url, %options) = @_;
    ...
  }
}
1;

Usado para obtener un recurso. La primera vez será llamado sin argumento (o con $url establecido a "undef", por lo que la configuración usada para encontrar el recurso debe ser especificada por las propiedades del plugin. En llamadas posteriores el primer argumento será una

URL.

El hash %options puede contener estas

opciones:
http_heade
rs
Encabezados de solicitud HTTP, si se está usando un protocolo apropiado. Los encabezados se proporcionan como una referencia de array de pares clave/valor, lo que permite claves de encabezado duplicadas con múltiples valores.

Si se usa un protocolo no HTTP, o si el plugin no puede de otro modo enviar encabezados de solicitud HTTP, el plugin DEBERÍA emitir una advertencia usando el método "$build->log", pero porque esta opción no era parte de l

a especificación original, el pl
ugin PUEDE no emitir esa
advertencia mientras la ignora.

Tenga en cuenta que las versiones de Alien::Build anteriores a la 2.39 no pasaban el hash de opciones al plugin

fetch.

Normalmente la primera obtención será de un archivo o de un listado de directorio. Si es un archivo entonces el contenido debe ser devuelto como una referencia de hash con las siguientes

claves: 
# content of file stored in Perl
return {
  type     => 'file',
  filename => $filename,
  content  => $content,
  version  => $version,  # optional, if known
  protocol => $protocol, # AB 2.60 optional, but recommended
};

# content of file stored in the filesystem
return {
  type     => 'file',
  filename => $filename,
  path     => $path,     # full file system path to file
  version  => $version,  # optional, if known
  tmp      => $tmp,      # optional
  protocol => $protocol, # AB 2.60 optional, but recommended
}
;

$tmp si está establecido indicará si el archivo es temporal o no, y puede ser usado por Alien::Build para guardar una copia en algunos casos. El valor por defecto es verdadero, por lo que Alien::Build asume que el archivo o directorio es temporal si no le indica lo contrario. Probablemente la situación más común en la que establecería "tmp" a falso, es cuando el archivo está incluido dentro de la distribución Alien. Vea Alien::Build::Plugin::Fetch::Local por

ejemplo.

Si la URL apunta a un listado de directorio, usted debe devolverlo como una referencia de hash que contenga una lista de

archivos: 
return {
  type => 'list',
  list => [
    # filename: each filename should be just the
    #   filename portion, no path or url.
    # url: each url should be the complete url
    #   needed to fetch the file.
    # version: OPTIONAL, may be provided by some fetch or prefer
    { filename => $filename1, url => $url1, version => $version1 },
    { filename => $filename2, url => $url2, version => $version2 },
  ],
  protocol => $protocol, # AB 2.60 optional, but recommended
}
;

o si el listado está en formato HTML como una referencia de hash que contenga la información

HTML: 
return {
  type => 'html',
  charset  => $charset, # optional
  base     => $base,    # the base URL: used for computing relative URLs
  content  => $content, # the HTML content
  protocol => $protocol, # optional, but recommended
}
;

o un listado de directorio (usualmente producido por servidores FTP) como una referencia de

hash: 
return {
  type     => 'dir_listing',
  base     => $base,
  content  => $content,
  protocol => $protocol, # AB 2.60 optional, but recommended
}
;

[versión 2.

60]

Para todas estas respuestas $protocol es opcional, ya que no era parte de la especificación original, sin embargo se recomienda encarecidamente que incluya este campo, porque las versiones futuras de Alien::Build usarán esto para determinar si un archivo fue descargado de forma segura (es decir, a través de un protocolo seguro como SSL)

.

Algunos plugins (como los plugins decode) traducen un hash de archivo de un tipo a otro, deberían mantener el $protocol de la representación an

tigua a la nueva
del archivo.

patch 
$meta->register_hook( patch => sub {
  my($build) = @_;
  ...
})

Este hook es completamente opcional. Si se registra, se activará des

pués de la extracción y antes de la compilación. Le permite aplicar
parches o realizar modificaciones en el código fuente si son necesarias.

hook

$meta->register_hook( patch_ffi => sub {
  my($build) = @_;
  ...

;

Este hook es exactamente igual que

el hook patch, excepto que se acti

hook

prefer 
$meta->register_hook( prefer => sub {
  my($build, $res) = @_;
  return {
    type => 'list',
    list => [sort @{ $res->{list} }],
  };
}

Este hook ordena los candidatos de una lista generada a partir de los hooks "fetch" o "decode". Debe devolver una nueva referencia hash de lista con los candidatos ordenado

s de mejor a peor. También puede eliminar
candidatos que sean totalmente inaceptables.

hook

probe 
$meta->register_hook( probe => sub {
  my($build) = @_;
  return 'system' if ...; # instalación del sistema
  return 'share';         # de lo contrario
});

$meta->register_hook( probe => [ $command ] )
;

Este hook debe devolver la cadena "system" si el sistema operativo proporciona la biblioteca o la herramienta. Debe devolver "share" en caso

contrario.

También puede usar un comando que devuelva verdadero cuando la herramienta o la biblioteca esté disponible. Por ejemplo, para usar con "pkg-config"

: 
$meta->register_hook( probe =>
  [ '%{pkgconf} --exists libfoo' ] )
;

O si necesitara una versión

mínima: 
$meta->register_hook( probe =>
  [ '%{pkgconf} --atleast-version=1.00 libfoo' ] )
;

Tenga en cuenta que este hook NO DEBE recopilar propiedades del sistema, como cflags, libs, versiones, etc., porque el hook probe se omitirá en el caso de que la variable de entorno "ALIEN_INSTALL_TYPE" esté establecida. La detección de estas propiedades debe realizarse en su lugar por el hook

gather_system.

Se pueden proporcionar múltiples ho

oks probe. Se usarán en secuencia,
deteniéndose en el primero que d
etecte una instalación del sistema.
