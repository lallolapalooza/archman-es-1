NOMBRE

alint - etiquetas y tags de linting

DESCRIPCIÓN

Una etiqueta y un tag son 2 atributos dados a cada prueba en alint, una etiqueta está compuesta por una colección de palabras separadas por guiones y está destinada a transmitir la idea general de lo que hace la prueba. Un tag es una cadena con AL seguido de un entero, los cuales se asignan en orden creciente a medida que se crean nuevas pruebas, pero nunca se reutilizan los antiguos.

las pruebas se pueden omitir estableciendo una variable de entorno compuesta de SKIP_ + la etiqueta en mayúsculas con los guiones reemplazados por guiones bajos o estableciendo una variable de entorno compuesta de SKIP_ + el tag.

Severidad

La severidad se asigna a cada tag e indica qué tan seria es la violación encontrada:

Seria (S)

Causará problemas durante la compilación o cuando el paquete se entregue a los usuarios. Debe corregirse inmediatamente.

Importante (I)

Podría causar problemas durante la compilación o cuando el paquete se entregue a los usuarios en ciertas situaciones. Debe corregirse pronto.

Menor (M)

No causará problemas directamente durante la compilación o cuando el paquete se entregue a los usuarios. Debe corregirse cuando sea conveniente.

Esto también incluye problemas de estilo que se dictan en el archivo CODINGSTYLE.md.

ESTILO (T)

No causará ningún problema, son problemas de estilo específicos pertinentes a un desarrollador o colaborador en particular. APKBUILD_STYLE la variable puede establecerse en un valor específico para habilitar un subconjunto de comprobaciones que el desarrollador o usuario específico utiliza.

Cuando una comprobación pertenece a esta categoría, esta página del manual también proporciona información sobre qué desarrolladores usan una comprobación de estilo específica, ya que los desarrolladores a veces pueden querer que se realice la misma comprobación en su propio estilo.

Los valores válidos actuales son:

•
leo (linting de estilo para leo)

Certeza

La certeza se asigna a cada tag e indica qué tan segura está una prueba de que la violación encontrada no es un falso positivo

Cierta (C)

La prueba está segura de que esto no es un falso positivo

Posible (P)

La prueba no está segura de que esto sea un falso positivo, pero hay una alta probabilidad de que no lo sea

duplicate-package [AL22]

El paquete que se está introduciendo ya está presente en otro repositorio. Resuelve el conflicto mediante:

  • Si el paquete en el repositorio superior tiene cambios más recientes, fusiona estos cambios.
  • Después, elimina el paquete en el repositorio superior.

Los paquetes duplicados se ocultarán mutuamente en el repositorio y ganará el que tenga la versión más alta. También puede hacer que los programas se compilen contra la versión incorrecta de un paquete. Por ejemplo: si main/foo-1-r0 y testing/foo-2-r0 existen y main/bar se actualiza a la versión 2 que requiere foo>=2-r0 entonces fallará porque solo find main/foo-1-r0 and not testing/foo-2-r0 . pkgname-has-uppercase [AL14]

pkgname tiene caracteres en mayúsculas, pkgname debe tener solo caracteres en minúsculas.

Se pueden añadir más nombres de paquete a las excepciones pasando una lista separada por espacios en la variable CUSTOM_UPPERCASE_PKGNAMES.

Severidad: Seria, Certeza: Cierta

pkgver-has-pkgrel [AL15]

pkgver tiene -r seguido de un número, que está reservado para la versión de un paquete tal como lo define la variable pkgrel .

Severidad: Seria, Certeza: Cierta

_builddir-is-set [AL26]

_builddir está establecido en lugar de builddir, que es una variable antigua de antes de que builddir existiera como concepto entendido por abuild.

Severidad: Seria, Certeza: Cierta

literal-integer-is-quoted [AL28]

Una declaración de variable que contiene solo enteros no debería estar entre comillas.

Severidad: Menor, Certeza: Cierta

pkgname-used-in-source [AL29]

"$pkgname" se usa en la URL de origen. Esto acopla estrechamente el nombre del paquete al nombre original, lo que dificulta renombrar paquetes o crear variantes especializadas de paquetes.

En su lugar, use el nombre original escrito completamente. Esto solo cuenta para la URL en sí, no para el prefijo del nombre del archivo local.

Severidad: Menor, Certeza: Cierta

double-underscore-in-variable [AL30]

El uso de doble guion bajo en variables está prohibido, use siempre un solo guion bajo para variables que no son utilizadas por abuild.

Severidad: Menor, Certeza: Cierta

variable-capitalized [AL31]

Las variables no deben tener letras en mayúsculas.

Severidad: Menor, Certeza: Cierta

braced-variable [AL32]

La variable tiene llaves alrededor mientras no es necesario, elimine las llaves.

Severidad: Menor, Certeza: Posible

cpan-variable [AL35]

Las variables `cpandepends`, `cpanmakedepends` y `cpancheckdepends` fueron creadas por el programa apkbuild-cpan pero ahora están obsoletas y su contenido debe fusionarse con el contenido de su variable respectiva.

Severidad: Menor, Certeza: Cierta

overwrite-xflags [AL36]

No sobrescriba `CFLAGS`, `GOFLAGS`, `CPPFLAGS`, `CXXFLAGS` y `FFLAGS`. Estas banderas generalmente se definen fuera del APKBUILD y no deberían sobrescribirse porque contienen banderas importantes que no deberían descartarse. En su lugar, expanda la variable. Por ejemplo: `CFLAGS="$CFLAGS .."`

Todavía es posible cambiar las banderas usando sustitución de variables. Por ejemplo: `CFLAGS="${CFLAGS/-Dflag}"`

Esta lista podría expandirse a medida que se encuentren más variables que no deberían sobrescribirse.

Severidad: Seria, Certeza: Cierta

invalid-option [AL49]

Una opción en la variable option= tiene un valor que no es utilizado por abuild, aunque probablemente no cause ningún problema, se considera buena práctica eliminarla.

La variable VALID_CUSTOM_OPTIONS puede usarse para denotar otras opciones que son aceptables, toma una lista separada por espacios.

Severidad: Menor, Certeza: Cierta

missing-default-prepare [AL54]

La función prepare() está definida pero falta una llamada a default_prepare (que aplica todos los parches en source=). Por favor, añada default_prepare donde sea apropiado en la definición de prepare().

Severidad: Seria, Certeza: Cierta

invalid-arch [AL57]

La variable 'arch' en el APKBUILD tiene un valor inválido, las únicas opciones son el nombre de las arquitecturas usadas por Alpine Linux y las cadenas 'noarch' y 'all'.

Las arquitecturas aceptables se toman de /usr/share/abuild/functions.sh ya que son las reconocidas por abuild y por lo tanto por Alpine Linux como arquitecturas válidas, si tiene otras arquitecturas, lea abajo.

La variable CUSTOM_VALID_ARCHES puede usarse para denotar otras arquitecturas que deben considerarse válidas, toma una lista separada por espacios.

Severidad: Seria, Certeza: Cierta

bad-version [AL61]

El pkgver coincide con una expresión regular para una mala versión, esto significa que el pkgver es una versión no deseable, como una rama de prueba/experimental.

La variable CUSTOM_BAD_VERSIONS puede usarse para añadir más combinaciones pkgname@regexes..., separadas por espacios.

Severidad: Importante, Certeza: Cierta

volatile-source [AL62]

La URL dada es volátil y cambiará su suma de verificación debido a factores inesperados.

El ejemplo más común son las pull-requests de GitHub / Merge Requests de GitLab que cambian a medida que el autor envía commits, otro son los commits de GitHub que podrían cambiar a medida que GitHub cambia su versión de Git en su infraestructura.

Severidad: Seria, Certeza: Cierta

unexpected-shebang-line [AL33]

Los archivos de servicio de OpenRC necesitan usar `#!/sbin/openrc-run` para funcionar correctamente. Vea https://github.com/OpenRC/openrc/blob/master/service-script-guide.md#syntax-of-service-scripts para más detalles.

Severidad: Importante, Certeza: Cierta

custom-start-stop-function [AL34]

Se desaconseja escribir funciones personalizadas de inicio / parada para archivos de servicio. En la mayoría de los casos es suficiente definir `command`, `command_args` y `pidfile`. Vea https://github.com/OpenRC/openrc/blob/master/service-script-guide.md#dont-write-your-own-startstop-functions para más información.

Severidad: Importante, Certeza: Cierta
