DESCRIPCIÓ

N

libalpm proporciona la capacidad de especificar ganchos que se ejecuten antes o después de las transacciones basándose en los paquetes y/o archivos que se modifican. Los ganchos consisten en una única sección [Action] que describe la acción a ejecutar y una o más secciones [Trigger] que describen para qué transacciones debe

ejecutarse.

Los ganchos se leen de archivos ubicados en el directorio de ganchos del sistema /usr/share/libalpm/hooks, y de directorios personalizados adicionales especificados en pacman.conf(5) (el valor predeterminado es /etc/pacman.d/hooks). Los nombres de archivo deben tener el sufijo ".hook

". Los ganchos se ejecutan en orden alfabético de su no
mbre de archivo, donde el ordenamiento ignora el sufijo.

DISPARADORE

S

Los ganchos deben contener al menos una sección [Trigger] que determina qué transacciones causarán la ejecución del gancho. Si se definen múltiples secciones de disparador, el gancho se ejecutará si la transacción coincide con alguno de los

disparadores.

Operation = Install|Upgrade|Remov

e
Selecciona el tipo de operación contra la cual comparar los objetivos. Puede especificarse múltiples veces. Las instalaciones se consideran una actualización si el paquete o archivo ya está presente en el sistema, independientemente de si la nueva versión del paquete es realmente mayor que la versión instalada actualmente. Para los disparadores de Path, esto es cierto incluso si el archivo cambia de propiedad de un paquete a otro.
Obligatorio.

Type =

Path|Package
Selecciona si los objetivos se comparan contra los paquetes de la transacción o los archivos. Consulte ADVERTENCIAS para notas especiales sobre los disparadores de Path. File es un alias obsoleto para Path y se eliminará en una versión futura.
Obligatorio.

Target =

<path|package>
La ruta o el nombre del paquete contra el cual comparar la transacción activa. Las rutas se refieren a los archivos en el archivo del paquete; la raíz de instalación no debe incluirse en la ruta. Se permiten patrones globales al estilo del shell. Es posible invertir las coinciden
cias anteponiendo un signo de exclamación a un objetiv
o. Puede especificarse múltiples veces. Obligatorio.

ACCIONE

S

Description = ..

.
Una descripción opcional que describe la acción que realiza el gancho, para su uso en la salida de la interfaz
gráfica.

Exec =

<command>
Comando a ejecutar. Los argumentos del comando se dividen por espacios en blanco. Los valores que contienen espacios en blanco deben ir entrecomillados.
Obligatorio.

When = PreTransaction|PostTransactio

n
Cuándo ejecutar el gancho.
Obligatorio.

Depends =

<package>
Paquetes que deben estar instalados para que el gancho se ejecute. Puede especificarse múltiples
veces.

AbortOnFai

l
Hace que la transacción se aborte si el gancho termina con un código de salida distinto de cero. Solo se aplica a los ganchos
PreTransaction.

NeedsTarget

s
Hace que la lista de objetivos de disparador coincidentes se pase al gancho en ejecución a través de std
i
n.

ANULACIÓN DE

GANCHOS

Los ganchos pueden anularse colocando un archivo con el mismo nombre en un directorio de ganchos de mayor prioridad. Los ganchos pueden deshabilitarse anulándolos con un enlace simbólico a /dev/

nul
l.

EJEMPLO

S 
# Forzar la sincronización de los discos para reducir el riesgo
de corrupción de datos [Trigger] Operation = Install Operation
= Upgrade Operation = Remove Type = Package Target = * [Action]
Depends = coreutils When = PostTransaction Exec = /usr/bin/sync

ADVERTENCI

AS

Hay situaciones en las que los disparadores de ruta pueden actuar de manera inesperada. Los ganchos se activan utilizando la lista de archivos del paquete instalado, actualizado o eliminado. Al instalar o actualizar un archivo que se extrae con una extensión .pacnew, se utiliza el nombre de archivo original para activar el gancho. Al eliminar un paquete, todos los archivos propiedad de ese paquete pueden activar un gancho, estén o no presentes en el sistema de archivos antes de la eliminación del

paquete.

Los ganchos PostTransaction no se ejecutarán si la transacción falla por cualquier

motivo.

Consulte el sitio web de pacman en https://archlinux.org/pacman/ para información a

ctual sobre pacman y sus
herramientas relacionadas.
