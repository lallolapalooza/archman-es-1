DESCRIPCIÓ

N

ALTER_ROLE cambia los atributos de un rol de

PostgreSQL.

La primera variante de este comando listada en la sinopsis puede cambiar muchos de los atributos del rol que se pueden especificar en CREATE ROLE. (Se cubren todos los atributos posibles, excepto que no hay opciones para añadir o eliminar membresías; use GRANT y REVOKE para eso.) Los atributos no mencionados en el comando conservan sus configuraciones anteriores. Los superusuarios de la base de datos pueden cambiar cualquiera de estas configuraciones para cualquier rol, excepto cambiar la propiedad SUPERUSER para el superusuario de arranque. Los roles no superusuarios que tienen el privilegio CREATEROLE pueden cambiar la mayoría de estas propiedades, pero solo para roles no superusuarios y no de replicación para los que se les ha concedido ADMIN OPTION. Los no superusuarios no pueden cambiar la propiedad SUPERUSER y pueden cambiar las propiedades CREATEDB, REPLICATION y BYPASSRLS solo si poseen la propiedad correspondiente. Los roles ordinarios solo pueden cambiar su propia

contraseña.

La segunda variante cambia el nombre del rol. Los superusuarios de la base de datos pueden renombrar cualquier rol. Los roles con privilegio CREATEROLE pueden renombrar roles no superusuarios para los que se les ha concedido ADMIN OPTION. El usuario de sesión actual no puede ser renombrado. (Conecte como un usuario diferente si necesita hacerlo.) Como las contraseñas cifradas con MD5 usan el nombre del rol como sal criptográfica, renombrar un rol borra su contraseña si la contraseña es cifrada con

MD5.

Las variantes restantes cambian el valor predeterminado de sesión de un rol para una variable de configuración, ya sea para todas las bases de datos o, cuando se especifica la cláusula IN DATABASE, solo para sesiones en la base de datos nombrada. Si se especifica ALL en lugar de un nombre de rol, esto cambia la configuración para todos los roles. Usar ALL con IN DATABASE es efectivamente lo mismo que usar el comando ALTER DATABASE ... SET ...

.

Siempre que el rol posteriormente inicie una nueva sesión, el valor especificado se convierte en el valor predeterminado de sesión, anulando cualquier configuración presente en postgresql.conf o que se haya recibido de la línea de comandos de postgres. Esto solo ocurre en el momento del inicio de sesión; ejecutar SET ROLE o SET SESSION AUTHORIZATION no causa que se establezcan nuevos valores de configuración. Las configuraciones establecidas para todas las bases de datos se anulan por configuraciones específicas de la base de datos vinculadas a un rol. Las configuraciones para bases de datos específicas o roles específicos anulan las configuraciones para todos los

roles.

Los superusuarios pueden cambiar los valores predeterminados de sesión de cualquiera. Los roles con privilegio CREATEROLE pueden cambiar los valores predeterminados para roles no superusuarios

para los que se les ha concedido ADMIN OPTION. Los roles ordinarios solo pueden establecer valores predeterminados para sí mismos. Ciertas variables de configuración no se pueden establece
r de esta manera, o solo se pueden establecer si un superusuario emite el comando. Solo los superusuarios pueden cambiar una configuración para todos los roles en todas las bases de datos.

NOTA

S

Use CREATE ROLE para añadir nuevos roles, y DROP ROLE para eliminar un

rol.

ALTER ROLE no puede cambiar las membresías de un rol. Use GRANT y REVOKE para

hacerlo.

Se debe tener cuidado al especificar una contraseña no cifrada con este comando. La contraseña se transmitirá al servidor en texto plano, y también podría registrarse en el historial de comandos del cliente o en el registro del servidor. psql(1) contiene un comando \password que puede usarse para cambiar la contraseña de un rol sin exponer la contraseña en texto

plano.

También es posible vincular un valor predeterminado de sesión a una base de datos específica en lugar de a un rol; consulte ALTER DATABASE (ALTER_DATABASE(7)). Si hay un conflicto, las configuraciones específicas de base de datos-rol

anulan las específicas del rol, que a su vez
anulan las específicas de la base de datos.
