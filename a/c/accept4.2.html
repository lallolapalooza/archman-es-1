DESCRIPCIÓ

N

La llamada al sistema accept() se utiliza con tipos de socket basados en conexión (SOCK_STREAM, SOCK_SEQPACKET). Extrae la primera solicitud de conexión en la cola de conexiones pendientes para el socket de escucha, sockfd, crea un nuevo socket conectado y devuelve un nuevo descriptor de archivo que hace referencia a ese socket. El socket recién creado no está en estado de escucha. El socket original sockfd no se ve afectado por esta

llamada.

El argumento sockfd es un socket que ha sido creado con socket(2), vinculado a una dirección local con bind(2), y está escuchando conexiones después de un listen(

2).

El argumento addr es un puntero a una estructura sockaddr. Esta estructura se rellena con la dirección del socket del par, tal como la conoce la capa de comunicación. El formato exacto de la dirección devuelta addr lo determina la familia de direcciones del socket (ver socket(2) y las páginas man del protocolo correspondientes). Cuando addr es NULL, no se rellena nada; en este caso, addrlen no se utiliza y también debería ser

NULL.

El argumento addrlen es un argumento de valor-resultado: el llamador debe inicializarlo para que contenga el tamaño (en bytes) de la estructura a la que apunta addr; al volver, contendrá el tamaño real de la dirección del

par.

La dirección devuelta se trunca si el búfer proporcionado es demasiado pequeño; en este caso, addrlen devolverá un valor mayor que el suministrado a la

llamada.

Si no hay conexiones pendientes en la cola y el socket no está marcado como no bloqueante, accept() bloquea al llamador hasta que haya una conexión. Si el socket está marcado como no bloqueante y no hay conexiones pendientes en la cola, accept() falla con el error EAGAIN o EWOULDBLOCK

.

Para recibir notificación de conexiones entrantes en un socket, se puede usar select(2), poll(2) o epoll(7). Se entregará un evento legible cuando se intente una nueva conexión y entonces se puede llamar a accept() para obtener un socket para esa conexión. Alternativamente, se puede configurar el socket para entregar SIGIO cuando haya actividad en un socket; ver socket(7) para más

detalles.

Si flags es 0, entonces accept4() es lo mismo que accept(). Los siguientes valores se pueden combinar con OR bit a bit en flags para obtener un comportamiento

diferente:

Manejo de

errores

Linux accept() (y accept4()) pasa errores de red ya pendientes en el nuevo socket como un código de error desde accept(). Este comportamiento difiere de otras implementaciones de sockets BSD. Para un funcionamiento fiable, la aplicación debe detectar los errores de red definidos para el protocolo después de accept() y tratarlos como EAGAIN reintentando. En el caso de TCP/IP, estos son ENETDOWN, EPROTO, ENOPROTOOPT, EHOSTDOWN, ENONET, EHOSTUNREACH, EOPNOTSUPP y ENETU

VERSIONE

S

En Linux, el nuevo socket devuelto por accept() no hereda marcas de estado de archivo como O_NONBLOCK ni O_ASYNC del socket de escucha. Este comportamiento difiere de la implementación canónica de sockets BSD. Los programas portables no deberían confiar en la herencia o no herencia de las marcas de estado de archivo y siempre establecer explícitamente todas las marcas requeridas en el socket devuelto desde acce

NOTA

S

Puede que no siempre haya una conexión esperando después de que se entregue un SIGIO o de que select(2), poll(2), o epoll(7) devuelvan un evento de legibilidad, porque la conexión podría haber sido eliminada por un error de red asincrónico u otro hilo antes de que se llame a accept(). Si esto ocurre, la llamada se bloqueará esperando a que llegue la siguiente conexión. Para asegurar que accept() nunca se bloquee, el socket pasado sockfd necesita tener la bandera O_NONBLOCK establecida (ver socket(7))

.

Para ciertos protocolos que requieren una confirmación explícita, como DECnet, accept() puede considerarse simplemente como desencolar la siguiente solicitud de conexión sin implicar confirmación. La confirmación puede implicarse mediante una lectura o escritura normal en el nuevo descriptor de archivo, y el rechazo puede implicarse cerrando el nuevo socket. Actualmente, solo DECnet tiene estas semánticas en

Linux.
