access.conf - el archivo

de tabla de control de a
cceso de inicio de sesión

DESCRIPCIÓ

N

El archivo /etc/security/access.conf especifica (usuario/grupo, host), (usuario/grupo, red/máscara de red), (usuario/grupo, tty), (usuario/grupo, valor de X-$DISPLAY), o (usuario/grupo, nombre de servicio pam) combinaciones para las cuales un inicio de sesión será aceptado o

rechazado.

Cuando alguien inicia sesión, el archivo access.conf se busca para encontrar la primera entrada que coincida con la combinación (usuario/grupo, host) o (usuario/grupo, red/máscara de red), o, en el caso de inicios de sesión no en red, la primera entrada que coincida con la combinación (usuario/grupo, tty), o en el caso de inicios de sesión no en red sin una tty, la primera entrada que coincida con la combinación (usuario/grupo, valor de X-$DISPLAY) o (usuario/grupo, nombre de servicio pam/) . El campo de permisos de esa entrada de la tabla determina si el inicio de sesión será aceptado o

rechazado.

Cada línea de la tabla de control de acceso de inicio de sesión tiene tres campos separados por un carácter ":" (dos puntos)

:

permiso:usuarios/grupos:orígene

s

El primer campo, el campo de permiso, puede ser un carácter"+" (más) para acceso concedido o un carácter"-" (menos) para acceso

denegado.

El segundo campo, el campo de usuarios/grupo, debe ser una lista de uno o más nombres de inicio de sesión, nombres de grupo, uid, gid, o ALL (que siempre coincide). Para diferenciar las entradas de usuario de las de grupo, las entradas de grupo deben escribirse con corchetes, por ejemplo (grupo) o (gid

).

El tercer campo, el campo de orígenes, debe ser una lista de uno o más nombres de tty (para inicios de sesión no en red), valores de $DISPLAY de X o nombres de servicios PAM (para inicios de sesión no en red sin una tty), nombres de host, nombres de dominio (comienzan con "."), direcciones de host, números de red de internet (terminan con "."), direcciones de red de internet con máscara de red (donde la máscara de red puede ser un número decimal o una dirección de internet también), ALL (que siempre coincide) o LOCAL. La palabra clave LOCAL coincide cuando el usuario se conecta sin una conexión de red (por ejemplo, su, login). Una conexión a través del dispositivo de loopback (por ejemplo, ssh user@localhost) se considera una conexión de red, y por lo tanto, la palabra clave LOCAL no

coincide.

Si el sistema lo soporta, puede usar @nombre-de-netgroup en patrones de host o de usuario. La sintaxis @@nombre-de-netgroup solo se soporta en el patrón de usuario y hace que el nombre de host del sistema local se pase a la llamada de coincidencia de netgroup además del nombre de usuario. Esto podría no funcionar correctamente en algunas implementaciones de libc, lo que haría que la coincidencia falle

siempre.

El operador EXCEPT hace posible escribir reglas muy

compactas.

Si nodefgroup no está establecido, se busca en el archivo de grupos cuando un nombre no coincide con el del usuario que ha iniciado sesión. Solo se coinciden grupos en los que los usuarios están listados explícitamente. Sin embargo, el módulo PAM no mira el id de grupo primario de un

usuario.

El carácter"#" al inicio de la línea (sin espacio al principio) se pu

ede usar para marcar esta líne
a como una línea de comentario.

NOTA

S

Los separadores predeterminados de los elementos de una lista en un campo son el espacio, la ',' y los caracteres de tabulador. Así, convenientemente, si se colocan espacios al principio y al final de los campos, se ignoran. Sin embargo, si el separador de la lista se cambia con la opción listsep, los espacios se convertirán en parte del elemento real y la línea probablemente será ignorada. Por esta razón, no se recomienda poner espacios alrededor de los caracteres ':

'.

Una dirección de host local de enlace IPv6 debe contener el identificador de interfaz. No se soporta la red/máscara local de enlace

IPv6.

Los nombres de host deberían escribirse como Nombre de

Host Totalmente Cualificado (FQHN) para evitar confusió
n con nombres de dispositivo o nombres de servicio PAM.

access.conf(5)

ACCESS.CONF - Configuración de acceso para el servidor web Apache

DESCRIPCIÓN

El archivo access.conf se utiliza para configurar las directivas de acceso del servidor web Apache. Estas directivas controlan quién puede acceder a los recursos de su sitio web y cómo.

Las directivas más comunes incluyen:

  • Require: Especifica las condiciones bajo las cuales se permite el acceso.
  • Allow y Deny: Controlan el acceso basado en direcciones IP o nombres de host.

La sintaxis del archivo access.conf es la siguiente:

Directiva [argumentos]

Por ejemplo, para denegar el acceso a todos excepto a una dirección IP específica:

<Directory "/var/www/html">
    Require all denied
    Require ip 192.168.1.100
</Directory>

ARCHIVOS

/etc/httpd/conf/access.conf

VÉASE TAMBIÉN

apachectl(8), httpd.conf(5)
