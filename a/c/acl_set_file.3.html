Paquete: acl

ACL_SET_FILE(3) Manual de Funciones de Biblioteca ACL_SET_FILE(3)

NOMBRE

acl_set_file — establecer un ACL por nombre de archivo

BIBLIOTECA

Biblioteca de Listas de Control de Acceso de Linux (libacl, -lacl).

SINOPSIS

#include <sys/types.h>
#include <sys/acl.h>

int
acl_set_file(const char *path_p, acl_type_t type, acl_t acl);

DESCRIPCIÓN

La acl_set_file() función asocia un ACL de acceso con un archivo o directorio, o asocia un ACL predeterminado con un directorio. La ruta de acceso del archivo o directorio es apuntada por el argumento path_p.

El ID de usuario efectivo del proceso debe coincidir con el propietario del archivo o directorio o el proceso debe tener la capacidad CAP_FOWNER para que la solicitud tenga éxito.

El valor del argumento type se utiliza para indicar si se está estableciendo el ACL de acceso o el ACL predeterminado asociado con path_p . Si el type parámetro es ACL_TYPE_ACCESS, el ACL de acceso de path_p debe ser establecido. Si el type parámetro es ACL_TYPE_DEFAULT, el ACL predeterminado de path_p debe ser establecido. Si el argumento type especifica un tipo de ACL que no puede ser asociado con path_p, entonces la función falla.

El acl parámetro debe referenciar un ACL válido de acuerdo con las reglas descritas en la página de manual acl_valid(3) si el type parámetro es ACL_TYPE_ACCESS, y debe referenciar ya sea un ACL válido o un ACL con cero entradas de ACL si el type parámetro es ACL_TYPE_DEFAULT. Si el acl parámetro referencia un ACL vacío, entonces la acl_set_file() función elimina cualquier ACL predeterminado asociado con el directorio referido por el path_p parámetro.

VALOR DE RETORNO

La acl_set_file() función devuelve el valor 0 si es exitosa; de lo contrario se devuelve el valor -1 y la variable global errno se establece para indicar el error.

ERRORES

Si ocurre alguna de las siguientes condiciones, la acl_set_file() función devuelve -1 y establece errno al valor correspondiente:

[EACCES]
Se deniega el permiso de búsqueda para un componente del prefijo de la ruta o el objeto existe y el proceso no tiene los derechos de acceso apropiados.

El argumento type especifica un tipo de ACL que no puede ser asociado con path_p.

[EINVAL]
El argumento acl no apunta a un ACL válido.

El ACL tiene más entradas de las que el archivo referido por path_p puede obtener.

El type parámetro no es ACL_TYPE_ACCESS ni ACL_TYPE_DEFAULT.

El type parámetro es ACL_TYPE_DEFAULT, pero el archivo referido por path_p no es un directorio.

[ENAMETOOLONG]
La longitud del argumento path_p es demasiado larga.
[ENOENT]
El objeto nombrado no existe o el argumento path_p apunta a una cadena vacía.
[ENOSPC]
El directorio o sistema de archivos que contendría el nuevo ACL no puede ser extendido o el sistema de archivos se ha quedado sin recursos de asignación de archivos.
[ENOTDIR]
Un componente del prefijo de la ruta no es un directorio.
[ENOTSUP]
El archivo identificado por path_p no puede ser asociado con el ACL porque el sistema de archivos en el que se encuentra el archivo no lo soporta.
[EPERM]
El proceso no tiene el privilegio apropiado para realizar la operación de establecer el ACL.
[EROFS]
Esta función requiere la modificación de un sistema de archivos que actualmente es de solo lectura.

ESTÁNDARES

IEEE Std 1003.1e borrador 17 (“POSIX.1e”, abandonado)

El comportamiento de acl_set_file() cuando el acl parámetro se refiere a un ACL vacío y el type parámetro es ACL_TYPE_DEFAULT es una extensión en la implementación de Linux, para que todos los valores devueltos por acl_get_file() puedan ser pasados a acl_set_file(). La función POSIX.1e para eliminar un ACL predeterminado es acl_delete_def_file().

VER TAMBIÉN

acl_delete_def_file(3), acl_get_file(3), acl_set_fd(3), acl_valid(3), acl(5)
