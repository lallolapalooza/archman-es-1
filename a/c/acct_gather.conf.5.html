acct_gather.conf(5) Archivo de configuración de Slurm acct_gather.conf(5)

NOMBRE

acct_gather.conf - Archivo de configuración de Slurm para los plugins relacionados con acct_gather

DESCRIPCIÓN

acct_gather.conf es un archivo con formato UTF8 que define los parámetros utilizados por los plugins relacionados con acct_gather de Slurm. El archivo se encontrará siempre en el mismo directorio que slurm.conf.

Los nombres de los parámetros no distinguen entre mayúsculas y minúsculas, pero los valores de los parámetros sí. Cualquier texto que siga a un "#" en el archivo de configuración se trata como un comentario hasta el final de esa línea. El tamaño de cada línea en el archivo está limitado a 1024 caracteres.

Los cambios en el archivo de configuración surten efecto tras reiniciar los demonios de Slurm.

Los siguientes parámetros de acct_gather.conf están definidos para controlar el comportamiento general de varios plugins en Slurm.

El archivo acct_gather.conf es diferente de otros archivos .conf de Slurm. Cada plugin define qué opciones están disponibles. Cada plugin que se va a cargar debe especificarse en slurm.conf bajo las siguientes entradas de configuración:

• AcctGatherEnergyType (plugin type=acct_gather_energy)
• AcctGatherInterconnectType (plugin type=acct_gather_interconnect)
• AcctGatherFilesystemType (plugin type=acct_gather_filesystem)
• AcctGatherProfileType (plugin type=acct_gather_profile)

Si el plugin correspondiente para una opción no está cargado, esa opción será desconocida para Slurm, lo que provocará un error fatal del demonio al inicializarse. Si decide cambiar los tipos de plugin en slurm.conf, asegúrese también de cambiar las opciones relacionadas en acct_gather.conf.

acct_gather_energy/gpu

Entrada requerida en slurm.conf:

AcctGatherEnergyType=acct_gather_energy/gpu
Este plugin no lee ninguna opción de acct_gather.conf.
El conjunto de datos proporcionado por el plugin es: Energy.

acct_gather_energy/IPMI

Entrada requerida en slurm.conf:

AcctGatherEnergyType=acct_gather_energy/ipmi

Las opciones utilizadas para acct_gather_energy/ipmi son las siguientes:

EnergyIPMIFrequency=<número>
Este parámetro es el número de segundos entre muestras de acceso a la BMC. Idealmente, debería ser mayor o igual a JobAcctGatherFrequency, de lo contrario, el plugin JobAcctGather obtendrá valores repetidos en sondeos sucesivos.
EnergyIPMICalcAdjustment=<sí|no>
Si se establece en "sí", el consumo entre la última muestra de acceso a la BMC y una actualización de consumo de paso se aproxima para obtener un consumo de tarea más preciso. El ajuste se realiza al inicio del paso y cada vez que se actualiza el consumo, incluido el final del paso. Las aproximaciones no se acumulan, solo se utilizan el primer y el último ajuste para calcular el consumo. El valor predeterminado es "no".
EnergyIPMIPowerSensors=<clave=valores>
Opcionalmente, especifique los identificadores de los sensores a utilizar. Se pueden establecer múltiples <clave=valores> con separadores ";". La clave "Node" es obligatoria y se utiliza para conocer la energía consumida por los nodos (scontrol show node) y los trabajos (sacct). Otras claves son opcionales y las nombra el administrador. Estas claves solo son útiles cuando el perfil está activado para la energía, para almacenar la potencia (en vatios) de cada clave. Los <valores> son enteros excepto cuando se usa DCMI. Se pueden establecer múltiples valores con separadores ",". Se utiliza la suma de los sensores listados para cada clave. EnergyIPMIPowerSensors es opcional, el valor predeterminado es "Node=<valor>", donde "<valor>" es el id del primer sensor de potencia devuelto por ipmi-sensors.
por ejemplo,
EnergyIPMIPowerSensors=Node=16,19,23,26;Socket0=16,23;Socket1=19,26;SSUP=23,26;KNC=16,19
EnergyIPMIPowerSensors=Node=29,32;SSUP0=29;SSUP1=32
EnergyIPMIPowerSensors=Node=1280

Interfaz de Gestión del Centro de Datos - acct_gather_energy/ipmi soporta la recopilación de datos de energía a través de comandos de extensión DCMI IPMI. Cuando se configura, el plugin ipmi consultará el DCMI usando los indicadores "System Power mode" o "Enhanced System Power Statistics mode" según la configuración.

Para configurar uno u otro, se pueden utilizar los valores especiales de sensor DCMI o DCMI_ENHANCED, por ejemplo:
EnergyIPMIPowerSensors=Node=DCMI
EnergyIPMIPowerSensors=Node=DCMI_ENHANCED

Los siguientes parámetros de acct_gather.conf se definen para controlar los valores predeterminados de configuración de IPMI para libipmiconsole.

EnergyIPMIUsername=NOMBRE_USUARIO
Especifique el Nombre de usuario de la BMC.
EnergyIPMIPassword=CONTRASEÑA
Especifique la Contraseña de la BMC.
Los conjuntos de datos proporcionados por el plugin tienen el nombre: <ETIQUETA_SENSOR_IPMI>Power.

NOTAS:

Este plugin requiere que los archivos de desarrollo de freeipmi estén instalados y sean enlazables en el momento de la configuración. De lo contrario, el plugin no se compilará. Al compilar el RPM, se puede especificar rpmbuild ... --with freeipmi para comprobar explícitamente estas dependencias.

acct_gather_energy/rapl

Entrada requerida en slurm.conf:

AcctGatherEnergyType=acct_gather_energy/rapl
Este plugin no lee ninguna opción de acct_gather.conf.
El conjunto de datos proporcionado por el plugin es: Power.

acct_gather_energy/XCC

Entrada requerida en slurm.conf:

AcctGatherEnergyType=acct_gather_energy/xcc

Las opciones utilizadas para acct_gather_energy/xcc solo incluyen comunicaciones in-band con XClarity Controller, por lo tanto, se admite un conjunto reducido de configuraciones:

EnergyIPMIFrequency=<número>
Este parámetro es el número de segundos entre muestras de acceso a la XCC. El valor predeterminado es 30 segundos.
EnergyIPMITimeout=<número>
Tiempo de espera, en segundos, para inicializar el contexto IPMI XCC para un nuevo hilo de recopilación. El valor predeterminado es 10 segundos.
Los conjuntos de datos proporcionados por el plugin son: Energy, CurrPower.

acct_gather_filesystem/lustre

Entrada requerida en slurm.conf:

AcctGatherFilesystemType=acct_gather_filesystem/lustre
Este plugin no lee ninguna opción de acct_gather.conf.
Los conjuntos de datos proporcionados por el plugin son: Reads, ReadMB, Writes, WriteMB.

acct_gather_profile/HDF5

Entrada requerida en slurm.conf:

AcctGatherProfileType=acct_gather_profile/hdf5

Las opciones utilizadas para acct_gather_profile/hdf5 son las siguientes:

ProfileHDF5Dir=<ruta>
Este parámetro es la ruta a la carpeta compartida en la que el acct_gathe
El plugin r_profile escribirá datos detallados (generalmente como un archivo HDF5). Se asume que el directorio está en un sistema de archivos compartido por el controlador y todos los nodos de cómputo. Este es un parámetro obligatorio.
ProfileHDF5Default
Una lista de tipos de datos separados por comas que se recopilarán para cada envío de trabajo. Los valores permitidos son:
All
Se recopilan todos los tipos de datos. (No se puede combinar con otros valores.)
None
No se recopilan tipos de datos. Este es el valor predeterminado. (No se puede combinar con otros valores.)
Energy
Se recopilan datos de energía.
Filesystem
Se recopilan datos del sistema de archivos (Lustre).
Network
Se recopilan datos de red (InfiniBand).
Task
Se recopilan datos de tarea (E/S, memoria, ...).

acct_gather_profile/InfluxDB

Entrada requerida en slurm.conf:

AcctGatherProfileType=acct_gather_profile/influxdb

El plugin InfluxDB proporciona la misma información que el plugin HDF5, pero enviará la información al servidor InfluxDB configurado.

El plugin InfluxDB está diseñado para el protocolo 1.x de InfluxDB. Cualquier sitio que ejecute un servidor InfluxDB v2.x deberá configurar un punto de compatibilidad v1.x junto con la autorización de usuario y contraseña correctas. La autenticación por token no es compatible actualmente.

Opciones:

ProfileInfluxDBDatabase
Nombre de la base de datos InfluxDB v1.x donde se escribirá la información de perfilado. Nombre del bucket de InfluxDB v2.x donde se escribirá la información de perfilado.
ProfileInfluxDBDefault
Una lista de tipos de datos separados por comas que se recopilarán para cada envío de trabajo. Los valores permitidos son:
All
Se recopilan todos los tipos de datos. No se puede combinar con otros valores.
None
No se recopilan tipos de datos. Este es el valor predeterminado. No se puede combinar con otros valores.
Energy
Se recopilan datos de energía.
Filesystem
Se recopilan datos del sistema de archivos (Lustre).
Network
Se recopilan datos de red (InfiniBand).
Task
Se recopilan datos de tarea (E/S, memoria, ...).
ProfileInfluxDBFrequency=<segundos>
Con qué frecuencia, en segundos, se deben enviar los datos al servidor InfluxDB. Tenga en cuenta que en la práctica, los datos de perfilado se enviarán no más de una vez cada JobAcctGatherFrequency segundos. Un valor de 0 desactiva el almacenamiento en búfer en el plugin para que los datos se envíen al servidor InfluxDB tan pronto como se recopilen. En todos los casos, los datos se envían a InfluxDB cuando el búfer interno del plugin está lleno y al final de cada paso de trabajo. El valor predeterminado es 30 segundos.
ProfileInfluxDBHost=<nombre_de_host>:<puerto>
El nombre de host de la máquina donde se InfluxDB ejecuta la instancia y el puerto utilizado por la API HTTP. El puerto utilizado por la API HTTP es el configurado a través de la opción bind-address de influxdb.conf en la sección [http]. Ejemplo: 
ProfileInfluxDBHost=myinfluxhost:8086

ProfileInfluxDBPass
Contraseña para el nombre de usuario configurado en ProfileInfluxDBUser. Obligatorio en v2.x y opcional en v1.x de InfluxDB.
ProfileInfluxDBRTPolicy
El nombre de la política de retención de InfluxDB v1.x para la base de datos configurada en la opción ProfileInfluxDBDatabase. El nombre del bucket de la política de retención de InfluxDB v2.x para la base de datos configurada en la opción ProfileInfluxDBDatabase.
ProfileInfluxDBUser
Nombre de usuario de InfluxDB que se debe utilizar para obtener acceso a la base de datos configurada en ProfileInfluxDBDatabase. Obligatorio en v2.x y opcional en v1.x de InfluxDB. Esto solo es necesario si InfluxDB v1.x está configurado con autenticación habilitada en la sección de configuración [http] y a un usuario se le ha concedido al menos acceso de ESCRITURA a la base de datos. Véase también ProfileInfluxDBPass.
ProfileInfluxDBTimeout=<segundos>
El tiempo máximo en segundos que puede tardar una consulta HTTP al servidor InfluxDB. Después de este tiempo de espera, los datos se descartan. Tenga en cuenta que un tiempo de espera largo puede agotar sus nodos si el servidor InfluxDB no responde y, al terminar el trabajo, el último conjunto de datos tarda más de UnkillableStepTimeout en enviarse. Internamente, esa opción establece la opción de biblioteca CURLOPT_TIMEOUT. El valor predeterminado es 10 segundos.

NOTAS:

Este plugin requiere que los archivos de desarrollo de libcurl estén instalados y sean enlazables en el momento de la configuración. De lo contrario, el plugin no se compilará.

Información sobre cómo instalar y configurar InfluxDB y gestionar bases de datos, políticas de retención, etc., está disponible en la página web oficial.

La información recopilada se escribe desde cada nodo de cómputo donde se ejecuta un trabajo hacia la instancia InfluxDB que escucha en el ProfileInfluxDBHost. Para evitar sobrecargar la instancia InfluxDB con solicitudes de conexión entrantes, el plugin utiliza un búfer interno que se llena con muestras. Una vez que el búfer está lleno, se realiza una solicitud de escritura de la API HTTP y el búfer se vacía para alojar las muestras posteriores. También se realiza una solicitud final cuando una tarea termina, incluso si el búfer no está lleno.

Las solicitudes de escritura de la API HTTP que fallan se descartan silenciosamente. Esto significa que la información de perfil recopilada en el búfer del plugin se pierde si no se puede escribir en la base de datos InfluxDB por cualquier motivo.

Los mensajes del plugin se registran junto con los registros de slurmdstepd en SlurmdLogFile. Para solucionar cualquier problema, se recomienda aumentar temporalmente el nivel de depuración de slurmd a debug3 y agregar Profile a los indicadores de depuración. Esto se puede lograr estableciendo SlurmdDebug y DebugFlags en slurm.conf respectivamente, o dinámicamente a través de scontrol setdebug y setdebugflags.

Se puede usar Grafana para crear gráficos basados en los datos que posee InfluxDB. Este tipo de herramienta permite crear paneles, tablas y otros gráficos utilizando las series temporales almacenadas.

acct_gather_interconnect/OFED

Entrada requerida en slurm.conf:

AcctGatherInterconnectType=acct_gather_interconnect/ofed

Las opciones utilizadas para acct_gather_interconnect/ofed son las siguientes:

InfinibandOFEDPort=<número>
Este parámetro representa el número de puerto de la tarjeta Infiniband local que estamos dispuestos a monitorear. El puerto predeterminado es 1.
Conjuntos de datos proporcionados por el plugin: PacketsIn, PacketsOut, InMB, OutMB

acct_gather_interconnect/sysfs

Entrada requerida en slurm.conf:

AcctGatherInterconnectType=acct_gather_interconnect/sysfs

Las opciones utilizadas para acct_gather_interconnect/sysfs son las siguientes:

SysfsInterfaces=<interfaces>
Lista de nombres de interfaces separados por comas de los que recopilar estadísticas. El uso de todas las interfaces enumeradas se sumará en conjunto y no se desglosará individualmente.
Conjuntos de datos proporcionados por el plugin: PacketsIn, PacketsOut, InMB, OutMB

EJEMPLO

###
# Archivo de configuración de acct_gather de Slurm
###
# Parámetros para el plugin acct_gather_energy/impi
EnergyIPMIFrequency=10
EnergyIPMICalcAdjustment=yes
#
# Parámetros para el plugin acct_gather_profile/hdf5
ProfileHDF5Dir=/app/slurm/profile_data
# Parametros para el plugin acct_gather_interconnect/ofed
InfinibandOFEDPort=1
