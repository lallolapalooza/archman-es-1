ACCESS(5) Manual de Formatos de Archivo ACCESS(5)

NOMBRE

access - Tabla de acceso del servidor SMTP de Postfix

SINOPSIS

postmap /etc/postfix/access
postmap -q "cadena" /etc/postfix/access
postmap -q - /etc/postfix/access <archivo_de_entrada

DESCRIPCIÓN


Este documento describe el control de acceso sobre la información del cliente SMTP remoto: nombres de host, direcciones de red y direcciones de remitente o destinatario del sobre; es implementado por el servidor SMTP de Postfix. Véase header_checks(5) o body_checks(5) para el control de acceso sobre el contenido de los mensajes de correo electrónico.

Normalmente, la tabla access(5) se especifica como un archivo de texto que sirve como entrada para el comando postmap(1) . El resultado, un archivo indexado en formato dbm o db , se utiliza para la búsqueda rápida por parte del sistema de correo. Ejecute el comando "postmap /etc/postfix/access" para reconstruir un archivo indexado después de cambiar el archivo de texto correspondiente.

Cuando la tabla se proporciona por otros medios como NIS, LDAP o SQL, se realizan las mismas búsquedas que para los archivos indexados ordinarios.

Alternativamente, la tabla se puede proporcionar como un mapa de expresiones regulares donde los patrones se dan como expresiones regulares, o las búsquedas se pueden dirigir a un servidor basado en TCP. En esos casos, las búsquedas se realizan de una manera ligeramente diferente, como se describe más adelante en "TABLAS DE EXPRESIONES REGULARES" o "TABLAS BASADAS EN TCP".

CONVERSIÓN DE MAYÚSCULAS A MINÚSCULAS

La cadena de búsqueda se convierte a minúsculas antes de la búsqueda en la base de datos. A partir de Postfix 2.3, la cadena de búsqueda no se convierte a minúsculas con tipos de base de datos como regexp: o pcre:, cuyos campos de búsqueda pueden coincidir tanto con mayúsculas como con minúsculas.

FORMATO DE LA TABLA

El formato de entrada para el comando postmap(1) es el siguiente:

patrón acción
Cuando patrón coincide con una dirección de correo, dominio o dirección de host, realice la accióncorrespondiente.
líneas en blanco y comentarios
Se ignoran las líneas vacías y las líneas que contienen solo espacios en blanco, así como las líneas cuyo primer carácter no sea espacio en blanco sea un `#'.
texto de varias líneas
Una línea lógica comienza con texto que no sea espacio en blanco. Una línea que comienza con espacio en blanco continúa una línea lógica.

PATRONES DE DIRECCIONES DE CORREO EN TABLAS INDEXADAS

Con búsquedas desde archivos indexados como DB o DBM, o desde tablas en red como NIS, LDAP o SQL, los patrones se prueban en el orden que se lista a continuación:

usuario@dominio
Coincide con la dirección de correo especificada.
dominio.tld
Coincide con dominio.tld como la parte de dominio de una dirección de correo electrónico.

El patrón dominio.tld también coincide con subdominios, pero solo cuando la cadena smtpd_access_maps está listada en la configuración de Postfix parent_domain_matches_subdomains .

.dominio.tld
Coincide con los subdominios de dominio.tld, pero solo cuando la cadena smtpd_access_maps no está listada en la configuración de Postfix parent_domain_matches_subdomains .
usuario@
Coincide con todas las direcciones de correo con la parte de usuario especificada.

Nota: la búsqueda de la dirección del remitente nulo no es posible con algunos tipos de tabla de búsqueda. Por defecto, Postfix usa <> como clave de búsqueda para tales direcciones. El valor se especifica con el parámetro smtpd_null_access_lookup_key en el archivo main.cf de Postfix.

EXTENSIÓN DE LA DIRECCIÓN DE CORREO

Cuando la parte local de una dirección de correo contiene el delimitador de destinatario opcional (por ejemplo, usuario+foo@dominio), el orden de búsqueda se convierte en: usuario+foo@dominio, usuario@dominio, dominio, usuario+foo@, y usuario@.

PATRONES DE NOMBRE/DIRECCIÓN DE HOST EN TABLAS INDEXADAS

Con búsquedas desde archivos indexados como DB o DBM, o desde tablas en red como NIS, LDAP o SQL, los siguientes patrones de búsqueda se examinan en el orden listado:

dominio.tld
Coincide con dominio.tld.

El patrón dominio.tld también coincide con subdominios, pero solo cuando la cadena smtpd_access_maps está listada en la configuración de Postfix parent_domain_matches_subdomains .

.dominio.tld
Coincide con los subdominios de dominio.tld, pero solo cuando la cadena smtpd_access_maps no está listada en la configuración de Postfix parent_domain_matches_subdomains .
red.dir.dir.dir
red.dir.dir
red.dir
red
Coincide con una dirección de host IPv4 remota o un rango de direcciones de red. Especifique uno a cuatro octetos decimales separados por ".". No especifique "[]", "/", ceros a la izquierda, ni formas hexadecimales.

Los rangos de red se coinciden truncando repetidamente el último ".octeto" de una cadena de dirección de host IPv4 remota, hasta que se encuentre una coincidencia en la tabla de acceso, o hasta que no sea posible truncar más.

NOTA: use el tipo de tabla de búsqueda cidr para especificar patrones de red/máscara de red. Véase cidr_table(5) para más detalles.

red:dir:dir:dir
red:dir:dir
red:dir
red
Coincide con una dirección de host IPv6 remota o un rango de direcciones de red. Especifique tres a ocho pares de octetos hexadecimales separados por ":", usando la forma comprimida "::" para una secuencia de pares de octetos con valor cero. No especifique "[]", "/", ceros a la izquierda, ni formas no comprimidas.

Un rango de red se coincide truncando repetidamente el último ":par_de_octetos" de una cadena de dirección de host IPv6 remota en forma comprimida, hasta que se encuentre una coincidencia en la tabla de acceso, o hasta que no sea posible truncar más.

NOTA: use el tipo de tabla de búsqueda cidr para especificar patrones de red/máscara de red. Véase cidr_table(5) para más detalles.

El soporte para IPv6 está disponible en Postfix 2.2 y versiones posteriores.

ACCIONES DE ACEPTACIÓN

OK
Acepta la dirección, etc., que coincide con el patrón.
todo-numérico
Un resultado completamente numérico se trata como OK. Este formato es generado por esquemas de autorización de retransmisión basados en direcciones como pop-before-smtp.

Para otras acciones de aceptación, véase "OTRAS ACCIONES" más abajo.

ACCIONES DE RECHAZO

La versión 2.3 y posteriores de Postfix admiten códigos de estado mejorados según lo definido en RFC 3463. Cuando no se especifica ningún código al principio del texto siguiente, Postfix inserta un código de estado mejorado predeterminado de "5.7.1" en el caso de acciones de rechazo, y "4.7.1" en el caso de acciones de diferimiento. Véase "CÓDIGOS DE ESTADO MEJORADOS" más abajo.

4NN texto
5<>NN texto
Rechaza la dirección, etc., que coincide con el patrón, y responde con el código numérico de tres dígitos y el texto. 4NN significa "inténtalo de nuevo más tarde", mientras que 5NN significa "no lo intentes de nuevo".

Las siguientes respuestas tienen un significado especial para el servidor SMTP de Postfix:

421 texto (Postfix 2.3 y posteriores)
521 texto (Postfix 2.6 y posteriores)
Después de responder con el código numérico de tres dígitos y el texto, desconecta inmediatamente del cliente SMTP. Esto libera los recursos del servidor SMTP para que puedan estar disponibles para otro cliente SMTP.
Nota: La respuesta "521" solo debe usarse con botnets y otro malware donde la interoperabilidad no sea una preocupación. El comportamiento de "enviar 521 y desconectar" NO está definido en el estándar SMTP.
REJECT texto opcional...
Rechaza la dirección, etc., que coincide con el patrón. Responde con "$access_map_reject_code texto opcional..." cuando se especifica el texto opcional, de lo contrario responde con un mensaje de error genérico.
DEFER texto opcional...
Rechaza la dirección, etc., que coincide con el patrón. Responde con "$access_map_defer_code texto opcional..." cuando se especifica el texto opcional, de lo contrario responde con un mensaje de error genérico.

Esta función está disponible en Postfix 2.6 y posteriores.

DEFER_IF_REJECT texto opcional...
Aplaz el solicitud si alguna restricción posterior resultara en una acción REJECT. Responde con "$access_map_defer_code 4.7.1 texto opcional..." cuando se especifica el texto opcional, de lo contrario responde con un mensaje de error genérico.

Antes de Postfix 2.6, el código de respuesta SMTP es 450.

Esta función está disponible en Postfix 2.1 y posteriores.

DEFER_IF_PERMIT texto opcional...
Aplaz la solicitud si alguna restricción posterior resultara en una acción PERMIT explícita o implícita. Responde con "$access_map_defer_code 4.7.1 texto opcional..." cuando se especifica el texto opcional, de lo contrario responde con un mensaje de error genérico.

Antes de Postfix 2.6, el código de respuesta SMTP es 450.

Esta función está disponible en Postfix 2.1 y posteriores.

Para otras acciones de rechazo, véase "OTRAS ACCIONES" más abajo.

BASADAS EN CP

Esta sección describe cómo cambian las búsquedas en tablas cuando las búsquedas se dirigen a un servidor basado en TCP. Para una descripción del protocolo de búsqueda cliente/servidor TCP, consulte tcp_table(5). Esta función no está disponible hasta e incluyendo la versión 2.4 de Postfix.

Cada operación de búsqueda utiliza la cadena de consulta completa una sola vez. Dependiendo de la aplicación, esa cadena es el nombre de host completo del cliente, la dirección IP completa del cliente o la dirección de correo electrónico completa. Por lo tanto, no se realiza ninguna búsqueda de dominio padre o red padre, user@domain las direcciones de correo electrónico no se dividen en sus partes constitutivas user@ y domain , ni user+foo se divide en user y foo.

Las acciones son las mismas que con las búsquedas en archivos indexados.

EJEMPLO

El siguiente ejemplo utiliza un archivo indexado, por lo que el orden de las entradas de la tabla no importa. El ejemplo permite el acceso por parte del cliente en la dirección 1.2.3.4 pero rechaza a todos los demás clientes en 1.2.3.0/24. En lugar de hash tablas de búsqueda, algunos sistemas utilizan dbm. Utilice el comando "postconf -m" para averiguar qué tablas de búsqueda admite Postfix en su sistema.

/etc/postfix/main.cf:
    smtpd_client_restrictions =
        check_client_access hash:/etc/postfix/access
/etc/postfix/access:
    1.2.3   REJECT
    1.2.3.4 OK

Ejecute el comando "postmap /etc/postfix/access" después de editar el archivo.
