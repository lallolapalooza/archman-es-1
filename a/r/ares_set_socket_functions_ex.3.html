NAME

ares_set_socket_functions_ex, ares_set_socket_functions - set socket functions

SYNOPSIS

#include <ares.h>

typedef void (*ares_sockstate_cb_t)(void *user_data, ares_socket_t fd, int read_fd, int write_fd);

typedef int (*ares_sockmake_cb_t)(int domain, int type, int protocol, ares_socket_t *fd, void *user_data);

typedef int (*ares_sockclose_cb_t)(ares_socket_t fd, void *user_data);

typedef int (*ares_sockconnect_cb_t)(ares_socket_t fd, const struct sockaddr *addr, ares_socklen_t addrlen, void *user_data);

typedef ares_ssize_t (*ares_sockrecvfrom_cb_t)(ares_socket_t fd, void *buffer, size_t bufsiz, int flags, struct sockaddr *addr, ares_socklen_t *addrlen, void *user_data);

typedef ares_ssize_t (*ares_sendsock_cb_t)(ares_socket_t fd, const void *buf, size_t count, int flags, void *user_data);

typedef ares_ssize_t (*ares_sendvsock_cb_t)(ares_socket_t fd, const struct iovec *data, int len, void *user_data);

typedef int (*ares_socksetopt_cb_t)(ares_socket_t fd, int level, int option, const void *value, ares_socklen_t optlen, void *user_data);

typedef int (*ares_sockgetsockname_cb_t)(ares_socket_t fd, struct sockaddr *addr, ares_socklen_t *addrlen, void *user_data);

typedef int (*ares_sockgetpeername_cb_t)(ares_socket_t fd, struct sockaddr *addr, ares_socklen_t *addrlen, void *user_data);

int ares_set_socket_functions(ares_channel_t *channel, ares_sockmake_cb_t make_callable, ares_sockclose_cb_t close_callable, ares_sockconnect_cb_t connect_callable, ares_sockrecvfrom_cb_t recvfrom_callable, ares_sendsock_cb_t send_callable, ares_sendvsock_cb_t sendv_callable, void *user_data);

DESCRIPTION

The ares_set_socket_functions_ex() function allows the user to supply their own socket functions to be used by c-ares for network communication. This can be used to integrate c-ares into an existing event loop or other framework that manages sockets.

The ares_set_socket_functions() function is an older version of ares_set_socket_functions_ex() that offers fewer callbacks and has different handling of socket options and interface indexing.

The user_data parameter is passed as the last argument to each of the supplied callback functions. This allows the user to pass context information into the callbacks.

The following socket functions are supported by ares_set_socket_functions_ex():

ares_sockmake_cb_t make_callable

Creates a socket. The parameters domain, type, and protocol are the same as for socket(2). The created socket file descriptor is returned in fd. It should return ares error code, 0 on success, or a positive value representing an error code that is compatible with the system error codes (e.g. POSIX errno(2) values).
ares_sockclose_cb_t close_callable

Closes the socket. The parameter fd is the socket file descriptor to close. Should return 0 on success, or a positive value representing an error code on failure. See close(2).
ares_sockconnect_cb_t connect_callable

Initiates a connection on the socket. The parameters fd, addr, and addrlen are the same as for connect(2). It should return 0 on success, or a positive value representing an error code on failure. It is strongly recommended that this function behave asynchronously and return EAGAIN or EWOULDBLOCK if the connection would otherwise block.
ares_sockrecvfrom_cb_t recvfrom_callable

Receives data from the socket. The parameters fd, buffer, bufsiz, flags, addr, and addrlen are the same as for recvfrom(2). It should return the number of bytes received, 0 on EOF, or a negative value representing an error code on failure. It is strongly recommended that this function behave asynchronously and return EAGAIN or EWOULDBLOCK if no data is available.
ares_sendsock_cb_t send_callable

Sends data on the socket. The parameters fd, buf, count, and flags are the same as for send(2). It should return the number of bytes sent, or a negative value representing an error code on failure. It is strongly recommended that this function behave asynchronously and return EAGAIN or EWOULDBLOCK if the socket is not ready for sending.
ares_sendvsock_cb_t sendv_callable

Sends data from a scatter-gather buffer on the socket. The parameters fd, data, and len are the same as for writev(2). It should return the number of bytes sent, or a negative value representing an error code on failure. It is strongly recommended that this function behave asynchronously and return EAGAIN or EWOULDBLOCK if the socket is not ready for sending.
ares_socksetopt_cb_t setopt_callable

Sets socket options. The parameters fd, level, option, value, and optlen are the same as for setsockopt(2). It should return 0 on success, or a positive value representing an error code on failure. Supported options include SO_SNDBUF, SO_RCVBUF, SO_BINDTODEVICE, and TCP_FASTOPEN (if available).
ares_sockgetsockname_cb_t getsockname_callable

Retrieves the local address of the socket. The parameters fd, addr, and addrlen are the same as for getsockname(2). It should return 0 on success, or a positive value representing an error code on failure.
ares_sockgetpeername_cb_t getpeername_callable

Retrieves the remote address of the socket. The parameters fd, addr, and addrlen are the same as for getpeername(2). It should return 0 on success, or a positive value representing an error code on failure.
ares_sockif_nametoindex_cb_t if_nametoindex_callable

Converts an interface name to its index. The parameter ifname is the interface name. It should return the interface index on success, or 0 on failure. See if_nametoindex(2). This callback is optional. If not provided, IPv6 link-local DNS servers cannot be used.
ares_sockif_indextoname_cb_t if_indextoname_callable

Converts an interface index to its name. The parameters ifindex, ifname_buf, and ifname_buf_len are the same as for if_indextoname(2). It should return a pointer to ifname_buf on success, or NULL on failure. This callback is optional. If not provided, IPv6 link-local DNS servers cannot be used.
ares_sockstate_cb_t state_callable

Called when the state of a socket changes, indicating that it is ready for reading or writing, or when it has been closed. The parameters fd, read_fd, and write_fd indicate the socket and its new state. read_fd is non-zero if the socket is ready for reading, and write_fd is non-zero if the socket is ready for writing. If both are zero, the socket has been closed.

The ares_set_socket_functions() function supports a subset of the callbacks provided by ares_set_socket_functions_ex(). It is missing callbacks for setopt, getsockname, getpeername, if_nametoindex, if_indextoname, and state notification. It also binds the socket to an address and port for client connections before connect, or for server connections before listening. Currently c-ares only supports client connections.

The structure passed to ares_set_socket_functions_ex() is copied and does not need to remain valid after the call. The structure passed to ares_set_socket_functions() is not copied and must remain valid.

The following flags can be used with the socket functions:

ARES_SOCKFUNC_FLAG_NONBLOCKING

Used to indicate that the io functions are asynchronous.

The following options can be set using setopt_callable:

ARES_SOCKET_OPT_SENDBUF_SIZE

Set the send buffer size. The value is a pointer to an int (SO_SNDBUF).
ARES_SOCKET_OPT_RECVBUF_SIZE

Set the receive buffer size. The value is a pointer to an int (SO_RCVBUF).
ARES_SOCKET_OPT_BIND_DEVICE

Set the network interface to use as the source for communication. The value is a C string (SO_BINDTODEVICE).
ARES_SOCKET_OPT_TCP_FASTOPEN

Enable TCP Fast Open. The value is a pointer to an ares_bool_t. On some systems this could be a no-op if it is known to be on by default and return success. Other systems may be a no-op if known the system does not support the feature and returns failure with errno set to ENOSYS or WSASetLastError(WSAEOPNOTSUPP);.

The following flags can be used with the connect function:

ARES_SOCKET_CONN_TCP_FASTOPEN

Connect using TCP Fast Open.

The following flags can be used with the bind function (only in ares_set_socket_functions()):

ARES_SOCKET_BIND_TCP

Bind is for a TCP connection.
ARES_SOCKET_BIND_CLIENT

Bind is for a client connection, not server.

All callback functions are expected to operate like their system equivalents, and to set errno(2) or WSASetLastError(2) to an appropriate error code on failure. It is strongly recommended all io functions behave asynchronously and return error codes of EAGAIN, EWOULDBLOCK, or WSAEWOULDBLOCK when they would otherwise block.

The ares_set_socket_functions() must provide the following callbacks:

ares_socket_t (*asocket)(int domain, int type, int protocol, void * user_data)

Creates an endpoint for communication and returns a descriptor. domain, type, and protocol each correspond to the parameters of socket(2). Returns a handle to the newly created socket, or ARES_SOCKET_BAD on error.
int (*aclose)(ares_socket_t fd, void * user_data)

Closes the socket endpoint indicated by fd. See close(2).
int (*aconnect)(ares_socket_t fd, const struct sockaddr * addr, ares_socklen_t addr_len, void * user_data)

Initiate a connection to the address indicated by addr on a socket. See connect(2)
ares_ssize_t (*arecvfrom)(ares_socket_t fd, void * buffer, size_t buf_size, int flags, struct sockaddr * addr, ares_socklen_t * addr_len, void * user_data)

Receives data from remote socket endpoint, if available. If the addr parameter is not NULL and the connection protocol provides the source address, the callback should fill this in. See recvfrom(2)
ares_ssize_t (*asendv)(ares_socket_t fd, const struct iovec * data, int len, void * user_data)

Send data, as provided by the iovec array data, to the socket endpoint. See writev(2)

The ares_set_socket_functions() struct provided is not copied but directly referenced, and must thus remain valid through out the channels and any created socket's lifetime. However, the ares_set_socket_functions_ex() struct is duplicated and does not need to survive past the call to the function.
