NOMBRE

arp-fingerprint - Identificar un sistema usando ARP

SINOPSIS

arp-fingerprint [opciones] objetivo

El objetivo debe especificarse como una única dirección IP o nombre de host. No se pueden especificar múltiples objetivos, redes IP o rangos.

Si se usa una dirección IP como objetivo, se puede usar la opción -o para pasar la opción --numeric a arp-scan, lo que evitará que intente resoluciones DNS. Esto puede acelerar el proceso de identificación, especialmente en sistemas con una configuración DNS lenta o defectuosa.

DESCRIPCIÓN

arp-fingerprint identifica el host objetivo especificado usando el protocolo ARP.

Envía varios tipos diferentes de solicitudes ARP al objetivo y registra a cuáles responde. A partir de esto, construye una cadena de huella digital que consiste en "1" donde el objetivo respondió y "0" donde no lo hizo. Un ejemplo de cadena de huella digital es 01000100000. Esta cadena de huella digital se utiliza luego para buscar el sistema operativo probable del objetivo.

Muchas de las cadenas de huella digital son compartidas por varios sistemas operativos, por lo que no siempre hay una correspondencia uno a uno entre cadenas de huella digital y sistemas operativos. Además, el hecho de que la huella digital de un sistema coincida con un sistema operativo específico (o una lista de sistemas operativos) no significa necesariamente que el sistema que se está identificando sea ese sistema operativo, aunque es bastante probable. Esto se debe a que la lista de sistemas operativos no es exhaustiva; es solo lo que he descubierto hasta la fecha, y seguramente hay sistemas operativos que no están listados.

La huella digital ARP de un sistema es generalmente una función de su kernel (aunque es posible que la función ARP se implemente en el espacio de usuario, casi nunca es así).

A veces, un sistema operativo puede dar diferentes huellas digitales dependiendo de la configuración. Un ejemplo es Linux, que responderá a una dirección IP de origen no local si esa IP está enrutada a través de la interfaz que se está probando. Esto es bueno y malo: por un lado, hace que la tarea de identificación sea más compleja; pero por otro lado, puede permitir determinar algunos aspectos de la configuración del sistema.

A veces, el hecho de que dos sistemas operativos diferentes compartan una cadena de huella digital ARP común apunta a una reutilización de código de red. Un ejemplo de esto es Windows NT y FreeBSD.

arp-fingerprint utiliza arp-scan para enviar las solicitudes ARP y recibir las respuestas.

Existen otros métodos que se pueden usar para identificar un sistema usando arp-scan y que se pueden usar además de arp-fingerprint. Estos métodos adicionales no se incluyen en arp-fingerprint porque es probable que causen interrupciones en el sistema objetivo, o porque requieren conocimiento de la configuración del objetivo que puede que no siempre esté disponible.

La mayoría de las solicitudes ARP que envía arp-fingerprint no son estándar, por lo que podría interrumpir sistemas que no tengan una pila TCP/IP robusta.

OPCIONES

-h
Muestra un breve mensaje de uso y sale.
-v
Muestra mensajes de progreso detallados.
-o <cadena-opcion>
Pasa las opciones especificadas a arp-scan. Debe encerrar la cadena de opciones entre comillas si contiene espacios. por ejemplo: -o "-I eth1". Las opciones usadas comúnmente son --interface (-I) y --numeric (-N).
-l
Identifica todos los hosts en la red local. No necesita especificar ningún host objetivo si se da esta opción.

EJEMPLOS

$ arp-fingerprint 192.168.0.1
192.168.0.1   01000100000     Linux 2.2, 2.4, 2.6
$ arp-fingerprint -o "-N -I eth1" 192.168.0.202
192.168.0.202 11110100000     FreeBSD 5.3, Win98, WinME, NT4, 2000, XP, 2003

NOTAS

arp-fingerprint está implementado en Perl, por lo que necesita tener el intérprete de Perl instalado en su sistema para usarlo.
