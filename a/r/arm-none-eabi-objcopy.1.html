DESCRIPCIÓN

La utilidad GNU objcopy copia el contenido de un archivo de objeto a otro. objcopy usa la Biblioteca GNU BFD para leer y escribir los archivos de objeto. Puede escribir el archivo de objeto de destino en un formato diferente al del archivo de objeto de origen. El comportamiento exacto de objcopy está controlado por las opciones de la línea de comandos. Tenga en cuenta que objcopy debería poder copiar un archivo completamente enlazado entre cualquier par de formatos. Sin embargo, copiar un archivo de objeto relocatable entre cualquier par de formatos puede no funcionar como se espera.

objcopy crea archivos temporales para realizar sus traducciones y los elimina después. objcopy usa BFD para realizar todo su trabajo de traducción; tiene acceso a todos los formatos descritos en BFD y por lo tanto es capaz de reconocer la mayoría de los formatos sin que se le indique explícitamente.

objcopy se puede usar para generar registros S utilizando como destino de salida srec (por ejemplo, use -O srec).

objcopy se puede usar para generar un archivo binario sin procesar utilizando como destino de salida binary (por ejemplo, use -O binary). Cuando objcopy genera un archivo binario sin procesar, producirá esencialmente un volcado de memoria del contenido del archivo de objeto de entrada. Todos los símbolos y la información de reubicación serán descartados. El volcado de memoria comenzará en la dirección de carga de la sección más baja copiada en el archivo de salida.

Al generar un registro S o un archivo binario sin procesar, puede ser útil usar -S para eliminar secciones que contengan información de depuración. En algunos casos -R será útil para eliminar secciones que contengan información que no es necesaria para el archivo binario.

Nota---objcopy no es capaz de cambiar la codificación de orden de los bytes (endianness) de sus archivos de entrada. Si el formato de entrada tiene una codificación de orden de los bytes (algunos formatos no la tienen), objcopy solo puede copiar las entradas en formatos de archivo que tengan la misma codificación de orden de los bytes o que no tengan ninguna (por ejemplo, srec). (Sin embargo, consulte la opción --reverse-bytes .)

--debugging
Convertir información de depuración, si es posible. Esto no es lo predeterminado porque solo se admiten ciertos formatos de depuración, y el proceso de conversión puede ser largo.
--gap-fill val
Rellenar los huecos entre secciones con val. Esta operación se aplica a la dirección de carga (LMA) de las secciones. Se hace aumentando el tamaño de la sección con la dirección más baja, y rellenando el espacio extra creado con val.
--pad-to address
Rellenar el archivo de salida hasta la dirección de carga address. Esto se hace aumentando el tamaño de la última sección. El espacio extra se rellena con el valor especificado por --gap-fill (cero por defecto).
--set-start val
Establecer la dirección de inicio (también conocida como dirección de entrada) del nuevo archivo en val. No todos los formatos de archivos de objeto admiten establecer la dirección de inicio.
--change-start incr
--adjust-start incr
Cambiar la dirección de inicio (también conocida como dirección de entrada) añadiendo incr. No todos los formatos de archivos de objeto admiten establecer la dirección de inicio.
--change-addresses incr
--adjust-vma incr
Cambiar las direcciones VMA y LMA de todas las secciones, así como la dirección de inicio, añadiendo incr. Algunos formatos de archivos de objeto no permiten cambiar las direcciones de las secciones arbitrariamente. Tenga en cuenta que esto no reubica las secciones; si el programa espera que las secciones se carguen en una dirección determinada, y se usa esta opción para cambiar las secciones de modo que se carguen en una dirección diferente, el programa puede fallar.
--change-section-address sectionpattern{=,+,-}val
--adjust-section-vma sectionpattern{=,+,-}val
Establecer o cambiar tanto la dirección VMA como la dirección LMA de cualquier sección que coincida con sectionpattern. Si se usa = , la dirección de la sección se establece en val. De lo contrario, val se añade o se resta de la dirección de la sección. Véanse los comentarios bajo --change-addresses, más arriba. Si sectionpattern no coincide con ninguna sección en el archivo de entrada, se emitirá una advertencia, a menos que se use --no-change-warnings .
--change-section-lma sectionpattern{=,+,-}val
Establecer o cambiar la dirección LMA de cualquier sección que coincida con sectionpattern. La dirección LMA es la dirección en la que la sección se cargará en la memoria en el momento de la carga del programa. Normalmente esta es la misma que la dirección VMA, que es la dirección de la sección en tiempo de ejecución del programa, pero en algunos sistemas, especialmente aquellos donde un programa reside en ROM, las dos pueden ser diferentes. Si se usa = , la dirección de la sección se establece en val. De lo contrario, val se añade o se resta de la dirección de la sección. Véanse los comentarios bajo --change-addresses, más arriba. Si sectionpattern no coincide con ninguna sección en el archivo de entrada, se emitirá una advertencia, a menos que se use --no-change-warnings .
--change-section-vma sectionpattern{=,+,-}val
Establecer o cambiar la dirección VMA de cualquier sección que coincida con sectionpattern. La dirección VMA es la dirección en la que la sección estará una vez que el programa haya comenzado a ejecutarse. Normalmente esta es la misma que la dirección LMA, que es la dirección en la que la sección se cargará en la memoria, pero en algunos sistemas, especialmente aquellos donde un programa reside en ROM, las dos pueden ser diferentes. Si se usa = , la dirección de la sección se establece en val. De lo contrario, val se añade o se resta de la dirección de la sección. Véanse los comentarios bajo --change-addresses, más arriba. Si sectionpattern no coincide con ninguna sección en el archivo de entrada, se emitirá una advertencia, a menos que se use --no-change-warnings .

Nota: cambiar la VMA de las secciones en un binario completamente enlazado puede ser peligroso, ya que puede haber código que espere que las secciones estén ubicadas en su dirección antigua.

--change-warnings
--adjust-warnings
Si se usa --change-section-address o --change-section-lma o --change-section-vma , y el patrón de sección no coincide con ninguna sección, emitir una advertencia. Esto es lo predeterminado.
--no-change-warnings
--no-adjust-warnings
No emitir una advertencia si se usa --change-section-address o --adjust-section-lma o --adjust-section-vma , incluso si el patrón de sección no coincide con ninguna sección.
--set-section-flags sectionpattern=flags
Establecer los indicadores para cualquier sección que coincida con sectionpattern. El argumento flags es una cadena de nombres de indicadores separados por comas. Los nombres reconocidos son alloc, contents, load, noload, readonly, code, data, rom, exclude, share, debugy large. Puede establecer el indicador contents para una sección que no tiene contenido, pero no tiene sentido borrar el indicador contents de una sección que sí tiene contenido; simplemente elimine la sección. No todos los indicadores son significativos para todos los formatos de archivos de objeto. En particular, el indicador share solo es significativo para archivos de formato COFF y no para archivos de formato ELF. El indicador específico de ELF x86-64 large corresponde a SHF_X86_64_LARGE.
--set-section-alignment sectionpattern=align
Establecer la alineación para cualquier sección que coincida con sectionpattern. align especifica la alineación en bytes y debe ser una potencia de dos, es decir, 1, 2, 4, 8....

Nota: establecer la alineación de una sección no alineará automáticamente sus direcciones LMA o VMA. Si también necesitan ser cambiadas, entonces deben usarse las opciones --change-section-lma y/o --change-section-vma . Tenga en cuenta también que cambiar las VMA puede causar problemas en binarios completamente enlazados donde puede haber código que espere que el contenido de las secciones esté ubicado en su dirección antigua.

--add-section sectionname=filename
Añadir una nueva sección llamada sectionname mientras se copia el archivo. El contenido de la nueva sección se toma del archivo filename. El tamaño de la sección será el tamaño del archivo. Esta opción solo funciona en formatos de archivo que pueden admitir secciones con nombres arbitrarios. Nota: puede ser necesario usar la opción --set-section-flags para establecer los atributos de la sección recién creada.
--dump-section sectionname=filename
Colocar el contenido de la sección llamada sectionname en el archivo filename, sobrescribiendo cualquier contenido que pueda haber tenido previamente. Esta opción es lo inverso de --add-section. Esta opción es similar a la opción --only-section excepto que no crea un archivo formateado, solo vuelca el contenido como datos binarios en bruto, sin aplicar ninguna reubicación. La opción puede especificarse más de una vez.
--update-section sectionname=filename
Reemplazar el contenido existente de una sección llamada sectionname con el contenido del archivo filename. El tamaño de la sección se ajustará al tamaño del archivo. Los indicadores de la sección para sectionname no cambiarán. Para archivos de formato ELF, el mapeo de sección a segmento también permanecerá sin cambios, algo que no es posible usando --remove-section seguido de --add-section. La opción puede especificarse más de una vez.

Nota: es posible usar --rename-section y --update-section para actualizar y renombrar una sección desde una sola línea de comando. En este caso, pase el nombre original de la sección a --update-section, y los nombres original y nuevo de la sección a --rename-section.

--add-symbol name=[section:]value[,flags]
Añadir un nuevo símbolo llamado name mientras se copia el archivo. Esta opción puede especificarse varias veces. Si se proporciona section , el símbolo se asociará con esa sección y será relativo a ella, de lo contrario será un símbolo ABS. Especificar una sección no definida resultará en un error fatal. No se comprueba el valor, se tomará tal como se especificó. Se pueden especificar indicadores de símbolo y no todos los indicadores serán significativos para todos los formatos de archivo de objeto. Por defecto, el símbolo será global. El indicador especial 'before=othersym' insertará el nuevo símbolo delante del especificado othersym, de lo contrario, el(los) símbolo(s) se añadirá(n) al final de la tabla de símbolos en el orden en que aparecen.
--rename-section oldname=newname[,flags]
Renombrar una sección de oldname a newname, cambiando opcionalmente los indicadores de la sección a flags en el proceso. Esto tiene la ventaja sobre usar un script de enlazador para realizar el cambio de nombre en que el[ { "heading": "--rename-section", "content": "Renombra una sección.

El formato es:\n--rename-section from=to[,flags]\n

\n

Esto renombrará la sección llamada from a to. Si una sección de entrada no se nombra, el campo from se puede omitir y todas las secciones que coincidan con los bits de flags se renombrarán a to. Si el campo to se omite, la sección se eliminará. El campo flags es una lista separada por comas de indicadores de sección. Consulte la descripción de --set-section-flags para conocer los indicadores disponibles.

DESCRIPTION

The objcopy utility can copy a symbolic information from one object file to another. It can be used to change the symbolic debugging information with the options --strip-debug, --strip-unneeded, --strip-all, and --strip-sectors. It can also be used to change the format of an object file, for instance to convert from one architecture to another, or to convert to a different endianness.

objcopy can also be used to create a binary dump of a section of an object file.

The formats of the input and output files are determined by BFD.

A number of options allow for the modification of an object file.

objcopy uses the Binary File Descriptor (BFD) library to handle object files. This means that it can support any object file format for which BFD has support.

When copying an object file, objcopy may perform any requested modifications. If no modifications are requested, objcopy can still be used to change the format of an object file. This is particularly useful for converting between object file formats that are not directly compatible.

The options -I, -O, and -F can be used to specify the input and output file formats.

The option -R can be used to remove a section from an object file.

The option -S can be used to remove symbol table entries from an object file.

The option -x can be used to remove all symbol table entries except for the local symbols.

The option -w can be used to suppress all warnings.

The option -W can be used to remove a symbol from an object file.

Other options allow for the modification of section addresses, contents, and names. The --change-addresses option can be used to add an offset to all the addresses in an object file. The --change-section-address, --change-section-contents, --change-section-dims, --change-section-loadaddr, and --change-section-name options allow for more fine-grained control over section modification.

The --set-start option can be used to change the entry point of an object file.

The --verilog-data-width option is used for Verilog output. It controls the number of bytes converted for each output data element. The input target controls the endianness of the conversion.

The --verbose option will list all object files modified. In the case of archives, -V lists all members of the archive.

The --help option shows a summary of the options to objcopy.

The --info option displays a list showing all architectures and object formats available.

For Verilog output, this options controls the number of bytes converted for each output data element. The input target controls the endianness of the conversion.
-v
--verbose
Verbose output: list all object files modified. In the case of archives, objcopy -V lists all members of the archive.
--help

--info
Display a list showing all architectures and object formats available.
@file
Read command-line options from file. The options read are inserted in place of the original @file option. If file does not exist, or cannot be read, then the option will be treated literally, and not removed.

Options in file are separated by whitespace. A whitespace character may be included in an option by surrounding the entire option in either single or double quotes. Any character (including a backslash) may be included by prefixing the character to be included with a backslash. The file may itself contain additional @file options; any such options will be processed recursively.
