DESCRIPCIÓN

archive_read_support_format_7zip(), archive_read_support_format_ar(), archive_read_support_format_cab(), archive_read_support_format_cpio(), archive_read_support_format_iso9660(), archive_read_support_format_lha(), archive_read_support_format_mtree(), archive_read_support_format_rar(), archive_read_support_format_rar5(), archive_read_support_format_raw(), archive_read_support_format_tar(), archive_read_support_format_warc(), archive_read_support_format_xar(), archive_read_support_format_zip()
Habilita el soporte —incluido el código de auto-detección— para el formato de archivo especificado. Por ejemplo, archive_read_support_format_tar() habilita el soporte para una variedad de formatos tar estándar, tar de estilo antiguo, ustar, formato de intercambio pax, y muchas variantes comunes. archive_read_support_format_zip() habilita el soporte tanto para los lectores de zip en streaming como para los que permiten búsqueda; estos pueden ser habilitados por separado mediante archive_read_support_format_zip_streamable() y archive_read_support_format_zip_seekable() respectivamente.
archive_read_support_format_all()
Habilita el soporte para todos los formatos disponibles excepto el formato "raw" (ver más abajo).
archive_read_support_format_by_code()
Habilita un único formato especificado por su código. Esto puede ser útil al leer un solo archivo dos veces; usa archive_format() después de la primera lectura y pasa el código resultante a esta función para habilitar selectivamente solo el soporte de formato necesario. Nota: En ejecutables enlazados estáticamente, esto hará que tu programa incluya soporte para todos los formatos. Si el tamaño del ejecutable es una preocupación, puede que desees evitar usar esta función.
archive_read_support_format_empty()
Habilita el soporte para tratar archivos vacíos como archivos vacíos. Debido a que los archivos vacíos son válidos para varios formatos diferentes, no es posible determinar con precisión un formato para un archivo vacío basándose únicamente en su contenido. Por lo tanto, libarchive trata los archivos vacíos como un formato distinto.

archive_read_format(3) — libarchive — Arch Linux

NAME

archive_read_format, archive_read_support_format_raw - support for reading raw, uncompressed data streams

LIBRARY

libarchive library

SYNOPSIS

#include <archive_read.h>

int archive_read_support_format_raw(archive_read_t *archive);

DESCRIPTION

The archive_read_support_format_raw() function enables support for reading arbitrary data streams. It treats any data stream as an archive with a single entry. The pathname of this entry is “data”; all other entry fields are unset. This is not enabled by archive_read_support_format_all() in order to avoid erroneous handling of damaged archives.

RETURN VALUES

These functions return ARCHIVE_OK on success, or ARCHIVE_FATAL.

ERRORS

Detailed error codes and textual descriptions are available from the archive_errno() and archive_error_string() functions.

SEE ALSO

tar(1), archive_read_data(3), archive_read_filter(3), archive_read_set_options(3), archive_util(3), libarchive(3), tar(5)

BUGS

Many traditional archiver programs treat empty files as valid empty archives. For example, many implementations of tar(1) allow you to append entries to an empty file. Of course, it is impossible to determine the format of an empty file by inspecting the contents, so this library treats empty files as having a special “empty” format.

Using the “raw” handler together with any other handler will often work but can produce surprising results.
