ARCHIVE_READ(3) Manual de Funciones de Biblioteca ARCHIVE_READ(3)

NOMBRE

archive_read — funciones para leer archivos comprimidos en flujo

BIBLIOTECA

Biblioteca de Archivos en Flujo (libarchive, -larchive)

SINOPSIS

#include <archive.h>

DESCRIPCIÓN

Estas funciones proporcionan una API completa para leer archivos comprimidos en flujo. El proceso general es primero crear el objeto struct archive, establecer opciones, inicializar el lector, iterar sobre los encabezados del archivo y los datos asociados, luego cerrar el archivo y liberar todos los recursos.

Crear objeto archivo

Vea archive_read_new(3).

Para leer un archivo, primero debe obtener un objeto struct archive inicializado de archive_read_new().

Habilitar filtros y formatos

Vea archive_read_filter(3) y archive_read_format(3).

Luego puede modificar este objeto para las operaciones deseadas con las diversas funciones archive_read_set_XXX() y archive_read_support_XXX() . En particular, necesitará invocar las funciones archive_read_support_XXX() apropiadas para habilitar el soporte de compresión y formato correspondiente. Tenga en cuenta que estas últimas funciones realizan dos operaciones distintas: hacen que el código de soporte correspondiente se enlace en su programa, y habilitan el código de autodetección correspondiente. A menos que tenga restricciones específicas, generalmente querrá invocar archive_read_support_filter_all() y archive_read_support_format_all() para habilitar la autodetección para todos los formatos y tipos de compresión actualmente soportados por la biblioteca.

Establecer opciones

Vea archive_read_set_options(3).

Abrir archivo

Vea archive_read_open(3).

Una vez que haya preparado el objeto struct archive, llama a archive_read_open() para abrir realmente el archivo y prepararlo para la lectura. Hay varias variantes de esta función; la más básica espera que usted proporcione punteros a varias funciones que pueden proporcionar bloques de bytes del archivo. Hay formas de conveniencia que le permiten especificar un nombre de archivo, un descriptor de archivo, FILE * objeto, o un bloque de memoria del cual leer los datos del archivo. Tenga en cuenta que la biblioteca principal no hace suposiciones sobre el tamaño de los bloques leídos; las funciones de retorno de llamada son libres de leer el tamaño de bloque que sea más apropiado para el medio.

Consumir archivo

Vea archive_read_header(3), archive_read_data(3) y archive_read_extract(3).

Cada entrada de archivo consiste en un encabezado seguido de una cierta cantidad de datos. Puede obtener el siguiente encabezado con archive_read_next_header(), que devuelve un puntero a una estructura struct archive_entry con información sobre el elemento actual del archivo. Si la entrada es un archivo regular, entonces el encabezado será seguido por los datos del archivo. Puede usar archive_read_data() (que funciona mucho como la llamada al sistema read(2) ) para leer estos datos del archivo, o archive_read_data_block() que proporciona una interfaz ligeramente más eficiente. Puede preferir usar el nivel superior archive_read_data_skip(), que lee y descarta los datos de esta entrada, archive_read_data_into_fd(), que copia los datos al descriptor de archivo proporcionado, o archive_read_extract(), que recrea la entrada especificada en el disco y copia los datos del archivo. En particular, tenga en cuenta que archive_read_extract() usa la estructura struct archive_entry que usted le proporciona, la cual puede diferir de la entrada recién leída del archivo. En particular, muchas aplicaciones querrán sobrescribir la ruta del archivo, los permisos del archivo o la propiedad.

Liberar recursos

Vea archive_read_free(3).

Una vez que haya terminado de leer datos del archivo, debería llamar a archive_read_close() para cerrar el archivo, luego llamar a archive_read_free() para liberar todos los recursos, incluyendo toda la memoria asignada por la biblioteca.

EJEMPLOS

Lo siguiente ilustra el uso básico de la biblioteca. En este ejemplo, las funciones de retorno de llamada son simplemente envoltorios alrededor de las llamadas al sistema estándar open(2), read(2), y close(2) .

void
list_archive(const char *name)
{
  struct mydata *mydata;
  struct archive *a;
  struct archive_entry *entry;

  mydata = malloc(sizeof(struct mydata));
  a = archive_read_new();
  mydata->name = name;
  archive_read_support_filter_all(a);
  archive_read_support_format_all(a);
  archive_read_open(a, mydata, myopen, myread, myclose);
  while (archive_read_next_header(a, &entry) == ARCHIVE_OK) {
    printf("%s\n",archive_entry_pathname(entry));
    archive_read_data_skip(a);
  }
  archive_read_free(a);
  free(mydata);
}

la_ssize_t
myread(struct archive *a, void *client_data, const void **buff)
{
  struct mydata *mydata = client_data;

  *buff = mydata->buff;
  return (read(mydata->fd, mydata->buff, 10240));
}

int
myopen(struct archive *a, void *client_data)
{
  struct mydata *mydata = client_data;

  mydata->fd = open(mydata->name, O_RDONLY);
  return (mydata->fd >= 0 ? ARCHIVE_OK : ARCHIVE_FATAL);
}

int
myclose(struct archive *a, void *client_data)
{
  struct mydata *mydata = client_data;

  if (mydata->fd > 0)
    close(mydata->fd);
  return (ARCHIVE_OK);
}

ERRORES

Muchos programas archivadores tradicionales tratan los archivos vacíos como archivos vacíos válidos. Por ejemplo, muchas implementaciones de tar(1) te permiten añadir entradas a un archivo vacío. Por supuesto, es imposible determinar el formato de un archivo vacío inspeccionando su contenido, por lo que esta biblioteca trata los archivos vacíos como si tuvieran un formato especial de “vacío”.
