archive_write_ope
n()
Congela la configuración, abre el archivo y se prepara para escribir entradas. Esta es la forma más genérica de esta función, que acepta punteros a tres funciones de retorno que serán invocadas por la capa de compresión para escribir el archivo construido. Esto no altera el relleno predeterminado del
archivo.

d()
Una forma conveniente de archive_write_open() que acepta un descriptor de archivo. La archive_write_open_fd() función es segura para usar con unidades de cinta u otros dispositivos orientados a
bloques.
archive_write_open_FIL
E()
Una forma conveniente de archive_write_open() que acepta un FILE * puntero. Tenga en cuenta que archive_write_open_FILE() no es seguro para escribir en unidades de cinta u otros dispositivos que requieran un bloqueo
correcto.
archive_write_open_fil
e()
Un sinónimo obsoleto para archive_write_open_f
ilename().
archive_write_open_filenam
e()
Una forma conveniente de archive_write_open() que acepta un nombre de archivo. Un argumento NULL indica que la salida debe ser escrita a la salida estándar; un argumento de “-” abrirá un archivo con ese nombre. Si no ha invocado archive_write_set_bytes_in_last_block(), entonces archive_write_open_filename() ajustará el relleno del último bloque dependiendo del archivo: habilitará el relleno cuando escriba a la salida estándar o a un nodo de dispositivo de carácter o bloque, y lo deshabilitará en otros casos. Puede anular esto invocando manualmente archive_write_set_bytes_in_last_block() antes de llamar a archive_write_open2(). La archive_write_open_filename() función es segura para usar con unidades de cinta u otros dispositivos orientados a
bloques.
archive_write_open_memor
y()
Una forma conveniente de archive_write_open2() que acepta un puntero a un bloque de memoria que recibirá el archivo. El argumento final size_t * apunta a una variable que será actualizada después de cada escritura para reflejar cuánto del búfer está actualmente en uso. Debe tener cuidado de asegurarse de que esta
variable permanezca asignada hasta después de que el archivo esté cerrado. Esta función
deshabilitará el relleno a menos que haya establecido específicamente el tamaño del bloque.

Se puede encontrar más información sobre el struct archive objeto y el diseño general de la biblioteca en el libarchive(3)

resumen.

Tenga en cuenta que las formas convenientes anteriores varían en cómo bloquean la salida. Vea archive_write_blocksize(3) si necesita controlar el tamaño del bloque util

izado para las escrituras o el comportam
iento de relleno de fin de archivo.

El callback de apertura es invocado por archive_write_open(). Debería devolver ARCHIVE_OK si el archivo subyacente o la fuente de datos se abre correctamente. Si la apertura falla, debería llamar a archive_set_error() para registrar un código de error y mensaje y devolver ARCHIVE_FATAL. Tenga en cuenta que si la apertura falla, el cierre no se llama y los recursos deben liberarse dentro del callback de apertura o con el callback de

El callback de escritura es invocado siempre que la biblioteca necesita escribir bytes sin procesar en el archivo. Para un bloqueo correcto, cada llamada a la función de retorno de escritura debería traducirse en una sola write(2) llamada al sistema. Esto es especialmente crítico al escribir archivos en unidades de cinta. En caso de éxito, el callback de escritura debería devolver el número de bytes realmente escritos. En caso de error, el callback debería invocar archive_set_error() para registrar un código de error y mensaje y devolver

-1.

El callback debe devolver ARCHIVE_OK en caso de éxito. En caso de fallo, el callback debe invocar archive_set_error() para registrar un código de error y un mensaje, y devolver ARCHIVE_FATAL
