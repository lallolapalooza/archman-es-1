ares_set_servers_ports_csv(3)

Paquete: c-ares

Licencias: MIT

ARES_SET_SERVERS_PORTS_CSV(3) Manual de funciones de biblioteca ARES_SET_SERVERS_PORTS_CSV(3)

NOMBRE

ares_set_servers_csv, ares_set_servers_ports_csv, ares_get_servers_csv - Establecer o obtener una lista de servidores DNS utilizada para consultas.

SINOPSIS

#include <ares.h>
int ares_set_servers_csv(ares_channel_t *channel, const char* servers)
int ares_set_servers_ports_csv(ares_channel_t *channel, const char* servers)
char *ares_get_servers_csv(const ares_channel_t *channel)

DESCRIPCIÓN

Las funciones ares_set_servers_csv y ares_set_servers_ports_csv establecen la lista de servidores DNS que c-ares consultará. A partir de la versión 1.22.0, esta función puede ser llamada en un canal activo con consultas en curso; anteriormente, devolvía ARES_ENOTIMP.

Aunque no se recomienda, pasar NULL para servers borrará todos los servidores configurados y dejará el canal inoperable; esto puede ser ventajoso para la simulación de pruebas, pero es poco probable que sea útil en producción.

La función ares_get_servers_csv recupera la lista de servidores en formato delimitado por comas.

El formato de entrada y salida es una lista de servidores separada por comas. Hay dos formatos disponibles: el formato típico de resolv.conf(5) nameserver, así como un formato URI. Ambos formatos pueden ser utilizados al mismo tiempo en la cadena CSV proporcionada.

El formato nameserver es:

ip[:puerto][%interfaz]
El ip puede estar encapsulado entre corchetes ([ ]) y debe estarlo si se utiliza ipv6 y también se especifica un puerto.

El puerto es opcional y por defecto será 53 o el valor especificado en ares_init_options(3).

La interfaz es específica para servidores de enlace local IPv6 (fe80::/10) y no debe usarse de otra manera.

Ejemplos del formato nameserver:

192.168.1.100
192.168.1.101:53
[1:2:3::4]:53
[fe80::1]:53%eth0

El formato URI está compuesto por los siguientes esquemas definidos:

dns:// - Servidor DNS normal (UDP + TCP). Debemos tener cuidado de no entrar en conflicto con los parámetros de consulta definidos en RFC4501, ya que técnicamente estaríamos extendiendo este esquema de URI. El puerto por defecto es 53.

dns+tls:// - DNS sobre TLS. El puerto por defecto es 853.

dns+https:// - DNS sobre HTTPS. El puerto por defecto es 443.

Los parámetros de consulta se definen a continuación. Es posible que se definan parámetros adicionales en el futuro.

tcpport - Puerto TCP a utilizar, solo para el esquema dns://. El puerto especificado como parte del componente de autoridad de la URI se utilizará tanto para UDP como para TCP por defecto; esta opción anulará el puerto TCP.

ipaddr - Solo para dns+tls:// y dns+https://. Si el componente de autoridad de la URI contiene un nombre de host, este se utiliza para especificar la dirección IP del nombre de host. Si no se especifica, se necesitará usar un servidor no seguro para realizar una consulta DNS para recuperar esta información. Siempre se recomienda especificar tanto la dirección IP como el nombre de dominio completamente cualificado.

hostname - Solo para dns+tls:// y dns+https://. Si el componente de autoridad de la URI contiene una dirección IP, este se utiliza para especificar el nombre de dominio completamente cualificado del servidor. Si no se especifica, se necesitará usar un servidor no seguro para realizar una búsqueda inversa de DNS para recuperar esta información. Siempre se recomienda especificar tanto la dirección IP como el nombre de dominio completamente cualificado.

domain - Si se especifica, este servidor es un servidor específico de dominio. Las consultas para este dominio se dirigirán a este servidor. Múltiples servidores pueden ser etiquetados con el mismo dominio.

Ejemplos del formato URI:

dns://8.8.8.8
dns://[2001:4860:4860::8888]
dns://[fe80::b542:84df:1719:65e3%en0]
dns://192.168.1.1:55
dns://192.168.1.1?tcpport=1153
dns://10.0.1.1?domain=myvpn.com
dns+tls://8.8.8.8?hostname=dns.google
dns+tls://one.one.one.one?ipaddr=1.1.1.1

NOTA: Aunque estamos definiendo el esquema para cosas como servidores específicos de dominio, DNS sobre TLS y DNS sobre HTTPS, las implementaciones subyacentes para esas características aún no existen y, por lo tanto, resultarán en errores si se intenta utilizarlas.

A partir de c-ares 1.24.0, ares_set_servers_csv y ares_set_servers_ports_csv son idénticas. Las versiones anteriores simplemente omitían los puertos en ares_set_servers_csv, pero debido a la adición de soporte para interfaces de enlace local, esta diferencia se eliminó.

EJEMPLO

192.168.1.100,[fe80::1]:53%eth0,dns://192.168.1.1?tcpport=1153

VALORES DE RETORNO

ares_set_servers_csv y ares_set_servers_ports_csv pueden devolver cualquiera de los siguientes valores:

ARES_SUCCESS
La configuración de los servidores de nombres se inicializó correctamente.
ARES_ENOMEM
Se agotó la memoria disponible del proceso.
ARES_ENODATA
Los datos del canal identificados por channel eran inválidos.
ARES_ENOTINITIALIZED
Aún no se ha realizado la inicialización de la biblioteca c-ares.

ares_get_servers_csv devuelve una cadena que representa los servidores configurados, la cual debe ser liberada con ares_free_string(3). Si devuelve NULL, se trata de una condición de falta de memoria.

VER TAMBIÉN

ares_set_servers(3)

DISPONIBILIDAD

ares_set_servers_csv se añadió en c-ares 1.7.2. ares_set_servers_ports_csv se añadió en c-ares 1.11.0. ares_get_servers_csv se añadió en c-ares 1.24.0. El soporte URI se añadió en c-ares 1.34.0.
