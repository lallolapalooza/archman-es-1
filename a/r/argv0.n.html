tclvars(n) Comandos integrados de Tcl tclvars(n)

NOMBRE

argc, argv, argv0, auto_path, env, errorCode, errorInfo, tcl_interactive, tcl_library, tcl_nonwordchars, tcl_patchLevel, tcl_pkgPath, tcl_platform, tcl_precision, tcl_rcFileName, tcl_traceCompile, tcl_traceExec, tcl_wordchars, tcl_version - Variables usadas por Tcl

DESCRIPCIÓN

Las siguientes variables globales son creadas y gestionadas automáticamente por la biblioteca Tcl. Excepto donde se indica a continuación, estas variables normalmente deben ser tratadas como de solo lectura por el código específico de la aplicación y por los usuarios.

auto_path
Si está establecida, entonces debe contener una lista Tcl válida que indique los directorios a buscar durante las operaciones de carga automática (incluyendo los archivos de índice de paquetes cuando se usa el manejador predeterminado package unknown). Esta variable se inicializa durante el arranque para contener, en orden: los directorios listados en la variable de entorno TCLLIBPATH, el directorio nombrado por la variable global tcl_library, el directorio padre de tcl_library, [file dirname [file dirname [info nameofexecutable]]]/lib, los directorios listados en la variable tcl_pkgPath. Las ubicaciones adicionales para buscar archivos e índices de paquetes normalmente deben agregarse a esta variable usando lappend.

Existen variables adicionales relacionadas con la gestión de paquetes. Más detalles se enumeran en la sección VARIABLES de la página del manual de library.

env
Esta variable es mantenida por Tcl como una matriz cuyos elementos son las variables de entorno del proceso. Leer un elemento devolverá el valor de la variable de entorno correspondiente. Establecer un elemento de la matriz modificará la variable de entorno correspondiente o creará una nueva si no existe. Quitar un elemento de env eliminará la variable de entorno correspondiente. Los cambios en la matriz env afectarán al entorno pasado a los hijos mediante comandos como exec. Si se quita toda la matriz env, Tcl dejará de monitorear los accesos a env y no actualizará las variables de entorno.

En Windows, las variables de entorno PATH y COMSPEC en cualquier capitalización se convierten automáticamente a mayúsculas. Por ejemplo, la variable PATH podría ser exportada por el sistema operativo como "path", "Path", "PaTh", etc., lo que provocaría que el código Tcl simple tuviera que soportar muchos casos especiales. Todas las demás variables de entorno heredadas por Tcl se dejan sin modificar. Establecer una variable de matriz env a blanco es lo mismo que quitarla, ya que este es el comportamiento del sistema operativo subyacente de Windows. Cabe señalar que depender de una variable de entorno existente y vacía no funcionará en Windows y se desaconseja para uso multiplataforma.

Los siguientes elementos de env son especiales para Tcl:

env(HOME)
Esta variable de entorno, si está establecida, indica la ubicación del directorio considerado como el directorio principal del usuario actual, y al cual se cambiará al llamar a cd sin argumentos o con solo "~" como argumento. La mayoría de las plataformas lo configuran correctamente por defecto; normalmente no necesita ser configurado por código de usuario.
env(TCL_LIBRARY)
Si está establecida, especifica la ubicación del directorio que contiene los scripts de biblioteca (el valor de esta variable se asignará a la variable tcl_library y, por lo tanto, será devuelto por el comando info library). Si esta variable no está establecida, se utiliza un valor predeterminado.

¡Tenga en cuenta que esta variable de entorno *no* debería ser normalmente establecida!

env(TCLLIBPATH)
Si está establecida, debe contener una lista Tcl válida que indique los directorios a buscar durante las operaciones de carga automática. Los directorios deben especificarse en formato Tcl, usando "/" como separador de ruta, independientemente de la plataforma. Esta variable solo se utiliza al inicializar la variable auto_path.
env(TCL_TZ), env(TZ)
Estos especifican la zona horaria predeterminada utilizada para analizar y formatear fechas y horas en el comando clock. En muchas plataformas, la variable de entorno TZ la configura el sistema operativo.
env(LC_ALL), env(LC_MESSAGES), env(LANG)
Estas variables de entorno son utilizadas por el paquete msgcat para determinar la configuración regional con la que formatear los mensajes.
env(TCL_INTERP_DEBUG_FRAME)
Si existe, tiene el mismo efecto que ejecutar interp debug {} -frame 1 como el primer comando de cada nuevo intérprete Tcl.
errorCode
Esta variable contiene el valor de la opción de retorno -errorcode establecida por el error más reciente ocurrido en este intérprete. Este valor de lista representa información adicional sobre el error en un formato fácil de procesar con programas. El primer elemento de la lista identifica una clase general de errores y determina el formato del resto de la lista. Los siguientes formatos para las opciones de retorno -errorcode son utilizados por el núcleo de Tcl; las aplicaciones individuales pueden definir formatos adicionales.
ARITH código mensaje
Este formato se utiliza cuando ocurre un error aritmético (por ejemplo, un intento de dividir cero por cero en el comando expr). código identifica el error preciso y mensaje proporciona una descripción legible del error. código será DIVZERO (por un intento de dividir por cero), DOMAIN (si un argumento está fuera del dominio de una función, como acos(-3)), IOVERFLOW (para desbordamiento de enteros), OVERFLOW (para un desbordamiento de punto flotante) o UNKNOWN (si no se puede determinar la causa del error).

La detección de estos errores depende en parte del hardware subyacente y las bibliotecas del sistema.

CHILDKILLED pid nombre_señal mensaje
Este formato se utiliza cuando un proceso hijo ha sido terminado debido a una señal. El elemento pid será el identificador del proceso (en decimal). El elemento nombre_señal será el nombre simbólico de la señal que provocó la terminación del proceso; será uno de los nombres del archivo de inclusión signal.h, como SIGPIPE. El elemento mensaje será un mensaje corto legible que describe la señal, como "escritura en tubería sin lectores" para SIGPIPE.
CHILDSTATUS pid código
Este formato se utiliza cuando un proceso hijo ha salido con un estado de salida distinto de cero. El elemento pid será el identificador del proceso (en decimal) y el elemento código será el código de salida devuelto por el proceso (también en decimal).
CHILDSUSP pid nombre_señal mensaje
Este formato se utiliza cuando un proceso hijo ha sido suspendido debido a una señal. El elemento pid será el identificador del proceso, en decimal. El elemento nombre_señal será el nombre simbólico de la señal que provocó la suspensión del proceso; será uno de los nombres del archivo de inclusión signal.h, como SIGTTIN. El elemento mensaje será un mensaje corto legible que describe la señal, como "lectura de tty en segundo plano" para SIGTTIN.
NONE
Este formato se utiliza para errores en los que no hay información adicional disponible para un error además del mensaje devuelto con el error. En estos casos, la opción de retorno -errorcode consistirá en una lista que contiene un solo elemento cuyo contenido es NONE.

Esta variable contiene una lista de directorios que indican dónde se instalan normalmente los paquetes. No se usa en Windows. Normalmente contiene una o dos entradas; si contiene dos entradas, la primera es normalmente un directorio para paquetes dependientes de la plataforma (por ejemplo, binarios de bibliotecas compartidas) y la segunda es normalmente un directorio para paquetes independientes de la plataforma (por ejemplo, archivos de script). tcl_precisi
on
Esta variable controla el número de dígitos a generar al convertir valores de punto flotente a cadenas. Su valor predeterminado es 0. Las aplicaciones no deben cambiar este valor; se p
roporciona por compatibilida
d con código heredado.
El valor predeterminado de 0 es especial, lo que significa que Tcl debe convertir números usando la menor cantidad de dígitos posible mientras aún distinga cualquier número de punto flotente de sus vecinos más cercanos. Diferente de usar un valor arbitrariamente alto para tcl_precision, en el que un número inexacto como 1.4 se convertirá como 1.4 en lugar de 1.3999999999999999, aunque el último está más cerca del valor exacto del número
binario.
Si tcl_precision no es cero, entonces cuando Tcl convierte un número de punto flotente, crea una representación decimal de como máximo tcl_precision dígitos significativos; el resultado puede ser más corto si el resultado más corto representa el número original exactamente. Si ningún resultado de como máximo tcl_precision dígitos es una representación exacta del número original, se elige el que está más cerca del número original. Si el número original se encuentra precisamente entre dos representaciones decimal igualmente precisas, se elige la que tiene un valor par para el dígito menos significativo; por ejemplo, si tcl_precision es 3, entonces 0.3125 se convertirá a 0.312, no 0.313, mientras que 0.6875 se convertirá a 0.688, no 0.687. Cualquier cadena de ceros finales que quede se
recorta.
Un valor de tcl_precision de 17 dígitos es “perfecto” para el punto flotente IEEE en el que permite que los valores de doble precisión se conviertan a cadenas y de vuelta a binario sin ninguna pérdida de información. Por esta razón, a menudo lo verá como un valor en código heredado que debe ejecutarse en versiones de Tcl anteriores a 8.5. Ya no se recomienda; como se indicó arriba, un valor cero es el método
preferido.
Todos los intérpretes en un hilo comparten un único valor de tcl_precision: cambiarlo en un intérprete afectará a todos los demás intérpretes también. A los intérpretes seguros no se les permite modificar la
variable.
Los valores válidos para tcl_precision van desde 0 hasta
17.

NAME

tclvars — Tcl global variables

SYNOPSIS

::auto_qualify
::env
::errorInfo
::errorCode
::tcl_debugger
::tcl_demerge
::tcl_findLibrary
::tcl_platform
::tcl_traceExec
::tcl_wordchars
::tcl_nonwordchars
::tcl_version
::argc
::argv
::argv0
::tcl_interactive

DESCRIPTION

This page describes many of the global variables that are defined by Tcl. This is not an exhaustive list, but it does describe the most commonly used ones. Note that the Tcl library itself defines some of these variables, while others are defined by specific Tcl applications such as tclsh and wish.

auto_path
This is a Tcl list containing a sequence of directories that should be searched when trying to find commands or packages. When Tcl needs to find a command that is not built-in, it searches for it in the directories specified by auto_path. This variable is initialized by Tcl with default values that are appropriate for the installation, and it can be modified by the user.
auto_qualify
If this variable is set to 1, then commands that are not found in the current namespace will be automatically qualified with the namespace name. For example, if you have a command named `foo` in namespace `bar`, and you try to run it from the global scope, it will be automatically run as `bar::foo`. This feature is off by default.
env
This variable holds an associative array containing the environment variables for the process. The names of the environment variables are the keys and the values are the corresponding environment variable values. Any changes made to this array are reflected in the environment variables for child processes spawned by Tcl, but they do not affect the environment variables of the parent process. Note that on some operating systems, Tcl may not be able to modify environment variables.
errorInfo
When an error occurs, this variable is set to a string containing a stack trace of the Tcl interpreter. This trace can be very useful for debugging.
errorCode
When an error occurs, this variable is set to a Tcl list containing information about the error. The format of this list depends on the type of error that occurred. Common values include POSIX error codes, Tcl script errors, and X11 errors.
tcl_debugger
If this variable is set to 1, the Tcl debugger will be invoked when an error occurs. This can be useful for interactively debugging Tcl scripts.
tcl_demerge
If this variable is set to 1, then Tcl will attempt to "demerge" commands that have been previously merged. This is an advanced feature that is typically used in conjunction with the Tcl compiler.
tcl_findLibrary
This variable holds the name of the Tcl library file that was used to initialize the interpreter. This can be useful for determining the location of the Tcl library on the system.
tcl_platform
This variable holds an associative array containing information about the Tcl platform. The keys include:
byteOrder
The byte order of the machine ("littleEndian" or "bigEndian").
machine
The type of machine, e.g. "i386", "sparc".
os
The operating system name, e.g. "windowsNT", "unix".
osVersion
The operating system version number.
platform
A general platform name, e.g. "unix", "windows".
user
The username of the person running the Tcl script.
This information can be useful for writing platform-independent Tcl scripts.
tcl_traceExec
The value of this variable can be set to control how much tracing information is displayed during bytecode execution. By default, tcl_traceExec is zero and no information is displayed. Setting tcl_traceExec to 1 generates a one-line trace in stdout on each call to a Tcl procedure. Setting it to 2 generates a line of output whenever any Tcl command is invoked that contains the name of the command and its arguments. Setting it to 3 produces a detailed trace showing the result of executing each bytecode instruction. Note that when tcl_traceExec is 2 or 3, commands such as set and incr that have been entirely replaced by a sequence of bytecode instructions are not shown. Setting this variable is useful in tracking down suspected problems with the bytecode compiler and interpreter.
This variable and functionality only exist if TCL_COMPILE_DEBUG was defined during Tcl's compilation.
tcl_wordchars
The value of this variable is a regular expression that can be set to control what are considered “word” characters, for instances like selecting a word by double-clicking in text in Tk. It is platform dependent. On Windows, it defaults to \S, meaning anything but a Unicode space character. Otherwise it defaults to \w, which is any Unicode word character (number, letter, or underscore).
tcl_nonwordchars
The value of this variable is a regular expression that can be set to control what are considered “non-word” characters, for instances like selecting a word by double-clicking in text in Tk. It is platform dependent. On Windows, it defaults to \s, meaning any Unicode space character. Otherwise it defaults to \W, which is anything but a Unicode word character (number, letter, or underscore).
tcl_version
When an interpreter is created Tcl initializes this variable to hold the version number for this version of Tcl in the form x.y. Changes to x represent major changes with probable incompatibilities and changes to y represent small enhancements and bug fixes that retain backward compatibility. The value of this variable is returned by the info tclversion command.

OTHER GLOBAL VARIABLES

The following variables are only guaranteed to exist in tclsh and wish executables; the Tcl library does not define them itself but many Tcl environments do.

argc
The number of arguments to tclsh or wish.
argv
Tcl list of arguments to tclsh or wish.
argv0
The script that tclsh or wish started executing (if it was specified) or otherwise the name by which tclsh or wish was invoked.
tcl_interactive
Contains 1 if tclsh or wish is running interactively (no script was specified and standard input is a terminal-like device), 0 otherwise.

EXAMPLES

To add a directory to the collection of locations searched by package require, e.g., because of some application-specific packages that are used, the auto_path variable needs to be updated:

lappend ::auto_path [file join [pwd] "theLibDir"]

A simple though not very robust way to handle command line arguments of the form “-foo 1 -bar 2” is to load them into an array having first loaded in the default settings:

array set arguments {-foo 0 -bar 0 -grill 0}
array set arguments $::argv
puts "foo is $arguments(-foo)"
puts "bar is $arguments(-bar)"
puts "grill is $arguments(-grill)"

The argv0 global variable can be used (in conjunction with the info script command) to determine whether the current script is being executed as the main script or loaded as a library. This is useful because it allows a single script to be used as both a library and a demonstration of that library:

if {$::argv0 eq [info script]} {
    # running as: tclsh example.tcl
} else {
    package provide Example 1.0
}
