ares_init(3)

Paquete: c-ares

ARES_INIT_OPTIONS(3) Manual de Funciones de Biblioteca ARES_INIT_OPTIONS(3)

NOMBRE

ares_init_options, ares_init - Inicializar un canal de resolución

SINOPSIS

#include <ares.h>
struct ares_server_failover_options {
  unsigned short retry_chance;
  size_t retry_delay;
};
struct ares_options {
  int flags;
  int timeout; /* en segundos o milisegundos, dependiendo de las opciones */
  int tries;
  int ndots;
  unsigned short udp_port;
  unsigned short tcp_port;
  int socket_send_buffer_size;
  int socket_receive_buffer_size;
  struct in_addr *servers;
  int nservers;
  char **domains;
  int ndomains;
  char *lookups;
  ares_sock_state_cb sock_state_cb;
  void *sock_state_cb_data;
  struct apattern *sortlist;
  int nsort;
  int ednspsz;
  char *resolvconf_path;
  char *hosts_path;
  int udp_max_queries;
  int maxtimeout; /* en milisegundos */
  unsigned int qcache_max_ttl; /* en segundos */
  ares_evsys_t evsys;
  struct ares_server_failover_options server_failover_opts;
};
int ares_init_options(ares_channel_t **channelptr,
                      const struct ares_options *options,
                      int optmask);
int ares_init(ares_channel_t **channelptr);

DESCRIPCIÓN

La función ares_init(3) es equivalente a llamar a ares_init_options(channelptr, NULL, 0). Se recomienda usar ares_init_options(3) en su lugar y establecer o hacer configurables las opciones apropiadas para su aplicación.

La función ares_init_options(3) inicializa un canal de comunicaciones para búsquedas de servicio de nombres. Si devuelve éxito, ares_init_options(3) establecerá la variable apuntada por channelptr a un manejador utilizado para identificar el canal de servicio de nombres. El llamador debe invocar ares_destroy(3) en el manejador cuando el canal ya no sea necesario.

Se recomienda que una aplicación tenga como máximo un canal de ares y lo utilice para todas las consultas DNS durante la vida de la aplicación. Cuando la configuración del sistema cambie, ares_reinit(3) puede ser llamado para recargar la configuración si es necesario. El límite concurrente de consulta recomendado es de aproximadamente 32k consultas, pero teniendo en cuenta que al especificar AF_UNSPEC para ares_getaddrinfo(3) o ares_gethostbyname(3), estos pueden generar 2 consultas internamente. La razón del límite es que c-ares no permite IDs de consulta DNS duplicadas (que tienen un máximo de 64k) en espera en un momento dado, y debe buscar aleatoriamente un ID disponible, por lo que 32k limitará el número de búsquedas. Esta limitación no debería ser un problema para la mayoría de las implementaciones y c-ares puede implementar colas en futuras versiones para levantar esta limitación.

El parámetro optmask generalmente especifica qué campos en la estructura apuntada por options están configurados, de la siguiente manera:

ARES_OPT_FLAGS
int flags;
Banderas que controlan el comportamiento del resolvedor:
ARES_FLAG_USEVC
Utilizar siempre consultas TCP (el "circuito virtual") en lugar de consultas UDP. Normalmente, TCP solo se utiliza si una consulta UDP produce un resultado truncado.
ARES_FLAG_PRIMARY
Consultar solo el primer servidor de la lista de servidores a consultar.
ARES_FLAG_IGNTC
Si se recibe una respuesta truncada a una consulta UDP, no se recurre a TCP; simplemente se continúa con la respuesta truncada.
ARES_FLAG_NORECURSE
No establecer la bit de "recursión deseada" en las consultas salientes, de modo que el servidor de nombres contactado no intente obtener la respuesta de otros servidores si no conoce la respuesta localmente. Tenga en cuenta que ares no hará la recursión por usted. La recursión debe ser manejada por la aplicación que llama a ares si se establece ARES_FLAG_NORECURSE.
ARES_FLAG_STAYOPEN
No cerrar los sockets de comunicación cuando el número de consultas activas desciende a cero.
ARES_FLAG_NOSEARCH
No utilizar los dominios de búsqueda predeterminados; consultar solo nombres de host tal cual o como alias.
ARES_FLAG_NOALIASES
No honrar la variable de entorno HOSTALIASES, que normalmente especifica un archivo de traducciones de nombres de host.
ARES_FLAG_NOCHECKRESP
No descartar respuestas con el código de respuesta SERVFAIL, NOTIMP o REFUSED o respuestas cuyas preguntas no coincidan con las preguntas de la solicitud. Útil principalmente para escribir clientes que puedan ser utilizados para probar o depurar servidores de nombres.
ARES_FLAG_EDNS
Incluir un registro de recursos pseudo EDNS (RFC 2671) en las solicitudes generadas. A partir de la versión 1.22, esto está activado por defecto si las banderas no están configuradas.
ARES_FLAG_NO_DFLT_SVR
No intentar agregar un servidor local predeterminado si no hay otros servidores disponibles. En su lugar, fallar la inicialización con ARES_ENOSERVER.
ARES_FLAG_DNS0x20
Habilitar soporte para DNS 0x20 según https://datatracker.ietf.org/doc/html/draft-vixie-dnsext-dns0x20-00, que agrega entropía adicional a la solicitud aleatorizando la capitalización del nombre de la consulta. Los integradores deben asegurarse de tratar las respuestas de nombres DNS como insensibles a mayúsculas y minúsculas. En raras circunstancias, esto puede causar la incapacidad de buscar dominios específicos si el servidor intermedio o el servidor autoritativo para el dominio no cumple con las normas.
ARES_OPT_TIMEOUT
int timeout;
El número de segundos que se da a cada servidor de nombres para responder a una consulta en el primer intento. Ver ARES_OPT_TIMEOUTMS, en el que se convierte este valor.
ARES_OPT_TIMEOUTMS
int timeout;
El número de milisegundos que se da a cada servidor de nombres para responder a una consulta en el primer intento de cada servidor. El valor predeterminado es dos segundos; sin embargo, cualquier valor inferior a 250 ms se establecerá automáticamente en 250 ms (aproximadamente el RTT a mitad de camino alrededor del mundo). Tenga en cuenta que esta opción se especifica con el mismo campo struct que la anterior ARES_OPT_TIMEOUT, es solo que las banderas le dicen a c-ares cómo interpretar el número. Esta opción se agregó en c-ares 1.5.2.

A partir de c-ares 1.32.0, esta opción solo se respeta en la primera consulta exitosa a cualquier servidor dado; después de eso, el tiempo de espera se calcula automáticamente basándose en el historial de consultas anterior.

ARES_OPT_TRIES
int tries;
El número de intentos que el resolvedor intentará contactando a cada servidor de nombres antes de rendirse. El valor predeterminado es tres intentos.
ARES_OPT_NDOTS
int ndots;
El número de puntos que deben estar presentes en un nombre de dominio para que se consulte tal cual ("as is") antes de consultarlo con las extensiones de dominio predeterminadas añadidas. El valor predeterminado es 1 a menos que se establezca de otra manera por resolv.conf o la variable de entorno RES_OPTIONS. El rango válido es 0-15.
ARES_OPT_MAXTIMEOUTMS
int maxtimeout;
El límite superior para el tiempo de espera entre intentos de reintento secuenciales. Al reintentar consultas, el tiempo de espera aumenta desde el tiempo de espera solicitado, esto limita el valor.
ARES_OPT_UDP_PORT
unsigned short udp_port;
El puerto a utilizar para consultas a través de UDP, en orden de bytes del host. El valor predeterminado es 53, el puerto estándar del servicio de nombres.
ARES_OPT_TCP_PORT
unsigned short tcp_port;
El puerto a utilizar para consultas a través de TCP, en orden de bytes del host. El valor predeterminado es 53, el puerto estándar del servicio de nombres.
ARES_OPT_SENDBUFSIZE
int socket_send_buffer_size;
El tamaño del búfer de envío del socket. El valor predeterminado es 0, que permite que el sistema operativo elija el tamaño. Útil si se quieren realizar muchas consultas simultáneas.
ARES_OPT_RECVBUFSIZE
int socket_receive_buffer_size;
El tamaño del búfer de recepción del socket. El valor predeterminado es 0, que permite que el sistema operativo elija el tamaño.
ARES_OPT_SERVERS
struct in_addr *servers; int nservers;
Un arreglo de estructuras in_addr que especifican las direcciones IP de los servidores DNS a utilizar. nservers debe ser el número de servidores en el arreglo. Si servers es NULL, se utilizarán los servidores predeterminados del sistema (generalmente leídos de resolv.conf). La memoria para servers debe ser asignada por el llamador y será copiada por c-ares. Si se establece, esto anula la lista de servidores leída de resolv.conf.
char **domains; int ndomains;
Un arreglo de cadenas de caracteres que especifican los dominios de búsqueda. ndomains debe ser el número de dominios en el arreglo. Si domains es NULL, se utilizarán los dominios predeterminados del sistema (generalmente leídos de resolv.conf). La memoria para domains debe ser asignada por el llamador y será copiada por c-ares. Si se establece, esto anula la lista de dominios leída de resolv.conf.
char *lookups;
Una cadena de caracteres que especifica los tipos de búsqueda que se realizarán. Los tipos posibles son "b" (archivo hosts), "a" (DNS), y "h" (archivo hosts). Los tipos pueden ser combinados, por ejemplo, "ab" intentará DNS y luego hosts. El valor predeterminado es "ab". Si lookups es NULL, se utilizará el valor predeterminado.
ares_sock_state_cb sock_state_cb; void *sock_state_cb_data;
Una función de devolución de llamada que se invocará cada vez que el estado de un socket cambie (por ejemplo, cuando un socket se vuelve elegible para leer o escribir). El parámetro sock_state_cb_data se pasará a la función de devolución de llamada. Esto es útil para integrar c-ares con un bucle de eventos.
struct apattern *sortlist; int nsort;
Un arreglo de estructuras apattern que especifican una lista de prefijos de red que se utilizarán para ordenar las direcciones IP devueltas por las búsquedas de nombres. nsort debe ser el número de elementos en sortlist. Si sortlist es NULL, no se realizará ninguna ordenación.
int ednspsz;
El tamaño del búfer EDNS a solicitar. El valor predeterminado es 0, que deshabilita EDNS. Un valor de 4096 es un valor común. Si se establece ARES_FLAG_EDNS, este valor se utiliza para el tamaño del búfer EDNS.
char *resolvconf_path;
Una ruta a un archivo resolv.conf alternativo. Útil para probar o si el resolv.conf predeterminado no está disponible.
char *hosts_path;
Una ruta a un archivo hosts alternativo. Útil para probar o si el archivo hosts predeterminado no está disponible.
int udp_max_queries;
El número máximo de consultas UDP que se enviarán a un servidor específico antes de pasar a TCP. El valor predeterminado es 0, lo que significa que siempre se utilizará UDP a menos que se trunque la respuesta.
ares_evsys_t evsys;
Sistema de eventos a utilizar. Las opciones son ARES_ETSYSLIB, ARES_ETSYSEPOLL, ARES_ETSYSIO, ARES_ETSYSPLL, ARES_ETSYSSIG.
struct ares_server_failover_options server_failover_opts;
Opciones para la conmutación por error del servidor.
  • unsigned short retry_chance: La probabilidad (en porcentaje) de que se intentará un servidor fallido.
  • size_t retry_delay: El retraso (en milisegundos) antes de intentar un servidor fallido.

La estructura de opciones contiene muchos campos que se pueden configurar. Si el argumento options es NULL, se utilizarán los valores predeterminados del sistema, que generalmente se leen de /etc/resolv.conf. Si no es NULL, solo se utilizarán los campos especificados por optmask.

Si se usa ares_init_options(), el campo optmask es una máscara de bits que especifica qué campos de la estructura options se han establecido. Si se establece un bit, el campo correspondiente en options se utiliza. Si no se establece, se utiliza el valor predeterminado del sistema o un valor predeterminado de c-ares. El valor predeterminado para el campo es 0 para enteros y punteros.

Los siguientes bits se pueden establecer en optmask:

ARES_OPT_FLAGS
ARES_OPT_TIMEOUT
ARES_OPT_TRIES
ARES_OPT_NDOTS
ARES_OPT_MAXTIMEOUTMS
ARES_OPT_UDP_PORT
ARES_OPT_TCP_PORT
ARES_OPT_SENDBUFSIZE
ARES_OPT_RECVBUFSIZE
ARES_OPT_SERVERS
ARES_OPT_DOMAINS
ARES_OPT_LOOKUPS
ARES_OPT_SOCK_STATE_CB
ARES_OPT_SORTLIST
ARES_OPT_EDNSPSZ
ARES_OPT_RESOLVCONF_PATH
ARES_OPT_HOSTS_PATH
ARES_OPT_UDP_MAX_QUERIES
ARES_OPT_TIMEOUTMS
ARES_OPT_EVENTSYS
ARES_OPT_SERVER_FAILOVER

Si se especifica ARES_OPT_FLAGS, la estructura options contendrá un campo flags que es una combinación de los indicadores descritos anteriormente. Si se especifica ARES_OPT_TIMEOUT, el campo timeout se interpreta como segundos. Si se especifica ARES_OPT_TIMEOUTMS, el campo timeout se interpreta como milisegundos.

Se recomienda el uso de ARES_OPT_TIMEOUTMS para el control de tiempo de espera más preciso.

Los valores para servers y domains se copian en la estructura de canal de c-ares. Si el llamador desea que c-ares libere la memoria para estos campos, deberá llamar a ares_free_hostent(3) después de llamar a ares_init(3).

VALORES DE RETORNO

ares_init_options(3) y ares_init(3) pueden devolver uno de los siguientes valores de error:

ARES_SUCCESS
Éxito.
ARES_ENOTFOUND
El servidor de nombres no se pudo encontrar (por ejemplo, el archivo resolv.conf está vacío o mal formado).
ARES_ECONNREFUSED
La conexión al servidor de nombres fue rechazada.
ARES_ETIMEOUT
Se agotó el tiempo de espera de la conexión al servidor de nombres.
ARES_ENOMEM
No hay suficiente memoria disponible.
ARES_ENOSOCKET
No se pudo crear un socket.
ARES_EFILE
Se produjo un error al leer un archivo (por ejemplo, resolv.conf).
ARES_EINVAL
Se proporcionó un valor de argumento inválido.
ARES_ENOTINIT
La biblioteca ares no ha sido inicializada.
ARES_ELOOP
Se detectó un bucle infinito.
ARES_ENOSRV
No se encontraron registros SRV.
ARES_ENOTIMP
La operación no está implementada.
ARES_EBADFAMILY
Se especificó una familia de direcciones no válida.
ARES_ENOSERVICE
No se encontró el servicio.
ARES_FAILOVER
Conmutación por error fallida del servidor.

unsigned int qcache_max_ttl;
A partir de c-ares 1.31.0, la caché de consultas está habilitada por defecto con un TTL de 1 hora. Para deshabilitar la caché de consultas, especifique esta opción con un TTL de 0. La caché de consultas se basa en el TTL devuelto en el mensaje DNS. Solo se almacenarán en caché los resultados de consultas completamente exitosos y NXDOMAIN. Rellene el qcache_max_ttl con el número máximo de segundos que un resultado de consulta puede permanecer en caché, lo que anulará un TTL más grande en el mensaje de respuesta. Este debe ser un valor distinto de cero, de lo contrario la caché se deshabilitará. Elija un valor razonable para su aplicación, como 300 (5 minutos) o 3600 (1 hora). La caché de consultas se vacía automáticamente si se realiza un cambio en la configuración del servidor.

ARES_OPT_SERVER_FAILO
VER
struct ares_server_failover_options server_failover_opts;
Configura el comportamiento de reintento en caso de fallo del servidor. Cuando un servidor DNS no responde a una consulta, c-ares lo degradará en prioridad. En consultas posteriores, se seleccionarán con preferencia los servidores con menos fallos consecutivos. Sin embargo, para detectar cuándo un servidor de este tipo se ha recuperado, c-ares ocasionalmente reintentará servidores fallidos sondeando con una copia de la consulta, sin afectar la latencia de la consulta solicitada real. La estructura ares_server_failover_options contiene opciones para controlar este comportamiento. El campo retry_chance da la probabilidad (1/N) de reintentar un servidor fallido en cualquier consulta dada. Establecerlo a un valor de 0 deshabilita los reintentos. El campo retry_delay da el retraso mínimo en milisegundos que c-ares esperará antes de reintentar un servidor fallido específico. Si esta opción no se especifica, c-ares usará una probabilidad del 10% y un retraso mínimo de 5 segundos.

El parámetro optmask también incluye opciones sin un campo correspondiente en la estructura ares_options, como

sigue:
ARES_OPT_ROT
ATE
Realiza la selección round-robin de los servidores de nombres configurados para el canal en cada
resolución.
ARES_OPT_NOROT
ATE
No realiza la selección round-robin de servidores de nombres; siempre usa la list
a de servidores de nombres en el mismo orden. El valor por defecto es no rotar se
rvidores, sin embargo la configuración del sistema puede especificar el deseo de rotar y este valor de configuración puede anular dicha configuración del sistema.

S

Al inicializar desde /etc/resolv.conf, (o, alternativamente cuando lo especifique la ubicación de la ruta resolvconf_path) ares_init_options(3) y ares_init(3) leen las directivas domain y search para permitir búsquedas de nombres cortos relativos a los dominios especificados.
