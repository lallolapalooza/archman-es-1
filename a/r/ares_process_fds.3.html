ares_process_fds(3)

Paquete: c-ares

Licencias: MIT

ARES_PROCESS(3) Manual de Funciones de Biblioteca ARES_PROCESS(3)

NOMBRE

ares_process_fds, ares_process_fd, ares_process - Procesar eventos para la resolución de nombres

SINOPSIS

#include <ares.h>
/*! Eventos usados por ares_fd_events_t */
typedef enum {
  ARES_FD_EVENT_NONE  = 0,      /*!< Sin eventos */
  ARES_FD_EVENT_READ  = 1 << 0, /*!< Evento de lectura (incluye desconexión/error) */
  ARES_FD_EVENT_WRITE = 1 << 1  /*!< Evento de escritura */
} ares_fd_eventflag_t;
/*! Tipo que contiene un descriptor de archivo y una máscara de eventos, usado por
 *  ares_process_fds() */
typedef struct {
  ares_socket_t fd;     /*!< Descriptor de archivo */
  unsigned int  events; /*!< Máscara de ares_fd_event_t */
} ares_fd_events_t;
typedef enum {
  ARES_PROCESS_FLAG_NONE        = 0,
  ARES_PROCESS_FLAG_SKIP_NON_FD = 1 << 0
} ares_process_flag_t;
ares_status_t ares_process_fds(ares_channel_t         *channel,
                               const ares_fd_events_t *events,
                               size_t                  nevents,
                               unsigned int            flags)
void ares_process_fd(ares_channel_t *channel,
                     ares_socket_t read_fd,
                     ares_socket_t write_fd)
void ares_process(ares_channel_t *channel,
                  fd_set *read_fds,
                  fd_set *write_fds)

DESCRIPCIÓN

Estas funciones deben ser utilizadas por los integradores que elijan no utilizar el EventThread habilitado a través de ARES_OPT_EVENT_THREAD pasado a ares_init_options. Esto asume que los integradores ya tienen su propio bucle de eventos manejando notificaciones de eventos para varios descriptores de archivo y desean hacer lo mismo con su integración con c-ares.

La función ares_process_fds(3) maneja los eventos de entrada/salida en los descriptores de archivo y los tiempos de espera asociados con las consultas pendientes en el canal identificado por channel. Los descriptores de archivo a procesar se pasan en una matriz de estructuras de datos ares_fd_events_t en el miembro fd, y los eventos son una máscara de bits de ares_fd_eventflag_t en el miembro event. Esta función también se puede usar para procesar tiempos de espera pasando NULL al miembro events con un valor nevents de 0. Las banderas también se pueden especificar en el campo flags y se definen en ares_process_flag_t.

Se puede especificar ARES_PROCESS_FLAG_SKIP_NON_FD para omitir específicamente cualquier procesamiento no relacionado con los eventos de descriptor de archivo pasados, como ejemplos se incluyen el procesamiento de tiempos de espera y el manejo de limpieza. Esto es útil si un integrador sabe que enviará múltiples solicitudes de ares_process_fds(3) y desea omitir ese procesamiento adicional. Sin embargo, el integrador debe enviar la solicitud final con la bandera para que el tiempo de espera y otros procesamientos se realicen antes de que su bucle de eventos espere eventos adicionales.

Es permisible usar un miembro ares_fd_events_t con el miembro events con valor ARES_FD_EVENT_NONE (0) si no hay eventos para un descriptor de archivo dado si un integrador desea simplemente mantener una matriz con todos los descriptores de archivo posibles y actualizar la preparación a través del miembro event.

Esta función devolverá ARES_ENOMEM en condiciones de falta de memoria, de lo contrario devolverá ARES_SUCCESS.

Esta función se recomienda sobre ares_process_fd(3) ya que puede manejar el procesamiento de múltiples descriptores de archivo a la vez, omitiendo así la repetición de lógica adicional como el procesamiento de tiempos de espera que sería necesario si se llama a ares_process_fd(3) para múltiples descriptores de archivo notificados al mismo tiempo.

Esta función se usa típicamente con la opción ARES_OPT_SOCK_STATE_CB.

Se debe usar ares_timeout(3) para obtener el tiempo de espera deseado, y cuando el tiempo de espera expire, el integrador debe llamar a ares_process_fds(3) con una matriz events NULL. (o ares_process_fd(3) con ambos sockets configurados en ARES_SOCKET_BAD). No es necesario hacer esto si también se entregan eventos para cualquier descriptor de archivo, ya que el procesamiento de tiempos de espera se manejará automáticamente en cualquier llamada a ares_process_fds(3) o ares_process_fd(3).

La función ares_process_fd(3) es la misma que ares_process_fds(3) excepto que solo puede procesar un descriptor de archivo de lectura y uno de escritura a la vez. Los nuevos integradores deberían usar ares_process_fds(3) si es posible.

La función ares_process(3) funciona de la misma manera, excepto que opera sobre fd_sets como los utilizados por select(3) y recuperados por ares_fds(3). Este método está obsoleto y no debe usarse en aplicaciones modernas debido a limitaciones conocidas en la implementación de select(3).

DISPONIBILIDAD

ares_process_fds(3) se introdujo en c-ares 1.34.0.

VER TAMBIÉN

ares_fds(3), ares_timeout(3), ares_init_options(3) con ARES_OPT_EVENT_THREAD o ARES_OPT_SOCK_STATE_CB
