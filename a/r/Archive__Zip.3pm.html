NOMBRE

Archive::Zip - Proporciona una interfaz para archivos de archivo ZIP.

SINOPSIS

# Crear un archivo Zip
use Archive::Zip qw( :ERROR_CODES :CONSTANTS );
my $zip = Archive::Zip->new();
# Añadir un directorio
my $dir_member = $zip->addDirectory( 'dirname/' );
# Añadir un archivo desde una cadena con compresión
my $string_member = $zip->addString( 'This is a test', 'stringMember.txt' );
$string_member->desiredCompressionMethod( COMPRESSION_DEFLATED );
# Añadir un archivo desde el disco
my $file_member = $zip->addFile( 'xyz.pl', 'AnotherName.pl' );
# Guardar el archivo Zip
unless ( $zip->writeToFileNamed('someZip.zip') == AZ_OK ) {
    die 'write error';
}
# Leer un archivo Zip
my $somezip = Archive::Zip->new();
unless ( $somezip->read( 'someZip.zip' ) == AZ_OK ) {
    die 'read error';
}
# Cambiar el tipo de compresión para un archivo en el Zip
my $member = $somezip->memberNamed( 'stringMember.txt' );
$member->desiredCompressionMethod( COMPRESSION_STORED );
unless ( $zip->writeToFileNamed( 'someOtherZip.zip' ) == AZ_OK ) {
    die 'write error';
}

DESCRIPCIÓN

El módulo Archive::Zip permite a un programa Perl crear, manipular, leer y escribir archivos de archivo Zip.

Se pueden crear archivos Zip, o puedes leer desde archivos Zip existentes.

Una vez creados, pueden escribirse en archivos, flujos o cadenas. Se pueden añadir, eliminar, extraer, reemplazar, reorganizar y enumerar miembros. También se pueden renombrar o consultar o modificar sus fechas, comentarios u otros atributos. Sus datos pueden comprimirse o descomprimirse según sea necesario.

Los miembros pueden crearse a partir de miembros en archivos Zip existentes, o a partir de directorios, archivos o cadenas existentes.

Este módulo usa la biblioteca Compress::Raw::Zlib para leer y escribir los flujos comprimidos dentro de los archivos.

Se puede usar Archive::Zip::MemberRead para leer los miembros del archivo zip como si fueran archivos.

Nombres de archivos

Independientemente de lo que use tu sistema de archivos local para nombrar archivos, los nombres en un archivo Zip están en formato Unix (barras inclinadas (/) separando los nombres de directorio, etc.).

"Archive::Zip" intenta ser consistente con las convenciones de nombres de archivos, y traducirá de ida y vuelta entre los nombres nativos y los de Zip.

Sin embargo, no puede adivinar en qué formato están los nombres. Así que dos reglas controlan qué tipo de nombre de archivo debes pasar a las distintas rutinas:

Los nombres de los archivos están en formato local.
"File::Spec" y "File::Basename" se usan para varias operaciones de archivos. Cuando te refieras a un archivo en tu sistema, usa sus convenciones de nombres de archivos.
Los nombres de los miembros del archivo están en formato Unix.
Esto se aplica a todo método que se refiera a un miembro del archivo, o que proporcione un nombre para nuevos miembros del archivo. Los métodos extract() que pueden tomar uno o dos nombres convertirán de nombres locales a nombres zip si los llamas con un solo nombre.

Modelo de objetos de Archive::Zip

Descripción general

Los objetos Archive::Zip::Archive son con los que normalmente tratas. Estos mantienen la estructura de un archivo zip, sin necesariamente contener datos. Cuando se lee un zip desde un archivo en disco, los datos (posiblemente comprimidos) siguen viviendo en el archivo, no en la memoria. Los miembros del archivo contienen información sobre los miembros individuales, pero no (normalmente) los datos reales del miembro. Cuando el zip se escribe en un archivo (diferente), los datos del miembro se comprimen o se copian según sea necesario. Es posible crear miembros del archivo cuyos datos se mantienen en una cadena en memoria, pero esto no se hace cuando se lee un archivo zip. Los miembros de directorio no tienen ningún dato.

CÓDIGOS DE ERROR

Muchos de los métodos en Archive::Zip devuelven códigos de error. Estos están implementados como subrutinas en línea, usando la directiva "use constant" Se pueden importar en tu espacio de nombres usando la etiqueta ":ERROR_CODES" :

use Archive::Zip qw( :ERROR_CODES );
...
unless ( $zip->read( 'myfile.zip' ) == AZ_OK ) {
    die "whoops!";
}
AZ_OK (0)
Todo está bien.
AZ_STREAM_END (1)
El flujo de lectura (o el directorio central) terminó normalmente.
AZ_ERROR (2)
Hubo algún tipo de error genérico.
AZ_FORMAT_ERROR (3)
Hay un error de formato en un archivo ZIP que se está leyendo.
AZ_IO_ERROR (4)
Hubo un error de E/S.

Compresión

Archive::Zip permite que cada miembro de un archivo ZIP esté comprimido (usando el algoritmo Deflate) o sin comprimir.

No se admiten otros algoritmos de compresión que algunas versiones de ZIP han podido producir. Cada miembro tiene dos métodos de compresión: el con el que está almacenado (esto es siempre COMPRESSION_STORED para miembros de cadenas y archivos externos), y el que deseas para el miembro en el archivo zip.

Estos pueden ser diferentes, por supuesto, así que puedes hacer un miembro zip que no esté comprimido a partir de uno que lo esté, y viceversa.

Puedes consultar la compresión actual y establecer el método de compresión deseado:

my $member = $zip->memberNamed( 'xyz.txt' );
$member->compressionMethod();    # devolver compresión actual
# establecer para leer sin comprimir
$member->desiredCompressionMethod( COMPRESSION_STORED );
# establecer para leer comprimido
$member->desiredCompressionMethod( COMPRESSION_DEFLATED );

Hay dos métodos de compresión diferentes:

COMPRESSION_STORED
El archivo está almacenado (sin compresión)
COMPRESSION_DEFLATED
El archivo está Deflated

Nivel de compresións

Si el desiredCompressionMethod de un miembro es COMPRESSION_DEFLATED, puedes elegir diferentes niveles de compresión. Esta elección puede afectar la velocidad de compresión y descompresión, así como el tamaño de los datos comprimidos del miembro.

$member->desiredCompressionLevel( 9 );

Los niveles que se pueden dar son:

  • 0 o COMPRESSION_LEVEL_NONE

    Esto es lo mismo que decir

    $member->desiredCompressionMethod( COMPRESSION_STORED );
  • 1 .. 9

    1 da la mejor velocidad y la peor compresión, y 9 da la mejor compresión y la peor velocidad.

  • COMPRESSION_LEVEL_FASTEST

    Este es un sinónimo para el nivel 1.

  • COMPRESSION_LEVEL_BEST_COMPRESSION

    Este es un sinónimo para el nivel 9.

  • COMPRESSION_LEVEL_DEFAULT

    Esto da un buen compromiso entre velocidad y compresión, y actualmente es equivalente a 6 (esto está en el código de zlib). Este es el nivel que se usará si no se especifica ninguno.

Métodos de Archive::Zip

La clase Archive::Zip (y su subclase invisible Archive::Zip::Archive) implementa la funcionalidad genérica de archivos zip. Crear un nuevo objeto Archive::Zip crea en realidad un objeto Archive::Zip::Archive, pero no tienes que preocuparte por esto a menos que estés creando subclases.

Constructor

new( [$fileName] )
new( { filename => $fileName } )
Crea un archivo zip nuevo y vacío. 
my $zip = Archive::Zip->new();

Si se pasa un argumento adicional, new() llamará a read() para leer el contenido de un archivo:

my $zip = Archive::Zip->new( 'xyz.zip' );

Si se pasa un argumento de nombre de archivo y la lectura falla por cualquier motivo, new devolverá undef. Por esta razón, puede ser mejor llamar a read por separado.

Métodos de utilidad del archivo Zip

Estos métodos de Archive::Zip pueden llamarse como funciones o como métodos de objeto. No los llames como métodos de clase:

$zip = Archive::Zip->new();
$crc = Archive::Zip::computeCRC32( 'ghijkl' );    # OK
$crc = $zip->computeCRC32( 'ghijkl' );            # también OK
$crc = Archive::Zip->computeCRC32( 'ghijkl' );    # NO OK
Archive::Zip::computeCRC32( $string [, $crc] )
Archive::Zip::computeCRC32( { string => $string [, checksum => $crc ] } )
Esta es una función de utilidad que usa la rutina CRC de Compress::Raw::Zlib para calcular un CRC-32. Puedes obtener el CRC de una cadena: 
$crc = Archive::Zip::computeCRC32( $string );

O puedes calcular el CRC acumulado:

$crc = 0;
$crc = Archive::Zip::computeCRC32( 'abcdef', $crc );
$crc = Archive::Zip::computeCRC32( 'ghijkl', $crc );
Archive::Zip::setChunkSize( $number )
Archive::Zip::setChunkSize( { chunkSize => $number } )
Informa o cambia el tamaño de bloque utilizado para leer y escribir. Esto puede hacer grandes diferencias al tratar con archivos grandes. Actualmente, el valor predeterminado es 32K. Esto también cambia el tamaño de bloque utilizado para Compress::Raw::Zlib. Debes llamar a setChunkSize() antes de leer o escribir. Esto no es exportable, así que debes llamarlo así: 
Archive::Zip::setChunkSize( 4096 );

o como método en un zip (aunque esta es una configuración global). Devuelve el tamaño de bloque antiguo.

Archive::Zip::chunkSize()
Devuelve el tamaño de bloque actual: 
my $chunkSize = Archive::Zip::chunkSize();
Archive::Zip::setErrorHandler( \&subroutine )
Archive::Zip::setErrorHandler( { subroutine => \&subroutine } )
Cambia la subrutina que se llama con cadenas de error. Por defecto es \&Carp::carp, pero puedes querer cambiarla para obtener las cadenas de error. Esto no es exportable, así que debes llamarlo así: 
Archive::Zip::setErrorHandler( \&myErrorHandler );

Si myErrorHandler es undef, restablece el manejador al valor predeterminado. Devuelve el manejador de errores antiguo. Ten en cuenta que si llamas a Carp::carp o a una rutina similar o si estás encadenando al manejador de errores predeterminado desde tu manejador de errores, puede que quieras incrementar el número de niveles de llamante que se omiten (no simplemente lo establezcas en un número):

$Carp::CarpLevel++;
Archive::Zip::tempFile( [ $tmpdir ] )
Archive::Zip::tempFile( { tempDir => $tmpdir } )
Crea un archivo temporal con un nombre único. Se devolverá abierto para lectura/escritura. Si $tmpdir se proporciona, se usa como el nombre de un directorio en el que crear el archivo. Si no se proporciona, crea el archivo usando File::Spec::tmpdir(). Generalmente, puedes anular esta elección usando la variable de entorno 
$ENV{TMPDIR}

. Pero consulta la documentación de File::Spec para tu sistema. Ten en cuenta que en muchos sistemas, si estás ejecutando en modo taint, entonces debes asegurarte de que $ENV{TMPDIR} esté limpio (untainted) para que pueda usarse. NO NO creará $tmpdir si no existe (¡esto es un cambio respecto a versiones anteriores!). Devuelve el manejador de archivo y el nombre:

my ($fh, $name) = Archive::Zip::tempFile();
my ($fh, $name) = Archive::Zip::tempFile('myTempDir');
my $fh = Archive::Zip::tempFile();  # si no necesitas el nombre

Accesores del archivo Zip

members()
Devuelve una copia del array de miembros 
my @members = $zip->members();
numberOfMembers()
Devuelve el número de miembros que tengo
memberNames()
Devuelve una lista de los nombres de archivo (internos) de los miembros del zip
memberNamed( $string )
memberNamed( { zipName => $string } )
Devuelve la referencia al miembro cuyo nombre de archivo es igual al nombre de archivo dado o undef. $string debe estar en formato de nombre de archivo de Zip (Unix).
membersMatching( $regex )
membersMatching( { regex => $regex } )
Devuelve un array de miembros cuyos nombres de archivo coinciden con la expresión regular dada en contexto de lista. Devuelve el número de miembros que coinciden en contexto escalar. 
my @textFileMembers = $zip->membersMatching( '.*\.txt' );
# o
my $numberOfTextFiles = $zip->membersMatching( '.*\.txt' );
zip64()
Devuelve si la lectura o escritura anterior del archivo se ha hecho en formato zip64.
desiredZip64Mode()
Obtiene o establece qué partes del archivo deben escribirse en formato zip64: Todas las partes según se necesite (ZIP64_AS_NEEDED), el predeterminado, forzar la escritura del registro de fin del directorio central zip64 (ZIP64_EOCD), forzar la escritura del registro EOCD zip64 y todos los encabezados en formato zip64 (ZIP64_HEADERS).
versionMadeBy()
versionNeededToExtract()
Obtiene los campos del registro de fin del directorio central zip64. Estos son siempre 0 si el archivo no está en formato zip64.
diskNumber()
Devuelve el disco en el que empiezo. No se usa para escribir zips, pero podría ser interesante si lees un zip. Esto debería ser 0, ya que Archive::Zip no maneja archivos de varios volúmenes.
diskNumberWithStartOfCentralDirectory()
Devuelve el número de disco que contiene el comienzo del directorio central. No se usa para escribir zips, pero podría ser interesante si lees un zip. Esto debería ser 0, ya que Archive::Zip no maneja archivos de varios volúmenes.
numberOfCentralDirectoriesOnThisDisk()
Devuelve el número de estructuras CD en el archivo zip leído por última vez. No se usa para escribir zips, pero podría ser interesante si lees un zip.
numberOfCentralDirectories()
Devuelve el número de estructuras CD en el archivo zip leído por última vez. No se usa para escribir zips, pero podría ser interesante si lees un zip.
centralDirectorySize()
Devuelve el tamaño del directorio central, tal como se lee de un archivo zip externo. No se usa para escribir zips, pero podría ser interesante si lees un zip.
centralDirectoryOffsetWRTStartingDiskNumber()
Devuelve el desplazamiento dentro del archivo zip donde comienza el CD. No se usa para escribir zips, pero podría ser interesante si lees un zip.
zipfileComment( [ $string ] )
Obtiene o establece el comentario del archivo zip. Devuelve el comentario antiguo. 
print $zip->zipfileComment();
$zip->zipfileComment( 'New Comment' );
eocdOffset()
Devuelve el número (inesperado) de bytes entre dónde se encontró el EOCD y dónde se esperaba que estuviera. Normalmente esto es 0, pero sería positivo si algo (un virus, quizás) hubiera añadido bytes en algún lugar antes del EOCD. No se usa para escribir zips, pero podría ser interesante si lees un zip. Aquí tienes un ejemplo de cómo diagnosticar esto: 
my $zip = Archive::Zip->new('somefile.zip');
if ($zip->eocdOffset())
{
  warn "A virus has added ", $zip->eocdOffset, " bytes of garbage\n";
}

El eocdOffset() se usa para ajustar la posición inicial de las cabeceras de los miembros, si es necesario.

fileName()
Devuelve el nombre del último archivo del que se ha leído. Si aún no se ha leído nada, devuelve una cadena vacía; si se ha leído desde un manejador de archivo, devuelve el manejador en forma de cadena.

Operaciones con miembros de archivos Zip

Varias operaciones sobre un archivo zip modifican miembros. Cuando se pasa un miembro como argumento, puedes usar una referencia al miembro mismo o el nombre de un miembro. Por supuesto, usar el nombre requiere que los nombres sean únicos dentro de un zip (esto no se verifica).

removeMember( $memberOrName )
removeMember( { memberOrZipName => $memberOrName } )
Elimina y devuelve el miembro dado, o busca su nombre y lo elimina. Devuelve undef si el miembro o el nombre no existen en este Zip. No hace nada si el miembro no pertenece a este zip.
replaceMember( $memberOrName, $newMember )
replaceMember( { memberOrZipName => $memberOrName, newMember => $newMember } )
Elimina y devuelve el miembro dado, o busca su nombre y lo elimina. Lo reemplaza con el nuevo miembro. Devuelve undef si el miembro o el nombre no existen en este Zip, o si $newMember está indefinido.

Es un error (no diagnosticado) proporcionar un $newMember que sea un miembro del zip que se está modificando.

my $member1 = $zip->removeMember( 'xyz' );
my $member2 = $zip->replaceMember( 'abc', $member1 );
# now, $member2 (named 'abc') is not in $zip,
# and $member1 (named 'xyz') is, having taken $member2's place.
extractMember( $memberOrName [, $extractedName ] )
extractMember( { memberOrZipName => $memberOrName [, name => $extractedName ] } )
Extrae el miembro dado, o busca su nombre y lo extrae. Devuelve undef si el miembro no existe en este Zip. Si se proporciona el segundo argumento opcional, se usa como el nombre del miembro extraído. De lo contrario, se usa el nombre de archivo interno del miembro como el nombre del archivo o directorio extraído. Si pasas $extractedName, debe estar en el formato del sistema de archivos local. Si no pasas $extractedName y el nombre de archivo interno recorre un directorio padre o un enlace simbólico, la extracción se abortará con "AC_ERROR" por razones de seguridad. Se crearán todos los directorios necesarios. Devuelve "AZ_OK" en caso de éxito.
extractMemberWithoutPaths( $memberOrName [, $extractedName ] )
extractMemberWithoutPaths( { memberOrZipName => $memberOrName [, name => $extractedName ] } )
Extrae el miembro dado, o busca su nombre y lo extrae. No usa información de ruta (extrae en el directorio actual). Devuelve undef si el miembro no existe en este Zip. Si se proporciona el segundo argumento opcional, se usa como el nombre del miembro extraído (sus rutas también se eliminarán). De lo contrario, se usa el nombre de archivo interno del miembro (sin rutas) como el nombre del archivo o directorio extraído. Devuelve "AZ_OK" en caso de éxito. Si no pasas $extractedName y el nombre de archivo interno es igual a un enlace simbólico local, la extracción se abortará con "AC_ERROR" por razones de seguridad.
addMember( $member )
addMember( { member => $member } )
Añade un miembro (posiblemente de otro archivo zip) al archivo zip. Devuelve el nuevo miembro. Generalmente, usarás addFile(), addDirectory(), addFileOrDirectory(), addString(), o read() para añadir miembros. 
# Move member named 'abc' to end of zip:
my $member = $zip->removeMember( 'abc' );
$zip->addMember( $member );
updateMember( $memberOrName, $fileName )
updateMember( { memberOrZipName => $memberOrName, name => $fileName } )
Actualiza un solo miembro desde el archivo o directorio llamado $fileName. Devuelve el miembro (posiblemente añadido o actualizado), si lo hay; "undef" en caso de error. La comparación se basa en lastModTime() y (en el caso de un no directorio) el tamaño del archivo.
addFile( $fileName [, $newName, $compressionLevel ] )
addFile( { filename => $fileName [, zipName => $newName, compressionLevel => $compressionLevel } ] )
Añade un miembro cuyos datos provienen de un archivo externo, devolviendo el miembro o undef. El miembro tendrá su nombre de archivo establecido al nombre del archivo externo, y su desiredCompressionMethod establecido a COMPRESSION_DEFLATED. Los atributos del archivo y la hora de última modificación se establecerán a partir del archivo. Si el nombre dado no representa un archivo plano legible o un enlace simbólico, se devolverá undef. $fileName debe estar en el formato requerido para el sistema de archivos local. El argumento opcional $newName establece el nombre de archivo interno a algo diferente del $fileNamedado. $newName, si se proporciona, debe estar en formato de nombre Zip (es decir, Unix). El bit de modo texto se establecerá si el contenido parece ser texto (como lo devuelve el "-T" operador de perl).

NOTA que no deberías (generalmente) usar nombres de ruta absolutos en los nombres de los miembros del zip, ya que esto causará problemas con algunas herramientas de zip, además de introducir un fallo de seguridad y hacer que el zip sea más difícil de usar.

addDirectory( $directoryName [, $fileName ] )
addDirectory( { directoryName => $directoryName [, zipName => $fileName ] } )
Añade un miembro creado a partir del nombre de directorio dado. El nombre del directorio no tiene que nombrar un directorio existente. Si el directorio nombrado existe, la hora de modificación del archivo y los permisos se establecen a partir del directorio existente; de lo contrario, se establecen a la hora actual y permisos predeterminados permisivos. $directoryName debe estar en formato de sistema de archivos local. El segundo argumento opcional establece el nombre del miembro del archivo (que por defecto es $directoryName). Si se proporciona, debe estar en formato Zip (Unix). Devuelve el nuevo miembro.
addFileOrDirectory( $name [, $newName, $compressionLevel ] )
addFileOrDirectory( { name => $name [, zipName => $newName, compressionLevel => $compressionLevel ] } )
Añade un miembro desde el archivo o directorio llamado $name. Si $newName se proporciona, úsalo como el nombre del nuevo miembro. Añadirá o eliminará barras diagonales finales de $newName según sea necesario. $name debe estar en formato de sistema de archivos local. El segundo argumento opcional establece el nombre del miembro del archivo (que por defecto es $name). Si se proporciona, debe estar en formato Zip (Unix).
addString( $stringOrStringRef, $name, [$compressionLevel] )
addString( { string => $stringOrStringRef [, zipName => $name, compressionLevel => $compressionLevel ] } )
Añade un miembro creado a partir de la cadena o referencia a cadena dada. El nombre lo proporciona el segundo argumento. Devuelve el nuevo miembro. La hora de última modificación se establecerá a la hora actual, y los atributos del archivo se establecerán a predeterminados permisivos. 
my $member = $zip->addString( 'This is a test', 'test.txt' );
contents( $memberOrMemberName [, $newContents ] )
contents( { memberOrZipName => $memberOrMemberName [, contents => $newContents ] } )
Devuelve los datos sin comprimir de un miembro particular, o undef. 
print "xyz.txt contains " . $zip->contents( 'xyz.txt' );

También puede cambiar el contenido de un miembro:

$zip->contents( 'xyz.txt', 'This is the new contents' );

Si se llama esperando un array como valor de retorno, incluirá el estado como segundo valor en el array.

($content, $status) = $zip->contents( 'xyz.txt');

Operaciones de E/S de archivos Zip

Un archivo Zip puede escribirse en un archivo o manejador de archivo, o leerse de uno.

writeToFileNamed( { fileName => $fileName } )
Escribe un archivo zip en un archivo con nombre. Devuelve "AZ_OK" en caso de éxito. 
my $status = $zip->writeToFileNamed( 'xx.zip' );
die "error somewhere" if $status != AZ_OK;

Ten en cuenta que si usas el mismo nombre que un archivo zip existente que leíste, sobrescribirás (clobber) los ZipFileMembers. En su lugar, escribe en un nombre de archivo diferente, luego elimina el original. Si usas los overwrite() o overwriteAs() métodos, puedes reescribir el zip original de esta manera. $fileName debe ser un nombre de archivo válido en tu sistema.

writeToFileHandle( $fileHandle [, $seekable] )
Escribe un archivo zip en un manejador de archivo (file handle). Devuelve AZ_OK en caso de éxito. El segundo argumento opcional indica si se debe intentar buscar (seek) hacia atrás para reescribir encabezados. Si no se proporciona, se establece en función de si la prueba "-f" de Perl devuelve verdadero. Esto podría fallar en algunos sistemas operativos, sin embargo. 
my $fh = IO::File->new( 'someFile.zip', 'w' );
unless ( $zip->writeToFileHandle( $fh ) == AZ_OK ) {
    # error handling
}

Si pasas un manejador de archivo que no es buscable (como si estuvieras escribiendo en una tubería (pipe) o un socket), pasa un segundo argumento falso:

my $fh = IO::File->new( '| cat > somefile.zip', 'w' );
$zip->writeToFileHandle( $fh, 0 );   # fh is not seekable

Si este método falla durante la escritura de un miembro, ese miembro y todos los que le sigan devolverán falso desde wasWritten(). Ver writeCentralDirectory() para una forma de manejar esto. Si quieres, puedes escribir datos en el archivo manejador antes de pasarlo a writeToFileHandle(); esto podría usarse (por ejemplo) para hacer archivos autoextraíbles. Sin embargo, esto solo funciona de manera confiable al escribir en un archivo real (a diferencia de STDOUT o algún otro posible no-archivo).

Ver examples/selfex.pl para cómo escribir un archivo autoextraíble.

writeCentralDirectory( $fileHandle [, $offset ] )
writeCentralDirectory( { fileHandle => $fileHandle [, offset => $offset ] } )
Escribe la estructura del directorio central en el manejador de archivo dado.

Devuelve AZ_OK en caso de éxito. Si se le da un $offset, buscará (seek) ese punto antes de escribir. Esto se puede usar para la recuperación en casos donde writeToFileHandle o writeToFileNamed devuelven un error IO por falta de espacio en el archivo de destino.

Puedes truncar el zip buscando hacia atrás y luego escribiendo el directorio:

my $fh = IO::File->new( 'someFile.zip', 'w' );
    my $retval = $zip->writeToFileHandle( $fh );
if ( $retval == AZ_IO_ERROR ) {
    my @unwritten = grep { not $_->wasWritten() } $zip->members();
    if (@unwritten) {
        $zip->removeMember( $member ) foreach my $member ( @unwritten );
        $zip->writeCentralDirectory( $fh,
        $unwritten[0]->writeLocalHeaderRelativeOffset());
    }
}
overwriteAs( $newName )
overwriteAs( { filename => $newName } )
Escribe el zip en el archivo especificado, de la manera más segura posible. Esto se hace escribiendo primero en un archivo temporal, luego renombrando el original si existe, luego renombrando el archivo temporal, luego eliminando el original renombrado si existe. Devuelve AZ_OK si es exitoso.
overwrite()
Escribe de vuelta en el archivo zip original. Ver overwriteAs() arriba. Si el zip nunca se leyó de un archivo, esto genera un error.
read( $fileName )
read( { filename => $fileName } )
Lee los encabezados del archivo zip desde un archivo zip, añadiendo nuevos miembros. Devuelve "AZ_OK" o un código de error. 
my $zipFile = Archive::Zip->new();
my $status = $zipFile->read( '/some/FileName.zip' );
readFromFileHandle( $fileHandle, $filename )
readFromFileHandle( { fileHandle => $fileHandle, filename => $filename } )
Lee los encabezados del archivo zip desde un manejador de archivo ya abierto, añadiendo nuevos miembros. No cierra el manejador de archivo. Devuelve "AZ_OK" o un código de error. Ten en cuenta que esto requiere un manejador de archivo buscable; leer desde un stream aún no está soportado, pero usar datos en memoria sí lo está. 
my $fh = IO::File->new( '/some/FileName.zip', 'r' );
my $zip1 = Archive::Zip->new();
my $status = $zip1->readFromFileHandle( $fh );
my $zip2 = Archive::Zip->new();
$status = $zip2->readFromFileHandle( $fh );

Lee el zip usando datos en memoria (recursable):

open my $fh, "<", "archive.zip" or die $!;
my $zip_data = do { local $.; <$fh> };
my $zip = Archive::Zip->new;
open my $dh, "+<", \$zip_data;
$zip->readFromFileHandle ($dh);

Zip Operaciones sobre árboles de archivos

Estos solían estar en Archive::Zip::Tree pero fueron movidos a Archive::Zip. Permiten operar sobre un árbol completo de miembros o archivos. Un ejemplo de uso:

use Archive::Zip;
my $zip = Archive::Zip->new();
# add all readable files and directories below . as xyz/*
$zip->addTree( '.', 'xyz' );
# add all readable plain files below /abc as def/*
$zip->addTree( '/abc', 'def', sub { -f && -r } );
# add all .c files below /tmp as stuff/*
$zip->addTreeMatching( '/tmp', 'stuff', '\.c$' );
# add all .o files below /tmp as stuff/* if they aren't writable
$zip->addTreeMatching( '/tmp', 'stuff', '\.o$', sub { ! -w } );
# add all .so files below /tmp that are smaller than 200 bytes as stuff/*
$zip->addTreeMatching( '/tmp', 'stuff', '\.o$', sub { -s < 200 } );
# and write them into a file
$zip->writeToFileNamed('xxx.zip');
# now extract the same files into /tmpx
$zip->extractTree( 'stuff', '/tmpx' );
$zip->addTree( $root, $dest [, $pred, $compressionLevel ] ) -- Añade un árbol de archivos a un zip
$zip->addTree( { root => $root, zipName => $dest [, select => $pred, compressionLevel => $compressionLevel ] )
$root es la raíz del árbol de archivos y directorios a añadir. Es un nombre de directorio válido en tu sistema. $dest es el nombre para la raíz en el archivo zip (undef o vacío significa usar rutas relativas). Es un nombre de directorio ZIP válido (es decir, usa barras diagonales (/) para separar los componentes del directorio). $pred es una referencia a subrutina opcional para seleccionar archivos: se le pasa el nombre del archivo o directorio prospectivo usando $_, y si devuelve verdadero, el archivo o directorio será incluido. El valor por defecto es añadir todos los archivos y directorios legibles. Por ejemplo, usando 
my $pred = sub { /\.txt/ };
$zip->addTree( '.', '', $pred );

añadirá todos los archivos .txt en y debajo del directorio actual, usando nombres relativos, y haciendo que los nombres sean idénticos en el archivo zip:

original name           zip member name
./xyz                   xyz
./a/                    a/
./a/b                   a/b

Para traducir rutas absolutas a relativas, simplemente pásalas así: $zip->addTree( '/c/d', 'a' );

original name           zip member name
/c/d/xyz                a/xyz
/c/d/a/                 a/a/
/c/d/a/b                a/a/b

Devuelve AZ_OK en caso de éxito. Ten en cuenta que esto no seguirá enlaces simbólicos a directorios. Ten en cuenta también que esto no verifica la validez de los nombres de archivo.

Ten en cuenta que generalmente no quieres hacer que los nombres de los miembros del archivo zip sean absolutos.

$zip->addTreeMatching( $root, $dest, $pattern [, $pred, $compressionLevel ] )
$zip->addTreeMatching( { root => $root, zipName => $dest, pattern => $pattern [, select => $pred, compressionLevel => $compressionLevel ] } )
$root es la raíz del árbol de archivos y directorios a añadir $dest es el nombre para la raíz en el archivo zip (undef significa usar rutas relativas) $pattern es una expresión regular (sin anclar) para los nombres de archivo a coincidir $pred es una referencia a subrutina opcional para seleccionar archivos: se le pasa el nombre del archivo o directorio prospectivo en $_, y si devuelve verdadero, el archivo o directorio será incluido. El valor por defecto es añadir todos los archivos y directorios legibles. Para añadir todos los archivos en y debajo del directorio actual cuyos nombres terminen en ".pl", y hacerlos extraer en un subdirectorio llamado "xyz", haz esto: 
$zip->addTreeMatching( '.', 'xyz', '\.pl$' )

Para añadir todos los archivos escribibles en y debajo del directorio llamado "/abc" cuyos nombres terminen en ".pl", y hacerlos extraer en un subdirectorio llamado "xyz", haz esto:

$zip->addTreeMatching( '/abc', 'xyz', '\.pl$', sub { -w } )

Devuelve AZ_OK en caso de éxito. Ten en cuenta que esto no seguirá enlaces simbólicos a directorios.

$zip->updateTree( $root [, $dest , $pred , $mirror, $compressionLevel ] );
$zip->updateTree( { root => $root [, zipName => $dest, select => $pred, mirror => $mirror, compressionLevel => $compressionLevel ] } );
Actualiza un archivo zip desde un árbol de directorios.

updateTree() toma los mismos argumentos que addTree(), pero primero verifica si el archivo o directorio ya existe en el archivo zip, y si ha sido modificado.

Si el cuarto argumento $mirror es verdadero, entonces elimina todos mis miembros si los archivos correspondientes no se encontraron.

Devuelve un código de error o AZ_OK si todo está bien.

$zip->extractTree( [ $root, $dest, $volume } ] )
$zip->extractTree( [ { root => $root, zipName => $dest, volume => $volume } ] )
Si no proporcionas ningún argumento, se extraerán todos los archivos del zip con sus nombres originales.

Si proporcionas un argumento para $root, "extractTree" extraerá todos los miembros cuyos nombres comiencen con $root en el directorio actual, eliminando primero $root . $root está en formato Zip (Unix). Por ejemplo,

$zip->extractTree( 'a' );

cuando se aplica a un zip que contiene los archivos: a/x a/b/c ax/d/e d/e extraerá:

a/x como ./x

a/b/c como ./b/c

Si proporcionas dos argumentos, "extractTree" extrae todos los miembros cuyos nombres comiencen con $root. Convertirá $root en $dest para construir el nombre del archivo de destino. $root y $dest están en formato Zip (Unix). Por ejemplo,

$zip->extractTree( 'a', 'd/e' );

cuando se aplica a un zip que contiene los archivos: a/x a/b/c ax/d/e d/e extraerá:

a/x a d/e/x

a/b/c a d/e/b/c e ignorará ax/d/e y d/e

Si proporcionas tres argumentos, "extractTree" extrae todos los miembros cuyos nombres comiencen con $root. Convertirá $root en $dest para construir el nombre del archivo de destino, y luego lo convertirá al formato del sistema de archivos local, usando $volume como nombre del volumen de destino.

$root y $dest están en formato Zip (Unix).

$volume está en formato del sistema de archivos local.

Por ejemplo, en Windows,

$zip->extractTree( 'a', 'd/e', 'f:' );

cuando se aplica a un zip que contiene los archivos: a/x a/b/c ax/d/e d/e extraerá:

a/x a f:d/e/x

a/b/c a f:d/e/b/c e ignorará ax/d/e y d/e

Si deseas rutas absolutas (el ejemplo anterior usó rutas relativas al directorio actual en el volumen de destino), puedes especificarlas en $dest:

$zip->extractTree( 'a', '/d/e', 'f:' );

cuando se aplica a un zip que contiene los archivos: a/x a/b/c ax/d/e d/e extraerá:

a/x a f:\d\e\x

a/b/c a f:\d\e\b\c e ignorará ax/d/e y d/e

Si la ruta al archivo extraído atraviesa un directorio padre o un enlace simbólico, la extracción se abortará con "AC_ERROR" por razones de seguridad. Devuelve un código de error o AZ_OK si todo funcionó correctamente.

OPERACIONES DE MIEMBROS

Métodos de Clase de Miembro

Varios constructores te permiten construir miembros sin añadirlos a un archivo zip. Funcionan igual que los métodos de instancia de zip addFile(), addDirectory(), y addString() descritos arriba, pero no añaden los nuevos miembros a un zip.

Archive::Zip::Member->newFromString( $stringOrStringRef [, $fileName ] )
Archive::Zip::Member->newFromString( { string => $stringOrStringRef [, zipName => $fileName ] )
Construye un nuevo miembro a partir de la cadena dada. Devuelve undef en caso de error. 
my $member = Archive::Zip::Member->newFromString( 'This is a test' );
my $member = Archive::Zip::Member->newFromString( 'This is a test', 'test.txt' );
my $member = Archive::Zip::Member->newFromString( { string => 'This is a test', zipName => 'test.txt' } );
newFromFile( $fileName [, $zipName ] )
newFromFile( { filename => $fileName [, zipName => $zipName ] } )
Construye un nuevo miembro a partir del archivo dado. Devuelve undef en caso de error. 
my $member = Archive::Zip::Member->newFromFile( 'xyz.txt' );
newDirectoryNamed( $directoryName [, $zipname ] )
newDirectoryNamed( { directoryName => $directoryName [, zipName => $zipname ] } )
Construye un nuevo miembro a partir del directorio dado. $directoryName debe ser un nombre válido en tu sistema de archivos; no tiene que existir.

Si se proporciona, $zipname será el nombre del miembro del zip; debe ser un nombre válido de Zip (Unix). Si no se proporciona, se convertirá a partir de $directoryName.

Devuelve undef en caso de error.

my $member = Archive::Zip::Member->newDirectoryNamed( 'CVS/' );

Lectura de datos de miembros de bajo nivel

Es posible usar rutinas de bajo nivel para acceder a los flujos de datos de los miembros, en lugar de los métodos extract* y contents(). Por ejemplo, así es como se imprimen los contenidos sin comprimir de un miembro en trozos usando estos métodos:

my ( $member, $status, $bufferRef );
$member = $zip->memberNamed( 'xyz.txt' );
$member->desiredCompressionMethod( COMPRESSION_STORED );
$status = $member->rewindData();
die "error $status" unless $status == AZ_OK;
while ( ! $member->readIsDone() )
{
( $bufferRef, $status ) = $member->readChunk();
die "error $status"
            if $status != AZ_OK && $status != AZ_STREAM_END;
# hacer algo con $bufferRef:
print $$bufferRef;
}
$member->endRead();
readChunk( [ $chunkSize ] )
readChunk( [ { chunkSize => $chunkSize } ] )
Esto lee el siguiente trozo del tamaño dado del flujo de datos del miembro y lo comprime o descomprime según sea necesario, devolviendo una referencia a los bytes leídos y un estado. Si el argumento de tamaño no es dado, usa por defecto el valor global establecido por Archive::Zip::setChunkSize. El estado es AZ_OK en caso de éxito hasta el último trozo, donde devuelve AZ_STREAM_END. Devuelve "( \$bytes, $status)". 
my ( $outRef, $status ) = $self->readChunk();
print $$outRef if $status != AZ_OK && $status != AZ_STREAM_END;
rewindData()
Rebobina los datos y prepara para leer flujos de datos o escribir archivos zip. Puede tomar opciones para inflateInit() o deflateInit(), pero esto no es probable que sea necesario. Las sobreescrituras de subclases deberían llamar a este método. Devuelve "AZ_OK" en caso de éxito.
endRead()
Restablece las variables de lectura y libera el inflador o el deflador. Debe ser llamado para cerrar archivos, etc. Devuelve AZ_OK en caso de éxito.
readIsDone()
Devuelve verdadero si la lectura se ha quedado sin datos o ha encontrado un error.
contents()
Devuelve todos los datos del miembro sin comprimir o undef en contexto escalar. Cuando se llama en contexto de matriz, devuelve "( $string, $status )"; el estado será AZ_OK en caso de éxito: 
my $string = $member->contents();
# o
my ( $string, $status ) = $member->contents();
die "error $status" unless $status == AZ_OK;

También puede usarse para establecer los contenidos de un miembro (esto puede cambiar la clase del miembro):

$member->contents( "estos son mis nuevos contenidos" );
extractToFileHandle( $fh )
extractToFileHandle( { fileHandle => $fh } )
Extrae (y descomprime, si es necesario) los contenidos del miembro al manejador de archivo dado. Devuelve AZ_OK en caso de éxito.

Para miembros que representan enlaces simbólicos, pase el nombre del enlace simbólico como manejador de archivo. Asegúrese de que todos los directorios en la ruta hacia el enlace simbólico ya existan.

La clase Archive::Zip::FileMember extiende Archive::Zip::Member. Es la clase base para las clases ZipFileMember y NewFileMember. Esta clase añade un "externalFileName" y un "fh" miembro para llevar la cuenta del archivo externo.

externalFileName()
Devuelve el nombre de archivo externo del miembro.
fh()
Devuelve el manejador de archivo de lectura del miembro. Abre el archivo automáticamente si es necesario.

Archive::Zip::ZipFileMember métodos

La clase Archive::Zip::ZipFileMember representa miembros que han sido leídos de archivos zip externos.

diskNumberStart()
Devuelve el número de disco en el que reside el encabezado local del miembro. Debería ser 0.
localHeaderRelativeOffset()
Devuelve el desplazamiento dentro del archivo zip donde se encuentra el encabezado local del miembro.
dataOffset()
Devuelve el desplazamiento desde el principio del archivo zip hasta los datos del miembro.

ERRORES Y ADVERTENCIAS

Cuándo no usar Archive::Zip

Si solo va a extraer archivos zip (y/o otros archivos), se recomienda que use Archive::Extract, ya que es mucho más fácil de usar y separa la funcionalidad específica de los archivos.

Soporte del formato Zip64

Desde la versión 1.66, Archive::Zip soporta el llamado formato zip64, que supera varias limitaciones en el formato original de archivo zip. Sin embargo, en algunos intérpretes de Perl, incluso la versión 1.66 y posteriores de Archive::Zip no pueden soportar el formato zip64. Entre estos se encuentran todos los intérpretes de Perl que carecen de soporte de 64 bits y aquellos anteriores a la versión 5.10.0.

Constante "ZIP64_SUPPORTED", exportada con la etiqueta :CONSTANTS, es verdadera si Archive::Zip en el intérprete de Perl actual soporta el formato zip64. Si no lo soporta e intenta leer o escribir un archivo en formato zip64 de todos modos, Archive::Zip devuelve un error "AZ_ERROR" e informa un mensaje de error del tipo "zip64 format not supported on this Perl interpreter".

"versionMadeBy" y "versionNeededToExtract"

El formato zip64 y el formato de archivo zip en general especifican qué valores usar para los campos "versionMadeBy" y "versionNeededToExtract" en el encabezado de archivo local, el encabezado de archivo del directorio central y el registro zip64 EOCD. En la práctica, sin embargo, estos campos parecen ser usados más o menos aleatoriamente por varias implementaciones de archivadores.

Para lograr un compromiso entre la compatibilidad hacia atrás y el cumplimiento (de algún) estándar, Archive::Zip los maneja de la siguiente manera:

  • Para el campo "versionMadeBy", Archive::Zip usa el valor predeterminado 20 (45 para el registro zip64 EOCD) o cualquier valor leído previamente. Nunca cambia ese valor al escribir un encabezado, incluso si se escribe en formato zip64, o al escribir el registro zip64 EOCD.
  • Del mismo modo para el campo "versionNeededToExtract", pero aquí Archive::Zip fuerza un valor mínimo de 45 al escribir un encabezado en formato zip64 o el registro zip64 EOCD.
  • Finalmente, Archive::Zip nunca depende de los valores de estos campos de ninguna manera al leer un archivo desde un archivo o manejador de archivo.

Intente evitar IO::Scalar

Una de las formas más comunes de usar Archive::Zip es generar archivos Zip en memoria. La mayoría de las personas usan IO::Scalar para este propósito.

Desafortunadamente, a partir de la versión 1.11, este módulo ya no funciona con IO::Scalar ya que implementa incorrectamente el posicionamiento.

Cualquiera que use IO::Scalar debería considerar migrar a IO::String, que es más pequeño, más ligero y está implementado para ser perfectamente compatible con manejadores de archivo posicionables regulares.

Es muy probable que el soporte para IO::Scalar no se restaure en el futuro, ya que IO::Scalar en sí mismo no puede cambiar la forma en que está implementado debido a problemas de compatibilidad hacia atrás.

Contraseña incorrecta para miembros cifrados

Cuando se lee un miembro cifrado con la contraseña incorrecta, actualmente tiene que volver a leer todo el archivo para intentarlo de nuevo con la contraseña correcta.
