DESCRIPCIÓN

Estas funciones proporcionan acceso a diversa información sobre el objeto struct archive utilizado en la biblioteca libarchive(3) .

archive_clear_error()
Borra cualquier información de error dejada por una llamada anterior. No se usa generalmente en el código del cliente.
archive_compression()
Sinónimo de archive_filter_code(a, 0).
archive_compression_name()
Sinónimo de archive_filter_name(a, 0).
archive_copy_error()
Copia la información de error de un archivo a otro.
archive_errno()
Devuelve un código de error numérico (ver errno(2)) que indica el motivo del último error devuelto. Nótese que esto no puede usarse de forma fiable para detectar si ha ocurrido un error. Debería usarse solo después de que otra función de libarchive haya devuelto un estado de error.
archive_error_string()
Devuelve un mensaje de error textual adecuado para mostrar. El mensaje de error aquí es usualmente más específico que el obtenido al pasar el resultado de archive_errno() a strerror(3).
archive_file_count()
Devuelve un recuento del número de archivos procesados por este objeto de archivo. El recuento se incrementa mediante las llamadas a archive_write_header(3) o archive_read_next_header(3).
archive_filter_code()
Devuelve un código numérico que identifica el filtro indicado. Ver archive_filter_count() para detalles de la numeración.
archive_filter_count()
Devuelve el número de filtros en la tubería actual. Para manejadores de lectura de archivos, estos filtros se añaden automáticamente por la detección automática de formato. Para manejadores de escritura de archivos, estos filtros se añaden mediante las llamadas a las diversas funciones archive_write_add_filter_XXX() . Los filtros en la tubería resultante están numerados de modo que el filtro 0 es el filtro más cercano al manejador de formato. Por conveniencia, las funciones que esperan un número de filtro aceptarán -1 como sinónimo del filtro con el número más alto.

Por ejemplo, al leer un archivo tar comprimido con gzip y codificado con uuencode, hay tres filtros: el filtro 0 es el filtro gunzip, el filtro 1 es el filtro uudecode, y el filtro 2 es el pseudo-filtro que envuelve las funciones de lectura de archivos. En este caso, solicitar archive_position(a, -1) sería un sinónimo de archive_position(a, 2) que devolvería el número de bytes actualmente leídos del archivo, mientras que archive_position(a, 1) devolvería el número de bytes después de la decodificación uu, y archive_position(a, 0) devolvería el número de bytes después de la descompresión.

archive_filter_name()
Devuelve un nombre textual que identifica el filtro indicado. Ver archive_filter_count() para detalles de la numeración.
archive_format()
Devuelve un código numérico que indica el formato de la entrada actual del archivo. Este valor se establece mediante una llamada exitosa a archive_read_next_header(). Nótese que es común que este valor cambie de una entrada a otra. Por ejemplo, un archivo tar podría tener varias entradas que utilizan extensiones de GNU tar y varias entradas que no. Estas entradas tendránferentes códigos de formato.
archive_format_name()
Una descripción textual del formato de la entrada actual.
archive_position()
Devuelve el número de bytes leídos de o escritos en el filtro indicado. En particular, archive_position(a, 0) devuelve el número de bytes leídos o escritos por el manejador de formato, mientras que archive_position(a, -1) devuelve el número de bytes leídos o escritos en el archivo. Véase archive_filter_count() para detalles sobre la numeración aquí.
archive_set_error()
Establece el código de error numérico y la descripción del error que serán devueltos por archive_errno() y archive_error_string(). Esta función debe usarse dentro de las devoluciones de llamada de E/S para establecer códigos de error y descripciones de error específicos del sistema. Esta función acepta una cadena de formato similar a printf y argumentos. Sin embargo, debe tener cuidado de usar solo los siguientes especificadores de formato printf: “%c”, “%d”, “%jd”, “%jo”, “%ju”, “%jx”, “%ld”, “%lo”, “%lu”, “%lx”, “%o”, “%u”, “%s”, “%x”, “%%”. Los especificadores de ancho de campo y otras funciones de printf no se admiten de manera uniforme y no deben usarse.
