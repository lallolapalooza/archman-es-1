ares_set_pending_write_cb(3)

Paquete: c-ares

Licencias: MIT

ARES_SET_NOTIFY_PENDING_WRITE_CALLBACK(3) Manual de funciones de la biblioteca ARES_SET_NOTIFY_PENDING_WRITE_CALLBACK(3)

NOMBRE

ares_set_pending_write_cb, ares_process_pending_write - Función para establecer una devolución de llamada que se activa cuando hay datos pendientes potenciales que deben escribirse.

SINOPSIS

#include <ares.h>
typedef void (*ares_pending_write_cb)(void *data);
void ares_set_pending_write_cb(
  ares_channel_t        *channel,
  ares_pending_write_cb  callback,
  void                  *user_data);
void ares_process_pending_write(ares_channel_t *channel);

DESCRIPCIÓN

La función ares_set_pending_write_cb(3) establece una función de devolución de llamada callback en el manejador de canal ares dado channel que se invoca cada vez que hay nuevos datos TCP pendientes para escribir. Dado que TCP se basa en flujos, si hay varias consultas encoladas una detrás de otra, pueden enviarse como un único buffer grande. Normalmente, se activaría una operación de llamada al sistema send(2) por cada consulta.

Al establecer esta devolución de llamada, se activará un evento cuando los datos se almacenen en búfer, pero no se escriban. Este evento se utiliza para despertar el bucle de eventos del llamador, que debe llamar a ares_process_pending_write(3) utilizando el canal asociado con la devolución de llamada. Cada vez que se active la devolución de llamada, debe resultar en una llamada a ares_process_pending_write(3) desde el bucle de eventos del llamador; de lo contrario, pueden ocurrir bloqueos y tiempos de espera agotados. La devolución de llamada **no debe** llamar directamente a ares_process_pending_write(3), ya que de lo contrario invalidaría cualquier ventaja de este caso de uso.

Esto se considera una optimización, especialmente cuando se utilizan conexiones basadas en TLS que añaden sobrecarga adicional al flujo de datos. Debido a la naturaleza asíncrona de c-ares, no hay forma de identificar cuándo un llamador puede haber terminado de encolar consultas a través de ninguna de las posibles llamadas a la API pública, como ares_getaddrinfo(3) o ares_search_dnsrec(3), por lo que esta es una mejora para intentar agrupar las operaciones de envío de consultas y dependerá de la latencia de señalización involucrada en despertar el bucle de eventos del usuario.

Si no se establece ninguna devolución de llamada, los datos se escribirán inmediatamente en el socket, omitiendo así esta optimización.

Esta opción no se puede utilizar con ARES_OPT_EVENT_THREAD pasado a ares_init_options(3) ya que el usuario no tiene un bucle de eventos. Esta optimización se habilita automáticamente cuando se utiliza el Hilo de Eventos, ya que establece la devolución de llamada para su propia señalización interna.

DISPONIBILIDAD

Esta función se introdujo por primera vez en la versión 1.34.0 de c-ares.
