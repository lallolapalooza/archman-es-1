val make : int -> 'a -> 'a

array

make n x devuelve un array nuevo de longitud n , inicializado con x . Todos los elementos de este nuevo array son inicialmente físicamente iguales a x (en el sentido del predicado ==). Arrays y seguridad de

concurrencia

Se debe tener cuidado al acceder a arrays concurrentemente desde múltiples dominios

: acceder a un array nunca hará que un programa se bloquee, pero los accesos no si
ncronizados pueden producir resultados sorprendentes (no secuencialmente consistentes).

Atomicida

d

Toda operación de array que accede a más de un elemento del array no es atómica. Esto incluye la iteración, la búsqueda, el ordenamiento, la división y la combinación de

arrays.

Por ejemplo, considere el siguiente

programa: 
let size = 100_000_000
let a = ArrayLabels.make size 1
let d1 = Domain.spawn (fun () ->
   ArrayLabels.iteri ~f:(fun i x -> a.(i) <- x + 1) a
)
let d2 = Domain.spawn (fun () ->
  ArrayLabels.iteri ~f:(fun i x -> a.(i) <- 2 * x + 1) a
)
let () = Domain.join d1; Domain.join d2

Después de ejecutar este código, cada campo del array a es o bien 2 , 3 , 4 o 5 . Si se requiere atomicidad, entonces el usuario debe implementar su propia sincronización (por ejemplo, usando Mutex.t

)
.

Carreras de

datos

Si dos dominios solo acceden a partes disjuntas del array, entonces el comportamiento observado es equivalente a alguna intercalación secuencial de las operaciones de los dos

dominios.

A Se dice que ocurre una condición de carrera de datos cuando dos dominios acceden al mismo elemento de un arreglo sin sincronización y al menos uno de los accesos es una escritura. En ausencia de condiciones de carrera de datos, el comportamiento observado es equivalente a alguna intercalación secuencial de las operaciones de diferentes

dominios.

Siempre que sea posible, las condiciones de carrera de datos deben evitarse utilizando sincronización para mediar los accesos a los elementos del

arreglo.

De hecho, en presencia de condiciones de carrera de datos, los programas no se bloquearán pero el comportamiento observado puede no ser equivale

nte a ninguna intercalación secuencial de operaciones de diferentes dominios. Sin embargo, incluso en presencia de condiciones de carrera de dato
s, una operación de lectura devolverá el valor de alguna escritura previa a esa ubicación (con algunas excepciones para arreglos de tipo float).

Arreglos de tipo

float

Los arreglos de tipo float tienen dos advertencias adicionales en presencia de condiciones de carrera de

datos.

Primero, la operación blit podría copiar un arreglo byte a byte. Las condiciones de carrera de datos entre una operación blit y otra operación podrían producir valores sorprendentes debido a la descomposición (tearing): escrituras parciales intercaladas con otras operaciones pueden crear valores de tipo float que no existirían con una ejecución

secuencial.

Por ejemplo, al final

de 
let zeros = Array.make size 0.
let max_floats = Array.make size Float.max_float
let res = Array.copy zeros
let d1 = Domain.spawn (fun () -> Array.blit zeros 0 res 0 size)
let d2 = Domain.spawn (fun () -> Array.blit max_floats 0 res 0 size)
let () = Domain.join d1; Domain.join d2
el arreglo res podría contener valores que no son ni 0. ni max_float .
