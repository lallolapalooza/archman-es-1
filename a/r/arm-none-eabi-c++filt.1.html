DESCRIPCIÓ

N

Los lenguajes C++ y Java proporcionan la sobrecarga de funciones, lo que significa que puede escribir muchas funciones con el mismo nombre, siempre que cada función tome parámetros de tipos diferentes. Para poder distinguir estas funciones de nombres similares, C++ y Java las codifican en un nombre de ensamblador de bajo nivel que identifica de forma única cada versión diferente. Este proceso se conoce como enmascaramiento. El programa c++filt [1] realiza la asignación inversa: decodifica (desenmascara) los nombres de bajo nivel en nombres de nivel de usuario para que puedan ser

leídos.

Cada palabra alfanumérica (consistente en letras, dígitos, guiones bajos, dólares o puntos) vista en la entrada es un nombre enmascarado potencial. Si el nombre se decodifica en un nombre de C++, el nombre de C++ reemplaza el nombre de bajo nivel en la salida; de lo contrario, se emite la palabra original. De esta manera, puede pasar un archivo fuente de ensamblador completo, que contenga nombres enmascarados, a través de c++filt y ver el mismo archivo fuente con los nombres desenmascarados

.

También puede usar c++filt para descifrar símbolos individuales pasándolos en la línea de

comandos: 
c++filt
<symbol>

Si no se proporcionan argumentos symbol, c++filt lee los nombres de símbolos de la entrada estándar. Todos los resultados se imprimen en la salida estándar. La diferencia entre leer nombres de la línea de comandos y leerlos de la entrada estándar es que se espera que los argumentos de la línea de comandos sean solo nombres enmascarados y no se realiza ninguna comprobación para separarlos del texto circundante. Así que, por

ejemplo: 
c++filt -n
_Z1fv

funcionará y desenmascarará el nombre a "f()" mientras

que: 
c++filt -n
_Z1fv,

no funcionará. (Note la coma extra al final del nombre enmascarado que lo hace inválido). Sin embargo, este comando

funcionará: 
echo _Z1fv, | c++filt
-n

y mostrará "f(),", es decir, el nombre desenmascarado seguido de una coma final. Este comportamiento se debe a que cuando los nombres se leen de la entrada estándar, se espera que puedan ser parte de un archivo fuente de ensamblador donde puede haber caracteres extra, superfluos después de un nombre enmascarado. Por

ejemplo: 
.type
_Z1fv, @
function

--no-recursion-li

Habilita o deshabilita un límite en la cantidad de recursión realizada al desenmascarar cadenas. Dado que los formatos de enmascaramiento de nombres permiten un nivel infinito de recursión, es posible crear cuyas cadenas su decodificación agotará la cantidad de espacio de pila disponible en la máquina anfitriona, provocando una falla de memoria. El límite intenta evitar que esto suceda restringiendo la recursión a 2048 niveles de anidamiento.

El valor por defecto es que este límite esté habilitado, pero deshabilitarlo puede ser necesario para desenmascarar nombres verdaderamente complicados. Sin embargo, tenga en cuenta que si el límite de recursión está deshabilitado, es posible que se agote la pila y cualquier informe de error sobre tal evento será

rechazado.
