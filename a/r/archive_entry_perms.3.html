DESCRIPCIÓN

Identificador de usuario, identificador de grupo y modo

Las funciones archive_entry_uid(), archive_entry_gid(), y archive_entry_perm() se pueden usar para extraer el identificador de usuario, el identificador de grupo y el permiso de la entrada dada. Las funciones correspondientes archive_entry_set_uid(), archive_entry_set_gid(), y archive_entry_set_perm() almacenan el identificador de usuario, el identificador de grupo y el permiso proporcionados en la entrada. El permiso también se establece como efecto secundario de llamar a archive_entry_set_mode().

archive_entry_strmode() devuelve una representación en cadena del permiso tal como se utiliza en el modo largo de ls(1).

Nombre de usuario y grupo

Los nombres de usuario y grupo se pueden proporcionar de tres maneras diferentes:

char *
Cadenas multibyte en la configuración regional actual.
wchar_t *
Cadenas de caracteres anchos en la configuración regional actual. Las funciones accesor se llaman XXX_w().
UTF-8
Cadenas Unicode codificadas como UTF-8. Las funciones accesor que terminan en _utf8 devolverán estas cadenas, mientras que los modificadores que terminan en _utf8 las establecerán.

Las funciones archive_entry_set_gname() y archive_entry_set_uname() almacenan cadenas multibyte. Estas cadenas se copian en la entrada. Las funciones archive_entry_copy_gname() y archive_entry_copy_uname() también copian las cadenas de entrada.

Las funciones archive_entry_gname_w() y archive_entry_uname_w() devuelven cadenas de caracteres anchos. Las funciones archive_entry_copy_gname_w() y archive_entry_copy_uname_w() copian cadenas de caracteres anchos.

Las funciones archive_entry_update_gname_utf8() y archive_entry_update_uname_utf8() pueden usarse para almacenar cadenas multibyte o de caracteres anchos y, si es necesario, para convertirlas a UTF-8. Si el nombre de usuario o grupo de entrada no es UTF-8, esta función intentará realizar la conversión.

Las funciones archive_entry_copy_fflags_text() y archive_entry_copy_fflags_text_w() se utilizan para copiar el texto de las banderas de archivo de la entrada. El texto de la bandera se puede proporcionar en un formato multibyte o de caracteres anchos.

La función archive_entry_fflags_text() devuelve una cadena multibyte que representa las banderas de archivo de la entrada.

La función archive_entry_fflags() recupera las banderas de archivo como dos valores de bits sin signo largos sin signo. <set_bits> apunta a los bits que deben establecerse y <clear_bits> apunta a los bits que deben borrarse.

La función archive_entry_set_fflags() establece las banderas de archivo de la entrada.

DESCRIPTION

The functions described here provide access to the metadata associated with an archive_entry object. This metadata includes file permissions, file type, extended attributes (ACLs), and ownership information (UID, GID, user name, and group name).

Note that the archive_entry_copy_* functions take ownership of the memory pointed to by the argument and will copy it internally. The caller should not free this memory after calling the function. The archive_entry_set_* functions only copy the pointer and do not take ownership. The caller must ensure that the pointed-to memory remains valid for the lifetime of the archive_entry object.

Permissions and File Types

archive_entry_set_perm() sets the file permission bits for the entry. The archive_entry_perm() function returns the permission bits.

archive_entry_set_file_type() sets the file type for the entry. Valid types are defined in archive.h and include AE_IFREG (regular file), AE_IFDIR (directory), AE_IFLNK (symbolic link), etc. archive_entry_file_type() returns the file type.

The functions archive_entry_copy_uname() and archive_entry_copy_gname() are convenience functions to update both the multibyte and wide character string representations of the username and group name, respectively. The strings are copied, and don't need to outlive the call.

archive_entry_set_uname() and archive_entry_set_gname() are aliases for archive_entry_copy_uname() and archive_entry_copy_gname() respectively. The strings are copied, and don't need to outlive the call.

The functions archive_entry_copy_uname_w() and archive_entry_copy_gname_w() are convenience functions to update both the multibyte and wide character string representations of the username and group name, respectively. The strings are copied, and don't need to outlive the call.

File Flags

File flags are transparently converted between a bitmap representation and a textual format. For example, if you set the bitmap and ask for text, the library will build a canonical text format. However, if you set a text format and request a text format, you will get back the same text, even if it is ill-formed. If you need to canonicalize a textual flags string, you should first set the text form, then request the bitmap form, then use that to set the bitmap form. Setting the bitmap format will clear the internal text representation and force it to be reconstructed when you next request the text form.

The bitmap format consists of two integers, one containing bits that should be set, the other specifying bits that should be cleared. Bits not mentioned in either bitmap will be ignored. Usually, the bitmap of bits to be cleared will be set to zero. In unusual circumstances, you can force a fully-specified set of file flags by setting the bitmap of flags to clear to the complement of the bitmap of flags to set. (This differs from fflagstostr(3), which only includes names for set bits.) Converting a bitmap to a textual string is a platform-specific operation; bits that are not meaningful on the current platform will be ignored.

The canonical text format is a comma-separated list of flag names. The archive_entry_copy_fflags_text() and archive_entry_copy_fflags_text_w() functions parse the provided text and set the internal bitmap values. This is a platform-specific operation; names that are not meaningful on the current platform will be ignored. The function returns a pointer to the start of the first name that was not recognized, or NULL if every name was recognized. Note that every name — including names that follow an unrecognized name — will be evaluated, and the bitmaps will be set to reflect every name that is recognized. (In particular, this differs from strtofflags(3), which stops parsing at the first unrecognized name.)

The functions archive_entry_fflags_text() and archive_entry_fflags_text_w() return the textual representation of the file flags. The return value is a pointer to a null-terminated string. This string is owned by the archive_entry object and should not be freed by the caller. The returned string is only valid as long as the archive_entry object is valid. These functions are convenient aliases for archive_entry_copy_fflags_text() and archive_entry_copy_fflags_text_w().

ACLs

archive_entry_acl() returns a pointer to the ACL data associated with the entry, or NULL if no ACL data is present. The format of the ACL data is architecture-dependent. It is recommended to use the archive_entry_acl(3) functions which provide a platform-independent way to access ACL information.

archive_entry_set_acl() sets the ACL data for the entry. The acl argument is a pointer to the ACL data. The archive_entry object takes ownership of this memory and will free it when the object is destroyed.

archive_entry_copy_acl() copies the provided ACL data into the archive_entry object. The object takes ownership of the copied memory and will free it when destroyed. The caller should not free the memory pointed to by acl after this call.

Ownership Information

archive_entry_set_uid() sets the user ID (UID) for the entry. archive_entry_uid() returns the UID.

archive_entry_set_gid() sets the group ID (GID) for the entry. archive_entry_gid() returns the GID.

archive_entry_set_uname() sets the username for the entry. archive_entry_uname() returns the username.

archive_entry_set_gname() sets the group name for the entry. archive_entry_gname() returns the group name.

The archive_entry_copy_uname() and archive_entry_copy_gname() functions are convenience functions to update both the multibyte and wide character string representations of the username and group name, respectively. The strings are copied, and don't need to outlive the call.

The functions archive_entry_set_uname() and archive_entry_set_gname() are aliases for archive_entry_copy_uname() and archive_entry_copy_gname() respectively. The strings are copied, and don't need to outlive the call.

The functions archive_entry_copy_uname_w() and archive_entry_copy_gname_w() are convenience functions to update both the multibyte and wide character string representations of the username and group name, respectively. The strings are copied, and don't need to outlive the call.

The functions archive_entry_set_XXX() are aliases for archive_entry_copy_XXX(). The strings are copied, and don't need to outlive the call.

BUGS

The platform types uid_t and gid_t are often 16 or 32 bit wide. In this case it is possible that the ids can not be correctly restored from archives and get truncated.
