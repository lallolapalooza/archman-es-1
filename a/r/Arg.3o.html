Módulo Arg
: sig end

Análisis de argumentos de la línea de comandos.

Este módulo proporciona un mecanismo general para extraer opciones y argumentos de la línea de comandos al programa. Por ejemplo:

     let usage_msg = "append [-verbose] <file1> [<file2>] ... -o <output>"
     let verbose = ref false
     let input_files = ref []
     let output_file = ref ""
     let anon_fun filename =
       input_files := filename::!input_files
     let speclist =
       [("-verbose", Arg.Set verbose, "Output debug information");
        ("-o", Arg.Set_string output_file, "Set output file name")]
     let () =
       Arg.parse speclist anon_fun usage_msg;
       (* Main functionality here *)

Sintaxis de las líneas de comandos: Una palabra clave es una cadena de caracteres que comienza con un - . Una opción es una palabra clave sola o seguida de un argumento. Los tipos de palabras clave son: Unit , Bool , Set , Clear , String , Set_string , Int , Set_int , Float , Set_float , Tuple , Symbol , Rest , Rest_all y Expand .

Unit , Set y Clear no toman ningún argumento.

Una palabra clave Rest o Rest_all toma el resto de la línea de comandos como argumentos. (Más explicaciones más abajo.)

Cualquier otra palabra clave toma la siguiente palabra de la línea de comandos como argumento. Para compatibilidad con GNU getopt_long, keyword=arg también está permitido. Los argumentos que no preceden a una palabra clave se llaman argumentos anónimos.

Ejemplos (se asume que cmd es el nombre del comando):

- cmd -flag (una opción unit)

- cmd -int 1 (una opción int con el argumento 1 )

- cmd -string foobar (una opción string con el argumento "foobar" )

- cmd -float 12.34 (una opción float con el argumento 12.34 )

- cmd a b c (tres argumentos anónimos: "a" , "b" y "c" )

- cmd a b -- c d (dos argumentos anónimos y una opción rest con dos argumentos)

Rest toma una función que se llama repetidamente para cada argumento restante de la línea de comandos. Rest_all toma una función que se llama una vez, con la lista de todos los argumentos restantes.

Ten en cuenta que si no siguen argumentos a una palabra clave Rest entonces la función no se llama en absoluto, mientras que la función para una palabra clave Rest_all se llama con una lista vacía.

Alerta de acceso no sincronizado. El módulo Arg depende de un estado global mutable, las funciones de análisis solo deben ser llamadas desde un único dominio.

type spec =
| Unit of (unit -> unit)
(* Call the function with unit argument
*)
| Bool of (bool -> unit)
(* Call the function with a bool argument
*)
| Set of bool ref
(* Set the reference to true
*)
| Clear of bool ref
(* Set the reference to false
*)
| String of (string -> unit)
(* Call the function with a string argument
*)
| Set_string of string ref
(* Set the reference to the string argument
*)
| Int of (int -> unit)
(* Call the function with an int argument
*)
| Set_int of int ref
(* Set the reference to the int argument
*)
| Float of (float -> unit)
(* Call the function with a float argument
*)
| Set_float of float ref
(* Set the reference to the float argument
*)
| Tuple of spec list
(* Take several arguments according to the spec list
*)
| Symbol of string list * (string -> unit)
(* Take one of the symbols as argument and call the function with the symbol
*)
| Rest of (string -> unit)
(* Stop interpreting keywords and call the function with each remaining argument
*)
| Rest_all of (string list -> unit)
(* Stop interpreting keywords and call the function with all remaining arguments
*)
| Expand of (string -> string array)
(* If the remaining arguments to process are of the form ["-foo"; "arg"] @ rest where "foo" is registered as Expand f , then the arguments f "arg" @ rest are processed. Only allowed in parse_and_expand_argv_dynamic .
*)

El tipo concreto que describe el comportamiento asociado con una palabra clave.

type key = string

type doc = string

type usage_msg = string

type anon_fun = string -> unit

val parse : (key * spec * doc) list -> anon_fun -> usage_msg -> unit

Arg.parse speclist anon_fun usage_msg analiza la línea de comandos. speclist es una lista de tríos (key, spec, doc) . key es la palabra clave de la opción, debe comenzar con el carácter '-' . spec da el tipo de la opción y la función a llamar cuando se encuentra esta opción en la línea de comandos. doc es una descripción de una línea de esta opción. anon_fun se llama con los argumentos anónimos. Las funciones en spec y anon_fun se llaman en el mismo orden en el que sus argumentos aparecen en la línea de comandos.

Si ocurre un error, Arg.parse sale del programa, después de imprimir en el error estándar un mensaje de error como sigue:

- La razón del error: opción desconocida, argumento inválido o ausente, etc.

- usage_msg

- La lista de opciones, cada una seguida de la cadena doc correspondiente. Cuidado: las opciones que tienen una cadena doc vacía no se incluirán en la lista.

Para que el usuario pueda especificar argumentos anónimos que comiencen con - , incluye por ejemplo ("-", String anon_fun, doc) en speclist .

Por defecto, parse reconoce dos opciones unit, -help y --help , que imprimirán en la salida estándar usage_msg y la lista de opciones, y saldrán del programa. Puedes anular este comportamiento especificando tus propias opciones -help y --help en speclist .

val parse_dynamic : (key * spec * doc) list ref -> anon_fun -> usage_msg -> unit

Igual que Arg.parse , excepto que el argumento speclist es una referencia y puede ser actualizada durante el análisis. Un uso típico para esta característica es analizar líneas de comandos de la forma:

- command subcommand options donde la lista de opciones depende del valor del argumento subcommand.

Desde 4.01

val parse_argv : ?current:int ref -> string array -> (key * spec * doc) list -> anon_fun -> usage_msg -> unit

Arg.parse_argv ~current args speclist anon_fun usage_msg analiza el array args como si fuera la línea de comandos. Usa y actualiza el valor de ~current (si se proporciona), o Arg.current . Debes establecerlo antes de llamar a parse_argv . El valor inicial de current es el índice del nombre del programa (argumento 0) en el array. Si ocurre un error, Arg.parse_argv lanza Arg.Bad con el mensaje de error como argumento. Si se proporciona la opción -help o --help , Arg.parse_argv lanza Arg.Help con el mensaje de ayuda como argumento.

val parse_argv_dynamic : ?current:int ref -> string array -> (key * spec * doc) list ref -> anon_fun -> string -> unit

Igual que Arg.parse_argv , excepto que el argumento speclist es una referencia y puede ser actualizada durante el análisis. Ver Arg.parse_dynamic .

Desde 4.05

exception Help of string

Lanzada por Arg.parse_argv cuando el usuario solicita ayuda.

exception Bad of string

Las funciones en spec o anon_fun pueden lanzar Arg.Bad con un mensaje de error para rechazar argumentos no válidos. Arg.Bad también es lanzada por Arg.parse_argv en caso de un error.

val usage : (key * spec * doc) list -> usage_msg -> unit

Arg.usage speclist usage_msg imprime en el error estándar un mensaje de error que incluye la lista de opciones válidas. Este es el mismo mensaje que Arg.parse imprime en caso de error. speclist y usage_msg son los mismos que para Arg.parse .

val usage_string : (key * spec * doc) list -> usage_msg -> string

Devuelve el mensaje que habría sido impreso por Arg.usage , si se le proporcionan los mismos parámetros.

val align : ?limit:int -> (key * spec * doc) list -> (key * spec * doc) list

Alinea las cadenas de documentación insertando espacios en el primer separador de alineación (tabulador o, si no se encuentra tabulador, espacio), de acuerdo con la longitud de la palabra clave. Usa un separador de alineación como primer carácter en una cadena de documentación si deseas alinear la cadena completa. Las cadenas de documentación correspondientes a los argumentos Symbol se alinean en la siguiente línea.

val current : int ref

Posición (en Sys.argv ) del argumento que se está procesando. Puedes cambiar este valor, por ejemplo, para forzar a Arg.parse a omitir algunos argumentos. Arg.parse usa el valor inicial de Arg.current como el índice del argumento 0 (el nombre del programa) y comienza a analizar los argumentos en el siguiente elemento.

val read_arg : string -> string array

Arg.read_arg file lee argumentos de la línea de comandos terminados por salto de línea del archivo file .

Desde 4.05

val read_arg0 : string -> string array

Idéntico a Arg.read_arg pero asume argumentos de la línea de comandos terminados por carácter nulo.

Desde 4.05

val write_arg : string -> string array -> unit

Arg.write_arg file args escribe los argumentos args terminados por salto de línea en el archivo file . Si alguno de los argumentos en args contiene un salto de línea, usa Arg.write_arg0 en su lugar.

Desde 4.05

val write_arg0 : string -> string array -> unit

Idéntico a Arg.write_arg pero usa el carácter nulo como terminador en lugar del salto de línea.
