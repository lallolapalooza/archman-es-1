archive_write_set_options(3)

Paquete: libarchive

Licencias: BSD-2-Clause

ARCHIVE_WRITE_OPTIONS(3) Manual de funciones de biblioteca ARCHIVE_WRITE_OPTIONS(3)

NOMBRE

archive_write_set_filter_option, archive_write_set_format_option, archive_write_set_option, archive_write_set_options — funciones que controlan las opciones para escribir archivos

BIBLIOTECA

Biblioteca de Archivo en Streaming (libarchive, -larchive)

SINOPSIS

int
archive_write_set_filter_option(struct archive *, const char *módulo, const char *opción, const char *valor);

int
archive_write_set_format_option(struct archive *, const char *módulo, const char *opción, const char *valor);

int
archive_write_set_option(struct archive *, const char *módulo, const char *opción, const char *valor);

int
archive_write_set_options(struct archive *, const char *opciones);

DESCRIPCIÓN

Estas funciones proporcionan una forma para que los clientes de libarchive configuren módulos de escritura específicos.

archive_write_set_filter_option(), archive_write_set_format_option()
Especifica una opción que se pasará a los filtros (incluidos los filtros de descompresión) o lectores de formato actualmente registrados.

Si opción y valor son ambos NULL, estas funciones no harán nada y se devolverá ARCHIVE_OK. Si opción es NULL pero valor no lo es, estas funciones no harán nada y se devolverá ARCHIVE_FAILED.

Si módulo no es NULL, opción y valor se proporcionarán al filtro o lector llamado módulo. El valor de retorno será ARCHIVE_OK si la opción se manejó correctamente o ARCHIVE_WARN si la opción no fue reconocida por el módulo o no se pudo manejar de otra manera. Si no existe dicho módulo, se devolverá ARCHIVE_FAILED.

Si módulo es NULL, opción y valor se proporcionarán a cada módulo registrado. Si algún módulo devuelve ARCHIVE_FATAL, este valor se devolverá inmediatamente. De lo contrario, se devolverá ARCHIVE_OK si algún módulo acepta la opción, y ARCHIVE_FAILED en todos los demás casos.

archive_write_set_option()
Llama a archive_write_set_format_option(), luego a archive_write_set_filter_option(). Si alguna de las funciones devuelve ARCHIVE_FATAL, se devolverá ARCHIVE_FATAL inmediatamente. De lo contrario, se devolverá el mayor de los dos valores.
archive_write_set_options()
opciones es una lista separada por comas de opciones. Si opciones es NULL o está vacío, se devolverá ARCHIVE_OK inmediatamente.

Las opciones individuales tienen una de las siguientes formas:

opción=valor
El par opción/valor se proporcionará a cada módulo. Los módulos que no acepten una opción con este nombre la ignorarán.
opción
La opción se proporcionará a cada módulo con un valor de “1”.
!opción
La opción se proporcionará a cada módulo con un valor NULL.
módulo:opción=valor, módulo:opción, módulo:!opción
Como arriba, pero la opción y el valor correspondientes se proporcionarán solo a los módulos cuyo nombre coincida con módulo.

OPCIONES

Filtro b64encode
modo
El valor se interpreta como dígitos octales que especifican el modo de archivo.
nombre
El valor especifica el nombre del archivo.
Filtro bzip2
nivel-de-compresión
El valor se interpreta como un entero decimal que especifica el nivel de compresión bzip2. Los valores admitidos son del 1 al 9.
Filtro gzip
nivel-de-compresión
El valor se interpreta como un entero decimal que especifica el nivel de compresión gzip. Los valores admitidos son del 0 al 9.
marca-de-tiempo
Almacenar marca de tiempo. Esto está habilitado por defecto.
Filtro lrzip
compresión=tipo
Usa tipo como método de compresión. Los valores admitidos son “bzip2”, “gzipi”, “lzo” (ultrarrápido) y “zpaq” (el mejor, extremadamente lento).
nivel-de-compresión
El valor se interpreta como un entero decimal que especifica el nivel de compresión lrzip. Los valores admitidos son del 1 al 9.
Filtro lz4
nivel-de-compresión
El valor se interpreta como un entero decimal que especifica el nivel de compresión lz4. Los valores admitidos son del 0 al 9.
suma-de-verificación-de-flujo
Habilitar suma de verificación de flujo. Esto está habilitado por defecto.
suma-de-verificación-de-bloque
Habilitar suma de verificación de bloque. Esto está deshabilitado por defecto.
tamaño-de-bloque
El valor se interpreta como un entero decimal que especifica el tamaño del bloque de compresión lz4. Los valores admitidos son del 4 al 7 (por defecto).
dependencia-de-bloque
Utilizar el bloque anterior del bloque que se está comprimiendo como diccionario de compresión para mejorar la relación de compresión. Esto está deshabilitado por defecto.
Filtro lzop
nivel-de-compresión
El valor se interpreta como un entero decimal que especifica el nivel de compresión lzop. Los valores admitidos son del 1 al 9.
Filtro uuencode
mode
El valor se interpreta como dígitos octales que especifican el modo del archivo.
name
El valor especifica el nombre del archivo.
Filtro xz
compression-level
El valor se interpreta como un entero decimal que especifica el nivel de compresión. Los valores admitidos van del 0 al 9.
threads
El valor se interpreta como un entero decimal que especifica el número de hilos para la compresión lzma multihilo. Si se admite, el valor predeterminado se lee desde lzma_cputhreads().
Filtro zstd
compression-level
El valor se interpreta como un entero decimal que especifica el nivel de compresión. Los valores admitidos dependen de la versión de la biblioteca; los valores comunes van del 1 al 22.
long
Habilita la coincidencia a larga distancia. El valor se interpreta como un entero decimal que especifica el tamaño de la ventana log2 en bytes. Se admiten valores de 10 a 30 para 32 bits, o 31 para 64 bits.
threads
El valor se interpreta como un entero decimal que especifica el número de hilos para la compresión zstd multihilo. Si se establece en 0, zstd intentará detectar y usar el número de núcleos físicos de CPU activos.
Formato 7zip
compression
El valor es uno de “store”, “copy”, “deflate”, “bzip2”, “lzma1”, “lzma2”, “ppmd” o “zstd” para indicar cómo deben comprimirse las entradas siguientes. Los valores “store” y “copy” son sinónimos. Tenga en cuenta que esta configuración se ignora para directorios, enlaces simbólicos y otras entradas especiales.
compression-level
El valor se interpreta como un entero decimal que especifica el nivel de compresión. Se admiten valores entre 0 y 9, con la excepción de bzip2, que solo admite valores entre 1 y 9, y zstd, que puede admitir valores negativos dependiendo de la versión de la biblioteca y valores comunes utilizados del 1 al 22. La interpretación del nivel de compresión depende del método de compresión elegido.
threads
El valor se interpreta como un entero decimal que especifica el número de hilos para la compresión multihilo (para compresores como zstd que lo admiten). Si se establece en 0, se intentará descubrir el número de núcleos de CPU.
Formato bin
hdrcharset
El valor se usa como nombre de juego de caracteres que se utilizará al traducir nombres de archivos.
Formato gnutar
hdrcharset
El valor se usa como nombre de juego de caracteres que se utilizará al traducir nombres de archivos, grupos y usuarios.
Formato iso9660 - metadatos del volumen
Estas opciones se usan para establecer metadatos ISO9660 estándar.
abstract-file=filename
El archivo con el nombre especificado se identificará en los metadatos ISO9660 como el que contiene el resumen de este volumen. Predeterminado: ninguno.
application-id=filename
El archivo con el nombre especificado se identificará en los metadatos ISO9660 como el que contiene el identificador de aplicación de este volumen. Predeterminado: ninguno.
biblio-file=filename
El archivo con el nombre especificado se identificará en los metadatos ISO9660 como el que contiene la bibliografía de este volumen. Predeterminado: ninguno.
copyright-file=filename
El archivo con el nombre especificado se identificará en los metadatos ISO9660 como el que contiene el copyright de este volumen. Predeterminado: ninguno.
publisher=filename
El archivo con el nombre especificado se identificará en los metadatos ISO9660 como el que contiene la información del editor de este volumen. Predeterminado: ninguno.
volume-id=string
La cadena especificada se usará como identificador de volumen en los metadatos ISO9660. Está limitada a 32 bytes. Predeterminado: ninguno.
Formato iso9660 - soporte de arranque
Estas opciones se usan para crear una imagen ISO9660 que pueda arrancarse directamente en varios sistemas.
boot=filename
El archivo que coincida con este nombre se usará como archivo de imagen de arranque El Torito.
boot-catalog=name
El nombre que se usará para el catálogo de arranque El Torito. Predeterminado: boot.catalog
boot-info-table
El archivo de imagen de arranque proporcionado por la opción boot=filename se editará con la información de arranque apropiada en los bytes 8 a 64. Predeterminado: deshabilitado
boot-load-seg=hexadecimal-number
El segmento de carga para una imagen de arranque sin emulación.
boot-load-size=decimal-number
El número de sectores "virtuales" de 512 bytes que se cargarán desde una imagen de arranque sin emulación. Algunos BIOS muy antiguos solo pueden cargar imágenes muy pequeñas; establecer este valor en 4 permitirá a menudo que tales BIOS carguen la primera parte de la imagen de arranque (que luego deberá ser lo suficientemente inteligente como para cargar el resto de sí misma). Esto no debería ser necesario a menos que esté intentando soportar sistemas con BIOS muy antiguos. El valor predeterminado es el tamaño completo de la imagen.
boot-type=value
Especifica la semántica de arranque utilizada por la imagen de arranque El Torito: Si el value es fd, se asume que la imagen de arranque es una imagen de disquete arrancable. Si el value es hd, se asume que la imagen de arranque es una imagen de disco duro arrancable. Si el value es no-emulation, la imagen de arranque se usa sin emulación de disquete o disco duro. Si la imagen de arranque es exactamente de 1.2MB, 1.44MB o 2.88MB, el valor predeterminado es fd, de lo contrario, el valor predeterminado es no-emulation.
Formato iso9660 - extensiones de nombre de archivo y tamaño
Varias extensiones al formato base ISO9660.
allow-ldots
Si está habilitado, permite que los nombres de archivo comiencen con un punto inicial. Si está deshabilitado, los nombres de archivo que comiencen con un punto inicial tendrán ese punto reemplazado por un carácter de guion bajo en el espacio de nombres ISO9660 estándar. Esto no afecta a los nombres almacenados en el área de extensión Rockridge o Joliet. Predeterminado: deshabilitado.
allow-lowercase
Si está habilitado, permite que los nombres de archivo contengan caracteres en minúsculas. Si está deshabilitado, los nombres de archivo se forzarán a mayúsculas. Esto no afecta a los nombres almacenados en el área de extensión Rockridge o Joliet. Predeterminado: deshabilitado.
allow-multidot
Si está habilitado, permite que los nombres de archivo contengan múltiples caracteres de punto, en violación de la especificación ISO9660. Si está deshabilitado, los puntos adicionales se convertirán en caracteres de guion bajo. Esto no afecta a los nombres almacenados en el área de extensión Rockridge o Joliet. Predeterminado: deshabilitado.
allow-period
Si está habilitado, permite que los nombres de archivo contengan caracteres de punto finales, en violación de la especificación ISO9660. Si está deshabilitado, los puntos finales se convertirán en caracteres de guion bajo. Esto no afecta a los nombres almacenados en el área de extensión Rockridge o Joliet. Predeterminado: deshabilitado.
allow-pvd-lowercase
Si está habilitado, el Descriptor de Volumen Primario puede contener caracteres ASCII en minúsculas, en violación de la especificación ISO9660. Si está deshabilitado, los caracteres se convertirán a ASCII en mayúsculas. Predeterminado: deshabilitado.
allow-sharp-tilde
Si está habilitado, se permitirán caracteres de almohadilla y virgulilla en los nombres de archivo, en violación de la especificación ISO9660. Si está deshabilitado, dichos caracteres se convertirán en caracteres de guion bajo. Predeterminado: deshabilitado.
allow-vernum
Si está habilitado, se incluirán números de versión con los archivos. Si está deshabilitado, los números de versión se suprimirán, en violación del estándar ISO9660. Esto no afecta a los nombres almacenados en el área de extensión Rockridge o Joliet. Predeterminado: habilitado.
iso-level
Esto habilita el soporte para extensiones de tamaño de archivo y nombre de archivo en el área central ISO9660. Las extensiones de nombre especificadas aquí no afectan a los nombres almacenados en las áreas de extensión Rockridge o Joliet.
iso-level=1
La forma más conforme de imagen ISO9660. Los nombres de archivo se limitan al formato 8.3 en mayúsculas, los nombres de directorio se limitan a 8 caracteres en mayúsculas, los archivos se limitan a 4 GiB, la imagen ISO9660 completa no puede exceder 4 GiB.
iso-level=2
Los nombres de archivo se limitan a 30 caracteres en mayúsculas con una extensión de 30 caracteres, los nombres de directorio se limitan a 30 caracteres, los archivos se limitan a 4 GiB.
iso-level=3
Igual que iso-level=2, excepto que los archivos pueden exceder 4 GiB.
iso-level=4
Igual que iso-level=3, excepto que los nombres de archivo pueden tener hasta 193 caracteres e incluir caracteres arbitrarios de 8 bits.
joliet
Las extensiones Joliet de Microsoft almacenan un conjunto completamente separado de información de directorio sobre cada archivo. En particular, esta información incluye nombres de archivo Unicode de hasta 255 caracteres. Predeterminado: habilitado.
limit-depth
Si está habilitado, libarchive usará registros de reubicación de directorios para asegurar que ninguna ruta de acceso exceda el límite de ISO9660 de 8 niveles de directorio. Si está deshabilitado, no se producirá ninguna reubicación. Predeterminado: habilitado.
limit-dirs
Si está habilitado, libarchive generará un error si hay más de 65536 directorios. Si está deshabilitado, no hay límite en el número de directorios. Predeterminado: habilitado
pad
Si está habilitado, se añadirán 300 kiB de bytes cero al final del archivo. Predeterminado: habilitado
relaxed-filenames
Si está habilitado, se permiten todos los caracteres ASCII de 7 bits en los nombres de archivo (excepto los caracteres en minúsculas, a menos que allow-lowercase también se especifique). Esto viola los estándares ISO9660. Esto no afecta a los nombres almacenados en el área de extensión Rockridge o Joliet. Predeterminado: deshabilitado.
rockridge
Las extensiones Rockridge almacenan un conjunto adicional de información de archivo estilo POSIX con cada archivo, incluyendo mtime, atime, ctime, permisos y nombres de archivo largos con caracteres arbitrarios de 8 bits. Estas extensiones también admiten enlaces simbólicos y otros tipos de archivos POSIX. Predeterminado: habilitado.
Formato iso9660 - soporte de zisofs
Las extensiones zisofs permiten que cada archivo se comprima de forma independiente usando una compresión compatible con gzip. Esto puede proporcionar un ahorro de tamaño significativo, pero requiere que el sistema de lectura tenga soporte para estas extensiones. Estas extensiones están deshabilitadas de forma predeterminada.
compression-level=número
El nivel de compresión usado por el compresor deflate. Va desde 0 (menor esfuerzo) hasta 9 (mayor esfuerzo). Predeterminado: 6
zisofs
Sinónimo de zisofs=direct.
zisofs=direct
Comprime cada archivo en el archivo. A diferencia de zisofs=indirect, esto se maneja completamente dentro de libarchive y no requiere una utilidad separada. Para obtener mejores resultados, libarchive prueba cada archivo y almacenará el archivo sin comprimir si la compresión no ahorra realmente espacio. En particular, los archivos menores a 2k nunca se comprimirán. Tenga en cuenta que los archivos de imagen de arranque nunca se comprimen.
zisofs=indirect
Reconoce archivos que ya han sido comprimidos con la utilidad mkzftree y configura los metadatos de archivo necesarios para que los lectores identifiquen correctamente estos archivos como archivos comprimidos con zisofs.
zisofs-exclude=nombre-de-archivo
Especifica un nombre de archivo que no debe comprimirse al usar zisofs=direct. Esta opción se puede proporcionar varias veces para suprimir la compresión de muchos archivos.
Formato mtree
cksum, device, flags, gid, gname, indent, link, md5, mode, nlink, rmd160, sha1, sha256, sha384, sha512, size, time, uid, uname
Habilita una palabra clave particular en la salida de mtree. Anteponga un signo de exclamación para deshabilitar la palabra clave correspondiente. El valor predeterminado es equivalente a “device, flags, gid, gname, link, mode, nlink, size, time, type, uid, uname”.
all
Habilita todas las palabras clave anteriores.
use-set
Habilita la generación de líneas /set que especifican valores predeterminados para los siguientes archivos y/o directorios.
indent
XXX necesita explicación XXX
Formato newc
hdrcharset
El valor se usa como nombre de conjunto de caracteres que se usará al traducir nombres de archivo.
Formato odc
hdrcharset
El valor se usa como nombre de conjunto de caracteres que se usará al traducir nombres de archivo.
Formato pwb
hdrcharset
El valor se usa como nombre de conjunto de caracteres que se usará al traducir nombres de archivo.
Formato pax
hdrcharset
El valor se usa como nombre de conjunto de caracteres que se usará al traducir nombres de archivo, grupo y usuario. El valor es uno de “BINARY” o “UTF-8”. Con “BINARY” no hay conversión de caracteres, con “UTF-8” los nombres se convierten a UTF-8.
xattrheader
Al almacenar atributos extendidos, esta opción configura qué cabeceras deben escribirse. El valor es uno de “all”, “LIBARCHIVE” o “SCHILY”. De forma predeterminada, se escriben tanto las cabeceras “LIBARCHIVE.xattr” como “SCHILY.xattr”.
Formato ustar
hdrcharset
El valor se usa como nombre de conjunto de caracteres que se usará al traducir nombres de archivo, grupo y usuario.
Formato v7tar
hdrcharset
El valor se usa como nombre de conjunto de caracteres que se usará al traducir nombres de archivo, grupo y usuario.
Formato warc
omit-warcinfo
Establezca en “true” para deshabilitar la salida del registro warcinfo.
Formato xar
checksum=tipo
Use tipo como método de suma de comprobación de archivo. Los valores admitidos son “none”, “md5” y “sha1” (predeterminado).
compression=tipo
Use tipo como método de compresión. Los valores admitidos son “none”, “bzip2”, “gzip” (predeterminado), “lzma” y “xz”.
compression_level
El valor es un entero decimal del 1 al 9 que especifica el nivel de compresión.
toc-checksum=tipo
Use tipo como método de comprobación de la tabla de contenidos. Los valores admitidos son “none”, “md5” y “sha1” (predeterminado).
Formato zip
compresión
El valor es “store”, “deflate”, “bzip2”, “lzma”, “xz” o “zstd” para indicar cómo deben comprimirse las entradas siguientes. Tenga en cuenta que esta configuración se ignora para directorios, enlaces simbólicos y otras entradas especiales.
compression-level
El valor se interpreta como un entero decimal que especifica el nivel de compresión. Se admiten valores entre 0 y 9. Un nivel de compresión de 0 cambia el método de compresión a “store”, otros valores habilitarán la compresión “deflate”, “bzip2”, “lzma” o “zstd” (en orden de prioridad, dependiendo de las bibliotecas enlazadas) con el nivel indicado.
threads
El valor se interpreta como un entero decimal que especifica el número de hilos a usar para la compresión. Solo se admite para la compresión “xz” o “zstd” y se ignora para cualquier otra. Un valor de hilos de 0 es un valor especial que solicita detectar y usar tantos hilos como núcleos físicos de CPU activos.
encryption
Habilita el cifrado usando el cifrado tradicional de zip.
encryption=type
Usa type como tipo de cifrado. Los valores admitidos son “zipcrypt” (cifrado tradicional de zip), “aes128” (cifrado WinZip AES-128) y “aes256” (cifrado WinZip AES-256).
experimental
Esta opción booleana habilita o deshabilita características experimentales de Zip que pueden no ser compatibles con otras implementaciones de Zip.
fakecrc32
Esta opción booleana deshabilita los cálculos de CRC. Todos los campos CRC se establecen en cero. No debe usarse salvo con fines de prueba.
hdrcharset
El valor se usa como nombre de juego de caracteres que se utilizará al traducir nombres de archivo.
zip64
Las extensiones Zip64 proporcionan información adicional de tamaño de archivo para entradas mayores de 4 GiB. También proporcionan información extendida de desplazamiento de archivo y tamaño del archivo cuando los archivos superan los 4 GiB. De forma predeterminada, el escritor de Zip habilita estas extensiones selectivamente solo según sea necesario. En particular, si el tamaño del archivo es desconocido, el escritor de Zip incluirá extensiones Zip64 para protegerse contra la posibilidad de que el archivo sea mayor de 4 GiB.

Establecer esta opción booleana forzará al escritor a usar extensiones Zip64 incluso para archivos pequeños que de otro modo no las requerirían. Esto es principalmente útil para pruebas.

Deshabilitar esta opción con !zip64 forzará al escritor de Zip a evitar las extensiones Zip64: Rechazará archivos con un tamaño mayor de 4 GiB, rechazará cualquier nueva entrada una vez que el tamaño total del archivo alcance los 4 GiB, y no usará extensiones Zip64 para archivos de tamaño desconocido. En particular, esto puede mejorar la compatibilidad al generar archivos donde los tamaños de las entradas no se conocen de antemano.

EJEMPLOS

El siguiente ejemplo crea un identificador de escritura de archivo para crear una imagen en formato ISO9660 comprimida con gzip. Las dos opciones aquí especifican que el archivo ISO9660 usará kernel.img como imagen de arranque para el arranque El Torito, y que el compresor gzip debe usar el nivel de compresión máximo.

a = archive_write_new();
archive_write_add_filter_gzip(a);
archive_write_set_format_iso9660(a);
archive_write_set_options(a, "boot=kernel.img,compression=9");
archive_write_open_filename(a, filename, blocksize);
