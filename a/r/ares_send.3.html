ares_send(3)

Paquete: c-ares

Licencias: MIT

ARES_SEND(3) Manual de funciones de biblioteca ARES_SEND(3)

NOMBRE

ares_send - Iniciar una consulta DNS

SINOPSIS

#include <ares.h>
typedef void (*ares_callback_dnsrec)(void *arg, ares_status_t status,
                                     size_t timeouts,
                                     const ares_dns_record_t *dnsrec);
ares_status_t ares_send_dnsrec(ares_channel_t *channel,
                               const ares_dns_record_t *dnsrec,
                               ares_callback_dnsrec callback,
                               void *arg, unsigned short *qid);
typedef void (*ares_callback)(void *arg, int status,
                              int timeouts, unsigned char *abuf,
                              int alen);
void ares_send(ares_channel_t *channel, const unsigned char *qbuf,
               int qlen, ares_callback callback, void *arg);

DESCRIPCIÓN

La función ares_send_dnsrec(3) inicia una consulta DNS formateada utilizando la estructura de datos ares_dns_record_t * creada a través de ares_dns_record_create(3) en el parámetro dnsrec. La función de devolución de llamada proporcionada en el parámetro callback también devuelve la respuesta utilizando una estructura de datos ares_dns_record_t *.

La función ares_send(3) inicia de manera similar una consulta DNS, pero en su lugar utiliza búferes binarios crudos con mensajes DNS completamente formateados pasados en la solicitud a través de los parámetros qbuf y qlen. La función de devolución de llamada proporcionada en el parámetro callback también devuelve la respuesta DNS binaria cruda en los parámetros abuf y alen. Este método debe considerarse obsoleto en favor de ares_send_dnsrec(3).

Ambas funciones toman un canal de ares inicializado identificado por channel.

La función ares_send_dnsrec(3) también puede recibir un parámetro de salida opcional de qid para poblar el ID de la consulta tal como se colocó en el cable.

La función ares_send_dnsrec(3) devuelve un código de respuesta ares_status_t. Esto puede ser útil para saber que la consulta se encoló correctamente. El código de respuesta no refleja el resultado de la consulta, solo el resultado de la puesta en cola de la consulta.

La finalización o el fallo de la consulta pueden ocurrir inmediatamente (incluso antes de que la función devuelva el control), o pueden ocurrir más tarde a medida que se procesan los eventos de red.

Cuando se llama a la función de devolución de llamada asociada, se llama con un bloqueo de canal, por lo que se debe tener cuidado para garantizar que cualquier procesamiento sea mínimo para evitar bloqueos en el canal DNS.

La función de devolución de llamada puede activarse desde un hilo diferente al que llamó a ares_send_dnsrec(3) o ares_send(3).

Para los integradores que ejecutan sus propios bucles de eventos y no utilizan ARES_OPT_EVENT_THREAD, se debe tener cuidado para garantizar que las listas de descriptores de archivo se actualicen inmediatamente dentro del bucle de eventos cuando se notifiquen.

El argumento de devolución de llamada arg se copia del parámetro arg de ares_send_dnsrec(3) o ares_send(3).

El argumento de devolución de llamada status indica si la consulta tuvo éxito y, si no, cómo falló. Puede tener cualquiera de los siguientes valores:

ARES_SUCCESS
La consulta se completó.
ARES_EBADQUERY
El búfer de consulta estaba mal formado (no era lo suficientemente largo para una cabecera DNS o era demasiado largo para la transmisión TCP).
ARES_ETIMEOUT
Ningún servidor de nombres respondió dentro del período de tiempo de espera.
ARES_ECONNREFUSED
No se pudo contactar a ningún servidor de nombres.
ARES_ENOMEM
Se agotó la memoria.
ARES_ECANCELLED
La consulta fue cancelada.
ARES_EDESTRUCTION
El canal de servicio de nombres channel se está destruyendo; la consulta no se completará.
ARES_ENOSERVER
La consulta no se completará porque no se configuraron servidores DNS en el canal.
ARES_EBADQUERY
Consulta DNS mal formateada.

El argumento de devolución de llamada timeouts informa cuántas veces una consulta expiró durante la ejecución de la solicitud dada.

Si la consulta se completó, el argumento de devolución de llamada dnsrec para ares_send_dnsrec(3) o abuf y alen para ares_send(3) no será NULL.

A menos que se estableciera la bandera ARES_FLAG_NOCHECKRESP en el momento de la inicialización del canal, ares_send_dnsrec(3) y ares_send(3) normalmente ignorarán las respuestas cuyas preguntas no coincidan con las preguntas proporcionadas, así como las respuestas con códigos de respuesta SERVFAIL, NOTIMP y REFUSED. Sin embargo, a diferencia de otras funciones de consulta en la biblioteca ares, ares_send_dnsrec(3) y ares_send(3) no inspeccionan la cabecera del paquete de respuesta para determinar el estado del error, por lo que un estado de devolución de llamada de ARES_SUCCESS no refleja tanto sobre la respuesta como para otras funciones de consulta.

DISPONIBILIDAD

ares_send_dnsrec(3) se introdujo en c-ares 1.28.0.

VER TAMBIÉN
