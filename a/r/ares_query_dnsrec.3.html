ares_query_dnsrec(3)

Paquete: c-ares

Licencias: MIT

ARES_QUERY(3) Manual de Funciones de Biblioteca ARES_QUERY(3)

NOMBRE

ares_query - Iniciar una consulta DNS de pregunta única

SINOPSIS

#include <ares.h>
typedef void (*ares_callback_dnsrec)(void *arg, ares_status_t status,
                                     size_t timeouts,
                                     const ares_dns_record_t *dnsrec);
ares_status_t ares_query_dnsrec(ares_channel_t      *channel,
                                const char          *name,
                                ares_dns_class_t     dnsclass,
                                ares_dns_rec_type_t  type,
                                ares_callback_dnsrec callback,
                                void                *arg,
                                unsigned short      *qid);
typedef void (*ares_callback)(void *arg, int status,
                              int timeouts, unsigned char *abuf,
                              int alen);
void ares_query(ares_channel_t *channel, const char *name,
                int dnsclass, int type,
                ares_callback callback, void *arg);

DESCRIPCIÓN

Las funciones ares_query_dnsrec(3) y ares_query(3) inician una consulta DNS de pregunta única en el canal de servicio de nombres identificado por channel. El parámetro name proporciona el nombre de la consulta como una cadena C terminada en NUL de etiquetas separadas por puntos, que opcionalmente termina con un punto; los puntos y las barras invertidas dentro de una etiqueta deben escaparse con una barra invertida.

ares_query_dnsrec(3) utiliza los tipos de datos ares_dns_class_t y ares_dns_rec_type_t de ares. Sin embargo, ares_query(3) utiliza los valores definidos en <arpa/nameser.h>.

Cuando la consulta se complete o haya fallado, la biblioteca ares invocará callback. La finalización o el fallo de la consulta pueden ocurrir inmediatamente (incluso antes de que la llamada a la función retorne), o pueden ocurrir durante una llamada posterior a ares_process(3) o ares_destroy(3).

Si esto se llama desde un hilo que no es el que ejecuta el bucle de eventos principal del programa, se debe tener cuidado de asegurar que las listas de descriptores de archivo se actualicen inmediatamente dentro del bucle de eventos. Cuando se llama a la función de devolución de llamada asociada, se llama con un bloqueo de canal, por lo que se debe tener cuidado de asegurar que cualquier procesamiento sea mínimo para evitar bloqueos en el canal DNS.

El argumento de devolución de llamada arg se copia del argumento arg de ares_query_dnsrec(3) o ares_query(3). El argumento de devolución de llamada status indica si la consulta tuvo éxito y, si no, cómo falló. Puede tener cualquiera de los siguientes valores:

ARES_SUCCESS
La consulta se completó con éxito.
ARES_ENODATA
La consulta se completó pero no contiene respuestas.
ARES_EFORMERR
La consulta se completó pero el servidor afirma que la consulta estaba mal formada.
ARES_ESERVFAIL
La consulta se completó pero el servidor afirma haber experimentado un fallo. (Este código solo puede ocurrir si se especificó el flag ARES_FLAG_NOCHECKRESP en el momento de la inicialización del canal; de lo contrario, tales respuestas se ignoran en el nivel de ares_send_dnsrec(3).)
ARES_ENOTFOUND
La consulta se completó pero no se encontró el nombre de dominio consultado.
ARES_ENOTIMP
La consulta se completó pero el servidor no implementa la operación solicitada por la consulta. (Este código solo puede ocurrir si se especificó el flag ARES_FLAG_NOCHECKRESP en el momento de la inicialización del canal; de lo contrario, tales respuestas se ignoran en el nivel de ares_send_dnsrec(3).)
ARES_EREFUSED
La consulta se completó pero el servidor rechazó la consulta. (Este código solo puede ocurrir si se especificó el flag ARES_FLAG_NOCHECKRESP en el momento de la inicialización del canal; de lo contrario, tales respuestas se ignoran en el nivel de ares_send_dnsrec(3).)
ARES_EBADNAME
El nombre de consulta name no se pudo codificar como un nombre de dominio, ya sea porque contenía una etiqueta de longitud cero o porque contenía una etiqueta de más de 63 caracteres.
ARES_ETIMEOUT
Ningún servidor de nombres respondió dentro del período de tiempo de espera.
ARES_ECONNREFUSED
No se pudo contactar ningún servidor de nombres.
ARES_ENOMEM
Se agotó la memoria.
ARES_ECANCELLED
La consulta fue cancelada.
ARES_EDESTRUCTION
El canal de servicio de nombres channel se está destruyendo; la consulta no se completará.
ARES_ENOSERVER
La consulta no se completará porque no se configuraron servidores DNS en el canal.

El argumento de devolución de llamada timeouts informa cuántas veces una consulta se agotó durante la ejecución de la solicitud dada.

Si la consulta se completó (incluso si hubo algún problema con ella, como se indica en algunos de los códigos de error anteriores), el argumento de devolución de llamada dnsrec o abuf no será NULL, de lo contrario serán NULL.

DISPONIBILIDAD

ares_query_dnsrec(3) se introdujo en c-ares 1.28.0.

VER TAMBIÉN
