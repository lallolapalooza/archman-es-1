DESCRIPCIÓN arptableses una herramienta de espacio de usuario, se utiliza para configurar y mantener las tablas de reglas ARP en el kernel de Linux. Estas reglas inspeccionan los tramas ARP que ven. arptables es análogo a la herramienta de espacio de

usuario

iptables [[116]], peroarptables es menos complicado. CADENAS La tabla del kernel se utiliza para dividir la funcionalidad en diferentes conjuntos de reglas. Cada conjunto de reglas se llama cadena. Cada cadena es una lista ordenada de reglas que pueden coincidir con tramas ARP. Si una regla coincide con un trama ARP, entonces una especificación de procesamiento indica qué hacer con ese trama coincidente. La especificación de procesamiento se llama 'destino'. Sin embargo, si el trama no coincide con la regla actual en la cadena, se examina la siguiente regla en la cadena, y así sucesivamente. El usuario puede crear nuevas cadenas (definidas por el usuario) que pueden usarse como el 'destino' de una regla. DESTINO

S

Una regla de firewall especifica criterios para un trama ARP y una especificación de procesamiento de tramas llamada destino. Cuando un trama coincide con una regla, la siguiente acción realizada por el kernel es especificada por el destino. El destino puede ser uno de estos

valores:

ACCEPT , DROP ,

CONTINUE , RETURN [[130]], una 'extensión' (ver más abajo) o una cadena definida por el usuario. ACC

E
PT

significa dejar pasar el

trama.

tramas.

Los argumentos del comando arptables especifican las acciones a realizar en la tabla definida con el argumento -t. Si no usa el argumento -t para nombrar una tabla, los comandos se aplican a la tabla filter predeterminada. Con la excepción del comando -Z [[158]], solo se puede usar un comando a la vez en la línea de comandos. -A, --append

Añade una regla al final de la cadena

seleccionada.

-D,

--delete

Elimina la regla especificada de la cadena seleccionada. Hay dos formas de usar este comando. La primera es especificando un intervalo de números de regla para eliminar, sintaxis: número_inicio[:número_fin]. Se permiten números negativos, para más detalles sobre el uso de números negativos, consulte el comando -I. El segundo uso es especificando la regla completa tal

como se habría especificado cuando se añadió.

-I, --insert Inserta la regla especificada en la cadena seleccionada en el número de regla especificado. Si el número actual de reglas es igual a N, entonces el número especificado puede estar entre -N y N+1. Para un número positivo i, se cumple que i e i-N-1 especifican el mismo lugar en la cadena donde se debe insertar la regla. El número 0 especifica el lugar después de la última regla en la cadena y usar este número es por lo tanto equivalente a usar el

ESPECIFICACIONES DE REGLAS

Los siguientes argumentos de la línea de comandos componen una especificación de regla (como se usa en los comandos de añadir y eliminar). Un operador "!" antes de la especificación invierte la prueba para esa especificación. Además de estas especificaciones de reglas estándar, hay otros argumentos de la línea de comandos de interés.

-s, --source-ip [!] address[/mask]
La especificación de la IP de origen.
-d, --destination-ip [!] address[/mask]
La especificación de la IP de destino.
--source-mac [!] address[/mask]
La dirección MAC de origen. Tanto la máscara como la dirección se escriben como 6 números hexadecimales separados por dos puntos.
--destination-mac [!] address[/mask]
La dirección MAC de destino. Tanto la máscara como la dirección se escriben como 6 números hexadecimales separados por dos puntos.
-i, --in-interface [!] name
La interfaz a través de la cual se recibe un trama (para la cadena INPUT ). La opción --in-if es un alias para esta opción.
-o, --out-interface [!] name
La interfaz a través de la cual se va a enviar un trama (para la cadena OUTPUT ). La opción --out-if es un alias para esta opción.
-l, --h-length length[/mask]
La longitud del hardware (número de bytes)
--opcode code[/mask]
El código de operación (2 bytes). Los valores disponibles son: 1=Request 2=Reply 3=Request_Reverse 4=Reply_Reverse 5=DRARP_Request 6=DRARP_Reply 7=DRARP_Error 8=InARP_Request 9=ARP_NAK.
--h-type type[/mask]
El tipo de hardware (2 bytes, hexadecimal). Los valores disponibles son: 1=Ethernet.
--proto-type type[/mask]
El tipo de protocolo (2 bytes). Los valores disponibles son: 0x800=IPv4.

EXTENSIONES DE DESTINO

Las extensiones de arptables están precompiladas en la herramienta de espacio de usuario. Por lo tanto, no es necesario cargarlas explícitamente con una opción -m como en iptables. Sin embargo, estas extensiones tratan funcionalidades soportadas por módulos del kernel suplementarios.

mangle

--mangle-ip-s IP address
Modifica la dirección IP de origen al valor dado.
--mangle-ip-d IP address
Modifica la dirección IP de destino al valor dado.
--mangle-mac-s MAC address
Modifica la dirección MAC de origen al valor dado.
--mangle-mac-d MAC address
Modifica la dirección MAC de destino al valor dado.
--mangle-target target
El destino de la operación de modificación de ARP (DROP, CONTINUE o ACCEPT — por defecto es ACCEPT).

CLASSIFY

Este módulo le permite establecer el valor skb->priority (y así clasificar el paquete en una clase CBQ específica).

--set-class major:minor

Establece los valores de clase mayor y menor. Los valores siempre se interpretan como hexadecimales incluso si no se proporciona el prefijo 0x.

MARK

Este módulo le permite establecer el valor skb->mark (y así clasificar el paquete por la marca en u32)

--set-mark mark
Establece el valor de la marca. Los valores siempre se interpretan como hexadecimales incluso si no se proporciona el prefijo 0x
--and-mark mark
Realiza un AND binario de la marca con bits.
--or-mark mark
Realiza un OR binario de la marca con bits.

NOTAS

En esta versión de arptablesbasada en nft, no se ha implementado el soporte para la cadena FORWARD . Dado que los paquetes ARP son "reenviados" solo por los puentes de Linux, lo mismo se puede lograr usando la cadena FORWARD en ebtables.
