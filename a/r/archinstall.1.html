archinstall - Documentación de

archinstall

archinstall es una biblioteca que se puede utilizar para instalar Arch Linux. La biblioteca viene empaquetada con diferentes instaladores preconfigurados, como el instalador de Instalación Guiada predeterminado <#guided>

.

Algunas de las características de Archinstall

son:
  • Amigable con el contexto. La biblioteca siempre ejecuta las llamadas en orden secuencial para asegurar que los pasos de instalación no se superpongan o se ejecuten en el orden incorrecto. También soporta (y usa) envoltorios de contexto para asegurar que la limpieza y las tareas finales como mkinitcpio se llamen cuando sea
    • necesario.
  • Total transparencia Los registros e información se pueden encontrar en /var/log/archinstall tanto en el ISO en vivo como parcialmente en el sistema
    • instalado.
  • Amigable con la accesibilidad Archinstall funciona con espeakup y otras her
    • ramientas de a
ccesibilidad
gracias al us
o de una TUI.

PROBLEMAS CONOCIDOS

Algunos problemas están fuera del alcance del proyecto archinstall https://github.com/archlinux/archinstall/, y los que conocemos se enumeran a continuación.

Esperando sincronización de tiempo #2144 <https://github.com/archlinux/archinstall/issues/2144>

La causa raíz habitual de esto es la topología de red. Más específicamente, timedatectl show https://github.com/archlinux/archinstall/blob/e6344f93f7e476d05bbcd642f2ed91fdde545870/archinstall/lib/installer.py#L136 no puede realizar una sincronización de tiempo adecuada contra los servidores predeterminados.

Reiniciar systemd-timesyncd.service podría funcionar, pero la mayoría de las veces necesita configurar /etc/systemd/timesyncd.conf para que coincida con el diseño de su red.

Nota:

Si sabe que su hora es correcta en la máquina, puede ejecutar archinstall --skip-ntp para ignorar la sincronización de hora.

Esperando a que termine la sincronización del anillo de claves de Arch Linux (archlinux-keyring-wkd-sync). #2679 <https://github.com/archlinux/archinstall/issues/2679>

El servicio archlinux-keyring-wkd-sync.service o el temporizador archlinux-keyring-wkd-sync.timer pueden colgarse "indefinidamente" algunas veces. Esto se debe generalmente a la incapacidad de llegar a los servidores de claves o a una conexión lenta hacia los servidores de claves.

El script /usr/bin/archlinux-keyring-wkd-sync se puede ejecutar manualmente, para verificar si se está ejecutando lentamente o no.

Si systemctl show --property=ActiveEnterTimestamp --no-pager archlinux-keyring-wkd-sync.timer no muestra nada, significa que la sincronización incorporada nunca finalizó. Del mismo modo, systemctl show --no-pager -p SubState --value archlinux-keyring-wkd-sync.service probablemente muestre dead, lo que significa que el servicio nunca se completó.

Para solucionar esto, intente lo siguiente:

# killall gpg-agent
# rm -rf /etc/pacman.d/gnupg
# pacman-key --init
# pacman-key --populate
# pacman -Sy archlinux-keyring
# systemctl restart archlinux-keyring-wkd-sync.timer

Nota:

Si sabe que la ISO es la más reciente y que tiene claves GPG válidas, intente archinstall --skip-wkd para omitir la espera de la sincronización.

Si omite la sincronización WKD, podría terminar con:

> error: archinstall: firma de "Anton Hvornum (Torxed) <torxed@archlinux.org>" desconocida
> :: El archivo /var/cache/pacman/pkg/archinstall-1.2.3-4-x86_64.pkg.tar.xz está corrupto (paquete no válido o corrupto (firma PGP)).
> ¿Desea eliminarlo? [S/n]

Falta Controlador Propietario Nvidia #2002 <https://github.com/archlinux/archinstall/issues/2002>

En algunos casos, es posible que el controlador nvidia no tenga todos los paquetes necesarios instalados. Esto se debe a la selección del kernel y/o a configuraciones de hardware que requieren paquetes adicionales para funcionar correctamente.

Una solución común es instalar el paquete linux-headers https://archlinux.org/packages/core/x86_64/linux-headers/ y nvidia-dkms https://archlinux.org/packages/extra/x86_64/nvidia-dkms/

ARM, 32 bits y otros tipos de CPU generan errores #1686 <https://github.com/archlinux/archinstall/issues/1686>, #2185 <https://github.com/archlinux/archinstall/issues/2185>

Este es un problema conocido de tipo "cajón de sastre". Oficialmente, x86_64 <https://wiki.archlinux.org/title/Frequently_asked_questions#What_architectures_does_Arch_support?> solo es compatible con Arch Linux. Por lo tanto, se ha puesto poco esfuerzo en el soporte de otras plataformas.

En teoría, otras arquitecturas deberían funcionar, pero podrían surgir pequeñas peculiaridades.

Se aceptan PR (solicitudes de extracción), pero por favor sea respetuoso con las demoras en la fusión. Otras correcciones, problemas o características tendrán prioridad por las razones anteriores.

Anillo de claves obsoleto #2213 <https://github.com/archlinux/archinstall/issues/2213>

Los problemas de falta de claves suelen deberse a que el paquete archlinux-keyring https://archlinux.org/packages/core/any/archlinux-keyring/ está obsoleto, generalmente como resultado de una ISO obsoleta. Hay un intento por parte de upstream para solucionar este problema, y es el servicio archlinux-keyring-wkd-sync https://gitlab.archlinux.org/archlinux/archlinux-keyring/-/blob/7e672dad10652a80d1cc575d75cdb46442cd7f96/wkd_sync/archlinux-keyring-wkd-sync.service.in

El servicio se inicia casi inmediatamente durante el arranque y, si la red no está configurada a tiempo, el servicio fallará. Posteriormente, la ejecución de archinstall podría operar con un anillo de claves antiguo a pesar de que existe un servicio de actualización para ello.

Realmente no hay una forma fiable a lo largo del tiempo de solucionar este problema en archinstall. En su lugar, los esfuerzos para el servicio upstream deben considerarse el camino a seguir. Y/o las claves no deben caducar entre una cantidad razonable de ISOs.

Nota:

El problema puede ocurrir también en nuevas ISO, incluso tan solo unos pocos días después de su lanzamiento, ya que algunas claves podrían expirar justo después de que el "llavero" (keyring) haya sido "quemado" en la ISO. "quemado"
