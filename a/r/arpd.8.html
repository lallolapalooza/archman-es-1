ARPD(8) Manual del Administrador del Sistema ARPD(8)

NOMBRE

arpd - demonio de ARP en el espacio de usuario.

SINOPSIS

Uso: arpd [ -lkh? ] [ -a N ] [ -b dbase ] [ -B número ] [ -f archivo ] [-p intervalo ] [ -n tiempo ] [ -R tasa ] [ <INTERFACES> ]

DESCRIPCIÓN

El demonio arpd recopila información ARP gratuita, la guarda en el disco local y la proporciona al kernel bajo demanda para evitar transmisiones redundantes debido al tamaño limitado de la caché ARP del kernel.

OPCIONES

-h -?
Imprimir ayuda
-l
Volcar la base de datos de arpd a la salida estándar y salir. La salida consiste en tres columnas: el índice de la interfaz, la dirección IP de la interfaz y la dirección MAC de la interfaz. También se muestran las entradas negativas para hosts inactivos, en cuyo caso la dirección MAC se reemplaza por la palabra FAILED seguida de dos puntos y el tiempo más reciente en que se demostró que el host está inactivo.
-f <ARCHIVO>
Leer y cargar una base de datos de arpd desde ARCHIVO en un formato de texto similar al que se vuelca con la opción -l. Salir después de cargar, posiblemente listando la base de datos resultante, si también se da la opción -l. Si ARCHIVO es -, se lee la entrada estándar para obtener la tabla ARP.
-b <BASE_DE_DATOS>
la ubicación del archivo de base de datos. La ubicación predeterminada es /var/lib/arpd/arpd.db
-a <NÚMERO>
Con esta opción, arpd no solo escucha pasivamente los paquetes ARP en la interfaz, sino que también envía consultas de difusión por sí mismo. NÚMERO es el número de tales consultas a realizar antes de que un destino se considere inactivo. Cuando arpd se inicia como ayudante del kernel (es decir, con app_solicit habilitado en sysctl o incluso con la opción -k) sin esta opción y aún no ha aprendido suficiente información, puede observar brechas de servicio de 1 segundo. No es fatal, pero no es bueno.
-k
Suprimir el envío de consultas de difusión por el kernel. Esta opción solo tiene sentido junto con la opción -a.
-n <TIEMPO>
Especifica el tiempo de espera de la caché negativa. Cuando la resolución falla, arpd suprime nuevos intentos de resolución durante este período. Esta opción solo tiene sentido junto con la opción '-k'. Este tiempo de espera no debe ser mucho mayor que el tiempo de arranque de un host típico que no admite ARP gratuito. El valor predeterminado es 60 segundos.
-p <TIEMPO>
El tiempo de espera en segundos entre intentos de sondeo de la caché ARP del kernel. TIEMPO puede ser un número de punto flotante. El valor predeterminado es 30.
-R <TASA>
Tasa máxima constante de transmisiones enviadas por arpd en paquetes por segundo. El valor predeterminado es 1.
-B <NÚMERO>
El número de transmisiones enviadas por arpd una tras otra. El valor predeterminado es 3. Junto con la opción -R, esta opción garantiza que el número de consultas ARP que se difunden no exceda B+R*T en ningún intervalo de tiempo T.

<INTERFACES> es una lista de nombres de interfaces de red a monitorear. Si no se especifican interfaces, arpd monitorea todas las interfaces. En este caso, arpd no ajusta los parámetros sysctl, se asume que el usuario lo hace él mismo después de que se inicie arpd.

SEÑALES

Cuando arpd recibe una señal SIGINT o SIGTERM, sale graciosamente, sincronizando la base de datos y restaurando los parámetros sysctl ajustados. Con SIGHUP sincroniza la base de datos en el disco. Con SIGUSR1 envía algunas estadísticas a syslog. El efecto de cualquier otra señal no está definido. En particular, pueden corromper la base de datos y dejar los parámetros sysctl en un estado impredecible.

NOTA

Para que arpd pueda servir como resolutor ARP, el kernel debe compilarse con la opción CONFIG_ARPD y, en caso de que la lista de interfaces no se proporcione en la línea de comandos, la variable app_solicit en las interfaces de interés debe estar en /proc/sys/net/ipv4/neigh/*. Si esto no se hace, arpd aún recopila información ARP gratuita en su base de datos.

EJEMPLOS

arpd -b /var/tmp/arpd.db
Iniciar arpd para recopilar ARP gratuito, pero sin interferir con la funcionalidad del kernel.
killall arpd ; arpd -l -b /var/tmp/arpd.db
Ver el resultado después de algún tiempo.
arpd -b /var/tmp/arpd.db -a 1 eth0 eth1
Habilitar el ayudante del kernel, dejando el papel principal al kernel.
arpd -b /var/tmp/arpd.db -a 3 -k eth0 eth1
Reemplazar completamente la resolución del kernel en las interfaces eth0 y eth1. En este caso, el kernel todavía realiza sondeos de unidifusión para validar entradas, pero toda la actividad de difusión se suprime y se realiza bajo la autoridad de arpd.

Este es el modo en el que normalmente se supone que debe funcionar arpd. No es el predeterminado para evitar la activación ocasional de un modo demasiado agresivo.
