ARCHIVE_WRITE(3) Manual de Funciones de Biblioteca ARCHIVE_WRITE(3)

NOMBRE

archive_write — funciones para crear archivos

BIBLIOTECA

Biblioteca de Archivo en Streaming (libarchive, -larchive)

SINOPSIS

#include <archive.h>

DESCRIPCIÓN

Estas funciones proporcionan una API completa para crear archivos en streaming. El proceso general es primero crear el objeto struct archive, establecer las opciones deseadas, inicializar el archivo, añadir entradas, luego cerrar el archivo y liberar todos los recursos.

Crear objeto de archivo

Ver archive_write_new(3).

Para escribir un archivo, primero debes obtener un objeto struct archive inicializado de archive_write_new().

Habilitar filtros y formatos, configurar tamaño de bloque y relleno

Ver archive_write_filter(3), archive_write_format(3) y archive_write_blocksize(3).

Luego puedes modificar este objeto para las operaciones deseadas con las diversas funciones archive_write_set_XXX(). En particular, necesitarás invocar las funciones apropiadas archive_write_add_XXX() y archive_write_set_XXX() para habilitar el soporte de compresión y formato correspondiente.

Establecer opciones

Ver archive_write_set_options(3).

Abrir archivo

Ver archive_write_open(3).

Una vez que hayas preparado el objeto struct archive, llamas a archive_write_open() para abrir realmente el archivo y prepararlo para escribir. Hay varias variantes de esta función; la más básica espera que proporciones punteros a varias funciones que pueden proporcionar bloques de bytes del archivo. Hay formas convenientes que te permiten especificar un nombre de archivo, un descriptor de archivo, un objeto FILE *, o un bloque de memoria desde el cual escribir los datos del archivo.

Producir archivo

Ver archive_write_header(3) y archive_write_data(3).

Las entradas individuales del archivo se escriben en un proceso de tres pasos: primero inicializas una estructura struct archive_entry con información sobre la nueva entrada. Como mínimo, debes establecer la ruta del nombre de la entrada y proporcionar una struct stat con un campo st_mode válido, que especifica el tipo de objeto y un campo st_size, que especifica el tamaño de la porción de datos del objeto.

Liberar recursos

Ver archive_write_free(3).

Después de escribir todas las entradas, usa la función archive_write_free() para liberar todos los recursos.

EJEMPLOS

El siguiente esquema ilustra el uso básico de la biblioteca. En este ejemplo, las funciones de devolución de llamada son simplemente envoltorios alrededor de las llamadas al sistema estándar open(2), write(2) y close(2).

#ifdef __linux__
#define	_FILE_OFFSET_BITS 64
#endif
#include <sys/stat.h>
#include <archive.h>
#include <archive_entry.h>
#include <fcntl.h>
#include <stdlib.h>
#include <unistd.h>

struct mydata {
  const char *name;
  int fd;
};

int
myopen(struct archive *a, void *client_data)
{
  struct mydata *mydata = client_data;

  mydata->fd = open(mydata->name, O_WRONLY | O_CREAT, 0644);
  if (mydata->fd >= 0)
    return (ARCHIVE_OK);
  else
    return (ARCHIVE_FATAL);
}

la_ssize_t
mywrite(struct archive *a, void *client_data, const void *buff, size_t n)
{
  struct mydata *mydata = client_data;

  return (write(mydata->fd, buff, n));
}

int
myclose(struct archive *a, void *client_data)
{
  struct mydata *mydata = client_data;

  if (mydata->fd > 0)
    close(mydata->fd);
  return (0);
}

void
write_archive(const char *outname, const char **filename)
{
  struct mydata *mydata = malloc(sizeof(struct mydata));
  struct archive *a;
  struct archive_entry *entry;
  struct stat st;
  char buff[8192];
  int len;
  int fd;

  a = archive_write_new();
  mydata->name = outname;
  /* Establecer el formato y el filtro del archivo según la extensión del archivo de salida.
   * Si falla, establecer el formato predeterminado. Función dependiente de la plataforma.
   * Ver formatos soportados en archive_write_set_format_filter_by_ext.c */
  if (archive_write_set_format_filter_by_ext(a, outname) != ARCHIVE_OK)  {
    archive_write_add_filter_gzip(a);
    archive_write_set_format_ustar(a);
  }
  archive_write_open(a, mydata, myopen, mywrite, myclose);
  while (*filename) {
    stat(*filename, &st);
    entry = archive_entry_new();
    archive_entry_copy_stat(entry, &st);
    archive_entry_set_pathname(entry, *filename);
    archive_write_header(a, entry);
    if ((fd = open(*filename, O_RDONLY)) != -1) {
      len = read(fd, buff, sizeof(buff));
      while (len > 0) {
        archive_write_data(a, buff, len);
        len = read(fd, buff, sizeof(buff));
      }
      close(fd);
    }
    archive_entry_free(entry);
    filename++;
  }
  archive_write_free(a);
}

int main(int argc, const char **argv)
{
  const char *outname;
  argv++;
  outname = *argv++;
  write_archive(outname, argv);
  return 0;
}

ERRORES

Hay muchos errores peculiares en implementaciones de tar históricas que pueden hacer que ciertos programas rechacen los archivos creados por esta biblioteca. Por ejemplo, varias implementaciones históricas calcularon las sumas de verificación de encabezados incorrectamente y, por lo tanto, rechazarán archivos válidos; GNU tar no soporta completamente el formato de intercambio pax; algunas implementaciones antiguas de tar requerían terminaciones de campo específicas.

El formato de intercambio pax predeterminado elimina la mayoría de las limitaciones históricas de tar y proporciona una instalación genérica de atributos clave/valor para extensiones definidas por el proveedor. Una omisión en POSIX es la falta de proporcionar un atributo estándar para números de dispositivo grandes.
