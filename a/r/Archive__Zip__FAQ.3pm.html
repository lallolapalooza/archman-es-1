¿Por qué mi archivo zip es tan

grande?

P: ¡Mi archivo zip es en realidad más grande que lo que guardé en él! ¿Por

qué?

R: Algunas cosas que debes

asegurarte:
Asegúrate de que estás solicitando COMPRESSION_DEFLATED si estás almacenando cadenas de
texto.
$member->desiredCompressionMethod( COMPRESSION_DEFLATED
);
No hagas muchos archivos pequeños si puedes
evitarlo.
Dado que zip calcula las tablas de compresión para cada miembro, los miembros pequeños sin mucha entropía no se comprimirán bien. En su lugar, si tienes muchas cadenas de texto repetidas en tus datos, intenta combinarlas en un solo miembro
grande.
Asegúrate de que estás solicitando COMPRESSION_STORED si estás almacenando cosas que ya están
comprimidas.
Si estás almacenando un .zip, .jpg
, .mp3 u otro archivo comprimido e
n un zip, entonces no los comprim
as de nuevo. Se harán más grandes.

No se puede leer/modificar/escribir el mismo archivo

Zip

P: ¿Por qué no puedo abrir un archivo Zip, añadir un miembro y escribirlo de vuelta? Recibo un mensaje de error cuando lo

intento.

R: Debido a que Archive::Zip no lee (y no puede, generalmente) el contenido de los archivos en la memoria, el archivo Zip original debe permanecer hasta que se complete la escritura del nuevo

archivo.

La mejor manera de hacer esto es escribir el Zip en un archivo temporal y luego renombrar el archivo temporal para que tenga el nombre antiguo (posiblemente después de eliminar el antiguo)

.

Archive::Zip v1.02 añadió los métodos de archivo overwrite() y overwriteAs() para hacer esto de manera simple y

cuidadosa.

Ver "examples/updateZip.pl" para

un ejemplo de
esta técnica.

Hora de creación del archivo no

establecida

P: Al extraer archivos, veo que su hora de modificación (y acceso) se establece en la hora del archivo Zip. Sin embargo, su hora de creación no se establece en la misma hora. ¿Por

qué?

R: Mayormente porque Perl no da acceso multiplataforma a la hora de creación. De hecho, muchos sistemas (como Unix) no soportan tal concepto. Sin embargo, si el tuyo lo soporta, puedes establecerla fácilmente. Obtén la hora de modificación del miembro usando lastMod

Tim
e().

No se puede usar Archive::Zip en archivos

gzip

P: ¿Puedo usar Archive::Zip para extraer archivos gzip de

Unix?

R:

No.

Hay una distinción entre los archivos gzip de Unix y los archivos Zip que también pueden usar la compresión

gzip.

Dependiendo del formato del archivo gzip, puedes usar Compress::Raw::Zlib o Archive::Tar para descomprimirlo (y desarchivarlo en el caso de los archivos Tar)

.

Puedes descomprimir archivos PKZIP/WinZip/etc/ usando Ar

chive::Zip (para eso sirve) siempre que cualquier miemb
ro comprimido esté comprimido usando compresión Deflate.

Añadir un directorio/árbol a un

Zip

P: ¿Cómo puedo añadir un directorio (o árbol) lleno de archivos a un

Zip?

R: Puedes usar los métodos Archive::Zip::addTree*()

: 
use Archive::Zip;
my $zip = Archive::Zip->new();
# añadir todos los archivos y directorios legibles debajo de . como xyz/*
$zip->addTree( '.', 'xyz' );
# añadir todos los archivos simples legibles debajo de /abc como def/*
$zip->addTree( '/abc', 'def', sub { -f && -r } );
# añadir todos los archivos .c debajo de /tmp como stuff/*
$zip->addTreeMatching( '/tmp', 'stuff', '\.c$' );
# añadir todos los archivos .o debajo de /tmp como stuff/* si no son escribibles
$zip->addTreeMatching( '/tmp', 'stuff', '\.o$', sub { ! -w } );
# añadir todos los archivos .so debajo de /tmp que son más pequeños que 200 bytes como stuff/*
$zip->addTr
eeMatching( '/tmp', 'stuff', '\.o$', sub { -s < 200 } ); # y
escribirlos en un archivo $zip->writeToFileNamed('xxx.zip');

No se pueden extraer archivos

Shrunk

P: Estoy intentando extraer un archivo de un Zip producido por PKZIP, y sigo recibiendo este mensaje de

error: 
error: Unsupported compression combination: read 6, write
0

R: No puedes descomprimir este miembro del archivo. Archive::Zip solo soporta miembros sin comprimir, y miembros comprimidos que están comprimidos usando la compresión soportada por Compress::Raw::Zlib. Eso significa solo miembros Deflated y

Stored.

Tu archivo está comprimido usando el formato Shrink, que no es soportado por Compress::Raw::

Zlib.

Podrías, quizás, usar un programa U

nZip de línea de comandos (como el
de Info-Zip) para extraer esto.

descifrado

cifrados?

R: Con algún otro programa o biblioteca. Archive::Zip no soporta descifrado, y probablemente nunca lo hará (a menos que tú escribas

el có
digo).

¿Cómo probar la integridad de un

archivo?

P: ¿Cómo puede Archive::Zip probar la validez de un archivo

Zip?

R: Si intentas descomprimir el archivo, los flujos gzip reportarán errores si hay basura. La mayor parte del

tiempo.

Si intentas abrir el archivo y no se puede encontrar una estructura de directorio central, se reportará un

error.

Cuando se lee un archivo, si no podemos encontrar una firma PK.. adecuada en los lugares correctos, reportamos un error de

formato.

Si hay basura añadida al principio de un archivo Zip (como la insertada por algunos virus), puedes enterarte de ello, pero Archive::Zip la ignorará, y aún podrás usar el archivo. Cuando se vuelva a escribir la cosa añadida habrá

desaparecido.

Hay dos utilidades listas para usar en el directorio examples que pueden usarse para probar la integridad de un archivo, o que puedes usar como ejemplos para tu propio

código:
examples/zipcheck.pl muestra cómo usar un intento de extracción para probar un
archivo.
examples/ziptest.pl muestra cómo probar los CRC en un
archivo.
