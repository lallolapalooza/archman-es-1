AGE(1) General Commands Manual AGE(1)

NAME

age - cifrado de archivos simple, moderno y seguro

SYNOPSIS

age [--encrypt] (-r RECIPIENT | -R PATH)... [--armor] [-o OUTPUT] [INPUT]
age [--encrypt] --passphrase [--armor] [-o OUTPUT] [INPUT]
age --decrypt [-i PATH | -j PLUGIN]... [-o OUTPUT] [INPUT]

DESCRIPTION

age cifra o descifra INPUT a OUTPUT. El argumento INPUT es opcional y por defecto es la entrada estándar. Solo se puede especificar un archivo INPUT. Si no se especifica -o, OUTPUT por defecto es la salida estándar.

Si se especifica -p/--passphrase, el archivo se cifra con una contraseña solicitada interactivamente. De lo contrario, se cifra para uno o más RECIPIENTES especificados con -r/--recipient o -R/--recipients-file. Cada destinatario puede descifrar el archivo.

En el modo -d/--decrypt, los archivos cifrados con contraseña se detectan automáticamente y se solicita la contraseña interactivamente. De lo contrario, se utilizan una o más IDENTIDADES especificadas con -i/--identity para descifrar el archivo.

Los archivos cifrados por age son binarios y no maleables, con alrededor de 200 bytes de sobrecarga por destinatario, más 16 bytes por cada 64KiB de texto plano.

OPCIONES

-o, --output=OUTPUT
Escribe el archivo cifrado o descifrado en OUTPUT en lugar de la salida estándar. Si OUTPUT ya existe, será sobrescrito.
Si se cifra sin --armor, age se negará a producir salida binaria a una TTY. Esto se puede forzar especificando - como OUTPUT.
--version
Imprime la versión y sale.

Opciones de cifrado

-e, --encrypt
Cifra INPUT a OUTPUT. Este es el valor por defecto.
-r, --recipient=RECIPIENT
Cifra al RECIPIENTE especificado explícitamente. Consulte la sección RECIPIENTES E IDENTIDADES para conocer los posibles formatos de destinatario.
Esta opción se puede repetir y combinar con otras banderas de destinatario, y el archivo puede ser descifrado por todos los destinatarios proporcionados de forma independiente.
-R, --recipients-file=PATH
Cifra a los RECIPIENTES listados en el archivo en PATH, uno por línea. Las líneas vacías y las líneas que comienzan con # se ignoran como comentarios.
Si PATH es -, los destinatarios se leen de la entrada estándar. En este caso, se debe especificar el argumento INPUT.
Esta opción se puede repetir y combinar con otras banderas de destinatario, y el archivo puede ser descifrado por todos los destinatarios proporcionados de forma independiente.
-p, --passphrase
Cifra con una contraseña, solicitada interactivamente desde la terminal. age ofrecerá generar automáticamente una contraseña segura.
Esta opción no se puede usar con otras banderas de destinatario.
-a, --armor
Cifra a una codificación "blindada" solo en ASCII.
El blindaje de age es una versión estricta de PEM con el tipo AGE ENCRYPTED FILE, Base64 canónico "estricto", sin encabezados y sin soporte para datos adicionales al principio y al final.
El descifrado detecta y decodifica transparentemente el blindaje ASCII.
-i, --identity=PATH
Cifra a los RECIPIENTES correspondientes a las IDENTIDADES listadas en el archivo en PATH. Esto es equivalente a convertir el archivo en PATH a un archivo de destinatarios con age-keygen -y y luego pasarlo a -R/--recipients-file.
Para el formato de PATH, consulte la definición de -i/--identity en la sección Opciones de descifrado.
Se debe especificar explícitamente -e/--encrypt al usar -i/--identity en modo de cifrado para evitar confusiones.
-j PLUGIN
Cifra usando el plugin sin datos PLUGIN.
Esto es equivalente a usar -i/--identity con un archivo que contiene una única IDENTIDAD de plugin que no codifica datos específicos del plugin.
Se debe especificar explícitamente -e/--encrypt al usar -j en modo de cifrado para evitar confusiones.

Opciones de descifrado

-d, --decrypt
Descifra INPUT a OUTPUT.
Si INPUT está cifrado con contraseña, se detectará automáticamente y se solicitará la contraseña interactivamente. De lo contrario, se utilizan las IDENTIDADES especificadas con -i/--identity.
El blindaje ASCII se detecta y decodifica de forma transparente.
-i, --identity=PATH
Descifra usando las IDENTIDADES en PATH.
PATH puede ser una de las siguientes opciones:
a. Un archivo que lista IDENTIDADES una por línea. Las líneas vacías y las líneas que comienzan con "#" se ignoran como comentarios.
b. Un archivo age cifrado con contraseña, que contiene IDENTIDADES una por línea como arriba. La contraseña se solicita interactivamente. Tenga en cuenta que los archivos de identidad protegidos con contraseña no son necesarios para la mayoría de los casos de uso, donde el acceso al archivo de identidad cifrado implica el acceso a todo el sistema.
c. Un archivo de clave privada SSH, en formato PKCS#1, PKCS#8 o OpenSSH. Si la clave privada está protegida con contraseña, la contraseña se solicita interactivamente solo si la identidad SSH coincide con el archivo. Consulte la sección Claves SSH para obtener más información, incluidos los tipos de clave compatibles.
d. "-", haciendo que una de las opciones anteriores se lea de la entrada estándar. En este caso, se debe especificar el argumento INPUT.
Esta opción se puede repetir. Las identidades se prueban en el orden en que se proporcionan, y se utiliza la primera que coincide con uno de los destinatarios del archivo. Las identidades no utilizadas se ignoran, pero es un error si el archivo INPUT está cifrado con contraseña y se especifica -i/--identity.
-j PLUGIN
Descifra usando el plugin sin datos PLUGIN.
Esto es equivalente a usar -i/--identity con un archivo que contiene una única IDENTIDAD de plugin que no codifica datos específicos del plugin.

RECIPIENTES E IDENTIDADES

Los RECIPIENTES son valores públicos, como una clave pública, a los que se puede cifrar un archivo. Las IDENTIDADES son valores privados, como una clave privada, que permiten descifrar un archivo cifrado para el RECIPIENTE correspondiente.

Claves X25519 nativas

Los pares de claves nativos de age se generan con age-keygen(1) y proporcionan codificaciones pequeñas y cifrado seguro basado en X25519. Son el tipo de destinatario recomendado para la mayoría de las aplicaciones.

Una codificación de RECIPIENTE comienza con age1 y tiene el siguiente aspecto:

a
ge1gde3ncmahlqd9gg50tanl99r960llztrhfapnmx853s4tjum03uqfssgdh

Una IDENTIDAD comienza con AGE-SECRET-KEY-1 y tiene el siguiente aspecto:

AGE-SECRET-KEY-1KTYK6RVLN5TAPE7VF6FQQSKZ9HWWCDSKUGXXNUQDWZ7XXT5YK5LSF3UTKQ

Un archivo cifrado no se puede vincular con el destinatario nativo al que está cifrado sin acceso a la identidad correspondiente.

Claves SSH

Como característica de conveniencia, age también admite cifrar con claves ssh(1) RSA o Ed25519. Las claves RSA deben tener al menos 2048 bits. Esta característica emplea una criptografía más compleja y solo debe usarse cuando no haya una clave nativa disponible para el destinatario. Ten en cuenta que las claves SSH podrían no estar protegidas a largo plazo por el destinatario, ya que son revocables cuando se usan solo para autenticación.

Una CODIFICACIÓN DE DESTINATARIO es una clave pública SSH en formato authorized_keys (consulta la sección FORMATO DEL ARCHIVO AUTHORIZED_KEYS de sshd(8)), que comienza con ssh-rsa o ssh-ed25519, como la siguiente:

ssh-rsa AAAAB3NzaC1yc2EAAAADAQABAAABgQDULTit0KUehbi[...]GU4BtElAbzh8=
ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIH9pO5pz22JZEas[...]l1uZc31FGYMXa

El comentario al final de la línea, si existe, se ignora.

En los archivos de destinatarios pasados a -R/--recipients-file, las claves SSH válidas pero no admitidas se ignoran con una advertencia, para facilitar el uso de archivos authorized_keys o .keys de GitHub. (Consulta EJEMPLOS.)

Una IDENTIDAD es un archivo de clave privada SSH archivo pasado individualmente a -i/--identity. Ten en cuenta que las claves almacenadas en tokens de hardware como YubiKeys o accedidas a través de ssh-agent(1) no están admitidas.

Un archivo cifrado puede vincularse con la clave pública SSH a la que fue cifrado. Esto permite que age identifique la clave privada SSH correcta antes de solicitar su contraseña, si la hay.

Plugins

age se puede extender a través de plugins. Un plugin solo se carga si se especifica un DESTINATARIO o IDENTIDAD correspondiente. (Simplemente descifrar un archivo cifrado con un plugin no hará que se cargue, entre otras razones por seguridad.)

Un DESTINATARIO para un plugin llamado example comienza con age1example1, mientras que una IDENTIDAD comienza con AGE-PLUGIN-EXAMPLE-1. Ambos codifican datos arbitrarios específicos del plugin y son generados por el plugin.

Cuando se especifica cualquiera de los dos, age busca age-plugin-example en el PATH y lo ejecuta para realizar el cifrado o descifrado de la cabecera del archivo. El plugin puede solicitar entrada del usuario a través de age para completar la operación.

Los plugins se pueden mezinar libremente con otros plugins o con claves admitidas nativamente.

Un plugin no está limitado a cifrar o descifrar archivos destinados o generados por el plugin. Por ejemplo, un plugin se puede usar para descifrar archivos cifrados a un DESTINATARIO X25519 nativo o incluso con una frase de paso. De manera similar, un plugin puede cifrar un archivo de tal forma que pueda descifrarse sin el uso de ningún plugin.

Los plugins para los que la distinción entre IDENTIDAD/DESTINATARIO no tiene sentido (como un plugin de cifrado simétrico) pueden generar solo una IDENTIDAD e indicar al usuario que realice el cifrado con los indicadores -e/--encrypt e -i/--identity . Los plugins para los que el concepto de identidades separadas no tiene sentido (como un plugin de cifrado por contraseña) pueden indicar al usuario que use el indicador -j .

ESTADO DE SALIDA

age saldrá con 0 si y solo si el cifrado o descifrado se realiza con éxito durante toda la longitud de la entrada.

Si ocurre un error durante el descifrado, aún podría generarse una salida parcial, pero solo si fue posible autenticarla de forma segura. Nunca se libera salida no autenticada.

COMPATIBILIDAD HACIA ATRÁS

Los archivos cifrados con una versión estable (no alfa, beta ni candidata a lanzamiento) de age, o con cualquier beta o candidata a lanzamiento de la v1.0.0, se descifrarán con cualquier versión posterior de la herramienta.

Si descifrar archivos más antiguos plantea un riesgo de seguridad, hacerlo podría causar un error de forma predeterminada. En este caso, se proporcionará un indicador para forzar la operación.

EJEMPLOS

Generar una nueva identidad, cifrar datos y descifrar:

$ age-keygen -o key.txt
Clave pública: age1ql3z7hjy54pw3hyww5ayyfg7zqgvc7w3j2elw8zmrj2kg5sfn9aqmcac8p
$ tar cvz ~/data | age -r age1ql3z7hjy54pw3hyww5ayyfg7zqgvc7w3j2elw8zmrj2kg5sfn9aqmcac8p > data.tar.gz.age
$ age -d -o data.tar.gz -i key.txt data.tar.gz.age

Cifrar example.jpg para múltiples destinatarios y generar la salida en example.jpg.age:

$ age -o example.jpg.age -r age1ql3z7hjy54pw3hyww5ayyfg7zqgvc7w3j2elw8zmrj2kg5sfn9aqmcac8p \
    -r age1lggyhqrw2nlhcxprm67z43rta597azn8gknawjehu9d9dl0jq3yqqvfafg example.jpg

Cifrar para una lista de destinatarios:

$ cat > recipients.txt
# Alice
age1ql3z7hjy54pw3hyww5ayyfg7zqgvc7w3j2elw8zmrj2kg5sfn9aqmcac8p
# Bob
age1lggyhqrw2nlhcxprm67z43rta597azn8gknawjehu9d9dl0jq3yqqvfafg
$ age -R recipients.txt example.jpg > example.jpg.age
