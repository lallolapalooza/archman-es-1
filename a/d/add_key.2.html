DESCRIPCIÓ

N

add_key() crea o actualiza una clave del tipo y descripción dados, la instancia con el payload de tamaño size, la adjunta al anillo de claves nominado, y devuelve el número de serie de la

clave.

La clave puede ser rechazada si los datos proporcionados están en el formato incorrecto o son inválidos de alguna otra

manera.

Si el anillo de claves de destino ya contiene una clave que coincide con el tipo y la descripción especificados, entonces, si el tipo de clave lo soporta, esa clave será actualizada en lugar de crear una nueva clave; si no, se creará una nueva clave (con un ID diferente) y desplazará el enlace a la clave existente del anillo de

claves.

El número de serie del anillo de claves de destino puede ser el de un anillo de claves válido para el cual el llamador tiene permiso de escritura. Alternativamente, puede ser uno de los siguientes IDs especiales de anillo de

claves:

Este es un tipo de clave de propósito general cuyo payload puede ser leído y actualizado por aplicaciones de espacio de usuario. La clave se mantiene completamente dentro de la memoria del núcleo. El payload para claves de este tipo es un blob de datos arbitrarios de hasta 32,767

"logon" (desde Linux
3.3)
Este tipo de clave es esencialmente el mismo que "user", pero no permite leer la clave. Esto es adecuado para almacenar

Este tipo de clave verifica la descripción para asegurar que está calificada por un prefijo "service", comprobando que la descripción contiene un ':' precedido por otros

caracteres.
"big_key" (desde Linux 3.
13)
Este tipo de clave es similar a "user", pero puede contener un payload de hasta 1 MiB. Si el payload de la clave es lo suficientemente grande, entonces
puede ser almacenado cifrado en tmpfs (que puede ser int

NAME


add_key, add_key_payload, keyctl_add_key - add a key to the kernel keyring






LIBRARY


libkeyutils






SYNOPSIS


#include <keyctl.h>


key_serial_t add_key(const char*, const char*, const void*, size_t, key_serial_t);


#include <keyutils.h>


key_serial_t add_key_payload(const char*, const char*, const void*, size_t, key_serial_t);


key_serial_t keyctl_add_key(const char*, const char*, const void*, size_t, key_serial_t);






DESCRIPTION


The add_key() system call (and the library
    functions add_key_payload() and
    keyctl_add_key() which wrap it) allows an
    application to add a key to the Linux kernel keyring.


A key consists of a type, a description, a payload, and an
    access control list (ACL). This function only adds a key; it does not
    allow specifying an ACL.


The key type is specified by the type
    argument.


The key description is specified by the desc
    argument.


The key payload is specified by the payload
    argument, which points to a buffer of length plen.


The key is added to the keyring specified by keyring_serial.
    If keyring_serial is 0, then the key is added to the
    "user" keyring of the calling thread, unless that keyring has been
    swapped out by keyctl(1), in which case it
    is added to the process-wide "user" keyring.


The add_key() system call is used to create
    a new key. The key type, description, and payload are provided as arguments.
    The key is added to the keyring specified by keyring_serial.
    If keyring_serial is 0, then the key is added to the
    "user" keyring of the calling thread. The return value is the serial
    number of the new key, or -1 if an error occurred.


The add_key_payload() and
    keyctl_add_key() library functions are wrappers around
    the add_key() system call. They provide a more
    convenient interface for applications that use the libkeyutils library.


The key type is specified by the type
    argument. The key description is specified by the desc
    argument. The key payload is specified by the payload
    argument, which points to a buffer of length plen. The
    key is added to the keyring specified by keyring_serial.






RETURN VALUE


On success, add_key(),
    add_key_payload(), and keyctl_add_key()
    return the serial number of the newly created key. This is a positive
    integer.


On error, -1 is returned, and errno is set
    to indicate the error.






ERRORS


EACCES: The caller does not have permission to
    write to the target keyring.


EFAULT: The type,
    desc, or payload argument
    points to invalid memory.


EIDRM: The keyring specified by
    keyring_serial has been cleared.


EINVAL: The type or
    desc argument is invalid, or plen
    is greater than the maximum allowed payload size.


ENOMEM: There was insufficient kernel memory
    to create the key.


ENOKEY: The keyring specified by
    keyring_serial does not exist.


ENOSPC: The keyring is full and cannot
    hold any more keys.


EPERM: The caller does not have permission to
    add a key of the specified type.


ESUBJSIZE: The size of the key description or
    payload is too large.


EUNATCH: The key type specified by type
    is not supported by the kernel.






STANDARDS


These system calls are Linux-specific.






HISTORY


The add_key() system call was introduced in
    Linux kernel 2.6.10.


The add_key_payload() and
    keyctl_add_key() library functions were added in
    libkeyutils 1.2.






NOTES


The add_key() system call can only be used to
    add keys to specific keyrings, such as the user keyring, session keyring,
    process keyring, or thread keyring. It cannot be used to add keys to
    keyrings that are not accessible to the calling process.


The maximum size of a key payload is determined by the kernel
    configuration. It is typically 32KB or 64KB.


The key type string must be null-terminated. The key description
    string must be null-terminated.


The keyring serial number is a positive integer that uniquely
    identifies a key. It is returned by add_key() when a
    key is created, and can be used by other key management system calls to
    refer to the key.


The keyctl_add_key() function is a wrapper
    that calls the add_key() system call. It takes the
    same arguments as add_key() and returns the same
    values.


The add_key_payload() function is also a
    wrapper around add_key(). It is intended for use
    when the payload is already in a buffer. It takes the same arguments as
    add_key() and returns the same values.






EXAMPLES


The following example adds a key of type "user" with description
    "mykey" and a payload of "mysecretvalue" to the session keyring:


#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <keyctl.h>

int
main(int argc, char *argv[])
{
    key_serial_t key;

    if (argc != 4) {
        fprintf(stderr, "Usage: %s <type> <desc> <payload>\n",
                argv[0]);
        exit(EXIT_FAILURE);
    }

    key = add_key(argv[1], argv[2], argv[3], strlen(argv[3]),
                  KEY_SPEC_SESSION_KEYRING);
    if (key == -1) {
        perror("add_key");
        exit(EXIT_FAILURE);
    }

    printf("Key ID is %jx\n", (uintmax_t) key);
    exit(EXIT_SUCCESS);
}
