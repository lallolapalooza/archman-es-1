ADMIN(1P) Manual del programador de POSIX ADMIN(1P)

PROLOGO

Esta página del manual es parte del Manual del programador de POSIX. La implementación de esta interfaz en Linux puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

admin — crear y administrar archivos SCCS (DESARROLLO)

SINOPSIS

admin -i[nombre] [-n] [-a login] [-d flag] [-e login] [-f flag]
    [-m lista_mr] [-r rel] [-t[nombre] [-y[comentario]] archivo_nuevo
admin -n [-a login] [-d flag] [-e login] [-f flag] [-m lista_mr]
    [-t[nombre]] [-y[comentario]] archivo_nuevo...
admin [-a login] [-d flag] [-m lista_mr] [-r rel] [-t[nombre]] archivo...
admin -h archivo...
admin -z archivo...

DESCRIPCION

El comando admin crea nuevos archivos SCCS o cambia los parámetros de los existentes. Si un archivo nombrado no existe, se creará y sus parámetros se inicializarán según las opciones especificadas. Los parámetros no inicializados por una opción recibirán un valor predeterminado. Si un archivo nombrado ya existe, los parámetros correspondientes a las opciones especificadas se cambiarán y los demás parámetros permanecerán sin cambios.

Todos los nombres de archivo SCCS suministrados por la aplicación deben tener el formato s.nombre_archivo. Los nuevos archivos SCCS tendrán permisos de solo lectura. Se requiere permiso de escritura en el directorio padre para crear un archivo. Toda la escritura realizada por admin se hará a un archivo temporal x-file, llamado x.nombre_archivo (consulte get), creado con modo de solo lectura si admin está creando un nuevo archivo SCCS, o creado con el mismo modo que el del archivo SCCS si el archivo ya existe. Después de la ejecución exitosa de admin, el archivo SCCS se eliminará (si existe) y el x-file se renombrará con el nombre del archivo SCCS. Esto asegura que los cambios se realicen en el archivo SCCS solo si no ocurren errores.

El comando admin también utilizará un archivo de bloqueo transitorio (llamado z.nombre_archivo), que se utiliza para evitar actualizaciones simultáneas del archivo SCCS; consulte get.

OPCIONES

El comando admin cumplirá con el volumen de Definiciones Base de POSIX.1‐2017, Sección 12.2, Directrices de sintaxis de utilidades, excepto que las opciones -i, -t y -y tienen argumentos de opción opcionales. Estos argumentos de opción opcionales no se presentarán como argumentos separados. Se admiten las siguientes opciones:

-n
Crea un nuevo archivo SCCS. Cuando se usa -n sin -i, el archivo SCCS se creará con información de control pero sin datos de archivo.
-i[nombre]
Especifica el nombre de un archivo del cual se tomará el texto para un nuevo archivo SCCS. El texto constituye el primer delta del archivo (consulte la opción -r para el esquema de numeración de deltas). Si se usa la opción -i, pero se omite el argumento de opción nombre, el texto se obtendrá leyendo la entrada estándar. Si se omite esta opción, el archivo SCCS se creará con información de control pero sin datos de archivo. La opción -i implica la opción -n.
-r SID
Especifica el SID del delta inicial a insertar. Este SID será un SID de rama principal; es decir, los números de rama y secuencia serán cero o faltantes. El número de nivel es opcional y por defecto es 1.
-t[nombre]
Especifica el nombre de un archivo del cual se tomará el texto descriptivo para el archivo SCCS. En el caso de archivos SCCS existentes (ni -i ni -n especificados):
*
Una opción -t sin argumento de opción nombre eliminará el texto descriptivo (si lo hay) actualmente en el archivo SCCS.
*
Una opción -t con un argumento de opción nombre hará que el texto (si lo hay) en el archivo nombrado reemplace el texto descriptivo (si lo hay) actualmente en el archivo SCCS.
-f flag
Especifica una flag, y, posiblemente, un valor para la flag, que se colocará en el archivo SCCS. Se pueden suministrar varias opciones -f en una sola línea de comando admin. Las implementaciones reconocerán las siguientes flags y sus valores asociados:
b
Permite el uso de la opción -b en un comando get para crear deltas de rama.
ctecho
Especifica la liberación más alta (es decir, techo), un número menor o igual a 9999, que puede ser recuperado por un comando get para edición. El valor predeterminado para una flag c no especificada será 9999.
fsuelo
Especifica la liberación más baja (es decir, suelo), un número mayor que 0 pero menor que 9999, que puede ser recuperado por un comando get para edición. El valor predeterminado para una flag f no especificada será 1.
dSID
Especifica el número de delta predeterminado (SID) a ser utilizado por un comando get.
icadena
Trata el mensaje ``No ID keywords'' emitido por get o delta como un error fatal. En ausencia de esta flag, el mensaje es solo una advertencia. El mensaje se emite si no se encuentran palabras clave de identificación SCCS (consulte get) en el texto recuperado o almacenado en el archivo SCCS. Si se suministra un valor, la aplicación garantizará que las palabras clave coincidan exactamente con la cadena dada; sin embargo, la cadena debe contener una palabra clave y no caracteres de nueva línea (<newline>) incrustados.
j
Permite comandos get concurrentes para edición en el mismo SID de un archivo SCCS. Esto permite múltiples actualizaciones concurrentes de la misma versión del archivo SCCS.
llista
Especifica una lista de liberaciones a las que ya no se pueden hacer deltas (es decir, get -e contra una de estas liberaciones bloqueadas falla). Las aplicaciones que cumplan deben usar la siguiente sintaxis para especificar una lista. Las implementaciones pueden aceptar formas adicionales como una extensión:
<lista> ::= a | <lista-rango>
<lista-rango> ::= <rango> | <lista-rango>, <rango>
<rango> ::= <SID>

El carácter a en la lista será equivalente a especificar todas las liberaciones para el archivo SCCS nombrado. El no terminal <SID> en rango será el número de delta de un delta existente asociado con el archivo SCCS.

n
Hace que delta cree un delta nulo en cada una de esas liberaciones (si las hay) que se omiten cuando se realiza un delta en una nueva liberación (por ejemplo, al crear el delta 5.1 después del delta 2.7, se omiten las liberaciones 3 y 4). Estos deltas nulos servirán como puntos de anclaje para que los deltas de rama puedan crearse a partir de ellos más tarde. La ausencia de esta flag hará que las liberaciones omitidas no existan en el archivo SCCS, evitando que se creen deltas de rama a partir de ellas en el futuro. Durante la creación inicial de un archivo SCCS, la flag n puede ignorarse; es decir, si la opción -r se usa para establecer el número de liberación del SID inicial a un valor mayor que 1, no es necesario crear deltas nulos para las liberaciones ``omitidas''.
qtexto
Sustituye el texto definible por el usuario por todas las ocurrencias de la palabra clave %Q% en el texto del archivo SCCS recuperado por get.
mmod
Especifica el nombre del módulo del archivo SCCS sustituido por todas las ocurrencias de la palabra clave %M% en el texto del archivo SCCS recuperado por get

>. Si el indicador m no se especifica, el valor asignado será el nombre del archivo SCCS con el '.' inicial eliminado.
ttipo
Especificar el tipo de módulo en el archivo SCCS sustituido por todas las ocurrencias de la palabra clave %Y% en el texto del archivo SCCS recuperado por get.
vpgm
Hacer que delta solicite números de solicitud de modificación (MR) como motivo para crear un delta. El valor opcional especifica el nombre de un programa de validación de números MR. (Si se establece esta opción al crear un archivo SCCS, la aplicación deberá asegurarse de que también se utilice la opción m, incluso si su valor es nulo).
-d flag
Eliminar (borrar) el flag especificado de un archivo SCCS. Se pueden suministrar varias opciones -d en un solo comando admin. Ver la opción -f para los nombres de flag permitidos. (El indicador llist proporciona una lista de versiones a desbloquear. Ver la opción -f para una descripción más detallada del indicador l y la sintaxis de una lista.)
-a login
Especificar un nombre de login, o ID de grupo numérico, que se añadirá a la lista de usuarios que pueden realizar deltas (cambios) en el archivo SCCS. Un ID de grupo será equivalente a especificar todos los nombres de login comunes a ese ID de grupo. Se pueden utilizar varias opciones -a en una sola línea de comando admin. Se pueden tener tantos logins, o IDs de grupo numéricos, como se desee en la lista simultáneamente. Si la lista de usuarios está vacía, entonces cualquiera puede añadir deltas. Si el login o el ID de grupo van precedidos por un '!', se denegará el permiso a los usuarios especificados para realizar deltas.
-e login
Especificar un nombre de login, o ID de grupo numérico, que se eliminará de la lista de usuarios permitidos para realizar deltas (cambios) en el archivo SCCS. Especificar un ID de grupo es equivalente a especificar todos los nombres de login comunes a ese ID de grupo. Se pueden utilizar varias opciones -e en una sola línea de comando admin.
-y[comentario]
Insertar el texto del comentario en el archivo SCCS como un comentario para el delta inicial de manera idéntica a la de delta. En la localización POSIX, la omisión de la opción -y dará como resultado la inserción de una línea de comentario predeterminada con el formato:
"fecha y hora de creación %s %s por %s", <fecha>, <hora>, <login>

donde <fecha> se expresa en el formato de la especificación de conversión %y/%m/%d del comando date, <hora> en el formato de la especificación de conversión %T del comando date, y <login> es el nombre de login del usuario que crea el archivo.

-m lista_mr
Insertar la lista de números de solicitud de modificación (MR) en el archivo SCCS como motivo para la creación del delta inicial de manera idéntica a delta. La aplicación deberá asegurarse de que el indicador v esté establecido y que los números MR se validen si el indicador v tiene un valor (el nombre de un programa de validación de números MR). Se mostrará un mensaje de diagnóstico si el indicador v no está establecido o si la validación MR falla.
-h
Verificar la estructura del archivo SCCS y comparar la suma de verificación recién calculada con la suma de verificación almacenada en el archivo SCCS. Si la suma de verificación recién calculada no coincide con la suma de verificación en el archivo SCCS, se mostrará un mensaje de diagnóstico.
-z
Recalcular la suma de verificación del archivo SCCS y almacenarla en la primera línea del archivo SCCS (ver la opción -h anterior). Tenga en cuenta que el uso de esta opción en un archivo realmente dañado puede impedir la detección futura de la corrupción.

OPERANDOS

Se soportarán los siguientes operandos:

archivo
Una ruta de un archivo SCCS existente o un directorio. Si archivo es un directorio, el comando admin se comportará como si cada archivo en el directorio se especificara como un archivo nombrado, excepto que los archivos que no son SCCS (el componente final de la ruta no comienza con s.) y los archivos ilegibles se ignorarán silenciosamente.
newfile
Una ruta de un archivo SCCS que se creará.

Si aparece exactamente un operando archivo o newfile, y es '-', se leerá la entrada estándar; cada línea de la entrada estándar se tomará como el nombre de un archivo SCCS a procesar. Los archivos que no son SCCS y los archivos ilegibles se ignorarán silenciosamente.

STDIN

La entrada estándar será un archivo de texto utilizado solo si se especifica -i sin un argumento de opción o si un operando archivo o newfile se especifica como '-'. Si el primer carácter de cualquier línea de entrada estándar es <SOH> en la localización POSIX, los resultados no están especificados.

ARCHIVOS DE ENTRADA

Los archivos SCCS existentes serán archivos de texto de formato no especificado.

La aplicación deberá asegurarse de que el archivo nombrado por el argumento de opción name de la opción -i sea un archivo de texto; si el primer carácter de cualquier línea de este archivo es <SOH> en la localización POSIX, los resultados no están especificados. Si este archivo contiene más de 99999 líneas, el número de líneas registradas en la cabecera de este archivo será 99999 para este delta.

VARIABLES DE ENTORNO

Las siguientes variables de entorno afectarán la ejecución de admin:

LANG
Proporcionar un valor predeterminado para las variables de internacionalización que no están establecidas o están vacías. (Consultar el volumen de Definiciones Base de POSIX.1‐2017, Sección 8.2, Variables de Internacionalización para conocer la precedencia de las variables de internacionalización utilizadas para determinar los valores de las categorías de localización).
LC_ALL
Si se establece en un valor de cadena no vacío, anulará los valores de todas las demás variables de internacionalización.
LC_CTYPE
Determinar la localización para la interpretación de secuencias de bytes de datos de texto como caracteres (por ejemplo, caracteres de un solo byte frente a caracteres multibyte en argumentos y archivos de entrada).
LC_MESSAGES

Determinar la localización que debe utilizarse para afectar el formato y contenido de los mensajes de diagnóstico escritos en el error estándar y el contenido del comentario predeterminado de -y.
NLSPATH
Determinar la ubicación de los catálogos de mensajes para el procesamiento de LC_MESSAGES.

EVENTOS ASÍNCRONOS

Predeterminado.

STDOUT

No se utiliza.

STDERR

El error estándar se utilizará solo para mensajes de diagnóstico.

ARCHIVOS DE SALIDA

Cualquier archivo SCCS creado será un archivo de texto de formato no especificado. Durante el procesamiento de un archivo, se puede crear y eliminar un archivo z-file de bloqueo, como se describe en get.

DESCRIPCIÓN EXTENDIDA

Ninguna.

ESTADO DE SALIDA

Se devolverán los siguientes valores de salida:

 0
Finalización exitosa.
>0
Ocurrió un error.

CONSECUENCIAS DE LOS ERRORES

Predeterminado.

USO DE LA APLICACIÓN

Se recomienda que los directorios que contienen archivos SCCS sean escribibles solo por el propietario, y que los archivos SCCS en sí mismos sean de solo lectura. El modo de los directorios debe permitir solo al propietario modificar los archivos SCCS contenidos en los directorios. El modo de los archivos SCCS impide cualquier modificación excepto por los comandos SCCS.
