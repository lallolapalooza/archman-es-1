avahi.service(5) Manual de formatos de archivo avahi.service(5)

NOMBRE

avahi.service - Archivo de servicio estático de avahi-daemon

SINOPSIS

/etc/avahi/services/*.service

DESCRIPCIÓN

/etc/avahi/services/*.service son fragmentos XML que contienen datos de servicio DNS-SD estáticos. Cada archivo de servicio puede contener múltiples definiciones de servicio que comparten el mismo nombre. Esto es útil para publicar datos de servicio para servicios que implementan múltiples protocolos (es decir, una impresora que implementa _ipp._tcp y _printer._tcp)

ETIQUETAS XML

<service-group> Etiqueta del documento de los archivos de servicio de avahi. Debe contener un elemento <name> y uno o más elementos <service>.
<name replace-wildcards="yes|no"> El nombre del servicio. Si replace-wildcards es "yes", cualquier ocurrencia de la cadena "%h" será reemplazada por el nombre del host local. Esto se puede utilizar para nombres de servicio como "Terminal Remoto en %h". Si replace-wildcards no se especifica, por defecto es "no".
<service protocol="ipv4|ipv6|any"> Contiene la información del servicio para exactamente un tipo de servicio. Debe contener un elemento <type> y un elemento <port>. Opcionalmente puede contener un <domain-name>, un <host-name>, cualquier número de <subtype> y cualquier número de elementos <txt-record>. El atributo protocol especifica el protocolo en el que se anunciará el servicio. Si se utiliza any (que es el valor predeterminado), el servicio se anunciará tanto en IPv4 como en IPv6.
<type> Contiene el tipo de servicio DNS-SD para este servicio. Ej. "_http._tcp".
<subtype> Contiene un subtipo de servicio DNS-SD adicional para este servicio. Ej. "_anon._sub._ftp._tcp".
<domain-name> El nombre de dominio en el que se debe registrar este servicio. Si se omite, se utiliza el dominio predeterminado del demonio avahi. (probablemente .local)
<host-name> El nombre del host que proporciona este servicio. Debe ser un host que sea resoluble por DNS multicast o unicast. ¡Tenga en cuenta que aquí debe especificar un nombre de dominio completo (FQDN), es decir, .local no se añade implícitamente! El nombre del host no necesita ser parte del dominio especificado en <domain-name>. Consulte avahi.hosts(5) para obtener más información sobre cómo publicar mapeos de nombres de host adicionales.
<port> El número de puerto IP en el que escucha el servicio.
<txt-record value-format="text|binary-hex|binary-base64"> Datos del registro TXT DNS-SD. Si value-format es "text", el valor del registro TXT se toma literalmente. Si value-format es "binary-hex", entonces el valor del registro TXT se decodifica tomando pares de caracteres después del carácter "=" y interpretándolos como la representación textual del número hexadecimal de dos dígitos. Se permiten dígitos hexadecimales tanto en mayúsculas como en minúsculas. El prefijo 0x o 0X no está permitido. Esto requiere que la longitud del valor sea par. Si value-format es "binary-base64", entonces el valor del registro TXT se decodifica con un decodificador base64. El conjunto de caracteres utilizado es A-Za-z0-9+/. Esto requiere que la longitud del valor sea un múltiplo de 4, con "=" como relleno al final. Si value-format no se especifica, por defecto es "text". Ejemplos (todos los valores se decodifican a la cadena "value" sin comillas):

<txt-record>key=value</txt-record>

<txt-record value-format="text">key=value</txt-record>

<txt-record value-format="binary-hex">key=76616c7565</txt-record>

<txt-record value-format="binary-base64">key=dmFsdWU=</txt-record>
