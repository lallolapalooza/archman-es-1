--compress-debug-sections
Comprimir secciones de depuración DWARF usando zlib con SHF_COMPRESSED de la ABI ELF. El archivo objeto resultante puede no ser compatible con enlazadores y utilidades de archivos objeto más antiguos. Tenga en cuenta que si la compresión hiciera una sección dada más grande, entonces no se comprime.
--compress-debug-sections=none
--compress-debug-sections=zlib
--compress-debug-sections=zlib-gnu
--compress-debug-sections=zlib-gabi
--compress-debug-sections=zstd
Estas opciones controlan cómo se comprimen las secciones de depuración DWARF. --compress-debug-sections=none es equivalente a --nocompress-debug-sections. --compress-debug-sections=zlib y --compress-debug-sections=zlib-gabi son equivalentes a --compress-debug-sections. --compress-debug-sections=zlib-gnu comprime secciones de depuración DWARF usando el formato obsoleto zlib-gnu. Las secciones de depuración se renombran para que comiencen con .zdebug. --compress-debug-sections=zstd comprime secciones de depuración DWARF usando zstd. Nota: si la compresión realmente hiciera una sección más grande, entonces no se comprime ni se renombra.
--nocompress-debug-sections
No comprimir secciones de depuración DWARF. Esto es generalmente el valor predeterminado para todos los objetivos excepto x86/x86_64, pero una opción de tiempo de configuración puede usarse para anular esto.
-D
Habilitar depuración en backends específicos del objetivo, si se admite. De lo contrario, se ignora. Incluso si se ignora, esta opción se acepta para compatibilidad de scripts con llamadas a otros ensambladores.
--debug-prefix-map viejo=nuevo
Al ensamblar archivos en el directorio viejo, registrar la información de depuración que los describe como en nuevo en su lugar.
--defsym simbolo=valor
Definir el símbolo simbolo para que sea valor antes de ensamblar el archivo de entrada. valor debe ser una constante entera. Al igual que en C, un prefijo 0x indica un valor hexadecimal y un prefijo 0 indica un valor octal. El valor del símbolo puede ser anulado dentro de un archivo fuente mediante el uso de una pseudo-directiva ".set".
--dump-config
Muestra cómo está configurado el ensamblador y luego sale.
--elf-stt-common=no
--elf-stt-common=yes
Estas opciones controlan si el ensamblador ELF debe generar símbolos comunes con el tipo "STT_COMMON". El valor predeterminado puede controlarse mediante una opción de configuración --enable-elf-stt-common.
--emulation=nombre
Si el ensamblador está configurado para admitir múltiples configuraciones de destino diferentes, esta opción se puede utilizar para seleccionar la forma deseada.
-f
"fast"---omitir el preprocesamiento de espacios en blanco y comentarios (asumir que el código fuente es salida del compilador).
-g
--gen-debug
Generar información de depuración para cada línea de código fuente del ensamblador utilizando el formato de depuración preferido por el objetivo. Actualmente, esto significa STABS, ECOFF o DWARF2. Cuando el formato de depuración es DWARF, una sección ".debug_info" y ".debug_line" solo se emite cuando el archivo de ensamblado no genera una por sí mismo.
--gstabs
Generar información de depuración stabs para cada línea del ensamblador. Esto puede ayudar a depurar código ensamblado, si el depurador puede manejarlo.
--gstabs+
Generar información de depuración stabs para cada línea del ensamblador, con extensiones de GNU que probablemente solo gdb pueda manejar, y que podrían hacer que otros depuradores fallen o se nieguen a leer su programa. Esto puede ayudar a depurar código ensamblado. Actualmente, la única extensión de GNU es la ubicación del directorio de trabajo actual en el momento del ensamblado.
--gdwarf-2
Generar información de depuración DWARF2 para cada línea del ensamblador. Esto puede ayudar a depurar código ensamblado, si el depurador puede manejarlo. Nota: esta opción solo es compatible con algunos objetivos, no con todos.
--gdwarf-3
Esta opción es la misma que la opción --gdwarf-2, excepto que permite la posibilidad de generar información de depuración adicional según la versión 3 de la especificación DWARF. Nota: habilitar esta opción no garantiza la generación de información adicional, la elección de hacerlo es a nivel de cada objetivo.
--gdwarf-4
Esta opción es la misma que la opción --gdwarf-2, excepto que permite la posibilidad de generar información de depuración adicional según la versión 4 de la especificación DWARF. Nota: habilitar esta opción no garantiza la generación de información adicional, la elección de hacerlo es a nivel de cada objetivo.
--gdwarf-5
Esta opción es la misma que la opción --gdwarf-2, excepto que permite la posibilidad de generar información de depuración adicional según la versión 5 de la especificación DWARF. Nota: habilitar esta opción no garantiza la generación de información adicional, la elección de hacerlo es a nivel de cada objetivo.
--gdwarf-sections
En lugar de crear una sección .debug_line, crea una serie de secciones .debug_line.foo donde foo es el nombre de la sección de código correspondiente. Por ejemplo, una sección de código llamada .text.func tendrá su información de línea de depuración colocada en una sección llamada .debug_line.text.func. Si la sección de código se llama simplemente .text, entonces la sección de línea de depuración seguirá llamándose solo .debug_line sin ningún sufijo.
--gdwarf-cie-version=version
Controla qué versión de las Entradas de Información Común DWARF (CIEs) se producen. Cuando esta bandera no se especifica, el valor predeterminado es la versión 1, aunque algunos objetivos pueden modificar este valor predeterminado. Otros valores posibles para version son 3 o 4.
