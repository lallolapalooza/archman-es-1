NOMBRE

avahi-daemon - El demonio mDNS/DNS-SD de Avahi

SINOPSIS

avahi-daemon [opciones]

avahi-daemon --kill

avahi-daemon --reload

avahi-daemon --check

DESCRIPCIÓN

El demonio mDNS/DNS-SD de Avahi implementa la arquitectura Zeroconf de Apple (también conocida como "Rendezvous" o "Bonjour"). El demonio registra las direcciones IP locales y los servicios estáticos utilizando mDNS/DNS-SD y proporciona dos APIs IPC para que los programas locales utilicen la caché de registros mDNS que mantiene avahi-daemon. En primer lugar, está el llamado "protocolo simple" que es utilizado exclusivamente por avahi-dnsconfd (un demonio que configura servidores DNS unicast utilizando información del servidor publicada a través de mDNS) y nss-mdns (un plugin NSS de libc, que proporciona resolución de nombres a través de mDNS). Finalmente, está la interfaz D-Bus que proporciona una rica interfaz orientada a objetos para aplicaciones habilitadas para D-Bus.

Al iniciarse, avahi-daemon interpreta su archivo de configuración /etc/avahi/avahi-daemon.conf y lee fragmentos XML de /etc/avahi/services/*.service que pueden definir servicios DNS-SD estáticos. Si habilita publish-resolv-conf-dns-servers en avahi-daemon.conf, también se leerá el archivo /etc/resolv.conf.

OPCIONES

-f | --file= ARCHIVO
Especifica el archivo de configuración a leer. (por defecto: /etc/avahi/avahi-daemon.conf)
-D | --daemonize
Se ejecuta como demonio después del inicio. Implica --syslog.
-s | --syslog
Registra en syslog en lugar de STDERR. Implicado por --daemonize.
--debug
Aumenta la verbosidad al nivel de depuración.
--no-rlimits
No aplica los límites de recursos especificados en el archivo de configuración. (Ver setrlimit(2) para más información)
--no-drop-root
No suelta los privilegios de root después del inicio y no requiere que el demonio se inicie como root. Recomendamos no usar esta opción.
--no-chroot
No hace chroot(2) al demonio. Esta opción solo está disponible cuando se compila con soporte para chroot().
--no-proc-title
No cambia el nombre del proceso mientras se ejecuta. A menos que se especifique esta opción, avahi-daemon reflejará su estado actual y el nombre de host seleccionado en el título del proceso.
-k | --kill
Detiene un avahi-daemon ya en ejecución. (equivalente a enviar una SIGTERM)
-r | --reload
Indica a un avahi-daemon ya en ejecución que vuelva a leer /etc/resolv.conf (en caso de que haya habilitado publish-resolv-conf-dns-servers en avahi-daemon.conf) y los archivos de /etc/avahi/services/. Tenga en cuenta que esto no recargará /etc/avahi/avahi-daemon.conf. (equivalente a enviar un SIGHUP)
-c | --check
Devuelve 0 como código de retorno cuando avahi-daemon ya se está ejecutando.
-h | --help
Mostrar ayuda
-v | --version
Mostrar información de la versión

ARCHIVOS

/etc/avahi/avahi-daemon.conf: el archivo de configuración predeterminado para avahi-daemon, consulte avahi-daemon.conf(5) para más información.

/etc/avahi/hosts: mapeos de nombres de host estáticos adicionales para publicar en mDNS, consulte avahi.hosts(5) para más información.

/etc/avahi/services/*.service: definiciones de servicios estáticos, consulte avahi.service(5) para más información.

SEÑALES

SIGINT, SIGTERM: avahi-daemon se apagará. (Igual que --kill).

SIGHUP: avahi-daemon recargará los datos del servidor DNS unicast de /etc/resolv.conf y las definiciones de servicios estáticos de /etc/avahi/services/. (Igual que --reload)

SIGUSR1: avahi-daemon volcará los datos de registros de recursos en caché locales y remotos a syslog.
