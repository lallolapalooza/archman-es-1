DLLTOOL(1) Herramientas de desarrollo GNU DLLTOOL(1)

NOMBRE

dlltool - crea archivos necesarios para construir y usar DLLs

SINOPSIS

dlltool [-d|--input-def nombre-archivo-def]
[-b|--base-file nombre-archivo-base]
[-e|--output-exp nombre-archivo-exp]
[-z|--output-def nombre-archivo-def]
[-l|--output-lib nombre-archivo-biblioteca]
[-y|--output-delaylib nombre-archivo-biblioteca]
[--export-all-symbols] [--no-export-all-symbols]
[--exclude-symbols lista]
[--no-default-excludes]
[-S|--as ruta-al-ensamblador] [-f|--as-flags opciones]
[-D|--dllname nombre] [-m|--machine máquina]
[-a|--add-indirect]
[-U|--add-underscore] [--add-stdcall-underscore]
[-k|--kill-at] [-A|--add-stdcall-alias]
[-p|--ext-prefix-alias prefijo]
[-x|--no-idata4] [-c|--no-idata5]
[--use-nul-prefixed-import-tables]
[-I|--identify nombre-archivo-biblioteca] [--identify-strict]
[-i|--interwork]
[-n|--nodelete] [-t|--temp-prefix prefijo]
[-v|--verbose]
[-h|--help] [-V|--version]
[--no-leading-underscore] [--leading-underscore]
[--deterministic-libraries] [--non-deterministic-libraries]
[archivo-objeto ...]

DESCRIPCIÓN

dlltool lee sus entradas, que pueden provenir de las opciones -d y -b, así como de archivos objeto especificados en la línea de comandos. Luego procesa estas entradas y, si se ha especificado la opción -e, crea un archivo de exportaciones. Si se ha especificado la opción -l, crea un archivo de biblioteca, y si se ha especificado la opción -z, crea un archivo def. Cualquiera o todas las opciones -e, -l y -z pueden estar presentes en una invocación de dlltool.

Al crear una DLL, junto con el código fuente de la DLL, es necesario tener otros tres archivos. dlltool puede ayudar con la creación de estos archivos.

El primer archivo es un archivo .def que especifica qué funciones se exportan desde la DLL, qué funciones importa la DLL, y así sucesivamente. Este es un archivo de texto y puede crearse manualmente, o dlltool puede usarse para crearlo con la opción -z. En este caso, dlltool escaneará los archivos objeto especificados en su línea de comandos buscando aquellas funciones que han sido marcadas especialmente como exportadas y colocará entradas para ellas en el archivo .def que crea.

Para marcar una función como exportada desde una DLL, necesita tener una entrada -export:<nombre_de_la_función> en la sección .drectve del archivo objeto. Esto se puede hacer en C usando el operador asm():

asm (".section .drectve");
asm (".ascii \"-export:mi_func\"");

int mi_func (void) { ... }

El segundo archivo necesario para la creación de DLLs es un archivo de exportaciones. Este archivo se enlaza con los archivos objeto que componen el cuerpo de la DLL y maneja la interfaz entre la DLL y el mundo exterior. Este es un archivo binario y puede crearse dando la opción -e a dlltool al crear o leer un archivo .def.

El tercer archivo necesario para la creación de DLLs es el archivo de biblioteca con el que los programas se enlazarán para acceder a las funciones de la DLL (una `biblioteca de importación'). Este archivo puede crearse dando la opción -l a dlltool al crear o leer un archivo .def.

Si se especifica la opción -y, dlltool genera una biblioteca de importación retardada que puede usarse en lugar de la biblioteca de importación normal para permitir que un programa se enlace a la dll solo tan pronto como se llame a una función importada por primera vez. El ejecutable resultante deberá enlazarse a la biblioteca retardada estática que contenga __delayLoadHelper2(), que a su vez importará LoadLibraryA y GetProcAddress de kernel32.

dlltool construye el archivo de biblioteca manualmente, pero construye el archivo de exportaciones creando archivos temporales que contienen declaraciones de ensamblador y luego ensamblando estos. La opción de línea de comandos -S se puede usar para especificar la ruta al ensamblador que usará dlltool, y la opción -f se puede usar para pasar opciones específicas a ese ensamblador. La opción -n se puede usar para evitar que dlltool elimine estos archivos temporales de ensamblador cuando termine, y si se especifica -n dos veces, esto evitará que dlltool elimine los archivos objeto temporales que utilizó para construir la biblioteca.

Aquí hay un ejemplo de creación de una DLL desde un archivo fuente dll.c y también de creación de un programa (desde un archivo objeto llamado program.o) que usa esa DLL:

gcc -c dll.c
dlltool -e exports.o -l dll.lib dll.o
gcc dll.o exports.o -o dll.dll
gcc program.o dll.lib -o program

dlltool también puede usarse para consultar una biblioteca de importación existente y determinar el nombre de la DLL a la que está asociada. Consulte la descripción de la opción -I o --identify.

OPCIONES

Las opciones de línea de comandos tienen los siguientes significados:

-d nombre-archivo
--input-def nombre-archivo
Especifica el nombre de un archivo .def para ser leído y procesado.
-b nombre-archivo
--base-file nombre-archivo
Especifica el nombre de un archivo base para ser leído y procesado. El contenido de este archivo se agregará a la sección de reubicación en el archivo de exportaciones generado por dlltool.
-e nombre-archivo
--output-exp nombre-archivo
Especifica el nombre del archivo de exportaciones que será creado por dlltool.
-z nombre-archivo
--output-def nombre-archivo
Especifica el nombre del archivo .def que será creado por dlltool.
-l nombre-archivo
--output-lib nombre-archivo
Especifica el nombre del archivo de biblioteca que será creado por dlltool.
-y nombre-archivo
--output-delaylib nombre-archivo
Especifica el nombre del archivo de biblioteca de importación retardada que será creado por dlltool.
--deterministic-libraries
--non-deterministic-libraries
Al crear bibliotecas de salida en respuesta a las opciones --output-lib o --output-delaylib, use el valor cero para cualquier marca de tiempo, ID de usuario y ID de grupo creados (--deterministic-libraries) o las marcas de tiempo, ID de usuario y ID de grupo reales (--non-deterministic-libraries).
--export-all-symbols
Trata todos los símbolos definidos globales y débiles encontrados en los archivos objeto de entrada como símbolos a exportar. Hay una pequeña lista de símbolos que no se exportan por defecto; consulte la opción --no-default-excludes. Puede agregar a la lista de símbolos a no exportar usando la opción --exclude-symbols.
--no-export-all-symbols
Exporta solo los símbolos listados explícitamente en un archivo .def de entrada o en secciones .drectve en los archivos objeto de entrada. Este es el comportamiento por defecto. Las secciones .drectve son creadas por los atributos dllexport en el código fuente.
--exclude-symbols lista
No exporte los símbolos en lista. Esta es una lista de nombres de símbolos separados por comas o dos puntos. Los nombres de los símbolos no deben contener un guión bajo inicial. Esto solo tiene sentido cuando se usa --export-all-symbols.
--no-defa

NAME

dlltool - create a DLL import library

SYNOPSIS

dlltool [-] [-options] [-file]

DESCRIPTION

dlltool is used to create an import library file for a DLL (Dynamic Link Library). This library file can then be used by the linker when linking an executable that uses the DLL, allowing the executable to call functions residing in the DLL.

dlltool can also be used to create a DLL file itself, using an object file which has been compiled with the appropriate flags (e.g., Microsoft Windows DLL export directives). It operates by creating an export file, which is then assembled into an object file, which is then linked to produce the final DLL.

The primary use of dlltool is to create GNU-style import libraries for Windows DLLs. These libraries allow the GNU toolchain (e.g., GCC) to link executables against existing Windows DLLs.

dlltool can create import libraries in two formats: PE (Portable Executable) format, which is standard for Windows PE DLLs, and coff (Common Object File Format), which is standard for Unix systems. The format is determined by the options given; if neither is specified, PE is assumed.

OPTIONS

-
See --help.
--export-all-symbols
When creating a DLL, this option tells dlltool to export all symbols from the object file. By default, only symbols exported via the DLL's definition file (e.g. using __declspec(dllexport) in C/C++ code) or through an explicit exports file are exported.
--no-default-excludes
When --export-all-symbols is used, it will by default avoid exporting certain special symbols. The current list of symbols to avoid exporting is DllMain@12, DllEntryPoint@0, impure_ptr. You may use the --no-default-excludes option to go ahead and export these special symbols. This is only meaningful when --export-all-symbols is used.
-S path
--as path
Specifies the path, including the filename, of the assembler to be used to create the exports file.
-f options
--as-flags options
Specifies any specific command-line options to be passed to the assembler when building the exports file. This option will work even if the -S option is not used. This option only takes one argument, and if it occurs more than once on the command line, then later occurrences will override earlier occurrences. So if it is necessary to pass multiple options to the assembler they should be enclosed in double quotes.
-D name
--dll-name name
Specifies the name to be stored in the .def file as the name of the DLL when the -e option is used. If this option is not present, then the filename given to the -e option will be used as the name of the DLL.
-m machine
-machine machine
Specifies the type of machine for which the library file should be built. dlltool has a built in default type, depending upon how it was created, but this option can be used to override that. This is normally only useful when creating DLLs for an ARM processor, when the contents of the DLL are actually encode using Thumb instructions.
-a
--add-indirect
Specifies that when dlltool is creating the exports file it should add a section which allows the exported functions to be referenced without using the import library. Whatever the hell that means!
-U
--add-underscore
Specifies that when dlltool is creating the exports file it should prepend an underscore to the names of all exported symbols.
--no-leading-underscore
--leading-underscore
Specifies whether standard symbol should be forced to be prefixed, or not.
--add-stdcall-underscore
Specifies that when dlltool is creating the exports file it should prepend an underscore to the names of exported stdcall functions. Variable names and non-stdcall function names are not modified. This option is useful when creating GNU-compatible import libs for third party DLLs that were built with MS-Windows tools.
-k
--kill-at
Specifies that @<number> suffixes should be omitted from the names of stdcall functions that will be imported from the DLL. This is useful when creating an import library for a DLL which exports stdcall functions but without the usual @<number> symbol name suffix.

This does not change the naming of symbols provided by the import library to programs linked against it, but only the entries in the import table (ie the .idata section).

-A
--add-stdcall-alias
Specifies that when dlltool is creating the exports file it should add aliases for stdcall symbols without @ <number> in addition to the symbols with @ <number>.
-p
--ext-prefix-alias prefix
Causes dlltool to create external aliases for all DLL imports with the specified prefix. The aliases are created for both external and import symbols with no leading underscore.
-x
--no-idata4
Specifies that when dlltool is creating the exports and library files it should omit the ".idata4" section. This is for compatibility with certain operating systems.
--use-nul-prefixed-import-tables
Specifies that when dlltool is creating the exports and library files it should prefix the ".idata4" and ".idata5" by zero an element. This emulates old gnu import library generation of "dlltool". By default this option is turned off.
-c
--no-idata5
Specifies that when dlltool is creating the exports and library files it should omit the ".idata5" section. This is for compatibility with certain operating systems.
-I filename
--identify filename
Specifies that dlltool should inspect the import library indicated by filename and report, on "stdout", the name(s) of the associated DLL(s). This can be performed in addition to any other operations indicated by the other options and arguments. dlltool fails if the import library does not exist or is not actually an import library. See also --identify-strict.
--identify-strict
Modifies the behavior of the --identify option, such that an error is reported if filename is associated with more than one DLL.
-i
--interwork
Specifies that dlltool should mark the objects in the library file and exports file that it produces as supporting interworking between ARM and Thumb code.
-n
--nodelete
Makes dlltool preserve the temporary assembler files it used to create the exports file. If this option is repeated then dlltool will also preserve the temporary object files it uses to create the library file.
-t prefix
--temp-prefix prefix
Makes dlltool use prefix when constructing the names of temporary assembler and object files. By default, the temp file prefix is generated from the pid.
-v
--verbose
Make dlltool describe what it is doing.
-h
--help
Displays a list of command-line options and then exits.
-V
--version
Displays dlltool's version number and then exits.
@file
Read command-line options from file. The options read are inserted in place of the original @file option. If file does not exist, or cannot be read, then the option will be treated literally, and not removed.

Options in file are separated by whitespace. A whitespace character may be included in an option by surrounding the entire option in either single or double quotes. Any character (including a backslash) may be included by prefixing the character to be included with a backslash. The file may itself contain additional @file options; any such options will be processed recursively.
