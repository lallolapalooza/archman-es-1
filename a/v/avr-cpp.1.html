DESCRIPCIÓ

N

El preprocesador de C, a menudo conocido como cpp, es un procesador de macros que es utilizado automáticamente por el compilador de C para transformar su programa antes de la compilación. Se llama procesador de macros porque le permite definir macros, que son abreviaturas breves para construcciones más

largas.

El preprocesador de C está destinado a usarse solo con código fuente de C, C++ y Objective-C. En el pasado, se ha abusado de él como un procesador de texto general. Fallará con entradas que no obedezcan las reglas léxicas de C. Por ejemplo, las comillas simples se interpretarán como el inicio de constantes de carácter y causarán errores. Además, no puede confiar en que preserve características de la entrada que no son significativas para las familias de lenguajes C. Si se preprocesa un Makefile, todas las pestañas duras serán eliminadas y el Makefile no

funcionará.

Dicho esto, a menudo puede salirse con la suya usando cpp en cosas que no son C. Otros lenguajes de programación tipo Algol suelen ser seguros (Ada, etc.). Lo mismo ocurre con el ensamblador, con precaución. El modo -traditional-cpp preserva más espacio en blanco y es de otro modo más permisivo. Muchos de los problemas pueden evitarse escribiendo comentarios de estilo C o C++ en lugar de comentarios del lenguaje nativo, y manteniendo las macros

simples.

Siempre que sea posible, debe usar un preprocesador orientado al lenguaje en el que está escribiendo. Las versiones modernas del ensamblador GNU tienen instalaciones de macros. La mayoría de los lenguajes de programación de alto nivel tienen su propio mecanismo de compilación condicional e inclusión. Si todo lo demás falla, intente con un procesador de texto general verdadero, como GNU

M4.

Los preprocesadores de C varían en algunos detalles. Este manual discute el preprocesador de C GNU, que proporciona un pequeño subconjunto de las características del Estándar C ISO. En su modo predeterminado, el preprocesador de C GNU no hace algunas cosas requeridas por el estándar. Estas son características que rara vez, si acaso, se usan, y pueden causar cambios sorprendentes en el significado de un programa que no las espera. Para obtener el Estándar C ISO estricto, debe usar las opciones -std=c90, -std=c99, -std=c11 o -std=c17, dependiendo de qué versión del estándar desee. Para obtener todos los diagnósticos obligatorios, también debe usar -pedantic

.

Este manual describe el comportamiento del preprocesador ISO. Para minimizar diferencias gratuitas, donde el comportamiento del preprocesador ISO no entra en conflicto con la semántica tradicional, el preprocesador tradicional debe comportarse de la misma manera. Las diversas diferencias que existen se detallan en la sección Modo Tradicional .

Para mayor claridad, a menos que se indique lo contrario, las referencias a CPP en este manual

se refieren
a GNU CPP.

OPCIONE

S

El comando cpp espera dos nombres de archivo como argumentos, infile y outfile. El preprocesador lee infile junto con cualquier otro archivo que especifique con #include. Todo el output generado por los archivos de entrada combinados se escribe en outfile

.

Tanto infile como outfile pueden ser -, el cual como infile significa leer de la entrada estándar y como outfile significa escribir en la salida estándar. Si se omite cualquiera de los archivos, significa lo mismo que si se hubiera especificado - para ese archivo. También puede usar la opción -o outfile para especificar el archivo de

salida.

A menos que se indique lo contrario, o la opción termine en =, todas las opciones que toman un argumento pueden tener ese argumento aparecer inmediatamente después de la opción, o con un espacio entre la opción y el argumento: -Ifoo y -I foo tienen el mismo

efecto.

Muchas opciones tienen nombres de múltiples letras; por lo tanto, múltiples opciones de una sola letra pueden no ser agrupadas: -dM es muy diferente de -d -

En lugar de emitir el resultado del preprocesamiento, emite una regla adecuada para make describiendo las dependencias del archivo fuente principal. El preprocesador emite una regla make que contiene el nombre del archivo objeto para ese archivo fuente, dos puntos, y los nombres de todos los archivos incluidos, incluyendo aquellos provenientes de las opciones de línea de comandos -include o -imacros.

comandos.

La salida de depuración aún se envía al flujo de salida regular.

-M
Like -E but the output contains only preprocessor directives for generating a dependency file. This means that the driver runs the preprocessor and creates rules to let make know when to recompile files.

When used with the driver options -MD or -MMD, -M is not implied. The dependency rules are printed to stdout.

The driver runs the preprocessor on the given input files and prints the rules to standard output. The preprocessor outputs a dependency file. If you use -o, then the driver will write the dependency rules to the specified file instead of standard output. Without -o, the driver writes the dependency rules to standard output.

-M implies -E and suppresses warnings with an implicit -w.

-MM
Like -M but do not mention header files that are found in system header directories, nor header files that are included, directly or indirectly, from such a header.

This implies that the choice of angle brackets or double quotes in an #include directive does not in itself determine whether that header appears in -MM dependency output.

-MF file
When used with -M or -MM, specifies a file to write the dependencies to. If no -MF switch is given the preprocessor sends the rules to the same place it would send preprocessed output.

When used with the driver options -MD or -MMD, -MF overrides the default dependency output file.

If file is -, then the dependencies are written to stdout.

-MG
In conjunction with an option such as -M requesting dependency generation, -MG assumes missing header files are generated files and adds them to the dependency list without raising an error. The dependency filename is taken directly from the "#include" directive without prepending any path. -MG also suppresses preprocessed output, as a missing header file renders this useless.

This feature is used in automatic updating of makefiles.

-Mno-modules
Disable dependency generation for compiled module interfaces.
-MP
This option instructs CPP to add a phony target for each dependency other than the main file, causing each to depend on nothing. These dummy rules work around errors make gives if you remove header files without updating the Makefile to match.

This is typical output:

test.o: test.c test.h

test.h:
-MT target
Change the target of the rule emitted by dependency generation. By default CPP takes the name of the main input file, deletes any directory components and any file suffix such as .c, and appends the platform's usual object suffix. The result is the target.

An -MT option sets the target to be exactly the string you specify. If you want multiple targets, you can specify them as a single argument to -MT, or use multiple -MT options.

For example, -MT '$(objpfx)foo.o' might give

$(objpfx)foo.o: foo.c
-MQ target
Same as -MT, but it quotes any characters which are special to Make. -MQ '$(objpfx)foo.o' gives 
$$(objpfx)foo.o: foo.c

The default target is automatically quoted, as if it were given with -MQ.

-MD
-MD is equivalent to -M -MF file, except that -E is not implied. The driver determines file based on whether an -o option is given. If it is, the driver uses its argument but with a suffix of .d, otherwise it takes the name of the input file, removes any directory components and suffix, and applies a .d suffix.

If -MD is used in conjunction with -E, any -o switch is understood to specify the dependency output file, but if used without -E, each -o is understood to specify a target object file.

Since -E is not implied, -MD can be used to generate a dependency output file as a side effect of the compilation process.

-MMD
Like -MD except mention only user header files, not system header files.
-fpreprocessed
Indicate to the preprocessor that the input file has already been preprocessed. This suppresses things like macro expansion, trigraph conversion, escaped newline splicing, and processing of most directives. The preprocessor still recognizes and removes comments, so that you can pass a file preprocessed with -C to the compiler without problems. In this mode the integrated preprocessor is little more than a tokenizer for the front ends.

-fpreprocessed is implicit if the input file has one of the extensions .i, .ii or .mi. These are the extensions that GCC uses for preprocessed files created by -save-temps.

-fdirectives-only
When preprocessing, handle directives, but do not expand macros.

The option's behavior depends on the -E and -fpreprocessed options.

With -E, preprocessing is limited to the handling of directives such as "#define", "#ifdef", and "#error". Other preprocessor operations, such as macro expansion and trigraph conversion are not performed. In addition, the -dD option is implicitly enabled.

With -fpreprocessed, predefinition of command line and most builtin macros is disabled. Macros such as "__LINE__", which are contextually dependent, are handled normally. This enables compilation of files previously preprocessed with "-E -fdirectives-only".

With both -E and -fpreprocessed, the rules for -fpreprocessed take precedence. This enables full preprocessing of files previously preprocessed with "-E -fdirectives-only".

-fdollars-in-identifiers
Accept $ in identifiers.
-fextended-identifiers
Accept universal character names and extended characters in identifiers. This option is enabled by default for C99 (and later C standard versions) and C++.
-fno-canonical-system-headers
When preprocessing, do not shorten system header paths with canonicalization.
-fmax-include-depth=depth
Set the maximum depth of the nested #include. The default is 200.
-fsearch-include-path[=kind]
Look for input files on the #include path, not just the current directory. This is particularly useful with C++20 modules, for which both header units and module interface units need to be compiled directly: 
g++ -c -std=c++20 -fmodules -fsearch-include-path bits/stdc++.h bits/std.cc

kind defaults to user, which looks on the "#include "..."" search path; you can also explicitly specify system for the "#include <...>" search path.

-ftabstop=width
Set the distance between tab stops. This helps the preprocessor report correct column numbers in warnings or errors, even if tabs appear on the line. If the value is less than 1 or greater than 100, the option is ignored. The default is 8.
-ftrack-macro-expansion[=level]
Track locations of tokens across macro expansions. This allows the compiler to emit diagnostic about the current macro expansion stack when a compilation error occurs in a macro expansion. Using this option makes the preprocessor and the compiler consume more memory. The level parameter can be used to choose the level of precision of token location tracking thus decreasing the memory consumption if necessary. Value 0 of level de-activates this option. Value 1 tracks tokens locations in a degraded mode for the sake of minimal memory overhead. In this mode all tokens resulting from the expansion of an argument of a function-like macro have the same location. Value 2 tracks tokens locations completely. This value is the most memory hungry. When this option is given no argument, the default parameter value is 2.

Note that "-ftrack-macro-expansion=2" is activated by default.

-fmacro-prefix-map=old=new
When preprocessing files residing in directory old, expand the "__FILE__" and "__BASE_FILE__" macros as if the files resided in directory new instead. This can be used to change an absolute path to a relative path by using . for new which can result in more reproducible builds that are location independent. This option also affects "__builtin_FILE()" during compilation. See also -ffile-prefix-map and -fcanon-prefix-map.
-fexec-charset=charset
Set the execution character set, used for string and character constants. The default is UTF-8. charset can be any encoding supported by the system's "iconv" library routine.
-fwide-exec-charset=charset
Set the wide execution character set, used for wide string and character constants. The default is one of UTF-32BE, UTF-32LE, UTF-16BE, or UTF-16LE, whichever corresponds to the width of "wchar_t" and the big-endian or little-endian byte order being used for code generation. As with -fexec-charset, charset can be any encoding supported by the system's "iconv" library routine; however, you will have problems with encodings that do not fit exactly in "wchar_t".
-finput-charset=charset
Set the input character set, used for translation from the character set of the input file to the source character set used by G
CC. Si la configuración regional no especifica, o GCC no puede obtener esta información de la configuración regional, el valor predeterminado es UTF-8. Esto puede ser anulado por la configuración regional o esta opción de línea de comandos. Actualmente, la opción de línea de comandos tiene prioridad si hay un conflicto. charset puede ser cualquier codificación compatible con la rutina de la biblioteca "iconv" del sistema.
-fworking-directory
Habilita la generación de marcadores de línea en la salida del preprocesador que permiten al compilador conocer el directorio de trabajo actual en el momento del preprocesamiento. Cuando esta opción está habilitada, el preprocesador emite, después del marcador de línea inicial, un segundo marcador de línea con el directorio de trabajo actual seguido de dos barras. GCC utiliza este directorio, cuando está presente en la entrada preprocesada, como el directorio emitido como directorio de trabajo actual en algunos formatos de información de depuración. Esta opción se habilita implícitamente si la información de depuración está habilitada, pero esto puede ser inhibido con la forma negada -fno-working-directory. Si el indicador -P está presente en la línea de comandos, esta opción no tiene efecto, ya que no se emite ninguna directiva "#line" en absoluto.
-A predicate=answer
Realiza una aserción con el predicado predicate y la respuesta answer. Esta forma es preferible a la forma antigua -A predicate(answer), que todavía se admite, ya que no utiliza caracteres especiales del shell.
-A -predicate=answer
Cancela una aserción con el predicado predicate y la respuesta answer.
-C
No descarta comentarios. Todos los comentarios se pasan al archivo de salida, excepto los comentarios en directivas procesadas, que se eliminan junto con la directiva.

Debe estar preparado para efectos secundarios al usar -C; hace que el preprocesador trate los comentarios como tokens por derecho propio. Por ejemplo, los comentarios que aparecen al principio de lo que sería una línea de directiva tienen el efecto de convertir esa línea en una línea de código fuente ordinaria, ya que el primer token de la línea ya no es un #.

-CC
No descarta comentarios, ni siquiera durante la expansión de macros. Esto es como -C, excepto que los comentarios contenidos dentro de macros también se pasan al archivo de salida donde se expande la macro.

Además de los efectos secundarios de la opción -C, la opción -CC hace que todos los comentarios de estilo C++ dentro de una macro se conviertan en comentarios de estilo C. Esto es para evitar que el uso posterior de esa macro comente inadvertidamente el resto de la línea de código fuente.

La opción -CC generalmente se usa para admitir comentarios de lint.

-P
Inhibe la generación de marcadores de línea en la salida del preprocesador. Esto puede ser útil al ejecutar el preprocesador en algo que no sea código C, y se enviará a un programa que podría confundirse con los marcadores de línea.
-traditional
-traditional-cpp
Intenta imitar el comportamiento de los preprocesadores C pre-estándar, en lugar de los preprocesadores C ISO.

Tenga en cuenta que GCC no intenta emular un compilador C pre-estándar de otra manera, y estas opciones solo se admiten con el modificador -E, o al invocar CPP explícitamente.

-trigraphs
Admite trigrafos C ISO. Estas son secuencias de tres caracteres, todas comenzando con ??, que están definidas por C ISO para representar caracteres individuales. Por ejemplo, ??/ representa \, por lo que '??/n' es una constante de carácter para un salto de línea.

Por defecto, GCC ignora los trigrafos, pero en modos que cumplen con los estándares los convierte. Consulte las opciones -std y -ansi.

-remap
Habilita código especial para solucionar problemas en sistemas de archivos que solo permiten nombres de archivo muy cortos, como MS-DOS.
-H
Imprime el nombre de cada archivo de cabecera utilizado, además de otras actividades normales. Cada nombre está indentado para mostrar cuán profundo está en la pila de #include. También se imprimen los archivos de cabecera precompilados, incluso si se encuentran inválidos; un archivo de cabecera precompilado inválido se imprime con ...x y uno válido con ...! .
-dletters
Indica que se realicen volcados de depuración durante la compilación según lo especificado por letters. Las banderas documentadas aquí son las relevantes para el preprocesador. Otras letters son interpretadas por el compilador propiamente dicho, o reservadas para versiones futuras de GCC, y por lo tanto se ignoran silenciosamente. Si especifica letters cuyo comportamiento entra en conflicto, el resultado no está definido.
-dM
En lugar de la salida normal, genera una lista de directivas #define para todas las macros definidas durante la ejecución del preprocesador, incluidas las macros predefinidas. Esto le da una forma de averiguar qué está predefinido en su versión del preprocesador. Suponiendo que no tiene el archivo foo.h, el comando 
touch foo.h; cpp -dM foo.h

muestra todas las macros predefinidas.

-dD
Similar a -dM excepto que emite *ambas* directivas #define y el resultado del preprocesamiento. Ambos tipos de salida van al archivo de salida estándar.
-dN
Similar a -dD, pero emite solo los nombres de las macros, no sus expansiones.
-dI
Emite directivas #include además del resultado del preprocesamiento.
-dU
Similar a -dD excepto que solo se emiten las macros que se expanden, o cuya definición se prueba en directivas del preprocesador; la salida se retrasa hasta el uso o la prueba de la macro; y también se emiten directivas #undef para las macros probadas pero no definidas en ese momento.
-fdebug-cpp
Esta opción solo es útil para depurar GCC. Cuando se usa desde CPP o con -E, vuelca información de depuración sobre mapas de ubicación. Cada token en la salida va precedido por el volcado del mapa al que pertenece su ubicación.

Cuando se usa desde GCC sin -E, esta opción no tiene efecto.

-I dir
-iquote dir
-isystem dir
-idirafter dir
Agrega el directorio dir a la lista de directorios que se buscarán para archivos de cabecera durante el preprocesamiento.

Si dir comienza con = o $SYSROOT, entonces el = o $SYSROOT se reemplaza por el prefijo sysroot; consulte --sysroot y -isysroot.

Los directorios especificados con -iquote se aplican solo a la forma de comillas de la directiva, "#include "file"". Los directorios especificados con -I, -isystem, o -idirafter se aplican a la búsqueda tanto para "#include "file"" como para "#include <file>" directivas.

Puede especificar cualquier número o combinación de estas opciones en la línea de comandos para buscar archivos de cabecera en varios directorios. El orden de búsqueda es el siguiente:

1.
Para la forma de comillas de la directiva de inclusión, primero se busca el directorio del archivo actual.
2.
Para la forma de comillas de la directiva de inclusión, se buscan los directorios especificados con las opciones -iquote en orden de izquierda a derecha, según aparecen en la línea de comandos.
3.
Los directorios especificados con opciones -I se escanean en orden de izquierda a derecha.
4.
Los directorios especificados con opciones -isystem se escanean en orden de izquierda a derecha.
5.
Se escanean los directorios de sistema estándar.
6.
Los directorios especificados con opciones -idirafter se escanean en orden de izquierda a derecha.

Puede usar -I para anular un archivo de cabecera del sistema, sustituyendo su propia versión, ya que estos directorios se buscan antes que los directorios de archivos de cabecera del sistema estándar. Sin embargo, no debe usar esta opción para agregar directorios que contengan archivos de cabecera del sistema suministrados por el proveedor; use -isystem para eso.

Las opciones -isystem y -idirafter también marcan el directorio como un directorio del sistema, de modo que reciba el mismo tratamiento especial que se aplica a los directorios del sistema estándar.

Si un directorio de inclusión del sistema estándar, o un directorio especificado con -isystem, también se especifica con -I, la opción -I se ignora. El directorio todavía se busca, pero como directorio del sistema en su posición normal en la cadena de inclusión del sistema. Esto es para garantizar que el procedimiento de GCC para corregir archivos de cabecera defectuosos y el orden de las directivas "#include_next" no se cambien inadvertidamente. Si realmente necesita cambiar el orden de búsqueda de los directorios del sistema, use las opciones -nostdinc y/o -isystem.
