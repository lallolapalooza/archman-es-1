DESCRIPCIÓ

N

La utilidad GNU objcopy copia el contenido de un archivo de objetos a otro. objcopy usa la Biblioteca BFD de GNU para leer y escribir los archivos de objetos. Puede escribir el archivo de objetos de destino en un formato diferente al del archivo de objetos de origen. El comportamiento exacto de objcopy está controlado por las opciones de la línea de comandos. Tenga en cuenta que objcopy debería poder copiar un archivo completamente enlazado entre dos formatos cualesquiera. Sin embargo, copiar un archivo de objetos reubicable entre dos formatos cualesquiera puede no funcionar como se

espera.

objcopy crea archivos temporales para realizar sus traducciones y los elimina después. objcopy usa BFD para hacer todo su trabajo de traducción; tiene acceso a todos los formatos descritos en BFD y por lo tanto es capaz de reconocer la mayoría de los formatos sin que se le indique

explícitamente.

objcopy se puede usar para generar registros S utilizando un destino de salida de srec (por ejemplo, use -O sre

c).

objcopy se puede usar para generar un archivo binario sin procesar utilizando un destino de salida de binary (por ejemplo, use -O binary). Cuando objcopy genera un archivo binario sin procesar, producirá esencialmente un volcado de memoria del contenido del archivo de objetos de entrada. Todos los símbolos y la información de reubicación serán descartados. El volcado de memoria comenzará en la dirección de carga de la sección más baja copiada en el archivo de

salida.

Al generar un registro S o un archivo binario sin procesar, puede ser útil usar -S para eliminar secciones que contienen información de depuración. En algunos casos -R será útil para eliminar secciones que contienen información que no es necesaria para el archivo

binario.

Nota---objcopy no es capaz de cambiar la codificación de orden de bytes (endianness) de sus archivos de entrada. Si el formato de entrada tiene una codificación de orden de bytes (algunos formatos no la tienen), objcopy solo puede copiar las entradas en formatos de archivo que tengan la misma codificación de orden de bytes o que no tengan ninguna (por ejemplo, srec). (Sin embargo, consulte la opción --revers

e-byt

--keep-section-symbols

--only-keep-debug
Depura un archivo, eliminando los contenidos de cualquier sección que no sería eliminada por --strip-debug y dejando intactas las secciones de depuración. En archivos ELF, esto preserva todas las secciones de notas en la salida.

Nota: las cabeceras de sección de las secciones depuradas se preservan, incluyendo sus tamaños, pero los contenidos de la sección se descartan. Las cabeceras de sección se preservan para que otras herramientas puedan correlacionar el archivo de información de depuración con el ejecutable real, incluso si ese ejecutable ha sido reubicado a un espacio de direcciones diferente.

La intención es que esta opción se use en conjunción con --add-gnu-debuglink para crear un ejecutable de dos partes. Uno, un binario depurado que ocupará menos espacio en RAM y en una distribución, y el segundo, un archivo de información de depuración que solo se necesita si se requieren capacidades de depuración. El procedimiento sugerido para crear estos archivos es el siguiente:

1.<Enlaza el ejecutable como normal. Asumiendo que se llama>
"foo" entonces...
1.<Ejecuta "objcopy --only-keep-debug foo foo.dbg" para>
crear un archivo que contenga la información de depuración.
1.<Ejecuta "objcopy --strip-debug foo" para crear un>
ejecutable depurado.
1.<Ejecuta "objcopy --add-gnu-debuglink=foo.dbg foo">
para añadir un enlace a la información de depuración en el ejecutable depurado.

Nota: la elección de ".dbg" como extensión para el archivo de información de depuración es arbitraria. También el paso "--only-keep-debug" es opcional. Podrías hacer esto en su lugar:

1.<Enlaza el ejecutable como normal.>
1.<Copia "foo" a "foo.full">
1.<Ejecuta "objcopy --strip-debug foo">
1.<Ejecuta "objcopy --add-gnu-debuglink=foo.full foo">

es decir, el archivo apuntado por --add-gnu-debuglink puede ser el ejecutable completo. No tiene que ser un archivo creado por el switch --only-keep-debug.

Nota: este switch solo está destinado a ser utilizado en archivos completamente enlazados. No tiene sentido usarlo en archivos objeto donde la información de depuración puede ser incompleta. Además, la característica gnu_debuglink actualmente solo admite la presencia de un nombre de archivo que contiene información de depuración, no múltiples nombres de archivo en una base de uno por archivo objeto.
