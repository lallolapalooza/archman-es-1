aa_getcon(2)

Paquete: apparmor

Licencias: GPL-2.0-only, LGPL-2.0-only, LGPL-2.1-only

AA_GETCON(2) AppArmor AA_GETCON(2)

NOMBRE

aa_getprocattr_raw, aa_getprocattr - leer y analizar datos de procattr

aa_getcon, aa_gettaskcon - obtener información de confinamiento de tareas

aa_getpeercon - obtener el confinamiento del otro extremo de un socket (par)

SINOPSIS

#include <sys/apparmor.h>

int aa_getprocattr_raw(pid_t tid, const char *attr, char *buf, int len, char **mode);

int aa_getprocattr(pid_t tid, const char *attr, char **label, char **mode);

int aa_gettaskcon(pid_t target, char **label, char **mode);

int aa_getcon(char **label, char **mode);

int aa_getpeercon_raw(int fd, char *buf, int *len, char **mode);

int aa_getpeercon(int fd, char **label, char **mode);

Enlace con -lapparmor al compilar.

DESCRIPCIÓN

La función aa_getcon obtiene el contexto de confinamiento de AppArmor actual para la tarea actual. El contexto de confinamiento consiste en una etiqueta y un modo. La etiqueta suele ser simplemente el nombre del perfil de AppArmor que restringe la tarea, pero puede incluir el espacio de nombres del perfil o, en algunos casos, un conjunto de nombres de perfiles (conocido como pila de perfiles). El modo es una cadena que describe cómo el kernel está aplicando la política definida en el perfil. Los perfiles cargados en modo "enforce" aplicarán la política definida en el perfil, así como informarán de los intentos de violación de la política. Los perfiles en modo "complain" no aplicarán la política, sino que informarán de los intentos de violación de la política.

Algunos ejemplos de cadenas de *label posibles son "unconfined", "/sbin/dhclient" y "Firefox". La cadena puede consistir en cualquier carácter que no sea NUL, pero estará terminada en NUL. La cadena *label debe liberarse usando free().

Las cadenas de *mode posibles son "enforce" y "complain". Además, *mode puede ser NULL cuando *label es "unconfined". La cadena *mode no debe liberarse. Las cadenas *label y *mode provienen de una única asignación de búfer y están separadas por un carácter NUL.

La función aa_gettaskcon es similar a la función aa_getcon, excepto que funcionará para cualquier tarea arbitraria del sistema.

La función aa_getpeercon es similar a la de aa_gettaskcon, excepto que devuelve la información de confinamiento de la tarea en el otro extremo de una conexión de socket.

La función aa_getpeercon_raw es el backend de la función aa_getpeercon y no maneja la asignación de búfer.

La función aa_getprocattr es el backend de las funciones aa_getcon y aa_gettaskcon y maneja la lectura y el análisis de los datos de confinamiento de diferentes archivos attr arbitrarios, y devuelve los resultados procesados en un búfer asignado.

aa_getprocattr_raw() es el backend de la función aa_getprocattr y no maneja la asignación de búfer.

VALOR DE RETORNO

En caso de éxito, se devuelve el tamaño de los datos colocados en el búfer, esto incluye el modo si está presente y cualquier carácter terminador. En caso de error, se devuelve -1 y errno(3) se establecerá apropiadamente.

ERRORES

EINVAL
El módulo del kernel apparmor no está cargado o la comunicación a través de /proc/*/attr/file no se ajustó al protocolo.
ENOMEM
No había suficiente memoria en el kernel.
EACCES
Se denegó el acceso al archivo/tarea especificado.
ENOENT
El archivo/tarea especificado no existe o no es visible.
ERANGE
Los datos de confinamiento son demasiado grandes para caber en el búfer proporcionado.
ENOPROTOOPT
El kernel no admite la opción SO_PEERLABEL en los sockets. Esto ocurre principalmente cuando el kernel carece de soporte de 'mediación fina de unix'. También puede ocurrir en kernels con múltiples LSM apilados donde otro LSM ha reclamado esta interfaz y decide devolver este error, aunque esto es realmente un caso límite.

NOTAS

Si aa_getpeercon_raw devuelve -1 y errno es ERANGE, el valor de *len se puede utilizar para reasignar buf para que sea lo suficientemente grande como para almacenar los datos de confinamiento.

ERRORES CONOCIDOS

Ninguno conocido. Si encuentra alguno, por favor repórtelo en https://gitlab.com/apparmor/apparmor/-/issues.
