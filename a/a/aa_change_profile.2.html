aa_change_profile(2)

Paquete: apparmor

Licencias: GPL-2.0-only, LGPL-2.0-only, LGPL-2.1-only

AA_CHANGE_PROFILE(2) AppArmor AA_CHANGE_PROFILE(2)

NOMBRE

aa_change_profile, aa_change_onexec - cambiar el perfil de una tarea

SINOPSIS

#include <sys/apparmor.h>

int aa_change_profile(const char *profile);

int aa_change_onexec(const char *profile);

Enlazar con -lapparmor al compilar.

DESCRIPCIÓN

Un perfil de AppArmor se aplica a un programa ejecutable; si una parte del programa necesita permisos de acceso diferentes a otras partes, el programa puede "cambiar de perfil" a un perfil diferente. Para cambiar a un nuevo perfil, puede usar la función aa_change_profile() para hacerlo. Pasa un puntero al perfil al que se debe transicionar. Los programas confinados que deseen usar aa_change_profile() necesitan tener reglas que permitan cambiar al perfil nombrado. Consulte apparmor.d(8) para más detalles.

Si un programa desea salir del perfil actual al perfil original, puede usar aa_change_hat(2). De lo contrario, los dos perfiles deben tener reglas que permitan el cambio entre los dos perfiles.

Es posible que los descriptores de archivo abiertos no se corrijan después de una llamada a aa_change_profile(), por lo que el programa llamante debe close(2) los descriptores de archivo abiertos para asegurarse de que no estén disponibles después de llamar a aa_change_profile(). Como aa_change_profile() se usa típicamente justo antes de execve(2), es posible que desee usar open(2) o fcntl(2) con close-on-exec.

La función aa_change_onexec() es similar a la función aa_change_profile(), excepto que especifica que la transición de perfil se llevará a cabo en el próximo exec en lugar de inmediatamente. El cambio de perfil retrasado tiene prioridad sobre cualquier regla de transición de exec dentro del perfil de confinamiento. Retrasar el límite del perfil tiene un par de ventajas: elimina la necesidad de perfiles de transición de marcador de posición y el límite de exec es una capa de seguridad natural donde la memoria potencialmente sensible se elimina del mapeo.

VALOR DE RETORNO

En caso de éxito, se devuelve cero. En caso de error, se devuelve -1 y se establece errno(3) apropiadamente.

ERRORES

EINVAL
El módulo del kernel de apparmor no está cargado, no se especificó ningún perfil ni espacio de nombres, o la comunicación a través del archivo /proc/*/attr/current no se ajustó al protocolo.
ENOMEM
No había suficiente memoria del kernel disponible.
EPERM
La aplicación que llama está confinada por apparmor y el bit no_new_privs está establecido.
EACCES
La tarea no tiene suficientes permisos para cambiar su dominio.
ENOENT
El perfil especificado no existe o no es visible desde el Espacio de Nombres actual.

EJEMPLO

El siguiente ejemplo muestra un uso simple, aunque forzado, de aa_change_profile(); un uso típico de aa_change_profile() será aa_change_profile() justo antes de un execve(2) para que el nuevo proceso hijo esté permanentemente confinado.

#include <stdlib.h>
#include <string.h>
#include <sys/apparmor.h>
#include <sys/types.h>
#include <sys/stat.h>
#include <fcntl.h>
#include <stdio.h>
#include <unistd.h>
int main(int argc, char * argv[])
{
        int fd;
        char buf[10];
        char *execve_args[4];
        printf("Antes de aa_change_profile():\n");
        if ((fd=open("/etc/passwd", O_RDONLY)) < 0) {
               perror("Fallo al abrir /etc/passwd");
               return 1;
        }
        /* Confirmar por nosotros mismos que realmente podemos leer /etc/passwd */
        memset(&buf, 0, 10);
        if (read(fd, &buf, 10) == -1) {
                perror("Fallo al leer /etc/passwd");
                return 1;
        }
        buf[9] = '\0';
        printf("/etc/passwd: %s\n", buf);
        close(fd);
        printf("Después de aa_change_profile():\n");
        /* cambiar el perfil a 'i_cant_be_trusted_anymore', que
         * no debería tener acceso de lectura a /etc/passwd. */
        if (aa_change_profile("i_cant_be_trusted_anymore") < 0) {
            perror("Fallo al cambiar de perfil -- abortando");
            _exit(1);
        }
        /* confirmar que no podemos leer /etc/passwd */
        execve_args[0] = "/usr/bin/head";
        execve_args[1] = "-1";
        execve_args[2] = "/etc/passwd";
        execve_args[3] = NULL;
        execve("/usr/bin/head", execve_args, NULL);
        perror("execve");
        _exit(1);
}

Este ejemplo de código requiere que se cargue un perfil similar al siguiente con apparmor_parser(8):

profile i_cant_be_trusted_anymore {
    /etc/ld.so.cache      mr,
    /lib/ld-*.so*         mrix,
    /lib/libc*.so*        mr,
    /usr/bin/head ix,
}

La salida al ejecutarlo:

$ /tmp/change_p
Antes de aa_change_profile():
/etc/passwd: root:x:0:
Después de aa_change_profile():
/usr/bin/head: no se puede abrir `/etc/passwd' para leer: Permiso denegado
$

Si /tmp/change_p también debe ser confinado, entonces se puede usar el siguiente perfil (además del de 'i_cant_be_trusted_anymore', arriba):

# Confina change_p para poder leer /etc/passwd y aa_change_profile()
# al perfil 'i_cant_be_trusted_anymore'.
/tmp/change_p {
    /etc/ld.so.cache          mr,
    /lib/ld-*.so*             mrix,
    /lib/libc*.so*            mr,
    /etc/passwd               r,
    # Necesario para aa_change_profile()
    /usr/lib/libapparmor*.so* mr,
    /proc/[0-9]*/attr/current w,
    change_profile -> i_cant_be_trusted_anymore,
}

ERRORES

Ninguno conocido. Si encuentra alguno, por favor repórtelo en https://gitlab.com/apparmor/apparmor/-/issues. Tenga en cuenta que usar aa_change_profile(2) sin execve(2) no proporciona barreras de memoria entre diferentes áreas de un programa; si se requiere separación del espacio de direcciones, se deben usar procesos separados.
