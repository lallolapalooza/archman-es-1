-iprefix prefijo
Especifique prefijo como el prefijo para las siguientes opciones -iwithprefix. Si el prefijo representa un directorio, debe incluir el / final.
-iwithprefix dir
-iwithprefixbefore dir
Anexa dir al prefijo especificado previamente con -iprefix, y agrega el directorio resultante a la ruta de búsqueda de inclusión. -iwithprefixbefore lo coloca en el mismo lugar que lo haría -I; -iwithprefix lo coloca donde lo haría -idirafter.
-isysroot dir
Esta opción es como la opción --sysroot, pero se aplica solo a los archivos de encabezado (excepto para los objetivos de Darwin, donde se aplica tanto a los archivos de encabezado como a las bibliotecas). Vea la opción --sysroot para más información.
-imultilib dir
Usa dir como un subdirectorio del directorio que contiene los encabezados C++ específicos del objetivo.
-nostdinc
No busque en los directorios del sistema estándar los archivos de encabezado. Solo se buscarán los directorios especificados explícitamente con las opciones -I, -iquote, -isystem y/o -idirafter (y el directorio del archivo actual, si es apropiado).
-nostdinc++
No busque archivos de encabezado en los directorios estándar específicos de C++, pero siga buscando en los demás directorios estándar. (Esta opción se usa al compilar la biblioteca C++).
--embed-dir=dir
Anexa el directorio dir a la lista de directorios buscados para la directiva de preprocesamiento "#embed" o la macro "__has_embed". No hay directorios predeterminados para "#embed".

Si dir comienza con = o $SYSROOT, entonces el = o $SYSROOT se reemplaza por el prefijo sysroot; vea --sysroot y -isysroot.

-Wcomment
-Wcomments
Advierte cada vez que una secuencia de inicio de comentario /* aparece en un comentario /*, o cada vez que una barra invertida seguida de un salto de línea aparece en un comentario //. Esta advertencia está habilitada por -Wall.
-Wtrigraphs
Advierte si se encuentran trigrafos que puedan cambiar el significado del programa. Los trigrafos dentro de comentarios no generan advertencias, excepto aquellos que formarían saltos de línea escapados.

Esta opción está implícita por -Wall. Si -Wall no se proporciona, esta opción aún está habilitada a menos que los trigrafos estén deshabilitados. Para obtener la conversión de trigrafos sin advertencias, pero sí las otras advertencias de -Wall, use -trigraphs -Wall -Wno-trigraphs.

-Wundef
Advierte si se evalúa un identificador indefinido en una directiva "#if". Dichos identificadores se reemplazan por cero.
-Wexpansion-to-defined
Advierte cada vez que se encuentra defined en la expansión de una macro (incluido el caso en que la macro se expande mediante una directiva #if). Dicho uso no es portátil. Esta advertencia también está habilitada por -Wpedantic y -Wextra.
-Wunused-macros
Advierte sobre macros definidas en el archivo principal que no se usan. Una macro se considera *usada* si se expande o se prueba su existencia al menos una vez. El preprocesador también advierte si la macro no se ha usado en el momento en que se redefine o se anula su definición.

Las macros integradas, las macros definidas en la línea de comandos y las macros definidas en los archivos de inclusión no generan advertencias.

Nota: Si una macro se usa realmente, pero solo se usa en bloques condicionales omitidos, el preprocesador la informa como no usada. Para evitar la advertencia en tal caso, puede mejorar el alcance de la definición de la macro, por ejemplo, moviéndola al primer bloque omitido. Alternativamente, podría proporcionar un uso ficticio con algo como:

#if defined la_macro_que_causa_la_advertencia
#endif
-Wno-endif-labels
No advierte cuando un "#else" o un "#endif" van seguidos de texto. Esto a veces ocurre en programas antiguos con código de la forma 
#if FOO
...
#else FOO
...
#endif FOO

El segundo y tercer "FOO" deberían estar en comentarios. Esta advertencia está activada por defecto.

ENTORNO

Esta sección describe las variables de entorno que afectan cómo opera CPP. Puede usarlas para especificar directorios o prefijos a usar al buscar archivos de encabezado, o para controlar la salida de dependencias.

Tenga en cuenta que también puede especificar lugares para buscar usando opciones como -I, y controlar la salida de dependencias con opciones como -M. Estas tienen precedencia sobre las variables de entorno, que a su vez tienen precedencia sobre la configuración de GCC.

CPATH
C_INCLUDE_PATH
CPLUS_INCLUDE_PATH
OBJC_INCLUDE_PATH
El valor de cada variable es una lista de directorios separados por un carácter especial, muy parecido a PATH, en los que buscar archivos de encabezado. El carácter especial, "PATH_SEPARATOR", depende del objetivo y se determina en el momento de la compilación de GCC. Para objetivos basados en Microsoft Windows es un punto y coma, y para casi todos los demás objetivos es dos puntos.

CPATH especifica una lista de directorios que se buscarán como si se hubieran especificado con -I, pero después de cualquier ruta dada con opciones -I en la línea de comandos. Esta variable de entorno se usa independientemente del idioma que se esté preprocesando.

Las variables de entorno restantes se aplican solo al preprocesar el idioma particular indicado. Cada una especifica una lista de directorios que se buscarán como si se hubieran especificado con -isystem, pero después de cualquier ruta dada con opciones -isystem en la línea de comandos.

En todas estas variables, un elemento vacío instruye al compilador a buscar en su directorio de trabajo actual. Los elementos vacíos pueden aparecer al principio o al final de una ruta. Por ejemplo, si el valor de CPATH es ":/special/include", esto tiene el mismo efecto que -I. -I/special/include.

DEPENDENCIES_OUTPUT
Si esta variable está configurada, su valor especifica cómo generar dependencias para Make basándose en los archivos de encabezado no del sistema procesados por el compilador. Los archivos de encabezado del sistema se ignoran en la salida de dependencias.

El valor de DEPENDENCIES_OUTPUT puede ser solo un nombre de archivo, en cuyo caso las reglas de Make se escriben en ese archivo, adivinando el nombre del objetivo a partir del nombre del archivo fuente. O el valor puede tener el formato archivo objetivo, en cuyo caso las reglas se escriben en el archivo archivo usando objetivo como el nombre del objetivo.

En otras palabras, esta variable de entorno es equivalente a combinar las opciones -MM y -MF, con un interruptor opcional -MT también.

SUNPRO_DEPENDENCIES
Esta variable es la misma que DEPENDENCIES_OUTPUT (ver arriba), excepto que los archivos de encabezado del sistema no se ignoran, por lo que implica -M en lugar de -MM. Sin embargo, la dependencia del archivo de entrada principal se omite.
SOURCE_DATE_EPOCH
Si esta variable está configurada, su valor especifica una marca de tiempo UNIX que se usará en reemplazo de la fecha y hora actuales en las macros "__DATE__" y "__TIME__", para que las marcas de tiempo incrustadas sean reproducibles.

El valor de SOURCE_DATE_EPOCH debe ser una marca de tiempo UNIX, definida como el número de segundos (excluyendo segundos bisiestos) desde el 01 Ene 1970 00:00:00 representada en ASCII; idéntica a la salida de "date +%s" en GNU/Linux y otros sistemas que soportan la extensión %s en el comando "date".

El valor debe ser una marca de tiempo conocida, como la hora de la última modificación de la fuente o paquete, y debe ser establecida por el proceso de compilación.
