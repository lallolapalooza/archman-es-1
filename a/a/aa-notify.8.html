NOMBRE

aa-notify - muestra información sobre mensajes registrados de AppArmor.

SINOPSIS

aa-notify [opción]

DESCRIPCIÓN

aa-notify mostrará un resumen o proporcionará notificaciones de escritorio para los mensajes DENIED de AppArmor.

OPCIONES

aa-notify acepta los siguientes argumentos:

-p, --poll
comprueba los registros de AppArmor y muestra notificaciones de escritorio. Se puede usar con la opción '-s' para mostrar un resumen al inicio.
--display $DISPLAY
establece la variable de entorno DISPLAY a $DISPLAY (puede ser necesario si sudo restablece $DISPLAY)
-f ARCHIVO, --file=ARCHIVO
busca en ARCHIVO mensajes de AppArmor
-l, --since-last
muestra el resumen desde el último inicio de sesión.
-s NUM, --since-days=NUM
muestra el resumen de los últimos NUM días.
-u USUARIO, --user=USUARIO
usuario al que se reducirán los privilegios al ejecutarse con privilegios. Cuando se usa con la opción -p, este debe ser el usuario que recibirá las notificaciones de escritorio. Esto no tiene efecto cuando se ejecuta bajo sudo.
-w NUM, --wait=NUM
espera NUM segundos antes de mostrar notificaciones (para usar con -p)
-v, --verbose
muestra mensajes con resúmenes.
-h, --help
muestra una breve declaración de uso.

CONFIGURACIÓN

La configuración a nivel de sistema para aa-notify se realiza a través de /etc/apparmor/notify.conf:

# Establecer a 'no' para deshabilitar las notificaciones de AppArmor globalmente
show_notifications="yes"
# Perfiles especiales utilizados para eliminar privilegios para binarios sin confinar usando espacios de nombres de usuario. Si no está seguro, déjelo como está.
userns_special_profiles="unconfined,unprivileged_userns"
# Tema para la GUI de aa-notify. Ver https://ttkthemes.readthedocs.io/en/latest/themes.html para temas disponibles.
interface_theme="ubuntu"
# Binarios para los que ignoramos las denegaciones de capacidades relacionadas con userns
ignore_denied_capability="sudo,su"
# OPCIONAL - tipo de operaciones que muestran un aviso emergente.
prompt_filter="userns"
# OPCIONAL - restringir el uso de aa-notify a los usuarios del grupo dado
# (si no se establece, cualquiera que tenga permisos para leer el archivo de registro puede usarlo)
# use_group="admin"
# OPCIONAL - cuerpo del mensaje de notificación personalizado
message_body="Este es un mensaje de notificación personalizado."
# OPCIONAL - pie de página del mensaje de notificación personalizado
message_footer="Para más información visita https://foo.com"
# OPCIONAL - filtrado de notificaciones personalizado
# Los filtros se utilizan para reducir la salida de información solo a aquellas entradas que coincidan con el filtro. Los filtros utilizan la sintaxis de expresiones regulares de Python.
filter.profile="^(foo|bar)$"  # Coincide con el perfil:            Solo muestra notificaciones para los perfiles "foo" o "bar"
filter.operation="^open$"     # Coincide con la operación:          Solo muestra notificaciones para la operación "open"
filter.name="^(?!/usr/lib/)"  # Coincide con el nombre:              Excluye notificaciones para nombres que comienzan con "/usr/lib/"
filter.denied="^r$"           # Coincide con el denied_mask:        Solo muestra notificaciones donde "r", y solo "r", fue denegado
filter.family="^inet$"        # Coincide con la familia de red:     Solo muestra notificaciones para la familia "inet"
filter.socket="stream"        # Coincide con el tipo de socket de red: Solo muestra notificaciones para sockets "stream"

La configuración por usuario se realiza a través de $XDG_CONFIG_HOME/apparmor/notify.conf (o el obsoleto ~/.apparmor/notify.conf si existe):

# establecer a 'yes' para habilitar las notificaciones DENIED de AppArmor
show_notifications="yes"

ERRORES

aa-notify necesita poder leer los archivos de registro que contienen los mensajes DENIED de AppArmor.

Si encuentra algún error adicional, por favor repórtelo en Gitlab en https://gitlab.com/apparmor/apparmor/-/issues.
