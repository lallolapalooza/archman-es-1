-fcheck=ch
Specifica qué comprobaciones de tiempo de ejecución habilitar. El argumento ch es una lista separada por comas de las comprobaciones de la siguiente lista.
all
Habilita todas las comprobaciones.
array-bounds
Comprueba los accesos a arreglos para ver si están dentro de los límites del arreglo. Para los accesos a arreglos multidimensionales, todas las dimensiones se comprueban con esta opción. Esta es la comprobación predeterminada. 
              PROGRAM test
                INTEGER, DIMENSION(10) :: a
                a(11) = 0
              END PROGRAM test
Si se compila sin esta opción, el programa intentará escribir en la memoria más allá de los límites del arreglo a. Si se compila con esta opción, se emitirá un mensaje de error indicando que el acceso al arreglo está fuera de los límites. Si la opción -fcheck=bounds está presente, los accesos a los límites de los arreglos se comprobarán siempre en tiempo de ejecución.

Para comprobar de forma más granular los accesos a arreglos, puede utilizar la opción -fcheck=array-bounds=level. Las comprobaciones de level=1 son la forma predeterminada y más rápida. Las comprobaciones de level=2 son más detalladas y verifican cada acceso a los límites de los arreglos individualmente. Las comprobaciones de level=3 son las más detalladas y también verifican que los accesos a los segmentos de arreglos sean válidos.

bounds
Es lo mismo que array-bounds.
do
Comprueba los límites de los bucles DO.
floating-point
Comprueba las operaciones de punto flotante para detectar infracciones de IEEE 754, como divisiones por cero, la producción de NaN o la subdesbordamiento. Para los desbordamientos y subdesbordamientos de punto flotante, la opción -fno-signaling-nans deshabilita las excepciones de punto flotante. Con -fno-guard-variables o -fno-check=floating-point, la comprobación de punto flotante se desactiva por completo.

La detección de subdesbordamiento de punto flotante puede tener un impacto negativo en el rendimiento, ya que las operaciones que no resultan en subdesbordamiento pueden ser más lentas. Además, el comportamiento de subdesbordamiento puede diferir entre las diferentes arquitecturas de hardware. Si la subdesbordamiento está deshabilitado en la arquitectura de hardware, esta comprobación no tendrá ningún efecto.

format
Comprueba que las cadenas de formato utilizadas con las sentencias READ y WRITE sean válidas.
mem
Realiza comprobaciones de acceso a memoria más exhaustivas. Cuando esta opción está habilitada, se detectan las escrituras en variables no inicializadas y los accesos a memoria no asignada. Esta comprobación se implementa mediante el uso de variables centinela.

Tenga en cuenta que esta comprobación puede ralentizar significativamente el programa y aumentar su uso de memoria.

recursion
Comprueba los procedimientos recursivos para ver si se ha superado la pila de llamadas.
stack
Es lo mismo que recursion.
stream
Comprueba las operaciones de E/S de flujo para ver si están utilizando unidades de archivo abiertas o cerradas de forma incorrecta. Por ejemplo, si intenta leer desde una unidad de archivo que ya está cerrada, o escribir en una unidad de archivo que no se abrió para escritura.
substring
Comprueba los accesos a subcadenas para ver si están dentro de los límites de la cadena. 
              PROGRAM test
                CHARACTER(LEN=10) :: s
                s(1:11) = 'abcdefghij'
              END PROGRAM test
Si se compila sin esta opción, el programa intentará escribir en la memoria más allá de los límites de la cadena s. Si se compila con esta opción, se emitirá un mensaje de error indicando que el acceso a la subcadena está fuera de los límites.
-fcheck=bounds=level
Comprueba los accesos a los límites de los arreglos en tiempo de ejecución. El argumento level puede ser 1, 2 o 3.
1
Comprobación predeterminada y más rápida. Se comprueban todos los accesos a arreglos, pero no se rastrean los accesos individuales a las dimensiones de los arreglos multidimensionales.
2
Comprobación más detallada. Cada acceso a los límites de los arreglos se verifica individualmente, lo que proporciona más información en caso de error.
3
Comprobación más detallada. Además de las comprobaciones del nivel 2, se verifica la validez de los accesos a los segmentos de los arreglos (por ejemplo, a(1:5:2)).
-fcheck=floating-point=level
Controla el nivel de comprobación de las operaciones de punto flotante. El argumento level puede ser 0, 1 o 2.
0
Las comprobaciones de punto flotante están deshabilitadas.
1
Se comprueban las operaciones de punto flotante para detectar infracciones de IEEE 754, como divisiones por cero, la producción de NaN o el subdesbordamiento. Esta es la comprobación predeterminada.
2
Además de las comprobaciones del nivel 1, se rastrean las excepciones de punto flotante, lo que puede ser útil para depurar problemas de rendimiento o comportamiento inesperado de los cálculos de punto flotante.
-fcheck=mem=level
Controla el nivel de comprobación de acceso a memoria. El argumento level puede ser 0, 1 o 2.
0
Las comprobaciones de memoria están deshabilitadas.
1
Se comprueban las escrituras en variables no inicializadas y los accesos a memoria no asignada. Esta es la comprobación predeterminada.
2
Además de las comprobaciones del nivel 1, se realiza un seguimiento de la asignación y desasignación de memoria para detectar posibles fugas de memoria o accesos a memoria liberada.
-fcheck=recursion=level
Controla el nivel de comprobación de recursividad. El argumento level puede ser 0, 1 o 2.
0
Las comprobaciones de recursividad están deshabilitadas.
1
Se comprueba si se ha superado la pila de llamadas en los procedimientos recursivos. Esta es la comprobación predeterminada.
2
Además de las comprobaciones del nivel 1, se realiza un seguimiento del uso de la pila para detectar posibles desbordamientos de pila en programas con un gran número de llamadas recursivas profundas.
-fcheck=stream=level
Controla el nivel de comprobación de E/S de flujo. El argumento level puede ser 0, 1 o 2.
0
Las comprobaciones de E/S de flujo están deshabilitadas.
1
Se comprueban las operaciones de E/S de flujo para ver si están utilizando unidades de archivo abiertas o cerradas de forma incorrecta. Esta es la comprobación predeterminada.
2
Además de las comprobaciones del nivel 1, se realiza un seguimiento del estado de las unidades de archivo para detectar posibles errores de E/S, como intentos de leer desde una unidad no disponible o escribir en una unidad de solo lectura.
-fcheck=substring=level
Controla el nivel de comprobación de subcadenas. El argumento level puede ser 0, 1 o 2.
0
Las comprobaciones de subcadenas están deshabilitadas.
1
Se comprueban los accesos a subcadenas para ver si están dentro de los límites de la cadena. Esta es la comprobación predeterminada.
2
Además de las comprobaciones del nivel 1, se realiza un seguimiento de la creación y modificación de subcadenas para detectar posibles errores de gestión de memoria o accesos no válidos.
-fconvert=endian
Especifica el orden de bytes para la conversión de archivos de datos binarios. La opción -fconvert=swap habilita la inversión de bytes para la lectura y escritura de archivos binarios. Esto puede ser útil cuando se trabaja con archivos de datos que se crearon en sistemas con un orden de bytes diferente. La opción -fconvert=ieee utiliza el orden de bytes IEEE estándar para la representación de punto flotante. El valor predeterminado depende de la arquitectura del sistema.
-fdummy-N
Proporciona N argumentos dummy vacíos para la llamada a una subrutina o función. Esto es útil para alinear datos en memoria o para pasar argumentos que no se utilizan, pero que se espera que estén presentes en la interfaz de la subrutina o función.
-fexternal-name
Declara que el nombre de la subrutina o función especificado es externo. Esto es útil para evitar que el compilador realice optimizaciones o comprobaciones innecesarias para esa subrutina o función.
-finteger-4-integer-8
Promueve todas las entidades INTEGER(KIND=4) a entidades INTEGER(KIND=8). Si "KIND=8" no está disponible, se emitirá un error. Esta opción debe usarse con cuidado y puede no ser adecuada para sus códigos. Las áreas de posible preocupación incluyen llamadas a procedimientos externos, alineación en "EQUIVALENCE" y/o "COMMON", interfaces genéricas, conversión de constantes literales BOZ y E/S. Se sugiere la inspección de la representación intermedia del código Fortran traducido, producido por -fdump-tree-original.
-fintrinsic-function

Habilitar y personalizar el preprocesamiento

Muchos compiladores de Fortran, incluido GNU Fortran, permiten pasar el código fuente a través de un preprocesador C (CPP; a veces también llamado preprocesador de Fortran, FPP) para permitir la compilación condicional. En el caso de GNU Fortran, este es el preprocesador GNU C en modo tradicional. En sistemas con nombres de archivo que conservan mayúsculas y minúsculas, el preprocesador se invoca automáticamente si la extensión del nombre de archivo es .F, .FOR, .FTN, .fpp, .FPP, .F90, .F95, .F03 o .F08. Para invocar manualmente el preprocesador en cualquier archivo, use -cpp; para deshabilitar el preprocesamiento en archivos donde el preprocesador se ejecuta automáticamente, use -nocpp.

Si un archivo preprocesado incluye otro archivo con la sentencia Fortran "INCLUDE", el archivo incluido no se preprocesa. Para preprocesar archivos incluidos, use la sentencia preprocesador equivalente "#include".

Si GNU Fortran invoca el preprocesador, "__GFORTRAN__" se define. Las macros "__GNUC__", "__GNUC_MINOR__" y "__GNUC_PATCHLEVEL__" se pueden utilizar para determinar la versión del compilador. Consulte Top,,Overview,cpp,The C Preprocessor para obtener más detalles.

GNU Fortran admite una serie de tipos de "INTEGER" y "REAL" además de los tipos de tipo requeridos por el estándar Fortran. La disponibilidad de cualquier tipo de tipo dado depende de la arquitectura. Las siguientes macros de preprocesador predefinidas se pueden utilizar para incluir condicionalmente código para estos tipos de tipo adicionales: "__GFC_INT_1__", "__GFC_INT_2__", "__GFC_INT_8__", "__GFC_INT_16__", "__GFC_REAL_10__" y "__GFC_REAL_16__".

Si bien CPP es el estándar de facto para preprocesar código Fortran, la Parte 3 del estándar Fortran 95 (ISO/IEC 1539-3:1998) define
