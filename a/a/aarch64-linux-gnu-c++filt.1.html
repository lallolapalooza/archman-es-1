aarch64-linux-gnu-c++filt(1)

Paquete: aarch64-linux-gnu-binutils

Licencias: GPL

C++FILT(1) Herramientas de desarrollo GNU C++FILT(1)

NOMBRE

c++filt - desenmascara símbolos de C++ y Java

SINOPSIS

c++filt [-_|--strip-underscore]
[-n|--no-strip-underscore]
[-p|--no-params]
[-t|--types]
[-i|--no-verbose]
[-r|--no-recurse-limit]
[-R|--recurse-limit]
[-s formato|--format=formato]
[--help] [--version] [símbolo...]

DESCRIPCIÓN

Los lenguajes C++ y Java proporcionan la sobrecarga de funciones, lo que significa que puede escribir muchas funciones con el mismo nombre, siempre que cada función tome parámetros de tipos diferentes. Para poder distinguir estas funciones de nombres similares, C++ y Java las codifican en un nombre de ensamblador de bajo nivel que identifica de forma única cada versión diferente. Este proceso se conoce como enmascaramiento. El c++filt [1] programa realiza el mapeo inverso: decodifica (desenmascara) nombres de bajo nivel en nombres de nivel de usuario para que puedan ser leídos.

Cada palabra alfanumérica (consistente en letras, dígitos, guiones bajos, dólares o puntos) vista en la entrada es un nombre enmascarado potencial. Si el nombre se decodifica en un nombre de C++, el nombre de C++ reemplaza el nombre de bajo nivel en la salida; de lo contrario, se emite la palabra original. De esta manera, puede pasar un archivo fuente de ensamblador completo, que contenga nombres enmascarados, a través de c++filt y ver el mismo archivo fuente que contiene nombres desenmascarados.

También puede usar c++filt para descifrar símbolos individuales pasándolos en la línea de comandos:

c++filt <símbolo>

Si no se proporcionan argumentos símbolo , entonces c++filt lee nombres de símbolos de la entrada estándar. Todos los resultados se imprimen en la salida estándar. La diferencia entre leer nombres de la línea de comandos y leerlos de la entrada estándar es que se espera que los argumentos de la línea de comandos sean solo nombres enmascarados y no se realiza ninguna comprobación para separarlos del texto circundante. Así que, por ejemplo:

c++filt -n _Z1fv

funcionará y desenmascarará el nombre a "f()", mientras que:

c++filt -n _Z1fv,

no funcionará. (Note la coma extra al final del nombre enmascarado que lo hace inválido). Sin embargo, este comando funcionará:

echo _Z1fv, | c++filt -n

y mostrará "f(),", es decir, el nombre desenmascarado seguido de una coma final. Este comportamiento se debe a que cuando los nombres se leen de la entrada estándar, se espera que puedan ser parte de un archivo fuente de ensamblador donde pueda haber caracteres extra, ajenos, al final de un nombre enmascarado. Por ejemplo:

.type   _Z1fv, @function

OPCIONES

-_
--strip-underscore
En algunos sistemas, tanto los compiladores de C como los de C++ colocan un guion bajo delante de cada nombre. Por ejemplo, el nombre de C "foo" obtiene el nombre de bajo nivel "_foo". Esta opción elimina el guion bajo inicial. Si c++filt elimina el guion bajo por defecto depende del destino.
-n
--no-strip-underscore
No elimina el guion bajo inicial.
-p
--no-params
Al desenmascarar el nombre de una función, no muestra los tipos de los parámetros de la función.
-t
--types
Intenta desenmascarar tipos así como nombres de funciones. Esto está deshabilitado por defecto, ya que los tipos enmascarados normalmente solo se usan internamente en el compilador, y pueden confundirse con nombres no enmascarados. Por ejemplo, una función llamada "a" tratada como un nombre de tipo enmascarado sería desenmascarada a "signed char".
-i
--no-verbose
No incluye detalles de implementación (si los hay) en la salida desenmascarada.
-r
-R
--recurse-limit
--no-recurse-limit
--recursion-limit
--no-recursion-limit
Habilita o deshabilita un límite en la cantidad de recursión realizada mientras se desenmascaran cadenas. Dado que los formatos de enmascaramiento de nombres permiten un nivel infinito de recursión, es posible crear cadenas cuya decodificación agotará la cantidad de espacio de pila disponible en la máquina anfitriona, provocando una falla de memoria. El límite intenta evitar que esto suceda restringiendo la recursión a 2048 niveles de anidamiento.

El valor por defecto es que este límite esté habilitado, pero deshabilitarlo puede ser necesario para desenmascarar nombres verdaderamente complicados. Sin embargo, tenga en cuenta que si el límite de recursión está deshabilitado, es posible que se agote la pila y cualquier informe de error sobre tal evento será rechazado.

La opción -r es un sinónimo de la opción --no-recurse-limit . La opción -R es un sinónimo de la opción --recurse-limit .

-s formato
--format=formato
c++filt puede decodificar varios métodos de enmascaramiento, utilizados por diferentes compiladores. El argumento de esta opción selecciona qué método usa:
"auto"
Selección automática basada en el ejecutable (el método por defecto)
"gnu"
el utilizado por el compilador de C++ de GNU (g++)
"lucid"
el utilizado por el compilador Lucid (lcc)
"arm"
el especificado por el Manual de Referencia Anotado de C++
"hp"
el utilizado por el compilador de HP (aCC)
"edg"
el utilizado por el compilador EDG
"gnu-v3"
el utilizado por el compilador de C++ de GNU (g++) con la ABI V3.
"java"
el utilizado por el compilador de Java de GNU (gcj)
"gnat"
el utilizado por el compilador de Ada de GNU (GNAT).
--help
Imprime un resumen de las opciones de c++filt y sale.
--version
Imprime el número de versión de c++filt y sale.
@archivo
Lee opciones de la línea de comandos desde archivo. Las opciones leídas se insertan en lugar de la opción original @archivo . Si archivo no existe o no se puede leer, la opción se tratará literalmente y no se eliminará.

Las opciones en archivo están separadas por espacios en blanco. Un carácter espacio en blanco puede incluirse en una opción rodeando toda la opción entre comillas simples o dobles. Cualquier carácter (incluida una barra invertida) puede incluirse anteponiendo al carácter a incluir una barra invertida. El archivo puede contener opciones adicionales @archivo ; cualquier opción de este tipo será procesada recursivamente.

NOTAS AL PIE

1.
MS-DOS no permite "+" caracteres en nombres de archivo, por lo que en MS-DOS este programa se llama CXXFILT.
