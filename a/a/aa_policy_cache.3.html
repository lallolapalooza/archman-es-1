DESCRIPCIÓ

N

El objeto aa_policy_cache contiene información sobre un conjunto de archivos de caché de políticas de AppArmor. Los archivos de caché de políticas son la representación binaria de un perfil de AppArmor legible por humanos. La representación binaria es la forma en que se carga en el

kernel.

La función aa_policy_cache_new() crea un objeto aa_policy_cache basándose en un descriptor de archivo de directorio y una ruta. Consulte la página de manual openat(2) para ejemplos de dirfd y path. El path debe apuntar a un directorio y se usará como base para la ubicación de los archivos de caché de políticas. Consulte aa_policy_cache_dir_path para averiguar qué directorio se usará para almacenar los archivos de caché de políticas binarias. Si se utilizan directorios de caché superpuestos adicionales (consulte aa_policy_cache_add_ro_dir), el directorio especificado en aa_policy_cache_new es el primer directorio que se busca y es la capa de superposición escribible. Si kernel_features es NULL, se utilizan las características del kernel actual. Al especificar un objeto kernel_features válido, debe ser compatible con las características del kernel de interés. El valor de max_caches debe ser igual al número de cachés que se deben permitir antes de que las cachés antiguas se eliminen automáticamente. La definición de lo que se considera una caché antigua es privada de libapparmor. Especificar 0 significa que no se deben crear nuevas cachés y solo se pueden usar las cachés existentes y válidas. Especificar UINT16_MAX significa que se puede crear una nueva caché y que la eliminación de cachés antiguas está deshabilitada. El objeto asignado aa_policy_cache debe liberarse usando aa_policy_cache_

unref().

La función aa_policy_cache_add_ro_dir() agrega un directorio de caché existente a la caché de políticas, como una capa de solo lectura bajo el directorio principal con el que se creó la caché. Cuando se busca en la caché un archivo de caché existente, se buscará en el directorio principal y luego en los directorios de solo lectura en el orden en que se agregaron a la caché de políticas. Esto permite que la caché de políticas se inicialice con políticas precompiladas que pueden actualizarse superponiendo el archivo de caché de solo lectura con uno escrito en el directorio de caché

principal.

aa_policy_cache_ref() incrementa el contador de referencias del objeto policy

_cache.

aa_policy_cache_unref() decrementa el contador de referencias del objeto policy_cache y libera todos los recursos correspondientes cuando el contador de referencias llega a

cero.

La función aa_policy_cache_remove() elimina todos los archivos de caché de políticas basándose en un descriptor de archivo de directorio y una ruta. El path debe apuntar a un directorio. Consulte la página de manual openat(2) para ejemplos de dirfd y path

.

La función aa_policy_cache_replace_all() se puede usar para realizar un reemplazo de políticas de todas las políticas en caché en el directorio de caché representado por el objeto policy_cache. Si kernel_interface es NULL, se utiliza la interfaz de kernel actual. Al especificar un objeto kernel_interface válido, debe ser la interfaz del kernel en

ejecución.

La función aa_policy_cache_dir_path() proporciona la ruta al directorio de caché para un objeto policy_cache en el nivel en la superposición de la caché de políticas de directorios. Un nivel 0 siempre estará presente y es el primer directorio que se busca en una superposición de directorios de caché, y también será la capa del directorio de caché escribible. Los archivos de caché de políticas binarias se encontrarán en el directorio devuelto por esta

función.

La función aa_policy_cache_dir_levels() proporciona acceso al número de d

irectorios que se están superponiendo
para crear la caché de políticas.

VALOR DE

RETORNO

La función aa_policy_cache_new() devuelve 0 en caso de éxito y *policy_cache apuntará a un objeto aa_policy_cache que debe liberarse con aa_policy_cache_unref(). Se devuelve -1 en caso de error, con errno establecido adecuadamente, y *policy_cache se establecerá en

NULL.

aa_policy_cache_ref() devuelve el valor de policy_cache

.

aa_policy_cache_remove() y aa_policy_cache_replace_all() devuelven 0 en caso de éxito. Se devuelve -1 en caso de error, con errno establecido

adecuadamente.

aa_policy_cache_dir_path() devuelve una cadena de ruta que debe ser liberada por el llamador. Se devuelve NULL en caso de error, con errno establecido

adecuadamente.

aa_policy_cache_dir_levels() devuelve un número que indica el número de niveles de directorio asociados con policy_cache

.

aa_policy_cache_dir_path_preview() es lo mismo que aa_policy_cache_dir_path() excepto que no requiere un objeto aa_policy_cache existente. Esto es útil si el programa que llama no puede crear un objeto aa_policy_cache debido a la falta de privileg

ios necesarios para cre
ar el directorio de caché.
