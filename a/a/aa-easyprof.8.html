DESCRIPCIÓ

N

aa-easyprof proporciona una interfaz fácil de usar para la generación de políticas de AppArmor. aa-easyprof soporta el uso de plantillas y grupos de políticas para perfilar rápidamente una aplicación. Tenga en cuenta que aunque esta herramienta puede ayudar con la generación de políticas, su utilidad depende de la calidad de las plantillas, grupos de políticas y abstracciones utilizadas. Además, esta herramienta puede crear políticas que sean menos restringidas que crear políticas a mano o con aa-genprof y aa-logpro

f
.

OPCIONE

S

aa-easyprof acepta los siguientes

argumentos:
-t PLANTILLA, --template=PLANTI
LLA
Especifica qué plantilla usar. Puede especificar una plantilla del sistema de /usr/share/apparmor/easyprof/templates o un nombre de archivo para la plantilla a usar. Si no se especifica, usa /usr/share/apparmor/easyprof/templates/defau
lt.
-p GRUPOSDEPOLÍTICAS, --policy-groups=GRUPOSDEPOLÍTI
CAS
Especifica POLÍTICA como una lista separada por comas de grupos de políticas. Vea --list-templates para los grupos de políticas soportados. Los grupos de políticas disponibles están en /usr/share/apparmor/easyprof/policy. Los grupos de políticas son simplemente agrupaciones de reglas o políticas de AppArmor. Son similares a las abstracciones de AppArmor, pero generalmente abarcan más reglas de
política.
--parser
RUTA
Especifica la RUTA del binario apparmor_parser a usar al verificar la política. Si esta opción no se especifica, aa-easyprof intentará localizar la ruta comenzando con /sbin/apparmor_pars
er.
-a ABSTRACCIONES, --abstractions=ABSTRACCIO
NES
Especifica ABSTRACCIONES como una lista separada por comas de abstracciones de AppArmor. Generalmente se recomienda usar grupos de políticas en su lugar, pero esto se proporciona como una conveniencia. Las abstracciones de AppArmor se encuentran en /etc/apparmor.d/abstractions. Vea apparmor.d(5) para más
detalles.
-b RUTA,
--base=RUTA
Establece la RUTA base para resolver las abstracciones especificadas por --abstractions. Vea la misma opción en apparmor_parser(8) para más
detalles.
-I RUTA,
--Include=RUTA
Añade RUTA a las rutas de búsqueda utilizadas para resolver las abstracciones especificadas por --abstractions. Vea la misma opción en apparmor_parser(8) para más
detalles.
-r RUTA,
--read-path=RUTA
Especifica una RUTA para permitir lecturas al propietario. Puede especificarse varias veces. Si la RUTA termina en una '/', entonces la RUTA se trata como un directorio y se permiten lecturas a todos los archivos bajo este directorio. Opcionalmente puede usar '/*' al final de la RUTA para permitir lecturas solo a archivos directamente en la
RUTA.
-w RUTA,
--write-dir=RUTA
Como --read-path pero también permite escrituras del propietario además de
lecturas.
-n NOMBRE,
--name=NOMBRE
Especifica el NOMBRE de la política. Si no se especifica, el NOMBRE se establece al nombre del binario. El NOMBRE de la política generalmente solo se usa para metadatos del perfil y no especifica el nombre del perfil de
AppArmor.
--profile-name=NOMBREDEPER
FIL
Especifica el nombre del perfil de AppArmor. Cuando se establece, usa 'profile NOMBREDEPERFIL' en el perfil. Cuando se establezca y se especifique un binario, usa 'profile NOMBREDEPERFIL BINARIO' en el perfil. Si no se establece, el binario se usará como el nombre del perfil y el anexo del
perfil.
--template-var="@{VAR}
=VALOR"
Establece VAR a VALOR en la política resultante. Esto generalmente solo tiene sentido si la plantilla especificada usa este valor. Puede especificarse varias
veces.

-m MANIFIESTO, --manifest=MANIFIE
STO
aa-easyprof también soporta el uso de un archivo manifiesto JSON para especificar opciones relacionadas con la política. A diferencia de los argumentos de la línea de comandos, el archivo JSON puede especificar múltiples perfiles. La estructura del JSON es: 
{
  "security": {
    "profiles": {
      "<nombre del perfil 1>": {
        ... atributos específicos de este perfil ...
      },
      "<nombre del perfil 2>": {
        ...
      }
    }
} }

Cada objeto JSON de perfil (es decir, todo lo que está bajo un nombre de perfil) puede especificar cualquier campo relacionado con la política. El contenedor JSON "security" es opcional y puede omitirse. Un archivo manifiesto de ejemplo que demuestra todos los

campos es: 
{
  "security": {
    "profiles": {
      "com.example.foo": {
        "abstractions": [
          "audio",
          "gnome"
        ],
        "author": "Tu Nombre",
        "binary": "/opt/foo/**",
        "comment": "Comentario sin estructura de una sola línea",
        "copyright": "Declaración de derechos de autor sin estructura de una sola línea",
        "name": "Mi Aplicación Foo",
        "policy_groups": [
          "networking",
          "user-application"
        ],
        "policy_vendor": "algúnproveedor",
        "policy_version": 1.0,
        "read_path": [
          "/tmp/foo_r",
          "/tmp/bar_r/"
        ],
        "template": "user-application",
        "template_variables": {
          "APPNAME": "foo",
          "VAR1": "bar",
          "VAR2": "baz"
        },
        "write_path": [
          "/tmp/foo_w",
          "/tmp/bar_w/"
        ]
      }
    }
} }

Un archivo manifiesto no tiene por qué incluir todos los campos. Por ejemplo, un archivo manifest para una aplicación de Ubuntu SDK podría ser:

{
  "security": {
    "profiles": {
      "com.ubuntu.developer.myusername.MyCoolApp": {
        "policy_groups": [
          "networking",
          "online-accounts"
        ],
        "policy_vendor": "ubuntu",
        "policy_version": 1.0,
        "template": "ubuntu-sdk",
        "template_variables": {
          "APPNAME": "MyCoolApp",
          "APPVERSION": "0.1.2"
        }
      }
    }
  }
}
--verify-manifest
Cuando se utiliza con --manifest, advierte sobre definiciones potencialmente inseguras en el archivo manifest.
--output-format=FORMAT
Especifica text (predeterminado si no se especifica) para la salida de la política de AppArmor o json para el formato de manifest JSON.
--output-directory=DIR
Especifica el directorio de salida para el perfil. Si no se especifica, la política se envía a la salida estándar.

EJEMPLOS

Ejemplo de uso para un programa llamado 'foo' que está instalado en /opt/foo:

$ aa-easyprof --template=user-application --template-var="@{APPNAME}=foo" \
              --policy-groups=opt-application,user-application \
              /opt/foo/bin/FooApp

Al usar un archivo manifest:

$ aa-easyprof --manifest=manifest.json

Para generar un archivo manifest basado en los argumentos de aa-easyprof:

$ aa-easyprof --output-format=json \
              --author="Tu Nombre" \
              --comment="Comentario no estructurado de una sola línea" \
              --copyright="Declaración de copyright no estructurada de una sola línea" \
              --name="Mi App Foo" \
              --profile-name="com.example.foo" \
              --template="user-application" \
              --policy-groups="user-application,networking" \
              --abstractions="audio,gnome" \
              --read-path="/tmp/foo_r" \
              --read-path="/tmp/bar_r/" \
              --write-path="/tmp/foo_w" \
              --write-path=/tmp/bar_w/ \
              --template-var="@{APPNAME}=foo" \
              --template-var="@{VAR1}=bar" \
              --template-var="@{VAR2}=baz" \
              "/opt/foo/**"
