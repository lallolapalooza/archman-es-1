ASTRACEROUTE(8) conjunto de herramientas netsniff-ng ASTRACEROUTE(8)

NOMBRE

astraceroute - utilidad de trazado de ruta de sistemas autónomos

SINOPSIS

astraceroute [opciones]

DESCRIPCIÓN

astraceroute es una pequeña utilidad para obtener información de la ruta de una manera similar a traceroute, pero con información adicional de ubicación geográfica. Rastrea la ruta de un paquete desde el host local hasta el host remoto incrementando sucesivamente el campo TTL de la IP, comenzando desde 1, con la esperanza de que cada nodo intermedio envíe una notificación ICMP TIME_EXCEEDED de vuelta al host local cuando el valor TTL se decrementa a 0.

astraceroute admite consultas IPv4 e IPv6 y mostrará información del país y la ciudad, si está disponible, el número AS al que pertenece el salto, y el nombre de su ISP. astraceroute también muestra información de tiempos y datos DNS inversos.

Debido a la configurabilidad de astraceroute, también es posible recopilar información más útil sobre el salto en cuanto a lo que hace y lo que no permite pasar. Esto se hace utilizando cadenas de texto sin formato para sondear DPIs o "grandes cortafuegos" para determinar si filtrarán palabras clave críticas bloqueadas. Esta herramienta podría ser un buen comienzo para un análisis más profundo de dichos sistemas.

OPCIONES

-H <host>, --host <host>
Nombre de host o dirección IPv4 o IPv6 del host remoto al que se debe rastrear la ruta AS. En el caso de una dirección o host IPv6, la opción -6 debe usarse. IPv4 es el predeterminado.
-p <puerto>, --port <puerto>
Puerto TCP que debe usar el host remoto. Si no se especifica, el puerto predeterminado utilizado es 80.
-i <dispositivo>, -d <dispositivo>, --dev <dispositivo>
Dispositivo de red desde donde iniciar el trazado de ruta, p. ej. eth0, wlan0.
-b <IP>, --bind <IP>
Dirección IP a la que enlazarse diferente a la dirección del dispositivo de red. Debe especificar -6 para una dirección IPv6.
-f <ttl>, --init-ttl <ttl>
Valor TTL inicial a utilizar. Esta opción puede ser útil si no está interesado en los primeros n saltos, sino en los siguientes. El valor TTL inicial predeterminado es 1.
-m <ttl>, --max-ttl <ttl>
Valor TTL máximo a utilizar. Si no se especifica de otra manera, el valor TTL máximo es 30. Así, una vez alcanzado esto, astraceroute termina.
-q <num>, --num-probes <num>
Especifica el número de consultas a realizar en un salto particular. El predeterminado es 2 solicitudes de consulta.
-x <seg>, --timeout <seg>
Indica a astraceroute el tiempo de espera de respuesta de sondeo en segundos, en otras palabras, el tiempo máximo que astraceroute debe esperar una respuesta ICMP del salto actual. El predeterminado es 3 segundos.
-X <cadena>, --payload <cadena>
Coloca una cadena de texto ASCII sin formato en la carga útil del paquete. El texto sin formato que contiene espacios en blanco debe ponerse entre comillas (p. ej.: "censor me").
-l <long>, --totlen <long>
Especifica la longitud total del paquete. La carga útil que no tiene una cadena de texto sin formato se rellena con datos aleatorios.
-4, --ipv4
Usar solo solicitudes IPv4. Este es el predeterminado.
-6, --ipv6
Usar solo solicitudes IPv6. Esto debe usarse al pasar un host IPv6 como argumento.
-n, --numeric
Indica a astraceroute que no realice búsquedas DNS inversas para las respuestas de los saltos. La opción opuesta es -N.
-u, --update
Se invocará el mecanismo de actualización de la base de datos geográfica incorporada para obtener la última versión de Maxmind. Para configurar las ubicaciones de búsqueda de las bases de datos, el archivo /etc/netsniff-ng/geoip.conf contiene direcciones posibles. Así, para ahorrar ancho de banda o para reflejar las bases de datos de Maxmind (para eludir su política de límite de tráfico), se pueden colocar diferentes hosts o direcciones IP en geoip.conf, separados por un salto de línea.
-L, --latitude
Mostrar también la latitud y longitud de los saltos.
-N, --dns
Indica a astraceroute que realice búsquedas DNS inversas para las respuestas de los saltos. La opción opuesta es -n.
-S, --syn
Usar el indicador SYN de TCP para la solicitud.
-A, --ack
Usar el indicador ACK de TCP para la solicitud.
-F, --fin
Usar el indicador FIN de TCP para la solicitud.
-P, --psh
Usar el indicador PSH de TCP para la solicitud.
-U, --urg
Usar el indicador URG de TCP para la solicitud.
-R, --rst
Usar el indicador RST de TCP para la solicitud.
-E, --ecn-syn
Usar el indicador ECN de TCP para la solicitud.
-t <tos>, --tos <tos>
Especificar explícitamente el TOS de la IP.
-G, --nofrag
Establecer el indicador de no fragmentación de la IP.
-Z, --show-packet
Mostrar y analizar el paquete devuelto.
-v, --version
Mostrar información de versión y salir.
-h, --help
Mostrar ayuda de usuario y salir.

EJEMPLO DE USO

astraceroute -i eth0 -N -S -H netsniff-ng.org
Esto envía una sonda TCP SYN a través del dispositivo de red ''eth0'' al host remoto IPv4 netsniff-ng.org. Esta solicitud es muy probable que pase. Además, indica a astraceroute que realice búsquedas DNS inversas para cada salto.
astraceroute -6 -i eth0 -S -E -N -H www.6bone.net
En este ejemplo, se está realizando una sonda TCP SYN/ECN para el host IPv6 www.6bone.net. También en este caso, se está utilizando el dispositivo ''eth0'' así como una búsqueda DNS inversa para cada salto.
astraceroute -i eth0 -N -F -H netsniff-ng.org
Aquí, enviamos una sonda TCP FIN al host remoto netsniff-ng.org. Nuevamente, en cada salto se realiza una búsqueda DNS inversa y las consultas se transmiten desde ''eth0''. Se usa IPv4.
astraceroute -i eth0 -N -FPU -H netsniff-ng.org
Como en la mayoría de los otros ejemplos, realizamos un trazado de ruta al host IPv4 netsniff-ng.org y hacemos una sonda TCP Xmas esta vez.
astraceroute -i eth0 -N -H netsniff-ng.org -X censor-me -Z
En este ejemplo, tenemos una sonda Null al host remoto netsniff-ng.org, puerto 80 (predeterminado) y esta vez, añadimos la cadena de texto sin formato "censor-me" a la carga útil del paquete para probar si un cortafuegos o DPI dejará pasar esta cadena. Dicho trazado podría hacerse una vez sin y una vez con una cadena bloqueada para recopilar posible información sobre la censura.

NOTA

Si una sonda basada en TCP falla después de un número de reintentos, astraceroute recurrirá automáticamente a sondas basadas en ICMP para pasar a través de cortafuegos y enrutadores utilizados en balanceo de carga, por ejemplo.

Para recopilar más información sobre los números AS mostrados por astraceroute, ver, p. ej.: http://bgp.he.net/AS<número>.

ERRORES

Las ubicaciones geográficas se estiman con la ayuda de la base de datos GeoIP de Maxmind y pueden diferir de la ubicación física real. Para disminuir los posibles errores, actualice la base de datos regularmente usando la opción --update de astraceroute.

En algún momento, necesitaremos un enfoque similar para recopilar información de ruta más confiable, como en la herramienta paris-traceroute.

Debido a la naturaleza genérica de astraceroute, actualmente tiene un mecanismo incorporado para detener el rastreo después de un número fijo de saltos, ya que las banderas TCP configurables pueden incluir cualquier cosa. Es posible disminuir este número, por supuesto. En el futuro, si se envía una sonda SYN, debería haber un oyente para que podamos detener el rastreo si detectamos un apretón de manos en progreso.
