NOMBR

E

anything-sync-daemon - Crea enlaces simbólicos y sincroniza directorios especificados por el usuario hacia la RAM, reduciendo así las llamadas al disco duro/SSD y acelerando el sistema.

DESCRIPCIÓ

N

Anything-sync-daemon (asd) es un pequeño pseudo-diseño diseñado para gestionar directorios especificados por el usuario (denominados objetivos de sincronización de aquí en adelante) en tmpfs y para sincronizarlos periódicamente de vuelta al disco físico (HDD/SSD). Esto se logra mediante un paso de montaje vinculado (bind mount) y un uso innovador de rsync para mantener la sincronización entre una copia en tmpfs y las copias de seguridad vinculadas al medio. Además, asd cuenta con varias funciones de recuperación tras

fallos.

Objetivos de diseño de

asd:
  • Experiencia de usuario completamente
    • transparente.
  • Reducción del desgaste de los discos físicos (particularmente los
    • SSD).
  • Velocid
    • a
d
.

Dado que el objetivo de sincronización se reubica en tmpfs (disco en RAM), el correspondiente asalto de

E/S asociado al uso del sistema de los mismos también se redirige desde el disco físico hacia la RAM, r
educiendo así el desgaste del disco físico y mejorando también la velocidad y la capacidad de respuesta.

CONFIGURACI

ÓN

/etc/asd.conf contiene todos los ajustes gestionados por el usuario. Opcionalmente, se puede usar otro archivo estableciendo la variable de entorno

ASDCONF.

NOTA: las ediciones realizadas en /etc/asd.conf mientras asd está en ejecución se aplicarán solo después de que asd se haya reiniciado desde el servicio de

init.
  • Como mínimo, defina los objetivos de sincronización que gestionará asd en el array WHATTOSYNC. Sintaxis a
    • continuación.
  • Opcionalmente, descomente y defina la ubicación de su tmpfs* de la distribución en la variable
    • VOLATILE.
  • Opcionalmente, habilite el uso de overlayfs para mejorar aún más la velocidad de sincronización y usar una huella de memoria más pequeña. Hágalo en la variable USE_OVERLAYFS. Tenga en cuenta que esta opción requiere que su kernel esté configurado para usar ya sea el módulo 'overlay' o 'overlayfs'. Consulte las preguntas frecuentes a continuación para obtener detalles adicionales sobre esta
    • función.
  • Opcionalmente, deshabilite el uso de instantáneas de recuperación tras fallos. Hágalo en la variable
    • USE_BACKUPS.
  • Opcionalmente, defina el número
    • de instantáneas de recuperació
n tras fallos a conservar. Hága
lo en la variable BACKUP_LIMIT.

*Tenga en cuenta que el valor predeterminado de "/tmp" debería funcionar bien para la configuración de VOLATILE. Si usa bleachbit, NO lo invoque con el interruptor--clean system.tmp o eliminará un archivo oculto clave (.foo) de /tmp que asd necesita para realizar un seguimiento del estado de sincronización. Tenga en cuenta también que usar un valor de "/dev/shm" puede causar problemas con el generación de NAMESPACE de systemd solo cuando los usuarios habilitan la opción

overlayfs.

INICIAR Y DETENER ASD PARA USUARIOS DE

SYSTEMD

Se proporcionan tanto un archivo de servicio systemd como un temporizador, y deben usarse para iniciar o detener

asd.

El papel del temporizador es actualizar las copias en tmpfs de vuelta al disco. Esto ocurre una vez por hora de forma predeterminada. El temporizador se inicia automáticamente con asd.

service. 
 # systemctl [opción] asd
Opciones disponibles: start stop enable
disable

INICIAR Y DETENER ASD PARA USUARIOS DE OTROS SISTEMAS

INIT

Para distribuciones que no usan systemd, se debe usar otro script de init para gestionar el demonio. Se proporcionan ejemplos y se sabe que funcionan con

Upstart.

Tenga en cuenta que para estos sistemas init, el script de cron proporcio

nado (instalado en /etc/cron.hourly) ejecutará la opción de resincronizac
ión para mantener las copias en tmpfs sincronizadas. Por supuesto, el si
stema de destino debe tener cron instalado y activo para que esto ocurra.

PREGUNTAS

FRECUENTES

P1: ¿Qué es el modo

overlayfs?

R1: Overlayfs es un sistema de archivos de unión simple incluido en el kernel de Linux en la versión 3.18.0. A partir de la versión 5.54 de asd, overlayfs se puede usar para reducir la huella de memoria del espacio tmpfs de asd y para acelerar las operaciones de sincronización y des-sincronización. La magia está en cómo la montura de overlay solo escribe los datos que han cambiado en lugar de todo el objetivo de sincronización. Vea el Ejemplo 1 a continuación. Las mismas funciones de recuperación que asd usa en su modo predeterminado también están activas cuando se ejecuta en modo overlayfs. El modo overlayfs se habilita descomentando USE_OVERLAYFS= en /etc/asd.conf seguido de un reinicio del

demonio.

Hay varias versiones de overlayfs disponibles para el kernel de Linux en producción en varias distribuciones. Las versiones 22 y anteriores tienen un módulo llamado 'overlayfs' mientras que las versiones más nuevas (23 y superiores) tienen un módulo llamado 'overlay' -- note la falta de 'fs' en la versión más nueva. Asd detectará automáticamente el overlayfs disponible para su kernel si está configurado para usar uno de

ellos.

Vea el ejemplo en la sección MODO VISTA PREVIA anterior que muestra un sistema usando overlayfs para ilustrar los ahorros de memoria que se pueden lograr. Note el informe de "overlayfs size" comparado con el informe total de "dir size" para cada objetivo de sincronización. Tenga en cuenta que estos números cambiarán dependiendo de cuántos datos se escriban en el objetivo de sincronización, pero en casos de uso comunes, el tamaño de overlayfs siempre será menor que el tamaño del

dir.

P2: ¿Por qué veo el directorio ".foo-backup_asd" ".foo-backup_asd-old"

?

R2: La forma en que funciona el proceso de respaldo de asd es que crea un clon vinculado duramente del directorio original; esto se conoce como .foo-backup_asd-old. El otro .foo-backup_asd es simplemente un montaje vinculado al enlace del directorio original que se usa para acceder al contenido del directorio original con fines de

overlay.

P3: Mi sistema se bloqueó y asd no se sincronizó de vuelta. ¿Qué

hago?

R3: El respaldo "último bueno" de sus objetivos de sincronización sigue bien sentado felizmente en su sistema de archivos. Al reiniciar asd (en un reinicio, por ejemplo), se realiza una comprobación para ver si asd salió en algún estado corrupto. Si se detecta, asd hará una instantánea del respaldo "último bueno" antes de rotarlo de vuelta a su lugar. Tenga en cuenta que, dado que asd intenta disminuir el uso del disco, nunca realmente "copia" el contenido completo del directorio y solo usa los enlaces duros a los archivos anteriores. Y durante el rsnc paso, crea nuevos archivos para que los enlaces duros anteriores no se vean afectados. Por lo tanto, intentar modificar el directorio mientras asd intenta hacer una copia de seguridad puede dejar el directorio en un estado

corrupto.

P4: ¿Dónde puedo encontrar esta

instantánea?

R4: Encontrará la instantánea en el mismo directorio que el destino de la sincronización y contendrá una marca de fecha y hora que corresponde al momento en que se realizó la recuperación. Por ejemplo, una instantánea de /foo/bar será /foo/.bar-backup_asd-crashrecovery-20141221_070112.tar.zstd -- por supuesto, el sufijo de fecha y hora será diferente para

usted.
