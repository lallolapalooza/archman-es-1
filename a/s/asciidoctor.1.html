ASCIIDOCTOR(1) Manual de Asciidoctor ASCIIDOCTOR(1)

NOMBRE

asciidoctor - convierte archivos fuente AsciiDoc a HTML, DocBook y otros formatos

SINOPSIS

asciidoctor [OPCIÓN]... ARCHIVO...

DESCRIPCIÓN

El comando asciidoctor(1) convierte el/los archivo(s) fuente AsciiDoc ARCHIVO a HTML5, DocBook 5, página de manual y otros formatos de salida personalizados.

Si ARCHIVO es - entonces el fuente AsciiDoc se lee de la entrada estándar.

OPCIONES

Configuración de seguridad

-B, --base-dir=DIR

Directorio base que contiene el documento y los recursos. Por defecto es el directorio que contiene el archivo fuente o, si el fuente se lee de un flujo, el directorio de trabajo. Cuando se combina con la configuración del modo seguro, se puede usar para hacer chroot a la ejecución del programa.

-S, --safe-mode=SAFE_MODE

Establece el nivel del modo seguro: unsafe, safe, servero secure. Desactiva macros potencialmente peligrosas en archivos fuente, como include::[]. Si no se establece, el nivel del modo seguro es unsafe cuando Asciidoctor se invoca usando este script.

--safe

Establece el nivel del modo seguro en safe. Habilita las directivas include, pero impide el acceso a rutas ascendentes del archivo fuente. Se proporciona para compatibilidad con el comando asciidoc. Si no se establece, el nivel del modo seguro es unsafe cuando Asciidoctor se invoca usando este script.

Configuración del documento

-a, --attribute=ATTRIBUTE

Define, sobrescribe o elimina un atributo del documento. Los atributos de la línea de comandos tienen prioridad sobre los atributos definidos en el archivo fuente a menos que el nombre o el valor termine en @. No se aplican sustituciones al valor.

ATTRIBUTE normalmente se formatea como un par clave-valor, en la forma NAME=VALUE. Las formas alternativas son NAME (donde VALUE por defecto es una cadena vacía), NAME! (elimina el atributo NAME ), y NAME=VALUE@ (o NAME@=VALUE) (donde VALUE no sobrescribe el atributo NAME si ya está definido en el documento fuente). Un valor que contenga espacios debe ir entre comillas, en la forma NAME="VALOR CON ESPACIOS".

Esta opción puede especificarse más de una vez.

-b, --backend=BACKEND

Formato de archivo de salida del backend: html5, docbook5y manpage son compatibles de forma nativa. También puedes usar los nombres de alias del backend html (alias de html5) o docbook (alias de docbook5). Se pueden pasar otros valores, pero si Asciidoctor no puede resolver el backend a un convertidor, fallará. Por defecto es html5.

-d, --doctype=DOCTYPE

Tipo de documento: article, book, manpageo inline. Establece el elemento raíz al usar el docbook backend y la clase de estilo en el elemento body HTML al usar el html backend. El tipo de documento book permite múltiples títulos de sección de nivel 0 en un solo documento. El tipo de documento manpage habilita el análisis de metadatos necesarios para producir una página de manual. El tipo de documento inline permite que el contenido de un solo párrafo sea formateado y devuelto sin envolverlo en un elemento contenedor. Por defecto es article.

Conversión del documento

-D, --destination-dir=DIR

Directorio de salida de destino. Por defecto es el directorio que contiene el archivo fuente o, si el fuente se lee de un flujo, el directorio de trabajo. Si se especifica, el directorio se resuelve en relación con el directorio de trabajo.

-E, --template-engine=NAME

Motor de plantillas a usar para las plantillas del convertidor personalizado. La gema con el mismo nombre que el motor se cargará automáticamente. Este nombre también se usa para construir la ruta completa a las plantillas del convertidor personalizado. Si no se especifica un motor de plantillas, se detectará automáticamente basándose en la extensión del archivo de las plantillas del convertidor personalizado encontradas.

-e, --embedded

Genera un documento incrustable, que excluye el encabezado, el pie de página y todo lo que esté fuera del cuerpo del documento. Esta opción es útil para producir documentos que pueden insertarse en una plantilla externa.

-I, --load-path=DIRECTORY

Agrega el directorio especificado a la ruta de carga, para que -r pueda cargar extensiones fuera de la ruta de carga predeterminada de Ruby. Esta opción puede especificarse más de una vez.

-n, --section-numbers

Numera automáticamente los títulos de sección. Sinónimo de --attribute sectnums.

-o, --out-file=OUT_FILE

Escribe la salida en el archivo OUT_FILE. Por defecto es el nombre base del archivo de entrada con la extensión del backend . El archivo se resuelve en relación con el directorio de trabajo. Si la entrada se lee de la entrada estándar o de un pipe con nombre (fifo), entonces el archivo de salida por defecto es stdout. Si OUT_FILE es -, entonces el archivo de salida se escribe en la salida estándar.

-R, --source-dir=DIR

Directorio fuente. Actualmente solo se usa si el directorio de destino también se especifica. Se usa para preservar la estructura de directorios de los archivos convertidos dentro de este directorio en el directorio de destino. Si se especifica, el directorio se resuelve en relación con el directorio de trabajo.

-r, --require=LIBRARY

Requiere la biblioteca especificada antes de ejecutar el procesador, usando el require estándar de Ruby. Esta opción puede especificarse más de una vez.

-s, --no-header-footer

Genera un documento incrustable, que excluye el encabezado, el pie de página y todo lo que esté fuera del cuerpo del documento. Esta opción es útil para producir documentos que pueden insertarse en una plantilla externa.

-T, --template-dir=DIR

Un directorio que contiene plantillas de convertidor personalizadas que sobrescriben una o más plantillas del conjunto incorporado. (requiere la gema tilt )

Si hay una subcarpeta que coincida con el nombre del motor (si se especifica), esa carpeta se agrega a la ruta del directorio de plantillas. De manera similar, si hay una subcarpeta en el directorio de plantillas resultante que coincida con el nombre del backend, esa carpeta se agrega a la ruta del directorio de plantillas.

Esta opción puede especificarse más de una vez. Las plantillas coincidentes encontradas en directorios posteriores sobrescriben las descubiertas previamente.

Información de procesamiento

--failure-level=LEVEL

Establece el nivel mínimo de registro (por defecto: FATAL) que produce un código de salida distinto de cero (es decir, fallo). Si esta opción no se establece, el programa sale con un código de salida cero incluso si se han registrado advertencias o errores.

-q, --quiet

Silencia los mensajes de registro de la aplicación y las advertencias del script.

--trace

Incluye información de traza inversa al informar errores.

-v, --verbose

Establece el nivel de registro en DEBUG para que los mensajes de la aplicación registrados a nivel INFO o DEBUG se impriman en stderr.

-w, --warnings

Activa las advertencias del script (se aplica al código ejecutado).

-t, --timings

Imprime el informe de tiempos en stderr (tiempo para leer, analizar y convertir).

Información del programa

-h, --help [TOPIC]

Imprime un mensaje de ayuda. Muestra el uso del comando si TOPIC no se especifica o no se reconoce. Vuelca la página de manual de Asciidoctor (en formato troff/groff) si TOPIC es manpage. Imprime una hoja de referencia de sintaxis AsciiDoc (en AsciiDoc) si TOPIC es syntax.

-V, --version

Imprime el número de versión del programa.

-v también se puede usar si no se especifican archivos fuente.

Asciidoctor honora la SOURCE_DATE_EPOCH variable de entorno. Si a esta variable se le asigna un valor entero, ese valor se utiliza como época de todos los documentos de entrada y como fecha y hora local. Véase https://reproducible-builds.org/specs/source-date-epoch/ para más información sobre esta variable de entorno.

ESTADO DE SALIDA

0

Éxito.

1

Fallo (error de sintaxis o de uso; error de configuración; fallo en el procesamiento del documento; error inesperado).
