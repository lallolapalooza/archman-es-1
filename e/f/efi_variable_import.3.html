Tenga en cuenta que los valores internos de guid, nombre y datos se asignan por separado, y deben liberarse ya sea individualmente o usando el parámetro free_data de efi_variable_free(). Los accesores _get() para esos valores devuelven datos adecuados para ser liberados individualmente, excepto en aquellos casos donde un accesador _set() se le ha pasado un objeto que ya no es adecuado para eso. efi_variable_export() se utiliza para serializar objetos efi_variable_t en datos lineales

que

pueden escribirse en un archivo. Si los parámetros data o size no se proporcionan, esta función devolverá cuánto almacenamiento debe asignar un llamador. De lo contrario, efi_variable_export() usará el almacenamiento referido como su búfer; si size es menor que la cantidad de almacenamiento necesaria, el búfer no se modificará, y se devolverá la diferencia entre el espacio necesario y size. efi_variable_alloc() se utiliza para asignar un objeto efi_variable_t no poblado adecuado para ser utilizado en

En los casos donde no se ha establecido ningún valor, los accesadores _get() establecerán errno a ENOENT y devolverán un valor negativo o NULL. efi_variable_set_name() y efi_variable_get_name() se utilizan

Todos los bits excepto EFI_VARIABLE_HAS_AUTH_HEADER y EFI_VARIABLE_HAS_SIGNATURE están definidos en la especificación UEFI y deben usarse en consecuencia. EFI_VARIABLE_HAS_AUTH_HEADER debe ser usado por las aplicaciones para rastrear si los contenidos de los datos de la variable incluyen un encabezado de autenticación. EFI_VARIABLE_HAS_SIGNATURE debe ser usado por las aplicaciones para rastrear si los contenidos de los datos de la variable incluyen una firma, y no debe establecerse a menos que EFI_VARIABLE_HAS_AUTH_HEADER también esté establecido. Estos atributos se utilizan para rastrear si una variable exportada se encuentra en un estado de construcción parcial, por ejemplo, si una variable autenticada ha sido creada pero está destinada a ser firmada en una fecha posterior. efi_variable_realize(
