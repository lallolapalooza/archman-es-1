DESC
RIP
CIÓN

Este módulo intenta facilitar la construcción de extensiones de Perl que usan funciones y mapas de tipos proporcionados por otras extensiones de Perl. Esto significa que una extensión de Perl se trata como una biblioteca compartida que también proporciona una interfaz C y una XS además

de la interfaz de Perl.

Esto funciona siempre que la extensión base (o "productora") se cargue con

el

indicador "RTLD_GLOBAL" (generalmente hecho con una sub dl_load_flags

{0x01} 
en el archivo
principal

.pm) si necesita usar funciones definidas en el módulo. Esa extensión "productora" también necesitará decirle a ExtUtils::MakeMaker las funciones específicas a exportar, con argumentos a "WriteMakefile" como: FUNCLIST => [qw(function_name)], DL_FUNCS => { 'Extension::Name' => []

}, 
El esquema básico de funcionamiento es recopilar información sobre un
    módulo en la instancia, y luego almacenar esos datos en la biblioteca de
    Perl donde podrán recuperarse más tarde. El objeto también puede reformatear
    esta información en las estructuras de datos requeridas por la función
    WriteMakefile de ExtUtils::
MakeMaker.

Para información sobre cómo hacer que su módulo encaje en este esquema, vea "hashref = ExtUtils::Depends::load (name)

".

Al crear un nuevo objeto Depends, le da un nombre, que es el nombre del módulo que está construyendo. También puede especificar los nombres de los módulos de los que depende este módulo. Estas dependencias se cargarán automáticamente, y sus mapas de tipos, archivos de cabecera, etc. se fusionarán con los elementos de su nuevo objeto. Cuando almacene los datos de su objeto, la lista de dependencias se almacena con él, de modo que otro módulo que dependa de usted no necesite saber exactamente de qué módulos depende el

suyo.

Por

ejemplo:

Gtk2 depende de Glib Gnome2::Canvas depende de Gtk2 ExtUtils::Depends->new ('Gnome2::Canvas', 'Gtk2'); este comando trae automáticamente todo lo necesario para Glib, ya que Gtk2

depende de él. 
Cuando se guarda la información de configuración, también incluye un
    método de clase
llamado

"Inline", heredable por su módulo. Esto le permite en su módulo simplemente decir al principio: package Mymod; use parent 'Mymod::Install::Files'; # para heredar el método

'Inline' 
Y los usuarios
de

"Mymod" que quieran escribir código en línea (usando Inline) simplemente podrán escribir: use Inline with =>

'Mymod'; 
Y todos los archivos de cabecera, definiciones y bibliotecas necesarios
    se añadirán para
ellos.
