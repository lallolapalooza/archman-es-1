EXT4(5) Manual de Formatos de Archivo EXT4(5)

NOMBRE

ext2 - el segundo sistema de archivos extendido
ext3 - el tercer sistema de archivos extendido
ext4 - el cuarto sistema de archivos extendido

DESCRIPCIÓN

Los segundos, terceros y cuartos sistemas de archivos extendidos, o ext2, ext3 y ext4 como se les conoce comúnmente, son sistemas de archivos de Linux que históricamente han sido el sistema de archivos por defecto para muchas distribuciones de Linux. Son sistemas de archivos de propósito general que han sido diseñados para la extensibilidad y la compatibilidad con versiones anteriores. En particular, los sistemas de archivos formateados previamente para su uso con ext2 y ext3 pueden ser montados utilizando el controlador de sistema de archivos ext4, y de hecho, en muchas distribuciones modernas de Linux, el controlador de sistema de archivos ext4 ha sido configurado para manejar solicitudes de montaje para sistemas de archivos ext2 y ext3.

CARACTERÍSTICAS DEL SISTEMA DE ARCHIVOS

Un sistema de archivos formateado para ext2, ext3 o ext4 puede tener alguna combinación de las siguientes banderas de características del sistema de archivos habilitadas. Algunas de estas características no son compatibles con todas las implementaciones de los controladores de sistemas de archivos ext2, ext3 y ext4, dependiendo de la versión del kernel de Linux en uso. En otros sistemas operativos, como GNU/HURD o FreeBSD, solo un conjunto muy restrictivo de características del sistema de archivos puede ser compatible en sus implementaciones de ext2.

64bit

Habilita el sistema de archivos para que sea mayor que 2^32 bloques. Esta característica se establece automáticamente, según sea necesario, pero puede ser útil especificarla explícitamente si el sistema de archivos podría necesitar ser redimensionado a más de 2^32 bloques, incluso si era menor que ese umbral cuando se creó originalmente. Tenga en cuenta que algunos kernels antiguos y versiones antiguas de e2fsprogs no admitirán sistemas de archivos con esta característica ext4 habilitada.
bigalloc

Esta característica de ext4 habilita la asignación de bloques agrupados, de modo que la unidad de asignación sea una potencia de dos del número de bloques. Es decir, cada bit en lo que tradicionalmente se conocía como el mapa de bits de asignación de bloques ahora indica si un clúster está en uso o no, donde un clúster está compuesto por defecto por 16 bloques. Esta característica puede reducir el tiempo dedicado a la asignación de bloques y disminuir la fragmentación, especialmente para archivos grandes. El tamaño se puede especificar utilizando la opción mke2fs -C.
Advertencia: La característica bigalloc todavía está en desarrollo y puede que no sea totalmente compatible con su kernel o que tenga varios errores. Consulte la página web http://ext4.wiki.kernel.org/index.php/Bigalloc para obtener detalles. Puede entrar en conflicto con la asignación retrasada (ver opción de montaje nodelalloc).
Esta característica requiere que la característica extent esté habilitada.
casefold

Esta característica de ext4 proporciona soporte de codificación de caracteres a nivel de sistema de archivos para directorios con la bandera casefold (+F) habilitada. Esta característica preserva los nombres en el disco, pero permite a las aplicaciones buscar un archivo en el sistema de archivos utilizando una versión codificada equivalente del nombre del archivo.
dir_index

Utiliza árboles b indexados para acelerar las búsquedas de nombres en directorios grandes. Esta característica es compatible con los sistemas de archivos ext3 y ext4, y es ignorada por los sistemas de archivos ext2.
dir_nlink

Normalmente, ext4 permite que un inodo no tenga más de 65.000 enlaces duros. Esto se aplica tanto a archivos regulares como a directorios, lo que significa que no puede haber más de 64.998 subdirectorios en un directorio (porque cada una de las entradas '.' y '..', así como la entrada del directorio para el directorio en su directorio padre, cuenta como un enlace duro). Esta característica elimina este límite haciendo que ext4 use un conteo de enlaces de 1 para indicar que el número de enlaces duros a un directorio no se conoce cuando el conteo de enlaces podría exceder el límite máximo.
ea_inode

Normalmente, los atributos extendidos de un archivo y los metadatos asociados deben caber dentro del inodo o del bloque de atributos extendidos asociado al inodo. Esta característica permite que el valor de cada atributo extendido se coloque en los bloques de datos de un inodo separado si es necesario, aumentando el límite en el tamaño y el número de atributos extendidos por archivo.
encrypt

Habilita el soporte para el cifrado a nivel de sistema de archivos de los bloques de datos y nombres de archivo. Los metadatos del inodo (marcas de tiempo, tamaño del archivo, propiedad de usuario/grupo, etc.) *no* se cifran.
Esta característica es más útil en sistemas de archivos con múltiples usuarios, o donde no todos los archivos deben ser cifrados. En muchos casos de uso, especialmente en sistemas de un solo usuario, el cifrado en la capa del dispositivo de bloques utilizando dm-crypt puede proporcionar una seguridad mucho mayor.
ext_attr

Esta característica habilita el uso de atributos extendidos. Esta característica es compatible con ext2, ext3 y ext4.
extent

Esta característica de ext4 permite que el mapeo de los números de bloque lógicos para un inodo particular a los bloques físicos en el dispositivo de almacenamiento se almacene utilizando un árbol de extensiones, que es una estructura de datos más eficiente que el esquema tradicional de bloques indirectos utilizado por los sistemas de archivos ext2 y ext3. El uso del árbol de extensiones reduce la sobrecarga de bloques de metadatos, mejora el rendimiento del sistema de archivos y disminuye la necesidad de ejecutar e2fsck(8) en el sistema de archivos. (Nota: tanto extent como extents son aceptados como nombres válidos para esta característica por razones históricas/compatibilidad con versiones anteriores.)
extra_isize

Esta característica de ext4 reserva una cantidad específica de espacio en cada inodo para metadatos extendidos, como marcas de tiempo en nanosegundos y la hora de creación del archivo, incluso si el kernel actual no necesita reservar tanto espacio. Sin esta característica, el kernel reservará la cantidad de espacio para las características que necesita actualmente, y el resto puede ser consumido por atributos extendidos.

Para que esta característica sea útil, el tamaño del inodo debe ser de 256 bytes o mayor.

filetype

Esta característica habilita el almacenamiento de información de tipo de archivo en las entradas de directorio. Esta característica es compatible con ext2, ext3 y ext4.
flex_bg

Esta característica de ext4 permite que los metadatos de cada grupo de bloques (mapas de bits de asignación y tablas de inodos) se coloquen en cualquier lugar de los medios de almacenamiento. Además, mke2fs colocará los metadatos de cada grupo de bloques juntos comenzando en el primer grupo de bloques de cada grupo "flex_bg". El tamaño del grupo flex_bg se puede especificar usando la opción -G.
has_journal

Crea un diario para garantizar la coherencia del sistema de archivos incluso después de apagados inesperados. Establecer la característica del sistema de archivos es equivalente a usar la opción -j con mke2fs o tune2fs. Esta característica es compatible con ext3 y ext4, e ignorada por el controlador del sistema de archivos ext2.
huge_file

Esta característica de ext4 permite que los archivos sean de más de 2 terabytes de tamaño.
inline_data
Permite que los datos se almacenen en el área del inodo y de atributos extendidos.
journal_dev

Esta característica se habilita en el superbloque encontrado en un dispositivo de diario externo. El tamaño del bloque para el diario externo debe ser el mismo que el del sistema de archivos que lo utiliza.
El dispositivo de diario externo puede ser utilizado por un sistema de archivos especificando la opción -J device=<dispositivo-externo> a mke2fs(8) o tune2fs8).
large_dir

Esta característica aumenta el límite en el número de archivos por directorio al elevar el tamaño máximo de los directorios y, para los directorios de árboles b indexados,
(ver dir_index ), la altura máxima del árbol b hasheado utilizado para almacenar las entradas del directorio. large_file

prohibir que esos kernels montaran sistemas de archivos que no podían entender.

Opciones de montaje para ext3

El sistema de archivos ext3 es una versión del sistema de archivos ext2 que ha sido mejorada con registro (journaling). Soporta las mismas opciones que ext2, así como las siguientes adiciones:

journal_dev=devnum/journal_path=path
Cuando los números mayor/menor del dispositivo de registro externo han cambiado, estas opciones permiten al usuario especificar la nueva ubicación del registro. El dispositivo de registro se identifica ya sea a través de sus nuevos números mayor/menor codificados en devnum, o a través de una ruta al dispositivo.
norecovery/noload
No cargar el registro al montar. Tenga en cuenta que si el sistema de archivos no fue desmontado limpiamente, omitir la reproducción del registro llevará a que el sistema de archivos contenga inconsistencias que pueden causar cualquier número de problemas.
data={journal|ordered|writeback}
Especifica el modo de registro para los datos de los archivos. Los metadatos siempre se registran. Para usar modos distintos de ordered en el sistema de archivos raíz, pase el modo al núcleo como pararrametro de arranque, p. ej. rootflags=data=journal.
journal
Todos los datos se confirman en el registro antes de ser escritos en el sistema de archivos principal.
ordered
Este es el modo por defecto. Todos los datos se fuerzan directamente hacia el sistema de archivos principal antes de que sus metadatos se confirmen en el registro.
writeback
El orden de los datos no se conserva: los datos pueden escribirse en el sistema de archivos principal después de que sus metadatos se hayan confirmado en el registro. Se rumorea que esta es la opción de mayor rendimiento. Garantiza la integridad interna del sistema de archivos, sin embargo, puede permitir que datos antiguos aparezcan en los archivos después de un fallo y la recuperación del registro.
data_err=ignore
Solo imprimir un mensaje de error si ocurre un error en un búfer de datos de archivo en modo ordered.
data_err=abort
Abortar el registro si ocurre un error en un búfer de datos de archivo en modo ordered.
barrier=0 / barrier=1
Esto deshabilita/habilita el uso de barreras de escritura en el código jbd. barrier=0 deshabilita, barrier=1 habilita (por defecto). Esto también requiere una pila de E/S que pueda soportar barreras, y si jbd obtiene un error en una escritura de barrera, volverá a deshabilitar las barreras con una advertencia. Las barreras de escritura imponen un ordenamiento adecuado en disco de las confirmaciones del registro, haciendo que las cachés de escritura volátiles del disco sean seguras de usar, con alguna penalización de rendimiento. Si sus discos tienen respaldo de batería de una u otra manera, deshabilitar las barreras puede mejorar el rendimiento de forma segura.
commit=nrsec
Iniciar una confirmación del registro cada nrsec segundos. El valor por defecto es 5 segundos. Cero significa por defecto.
user_xattr
Habilitar Atributos Extendidos de Usuario. Véase la página de manual attr(5) .
jqfmt={vfsold|vfsv0|vfsv1}
Aparte del viejo sistema de cuotas (como en ext2, jqfmt=vfsold también conocido como cuotas de versión 1), ext3 también soporta cuotas registradas (cuotas de versión 2). jqfmt=vfsv0 o jqfmt=vfsv1 habilitan las cuotas registradas. Las cuotas registradas tienen la ventaja de que incluso después de un fallo no se requiere ninguna comprobación de cuotas. Cuando la característica de sistema de archivos quota está habilitada, se usan automáticamente las cuotas registradas, y esta opción de montaje se ignora.
usrjquota=aquota.user|grpjquota=aquota.group
Para las cuotas registradas (jqfmt=vfsv0 o jqfmt=vfsv1), las opciones de montaje usrjquota=aquota.user y grpjquota=aquota.group son requeridas para decirle al sistema de cuotas qué archivos de base de datos de cuotas usar. Cuando la característica de sistema de archivos quota está habilitada, se usan automáticamente las cuotas registradas, y esta opción de montaje se ignora.

Opciones de montaje para ext4

El sistema de archivos ext4 es un nivel avanzado del sistema de archivos ext3 que incorpora mejoras de escalabilidad y fiabilidad para soportar sistemas de archivos grandes.

Las opciones journal_dev, journal_path, norecovery, noload, data, commit, orlov, oldalloc, [no]user_xattr, [no]acl, bsddf, minixdf, debug, errors, data_err, grpid, bsdgroups, nogrpid, sysvgroups, resgid, resuid, sb, quota, noquota, nouid32, grpquota, usrquota, usrjquota, grpjquota, y jqfmt son compatibles hacia atrás con ext3 o ext2.

journal_checksum | nojournal_checksum
La opción journal_checksum habilita la suma de comprobación de las transacciones del registro. Esto permitirá al código de recuperación en e2fsck y al núcleo detectar corrupción en el núcleo. Es un cambio compatible y será ignorado por núcleos más antiguos.
journal_async_commit
El bloque de confirmación puede escribirse en disco sin esperar a los bloques de descriptor. Si está habilitado, los núcleos más antiguos no pueden montar el dispositivo. Esto habilitará 'journal_checksum' internamente.
barrier=0 / barrier=1 / barrier / nobarrier
Estas opciones de montaje tienen el mismo efecto que en ext3. Las opciones de montaje "barrier" y "nobarrier" se añaden por consistencia con otras opciones de montaje de ext4.

El sistema de archivos ext4 habilita las barreras de escritura por defecto.

inode_readahead_blks=n
Este parámetro de ajuste controla el número máximo de bloques de la tabla de inodos que el algoritmo de lectura anticipada de la tabla de inodos de ext4 pre-leerá en la caché de búfer. El valor debe ser una potencia de 2. El valor por defecto es 32 bloques.
stripe=n
Número de bloques del sistema de archivos que mballoc intentará usar para el tamaño y la alineación de la asignación. Para sistemas RAID5/6, este debería ser el número de discos de datos * tamaño de trozo de RAID en bloques del sistema de archivos.
delalloc
Diferir la asignación de bloques hasta el momento de la escritura.
nodelalloc
Deshabilitar la asignación diferida. Los bloques se asignan cuando los datos se copian del usuario a la caché de páginas.
max_batch_time=usec
Cantidad máxima de tiempo que ext4 debería esperar a que operaciones adicionales del sistema de archivos se agrupen junto con una operación de escritura síncrona. Dado que una operación de escritura síncrona va a forzar una confirmación y luego una espera a que la E/S se complete, no cuesta mucho, y puede ser una enorme ganancia de rendimiento, esperamos una pequeña cantidad de tiempo para ver si alguna otra transacción puede aprovecharse de la escritura síncrona. El algoritmo usado está diseñado para ajustarse automáticamente a la velocidad del disco, midiendo la cantidad de tiempo (de media) que tarda en finalizar la confirmación de una transacción. Llame a este tiempo el "tiempo de confirmación". Si el tiempo que la transacción ha estado activa es menor que el tiempo de confirmación, ext4 intentará dormir durante el tiempo de confirmación para ver si otras operaciones se unirán a la transacción. El tiempo de confirmación está limitado por max_batch_time, que por defecto es 15000 µs (15 ms). Esta optimización puede desactivarse por completo estableciendo max_batch_time a 0.
min_batch_time=usec
Este parámetro establece el tiempo de confirmación (como se describió arriba) para que sea al menos min_batch_time. Por defecto es cero microsegundos. Aumentar este parámetro puede mejorar el rendimiento de cargas de trabajo síncronas de múltiples hilos en discos muy rápidos, a costa de aumentar la latencia.
journal_ioprio=prio
La prioridad de E/S (de 0 a 7, donde 0 es la prioridad más alta) que debe usarse para las operaciones de E/S enviadas por kjournald2 durante una operación de confirmación. El valor predeterminado es 3, que es una prioridad ligeramente más alta que la prioridad de E/S predeterminada.
abort
Simula los efectos de llamar a ext4_abort() con fines de depuración. Esto se usa normalmente al remontar un sistema de archivos que ya está montado.
auto_da_alloc|noauto_da_alloc
Muchas aplicaciones defectuosas no usan fsync() al reemplazar archivos existentes mediante patrones como

fd = open("foo.new")/write(fd,...)/close(fd)/ rename("foo.new", "foo")

o, peor aún,

fd = open("foo", O_TRUNC)/write(fd,...)/close(fd).

Si auto_da_alloc está habilitado, ext4 detectará los patrones de reemplazo mediante rename y de reemplazo mediante truncate, y forzará que cualquier bloque de asignación diferida se asigne de modo que, en la siguiente confirmación del diario, en el modo data=ordered predeterminado, los bloques de datos del nuevo archivo se forcen al disco antes de que la operación rename() se confirme. Esto proporciona aproximadamente el mismo nivel de garantías que ext3, y evita el problema de "longitud cero" que puede ocurrir cuando el sistema se bloquea antes de que los bloques de asignación diferida se forcen al disco.

noinit_itable
No inicializa ningún bloque de tabla de inodos no inicializado en segundo plano. Esta función puede ser utilizada por los CD de instalación para que el proceso de instalación pueda completarse lo más rápido posible; el proceso de inicialización de la tabla de inodos se pospondría hasta la próxima vez que se monte el sistema de archivos.
init_itable=n
El código de inicialización perezosa de la tabla de inodos esperará n veces el número de milisegundos que tardó en poner a cero la tabla de inodos del grupo de bloques anterior. Esto minimiza el impacto en el rendimiento del sistema mientras se inicializa la tabla de inodos del sistema de archivos.
discard/nodiscard
Controla si ext4 debe emitir comandos discard/TRIM al dispositivo de bloque subyacente cuando se liberan bloques. Esto es útil para dispositivos SSD y LUNs dispersos/sin aprovisionamiento, pero está desactivado por defecto hasta que se haya realizado una prueba suficiente.
block_validity/noblock_validity
Esta opción habilita/deshabilita la funcionalidad del kernel para rastrear los bloques de metadatos del sistema de archivos dentro de las estructuras de datos internas. Esto permite al asignador de múltiples bloques y a otras rutinas localizar rápidamente los extents que podrían superponerse con los bloques de metadatos del sistema de archivos. Esta opción está destinada para fines de depuración y, como afecta negativamente al rendimiento, está desactivada por defecto.
dioread_lock/dioread_nolock
Controla si ext4 debe usar o no el bloqueo de lectura DIO. Si se especifica la opción dioread_nolock, ext4 asignará un extent no inicializado antes de la escritura del búfer y convertirá el extent a inicializado después de que la E/S se complete. Este enfoque permite al código de ext4 evitar usar el mutex del inodo, lo que mejora la escalabilidad en almacenamientos de alta velocidad. Sin embargo, esto no funciona con el diario de datos y la opción dioread_nolock se ignorará con una advertencia del kernel. Tenga en cuenta que la ruta de código dioread_nolock solo se usa para archivos basados en extents. Debido a las restricciones que implica esta opción, está desactivada por defecto (por ejemplo, dioread_lock).
max_dir_size_kb=n
Esto limita el tamaño de los directorios de modo que cualquier intento de expandirlos más allá del límite especificado en kilobytes causará un error ENOSPC. Esto es útil en entornos con memoria limitada, donde un directorio muy grande puede causar graves problemas de rendimiento o incluso provocar el asesino de memoria (Out Of Memory killer). (Por ejemplo, si solo hay 512 MiB de memoria disponible, un directorio de 176 MiB puede dificultar seriamente el funcionamiento del sistema.)
i_version
Habilita la compatibilidad con la versión de inodo de 64 bits. Esta opción está desactivada por defecto.
nombcache
Esta opción desactiva el uso de mbcache para la deduplicación de atributos extendidos. En sistemas donde los atributos extendidos rara vez o nunca se comparten entre archivos, el uso de mbcache para la deduplicación añade una sobrecarga computacional innecesaria.
prjquota
La opción de montaje prjquota habilita la compatibilidad con cuotas de proyecto en el sistema de archivos. Necesita las utilidades de cuotas para habilitar y gestionar realmente el sistema de cuotas. Esta opción de montaje requiere la project característica del sistema de archivos.

ATRIBUTOS DE ARCHIVOS

Los sistemas de archivos ext2, ext3 y ext4 admiten la configuración de los siguientes atributos de archivo en sistemas Linux usando la chattr(1) utilidad:

a - solo añadir (append only)

A - no actualizar atime

d - no volcar (no dump)

D - actualizaciones de directorio síncronas

i - inmutable

S - actualizaciones síncronas

u - no borrable

Además, los sistemas de archivos ext3 y ext4 admiten el siguiente indicador:

j - diario de datos (data journaling)

Finalmente, el sistema de archivos ext4 también admite el siguiente indicador:

e - formato de extents

Para obtener descripciones de estos indicadores de atributos, consulte la chattr(1) página del manual.
