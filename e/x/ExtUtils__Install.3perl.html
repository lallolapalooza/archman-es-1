ExtUtils::Install(3perl) Guía de referencia para programadores de Perl ExtUtils::Install(3perl)

NOMBRE

ExtUtils::Install - instala archivos de aquí para allá

SINOPSIS

use ExtUtils::Install;
install({ 'blib/lib' => 'some/install/dir' } );
uninstall($packlist);
pm_to_blib({ 'lib/Foo/Bar.pm' => 'blib/lib/Foo/Bar.pm' });

VERSIÓN

2.22

DESCRIPCIÓN

Maneja la instalación y desinstalación de módulos de perl, scripts, páginas de manual, etc...

Tanto install() como uninstall() son específicas de la forma en que ExtUtils::MakeMaker maneja la instalación y desinstalación de módulos de perl. No están diseñadas como herramientas de propósito general.

En algunos sistemas operativos como Win32, la instalación puede no ser posible hasta después de que se haya producido un reinicio. Esto puede tener consecuencias variables: eliminar una DLL antigua no afecta a los programas que usan la nueva, pero si una nueva DLL no se puede instalar correctamente hasta el reinicio, entonces todo lo que dependa de ella debe esperar. La variable de paquete

$ExtUtils::Install::MUST_REBOOT

se usa para almacenar este estado.

Si esta variable es verdadera, entonces tal operación ha ocurrido y todo lo que dependa de este módulo no puede proceder hasta que se haya producido un reinicio.

Si este valor está definido pero es falso, entonces tal operación ha ocurrido, pero no debería afectar a las operaciones posteriores.

Funciones

install

# formas obsoletas
install(\%from_to);
install(\%from_to, $verbose, $dry_run, $uninstall_shadows,
            $skip, $always_copy, \%result);
# forma recomendada a partir de 1.47
install([
    from_to => \%from_to,
    verbose => 1,
    dry_run => 0,
    uninstall_shadows => 1,
    skip => undef,
    always_copy => 1,
    result => \%install_results,
]);

Copia cada árbol de directorios de %from_to a su valor correspondiente preservando marcas de tiempo y permisos.

Hay dos claves con un significado especial en el hash: "read" y "write". Estas contienen archivos packlist. Después de que la copia esté hecha, install() escribirá la lista de archivos de destino en $from_to{write}. Si $from_to{read} es proporcionado, el contenido de este archivo se fusionará en el archivo escrito. El archivo leído y el escrito pueden ser idénticos, pero en AFS es bastante probable que la gente esté instalando en un directorio diferente de aquel donde los archivos aparecen más tarde.

Si $verbose es verdadero, imprimirá cada archivo eliminado. El valor por defecto es falso. Esto es "make install VERBINST=1". $verbose valores que llegan hasta 5 muestran cada vez más salida de diagnóstico.

Si $dry_run es verdadero, solo imprimirá lo que iba a hacer sin hacerlo realmente. El valor por defecto es falso.

Si $uninstall_shadows es verdadero, cualquier versión diferente a lo largo de @INC será desinstalada. Esto es "make install UNINST=1"

A partir de 1.37_02 install() soporta el uso de una lista de patrones para filtrar archivos que no deberían ser instalados. Si $skip es omitido o indefinido, entonces la instalación intentará leer la lista de INSTALL.SKIP en el CWD. Este archivo es una lista de expresiones regulares y es igual al archivo MANIFEST.SKIP usado por ExtUtils::Manifest.

Un INSTALL.SKIP de sitio por defecto puede ser proporcionado estableciendo la variable de entorno EU_INSTALL_SITE_SKIPFILE, esto solo se usará cuando no haya un INSTALL.SKIP específico de la distribución. Si la variable de entorno EU_INSTALL_IGNORE_SKIP es verdadera, entonces no se realizará ningún filtrado de archivos de instalación.

Si $skip es indefinido, entonces el archivo de omisión será autodetectado y usado si se encuentra. Si $skip es una referencia a un array, se asume que el array contiene la lista de patrones, si $skip es un valor verdadero que no es una referencia, se asume que es el nombre de archivo que contiene la lista de patrones, cualquier otro valor de $skip se toma como que no debe ocurrir ningún filtrado de instalación.

Cambios a partir de la versión 1.47

A partir de la versión 1.47 se hicieron las siguientes adiciones a la interfaz de install. Note que se recomienda el nuevo estilo de argumentos y el uso del hash %result .

El parámetro $always_copy que cuando es verdadero hace que los archivos se actualicen independientemente de si han cambiado, si está definido pero es falso, entonces las copias se hacen solo si los archivos han cambiado, si está indefinido, entonces el valor de la variable de entorno EU_INSTALL_ALWAYS_COPY se usa por defecto.

El hash %result será poblado con las varias claves/subhashes que reflejan la instalación. Actualmente estas claves y su estructura son:

install             => { $target    => $source },
install_fail        => { $target    => $source },
install_unchanged   => { $target    => $source },
install_filtered    => { $source    => $pattern },
uninstall           => { $uninstalled => $source },
uninstall_fail      => { $uninstalled => $source },

donde $source es la especificación de archivo del archivo que se está instalando. $target es a dónde se está instalando, y $uninstalled es cualquier archivo sombra que esté en @INC o $ENV{PERL5LIB} u otras ubicaciones estándar, y $pattern es el patrón que causó que un archivo fuente fuera omitido. En el futuro se añadirán más claves, como para mostrar directorios creados, sin embargo esto requiere cambios en otros módulos y por lo tanto debe esperar.

Estas claves serán pobladas antes de que se lancen excepciones si hay un error.

Note que todas las actualizaciones del hash %result son aditivas, el hash no será limpiado antes de su uso, permitiendo así que los resultados de estado de muchas instalaciones se agreguen fácilmente.

NUEVO ESTILO DE ARGUMENTOS

Si solo hay un argumento y es una referencia a un array entonces se asume que el array contiene una lista de pares clave-valor que especifican las opciones. En este caso la opción "from_to" es obligatoria. Este estilo significa que no tiene que proporcionar una lista críptica de argumentos y puede usar una lista de argumentos auto documentada que es más fácil de entender.

Esta es ahora la interfaz recomendada para install().

RETORNO

Si todas las acciones fueron exitosas, install devolverá una referencia a hash de los resultados como se describió arriba para el parámetro $result . Si alguna acción falla, entonces install morirá, por lo tanto se recomienda pasar el parámetro $result en lugar de usar el valor de retorno. Si el parámetro result es proporcionado, entonces la referencia a hash devuelta será la referencia a hash pasada.

install_default

DESACONSEJADO

install_default();
install_default($fullext);

Llama a install() con argumentos para copiar un módulo desde blib/ a la ubicación de instalación de sitio por defecto.

$fullext es el nombre del módulo convertido a un directorio (ej. Foo::Bar sería Foo/Bar). Si $fullext no es especificado, intentará leerlo desde @ARGV.

Esto es principalmente útil para scripts de instalación.

NOTA Esta función no es realmente útil debido a la ubicación de instalación codificada de forma rígida sin forma de controlar los directorios de sitio vs núcleo vs proveedor y la extraña forma en que se da el nombre del módulo. Considere su uso desaconsejado.

uninstall

uninstall($packlist_file);
uninstall($packlist_file, $verbose, $dont_execute);

Elimina los archivos listados en un $packlist_file.

Si $verbose es verdadero, imprimirá cada archivo eliminado. El valor por defecto es falso.

Si $dont_execute es verdadero, solo imprimirá lo que iba a hacer sin hacerlo realmente. El valor por defecto es falso.

pm_to_blib(\%from_to);
pm_to_blib(\%from_to, $autosplit_dir);
pm_to_blib(\%from_to, $autosplit_dir, $filter_cmd)
;
