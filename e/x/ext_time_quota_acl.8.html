ext_time_quota_acl - Ayudante de acl externa de cuota de tiempo de

Squid.

Versión

1.
0

SINOPSI

S

ext_time_quota_acl [-b base de datos] [-d nivel]

[-p longitud de pausa]
[-h] archivo de configuración

DESCRIPCIÓ

N

ext_time_quota_acl permite a un administrador definir presupuestos de tiempo para los usuarios de squid para limitar el tiempo de uso de

squid.

Esto es útil para asignaciones de tiempo de almuerzo corporativo, instalaciones de portales wifi

de pago por minuto o para el control parental de los niños. El administrador puede definir un p
resupuesto de tiempo (por ejemplo, 1 hora al día) que se hace cumplir a través de este ayudante.

.

comandos.

Este archivo contiene

CONFIGURACIÓ

N

Las cuotas de tiempo de los usuarios se definen en un archivo de texto que reside típicamente en /etc/squid/time_quota. Cualquier línea que comience con "#" contiene un comentario y se ignora. Cada línea debe comenzar con un usuario seguido de un presupuesto de tiempo y un período de tiempo correspondiente separado por "/". Aquí hay un archivo de

ejemplo:
# usuario presupuesto / período
john 8h / 1d
littlejoe 1h / 1d
babymary 30m / 1w

John tiene un presupuesto de tiempo de 8 horas cada día, a littlejoe solo se le permite 1 hora y a la pobre babymary solo 30 minutos a la

semana.

Puede usar "s" para segundos, "m" para minutos, "h" para horas, "d" para días y "w" para semanas. Los valores numéricos pueden darse como valores enteros o con una fracción. Por ejemplo, "0.5h" significa 30

minutos.

Este ayudante se configura en squid.conf usando la directiva external_acl_type y luego controles de acceso que la usan para permitir o

denegar.

Aquí hay un

ejemplo.
# Asegurarse de que los usuarios tienen un inicio de sesión válido. Necesitamos su nombre de usuario.
acl users proxy_auth REQUIRED
http_access deny !users
# Definir el programa y el archivo de cuota
external_acl_type time_quota ttl=60 children-max=1 %LOGIN /usr/libexec/ext_time_quota_acl /etc/squid/time_quota
acl noquota src all
acl time_quota external time_quota
deny_info ERR_ACL_TIME_QUOTA_EXCEEDED noquota
http_access deny !time_quota
noquota

En este ejemplo, después de reiniciar Squid, debería permitir el acceso solo a los usuarios mientras tengan presupuesto de tiempo restante. Si se excede el presupuesto, se le presentará al usuario una página de error

informándole.

En este ejemplo usamos un control de acceso de usuarios separado y la ACL noquota para mantener separadas la petición de nombre de usuario y contraseña y los mensajes de cuota

excedida.

El usuario es solo un valor de clave única. El ejemplo anterior usa %LOGIN y el nombre de usuario, pero cualquiera de las etiquetas de formato external_acl_type puede sustituirse en su lugar. %EXT_TAG , %LOGIN , %EXT_USER , %SRC , %SRCEUI48 , y %SRCEUI64 son todos candidatos probables para la identificación del cliente. La wiki de Squid tiene más ejemplos en https://wiki.squid-cache.org/ConfigExample

s
.

LIMITACIONE

S

Este ayudante solo controla el acceso a Internet a través de HTTP. No controla otros protocolos, como VOIP, ICQ, IRC, FTP, IMAP, SMTP o

SSH.

Los navegadores de escritorio generalmente pueden manejar la autenticación a proxies HTTP como squid . Pero cada vez más programas y dispositivos diferentes (teléfonos inteligentes, juegos en dispositivos móviles, ...) están usando Internet a través de HTTP. Estos dispositivos a menudo no pueden trabajar a través de un proxy autenticador. Se requieren medios distintos a la autenticación %LOGIN para autorizar estos dispositivos y

software.

Un control más general del acceso a Internet podría ser un enfoque de portal cautivo (co

mo pfSense o ChilliSpot) usando %SRC, %SRCEUI48 y %SRCEUI64 como claves o tal vez una so
lución 802.11X. Pero esta última a menudo no es compatible con los dispositivos móviles.

IMPLEMENTACIÓ

N

Cuando se llama al ayudante, se le preguntará si el usuario actual tiene permitido acceder a squid. El ayudante reducirá el presupuesto de tiempo restante de este usuario y devolverá OK si queda presupuesto. De lo contrario, devolverá ERR

.

El parámetro ttl=N en squid.conf determina con qué frecuencia se llamará al ayudante, la configuración de ejemplo usa un TTL de 1 minuto. La interacción es que Squid solo llamará al ayudante en nuevas peticiones si han pasado más segundos que el TTL desde la última comprobación. Este manejo crea una cantidad de deslizamiento fuera de la cuota por la cantidad que se haya configurado. El TTL puede establecerse tan corto como se desee, hasta e incluyendo cero. Aunque se recomiendan valores de 1 o más debido a una resolución de cuota de un

segundo.

Si el período de tiempo configurado (por ejemplo, "1w" para babymary) ha terminado, el presupuesto de tiempo se restaurará al valor configurado, permitiendo así al usuario acceder a squid con un presupuesto

nuevo.

Si el tiempo entre la petición actual y la petición anterior es mayor que pauselen (por defecto 5 minutos y ajustable con el parámetro de línea de comandos -p ), la petición actual se considerará como una nueva petición y el presupuesto de tiempo no se disminuirá. Si el tiempo es menor que pauselen , entonces ambas peticiones se considerarán como parte del mismo período de tiempo activo y el presupuesto de tiempo se disminuirá por

la diferencia de tiempo. Esto permite al usuario tomar descansos arbitra
rios durante el acceso a Internet sin perder su presupuesto de tiempo.
