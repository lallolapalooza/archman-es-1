ExtUtils::ParseXS(3perl) Guía de referencia para programadores de Perl ExtUtils::ParseXS(3perl)

NOMBRE

ExtUtils::ParseXS - convierte código XS de Perl en código C

SINOPSIS

use ExtUtils::ParseXS;
my $pxs = ExtUtils::ParseXS->new;
$pxs->process_file( filename => 'foo.xs' );
$pxs->process_file( filename => 'foo.xs',
                    output => 'bar.c',
                    'C++' => 1,
                    typemap => 'path/to/typemap',
                    hiertype => 1,
                    except => 1,
                    versioncheck => 1,
                    linenumbers => 1,
                    optimize => 1,
                    prototypes => 1,
                    die_on_error => 0,
                  );
# Interfaz heredada no orientada a objetos usando un singleton:
use ExtUtils::ParseXS qw(process_file);
process_file( filename => 'foo.xs' );

DESCRIPCIÓN

"ExtUtils::ParseXS" compilará código XS en código C incrustando las construcciones necesarias para permitir que las funciones C manipulen valores Perl y crea el enlace necesario para que Perl acceda a esas funciones. El compilador usa mapas de tipos (typemaps) para determinar cómo asignar los parámetros y variables de las funciones C a valores Perl.

El compilador buscará archivos de mapa de tipos llamados typemap. Usará la siguiente ruta de búsqueda para encontrar los mapas de tipos predeterminados, con el mapa de tipos más a la derecha teniendo prioridad.

../../../typemap:../../typemap:../typemap:typemap

EXPORTACIÓN

Ninguna por defecto. process_file() y/o report_error_count() pueden ser exportados bajo petición. Se desaconseja usar la interfaz funcional.

MÉTODOS

$pxs->new()
Devuelve un nuevo objeto analizador/compilador XS vacío.
$pxs->process_file()
Este método procesa un archivo XS y envía la salida a un archivo C. El método puede ser llamado como una función (esta es la interfaz heredada) y entonces usará un singleton como invocante.

Los parámetros con nombre controlan cómo se realiza el procesamiento. Se aceptan los siguientes parámetros:

filename
Esta es la ruta completa del archivo XS a abrir y procesar. process_file() normalmente hará chdir() al nombre base del archivo.

El nombre de archivo puede ser una referencia a una cadena, en cuyo caso las líneas de la cadena forman el contenido del archivo "input" (entrada), usando el mecanismo estándar "open $fh, '<', \$string" .

C++
Añade "extern "C"" al código C. El valor predeterminado es falso.
hiertype
Conserva "::" en los nombres de tipo para que los tipos jerárquicos de C++ puedan ser asignados. El valor predeterminado es falso.
except
Añade manejadores de excepciones (stubs) al código C. El valor predeterminado es falso.
typemap
Indica que un mapa de tipos proporcionado por el usuario debe tener prioridad sobre los mapas de tipos predeterminados. Un solo mapa de tipos puede especificarse como una cadena, o múltiples mapas de tipos pueden especificarse en una referencia a array, con el último mapa de tipos teniendo la mayor prioridad.
prototypes
Genera código de prototipos para todos los xsubs. El valor predeterminado es falso.
versioncheck
Asegura en tiempo de ejecución que el archivo objeto (derivado del ".xs" archivo) y los ".pm" archivos tengan el mismo número de versión. El valor predeterminado es verdadero.
linenumbers
Añade "#line" directivas a la salida C para que los mensajes de error parezcan provenir del archivo XS original. El valor predeterminado es verdadero.
optimize
Habilita ciertas optimizaciones. La única optimización que actualmente está afectada es el uso de targets por el código C de salida (ver perlguts). No optimizar puede ralentizar significativamente el código generado, pero esta es la forma en que xsubpp de 5.005 y anteriores operaba. El valor predeterminado es optimizar.
inout
Habilita el reconocimiento de "IN", "OUT_LIST" y "INOUT_LIST" declaraciones. El valor predeterminado es verdadero.
argtypes
Habilita el reconocimiento de descripciones de firma de función tipo ANSI. El valor predeterminado es verdadero.
s
Nota del mantenedor: No tengo idea de lo que hace esto. ¿Elimina prefijos de función?
die_on_error
Normalmente ExtUtils::ParseXS terminará el programa con un exit(1) después de imprimir los detalles de la excepción en STDERR mediante (warn). Esto puede ser incómodo cuando se usa programáticamente y no a través de xsubpp, por lo que esta opción puede usarse para causar que muera en su lugar proporcionando un valor verdadero. Cuando no se proporciona, esto usa por defecto el valor de $ExtUtils::ParseXS::DIE_ON_ERROR que a su vez tiene como valor predeterminado falso.
$pxs->report_error_count()
Este método devuelve el número de errores [de un cierto tipo] encontrados durante el procesamiento del archivo XS.

El método puede ser llamado como una función (esta es la interfaz heredada) y entonces usará un singleton como invocante.
