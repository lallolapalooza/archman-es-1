Exporter::Tiny::Manual::QuickStart(3) Documentación de Perl contribuida por el usuario Exporter::Tiny::Manual::QuickStart(3)

NOMBRE

Exporter::Tiny::Manual::QuickStart - la forma más rápida de empezar a usar Exporter::Tiny

SINOPSIS

package MyUtils;

use Exporter::Shiny qw( frobnicate );

sub frobnicate {
   ...;   # tu código aquí
}

1;

Ahora la gente puede usar tu módulo así:

use MyUtils "frobnicate";

frobnicate(42);

O así:

use MyUtils "frobnicate" => { -as => "frob" };

frob(42);

DESCRIPCIÓN

Ver la sinopsis. Sí, es así de simple.

Próximos pasos

Exportaciones por defecto

Ten en cuenta que el módulo de la sinopsis no exporta nada por defecto. Si la gente carga "MyUtils" así:

use MyUtils;

Entonces no han importado ninguna función. Puedes especificar un conjunto por defecto de funciones a exportar así:

package MyUtils;

use Exporter::Shiny qw( frobnicate );

our @EXPORT = qw( frobnicate );

sub frobnicate { ... }

1;

O, si quieres ser una superestrella del rock:

package MyUtils;

use Exporter::Shiny our @EXPORT = qw( frobnicate );

sub frobnicate { ... }

1;

Etiquetas

Puedes proporcionar etiquetas para que la gente las use:

package MyUtils;

use Exporter::Shiny qw( frobnicate red green blue );

our %EXPORT_TAGS = (
   utils   => [qw/ frobnicate /],
   colours => [qw/ red green blue /],
);

sub frobnicate { ... }
sub red        { ... }
sub green      { ... }
sub blue       { ... }

1;

Y la gente ahora puede importar tus funciones así:

use MyUtils ":colours";

O así:

use MyUtils "-colours";

O aprovechar el hecho de que Perl cita mágicamente las palabras desnudas precedidas por un guion:

use MyUtils -colours;

Se definen automáticamente dos etiquetas para ti: "-default" (que es lo mismo que @EXPORT) y "-all" (que es la unión de @EXPORT y @EXPORT_OK). Si no te gustan, puedes anularlas:

our %EXPORT_TAGS = (
   default => \@some_other_stuff,
   all     => \@more_stuff,
);

Generadores

La exportación normalmente funciona copiando una subrutina de tu paquete al paquete de tu llamador. Pero a veces es más útil generar una subrutina *personalizada* para insertarla en el paquete de tu llamador. Esto es bastante fácil de hacer.

package MyUtils;

use Exporter::Shiny qw( frobnicate );

sub _generate_frobnicate {
   my ( $me, $name, $args, $globals ) = @_;
   my $caller = $globals->{into};

   return sub {
       ...;  # tu código aquí
   };
}

1;

El parámetro $me aquí es una cadena que contiene el nombre del paquete desde el que se está importando; $caller es el paquete de destino; $name es el nombre de la subrutina (en este caso "frobnicate"); y $args es un argumento personalizado para esta función. (Por convención, $args suele ser un hashref.)

# El hashref { foo => 42 } es $args arriba.
#
use MyUtils "frobnicate" => { foo => 42 };

Evitar Exporter::Shiny

Exporter::Shiny es una pequeña capa alrededor de Exporter::Tiny. Debería hacer mayormente lo que quieres, pero a veces preferirás usar Exporter::Tiny directamente.

El ejemplo en la sinopsis podría haber sido escrito así:

package MyUtils;

use parent "Exporter::Tiny";
our @EXPORT_OK = qw( frobnicate );

sub frobnicate {
   ...;   # tu código aquí
}

1;

Lo que hace Exporter::Shiny es principalmente establecer @EXPORT_OK para ti y configurar la herencia de la clase base (Exporter::Tiny).

Exporter::Shiny también establece $INC{'MyUtils.pm'} para ti, lo cual generalmente marca poca diferencia, pero es útil en algunos casos extremos.
