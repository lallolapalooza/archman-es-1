La configuración simple funciona igual que con Exporter; herede de Exporter::Tiny

y use las

variables de paquete @EXPORT, @EXPORT_OK y %EXPORT_TAGS para listar las subrutinas a

exportar.

A diferencia de Exporter, Exporter::Tiny realiza la mayoría de sus funciones internas (incluida la resolución de nombres de etiquetas a nombres de subrutinas, la resolución de nombres de subrutinas a referencias de código y la instalación de referencias de código en el paquete de destino) como llamadas a métodos, lo que significa que su módulo (que es una subclase de Exporter::Tiny) puede sobrescribirlas para proporcionar un comportamiento

interesante.

Avanzado

Etiquetas

Puede definir etiquetas usando otras

etiquetas: 
use Exporter::Shiny qw(
   black white red green blue cyan magenta yellow
);

our %EXPORT_TAGS = (
   rgb        => [qw( red green blue )],
   cym        => [qw( cyan magenta yellow )],
   cymk       => [qw( black :cym )],
   monochrome => [qw( black white )],
   all        => [qw( :rgb :cymk :monochrome )],
)
;

rter::Tiny en un bucle infinito expan
diendo las etiquetas. No haga eso.

Más sobre

generadores

Exporter::Tiny siempre ha permitido que las subrutinas exportadas sean generadas (como Sub::Exporter), pero hasta la versión 0.025 no tenía una API especialmente atractiva para

ello.

Ahora, es fácil. Si desea generar una subrutina "foo" para exportar, listela en @EXPORT o @EXPORT_OK como de costumbre, y luego simplemente dé a su módulo exportador un método de clase llamado "_generate_foo"

. 
push @EXPORT_OK, 'foo';

sub _generate_foo {
   my $class = shift;
   my ($name, $args, $globals) = @_;

   return sub {
      ...;
   }
}

Mostramos cómo hacer eso en Exporter::Tiny::Manual::QuickStart, pero una cosa que no mostramos fue que $globals se pasa allí. Este es el hash de opciones globales, como se describe en Exporter::Tiny::Manual::Importing. A menudo puede ser útil. En particular, le dirá en qué paquete se destina a instalarse la subrutina

generada.

Para generar símbolos que no son código, nombre sus generadores

así: 
sub _generateScalar_Foo { ... }  # generar un símbolo $Foo
sub _generateArray_Bar  { ... }  # generar un símbolo @Bar
sub _generateHash_Baz   { ... }  # generar un símbolo
%Baz

También puede generar

etiquetas: 
my %constants;
BEGIN {
   %constants = (FOO => 1, BAR => 2);
}
use constant \%constants;

$EXPORT_TAGS{constants} = sub {
   my $class = shift;
   my ($name, $args, $globals) = @_;

   return keys(%constants);
}
;

Gancho

s

A veces, además de exportar cosas, desea realizar alguna configuración o algo

similar.

Puede definir un par de métodos de clase en su paquete, y se llamarán en el momento

adecuado: 
package MyUtils;

...;

sub _exporter_validate_opts {
   my $class = shift;
   my ($globals) = @_;

   ...;   # hacer cosas aquí

   $class->SUPER::_exporter_validate_opts(@_);
}

sub _exporter_validate_unimport_opts {
   my $class = shift;
   my ($globals) = @_;

   ...;   # hacer cosas aquí

   $class->SUPER::_exporter_validate_unimport_opts(@_);
}

La variable $globals es ese famoso hash de opciones globales. En particular, "$globals->{into}" es útil porque le dice qué paquete le ha

importado.

Como puede haber adivinado, estos métodos fueron originalmente destinados a

validar el hash de opciones globales, pero pueden usarse para realizar cualq
uier función general antes de que se realice el trabajo real de exportación.

internos

Una diferencia importante entre Exporter y Exporter::Tiny es que este último llama a todas sus funciones internas como métodos de clase. Esto significa que su subclase puede sobrescribirlos para alterar su

comportamiento.

Este método se llama para traducir un nombre de subrutina a un hash de pares nombre => referencia de código para exportar al llamador. En general, esto sería solo un hash con una clave y un valor, pero, por ejemplo, Type::Library sobrescribe este método para que "+Foo" se expanda a:

   to_Foo      => sub { $type->assert_coerce(@_) },

La implementación por defecto comprueba que el nombre esté permitido para ser exportado (usando el método "_exporter_permitted_regexp"), obtiene la referencia de código usando el generador si hay uno (o llamando a "can" en su exportador de lo contrario) y llama a "_exporter_fail" si no puede generar u obtener una referencia de
