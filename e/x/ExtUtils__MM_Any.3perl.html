NOMBRE

ExtUtils::MM_Any - Métodos MM agnósticos de plataforma

SINOPSIS

¡SOLO PARA USO INTERNO!
package ExtUtils::MM_SomeOS;
# Temporalmente, tienes que heredar de ambos. Pon MM_Any primero.
require ExtUtils::MM_Any;
require ExtUtils::MM_Unix;
@ISA = qw(ExtUtils::MM_Any ExtUtils::Unix);

DESCRIPCIÓN

¡SOLO PARA USO INTERNO!

ExtUtils::MM_Any es una superclase para el conjunto de módulos ExtUtils::MM_*. Contiene métodos que son inherentemente multiplataforma o que están escritos de una manera multiplataforma.

Hereda de ExtUtils::MM_Any y ExtUtils::MM_Unix. Esta es una solución temporal.

¡ESTO PUEDE SER TEMPORAL!

MÉTODOS

Cualquier método marcado como Abstracto debe ser implementado por las subclases.

Métodos auxiliares multiplataforma

Estos son métodos que ayudan a escribir código multiplataforma.

os_flavor Abstracto

my @os_flavor = $mm->os_flavor;

@os_flavor es el estilo de sistema operativo que es este, generalmente correspondiente al archivo MM_*.pm que estamos usando.

El primer elemento de @os_flavor es la familia principal (es decir, Unix, Windows, VMS, OS/2, etc.) y el resto son subfamilias.

Algunos ejemplos:

Cygwin98       ('Unix',  'Cygwin', 'Cygwin9x')
Windows        ('Win32')
Win98          ('Win32', 'Win9x')
Linux          ('Unix',  'Linux')
MacOS X        ('Unix',  'Darwin', 'MacOS', 'MacOS X')
OS/2           ('OS/2')

Esto se usa para escribir código para estilos de sistemas operativos. Ver os_flavor_is() para su uso.

os_flavor_is

my $is_this_flavor = $mm->os_flavor_is($this_flavor);
my $is_this_flavor = $mm->os_flavor_is(@one_of_these_flavors);

Comprueba si el sistema operativo actual es uno de los sabores dados.

Esto es útil para código como:

if( $mm->os_flavor_is('Unix') ) {
    $out = `foo 2>&1`;
}
else {
    $out = `foo`;
}

can_load_xs

my $can_load_xs = $self->can_load_xs;

Devuelve true si tenemos la capacidad de cargar XS.

Esto es importante porque miniperl, usado para construir módulos XS en el núcleo, no puede cargar XS.

can_run

use ExtUtils::MM;
my $runnable = MM->can_run($Config{make});

Si se llama en un contexto escalar, devolverá la ruta completa al binario que pediste si se encontró, o "undef" si no se encontró.

Si se llama en un contexto de lista, devolverá una lista de las rutas completas a las instancias del binario donde se encontraron en "PATH", o una lista vacía si no se encontró.

Copiado de IPC::Cmd, pero modificado como método (y se eliminó la $INSTANCES capacidad).

can_redirect_error

$useredirect = MM->can_redirect_error;

True si en un SO donde el operador qx (o backticks) puede redirigir "STDERR" hacia "STDOUT".

is_make_type

my $is_dmake = $self->is_make_type('dmake');

Devuelve true si "$self->make" es del tipo dado; las posibilidades son:

gmake    GNU make
dmake
nmake
bsdmake  BSD pmake-derived

can_dep_space

my $can_dep_space = $self->can_dep_space;

Devuelve true si "make" puede manejar (probablemente entrecomillando) dependencias que contienen un espacio. Actualmente se sabe que es true para GNU make, false para el derivado de BSD pmake.

quote_dep

$text = $mm->quote_dep($text);

Método que protege las constantes de valor único de Makefile (principalmente nombres de archivo), para que make aún las trate como valores únicos incluso si, inconveniente, tienen espacios. Si el programa make que se está usando no puede lograr tal protección y el texto dado lo necesitaría, lanza una excepción.

split_command

my @cmds = $MM->split_command($cmd, @args);

La mayoría de los SO tienen una longitud máxima de comando que pueden ejecutar a la vez. Los módulos grandes pueden generar fácilmente comandos que superan con creces ese límite. Es necesario dividir los comandos largos en una serie de comandos más cortos.

"split_command" devolverá una serie de @cmds cada uno procesando parte de los argumentos. Colectivamente procesarán todos los argumentos. Cada línea individual en @cmds no será más larga que $self->max_exec_len teniendo cuidado de tener en cuenta la expansión de macros.

$cmd debe incluir cualquier interruptor y argumentos iniciales repetidos. Si tiene saltos de línea, deben estar ya escapados.

Si no se dan @args , no se devolverán @cmds .

Los pares de argumentos siempre se conservarán en un solo comando, esto es una heurística para cosas como pm_to_blib y pod2man que trabajan con pares de argumentos. Esto hace que cosas como esto sean seguras:

$self->split_command($cmd, %pod2man);

make_type

Devuelve una cadena adecuada que describe el tipo de archivo de makefile que se está escribiendo.

stashmeta

my @recipelines = $MM->stashmeta($text, $file);

Genera un conjunto de @recipelines que harán que el literal $text termine en el literal $file cuando se ejecute la receta. Llámalo una vez, con todo el texto que quieras en $file. Las macros de make no se expandirán, por lo que las ubicaciones se fijarán en el momento de la configuración, no en el momento de la construcción.

echo

my @commands = $MM->echo($text);
my @commands = $MM->echo($text, $file);
my @commands = $MM->echo($text, $file, \%opts);

Genera un conjunto de @commands que imprimen el $text en un $file.

Si $file no se da, la salida va a STDOUT.

Si $opts{append} es true, se añadirá al $file en lugar de sobrescribirlo. El valor predeterminado es sobrescribir.

Si $opts{allow_variables} es true, las variables de make de la forma "$(...)" no serán escapadas. Otros "$" sí lo serán. El valor predeterminado es escapar todos "$".

Ejemplo de uso:

my $make = join '', map "\t$_\n", $MM->echo($text, $file);

wraplist

my $args = $mm->wraplist(@list);

Toma una lista de elementos y los convierte en una lista de argumentos bien formateada. En la mayoría de los casos esto es simplemente algo como:

FOO \
BAR \
BAZ

maketext_filter

my $filter_make_text = $mm->maketext_filter($make_text);

El texto del Makefile se procesa a través de este método antes de escribirse en disco. Permite a los sistemas tener la oportunidad de hacer correcciones de portabilidad en el Makefile.

Por defecto no hace nada.

Este método está protegido y no está destinado a ser llamado desde fuera de MakeMaker.

cd Abstracto

my $subdir_cmd = $MM->cd($subdir, @cmds);

Esto generará un fragmento de make que ejecuta los @cmds en el $dirdado. El equivalente aproximado a esto, excepto multiplataforma.

cd $subdir && $cmd

Actualmente $dir solo puede bajar un nivel. "foo" está bien. "foo/bar" no. "../foo" está completamente fuera.

El $subdir_cmd resultante no tiene tabulación inicial ni salto de línea final. Esto facilita incrustarlo en una cadena de make. Por ejemplo.

    my $make = sprintf <<'CODE', $subdir_cmd;
foo :
    $(ECHO) what
    %s
    $(ECHO) mouche
CODE

oneliner Abstracto

my $oneliner = $MM->oneliner($perl_code);
my $oneliner = $MM->oneliner($perl_code, \@switches);

Esto generará un one-liner de perl seguro para la plataforma particular en la que estás basado en el $perl_code dado y @switches (se asume un -e) adecuado para usar en un objetivo de make. Usará el entrecomillado y los escapes adecuados del shell.

$(PERLRUN) se usará como perl.

Cualquier salto de línea en $perl_code será escapado. Los saltos de línea iniciales y finales serán eliminados. Hace que este idioma sea mucho más fácil:

    my $code = $MM->oneliner(<<'CODE', [...switches...]);
some code here
another line here
CODE

El uso podría ser algo como:

# una emulación de echo
$oneliner = $MM->oneliner('print "Foo\n"');
$make = '$oneliner > somefile';

Los signos de dólar en $perl_code serán protegidos de make usando el "quote_literal" método, a menos que sean reconocidos como una variable de make, "$(varname)", en cuyo caso serán dejados para que make los expanda. Recuerda citar las macros de make, de lo contrario podrían ser usadas como palabra desnuda. Por ejemplo:

# Asigna el valor de la macro de make $(VERSION_FROM) a $vf.
$oneliner = $MM->oneliner('$vf = "$(VERSION_FROM)"');

Actualmente es muy simple, y podría ser expandido en algún momento en el futuro para incluir código y switches más flexibles.

quote_literal Abstract

my $safe_text = $MM->quote_literal($text);
my $safe_text = $MM->quote_literal($text, \%options);

Esto citará $text para que sea interpretado literalmente en el shell.

Por ejemplo, en Unix esto escaparía cualquier comilla simple en $text y pondría comillas simples alrededor de todo el asunto.

Si $options{allow_variables} es verdadero, dejará intactas las variables de make '$(FOO)' . Si es falso, serán escapadas como cualquier otro "$". Por defecto es verdadero.

escape_dollarsigns

my $escaped_text = $MM->escape_dollarsigns($text);

Escapa signos de dólar sueltos "$" para que no sean interpretados como variables de make.

Permite pasar "$(...)".

escape_all_dollarsigns

my $escaped_text = $MM->escape_all_dollarsigns($text);

Escapa todos los "$" para que no sean interpretados como variables de make.

escape_newlines Abstract

my $escaped_text = $MM->escape_newlines($text);

Escapa con el shell los saltos de línea en $text.

max_exec_len Abstract

my $max_exec_len = $MM->max_exec_len;

Calcula el tamaño máximo de comando que el SO puede ejecutar. Efectivamente, este es el tamaño máximo de una línea de comando del shell.

make

my $make = $MM->make;

Devuelve la variante de make para la que estamos generando el Makefile. Esto intenta hacer alguna normalización de la información de %Config o del usuario.

dir_target

Genera objetivos para crear los directorios especificados y establece su permiso a PERM_DIR.

Debido a que depender de un directorio solo para asegurarse de que existe no funciona muy bien (la hora de modificación cambia muy a menudo) dir_target() crea un archivo .exists en el directorio creado. De esto es de lo que deberías depender. Para propósitos de portabilidad deberías usar la macro $(DIRFILESEP) en lugar de un '/' para separar el directorio del archivo.

yourdirectory$(DIRFILESEP).exists

Genera el objetivo metafile.

Escribe el archivo META.yml (metadatos codificados en YAML) y META.json (metadatos codificados en JSON) sobre el módulo en el distdir. El formato sigue el de Module::Build lo más de cerca posible.

metafile_data

Devuelve los datos que MakeMaker convierte en el archivo META.yml y el archivo META.json. Siempre está en la versión 2.0 del formato.

Los valores de %meta_add sobrescribirán cualquier metadato existente en esas claves. %meta_merge será fusionado con ellos.

metafile_file

my $meta_yml = $mm->metafile_file(@metadata_pairs);

Convierte @metadata_pairs en YAML.

Este método no implementa un dumper YAML completo, estando limitado a volcar un hash con valores que sean cadenas, undef's o hashes anidados y arrays de cadenas. No se hace ningún citado/escape.
