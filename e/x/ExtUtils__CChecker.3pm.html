DESCRIPCIÓ

N

A menudo, los módulos de Perl se escriben para envolver funcionalidad encontrada en encabezados de C existentes, bibliotecas, o para usar características específicas del SO. Es útil en el Build.PL o archivo Makefile.PL comprobar la existencia de estos requisitos antes de intentar compilar realmente el

módulo.

Los objetos en esta clase proporcionan una extensión alrededor de ExtUtils::CBuilder para simplificar la creación de un archivo .c, compilarlo, enlazarlo y ejecutarlo, para probar si cierta característica está

presente.

También puede ser necesario buscar la biblioteca correcta con la que

enlazar, o los directorios de inclusión correctos para encontrar los
archivos de encabezado. Esta clase también proporciona asistencia aquí.

Bibliotecas de

Sockets

Algunos sistemas operativos proporcionan la API de sockets BSD en su biblioteca principal libc. Otros la mantienen en una biblioteca separada con la que se debe enlazar. El siguiente ejemplo demuestra cómo se manejaría

esto. 
use ExtUtils::CChecker;
my $cc = ExtUtils::CChecker->new;
$cc->find_libs_for(
   diag => "no socket()",
   libs => [ "", "socket nsl" ],
   source => q[
#include <sys/socket.h>
int main(int argc, char *argv) {
  int fd = socket(PF_INET, SOCK_STREAM, 0);
  if(fd < 0)
    return 1;
  return 0;
}
] );
$cc->new_module_build(
   module_name => "Your::Name::Here",
   requires => {
      'IO::Socket' => 0,
   },
   ...
)->create_build_script
;

Prueba de Funcionalidades

Opcionales

A veces una función o capacidad puede ser proporcionada opcionalmente por el SO, o puede desear que su módulo sea utilizable cuando solo se proporciona soporte parcial, sin requerir que todo esté presente. En estos casos, es tradicional detectar la presencia de esta característica opcional en el script Build.PL, y definir un símbolo para declarar este hecho si se encuentra. El código XS puede entonces usar este símbolo para seleccionar entre diferentes implementaciones. Por ejemplo, el Build.

PL: 
use ExtUtils::CChecker;
my $cc = ExtUtils::CChecker->new;
$cc->try_compile_run(
   define => "HAVE_MANGO",
   source => <<'EOF' );
#include <mango.h>
#include <unistd.h>
int main(void) {
  if(mango() != 0)
    exit(1);
  exit(0);
}
EOF
$cc->new_module_build(
   ...
)->create_build_script
;

Si el código C compila y se ejecuta con éxito, y termina con un estado verdadero, el símbolo "HAVE_MANGO" será definido en la línea de comandos del compilador. Esto permite al código XS detectarlo, por

ejemplo 
int
mango()
  CODE:
#ifdef HAVE_MANGO
    RETVAL = mango();
#else
    croak("mango() not implemented");
#endif
  OUTPUT:
RETVAL

Este módulo seguirá compilando incluso si el sistema operativo

carece de esta función en particular. Intentar invocar la func
ión en tiempo de ejecución simplemente lanzará una excepción.

Encabezados del Kernel de

Linux

Los sistemas operativos construidos sobre el kernel de Linux a menudo comparten una asociación más laxa con su versión de kernel que la mayoría de los otros sistemas operativos. Puede ser que el kernel en ejecución sea más nuevo, conteniendo más características, de lo que los encabezados de libc de la distribución creerían. En tales circunstancias puede ser difícil hacer uso de nuevas opciones de socket, ioctl()s, etc.. sin tener las constantes que las definen y sus estructuras de parámetros, porque los archivos de encabezado relevantes no son visibles para el compilador. En este caso, puede haber poca opción más que incorporar algunos de los archivos de encabezado del kernel, que proporcionarán las constantes y estructuras

requeridas.

Los encabezados del kernel de Linux se pueden encontrar usando el directorio /lib/modules. Un fragmento en Build.PL como el siguiente, puede ser

apropiado. 
chomp( my $uname_r = `uname -r` );
my @dirs = (
   [],
   [ "/lib/modules/$uname_r/source/include" ],
);
$cc->find_include_dirs_for(
   diag => "no PF_MOONLASER",
   dirs => \@dirs,
   source => <<'EOF' );
#include <sys/socket.h>
#include <moon/laser.h>
int family = PF_MOONLASER;
struct laserwl lwl;
int main(int argc, char *argv[]) {
  return 0;
}
EOF

Este fragmento primero intentará compilar el programa tal como está, esperando que los encabezados de libc sean suficientes. Si falla, entonces intentará incluir los encabezados del ker

nel, que deberían hacer visibles la constante y
la estructura, permitiendo que el programa compile.

Creación de un archivo

"#include"

A veces, en lugar de establecer símbolos definidos en la línea de comandos del compilador, es preferible que se escriban en un archivo de inclusión del preprocesador C (.h). Esto puede ser beneficioso para cuestiones de portabilidad multiplataforma, ya que no todos los compiladores C pueden aceptar argumentos "-D" adicionales en la línea de comandos, o las plataformas pueden tener pequeñas restricciones de longitud en la longitud de una línea de

comandos. 
use ExtUtils::CChecker;
my $cc = ExtUtils::CChecker->new(
   defines_to => "mymodule-config.h",
);
$cc->try_compile_run(
   define => "HAVE_MANGO",
   source => <<'EOF' );
#include <mango.h>
#include <unistd.h>
#include "mymodule-config.h"
int main(void) {
  if(mango() != 0)
    exit(1);
  exit(0);
}
EOF

Debido a que el archivo mymodule-config.h se escribe y se vacía después de cada operación de definición, seguirá siendo utilizable en fragmentos C posteriores para probar características detectadas en los

anteriores.

Se sugiere no nombrar el archivo simplemente config.h, ya que el núcleo de Perl en sí mismo tiene un archivo con ese nombre que contie

ne su propia configuración detectada en tie
mpo de compilación. Una confusión entre los do
s podría llevar a resultados sorprendentes.
