ExtUtils::InstallPaths(3) Documentación de Perl aportada por el usuario ExtUtils::InstallPaths(3)

NOMBRE

ExtUtils::InstallPaths - Lógica de rutas de instalación de Build.PL hecha fácil

VERSIÓN

versión 0.015

SINOPSIS

use ExtUtils::InstallPaths;
use ExtUtils::Install 'install';
GetOptions(\my %opt, 'install_base=s', 'install_path=s%', 'installdirs=s', 'destdir=s', 'prefix=s', 'uninst:1', 'verbose:1');
my $paths = ExtUtils::InstallPaths->new(%opt, dist_name => $dist_name);
install($paths->install_map, $opt{verbose}, 0, $opt{uninst});

DESCRIPCIÓN

Este módulo intenta hacer la resolución de rutas de instalación lo más fácil posible.

Cuando quieres instalar un módulo, necesita averiguar dónde instalar las cosas. La versión resumida de cómo funciona esto es que las ubicaciones de instalación predeterminadas se determinan a partir de ExtUtils::Config, y pueden ser anuladas individualmente usando el "install_path" atributo. Un "install_base" atributo te permite especificar una raíz de instalación alternativa como /home/foo y "prefix" hace algo similar de una manera bastante diferente (y más complicada). "destdir" te permite especificar un directorio de instalación temporal como /tmp/install en caso de que quieras crear paquetes instalables empaquetados.

Los siguientes tipos son soportados por defecto.

  • lib

    Archivos de módulos generalmente puros de Perl que terminan en .pm o .pod.

  • arch

    Archivos de módulos "dependientes de la arquitectura", generalmente producidos al compilar XS, Inline, o código similar.

  • script

    Programas escritos en Perl puro. Para mejorar la reutilización, puedes querer hacerlos lo más pequeños posible - pon el código en módulos siempre que sea posible.

  • bin

    Programas ejecutables "dependientes de la arquitectura", es decir, código C compilado o algo similar. Es bastante raro ver esto en una distribución de perl, pero ocurre.

  • bindoc

    Documentación para las cosas en "script" y "bin". Generalmente generada desde el POD en esos archivos. Bajo Unix, son páginas de manual que pertenecen a la categoría 'man1'. A menos que se establezca explícitamente, esto solo está disponible en plataformas que soportan páginas de manual.

  • libdoc

    Documentación para las cosas en "lib" y "arch". Esto generalmente se genera desde el POD en los archivos .pm y .pod . Bajo Unix, son páginas de manual que pertenecen a la categoría 'man3'. A menos que se establezca explícitamente, esto solo está disponible en plataformas que soportan páginas de manual.

  • binhtml

    Esto es lo mismo que "bindoc" arriba, pero se aplica a documentos HTML. A menos que se establezca explícitamente, esto solo está disponible cuando perl fue configurado para hacerlo.

  • libhtml

    Esto es lo mismo que "libdoc" arriba, pero se aplica a documentos HTML. A menos que se establezca explícitamente, esto solo está disponible cuando perl fue configurado para hacerlo.

ATRIBUTOS

installdirs

Los destinos predeterminados para estas cosas instalables provienen de entradas en la configuración de tu sistema. Puedes seleccionar entre tres conjuntos diferentes de ubicaciones predeterminadas estableciendo el "installdirs" parámetro de la siguiente manera:

                        'installdirs' establecido a:
                 core          site                vendor
            usa los siguientes valores predeterminados de ExtUtils::Config:
lib     => installprivlib  installsitelib      installvendorlib
arch    => installarchlib  installsitearch     installvendorarch
script  => installscript   installsitescript   installvendorscript
bin     => installbin      installsitebin      installvendorbin
bindoc  => installman1dir  installsiteman1dir  installvendorman1dir
libdoc  => installman3dir  installsiteman3dir  installvendorman3dir
binhtml => installhtml1dir installsitehtml1dir installvendorhtml1dir [*]
libhtml => installhtml3dir installsitehtml3dir installvendorhtml3dir [*]
* En algunos SO (ej. MSWin32) el destino para documentos HTML es determinado por la entrada C<Config.pm> C<installhtmldir>.

El valor predeterminado de "installdirs" es "site".

install_base

También puedes establecer todo el conjunto de rutas de instalación proporcionando el "install_base" parámetro para apuntar a un directorio en tu sistema. Por ejemplo, si estableces "install_base" a "/home/ken" en un sistema Linux, instalarás de la siguiente manera:

lib     => /home/ken/lib/perl5
arch    => /home/ken/lib/perl5/i386-linux
script  => /home/ken/bin
bin     => /home/ken/bin
bindoc  => /home/ken/man/man1
libdoc  => /home/ken/man/man3
binhtml => /home/ken/html
libhtml => /home/ken/html

prefix

Esto establece un prefijo, idéntico a la opción PREFIX de ExtUtils::MakeMaker. Esto hace algo similar a "install_base" pero de una manera mucho más complicada.

config()

El objeto ExtUtils::Config usado para este objeto.

verbose

La verbosidad de ExtUtils::InstallPaths. Por defecto es 0.

create_packlist

Junto con "module_name" esto controla si se añadirá un packlist; por defecto es 1.

dist_name

El nombre del módulo actual.

module_name

El nombre del módulo principal del paquete. Esto es requerido para la creación del packlist, pero en el futuro puede ser reemplazado por dist_name. Por defecto es "dist_name =~ s/-/::/gr" si dist_name está establecido.

destdir

Si quieres instalar todo en un directorio temporal primero (por ejemplo, si quieres crear un árbol de directorios del que un gestor de paquetes como "rpm" o "dpkg" podría crear un paquete), puedes usar el "destdir" parámetro. Ej. Establecer "destdir" a "/tmp/foo" instalará efectivamente en "/tmp/foo/$sitelib", "/tmp/foo/$sitearch", y similares, excepto que usará "File::Spec" para hacer que los nombres de ruta funcionen correctamente en la plataforma en la que estés instalando.

MÉTODOS

new

Crea un nuevo objeto ExtUtils::InstallPaths. Todos los atributos son argumentos válidos para el constructor, así como esto:

  • install_path

    Debe ser un hashref con el tipo como claves y el destino como valores.

  • install_base_relpaths

    Debe ser un hashref con tipos como claves y una ruta relativa al install_base como valor.

  • prefix_relpaths

    Debe ser un hashref con cualquiera de estas tres claves: core, vendor, site. Cada uno de los valores debe ser un hashref con tipos como claves y una ruta relativa al prefijo como valor. Probablemente quieras hacer estos tres hashrefs idénticos.

  • original_prefix

    Debe ser un hashref con los valores legales de installdirs como claves y los directorios de prefijo como valores.

  • install_sets

    Debe ser un hashref con los valores legales de installdirs como claves, y los valores siendo hashrefs con tipos comoclaves y ubicaciones como valores.

install_map()

Devuelve un mapa adecuado para su uso con ExtUtils::Install. En la mayoría de los casos, este es el único método que necesitarás.

install_destination($type)

Devuelve el destino de un cierto tipo.

install_types()

Devuelve una lista de todos los tipos de instalación admitidos en la configuración actual.

is_default_installable($type)

Dado un tipo de archivo, devolverá true si el tipo de archivo se instalaría normalmente cuando no se han establecido ni install-base ni prefix. Es decir, será true solo si la ruta está establecida desde el objeto de configuración o establecida explícitamente por el usuario a través de install_path.

install_path($type)

Obtiene la ruta de instalación para un cierto tipo.

install_sets($installdirs, $type)

Obtiene la ruta para un cierto $type con un cierto $installdirs.

install_base_relpaths($type, $relpath)

Obtiene las rutas relativas para usar con install_base para un cierto tipo.

prefix_relative($installdirs, $type)

Obtiene la ruta de un cierto $type y $installdirs relativa al prefijo.

prefix_relpaths($install_dirs, $type)

Obtiene la ruta relativa predeterminada para usar en caso de que las rutas de instalación de la configuración no se puedan convertir en prefijos. No querrás usar esto para obtener cualquier ruta relativa, pero puede ser necesario establecerla para tipos personalizados.

original_prefix($installdirs)

Obtiene el prefijo original para un cierto tipo de $installdirs.
