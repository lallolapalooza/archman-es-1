Opción Detalles

Operaciones con etiquetas

-TAG
Extraer información para la etiqueta especificada (por ejemplo, "-CreateDate"). Se pueden especificar múltiples etiquetas en un solo comando. Un nombre de etiqueta es el identificador por el cual se hace referencia a un fragmento de información. Consulte Image::ExifTool::TagNames para obtener documentación sobre los nombres de etiquetas disponibles. Un nombre de etiqueta puede incluir nombres de grupo iniciales separados por dos puntos (por ejemplo, "-EXIF:CreateDate", o "-Doc1:XMP:Creator"), y cada nombre de grupo puede ir precedido por un dígito para especificar el número de familia (por ejemplo, "-1IPTC:City"). (Tenga en cuenta que las opciones de la API SavePath y SaveFormat deben usarse para que los grupos de las familias 5 y 6 estén disponibles respectivamente.) Use la opción -listg para listar los nombres de grupo disponibles por familia.

Un nombre de etiqueta especial de "All" puede usarse para indicar toda la metainformación (es decir, -All). Esto es particularmente útil cuando se especifica un nombre de grupo para extraer toda la información de un grupo (pero tenga cuidado de que, a menos que también se use la opción -a , algunas etiquetas del grupo pueden ser suprimidas por etiquetas con el mismo nombre en otros grupos). Los caracteres comodín "?" y "*" pueden usarse en un nombre de etiqueta para que coincidan con cualquier carácter único y cero o más caracteres respectivamente. Estos no pueden usarse en un nombre de grupo, con la excepción de que un nombre de grupo de "*" (o "All") puede usarse para extraer todas las instancias de una etiqueta (como si se hubiera usado -a ). Tenga en cuenta que los argumentos que contienen comodines deben estar entre comillas en la línea de comandos de la mayoría de los sistemas para evitar el globbing del shell.

Un "#" puede añadirse al nombre de la etiqueta para desactivar la conversión de impresión a nivel de etiqueta (consulte la opción -n ). Esto también puede usarse al escribir o copiar etiquetas.

Si no se especifican etiquetas, se extrae toda la información disponible (como si se hubiera especificado "-All" ).

Nota: Por defecto, se muestran las descripciones, no los nombres de etiquetas, al extraer información. Use la opción -s para ver los nombres de etiquetas en su lugar.

--TAG
Excluir la etiqueta especificada de la información extraída. Igual que la opción -x . Se permiten nombres de grupo y comodines como se describe arriba para -TAG. Una vez excluida de la salida, una etiqueta no puede ser re-incluida por una opción posterior. También puede usarse después de una opción -tagsFromFile para excluir etiquetas de ser copiadas (al redirigir a otra etiqueta, es la etiqueta de origen la que debe excluirse), o para excluir grupos de ser eliminados al borrar toda la información (por ejemplo, "-all= --exif:all" elimina todo menos la información EXIF). Pero tenga en cuenta que esto no excluirá etiquetas individuales de una eliminación de grupo (a menos que se especifique un grupo de familia 2, consulte la nota 4 a continuación). En su lugar, las etiquetas individuales pueden recuperarse usando la opción -tagsFromFile (por ejemplo, "-all= -tagsfromfile @ -artist").

Para acelerar el procesamiento al leer XMP, las exclusiones en grupos XMP también omiten el procesamiento de la propiedad XMP correspondiente y cualquier propiedad contenida. Por ejemplo, "--xmp-crs:all" puede acelerar significativamente el procesamiento en casos donde existe un gran número de etiquetas XMP-crs. Para usar esta característica para omitir el procesamiento de una propiedad XMP específica, debe usarse el nombre de la propiedad en lugar del nombre de la etiqueta de ExifTool (por ejemplo, "--xmp-crs:dabs"). También, "XMP-all" puede usarse para indicar cualquier espacio de nombres XMP (por ejemplo, "--xmp-all:dabs").

-TAG[+-^]=[VALUE]
Escribir un nuevo valor para la etiqueta especificada (por ejemplo, "-comment=wow"), o eliminar la etiqueta si no se proporciona ningún VALUE (por ejemplo, "-comment="). "+=" y "-=" se usan para añadir o eliminar entradas existentes de una lista, o para desplazar valores de fecha/hora (consulte Image::ExifTool::Shift.pl y las notas 6 y 7 a continuación para más detalles). "+=" también puede usarse para incrementar valores numéricos (o decrementar si VALUE es negativo), y "-=" puede usarse para eliminar o reemplazar condicionalmente una etiqueta (consulte "EJEMPLOS DE ESCRITURA" para ver ejemplos). "^=" se usa para escribir una cadena vacía en lugar de eliminar la etiqueta cuando no se proporciona ningún VALUE , pero de lo contrario es equivalente a "=". (Tenga en cuenta que el signo de intercalación debe ir entre comillas en la línea de comandos de Windows.)

TAG puede contener uno o más nombres de grupo iniciales de familia 0, 1, 2 o 7, precedidos por números de familia opcionales y separados por dos puntos. Si no se especifica ningún nombre de grupo, la etiqueta se crea en el grupo preferido, y se actualiza en cualquier otra ubicación donde ya exista una etiqueta con el mismo nombre. El grupo preferido en imágenes de formato JPEG y TIFF es el primer grupo de la siguiente lista donde TAG es válido: 1) EXIF, 2) IPTC, 3) XMP.

Los comodines "*" y "?" pueden usarse en nombres de etiquetas para asignar el mismo valor a múltiples etiquetas. Cuando se especifican con comodines, las etiquetas "Unsafe" no se escriben. Un nombre de etiqueta de "All" es equivalente a "*" (excepto que no requiere comillas, mientras que los argumentos con comodines sí las requieren en sistemas con globbing de shell), y se usa a menudo al eliminar todos los metadatos (es decir, "-All=") o un grupo completo (por ejemplo, "-XMP-dc:All=", consulte la nota 4 a continuación). Tenga en cuenta que no todos los grupos son eliminables, y que el grupo "Adobe" de JPEG APP14 no se elimina por defecto con "-All=" porque puede afectar la apariencia de la imagen. Sin embargo, la información del espacio de color se elimina, por lo que los colores pueden verse afectados (pero esto puede evitarse copiando de vuelta las etiquetas definidas por el atajo ColorSpaceTags). Use la opción -listd para obtener una lista completa de grupos eliminables, y consulte la nota 5 a continuación sobre los grupos "APP". -d FMT (-dateFormat)
Establece el formato para los valores de las etiquetas de fecha/hora. La FMT cadena puede contener códigos de formato que comienzan con un carácter de porcentaje ("%") para representar los diversos componentes de un valor de fecha/hora. Códigos de formato adicionales implementados internamente por ExifTool:

1) %z representa la zona horaria en el formato "+/-HHMM". Añadir dos puntos (es decir, %:z) añade un separador de dos puntos (por ejemplo, "-05:00"). Si el valor de fecha/hora no contiene una zona horaria entonces %z da la zona horaria del sistema para el valor de fecha/hora especificado.

2) %f representa segundos fraccionarios y soporta un ancho opcional para especificar el número de dígitos después del punto decimal (por ejemplo, %3f daría algo como ".437"). Añadir un signo menos elimina el punto decimal (por ejemplo, "%-3f" daría "437").

3) %s representa el número de segundos desde 00:00 UTC del 1 de enero de 1970, teniendo en cuenta la zona horaria especificada (o la zona horaria del sistema si no se especifica).

-plot
Escribe la salida para todas las etiquetas especificadas y todos los archivos de entrada como un único gráfico con formato SVG. Cuando se combina con esta función, el argumento de la -w opción es un nombre de archivo completo sin códigos de formato y la función de adjuntar no se puede usar. Cada etiqueta especificada en la línea de comandos representa un conjunto de datos en el gráfico (o más para valores de matriz o si se usa la configuración de gráfico Split). Se ignoran los valores no numéricos. Cada archivo de entrada puede contribuir con múltiples puntos a un conjunto de datos si contiene subdocumentos y se usa la -ee opción, o si el valor de la etiqueta es una cadena delimitada de números (los delimitadores válidos son: espacio, coma, punto y coma, tabulación y salto de línea). Formato de salida corto. Imprime nombres de etiquetas en lugar de descripciones. Añada NUM o hasta 3 -s opciones para formatos aún más cortos: 
-s1 o -s        - imprimir nombres de etiquetas en lugar de descripciones
-s2 o -s -s     - sin espacios extra para alinear valores en columnas
-s3 o -s -s -s  - imprimir solo valores (sin nombres de etiquetas)

También es efectivo cuando se combina con las opciones -t, -h, -X o -listx .

-S (-veryShort)
Formato muy corto. Lo mismo que -s2 o dos -s opciones. Se imprimen nombres de etiquetas en lugar de descripciones, y no se añaden espacios extra para alinear valores en columnas.
-sep STR (-separator)
Especifica la cadena separadora para los elementos en etiquetas de tipo lista. Al leer, el valor predeterminado es unir los elementos de la lista con ", ". Al escribir, esta opción hace que los valores asignados a etiquetas de tipo lista se dividan en elementos individuales en cada subcadena que coincida con STR (de lo contrario, no se dividen por defecto). Los caracteres de espacio en STR coinciden con cero o más caracteres de espacio en blanco en el valor.

Tenga en cuenta que se permite un separador vacío ("") y unirá los elementos sin separador al leer, o dividirá el valor en caracteres individuales al escribir.

Para la salida binaria pura (-b usado sin -j, -php o -X), la primera -sep la opción especifica un separador de elementos de lista, y una segunda -sep la opción especifica un terminador para el final de la lista (o después de cada valor si no es una lista). En estas cadenas, "\n", "\r" y "\t" pueden usarse para representar un salto de línea, retorno de carro y tabulación respectivamente. De forma predeterminada, los elementos de la lista binaria se separan con un salto de línea y no se añade ningún terminador.

-sort, --sort
Ordena la salida por descripción de la etiqueta, o por nombre de la etiqueta si se usa la -s opción. Al ordenar por descripción, el orden de clasificación dependerá de la configuración de la -lang opción. Sin la -sort opción, las etiquetas aparecen en el orden en que se especificaron en la línea de comandos, o si no se especificaron, en el orden en que se extrajeron del archivo. De forma predeterminada, las etiquetas se organizan por grupos cuando se combinan con la -g o -G opción, pero esta agrupación se puede deshabilitar con --sort.
-struct, --struct
Genera información XMP estructurada en lugar de aplanarla a etiquetas individuales. Esta opción funciona bien cuando se combina con los formatos de salida XML (-X) y JSON (-j). Para otros formatos de salida, las estructuras y listas XMP se serializan en el mismo formato que al escribir información estructurada (ver https://exiftool.org/struct.html para más detalles). Al copiar, las etiquetas estructuradas se copian de forma predeterminada a menos que se use --struct para deshabilitar esta función (aunque las etiquetas aplanadas aún pueden copiarse especificándolas individualmente a menos que se use -struct ). Estas opciones no tienen efecto al asignar nuevos valores, ya que tanto las etiquetas aplanadas como las estructuradas siempre se pueden usar al escribir.
-t (-tab)
Genera una lista de descripciones/valores delimitada por tabulaciones (útil para importación a bases de datos). Se puede combinar con -s para imprimir nombres de etiquetas en lugar de descripciones, o -S para imprimir solo los valores de las etiquetas, delimitados por tabulaciones en una sola línea. La -t opción se puede combinar con -j, -php o -X para añadir información de la tabla de etiquetas ("table", etiqueta "id", y "index" para los casos en que existen múltiples etiquetas condicionales con el mismo ID), lo que permite localizar la etiqueta correspondiente en la -listx salida.
-T (-table)
Genera los valores de las etiquetas en forma de tabla. Equivalente a -t -S -q -f.
-v[NUM] (-verbose)
Imprime mensajes detallados. NUM especifica el nivel de detalle en el rango 0-5, siendo los números más altos más detallados. Si NUM no se proporciona, entonces cada -v la opción aumenta el nivel de detalle en 1. Con cualquier nivel mayor que 0, la mayoría de las otras opciones se ignoran y la salida normal de la consola se suprime a menos que se extraigan etiquetas específicas. Usar -v0 hace que el búfer de salida de la consola se vacíe después de cada línea (lo que puede ser útil para evitar retrasos al redirigir la salida de exiftool), e imprime el nombre de cada archivo procesado al escribir y el nuevo nombre de archivo al renombrar, mover o copiar. Los niveles de detalle superiores a -v0 no vacían después de cada línea. Ver también la -progress opción.
-w[+|!] EXT o FMT (-textOut)
Escribe la salida de la consola en archivos con nombres que terminan en EXT, uno para cada archivo de origen. El nombre del archivo de salida se obtiene reemplazando la extensión del archivo de origen (incluyendo el '.') con la extensión especificada (y se añade un '.' al inicio de EXT si no contiene uno ya). Alternativamente, se puede usar una FMT cadena para tener más control sobre el nombre y el directorio del archivo de salida. En la cadena de formato, %d, %f y %e representan el directorio, el nombre del archivo y la extensión del archivo de origen, y %c representa un número de copia que se incrementa automáticamente si el archivo ya existe. %d incluye la barra final '/' si es necesario, pero %e no incluye el punto inicial '.'. Por ejemplo: 
-w %d%f.txt       # mismo efecto que "-w txt"
-w dir/%f_%e.out  # escribe archivos en "dir" como "FILE_EXT.out"
-w dir2/%d%f.txt  # escribe en "dir2", manteniendo la estructura de dir
-w a%c.txt        # escribe en "a.txt" o "a1.txt" o "a2.txt"...

Los archivos existentes no se cambiarán a menos que se añada un signo de exclamación al nombre de la opción (es decir, -w! o -textOut!) para sobrescribir el archivo, o un signo más (es decir, -w+ o -textOut+) para añadir al archivo existente. Se pueden usar ambos (es decir, -w+! o -textOut+!) para sobrescribir los archivos de salida que no existían antes de ejecutar el comando y añadir la salida de múltiples archivos de origen. Por ejemplo, para escribir un archivo de salida para todos los archivos de origen en cada directorio:

exiftool -filename -createdate -T -w+! %d/out.txt -r DIR

Los códigos de formato en mayúsculas %D, %F, %E y %C proporcionan alternativas ligeramente diferentes a las versiones en minúsculas. %D no incluye la barra final '/', %F es el nombre completo del archivo incluyendo la extensión, %E incluye el punto inicial '.', y %C incrementa el contador para cada archivo procesado (ver abajo).

Notas:

1) En un archivo BAT de Windows el carácter "%" se representa con "%%", por lo que un argumento como "%d%f.txt" se escribe como "%%d%%f.txt".

2) Si el argumento para -w no contiene un código de formato válido (por ejemplo, %f), entonces se interpreta como una extensión de archivo, pero hay tres formas diferentes de crear un solo archivo de salida a partir de múltiples archivos de origen:

# 1. Redirección del shell
exiftool FILE1 FILE2 ... > out.txt
# 2. Con la opción -w y un código de formato de ancho cero
exiftool -w+! %0fout.txt FILE1 FILE2 ...
# 3. Con la opción -W (ver la opción -W más abajo)
exiftool -W+! out.txt FILE1 FILE2 ...

3) La opción -w cambia cuando se usa con un formato de salida de varios archivos (-csv o -plot). Con estos, el argumento de -w es un nombre de archivo completo sin códigos de formato, y la característica de añadir no puede ser utilizada.

Características avanzadas:

Se puede tomar una subcadena del nombre de archivo original, directorio o extensión especificando un ancho de campo inmediatamente después del carácter '%'. Si el ancho es negativo, la subcadena se toma desde el final. La posición de la subcadena (caracteres a ignorar al principio o al final de la cadena) se puede indicar con un segundo valor opcional después de un punto decimal. Por ejemplo:

Nombre de Archivo de Entrada    Especificador de Formato    Nombre de Archivo de Salida
--------------------    ----------------------    ---------------------------
Picture-123.jpg         %7f.txt                   Picture.txt
Picture-123.jpg         %-.4f.out                 Picture.out
Picture-123.jpg         %7f.%-3f                  Picture.123
Picture-123a.jpg        Meta%-3.1f.txt            Meta123.txt

(Tenga en cuenta que los caracteres especiales pueden tener un ancho mayor que uno.)

Para %d y %D, los especificadores de ancho/posición de campo se pueden aplicar a los niveles de directorio en lugar de la posición de subcadena, utilizando dos puntos en lugar de un punto decimal en el especificador de formato. Por ejemplo:

Directorio de Origen     Formato   Resultado       Notas
--------------------   --------   ----------   ------------------
pics/2012/02           %2:d       pics/2012/   tomar los 2 niveles superiores
pics/2012/02           %-:1d      pics/2012/   subir un nivel de directorio
pics/2012/02           %:1d       2012/02/     ignorar el nivel superior
pics/2012/02           %1:1d      2012/        tomar 1 nivel después del superior
pics/2012/02           %-1:D      02           nombre de carpeta del nivel inferior
/Users/phil            %:2d       phil/        ignorar los 2 niveles superiores

(Tenga en cuenta que el directorio raíz cuenta como un nivel cuando se utiliza una ruta absoluta, como en el último ejemplo.)

Para %c, estos modificadores tienen efectos diferentes. Si se proporciona un ancho de campo, el número de copia se rellena con ceros hasta el ancho especificado. Un '-' inicial agrega un guion antes del número de copia, y un '+' agrega un subrayado. Por defecto, el número de copia se omite del primer archivo con un nombre dado, pero esto se puede cambiar agregando un punto decimal al modificador. Por ejemplo:

-w A%-cZ.txt      # AZ.txt, A-1Z.txt, A-2Z.txt ...
-w B%5c.txt       # B.txt, B00001.txt, B00002.txt ...
-w C%.c.txt       # C0.txt, C1.txt, C2.txt ...
-w D%-.c.txt      # D-0.txt, D-1.txt, D-2.txt ...
-w E%-.4c.txt     # E-0000.txt, E-0001.txt, E-0002.txt ...
-w F%-.4nc.txt    # F-0001.txt, F-0002.txt, F-0003.txt ...
-w G%+c.txt       # G.txt, G_1.txt G_2.txt ...
-w H%-lc.txt      # H.txt, H-b.txt, H-c.txt ...
-w I.%.3uc.txt    # I.AAA.txt, I.AAB.txt, I.AAC.txt ...

Una característica especial permite que el número de copia se incremente para cada archivo procesado utilizando %C (mayúscula) en lugar de %c. Esto permite agregar un número secuencial a los nombres de archivo de salida, incluso si los nombres son diferentes. Para %C, el número de copia cero no se omite como ocurre con %c. Un '-' inicial hace que el número se reinicie al comienzo de cada nuevo directorio (en la estructura de directorios original si los archivos se están moviendo), y '+' no tiene efecto. El número antes del punto decimal da el índice de inicio, el número después del punto decimal da el ancho del campo. Para mantener la sincronización con el número de archivo procesado, por defecto el número de copia no se incrementa para evitar colisiones de nombres de archivo, por lo que cualquier archivo existente del mismo nombre causará un error. Sin embargo, usar dos puntos en lugar de un punto decimal hace que el número se incremente para evitar colisiones con archivos existentes.

Los siguientes ejemplos muestran los nombres de archivo de salida cuando se usan con el comando "exiftool rose.jpg star.jpg jet.jpg ...":

-w %C%f.txt       # 0rose.txt, 1star.txt, 2jet.txt
-w %f-%10C.txt    # rose-10.txt, star-11.txt, jet-12.txt
-w %.3C-%f.txt    # 000-rose.txt, 001-star.txt, 002-jet.txt
-w %57.4C%f.txt   # 0057rose.txt, 0058star.txt, 0059jet.txt

Todos los códigos de formato se pueden modificar con 'l' o 'u' para especificar minúsculas o mayúsculas respectivamente (por ejemplo, %le para una extensión de archivo en minúsculas). Cuando se usan para modificar %c o %C, los números se cambian a una base alfabética (ver ejemplo H arriba). Además, %c y %C pueden ser modificados por 'n' para contar usando números naturales a partir de 1, en lugar de 0 (ver ejemplo F arriba).

La misma sintaxis FMT se utiliza con las opciones -o y -tagsFromFile, aunque %c y %C solo son válidos para nombres de archivo de salida.

-W[+|!] FMT (-tagOut)
Esta versión mejorada de la opción -w permite crear un archivo de salida separado para cada etiqueta extraída. Consulte la documentación de la opción -w anterior para obtener detalles de la funcionalidad básica. Aquí se enumeran las diferencias entre -W y -w:

1) Con -W, se crea un nuevo archivo de salida para cada etiqueta extraída.

2) -W admite cuatro códigos de formato adicionales: %t, %g y %s representan el nombre de la etiqueta, el nombre del grupo y la extensión sugerida para el archivo de salida (basado en el formato de los datos), y %o representa el valor de la etiqueta OriginalRawFileName o OriginalFileName del archivo de entrada (incluida la extensión). El código %g puede ir seguido de un solo dígito para especificar el número de familia del grupo (por ejemplo, %g1), de lo contrario se asume la familia 0. Los especificadores de ancho/posición/mayúsculas de subcadena se pueden utilizar con estos códigos de formato de la misma manera que con %f y %e.

3) El argumento para -W se interpreta como un nombre de archivo si no contiene códigos de formato. (Para -w, esto sería una extensión de archivo.) Este cambio permite especificar un nombre de archivo simple, que, al combinarse con la característica de añadir, proporciona un método para escribir metadatos de múltiples archivos de origen en un único archivo de salida sin necesidad de redirección del shell. Por ejemplo, los siguientes pares de comandos dan el mismo resultado:

# sobrescribiendo archivo de texto existente
exiftool test.jpg > out.txt     # redirección del shell
exiftool test.jpg -W+! out.txt  # opción -W equivalente
# añadir a archivo de texto existente
exiftool test.jpg >> out.txt    # redirección del shell
exiftool test.jpg -W+ out.txt   # opción -W equivalente

4) Añadir la opción -v a -W envía una lista de las etiquetas y los nombres de archivo de salida a la consola en lugar de dar un volcado detallado de todo el archivo. (A menos que se añadan todas las salidas a un solo archivo para cada archivo de origen utilizando -W+ con un archivo de salida FMT que no contenga %t, %g, %s o %o.)

5) Los elementos individuales de la lista se almacenan en archivos separados cuando -W se combina con -b, pero tenga en cuenta que para que se creen archivos separados, se debe usar %c o %C en FMT para dar nombres únicos a los archivos.

-Wext EXT, --Wext EXT (-tagOutExt)
Esta opción se utiliza para especificar el tipo de archivo(s) de salida escritos por la opción -W. Se escribe un archivo de salida solo si la extensión sugerida coincide con EXT. Se pueden usar múltiples opciones -Wext para escribir más de un tipo de archivo. Utilice --Wext para escribir todos excepto el tipo(s) especificado(s).
-X (-xmlFormat)
Utiliza formato RDF/XML específico de ExifTool para la salida de la consola. Implica la opción -a, por lo que se extraen etiquetas duplicadas. Las opciones de formato -b, -D, -H, -l, -s, -sep, -struct y -t se pueden usar en combinación con -X para afectar la salida, pero tenga en cuenta que las opciones de ID de etiqueta (-D, -H y -t), datos binarios (-b) y salida estructurada (-struct) no son efectivas para la salida corta (-s). Otra restricción de -s es que solo una etiqueta con un grupo y nombre dados puede aparecer en la salida. Tenga en cuenta que las opciones de ID de etiqueta (-D, -H y -t) producirán RDF/XML no estándar a menos que también se use la opción -l.

Por defecto, -X produce etiquetas aplanadas, por lo que se debe añadir -struct si se requiere para preservar las estructuras XMP. Las etiquetas de lista con valores múltiples se formatean como un Bolso RDF, pero se combinan en una sola cadena cuando se usa -s o -sep. El uso de -L cambia la codificación XML de "UTF-8" a "windows-1252". Otras configuraciones de -charset cambian la codificación solo si hay un conjunto de caracteres XML estándar correspondiente. La opción -b hace que los valores de datos binarios se escriban, codificados en base64 si es necesario. La opción -t agrega información de la tabla de etiquetas a la salida (ver -t para más detalles).

Nota: Esta salida NO es la misma que XMP porque utiliza nombres de propiedad generados dinámicamente que corresponden a los nombres de etiqueta de ExifTool con nombres de grupo de ExifTool familia 1 como espacios de nombres, y no las propiedades y espacios de nombres XMP estándar. Para escribir XMP en su lugar, use la opción -o con una extensión XMP para el archivo de salida.

-geotag TRKFILE
Geotagifica imágenes desde el archivo de registro de pista GPS especificado. Usar la opción -geotag es equivalente a escribir un valor en la etiqueta "Geotag" . La posición GPS se interpola de la pista en un tiempo especificado por el valor escrito en la etiqueta "Geotime" . Si no se especifica "Geotime" , el valor se copia de "SubSecDateTimeOriginal#" si existe, de lo contrario de "DateTimeOriginal#" (el "#" se añade para copiar el valor sin formato, evitando posibles conflictos con la opción -d" ). Por ejemplo, los dos siguientes comandos son equivalentes si SubSecDateTimeOriginal existe en el archivo: 
exiftool -geotag trk.log image.jpg
exiftool -geotag trk.log "-Geotime<SubSecDateTimeOriginal#" image.jpg

Si el valor "Geotime" no contiene una zona horaria, se asume la zona horaria local del sistema. Escribir "Geotime" causa que se escriban las siguientes etiquetas (siempre que puedan calcularse desde el registro de la pista y sean admitidas por el formato de metadatos de destino): GPSLatitude, GPSLatitudeRef, GPSLongitude, GPSLongitudeRef, GPSAltitude, GPSAltitudeRef, GPSDateStamp, GPSTimeStamp, GPSDateTime, GPSTrack, GPSTrackRef, GPSSpeed, GPSSpeedRef, GPSImgDirection, GPSImgDirectionRef, GPSMeasureMode, GPSDOP, GPSPitch, GPSRoll, GPSCoordinates, AmbientTemperature y CameraElevationAngle. Por defecto, en archivos de imagen las etiquetas se crean en EXIF, y se actualizan en XMP solo si ya existen. En archivos de formato QuickTime, GPSCoordinates se crea en la ubicación preferida (ItemList por defecto) así como en XMP. Sin embargo, "EXIF:Geotime", "XMP:Geotime" o "QuickTime:Geotime" pueden especificarse para escribir solo en un grupo. Además, "ItemList:Geotime", "Keys:Geotime" o "UserData:Geotime" pueden usarse para escribir en una ubicación específica en archivos de formato QuickTime. Tenga en cuenta que GPSPitch y GPSRoll son no estándar, y requieren etiquetas definidas por el usuario para poder escribirse.

La etiqueta "Geosync" puede usarse para especificar una corrección de tiempo que se aplica a cada valor de "Geotime" para la sincronización con el tiempo GPS. Por ejemplo, el siguiente comando compensa los tiempos de imagen que están 1 minuto y 20 segundos por detrás del GPS:

exiftool -geosync=+1:20 -geotag a.log DIR

Las características avanzadas de "Geosync" permiten una corrección de deriva de tiempo lineal por partes y la sincronización desde imágenes previamente geotagificadas. Consulte "geotag.html" en la distribución completa de ExifTool para más información.

Se pueden usar múltiples opciones -geotag para concatenar datos de registro de pista GPS. Además, una sola opción -geotag puede usarse para cargar múltiples archivos de registro de pista usando comodines en el nombre TRKFILE , pero tenga en cuenta que en este caso TRKFILE debe ir entre comillas en la mayoría de los sistemas (con la notable excepción de Windows) para prevenir la expansión del nombre de archivo. 2) Escribir los argumentos de la línea de comandos de exiftool en ARGFILE,

        ARGFILE, donde "\n" representa
        una secuencia de salto de línea. (Nota: Puede ser necesario vaciar sus búferes de escritura aquí

        "-execute613" resulta en "{ready613}". Cuando se añade este número, -q ya no

        y -echo4 para formas adicionales de pasar señales de vuelta a
        su aplicación.)

    
4) Repetir los pasos 2 y 3 para cada comando.

    
5) Escribir
        "-stay_open\nFalse\n" (o
        "-stay_open\n0\n") en ARGFILE

-@

Característica de formato avanzado


Una característica de formato avanzado permite la modificación del valor de
    cualquier etiqueta interpolada dentro de un argumento -if, -p o -fileNUM
    , o una cadena de redirección de -tagsFromFile . Los nombres de etiqueta dentro de
    estas cadenas se prefijan con el símbolo "$"
    , y una expresión Perl arbitraria puede aplicarse al valor de la etiqueta colocando llaves alrededor del nombre de la etiqueta e insertando la expresión después del nombre, separada por un punto y coma (es decir,
    "${TAG;EXPR}"). La expresión actúa sobre el
    valor de la etiqueta a través de la variable de entrada predeterminada ($_), y tiene acceso a la API completa de ExifTool a través del objeto ExifTool actual ($self) y la clave de la etiqueta ($tag). Puede contener cualquier código Perl válido,
    incluyendo operaciones de traducción ("tr///") y
    sustitución ("s///"), pero note
    que las llaves dentro de la expresión deben estar balanceadas. Si la expresión no modifica $_ , se devuelve el valor original de la etiqueta.
    El ejemplo siguiente imprime la marca (Make) de la cámara con los espacios traducidos a
    subrayados, y los múltiples subrayados consecutivos reemplazados por un solo subrayado:


exiftool -p '${make;tr/ /_/;s/__+/_/g}' image.jpg


Un "@" puede añadirse después del
    nombre de la etiqueta para hacer que la expresión actúe sobre elementos individuales de la lista para etiquetas de tipo lista, simplificando el procesamiento de listas. Establecer $_ a undef
    para eliminar un elemento de la lista. Como ejemplo, el siguiente comando
    devuelve todos los asuntos (subjects) que no contienen la cadena "xxx":


exiftool -p '${subject@;$_=undef if /xxx/}' image.jpg


Se asume una expresión predeterminada de
    "tr(/\\?*:|"<>\0)()d" si la expresión está vacía (es decir,
    "${TAG;}"). Esto elimina los caracteres /
    \ ? * : | < > y nulo del valor impreso. (Estos caracteres son
    ilegales en nombres de archivo de Windows, por lo que esta característica es útil si los valores de las etiquetas se usan en nombres de archivo.)


Funciones auxiliares


Note que los nombres de las funciones distinguen mayúsculas y minúsculas.


"DateFmt"


Simplifica el reformateo de valores individuales de fecha/hora. Esta
    función actúa sobre un valor de fecha/hora con formato EXIF estándar en
    $_ y lo formatea de acuerdo con la cadena de formato especificada (consulte la opción -d ). Para evitar intentar reformatear un valor de fecha/hora ya formateado, se debe añadir un "#"
    al nombre de la etiqueta (como en el ejemplo siguiente) si también se usa la opción -d
    . Por ejemplo:


exiftool -p '${createdate#;DateFmt("%Y-%m-%d_%H%M%S")}' a.jpg


"ShiftTime"


Desplaza una cadena de fecha/hora con formato EXIF por una cantidad especificada.
    Comience con un signo menos inicial para desplazar hacia atrás en el tiempo. Consulte
    Image::ExifTool::Shift.pl para detalles sobre la sintaxis de desplazamiento. Por ejemplo, para
    desplazar un valor de fecha/hora hacia atrás en un año:


exiftool -p '${createdate;ShiftTime("-1:0:0 0")}' a.jpg


"NoDups"


Elimina elementos duplicados de una lista con un separador especificado por la opción -sep . Esta función es más útil al copiar etiquetas de tipo lista. Por ejemplo, el siguiente comando puede usarse para eliminar Palabras clave (Keywords) duplicadas:


exiftool -sep '##' '-keywords<${keywords;NoDups}' a.jpg


La opción -sep es necesaria para dividir la cadena de nuevo en
    elementos individuales de la lista al escribir en una etiqueta de tipo lista.


Se puede establecer un argumento de indicador opcional a 1 para hacer que
    "NoDups" establezca $_
    a undef si no existían duplicados, previniendo así que el archivo se reescriba innecesariamente:


exiftool -sep '##' '-keywords<${keywords;NoDups(1)}' a.jpg


ExifTool 12.64 añade una opción NoDups de la API que hace que la función auxiliar NoDups sea en gran medida redundante, con toda la funcionalidad excepto la capacidad de evitar reescribir el archivo si no hay duplicados, pero con la ventaja de que los duplicados pueden eliminarse al acumular elementos de lista de múltiples fuentes. Un equivalente a los comandos anteriores usando esta característica sería:


exiftool -tagsfromfile @ -keywords -api nodups a.jpg


"SetTags"


Se usa para establecer etiquetas en imágenes extraídas. Sin argumentos, copia todas las etiquetas del archivo fuente a la imagen incrustada:


exiftool -p '${previewimage;SetTags}' -b a.arw > preview.jpg


Se pueden añadir argumentos para copiar o establecer etiquetas específicas. Los argumentos toman exactamente la misma forma que aquellos en la línea de comandos al copiar o escribir etiquetas, pero sin el guion inicial. Por ejemplo:


exiftool -p '${previewimage;SetTags("comment=test","title<filename")}' ...








WINDOWS   NOMBRES DE ARCHIVO UNICODE


En Windows, los argumentos de la línea de comandos se especifican usando la página de código actual y se recodifican automáticamente a la página de código del sistema. Esta recodificación no se hace para los argumentos en los archivos arg de ExifTool, por lo que de forma predeterminada los nombres de archivo en los archivos arg usan la página de código del sistema. Desafortunadamente, estas páginas de código no son conjuntos de caracteres completos, por lo que no todos los nombres de archivo pueden representarse.


ExifTool 9.79 y posteriores permiten especificar la codificación del nombre de archivo con "-charset
    filename=CHARSET", donde
    "CHARSET" es el nombre de un conjunto de caracteres válido de ExifTool, preferiblemente an class="Li">"UTF8" (consulte la
    -charset opción para una lista completa). Establecer esto activa el uso
    de rutinas de E/S de caracteres anchos de Windows, proporcionando así soporte para la mayoría
    de los nombres de archivo Unicode (ver nota 4). Pero tenga en cuenta que no es trivial pasar
    nombres de archivo correctamente codificados en la línea de comandos de Windows (ver
    https://exiftool.org/faq.html#Q18 para más detalles), por lo que colocarlos en un
    archivo de argumentos
    codificado en UTF-8 -@ y usar "-charset
    filename=utf8" se recomienda si es posible.


Se emite una advertencia si un nombre de archivo especificado contiene
    caracteres especiales y el juego de caracteres del nombre de archivo no fue proporcionado. Sin embargo, la
    advertencia puede desactivarse estableciendo "-charset
    filename=""", y ExifTool aún puede funcionar
    correctamente si la página de código del sistema coincide con el juego de caracteres utilizado para
    los nombres de archivo.


Cuando se proporciona un nombre de directorio, no es necesario especificar la
    codificación del nombre de archivo (a menos que el nombre del directorio contenga caracteres especiales), y
    ExifTool usará automáticamente rutinas de caracteres anchos para escanear el
    directorio.


El juego de caracteres del nombre de archivo se aplica a los FILE argumentos, así como a los argumentos de nombre de archivo de -@, -geotag, -o,
    -p, -srcfile, -tagsFromFile, -csv=, -j=
    y -TAG<=. Sin embargo, no se aplica al
    -config nombre de archivo, que siempre usa el juego de caracteres del sistema. La
    "-charset filename=" opción debe venir
    antes de la -@ opción para ser efectiva, pero el orden no importa
    con respecto a otras opciones.


Notas:


1) Los valores de las etiquetas FileName y Directory aún usan la misma codificación
    que otros valores de etiquetas, y se convierten a/desde el juego de caracteres del nombre de archivo
    al escribir/leer si se especifica.


2) El soporte de Unicode aún no está implementado para otros sistemas basados en Windows
    como Cygwin.


3) Consulte "ESCRITURA DE ARCHIVOS DE SOLO LECTURA" más abajo para una nota sobre
    la edición de archivos de solo lectura con nombres Unicode.


4) Los nombres de archivo Unicode con pares sustitutos (puntos de código por encima de
    U+FFFF) aún causan problemas.






ESCRITURA   DE ARCHIVOS DE SOLO LECTURA


En general, ExifTool puede usarse para escribir metadatos en archivos de solo
    lectura siempre que el usuario tenga permiso de escritura en el directorio. Sin embargo,
    hay tres casos en los que también se requiere permiso de escritura en el archivo:


1) Al usar la -overwrite_original_in_place opción.


2) Al escribir solo etiquetas pseudo de Sistema (por ejemplo, FileModifyDate).


3) En Windows, si el archivo tiene caracteres Unicode en su nombre, y
    a) la -overwrite_original opción se usa, o b) la copia de seguridad
    "_original" ya existe.


Los archivos ocultos en Windows se comportan como archivos de solo lectura cuando se intenta
    escribir cualquier etiqueta real en el archivo -- se genera un error al usar la
    -overwrite_original_in_place, de lo contrario la escritura debería ser exitosa
    y el atributo oculto será eliminado. Pero la -if opción puede
    usarse para evitar el procesamiento de archivos ocultos (siempre que Win32API::File esté
    disponible):


exiftool -if "$fileattributes !~ /Hidden/" ...

Copy the values of all writable tags from
      "src.jpg" to
      "dst.jpg", preserving the original tag
      groups.

Erase all meta information from
      "dst.jpg" image, then copy EXIF tags
      from "src.jpg".

    bad.jpg"

  
Rebuild all EXIF meta information from scratch in an image. This technique
      can be used in JPEG images to repair corrupted EXIF information which
      otherwise could not be written due to errors. The
      "Unsafe" tag is a shortcut for unsafe
      EXIF tags in JPEG images which are not normally copied. See the tag name
      documentation for more details about unsafe tags.

  
"exiftool -Tagsfromfile a.jpg out.xmp"

  
Copy meta information from "a.jpg" to an
      XMP data file. If the XMP data file
      "out.xmp" already exists, it will be
      updated with the new information. Otherwise the XMP data file will be
      created. Only metadata-only files may be created like this (files
      containing images may be edited but not created). See "WRITING
      EXAMPLES" above for another technique to generate XMP files.

      to "b.jpg", deleting all XMP information
      and the thumbnail image from the destination.

    dst.jpg"

    dst.jpg"

  
Copy ISO from one image and Comment from another image to a destination

      "dir" from the values of the EXIF:ISO

      be used to store the metadata of an image so it can be inserted back into

      that the -o option will not write to an output file that already
