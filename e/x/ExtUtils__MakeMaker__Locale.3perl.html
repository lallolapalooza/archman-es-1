Donde las interfaces del sistema de archivos pasan nombres de archivo hacia dentro y hacia fuera del programa, también necesitamos tener cuidado. La tendencia es que los sistemas operativos utilicen una codificación de archivo fija que no dependa realmente del locale; y este módulo determina la codificación más adecuada para los nombres de archivo. El módulo Encode conocerá esta codificación bajo el nombre "locale_fs". Para los sistemas Unix tradicionales,

esta será un alias a la misma codificación que "locale". 
Para los programas que se ejecutan en una ventana de terminal (llamada
    "Consola" en algunos sistema
s), la codificación "locale" es normalmente una buena elección para lo que se espera como entrada y
salida. Algunos sistemas nos permiten consultar la codificación establecida para la terminal y

"Encode::Locale" hará eso si está disponible y hará que estas codificaciones sean conocidas

bajo los

alias de "Encode" "console_in" y "console_out". Para los sistemas donde no podemos determinar la codificación de la terminal, estas serán alias a la misma codificación que "locale". Se recomienda usar "console_in" para la entrada que se sabe que proviene de la terminal y "console_out" para la salida a la

terminal.

Windows tiene básicamente 2 conjuntos de APIs. Una API ancha (basada en pasar
    cadenas UTF-16) y una API basada en bytes basada en un juego de caracteres llamado ANSI. Las
    interfaces regulares de Perl al SO actualmente solo usan las APIs ANSI.
    Desafortunadamente ANSI no es un solo juego de
caracteres.

La codificación que corresponde a ANSI varía entre diferentes ediciones de Windows. Para muchas ediciones occidentales de Windows ANSI corresponde a CP-1252, que es un juego de caracteres similar a ISO-8859-1. Conceptualmente el juego de caracteres ANSI es un concepto similar al CODESET del locale POSIX, por lo que este módulo averigua cuál es

la página de código ANSI y la pone a disposición como

$ENCODING_LOCAL

En Mac OS X la codificación del sistema de archivos es siempre UTF-8 mientras que el locale puede configurarse normalmente como para los

sistemas POSIX.

Los nombres de archivo en Mac OS X serán convertidos a nivel de SO a forma NFD. Un archivo creado pasando un nombre de archivo NFC vendrá en forma NFD

desde

readdir() . Vea Unicode::Normalize para detalles de

NFD/NFC.

En realidad, Apple no sigue el estándar Unicode NFD ya que no todos los rangos de carac

teres son descompuestos. Se afirma que esto evita problemas con conversiones de ida y v
uelta desde codificaciones de texto antiguas de Mac. Vea Encode::UTF8Mac para detalles.

POSIX (Linux y otros

Unix)

Los sistemas de archivos pueden variar en qué codificación se debe usar para los nombres de archivo. Da

do que este módulo no tiene forma de averiguar realmente cuál es la correcta, se basa en la suposición
más probable, que es asumir que los nombres de archivo están codificados de acuerdo con el locale actu
al. Se recomienda a los usuarios que siempre especifiquen UTF-8 como el juego de caracteres del locale.
