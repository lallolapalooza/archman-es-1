DESCRIPCIÓ

N

Concatena args (añadiendo espacios separadores entre ellos), evalúa el resultado como una expresión Tcl y devuelve el valor. Los operadores permitidos en las expresiones Tcl incluyen un subconjunto de los operadores permitidos en las expresiones C. Para aquellos operadores comunes a Tcl y C, Tcl aplica el mismo significado y precedencia que los operadores C correspondientes. Las expresiones casi siempre producen resultados numéricos (valores enteros o de punto flotante). Por ejemplo, la

expresión 
expr 8.2
+
6

se evalúa a 14.2. Las expresiones Tcl difieren de las expresiones C en la forma en que se especifican los operandos. Además, las expresiones Tcl admiten operandos no numéricos y comparaciones de cadenas, así como algunos operadores adicionales que no se encuentran en

C.

OPERANDO

S

Una expresión Tcl consiste en una combinación de operandos, operadores, paréntesis y comas. Se puede usar espacio en blanco entre los operandos y operadores y paréntesis (o comas); es ignorado por las instrucciones de la expresión. Siempre que sea posible, los operandos se interpretan como valores enteros. Los valores enteros pueden especificarse en decimal (el caso normal), en binario (si los dos primeros caracteres del operando son 0b), en octal (si los dos primeros caracteres del operando son 0o), o en hexadecimal (si los dos primeros caracteres del operando son 0x). Por compatibilidad con versiones anteriores de Tcl, un valor entero octal también se indica simplemente cuando el primer carácter del operando es 0, independientemente de si el segundo carácter es también o. Si un operando no tiene uno de los formatos enteros indicados anteriormente, entonces se trata como un número de punto flotante si eso es posible. Los números de punto flotante pueden especificarse en cualquiera de varios formatos comunes utilizando los dígitos decimales, el punto decimal ., los caracteres e o E que indican notación científica, y los caracteres de signo + o -. Por ejemplo, todos los siguientes son números de punto flotantes válidos: 2.1, 3., 6e4, 7.91e+16. También se reconocen como valores de punto flotante las cadenas Inf y NaN utilizando cualquier combinación de mayúsculas y minúsculas para cada carácter. Si no es posible ninguna interpretación numérica (ten en cuenta que todos los operandos literales que no son numéricos o booleanos deben estar entrecomillados con llaves o con comillas dobles), entonces un operando se deja como una cadena (y solo se le puede aplicar un conjunto limitado de operadores)

.

Los operandos pueden especificarse de cualquiera de las siguientes

maneras:
[1
]
Como un valor numérico, ya sea entero o de punto
flotante.
[2
]
Como un valor booleano, usando cualquier forma entendida por string is boolea
n.
[3
]
Como una variable Tcl, usando la notación estándar $. El valor de la variable se usará como
operando.
[4
]
Como una cadena encerrada entre comillas dobles. El analizador de expresiones realizará sustituciones de barras invertidas, variables y comandos en la información entre las comillas, y usará el valor resultante como
operando.
[5
]
Como una cadena encerrada en llaves. Los caracteres entre la llave de apertura y la llave de cierre correspondiente se usarán como operando sin ninguna
sustitución.
[6
]
Como un comando Tcl encerrado entre corchetes. El comando se ejecutará y su resultado se usará como
operando.
[7
]
Como una función matemática cuyos argumentos tienen cualquiera de las formas anteriores para los operandos, como sin($x). Ver FUNCIONES MATEMÁTICAS más abajo para una discu
sión sobre cómo se manejan
las funciones matemáticas.

Donde ocurren las sustituciones anteriores (p. ej., dentro de cadenas entrecomilladas), son realizadas por las instrucciones de la expresión. Sin embargo, el analizador de comandos puede haber realizado ya una ronda de sustitución antes de que se llamara al procesador de la expresión. Como se discute más abajo, generalmente es mejor encerrar las expresiones entre llaves para evitar que el analizador de comandos realice sustituciones en el

contenido.

Para algunos ejemplos de expresiones simples, supón que la variable a tiene el valor 3 y la variable b tiene el valor 6. Entonces el comando en el lado izquierdo de cada una de las líneas siguientes producirá el valor en el lado derecho de la

línea: 
expr {3.1 + $a}	6.1
expr {2 + "$a.$b"}	5.6
expr {4*[llength "6 2"]}	8
expr {{palabra uno} < "palabra $a"}
0

OPERADORE

S

Los operadores válidos (la mayoría de los cuales también están disponibles como comandos en el espacio de nombres tcl::mathop; ver la página man de mathop(n) para más detalles) se enumeran a continuación, agrupados en orden de precedencia

decreciente:
- + ~
!
Menos unario, más unario, NOT a nivel de bits, NOT lógico. Ninguno de estos operadores puede aplicarse a operandos de cadena, y el NOT a nivel de bits solo puede aplicarse a
enteros.
*
*
Exponenciación. Válido para cualquier operando numérico. El valor máximo del exponente que Tcl puede manejar si el primer número es un entero > 1 es
268435455.
* /
%
Multiplicar, dividir, resto. Ninguno de estos operadores puede aplicarse a operandos
de cadena, y el resto solo puede aplicarse a enteros. El resto siempre tendrá el mis
mo signo que el divisor y un valor absoluto menor que el valor absoluto del divisor.

Cuando se aplican a enteros, los operadores de división y resto pueden considerarse que particionan la recta numérica en una secuencia de piezas adyacentes de igual tamaño y no superpuestas, donde cada pieza es del tamaño del divisor; el resultado de la división identifica en qué pieza se encuentra el divisor, y el resultado del resto identifica dónde dentro de esa pieza se encuentra el divisor. Una consecuencia de esto es que el resultado de “-57 / 10” es siempre -6, y el resultado de “-57 % 10” es s

iempre
3.
+
-
Sumar y restar. Válido para cualquier operando
numérico.
<<
>>
Desplazamiento a la izquierda y a la derecha. Válido solo para operandos enteros. Un desplazamiento a la derecha siempre propaga el bit de
signo.
< > <=
>=
Booleano menor que, mayor que, menor o igual, y mayor o igual. Cada operador produce 1 si la condición es verdadera, 0 en caso contrario. Estos operadores pueden aplicarse a cadenas así como a operandos numéricos, en cuyo caso se utiliza la comparación de
cadenas.
==
!=
Booleano igual y no igual. Cada operador produce un resultado cero/uno. Válido para todos los tipos de
operandos.
eq
ne
Booleano cadena igual y cadena no igual. Cada operador produce un resultado cero/uno. Los tipos de operandos se interpretan solo como
cadenas.
in
ni
Contención en lista y negación de contención en lista. Cada operador produce un resultado cero/uno y trata su primer argumento como una cadena y su segundo argumento como una lista Tcl. El operador in indica si el primer argumento es un miembro de la lista del segundo argumento; el operador ni invierte el sentido del
resultado.
&
AND a nivel de bits. Válido solo para operandos
enteros.
^
OR exclusivo a nivel de bits. Válido solo para operandos
enteros.
|
OR a nivel de bits. Válido solo para operandos
enteros.
&
&
AND lógico. Produce un resultado 1 si ambos operandos son distintos de cero, 0 en caso contrario. Válido solo para operandos booleanos y numéricos (enteros o de punto flotante). Este operador se evalúa de forma perezosa; solo evalúa su segundo operando si es necesario para determinar su
resultado.
|
|
OR lógico. Produce un resultado 0 si ambos operandos son cero, 1 en caso contrario. Válido solo para operandos booleanos y numéricos (enteros o de punto flotante). Este operador se evalúa de forma perezosa; solo evalúa su segundo operando si es necesario para determinar su

z
Si-entonces-de lo contrario, como en C. Si x se evalúa a distinto de cero, entonces el resultado es el valor de y. De lo contrario, el resultado es el valor de z. El operando x debe tener un valor booleano o numérico. Este operador se evalúa de forma perezosa; evalúa solo uno de y o z
.

Ver el manual de C para más detalles sobreen los resultados producidos por cada operador. El operador de exponenciación promueve tipos como los operadores de multiplicación y división, y produce un resultado que es el mismo que la salida de la función pow (después de cualquier conversión de tipos.) Todos los operadores binarios excepto la exponenciación se agrupan de izquierda a derecha dentro del mismo nivel de precedencia; la exponenciación se agrupa de derecha a izquierda. Por ejemplo, el

comando 
expr {4
*2
< 7}

devuelve 0, mientras

que 
expr {2
**3
**2}

devuelve

512.

Los operadores &&, || y ?: tienen “evaluación perezosa”, igual que en C, lo que significa que los operandos no se evalúan si no son necesarios para determinar el resultado. Por ejemplo, en el

comando 
expr {$v
?[a]:
[b]}

solo uno de “[a]” o “[b]” será realmente evaluado, dependiendo del valor de $v. Sin embargo, ten en cuenta que esto solo es cierto si toda la expresión está encerrada en llaves; de lo contrario, el analizador de Tcl evaluará tanto “[a]” como “[b]” antes de invocar el comando ex

pr

MATEMÁTICAS

ejemplo:

n($x+
$y)}

es de todos los maneras el mismo que el procesamiento

de: 
expr {[tcl::mathfunc::sin [expr {$x+$y}]

de: 
tcl::mathfunc::sin [expr {

y}]

El ejecutor buscará tcl::mathfunc::sin usando las reglas habituales para resolver funciones en espacios de nombres. Cualquiera de ::tcl::mathfunc::sin o [namespace current]::tcl::mathfunc::sin satisfará la solicitud, y otros también pueden hacerlo (dependiendo de la configuración actual de la ruta del espacio de nombres)

.

Algunas funciones matemáticas tienen varios argumentos, separados por comas como en C.

Así:

TIPOS, DESBORDAMIENTO Y

PRECISIÓN

Todos los cálculos internos que involucran enteros se realizan llamando a la biblioteca de enteros de precisión múltiple LibTomMath según sea necesario para que todos los cálculos de enteros se realicen exactamente. Ten en cuenta que en las versiones de Tcl anteriores a la 8.5, los cálculos de enteros se realizaban con uno de los tipos de C long int o Tcl_WideInt, lo que causaba una truncación de rango implícita en aquellos cálculos donde los valores desbordaban el rango de esos tipos. Cualquier código que dependiera de estas truncaciones implícitas necesitará añadir explícitamente llamadas a las funciones int() o wide() a las expresiones en los puntos donde se requiere que dicha truncación tenga

lugar.

Todos los cálculos internos que involucran punto flotante se realizan con el tipo de C double. Al convertir una cadena a punto flotante, se detecta el desbordamiento del exponente y resulta en el valor double de Inf o -Inf según corresponda. El desbordamiento y el subdesbordamiento de punto flotante se detectan en la medida en que lo soporta el hardware, lo que generalmente es bastante

fiable.

La conversión entre representaciones internas para operandos de enteros, punto flotante y cadena se realiza automáticamente según sea necesario. Para cálculos aritméticos, se usan enteros hasta que se introduce algún número de punto flotante, después de lo cual se usa punto flotante. Por

ejemplo, 
expr {
5 /
4}

devuelve 1, mientras

que 
expr {5 / 4.0}
expr {5 / ( [string length "abcd"] + 0.0
)
}

ambos devuelven 1.25. Los valores de punto flotante siempre se devuelven con un “.” o un “e” para que no parezcan valores enteros. Por

ejemplo, 
expr {20
.0/
5.0}

devuelve 4.0, no 4

.

OPERACIONES DE

CADENAS

Los valores de cadena pueden usarse como operandos de los operadores de comparación, aunque el evaluador de expresiones intenta hacer comparaciones como enteros o punto flotante cuando puede, es decir, cuando todos los argumentos del operador permiten interpretaciones numéricas, excepto en el caso de los operadores eq y ne. Si uno de los operandos de una comparación es una cadena y el otro tiene un valor numérico, se genera una representación canónica de cadena del valor del operando numérico para compararla con el operando de cadena. La representación canónica de cadena para valores enteros es un formato de cadena decimal. La representación canónica de cadena para valores de punto flotante es la producida por el especificador de formato %g del comando format de Tcl. Por ejemplo, los

comandos 
expr {"0x03" > "2"}
expr {"0y"
> "0
x12"}

ambos devuelven 1. La primera comparación se realiza usando comparación de enteros, y la segunda se realiza usando comparación de cadenas. Debido a la tendencia de Tcl a tratar los valores como números siempre que es posible, generalmente no es una buena idea usar operadores como == cuando realmente quieres una comparación de cadenas y los valores de los operandos podrían ser arbitrarios; es mejor en estos casos usar los operadores eq o ne, o el comand

o s
tri
ng.

CONSIDERACIONES DE

RENDIMIENTO

Encierra las expresiones en llaves para la mejor velocidad y los menores requisitos de almacenamiento. Esto permite que el compilador de código de bytes de Tcl genere el mejor

código.

Como se mencionó anteriormente, las expresiones se sustituyen dos veces: una por el analizador de Tcl y otra por el comando expr. Por ejemplo, los

comandos 
set a 3
set b {$a + 2}
expr
$b
*4

devuelven 11, no un múltiplo de 4. Esto se debe a que el analizador de Tcl sustituirá primero “$a + 2” por la variable b, luego el comando expr evaluará la expresión “$a + 2*

4”.

La mayoría de las expresiones no requieren una segunda ronda de sustituciones. O están encerradas en llaves o, si no lo están, sus sustituciones de variables y comandos producen números o cadenas que no requieren por sí mismas sustituciones. Sin embargo, como algunas expresiones sin llaves necesitan dos rondas de sustituciones, el compilador de código de bytes debe emitir instrucciones adicionales para manejar esta situación. El código más costoso se requiere para expresiones sin llaves que contienen sustituciones de comandos. Estas expresiones deben implementarse generando nuevo código cada vez que se ejecuta la

expresión.

Si es necesario incluir una cadena de expresión no constante dentro del contexto más amplio de una expresión que de otro modo es constante, la técnica más eficiente es poner la parte variable dentro de un expr recursivo, ya que esto al menos permite la compilación de la parte externa, aunque significa que la parte variable debe evaluarse por sí misma como una expresión separada. Así, en este ejemplo el resultado es 20 y la expresión externa se beneficia de la compilación de código de bytes completamente en

caché. 
set a 3
set b {$a + 2}
expr {[expr $
b] *
4}

Cuando la expresión está sin llaves para permitir la sustitución de una función u operador, considera usar directamente los comandos documentados en las páginas del manual mathfunc(n) o matho

p(n
).

EJEMPLO

S

Define un procedimiento que calcula una función matemática

“interesante”: 
proc tcl::mathfunc::calc {x y} {
    expr { ($x**2 - $y**2) / exp($x**2 + $y**2) }
}

Convierte coordenadas polares en coordenadas

cartesianas: 
# convertir de ($radius,$angle)
set x [expr { $radius * cos($angle) }]
set y [expr { $radius * sin($angle)
}
]

Convierte coordenadas cartesianas en coordenadas

polares: 
# convertir de ($x,$y)
set radius [expr { hypot($y, $x) }]
set angle  [expr { atan2($y, $x)
}
]

Imprime un mensaje describiendo la relación de dos valores de cadena entre

sí: 
puts "a and b are [expr {$a eq $b ? {equal} : {different}}
]
"

Establece una variable para indicar si una variable de entorno está definida en absoluto y también está establecida en un valor booleano

verdadero: 
set isTrue [expr {
    [info exists ::env(SOME_ENV_VAR)] &&
    [string is true -strict $::env(SOME_ENV_VAR)]
}
]

Genera un entero aleatorio en el rango 0..99

inclusive: 
set randNum [expr { int(100 * rand())
}
]
