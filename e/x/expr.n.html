TIPOS, DESBORDAMIENTO Y

PRECISIÓN

Todos los cálculos internos que involucran enteros se realizan llamando a la biblioteca de enteros de precisión múltiple LibTomMath según sea necesario para que todos los cálculos de enteros se realicen exactamente. Ten en cuenta que en las versiones de Tcl anteriores a la 8.5, los cálculos de enteros se realizaban con uno de los tipos de C long int o Tcl_WideInt, lo que causaba una truncación de rango implícita en aquellos cálculos donde los valores desbordaban el rango de esos tipos. Cualquier código que dependiera de estas truncaciones implícitas necesitará añadir explícitamente llamadas a las funciones int() o wide() a las expresiones en los puntos donde se requiere que dicha truncación tenga

lugar.

Todos los cálculos internos que involucran punto flotante se realizan con el tipo de C double. Al convertir una cadena a punto flotante, se detecta el desbordamiento del exponente y resulta en el valor double de Inf o -Inf según corresponda. El desbordamiento y el subdesbordamiento de punto flotante se detectan en la medida en que lo soporta el hardware, lo que generalmente es bastante

fiable.

La conversión entre representaciones internas para operandos de enteros, punto flotante y cadena se realiza automáticamente según sea necesario. Para cálculos aritméticos, se usan enteros hasta que se introduce algún número de punto flotante, después de lo cual se usa punto flotante. Por

ejemplo, 
expr {
5 /
4}

devuelve 1, mientras

que 
expr {5 / 4.0}
expr {5 / ( [string length "abcd"] + 0.0
)
}

ambos devuelven 1.25. Los valores de punto flotante siempre se devuelven con un “.” o un “e” para que no parezcan valores enteros. Por

ejemplo, 
expr {20
.0/
5.0}

devuelve 4.0, no 4

.

OPERACIONES DE

CADENAS

Los valores de cadena pueden usarse como operandos de los operadores de comparación, aunque el evaluador de expresiones intenta hacer comparaciones como enteros o punto flotante cuando puede, es decir, cuando todos los argumentos del operador permiten interpretaciones numéricas, excepto en el caso de los operadores eq y ne. Si uno de los operandos de una comparación es una cadena y el otro tiene un valor numérico, se genera una representación canónica de cadena del valor del operando numérico para compararla con el operando de cadena. La representación canónica de cadena para valores enteros es un formato de cadena decimal. La representación canónica de cadena para valores de punto flotante es la producida por el especificador de formato %g del comando format de Tcl. Por ejemplo, los

comandos 
expr {"0x03" > "2"}
expr {"0y"
> "0
x12"}

ambos devuelven 1. La primera comparación se realiza usando comparación de enteros, y la segunda se realiza usando comparación de cadenas. Debido a la tendencia de Tcl a tratar los valores como números siempre que es posible, generalmente no es una buena idea usar operadores como == cuando realmente quieres una comparación de cadenas y los valores de los operandos podrían ser arbitrarios; es mejor en estos casos usar los operadores eq o ne, o el comand

o s
tri
ng.

CONSIDERACIONES DE

RENDIMIENTO

Encierra las expresiones en llaves para la mejor velocidad y los menores requisitos de almacenamiento. Esto permite que el compilador de código de bytes de Tcl genere el mejor

código.

Como se mencionó anteriormente, las expresiones se sustituyen dos veces: una por el analizador de Tcl y otra por el comando expr. Por ejemplo, los

comandos 
set a 3
set b {$a + 2}
expr
$b
*4

devuelven 11, no un múltiplo de 4. Esto se debe a que el analizador de Tcl sustituirá primero “$a + 2” por la variable b, luego el comando expr evaluará la expresión “$a + 2*

4”.

La mayoría de las expresiones no requieren una segunda ronda de sustituciones. O están encerradas en llaves o, si no lo están, sus sustituciones de variables y comandos producen números o cadenas que no requieren por sí mismas sustituciones. Sin embargo, como algunas expresiones sin llaves necesitan dos rondas de sustituciones, el compilador de código de bytes debe emitir instrucciones adicionales para manejar esta situación. El código más costoso se requiere para expresiones sin llaves que contienen sustituciones de comandos. Estas expresiones deben implementarse generando nuevo código cada vez que se ejecuta la

expresión.

Si es necesario incluir una cadena de expresión no constante dentro del contexto más amplio de una expresión que de otro modo es constante, la técnica más eficiente es poner la parte variable dentro de un expr recursivo, ya que esto al menos permite la compilación de la parte externa, aunque significa que la parte variable debe evaluarse por sí misma como una expresión separada. Así, en este ejemplo el resultado es 20 y la expresión externa se beneficia de la compilación de código de bytes completamente en

caché. 
set a 3
set b {$a + 2}
expr {[expr $
b] *
4}

Cuando la expresión está sin llaves para permitir la sustitución de una función u operador, considera usar directamente los comandos documentados en las páginas del manual mathfunc(n) o matho

p(n
).
