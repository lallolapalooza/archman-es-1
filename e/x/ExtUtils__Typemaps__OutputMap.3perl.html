ExtUtils::Typemaps::OutputMap(3perl) Guía de referencia para programadores de Perl ExtUtils::Typemaps::OutputMap(3perl)

NOMBRE

ExtUtils::Typemaps::OutputMap - Entrada en la sección OUTPUT de un typemap

SINOPSIS

use ExtUtils::Typemaps;
...
my $output = $typemap->get_output_map('T_NV');
my $code = $output->code();
$output->code("...");

DESCRIPCIÓN

Consulte ExtUtils::Typemaps para obtener detalles.

MÉTODOS

new

Requiere los parámetros "xstype" y "code".

code

Devuelve o establece el código de mapeo de SALIDA para esta entrada.

xstype

Devuelve el nombre del tipo XS del mapa de SALIDA.

cleaned_code

Devuelve una copia limpiada del código al que se han aplicado ciertas transformaciones para hacerlo más compatible con ANSI.

targetable_legacy

No utilizar para código nuevo.

Esta es la versión original del método targetable(), cuyo comportamiento se ha congelado por compatibilidad con versiones anteriores. Se utiliza para determinar si se debe emitir un temprano "dXSTARG", que estará en el ámbito para la mayor parte de la XSUB. La generación de código XSUB más reciente emite un "dXSTARG" en un ámbito más reducido si aún no se ha emitido uno. Algunos códigos XS asumen que "TARG" ha sido declarado, así que continúe declarándolo bajo las mismas condiciones que antes. El método más nuevo "targetable" puede ser verdadero en circunstancias adicionales.

Si la optimización no se puede aplicar, esto devuelve undef. Si se puede aplicar, este método devuelve una referencia de hash que contiene la siguiente información:

type:      Cualquiera de los caracteres i, u, n, p
with_size: Booleano que indica si esta es la variante sv_setpvn
what:      El código que se evalúa realmente al escalar de salida
what_size: Si es "with_size", esto tiene la longitud de la cadena (como código,
           no constante, incluyendo la coma inicial)

targetable

Método de clase.

Devuelve un booleano que indica si el fragmento de código proporcionado es adecuado para usar TARG como SV de destino en lugar de un nuevo mortal.

En principio, la mayoría de las cosas lo son, excepto las expresiones que establecerían el SV a un valor de referencia. Eso puede hacer que el valor referenciado nunca se libere, ya que los targs no se liberan (al menos durante la vida útil de su CV). Así que, en la práctica, lo restringimos a una lista aprobada de formularios sv_setfoo(), y solo donde no hay código adicional después de sv_setfoo() (por lo que tenemos que coincidir con el corchete de cierre, permitiendo corchetes anidados, etc., dentro).
