XSBuilder - ¿Qué es?

Su propósito es generar automáticamente una interfaz de Perl para código C

Resuelve el problema de que la interfaz de Perl no siempre está actualizada con la interfaz C

Ahorra mucho trabajo de copiar y pegar

Los cambios sistemáticos solo deben hacerse una vez

Por ejemplo, cambios en la gestión de memoria de cadenas.

Es parte del sistema de construcción de mod_perl 2.0

La mayor parte del código fue desarrollada por Doug MacEachern. Adicionalmente, he

abstraído el código de mod_perl para que sea utilizable para cualquier código C
añadido nuevas características como devoluciones de llamada y la capacidad de analizar comentarios
Reemplacé C::Scan con Parse::RecDescent para ser independiente de plataforma y compilador

El objetivo es reemplazar el código actual de generación XS de mod_perl con XSBuilder

Inline versus XSBuilder

Inline: incrustar código C en Perl
XSBuilder: Crear una interfaz para bibliotecas/aplicaciones C existentes

XSBuilder - ¿Qué hace?

Crear funciones/métodos de Perl para cada función C

La función puede asignarse a diferentes paquetes, también automáticamente al inspeccionar el primer parámetro

Crear una clase de Perl para cada estructura C

Cada elemento de la estructura se convierte en un método de Perl para obtener/establecer su valor. El objeto puede ser una referencia a escalar (usada por mod_perl) o una referencia a un hash (usada por Embperl), lo que permite almacenar datos adicionales por el código Perl en este hash.

Crear código de enlace para manejar devoluciones de llamada

Hay varios tipos de devolución de llamada, no todos están implementados en este momento

Crear subrutinas constantes de Perl

Analizar el código fuente

Crea tu propia clase ParseSource y sobrescribe los métodos...

package Apache::DAV::ParseSource;
use strict;
use vars qw{@ISA $VERSION} ;
use ExtUtils::XSBuilder::ParseSource  ;
@ISA = ('ExtUtils::XSBuilder::ParseSource') ;
$VERSION = '0.01';
my $dav_dir = 'C:\perl\msrc\cvs\mod_dav' ;
my $ap_dir  = 'c:\programme\apache group\apache' ;
# ============================================================================
sub find_includes {
    my $self = shift;
    return $self->{includes} if $self->{includes};
    my @includes = ("$ap_dir/include/ap_alloc.h", "$dav_dir/mod_dav.h") ;
    return $self->{includes} = $self -> sort_includes (\@includes) ;
    }
# ============================================================================
sub package     { 'Apache::DAV' } 
# ============================================================================
sub preprocess {
    my $self     = shift ;
    $_[0] =~ s/(?:API_EXPORT)(?:_NONSTD)?\s*\(\s*(.*?)\s*\)/$1/g ;
}
1;

Crear los archivos de mapeo

Los archivos de mapeo se utilizan para indicar a XSBuilder cómo deben mapearse los tipos de datos, las estructuras y los argumentos de las funciones de C en los de Perl.

Crea tu propia clase WrapXS y sobrescribe los métodos

package Apache::DAV::WrapXS ;
use strict;
use vars qw{@ISA $VERSION} ;
use ExtUtils::XSBuilder::WrapXS ;
@ISA = ('ExtUtils::XSBuilder::WrapXS') ;
$VERSION = '0.01';
# ============================================================================
sub new_parsesource  { [ Apache::DAV::ParseSource->new ] }
# ============================================================================
sub my_xs_prefix  { 'davxs_' }
# ============================================================================
sub h_filename_prefix  { 'moddav_xs_' }
# ============================================================================
sub xs_includes {
    my $self = shift ;
    my $i = $self -> SUPER::xs_includes ;
    my @i = grep (!/ap_alloc/, @$i) ;
    return \@i ;
}

Ahora tenemos cuatro archivos de mapeo

new_types.map
Contiene el mapeo del tipo de C a las clases de Perl
new_functions.map
Contiene el mapeo de las funciones de C a las funciones de Perl. Puede usarse para reordenar argumentos, indicar a XSBuilder qué argumentos son en realidad valores de retorno y en qué paquete de Perl se creará la función.
new_structures.map
Contiene el mapeo de las estructuras de C a las clases de Perl y define para qué miembros se deben crear métodos de acceso. También puedes especificar si quieres un "new" método para la clase.
new_callbacks.map
Contiene el mapeo de las funciones de retorno de llamada de C a las funciones de retorno de llamada de Perl. Puede usarse para reordenar argumentos, indicar a XSBuilder qué argumentos son en realidad valores de retorno y en qué paquete de Perl se creará la función.

Es una buena idea renombrar el prefijo de "new_" a algo único, aquí usamos "dav"

Cada vez que vuelvas a ejecutar checkmaps, XSBuilder creará archivos new_* con los elementos que aún no forman parte de los otros mapas.

mapa de funciones

El mapa de funciones define el mapeo de los argumentos de las funciones de C a los argumentos de Perl

Indica a XSBuilder dónde colocar las funciones y qué prefijo eliminar

La siguiente entrada del archivo de mapeo le indica a XSBuilder que el valor de "res_p" debe ser devuelto
dav_get_resource           | | r, <res_p

La función C

int dav_get_resource(request_rec *r, dav_resource **res_p) ;

Cómo llamarla desde Perl

# get a sub request of the actual document
$subr = $r -> lookup_uri($uri);
# get a mod_dav resource object
my ($err, $resource) =  $subr->get_resource;
Puedes permitir que XSBuilder inserte tu código personalizado, para la interfaz
Si llamas a "get_props" desde Perl "glue_dav_get_props" será llamado, lo que puede ajustar los argumentos y los tipos de retorno según sea necesario. El código real para "glue_dav_get_props" se tomará de un archivo de inclusión separado. 
dav_get_props      | glue_
dav_get_allprops   | glue_

xsinclude\Apache\DAV\PropResult\Apache__DAV__PropResults.h

dav_get_props_result * dav_glue_get_props(dav_propdb * db, dav_xml_doc *doc)
    {
    dav_get_props_result * result = (dav_get_props_result *)ap_palloc (db -> p, sizeof (dav_get_props_result)) ;
    *result = dav_get_props(db, doc) ;
    return result ;
    }
Los argumentos pueden ser reemplazados
MODULE=Apache::Array   PACKAGE=Apache::Array PREFIX=ap_
 ap_make_array      | ap_make_array(r->pool, nelts, elt_size) | request_rec *:r, nelts, elt_size

ap_make_array requiere un pool como primer parámetro, pasamos el request_rec desde Perl y XSBuilder tomará el pool del request_rec.

Makefile.PL

Necesitamos crear un Makefile.PL de nivel superior

use ExtUtils::MakeMaker ();

my $apdir  = '/path/to/apache';
my $davdir = '/path/to/moddav';
%MMARGS = (
           'INC'    => "-I\"$davdir\" -I\"$apdir/include\" -I\"$apdir/os/unix\" -I\"$dir/xs\"  -I\"$dir/xsinclude\"",
           ) ;
open FH, ">xs/mmargs.pl" or die "Cannot open xs/mmargs.pl ($!)" ;
print FH Data::Dumper -> Dump ([\%MMARGS], ['MMARGS']) ;
close FH ;
ExtUtils::MakeMaker::WriteMakefile(
    'NAME'    => 'Apache::DAV',
    'VERSION' => '0.13',
    %MMARGS,
);

Generando documentación

XSBuilder ya extrae los comentarios del código fuente para funciones y estructuras. También analiza los comentarios doxygen, que se utilizan en Apache 2.0. Lyle Brooks ha comenzado a crear automáticamente archivos POD a partir de esta información.
