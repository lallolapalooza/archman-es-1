nfsv4.exportd(8) Manual del Administrador del Sistema nfsv4.exportd(8)

NOMBRE

nfsv4.exportd - Demonio de montaje del servidor NFSv4

SINOPSIS

/usr/sbin/nfsv4.exportd [opciones]

DESCRIPCIÓN

El demonio nfsv4.exportd se utiliza para administrar las exportaciones de NFSv4. El servidor NFS (nfsd) mantiene una caché de información de autenticación y autorización que se utiliza para identificar el origen de cada solicitud y, a continuación, qué permisos de acceso tiene ese origen al sistema de archivos local. Cuando la información requerida no se encuentra en la caché, el servidor envía una solicitud a nfsv4.exportd para completar la información faltante. nfsv4.exportd utiliza una tabla de información almacenada en /var/lib/nfs/etab y mantenida por exportfs(8), posiblemente basada en el contenido de exports(5), para responder a cada solicitud.

OPCIONES

-d kind o --debug kind
Activa la depuración. Los tipos válidos son: all, auth, call, general y parse.
-l o --log-auth
Habilita el registro de respuestas a las solicitudes de autenticación y acceso de nfsd. Cada respuesta se almacena en caché en el kernel durante 30 minutos (o según se establezca con --ttl a continuación), y se actualizará después de 15 minutos (la mitad del tiempo de ttl) si el cliente relevante permanece activo. Tenga en cuenta que -l es equivalente a -d auth y, por lo tanto, se puede habilitar en /etc/nfs.conf con "debug = auth" en la sección [exportd].
-i o --cache-use-ipaddr
Normalmente, cada dirección IP del cliente se compara con cada identificador de host (nombre, comodín, netgroup, etc.) que se encuentra en /etc/exports y se forma una identidad combinada a partir de todos los identificadores coincidentes. A menudo, muchos clientes se mapearán a la misma identidad combinada, por lo que realizar este mapeo reduce el número de detalles de acceso distintos que el kernel necesita almacenar. Especificar la opción -i suprime este mapeo, de modo que el acceso a cada sistema de archivos se solicita y se almacena en caché por separado para cada dirección IP del cliente. Hacer esto puede aumentar ligeramente la carga de actualizar la caché, pero puede hacer que los mensajes de registro producidos por la opción -l sean más fáciles de leer.
-T o --ttl
Proporciona un tiempo de vida (TTL) para la información en caché dada al kernel. Normalmente, el kernel solicitará una actualización si la información es necesaria después de que haya transcurrido la mitad de este tiempo. Aumentar el número proporcionado, que está en segundos, reduce la tasa de solicitudes de actualización de la caché, y esto es particularmente notable cuando estas solicitudes se registran con -l. Sin embargo, aumentar también significa que los cambios en los mapeos de nombres de host a direcciones pueden tardar más en ser detectados. El TTL predeterminado es 1800 (30 minutos).
-F o --foreground
Ejecutar en primer plano (no demonizar)
-h o --help
Mostrar mensaje de uso.
-t N o --num-threads=N o --num-threads N
Esta opción especifica el número de hilos de trabajo que nfsv4.exports crea. El valor predeterminado es 1 hilo, lo que probablemente sea suficiente. Se necesitan más hilos generalmente solo para servidores NFS que necesitan manejar tormentas de montaje de cientos de montajes NFS en unos pocos segundos, o cuando su servidor DNS es lento o poco fiable.
-g o --manage-gids
Aceptar solicitudes del kernel para mapear números de ID de usuario en listas de números de ID de grupo para su uso en control de acceso. Una solicitud NFS normalmente (excepto cuando se usa Kerberos u otra autenticación criptográfica) contendrá un ID de usuario y una lista de ID de grupo. Debido a una limitación en el protocolo NFS, solo se pueden enumerar como máximo 16 ID de grupo. Si usa la bandera -g, la lista de ID de grupo recibida del cliente se reemplazará por una lista de ID de grupo determinada por una búsqueda apropiada en el servidor. Tenga en cuenta que el ID de grupo 'primario' no se afecta, por lo que un comando newgroup en el cliente seguirá siendo efectivo. Esta función requiere un kernel de Linux con una versión de al menos 2.6.21.

ARCHIVO DE CONFIGURACIÓN

Muchas de las opciones que se pueden establecer en la línea de comandos también se pueden controlar a través de valores establecidos en las secciones [exportd] o, en algunos casos, [nfsd] del archivo de configuración /etc/nfs.conf. Los valores reconocidos en la sección [exportd] incluyen cache-use-ipaddr, ttl, manage-gids y debug, cada uno con el mismo efecto que la opción con el mismo nombre.

ARCHIVOS

/etc/exports
archivo de entrada para exportfs, que enumera exportaciones, opciones de exportación y listas de control de acceso
