NOMBRE

ExtUtils::MakeMaker::Tutorial - Escribir un módulo con MakeMaker

SINOPSIS

use ExtUtils::MakeMaker;
WriteMakefile(
    NAME            => 'Your::Module',
    VERSION_FROM    => 'lib/Your/Module.pm'
);

DESCRIPCIÓN

Este es un breve tutorial sobre cómo escribir un módulo simple con MakeMaker. Realmente no es tan difícil.

El Mantra

Los módulos de MakeMaker se instan usando este simple mantra

perl Makefile.PL
make
make test
make install

Hay muchos más comandos y opciones, pero lo anterior es suficiente.

La Estructura

Los archivos básicos de un módulo se ven algo así.

Makefile.PL
MANIFEST
lib/Your/Module.pm

Eso es todo lo estrictamente necesario. Hay archivos adicionales que podrías querer:

lib/Your/Other/Module.pm
t/some_test.t
t/some_other_test.t
Changes
README
INSTALL
MANIFEST.SKIP
bin/some_program
Makefile.PL
Cuando ejecutas Makefile.PL, este crea un Makefile. Ese es todo el propósito de MakeMaker. El Makefile.PL es un programa simple que carga ExtUtils::MakeMaker y ejecuta la WriteMakefile() función para generar un Makefile.

Aquí tienes un ejemplo de lo que necesitas para un módulo simple:

use ExtUtils::MakeMaker;
WriteMakefile(
    NAME            => 'Your::Module',
    VERSION_FROM    => 'lib/Your/Module.pm'
);

NAME es el espacio de nombres de nivel superior de tu módulo. VERSION_FROM es el archivo que contiene la $VERSION variable para toda la distribución. Típicamente este es el mismo que tu módulo de nivel superior.

MANIFEST
Un listado simple de todos los archivos en tu distribución. 
Makefile.PL
MANIFEST
lib/Your/Module.pm

Las rutas de archivo en un MANIFEST siempre usan convenciones de Unix (es decir, /) incluso si no estás en Unix.

Puedes escribirlo a mano o generarlo con 'make manifest'.

Consulta ExtUtils::Manifest para más detalles.

lib/
Este es el directorio donde van los archivos .pm y .pod que deseas tener instalados. Están organizados según el espacio de nombres. Así que Foo::Bar es lib/Foo/Bar.pm.
t/
Las pruebas de tus módulos van aquí. Cada nombre de archivo de prueba termina con .t. Así que t/foo.t 'make test' ejecutará estas pruebas.

Típicamente, el t/ directorio de pruebas es plano, con todos los archivos de prueba ubicados directamente dentro de él. Sin embargo, puedes anidar pruebas dentro de subdirectorios, por ejemplo:

t/foo/subdir_test.t

Para hacer esto, necesitas informar a WriteMakefile() en tu Makefile.PL archivo de la siguiente manera:

test => {TESTS => 't/*.t t/*/*.t'}

Eso ejecutará todas las pruebas en t/, así como todas las pruebas en todos los subdirectorios que residen bajo t/. Puedes anidar tan profundamente como tenga sentido para tu proyecto. Simplemente agrega otra entrada en la cadena de ubicación de pruebas. Por ejemplo, para probar:

t/foo/bar/subdir_test.t

Usarías la siguiente "test" directiva:

test => {TESTS => 't/*.t t/*/*/*.t'}

Ten en cuenta que en el ejemplo anterior, las pruebas en el primer subdirectorio no se ejecutarán. Para ejecutar todas las pruebas en el subdirectorio intermedio que precede al que contienen los archivos de prueba, necesitas anotarlo explícitamente:

test => {TESTS => 't/*.t t/*/*.t t/*/*/*.t'}

No necesitas especificar comodines si solo quieres probar dentro de subdirectorios específicos. El siguiente ejemplo solo ejecutará pruebas en t/foo:

test => {TESTS => 't/foo/*.t'}

Las pruebas se ejecutan desde el nivel superior de tu distribución. Así que dentro de una prueba te referirías a ./lib para entrar al directorio lib, por ejemplo.

Changes
Un registro de los cambios que has hecho a este módulo. La estructura es de forma libre. Aquí tienes un ejemplo: 
1.01 Fri Apr 11 00:21:25 PDT 2003
    - thing() hace algunas cosas ahora
    - corregido el error raro en withit()
1.00 Mon Apr  7 00:57:15 PDT 2003
    - "Rain of Frogs" ahora soportado
README
Una breve descripción de tu módulo, qué hace, por qué alguien lo usaría y sus limitaciones. CPAN automáticamente extrae tu archivo README del archivo comprimido y lo pone disponible para los usuarios de CPAN, es lo primero que leerán para decidir si tu módulo es adecuado para ellos.
INSTALL
Instrucciones sobre cómo instalar tu módulo junto con cualquier dependencia. Información sugerida para incluir aquí: 
cualquier módulo extra requerido para usar
la versión mínima de Perl requerida
si solo funciona en ciertos sistemas operativos
MANIFEST.SKIP
Un archivo lleno de expresiones regulares para excluir cuando se usa 'make manifest' para generar el MANIFEST. Estas expresiones regulares se verifican contra cada ruta de archivo encontrada en la distribución (así que estás comparando contra "t/foo.t" no "foo.t").

Aquí tienes un ejemplo:

~$          # ignorar archivos de respaldo de emacs y vim
.bak$       # ignorar respaldos manuales
\#          # ignorar archivos de revisiones antiguas de CVS y archivos temporales de emacs

Dado que # puede usarse para comentarios, # debe escaparse.

MakeMaker viene con un MANIFEST.SKIP predeterminado para evitar cosas como directorios de control de versiones y archivos de respaldo. Especificar el tuyo propio anulará este valor predeterminado.
