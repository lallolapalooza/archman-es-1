Archivo de mapeo de tipos

Contiene la correspondencia entre tipos de C y clases de Perl.

El formato es el nombre del tipo de C seguido del nombre de la clase de Perl o el especificador de tipo XS, separados por un "|". Ejemplo:

int                 | IV
struct request_rec  | Apache::RequestRec

Si tienes una clase de Perl con un espacio de nombres de un solo nivel (por ejemplo, Apache) necesitas posponerle dos dos puntos (por ejemplo, "Apache::"). Cuando un typedef y una estructura comparten el mismo nombre, las estructuras deben escribirse con el prefijo "struct " (por ejemplo, "struct foo".) Adicionalmente, puedes dar el id para el typemap si necesitas una conversión especial y uno o más otros nombres para la estructura:

struct request_rec  | Apache::RequestRec | T_APACHEOBJ | r

Un quinto parámetro opcional especifica que los datos necesitan ser copiados cuando se asignan a un miembro de la estructura y selecciona la forma en que se asigna la memoria:

char *   | PV | | | strdup

El código real para la asignación de memoria se proporciona dentro del mapa de estructura, por ejemplo:

MALLOC=strdup:$dest = ($type)ap_pstrdup(obj -> pool, $src)
MALLOC=malloc:ap_palloc(obj -> pool, $src, sizeof($type)) ; memcpy($dest,$src,sizeof($type))

Esto da dos formas de asignar memoria y copiar los datos en ella. El quinto parámetro en el mapa de tipos selecciona cuál de estos dos debe usarse. $src, $dest y $type son reemplazados por el origen, el destino y el tipo. "obj" es un puntero a la estructura de C.

Tipos Especiales

Cadena, PV y PVnull
Una cadena se representa en C como un puntero a un rango de caracteres terminado por nulo. En Perl se le llama "PV" (valor de puntero). Al convertir un "undef" de Perl a una cadena de C, Perl por defecto lo convierte en una cadena vacía. Aunque esto es seguro, no siempre es lo que se requiere, porque muchas interfaces de C tratan NULL como un caso especial. Por esta razón se introduce el tipo "PVnull" , que convierte "undef" en "NULL" y "NULL" en "undef".

Para hacerlo funcionar necesitas la siguiente línea en tu archivo de mapa de tipos:

PVnull          | PVnull | | | strdup

Ahora puedes definir cualquier tipo, miembro de estructura o argumento de función como tipo "PVnull".

Archivo de mapa de funciones

Contiene la correspondencia entre funciones de C y funciones de Perl. Esto puede usarse para reordenar argumentos, decirle a XSBuilder cuáles argumentos son valores de retorno, y en qué paquete de Perl se creará la función.

Hay algunas directivas que afectan a las correspondencias de funciones que le siguen. Cada directiva puede aparecer en el archivo más de una vez.

MODULE
el nombre del módulo (nombre del archivo) donde se debe definir la función, por ejemplo 
MODULE=Apache::Connection

definirá las funciones que siguen en archivos llamados Apache/Connection.{pm,xs}

PACKAGE
El nombre del paquete en el que se definen las funciones. Si no está definido, PACKAGE toma por defecto el valor de MODULE. Un valor de 'guess' indica que el nombre del paquete debe deducirse basándose en el primer argumento que se encuentre y que se corresponda con una clase de Perl. Recurre al prefijo (ap_ -> Apache, apr_ -> APR).
PREFIX
El prefijo que se debe eliminar de las funciones de C al crear los stubs XS. Por defecto es el valor de PACKAGE, convertido a la convención de nombres de C. Por ejemplo, 
PREFIX=APR::Base64

eliminará "apr_base64_" de las funciones de C. Si el prefijo no coincide, por defecto es "ap_" o "apr_".

NOTA: Debes tener al menos una definición de "MODULE" de lo contrario todas las funciones serán ignoradas.

El formato de las entradas es:

Nombre de la función C | nombre de la función de despacho (argspec de despacho) | argspec | alias de Perl

El "nombre de la función de despacho" (la función de C que se llama realmente) por defecto es el nombre de la función de C. Si el nombre de la función de despacho es solo un prefijo (mpxs_, MPXS_), se le añade el "nombre de la función de C" . El tipo de retorno puede especificarse antes del "nombre de la función de C", y por defecto es el "return_type" en el módulo "{foo}::FunctionTable" generado por el módulo "ParseSource" .

El "argspec de despacho" es opcional. Si se proporciona, se puede usar para pasar parámetros diferentes a la función de despacho que a la función XS. Si el nombre de la función comienza con "DEFINE_", se define una nueva función (para definir funciones que no se analizan desde el código fuente). "argspec" debe proporcionarse. "DEFINE_" no se incluye en el nombre de la función generada.

El "argspec" por defecto son los argumentos en "{foo}::FunctionTable", tal como lo genera el módulo "ParseSource" . Los tipos de argumento pueden especificarse para anular los de "{foo}::FunctionTable". También se pueden especificar valores por defecto, por ejemplo arg=default_value

Por ejemplo:
ap_get_client_block | mpxs_ | r, SV *:buffer, bufsiz
ap_setup_client_block | | r, read_policy=REQUEST_CHUNKED_ERROR
ap_make_array | ap_make_array(r->pool, nelts, elt_size) | request_rec *:r, nelts, elt_size

Un argspec de '...' indica passthru, llamando a la función con

(aTHX_ I32 items, SP **sp, SV **MARK)

Para marcar un argumento como solo de retorno puedes anteponerle < por ejemplo

dav_open_lockdb | | r, ro, <lockdb

se llamará como ($error obtiene el valor de retorno de la función de C)

($error, $lockdb) = $r -> open_lockdb (0) ;

El argumento de retorno (por ejemplo, lockdb) siempre se pasará por dirección a la función.

El alias de la función, si está definido, se creará en el "PACKAGE"actual.

Los nombres de función en líneas que no comienzan con un carácter de palabra o un espacio simple se omiten. Los nombres de función pueden anteponerse con los siguientes símbolos:

'!' => 'deshabilitado o aún no implementado',
'~' => 'implementado pero no autogenerado',
'-' => 'probablemente nunca estará disponible para Perl',
'>' => '"privado" para tu biblioteca de C',
'?' => 'sin clasificar',

Archivo de mapa de estructuras

Contiene la correspondencia entre estructuras de C y clases de Perl, y define los miembros para los que se deben crear métodos de acceso. Se puede especificar un método "new" , si se desea. El formato es el siguiente:

<struct_name>
  member1
  member2
  new
</struct_name>

Se puede dar un nombre de módulo opcional, para especificar en qué módulo debe colocarse el código. Para colocar la estructura en My::Module, por ejemplo, especifica:

<struct_name MODULE=My::Module>

Para todos los miembros que se listan aquí, XSBuilder generará un método de acceso para leer y escribir su contenido. Si quieres que el método de acceso de Perl se llame diferente al miembro de C, puedes escribir

cMemberValue | member_value | type

esto mapeará el miembro de la estructura "cMemberValue" a la función de acceso "member_value". Por defecto se usa el mismo nombre en Perl que en C. Como tercer argumento puedes dar un nombre de tipo. Por defecto es el tipo de la variable. Se puede usar para especificar un tipo diferente, para necesidades de conversión especiales (por ejemplo, PV versus PVnull). Si das el miembro "new" , XSBuilder creará un método new para esa clase, que se puede usar para crear una nueva instancia e inicializarla con datos.

Archivo de mapa de callbacks

El formato de las entradas es:

Nombre de la función C | argspec

El contenido es el mismo que el del mapa de funciones, pero contiene los callbacks.

Métodos adicionales generados

Para las estructuras, XSBuilder generará dos métodos adicionales: "new", y "init_callbacks".

new ($initialvalue)

Con "new" puedes crear un nuevo objeto Perl para una estructura de C. Opcionalmente, puedes pasar una referencia a un hash con datos iniciales, u otro objeto, cuyos datos serán copiados en el nuevo objeto.

init_callbacks

"init_callbacks" debe llamarse durante la inicialización del objeto. Rellenará todos los miembros de callback de una estructura con punteros que provocan una llamada a un método en el objeto, cuando el callback es llamado desde C.

Puedes llamarlo con

$obj -> init_callbacks

o

MyModule -> init_callbacks ($obj) ;

Callbacks

Un callback que es parte de una estructura provocará una llamada al método con el mismo nombre que el miembro de la estructura, anteponiéndole "cb_". Por ejemplo, si tienes un miembro de estructura llamado "open", entonces el método de Perl "cb_open" será llamado siempre que el código de C llame al callback.

Si quieres llamar al callback por tu cuenta necesitas llamar al método que se llama como el miembro de la estructura, por ejemplo "open".

NOTA: Necesitasnecesita llamar "init_callbacks" durante la inicialización de su método para poder llamar a las funciones de retorno de llamada.
