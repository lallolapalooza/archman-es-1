DESCRIPCIÓ

N

Los segundos, terceros y cuartos sistemas de archivos extendidos, o ext2, ext3 y ext4 como se los conoce comúnmente, son sistemas de archivos de Linux que históricamente han sido el sistema de archivos predeterminado para muchas distribuciones de Linux. Son

sistemas de archivos de propósito general que han sido diseñados para la extensibilidad y la compatibilidad hacia atrás. En particular, los sistemas de archivos previamente destinados para su uso con los sistemas de archivos ext2 y ext3 pueden ser monta
dos usando el controlador del sistema de archivos ext4, y de hecho en muchas distribuciones modernas de Linux, el controlador del sistema de archivos ext4 ha sido configurado para manejar solicitudes de montaje para los sistemas de archivos ext2 y ext3.

ARCHIVOS

Un sistema de archivos formateado para ext2, ext3 o ext4 puede tener alguna colección de las siguientes banderas de características del sistema de archivos habilitadas. Algunas de estas características no son soportadas por todas las implementaciones de los controladores de los sistemas de archivos ext2, ext3 y ext4, dependiendo de la versión del kernel de Linux en uso. En otros sistemas operativos, como GNU/HURD o FreeBSD, solo un conjunto muy restrictivo de características del sistema de archivos puede ser soportado en sus implementaciones de

ext2.

Esta característica se establece automáticamente, según sea necesario, pero puede ser útil especificar esta característica explícitamente si el sistema de archivos podría necesitar ser redimensionado a más de 2^32 bloques, incluso si era más pequeño que ese umbral cuando fue creado originalmente. Tenga en cuenta que algunos kernels más antiguos y versiones más antiguas de e2fsprogs no soportarán sistemas de archivos con esta característica de ext4
habilitada.

El sistema de archivo `ext2' es el sistema de archivo estándar de Linux. Desde Linux 2.5.46, para la mayoría de las opciones de montaje el valor por defecto está determinado por el superbloque del sistema de archivo. Establézcalas con tune2fs

Opciones de montaje para

ext3

El sistema de archivos ext3 es una versión del sistema de archivos ext2 que ha sido mejorado con registro (journaling). Soporta las mismas opciones que ext2 así como las siguientes

adiciones:
journal_dev=devnum/journal_path=p
ath
Cuando los números mayor/menor del dispositivo de registro externo han cambiado, estas opciones permiten al usuario especificar la nueva ubicación del registro. El dispositivo de registro se identifica ya sea a través de sus nuevos números mayor/menor codificados en devnum, o a través de una ruta al
dispositivo.
norecovery/nolo
ad
No cargar el registro al montar. Ten en cuenta que si el sistema de archivos no fue desmontado limpiamente, omitir la reproducción del registro llevará a que el sistema de archivos contenga inconsistencias que pueden llevar a cualquier número de
problemas.

k}
Especifica el modo de registro para los datos de archivo. Los metadatos siempre se registran. Para usar modos distintos de ordered en el sistema de archivos raíz, pasa el modo al núcleo como parámetro de arranque, p. ej. rootflags=data=journa
l
.
journ
al
Todos los datos se confirman en el registro antes de ser escritos en el sistema de archivos
principal.
order
ed
Este es el modo predeterminado. Todos los datos se fuerzan directamente al sistema de archivos principal antes de que sus metadatos se confirmen en el
registro.
writeba
ck
El orden de los datos no se conserva – los datos pueden escribirse en el sistema de archivos princi
pal después de que sus metadatos se hayan confirmado en el registro. Se rumorea que esta es la opci
ón de mayor rendimiento. Garantiza la integridad interna del sistema de archivos, sin embargo, puede
permitir que datos antiguos aparezcan en archivos después de un fallo y recuperación del registro.
data_err=ign
ore
Solo imprimir un mensaje de error si ocurre un error en un búfer de datos de archivo en modo
ordered.
data_err=abo
rt
Abortar el registro si ocurre un error en un búfer de datos de archivo en modo
ordered.
barrier=0 / barrier
=1
Esto deshabilita / habilita el uso de barreras de escritura en el código jbd. barrier=0 deshabilita, barrier=1 habilita (predeterminado). Esto también requiere una pila de IO que pueda soportar barreras, y si jbd obtiene un error en una escritura de barrera, deshabilitará las barreras de nuevo con una advertencia. Las barreras de escritura imponen el ordenamiento correcto en disco de las confirmaciones del registro, haciendo seguros los búferes de escritura volátiles del disco para su uso, con alguna penalización de rendimiento. Si tus discos están respaldados por batería de alguna manera, deshabilitar las barreras puede mejorar el rendimiento de forma
segura.

Iniciar una confirmación de registro cada nrsec segundos. El valor predeterminado es 5 segundos. Cero significa
predeterminado.

Aparte del antiguo sistema de cuotas (como en ext2, jqfmt=vfsold también conocido como cuota de versión 1), ext3 también soporta cuotas con registro (cuota de versión 2). jqfmt=vfsv0 o jqfmt=vfsv1 habilita cuotas con registro. Las cuotas con registro tienen la ventaja de que incluso después de un fallo no se requiere ninguna verificación de cuotas. Cuando la característica de sistema de archivos de cuotas está habilitada, se usan automáticamente cuotas con registro, y esta opción de montaje se
ignora.

group
Para cuotas con registro (jqfmt=vfsv0 o jqfmt=vfsv1), las opciones de montaje usrjquota=aquota.user y grpjquota=aquota.group son requeridas para decirle al sistema de cuotas qué archivos de base de datos de cuotas usar. Cuando la característica de sistema de archivos de cuotas está habil
itada, se usan automáticament
e cuotas con registro, y esta
opción de montaje se ignora.

ext2.

max_batch_time=us
ec
Cantidad máxima de tiempo que ext4 debe esperar para que operaciones adicionales del sistema de archivos se agrupen junto con una operación de escritura síncrona. Dado que una operación de escritura síncrona va a forzar una confirmación y luego una espera a que la E/S se complete, no cuesta mucho, y puede ser una gran ganancia de rendimiento, esperamos una pequeña cantidad de tiempo para ver si otras transacciones pueden aprovechar la escritura síncrona. El algoritmo utilizado está diseñado para ajustarse automáticamente a la velocidad del disco, midiendo la cantidad de tiempo (en promedio) que tarda en terminar de confirmar una transacción. Llama a este tiempo el "tiempo de confirmación". Si el tiempo que la transacción ha estado en ejecución es menor que el tiempo de confirmación, ext4 intentará dormir durante el tiempo de confirmación para ver si otras operaciones se unirán a la transacción. El tiempo de confirmación está limitado por max_batch_time, que por defecto es 15000 µs (15 ms). Esta optimización puede desactivarse por completo estableciendo max_batch_time
a 0.
min_batch_time=us
ec
Este parámetro establece el tiempo de confirmación (como se describió anteriormente) para que sea al menos min_batch_time. Por defecto es cero microsegundos. Aumentar este parámetro puede mejorar el rendimiento de cargas de trabajo síncronas de múltiples hilos en discos muy rápidos, a costa de aumentar la
latencia.
