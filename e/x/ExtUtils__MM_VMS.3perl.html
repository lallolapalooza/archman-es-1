guess_name
(anulación)
Intenta determinar el nombre de la extensión que se está construyendo. Comenzamos con el nombre de el directorio actual. Dado que los nombres de archivo en VMS no distinguen mayúsculas de minúsculas, sin embargo, buscamos un archivo .pm cuyo nombre coincida con el del directorio actual (presumiblemente el archivo 'main' .pm para esta extensión), y intentamos encontrar una declaración "package" de la cual obtener el nombre del paquete Mixed::
Case.

Rutina auxiliar para MM->fixin(), anulada porque no existe una línea shebang real que sea interpretada por el shell, así que simplemente anteponemos $Config{startperl} y preservamos el argumento de la línea shebang para cualquier interruptor que pueda
contener.
maybe_command
(anulación)
Sigue las convenciones de nombres de VMS para archivos ejecutables. Si el nombre pasado no coincide exactamente con un archivo ejecutable, añade .Exe (o el equivalente) para comprobar si es una imagen ejecutable, y .Com para comprobar si es un procedimiento DCL. Si esto falla, comprueba los directorios en DCL$PATH y finalmente Sys$System: para un archivo ejecutable que tenga el nombre especificado, con o sin el sufijo equivalente a .
Exe.

(anulación)
La lista de definiciones de macro que deben pasarse a través debe especificarse usando el calificador /MACRO y no debe añadir otro calificador /DEFINE. Preponemos nuestra propia coma aquí al contenido de $(PASTHRU_DEFINE) porque a menudo está vacío y una coma siempre presente en CCFLAGS generaría un error de valor de calificador
faltante.

Rutina general para limpiar macros problemáticas de MM[SK]/Make. Expande macros en cualquier especificación de directorio, para evitar yuxtaponer dos directorios de sintaxis VMS cuando se ejecuta MM[SK]. También expande expresiones que son completamente macro, para que podamos saber cuánto es la expansión, y evitar desbordar el búfer de comandos de DCL cuando se ejecuta

MM[KS].
