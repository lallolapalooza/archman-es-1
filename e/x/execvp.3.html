familia de funciones exec() reemplaza la imagen del proceso actual con una nueva imagen de proceso. Las funciones descritas en esta página manual se basan en execve(2). (Ver la página manual de execve(2) para más detalles sobre el reemplazo de la imagen del proceso actual.) El argumento inicial de estas funciones es el nombre de un archivo que se va a

ejecutar.

Las funciones se pueden agrupar basándose en las letras que siguen al prefijo

"exec".

l - execl(), execlp(),

execle()

E

l

const char *arg y los puntos suspensivos siguientes pueden pensarse como arg0, arg1, ..., argn. Juntos describen una lista de uno o más punteros a cadenas terminadas en nulo que representan la lista de argumentos disponible para el programa ejecutado. El primer argumento, por convención, debe apuntar al nombre de archivo asociado con el archivo que se está ejecutando. La lista de argumentos debe terminar con un puntero nulo y, ya que estas son funciones variádicas, este puntero debe ser convertido a (char *)

NULL.

A diferencia de las funciones 'l', las funciones

'v' (abajo) especifican los argumentos de línea d
e comandos del programa ejecutado como un vector.

execvpe()

El primer argumento, por convención, debe apuntar al nombre de archivo asociado con el archivo que se está ejecutando. El array de punteros debe terminar con

El entorno de la nueva imagen de proceso se especifica a través del argumento envp. El argumento envp es un array de punteros a cadenas terminadas en nulo y debe terminar con un puntero

Todas las demás funciones exec() (que no incluyen 'e' en el sufijo) toman el entorno para la nueva imagen de proceso de la variable externa environ en el pr

p - execlp(), execvp(),

execvpe()

Estas funciones duplican las acciones del shell al buscar un archivo ejecutable si el nombre de archivo especificado no contiene una barra diagonal (/). El archivo se busca en la lista de rutas de directorios separadas por dos puntos especificada en la variable de entorno PATH. Si esta variable no está definida, la lista de rutas por defecto es una lista que incluye los directorios devueltos por confstr(_CS_PATH) (que típicamente devuelve el valor "/bin:/usr/bin") y posiblemente también el directorio de trabajo actual; ver VERSIONES para más

detalles.

execvpe() busca el programa usando el valor de PATH del entorno del llamador, no del argumento envp

.

Si el nombre de archivo especificado incluye una barra diagonal, entonces PATH se ignora y se ejecuta el archivo en la ruta de archivo

especificada.

Además, ciertos errores se tratan de manera

especial.

Si se deniega el permiso para un archivo (el intento de execve(2) falló con el error EACCES), estas funciones continuarán buscando el resto de la ruta de búsqueda. Sin embargo, si no se encuentra ningún otro archivo, retornarán con errno establecido a EACCES

.

Si la cabecera de un archivo no se reconoce (el intento de execve(2) falló con el error ENOEXEC), estas funciones ejecutarán el shell (/bin/sh) con la ruta del archivo como su primer argumento. (Si este intento falla, no se realiza ninguna búsqueda adicional.

)

Todas las demás funciones exec() (que no incluyen 'p' en el sufijo) toman como primer

argumento una ruta de archivo
(relativa o absoluta) que iden

VERSIONE

S

La ruta de búsqueda por defecto (usada cuando el entorno no contiene la variable PATH) muestra alguna variación entre sistemas. Generalmente incluye /bin y /usr/bin (en ese orden) y puede también incluir el directorio de trabajo actual. En algunos otros sistemas, el directorio de trabajo actual se incluye después de /bin y /usr/bin, como una medida anti-troyano. La implementación de glibc siguió durante mucho tiempo el tradicional por defecto donde el directorio de trabajo actual se incluye al inicio de la ruta de búsqueda. Sin embargo, alguna refactorización de código durante el desarrollo de glibc 2.24 causó que el directorio de trabajo actual se eliminara por completo de la ruta de búsqueda por defecto. Este cambio de comportamiento accidental se considera ligeramente beneficioso y no se

revertirá.

El comportamiento de execlp() y execvp() cuando ocurren errores al intentar ejecutar el archivo es práctica histórica, pero no ha sido tradicionalmente documentado y no está especificado por el estándar POSIX. BSD (y posiblemente otros sistemas) hacen un sueño y reintento automático si se encuentra ETXTBSY. Linux lo trata como un error duro y retorna

inmediatamente.

Tradicionalmente, las funciones execlp() y execvp() ignoraban todos los errores excepto los descritos arriba y ENOMEM y E2BIG, para los cuales retornaban. Ahora retornan si o

curre cualquier error disti
nto a los descritos arriba.

BUGS

Antes de glibc 2.24, execl() y execle() empleaban realloc(3) internamente y, en consecuencia, no eran seguros para señales asíncronas, en violación de los requisitos de POSIX.1. Esto se corrigió en glibc 2.24.

Detalles específicos de la arquitectura

En sparc y sparc64, execv() es proporcionado como una llamada del sistema por el kernel (con el prototipo mostrado arriba) para compatibilidad con SunOS. Esta función *no* es empleada por la función envolvente execv() en esas arquitecturas.
