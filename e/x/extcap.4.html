DESCRIPCIÓ

N

La interfaz extcap (captura externa) es una versátil interfaz de complementos que permite a binarios externos actuar como interfaces de captura directamente en Wireshark. Se utiliza en escenarios donde la fuente de la captura no es un modelo de captura tradicional (captura en vivo desde una interfaz, desde una tubería, desde un archivo, etc). El ejemplo típico es conectar hardware poco común de algún tipo a la aplicación principal de

Wireshark.

Sin extcap, una captura siempre se puede lograr escribiendo directamente en un archivo de

captura: 
the-esoteric-binary --the-strange-f
lag --interface=stream1 --file dump
file.pcap & wireshark dumpfile.pcap

pero la interfaz extcap permite que dicha conexión se establezca y configure fácilmente usando la GUI de

Wireshark.

El subsistema extcap está compuesto por múltiples binarios extcap que son llamados automáticamente por la GUI en secuencia. En los siguientes capítulos nos referiremos a ellos como "los

extcaps".

Los extcaps pueden ser cualquier binario o script dentro de los directorios extcap/wireshark o extcap/stratoshark. Por favor, tenga en cuenta que los scripts deben ser ejecutables sin anteponer un intérprete de scripts antes de la

llamada.

USUARIOS DE WINDOWS: Debido a restricciones, llamar directamente al script puede no funcionar siempre. En tal caso, se puede proporcionar un archivo por lotes, que a su vez ejecuta el script. Por favor, consulte doc/extcap_example.py para más

información.

Cuando Wireshark lanza un extcap, añade automáticamente su ruta de instalación (normalmente C:\Program Files\Wireshark\) al camino de búsqueda de DLL para que se puedan encontrar las dependencias de la biblioteca extcap (no está diseñado para ser lanzado manualmente). Esto se hace a prop

ósito. Solo debería haber programas extcap (ejecutables, scripts de Python, ...) en la carpeta extc
ap para reducir el tiempo de inicio y evitar que Wireshark intente ejecutar otros tipos de archivos.

CAMPO

TABLE

El campo "table" es un poco diferente, en el que sus valores pueden tener opciones de configuración adicionales. Los valores pueden ser introducidos manualmente por el usuario, o se puede proporcionar una lista de valores disponibles usando la misma API que "multicheck". A diferencia de la mayoría de las APIs, el valor se proporciona usando una API similar a la línea de comandos, separada por espacios en lugar de comas. Por ejemplo, un atributo "myparam" configurado donde el usuario seleccionó tres valores (1, 2 y 3)

recibiría: 
--mypa
ram "
1 2 3"

Si se configura un "prefix" como "--p", recibiría lo

siguiente: 
--myparam
"--p 1 --
p 2 --p 3"

Los valores seleccionados en un campo table pueden tener opciones de configuración específicas, si "configurable=true" para el campo "multicheck". En este caso, el extcap será llamado de nuevo cuando el usuario presione la rueda de configuración que corresponde a un valor en la tabla, con el adicional "--extcap-config-option-name <option_name> --extcap-config-option-value <option_value>" sin prefijo. Un programa extcap debe responder con un conjunto adicional de argumentos, que se abrirán en una ventana emergente. Una vez que se configuran esos, el extcap podría recibir lo siguiente, asumiendo por ejemplo que se solicita un adicional "param1" cuando el valor es 1, y "param2" cuando el valor es

2. 
--myparam "--p
1 --param1 1
--p 2 --para
m2 true --p 3"
