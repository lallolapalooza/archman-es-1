DESCRIPTION

The execvpe() function is similar to execvp(), but it can only be called from the main thread. It is identical to execvp() except that it uses the value of the environ global variable to determine the environment if envp is NULL.

The execvpe() function constructs a list of arguments for the new process image from the array argv. The list of arguments must be terminated by a NULL pointer. The first argument (i.e., argv[0]) should point to a filename with which to execute the program. The envp argument points to an array of strings, each of which is an environment variable in the format name=value. This array must be terminated by a NULL pointer. If envp is NULL, then the current environment is inherited.

The execvpe() function searches for the executable file in the directories specified by the PATH environment variable. This search is performed by the exec(3) wrapper function. The file argument is the name of the executable file. If file contains a slash (`/'), then it is interpreted as a path name, and the PATH variable is not used. Otherwise, the PATH variable is used to search for the executable. The argv argument is a pointer to an array of arguments passed to the new process. The first element of this array, argv[0], is conventionally a pointer to the filename itself.

If envp is NULL, the new process inherits the environment of the calling process. If envp is not NULL, it is used as the environment for the new process. The list of environment variables must be terminated by a NULL pointer.

The functions in the exec family replace the current process image with a new process image. The new process image is constructed from a regular, executable file, specified by file. This file is given to the new process as its first argument, argv[0]. The new process inherits the process ID, the parent process ID, the current working directory, resource utilization limits, and resource limits of the calling process. All file descriptors, except those marked with close-on-exec (see fcntl(2)), remain open in the new process. Any signal handlers or ignored signals are also inherited by the new process. The set of pending signals for the new process is cleared.

The execvpe() function is an extension of the execvp() functionality. It is intended to be used when the calling thread is the main thread and has potentially modified the environ global variable. If envp is NULL, execvpe() uses the value of environ to determine the environment of the new process. Otherwise, if envp is not NULL, it is used as the environment, as described for execvp().

BUGS

Before glibc 2.24, execl() and execle() employed realloc(3) internally and were consequently not async-signal-safe, in violation of the requirements of POSIX.1. This was fixed in glibc 2.24.

Architecture-specific details

On sparc and sparc64, execv() is provided as a system call by the kernel (with the prototype shown above) for compatibility with SunOS. This function is not employed by the execv() wrapper function on those architectures.
