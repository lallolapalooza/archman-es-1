exec(3) Manual de funciones de biblioteca exec(3)

NOMBRE

execl, execlp, execle, execv, execvp, execvpe - ejecutar un archivo

BIBLIOTECA

Biblioteca estándar C (libc, -lc)

SINOPSIS

#include <unistd.h>
extern char **environ;
int execl(const char *path, const char *arg, ...
                /*, (char *) NULL */);
int execlp(const char *file, const char *arg, ...
                /*, (char *) NULL */);
int execle(const char *path, const char *arg, ...
                /*, (char *) NULL, char *const envp[] */);
int execv(const char *path, char *const argv[]);
int execvp(const char *file, char *const argv[]);
int execvpe(const char *file, char *const argv[], char *const envp[]);

execvpe():

    _GNU_SOURCE

DESCRIPCIÓN

La familia de funciones exec() reemplaza la imagen del proceso actual con una nueva imagen de proceso. Las funciones descritas en esta página del manual se basan en execve(2). (Ver la página del manual de execve(2) para más detalles sobre el reemplazo de la imagen del proceso actual.)

El argumento inicial para estas funciones es el nombre de un archivo que se va a ejecutar.

Las funciones se pueden agrupar según las letras que siguen al prefijo "exec".

l - execl(), execlp(), execle()

El const char *arg y las elipses subsiguientes se pueden pensar como arg0, arg1, ..., argn. Juntos describen una lista de uno o más punteros a cadenas terminadas en nulo que representan la lista de argumentos disponibles para el programa ejecutado. El primer argumento, por convención, debe apuntar al nombre del archivo asociado con el archivo que se está ejecutando. La lista de argumentos debe terminar con un puntero nulo y, dado que estas son funciones variádicas, este puntero debe ser un cast (char *) NULL.

En contraste con las funciones 'l', las funciones 'v' (abajo) especifican los argumentos de la línea de comandos del programa ejecutado como un vector.

v - execv(), execvp(), execvpe()

El argumento char *const argv[] es un array de punteros a cadenas terminadas en nulo que representan la lista de argumentos disponibles para el nuevo programa. El primer argumento, por convención, debe apuntar al nombre del archivo asociado con el archivo que se está ejecutando. El array de punteros debe terminar con un puntero nulo.

e - execle(), execvpe()

El entorno de la nueva imagen de proceso se especifica a través del argumento envp. El argumento envp es un array de punteros a cadenas terminadas en nulo y debe terminar con un puntero nulo.

Todas las demás funciones exec() (que no incluyen 'e' en el sufijo) toman el entorno para la nueva imagen de proceso de la variable externa environ en el proceso llamador.

p - execlp(), execvp(), execvpe()

Estas funciones duplican las acciones del shell al buscar un archivo ejecutable si el nombre del archivo especificado no contiene un carácter de barra (/). El archivo se busca en la lista de nombres de ruta de directorios separados por dos puntos especificada en la variable de entorno PATH. Si esta variable no está definida, la lista de rutas por defecto incluye los directorios devueltos por confstr(_CS_PATH) (que típicamente devuelve el valor "/bin:/usr/bin") y posiblemente también el directorio de trabajo actual; ver VERSIONES para más detalles.

execvpe() busca el programa utilizando el valor de PATH del entorno del llamador, no del argumento envp.

Si el nombre de archivo especificado incluye un carácter de barra, PATH se ignora y se ejecuta el archivo en la ruta especificada.

Además, ciertos errores se tratan de forma especial.

Si se deniega el permiso para un archivo (el intento de execve(2) falló con el error EACCES), estas funciones continuarán buscando en el resto de la ruta de búsqueda. Sin embargo, si no se encuentra ningún otro archivo, devolverán con errno establecido en EACCES.

Si la cabecera de un archivo no se reconoce (el intento de execve(2) falló con el error ENOEXEC), estas funciones ejecutarán el shell (/bin/sh) con la ruta del archivo como su primer argumento. (Si este intento falla, no se realizará ninguna búsqueda adicional.)

Todas las demás funciones exec() (que no incluyen 'p' en el sufijo) toman como primer argumento una ruta (relativa o absoluta) que identifica el programa a ejecutar.

VALOR DE RETORNO

Las funciones exec() solo devuelven si ha ocurrido un error. El valor de retorno es -1 y errno se establece para indicar el error.

ERRORES

Todas estas funciones pueden fallar y establecer errno para cualquiera de los errores especificados para execve(2).

VERSIONES

La ruta de búsqueda predeterminada (utilizada cuando el entorno no contiene la variable PATH) muestra algunas variaciones entre sistemas. Generalmente incluye /bin y /usr/bin (en ese orden) y puede incluir también el directorio de trabajo actual. En algunos otros sistemas, el directorio de trabajo actual se incluye después de /bin y /usr/bin, como medida anti-troyanos. La implementación de glibc siguió durante mucho tiempo el comportamiento predeterminado tradicional donde el directorio de trabajo actual se incluía al principio de la ruta de búsqueda. Sin embargo, una refactorización del código durante el desarrollo de glibc 2.24 provocó que el directorio de trabajo actual se eliminara por completo de la ruta de búsqueda predeterminada. Este cambio de comportamiento accidental se considera ligeramente beneficioso y no se revertirá.

El comportamiento de execlp() y execvp() cuando ocurren errores al intentar ejecutar el archivo es una práctica histórica, pero no ha sido documentada tradicionalmente y no está especificada por el estándar POSIX. BSD (y posiblemente otros sistemas) realizan una pausa y reintento automático si se encuentra ETXTBSY. Linux lo trata como un error difícil y devuelve inmediatamente.

Tradicionalmente, las funciones execlp() y execvp() ignoraban todos los errores excepto los descritos anteriormente y ENOMEM y E2BIG, ante los cuales devolvían. Ahora devuelven si ocurre algún error distinto de los descritos anteriormente.
