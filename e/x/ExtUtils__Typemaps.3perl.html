ExtUtils::Typemaps(3perl) Guía de referencia para programadores de Perl ExtUtils::Typemaps(3perl)

NOMBRE

ExtUtils::Typemaps - Leer/Escribir/Modificar archivos de mapa de tipos Perl/XS

SINOPSIS

# leer/crear archivo
my $typemap = ExtUtils::Typemaps->new(file => 'typemap');
# alternativamente crear un mapa de tipos en memoria
# $typemap = ExtUtils::Typemaps->new();
# alternativamente crear un mapa de tipos en memoria analizando una cadena
# $typemap = ExtUtils::Typemaps->new(string => $sometypemap);
# añadir un mapeo
$typemap->add_typemap(ctype => 'NV', xstype => 'T_NV');
$typemap->add_inputmap(
   xstype => 'T_NV', code => '$var = ($type)SvNV($arg);'
);
$typemap->add_outputmap(
   xstype => 'T_NV', code => 'sv_setnv($arg, (NV)$var);'
);
$typemap->add_string(string => $typemapstring);
                                         # será analizado y fusionado
# eliminar un mapeo (igual para remove_typemap y remove_outputmap...)
$typemap->remove_inputmap(xstype => 'SomeType');
# guardar un mapa de tipos en un archivo
$typemap->write(file => 'anotherfile.map');
# fusionar el otro mapa de tipos en este
$typemap->merge(typemap => $another_typemap);

DESCRIPCIÓN

Este módulo puede leer, modificar, crear y escribir archivos de mapa de tipos Perl XS. Si no sabe lo que es un mapa de tipos, consulte los manuales perlxstut y perlxs.

El módulo no es completamente seguro para ida y vuelta: Por ejemplo, actualmente simplemente elimina todos los comentarios. Sin embargo, se conserva el orden de las entradas en los mapas.

Verificamos entradas duplicadas en el mapa de tipos, pero no verificamos entradas "TYPEMAP" faltantes para entradas "INPUTMAP" o "OUTPUTMAP" ya que estas podrían estar ocultas en un mapa de tipos diferente.

MÉTODOS

new

Devuelve un nuevo objeto de mapa de tipos. Acepta un parámetro opcional "file" . Si se establece, se leerá el archivo dado. Si el archivo no existe, se devuelve un mapa de tipos vacío.

Alternativamente, si se proporciona el parámetro "string" , se analizará la cadena proporcionada en lugar de un archivo.

file

Obtiene/establece el archivo al que se escribe el mapa de tipos cuando se llama al método "write" .

add_typemap

Añade una entrada "TYPEMAP" al mapa de tipos.

Argumentos con nombre requeridos: El "ctype" (por ejemplo, "ctype => 'double'") y el "xstype" (por ejemplo, "xstype => 'T_NV'").

Argumentos con nombre opcionales: "replace => 1" fuerza la eliminación/reemplazo de entradas "TYPEMAP" existentes del mismo "ctype". "skip => 1" activa una lógica de "primero en llegar, primero en servir" por la cual las nuevas entradas que entran en conflicto con las entradas existentes se ignoran silenciosamente.

Como alternativa al uso de parámetros con nombre, puede pasar un objeto "ExtUtils::Typemaps::Type" como primer argumento, del cual se añadirá una copia al mapa de tipos. En ese caso, solo se pueden usar los parámetros con nombre "replace" o "skip" después del objeto. Ejemplo:

$map->add_typemap($type_obj, replace => 1);

add_inputmap

Añade una entrada "INPUT" al mapa de tipos.

Argumentos con nombre requeridos: El "xstype" (por ejemplo, "xstype => 'T_NV'") y el "code" a asociar con él para la entrada.

Argumentos con nombre opcionales: "replace => 1" fuerza la eliminación/reemplazo de entradas "INPUT" existentes del mismo "xstype". "skip => 1" activa una lógica de "primero en llegar, primero en servir" por la cual las nuevas entradas que entran en conflicto con las entradas existentes se ignoran silenciosamente.

Como alternativa al uso de parámetros con nombre, puede pasar un objeto "ExtUtils::Typemaps::InputMap" como primer argumento, del cual se añadirá una copia al mapa de tipos. En ese caso, solo se pueden usar los parámetros con nombre "replace" o "skip" después del objeto. Ejemplo:

$map->add_inputmap($type_obj, replace => 1);

add_outputmap

Añade una entrada "OUTPUT" al mapa de tipos. Funciona exactamente igual que "add_inputmap".

add_string

Analiza una cadena como mapa de tipos y la fusiona en el objeto de mapa de tipos.

Argumento con nombre requerido: "string" para especificar la cadena a analizar.

remove_typemap

Elimina una entrada "TYPEMAP" del mapa de tipos.

Argumento con nombre requerido: "ctype" para especificar la entrada a eliminar del mapa de tipos.

Alternativamente, puede pasar un único objeto "ExtUtils::Typemaps::Type" .

remove_inputmap

Elimina una entrada "INPUT" del mapa de tipos.

Argumento con nombre requerido: "xstype" para especificar la entrada a eliminar del mapa de tipos.

Alternativamente, puede pasar un único objeto "ExtUtils::Typemaps::InputMap" .

remove_outputmap

Elimina una entrada "OUTPUT" del mapa de tipos.

Argumento con nombre requerido: "xstype" para especificar la entrada a eliminar del mapa de tipos.

Alternativamente, puede pasar un único objeto "ExtUtils::Typemaps::OutputMap" .

get_typemap

Obtiene una entrada de la sección TYPEMAP del mapa de tipos.

Argumentos con nombre obligatorios: El "ctype" de la entrada.

Devuelve el objeto "ExtUtils::Typemaps::Type" para la entrada si se encuentra.

get_inputmap

Obtiene una entrada de la sección INPUT del mapa de tipos.

Argumentos con nombre obligatorios: El "xstype" de la entrada o el "ctype" del mapa de tipos que se puede usar para encontrar el "xstype". Es decir, los siguientes fragmentos de código son equivalentes:

my $type = $typemap->get_typemap(ctype => $ctype)
my $input_map = $typemap->get_inputmap(xstype => $type->xstype);
my $input_map = $typemap->get_inputmap(ctype => $ctype);

Devuelve el objeto "ExtUtils::Typemaps::InputMap" para la entrada si se encuentra.

get_outputmap

Obtiene una entrada de la sección OUTPUT del mapa de tipos.

Argumentos con nombre obligatorios: El "xstype" de la entrada o el "ctype" del mapa de tipos que se puede usar para resolver el "xstype". (Vea arriba para un ejemplo.)

Devuelve el objeto "ExtUtils::Typemaps::InputMap" para la entrada si se encuentra.d.

write

Escribe el mapa de tipos en un archivo. Opcionalmente acepta un argumento "file". "file" Si se proporciona, el mapa de tipos se escribirá en el archivo especificado. Si no, el mapa de tipos se escribe en el nombre de archivo almacenado actualmente (ver "file" arriba, por defecto es el archivo del que se leyó, si lo hay).

as_string

Genera y devuelve la forma de cadena de texto del mapa de tipos.

as_embedded_typemap

Genera y devuelve la forma de cadena de texto del mapa de tipos con el prefijo apropiado alrededor de él para la inclusión textual en un archivo XS como un mapa de tipos incrustado. Esto devolverá una cadena como

TYPEMAP: <<END_OF_TYPEMAP
... mapa de tipos aquí (ver as_string) ...
END_OF_TYPEMAP

El método se encarga de no usar un marcador de fin de HERE-doc que aparezca en la propia cadena del mapa de tipos.

merge

Fusiona un mapa de tipos dado en el objeto. Ten en cuenta que una operación de fusión fallida deja el objeto en un estado inconsistente, así que clónalo si es necesario.

Argumentos con nombre obligatorios: O bien "typemap => $another_typemap_obj" o "file => $path_to_typemap_file" pero no ambos.

Argumentos opcionales: "replace => 1" para forzar el reemplazo de las entradas existentes del mapa de tipos sin advertencia, o "skip => 1" para omitir las entradas que ya existen en el mapa de tipos.

is_empty

Devuelve un valor booleano que indica si este mapa de tipos está completamente vacío.

list_mapped_ctypes

Devuelve una lista de los tipos C que pueden ser mapeados por este objeto de mapa de tipos.

_get_typemap_hash

Devuelve un hash que mapea los tipos C a los tipos XS:

{
  'char **' => 'T_PACKEDARRAY',
  'bool_t' => 'T_IV',
  'AV *' => 'T_AVREF',
  'InputStream' => 'T_IN',
  'double' => 'T_DOUBLE',
  # ...
}

Esto está documentado porque es utilizado por "ExtUtils::ParseXS", pero no está destinado para un uso general. Puede ser eliminado en cualquier momento.

_get_inputmap_hash

Devuelve un hash que mapea los tipos XS (identificadores) al código INPUT correspondiente:

{
  'T_CALLBACK' => '   $var = make_perl_cb_$type($arg)
',
  'T_OUT' => '    $var = IoOFP(sv_2io($arg))
',
  'T_REF_IV_PTR' => '   if (sv_isa($arg, \\"${ntype}\\")) {
  # ...
}

Esto está documentado porque es utilizado por "ExtUtils::ParseXS", pero no está destinado para un uso general. Puede ser eliminado en cualquier momento.

_get_outputmap_hash

Devuelve un hash que mapea los tipos XS (identificadores) al código OUTPUT correspondiente:

{
  'T_CALLBACK' => '   sv_setpvn($arg, $var.context.value().chp(),
              $var.context.value().size());
',
  'T_OUT' => '    {
          GV *gv = (GV *)sv_newmortal();
          gv_init_pvn(gv, gv_stashpvs("$Package",1),
                     "__ANONIO__",10,0);
          if ( do_open(gv, "+>&", 3, FALSE, 0, 0, $var) )
              sv_setsv(
                $arg,
                sv_bless(newRV((SV*)gv), gv_stashpv("$Package",1))
              );
          else
              $arg = &
       }
',
  # ...
}

Esto está documentado porque es utilizado por "ExtUtils::ParseXS", pero no está destinado para un uso general. Puede ser eliminado en cualquier momento.

_get_prototype_hash

Devuelve un hash que mapea los tipos C del mapa de tipos a sus prototipos correspondientes.

{
  'char **' => '$',
  'bool_t' => '$',
  'AV *' => '$',
  'InputStream' => '$',
  'double' => '$',
  # ...
}

Esto está documentado porque es utilizado por "ExtUtils::ParseXS", pero no está destinado para un uso general. Puede ser eliminado en cualquier momento.

clone

Crea y devuelve un clon de un objeto de mapas de tipos completo.

Acepta parámetros con nombre: Si "shallow" es verdadero, el clon compartirá los objetos individuales reales de tipo/entrada/mapa de salida, pero no compartirá su almacenamiento. Úsalo con precaución. Sin "shallow", el clon será completamente independiente.

tidy_type

Función para (heurísticamente) canonizar un tipo C en términos de espacios en blanco. Funciona hasta cierto punto con tipos C++. Por ejemplo,

$halfway_canonical_type = tidy_type('  int *  * const   *  ');

devuelve 'int ** const *'.

Movido desde "ExtUtils::ParseXS".

ADVERTENCIAS

Hereda algo de código maligno de "ExtUtils::ParseXS".

VÉASE TAMBIÉN

El analizador está fuertemente inspirado en el de ExtUtils::ParseXS.
