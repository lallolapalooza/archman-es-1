NOMBRE

ecm-find-modules - Referencia de módulos de búsqueda de ECM

INTRODUCCIÓN

Los módulos de búsqueda son utilizados por el comando find_package de CMake para buscar paquetes que no proporcionan sus propios archivos de configuración de paquetes de CMake. CMake proporciona un amplio conjunto de módulos de búsqueda, y Extra CMake Modules (ECM) los amplía.

Para usar los módulos de búsqueda de ECM, debe indicar a CMake que encuentre el paquete ECM y luego añadir ${ECM_MODULE_PATH} o ${ECM_FIND_MODULE_DIR} a la variable CMAKE_MODULE_PATH:

find_package(ECM REQUIRED NO_MODULE)
set(CMAKE_MODULE_PATH ${ECM_FIND_MODULE_DIR})

Usar ${ECM_MODULE_PATH} también hará que los módulos destinados al uso directo por scripts de CMake estén disponibles (consulte ecm-modules(7) <#manual:ecm-modules(7)> y ecm-kde-modules(7) <#manual:ecm-kde-modules(7)>).

También puede hacer copias locales de los módulos de búsqueda usando la función ecm_use_find_modules de ECMUseFindModules <#module:ECMUseFindModules>, que se incluye automáticamente cuando se encuentra ECM:

find_package(ECM REQUIRED NO_MODULE)
ecm_use_find_modules(
    DIR "${CMAKE_BINARY_DIR}/cmake"
    MODULES FindEGL.cmake
)
set(CMAKE_MODULE_PATH "${CMAKE_BINARY_DIR}/cmake")

Esto permite el uso selectivo de los módulos de búsqueda de ECM, y el argumento NO_OVERRIDE se puede usar para garantizar que, si CMake incluye su propia versión de ese módulo de búsqueda, se use en su lugar.

Find7Zip

Intenta encontrar 7-Zip.

Si el ejecutable de 7-Zip no está en tu PATH, puedes proporcionar un nombre alternativo o una ubicación de ruta completa con la variable 7Zip_EXECUTABLE.

Esto definirá las siguientes variables:

7Zip_FOUND
TRUE si 7-Zip está disponible
7Zip_EXECUTABLE
Ruta al ejecutable de 7-Zip

Si 7Zip_FOUND es TRUE, también definirá el siguiente target importado:

7Zip::7Zip
Ruta al ejecutable de 7-Zip

Nota:

Solo buscará el 7-Zip original, no uno de los forks p7zip.

FindFFmpeg

Intenta encontrar los componentes de FFmpeg.

Los siguientes componentes están disponibles:

AVCODEC  AVFILTER    AVDEVICE  AVFORMAT
AVUTIL   SWRESAMPLE  SWSCALE   POSTPROCESS

Si no se especifican componentes en la llamada a find_module, se elegirán los siguientes como predeterminados:

AVFORMAT AVUTIL AVCODEC

Targets Importados

Este módulo proporciona los siguientes targets importados, si se encuentran:

FFmpeg::FFmpeg
Para todos los componentes requeridos de FFmpeg
FFmpeg::<component>
Para cada <component> que se encontró

Variables de Resultado

Esto definirá las siguientes variables:

FFMPEG_FOUND
El sistema tiene todos los componentes requeridos.
FFMPEG_INCLUDE_DIRS
Directorio de inclusión necesario para usar los encabezados de los componentes requeridos.
FFMPEG_LIBRARIES
Enlaza estos para usar los componentes requeridos de FFmpeg.
FFMPEG_DEFINITIONS
Opciones del compilador necesarias para usar los componentes requeridos de FFmpeg.

Además, para cada uno de los componentes, se definirán las siguientes variables:

<component>_FOUND
True si (la versión solicitada de) <component> está disponible
<component>_INCLUDE_DIRS
Directorio de inclusión necesario para usar los encabezados de <component>
<component>_LIBRARIES
Enlaza estos para usar <component>
<component>_DEFINITIONS
Opciones del compilador necesarias para usar <component>
<component>_VERSION
La versión del componente (NOTA: siempre vacía en Windows)

Como las versiones de los distintos componentes de FFmpeg difieren para una versión dada, y CMake solo admite una versión común para todos los componentes, utilice lo siguiente para especificar las versiones requeridas para múltiples componentes:

find_package(FFmpeg 57.48 COMPONENTS AVCODEC)
find_package(FFmpeg 57.40 COMPONENTS AVFORMAT)
find_package(FFmpeg 55.27 COMPONENTS AVUTIL)

NOTA: la comprobación de versión se omite en Windows

Esto definirá las siguientes variables:

El ejecutable gperf.

y la siguiente función pública:

ecm_gperf_generate(<GperfInput> <OutputFile> <OutputVariable(|target (since 5.83))>

Ejecuta gperf sobre <GperfInput> para generar <OutputFile>, añadiéndolo a la variable <OutputVariable> que contiene el código fuente para el objetivo donde se va a construir <OutputFile> o, desde KF 5.83, si el argumento dado es un objetivo, a la lista de fuentes privadas de ese objetivo. El argumento opcional GENERATION_FLAGS es necesario para pasar parámetros extra a gperf (tenga en cuenta que no puede sobrescribir de esa manera el archivo de salida).

Una invocación simple sería:

ecm_gperf_generate(simple.gperf ${CMAKE_CURRENT_BINARY_DIR}/simple.h MySources)

FindKF5

Encuentra KDE Frameworks 5 con una sola llamada a find_package().

Esto utilizará los archivos de configuración de paquetes proporcionados por los frameworks individuales. Por ejemplo, si deseas encontrar KArchive, que se presenta a CMake como KF5Archive (es decir: harías find_package(KF5Archive) para encontrarlo directamente), puedes hacer

find_package(KF5 COMPONENTS Archive)

Si se encuentran todos los componentes requeridos (los indicados en el argumento COMPONENTS, pero no los indicados en el argumento OPTIONAL_COMPONENTS), KF5_FOUND se establecerá en verdadero. De lo contrario, se establecerá en falso.

Desde la versión 1.0.0.

Core  Cpp  Qt5  Qt4  Glib

Este módulo definirá las siguientes variables, independientemente de los componentes buscados o encontrados:

Poppler_FOUND
TRUE si (la versión solicitada de) Poppler está disponible
Poppler_VERSION
Versión de Poppler encontrada
Poppler_TARGETS
Una lista de todos los destinos importados por este módulo (tenga en cuenta que puede haber más que los componentes que se solicitaron)
Poppler_LIBRARIES
Esto se puede pasar a target_link_libraries() en lugar de los destinos importados

FindQtWaylandScanner

Intenta encontrar qtwaylandscanner.

Si el ejecutable qtwaylandscanner no está en su PATH, puede proporcionar un nombre alternativo o una ubicación de ruta completa con la variable QtWaylandScanner_EXECUTABLE.

Esto definirá las siguientes variables:

QtWaylandScanner_FOUND
Verdadero si qtwaylandscanner está disponible
QtWaylandScanner_EXECUTABLE
El ejecutable qtwaylandscanner.

Si QtWaylandScanner_FOUND es TRUE, también definirá el siguiente destino importado:

Wayland::QtScanner
El ejecutable qtwaylandscanner.

Este módulo proporciona las siguientes funciones para generar implementaciones de protocolo en C++:

  • ecm_add_qtwayland_client_protocol
  • ecm_add_qtwayland_server_protocol
ecm_add_qtwayland_client_protocol(<target>
                                  PROTOCOL <xmlfile>
                                  BASENAME <basename>
                                  [PREFIX <prefix>]
                                  [PRIVATE_CODE])
ecm_add_qtwayland_client_protocol(<source_files_var>
                                  PROTOCOL <xmlfile>
                                  BASENAME <basename>
                                  [PREFIX <prefix>]
                                  [PRIVATE_CODE])

Genera un contenedor de C++ para los archivos de protocolo de cliente de Wayland a partir de la definición XML <xmlfile> para la interfaz <basename> y añade esos archivos a <source_files_var> o <target>. Pase el argumento <prefix> si los nombres de las interfaces no comienzan con qt_ o wl_. PRIVATE_CODE indica a wayland-scanner que oculte el código de marshalling del DSO compilado para su uso en otros DSO. El valor predeterminado es exportar este código.

Se requiere WaylandScanner y se buscará.

ecm_add_qtwayland_server_protocol(<target>
                                  PROTOCOL <xmlfile>
                                  BASENAME <basename>
                                  [PREFIX <prefix>]
                                  [PRIVATE_CODE])
ecm_add_qtwayland_server_protocol(<source_files_var>
                                  PROTOCOL <xmlfile>
                                  BASENAME <basename>
                                  [PREFIX <prefix>]
                                  [PRIVATE_CODE])

Genera un contenedor de C++ para los archivos de protocolo del servidor Wayland a partir de la definición XML <xmlfile> para la interfaz <basename> y añade esos archivos a <source_files_var> o <target>. Pasa el argumento <prefix> si los nombres de las interfaces no comienzan con qt_ o wl_. PRIVATE_CODE indica a wayland-scanner que oculte el código de marshalling del DSO compilado para su uso en otros DSOs. El valor predeterminado es exportar este código.

Se requiere WaylandScanner y se buscará.

Este es un módulo de búsqueda basado en componentes, que hace uso de los argumentos COMPONENTS y OPTIONAL_COMPONENTS de find_module. Los siguientes componentes están disponibles:

Client  Server  Cursor  Egl

Si no se especifica ningún componente, este módulo actuará como si todos los componentes se hubieran pasado a OPTIONAL_COMPONENTS.

Este módulo definirá las siguientes variables, independientemente de los componentes buscados o encontrados:

Wayland_FOUND
TRUE si (la versión solicitada de) Wayland está disponible
Wayland_VERSION
Versión de Wayland encontrada
Wayland_TARGETS
Una lista de todos los objetivos importados por este módulo (tenga en cuenta que puede haber más que los componentes que fueron solicitados)
Wayland_LIBRARIES
Esto se puede pasar a target_link_libraries() en lugar de los objetivos importados
Wayland_INCLUDE_DIRS
Esto debería pasarse a target_include_directories() si los objetivos no se utilizan para el enlazado
Wayland_DEFINITIONS
Esto debería pasarse a target_compile_options() si los objetivos no se utilizan para el enlazado
Wayland_DATADIR
El directorio de datos de los protocolos principales de wayland Desde 5.73.0

Para cada componente buscado, Wayland_<component>_FOUND se establecerá en TRUE si se encontró la biblioteca Wayland correspondiente, y FALSE en caso contrario. Si Wayland_<component>_FOUND es TRUE, se definirá el objetivo importado Wayland::<component>. Este módulo también intentará determinar las variables Wayland_*_VERSION para cada objetivo importado, aunque Wayland_VERSION normalmente debería ser suficiente.

En general, recomendamos usar los objetivos importados, ya que son más fáciles de usar y proporcionan más control. Tenga en cuenta, sin embargo, que si algún objetivo está en la interfaz de enlazado de una biblioteca exportada, debe estar disponible mediante el archivo de configuración del paquete.

Desde pre-1.0.0.

FindWaylandScanner

Intenta encontrar wayland-scanner.

Si el ejecutable wayland-scanner no está en tu PATH, puedes proporcionar un nombre alternativo o una ubicación de ruta completa con la variable WaylandScanner_EXECUTABLE.

Esto definirá las siguientes variables:

WaylandScanner_FOUND
True si wayland-scanner está disponible.
WaylandScanner_EXECUTABLE
El ejecutable wayland-scanner.

Si WaylandScanner_FOUND es TRUE, también definirá el siguiente objetivo importado:

Wayland::Scanner
El ejecutable wayland-scanner.

Este módulo proporciona las siguientes funciones para generar implementaciones de protocolos en C:

  • ecm_add_wayland_client_protocol
  • ecm_add_wayland_server_protocol
ecm_add_wayland_client_protocol(<target>
                                PROTOCOL <xmlfile>
                                BASENAME <basename>
                                [PRIVATE_CODE])
ecm_add_wayland_client_protocol(<source_files_var>
                                PROTOCOL <xmlfile>
                                BASENAME <basename>
                                [PRIVATE_CODE])

Genera archivos de protocolo de cliente Wayland a partir de la definición XML <xmlfile> para la interfaz <basename> y añade esos archivos a <source_files_var> o <target>.

PRIVATE_CODE indica a wayland-scanner que oculte el código de marshalling del DSO compilado para su uso en otros DSO. El valor predeterminado es exportar este código.

ecm_add_wayland_server_protocol(<target>
                                PROTOCOL <xmlfile>
                                BASENAME <basename>
                                [PRIVATE_CODE])
ecm_add_wayland_server_protocol(<source_files_var>
                                PROTOCOL <xmlfile>
                                BASENAME <basename>
                                [PRIVATE_CODE])

Genera archivos de protocolo de servidor Wayland a partir de la definición XML <xmlfile> para la interfaz <basename> y añade esos archivos a <source_files_var> o <target>.

PRIVATE_CODE indica a wayland-scanner que oculte el código de marshalling del DSO compilado para su uso en otros DSO. El valor predeterminado es exportar este código.

Desde 1.4.0.

ATOM         AUX          COMPOSITE    CURSOR       DAMAGE

Si no se especifica ningún componente, este módulo actuará como si todos los componentes se hubieran pasado a OPTIONAL_COMPONENTS. Antes de 5.82 esto excluía XINPUT. Desde 5.82 se buscan todos los componentes.
