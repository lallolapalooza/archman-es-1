ecasound(1)

Paquete: ecasound

ecasound(1) Software multimedia ecasound(1)

NOMBRE

ecasound - editor de muestras, grabador multipista, procesador de efectos, etc.

SINOPSIS

ecasound [ opciones_generales ] { [ configuración_cadena ] [ configuración_efecto ] [ configuración_entrada ] [ configuración_salida ] }

DESCRIPCIÓN

Ecasound es un paquete de software diseñado para el procesamiento de audio multipista. Se puede utilizar para tareas sencillas como la reproducción de audio, la grabación y las conversiones de formato, así como para el procesamiento de efectos multipista, la mezcla, la grabación y el reciclaje de señales. Ecasound admite una amplia gama de entradas, salidas de audio y algoritmos de efectos. Los efectos y objetos de audio se pueden combinar de diversas maneras, y sus parámetros se pueden controlar mediante objetos operadores como osciladores y CC de MIDI. El paquete incluye una interfaz de usuario de modo consola versátil.

OPCIONES

¡Nota! Todas las opciones, excepto las mencionadas en opciones_ecasound y Opciones globales, se pueden usar en archivos de configuración de cadenas de ecasound (.ecs).

OPCIONES DE ECASOUND

Estas opciones son analizadas y manejadas por el ejecutable frontend de ecasound y no se pasan a la biblioteca backend. Esto significa que estas opciones pueden no funcionar en otras aplicaciones que utilicen las bibliotecas de ecasound para su funcionalidad.
-c
Inicia ecasound en modo interactivo. En modo interactivo, puedes controlar ecasound con comandos sencillos ("start", "stop", "pause", etc.). Consulta ecasound-iam.
-C
Desactiva el modo interactivo de ecasound (ver '-c' y '-K').
-D
Imprime toda la información de depuración en stderr (sin búfer, salida directa sin ncurses).
-s[:]configuración-cadena-archivo
Crea una nueva configuración de cadena desde el archivo 'configuración-cadena-archivo' y la agrega a la sesión actual. Los archivos de configuración de cadenas comúnmente tienen una extensión de nombre de archivo '.ecs'. Una configuración de cadena puede contener entradas, salidas, cadenas, efectos, controladores: es decir, objetos de una configuración específica de elementos de procesamiento de audio. Una sesión, por otro lado, es una colección de una o más configuraciones de cadena. Solo una de las configuraciones de cadena puede estar conectada (es decir, puede ejecutarse/procesarse). Pero es posible tener otra configuración de cadena seleccionada (es decir, configurada) mientras otra está conectada (es decir, ejecutándose).
-E "comando1 [[argumentos] ; comando2 argumentos ; ... ; comandoN]"
Ejecuta un conjunto de comandos del modo interactivo de Ecasound (EIAM) al iniciar. Estos comandos se ejecutan inmediatamente después de que ecasound se inicia. Si la línea de comandos contiene suficientes opciones para crear una configuración de cadena válida que se ejecutará, los comandos de inicio se ejecutan después de que se analizan las otras opciones de la línea de comandos, pero antes de que se inicie el motor de procesamiento. Tenga en cuenta que este comando es una característica del ejecutable frontend de ecasound y no es compatible con la biblioteca backend. Esto significa que otros clientes pueden no admitir la opción '-E', y que los comandos de inicio no se guardan como parte de la configuración de cadena o del estado de la sesión.
--server
Habilita el llamado modo NetECI, en el que ecasound se puede controlar remotamente a través de una conexión de socket. Cuando se activa, los clientes pueden conectarse a la sesión ecasound en ejecución y utilizar los comandos del modo interactivo para controlar y observar el procesamiento de ecasound.
El protocolo NetECI se define en la Guía del Programador de Ecasound.
Un ejemplo de cliente que utiliza esta característica es ecamonitor(1). Esta utilidad se incluye en el paquete de distribución de Ecasound (requiere un entorno Python funcional).
¡Advertencia! Si la máquina que ejecuta ecasound está conectada a una red pública, ¡asegúrese de bloquear el puerto de ecasound en su cortafuegos! Como no hay control de acceso implementado para conexiones entrantes, de lo contrario, cualquiera puede conectarse, controlar y observar sus sesiones de ecasound. Esta opción reemplaza '--daemon' (obsoleta en 2.6.0).
--server-tcp-port=NNN
Establece el puerto TCP utilizado por el modo demonio. Por defecto, ecasound utilizará el número de puerto 2868. Esta opción reemplaza '--daemon-port' (obsoleta en 2.6.0).
--no-server
Desactiva el modo demonio de ecasound. Este es el valor predeterminado. Esta opción reemplaza '--nodaemon' (obsoleta en 2.6.0).
--osc-udp-port=NNN
Habilita el soporte para Open Sound Control (OSC). Ecasound escuchará los mensajes OSC entrantes en el puerto UDP NNN. La interfaz OSC de Ecasound está documentada en: http://ecasound.git.sourceforge.net/git/gitweb.cgi?p=ecasound/ecasound;a=blob;f=Documentation/ecasound_osc_interface.txt;hb=HEAD
Tenga en cuenta que el soporte OSC aún es experimental y la interfaz puede cambiar en versiones posteriores de Ecasound.
Esta opción se agregó a ecasound 2.7.0.
--keep-running,-K
No salir cuando el procesamiento haya finalizado/detenido. Solo afecta al modo de operación no interactivo (ver -c/-C). Opción agregada a ecasound 2.4.2.
--help,-h
Mostrar esta ayuda.
--version
Imprimir información de versión.
OPCIONES GLOBALES
-d, -dd, -ddd
Aumenta la cantidad de mensajes de depuración impresos. -d agrega algo de verbosidad, mientras que -ddd resulta en una salida muy detallada.
-d:nivel_depuración
Establece la máscara de nivel de depuración en 'nivel_depuración'. Este es un valor enmascarado en bits con las siguientes clases: errores (1), información (2), subsistemas (4), nombres de módulos (8), objetos de usuario (16), objetos del sistema (32), funciones (64), continuo (128) y valores de retorno de eiam (256). El valor predeterminado es 271 (1+2+4+8+256). Vea la documentación del código fuente de la clase ECA_LOGGER para obtener información más detallada.
-R[:]ruta-al-archivo
Utiliza el archivo de recursos de ecasound (ver la página del manual de ecasoundrc) 'ruta-al-archivo' como única fuente para establecer el valor de los recursos. Especificar esta opción deshabilitará la política normal de consulta de los archivos de recursos globales y del usuario (si existe).
-q
Modo silencioso, sin salida. Igual que -d:0.
OPCIONES GENERALES DE CONFIGURACIÓN DE CADENA
-a:nombrecadena1, nombrecadena2, ...
Selecciona cadenas de señales activas. Todas las entradas y salidas que siguen a esta opción '-a' se asignan a las cadenas seleccionadas (hasta que se especifique una nueva opción -a). Al agregar efectos, controladores y otros operadores de cadena, solo se puede seleccionar una cadena a la vez. Si no se ha proporcionado ninguna opción -a, se utilizará la cadena 'default' al agregar objetos. El nombre de cadena 'all' también está reservado. Provocará que se seleccionen todas las cadenas existentes. Al proporcionar múltiples opciones -a, puede controlar a qué cadenas se asignan los efectos, las entradas y las salidas. Consulte la sección EJEMPLOS para obtener información más detallada sobre el uso de esta opción.
-n:nombre
Establece el nombre de la configuración de cadena en 'nombre'. Si no se especifica, el valor predeterminado es "command-line-setup" o el nombre del archivo desde el que se cargó la configuración de cadena. No se permiten espacios en blanco.
-x
Recortar salidas. Todos los objetos de salida se abren en modo de sobrescritura. Los archivos existentes se truncarán.
-X
Abrir salidas para actualización. Ecasound abre todas las salidas, si el formato de destino lo permite, en modo de lectura/escritura.
-z:característica
Habilita 'característica'. La mayoría de las características se pueden deshabilitar usando la notación -z:sin_característica. '-z:db,tamaño_db' habilita el doble búfer para objetos de audio que lo soportan (tamaño_db=0 para predeterminado, de lo contrario, el tamaño del búfer en fotogramas de muestra). '-z:nodb' deshabilita el doble búfer. '-z:intbuf' y '-z:no_intbuf' controlan si se usa búfer interno adicional
permitido para dispositivos en tiempo real. Desactivar esto puede reducir los tiempos de latencia en algunas situaciones. Con '-z:xruns', el procesamiento se detendrá si ocurre un sub/desbordamiento. '-z:multitrack' y 'z:nomultitrack' se pueden usar para forzar a ecasound a habilitar o deshabilitar el modo multipista. En casos raros, puede que quieras especificar explícitamente el desplazamiento de grabación con '-z:multitrack,offset-in-samples'. El desplazamiento es la cantidad de muestras omitidas al grabar desde entradas en tiempo real. '-z:psr' habilita el modo de *tasas de muestreo precisas* para dispositivos OSS. '-z:mixmode,sum' habilita el modo de mezcla donde los canales se mezclan sumando todos los canales. El valor predeterminado es '-z:mixmode,avg', en el que los canales se mezclan promediando. La selección del modo de mezcla se agregó por primera vez a ecasound 2.4.0. Consulte la página del manual de ecasoundrc.
OPCIONES DE BUFFERIZADO Y RENDIMIENTO DE CHAINSETUP
-B:buffering_mode
Selecciona el modo de bufferizado predeterminado. El modo es uno de: 'auto' (predeterminado), 'nonrt', 'rt', 'rtlowlatency'.
-b:buffer_size
Establece el tamaño del búfer del motor de procesamiento en muestras. El tamaño debe ser una potencia de 2 y es independiente del número de canales (por ejemplo, * -b:1024* a 48 kHz resultará en una longitud de búfer de 21.333 ms, ya sea que la entrada sea mono, estéreo o 5.1).
Esta es una opción importante ya que define la longitud de una iteración del motor de procesamiento y afecta el comportamiento de ecasound de muchas maneras. Si no se especifica explícitamente, ecasound intentará elegir un valor óptimo basado en el modo de bufferizado actual (ver opción *-B*). Para procesamiento en tiempo real, puede intentar establecerlo lo más bajo posible para reducir el retardo de procesamiento. Algunas máquinas pueden manejar valores de búfer tan bajos como 64 y 128. En algunas circunstancias (por ejemplo, al usar envolventes de oscilador), los tamaños de búfer pequeños harán que las envolventes actúen de manera más fluida. Cuando no se procesa en tiempo real (todas las entradas y salidas son archivos normales), valores más grandes pueden ayudar a evitar desbordamientos de búfer, reducir el uso de CPU y/o mejorar el rendimiento en general.
Tenga en cuenta que cuando se utilizan entradas/salidas JACK, la configuración del tamaño del búfer se anula y se establece en el tamaño de período/búfer informado por el servidor JACK (por ejemplo, la opción '-p' de jackd). No es posible desactivar este comportamiento.
Si no se especifica explícitamente, el tamaño del búfer predeterminado se elige según el modo de bufferizado actual (ver *-B*).
-r:sched_priority
Utiliza la política de programación en tiempo real (SCHED_FIFO). Esto es imposible si ecasound no tiene privilegios de root. ¡Cuidado! Esto proporciona un mejor rendimiento, pero puede causar bloqueos totales si algo sale mal. La '*sched_priority*' se puede omitir (0 = omitido). Si se proporciona, esta es la prioridad estática para el hilo de ecasound de mayor prioridad. Otros hilos de ecasound se ejecutan con prioridad '*sched_priority-1...n*'. El valor de '* -1*' se puede usar para deshabilitar el modo de prioridad elevada.
-z:feature
Las características relevantes son -z:db,xxx (-z:nodb) y -z:intbuf (-z:nointbuf). Ver sección *Opciones generales de chainsetup* para detalles.
CONTROL DE PROCESAMIENTO
-t:seconds
Establece el tiempo de procesamiento en segundos (no tiene que ser un valor entero). Si no se establece el tiempo de procesamiento, el motor se detiene cuando todas las entradas han finalizado. Esta opción es equivalente al comando EIAM '*cs-set-length*'. Un valor especial de '* -1*' establecerá la longitud de la configuración de la cadena según el objeto de entrada más largo.
-tl
Habilita la repetición en bucle. Cuando se completa el procesamiento, el motor comenzará de nuevo desde el principio. Esta opción es equivalente al comando EIAM '*cs-loop*'.
CONFIGURACIÓN DE ENTRADA/SALIDA

Consulte la guía del usuario de ecasound para obtener documentación más detallada.

-G:mgrtype,optstring
Establece opciones para el tipo de gestor de objetos de audio '*mgrtype*'. Para las opciones disponibles, consulte las "NOTAS ESPECÍFICAS DEL TIPO DE OBJETO" a continuación.
-f:sample_format,channel,sample-rate,interleaving
Establece los parámetros del flujo de audio para los objetos de audio subsiguientes. Para establecer parámetros diferentes para diferentes objetos de audio, se deben especificar múltiples opciones de '* -f*' (tenga en cuenta el orden, las opciones de '* -f*' deben preceder a los objetos de audio para que tengan algún efecto). Consulte la documentación de las opciones de '* -i*' y '* -o*'.
Cuando se abre un objeto de audio (por ejemplo, se abre un archivo o un dispositivo de sonido, o se establece una conexión con un servidor de sonido), los parámetros del flujo de audio se pasan al objeto. Cabe señalar que no todos los objetos de audio permiten establecer todos o algunos de los parámetros. Por ejemplo, al abrir archivos de audio existentes, muchos formatos de archivo tienen una cabecera que describe los parámetros de audio del archivo. En estos casos, la cabecera del archivo de audio anula los parámetros pasados con la opción '* -f*'. De manera similar, al crear entradas y salidas JACK, el servidor JACK exige la frecuencia de muestreo y el formato de muestra.
Si no se especifica ninguna opción de '* -f*', o si se dejan vacíos algunos de los campos de argumento (por ejemplo, '* -f:,2,44100*'), ecasound usará valores predeterminados. Estos valores predeterminados se definen en el archivo de configuración de ecasoundrc. Consulte la página del manual de ecasoundrc(5).
Tenga en cuenta que ecasound abre los archivos de salida de forma predeterminada en modo de actualización. A menos que se proporcione la opción '* -x*' (sobrescribir salidas), los parámetros de audio de un archivo de audio existente tienen preferencia sobre los parámetros establecidos con '* -f*'.
El formato de muestra se proporciona como una cadena formateada. La primera letra es '"u"', '"s"' y '"f"' (sin signo, con signo, punto flotante). El número siguiente especifica el tamaño de la muestra en bits. Si la muestra es little endian, se añade '"_le"' al final. De manera similar, si es big endian, se añade '"_be"'. Si no se especifica el orden de bytes, se utiliza el orden de bytes del host. Los formatos admitidos actualmente son '"u8"' (igual que '"8"'), '"s16_le"' (igual que '"16"'), '"s16_be"', '"s24_le"', '"s24_be"', '"s32_le"', '"s32_be"', '"f32_le"' y '"f32_be"'. Una cadena vacía '""' selecciona el formato de muestra predeterminado del sistema.
El cuarto parámetro define la disposición de los canales. Las opciones disponibles son '* i*' (intercalado) y '* n*' (no intercalado). Con la configuración no intercalada, ecasound procesará muestras de un canal a la vez y el tamaño del bloque se establece con '* -b*'. La configuración predeterminada es '* i*'.
-y:seconds
Establece la posición de inicio para la última entrada/salida especificada. Si necesita un control más flexible sobre los objetos de audio, debe utilizar el formato *.ewf*.
-i[:]input-file-or-device[,params]
Especifica una nueva fuente de entrada que se conecta a todas las cadenas seleccionadas (las cadenas se seleccionan con '* -a: ...*'). No es posible conectar múltiples entradas a la misma cadena, pero una entrada se puede conectar a múltiples cadenas. La entrada puede ser un archivo, un dispositivo o algún otro objeto de audio (ver abajo). Si la entrada es un archivo, su tipo se determina utilizando la extensión del nombre del archivo. Si el nombre del objeto contiene comas, el nombre debe encerrarse entre comillas invertidas para evitar confundir al analizador. Los formatos actualmente compatibles son archivos RIFF WAVE (.wav), pistas de CD de audio (.cdr), archivos EWF de ecasound (.ewf), datos de audio RAW (.raw) y archivos de audio MPEG (.mp2,.mp3). Se admiten más formatos de audio a través de las bibliotecas libaudiofile y libsndfile (ver documentación a continuación). MikMod también es compatible (.xm, .mod, .s3m, .it, etc.). Los archivos MIDI (.mid) se admiten utilizando Timidity++. De manera similar, Ogg Vorbis (.ogg) se puede leer y escribir si las herramientas ogg123 y vorbize están instaladas; archivos FLAC (.flac) con las herramientas de línea de comandos de flac o usando libsndfile; y archivos AAC (.aac/.m4a/.mp4) con las herramientas faad2/faac. Los dispositivos en tiempo real compatibles son dispositivos de audio OSS (/dev/dsp*), dispositivos de audio y loopback ALSA y el subsistema de audio JACK. Si no se especifican entradas, el primer argumento de línea de comandos que no sea una opción (no comienza con '-') se considera una entrada.
-o[:]output-file-or-device[,params]
Funciona de la misma manera que la opción -i. Si no se especifican salidas, se utiliza el dispositivo de salida predeterminado (ver ~/.ecasoundrc). Si el nombre del objeto contiene comas, el nombre debe encerrarse entre comillas invertidas para evitar confundir al analizador. Tenga en cuenta que muchos tipos de objetos no admiten salida (por ejemplo, MikMod, MIDI y muchos otros).
NOTAS ESPECÍFICAS DEL TIPO DE OBJETO
Dispositivos ALSA - '*alsa*'
Al usar controladores ALSA, en lugar de un nombre de archivo de dispositivo, necesita usar la siguiente sintaxis de opción: **-i[:]alsa,pcm_device_name**.
Acceso directo a ALSA hw y plugin - '*alsahw*', '*alsaplugin*'
También es posible usar una combinación específica de tarjeta y dispositivo utilizando la siguiente notación: **-i[:]alsahw,card_number,device_number,subdevice_number**. Otra opción es la capa de plugin PCM de ALSA. Funciona igual que los pcm-dispositivos normales de ALSA, pero con conversiones automáticas de número de canales y formato de muestra. La sintaxis de la opción es **-i[:]alsaplugin,card_number,device_number,subdevice_number**.
Entrada/salida aRts - '*arts*'
Si está habilitado en tiempo de compilación, ecasound admite entrada y salida de audio utilizando el servidor de audio aRts. La sintaxis de la opción es **-i:arts**, **-o:arts**.
Secuenciación de archivos de audio - '*audioloop*', '*select*', '*playat*'
Ecasound proporciona un conjunto de tipos de objetos de audio especiales que se pueden utilizar para la secuenciación temporal de archivos de audio, es decir, bucles, reproducir solo una porción seleccionada de un archivo, reproducir un archivo en un momento específico y otras operaciones similares.
Los bucles son posibles con **-i:audioloop,file.ext,params**. El nombre del archivo (o cualquier tipo de objeto entendido por Ecasound) proporcionado como segundo parámetro se reproducirá continuamente volviendo al principio cuando se alcance el final del archivo. Cualquier pa adicional
parámetro establece la frecuencia del tono generado y ’duration-secs’ la longitud del flujo generado. Especificar cero, o un valor negativo, como la duración producirá un flujo infinito. Esta función se añadió por primera vez a Ecasound 2.4.7.
Typeselect -
’typeselect’
El tipo de objeto especial ’typeselect’ se puede usar para anular cómo ecasound asigna las extensiones de nombre de archivo y los tipos de objeto. Por ejemplo ecasound -i typeselect,.mp3,an_mp3_file.wav -o /dev/dsp. reproduciría el archivo ’an_mp3_file.wav’ como un archivo mp3 y no como un archivo wav como ocurriría sin
typeselect.
Los parámetros 4...N se pasan tal cual al objeto hijo (es decir, "-i typeselect,.au,foo.wav,bar1,bar2" pasará los parámetros "bar1,bar2" al objeto "foo.
wav".

SEÑAL
-eS:
stamp-id
Sello de audio. Toma una instantánea de los datos de audio que pasan y los almacena usando el id ’stamp-id’ (número entero). Estos datos pueden ser usados más tarde por controladores y otros
operadores.
-ea:
amplify%
Ajusta la amplitud de la señal al ’amplify%’ por ciento (escala lineal, es decir, las muestras individuales se multiplican por ’amplify%/100’). Ver también
’-eadb’.
-eac:amplify%,
channel
Amplifica la señal del canal ’channel’ en un porcentaje amplify-% (escala lineal, es decir, las muestras individuales se multiplican por ’amplify%/100’). ’channel’ varía de 1...n donde n es el número total de canales. Ver también
’-eadb’.
-eadb:gain-dB[,
channel]
Ajusta el nivel de la señal en ’gain-dB’, con una ganancia de 0dB que no tiene efecto sobre la señal, ganancias negativas que atenúan la señal y valores de ganancia positivos que la amplifican. El parámetro ’channel’ (1...n) es opcional. Si se especifica el parámetro ’channel’ y su valor es distinto de cero, la ganancia solo se aplica al canal dado (1...
n).
-eaw:amplify%,max-clipped-samp
les
Amplifica la señal en un porcentaje amplify-% (escala lineal, es decir, las muestras individuales se multiplican por ’amplify%/100’). Si el número de muestras recortadas consecutivas (el valor de la muestra resultante está fuera del rango nominal [-1,1]) supera max-clipped-samples, se emitirá una
advertencia.

Un compresor más avanzado (algoritmo original de John S. Dyson). LADSPA
-el:plugin_unique_name,param-1,...,
param-N
Ecasound soporta plugins de efectos LADSPA (Linux Audio Developer’s Simple Plugin API). Los parámetros 1..N se establecen como valores de los puertos de control del
plugin.
Si el plugin tiene más de un puerto de entrada y/o salida de audio, solo se crea una instancia del plugin, y los canales de la cadena se alimentan a la misma instancia del plugin. Si el plugin tiene como máximo un puerto de entrada y como máximo un puerto de salida de audio, se crea una instancia de plugin separada para cada canal de la cadena de ecasound (p. ej., para un canal de audio estéreo, se crean dos plugins LADSPA del mismo tipo, uno por canal)
.
Los plugins se localizan en archivos de biblioteca compartida (.so). Ecasound busca plugins en @prefix@/lib/ladspa (p. ej. "/usr/local/lib/ladspa"), directorios listados en la variable de entorno LADSPA_PATH. La ruta de búsqueda de plugins también se puede configurar a través de ecasoundrc, ver la página de manual ecasoundrc(5). Un archivo de biblioteca compartida puede contener múltiples objetos de plugin, pero cada plugin tiene un nombre de plugin único. Este nombre se usa para seleccionar
plugins.
Vea el sitio web de la lista de correo LAD para más información sobre LADSPA. Otros sitios útiles son la página de inicio de LADSPA y la documentación de
LADSPA.

-gc:start-time,

Compuerta de recorte por tiempo. Inicialmente la compuerta está cerrada. Después de que han transcurrido ’start-time’ segundos, la compuerta se abre y permanece abierta durante ’len’ segundos. Cuando está cerrada, los buffers de audio que pasan se truncan a longitud

-ge:open-threshold-%,close-thold-%,volume-mode,

Compuerta por umbral. Inicialmente la compuerta está cerrada. Se abre cuando el volumen supera el porcentaje ’othreshold’. Después de esto, si el volumen cae por debajo del porcentaje ’cthold’, la compuerta se cierra y no se abrirá de nuevo, a menos que ’reopen-count’ esté establecido a algo distinto de cero. Si ’value_mode’ es ’rms’, se usa el volumen RMS promedio. De lo contrario se usa el promedio de pico. Cuando está cerrada, los buffers de audio que pasan se truncan a longitud cero. Si ’reopen-count’ está establecido a un número positivo, la compuerta reiniciará su operación esa cantidad de veces. Así que por ejemplo, un recuento de reapertura de 1 causará hasta 2 aperturas de la compuerta. Se pueden grabar tantos lados como desee en una sesión. Necesitará experimentar con longitudes de buffer y niveles de inicio/parada para obtener configuraciones fiables para su
equipo.

SEÑALE

S

Cuando ecasound recibe cualquiera de las señales POSIX SIGINT (ctrl-c), SIGHUP, SIGTERM o SIGQUIT, se inicia el procedimiento normal de limpieza y salida. Aquí, la salida normal significa que, por ejemplo, se actualizan las cabeceras de los archivos antes de cerrar, los procesos auxiliares se terminan de forma normal, y así

sucesivamente.

Si, mientras realiza la limpieza descrita anteriormente, ecasound recibe otra señal (del mismo conjunto de señales POSIX), ecasound omitirá el procedimiento de limpieza normal y terminará inmediatamente. Cualquier tarea de limpieza restante será omitida. Dependiendo del estado de ejecución y la configuración, esta salida forzada puede tener algunos efectos secundarios. Ecasound devolverá el código de salida ’4’ si se omitió la limpieza

normal.

Se aplica un manejo especial a la señal SIGINT (ctrl-c). Si se recibe una señal SIGINT durante el procedimiento de limpieza, ecasoun

d ignorará la señal una vez y emitirá un aviso en ’stderr’ que la limpieza ya está en progreso. Cualquier señal SIGINT posterior
ya no recibirá un manejo especial, y en su lugar el proceso terminará inmediatamente (y posiblemente sin una limpieza adecuada).
