ECM-TOOLCHAINS(7) Módulos Extra de CMake ECM-TOOLCHAINS(7)

NOMBRE

ecm-toolchains - Referencia de Toolchains de ECM

INTRODUCCIÓN

Extra CMake Modules (ECM) proporciona algunos módulos de toolchain. A diferencia de los módulos normales, estos no se incluyen directamente en los proyectos, sino que se especifican con la variable de caché CMAKE_TOOLCHAIN_FILE en la línea de comandos.

TODOS LOS MÓDULOS

AndroidToolchain

Permite la compilación sencilla de proyectos de CMake en Android.

Al usar esta toolchain de Android, los proyectos se configurarán para compilar el proyecto especificado apuntando a una plataforma Android, dependiendo de su entrada. Además, si se desea, se puede generar directamente un APK utilizando la herramienta androiddeployqt https://doc.qt.io/qt-5/deployment-android.html.

CMake upstream ahora tiene soporte para Android. Este módulo aún nos proporcionará algunas características útiles que ofrecen integración con androiddeployqt y formatos de ejecutables adecuados para nuestras aplicaciones Android.

Dado que estamos utilizando el soporte de Android de CMake, cualquier información de la documentación de CMake sigue siendo aplicable: https://cmake.org/cmake/help/v3.7/manual/cmake-toolchains.7.html#cross-compiling-for-android

Nota:

Este módulo requiere CMake 3.18.

Desde la versión 1.7.0.

Uso

Para usar este archivo, necesita establecer CMAKE_TOOLCHAIN_FILE para que apunte a Android.cmake en la línea de comandos:

cmake -DCMAKE_TOOLCHAIN_FILE=/usr/share/ECM/toolchain/Android.cmake

También deberá proporcionar las ubicaciones del NDK y SDK de Android. Esto se puede hacer en la línea de comandos o con variables de entorno; en cualquier caso, los nombres de las variables son:

CMAKE_ANDROID_NDK
La ruta raíz del NDK.
ANDROID_SDK_ROOT
La ruta raíz del SDK.

Las opciones adicionales se especifican como variables de caché (por ejemplo, en la línea de comandos):

ANDROID_ABI
La ABI a usar. Consulte los directorios sources/cxx-stl/gnu-libstdc++/*/libs en el NDK. Por defecto: armeabi-v7a.
ANDROID_SDK_COMPILE_API
El nivel de API de la plataforma contra el que compilar. Puede ser diferente del objetivo del NDK. Por defecto: la versión instalada más reciente (por ejemplo, android-30).
ANDROID_SDK_BUILD_TOOLS_REVISION
La versión de las herramientas de compilación a usar. Por defecto: la versión instalada más reciente (por ejemplo, 30.0.2).
ANDROID_EXTRA_LIBS
La lista separada por “;” de rutas completas a bibliotecas para incluir en el APK resultante (solo Qt 5).

Para integrar otras bibliotecas que no forman parte de la toolchain de Android, como Qt5, e instaladas en un prefijo separado en el sistema huésped, los prefijos de instalación de esas bibliotecas se pasarían como raíces alternativas mediante una lista a través de ECM_ADDITIONAL_FIND_ROOT_PATH. Desde la versión 5.30.0.

Por ejemplo, para integrar un Qt5 para Android presente en ~/Qt/5.14.2/android/ y algunas otras bibliotecas instaladas en el prefijo /opt/android/foo, usaría:

cmake \
  -DCMAKE_TOOLCHAIN_FILE=/usr/share/ECM/toolchain/Android.cmake \
  -DECM_ADDITIONAL_FIND_ROOT_PATH="~/Qt/5.14.2/android/;/opt/android/foo"

Si su proyecto utiliza find_package() para localizar herramientas de compilación en el sistema huésped, asegúrese de pasar CMAKE_FIND_ROOT_PATH_BOTH o NO_CMAKE_FIND_ROOT_PATH como argumento en la llamada. Consulte la documentación de find_package() para obtener más detalles.

Despliegue de Aplicaciones Qt 5

Después de compilar la aplicación, necesitará generar un APK que pueda desplegarse en un dispositivo Android. Este módulo integra el soporte de androiddeployqt para ayudar con esto para proyectos basados en Qt. Para activarlo, establezca la variable QTANDROID_EXPORTED_TARGET en los objetivos que desea exportar como un APK (en una lista separada por ';'), así como ANDROID_APK_DIR en un directorio que contenga información básica. Esto creará un objetivo create-apk-<objetivo> que generará el archivo APK. Consulte la documentación de Qt en Android sobre el despliegue https://doc.qt.io/qt-5/deployment-android.html para más información.

Por ejemplo, podría hacer:

cmake \
  -DCMAKE_TOOLCHAIN_FILE=/usr/share/ECM/toolchain/Android.cmake \
  -DQTANDROID_EXPORTED_TARGET=mi_app \
  -DANDROID_APK_DIR=mi_app-apk
make
make create-apk-mi_app

Puede especificar el directorio de salida del APK estableciendo ANDROID_APK_OUTPUT_DIR. De lo contrario, el APK se encontrará en myapp_build_apk/ en el directorio de compilación.

El objetivo create-apk-mi_app podrá tomar un parámetro ARGS con argumentos adicionales para androiddeployqt. Por ejemplo, puede usar:

make create-apk-mi_app ARGS="--install"

Para instalar el apk y probarlo. Para generar un apk firmado, puede hacerlo con la siguiente sintaxis:

make create-apk-mi_app ARGS="--sign ~/mi.keystore nombre_alias"

En caso de que sea necesario para su aplicación establecer el directorio del APK desde el script de CMake, también puede establecer el directorio como la propiedad ANDROID_APK_DIR del objetivo create-apk-mi_app.

Consulte la documentación de Android sobre cómo crear un almacén de claves para usarlo.

Opciones Avanzadas

Las siguientes opciones de empaquetado son principalmente interesantes para la automatización o la integración con canalizaciones de CI/CD:

ANDROID_APK_OUTPUT_DIR
Especifica una carpeta donde se deben colocar los archivos APK generados.
ANDROID_FASTLANE_METADATA_OUTPUT_DIR
Especifica una carpeta donde se deben colocar los metadatos generados para la tienda F-Droid.
ANDROIDDEPLOYQT_EXTRA_ARGS
Permite pasar argumentos adicionales a androiddeployqt. Esto es una alternativa al argumento ARGS= para make y, a diferencia de este, funciona con todos los generadores de CMake.
