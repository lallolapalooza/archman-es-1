DESCRIPCIÓ

N

ecj es el compilador por lotes de Eclipse y está disponible como ecj.jar. Desde la versión 3.3, este jar también contiene el soporte para jsr199 (AP

I de compilación) y el soporte para jsr269 (Procesamiento de anotaciones). Par
a usar el soporte de procesamiento de anotaciones, se requiere una VM 1.6.

Opciones de

ClassPath
-bootclasspath <dir 1>;<dir 2>;...;<dir
P>
Esta es una lista de directorios o archivos jar utilizados para iniciar los archivos de clase usados por el compilador. Por defecto, se usan las bibliotecas de la VM en ejecución. Las entradas están separadas por el separador de ruta de la plataforma. Cada directorio o archivo puede especificar reglas de acceso para tipos entre '[' y ']'. Si no se especifica bootclasspath, el compilador lo inferirá usando las siguientes propiedades del sistema sun.boot.class.path, vm.boot.class.path o org.apache.harmony.boot.class.path en este orden
respectivamente
-cp|-classpath <dir 1>;dir2;...<dir
P>
Esta es una lista de directorios o archivos jar utilizados para compilar los archivos fuente. El valor predeterminado es el valor de la propiedad "java.class.path". Las entradas están separadas por el separador de ruta de la plataforma. Cada directorio o archivo puede especificar reglas de acceso para tipos entre '[' y ']' (por ejemplo, [-X] para prohibir el acceso al tipo X, [~X] para desalentar el acceso al tipo X, [+p/X:-p/*] para prohibir el acceso a todos los tipos en el paquete p pero permitir el acceso a p/X). El compilador sigue las cláusulas Class-Path de los manifiestos de los archivos jar recursivamente y agrega cada archivo jar referenciado al final de la classpath, siempre que aún no esté en la
classpath.
-extdirs <dir 1>;<dir 2>;...;<dir
P>
Esta es una lista de directorios utilizados para especificar la ubicación de los archivos zip/jar de extensión. Las entradas están separadas por el separador de ruta de la
plataforma.
-endorseddirs <dir 1>;<dir 2>;...;<dir
P>
Esta es una lista de directorios utilizados para especificar la ubicación de los archivos zip/jar respaldados. Las entradas están separadas por el separador de ruta de la
plataforma.
-sourcepath <dir 1>;<dir 2>;...;<dir
P>
Esta es una lista de directorios utilizados para especificar los archivos fuente. Las entradas están separadas por el separador de ruta de la plataforma. Cada directorio puede especificar reglas de acceso para tipos entre '[' y
']'.
-d <dir 1>
|none
Esto se usa para especificar en qué directorio deben volcarse los archivos .class generados. Si se omite, no se crea ninguna estructura de directorios de paquetes. Si desea no generar ningún archivo .class, use -d
none.
-encoding <nombre-de-codificaci
ón>
Especifica la codificación predeterminada para todos los archivos fuente. La codificación personalizada también puede especificarse por archivo al sufijar cada nombre de archivo/carpeta de entrada fuente con [<nombre-de-codificación>]. Por ejemplo, X.java[UTF-8] especificaría la codificación UTF-8 para la unidad de compilación X.java ubicada en el directorio de usuario actual. Si se especifican múltiples codificaciones de archivo fuente predeterminadas, se usará la última.

Por ejemplo: ... -encoding UTF-8 X.java[Cp1252] Y.java[UTF-16] Z.java ....
Todos los archivos fuente se leerán usando la codificación UTF-8 (esto incluye Z.java). X.java se leerá usando la codificación Cp1252 y Y.java se leerá usando la codificación

UTF-16.

... -encoding UTF-8 -encoding UTF-16 ....
Todos los archivos fuente se leerán usando la codificación UTF-16. La opción -encoding para UTF-8 se

ignora.

... -encoding Cp1252 /foo/bar/X.java[UTF-16] /foo/bar[UTF-8] ....
Todos los archivos fuente se leerán usando la codificación Cp125

2. X.java es el único archivo dentro del directorio /foo
/bar que se leerá usando la codificación UTF-16. Todos lo
s demás archivos en ese directorio usarán la codificación UTF-8.

Opciones de advertencia

-?:warn -help:warn
Muestra opciones avanzadas de advertencia.
-warn:...
Especifica el conjunto de advertencias habilitadas.
-warn:none desactiva todas las advertencias
-warn:<tokens de advertencia separados por ,> habilita exactamente las advertencias listadas
-warn:+<tokens de advertencia separados por ,> habilita advertencias adicionales
-warn:-<tokens de advertencia separados por ,> deshabilita advertencias específicas

Ejemplos:

warn:unusedLocal,deprecation
habilita solo las dos opciones de advertencia dadas y deshabilita todas las demás opciones

warn:-unusedLocal,deprecation,+fallthrough
deshabilita unusedLocal y deprecation, habilita fallthrough y deja las demás opciones de advertencia sin cambios

La primera columna a continuación muestra el estado predeterminado para una opción. Una marca "+/-" indica que una opción cubre varias variantes de advertencia detalladas, algunas de las cuales están habilitadas de forma predeterminada, otras deshabilitadas. Esto significa que especificar la opción dada con "+" habilitará más advertencias que las predeterminadas, y especificar "-" deshabilitará algunas que están habilitadas de forma predeterminada.
