NOMBRE

ecasound-iam - modo interactivo de ecasound

SINOPSIS

DESCRIPCIÓN

La biblioteca de Ecasound contiene un módulo intérprete que entiende un conjunto de comandos destinados a controlar varios servicios de la biblioteca. Esto se denomina el modo interactivo de ecasound (EIAM). Todos los programas vinculados a la biblioteca de ecasound pueden utilizar esta funcionalidad.

API ECI y tipos de retorno

Un caso especial del uso del modo interactivo es la interfaz de control de ecasound (ECI), que es una pequeña biblioteca que proporciona un acceso fácil a los comandos del modo interactivo desde fuera de libecasound. Al emitir comandos inter utilizando la interfaz de control, es posible que los comandos también devuelvan información. Los tipos de valor de retorno soportados actualmente son: cadena [s], lista de cadenas [S] (elementos separados por comas; escapados si es necesario), entero [i], entero largo [li] y número de punto flotante [f]. Estas definiciones se utilizan en todo este documento. Los comandos que no devuelven nada (void) se marcan con [-]. Además, el tipo de retorno [e] marca una condición de error. Cuando un comando del modo interactivo resulta en un error, se devuelve una cadena de error que explica la condición.

Limitaciones relacionadas con el control y las modificaciones en tiempo real

No es posible usar todos los comandos del modo interactivo para modificar y controlar objetos que pertenecen a un chainsetup conectado. Ecasound desconectará automáticamente (y luego intentará reconectar) el chainsetup en caso de que estos comandos se reciban mientras está conectado. Los comandos que tienen esta limitación son:

cs-remove, cs-set-length, cs-set-length-samples, cs-toggle-loop, cs-set-param, cs-option, c-add, c-remove, c-rename, c-clear, ai-add, ai-remove, ai-attach, ai-forward, ai-rewind, ai-set-position, ai-set-position-samples, ao-add, ao-add-default, ao-remove, ao-attach, ao-forward, ao-rewind, ao-set-position, ao-set-position-samples.

Los siguientes comandos pueden usarse con un chainsetup conectado, pero requieren pausar el motor temporalmente (si está en ejecución) y esto puede causar interrupciones audibles en la reproducción y la grabación. En la práctica, esto significa que actualmente no es posible añadir o eliminar operadores de cadena de manera sin interrupciones/sin costuras. Los comandos afectados:

cop-add, ctrl-add,

Los siguientes comandos pueden usarse en un chainsetup conectado y cuando el motor está en ejecución (no es una lista completa, pero al menos estos comandos están soportados):

cop-set, copp-set, ctrlp-set, c-bypass, c-muting, setpos, cs-set-position, *-describe *-deselect, *-get, *-list, *-register *-select, *-selected, *-status, dump-*, int-*, jack-*, map-*

GENERAL

quit, q
Termina la sesión de ecasound. Lo que esto significa en la práctica depende de la implementación del cliente. En el modo interactivo de ecasound, ’quit’ termina el proceso de ecasound. Cuando se envía a través de una conexión de servidor de ecasound (también conocido como NetECI), ’quit’ termina la conexión de red activa, pero no termina el proceso del servidor de ecasound. [-]
start, t
Se inicia el procesamiento (reproducción). Se devuelve una cadena de error si se encuentran errores al inicio. [e]
stop, s
Detiene el procesamiento. [-]
stop-sync, s
Detiene el procesamiento con una llamada bloqueante (no retorna hasta que el motor se ha detenido realmente). [-]
run
Como ’start’ pero bloquea hasta que el procesamiento ha finalizado. Se devuelve una cadena de error si se encuentran errores al inicio o durante el proceso. [e]
debug ’debug-level’
Establece el nivel de depuración a ’debug-level’. Ten en cuenta que los programas cliente pueden reimplementar las rutinas de depuración. [-]
resource-file ’path-to-file’
Sobreescribe los archivos de recursos globales y de usuario. No afecta a los objetos ya creados. Este comando es equivalente a la opción de ecasound ’-R’ (ver la página de manual de ecasound (1)).
-prefix:arg1,...,argN
Equivalente a emitir ’cs-option -prefix:arg1,...,argN). Ver la documentación de ’cs-option’.
help’, ’h’
¡Ayuda! [-]

GLOBAL

engine-status
Devuelve una cadena que describe el estado del motor (en ejecución, detenido, finalizado, error, no listo). Ver también cs-status. [s]
engine-launch
Inicia el motor en tiempo real. El motor ejecutará el chainsetup actualmente conectado (ver ’cs-connect). Esta acción aún no inicia el procesamiento real (ver start y stop). Cuando ecasound se usa como un cliente JACK, emitir engine-launch hace que ecasound sea un cliente JACK activo (es decir, los puertos de ecasound pueden conectarse a otros clientes JACK). [-]
engine-halt
Detiene el motor. No desconecta el chainsetup que estaba en ejecución. Ver también cs-disconnet y stop. Cuando ecasound se usa como un cliente JACK, engine-halt hará que ecasound se convierta en un cliente desactivado (todas las conexiones JACK se desmontan). [-]

CHAINSETUPS

El chainsetup es el objeto de datos central. Todos los demás objetos (entradas, salidas, cadenas, etc) están conectados a algún chainsetup. Puede haber muchos chainsetups pero solo uno puede estar conectado. De manera similar, solo un chainsetup puede estar seleccionado. Si no se especifica lo contrario, las operaciones se realizan en el chainsetup seleccionado. Algunas operaciones también requieren que el chainsetup seleccionado no esté conectado.

CHAINSETUPS

A chainsetup is a collection of chains. For the moment, ecasound supports only one chainsetup at a time. This implies that the currently loaded chainsetup is also the one that is currently running.

cs-load ’chainsetup_file’
Loads a chainsetup from the given file. If a chainsetup is already loaded, it will be unloaded first. [-]
cs-load-stream ’stream_name’
Loads chainsetup from a named stream. This is how chainsetups defined via commandline arguments (e.g. -p) are loaded. [-]
cs-unload
Unloads currently loaded chainsetup. [-]
cs-save ’chainsetup_file’
Saves the currently loaded chainsetup to the specified file. [-]
cs-name
Returns the name of the currently loaded chainsetup. [s]
cs-select ’chainsetup_name’
Selects a chainsetup by name. This is needed if you have multiple chainsetups loaded (e.g. by using streams). Normally you only have one chainsetup loaded by using cs-load. [-]
cs-iselect ’index’
Selects a chainsetup by its index (1..N). [-]
cs-list
Returns a list of all loaded chainsetups. [S]
cs-is-loaded
Returns true if there is a chainsetup loaded. [i]
cs-is-active
Returns true if the currently selected chainsetup is loaded back to ecasound. [-]
cs-is-valid
Whether currently selected chainsetup is valid (=can be connected)? [i]
cs-connect
Connect currently selected chainsetup to engine. When connecting, all resources (e.g. files, soundcard devices, external programs) needed to execute the chainsetup are reserved. Only one chainsetup can be connected at a time. Error string is returned if connection fails (for instance due to error in allocating the resources). [e]
cs-disconnect
Disconnect currently connected chainsetup. This action will free all external resources needed by the chainsetup. [-]
cs-connected
Returns the name of currently connected chainsetup. [s]
cs-rewind ’time-in-seconds’, rewind ’time-in-seconds’, rw ’time-in-seconds’
Rewinds the current chainsetup position by ’time-in-seconds’ seconds. Position of all inputs and outputs attached to the selected chainsetup is also affected. [-]
cs-forward ’time-in-seconds’, forward ’time-in-seconds’, fw ’ttime-in-seconds’
The current chainsetup position is forwarded by ’time-in-seconds’ seconds. Position of all inputs and outputs attached to the selected chainsetup is also affected. [-]
cs-set-position ’time-in-seconds’, cs-setpos ’time-in-seconds’, setpos ’time-in-seconds’, set-position ’time-in-seconds’
Sets the chainsetup position to ’time-in-seconds’ seconds from the beginning. Position of all inputs and outputs attached to the selected chainsetup is also affected. [-]
cs-set-position-samples ’time-in-samples’
Sets the chainsetup position to ’time-in-samples’ samples from the beginning. Position of all inputs and outputs attached to the selected chainsetup is also affected. [-]
cs-get-position, cs-getpos, getpos, get-position
Returns the current chainsetup position in seconds. [f]
cs-get-position-samples
Returns the current chainsetup position in samples. [li]
cs-get-length, get-length
Returns the chainsetup length in seconds (if known). [f]
cs-get-length-samples, get-length-samples
Returns the chainsetup length in samples (if known). [li]
cs-set-length ’seconds’
Sets processing time in seconds (doesn’t have to be an integer value). A special-case value of ’-1’ will set the chainsetup length according to the longest input object. [-]
cs-set-length-samples ’samples’
Sets processing time in samples. [-]
cs-toggle-loop
Toggle looping. When processing is finished, engine will start again from the initial position. It’s not always possible to enable looping (for instance all inputs and outputs have infinite length and chainsetup length is not explicitly set with ’cs-set-length’). [-]
cs-set-param
Interpret general chainsetup parameters like for example "-b" (buffersize), "-n" (name), etc. See ecasound (1) for more info. [-]
cs-set-audio-format ’bits,channels,sample_rate’
Set the default sample parameters for currently selected chainsetup. For example cd-quality audio would be "16,2,44100". This does the same as command-line argument "-f" (see ecasound (1)). [-]
cs-status, status, st
Prints out status information about available chainsetup. Detailed information is printed out for connected (=available for running) nd selected (=available for editing) chainsetups. Other chainsetups are listed, but further details are suppressed. To get full details of a specific chainsetup, select it with ’cs-select’ or ’cs-iselect’, and then issue ’cs-select’. [s]
cs-option ’-prefix:arg1,...,argN’
One powerful feature of the interactive-mode is that it provides full access to ecasound’s command-line syntax. For instance, command "cs-option -efb:400,200" means that a bandpass filter is added to the currently selected chain, with initial parameters 400 (center frequency) and 200 (width in Hz).

Note that session level options (such as setting debug level) can not be used with ’cs-option’ (i.e. only options that modify chainsetups).

Note! Ecasound interactive mode implicitly interprets all strings beginning with a ’-’ as "cs-option string".

CHAINS

Chain is a simple signal flow abstraction. Every chain has one input and one output. All chain operators and their controllers are attached to chains. Chains can be muted, unmuted and be bypassed. If not otherwise stated, all operations are done to currently selected chainsetup.

c-add ’cname1,...,cnameN’
Adds a set of chains. Added chains are automatically selected. Note that commas in chain names are not allowed. [-]
c-remove
Removes selected chains. [-]
c-list
Returns a list of all chains. [S]
c-select ’cname1,...,cnameN’
Selects chains. Other chains are automatically deselected. [-]
c-index-select ’index1,...,indexN’, c-iselect ’index1,...,indexN’
Selects a set of chains based on the list of indixes. Each index is an integer value, where ’1’ refers to the first chain. You can use ’c-list’ and ’c-status’ to get a full list of currently available chains. [-]
c-select-all
Selects all chains. [-]
c-select-add ’cname1,...,cnameN’
Selects more chains. [-]
c-deselect ’cname1,...,cnameN’
Deselects chains. [-]
c-selected
Returns a list of selected chains. [S]
c-clear
Clear selected chains by removing all chain operators and controllers. Doesn’t change how chains are connected to inputs and outputs. [-]
c-rename ’new_name’
Renames the selected chain. When using this command, exactly one chain must be selected. [-]
c-mute <on|off|toggle>
Set the mute state of the currently selected chain. When chain is muted, it will only output silence.

The command takes a single parameter: "on" -> chain is muted, "off" -> not muted, and "toggle" -> change the muting state. If parameter is omitted, "toggle" is assumed (muting is either enabled or disabled, depending on previous state).

Control of chain and chain operator muting states is independent. If "c-mute off" is executed, the states of individual cop-bypass commands will take effect. If chain is muted, the chain will output silence irrespective of the individual chain operator muting state. [-]

c-bypass <on|off|toggle>
Set the bypass state of the currently selected chain. When chain is bypassed, sample data is passed through unprocessed (all chain operators are disabled for the given chain).

The command takes a single parameter: "on" -> chain is bypassed, "off" -> no bypass, and "toggle" -> change the bypass state. If parameter is omitted, "toggle" is assumed (bypass is either enabled or disabled, depending on previous state).

Control of chain and chain operator bypass states is independent. If chain bypass is disabled, the states of individual cop-bypass commands will take effect. If chain is bypassed, all operators are bypassed independetly of their cop-bypass state. [-]

c-status, cs
Print status info about all chains. [s]
c-is-bypassed
Returns true if selected chain is currently bypassed (none of the chain operators are run). See ’c-bypass’. [i]
c-is-mute
Returns true if selected chain is currently muted (outputs silence as its output). See ’c-mute’. [i]

AUDIO INPUT/OUTPUT OBJECTS

If not otherwise stated, all operations are done to currently selected object. All commands with ai- prefix operate on audio inputs, while commands with ao- operate on outputs.

ai-add ’input_format_string’
Adds a new input object. See ecasound (1) man page for more info about the argument format (’-i’ option). Note on syntax: if any of the parameters (such as a filename) contains commas, the parameter should be enclosed in double-quotes. [-]
ao-add ’output_format_string’
Adds a new output object. See ecasound (1) man page for more info about the argument format (’-o’ option). [-]
ai-remove, ao-remove
Removes the selected input/output object. [-]
ai-list, ao-list
Returns a list of all audio input/output objects. [S]
ai-select ’input_object_name’, ao-select ’output_object_name’
Selects an object by its name. Other objects are automatically deselected. [-]
ai-iselect ’index1,...,indexN’, ao-iselect ’index1,...,indexN’
Selects a set of audio input/output objects based on the list of indices. Each index is an integer value, where ’1’ refers to the first object. You can use ’ai-list’ or ’ao-list’ to get a full list of currently available objects. [-]
ai-select-all, ao-select-all
Selects all audio input/output objects. [-]
ai-selected, ao-selected
Returns a list of currently selected audio input/output objects. [S]
ai-connect, ao-connect
Connects the selected audio object(s) to the engine. This implies that the object becomes active and potentially starts consuming/producing audio. [-]
ai-disconnect, ao-disconnect
Disconnects the selected audio object(s) from the engine. Resources used by the object are released. [-]
ai-is-connected, ao-is-connected
Returns true if the selected audio object is currently connected to the engine. [i]
ai-start, ao-start
Starts the selected audio object(s). For inputs this means starting to read audio data, for outputs this means starting to write audio data. [-]
ai-stop, ao-stop
Stops the selected audio object(s). [-]
ai-is-playing, ao-is-playing
Returns true if the selected audio object is currently playing (i.e. actively reading/writing audio data). [i]
ai-rewind, ao-rewind
Rewinds the selected audio object(s). For inputs this means setting the read position to the beginning of the file/stream. For outputs this means setting the write position to the beginning. [-]
ai-forward, ao-forward
Forwards the selected audio object(s) by the specified number of seconds. [-]
ai-set-position, ao-set-position
Sets the position of the selected audio object(s) to the specified number of seconds from the beginning. [-]
ai-set-position-samples, ao-set-position-samples
Sets the position of the selected audio object(s) to the specified number of samples from the beginning. [-]
ai-get-position, ao-get-position
Returns the current position of the selected audio object(s) in seconds. [f]
ai-get-position-samples, ao-get-position-samples
Returns the current position of the selected audio object(s) in samples. [li]
ai-get-length, ao-get-length
Returns the length of the selected audio object(s) in seconds (if known). [f]
ai-get-length-samples, ao-get-length-samples
Returns the length of the selected audio object(s) in samples (if known). [li]
ai-set-length ’seconds’, ao-set-length ’seconds’
Sets the length of the selected audio object(s) in seconds. This is primarily useful for outputs, to specify the total amount of data to be written. [-]
ai-set-length-samples ’samples’, ao-set-length-samples ’samples’
Sets the length of the selected audio object(s) in samples. [-]
ai-status, ao-status
Prints status information about the selected audio object(s). [s]
ai-set-param, ao-set-param
Interpret general audio object parameters. See ecasound (1) for more info. [-]

CHAIN OPERATORS

Chain operators (or cop s) are the building blocks of chains. Every chain has an input and an output, and these are connected via chain operators. If not otherwise stated, all operations are done to currently selected chainsetup.

cop-add ’operator_name’
Adds a chain operator to the selected chain(s). Chain operator is added to the end of the chain. [-]
cop-add-before ’operator_name’
Adds a chain operator before the selected operator(s) in the chain. If no operator is selected, it is added to the beginning of the chain.
cop-add-after ’operator_name’
Adds a chain operator after the selected operator(s) in the chain. If no operator is selected, it is added to the end of the chain.
cop-remove
Removes the selected chain operator(s). [-]
cop-list
Returns a list of all chain operators in the selected chain(s). [S]
cop-select ’operator_name1,...,operator_nameN’
Selects operators by name. Other operators are deselected. Note that operator names are not unique, so this command selects all operators matching the given name. [-]
cop-iselect ’index1,...,indexN’
Selects operators based on their indices within the current chain. Indices start from 1. Use `cop-list` to see the indices. [-]
cop-select-add ’operator_name1,...,operator_nameN’
Adds operators to the current selection by name. [-]
cop-iselect-add ’index1,...,indexN’
Adds operators to the current selection by index. [-]
cop-deselect ’operator_name1,...,operator_nameN’
Deselects operators by name. [-]
cop-clear
Removes all operators from the selected chain(s). [-]
cop-move <up|down>
Moves the selected operator(s) one step up or down in the chain. [-]
cop-move-first
Moves the selected operator(s) to the beginning of the chain. [-]
cop-move-last
Moves the selected operator(s) to the end of the chain. [-]
cop-mute <on|off|toggle>
Set the mute state of the selected operator(s). Muted operators do not output any signal. [-]
cop-bypass <on|off|toggle>
Set the bypass state of the selected operator(s). When bypassed, the operator is effectively removed from the signal path, but its state is preserved. [-]
cop-status
Prints status information about the selected operator(s). [s]
cop-set-param ’param_list’
Sets parameters of the selected operator(s). Parameter list is a comma separated list of parameter-value pairs. For example: "100,0.5" or "freq=100,q=0.5". Consult operator specific documentation for available parameters and their meanings. [-]
cop-get-param
Returns the parameters of the selected operator(s). [s]
cop-get-name
Returns the name of the selected operator(s). [s]
cop-get-type
Returns the type name of the selected operator(s). [s]
cop-get-index
Returns the index of the selected operator(s) within their chain. [li]
cop-is-muted
Returns true if the selected operator(s) are muted. [i]
cop-is-bypassed
Returns true if the selected operator(s) are bypassed. [i]

CONTROLLERS

Controllers are used to change parameters of chain operators over time. They can be, for example, LFOs, envelopes, or simple ramps. All controllers are attached to chain operators. If not otherwise stated, all operations are done to currently selected chain operator.

ctl-add ’controller_name’
Adds a controller of the given name to the selected operator. Available controller types include: env (envelope), lfo, ramp, midi. [-]
ctl-remove
Removes the selected controller(s). [-]
ctl-list
Returns a list of controllers attached to the selected operator. [S]
ctl-select ’controller_name1,...,controller_nameN’
Selects controllers by name. Note that controller names are not unique. [-]
ctl-iselect ’index1,...,indexN’
Selects controllers based on their indices within the operator. Use `ctl-list` to see the indices. [-]
ctl-set-param ’param_list’
Sets parameters for the selected controller(s). See controller specific documentation for available parameters. [-]
ctl-get-param
Returns the parameters of the selected controller(s). [s]
ctl-get-name
Returns the name of the selected controller(s). [s]
ctl-get-type
Returns the type name of the selected controller(s). [s]
ctl-connect ’operator_name:parameter_name’
Connects the selected controller to a specific parameter of a chain operator. Parameter name can be found using `cop-get-param`. For example: "ctl-connect gain:value". [-]
ctl-disconnect
Disconnects the selected controller(s) from their target parameter(s). [-]
ctl-is-connected
Returns true if the selected controller is connected to any parameter. [i]
ctl-reset
Resets the controller to its initial state. For example, an envelope controller would reset to the beginning, and an LFO would reset its phase. [-]
