eza_colors — personalización d

e los colores de archivos y de
la interfaz de usuario de eza

SINOPSI

S

La variable de entorno EZA_COLORS puede usarse para personalizar los colores que eza utiliza para resaltar nombres de archivos, metadatos de archivos y partes de la interfaz de

usuario.

Puede usar el programa dircolors para generar un script que establezca la variable a partir de un archivo de entrada, o si no le importa editar largas cadenas de texto, puede escribirla directamente. Estas variables tienen la siguiente

estructura:
•
Una lista de pares clave-valor separados por `=', como por ejemplo `*.txt=3
2'.
•
Múltiples códigos de formato ANSI se separan con `;', como `*.txt=32;1;
4'.
•
Finalmente, múltiples pares se separan con `:', como por ejemplo `*.txt=32:*
.mp3=1
;35'.

La parte clave del par puede ser un código de dos letras o un patrón de coincidencia de archivos (glob), y cualquier cosa que no sea un código válido se tratará como un glob, incluyendo claves que resulten tener exactamente dos

letras.

Por compatibilidad con versiones anteriores se comprueba la variable de entorno EXA_COLORS si EZA_COLORS no es

tá d
efinida.

Muchos terminales tratarán el texto en negrita como un color diferente, o al menos proporcionarán la opción de

hacerlo.

eza proporciona su propio conjunto integrado de mapeos de extensiones de archivo que cubre una gran variedad de extensiones de archivo comunes, incluyendo documentos, archivos comprimidos, medios y archivos temporales. Cualquier mapeo en las variables de entorno anulará este conjunto predeterminado: ejecutar eza con LS_COLORS="*.zip=32" convertirá los archivos zip en verdes pero dejará los colores de otros archivos comprimidos sin

cambios.

También puedes desactivar este conjunto integrado por completo incluyendo una entrada de reinicio al principio de EZA_COLORS. Así que establecer EZA_COLORS="reset:*.txt=31" resaltará solo archivos de texto; establecer EZA_COLORS="reset" n

o resalta
rá nada.
