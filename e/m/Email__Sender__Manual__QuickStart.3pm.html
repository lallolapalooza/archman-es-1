INICIO

RÁPIDO

¡Enviamos algo de

correo!

Sin rodeos, enviemos algo de

correo. 
use strict;
use Email::Sender::Simple qw(sendmail);
use Email::MIME;
# ¡Puedes crear un objeto de correo de muchas formas. Elige la que te guste!
my $email = Email::MIME->create(...);
sendmail($email)
;

Eso es todo. Tu mensaje sale a Internet e intenta ser entregado a "x.ample@exampl

e.com".

En el ejemplo anterior, $email podría ser un objeto Email::MIME, un MIME::Entity, una cadena que contiene un mensaje de correo electrónico, o uno de varios otros tipos de entrada. Si "Email::Abstract" puede entender un valor, se puede pasar a Email::Sender::Simple. Email::Sender::Simple intenta hacer una buena suposición sobre cómo enviar el mensaje. Normalmente intentará usar el programa sendmail en sistemas tipo unix y usar SMTP en Windows. Puedes especificar un transporte, si lo necesitas, pero normalmente eso no debería ser un problema. (Consulta "Elegir un transporte", sin embargo, para más información.

)

También ten en cuenta que importamos y usamos una rutina "sendmail" en el ejemplo anterior. Esto es exactamente lo mismo que

decir: 
Email::Sender::Simple->send($email)
;

...pero es mucho más fácil de escribir. Puedes usar cualquiera de las

dos.

información del

sobre

No tuvimos que decirle a Email::Sender::Simple dónde enviar el mensaje. Si no especificas destinatarios, usará todas las direcciones de correo electrónico que pueda encontrar en los encabezados To y Cc por defecto. Usará Email::Address::XS para analizar esos campos. De manera similar, si no se especifica un remitente, usará la primera dirección encontrada en el encabezado From

.

En la mayoría de los sistemas de transmisión de correo electrónico, sin embargo, los encabezados no están necesariamente vinculados a las direcciones usadas como remitente y destinatarios. Por ejemplo, el encabezado de tu mensaje podría decir "From: mailing-list@example.com" mientras que tu cliente SMTP dice "MAIL FROM:<verp-1234@lists.example.com>". Esta es una característica poderosa, y es necesaria para muchas aplicaciones de correo electrónico. Poder establecerlos distintamente es importante, y Email::Sender::Simple te permite hacer

esto: 
sendmail($email, { to => [ $to_1, $to_2 ], from => $sender })
;

en caso de

error

Cuando el mensaje se envía con éxito (al menos hasta su siguiente salto), "sendmail" devolverá un valor verdadero -- específicamente, un objeto Email::Sender::Success. Este objeto rara vez tiene mucho uso. Lo que es más útil es lo que sucede si el mensaje no puede ser

enviado.

Si hay un error al enviar el mensaje, se lanzará una excepción. Será un objeto que pertenezca a la clase Email::Sender::Failure. Este objeto tendrá un atributo "message" que describe la naturaleza del fallo. Hay varias formas especializadas de fallo, como Email::Sender::Failure::Multi, que se lanza cuando se encuentran más de un error al intentar enviar. No necesitas conocer estas para usar Email::Sender::Simple, sin embargo. Todo lo que necesitas saber es que "sendmail" devuelve verdadero en éxito y muere en

fallo.

Si prefieres no tener que capturar excepciones por fallo al enviar correo, puedes usar el método "try_to_send", que se puede importar como "try_to_sendmail". Este método devolverá solo falso en fallo al enviar

correo.

Por

ejemplo: 
Email::Sender::Simple->try_to_send($email, { ... });
use Email::Sender::Simple qw(try_to_sendmail);
try_to_sendmail($email, { ... })
;

Algunos transportes de Email::Sender pueden señalar éxito si algunos, pero no todos, los destinatarios pu

dieron ser alcanzados. Email::Sender::Simple hace todo lo posible para asegurar que esto nunca suceda. Cu
ando usas Email::Sender::Simple, el correo debería enviarse o no. El éxito parcial nunca debería ocurrir.

Elegir un

transporte

pasar tu propio

transporte

Si Email::Sender::Simple no elige el transporte que quieres, o si tienes necesidades más específicas, puedes especificar un transporte de varias formas. La más simple es construir un objeto de transporte y pasarlo. Puedes leer más sobre transportes en otro lugar. Por ahora, asumiremos que necesitas enviar correo vía SMTP en un puerto inusual. Puedes enviar correo

así: 
my $transport = Email::Sender::Transport::SMTP->new({
  host => 'smtp.example.com',
  port => 2525,
});
sendmail($email, { transport => $transport })
;

Ahora, en lugar de adivinar qué transporte usar, Email::Sender::Simple usará el que proporcionaste. Este transporte tendrá que especificarse para cada llamada a "sendmail", así que podrías querer mirar otras opciones, que siguen a

continuación.

especificar transporte en el

entorno

Si tienes un programa que hace varias llamadas a Email::Sender::Simple, y necesitas ejecutar este programa usando un servidor de correo diferente, puedes establecer variables de entorno para cambiar el valor predeterminado. Por

ejemplo: 
$ export EMAIL_SENDER_TRANSPORT=SMTP
$ export EMAIL_SENDER_TRANSPORT_host=smtp.example.com
$ export EMAIL_SENDER_TRANSPORT_port=2525
$ perl
your-program

Es importante notar que si has establecido el transporte predeterminado usando el entorno, ninguna llamada posterior con el argumento "transport" a "sendmail" será respetada. Si estableces el transporte predeterminado a través del entorno, eso es todo. Todo usará ese transporte. (También, ten en cuenta que aunque dimos los argumentos host y port arriba en minúsculas, las mayúsculas de los argumentos en el entorno se normalizan para soportar sistemas donde las variables de entorno tienen un caso fijo. Así que, "EMAIL_SENDER_TRANSPORT_PORT" también

funcionaría.

Este es un comportamiento extremadamente valioso, ya que te permite auditar cada mensaje que sería enviado por un programa ejecutando algo como

esto: 
$ export EMAIL_SENDER_TRANSPORT=Maildir
$ perl
your-program

En ese ejemplo, cualquier mensaje enviado vía Email::Sender::Simple sería entregado a un maildir en el directorio

actual.

subclasear para cambiar el transporte

predeterminado

Si quieres usar una biblioteca que se comporte como Email::Sender::Simple pero con un transporte predeterminado diferente, puedes subclasear Email::Sender::Simple y reemplazar el método "build_defaul

t_trans
port".

Prueba

s

Email::Sender::Simple hace que sea muy, muy fácil probar código que envía correo electrónico. La forma más simple es hacer algo como

esto: 
use Test::More;
BEGIN { $ENV{EMAIL_SENDER_TRANSPORT} = 'Test' }
use YourCode;
YourCode->run;
my @deliveries = Email::Sender::Simple->default_transport->
deliveries;

Ahora tienes un array que contiene cada entrega realizada a través de Email::Sender::Simple, en orden. Como estableciste el transporte a través del entorno, ningún otro código podrá forzar un transporte

diferente.

Al probar código que hace fork, se puede usar Email::Sender::T

ransport::SQLite para permitir que cada proceso hijo entreg
ue a una sola base de datos de destino, fácil de inspeccionar.

Oye, ¿dónde está mi soporte para

Bcc?

Una pregunta común es "¿Por qué Email::Sender::Simple no respeta automáticamente mi encabezado Bcc?" Esto a menudo se combina con, "Aquí tienes un parche para 'arreglarlo'". Esto no es un error ni una omisión. Bcc se ignora intencionalmentemente por ahora, porque simplemente añadir las direcciones Bcc a los destinatarios del mensaje no produciría el comportamiento generalmente

deseado.

Por ejemplo, aquí hay un conjunto de

encabezados: 
From: sender@example.com
To:   to_rcpt@example.com
Cc:   cc_rcpt@example.com
Bcc:  the_boss@example.
com

En este caso, esperaríamos que el mensaje se entregara a tres personas: to_rcpt, cc_rcpt y the_boss. Por eso se suele sugerir que el encabezado Bcc debería ser una fuente para los destinatarios del sobre. De hecho, sin embargo, un mensaje con un encabezado Bcc probablemente debería entregarse solo a los destinatarios Bcc. La "B" en Bcc significa "ciega" (blind). Los otros destinatarios no deberían ver quién ha recibido copia ciega. Esto significa que quieres enviar dos mensajes: uno a to_rcpt y cc_rcpt, sin ningún encabezado Bcc presente; y otro solo a the_boss, con el encabezado Bcc. Si simplemente recoges las direcciones Bcc como destinatarios, todos verán quién recibió copia

ciega.

Email::Sender::Simple promete enviar mensajes de forma atómica. Es decir: no entregará solo a algunos de los destinatarios y no a otros. Eso significa que no puede detectar automáticamente el encabezado Bcc y realizar dos entregas. Habría una posibilidad de que la segunda fallara después de que la primera tuviera éxito, lo que rompería la promesa de un fallo o éxito

puro.

La otra estrategia para tratar el Bcc es eliminar el encabezado Bcc del mensaje y luego inyectar el mensaje con un sobre que incluya las direcciones Bcc. La información del sobre no será visible para los destinatarios finales, por lo que esto es seguro. Desafortunadamente, esto requiere modificar el mensaje, y Email::Sender::Simple no debería alterar el objeto de correo mutable que se le pasa. No hay un método "clone" en Email::Abstract, por lo que tampoco puede simplemente construir una copia y modificarla. Cuando exista dicho método, el manejo de Bcc podría ser

posible.

Ejemplo de Manejo de

Bcc

Si quieres soportar el encabezado Bcc ahora, depende de ti decidir cómo quieres manipular el correo y inyectar las copias (posiblemente) manipuladas en tu flujo de correo saliente. No es razonable sugerir que Email::Sender::Simple haga este

trabajo.

Ejemplo 1: Establecer explícitamente los destinatarios del sobre para los destinatarios

Bcc

Crea el correo sin un encabezado Bcc, envíalo explícitamente a los usuarios Bcc y luego envíalo implícitamente a los usuarios

To/Cc. 
my $message = create_email_mime_msg;  # <- lo que hagas para obtener el mensaje
$message->header_set('bcc');          # elimina el encabezado Bcc antes de enviar
sendmail($message, { to => $rcpt });  # envía a la dirección Bcc explícita
sendmail($message);                   # y luego envía como
normal

Ejemplo 2: Establecer explícitamente los destinatarios del sobre para todos los

destinatarios

Puedes hacer una sola llamada a "sendmail" extrayendo todas las direcciones de los destinatarios de los encabezados tú mis

mo y especificando todos los destinatarios d
el sobre de una vez. De nuevo, elimina el enc
abezado Bcc antes de que se envíe el mensaje.
