NAME

epoll_wait - wait for some events on an epoll file descriptor

LIBRARY

Epollexclusive to the Linux kernel

SYNOPSIS

       #include <sys/epoll.h>

       int epoll_wait(int epfd, struct epoll_event *events,
                      int maxevents, int timeout);

DESCRIPTION

The epoll interface provides a mechanism for multiplexing I/O events. An epoll instance is created using epoll_create(2) or epoll_create1(2). The set of file descriptors to be monitored is managed using epoll_ctl(2).

The epoll_wait() function waits for events on the epoll instance referred to by the file descriptor epfd. The events argument is a pointer to an array of struct epoll_event; this array will contain the details of the events that occurred.

The maxevents argument specifies the maximum number of file descriptors for which events are to be collected. The value of this argument must be greater than zero.

The timeout argument specifies the number of milliseconds that epoll_wait() will block if there are no events. The behavior of epoll_wait() depends on the value of timeout:

  • If timeout is a positive integer, epoll_wait() will block for at most the specified number of milliseconds, and will return 0 if no event occurs within that time.
  • If timeout is zero, epoll_wait() will return immediately, whether there are events or not.
  • If timeout is -1, epoll_wait() will block indefinitely until there is at least one event.

The epoll_wait() function returns the number of file descriptors for which events were I/O-ready. This number will be between 0 and maxevents, inclusive.

If the return value is greater than 0, then the array events contains at least one event that occurred. The array will contain N struct epoll_event entries, where N is the return value of epoll_wait().

If the return value is 0, then the timeout expired. No file descriptors are ready.

If the return value is -1, an error occurred. The variable errno is set to indicate the error.

The struct epoll_event is defined as follows:

  •       typedef union epoll_data {
          void    *ptr;
          int      fd;
          uint32_t u32;
          uint64_t u64;
      } epoll_data_t;

      struct epoll_event {
          uint32_t     events;   /* Event flags */
          epoll_data_t data;     /* User data value */
      };

The events field is a bitmask indicating the event type. The possible event flags are:

  • EPOLLIN: The file descriptor is ready for read(2) operations.
  • EPOLLPRI: There is urgent data available for read(2) operations.
  • EPOLLOUT: The file descriptor is ready for write(2) operations.
  • EPOLLERR: Error condition happened on the associated file descriptor. epoll_wait(2) will always wait for this event; it is the caller's responsibility to detect and handle this event. In this case, the value of events will be EPOLLERR.
  • EPOLLHUP: Hang up happened on the associated file descriptor. epoll_wait(2) will always wait for this event; it is the caller's responsibility to detect and handle this event. In this case, the value of events will be EPOLLHUP.
  • EPOLLRDNORM: Ordinary condition on the file descriptor.
  • EPOLLWRNORM: Ordinary write condition on the file descriptor.
  • EPOLLRDBAND: Band data available for read(2) operations.
  • EPOLLWRBAND: Band write available for write(2) operations.

The data field is used to return user data associated with the file descriptor. This is the same value that was specified when the file descriptor was added to the epoll instance using epoll_ctl(2).

The events field can also include:

  • EPOLLET: Enable Edge Triggered behavior. This is the default behavior (Level Triggered). With Edge Triggered, epoll_wait(2) only returns events once. So if you don't read all data, you won't get notified again. With Level Triggered, epoll_wait(2) will keep returning events until you read all data.
  • EPOLLONESHOT: Enable one-shot mode. The caller must re-arm the file descriptor once an event is received.

RETURN VALUE

On success, epoll_wait() returns a non-negative integer representing the number of file descriptors ready to perform I/O. A return value of 0 means that the timeout expired.

On failure, epoll_wait() returns -1 and sets errno to indicate the error.

ERRORS

The epoll_wait() function may fail if:

  • EBADF: epfd is not a valid file descriptor.
  • EFAULT: The memory area pointed to by events or maxevents is not writable.
  • EINTR: The call was interrupted by a signal before any of the events occurred.
  • EINVAL: epfd is not an epoll file descriptor, or maxevents is less than or equal to 0.

STANDARDS

The epoll interface is Linux-specific.

HISTORY

The epoll interface was introduced in Linux kernel 2.5.44.

NOTES

Edge-Triggered vs. Level-Triggered

The epoll interface supports two styles of event notification: Edge-Triggered (ET) and Level-Triggered (LT). Level-Triggered is the default.

Level-Triggered (LT):

In this mode, epoll_wait() will report a file descriptor as ready as long as the condition for which it was registered is true. For example, if you register for EPOLLIN and the data is available in the buffer, epoll_wait() will return that the file descriptor is ready for reading. If you don't read all the data, epoll_wait() will continue to report the file descriptor as ready on subsequent calls.

Edge-Triggered (ET):

In this mode, epoll_wait() will report the file descriptor as ready only once, when the state of the file descriptor changes. For example, if you register for EPOLLIN and new data arrives, epoll_wait() will return that the file descriptor is ready for reading. If you don't read all the data, epoll_wait() will not return that the file descriptor is ready again until new data arrives. It is crucial to read or write the entire amount of data available (or until EAGAIN/EWOULDBLOCK is returned) to avoid missing events.

For edge-triggered I/O, it is recommended to use non-blocking file descriptors to avoid deadlocks. This is because if you call read() on a blocking file descriptor, and there is no data available, the call will block. If you were to do this in edge-triggered mode, you might block indefinitely, and since epoll_wait() only returns once per event, you would not get any further notifications.

EPOLLONESHOT:

When using EPOLLONESHOT, once an event is received for a file descriptor, that file descriptor is disabled for further epoll_wait() calls until the caller explicitly re-arms it by calling epoll_ctl(2) with EPOLL_CTL_MOD. This is useful in situations where you want to handle an event completely before receiving another event on the same file descriptor.

Return Value of 0:

A return value of 0 from epoll_wait() simply means that the timeout expired. It does not indicate an error. The application should not treat this as an error condition.

BUGS

None reported.
