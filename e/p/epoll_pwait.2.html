epoll_wait(2) Manual de Llamadas al Sistema epoll_wait(2)

NOMBRE

epoll_wait, epoll_pwait, epoll_pwait2 - esperar un evento de E/S en un descriptor de archivo epoll

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <sys/epoll.h>
int epoll_wait(int n;
               int epfd, struct epoll_event events[n], int n,
               int timeout);
int epoll_pwait(int n;
               int epfd, struct epoll_event events[n], int n,
               int timeout,
               const sigset_t *_Nullable sigmask);
int epoll_pwait2(int n;
               int epfd, struct epoll_event events[n], int n,
               const struct timespec *_Nullable timeout,
               const sigset_t *_Nullable sigmask);

DESCRIPCIÓN

La llamada al sistema epoll_wait() espera eventos en la instancia de epoll(7) referenciada por el descriptor de archivo epfd. El buffer apuntado por events se utiliza para devolver información de la lista de espera sobre descriptores de archivo en la lista de interés que tienen eventos disponibles. Se pueden devolver hasta n en epoll_wait(). El argumento n debe ser mayor que cero.

El argumento timeout especifica el número de milisegundos que epoll_wait() bloqueará. El tiempo se mide contra el reloj CLOCK_MONOTONIC.

Una llamada a epoll_wait() se bloqueará hasta que:

•
un descriptor de archivo entregue un evento;
•
la llamada sea interrumpida por un manejador de señales; o
•
el tiempo de espera expire.

Tenga en cuenta que el intervalo de timeout se redondeará al alza a la granularidad del reloj del sistema, y los retrasos de planificación del kernel implican que el intervalo de bloqueo puede excederse en una pequeña cantidad. Especificar un timeout de -1 hace que epoll_wait() se bloquee indefinidamente, mientras que especificar un timeout igual a cero hace que epoll_pwait() devuelva inmediatamente, incluso si no hay eventos disponibles.

La struct epoll_event se describe en epoll_event(3type).

El campo data de cada estructura epoll_event devuelta contiene los mismos datos que se especificaron en la llamada más reciente a epoll_ctl(2) (EPOLL_CTL_ADD, EPOLL_CTL_MOD) para el descriptor de archivo abierto correspondiente.

El campo events es una máscara de bits que indica los eventos que han ocurrido para la descripción de archivo abierta correspondiente. Consulte epoll_ctl(2) para ver una lista de los bits que pueden aparecer en esta máscara.

epoll_pwait()

La relación entre epoll_wait() y epoll_pwait() es análoga a la relación entre select(2) y pselect(2): al igual que pselect(2), epoll_pwait() permite a una aplicación esperar de forma segura hasta que un descriptor de archivo esté listo o hasta que se capture una señal.

La siguiente llamada a epoll_pwait():


ready = epoll_pwait(epfd, &events, n, timeout, &sigmask);

es equivalente a ejecutar *atmicamente* las siguientes llamadas:


sigset_t origmask;
pthread_sigmask(SIG_SETMASK, &sigmask, &origmask);
ready = epoll_wait(epfd, &events, n, timeout);
pthread_sigmask(SIG_SETMASK, &origmask, NULL);

El argumento sigmask puede especificarse como NULL, en cuyo caso epoll_pwait() es equivalente a epoll_wait().

epoll_pwait2()

La llamada al sistema epoll_pwait2() es equivalente a epoll_pwait() excepto por el argumento timeout. Toma un argumento de tipo timespec para poder especificar un tiempo de espera con resolución de nanosegundos. Este argumento funciona igual que en pselect(2) y ppoll(2). Si timeout es NULL, entonces epoll_pwait2() puede bloquearse indefinidamente.

VALOR DE RETORNO

En caso de éxito, epoll_wait() devuelve el número de descriptores de archivo listos para la operación de E/S solicitada, o cero si ningún descriptor de archivo se preparó durante los milisegundos de timeout solicitados. En caso de fallo, epoll_wait() devuelve -1 y errno se establece para indicar el error.

ERRORES

EBADF
epfd no es un descriptor de archivo válido.
EFAULT
El área de memoria apuntada por events no es accesible con permisos de escritura.
EINTR
La llamada fue interrumpida por un manejador de señales antes de que (1) ocurrieran alguno de los eventos solicitados o (2) expirara el timeout; véase signal(7).
EINVAL
epfd no es un descriptor de archivo de epoll, o n es menor o igual que cero.

ESTÁNDARES

Linux.

NOTAS

Mientras un hilo está bloqueado en una llamada a epoll_wait(), es posible que otro hilo agregue un descriptor de archivo a la instancia de epoll que se está esperando. Si el nuevo descriptor de archivo se prepara, hará que la llamada a epoll_wait() se desbloquee.

Si más de n descriptores de archivo están listos cuando se llama a epoll_wait(), entonces las llamadas sucesivas a epoll_wait() itinerarán a través del conjunto de descriptores de archivo listos. Este comportamiento ayuda a evitar escenarios de inanición, donde un proceso no se da cuenta de que descriptores de archivo adicionales están listos porque se centra en un conjunto de descriptores de archivo que ya se sabe que están listos.

Tenga en cuenta que es posible llamar a epoll_wait() en una instancia de epoll cuya lista de interés esté actualmente vacía (o cuya lista de interés se vacíe porque los descriptores de archivo se cierran o se eliminan del interés en otro hilo). La llamada se bloqueará hasta que algún descriptor de archivo se agregue más tarde a la lista de interés (en otro hilo) y ese descriptor de archivo se prepare.

Diferencias entre biblioteca C/kernel

Las llamadas al sistema brutas epoll_pwait() y epoll_pwait2() tienen un sexto argumento, size_t sigsetsize, que especifica el tamaño en bytes del argumento sigmask. La función wrapper epoll_pwait() de glibc especifica este argumento como un valor fijo (igual a sizeof(sigset_t)).

ERRORES CONOCIDOS

Antes de Linux 2.6.37, un valor de timeout mayor que aproximadamente LONG_MAX / HZ milisegundos se trata como -1 (es decir, infinito). Por lo tanto, por ejemplo, en un sistema donde sizeof(long) es 4 y el valor HZ del kernel es 1000, esto significa que los tiempos de espera mayores que 35.79 minutos se tratan como infinito.
