DESCRIPCIÓ

N

La llamada al sistema epoll_wait() espera a que se produzcan eventos en la instancia de epoll(7) a la que hace referencia el descriptor de archivo epfd. El búfer al que apunta events se utiliza para devolver información de la lista de listos sobre los descriptores de archivo de la lista de interés que tienen algunos eventos disponibles. Se devuelven hasta n por epoll_wait(). El argumento n debe ser mayor que

cero.

El argumento timeout especifica el número de milisegundos durante los que epoll_wait() se bloqueará. El tiempo se mide con respecto al reloj CLOCK_MONOTONIC

.

Una llamada a epoll_wait() se bloqueará hasta

que:
•
un descriptor de archivo entregue un
evento;
•
la llamada sea interrumpida por un manejador de señales;
o
•
expire el
tiempo d
e espera.

Tenga en cuenta que el intervalo de tiempo se redondeará hacia arriba a la granularidad del reloj del sistema, y los retrasos en la planificación del kernel significan que el intervalo de bloqueo puede excederse en una pequeña cantidad. Especificar un timeout de -1 hace que epoll_wait() se bloquee indefinidamente, mientras que especificar un timeout igual a cero hace que epoll_wait() devuelva inmediatamente, incluso si no hay eventos

disponibles.

La struct epoll_event se describe en epoll_event(3

type).

El campo data de cada estructura epoll_event devuelta contiene los mismos datos que se especificaron en la llamada más reciente a epoll_ctl(2) (EPOLL_CTL_ADD, EPOLL_CTL_MOD) para el descriptor de archivo abierto correspondiente

.

El campo events es una máscara de bits que indica los eventos que han ocurrido para la descripción de archivo abierta correspondiente. Vea epoll_ctl(2) para una lista de los bits que pueden aparecer en esta

máscara.

epoll_pwait(

)

La relación entre epoll_wait() y epoll_pwait() es análoga a la relación entre select(2) y pselect(2): como pselect(2), epoll_pwait() permite a una aplicación esperar de forma segura hasta que un descriptor de archivo esté listo o hasta que se capture una

señal.

La siguiente llamada a epoll_pwait()

: 


ready = epoll_pwait(epfd, &events, n, timeout, &sigmask)
;

es equivalente a ejecutar atómicamente las siguientes

llamadas: 


sigset_t origmask;
pthread_sigmask(SIG_SETMASK, &sigmask, &origmask);
ready = epoll_wait(epfd, &events, n, timeout);
pthread_sigmask(SIG_SETMASK, &origmask, NULL)
;

El argumento sigmask puede especificarse como NULL, en cuyo caso epoll_pwait() es equivalente a epoll_

wait
().

epoll_pwait2(

)

La llamada al sistema epoll_pwait2() es equivalente a epoll_pwait() excepto por el argumento timeout. Toma un argumento de tipo timespec para poder especificar un tiempo de espera con resolución de nanosegundos. Este argumento funciona igual que en pselect(2) y ppoll(2). Si timeout es NULL, entonces epoll_pwait2() puede

bloque
arse indefi
nidamente.

En caso de fallo, epoll_wait() devuelve -1 y errno se establece par

NOTA

S

Mientras un hilo está bloqueado en una llamada a epoll_wait(), es posible que otro hilo añada un descriptor de archivo a la instancia epoll sobre la que se está esperando. Si el nuevo descriptor de archivo se pone en estado listo, hará que la llamada a epoll_wait() se

desbloquee.

Si hay más de n descriptores de archivo listos cuando se llama a epoll_wait(), entonces las llamadas sucesivas a epoll_wait() pasarán en modo round robin por el conjunto de descriptores de archivo listos. Este comportamiento ayuda a evitar escenarios de inanición, donde un proceso no logra notar que hay descriptores de archivo adicionales listos porque se centra en un conjunto de descriptores de archivo que ya se sabe que están

listos.

Tenga en cuenta que es posible llamar a epoll_wait() sobre una instancia de epoll cuya lista de interés está actualmente vacía (o cuya lista de interés se vuelve vacía porque los descriptores de archivo se cierran o se eliminan del interés en otro hilo). La llamada se bloqueará hasta que se añada algún descriptor de archivo más adelante a la lista de interés (en otro hilo) y ese descriptor de archivo se ponga en estado

listo.

kernel
