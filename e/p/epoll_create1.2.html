epoll_create(2) Manual de llamadas al sistema epoll_create(2)

NOMBRE

epoll_create, epoll_create1 - abrir un descriptor de archivo epoll

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <sys/epoll.h>
int epoll_create(int size);
int epoll_create1(int flags);

DESCRIPCIÓN

epoll_create() crea una nueva instancia de epoll(7). Desde Linux 2.6.8, el argumento size se ignora, pero debe ser mayor que cero; véase HISTORIA.

epoll_create() devuelve un descriptor de archivo que se refiere a la nueva instancia de epoll. Este descriptor de archivo se utiliza para todas las llamadas posteriores a la interfaz epoll. Cuando ya no sea necesario, el descriptor de archivo devuelto por epoll_create() debe cerrarse usando close(2). Cuando todos los descriptores de archivo que se refieren a una instancia de epoll se hayan cerrado, el kernel destruirá la instancia y liberará los recursos asociados para su reutilización.

epoll_create1()

Si flags es 0, entonces, aparte del hecho de que el argumento obsoleto size se elimina, epoll_create1() es lo mismo que epoll_create(). El siguiente valor puede incluirse en flags para obtener un comportamiento diferente:

EPOLL_CLOEXEC
Establece la marca de cierre al ejecutar (FD_CLOEXEC) en el nuevo descriptor de archivo. Consulte la descripción de la marca O_CLOEXEC en open(2) para conocer las razones por las que esto puede ser útil.

VALOR DE RETORNO

En caso de éxito, estas llamadas al sistema devuelven un descriptor de archivo (un entero no negativo). En caso de error, se devuelve -1 y se establece errno para indicar el error.

ERRORES

EINVAL
size no es positivo.
EINVAL
(epoll_create1()) Valor inválido especificado en flags.
EMFILE
Se ha alcanzado el límite por proceso en el número de descriptores de archivo abiertos.
ENFILE
Se ha alcanzado el límite a nivel de sistema del número total de archivos abiertos.
ENOMEM
No había suficiente memoria para crear el objeto del kernel.

ESTÁNDARES

Linux.

HISTORIA

epoll_create()
Linux 2.6, glibc 2.3.2.
epoll_create1()
Linux 2.6.27, glibc 2.9.

En la implementación inicial de epoll_create(), el argumento size informaba al kernel del número de descriptores de archivo que el llamante esperaba añadir a la instancia de epoll. El kernel utilizaba esta información como una pista para la cantidad de espacio a asignar inicialmente en las estructuras de datos internas que describían los eventos. (Si era necesario, el kernel asignaba más espacio si el uso del llamante superaba la pista dada en size). Hoy en día, esta pista ya no es necesaria (el kernel dimensiona dinámicamente las estructuras de datos requeridas sin necesidad de la pista), pero size aún debe ser mayor que cero, para garantizar la compatibilidad con versiones anteriores cuando las nuevas aplicaciones de epoll se ejecutan en kernels más antiguos.

Antes de Linux 2.6.29, un parámetro del kernel /proc/sys/fs/epoll/max_user_instances limitaba los epolls activos por cada ID de usuario real, y hacía que epoll_create() fallara con EMFILE en caso de desbordamiento.

VER TAMBIÉN

close(2), epoll_ctl(2), epoll_wait(2), ioctl_eventpoll(2), epoll(7)
