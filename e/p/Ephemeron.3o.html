Ephemerons y tablas hash débiles.

Los ephemerons y las tablas hash débiles son útiles cuando se desea almacenar en caché o memorizar el cálculo de una función, siempre que los argumentos y la función se utilicen, sin crear fugas de memoria manteniendo continuamente resultados de cálculos antiguos que ya no son útiles porque un argumento o la función se liberan. Una implementación que utiliza Hashtbl.t no es adecuada porque todas las asociaciones mantendrían los argumentos y el resultado en memoria.

Los ephemerons también se pueden usar para "añadir" un campo a un valor OCaml arbitrario con caja: puede adjuntar información a un valor creado por una biblioteca externa sin fugas de memoria.

Los ephemerons contienen algunas claves y cero o un dato. Todos son valores OCaml con caja. Las claves de un ephemeron tienen el mismo comportamiento que los punteros débiles según el recolector de basura. De hecho, los punteros débiles de OCaml se implementan como ephemerons sin datos.

Las claves y los datos de un ephemeron se consideran completos si apuntan a un valor, o vacíos si el valor nunca se estableció, se desestableció o fue borrado por la GC. En la función que accede a las claves o a los datos, estos dos estados se representan mediante el tipo option.

Los datos se consideran vivos por el recolector de basura si todas las claves completas están vivas y si el ephemeron está vivo. Cuando una de las claves ya no se considera viva por la GC, los datos se vacían del ephemeron. Los datos podrían estar vivos por otra razón y, en ese caso, la GC no los liberará, pero el ephemeron ya no contendrá los datos.

Los ephemerons complican la noción de vivacidad de los valores, porque ya no es una equivalencia con la alcanzabilidad desde el valor raíz mediante punteros habituales (no débiles y no ephemerons). Con los ephemerons, la noción de vivacidad se construye mediante el punto fijo más pequeño de: Un valor está vivo si:

-es un valor raíz

-es alcanzable desde un valor vivo mediante punteros habituales

-es el dato de un ephemeron vivo con todas sus claves completas vivas

Notas:

-Todos los tipos definidos en este módulo no se pueden serializar usando output_value o las funciones del módulo Marshal.

Los ephemerons se definen de una manera agnóstica al lenguaje en este artículo: B. Hayes, Ephemerons: A New Finalization Mechanism, OOPSLA'97

Desde 4.03

Advertencia unsynchronized_access. Los accesos no sincronizados a tablas hash débiles son un error de programación.

Accesos no sincronizados

Los accesos no sincronizados a una tabla hash débil pueden dar lugar a un estado inválido de la tabla hash débil. Por lo tanto, los accesos concurrentes a una tabla hash débil deben sincronizarse (por ejemplo, con un Mutex.t).

module type S = sig end

La firma de salida de los functores Ephemeron.K1.Make y Ephemeron.K2.Make. Estas tablas hash son débiles en las claves. Si todas las claves de una asociación están vivas, la asociación se mantiene, pero si una de las claves de la asociación está muerta, entonces la asociación se elimina.

module type SeededS = sig end

La firma de salida de los functores Ephemeron.K1.MakeSeeded y Ephemeron.K2.MakeSeeded.

module K1 : sig end

Ephemerons con una clave.

module K2 : sig end

Ephemerons con dos claves.

module Kn : sig end

Ephemerons con un número arbitrario de claves del mismo tipo.
