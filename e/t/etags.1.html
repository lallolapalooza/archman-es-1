NOMBRE

etags, ctags - genera un archivo de etiquetas para Emacs, vi

SINOPSIS

etags [-aCDGIQRVh] [-i archivo] [-l lenguaje]
[-o archivo_de_etiquetas] [-r expresión_regular] [--parse-stdin=archivo]
[--append] [--no-defines] [--globals] [--no-globals] [--no-line-directive] [--include=archivo] [--ignore-indentation] [--language=lenguaje] [--members] [--no-members] [--output=archivo_de_etiquetas] [--class-qualify] [--regex=expresión_regular] [--no-regex] [--help] [--version] archivo ...

ctags [-aCdgIQRVh] [-BtTuvwx] [-l lenguaje]
[-o archivo_de_etiquetas] [-r expresión_regular] [--parse-stdin=archivo]
[--append] [--backward-search] [--cxref] [--no-defines] [--globals] [--no-globals] [--no-line-directive] [--ignore-indentation] [--language=lenguaje] [--members] [--no-members] [--class-qualify] [--output=archivo_de_etiquetas] [--regex=expresión_regular] [--update] [--help] [--version] archivo ...

DESCRIPCIÓN

El programa etags se utiliza para crear un archivo de tabla de etiquetas, en un formato entendido por emacs(1); el programa ctags se utiliza para crear una tabla similar en un formato entendido por vi(1). Ambas formas del programa entienden la sintaxis de C, Objective C, C++, Java, Fortran, Ada, Cobol, Erlang, Forth, Go, HTML, LaTeX, Emacs Lisp/Common Lisp, Lua, Makefile, Mercury, Pascal, Perl, Ruby, Rust, PHP, PostScript, Python, Prolog, Scheme y la mayoría de las sintaxis parecidas al ensamblador. Ambas formas leen los archivos especificados en la línea de comandos y escriben una tabla de etiquetas (por defecto: TAGS para etags, tags para ctags) en el directorio de trabajo actual. Los archivos especificados con nombres de archivo relativos se registrarán en la tabla de etiquetas con nombres de archivo relativos al directorio donde se encuentra la tabla de etiquetas. Sin embargo, si la tabla de etiquetas está en /dev o es la salida estándar, los nombres de archivo se harán relativos al directorio de trabajo. Los archivos especificados con nombres de archivo absolutos se registrarán con nombres de archivo absolutos. Los archivos generados a partir de un archivo fuente, como un archivo C generado a partir de un archivo fuente Cweb, se registrarán con el nombre del archivo fuente. Se admiten archivos comprimidos usando gzip, bzip2, xz y zstd. Los programas reconocen el lenguaje utilizado en un archivo de entrada basándose en su nombre de archivo y contenido. El --language se puede usar para forzar el análisis de los nombres de archivos que siguen al interruptor según el lenguaje dado, anulando las suposiciones basadas en las extensiones de nombre de archivo.

OPCIONES

Algunas opciones solo tienen sentido para los archivos de etiquetas de estilo vi producidos por ctags; etags no las reconoce. Los programas aceptan abreviaturas no ambiguas para los nombres de opciones largas.

-a, --append
Añadir al archivo de etiquetas existente. (Para los archivos de etiquetas de formato vi, véase también --update.)
-B, --backward-search
Los archivos de etiquetas escritos en el formato esperado por vi contienen instrucciones de búsqueda de expresiones regulares; la opción -B las escribe usando el delimitador "?", para buscar hacia atrás en los archivos. Por defecto se usa el delimitador "/", para buscar hacia adelante en los archivos. Solo ctags acepta esta opción.
--declarations
En C y lenguajes derivados, crea etiquetas para declaraciones de funciones, y crea etiquetas para variables externas a menos que se use --no-globals. En Lisp, crea etiquetas para declaraciones (defvar foo). En Mercury, las declaraciones comienzan una línea con ":-" y siempre se etiquetan. Además, esta opción etiqueta predicados o funciones en las primeras reglas de cláusulas, como en Prolog.
-D, --no-defines
No crear entradas de etiquetas para definiciones de constantes del preprocesador de C y constantes de enum. Esto puede hacer que el archivo de etiquetas sea mucho más pequeño si se etiquetan muchos archivos de cabecera.
--globals
Crear entradas de etiquetas para variables globales en Perl y Makefile. Este es el comportamiento por defecto en C y lenguajes derivados.
--no-globals
No etiquetar variables globales en C y lenguajes derivados. Normalmente esto reduce el tamaño del archivo en una cuarta parte.
--no-line-directive
Ignorar #line directivas del preprocesador en C y lenguajes derivados. Por defecto se respetan esas directivas, y se registran las etiquetas como si el archivo escaneado fuera el nombrado en la #line directiva. Este interruptor es útil cuando el archivo original nombrado por #line ya no está disponible.
-i archivo, --include=archivo
Incluir una nota en el archivo de etiquetas indicando que, al buscar una etiqueta, también se debe consultar el archivo de etiquetas archivo después de comprobar el archivo actual. Solo etags acepta esta opción.
-I, --ignore-indentation
No confiar en la indentación tanto como normalmente lo hacemos. Actualmente, esto significa no asumir que una llave de cierre en la primera columna es la llave final de una definición de función o estructura en C y C++. Esto es importante para código que no observa las convenciones de codificación GNU de colocar solo llaves de nivel superior en la columna cero.
-l lenguaje, --language=lenguaje
Analizar los archivos siguientes según el lenguaje dado. Se pueden intercalar más de una de estas opciones con los nombres de archivo. Usa --help para obtener una lista de los lenguajes disponibles y sus extensiones de nombre de archivo por defecto. Por ejemplo, como Mercury y Objective-C tienen la misma extensión de nombre de archivo .m, una prueba basada en el contenido intenta detectar el lenguaje. Si esta prueba falla, se debe usar --language=mercury o --language=objc . El lenguaje "auto" se puede usar para restaurar la detección automática del lenguaje basándose en el nombre de archivo. El lenguaje "none" se puede usar para deshabilitar el análisis de lenguaje por completo; en este caso solo se hace coincidencia de expresiones regulares (véase la --regex opción).
--members
Crear entradas de etiquetas para variables que son miembros de constructos similares a estructuras en PHP. Este es el comportamiento por defecto para C y lenguajes derivados.
--no-members
No etiquetar variables miembro.
--packages-only
Solo etiquetar paquetes en archivos Ada.
--parse-stdin=archivo
Puede usarse (solo una vez) en lugar de un nombre de archivo en la línea de comandos. etags leerá de la entrada estándar y marcará las etiquetas producidas como pertenecientes al archivo FILE.
-Q, --class-qualify
Calificar los nombres de etiquetas con su nombre de clase en C++, ObjC, Java y Perl. Esto produce nombres de etiquetas de la forma class::member para C++ y Perl, class(category) para Objective C, y class.member para Java. Para Objective C, esto también produce métodos de clase calificados con sus argumentos, como en foo:bar:baz:more.
-o archivo_de_etiquetas, --output=archivo_de_etiquetas
Nombre explícito del archivo para la tabla de etiquetas; solo para etags , un nombre de archivo de - significa salida estándar; anula el TAGS o tagspor defecto. (Pero se ignora con -v o -x.)
-r expresión_regular, --regex=expresión_regular

Crear etiquetas basadas en la coincidencia de expresiones regulares para los archivos que siguen a esta opción, además de las etiquetas hechas con el análisis estándar basado en el lenguaje. Se pueden intercalar libremente con nombres de archivo y la opción -R . Las expresiones regulares son acumulativas, es decir, cada opción de este tipo añadirá a las anteriores. Las expresiones regulares son de una de las formas:
[{lenguaje}]/tagregexp/[nameregexp/]modificadores
@archivo_de_expresiones_regulares

donde tagregexp se usa para hacer coincidir la etiqueta. No debería hacer coincidir caracteres inútiles. Si la coincidencia es tal que se hacen coincidir inevitablemente más caracteres de los necesarios por tagregexp, puede ser útil añadir un nameregexp, para acotar el alcance de la etiqueta. ctags etags(1) — Arch manual pages

NAME

etags, ctags - create tags files for classes, functions, variables, etc.

SYNOPSIS

etags [OPTION...] [FILE...]

ctags [OPTION...] [FILE...]

DESCRIPTION

This program generates an index file (called a tags file) for classes, functions, variables, and other items of interest in a source code file, used by text editors such as Emacs and Vim to quickly locate the definitions of these items. The index file is named tags by default, and it is created in the current directory.

The program automatically detects the language of the files and creates tags suitable for that language. You can override the default language detection using the --language option.

The tag entries generated are language-dependent. For example, for C and C++, it tags functions, macros, typedefs, enums, struct/union members, and class members. For Lisp, it tags functions and macros. For shell scripts, it tags functions.

The supported languages include C, C++, Objective-C, Java, Fortran, Fortran 77, Ada, COBOL, Scheme, Emacs Lisp, and shell scripts. Support for other languages may be available via the --regex option.

OPTIONS

-a, --append
Append the tags for the current files to the existing tags file, rather than replacing it.
-B
Search backwards for tags.
-c, --cxref
Generate a cross-reference file in cxref format instead of a tags file. Only ctags accepts this option.
-d, --distant
Add tags for distant scope.
-e, --emacs
Create an emacs-style tags file (default).
-f FILE, --file=FILE
Use the specified file as the tags file. The default is tags.
-F, --forward
Search forward for tags.
-g, --globals
Tag only global variables.
-h, -H, --help
Print usage information. Followed by one or more --language=LANG prints detailed information about how tags are created for LANG.
-i, --ignore-indentation
Ignore indentation when searching for tags.
-l, --language=LANGUAGES
Specify the language or languages for which to create tags. The default is to detect the language automatically. You can specify multiple languages, separated by commas. Use --help=languages to list the supported languages.
-L FILE, --lib-tags=FILE
Prepend tags from FILE to the list of tags being generated. This is useful for including tags from standard libraries.
-m, --members
Tag members of classes.
-O
Put the tags file in the object directory.
-P
Prepend the object directory to the file names.
-R, --no-regex
Don't do any more regexp matching on the following files. May be freely intermixed with filenames and the --regex option.
-s, --c-signatures
Try to extract C function signatures.
--tables
Generate tags for tables.
-V, --version
Print the current version of the program (same as the version of the emacs etags is shipped with).
-v, --vgrind
Instead of generating a tag file, write index (in vgrind format) to standard output. Only ctags accepts this option.
-x, --cxref
Instead of generating a tag file, write a cross reference (in cxref format) to standard output. Only ctags accepts this option.
--code-roots=ROOTS
Comma-separated list of language keywords that define the root of a code block. Default: 'package,subroutine,function,typedef,class,define'.
--default-excludes=VAL
Set to 0 to disable default file exclusion patterns.
--help=LANGUAGES
Print a list of supported languages and exit.
--local-tags
Add the tags for the current files to the current tags file, rather than creating a new tags file.
--regex=REGEX
Add a regular expression for finding tags. The format of the regular expression is: 
    /tagregexp/nameregexp/modifiers/
where tagregexp is a regular expression that matches the tag definition line, and nameregexp is a regular expression that extracts the tag name from the matched line. The tagregexp must match the whole line from the beginning of the file or from the beginning of the line. The nameregexp is used to extract the tag name from the matched tagregexp. The tag name is the part of the matched string that is captured by the first \(...\) group in nameregexp. If nameregexp is omitted, the entire matched string is used as the tag name.

Regular expressions are the same as in Emacs, except that backslash escapes are the same as GNU grep (which means, for example, that shy groups are not supported), and [:ascii:], [:multibyte:], [:nonascii:], [:word:], and [:unibyte:] are not supported. The following character escape sequences are supported: \a, \b, \d, \e, \f, \n, \r, \t, \v, which respectively stand for the ASCII characters BEL, BS, DEL, ESC, FF, NL, CR, TAB, VT.

The modifiers are a sequence of 0 or more characters among i, which means to ignore case when matching; m, which means that the tagregexp will be matched against the whole file contents at once, rather than line by line, and the matching sequence can match multiple lines; and s, which implies m and means that the dot character in tagregexp matches the newline char as well.

The separator, which is / in the examples, can be any character different from space, tab, braces and @. If the separator character is needed inside the regular expression, it must be quoted by preceding it with \.

The optional {language} prefix means that the tag should be created only for files of language language, and ignored otherwise. This is particularly useful when storing many predefined regexps in a file.

In its second form, regexfile is the name of a file that contains a number of arguments to the --regex= option, one per line. Lines beginning with a space or tab are assumed to be comments, and ignored.

Here are some examples. All the regexps are quoted to protect them from shell interpretation.

Tag the DEFVAR macros in the emacs source files:
--regex='/[ \t]*DEFVAR_[A-Z_ \t(]+"\([^"]+\)"/'

Tag VHDL files (this example is a single long line, broken here for formatting reasons):
--language=none --regex='/[ \t]*\(ARCHITECTURE\|\ CONFIGURATION\) +[^ ]* +OF/' --regex='/[ \t]*\ \(ATTRIBUTE\|ENTITY\|FUNCTION\|PACKAGE\( BODY\)?\ \|PROCEDURE\|PROCESS\|TYPE\)[ \t]+\([^ \t(]+\)/\3/'

Tag Tcl files (this last example shows the usage of a tagregexp):
--lang=none --regex='/proc[ \t]+\([^ \t]+\)/\1/'

A regexp can be preceded by {lang}, thus restricting it to match lines of files of the specified language. Use etags --help to obtain a list of the recognized languages. This feature is particularly useful inside regex files. A regex file contains one regex per line. Empty lines, and those lines beginning with space or tab are ignored. Lines beginning with @ are references to regex files whose name follows the @ sign. Other lines are considered regular expressions like those following --regex.
For example, the command
etags --regex=@regex.file *.c
reads the regexes contained in the file regex.file.

-R, --no-regex
Don't do any more regexp matching on the following files. May be freely intermixed with filenames and the --regex option.
-u, --update
Update tag entries for files specified on command line, leaving tag entries for other files in place. Currently, this is implemented by deleting the existing entries for the given files and then rewriting the new entries at the end of the tags file. It is often faster to simply rebuild the entire tag file than to use this. Only ctags accepts this option.
-v, --vgrind
Instead of generating a tag file, write index (in vgrind format) to standard output. Only ctags accepts this option.
-x, --cxref
Instead of generating a tag file, write a cross reference (in cxref format) to standard output. Only ctags accepts this option.
-h, -H, --help
Print usage information. Followed by one or more --language=LANG prints detailed information about how tags are created for LANG.
-V, --version
Print the current version of the program (same as the version of the emacs etags is shipped with).
