ETTERFILTER(8) Manual del administrador del sistema ETTERFILTER(8)

NOMBRE

etterfilter - Compilador de filtros para el motor de filtrado de contenido de ettercap

SINOPSIS

etterfilter [OPCIONES] ARCHIVO

DESCRIPCIÓN

La utilidad etterfilter se utiliza para compilar archivos fuente de filtros en archivos binarios de filtros que pueden ser interpretados por el intérprete JIT en el motor de filtros de ettercap(8). Tienes que compilar tus scripts de filtro para poder usarlos en ettercap. Todos los errores de sintaxis/análisis se verificarán en el momento de la compilación, por lo que estarás seguro de producir un filtro binario correcto para ettercap.

OPCIONES GENERALES
-o, --output <ARCHIVO>
Puedes especificar el archivo de salida para un archivo fuente de filtro. Por defecto, la salida es filter.ef.
-t, --test <ARCHIVO>
Puedes analizar un archivo de filtro compilado con esta opción. etterfilter imprimirá de forma legible para humanos todas las instrucciones que contiene. Es una especie de "desensamblador" para archivos de filtro binarios.
-d, --debug
Imprime algunos mensajes de depuración durante la compilación. Úsalo más de una vez para aumentar el nivel de depuración (etterfilter -ddd ...).
-w, --suppress-warnings
No salir en caso de advertencias. Con esta opción, el compilador compilará el script incluso si contiene advertencias.
OPCIONES ESTÁNDAR
-v, --version
Imprime la versión y sale.
-h, --help
Imprime la pantalla de ayuda con un resumen de las opciones disponibles.
SINTAXIS DE LOS SCRIPTS
Un script es un compuesto de instrucciones. Se ejecuta secuencialmente y puedes hacer ramas con las sentencias 'if'. Las sentencias 'if' y 'if/else' son las únicas soportadas. No hay bucles implementados. La sintaxis es casi como código C, excepto que debes poner los bloques 'if' entre llaves '{' '}', incluso si solo contienen una instrucción.

NOTA: debes poner un espacio entre 'if' y '('. No debes poner el espacio entre el nombre de la función y el '('.

Ejemplo:
if (condiciones) { }
func(args...);

Las condiciones para una sentencia 'if' pueden ser funciones o comparaciones. Se pueden enlazar dos o más condiciones con operadores lógicos como OR '||' y AND '&&'.

Ejemplo:
if (tcp.src == 21 && search(DATA.data, "ettercap")) {
}

Presta atención a la precedencia de los operadores. No puedes usar paréntesis para agrupar condiciones, así que ten cuidado con el orden. Un AND al principio de un bloque de condiciones excluirá todas las demás pruebas si se evalúa como falso. El análisis se realiza de izquierda a derecha, cuando se encuentra un operador: si es un AND y la condición anterior es falsa, toda la sentencia se evalúa como falsa; si es un OR, el análisis continúa incluso si la condición es falsa.

Ejemplo:
if (ip.proto == UDP || ip.proto == TCP && tcp.src == 80) {
}

if (ip.proto == TCP && tcp.src == 80 || ip.proto == UDP) {
}

la primera condición coincidirá con todo el tráfico UDP o HTTP. La segunda es incorrecta, porque si el paquete no es TCP, todo el bloque de condiciones se evaluará como falso. Si quieres hacer condiciones complejas, la mejor manera es dividirlas en bloques 'if' anidados.

Dado que etterfilter soporta ambas familias de direcciones IP, debes tener cuidado de si usas 'ip.proto', que es específico para la familia de direcciones IPv4, o su contraparte IPv6 'ipv6.nh'. Especialmente para la coincidencia de protocolos L4 usando 'ip.proto' y/o 'ipv6.nh', debes tener cuidado si realmente estás actuando sobre el protocolo correcto. Esto debería reforzarse usando el identificador de protocolo L3 'eth.proto'.

Ejemplo:
if (eth.proto == IP && ip.proto == TCP && tcp.dst == 80 || tcp.src == 80) {
}

if (eth.proto == IP6 && ipv6.nh == TCP && tcp.dst == 80 || tcp.src == 80) {
}

if (tcp.dst == 80 || tcp.src == 80) {
}

El primer ejemplo coincide correctamente con el tráfico HTTP solo en IPv4, mientras que el segundo coincidiría con el tráfico HTTP solo en IPv6. El tercer ejemplo coincide con HTTP independientemente de su familia de direcciones IP.

Cada instrucción en un bloque debe terminar con un punto y coma ';'.

Las comparaciones se implementan con el operador '==' y se pueden usar para comparar números, cadenas o direcciones IP. Una dirección IP DEBE estar entre dos comillas simples (ej. '192.168.0.7' o '2001:db8::2'). También puedes usar los operadores 'menor que' ('<'), 'mayor que' ('>'), 'menor o igual' ('<=') y 'mayor o igual' ('>='). El lvalue de una comparación debe ser un desplazamiento (ver más abajo).

Ejemplo:
if (DATA.data + 20 == "ettercap" && ip.ttl > 16) {
}

Las asignaciones se implementan con el operador '=' y el lvalue puede ser un desplazamiento (ver más abajo). El rvalue puede ser una cadena, un entero o un valor hexadecimal.

Ejemplo:
ip.ttl = 0xff;
DATA.data + 7 = "ettercap NG";

También puedes usar las operaciones 'inc' y 'dec' en los campos del paquete. Los operadores utilizados son '+=' y '-='. El rvalue puede ser un entero o un valor hexadecimal.

Ejemplo:
ip.ttl += 5;

Más ejemplos se pueden encontrar en el archivo etter.filter.examples.

DEFINICIÓN DE DESPLAZAMIENTO
Un desplazamiento se identifica por un puntero virtual. En pocas palabras, un desplazamiento es un puntero al búfer del paquete. El puntero virtual es una tupla <L, O, S>, donde L es el nivel iso/osi, O es el desplazamiento en ese nivel y S es el tamaño del puntero virtual. Puedes realizar operaciones algebraicas en un puntero virtual y el resultado sigue siendo un desplazamiento. Especificar 'vp + n' resultará en un nuevo puntero virtual <L, O+n, S>. Y esto es perfectamente legal, hemos cambiado el desplazamiento interno de ese nivel.

Los punteros virtuales tienen el formato 'nombre.campo.subcampo'. Por ejemplo, 'ip.ttl' es el puntero virtual para el campo Time To Live en la cabecera IP de un paquete. Se traducirá como <L=3, O=9, S=1>. De hecho, es el noveno byte del nivel 3 y su tamaño es de 1 byte. 'ip.ttl + 1' es lo mismo que 'ip.proto', ya que el décimo byte de la cabecera IP es el protocolo encapsulado en el paquete IP. Ten en cuenta que, dado que etterfilter también admite el procesamiento de IPv6, lo anterior solo se aplica a paquetes IPv4, mientras que su contraparte en IPv6 sería 'ipv6.nh'.

La lista de todos los punteros virtuales compatibles se encuentra en el archivo etterfilter.tbl. Puedes añadir tus propios punteros virtuales añadiendo una nueva tabla o modificando las existentes. Consulta los comentarios al principio del archivo para ver la sintaxis del archivo etterfilter.tbl.

FUNCIONES DE LOS SCRIPTS
search(donde, qué)
esta función busca la cadena 'qué' en el búfer 'dónde'. El búfer puede ser DATA.data o DECODED.data. El primero es la carga útil en el nivel DATA (encima de TCP o UDP) tal como se transmite por el cable, el segundo es la carga útil decodificada/descifrada por los disectores.
Por lo tanto, si quieres buscar en una conexión SSH, es mejor usar 'DECODED.data' ya que 'data' estará cifrada.
La cadena 'qué' puede ser binaria. Debes escaparla.

ejemplo:
search(DATA.data, "\x41\x42\x43")

regex(donde, regex)
esta función devolverá verdadero si la 'regex' ha coincidido con el búfer 'dónde'. Las consideraciones sobre 'DECODED.data' y 'DATA.data' mencionadas para la función 'search' son las mismas para la función regex.

NOTA: regex solo se puede usar contra un búfer de cadena.

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

ejemplo:
regex(DECODED.data, ".*login.*")

pcre_regex(donde, pcre_regex ... )
esta función evaluará una expresión regular compatible con Perl. Puede coincidir tanto con DATA como con DECODED, pero si su expresión modifica el búfer, tiene sentido operar solo con DATA. La función acepta 2 o 3 parámetros dependiendo de la operación que desee realizar. La forma de dos parámetros se usa solo para coincidir con un patrón. La forma de tres parámetros significa que desea realizar una sustitución. En ambos casos, el segundo parámetro es la cadena de búsqueda.
Puede usar $n en la cadena de reemplazo. Estos marcadores de posición se refieren a los grupos creados en la cadena de búsqueda. (por ejemplo, pcre_regex(DATA.data, "^var1=([:digit:]*)&var2=([:digit:]*)", "var1=$2&var2=$1") intercambiará el valor de var1 y var2).
NOTA: El soporte de pcre es opcional en ettercap y solo se habilitará si tiene instalada la libpcre. El compilador le advertirá si intenta compilar un filtro que contiene expresiones pcre pero no tiene libpcre. Use la opción -w para suprimir la advertencia.

ejemplo:
pcre_regex(DATA.data, ".*foo$")
pcre_regex(DATA.data, "([^ ]*) bar ([^ ]*)", "foo $1 $2")

replace(qué, con)
esta función reemplaza la cadena 'what' con la cadena 'with'. Pueden ser cadenas binarias y deben escaparse. El reemplazo siempre se realiza en DATA.data ya que es la única carga útil que se reenvía. El búfer 'DECODED.data' se usa solo internamente y nunca llega a la red.

ejemplo:
replace("ethercap", "ettercap")

inject(qué)
esta función inyecta el contenido del archivo 'what' después del paquete siendo procesado. Siempre inyecta en DATA.data. Puede usarla para reemplazar el paquete completo con uno falso usando la función drop() justo antes del comando inject(). En ese caso, el motor de filtrado descartará el paquete actual e inyectará el falso.

ejemplo:
inject("./fake_packet")

log(qué, dónde)
esta función vuelca en el archivo 'where' el búfer 'what'. No se almacena información sobre el paquete, solo se vuelca la carga útil. Por lo tanto, verá el flujo en el archivo. Si desea registrar paquetes de una manera más avanzada, necesita usar la opción -L de ettercap y analizarla con etterlog(8).
El archivo 'where' debe ser escribible para el usuario EC_UID (ver etter.conf(5)).

ejemplo:
log(DECODED.data, "/tmp/interesting.log")

msg(mensaje)
esta función muestra un mensaje al usuario en la ventana de Mensajes de Usuario. Es útil para informar al usuario si un filtro en particular ha sido exitoso o no.

ejemplo:
msg("Packet filtered successfully")

drop()
esta función marca el paquete "para ser descartado". El paquete no será reenviado al destino real.

ejemplo:
drop()

kill()
esta función termina la conexión que posee el paquete coincidente. Si es una conexión TCP, se envía un RST a ambos lados de la conexión. Si es una conexión UDP, se envía un ICMP PORT UNREACHABLE a la fuente del paquete.

ejemplo:
kill()

exec(comando)
esta función ejecuta un comando de shell. Debe proporcionar la ruta completa al comando ya que se ejecuta sin ningún entorno. No hay manera de determinar si el comando fue exitoso o no. Además, se ejecuta de forma asíncrona ya que se bifurca desde el proceso principal.

ejemplo:
exec("/bin/cat /tmp/foo >> /tmp/bar")

execinject(comando)
esta función opera de manera similar a la función inyectar excepto que usa la salida de un comando de shell para inyectar datos en lugar del contenido de un archivo. Siempre inyecta en DATA.data. Puede usarla para reemplazar el paquete completo con uno falso usando la función drop() justo antes del comando execinject(). En ese caso, el motor de filtrado descartará el paquete actual e inyectará el falso.

ejemplo:
execinject("/bin/cat /tmp/foo")

execreplace(comando)
esta función opera de manera similar a la función reemplazar excepto que usa la salida de un comando de shell para reemplazar datos completos en lugar del contenido de un archivo. Otra diferencia es que el contenido original del paquete se pasa al comando de shell en stdin. Siempre inyecta en DATA.data. Puede usarla para reemplazar el paquete completo con uno falso dependiendo del original.

ejemplo:
execreplace("tr A-Z a-z")

exit()
esta función hace que el motor de filtrado deje de ejecutar el código. Es útil para detener la ejecución del script en alguna circunstancia verificada por una declaración 'if'.

ejemplo:
exit()
