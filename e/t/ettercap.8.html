ETTERCAP(8) Manual del Administrador del Sistema ETTERCAP(8)

NOMBRE

ettercap - sniffer/filtro de contenido multifuncional para ataques man-in-the-middle

***** NOTA IMPORTANTE ******

Desde ettercap NG (anteriormente 0.7.0), todas las opciones han cambiado. Incluso la especificación del objetivo ha cambiado. Por favor, lea detenidamente esta página del manual.

SINOPSIS

ettercap [OPCIONES] [OBJETIVO1] [OBJETIVO2]

Si IPv6 está habilitado:
OBJETIVO tiene el formato MAC/IPs/IPv6/PUERTOS
De lo contrario,
OBJETIVO tiene el formato MAC/IPs/PUERTOS
donde IPs y PUERTOS pueden ser rangos (por ejemplo, /192.168.0.1-30,40,50/20,22,25)

DESCRIPCIÓN

Ettercap nació como un sniffer para LAN conmutada (y obviamente también para las "hubbed"), pero durante el proceso de desarrollo ha ido ganando más y más características que lo han convertido en una herramienta potente y flexible para ataques man-in-the-middle. Soporta el análisis activo y pasivo de muchos protocolos (incluso cifrados) e incluye muchas funciones para el análisis de red y de hosts (como la huella digital del sistema operativo).

Tiene dos opciones principales de sniffing:

UNIFICADO, este método captura todos los paquetes que pasan por el cable. Puedes elegir poner o no la interfaz en modo promisc (-p opción). Los paquetes que no estén dirigidos al host que ejecuta ettercap serán reenviados automáticamente utilizando enrutamiento de capa 3. Así puedes usar un ataque mitm lanzado desde otra herramienta y dejar que ettercap modifique los paquetes y los reenvíe por ti.
El reenvío de IP del kernel es siempre deshabilitado por ettercap. Esto se hace para evitar que un paquete se reenvíe dos veces (una por ettercap y otra por el kernel). Esto es un comportamiento invasivo en los gateways. Por lo tanto, te recomendamos que uses ettercap en los gateways SÓLO CON EL MODO NO OFENSIVO HABILITADO. Dado que ettercap solo escucha en una interfaz de red, lanzarlo en el gateway en modo ofensivo no permitirá que los paquetes sean redirigidos de vuelta desde la segunda interfaz.

PUENTEADO, utiliza dos interfaces de red y reenvía el tráfico de una a otra mientras realiza sniffing y filtrado de contenido. Este método de sniffing es totalmente sigiloso ya que no hay forma de descubrir que alguien está en el medio del cable. Puedes considerar este método como un ataque mitm en la capa 1. Estarás en medio del cable entre dos entidades. No lo uses en gateways o transformará tu gateway en un bridge. PISTA: puedes usar el motor de filtrado de contenido para descartar paquetes que no deberían pasar. ¡¡De esta manera ettercap funcionará como un IPS en línea!!

También puedes realizar ataques man in the middle mientras usas el sniffing unificado. Puedes elegir el ataque mitm que prefieras. El módulo de ataque mitm es independiente del proceso de sniffing y filtrado, por lo que puedes lanzar varios ataques al mismo tiempo o usar tu propia herramienta para el ataque. El punto crucial es que los paquetes deben llegar a ettercap con la dirección MAC correcta y una dirección IP diferente (solo estos paquetes serán reenviados).

Las características más relevantes de ettercap son:

Soporte SSH1: puedes hacer sniffing de Usuario y Contraseña, e incluso de los datos de una conexión SSH1. ettercap es el primer software capaz de hacer sniffing de una conexión SSH en FULL DÚPLEX

Soporte SSL: puedes hacer sniffing de datos seguros SSL... se presenta un certificado falso al cliente y la sesión se descifra.

Inyección de caracteres en una conexión establecida: ¡¡puedes inyectar caracteres al servidor (emulando comandos) o al cliente (emulando respuestas) manteniendo la conexión viva!!

Filtrado/descarte de paquetes: Puedes configurar un script de filtro que busque una cadena particular (incluso en hexadecimal) en la carga útil TCP o UDP y la reemplace por la tuya o descarte el paquete completo. El motor de filtrado puede hacer coincidir cualquier campo de los protocolos de red y modificar lo que quieras (ver etterfilter(8)).

Sniffing de tráfico remoto a través de túneles y manipulación de rutas: Puedes jugar con interfaces linux "cooked" o usar el plugin integrado para hacer sniffing de conexiones remotas tunelizadas o manipuladas por ruta y realizar ataques mitm sobre ellas.

Soporte de plugins: Puedes crear tu propio plugin usando la API de ettercap.

Recolector de contraseñas para: TELNET, FTP, POP, RLOGIN, SSH1, ICQ, SMB, MySQL, HTTP, NNTP, X11, NAPSTER, IRC, RIP, BGP, SOCKS 5, IMAP 4, VNC, LDAP, NFS, SNMP, HALF LIFE, QUAKE 3, MSN, YMSG (otros protocolos próximamente...)

Huella digital pasiva del sistema operativo: escaneas pasivamente la LAN (sin enviar ningún paquete) y recopilas información detallada sobre los hosts en la LAN: Sistema Operativo, servicios en ejecución, puertos abiertos, dirección IP, dirección MAC y proveedor de la tarjeta de red.

Matar una conexión: desde la lista de conexiones puedes matar todas las conexiones que quieras

ESPECIFICACIÓN DEL OBJETIVO

No hay concepto de ORIGEN ni DESTINO. Los dos objetivos están destinados a filtrar el tráfico que viene de uno al otro y viceversa (ya que la conexión es bidireccional).

OBJETIVO tiene el formato MAC/IPs/PUERTOS.
NOTA: Si IPv6 está habilitado, OBJETIVO tiene el formato MAC/IPs/IPv6/PUERTOS.

Si quieres, puedes omitir cualquier parte y esto representará un CUALQUIERA en esa parte.
ej.
"//80" significa cualquier dirección MAC, cualquier IP y solo el puerto 80
"/10.0.0.1/" significa cualquier dirección MAC, solo la IP 10.0.0.1 y cualquier puerto

MAC debe ser única y tener el formato 00:11:22:33:44:55

IPs es un rango de IP en notación de puntos. Puedes especificar rangos con el - (guion) e IPs individuales con , (coma). También puedes usar ; (punto y coma) para indicar diferentes direcciones IP.
ej.
"10.0.0.1-5;10.0.1.33" se expande en las IP 10.0.0.1, 2, 3, 4, 5 y 10.0.1.33

PUERTOS es un rango de PUERTOS. Puedes especificar rangos con el - (guion) y puertos individuales con , (coma).
ej.
"20-25,80,110" se expande en los puertos 20, 21, 22, 23, 24, 25, 80 y 110

NOTA:
puedes invertir la coincidencia del OBJETIVO añadiendo la opción -R a la línea de comandos. Así que si quieres hacer sniffing de TODO el tráfico PERO el que viene o va a 10.0.0.1 puedes especificar "./ettercap -R /10.0.0.1/"

NOTA:
los OBJETIVOS también son responsables del escaneo inicial de la LAN. Puedes usarlos para restringir el escaneo solo a un subconjunto de hosts en la netmask. Se escaneará el resultado de la fusión entre los dos objetivos. Recuerda que no especificar un objetivo significa "ningún objetivo", pero especificar "//" significa "todos los hosts en la subred".

REDUCCIÓN DE PRIVILEGIOS

ettercap necesita privilegios de root para abrir los sockets de la Capa de Enlace. Después de la fase de inicialización, los privilegios de root ya no son necesarios, por lo que ettercap los reduce a UID = 65535 (nobody). Dado que ettercap tiene que escribir (crear) archivos de registro, debe ser ejecutado en un directorio con los permisos adecuados (por ejemplo, /tmp/). Si deseas reducir los privilegios a un uid diferente, puedes exportar la variable de entorno EC_UID con el valor del uid al que quieres reducir los privilegios (por ejemplo, export EC_UID=500) o establecer el parámetro correcto en el archivo etter.conf.

ATAQUE SSL MITM

El ataque SSL mitm depende de la redirección del tráfico TCP a un puerto de escucha personalizado de ettercap. Las variables de configuración redir_command_on y redir_command_off se encargan de esto (ver "etter.conf(5)").
Sin embargo, cuando ettercap se inicia, el tráfico de cualquier origen y cualquier destino dirigido a los servicios redirigibles será redirigido a ettercap y el flujo SSL será interceptado.
Es posible que este no sea el comportamiento deseado. Por lo tanto, puedes ajustar las reglas de redirección después de que ettercap se haya iniciado utilizando la interfaz de usuario seleccionada.

Mientras realiza el ataque SSL mitm, ettercap sustituye el certificado SSL real por el suyo propio. El certificado falso se crea sobre la marcha y todos los campos se rellenan según el certificado real presentado por el servidor. Solo el emisor se modifica y se firma con la clave privada contenida en el archivo 'etter.ssl.crt'. Si deseas usar una clave privada diferente, tienes que regenerar este archivo. Para regenerar el archivo de certificado, usa los siguientes comandos:

openssl genrsa -out etter.ssl.crt 1024
openssl req -new -key etter.ssl.crt -out tmp.csr
openssl x509 -req -days 1825 -in tmp.csr -signkey etter.ssl.crt -out tmp.new
cat tmp.new >> etter.ssl.crt
rm -f tmp.new tmp.

OPCIONES DE SNIFFING Y
ATAQUE

ettercap NG tiene un nuevo método de sniffing unificado. Esto implica que ip_forwarding en el kernel está siempre deshabilitado y el reenvío lo realiza ettercap. Cada paquete con dirección mac de destino igual a la mac del host y dirección ip de destino diferente a la asignada a la interfaz será reenviado por ettercap. Antes de reenviarlos, ettercap puede filtrar el contenido, capturar, registrar o descartar. No importa cómo se secuestren estos paquetes, ettercap los procesará. Puede incluso usar programas externos para secuestrar paquetes.
Tiene control total sobre lo que ettercap debe recibir. Puede usar los ataques mitm internos, poner la interfaz en modo promiscuo, usar complementos o usar cualquier método que

desee.

NOTA IMPORTANTE: si ejecuta ettercap en una puerta de enlace, recuerde volver a habilitar el ip_forwarding después de haber terminado con ettercap. Dado que ettercap renuncia a sus privilegios, no puede restaurar el ip_forwarding por

usted.

Este método implementa el ataque mitm de envenenamiento ARP. Se envían solicitudes/respuestas ARP a las víctimas para envenenar su caché ARP. Una vez que la caché ha sido envenenada, las víctimas enviarán todos los paquetes al atacante que, a su vez, puede modificarlos y reenviarlos al destino real.

Este ataque implementa el spoofing DHCP. Finge ser un servidor DHCP y intenta ganar la condición de carrera con el real para forzar al cliente a aceptar la respuesta del atacante. De esta manera ettercap es capaz de manipular el parámetro GW y secuestrar todo el tráfico saliente generado por los clientes.
El ataque resultante es un mitm SEMIDÚPLEX. Así que asegúrese de usar filtros apropiados (ver arriba en la sección ICMP).

Debe pasar el rango de ip a usar, la máscara de red y la ip del servidor dns. Dado que ettercap intenta ganar la carrera con el servidor real, NO VERIFICA si la ip ya está asignada. Debe especificar un rango de ip de direcciones LIBRES para usar. El rango de ip tiene la misma forma que la especificación de

objetivo.

Si el cliente envía una solicitud dhcp (sugiriendo una dirección ip) ettercap responderá con ack a esa ip y modificará solo la opción gw. Si el cliente hace un descubrimiento dhcp, ettercap usará la primera dirección ip no usada de la lista que haya especificado en la línea de comandos. Cada descubrimiento consume una dirección ip. Cuando la lista se agote, ettercap dejará de ofrecer nuevas direcciones ip y responderá solo a solicitudes dhcp.
Si no desea ofrecer ninguna dirección ip, sino solo cambiar la información del enrutador de la solicitud/ack dhcp, puede especificar un ip_pool

vacío.

GRAN ADVERTENCIA: si especifica una lista de ip que están en uso, arruinará su red! En general, use este ataque con cuidado. ¡Puede arruinar las cosas de verdad! Cuando detenga el ataque, todas las víctimas seguirán convencidas de que ettercap es la puerta de enlace hasta que expire la concesión.

port ([remoto],[árbol]
)
Este ataque implementa el Robo de Puertos. Esta técnica es útil para capturar en un entorno conmutado cuando el envenenamiento ARP no es efectivo (por ejemplo donde se usan ARPs mapeados estáticamente).

Inunda la LAN (basado en la opción port_steal_delay en etter.conf) con paquetes ARP. Si no especifica la opción "árbol", la dirección mac de destino de cada paquete de "robo" es la misma que la del atacante (otras tarjetas de red no verán estos paquetes), la dirección mac de origen será una de las macs en la lista de hosts. Este proceso "roba" el puerto del switch de cada host víctima en la lista de hosts. Usando retrasos bajos, los paquetes destinados a direcciones mac "robadas" serán recibidos por el atacante, ganando la condición de carrera con el propietario real del puerto. Cuando el atacante recibe paquetes para hosts "robados", detiene el proceso de inundación y realiza una solicitud ARP para el destino real del paquete. Cuando recibe la respuesta ARP está seguro de que la víctima ha "recuperado" su puerto, así que ettercap puede reenviar el paquete al destino tal cual. Ahora podemos reiniciar el proceso de inundación esperando nuevos

paquetes.

Si usa la opción "árbol", la dirección mac de destino de cada paquete de robo será una falsa, así que estos paquetes se propagarán a otros switches (no solo al directamente conectado). De esta manera podrá robar puertos en otros switches en el árbol (si los hay), pero generará una gran cantidad de tráfico (según port_steal_delay). La opción "remoto" tiene el mismo significado que en el método mitm

"arp".

Cuando detenga el ataque, ettercap enviará una solicitud ARP a cada host robado devolviendo sus puertos de switch.
Puede realizar un mitm SEMI o FULL DUPLEX según la selección de

objetivo.

NOTA: Use este método mitm solo en switches ethernet. Úselo con cuidado, podría producir pérdida de rendimiento o caos

general.

NOTA: NO puede usar este método en modo solo-mitm (flag -o), porque engancha el motor de sniffing, y no puede usar la inyección interactiva de

datos.

NOTA: Podría ser peligroso usarlo en conjunto con otros métodos

mitm.

NOTA: Este método mitm no funciona en Solaris y Windows debido al diseño de lipcap y libnet y la falta de ciertos ioctl(). (Presentaremos este método en estos SO si alguien lo solicita.

..)

Este método implementa el ataque de envenenamiento NDP que se usa para MITM de conexiones IPv6. Se envían solicitudes/respuestas ND a las víctimas para envenenar su caché de vecinos. -r, --read
<ARCHIVO>
SNIFFING SIN CONEXIÓN
Con esta opción habilitada, ettercap esnifará paquetes de un archivo compatible con pcap en lugar de capturar desde el cable.
Esto es útil si tienes un archivo volcado desde tcpdump o wireshark y quieres realizar un análisis (buscar contraseñas o huella digital pasiva) en él.

archivo.

<ARCHIVO>

Esto es útil si tienes que usar sniffing "activo" (envenenamiento arp) en una LAN conmutada pero quieres analizar los paquetes con tcpdump o wireshark. Puedes usar esta opción para volcar los paquetes a un archivo y luego cargarlo en tu aplicación favorita.

herramientas.

Cada vez que ettercap inicia, desactiva el reenvío de ip en el kernel y comienza a reenviar paquetes él mismo. Esta opción previene hacer eso, así que la responsabilidad del reenvío de ip se le deja al kernel.
Esta opción es útil si quieres ejecutar múltiples instancias de ettercap. Tendrás una instancia (la que no tiene la opción -u) reenviando los paquetes, y todas las otras instancias haciendo su trabajo sin reenviarlos. De lo contrario obtendrás paquetes duplicados.
También desactiva la creación interna de sesiones para cada conexión. Aumenta el rendimiento, pero no podrás modificar paquetes en caliente.
Si quieres usar un ataque mitm tienes que use a separate instance.

-F, --filter
<FILE>
Load the filter from the file <FILE>. The filter must be compiled with etterfilter(8). The utility will compile the filter script and produce an ettercap-compliant binary filter file. Read the etterfilter(8) man page for the list of functions you can use inside a filter script. Any number of filters can be loaded by specifying the option multiple times; packets are passed through each filter in the order specified on the command line. -L, --log
<LOGFILE>
Log all the packets to binary files. These files can be parsed by etterlog(8) to extract human readable data. With this option, all packets sniffed by ettercap will be logged, together with all the passive info (host info + user & pass) it can collect. Given a LOGFILE, ettercap will create LOGFILE.ecp (for packets) and LOGFILE.eci (for the infos).

NOTE: if you specify this option on command line you don't have to take care of privileges since the log file is opened in the startup phase (with high privs). But if you enable the log option while ettercap is already started, you have to be in a directory where uid = 65535 or uid = EC_UID can

write.
