ETTER.CONF(5) Manual de formatos de archivo ETTER.CONF(5)

NOMBRE

etter.conf - Archivo de configuración de Ettercap

DESCRIPCIÓN

etter.conf es el archivo de configuración que determina el comportamiento de ettercap. Se carga siempre al inicio y configura algunos atributos utilizados en tiempo de ejecución.

El archivo contiene entradas de la forma:

[sección]
entrada = valor
...

Cada entrada define una variable que puede personalizarse. Cada valor DEBE ser un entero. Las secciones se utilizan solo para agrupar algunas variables.

NOTA: si se omite una variable en el archivo de configuración, se inicializará con el valor 0. Se desaconseja encarecidamente no inicializar variables críticas como "arp_poison_delay" o "connection_timeout".

A continuación se muestra una lista de las variables disponibles:

[privs]
ec_uid
Esta variable especifica la UID a la que se bajan los privilegios al inicio. Después de abrir el socket en la capa de enlace, los privilegios se bajan a una UID específica diferente de root por razones de seguridad. etter.conf es el único archivo que se lee con privilegios de root. Asegúrese de que la UID especificada tenga suficientes privilegios para leer otros archivos (etter.*). Puede omitir esta variable configurando la variable de entorno EC_UID.
[mitm]
arp_storm_delay
El valor representa los milisegundos de espera entre dos paquetes consecutivos durante el escaneo ARP inicial. Puede aumentar este valor para ser menos agresivo al inicio. El escaneo aleatorio más un retraso alto puede engañar a algunos tipos de detectores de escaneo ARP.
arp_poison_smart
Con esta variable configurada, solo se envían 3 mensajes ARP envenenados iniciales a las víctimas. Este estado envenenado se mantiene respondiendo a las solicitudes ARP de las víctimas que desean actualizar su caché ARP. Esto hace que el envenenamiento ARP sea muy sigiloso, pero puede ser poco fiable en medios compartidos como WiFi.
arp_poison_warm_up
Cuando comienza el proceso de envenenamiento, el retraso entre paquetes es bajo para los primeros 5 envenenamientos (para asegurarse de que el proceso de envenenamiento ha sido exitoso). Después de los primeros 5 envenenamientos, el retraso se incrementa (para mantener el envenenamiento). Esta variable controla el retraso para los primeros 5 envenenamientos. El valor está en segundos.
Se utiliza el mismo retraso cuando las víctimas se restauran a las asociaciones originales (RE-ARPing) cuando se cierra ettercap.
arp_poison_delay
Esta variable controla el retraso de envenenamiento después de los primeros 5 envenenamientos. El valor se expresa en segundos. Puede aumentar este valor (para intentar engañar al IDS) hasta el tiempo de espera de la caché ARP (que depende del sistema operativo envenenado).
arp_poison_icmp
Habilita el envío de un mensaje ICMP falsificado para forzar a los objetivos a realizar una solicitud ARP. Esto creará una entrada en la caché ARP, por lo que ettercap podrá ganar la condición de carrera y envenenar al objetivo. Útil contra objetivos que no aceptan ARP gratuitas si la entrada no está en la caché.
arp_poison_reply
Utiliza respuestas ARP para envenenar a los objetivos. Este es el ataque clásico.
arp_poison_request
Utiliza solicitudes ARP para envenenar a los objetivos. Útil contra objetivos que almacenan en caché incluso los valores de solicitud ARP.
arp_poison_equal_mac
Configure esta opción en 0 si desea omitir el envenenamiento de dos hosts con la misma dirección MAC. Esto puede ocurrir si una NIC tiene uno o más alias en la misma red.
dhcp_lease_time
Este es el tiempo de arrendamiento (en segundos) para una asignación DHCP. Puede disminuir este valor para permitir que las víctimas reciban una respuesta DHCP correcta después de que haya detenido su ataque. Usar tiempos de espera más altos puede desordenar seriamente su red después de que finalice el ataque. Por otro lado, algunos clientes preferirán un tiempo de espera más alto, por lo que deberá aumentarlo para ganar la condición de carrera contra el servidor real.
port_steal_delay
Este es el tiempo de espera (en milisegundos) entre paquetes para el método MITM "port". Con retrasos bajos podrá interceptar más paquetes, pero generará más tráfico. Debe ajustar este valor para encontrar un buen equilibrio entre el número de paquetes interceptados, paquetes retransmitidos y paquetes perdidos. Este valor depende de canales full/half duplex, controladores y adaptadores de red, configuración general de red y hardware.
port_steal_send_delay
Este es el tiempo de espera (en microsegundos) entre paquetes cuando el método MITM "port" tiene que reenviar colas de paquetes. Como se mencionó para port_steal_delay, debe ajustar esta opción al valor aceptable más bajo.
ndp_poison_warm_up
Esta opción funciona de manera similar a la opción arp_poison_warm_up. Cuando comienza el proceso de envenenamiento, esta opción controla el retraso del envenenamiento NDP para los primeros 5 envenenamientos (para asegurarse de que el proceso de envenenamiento ha sido exitoso). Después de los primeros 5 envenenamientos, el retraso se incrementa (para mantener el envenenamiento). Esta variable controla el retraso para los primeros 5 envenenamientos. El valor debe ser inferior a ndp_poison_delay. El valor está en segundos.
Se utiliza el mismo retraso cuando las víctimas se restauran a las asociaciones originales
cuando se cierra ettercap.
ndp_poison_delay
Esta opción es similar a la opción arp_poison_delay. Controla el retraso en segundos para enviar los paquetes NDP envenenados para envenenar la caché de vecinos de la víctima. Este valor puede aumentarse para ocultarse de los IDS. Pero aumentar el valor también aumenta la probabilidad de fallar las condiciones de carrera durante el descubrimiento de vecinos y de perder algunos paquetes.
ndp_poison_send_delay
Esta opción controla el retraso en microsegundos entre el envío de paquetes NDP envenenados. Este valor puede aumentarse para ocultarse de los IDS. Pero aumentar el valor también aumenta la probabilidad de fallar las condiciones de carrera durante el descubrimiento de vecinos y de perder algunos paquetes.
ndp_poison_icmp
Habilita el envío de un mensaje ICMPv6 falsificado para motivar a los objetivos a realizar el descubrimiento de vecinos. Esto creará una entrada en la caché de vecinos del host, por lo que ettercap podrá ganar la condición de carrera y envenenar al objetivo. Útil contra objetivos que no aceptan anuncios de vecinos si la entrada no está en la caché.
ndp_poison_equal_mac
Configure esta opción en 0 si desea omitir el envenenamiento NDP de dos hosts con la misma dirección MAC. Esto puede ocurrir si una NIC tiene uno o más alias en la misma red.
icmp6_probe_delay
Esta opción define el tiempo en segundos que ettercap espera a que los nodos IPv6 activos respondan a las sondas ICMP. Disminuir este valor podría llevar a perder respuestas de nodos IPv6 activos, y por lo tanto, omitirlos en la lista de hosts. Aumentar el valor normalmente no tiene impacto; normalmente los nodos pueden responder durante el retraso predeterminado.

NOTA: Las opciones ndp e icmp6 solo están disponibles si ettercap se compiló con soporte IPv6.

connection_i

El número de segundos a esperar antes de que una conexión se marque como

connection_buf
fer
Esta variable controla el tamaño del búfer vinculado a cada conexión. Cada paquete capturado se añade al búfer y cuando el búfer está lleno los paquetes más antiguos se eliminan para hacer espacio a los más nuevos. Este búfer es útil para ver datos que pasaron por el cable antes de que selecciones y veas una conexión específica. Cuanto mayor sea este valor, mayor será la ocupación de memoria de ettercap. Por cierto, el búfer es dinámico, así que si estableces un búfer de 100.000 bytes no se asigna todo de una vez en el primer paquete de una conexión, sino que se va llenando a medida que llegan los
paquetes.
connect_time
out
El tiempo de espera en segundos al usar la llamada al sistema connect(). Aumenta este valor si recibes un error "Connection timeout". Esta opción no tiene nada que ver con las conexiones capturadas por ettercap. Es un tiempo de espera para las conexiones que ettercap realiza a otros hosts (por ejemplo, al identificar un host remoto)

[stat
s]
sampling_ra
te
Ettercap mantiene algunas estadísticas sobre el tiempo de procesamiento de la mitad inferior (el capturador) y la mitad superior (el decodificador de protocolos). Estas estadísticas se basan en el tiempo de procesamiento promedio de sampling_rate paquetes. Puedes disminuir este valor para obtener una imagen más precisa del tiempo de procesamiento en tiempo real o aumentarlo para obtener una imagen más suave. El promedio total no cambiará, pero el valor peor se verá fuertemente influenciado por este
valor.
[mis

close_on_e
of
Al leer desde un archivo de volcado y usar la interfaz de consola o de demonio, esta variable se utiliza para determinar qué acción debe realizarse en EOF. Es un valor booleano. Si se establece en 1, ettercap se cerrará a sí mismo (útil en scripts). De lo contrario, la sesión continuará esperando la entrada del
usuario.
store_profil
es
Ettercap recopila en memoria un perfil para cada host que detecta. Los usuarios y las contraseñas se recopilan allí. Si deseas ejecutar ettercap en segundo plano registrando todo el tráfico, es posible que desees desactivar la recopilación en memoria para ahorrar memoria del sistema. Establece esta opción en 0 (cero) para desactivar la recopilación de perfiles. Un valor de 1 habilitará la recopilación para todos los hosts, 2 recopilará solo los hosts locales y 3 solo los hosts remotos (un host se considera remoto si no pertenece a la máscara de
red).
aggressive_dissect
ors
Algunos dissectores (como SSH y HTTPS) necesitan modificar la carga útil de los paquetes para recopilar contraseñas y realizar un ataque de descifrado. Si deseas desactivar por completo los dissectores "peligrosos", establece este valor en
0.
skip_forward
ed
Si estableces este valor en 0, capturarás incluso los paquetes reenviados por ettercap o por el kernel. Generará paquetes duplicados en conjunto con el método MITM de arp (por ejemplo). Podría ser útil mientras ejecutas ettercap en modo no ofensivo en un host con más de una interfaz de red (esperando la función de múltiples interfaces.
..)
checksum_warn
ing
Si estableces el valor en 0, los mensajes sobre sumas de verificación incorrectas no se mostrarán en las ventanas de mensajes del usuario (ni se registrarán en un archivo con -m).
Ten en cuenta que esta opción no desactivará la comprobación en los paquetes, sino que solo evitará que se muestre el mensaje (ver más abajo)
.
checksum_che
ck
Esta opción se utiliza para desactivar por completo la comprobación de la suma de verificación de los paquetes que ettercap recibe. La comprobación en los paquetes se realiza para evitar que ettercap sea detectado a través de paquetes con malas sumas de verificación (ver Phrack 60.12). Si desactivas la comprobación, podrás capturar incluso paquetes con malas sumas de verificación, pero serás detectado si alguien te está buscando.
..
sniffing_at_star
tup
Si esta opción se establece en 1, ettercap comenzará inmediatamente la capturación unificada o en puente después de que se haya completado la fase de configuración. Esta opción ayuda a evitar el bloqueo del tráfico cuando se ha iniciado una técnica MITM pero se ha olvidado iniciar la capturación. Por lo tanto, esta opción se establece en 1 por defecto.
Si este comportamiento no es deseable, establece en 0 para controlar manualmente el estado de la capturación unificada o en puente después de que ettercap haya iniciado. Sin embargo, la capturación se puede detener y comenzar en cualquier momento mientras ettercap se
ejecuta.
geoip_support_ena
ble
Esta opción controla si la información de GeoIP debe procesarse para las direcciones IP, independientemente de si ettercap se ha compilado con soporte de GeoIP o
no.
gtkui_prefer_dark_th
eme
Esta opción intenta forzar la variante oscura del tema aplicado. Sin embargo, esto solo tiene efecto si el tema aplicado proporciona una variante oscura. Normalmente, el entorno de escritorio controla el tema de las aplicaciones. Pero algunos entornos de escritorio ligeros no admiten una opción de configuración para temas oscuros incluso cuando el tema proporciona una variante oscura. Para dejar la configuración de la variante del tema al entorno de escritorio, esta opción se establece en 0 por defecto.
NOTA: Esta opción solo es relevante en modo GTK y si ettercap se ha compilado con soporte completo de
GTK3.
[dissector
s]
protocol_na
me
Este valor representa el puerto en el que el disector de protocolo debe vincularse. Un valor de 0 desactivará el disector. El nombre de la variable es el mismo que el nombre del protocolo. Puedes especificar un puerto no estándar para cada disector, así como múltiples puertos. La sintaxis para la selección de múltiples puertos es la siguiente: puerto1,puerto2,puerto3,...
NOTA: algunos dissectores se compilan condicionalmente. Esto significa que dependiendo de las bibliotecas encontradas en tu sistema, algunos dissectores estarán habilitados y otros no. Por defecto, etter.conf contiene todos los dissectores admitidos. Si recibes un error "FATAL: Dissector "xxx" does not exists (etter.conf line yy)", debes comentar la línea yy en etter.
conf.
