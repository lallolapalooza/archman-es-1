DESCRIPCIÓ

N

ebtables es un programa de aplicación utilizado para configurar y mantener las tablas de reglas (dentro del núcleo de Linux) que inspeccionan tramas Ethernet. Es análogo a la aplicación iptables, pero menos complicado, debido al hecho de que el protocolo Ethernet es mucho más simple que el protocolo

IP.

CADENA

S

Hay tres tablas de ebtables con cadenas incorporadas en el núcleo de Linux. Estas tablas se utilizan para dividir la funcionalidad en diferentes conjuntos de reglas. Cada conjunto de reglas se llama cadena. Cada cadena es una lista ordenada de reglas que pueden coincidir con tramas Ethernet. Si una regla coincide con una trama Eth

ernet, entonces una especificación de procesamiento indica qué hacer con esa trama coincidente. La especificación de procesamiento se llama 'destino'. Sin embargo, si la trama no coincide con la regla actual en la cadena, entonces se examina la siguiente regla en la cadena y así sucesivamente. El usuario puede crear nuevas ca
denas (definidas por el usuario) que pueden usarse como el 'destino' de una regla. Las cadenas definidas por el usuario son muy útiles para obtener un mejor rendimiento sobre el recorrido lineal de las reglas y también son esenciales para estructurar las reglas de filtrado en conjuntos de reglas bien organizados y mantenibles.

DESTINO

S

Una regla de firewall especifica criterios para una trama Ethernet y una especificación de procesamiento de tramas llamada destino. Cuando una trama coincide con una regla, entonces la siguiente acción realizada por el núcleo es especificada por el destino. El destino puede ser uno de estos valores: ACCEPT, DROP, CONTINUE, RETURN, una 'extensión' (ver más abajo) o un salto a una cadena definida por el

usuario.

ACCEPT significa dejar pasar la trama. DROP significa que la trama debe ser descartada. En la cadena BROUTING sin embargo, los destinos ACCEPT y DROP tienen significados diferentes (ver la información proporcionada para la opción -t). CONTINUE significa que se debe comprobar la siguiente regla. Esto puede ser útil, por ejemplo, para saber cuántas tramas pasan por un cierto punto en la cadena, para registrar esas tramas o para aplicar múltiples destinos a una trama. RETURN significa dejar de recorrer esta cadena y reanudar en la siguiente regla en la cadena anterior (llamadora). Para los destinos de extensión, por favor consulte la sección de EXTENSIONES DE DEST

INO de esta pág
ina del manual.

TABLA

S

Como se mencionó anteriormente, los nombres de las tablas son filter, nat y broute. De estas tablas, la tabla filter es la tabla predeterminada en la que opera el comando. Si está trabajando con una tabla que no sea filter, necesitará proporcionar el argumento -t. Además, el argumento -t debe ser el primer argumento en la línea de comando de ebtables, si se

usa.
-t,
--table

filter es la tabla predeterminada y contiene tres cadenas incorporadas: INPUT (para tramas destinadas al propio puente, a nivel de la dirección MAC de destino), OUTPUT (para tramas generadas localmente o (b)rutadas) y FORWARD (para tramas que están siendo reenviadas por el puente).
nat se usa principalmente para cambiar las direcciones mac y contiene tres cadenas incorporadas: PREROUTING (para alterar tramas tan pronto como entran), OUTPUT (para alterar tramas generadas localmente o (b)rutadas antes de que sean puenteadas) y POSTROUTING (para alterar tramas a punto de salir). Una pequeña nota sobre la nomenclatura de las cadenas PREROUTING y POSTROUTING: sería más preciso llamarlas PREFORWARDING y POSTFORWARDING, pero para todos aquellos que vienen del mundo de iptables a ebtables es más fácil tener los mismos nombres. Tenga en cuenta que puede cambiar el nombre (-E) si no le gusta el predeterminado.
broute se usa para hacer un brouter, tiene una cadena incorporada: BROUTING. Los destinos DROP y ACCEPT tienen un significado especial en la tabla broute (estos nombres se usan por razones de compatibilidad con ebtables-legacy). DROP realmente significa que la trama debe ser rutada, mientras que ACCEPT significa que la trama debe ser puenteada. La cadena BROUTING se recorre muy temprano. Nor
malmente esas tramas s
erían puenteadas,
pero usted puede deci

COMANDO

S

Los argumentos del comando ebtables especifican las acciones a realizar en la tabla definida con el argumento -t. Si no usa el argumento -t para nombrar una tabla, los comandos se aplican a la tabla filter predeterminada. Solo un comando puede usarse en la línea de comando a la vez, excepto cuando los comandos -L y -Z se combinan o los comandos -N y -P se

combinan.
-A,
--append
Añade una regla al final de la cadena
seleccionada.
-D,
--delete
Elimina la regla o reglas especificadas de la cadena seleccionada. Hay dos formas de usar este comando. La primera es especificando un intervalo de números de regla para eliminar (directamente después de -D). Sintaxis: nr_inicio[:nr_fin] (use -L --Ln para listar las reglas con su número de regla). Cuando nr_fin se omite, se eliminan todas las reglas a partir de nr_inicio. Se permiten números negativos, para más detalles sobre el uso de números negativos, consulte el comando -I. El segundo uso es especificando la regla completa como se habría especificado cuando se añadió. Solo la primera regla encontrada que es igual a esta regla especificada, en otras palabras la regla coincidente con el número de regla (positivo) más bajo, es
eliminada.
-C,
--change-counters
Cambia los contadores de la regla o reglas especificadas de la cadena seleccionada. Hay dos formas de usar este comando. La primera es especificando un intervalo de números de regla para hacer los cambios (directamente después de -C). Sintaxis: nr_inicio[:nr_fin] (use -L --Ln para listar las reglas con su número de regla). Los detalles son los mismos que para el comando -D. El segundo uso es especificando la regla completa como se habría especificado cuando se añadió. Solo los contadores de la primera regla encontrada que es igual a esta regla especificada, en otras palabras la regla coincidente con el número de regla (positivo) más bajo, son cambiados. En el primer uso, los contadores se especifican directamente después de la especificación del intervalo, en el segundo uso directamente después de -C. Primero se especifica el contador de paquetes, luego el contador de bytes. Si los contadores especificados comienzan con un '+', los valores de los contadores se añaden a los respectivos valores de los contadores actuales. Si los contadores especificados comienzan con un '-', los valores de los contadores se restan de los respectivos valores de los contadores actuales. No se realiza ninguna comprobación de límites. Si los contadores no comienzan con '+' o '-', los contadores actuales se cambian a los contadores
especificados.
-I,
--insert
Inserta la regla especificada en la cadena seleccionada en el número de regla especificado. Si el número de regla no se especifica, la regla se añade en la cabecera de la cadena. Si el número actual de reglas es igual a N, entonces el número especificado puede estar entre -N y N+1. Para un número positivo número i, se tiene que i y i-N-1 especifican el mismo lugar en la cadena donde debe insertarse la regla. El número de regla 0 especifica el lugar después de la última regla en la cadena y, por lo tanto, usar este número es equivalente a usar el comando -A. Los números de regla estrictamente menores que 0 pueden ser útiles cuando se necesita insertar más de una regla en una cadena.
-P, --policy
Establece la política para la cadena al destino dado. La política puede ser ACCEPT, DROP o RETURN.
-F, --flush
Vacía la cadena seleccionada. Si no se selecciona ninguna cadena, se vaciarán todas las cadenas. Vaciar una cadena no cambia la política de la cadena, sin embargo.
-Z, --zero
Establece los contadores de la cadena seleccionada a cero. Si no se selecciona ninguna cadena, todos los contadores se establecen a cero. El comando -Z se puede usar en conjunción con el comando -L. Cuando ambos comandos -Z y -L se usan juntos de esta manera, los contadores de reglas se imprimen en la pantalla antes de que se establezcan a cero.
-L, --list
Lista todas las reglas en la cadena seleccionada. Si no se selecciona ninguna cadena, se listan todas las cadenas.
Las siguientes opciones cambian la salida del comando -L.
--Ln
Coloca el número de regla delante de cada regla. Esta opción es incompatible con la opción --Lx.
--Lc
Muestra los contadores al final de cada regla mostrada por el comando -L. Se muestra tanto un contador de tramas (pcnt) como un contador de bytes (bcnt). El contador de tramas muestra cuántas tramas han coincidido con la regla específica, el contador de bytes muestra la suma de los tamaños de trama de esas tramas coincidentes. El uso de esta opción en combinación con la opción --Lx hace que los contadores se escriban en el formato de la opción '-c <pcnt> <bcnt>'.
--Lx
Cambia la salida para que produzca un conjunto de comandos ebtables que construyen el contenido de la cadena, cuando se especifica. Si no se especifica ninguna cadena, se proporcionan comandos ebtables para construir el contenido de la tabla, incluidos los comandos para crear las cadenas definidas por el usuario (si las hay). Puede usar este conjunto de comandos en un script de arranque o recarga de ebtables. Por ejemplo, la salida podría usarse al inicio del sistema. La opción --Lx es incompatible con la opción de listado --Ln. El uso de la opción --Lx junto con la opción --Lc hará que los contadores se escriban en el formato de la opción '-c <pcnt> <bcnt>'.
--Lmac2
Muestra todas las direcciones MAC con la misma longitud, añadiendo ceros iniciales si es necesario. La representación predeterminada omite los ceros iniciales en las direcciones.
-N, --new-chain
Crea una nueva cadena definida por el usuario con el nombre dado. El número de cadenas definidas por el usuario está limitado solo por el número de nombres de cadena posibles. Un nombre de cadena definida por el usuario tiene una longitud máxima de 31 caracteres. La política predeterminada de la cadena definida por el usuario es ACCEPT. La política de la nueva cadena se puede inicializar a un destino estándar diferente utilizando el comando -P junto con el comando -N. En este caso, el nombre de la cadena no tiene que especificarse para el comando -P.
-X, --delete-chain
Elimina la cadena definida por el usuario especificada. No debe haber referencias (saltos) restantes a la cadena especificada, de lo contrario, ebtables se negará a eliminarla. Si no se especifica ninguna cadena, se eliminarán todas las cadenas definidas por el usuario que no se referencien.
-E, --rename-chain
Renombra la cadena especificada a un nuevo nombre. Además de renombrar una cadena definida por el usuario, puede renombrar una cadena estándar a un nombre que se adapte a su gusto. Por ejemplo, si prefiere PREFORWARDING a PREROUTING, puede usar el comando -E para renombrar la cadena PREROUTING. Si renombra uno de los nombres de cadena estándar de ebtables, asegúrese de mencionar este hecho si publica una pregunta en las listas de correo de ebtables. Sería aconsejable usar el nombre estándar en su publicación. Renombrar una cadena estándar de ebtables de esta manera no tiene ningún efecto en la estructura o el funcionamiento de la tabla de kernel de ebtables.
--init-table
Reemplaza los datos actuales de la tabla por los datos iniciales de la tabla.

COMANDOS MISCELÁNEOS

-v, --verbose
Modo detallado. Para añadir, insertar, eliminar y reemplazar, esto causa que se imprima información detallada sobre la regla o reglas. -v puede especificarse varias veces para emitir posiblemente declaraciones de depuración más detalladas.
-V, --version
Muestra la versión del programa de espacio de usuario ebtables.
-h, --help [lista de nombres de módulos]
Proporciona una breve descripción de la sintaxis del comando. Aquí también puede especificar nombres de extensiones y ebtables intentará escribir ayuda sobre esas extensiones. Por ejemplo, ebtables -h snat log ip arp. Especifique list_extensions para listar todas las extensiones admitidas por la utilidad de espacio de usuario.
-j, --jump destino
El destino de la regla. Este es uno de los siguientes valores: ACCEPT, DROP, CONTINUE, RETURN, una extensión de destino (ver EXTENSIÓN DE DESTINO) o un nombre de cadena definido por el usuario.
-M, --modprobe programa
Al comunicarse con el kernel, use este programa para intentar cargar automáticamente los módulos del kernel que faltan.
--concurrent
Esto usaría un bloqueo de archivo para admitir scripts concurrentes que actualizan las tablas del kernel de ebtables. No es necesario con ebtables-nft y, por lo tanto, se ignora.

ESPECIFICACIONES DE REGLAS

Los siguientes argumentos de línea de comandos constituyen una especificación de regla (como se usa en los comandos de adición y eliminación). Una opción "!" antes de la especificación invierte la prueba para esa especificación. Aparte de estas especificaciones de regla estándar, hay algunos otros argumentos de línea de comandos de interés. Consulte tanto las EXTENSIONES DE COINCIDENCIA como las EXTENSIONES DE VIGILANCIA a continuación.

[!] -p, --protocol protocolo
El protocolo que fue responsable de la creación de la trama. Puede ser un número hexadecimal, mayor que 0x0600, un nombre (por ejemplo, ARP) o LENGTH. El campo de protocolo del marco Ethernet se puede utilizar para denotar la longitud de la cabecera (redes 802.2/802.3). Cuando el valor de ese campo es inferior o igual a 0x0600, el valor es igual al tamaño de la cabecera y no debe usarse como número de protocolo. En su lugar, se asume que todas las tramas donde el campo de protocolo se usa como campo de longitud son del mismo 'protocolo'. El nombre del protocolo utilizado en ebtables para estas tramas es LENGTH.
El archivo /etc/ethertypes se puede usar para mostrar caracteres legibles en lugar de números hexadecimales para los protocolos. Por ejemplo, 0x0800 se representará como IPV4. El uso de este archivo no distingue entre mayúsculas y minúsculas. Consulte ese archivo para obtener más información. El indicador --proto es un alias de esta opción.
[!] -i, --in-interface nombre
La interfaz (puerto de puente) a través de la cual se recibe una trama (esta opción es útil en las cadenas INPUT, FORWARD, PREROUTING y BROUTING). Si el nombre de la interfaz termina con '+', entonces coincidirá cualquier nombre de interfaz que comience con este nombre (sin tener en cuenta '+'). El indicador --in-if es un alias de esta opción.
[!] --logical-in nombre
La interfaz de puente (lógica) a través de la cual se recibe una trama (esta opción es útil en las cadenas INPUT, FORWARD, PREROUTING y BROUTING). Si el nombre de la interfaz termina con '+', entonces coincidirá cualquier nombre de interfaz que comience con este nombre (sin tener en cuenta '+').
[!] -o, --out-interface nombre
La interfaz (puerto de puente) a través de la cual se va a enviar una trama (esta opción es útil en las cadenas OUTPUT, FORWARD y POSTROUTING). Si el nombre de la interfaz termina con '+', entonces coincidirá cualquier nombre de interfaz que comience con este nombre (sin tener en cuenta '+'). El indicador --out-if es un alias de esta opción.
[!] --logical-out nombre
La interfaz de puente (lógica) a través de la cual se va a enviar una trama (esta opción es útil en las cadenas OUTPUT, FORWARD y POSTROUTING). Si el nombre de la interfaz termina con '+', entonces coincidirá cualquier nombre de interfaz que comience con este nombre (sin tener en cuenta '+').
[!] -s, --source dirección[/máscara]
La dirección MAC de origen. Tanto la máscara como la dirección se escriben como 6 números hexadecimales separados por dos puntos. Alternativamente, se puede especificar Unicast, Multicast, Broadcast o BGA (Bridge Group Address):
Unicast=00:00:00:00:00:00/01:00:00:00:00:00, Multicast=01:00:00:00:00:00/01:00:00:00:00:00, Broadcast=ff:ff:ff:ff:ff:ff/ff:ff:ff:ff:ff:ff o BGA=01:80:c2:00:00:00/ff:ff:ff:ff:ff:ff. Tenga en cuenta que una dirección de broadcast también coincidirá con la especificación de multicast. El indicador --src es un alias de esta opción.
[!] -d, --destination dirección[/máscara]
La dirección MAC de destino. Consulte -s (arriba) para obtener más detalles sobre las direcciones MAC. El indicador --dst es un alias de esta opción.
-c, --set-counter pcnt bcnt
Si se usa con -A o -I, entonces los contadores de paquetes y bytes de la nueva regla se establecerán en pcnt, respectivamente, bcnt. Si se usa con los comandos -C o -D, solo las reglas con un recuento de paquetes y bytes igual a pcnt, respectivamente, bcnt coincidirán.
