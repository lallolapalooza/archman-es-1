EBFC(1) Manual de Comandos Generales EBFC(1)

NOMBRE

ebfc - compilador ELF de Brainfuck

SINOPSIS

ebfc [OPCIONES] ARCHIVOFUENTE

DESCRIPCIÓN

ebfc es un compilador para el lenguaje de programación Brainfuck, que crea archivos ELF de 64 bits dirigidos a la arquitectura Intel x86-64.

ebfc puede crear ejecutables independientes, bibliotecas compartidas u archivos de objeto. Los archivos de objeto pueden estar dirigidos a un ejecutable independiente, una biblioteca compartida o un módulo en un programa más grande.

OPCIONES DE OBJETIVO DE COMPILACIÓN

Las siguientes opciones controlan qué tipo de archivo fuente se crea. Se asume aquí que el nombre del archivo fuente es foo.b.

-x
Compila el código fuente en un archivo ejecutable independiente, llamado foo.
-l
Compila el código fuente en un archivo de biblioteca compartida, llamado libfoo.so. El programa se exportará como una función llamada foo().
-c
Compila el código fuente en una función, llamada foo(), en un archivo de objeto, llamado foo.o. El archivo de objeto estará dirigido a un módulo en un ejecutable.
-xc
Compila el código fuente en un archivo de objeto, llamado foo.o, que puede luego enlazarse como un ejecutable independiente.
-lc
Compila el código fuente en una función, llamada foo(), en un archivo de objeto, llamado foo.o, que puede luego enlazarse como una biblioteca compartida.

Si el argumento ARCHIVOFUENTE carece de un sufijo .b o .bf , entonces se usará el nombre de archivo completo al crear el nombre del archivo de destino y de la función. (En el caso de -x, el nombre del archivo de destino será a.out en su lugar.)

OTRAS OPCIONES

-a, --arg
Compila la función para que tome un argumento, a saber, un puntero al arreglo de bytes. De forma predeterminada, ebfc compilará su código como una función que no toma argumentos, la cual usará un arreglo de bytes interno. Cuando se usa esta opción, no hay diferencia en el archivo de objeto creado por -c y -lc. (Esta opción no es aplicable a un ejecutable independiente.)
-f, --function=FUNCIÓN
Usa FUNCIÓN como el nombre de la función que contendrá el programa compilado. Si este argumento se omite, el nombre de la función se tomará del nombre del archivo fuente, como se describe en la sección anterior.
-i, --input=ARCHIVO
Usa ARCHIVO como el nombre del archivo fuente que se colocará en el archivo de destino. Esta opción no reemplaza el argumento ARCHIVOFUENTE ; simplemente cambia qué nombre se almacena en el archivo de objeto. (Esta opción no es significativa si el destino no es un archivo de objeto, o si se usa la opción --strip .)
-o, --output=ARCHIVO
Usa ARCHIVO como el nombre de archivo de destino. Si esta opción se omite, el nombre de archivo de salida se generará a partir del nombre del archivo fuente, como se describe en la sección anterior.
-s, --strip
Suprime la inclusión de datos innecesarios en el archivo de destino. De forma predeterminada, ebfc incluye una sección .comment, e incluye un símbolo en la tabla de símbolos para el nombre del archivo fuente. Estos elementos se eliminarán de la salida cuando se usa esta opción. Además, si la salida es un ejecutable independiente, esta opción suprimirá la inclusión de la tabla de encabezados de sección.
-z, --compressed
Lee el archivo fuente en formato Brainfuck comprimido (ver más abajo).
--help
Muestra la ayuda y termina.
--version
Muestra el número de versión y termina.

ENLAZADO

Al llamar a un programa Brainfuck compilado desde un programa en C, el prototipo en C de la función debe tener la forma:


extern void foo(void);

o, si se especifica la opción --arg :


extern void char *buffer);

En este último caso, el búfer al que apunta el parámetro de la función se usará como el estado inicial del búfer de Brainfuck cuando se invoque la función, y al retornar contendrá el estado final del búfer.

EL LENGUAJE DE PROGRAMACIÓN BRAINFUCK

Un programa en Brainfuck tiene un puntero de bytes implícito, llamado "el puntero", que puede moverse libremente dentro de un arreglo de bytes, inicialmente todos establecidos en cero. El puntero mismo se inicializa para apuntar al comienzo de este arreglo. (El tamaño del arreglo no está restringido por el lenguaje, pero típicamente es de 30000 bytes o más. ebfc Los programas reciben un arreglo de 32768 bytes.)

El lenguaje de programación Brainfuck consiste en ocho comandos, cada uno de los cuales se representa como un solo carácter.

>
Incrementa el puntero.
<
Decrementa el puntero.
+
Incrementa el byte en el puntero.
-
Decrementa el byte en el puntero.
.
Salida el byte en el puntero.
,
Entrada un byte y lo almacena en el byte en el puntero.
[
Salta al ] correspondiente si el byte en el puntero es cero.
]
Salta al [correspondiente.

Cualquier otro carácter en el código fuente se trata como comentarios o espacios en blanco, y se ignora.

La semántica de los comandos de Brainfuck también puede expresarse sucintamente en términos de C, como sigue (asumiendo que p ha sido previamente definido como un char*):

>
se convierte en ++p;
<
se convierte en --p;
+
se convierte en ++*p;
-
se convierte en --*p;
.
se convierte en putchar(*p);
,
se convierte en *p = getchar();
[
se convierte en while (*p) {
]
se convierte en }

Al igual que con C, el comportamiento del programa generado es indefinido si el puntero se mueve fuera del arreglo de bytes.

BRAINFUCK COMPRIMIDO

Existe un formato comprimido para almacenar y transmitir programas en Brainfuck, el cual ebfc puede leer de forma nativa usando la opción --compressed .

En Brainfuck comprimido, los ocho comandos se codifican en tres bits como sigue:

+
000
-
001
<
010
>
011
[
100
]
101
,
110
.
111

Cada byte en un archivo Brainfuck comprimido contiene uno o más comandos. Los dos bits superiores seleccionan entre una de cuatro posibles lecturas de los seis bits inferiores, como sigue:

Codificación Bits
Traducción
singleton 00 abc abc
abc
par 00 abc def
abc seguido de def
tríada 10 ab cd ef
0ab luego 0cd luego 0ef
repetición 01 abc def
def repetido 2 + abc veces (2-9)
0ef repetido 2 + abcd veces (2-17)

ERRORES

El compilador emitirá un mensaje de error y la compilación fallará si el programa contiene comandos de corchete desbalanceados, o si el nivel de anidamiento de corchetes supera la capacidad máxima del compilador (que está fijada arbitrariamente en 256).
