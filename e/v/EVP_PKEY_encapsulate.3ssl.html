EVP_PKEY_encapsulate(3ssl)

Paquete: openssl

Licencias: Apache-2.0

EVP_PKEY_ENCAPSULATE(3ssl) OpenSSL EVP_PKEY_ENCAPSULATE(3ssl)

NOMBRE

EVP_PKEY_encapsulate_init, EVP_PKEY_auth_encapsulate_init, EVP_PKEY_encapsulate - Encapsulación de claves usando un algoritmo KEM con una clave pública

SINOPSIS

#include <openssl/evp.h>
int EVP_PKEY_encapsulate_init(EVP_PKEY_CTX *ctx, const OSSL_PARAM params[]);
int EVP_PKEY_auth_encapsulate_init(EVP_PKEY_CTX *ctx, EVP_PKEY *authpriv,
                                  const OSSL_PARAM params[]);
int EVP_PKEY_encapsulate(EVP_PKEY_CTX *ctx,
                         unsigned char *wrappedkey, size_t *wrappedkeylen,
                         unsigned char *genkey, size_t *genkeylen);

DESCRIPCIÓN

La EVP_PKEY_encapsulate_init() función inicializa un contexto de algoritmo de clave pública ctx para una operación de encapsulación y luego establece los params en el contexto de la misma manera que al llamar a EVP_PKEY_CTX_set_params(3). Tenga en cuenta que ctx generalmente es producido usando EVP_PKEY_CTX_new_from_pkey(3), especificando la clave pública a usar.

La EVP_PKEY_auth_encapsulate_init() función es similar a EVP_PKEY_encapsulate_init() pero también pasa una clave privada de autenticación authpriv que se utiliza durante el encapsulamiento.

La EVP_PKEY_encapsulate() función realiza una operación de encapsulamiento de clave pública usando ctx. El secreto compartido escrito en genkey puede usarse como entrada para la derivación de claves, típicamente para varios algoritmos simétricos. Su tamaño se escribe en genkeylen, que debe inicializarse al tamaño del búfer proporcionado.

El texto cifrado escrito en wrappedkey es una forma encapsulada, que se espera que solo sea utilizable por el poseedor de la clave privada correspondiente a la clave pública asociada con ctx. Este texto cifrado se comunica entonces al poseedor de la clave privada, quien puede usar EVP_PKEY_decapsulate(3) para recuperar de forma segura el mismo secreto compartido.

Si wrappedkey es NULL, entonces el tamaño máximo del búfer de salida se escribe en el parámetro *wrappedkeylen a menos que wrappedkeylen sea NULL, y el tamaño máximo del búfer de clave generada se escribe en *genkeylen a menos que genkeylen sea NULL.

Si wrappedkey no es NULL y la llamada es exitosa, entonces el secreto compartido generado se escribe en genkey y su tamaño se escribe en *genkeylen (que debe ser no-NULL). El texto cifrado encapsulado se escribe en wrappedkey y su tamaño se escribe en *wrappedkeylen (también debe ser no-NULL). El valor al que apunta wrappedlen contiene inicialmente el tamaño del búfer sin envolver de modo que su tamaño pueda ser validado por la llamada, asegurando que sea lo suficientemente grande para contener el resultado escrito en wrapped.

En ausencia de un conocimiento detallado previo de los internos del algoritmo KEM específico, los llamadores NO DEBEN asumir que el secreto compartido y el texto cifrado devueltos son necesariamente de la longitud máxima posible. Las longitudes devueltas a través de *wrappedkeylen y *genkeylen DEBERÍAN usarse para determinar las longitudes reales de las salidas.

NOTAS

Después de la llamada a EVP_PKEY_encapsulate_init(), los parámetros específicos del algoritmo para la operación pueden establecerse o modificarse usando EVP_PKEY_CTX_set_params(3).

VALORES DE RETORNO

EVP_PKEY_encapsulate_init(), EVP_PKEY_auth_encapsulate_init() y EVP_PKEY_encapsulate() devuelven 1 para éxito y 0 o un valor negativo para fallo. En particular, un valor de retorno de -2 indica que la operación no es soportada por el algoritmo de clave pública.

EJEMPLOS

Encapsular una clave RSASVE (para claves RSA).

#include <openssl/evp.h>
/*
 * NB: se asume que rsa_pub_key es una clave pública de otra parte.
 */
EVP_PKEY_CTX *ctx = NULL;
size_t secretlen = 0, outlen = 0;
unsigned char *out = NULL, *secret = NULL;
ctx = EVP_PKEY_CTX_new_from_pkey(libctx, rsa_pub_key, NULL);
if (ctx == NULL)
    /* Error */
if (EVP_PKEY_encapsulate_init(ctx, NULL) <= 0)
    /* Error */
/* Establecer el modo - solo 'RSASVE' es soportado actualmente */
 if (EVP_PKEY_CTX_set_kem_op(ctx, "RSASVE") <= 0)
    /* Error */
/* Determinar la longitud del búfer */
if (EVP_PKEY_encapsulate(ctx, NULL, &outlen, NULL, &secretlen) <= 0)
    /* Error */
out = OPENSSL_malloc(outlen);
secret = OPENSSL_malloc(secretlen);
if (out == NULL || secret == NULL)
    /* fallo de malloc */
/*
 * El 'secret' generado puede usarse como material de clave.
 * El 'out' encapsulado puede enviarse a otra parte que puede
 * desencapsularlo usando su clave privada para recuperar el 'secret'.
 */
if (EVP_PKEY_encapsulate(ctx, out, &outlen, secret, &secretlen) <= 0)
    /* Error */

VER TAMBIÉN

EVP_PKEY_CTX_new_from_pkey(3), EVP_PKEY_decapsulate(3), EVP_KEM-RSA(7), EVP_KEM-X25519(7), EVP_KEM-EC(7), EVP_KEM-ML-KEM-512(7), EVP_KEM-ML-KEM-768(7), EVP_KEM-ML-KEM-1024(7)

HISTORIA

Las funciones EVP_PKEY_encapsulate_init() y EVP_PKEY_encapsulate() se añadieron en OpenSSL 3.0. La función EVP_PKEY_auth_encapsulate_init() se añadió en OpenSSL 3.2.

El soporte para ML-KEM se añadió en OpenSSL 3.5.
