EVP_VerifyInit(3ssl)

Paquete: openssl

Licencias: Apache-2.0

EVP_VERIFYINIT(3ssl) OpenSSL EVP_VERIFYINIT(3ssl)

NOMBRE

EVP_VerifyInit_ex, EVP_VerifyInit, EVP_VerifyUpdate, EVP_VerifyFinal_ex, EVP_VerifyFinal - Funciones de verificación de firmas EVP

SINOPSIS

#include <openssl/evp.h>
int EVP_VerifyInit_ex(EVP_MD_CTX *ctx, const EVP_MD *type, ENGINE *impl);
int EVP_VerifyUpdate(EVP_MD_CTX *ctx, const void *d, unsigned int cnt);
int EVP_VerifyFinal_ex(EVP_MD_CTX *ctx, const unsigned char *sigbuf,
                       unsigned int siglen, EVP_PKEY *pkey,
                       OSSL_LIB_CTX *libctx, const char *propq);
int EVP_VerifyFinal(EVP_MD_CTX *ctx, unsigned char *sigbuf, unsigned int siglen,
                    EVP_PKEY *pkey);
int EVP_VerifyInit(EVP_MD_CTX *ctx, const EVP_MD *type);

DESCRIPCIÓN

Las rutinas de verificación de firmas EVP son una interfaz de alto nivel para firmas digitales.

EVP_VerifyInit_ex() configura el contexto de verificación ctx para usar el digest type del ENGINE impl. ctx debe ser creado llamando a EVP_MD_CTX_new() antes de llamar a esta función.

EVP_VerifyUpdate() hashea cnt bytes de datos en d en el contexto de verificación ctx. Esta función puede ser llamada varias veces en el mismo ctx para incluir datos adicionales.

EVP_VerifyFinal_ex() verifica los datos en ctx usando la clave pública pkey y siglen bytes en sigbuf. El contexto de librería libctx y la consulta de propiedad propq se usan al crear un contexto para usar con la clave pkey.

EVP_VerifyFinal() es similar a EVP_VerifyFinal_ex() pero usa los valores predeterminados de NULL para el contexto de librería libctx y la consulta de propiedad propq.

EVP_VerifyInit() inicializa el contexto de verificación ctx para usar la implementación predeterminada del digest type.

VALORES DE RETORNO

EVP_VerifyInit_ex() y EVP_VerifyUpdate() retornan 1 en caso de éxito y 0 en caso de fallo.

EVP_VerifyFinal_ex() y EVP_VerifyFinal() retornan 1 para una firma correcta, 0 para fallo y un valor negativo si ocurrió algún otro error.

Los códigos de error se pueden obtener mediante ERR_get_error(3).

NOTAS

La interfaz EVP para firmas digitales casi siempre debe usarse en preferencia a las interfaces de bajo nivel. Esto se debe a que el código entonces se vuelve transparente al algoritmo utilizado y mucho más flexible.

La llamada a EVP_VerifyFinal() finaliza internamente una copia del contexto de digest. Esto significa que las llamadas a EVP_VerifyUpdate() y EVP_VerifyFinal() se pueden hacer más tarde para hashear y verificar datos adicionales. Las aplicaciones pueden deshabilitar este comportamiento estableciendo el flag de contexto EVP_MD_CTX_FLAG_FINALISE mediante EVP_MD_CTX_set_flags(3).

Dado que solo se finaliza una copia del contexto de digest, el contexto debe limpiarse después de su uso llamando a EVP_MD_CTX_free() o se producirá una fuga de memoria.

Tenga en cuenta que no todos los proveedores admiten la continuación; en caso de que el proveedor seleccionado no permita duplicar contextos, EVP_VerifyFinal() finalizará el contexto de digest e intentar procesar datos adicionales a través de EVP_VerifyUpdate() resultará en un error.

ERRORES

Versiones anteriores de esta documentación indicaron erróneamente que las llamadas a EVP_VerifyUpdate() no se podían hacer después de llamar a EVP_VerifyFinal().

Dado que la clave pública se pasa en la llamada a EVP_SignFinal(), cualquier error relacionado con la clave privada (por ejemplo, una combinación inadecuada de clave y digest) no se indicará hasta después de que potencialmente se hayan pasado grandes cantidades de datos a través de EVP_SignUpdate().

No es posible cambiar los parámetros de firma usando estas funciones.

Los dos errores anteriores están corregidos en la función más nueva EVP_DigestVerify*().
