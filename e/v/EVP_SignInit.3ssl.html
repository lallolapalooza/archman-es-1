EVP_SignInit(3ssl)

Paquete: openssl

Licencias: Apache-2.0

EVP_SIGNINIT(3ssl) OpenSSL EVP_SIGNINIT(3ssl)

NOMBRE

EVP_SignInit, EVP_SignInit_ex, EVP_SignUpdate, EVP_SignFinal_ex, EVP_SignFinal - Funciones de firma EVP

SINOPSIS

#include <openssl/evp.h>
int EVP_SignInit_ex(EVP_MD_CTX *ctx, const EVP_MD *type, ENGINE *impl);
int EVP_SignUpdate(EVP_MD_CTX *ctx, const void *d, unsigned int cnt);
int EVP_SignFinal_ex(EVP_MD_CTX *ctx, unsigned char *md, unsigned int *s,
                     EVP_PKEY *pkey, OSSL_LIB_CTX *libctx, const char *propq);
int EVP_SignFinal(EVP_MD_CTX *ctx, unsigned char *sig, unsigned int *s,
                  EVP_PKEY *pkey);
void EVP_SignInit(EVP_MD_CTX *ctx, const EVP_MD *type);

DESCRIPCIÓN

Las rutinas de firma EVP son una interfaz de alto nivel para firmas digitales.

EVP_SignInit_ex() configura el contexto de firma ctx para usar el digest type del ENGINE impl. ctx debe crearse con EVP_MD_CTX_new() antes de llamar a esta función.

EVP_SignUpdate() hashea cnt bytes de datos en d al contexto de firma ctx. Esta función se puede llamar varias veces en el mismo ctx para incluir datos adicionales.

EVP_SignFinal_ex() firma los datos en ctx usando la clave privada pkey y coloca la firma en sig. El contexto de biblioteca libctx y la consulta de propiedad propq se usan al crear un contexto para usar con la clave pkey. sig debe tener al menos EVP_PKEY_get_size(pkey) bytes de tamaño. s es un parámetro de SALIDA y no se usa como parámetro de ENTRADA. El número de bytes de datos escritos (es decir, la longitud de la firma) se escribirá en el entero en s, se escribirán como máximo EVP_PKEY_get_size(pkey) bytes.

EVP_SignFinal() es similar a EVP_SignFinal_ex() pero usa valores predeterminados de NULL para el contexto de biblioteca libctx y la consulta de propiedad propq.

EVP_SignInit() inicializa un contexto de firma ctx para usar la implementación predeterminada del digest type.

VALORES DE RETORNO

EVP_SignInit_ex(), EVP_SignUpdate(), EVP_SignFinal_ex() y EVP_SignFinal() devuelven 1 para éxito y 0 para fallo.

Los códigos de error se pueden obtener mediante ERR_get_error(3).

NOTAS

La interfaz EVP para firmas digitales casi siempre debe usarse en lugar de las interfaces de bajo nivel. Esto se debe a que el código entonces se vuelve transparente al algoritmo utilizado y mucho más flexible.

Al firmar con algunos tipos de claves privadas, el generador de números aleatorios debe ser inicializado. Si la inicialización automática o la reinicialización del CSPRNG de OpenSSL falla debido a circunstancias externas (ver RAND(7)), la operación fallará.

La llamada a EVP_SignFinal() finaliza internamente una copia del contexto de digest. Esto significa que las llamadas a EVP_SignUpdate() y EVP_SignFinal() se pueden realizar más tarde para procesar y firmar datos adicionales. Las aplicaciones pueden deshabilitar este comportamiento estableciendo la bandera de contexto EVP_MD_CTX_FLAG_FINALISE a través de EVP_MD_CTX_set_flags(3).

Dado que solo se finaliza una copia del contexto de digest, el contexto debe limpiarse después de su uso llamando a EVP_MD_CTX_free() o se producirá una fuga de memoria.

Tenga en cuenta que no todos los proveedores admiten la continuación, en caso de que el proveedor seleccionado no permita duplicar contextos, EVP_SignFinal() finalizará el contexto de digest e intentar procesar datos adicionales a través de EVP_SignUpdate() resultará en un error.

ERRORES

Versiones anteriores de esta documentación indicaban erróneamente que las llamadas a EVP_SignUpdate() no se podían realizar después de llamar a EVP_SignFinal().

Dado que la clave privada se pasa en la llamada a EVP_SignFinal(), cualquier error relacionado con la clave privada (por ejemplo, una combinación inadecuada de clave y digest) no se indicará hasta después de que potencialmente grandes cantidades de datos hayan pasado por EVP_SignUpdate().

No es posible cambiar los parámetros de firma utilizando estas funciones.

Los dos errores anteriores se corrigen en las funciones más nuevas EVP_DigestSign*().
