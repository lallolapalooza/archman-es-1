EVP_PKEY_decapsulate(3ssl)

Paquete: openssl

Licencias: Apache-2.0

EVP_PKEY_DECAPSULATE(3ssl) OpenSSL EVP_PKEY_DECAPSULATE(3ssl)

NOMBRE

EVP_PKEY_decapsulate_init, EVP_PKEY_auth_decapsulate_init, EVP_PKEY_decapsulate - Desencapsulación de claves mediante un algoritmo KEM con una clave privada

SINOPSIS

#include <openssl/evp.h>
int EVP_PKEY_decapsulate_init(EVP_PKEY_CTX *ctx, const OSSL_PARAM params[]);
int EVP_PKEY_auth_decapsulate_init(EVP_PKEY_CTX *ctx, EVP_PKEY *authpub,
                                  const OSSL_PARAM params[]);
int EVP_PKEY_decapsulate(EVP_PKEY_CTX *ctx,
                         unsigned char *unwrapped, size_t *unwrappedlen,
                         const unsigned char *wrapped, size_t wrappedlen);

DESCRIPCIÓN

La función EVP_PKEY_decapsulate_init() inicializa un contexto de algoritmo de clave privada ctx para una operación de desencapsulación y luego establece los params en el contexto de la misma manera que al llamar a EVP_PKEY_CTX_set_params(3). Tenga en cuenta que ctx generalmente se produce usando EVP_PKEY_CTX_new_from_pkey(3), especificando la clave privada a utilizar.

La función EVP_PKEY_auth_decapsulate_init() es similar a EVP_PKEY_decapsulate_init() pero también pasa una clave pública de autenticación authpub que se utiliza durante la desencapsulación.

La función EVP_PKEY_decapsulate() realiza una operación de desencapsulación de clave privada utilizando ctx. Los datos a desencapsular se especifican utilizando los parámetros wrapped y wrappedlen (que deben ser no nulos).

El parámetro wrapped es un argumento de salida, al que se escribe el secreto compartido desencapsulado. El secreto compartido puede no coincidir con el valor del par, incluso cuando la desencapsulación devuelve éxito. En su lugar, el secreto compartido debe usarse para derivar una clave que se utiliza para autenticar los datos recibidos posteriormente del par. Si unwrapped es NULL, el tamaño del búfer del secreto compartido de salida se escribe en *unwrappedlen y no se realiza ninguna desencapsulación, lo que permite determinar el tamaño de búfer requerido en tiempo de ejecución. De lo contrario, los datos del secreto desencapsulado se escriben en unwrapped y la longitud del secreto compartido se escribe en *unwrappedlen.

Tenga en cuenta que el valor al que apunta unwrappedlen (que NO debe ser NULL) debe inicializarse con la longitud de unwrapped, para que la llamada pueda validar que tiene un tamaño suficiente para contener el resultado de la operación.

En ausencia de un conocimiento previo detallado de los detalles internos del algoritmo KEM específico, los llamadores NO DEBEN asumir que el secreto compartido devuelto es necesariamente de la longitud máxima posible. La longitud devuelta a través de *unwrappedlen DEBE usarse para determinar la longitud real de la salida.

NOTAS

Después de la llamada a EVP_PKEY_decapsulate_init(), los parámetros específicos del algoritmo para la operación pueden establecerse o modificarse utilizando EVP_PKEY_CTX_set_params(3).

VALORES DE RETORNO

EVP_PKEY_decapsulate_init(), EVP_PKEY_auth_decapsulate_init() y EVP_PKEY_decapsulate() devuelven 1 para éxito y 0 o un valor negativo para fallo. En particular, un valor de retorno de -2 indica que la operación no es compatible con el algoritmo de clave privada.

EJEMPLOS

Desencapsular datos usando RSA:

#include <openssl/evp.h>
/*
 * NOTA: asume que rsa_priv_key es una clave privada RSA,
 * y que in, inlen ya están configurados para contener datos encapsulados.
 */
EVP_PKEY_CTX *ctx = NULL;
size_t secretlen = 0;
unsigned char *secret = NULL;;
ctx = EVP_PKEY_CTX_new_from_pkey(libctx, rsa_priv_key, NULL);
if (ctx == NULL)
    /* Error */
if (EVP_PKEY_decapsulate_init(ctx, NULL) <= 0)
    /* Error */
/* Establecer el modo - solo 'RSASVE' es compatible actualmente */
if (EVP_PKEY_CTX_set_kem_op(ctx, "RSASVE") <= 0)
    /* Error */
/* Determinar la longitud del búfer */
if (EVP_PKEY_decapsulate(ctx, NULL, &secretlen, in, inlen) <= 0)
    /* Error */
secret = OPENSSL_malloc(secretlen);
if (secret == NULL)
    /* Fallo de malloc */
/* Los datos del secreto desencapsulado tienen una longitud de secretlen bytes */
if (EVP_PKEY_decapsulate(ctx, secret, &secretlen, in, inlen) <= 0)
    /* Error */

VER TAMBIÉN

EVP_PKEY_CTX_new_from_pkey(3), EVP_PKEY_encapsulate(3), EVP_KEM-RSA(7), EVP_KEM-X25519(7), EVP_KEM-EC(7), EVP_KEM-ML-KEM-512(7), EVP_KEM-ML-KEM-768(7), EVP_KEM-ML-KEM-1024(7)

HISTORIA

Las funciones EVP_PKEY_decapsulate_init() y EVP_PKEY_decapsulate() se añadieron en OpenSSL 3.0.

La función EVP_PKEY_auth_decapsulate_init() se añadió en OpenSSL 3.2.

El soporte para ML-KEM se añadió en OpenSSL 3.5.
