EVP_KDF-SSHKDF -

EVP_KDF de SSHKDF

DESCRIPCIÓ

N

Soporte para calcular el KDF SSHKDF a través de la API EVP_

KDF.

El algoritmo EVP_KDF-SSHKDF implementa la función de derivación de claves SSHKDF. Está definido en la RFC 4253, sección 7.2 y es utilizado por SSH para derivar IVs, claves de cifrado y claves de integridad. Se requieren cinco entradas para realizar la derivación de claves: la función de hash (por ejemplo, SHA256), la Clave Inicial, el Hash de Intercambio, el ID de Sesión y el tipo de clave de

derivación.

La salida se considera material de

claveado.

El proveedor FIPS de OpenSSL también soporta los siguientes

parámetros:
"fips-indicator" (OSSL_KDF_PARAM_FIPS_APPROVED_INDICATOR)
<entero>
Un getter que devuelve 1 si la operación está aprobada por FIPS, o 0 en caso contrario. Esto puede usarse después de llamar a EVP_KDF_derive. Devuelve 0 si algún parámetro relacionado con "***-check" está establecido en 0 y la verificación
falla.
"digest-check" (OSSL_KDF_PARAM_FIPS_DIGEST_CHECK)
<entero>
El valor por defecto de 1 causa un error durante EVP_KDF_CTX_set_params() si el digesto utilizado no está aprobado. Establecer esto en cero ignorará el error y establecerá el "fips-indicator" aprobado en 0. Esta opción rompe el cumplimiento de FIPS si causa que el "fips-indicator" aprobado devuelva 0.

NOTA

Se puede obtener un contexto para SSHKDF llamando

a:

EVP_KDF_CTX *kctx = EVP_KDF_CTX_new(kdf)

La longitud de salida de la derivación SSHKDF se especifica a través del parámetro keylen de la función EVP_KDF_derive(3). Dado que la longitud de salida de SSHKDF es variable, llamar a EVP_KDF_CTX_get_kdf_size(3) para obtener la longitud requerida no tiene sentido. El llamador debe asignar un búfer de la longitud deseada y pasar ese búfer a la función EVP_KDF_derive(3) ju

nto con la lon
gitud deseada.
