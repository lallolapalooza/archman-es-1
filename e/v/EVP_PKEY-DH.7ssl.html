Paquete: openssl

EVP_PKEY-DH(7ssl) OpenSSL EVP_PKEY-DH(7ssl)

NOMBRE

EVP_PKEY-DH, EVP_PKEY-DHX, EVP_KEYMGMT-DH, EVP_KEYMGMT-DHX - Soporte de tipo de clave y algoritmo EVP_PKEY DH y DHX

DESCRIPCIÓN

Para el acuerdo de claves Diffie-Hellman de campo finito, se pueden usar dos clases de parámetros de dominio: parámetros de dominio "seguros" que están asociados con grupos seguros con nombre aprobados, y una clase de parámetros de dominio de tipo "FIPS186". Los parámetros de dominio de tipo FIPS186 solo deben usarse para compatibilidad con versiones anteriores de aplicaciones existentes que no pueden actualizarse para usar los grupos seguros con nombre aprobados.

Vea EVP_PKEY-FFC(7) para más información sobre claves FFC.

El DH tipo de clave usa el formato PKCS#3 que guarda p y g, pero no el q valor. El DHX tipo de clave usa el formato X9.42 que guarda el valor de q y este debe usarse para FIPS186-4. Si se requiere validación de claves, los usuarios deben tener en cuenta los matices asociados con los parámetros estilo FIPS186-4 como se discute en "Validación de claves DH y DHX".

Parámetros de dominio DH y DHX

Además de los parámetros FFC comunes que todos los tipos de clave FFC deben soportar (vea "Parámetros FFC" en EVP_PKEY-FFC(7)) las implementaciones de tipo de clave DHX y DH soportan lo siguiente:

"group" (OSSL_PKEY_PARAM_GROUP_NAME) <cadena UTF8>
Establece o obtiene una cadena que asocia un DH o DHX grupo de primos seguras con nombre con valores conocidos para p, q y g.

Los siguientes valores pueden ser usados por los proveedores predeterminado y FIPS de OpenSSL: "ffdhe2048", "ffdhe3072", "ffdhe4096", "ffdhe6144", "ffdhe8192", "modp_2048", "modp_3072", "modp_4096", "modp_6144", "modp_8192".

Los siguientes valores adicionales también pueden ser usados por el proveedor predeterminado de OpenSSL: "modp_1536", "dh_1024_160", "dh_2048_224", "dh_2048_256".

Los grupos con nombre DH/DHX pueden ser validados fácilmente ya que los parámetros son bien conocidos. Para protocolos que solo transfieren p y g el valor de q también puede ser recuperado.

Parámetros adicionales DH y DHX

"encoded-pub-key" (OSSL_PKEY_PARAM_ENCODED_PUBLIC_KEY) <cadena de octetos>
Usado para obtener y establecer la codificación de la clave pública DH usada en un mensaje de intercambio de claves para el protocolo TLS. Vea EVP_PKEY_set1_encoded_public_key() y EVP_PKEY_get1_encoded_public_key().

Parámetros de dominio adicionales DH

"safeprime-generator" (OSSL_PKEY_PARAM_DH_GENERATOR) <entero>
Usado para la generación DH de primos seguras usando el código antiguo de generador de primos seguras. El valor predeterminado es 2. Se recomienda usar un grupo de primos seguras con nombre en su lugar, si se requiere validación de parámetros de dominio.

Las primos seguras generadas aleatoriamente no están permitidas por FIPS, por lo que establecer este valor para el proveedor FIPS de OpenSSL elegirá en su lugar un grupo de primos seguras con nombre basado en el tamaño de p.

Parámetros de generación de parámetros de dominio / clave DH y DHX

Además de los parámetros comunes de generación de claves FFC que todos los tipos de clave FFC deben soportar (vea "Parámetros de generación de claves FFC" en EVP_PKEY-FFC(7)) la implementación de tipo de clave DH y DHX soporta lo siguiente:

"type" (OSSL_PKEY_PARAM_FFC_TYPE) <cadena UTF8>
Establece el tipo de generación de parámetros. Para DH los valores válidos son:
"fips186_4"
"default"
"fips186_2"
Estos están descritos en "Parámetros de generación de claves FFC" en EVP_PKEY-FFC(7)
"group"
Esto especifica que un nombre de grupo de primos seguras con nombre será elegido usando el tipo "pbits".
"generator"
Un generador de primos seguras. Vea el tipo "safeprime-generator" arriba. Esto solo es válido para claves DH .
"pbits" (OSSL_PKEY_PARAM_FFC_PBITS) <entero sin signo>
Establece el tamaño (en bits) del primo 'p'.

Para "fips186_4" esto debe ser 2048. Para "fips186_2" esto debe ser 1024. Para "group" esto puede ser cualquiera de 2048, 3072, 4096, 6144 o 8192.

"priv_len" (OSSL_PKEY_PARAM_DH_PRIV_LEN) <entero>
Un valor opcional para establecer la longitud máxima de la clave privada generada. El valor predeterminado usado si esto no se establece es el valor máximo de BN_num_bits(q)). El valor mínimo al que esto puede establecerse es 2 * s. Donde s es la fuerza de seguridad de la clave que tiene valores de 112, 128, 152, 176 y 200 para tamaños de clave de 2048, 3072, 4096, 6144 y 8192.

Validación de claves DH y DHX

Para claves que no son un grupo con nombre, el estándar FIPS186-4 especifica que los valores usados para la generación de parámetros FFC también son requeridos para la validación de parámetros. Esto significa que los valores opcionales de parámetros de dominio FFC para seed, pcounter y gindex o hindex pueden necesitar ser almacenados con fines de validación. Para DHX el seed y pcounter pueden ser almacenados en datos ASN1 (pero el gindex o hindex no pueden ser almacenados). Se recomienda usar parámetros DH con un grupo de primos seguras con nombre en su lugar.

Con el proveedor FIPS de OpenSSL, EVP_PKEY_param_check(3) y EVP_PKEY_param_check_quick(3) se comportan de la siguiente manera: los parámetros se prueban si son un grupo de primos seguras aprobado O que los parámetros FFC se conforman a FIPS186-4 como se define en SP800-56Ar3 Aseguramientos de Validez de Parámetros de Dominio.

El proveedor predeterminado de OpenSSL usa verificaciones más simples que permiten que no haya q valor para compatibilidad con versiones anteriores, sin embargo EVP_PKEY_param_check(3) probará el p valor para ser un primo (y un primo seguro si q falta) lo que puede tomar un tiempo significativo. El EVP_PKEY_param_check_quick(3) evita las pruebas de primalidad.

EVP_PKEY_public_check(3) se conforma a SP800-56Ar3 Validación Completa de Clave Pública FFC.

EVP_PKEY_public_check_quick(3) se conforma a SP800-56Ar3 Validación Parcial de Clave Pública FFC cuando la clave es un grupo de primos seguras con nombre aprobado, de lo contrario es lo mismo que EVP_PKEY_public_check(3).

EVP_PKEY_private_check(3) prueba que la clave privada está en el rango correcto de acuerdo con SP800-56Ar3. El proveedor FIPS de OpenSSL requiere que el valor de q esté establecido (note que esto se establece implícitamente para grupos de primos seguras con nombre). Para compatibilidad con versiones anteriores el proveedor predeterminado de OpenSSL solo requiere que p esté establecido.

EVP_PKEY_pairwise_check(3) se conforma a SP800-56Ar3 Aseguramiento del Propietario de Consistencia por Pares.

EJEMPLOS

Un EVP_PKEY contexto puede ser obtenido llamando a:

EVP_PKEY_CTX *pctx = EVP_PKEY_CTX_new_from_name(NULL, "DH", NULL);

Una clave DH puede ser generada con un grupo de primos seguras con nombre llamando a:

int priv_len = 2 * 112;
OSSL_PARAM params[3];
EVP_PKEY *pkey = NULL;
EVP_PKEY_CTX *pctx = EVP_PKEY_CTX_new_from_name(NULL, "DH", NULL);
params[0] = OSSL_PARAM_construct_utf8_string("group", "ffdhe2048", 0);
/* "priv_len" es opcional */priv_len", &priv_len);
params[2] = OSSL_PARAM_construct_end();
EVP_PKEY_keygen_init(pctx);
EVP_PKEY_CTX_set_params(pctx, params);
EVP_PKEY_generate(pctx, &pkey);
...
EVP_PKEY_free(pkey);
EVP_PKEY_CTX_free(pctx);

DHX los parámetros de dominio pueden generarse según FIPS186-4 llamando a:

int gindex = 2;
unsigned int pbits = 2048;
unsigned int qbits = 256;
OSSL_PARAM params[6];
EVP_PKEY *param_key = NULL;
EVP_PKEY_CTX *pctx = NULL;
pctx = EVP_PKEY_CTX_new_from_name(NULL, "DHX", NULL);
EVP_PKEY_paramgen_init(pctx);
params[0] = OSSL_PARAM_construct_uint("pbits", &pbits);
params[1] = OSSL_PARAM_construct_uint("qbits", &qbits);
params[2] = OSSL_PARAM_construct_int("gindex", &gindex);
params[3] = OSSL_PARAM_construct_utf8_string("type", "fips186_4", 0);
params[4] = OSSL_PARAM_construct_utf8_string("digest", "SHA256", 0);
params[5] = OSSL_PARAM_construct_end();
EVP_PKEY_CTX_set_params(pctx, params);
EVP_PKEY_generate(pctx, &param_key);
EVP_PKEY_print_params(bio_out, param_key, 0, NULL);
...
EVP_PKEY_free(param_key);
EVP_PKEY_CTX_free(pctx);

A DH una clave puede generarse usando los parámetros de dominio llamando a:

EVP_PKEY *key = NULL;
EVP_PKEY_CTX *gctx = EVP_PKEY_CTX_new_from_pkey(NULL, param_key, NULL);
EVP_PKEY_keygen_init(gctx);
EVP_PKEY_generate(gctx, &key);
EVP_PKEY_print_private(bio_out, key, 0, NULL);
...
EVP_PKEY_free(key);
EVP_PKEY_CTX_free(gctx);

Para validar FIPS186-4 los parámetros de dominio DHX decodificados desde PEM o DER datos, puede ser necesario establecer en la clave valores adicionales utilizados durante la generación.

EVP_PKEY_todata(), OSSL_PARAM_merge(), y EVP_PKEY_fromdata() son útiles para añadir estos parámetros a la clave original o a los parámetros de dominio antes de la validación real. En el código de producción, los valores de retorno deben ser comprobados.

EVP_PKEY *received_domp = ...; /* parámetros recibidos y decodificados */
unsigned char *seed = ...;     /* y parámetros adicionales recibidos */
size_t seedlen = ...;          /* por otros medios, requeridos */
int gindex = ...;              /* para la validación */
int pcounter = ...;
int hindex = ...;
OSSL_PARAM extra_params[4];
OSSL_PARAM *domain_params = NULL;
OSSL_PARAM *merged_params = NULL;
EVP_PKEY_CTX *ctx = NULL, *validate_ctx = NULL;
EVP_PKEY *complete_domp = NULL;
EVP_PKEY_todata(received_domp, OSSL_KEYMGMT_SELECT_DOMAIN_PARAMETERS,
                &domain_params);
extra_params[0] = OSSL_PARAM_construct_octet_string("seed", seed, seedlen);
/*
 * NOTA: Para g no verificable use "hindex" en lugar de "gindex"
 * extra_params[1] = OSSL_PARAM_construct_int("hindex", &hindex);
 */
extra_params[1] = OSSL_PARAM_construct_int("gindex", &gindex);
extra_params[2] = OSSL_PARAM_construct_int("pcounter", &pcounter);
extra_params[3] = OSSL_PARAM_construct_end();
merged_params = OSSL_PARAM_merge(domain_params, extra_params);
ctx = EVP_PKEY_CTX_new_from_name(NULL, "DHX", NULL);
EVP_PKEY_fromdata_init(ctx);
EVP_PKEY_fromdata(ctx, &complete_domp, OSSL_KEYMGMT_SELECT_ALL,
                  merged_params);
validate_ctx = EVP_PKEY_CTX_new_from_pkey(NULL, complete_domp, NULL);
if (EVP_PKEY_param_check(validate_ctx) > 0)
    /* validacion_aprobada(); */
else
    /* validacion_fallida(); */
OSSL_PARAM_free(domain_params);
OSSL_PARAM_free(merged_params);
EVP_PKEY_CTX_free(ctx);
EVP_PKEY_CTX_free(validate_ctx);
EVP_PKEY_free(complete_domp);
