NOMBRE

EVP_KDF-KB - La implementación EVP_KDF basada en claves

DESCRIPCIÓN

El algoritmo EVP_KDF-KB implementa la función de derivación de claves basada en claves (KBKDF). KBKDF deriva una clave de la aplicación repetida de un MAC con clave a un secreto de entrada (y otros valores opcionales).

La salida se considera material de claveado.

Identidad

"KBKDF" es el nombre para esta implementación; puede usarse con la función EVP_KDF_fetch()

.

Parámetros soportados

Los parámetros soportados son:"mode" (OSSL_KDF_PARAM_MODE
) <cadena UTF8>
El parámetro mode determina qué variante de KBKDF usar - actualmente las opciones son "counter" y "feedback". "counter" es el predeterminado, y se usará si no se especifica."mac" (OSSL_KDF_PARAM_MAC
) <cadena UTF8>
El valor es CMAC, HMAC, KMAC128 o KMAC256."digest" (OSSL_KDF_PARAM_DIGEST
) <cadena UTF8>"cipher" (OSSL_KDF_PARAM_CIPHER
) <cadena UTF8>"properties" (OSSL_KDF_PARAM_PROPERTIES
) <cadena UTF8>"key" (OSSL_KDF_PARAM_KEY
) <cadena de octetos>"salt" (OSSL_KDF_PARAM_SALT
) <cadena de octetos>"info (OSSL_KDF_PARAM_INFO
) <cadena de octetos>"seed" (OSSL_KDF_PARAM_SEED
) <cadena de octetos>
El parámetro seed no se usa en modo counter."use-l" (OSSL_KDF_PARAM_KBKDF_USE_L
) <entero> Establecer a 0 para deshabilitar el uso del dato de entrada fija opcional 'L' (ver SP800-108). El valor predeterminado de 1
se usará si no se especifica."use-separator" (OSSL_KDF_PARAM_KBKDF_USE_SEPARATOR
) <entero> Establecer a 0 para deshabilitar el uso del dato de entrada fija opcional 'separador cero' (ver SP800-108) que se coloca entre la Etiqueta y el Contexto. El valor predeterminado de 1
se usará si no se especifica."r" (OSSL_KDF_PARAM_KBKDF_R
) <entero>

Establece el valor fijo 'r', que indica la longitud del contador en bits. Los valores soportados son8 ,16 ,24 y32 . El valor predeterminado de 32

se usará si no se especifica.

El proveedor FIPS de OpenSSL también soporta los siguientes parámetros:"fips-indicator" (OSSL_KDF_PARAM_FIPS_APPROVED_INDICATOR
) <entero>
Un getter que devuelve 1 si la operación está aprobada por FIPS, o 0 en caso contrario. Esto puede usarse después de llamar a EVP_KDF_derive. Devuelve 0 si "key-check" está establecido a 0 y la verificación falla."key-check" (OSSL_KDF_PARAM_FIPS_KEY_CHECK
) <entero> El valor predeterminado de 1 causa un error durante EVP_KDF_CTX_set_params()si la longitud de la clave de derivación de claves utilizada (OSSL_KDF_PARAM_KEY

) es más corta que 112 bits. Establecer esto a cero ignorará el error y establecerá el "fips-indicator" aprobado a 0. Esta opción rompe la conformidad con FIPS si hace que el "fips-indicator" aprobado devuelva 0.

Dependiendo de si mac es CMAC o HMAC, se requiere respectivamente digest o cipher, y el otro no se usa. No se usan para KMAC128 y KMAC256.

Los parámetros key, salt, info y seed corresponden a KI, Etiqueta, Contexto e IV (respectivamente) en SP800-108. Como en ese documento, salt, info y seed son opcionales y pueden omitirse. "mac", "digest", cipher" y "properties" se describen en "PARAMETERS" enEVP_KDF(3)

.

NOTAS

Un contexto para KBKDF puede obtenerse llamando a:

EVP_KDF *kdf = EVP_KDF_fetch(NULL, "KBKDF", NULL); EVP_KDF_CTX *kctx = EVP_KDF_CTX_new(kdf); La longitud de salida de un KBKDF se especifica a través del parámetro "keylen" de la función EVP_KDF_derive(3)

.

Tenga en cuenta que actualmente OpenSSL solo implementa los modos counter y feedback. Otras variantes pueden soportarse en el futuro.

EJEMPLOS

Este ejemplo deriva 10 bytes usando COUNTER-HMAC-SHA256, con KI "secret", Etiqueta "label" y Contexto "context".

EVP_KDF *kdf; EVP_KDF_CTX *kctx; unsigned char out[10]; OSSL_PARAM params[6], *p = params; kdf = EVP_KDF_fetch(NULL, "KBKDF", NULL); kctx = EVP_KDF_CTX_new(kdf); EVP_KDF_free(kdf); *p++ = OSSL_PARAM_construct_utf8_string(OSSL_KDF_PARAM_DIGEST, "SHA2-256", 0); *p++ = OSSL_PARAM_construct_utf8_string(OSSL_KDF_PARAM_MAC, "HMAC", 0); *p++ = OSSL_PARAM_construct_octet_string(OSSL_KDF_PARAM_KEY, "secret", strlen("secret")); *p++ = OSSL_PARAM_construct_octet_string(OSSL_KDF_PARAM_SALT, "label", strlen("label")); *p++ = OSSL_PARAM_construct_octet_string(OSSL_KDF_PARAM_INFO, "context", strlen("context")); *p = OSSL_PARAM_construct_end(); if (EVP_KDF_derive(kctx, out, sizeof(out), params) <= 0) error("EVP_KDF_derive"); EVP_KDF_CTX_free(kctx);

Este ejemplo deriva 10 bytes usando FEEDBACK-CMAC-AES256, con KI "secret", Etiqueta "label" e IV "sixteen bytes iv".

EVP_KDF *kdf; EVP_KDF_CTX *kctx; unsigned char out[10]; OSSL_PARAM params[8], *p = params; unsigned char *iv = "sixteen bytes iv"; kdf = EVP_KDF_fetch(NULL, "KBKDF", NULL); kctx = EVP_KDF_CTX_new(kdf); EVP_KDF_free(kdf); *p++ = OSSL_PARAM_construct_utf8_string(OSSL_KDF_PARAM_CIPHER, "AES256", 0); *p++ = OSSL_PARAM_construct_utf8_string(OSSL_KDF_PARAM_MAC, "CMAC", 0); *p++ = OSSL_PARAM_construct_utf8_string(OSSL_KDF_PARAM_MODE, "FEEDBACK", 0); *p++ = OSSL_PARAM_construct_octet_string(OSSL_KDF_PARAM_KEY, "secret", strlen("secret")); *p++ = OSSL_PARAM_construct_octet_string(OSSL_KDF_PARAM_SALT, "label", strlen("label")); *p++ = OSSL_PARAM_construct_octet_string(OSSL_KDF_PARAM_INFO, "context", strlen("context")); *p++ = OSSL_PARAM_construct_octet_string(OSSL_KDF_PARAM_SEED, iv, strlen(iv)); *p = OSSL_PARAM_construct_end(); if (EVP_KDF_derive(kctx, out, sizeof(out), params) <= 0) error("EVP_KDF_derive"); EVP_KDF_CTX_free(kctx);
