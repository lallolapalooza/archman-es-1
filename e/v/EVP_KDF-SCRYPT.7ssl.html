EVP_KDF-SCRYPT(7ssl) OpenSSL EVP_KDF-SCRYPT(7ssl)

NOMBRE

EVP_KDF-SCRYPT - La implementación de EVP_KDF scrypt

DESCRIPCIÓN

Soporte para calcular la KDF basada en contraseña scrypt a través de la API EVP_KDF.

El algoritmo EVP_KDF-SCRYPT implementa la función de derivación de clave basada en contraseña scrypt, tal como se describe en RFC 7914. Es resistente a la memoria en el sentido de que deliberadamente requiere una cantidad significativa de RAM para un cálculo eficiente. La intención de esto es hacer que la fuerza bruta de contraseñas en sistemas que carecen de grandes cantidades de memoria principal (como GPUs o ASICs) sea computacionalmente inviable.

scrypt proporciona tres factores de trabajo que se pueden personalizar: N, r y p. N, que debe ser una potencia positiva de dos, es el factor de trabajo general y escala el tiempo de CPU de manera aproximadamente lineal. r es el tamaño del bloque de la función hash utilizada internamente y p es el factor de paralelización. Tanto r como p deben ser mayores que cero. La cantidad de RAM que scrypt requiere para su cálculo es aproximadamente (128 * N * r * p) bytes.

En el artículo original de Colin Percival ("Stronger Key Derivation Via Sequential Memory-Hard Functions", 2009), los valores sugeridos que dan un tiempo de cálculo de menos de 5 segundos en un Intel Core 2 Duo de 2.5 GHz son N = 2^20 = 1048576, r = 8, p = 1. En consecuencia, la cantidad de memoria requerida para este cálculo es aproximadamente 1 GiB. En una CPU más reciente (Intel i7-5930K a 3.5 GHz), este cálculo tarda aproximadamente 3 segundos. Cuando N, r o p no se especifican, por defecto son 1048576, 8 y 1, respectivamente. La cantidad máxima de RAM que puede usar scrypt por defecto es 1025 MiB.

Identidad

"SCRYPT" es el nombre de esta implementación; se puede usar con la función EVP_KDF_fetch().

Parámetros soportados

Los parámetros soportados son:

"pass" (OSSL_KDF_PARAM_PASSWORD) <cadena de octetos>
"salt" (OSSL_KDF_PARAM_SALT) <cadena de octetos>
Estos parámetros funcionan como se describe en "PARÁMETROS" en EVP_KDF(3).
"n" (OSSL_KDF_PARAM_SCRYPT_N) <entero sin signo>
"r" (OSSL_KDF_PARAM_SCRYPT_R) <entero sin signo>
"p" (OSSL_KDF_PARAM_SCRYPT_P) <entero sin signo>
"maxmem_bytes" (OSSL_KDF_PARAM_SCRYPT_MAXMEM) <entero sin signo>
Estos parámetros configuran los factores de trabajo de scrypt N, r, maxmem y p. Tanto N como maxmem_bytes son parámetros de tipo uint64_t. Tanto r como p son parámetros de tipo uint32_t.
"properties" (OSSL_KDF_PARAM_PROPERTIES) <cadena UTF8>
Esto se puede usar para establecer la cadena de consulta de propiedades al obtener el digest fijo internamente. Se usa NULL si este valor no está establecido.

NOTAS

Se puede obtener un contexto para scrypt llamando a:

EVP_KDF *kdf = EVP_KDF_fetch(NULL, "SCRYPT", NULL);
EVP_KDF_CTX *kctx = EVP_KDF_CTX_new(kdf);

La longitud de salida de una derivación de clave scrypt se especifica a través del parámetro "keylen" de la función EVP_KDF_derive(3).

EJEMPLOS

Este ejemplo deriva un vector de prueba de 64 bytes usando scrypt con la contraseña "password", salt "NaCl" y N = 1024, r = 8, p = 16.

EVP_KDF *kdf;
EVP_KDF_CTX *kctx;
unsigned char out[64];
OSSL_PARAM params[6], *p = params;
kdf = EVP_KDF_fetch(NULL, "SCRYPT", NULL);
kctx = EVP_KDF_CTX_new(kdf);
EVP_KDF_free(kdf);
*p++ = OSSL_PARAM_construct_octet_string(OSSL_KDF_PARAM_PASSWORD,
                                         "password", (size_t)8);
*p++ = OSSL_PARAM_construct_octet_string(OSSL_KDF_PARAM_SALT,
                                         "NaCl", (size_t)4);
*p++ = OSSL_PARAM_construct_uint64(OSSL_KDF_PARAM_SCRYPT_N, (uint64_t)1024);
*p++ = OSSL_PARAM_construct_uint32(OSSL_KDF_PARAM_SCRYPT_R, (uint32_t)8);
*p++ = OSSL_PARAM_construct_uint32(OSSL_KDF_PARAM_SCRYPT_P, (uint32_t)16);
*p = OSSL_PARAM_construct_end();
if (EVP_KDF_derive(kctx, out, sizeof(out), params) <= 0) {
    error("EVP_KDF_derive");
}
{
    const unsigned char expected[sizeof(out)] = {
        0xfd, 0xba, 0xbe, 0x1c, 0x9d, 0x34, 0x72, 0x00,
        0x78, 0x56, 0xe7, 0x19, 0x0d, 0x01, 0xe9, 0xfe,
        0x7c, 0x6a, 0xd7, 0xcb, 0xc8, 0x23, 0x78, 0x30,
        0xe7, 0x73, 0x76, 0x63, 0x4b, 0x37, 0x31, 0x62,
        0x2e, 0xaf, 0x30, 0xd9, 0x2e, 0x22, 0xa3, 0x88,
        0x6f, 0xf1, 0x09, 0x27, 0x9d, 0x98, 0x30, 0xda,
        0xc7, 0x27, 0xaf, 0xb9, 0x4a, 0x83, 0xee, 0x6d,
        0x83, 0x60, 0xcb, 0xdf, 0xa2, 0xcc, 0x06, 0x40
    };
    assert(!memcmp(out, expected, sizeof(out)));
}
EVP_KDF_CTX_free(kctx);
