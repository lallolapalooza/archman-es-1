VERSIONES

Diferencias entre la biblioteca/núcleo

Existen dos llamadas al sistema subyacentes de Linux: eventfd() y la más reciente eventfd2(). La primera llamada al sistema no implementa un argumento flags . La segunda llamada al sistema implementa los valores de flags descritos arriba. La función envoltorio de glibc usará eventfd2() cuando esté disponible.

Características adicionales de glibc

La biblioteca C de GNU define un tipo adicional y dos funciones que intentan abstraer algunos de los detalles de la lectura y escritura en un descriptor de archivo eventfd:


typedef uint64_t eventfd_t;
int eventfd_read(int fd, eventfd_t *value);
int eventfd_write(int fd, eventfd_t value);

Las funciones realizan las operaciones de lectura y escritura en un descriptor de archivo eventfd, devolviendo 0 si se transfirió el número correcto de bytes, o -1 en caso contrario.

NOTAS

Las aplicaciones pueden usar un descriptor de archivo eventfd en lugar de una tubería (ver pipe(2)) en todos los casos donde una tubería se usa simplemente para señalizar eventos. La sobrecarga en el núcleo de un descriptor de archivo eventfd es mucho menor que la de una tubería, y solo se requiere un descriptor de archivo (frente a los dos requeridos para una tubería).

Cuando se usa en el núcleo, un descriptor de archivo eventfd puede proporcionar un puente del núcleo al espacio de usuario, permitiendo, por ejemplo, funcionalidades como KAIO (AIO del núcleo) señalizar a un descriptor de archivo que alguna operación está completa.

Un punto clave sobre un descriptor de archivo eventfd es que puede ser monitoreado como cualquier otro descriptor de archivo usando select(2), poll(2), o epoll(7). Esto significa que una aplicación puede monitorear simultáneamente la disponibilidad de archivos "tradicionales" y la disponibilidad de otros mecanismos del núcleo que soportan la interfaz eventfd. (Sin la interfaz eventfd(), estos mecanismos no podrían ser multiplexados vía select(2), poll(2), o epoll(7).)

El valor actual de un contador eventfd puede ser visto a través de la entrada para el descriptor de archivo correspondiente en el directorio /proc/pid/fdinfo del proceso. Ver proc(5) para más detalles.

EJEMPLOS

El siguiente programa crea un descriptor de archivo eventfd y luego hace un fork para crear un proceso hijo. Mientras el padre duerme brevemente, el hijo escribe cada uno de los enteros proporcionados en los argumentos de la línea de comandos del programa en el descriptor de archivo eventfd. Cuando el padre termina de dormir, lee del descriptor de archivo eventfd.

La siguiente sesión de shell muestra una ejecución de muestra del programa:


$ ./a.out 1 2 4 7 14
Child writing 1 to efd
Child writing 2 to efd
Child writing 4 to efd
Child writing 7 to efd
Child writing 14 to efd
Child completed write loop
Parent about to read
Parent read 28 (0x1c) from efd

Fuente del programa

#include <err.h>
#include <inttypes.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/eventfd.h>
#include <sys/types.h>
#include <unistd.h>
int
main(int argc, char *argv[])
{
    int       efd;
    uint64_t  u;
    ssize_t   s;
    if (argc < 2) {
        fprintf(stderr, "Usage: %s <num>...\n", argv[0]);
        exit(EXIT_FAILURE);
    }
    efd = eventfd(0, 0);
    if (efd == -1)
        err(EXIT_FAILURE, "eventfd");
    switch (fork()) {
    case 0:
        for (size_t j = 1; j < argc; j++) {
            printf("Child writing %s to efd\n", argv[j]);
            u = strtoull(argv[j], NULL, 0);
                    /* strtoull() allows various bases */
            s = write(efd, &u, sizeof(uint64_t));
            if (s != sizeof(uint64_t))
                err(EXIT_FAILURE, "write");
        }
        printf("Child completed write loop\n");
        exit(EXIT_SUCCESS);
    default:
        sleep(2);
        printf("Parent about to read\n");
        s = read(efd, &u, sizeof(uint64_t));
        if (s != sizeof(uint64_t))
            err(EXIT_FAILURE, "read");
        printf("Parent read %"PRIu64" (%#"PRIx64") from efd\n", u, u);
        exit(EXIT_SUCCESS);
    case -1:
        err(EXIT_FAILURE, "fork");
    }
}
