NAME

EVP_SIGNATURE-ED25519, EVP_SIGNATURE-ED448, Ed25519, Ed448 - Soporte para EVP_PKEY Ed25519 y Ed448

DESCRIPTION

La implementación Ed25519 y Ed448 de EVP_PKEY soporta la generación de claves, firma de digest en un solo paso y verificación de digest utilizando los esquemas de firma EdDSA descritos en la RFC 8032. Tiene formatos de claves privadas y públicas asociados compatibles con la RFC 8410.

Instancias EdDSA

La RFC 8032 describe cinco instancias EdDSA: Ed25519, Ed25519ctx, Ed25519ph, Ed448, Ed448ph.

Las instancias Ed25519, Ed25519ctx, Ed448 se denominan esquemas PureEdDSA. Para estas tres instancias, los procedimientos de firma y verificación requieren acceso al mensaje completo (no un digest del mensaje).

Las instancias Ed25519ph, Ed448ph se denominan esquemas HashEdDSA. Para estas dos instancias, los procedimientos de firma y verificación no requieren acceso al mensaje completo; operan sobre un hash del mensaje. Para Ed25519ph, la función de hash es SHA512. Para Ed448ph, la función de hash es SHAKE256 con una longitud de salida de 512 bits.

Las instancias Ed25519ctx, Ed25519ph, Ed448, Ed448ph aceptan una cadena opcional context-string como entrada para las operaciones de firma y verificación (y para Ed25519ctx, la cadena context-string debe no estar vacía). Para la instancia Ed25519, una cadena context-string no vacía no está permitida.

Estas instancias pueden especificarse como parámetros de firma cuando se utiliza EVP_DigestSignInit(3) y EVP_DigestVerifyInit(3), véase "Parámetros de firma ED25519 y ED448" a continuación.

Estas instancias también se pueden recuperar explícitamente como algoritmos utilizando EVP_SIGNATURE_fetch(3), lo cual se puede usar con EVP_PKEY_sign_init_ex2(3), EVP_PKEY_verify_init_ex2(3), EVP_PKEY_sign_message_init(3) y EVP_PKEY_verify_message_init(3).

Parámetros de firma ED25519 y ED448

Se pueden establecer dos parámetros durante la firma o verificación: el nombre de instancia EdDSA y el valor de context-string. Se pueden establecer pasando un array OSSL_PARAM a EVP_DigestSignInit_ex().

  • "instance" (OSSL_SIGNATURE_PARAM_INSTANCE) <cadena utf8>

    Una de las cinco cadenas "Ed25519", "Ed25519ctx", "Ed25519ph", "Ed448", "Ed448ph".

    "Ed25519", "Ed25519ctx", "Ed25519ph" son válidos solo para un EVP_PKEY Ed25519.

    "Ed448", "Ed448ph" son válidos solo para un EVP_PKEY Ed448.

  • "context-string" (OSSL_SIGNATURE_PARAM_CONTEXT_STRING) <cadena de octetos>

    Una cadena de octetos con longitud de al menos 255.

Ambos parámetros son opcionales.

Al utilizar EVP_DigestSignInit(3) o EVP_DigestVerifyInit(3), el algoritmo de firma se deriva del nombre del tipo de clave. El nombre del tipo de clave ("Ed25519" o "Ed448") también es el predeterminado para la instancia, pero esto puede cambiarse con el parámetro "instance".

Tenga en cuenta que el nombre de un digest de mensaje NO debe especificarse al firmar o verificar.

Al utilizar EVP_PKEY_sign_init_ex2(3), EVP_PKEY_verify_init_ex2(3), EVP_PKEY_sign_message_init(3) o EVP_PKEY_verify_message_init(3), la instancia es el nombre explícito del algoritmo de firma y no puede cambiarse (intentar darle uno con el parámetro "instance" es, por lo tanto, un error).

Si no se especifica una cadena context-string, se utiliza una cadena context-string vacía.

Véase EVP_PKEY-X25519(7) para información relacionada con las claves X25519 y X448.

Los siguientes parámetros de firma se pueden recuperar utilizando EVP_PKEY_CTX_get_params().

  • "algorithm-id" (OSSL_SIGNATURE_PARAM_ALGORITHM_ID) <cadena de octetos>
  • "instance" (OSSL_SIGNATURE_PARAM_INSTANCE) <cadena utf8>
  • "context-string" (OSSL_SIGNATURE_PARAM_CONTEXT_STRING) <cadena de octetos>

Los parámetros se describen en provider-signature(7).

NOTAS

Las instancias PureEdDSA no soportan el mecanismo de transmisión de otros algoritmos de firma que utilizan, por ejemplo, EVP_DigestUpdate(). El mensaje a firmar o verificar debe pasarse utilizando las funciones EVP_DigestSign() y EVP_DigestVerify() en un solo paso.

Las instancias HashEdDSA aún no soportan los mecanismos de transmisión (por lo que las funciones en un solo paso también deben usarse con HashEdDSA).

Al llamar a EVP_DigestSignInit() o EVP_DigestVerifyInit(), el parámetro de tipo digest DEBE establecerse en NULL.

Las aplicaciones que desean firmar certificados (u otras estructuras como CRLs o solicitudes de certificados) utilizando Ed25519 o Ed448 pueden utilizar X509_sign() o X509_sign_ctx() de la manera habitual.

Las claves privadas Ed25519 o Ed448 se pueden establecer directamente utilizando EVP_PKEY_new_raw_private_key(3) o cargarse desde un archivo de clave privada PKCS#8 utilizando PEM_read_bio_PrivateKey(3) (o una función similar). También se pueden generar completamente nuevas claves (véase el ejemplo a continuación). Establecer una clave privada también establece la clave pública asociada.

Las claves públicas Ed25519 o Ed448 se pueden establecer directamente utilizando EVP_PKEY_new_raw_public_key(3) o cargarse desde una estructura SubjectPublicKeyInfo en un archivo PEM utilizando PEM_read_bio_PUBKEY(3) (o una función similar).

Ed25519 y Ed448 se pueden probar con la aplicación openssl-speed(1) desde la versión 1.1.1. Los nombres de algoritmo válidos son ed25519, ed448 y eddsa. Si se especifica eddsa, se benchmarkean tanto Ed25519 como Ed448.

EJEMPLOS

Para firmar un mensaje utilizando una estructura EVP_PKEY ED25519:

void do_sign(EVP_PKEY *ed_key, unsigned char *msg, size_t msg_len)
{
    size_t sig_len;
    unsigned char *sig = NULL;
    EVP_MD_CTX *md_ctx = EVP_MD_CTX_new();
    const OSSL_PARAM params[] = {
        OSSL_PARAM_utf8_string ("instance", "Ed25519ctx", 10),
        OSSL_PARAM_octet_string("context-string", (unsigned char *)"A protocol defined context string", 33),
        OSSL_PARAM_END
    };
    /* La entrada "params" no es necesaria si se aceptan las opciones predeterminadas.
       Use NULL en lugar de "params" en ese caso. */
    EVP_DigestSignInit_ex(md_ctx, NULL, NULL, NULL, NULL, ed_key, params);
    /* Calcule el tamaño necesario para la firma pasando un buffer NULL. */
    EVP_DigestSign(md_ctx, NULL, &sig_len, msg, msg_len);
    sig = OPENSSL_zalloc(sig_len);
    EVP_DigestSign(md_ctx, sig, &sig_len, msg, msg_len);
    ...
    OPENSSL_free(sig);
    EVP_MD_CTX_free(md_ctx);
}
