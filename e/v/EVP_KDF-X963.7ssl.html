NOMBRE

EVP_KDF-X963 - La implementación EVP_KDF de X9.63-2001

DESCRIPCIÓN

El algoritmo EVP_KDF-X963 implementa la función de derivación de clave (X963KDF). X963KDF es utilizado por Cryptographic Message Syntax (CMS) para EC KeyAgreement, para derivar una clave utilizando entradas como una clave secreta compartida e información compartida.

La salida se considera material de clave.

Identidad

"X963KDF" es el nombre de esta implementación; se puede usar con la función EVP_KDF_fetch().

Parámetros soportados

Los parámetros soportados son:

"properties" (OSSL_KDF_PARAM_PROPERTIES) <cadena UTF8>
"digest" (OSSL_KDF_PARAM_DIGEST) <cadena UTF8>
Estos parámetros funcionan como se describe en "PARÁMETROS" en EVP_KDF(3).
"key" (OSSL_KDF_PARAM_KEY) <cadena de octetos>
El secreto compartido utilizado para la derivación de claves. Este parámetro establece el secreto.
"info" (OSSL_KDF_PARAM_INFO) <cadena de octetos>
Este parámetro especifica un valor opcional para la información compartida.

El proveedor FIPS de OpenSSL también soporta los siguientes parámetros:

"fips-indicator" (OSSL_KDF_PARAM_FIPS_APPROVED_INDICATOR) <entero>
Un getter que devuelve 1 si la operación está aprobada por FIPS, o 0 en caso contrario. Esto se puede usar después de llamar a EVP_KDF_derive. Devuelve 0 si algún parámetro relacionado con "***-check" se establece en 0 y la verificación falla.
"digest-check" (OSSL_KDF_PARAM_FIPS_DIGEST_CHECK) <int>
El valor predeterminado de 1 causa un error durante EVP_KDF_CTX_set_params() si el digest utilizado no está aprobado. Establecer esto a cero ignorará el error y establecerá el "fips-indicator" aprobado en 0. Esta opción rompe el cumplimiento de FIPS si hace que el "fips-indicator" aprobado devuelva 0.

Según ANSI X9.63-2001, los siguientes son algoritmos de digest aprobados: SHA2-224, SHA2-256, SHA2-384, SHA2-512, SHA2-512/224, SHA2-512/256, SHA3-224, SHA3-256, SHA3-384, SHA3-512.

"key-check" (OSSL_KDF_PARAM_FIPS_KEY_CHECK) <entero>
El valor predeterminado de 1 causa un error durante EVP_KDF_CTX_set_params() si la longitud de la clave de derivación de clave utilizada (OSSL_KDF_PARAM_KEY) es inferior a 112 bits. Establecer esto a cero ignorará el error y establecerá el "fips-indicator" aprobado en 0. Esta opción rompe el cumplimiento de FIPS si hace que el "fips-indicator" aprobado devuelva 0.

NOTAS

X963KDF es muy similar a SSKDF, que utiliza un digest como función auxiliar. X963KDF anexa el contador al secreto, mientras que SSKDF antepone el contador.

Se puede obtener un contexto para X963KDF llamando a:

EVP_KDF *kdf = EVP_KDF_fetch(NULL, "X963KDF", NULL);
EVP_KDF_CTX *kctx = EVP_KDF_CTX_new(kdf);

La longitud de salida de un X963KDF se especifica a través del parámetro keylen en la función EVP_KDF_derive(3).

EJEMPLOS

Este ejemplo deriva 10 bytes, con la clave secreta "secret" y el valor de información compartida "label":

EVP_KDF *kdf;
EVP_KDF_CTX *kctx;
unsigned char out[10];
OSSL_PARAM params[4], *p = params;
kdf = EVP_KDF_fetch(NULL, "X963KDF", NULL);
kctx = EVP_KDF_CTX_new(kdf);
EVP_KDF_free(kdf);
*p++ = OSSL_PARAM_construct_utf8_string(OSSL_KDF_PARAM_DIGEST,
                                        SN_sha256, strlen(SN_sha256));
*p++ = OSSL_PARAM_construct_octet_string(OSSL_KDF_PARAM_SECRET,
                                         "secret", (size_t)6);
*p++ = OSSL_PARAM_construct_octet_string(OSSL_KDF_PARAM_INFO,
                                         "label", (size_t)5);
*p = OSSL_PARAM_construct_end();
if (EVP_KDF_derive(kctx, out, sizeof(out), params) <= 0) {
    error("EVP_KDF_derive");
}
EVP_KDF_CTX_free(kctx);
