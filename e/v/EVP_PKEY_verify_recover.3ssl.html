EVP_PKEY_verify_recover(3ssl)

Paquete: openssl

Licencias: Apache-2.0

EVP_PKEY_VERIFY_RECOVER(3ssl) OpenSSL EVP_PKEY_VERIFY_RECOVER(3ssl)

NOMBRE

EVP_PKEY_verify_recover_init, EVP_PKEY_verify_recover_init_ex, EVP_PKEY_verify_recover_init_ex2, EVP_PKEY_verify_recover - recuperar la firma usando un algoritmo de clave pública

SINOPSIS

#include <openssl/evp.h>
int EVP_PKEY_verify_recover_init(EVP_PKEY_CTX *ctx);
int EVP_PKEY_verify_recover_init_ex(EVP_PKEY_CTX *ctx,
                                    const OSSL_PARAM params[]);
int EVP_PKEY_verify_recover_init_ex2(EVP_PKEY_CTX *ctx, EVP_SIGNATURE *algo,
                                     const OSSL_PARAM params[]);
int EVP_PKEY_verify_recover(EVP_PKEY_CTX *ctx,
                            unsigned char *rout, size_t *routlen,
                            const unsigned char *sig, size_t siglen);

DESCRIPCIÓN

EVP_PKEY_verify_recover_init() inicializa un contexto de algoritmo de clave pública ctx para firmar usando el algoritmo dado cuando se creó el contexto mediante EVP_PKEY_CTX_new(3) o variantes del mismo. El algoritmo se utiliza para obtener un método EVP_SIGNATURE implícitamente, véase "Obtención implícita" en provider(7) para más información sobre obtenciones implícitas.

EVP_PKEY_verify_recover_init_ex() es lo mismo que EVP_PKEY_verify_recover_init() pero además establece los parámetros proporcionados params en el contexto antes de devolver.

EVP_PKEY_verify_recover_init_ex2() es lo mismo que EVP_PKEY_verify_recover_init_ex(), pero funciona con un método EVP_SIGNATURE obtenido explícitamente algo. Un contexto ctx sin una clave precargada no puede usarse con esta función. Dependiendo del algoritmo obtenido, ciertos detalles sobre el tratamiento de la entrada a EVP_PKEY_verify() pueden estar predeterminados y, en ese caso, esos detalles normalmente no pueden cambiarse. Véase "NOTAS" más abajo para una explicación más profunda.

La función EVP_PKEY_verify_recover() recupera los datos firmados usando ctx. La firma se especifica usando los parámetros sig y siglen. Si rout es NULL entonces el tamaño máximo del búfer de salida se escribe en el parámetro routlen. Si rout no es NULL entonces antes de la llamada el parámetro routlen debe contener la longitud del búfer rout; si la llamada es exitosa, los datos recuperados se escriben en rout y la cantidad de datos escritos se indica en routlen.

NOTAS

Normalmente una aplicación solo está interesada en si una operación de verificación de firma es exitosa; en esos casos se debe usar la función EVP_verify().

A veces, sin embargo, es útil obtener los datos originalmente firmados mediante una operación de firma. Solo ciertos algoritmos de clave pública pueden recuperar una firma de esta manera (por ejemplo, RSA en modo de relleno PKCS).

Después de la llamada a EVP_PKEY_verify_recover_init() se pueden realizar operaciones de control específicas del algoritmo para establecer cualquier parámetro apropiado para la operación.

Después de la llamada a EVP_PKEY_verify_recover_init_ex2(), las operaciones de control específicas del algoritmo pueden no ser necesarias si el algoritmo elegido implica que dichos controles están preestablecidos (e inmutables).

La función EVP_PKEY_verify_recover() puede llamarse más de una vez en el mismo contexto si se realizan varias operaciones usando los mismos parámetros.

VALORES DE RETORNO

EVP_PKEY_verify_recover_init() y EVP_PKEY_verify_recover() devuelven 1 en caso de éxito y 0 o un valor negativo en caso de fallo. En particular, un valor de retorno de -2 indica que la operación no es compatible con el algoritmo de clave pública.

EJEMPLOS

Recuperar el digest originalmente firmado usando PKCS#1 y digest SHA256:

#include <openssl/evp.h>
#include <openssl/rsa.h>
EVP_PKEY_CTX *ctx;
unsigned char *rout, *sig;
size_t routlen, siglen;
EVP_PKEY *verify_key;
/*
 * NOTA: asume que verify_key, sig y siglen ya están configurados
 * y que verify_key es una clave pública RSA
 */
ctx = EVP_PKEY_CTX_new(verify_key, NULL /* sin engine */);
if (!ctx)
    /* Ocurrió un error */
if (EVP_PKEY_verify_recover_init(ctx) <= 0)
    /* Error */
if (EVP_PKEY_CTX_set_rsa_padding(ctx, RSA_PKCS1_PADDING) <= 0)
    /* Error */
if (EVP_PKEY_CTX_set_signature_md(ctx, EVP_sha256()) <= 0)
    /* Error */
/* Determinar la longitud del búfer */
if (EVP_PKEY_verify_recover(ctx, NULL, &routlen, sig, siglen) <= 0)
    /* Error */
rout = OPENSSL_malloc(routlen);
if (!rout)
    /* Fallo de malloc */
if (EVP_PKEY_verify_recover(ctx, rout, &routlen, sig, siglen) <= 0)
    /* Error */
/* Los datos recuperados son routlen bytes escritos en el búfer rout */

VER TAMBIÉN

EVP_PKEY_CTX_new(3), EVP_PKEY_encrypt(3), EVP_PKEY_decrypt(3), EVP_PKEY_sign(3), EVP_PKEY_verify(3), EVP_PKEY_derive(3)

HISTORIA

Las funciones EVP_PKEY_verify_recover_init() y EVP_PKEY_verify_recover() se añadieron en OpenSSL 1.0.0.

La función EVP_PKEY_verify_recover_init_ex() se añadió en OpenSSL 3.0.
