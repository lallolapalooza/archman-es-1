EVP_DigestVerifyInit(3ssl)

Paquete: openssl

Licencias: Apache-2.0

EVP_DIGESTVERIFYINIT(3ssl) OpenSSL EVP_DIGESTVERIFYINIT(3ssl)

NOMBRE

EVP_DigestVerifyInit_ex, EVP_DigestVerifyInit, EVP_DigestVerifyUpdate, EVP_DigestVerifyFinal, EVP_DigestVerify - Funciones de verificación de firmas EVP

SINOPSIS

#include <openssl/evp.h>
int EVP_DigestVerifyInit_ex(EVP_MD_CTX *ctx, EVP_PKEY_CTX **pctx,
                            const char *mdname, OSSL_LIB_CTX *libctx,
                            const char *props, EVP_PKEY *pkey,
                            const OSSL_PARAM params[]);
int EVP_DigestVerifyInit(EVP_MD_CTX *ctx, EVP_PKEY_CTX **pctx,
                         const EVP_MD *type, ENGINE *e, EVP_PKEY *pkey);
int EVP_DigestVerifyUpdate(EVP_MD_CTX *ctx, const void *d, size_t cnt);
int EVP_DigestVerifyFinal(EVP_MD_CTX *ctx, const unsigned char *sig,
                          size_t siglen);
int EVP_DigestVerify(EVP_MD_CTX *ctx, const unsigned char *sig,
                     size_t siglen, const unsigned char *tbs, size_t tbslen);

DESCRIPCIÓN

Las rutinas de firma EVP son una interfaz de alto nivel para firmas digitales. Los datos de entrada se procesan primero antes de que tenga lugar la verificación de la firma.

EVP_DigestVerifyInit_ex() configura el contexto de verificación ctx para usar un resumen con el nombre mdname y la clave pública pkey. El nombre del resumen a usar se pasa al proveedor del algoritmo de firma en uso. Cómo ese proveedor interpreta el nombre del resumen es específico del proveedor. El proveedor puede implementar ese resumen directamente por sí mismo o puede (opcionalmente) optar por obtenerlo (lo que podría resultar en la selección de un resumen de un proveedor diferente). Si el proveedor soporta la obtención de resúmenes, entonces puede usar el argumento props para las propiedades a usar durante la obtención. Finalmente, los parámetros pasados params, si no son NULL, se establecen en el contexto antes de regresar.

El algoritmo pkey se usa para obtener implícitamente un método EVP_SIGNATURE , para ser usado para la firma real. Vea "Obtención implícita" en provider(7) para más información sobre las obtenciones implícitas.

Los proveedores por defecto y legacy de OpenSSL soportan la obtención de resúmenes y pueden obtener esos resúmenes de cualquier proveedor disponible. El proveedor FIPS de OpenSSL también soporta la obtención de resúmenes pero solo obtendrá resúmenes que estén implementados dentro del proveedor FIPS.

ctx debe ser creado con EVP_MD_CTX_new() antes de llamar a esta función. Si pctx no es NULL, el EVP_PKEY_CTX de la operación de verificación se escribirá en *pctx: esto puede usarse para establecer opciones de verificación alternativas. Note que cualquier valor existente en *pctx se sobrescribe. El valor EVP_PKEY_CTX devuelto no debe ser liberado directamente por la aplicación si ctx no tiene asignado un valor EVP_PKEY_CTX antes de ser pasado a EVP_DigestVerifyInit_ex() (lo que significa que el EVP_PKEY_CTX es creado dentro de EVP_DigestVerifyInit_ex() y se liberará automáticamente cuando el EVP_MD_CTX sea liberado). Si el EVP_PKEY_CTX a usar es creado por EVP_DigestVerifyInit_ex, entonces usará el OSSL_LIB_CTX especificado en libctx y la cadena de consulta de propiedades especificada en props.

No se creará ningún EVP_PKEY_CTX por EVP_DigestVerifyInit_ex() si el ctx pasado ya le ha sido asignado uno a través de EVP_MD_CTX_set_pkey_ctx(3). Vea también SM2(7).

No todos los resúmenes pueden usarse para todos los tipos de clave. Se aplican las siguientes combinaciones.

DSA
Soporta SHA1, SHA224, SHA256, SHA384 y SHA512
ECDSA
Soporta SHA1, SHA224, SHA256, SHA384, SHA512 y SM3
RSA sin relleno
No soporta resúmenes (el tipo de resumen type debe ser NULL)
RSA con relleno X931
Soporta SHA1, SHA256, SHA384 y SHA512
Todos los demás tipos de relleno RSA
Soportan SHA1, SHA224, SHA256, SHA384, SHA512, MD5, MD5_SHA1, MD2, MD4, MDC2, SHA3-224, SHA3-256, SHA3-384, SHA3-512
Ed25519 y Ed448
No soportan resúmenes (el tipo de resumen type debe ser NULL)
HMAC
Soporta cualquier resumen
CMAC, Poly1305 y Siphash
Ignorarán cualquier resumen proporcionado.

Si se usa RSA-PSS y se aplican restricciones, el resumen debe coincidir.

EVP_DigestVerifyInit() funciona de la misma manera que EVP_DigestVerifyInit_ex() excepto que el parámetro mdname se inferirá del resumen typeproporcionado, y props será NULL. Donde se proporcione, el ENGINE e se usará para las implementaciones del algoritmo de verificación de firmas y de resumen. e puede ser NULL.

EVP_DigestVerifyUpdate() hashea cnt bytes de datos en d en el contexto de verificación ctx. Esta función puede ser llamada varias veces en el mismo ctx para incluir datos adicionales.

EVP_DigestVerifyFinal() verifica los datos en ctx contra la firma en sig de longitud siglen.

EVP_DigestVerify() verifica tbslen bytes en tbs contra la firma en sig de longitud siglen.

VALORES DE RETORNO

EVP_DigestVerifyInit() y EVP_DigestVerifyUpdate() devuelven 1 para éxito y 0 para fallo.

EVP_DigestVerifyFinal() y EVP_DigestVerify() devuelven 1 para éxito; cualquier otro valor indica fallo. Un valor de retorno de cero indica que la firma no se verificó exitosamente (es decir, tbs no coincidió con los datos originales o la firma tenía una forma inválida), mientras que otros valores indican un error más serio (y a veces también indican una forma de firma inválida).

Los códigos de error pueden obtenerse de ERR_get_error(3).

NOTAS

La interfaz EVP para firmas digitales debe usarse casi siempre en lugar de las interfaces de bajo nivel. Esto se debe a que el código se vuelve transparente al algoritmo usado y mucho más flexible.

EVP_DigestVerify() es una operación de un solo disparo que verifica un solo bloque de datos en una función. Para algoritmos que soportan streaming es equivalente a llamar a EVP_DigestVerifyUpdate() y EVP_DigestVerifyFinal(). Para algoritmos que no soportan streaming (ej. PureEdDSA) es la única manera de verificar datos.

En versiones anteriores de OpenSSL había un enlace entre los tipos de resumen de mensajes y los algoritmos de clave pública. Esto significaba que los resúmenes "clon" como EVP_dss1() necesitaban usarse para firmar usando SHA1 y DSA. Esto ya no es necesario y el uso de resúmenes clon ahora está desalentado.

Para algunos tipos de clave y parámetros, el generador de números aleatorios debe ser sembrado. Si el siembra o re-siembra automática del CSPRNG de OpenSSL falla debido a circunstancias externas (vea RAND(7)), la operación fallará.

La llamada a EVP_DigestVerifyFinal() finaliza internamente una copia del contexto de resumen. Esto significa que EVP_VerifyUpdate() y EVP_VerifyFinal() pueden ser llamadas más tarde para hashear y verificar datos adicionales. Las aplicaciones pueden deshabilitar este comportamiento estableciendo el flag de contexto EVP_MD_CTX_FLAG_FINALISE a través de EVP_MD_CTX_set_flags(3).

Note que no todos los proveedores soportan la continuación; en caso de que el proveedor seleccionado no permita duplicar contextos, EVP_DigestVerifyFinal() finalizará el contexto de resumen y el intento de procesar datos adicionales a través de EVP_DigestVerifyUpdate() resultará en un error.

Las funciones EVP_DigestVerifyInit() y EVP_DigestVerifyInit_ex() pueden ser llamadas múltiples veces en un contexto y los parámetros establecidos por llamadas anteriores deberían preservarse si el parámetro pkey es NULL. La llamada entonces solo restablece el estado de ctx.

EVP_DigestVerify() solo puede ser llamado una vez, y no puede ser usado de nuevo sin reinicializar el EVP_MD_CTX llamando a EVP_DigestVerifyInit_ex().

Ignorar los retornos de fallo de las funciones EVP_DigestVerifyInit() y EVP_DigestVerifyInit_ex() puede llevar a un comportamiento indefinido posterior al llamar a EVP_DigestVerifyUpdate(), EVP_DigestVerifyFinal(), o EVP_DigestVerify().

HISTORIAL

EVP_DigestVerifyInit(), EVP_DigestVerifyUpdate() y EVP_DigestVerifyFinal() se añadieron en OpenSSL 1.0.0.

EVP_DigestVerifyInit_ex() se añadió en OpenSSL 3.0.

EVP_DigestVerifyUpdate() se convirtió de una macro a una función en OpenSSL 3.0.
