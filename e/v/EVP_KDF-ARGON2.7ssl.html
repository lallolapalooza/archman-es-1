EVP_KDF-ARGON2 -

La implementación
EVP KDF de Argon2

DESCRIPCIÓ

N

Soporte para calcular el KDF basado en contraseñas argon2 a través de la API EVP_

KDF.

El algoritmo EVP_KDF-ARGON2 implementa la función de derivación de claves basada en contraseñas Argon2, como se describe en el RFC 9106 de IETF. Es resistente a la memoria en el sentido de que requiere deliberadamente una cantidad significativa de RAM para un cálculo eficiente. La intención de esto es hacer que la fuerza bruta de contraseñas en sistemas que carecen de grandes cantidades de memoria principal (como GPUs o ASICs) sea computacionalmente

inviable.

Argon2d (Argon2i) utiliza acceso a memoria dependiente de los datos (independiente de los datos) y busca principalmente abordar ataques de compromiso (canales laterales)

.

Argon2id es una construcción híbrida que, en los dos primeros segmentos de la primera pasada, genera direcciones de referencia independientemente de los datos como en Argon2i, mientras que en segmentos posteriores y pasadas siguientes las genera dependientemente de los datos como en

Argon2d.

La versión reforzada con Sbox Argon2ds no es

compatible.

Para más información, consulte el RFC

9106.

Parámetros

admitidos

Los parámetros admitidos

son:
"pass" (OSSL_KDF_PARAM_PASSWORD) <cadena de
octetos>
"salt" (OSSL_KDF_PARAM_SALT) <cadena de
octetos>
"secret" (OSSL_KDF_PARAM_SECRET) <cadena de
octetos>
"iter" (OSSL_KDF_PARAM_ITER) <entero sin
signo>
"size" (OSSL_KDF_PARAM_SIZE) <entero sin
signo>
"properties" (OSSL_KDF_PARAM_PROPERTIES) <cadena
UTF8>
Estos parámetros funcionan como se describe en "PARAMETERS" en EVP_KDF(3).

Tenga en cuenta que el RFC 9106 recomienda una sal de 128 bits para la mayoría de las aplicaciones, o una sal de 64 bits en caso de restricciones de espacio. Se recomienda una longitud de salida de al menos 128

bits.

Tenga en cuenta que el secreto (o pimi

enta) son datos secretos opcionales qu
e se utilizan junto con la contraseña.
"threads" (OSSL_KDF_PARAM_THREADS) <entero sin
signo>
El número de hilos, limitado superiormente por el número de carriles.

Esto solo se puede usar con soporte de hilos integra

do. Los hilos deben estar habilitados explícitamente
. Consulte la sección EXAMPLES para más información.
"ad" (OSSL_KDF_PARAM_ARGON2_AD) <cadena de
octetos>
Datos asociados opcionales, pueden usarse para "etiquetar" un grupo de claves, o vincularlas a una clave pública particular, sin tener que modificar la
sal.
"lanes" (OSSL_KDF_PARAM_ARGON2_LANES) <entero sin
signo>
Argon2 divide el tamaño de memoria solicitado en carriles, cada uno de los cuales está diseñado para procesarse en paralelo. Por ejemplo, en un sistema con p núcleos, se recomienda usar p carriles.

El número de carriles se utiliza para derivar la clave. Es posible espe

cificar más carriles que el número de hilos de cálculo disponibles. Est
o se fomenta especialmente si el multiprocesamiento está deshabilitado.
"memcost" (OSSL_KDF_PARAM_ARGON2_MEMCOST) <entero sin
signo>
Parámetro de costo de memoria (el número de bloques de memoria de 1k utilizados)
.
"version" (OSSL_KDF_PARAM_ARGON2_VERSION) <entero sin
signo>
Versión de Argon2. Valores admitidos: 0x10, 0x13 (predeterminado)
.
"early_clean" (OSSL_KDF_PARAM_EARLY_CLEAN) <entero sin
signo>
Si se establece (distinto de cero), la contraseña y el secreto almacenados en el contexto de Argon2 se ponen a cero tempranamente durante el cálculo inicial del hash, tan pronto como ya no se necesitan. De lo contrario, se ponen a cero junto con el resto de los datos del contexto de Argon2 al limpiar, liberar, restablecer.

Esto puede ser útil si,

por ejemplo, se van a ge
nerar múltiples claves c
on diferentes valores d
e ad a partir de una úni
ca contraseña y secreto.

EJEMPLO

S

Este ejemplo usa Argon2d con la contraseña "1234567890", la sal "saltsalt", usando 2 carriles, 2 hilos y un costo de memoria de

65536: 
#include <string.h>                 /* strlen               */
#include <openssl/core_names.h>     /* OSSL_KDF_*           */
#include <openssl/params.h>         /* OSSL_PARAM_*         */
#include <openssl/thread.h>         /* OSSL_set_max_threads */
#include <openssl/kdf.h>            /* EVP_KDF_*            */
int main(void)
{
    int retval = 1;
    EVP_KDF *kdf = NULL;
    EVP_KDF_CTX *kctx = NULL;
    OSSL_PARAM params[6], *p = params;
    /* argon2 params, please refer to RFC9106 for recommended defaults */
    uint32_t lanes = 2, threads = 2, memcost = 65536;
    char pwd[] = "1234567890", salt[] = "saltsalt";
    /* derive result */
    size_t outlen = 128;
    unsigned char result[outlen];
    /* required if threads > 1 */
    if (OSSL_set_max_threads(NULL, threads) != 1)
        goto fail;
    p = params;
    *p++ = OSSL_PARAM_construct_uint32(OSSL_KDF_PARAM_THREADS, &threads);
    *p++ = OSSL_PARAM_construct_uint32(OSSL_KDF_PARAM_ARGON2_LANES,
                                       &lanes);
    *p++ = OSSL_PARAM_construct_uint32(OSSL_KDF_PARAM_ARGON2_MEMCOST,
                                       &memcost);
    *p++ = OSSL_PARAM_construct_octet_string(OSSL_KDF_PARAM_SALT,
                                             salt,
                                             strlen((const char *)salt));
    *p++ = OSSL_PARAM_construct_octet_string(OSSL_KDF_PARAM_PASSWORD,
                                             pwd,
                                             strlen((const char *)pwd));
    *p++ = OSSL_PARAM_construct_end();
    if ((kdf = EVP_KDF_fetch(NULL, "ARGON2D", NULL)) == NULL)
        goto fail;
    if ((kctx = EVP_KDF_CTX_new(kdf)) == NULL)
        goto fail;
    if (EVP_KDF_derive(kctx, &result[0], outlen, params) != 1)
        goto fail;
    printf("Output = %s\n", OPENSSL_buf2hexstr(result, outlen));
    retval = 0;
fail:
    EVP_KDF_free(kdf);
    EVP_KDF_CTX_free(kctx);
    OSSL_set_max_threads(NULL, 0);
    return retval;
}
