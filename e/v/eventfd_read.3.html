eventfd(2) Manual de Llamadas al Sistema eventfd(2)

NOMBRE

eventfd - crear un descriptor de archivo para notificación de eventos

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <sys/eventfd.h>
int eventfd(unsigned int initval, int flags);

DESCRIPCIÓN

eventfd() crea un "objeto eventfd" que puede ser utilizado como mecanismo de espera/notificación de eventos por aplicaciones del espacio de usuario, y por el kernel para notificar a las aplicaciones del espacio de usuario de eventos. El objeto contiene un contador entero sin signo de 64 bits (uint64_t) que es mantenido por el kernel. Este contador se inicializa con el valor especificado en el argumento initval.

Como valor de retorno, eventfd() devuelve un nuevo descriptor de archivo que puede ser utilizado para referirse al objeto eventfd.

Los siguientes valores pueden ser combinados con OR bit a bit en flags para cambiar el comportamiento de eventfd():

EFD_CLOEXEC (desde Linux 2.6.27)
Establece la bandera close-on-exec (FD_CLOEXEC) en el nuevo descriptor de archivo. Consulte la descripción de la bandera O_CLOEXEC en open(2) para conocer las razones por las que esto puede ser útil.
EFD_NONBLOCK (desde Linux 2.6.27)
Establece la bandera de estado de archivo O_NONBLOCK en la descripción de archivo abierta (ver open(2)) a la que se refiere el nuevo descriptor de archivo. El uso de esta bandera ahorra llamadas adicionales a fcntl(2) para lograr el mismo resultado.
EFD_SEMAPHORE (desde Linux 2.6.30)
Proporciona semántica similar a semáforos para lecturas del nuevo descriptor de archivo. Ver más abajo.

Hasta Linux 2.6.26, el argumento flags no se utiliza y debe especificarse como cero.

Las siguientes operaciones pueden realizarse en el descriptor de archivo devuelto por eventfd():

read(2)
Cada llamada exitosa a read(2) devuelve un entero de 8 bytes. Una llamada a read(2) falla con el error EINVAL si el tamaño del búfer proporcionado es menor a 8 bytes.
El valor devuelto por read(2) está en orden de bytes del host, es decir, el orden de bytes nativo para los enteros en la máquina anfitriona.
La semántica de read(2) depende de si el contador eventfd tiene actualmente un valor distinto de cero y de si se especificó la bandera EFD_SEMAPHORE al crear el descriptor de archivo eventfd:
•
Si no se especificó EFD_SEMAPHORE y el contador eventfd tiene un valor distinto de cero, entonces una llamada a read(2) devuelve 8 bytes que contienen ese valor, y el valor del contador se restablece a cero.
•
Si se especificó EFD_SEMAPHORE y el contador eventfd tiene un valor distinto de cero, entonces una llamada a read(2) devuelve 8 bytes que contienen el valor 1, y el valor del contador se decrementa en 1.
•
Si el contador eventfd es cero en el momento de la llamada a read(2), entonces la llamada o bien se bloquea hasta que el contador se vuelve distinto de cero (momento en el que la llamada a read(2) procede como se describe arriba) o falla con el error EAGAIN si el descriptor de archivo se ha configurado como no bloqueante.
write(2)
Una llamada a write(2) añade el valor entero de 8 bytes proporcionado en su búfer al contador. El valor máximo que se puede almacenar en el contador es el valor entero sin signo de 64 bits más grande menos 1 (es decir, 0xfffffffffffffffe). Si la adición hiciera que el valor del contador excediera el máximo, entonces la llamada a write(2) o bien se bloquea hasta que se realiza una llamada a read(2) en el descriptor de archivo, o falla con el error EAGAIN si el descriptor de archivo se ha configurado como no bloqueante.
Una llamada a write(2) falla con el error EINVAL si el tamaño del búfer proporcionado es menor a 8 bytes, o si se intenta escribir el valor 0xffffffffffffffff.
poll(2)
select(2)
(y similares)
El descriptor de archivo devuelto soporta poll(2) (y análogamente epoll(7)) y select(2), de la siguiente manera:
•
El descriptor de archivo es legible (el argumento readfds de select(2); la bandera POLLIN de poll(2)) si el contador tiene un valor mayor que 0.
•
El descriptor de archivo es escribible (el argumento writefds de select(2); la bandera POLLOUT de poll(2)) si es posible escribir un valor de al menos "1" sin bloquear.
•
Si se detectó un desbordamiento del valor del contador, entonces select(2) indica el descriptor de archivo como legible y escribible, y poll(2) devuelve un evento POLLERR. Como se mencionó anteriormente, write(2) nunca puede desbordar el contador. Sin embargo, puede ocurrir un desbordamiento si se realizan 2^64 "publicaciones de señales" eventfd por el subsistema KAIO (teóricamente posible, pero prácticamente improbable). Si ha ocurrido un desbordamiento, entonces read(2) devolverá ese valor máximo de uint64_t (es decir, 0xffffffffffffffff).
El descriptor de archivo eventfd también soporta las otras APIs de multiplexación de descriptores de archivo: pselect(2) y ppoll(2).
close(2)
Cuando el descriptor de archivo ya no sea necesario, debe ser cerrado. Cuando todos los descriptores de archivo asociados con el mismo objeto eventfd hayan sido cerrados, el kernel liberará los recursos del objeto.

Una copia del descriptor de archivo creado por eventfd() es heredada por el hijo producido por fork(2). El descriptor de archivo duplicado está asociado con el mismo objeto eventfd. Los descriptores de archivo creados por eventfd() se conservan a través de execve(2), a menos que se haya establecido la bandera close-on-exec.

VALOR DE RETORNO

En caso de éxito, eventfd() devuelve un nuevo descriptor de archivo eventfd. En caso de error, se devuelve -1 y errno se establece para indicar el error.

ERRORES

EINVAL
Se especificó un valor no soportado en flags.
EMFILE
Se ha alcanzado el límite por proceso en el número de descriptores de archivo abiertos.
ENFILE
Se ha alcanzado el límite a nivel de sistema en el número total de archivos abiertos.
ENODEV
No se pudo montar el dispositivo de inode anónimo (interno).
ENOMEM
No había suficiente memoria para crear un nuevo descriptor de archivo eventfd.

VERSIONES

Diferencias entre la biblioteca y el núcleo de C

Existen dos llamadas al sistema subyacentes en Linux: eventfd() y la más reciente eventfd2(). La primera llamada al sistema no implementa un argumento flags . La segunda llamada al sistema implementa los valores de flags descritos anteriormente. La función envoltorio (wrapper) de glibc utilizará eventfd2() cuando esté disponible.

Funcionalidades adicionales de glibc

La biblioteca C de GNU define un tipo adicional y dos funciones que intentan abstraer algunos de los detalles de la lectura y escritura en un descriptor de archivo eventfd:


typedef uint64_t eventfd_t;
int eventfd_read(int fd, eventfd_t *value);
int eventfd_write(int fd, eventfd_t value);

Las funciones realizan las operaciones de lectura y escritura en un descriptor de archivo eventfd, devolviendo 0 si se transfirió el número correcto de bytes, o -1 en caso contrario.

ESTÁNDARES

HISTORIA

eventfd()
Linux 2.6.22, glibc 2.8.
eventfd2()
Linux 2.6.27 (véase VERSIONES). Desde glibc 2.9, el envoltorio eventfd() empleará la llamada al sistema eventfd2(), si es soportada por el núcleo.

NOTAS

Las aplicaciones pueden usar un descriptor de archivo eventfd en lugar de una tubería (véase pipe(2)) en todos los casos donde una tubería se usa simplemente para señalizar eventos. La sobrecarga en el núcleo de un descriptor de archivo eventfd es mucho menor que la de una tubería, y solo se requiere un descriptor de archivo (frente a los dos requeridos para una tubería).

Cuando se usa en el núcleo, un descriptor de archivo eventfd puede proporcionar un puente del núcleo al espacio de usuario, permitiendo, por ejemplo, funcionalidades como KAIO (AIO de núcleo) señalizar a un descriptor de archivo que alguna operación está completa.

Un punto clave sobre un descriptor de archivo eventfd es que puede ser monitoreado como cualquier otro descriptor de archivo usando select(2), poll(2), o epoll(7). Esto significa que una aplicación puede monitorear simultáneamente la disponibilidad de archivos "tradicionales" y la disponibilidad de otros mecanismos del núcleo que soportan la interfaz eventfd. (Sin la interfaz eventfd(), estos mecanismos no podrían ser multiplexados vía select(2), poll(2), o epoll(7).)

El valor actual de un contador eventfd puede ser visto a través de la entrada correspondiente al descriptor de archivo en el directorio /proc/pid/fdinfo del proceso. Véase proc(5) para más detalles.

EJEMPLOS

El siguiente programa crea un descriptor de archivo eventfd y luego hace un fork para crear un proceso hijo. Mientras el padre duerme brevemente, el hijo escribe cada uno de los enteros proporcionados en los argumentos de la línea de comandos del programa en el descriptor de archivo eventfd. Cuando el padre termina de dormir, lee del descriptor de archivo eventfd.

La siguiente sesión de shell muestra una ejecución de muestra del programa:


$ ./a.out 1 2 4 7 14
Child writing 1 to efd
Child writing 2 to efd
Child writing 4 to efd
Child writing 7 to efd
Child writing 14 to efd
Child completed write loop
Parent about to read
Parent read 28 (0x1c) from efd

Código fuente del programa

#include <err.h>
#include <inttypes.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/eventfd.h>
#include <sys/types.h>
#include <unistd.h>
int
main(int argc, char *argv[])
{
    int       efd;
    uint64_t  u;
    ssize_t   s;
    if (argc < 2) {
        fprintf(stderr, "Usage: %s <num>...\n", argv[0]);
        exit(EXIT_FAILURE);
    }
    efd = eventfd(0, 0);
    if (efd == -1)
        err(EXIT_FAILURE, "eventfd");
    switch (fork()) {
    case 0:
        for (size_t j = 1; j < argc; j++) {
            printf("Child writing %s to efd\n", argv[j]);
            u = strtoull(argv[j], NULL, 0);
                    /* strtoull() allows various bases */
            s = write(efd, &u, sizeof(uint64_t));
            if (s != sizeof(uint64_t))
                err(EXIT_FAILURE, "write");
        }
        printf("Child completed write loop\n");
        exit(EXIT_SUCCESS);
    default:
        sleep(2);
        printf("Parent about to read\n");
        s = read(efd, &u, sizeof(uint64_t));
        if (s != sizeof(uint64_t))
            err(EXIT_FAILURE, "read");
        printf("Parent read %"PRIu64" (%#"PRIx64") from efd\n", u, u);
        exit(EXIT_SUCCESS);
    case -1:
        err(EXIT_FAILURE, "fork");
    }
}
