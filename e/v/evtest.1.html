NOMBRE

evtest - Herramienta de consulta y monitorización de eventos de dispositivos de entrada

SINOPSIS

evtest [--grab] /dev/input/eventX
evtest --query /dev/input/eventX <tipo> <valor>

DESCRIPCIÓN

La primera invocación mostrada arriba ("modo captura") hace que evtest muestre información sobre el dispositivo de entrada especificado, incluyendo todos los eventos soportados por el dispositivo. Luego monitoriza el dispositivo y muestra todos los eventos de capa generados.

Si se proporciona la bandera --grab en modo captura, evtest mantiene un EVIOCGRAB sobre el dispositivo. Mientras este grab está activo, otros procesos no recibirán eventos de los dispositivos del kernel. El grab se libera de nuevo cuando evtest finaliza.

En el segundo tipo de invocación ("modo consulta"), evtest realiza una consulta de una sola vez del estado de una valor específica de un tipo de evento.

tipo es uno de: EV_KEY, EV_SW, EV_SND, EV_LED (o el valor numérico)

valor puede ser una representación decimal (p. ej. 44), hexadecimal (p. ej. 0x2c), o el nombre de la constante (p. ej. KEY_Z) de la tecla/interruptor/sonido/LED que se está consultando.

Si el bit de estado está establecido (tecla presionada, interruptor encendido, ...), evtest sale con el código 10. Si el bit de estado no está establecido (tecla liberada, interruptor apagado, ...), evtest sale con el código 0. No se genera ninguna otra salida.

evtest necesita poder leer del dispositivo; en la mayoría de los casos, esto significa que debe ejecutarse como root.

evtest se utiliza comúnmente para depurar problemas con dispositivos de entrada en X.Org. La salida de evtest muestra la información presentada por el kernel; basándose en esta información, se puede determinar si un error puede ser un problema del kernel o de X.Org.

DIAGNÓSTICOS

Si evtest no muestra ningún evento a pesar de que el dispositivo se está utilizando, es posible que el dispositivo esté siendo capturado por un proceso (EVIOCGRAB). Este suele ser el caso al depurar un dispositivo synaptics dentro de X. Cambiar de VT a una TTY o apagar el servidor X termina este grab y los dispositivos synaptics pueden ser depurados.

El siguiente comando muestra los procesos con un descriptor de archivo abierto en el dispositivo:

fuser -v /dev/input/eventX

CÓDIGO DE SALIDA

evtest devuelve 1 en caso de error.

Cuando se utiliza para consultar el estado, evtest devuelve 0 si el bit de estado no está establecido y 10 si el bit de estado está establecido.
