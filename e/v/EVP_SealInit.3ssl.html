EVP_SealInit(3ssl)

Paquete: openssl

Licencias: Apache-2.0

EVP_SEALINIT(3ssl) OpenSSL EVP_SEALINIT(3ssl)

NOMBRE

EVP_SealInit, EVP_SealUpdate, EVP_SealFinal - cifrado de sobre EVP

SINOPSIS

#include <openssl/evp.h>
int EVP_SealInit(EVP_CIPHER_CTX *ctx, const EVP_CIPHER *type,
                 unsigned char **ek, int *ekl, unsigned char *iv,
                 EVP_PKEY **pubk, int npubk);
int EVP_SealUpdate(EVP_CIPHER_CTX *ctx, unsigned char *out,
                   int *outl, unsigned char *in, int inl);
int EVP_SealFinal(EVP_CIPHER_CTX *ctx, unsigned char *out, int *outl);

DESCRIPCIÓN

Las rutinas de sobre EVP son una interfaz de alto nivel para el cifrado de sobre. Generan una clave y un IV aleatorios (si es necesario) y luego los "envuelven" mediante cifrado de clave pública. Los datos se pueden cifrar a continuación utilizando esta clave.

EVP_SealInit() inicializa un contexto de cifrado ctx para el cifrado con el cifrador type utilizando una clave secreta y un IV aleatorios. type normalmente se proporciona mediante una función como EVP_aes_256_cbc(). La clave secreta se cifra utilizando una o más claves públicas, lo que permite que los mismos datos cifrados se descifren utilizando cualquiera de las claves privadas correspondientes. ek es una matriz de búferes donde se escribirá la clave secreta cifrada con clave pública, cada búfer debe contener suficiente espacio para la clave cifrada correspondiente: es decir, ek[i] debe tener espacio para EVP_PKEY_get_size(pubk[i]) bytes. El tamaño real de cada clave secreta cifrada se escribe en la matriz ekl. pubk es una matriz de npubk claves públicas.

El parámetro iv es un búfer donde se escribe el IV generado. Debe contener suficiente espacio para el IV del cifrador correspondiente, según lo determinado por (por ejemplo) EVP_CIPHER_get_iv_length(type).

Si el cifrador no requiere un IV, el parámetro iv se ignora y puede ser NULL.

EVP_SealUpdate() y EVP_SealFinal() tienen exactamente las mismas propiedades que las rutinas EVP_EncryptUpdate() y EVP_EncryptFinal(), como se documenta en la página del manual de EVP_EncryptInit(3).

VALORES DE RETORNO

EVP_SealInit() devuelve 0 en caso de error o npubk si tiene éxito.

EVP_SealUpdate() y EVP_SealFinal() devuelven 1 para éxito y 0 para fallo.

NOTAS

Debido a que se genera una clave secreta aleatoria, el generador de números aleatorios debe sembrarse cuando se llama a EVP_SealInit(). Si la siembra o resiembra automática del CSPRNG de OpenSSL falla debido a circunstancias externas (ver RAND(7)), la operación fallará.

La clave pública debe ser RSA porque es el único algoritmo de clave pública de OpenSSL que admite el transporte de claves.

El cifrado de sobre es el método habitual de usar el cifrado de clave pública en grandes cantidades de datos, esto se debe a que el cifrado de clave pública es lento pero el cifrado simétrico es rápido. Por lo tanto, el cifrado simétrico se utiliza para el cifrado masivo y la pequeña clave simétrica aleatoria utilizada se transfiere mediante cifrado de clave pública.

Es posible llamar a EVP_SealInit() dos veces de la misma manera que EVP_EncryptInit(). La primera llamada debe tener npubk establecido en 0 y (después de configurar cualquier parámetro de cifrado) debe llamarse de nuevo con type establecido en NULL.
