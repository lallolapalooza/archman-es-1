EVP_PKEY-ML-DSA(7ssl)

Paquete: openssl

Licencias: Apache-2.0

EVP_PKEY-ML-DSA(7ssl) OpenSSL EVP_PKEY-ML-DSA(7ssl)

NOMBRE

EVP_PKEY-ML-DSA, EVP_KEYMGMT-ML-DSA, EVP_PKEY-ML-DSA-44, EVP_PKEY-ML-DSA-65, EVP_PKEY-ML-DSA-87 - Tipo de clave y soporte de algoritmo EVP_PKEY ML-DSA

DESCRIPCIÓN

ML-DSA implementa los algoritmos ML-DSA-44, ML-DSA-65 y ML-DSA-87. Los tipos de clave EVP_PKEY_ML_DSA_44, EVP_PKEY_ML_DSA_65 y EVP_PKEY_ML_DSA_87 están implementados en los proveedores predeterminado y FIPS de OpenSSL. Estas implementaciones admiten la clave asociada, que contiene la clave pública pub y la clave privada priv.

Cada uno de los diferentes tipos de clave tiene una categoría de seguridad asociada. Este valor es 2, 3 o 5 para los tipos de clave ML-DSA-44, ML-DSA-65 y ML-DSA-87 respectivamente, que corresponden a fortalezas de seguridad de 128, 192 y 256 respectivamente.

Parámetros de generación de claves

"seed" (OSSL_PKEY_PARAM_ML_DSA_SEED) <cadena de octetos>
La semilla puede usarse para generar los componentes de la clave privada y pública de manera determinista. La longitud del valor proporcionado debe ser de 32 bytes. Cuando no se proporciona este valor, la semilla se genera aleatoriamente usando un DRBG.

Las claves generadas retienen por defecto la semilla utilizada. La semilla también se retiene de forma predeterminada cuando se cargan claves desde archivos PKCS#8 en el formato de semilla. Cuando está disponible, el parámetro de semilla también se usa durante la exportación e importación de claves, con las claves (de forma predeterminada) regeneradas a partir de la semilla incluso cuando también se proporcionan en la importación. Vea "Parámetros de configuración del proveedor" más abajo para los controles relacionados.

Cuando la semilla se retiene, también está disponible como un parámetro obtenible , y la salida de la clave privada a archivos PKCS#8 incluirá de forma predeterminada la semilla. Cuando la semilla no se conocía inicialmente, o no se retuvo, los archivos de clave privada PKCS#8 contendrán solo la clave privada en el formato "sk" de FIPS 204 .

"properties" (OSSL_PKEY_PARAM_PROPERTIES) <cadena UTF8>
Establece las propiedades que se usarán al obtener las implementaciones de algoritmos utilizadas para las operaciones de hashing de ML-DSA.

Use EVP_PKEY_CTX_set_params(3) después de llamar a EVP_PKEY_keygen_init(3).

Parámetros comunes de ML-DSA

Además de los parámetros comunes que todos los tipos de clave deben admitir (vea "Common Information Parameters" en provider-keymgmt(7)), la implementación de estos tipos de clave admite los parámetros listados a continuación. Estos se pueden obtener usando EVP_PKEY_get_octet_string_param(3) o EVP_PKEY_get_params(3). Se pueden inicializar mediante EVP_PKEY_fromdata(3), y los devuelve EVP_PKEY_todata(3) dado una selecciónadecuada. Una vez que se configura una clave pública o privada, ya no se puede modificar, ni se puede añadir otro componente de clave.

"pub" (OSSL_PKEY_PARAM_PUB_KEY) <cadena de octetos>
El valor codificado de la clave pública de tamaño 1312, 1952 o 2592 bytes dependiendo del tipo de clave respectivo de ML-DSA-44, ML-DSA-65 o ML-DSA-87.
"priv" (OSSL_PKEY_PARAM_PRIV_KEY) <cadena de octetos>
El valor codificado de la clave privada de tamaño 2560, 4032 o 4896 bytes dependiendo del tipo de clave respectivo de ML-DSA-44, ML-DSA-65 o ML-DSA-87.

Parámetros de configuración del proveedor

Vea la descripción de la opción -provparam en openssl(1) para aprender cómo establecer parámetros de configuración del proveedor en las herramientas de línea de comandos. Vea OSSL_PROVIDER_add_conf_parameter(3) para aprender cómo establecer opciones de configuración del proveedor programáticamente.

"ml-dsa.retain_seed" (OSSL_PKEY_PARAM_ML_DSA_RETAIN_SEED) <cadena UTF8>
Cuando se establece en una cadena que representa un valor booleano falso (vea OSSL_PROVIDER_conf_get_bool(3)), la semilla no se retendrá después de la generación de claves o la importación de claves desde un valor de semilla. Si la clave resultante se escribe entonces en un objeto PKCS#8, contendrá solo la clave "sk" de FIPS 204.
"ml-dsa.prefer_seed" (OSSL_PKEY_PARAM_ML_DSA_PREFER_SEED) <cadena UTF8>
Al decodificar objetos PKCS#8 que contienen tanto una semilla como la clave privada "sk" de FIPS 204, la semilla se usa de forma predeterminada para regenerar la clave, y la clave privada acompañante se ignora. Cuando este parámetro de configuración se establece en una cadena que representa un valor booleano falso (vea OSSL_PROVIDER_conf_get_bool(3)), la semilla se ignora (ni se usa para regenerar la clave, ni se retiene), y se usa la clave acompañante en su lugar.
"ml-dsa.input_formats" (OSSL_PKEY_PARAM_ML_DSA_INPUT_FORMATS) <cadena UTF8>
Lista de formatos de entrada de clave privada habilitados al analizar objetos PKCS#8. Los elementos de la lista se separan por comas, espacios o tabuladores. La lista de formatos habilitados se puede especificar en el archivo de configuración, como se ve en la sección "EJEMPLOS" más abajo, o mediante la opción de línea de comandos -provparam (véase también OSSL_PROVIDER_add_conf_parameter(3)).

Los valores especificados en la línea de comandos anulan cualquier configuración del archivo. De forma predeterminada, todos los formatos admitidos están habilitados. Los formatos admitidos son:

"seed-priv":
Este formato representa objetos PKCS#8 en los que tanto la semilla ξ de 32 bytes de FIPS 204 como la clave secreta sk están presentes en la clave privada como parte de la codificación DER de la secuencia ASN.1: 
ML-DSA-PrivateKey ::= CHOICE {
  seed [0] IMPLICIT OCTET STRING (SIZE (32)),
  expandedKey OCTET STRING (SIZE (2560 | 4032 | 4896)),
  both SEQUENCE {
    seed OCTET STRING (SIZE (32)),
    expandedKey OCTET STRING (SIZE (2560 | 4032 | 4896)) } }

Si el formato "seed-priv" no está incluido en la lista, este formato no se reconocerá en la entrada.

"seed-only":
Este formato representa objetos PKCS#8 en los que solo la semilla ξ de 32 bytes de FIPS 204 está presente en la secuencia anterior. Si el formato "seed-only" no está incluido en la lista, este formato no se reconocerá en la entrada.
"priv-only":
Este formato representa objetos PKCS#8 en los que solo la clave privada sk de FIPS 204 está presente en la secuencia anterior. Si el formato "priv-only" no está incluido en la lista, este formato no se reconocerá en la entrada.
"oqskeypair":
Este formato representa objetos PKCS#8 en los que la clave privada es una codificación DER de una cadena de octetos que contiene la concatenación de la clave privada sk y la clave pública pkde FIPS 204. Esta codificación se usa en algunas compilaciones de "oqsprovider". Si el formato "oqskeypair" no está incluido en la lista, este formato no se reconocerá en la entrada.
"bare-seed":
Este formato representa objetos PKCS#8 en los que la clave privada contiene la semilla ξ de 32 bytes de FIPS 204 sin ninguna encapsulación ASN.1. Si el formato "bare-seed" no está incluido en la lista, este formato no se reconocerá en la entrada.
"bare-priv":
Este formato representa objetos PKCS#8 en los que la clave privada contiene la clave secreta sk de FIPS 204 sin ninguna encapsulación ASN.1. Si el formato "bare-priv" no está incluido en la lista, este formato no se reconocerá en la entrada.
"ml-dsa.output_formats" (OSSL_PKEY_PARAM_ML_DSA_OUTPUT_FORMATS) <cadena UTF8>
Lista ordenada de formatos de salida de clave privada habilitados al escribir archivos PKCS#8 . Los elementos de la lista se separan por comas, espacios o tabuladores. La lista de formatos habilitados se puede especificar en el archivo de configuración, como se ve en la sección "EJEMPLOS" a continuación, o mediante la -provparam opción de línea de comandos.

Esto admite el mismo conjunto de formatos que se describen en "ml-dsa.input_formats" arriba. El orden en que se enumeran los elementos es importante; el formato seleccionado será el primero que sea posible de generar. Si la semilla de la clave es conocida, se seleccionará el primer formato enumerado. Si la semilla de la clave no es conocida, se seleccionará el primer formato que omita la semilla. El orden por defecto es equivalente a "seed-priv" primero y "priv-only" segundo, con la semilla y la clave generadas cuando la semilla está disponible, y solo la clave en caso contrario. Si "seed-only" se enumera primero, entonces la semilla se generará sin la clave cuando esté disponible; de lo contrario, la salida contendrá solo la clave. Si "priv-only" se enumera primero, entonces solo se genera la clave, independientemente de si la semilla está presente. Los formatos heredados "oqskeypair", "bare-seed" y "bare-priv" también pueden generarse, enumerándolos primero.

CONFORME A

FIPS 204

EJEMPLOS

Un EVP_PKEY contexto se puede obtener llamando a:

EVP_PKEY_CTX *pctx =
    EVP_PKEY_CTX_new_from_name(NULL, "ML-DSA-44", NULL);

Una ML-DSA-44 clave se puede generar de esta manera:

pkey = EVP_PKEY_Q_keygen(NULL, NULL, "ML-DSA-44");

Los componentes del par de claves se pueden extraer de una clave llamando a:

/* Tamaños suficientes para ML-DSA-87 */
uint8_t pub[2592], priv[4896], seed[32]:
size_t priv_len, pub_len, seed_len;
EVP_PKEY_get_octet_string_param(pkey, OSSL_PKEY_PARAM_ML_DSA_SEED,
                                seed, sizeof(seed), &seed_len);
EVP_PKEY_get_octet_string_param(pkey, OSSL_PKEY_PARAM_PRIV_KEY,
                                priv, sizeof(priv), &priv_len);
EVP_PKEY_get_octet_string_param(pkey, OSSL_PKEY_PARAM_PUB_KEY,
                                pub, sizeof(pub), &pub_len));

Una ML-DSA clave privada en formato de semilla se puede convertir a una clave en el formato sk del FIPS 204 ejecutando:

$ openssl pkey -provparam ml-dsa.retain_seed=no \
    -in seed-only.pem -out priv-only.pem

Para generar, por ejemplo, una ML-DSA-65 clave, en el formato sk del FIPS 204, puedes ejecutar:

$ openssl genpkey -provparam ml-dsa.retain_seed=no \
    -algorithm ml-dsa-65 -out priv-only.pem

Si tienes un PKCS#8 archivo con tanto una semilla como una clave, y prefieres importar la clave asociada en lugar de la semilla, puedes ejecutar:

$ openssl pkey -provparam ml-dsa.prefer_seed=no \
    -in seed-priv.pem -out priv-only.pem

En el openssl.cnf archivo, esto se ve así:

openssl_conf = openssl_init
[openssl_init]
providers = providers_sect
# Puede ser referenciado en una o más secciones de proveedores
[ml_dsa_sect]
prefer_seed = yes
retain_seed = yes
# Formatos heredados de OQS deshabilitados
input_formats = seed-priv, seed-only, priv-only
# Generar o bien la semilla sola, o bien la clave sola
output_formats = seed-only, priv-only
[providers_sect]
default = default_sect
# O quizás solo: base = default_sect
base = base_sect
[default_sect]
ml-dsa = ml_dsa_sect
[base_sect]
ml-dsa = ml_dsa_sect
