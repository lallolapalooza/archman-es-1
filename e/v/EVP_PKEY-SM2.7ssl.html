EVP_PKEY-SM2(7ssl)

Paquete: openssl

Licencias: Apache-2.0

EVP_PKEY-SM2(7ssl) OpenSSL EVP_PKEY-SM2(7ssl)

NOMBRE

EVP_PKEY-SM2, EVP_KEY MGMT-SM2, SM2 - Soporte de tipo de clave EVP_PKEY para los algoritmos chinos de firma y cifrado SM2

DESCRIPCIÓN

El algoritmo SM2 fue definido por primera vez por el estándar nacional chino GM/T 0003-2012 y posteriormente estandarizado por la ISO como ISO/IEC 14888. SM2 es en realidad un algoritmo basado en curvas elípticas. La implementación actual en OpenSSL soporta esquemas de firma y cifrado a través de la interfaz EVP.

Al usar el algoritmo de firma SM2, se requiere un identificador distintivo para formar el prefijo del mensaje que se hashea antes de hashear el mensaje real.

Parámetros comunes SM2

SM2 utiliza los parámetros definidos en "Parámetros EC comunes" en EVP_PKEY-EC(7). Los siguientes parámetros son diferentes:

"cofactor" (OSSL_PKEY_PARAM_EC_COFACTOR) <entero sin signo>
Este parámetro se ignora para SM2.
(OSSL_PKEY_PARAM_DEFAULT_DIGEST) <cadena UTF8>
Obtenedor que devuelve el nombre del digest por defecto. (Actualmente devuelve "SM3" a partir de OpenSSL 3.0).

NOTAS

Las firmas SM2 se pueden generar utilizando la serie de APIs 'DigestSign', por ejemplo, EVP_DigestSignInit(), EVP_DigestSignUpdate() y EVP_DigestSignFinal(). Lo mismo ocurre con el proceso de verificación llamando a la serie de APIs 'DigestVerify'. Tenga en cuenta que el algoritmo SM2 requiere la presencia de la clave pública para las firmas, por lo que la opción OSSL_PKEY_PARAM_PUB_KEY debe establecerse en cualquier clave utilizada en la generación de firmas.

Antes de calcular una firma SM2, se necesita crear un EVP_PKEY_CTX y establecerle un ID SM2, de la siguiente manera:

EVP_PKEY_CTX_set1_id(pctx, id, id_len);

Antes de llamar a las funciones EVP_DigestSignInit() o EVP_DigestVerifyInit(), ese EVP_PKEY_CTX debe asignarse al EVP_MD_CTX, de la siguiente manera:

EVP_MD_CTX_set_pkey_ctx(mctx, pctx);

Normalmente no es necesario pasar un parámetro pctx a EVP_DigestSignInit() o EVP_DigestVerifyInit() en tal escenario.

SM2 se puede probar con la aplicación openssl-speed(1) desde la versión 3.0. Actualmente, el único nombre de algoritmo válido es sm2.

Desde la versión 3.0, las claves SM2 solo se pueden generar y cargar cuando los parámetros del dominio especifican la curva elíptica SM2.

EJEMPLOS

Este ejemplo demuestra la secuencia de llamadas para usar un EVP_PKEY para verificar un mensaje con el algoritmo de firma SM2 y el algoritmo de hash SM3:

#include <openssl/evp.h>
/* obtener un EVP_PKEY usando cualquier método... */
mctx = EVP_MD_CTX_new();
pctx = EVP_PKEY_CTX_new(pkey, NULL);
EVP_PKEY_CTX_set1_id(pctx, id, id_len);
EVP_MD_CTX_set_pkey_ctx(mctx, pctx);
EVP_DigestVerifyInit(mctx, NULL, EVP_sm3(), NULL, pkey);
EVP_DigestVerifyUpdate(mctx, msg, msg_len);
EVP_DigestVerifyFinal(mctx, sig, sig_len)
