EVP_PKEY_sign(3ssl)

Paquete: openssl

Licencias: Apache-2.0

EVP_PKEY_SIGN(3ssl) OpenSSL EVP_PKEY_SIGN(3ssl)

NOMBRE

EVP_PKEY_sign_init, EVP_PKEY_sign_init_ex, EVP_PKEY_sign_init_ex2, EVP_PKEY_sign, EVP_PKEY_sign_message_init, EVP_PKEY_sign_message_update, EVP_PKEY_sign_message_final - firmar usando un algoritmo de clave pública

SINOPSIS

#include <openssl/evp.h>
int EVP_PKEY_sign_init(EVP_PKEY_CTX *ctx);
int EVP_PKEY_sign_init_ex(EVP_PKEY_CTX *ctx, const OSSL_PARAM params[]);
int EVP_PKEY_sign_init_ex2(EVP_PKEY_CTX *ctx, EVP_SIGNATURE *algo,
                           const OSSL_PARAM params[]);
int EVP_PKEY_sign_message_init(EVP_PKEY_CTX *ctx, EVP_SIGNATURE *algo,
                               const OSSL_PARAM params[]);
int EVP_PKEY_sign_message_update(EVP_PKEY_CTX *ctx,
                                 unsigned char *in, size_t inlen);
int EVP_PKEY_sign_message_final(EVP_PKEY_CTX *ctx, unsigned char *sig,
                                size_t *siglen, size_t sigsize);
int EVP_PKEY_sign(EVP_PKEY_CTX *ctx,
                  unsigned char *sig, size_t *siglen,
                  const unsigned char *tbs, size_t tbslen);

DESCRIPCIÓN

EVP_PKEY_sign_init() inicializa un contexto de algoritmo de clave pública ctx para firmar usando el algoritmo dado cuando el contexto fue creado usando EVP_PKEY_CTX_new(3) o variantes del mismo. El algoritmo se usa para obtener implícitamente un método EVP_SIGNATURE , véase "Implicit fetch" en provider(7) para más información sobre obtenciones implícitas.

EVP_PKEY_sign_init_ex() es lo mismo que EVP_PKEY_sign_init() pero además establece los parámetros pasados params en el contexto antes de retornar.

EVP_PKEY_sign_init_ex2() inicializa un contexto de algoritmo de clave pública ctx para firmar un resumen de mensaje precalculado usando el algoritmo dado por algo y la clave dada a través de EVP_PKEY_CTX_new(3) o EVP_PKEY_CTX_new_from_pkey(3). Un contexto ctx sin una clave precargada no puede usarse con esta función. Esta función proporciona casi la misma funcionalidad que EVP_PKEY_sign_init_ex(), pero está destinada únicamente a usarse con un resumen de mensaje precalculado, y permite predeterminar las condiciones exactas para ese resumen de mensaje, si se obtuvo un algoritmo de firma compuesto (como RSA-SHA256). Después de una llamada a esta función, normalmente no se permite establecer parámetros que modifiquen la implementación del resumen o el relleno.

EVP_PKEY_sign_message_init() inicializa un contexto de algoritmo de clave pública ctx para firmar un mensaje de tamaño ilimitado usando el algoritmo dado por algo y la clave dada a través de EVP_PKEY_CTX_new(3) o EVP_PKEY_CTX_new_from_pkey(3). Pasar el mensaje se soporta tanto de una sola vez usando EVP_PKEY_sign(), como a través de la combinación de EVP_PKEY_sign_message_update() y EVP_PKEY_sign_message_final(). Esta función permite usar algoritmos que pueden procesar entradas de longitud arbitraria, como ED25519, RSA-SHA256 y similares.

EVP_PKEY_sign_message_update() añade inlen bytes de in a los datos a procesar para la firma. La especificación e implementación del algoritmo de firma determinan cómo se procesan los bytes de entrada y si hay un límite en el tamaño total de la entrada. Véase "NOTAS" más abajo para una explicación más profunda.

EVP_PKEY_sign_message_final() firma los datos procesados y coloca los datos en sig, y el número de bytes de la firma en *siglen, si el número de bytes no supera el tamaño dado por sigsize. sig puede ser NULL, y en ese caso, solo se actualiza *siglen con el número de bytes de la firma.

EVP_PKEY_sign() es una función de una sola vez que puede usarse con todas las funciones de inicialización anteriores. Cuando la inicialización se hizo con EVP_PKEY_sign_init(), EVP_PKEY_sign_init_ex() o EVP_PKEY_sign_init_ex2(), los datos especificados por tbs y tbslen se firman después de un relleno apropiado. Cuando la inicialización se hizo con EVP_PKEY_sign_message_init(), los datos especificados por tbs y tbslen son resumidos por el algoritmo implícito de resumen de mensaje, y el resultado se firma después de un relleno apropiado. Si sig es NULL, entonces se escribe el tamaño máximo del búfer de salida en el parámetro siglen . Si sig no es NULL, entonces antes de la llamada el parámetro siglen debería contener la longitud del búfer sig , y si la llamada es exitosa, la firma se escribe en sig y la cantidad de datos escritos en siglen.

NOTAS

General

Algunas implementaciones de firma solo acumulan los datos de entrada y no realizan ningún procesamiento adicional antes de firmarlos (esperan que la entrada sea un resumen), mientras que otras comprimen los datos, típicamente produciendo internamente un resumen, y firman el resultado. Algunas de ellas soportan ambos modos de operación al mismo tiempo. Se espera que el llamador sepa cómo se supone que debe comportarse el algoritmo elegido y bajo qué condiciones.

Por ejemplo, se puede esperar que una implementación RSA solo espere un resumen de mensaje como entrada, mientras que se puede esperar que ED25519 procese la entrada con un hash, es decir, produzca internamente el resumen de mensaje, y mientras que se puede esperar que RSA-SHA256 maneje cualquiera de los modos de operación, dependiendo de si la operación se inicializó con EVP_PKEY_sign_init_ex2() o con EVP_PKEY_sign_message_init().

De manera similar, una implementación RSA usualmente espera que se establezcan detalles adicionales, como el algoritmo de resumen de mensaje con el que se supone que debe resumirse la entrada, así como el modo de relleno (véase EVP_PKEY_CTX_set_signature_md(3) y EVP_PKEY_CTX_set_rsa_padding(3) y otros similares), mientras que una implementación RSA-SHA256 usualmente tiene estos detalles preestablecidos e inmutables.

Las funciones descritas aquí no pueden usarse para combinar algoritmos separados. En particular, ni EVP_PKEY_CTX_set_signature_md(3) ni el parámetro OSSL_PARAM "digest" (OSSL_SIGNATURE_PARAM_DIGEST) pueden usarse para combinar un algoritmo de firma con un algoritmo hash para procesar la entrada. En otras palabras, no es posible especificar un ctx precargado con una clave pkey RSA, o un algo que obtuvo "RSA" e intentar especificar SHA256 por separado para obtener la funcionalidad de RSA-SHA256. Si se desea combinar algoritmos de esa manera, por favor use EVP_DigestSignInit(3) y las funciones asociadas.

Realizar múltiples firmas

Cuando se inicializa usando EVP_PKEY_sign_init_ex() o EVP_PKEY_sign_init_ex2(), EVP_PKEY_sign() puede llamarse más de una vez en el mismo contexto para realizar varias operaciones de una sola vez usando los mismos parámetros.

Cuando se inicializa usando EVP_PKEY_sign_message_init(), no es posible llamar a EVP_PKEY_sign() múltiples veces.

VALORES DE RETORNO

Todas las funciones retornan 1 para éxito y 0 o un valor negativo para fallo.

En particular, EVP_PKEY_sign_init() y sus otras variantes pueden retornar -2 para indicar que la operación no es soportada por el algoritmo de clave pública.

EJEMPLOS

RSA con relleno PKCS#1 para SHA256

Firmar datos usando RSA con relleno PKCS#1 y un resumen SHA256 como entrada:

#include <openssl/evp.h>
#include <openssl/rsa.h>
EVP_PKEY_CTX *ctx;
/* md es un resumen SHA-256 en este ejemplo. */
unsigned char *md, *sig;
size_t mdlen = 32, siglen;
EVP_PKEY *signing_key;
/*
 * NB: asume que signing_key y md están configurados antes del siguiente
 * paso. signing_key debe ser una clave privada RSA y md debe
 * apuntar al resumen SHA-256 a firmar.
 */
ctx = EVP_PKEY_CTX_new(signing_key, NULL /* sin motor */);
if (ctx == NULL)
    /* Ocurrió un error */
if (EVP_PKEY_sign_init(ctx) <= 0)
    /* Error */
if (EVP_PKEY_CTX_set_rsa_padding(ctx, RSA_PKCS1_PADDING) <= 0)
    /* Error */
if (EVP_PKEY_CTX_set_signature_md(ctx, EVP_sha256()) <= 0)
    /* Error */
/* Determinar la longitud del búfer */
if (EVP_PKEY_sign(ctx, NULL, &siglen, md, mdlen) <= 0)
    /* Error */
sig = OPENSSL_malloc(siglen);
if (sig == NULL)
    /* fallo de malloc */
if (EVP_PKEY_sign(ctx, sig, &siglen, md, mdlen) <= 0)
    /* Error */
/* La firma son siglen bytes escritos en el búfer sig */

RSA-SHA256 con un resumen precalculado

Firmar un resumen con RSA-SHA256 usando funciones de un solo paso. A tener en cuenta que RSA-SHA256 se asume como una implementación de "sha256WithRSAEncryption", para la cual el relleno está predeterminado a ser RSA_PKCS1_PADDING, y se asume que el resumen de entrada ha sido calculado usando SHA256.

#include <openssl/evp.h>
#include <openssl/rsa.h>
EVP_PKEY_CTX *ctx;
/* md es un resumen SHA-256 en este ejemplo. */
unsigned char *md, *sig;
size_t mdlen = 32, siglen;
EVP_PKEY *signing_key;
/*
 * NB: se asume que signing_key y md están configurados antes del siguiente
 * paso. signing_key debe ser una clave privada RSA y md debe
 * apuntar al resumen SHA-256 a firmar.
 */
ctx = EVP_PKEY_CTX_new(signing_key, NULL /* no engine */);
alg = EVP_SIGNATURE_fetch(NULL, "RSA-SHA256", NULL);
if (ctx == NULL)
    /* Ocurrió un error */
if (EVP_PKEY_sign_init_ex2(ctx, alg, NULL) <= 0)
    /* Error */
/* Determinar la longitud del búfer */
if (EVP_PKEY_sign(ctx, NULL, &siglen, md, mdlen) <= 0)
    /* Error */
sig = OPENSSL_malloc(siglen);
if (sig == NULL)
    /* fallo de malloc */
if (EVP_PKEY_sign(ctx, sig, &siglen, md, mdlen) <= 0)
    /* Error */
/* La firma son siglen bytes escritos en el búfer sig */

RSA-SHA256, de un solo paso

Firmar un documento con RSA-SHA256 usando funciones de un solo paso. A tener en cuenta que RSA-SHA256 se asume como una implementación de "sha256WithRSAEncryption", para la cual el relleno está predeterminado a ser RSA_PKCS1_PADDING.

#include <openssl/evp.h>
#include <openssl/rsa.h>
EVP_PKEY_CTX *ctx;
/* in es la entrada en este ejemplo. */
unsigned char *in, *sig;
/* inlen es la longitud de la entrada en este ejemplo. */
size_t inlen, siglen;
EVP_PKEY *signing_key;
EVP_SIGNATURE *alg;
/*
 * NB: se asume que signing_key, in y inlen están configurados antes
 * del siguiente paso. signing_key debe ser una clave privada RSA,
 * in debe apuntar a los datos a resumir y firmar, y
 * inlen debe ser el tamaño de los datos en bytes.
 */
ctx = EVP_PKEY_CTX_new(signing_key, NULL /* no engine */);
alg = EVP_SIGNATURE_fetch(NULL, "RSA-SHA256", NULL);
if (ctx == NULL || alg == NULL)
    /* Ocurrió un error */
if (EVP_PKEY_sign_message_init(ctx, alg, NULL) <= 0)
    /* Error */
/* Determinar la longitud del búfer sig */
if (EVP_PKEY_sign(ctx, NULL, &siglen, in, inlen) <= 0)
    /* Error */
sig = OPENSSL_malloc(siglen);
if (sig == NULL)
    /* fallo de malloc */
if (EVP_PKEY_sign(ctx, sig, &siglen, in, inlen) <= 0)
    /* Error */
/* La firma son siglen bytes escritos en el búfer sig */

RSA-SHA256, usando update y final

Esto es igual al ejemplo anterior, pero permitiendo funcionalidad tipo streaming.

#include <openssl/evp.h>
#include <openssl/rsa.h>
EVP_PKEY_CTX *ctx;
/* in es la entrada en este ejemplo. */
unsigned char *in, *sig;
/* inlen es la longitud de la entrada en este ejemplo. */
size_t inlen, siglen;
EVP_PKEY *signing_key;
EVP_SIGNATURE *alg;
/*
 * NB: se asume que signing_key, in y inlen están configurados antes
 * del siguiente paso. signing_key debe ser una clave privada RSA,
 * in debe apuntar a los datos a resumir y firmar, y
 * inlen debe ser el tamaño de los datos en bytes.
 */
ctx = EVP_PKEY_CTX_new(signing_key, NULL /* no engine */);
alg = EVP_SIGNATURE_fetch(NULL, "RSA-SHA256", NULL);
if (ctx == NULL || alg == NULL)
    /* Ocurrió un error */
if (EVP_PKEY_sign_message_init(ctx, alg, NULL) <= 0)
    /* Error */
while (inlen > 0) {
    if (EVP_PKEY_sign_message_update(ctx, in, inlen)) <= 0)
        /* Error */
    if (inlen > 256) {
        inlen -= 256;
        in += 256;
    } else {
        inlen = 0;
    }
}
/* Determinar la longitud del búfer sig */
if (EVP_PKEY_sign_message_final(ctx, NULL, &siglen) <= 0)
    /* Error */
sig = OPENSSL_malloc(siglen);
if (sig == NULL)
    /* fallo de malloc */
if (EVP_PKEY_sign_message_final(ctx, sig, &siglen) <= 0)
    /* Error */
/* La firma son siglen bytes escritos en el búfer sig */

HISTORIA

Las funciones EVP_PKEY_sign_init() y EVP_PKEY_sign() se añadieron en OpenSSL 1.0.0.

La función EVP_PKEY_sign_init_ex() se añadió en OpenSSL 3.0.

Las funciones EVP_PKEY_sign_init_ex2(), EVP_PKEY_sign_message_init(), EVP_PKEY_sign_message_update() y EVP_PKEY_sign_message_final() se añadieron en OpenSSL 3.4.
