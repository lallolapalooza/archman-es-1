errno(3) Manual de Funciones de Librería errno(3)

NOMBRE

errno - número del último error

LIBRERÍA

Librería C estándar (libc, -lc)

SINOPSIS

#include <errno.h>

DESCRIPCIÓN

El archivo de cabecera <errno.h> define la variable entera errno, que es establecida por llamadas al sistema y algunas funciones de librería en caso de error para indicar qué salió mal.

errno

El valor en errno solo es significativo cuando el valor de retorno de la llamada indicó un error (es decir, -1 de la mayoría de las llamadas al sistema; -1 o NULL de la mayoría de las funciones de librería); una función que tiene éxito *puede* cambiar errno. El valor de errno nunca se establece en cero por ninguna llamada al sistema o función de librería.

Para algunas llamadas al sistema y funciones de librería (por ejemplo, getpriority(2)), -1 es un retorno válido con éxito. En tales casos, un retorno exitoso puede distinguirse de un retorno de error estableciendo errno a cero antes de la llamada, y luego, si la llamada devuelve un estado que indica que un error puede haber ocurrido, comprobando si errno tiene un valor distinto de cero.

errno está definido por el estándar C de ISO como un lvalue modificable de tipo int, y no debe declararse explícitamente; errno puede ser una macro. errno es thread-local; establecerlo en un hilo no afecta su valor en ningún otro hilo.

Números y nombres de error

Los números de error válidos son todos números positivos. El archivo de cabecera <errno.h> define nombres simbólicos para cada uno de los posibles números de error que pueden aparecer en errno.

Todos los nombres de error especificados por POSIX.1 deben tener valores distintos, con la excepción de EAGAIN y EWOULDBLOCK, que pueden tener el mismo valor. En Linux, estos dos tienen el mismo valor en todas las arquitecturas.

Los números de error que corresponden a cada nombre simbólico varían entre los sistemas UNIX, e incluso entre diferentes arquitecturas en Linux. Por lo tanto, los valores numéricos no se incluyen como parte de la lista de nombres de error a continuación. Las funciones perror(3) y strerror(3) pueden usarse para convertir estos nombres a mensajes de error textuales correspondientes.

En cualquier sistema Linux en particular, se puede obtener una lista de todos los nombres de error simbólicos y los números de error correspondientes usando el comando errno(1) (parte del paquete moreutils):


$ errno -l;
EPERM 1 Operation not permitted
ENOENT 2 No such file or directory
ESRCH 3 No such process
EINTR 4 Interrupted system call
EIO 5 Input/output error
...

El comando errno(1) también se puede usar para buscar números de error individuales y nombres, y para buscar errores usando cadenas de la descripción del error, como en los siguientes ejemplos:


$ errno 2;
ENOENT 2 No such file or directory
$ errno ESRCH;
ESRCH 3 No such process
$ errno -s permission;
EACCES 13 Permission denied

NOTAS

Un error común es hacer


if (somecall() == -1) {
    printf("somecall() failed\n");
    if (errno == ...) { ...; }
}

donde errno ya no necesita tener el valor que tenía al retornar de somecall() (es decir, puede haber sido cambiado por el printf(3)). Si el valor de errno debe preservarse a través de una llamada a la biblioteca, debe guardarse:


if (somecall() == -1) {
    int errsv = errno;
    printf("somecall() failed\n");
    if (errsv == ...) { ...; }
}

Tenga en cuenta que las API de hilos de POSIX no establecen establecen errno en caso de error. En su lugar, en caso de fallo retornan un número de error como el resultado de la función. Estos números de error tienen los mismos significados que los números de error retornados en errno por otras API.

En algunos sistemas antiguos, <errno.h> no estaba presente o no declaraba errno, por lo que era necesario declarar errno manualmente (es decir, extern int errno). No haga esto. Hace mucho tiempo que dejó de ser necesario, y causará problemas con las versiones modernas de la biblioteca C.
