Error(3pm)

Paquete: perl-error

Licencias: PerlArtistic, GPL

Error(3) Documentación de Perl aportada por el usuario Error(3)

NOMBRE

Error - Manejo de errores/excepciones de una manera orientada a objetos

VERSIÓN

versión 0.17030

SINOPSIS

use Error qw(:try);
throw Error::Simple( "A simple error");
sub xyz {
    ...
    record Error::Simple("A simple error")
        and return;
}
unlink($file) or throw Error::Simple("$file: $!",$!);
try {
    do_some_stuff();
    die "error!" if $condition;
    throw Error::Simple "Oops!" if $other_condition;
}
catch Error::IO with {
    my $E = shift;
    print STDERR "File ", $E->{'-file'}, " had a problem\n";
}
except {
    my $E = shift;
    my $general_handler=sub {send_message $E->{-description}};
    return {
        UserException1 => $general_handler,
        UserException2 => $general_handler
    };
}
otherwise {
    print STDERR "Well I don't know what to say\n";
}
finally {
    close_the_garage_door_already(); # Should be reliable
}; # Don't forget the trailing ; or you might be surprised

DESCRIPCIÓN

El paquete "Error" proporciona dos interfaces. Primero, "Error" proporciona una interfaz procedural para el manejo de excepciones. Segundo, "Error" es una clase base para errores/excepciones que pueden ser lanzados para su posterior captura, o simplemente pueden ser registrados.

Los errores en la clase "Error" no deben ser lanzados directamente, sino que el usuario debe lanzar errores desde una subclase de "Error".

ADVERTENCIA

Usar el módulo "Error" ya no se recomienda debido a la naturaleza de magia negra de su azúcar sintáctica, que tiende a fallar con frecuencia. Sus mantenedores han dejado de escribir activamente código que lo use y desaconsejan a las personas que lo hagan. Vea la sección "VEA TAMBIÉN" más abajo para mejores recomendaciones.

INTERFAZ PROCEDURAL

"Error" exporta subrutinas para realizar el manejo de excepciones. Estas se exportarán si se usa la etiqueta ":try" en la línea "use" .

try BLOQUE CLÁUSULAS
"try" es la subrutina principal llamada por el usuario. Todas las demás subrutinas exportadas son cláusulas para la subrutina try.

El BLOQUE será evaluado y, si no se lanza ningún error, try devolverá el resultado del bloque.

"CLÁUSULAS" son las subrutinas a continuación, que describen qué hacer en caso de que se lance un error dentro del BLOQUE.

capturar CLASE con BLOQUE
Esta cláusula hará que todos los errores que satisfagan "$err->isa(CLASE)" sean capturados y manejados evaluando "BLOQUE".

"BLOQUE" recibirá dos argumentos. El primero será el error que se está lanzando. El segundo es una referencia a una variable escalar. Si esta variable es establecida por el bloque catch, entonces, al regresar del bloque catch, try continuará el procesamiento como si el bloque catch nunca hubiera sido encontrado. El error también estará disponible en $@.

Para propagar el error, el bloque catch puede llamar a "$err->throw"

Si la referencia escalar del segundo argumento no está establecida, y el error no es lanzado, entonces el bloque try actual se devolverá con el resultado del bloque catch.

except BLOQUE
Cuando "try" está buscando un manejador, si se encuentra una cláusula except, "BLOQUE" es evaluado. El valor de retorno de este bloque debe ser una referencia a un HASH o una lista de pares clave-valor, donde las claves son nombres de clase y los valores son referencias a código para el manejador de errores de ese tipo.
de lo contrario BLOQUE
Captura cualquier error ejecutando el código en "BLOQUE"

Cuando se evalúa, "BLOQUE" recibirá un argumento, que será el error que se está procesando. El error también estará disponible en $@.

Solo se puede especificar un bloque "de lo contrario" por cada bloque try.

finalmente BLOQUE
Ejecuta el código en "BLOQUE" ya sea después de que el código en el bloque try se haya completado con éxito, o si el bloque try lanza un error, entonces "BLOQUE" se ejecutará después de que el manejador haya terminado.

Si el manejador lanza un error, entonces el error será capturado, el bloque finally será ejecutado y el error será relanzado.

Solo se puede especificar un bloque finally por cada bloque try.

COMPATIBILIDAD

Moose exporta una palabra clave llamada "with" que entra en conflicto con la de Error. Este ejemplo devuelve un error de desajuste de prototipo:

package MyTest;
use warnings;
use Moose;
use Error qw(:try);

(Gracias a "maik.hentsche@amd.com" por el reporte.).

INTERFAZ DE CLASE

CONSTRUCTORES

El objeto "Error" está implementado como un HASH. Este HASH se inicializa con los argumentos que se pasan a su constructor. Los elementos que son usados por, o recuperables por la clase "Error" se listan a continuación, otras clases pueden añadir a estos.

-archivo
-línea
-texto
-valor
-objeto

Si "-archivo" o "-línea" no se especifican en los argumentos del constructor, entonces estos se inicializarán con el nombre del archivo y el número de línea desde donde se llamó al constructor.

Si el error está asociado con un objeto, entonces el objeto debe pasarse como el argumento "-objeto" . Esto permitirá que el paquete "Error" asocie el error con el objeto.

El paquete "Error" recuerda el último error creado, y también el último error asociado con un paquete. Este podría ser el último error creado por un sub en ese paquete, o el último error que pasó un objeto bendecido en ese paquete como el argumento "-objeto" .

Error->new()
Vea la documentación de Error::Simple.
throw ( [ ARGS ] )
Crea un nuevo objeto "Error" y lanza un error, que será capturado por un bloque "try" circundante, si hay uno. De lo contrario, causará que el programa salga.

"throw" también puede ser llamado en un error existente para relanzarlo.

with ( [ ARGS ] )
Crea un nuevo objeto "Error" y lo devuelve. Esto está definido como azúcar sintáctica, por ejemplo 
die with Some::Error ( ... );
record ( [ ARGS ] )
Crea un nuevo objeto "Error" y lo devuelve. Esto está definido como azúcar sintáctica, por ejemplo 
record Some::Error ( ... )
    and return;

MÉTODOS ESTÁTICOS

prior ( [ PAQUETE ] )
Devuelve el último error creado, o el último error asociado con "PAQUETE"
flush ( [ PAQUETE ] )
Vacía el último error creado, o el último error asociado con "PACKAGE". Es necesario limpiar la pila de errores antes de salir del paquete o los errores no capturados generados usando "record" serán reportados. 
$Error->flush;

MÉTODOS DE OBJETO

stacktrace
Si la variable $Error::Debug era distinta de cero cuando el error fue creado, entonces "stacktrace" devuelve una cadena creada al llamar a "Carp::longmess". Si la variable era cero, el "stacktrace" devuelve el texto del error al que se le añade el nombre del archivo y el número de línea donde el error fue creado, siempre que el texto no termine con un salto de línea.
object
El objeto con el que este error estaba asociado
file
El archivo desde el cual se llamó al constructor de este error
line
La línea desde la cual se llamó al constructor de este error
text
El texto del error
$err->associate($obj)
Asocia un error con un objeto para permitir la propagación de errores. Es decir: 
$ber->encode(...) o
    return Error->prior($ber)->associate($ldap);

MÉTODOS DE SOBRECARGA

stringify
Un método que convierte el objeto en una cadena. Este método puede simplemente devolver lo mismo que el método "text" , o puede añadir más información. Por ejemplo, el nombre del archivo y el número de línea.

Por defecto, este método devuelve el argumento "-text" que fue pasado al constructor, o la cadena "Died" si no se proporcionó ninguno.

value
Un método que devolverá un valor que puede ser asociado con el error. Por ejemplo, si un error fue creado debido a la falla de una llamada al sistema, entonces este puede devolver el valor numérico de $! en ese momento.

Por defecto, este método devuelve el argumento "-value" que fue pasado al constructor.

CLASES DE ERROR PREDEFINIDAS

Error::Simple

Esta clase puede usarse para contener cadenas de error simples y valores. Su constructor toma dos argumentos. El primero es un valor de texto, el segundo es un valor numérico. Estos valores son los que serán devueltos por los métodos de sobrecarga.

Si el valor de texto termina con "at file line 1" como lo hacen las cadenas de $@, entonces esta información será usada para establecer los argumentos "-file" y "-line" del objeto de error.

Esta clase se usa internamente si un bloque eval'd muere con un error que es una cadena simple. (A menos que $Error::ObjectifyCallback sea modificado)

$Error::ObjectifyCallback

Esta variable contiene una referencia a una subrutina que convierte errores que son cadenas simples en objetos. Es usada por Error.pm para convertir errores textuales en objetos, y puede ser sobrescrita por el usuario.

Acepta un solo argumento que es una referencia a un hash de parámetros con nombre. Actualmente, el único parámetro con nombre pasado es 'text' que es el texto del error, pero otros pueden estar disponibles en el futuro.

Por ejemplo, el siguiente código hará que Error.pm lance objetos de la clase MyError::Bar por defecto:

sub throw_MyError_Bar
{
    my $args = shift;
    my $err = MyError::Bar->new();
    $err->{'MyBarText'} = $args->{'text'};
    return $err;
}
{
    local $Error::ObjectifyCallback = \&
    # Manejo de errores aquí.
}

MANEJADORES DE MENSAJES

"Error" también proporciona manejadores para extender la salida de la función de perl warn() , y para manejar la impresión de un "Error" lanzado que no es capturado o manejado de otra manera. Estos no están instalados por defecto, pero se solicitan usando la etiqueta ":warndie" en la línea "use" .

use Error qw( :warndie );

Estos nuevos manejadores de error se instalan en $SIG{__WARN__} y $SIG{__DIE__}. Si estos manejadores ya están definidos cuando se importa la etiqueta, los valores antiguos se almacenan y se usan durante el nuevo código. Así, para organizar un manejo personalizado de advertencias y errores, necesitarás realizar algo como lo siguiente:

BEGIN {
  $SIG{__WARN__} = sub {
    print STDERR "Mi manejador especial de advertencias: $_[0]"
  };
}
use Error qw( :warndie );

Ten en cuenta que establecer $SIG{__WARN__} después de que la etiqueta ":warndie" haya sido importada sobrescribirá el manejador que "Error" proporciona. Si esto no puede evitarse, entonces la etiqueta puede ser explícitamente "import"ada más tarde

use Error;
$SIG{__WARN__} = ...;
import Error qw( :warndie );

EJEMPLO

El manejador "__DIE__" convierte mensajes como

Can't call method "foo" on an undefined value at examples/warndie.pl line 16.

en

Unhandled perl error caught at toplevel:
  Can't call method "foo" on an undefined value
Thrown from: examples/warndie.pl:16
Full stack trace:
        main::inner('undef') called at examples/warndie.pl line 20
        main::outer('undef') called at examples/warndie.pl line 23

VER TAMBIÉN

Ver Exception::Class para un módulo diferente que proporciona manejo de excepciones Orientado a Objetos, junto con una sintaxis conveniente para declarar jerarquías para ellas. No proporciona el azúcar sintáctico de Error de "try { ... }", "catch { ... }", etc., lo cual puede ser una cosa buena o mala dependiendo de lo que quieras. (Porque el azúcar sintáctico de Error tiende a fallar.)

Error::Exception intenta combinar Error y Exception::Class "con una correcta conversión a cadena".

TryCatch y Try::Tiny son similares en concepto a Error.pm, solo proporcionando una sintaxis que esperamos que falle menos.
