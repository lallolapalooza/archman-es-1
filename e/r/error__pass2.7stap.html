NOMBRE

error::pass2 - errores de la segunda pasada de systemtap

DESCRIPCIÓN

Los errores que ocurren durante la segunda pasada (elaboración) pueden tener una variedad de causas. Los tipos comunes incluyen:

información de depuración faltante
El script requiere información de depuración para resolver un punto de sondeo, pero no pudo encontrar ninguna. Consulte error::dwarf(7stap) y warning::debuginfo(7stap) para más detalles.
clases de puntos de sondeo no disponibles
Algunos tipos de puntos de sondeo solo están disponibles en ciertas versiones del sistema, arquitecturas y configuraciones. Por ejemplo, los sondeos del espacio de usuario process.* pueden requerir la capacidad utrace o uprobes en el kernel para esta arquitectura.
puntos de sondeo no disponibles
Algunos puntos de sondeo pueden no estar disponibles individualmente incluso si su clase está bien. Por ejemplo, kprobe.function("foobar") puede fallar si la función foobar ya no existe en el kernel. Los datos de depuración o símbolos pueden estar ausentes para algunos tipos de sondeos .function o .statement; verifique la disponibilidad de la información de depuración. Pruebe el programa stap-prep para descargar la información de depuración posiblemente requerida. Use un parámetro comodín como stap -l 'kprobe.function("*foo*")' para localizar variantes aún existentes. Use los sufijos de punto de sondeo ! o ? para denotar alternativas opcionales / preferidas, para que las partes funcionales de un script continúen.
errores tipográficos
Puede haber un error de ortografía en el nombre del punto de sondeo ("sycsall" en lugar de "syscall"). Los sondeos comodín pueden no encontrar ninguna coincidencia en las tapsets. Vuelva a verificar los nombres usando stap -l PROBEPOINT. Otro error común es usar el operador . en lugar del correcto -> al desreferenciar subcampos o punteros de variables de contexto: $foo->bar->baz incluso si en C se diría foo->bar.baz.
variables de contexto no disponibles
Los scripts de Systemtap a menudo desean referirse a variables del contexto de los programas sondeados usando la notación $variable. Estas variables no siempre pueden estar disponibles, dependiendo de las versiones del compilador, las banderas de depuración/optimización utilizadas, la arquitectura, etc. Use stap -L PROBEPOINT para listar las variables de contexto disponibles para sondeos dados. Use la expresión @defined() para verificar la resolubilidad de una expresión de variable de contexto. Considere usar la opción stap --skip-badvars para reemplazar silenciosamente las expresiones de variables de contexto problemáticas con cero. Experimente con la opción stap --prologue-searching.
inconsistencias en la caché del módulo
Ocasionalmente, la caché de módulos de systemtap ($HOME/.systemtap/cache) podría contener información obsoleta de una configuración/versión del sistema anterior, y producir resultados falsos mientras systemtap intenta reutilizarla. Reintentar con stap --poison-cache ... fuerza la generación de nueva información. Nota: esto no debería ocurrir y probablemente representa un error de systemtap. Por favor, repórtelo.

OBTENIENDO MÁS INFORMACIÓN

Aumentar la verbosidad de la segunda pasada con una opción como --vp 02 puede ayudar a identificar el problema.
