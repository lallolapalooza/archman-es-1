erlc(1) Comandos de usuario erlc(1)

NOMBRE

erlc - Compilador

DESCRIPCIÓN

El programa erlc proporciona una forma común de ejecutar todos los compiladores del sistema Erlang. Dependiendo de la extensión de cada archivo de entrada, erlc invoca al compilador apropiado. Independientemente del compilador que se utilice, las mismas opciones se emplean para proporcionar parámetros, como rutas de inclusión y directorios de salida.

El directorio de trabajo actual, ".", no se incluye en la ruta de código al ejecutar el compilador. Esto es para evitar la carga de archivos Beam del directorio de trabajo actual que potencialmente podrían entrar en conflicto con el compilador o el sistema Erlang/OTP utilizado por el compilador.

erlc flags archivo1.ext archivo2.ext...

Compila uno o más archivos. Los archivos deben incluir la extensión, por ejemplo, .erl para código fuente Erlang, o .yrl para código fuente Yecc. Erlc utiliza la extensión para invocar al compilador correcto.

Opciones generalmente útiles

Las siguientes opciones son compatibles:

-I <Directorio>

Indica al compilador que busque archivos de inclusión en el Directorio. Al encontrar una directiva -include o -include_lib, el compilador busca archivos de encabezado en los siguientes directorios:
•".", el directorio de trabajo actual del servidor de archivos
•El nombre base del archivo compilado
•Los directorios especificados con la opción -I; el directorio especificado al final se busca primero

-o <Directorio>

El directorio donde el compilador debe colocar los archivos de salida. Por defecto es el directorio de trabajo actual.

-D<Nombre>

Define una macro.

-D<Nombre>=<Valor>

Define una macro con el valor especificado. El valor puede ser cualquier término de Erlang. Dependiendo de la plataforma, el valor puede necesitar ser entrecomillado si el propio shell interpreta ciertos caracteres. En Unix, los términos que contienen tuplas y listas deben ser entrecomillados. Los términos que contienen espacios deben ser entrecomillados en todas las plataformas.

-Werror

Convierte todas las advertencias en errores.

-W<Número>

Establece el nivel de advertencia a Número. El valor por defecto es 1. Para desactivar las advertencias, use -W0.

-W

Igual que -W1. Por defecto.

-v

Activa la salida detallada.

-b <Tipo_salida>

Especifica el tipo de archivo de salida. Tipo_salida es lo mismo que la extensión del archivo de salida, pero sin el punto. Esta opción es ignorada por los compiladores que tienen un único formato de salida.

-no-server

No utilizar el servidor de compilación.

-server

Utilizar el servidor de compilación.

-enable-feature <Característica>

Activa la característica característica durante la compilación. La característica especial all se puede usar para activar todas las características.

-disable-feature <característica>

Desactiva la característica característica durante la compilación. La característica especial all se puede usar para desactivar todas las características no permanentes.

-list-features

Enumera descripciones cortas de las características configurables actuales. Las características no configurables (aquellas con estado rejected o permanent) no se mostrarán.

-describe-feature <característica>

Muestra una descripción larga y el historial de la característica característica.

-M

Genera una regla de Makefile para rastrear dependencias de encabezados. La regla se envía a stdout. No se produce ningún archivo objeto.

-MMD

Genera dependencias como efecto secundario. El archivo objeto se producirá como de costumbre. Esta opción anula la opción -M.

-MF <Makefile>

Igual que la opción -M, excepto que el Makefile se escribe en Makefile. No se produce ningún archivo objeto.

-MD

Igual que -M -MF <Archivo>.Pbeam.

-MT <Objetivo>

En conjunción con la opción -M o -MF, cambia el nombre de la regla emitida a Objetivo.

-MQ <Objetivo>

Igual que la opción -MT, excepto que los caracteres especiales para make/1 se entrecomillan.

-MP

En conjunción con la opción -M o -MF, añade un objetivo ficticio para cada dependencia.

-MG

En conjunción con la opción -M o -MF, considera los encabezados faltantes como archivos generados y los añade a las dependencias.

--

Indica que no seguirán más opciones. El resto de los argumentos se tratan como nombres de archivo, incluso si comienzan con guiones.

+<Término>

Una opción que comienza con un signo más ( +) en lugar de un guion se convierte en un término de Erlang y se pasa sin cambios al compilador. Por ejemplo, la opción export_all para el compilador Erlang se puede especificar de la siguiente manera: 
erlc +export_all archivo.erl

Dependiendo de la plataforma, el valor puede necesitar ser entrecomillado si el propio shell interpreta ciertos caracteres. En Unix, los términos que contienen tuplas y listas deben ser entrecomillados. Los términos que contienen espacios deben ser entrecomillados en todas las plataformas.

Opciones especiales

Las siguientes opciones son útiles en situaciones especiales, como la reconstrucción del sistema OTP:

-pa <Directorio>

Añade Directorio al principio de la ruta de código en el emulador Erlang invocado. Esto se puede utilizar para invocar un compilador diferente al predeterminado.

-pz <Directorio>

Añade Directorio al final de la ruta de código en el emulador Erlang invocado.

Compiladores soportados

Los siguientes compiladores son compatibles:

.erl

Código fuente de Erlang. Genera un archivo .beam.

Las opciones -P, -E y -S son equivalentes a +'P', +'E' y +'S', excepto que no es necesario incluir las comillas simples para protegerlas del shell.

Opciones soportadas: -I, -o, -D, -v, -W, -b.

.S

Código fuente ensamblador de Erlang. Genera un archivo .beam.

Opciones soportadas: las mismas que para .erl.

.core

Código fuente de Erlang core. Genera un archivo .beam.

Opciones soportadas: las mismas que para .erl.

.yrl

Código fuente de Yecc. Genera un archivo .erl.

Utilice la opción -I con el nombre de un archivo para usar ese archivo como un archivo prólogo personalizado (opción includefile).

Opciones soportadas: -o, -v, -I, -W.

.mib

MIB para SNMP. Genera un archivo .bin.

Opciones soportadas: -I, -o, -W.

.bin

Una MIB compilada para SNMP. Genera un archivo .hrl.

Opciones soportadas: -o, -v.

.rel

Archivo de script. Genera un archivo de arranque.

Utilice la opción -I para nombrar directorios que se buscarán para archivos de aplicación (equivalente a la ruta en la lista de opciones para systools:make_script/2).

Opción soportada: -o.

.asn1

Archivo ASN1. Crea un archivo .erl, .hrl y .asn1db a partir de un archivo .asn1. También compila el .erl utilizando el compilador Erlang a menos que se especifique la opción +noobj.

Opciones soportadas: -I, -o, -b, -W.

.idl

Archivo IC. Ejecuta el compilador IDL.

Opciones soportadas: -I, -o.

Servidor de compilación

El servidor de compilación puede ser utilizado para

o potencialmente acelerar la compilación de proyectos de múltiples archivos al evitar iniciar un sistema Erlang para cada archivo a compilar. Si acelerará la compilación depende de la naturación del proyecto y de la máquina de compilación.

De forma predeterminada, el servidor de compilación no se utiliza. Se puede habilitar dando a erlc la opción -server o estableciendo la variable de entorno ERLC_USE_SERVER a yes o true.

Cuando el servidor de compilación está habilitado, erlc lo utilizará automáticamente si está iniciado, y lo iniciará si aún no se ha iniciado. El servidor se terminará a sí mismo cuando haya estado inactivo durante un número determinado de segundos.

erlc y el servidor de compilación se comunican mediante la distribución de Erlang. El servidor de compilación se inicia como un nodo oculto, con un nombre que incluye al usuario actual. Así, cada usuario en un ordenador tiene su propio servidor de compilación.

Utilizar el servidor de compilación no siempre acelera la compilación, ya que el servidor de compilación a veces debe reiniciarse para garantizar la corrección. A continuación se muestran algunos ejemplos de situaciones que fuerzan un reinicio:

•erlc quiere usar una versión diferente de Erlang a la que usa el servidor de compilación.
•erlc quiere usar opciones diferentes para erl a las con las que se inició el servidor de compilación. (Un cambio en la ruta de código usando la opción -pa podría causar que se carguen transformaciones de análisis diferentes. Por seguridad, el servidor de compilación se reiniciará cuando se cambie cualquier opción de erl .)
•Si el directorio de trabajo actual para erlc es diferente del directorio de trabajo activo cuando se inició el servidor de compilación, y si el servidor de compilación tiene trabajos activos, se reiniciará tan pronto como esos trabajos hayan terminado. (Los sistemas de compilación que compilan archivos aleatoriamente en múltiples directorios en paralelo probablemente no se beneficiarán del servidor de compilación.)

Variables de entorno

ERLC_EMULATOR

El comando para iniciar el emulador, que debe ser solo la ruta al emulador sin ningún parámetro. Por defecto es erl en el mismo directorio que el propio programa erlc , o, si no existe, erl en cualquiera de los directorios especificados en la variable de entorno PATH.

ERLC_USE_SERVER

Los valores permitidos son yes o true para usar el servidor de compilación, y no o false para no usar el servidor de compilación. Si se proporcionan otros valores, erlc imprimirá un mensaje de advertencia y continuará.

ERLC_SERVER_ID

Indica a erlc que identifique el servidor de compilación por el nombre dado, permitiendo a un único usuario ejecutar múltiples compilaciones no relacionadas en paralelo sin que se afecten entre sí, lo que puede ser útil para máquinas de compilación compartidas y similares. El nombre debe ser alfanumérico y por defecto está vacío.
