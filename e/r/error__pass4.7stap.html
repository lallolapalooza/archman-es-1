NOMBRE

error::pass4 - errores de la pasada 4 de systemtap

DESCRIPCIÓN

Los errores que ocurren durante la pasada 4 (compilación) generalmente solo tienen unas pocas causas:

cambios en la versión del kernel o del SO
El runtime de systemtap y los fragmentos C incrustados en la biblioteca tapset están diseñados para ser portables en una amplia gama de versiones del SO. Sin embargo, pueden ocurrir incompatibilidades cuando se producen algunos cambios en el SO, como modificaciones del kernel que cambian funciones, tipos o macros referenciadas por systemtap. Las compilaciones upstream (git://sourceware.org/git/systemtap.git) de systemtap a menudo se actualizan rápidamente para incluir correcciones relevantes, así que intente obtener o realizar una compilación actualizada. Reescribiendo: compilar systemtap desde git para usar con kernels muy recientes. Si el problema persiste, informe el problema a los desarrolladores de systemtap.
código C incrustado con errores
Systemtap no puede verificar el código C incrustado en su propio script en modo guru y se pasa textualmente al compilador. Los errores en tales fragmentos de código pueden encontrarse durante la invocación del compilador de la pasada 4, aunque pueden ser difíciles de identificar por los errores del compilador.
código C incrustado incompatible
Los estándares de interfaz entre el código generado por systemtap y el código C incrustado cambian ocasionalmente. Por ejemplo, antes de la versión 1.8, los argumentos se pasaban utilizando las macros THIS->foo y THIS->__retvalue, pero a partir de la versión 1.8, se utilizan STAP_ARG_foo y STAP_RETVALUE. Ajuste su código C incrustado a los estándares actuales o use la opción stap --compatible=VERSION para hacer que systemtap use uno diferente.
errores y misterios del compilador
Mensajes como "internal compiler error" sugieren problemas con el compilador. Estos deben informarse a los desarrolladores del compilador en forma de un archivo .i preprocesado, más la línea de comandos del compilador. Para recopilar información relevante, ejecute 
stap -k --vp 0003 -p4 ....

Systemtap informará el directorio temporal guardado y la línea de comandos del compilador que intentó. Vaya al directorio para encontrar el archivo principal generado stap_NNNNN_src.c. Fuerza al compilador a producir un archivo preprocesado con:

make -C /lib/modules/`uname -r`/build M=`pwd` stap_NNNNN_src.i

(note el sufijo .i), y la línea de comandos del compilador debería estar en el archivo .stap_NNNNN_src.i.cmd.
