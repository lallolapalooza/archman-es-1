NOMBRE

error::pass5 - errores de la pasada 5 de systemtap

DESCRIPCIÓN

Los errores que ocurren durante la pasada 5 (ejecución) pueden tener una variedad de causas.

eventos excepcionales durante la ejecución del script
El traductor y el runtime de SystemTap incluyen numerosas comprobaciones de errores que buscan proteger a los sistemas y a los usuarios de errores o condiciones transitorias. El script puede llamar deliberadamente a la función tapset error() para señalar un problema. Es posible que la memoria necesaria para acceder a las variables de $context no esté temporalmente disponible. Considere usar la construcción try/catch para envolver fragmentos de script en código de manejo de excepciones. Considere usar la opción stap --suppress-handler-errors o stap --skip-badvars.
agotamiento de recursos
Puede que el script exceda uno de varios límites de recursos de espacio o tiempo, incluyendo sobrecarga del sistema, demasiadas tuplas para ser almacenadas en un array, etc. Algunos de los mensajes de error identifican la restricción por nombre de macro, la cual puede ser aumentada individualmente. Considere usar las opciones stap --suppress-handler-errors y/o stap -g --suppress-time-limits. Extienda o deshabilite límites de recursos individuales usando la opción stap -DSOME_LIMIT=NNNN. La opción stap -t puede identificar aquellas sondas que están tardando demasiado.
problemas con el servidor de ejecución remota
Si usa la opción stap --remote para dirigir la ejecución de un script de SystemTap en otro lugar, asegúrese de que se pueda establecer una conexión SSH al host remoto y que este tenga instalado y disponible el runtime actual de SystemTap.
incompatibilidad de versión del kernel
Si ve un mensaje de error como "Couldn't insert module ..." al ejecutar el script, la versión del árbol de desarrollo del kernel seleccionada por stap (o por el usuario a través de la opción -r) podría no coincidir con la del kernel en ejecución real. Esto puede ocurrir más fácilmente si ejecuta kernels compilados manualmente. Compruebe la salida de dmesg para obtener pistas.
problemas de instalación/permiso
Es posible que su copia de SystemTap no se haya instalado correctamente. Por ejemplo, al programa /usr/bin/staprun le podrían faltar los permisos setuid necesarios, o su usuario invocador podría no tener privilegios suficientes (root, o membresías de grupo stapusr y relacionadas). Las variables de entorno pueden interferir con la localización de /usr/libexec/.../stapio.
configuración de seguridad
SecureBoot u otra maquinaria de firma de módulos podría estar en efecto, impidiendo la carga de módulos .ko. Un servicio stap-server local o remoto sería necesario para gestionar de forma segura las claves. Esta situación se detecta automáticamente en la mayoría de los kernels, pero en algunos, la variable de entorno SYSTEMTAP_SIGN podría tener que establecerse para activar este procesamiento adicional relacionado con la firma. Compruebe la salida de dmesg para obtener pistas.

El backend normal de SystemTap basado en módulos del kernel podría ser más de lo que su script requiere. Pruebe los backends stap --runtime=bpf y/o stap --runtime=dyninst. Aunque tienen limitaciones inherentes, operan con menores privilegios y riesgos percibidos.

Podría ser posible deshabilitar temporalmente las medidas de seguridad/bloqueo con la combinación de teclas SysRQ+x, o permanentemente con sudo mokutil --disable-validation y un reinicio.

errores del programa objetivo
El programa invocado por la opción stap -c CMD puede salir con un código distinto de cero.
excepciones no capturadas en el programa objetivo
Al usar --runtime=dyninst, puede encontrar un problema donde el programa objetivo se aborta con un mensaje como "terminate called after throwing an instance of 'foo_exception'". Desafortunadamente, esta es una limitación de Dyninst, que a veces impide que las excepciones se desenrollen correctamente a través del código instrumentado.

RECOPILAR MÁS INFORMACIÓN

Aumentar la verbosidad de la pasada 5 con una opción como --vp 00001 puede ayudar a localizar el problema. Ver también: dmesg en las máquinas relevantes.
