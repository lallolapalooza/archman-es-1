erl_call(1) Comandos de usuario erl_call(1)

NOMBRE

erl_call - Llamar/iniciar un nodo Erlang distribuido

DESCRIPCIÓN

erl_call hace posible iniciar y/o comunicarse con un nodo Erlang distribuido. Está construido sobre la biblioteca Erl_Interface como una aplicación de ejemplo. Su propósito es usar un script de shell de Unix para interactuar con un nodo Erlang distribuido. Realiza toda la comunicación con el servidor rex de Erlang, utilizando la instalación RPC estándar de Erlang. No requiere ningún software especial para ejecutarse en el nodo de destino de Erlang.

El uso principal es iniciar un nodo Erlang distribuido o realizar una llamada de función ordinaria. Sin embargo, también es posible enviar un módulo Erlang a erl_call y compilarlo, o enviar una secuencia de expresiones Erlang para ser evaluadas (similar al shell de Erlang).

Las opciones, que hacen que stdin sea leído, pueden usarse con ventaja, como scripts desde el interior de scripts de shell (Unix). Otro buen uso de erl_call podría ser desde scripts CGI-bin (HTTP).

erl_call <opciones>

Inicia/llama a Erlang.

Cada opción se describe a continuación con su nombre, tipo y significado.

-a [Mod [Fun [Args]]]]

( Opcional.) Aplica la función especificada y devuelve el resultado. Se debe especificar Mod. Sin embargo, se asume start y [] para Fun y Args no especificados, respectivamente. Args debe tener el mismo formato que para erlang:apply/3 en ERTS, excepto que solo se permite un subconjunto de todos los términos. Los tipos de términos permitidos son: lista (y representación de string de lista, es decir, "ejemplo"), tupla, átomo y número.

Tenga en cuenta que esta bandera toma exactamente un argumento, por lo que puede ser necesario usar comillas para agrupar Mod, Fun y Args de una manera dependiente del comportamiento de su shell de comandos.

-address [Hostname:]Puerto

(Se requiere una de las opciones -n, -name, -sname o -address.) Hostname es el nombre de host de la máquina que está ejecutando el nodo par con el que se comunicará erl_call. El nombre de host predeterminado es el nombre de host de la máquina local. Puerto es el número de puerto del nodo con el que se comunicará erl_call. La bandera -address no se puede combinar con ninguna de las banderas -n, -name, -sname o -s.

La bandera -address es típicamente útil cuando se desea llamar a un nodo que se está ejecutando en una máquina sin una instancia de epmd accesible.

-c Cookie

( Opcional.) Utilice esta opción para especificar una cookie determinada. Si no se especifica ninguna cookie, se lee el archivo ~/.erlang.cookie y su contenido se utiliza como cookie. El nodo Erlang con el que queremos comunicarnos debe tener la misma cookie.

-d

( Opcional.) Modo de depuración. Esto hace que toda la E/S se envíe al archivo ~/.erl_call.out.NombreNodo, donde NombreNodo es el nombre del nodo Erlang en cuestión.

-e

( Opcional.) Lee una secuencia de expresiones Erlang, separadas por comas (,) y terminadas con un punto (.), desde stdin hasta EOF (Control-D). Evalúa las expresiones y devuelve el resultado de la última expresión. Devuelve {ok,Resultado} en caso de éxito.

-fetch_stdout

( Opcional.) Ejecuta el código, especificado con la opción -a o -e, en un nuevo proceso que tiene un líder de grupo que reenvía toda la salida estándar (stdout) para que se imprima en la salida estándar del proceso erl_call. Esto significa que los datos de stdout que se escriben durante la ejecución del código llamado, por el código y por los procesos descendientes, se reenviarán (dado que el líder de grupo no ha sido cambiado por una llamada a erlang:group_leader/2).

Los datos impresos están codificados en UTF-8.

Esta opción solo es relevante combinada con las opciones -a o -e.

Consulte la documentación del protocolo de E/S para obtener más información sobre el concepto de líder de grupo.

NOTA: Esta opción solo funciona cuando erl_call está interactuando con un nodo con una versión igual o superior a OTP-24.

-h NombreOculto

( Opcional.) Especifica el nombre del nodo oculto que representa erl_call.

-m

( Opcional.) Lee un módulo Erlang desde stdin y lo compila.

-n Nodo

(Se requiere una de las opciones -n, -name, -sname o -address.) Tiene el mismo significado que -name y aún puede usarse por razones de compatibilidad con versiones anteriores.

-name Nodo

(Se requiere una de las opciones -n, -name, -sname o -address.) Nodo es el nombre del nodo par que se iniciará o con el que se comunicará. Se asume que Nodo se inicia con erl -name, lo que significa que se utilizan nombres de nodo largos y completos. Si se especifica la opción -s, se iniciará un nodo Erlang (si es necesario) con erl -name.

-no_result_term

( Opcional.) No imprime el término de resultado. Esta opción solo es relevante junto con las opciones -a y -e.

-q

( Opcional.) Detiene el nodo Erlang especificado con la opción -n. Esta opción anula la opción -s.

-r

( Opcional.) Genera un nombre aleatorio para el nodo oculto que representa erl_call.

-R

( Opcional.) Solicita un nombre aleatorio dinámico, del nodo oculto que representa erl_call, desde el nodo par. Compatible desde OTP 23. Prefiera -R sobre -r al realizar solicitudes repetidas al mismo nodo par.

-s

( Opcional.) Inicia un nodo Erlang distribuido si es necesario. Esto significa que en una secuencia de llamadas, donde '-s' y '-n Nodo' son constantes, solo la primera llamada inicia el nodo Erlang. Esto hace que el resto de la comunicación sea muy rápida. Esta bandera actualmente solo está disponible en plataformas similares a Unix (Linux, Mac OS X, Solaris, etc.).

-sname Nodo

(Se requiere una de las opciones -n, -name, -sname o -address.) Nodo es el nombre del nodo par que se iniciará o con el que se comunicará. Se asume que Nodo se inicia con erl -sname, lo que significa que se utilizan nombres de nodo cortos. Si se especifica la opción -s, se iniciará un nodo Erlang (si es necesario) con erl -sname.

-timeout Segundos

( Opcional.) Aborta el proceso erl_call después de que expire el tiempo de espera. Tenga en cuenta que esto no interrumpe los comandos que ya se han iniciado con -a, -e o similares.

-v

( Opcional.) Imprime mucha información detallada. Esto solo es útil para el desarrollador y mantenedor de erl_call.

-x ScriptErl

( Opcional.) Especifica un nombre diferente para el script de inicio de Erlang que se utilizará. Si no se especifica, se utiliza el script de inicio estándar erl.

Ejemplos

Para iniciar un nodo Erlang y llamar a erlang:time/0:

erl_call -s -a 'erlang time' -n madonna
{18,27,34}

Para terminar un nodo Erlang llamando a erlang:halt/0:

erl_call -s -a 'erlang halt' -n madonna

Para aplicar con muchos argumentos:

erl_call -s -a 'lists seq [1,10]' -n madonna

Para evaluar algunas expresiones (la entrada termina con EOF (Control-D)):

erl_call -s -e -n madonna
statistics(runtime),
X=1,
Y=2,
{_,T}=statistics(runtime),
{X+Y,T}.
^D
{ok,{3,0}}

NAME

erl_call - Execute Erlang code on a remote Erlang node.

SYNOPSIS

erl_call [ -sname NAME ] [ -name NAME ] [ -setcookie COOKIE ] [ -e ] [ -s ] [ -verbose ] [ -fetch_stdout ] [ -no_result_term ] NODE FUNCTION [ ARG ... ]

erl_call FILE

DESCRIPTION

The erl_call utility provides a simple way to execute Erlang code on a remote Erlang node. It can be used to perform administrative tasks, query information, or execute arbitrary Erlang code.

The utility can either execute a specified Erlang function on a given node, or execute the Erlang code contained within a file.

Arguments are passed using standard Erlang syntax. For example, atoms are represented as atom, strings as "string", integers as 123, lists as [1, 2, atom], etc.

The default behaviour is to print the result term of the executed function to standard output. If the result is ok, {ok, Value}, or error, {error, Reason}, it will be formatted accordingly.

The following options are available:

-sname NAME
Connect to a node using a short name.
-name NAME
Connect to a node using a full name.
-setcookie COOKIE
Set the Erlang cookie for connecting to the remote node.
-e
Enable Erlang tracing.
-s
Enable Erlang shell commands. This is useful when executing code from a file where the last expression's result should not be printed.
-verbose
Print debugging information about the connection and execution process.
-fetch_stdout
Fetch and print standard output from the remote Erlang node. This is useful for functions that perform I/O operations, such as io:format/2.
-no_result_term
Do not print the result term of the executed function. This is useful in combination with -fetch_stdout when you only want to see the output and not the return value of the function.

EXAMPLES

To get the registered names on a node named madonna@chivas.du.etx.ericsson.se with the cookie bar:

erl_call -sname madonna -setcookie bar -e -registered_name
^D
[{error,
  {undef,
   [{erl_call_handler,registered_name,[],[]},
    {erl_call_handler,loop,4,[]}]}}].

The above example shows an error because registered_name is not a valid function. To get the registered names, you should use erlang:registered():

erl_call -sname madonna -setcookie bar erlang:registered\(\)
^D
[global_name_server,net_sup,rex,net_kernel,error_logger,kernel,auth,application_controller,kernel_sup,user,code_server,file_server]

To get the registered names with more details, you can query pgc:ps/0 (if pgc application is running):

erl_call -sname madonna -setcookie bar pgc:ps\(\)
^D
[{mnesia,promoted,[]},
 {global,global,[]},
 {kernel,user,[]},
 {kernel,file_server,[]},
 {kernel,code_server,[]},
 {kernel,auth,[]},
 {kernel,net_kernel,[]},
 {kernel,net_sup,[]},
 {kernel,kernel_sup,[]},
 {kernel,error_logger,[]},
 {kernel,application_controller,[]},
 {kernel,kernel,[]}]

To execute Erlang code from a file named myscript.erl:

erl_call -sname madonna -setcookie bar myscript.erl

Where myscript.erl contains:

-module(myscript).
-export([start/0]).

start() ->
    io:format("Hello from myscript!~n"),
    {ok, os:cmd("ls -l")}.

The output will be:

Hello from myscript!
total 4
-rw-r--r-- 1 user group 123 Jan 1 12:00 myscript.erl

To fetch standard output without printing the result term:

erl_call -sname madonna -setcookie bar -fetch_stdout -no_result_term
io:format("Erlang version: ~p~n", [erlang:system_info(version)]),
erlang:halt().
^D
Erlang version: 25.3.2
