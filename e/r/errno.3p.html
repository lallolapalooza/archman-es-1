ERRNO(3P) Manual del programador POSIX ERRNO(3P)

PROLOGO

Esta página del manual forma parte del Manual del programador POSIX. La implementación de esta interfaz en Linux puede diferir (consulte la página del manual de Linux correspondiente para obtener detalles sobre el comportamiento en Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

errno — valor de retorno de error

SINOPSIS

#include <errno.h>

DESCRIPCION

El lvalue errno es utilizado por muchas funciones para devolver valores de error.

Muchas funciones proporcionan un número de error en errno, que es de tipo int y está definido en <errno.h>. El valor de errno se definirá solo después de una llamada a una función para la que se indique explícitamente que se establecerá y hasta que sea cambiado por la siguiente llamada a función o si la aplicación le asigna un valor. El valor de errno solo debe examinarse cuando se indica que es válido por el valor de retorno de una función. Las aplicaciones obtendrán la definición de errno mediante la inclusión de <errno.h>. Ninguna función en este volumen de POSIX.1‐2017 establecerá errno a 0. La configuración de errno después de una llamada exitosa a una función no está especificada, a menos que la descripción de esa función especifique que errno no se modificará.

No está especificado si errno es una macro o un identificador declarado con enlace externo. Si se suprime una definición de macro para acceder a un objeto real, o si un programa define un identificador con el nombre errno, el comportamiento no está definido.

Los valores simbólicos almacenados en errno se documentan en las secciones ERRORS de todas las páginas relevantes.

USO DE APLICACIONES

Anteriormente, tanto los documentos POSIX como los X/Open eran más restrictivos que el estándar ISO C, ya que requerían que errno se definiera como una variable externa, mientras que el estándar ISO C solo requería que errno se definiera como un lvalue modificable de tipo int.

Una aplicación que necesita examinar el valor de errno para determinar el error debe establecerlo a 0 antes de una llamada a función, y luego inspeccionarlo antes de una llamada a función subsiguiente.
