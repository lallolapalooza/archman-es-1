DESCRIPCIÓ

N

e2fsck.conf es el archivo de configuración para e2fsck(8). Controla el comportamiento predeterminado de e2fsck(8) mientras verifica los sistemas de archivos ext2, ext3 o

ext4.

El archivo e2fsck.conf utiliza un formato de estilo INI. Las estrofas, o secciones de primer nivel, están delimitadas por corchetes: [ ]. Dentro de cada sección, cada línea define una relación, que asigna etiquetas a valores, o a una subsección, que contiene más relaciones o subsecciones. A continuación se muestra un ejemplo del formato de estilo INI utilizado por este archivo de

configuración:

[section1]
tag1 = value_a
tag1 = value_b
tag2 =

value_c

[section 2]
tag3 = {
subtag1 = subtag_value_a
subtag1 = subtag_value_b
subtag2 = subtag_value_c
}
tag1 = value_d
tag2 = value_e

}

Los comentarios están delimitados por un punto y coma (';') o un carácter almohadilla ('#') al comienzo del comentario, y terminan con el carácter de fin de

línea.

Las etiquetas y los valores deben estar entre comillas dobles si contienen espacios. Dentro de una cadena entre comillas, se aplican las interpretaciones estándar de la barra invertida: "\n" (para el carácter de nueva línea), "\t" (para el carácter de tabulación), "\b" (para el carácter de retroceso) y "\\" (para el carácter de barra invertida)

.

Las siguientes estrofas se utilizan en el archivo e2fsck.conf. Se describirán con más detalle en las secciones posteriores de este

documento.

LA ESTROFA

[options]

Las siguientes relaciones se definen en la estrofa [options]

.
allow_cancellat
ion
Si esta relación se establece en un valor booleano de true, entonces si el usuario interrumpe e2fsck usando ^C, y el sistema de archivos no está marcado explícitamente como que contiene errores, e2fsck saldrá con un estado de salida de 0 en lugar de 32. Esta configuración tiene el valor predeterminado de
false.
accept_time_fu
dge
Desafortunadamente, debido a la desafortunada decisión de diseño de Windows de configurar el reloj de hardware para q
ue marque la hora local, en lugar de la hora UTC más adecuada y menos propensa a errores, muchos usuarios terminan en
una situación en la que el reloj del sistema está configurado incorrectamente en el momento en que se ejecuta e2fsck.
Históricamente, esto solía deberse a que algunas distribuciones tenían scripts de inicio y/o instaladores con errores que no detectaban correctamente este caso y tomaban las medidas de contramedida correspondientes. Desafortunadamente, esto sigue siendo cierto ocasionalmente hoy en día, generalmente debido a un gestor de virtualización con errores o mal configurado, o a que el instalador no tenía acceso a un servidor de tiempo de red durante el proceso de instalación. Por lo tanto, de forma predeterminada, permitimos que los tiempos del superbloque sean manipulados hasta por 24 horas. Esto se puede deshabilitar estableciendo accept_time_fudge en el valor booleano de false. Esta co
nfiguración tiene el v
alor predeterminado de true.
broken_system_cl
ock
El programa e2fsck(8) tiene algunas heurísticas que asumen que el reloj del sistema es correcto. Además, muchos programas del sistema hacen supuestos similares. Por ejemplo, la biblioteca UUID depende de que el tiempo no vaya hacia atrás para poder cumplir sus garantías de emisión de identificadores universalmente únicos. Los sistemas con relojes del sistema rotos están, bueno, rotos. Sin embargo, los relojes del sistema rotos, particularmente en sistemas integrados, existen. E2fsck intentará usar heurísticas para determinar si el tiempo no es confiable; y omitir las comprobaciones basadas en el tiempo si esto es cierto. Si este booleano se establece en true, entonces e2fsck siempre asumirá que el reloj del sistema no es
confiable.
buggy_init_scri
pts
Esta relación booleana es un alias para accept_time_fudge por compatibilidad con versiones anteriores; antes, el comportamiento definido por accept_time_fudge anteriormente tenía el valor predeterminado de false, y buggy_init_scripts habilitaría que el campo de tiempo del superbloque estuviera incorrecto hasta por 24 horas. Cuando cambiamos el valor predeterminado, también renombramos esta relación booleana a accept_time_fud
ge.
clear_test_fs_f
lag
Esta relación booleana controla si e2fsck(8) ofrecerá o no borrar la bandera test_fs si el sistema de archivos ext4 está disponible en el sistema. Su valor predeterminado es
true.
defer_check_on_batt
ery
Esta relación booleana controla si el intervalo entre las comprobaciones del sistema de archivos (ya sea basado en el tiempo o en el número de montajes) debe duplicarse si el sistema está funcionando con batería. Esta configuración tiene el valor predeterminado de
true.
indexed_dir_slack_percent
age
Cuando e2fsck(8) reempaqueta un directorio indexado, reserve el porcentaje especificado de espacio vacío en cada nodo hoja para que se puedan añadir algunas entradas nuevas al directorio sin dividir nodos hoja, de modo que la relación media de llenado de los directorios se pueda mantener en un nivel más alto y eficiente. Esta relación tiene el valor predeterminado de 20 por
ciento.
inode_count_full
map
Si esta relación booleana es true, se intercambia el uso de memoria por velocidad al comprobar un sistema de archivos con un gran número de archivos con enlaces duros. La cantidad de memoria requerida es proporcional al número de inodos en el sistema de archivos. Para sistemas de archivos grandes, esto puede ser de gigabytes de memoria. (Por ejemplo, un sistema de archivos de 40 TB con 2.8 mil millones de inodos consumirá 5.7 GB de memoria adicional si esta optimización está habilitada.) Esta configuración tiene el valor predeterminado de
false.
log_d
ir
Si las relaciones log_filename o problem_log_filename contienen una ruta relativa, entonces el archivo de registro se colocará en el directorio nombrado por la relación lo
g_dir.
log_dir_fallb
ack
Esta relación contiene un directorio alternativo que se utilizará si el directorio especificado por log_dir no está disponible o no es
escribible.
log_dir_wa
it
Si esta relación booleana es true, entonces si los directorios especificados por log_dir o log_dir_fallback no están disponibles o aún no son escribibles, e2fsck guardará la salida en un búfer de memoria, y un proceso hijo comprobará periódicamente si el directorio de registro se ha vuelto disponible después de que la secuencia de arranque haya montado el sistema de archivos solicitado para lectura/escritura. Esto implementa la funcionalidad proporcionada por logsave(8) para los archivos de registro de
e2fsck.
log_filena
me
Esta relación especifica el nombre de archivo donde se escribirá una copia de la salida de e2fsck. Si ciertos informes de problemas se suprimen usando la relación max_count_problems, (o por problema individual usando la relación max_count), el conjunto completo de informes de problemas se escribirá en el archivo de registro. El nombre de archivo puede contener varias expresiones de porcentaje (%D, %T, %N, etc.) que se expandirán para que el nombre de archivo del registro pueda incluir cosas como la fecha, la hora, el nombre del dispositivo y otros parámetros en tiempo de ejecución. Vea la sección LOGGING para más
detalles.
max_count_proproble
mas
Esta relación especifica el número máximo de informes de problemas de un tipo particular que se imprimirán en stdout antes de que se silencien más informes de problemas de ese tipo. Esto puede ser útil si la consola es lenta (es decir, está conectada a un puerto serie) y por lo tanto una gran cantidad de salida podría terminar retrasando el proceso de arranque durante mucho tiempo (potencialmente horas)
.
no_optimize_exte
nts
Si esta relación booleana es verdadera, no se ofrecerá optimizar el árbol de extensiones reduciendo el ancho o la profundidad del árbol. Esta configuración por defecto es
false.
problem_log_filen
ame
Esta relación especifica el nombre del archivo donde se escribirá un registro de los códigos de problemas encontrados por e2fsck. El nombre del archivo puede contener varias expresiones porcentuales (%D, %T, %N, etc.) que se expandirán para que el nombre del archivo de registro pueda incluir cosas como fecha, hora, nombre del dispositivo y otros parámetros en tiempo de ejecución. Vea la sección LOGGING para más
detalles.
readahead_mem_
pct
Use este porcentaje de memoria para intentar leer bloques de metadatos por delante del hilo principal de e2fsck. Esto debería reducir los tiempos de ejecución, dependiendo de la velocidad del almacenamiento subyacente y la cantidad de memoria libre. No hay un valor por defecto, pero vea readahead_kb para más
detalles.
readahead_
kb
Use esta cantidad de memoria para leer bloques de metadatos por delante del hilo principal de comprobación. Establecer este valor a cero desactiva la lectura anticipada por completo. Por defecto, se establece al tamaño de las tablas de inodos de dos grupos de bloques (típicamente 4MiB en un sistema de archivos ext4 regular); si esta cantidad es más de 1/50 de la memoria física total, la lectura anticipada se
desactiva.
report_featu
res
Si esta relación booleana es verdadera, e2fsck imprimirá las características del sistema de archivos como parte de su informe detallado (es decir, si se especifica la opción
-v)
report_ti
me
Si esta relación booleana es verdadera, e2fsck se ejecutará como si las opciones -tt se especificaran siempre. Esto hará que e2fsck imprima estadísticas de tiempo paso a paso para las completas comprobaciones del sistema de
archivos.
report_verbo
se
Si esta relación booleana es verdadera, e2fsck se ejecutará como si la opción -v se especificara siempre. Esto hará que e2fsck imprima algo de
información adicional al f
inal de cada comprobación complet
a del sistema de archivos.

LA SECCIÓN

[problems]

Cada etiqueta en la sección [problems] nombra un código de problema especificado con un "0x" inicial seguido de seis dígitos hexadecimales. El valor de la etiqueta es una subsección donde las relaciones en esa subsección sobreescriben el tratamiento por defecto de ese código de problema en

particular.

Tenga en cuenta que configuraciones inapropiadas en esta sección pueden hacer que e2fsck se comporte incorrectamente, o incluso se bloquee. La mayoría de los administradores de sistemas no deberían hacer cambios en esta sección sin consultar el código

fuente.

Dentro de la subsección de cada código de problema, se pueden usar las siguientes

etiquetas:
descripti
on
Esta relación permite sobreescribir el mensaje que se imprime cuando se detecta esta inconsistencia del sistema de
archivos.
preen_
ok
Esta relación booleana sobreescribe el comportamiento por defecto que controla si este problema del sistema de archivos debe corregirse automáticamente cuando e2fsck se está ejecutando en modo
preen.
max_cou
nt
Esta relación entera sobreescribe el parámetro max_count_problems (establecido en la sección de opciones) para este problema en
particular.
no_
ok
Esta relación booleana sobreescribe el comportamiento por defecto que determina si el sistema de archivos se marcará como inconsistente o no si el usuario declina corregir el problema
reportado.
no_defau
lt
Esta relación booleana sobreescribe si la respuesta por defecto para este problema (o pregunta) debería ser
"no".
preen_nomess
age
Esta relación booleana sobreescribe el comportamiento por defecto que controla si la descripción de este problema del sistema de archivos debe suprimirse o no cuando e2fsck se está ejecutando en modo
preen.
no_nom
sg
Esta relación booleana sobreescribe el comportamiento por defecto que controla si la descripción de este problema del sistema de archivos debe suprimirse o no cuando un problema se fuerza a no ser corregido, ya sea porque e2fsck se ejecuta con la opción -n o porque la marca force_no se ha establecido para el
problema.
force_
no
Esta opción booleana, si se establece en true, fuerza a que un problema nunca se corrija. Es decir, será como si el usuario respondiera 'no' a la pregunta de '¿debería corregirse este problema?'. La opción force_no incluso sobreescribe la opción -y dada en la línea de comandos (solo para el problema específico, por supuesto)
.
not_a_f
ix
Esta opción booleana, si se establece en true, marca el problema como uno donde, si el usuar
io da permiso para hacer el cambio solicitado, no significa que el sistema de archivos tuvier
a un problema que haya sido corregido desde entonces. Esto se usa para solicitudes de optimiz
ar la estructura de datos del sistema de archivos, como podar un árbol de extensiones.

REGISTR

O

E2fsck tiene la capacidad de guardar la información de una ejecución de e2fsck en un directorio para que un administrador de sistemas pueda revisar su salida a su conveniencia. Esto permite que la información capturada durante la ejecución automática de preen de e2fsck, así como una ejecución de e2fsck iniciada manualmente, se guarde para la posteridad. Esta capacidad está controlada por las relaciones log_filename, log_dir, log_dir_fallback y log_dir_wait en la sección [options]

.

EJEMPLO

S

La siguiente receta evitará que e2fsck se aborte durante el proceso de arranque cuando un sistema de archivos contiene archivos huérfanos. (Por supuesto, esto no siempre es una buena idea, ya que los archivos críticos necesarios para la seguridad del sistema podrían terminar potencialmente en lost+found, y arrancar el sistema sin que primero un administrador de sistemas revise las cosas puede ser peligroso.

)

[problems]
0x040002 = {
preen_ok = true
description = "@u @i %i. "

}

La siguiente receta hará que un archivo de registro de e2fsck se escriba en el directorio /var/log/e2fsck, con un nombre de archivo que contiene el nombre del dispositivo, el nombre de host del sistema, la fecha y la hora: por ejemplo, "e2fsck-sda3.server.INFO.20120314-112142". Si el directorio que contiene /var/log está ubicado en el sistema de archivos raíz que inicialmente se monta solo lectura, entonces la salida se guardará en memoria y se escribirá una vez que el sistema de archivos raíz haya sido remontado lectura/escritura. Para evitar que se escriba demasiado detalle en el sconsola serie (lo que podría ralentizar la secuencia de arranque), imprimir no más de 16 instancias de cada tipo de corrupción del sistema de

archivos.

log_dir = /var/log/e2fsck
log_filename = e2fsck-%N.%h.INFO.%D-%T
