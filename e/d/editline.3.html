FUNCIONES DE TOKENIZACIÓN

Las funciones de tokenización utilizan una estructura de datos común, Tokenizer, que es creada por tok_init() y liberada por tok_end().

Las siguientes funciones están disponibles:

tok_init()
Inicializar el tokenizador y devolver una estructura de datos para ser utilizada por todas las demás funciones de tokenización. IFS contiene los Separadores de Campos de Entrada, que por defecto son ⟨espacio⟩, ⟨tabulador⟩ y ⟨salto de línea⟩ si es NULL.
tok_end()
Limpiar y finalizar con t, asumiendo que fue creado con tok_init().
tok_reset()
Restablecer el estado del tokenizador. Usar después de que una línea haya sido tokenizada con éxito por tok_line() o tok_str() y antes de que una nueva línea vaya a ser tokenizada.
tok_line()
Tokenizar li, Si tiene éxito, modificar: argv para contener las palabras, argc para contener el número de palabras, cursorc (si no es NULL) para contener el índice de la palabra que contiene el cursor, y cursoro (si no es NULL) para contener el desplazamiento dentro de argv[cursorc] del cursor.

Devuelve 0 si tiene éxito, -1 para un error interno, 1 para una comilla simple sin cerrar, 2 para una comilla doble sin cerrar, y 3 para un ⟨salto de línea⟩ entrecomillado con barra invertida. Un código de salida positivo indica que se debe leer otra línea e intentar tokenizar de nuevo.

tok_str()
Una forma más simple de tok_line(); str es una cadena terminada en NUL a tokenizar.

HISTORIAL

La biblioteca editline apareció por primera vez en 4.4BSD. CC_REDISPLAY apareció en NetBSD 1.3. CC_REFRESH_BEEP, EL_EDITMODE y la emulación de readline aparecieron en NetBSD 1.4. EL_RPROMPT apareció en NetBSD 1.5.

AUTORES

La biblioteca editline fue escrita por Christos Zoulas. Luke Mewburn escribió este manual e implementó CC_REDISPLAY, CC_REFRESH_BEEP, EL_EDITMODEy EL_RPROMPT. Jaromir Dolecek implementó la emulación de readline. Johny Mattsson implementó el soporte de caracteres anchos.

ERRORES

En este momento, es responsabilidad del llamador verificar el resultado de la operación EL_EDITMODE de el_get() (después de un el_source() o el_parse()) para determinar si editline debe usarse para más entrada. Es decir, EL_EDITMODE es puramente una indicación del resultado del comando editrc(5) edit más reciente.
