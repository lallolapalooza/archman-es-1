ED(1P) Manual de Programación POSIX ED(1P)

PROLOG

Esta página del manual es parte del Manual de Programación POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

ed — editar texto

SINOPSIS

ed [-p cadena] [-s] [archivo]

DESCRIPCIÓN

La utilidad ed es un editor de texto orientado a líneas que utiliza dos modos: modo de comando y modo de entrada. En modo de comando, los caracteres de entrada se interpretarán como comandos, y en modo de entrada se interpretarán como texto. Consulte la sección DESCRIPCIÓN EXTENDIDA.

Si un operando es '-', los resultados no están especificados.

OPCIONES

La utilidad ed cumplirá con el volumen de Definiciones Base de POSIX.1‐2017, Sección 12.2, Directrices de sintaxis de utilidades, excepto por el uso no especificado de '-'.

Se admitirán las siguientes opciones:

-p cadena
Utilice cadena como la cadena de aviso cuando esté en modo de comando. Por defecto, no habrá cadena de aviso.
-s
Suprima la escritura de recuentos de bytes por los comandos e, E, r y w y del aviso '!' después de un !comando.

OPERANDOS

Se admitirá el siguiente operando:

archivo
Si se proporciona el argumento archivo, ed simulará un comando e en el archivo nombrado por la ruta, archivo, antes de aceptar comandos desde la entrada estándar.

ENTRADA ESTÁNDAR

La entrada estándar será un archivo de texto que consta de comandos, como se describe en la sección DESCRIPCIÓN EXTENDIDA.

ARCHIVOS DE ENTRADA

Los archivos de entrada serán archivos de texto.

VARIABLES DE ENTORNO

Las siguientes variables de entorno afectarán la ejecución de ed:

HOME
Determina la ruta del directorio personal del usuario.
LANG
Proporciona un valor predeterminado para las variables de internacionalización que no están establecidas o están vacías. (Consulte el volumen de Definiciones Base de POSIX.1‐2017, Sección 8.2, Variables de internacionalización para conocer la precedencia de las variables de internacionalización utilizadas para determinar los valores de las categorías de localización).
LC_ALL
Si se establece en un valor de cadena no vacío, anula los valores de todas las demás variables de internacionalización.
LC_COLLATE

Determina la localización para el comportamiento de rangos, clases de equivalencia y elementos de ordenación multicarácter dentro de expresiones regulares.
LC_CTYPE
Determina la localización para la interpretación de secuencias de bytes de datos de texto como caracteres (por ejemplo, caracteres de un solo byte en oposición a caracteres multibyte en argumentos y archivos de entrada) y el comportamiento de las clases de caracteres dentro de expresiones regulares.
LC_MESSAGES

Determina la localización que debe utilizarse para afectar el formato y el contenido de los mensajes de diagnóstico escritos en la salida estándar de errores y los mensajes informativos escritos en la salida estándar.
NLSPATH
Determina la ubicación de los catálogos de mensajes para el procesamiento de LC_MESSAGES.

EVENTOS ASÍNCRONOS

La utilidad ed tomará la acción estándar para todas las señales (consulte la sección EVENTOS ASÍNCRONOS en Sección 1.4, Valores Predeterminados de Descripción de Utilidades) con las siguientes excepciones:

SIGINT
La utilidad ed interrumpirá su actividad actual, escribirá la cadena "?\n" en la salida estándar y volverá al modo de comando (consulte la sección DESCRIPCIÓN EXTENDIDA).
SIGHUP
Si el búfer no está vacío y ha cambiado desde la última escritura, la utilidad ed intentará escribir una copia del búfer en un archivo. Primero, se utilizará el archivo llamado ed.hup en el directorio actual; si eso falla, se utilizará el archivo llamado ed.hup en el directorio especificado por la variable de entorno HOME. En cualquier caso, la utilidad ed saldrá sin escribir el archivo en la ruta recordada actualmente y sin volver al modo de comando.
SIGQUIT
La utilidad ed ignorará este evento.

SALIDA ESTÁNDAR

Varios comandos de edición y la característica de aviso (consulte -p) escriben en la salida estándar, como se describe en la sección DESCRIPCIÓN EXTENDIDA.

SALIDA DE ERROR ESTÁNDAR

La salida de error estándar se utilizará únicamente para mensajes de diagnóstico.

ARCHIVOS DE SALIDA

Los archivos de salida serán archivos de texto cuyos formatos dependen de los comandos de edición dados.

DESCRIPCIÓN EXTENDIDA

La utilidad ed operará sobre una copia del archivo que está editando; los cambios realizados en la copia no tendrán efecto en el archivo hasta que se emita un comando w (write/escribir). La copia del texto se llama búfer.

Los comandos para ed tienen una estructura simple y regular: una, dos o ninguna dirección seguida de un comando de un solo carácter, posiblemente seguido de parámetros para ese comando. Estas direcciones especifican una o más líneas en el búfer. Cada comando que requiere direcciones tiene direcciones predeterminadas, de modo que las direcciones a menudo se pueden omitir. Si se especifica la opción -p, la cadena de aviso se escribirá en la salida estándar antes de leer cada comando.

En general, solo un comando puede aparecer en una línea. Ciertos comandos permiten la entrada de texto. Este texto se coloca en el lugar apropiado en el búfer. Mientras ed está aceptando texto, se dice que está en modo de entrada. En este modo, no se reconocerán comandos; toda la entrada simplemente se recopila. El modo de entrada se termina al introducir una línea que consta de dos caracteres: un <punto> ('.') seguido de un <salto de línea>. Esta línea no se considera parte del texto de entrada.

Expresiones Regulares en ed

La utilidad ed admitirá expresiones regulares básicas, como se describe en el volumen de Definiciones Base de POSIX.1‐2017, Sección 9.3, Expresiones Regulares Básicas. Dado que las expresiones regulares en ed siempre se comparan con líneas individuales (excluyendo los caracteres de <salto de línea> de terminación), nunca con una sección de texto más grande, no hay forma de que una expresión regular coincida con un <salto de línea>.

Una RE nula será equivalente a la última RE encontrada.

Las expresiones regulares se utilizan en direcciones para especificar líneas, y en algunos comandos (por ejemplo, el comando s de sustitución) para especificar porciones de una línea que se sustituirán.

FUNDAMENTO   
RACIONAL

La descripción inicial de esta utilidad se adaptó de la SVID.
    Contiene algunas características que no se encuentran en Version 7 o en sistemas derivados de BSD.
    Algunas de las diferencias entre las utilidades ed de POSIX y BSD
    incluyen, pero no se limitan 
a:


  
 
*
  
La opción - de BSD no suprime el prompt '!' después de un
      comando
 !.
  
 
*
  
BSD no soporta los significados especiales de los caracteres '%' y '!'
      dentro de un comando
 !.
  
 
*
  
BSD no soporta las direcciones ';' y ','
.
  
 
*
  
BSD permite los pares de comando/sufijo pp, ll, etc., que
      no están especificados en este volumen de POSIX.
1‐2017.
  
 
*
  
BSD no soporta el carácter '!' como parte de los comandos e,
      r o w
.
  
 
*
  
Un comando g fallido en BSD establece el número de línea en la última línea
      buscada si no hay 
coincidencias.
  
 
*
  
BSD no establece por defecto la lista de comandos en el comando
 p.
  
 
*
  
BSD no soporta los comandos G, h, H, n o
      V
.
  
 
*
  
En BSD, si no hay texto insertado, el comando de inserción cambia la
      línea actual a la línea referenciada -1; es decir, la línea anterior a la
      línea 
especificada.
  
 
*
  
En BSD, el comando de unión con una sola dirección cambia la
      línea actual a esa 
dirección.
  
 
*
  
BSD no soporta el comando P; además, en BSD es
      sinónimo del comando
 p.
  
 
*
  
BSD no soporta el deshacer de los comandos j, m,
      r, s o t
.
  
 
*
  
El comando ed de Version 7 W, y los comandos ed de BSD
      W, wq y z no están presentes en este v
olumen de
    
  POSIX.1‐2017.

La opción -s se añadió para permitir la funcionalidad de la
    opción - eliminada de una manera compatible con las
    Directrices de Sintaxis de 
Utilidades.

En las primeras propuestas había un límite, {ED_FILE_MAX}, que
    describía las limitaciones históricas de algunas utilidades ed en su
    manejo de archivos grandes; algunas de estas han tenido problemas con archivos mayores
    de 100000 bytes. Fue esta limitación la que impulsó gran parte del deseo
    de incluir un comando split en este volumen de POSIX.1‐2017.
    Dado que este límite fue eliminado, este volumen de POSIX.1‐2017 requiere
    que las implementaciones documenten los límites de tamaño de archivo impuestos por ed en
    el documento de conformidad. El límite {ED_LINE_MAX} también fue eliminado;
    por lo tanto, se utiliza el límite global {LINE_MAX} para las líneas de entrada y 
salida.

La forma en que el comando l escribe caracteres no imprimibles
    fue cambiada para evitar el método histórico de sobrescritura con retroceso.
    En terminales de pantalla de video, la sobrescritura es ambigua porque la mayoría de
    los terminales simplemente reemplazan los caracteres sobrescritos, haciendo que el formato l
    no sea útil para su propósito previsto de entender sin ambigüedad el
    contenido de la línea. Los <backslash>-escapes históricos también eran
    ambiguos. (La cadena "a\0011" podría representar una línea
    que contiene esos seis caracteres o una línea que contiene los tres caracteres
    'a', un byte con un valor binario de 1, y un 1.) En el formato
    requerido aquí, un <backslash> que aparece en la línea se escribe como
    "\\" para que la salida sea verdaderamente inequívoca. El método de
    marcar los finales de línea fue adoptado del editor ex y es
    requerido para cualquier línea que termine en caracteres <space>; el '$' se
    coloca en todas las líneas para que un '$' real al final de una línea no pueda ser
    malinterpretado
.

Versiones anteriores de este estándar permitían implementaciones con
    bytes de más de ocho bits, pero esto ha sido modificado en esta 
versión.

La descripción de cómo se escribe un NUL fue eliminada. El carácter NUL
    no puede estar en archivos de texto, y este volumen de POSIX.1‐2017
    no debería dictar el comportamiento en el caso de entrada errónea o 
indefinida.

A diferencia de algunas de las otras utilidades de edición, los nombres de archivo aceptados
    por los comandos E, e, R y r no son
  
patrones.

Las primeras propuestas afirmaban que la opción -p funcionaba solo cuando
    la entrada estándar estaba asociada con un dispositivo terminal. Esto ha sido cambiado
    para conformarse con las implementaciones históricas, permitiendo así que las aplicaciones se
    interpongan entre un usuario y la utilidad
 ed.

La forma del comando de sustitución que utiliza el sufijo n
    fue limitada en alguna documentación histórica (donde esto se describía
    incorrectamente como ``retroreferencia''). Este límite ha sido omitido porque
    no hay razón por la cual un editor que procesa líneas de longitud {LINE_MAX}
    deba tener esta restricción. El comando s/x/X/2047 debería poder
    sustituir la 2047ª ocurrencia de 'x' en una 
línea.

El uso de comandos de impresión con sufijos de impresión (como
    pn, lp, etc.) fue hecho no especificado porque los sistemas basados en BSD
    permiten esto, mientras que System V 
no.

Algunos sistemas basados en BSD salen inmediatamente al recibir el
    fin de archivo si todas las líneas del archivo han sido eliminadas. Dado que
    este volumen de POSIX.1‐2017 se refiere al comando q en este
    caso, tal comportamiento no está 
permitido.

Algunas implementaciones históricas devolvían el estado de salida cero incluso si
    habían ocurrido errores de comando; esto no está permitido por este volumen de
    POSIX.
1‐2017.

Algunas implementaciones históricas contenían un error que permitía
    que un solo <period> se introdujera en modo de entrada como <backslash>
    <period> <newline>. Esto no está permitido por ed porque
    no hay descripción de escapar ninguno de los caracteres en modo de entrada;
    los caracteres <backslash> se introducen en el buffer exactamente como se escriben.
    El método típico de introducir un solo <period> ha sido precederlo
    con otro carácter y luego usar el comando de sustitución para eliminar ese
    
carácter.

Es difícil bajo algunos modos de algunas versiones de los controladores de terminal de sistemas operativos históricos
    distinguir entre una condición de fin de archivo y la desconexión del terminal. POSIX.1‐2008 no requiere
    que las implementaciones distingan entre las dos situaciones, lo que permite
    las implementaciones históricas de la utilidad ed en plataformas históricas
    se ajusten. Se anima a las implementaciones a distinguir entre las dos,
    si es posible, y tomar la acción apropiada ante la desconexión del 
terminal.

Históricamente, ed aceptaba una dirección cero para los comandos a
    y r para insertar texto al inicio del buffer de edición.
    Cuando el buffer estaba vacío, el comando .= devolvía cero.
    POSIX.1‐2008 requiere la conformidad con la práctica 
histórica.

Para consistencia con los comandos a y r y una mejor
    funcionalidad para el usuario, los comandos i y c también deben aceptar una
    dirección de 0, en cuyo caso 0i se trata como 1i e igualmente
    para el comando
 c.

Se pueden proporcionar cualquier número de direcciones a los comandos que toman
    direcciones; por ejemplo, "1,2,3,4,5p" imprime las líneas 4 y 5,
    porque dos es el número máximo válido de direcciones aceptadas por el
    comando print. Esto, en combinación con el delimitador <semicolon>,
    permite a los usuarios crear comandos basados en patrones ordenados en el
    archivo. Por ejemplo, el comando "3;/foo/;+2p" mostrará
    la primera línea después de la línea 3 que contiene el patrón foo, más las
    siguientes dos líneas. Note que la dirección "3;" aún debe ser
    evaluada antes de ser descartada, porque el origen de búsqueda para el
    comando "/foo/" depende de 
esto.

Históricamente, ed desalentaba las cadenas de direcciones, como se discutió
