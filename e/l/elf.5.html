DESCRIPCIÓ

N

El archivo de cabecera <elf.h> define el formato de los archivos binarios ejecutables ELF. Entre estos archivos se encuentran los archivos ejecutables normales, los archivos de objeto reubicables, los archivos de volcado de memoria (core) y los objetos

compartidos.

Un archivo ejecutable que utiliza el formato de archivo ELF consta de una cabecera ELF, seguida de una tabla de cabeceras de programa o una tabla de cabeceras de sección, o ambas. La cabecera ELF siempre se encuentra en el desplazamiento cero del archivo. El desplazamiento de la tabla de cabeceras de programa y de la tabla de cabeceras de sección en el archivo se define en la cabecera ELF. Las dos tabras describen el resto de las particularidades del

archivo.

Este archivo de cabecera describe las cabeceras mencionadas anteriormente como estructuras C e incluye también estructuras para secciones dinámicas, secciones de reubicación y tablas de

símbolos.

básicos

Todas las estructuras de datos que define el formato de archivo siguen las directrices de tamaño y alineación "naturales" de

la clase correspondiente. Si es necesario, las estructuras de datos contienen relleno explícito para garantizar una alineación
de 4 bytes para objetos de 4 bytes, para forzar que los tamaños de las estructuras sean múltiplos de 4, y así sucesivamente.

Cabecera de programa

(Phdr)

La tabla de cabeceras de programa de un archivo ejecutable u objeto compartido es un arreglo de estructuras, cada una describiendo un segmento u otra información que el sistema necesita para preparar el programa para su ejecución. Un segmento de un archivo de objeto contiene una o más secciones. Las cabeceras de programa son significativas solo para archivos ejecutables y objetos compartidos. Un archivo especifica su propio tamaño de cabecera de programa con los miembros e_phentsize y e_phnum de la cabecera ELF. La cabecera de programa ELF se describe con el tipo Elf32_Phdr o Elf64_Phdr dependiendo de la

arquitectura: 


typedef struct {
    uint32_t   p_type;
    Elf32_Off  p_offset;
    Elf32_Addr p_vaddr;
    Elf32_Addr p_paddr;
    uint32_t   p_filesz;
    uint32_t   p_memsz;
    uint32_t   p_flags;
    uint32_t   p_align;
}
Elf32_Phdr; 


typedef struct {
    uint32_t   p_type;
    uint32_t   p_flags;

Cabecera de sección

(Shdr)

La tabla de cabeceras de secciones de un archivo permite localizar todas las secciones del archivo. La tabla de cabeceras de secciones es una matriz de Elf32_Shdr o Elf64_Shdr estructuras. El miembro e_shoff de la cabecera ELF proporciona el desplazamiento en bytes desde el inicio del archivo hasta la tabla de cabeceras de secciones. e_shnum contiene el número de entradas que contiene la tabla de cabeceras de secciones. e_shentsize contiene el tamaño en bytes de cada

entrada.

Un índice de tabla de cabeceras de secciones es un subíndice en esta matriz. Algunos índices de tabla de cabeceras de secciones están reservados: la entrada inicial y los índices entre SHN_LORESERVE y SHN_HIRESERVE. La entrada inicial se utiliza en extensiones ELF para e_phnum, e_shnum y e_shstrndx; en otros casos, cada campo de la entrada inicial se establece en cero. Un archivo objeto no tiene secciones para estos índices

especiales:

Notas

(Nhdr)

Las notas ELF permiten agregar información arbitraria para que el sistema las use. Son utilizadas en gran medida por los archivos core (e_type de ET_CORE), pero muchos proyectos definen su propio conjunto de extensiones. Por ejemplo, la cadena de herramientas GNU usa notas ELF para pasar información del enlazador a la biblioteca

C.

Las secciones de notas contienen una serie de notas (véanse las definiciones de struct más abajo). Cada nota es seguida por el campo nombre (cuya longitud está definida en n_namesz) y luego por el campo descriptor (cuya longitud está definida en n_descsz) y cuya dirección de inicio tiene una alineación de 4 bytes. Ninguno de los campos está definido en la estructura de la nota debido a sus longitudes

arbitrarias.

Un ejemplo para analizar dos notas consecutivas debería aclarar su diseño en

memoria: 


void *memory, *name, *desc;
Elf64_Nhdr *note, *next_note;
/* El búfer apunta al inicio de la sección/segmento.  */
note = memory;
/* Si el nombre está definido, sigue a la nota.  */
name = note->n_namesz == 0 ? NULL : memory + sizeof(*note);
/* Si el descriptor está definido, sigue al nombre
   (con alineación).  */
desc = note->n_descsz == 0 ? NULL :
       memory + sizeof(*note) + ALIGN_UP(note->n_namesz, 4);
/* La siguiente nota sigue a ambos (con alineación).  */
next_note = memory + sizeof(*note) +
                     ALIGN_UP(note->n_namesz, 4) +
                     ALIGN_UP(note->n_descsz, 4)
;

Tenga en cuenta que la interpretación de n_type depende del espacio de nombres definido por el campo n_namesz. Si el campo n_namesz no está establecido (por ejemplo, es 0), entonces hay dos conjuntos de notas: uno para archivos core y otro para todos los demás tipos de ELF. Si el espacio de nombres es desconocido, entonces las herramientas generalmente recurrirán a estos conjuntos de notas

también.
