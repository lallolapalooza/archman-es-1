DESCRIPCIÓ

N

La función getgrent() devolverá un puntero a una estructura que contiene los campos desglosados de una entrada en la base de datos de grupos. Si la base de datos de grupos no está ya abierta, getgrent() la abrirá y devolverá un puntero a una estructura group que contiene la primera entrada de la base de datos. A partir de ahí, devolverá un puntero a una estructura group que contiene la siguiente estructura group en la base de datos de grupos, de modo que se pueden realizar llamadas sucesivas para buscar en toda la base de

datos.

Una implementación que proporcione controles de seguridad extendidos puede imponer restricciones adicionales definidas por la implementación para acceder a la base de datos de grupos. En particular, el sistema puede negar la existencia de algunas o todas las entradas de la base de datos de grupos asociadas con grupos distintos de aquellos asociados con el solicitante, y puede omitir a los usuarios distintos del solicitante de la lista de miembros de los grupos en las entradas de la base de datos que se

devuelven.

La función setgrent() rebobinará la base de datos de grupos de modo que la siguiente llamada a getgrent() devuelva la primera entrada, permitiendo búsquedas

repetidas.

La función endgrent() cerrará la base de datos de

grupos.

Las funciones setgrent() y endgrent() no cambiarán la configuración de errno si tienen

éxito.

En caso de error, las funciones setgrent() y endgrent() establecerán errno para indicar el

error.

Dado que las funciones setgrent() y endgrent() no devuelven ningún valor, una aplicación que desee comprobar situaciones de error debe establecer errno a 0, luego llamar a la función y luego comprobar errno

.

Estas funciones no

necesitan ser segura
s para subprocesos.

VALOR DE

RETORNO

Al completarse con éxito, getgrent() devolverá un puntero a una estructura group. Al alcanzar el fin de archivo, getgrent() devolverá un puntero nulo y no cambiará la configuración de errno. En caso de error, getgrent() devolverá un puntero nulo y errno se establecerá para indicar el

error.

La aplicación no debe modificar la estructura a la que apunta el valor de retorno, ni ninguna de las áreas de almacenamiento a las que apuntan punteros dentro de la estructura. El puntero devuelto, y los punteros dentro de la estructura, podrían invalidarse, o la estructura o las áreas de almacenamiento podrían ser sobrescritas por una llamada posterior a getgrgid(), getgrnam() o getgrent(). El puntero devuelto, y los punteros dentro de la estructur

a, también podrían invalidarse si el s
ubproceso que llama es terminado.

APLICACIONES

Estas funciones se proporcionan debido a su uso histórico. Las aplicaciones deben evitar depender de campos en la base de datos de grupos, ya sea que la base de datos sea un solo archivo o dónde reside la base de datos en el espacio de nombres del sistema de archivos. Las aplicaciones deben usar getgrnam() y getgrgid() siempre que sea posible, ya
