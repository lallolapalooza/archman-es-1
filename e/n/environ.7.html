DESCRIPCIÓ

N

La variable environ apunta a un array de punteros a cadenas llamado el "entorno". El último puntero en este array tiene el valor NULL. Este array de cadenas se pone a disposición del proceso por la llamada execve(2) cuando se inicia un nuevo programa. Cuando se crea un proceso hijo a través de fork(2), este hereda una copia del entorno de su

padre.

Por convención, las cadenas en environ tienen la forma "nombre=valor". El nombre distingue entre mayúsculas y minúsculas y no puede contener el carácter "=". El valor puede ser cualquier cosa que pueda representarse como una cadena. El nombre y el valor no pueden contener un byte nulo incrustado ('\0'), ya que se asume que esto termina la

cadena.

Las variables de entorno pueden colocarse en el entorno del shell mediante el comando export en sh(1), o mediante el comando setenv si se utiliza csh(1

).

El entorno inicial del shell se rellena de varias maneras, como definiciones de /etc/environment que son procesadas por pam_env(8) para todos los usuarios en el momento del inicio de sesión (en sistemas que emplean pam(8)). Además, varios scripts de inicialización del shell, como el script de sistema /etc/profile y los scripts de inicialización por usuario pueden incluir comandos que añaden variables al entorno del shell; consulte la página manual de su shell preferido para más

detalles.

Los shells estilo Bourne admiten la

sintaxis 


NOMBRE=valor
comando

para crear una definición de variable de entorno solo en el ámbito de el proceso que ejecuta comando. Múltiples definiciones de variables, separadas por espacios en blanco, pueden preceder a comando

.

Los argumentos también pueden colocarse en el entorno en el punto de una exec(3). Un programa C puede manipular su entorno utilizando las funciones getenv(3), putenv(3), setenv(3) y unsetenv

(3).

A continuación se muestra una lista de variables de entorno típicas que se encuentran en un sistema. Esta lista está incompleta e incluye solo variables comunes que ven los usuarios promedio en su rutina diaria. Las variables de entorno específicas de un programa o función de biblioteca particular se documentan en la sección ENVIRONMENT de la página manual correspondiente

.

La secuencia de prefijos de directorios que sh(1) y muchos otros programas emplean al buscar un archivo ejecutable que se especifica como un nombre de archivo simple (es decir, una ruta de acceso que no contiene barras). Los prefijos están separados por dos puntos (:). La lista de prefijos se busca de principio a fin, comprobando la ruta de acceso formada por concaten

Sin embargo, el uso de esta característica está obsoleto, y POSIX indica que una aplicación conforme debe usar una ruta de acceso explícita (por ejemplo, .) para especificar el directorio de trabajo
actual.

Tenga en cuenta que el comportamiento de muchos programas y rutinas de biblioteca está influenciado por la presencia o el valor de ciertas variables de entorno. Ejemplos incluyen los

siguientes:
•
Las variables LANG, LANGUAGE, NLSPATH, LOCPATH, LC_ALL, LC_MESSAGES, etc., influyen en el manejo de la configuración regional; consulte catopen(3), gettext(3) y locale(
7).
•
TMPDIR influye en el prefijo de ruta de los nombres creados por tempnam(3) y otras rutinas, y en el directorio temporal usado por sort(1) y otros
programas.
•
LD_LIBRARY_PATH, LD_PRELOAD y otras variables LD_* influyen en el comportamiento del cargador/enlazador dinámico. Consulte también ld.so(
8).
•
POSIXLY_CORRECT hace que ciertos programas y rutinas de biblioteca sigan las prescripciones de
POSIX.
•
El comportamiento de malloc(3) está influenciado por variables MAL
LOC_*.
•
La variable HOSTALIASES da el nombre de un archivo que contiene alias a usar con gethostbyna
me(3).
•
TZ y TZDIR proporcionan información de zona horaria usada por tzset(3) y a través de ella por funciones como ctime(3), localtime(3), mktime(3), strftime(3). Consulte también tzselect
(8).
•
TERMCAP proporciona información sobre cómo dirigirse a una terminal dada (o da el nombre de un archivo que contiene dicha información)
.
•
COLUMNS y LINES informan a las aplicaciones sobre el tamaño de la ventana, posiblemente anulando el tamaño
real.
•
PRINTER o LPDEST pueden especificar la impresora deseada a usar. Consulte lpr
(
1)
.

NOTA

S

Históricamente y por estándar, environ debe declararse en el programa del usuario. Sin embargo, como comodidad para el programador (no estándar), environ se declara en el archivo de cabecera <unistd.h> si se define la macro de prueba de características _GNU_SOURCE (ver feature_test_macros(7))

.

Las prctl(2) operaciones PR_SET_MM_ENV_START y PR_SET_MM_ENV_END se pueden utilizar para controlar la ubicación del entorno del

proceso.

Las variables HOME, LOGNAME, SHELL y USER se establecen cuando se cambia el usuario a través de una interfaz de gestión de sesiones, típicamente por un programa como login(1) a partir de una base de datos de usuarios (como passwd(5)). (Cambiar al usuario root usando su(1) puede resultar en un entorno mixto donde LOGNAME y USER se conservan del usuario anterior; ver la página de manual de su(1)

.
)

ERRORE

S

Claramente, existe un riesgo de seguridad aquí. Muchos comandos del sistema han sido engañados para hacer travesuras por un usuario que especificó valores inusuales para IFS o LD_LIBRARY_PATH

.

También existe el riesgo de contaminación del espacio de nombres. Programas como make y autoconf permiten la anulación de los nombres de utilidades predeterminados desde el entorno con variables de nombre similar en mayúsculas. Así, uno usa CC para seleccionar el compilador C deseado (y de manera similar MAKE, AR, AS, FC, LD, LEX, RM, YACC, etc.). Sin embargo, en algunos usos tradicionales, una variable de entorno así proporciona opciones para el programa en lugar de un nombre de ruta. Así, uno tiene MORE y LESS. Tal uso se considera erróneo y d

ebe evitarse e
n programas nuevos.
