Descripción

detallada

Interfaz abstracta para proporcionar soporte para archivos definidos por el

usuario.

Advertenci

a
Esto es avanzado y complejo. No lo necesitas a menos que sepas realmente lo que estás haciendo. La mayoría de las aplicaciones no necesitarán
esto.

Históricamente, PhysicsFS proporcionaba un medio para montar varios formatos de archivo y directorios físicos en el sistema de archivos nativo. Sin embargo, las aplicaciones se han visto limitadas a los formatos de archivo proporcionados por la biblioteca. Esta interfaz permite a una aplicación proporcionar sus propios tipos de

archivo.

Conceptualmente, un PHYSFS_Archiver proporciona entradas de directorio, mientras que PHYSFS_Io proporciona flujos de datos para esas entradas de directorio. El uso más obvio de PHYSFS_Archiver es proporcionar soporte para un tipo de archivo que no es proporcionado directamente por PhysicsFS: quizás algún formato propietario que solo tu aplicación necesite

entender.

Internamente, todo el soporte de archivos integrado usa esta interfaz, por lo que los mejores ejemplos para construir un PHYSFS_Archiver es el código fuente de PhysicsFS

mismo.

Un archivador se añade al sistema con PHYSFS_registerArchiver(), y luego estará disponible para uso automáticamente con PHYSFS_mount(); si un archivo dado puede ser manejado con tu archivador, se le dará el control como

corresponda.

Estos métodos manejan manejadores de directorios. Tienes una instancia de tu archivador, y este genera un manejador único y opaco para cada archivo abierto en su openArchive() método. Dado que la vida útil de un Archiver (no un archivo) es generalmente toda la vida útil del proceso, y se asume que es un singleton, no proporcionamos datos de instancia para el archivador mismo; la aplicación puede simplemente usar algunas variables estáticas si es

necesario.

Los enlaces simbólicos siempre deben ser seguidos (excepto en stat()); PhysicsFS usará el stat() método para verificar enlaces simbólicos y tomar una decisión sobre si continuar llamando a otros métodos basándose en

eso.

Los archivadores, cuando sea necesario, deben establecer el estado de error de PhysicsFS con PHYSFS_setErrorCode() antes de retornar. PhysicsFS pasará estos errores de vuelta a la aplicación sin alterar en la mayoría de los

casos.

Seguridad de hilos: Las implementaciones de PHYSFS_Archiver no están garantizadas para ser seguras en hilos en sí mismas. PhysicsFS proporciona seguridad de hilos cuando llama a un archivador dado dentro de la biblioteca, pero no promete que usar el mismo PHYSFS_File desde dos hilos a la vez sea seguro; como tal, tu PHYSFS_Archiver puede asumir que el bloqueo es manejado por ti siempre que el PHYSFS_Io que retornas de PHYSFS_open* no cambie ninguno de tu estado de Archiver, ya que el PHYSFS_Io no será tan agresivamente

protegido.

Destruye un archivo previamente abierto. Cierra este archivo y libera cualquier memoria asociada, incluyendo el original PHYSFS_Io y (opaque) mismo, si aplica. La implementación puede asumir

PHYSFS_EnumerateCallbackResult(* PHYSFS_Archiver::enumerate) (void *opaque, const char *dirname, PHYSFS_EnumerateCallback cb, const char *origdir, void

*callbackdata)

Lista todos los archivos en (dirname). Cada archivo se pasa a (cb), donde se hace una copia si es apropiado, para que puedas disponer de él al retornar del callback. (dirname) está en notación independiente de plataforma. Si tienes un fallo, llama a PHYSFS_SetErrorCode() con cualquier código que parezca apropiado y retorna PHYSFS_ENUM_ERROR. Si el callback retorna PHYSFS_ENUM_ERROR, por favor llama a PHYSFS_SetErrorCode(PHYSFS_ERR_APP_CALLBACK) y luego retorna PHYSFS_ENUM_ERROR también. No llames al callback de nuevo en ninguna circunstancia. Si el callback retorna PHYSFS_ENUM_STOP, deja de enumerar y retorna PHYSFS_ENUM_STOP también. No llames al callback de nuevo en ninguna circunstancia. No establezcas un código de error en este caso. Los callbacks solo deben retornar un valor de PHYSFS_EnumerateCallbackResult. Cualquier otro resultado tiene comportamiento indefinido. Siempre que el callback haya retornado PHYSFS_ENUM_OK y no hayas experimentado ningún error propio, sigue enumerando hasta que termines y luego retorna PHYSFS_ENUM_OK sin establecer un código de

error.

void *(* PHYSFS_Archiver::openArchive) (PHYSFS_Io *io, const char *name, int forWrite, int

*claimed)

Abre un archivo proporcionado por (io). Aquí es donde se asignan recursos y se analizan datos al montar un archivo. (name) es un nombre de archivo asociado con (io), pero no necesariamente mapea a nada, mucho menos a un nombre de archivo real. Este nombre posiblemente sin sentido está en notación dependiente de plataforma. (forWrite) es no cero si esto va a ser usado para el directorio de escritura, y cero si esto va a ser usado para un elemento del ruta de búsqueda. (claimed) debe establecerse en 1 si este es definitivamente un archivo que su implementación de archiver puede manejar, incluso si falla. Usamos esto para decidir si debemos dejar de intentar otros archivers si usted falla al abrirlo. Por ejemplo: el archiver .zip establecerá esto en 1 para algo que tiene una firma de archivo .zip, incluso si falló porque el archivo también estaba truncado. No tiene sentido intentar otros archivers aquí, ¡ya intentamos manejarlo con la implementación apropiada!. Devuelve NULL en caso de fallo y establece (claimed) apropiadamente. Si ningún archiver abrió el archivo o estableció (claimed), PHYSFS_mount() reportará PHYSFS_ERR_UNSUPPORTED. De lo contrario, reportará el error del archiver que reclamó los datos a trav

és de (claimed). Devuelve no-NULL en éxito. El puntero devuelto
se pasará como el parámetro "opaque" para llamadas posteriores.
