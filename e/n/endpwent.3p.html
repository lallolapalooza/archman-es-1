ENDPWENT(3P) Manual del Programador POSIX ENDPWENT(3P)

PRÓLOGO

Esta página del manual forma parte del Manual del Programador POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página del manual de Linux correspondiente para detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

endpwent, getpwent, setpwent — funciones de la base de datos de usuarios

SINOPSIS

#include <pwd.h>
void endpwent(void);
struct passwd *getpwent(void);
void setpwent(void);

DESCRIPCIÓN

Estas funciones recuperan información sobre usuarios.

La getpwent() función devolverá un puntero a una estructura que contiene los campos desglosados de una entrada en la base de datos de usuarios. Cada entrada en la base de datos de usuarios contiene una passwd estructura. Si la base de datos de usuarios no está ya abierta, getpwent() la abrirá y devolverá un puntero a una passwd estructura que contiene la primera entrada en la base de datos. Después, devolverá un puntero a una passwd estructura que contiene la siguiente entrada en la base de datos de usuarios. Se pueden usar llamadas sucesivas para buscar en toda la base de datos de usuarios.

Si se encuentra un fin de archivo o un error durante la lectura, getpwent() devolverá un puntero nulo.

Una implementación que proporcione controles de seguridad extendidos puede imponer restricciones adicionales definidas por la implementación al acceder a la base de datos de usuarios. En particular, el sistema puede negar la existencia de algunas o todas las entradas de la base de datos de usuarios asociadas con usuarios distintos al llamador.

La setpwent() función rebobinará la base de datos de usuarios para que la siguiente getpwent() llamada devuelva la primera entrada, permitiendo búsquedas repetidas.

La endpwent() función cerrará la base de datos de usuarios.

Las funciones setpwent() y endpwent() no cambiarán la configuración de errno si tienen éxito.

En caso de error, setpwent() y endpwent() funciones establecerán errno para indicar el error.

Dado que las funciones setpwent() y endpwent() no devuelven ningún valor, una aplicación que desee comprobar situaciones de error debe establecer errno a 0, luego llamar a la función, luego comprobar errno.

Estas funciones no necesitan ser seguras para hilos.

VALOR DEVUELTO

En la finalización con éxito, getpwent() devolverá un puntero a una passwd estructura. En el fin de archivo, getpwent() devolverá un puntero nulo y no cambiará la configuración de errno. En caso de error, getpwent() devolverá un puntero nulo y errno se establecerá para indicar el error.

La aplicación no debe modificar la estructura a la que apunta el valor devuelto, ni ninguna de las áreas de almacenamiento a las que apuntan los punteros dentro de la estructura. El puntero devuelto, y los punteros dentro de la estructura, podrían invalidarse o la estructura o las áreas de almacenamiento podrían ser sobrescritas por una llamada posterior a getpwuid(), getpwnam(), o getpwent(). El puntero devuelto, y los punteros dentro de la estructura, también podrían invalidarse si el hilo que llama es terminado.

ERRORES

Estas funciones pueden fallar si:

EINTR
Se capturó una señal durante la operación.
EIO
Ha ocurrido un error de E/S.

Además, getpwent() y setpwent() pueden fallar si:

EMFILE
Todos los descriptores de archivo disponibles para el proceso están actualmente abiertos.
ENFILE
El número máximo permitido de archivos está actualmente abierto en el sistema.

EJEMPLOS

Buscando la Base de Datos de Usuarios

El siguiente ejemplo usa la getpwent() función para obtener entradas sucesivas en la base de datos de usuarios, devolviendo un puntero a una passwd estructura que contiene información sobre cada usuario. La llamada a endpwent() cierra la base de datos de usuarios y limpia.

#include <pwd.h>
#include <stdio.h>
void printname(uid_t uid)
{
    struct passwd *pwd;
    setpwent();
    while((pwd = getpwent()) != NULL) {
        if (pwd->pw_uid == uid) {
            printf("name=%s\n",pwd->pw_name);
            break;
        }
    }
    endpwent();
}

USO EN APLICACIONES

Estas funciones se proporcionan debido a su uso histórico. Las aplicaciones deben evitar depender de campos en la base de datos de contraseñas, ya sea que la base de datos sea un solo archivo, o dónde en el espacio de nombres del sistema de archivos resida la base de datos. Las aplicaciones deben usar getpwuid() siempre que sea posible porque evita estas dependencias.
