Documentación del Tipo de Enumeración

enum BrotliEncoderMode

Opciones para BROTLI_PARAM_MODE parámetro.

Enumerador

BROTLI_MODE_GENERIC
Modo de compresión predeterminado. En este modo, el compresor no sabe nada de antemano sobre las propiedades de la entrada.
BROTLI_MODE_TEXT
Modo de compresión para entradas de texto con formato UTF-8.
BROTLI_MODE_FONT
Modo de compresión utilizado en WOFF 2.0.

enum BrotliEncoderOperation

Operaciones que puede realizar el codificador de flujo.

Enumerador

BROTLI_OPERATION_PROCESS
Procesar entrada. El codificador puede retrasar la producción de salida hasta que haya procesado suficiente entrada.
BROTLI_OPERATION_FLUSH
Producir salida para toda la entrada procesada. El vaciado real se realiza cuando el flujo de entrada se ha agotado y hay suficiente espacio en el flujo de salida. Esto significa que el cliente debe repetir BROTLI_OPERATION_FLUSH la operación hasta que available_in se convierta en 0, y BrotliEncoderHasMoreOutput devuelva BROTLI_FALSE. Si la salida se adquiere mediante BrotliEncoderTakeOutput, la operación debe repetirse después de que el búfer de salida se haya vaciado.

Advertencia:

Hasta que el vaciado se complete, el cliente DEBE NO intercambiar, reducir o extender el flujo de entrada.

Cuando el vaciado esté completo, los datos de salida serán suficientes para que el decodificador reproduzca toda la entrada dada.

BROTLI_OPERATION_FINISH
Finalizar el flujo. La finalización real se realiza cuando el flujo de entrada se ha agotado y hay suficiente espacio en el flujo de salida. Esto significa que el cliente debe repetir BROTLI_OPERATION_FINISH la operación hasta que available_in se convierta en 0, y BrotliEncoderHasMoreOutput devuelva BROTLI_FALSE. Si la salida se adquiere mediante BrotliEncoderTakeOutput, la operación debe repetirse después de que el búfer de salida se haya vaciado.

Advertencia:

Hasta que la finalización se complete, el cliente DEBE NO intercambiar, reducir o extender el flujo de entrada.

La función auxiliar BrotliEncoderIsFinished comprueba si el flujo está finalizado y la salida se ha volcado por completo.

Es imposible añadir más datos de entrada a un flujo finalizado.

BROTLI_OPERATION_EMIT_METADATA
Emitir un bloque de metadatos al flujo. Los metadatos son opacos para Brotli: ni el codificador ni el decodificador procesan estos datos ni dependen de ellos. Puede utilizarse para pasar alguna información adicional del cliente del codificador al cliente del decodificador sin interferir con el flujo de datos principal.

Nota:

El codificador puede emitir internamente bloques de metadatos vacíos, para alinear el flujo codificado a un límite de byte.

Advertencia:

Hasta que la emisión de metadatos se complete, el cliente DEBE NO intercambiar, reducir o extender el flujo de entrada.

Todo el contenido del búfer de entrada se considera el contenido del bloque de metadatos. NO NO añada metadatos al flujo de entrada, antes de que se haya agotado con otras operaciones.

El flujo se vacía de forma suave antes de que se emita el bloque de metadatos. El bloque de metadatos DEBE tener una longitud no superior a 16MiB.

enum BrotliEncoderParameter

Opciones a utilizar con BrotliEncoderSetParameter.

Enumerador

BROTLI_PARAM_MODE
Ajustar el codificador para una entrada específica. BrotliEncoderMode enumera todos los valores disponibles.
BROTLI_PARAM_QUALITY
La palanca principal de velocidad-densidad de compresión. Cuanto mayor sea la calidad, más lenta será la compresión. El rango va desde BROTLI_MIN_QUALITY hasta BROTLI_MAX_QUALITY.
BROTLI_PARAM_LGWIN
Tamaño de ventana LZ77 deslizante recomendado. El codificador puede reducir este valor, p. ej. si la entrada es mucho menor que el tamaño de la ventana.

El tamaño de la ventana es (1 << value) - 16.

El rango va desde BROTLI_MIN_WINDOW_BITS hasta BROTLI_MAX_WINDOW_BITS.

BROTLI_PARAM_LGBLOCK
Tamaño de bloque de entrada recomendado. El codificador puede reducir este valor, p. ej. si la entrada es mucho menor que el tamaño del bloque de entrada.

El rango va desde BROTLI_MIN_INPUT_BLOCK_BITS hasta BROTLI_MAX_INPUT_BLOCK_BITS.

Nota:

Un tamaño de bloque de entrada mayor permite una mejor compresión, pero consume más memoria.
La fórmula aproximada de la memoria utilizada para el almacenamiento temporal de la entrada es 3 << lgBlock.
BROTLI_PARAM_DISABLE_LITERAL_CONTEXT_MODELING
Bandera que afecta al uso de la característica de formato 'modelado de contexto de literales'. Esta bandera es una compensación entre 'velocidad de decodificación' y 'ratio de compresión'.
BROTLI_PARAM_SIZE_HINT
Tamaño total de entrada estimado para todas las llamadas a BrotliEncoderCompressStream . El valor predeterminado es 0, lo que significa que el tamaño total de la entrada es desconocido.
BROTLI_PARAM_LARGE_WINDOW
Bandera que determina si se utiliza 'Brotli de ventana grande'.
BROTLI_PARAM_NPOSTFIX
Número recomendado de bits de sufijo (NPOSTFIX). El codificador puede cambiar este valor.

El rango va desde 0 hasta BROTLI_MAX_NPOSTFIX.

BROTLI_PARAM_NDIRECT
Número recomendado de códigos de distancia directos (NDIRECT). El codificador puede cambiar este valor.

El rango va desde 0 hasta (15 << NPOSTFIX) en pasos de (1 << NPOSTFIX).

BROTLI_PARAM_STREAM_OFFSET
Número de bytes del flujo de entrada ya procesados por una instancia diferente.

Nota:

Es importante configurar todas las instancias del codificador con los mismos parámetros (excepto este) para permitir que todas las partes codificadas obedezcan las mismas restricciones impuestas por la cabecera.

Si el desplazamiento no es 0, se omite la cabecera del flujo. En cualquier caso, el inicio de la salida está alineado a bytes, por lo que para una correcta unión de flujos, el flujo 'predecesor' debe ser vaciado.

El rango no está limitado artificialmente, pero todos los valores mayores o iguales al tamaño máximo de ventana tienen el mismo efecto. No se permiten valores mayores que 2**30.

BROTLI_BOOL BrotliEncoderAttachPreparedDictionary (BrotliEncoderState * state, const BrotliEncoderPreparedDictionary * dictionary)

Adjunta un diccionario preparado de cualquier tipo al codificador. Puede usarse varias veces para adjuntar múltiples diccionarios. El tipo de diccionario fue determinado por BrotliEncoderPrepareDictionary. Se pueden adjuntar múltiples diccionarios de prefijo en bruto y/o un máximo de 1 diccionario serializado con palabras personalizadas.

Devuelve:

BROTLI_FALSE en caso de error

BROTLI_TRUE en caso contrario

BROTLI_BOOL BrotliEncoderCompress (int quality, int lgwin, BrotliEncoderMode mode, size_t input_size, const uint8_t input_buffer[input_size], size_t * encoded_size, uint8_t encoded_buffer[*encoded_size])

Realiza una compresión de memoria a memoria en un solo paso. Comprime los datos en input_buffer en encoded_buffer, y establece *encoded_size en la longitud comprimida.

Nota:

Si BrotliEncoderMaxCompressedSize(input_size) devuelve un valor distinto de cero, se garantiza que la salida no será mayor que ese valor.

Si lgwin es mayor que BROTLI_MAX_WINDOW_BITS entonces el flujo resultante podría ser incompatible con RFC 7932; para decodificar tales flujos, el decodificador debe configurarse con BROTLI_DECODER_PARAM_LARGE_WINDOW = 1

Parámetros:

quality valor del parámetro quality, p. ej. BROTLI_DEFAULT_QUALITY
lgwin valor del parámetro lgwin, p. ej. BROTLI_DEFAULT_WINDOW
mode valor del parámetro mode, p. ej. BROTLI_DEFAULT_MODE
input_size tamaño de input_buffer
input_buffer búfer de datos de entrada con al menos input_size bytes direccionables
encoded_size in: tamaño de encoded_buffer;
out: longitud de los datos comprimidos escritos en encoded_buffer, o 0 si la compresión falla
encoded_buffer búfer de destino de los datos comprimidos

Devuelve:

BROTLI_FALSE en caso de error de compresión

BROTLI_FALSE si el búfer de salida es demasiado pequeño

BROTLI_TRUE en caso contrario

BROTLI_BOOL BrotliEncoderCompressStream (BrotliEncoderState * state, BrotliEncoderOperation op, size_t * available_in, const uint8_t ** next_in, size_t * available_out, uint8_t ** next_out, size_t * total_out)

Comprime el flujo de entrada en el flujo de salida. Los valores *available_in y *available_out deben especificar el número de bytes direccionables en *next_in y *next_out respectivamente. Cuando *available_out es 0, next_out puede ser NULL.

Después de cada llamada, *available_in se decrementará en la cantidad de bytes de entrada consumidos, y el puntero *next_in se incrementará en esa cantidad. De manera similar, *available_out se decrementará en la cantidad de bytes de salida escritos, y el puntero *next_out se incrementará en esa cantidad.

total_out, si no es un puntero nulo, se establecerá en el número de bytes comprimidos desde la última inicialización de estado.

El flujo de trabajo interno consiste en 3 tareas:

1.
(opcionalmente) copiar los datos de entrada al búfer interno
2.
comprimir realmente los datos y (opcionalmente) almacenarlos en el búfer interno
3.
(opcionalmente) copiar los bytes comprimidos del búfer interno al flujo de salida

Cuando las 3 tareas ya no pueden avanzar más, o se produce un error, este método devuelve el flujo de control al llamador.

op se usa para realizar un flush, finalizar el flujo o inyectar un bloque de metadatos. Vea BrotliEncoderOperation para más información.

Hacer flush del flujo significa forzar la codificación de toda la entrada pasada al codificador y completar el bloque de salida actual, para que pueda ser completamente decodificado por el decodificador de flujo. Para realizar un flush, establezca op en BROTLI_OPERATION_FLUSH. En algunas circunstancias (p. ej. falta de capacidad del flujo de salida) esta operación requerirá varias llamadas a BrotliEncoderCompressStream. El método debe ser llamado de nuevo hasta que tanto el flujo de entrada se agote como el codificador no tenga más salida (vea BrotliEncoderHasMoreOutput) después de que el método sea llamado.

Finalizar el flujo significa la codificación de toda la entrada pasada al codificador y la adición de marcas 'finales' específicas, para que el decodificador de flujo pueda determinar que el flujo está completo. Para realizar la finalización, establezca op en BROTLI_OPERATION_FINISH. En algunas circunstancias (p. ej. falta de capacidad del flujo de salida) esta operación requerirá varias llamadas a BrotliEncoderCompressStream. El método debe ser llamado de nuevo hasta que tanto el flujo de entrada se agote como el codificador no tenga más salida (vea BrotliEncoderHasMoreOutput) después de que el método sea llamado.

Advertencia:

Al hacer flush y finalizar, op no debe cambiar hasta que la operación esté completa; el flujo de entrada tampoco debe ser intercambiado, reducido o extendido.

Parámetros:

state instancia del codificador
op operación solicitada
available_in in: cantidad de entrada disponible;
out: cantidad de entrada no utilizada
next_in puntero al siguiente byte de entrada
available_out in: longitud del búfer de salida;
out: tamaño restante del búfer de salida
next_out cursor del búfer de salida comprimido; puede ser NULL si available_out es 0
total_out número de bytes producidos hasta ahora; puede ser NULL

Devuelve:

BROTLI_FALSE si hubo un error

BROTLI_TRUE en caso contrario

BrotliEncoderState* BrotliEncoderCreateInstance (brotli_alloc_func alloc_func, brotli_free_func free_func, void * opaque)

Crea una instancia de BrotliEncoderState y la inicializa. alloc_func y free_func DEBEN ser ambos cero o ambos no cero. const uint8_t* BrotliEncoderTakeOutput (BrotliEncoderState * state, size_t * size)

Adquiere un puntero al búfer de salida interno. Este método se usa para hacer que los enlaces de lenguaje sean más fáciles y eficientes:

1.
empujar datos a BrotliEncoderCompressStream, hasta que BrotliEncoderHasMoreOutput devuelva BROTLI_TRUE
2.
usar BrotliEncoderTakeOutput para inspeccionar los bytes y copiarlos a la entidad específica del lenguaje

También esto podría ser útil si hay un flujo de salida que es capaz de consumir todos los datos proporcionados (p. ej. cuando los datos se guardan en el sistema de archivos).

Atención:

Después de cada llamada a BrotliEncoderTakeOutput *size bytes de salida se consideran consumidos para todas las llamadas consecutivas a los métodos de la instancia; el puntero devuelto también queda invalidado.

Nota:

No se garantiza que la salida del codificador sea contigua. Esto significa que después de la llamada a BrotliEncoderTakeOutputsin restricción de tamaño, la siguiente llamada inmediata a BrotliEncoderTakeOutput podría devolver más datos.

Parámetros:

state instancia del codificador
size in: número de bytes que el llamador está listo para tomar, 0 si se puede manejar cualquier cantidad;
out: cantidad de datos a la que apunta el puntero devuelto y que se considera consumida;
el valor out nunca es mayor que el valor in, a menos que sea 0

Devuelve:

puntero a los datos de salida
