DESCRIPCIÓ

N

En muchas aplicaciones es conveniente dejar que Perl use Unicode para las cadenas que procesa. La mayoría de las interfaces que Perl tiene con el mundo exterior siguen basándose en bytes. Por lo tanto, los programas necesitan decodificar cadenas de bytes que entran al programa desde el exterior y codificarlas de nuevo al

salir.

El sistema de configuración regional POSIX se utiliza para especificar tanto las convenciones lingüísticas solicitadas por el usuario como el juego de caracteres preferido para consumir y producir. El módulo "Encode::Locale" busca el juego de caracteres y la codificación (llamada CODESET en la jerga de la configuración regional) y hace que el módulo Encode conozca esta codificación bajo el nombre "locale". Significa que los bytes obtenidos del entorno pueden convertirse en cadenas Unicode llamando a "Encode::encode(locale => $bytes)" y convertirse de nuevo con "Encode::decode(locale =>

$string)".

Donde las interfaces del sistema de archivos pasan nombres de archivo hacia dentro y hacia fuera del programa, también necesitamos tener cuidado. La tendencia es que los sistemas operativos utilicen una codificación de archivo fija que no depende realmente de la configuración regional; y este módulo determina la codificación más adecuada para los nombres de archivo. El módulo Encode conocerá esta codificación bajo el nombre "locale_fs". Para los sistemas Unix tradicionales, esto será un alias a la misma codificación que

"locale".

Para los programas que se ejecutan en una ventana de terminal (llamada "Consola" en algunos sistemas), la codificación "locale" suele ser una buena elección para lo que se espera como entrada y salida. Algunos sistemas nos permiten consultar la codificación establecida para la terminal y "Encode::Locale" hará eso si está disponible y hará que estas codificaciones sean conocidas bajo los alias de "Encode" "console_in" y "console_out". Para los sistemas donde no podemos determinar la codificación de la terminal, estas serán alias a la misma codificación que "locale". El consejo es usar "console_in" para la entrada que se sabe que proviene de la terminal y "console_out" para la salida hacia la

terminal.

Además de organizar varios alias de Encode, se proporcionan las siguientes funciones y

variables:

Window

s

Windows tiene básicamente 2 conjuntos de APIs. Una API "wide" (basada en pasar cadenas UTF-16) y una API basada en bytes basada en un juego de caracteres llamado ANSI. Las interfaces regulares de Perl al SO actualmente solo usan las APIs ANSI. Desafortunadamente, ANSI no es un único juego de

caracteres.

La codificación que corresponde a ANSI varía entre las diferentes ediciones de Windows. Para muchas ediciones occidentales de Windows, ANSI corresponde a CP-1252, que es un juego de caracteres similar a ISO-8859-1. Conceptualmente, el juego de caracteres ANSI es un concepto similar al CODESET de la configuración regional POSIX, por lo que este módulo averigua cuál es la página de código ANSI y la pone disponible como $ENCODING_LOCALE y el alias de codificación

"locale".

Los sistemas Windows también operan con otro juego de caracteres basado en bytes. Se

llama la página de código OEM. Esta es la codificación que la Consola toma como entrad
a y salida. Es común que la página de código OEM difiera de la página de código ANSI.

Mac OS

X

En Mac OS X, la codificación del sistema de archivos es siempre UTF-8, mientras que la configuración regional puede configurarse de lo normal para los sistemas

POSIX.

Los nombres de archivo en Mac OS X serán convertidos a nivel de SO a la forma NFD. Un archivo creado pasando un nombre de archivo NFC vendrá en forma NFD desde readdir(). Vea Unicode::Normalize para detalles de

NFD/NFC.

En realidad, Apple no sigue el estándar NFD de Unicode ya que no todos los rangos de ca

racteres se descomponen. Se afirma que esto evita problemas con conversiones de ida y v
uelta desde codificaciones de texto antiguas de Mac. Vea Encode::UTF8Mac para detalles.

POSIX (Linux y otros

Unixes)

Los sistemas de archivos pueden variar en qué codificación se debe usar para los nombres de archivo. Dado que

este módulo no tiene forma de averiguar realmente cuál es la correcta, se basa en la suposición más probable,
que es asumir que los nombres de archivo están codificados de acuerdo con la configuración regional actual. Se
recomienda a los usuarios especificar siempre UTF-8 como el juego de caracteres de la configuración regional.
