ensemble(n)

Paquete: tcl

Licencias: TCL

ensemble(n) [incr Tcl] ensemble(n)

NOMBRE

itcl::ensemble - crear o modificar un comando compuesto

SINOPSIS

itcl::ensemble nombreConjunto ?comando arg arg...?

o

ensemble nombreConjunto {
    parte nombreParte args cuerpo
    ...
    ensemble nombreParte {
        parte subNombreParte args cuerpo
        parte subNombreParte args cuerpo
    ...
    }
}

DESCRIPCIÓN

El comando ensemble se utiliza para crear o modificar un comando compuesto. Consulte la sección ¿QUÉ ES UN CONJUNTO? a continuación para una breve descripción general de los conjuntos.

Si el comando ensemble encuentra un conjunto existente llamado nombreConjunto, lo actualiza. De lo contrario, crea un conjunto llamado nombreConjunto. Si nombreConjunto es un nombre simple como "foo", entonces se agrega un comando de conjunto llamado "foo" al contexto del espacio de nombres actual. Si ya existe un comando llamado "foo" en ese contexto, se elimina. Si nombreConjunto contiene calificadores de espacio de nombres como "a::b::foo", entonces se resuelve la ruta del espacio de nombres y se agrega el comando de conjunto a ese contexto de espacio de nombres. Los espacios de nombres padre como "a" y "b" se crean automáticamente, según sea necesario.

Si nombreConjunto contiene espacios como "a::b::foo bar baz", entonces las palabras adicionales como "bar" y "baz" se tratan como subconjuntos. Los subconjuntos son simplemente partes dentro de un conjunto; no tienen un comando Tcl asociado con ellos. Un conjunto como "foo" puede tener un subconjunto llamado "foo bar", que a su vez puede tener un subconjunto llamado "foo bar baz". En este caso, el subconjunto "foo bar" debe crearse antes que el subconjunto "foo bar baz" que reside dentro de él.

Si hay argumentos que siguen a nombreConjunto, entonces se tratan como comandos y se ejecutan para actualizar el conjunto. Los siguientes comandos se reconocen en este contexto: parte y ensemble.

El comando parte define una nueva parte para el conjunto. Su sintaxis es idéntica al comando proc habitual, pero define una parte dentro de un conjunto, en lugar de un comando Tcl. Si ya existe una parte llamada nombreParte dentro del conjunto, entonces el comando parte devuelve un error.

El comando ensemble puede anidarse dentro de otro comando ensemble para definir un subconjunto.

¿QUÉ ES UN CONJUNTO?

El comando habitual "info" es un comando compuesto: el nombre del comando info debe ir seguido de un subcomando como body o globals. Nos referiremos a un comando como info como un *conjunto*, y a subcomandos como body o globals como sus *partes*.

Los conjuntos pueden anidarse. Por ejemplo, el comando info tiene un conjunto info namespace dentro de él. Este conjunto tiene partes como info namespace all y info namespace children.

Con los conjuntos, los comandos compuestos se pueden crear y extender de forma automática. Cualquier paquete puede encontrar un conjunto existente y agregarle nuevas partes. Por lo tanto, los escritores de extensiones pueden agregar sus propias partes, por ejemplo, al comando info.

El sistema de conjuntos administra todos los nombres de partes y realiza un seguimiento de las abreviaturas únicas. Normalmente, puede abreviar info complete como info comp. Pero si una extensión agrega la parte info complexity, la abreviatura mínima para info complete se convierte en info complet.

El sistema de conjuntos no solo automatiza la construcción de comandos compuestos, sino que también automatiza el manejo de errores. Si invoca un comando de conjunto sin especificar un nombre de parte, obtendrá un mensaje de error generado automáticamente que resume la información de uso. Por ejemplo, cuando se invoca el comando info sin argumentos, produce el siguiente mensaje de error:

número incorrecto de argumentos: debería ser uno de...
  info args procname
  info body procname
  info cmdcount
  info commands ?patrón?
  info complete command
  info context
  info default procname arg varname
  info exists varName
  info globals ?patrón?
  info level ?número?
  info library
  info locals ?patrón?
  info namespace opción ?arg arg ...?
  info patchlevel
  info procs ?patrón?
  info protection ?-comando? ?-variable? nombre
  info script
  info tclversion
  info vars ?patrón?
  info which ?-comando? ?-variable? ?-namespace? nombre

También puede personalizar la forma en que un conjunto responde a los errores. Cuando un conjunto encuentra un nombre de parte no especificado o ambiguo, busca una parte llamada @error. Si existe, se utiliza para manejar el error. Esta parte recibirá todos los argumentos en la línea de comandos comenzando con el nombre de parte que causa el error. Puede encontrar otra forma de resolver el comando o generar su propio mensaje de error.

EJEMPLO

Podríamos usar un conjunto para limpiar la sintaxis de los diversos comandos "wait" en Tcl/Tk. En lugar de usar una serie de comandos extraños como estos:

vwait x
tkwait visibility .top
tkwait window .

podríamos usar comandos con una sintaxis uniforme, como esta:

wait variable x
wait visibility .top
wait window .

El paquete Tcl podría definir el siguiente conjunto:

itcl::ensemble wait parte variable {nombre} {
    uplevel vwait $nombre
}

El paquete Tk podría agregar algunas opciones a este conjunto, con un comando como este:

itcl::ensemble wait {
    parte visibility {nombre} {
        tkwait visibility $nombre
    }
    parte window {nombre} {
        tkwait window $nombre
    }
}

Otras extensiones también podrían agregar sus propias partes al comando wait.
