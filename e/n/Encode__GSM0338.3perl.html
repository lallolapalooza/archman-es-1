NOMBRE

Encode::GSM0338 -- Codificación ETSI GSM 03.38

SINOPSIS

use Encode qw/encode decode/;
$gsm0338 = encode("gsm0338", $unicode); # carga Encode::GSM0338 implícitamente
$unicode = decode("gsm0338", $gsm0338); # ídem

DESCRIPCIÓN

GSM0338 es para teléfonos móviles GSM. Aunque comparte alfanuméricos con ASCII, los rangos de caracteres de control y otras partes se mapean de manera muy diferente, principalmente para almacenar caracteres griegos. También hay secuencias de escape (que comienzan con 0x1B) para cubrir, por ejemplo, el signo del euro.

Esto fue manejado una vez por Encode::Bytes pero debido a todas esas especificaciones inusuales, Encode 2.20 ha reubicado el soporte a este módulo.

Este módulo implementa solo el *Alfabeto Predeterminado GSM de 7 bits* y la *Tabla de extensión del alfabeto predeterminado GSM de 7 bits* según el estándar 3GPP TS 23.038 versión 16. Por lo tanto, *National Language Single Shift* y *National Language Locking Shift* no se implementan ni se soportan.

Septetos

Este módulo opera con octetos (como cualquier otro módulo Encode) y no con septetos empaquetados (a diferencia de otros estándares GSM). Por lo tanto, para procesar SMS binarios o partes de la carga útil TPDU de GSM (3GPP TS 23.040) es necesario realizar la conversión entre octetos y septetos empaquetados. Para este propósito, las funciones "pack" y "unpack" de Perl pueden ser útiles:

$bytes = substr(pack('(b*)*', unpack '(A7)*', unpack 'b*', $septets), 0, $num_of_septets);
$unicode = decode('GSM0338', $bytes);
$bytes = encode('GSM0338', $unicode);
$septets = pack 'b*', join '', map { substr $_, 0, 7 } unpack '(A8)*', unpack 'b*', $bytes;
$num_of_septets = length $bytes;

Tenga en cuenta que para la decodificación correcta de septetos empaquetados se requiere conocer el número de septetos empaquetados en el búfer binario, ya que el búfer binario siempre se rellena con bits cero y 7 bits cero representan el carácter "@". El número de septetos también se almacena en la carga útil TPDU cuando se trata de 3GPP TS 23.040.

ERRORES

Encode::GSM0338 2.7 y versiones anteriores (parte de Encode 3.06) manejaron incorrectamente los bytes cero (carácter "@"). Esto se corrigió en Encode::GSM0338 versión 2.8 (parte de Encode 3.07).
