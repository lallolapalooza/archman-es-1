ENCFS(1) Sistema de archivos cifrado ENCFS(1)

NOMBRE

encfs - monta o crea un sistema de archivos virtual cifrado

SINOPSIS

encfs [--version] [-v|--verbose] [-c|--config] [-t|--syslogtag] [-s] [-f] [--annotate] [--standard] [--paranoia] [--insecure] [--reverse] [--reversewrite] [--extpass=programa] [-S|--stdinpass] [--anykey] [--forcedecode] [-require-macs] [-i MINUTOS|--idle=MINUTOS] [-m|--ondemand] [--delaymount] [-u|--unmount] [--public] [--nocache] [--noattrcache] [--nodatacache] [--no-default-flags] [-o OPCION_FUSE] [-d|--fuse-debug] [-H|--fuse-help] directorio_raiz punto_montaje [-- [Opciones de Montaje Fuse]]

DESCRIPCIÓN

EncFS crea un sistema de archivos virtual cifrado que almacena datos cifrados en el directorio directorio_raiz y hace que los datos descifrados sean visibles en el directorio punto_montaje. El usuario debe proporcionar una contraseña que se utiliza para cifrar (indirectamente) tanto los nombres de archivo como el contenido de los archivos.

Si EncFS no puede encontrar un sistema de archivos compatible en el directorio_raiz especificado, se le preguntará al usuario si desea crear un nuevo sistema de archivos cifrado en esa ubicación. Se presentarán opciones al usuario que permitirán cierto control sobre los algoritmos a utilizar. A medida que EncFS madure, puede haber un número creciente de elecciones.

OPCIONES

--version
Muestra la versión de EncFS. Usar --verbose antes de --version puede mostrar información adicional.
-c, --config
Hace que EncFS utilice el archivo proporcionado como archivo de configuración.
-v, --verbose
Hace que EncFS habilite el registro de varios canales de depuración dentro de EncFS. Normalmente, estos mensajes de registro están deshabilitados y no tienen efecto. Se recomienda ejecutar en modo de primer plano (-f) cuando se ejecute con el modo verboso habilitado.
-t, --syslogtag
Esta opción permite establecer la etiqueta de syslog que se utilizará cuando se registren mensajes a través de syslog. Por defecto, la etiqueta de syslog se establece en encfs.
-s
La opción -s (hilo único) hace que EncFS se ejecute en modo de hilo único. Por defecto, EncFS se ejecuta en modo multihilo. Esta opción se utiliza durante el desarrollo de EncFS para simplificar la depuración y permitir que se ejecute bajo herramientas de verificación de memoria.
-f
La opción -f (primer plano) hace que EncFS se ejecute en primer plano. Normalmente, EncFS se lanza como un demonio y se ejecuta en segundo plano, devolviendo el control al shell que lo lanzó. Con la opción -f, se ejecutará en primer plano y cualquier mensaje de advertencia/depuración se mostrará en la salida estándar de error. En el modo predeterminado (segundo plano), todos los mensajes de registro se registran a través de syslog.
--annotate
Imprime líneas de anotación en stderr durante la configuración.
--standard
Si se crea un nuevo sistema de archivos, esto selecciona automáticamente opciones de configuración estándar, para ayudar a la creación automática de sistemas de archivos. Este es el conjunto de opciones que deben usarse a menos que sepa lo que está haciendo y haya leído la documentación.

Cuando no se crea un sistema de archivos, esta bandera no hace nada.

--paranoia
Igual que --standard, pero para el modo paranoia.
--insecure
Permite deshabilitar la codificación de datos, pasando así datos sin cifrar tal cual. ¡Totalmente desaconsejado, por supuesto!
--reverse
Normalmente, EncFS proporciona una vista en texto plano de los datos bajo demanda: almacena datos cifrados y muestra datos en texto plano. Con --reverse, toma datos en texto plano como fuente y produce datos cifrados bajo demanda. Esto puede ser útil para crear copias de seguridad cifradas remotas, donde no desea mantener los archivos locales sin cifrar.

Por ejemplo, lo siguiente crearía una vista cifrada en /tmp/crypt-view.

encfs --reverse /home/me /tmp/crypt-view

Luego podría copiar el directorio /tmp/crypt-view para tener una copia de los datos cifrados. También debe conservar una copia del archivo /home/me/.encfs6.xml que contiene la información del sistema de archivos. Juntos, los dos pueden usarse para reproducir los datos sin cifrar:

ENCFS6_CONFIG=/home/me/.encfs6.xml encfs /tmp/crypt-view /tmp/plain-view

Ahora /tmp/plain-view contiene los mismos datos que /home/me

Tenga en cuenta que el modo --reverse solo funciona con opciones de configuración limitadas, por lo que muchas configuraciones pueden deshabilitarse cuando se usa. Opciones incompatibles por ahora: Cadena de Vector de Inicialización de Nombres de Archivo y Cadena de IV Externo.

--reversewrite
Igual que --reverse, pero permitirá escrituras, si es posible (la configuración debe tener UniqueIV deshabilitado). Opción incompatible: Vectores de Inicialización por Archivo.
--extpass=programa
Especifica un programa externo para obtener la contraseña del usuario. Cuando se lanza el programa externo, la variable de entorno "RootDir" se establecerá para contener la ruta al directorio raíz. El programa debe imprimir la contraseña en la salida estándar.

EncFS toma todo lo devuelto por el programa como contraseña, excepto un salto de línea (\n) final que se eliminará.

Por ejemplo, especificar --extpass=/usr/lib/ssh/ssh-askpass hará que EncFS utilice el programa de aviso de contraseña de ssh.

Nota: EncFS lee como máximo 2k de datos del programa de contraseñas y elimina cualquier salto de línea final. Las versiones anteriores a la 1.4.x aceptaban solo 64 bytes de texto.

-S, --stdinpass
Lee la contraseña desde la entrada estándar, sin solicitarla. Esto puede ser útil para scripts de montaje de encfs.

Tenga en cuenta que primero debe asegurarse de que el sistema de archivos y los puntos de montaje existan. De lo contrario, encfs solicitará las opciones de creación del sistema de archivos, lo que puede interferir con su script.

--anykey
Deshabilita la verificación de validación de claves. Esto permite que EncFS se utilice con contraseñas secundarias. Esto podría usarse para almacenar un conjunto separado de archivos en un sistema de archivos cifrado. EncFS ignora los archivos que no se descifran correctamente, por lo que los archivos creados con contraseñas separadas solo serán visibles cuando el sistema de archivos se monte con su contraseña asociada.

Tenga en cuenta que si la contraseña principal se cambia (usando encfsctl), las otras contraseñas no serán utilizables a menos que la contraseña principal se restablezca a lo que era, ya que las otras contraseñas dependen de un descifrado inválido de la clave del volumen, que no permanecerá igual si la contraseña principal se cambia.

Advertencia: Utilice esta opción bajo su propio riesgo.

--forcedecode
Esta opción solo tiene efecto en sistemas de archivos que utilizan encabezados de bloque MAC. Por defecto, si un bloque se descifra y el MAC almacenado no coincide con el calculado, se devuelve un error de E/S a la aplicación y el bloque no se devuelve. Sin embargo, al especificar --forcedecode, solo se registrará un error y los datos aún se devolverán a la aplicación. Esto puede ser útil para intentar leer archivos corruptos.
--require-macs
Si se crea un nuevo sistema de archivos, esto fuerza la habilitación de los encabezados de código de autenticación de bloque. Al montar un sistema de archivos existente, esto hace que encfs salga si los encabezados de código de autenticación de bloque no están habilitados.

Esto se puede usar para mejorar la seguridad en caso de que el texto cifrado sea vulnerable a la manipulación, al evitar que un atacante deshabilite los MAC en la configuración

arch

ADVERTENCI

AS

EncFS no es un sistema de archivos verdadero. No se ocupa de ninguno del almacenamiento o mantenimiento real de archivos. Simplemente traduce solicitudes (cifrando o descifrando según sea necesario) y pasa las solicitudes al sistema de archivos subyacente del host. Por lo tanto, cualquier limitación del sistema de archivos del host será heredada por EncFS (o posiblemente ser aún más limitada)

.

Una de esas limitaciones es la longitud del nombre de archivo. Si su sistema de archivos subyacente lo limita a N caracteres en un nombre de archivo, entonces EncFS lo limitará a aproximadamente 3*(N-2)/4. Por ejemplo, si el sistema de archivos del host limita a 255 caracteres, entonces EncFS se limitará a nombres de archivo de 189 caracteres. Esto se debe a que los nombres

de archivo cifrados siempre son más largos qu
e los nombres de archivo en texto plano.

Tenga en cuenta que las opciones solo se pueden establecer en el momento de la creación del sistema de archivos. No hay soporte para modificar las opciones de un sistema de archivos in

Si desea actualizar un sistema de archivos para usar funciones más nuevas, entonces necesita crear un nuevo sistema de archivos y montar tanto el sistema de archivos antiguo como el nuevo al mismo tiempo y copiar el antiguo al

sistema.

Función de derivación de

clave

A partir de la versión 1.5, EncFS ahora usa PBKDF2 como la función de derivación de clave predeterminada. El número de iteraciones en la función de generación de claves se selecciona basbasado en el tiempo del reloj de pared para generar la clave. En el modo estándar, se utiliza un tiempo objetivo de 0.5 segundos, y en el modo paranoia se utiliza un objetivo de 3.0

segundos.

En un sistema AMD 64 de 1.6 GHz, aproximadamente 64k iteraciones de la función de derivación de claves pueden ser manejadas en medio segundo. El número exacto de iteraciones a usar se almacena en el archivo de configuración, ya que es necesario para volver a montar el sistema de

archivos.

Si una configuración del sistema de archivos EncFS de la versión 1.4.x es modificada con la versión 1.5 (como cuando se usa encfsctl para cambiar la contraseña), entonces se usará la nueva función PBKDF2 y el sistema de archivos ya no será legible por versiones

anteriores.

Tamaño de la Clave del

Muchos, si no todos, de los cifrados soportados admiten múltiples longitudes de clave. No hay realmente mucha necesidad de tener longitudes de clave enormes. Incluso 160 bits (el valor por defecto) probablemente es

Tamaño de Bloque del Sistema de
Archivos
Este es el tamaño (en bytes) que EncFS maneja a la vez. Cada bloque recibe su propio vector de inicialización y es codificado en el modo de encadenamiento de bloques de cifrado (cipher-block-chaining) del cifrado. Un bloque parcial al final de un archivo es codificado usando un modo de flujo para evitar tener que almacenar el tamaño del archivo en algún lugar.

Tener tamaños de bloque más grandes reduce la sobrecarga de EncFS un poco, pero también puede añadir sobrecarga si tus programas leen pequeñas partes de archivos. Para leer un solo byte de un archivo, el bloque completo que contiene ese byte debe ser leído y decodificado, por lo que un tamaño de bloque grande añade sobrecarga a las peticiones pequeñas. Con las llamadas de escritura es aún peor, ya que un bloque debe ser leído y decodificado, el cambio aplicado y el bloque codificado y escrito de

vuelta.

El valor por defecto es 512 bytes a partir de la versión 1.0. Estaba

codificado de forma fija en 64 bytes en la versión 0.x, lo cual no
era tan eficiente como la configuración actual para el uso general.
Codificación de Nombres de
Archivo
Nuevo en 1.1. Se da una elección entre la codificación de flujo de nombres de archivo y la codificación de bloques. La ventaja de la codificación de flujo es que los nombres de archivo codificados serán lo más cortos posible. Si tienes un nombre de archivo con una sola letra, será muy corto en la forma codificada, mientras que los nombres de archivo codificados por bloques siempre se redondean al tamaño de bloque del cifrado (8 bytes para Blowfish y 16 bytes para AES).

La ventaja del modo de codificación por bloques es que las longitudes de los nombres de archivo resultan todas en un múltiplo del tamaño de bloque del cifrado. Esto significa que alguien que mire tus datos cifrados no puede saber tanto sobre la longitud de tus nombres de archivo. Está activado por defecto, ya que toma una cantidad de tiempo similar a usar el cifrado de flujo. Sin embargo, el modo de cifrado de flujo puede ser útil si quieres nombres de archivo cifrados más cortos por alguna

razón.

Basado en un sistema de archivos subyacente que soporta un máximo de 255 caracteres en nombres de archivo, aquí está la longitud máxima posible del nombre de archivo dependiendo del esquema de codificación elegido: flujo (189), bloque (176), block32 (143). Nota que deberíamos hablar más bien de bytes, cuando los nombres de archivo contienen caracteres especiales (multibyte)

.

Encadenamiento del Vector de Inicialización del Nombre de
Archivo
Nuevo en 1.1. En versiones anteriores de EncFS, cada elemento del nombre de archivo en una ruta era codificado por separado. Así que si "foo" se codificaba a "XXX", siempre se codificaría de esa manera (dada la misma clave de cifrado), sin importar si la ruta era "a/b/foo", o "aa/foo/cc", etc. Eso significaba que era posible para alguien que mirara los datos cifrados ver si dos archivos en diferentes directorios tenían el mismo nombre, aunque no supieran a qué decodificaba ese nombre.

Con el encadenamiento de vectores de inicialización, cada directorio recibe su propio vector de inicialización. Así que "a/foo" y "b/foo" tendrán nombres codificados completamente diferentes para "foo". Esta característica tiene casi ningún impacto en el rendimiento (para la mayoría de las operaciones), y por lo tanto es el valor por defecto en todos los

modos.

Nota: Una excepción de rendimiento significativa es el renombrado de directorios. Dado que el vector de inicialización para la codificación del nombre de archivo depende de la ruta del directorio, cualquier renombrado requiere recodificar cada nombre de archivo en el árbol del directorio que se está cambiando

. Si hay miles de archivos, entonces EncFS tendrá que hacer miles de renombrados. También es posible que EncFS encuentre un archivo que no pueda decodificar o n
o tenga permiso para mover durante la operación de renombrado, en cuyo caso intentará deshacer cualquier cambio que haya hecho hasta ese punto y el renombrado fallará.
Vectores de Inicialización por
Archivo
Nuevo en 1.1. En versiones anteriores de EncFS, cada archivo era codificado de la misma manera. Cada bloque en un archivo siempre ha tenido su propio vector de inicialización, pero de una manera determinista, de modo que el bloque N en un archivo era codificado de la misma manera que el bloque N en otro archivo. Eso hacía posible para alguien saber si dos archivos eran idénticos (o partes del archivo eran idénticas) comparando los datos codificados.

Con vectores de inicialización por archivo, cada archivo recibe su propio vector de inicialización aleatorio de 64 bits, de modo que cada archivo es cifrado de una manera

diferente.

Esta opción está activada por

defecto.

El modo inverso deriva el IV del número de inodo, por lo que puede cambiar, por ejemplo, cuando los archivos de origen se copian de un sistema de archivos a

otro.
Encadenamiento de IV
Externo
Nuevo en 1.1.3. Esta opción está estrechamente relacionada con los Vectores de Inicialización por Archivo y el Encadenamiento del Vector de Inicialización del Nombre de Archivo. Básicamente extiende el encadenamiento de vectores de inicialización de los nombres de archivo al vector de inicialización por archivo.

Cuando esta opción está activada, el vector de inicialización por archivo es codificado usando el vector de inicialización derivado del código de encadenamiento del vector de inicialización del nombre de archivo. Esto significa que los datos en un archivo quedan ligados al nombre de archivo. Si un archivo cifrado es renombrado fuera de encfs, ya no será decodificable dentro de encfs. Nota que a menos que las Cabeceras MAC de Bloque estén activadas, el error de decodificación no será detectado y resultará en la lectura de datos que parecen

aleatorios.

Hay un costo asociado con esto. Cuando el Encadenamiento de IV Externo está activado, no se permitirán enlaces duros dentro del sistema de archivos, ya que no habría manera de decodificar correctamente dos nombres de archivo diferentes que apuntan a los mismos

datos.

Además, renombrar un archivo requiere modificar la cabecera del archivo. Por lo tanto, los renombrados solo se permitirán cuando el usuario tenga acceso de escritura al

archivo.

Debido a estos límites, esta opción está desactivada por defecto para el modo estándar (y activada por defecto para el modo paranoia)

.

Esta opción puede ser incompatible con algunos proveedores de nube, ya que durante un renombrado, el contenido del archivo cambia, pero no su marca de tiempo. Debido a esto, los cambios del archivo pueden no ser vistos correctamente por los programas de sincronización de los proveedores de nube. Por lo tanto, no se recomienda para uso en

la
nube.

El objetivo principal de EncFS es proteger datos fuera de línea. Es decir, proporcionar una manera conveniente de almacenar archivos de una manera que frustrará cualquier intento de leerlos si los archivos son interceptados

posteriormente.

Algunos algoritmos en EncFS también están destinados a frustrar ataques en línea donde se asume que un atacante es capaz de modificar los

archivos.

Los ataques más intrusivos, donde un atacante tiene control completo de la máquina del usuario (y por lo tanto puede modificar EncFS, o FUSE, o el kernel mismo) no están protegidos. No asumas que los archivos cifrados protegerán tus datos sensibles si ingresas tu contraseña en una computadora comprometida. Cómo determinas que la computadora es segura para usar está fuera del alcance de esta

documentación.

Dicho esto, aquí hay algunos ejemplos de ataques y técnicas de recopilación de datos sobre el contenido del sistema de archivos junto con los algoritmos que EncFS soporta para contrarrestarlos

:
Ataque: modificar unos pocos bytes de un archivo cifrado (sin saber a qué se decodificarán)
.
EncFS no usa ninguna forma de cifrado XOR que permitiría modificar bytes individuales sin afectar a otros. La mayoría de las modificaciones afectarían a docenas o más bytes. Adicionalmente, las Cabeceras MAC de Bloque pueden ser usadas para identificar cualquier cambio en los
archivos.

archivo.

Attacks

Attack: filename obfuscation
This is not an attack, but a feature. The filenames are obfuscated. There is no metadata exposed that could leak filename information.
Attack: detecting file type
It is not possible to determine file type from the encrypted file names.
Attack: recognizing repeated file content
Can be prevented by enabling Block MACs. This is the default. The MACs are computed on encrypted data, so they can not be modified without changing the encrypted data. (This is not a protection against a passive attacker.)
Attack: copying an entire file to another file.
Can be prevented by enabling External IV Chaining mode.
Attack: determine if two filenames are the same by looking at encrypted names.
Filename Initialization Vector chaining prevents this by giving each file a 64-bit initialization vector derived from its full path name.
Attack: compare if two files contain the same data.
Per-File Initialization Vector support prevents this.
