ENC2XS(1perl) Guía de referencia para programadores de Perl ENC2XS(1perl)

NOMBRE

enc2xs -- Generador de Módulos Encode para Perl

SINOPSIS

enc2xs -[opciones]
enc2xs -M ModName archivos_mapeo...
enc2xs -C

DESCRIPCIÓN

enc2xs construye una extensión de Perl para ser usada por Encode a partir de archivos de Mapeo de Caracteres Unicode (.ucm) o Archivos de Codificación Tcl (.enc). Además de ser usado internamente durante el proceso de construcción del módulo Encode, puedes usar enc2xs para agregar tu propia codificación a perl. No se necesita conocimiento de XS.

Guía Rápida

Si quieres saber lo menos posible sobre Perl pero necesitas agregar una nueva codificación, solo lee este capítulo y olvida el resto.

0.
Ten un archivo .ucm listo. Puedes obtenerlo de algún lugar o escribir el tuyo propio desde cero o tomar uno de la distribución de Encode y personalizarlo. Para el formato UCM, consulta el siguiente Capítulo. En el ejemplo a continuación, llamaré a mi codificación teórica myascii, definida en my.ucm. "$" es un prompt de shell. 
$ ls -F
my.ucm
1.
Ejecuta un comando como el siguiente; 
$ enc2xs -M My my.ucm
generando Makefile.PL
generando My.pm
generando README
generando Changes

Ahora mira tu directorio actual. Debería verse así.

$ ls -F
Makefile.PL   My.pm         my.ucm        t/

Los siguientes archivos fueron creados.

Makefile.PL - Script MakeMaker
My.pm       - Submódulo Encode
t/My.t      - archivo de prueba
1.1.
Si quieres que los archivos *.ucm se instalen junto con los módulos, haz lo siguiente; 
$ mkdir Encode
$ mv *.ucm Encode
$ enc2xs -M My Encode/*ucm
2.
Edita los archivos generados. No tienes que hacerlo si no tienes tiempo Y no tienes la intención de dárselo a alguien más. Pero es una buena idea editar el pod y agregar más pruebas.
3.
Ahora ejecuta un comando que todos los Perl Mongers aman: 
$ perl Makefile.PL
Escribiendo Makefile para Encode::My
4.
Ahora todo lo que tienes que hacer es make. 
$ make
cp My.pm blib/lib/Encode/My.pm
/usr/local/bin/perl /usr/local/bin/enc2xs -Q -O \
  -o encode_t.c -f encode_t.fnm
Leyendo myascii (myascii)
Escribiendo forma compilada
128 bytes en tablas de cadenas
384 bytes (75%) ahorrados al detectar duplicados
1 bytes (0.775%) ahorrados usando subcadenas
....
chmod 644 blib/arch/auto/Encode/My/My.bs
$

El tiempo que toma varía dependiendo de la velocidad de tu máquina y del tamaño de tu codificación. A menos que estés trabajando en algo grande como euc-tw, no tomará mucho tiempo.

5.
Ya puedes hacer "make install" pero deberías probar primero. 
$ make test
PERL_DL_NONLAZY=1 /usr/local/bin/perl -Iblib/arch -Iblib/lib \
  -e 'use Test::Harness  qw(&runtests $verbose); \
  $verbose=0; runtests @ARGV;' t/*.t
t/My....ok
Todas las pruebas exitosas.
Archivos=1, Pruebas=2, 0 segundos de reloj
 ( 0.09 cusr + 0.01 csys = 0.09 CPU)
6.
Si estás satisfecho con el resultado de la prueba, simplemente haz "make install"
7.
Si deseas agregar tu codificación a la lista de carga bajo demanda de Encode (para que no tengas que ejecutar "use Encode::YourEncoding"), ejecuta 
enc2xs -C

para actualizar Encode::ConfigLocal, un módulo que controla la configuración local. Después de eso, "use Encode;" será suficiente para cargar tus codificaciones bajo demanda.

El mapa de caracteres Unicode

Encode utiliza el formato UCM (Unicode Character Map) para los mapeos de caracteres fuente. Este formato es utilizado por el paquete ICU de IBM y fue adoptado por Nick Ing-Simmons para usarlo con el módulo Encode. Dado que UCM es más flexible que el Tcl Encoding Map y mucho más amigable para el usuario, este es el formato recomendado para Encode ahora.

Un archivo UCM se ve así.

#
# Comentarios
#
<code_set_name> "US-ascii" # Requerido
<code_set_alias> "ascii"   # Opcional
<mb_cur_min> 1             # Requerido; usualmente 1
<mb_cur_max> 1             # Máx. # de bytes/carácter
<subchar> \x3F             # Carácter de sustitución
#
CHARMAP
<U0000> \x00 |0 # <control>
<U0001> \x01 |0 # <control>
<U0002> \x02 |0 # <control>
....
<U007C> \x7C |0 # LÍNEA VERTICAL
<U007D> \x7D |0 # LLAVE DERECHA
<U007E> \x7E |0 # TILDE
<U007F> \x7F |0 # <control>
END CHARMAP
  • Cualquier cosa que siga a "#" se trata como un comentario.
  • La sección de encabezado continúa hasta una línea que contiene la palabra CHARMAP. Esta sección tiene el formato de <palabra_clave> valor, un par por línea. Las cadenas usadas como valores deben estar entre comillas. Las palabras desnudas se tratan como números. \xXX representa un byte.

    La mayoría de las palabras clave son autoexplicativas. subchar significa carácter de sustitución, no subcarácter. Cuando decodificas una secuencia Unicode a esta codificación pero no se encuentra un carácter coincidente, se usará la secuencia de bytes definida aquí. Para la mayoría de los casos, el valor aquí es \x3F; en ASCII, esto es un signo de interrogación.

  • CHARMAP inicia la sección del mapa de caracteres. Cada línea tiene un formato como el siguiente: 
    <UXXXX> \xXX.. |0 # comentario
  ^     ^      ^
  |     |      +- Bandera de reserva
  |     +-------- Secuencia de bytes codificados
  +-------------- ID de Carácter Unicode en hexadecimal

    El formato es aproximadamente el mismo que el de una sección de encabezado excepto por la bandera de reserva: | seguida de 0..3. El significado de los posibles valores es el siguiente:

|0
Seguro para ida y vuelta. Un carácter decodificado a Unicode se codifica de vuelta a la misma secuencia de bytes. La mayoría de los caracteres tienen esta bandera.
|1
Reserva para unicode -> codificación. Cuando se ve, enc2xs agrega este carácter solo para el mapa de codificación.
|2
Omitir el mapeo de caracteres de sustitución si no hay un punto de código.
|3
Reserva para codificación -> unicode. Cuando se ve, enc2xs agrega este carácter solo para el mapa de decodificación.
•
Y finalmente, END OF CHARMAP termina la sección.

Cuando creas manualmente un archivo UCM, deberías copiar ascii.ucm o una codificación existente que sea similar a la tuya, en lugar de escribir la tuya desde cero.

Al hacerlo, asegúrate de dejar al menos U0000 a U0020 sin cambios, a menos que tu entorno sea EBCDIC.

ADVERTENCIA: no todas las características de UCM están implementadas. Por ejemplo, icu:state no se utiliza. Debido a esto, necesitas escribir un módulo perl si deseas soportar codificaciones algorítmicas, notablemente la serie ISO-2022. Dichos módulos incluyen Encode::JP::2022_JP, Encode::KR::2022_KR y Encode::TW::HZ.

Manejo de mapeos duplicados

Al crear un mapa, DEBES hacer que tus mapeos sean seguros para ida y vuelta. Es decir, encode('tu-codificacion', decode('tu-codificacion', $datos)) eq $datos se aplica a todos los caracteres marcados como "|0". Aquí te explicamos cómo asegurarlo:

  • Ordena tu mapa en orden Unicode.
  • Cuando tengas una entrada duplicada, marca una de ellas con '|1' o '|3'.
  • Y asegúrate de que la entrada '|1' o '|3' SIGA a la entrada '|0'.

Aquí tienes un ejemplo de big5-eten.

<U2550> \xF9\xF9 |0
<U2550> \xA2\xA4 |3

Internamente, el mapa de Codificación -> Unicode y Unicode -> Codificación se ve así;

E a U               U a E
--------------------------------------
\xF9\xF9 => U2550    U2550 => \xF9\xF9
\xA2\xA4 => U2550

Así que es seguro para ida y vuelta para \xF9\xF9. Pero si la línea anterior estuviera al revés, esto es lo que sucedería.

E a U               U a E
--------------------------------------
\xA2\xA4 => U2550    U2550 => \xF9\xF9
(¡\xF9\xF9 => U2550 ahora se ha sobrescrito!)

El paquete Encode viene con ucmlint, una utilidad rudimentaria pero suficiente para verificar la integridad de un archivo UCM. Busca en el directorio Encode/bin.

En caso de duda, puedes usar ucmsort, otra utilidad en el directorio Encode/bin.
