NOMBRE

Encode::MIME::Header -- Codificación MIME para un cuerpo de cabecera de correo electrónico no estructurado

SINOPSIS

use Encode qw(encode decode);
my $mime_str = encode("MIME-Header", "Muestra:Texto \N{U+263A}");
# $mime_str es "=?UTF-8?B?U2FtcGxlOlRleHQg4pi6?="
my $mime_q_str = encode("MIME-Q", "Muestra:Texto \N{U+263A}");
# $mime_q_str es "=?UTF-8?Q?Sample=3AText_=E2=98=BA?="
my $str = decode("MIME-Header",
    "=?ISO-8859-1?B?SWYgeW91IGNhbiByZWFkIHRoaXMgeW8=?=\r\n " .
    "=?ISO-8859-2?B?dSB1bmRlcnN0YW5kIHRoZSBleGFtcGxlLg==?="
);
# $str es "Si puedes leer esto entiendes el ejemplo."
use Encode qw(decode :fallbacks);
use Encode::MIME::Header;
local $Encode::MIME::Header::STRICT_DECODE = 1;
my $strict_string = decode("MIME-Header", $mime_string, FB_CROAK);
# usa decodificación estricta y falla en caso de errores

RESUMEN

Este módulo implementa la codificación MIME RFC 2047 https://tools.ietf.org/html/rfc2047 para un cuerpo de campo no estructurado de la cabecera del correo electrónico. También puede ser utilizado para el token 'text' de RFC 822 https://tools.ietf.org/html/rfc822. Sin embargo, no se puede utilizar directamente para la cabecera completa con el nombre del campo ni para los campos de cabecera estructurados como From, To, Cc, Message-Id, etc... Hay 3 nombres de codificación soportados por este módulo: "MIME-Header", "MIME-B" y "MIME-Q".

DESCRIPCION

El método de decodificación toma como entrada un cuerpo de campo no estructurado de la cabecera del correo electrónico (o el token 'text' de RFC 822 https://tools.ietf.org/html/rfc822) y decodifica cada palabra codificada MIME de la cadena de entrada a una secuencia de bytes según RFC 2047 https://tools.ietf.org/html/rfc2047 y RFC 2231 https://tools.ietf.org/html/rfc2231. Posteriormente, cada secuencia de bytes con el charset MIME correspondiente se decodifica con el módulo Encode y finalmente se devuelve una cadena de salida. Las partes de texto de la cadena de entrada que no contienen palabras codificadas MIME permanecen sin modificar en la cadena de salida. Los saltos de línea plegados entre dos palabras codificadas MIME consecutivas se descartan, otros se preservan en la cadena de salida. "MIME-B" puede decodificar la variante Base64, "MIME-Q" puede decodificar la variante Quoted-Printable y "MIME-Header" puede decodificar ambas. Si el módulo Encode no soporta un charset MIME particular o una variante elegida, se realiza una acción basada en las banderas CHECK (por defecto, la palabra codificada MIME no se decodifica).

El método de codificación toma una cadena escalar como entrada y usa un codificador estricto de UTF-8 para codificarla a bytes UTF-8. Luego, una secuencia de bytes UTF-8 se codifica en palabras codificadas MIME ("MIME-Header" y "MIME-B" usan una variante Base64 mientras que "MIME-Q" usa una variante Quoted-Printable) donde cada palabra codificada MIME se limita a 75 caracteres. Las palabras codificadas MIME se separan por "CRLF SPACE" y se unen en una cadena de salida. La cadena de salida es adecuada para el cuerpo de campo no estructurado de la cabecera del correo electrónico.

Ambos métodos, codificar y decodificar, propagan las banderas CHECK al codificar y decodificar el charset MIME.

ERRORES

Las versiones anteriores a la 2.22 (parte de Encode 2.83) tenían un decodificador y codificador defectuosos. El codificador MIME insertaba infamemente espacios adicionales o descartaba espacios en blanco entre palabras codificadas MIME consecutivas, lo que provocaba cabeceras MIME inválidas producidas por este módulo. El decodificador MIME tenía la tendencia de descartar espacios en blanco, interpretar incorrectamente los datos o intentar decodificar palabras codificadas MIME Base64 como Quoted-Printable. Estos problemas se solucionaron en la versión 2.22. ¡Se recomienda encarecidamente no usar ninguna versión anterior a la 2.22!

Las versiones anteriores a la 2.24 (parte de Encode 2.87) ignoraban las banderas CHECK. El codificador MIME no utilizaba un codificador UTF-8 estricto para las cadenas Unicode de entrada, lo que podía provocar secuencias UTF-8 inválidas. El decodificador MIME tampoco utilizaba un decodificador UTF-8 estricto y, además, llamaba al método decode con una bandera "Encode::FB_PERLQQ" (por lo tanto, se ignoraban las banderas CHECK especificadas por el usuario). Además, fallaba automáticamente cuando una palabra codificada MIME contenía una codificación desconocida. Desde la versión 2.24, este módulo utiliza un codificador y decodificador UTF-8 estrictos. Y las banderas CHECK se propagan correctamente.

Desde la versión 2.22 (parte de Encode 2.83), el codificador MIME debería ser totalmente compatible con RFC 2047 https://tools.ietf.org/html/rfc2047 y RFC 2231 https://tools.ietf.org/html/rfc2231. Debido a los errores mencionados en versiones anteriores del codificador MIME, existe un modo compatible menos estricto para el decodificador MIME que se utiliza por defecto. Debería ser capaz de decodificar palabras codificadas MIME por versiones anteriores a la 2.22 de este módulo. Sin embargo, tenga en cuenta que esto no es correcto según RFC 2047 https://tools.ietf.org/html/rfc2047.

En el modo no estricto por defecto, el decodificador MIME intenta decodificar cada subcadena que parece una palabra codificada MIME. Por lo tanto, las palabras codificadas MIME no necesitan estar separadas por espacios en blanco. Para forzar un modo estricto correcto, establezca la variable $Encode::MIME::Header::STRICT_DECODE a 1, por ejemplo, localizándola:

use Encode::MIME::Header;
local $Encode::MIME::Header::STRICT_DECODE = 1;
