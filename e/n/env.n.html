env Esta variable es mantenida por Tcl como un array cuyos elementos son las variables de entorno del proceso. Leer un elemento devolverá el valor de la variable de entorno correspondiente. Establecer un elemento del array modificará la variable de entorno correspondiente o creará una nueva si no existe ya. Eliminar un elemento de env eliminará la variable de entorno correspondiente. Los cambios en el array env afectarán al entorno pasado a los procesos hijos por comandos como exec. Si se elimina el array env completo, entonces Tcl dejará de monitorizar los accesos a env y no actualizará las variables de entorno. En Windows, las vari

PATH y COMSPEC,

errorInfo
Esta variable contiene el valor de la opción de retorno -errorinfo establecida por el error más reciente que ocurrió en este intérprete. Este valor de cadena contendrá una o más líneas que identifican los comandos y procedimientos Tcl que se estaban ejecutando cuando ocurrió el error más reciente. Su contenido tiene la forma de un rastreo de pila que muestra los diversos comandos anidados de Tcl que se habían invocado en el momento del error.
tcl_library
Esta variable contiene el nombre de un directorio que contiene la biblioteca del sistema de scripts Tcl, como los utilizados para la carga automática. El valor de esta variable se devuelve con el comando info library. Consulte la entrada del manual library para obtener detalles sobre las instalaciones proporcionadas por la biblioteca de scripts Tcl. Normalmente, cada aplicación o paquete tendrá su propia biblioteca de scripts específica de la aplicación, además de la biblioteca de scripts Tcl; cada aplicación debe establecer una variable global con un nombre como $app_library (donde app es el nombre de la aplicación) para contener el nombre de archivo de red del directorio de la biblioteca de esa aplicación. El valor inicial de tcl_library se establece cuando se crea un intérprete, buscando en varios directorios diferentes hasta que se encuentra uno que contiene un script de inicio Tcl apropiado. Si la variable de entorno TCL_LIBRARY existe, se comprueba primero el directorio que nombra. Si TCL_LIBRARY no está establecida o no se refiere a un directorio apropiado, Tcl verifica varios otros directorios basándose en una ubicación predeterminada compilada, la ubicación del binario que contiene la aplicación y el directorio de trabajo actual.
tcl_patchLevel
Cuando se crea un intérprete, Tcl inicializa esta variable para contener una cadena que indica el nivel de parche actual para Tcl, como 8.4.16 para Tcl 8.4 con los primeros dieciséis parches oficiales, o 8.5b3 para la tercera versión beta de Tcl 8.5. El valor de esta variable se devuelve con el comando info patchlevel.
tcl_pkgPath
Esta variable contiene una lista de directorios que indican dónde se instalan normalmente los paquetes. No se utiliza en Windows. Típicamente contiene una o dos entradas; si contiene dos entradas, la primera es normalmente un directorio para paquetes dependientes de la plataforma (por ejemplo, binarios de bibliotecas compartidas) y la segunda es normalmente un directorio para paquetes independientes de la plataforma (por ejemplo, archivos de script). Típicamente, un paquete se instala como un subdirectorio de una de las entradas en la variable tcl_pkgPath. Los directorios en la variable tcl_pkgPath se incluyen por defecto en la variable auto_path, por lo que ellos y sus subdirectorios inmediatos se buscan automáticamente para encontrar paquetes durante los comandos package require. Nota: tcl_pkgPath no está destinado a ser modificado por la aplicación. Su valor se añade a auto_path al inicio; los cambios en tcl_pkgPath no se reflejan en auto_path. Si desea que Tcl busque directorios adicionales para paquetes, debe agregar los nombres de esos directorios a auto_path, no a tcl_pkgPath.
tcl_platform
Este es un array asociativo cuyos elementos contienen información sobre la plataforma en la que se está ejecutando la aplicación, como el nombre del sistema operativo, su número de versión actual y el conjunto de instrucciones de la máquina. Los elementos que se enumeran a continuación siempre estarán definidos, pero pueden tener cadenas vacías como valores si Tcl no pudo recuperar ninguna información relevante. Además, las extensiones y aplicaciones pueden agregar valores adicionales al array. Los elementos predefinidos son:
byteOrder
El orden de bytes nativo de esta máquina: littleEndian o bigEndian.
debug
Si esta variable existe, entonces el intérprete se compiló y enlazó con un tiempo de ejecución C habilitado para depuración. Esta variable solo existirá en Windows, por lo que los escritores de extensiones pueden especificar qué paquete cargar dependiendo de la biblioteca de tiempo de ejecución C que se esté utilizando. Esto no es una indicación de que este núcleo contenga símbolos.
engine
El nombre de la implementación del lenguaje Tcl. Cuando el intérprete se crea por primera vez, esto siempre se establece en la cadena Tcl.
machine
El conjunto de instrucciones ejecutado por esta máquina, como intel, PPC, 68k o sun4m. En máquinas UNIX, este es el valor devuelto por uname -m.
os
El nombre del sistema operativo que se ejecuta en esta máquina, como Windows NT o SunOS. En máquinas UNIX, este es el valor devuelto por uname -s.
osVersion
El número de versión del sistema operativo que se ejecuta en esta máquina. En máquinas UNIX, este es el valor devuelto por uname -r.
pathSeparator
El carácter que debe usarse para dividir variables de entorno similares a PATH en su lista correspondiente de nombres de directorio.
platform
Ya sea windows o unix. Esto identifica el entorno operativo general de la máquina.
pointerSize
Esto da el tamaño del puntero nativo de la máquina en bytes (estrictamente, es lo mismo que el resultado de evaluar sizeof(void*) en C).
threaded
Si esta variable existe, entonces el intérprete se compiló con hilos habilitados.
user
Esto identifica al usuario actual basándose en la información de inicio de sesión disponible en la plataforma. Este valor proviene de las llamadas al sistema getuid() y getpwuid() en Unix, y del valor de la llamada al sistema GetUserName() en Windows.
wordSize
Esto da el tamaño de la palabra nativa de la máquina en bytes (estrictamente, es lo mismo que el resultado de evaluar sizeof(long) en C).
tcl_precision
Esta variable controla el número de dígitos a generar al convertir valores de punto flotante a cadenas. Por defecto es 0. Las aplicaciones no deben cambiar este valor; se proporciona por compatibilidad con código heredado.
El valor predeterminado de 0 es especial, lo que significa que Tcl debe convertir números utilizando el menor número de dígitos posible sin dejar de distinguir cualquier número de punto flotante de sus vecinos más cercanos. Difiere de usar un valor arbitrariamente alto para tcl_precision en que un número inexacto como 1.4 se convertirá como 1.4 en lugar de 1.3999999999999999, aunque este último esté más cerca del valor exacto del número binario.
Si tcl_precision no es cero, entonces cuando Tcl convierte un número de punto flotante, crea una representación decimal de como máximo tcl_precision dígitos significativos; el resultado puede ser más corto si el resultado más corto representa el número original exactamente. Si no existe una representación exacta del número original con un máximo de tcl_precision dígitos, se elige la que está más cerca del número original. Si el número original se encuentra precisamente entre dos representaciones decimales igualmente precisas, se elige la que tiene un valor par para el dígito menos significativo; por ejemplo, si tcl_precision es 3, entonces 0.3125 se convertirá en 0.312, no en 0.313, mientras que 0.6875 se convertirá en 0.688, no en 0.687. Cualquier cadena de ceros finales que queden se recortará.
Un valor de tcl_precision de 17 dígitos es "perfecto" para punto flotante IEEE, ya que permite que los valores de doble precisión se conviertan a cadenas y de nuevo a binario sin pérdida de información. Por esta razón, a menudo se ve como un valor en código heredado que debe ejecutarse en versiones de Tcl anteriores a la 8.5. Ya no se recomienda; como se mencionó anteriormente, el valor cero es el método preferido.
Todos los intérpretes en un hilo comparten un único valor de tcl_precision: cambiarlo en un intérprete afectará a todos los demás intérpretes. A los intérpretes seguros no se les permite modificar la variable.
Los valores válidos para tcl_precision van de 0 a 17.
tcl_rcFileName
Esta variable se utiliza durante la inicialización para indicar el nombre de un archivo de inicio específico del usuario. Si es establecido por la inicialización específica de la aplicación, entonces el código de inicio de Tcl verificará la existencia de este archivo y lo sondeará si existe. Por ejemplo, para wish la variable se establece en ~/.wishrc para Unix y en ~/wishrc.tcl para Windows.
