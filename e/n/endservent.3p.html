DESCRIPCIÓ

N

Estas funciones recuperan información sobre servicios de red. Esta información se considera almacenada en una base de datos a la que se puede acceder secuencial o aleatoriamente. La implementación de esta base de datos no está

especificada.

La función setservent() abrirá una conexión con la base de datos y establecerá la siguiente entrada como la primera entrada. Si el argumento stayopen es distinto de cero, la base de datos net no se cerrará después de cada llamada a la función getservent() (ya sea directamente, o indirectamente a través de una de las otras funciones getserv*()), y la implementación puede mantener un descriptor de archivo abierto para la base de

datos.

La función getservent() leerá la siguiente entrada de la base de datos, abriendo y cerrando una conexión con la base de datos según sea

necesario.

La función getservbyname() buscará en la base de datos desde el principio y encontrará la primera entrada para la que el nombre de servicio especificado por name coincida con el miembro s_name y el nombre de protocolo especificado por proto coincida con el miembro s_proto, abriendo y cerrando una conexión con la base de datos según sea necesario. Si proto es un puntero nulo, se coincidirá con cualquier valor del miembro s_p

roto.

La función getservbyport() buscará en la base de datos desde el principio y encontrará la primera entrada para la que el puerto especificado por port coincida con el miembro s_port y el nombre de protocolo especificado por proto coincida con el miembro s_proto, abriendo y cerrando una conexión con la base de datos según sea necesario. Si proto es un puntero nulo, se coincidirá con cualquier valor del miembro s_proto. El argumento port debe ser un valor obtenido al convertir un uint16_t en orden de bytes de red a int

.

Las funciones getservbyname(), getservbyport() y getservent() devolverán cada una un puntero a una estructura servent, cuyos miembros contendrán los campos de una entrada en la base de datos de servicios de

red.

La función endservent() cerrará la base de datos, liberando cualquier descriptor de archivo

abierto.

Estas funciones no ne

cesitan ser seguras e
n entornos multihilo.

VALOR DE

RETORNO

Tras una finalización exitosa, getservbyname(), getservbyport() y getservent() devuelven un puntero a una estructura servent si se encontró la entrada solicitada, y un puntero nulo si se alcanzó el final de la base de datos o no se encontró la entrada solicitada. De lo contrario, se devuelve un puntero

nulo.

La aplicación no debe modificar la estructura a la que apunta el valor de retorno, ni ninguna de las áreas de almacenamiento a las que apuntan los punteros dentro de la estructura. El puntero devuelto, y los punteros dentro de la estructura, podrían invalidarse, o la estructura o las áreas de almacenamiento podrían ser sobrescritas por una llamada posterior a getservbyname(), getservbyport() o getservent(). El puntero devuelto, y los punteros dentro de la estructura,

también podrían invalidarse si el hilo
que realiza la llamada es terminado.
