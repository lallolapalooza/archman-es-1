NOMBRE

encode_keychange - produce la cadena KeyChange para SNMPv3

SINOPSIS

encode_keychange -t md5|sha1 [OPCIONES]

DESCRIPCIÓN

encode_keychange produce una cadena KeyChange utilizando las contraseñas antigua y nueva tal como se describe en la Sección 5 de RFC 2274 "User-based Security Model (USM) for version 3 of the Simple Network Management Protocol (SNMPv3)". La opción -t es obligatoria y especifica el tipo de transformación hash a utilizar.

La transformación se utiliza para convertir la contraseña en la clave maestra para un usuario determinado (Ku), convertir la clave maestra en la clave localizada (Kul), y para aplicar hash a la Kul antigua con los bits aleatorios.

Las contraseñas se obtienen examinando una serie de fuentes hasta tener éxito (en el orden indicado):

opciones de línea de comandos (ver opciones -N y -O abajo);
el archivo $HOME/.snmp/passphrase.ek que solo debe contener dos líneas con la contraseña antigua y la nueva;
entrada estándar o entrada del usuario desde la terminal.

OPCIONES

-E [0x]<engineID> EngineID utilizada para la generación de Kul.
<engineID> se interpreta como una cadena hexadecimal cuando va precedida por 0x, de lo contrario se trata como una cadena de texto. Si no se especifica ningún <engineID>, se construye a partir de la primera dirección IP del host local.
-f
Forzar la lectura de contraseñas desde la entrada estándar.
-h
Mostrar el mensaje de ayuda.
-N "<nueva_contraseña>"
Contraseña utilizada para generar la nueva Ku.
-O "<antigua_contraseña>"
Contraseña utilizada para generar la antigua Ku.
-P
Desactivar el aviso para solicitar contraseñas al obtener datos de la entrada estándar.
-v
Ser verboso.
-V
Eco de las contraseñas en la terminal.

VER TAMBIÉN

El método de clave localizada se define en RFC 2274, Secciones 2.6 y A.2, y se documentó originalmente en

U. Blumenthal, N. C. Hien, B. Wijnen, "Key Derivation for Network Management Applications", IEEE Network Magazine, número de abril/mayo, 1997.
