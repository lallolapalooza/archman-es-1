TSS2_RC Esys_ContextLoad (ESYS_CONTEXT * esysContext, const TPMS_CONTEXT * context, ESYS_TR * loadedHandle)

Función de llamada única para TPM2_ContextLoad

Esta función invoca el comando TPM2_ContextLoad en una variante de llamada única. Esto significa que la función se bloqueará hasta que la respuesta del TPM esté disponible. Todos los parámetros de entrada son const. La memoria para parámetros de salida no simples es asignada por la implementación de la función.

Parámetros

esysContext El ESYS_CONTEXT.
context El blob de contexto.
loadedHandle Handle ESYS_TR del recurso ESYS para TPMI_DH_CONTEXT.

Valores de retorno

TSS2_RC_SUCCESS si la llamada a la función fue un éxito.
TSS2_ESYS_RC_BAD_REFERENCE si esysContext o los punteros de entrada requeridos o las referencias de handle de salida requeridas son NULL.
TSS2_ESYS_RC_BAD_CONTEXT si se detecta corrupción en esysContext.
TSS2_ESYS_RC_MEMORY si ESAPI no puede asignar suficiente memoria para operaciones internas o parámetros de retorno.
TSS2_ESYS_RC_BAD_SEQUENCE si el contexto ya tiene una operación asíncrona pendiente.
TSS2_ESYS_RC_INSUFFICIENT_RESPONSE si la respuesta del TPM no contiene al menos la etiqueta, la longitud de la respuesta y el código de respuesta.
TSS2_ESYS_RC_MALFORMED_RESPONSE si la respuesta del TPM está corrupta.
TSS2_ESYS_RC_RSP_AUTH_FAILED si el HMAC de respuesta del TPM no se verificó.
TSS2_RCs producidos por capas inferiores de la pila de software pueden ser devueltos al llamador sin modificar, a menos que se manejen internamente.

TSS2_RC Esys_ContextLoad_Async (ESYS_CONTEXT * esysContext, const TPMS_CONTEXT * context)

Función asíncrona para TPM2_ContextLoad

Esta función invoca el comando TPM2_ContextLoad en una variante asíncrona. Esto significa que la función devolverá tan pronto como el comando haya sido enviado hacia abajo en la pila al TPM. Todos los parámetros de entrada son const. Para recuperar la respuesta del TPM, llame a Esys_ContextLoad_Finish.

Parámetros

esysContext El ESYS_CONTEXT.
context El blob de contexto.

Valores de retorno

ESYS_RC_SUCCESS si la llamada a la función fue un éxito.
TSS2_ESYS_RC_BAD_REFERENCE si esysContext o los punteros de entrada requeridos o las referencias de handle de salida requeridas son NULL.
TSS2_ESYS_RC_BAD_CONTEXT si se detecta corrupción en esysContext.
TSS2_ESYS_RC_MEMORY si ESAPI no puede asignar suficiente memoria para operaciones internas o parámetros de retorno.
TSS2_RCs producidos por capas inferiores de la pila de software pueden ser devueltos al llamador sin modificar, a menos que se manejen internamente.

TSS2_RC Esys_ContextLoad_Finish (ESYS_CONTEXT * esysContext, ESYS_TR * loadedHandle)

Función asíncrona de finalización para TPM2_ContextLoad

Esta función devuelve los resultados de un comando TPM2_ContextLoad invocado a través de Esys_ContextLoad_Finish. Todos los parámetros de salida no simples son asignados por la implementación de la función. NULL puede ser pasado para cada parámetro de salida si el valor no es requerido.

Parámetros

esysContext El ESYS_CONTEXT.
loadedHandle Handle ESYS_TR del recurso ESYS para TPMI_DH_CONTEXT.

Valores de retorno

TSS2_RC_SUCCESS en caso de éxito
ESYS_RC_SUCCESS si la llamada a la función fue un éxito.
TSS2_ESYS_RC_BAD_REFERENCE si esysContext o los punteros de entrada requeridos o las referencias de handle de salida requeridas son NULL.
TSS2_ESYS_RC_BAD_CONTEXT si se detecta corrupción en esysContext.
TSS2_ESYS_RC_MEMORY si ESAPI no puede asignar suficiente memoria para operaciones internas o parámetros de retorno.
TSS2_ESYS_RC_BAD_SEQUENCE si el contexto ya tiene una operación asíncrona pendiente.
TSS2_ESYS_RC_TRY_AGAIN si el contador de tiempo de espera expira antes de que se reciba la respuesta del TPM.
TSS2_ESYS_RC_INSUFFICIENT_RESPONSE si la respuesta del TPM no contiene al menos la etiqueta, la longitud de la respuesta y el código de respuesta.
TSS2_ESYS_RC_RSP_AUTH_FAILED si el HMAC de respuesta del TPM no se verificó.
TSS2_ESYS_RC_MALFORMED_RESPONSE si la respuesta del TPM está corrupta.
TSS2_RCs producidos por capas inferiores de la pila de software pueden ser devueltos al llamador sin modificar, a menos que se manejen internamente.
