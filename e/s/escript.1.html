escript proporciona soporte para ejecutar programas cortos en Erlang sin tener que compilarlos primero, y una manera fácil de recuperar los argumentos de la línea de comandos. Los escripts se crean ya sea escribiéndolos a mano o utilizando escript:cre

El resto del archivo de script de Erlang puede contener código fuente de Erlang, un archivo beam en línea, o un archivo de archivo (archive) en línea. Un archivo de script de Erlang siempr

e debe contener la

función main/1. Cuando se ejecuta el script, la función main/1 se llama con una lista de cadenas que representan los argumentos especificados para el script (no modificados ni interpretados de ninguna manera)

.

Si la función main/1 en el script retorna exitosamente, el estado de salida para el script es 0. Si se genera una excepción durante la ejecución, se imprime un mensaje corto y el script termina con el estado de salida 127

.

Para retornar tu propio código de salida distinto de cero, llama a halt(ExitCode), por

ejemplo:

Para recuperar la ruta del archivo del script, llama a escript:script_name/0 desde tu script (la ruta es usualmente, pero no siempre, absoluta)

Si el archivo contiene código fuente (como en el ejemplo anterior), es procesado por el preprocesador epp. Esto significa que puedes, por ejemplo, usar macros predefinidas (como ?MODULE) y directivas de inclusión como la directiva -include_lib. Por ejemplo,

prioridad.

El script se verifica para asegurar su corrección sintáctica y semántica antes de ser ejecutado. Si hay advertencias (como variables sin usar), estas se imprimen y el script se ejecutará de todos modos. Si hay errores, se imprimen y el script no se ejecutará y su estado de salida es 127

.

Tanto la declaración del módulo como la declaración de exportación de la función main/1 son

opcionales.

Por defecto, el script será compilado por el compilador de

Erlang.

script:

La ejecución de código interpretado es más lenta que el código compilado, y algunas construcciones del lenguaje no funcionarán, pero no hay requisito de que la aplicación del compilador de Erlang esté

disponible.

CAMBIO: Antes de Erlang/OTP 27, el script era interpretado por

defecto.

Escripts

precompilados

Un script también puede contener código beam precompilado. Para crear un escript precompilado se recomienda que uses escript:create/2. En un script precompilado, la interpretación de la cabecera del script es la misma que en un script que contiene código fuente. Esto significa que puedes hacer que un archivo beam sea ejecutable anteponiendo al archivo las líneas que comienzan con #! y %%! mencionadas anteriormente. En un script precompilado, la función main/1 debe ser

exportada.

Otra opción es tener un archivo de archivo (archive) de Erlang completo en el script. En un script de archivo, la interpretación de la cabecera del script es la misma que en un script que contiene código fuente. Esto significa que puedes hacer que un archivo de archivo sea ejecutable anteponiendo al archivo las líneas que comienzan con #! y %%! mencionadas anteriormente. En un script de archivo, la función main/1 debe ser exportada. Por defecto, se invoca la función main/1 en el módulo con el mismo nombre que el nombre base del archivo escript. Este comportamiento se puede anular estableciendo el indicador -escript main Module como uno de los indicadores del emulador. Module debe ser el nombre de un módulo que tenga una función main/1 exportada. Para más información sobre archivos y carga de código, vea escript y code

.

A menudo es muy conveniente tener una cabecera en el escript, especialmente en las plataformas Unix. Sin embargo, la cabecera es opcional, así que puedes "ejecutar" directamente un módulo de Erlang, un archivo Beam, o un archivo de archivo sin añadirles ninguna cabecera. Pero entonces tienes que invocar el script de la siguiente

manera: 
$ escript factorial.erl 5
factorial 5 = 120 $ escript
factorial.beam 5 factoria
l 5 = 120 $ escript factori
al.zip 5 factorial 5 = 120

Empaquetado de

escripts

Es posible empaquetar escript(s) con un sistema de tiempo de ejecución de Erlang para hacerlo autosuficiente y reubicable. En un sistema independiente como este, los escript(s) deberían ubicarse en el directorio superior bin del sistema independiente y tener la extensión de archivo .escript. Además, el programa escript (integrado) debería copiarse al mismo directorio y recibir el nombre original del script (sin la extensión .escript). Esto permitirá el uso del sistema de tiempo de ejecución de Erlang

empaquetado.

El programa escript (integrado) primero determina quésistema a utilizar y luego lo inicia para ejecutar su script. Normalmente, el sistema de tiempo de ejecución se encuentra en la misma instalación de Erlang que el programa escript en sí. Pero para sistemas independientes con uno o más escripts, es posible que el programa escript en su ruta de búsqueda inicie en realidad el sistema de tiempo de ejecución incluido con el escript. Esto es intencional y típicamente ocurre cuando el sistema independiente bin no está en la ruta de ejecución (ya que podría hacer que su erl programe anule el deseado) y los escript(s) se referencian mediante enlaces simbólicos desde un bin en l

a r
uta.

Opciones Aceptadas por

escript

-

c
Compila el escript independientemente del valor del atributo
mode.

-

d
Depura el escript. Inicia el depurador, carga el módulo que contiene la función main/1 en el depurador, establece un punto de interrupción en main/1 e invoca main/1. Si el módulo está precompilado, debe compilarse explícitamente con la opción debug_info
.

-

i
Interpreta el escript independientemente del valor del atributo
mode.

-

s
Realiza una verificación sintáctica y semántica del archivo de script. Las advertencias y errores (si los hay) se escriben en la salida estándar, pero el script no se ejecutará. El estado de salida es 0 si se encuentran errores, de lo contrario 127
.
