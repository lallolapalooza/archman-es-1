NOMBRE

buildah-config - Actualiza la configuración de la imagen.

SINOPSIS

buildah config [opciones] contenedor

DESCRIPCIÓN

Actualiza una o más de las configuraciones guardadas para un contenedor.

OPCIONES

--add-history

Añade una entrada al historial de la imagen que anotará los cambios en la configuración para --cmd, --entrypoint, --env, --healthcheck, --label, --onbuild, --port, --shell, --stop-signal, --user, --volumey --workingdir. Por defecto es false.

Nota: También puedes anular el valor por defecto de --add-history estableciendo la variable de entorno BUILDAH_HISTORY. export BUILDAH_HISTORY=true

--annotation, -a anotación=anotación

Añade una anotación de imagen (p. ej. anotación=anotación) al manifiesto de la imagen de cualquier imagen que se construya usando el contenedor especificado. Puede usarse varias veces. Si anotación tiene un -final, entonces la anotación se elimina de la configuración. Si la anotación se establece en "-", entonces todas las anotaciones se eliminan de la configuración.

--arch arquitectura

Establece la arquitectura de destino para cualquier imagen que se construya usando el contenedor especificado. Por defecto, si el contenedor se basaba en una imagen, se mantiene la arquitectura de destino de esa imagen; de lo contrario, se registra la arquitectura del host.

--author autor

Establece la información de contacto del autor para cualquier imagen que se construya usando el contenedor especificado.

--cmd comando

Establece el comando predeterminado a ejecutar para los contenedores basados en cualquier imagen que se construya usando el contenedor especificado. Cuando se usa en combinación con un punto de entrada, esto especifica los parámetros predeterminados para el punto de entrada.

--comment comentario

Establece el comentario a nivel de imagen para cualquier imagen que se construya usando el contenedor especificado.

Nota: esta configuración no está presente en el formato de imagen OCIv1, por lo que se descarta al escribir imágenes usando formatos OCIv1.

--created-by creado

Establece la descripción de cómo se creó la capa más superior para cualquier imagen que se cree usando el contenedor especificado.

--domainname dominio

Establece el nombre de dominio (domainname) a configurar al ejecutar contenedores basados en cualquier imagen construida usando el contenedor especificado.

Nota: esta configuración no está presente en el formato de imagen OCIv1, por lo que se descarta al escribir imágenes usando formatos OCIv1.

--entrypoint "comando" | '["comando", "arg1", ...]'

Establece el punto de entrada para los contenedores basados en cualquier imagen que se construya usando el contenedor especificado. buildah soporta dos formatos para el punto de entrada. Puede especificarse como una cadena simple, o como una matriz de comandos.

Nota: Cuando el punto de entrada se especifica como una cadena, los tiempos de ejecución (runtimes) de contenedores ignorarán el valor cmd de la imagen del contenedor. Sin embargo, si usas la forma de matriz, el cmd se añadirá al final del cmd del punto de entrada y se ejecutará junto con él.

Nota: La forma de cadena se añade al comando sh -c como el punto de entrada. La forma de matriz reemplaza el punto de entrada por completo.

Formato de Cadena:

$ buildah from scratch
$ buildah config --entrypoint "/usr/bin/notashell" working-container
$ buildah inspect --format '{{ .OCIv1.Config.Entrypoint }}' working-container
[/bin/sh -c /usr/bin/notshell]
$ buildah inspect --format '{{ .Docker.Config.Entrypoint }}' working-container
[/bin/sh -c /usr/bin/notshell]

Formato de Matriz:

$ buildah config --entrypoint '["/usr/bin/notashell"]' working-container
$ buildah inspect --format '{{ .OCIv1.Config.Entrypoint }}' working-container
[/usr/bin/notashell]
$ buildah inspect --format '{{ .Docker.Config.Entrypoint }}' working-container
[/usr/bin/notashell]

--env, -e env[=valor]

Añade un valor (p. ej. env=valor) al entorno para los contenedores basados en cualquier imagen que se construya usando el contenedor especificado. Puede usarse varias veces. Si env se nombra pero no se especifica ni = ni un valor , entonces el valor se tomará del entorno del proceso actual. Si env tiene un -final, entonces la env se elimina de la configuración. Si env se establece en "-" entonces todas las variables de entorno se eliminan de la configuración.

--healthcheck comando

Especifica un comando que debe ejecutarse para comprobar si un contenedor está funcionando correctamente.

Los valores pueden ser NONE, "CMD ..." (ejecuta el comando especificado directamente), o "CMD-SHELL ..." (ejecuta el comando especificado usando el shell del sistema), o el valor vacío (elimina un valor establecido previamente y la configuración relacionada).

Nota: esta configuración no está presente en el formato de imagen OCIv1, por lo que se descarta al escribir imágenes usando formatos OCIv1.

--healthcheck-interval intervalo

Especifica con qué frecuencia debe ejecutarse el comando especificado usando la opción --healthcheck .

Nota: esta configuración no está presente en el formato de imagen OCIv1, por lo que se descarta al escribir imágenes usando formatos OCIv1.

--healthcheck-retries cuenta

Especifica cuántas veces puede fallar el comando especificado usando la opción --healthcheck antes de que el contenedor se considere no saludable.

Nota: esta configuración no está presente en el formato de imagen OCIv1, por lo que se descarta al escribir imágenes usando formatos OCIv1.

--healthcheck-start-interval intervalo

Especifica el tiempo entre comprobaciones de salud durante el período de inicio.

Nota: esta configuración no está presente en el formato de imagen OCIv1, por lo que se descarta al escribir imágenes usando formatos OCIv1.

--healthcheck-start-period intervalo

Especifica cuánto tiempo puede transcurrir después de que un contenedor haya iniciado antes de que un fallo al ejecutar el comando especificado usando la opción --healthcheck deba tratarse como una indicación de que el contenedor está fallando. Durante este período de tiempo, los fallos se atribuirán a que el contenedor aún no ha iniciado completamente y no se contarán como errores. Después de que el comando tenga éxito, o de que haya transcurrido el período de tiempo, los fallos se contarán como errores.

Nota: esta configuración no está presente en el formato de imagen OCIv1, por lo que se descarta al escribir imágenes usando formatos OCIv1.

--healthcheck-timeout intervalo

Especifica cuánto tiempo esperar después de iniciar el comando especificado usando la opción --healthcheck a que el comando devuelva su estado de salida. Si el comando no ha devuelto nada dentro de este tiempo, debe considerarse que ha fallado.

Nota: esta configuración no está presente en el formato de imagen OCIv1, por lo que se descarta al escribir imágenes usando formatos OCIv1.

--history-comment comentario

Establece un comentario en la capa más superior de cualquier imagen que se cree usando el contenedor especificado.

--hostname host

Establece el nombre de host (hostname) a configurar al ejecutar contenedores basados en cualquier imagen construida usando el contenedor especificado.

Nota: esta configuración no está presente en el formato de imagen OCIv1, por lo que se descarta al escribir imágenes usando formatos OCIv1.

--label, -l etiqueta=valor

Añade una etiqueta de imagen (p. ej. etiqueta=valor) a la configuración de la imagen de cualquier imagen que se construya usando el contenedor especificado. Puede usarse varias veces. Si etiqueta tiene un -final, entonces la etiqueta se elimina de la configuración. Si la etiqueta se establece en "-" entonces todas las etiquetas se eliminan de la configuración.

--onbuild comando onbuild

Añade un comando ONBUILD a la imagen. Los comandos ONBUILD se ejecutan automáticamente cuando se construyen imágenes basadas en la imagen que estás creando.

Nota: esta configuración no está presente en el formato de imagen OCIv1, por lo que se descarta al escribir imágenes usando formatos OCIv1.

--os sistema operativo

Establece el sistema operativo de destino para cualquier imagen que se construya usando el contenedor especificado. Por defecto, si el contenedor se basaba en una imagen, se mantiene su SO; de lo contrario, se registra el nombre del SO del host.

--os-feature feature

Establece el nombre de una característica requerida del sistema operativo feature para cualquier imagen que se construya usando el contenedor especificado. De forma predeterminada, si el contenedor se basaba en una imagen, se conserva la lista de características del sistema operativo requeridas de la imagen base, si especificaba alguna. Esta opción normalmente solo tiene sentido cuando el sistema operativo de la imagen es Windows.

Si feature tiene un guion final -, entonces la feature se elimina del conjunto de características requeridas que se enumerarán en la imagen. Si la feature se establece en "-", se elimina la lista completa de características de la configuración.

--os-version version

Establece la versión exacta requerida del sistema operativo version para cualquier imagen que se construya usando el contenedor especificado. De forma predeterminada, si el contenedor se basaba en una imagen, se conserva la versión del sistema operativo requerida de la imagen base, si especificaba alguna. Esta opción normalmente solo tiene sentido cuando el sistema operativo de la imagen es Windows, y normalmente se establece en las imágenes base de Windows, por lo que usar esta opción generalmente es innecesario.

--port, -p port/protocol

Añade un puerto que exponer al ejecutar contenedores basados en cualquier imagen que se construya usando el contenedor especificado. Se puede usar varias veces. Para especificar si el puerto escucha en TCP o UDP, usa "port/protocol". El valor predeterminado es TCP si el protocolo no está especificado. Para exponer el puerto tanto en TCP como en UDP, especifica la opción de puerto varias veces. Si port tiene un guion final - y ya está establecido, entonces el port se elimina de la configuración. Si el puerto se establece en - entonces se eliminan todos los ajustes de puertos expuestos de la configuración.

--shell shell

Establece la shell predeterminada que ejecutar dentro de la imagen del contenedor. La instrucción shell permite anular la shell predeterminada usada para la forma shell de comandos. La shell predeterminada para contenedores Linux es "/bin/sh -c".

Nota: este ajuste no está presente en el formato de imagen OCIv1, por lo que se descarta al escribir imágenes usando formatos OCIv1.

--stop-signal signal

Establece la señal de parada predeterminada para el contenedor. Esta señal se enviará cuando el contenedor se detenga, el valor predeterminado es SIGINT.

--unsetannotation annotation

Desestablece la anotación de la imagen, haciendo que la anotación no se herede de la imagen base.

--unsetlabel label

Desestablece la etiqueta de la imagen, haciendo que la etiqueta no se herede de la imagen base.

--user, -u user[:group]

Establece el usuario predeterminado que usar al ejecutar contenedores basados en esta imagen. El usuario se puede especificar como un nombre de usuario o UID, seguido opcionalmente por un nombre de grupo o GID, separados por dos puntos (':'). Si se usan nombres, el contenedor debería incluir entradas para esos nombres en sus /etc/passwd y /etc/group archivos.

--variant variant

Establece la variante de la arquitectura de destino para cualquier imagen que se construya usando el contenedor especificado. De forma predeterminada, si el contenedor se basaba en una imagen, se conserva la información de la arquitectura y variante de destino de esa imagen; de lo contrario, se registran la arquitectura y variante del host.

--volume, -v volume

Añade una ubicación en el árbol de directorios que debería marcarse como un volumen en cualquier imagen que se construya usando el contenedor especificado. Se puede usar varias veces. Si volume tiene un guion final -, y ya está establecido, entonces el volume se elimina de la configuración. Si el volume se establece en "-" se eliminan todos los volúmenes de la configuración.

--workingdir directory

Establece el directorio de trabajo inicial directory para contenedores basados en imágenes que se construyan usando el contenedor especificado.

EJEMPLO

buildah config --author='Jane Austen' --workingdir='/etc/mycontainers' containerID

buildah config --entrypoint /entrypoint.sh containerID

buildah config --entrypoint '[ "/entrypoint.sh", "dev" ]' containerID

buildah config --env foo=bar --env PATH=$PATH containerID

buildah config --env foo- containerID

buildah config --label Name=Mycontainer --label Version=1.0 containerID

buildah config --label Name- containerID

buildah config --annotation note=myNote containerID

buildah config --annotation note-

buildah config --volume /usr/myvol containerID

buildah config --volume /usr/myvol- containerID

buildah config --port 1234 --port 8080 containerID

buildah config --port 514/tcp --port 514/udp containerID

buildah config --env 1234=5678 containerID

buildah config --env 1234- containerID

buildah config --os-version 10.0.19042.1645 containerID

buildah config --os-feature win32k containerID

buildah config --os-feature win32k- containerID
