DESCRIPCIÓ

N

El comando release gestiona la versión del proyecto durante la publicación. Específicamente, primero cambia la versión de instantánea a la versión de publicación correspondiente en el archivo manifest de cada paquete del proyecto, confirma estos cambios (a menos que se especifique --no-commit), etiqueta esta confirmación (a menos que se especifique --no-tag), y, si se especifica --push, envía los cambios al remoto. A menos que se especifique --no-open, el comando release luego abre el siguiente ciclo de desarrollo cambiando la versión a una instantánea, confirmando estos cambios (a menos que se especifique --no-commit), y, si se especifica --push, los envía al remoto. Tenga en cuenta que confirmar, etiquetar y enviar actualmente solo es compatible para repositorios de proyectos git(1

).

El comando release también se puede usar para publicar una nueva revisión del paquete pasando la opción --revision. En este modo, release incrementa el componente de revisión de la versión actual en el archivo manifest de cada paquete del proyecto, confirma estos cambios (a menos que se especifique --no-commit), etiqueta esta confirmación (a menos que se especifique --no-tag), y, si se especifica --push, envía los cambios al remoto. En este modo, release puede ser instruido opcionalmente para actualizar una etiqueta existente para la versión actual para que apunte a la última revisión (--current-tag=update) o para eliminarla (--current-tag=r

emove).

Al publicar una revisión, se espera que el índice del repositorio del proyecto ya contenga otros cambios, ya que para una revisión todos los cambios asociados, incluidos los de la versión, deben pertenecer a una única confirmación. Alternativamente, una revisión se puede publicar enmendando una o más confirmaciones existentes usando las opciones --amend y --squash. En este caso, el índice aún puede contener cambios adicionales, pero no es necesario que los

contenga.

El comando release también tiene una serie de modos continue que permiten la finalización de pasos que fueron suprimidos previamente con las opciones --no-* en los modos principales anteriores. Estos son --tag, que etiqueta la confirmación de la publicación y, si se especifica --push, también la envía al remoto, así como --open, que realiza la apertura del siguiente ciclo de desarrollo como se describió

anteriormente.

En todos los modos que realizan una confirmación, si el índice del repositorio del proyecto ya contiene otros cambios, entonces el mensaje de confirmación se abre automáticamente para su edición a menos que se especifique --no-edit. La edición del mensaje de confirmación en ausencia de otros cambios se puede solicitar con la opción --edit

.

Normalmente, release opera en todos los paquetes de un proyecto. Si no se especifica un directorio de proyecto, se asume el directorio de trabajo actual y se publican todos los paquetes, incluso si el directorio actual es un directorio de paquete. Sin embargo, si se especifican explícitamente uno o más directorios de paquetes con --directory|-d, entonces release asume que sabe lo que está haciendo y solo publica estos paquetes. Todos los paque

tes que se publican deben tener la misma versi
ón pero pueden tener diferentes revisiones.

indicado:

modo)
