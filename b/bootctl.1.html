OPCIONES

Se entienden las siguientes opciones:

--esp-path=

Ruta a la Partición de Sistema EFI (ESP). Si no se especifica, se comprueban en orden /efi/, /boot/ y /boot/efi/. Se recomienda montar la ESP en /efi/, si es posible.

--boot-path=

Ruta a la partición del cargador de arranque extendido, tal y como se define en la Especificación del Cargador de Arranque[1]. Si no se especifica, se comprueba /boot/. Se recomienda montar la partición del cargador de arranque extendido en /boot/, si es posible.

--root=root

Toma una ruta de directorio como argumento. Todas las rutas serán prefijadas con la ruta alternativa de root dada, incluyendo las rutas de búsqueda de configuración.

Añadido en la versión 252.

--image=image

Toma una ruta a un archivo de imagen de disco o a un nodo de dispositivo de bloque. Si se especifica, todas las operaciones se aplican al sistema de archivos en la imagen de disco indicada. Esta opción es similar a --root=, pero opera sobre sistemas de archivos almacenados en imágenes de disco o dispositivos de bloque. La imagen de disco debe contener o bien solo un sistema de archivos o un conjunto de sistemas de archivos dentro de una tabla de particiones GPT, siguiendo la Especificación de Particiones Detectables[4]. Para más información sobre las imágenes de disco soportadas, véase la opción del mismo nombre de systemd-nspawn(1).

Añadido en la versión 252.

--image-policy=policy

Toma una cadena de política de imagen como argumento, según systemd.image-policy(7). La política se aplica al operar sobre la imagen de disco especificada mediante --image=, véase arriba. Si no se especifica, por defecto es la política "*", es decir, se usan todos los sistemas de archivos reconocidos en la imagen.

--install-source=

Al instalar binarios con --root= o --image=, selecciona de dónde obtenerlos. Toma uno de "auto" (el valor por defecto), "image" o "host". Con "auto", los binarios se tomarán del directorio o imagen especificados, y si no se encuentran, se tomarán del host. Con "image" o "host" no se realizará ninguna búsqueda de respaldo si los binarios no se encuentran en la fuente seleccionada.

Añadido en la versión 252.

-p, --print-esp-path

Esta opción modifica el comportamiento de status. Solo imprime la ruta a la Partición de Sistema EFI (ESP) en la salida estándar y sale.

Añadido en la versión 236.

-x, --print-boot-path

Esta opción modifica el comportamiento de status. Solo imprime la ruta a la partición del cargador de arranque extendido si existe, y la ruta a la ESP en caso contrario, en la salida estándar y sale. Este comando es útil para determinar dónde colocar las entradas del cargador de arranque, ya que se prefieren colocadas en la partición del cargador de arranque extendido si existe, y en la ESP en caso contrario.

Las entradas del Tipo #1 de la Especificación del Cargador de Arranque deben colocarse generalmente en el directorio "$(bootctl -x)/loader/entries/". La existencia de ese directorio también puede usarse como indicación de que el sistema soporta entradas del cargador de arranque. De manera similar, las entradas del Tipo #2 de la Especificación del Cargador de Arranque deben colocarse en el directorio "$(bootctl -x)/EFI/Linux/".

Nótese que esta opción (de manera similar a la opción --print-esp-path mencionada arriba), está disponible independientemente del cargador de arranque usado, es decir, también sin que systemd-boot esté instalado.

Añadido en la versión 242.

Añadido en la versión 257.

-R, --print-root-device

Imprime la ruta al nodo de dispositivo de bloque que respalda el sistema de archivos raíz del SO local. Imprime una ruta como /dev/nvme0n1p5. Si el sistema de archivos raíz está respaldado por dm-crypt/LUKS o dm-verity, se devuelve el dispositivo de bloque subyacente. Si el sistema de archivos raíz está respaldado por múltiples dispositivos de bloque (como soporta btrfs), la operación fallará. Si la opción se especifica dos veces (es decir, -RR) y el dispositivo de bloque descubierto es un dispositivo de partición, se determina e imprime el dispositivo de bloque "completo" al que pertenece (por ejemplo, /dev/nvme0n1). Si el sistema de archivos raíz es "tmpfs" (o un sistema de archivos en memoria similar), se devuelve el dispositivo de bloque que respalda /usr/, si aplica. Si el sistema de archivos raíz es un sistema de archivos de red (por ejemplo, NFS, CIFS), la operación fallará.

--graceful

Ignora el fallo cuando la Partición de Sistema EFI no puede ser encontrada, cuando las variables EFI no pueden ser escritas, o cuando ya está instalado un cargador de arranque diferente o más nuevo. Actualmente solo se aplica a los verbos is-installed, update, random-seed y install . Desde la versión v258, se habilita implícitamente al ejecutarse dentro de un chroot.

Añadido en la versión 251.

--make-entry-directory=yes|no

Controla la creación y el borrado del directorio de entradas del Tipo #1 de la Especificación del Cargador de Arranque[1] en el sistema de archivos que contiene recursos como imágenes del kernel e initrd durante install y remove, respectivamente. El directorio se nombra según el token de entrada, tal y como se especifica con el parámetro --entry-token= descrito más abajo, y se coloca inmediatamente debajo del directorio raíz $BOOT (es decir, debajo del sistema de archivos devuelto por la opción --print-boot-path , véase arriba). Por defecto es "no".

Añadido en la versión 251.

--entry-token=

Controla cómo nombrar e identificar las entradas del cargador de arranque para esta instalación del SO. Se acepta durante instally toma como argumento uno de "auto", "machine-id", "os-id", "os-image-id" o una cadena arbitraria con el prefijo "literal:".

Si se establece en machine-id , las entradas se nombran según el ID de máquina del sistema en ejecución (por ejemplo, "b0e793a9baf14b5fa13ecbe84ff637ac"). Véase machine-id(5) para detalles sobre el concepto y el archivo del ID de máquina.

Si se establece en os-id , las entradas se nombran según el ID del SO del sistema en ejecución, es decir, el campo ID= de os-release(5) (por ejemplo, "fedora"). De manera similar, si se establece en os-image-id , las entradas se nombran según el ID de imagen del SO del sistema en ejecución, es decir, el campo IMAGE_ID= de os-release (por ejemplo, "vendorx-cashier-system").

Si se establece en auto (el valor por defecto), se leerá el archivo /etc/kernel/entry-token si existe, y se usará el valor almacenado. De lo contrario, si el ID de máquina local está inicializado, se usará ese. De lo contrario, se usará IMAGE_ID= de os-release, si está establecido. De lo contrario, se usará ID= de os-release, si está establecido.

A menos que se establezca en "machine-id", o cuando se use --make-entry-directory=yes , la cadena de token seleccionada se escribe en el archivo /etc/kernel/entry-token, para asegurar que se usará para futuras entradas. Este archivo también es leído por kernel-install(8), para identificar bajo qué nombre generar las entradas del cargador de arranque para los kernels recién instalados, o para determinar los nombres de las entradas para eliminar las antiguas.

Usar el ID de máquina para nombrar las entradas es generalmente preferible, sin embargo, hay casos en los que usar los otros identificadores es una buena opción. Específicamente: si los datos de identificación que implica el ID de máquina no deben almacenarse en la partición $BOOT (sin cifrar), o si el ID debe generarse en el primer arranque y no se conoce cuando se preparan las entradas. Nótese que usar el ID de máquina tiene el beneficio de que múltiples instalaciones paralelas del mismo SO pueden coexistir en el mismo medio, y pueden actualizar sus entradas del cargador de arranque de forma independiente. Al usar otro identificador (como el ID del SO o el ID de imagen del SO), instalaciones paralelas del mismo SO intentarían usar el mismo nombre de entrada. Para soportar instalaciones paralelas, el instalador debe usar un token de entrada diferente al añadir una segunda instalación.

--efi-boot-option-description=

Descripción de la entrada añadida a la lista de opciones de arranque del firmware. Por defecto eso "Linux Boot Manager".

Usar el nombre de entrada predeterminado "Linux Boot Manager" es generalmente preferible, ya que solo debe usarse un gestor de arranque instalado en una única partición ESP para arrancar cualquier número de instalaciones del sistema operativo encontradas en los distintos discos instalados en el sistema. Específicamente, las distribuciones no deberían usar esta opción para instalar una entrada con su marca en la lista de opciones de arranque. Sin embargo, en situaciones con múltiples discos, cada uno con su propia partición ESP, puede ser beneficioso facilitar la identificación del gestor de arranque utilizado en el menú de opciones de arranque del

firmware.
