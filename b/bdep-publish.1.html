-a | --forwardDESCRIPCIÓN El comando publish publica los paquetes del proyecto en un repositorio basado en archivos.
Si no se especifica un directorio de proyecto o de paquete, se asume el directorio de trabajo actual. Si no se especifica una configuración, se usan las configuraciones por defecto para preparar las distribuciones del paquete. Si el directorio especificado es un directorio de proyecto, se publican todos los paquetes del proyecto. Véasebdep-projects-configs(1)para detalles sobre cómo especificar proyectos y configuraciones. Para cada paquete especificado, elcomando publish prepara un archivo de paquete y lo envía como parte de la solicitud de envío del paquete a un repositorio basado en archivos. Si el repositorio no se especifica explícitamente con laopción --repository [[68]], los paquetes se

publican
en

cppget.

org

por defecto. Junto con el archivo del paquete, la solicitud de envío especifica la sección del repositorio en la que publicar el paquete, la URL del repositorio de control a usar para la autorización, y el nombre y la dirección de correo electrónico del publicador para el registro. Aunque el uso e interpretación exactos de esta información dependen del repositorio específico, la siguiente semántica se aplica al

enviar a

cppget.org [[73]]. La sección especifica la sección del repositorio deseada en la que publicar el proyecto. Si no se especifica explícitamente con

la

opción --section [[77]], uno de los valores alpha [[79]], beta o

stable

se deriva automáticamente de la versión del paquete. La URL del repositorio de control es una URL de solo lectura y de acceso público a un repositorio de control de versiones (normalmente el mismo que el del proyecto) que se usa para autenticar al publicador como alguien autorizado a publicar bajo este nombre de paquete

(actualmente solo se soporta

git(1) [[86]]). Antes de enviar la solicitud de envío, el comando publish añade la suma de comprobación del archivo del paquete a la rama build2-control del repositorio de control de versiones del proyecto. Al recibir la solicitud de envío, el repositorio de archivo (1) asocia el repositorio de control con el nombre del paquete si es la primera vez que se publica este nombre de paquete, o (2) compara el repositorio de control enviado con el previamente asociado y, si coinciden, consulta la

rama

build2-control para verificar que el remitente está autorizado a publicar este archivo bajo este nombre de

paquete.

A menos que la URL del repositorio de control se especifique con la opción --control [[98]], se derivará automáticamente de la URL "remota" del control de versiones. En el caso de git(1) [[100]], se basará en el valor de

configuración

remote.origin.url a menos que se anule con remote.origin.build2ControlUrl o remote.origin.build2Url [[106]]. El valor especial none para la opción --contro

l

puede usarse para desactivar esta

funcionalidad.

Véase Package Submission (#submit) para detalles sobre el manejo de solicitudes de envío por parte de los repositorios de archivo. Si se especifica la opc

i
ón

--forward [[116]], se usan las configuraciones reenviadas para preparar las distribuciones del paquete. En particular, esto significa que en este modo el proyecto no necesita estar inicializado y todo lo que se requiere es que los directorios de origen del paquete estén configurados para reenviar a una configuración de compilación

fuera de origen (véase
b(1)para detalles sobre configuraciones reenviadas). Esto,
por ejemplo, puede usarse para publicar paquetes que no usan la versión estándar.

ARCHIVOS DE OPCIONES PREDETERMINADAS

Consulte bdep-default-options-files(1) para obtener una descripción general de los archivos de opciones predeterminadas. Para el publish comando, el directorio de inicio de búsqueda es el directorio del proyecto. Se buscan los siguientes archivos de opciones en cada directorio y, si se encuentran, se cargan en el orden indicado:

bdep.options
bdep-publish.options

Las siguientes opciones del comando publish no se pueden especificar en los archivos de opciones predeterminadas:

--directory|-d

ENTORNO

Las variables de entorno BDEP_AUTHOR_NAME y BDEP_AUTHOR_EMAIL se pueden utilizar para especificar el nombre y la dirección de correo electrónico del publicador, respectivamente. Si no están establecidas, el publish comando primero intentará obtener el nombre y el correo electrónico del sistema de control de versiones (si se usa) y luego de las variables de entorno USER y EMAIL , respectivamente. Consulte también las opciones --author-name y --author-email .

ERRORES

Envíe informes de errores a la lista de correo users@build2.org.
