BPFTOOL-NET(8) Manual del Administrador del Sistema BPFTOOL-NET(8)

NOMBRE

bpftool-net - herramienta para la inspección de adjuntos de programas bpf relacionados con la red

SINOPSIS

bpftool [OPCIONES] net COMANDO

OPCIONES := { { -j | --json } [{ -p | --pretty }] | { -d | --debug } }

COMANDOS := { show | list | attach | detach | help }

COMANDOS NET

bpftool net { show | list } [ dev NOMBRE ]
bpftool net attach TIPO_ADJUNTO PROG dev NOMBRE [ overwrite ]
bpftool net detach TIPO_ADJUNTO dev NOMBRE
bpftool net help
PROG := { id ID_PROG | pinned ARCHIVO | tag TAG_PROG | name NOMBRE_PROG }
TIPO_ADJUNTO := { xdp | xdpgeneric | xdpdrv | xdpoffload | tcx_ingress | tcx_egress }

DESCRIPCIÓN

bpftool net { show | list } [ dev NOMBRE ]
Lista los adjuntos de programas bpf en el subsistema de red del kernel.

Actualmente, se implementan adjuntos xdp de controladores de dispositivos, tcx, netkit y adjuntos de clasificadores/acciones tc de estilo antiguo, flow_dissector, así como adjuntos netfilter, es decir, para los tipos de programa BPF_PROG_TYPE_XDP, BPF_PROG_TYPE_SCHED_CLS, BPF_PROG_TYPE_SCHED_ACT, BPF_PROG_TYPE_FLOW_DISSECTOR, BPF_PROG_TYPE_NETFILTER.

Para los programas adjuntos a un cgroup particular, por ejemplo, BPF_PROG_TYPE_CGROUP_SKB, BPF_PROG_TYPE_CGROUP_SOCK, BPF_PROG_TYPE_SOCK_OPS y BPF_PROG_TYPE_CGROUP_SOCK_ADDR, los usuarios pueden usar bpftool cgroup para volcar los adjuntos del cgroup. Para los programas bpf sk_{filter, skb, msg, reuseport} y lwt/seg6, los usuarios deben consultar otras herramientas, por ejemplo, iproute2.

La salida actual comenzará con todos los adjuntos de programas xdp, seguidos de todos los tcx, netkit, luego adjuntos de programas bpf de clases/qdiscs tc, luego flow_dissector y finalmente programas netfilter. Tanto los programas xdp como los programas tcx/netkit/tc se ordenan según el número ifindex. Si se adjuntan varios programas bpf al mismo dispositivo de red a través de tc, el orden será primero todos los programas bpf adjuntos a tcx, netkit, luego clases tc, luego todos los programas bpf adjuntos a qdiscs no clsact, y finalmente todos los programas bpf adjuntos a qdisc raíz y clsact.

bpftool net attach TIPO_ADJUNTO PROG dev NOMBRE [ overwrite ]
Adjunta el programa bpf PROG a la interfaz de red NOMBRE con el tipo especificado por TIPO_ADJUNTO. El programa bpf adjuntado previamente puede ser reemplazado por el comando usado con la opción overwrite. Actualmente, solo se admiten modos relacionados con XDP para TIPO_ADJUNTO.

TIPO_ADJUNTO puede ser: xdp - intenta XDP nativo y recurre a XDP genérico si el controlador de NIC no lo admite; xdpgeneric - XDP genérico. Se ejecuta en el hook XDP genérico cuando el paquete ya entra en la ruta de recepción como skb; xdpdrv - XDP nativo. Se ejecuta en el punto más temprano de la ruta de recepción del controlador; xdpoffload - Descarga XDP. Se ejecuta directamente en la NIC en cada recepción de paquete; tcx_ingress - TCX de entrada. Se ejecuta en el tráfico de red de entrada; tcx_egress - TCX de salida. Se ejecuta en el tráfico de red de salida;

bpftool net detach TIPO_ADJUNTO dev NOMBRE
Desadjunta el programa bpf adjuntado a la interfaz de red NOMBRE con el tipo especificado por TIPO_ADJUNTO. Para desadjuntar el programa bpf, se debe especificar el mismo TIPO_ADJUNTO usado previamente para el adjunto. Actualmente, solo se admiten modos relacionados con XDP para TIPO_ADJUNTO.
bpftool net help
Imprime un mensaje de ayuda corto.

OPCIONES

-h, --help
Imprime un mensaje de ayuda corto (similar a bpftool help).
-V, --version
Imprime el número de versión de bpftool (similar a bpftool version), el número de la versión de libbpf en uso y las características opcionales que se incluyeron cuando se compiló bpftool. Las características opcionales incluyen la vinculación con LLVM o libbfd para proporcionar el desensamblador para programas JITeados (bpftool prog dump jited) y el uso de esqueletos BPF (algunas características como bpftool prog profile o mostrar pids asociados a objetos BPF pueden depender de ello).
-j, --json
Genera salida JSON. Para los comandos que no pueden producir JSON, esta opción no tiene efecto.
-p, --pretty
Genera salida JSON legible por humanos. Implica -j.
-d, --debug
Imprime todos los registros disponibles, incluso información a nivel de depuración. Esto incluye registros de libbpf y del verificador, al intentar cargar programas.
