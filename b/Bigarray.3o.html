Arreglos numéricos grandes y multidimensionales

.

Este módulo implementa arreglos multidimensionales de enteros y números de punto flotante, a partir de ahora denominados 'Bigarrays', para distinguirlos de los arreglos OCaml estándar descritos en Array

.

La implementación permite el intercambio eficiente de grandes arreglos numéricos entre el código OCaml y las bibliotecas numéricas de C o

Fortran.

Las principales diferencias entre 'Bigarrays' y los arreglos OCaml estándar son las

siguientes:

-Los Bigarrays no tienen límite de tamaño, a diferencia de los arreglos OCaml. (Los arreglos de flotantes normales están limitados a 2,097,151 elementos en una plataforma de 32 bits, y los arreglos normales de otros tipos a 4,194,303 elementos.

)

-Los Bigarrays son multidimensionales. Se admiten cualquier número de dimensiones entre 0 y 16. En cambio, los arreglos OCaml son monodimensionales y requieren codificar arreglos multidimensionales como arreglos de

arreglos.

-Los Bigarrays solo pueden contener enteros y números de punto flotante, mientras que los arreglos OCaml pueden contener tipos de datos OCaml

arbitrarios.

-Los Bigarrays proporcionan un almacenamiento más eficiente en espacio de elementos enteros y de punto flotante que los arreglos OCaml normales, en particular porque admiten tipos 'pequeños' como flotantes de precisión simple y enteros de 8 y 16 bits, además de los tipos OCaml estándar de flotantes de doble precisión y enteros de 32 y 64

bits.

-La disposición en memoria de los Bigarrays es totalmente compatible con la de los arreglos en C y Fortran, lo que permite pasar grandes arreglos de ida y vuelta entre el código OCaml y el código C / Fortran sin copiar datos en

absoluto.

-Los Bigarrays admiten operaciones de alto nivel interesantes que los arreglos normales no proporcionan eficientemente, como extraer subarreglos y 'rebanar' un arreglo multidimensional a lo largo de ciertas dimensiones, todo sin ninguna

copia.

Se anima a los usuarios de este módulo a hacer open Bigarray en su código fuente, y luego referirse a los tipos y operaciones de arreglos mediante la notación corta con punto, por ejemplo Array1.t o Array2.sub

.

Los Bigarrays admiten todas las operaciones polimórficas ad-hoc de

OCaml:

-comparaciones ( = , <> , <= , etc, así como compare )

;

-hashing (módulo Hash )

;

-y entrada/salida estructurada (las funciones del módulo Marshal, así como output_value y input_value )

.

Tipos de

elementos

Los Bigarrays pueden contener elementos de los siguientes

tipos:

-números de punto flotante de precisión media IEEE (16 bits) ( Bigarray.float16_elt )

,

-números de punto flotante de precisión simple IEEE (32 bits) ( Bigarray.float32_elt )

,

-números de punto flotante de precisión doble IEEE (64 bits) ( Bigarray.float64_elt )

,

-números complejos de punto flotante de precisión simple IEEE (2 * 32 bits) ( Bigarray.complex32_elt )

,

-números complejos de punto flotante de precisión doble IEEE (2 * 64 bits) ( Bigarray.complex64_elt )

,

-enteros de 8 bits (con signo o sin signo) ( Bigarray.int8_signed_elt o Bigarray.int8_unsigned_elt )

,

-enteros de 16 bits (con signo o sin signo) ( Bigarray.int16_signed_elt o Bigarray.int16_unsigned_elt )

,

-enteros OCaml (con signo, 31 bits en arquitecturas de 32 bits, 63 bits en arquitecturas de 64 bits) ( Bigarray.int_elt )

,

-enteros con signo de 32 bits ( Bigarray.int32_elt )

,

-enteros con signo de 64 bits ( Bigarray.int64_elt )

,

-enteros con signo nativos de la plataforma (32 bits en arquitecturas de 32 bits, 64 bits en arquitecturas de 64 bits) ( Bigarray.nativeint_elt )

.

Cada tipo de elemento se representa en el nivel de tipos por uno de los tipos *_elt definidos a continuación (definidos con un solo constructor en lugar de tipos abstractos por razones técnicas de inyectividad)

.

A cada tipo de elemento se le asocia un tipo OCaml, que es el tipo de valores OCaml que se pueden almacenar en el Bigarray o leer de él. Este tipo no es necesariamente el mismo que el tipo de los elementos del arreglo en sí: por ejemplo, un Bigarray cuyos elementos son de tipo float32_elt contiene flotantes de precisión simple de 32 bits, pero leer o escribir uno de sus elementos desde OCaml usa el tipo OCaml float , que son flotantes de precisión doble de 64

bits.

El tipo GADT ('a, 'b) kind captura esta asociación de un tipo OCaml 'a para los valores leídos o escritos en el Bigarray, y de un tipo de elemento 'b que representa el contenido real del Bigarray. Sus constructores listan todas las asociaciones posibles de tipos OCaml con tipos de elementos, y se reexportan a continuación por razones de compatibilidad hacia

atrás.

Usar aquí un tipo de dato algebraico generalizado (GADT) permite escribir funciones polimórficas bien tipadas cuyo tipo de retorno depende del tipo del argumento,

como: 
  let zero : type a b. (a, b) kind -> a = function
    | Float32 -> 0.0 | Complex32 -> Complex.zero
    | Float64 -> 0.0 | Complex64 -> Complex.zero
    | Float16 -> 0.0
    | Int8_signed -> 0 | Int8_unsigned -> 0
    | Int16_signed -> 0 | Int16_unsigned -> 0
    | Int32 -> 0l | Int64 -> 0L
    | Int -> 0 | Nativeint -> 0n
    | Char -> '\000'

Como se muestra en los tipos de los valores anteriores, los Bigarrays de tipo float16_elt , float32_elt y float64_elt se acceden utilizando el tipo OCaml float . arrays

Para facilitar la interoperabilidad con el código C y Fortran existente, esta biblioteca admite dos disposiciones de memoria diferentes para Bigarrays, una compatible con las convenciones de C y la otra compatible con las convenciones de

Fortran.

En la disposición estilo C, los índices de array comienzan en 0, y los arrays multidimensionales se disponen en formato de fila mayor. Es decir, para un array bidimensional, todos los elementos de la fila 0 son contiguos en memoria, seguidos de todos los elementos de la fila 1, etc. En otras palabras, los elementos del array en (x,y) y (x, y+1) son adyacentes en

memoria.

En la disposición estilo Fortran, los índices de array comienzan en 1, y los arrays multidimensionales se disponen en formato de columna mayor. Es decir, para un array bidimensional, todos los elementos de la columna 0 son contiguos en memoria, seguidos de todos los elementos de la columna 1, etc. En otras palabras, los elementos del array en (x,y) y (x+1, y) son adyacentes en

memoria.

Cada estilo de disposición se identifica en el nivel de tipo mediante los tipos fantasma Bigarray.c_layout y Bigarray.fortran_layout

respectivamente
.

Reconfiguración de

Bigarrays

val reshape : ('a, 'b, 'c) Genarray.t -> int array -> ('a, 'b, 'c) Genarray.

t

reshape b [|d1;...;dN|] convierte el Bigarray b en un array de N dimensiones con dimensiones d1 ... dN . El array devuelto y el array original b comparten sus datos y tienen la misma disposición. Por ejemplo, asumiendo que b es un array de una dimensión de dimensión 12, reshape b [|3;4|] devuelve un array bidimensional b' de dimensiones 3 y 4. Si b tiene disposición C, el elemento (x,y) de b' corresponde al elemento x * 3 + y de b . Si b tiene disposición Fortran, el elemento (x,y) de b' corresponde al elemento x + (y - 1) * 4 de b . El Bigarray devuelto debe tener exactamente el mismo número de elementos que el Bigarray original b . Es decir, el producto de las dimensiones de b debe ser igual a i1 * ... * iN . De lo contrario, se lanza Invalid_argument

.

Bigarrays y seguridad de

concurrencia

Se debe tener cuidado al acceder a bigarrays concurrentemente desde múltiples dominio

s: acceder a un bigarray nunca hará que un programa se bloquee, pero los accesos no s
incronizados podrían producir resultados sorprendentes (no consistentes secuencialmente).

Atomicida

d

Toda operación de bigarray que accede a más de un elemento de array no es atómica. Esto incluye el slicing, el bliting y el relleno de

bigarrays.

Por ejemplo, considere el siguiente

programa: 
open Bigarray
let size = 100_000_000
let a = Array1.init Int C_layout size (fun _ -> 1)
let update f a () =
  for i = 0 to size - 1 do a.{i} <- f a.{i} done
let d1 = Domain.spawn (update (fun x -> x + 1) a)
let d2 = Domain.spawn (update (fun x -> 2 * x + 1) a)
let () = Domain.join d1; Domain.join d2

Después de ejecutar este código, ecampo del bigarray a es o bien 2 , 3 , 4 o 5 . Si se requiere atomicidad, entonces el usuario debe implementar su propia sincronización (por ejemplo, usando Mutex.t

)
.

Carreras de

datos

Si dos dominios solo acceden a partes disjuntas del bigarray, entonces el comportamiento observado es equivalente a alguna intercalación secuencial de las operaciones de los dos

dominios.

Se dice que ocurre una carrera de datos cuando dos dominios acceden al mismo elemento del bigarray sin sincronización y al menos uno de los accesos es una escritura. En ausencia de carreras de datos, el comportamiento observado es equivalente a alguna intercalación secuencial de las operaciones de diferentes

dominios.

Siempre que sea posible, las carreras de datos deben evitarse utilizando sincronización para mediar los accesos a los elementos del

bigarray.

De hecho, en presencia de carreras de datos, los programas no se bloq

uearán, pero el comportamiento observado puede no ser equivalente a ni
nguna intercalación secuencial de operaciones de diferentes dominios.

Desgarro

(Tearing)

Los bigarrays tienen una advertencia distintiva en presencia de carreras de datos: las operaciones concurrentes en bigarrays pueden producir valores sorprendentes debido al desgarro (tearing). Más precisamente, la intercalación de escrituras y lecturas parciales podría crear valores que no existirían con una ejecución secuencial. Por ejemplo, al final

de 
let res = Array1.init Complex64 c_layout size (fun _ -> Complex.zero)
let d1 = Domain.spawn (fun () -> Array1.fill res Complex.one)
let d2 = Domain.spawn (fun () -> Array1.fill res Complex.i)
let () = Domain.join d1; Domain.join d2

el bigarray res podría contener valores que no son ni Complex.i ni Complex.one (por ejemplo 1 +

i
)
