NOMBRE

Bit::Vector::String - Importación/exportación de cadenas genéricas para Bit::Vector

SINOPSIS

use Bit::Vector::String;
to_Oct
    $string = $vector->to_Oct();
from_Oct
    $vector->from_Oct($string);
new_Oct
    $vector = Bit::Vector->new_Oct($bits,$string);
String_Export
    $string = $vector->String_Export($type);
String_Import
    $type = $vector->String_Import($string);
new_String
    $vector = Bit::Vector->new_String($bits,$string);
    ($vector,$type) = Bit::Vector->new_String($bits,$string);

DESCRIPCIÓN

  • "$string = $vector->to_Oct();"

    Devuelve una cadena octal que representa el vector de bits dado.

    Tenga en cuenta que este método no es particularmente eficiente, ya que está casi completamente realizado en Perl, y además opera internamente sobre una lista de Perl de dígitos octales individuales que concatena en la cadena final usando ""join('', ...)"".

    Un benchmark revela que este método es unas 40 veces más lento que el método "to_Bin()" (que está realizado en C):

    Benchmark: timing 10000 iterations of to_Bin, to_Hex, to_Oct...
    to_Bin:  1 wallclock secs ( 1.09 usr +  0.00 sys =  1.09 CPU)
    to_Hex:  1 wallclock secs ( 0.53 usr +  0.00 sys =  0.53 CPU)
    to_Oct: 40 wallclock secs (40.16 usr +  0.05 sys = 40.21 CPU)

    Tenga en cuenta que, dado que un dígito octal siempre equivale a tres bits, la longitud de la cadena resultante siempre es un múltiplo de tres bits, independientemente de la longitud real (en bits) del vector de bits dado.

    Tenga en cuenta también que el dígito octal MENOS significativo se encuentra en el extremo DERECHO de la cadena resultante, y el dígito MÁS significativo en el extremo IZQUIERDO .

    Finalmente, tenga en cuenta que este método NO antepone ningún prefijo de formato de identificación única (como "0o") a la cadena resultante (lo que significa que el resultado de este método solo contiene dígitos octales válidos, es decir, [0-7]).

    Sin embargo, esto, por supuesto, se puede hacer más fácilmente según sea necesario, de la siguiente manera:

    $string = '0o' . $vector->to_Oct();
  • "$vector->from_Oct($string);"

    Permite leer el contenido de un vector de bits desde una cadena octal, como la devuelta por el método "to_Oct()" (véase arriba).

    Tenga en cuenta que este método no es particularmente eficiente, ya que está casi completamente realizado en Perl, y además trocea la cadena de entrada en caracteres individuales usando ""split(//, $string)"".

    Recuerde también que los bits menos significativos siempre están a la derecha de una cadena octal, y los bits más significativos a la izquierda. Por lo tanto, la cadena se invierte internamente antes de almacenarla en el vector de bits dado usando el método "Chunk_List_Store()", que espera los fragmentos de datos menos significativos al principio de una lista.

    Un benchmark revela que este método es unas 40 veces más lento que el método "from_Bin()" (que está realizado en C):

    Benchmark: timing 10000 iterations of from_Bin, from_Hex, from_Oct...
  from_Bin:  1 wallclock secs ( 1.13 usr +  0.00 sys =  1.13 CPU)
  from_Hex:  1 wallclock secs ( 0.80 usr +  0.00 sys =  0.80 CPU)
  from_Oct: 46 wallclock secs (44.95 usr +  0.00 sys = 44.95 CPU)

    Si la cadena dada contiene algún carácter que no sea un dígito octal (es decir, [0-7]), se produce un error de sintaxis fatal ("unknown string type").

    Tenga en cuenta especialmente que este método NO acepta ningún prefijo de formato de identificación única (como "0o") en la cadena dada; la presencia de dicho prefijo también conducirá al error fatal "unknown string type".

    Si la cadena dada contiene menos dígitos octales de los necesarios para llenar completamente el vector de bits dado, los bits restantes (más significativos) permanecen todos borrados (es decir, establecidos en cero).

    Esto también significa que, incluso si la cadena dada no contiene suficientes dígitos para llenar completamente el vector de bits, los contenidos anteriores del vector de bits se borran completamente.

    Si la cadena dada es más larga de lo necesario para llenar el vector de bits dado, los caracteres superfluos simplemente se ignoran.

    Este comportamiento es intencional para que pueda leer la cadena que representa un vector de bits en otro vector de bits de diferente tamaño, es decir, tanto de ella como que quepa.

  • "$vector = Bit::Vector->new_Oct($bits,$string);"

    Este método es un constructor alternativo que le permite crear un nuevo objeto de vector de bits (con "$bits" bits) e inicializarlo todo de una sola vez.

    El método internamente primero llama al método constructor del vector de bits "new()" y luego almacena la cadena dada en el vector de bits recién creado usando el mismo enfoque que el método "from_Oct()" (descrito arriba).

    Tenga en cuenta que este enfoque no es particularmente eficiente, ya que está casi completamente realizado en Perl, y además trocea la cadena de entrada en caracteres individuales usando ""split(//, $string)"".

    Se lanzará una excepción si no se puede asignar la memoria necesaria (véase la descripción del método "new()" en Bit::Vector(3) para posibles causas) o si la cadena dada no se puede convertir con éxito (véase la descripción del método "from_Oct()" arriba para más detalles).

    Tenga en cuenta especialmente que este método NO acepta ningún prefijo de formato de identificación única (como "0o") en la cadena dada y que tal prefijo conducirá a un error fatal "unknown string type".

    En caso de error, la memoria ocupada por el nuevo vector de bits se libera de nuevo antes de que la excepción se lance realmente.

    Si el número de bits "$bits" dado tiene el valor ""undef"", el método asignará automáticamente un vector de bits con un tamaño (es decir, número de bits) de tres veces la longitud de la cadena dada (ya que cada dígito octal equivale a tres bits).

    Tenga en cuenta que este comportamiento es diferente al de los métodos "new_Hex()", "new_Bin()", "new_Dec()" y "new_Enum()" (que están realizados en C, internamente); estos métodos asumirán silenciosamente un valor de 0 bits si se da ""undef"" (y pueden advertir sobre el "Use of uninitialized value" si las advertencias están habilitadas).

  • "$string = $vector->String_Export($type);"

    Devuelve una cadena que representa el vector de bits dado en el formato especificado por "$type":

    1 | b | bin      =>  binario       (usando "to_Bin()")
2 | o | oct      =>  octal         (usando "to_Oct()")
3 | d | dec      =>  decimal       (usando "to_Dec()")
4 | h | hex | x  =>  hexadecimal   (usando "to_Hex()")
5 | e | enum     =>  enumeración   (usando "to_Enum()")
6 | p | pack     =>  binario empaquetado (usando "Block_Read()")

    El caso (minúsculas/mayúsculas/mixto) de "$type" se ignora.

    Si "$type" se omite o es ""undef"" o falso ("0" o la cadena vacía), se devuelve una cadena hexadecimal como formato predeterminado.

    Si "$type" no tiene ninguno de los valores descritos anteriormente, ocurrirá un error fatal "unknown string type".

    Tenga cuidado de que, para garantizar que las cadenas puedan ser analizadas y leídas correctamente por los métodos "String_Import()" y "new_String()" (descritos más abajo), el método "String_Export() " proporciona prefijos de identificación única (y, en un caso, un sufijo) de la siguiente manera: 1 | b | bin => '0b' . $vector->to_Bin(); 2 | o | oct => '0o' . $vector->to_Oct(); 3 | d | dec => $vector->to_Dec(); # el prefijo es [+-] 4 | h | hex | x => '0x' . $vector->to_Hex(); 5 | e | enum => '{' . $vector->to_Enum() .
