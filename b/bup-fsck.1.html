NOMBRE

bup-fsck - verifica o repara un repositorio bup

SINOPSIS

bup fsck [-r] [-g] [-v] [--quick] [-j jobs] [--par2-ok] [--disable-par2] [archivos...]

DESCRIPCIÓN

bup fsck es una herramienta para validar repositorios bup de la misma manera que git fsck valida repositorios git.

También puede generar y/o usar "bloques de recuperación" usando la herramienta par2(1) (si la tienes instalada). Esto te permite recuperar bloques dañados que cubren hasta el 5% de tus archivos .pack.

En un sistema de copias de seguridad normal, los bloques dañados son menos importantes, porque tiende a haber suficientes datos duplicados entre conjuntos de copias de seguridad, lo que hace que un único conjunto de copias de seguridad dañado no sea crítico. Sin embargo, en un sistema de copias de seguridad que elimina duplicados como bup, ningún bloque se almacena más de una vez, incluso si se utiliza en cada copia de seguridad. Si ese bloque no se pudiera recuperar, ¡*todos* tus conjuntos de copias de seguridad se dañarían a la vez! Por lo tanto, es importante poder verificar la integridad de tus copias de seguridad y recuperarte de errores de disco si ocurren.

*¡ADVERTENCIA!*: Las funciones de recuperación de bup fsck no están disponibles a menos que tengas instalado el paquete gratuito par2(1) en tu servidor bup.

*¡ADVERTENCIA!*: bup fsck obviamente no puede recuperarse de un fallo completo del disco. Si tus copias de seguridad son importantes, necesitas considerar cuidadosamente la redundancia (como usar RAID para redundancia de varios discos, o hacer copias de seguridad externas para redundancia de sitio).

OPCIONES

-r, --repair
intenta reparar cualquier pack dañado utilizando los bloques de recuperación existentes. (Requiere par2(1).)
-g, --generate
genera bloques de recuperación para cualquier pack que aún no los tenga. (Requiere par2(1).)
-v, --verbose
aumenta la verbosidad (se puede usar más de una vez).
--quick
no ejecuta un git verify-pack completo en cada archivo de pack; en su lugar, solo verifica la suma de verificación final. Esto puede suponer una mejora significativa de la velocidad sin una disminución aparente de la fiabilidad. Sin embargo, es posible que desees evitar esta opción si eres paranoico. No tiene ningún efecto en los packs que ya tienen información de recuperación.
-j, --jobs=numjobs
número máximo de verificaciones de packs que se ejecutarán a la vez. El valor óptimo para esta opción depende de la rapidez con la que tu CPU puede verificar los packs frente al rendimiento de tu disco. Si ejecutas demasiados trabajos a la vez, tu disco se saturará al buscar entre archivos y el rendimiento disminuirá, incluso si *numjobs* es inferior al número de núcleos de CPU de tu sistema. Puedes experimentar con esta opción para encontrar el valor óptimo.
--par2-ok
devuelve inmediatamente 0 si par2(1) está instalado y funciona, o 1 en caso contrario. No verifica nada en realidad.
--disable-par2
pretende que par2(1) no está instalado, e ignora todos los bloques de recuperación.

EJEMPLOS

# genera bloques de recuperación para todos los packs que no
# los tengan
bup fsck -g
# genera bloques de recuperación para un pack en particular
bup fsck -g ~/.bup/objects/pack/153a1420cb1c8*.pack
# comprueba todos los packs para ver si son correctos (¡puede ser muy lento!)
bup fsck
# comprueba todos los packs para ver si son correctos y recupera los
# dañados
bup fsck -r
# comprueba un pack en particular para ver si es correcto y lo recupera
# si está dañado
bup fsck -r ~/.bup/objects/pack/153a1420cb1c8*.pack
# comprueba si hay bloques de recuperación disponibles en este sistema
if bup fsck --par2-ok; then
    echo "par2 está bien"
fi
