NOMBRE

binfmt.d - Configurar formatos binarios adicionales para ejecutables al arrancar

SINOPSIS

/etc/binfmt.d/*.conf
/run/binfmt.d/*.conf
/usr/local/lib/binfmt.d/*.conf
/usr/lib/binfmt.d/*.conf

DESCRIPCIÓN

Al arrancar, systemd-binfmt.service(8) lee los archivos de configuración de los directorios anteriores para registrar en el kernel formatos binarios adicionales para ejecutables.

FORMATO DE CONFIGURACIÓN

Cada archivo contiene una lista de reglas de formato binario del kernel binfmt_misc. Consulta el archivo de documentación del kernel Kernel Support for miscellaneous Binary Formats (binfmt_misc)[1] para obtener más información sobre el registro de formatos binarios adicionales y cómo escribir reglas.

Las líneas vacías y las líneas que comienzan con ";" y "#" se ignoran. Ten en cuenta que esto significa que no puedes usar esos símbolos como delimitador en las reglas de formato binario.

DIRECTORIOS DE CONFIGURACIÓN Y PREFERENCIA

Los archivos de configuración se leen de los directorios /etc/, /run/, /usr/local/lib/ y /usr/lib/, en orden de preferencia, como se indica en la sección SINOPSIS anterior. Los archivos deben tener la extensión ".conf". Los archivos en /etc/ tienen prioridad sobre los archivos con el mismo nombre en /run/, /usr/local/lib/ y /usr/lib/. Los archivos en /run/ tienen prioridad sobre los archivos con el mismo nombre en /usr/.

Todos los archivos de configuración se ordenan por su nombre de archivo en orden lexicográfico, independientemente de en qué directorios residan. Si varios archivos especifican la misma opción, la entrada del archivo con el nombre lexicográficamente más reciente tendrá prioridad. Por lo tanto, la configuración de un determinado archivo puede ser reemplazada completamente (colocando un archivo con el mismo nombre en un directorio con mayor prioridad) o se pueden cambiar configuraciones individuales (especificando configuraciones adicionales en un archivo con un nombre diferente que se ordena posteriormente).

Los paquetes deben instalar sus archivos de configuración en /usr/lib/ (paquetes de distribución) o /usr/local/lib/ (instalaciones locales) [2]. Los archivos en /etc/ están reservados para el administrador local, que puede usar esta lógica para anular los archivos de configuración instalados por los paquetes del proveedor.

Se recomienda prefijar todos los nombres de archivo con un número de dos dígitos y un guión para simplificar el orden. Se recomienda usar el rango 10-40 para los archivos de configuración en /usr/ y el rango 60-90 para los archivos de configuración en /etc/ y /run/, para asegurarse de que los archivos de configuración locales y transitorios siempre tengan prioridad sobre los archivos de configuración proporcionados por el proveedor del sistema operativo.

Si el administrador quiere deshabilitar un archivo de configuración proporcionado por el proveedor, la forma recomendada es colocar un enlace simbólico a /dev/null en el directorio de configuración en /etc/, con el mismo nombre de archivo que el archivo de configuración del proveedor. Si el archivo de configuración del proveedor está incluido en la imagen initrd, la imagen tendrá que ser regenerada.

EJEMPLO

Ejemplo 1. Ejemplo de /etc/binfmt.d/wine.conf:

# Inicia WINE en ejecutables de Windows
:DOSWin:M::MZ::/usr/bin/wine:
