Establece el destino SCSI para la grabadora de CD/DVD/BluRay, consulte las notas anteriores. Una especificación de dispositivo de destino típica es dev=1,6,0 . Si se debe proporcionar un nombre de archivo junto con la especificación numérica del destino, el nombre de archivo es específico de la implementación. El nombre de archivo correcto en este caso se puede encontrar en los manuales específicos del sistema del sistema operativo de destino. En un sistema FreeBSD sin soporte de CAM, necesita usar el dispositivo de control (por ejemplo, /dev/rcd0.ctl). Una especificación de dispositivo correcta en este caso puede ser dev=/dev/rcd0.ctl:@ .

Dirección SCSI general
El dispositivo de destino de la opción dev= se refiere al scsibus/target/lun de la grabadora de CD/DVD/BluRay. La comunicación en SunOS se realiza con el controlador general de SCSI scg. Otros sistemas operativos utilizan una simulación por biblioteca de este controlador. La sintaxis posible es: dev= scsibus,target,lun o dev= target,lun. En el último caso, la grabadora de CD/DVD/BluRay tiene que estar conectada al bus SCSI predeterminado de la máquina. Scsibus, target y lun son números enteros. Algunos sistemas operativos o implementaciones de transporte SCSI pueden requerir especificar un nombre de archivo adicional. En este caso, la sintaxis correcta para el dispositivo es: dev= nombre_de_dispositivo:scsibus,target,lun o dev= nombre_de_dispositivo:target,lun. Si el nombre del nodo de dispositivo que se ha especificado en tal sistema se refiere a exactamente un dispositivo SCSI, se puede usar una forma abreviada de la forma dev= nombre_de_dispositivo:@ o dev= nombre_de_dispositivo:@,lun en lugar de dev= nombre_de_dispositivo:scsibus,target,lu

n.

Dirección SCSI remota
Para acceder a dispositivos SCSI remotos, necesita anteponer un indicador de dispositivo remoto al nombre del dispositivo SCSI. El indicador de dispositivo remoto es REMOTE:usuario@host: o REMOTE:host: Un nombre de dispositivo SCSI remoto válido puede ser: REMOTE:usuario@host: para permitir el escaneo remoto del bus SCSI o REMOTE:usuario@host:1,0,0 para acceder al dispositivo SCSI en host conectado al bus SCSI # 1, destino 0, lun 0. Para permitir el acceso remoto a un host específico, el programa rscsi(1) debe estar presente y configurado en el hos

t.

Transportes SCSI alternativos
Las unidades ATAPI son simplemente unidades SCSI que utilizan inherentemente la interfaz de paquetes ATA como capa de transporte de comandos SCSI integrada en el transporte IDE (ATA). Es posible que necesite especificar una capa de transporte alternativa en la línea de comandos si su sistema operativo no implementa un subsistema de controlador de kernel completamente integrado que permita acceder a cualquier unidad usando comandos SCSI a través de una única interfaz de usuario

única.

Para acceder a dispositivos SCSI a través de capas de transporte alternativas, necesita anteponer un indicador de capa de transporte al nombre del dispositivo SCSI. El indicador de capa de transporte puede ser algo como USCSI: o ATAPI:. Para obtener una lista de las capas de transporte admitidas para su plataforma, use dev= HEL

P:

Antecedentes de portabilidad
Para hacer que btcflash sea portable a todas las plataformas UNIX, se prefiere la sintaxis dev= nombre_de_dispositivo:scsibus,target,lun, ya que oculta al usuario el conocimiento específico del sistema operativo sobre los nombres de los dispositivos. Un sistema operativo específico no necesariamente admite una forma de especificar un nombre de archivo de dispositivo real ni una forma de especificar scsibus,target,lu

n.

Scsibus 0 es el bus SCSI predeterminado en la máquina. Observe los mensajes de arranque para obtener más información o consulte /var/adm/messages para obtener más información sobre la configuración de SCSI de su máquina. Si tiene problemas para averiguar qué valores para scsibus,target,lun se deben usar, pruebe la opción -scanbus de btcflash descrita a

continuación.

Uso de nombres lógicos para dispositivos
Si no está presente la opción dev, btcflash intentará obtener el dispositivo desde el entorno CDR_D

EVICE.

Si existe un archivo /etc/default/cdrecord, y si el argumento de la opción dev= o el entorno CDR_DEVICE no contiene los caracteres ',', '/', '@' o ':', se interpreta como un nombre de etiqueta de dispositivo que fue definido en el archivo /etc/default/cdrecord (consulte la sección ARCHIVOS)

.

Establece el valor de tiempo de espera predeterminado del comando SCSI en # segundos. El tiempo de espera predeterminado del comando SCSI es el tiempo de espera mínimo utilizado para enviar comandos SCSI. Si un comando SCSI falla debido a un tiempo de espera, puede intentar aumentar el tiempo de espera predeterminado del comando SCSI por encima del valor de tiempo de espera del comando que falló. Si el comando se ejecuta correctamente con un tiempo de espera de comando aumentado, por favor informe el mejor valor de tiempo de espera y el comando correspondiente al autor del programa. Si no está presente la opción timeout, se usa un tiempo de espera predeterminado de 40
segundos.

Si la variable de entorno RSH está presente, la conexión remota no será creada mediante rcmd(3) sino llamando al programa al que apunta RSH. Utilice, por ejemplo, RSH=/usr/bin/ssh para crear una conexión de shell segura.

Tenga en cuenta que esto obliga a cdrecord a crear una tubería (pipe) hacia el programa rsh(1) e impide que cdrecord acceda directamente al socket de red del servidor remoto. Esto hace imposible configurar parámetros de rendimiento y ralentiza la conexión en comparación con una conexión rcmd(3) iniciada por ro

S

Un mensaje de error típico para un comando SCSI tiene el aspecto

siguiente: 
btcflash: I/O error. test unit ready: scsi sendcmd: no error
CDB:  00 20 00 00 00 00
status: 0x2 (CHECK CONDITION)
Sense Bytes: 70 00 05 00 00 00 00 0A 00 00 00 00 25 00 00 00 00 00
Sense Ke
y: 0x5 Illegal Request, Segment 0 Sense Code: 0x25 Qual 0x00 (logical unit not supported) Fru 0x0 Sense flags: Blk 0 (not valid) cmd finished after 0.002s timeout 40s La primera línea propo
rciona información sobre el transporte del comando. El texto después de los dos puntos es el texto de error para la llamada al sistema desde el punto de vista del kernel. Normalmente es: I/O error a menos que ocurran otros problemas. Las siguientes palabras contienen una breve descripción del comando SCSI que falla. El resto de la línea indica si hubo problemas en el transporte del comando a través del bus SCSI. fatal error significa que no fue posible transportar el comando (es decir, no hay ningún dispositivo presente en la dirección SCSI solicitada).

La segunda línea imprime el bloque de descriptores de comando SCSI del comando

fallido.

La tercera línea proporciona información sobre el código de estado SCSI devuelto por el comando, si el transporte del comando tiene éxito. Esta es información de error del dispositivo

SCSI.

La cuarta línea es un volcado hexadecimal de la información de auto-solicitud de sentido (auto request sense) del

comando.

La quinta línea es el texto de error para la clave de sentido (sense key), si está disponible, seguido del número de segmento que solo es válido si el comando era un comando de copia. Si el mensaje de error no está directamente relacionado con el comando actual, se añade el texto deferred e

rror.

La sexta línea es el texto de error para el código de sentido (sense code) y el calificador de sentido, si están disponibles. Si el tipo de dispositivo es conocido, los datos de sentido se decodifican a partir de tablas en scsierrs.c . El texto va seguido del valor de error para una unidad reemplazable en el campo (field replaceable unit)

.

La séptima línea imprime el número de bloque relacionado con el comando fallido y el texto para varios indicadores de error. El número de bloque puede no ser

válido.

La octava línea informa del tiempo de espera (tim

eout) configurado para este comando y el tiem
po que el comando realmente tardó en completarse.
