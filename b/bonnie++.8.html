DESCRIPCIÓ

N

Esta página del manual documenta brevemente el bonnie++,

programa.

Bonnie++ es un programa para probar el rendimiento de discos duros y sistemas de archivos, o la falta del mismo. Hay muchos tipos diferentes de operaciones de sistema de archivos que las diferentes aplicaciones usan en distintos grados. Bonnie++ prueba algunos de ellos y para cada prueba da un resultado de la cantidad de trabajo realizada por segundo y el porcentaje de tiempo de CPU que esto tomó. Para los resultados de rendimiento, números más altos son mejores; para el uso de CPU y la latencia, números más bajos son mejores (NB una configuración que obtiene un resultado de rendimiento de 2000 y un resultado de CPU del 90% es mejor en términos de uso de CPU que una configuración que ofrece un rendimiento de 1000 y un uso de CPU del 60%)

.

Hay dos secciones en las operaciones del programa. La primera es probar el rendimiento de E/S (IO) de una manera diseñada para simular algunos tipos de aplicaciones de bases de datos. La segunda es probar la creación, lectura y eliminación de muchos archivos pequeños de una manera similar a los patrones de uso de programas como Squid o

INN.

Todos los detalles de las pruebas realizadas por Bonnie++ están contenidos en el archivo /usr/share/d

oc/bonnie++
/readme.html

S

Para Bonnie++ cada opción tiene la forma de un guion seguido de una letra y luego el siguiente parámetro contiene el

valor.
-
d
el directorio a usar para las
pruebas.
-
c
el nivel de concurrencia (por defecto 1). El número de copias de la prueba a realizar al mismo
tiempo.
-
s
el tamaño del archivo(s) para medidas de rendimiento de E/S en megabytes. Si el tamaño es mayor que 1G, se usarán múltiples archivos para almacenar los datos, y cada archivo será de hasta 1G de tamaño. Este parámetro puede incluir el tamaño del bloque (chunk size) separado del tamaño por dos puntos. El tamaño del bloque se mide en bytes y debe ser una potencia de dos desde 256 hasta 1048576, el valor por defecto es 8192. NB Puede especificar el tamaño en gigabytes o el tamaño del bloque en kilobytes si agrega g o k al final del número respectivamente. Este parámetro también puede incluir el número de búsquedas (seeks) (por defecto 8192) y el número de procesos buscadores (seekers) (por defecto 5).

Si el tamaño especi

ficado es 0, esta p
rueba será omitida.
-
n
el número de archivos para la prueba de creación de archivos. Esto se mide en múltiplos de 1024 archivos. Esto es porque nadie querrá probar con menos de 1024 archivos, y necesitamos el espacio extra en las pantallas braille.

Si el número especificado es 0, esta prueba será

omitida.

El valor por defecto para esta prueba es probar con archivos de 0 bytes. Para usar archivos de otros tamaños puede especificar number:max:min:num-directories:chunk-size donde max es el tamaño máximo y min es el tamaño mínimo (ambos por defecto a 0 si no se especifican). Si se especifican los tamaños mínimo y máximo, entonces cada archivo tendrá un tamaño aleatorio del rango min..max inclusive. Si especifica un número de directorios, los archivos se distribuirán uniformemente entre ese número de

subdirectorios.

Si max es -1, se crearán enlaces duros en lugar de archivos. Si max es -2, se crearán enlaces simbó

licos en luga
r de archivos.

nombre de la máquina - solo para fines de
visualización.
-
r
tamaño de la RAM en megabytes. Si especifica esto, los otros parámetros serán verificados para asegurarse de que tengan sentido para una máquina con esa cantidad de RAM. No debería necesitar hacer esto en uso general, ya que debería poder descubrir el tamaño de la RAM. NB Si especifica un tamaño de 0, todas las verificaciones serán deshabilitadas.
..

número de ejecuciones de prueba. Esto es útil si desea realizar más de una prueba. Derramará la salida continuamente en formato CSV hasta que se completen el número de pruebas o sea
terminado.
-

user-id a usar. Al ejecutar como root, especifique el UID a usar para las pruebas. No se recomienda usar root (desde la ocasión en que un bug de Bonnie++ borró el sistema de alguien), así que si realmente quiere ejecutar como root entonces use -u root. También, si quiere especificar el grupo con el que ejecutar, use el formato user:group. Si especifica un usuario por nombre pero no un grupo, entonces se elegirá el grupo primario de ese usuario. Si especifica un usuario por número y no un grupo, entonces el grupo será nogroup

semáforo.

SALID

A

La salida principal es texto plano en 80 columnas, diseñado para ajustarse bien cuando se pega en un correo electrónico y que funcionará bien con pantallas

Braille.

El segundo tipo de salida es CSV (Valores Separados por Comas). Esto puede importarse fácilmente en cualquier programa de hoja de cálculo o base de datos. También he incluido los programas bon_csv2html y bon_csv2txt para convertir datos CSV a HTML y texto plano ascii respectivamente

.

El campo "Name:Size etc" tiene el nombre, tamaño de archivo, tamaño de bloque de E/S, concurrencia, número de búsquedas (seeks) y número de procesos buscadores (seekers) separados por caracteres ":

".

Para cada prueba se reportan dos números, la cantidad de trabajo realizada (números más altos son mejores) y el porcentaje de tiempo de CPU tomado para realizar el trabajo (números más bajos son mejores). Si una prueba se completa en menos de 500ms, la salida se mostrará como "++++". Esto es porque tal resultado de prueba no puede calcularse con precisión debido a errores de redondeo y prefiero no mostrar un resultado que mostrar uno

incorrecto.

Los volúmenes de datos para la visualización de texto de 80 columnas usan "K" para KiB (1024 bytes), "M" para MiB (1048576 bytes), y &quot;G" para GiB (1073741824 bytes

). Así que K/sec significa un múlt
iplo de 1024 bytes por segundo.
