BADBLOCKS(8) Manual del Administrador del Sistema BADBLOCKS(8)

NOMBRE

badblocks - buscar bloques defectuosos en un dispositivo

SINOPSIS

badblocks [ -svwnfBX ] [ -b tamaño_bloque ] [ -c bloques_a_la_vez ] [ -d factor_retraso_lectura ] [ -e max_bloques_defectuosos ] [ -i archivo_entrada ] [ -o archivo_salida ] [ -p num_pasadas ] [ -t patron_prueba ] dispositivo [ ultimo_bloque ] [ primer_bloque ]

DESCRIPCIÓN

badblocks se utiliza para buscar bloques defectuosos en un dispositivo (normalmente una partición de disco). dispositivo es el archivo especial que corresponde al dispositivo (por ejemplo, /dev/hdc1). ultimo_bloque es el último bloque a verificar; si no se especifica, se utiliza el último bloque del dispositivo por defecto. primer_bloque es un parámetro opcional que especifica el número de bloque de inicio para la prueba, lo que permite que la prueba comience en medio del disco. Si no se especifica, se utiliza el primer bloque del disco por defecto.

Nota importante: Si la salida de badblocks se va a alimentar a los programas e2fsck o mke2fs, es importante que el tamaño del bloque se especifique correctamente, ya que los números de bloque que se generan dependen en gran medida del tamaño de bloque utilizado por el sistema de archivos. Por esta razón, se recomienda encarecidamente a los usuarios que no ejecuten badblocks directamente, sino que utilicen la opción -c de los programas e2fsck y mke2fs.

OPCIONES

-b tamaño_bloque
Especifica el tamaño de los bloques en bytes. El valor predeterminado es 1024.
-c número de bloques
es el número de bloques que se prueban a la vez. El valor predeterminado es 64.
-d factor_retraso_lectura
Este parámetro, si se pasa y es distinto de cero, hará que badblocks espere entre lecturas si no se encontraron errores en la operación de lectura; el retraso se calculará como un porcentaje del tiempo que tardó la operación de lectura. En otras palabras, un valor de 100 hará que cada lectura se retrase tanto como la lectura anterior, y un valor de 200 el doble de ese tiempo.
-e recuento máximo de bloques defectuosos
Especifica un número máximo de bloques defectuosos antes de abortar la prueba. El valor predeterminado es 0, lo que significa que la prueba continuará hasta que se alcance el final del rango de prueba.
-f
Normalmente, badblocks se negará a realizar una prueba de lectura/escritura o una prueba no destructiva en un dispositivo que esté montado, ya que cualquiera de las dos puede hacer que el sistema se bloquee y/o dañe el sistema de archivos, incluso si está montado en modo de solo lectura. Esto se puede anular usando la bandera -f, pero casi nunca se debería usar; si crees que eres más listo que el programa badblocks, casi seguro que no lo eres. La única vez que esta opción podría ser segura de usar es si el archivo /etc/mtab es incorrecto y el dispositivo realmente no está montado.
-i archivo_entrada
Lee una lista de bloques defectuosos ya conocidos. Badblocks omitirá la prueba de estos bloques ya que se sabe que son defectuosos. Si archivo_entrada se especifica como "-", la lista se leerá de la entrada estándar. Los bloques listados en esta lista se omitirán de la lista de bloques defectuosos nuevos producidos en la salida estándar o en el archivo de salida. La opción -b de dumpe2fs(8) puede usarse para recuperar la lista de bloques actualmente marcados como defectuosos en un sistema de archivos existente, en un formato adecuado para usar con esta opción.
-n
Usa el modo de prueba de lectura/escritura no destructiva. Por defecto, solo se realiza una prueba de solo lectura no destructiva. Esta opción no debe combinarse con la opción -w, ya que son mutuamente exclusivas.
-o archivo_salida
Escribe la lista de bloques defectuosos en el archivo especificado. Sin esta opción, badblocks muestra la lista en su salida estándar. El formato de este archivo es adecuado para ser utilizado por la opción -l en e2fsck(8) o mke2fs(8).
-p num_pasadas
Repite el escaneo del disco hasta que no se descubran nuevos bloques en num_pasadas escaneos consecutivos del disco. El valor predeterminado es 0, lo que significa que badblocks saldrá después de la primera pasada.
-s
Muestra el progreso del escaneo escribiendo un porcentaje aproximado de completitud de la pasada actual de badblocks sobre el disco. Ten en cuenta que badblocks puede realizar múltiples pasadas de prueba sobre el disco, en particular si el usuario solicita la opción -p o -w.
-t patron_prueba
Especifica un patrón de prueba para leer (y escribir) en los bloques del disco. El patron_prueba puede ser un valor numérico entre 0 y ULONG_MAX-1 inclusive, o la palabra "random", que especifica que el bloque se llenará con un patrón de bits aleatorio. Para los modos de lectura/escritura (-w) y no destructivo (-n), se pueden especificar uno o más patrones de prueba especificando la opción -t para cada patrón de prueba deseado. Para el modo de solo lectura, solo se puede especificar un patrón y no puede ser "random". La prueba de solo lectura con un patrón asume que el patrón especificado se ha escrito previamente en el disco; de lo contrario, un gran número de bloques fallarán la verificación. Si se especifican múltiples patrones, todos los bloques se probarán con un patrón antes de pasar al siguiente patrón.
-v
Modo detallado. Escribirá el número de errores de lectura, errores de escritura y corrupción de datos en stderr.
-w
Usa la prueba en modo de escritura. Con esta opción, badblocks busca bloques defectuosos escribiendo algunos patrones (0xaa, 0x55, 0xff, 0x00) en cada bloque del dispositivo, leyendo cada bloque y comparando el contenido. Esta opción no puede combinarse con la opción -n, ya que son mutuamente exclusivas.
-B
Usa E/S con búfer y no uses E/S directa, incluso si está disponible.
-X
Bandera interna solo para ser utilizada por e2fsck(8) y mke2fs(8). Omite la comprobación de seguridad del dispositivo en uso en modo exclusivo.

ADVERTENCIA

Nunca uses la opción -w en un dispositivo que contenga un sistema de archivos existente. ¡Esta opción borra datos! Si quieres hacer pruebas en modo de escritura en un sistema de archivos existente, usa la opción -n en su lugar. Es más lenta, pero conservará tus datos.

La opción -e hará que badblocks genere una lista posiblemente incompleta de bloques defectuosos. Por lo tanto, se recomienda usarla solo cuando se quiera saber si hay algún bloque defectuoso en el dispositivo, y no cuando se quiera la lista de bloques defectuosos.
