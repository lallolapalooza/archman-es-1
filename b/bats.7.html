BATS(7) Sistema de Pruebas Automatizadas en Bash BATS(7)

NAME

bats - Formato de archivo de pruebas de Bats

DESCRIPCIÓN

Un archivo de prueba de Bats es un script de Bash con una sintaxis especial para definir casos de prueba. Bajo el capó, cada caso de prueba es simplemente una función con una descripción.

#!/usr/bin/env bats
@test "suma usando bc" {
  result="$(echo 2+2 | bc)"
  [ "$result" -eq 4 ]
}
@test "suma usando dc" {
  result="$(echo 2 2+p | dc)"
  [ "$result" -eq 4 ]
}

Cada archivo de prueba de Bats se evalúa n+1 veces, donde n es el número de casos de prueba en el archivo. La primera ejecución cuenta el número de casos de prueba, luego itera sobre los casos de prueba y ejecuta cada uno en su propio proceso.

Etiquetado de pruebas

Cada prueba tiene una lista de etiquetas adjunta a ella. Sin especificación, esta lista está vacía. Las etiquetas se pueden definir de dos maneras. La primera es # bats test_tags=:

# bats test_tags=tag:1, tag:2, tag:3 @test "segunda prueba" { # ... }

@test "segunda prueba" { # ... }

Estas etiquetas (tag:1, tag:2, tag:3) se adjuntarán a la prueba primera prueba. La segunda prueba no tendrá etiquetas adjuntas. Los valores definidos en la directiva # bats test_tags= se asignarán a la siguiente @test que se encuentre en el archivo y se olvidarán después de eso. Solo se usará el valor de la última directiva # bats test_tags= antes de una prueba dada.

A veces, queremos dar a todas las pruebas en un archivo un conjunto de las mismas etiquetas. Esto se puede lograr mediante # bats file_tags=. Se añadirán a todas las pruebas en el archivo después de esa directiva. Una directiva adicional # bats file_tags= sobrescribirá los valores previamente definidos:

@test "Cero prueba" {
  # no tendrá etiquetas
}
# bats file_tags=a:b
# bats test_tags=c:d
@test "Primera prueba" {
  # se etiquetará a:b, c:d
}
# bats file_tags=
@test "Segunda prueba" {
  # no tendrá etiquetas
}

Las etiquetas son sensibles a mayúsculas y minúsculas y solo deben consistir en caracteres alfanuméricos y _, - o :. No deben contener espacios en blanco! El punto y coma está destinado como separador para (espaciado recursivo) namespacing.

Las listas de etiquetas deben separarse por comas y se permite que contengan espacios en blanco. No deben contener etiquetas vacías como test_tags=,b (primera etiqueta vacía), test_tags=a,,c, test_tags=a, ,c (segunda etiqueta solo espacios en blanco/vacía), test_tags=a,b, (tercera etiqueta vacía).

Todas las etiquetas que empiecen con bats: (¡insensible a mayúsculas y minúsculas!) están reservadas para el uso interno de Bats:

bats:focus
Si se encuentra cualquier prueba con la etiqueta bats:focus en una suite de pruebas, solo se ejecutarán aquellas etiquetadas con esta etiqueta. Para prevenir que la CI ejecute silenciosamente en un subconjunto de pruebas debido a una etiqueta bats:focus accidentalmente comprometida, el código de salida de las ejecuciones exitosas se sobrescribirá con 1.
Si requiere el código de salida verdadero, por ejemplo para una operación git bisect, puede deshabilitar este comportamiento estableciendo BATS_NO_FAIL_FOCUS_RUN=1 al ejecutar bats, pero asegúrese de no comprometer esto en CI!

EL AYUDANTE DE EJECUCIÓN

Uso: run [OPCIONES] [--]

Muchas pruebas de Bats necesitan ejecutar un comando y luego hacer afirmaciones sobre su estado de salida y salida. Bats incluye un ayudante run que invoca sus argumentos como un comando, guarda el estado de salida y la salida en variables globales especiales y (opcionalmente) comprueba el estado de salida contra un valor esperado dado. Si tiene éxito, run regresa con un código de estado 0 para que puedas continuar haciendo afirmaciones en tu caso de prueba.

Por ejemplo, digamos que estás probando que el comando foo, cuando se le pasa un nombre de archivo no existente, salga con un código de estado 1 y imprima un mensaje de error.

@test "invocar foo con un archivo no existente imprime un error" {
  run -1 foo nonexistent_filename
  [ "$output" = "foo: no such file ´nonexistent_filename´" ]
}

El -1 como primer argumento le dice a run que espere 1 como estado de salida, y fallar si el comando sale con cualquier otro valor. En caso de fallo, se mostrarán tanto los valores reales como esperados, junto con el comando invocado y su salida:

(en archivo de prueba test.bats, línea 2)
 `run -1 foo nonexistent_filename´ falló, código de salida esperado 1, obtenido 127

Este error indica un posible problema con la instalación o configuración de foo; note que una prueba simple [ $status != 0 ] no habría capturado este tipo de fallo.

La variable $status contiene el código de estado del comando, y la variable $output contiene el contenido combinado de los flujos de salida estándar y de error estándar del comando.

Una tercera variable especial, el array $lines, está disponible para acceder fácilmente a líneas individuales de salida. Por ejemplo, si quieres probar que invocar foo sin argumentos imprima información de uso en la primera línea:

@test "invocar foo sin argumentos imprime uso" {
  run -1 foo
  [ "${lines[0]}" = "usage: foo <filename>" ]
}

Por defecto run omite líneas vacías en ${lines[@]}. Usa run --keep-empty-lines para retenerlas.

Además, puedes usar --separate-stderr para separar stdout y stderr en $output/$stderr y ${lines[@]}/${stderr_lines[@]}.

Todos los parámetros adicionales a run deben venir antes del comando. Si quieres ejecutar un comando que empieza con -, prefixa con -- para prevenir que run lo parsee como una opción.

EL COMANDO DE CARGA

Quizás quieras compartir código común entre múltiples archivos de prueba. Bats incluye un cómodo comando load para cargar un archivo de fuente de Bash relativo a la ubicación del archivo de prueba actual. Por ejemplo, si tienes una prueba de Bats en test/foo.bats, el comando

load test_helper

cargará el script test/test_helper.bash en tu archivo de prueba. Esto puede ser útil para compartir funciones para configurar tu entorno o cargar fixtures.

EL COMANDO BATS_LOAD_LIBRARY

Algunas bibliotecas están instaladas en el sistema, por ejemplo por npm o brew. Estas no deberían loadearse, ya que su ruta depende del método de instalación. En su lugar, uno debería usar bats_load_library junto con establecer BATS_LIB_PATH, una variable similar a PATH separada por dos puntos.

bats_load_library tiene dos modos de resolución de solicitudes:

1.
por ruta relativa desde BATS_LIB_PATH a un archivo en la biblioteca
2.
por nombre de biblioteca, esperando que las bibliotecas tengan un punto de entrada load.bash

Por ejemplo si tu BATS_LIB_PATH está establecido en ~/.bats/libs:/usr/lib/bats, entonces bats_load_library test_helper buscaría archivos existentes con las siguientes rutas:

○
~/.bats/libs/test_helper
○
~/.bats/libs/test_helper/load.bash
○
/usr/lib/bats/test_helper
○
/usr/lib/bats/test_helper/load.bash

El primer archivo existente en esta lista se cargará.

Si quieres cargar solo parte de una biblioteca o el punto de entrada no se llama load.bash, tienes que incluirlo en el argumento: bats_load_library library_name/file_to_load intentará

○
~/.bats/libs/library_name/file_to_load
○
~/.bats/libs/library_name/file_to_load/load.bash
○
/usr/lib/bats/library_name/file_to_loa
