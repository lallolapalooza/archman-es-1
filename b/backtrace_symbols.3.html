backtrace(3) Manual de Funciones de Biblioteca backtrace(3)

NOMBRE

backtrace, backtrace_symbols, backtrace_symbols_fd - soporte para autodepuración de aplicaciones

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <execinfo.h>
int backtrace(int size;
              void *buffer[size], int size);
char **backtrace_symbols(int size;
              void *const buffer[size], int size);
void backtrace_symbols_fd(int size;
              void *const buffer[size], int size, int fd);

DESCRIPCIÓN

backtrace() devuelve una traza de pila (backtrace) para el programa llamante, en el array apuntado por buffer. Una traza de pila es la serie de llamadas a funciones activas actualmente para el programa. Cada elemento en el array apuntado por buffer es de tipo void *, y es la dirección de retorno del frame de pila correspondiente. El argumento size especifica el número máximo de direcciones que se pueden almacenar en buffer. Si la traza de pila es mayor que size, entonces se devuelven las direcciones correspondientes a las size llamadas a función más recientes; para obtener la traza de pila completa, asegúrese de que buffer y size sean lo suficientemente grandes.

Dado el conjunto de direcciones devueltas por backtrace() en buffer, backtrace_symbols() traduce las direcciones a un array de cadenas que describen las direcciones simbólicamente. El argumento size especifica el número de direcciones en buffer. La representación simbólica de cada dirección consiste en el nombre de la función (si se puede determinar), un desplazamiento hexadecimal dentro de la función y la dirección de retorno real (en hexadecimal). La dirección del array de punteros a cadenas se devuelve como resultado de la función backtrace_symbols(). Este array es malloc(3)do por backtrace_symbols(), y debe ser liberado por el llamante. (Las cadenas apuntadas por los punteros del array no necesitan y no deben ser liberadas.)

backtrace_symbols_fd() toma los mismos argumentos buffer y size que backtrace_symbols(), pero en lugar de devolver un array de cadenas al llamante, escribe las cadenas, una por línea, en el descriptor de archivo fd. backtrace_symbols_fd() no llama a malloc(3), y por lo tanto puede ser empleada en situaciones donde la función anterior podría fallar, pero véase NOTAS.

VALOR DE RETORNO

backtrace() devuelve el número de direcciones devueltas en buffer, que no es mayor que size. Si el valor de retorno es menor que size, entonces se almacenó la traza de pila completa; si es igual a size, entonces pudo haber sido truncada, en cuyo caso, no se devuelven las direcciones de los frames de pila más antiguos.

En caso de éxito, backtrace_symbols() devuelve un puntero al array malloc(3)do por la llamada; en caso de error, devuelve NULL.

backtrace (), backtrace_symbols (), backtrace_symbols_fd () Seguridad de hilos MT-Safe

ESTÁNDARES

GNU.

HISTORIAL

glibc 2.1.

NOTAS

Estas funciones hacen algunas suposiciones sobre cómo se almacena la dirección de retorno de una función en la pila. Tenga en cuenta lo siguiente:

•
La omisión de los punteros de frame (como se infiere de cualquier nivel de optimización distinto de cero de gcc(1)) puede provocar que estas suposiciones se violen.
•
Las funciones en línea no tienen frames de pila.
•
La optimización de llamada final provoca que un frame de pila reemplace a otro.
•
backtrace() y backtrace_symbols_fd() no llaman explícitamente a malloc(), pero forman parte de libgcc, que se carga dinámicamente cuando se usa por primera vez. La carga dinámica suele activar una llamada a malloc(3). Si necesita que ciertas llamadas a estas dos funciones no asignen memoria (en manejadores de señales, por ejemplo), debe asegurarse de que libgcc se cargue de antemano.

Los nombres simbólicos pueden no estar disponibles sin el uso de opciones especiales del enlazador. Para sistemas que utilizan el enlazador GNU, es necesario utilizar la opción del enlazador -rdynamic. Tenga en cuenta que los nombres de las funciones "estáticas" no se exponen y no estarán disponibles en la traza de pila.

EJEMPLOS

El siguiente programa demuestra el uso de backtrace() y backtrace_symbols(). La siguiente sesión de shell muestra lo que podríamos ver al ejecutar el programa:


$ cc -rdynamic prog.c -o prog
$ ./prog 3
backtrace() returned 8 addresses
./prog(myfunc3+0x5c) [0x80487f0]
./prog [0x8048711]
./prog(myfunc+0x21) [0x8048894]
./prog(myfunc+0x1a) [0x804888d]
./prog(myfunc+0x1a) [0x804888d]
./prog(main+0x65) [0x80488fb]
/lib/libc.so.6(__libc_start_main+0xdc) [0xb7e38f9c]
./prog [0x8048711]

Código fuente del programa

#include <execinfo.h>
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#define BT_BUF_SIZE 100
void
myfunc3(void)
{
    int nptrs;
    void *buffer[BT_BUF_SIZE];
    char **strings;
    nptrs = backtrace(buffer, BT_BUF_SIZE);
    printf("backtrace() returned %d addresses\n", nptrs);
    /* La llamada backtrace_symbols_fd(buffer, nptrs, STDOUT_FILENO)
       produciría una salida similar a la siguiente: */
    strings = backtrace_symbols(buffer, nptrs);
    if (strings == NULL) {
        perror("backtrace_symbols");
        exit(EXIT_FAILURE);
    }
    for (size_t j = 0; j < nptrs; j++)
        printf("%s\n", strings[j]);
    free(strings);
}
static void   /* "static" significa no exportar el símbolo.  */
myfunc2(void)
{
    myfunc3();
}
void
myfunc(int ncalls)
{
    if (ncalls > 1)
        myfunc(ncalls - 1);
    else
        myfunc2();
}
int
main(int argc, char *argv[])
{
    if (argc != 2) {
        fprintf(stderr, "%s num-llamadas\n", argv[0]);
        exit(EXIT_FAILURE);
    }
    myfunc(atoi(argv[1]));
    exit(EXIT_SUCCESS);
}
