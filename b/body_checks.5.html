ACTIONS

BCC user@domain
Añade la dirección especificada como destinatario BCC y examina la siguiente línea de entrada. La dirección debe tener una parte local y una parte de dominio. El número de direcciones BCC que se pueden añadir está limitado únicamente por la cantidad de espacio de almacenamiento disponible.

Nota 1: la dirección BCC se añade como si se especificara con NOTIFY=NONE. El remitente no será notificado cuando la dirección BCC no sea entregable, siempre y cuando todo el software descendente implemente RFC 3461.

Nota 2: esto ignora las direcciones duplicadas (con las mismas opciones de notificación de estado de entrega).

Esta característica está disponible en Postfix 3.0 y posteriores.

Esta característica no es compatible con las comprobaciones de encabezados/cuerpos smtp.

DISCARD texto opcional...
Declara la entrega como exitosa y descarta silenciosamente el mensaje. No examina el resto del mensaje de entrada. Registra el texto opcional si se especifica, de lo contrario, registra un mensaje genérico.

Nota: esta acción deshabilita la inspección posterior de encabezados o body_checks del mensaje actual y afecta a todos los destinatarios. Para descartar solo un destinatario sin descartar el mensaje completo, utilice la tabla transport(5) para dirigir el correo al servicio discard(8).

Esta característica está disponible en Postfix 2.0 y posteriores.

Esta característica no es compatible con las comprobaciones de encabezados/cuerpos smtp.

DUNNO
Finge que la línea de entrada no coincidió con ningún patrón y examina la siguiente línea de entrada. Esta acción se puede utilizar para acortar la búsqueda en la tabla.

Por razones de compatibilidad con versiones anteriores, Postfix también acepta OK, pero se trata (y siempre se ha tratado) como DUNNO.

Esta característica está disponible en Postfix 2.1 y posteriores.

FILTER transporte:destino
Anula la configuración del parámetro content_filter y examina la siguiente línea de entrada. Después de poner en cola el mensaje, envía todo el mensaje a través del filtro de contenido externo especificado. El nombre del transporte especifica el primer campo de una definición del agente de entrega de correo en master.cf; la sintaxis del destino del siguiente salto se describe en la página del manual del agente de entrega correspondiente. Hay más información sobre filtros de contenido externos en el archivo Postfix FILTER_README.

Nota 1: no utilice sustituciones de expresiones regulares $número para el transporte o el destino a menos que sepa que la información tiene un origen de confianza.

Nota 2: esta acción anula la configuración de content_filter de main.cf y afecta a todos los destinatarios del mensaje. En el caso de que se activen varias acciones FILTER, solo se ejecuta la última.

Nota 3: el propósito del comando FILTER es anular el enrutamiento del mensaje. Para anular el transporte del destinatario pero no el destino del siguiente salto, especifique un destino de filtro vacío (Postfix 2.7 y posteriores), o especifique un transporte:destino que entregue a través de una instancia de Postfix diferente (Postfix 2.6 y anteriores). Otras opciones son utilizar las funciones transport_maps dependientes del destinatario o sender_dependent_default_transport_maps dependientes del remitente.

Esta característica está disponible en Postfix 2.0 y posteriores.

Esta característica no es compatible con las comprobaciones de encabezados/cuerpos smtp.

HOLD texto opcional...
Organiza la colocación del mensaje en la cola de hold (retención) y examina la siguiente línea de entrada. El mensaje permanece en hold hasta que alguien lo elimina o lo libera para su entrega. Registra el texto opcional si se especifica, de lo contrario, registra un mensaje genérico.

El correo que se pone en espera se puede examinar con el comando postcat(1), y se puede destruir o liberar con el comando postsuper(1).

Nota: utilice "postsuper -r" para liberar el correo que se mantuvo en espera durante una fracción significativa de $maximal_queue_lifetime o $bounce_queue_lifetime, o más tiempo. Utilice "postsuper -H" solo para el correo que no expirará dentro de algunos intentos de entrega.

Nota: esta acción afecta a todos los destinatarios del mensaje.

Esta característica está disponible en Postfix 2.0 y posteriores.

Esta característica no es compatible con las comprobaciones de encabezados/cuerpos smtp.

IGNORE
Elimina la línea actual de la entrada y examina la siguiente línea de entrada. Véase STRIP para una alternativa que registra la acción.
INFO texto opcional...
Registra un registro de "info:" con el texto opcional... (o registra un texto genérico) y examina la siguiente línea de entrada. Esta acción es útil para el registro rutinario o para la depuración.

Esta característica está disponible en Postfix 2.8 y posteriores.

PASS texto opcional...
Registra un registro de "pass:" con el texto opcional... (o registra un texto genérico) y desactiva la inspección de encabezados, cuerpos y Milter para el resto de este mensaje.

Nota: esta característica se basa en la confianza en información que es fácil de falsificar.

Esta característica está disponible en Postfix 3.2 y posteriores.

Esta característica no es compatible con las comprobaciones de encabezados/cuerpos smtp.

PREPEND texto...
Antepone una línea con el texto especificado y examina la siguiente línea de entrada.

Notas:

  • El texto antepuesto se emite en una línea separada, inmediatamente antes de la entrada que activó la acción PREPEND.
  • El texto antepuesto no se considera parte del flujo de entrada: no está sujeto a comprobaciones de encabezados/cuerpos ni a reescritura de direcciones, y no afecta a la forma en que Postfix añade encabezados de mensaje faltantes.
  • Al anteponer texto antes de una línea de encabezado de mensaje, el texto antepuesto debe comenzar con una etiqueta de encabezado de mensaje válida.
  • Esta acción no se puede utilizar para anteponer texto multilínea.
Esta característica está disponible en Postfix 2.1 y posteriores.

Esta característica no es compatible con milter_header_checks.

REDIRECT user@domain
Escribe una solicitud de redirección de mensajes en el archivo de cola y examina la siguiente línea de entrada. Después de poner en cola el mensaje, se enviará a la dirección especificada en lugar de al destinatario(s) previsto(s).

Nota 1: esta acción anula la acción FILTER y afecta a todos los destinatarios del mensaje. Si se activan varias acciones REDIRECT, solo se ejecuta la última.

Nota 2: una dirección REDIRECT está sujeta a canonización (añadir dominio faltante) pero NO está sujeta a mapeo de alias canónico, enmascaramiento, bcc o virtual.

Esta característica está disponible en Postfix 2.1 y posteriores.

Esta característica no es compatible con las comprobaciones de encabezados/cuerpos smtp.

REPLACE texto...
Reemplaza la línea actual con el texto especificado y examina la siguiente línea de entrada.

Esta característica está disponible en Postfix 2.2 y posteriores. La descripción siguiente se aplica a Postfix 2.2.2 y posteriores.

Notas:

  • Al reemplazar una línea de encabezado de mensaje, el texto de reemplazo debe comenzar con una etiqueta de encabezado válida.
  • El texto reemplazado permanece como parte del flujo de entrada. A diferencia del resultado de la acción PREPEND, un encabezado de mensaje reemplazado puede estar sujeto a reescritura de direcciones y puede afectar a la forma en que Postfix añade encabezados de mensaje faltantes.
REJECT texto opcional...
Rechaza todo el mensaje. No examina el resto del mensaje de entrada. Responde con texto opcional... cuando se especifica el texto opcional, de lo contrario, responde con un mensaje de error genérico.

Nota: esta acción deshabilita la inspección posterior de encabezados o body_checks del mensaje actual y afecta a todos los destinatarios.

Postfix versión 2.3 y posteriores admiten códigos de estado mejorados. Cuando no se especifica ningún código al principio del texto opcional..., Postfix inserta un código de estado mejorado predeterminado de "5.7.1".

Esta característica no es compatible con las comprobaciones de encabezados/cuerpos smtp.

STRIP texto opcional...
Registra un registro de "strip:" con el texto opcional... (o registra un texto genérico), elimina la línea de entrada de la entrada y examina la siguiente línea de entrada. Véase IGNORE para una alternativa silenciosa.

Esta característica está disponible en Postfix 3.2 y posteriores.

WARN texto opcional...
Registra un registro de "warning:" con el texto opcional... (o registra un texto genérico) y examina la siguiente línea de entrada. Esta acción es útil para la depuración y para probar un patrón antes de aplicar acciones más drásticas.

BUGS


Las líneas vacías nunca coinciden, porque algunos tipos de mapa se comportan mal cuando se les da una cadena de búsqueda de longitud cero. Esta limitación puede eliminarse para las tablas de expresiones regulares en una futura versión.

Mucha gente pasa por alto las principales limitaciones de las reglas de header_checks y body_checks.

  • Estas reglas operan sobre un encabezado de mensaje lógico o una línea de cuerpo a la vez. Una decisión tomada para una línea no se traslada a la siguiente línea.
  • Si el texto del cuerpo del mensaje está codificado (RFC 2045), las reglas deben especificarse para la forma codificada.
  • Asimismo, cuando los encabezados de mensaje están codificados (RFC 2047), las reglas deben especificarse para la forma codificada.

Los encabezados de mensaje añadidos por el propio demonio cleanup(8) están excluidos de la inspección. Ejemplos de tales encabezados de mensaje son From:, To:, Message-ID:, Date:.

Los encabezados de mensaje eliminados por el demonio cleanup(8) se examinarán antes de ser eliminados. Ejemplos son: Bcc:, Content-Length:, Return-Path:.
