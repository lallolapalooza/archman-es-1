x

Añade la capacidad especificada al conjunto de capacidades que se concederán al comando especificado. Ciertas capacidades se conceden por defecto; esta opción se puede usar para añadir más allá de los valores predeterminados, que pueden haber sido modificados por --cap-add y --cap-drop opciones usadas con la invocación buildah from que creó el

Elimina la capacidad especificada del conjunto de capacidades que se concederán al comando especificado. La lista de capacidades predeterminadas se gestiona en containers.conf(5)

--mount=tipo=TIPO,OPCIÓN-ESPECÍFICA-DEL-TIPO[,...

]

Adjunta un montaje de sistema de archivos al

contenedor

Los TIPOS de montaje soportados actualmente son bind, cache, secret y tmpfs. Las escrituras en bind y tmpfs se descartan después de que el comando termine, mientras que los cambios en cache persisten entre

usos. 
   ej.
   tipo=bind,source=/ruta/en/host,destination=/ruta/en/contenedor
   tipo=tmpfs,tmpfs-size=512M,destination=/ruta/en/contenedor
   tipo=cache,target=/ruta/en/contenedor
   Opciones Comunes:
          · src, source: especificación de origen del montaje para bind y cache. Obligatorio para bind. Si se especifica `from`, `src` es la subruta en el campo `from`.
          · dst, destination, target: ubicación donde el comando que se ejecuta debe ver el contenido que se monta.
          · ro, read-only: (predeterminado true para `tipo=bind`, false para `tipo=tmpfs`, `tipo=cache`).
          · rw, read-write: (predeterminado false para `tipo=bind`, true para `tipo=tmpfs`, `tipo=cache`).
   Opciones específicas para bind:
          · bind-propagation: shared, slave, private, rshared, rslave, o rprivate(predeterminado). Ver también mount(2). [[1]](#Footnote1)
          . bind-nonrecursive: no configurar un montaje bind recursivo. Por defecto es recursivo.
          · from: nombre de la imagen para la raíz del origen. Por defecto es **--contextdir**, obligatorio si **--contextdir** no se especificó.
          · src: ubicación en el directorio de contexto (o imagen, si se usa la opción **from**) a montar en lugar de su directorio de nivel superior.
          · z: Establecer etiqueta SELinux compartida en el destino montado. Usar si SELinux está habilitado en la máquina host.
          · Z: Establecer etiqueta SELinux privada en el destino montado. Usar si SELinux está habilitado en la máquina host.
   Opciones específicas para tmpfs:
          · tmpfs-size: Tamaño del montaje tmpfs en bytes. Sin límite por defecto en Linux.
          · tmpfs-mode: Modo de archivo del tmpfs en octal. (ej. 700 o 0700.) Por defecto 1777 en Linux.
          · tmpcopyup: La ruta que está sombreada por el montaje tmpfs se copia recursivamente hacia el propio tmpfs.
   Opciones específicas para secret:
          · id: el identificador para el secreto pasado al comando `buildah bud --secret` o `podman build --secret`.
   Opciones específicas para cache:
          · id: Distinguir esta caché de otras cachés usando este ID en lugar de la ruta de montaje de destino.
          · mode: Modo de archivo para el nuevo directorio de caché en octal. Predeterminado 0755.
          · src: ubicación en la caché (o imagen, si se usa la opción **from**) a montar en lugar de su directorio de nivel superior.
          · uid: uid para el directorio de caché.
          · gid: gid para el directorio de caché.
          · from: nombre de la etapa para la raíz del origen. Por defecto es el directorio de caché del host.
          · sharing: Si otros usuarios de esta caché necesitan esperar a que este comando termine (`sharing=locked`) o no (`sharing=shared`, que es el predeterminado).
          · z: Establecer etiqueta SELinux compartida en el destino montado. Habilitado por defecto si SELinux está habilitado en la máquina host.
          · Z: Establecer etiqueta SELinux privada en el destino montado. Usar si SELinux está habilitado en la máquina
host.

Montajes de Volumen Protegidos contra

Escritura

Puede añadir el sufijo :ro o :rw a un volumen para montarlo en modo solo lectura o lectura-escritura, respectivamente. Por defecto, los volúmenes se montan en modo lectura-escritura. Vea

ejemplos.

Cambio de Propiedad de los Montajes de

Volumen

Por defecto, Buildah no cambia el propietario y grupo de los directorios de volumen de origen montados en los contenedores. Si un contenedor se crea en un nuevo espacio de nombres de usuario, el UID y GID en el contenedor pueden corresponder a otro UID y GID en el

host.

El sufijo :U le indica a Buildah que use el UID y GID correctos del host basados en el UID y GID dentro del contenedor, para cambiar el propietario y grupo del volumen de

origen.

Etiquetado de los Montajes de

Volumen

Los sistemas de etiquetado como SELinux requieren que se coloquen etiquetas adecuadas en el contenido del volumen montado en un contenedor. Sin una etiqueta, el sistema de seguridad podría impedir que los procesos que se ejecutan dentro del contenedor usen el contenido. Por defecto, Buildah no cambia las etiquetas establecidas por el

SO.

Para cambiar una etiqueta en el contexto del contenedor, puede añadir cualquiera de dos sufijos :z o :Z al montaje del volumen. Estos sufijos le dicen a Buildah que reetiquete los objetos de archivo en los volúmenes compartidos. La opción z le dice a Buildah que dos contenedores comparten el contenido del volumen. Como resultado, Buildah etiqueta el contenido con una etiqueta de contenido compartido. Las etiquetas de volumen compartido permiten a todos los contenedores leer/escribir contenido. La opción Z le dice a Buildah que etiquete el contenido con una etiqueta privada no compartida. Solo el contenedor actual puede usar un volumen

privado.

Por defecto, los volúmenes montados enlace son privados. Eso significa que cualquier montaje hecho dentro del contenedor no será visible en el host y viceversa. Este comportamiento puede cambiarse especificando una propiedad de propagación del montaje del

volumen.

Cuando la política de propagación del montaje se establece en shared, cualquier montaje completado dentro del contenedor en ese volumen será visible tanto para el host como para el contenedor. NOMBRE

buildah-run - Ejecuta un comando dentro de un contenedor.

SINOPSIS

buildah run [opciones] container [comando [args...]]

buildah run [opciones] [-- [comando [args...]]]

DESCRIPCIÓN

Ejecuta un comando dentro de un contenedor. Si no se especifica ningún comando, se ejecutará el comando predeterminado definido en la imagen del contenedor.

OPCIONES

Todas las opciones de buildah run se aplican al contenedor especificado, no a la imagen.

--adduser user:group

Ejecuta el comando como el usuario y grupo especificados. Esto anula la configuración del usuario del contenedor.

--blk-io-weight weight

Peso de I/O de bloque para el contenedor (0 a 1000, valor predeterminado 0, lo que significa que no hay limitación).

--cap-add capability

Añade capacidades al proceso.

--cap-drop capability

Elimina capacidades del proceso.

--cpu-period period

Límite de tiempo de CPU en microsegundos.

--cpu-quota quota

Límite de tiempo de CPU en microsegundos por período.

--cpu-shares shares

Puntos de CPU para el contenedor (predeterminado 1024).

--cpuset-cpus cpus

Asigna CPUs a los contenedores (ej. 0-1).

--cpuset-mems mems

Asigna nodos de memoria a los contenedores (ej. 0-1).

--device device

Añade un dispositivo al contenedor.

--device-cgroup-rule rule

Añade una regla de cgroup de dispositivo al contenedor.

--device-read-bps device rate

Límite de velocidad de lectura para un dispositivo en bytes por segundo.

--device-read-iops device ops

Límite de velocidad de I/O para un dispositivo en operaciones por segundo.

--device-write-bps device rate

Límite de velocidad de escritura para un dispositivo en bytes por segundo.

--device-write-iops device ops

Límite de velocidad de I/O para un dispositivo en operaciones por segundo.

--entrypoint command

Anula el punto de entrada del contenedor.

--env, -e variable=valor

Establece una variable de entorno dentro del contenedor.

--env-file file

Lee variables de entorno desde un archivo.

--gidmap container-uid:host-uid:size

Mapeo de GID.

--group group

Ejecuta el comando como el grupo especificado.

--hostname name

Establece el nombre de host del contenedor.

--interactive, -i

Mantén STDIN abierto incluso si no está conectado.

--ip address

Establece la dirección IP del contenedor.

--ip6 address

Establece la dirección IPv6 del contenedor.

--kernel-memory limit

Límite de memoria del kernel en bytes.

--link-local-ip address

Establece la dirección IP de enlace local del contenedor.

--mount type=bind,src=,dst=[,options]

Monta un volumen en el contenedor. El tipo de montaje puede ser bind, volume o tmpfs. Las opciones pueden incluir ro (solo lectura).

--memory limit

Límite de memoria en bytes.

--memory-reservation limit

Límite de memoria reservada en bytes.

--memory-swap limit

Límite de memoria y swap en bytes.

--mount-propagation [r]shared | [r]slave | [r]private

Establece la propiedad de propagación de montaje para volúmenes bind-mounted. Requiere que el punto de montaje de origen tenga las propiedades de propagación adecuadas.

Para determinar el punto de montaje de origen y sus propiedades de propagación, usa:

1. Ejecuta df <source-dir> para obtener el punto de montaje de origen.

2. Ejecuta findmnt -o TARGET,PROPAGATION <source-mount-dir> para ver las propiedades de propagación. Si findmnt no está disponible, revisa /proc/self/mountinfo.

Para cambiar las propiedades de propagación, usa el comando mount. Por ejemplo, para hacer que un punto de montaje sea shared: mount --make-shared <source-mount-dir>.

--name name

Establece el nombre del contenedor.

--network network

Establece la red del contenedor.

--no-stdin-ipc

No realizar IPC a través de stdin.

--privileged

Otorga todas las capacidades al contenedor.

--pull

Extrae la imagen si no está presente localmente.

--read-only

Monta el sistema de archivos raíz del contenedor como solo lectura.

--restart policy

Política de reinicio para el contenedor (no, on-failure, always, unless-stopped).

--runtime runtime

Runtime a utilizar para el contenedor (ej. crun, kata, runc).

--runtime-flag flag

Opciones adicionales para el runtime.

--security-opt option

Opciones de seguridad para el contenedor.

--shm-size size

Tamaño del volumen de memoria compartida /dev/shm.

--storage-driver driver

Controlador de almacenamiento a utilizar para el contenedor.

--storage-opt option

Opciones del controlador de almacenamiento.

--sysctl parameter=value

Configura parámetros sysctl para el contenedor.

--tty, -t

Asigna una TTY pseudo.

--uidmap container-uid:host-uid:size

Mapeo de UID.

--ulimit limit

Establece límites ulimit para el contenedor.

--user, -u user

Nombre de usuario o UID para ejecutar el comando.

--uts

Asigna un nuevo espacio de nombres UTS al contenedor.

--userns

Asigna un nuevo espacio de nombres de usuario al contenedor.

--uts-chroot

Utiliza chroot para el espacio de nombres UTS.

--volume, -v source:destination:options

Monta un volumen en el contenedor. Las opciones pueden incluir ro (solo lectura) y z o Z para el contexto SELinux.

--volume-driver driver

Controlador de volumen a utilizar para volúmenes nombrados.

--volumes-from container

Monta volúmenes desde otro contenedor.

--workdir, -w directory

Establece el directorio de trabajo para el comando que se ejecuta dentro del contenedor. Esto no persiste en llamadas posteriores a buildah run ni en la imagen construida.

Utiliza -- para indicar el final de las opciones y pasar otras opciones al comando dentro del contenedor.

EJEMPLO

Ejecuta el comando ps -auxw dentro de un contenedor llamado containerID:

buildah run containerID -- ps -auxw

Ejecuta ps -auxw con el nombre de host myhost:

buildah run --hostname myhost containerID -- ps -auxw

Ejecuta echo $PATH dentro de un contenedor:

buildah run containerID -- sh -c 'echo $PATH'

Ejecuta /bin/bash con el runtime crun y la opción log-format=json:

buildah run --runtime-flag log-format=json containerID /bin/bash

Ejecuta /bin/bash con el runtime crun y la opción debug:

buildah run --runtime-flag debug containerID /bin/bash

Asigna una TTY al contenedor y ejecuta /bin/bash:

buildah run --tty containerID /bin/bash

Ejecuta ls / dentro de un contenedor sin asignar una TTY:

buildah run --tty=false containerID ls /

Monta el volumen /path/on/host en /path/in/container como solo lectura y con el contexto SELinux z:

buildah run --volume /path/on/host:/path/in/container:ro,z containerID sh

Monta el volumen /path/on/host en /path/in/container con el contexto SELinux U (no compartido):

buildah run -v /path/on/host:/path/in/container:z,U containerID sh

Monta un volumen bind de /tmp/on:host a /in:container como solo lectura:

buildah run --mount type=bind,src=/tmp/on:host,dst=/in:container,ro containerID sh
