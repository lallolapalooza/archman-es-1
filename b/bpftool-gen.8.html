BPFTOOL-GEN(8) Manual del Administrador del Sistema BPFTOOL-GEN(8)

NOMBRE

bpftool-gen - herramienta para la generación de código BPF

SINOPSIS

bpftool [OPCIONES] gen COMANDO

OPCIONES := { { -j | --json } [{ -p | --pretty }] | { -d | --debug } | { -L | --use-loader } }

COMANDO := { object | skeleton | help }

COMANDOS GEN

bpftool gen object ARCHIVO_DE_SALIDA ARCHIVO_DE_ENTRADA [ARCHIVO_DE_ENTRADA...]
bpftool gen skeleton ARCHIVO [name NOMBRE_DE_OBJETO]
bpftool gen subskeleton ARCHIVO [name NOMBRE_DE_OBJETO]
bpftool gen min_core_btf ENTRADA SALIDA OBJETO [OBJETO...]
bpftool gen help

DESCRIPCIÓN

bpftool gen object ARCHIVO_DE_SALIDA ARCHIVO_DE_ENTRADA [ARCHIVO_DE_ENTRADA...]
Enlaza estáticamente (combina) uno o más ARCHIVO_DE_ENTRADA en un único ARCHIVO_DE_SALIDA resultante. Todos los archivos involucrados son archivos de objetos ELF de BPF. ARCHIVO_DE_ENTRADA's into a single resulting ARCHIVO_DE_SALIDA. All the files involved are BPF ELF object files.

Las reglas del enlazado estático de BPF son en su mayoría las mismas que para los archivos de objetos de espacio de usuario, pero además de combinar las secciones de datos e instrucciones, los datos .BTF y .BTF.ext (si están presentes en cualquiera de los archivos de entrada) se combinan. Los datos .BTF se deduplican, por lo que todos los tipos comunes entre los ARCHIVO_DE_ENTRADA's solo se representarán una vez en la información BTF resultante.

El enlazado estático de BPF permite dividir el código fuente de BPF en archivos compilados individualmente que luego se enlazan en un único archivo de objeto BPF resultante, el cual puede usarse para generar un esqueleto BPF (con el gen skeleton comando) o pasarse directamente a libbpf (usando la familia de APIs bpf_object__open() ).

bpftool gen skeleton ARCHIVO
Genera un archivo de cabecera C de esqueleto BPF para un ARCHIVO dado. ARCHIVO.

El esqueleto BPF es una interfaz alternativa a las APIs existentes de libbpf para trabajar con objetos BPF. El código del esqueleto está destinado a acortar y simplificar significativamente el código para cargar y trabajar con programas BPF desde el lado del espacio de usuario. El código generado está adaptado a un ARCHIVO de objeto BPF de entrada específico, reflejando su estructura al enumerar los mapas, programas, variables, etc. disponibles. El esqueleto elimina la necesidad de buscar los componentes mencionados por nombre. En su lugar, si la instanciación del esqueleto tiene éxito, se rellenan en la estructura del esqueleto como tipos válidos de libbpf (por ejemplo, un puntero ARCHIVO, reflecting its structure by listing out available maps, program, variables, etc. Skeleton eliminates the need to lookup mentioned components by name. Instead, if skeleton instantiation succeeds, they are populated in skeleton structure as valid libbpf types (e.g., struct bpf_map pointer) y pueden pasarse a las APIs genéricas existentes de libbpf.

Además de un acceso simple y fiable a mapas y programas, el esqueleto proporciona un almacenamiento para los enlaces BPF (struct bpf_link) para cada programa BPF dentro del objeto BPF. Cuando se solicita, los programas BPF compatibles se adjuntarán automáticamente y los enlaces BPF resultantes se almacenarán para su posterior uso por el usuario en campos preasignados en la estructura del esqueleto. Para los programas BPF que libbpf no puede adjuntar automáticamente, el usuario puede adjuntarlos manualmente, pero almacenar el enlace BPF resultante en el campo de enlace por programa. Todos estos enlaces configurados se destruirán automáticamente al destruir el esqueleto BPF. Esto elimina la necesidad de que los usuarios gestionen los enlaces manualmente y dependan del soporte de libbpf para desvincular los programas y liberar los recursos.

Otra funcionalidad que proporciona el esqueleto BPF es una interfaz para variables globales de todos los tipos compatibles: mutables, de solo lectura, así como externas. Esta interfaz permite preconfigurar los valores iniciales de las variables antes de que el objeto BPF sea cargado y verificado por el kernel. Para las variables que no son de solo lectura, la misma interfaz se puede usar para obtener los valores de las variables globales en el lado del espacio de usuario, incluso si son modificadas por el código BPF.

Durante la generación del esqueleto, el contenido del objeto BPF de origen ARCHIVO se incrusta dentro del código generado y, por lo tanto, no es necesario mantenerlo. Esto asegura que el esqueleto y el archivo de objeto BPF coincidan 1 a 1 y se mantengan siempre sincronizados. El código generado está bajo doble licencia bajo las licencias LGPL-2.1 y BSD-2-Clause.

Es un objetivo de diseño y una garantía que las interfaces del esqueleto sean interoperables con las APIs genéricas de libbpf. El usuario siempre debe poder usar la API del esqueleto para crear y cargar un objeto BPF, y luego usar las APIs de libbpf para seguir trabajando con mapas, programas, etc. específicos.

Como parte del esqueleto, se generan algunas funciones personalizadas. Cada una de ellas tiene como prefijo el nombre del objeto. El nombre del objeto puede derivarse del nombre del archivo de objeto, es decir, si el nombre del archivo de objeto BPF es example.o, el nombre del objeto BPF será example. El nombre del objeto también puede especificarse explícitamente a través del parámetro name NOMBRE_DE_OBJETO . Se proporcionan las siguientes funciones personalizadas (asumiendo example como el nombre del objeto):

  • example__open y example__open_opts. Estas funciones se usan para instanciar el esqueleto. Corresponde a la API de libbpf bpf_object__open(). _opts las variantes aceptan opciones extra de bpf_object_open_opts .
  • example__load. Esta función crea mapas, carga y verifica programas BPF, inicializa mapas de datos globales. Corresponde a la API de libbpf bpf_object__load().
  • example__open_and_load combina las invocaciones de example__open y example__load en una operación comúnmente usada.
  • example__attach y example__detach. Este par de funciones permite adjuntar y desadjuntar, respectivamente, un objeto BPF ya cargado. Solo los programas BPF de tipos compatibles con libbpf para la autoadjuntación serán autoadjuntados y sus correspondientes enlaces BPF instanciados. Para otros programas BPF, el usuario puede crear manualmente un enlace BPF y asignarlo a los campos correspondientes en la estructura del esqueleto. example__detach desadjuntará tanto los enlaces creados automáticamente como los poblados manualmente por el usuario.
  • example__destroy. Desadjunta y descarga los programas BPF, libera todos los recursos usados por el esqueleto y el objeto BPF.

Si el objeto BPF tiene variables globales, se crearán estructuras correspondientes con una disposición de memoria que corresponda a la disposición de la sección de datos global. Actualmente se admiten las siguientes: .data, .bss, .rodatay .kconfig . Estas secciones/estructuras de datos se pueden usar para configurar los valores iniciales de las variables, si se establecen antes de example__load. Después, si el kernel de destino admite matrices BPF mapeadas en memoria, las mismas estructuras se pueden usar para obtener y actualizar datos (que no sean de solo lectura) desde el espacio de usuario, con la misma simplicidad que en el lado de BPF.

bpftool gen subskeleton ARCHIVO
Genera un archivo de cabecera C de subsqueleto BPF para un ARCHIVO dado. ARCHIVO.

Los subsqueletos son similares a los esqueletos, excepto que no poseen los mapas, programas o variables globales correspondientes. Requieren que el archivo de objeto usado para generarlos ya esté cargado en un bpf_object por algún otro medio.

Esta funcionalidad es útil cuando una biblioteca se incluye en un programa BPF más grande. Un subsqueleto para la biblioteca tendría acceso a todos los objetos y globales definidos en ella, sin tener que conocer el programa más grande.

En consecuencia, solo se definen dos funciones para los subsqueletos:

  • example__open(bpf_object*). Instancia un subsqueleto desde un bpf_object ya abierto (pero no necesariamente cargado). bpf_object.
  • example__destroy(). Libera el almacenamiento para el subsqueleto pero no descarga ningún programa BPF o mapa.
bpftool gen min_core_btf ENTRADA SALIDA OBJETO [OBJETO...]
Genera un archivo BTF mínimo como SALIDA, derivado de un ARCHIVO BTF de entrada dado, que contiene todos los tipos BTF necesarios para que se puedan satisfacer las reubicaciones CO-RE de uno o más objetos eBPF dados. ENTRADA BTF file, containing all needed BTF types so one, or more, given eBPF objects CO-RE relocations may be satisfied.

Cuando los kernels no se compilan con CONFIG_DEBUG_INFO_BTF, libbpf, al cargar un objeto eBPF, tiene que depender de archivos BTF externos para poder calcular las reubicaciones CO-RE.

Usualmente, un archivo BTF externo se construye a partir de datos DWARF existentes del kernel usando pahole. Contiene todos los tipos usados por su respectiva imagen de kernel y, debido a eso, es grande.

La funcionalidad min_core_btfe construye archivos BTF más pequeños, personalizados para uno o varios objetos eBPF, de modo que puedan distribuirse junto con una aplicación basada en eBPF CO-RE, haciendo que la aplicación sea portable a diferentes versiones del kernel.

Consulte los ejemplos a continuación para obtener más información sobre cómo usarlo.

bpftool gen help
Imprime un mensaje de ayuda breve.

OPCIONES

-h, --help
Imprime un mensaje de ayuda breve (similar a bpftool help).
-V, --version
Imprime el número de versión de bpftool (similar a bpftool version), el número de la versión de libbpf en uso y las características opcionales que se incluyeron cuando se compiló bpftool. Las características opcionales incluyen el enlace contra LLVM o libbfd para proporcionar el desensamblador para programas JIT (bpftool prog dump jited) y el uso de esqueletos BPF (algunas características como bpftool prog profile o mostrar los pids asociados a los objetos BPF pueden depender de él).
-j, --json
Genera salida en formato JSON. Para los comandos que no pueden producir JSON, esta opción no tiene efecto.
-p, --pretty
Genera una salida JSON legible por humanos. Implica -j.
-d, --debug
Imprime todos los registros disponibles, incluso información de nivel de depuración. Esto incluye registros de libbpf así como del verificador, al intentar cargar programas.
-L, --use-loader
Para esqueletos, genera un esqueleto "ligero" (también conocido como esqueleto "loader"). Un esqueleto ligero contiene un programa eBPF cargador. No utiliza la mayor parte de la infraestructura de libbpf y no necesita libelf.

EJEMPLOS

$ cat example1.bpf.c

#include <stdbool.h>
#include <linux/ptrace.h>
#include <linux/bpf.h>
#include <bpf/bpf_helpers.h>
const volatile int param1 = 42;
bool global_flag = true;
struct { int x; } data = {};
SEC("raw_tp/sys_enter")
int handle_sys_enter(struct pt_regs *ctx)
{
      static long my_static_var;
      if (global_flag)
              my_static_var++;
      else
              data.x += param1;
      return 0;
}

$ cat example2.bpf.c

#include <linux/ptrace.h>
#include <linux/bpf.h>
#include <bpf/bpf_helpers.h>
struct {
      __uint(type, BPF_MAP_TYPE_HASH);
      __uint(max_entries, 128);
      __type(key, int);
      __type(value, long);
} my_map SEC(".maps");
SEC("raw_tp/sys_exit")
int handle_sys_exit(struct pt_regs *ctx)
{
      int zero = 0;
      bpf_map_lookup_elem(&my_map, &zero);
      return 0;
}

$ cat example3.bpf.c

#include <linux/ptrace.h>
#include <linux/bpf.h>
#include <bpf/bpf_helpers.h>
/* Este archivo de cabecera lo proporciona el módulo bpf_testmod. */
#include "bpf_testmod.h"
int test_2_result = 0;
/* bpf_Testmod.ko llama a esta función, pasando un "4"
 * y testmod_map->data.
 */
SEC("struct_ops/test_2")
void BPF_PROG(test_2, int a, int b)
{
      test_2_result = a + b;
}
SEC(".struct_ops")
struct bpf_testmod_ops testmod_map = {
      .test_2 = (void *)test_2,
      .data = 0x1,
};

Esta es una aplicación BPF de ejemplo con tres programas BPF y una mezcla de mapas BPF y variables globales. El código fuente está dividido en tres archivos de código fuente.

$ clang --target=bpf -g example1.bpf.c -o example1.bpf.o

$ clang --target=bpf -g example2.bpf.c -o example2.bpf.o

$ clang --target=bpf -g example3.bpf.c -o example3.bpf.o

$ bpftool gen object example.bpf.o example1.bpf.o example2.bpf.o example3.bpf.o

Este conjunto de comandos compila example1.bpf.c, example2.bpf.c y example3.bpf.c individualmente y luego enlaza estáticamente los archivos objeto respectivos en el archivo objeto ELF BPF final example.bpf.o.

$ bpftool gen skeleton example.bpf.o name example | tee example.skel.h

/* SPDX-License-Identifier: (LGPL-2.1 OR BSD-2-Clause) */
/* ¡ESTE ARCHIVO SE HA GENERADO AUTOMÁTICAMENTE! */
#ifndef __EXAMPLE_SKEL_H__
#define __EXAMPLE_SKEL_H__
#include <stdlib.h>
#include <bpf/libbpf.h>
struct example {
      struct bpf_object_skeleton *skeleton;
      struct bpf_object *obj;
      struct {
              struct bpf_map *rodata;
              struct bpf_map *data;
              struct bpf_map *bss;
              struct bpf_map *my_map;
              struct bpf_map *testmod_map;
      } maps;
      struct {
              struct example__testmod_map__bpf_testmod_ops {
                      const struct bpf_program *test_1;
                      const struct bpf_program *test_2;
                      int data;
              } *testmod_map;
      } struct_ops;
      struct {
              struct bpf_program *handle_sys_enter;
              struct bpf_program *handle_sys_exit;
      } progs;
      struct {
              struct bpf_link *handle_sys_enter;
              struct bpf_link *handle_sys_exit;
      } links;
      struct example__bss {
              struct {
                      int x;
              } data;
              int test_2_result;
      } *bss;
      struct example__data {
              _Bool global_flag;
              long int handle_sys_enter_my_static_var;
      } *data;
      struct example__rodata {
              int param1;
      } *rodata;
};
static void example__destroy(struct example *obj);
static inline struct example *example__open_opts(
              const struct bpf_object_open_opts *opts);
static inline struct example *example__open();
static inline int example__load(struct example *obj);
static inline struct example *example__open_and_load();
static inline int example__attach(struct example *obj);
static inline void example__detach(struct example *obj);
#endif /* __EXAMPLE_SKEL_H__ */

$ cat example.c

#include "example.skel.h"
int main()
{
      struct example *skel;
      int err = 0;
      skel = example__open();
      if (!skel)
              goto cleanup;
      skel->rodata->param1 = 128;
      /* Cambia el valor a través del puntero de tipo sombra */
      skel->struct_ops.testmod_map->data = 13;
      err = example__load(skel);
      if (err)
              goto cleanup;
      /* El resultado de la función test_2() */
      printf("test_2_result: %d\n", skel->bss->test_2_result);
      err = example__attach(skel);
      if (err)
              goto cleanup;
      /* todas las APIs de libbpf son utilizables */
      printf("my_map name: %s\n", bpf_map__name(skel->maps.my_map));
      printf("sys_enter prog FD: %d\n",
             bpf_program__fd(skel->progs.handle_sys_enter));
      /* desvincula y vuelve a vincular el programa sys_exit */
      bpf_link__destroy(skel->links.handle_sys_exit);
      skel->links.handle_sys_exit =
              bpf_program__attach(skel->progs.handle_sys_exit);
      printf("my_static_var: %ld\n",
             skel->bss->handle_sys_enter_my_static_var);
cleanup:
      example__destroy(skel);
      return err;
}

# ./example
