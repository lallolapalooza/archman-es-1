NOMBRE

Bytes::Random::Secure - Extensión de Perl para generar bytes aleatorios criptográficamente seguros.

SINOPSIS

use Bytes::Random::Secure qw(
    random_bytes random_bytes_base64 random_bytes_hex
);
my $bytes = random_bytes(32); # Una cadena de 32 bytes aleatorios.
my $bytes = random_string_from( 'abcde', 10 ); # 10 caracteres aleatorios a, b, c, d y e.
my $bytes_as_base64 = random_bytes_base64(57); # Bytes aleatorios codificados en Base64.
my $bytes_as_hex = random_bytes_hex(8); # Ocho bytes aleatorios como dígitos hexadecimales.
my $bytes_as_quoted_printable = random_bytes_qp(100); # Bytes codificados en QP.
my $random = Bytes::Random::Secure->new(
    Bits        => 64,
    NonBlocking => 1,
); # Sembrar con 64 bits y usar /dev/urandom (u otro no bloqueante).
my $bytes = $random->bytes(32); # Una cadena de 32 bytes aleatorios.
my $long  = $random->irand;     # Entero aleatorio de 32 bits.

DESCRIPCIÓN

Bytes::Random::Secure proporciona dos interfaces para obtener bytes aleatorios de calidad criptográfica. La interfaz simple está construida en torno a funciones simples. Para un mayor control sobre la siembra del generador de números aleatorios, existe una interfaz orientada a objetos que proporciona mucha más flexibilidad.

La interfaz de "funciones" proporciona funciones que se pueden usar cada vez que necesite una cadena de un número específico de bytes aleatorios. Los bytes aleatorios están disponibles como cadenas simples, o como dígitos hexadecimales, Quoted Printable o MIME Base64. Hay métodos equivalentes disponibles en la interfaz orientada a objetos, además de algunos otros.

Este módulo puede ser un reemplazo directo para Bytes::Random, con la mejora principal de usar un generador de números aleatorios de calidad criptográfica para crear los datos aleatorios. La "random_bytes" función emula la interfaz de usuario de la función de Bytes::Random con el mismo nombre. Pero con Bytes::Random::Secure, el generador de números aleatorios proviene de Math::Random::ISAAC y es adecuado para fines criptográficos. El problema más difícil de resolver es cómo sembrar el generador. Este módulo usa Crypt::Random::Seed para generar las semillas iniciales para Math::Random::ISAAC.

Además de proporcionar random_bytes(), este módulo también proporciona varias funciones que no se encuentran en Bytes::Random: "random_string_from", random_bytes_base64(), "random_bytes_hex", y "random_bytes_qp".

Y finalmente, para aquellos que necesitan un control más fino sobre cómo Crypt::Random::Seed genera su semilla, existe una interfaz orientada a objetos con un constructor que facilita la configuración del proceso de siembra, mientras proporciona métodos que hacen todo lo que la interfaz de "funciones" puede hacer (la verdad es que la interfaz de funciones es solo un envoltorio delgado alrededor de la versión orientada a objetos, con algunos valores predeterminados razonables seleccionados). La interfaz orientada a objetos también proporciona un método "irand" , no disponible a través de la interfaz de funciones.

JUSTIFICACIÓN

Hay muchos usos para la aleatoriedad de calidad criptográfica. Este módulo tiene como objetivo proporcionar una herramienta generalizada que pueda adaptarse a muchas aplicaciones mientras proporciona una cadena de dependencias mínima y una interfaz de usuario simple. Usted es libre de proponer sus propios casos de uso, pero hay varios obvios:

  • Crear frases de paso temporales (random_string_from()).
  • Generar sal aleatoria por cuenta para ser hasheada junto con las frases de paso (y almacenada junto a ellas) para prevenir ataques de tablas arcoíris.
  • Generar un secreto que pueda ser hasheado junto con el contenido de sesión de una cookie para prevenir falsificaciones de cookies.
  • Construir conjuntos de datos pseudoaleatorios de calidad criptográfica sin procesar para pruebas o muestreo.
  • Alimentar utilidades seguras de generación de claves.

¿Por qué usar este módulo? Este módulo emplea varias herramientas de CPAN bien diseñadas para primero generar una semilla aleatoria fuerte y luego instanciar un generador de números aleatorios de alta calidad basado en la semilla. El código en este módulo realmente solo une los bloques de construcción. Sin embargo, ha tomado una buena cantidad de investigación para llegar a lo que siento que es una cadena de herramientas fuerte que no va a retroceder a un estado débil en algunos sistemas. La interfaz está diseñada con la simplicidad en mente, para minimizar el potencial de configuración incorrecta.

EXPORTACIONES

Por defecto "random_bytes" es la única función exportada. Opcionalmente "random_string_from", "random_bytes_base64", "random_bytes_hex", y "random_bytes_qp" pueden ser exportadas.

FUNCIONES

La interfaz de funciones siembra el generador ISAAC en el primer uso con una semilla de 256 bits que usa la configuración predeterminada de Crypt::Random::Seed como fuente de semilla aleatoria fuerte.

random_bytes

my $random_bytes = random_bytes( 512 );

Devuelve una cadena que contiene tantos bytes aleatorios como se soliciten. Obviamente la cadena no es útil para mostrar, ya que puede contener cualquier valor de byte desde 0 hasta 255.

El parámetro es un recuento de bytes y debe ser un entero mayor o igual a cero.

random_string_from

my $random_bytes = random_string_from( $bag, $length );
my $random_bytes = random_string_from( 'abc', 50 );

$bag es una cadena de caracteres de la cual "random_string_from" puede elegir al construir una cadena aleatoria. Lo llamamos una 'bolsa' (bag), porque es permitido tener caracteres repetidos en la bolsa (si no, podríamos llamarlo un conjunto). Los dígitos repetidos tienen más peso. Por ejemplo, "random_string_from( 'aab', 1 )" tendría un 66.67% de probabilidad de devolver una 'a', y un 33.33% de probabilidad de devolver una 'b'. Para una distribución sin ponderación, asegúrese de que no haya duplicados en $bag.

Esto no es un algoritmo de "sacar y descartar", o de permutación; cada carácter seleccionado es independiente de las selecciones anteriores o posteriores; las selecciones duplicadas son posibles por diseño.

El valor de retorno es una cadena de tamaño $length, de caracteres elegidos al azar de la cadena 'bolsa'.

Es perfectamente legal pasar una cadena Unicode como la "bolsa", y en ese caso, el resultado incluirá caracteres Unicode seleccionados de los pasados en la cadena de la bolsa.

Esta función es útil para la generación de cadenas aleatorias como contraseñas aleatorias temporales.

random_bytes_base64

my $random_bytes_b64           = random_bytes_base64( $num_bytes );
my $random_bytes_b64_formatted = random_bytes_base64( $num_bytes, $eol );

Devuelve una codificación MIME Base64 de una cadena de $number_of_bytes bytes aleatorios. Nótese, debería ser obvio, pero vale la pena mencionar que una codificación base64 de datos base256 requiere más dígitos para representar los bytes solicitados. El número real de dígitos requeridos, incluyendo el relleno (padding), es 4(n/3). Además, el estándar Base64 es agregar relleno al final de cualquier cadena para la cual "length % 57" es un valor distinto de cero.

Si se especifica un $eol , el/los carácter(es) especificado(s) se usarán como delimitadores de línea después de cada 76º carácter. El valor predeterminado es "qq{\n}". Si desea eliminar las inserciones de salto de línea, especifique una cadena vacía: "q{}".

random_bytes_hex

my $random_bytes_as_hex = random_bytes_hex( $num_bytes );

Devuelve una cadena de dígitos hexadecimales que representa la cadena de $number_of_bytes bytes aleatorios.

Vale la pena mencionar que una representación hexadecimal (base16) de datos base256 requiere dos dígitos por cada byte solicitado. Así que "length( random_bytes_hex( 16 ) )" devolverá 32, ya que se necesitan 32 dígitos hexadecimales para representar 16 bytes. Cosas simples, pero mejor mencionarlo ahora que olvidarlo y establecer un campo de base de datos que sea demasiado estrecho.

</section>

random_bytes_qp

my $random_bytes_qp           = random_bytes_qp( $num_bytes );
my $random_bytes_qp_formatted = random_bytes_qp( $num_bytes, $eol );

Produce una cadena de $num_bytes bytes aleatorios, usando la codificación MIME Quoted Printable (tal como la produce la función "encode_qp" de MIME::QuotedPrint. La configuración por defecto usa "\n" como salto de línea después de cada 76 caracteres, y la configuración "binmode" se utiliza para garantizar una conversión de ida y vuelta sin pérdidas. Si no se desea ningún salto de línea, pasa una cadena vacía como $eol.

MÉTODOS

La interfaz orientada a objetos proporciona métodos que reflejan la interfaz de "funciones". Sin embargo, la interfaz OO ofrece la ventaja de que el usuario puede controlar cuántos bits de entropía se usan en la siembra, e incluso cómo se configura Crypt::Random::Seed.

new

my $random = Bytes::Random::Secure->new( Bits => 512 );
my $bytes  = $random->bytes( 32 );

El constructor se usa para especificar cómo se siembra el generador ISAAC. Las versiones futuras también podrían permitir seleccionar CSPRNG alternativos. Si no se pasan parámetros, la configuración por defecto especifica 256 bits para la semilla. El resto de la configuración por defecto acepta los valores por defecto de Crypt::Random::Seed, que favorecen la fuente de entropía proporcionada por el sistema operativo más fuerte, que en muchos casos puede ser "bloqueante".

PARÁMETROS DEL CONSTRUCTOR

Bits

my $random = Bytes::Random::Secure->new( Bits => 128 );

El parámetro "Bits" especifica cuántos bits (redondeados al múltiplo de 32 más cercano) se usarán para sembrar el generador de números aleatorios ISAAC. El valor por defecto es 256 bits de entropía. Pero en algunos casos puede no ser necesario, o incluso inadecuado, extraer tantos bits de entropía de "/dev/random" (una fuente bloqueante).

Se aceptará cualquier valor entre 64 y 8192. Si se especifica un valor fuera de rango, o un valor que no es múltiplo de 32, se generará una advertencia y el parámetro se redondeará al múltiplo de 32 más cercano dentro del rango de 64 a 8192 bits. Así que si se especifica 16384, obtendrás 8192. Si se especifica 33, obtendrás 64.

Nota: En el espíritu Perl de "sin límites arbitrarios", el número máximo de bits que acepta este módulo es 8192, que es el número máximo que ISAAC puede utilizar. Pero solo porque puedas especificar una semilla de 8192 bits no significa que debas hacerlo, y mucho menos que lo necesites. Y si lo haces, probablemente quieras usar la opción "NonBlocking" , discutida más abajo. 8192 bits es mucho para pedirle a una fuente bloqueante como "/dev/random", y realmente cualquier cosa más allá de 512 bits en la semilla es probablemente un desperdicio.

PRNG

Reservado para uso futuro. Eventualmente el usuario podrá seleccionar otros RNGs además de Math::Random::ISAAC.

Unique

Reservado para uso futuro.

Otros parámetros de configuración de Crypt::Random::Seed

Para un control de siembra adicional, consulta la documentación POD de Crypt::Random::Seed. Al proporcionar un parámetro de Crypt::Random::Seed al constructor de Bytes::Random::Secure, se pasará a través a Crypt::Random::Seed. Por ejemplo:

my $random = Bytes::Random::Secure->new( NonBlocking => 1, Bits => 64 );

En este ejemplo, "Bits" se usa internamente, mientras que "NonBlocking" se pasa a través a Crypt::Random::Seed.

bytes

my $random_bytes = $random->bytes(1024);

Esto funciona igual que la función "random_bytes" .

string_from

my $random_string = $random->string_from( 'abcdefg', 10 );

Igual que "random_string_from": Devuelve una cadena de octetos aleatorios seleccionados de la cadena "Bolsa" (en este caso diez octetos de 'abcdefg').

bytes_hex

my $random_hex = $random->bytes_hex(12);

Idéntica en función a "random_bytes_hex".

bytes_base64

my $random_base64 = $random->bytes_base64( 32, EOL => "\n" );

Idéntica en función a "random_bytes_base64".

bytes_qp

my $random_qp = $random->bytes_qp( 80 );

Lo adivinaste: Idéntica en función a "random_bytes_qp".

irand

my $unsigned_long = $random->irand;

Devuelve un entero sin signo de 32 bits aleatorio. El valor satisfará "0 <= x <= 2**32-1". Esta funcionalidad solo está disponible a través de la interfaz OO.

shuffle

my $aref_shuffled = $random->shuffle($aref);

Baraja los contenidos de una referencia a un array in situ, y devuelve la misma referencia.

List::Util, que se incluye con Perl, incluye la función "shuffle" . Pero esa función está defectuosa de dos maneras. Primero, desde un punto de vista criptográfico, usa el "rand"de Perl, que no es un CSPRNG, y por lo tanto es inadecuado.

Segundo, porque el rand de Perl tiene un estado interno de solo 32 bits, no puede generar todas las permutaciones de arrays que contienen 13 o más elementos.

El "shuffle" de este módulo usa un CSPRNG, y también se beneficia de semillas grandes y un enorme estado interno. ISAAC puede sembrarse con hasta 8192 bits, produciendo 2^8192 estados iniciales posibles, y 2^8288 estados internos posibles. Una semilla de 8192 bits asegurará que para arrays de hasta 966 elementos cada permutación sea accesible.

CONFIGURACIÓN

La interfaz de Bytes::Random::Secure intenta mantenerlo simple. Generalmente no hay nada que configurar. Este diseño elimina gran parte del potencial de disminuir la calidad del flujo de bytes aleatorios a través de una configuración incorrecta. El algoritmo ISAAC se usa como nuestra fábrica, sembrada con una fuente fuerte.

Puede haber momentos en que las características de la semilla por defecto impongan una carga demasiado pesada en los recursos del sistema. La semilla por defecto para la interfaz de funciones es 256 bits de entropía tomados de /dev/random (una fuente bloqueante en muchos sistemas), o a través de llamadas API en Windows. El tamaño de semilla por defecto para la interfaz OO también es de 256 bits. Si /dev/random se agotara en el momento en que este módulo intenta sembrar el generador ISAAC, podría haber un retraso mientras se genera entropía adicional del sistema. Si esto es un problema, es posible anular las características de siembra por defecto usando la interfaz OO en lugar de la interfaz de funciones. Sin embargo, bajo la mayoría de las circunstancias, esta capacidad puede ignorarse de forma segura.

A partir de la versión 0.20 de Bytes::Random::Secure, Crypt::Random::Seed proporciona nuestra semilla fuerte (anteriormente era Crypt::Random::Source). Este módulo nos da un excelente comportamiento a prueba de fallos de "fuente fuerte", manteniendo las dependencias no centrales al mínimo absoluto. Lo mejor de todo, funciona bien en una amplia variedad de plataformas, y es compatible con versiones de Perl desde la 5.6.0.

Y como se mencionó anteriormente en este documento, puede haber circunstancias en las que el rendimiento de la fuente aleatoria fuerte del sistema operativo haga prohibitivo usar la configuración de siembra por defecto del módulo. Usa la interfaz OO en su lugar, y lee la documentación de Crypt::Random::Seed para aprender qué opciones están disponibles.

Antes de la versión 0.20, se requería una pesada cadena de dependencias para sembrar el generador ISAAC de forma fiable y segura. Las versiones anteriores requerían Crypt::Random::Source, que a su vez requería Any::Moose. Gracias al nuevo módulo Crypt::Random::Seed de Dana Jacobsen, esta situación se ha resuelto. Así que si buscas una solución de bytes aleatorios seguros que "simplemente funcione" de forma portable, y en versiones de Perl tan antiguas como la 5.6.0, has llegado al lugar correcto. Se anima a los usuarios de versiones anteriores de este módulo a actualizar a la versión 0.20 o superior para beneficiarse de la interfaz de usuario mejorada y la cadena de dependencias más ligera.

DEPENDENCIA OPCIONAL (RECOMENDADA)

Si el rendimiento es una consideración, también puedes instalar Math::Random::ISAAC::XS. El generador de números aleatorios de Bytes::Random::Secure usa Math::Random::ISAAC. Ese módulo implementa el algoritmo ISAAC en Perl puro. Sin embargo, si instalas Math::Random::ISAAC::XS, obtienes el mismo algoritmo implementado en C/XS, lo que proporcionará un mejor rendimiento. Si necesitas producir tus bytes aleatorios más rápidamente, simplemente instalar Math::Random::ISAAC::XS hará que se use automáticamente, y coincidirá una mejora de rendimiento bastante buena.

ADVERTENCIAS

SEGURIDAD ANTE FORK Y HILOS

Al programar para computación paralela, evita la interfaz de "funciones" y usa la interfaz orientada a objetos, y crea un objeto único "Bytes::Random::Secure" dentro de cada proceso o hilo. Bytes::Random::Secure usa un CSPRNG, y compartir el mismo RNG entre hilos o procesos compartirá la misma semilla y el mismo punto de partida. Probablemente esto no sea lo que uno querría hacer. Al instanciar el objeto B::R::S después de hacer fork o crear hilos, se creará un flujo de aleatoriedad único por hilo o proceso.

ALEATORIEDAD FUERTE

Es fácil generar bytes pseudoaleatorios débiles. También es fácil pensar que estás generando bytes pseudoaleatorios fuertes cuando realmente no lo es. Y es difícil probar la calidad criptográficamente aceptable del pseudoaleatorio. Hay muchos generadores de números aleatorios de alta calidad que son adecuados para fines estadísticos, pero no necesariamente cumplen con los rigores del uso

criptográfico.

Asegurar bytes aleatorios fuertes (es decir, seguros) de una manera que funcione en una amplia variedad de plataformas también es un desafío. Un objetivo principal para est

e módulo es proporcionar bytes pseudoaleatorios criptográficamente seguros. Un objetivo secundario es proporcionar una experiencia de usuario simple (reduciendo así la prop
ensión a cometer errores). Un objetivo terciario es minimizar las dependencias necesarias para lograr los objetivos primario y secundario, en la medida en que sea práctico.

ISAA

C

El algoritmo ISAAC se considera un generador de números pseudoaleatorios criptográficamente fuerte. Hay 1.0e2466 estados iniciales. El mejor ataque conocido para descubrir el estado inicial teóricamente tomaría una complejidad de aproximadamente 4.67e1240, lo que no tiene impacto práctico en la seguridad de ISAAC. Se garantiza que los ciclos tengan una longitud mínima de 2**40, con un ciclo promedio de 2**8295. Como no existe un ataque práctico capaz de descubrir el estado inicial, y como el ciclo promedio es tan largo, generalmente no es necesario re-sembrar una aplicación en ejecución. Los resultados están uniformemente distribuidos, sin sesgo e impredecibles a menos que la semilla sea

conocida.

Para confirmar la calidad del CSPRNG, la suite de pruebas de este módulo implementa el FIPS-140-1 http://csrc.nist.gov/publications/fips/fips1401.htm pruebas para generadores de números aleatorios fuertes. Vea los comentarios en "t/27-fips140-1.t" para más detalles. DEPEND
