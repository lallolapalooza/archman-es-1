boot(7) Manual de Información Miscelánea boot(7)

NOMBRE

boot - Proceso de arranque del sistema basado en UNIX System V Release 4

DESCRIPCIÓN

El proceso de arranque (o "secuencia de arranque") varía en detalles entre sistemas, pero se puede dividir aproximadamente en fases controladas por los siguientes componentes:

(1)
hardware
(2)
cargador del sistema operativo (SO)
(3)
kernel
(4)
proceso user-space raíz (init(8) y inittab(5))
(5)
scripts de arranque

Cada uno de estos se describe a continuación con más detalle.

Hardware

Tras el encendido o el reinicio forzado, el control se cede a un programa almacenado en memoria de solo lectura (normalmente PROM); por razones históricas relacionadas con la computadora personal, este programa a menudo se llama "el BIOS".

Este programa normalmente realiza una autoprueba básica de la máquina y accede a la memoria no volátil para leer más parámetros. Esta memoria en la PC tiene respaldo de batería CMOS, por lo que la mayoría de las personas se refieren a ella como "el CMOS"; fuera del mundo de las PC, generalmente se llama "la NVRAM" (RAM no volátil).

Los parámetros almacenados en la NVRAM varían entre sistemas, pero como mínimo, deben especificar qué dispositivo puede suministrar un cargador de SO, o al menos qué dispositivos pueden ser sondeados en busca de uno; dicho dispositivo se conoce como "el dispositivo de arranque". La etapa de arranque del hardware carga el cargador del SO desde una posición fija en el dispositivo de arranque y luego le transfiere el control.

Nota:
El dispositivo desde el que se lee el cargador del SO puede estar conectado a través de una red, en cuyo caso, los detalles del arranque se especifican además mediante protocolos como DHCP, TFTP, PXE, Etherboot, etc.

Cargador del SO

El trabajo principal del cargador del SO es localizar el kernel en algún dispositivo, cargarlo y ejecutarlo. La mayoría de los cargadores de SO permiten el uso interactivo, para habilitar la especificación de un kernel alternativo (quizás una copia de seguridad en caso de que el último compilado no funcione) y para pasar parámetros opcionales al kernel.

En una PC tradicional, el cargador del SO se encuentra en el bloque inicial de 512 bytes del dispositivo de arranque; este bloque se conoce como "el MBR" (Master Boot Record).

En la mayoría de los sistemas, el cargador del SO es muy limitado debido a diversas restricciones. Incluso en sistemas no PC, existen algunas limitaciones en el tamaño y la complejidad de este cargador, pero la limitación de tamaño del MBR de PC (512 bytes, incluida la tabla de particiones) hace que sea casi imposible exprimir mucha funcionalidad en él.

Por lo tanto, la mayoría de los sistemas dividen la función de cargar el SO entre un cargador de SO primario y un cargador de SO secundario; este cargador de SO secundario puede estar ubicado dentro de una porción más grande de almacenamiento persistente, como una partición de disco.

En Linux, el cargador del SO es a menudo grub(8) (una alternativa es lilo(8)).

Kernel

Cuando el kernel se carga, inicializa varios componentes de la computadora y del sistema operativo; cada porción de software responsable de dicha tarea generalmente se considera "un driver" para el componente aplicable. El kernel inicia el swapper de memoria virtual (es un proceso del kernel, llamado "kswapd" en un kernel de Linux moderno), y monta algún sistema de archivos en la ruta raíz, /.

Algunos de los parámetros que se pueden pasar al kernel se relacionan con estas actividades (por ejemplo, el sistema de archivos raíz predeterminado puede ser anulado); para obtener más información sobre los parámetros del kernel de Linux, lea bootparam(7).

Solo entonces el kernel crea el proceso inicial de espacio de usuario, al que se le da el número 1 como su PID (identificador de proceso). Tradicionalmente, este proceso ejecuta el programa /sbin/init, al cual se le pasan los parámetros que aún no han sido manejados por el kernel.

Proceso root de espacio de usuario

Nota:
La siguiente descripción se aplica a un SO basado en UNIX System V Release 4. Sin embargo, varios sistemas ampliamente utilizados han adoptado un enfoque relacionado pero fundamentalmente diferente conocido como systemd(1), para el cual el proceso de arranque se detalla en su bootup(7) asociado.

Cuando se inicia /sbin/init, lee /etc/inittab para obtener instrucciones adicionales. Este archivo define qué se debe ejecutar cuando el programa /sbin/init recibe la instrucción de entrar en un nivel de ejecución particular, lo que brinda al administrador una forma fácil de establecer un entorno para algún uso; cada nivel de ejecución está asociado con un conjunto de servicios (por ejemplo, el nivel de ejecución S es el modo de un solo usuario y el nivel de ejecución 2 implica ejecutar la mayoría de los servicios de red).

El administrador puede cambiar el nivel de ejecución actual a través de init(1), y consultar el nivel de ejecución actual a través de runlevel(8).

Sin embargo, dado que no es conveniente administrar servicios individuales editando este archivo, /etc/inittab solo arranca un conjunto de scripts que realmente inician/detienen los servicios individuales.

Scripts de arranque

Nota:
La siguiente descripción se aplica a un SO basado en UNIX System V Release 4. Sin embargo, varios sistemas ampliamente utilizados (Slackware Linux, FreeBSD, OpenBSD) tienen un esquema de scripts de arranque algo diferente.

Para cada servicio administrado (correo, servidor nfs, cron, etc.), hay un único script de inicio ubicado en un directorio específico (/etc/init.d en la mayoría de las versiones de Linux). Cada uno de estos scripts acepta como único argumento la palabra "start" (haciendo que inicie el servicio) o la palabra "stop" (haciendo que detenga el servicio). El script puede aceptar opcionalmente otros parámetros de conveniencia (por ejemplo, "restart" para detener y luego iniciar, "status" para mostrar el estado del servicio, etc.). Ejecutar el script sin parámetros muestra los argumentos posibles.

Directorios de secuenciación

Para que los scripts específicos se inicien/detengan en niveles de ejecución específicos y en un orden específico, existen directorios de secuenciación, normalmente de la forma /etc/rc[0-6S].d. En cada uno de estos directorios, hay enlaces (generalmente simbólicos) a los scripts en el directorio /etc/init.d.

Un script principal (generalmente /etc/rc) es llamado desde inittab(5); este script principal llama al script de cada servicio a través de un enlace en el directorio de secuenciación relevante. Cada enlace cuyo nombre comienza con 'S' se llama con el argumento "start" (iniciando así el servicio). Cada enlace cuyo nombre comienza con 'K' se llama con el argumento "stop" (deteniendo así el servicio).

Para definir el orden de inicio o detención dentro del mismo nivel de ejecución, el nombre de un enlace contiene un número de orden. Además, para mayor claridad, el nombre de un enlace generalmente termina con el nombre del servicio al que se refiere. Por ejemplo, el enlace /etc/rc2.d/S80sendmail inicia el servicio sendmail(8) en el nivel de ejecución 2. Esto ocurre después de que se ejecuta /etc/rc2.d/S12syslog pero antes de que se ejecute /etc/rc2.d/S90xfs.

Gestionar estos enlaces es gestionar el orden de arranque y los niveles de ejecución; en muchos sistemas, existen herramientas para ayudar en esta tarea (por ejemplo, chkconfig(8)).
