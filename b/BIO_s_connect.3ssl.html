DESCRIPCIÓ

N

BIO_s_connect() devuelve el método BIO de conexión. Este es un envoltorio alrededor de las rutinas de conexión de sockets TCP/IP de la

plataforma.

Usando BIOs de conexión, se pueden establecer conexiones TCP/IP y transferir datos usando únicamente rutinas BIO. De esta manera, cualquier operación específica de la plataforma queda oculta por la abstracción

BIO.

Las operaciones de lectura y escritura en un BIO de conexión realizarán E/S en la conexión subyacente. Si no se ha establecido ninguna conexión y el puerto y el nombre de host (ver más abajo) están configurados correctamente, primero se establece una

conexión.

Los BIOs de conexión admiten BIO_puts() y BIO_get

s().

Si la bandera de cierre está establecida en un BIO de conexión, cualquier conexión activa se apagará y el socket se cerrará cuando el BIO se

libere.

Llamar a BIO_reset() en un BIO de conexión cerrará cualquier conexión activa y restablecerá el BIO a un estado desde el cual pueda conectarse de nuevo al mismo

host.

BIO_new_connect() combina BIO_new() y BIO_set_conn_hostname() en una sola llamada: es decir, crea un nuevo BIO de conexión con el nombre de host name

.

BIO_set_conn_hostname() usa la cadena name para establecer el nombre de host. El nombre de host puede ser una dirección IP; si la dirección es IPv6, debe estar encerrada entre corchetes "[" y "]". El nombre de host también puede incluir el puerto en la forma nombredehost:puerto; ver BIO_parse_hostserv(3) y BIO_set_conn_port() para más

detalles.

BIO_set_conn_port() establece el puerto a port. port puede ser la forma numérica o una cadena de servicio como "http", que se mapeará a un número de puerto usando la función del sistema getservbyna

me().

BIO_set_conn_address() establece la información de dirección y puerto usando un BIO_ADDR(3

ssl).

BIO_set_conn_ip_family() establece la familia

IP.

BIO_get_conn_hostname() devuelve el nombre de host del BIO de conexión o NULL si el BIO está inicializado pero no se ha establecido ningún nombre de host. Este valor de retorno es un puntero interno que no debe ser

modificado.

BIO_get_conn_port() devuelve el puerto como una cadena. Este valor de retorno es un puntero interno que no debe ser

modificado.

BIO_get_conn_address() devuelve la información de dirección como un BIO_ADDR. Este valor de retorno es un puntero interno que no debe ser

modificado.

BIO_get_conn_ip_family() devuelve la familia IP del BIO de

conexión.

BIO_set_nbio() establece la bandera de E/S no bloqueante a n. Si n es cero, se establece E/S bloqueante. Si n es 1, se establece E/S no bloqueante. La E/S bloqueante es la predeterminada. La llamada a BIO_set_nbio() debe hacerse antes de que se establezca la conexión porque la E/S no bloqueante se establece durante el proceso de

conexión.

BIO_do_connect() intenta conectar el BIO proporcionado. Esto realiza un protocolo de enlace SSL/TLS en la medida en que lo admita el BIO. Para BIOs no SSL, la conexión se realiza típicamente a nivel TCP. Si la resolución de nombres de dominio produce múltiples direcciones IP, se prueban todas después de fallos de connect(). La función devuelve 1 si la conexión se estableció con éxito. Se devuelve un valor cero o negativo si la conexión no pudo establecerse. La llamada BIO_should_retry() debe usarse para BIOs de conexión no bloqueantes para determinar si la llamada debe reintentarse. Si una conexión ya ha sido establecida, esta llamada no tiene

efecto.

BIO_set_sock_type() puede usarse para establecer un valor de tipo de socket como el que se pasaría en una llamada a socket(2). Los únicos valores admitidos actualmente son SOCK_STREAM (el predeterminado) y SOCK_DGRAM. Si SOCK_DGRAM está configurado, la conexión creada es un socket de datagramas UDP manejado a través de BIO_s_datagram(3). Las llamadas de E/S como BIO_read(3) y BIO_write(3) se reenvían de forma transparente a una instancia interna de BIO_s_datagram(3). La instancia creada de BIO_s_datagram(3) puede recuperarse usando BIO_get0_dgram_bio() si se desea, lo cual escribe un puntero a la instancia de BIO_s_datagram(3) en *dgram_bio. La vida útil de la instancia interna de BIO_s_datagram(3) es gestionada por BIO_s_connect() y no necesita ser liberada por el

llamador.

BIO_get_sock_type() recupera el valor establecido usando BIO_set_so

ck_ty
pe().

NOTA

S

Si la E/S bloqueante está establecida, un valor de retorno no positivo de cualquier llamada de E/S es causado por una condición de error, aunque un retorno cero normalmente significará que la conexión fue

cerrada.

Si el nombre del puerto se proporciona como parte del nombre de host, esto anulará cualquier valor establecido con BIO_set_conn_port(). Esto puede ser indeseable si la aplicación no desea permitir la conexión a puertos arbitrarios. Esto puede evitarse verificando la presencia del carácter ':' en el nombre de host pasado e indicando un error o truncando la cadena en ese

punto.

Los valores devueltos por BIO_get_conn_hostname(), BIO_get_conn_address(), y BIO_get_conn_port() se actualizan cuando se hace un intento de conexión. Antes de cualquier intento de conexión, los valores devueltos son los establecidos por la propia

aplicación.

Las aplicaciones no tienen que llamar a BIO_do_connect() pero pueden desear hacerlo para separar el proceso de conexión de otro procesamiento de

E/S.

Si la E/S no bloqueante está establecida, se solicitarán reintentos según

corresponda.

Además de BIO_should_read() y BIO_should_write(), también es posible que BIO_should_io_special() sea verdadero durante el proceso de conexión inicial con la razón BIO_RR_CONNECT. Si esto se devuelve, es una indicación de que un intento de conexión se bloquearía; la aplicación debería entonces tomar las medidas apropiadas para esperar hasta que el socket subyacente se haya conectado y reintentar la

llamada.

RETORNO

BIO_s_connect() devuelve el método BIO de

conexión.

BIO_set_conn_address(), BIO_set_conn_port(), y BIO_set_conn_ip_family() devuelven 1 o <=0 si ocurre un

error.

BIO_set_conn_hostname() devuelve 1 en éxito y <=0 en

fallo.

BIO_get_conn_address() devuelve la información de dirección o NULL si no se estableció

ninguna.

BIO_get_conn_hostname() devuelve el nombre de host conectado o NULL si no se estableció

ninguno.

BIO_get_conn_ip_family() devuelve la familia de direcciones o -1 si no se estableció

ninguna.

BIO_get_conn_port() devuelve una cadena que representa el puerto conectado o NULL si no está

establecido.

BIO_set_nbio() devuelve 1 o <=0 si ocurre un

error.

BIO_do_connect() devuelve 1 si la conexión se estableció con éxito y <=0 si la conexión

falló.

BIO_set_sock_type() devuelve 1 en éxito o 0 en

fallo.

BIO_get_sock_type() devuelve un tipo de socket o 0 si la llamada no está

soportada.

BIO_get0_dgram_bio() devuelve 1 en éxitoacceso o

0 en caso
de fallo.

S

Este ejemplo se conecta a un servidor web en el host local y intenta recuperar una página y copiar el resultado a la salida

estándar. 
BIO *cbio, *out;
int len;
char tmpbuf[1024];
cbio = BIO_new_connect("localhost:http");
out = BIO_new_fp(stdout, BIO_NOCLOSE);
if (BIO_do_connect(cbio
) <= 0) { fprintf(stderr, "Error connecting to server\n"); ERR_print_errors_fp(stderr); exit(1); } BIO_puts(cbio, "GET / HTTP/1.0\n\n");
for (;;) { len = BIO_read(cbio, tmpbuf, 1024); if (len <= 0) break; BIO_write(out, tmpbuf, len); } BIO_free(cbio); BIO_free(out);
