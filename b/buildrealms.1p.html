-directory target
target es el directorio de destino para los realms que serán construidos por buildrealms. Los nuevos realms no serán movidos a este directorio, pero los archivos de los realms reflejarán el uso de este directorio. Si esta opción no se especifica, se utilizará el directorio actual.

Si -directory y -stagedir usan el mismo directorio, entonces el entorno de realms será construido en el directorio final.

-nobuild
Esta opción le indica a buildrealms que realice los pasos de construcción de los nuevos realms, pero sin construir realmente nada. Si se usa en conjunción con la opción -actions , buildrealms mostrará las acciones que se habrían realizado.
-stagedir directory
Este es el directorio en el que se construye la jerarquía de los nuevos realms. El área de preparación (staging) por defecto es ./staging-buildrealms si esta opción no se especifica.

Si -directory y -stagedir usan el mismo directorio, entonces el entorno de realms será construido en el directorio final.

-quiet
Se impide que buildrealms imprima cualquier salida que no sea de error. Esta opción y la opción -verbose
son mutuamente excluyentes.
-verbose buildrealms imprime mucha información sobre lo que está haciendo. Esta opción y la opción -quiet
son mutuamente excluyentes.
-Version
Muestra el número de versión.

EJEMPLOS Los siguientes ejemplos pueden ayudar a aclarar el uso debuildrealms . En cada ejemplo, se utilizará el siguiente archivo realms.

realm "example"
    state           "active"
    configdir       "configs/example"
    statedir        "states/example"
    realmdir        "r-example"
    rollrec         "demo-example.rollrec"
    administrator   "zonefolks@example.com"
    display         "1"
    manager         "rollerd"
    args            "-loglevel phase -logfile log.example"
    hoard           "r-example"
realm "test"
    state           "active"
    realmdir        "r-test"
    configdir       "configs/test"
    statedir        "states/test"
    rollrec         "demo-test.rollrec"
    manager         "rollerd"
    args            "-loglevel tmi -logfile log.test"
    display         "1"
    hoard           "r-test"
