HOSTRANGED OPCIONES

Las siguientes opciones manipulan la salida de hostranged. Consulte SOPORTE DE HOSTRANGED a continuación para obtener información adicional sobre hostranges.

-B, --buffer-output
Búfer de salida de hostranged. Para cada nodo, almacena en búfer la salida estándar hasta que el nodo haya completado su operación IPMI. Al especificar esta opción, los datos pueden parecer que se muestran más lentamente al usuario, ya que toda la operación IPMI debe completarse antes de que se puedan mostrar los datos. Consulte SOPORTE DE HOSTRANGED a continuación para obtener información adicional.
-C, --consolidate-output
Consolida la salida de hostranged. La salida estándar completa de cada nodo especificado se consolidará de modo que los nodos con salida idéntica no se muestren dos veces. Un encabezado enumerará los nodos con la salida consolidada. Cuando se especifica esta opción, no se puede ver ninguna salida hasta que se completen las operaciones IPMI en todos los nodos. Si el usuario sale anticipadamente del programa, se volcará toda la salida consolidada actualmente. Consulte SOPORTE DE HOSTRANGED a continuación para obtener información adicional.
-F NUM, --fanout=NUM
Especifica la distribución de ventilador de host múltiple. Se utiliza un algoritmo de "ventana deslizante" (o distribución de ventilador) para la comunicación paralela de IPMI, de modo que los nodos lentos o los nodos con tiempo de espera agotado no impidan la comunicación paralela. El número máximo de hilos disponibles al mismo tiempo está limitado por la distribución de ventilador. El valor predeterminado es 64.
-E, --eliminate
Elimina los hosts determinados como no detectados por ipmidetect. Esto intenta eliminar el problema común de que la ejecución de hostranged agote el tiempo de espera debido a que varios nodos se retiran del servicio en un clúster grande. El demonio ipmidetectd debe estar en ejecución en el nodo que ejecuta el comando.
--always-prefix
Prefija la salida siempre, incluso si solo se especifica un host o se comunica en banda. Esta opción es útil principalmente para fines de scripting. La opción se ignorará si se especifica con la opción -C.

SOPORTE DE HOSTRANGED

Se pueden ingresar múltiples hosts ya sea como listas explícitas de hosts separadas por comas o como un rango de nombres de host en la forma general: prefijo[n-m,l-k,...], donde n < m y l < k, etc. La última forma no debe confundirse con las clases de caracteres de expresiones regulares (también denotadas por []). Por ejemplo, foo[19] no representa foo1 o foo9, sino que representa un rango degenerado: foo19.

Esta sintaxis de rango está pensada solo como una conveniencia en clústeres con una convención de nombres prefijoNN y no se debe considerar necesaria la especificación de rangos: la lista foo1,foo9 podría especificarse como tal, o mediante el rango foo[1,9].

A continuación se presentan algunos ejemplos de uso de rangos:

    foo[01-05] en lugar de foo01,foo02,foo03,foo04,foo05
    foo[7,9-10] en lugar de foo7,foo9,foo10
    foo[0-3] en lugar de foo0,foo1,foo2,foo3

Como recordatorio para el lector, algunos shells interpretarán corchetes ([ y ]) para la coincidencia de patrones. Dependiendo de su shell, puede ser necesario encerrar las listas de rangos entre comillas.

Cuando el usuario especifica varios hosts, se ejecutará un hilo para cada host en paralelo hasta la distribución de ventilador configurada (que se puede ajustar a través de la opción -F). Esto permitirá la comunicación a un gran número de nodos mucho más rápido que si se hiciera en serie.

Por defecto, la salida estándar de cada nodo especificado se mostrará con el nombre del host antepuesto a cada línea. Aunque esta salida es legible en muchas situaciones, puede ser difícil de leer en otras situaciones. Por ejemplo, la salida de múltiples nodos puede mezclarse. Las opciones -B y -C se pueden utilizar para cambiar este comportamiento predeterminado.

La comunicación IPMI en banda se utilizará cuando se especifique el host "localhost". Esto permite al usuario agregar el localhost a la salida de hostranged.

SOLUCIÓN DE PROBLEMAS GENERAL

La mayoría de las veces, los problemas de IPMI se deben a problemas de configuración.

Los problemas de IPMI sobre LAN implican una configuración incorrecta del BMC de la máquina remota. Verifique dos veces para asegurarse de que lo siguiente esté configurado correctamente en el BMC de la máquina remota: dirección IP, dirección MAC, máscara de subred, nombre de usuario, habilitación de usuario, privilegio de usuario, contraseña, privilegio de LAN, habilitación de LAN y tipo(s) de autenticación permitidos(s). Para conexiones IPMI 2.0, verifique dos veces para asegurarse de que el privilegio de la suite de cifrado y la clave K_g estén configurados correctamente. La herramienta ipmi-config(8) se puede usar para verificar y/o cambiar estas configuraciones.

Los problemas de IPMI en banda suelen ser causados por controladores configurados incorrectamente o BMC no estándar.

Además de los consejos de solución de problemas a continuación, consulte SOLUCIONES ALTERNATIVAS a continuación también si hay algún error específico del proveedor que se haya descubierto y resuelto.

A continuación, se enumeran muchos de los problemas comunes de mensajes de error. Para obtener soporte adicional, envíe un correo electrónico a la lista de correo <freeipmi-users@gnu.org>.

"username invalid" - El nombre de usuario ingresado (o un nombre de usuario NULL si no se ingresó ninguno) no está disponible en la máquina remota. También es posible que la configuración del nombre de usuario del BMC remoto sea incorrecta.

"password invalid" - La contraseña ingresada (o una contraseña NULL si no se ingresó ninguna) no es correcta. También es posible que la contraseña del usuario no esté configurada correctamente en el BMC remoto.

"password verification timeout" - La verificación de la contraseña ha agotado el tiempo de espera. Ocurrió un error de "contraseña inválida" (descrito anteriormente) o un error genérico de "tiempo de espera de sesión" (descrito a continuación). Durante este punto del protocolo, no se puede diferenciar cuál ocurrió.

"k_g invalid" - La clave K_g ingresada (o una clave K_g NULL si no se ingresó ninguna) no es correcta. También es posible que la clave K_g no esté configurada correctamente en el BMC remoto.

"privilege level insufficient" - Un comando IPMI requiere un privilegio de usuario más alto que el con el que se autenticó. Intente autenticarse con un privilegio más alto. Esto puede requerir autenticarse con un usuario diferente que tenga un privilegio máximo más alto.

"privilege level cannot be obtained for this user" - El nivel de privilegio con el que intenta autenticarse es más alto que el máximo permitido para este usuario. Intente nuevamente con un privilegio más bajo. También es posible que el nivel de privilegio máximo permitido para un usuario no esté configurado correctamente en el BMC remoto.

"authentication type unavailable for attempted privilege level" - El tipo de autenticación con el que desea autenticarse no está disponible para este nivel de privilegio. Intente nuevamente con un tipo de autenticación alternativo o un nivel de privilegio alternativo. También es posible que los tipos de autenticación disponibles con los que puede autenticarse no estén configurados correctamente en el BMC remoto.

"cipher suite id unavailable" - El ID de la suite de cifrado con el que desea autenticarse no está disponible en el BMC remoto. Intente nuevamente con un ID de suite de cifrado alternativo. También es posible que los ID de suite de cifrado disponibles no estén configurados correctamente en el BMC remoto.

"ipmi 2.0 unavailable" - IPMI 2.0 no se descubrió en la máquina remota. Intente usar IPMI 1.5 en su lugar.

"connection timeout" - La comunicación IPMI inicial falló. Son posibles una serie de errores potenciales, que incluyen un nombre de host especificado incorrecto, la dirección IP de IPMI no se puede resolver, IPMI no está habilitado en el servidor remoto, la conexión de red es defectuosa, etc. Verifique la configuración y la conectividad.

"session timeout" - La sesión IPMI ha agotado el tiempo de espera. Vuelva a conectarse. Si este error ocurre con frecuencia, es posible que desee aumentar el tiempo de espera de retransmisión. Algunos BMC remotos son considerablemente más lentos que otros.

"device not found" - No se pudo encontrar el dispositivo especificado. Verifique la configuración o las entradas e intente nuevamente.

"driver timeout" - La comunicación con el controlador o dispositivo ha agotado el tiempo de espera. Intente nuevamente.

"message timeout" - La comunicación con el controlador o dispositivo ha agotado el tiempo de espera. Intente nuevamente.

"BMC busy" - El BMC está ocupado actualmente. Puede estar procesando información o tener demasiadas sesiones simultáneas para administrar. Espere e inténtelo de nuevo.

"could not find inband device" - No se pudo encontrar un dispositivo en banda. Verifique la configuración o especifique un dispositivo o controlador específico en la línea de comandos.

"driver timeout" - El controlador en banda ha agotado el tiempo de espera al comunicarse con el BMC local o el procesador de servicio. El BMC o el procesador de servicio pueden estar ocupados o (en el peor de los casos) posiblemente no funcionen.

SOLUCIONES ALTERNATIVAS

Con tantos proveedores diferentes implementando sus propias soluciones IPMI, diferentes proveedores pueden implementar sus protocolos IPMI incorrectamente. Lo siguiente describe una serie de soluciones alternativas actualmente disponibles para manejar problemas de cumplimiento descubiertos. Cuando sea posible, las soluciones alternativas se han implementado para que sean transparentes para el usuario. Sin embargo, algunas requerirán que el usuario especifique que se utilice una solución alternativa a través de la opción -W.

El hardware que se enumera a continuación puede indicar solo el hardware en el que se descubrió un problema. Las versiones más nuevas de hardware pueden solucionar los problemas indicados a continuación. Máquinas similares de proveedores pueden o no presentar los mismos problemas. Diferentes proveedores pueden licenciar su firmware del mismo desarrollador de firmware IPMI, por lo que puede valer la pena intentar las soluciones alternativas enumeradas a continuación, incluso si su placa base no está listada.

Si cree que su hardware tiene un problema de cumplimiento adicional que requiere la implementación de una solución alternativa, póngase en contacto con los mantenedores de FreeIPMI en <freeipmi-users@gnu.org> o <freeipmi-devel@gnu.org>.

assumeio - Esta bandera de solución alternativa asumirá que las interfaces en banda se comunican con la E/S del sistema en lugar de estar mapeadas en memoria. Esto solucionará problemas en sistemas que informan direcciones base incorrectas. Aquellos que encuentren este problema pueden ver errores como "dispositivo no soportado" o "no se pudo encontrar el dispositivo en banda". Problema observado en HP ProLiant DL145 G1.

spinpoll - Esta bandera de solución alternativa indicará a algunos controladores en banda (notablemente el controlador KCS) que giren mientras encuestan en lugar de poner el proceso a dormir. Esto puede mejorar significativamente el tiempo de ejecución en reloj de pared de las herramientas debido a la granularidad del programador del sistema operativo.

y sea mucho mayor que el tiempo que se tarda en realizar una única transacción de mensaje IPMI. Sin embargo, al hacer un bucle, su sistema puede estar realizando un trabajo menos útil al no cambiar de contexto de la herramienta para una tarea más útil.

authcap - Esta opción de solución temporal omitirá las comprobaciones tempranas de capacidades de nombre de usuario, capacidades de autenticación y soporte de K_g, y permitirá que la autenticación IPMI tenga éxito. Soluciona múltiples problemas en los que el sistema remoto no informa correctamente las capacidades del nombre de usuario, las capacidades de autenticación o el estado de K_g. Aquellos que se encuentren con este problema pueden ver errores como "username invalid" (nombre de usuario no válido), "authentication type unavailable for attempted privilege level" (tipo de autenticación no disponible para el nivel de privilegio intentado) o "k_g invalid" (k_g no válido). Problema observado en Asus P5M2/P5MT-R/RS162-E4/RX4, Intel SR1520ML/X38ML y Sun Fire 2200/4150/4450 con ELOM.

nochecksumcheck - Esta opción de solución temporal le indicará a FreeIPMI que no verifique las sumas de comprobación devueltas por las respuestas de los comandos IPMI. Soluciona sistemas que devuelven sumas de comprobación no válidas debido a errores de implementación, pero el paquete es válido de otro modo. Se advierte a los usuarios sobre el uso de esta opción, ya que elimina la validación de la integridad del paquete en una serie de circunstancias. Sin embargo, es poco probable que sea un problema en la mayoría de las situaciones. Aquellos que se encuentren con este problema pueden ver errores como "connection timeout" (tiempo de espera de conexión agotado), "session timeout" (tiempo de espera de sesión agotado) o "password verification timeout" (tiempo de espera de verificación de contraseña agotado). En conexiones IPMI 1.5, también puede ser necesaria la solución temporal "noauthcodecheck". Problema observado en Supermicro X9SCM-iiF, Supermicro X9DRi-F y Supermicro X9DRFR.

idzero - Esta opción de solución temporal permitirá que el cliente acepte identificadores de sesión vacíos. Soluciona sesiones IPMI que informan identificadores de sesión vacíos al cliente. Aquellos que se encuentren con este problema pueden ver errores como "session timeout" (tiempo de espera de sesión agotado). Problema observado en Tyan S2882 con BMC M3289.

unexpectedauth - Esta opción de solución temporal permitirá que los códigos de autenticación no nulos inesperados se verifiquen como si se esperaran. Soluciona un problema cuando los paquetes contienen datos de autenticación no nulos cuando deberían ser nulos debido a la autenticación por mensaje deshabilitada. Aquellos que se encuentren con este problema pueden ver errores como "session timeout" (tiempo de espera de sesión agotado). Problema observado en Dell PowerEdge 2850, SC1425. Confirmado como corregido en firmware más reciente.

forcepermsg - Esta opción de solución temporal forzará el uso de la autenticación por mensaje, independientemente de lo que anuncie el sistema remoto. Soluciona un problema cuando la autenticación por mensaje se anuncia como deshabilitada en el sistema remoto, pero en realidad es necesaria para el protocolo. Aquellos que se encuentren con este problema pueden ver errores como "session timeout" (tiempo de espera de sesión agotado). Problema observado en IBM eServer 325.

endianseq - Esta opción de solución temporal invertirá el orden de los bytes (endian) de los números de secuencia de sesión para permitir que la sesión continúe correctamente. Soluciona números de secuencia de sesión de IPMI 1.5 que tienen el orden de bytes (endian) incorrecto. Aquellos que se encuentren con este problema pueden ver errores como "session timeout" (tiempo de espera de sesión agotado). Problema observado en algunos Sun ILOM 1.0/2.0 (depende del orden de bytes del procesador de servicio).

noauthcodecheck - Esta opción de solución temporal le indicará a FreeIPMI que no verifique los códigos de autenticación devueltos por las respuestas de los comandos IPMI 1.5. Soluciona sistemas que devuelven códigos de autenticación no válidos debido a errores de hashing o de implementación. Se advierte a los usuarios sobre el uso de esta opción, ya que elimina una comprobación de autenticación que verifica la validez de un paquete. Sin embargo, en la mayoría de las organizaciones, es poco probable que sea un problema de seguridad. Aquellos que se encuentren con este problema pueden ver errores como "connection timeout" (tiempo de espera de conexión agotado), "session timeout" (tiempo de espera de sesión agotado) o "password verification timeout" (tiempo de espera de verificación de contraseña agotado). Problema observado en Xyratex FB-H8-SRAY, Intel Windmill, Quanta Winterfell y Wiwynn Windmill.

intel20 - Esta opción de solución temporal solucionará varios problemas de autenticación de IPMI 2.0 de Intel. Los problemas cubiertos incluyen el relleno de nombres de usuario y el truncamiento de contraseñas si el algoritmo de autenticación es HMAC-MD5-128. Aquellos que se encuentren con este problema pueden ver errores como "username invalid" (nombre de usuario no válido), "password invalid" (contraseña no válida) o "k_g invalid" (k_g no válido). Problema observado en Intel SE7520AF2 con Intel Server Management Module (Professional Edition).

supermicro20 - Esta opción de solución temporal solucionará varios problemas de autenticación de IPMI 2.0 de Supermicro en placas base con firmware IPMI de Peppercon. Los problemas cubiertos incluyen el manejo de códigos de autenticación de longitud no válida. Aquellos que se encuentren con este problema pueden ver errores como "password invalid" (contraseña no válida). Problema observado en Supermicro H8QME con tarjeta hija SIMSO. Confirmado como corregido en firmware más reciente.

sun20 - Esta opción de solución temporal solucionará varios problemas de autenticación de IPMI 2.0 de Sun. Los problemas cubiertos incluyen claves hash de longitud no válida, claves con hash incorrecto y registros de suite de cifrado no válidos. Aquellos que se encuentren con este problema pueden ver errores como "password invalid" (contraseña no válida) o "bmc error" (error de BMC). Problema observado en Sun Fire 4100/4200/4500 con ILOM. Esta solución temporal incluye automáticamente la solución temporal "opensesspriv".

opensesspriv - Esta opción de solución temporal alterará ligeramente el protocolo de conexión IPMI 2.0 de FreeIPMI para solucionar un algoritmo de hashing no válido utilizado por el sistema remoto. El nivel de privilegio enviado durante la etapa de Apertura de Sesión (Open Session) de una conexión IPMI 2.0 se utiliza para el hashing de claves en lugar del nivel de privilegio enviado durante la etapa de conexión RAKP1. Aquellos que se encuentren con este problema pueden ver errores como "password invalid" (contraseña no válida), "k_g invalid" (k_g no válido), "bad rmcpplus status code" (código de estado rmcpplus incorrecto) o "privilege level cannot be obtained for this user" (no se puede obtener el nivel de privilegio para este usuario). Problema observado en Sun Fire 4100/4200/4500 con ILOM, Inventec 5441/Dell Xanadu II, Supermicro X8DTH, Supermicro X8DTG, Intel S5500WBV/Penguin Relion 700, Intel S2600JF/Appro 512X, Quanta QSSC-S4R/Appro GB812X-CN, Dell C5220 y el software BMC OpenIPMI. Esta solución temporal se activa automáticamente con la solución temporal "sun20".

integritycheckvalue - Esta opción de solución temporal solucionará un valor de comprobación de integridad no válido durante el establecimiento de una sesión IPMI 2.0 al usar el ID de Suite de Cifrado 0. El valor de comprobación de integridad debería tener una longitud de 0, sin embargo, la placa base remota responde con un campo no vacío. Aquellos que se encuentren con este problema pueden ver errores como "k_g invalid" (k_g no válido). Problema observado en Supermicro X8DTG, Supermicro X8DTU, Intel S5500WBV/Penguin Relion 700 e Intel S2600JF/Appro 512X.

assumemaxsdrrecordcount - Esta opción de solución temporal informará a la lectura de SDR que deje de leer después de que se hayan leído un número máximo conocido de registros SDR. Esto solucionará sistemas que tienen funciones de lectura de SDR mal implementadas. Aquellos que se encuentren con este problema pueden ver errores como "SDR record count invalid" (recuento de registros SDR no válido). Problema observado en una placa base Inspur no especificada.

Sin soporte para IPMI 1.5 - Se ha descubierto que algunas placas base que soportan IPMI 2.0 no soportan IPMI 1.5. Aquellos que se encuentren con este problema pueden ver errores como "ipmi 2.0 unavailable" (ipmi 2.0 no disponible) o "connection timeout" (tiempo de espera de conexión agotado). Este problema se puede solucionar usando IPMI 2.0 en lugar de IPMI 1.5 especificando --driver-type=LAN_2_0. Problema observado en un número de placas base de HP y Supermicro.

EJEMPLOS

# bmc-device --cold-reset

Realiza un reinicio en frío.

# bmc-device -h ahost -u myusername -p mypassword --cold-reset

Realiza un reinicio en frío de una máquina remota usando IPMI sobre LAN.

# bmc-device -h mycluster[0-127] -u myusername -p mypassword --cold-reset

Realiza un reinicio en frío en un clúster usando IPMI sobre LAN.

DIAGNÓSTICOS

Tras una ejecución exitosa, el estado de salida es 0. En caso de error, el estado de salida es 1.

Si se especifican múltiples hosts para la comunicación, el estado de salida es 0 si y solo si todos los objetivos se ejecutan correctamente. De lo contrario, el estado de salida es 1.

PROBLEMAS CONOCIDOS

En sistemas operativos antiguos, si introduce su nombre de usuario, contraseña y otra información potencialmente relevante para la seguridad en la línea de comandos, esta información puede ser descubierta por otros usuarios al usar herramientas como el ps(1) o al mirar en el sistema de archivos /proc. Generalmente es más seguro introducir la información de la contraseña con opciones como -P o -K. Configurar la información relevante para la seguridad en el archivo de configuración de FreeIPMI también sería una forma apropiada de ocultar esta información.

Para prevenir ataques de fuerza bruta, algunos BMC se "bloquearán" temporalmente después de un número de errores de autenticación remota. Puede que necesite esperar un tiempo para que este bloqueo temporal pase antes de que pueda autenticarse de nuevo.
