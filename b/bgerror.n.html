bgerror(n) Comandos integrados de Tcl bgerror(n)

NOMBRE

bgerror - Comando invocado para procesar errores en segundo plano

SINOPSIS

bgerror mensaje

DESCRIPCIÓN

La versión 8.5 de Tcl soporta el comando interp bgerror, que permite a las aplicaciones registrar en un intérprete el comando que manejará los errores en segundo plano en ese intérprete. En versiones anteriores de Tcl, este nivel de control no estaba disponible, y las aplicaciones solo podían controlar el manejo de errores en segundo plano creando un comando con el nombre particular bgerror en el espacio de nombres global de un intérprete. La siguiente documentación describe los requisitos de interfaz del comando bgerror que una aplicación podría definir para mantener la compatibilidad con las versiones de Tcl anteriores a la 8.5. Las aplicaciones que solo pretenden dar soporte a las versiones de Tcl 8.5 y posteriores solo deberían usar interp bgerror.

El comando bgerror no existe como parte integrada de Tcl. En su lugar, las aplicaciones individuales o los usuarios pueden definir un comando bgerror (por ejemplo, como un procedimiento Tcl) si desean manejar errores en segundo plano.

Un error en segundo plano es uno que ocurre en un manejador de eventos o en algún otro comando que no se originó en la aplicación. Por ejemplo, si ocurre un error mientras se ejecuta un comando especificado con el comando after, entonces es un error en segundo plano. Para un error no en segundo plano, el error simplemente puede devolverse a través de evaluaciones anidadas de comandos Tcl hasta que llegue al código de nivel superior en la aplicación; entonces la aplicación puede informar el error de la manera que desee. Cuando ocurre un error en segundo plano, el desenrollado termina en la biblioteca Tcl y no hay una forma obvia para que Tcl informe el error.

Cuando Tcl detecta un error en segundo plano, guarda información sobre el error e invoca un comando manejador registrado por interp bgerror más tarde como un manejador de eventos inactivo. El comando manejador predeterminado, a su vez, llama al comando bgerror. Antes de invocar bgerror, Tcl restaura las variables errorInfo y errorCode a sus valores en el momento en que ocurrió el error, y luego invoca bgerror con el mensaje de error como su único argumento. Tcl asume que la aplicación ha implementado el comando bgerror, y que el comando informará el error de una manera que tenga sentido para la aplicación. Tcl ignorará cualquier resultado devuelto por el comando bgerror siempre que no se genere ningún error.

Si ocurre otro error Tcl dentro del comando bgerror (por ejemplo, porque no se ha definido ningún comando bgerror), entonces Tcl informará el error escribiendo un mensaje en stderr.

Si se acumulan varios errores en segundo plano antes de que se invoque bgerror para procesarlos, bgerror se invocará una vez por cada error, en el orden en que ocurrieron. Sin embargo, si bgerror devuelve una excepción de interrupción (break), entonces los errores restantes se omiten sin llamar a bgerror.

Si está escribiendo código que será utilizado por otros como parte de un paquete o algún otro tipo de biblioteca, considere evitar bgerror. La razón de esto es que el programador de la aplicación también puede querer definir un bgerror, o usar otro código que lo haga y, por lo tanto, tendrá problemas para integrar su código.

EJEMPLO

Este procedimiento bgerror añade errores a un archivo, con una marca de tiempo.

proc bgerror {message} {
    set timestamp [clock format [clock seconds]]
    set fl [open mylog.txt {WRONLY CREAT APPEND}]
    puts $fl "$timestamp: bgerror en $::argv '$message'"
    close $fl
}
