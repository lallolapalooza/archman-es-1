bpf(2) Manual de Llamadas al Sistema bpf(2)

NOMBRE

bpf - realizar un comando en un mapa o programa BPF extendido

SINOPSIS

#include <linux/bpf.h>
int bpf(int cmd, union bpf_attr *attr, unsigned int size);

DESCRIPCIÓN

La llamada al sistema bpf() realiza una serie de operaciones relacionadas con los filtros de paquetes Berkeley extendidos. Berkeley Packet Filter extendido (o eBPF) es similar al BPF original ("clásico") (cBPF) utilizado para filtrar paquetes de red. Para ambos programas, cBPF y eBPF, el kernel analiza estáticamente los programas antes de cargarlos, para garantizar que no puedan dañar el sistema en ejecución.

eBPF extiende cBPF de múltiples maneras, incluida la capacidad de llamar a un conjunto fijo de funciones de ayuda en el kernel (a través de la extensión de opcode BPF_CALL proporcionada por eBPF) y acceder a estructuras de datos compartidas como los mapas eBPF.

Diseño/Arquitectura BPF Extendida

Los mapas eBPF son una estructura de datos genérica para el almacenamiento de diferentes tipos de datos. Los tipos de datos generalmente se tratan como bloques binarios, por lo que un usuario simplemente especifica el tamaño de la clave y el tamaño del valor en el momento de la creación del mapa. En otras palabras, una clave/valor para un mapa dado puede tener una estructura arbitraria.

Un proceso de usuario puede crear múltiples mapas (con pares clave/valor siendo bytes de datos opacos) y acceder a ellos a través de descriptores de archivo. Diferentes programas eBPF pueden acceder a los mismos mapas en paralelo. Depende del proceso de usuario y del programa eBPF decidir qué almacenar dentro de los mapas.

Hay un tipo especial de mapa, llamado array de programas. Este tipo de mapa almacena descriptores de archivo que hacen referencia a otros programas eBPF. Cuando se realiza una búsqueda en el mapa, el flujo del programa se redirige in situ al principio de otro programa eBPF y no devuelve el control al programa que lo llama. El nivel de anidamiento tiene un límite fijo de 32, de modo que no se puedan crear bucles infinitos. En tiempo de ejecución, los descriptores de archivo de programas almacenados en el mapa se pueden modificar, por lo que la funcionalidad del programa se puede alterar según los requisitos específicos. Todos los programas a los que se hace referencia en un mapa de array de programas deben haberse cargado previamente en el kernel a través de bpf(). Si una búsqueda de mapa falla, el programa actual continúa su ejecución. Consulte BPF_MAP_TYPE_PROG_ARRAY más abajo para obtener más detalles.

En general, los programas eBPF son cargados por el proceso de usuario y descargados automáticamente cuando el proceso sale. En algunos casos, por ejemplo, tc-bpf(8), el programa seguirá vivo dentro del kernel incluso después de que el proceso que cargó el programa termine. En ese caso, el subsistema tc mantiene una referencia al programa eBPF después de que el programa de espacio de usuario haya cerrado el descriptor de archivo. Por lo tanto, si un programa específico continúa vivo dentro del kernel depende de cómo se adjunte posteriormente a un subsistema del kernel dado después de haber sido cargado a través de bpf().

Cada programa eBPF es un conjunto de instrucciones que es seguro ejecutar hasta su finalización. Un verificador del kernel determina estáticamente que el programa eBPF termina y es seguro de ejecutar. Durante la verificación, el kernel incrementa los recuentos de referencia de cada uno de los mapas que utiliza el programa eBPF, de modo que los mapas adjuntos no se puedan eliminar hasta que se descargue el programa.

Los programas eBPF se pueden adjuntar a diferentes eventos. Estos eventos pueden ser la llegada de paquetes de red, eventos de trazado, eventos de clasificación por disciplinas de colas de red (para programas eBPF adjuntos a un clasificador tc(8)) y otros tipos que se puedan añadir en el futuro. Un nuevo evento activa la ejecución del programa eBPF, que puede almacenar información sobre el evento en mapas eBPF. Más allá de almacenar datos, los programas eBPF pueden llamar a un conjunto fijo de funciones de ayuda en el kernel.

El mismo programa eBPF se puede adjuntar a múltiples eventos y diferentes programas eBPF pueden acceder al mismo mapa:

evento A     evento B    evento C    en eth0     en eth1    en eth2

Argumentos

La operación a realizar por la llamada al sistema bpf() se determina mediante el argumento cmd. Cada operación toma un argumento complementario, proporcionado a través de attr, que es un puntero a una unión del tipo bpf_attr (ver abajo). Los campos no utilizados y el relleno deben ponerse a cero antes de la llamada. El argumento size es el tamaño de la unión apuntada por attr.

El valor proporcionado en cmd es uno de los siguientes:

BPF_MAP_CREATE
Crea un mapa y devuelve un descriptor de archivo que se refiere al mapa. La bandera de archivo cerrado al ejecutar (ver fcntl(2)) se habilita automáticamente para el nuevo descriptor de archivo.
BPF_MAP_LOOKUP_ELEM
Busca un elemento por clave en un mapa especificado y devuelve su valor.
BPF_MAP_UPDATE_ELEM
Crea o actualiza un elemento (par clave/valor) en un mapa especificado.
BPF_MAP_DELETE_ELEM
Busca y elimina un elemento por clave en un mapa especificado.
BPF_MAP_GET_NEXT_KEY
Busca un elemento por clave en un mapa especificado y devuelve la clave del siguiente elemento.
BPF_PROG_LOAD
Verifica y carga un programa eBPF, devolviendo un nuevo descriptor de archivo asociado con el programa. La bandera de archivo cerrado al ejecutar (ver fcntl(2)) se habilita automáticamente para el nuevo descriptor de archivo.
La unión bpf_attr consta de varias estructuras anónimas que son utilizadas por diferentes comandos de bpf():


union bpf_attr {
    struct {    /* Usado por BPF_MAP_CREATE */
        __u32         map_type;
        __u32         key_size;    /* tamaño de la clave en bytes */
        __u32         value_size;  /* tamaño del valor en bytes */
        __u32         max_entries; /* número máximo de entradas
                                      en un mapa */
    };
    struct {    /* Usado por los comandos BPF_MAP_*_ELEM y BPF_MAP_GET_NEXT_KEY
                   */
        __u32         map_fd;
        __aligned_u64 key;
        union {
            __aligned_u64 value;
            __aligned_u64 next_key;
        };
        __u64         flags;
    };
    struct {    /* Usado por BPF_PROG_LOAD */
        __u32         prog_type;
        __u32         insn_cnt;
        __aligned_u64 insns;      /* 'const struct bpf_insn *' */
        __aligned_u64 license;    /* 'const char *' */
        __u32         log_level;  /* nivel de verbosidad del verificador */
        __u32         log_size;   /* tamaño del buffer del usuario */
        __aligned_u64 log_buf;    /* buffer 'char *' suministrado por el usuario */
        __u32         kern_version;
                                  /* comprobado cuando prog_type=kprobe
                                     (desde Linux 4.1) */
    };
} __attribute__((aligned(8)));

Mapas eBPF

Los mapas son una estructura de datos genérica para el almacenamiento de diferentes tipos de datos. Permiten compartir datos entre programas eBPF del kernel y también entre aplicaciones del kernel y del espacio de usuario.

Cada tipo de mapa tiene los siguientes atributos:

•
tipo
•
número máximo de elementos
•
tamaño de la clave en bytes
•
tamaño del valor en bytes

Las siguientes funciones envoltorio demuestran cómo se pueden usar varios comandos de bpf() para acceder a los mapas. Las funciones usan el argumento cmd para invocar diferentes operaciones.

BPF_MAP_CREATE
Crea un mapa. Los campos relevantes de la estructura bpf_attr se inicializan como sigue:


attr.map_type = BPF_MAP_TYPE_HASH; /* o BPF_MAP_TYPE_ARRAY, etc. */
attr.key_size = sizeof(key);
attr.value_size = sizeof(value);
attr.max_entries = max_entries;

Los mapas se pueden crear con los siguientes tipos:

BPF_MAP_TYPE_HASH
Tabla hash. Las búsquedas, actualizaciones y eliminaciones son O(1) en promedio.
BPF_MAP_TYPE_ARRAY
Array. Las búsquedas, actualizaciones y eliminaciones son O(1).
BPF_MAP_TYPE_PROG_ARRAY
Array de programas. Los elementos son descriptores de archivo de programas eBPF. La búsqueda de un elemento devuelve el descriptor de archivo del programa eBPF para su ejecución, o devuelve un valor de error si el descriptor de archivo no es válido o no está establecido.

El descriptor de archivo devuelto se puede utilizar para realizar operaciones en los elementos del mapa.

BPF_MAP_LOOKUP_ELEM
Busca un elemento en el mapa por su clave y copia el valor asociado en el buffer del usuario. Los campos relevantes de la estructura bpf_attr se inicializan como sigue:


attr.map_fd = map_fd;
attr.key = (uintptr_t)&key;
attr.value = (uintptr_t)&value;

El valor recuperado se copia en el buffer de memoria del usuario apuntado por `attr.value`.

BPF_MAP_UPDATE_ELEM
Actualiza un elemento en el mapa con el par clave/valor proporcionado. Si la clave ya existe, se actualiza su valor. Si no existe, se inserta un nuevo elemento. Los campos relevantes de la estructura bpf_attr se inicializan como sigue:


attr.map_fd = map_fd;
attr.key = (uintptr_t)&key;
attr.value = (uintptr_t)&value;
attr.flags = flags; /* BPF_ANY, BPF_NOEXIST, o BPF_EXIST */

El campo flags se puede establecer en:

BPF_ANY
Reemplaza el elemento existente o lo inserta si no existe.
BPF_NOEXIST
Inserta el elemento solo si la clave no existe.
BPF_EXIST
Actualiza el elemento solo si la clave ya existe.

Las operaciones fallarán con EEXIST si se utiliza BPF_NOEXIST y la clave ya existe, o con ENOENT si se utiliza BPF_EXIST y la clave no existe.

BPF_MAP_DELETE_ELEM
Elimina un elemento del mapa por su clave. Los campos relevantes de la estructura bpf_attr se inicializan como sigue:


attr.map_fd = map_fd;
attr.key = (uintptr_t)&key;
BPF_MAP_GET_NEXT_KEY
Devuelve la clave del siguiente elemento en el mapa. Si se proporciona una clave válida, se devuelve la clave del siguiente elemento después de ella. Si se proporciona una clave nula (es decir, todos los bits a 0), se devuelve la clave del primer elemento del mapa. Los campos relevantes de la estructura bpf_attr se inicializan como sigue:


attr.map_fd = map_fd;
attr.key = (uintptr_t)&key;      /* Clave actual o clave nula */
attr.next_key = (uintptr_t)&next_key; /* Buffer para la siguiente clave */

La operación falla con ENOENT si no hay más claves.

Carga de programas eBPF

El comando BPF_PROG_LOAD se utiliza para cargar un programa eBPF en el kernel. El programa consiste en una secuencia de instrucciones eBPF (struct bpf_insn). El kernel realiza una verificación exhaustiva del programa para garantizar que sea seguro y que termine. Si la verificación se realiza correctamente, se devuelve un descriptor de archivo para el programa cargado.

Los campos relevantes de la estructura bpf_attr se inicializan como sigue:

attr.prog_type = prog_type;
attr.insns = (uintptr_t)insns;
attr.insn_cnt = insn_cnt;
attr.license = (uintptr_t)license;
attr.log_level = log_level;
attr.log_size = log_size;
attr.log_buf = (uintptr_t)log_buf;
attr.kern_version = kern_version;

Los tipos de programa soportados (prog_type) incluyen:

BPF_PROG_TYPE_SOCKET_FILTER
Programas para filtrar paquetes de red en sockets.
BPF_PROG_TYPE_KPROBE
Programas para adjuntar a kprobes (eventos de kernel).
BPF_PROG_TYPE_TRACING
Programas para trazado genérico (usando kprobes o uprobes).
BPF_PROG_TYPE_SCHED_CLS
Programas para clasificación de paquetes en tc (traffic control).
BPF_PROG_TYPE_SCHED_ACT
Programas para acciones en tc.
BPF_PROG_TYPE_XDP
Programas para el framework de Data Path de alto rendimiento (XDP).

El campo license es una cadena de caracteres que indica la licencia del programa eBPF. Es obligatorio para poder usar las funciones de ayuda del kernel. El kernel verifica que la licencia permita el uso de las funciones de ayuda. Se debe usar una licencia SPDX compatible, como "GPL".

Los campos log_level, log_size y log_buf se utilizan para recopilar información de depuración y errores generada por el verificador del kernel. Si la verificación falla, esta información estará disponible en log_buf.

El campo kern_version se usa para indicar la versión del kernel para la que se compiló el programa. Esto es importante para la compatibilidad y para acceder a nuevas funciones o estructuras de datos del kernel.

DEVOLUCIÓN

En caso de éxito, bpf() devuelve un descriptor de archivo no negativo. En caso de error, devuelve -1 y establece errno para indicar el error.

ERRORES

EACCES
Se intentó una operación prohibida (por ejemplo, acceder a un mapa sin los permisos adecuados).
EFAULT
Se especificó una dirección de memoria inválida en attr.
EINVAL
Se especificó un argumento inválido (por ejemplo, un tipo de mapa desconocido, un número de instrucciones incorrecto, o una licencia inválida).
EEXIST
Se intentó insertar un elemento en un mapa usando BPF_NOEXIST y la clave ya existe.
ENOENT
Se intentó buscar un elemento que no existe en el mapa, o se intentó eliminar/actualizar un elemento que no existe usando BPF_EXIST. También se devuelve si no hay más claves en BPF_MAP_GET_NEXT_KEY.
ENOMEM
No hay suficiente memoria disponible en el kernel.
ENOSPC
El mapa ha alcanzado su número máximo de entradas.
EPERM
Se requiere un privilegio de administrador para la operación.
E2BIG
El tamaño del buffer de registro es demasiado pequeño.

VERSIÓN

La llamada al sistema bpf() está disponible desde Linux 3.18.

EJEMPLOS

Aquí hay un ejemplo simple de cómo crear un mapa de tipo hash y actualizar/leer un elemento:


#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <linux/bpf.h>
#include <sys/syscall.h>

// Helper macro para llamar a la syscall bpf()
static inline int bpf_syscall(int cmd, union bpf_attr *attr, unsigned int size) {
    return syscall(__NR_bpf, cmd, attr, size);
}

int main() {
    union bpf_attr attr = {0};
    int map_fd;
    int key = 1, value = 123;
    int retrieved_value;

    // Crear un mapa hash
    attr.map_type = BPF_MAP_TYPE_HASH;
    attr.key_size = sizeof(key);
    attr.value_size = sizeof(value);
    attr.max_entries = 100;

    map_fd = bpf_syscall(BPF_MAP_CREATE, &attr, sizeof(attr));
    if (map_fd < 0) {
        perror("BPF_MAP_CREATE failed");
        return 1;
    }

    printf("Map created with fd: %d\n", map_fd);

    // Actualizar un elemento
    attr.map_fd = map_fd;
    attr.key = (uintptr_t)&key;
    attr.value = (uintptr_t)&value;
    attr.flags = BPF_ANY; // Sobrescribir si existe, insertar si no

    if (bpf_syscall(BPF_MAP_UPDATE_ELEM, &attr, sizeof(attr)) < 0) {
        perror("BPF_MAP_UPDATE_ELEM failed");
        close(map_fd);
        return 1;
    }

    printf("Element updated: key=%d, value=%d\n", key, value);

    // Buscar el elemento
    memset(&attr, 0, sizeof(attr)); // Limpiar la estructura para la siguiente operación
    attr.map_fd = map_fd;
    attr.key = (uintptr_t)&key;
    attr.value = (uintptr_t)&retrieved_value; // Buffer para el valor recuperado

    if (bpf_syscall(BPF_MAP_LOOKUP_ELEM, &attr, sizeof(attr)) < 0) {
        perror("BPF_MAP_LOOKUP_ELEM failed");
        close(map_fd);
        return 1;
    }

    printf("Element looked up: key=%d, value=%d\n", key, retrieved_value);

    // Eliminar el elemento
    memset(&attr, 0, sizeof(attr));
    attr.map_fd = map_fd;
    attr.key = (uintptr_t)&key;

    if (bpf_syscall(BPF_MAP_DELETE_ELEM, &attr, sizeof(attr)) < 0) {
        perror("BPF_MAP_DELETE_ELEM failed");
        close(map_fd);
        return 1;
    }

    printf("Element deleted: key=%d\n", key);

    close(map_fd);
    return 0;
}

Para compilar y ejecutar este ejemplo, necesitará las cabeceras del kernel de Linux. Puede instalarlas con el paquete linux-headers.


gcc -o bpf_example bpf_example.c
sudo ./bpf_example

Nota: este programa requiere privilegios de administrador (root) para crear mapas eBPF.
