defragment [opciones] <archivo>|<directorio> [<archivo>|<directorio>
...]
Desfragmentar datos de archivos en un sistema de archivos montado. Requiere el kernel 2.6.33 o más reciente.

Si se pasa -r, los archivos en directorio serán desfragmentados recursivamente (sin descender a subvolúmenes, puntos de montaje y enlaces simbólicos de directorio). La posición de inicio y el número de bytes a desfragmentar pueden ser especificados por inicio y longitud usando -s y -l opciones abajo. Las extensiones más grandes que el valor dado por -t serán omitidas, de lo contrario este valor se usa como un tamaño de extensión objetivo, pero es solo consultivo y puede no alcanzarse si el espacio libre está demasiado fragmentado. Usa 0 para tomar el valor predeterminado del kernel, que es 256KiB pero puede cambiar en el futuro. También puedes activar la compresión en operaciones de

desfragmentación.

El devid se puede encontrar en la salida de btrfs filesystem show y es 1 por defecto si no se especifica. El parámetro tamaño especifica el nuevo tamaño del sistema de archivos. Si el prefijo + o - está presente, el tamaño se incrementa o disminuye en la cantidad tamaño. Si no se especifican unidades, se asume que son bytes para tamaño. Opcionalmente, el parámetro tamaño puede tener un sufijo de uno de los siguientes designadores de unidad: K, M, G, T, P o E, que representan KiB, MiB, GiB, TiB, PiB o EiB, respectivamente (no importa mayúsculas o minúsculas)

.

Si se pasa max, el sistema de archivos ocupará todo el espacio disponible en el dispositivo respetando devid (recuerde, devid 1 por defecto)

.

El comando resize no manipula el tamaño de la partición subyacente. Si desea ampliar/reducir un sistema de archivos, debe asegurarse de expandir la partición antes de ampliar el sistema de archivos y reducir la partición después de reducir el tamaño del sistema de archivos. Esto se puede hacer usando fdisk(8) https://man7.org/linux/man-pages/man8/fdisk.8.html o parted(8) https://man7.org/linux/man-pages/man8/parted.8.html para eliminar la partición existente y recrearla con el nuevo tamaño deseado. Al recrear la partición, asegúrese de usar el mismo desplazamiento de inicio de la partición que

antes.

El tamaño de la porción que el sistema de archivos usa de un dispositivo subyacente se puede determinar a través del comando btrfs filesystem show --raw en el punto de montaje del sistema de archivos (donde se da para cada devid después de la cadena size o a través del comando btrfs inspect-internal dump-super en el dispositivo específico (donde se da como el valor de dev_item.total_bytes, que no debe confundirse con total_bytes). El valor es también la dirección de el primer byte no utilizado por el sistema de

archivos.

El crecimiento suele ser instantáneo ya que solo actualiza el tamaño. Sin embargo, la reducción podría llevar mucho tiempo si hay datos en el área del dispositivo que están más allá del nuevo final. La reubicación de los datos lleva

tiempo.

Tenga en cuenta que hay un límite inferior para el nuevo tamaño (ya sea especificado como un tamaño absoluto o como una diferencia) que es verificado por el kernel y rechazado finalmente como inválido. Los valores más bajos imprimirán una advertencia pero aún pasarán la solicitud al kernel. El valor conocido actualmente es

256MiB.

NAME

btrfs-filesystem – manage btrfs filesystem(s)

SYNOPSIS

btrfs filesystem subcommand [-h | --help] [-V | --version]

btrfs filesystem defrag [-c alg] [-f] [-r] [-v] [-z] [-t size] path...

btrfs filesystem du [-summarize] [-used] [-bytes] [-human] [-Human] [--sync] [--all-devicesall] path...

btrfs filesystem df [-human] [--human-readablereadable] [--kbyteskbytes] [--megabytesmegabytes] [--gigabytesgigabytes] [--terabytesterabytes] [--rawraw] [--print-sizesize] [--backgroundbackground] [--rootid [rootid] [path] [--tree-log-uuiduuid]

btrfs filesystem resize [+/-]size[bytes|kbytes|mbytes|gbytes|tbytes|pbytes] [-+|-]size[compressed] [devid:devid:]path...

btrfs filesystem show [-force] path...

btrfs filesystem sync path

btrfs filesystem usage [--rawraw] [-human] [-Human] [--kbyteskbytes] [--mbytesmegabytes] [--gbytesgigabytes] [--tbytesterabytes] [--ieciec] [--sisi] [-Table] path...

DESCRIPTION

This command group manages filesystem-level operations on btrfs filesystem(s). The subcommands perform operations like defragmentation, changing filesystem size, showing filesystem usage, etc.

SUBCOMMAND

defrag [-c alg] [-f] [-r] [-v] [-z] [-t size] path...
Defragment the file(s) specified by path. If a directory is specified, the operation is recursive by default, unless -r is not given.

Options:

-c alg
Use compression alg for the defrag operation. The available algorithms are zlib, lzo, zstd, and no compression. This option implies -z.
-f
Force defragmentation of all files. Without this option, files smaller than 128MiB are skipped, or if the file is already larger than 128MiB, files with more than 2 extents are skipped.
-r
Recursively defragment directories. This is the default behaviour for directories.
-v
Be verbose, print files as they are processed.
-z
Try to use fewer extents when possible. This option is implied by -c.
-t size
Try to merge extents to reach the target size. The default extent size is 0 (no specific target).
du [-summarize] [-used] [-bytes] [-human] [-Human] [--syncsync] [--all-devicesall] path...
Display the disk usage of files/directories in the filesystem.

Options:

-s summarize
Display only a total for each argument specified.
-u used
Display human readable sizes, but do not show the full size of files. Only show the space used by files.
-b bytes
Display sizes in bytes.
-h human
Display human readable sizes (e.g. 1K, 2M, 3G).
-H human
Display human readable sizes, but use powers of 1000 instead of 1024.
--sync sync
Ensure that the filesystem is synchronized before running the command.
--all-devices all
Print usage for all devices, not just the one the path resides on.

resize [+/-]size[bytes|kbytes|mbytes|gbytes|tbytes|pbytes] [-+|-]size[compressed] [devid:devid:]path...
Resize the filesystem. The size can be specified as an absolute value or relative to the current size (using '+' or '-'). The unit suffix can be 'b' (bytes), 'k' (KiB), 'm' (MiB), 'g' (GiB), 't' (TiB), 'p' (PiB). Alternatively, 'max' can be used to resize to the maximum possible size.

The optional devid: prefix specifies which device to resize in a multi-device filesystem.

The -+ and - options can be used to increase or decrease the filesystem size. The c suffix indicates that the size should be compressed (e.g. if the filesystem is mounted with compression).

Examples:

btrfs filesystem resize -1G /path
Shrink the filesystem by 1 GiB.
btrfs filesystem resize max /path
Expand the filesystem to the maximum possible size.
show [-force] path...
Show filesystem information.

Options:

-f force
Force the operation even if the filesystem is not clean.
sync path
Force a sync of the filesystem at path, similar to the sync(1) command. In addition, it starts cleaning of deleted subvolumes. To wait for the subvolume deletion to complete use the btrfs subvolume sync command.

  • Device size -- sum of raw device capacity available to the filesystem, note that this may not be the same as the total device size (the difference is accounted as slack)
  • Device allocated -- sum of total space allocated for data/metadata/system profiles, this also accounts space reserved but not yet used for extents
  • Device unallocated -- the remaining unallocated space for future allocations (difference of the above two numbers)
  • Device missing -- sum of capacity of all missing devices
  • Device slack -- sum of slack space on all devices (difference between entire device size and the space occupied by filesystem)
  • Used -- sum of the used space of data/metadata/system profiles, not including the reserved space
  • Free (estimated) -- approximate size of the remaining free space usable for data, including currently allocated space and estimating the usage of the unallocated space based on the block group profiles, the min is the lower bound of the estimate in case multiple profiles are present
  • Free (statfs, df) -- the amount of space available for data as reported by the statfs/statvfs syscall, also returned as Avail in the output of df. The value is calculated in a different way and may not match the estimate in some cases (e.g. multiple profiles).
  • Data ratio -- ratio of total space for data including redundancy or parity to the effectively usable data space, e.g. single is 1.0, RAID1 is 2.0 and for RAID5/6 it depends on the number of devices
  • Metadata ratio -- ditto, for metadata
  • Global reserve -- portion of metadata currently used for global block reserve, used for emergency purposes (like deletion on a full filesystem)
  • Multiple profiles -- what block group types (data, metadata) have more than one profile (single, raid1, ...), see btrfs(5) <> section FILESYSTEMS WITH MULTIPLE PROFILES <#man-btrfs5-filesystem-with-multiple-profiles>.

Device zone size:            256.00MiB
  • Device zone unusable -- sum of of space that's been used in the past but now is not due to COW and not referenced anymore, the chunks have to be reclaimed and zones reset to make it usable again
  • Device zone size -- the reported zone size of the host-managed device, same for all devices

The root user will also see stats broken down by block group types:

Data,single: Size:1.15TiB, Used:1.13TiB (98.26%)
   /dev/sdb        1.15TiB
Metadata,single: Size:12.00GiB, Used:6.45GiB (53.75%)
   /dev/sdb       12.00GiB
System,single: Size:32.00MiB, Used:144.00KiB (0.44%)
   /dev/sdb       32.00MiB
Unallocated:
   /dev/sdb      669.99GiB

Data is block group type, single is block group profile, Size is total size occupied by this type, Used is the actually used space, the percent is ratio of Used/Size. The Unallocated is remaining space.

EXAMPLES

$ btrfs filesystem defrag -v -r dir/

Recursively defragment files under dir/, print files as they are processed. The file names will be printed in batches, similarly the amount of data triggered by defragmentation will be proportional to last N printed files. The system dirty memory throttling will slow down the defragmentation but there can still be a lot of IO load and the system may stall for a moment.

$ btrfs filesystem defrag -v -r -f dir/

Recursively defragment files under dir/, be verbose and wait until all blocks are flushed before processing next file. You can note slower progress of the output and lower IO load (proportional to currently defragmented file).

$ btrfs filesystem defrag -v -r -f -clzo dir/

Recursively defragment files under dir/, be verbose, wait until all blocks are flushed and force file compression.

$ btrfs filesystem defrag -v -r -t 64M dir/

Recursively defragment files under dir/, be verbose and try to merge extents to be about 64MiB. As stated above, the success rate depends on actual free space fragmentation and the final result is not guaranteed to meet the target even if run repeatedly.

$ btrfs filesystem resize -1G /path

$ btrfs filesystem resize 1:-1G /path

Shrink size of the filesystem's device id 1 by 1GiB. The first syntax expects a device with id 1 to exist, otherwise fails. The second is equivalent and more explicit. For a single-device filesystem it's typically not necessary to specify the devid though.

$ btrfs filesystem resize max /path

$ btrfs filesystem resize 1:max /path

Let's assume that devid 1 exists and the filesystem does not occupy the whole block device, e.g. it has been enlarged and we want to grow the filesystem. By simply using max as size we will achieve that.

Note:

There are two ways to minimize the filesystem on a given device. The btrfs inspect-internal min-dev-size command, or iteratively shrink in steps.

EXIT STATUS

btrfs filesystem returns a zero exit status if it succeeds. Non zero is returned in case of failure.
