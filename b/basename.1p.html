BASENAME(1P) Manual del programador POSIX BASENAME(1P)

PROLOG

Esta página del manual forma parte del Manual del programador POSIX. La implementación de esta interfaz en Linux puede diferir (consulte la página del manual de Linux correspondiente para obtener detalles sobre el comportamiento en Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

basename — devuelve la parte no de directorio de una ruta de archivo

SINAPSIS

basename string [suffix]

DESCRIPCIÓN

El operando string se tratará como una ruta de archivo, según se define en el volumen de Definiciones Base de POSIX.1‐2017, Sección 3.271, Ruta de archivo. La cadena string se convertirá al nombre de archivo correspondiente al último componente de la ruta de archivo en string y luego se eliminará el sufijo suffix, si está presente. Esto se hará realizando acciones equivalentes a los siguientes pasos en orden:

1.
Si string es una cadena nula, es indeterminado si la cadena resultante es '.' o una cadena nula. En cualquier caso, omita los pasos 2 a 6.
2.
Si string es "//", es indeterminado si los pasos 3 a 6 se omiten o se procesan.
3.
Si string consiste enteramente en caracteres <barra>, string se establecerá en un solo carácter <barra>. En este caso, omita los pasos 4 a 6.
4.
Si hay caracteres <barra> finales en string, se eliminarán.
5.
Si quedan caracteres <barra> en string, se eliminará el prefijo de string hasta e incluyendo el último carácter <barra> en string.
6.
Si el operando suffix está presente, no es idéntico a los caracteres restantes en string y es idéntico a un sufijo de los caracteres restantes en string, el sufijo suffix se eliminará de string. De lo contrario, string no se modificará con este paso. No se considerará un error si suffix no se encuentra en string.

La cadena resultante se escribirá en la salida estándar.

Ninguna.

Se admitirán los siguientes operandos:

Una cadena.
suffix
Una cadena.

No utilizado.

VARIABLES DE ENTORNO

Las siguientes variables de entorno afectarán la ejecución de basename:

LANG
Proporciona un valor predeterminado para las variables de internacionalización que no están establecidas o están vacías. (Consulte el volumen de Definiciones Base de POSIX.1‐2017, Sección 8.2, Variables de internacionalización para ver la precedencia de las variables de internacionalización utilizadas para determinar los valores de las categorías de localización).
LC_ALL
Si se establece en un valor de cadena no vacío, anula los valores de todas las demás variables de internacionalización.
LC_CTYPE
Determina la localización para la interpretación de secuencias de bytes de datos de texto como caracteres (por ejemplo, caracteres de un solo byte en comparación con caracteres multibyte en los argumentos).
LC_MESSAGES

Determina la localización que debe utilizarse para afectar el formato y el contenido de los mensajes de diagnóstico escritos en la salida de error estándar.
NLSPATH
Determina la ubicación de los catálogos de mensajes para el procesamiento de LC_MESSAGES.

USO PARA APLICACIONES

La definición de ruta de archivo especifica un comportamiento indeterminado para rutas de archivo que comienzan con dos caracteres <barra>. Por lo tanto, las aplicaciones no deben agregar arbitrariamente caracteres <barra> al principio de una ruta de archivo a menos que puedan asegurarse de que hay más o menos de dos o estén preparadas para lidiar con las consecuencias indeterminadas.

EJEMPLOS

Si la cadena string es una ruta de archivo válida:

$(basename -- "string")

produce un nombre de archivo que podría usarse para abrir el archivo nombrado por string en el directorio devuelto por:

$(dirname -- "string")

Si la cadena string no es una ruta de archivo válida, se utiliza el mismo algoritmo, pero el resultado no necesariamente será un nombre de archivo válido. No se espera que la utilidad basename haga juicios sobre la validez de string como ruta de archivo; simplemente sigue el algoritmo especificado para producir una cadena de resultado.

El siguiente script de shell compila /usr/src/cmd/cat.c y mueve la salida a un archivo llamado cat en el directorio actual cuando se invoca con el argumento /usr/src/cmd/cat o con el argumento /usr/src/cmd/cat.c:

c99 -- "$(dirname -- "$1")/$(basename -- "$1" .c).c" &&
mv a.out "$(basename -- "$1" .c)"

La sección EXAMPLES de la función basename() (consulte el volumen de Interfaces del Sistema de POSIX.1‐2017, basename()) incluye una tabla que muestra ejemplos de los resultados del procesamiento de varias rutas de archivo de muestra por las funciones basename() y dirname() y por las utilidades basename y dirname.

FUNDAMENTO

Los comportamientos de basename y dirname se han coordinado para que cuando string sea una ruta de archivo válida:

$(basename -- "string")

sería un nombre de archivo válido para el archivo en el directorio:

$(dirname -- "string")

Esto no funcionaría para las primeras versiones propuestas de estas utilidades debido a la forma en que especificaban el manejo de caracteres <barra> finales.
