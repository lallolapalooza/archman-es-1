DESCRIPCIÓ

N

Antes de que muchas herramientas IPMI puedan usarse a través de una red, el Controlador de Gestión de la Placa Base (BMC) de una máquina debe ser configurado. La configuración puede ser bastante intimidante para aquellos que no saben mucho sobre IPMI. Esta página de manual espera proporcionar suficiente información sobre la configuración del BMC para que pueda configurar el BMC de su sistema. Cuando sea apropiado, se sugerirán configuraciones BMC

típicas.

El siguiente es un archivo de configuración de ejemplo parcialmente generado al ejecutar la opción --checkout con el comando ipmi-config(8). Esta configuración proviene de la categoría core de valores de configuración (la predeterminada). Esta configuración de ejemplo debería ser suficiente para la mayoría de los usuarios después de introducir las direcciones IP y MAC locales apropiadas. Siguiendo este ejemplo, secciones separadas de esta página de manual discutirán las diferentes secciones del archivo de configuración con más detalle, con explicaciones de cómo el BMC puede configurarse para diferentes

entornos.

Tenga en cuenta que muchas opciones pueden o no estar disponibles en su máquina en particular. Por ejemplo, Serial-Over-Lan (SOL) solo está disponible en máquinas IPMI 2.0. Por lo tanto, si está buscando configurar una máquina IPMI 1.5, muchas de las opciones relacionadas con SOL o IPMI 2.0 no estarán disponibles para usted. El número de usuarios configurables también puede variar para su máquina en

particular.

El archivo de configuración siguiente y la mayor parte de esta página de manual asumen que el usuario está interesado en configurar un BMC para uso con IPMI sobre LAN. Varias opciones de configuración de ipmi-config(8) se han omitido o saltado porque se considera innecesario. Las versiones futuras de esta página de manual intentarán incluir más

información.

Sección User1, User2, ..

.

Las secciones de usuario del archivo de configuración del BMC son para la configuración de nombres de usuario para la comunicación IPMI sobre LAN. El número de usuarios disponibles para configurar en su sistema variará según el fabricante. Con la excepción del Nombre de usuario para User1, todas las secciones son

idénticas.

El/los nombre(s) de usuario con los que desea configurar el BMC se definen con Username. El primer nombre de usuario bajo la Sección User1 es típicamente el nombre de usuario NULL y no puede ser modificado. La contraseña para el nombre de usuario se puede especificar con Password. Puede dejarse vacío para definir una contraseña NULL. Cada usuario que desee habilitar debe ser habilitado a través de la opción de configuración Enable_User. Se recomienda que todos los nombres de usuario tengan contraseñas no NULL o estén deshabilitados por razones de

seguridad.

Lan_Enable_Ipmi_Msgs se utiliza para habilitar o deshabilitar el acceso IPMI sobre LAN para el usuario. Esto debe establecerse en "Yes" para permitir que las herramientas IPMI sobre LAN

funcionen.

Lan_Privilege_Limit especifica el límite máximo de nivel de privilegio que se le permite al usuario. Diferentes comandos IPMI tienen diferentes restricciones de privilegio. Por ejemplo, determinar el estado de energía de una máquina solo requiere el nivel de privilegio "User". Sin embargo, el ciclo de energía requiere el privilegio "Operator". Típicamente, querrá asignar al menos un usuario con un límite de privilegio de "Administrator" para que todas las funciones del sistema estén disponibles para al menos un usuario a través de IPMI sobre

LAN.

Lan_Session_Limit especifica el número de sesiones IPMI simultáneas permitidas para el usuario. La mayoría de los usuarios desearán establecer esto en "0" para permitir sesiones IPMI simultáneas ilimitadas. Este campo se considera opcional según los estándares de IPMI, y puede resultar en errores al intentar configurarlo en un valor distinto de cero. Si ocurren errores, establecer el valor de nuevo en 0 debería resolver los

problemas.

SOL_Payload_Access especifica si un usuario en particular está permitido conectarse con Serial-Over-LAN (SOL). Esto debe establecerse en "Yes" para permitir que este nombre de usuario use

SOL.

La configuración de ejemplo anterior deshabilita "User2" pero habilita el usuario predeterminado "NULL" (es decir, anónimo). Muchas herramientas IPMI (tanto de código abierto como de proveedores) no permiten al usuario ingresar un nombre de usuario y asumen el nombre de usuario NULL de forma predeterminada. Si las herramientas que le interesan usar permiten ingresar nombres de usuario, se recomienda que uno de los nombres de usuario no NULL sea habilitado y el nombre de usuario NULL deshabilitado por razones de seguridad. Se recomienda que deshabilite el nombre de usuario NULL en la sección User1, para que se requiera a los usuarios especificar un nombre de usuario para la comunicación IPMI sobre

LAN.

Algunas placas base pueden requerir un Username para ser configurado antes de que otros campos sean leídos/escritos. Si este es el caso, esos campos se establecerán en <username-no

t-set
-yet>.

Sección

Lan_Channel

La sección Lan_Channel configura una variedad de parámetros de configuración de IPMI sobre LAN. Tanto Volatile como Non_Volatile se pueden configurar. Las configuraciones Volatile se configuran inmediatamente en el BMC y tendrán un efecto inmediato en el sistema. Las configuraciones Non_Volatile solo están disponibles después del siguiente reinicio del sistema. Generalmente, tanto Volatile como Non_Volatile deben ser configurados de manera

idéntica.

El parámetro Access_Mode configura la disponibilidad de IPMI sobre LAN en el sistema. Típicamente esto debe establecerse en "Always_Available" para habilitar IPMI sobre

LAN.

El Privilege_Limit establece el privilegio máximo que cualquier usuario del sistema puede tener al realizar IPMI sobre LAN. Esto debe establecerse en el nivel de privilegio máximo configurado para un nombre de usuario. Típicamente, esto debe establecerse en "Administrator"

.

Típicamente User_Level_Auth y Per_Message_Auth deben establecerse en "Yes" para mayor seguridad. Deshabilitar User_Level_Auth permite que los comandos IPMI con privilegio "User" se ejecuten sin autenticación. Deshabilitar Per_Message_Auth permite que menos mensaj

es IPMI individuales re
quieran autenticación.

Sección

Lan_Conf

Aquellos familiarizados con la configuración de redes deberían encontrar la mayoría de los campos en esta sección autoexplicativos. La configuración de BMC de ejemplo anterior ilustra la configuración de una dirección IP estática. El campo IP_Address_Source se configura con "Static". La dirección IP, la máscara de subred y las direcciones IP de la puerta de enlace de la máquina se configuran respectivamente con los campos IP_Address, Subnet_Mask, Default_Gateway_Ip_Address, y Backup_Gateway_Ip_Address. Las respectivas direcciones MAC para las direcciones IP se configuran bajo Mac_Address, Default_Gateway_Mac_Address, y Backup_Gateway_Mac_Address

No es necesario configurar la dirección IP_Address del BMC para que sea la misma P_Address utilizada por su sistema operativo para esa interfaz de red. Sin embargo, si elige usar una dirección diferente, puede ser necesario configurar una configuración ARP

alternativa.

Para configurar en su lugar la información de red de su BMC a través de DHCP, el campo IP_Address_Source debe configurarse con

"Use_DHCP".

Se recomienda que se configuren direcciones IP estáticas por razones de resolución de direcciones. Vea Lan_Conf_Misc a continuación para

Sección

Lan_Conf_Auth

Esta sección determina qué tipos de mecanismos de autenticación de contraseña se permiten para los usuarios en diferentes niveles de privilegio bajo el protocolo IPMI 1.5. Los métodos de autenticación actualmente soportados para IPMI 1.5 son None (no se requiere nombre de usuario/contraseña), Straight_Password (las contraseñas se envían en claro), MD2 (las contraseñas se hashean con MD2), y MD5 (las contraseñas se hashean con MD5). Diferentes nombres de usuario en diferentes niveles de privilegio pueden estar permitidos para autenticarse de manera diferente a través de esta configuración. Por ejemplo, un nombre de usuario con privilegios "User" puede estar permitido para autenticarse con una contraseña en claro, pero un nombre de usuario con privilegios "Administrator" puede estar permitido autenticarse solo con

MD5.

La configuración de ejemplo anterior soporta MD2 y MD5 autenticación para todos los usuarios en los niveles de privilegio "User", "Operator", y "Administrator". Todos los mecanismos de autenticación han sido deshabilitados para el nivel de privilegio

"Callback".

En términos generales, no desea permitir que ningún usuario se autentique con None o Straight_Password por razones de seguridad. MD2 y MD5 son algoritmos de firma digital que pueden cifrar contraseñas mínimamente. Si ha elegido soportar el nombre de usuario NULL (User1 habilitado) y contraseñas NULL (contraseña NULL para User1), tendrá que habilitar los campos de autenticación None anteriores para permitir que los usuarios se conecten a través de No

ne
.

Sección

Lan_Conf_Misc

Esta sección lista opciones de configuración misceláneas de IPMI sobre LAN. Estas son opciones de configuración IPMI opcionales que no están implementadas en todos los

BMC.

Normalmente, un cliente no puede resolver la dirección MAC de ethernet sin el sistema operativo remoto en ejecución. Sin embargo, IPMI sobre LAN no funcionaría cuando una máquina está apagada o si la dirección IP usada por el sistema operativo para esa interfaz de red difiere de la dirección IP del BMC. Una forma de solucionar esto es a través de ARPs gratuitos. Los ARPs gratuitos son paquetes ARP generados por el BMC y enviados para anunciar la dirección IP y MAC del BMC. Otras máquinas en la red pueden almacenar esta información en su caché ARP local para una posterior resolución de IP/nombre de host. Esto permitiría que IPMI sobre LAN funcionara cuando la máquina remota esté apagada. La opción Enable_Gratuitous_Arps le permite habilitar o deshabilitar esta función. La opción Gratuitous_Arp_Interval le permite configurar la frecuencia con la que se envían ARPs gratuitos a la

red.

En lugar de ARPs gratuitos, algunos BMC son capaces de responder a solicitudes ARP, incluso cuando están apagados. Si se ofrece, esta función se puede habilitar a través de la opción Enable_Arp_Response

.

En términos generales, activar los ARPs gratuitos es aceptable. Sin embargo, aumentará el tráfico en su red. Si está usando IPMI en un gran clúster, los ARPs gratuitos pueden inundar fácilmente su red. Deben ajustarse para que ocurran con menos frecuencia o deshabilitarse. Si se deshabilitan, la dirección MAC de la máquina remota debe almacenarse permanentemente en la caché ARP local a través de arp(8)

.

Vea bmc-watchdog(8) para un método que permite que los ARPs gratuitos se deshabiliten cuando

el sistema operativo está en ejecución, pero
se habiliten cuando el sistema está caído.

Esta sección soporta la configuración de los IDs de suite de cifrado de IPMI 2.0 (incluyendo Serial-over-LAN). Si su máquina no soporta IPMI 2.0, los campos no serán

Cada ID de suite de cifrado describe una combinación de un algoritmo de autenticación, un algoritmo de integridad y un algoritmo de cifrado para IPMI 2.0. El algoritmo de autenticación se usa para la autenticación de usuarios con el BMC. El algoritmo de integridad se usa para generar firmas en paquetes IPMI. El algoritmo de confidencialidad se usa para cifrar datos. La configuración en esta sección permite habilitar o deshabilitar ciertos IDs de suite de cifrado, y el nivel de privilegio máximo que un bmc-config.conf(5)

NAME

bmc-config.conf

Configuration file for freeipmi-config

DESCRIPTION

The bmc-config.conf file is used to configure the FreeIPMI tools, such as ipmi-config.

The configuration file is divided into sections, each corresponding to a specific configuration area. The sections are denoted by square brackets, e.g., [Section_Name].

Within each section, configuration options are set using a key-value pair format, where the key is the option name and the value is the desired setting. For example:

Option_Name = Value

Comments in the configuration file start with a hash symbol (#) and extend to the end of the line.

Section User1, User2, ...

This section allows you to configure user accounts and their privileges. Each user is configured in a separate section, named User1, User2, and so on.

The following options are available within each user section:

Username
The username for the account.
Password
The password for the account. This should be the encrypted password if supported by the underlying IPMI implementation. Otherwise, it is the plain text password.
Privilege_Level
The privilege level assigned to the user. This can be set to various levels, such as CALLBACK, USER, OPERATOR, or ADMINISTRATOR.
Cipher_Suite_IDs
A comma-separated list of cipher suite IDs that the user is allowed to use. If this option is not specified, the user can use any cipher suite ID allowed by their privilege level.

The following table shows the cipher suite ID to algorithms mapping:

0 - Authentication Algorithm = None; Integrity Algorithm = None; Confidentiality Algorithm = None

1 - Authentication Algorithm = HMAC-SHA1; Integrity Algorithm = None; Confidentiality Algorithm = None

2 - Authentication Algorithm = HMAC-SHA1; Integrity Algorithm = HMAC-SHA1-96; Confidentiality Algorithm = None

3 - Authentication Algorithm = HMAC-SHA1; Integrity Algorithm = HMAC-SHA1-96; Confidentiality Algorithm = AES-CBC-128

4 - Authentication Algorithm = HMAC-SHA1; Integrity Algorithm = HMAC-SHA1-96; Confidentiality Algorithm = xRC4-128

5 - Authentication Algorithm = HMAC-SHA1; Integrity Algorithm = HMAC-SHA1-96; Confidentiality Algorithm = xRC4-40

6 - Authentication Algorithm = HMAC-MD5; Integrity Algorithm = None; Confidentiality Algorithm = None

7 - Authentication Algorithm = HMAC-MD5; Integrity Algorithm = HMAC-MD5-128; Confidentiality Algorithm = None

8 - Authentication Algorithm = HMAC-MD5; Integrity Algorithm = HMAC-MD5-128; Confidentiality Algorithm = AES-CBC-128

9 - Authentication Algorithm = HMAC-MD5; Integrity Algorithm = HMAC-MD5-128; Confidentiality Algorithm = xRC4-128

10 - Authentication Algorithm = HMAC-MD5; Integrity Algorithm = HMAC-MD5-128; Confidentiality Algorithm = xRC4-40

11 - Authentication Algorithm = HMAC-MD5; Integrity Algorithm = MD5-128; Confidentiality Algorithm = None

12 - Authentication Algorithm = HMAC-MD5; Integrity Algorithm = MD5-128; Confidentiality Algorithm = AES-CBC-128

13 - Authentication Algorithm = HMAC-MD5; Integrity Algorithm = MD5-128; Confidentiality Algorithm = xRC4-128

14 - Authentication Algorithm = HMAC-MD5; Integrity Algorithm = MD5-128; Confidentiality Algorithm = xRC4-40

Generally speaking, HMAC-SHA1 based algorithms are stronger than HMAC-MD5, which are better than MD5-128 algorithms. AES-CBC-128 confidentiality algorithms are stronger than xRC4-128 algorithms, which are better than xRC4-40 algorithms. Cipher suite ID 3 is therefore typically considered the most secure. Some users may wish to set cipher suite ID 3 to a privilege level and disable all remaining cipher suite IDs.

The above example configuration has decided to allow any user with "Administrator" privileges use any Cipher Suite algorithm suite which requires an authentication, integrity, and confidentiality algorithm. Typically, the maximum privilege level configured to a username should be set for atleast one cipher suite ID. Typically, this is the "Administrator" privilege.

A number of cipher suite IDs are optionally implemented, so the available cipher suite IDs available your system may vary.

Section Lan_Channel

This section is for configuring the LAN channel properties. The following options are available:

Enable
Enables or disables the LAN channel. Set to TRUE to enable, FALSE to disable.
Authentication_Type
Specifies the authentication type for the LAN channel. Supported values include NONE, IPMI_ENCRYPTION, PASSWORD, and CALLBACK.

Section Lan_Conf

This section is for configuring general LAN settings.

Default_User_Privilege_Level
Sets the default privilege level for users. This can be set to CALLBACK, USER, OPERATOR, or ADMINISTRATOR.
Max_Concurrent_Sessions
Specifies the maximum number of concurrent sessions allowed.
Max_Login_Retry
The maximum number of login attempts before the session is locked.
Max_Session_Timeout
The maximum session timeout in minutes.
Session_Keep_Alive_Timeout
The session keep-alive timeout in minutes.

Section Lan_Conf_Auth

This section is for configuring LAN authentication settings.

Auth_Type_Supported
A comma-separated list of supported authentication types. See Authentication_Type in Section Lan_Channel for possible values.
Auth_Algorithm_Enable
A comma-separated list of enabled authentication algorithms. Possible values include NONE, MD2, MD5, SHA1, SHA256, SHA384, SHA512.
Integrity_Algorithm_Enable
A comma-separated list of enabled integrity algorithms. Possible values include NONE, HMAC-MD2-128, HMAC-MD5-128, HMAC-SHA1-96, HMAC-SHA256-128, HMAC-SHA384-192, HMAC-SHA512-256.
Confidentiality_Algorithm_Enable
A comma-separated list of enabled confidentiality algorithms. Possible values include NONE, DES-CBC, 3DES-CBC, AES-CBC-128, AES-CBC-192, AES-CBC-256, RC4-128, RC4-40.

Section Lan_Conf_Security_Keys

This section is for configuring security keys for the LAN interface.

User_Session_Key
The user session key. This is typically an automatically generated key.
RAKP_Integrity_Hash_Algorithm
The RAKP (Remote Access and Keyboard Partitioning) integrity hash algorithm. See Integrity_Algorithm_Enable for possible values.
RAKP_Confidentiality_Algorithm
The RAKP confidentiality algorithm. See Confidentiality_Algorithm_Enable for possible values.

Section Rmcpplus_Conf_Privilege

This section is for configuring privilege levels for RMCP+ (Remote Management and Control Protocol Plus) sessions.

Privilege_Level
Sets the privilege level for RMCP+ sessions. This can be set to CALLBACK, USER, OPERATOR, or ADMINISTRATOR.
Cipher_Suite_IDs
A comma-separated list of cipher suite IDs that are allowed for RMCP+ sessions. If this option is not specified, all supported cipher suite IDs are allowed.

The following table shows the cipher suite ID to algorithms mapping:

0 - Authentication Algorithm = None; Integrity Algorithm = None; Confidentiality Algorithm = None

1 - Authentication Algorithm = HMAC-SHA1; Integrity Algorithm = None; Confidentiality Algorithm = None

2 - Authentication Algorithm = HMAC-SHA1; Integrity Algorithm = HMAC-SHA1-96; Confidentiality Algorithm = None

3 - Authentication Algorithm = HMAC-SHA1; Integrity Algorithm = HMAC-SHA1-96; Confidentiality Algorithm = AES-CBC-128

4 - Authentication Algorithm = HMAC-SHA1; Integrity Algorithm = HMAC-SHA1-96; Confidentiality Algorithm = xRC4-128

5 - Authentication Algorithm = HMAC-SHA1; Integrity Algorithm = HMAC-SHA1-96; Confidentiality Algorithm = xRC4-40

6 - Authentication Algorithm = HMAC-MD5; Integrity Algorithm = None; Confidentiality Algorithm = None

7 - Authentication Algorithm = HMAC-MD5; Integrity Algorithm = HMAC-MD5-128; Confidentiality Algorithm = None

8 - Authentication Algorithm = HMAC-MD5; Integrity Algorithm = HMAC-MD5-128; Confidentiality Algorithm = AES-CBC-128

9 - Authentication Algorithm = HMAC-MD5; Integrity Algorithm = HMAC-MD5-128; Confidentiality Algorithm = xRC4-128

10 - Authentication Algorithm = HMAC-MD5; Integrity Algorithm = HMAC-MD5-128; Confidentiality Algorithm = xRC4-40

11 - Authentication Algorithm = HMAC-MD5; Integrity Algorithm = MD5-128; Confidentiality Algorithm = None

12 - Authentication Algorithm = HMAC-MD5; Integrity Algorithm = MD5-128; Confidentiality Algorithm = AES-CBC-128

13 - Authentication Algorithm = HMAC-MD5; Integrity Algorithm = MD5-128; Confidentiality Algorithm = xRC4-128

14 - Authentication Algorithm = HMAC-MD5; Integrity Algorithm = MD5-128; Confidentiality Algorithm = xRC4-40

Generally speaking, HMAC-SHA1 based algorithms are stronger than HMAC-MD5, which are better than MD5-128 algorithms. AES-CBC-128 confidentiality algorithms are stronger than xRC4-128 algorithms, which are better than xRC4-40 algorithms. Cipher suite ID 3 is therefore typically considered the most secure. Some users may wish to set cipher suite ID 3 to a privilege level and disable all remaining cipher suite IDs.

The above example configuration has decided to allow any user with "Administrator" privileges use any Cipher Suite algorithm suite which requires an authentication, integrity, and confidentiality algorithm. Typically, the maximum privilege level configured to a username should be set for atleast one cipher suite ID. Typically, this is the "Administrator" privilege.

A number of cipher suite IDs are optionally implemented, so the available cipher suite IDs available your system may vary.

Section SOL_Conf

This section is for setting up Serial-Over-Lan (SOL) and will only be available for configuration on those machines. SOL can be enabled with the Enable_SOL field. The minimum privilege level required for connecting with SOL is specified by SOL_Privilege_Level. This should be set to the maximum privilege level configured to a username that has SOL enabled. Typically, this is the "Administrator" privilege. Authentication and Encryption can be forced or not using the fields Force_SOL_Payload_Authentication and Force_SOL_Payload_Encryption respectively. It is recommended that these be set on. However, forced authentication and/or encryption support depend on the cipher suite IDs supported.

The Character_Accumulate_Interval, Character_Send_Threshold , SOL_Retry_Count and , SOL_Retry_Interval options are used to set SOL character output speeds. Character_Accumulate_Interval determines how often serial data should be regularly sent and Character_Send_Threshold indicates the character count that if passed, will force serial data to be sent. SOL_Retry_Count indicates how many times packets must be retransmitted if acknowledgements are not received. SOL_Retry_Interval indicates the timeout interval. Generally, the manufacturer recommended numbers will be sufficient. However, you may wish to experiment with these values for faster SOL throughput.

The Non_Volatile_Bit_Rate and Volatile_Bit_Rate determine the baudrate the BMC should use. This should match the baudrate set in the BIOS and operating system, such as agetty(8). Generally speaking, both the Volatile and Non_Volatile options should be set identically.

In addition to enabling SOL in this section, individual users most also be capable of connecting with SOL. See the section Section User1, User2, ... above for details.
