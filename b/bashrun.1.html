EXÉCUTION DE

COMMANDES

Exécuter des commandes simples est direct. Le shell effectuera les expansions habituelles et la commande résultante sera traitée et lancée selon l'action et les préférences demandées par l'utilisateur. Plusieurs

commandes

séparées par ; sont traitées successivement de la même manière. Si les commandes

sont

séparées par un symbole de pipe ( |) ou par lesopérateurs logiques || ou &&, le comportement de bashrun différera sensiblement du comportement normal du shell. Pour le shell bashrun, chaque commande simple dans une instruction composée apparaîtra comme si elle retournait immédiatement un succès. Cela signifie que séparer des commandes avec && ou | est effectivement équivalent à l'utilisation de ;. Séparer des commandes avec || empêchera l'exécution des commandes sur le côté droit de l'expression. Pour contourner ce comportement, les caractères ;,

&

et | peuvent être échappés avec un caractère antislash ( \). Veuillez noter que dans ce cas, les règles duterminal ne sont appliquées que sur la base du nom de commande de la première commande. À titre d'illustration, une commande comme $

cat

fichier_texte | wc -l

<term-page>


ne fonctionnera pas comme prévu et

mettra

à la place la sortie des deux commandes en pages dans des terminaux séparés, sans pipe établi entre les commandes. Vous devrez utiliser $ cat fichier_texte \| wc -l <term-page> pour

mettre


en pages le nombre de lignes

dans

fichier_texte dans une seule fenêtre de terminal comme prévu. L'édition de plusieurs lignes

ne

des

ARCHIVO DE

CONFIGURACIÓN

El archivo de configuración de usuario $XDG_CONFIG_HOME/bashrun/rc será cargado como el archivo de configuración (rcfile) para la sesión de bash utilizada por bashrun. Además de las variables de entorno descritas aquí, puedes añadir cualquier cosa que normalmente añadirías a tu archivo ~/.bashrc. Por ejemplo, podrías querer añadir funciones o alias, vincular teclas de función adicionales o simplemente cargar tu archivo ~/.bashrc e

xistente.

Por favor, asegúrate de no interferir con la configuración de tty/bash y las combinaciones de teclas reservadas utilizadas por bashrun. Ver CONFIGURACIÓN DE TECLADO ARCHIVO DE CONFIGURACIÓN y ENTORNO o echa un vistazo a $PREFIX/share/bashrun/bashrc

.

TERMINAL_RULES=('RUN:[progs]' 'PAGE:[progs]' 'HOLD:[progs]

')
Un array que contiene cadenas de reglas que definen qué programas deben lanzarse siempre en una ventana de terminal. Inserta una lista de nombres de programas separados por espacios después de : en la cadena para la regla deseada. Los programas en la regla RUN se lanzan siempre en una terminal. Los programas en la regla PAGE tendrán su salida paginada en PAGER. Para los programas en la regla HOLD, la terminal permanece abierta después de que el programa termine.

Ejemplo

:


TERMINAL_RULES=(
"RUN:watch top htop less man info ncftp links"
"HOLD:ps su"
"PAGE:echo ls which uname lsusb lshal lsmod fortune"

)

HANDLERS=([regexp handler]...) (por defecto: ver

abajo)
Un array que contiene expresiones regulares de bash y cadenas de manejadores asociadas. Si la línea de comandos introducida en bashrun no es ejecutable (es decir, no es una función, alias o un binario en PATH), se intenta hacer coincidir sucesivamente la línea de comandos con los patrones contenidos en HANDLERS. Si un patrón coincide, se usará la cadena del manejador que sigue al patrón como el comando a ejecutar, pasando la propia línea de comandos como argumento, o, si la expresión regular contiene subpatrones dentro de paréntesis, se intenta sustituir la ocurrencia de $[1-9] en la cadena del manejador con el contenido de la coincidencia del subpatrón correspondiente. La cadena del manejador modificada se usa entonces como la línea de comandos sin añadir más argumentos.

Si no hay suficientes coincidencias de subpatrones para sustituir cada ocurrencia de $[0-9] en la cadena del manejador, el manejador no se ejecutará y se emitirá un mensaje de error al

usuario.

La cadena del manejador puede adicionalmente tener un prefijo con una expresión de prueba de archivo que define una serie de pruebas de archivo a realizar sobre el contenido de la línea de comandos antes de aplicar el manejador. Si alguna de estas pruebas falla, el manejador no se

aplicará.

La expresión de prueba es una serie de caracteres que corresponden a los operadores de prueba de archivo unarios definidos en la sección EXPRESIONES CONDICIONALES del manual bash(1), terminada por :. Las pruebas de archivo pueden negarse anteponiendo un solo !. Por ejemplo, un manejador con el prefijo f!x: solo se aplicará si la línea de comandos es una ruta a un archivo regular, no

ejecutable.

Por ejemplo, para definir asociaciones de archivos para archivos jpeg puedes usar un patrón y un manejador

como


'\.jpe?g$' 'f!x:

gimp'

Esto abrirá las líneas que terminan en .jpg o .jpeg usando gimp(1). La prueba de archivo asegura que aún puedes escribir una línea

como


$ convert foo.tif foo.

jpg

que no será gestionada aunque también termine en .jpg. Esto se debe a que la expresión de prueba se aplica a la línea completa, por lo que la prueba f!x

fallará.

Para abrir líneas que comienzan con http o https en tu BROWSER, añade una línea como esta al array HANDLERS

:


'^https?'

"$BROWSER"

Para implementar atajos web similares a los del navegador konqueror de KDE, usa un patrón que contenga un subpatrón, como

este:


'^gg:(.+)

'

y usa una línea como esta como cadena de

manejador:


"$BROWSER 'http://www.google.com/se

arch?q=\$1'"

Bashrun reemplazará la parte $1 de la cadena del manejador con cualquier cosa que el usuario haya introducido después de gg:.

LOGFILE=[path] (default: /dev/null)
Command output (stdout and stderr) is appended to LOGFILE. If it doesn't exist, bashrun will attempt to create it. If it is not writeable, output is redirected to /dev/null instead.

Logging is disabled for commands run with root privileges.

FILES

$XDG_CONFIG_HOME/bashrun/rc

The user configuration file. If it does not exist, it will be created and initialized with the default configuration.

$XDG_CONFIG_HOME/bashrun/keys

The keyboard configuration file. If it does not exist, it will be created and initialized with the default keybindings.

If xdotool(1) is used, bashrun needs to be restarted to make changes to these files take effect.

If XDG_CONFIG_HOME is not set or empty, ~/.config will be used instead.

$XDG_DATA_HOME/bashrun/history

The history file used by bashrun. If XDG_DATA_HOME is not set or empty, ~/.local/share will be used instead.

$XDG_CACHE_HOME/bashrun/

Directory for temporary files created by bashrun. If XDG_CACHE_HOME is not set or empty, ~/.cache will be used instead.

ENVIRONMENT

X11
The Window manager properties WM_CLASS and WM_NAME are set to "bashrun". These properties can be used with your window manager's facilities to further configure the appearance of bashrun. Note that if you are using xdotool(1) it is recommended to make the bashrun window "sticky" to make sure it will always appear on the current desktop.
BASH
The extdebug shell option is enabled. A trap on DEBUG is set each time a commandline is issued. The trap is disabled again after commandline processing to prevent it from interfering with interactive commandline editing.

Sending ^D (eof) on an empty line does not terminate the shell if xdotool(1) is being used. See stty(1)

XON/XOFF flow control (Suspend/Resume terminal via C-s and C-q) is disabled. C-s will search forward in the history buffer (readline default) while C-q is bound to the <quit> action when using the default keybindings. See stty(1)

KNOWN ISSUES

Some terminals require quoting of the commandline to be run. This means that running commandlines with lots quoting may fail for these terminals, although two levels of quoting should generally work. You can use the debug mode to find out exactly why and how a heavily quoted command fails.

Only xterm(1) and *rxvt(1) support resizing using keybindings. xterm has occasionally been found to freeze during resizing, requiring at least a SIGTERM to close it.

For XTerm, the allowWindowOps resource needs to be set to True to allow window resizing. This is enabled in the default configuration for xterm as of bashrun version 0.14. Note that setting allowSendEvents to True will forcefully disable allowWindowOps in XTerm.

In order for meta keybindings (prefixed with \e or \M-) to work with the Alt or Meta key, the terminal needs to be configured to translate your meta key to an escape. For XTerm, this can be enabled by setting the metaSendsEscape resource to True. This is enabled in the default configuration for xterm as of bashrun version 0.14. For URxvt, the meta8 resource needs to be set to False (which is the default setting for URxvt).
