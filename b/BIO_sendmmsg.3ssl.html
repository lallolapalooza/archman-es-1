A diferencia de la mayoría de las funciones BIO, estas funciones soportan explícitamente su uso multihilo. Se permiten múltiples escritores concurrentes y múltiples lectores concurrentes del mismo BIO en cualquier combinación. Como tal, estas funciones no limpian, establecen o modifican de otra manera las banderas de reintento de BIO. El valor devuelto debe usarse para determinar si una operación debe reintentarse; ver abajo. El soporte para uso concurrente se extiende solo a BIO_sendmmsg() y BIO_recvmmsg() , y no se puede llamar a ninguna otra función en un BIO dado mientras cualquier llamada a BIO_sendmmsg() o BIO_recvmmsg() está en progreso, o viceversa. Las implementaciones de esta interfaz que no realizan llamadas al sistema y por lo tanto pasan códigos de error del sistema utilizando ERR_LIB_SYS (por ejemplo, implementaciones basadas en memoria) deben emitir este código de razón para indicar una falla transitoria. Sin embargo, los usuarios de esta interfaz no deben comprobar directamente este código de razón, ya que hay múltiples códigos de error empaquetados posibles que representan una falla transitoria; utilice BIO_err_is_non_fatal() en su lugar (discutido a continuación).

Errores de socket
Los errores de socket a nivel del SO se reportan utilizando un error con el código de biblioteca ERR_LIB_SYS; para un código de error empaquetado errcode donde "ERR_SYSTEM_ERROR(errcode) == 1", el código de error de socket a nivel del SO se puede obtener utilizando ERR_GET_REASON(errcode). El código de error empaquetado se puede obtener llamando a ERR_peek_last_error(3) después de que la llamada a BIO_sendmmsg() o BIO_recvmmsg() retorna 0.
Errores no fatales
Si un error es transitorio se puede determinar pasando el código de error empaquetado a BIO_err_is_non_fatal(). Los llamadores deben hacer esto en lugar de comprobar directamente el código de razón, ya que hay muchos códigos de error posibles que pueden indicar un error transitorio, muchos de los cuales son específicos del sistema.

Los terceros que implementen BIOs personalizados que soporten los BIO_sendmmsg() o BIO_recvmmsg() métodos deben tener en cuenta que es una parte requerida del contrato de la API que siempre se genere un error cuando cualquiera de estas funciones retorne 0.

BIO_dgram_set_local_addr_enable() retorna 1 si el soporte de dirección local fue habilitado o deshabilitado exitosamente y 0 en caso contrario.

BIO_dgram_get_local_addr_enable() retorna 1 si el indicador de habilitación de soporte de dirección local fue recuperado exitosamente.

BIO_dgram_get_local_addr_cap() retorna 1 si el BIO puede soportar direcciones locales.

BIO_err_is_non_fatal() retorna 1 si el código de error empaquetado pasado representa un error que es transitorio por naturaleza.
