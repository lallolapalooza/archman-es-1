DESCRIPCIÓ

N

El paquete Buildah proporciona una herramienta de línea de comandos que se puede utilizar

para: 
* Crear un contenedor de trabajo, ya sea desde cero o usando una imagen como punto de partida.
* Montar el sistema de archivos raíz de un contenedor de trabajo
para su manipulación. * Desmontar el sistema de archivos raíz de un contenedor de trabajo. * Usar el contenido actualizado del sistema de archivos raíz de un
contenedor como una capa de sistema de archivos para crear una nueva imagen. * Eliminar un contenedor de trabajo o una imagen. * Renombrar un contenedor local.

OPCIONE

S

--cgroup-manager=manage

r

El gestor de CGroup a usar para los cgroups de los contenedores. Los valores admitidos son cgroupfs o systemd. El valor predeterminado es systemd, a menos que se anule en el archivo containers.

conf.

Nota: Establecer esta bandera puede hacer que ciertos comandos fallen cuando se invocan en contenedores creados previamente por el otro tipo de gestor de CGroup. Nota: El gestor de CGroup no está soportado en modo sin raíz (rootless) cuando se usan CGroups Versión

V1.

--imagestore pat

h

Ruta bajo la cual se almacenará el contenido de las imágenes extraídas y construidas. Por defecto, la ubicación configurada --root se utiliza para las imágenes extraídas y construidas, así como para los contenedores. Si el controlador de almacenamiento es overlay, entonces cualquier imagen que haya sido escrita previamente en la ubicación --root seguirá estando

disponible.

Esto anulará la opción imagestore en containers-storage.conf(5)

.

--log-level leve

l

El nivel de registro a utilizar. Puede ser "trace", "debug", "info", "warn", "error", "fatal" o "panic", con "warn" como valor

predeterminado.

--registries-conf pat

h

Ruta del archivo de configuración que especifica qué registros de contenedores deben consultarse al completar nombres de imágenes que no incluyen un componente de registro o dominio. No se recomienda usar esta opción, ya que el comportamiento predeterminado de usar la configuración de todo el sistema (/etc/containers/registries.conf) es lo más

habitual.

--registries-conf-dir pat

h

Ruta del directorio que contiene fragmentos de configuración que especifican los registros que deben consultarse al completar nombres de imágenes que no incluyen un componente de registro o dominio. No se recomienda usar esta opción, ya que el comportamiento predeterminado de usar la configuración de todo el sistema (/etc/containers/registries.d) es lo más

habitual.

--root pat

h

Directorio raíz de almacenamiento (predeterminado: "/var/lib/containers/storage" para UID 0, "$HOME/.local/share/containers/storage" para otros usuarios). El directorio raíz predeterminado está configurado en /etc/containers/storage.

conf.

--runroot pat

h

Directorio de estado de almacenamiento (predeterminado: "/run/containers/storage" para UID 0, "/run/user/$UID" para otros usuarios). El directorio de estado predeterminado está configurado en /etc/containers/storage.

conf.

--short-name-alias-conf pat

h

Ruta del archivo que contiene mapeos en caché entre nombres cortos de imágenes y sus nombres completos correspondientes. Se utiliza para mapear desde nombres de imágenes especificados con nombres cortos como "ubi8" que no incluyen un componente de registro, a un nombre completamente especificado correspondiente que incluye un registro y cualquier otro componente, como "registry.access.redhat.com/ubi8". No se recomienda usar esta opción, ya que el comportamiento predeterminado de usar la caché de todo el sistema (/var/cache/containers/short-name-aliases.conf) o la caché por usuario ($HOME/.cache/containers/short-name-aliases.conf) para complementar los valores predeterminados de todo el sistema es lo más

habitual.

--storage-driver valu

e

Controlador de almacenamiento. El controlador de almacenamiento predeterminado para UID 0 está configurado en /etc/containers/storage.conf ($HOME/.config/containers/storage.conf en modo sin raíz), y es vfs para otros usuarios. La variable de entorno STORAGE_DRIVER anula el valor predeterminado. El controlador especificado con --storage-driver anula

todo.

Ejemplos: "overlay",

"vfs"

Anular esta opción hará que los ajustes storage-opt en /etc/containers/storage.conf se ignoren. El usuario debe especificar opciones adicionales a través de la bandera --stora

ge-opt.

--storage-opt valu

e

Opción del controlador de almacenamiento. Las opciones predeterminadas del controlador de almacenamiento están configuradas en /etc/containers/storage.conf ($HOME/.config/containers/storage.conf en modo sin raíz). La variable de entorno STORAGE_OPTS anula el valor predeterminado. Las opciones especificadas con --storage-opt anulan

todo.

--transient-store bool-valu

e

Almacenar metadatos sobre los contenedores bajo el directorio de estado de almacenamiento (--runroot), con la intención de que los registros sobre ellos se eliminen cuando el sistema se reinicie. Aún se debe realizar una recolección de basura adicional en el arranque, por lo que esta opción debería permanecer deshabilitada en la mayoría de las configuraciones. (predeterminado:

false)

--userns-gid-map mappin

g

Especifica directamente un mapeo de GID que debe usarse para establecer la propiedad, a nivel de sistema de archivos, sobre el contenido del contenedor de trabajo. Los comandos ejecutados al manejar instrucciones RUN se ejecutarán por defecto en sus propios espacios de nombres de usuario, configurados usando los mapas de UID y

GID.

Las entradas en este mapa tienen la forma de uno o más tríos separados por dos puntos de un GID inicial dentro del contenedor, un GID inicial correspondiente a nivel de host, y el número de IDs consecutivos que representa la entrada del

mapa.

Esta opción anula el ajuste remap-gids en la sección options de /etc/containers/storage.

conf.

Si esta opción no se especifica, pero se proporciona un ajuste global --userns-gid-map, se usarán los ajustes de la opción

global.

Si no se especifica ninguna de --userns-uid-map-user, --userns-gid-map-group o --userns-gid-map, pero se especifica --userns-uid-map, el mapa de GID se configurará para usar los mismos valores numéricos que el mapa de

UID.

NOTA: Cuando esta opción es especificada por un usuario sin raíz, los mapeos especificados son relativos al espacio de nombres de usuario sin raíz en el contenedor, en lugar de ser relativos al host como lo sería si se ejecutara con

raíz.

Archivo

s

storage.conf (/etc/containers/sto

rage.conf)

storage.conf es el archivo de configuración de almacenamiento para todas las herramientas que utilizan containers/storage

.

El archivo de configuración de almacenamiento especifica todas las opciones de almacenamiento de contenedores disponibles para las herramientas que utilizan almacenamiento de contenedores

compartido.

mounts.conf (/usr/share/containers/mounts.conf y opcionalmente /etc/containers/mou

nts.conf)

Los archivos mounts.conf especifican archivos o directorios de montaje de volumen que se montan automáticamente dentro de los contenedores al ejecutar los comandos buildah run o buildah build. Los procesos del contenedor pueden entonces utilizar este contenido. El contenido del montaje de volumen no se incorpora a la imagen

final.

Usualmente estos directorios se utilizan para pasar secretos o credenciales requeridas por el software del paquete para acceder a repositorios de paquetes

remotos.

Por ejemplo, un mounts.conf con la línea "/usr/share/rhel/secrets:/run/secrets", el contenido del directorio /usr/share/rhel/secrets se monta en /run/secrets dentro del contenedor. Este punto de montaje permite que las suscripciones de Red Hat Enterprise Linux del host se utilicen dentro del contenedor. También es posible omitir el destino si es igual a la ruta de origen. Por ejemplo, especificando /var/lib/secrets montará el directorio en la misma ruta de destino del contenedor /var/lib/secrets. Tenga en cuenta que esto no es un montaje de volumen. El contenido de los volúmenes se copia en el almacenamiento del contenedor, no se monta directamente mediante enlace

desde el host.
