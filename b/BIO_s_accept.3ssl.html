DESCRIPCIÓ

N

BIO_s_accept() devuelve el método BIO de aceptación. Este es un envoltorio alrededor de las rutinas de aceptación de sockets TCP/IP de la

plataforma.

Usando BIOs de aceptación, se pueden aceptar conexiones TCP/IP y transferir datos usando únicamente rutinas BIO. De esta manera, cualquier operación específica de la plataforma queda oculta por la abstracción

BIO.

Las operaciones de lectura y escritura en un BIO de aceptación realizarán E/S en la conexión subyacente. Si no se ha establecido ninguna conexión y el puerto (ver abajo) está configurado correctamente, el BIO espera una conexión

entrante.

Los BIOs de aceptación soportan BIO_puts() pero no BIO_get

s().

Si la bandera de cierre está establecida en un BIO de aceptación, cualquier conexión activa en esa cadena se apagará y el socket se cerrará cuando el BIO se

libere.

Llamar a BIO_reset() en un BIO de aceptación cerrará cualquier conexión activa y restablecerá el BIO a un estado donde espera otra conexión

entrante.

BIO_get_fd() y BIO_set_fd() pueden ser llamados para obtener o establecer el socket de aceptación. Ver BIO_s_fd(3

)

BIO_set_accept_name() usa la cadena name para establecer el nombre de aceptación. El nombre se representa como una cadena de la forma "host:port", donde "host" es la interfaz a usar y "port" es el puerto. El host puede ser "*" o estar vacío, lo cual se interpreta como cualquier interfaz. Si el host es una dirección IPv6, debe estar encerrada entre corchetes, por ejemplo "[::1]:https". "port" tiene la misma sintaxis que el puerto especificado en BIO_set_conn_port() para BIOs de conexión, es decir, puede ser una cadena de puerto numérico o una cadena para buscar usando getservbyname() y una tabla de

cadenas.

BIO_set_accept_port() usa la cadena port para establecer el puerto de aceptación del BIO b. "port" tiene la misma sintaxis que el puerto especificado en BIO_set_conn_port() para BIOs de conexión, es decir, puede ser una cadena de puerto numérico o una cadena para buscar usando getservbyname() y una tabla de cadenas. Si el puerto dado es 0, se elige un puerto disponible aleatorio. Puede ser consultado usando BIO_sock_info() y BIO_ADDR_service_s

tring(3).

BIO_new_accept() combina BIO_new() y BIO_set_accept_name() en una sola llamada: es decir, crea un nuevo BIO de aceptación con el puerto host_port

.

BIO_set_nbio_accept() establece el socket de aceptación en modo bloqueante (el predeterminado) si n es 0, o en modo no bloqueante si n es

1.

BIO_set_tfo_accept() habilita TCP Fast Open en el socket de aceptación si n es 1, o deshabilita TCP Fast Open si n es 0 (el predeterminado). Establecer el valor en 1 es equivalente a establecer BIO_SOCK_TFO en BIO_set_bind_

mode().

BIO_set_accept_bios() puede usarse para establecer una cadena de BIOs que serán duplicados y ante-puestos a la cadena cuando se reciba una conexión entrante. Esto es útil si, por ejemplo, se requiere un BIO de almacenamiento intermedio o SSL para cada conexión. La cadena de BIOs no debe ser liberada después de esta llamada, serán automáticamente liberados cuando el BIO de aceptación sea

liberado.

BIO_get_accept_ip_family() devuelve la familia IP aceptada por el BIO b, la cual puede ser BIO_FAMILY_IPV4, BIO_FAMILY_IPV6, o BIO_FAMILY_IPANY

.

BIO_set_accept_ip_family() establece la familia IP family aceptada por el BIO b. El valor predeterminado es BIO_FAMILY_IPANY

.

BIO_set_bind_mode() y BIO_get_bind_mode() establecen y recuperan el modo de enlace actual. Si BIO_BIND_NORMAL (el predeterminado) está establecido, otro socket no puede ser enlazado al mismo puerto. Si BIO_BIND_REUSEADDR está establecido, otros sockets pueden enlazarse al mismo puerto. Si BIO_BIND_REUSEADDR_IF_UNUSED está establecido, primero se intenta usar BIO_BIN_NORMAL, si esto falla y el puerto no está en uso, se hace un segundo intento usando BIO_BIND_REUSEADDR. Si BIO_SOCK_TFO está establecido, el socket será configurado para aceptar conexiones TCP Fast

Open.

BIO_do_accept() sirve dos funciones. Cuando es llamado por primera vez, después de que el BIO de aceptación ha sido configurado, intentará crear el socket de aceptación y enlazar una dirección a él. Segundas y subsecuentes llamadas a BIO_do_accept() esperarán una conexión entrante, o

solicitarán un reinte
nto en modo no bloqueante.

NOTA

S

Cuando un BIO de aceptación está al final de una cadena, esperará una conexión entrante antes de procesar llamadas de E/S. Cuando un BIO de aceptación no está al final de una cadena, pasa las llamadas de E/S al siguiente BIO en la

cadena.

Cuando se establece una conexión, se crea un nuevo BIO de socket para la conexión y se añade a la cadena. Es decir, la cadena es ahora aceptación->socket. Esto significa efectivamente que intentar E/S en un socket de aceptación inicial esperará una conexión entrante y luego realizará E/S en

ella.

Si se han establecido BIOs adicionales usando BIO_set_accept_bios(), entonces son colocados entre el socket y el BIO de aceptación, es decir, la cadena será aceptación->otrosbios->

socket.

Si un servidor desea procesar múltiples conexiones (como es normalmente el caso), el BIO de aceptación debe hacerse disponible para más conexiones entrantes. Esto puede hacerse esperando una conexión y luego

llamando: 
connection = BIO_pop(accept)
;

Después de esta llamada connection contendrá un BIO para la conexión recientemente establecida y accept será ahora un BIO único otra vez que puede usarse para esperar más conexiones entrantes. Si no se aceptarán más conexiones, el accept puede ser liberado usando BIO_fre

e().

Si solo se procesará una única conexión, es posible realizar E/S usando el propio BIO de aceptación. Esto es a menudo indeseable sin embargo, porque el BIO de aceptación seguirá aceptando conexiones entrantes adicionales. Esto puede resolverse usando BIO_pop() (ver arriba) y liberando el BIO de aceptación después de la conexión

inicial.

Si el socket de aceptación subyacente es no bloqueante y BIO_do_accept() es llamado para esperar una conexión entrante, es posible que BIO_should_io_special() con la razón BIO_RR_ACCEPT. Si esto sucede, es una indicación de que un intento de aceptación bloquearía: la aplicación debe tomar la acción apropiada para esperar hasta que el socket subyacente haya aceptado una conexión y reintentar la

llamada.

EJEMPLO

S

Este ejemplo acepta dos conexiones en el puerto 4444, envía mensajes por cada una y finalmente cierra

ambas. 
BIO *abio, *cbio, *cbio2;
/* La primera llamada a BIO_do_accept() configura el BIO de aceptación */
abio = BIO_new_accept("4444");
if (BIO_do_accept(abio) <= 0) {
    fprintf(stderr, "Error setting up accept\n");
    ERR_print_errors_fp(stderr);
    exit(1);
}
/* Esperar la conexión entrante */
if (BIO_do_accept(abio) <= 0) {
    fprintf(stderr, "Error accepting connection\n");
    ERR_print_errors_fp(stder
r); exit(1); } fprintf(stderr, "Connection 1 established\n"); /* Obtener el BIO para la conexión */ cbio = BIO_pop(abio); BIO_puts(cbio, "Connection 1: Sending out Data on initial connection\n"); fprintf(stderr, "Sent out data on connection 1\n"); /* Esperar otra conexión */ if (BIO_do_accept(abio) <= 0) { fprintf(stderr, "Error accepting connection\n"); ERR_print_errors_fp(stderr); exit(1)
; } fprintf(stderr, "Connection 2 established\n"); /* Cerrar el BIO de aceptación para rechazar más conexiones */ cbio2 = BIO_pop(abio); BIO_free(abio); BIO_puts(cbio2, "Connection 2: Sending out Data on second\n"); fprintf(stderr, "Sent out data on connection 2\n"); BIO_puts(cbio, "Connection 1: Second connection established\n"); /* Cerrar las dos conexiones establecidas */ BIO_free(cbio); BIO_free(cbio2);
