NOMBRE

bdep-init - inicializar proyecto en configuraciones de compilación

SINOPSIS

bdep init [opciones] [pkg-spec] [cfg-spec] [pkg-args]
bdep init [opciones] [prj-spec] --empty|-E
bdep init [opciones] [pkg-spec] --config-add|-A cfg-dir [@cfg-name]
[pkg-args]
bdep init [opciones] [pkg-spec] --config-create|-C cfg-dir [@cfg-name]
[cfg-args] [-- pkg-args]

cfg-spec = (@cfg-name | --config|-c cfg-dir)... | --all|-a
pkg-spec = (--directory|-d pkg-dir)... | prj-spec
prj-spec = --directory|-d prj-dir
pkg-args = (?pkg | cfg-var)...
cfg-args = [-- [bpkg-options]] [--existing|-e | (module | cfg-var)...]

DESCRIPCIÓN

El init inicializa un proyecto en una o más configuraciones de compilación. La primera forma inicializa los paquetes del proyecto especificados (pkg-spec), o, si se especifica el proyecto en sí (prj-spec), todos sus paquetes disponibles, en una o más configuraciones de compilación (cfg-spec) que ya se han asociado con el proyecto (bdep-config(1)).

Si no se especifica un directorio de proyecto, se asume el directorio de trabajo actual. Si no se especifica una configuración, se asume la configuración predeterminada (fallando si hay múltiples configuraciones predeterminadas). Consulte bdep-projects-configs(1) para detalles sobre cómo especificar proyectos y configuraciones. Los pkg-args opcionales son los paquetes de dependencias adicionales y/o variables de configuración que se pasan al comando subyacente bpkg-pkg-build(1) .

La segunda forma (--empty se especifica) inicializa una base de datos de proyecto vacía que puede usarse más tarde para primero añadir configuraciones de compilación (bdep-config(1)) y luego inicializar los paquetes del proyecto usando la primera forma.

La tercera (--config-add) y la cuarta (--config-create) formas son atajos para primero añadir una configuración de compilación existente o recién creada y luego inicializar los paquetes del proyecto en esa configuración. Semánticamente son equivalentes a primero realizar los comandos config add o config create (bdep-config(1)), respectivamente, seguidos de la primera forma. Los cfg-args opcionales en la cuarta forma son los argumentos adicionales para el comando subyacente bpkg-cfg-create(1) . Tenga en cuenta que en este caso, para especificar pkg-args sin especificar cfg-args tiene que usar dos separadores -- , por ejemplo:

$ bdep init -C ../prj-gcc @gcc -- -- ?sys:libsqlite3/*

Se pueden especificar variables de configuración para que se apliquen solo a paquetes específicos en pkg-args usando el mecanismo de agrupación de argumentos (bdep-argument-grouping(1)). Adicionalmente, tales paquetes pueden colocarse en configuraciones enlazadas específicas especificando la configuración con una de las opciones --config* (o la notación @ ) usando el mismo mecanismo de agrupación. Por ejemplo (asumiendo que gcc está enlazado a common):

$ bdep init @gcc { @common config.liblarge.extra=true }+ ?liblarge

EJEMPLOS

Como ejemplo, considere el proyecto prj con dos paquetes, foo y libfoo:

prj/
|-- foo/
`-- libfoo/

Las siguientes invocaciones ilustran los casos de uso comunes de init (el directorio de trabajo actual se muestra antes del prompt del shell).

Crear una nueva configuración de compilación en ../prj-gcc, llamarla gcc, e inicializar los paquetes del proyecto foo y libfoo en esta configuración:

prj/$ bdep init -C ../prj-gcc @gcc cc config.cxx=g++

Crear una nueva configuración de compilación en ../prj-clang usando bpkg-cfg-create(1). Luego añadirla llamándola clang e inicializar el paquete del proyecto foo en esta configuración:

prj/$ bpkg create -d ../prj-clang cc config.cxx=clang++
prj/$ cd foo
foo/$ bdep init -A ../../prj-clang @clang

Inicializar el paquete del proyecto libfoo en la configuración de compilación clang:

foo/$ cd ..
prj/$ bdep init -d libfoo @clang

El siguiente conjunto de invocaciones logra el mismo resultado final pero usando el comando bdep-config(1) para gestionar la configuración.

Inicializar una base de datos de proyecto vacía:

prj/$ bdep init --empty

Crear una nueva configuración de compilación en ../prj-gcc, llamarla gcc:

prj/$ bdep config create ../prj-gcc @gcc cc config.cxx=g++

Añadir una configuración de compilación existente en ../prj-clang, llamarla clang.

prj/$ bdep config add ../prj-clang @clang

Inicializar los paquetes del proyecto foo y libfoo en las configuraciones de compilación gcc y clang.

prj/$ bdep init @gcc @clang

O, alternativamente, en todas las configuraciones de compilación:

prj/$ bdep init -a

INICIALIZAR OPCIONES

--empty|-E
Inicializar un conjunto de configuraciones de compilación vacío.
--config-add|-A dir
Añadir una configuración de compilación existente dir.
--config-create|-C dir
Crear una nueva configuración de compilación en dir.
--no-sync
Registrar el proyecto en la base de datos pero no inicializarlo en las configuraciones de compilación. La inicialización puede finalizarse más tarde con un comando explícito bdep-sync(1) .
--sys-no-query
No consultar al gestor de paquetes del sistema por las versiones instaladas de los paquetes especificados con el esquema sys . Consulte la opción correspondiente de bpkg-pkg-build(1) para detalles.
--sys-install
Instruir al gestor de paquetes del sistema para instalar las versiones disponibles de los paquetes especificados con el esquema sys que aún no estén instaladas. Consulte la opción correspondiente de bpkg-pkg-build(1) para detalles.
--sys-no-fetch
No obtener los metadatos del gestor de paquetes del sistema antes de consultar por las versiones disponibles de los paquetes especificados con el esquema sys . Consulte la opción correspondiente de bpkg-pkg-build(1) para detalles.
--sys-no-stub
No requerir un stub para los paquetes especificados con el esquema sys . Consulte la opción correspondiente de bpkg-pkg-build(1) para detalles.
--sys-yes
Asumir que la respuesta a las indicaciones del gestor de paquetes del sistema es sí. Consulte la opción correspondiente de bpkg-pkg-build(1) para detalles.
--sys-sudo prog
El sudo programa a usar para las interacciones con el gestor de paquetes del sistema que normalmente requieren privilegios administrativos (obtener metadatos de paquetes, instalar paquetes, etc). Consulte la opción correspondiente de bpkg-pkg-build(1) para detalles.
--create-host-config
Crear una configuración para dependencias de tiempo de compilación sin indicación (consulte bdep-sync(1) para detalles).
--create-build2-config
Crear una configuración para dependencias del módulo del sistema de compilación sin indicación (consulte

OPCIONES DE INICIALIZACIÓN

--config-add|-A dir
Add a new build configuration located in dir. This is a shortcut for running bdep-config-add(1).
--config-create|-C dir
Create a new build configuration in dir. This is a shortcut for running bdep-config-create(1).
--config-delete|-D dir
Delete the build configuration located in dir. This is a shortcut for running bdep-config-delete(1).
--sync|-s
Synchronize build configurations. This is a shortcut for running bdep-sync(1) for details).
--type|--config-type typ
The type of the configuration being created. By default, configuration of type target is created. See bpkg-cfg-create(1) for background on configuration types.
--default
Make the added or created configuration the default.
--no-default
Don't make the first added or created configuration the default.
--forward
Make the added or created configuration forwarded.
--no-forward
Don't make the added or created configuration forwarded.
--auto-sync
Make the added or created configuration automatically synchronized.
--no-auto-sync
Don't make the added or created configuration automatically synchronized.
--existing|-e
Initialize a bpkg configuration based on an existing build system configuration.
--wipe
Wipe the configuration directory clean before creating the new configuration.
--all|-a
Use all build configurations.
--config|-c dir
Specify the build configuration as a directory.
--directory|-d dir
Assume project/package is in the specified directory rather than in the current working directory.
--config-name|-n name
Specify the build configuration as a name.
--config-id num
Specify the build configuration as an id.

ARCHIVOS DE OPCIONES PREDETERMINADAS

Consulte bdep-default-options-files(1) para una visión general de los archivos de opciones predeterminadas. Para el comando init, el directorio inicial de búsqueda es el directorio del proyecto. Los siguientes archivos de opciones se buscan en cada directorio y, si se encuentran, se cargan en el orden indicado:

bdep.options
bdep-{config config-add}.options                # if --config-add|-A
bdep-{config config-add config-create}.options  # if --config-create|-C
bdep-init.options

Las siguientes opciones del comando init no se pueden especificar en los archivos de opciones predeterminados:

--directory|-d
--config-add|-A
--config-create|-C
--wipe
