DESCRIPCIÓ

N

El controlador del sistema de construcción build2 ejecuta un conjunto de meta-operaciones sobre operaciones en destinos de acuerdo con la especificación de construcción, o especificación de construcción para abreviar. Este proceso puede ser controlado especificando las opciones del controlador y las variables del sistema de

construcción.

Tenga en cuenta que las opciones, variables y los fragmentos de especificación de construcción pueden especificarse en cualquier orden. Para evitar tratar un argumento que comienza con '-' como una opción, añada el separador '--'. Para evitar tratar un argumento que contiene '=' como una variable, añada el segundo separador '--'

.

Todos los componentes de la especificación de construcción pueden omitirse. Si la meta-operación se omite, entonces por defecto es perform. Si la operación se omite, entonces por defecto es la operación predeterminada para esta meta-operación. Para perform es update. Finalmente, si el destino se omite, entonces por defecto es el directorio de trabajo actual. Una meta-operación sobre una operación se llama una acción. Algunas operaciones y meta-operaciones pueden tomar parámetros adicionales. Por

ejemplo: 
$ b                       # perform(update(./))
$ b foo/                  # perform(update(foo/))
$ b foo/ bar/             # perform(update(foo/ bar/))
$ b update                # perform(update(./))
$ b 'clean(../)'          # perform(clean(../))
$ b perform               # perform(update(./))
$ b configure             # configure(?(./))
$ b 'configure(../)'      # configure(?(../))
$ b clean update          # perform(clean(./) update(./))
$ b configure update      # configure(?(./)) perform(update(./))
$ b 'create(conf/, cxx)'  # create(?(conf/),
cxx)

Observe el signo de interrogación utilizado para mostrar la operación predeterminada (imaginaria) para la meta-operación configure. Para configure la operación predeterminada es "todas las operaciones". Es decir, configurará todas las operaciones para el destino

especificado.

También puede "generar" múltiples operaciones para el mismo conjunto de destinos.

Compare: 
$ b 'clean(foo/ bar/)' 'update(foo/ bar/)'
$ b '{clean update}(foo/ bar/)
'

Algunos ejemplos más útiles de especificación de

construcción: 
$ b '{clean update}(...)'        # reconstruir
$ b '{clean update clean}(...)'  # asegurar que se compila
$ b '{clean test clean}(...)'    # asegurar que pasa las pruebas
$ b '{clean disfigure}(...)'     # similar a
distclean

En shells POSIX, los paréntesis son caracteres especiales y deben estar entre comillas cuando se usan en una especificación de construcción. Además de ser una molestia en sí misma, el uso de comillas también inhibe la autocompletación de rutas. Para ayudar con esta situación, existe una sintaxis abreviada para ejecutar una sola operación o meta-operación, por

ejemplo: 
$ b clean: foo/ bar/                # clean(foo/ bar/)
$ b configure: src/@out/            # configure(src/@out/)
$ b create: conf/, cxx              # create(conf/, cxx)
$ b configure: config.cxx=g++ src/  # configure(src/) config.
cxx=g++

Para activar la sintaxis abreviada, el primer argumento de la especificación de construcción debe comenzar con un nombre de operación o meta-operación y terminar con dos puntos (:). Para transformar la sintaxis abreviada a la sintaxis normal de la especificación de construcción, los dos puntos se reemplazan con el paréntesis de apertura ('('), el resto de los argumentos de la especificación de construcción se tratan tal cual, y se añade el paréntesis de cierre final (')')

.

Además de las compilaciones dentro y fuera de la fuente, build2 también soporta configurar el directorio fuente de un proyecto como reenviado a una compilación fuera de la fuente. Con una configuración reenviada en su lugar, si ejecutamos el controlador del sistema de construcción desde el directorio fuente, compilará automáticamente en el directorio de salida y creará enlaces (usando enlaces simbólicos u otro mecanismo adecuado) ciertos "objetivos interesantes" (ejecutables, documentación, etc.) al directorio fuente para un fácil acceso. Continuando con el ejemplo

anterior: 
$ b configure: foo/@foo-out/,forward  # foo/ se reenvía a foo-out/
$ cd foo/
$ b                                   # compilar en foo-out/
$ ./foo                               # enlace simbólico a
foo-out/foo

La capacidad de especificar variables de build2 como parte de la línea de comandos se usa normalmente para pasar valores de configuración, por
