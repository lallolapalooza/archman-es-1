DESCRIPCIÓ

N

BIO_f_ssl() devuelve el método BIO SSL. Este es un BIO filtro que es un envoltorio alrededor de las rutinas SSL de OpenSSL que añade un "sabor" BIO a la E/S de

SSL.

La E/S realizada en un BIO SSL se comunica usando el protocolo SSL con los BIO de lectura y escritura de SSL. Si no se ha establecido una conexión SSL, se intenta establecer una en la primera llamada de

E/S.

Si se añade un BIO a un BIO SSL usando BIO_push() se utiliza automáticamente como los BIO de lectura y escritura del BIO

SSL.

Llamar a BIO_reset() en un BIO SSL cierra cualquier conexión SSL actual llamando a SSL_shutdown(). A continuación se envía BIO_reset() al siguiente BIO en la cadena: esto normalmente desconectará el transporte subyacente. El BIO SSL se restablece entonces al estado inicial de aceptar o

conectar.

Si la bandera de cierre está establecida cuando se libera un BIO SSL, la estructura SSL interna también se libera usando SSL_fre

e().

BIO_set_ssl() establece el puntero SSL interno del BIO SSL b a ssl usando la bandera de cierre c

.

BIO_get_ssl() recupera el puntero SSL del BIO SSL b, que luego puede manipularse usando las funciones estándar de la biblioteca

SSL.

BIO_set_ssl_mode() establece el modo del BIO SSL a cliente. Si cliente es 1 se establece el modo cliente. Si cliente es 0 se establece el modo

servidor.

BIO_set_ssl_renegotiate_bytes() establece el recuento de bytes de renegotiación del BIO SSL b a num. Cuando se establece, después de cada num bytes de E/S (lectura y escritura) la sesión SSL se renegocia automáticamente. num debe ser al menos 512

bytes.

BIO_set_ssl_renegotiate_timeout() establece el tiempo de espera de renegotiación del BIO SSL b a segundos. Cuando expira el tiempo de espera de renegotiación, la sesión se renegocia automáticamente

.

BIO_get_num_renegotiates() devuelve el número total de renegotiaciones de sesión debido a la E/S o al tiempo de espera del BIO SSL b

.

BIO_new_ssl() asigna un BIO SSL usando SSL_CTX ctx y usando el modo cliente si cliente es distinto de

cero.

BIO_new_ssl_connect() crea una nueva cadena BIO que consiste en un BIO SSL (usando ctx) seguido de un BIO de

conexión.

BIO_new_buffer_ssl_connect() crea una nueva cadena BIO que consiste en un BIO de buffer, un BIO SSL (usando ctx), y un BIO de

conexión.

BIO_ssl_copy_session_id() copia un id de sesión SSL entre cadenas BIO de y a. Hace esto localizando los BIO SSL en cada cadena y llamando a SSL_copy_session_id() en el puntero SSL

interno.

BIO_ssl_shutdown() cierra una conexión SSL en la cadena BIO bio. Hace esto localizando el BIO SSL en la cadena y llamando a SSL_shutdown() en su puntero SSL

interno.

BIO_do_handshake() intenta completar un handshake SSL en el BIO proporcionado y establecer la conexión SSL. Para BIOs no SSL, la conexión se realiza normalmente a nivel TCP. Si la resolución de nombres de dominio produce múltiples direcciones IP, se prueban todas después de fallos de connect(). La función devuelve 1 si la conexión se estableció con éxito. Se devuelve un valor cero o negativo si la conexión no pudo establecerse. La llamada BIO_should_retry() debe usarse para BIOs de conexión no bloqueantes para determinar si la llam

ada debe reintentarse. Si una conexión ya se
ha establecido, esta llamada no tiene efecto.

NOTA

S

Los BIOs SSL son excepcionales en que si el transporte subyacente es no bloqueante, aún pueden solicitar un reintento en circunstancias excepcionales. Específicamente, esto ocurrirá si tiene lugar una renegotiación de sesión durante una operación BIO_read_ex(), un caso en el que esto ocurre es cuando se produce un

escalado.

La bandera SSL SSL_AUTO_RETRY puede establecerse para deshabilitar este comportamiento. Es decir, cuando esta bandera está establecida, un BIO SSL que usa un transporte bloqueante nunca solicitará un

reintento.

Dado que las operaciones BIO_ctrl() desconocidas se envían a través de BIOs filtro, el nombre y el puerto del servidor pueden establecerse usando BIO_set_host() en el BIO devuelto por BIO_new_ssl_connect() sin tener que localizar el BIO de conexión

primero.

Las aplicaciones no tienen que llamar a BIO_do_handshake() pero pueden desear hacerlo para separar el proceso de handshake de otro procesamiento de

E/S.

BIO_set_ssl(), BIO_get_ssl(), BIO_set_ssl_mode(), BIO_set_ssl_renegotiate_bytes(), BIO_set_ssl_renegotiate_timeout(), BIO_get_num_renegotiates(), y BIO_do_handshake() están implementados como

macros.

BIO_ssl_copy_session_id() no está soportado actualmente en

objetos SSL QUIC y falla si se
llama en un objeto de ese tipo.

VALORES DE

RETORNO

BIO_f_ssl() devuelve la estructura BIO_METHOD

SSL.

BIO_set_ssl(), BIO_get_ssl(), BIO_set_ssl_mode(), BIO_set_ssl_renegotiate_bytes(), BIO_set_ssl_renegotiate_timeout() y BIO_get_num_renegotiates() devuelven 1 en éxito o un valor que es menor o igual a 0 si ocurrió un

error.

BIO_new_ssl(), BIO_new_ssl_connect() y BIO_new_buffer_ssl_connect() devuelven una estructura BIO válida en éxito o NULL si ocurrió un

error.

BIO_ssl_copy_session_id() devuelve 1 en éxito o 0 en error, o si se llama en un objeto SSL

QUIC.

BIO_do_handshake() devuelve 1 si la conexión se estableció con éxito. Se

devuelve un valor cero o negativo si
la conexión no pudo establecerse.

ct(3).

    fprintf(stderr, "Can't locate SSL pointer\n");
    ERR_print_errors_fp(stderr);

/* XXX Podríamos querer hacer otras cosas con ssl aquí */
/* Una parte de host vacía significa la dirección de loopback */
BIO_set_conn_hostname(sbio, ":https");
out = BIO_new_fp(stdout, BIO_NOCLOSE);
if (BIO_do_connect(sbio) <= 0) {
    fprintf(stderr, "Error connecting to server\n");
    ERR_print_errors_fp(stderr);
    exit(1);
}
/* XXX Podríamos examinar ssl aquí para obtener información de la conexión */
BIO_puts(sbio, "GET / HTTP/1.0\n\n");
for (;;) {
    len = BIO_read(sbio, tmpbuf, 1024);
    if (len <= 0)
        break;
    BIO_write(out, tmpbuf, len);
}
BIO_free_all(sbio);
BIO_free(out)
;

HISTORIA

L

En OpenSSL antes de la versión 1.0.0, la llamada a BIO_pop() se manejaba incorrectamente, el recuento de referencias del BIO de E/S se incrementaba incorrectamente (en lugar de decrementarse) y se disociaba del BIO SSL incluso si el BIO SSL no se estaba eliminando explícitamente (por e

jemplo, una eliminación más arriba en la cadena). Las aplicaciones que incluían soluciones temporales para este error (por ej
emplo, liberar BIOs más de una vez) deben modificarse para manejar esta corrección o podrían liberar un BIO ya liberado.
