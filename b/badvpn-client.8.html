INTRODUCCIÓ

N

Esta página documenta el cliente BadVPN, un demonio para un nodo en una red VPN BadVPN. Para una descripción general de BadVPN, véase badvp

n(7
).

DESCRIPCIÓ

N

El cliente BadVPN es un demonio que se ejecuta en un nodo VPN. Abre el dispositivo TAP, se conecta al servidor y luego sigu

e ejecutándose mientras intenta establecer una conexión de datos con los pares y transferir datos entre el dispositivo T
AP y los pares. Una vez inicializado, el programa solo termina si pierde la conexión con el servidor o si recibe una señal.

OPCIONE

S

El cliente BadVPN se configura completamente desde la línea de

comandos.

lp

sale.

--logger
<stdout/syslog>
Selecciona dónde registrar los mensajes. El valor predeterminado es stdout. Syslog no está disponible en
Windows.
--syslog-facility
<string>
Al registrar en syslog, establece la facilidad de registro. El nombre de la facilidad debe estar en
minúsculas.
--syslog-ident
<string>
Al registrar en syslog, establece el
ident.
--loglevel <0-5/none/error/warning/notice/info/deb
ug>
Establece el nivel de registro
predeterminado.
--channel-loglevel <channel-name> <0-5/none/error/warning/notice/info/deb
ug>
Establece el nivel de registro para un canal de registro
específico.
--threads
<integer>
Pista para el número de hilos adicionales a usar para cálculos potencialmente largos (como el cifrado y la generación de OTP). Si es cero (0) (predeterminado), los hilos adicionales estarán deshabilitados y todos los cálculos se realizarán en el bucle de eventos. Si es negativo (<0), se hará una suposición, posiblemente basada en el número de CPUs. Si es positivo (>0), se usarán el número de hilos
dado.
--s
sl
Usa TLS. Requiere --nssdb y --server-cert-na
me.
--nssdb
<string>
Al usar TLS, la base de datos NSS a usar. Probablemente algo como sql:
/some/folder.
--client-cert-name
<string>
Al usar TLS, el nombre del certificado a usar. El certificado debe estar fácilmente
accesible.
--server-name
<string>
Establece el nombre del servidor usado para validar el certificado del servidor. El nombre del servidor predetermina al nombre en la dirección del servidor (o una dirección numérica)
.
--server-addr
<addr>
Establece la dirección en la que el servidor debe escuchar. Véase más abajo para el formato de la
dirección.
--tapdev
<name>
Establece el dispositivo TAP a usar. Véase más abajo cómo configurar el dispositivo. Un dispositivo TAP es una tarjeta virtual en el sistema operativo, pero en lugar de recibir de y enviar tramas a una pieza de hardware, un programa (este uno) lo abre para leer de y escribir tramas en él. Si la red VPN está configurada correctamente, los dispositivos TAP en los nodos VPN actuarán como si estuvieran todos conectados a un conmutador de
red.
--scope
<scope_name>
Añade un ámbito de dirección permitido para conectarse a los pares. Puede especificarse varias veces para añadir múltiples ámbitos. El orden de los ámbitos es irrelevante. Tenga en cuenta que debe ser realmente posible conectarse a las direcciones en el ámbito dado; cuando otro par se enlaza para que nos conectemos, elegimos la primera dirección externa cuyo ámbito reconocemos, y no intentamos más direcciones externas, incluso si la conexión
falla.
--bind-addr
<addr>
Añade una dirección para permitir enlazar. Véase más abajo para el formato de la dirección. Al intentar enlazar para que algún par se conecte a nosotros, las direcciones se probarán en el orden en que se especifican. Si se está usando el transporte de datos UDP, debe seguir una opción --num-ports para especificar cuántos puertos continuos permitir enlazar. Para que la dirección sea útil, una o más opciones --ext-addr deben seguir. Tenga en cuenta que cuando dos pares necesitan establecer una conexión de datos, es arbitrario cuál de ellos intentará enlazar
primero.
--num-ports
<num>
Al usar transporte UDP, establece el número de puertos continuos para una dirección de enlace especificada previamente. Debe seguir una opción --bind-addr
previa.
--ext-addr <addr / {server_reported}:port>
<scope_name>
Añade una dirección externa para una dirección de enlace especificada previamente. Debe seguir una opción --bind-addr previa. Puede especificarse varias veces para añadir múltiples direcciones externas. Véase más abajo para el formato de la dirección. Además, la parte de la dirección IP puede ser {server_reported} para usar la dirección IPv4 como el servidor nos ve. Las direcciones externas son probadas por el par que se conecta en el orden en que se especifican. Tenga en cuenta que el par que se conecta solo intenta conectarse a la primera dirección cuyo ámbito reconoce y no prueba otras direcciones. Esto significa que todas las direcciones deben funcionar para poder
comunicarse.
--transport-mode
<udp/tcp>
Establece el protocolo de transporte para las conexiones de datos. Se recomienda UDP y funciona mejor para la mayoría de las redes. Se puede usar TCP en su lugar si la red subyacente tiene una alta pérdida de paquetes que su red virtual no puede tolerar. Debe coincidir en todos los
pares.
--encryption-mode <blowfish/aes/no
ne>
Al usar transporte UDP, establece el modo de cifrado. None significa no cifrado, otras opciones significan un cifrado específico. Tenga en cuenta que el cifrado es solo útil si los clientes usan TLS para conectarse al servidor. El modo de cifrado debe coincidir en todos los
pares.
--hash-mode
<md5/sha1/none>
Cuando se usa el transporte UDP, establece el modo de hash. None significa sin hashes, otras opciones significan un tipo específico de hash. Tenga en cuenta que el hash solo es útil si se usa cifrado también. El modo de hash debe coincidir en todos los
pares.
--otp <blowfish/aes> <num>
<num-warn>
Cuando se usa el transporte UDP, habilita contraseñas de un solo uso. El primer argumento especifica un cifrado de bloque utilizado para generar contraseñas a partir de una semilla. El segundo argumento especifica cuántas contraseñas se generan de una sola semilla. El tercer argumento especifica después de cuántas contraseñas usadas para enviar paquetes se intenta negociar una nueva semilla con el otro par. num debe ser >0, y num-warn debe ser >0 y <=num. La diferencia (num - num-warn) debe ser lo suficientemente grande para permitir que una nueva semilla sea negociada antes de que el emisor se quede sin contraseñas. Negociar una semilla implica que el par emisor la envíe al par receptor a través del servidor y que el par receptor la confirme a través del servidor. Tenga en cuenta que las contraseñas de un solo uso solo son útiles si los clientes usan TLS para conectarse al servidor. La opción OTP debe coincidir en todos los pares, excepto para
num-warn.
--fragmentation-latency
<milliseconds>
Cuando se usa el transporte UDP, establece la latencia máxima a sacrificar para empaquetar tramas en paquetes de datos de manera más eficiente. Si es >=0, un temporizador de esa cantidad de milisegundos se usa para esperar más tramas para poner en un paquete incompleto desde que se escribió el primer fragmento del paquete. Si es <0, los paquetes se envían inmediatamente. Por defecto es 0, que es la configuración
recomendada.
--peer-s
sl
Cuando se usa el transporte TCP, habilita TLS para conexiones de datos. Requiere usar TLS para la conexión al servidor. Para que esto funcione, los pares deben confiar en los certificados de los demás, y los certificados deben otorgar el contexto de uso del servidor TLS. Esta opción debe coincidir en todos los
pares.
--peer-tcp-socket-sndbuf <bytes
/ 0>
Establece el valor de la opción de socket SO_SNDBUF para los sockets TCP de los pares (cero para no establecerlo). Valores más bajos mejorarán la equidad cuando los datos de múltiples fuentes (local y de retransmisión) se envían a un par dado, pero pueden resultar en un ancho de banda menor si el producto de ancho de banda-retardo de la red es demasiado
grande.
--send-buffer-size
<num-packets>
Establece el tamaño mínimo de los búferes de envío de los pares para enviar tramas originadas desde este sistema, en número de
paquetes.
--send-buffer-relay-size
<num-packets>
Establece el tamaño mínimo de los búferes de envío de los pares para retransmitir tramas de otros pares, en número de
paquetes.
--max-macs
<num>
Establece el número máximo de direcciones MAC a recordar para un par. Cuando se supera el número, se reutilizará el espacio menos utilizado
recientemente.
--max-groups
<num>
Establece el número máximo de membresías de grupos IGMP a recordar para un par. Cuando se supera el número, se reutilizará el espacio menos utilizado
recientemente.
--igmp-group-membership-interval
<ms>
Establece el parámetro de Intervalo de Membresía de Grupo para el snooping de IGMP, en
milisegundos.
--igmp-last-member-query-time
<ms>
Establece el parámetro de Tiempo de Consulta del Último Miembro para el snooping de IGMP, en
milisegundos.
--allow-peer-talk-without-
ssl
Cuando SSL está habilitado, los clientes no solo se conectan al servidor usando SSL, sino que también intercambian mensajes a través del servidor
mediante otra capa de SSL. Esto protege los mensajes de ataques al servidor. Versiones anteriores de BadVPN (<1.999.109), sin embargo, no so
portan esto. Esta opción permite que clientes antiguos y nuevos interoperen al no usar SSL si el otro par no lo soporta. Sin embargo, anula l
os beneficios de seguridad de usar SSL, ya que el servidor (potencialmente comprometido) puede entonces ordenar a los pares que no usen SSL.

CONFIGURACIÓN DEL DISPOSITIVO

TAP

Para usar este programa, primero tienes que configurar un dispositivo de red TAP que actuará como un punto final para la red virtual. La configuración depende de tu sistema

operativo.

Ten en cuenta que el programa cliente no configura el dispositivo TAP de ninguna manera; solo lee y escribe tramas desde/hacia él. Tú eres responsable de configurarlo (p. ej., ponerlo en funcionamiento y establecer su dirección IP)

.

Linu

x

Necesitas habilitar la opción de configuración del kernel CONFIG_TUN. Si la habilitaste como módulo, podrías tener que cargarlo (`modprobe tun`) antes de que puedas crear el

dispositivo.

Luego deberías crear un dispositivo TAP persistente para que el programa cliente de VPN lo abra. Esto se puede hacer con tunctl o con el programa openvpn. El dispositivo se asociará con una cuenta de usuario que tendrá permiso para usarlo, que debería ser el mismo usuario como el que se ejecutará el programa cliente (¡no root!). Para crear el dispositivo con tunctl, usa `tunctl -u <user> -t tapN`, y para crearlo con openvpn, usa `openvpn --mktun --user <user> --dev tapN`, donde N es un número que identifica el dispositivo

TAP.

Una vez creado el dispositivo TAP, pasa `--tapdev tapN` al programa cliente para que use este dispositivo. Ten en cuenta que el dispositivo no se preservará a través de un apagado del sistema; consulta la documentación de tu SO si quieres automatizar la creación o configuración del

dispositivo.

Window

s

Windows no viene con un controlador TAP. El programa cliente usa el controlador TAP-Win32, que es parte de OpenVPN. Necesitas instalar la versión de código abierto (!) de OpenVPN, y en el instalador habilitar al menos las opciones `TAP Virtual Ethernet Adapter` y `Add Shortcuts to Start Menu`. Puedes obtener el instalador en
http://openvpn.net/index.php/open-sou

rce/downloads.html.

El instalador de OpenVPN crea automáticamente un dispositivo TAP en tu sistema cuando se ejecuta por primera vez. Para crear otro dispositivo, usa `Programs -> OpenVPN -> Utilities -> Add a new TAP virtual ethernet adapter`. Puede que tengas que instalar OpenVPN de nuevo para que este acceso directo

aparezca.

Una vez que tengas un dispositivo TAP, puedes configurarlo como una tarjeta de red física. Puedes reconocer los dispositivos TAP por su campo `Device

Name`.

Para usar el dispositivo, pasa `--tapdev "<driver_name>:<interface_name>"` al programa cliente, donde

<driver_name> es el nombre del controlador TAP (tap0901 para OpenVPN 2.1 y 2.2) (sensible a mayúsculas),
y <interface_name> es el nombre (humano) de la interfaz de red TAP (p. ej. `Local Area Connection 2`).
