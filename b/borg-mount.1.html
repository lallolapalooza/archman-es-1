NOMBRE

borg-mount - Monta un archivo o un repositorio completo como un sistema de archivos FUSE

SINOPSIS

borg [opciones comunes] mount [opciones] REPOSITORIO_O_ARCHIVO PUNTO_DE_MONTAJE [RUTA...]

DESCRIPCIÓN

Este comando monta un repositorio o un archivo como un sistema de archivos FUSE. Esto puede ser útil para explorar o restaurar archivos individuales.

Al restaurar, tenga en cuenta que la implementación actual de FUSE no soporta flags especiales del sistema de archivos ni ACLs.

Al montar un repositorio, los directorios superiores se nombrarán como los archivos y la estructura de directorios debajo de estos se cargará bajo demanda desde el repositorio al entrar en estos directorios, así que espere cierta demora.

A menos que se proporcione la opción --foreground , el comando se ejecutará en segundo plano hasta que el sistema de archivos sea desmontado.

Consejos de rendimiento:

  • al hacer un montaje de "repositorio completo": no entre en los directorios de archivo si no es necesario; esto evita la carga bajo demanda.
  • monte solo un archivo específico, no el repositorio completo.
  • monte solo rutas específicas en un archivo específico, no el archivo completo.

El comando borgfs proporciona un envoltorio para borg mount. Esto también puede usarse en entradas de fstab: /ruta/al/repo /punto/de/montaje fuse.borgfs defaults,noauto 0 0

Para permitir que un usuario normal use entradas de fstab, añada la opción user : /ruta/al/repo /punto/de/montaje fuse.borgfs defaults,noauto,user 0 0

Para la configuración de FUSE y las opciones de montaje, consulte la página de manual mount.fuse(8).

El comportamiento por defecto de Borg es usar los nombres de usuario y grupo archivados de cada archivo y mapearlos a los IDs de usuario y grupo respectivos del sistema. Alternativamente, usar numeric-ids usará en su lugar los IDs de usuario y grupo archivados sin ningún mapeo.

Las opciones de montaje uid y gid (implementadas por Borg) pueden usarse para anular los IDs de usuario y grupo de todos los archivos (es decir, borg mount -o uid=1000,gid=1000).

La página de manual hace referencia a las opciones de montaje user_id y group_id (implementadas por FUSE) que especifican el ID de usuario y grupo del propietario del montaje (es decir, el usuario que realiza el montaje). Se establece automáticamente por libfuse (o por el sistema de archivos si no se usa libfuse). Sin embargo, no debería especificar estas manualmente. A diferencia de las opciones de montaje uid y gid que afectan a todos los archivos, user_id y group_id afectan al ID de usuario y grupo del directorio base montado.

Opciones de montaje adicionales soportadas por borg:

  • versions: cuando se usa con un montaje de repositorio, esto proporciona una vista fusionada y versionada de los archivos en los archivos. EXPERIMENTAL; la disposición puede cambiar en el futuro.
  • allow_damaged_files: por defecto los archivos dañados (donde los fragmentos faltantes fueron reemplazados con secuencias de ceros por borg check --repair) no son legibles y devuelven EIO (error de E/S). Establezca esta opción para leer tales archivos.
  • ignore_permissions: por razones de seguridad, la opción de montaje default_permissions es aplicada internamente por borg. ignore_permissions puede darse para no aplicar default_permissions.

La variable de entorno BORG_MOUNT_DATA_CACHE_ENTRIES está destinada a usuarios avanzados para ajustar el rendimiento. Establece el número de fragmentos de datos en caché; el uso adicional de memoria puede ser de hasta ~8 MiB por este número. El defecto es el número de núcleos de la CPU.

Cuando el proceso daemonizado recibe una señal o falla, no desmonta. Desmontar en estos casos podría causar que un proceso rsync activo o similar elimine datos involuntariamente.

Cuando se ejecuta en primer plano, ^C/SIGINT desmonta limpiamente el sistema de archivos, pero otras señales o fallos no lo hacen.

Depuración:

borg mount usualmente se daemoniza y el proceso daemon envía stdout/stderr a /dev/null. Por lo tanto, necesita usar ya sea -f / --foreground para que permanezca en primer plano y no se daemonice, o usar BORG_LOGGING_CONF para reconfigurar el logger para que salga a un archivo.

OPCIONES

Consulte borg-common(1) para las opciones comunes de los comandos de Borg.

argumentos

REPOSITORIO_O_ARCHIVO
repositorio o archivo a montar
PUNTO_DE_MONTAJE
dónde montar el sistema de archivos
RUTA
rutas a extraer; se soportan patrones

opciones

--consider-checkpoints
Mostrar los archivos de punto de control en la lista de contenidos del repositorio (por defecto: ocultos).
-f, --foreground
permanecer en primer plano, no daemonizar
-o
Opciones de montaje extra
--numeric-owner
obsoleto, use --numeric-ids en su lugar
--numeric-ids
usar identificadores numéricos de usuario y grupo de los archivo(s)

Filtros de archivo

-PPREFIJO,--prefixPREFIJO
solo considerar nombres de archivo que comiencen con este prefijo. (obsoleto)
-aGLOB,--glob-archivesGLOB
solo considerar nombres de archivo que coincidan con el glob. Se aplican reglas de sh: (sin usar realmente el prefijo sh:), consulte "borg help patterns".
--sort-byCLAVES
Lista de claves de ordenación separadas por comas; claves válidas son: timestamp, archive, name, id; por defecto es: timestamp
--firstN
considerar los primeros N archivos después de aplicar otros filtros
--lastN
considerar los últimos N archivos después de aplicar otros filtros

Opciones de Incluir/Excluir

-ePATRÓN,--excludePATRÓN
excluir rutas que coincidan con PATRÓN
--exclude-fromARCHIVO_DE_EXCLUSIÓN
leer patrones de exclusión de ARCHIVO_DE_EXCLUSIÓN, uno por línea
--patternPATRÓN
incluir/excluir rutas que coincidan con PATRÓN
--patterns-fromARCHIVO_DE_PATRONES
leer patrones de inclusión/exclusión de ARCHIVO_DE_PATRONES, uno por línea
--strip-componentsNÚMERO
Eliminar el número especificado de elementos iniciales de la ruta. Las rutas con menos elementos se omitirán silenciosamente.
