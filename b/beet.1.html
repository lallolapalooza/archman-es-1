NOMBRE

beet - etiquetador de música y organizador de biblioteca

SINOPSIS

beet [args...] command [args...]
beet help command

COMANDOS

import

beet import [-CWAPRqst] [-l LOGPATH] PATH...
beet import [opciones] -L QUERY

Añade música a tu biblioteca, intentando obtener etiquetas correctas para ella desde MusicBrainz.

Apunta el comando a algo de música: directorios, archivos individuales o archivos comprimidos. La música se copiará a una estructura de directorios configurable y se añadirá a una base de datos de la biblioteca. El comando es interactivo e intentará que verifiques las etiquetas de MusicBrainz que considera sospechosas. Consulta la guía de etiquetado automático para detalles sobre cómo usar el flujo interactivo de corrección de etiquetas.

Banderas opcionales del comando:

  • Por defecto, el comando copia los archivos a tu directorio de biblioteca y actualiza las etiquetas ID3 de tu música. Para mover los archivos en lugar de copiarlos, usa la opción -m (mover). Si prefieres dejar tus archivos de música intactos, prueba las opciones -C (no copiar) y -W (no escribir etiquetas). También puedes desactivar este comportamiento por defecto en el archivo de configuración (más abajo).
  • Además, puedes desactivar por completo el comportamiento de etiquetado automático usando -A (no etiquetar automáticamente)---entonces tu música se importará con sus metadatos existentes.
  • Durante una importación larga de etiquetado, puede ser útil llevar un registro de los álbumes que no se etiquetaron correctamente---ya sea porque no están en la base de datos de MusicBrainz o porque hay algo mal con los archivos. Usa la opción -l para especificar un nombre de archivo para registrar cada vez que omitas un álbum o lo importes "tal cual" o un álbum se omita como duplicado. Puedes revisar el archivo manualmente más tarde o importar rutas omitidas del archivo de registro automáticamente usando el argumento --from-logfile LOGFILE .
  • Relacionado con esto, la opción -q (silencioso) puede ayudar con importaciones grandes al etiquetar automáticamente sin molestar nunca pidiendo entrada del usuario. Siempre que el modo normal del etiquetador automático pediría confirmación, el modo silencioso realiza una acción de respaldo que se puede configurar usando la configuración quiet_fallback o la opción CLI --quiet-fallback . Por defecto, de manera pesimista, omite`` el archivo. Alternativamente, se puede usar tal cual, configurando ``asis.
  • Hablando de reanudar importaciones interrumpidas, el etiquetador te preguntará si parece que la última importación del directorio fue interrumpida (por ti o por un fallo). Si quieres omitir esta pregunta, puedes decir "sí" automáticamente proporcionando -p o "no" usando -P. La función de reanudación se puede desactivar por defecto usando una opción de configuración (ver más abajo).
  • Si quieres importar solo lo nuevo de un directorio, usa la opción -i para ejecutar una importación incremental . Con esta bandera, beets llevará un registro de cada directorio que importe alguna vez y evitará importarlos de nuevo. Esto es útil si tienes un directorio de "entrada" al que añades cosas periódicamente. Para que esto funcione correctamente, necesitarás usar una importación incremental cada vez que ejecutes una importación en el directorio correspondiente---incluyendo la primera vez, cuando no se omitirá ningún subdirectorio. Así que considera habilitar la opción de configuración incremental .
  • Si no quieres registrar los archivos omitidos durante una importación incremental , usa la bandera --incremental-skip-later que corresponde a la opción de configuración incremental_skip_later . Establecer la bandera evita que beets persista las decisiones de omisión durante una importación no interactiva para que un usuario pueda tomar una decisión sobre archivos omitidos previamente durante una ejecución posterior de importación interactiva. Para registrar archivos omitidos durante la importación incremental explícitamente, usa la opción --noincremental-skip-later .
  • Cuando beets aplica metadatos a tu música, conservará el valor de cualquier etiqueta existente que no haya sido sobrescrita, y la importará en la base de datos. Puede que prefieras usar solo los metadatos existentes para encontrar coincidencias, y borrarlos por completo cuando se apliquen nuevos metadatos. Puedes imponer este comportamiento con la opción --from-scratch , o la opción de configuración from_scratch .
  • Por defecto, beets procederá sin preguntar si encuentra una coincidencia de metadatos muy cercana. Para desactivar esto y hacer que el importador te pregunte cada vez, usa la opción -t (por tímido).
  • El importador típicamente funciona en modo de un álbum completo a la vez. Si en cambio quieres importar pistas individuales que no son de un álbum, usa el modo singleton proporcionando la opción -s .
  • Si tienes un álbum que está dividido en varios directorios bajo un directorio superior común, usa la opción --flat . Esta toma todos los archivos de música bajo el directorio (recursivamente) y los trata como un solo álbum grande en lugar de como un álbum por directorio. Esto puede ayudar con tus álbumes multidisco más difíciles.
  • De manera similar, si tienes un directorio que contiene varios álbumes, usa la opción --group-albums para dividir los archivos basándose en sus metadatos antes de emparejarlos como álbumes separados.
  • Si quieres previsualizar qué archivos se importarían, usa la opción --pretend . Si se establece, beets simplemente imprimirá una lista de archivos que de otro modo importaría.
  • Si ya tienes un ID de backend de metadatos que coincide con los elementos a importar, puedes instruir a beets para que restrinja la búsqueda a ese ID en lugar de buscar otros candidatos usando la opción --search-id SEARCH_ID . Se pueden especificar varios IDs simplemente repitiendo la opción varias veces.
  • Puedes proporcionar --set field=value para asignar field a value en la importación. Los valores admiten la misma sintaxis de plantilla que los formatos de rutade beets. Estas asignaciones se fusionarán con (y posiblemente sobrescribirán) el diccionario de configuración set_fields . Puedes usar la opción varias veces en la línea de comandos, así:
beet import --set genre="Alternative Rock" --set mood="emotional"

list

beet list [-apf] QUERY

Consultas la base de datos de música.

¿Quieres buscar "Gronlandic Edit" de of Montreal? Prueba beet list gronlandic. ¿Quizás quieres ver todo lo publicado en 2009 con "vegetables" en el título? Prueba beet list year:2009 title:vegetables. También puedes especificar el orden de clasificación. (Lee más en Consultas.)

Puedes usar el interruptor -a para buscar álbumes en lugar de elementos individuales. En este caso, las consultas que uses se restringen a campos de nivel de álbum: por ejemplo, puedes buscar year:1969 pero las partes de consulta para campos de nivel de elemento como title:foo serán ignoradas. Recuerda que artist es un campo de nivel de elemento; albumartist es el campo de álbum correspondiente.

remove

beet remove [-adf] QUERY

Elimina música de tu biblioteca.

Este comand usa la misma sintaxis de query que el comando list. Por defecto, solo elimina entradas de la base de datos de la biblioteca; no toca los archivos en el disco. Para eliminar realmente los archivos, usa la bandera -d. Cuando se proporciona la bandera -a, el comando opera sobre álbumes en lugar de pistas individuales. Cuando ejecutas el comando remove, imprime una lista de todos los elementos afectados en la biblioteca y solicita tu permiso antes de eliminarlos. Luego puedes elegir abortar (escribe n), confirmar (y), o elegir interactivamente algunos de los elementos (s). En este último caso, el comando te pedirá cada elemento o álbum coincidente y te invitará a escribir y para eliminar el elemento/álbum, n para conservarlo o q para salir y solo eliminar los elementos/álbumes seleccionados hasta ese momento. Esta opción te permite elegir con precisión qué pistas/álbumes eliminar sin pasar demasiado tiempo creando cuidadosamente una consulta. Si no deseas que se te pida confirmación, usa la opción -f.

modify

beet modify [-IMWay] [-f FORMAT] QUERY [FIELD=VALUE...] [FIELD!...]

Cambia los metadatos de elementos o álbumes en la base de datos.

Proporciona una consulta que coincida con las cosas que deseas cambiar y una serie de pares campo=valor. Por ejemplo, beet modify genius of love artist="Tom Tom Club" cambiará el artista de la pista "Genius of Love". Para eliminar campos (lo que solo es posible para atributos flexibles), sigue el nombre del campo con un signo de exclamación: campo!.

Los valores también pueden ser plantillas, utilizando la misma sintaxis que los formatos de ruta. Por ejemplo, beet modify artist='$artist_sort' copiará el nombre de ordenación del artista en el campo del artista para todas tus pistas, y beet modify title='$track $title' agregará números de pista a sus metadatos de título.

La opción -a cambia a consultar campos de álbum en lugar de campos de pista y también permite operar sobre álbumes además de las pistas individuales. Sin esta bandera, el comando solo cambiará datos a nivel de pista, incluso si todas las pistas pertenecen al mismo álbum. Si deseas cambiar un campo a nivel de álbum, como year o albumartist, querrás usar la bandera -a para evitar una situación confusa en la que los datos de pistas individuales entren en conflicto con los datos del álbum completo.

Las modificaciones emitidas usando -a se propagan automáticamente a las pistas individuales. Para evitar este comportamiento, usa -I/--noinherit.

Los elementos se moverán automáticamente cuando sea necesario si se encuentran en tu directorio de biblioteca, pero puedes deshabilitar eso con -M. Las etiquetas se escribirán en los archivos según la configuración que tengas para las importaciones, pero estas se pueden anular con -w (escribir etiquetas, por defecto) y -W (no escribir etiquetas).

Cuando ejecutas el comando modify, imprime una lista de todos los elementos afectados en la biblioteca y solicita tu permiso antes de realizar cualquier cambio. Luego puedes elegir abortar el cambio (escribe n), confirmar (y), o elegir interactivamente algunos de los elementos (s). En este último caso, el comando te pedirá cada elemento o álbum coincidente y te invitará a escribir y para aplicar los cambios, n para descartarlos o q para salir y aplicar los cambios seleccionados. Esta opción te permite elegir con precisión qué datos cambiar sin pasar demasiado tiempo creando cuidadosamente una consulta. Para omitir las solicitudes por completo, usa la opción -y.

move

beet move [-capt] [-d DIR] QUERY

Mueve o copia elementos en tu biblioteca.

Este comando, por defecto, actúa como un consolidar de biblioteca: los elementos que coinciden con la consulta se renombran en la estructura del directorio de tu biblioteca. Al especificar un directorio de destino con -d manualmente, puedes mover elementos que coincidan con una consulta a cualquier lugar de tu sistema de archivos. La opción -c copia archivos en lugar de moverlos. Al igual que con otros comandos, la opción -a coincide con álbumes en lugar de elementos. La bandera -e (para "exportar") copia archivos sin cambiar la base de datos.

Para realizar una "ejecución de prueba", simplemente usa la bandera -p (para "pretender"). Esto te mostrará una lista de archivos que se moverían pero en realidad no cambiará nada en el disco. La opción -t establece el modo tímido, que volverá a preguntar antes de mover o copiar realmente los archivos.

update

beet update [-F] FIELD [-e] EXCLUDE_FIELD [-aM] QUERY

Actualiza la biblioteca (y, por defecto, mueve archivos) para reflejar cambios de metadatos fuera de banda y eliminaciones de archivos.

Esto escaneará todos los archivos coincidentes y leerá sus etiquetas, poblando la base de datos con los nuevos valores. Por defecto, los archivos se renombrarán de acuerdo con sus nuevos metadatos; deshabilita esto con -M. Beets omitirá los archivos si sus tiempos de modificación no han cambiado, por lo que cualquier cambio de metadatos fuera de banda también debe actualizar estos para que beet update reconozca que los archivos han sido editados.

Para realizar una "ejecución de prueba" de una actualización, simplemente usa la bandera -p (para "pretender"). Esto te mostrará todos los cambios propuestos pero en realidad no cambiará nada en el disco.

Por defecto, todos los metadatos cambiados se poblarán de nuevo en la base de datos. Si solo deseas que se escriban ciertos campos, especifícalos con las banderas -F (que se pueden usar varias veces). Alternativamente, especifica los campos que no deseas escribir con las banderas -e (que se pueden usar varias veces). Para la lista de campos compatibles, consulta `beet fields`.

Cuando una pista actualizada forma parte de un álbum, los campos a nivel de álbum de todas las pistas del álbum también se actualizan. (Específicamente, el comando copia los datos a nivel de álbum de la primera pista del álbum y los aplica al resto de las pistas). Esto significa que, si los campos a nivel de álbum no son idénticos dentro de un álbum, algunos cambios mostrados por el comando update pueden ser anulados por datos de otras pistas del mismo álbum. Esto significa que ejecutar el comando update varias veces puede mostrar los mismos cambios aplicándose.

write

beet write [-pf] [QUERY]

Escribe metadatos de la base de datos en las etiquetas de los archivos.

Cuando realizas cambios en los metadatos almacenados en la base de datos de la biblioteca de beets (durante la importación o con el comando modify, por ejemplo), a menudo tienes la opción de almacenar los cambios solo en la base de datos, dejando tus archivos intactos. El comando write te permite cambiar de opinión más tarde y escribir el contenido de la base de datos en los archivos. Por defecto, esto escribe los cambios solo si hay una diferencia entre la base de datos y las etiquetas del archivo.

Puedes pensar en este comando como lo opuesto a update.

La opción -p previsualiza los cambios de metadatos sin aplicarlos realmente.

La opción -f fuerza la escritura en el archivo, incluso si las etiquetas del archivo coinciden con la base de datos. Esto es útil para asegurarse de que los complementos habilitados que se ejecutan al escribir (por ejemplo, los complementos Scrub y Zero) se ejecuten en el archivo.

stats

beet stats [-e] [QUERY]

Muestra algunas estadísticas sobre toda tu biblioteca (si no proporcionas una consulta) o los elementos coincidentes (si lo haces).

Por defecto, el comando calcula los tamaños de archivo utilizando su tasa de bits y duración. La opción -e (--exact) lee los tamaños exactos de cada archivo (pero es más lento). El modo exacto también muestra la duración exacta en segundos.

fields

beet fields

Muestra los campos de metadatos de elementos y álbumes disponibles para su uso en Consultas y Formatos de Ruta. La lista incluye cualquier campo de plantilla proporcionado por plugins y cualquier atributo flexible que hayas asignado manualmente a tus elementos y álbumes.

config

beet config [-pdc]
beet config -e

Muestra o edita la configuración del usuario. Este comando hace una de tres cosas:

  • Sin opciones, imprime una representación YAML de la configuración de usuario actual. Con la opción --default, las opciones predeterminadas de beets también se incluyen en la descarga.
  • La opción --path en cambio muestra la ruta a tu archivo de configuración. Esto se puede combinar con la bandera --default para mostrar dónde beets guarda sus valores predeterminados internos.
  • Por defecto, la información sensible como las contraseñas se elimina al volcar la configuración. La opción --clear incluye estos datos sensibles.
  • Con la opción --edit, beets intenta abrir tu archivo de configuración para editarlo. Primero intenta la variable de entorno $EDITOR, seguida de $EDITOR y luego una opción de respaldo según tu plataforma: open en OS X, xdg-open en Unix, e invocación directa en Windows.

FLAGS GLOBALES

Beets tiene algunas banderas "globales" que afectan a todos los comandos. Estas deben aparecer entre el nombre ejecutable (beet) y el comando; por ejemplo, beet -v import ....

  • -l LIBPATH: especifica el archivo de base de datos de la biblioteca a usar.
  • -d DIRECTORY: especifica el directorio raíz de la biblioteca.
  • -v: modo detallado; imprime un diluvio de información de depuración. Por favor, usa esta bandera al informar de errores. Puedes usarla dos veces, como en -vv, para hacer que beets sea aún más detallado.
  • -c FILE: lee un archivo de configuración YAML especificado. Esta configuración funciona como una superposición: en lugar de reemplazar completamente tus opciones de configuración normales, las dos se fusionan. Cualquier opción individual establecida en este archivo de configuración anulará los ajustes correspondientes en tu configuración base.
  • -p plugins: especifica una lista separada por comas de plugins a habilitar. Si se especifica, la lista de plugins en tu configuración se ignora. La forma larga de este argumento también permite especificar ningún plugin, deshabilitando efectivamente todos los plugins: --plugins=.
