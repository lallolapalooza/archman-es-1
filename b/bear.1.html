NOMBRE

Bear - una herramienta para generar bases de datos de compilación para herramientas de Clang.

SINOPSIS

bear [opciones] -- [comando de compilación]

DESCRIPCIÓN

La base de datos de compilación JSON http://clang.llvm.org/docs/JSONCompilationDatabase.html se utiliza en el proyecto Clang para proporcionar información sobre cómo se procesó una unidad de compilación individual. Cuando esto está disponible, es fácil volver a ejecutar la compilación con diferentes programas.

Bear ejecuta el comando de compilación original e intercepta las ejecuciones de comandos emitidas por la herramienta de compilación. A partir del registro de ejecuciones de comandos, intenta identificar las llamadas al compilador y crea la base de datos de compilación final.

OPCIONES

--version
Imprime el número de versión.
--help
Imprime el mensaje de ayuda.
--verbose
Habilita el registro detallado.
--output archivo
Especifica el archivo de salida. (Se proporciona un nombre de archivo predeterminado). La salida es una base de datos de compilación JSON.
--append
Utiliza el archivo de salida generado previamente y le agrega las nuevas entradas. De esta manera, puede ejecutar Bear continuamente durante el trabajo y mantendrá la base de datos de compilación actualizada. Se consideran tanto la eliminación como la adición de archivos. Pero los cambios en el proceso de compilación (cambios en las banderas del compilador) pueden causar entradas duplicadas.
--config archivo
Especifica un archivo de configuración. El archivo de configuración captura cómo se debe formatear la salida y qué entradas debe contener.
--force-preload
Fuerza el uso del método del enlazador dinámico para interceptar comandos.
--force-wrapper
Fuerza el uso del método del envoltorio del compilador para interceptar comandos.

COMANDOS

bear-intercept(1)
Intercepta los eventos que ocurrieron durante la ejecución del comando de compilación.
bear-citnames(1)
Deduce la semántica de los comandos capturados por bear-intercept(1).

SALIDA

La definición de la base de datos de compilación JSON ha cambiado con el tiempo. La versión actual de Bear genera entradas donde:

directory
tiene una ruta absoluta.
file
tiene una ruta absoluta.
output
tiene una ruta absoluta.
arguments
se utiliza en lugar de command para evitar problemas de escape del shell. (La configuración puede forzar la emisión del campo command). El compilador como primer argumento tiene una ruta absoluta. Algunas banderas no relacionadas con la compilación se filtran de la salida final.

ARCHIVO DE CONFIGURACIÓN

Lee la página del manual de bear-citnames(1) para conocer el contenido de este archivo. bear no lee el contenido de este archivo, sino que pasa el nombre del archivo al comando bear citnames.

ESTADO DE SALIDA

El estado de salida del programa es el estado de salida del comando de compilación. Excepto cuando el programa se bloquea, en cuyo caso se establece en un valor distinto de cero.

SOLUCIÓN DE PROBLEMAS

Los problemas potenciales que puedes encontrar son: la compilación con y sin Bear se comporta de manera diferente o la salida está vacía.

La causa más común de salidas vacías es que el comando de compilación no ejecutó ningún comando. La razón de esto podría ser que las compilaciones incrementales no ejecutan los compiladores si todo está actualizado. Recuerda, Bear no entiende el archivo de compilación (por ejemplo, makefile), sino que intercepta los comandos ejecutados.

La otra causa común de salida vacía es que la compilación tiene un paso de “configuración”, que captura el compilador para compilar el proyecto. En el caso de que Bear esté utilizando el modo wrapper (lee la página del manual de bear-intercept(1)), necesita ejecutar el paso de configuración con Bear también (y descartar esa salida), antes de ejecutar la compilación con Bear.

Puede haber muchas razones para cualquiera de estas fallas. Es mejor consultar la página wiki del proyecto para conocer los problemas conocidos, antes de abrir un informe de errores.
