Añadir los archivos o directorios especificados.

En modo no recursivo, todos los elementos nombrados se añaden, independientemente de si fueron ignorados previamente. Se emite una advertencia si alguno de los archivos nombrados ya está versionado.

En modo recursivo (el predeterminado), los archivos se tratan de la misma manera pero el comportamiento para los directorios es diferente. Los directorios que ya están versionados no generan advertencia. Todos los directorios, ya sea que estén versionados o no, se buscan archivos o subdirectorios que no estén ni versionados ni ignorados, y estos se añaden. Esta búsqueda procede recursivamente dentro de directorios versionados. Si no se dan nombres, se asume '.'.

Se imprimirá una advertencia cuando se encuentren árbols anidados, a menos que se ignoren explícitamente.

Por lo tanto, simplemente decir 'brz add' versionará todos los archivos que estén actualmente desconocidos.

Añadir un archivo cuyo directorio padre no está versionado añadirá implícitamente al padre, y así sucesivamente hasta la raíz. Esto significa que no debería necesitar añadir explícitamente un directorio, simplemente se añadirán cuando añada un archivo en el directorio.

--dry-run mostrará qué archivos se añadirían, pero no los añadirá realmente.

--file-ids-from intentará usar los ids de archivo de la ruta suministrada. Busca ids intentando encontrar un directorio padre coincidente con el mismo nombre de archivo, y luego por ruta pura. Esta opción rara vez es necesaria pero puede ser útil al añadir el mismo archivo lógico en dos ramas que se combinarán más tarde (sin mostrar los dos añadidos diferentes como un conflicto). También es útil al combinar otro proyecto en un subdirectorio de este uno.

Cualquier archivo que coincida con patrones en la lista de ignorados no se añadirá a menos que se mencione explícitamente.

En modo recursivo, los archivos mayores que la opción de configuración add.maximum_file_size se omitirán. Los elementos nombrados nunca se omiten debido a tamaño de archivo.

Encontrar un commit interesante usando una búsqueda binaria.

Biseccionar, en resumen, es una forma de encontrar el commit en el que se hizo algún cambio comprobable, como la introducción de un error o una característica. Al identificar una versión que no tenía el cambio interesante y una versión posterior que sí lo tenía, un desarrollador puede probar la presencia del cambio en varios puntos de la historia, terminando eventualmente en el commit preciso cuando el cambio se introdujo por primera vez.

Este comando usa subcomandos para implementar la búsqueda, cada uno de los cuales cambia el estado de la bisección. Los subcomandos son:

brz bisect start
Iniciar una bisección, posiblemente limpiando una bisección anterior.

brz bisect yes [-r rev]
La revisión especificada (o la revisión actual, si no se da)
tiene la característica que estamos buscando,

brz bisect no [-r rev]
La revisión especificada (o la revisión actual, si no se da)
no tiene la característica que estamos buscando,

brz bisect move -r rev
Cambiar manualmente a una revisión diferente. Usar si el algoritmo de bisección
elige una revisión que no es adecuada. Intentar
mover lo menos posible.

brz bisect reset
Limpiar una bisección en progreso.

brz bisect log [-o archivo]
Sacar por salida estándar un registro de la bisección actual, o
al archivo especificado.

Hacer commit de los cambios en una nueva revisión.

Se debe dar un mensaje explicativo para cada commit. Esto se hace a menudo usando la opción --message (obteniendo el mensaje de la línea de comandos) o usando la opción --file (obteniendo el mensaje de un archivo). Si no se da ninguna de estas opciones, se abre un editor para que el usuario introduzca el mensaje. Para ver los archivos modificados en el texto de plantilla cargado en el editor, use la opción --show-diff.

Por defecto, se hace commit de todo el árbol y se asume que la persona que realiza el commit es el autor. Estos valores predeterminados se pueden sobrescribir como se explica a continuación.

Commits selectivos:


Si se especifican archivos seleccionados, solo se hace commit de
los cambios de esos archivos. Si se especifica un directorio, entonces
se hace commit del directorio y de todo lo que contiene.


Cuando se dan exclusiones, tienen prioridad sobre los archivos seleccionados.
Por ejemplo, para hacer commit solo de los cambios dentro de foo, pero no de los cambios
dentro de foo/bar:


brz commit foo -x foo/bar


Un commit selectivo después de una fusión aún no está soportado.

Autores personalizados:


Si el autor del cambio no es la misma persona que realiza el commit,
puede especificar el nombre del autor usando la opción --author. El
nombre debe estar en el mismo formato que un committer-id, p. ej.
"John Doe <jdoe@example.com>". Si hay más de un autor de
el cambio, puede especificar la opción varias veces, una por cada
autor.

Comprobaciones:


Un error común es olvidar añadir un archivo o directorio nuevo antes de
ejecutar el comando commit. La opción --strict comprueba si hay archivos
desconocidos y aborta el commit si se encuentran. Se pueden implementar
comprobaciones pre-commit más avanzadas definiendo hooks. Vea \*(Aq\*(Aqbrz help hooks\*(Aq\*(Aq
para más detalles.

Cosas a tener en cuenta:


Si accidentalmente hace commit de los cambios equivocados o comete un error
de ortografía en el mensaje del commit, puede usar el comando uncommit
para deshacerlo. Vea \*(Aq\*(Aqbrz help uncommit\*(Aq\*(Aq para más detalles.


Los hooks también se pueden configurar para ejecutarse después de un commit. Esto le permite
desencadenar actualizaciones en sistemas externos como rastreadores de errores. La opción --fixes
se puede usar para registrar la asociación entre una revisión y
uno o más errores. Vea \*(Aq\*(Aqbrz help bugs\*(Aq\*(Aq para más detalles.

Mostrar diferencias en el árbol de trabajo, entre revisiones o ramas.

Si no se dan argumentos, se listan todos los cambios para el árbol actual. Si se dan archivos, solo se listan los cambios en esos archivos. RemEl control de versiones y las múltiples ramas se pueden comparar usando las opciones --old y --new. Si no se proporcionan, el valor predeterminado para ambos se deriva del primer argumento, si lo hay, o del árbol actual si no se proporcionan argumentos.

"brz diff -p1" es equivalente a "brz diff --prefix old/:new/", y produce parches adecuados para "patch -p1".

Tenga en cuenta que al usar el argumento -r con un rango de revisiones, las diferencias se calculan entre las dos revisiones especificadas. Esto difiere de la interpretación de rangos de revisiones utilizada por "brz log", que incluye la primera revisión en el rango.

2 - cambios irrepresentables

Realiza una fusión de tres vías.

El origen de la fusión puede especificarse bien en forma de una rama, bien en forma de una ruta a un archivo que contenga una directiva de fusión generada con brz send. Si no se especifica ninguno, el valor predeterminado es la rama ascendente o la rama fusionada más recientemente usando --remember. El origen de la fusión también puede especificarse en forma de una ruta a un archivo en otra rama: en este caso, solo las modificaciones a ese archivo se fusionan en el árbol de trabajo actual.

Al fusionar desde una rama, por defecto brz intentará fusionar todo el trabajo nuevo de la otra rama, determinando automáticamente una revisión base apropiada. Si esto falla, puede que necesites proporcionar una base explícita.

Para elegir una revisión final diferente, pasa "--revision OTRA". brz intentará fusionar todo el trabajo nuevo hasta e incluyendo la revisión OTRA.

Si especificas dos valores, "--revision BASE..OTRA", solo se fusionarán las revisiones de BASE a OTRA, excluyendo BASE pero incluyendo OTRA. Si esto causa que se omitan algunas revisiones, es decir, si la rama de destino no contiene ya la revisión BASE, una fusión así se denomina comúnmente "cherrypick". A diferencia de una fusión normal, Breezy actualmente no rastrea los cherrypicks. Los cambios parecen una confirmación normal, y el historial de los cambios de la otra rama no se almacena en la confirmación.

Los números de revisión son siempre relativos a la rama de origen.

merge hará todo lo posible para combinar los cambios en dos ramas, pero hay algunos tipos de problemas que solo un humano puede arreglar. Cuando encuentre esos problemas, marcará un conflicto. Un conflicto significa que necesitas arreglar algo antes de poder confirmar.

Usa brz resolve cuando hayas arreglado un problema. Véase también brz conflicts.

Si no hay una rama predeterminada configurada, la primera fusión la configurará (usa --no-remember para evitar configurarla). Después de eso, puedes omitir la rama para usar la predeterminada. Para cambiar la predeterminada, usa --remember. El valor solo se guardará si se puede acceder a la ubicación remota.

Los resultados de la fusión se colocan en el directorio de trabajo de destino, donde pueden ser revisados (con brz diff), probados y luego confirmados para registrar el resultado de la fusión.

merge se niega a ejecutarse si hay cambios sin confirmar, a menos que se proporcione --force. Si se proporciona --force, entonces los cambios del origen se fusionarán con el árbol de trabajo actual, incluyendo cualquier cambio sin confirmar en el árbol. La opción --force también se puede usar para crear una revisión de fusión que tenga más de dos padres.

Si se desea fusionar cambios del árbol de trabajo de la otra rama sin fusionar ninguna revisión confirmada, se puede proporcionar la opción --uncommitted.

Para seleccionar solo algunos cambios para fusionar, usa "merge -i", que te pedirá que apliques cada fragmento de diferencia y cambio de archivo, similar a "shelve".

NAME

brz - Breezy is a decentralized source code management tool

SYNOPSIS

brz [OPTIONS] COMMAND [COMMAND OPTIONS]

DESCRIPTION

Breezy is a decentralized source code management tool. It aims to be simple to use, yet powerful enough for most development workflows. Breezy supports a wide variety of version control workflows, including centralized, decentralized, and hybrid models.

This manual page describes the common commands and options available in Breezy. For a comprehensive list and detailed explanation, please refer to the official Breezy documentation.

COMMAND OVERVIEW

The brz command provides a rich set of subcommands for managing your source code. Some of the most common commands include:

  • brz init: Initialize a new Breezy repository.
  • brz update: Update your working copy to the latest revision.
  • brz commit: Commit changes to your repository.
  • brz log: View the commit history.
  • brz diff: Show differences between revisions or working copy.
  • brz branch: Manage branches within your repository.
  • brz merge: Merge changes from one branch to another.
  • brz push: Push your changes to a remote repository.
  • brz pull: Pull changes from a remote repository.
  • brz view: Manage named views of your repository.
  • brz whoami: Show or set the current user identity.

COMMAND REFERENCE

brz view

Manage named views of your repository. A view is a snapshot of your repository at a specific point in time, defined by a set of files and directories.

Options:
--delete: Delete the current or named view.
--switch NAME: Switch to the specified named view.
--switch off: Disable the current view.
--name NAME: Specify a name for the view.
--all: Operate on all named views.
--help, -h: Show help message.
--usage: Show usage message and options.

When no options are given, the command lists the current view. If you define a view, you can switch back to your view after that.

Examples:
To define the current view:


brz view file1 dir1 ...


To list the current view:


brz view


To delete the current view:


brz view --delete


To disable the current view without deleting it:


brz view --switch off


To define a named view and switch to it:


brz view --name view-name file1 dir1 ...


To list a named view:


brz view --name view-name


To delete a named view:


brz view --name view-name --delete


To switch to a named view:


brz view --switch view-name


To list all views defined:


brz view --all


To delete all views:


brz view --delete --all

brz whoami [NAME]

Show or set brz user id.

Options:
--branch Set identity for the current branch
instead of globally.
--directory ARG, -d Branch to operate on, instead of working
directory.
--email Display email address only.
--help, -h Show help message.
--quiet, -q Only display errors and warnings.
--usage Show usage message and options.
--verbose, -v Display more information.

Examples:
Show the email of the current user:


brz whoami --email


Set the current user:


brz whoami "Frank Chu <fchu@example.com>"
