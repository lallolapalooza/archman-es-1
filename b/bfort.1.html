NOMBRE

bfort - programa para extraer definiciones cortas para una interfaz de Fortran a C

ENTRADA

nombres_de_archivo
- Nombra los archivos de los que se extraerán las definiciones de lint
-nomsgs
- No generar mensajes para rutinas que no se pueden convertir a Fortran.
-nofort
- Generar mensajes para todas las rutinas/macros sin un homólogo Fortran.
-dir nombre
- Directorio para el archivo de salida
-I nombre
- archivo que contiene includes comunes
-mapptr
- traducir punteros a índices enteros
-ptrprefix
- prefijo para nombres de funciones a convertir desde/hacia punteros (el valor por defecto es __). La macro que selecciona la forma basada en el tamaño del puntero se puede cambiar con -ptr64.
-anyname
- Generar un único envoltura Fortran que funcione para casi todos los sistemas, agregando nombres del preprocesador C (ver abajo). Estos nombres se pueden cambiar con -fcaps, -fuscore, y -fduscore.
-ferr
- Las versiones Fortran devuelven el valor de la rutina como último argumento (un entero). Esto se usa en MPI y es un enfoque bastante común para manejar retornos de error.
-shortargname
- Usar nombres de argumento cortos (un solo carácter) en lugar del nombre en la definición C.
-fstring
- Habilitar el manejo de parámetros de caracteres Fortran, usando la interfaz de llamada más común. Esto es lo predeterminado a menos que la variable de entorno BFORT_STRINGHANDLING se establezca en IGNORE.
-fnostring
- Deshabilitar el manejo de parámetros de caracteres Fortran. Las rutinas con argumentos de tipo char en C no tendrán rutinas de interfaz generadas para ellas.
-fstring
- asis - Sin procesamiento especial para argumentos de cadena. Proporcionado para compatibilidad hacia atrás con versiones anteriores de bfort que no manejaban cadenas
-mpi
- Manejar tipos MPI (algunas cosas son punteros por definición)
-no_pmpi
- No generar nombres PMPI
-pmpi nombre
- Cambiar la macro utilizada para seleccionar la versión de perfilado MPI
-noprofile
- Desactivar la generación de la versión de perfilado
-mnative
- Múltiples indirectos son tipos de datos nativos (sin coerción)
-voidisptr
- Considerar "void *" como un puntero a una estructura.
-nodebug
- No agregar 
#ifndef DEBUG_ALL
#define DEBUG_ALL
#endif

al archivo de envoltura.

-anyname
- Generar una envoltura única que pueda manejar los tres casos más comunes: guión bajo final, sin guión bajo y todo en mayúsculas. La elección se basa en si 
FORTRANCAPS:       Los nombres están en mayúsculas, sin guión bajo final
FORTRANUNDERSCORE: Los nombres están en minúsculas, con guión bajo final
FORTRANDOUBLEUNDERSCORE: Los nombres están en minúsculas, con DOS guiones bajos finales

están definidos. Esto es necesario cuando se utilizan algunas versiones de "f2c" para generar C para rutinas Fortran. Tenga en cuenta que f2c usa dos guiones bajos SOLAMENTE cuando el nombre ya contiene un guión bajo (al menos en el sistema FreeBSD que uso que utiliza f2c). Para manejar este caso, el código generado contiene el segundo guión bajo solo cuando el nombre ya contiene uno.

Si también se elige -mapptr, entonces

POINTER_64_BITS

también se usará para determinar si los punteros son demasiado largos para caber en un entero Fortran de 32 bits. Las rutinas que destruyen un puntero deberán insertar manualmente una llamada a __RmPointer. Las rutinas para gestionar los punteros se encuentran en ptrcvt.c

Además, si se usa -mpi y no se usa -no_pmpi, también se generan los nombres de perfilado MPI, rodeados por MPI_BUILD_PROFILING.

NOTA

Realmente necesitamos una forma de especificar un tipo general como puntero, para que se maneje como puntero. La opción -mpi es una solución provisional para una necesidad apremiante. Eventualmente, debería proporcionarse una opción "-ptr nombre" y mantenerse en un espacio de búsqueda al buscar tipos conocidos.
