BIO_read(3ssl)

Paquete: openssl

Licencias: Apache-2.0

BIO_READ(3ssl) OpenSSL BIO_READ(3ssl)

NOMBRE

BIO_read_ex, BIO_write_ex, BIO_read, BIO_write, BIO_gets, BIO_get_line, BIO_puts - Funciones de E/S BIO

SINOPSIS

#include <openssl/bio.h>
int BIO_read_ex(BIO *b, void *data, size_t dlen, size_t *readbytes);
int BIO_write_ex(BIO *b, const void *data, size_t dlen, size_t *written);
int BIO_read(BIO *b, void *data, int dlen);
int BIO_gets(BIO *b, char *buf, int size);
int BIO_get_line(BIO *b, char *buf, int size);
int BIO_write(BIO *b, const void *data, int dlen);
int BIO_puts(BIO *b, const char *buf);

DESCRIPCIÓN

BIO_read_ex() intenta leer dlen bytes del BIO b y coloca los datos en data. Si se leyeron bytes con éxito, el número de bytes leídos se almacena en *readbytes.

BIO_write_ex() intenta escribir dlen bytes de data en el BIO b. Si tiene éxito, el número de bytes escritos se almacena en *written, a menos que written sea NULL.

BIO_read() intenta leer len bytes del BIO b y coloca los datos en buf.

BIO_gets() realiza la operación "gets" del BIO y coloca los datos en buf. Normalmente, esta operación intentará leer una línea de datos del BIO con una longitud máxima de size-1. Sin embargo, hay excepciones; por ejemplo, BIO_gets() en un BIO de digestión calculará y devolverá la digestión y otros BIOs pueden no admitir BIO_gets() en absoluto. La cadena devuelta siempre termina en NUL y el '\n' se conserva si está presente en los datos de entrada. En datos binarios puede haber caracteres NUL dentro de la cadena; en este caso, el valor de retorno (si es no negativo) puede dar una longitud incorrecta.

BIO_get_line() intenta leer del BIO b una línea de datos hasta el siguiente '\n' o hasta que se alcance la longitud máxima size-1 y coloca los datos en buf. La cadena devuelta siempre termina en NUL y el '\n' se conserva si está presente en los datos de entrada. En datos binarios puede haber caracteres NUL dentro de la cadena; en este caso, el valor de retorno (si es no negativo) indica la longitud real leída. Para implementar esto, lamentablemente los datos deben leerse byte a byte.

BIO_write() intenta escribir len bytes de buf en el BIO b.

BIO_puts() intenta escribir una cadena terminada en NUL buf en el BIO b.

VALORES DE RETORNO

BIO_read_ex() devuelve 1 si se leyeron datos con éxito, y 0 en caso contrario.

BIO_write_ex() devuelve 1 si no se encontró ningún error al escribir los datos, 0 en caso contrario. Solicitar escribir 0 bytes no se considera un error.

BIO_write() devuelve -2 si la operación "write" no está implementada por el BIO o -1 en otros errores. En caso contrario, devuelve la cantidad de bytes escritos. Esto puede ser 0 si el BIO b es NULL o dlen <= 0.

BIO_gets() devuelve -2 si la operación "gets" no está implementada por el BIO o -1 en otros errores. En caso contrario, devuelve típicamente la cantidad de datos leídos, pero dependiendo de la implementación, puede devolver solo la longitud hasta el primer carácter NUL contenido en los datos leídos. En cualquier caso, el NUL final que se añade después de los datos leídos no se incluye en la longitud devuelta.

Todas las demás funciones devuelven la cantidad de datos leídos o escritos con éxito (si el valor de retorno es positivo) o que no se leyó ni escribió ningún dato si el resultado es 0 o -1. Si el valor de retorno es -2, la operación no está implementada en el tipo de BIO específico.

NOTAS

Un retorno de 0 o -1 no es necesariamente una indicación de un error. En particular, cuando la fuente/sumidero no es bloqueante o de cierto tipo, puede ser simplemente una indicación de que actualmente no hay datos disponibles y que la aplicación debería reintentar la operación más tarde.

Una técnica utilizada a veces con sockets bloqueantes es usar una llamada al sistema (como select(), poll() o equivalente) para determinar cuándo hay datos disponibles y luego llamar a read() para leer los datos. El equivalente con BIOs (es decir, llamar a select() en la estructura de E/S subyacente y luego llamar a BIO_read() para leer los datos) no debe usarse porque una sola llamada a BIO_read() puede provocar varias lecturas (y escrituras en el caso de BIOs SSL) en la estructura de E/S subyacente y puede bloquearse como resultado. En su lugar, select() (o equivalente) debe combinarse con E/S no bloqueantes para que las lecturas sucesivas soliciten un reintento en lugar de bloquearse.

Consulte BIO_should_retry(3) para obtener detalles sobre cómo determinar la causa de un reintento y otros problemas de E/S.

Si el método "gets" no es compatible con un BIO, se puede usar BIO_get_line(). También es posible hacer que BIO_gets() sea utilizable incluso si el método "gets" no es compatible agregando un BIO de búfer BIO_f_buffer(3) a la cadena.

VER TAMBIÉN

BIO_should_retry(3)

HISTORIA

BIO_gets() en 1.1.0 y anteriores, cuando se llamaba en un BIO basado en BIO_fd(), no conservaba el '\n' al final de la línea en el búfer.

BIO_get_line() se añadió en OpenSSL 3.0.

BIO_write_ex() devuelve 1 si el tamaño de los datos a escribir es 0 y el parámetro written de la función puede ser NULL desde OpenSSL 3.0.
