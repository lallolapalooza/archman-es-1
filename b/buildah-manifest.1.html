NOMBRE

buildah-manifest - Crear y manipular listas de manifiestos e índices de imágenes.

SINOPSIS

buildah manifest COMANDO [OPCIONES] [ARG...]

DESCRIPCIÓN

El comando buildah manifest proporciona subcomandos que pueden ser utilizados para:

* Crear una lista de manifiestos de Docker o un índice de imágenes OCI en
    funcionamiento.
* Añadir una entrada a una lista de manifiestos o índice de imágenes para una
    imagen especificada.
* Añadir una entrada a un índice de imágenes para un manifiesto de artefacto
    que hace referencia a un archivo.
* Añadir o actualizar información sobre una entrada en una lista de manifiestos
    o índice de imágenes.
* Eliminar un contenedor o una imagen en funcionamiento.
* Empujar una lista de manifiestos o índice de imágenes a un registro u otra
    ubicación.

EJEMPLOS

Construir una lista de manifiestos multi-arquitectura desde un Containerfile

Suponiendo que el Containerfile utiliza instrucciones RUN, el host necesita una forma de ejecutar binarios no nativos. La configuración de esto está fuera del alcance de este ejemplo. La construcción de una lista de manifiestos multi-arquitectura shazam en paralelo en 4 hilos se puede hacer así:

    $ platarch=linux/amd64,linux/ppc64le,linux/arm64,linux/s390x
    $ buildah build --jobs=4 --platform=$platarch --manifest shazam .

Nota: El argumento --jobs es opcional, y la opción --manifest debe usarse en lugar de las opciones -t o --tag.

Ensamblar un manifiesto multi-arquitectura a partir de imágenes construidas por separado

Suponiendo que las imágenes example.com/example/shazam:$arch se construyen por separado en otros hosts y se envían al registro example.com. Pueden combinarse en una lista de manifiestos y enviarse utilizando un simple bucle:

    $ REPO=example.com/example/shazam
    $ buildah manifest create $REPO:latest
    $ for IMGTAG in amd64 s390x ppc64le arm64; do   
              buildah manifest add $REPO:latest docker://$REPO:$IMGTAG;   
          done
    $ buildah manifest push --all $REPO:latest

Nota: El orden de los argumentos de la instrucción add es <manifiesto> seguido de <imagen>. Además, la opción --all de push es necesaria para asegurar que se empuje todo el contenido, no solo la plataforma/arquitectura nativa.

Eliminar y etiquetar una lista de manifiestos antes de empujar

Se necesita un cuidado especial al eliminar y empujar listas de manifiestos, en contraposición al contenido. Casi siempre querrás usar los subcomandos manifest rm y manifest push --all. Por ejemplo, un cambio de nombre y empuje podría realizarse de la siguiente manera:

    $ buildah tag localhost/shazam example.com/example/shazam
    $ buildah manifest rm localhost/shazam
    $ buildah manifest push --all example.com/example/shazam
