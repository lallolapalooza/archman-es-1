DESCRIPCIÓ

N

Babel es un protocolo de enrutamiento de vectores de distancia que evita bucles, basado aproximadamente en DSDV y AODV, pero con disposiciones para la estimación del costo del enlace y la redistribución de rutas desde otros protocolos de

enrutamiento.

Aunque está optimizado para redes de mal

la inalámbricas, Babel también funci
onará eficientemente en redes cableadas.

Configuración de interfaz

Una interfaz se configura mediante una línea con el siguiente formato:

interface nombre [parámetro...]

donde nombre es el nombre de la interfaz (algo como eth0). El valor predeterminado de un parámetro de interfaz puede especificarse y cambiarse mediante una línea de la forma

default [parámetro...]

Cada parámetro puede ser uno de:

type {auto|wired|wireless|tunnel}

El valor predeterminado es auto a menos que se haya especificado la bandera de línea de comandos -w.

link-quality {true|false|auto}
Esto especifica si se debe realizar la estimación de la calidad del enlace en esta interfaz. El valor predeterminado es realizar la estimación de la calidad del enlace solo en interfaces inalámbricas.
split-horizon {true|false|auto}
Esto especifica si se debe realizar el procesamiento de horizonte dividido en esta interfaz. El valor predeterminado es realizar el procesamiento de horizonte dividido en interfaces cableadas, a menos que se haya establecido la bandera -s.
rxcost costo
Esto define el costo de recibir tramas en la interfaz dada en condiciones ideales (sin pérdida de paquetes); cómo se relaciona esto con el costo real utilizado para calcular las métricas de las rutas que pasan por esta interfaz depende de si se está realizando la estimación de la calidad del enlace. El valor predeterminado es 256 si la interfaz es inalámbrica y 96 en caso contrario.
hello-interval intervalo
Esto define el intervalo entre los paquetes de saludo enviados en esta interfaz. El valor predeterminado se especifica con las banderas de línea de comandos -h y -H.
update-interval intervalo
Esto define el intervalo entre los volcados completos de la tabla de enrutamiento enviados en esta interfaz; dado que Babel utiliza actualizaciones activadas y no cuenta hasta el infinito, este valor puede establecerse en un valor bastante grande, a menos que se espere una pérdida de paquetes significativa. El valor predeterminado es cuatro veces el intervalo de saludo.
enable-timestamps {true|false}
Habilita el envío de marcas de tiempo con cada mensaje de saludo y IHU para calcular los valores RTT. El valor predeterminado es true para interfaces de túnel y false en caso contrario.
unicast {true|false}
Envía copias múltiples de TLVs distintos de los saludos a todos los vecinos en lugar de enviar un único paquete multicast. El valor predeterminado es false.
rfc6126-compatible {true|false}
Deshabilita algunas características que son incompatibles con RFC 6126 (la versión anterior del protocolo Babel), como el enrutamiento específico de origen y la estimación RTT sobre unicast. El valor predeterminado es false.
rtt-decay decaimiento
Esto especifica el factor de decaimiento para el promedio móvil exponencial de las muestras RTT, en unidades de 1/256. Debe estar entre 1 y 256, inclusive. Valores más altos descartan muestras antiguas más rápido. El valor predeterminado es 42.
rtt-min rtt
Esto especifica el RTT mínimo, en milisegundos, a partir del cual aumentamos el costo a un vecino. El costo adicional es lineal en (rtt - rtt-min). El valor predeterminado es 10 ms.
rtt-max rtt
Esto especifica el RTT máximo, en milisegundos, por encima del cual no aumentamos el costo a un vecino. El valor predeterminado es 120 ms.
max-rtt-penalty costo
Esto especifica el costo máximo agregado a un vecino debido al RTT, es decir, cuando el RTT es mayor o igual que rtt-max. El valor predeterminado es 96 si la interfaz es de tipo tunnel, y 0 en caso contrario.
Si anunciar rutas IPv4 a través de esta interfaz incluso cuando no hay
dirección IPv4. El valor predeterminado depende de la versión del kernel.
key id
Habilita la seguridad HMAC en esta interfaz y utiliza la clave id.
accept-bad-signatures {true|false}
Acepta paquetes sin firma o con firma incorrecta. Esto solo tiene efecto si se configuró una clave en una interfaz. El valor predeterminado es false.
