INTRODUCCIÓ

N

El comando bind asocia scripts Tcl con eventos X. Si se especifican los tres argumentos, bind organizará que script (un script Tcl llamado “script de enlace”) se evalúe siempre que ocurra(n) el/los evento(s) dado(s) por secuencia en la(s) ventana(s) identificada(s) por etiqueta. Si script está precedido por un “+”, entonces se añade a cualquier enlace existente para secuencia; de lo contrario script reemplaza cualquier enlace existente. Si script es una cadena vacía, entonces el enlace actual para secuencia se destruye, dejando secuencia sin enlazar. En todos los casos en los que se proporciona un argumento script, bind devuelve una cadena

vacía.

Si se especifica secuencia sin un script, entonces se devuelve el script actualmente enlazado a secuencia, o se devuelve una cadena vacía si no hay enlace para secuencia. Si no se especifica secuencia ni script, entonces el valor de retorno es una lista cuyos elementos son todas las secuencias para las que existen enlaces para etiquet

a.

El argumento etiqueta determina a qué ventana(es) se aplica el enlace. Si etiqueta comienza con un punto, como en .a.b.c, entonces debe ser el nombre de ruta de una ventana; de lo contrario, puede ser una cadena arbitraria. Cada ventana tiene una lista de etiquetas asociada, y un enlace se aplica a una ventana particular si su etiqueta está entre las especificadas para la ventana. Aunque el comando bindtags puede usarse para asignar un conjunto arbitrario de etiquetas de enlace a una ventana, las etiquetas de enlace predeterminadas proporcionan el siguiente

comportamiento:
  • Si una etiqueta es el nombre de una ventana interna, el enlace se aplica a esa
    • ventana.
  • Si la etiqueta es el nombre de una clase de widgets, como Button, el enlace se aplica a todos los widgets de esa
    • clase.
  • Si la etiqueta es el nombre de una ventana de nivel superior (toplevel), el enlace se aplica a la ventana de nivel superior y a todas sus ventanas
    • internas.
  • Si etiqueta tiene el valor all, el enlace se aplica a t
    • odas las vent

la aplicación.

PATRONES DE

EVENTOS

El argumento secuencia especifica una secuencia de uno o más patrones de eventos, con espacio en blanco opcional entre los patrones. Cada patrón de evento puede tomar una de tres formas. En el caso más simple, es un solo carácter ASCII imprimible, como a o [. El carácter no puede ser un espacio en blanco ni el carácter <. Esta forma de patrón coincide con un evento KeyPress para el carácter particular. La segunda forma de patrón es más larga pero más general. Tiene la siguiente

sintaxis: 
<modificador-modificador-tipo-detalle>
Todo el patrón de evento está rodeado por corchetes angulares. Dentro de los corchetes angulares hay cero o más modificadores, un tipo de evento y una pieza adicional de información (detalle) que identifica un botón o tecla particular. Cualquiera de los campos puede omitirse, siempre que al menos uno de tipo y detalle esté presente. Los campos deben estar separados por espacio en blanco o guiones.

La tercera forma de patrón se usa para especificar un evento virtual con nombre, definido por el usuario. Tiene la siguiente

sintaxis: 
<<nombre>>
Todo el patrón de evento virtual está rodeado por dobles corchetes angulares. Dentro de los corchetes angulares está el nombre definido por el usuario del evento virtual. Los modificadores, como Shift o Control, no pueden combinarse con un evento virtual para modificarlo. Los enlaces en un evento virtual pueden crearse antes de que el evento virtual esté definido, y si la definición de un evento virtual cambia dinámicamente, todas las ventanas enlazadas a ese evento virtual responderán inmediatamente a la nueva definición.

Algunos widgets (por ejemplo, menu y text) emiten eventos virtuales cuando su estado interno se actualiza de ciertas maneras. Consulte la página man de cada widget para obtener

detalles.

Cuando se lista más de un valor, separados por comas, los valores son equivalentes. La mayoría de los modificadores tienen los significados obvios de X. Por ejemplo, Button1 requiere que el botón 1 esté presionado cuando ocurra el evento. Para que un enlace coincida con un evento dado, los modificadores en el evento deben incluir todos los especificados en el patrón de evento. Un evento puede también contener modificadores adicionales no especificados en el enlace. Por ejemplo, si se presiona el botón 1 mientras las teclas shift y control están abajo, el patrón <Control-Button-1> coincidirá con el evento, pero <Mod1-Button-1> no lo hará. Si no se especifican modificadores, entonces puede haber cualquier combinación de modificadores en el

evento.

Meta y M se refieren a cuál de los modificadores M1 a M5 está asociado con la(s) tecla(s) Meta en el teclado (keysyms Meta_R y Meta_L). Si no hay teclas Meta, o si no están asociadas con ningún modificador, entonces Meta y M no coincidirán con ningún evento. De manera similar, el modificador Alt se refiere a cuál modificador está asociado con la(s) tecla(s) alt en el teclado (keysyms Alt_L y Alt_R

).

Los modificadores Double, Triple y Quadruple son una conveniencia para especificar dobles clics de ratón y otros eventos repetidos. Hacen que un patrón de evento particular se repita 2, 3 o 4 veces, y también imponen un requisito de tiempo y espacio en la secuencia: para que una secuencia de eventos coincida con un patrón Double, Triple o Quadruple, todos los eventos deben ocurrir cerca en el tiempo y sin movimiento sustancial del ratón entre ellos. Por ejemplo, <Double-Button-1> es equivalente a <Button-1><Button-1> con el requisito adicional de tiempo y

espacio.

Los modificadores Command y Option son equivalentes de Mod1 respectivamente Mod2, corresponden a teclas modificadoras específicas de

Macintosh.

El modificador Extended es, por ahora, específico de Windows. Aparece en eventos que están asociados con las teclas del “teclado extendido”. En un teclado estadounidense, las teclas extendidas incluyen las teclas Alt y Control a la derecha del teclado, las teclas de cursor en el grupo a la izquierda del teclado numérico, la tecla NumLock, la tecla Break, la tecla PrintScreen, y las teclas / y Enter en el te

DETALLES DEL

EVENTO

La última parte de una especificación de evento larga es detail. En el caso de un evento ButtonPress o ButtonRelease, es el número de un botón (1-5). Si se da un número de botón, entonces solo un evento en ese botón en particular coincidirá; si no se da un número de botón, entonces un evento en cualquier botón coincidirá. Nota: dar un número de botón específico es diferente de especificar un modificador de botón; en el primer caso, se refiere a un botón siendo presionado o liberado, mientras que en el segundo se refiere a algún otro botón que ya está presionado cuando ocurre el evento coincidente. Si se da un número de botón entonces type puede omitirse: se establecerá por defecto en ButtonPress. Por ejemplo, el especificador <1> es equivalente a <ButtonPres

s-1>.

Si el tipo de evento es KeyPress o KeyRelease, entonces detail puede ser especificado en la forma de un keysym de X. Los keysyms son especificaciones textuales para teclas particulares en el teclado; incluyen todos los caracteres ASCII alfanuméricos (por ejemplo, "a" es el keysym para el carácter ASCII "a"), más descripciones para caracteres no alfanuméricos ("comma" es el keysym para el carácter coma), más descripciones para todas las teclas no ASCII en el teclado (por ejemplo, "Shift_L" es el keysym para la tecla shift izquierda, y "F1" es el keysym para la tecla de función F1, si existe). La lista completa de keysyms no se presenta aquí; está disponible en otra documentación de X y puede variar de sistema a sistema. Si es necesario, puedes usar la notación %K descrita abajo para imprimir el nombre del keysym para una tecla particular. Si se da un detail de keysym, entonces el campo type puede omitirse; se establecerá por defecto en KeyPress. Por ejemplo, <Control-comma> es equivalente a <Control-K

Es posible que varios enlaces coincidan con un evento X dado. Si los enlaces están asociados con

diferentes

etiquetas (tag's), entonces cada uno de los enlaces será ejecutado, en orden. Por defecto, un enlace para el widget será ejecutado primero, seguido de un enlace de clase, un enlace para su ventana de nivel superior, y un enlace all. El comando bindtags puede usarse para cambiar este orden para una ventana particular o para asociar etiquetas de enlace adicionales con la

ventana.

Los comandos continue y break pueden usarse dentro de un script de enlace para controlar el procesamiento de los scripts que coinciden. Si continue se invoca dentro de un script de enlace, entonces este script de enlace, incluyendo todos los otros scripts añadidos con “+”, es terminado pero Tk continuará procesando los scripts de enlace asociados con otras etiquetas. Si el comando break se invoca dentro de un script de enlace, entonces ese script termina y no se invocarán otros scripts para el

evento.

Dentro de un script llamado desde el script de enlace, return -code ok> puede usarse para continuar el procesamiento (incluyendo scripts añadidos con “+”), o return -code break puede usarse para detener el procesamiento de todos los demás scripts de

enlace.

Si más de un enlace coincide con un evento particular y tienen la misma etiqueta, entonces se elige el enlace más específico y se evalúa su script. Se aplican las siguientes pruebas, en orden, para determinar cuál de varias secuencias coincidentes es más

específica:
(a
)
un patrón de evento que especifica un botón o tecla concreto es más específico que uno que no lo
hace;
(b
)
una secuencia más larga (en términos del número de eventos coincidentes) es más específica que una secuencia más
corta;
(c
)
si los modificadores especificados en un patrón son un subconjunto de los modificadores en otro patrón, entonces el patrón con más modificadores es más
específico;
(d
)
un evento virtual cuyo patrón físico coincide con la secuencia es menos específico que el mismo patrón físico que no está asociado con un evento
virtual;
(e
)
dada una secuencia que coincide con
dos o más eventos virtuales, se eleg

les, pero el orden no está definido.

Si las secuencias coincidentes contienen más de un evento, entonces las pruebas (c)-(e) se aplican en orden desde el evento más reciente hasta el menos reciente en las secuencias. Si estas pruebas no logran determinar un ganador, entonces la secuencia registrada más recientemente es la

ganadora.

Si hay dos (o más) eventos virtuales que son ambos activados por la misma secuencia, y ambos de esos eventos virtuales están vinculados a la misma etiqueta de ventana, entonces solo se activará uno de los eventos virtuales, y se elegirá al

azar: 
event add <<Paste>> <Control-y>
event add <<Paste>> <Button-2>
event add <<Scroll>> <Button-2>
bind Entry <<Paste>> {puts Paste}
bind Entry <<Scroll>> {puts Scroll}
Si el usuario escribe Control-y, se invocará el enlace <<Paste>>, pero si el usuario presiona el botón 2 entonces se invocará uno de los enlaces <<Paste>> o <<Scroll>>, pero exactamente cuál se invoca no está definido.

SECUENCIAS DE MÚLTIPLES EVENTOS Y EVENTOS

IGNORADOS

Cuando una secuencia especificada en un comando bind contiene más de un patrón de evento, entonces su script se ejecuta siempre que los eventos recientes (que conducen hasta e incluyendo el evento actual) coincidan con la secuencia dada. Esto significa, por ejemplo, que si se hace clic repetidamente en el botón 1 la secuencia <Double-ButtonPress-1> coincidirá con cada pulsación de botón excepto la primera. Si ocurren eventos superfluos que impedirían una coincidencia en el medio de una secuencia de eventos, entonces los eventos superfluos se ignoran a menos que sean KeyPress o ButtonPress. Por ejemplo, <Double-ButtonPress-1> coincidirá con una secuencia de pulsaciones de botón 1, aunque habrá ButtonRelease (y posiblemente Motion) entre los ButtonPress. Además, un evento KeyPress puede ir precedido por cualquier número de otros eventos KeyPress de teclas modificadoras sin que las teclas modificadoras impidan una coincidencia. Por ejemplo, la secuencia de eventos aB coincidirá con una pulsación de la tecla a, una liberación de la tecla a, una pulsación de la tecla Shift, y una pulsación de la tecla b: la pulsación de Shift se ignora porque es una tecla modificador. Finalmente, si varios eventos Motion ocurren seguidos, solo se usa el último

para los fines de coincidir
con secuencias de enlace.
