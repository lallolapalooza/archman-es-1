DESCRIPCIÓ

N

Bats es un marco de trabajo de pruebas compatible con TAP para Bash. Proporciona una forma sencilla de verificar que los programas UNIX que escribes se comportan como se

espera.

Un archivo de prueba de Bats es un script de Bash con sintaxis especial para definir casos de prueba. Internamente, cada caso de prueba es simplemente una función con una

descripción.

Los casos de prueba consisten en comandos estándar de shell. Bats hace uso de la opción errexit (set -e) de Bash al ejecutar los casos de prueba. Si cada comando en el caso de prueba termina con un código de estado 0 (éxito), la prueba pasa. De esta manera, cada línea es una afirmación de

verdad.

Consulta bats(7) para obtener más información

sobre cómo escribir
pruebas con Bats.

EJECUCIÓN DE

PRUEBAS

Para ejecutar tus pruebas, invoca el intérprete de bats con la ruta a un archivo de prueba. Los casos de prueba del archivo se ejecutan secuencialmente y en aislamiento. Si todos los casos de prueba pasan, bats termina con un código de estado 0. Si hay algún fallo, bats termina con un código de estado

1.

Puedes invocar el intérprete de bats con múltiples argumentos de archivo de prueba, o con la ruta a un directorio que contiene múltiples archivos .bats. Bats ejecutará cada archivo de prueba individualmente y agregará los resultados. Si algún caso de prueba falla, bats termina con un código de estado

1.

FILTRADO DE

PRUEBAS

Hay múltiples mecanismos para filtrar qué pruebas

ejecutar:
○
--filter <regex> para filtrar por nombre de la
prueba
○
--filter-status <status> para filtrar por el estado de la prueba en la última
ejecución
○
--filter-tags <tag-list> para filtrar por las etiquetas de una
prueba

--FILTER-TAGS <var>

TAG-LIST</var>

Las etiquetas se pueden utilizar para un filtrado más detallado de qué pruebas ejecutar a través de --filter-tags. Esto acepta una lista de etiquetas separadas por comas. Solo se ejecutarán las pruebas que coincidan con todas estas etiquetas. Por ejemplo, bats --filter-tags a,b,c seleccionará las pruebas con las etiquetas a,b,c, pero no las pruebas que carezcan de una o más de esas

etiquetas.

Además, puedes especificar etiquetas negativas mediante bats --filter-tags a,!b,c, lo que ahora no coincidirá con las pruebas con las etiquetas a,b,c, debido a la b, pero seleccionará las que tengan a,c. Para expresarlo de forma más formal, --filter-tags es una conjunción

booleana.

Para permitir consultas más complejas, puedes especificar múltiples --filter-tags. Una prueba se ejecutará si coincide con al menos una de ellas. Esto significa que múltiples --filter-tags forman una disyunción

booleana.

Una consulta de --filter-tags a,!b --filter-tags b,c puede traducirse a: Ejecutar solo las pruebas que (tengan la etiqueta a, pero no la etiqueta b) o (tengan las etiquetas b y c)

.

Una lista de etiquetas

vacía coincide con las
pruebas sin etiquetas.

SALID

A

Cuando ejecutas Bats desde una terminal, verás la salida a medida que se realiza cada prueba, con una marca de verificación junto al nombre de la prueba si pasa o una "X" si

falla. 
$ bats addition.bats
 ✓ add
ition using bc ✓ addition u
sing dc 2 tests, 0 failures

Si Bats no está conectado a una terminal, es decir, si lo ejecutas desde un sistema de integración continua o rediriges su salida a un archivo, los resultados se muestran en formato TAP legible por humanos y analizable por máquina. Puedes forzar la salida TAP desde una terminal invocando Bats con la opción --

tap. 
$ bats --tap addition.bats
1..2
ok 1 addition using bc
ok 2 addition
using
dc
