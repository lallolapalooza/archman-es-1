NOMBRE

bind9_query2dlf - convertir logs de consultas BIND9 a dlf

SINOPSIS

bind9_query2dlf

DESCRIPCIÓN

bind9_query2dlf espera archivos de log de consultas BIND 9 en la entrada estándar.

Si tienes un

channel query_logging {
        file "/var/log/named_querylog"
        versions 3 size 100M;
        print-time yes;                 // marca de tiempo en las entradas del log
};

en tu named.conf, los archivos de log producidos son compatibles. Opcionalmente, podrías añadir

print-category yes;             // muestra el nombre de la categoría
print-severity yes;             // muestra el nivel de severidad

a este canal. Los logs de consultas producidos por un BIND parcheado (ver NOTAS abajo) también son compatibles.

También soportamos el archivo de log de Bind 9.3 que utiliza un nuevo formato de fecha (15-Jul-2002) en lugar del antiguo formato de syslog.

EJEMPLOS

Para procesar un log producido por bind9:

$ bind9_query2dlf < dns-query

bind9_query2dlf rara vez se usará por sí solo, sino que es más probable que sea llamado por lr_log2report:

$ lr_log2report bind9_query < /var/log/dns-query

NOTAS

Las versiones de Bind9 anteriores a la 9.3 no registraban si la consulta era recursiva, por lo tanto, el último campo dlf (DLF_RESOLVER) es un '-'. Sin embargo, aplicando este parche de Wytze van der Raay:

# patch bin/named/query.c para registrar la indicación de consulta recursiva/no recursiva
SRC=bin/named/query.c
if [ -f ${SRC}.org ]
then
        echo "Parche ${SRC} ya aplicado"
else
        echo "Parche ${SRC} para indicación de consulta recursiva/no recursiva"
        cp -p ${SRC} ${SRC}.org
        patch -p0 ${SRC} <<\!
--- bin/named/query.c.org       Mon Sep 24 22:57:48 2001
+++ bin/named/query.c   Tue Sep 25 09:55:21 2001
@@ -3272,7 +3272,8 @@
        dns_rdatatype_format(rdataset->type, typename, sizeof(typename));
        ns_client_log(client, NS_LOGCATEGORY_QUERIES, NS_LOGMODULE_QUERY,
-                     level, "query: %s %s %s", namebuf, classname, typename);
+                     level, "query: %s %s %s%s", namebuf, classname, typename,
+                     WANTRECURSION(client) ? "+" : "-");
 }
 void
!
fi

producirá líneas de log como

Nov 11 12:06:42.829 queries: info: client 10.0.0.1#3664:
  query: 6.example.com.nl IN A+

Un '+' indica una consulta recursiva, '-' indica una consulta no recursiva, la ausencia de + o - indica un bind9 pre-9.3 no parcheado. Ver el mensaje de Wytze del Fri, 28 Dec 2001 16:56:30 +0100 en bind9-workers@isc.org , archivado en http://www.mail-archive.com/bind9-workers@isc.org/msg00501.html .

Este tipo de archivos de log es reconocido por el script.

BIND 9.3 o posterior ofrece soporte completo para esta función de registro. Además, registra información de vista, firmante y EDNS, todo lo cual será ignorado por esta versión del script.

En una discusión privada el Thu, 18 Jul 2002 07:55:22 +0200, Wytze escribió:

Esto contiene la versión "compatible con ISC" del parche para obtener un
registro de solicitud recursiva/no recursiva. ISC decidió que debería haber un
espacio entre el tipo y el indicador de recursión en el archivo de log, así sea.

Si deseas que tu BIND 9.2.1 registre al estilo ISC compatible con 9.3, aplica este parche a tus fuentes de BIND:

--- bin/named/query.c.org       Thu Mar 28 06:10:09 2002
+++ bin/named/query.c   Wed Jul 17 08:14:41 2002
@@ -3279,7 +3279,8 @@
        dns_rdatatype_format(rdataset->type, typename, sizeof(typename));
        ns_client_log(client, NS_LOGCATEGORY_QUERIES, NS_LOGMODULE_QUERY,
-                     level, "query: %s %s %s", namebuf, classname, typename);
+                     level, "query: %s %s %s %s", namebuf, classname, typename,
+                     WANTRECURSION(client) ? "+" : "-");
 }
 void

. Este script entiende la indicación de recursividad estilo Wytze y estilo ISC.
