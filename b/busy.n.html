busy(n)

Paquete: tk

Licencias: TCL

busy(n) Comandos integrados de Tk busy(n)

NOMBRE

busy - Hace que los widgets de Tk estén ocupados, bloqueando temporalmente las interacciones del usuario

SINOPSIS

tk busy ventana ?opciones?
tk busy hold ventana ?opciones?
tk busy configure ventana ?opción valor?...
tk busy forget ventana ?ventana ?...
tk busy current ?patrón?
tk busy status ventana

DESCRIPCIÓN

El comando tk busy proporciona un medio sencillo para bloquear los eventos del puntero del ratón de los widgets de Tk, mientras se anula el cursor del widget con un cursor ocupado configurable. Tenga en cuenta que este comando no evita que los eventos del teclado se envíen a los widgets que se vuelven ocupados.

INTRODUCCIÓN

Hay muchas ocasiones en las aplicaciones en las que se desea restringir temporalmente las acciones que el usuario puede realizar. Por ejemplo, una aplicación podría tener un botón “Ejecutar” que, al pulsarlo, provoca algún procesamiento. Sin embargo, mientras la aplicación está ocupada procesando, probablemente no querrá que el usuario pueda volver a hacer clic en el botón “Ejecutar”. También puede querer restringir al usuario de otras tareas, como hacer clic en un botón “Imprimir”.

El comando tk busy le permite hacer que los widgets de Tk estén ocupados. Esto significa que las interacciones del usuario, como clics de ratón, movimientos del ratón, escritura en el teclado, etc., son ignoradas por el widget. Puede establecer un cursor especial (como un reloj) que anula el cursor normal del widget, proporcionando retroalimentación de que la aplicación (widget) está temporalmente ocupada.

Cuando un widget se vuelve ocupado, el widget y todos sus descendientes ignorarán los eventos del puntero. Es fácil hacer que todo un panel de widgets esté ocupado. Simplemente puede hacer que el widget de nivel superior (como “.”) esté ocupado. Esto es más fácil y mucho más eficiente que recorrer recursivamente la jerarquía de widgets, deshabilitando cada widget y reconfigurando su cursor.

A menudo, el comando tk busy puede usarse en lugar del comando grab de Tk. A diferencia de grab, que restringe todas las interacciones del usuario a un solo widget, con el comando tk busy puede tener más de un widget activo (por ejemplo, un diálogo de “Cancelar” y un botón de “Ayuda”).

EJEMPLO

Puede hacer que varios widgets estén ocupados simplemente haciendo que su widget ancestro esté ocupado usando la operación hold.

frame .top
button .top.button; canvas .top.canvas
pack .top.button .top.canvas
pack .top
# . . .
tk busy hold .top
update

Todos los widgets dentro de .top (incluido .top) están ahora ocupados. El uso de update asegura que el comando tk busy tenga efecto antes de que cualquier otro evento de usuario pueda ocurrir.

Cuando la aplicación ya no está ocupada procesando, puede permitir las interacciones del usuario de nuevo y liberar cualquier recurso que haya asignado mediante la operación forget.

tk busy forget .top

El widget ocupado tiene un cursor configurable. Puede cambiar el cursor ocupado usando la operación configure.

tk busy configure .top -cursor "watch"

Destruir el widget también limpiará cualquier recurso asignado por el comando tk busy.

OPERACIONES

Las siguientes operaciones están disponibles para el comando tk busy:

tk busy ventana ?opción valor?...
Atajo para el comando tk busy hold.
tk busy cget ventana opción
Consulta las opciones de configuración del comando tk busy para ventana. Ventana debe ser el nombre de ruta de un widget que previamente se hizo ocupar mediante la operación hold. El comando devuelve el valor actual de la opción especificada. Opción puede tener cualquiera de los valores aceptados por la operación hold.
tk busy configure ventana ?opción valor?...
Consulta o modifica las opciones de configuración del comando tk busy para ventana. Ventana debe ser el nombre de ruta de un widget que previamente se hizo ocupar mediante la operación hold. Si no se especifican opciones, se devuelve una lista que describe todas las opciones disponibles para ventana (consulte Tk_ConfigureInfo para obtener información sobre el formato de esta lista). Si se especifica opción sin valor, el comando devuelve una lista que describe la opción con ese nombre (esta lista será idéntica a la sublista correspondiente del valor devuelto si no se especifica ninguna opción). Si se especifican uno o más pares opción-valor, el comando modifica las opciones del widget dadas para que tengan los valores dados; en este caso, el comando devuelve una cadena vacía. Opción puede tener cualquiera de los valores aceptados por la operación hold.

Tenga en cuenta que la base de datos de opciones se referencia a través de ventana. Por ejemplo, si el widget .frame debe hacerse ocupado, el cursor ocupado se puede especificar para él mediante el comando option:

option add *frame.busyCursor gumby
option add *Frame.BusyCursor gumby
tk busy current ?patrón?
Devuelve los nombres de ruta de todos los widgets que están actualmente ocupados. Si se proporciona un patrón, solo se devuelven los nombres de ruta de los widgets ocupados que coincidan con el patrón.
tk busy forget ventana ?ventana?...
Libera los recursos asignados por el comando tk busy para ventana, incluida la ventana transparente. Los eventos del usuario volverán a ser recibidos por ventana. Los recursos también se liberan cuando se destruye ventana. Ventana debe ser el nombre de un widget especificado en la operación hold, de lo contrario se informa un error.
tk busy hold ventana ?opción valor?...
Hace que la ventana especificada (y sus descendientes en la jerarquía de ventanas de Tk) parezcan ocupadas. Ventana debe ser un nombre de ruta válido de un widget de Tk. Se coloca una ventana transparente delante de la ventana especificada. Esta ventana transparente se mapeará la próxima vez que se procesen las tareas inactivas, y la ventana especificada y sus descendientes estarán bloqueados de las interacciones del usuario. Normalmente, se debe llamar a update inmediatamente después para asegurar que la operación de retención esté en vigor antes de que la aplicación comience su procesamiento. Las siguientes opciones de configuración son válidas:
-cursor nombreCursor
Especifica el cursor que se mostrará cuando el widget esté ocupado. NombreCursor puede estar en cualquier forma aceptada por Tk_GetCursor. El cursor predeterminado es wait en Windows y watch en otras plataformas.
tk busy status ventana
Devuelve el estado de un widget ventana. Si ventana actualmente no puede recibir interacciones del usuario, se devuelve 1, de lo contrario se devuelve 0.

MANEJO DE EVENTOS

VINCULACIONES

La característica de bloqueo de eventos se implementa creando y mapeando una ventana transparente que cubre completamente el widget. Cuando la ventana ocupada se mapea, protege invisiblemente el widget y su jerarquía de todos los eventos que puedan enviarse. Al igual que los widgets de Tk, las ventanas ocupadas tienen nombres de widget en la jerarquía de ventanas de Tk. Esto significa que puede usar el comando bind para manejar eventos en la ventana ocupada:

tk busy hold .frame.canvas
bind .frame.canvas_Busy <Enter> { ... }

Normalmente, la ventana ocupada es un hermano del widget. El nombre de la ventana ocupada es “widget_Busy”, donde widget es el nombre del widget que se va a hacer ocupar. En el ejemplo anterior, el nombre de ruta de la ventana ocupada es “.frame.canvas_Busy”. La excepción es cuando el widget es un widget de nivel superior (como “.”) donde la ventana ocupada no puede hacerse un hermano.

La ventana ocupada es entonces un hijo del widget llamado “widget._Busy”, donde widget es el nombre del widget de nivel superior. En el siguiente ejemplo, la ruta del archivo de la ventana ocupada es “._Busy”.

tk busy hold .
bind ._Busy <Enter> { ... }

EVENTOS ENTER/LEAVE

El mapeo y desmapeo de ventanas ocupadas genera eventos Enter/Leave para todos los widgets que cubren. Tenga en cuenta esto si está rastreando eventos Enter/Leave en widgets.

EVENTOS DE TECLADO

Cuando un widget se vuelve ocupado, la ventana ocupada impide que el widget obtenga el foco del teclado al hacer clic en él por parte del usuario. Pero si el widget ya tenía el foco, aún puede recibir eventos de teclado. El widget también puede recibir foco a través de la navegación por teclado. Para evitar esto, debe mover el foco a otra ventana y asegurarse de que el foco no pueda volver a los widgets ocupados (por ejemplo, restringiendo el foco a un botón de cancelar).

pack [frame .frame]
pack [text .frame.text]
tk busy hold .frame
pack [button .cancel -text "Cancel" -command exit]
focus .cancel
bind .cancel <Tab> {break}
bind .cancel <Shift-Tab> {break}
update

El ejemplo anterior mueve el foco de .frame inmediatamente después de invocar hold para que no se envíen eventos de teclado a .frame ni a ninguno de sus descendientes. También se asegura de que no sea posible salir del botón .cancel usando el teclado.

PORTABILIDAD

Tenga en cuenta que el comando tk busy actualmente no tiene ningún efecto en macOS cuando Tk se compila con soporte Aqua.
