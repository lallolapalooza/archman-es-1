NOMBRE

backend - interfaces de transmisión de backend de cups

SINOPSIS

backend
backend job user title num-copies options [ filename ]

#include <cups/cups.h>
const char *cupsBackendDeviceURI(char **argv);
void cupsBackendReport(const char *device_scheme,
                       const char *device_uri,
                       const char *device_make_and_model,
                       const char *device_info,
                       const char *device_id,
                       const char *device_location);
ssize_t cupsBackChannelWrite(const char *buffer,
                             size_t bytes, double timeout);
int cupsSideChannelRead(cups_sc_command_t *command,
                        cups_sc_status_t *status, char *data,
                        int *datalen, double timeout);
int cupsSideChannelWrite(cups_sc_command_t command,
                         cups_sc_status_t status, const char *data,
                         int datalen, double timeout);

DESCRIPCIÓN

Los backends son un tipo especial de filtro(7) que se utiliza para enviar datos de impresión y descubrir diferentes dispositivos en el sistema.

Al igual que los filtros, los backends deben ser capaces de leer de un nombre de archivo en la línea de comandos o de la entrada estándar, copiando la entrada estándar a un archivo temporal según lo requiera la interfaz física.

El nombre del comando (argv[0]) se establece en la URI del dispositivo de la impresora de destino. La información de autenticación en argv[0] se elimina, por lo que se insta a los desarrolladores de backends a utilizar la variable de entorno DEVICE_URI siempre que se requiera información de autenticación. La función cupsBackendDeviceURI() se puede utilizar para recuperar la URI del dispositivo correcta.

Los datos del canal posterior del dispositivo deben ser retransmitidos a los filtros del trabajo utilizando la función cupsBackChannelWrite.

Los backends son responsables de leer las solicitudes del canal lateral utilizando la función cupsSideChannelRead() y de responder con la función cupsSideChannelWrite(). La constante CUPS_SC_FD define el descriptor de archivo que debe monitorearse para las solicitudes entrantes.

DESCUBRIMIENTO DE DISPOSITIVOS

Cuando se ejecuta sin argumentos, el backend debe listar los dispositivos y esquemas que soporta o que anuncia a la salida estándar. La salida consiste en cero o más líneas de alguna de las siguientes formas:

    device-class scheme "Unknown" "device-info"
    device-class device-uri "device-make-and-model" "device-info"
    device-class device-uri "device-make-and-model" "device-info" "device-id"
    device-class device-uri "device-make-and-model" "device-info" "device-id" "device-location"

La función cupsBackendReport() se puede utilizar para generar estas líneas y manejar cualquier escapado necesario de caracteres en las diversas cadenas.

El campo device-class es uno de los siguientes valores:

direct
La URI del dispositivo se refiere a un dispositivo de acceso directo específico sin opciones, como un dispositivo paralelo, USB o SCSI.
file
La URI del dispositivo se refiere a un archivo en disco.
network
La URI del dispositivo se refiere a un dispositivo en red y cumple con la forma general de las URIs de red.
serial
La URI del dispositivo se refiere a un dispositivo serie con velocidad en baudios configurable y otras opciones. Si la URI del dispositivo contiene un valor de baudios, representa la velocidad máxima en baudios admitida por el dispositivo.

El campo scheme proporciona el esquema URI compatible con el backend. Los backends deben usar esta forma solo cuando el backend sea compatible con cualquier URI que utilice ese esquema. El campo device-uri especifica la URI completa a utilizar al comunicarse con el dispositivo.

El campo device-make-and-model especifica la marca y el modelo del dispositivo, por ejemplo, "Example Foojet 2000". Si la marca y el modelo no se conocen, debe informar "Unknown".

El campo device-info especifica información adicional sobre el dispositivo. Normalmente incluye la marca y el modelo junto con el número de puerto o la dirección de red, por ejemplo, "Example Foojet 2000 USB #1".

El campo opcional device-id especifica la cadena de ID de dispositivo IEEE-1284 para el dispositivo, que se utiliza para seleccionar un controlador coincidente.

El campo opcional device-location especifica la ubicación física del dispositivo, que a menudo se utiliza para prellenar el atributo printer-location al agregar una impresora.

PERMISOS

Los backends sin permisos de lectura y ejecución para todos se ejecutan como usuario root. De lo contrario, el backend se ejecuta utilizando una cuenta de usuario sin privilegios, típicamente "lp".

ESTADO DE SALIDA

Los siguientes códigos de salida están definidos para los backends:

CUPS_BACKEND_OK
El archivo de impresión se transmitió con éxito al dispositivo o servidor remoto.
CUPS_BACKEND_FAILED

El archivo de impresión no se transmitió con éxito al dispositivo o servidor remoto. El planificador responderá a esto cancelando el trabajo, reintentando el trabajo o deteniendo la cola según el estado del atributo printer-error-policy.
CUPS_BACKEND_AUTH_REQUIRED
El archivo de impresión no se transmitió con éxito porque se requiere información de autenticación válida. El planificador responderá reteniendo el trabajo y agregando la palabra clave 'cups-held-for-authentication' al atributo Job Description de "job-reasons".
CUPS_BACKEND_HOLD
El archivo de impresión no se transmitió con éxito porque no se puede imprimir en este momento. El planificador responderá reteniendo el trabajo.
CUPS_BACKEND_STOP
El archivo de impresión no se transmitió con éxito porque no se puede imprimir en este momento. El planificador responderá deteniendo la cola.
CUPS_BACKEND_CANCEL
El archivo de impresión no se transmitió con éxito porque uno o más atributos no son compatibles o el trabajo fue cancelado en la impresora. El planificador responderá cancelando el trabajo.
CUPS_BACKEND_RETRY
El archivo de impresión no se transmitió con éxito debido a un problema temporal. El planificador reintentará el trabajo en un momento posterior; otros trabajos pueden imprimirse antes que este.
CUPS_BACKEND_RETRY_CURRENT
El archivo de impresión no se transmitió con éxito debido a un problema temporal. El planificador reintentará el trabajo inmediatamente sin permitir trabajos intermedios.

Todos los demás valores de código de salida están reservados.

ENTORNO

Además de las variables de entorno enumeradas en cups(1) y filter(7), los backends de CUPS pueden esperar la siguiente variable de entorno:

DEVICE_URI
La URI del dispositivo asociada con la impresora.

NAME

backend - CUPS backend interface

SYNOPSIS

backend [ options ] job-id user title num-copies options

backend [ options ] device-uri

DESCRIPTION

The CUPS backend is a program that handles the actual printing of print jobs to printers. It receives print data from the CUPS scheduler via standard input and device-specific information through command-line arguments and environment variables.

The backend is responsible for communicating with the printer hardware, including tasks such as opening the printer device, sending print data, and handling any printer-specific commands or status reporting.

The exact arguments and environment variables used by a backend can vary depending on the specific device and driver, but the general format is as shown in the SYNOPSIS.

EXIT STATUS

Backends typically return an exit status of 0 on success and a non-zero value on error. Common exit codes include:

1
General error
2
Invalid job
3
File access error
4
Cannot open printer
5
Cannot write to printer
6
No suitable destination found
7
Device disconnected

ENVIRONMENT

Backends may rely on several environment variables set by the CUPS scheduler:

DEVICE_URI
The URI of the printer device.
CUPS_PRINTER_STATE
The current state of the printer.
CUPS_PRINTER_STATE_REASON
The reason for the current printer state.

Other environment variables may be set for specific options or configurations.

FILES

Backends are typically located in the CUPS backend directory, which is usually /usr/lib/cups/backend/.

UNPRIVILEGED USER ISSUE

CUPS backends are not generally designed to be run directly by the user. Aside from the device URI issue ( argv[0] and DEVICE_URI environment variable contain the device URI), CUPS backends also expect specific environment variables and file descriptors, and typically run in a user session that (on macOS) has additional restrictions that affect how it runs. Backends can also be installed with restricted permissions (0500 or 0700) that tell the scheduler to run them as the "root" user instead of an unprivileged user (typically "lp") on the system.

Unless you are a developer and know what you are doing, please do not run backends directly. Instead, use the lp(1) or lpr(1) programs to send print jobs or lpinfo(8) to query for available printers using the backend. The one exception is the SNMP backend - see cups-snmp(8) for more information.

NOTES

CUPS printer drivers and backends are deprecated and will no longer be supported in a future feature release of CUPS. Printers that do not support IPP can be supported using applications such as ippeveprinter(1).
