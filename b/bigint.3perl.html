DESCRIPCIÓ

N

Todos los literales numéricos en el ámbito dado se convierten en objetos Math::BigInt. Los literales numéricos que representan no enteros se truncan a un entero. Todos los resultados de las expresiones también se truncan a

entero.

Todos los operadores (incluyendo operaciones matemáticas básicas) excepto el operador de rango ".." están

sobrecargados.

A diferencia de la directiva integer, la directiva "bigint" crea enteros que solo están limitados en su tamaño por la memoria

disponible.

Así, lo

siguiente: 
use bigint;
$x =
1234;

crea un Math::BigInt y almacena una referencia a él en $x. Esto ocurre de forma transparente y a tus espaldas, por así

decirlo.

Puedes ver esto con lo

siguiente: 
perl -Mbigint -le 'print ref(1234)
'

Dado que los números son en realidad objetos, puedes llamar a todos los métodos habituales de Math::BigFloat sobre ellos. Esto incluso funciona hasta cierto punto en

expresiones: 
perl -Mbigint -le '$x = 1234; print $x->bdec()'
perl -Mbigint -le 'print 1234->copy()->binc();'
perl -Mbigint -le 'print 1234->copy()->binc->badd(6);'
perl -Mbigint -le 'print +(1234)->copy()->binc()
'

(Ten en cuenta que print no hace lo que esperas si la expresión comienza con '(' por lo tanto el "+"

)

Incluso puedes encadenar las operaciones como de

costumbre: 
perl -Mbigint -le 'print 1234->copy()->binc->badd(6);'
1241

Ten en cuenta que lo siguiente no funciona como se espera (no imprime nada), ya que la sobrecarga de '..' aún no es posible en Perl (a partir de la v5.8.0)

: 
perl -Mbigint -le 'for (1..2) { print ref($_); }
'

use integer vs. use

bigint

Hay algunas diferencias entre "use integer" y "use bigi

nt".

Mientras que "use integer" está limitado a lo que puede manejarse como un escalar de Perl, "use bigint" puede manejar enteros arbitrariamente

grandes.

Además, "use integer" sí afecta las asignaciones a variables y el valor de retorno de algunas funciones. "use bigint" trunca estos resultados a

entero: 
# perl -Minteger -wle 'print 3.2'
3.2
# perl -Minteger -wle 'print 3.2 + 0'
3
# perl -Mbigint -wle 'print 3.2'
3
# perl -Mbigint -wle 'print 3.2 + 0'
3
# perl -Mbigint -wle 'print exp(1) + 0'
2
# perl -Mbigint -wle 'print exp(1)'
2
# perl -Minteger -wle 'print exp(1)'
2.71828182845905
# perl -Minteger -wle 'print exp(1) + 0'
2

En la práctica esto rara vez hace una diferencia para enteros pequeños, ya que las partes y los resultados de las expresiones se truncan de todos modos, pero esto puede, por ejemplo, afectar el valor de retorno de

subrutinas: 
sub three_integer { use integer; return 3.2; }
sub thr
ee_bigint { use bigint; return 3.2; } print three_int
eger(), " ", three_bigint(),"\n"; # imprime "3.2 3"

"bigint" reconoce algunas opciones que se pueden pasar mientras se carga mediante "use". Existen las siguientes

opciones:
a o
accuracy
Esto establece la precisión para todas las operaciones matemáticas. El argumento debe ser mayor o igual que cero. Consulta el método bround() de Math::BigInt para más detalles. 
perl -Mbigint=a,2 -le 'print
12345+1'

Ten en cuenta que establecer la

precisión y la exactitud al
mismo tiempo no es posible.
p o
precision
Esto establece la precisión para todas las operaciones matemáticas. El argumento puede ser cualquier entero. Los valores negativos significan un número fijo de dígitos después del punto, y se ignoran ya que todas las operaciones ocurren en el espacio de enteros. Un valor positivo redondea a este dígito a la izquierda del punto. 0 significa redondear a entero. Consulta el método bfround() de Math::BigInt para más detalles. 
perl -mbigint=p,5 -le 'print
123456789+123'

Ten en cuenta que establecer la

Biblioteca

matemática

Los cálculos con los números se realizan (por defecto) por un módulo de biblioteca de backend llamado Math::BigInt::Calc. El valor por defecto es equivalente a

decir: 
use bigint lib =>
'Calc';

puedes cambiar esto

usando: 
use bigint lib =>
'GMP';

Lo siguiente primero intentaría encontrar Math::BigInt::Foo, luego Math::BigInt::Bar, y si esto también falla, volvería a Math::BigInt::

Calc: 
use bigint lib => 'Foo,Math::BigInt::
Bar';

Usar c<lib> advierte si ninguna de las bibliotecas especificadas puede encontrarse y Math::BigInt volvió a una de las bibliotecas predeterminadas. Para suprimir esta advertencia, usa c<try> en su

lugar: 
use bigint try =>
'GMP';

Si quieres que el código falle en lugar de volver atrás, usa "only" en su

lugar: 
use bigint only =>
'GMP';

Consulta la documentación

del módulo correspondien
te para más detalles.

Llamadas a

métodos

Dado que todos los números son ahora objetos, puedes usar todos los métodos que forman parte de la API de Math::

BigInt.

Pero es necesario una advertencia. Al usar lo siguiente para hacer una copia de un número, solo se hará una copia

superficial. 
$x = 9; $y = $x;
$x = $y =
7;

Usar la copia o el original con matemáticas sobrecargadas está bien, por ejemplo, lo siguiente

funciona: 
$x = 9; $y = $x;
print $x + 1, " ", $y,"\n";     # imprime 10
9

pero llamar a cualquier método que modifique el número directamente resultará en que tanto el original como la copia sean

destruidos: 
$x = 9; $y = $x;
print $x->badd(1), " ", $y,"\n";        # imprime 10 10
$x = 9; $y = $x;
print $x->binc(1), " ", $y,"\n";        # imprime 10 10
$x = 9; $y = $x;
print $x->bmul(2), " ", $y,"\n";        # imprime 18
18

Usar métodos que no modifican, sino que prueban el contenido

funciona: 
$x = 9; $y = $x;
$z = 9 if $x->is_zero();                # funciona
bien

Consulta la documentación sobre el constructor de copia y "=" en overload, así como la documentación en Math::BigInt para más detalles.l

ADVERTENCI

AS
Literales de punto flotante hexadecimales, octales y
binarios
Perl (y este módulo) acepta literales de punto flotante hexadecimales, octales y binarios, pero úsalos con precaución con versiones de Perl anteriores a la v5.32.0, porque algunas versiones de Perl dan silenciosamente un resultado
incorrecto.
Sobrecarga de operadores vs.
literales
"bigint" funciona sobrecargando el manejo de literales enteros y de punto flotante, convirtiéndolos en objetos Math::BigInt.

Esto significa que la aritmética que involucra solo valores de cadena o literales de cadena se realiza con los operadores incorporados de

Perl.

Por

ejemplo: 
use bigint;
my $x = "900000000000000009";
my $y = "900000000000000007";
print $x
- $y;

imprime 0 en compilaciones predeterminadas de 32 bits, ya que "bigint" nunca ve los literales de cadena. Para asegurarte de que la expresión se trate por completo como objetos "Math::BigInt", usa un número literal en la

expresión: 
print +(0+$x)
-
$y;
Rang
os
Perl no permite la sobrecarga de rangos, por lo que no puedes usar de forma segura rangos con extremos "bigint", ni la variable iteradora es un "Math::BigInt". 
use 5.010;
for my $i (12..13) {
  for my $j (20..21) {
    say $i ** $j;  # produces a floating-point number,
                   # not an object
} }

()

Sin embargo, en Perl anterior a la versión v5.9.4, esto no ocurrirá a menos que lo pidas específicamente con las dos etiquetas de importación "hex" y "oct" - y entonces será global y no se puede desactivar dentro de un ámbito con "no bigint":
