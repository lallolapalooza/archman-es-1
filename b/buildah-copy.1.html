NOMBRE

buildah copy - Copia el contenido de un archivo, URL o directorio al directorio de trabajo de un contenedor.

SINOPSIS

buildah copy contenedor origen [[origen ...] destino]

DESCRIPCIÓN

Copia el contenido de un archivo, URL o directorio al directorio de trabajo de un contenedor o a una ubicación especificada en el contenedor. Si se especifica un directorio local como origen, se copia su *contenido* al destino.

OPCIONES

--add-history

Agrega una entrada al historial que notará el digest del contenido agregado. Por defecto es falso.

Nota: También puede anular el valor predeterminado de --add-history estableciendo la variable de entorno BUILDAH_HISTORY. export BUILDAH_HISTORY=true

--cert-dir ruta

Utiliza los certificados en ruta (*.crt, *.cert, *.key) al conectarse a los registros para descargar imágenes nombradas con la bandera --from. El directorio de certificados predeterminado es /etc/containers/certs.d.

--checksum checksum

Calcula la suma de verificación del contenido de origen. El valor de checksum debe ser una cadena de digest de contenedor estándar. Solo soportado para fuentes HTTP.

--chmod permisos

Establece los permisos de acceso del contenido de destino. Acepta el formato numérico. Si no se usa --from, el valor predeterminado es 0755.

--chown propietario:grupo

Establece la propiedad del usuario y grupo del contenido de destino. Si no se usa --from, el valor predeterminado es 0:0.

--contextdir directorio

Directorio de contexto de compilación. Especificar un directorio de contexto hace que Buildah cambie de directorio (chroot) a ese directorio. Esto significa que copiar archivos apuntados por enlaces simbólicos fuera del chroot fallará.

--exclude patrón

Excluye la copia de archivos que coincidan con el patrón especificado. La opción se puede especificar varias veces. Consulte containerignore(5) para ver los formatos admitidos.

--from contenedorOImagen

Utiliza el directorio raíz del contenedor de trabajo o imagen especificado como directorio raíz al resolver rutas de origen absolutas y la ruta del directorio de contexto. Si se necesita descargar una imagen, se pueden usar las opciones reconocidas por buildah pull. Si no se usan --chown o --chmod, se conservan los permisos y la propiedad.

--ignorefile archivo

Ruta a un archivo alternativo .containerignore (.dockerignore). Requiere que se especifique --contextdir.

--link

Crea una capa de imagen independiente para los archivos agregados en lugar de modificar el sistema de archivos del contenedor de trabajo. Si buildah run crea un archivo y buildah copy --link agrega un archivo a la misma ruta, el archivo de buildah copy --link estará presente en la imagen confirmada. La capa --link se aplica después de todos los cambios en el sistema de archivos del contenedor en el momento de la confirmación.

--parents

Conserva los directorios principales en las rutas de los elementos que se copian, en relación con la parte superior del contexto de compilación, o con el "punto de pivote", una ubicación en la ruta de origen marcada por un componente de ruta llamado "." (es decir, donde ocurre "/./" en la ruta).

--quiet, -q

Evita imprimir un digest del contenido copiado.

--retry intentos

Número de veces que se reintentará en caso de fallo al realizar la descarga de imágenes del registro.

El valor predeterminado es 3.

--retry-delay duración

Duración del retraso entre intentos de reintento en caso de fallo al realizar la descarga de imágenes del registro.

El valor predeterminado es 2s.

--timestamp segundos

Establece la marca de tiempo ("mtime") para el contenido agregado a exactamente este número de segundos desde la época (Unix time 0, es decir, 00:00:00 UTC del 1 de enero de 1970) para ayudar a permitir compilaciones deterministas.

El directorio de destino en el que se copia el contenido probablemente reflejará la hora en que se agregó el contenido.

--tls-verify valor-booleano

Requiere la verificación de certificados al descargar imágenes a las que se hace referencia con la bandera --from* (el valor predeterminado es verdadero). La verificación TLS no se puede utilizar al hablar con un registro inseguro.

EJEMPLO

buildah copy containerID '/myapp/app.conf' '/myapp/app.conf'

buildah copy --exclude=*/.md docs containerID 'docs' '/docs'

buildah copy --parents containerID './x/a.txt' './y/a.txt' '/parents'

buildah copy --chown myuser:mygroup containerID '/myapp/app.conf' '/myapp/app.conf'

buildah copy --chmod 660 containerID '/myapp/app.conf' '/myapp/app.conf'

buildah copy containerID '/home/myuser/myproject.go'

buildah copy containerID '/home/myuser/myfiles.tar' '/tmp'

buildah copy containerID '/tmp/workingdir' '/tmp/workingdir'

buildah copy containerID 'https://github.com/containers/buildah' '/tmp'

buildah copy containerID 'passwd' 'certs.d' /etc

ARCHIVOS

.containerignore/.dockerignore

Si el archivo .containerignore/.dockerignore existe en el directorio de contexto, buildah copy lee su contenido. Si ambos existen, se utiliza .containerignore.

Cuando se especifica la opción --ignorefile, Buildah la lee y la utiliza para decidir qué contenido excluir al copiar contenido al contenedor de trabajo.

Los usuarios pueden especificar una serie de patrones de glob de shell Unix en un archivo de ignorar para identificar archivos/directorios a excluir.

Buildah admite la cadena comodín especial ** que coincide con cualquier número de directorios (incluyendo cero). Por ejemplo, **/*.go** excluirá todos los archivos que terminen en .go y que se encuentren en todos los directorios.

Ejemplo de archivo .containerignore/.dockerignore:

# aquí están los archivos que queremos excluir
*/*.c
**/output*
src

*/*.c Excluye archivos y directorios cuyos nombres terminan en .c en cualquier subdirectorio de nivel superior. Por ejemplo, el archivo de origen include/rootless.c.

**/output* Excluye archivos y directorios que comienzan con output de cualquier directorio.

src Excluye archivos llamados src y el directorio src, así como cualquier contenido en él.

Las líneas que comienzan con ! (signo de exclamación) se pueden usar para hacer excepciones a las exclusiones. El siguiente es un ejemplo de archivo .containerignore/.dockerignore que utiliza este mecanismo:

*.doc
!Help.doc

Excluye todos los archivos doc excepto Help.doc al copiar contenido al contenedor.

Esta funcionalidad es compatible con el manejo de archivos .containerignore descrito aquí:

https://github.com/containers/common/blob/main/docs/containerignore.5.md
