replace

A dictionary mapping strings to strings, used to replace characters in filenames and paths. By default, this mapping is empty, but the autotagger automatically adds replacements for common problematic characters. For example, a default replacement might turn a tab character into an underscore.

These replacements are applied to filenames after paths have been generated using the Path Format Configuration. The default replacements are applied for all path formats, and are also used to help prevent filenames from becoming too long.

The default replacements can be configured in the config.yaml file. For example, to replace all occurrences of "The " at the beginning of a string with nothing, and to replace apostrophes with the empty string, you can write:

replace:
    The :
    ':

Note that this configuration maps keys to values. The example above replaces the string "The " with an empty string and the apostrophe character with an empty string. The keys are the strings to be replaced, and the values are the strings to replace them with. This is used to remove characters that are problematic on some filesystems (e.g., slashes on Windows) or to shorten very long filenames.

Leading and trailing whitespace, which can cause problems on Windows clients, are also removed.

When replacements other than the defaults are used, it is possible that they will increase the length of the path. In the scenario where this leads to a conflict with the maximum filename length, the default replacements will be used to resolve the conflict and beets will display a warning.

Note that paths might contain special characters such as typographical quotes (“”). With the configuration above, those will not be replaced as they don't match the typewriter quote ("). To also strip these special characters, you can either add them to the replacement list or use the asciify_paths configuration option below.

path_sep_replace

Una cadena que reemplaza el separador de ruta (por ejemplo, la barra diagonal / en Linux y MacOS, y la barra invertida \\ en Windows) al generar nombres de archivo con beets. Esta opción está relacionada con replace, pero es distinta de ella por razones técnicas.

ADVERTENCIA:

Cambiar esta opción es potencialmente peligroso. Por ejemplo, establecerla en el separador de ruta real podría crear directorios en ubicaciones inesperadas. Tenga cuidado al cambiarla y pruébela siempre en un pequeño número de archivos antes de aplicarla a toda su biblioteca.

Valor predeterminado: _.

asciify_paths

Convierte todos los caracteres no ASCII en las rutas a sus equivalentes ASCII.

Por ejemplo, si su plantilla de ruta para individuales es singletons/$title y el título de una pista es "Café", la pista se guardará como singletons/Cafe.mp3. Los cambios se realizan antes de aplicar la configuración de replace y son aproximadamente equivalentes a envolver todas sus plantillas de ruta en la función de plantilla %asciify{}.

Valor predeterminado: no.

art_filename

Al importar carátulas de álbum, el nombre del archivo (sin extensión) donde se colocará la imagen de la carátula. Esta es una cadena de plantilla, por lo que puede usar cualquier sintaxis disponible para Path Formats. El valor predeterminado es cover (es decir, las imágenes se nombrarán cover.jpg o cover.png y se colocarán en el directorio del álbum).

threaded

yes o no, indicando si el autotagger debe usar múltiples hilos. Esto hace que las cosas sean sustancialmente más rápidas al superponer el trabajo: por ejemplo, puede copiar archivos de un álbum en paralelo con la búsqueda de datos en MusicBrainz para otro álbum. Es posible que desee deshabilitar esto al depurar problemas con el autotagger. El valor predeterminado es yes.

format_item

Formato a utilizar al listar pistas individuales con el comando list y otros comandos que necesiten imprimir pistas. El valor predeterminado es $artist - $album - $title. La opción de línea de comandos -f anula esta configuración.

Solía llamarse list_format_item.

format_album

Formato a utilizar al listar álbumes con list y otros comandos. El valor predeterminado es $albumartist - $album. La opción de línea de comandos -f anula esta configuración.

Solía llamarse list_format_album.

sort_item

Orden de clasificación predeterminado a utilizar al obtener pistas de la base de datos. El valor predeterminado es artist+ album+ disc+ track+. Los órdenes de clasificación explícitos anulan este predeterminado.

sort_album

Orden de clasificación predeterminado a utilizar al obtener álbumes de la base de datos. El valor predeterminado es albumartist+ album+. Los órdenes de clasificación explícitos anulan este predeterminado.

sort_case_insensitive

yes o no, indicando si se debe ignorar la capitalización al clasificar campos lexicográficos. Cuando se establece en no, los valores en minúsculas se colocarán después de los valores en mayúsculas (por ejemplo, Bar Qux foo), mientras que yes daría como resultado el más esperado Bar foo Qux. Predeterminado: yes.

original_date

yes o no, indicando si los álbumes coincidentes deben tener sus campos year, month y day establecidos en la fecha de lanzamiento de la versión *original* de un álbum en lugar de la versión seleccionada del lanzamiento. Es decir, si esta opción está activada, entonces year siempre será igual a original_year y así sucesivamente. Predeterminado: no.

overwrite_null

Esta opción, de nombre confuso, indica qué campos tienen valores *nulos* significativos. Si un campo de álbum o pista está en la lista correspondiente, entonces un valor existente para este campo en un elemento de la base de datos puede ser sobrescrito con *nulo*. Por defecto, sin embargo, *nulo* se interpreta como información de que el campo no está disponible, por lo que no sobrescribiría los valores existentes. Por ejemplo:

overwrite_null:
    album: ["albumid"]
    track: ["title", "date"]

artist_credit

yes o no, indicando si las pistas y álbumes coincidentes deben usar el crédito del artista, en lugar del artista. Es decir, si esta opción está activada, entonces artist contendrá el artista tal como se acredita en el lanzamiento.

per_disc_numbering

Un booleano que controla el estilo de numeración de pistas en lanzamientos de múltiples discos. Por defecto (per_disc_numbering: no), las pistas se numeran por lanzamiento, por lo que la primera pista del segundo disco tiene el número de pista N+1 donde N es el número de pistas del primer disco. Si este per_disc_numbering está habilitado, entonces la primera pista (sin pregap) de cada disco siempre tiene el número de pista 1.

Si habilita per_disc_numbering, es probable que también desee cambiar su Configuración de Formato de Ruta para incluir $disc antes de $track para que los nombres de archivo se clasifiquen correctamente en los directorios de álbumes. Por ejemplo, podría desear usar un formato de ruta como este:

paths:
    default: $albumartist/$album%aunique{}/$disc-$track $title

Cuando esta opción está desactivada (el valor predeterminado), incluso las pistas ocultas de "pregap" se numeran a partir de uno, no de cero, por lo que otros números de pista pueden parecer incrementados en uno. Cuando está activada, la pista de pregap de cada disco puede numerarse cero.

aunique

Estas opciones se utilizan para generar una cadena que se garantiza que sea única entre todos los álbumes de la biblioteca que comparten el mismo conjunto de claves.

Los valores predeterminados se ven así:

aunique:
    keys: albumartist album
    disambiguators: albumtype year label catalognum albumdisambig releasegroupdisambig
    bracket: '[]'

sunique

Al igual que aunique para álbumes, estas opciones controlan la generación de una cadena única para desambiguar individuales que comparten metadatos similares.

Los valores predeterminados se ven así:

    keys: artist title
    disambiguators: year trackdisambig

Consulte Desambiguación de Individuales para obtener más detalles.

clutter

Cuando beets importa todos los archivos de un directorio, intenta eliminar el directorio si está vacío. Un directorio se considera vacío si solo contiene archivos cuyos nombres coinciden con los patrones glob en clutter, que debe ser una lista de cadenas. Establece el número máximo de caracteres en un nombre de archivo, después del cual los nombres se truncarán. Por defecto, beets intenta preguntar al sistema de archivos cuál es el máximo correcto.

id3v23

Por defecto, beets escribe etiquetas MP3 utilizando el estándar ID3v2.4, la última versión de ID3. Habilite esta opción para usar en su lugar el estándar ID3v2.3 más antiguo, que es preferido por cierto software más antiguo como Windows Media Player.

Establece el `albumartist` para compilaciones de varios artistas. El valor predeterminado es 'Various Artists' (el estándar de MusicBrainz). También afecta a otras fuentes, como el Discogs Plugin.
