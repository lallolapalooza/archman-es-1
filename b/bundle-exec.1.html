BUNDLE-EXEC(1) Manual de Comandos Generales BUNDLE-EXEC(1)

NOMBRE

bundle-exec - Ejecuta un comando en el contexto del bundle

SINOPSIS

bundle exec [--keep-file-descriptors] [--gemfile=GEMFILE] command

DESCRIPCIÓN

Este comando ejecuta el comando, haciendo que todas las gema especificadas en el [Gemfile(5)][Gemfile(5)] estén disponibles para require en programas Ruby.

Esencialmente, si normalmente ejecutarías algo como rspec spec/my_spec.rb, y quieres usar las gemas especificadas en el [Gemfile(5)][Gemfile(5)] e instaladas mediante bundle install(1) bundle-install.1.html, deberías ejecutar bundle exec rspec spec/my_spec.rb.

Ten en cuenta que bundle exec no requiere que un ejecutable esté disponible en el $PATH de tu shell.

OPCIONES

--keep-file-descriptors
Pasa todos los descriptores de archivo a los nuevos procesos. El valor por defecto es verdadero desde la versión 2.2.26 de bundler. Establecerlo a falso está obsoleto.
--gemfile=GEMFILE
Usa el gemfile especificado en lugar de [Gemfile(5)][Gemfile(5)].

BUNDLE INSTALL --BINSTUBS

Si usas el --binstubs indicador en bundle install(1) bundle-install.1.html, Bundler creará automáticamente un directorio (cuyo valor por defecto es app_root/bin) que contiene todos los ejecutables disponibles de las gemas en el bundle.

Después de usar --binstubs, bin/rspec spec/my_spec.rb es idéntico a bundle exec rspec spec/my_spec.rb.

MODIFICACIONES DEL ENTORNO

bundle exec realiza una serie de cambios en el entorno del shell, y luego ejecuta el comando que especificas por completo.

  • asegurarse de que todavía sea posible invocar shell a bundle desde dentro de un comando invocado por bundle exec (usando $BUNDLE_BIN_PATH)
  • poner el directorio que contiene los ejecutables (como rails, rspec, rackup) de tu bundle en $PATH
  • asegurarse de que si bundler es invocado en el subshell, use el mismo Gemfile (estableciendo BUNDLE_GEMFILE)
  • añadir -rbundler/setup a $RUBYOPT, lo que asegura que los programas Ruby invocados en el subshell puedan ver las gemas en el bundle

También modifica Rubygems:

  • deshabilitar la carga de gemas adicionales que no estén en el bundle
  • modificar el gem método para que sea una operación sin efecto si una gema que coincide con los requisitos está en el bundle, y para lanzar un Gem::LoadError si no lo está
  • Definir Gem.refresh como una operación sin efecto, ya que el índice de fuentes siempre está congelado cuando se usa bundler, y para evitar que las gemas del sistema se filtren en el entorno
  • Sobrescribir Gem.bin_path para usar las gemas en el bundle, haciendo que los ejecutables del sistema funcionen
  • Añadir todas las gemas en el bundle a Gem.loaded_specs

Finalmente, bundle exec también modifica implícitamente Gemfile.lock si el archivo de bloqueo y el Gemfile no coinciden. Bundler necesita el Gemfile para determinar cosas como los grupos de una gema, autorequire, y plataformas, etc., y esa información no está almacenada en el archivo de bloqueo. El Gemfile y el archivo de bloqueo deben estar sincronizados para que bundle exec funcione correctamente, por lo que bundle exec actualiza el archivo de bloqueo de antemano.

Carga

Por defecto, al intentar bundle exec un archivo con un shebang de ruby, Bundler hará Kernel.load de ese archivo en lugar de usar Kernel.exec. Para la gran mayoría de los casos, esto es una mejora de rendimiento. En unos pocos casos raros, esto podría causar algunos efectos secundarios sutiles (como la dependencia del contenido exacto de $0 o __FILE__) y la optimización puede deshabilitarse activando la configuración disable_exec_load .

Invocación de shell

Cualquier código Ruby que abre un subshell (como system, comillas invertidas, o %x{}) usará automáticamente el entorno actual de Bundler. Si necesitas invocar shell a un comando Ruby que no es parte de tu bundle actual, usa el método with_unbundled_env con un bloque. Cualquier subshell creado dentro del bloque recibirá el entorno presente antes de que Bundler fuera activado. Por ejemplo, los comandos de Homebrew ejecutan Ruby, pero no funcionan dentro de un bundle:

Bundler.with_unbundled_env do
  `brew install wget`
end

Usar with_unbundled_env también es necesario si estás invocando shell a un bundle diferente. Cualquier comando de Bundler ejecutado en un subshell heredará el Gemfile actual, por lo que los comandos que necesitan ejecutarse en el contexto de un bundle diferente también necesitan usar with_unbundled_env.

Bundler.with_unbundled_env do
  Dir.chdir "/other/bundler/project" do
    `bundle exec ./script`
  end
end

Bundler proporciona asistentes de conveniencia que envuelven system y exec, y pueden usarse así:

Bundler.unbundled_system('brew install wget')
Bundler.unbundled_exec('brew install wget')

PLUGINS DE RUBYGEMS

Actualmente, el sistema de plugins de Rubygems requiere que todos los archivos llamados rubygems_plugin.rb en la ruta de carga de cualquier gema instalada cuando cualquier código Ruby requiere rubygems.rb. Esto incluye ejecutables instalados en el sistema, como rails, rackup, y rspec.

Dado que los plugins de Rubygems pueden contener código Ruby arbitrario, comúnmente terminan activándose a sí mismos o a sus dependencias.

Por ejemplo, la gema gemcutter 0.5 dependía de json_pure. Si tenías esa versión de gemcutter instalada (incluso si también tenías una versión más nueva sin este problema), Rubygems activaría gemcutter 0.5 y json_pure <latest>.

Si tu Gemfile(5) también contenía json_pure (o una gema con una dependencia en json_pure), la versión más reciente en tu sistema podría entrar en conflicto con la versión en tu Gemfile(5), o la versión de instantánea en tu Gemfile.lock.

Si esto sucede, bundler dirá:

You have already activated json_pure 1.4.6 but your Gemfile
requires json_pure 1.4.3. Consider using bundle exec.

En esta situación, casi con certeza querrás eliminar la gema subyacente con el plugin de gema problemático. En general, los autores de estos plugins (en este caso, la gema gemcutter ) han publicado versiones más nuevas que son más cuidadosas en sus plugins.

Puedes encontrar una lista de todas las gemas que contienen plugins de gema ejecutando

ruby -e "puts Gem.find_files('rubygems_plugin.rb')"

Como mínimo, deberías eliminar todas las versiones excepto la más reciente de cada plugin de gema, y también eliminar todos los plugins de gema que no estés usando (gem uninstall gem_name).
