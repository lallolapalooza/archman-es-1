N

Las rutas/nombres de archivo utilizados como entrada para la coincidencia de patrones comienzan con la raíz de recursión activa actualmente. Normalmente, se proporciona la(s) raíz(es) de recursión al invocar borg, y estas pueden ser rutas relativas o

absolutas.

Tenga cuidado, sus patrones deben coincidir con las rutas

archivadas:
•
Las rutas archivadas nunca com
ienzan con una barra inicial (
'/'), ni con '.', ni con '..'.
  • Cuando realiza una copia de seguridad de rutas absolutas como /home/user, las rutas archivadas comienzan con home/use
    • r.
  • Cuando realiza una copia de seguridad de rutas relativas como ./src, las rutas archivadas comienzan con src
    • .
  • Cuando realiza una copia de seguridad de rutas relativas como ../../src, las rutas archivadas comienzan con s
    • r
c
.

Un patrón de exclusión de directorio puede terminar con o sin una barra ('/'). Si termina con una barra, como some/path/, el directorio se incluirá pero no su contenido. Si no termina con una barra, como some/path, tanto el directorio como el contenido serán

excluidos.

Borg soporta diferentes estilos de patrón. Para definir un estilo no predeterminado para un patrón específico, prefíjelo con dos caracteres seguidos de dos puntos ':' (es decir, fm:path/*, sh:path/

**).

El estilo de patrón predeterminado para --exclude difiere del de --pattern, vea más

abajo.
Fnmatch <https://docs.python.org/3/library/fnmatch.
html>
, selector fm: Este es el estilo predeterminado para --exclude y --exclude-from. Estos patrones usan una variante de la sintaxis de patrones de shell, donde '*' coincide con cualquier número de caracteres, '?' coincide con cualquier carácter individual, '[...]' coincide con cualquier carácter especificado, incluyendo rangos, y '[!...]' coincide con cualquier carácter no especificado. Para el propósito de estos patrones, el separador de ruta (barra invertida para Windows y '/' en otros sistemas) no se trata de manera especial. Envuelva los metacaracteres entre corchetes para una coincidencia literal (es decir, [?] para coincidir con el carácter literal ?). Para que una ruta coincida con un patrón, la ruta completa debe coincidir, o debe coincidir desde el inicio de la ruta completa hasta justo antes de un separador de ruta. Excepto para la ruta raíz, las rutas nunca terminarán en el separador de ruta cuando se intente la coincidencia. Por lo tanto, si un patrón dado termina en un separador de ruta, se agrega un '*' antes de intentar la coincidencia. Un separador de ruta inicial siempre se
elimina.
Patrones estilo shell, selector sh
:
Este es el estilo predeterminado para --pattern y --patterns-from. Al igual que los patrones fnmatch, estos son similares a los patrones de shell. La diferencia es que el patrón puede incluir **/ para coincidir con cero o más niveles de directorio, * para coincidir con cero o más caracteres arbitrarios, con la excepción de cualquier separador de ruta. Un separador de ruta inicial siempre se
elimina.
Expresiones regulares, selector re
:
Se admiten expresiones regulares similares a las que se encuentran en Perl. A diferencia de los patrones de shell, las expresiones regulares no están obligadas a coincidir con la ruta completa y es suficiente con que coincida cualquier subcadena. Se recomienda encarecidamente anclar los patrones al inicio ('^'), al final ('$') o a ambos. Los separadores de ruta (barra invertida para Windows y '/' en otros sistemas) en las rutas siempre se normalizan a una barra diagonal ('/') antes de aplicar un patrón. La sintaxis de expresiones regulares se describe en la documentación de Python para el módulo re https://docs.python.org/3/library/re.html
.
Prefijo de ruta, selector pp
:
Este estilo de patrón es útil para coincidir con subdirectorios completos. El patrón pp:root/somedir coincide con root/somedir y todo lo que contiene. Un separador de ruta inicial siempre se
elimina.
Coincidencia completa de ruta, selector pf
:
Este estilo de patrón es (únicamente) útil para coincidir con rutas completas. Es una especie de pseudo-patrón ya que no puede tener ninguna parte variable o no especificada; se debe proporcionar la ruta completa. pf:root/file.ext coincide con root/file.ext únicamente. Un separador de ruta inicial siempre se elimina.

Nota de implementación: esto se implementa mediante búsquedas en tablas hash muy eficientes en tiempo O(1) (e

sto significa que puede tener una gran cantidad de estos patrones sin afectar significativamente el rendimien
to). Debido a esto, este tipo de patrón no respeta ningún contexto u orden. Si usa un patrón de este tipo pa
ra incluir un archivo, siempre se incluirá (si la recursión del directorio lo encuentra). Otros patrones de i
nclusión/exclusión que normalmente coincidirían serán ignorados. La misma lógica se aplica para la exclusión.

NOTA

:
re:, sh: y fm: los patrones están todos implementados sobre el motor SRE de Python. Es muy fácil formular patrones para cada uno de estos tipos que requieren una cantidad inmensa de tiempo para hacer coincidir rutas. Si usuarios no confiables pueden proporcionar patrones, asegúrese de que no puedan proporcionar patrones re:. Además, asegúrese de que los patrones sh: y fm: solo contengan un puñad
o de comodine
s como máximo.

Las exclusiones se pueden pasar a través de la opción de línea de comandos --exclude. Cuando se usa desde un shell, los patrones deben entrecomillarse para protegerlos de la

expansión.

Los patrones que coincidan con caracteres especiales, por ejemplo, espacios en blanco, dentro de un shell pueden requerir ajustes, como poner comillas alrededor de los argumentos. Ejemplo: usando bash, la siguiente opción de línea de comandos coincidiría y excluiría "item name": --pattern='-path/item name' Tenga en cuenta que cuando los patrones se usan dentro de un archivo de patrones leído directamente por borg, por ejemplo, al usar --exclude-from o --patterns-from, no hay un shell involucrado y por lo tanto no se requieren

comillas.

La opción --exclude-from permite cargar patrones de exclusión desde un archivo de texto con un patrón por línea. Las líneas vacías o que comienzan con el signo de número ('#') después de eliminar los espacios en blanco en ambos extremos se ignoran. El prefijo selector de estilo opcional también es soportado para patrones cargados desde un archivo. Debido a la eliminación de espacios en blanco, las rutas con espacios en blanco al principio o al final solo pueden excluirse usando expresiones

regulares.

Para probar sus patrones de exclusión sin realizar una copia de seguridad real, puede ejecutar borg create --list --dry-run ...

.

Existe una forma más general y fácil de usar para definir patrones de coincidencia de nombres de archivo con las opciones --pattern y --patterns-from. Usando estas, puede especificar las raíces de la copia de seguridad, los estilos de patrón predeterminados y los patrones de inclusión y

exclusión.
Prefijo de ruta raíz
R
Una ruta raíz de recursión comienza con el prefijo R, seguido de una ruta (una ruta simple, no un patrón de archivo). Use este prefijo para tener las rutas raíz en el archivo de patrones en lugar de como argumentos de la línea de
comandos.
Prefijo de estilo de patrón P (útil solo dentro de archivos de
patrones)
Para cambiar el estilo de patrón predeterminado, use el prefijo P, seguido de la abreviatura del estilo de patrón (fm, pf, pp, re, sh). Todos los patrones que sigan a esta línea en el mismo archivo de patrones usarán este estilole hasta que se especifique otro estilo o se alcance el final del archivo. Cuando se termina el archivo de patrones actual, el estilo de patrón predeterminado se
restablecerá.
Prefijo de patrón de exclusión
-
Utilice el prefijo -, seguido de un patrón, para definir una exclusión. Esto tiene el mismo efecto que la opción --exclud
e.
Prefijo de patrón de exclusión sin recursión
!
Utilice el prefijo !, seguido de un patrón, para definir una exclusión que no recursa en los subdirectorios. Esto ahorra tiempo, pero impide que los patrones de inclusión coincidan con archivos en
subdirectorios.
Prefijo de patrón de inclusión
+
Utilice el prefijo +, seguido de un patrón, para definir inclusiones. Esto es útil
para incluir rutas que están cubie
rtas por un patrón de exclusión y q
ue de otro modo no se respaldarían.

NOTA

:
A través de --pattern o --patterns-from puede definir TANTO la inclusión como la exclusión de archivos utilizando los prefijos de patrón + y -. Con --exclude y --exclude-from SOLO se
definen e
xclusiones.

Se utiliza el primer patrón que coincida, de modo que si un patrón de inclusión coincide antes que un patrón de exclusion, el archivo se respalda. Tenga en cuenta que una exclusión sin recursión detiene el examen de los subdirectorios, por lo que las posibles inclusiones no coincidirán; utilice exclusiones normales para estos casos de

uso.

Es posible que un subdirectorio/archivo coincida mientras que los dir

Tenga en cuenta que el estilo de patrón predeterminado para --pattern y --patterns-from es estilo shell (sh:), por lo que esos patrones se comportan de manera similar a los patrones de inclusión/exclusión de rsync. El estilo de patrón se puede establecer mediante el prefijo

P.

Los patrones (--pattern) y las exclusiones (--exclude) de la línea de comandos se consideran primero (en el orden de aparición). Luego se añaden los patrones de --patterns-from. Los patrones de exclusión de los archivos --exclude-from se añaden al

final.
