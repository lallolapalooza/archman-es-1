Nombre

bluetoothctl - Herramienta de línea de comandos de control de Bluetooth

SINOPSIS

bluetoothctl [-a capability] [-e] [-m] [-t seconds] [-v] [-h]

DESCRIPCIÓN

bluetoothctl(1) herramienta interactiva de control de bluetooth. La herramienta funciona con controladores Bluetooth Classic (BR/EDR) y Bluetooth de Energía Baja (LE).

La herramienta está guiada por menús pero puede automatizarse desde la línea de comandos. Se proporcionan ejemplos en la sección de automatización.

OPCIONES

-acapability,--agentcapability
Registra un manejador de agente: <capability>
-e, --endpoints
Registra puntos de conexión de medios
-m, --monitor
Habilita la salida de monitorización
-tseconds,--timeoutseconds
Tiempo de espera en segundos para el modo no interactivo
-v, --version
Muestra la versión
-h, --help
Muestra la ayuda

Comandos

list

Lista los controladores disponibles.

Uso
> list

show

Información del controlador.

Uso
> show [ctrl]

select

Selecciona el controlador predeterminado.

Uso
> select <ctrl>

devices

Lista los dispositivos disponibles, con una propiedad opcional como filtro.

Uso
> devices [Paired/Bonded/Trusted/Connected]

system-alias

Establece el alias del controlador.

Uso
> system-alias <name>

reset-alias

Restablece el alias del controlador.

Uso
> reset-alias

power

Establece la energía del controlador.

Cuando el controlador está apagado, el puerto USB al que está conectado se pone en estado de suspensión.

Uso
> power <on/off>

advertise

Habilita/deshabilita la publicidad con el tipo dado.

Si sales del programa, la publicidad se deshabilitará.

Al publicitar, el controlador debería publicitar con una dirección aleatoria, pero puede usar su dirección pública si no soporta la característica (dirección del dispositivo).

Un dispositivo puede publicitar si inició la conexión con otro dispositivo publicitario.

Uso
> advertise <on/off/type>

set-alias

Establece el alias del dispositivo.

Uso
> set-alias <alias>

scan

Escanea en busca de dispositivos.

Para LE, el escaneo es un requisito importante antes de conectarse o emparejarse.

El propósito del escaneo es encontrar dispositivos que estén publicitando con su indicador de descubrimiento activado (ya sea limitado o general). Una vez que hayas encontrado la dirección, puedes conectarte o emparejarte.

Ten en cuenta lo siguiente al escanear:

  • Al escanear, el controlador usará una dirección aleatoria no resoluble para que no se filtre la dirección pública. Se crea una nueva dirección aleatoria cada vez que se usa scan on.
  • Al activar el escaneo, el dispositivo comenzará a recibir informes de publicidad de qué dispositivos están publicitando.
  • El filtrado de informes de publicidad duplicados puede estar habilitado dependiendo de la configuración de filtrado.
  • Los objetos de dispositivo encontrados durante una sesión de escaneo solo se persistirán si están conectados/emparejados, de lo contrario se eliminarán después de algún tiempo.
Uso
> scan <on/off/bredr/le>

pair

Empareja con un dispositivo.

Esto emparejará con un dispositivo y luego confiará y se conectará a él. Si el dispositivo ya está emparejado, primero se eliminará el emparejamiento.

El comando puede usarse mientras el controlador está en estado conectado o no conectado.

Si el controlador ya está conectado, el comando pair puede usarse sin argumentos. Si el controlador no está conectado, al comando pair se le puede dar la dirección de un dispositivo con un informe de escaneo activo e iniciará la conexión antes de emparejar.

Antes de emparejar, se debe seleccionar el agente para elegir el mecanismo de autenticación.

Uso
> pair <dev>

pairable

Establece el modo emparejable del controlador.

Esto habilita/deshabilita el emparejamiento. Si el emparejamiento está deshabilitado, el controlador no aceptará ninguna solicitud de emparejamiento.

Uso
> pairable <on/off>

discoverable

Establece el modo descubrible.

Esto habilita/deshabilita el modo descubrible. Si descubrible está deshabilitado, el controlador no responderá a ninguna solicitud de escaneo.

En LE, si descubrible está desactivado, el controlador solo escaneará pasivamente y no hará solicitudes de escaneo a los dispositivos publicitarios. Si está activado, hará las solicitudes de publicidad.

Usará una dirección aleatoria si el controlador lo soporta. El tiempo de validez de "discoverable on" lo determina el comando discoverable-timeout.

Uso
> discoverable <on/off>

discoverable-timeout

Establece el tiempo de espera de descubrimiento.

El tiempo en segundos que "discoverable on" es válido.

Uso
> discoverable-timeout [value]

agente

Habilita/deshabilita el agente con la capacidad dada.

Esto elige el mecanismo de autenticación local del controlador. Es necesario para el emparejamiento y te permite elegir las capacidades de entrada/salida (IO) del controlador.

Las capacidades válidas del agente son: DisplayOnly, DisplayYesNo, KeyboardDisplay, KeyboardOnly, NoInputNoOutput.

Uso
> agente <on/off/capacidad>

agente-predeterminado

Establece el agente actual como el predeterminado.

Después de seleccionar el agente, este se convertirá en el agente predeterminado.

Uso
> agente-predeterminado

confiar

Confiar en el dispositivo.

Uso
> confiar <dev>

no-confiar

No confiar en el dispositivo.

Uso
> no-confiar <dev>

bloquear

Bloquear dispositivo.

Uso
> bloquear <dev>

desbloquear

Desbloquear dispositivo.

Uso
> desbloquear <dev>

eliminar

Eliminar dispositivo.

Uso
> eliminar <dev>

conectar

Conectar dispositivo.

Esto iniciará una conexión a un dispositivo.

Por defecto, este comando intenta conectar todos los perfiles que el dispositivo remoto soporta y que han sido marcados como conectables automáticamente. En caso de que se proporcione el UUID del servicio remoto, solo se conectará ese servicio. El UUID puede ser una forma corta (UUID de 16 bits) o una forma larga (UUID de 128 bits). También hay algunos valores especiales para perfiles conocidos como "a2dp-sink", "a2dp-source", "hfp-hf", "hfp-ag", "ftp" o "spp".

Para conectarse con un dispositivo LE, el controlador debe tener un informe de escaneo activo del dispositivo al que se desea conectar.

Si no se recibe ningún informe de publicidad antes del tiempo de espera, se emitirá un error de conexión LE abortada por el local. En ese caso, intente nuevamente conectar asumiendo que el dispositivo está transmitiendo publicidad.

Uso
> conectar <dev> [uuid]
Ejemplo
> conectar 1C:48:F9:9D:81:5C
Ejemplo
> conectar 1C:48:F9:9D:81:5C hsp-hs
Ejemplo
> conectar 1C:48:F9:9D:81:5C 00001108-0000-1000-8000-00805f9b34fb
Ejemplo
> conectar 1C:48:F9:9D:81:5C 0x1108

desconectar

Desconectar dispositivo.

Por defecto, este comando desconecta todos los perfiles y luego termina la conexión. En caso de que se proporcione el UUID del servicio remoto, solo se desconectará ese servicio.

Para LE, al desconectarse de una conexión activa, no se necesita la dirección del dispositivo.

Uso
> desconectar <dev> [uuid]

informacion

Información del dispositivo.

Uso
> informacion <dev>

portador

Obtener/Establecer portador preferido.

Uso
> portador <dev> [visto-por-última-vez/bredr/le]
Ejemplo para obtener el portador preferido
> portador <dir>
PreferredBearer: last-seen
Ejemplo para establecer el portador preferido a LE
> portador <dir> le
[CHG] Device <dir> PreferredBearer: le
Changing le succeeded
Ejemplo para establecer el portador preferido a BREDR
> portador <dir> bredr
[CHG] Device <dir> PreferredBearer: bredr
Changing bredr succeeded

AUTOMATIZACIÓN

Dos formas comunes de automatizar la herramienta son usar Here Docs o el programa expect. Usando Here Docs para mostrar información sobre el controlador Bluetooth.

bluetoothctl <<EOF
list
show
EOF
