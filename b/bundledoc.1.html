DESCRIPCIÓ

N

bundledoc es un postprocesador para el paquete snapshot que empaqueta juntas todas las clases, paquetes y archivos necesarios para compilar un documento LaTeX determinado. Lee el archivo .dep que snapshot produce, encuentra cada uno de los archivos mencionados en él, y los empaqueta en un único archivo de archivo (por ejemplo, un archivo .tar.gz), adecuado para moverse entre sistemas, transmitirse a un colega,

etc.

Como el ejemplo más simple posible, considere un archivo LaTeX llamado, digamos, hello.t

ex: 
\RequirePackage{snapshot}       % Needed by bundledoc
\documentclass[11pt]{article}
\begin{document}
Hello, world!
\end{document}

El "\RequirePackage{snapshot}" hace que se produzca un archivo hello.dep. Cuando bundledoc recibe luego "hello.dep" como argumento, localiza los archivos dependientes -- snapshot.sty, article.cls, y size11.clo -- y los empaqueta en un único archivo de archivo, junto con hello.tex y un archivo MANIFEST (descrito e

n "OPTIONS
", más abajo).

bundledoc requiere el nombre del archivo de dependencias producido por snapshot, normalmente somefile.dep). (Por conveniencia, el archivo se puede especificar sin su extensión .dep.) Las siguientes opciones también se pueden

--versi

--[no]verbose (por defecto:
"noverbose")
bundledoc normalmente no muestra nada excepto mensajes de error. Con "--verbose", muestra numerosos mensajes de
estado.
--texfile=archivo .tex principal (por defecto: somefile.te
x)
El archivo de dependencias de snapshot no lista el archivo LaTeX principal (el que se pasa a latex). Para que bundledoc pueda encontrar y empaquetar ese archivo, bundledoc asume que tiene el mismo nombre que el archivo de dependencias de snapshot pero con una extensión .tex. Si no es el caso, use "--texfile" para especificar el nombre de archivo
correcto.
--directory=directorio de archivo (por defecto: somefil
e)
Cuando bundledoc crea un archivo (por ejemplo, un archivo .tar o archivo .zip) que contiene los archivos del documento, los pone a todos en un directorio para evitar desordenar el directorio actual con archivos. Si el archivo de dependencias dado se llama somefile.dep, entonces el archivo resultante almacenará por defecto todos los archivos dependientes en un directorio somefile. Para cambiar el nombre del directorio use la opción "--dire
ctory".
--[no]localonly (por defecto:
"nolocalonly")
Aunque bundledoc normalmente archiva todos los archivos nombrados en el archivo .dep, la opción "--localonly" le dice a bundledoc que excluya todos los archivos ubicados en un directorio diferente al del archivo .tex o a uno de sus
subdirectorios.
--exclude=string (por defecto: non
e)
Mientras que "--localonly" hace que los archivos fuera del árbol de directorios del archivo .tex se omitan del archivo, "--exclude" proporciona un control más detallado sobre los archivos a omitir del archivo. La opción "--exclude", que se puede especificar repetidamente en la línea de comandos, hace que todos los archivos cuyo nombre contenga string se omitan del
archivo.
--include=filespec (por defecto: non
e)
La opción "--include", que se puede especificar repetidamente en la línea de comandos, instruye a bundledoc a incluir en el archivo todos los archivos que coincidan con filespec, incluso si no están referenciados en el archivo .
dep.
--manifest=archivo manifiesto (por defecto: MANIFES
T)
Además de los archivos dependientes, bundledoc incluye en el archivo un archivo extra llamado, por defecto, ``MANIFEST''. MANIFEST es un archivo de texto que lista los nombres de archivo originales de todas las dependencias. Para cambiar el nombre de archivo de ``MANIFEST'' a algo más, use la opción "--manifest". Como caso especial, "--manifest=""" le dice a bundledoc que no incluya un archivo manifiesto en
absoluto.
--listdeps=[yes|no|only|rel]...] (por defecto:
"no")
"--listdeps" acepta uno o más de "yes", "no", "only", o "rel" como una lista separada por comas. Siempre que "no" no aparezca en esta lista, bundledoc muestra todas las dependencias del archivo LaTeX principal. Si la lista contiene "rel", entonces bundledoc muestra la lista de dependencias con rutas relativas. Si la lista contiene "only", entonces bundledoc sale después de mostrar la lista, sin producir un
archivo.
--[no]keepdirs (por defecto:
"nokeepdirs")
Normalmente, el archivo que bundledoc produce contiene un único directorio -- y subdirectorios, si el documento se refiere explícitamente a ellos -- en el que se encuentran todos los archivos dependientes. Si se especifica "--keepdirs", todos los archivos dependientes se almacenan con sus rutas originales. Por ejemplo, si somefile.tex depende de figures/somefigure.eps, article.cls, y snapshot.sty, entonces el archivo somefile normalmente

La opción "--config" se usa para apuntar bundledoc al archivo de configuración (.cfg) apropiado para su distribución TeX y sistema operativo. bundledoc viene con algunos archivos de configuración y es fácil escribir más.
