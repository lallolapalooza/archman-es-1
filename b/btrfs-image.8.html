NOMBRE

btrfs-image - crear/restaurar una imagen del sistema de archivos

SINOPSIS

btrfs-image [opciones] <fuente> <destino>

DESCRIPCIÓN

btrfs-image se utiliza para crear una imagen de un sistema de archivos btrfs. Todos los datos se pondrán a cero, pero la metadatos y similares se conservan. Principalmente se usa para fines de depuración.

En modo de volcado (dump), la fuente es el dispositivo/archivo btrfs y el destino es el archivo de salida (use - para stdout).

En modo de restauración (opción -r), la fuente es la imagen volcada y el destino es el dispositivo/archivo btrfs.

OPCIONES

-r
Restaurar imagen de metadatos (metadump). Por defecto, esto corrige el árbol de fragmentos (chunk tree) del superbloque, utilizando una franja (stripe) que apunta al dispositivo principal, para que el sistema de archivos pueda ser restaurado ejecutando la replicación del registro del árbol (tree log reply) si es posible. Para restaurar sin cambiar el número de franjas en el árbol de fragmentos, consulte la opción -o.
-c <valor>
Nivel de compresión (0 ~ 9).
-t <valor>
Número de hilos (1 ~ 32) a utilizar para procesar el volcado o la restauración de la imagen.
-o
Utilizar el antiguo método de restauración. Esto no corrige el árbol de fragmentos, por lo que el sistema de archivos restaurado no podrá ser montado.
-s
Sanitizar los nombres de archivo al generar la imagen. No recomendado, ya que introduciría nuevas discrepancias en los hashes de los nombres de archivo, por lo tanto, si su problema involucra árboles de subvolúmenes, podría incluso enmascarar problemas existentes. Además, los núcleos (kernels) no pueden realizar una resolución de rutas adecuada debido a las discrepancias introducidas en los hashes.

Un -s significa simplemente generar basura aleatoria, lo que significa que el hash del directorio no coincidirá con sus nombres de archivo. Usar dos -s calculará una colisión para el nombre de archivo de modo que los hashes coincidan, y si no puede calcular una colisión, simplemente generará basura. La calculadora de colisiones es muy intensiva en tiempo y CPU.

-w
Recorrer manualmente todos los árboles y copiar cualquier bloque que esté referenciado. Utilice esta opción si su árbol de extents está corrupto para asegurarse de que se capture toda la metadatos.
-m
Restaurar para múltiples dispositivos, se deben proporcionar más de 1 dispositivo.
--version
Imprimir la versión de btrfs-image, las características integradas y salir.

ESTADO DE SALIDA

btrfs-image devolverá 0 si no ocurrió ningún error. Si ocurrieron problemas, se devolverá 1.
