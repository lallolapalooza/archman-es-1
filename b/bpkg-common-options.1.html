--fetch-timeout se

Tiempo de espera del programa de obtención y similares (por ejemplo, git). Aunque la semántica exacta del valor depende del programa utilizado, como mínimo especifica en segundos el tiempo máximo que se puede pasar sin ninguna actividad de red.

Para git sobre HTTP/HTTPS esta semántica se consigue utilizando los valores de configuración http.lowSpeedLimit=1 http.lowSpeedTime=sec (los protocolos git:// y ssh:// actualmente no admiten tiempos de espera)

--pkg-proxy ur
l
Servidor proxy HTTP a utilizar al obtener manifiestos y archivos de paquetes de repositorios remotos pkg. Si se especifica, la url del proxy debe estar en la forma http://host[:port]. Si port se omite, se utiliza 80 de forma predeterminada.

Tenga en cuenta que para permitir el almacenamiento en caché, las URL https:// a través del proxy se convierten a http:// para evitar que el programa de obtención establezca túneles (que es el enfoque estándar para el proxy de HTTPS). Si se utilizan repositorios tanto HTTP como HTTPS, se asume que el servidor proxy puede averiguar qué URL deben convertirse de nuevo a https:// basándose en la información de la solicitud (por ejemplo, el nombre del host). Por seguridad, este me

canismo solo debe utilizarse con repositorios firmados o c
uando el proxy se encuentre dentro de una red de confianza.

--git-option op
t
Opción común adicional a pasar al programa git. Tenga en cuenta que las opciones comunes son las que preceden al comando git. Consulte --git para obtener más información sobre el programa git. Repita esta opción para especificar múltiples opciones de
git.
--sha256 path
El programa sha256 que se utilizará para calcular las sumas SHA256. Actualmente, bpkg reconoce sha256, sha256sum y shasum. Tenga en cuenta que el último componente de path debe contener uno de estos nombres como subcadena para que bpkg reconozca qué programa se está utilizando. También puede especificar opciones adicionales que se deben pasar al programa sha256 con --sha256-option.

Si el programa sha256 no se especifica, entonces bpkg intentará descubrir si alguno de los programas anteriores está disponible y lo usará. Actualmente, bpkg tiene el siguiente orden de preferencia: sha256, sha256sum y shasum.

--sha256-option opt
Opción adicional que se pasará al programa sha256. Consulte --sha256 para obtener más información sobre el programa sha256. Repita esta opción para especificar múltiples opciones sha256.
--tar path
El programa tar que se utilizará para extraer archivos de paquetes. Por ejemplo, gtar o bsdtar. También puede especificar opciones adicionales que se deben pasar al programa tar con --tar-option. Si el programa tar no se especifica explícitamente, entonces bpkg usará tar por defecto.
--tar-option opt
Opción adicional que se pasará al programa tar. Consulte --tar para obtener más información sobre el programa tar. Repita esta opción para especificar múltiples opciones tar.
--openssl path
El programa openssl que se utilizará para operaciones criptográficas. También puede especificar opciones adicionales que se deben pasar al programa openssl con --openssl-option. Si el programa openssl no se especifica explícitamente, entonces bpkg usará openssl por defecto.

Los valores --openssl* pueden calificarse opcionalmente con el comando openssl en el formato comando:valor. Esto hace que el valor solo sea aplicable al comando específico, por ejemplo:

bpkg rep-create                      \
  --openssl pkeyutl:/path/to/openssl \
  --openssl-option pkeyutl:-engine   \
  --openssl-option pkeyutl:pkcs11    \
  ...

Tenga en cuenta que para las versiones de openssl anteriores a la 3.0.0, bpkg utiliza el comando rsautl en lugar de pkeyutl para las operaciones de firma y recuperación de datos.

Un valor no calificado que contiene dos puntos se puede especificar como calificado con un comando vacío, por ejemplo, --openssl :C:\bin\openssl. Para ver los comandos de openssl ejecutados por bpkg, utilice el modo detallado (opción -v).

--openssl-option opt
Opción adicional que se pasará al programa openssl. Consulte --openssl para obtener más información sobre el programa openssl. Los valores pueden calificarse opcionalmente con el comando openssl, como se describe en --openssl. Repita esta opción para especificar múltiples opciones openssl.
--auth type
Tipos de repositorios a autenticar. Los valores válidos para esta opción son none, remote, all. Por defecto, solo se autentican los repositorios remotos. Puede solicitar la autenticación de repositorios locales pasando all o deshabilitar la autenticación por completo pasando none.
--trust fingerprint
Confíe en el certificado del repositorio con una huella digital SHA256. Dicho certificado se considera confiable automáticamente, sin solicitar confirmación al usuario. Repita esta opción para confiar en múltiples certificados.

Tenga en cuenta que por defecto openssl imprime una huella digital SHA1 y para obtener una SHA256 necesitará pasar la opción -sha256, por ejemplo:

openssl x509 -sha256 -fingerprint -noout -in cert.pem
--trust-yes
Asuma que la respuesta a todas las indicaciones de autenticación es yes.
--trust-no
Asuma que la respuesta a todas las indicaciones de autenticación es no.
--git-capabilities up=pc
Capacidades del protocolo (pc) para un prefijo de URL de repositorio git (up). Los valores válidos para las capacidades son dumb (sin soporte para clonación superficial), smart (soporte para clonación superficial, pero no para obtener commits no anunciados), unadv (soporte para clonación superficial y para obtener commits no anunciados). Por ejemplo: 
bpkg build https://example.org/foo.git#master \
  --git-capabilities https://example.org=smart

Consulte bpkg-repository-types(1) para obtener detalles sobre las capacidades del protocolo git.

--pager path
El programa paginador que se utilizará para mostrar texto largo. Los programas paginadores comúnmente utilizados son less y more. También puede especificar opciones adicionales que se deben pasar al programa paginador con --pager-option. Si se especifica una cadena vacía como programa paginador, no se utilizará ningún paginador. Si el programa paginador no se especifica explícitamente, entonces bpkg intentará usar less. Si no está disponible, no se utilizará ningún paginador.
--pager-option opt
Opción adicional que se pasará al programa paginador. Consulte --pager para obtener más información sobre el programa paginador. Repita esta opción para especificar múltiples opciones de paginador.
--options-file file
Leer opciones adicionales del archivo. Cada opción debe aparecer en una línea separada, seguida opcionalmente por un espacio o un signo igual (=) y un valor de opción. Las líneas vacías y las líneas que comienzan con # se ignoran. Los valores de las opciones se pueden encerrar entre comillas dobles (") o simples (') para conservar los espacios en blanco iniciales y finales, así como para especificar valores vacíos. Si el valor contiene comillas iniciales o finales, enciérrelo con un par adicional de comillas, por ejemplo '"x"'. Las comillas no iniciales y no finales se interpretan como parte del valor de la opción.

La semántica de proporcionar opciones en un archivo es equivalente a proporcionar el mismo conjunto de opciones en el mismo orden en la línea de comandos en el punto donde se especifica la opción --options-file, excepto que no se requiere el escape y la codificación de la shell. Repita esta opción para especificar más de un archivo de opciones.

--default-options dir
El directorio desde el cual cargar archivos de opciones predeterminados adicionales.
--no-default-options
No cargar archivos de opciones predeterminados.
--keep-tmp
No eliminar el directorio temporal de bpkg al final de la ejecución del comando e imprimir su ruta en el nivel de verbosidad 2 o superior. Esta opción es principalmente útil para la depuración.

SALIDA JSON

Los comandos que admiten la salida JSON especifican sus formatos como una representación serializada de una struct de C++ o un arreglo de ellas. Por ejemplo:

struct package
{
  string name;
};
struct configuration
{
  uint64_t         id;
  string           path;
  optional<string> name;
  bool             default;
  vector<package>  packages;
};

Un ejemplo de la representación JSON serializada de la struct configuration:

{
  "id": 1,
  "path": "/tmp/hello-gcc",
  "name": "gcc",
  "default": true,
  "packages": [
    {
      "name": "hello"
    }
  ]
}

Esta sección proporciona detalles sobre las propiedades generales de dichos formatos y la semántica de la serialización de struct.

El orden de los miembros en un objeto JSON es fijo, según lo especificado en la struct correspondiente. Si bien se pueden agregar nuevos miembros en el futuro (y los consumidores más antiguos deberían ignorarlos), la semántica de los miembros existentes (incluido si la entrada de nivel superior es un objeto o una matriz) no puede cambiar.

Un miembro de objeto es requerido a menos que su tipo sea optional<>, bool o vector<> (matriz). Para los miembros bool, la ausencia significa false. Para los miembros vector<>, la ausencia significa vacío. Una matriz vacía de nivel superior siempre está presente.

Por ejemplo, el siguiente texto JSON es una posible serialización de la struct configuration anterior:

{
  "id": 1,
  "path": "/tmp/hello-gcc"
}
