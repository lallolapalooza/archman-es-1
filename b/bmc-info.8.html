HOSTRANGED OPTIONS

Las siguientes opciones manipulan la salida de hostranged. Consulte HOSTRANGED SUPPORT a continuación para obtener información adicional sobre hostranges.

-B, --buffer-output
Almacenar en búfer la salida de hostranged. Para cada nodo, almacenar en búfer la salida estándar hasta que el nodo haya completado su operación IPMI. Al especificar esta opción, los datos pueden parecer que se muestran más lentamente al usuario, ya que la operación IPMI completa debe completarse antes de que se puedan mostrar los datos. Consulte HOSTRANGED SUPPORT a continuación para obtener información adicional.
-C, --consolidate-output
Consolidar la salida de hostranged. La salida estándar completa de cada nodo especificado se consolidará para que los nodos con salida idéntica no se muestren dos veces. Un encabezado listará aquellos nodos con la salida consolidada. Cuando se especifica esta opción, no se puede ver ninguna salida hasta que las operaciones IPMI a todos los nodos hayan completado. Si el usuario sale temprano del programa, se volcará toda la salida consolidada actualmente. Consulte HOSTRANGED SUPPORT a continuación para obtener información adicional.
-F NUM, --fanout=NUM
Especificar múltiples salidas de host. Se utiliza un algoritmo de "ventana deslizante" (o fanout) para la comunicación paralela IPMI, de modo que los nodos más lentos o los nodos que caducan no obstaculicen la comunicación paralela. El número máximo de hilos disponibles al mismo tiempo está limitado por el fanout. El valor predeterminado es 64.
-E, --eliminate
Eliminar hosts determinados como no detectados por ipmidetect. Esto intenta eliminar el problema común de que la ejecución de hostranged caduque debido a que varios nodos se retiran del servicio en un clúster grande. El demonio ipmidetectd debe estar ejecutándose en el nodo que ejecuta el comando.
--always-prefix
Prefijar siempre la salida, incluso si solo se especifica un host o se comunica en banda. Esta opción es principalmente útil para fines de scripting. La opción se ignorará si se especifica con la opción -C.

HOSTRANGED SUPPORT

Se pueden ingresar varios hosts ya sea como listas explícitas de hosts separadas por comas o como un rango de nombres de host en la forma general: prefijo[n-m,l-k,...], donde n < m y l < k, etc. La última forma no debe confundirse con las clases de caracteres de expresiones regulares (también denotadas por []). Por ejemplo, foo[19] no representa foo1 o foo9, sino que representa un rango degenerado: foo19.

Esta sintaxis de rango solo está pensada como una conveniencia en clústeres con una convención de nomenclatura prefijoNN y la especificación de rangos no debe considerarse necesaria; la lista foo1,foo9 podría especificarse como tal, o mediante el rango foo[1,9].

Algunos ejemplos de uso de rangos son los siguientes:

    foo[01-05] en lugar de foo01,foo02,foo03,foo04,foo05
    foo[7,9-10] en lugar de foo7,foo9,foo10
    foo[0-3] en lugar de foo0,foo1,foo2,foo3

Como recordatorio para el lector, algunos shells interpretarán corchetes ([ y ]) para la coincidencia de patrones. Dependiendo de su shell, puede ser necesario encerrar las listas de rangos entre comillas.

Cuando se especifican varios hosts, se ejecutará un hilo para cada host en paralelo hasta el fanout configurado (que se puede ajustar mediante la opción -F). Esto permitirá la comunicación a un gran número de nodos mucho más rápido que si se hiciera en serie.

Por defecto, la salida estándar de cada nodo especificado se mostrará con el nombre del host antepuesto a cada línea. Aunque esta salida es legible en muchas situaciones, puede ser difícil de leer en otras situaciones. Por ejemplo, la salida de varios nodos puede mezclarse. Las opciones -B y -C se pueden utilizar para cambiar este valor predeterminado.

La comunicación IPMI en banda se utilizará cuando se especifique el host "localhost". Esto permite al usuario agregar el localhost a la salida de hostranged.

GENERAL TROUBLESHOOTING

La mayoría de las veces, los problemas de IPMI se deben a problemas de configuración.

Los problemas de IPMI sobre LAN implican una configuración incorrecta del BMC de la máquina remota. Verifique cuidadosamente que los siguientes elementos estén configurados correctamente en el BMC de la máquina remota: dirección IP, dirección MAC, máscara de subred, nombre de usuario, habilitación de usuario, privilegio de usuario, contraseña, privilegio de LAN, habilitación de LAN y tipo(s) de autenticación permitidos. Para conexiones IPMI 2.0, verifique cuidadosamente que el privilegio del conjunto de cifrado y la clave K_g estén configurados correctamente. La herramienta ipmi-config(8) se puede utilizar para verificar y/o cambiar estas configuraciones.

Los problemas de IPMI en banda suelen ser causados por controladores mal configurados o BMC no estándar.

Además de los consejos de solución de problemas a continuación, consulte también SOLUCIONES ALTERNATIVAS a continuación si existen errores específicos del proveedor que se hayan descubierto y para los cuales se hayan encontrado soluciones alternativas.

A continuación, se enumeran muchos de los problemas comunes para los mensajes de error. Para obtener soporte adicional, envíe un correo electrónico a la lista de correo <freeipmi-users@gnu.org>.

"username invalid" - El nombre de usuario ingresado (o un nombre de usuario NULL si no se ingresó ninguno) no está disponible en la máquina remota. También es posible que la configuración del nombre de usuario del BMC remoto sea incorrecta.

"password invalid" - La contraseña ingresada (o una contraseña NULL si no se ingresó ninguna) no es correcta. También es posible que la contraseña del usuario no esté configurada correctamente en el BMC remoto.

"password verification timeout" - La verificación de contraseña ha caducado. Ocurrió un error de "password invalid" (descrito anteriormente) o un error genérico de "session timeout" (descrito a continuación). Durante este punto del protocolo, no se puede diferenciar cuál ocurrió.

"k_g invalid" - La clave K_g ingresada (o una clave K_g NULL si no se ingresó ninguna) no es correcta. También es posible que la clave K_g no esté configurada correctamente en el BMC remoto.

"privilege level insufficient" - Un comando IPMI requiere un privilegio de usuario superior al con el que se autenticó. Intente autenticarse con un privilegio superior. Esto puede requerir la autenticación con un usuario diferente que tenga un privilegio máximo mayor.

"privilege level cannot be obtained for this user" - El nivel de privilegio con el que intenta autenticarse es superior al máximo permitido para este usuario. Intente nuevamente con un privilegio inferior. También es posible que el nivel de privilegio máximo permitido para un usuario no esté configurado correctamente en el BMC remoto.

"authentication type unavailable for attempted privilege level" - El tipo de autenticación con el que desea autenticarse no está disponible para este nivel de privilegio. Intente nuevamente con un tipo de autenticación alternativo o un nivel de privilegio alternativo. También es posible que los tipos de autenticación disponibles con los que puede autenticarse no estén configurados correctamente en el BMC remoto.

"cipher suite id unavailable" - El ID del conjunto de cifrado con el que desea autenticarse no está disponible en el BMC remoto. Intente nuevamente con un ID de conjunto de cifrado alternativo. También es posible que los ID de conjunto de cifrado disponibles no estén configurados correctamente en el BMC remoto.

"ipmi 2.0 unavailable" - IPMI 2.0 no se detectó en la máquina remota. Intente usar IPMI 1.5 en su lugar.

"connection timeout" - La comunicación IPMI inicial falló. Son posibles una serie de errores potenciales, que incluyen un nombre de host inválido especificado, que la dirección IP de IPMI no se puede resolver, que IPMI no esté habilitado en el servidor remoto, que la conexión de red sea deficiente, etc. Verifique la configuración y la conectividad.

"session timeout" - La sesión IPMI ha caducado. Vuelva a conectarse. Si este error ocurre con frecuencia, puede que desee aumentar el tiempo de espera de retransmisión. Algunos BMC remotos son considerablemente más lentos que otros.

"device not found" - No se pudo encontrar el dispositivo especificado. Verifique la configuración o las entradas e intente nuevamente.

"driver timeout" - La comunicación con el controlador o dispositivo ha caducado. Intente nuevamente.

"message timeout" - La comunicación con el controlador o dispositivo ha caducado. Intente nuevamente.

"BMC busy" - El BMC está ocupado actualmente. Puede estar procesando información o tener demasiadas sesiones simultáneas para gestionar. Espere e intente nuevamente.

"could not find inband device" - No se pudo encontrar un dispositivo en banda. Verifique la configuración o especifique un dispositivo o controlador específico en la línea de comandos.

"driver timeout" - El controlador en banda ha caducado en la comunicación con el BMC local o el procesador de servicio. El BMC o el procesador de servicio pueden estar ocupados o (en el peor de los casos) posiblemente no funcionen.

WORKAROUNDS

Dado que tantos proveedores diferentes implementan sus propias soluciones IPMI, los diferentes proveedores pueden implementar sus protocolos IPMI incorrectamente. A continuación, se describen una serie de soluciones alternativas disponibles actualmente para manejar problemas de cumplimiento descubiertos. Cuando sea posible, las soluciones alternativas se han implementado para que sean transparentes para el usuario. Sin embargo, algunas requerirán que el usuario especifique que se utilice una solución alternativa a través de la opción -W.

El hardware que se enumera a continuación puede indicar solo el hardware en el que se descubrió un problema. Las versiones más nuevas de hardware pueden corregir los problemas indicados a continuación. Máquinas similares de otros proveedores pueden o no presentar el mismo problema.

s. Diferentes proveedores pueden licenciar su firmware del mismo desarrollador de firmware IPMI, por lo que puede ser útil probar las soluciones alternativas listadas a continuación, incluso si su placa base no está

listada.

Si cree que su hardware tiene un problema de cumplimiento adicional que requiere la implementación de una solución alternativa, por favor contacte a los mantenedores de FreeIPMI en <freeipmi-users@gnu.org> o <freeipmi-devel@gnu.org>

.

assumeio - Esta bandera de solución alternativa asumirá que las interfaces inband se comunican con las E/S del sistema en lugar de estar mapeadas en memoria. Esto funcionará como solución alternativa para sistemas que reportan direcciones base inválidas. Aquellos que encuentren este problema pueden ver errores "device not supported" o "could not find inband device". Problema observado en HP ProLiant DL145

G1.

spinpoll - Esta bandera de solución alternativa informará a algunos controladores inband (el más notable es el controlador KCS) que giren mientras hacen sondeo en lugar de poner el proceso a dormir. Esto puede mejorar significativamente el tiempo de ejecución real de las herramientas porque la granularidad del planificador de un sistema operativo puede ser mucho mayor que el tiempo que toma realizar una transacción de mensaje IPMI individual. Sin embargo, al girar, su sistema puede estar realizando un trabajo menos útil al no cambiar el contexto de la herramienta para una tarea más

útil.

authcap - Esta bandera de solución alternativa omitirá las verificaciones tempranas de capacidades de nombre de usuario, capacidades de autenticación y soporte de K_g, y permitirá que la autenticación IPMI tenga éxito. Funciona como solución alternativa a múltiples problemas en los que el sistema remoto no reporta correctamente las capacidades de nombre de usuario, las capacidades de autenticación o el estado de K_g. Aquellos que encuentren este problema pueden ver errores "username invalid", "authentication type unavailable for attempted privilege level" o "k_g invalid". Problema observado en Asus P5M2/P5MT-R/RS162-E4/RX4, Intel SR1520ML/X38ML y Sun Fire 2200/4150/4450 con

ELOM.

nochecksumcheck - Esta bandera de solución alternativa le dirá a FreeIPMI que no verifique las sumas de verificación devueltas por las respuestas de los comandos IPMI. Funciona como solución alternativa para sistemas que devuelven sumas de verificación inválidas debido a errores de implementación, pero el paquete es válido de otro modo. Se recomienda precaución en el uso de esta opción, ya que elimina la validación de la integridad del paquete en varias circunstancias. Sin embargo, es improbable que sea un problema en la mayoría de las situaciones. Aquellos que encuentren este problema pueden ver errores "connection timeout", "session timeout" o "password verification timeout". En conexiones IPMI 1.5, también puede ser necesaria la solución alternativa "noauthcodecheck". Problema observado en Supermicro X9SCM-iiF, Supermicro X9DRi-F y Supermicro

X9DRFR.

idzero - Esta bandera de solución alternativa permitirá que el cliente acepte IDs de sesión vacíos. Funciona como solución alternativa para sesiones IPMI que reportan IDs de sesión vacíos al cliente. Aquellos que encuentren este problema pueden ver errores "session timeout". Problema observado en Tyan S2882 con BMC

M3289.

unexpectedauth - Esta bandera de solución alternativa permitirá que los códigos de autenticación no nulos inesperados se verifiquen como si se esperaran. Funciona como solución alternativa a un problema cuando los paquetes contienen datos de autenticación no nulos cuando deberían ser nulos debido a la autenticación por mensaje deshabilitada. Aquellos que encuentren este problema pueden ver errores "session timeout". Problema observado en Dell PowerEdge 2850, SC1425. Confirmado como corregido en firmware más

reciente.

forcepermsg - Esta bandera de solución alternativa forzará el uso de la autenticación por mensaje sin importar lo que anuncie el sistema remoto. Funciona como solución alternativa a un problema cuando la autenticación por mensaje está anunciada como deshabilitada en el sistema remoto, pero en realidad es requerida por el protocolo. Aquellos que encuentren este problema pueden ver errores "session timeout". Problema observado en IBM eServer

325.

endianseq - Esta bandera de solución alternativa invertirá el orden de bytes de los números de secuencia de sesión para permitir que la sesión continúe correctamente. Funciona como solución alternativa para números de secuencia de sesión IPMI 1.5 que tienen el orden de bytes incorrecto. Aquellos que encuentren este problema pueden ver errores "session timeout". Problema observado en algunos Sun ILOM 1.0/2.0 (depende del orden de bytes del procesador de servicio)

.

noauthcodecheck - Esta bandera de solución alternativa le dirá a FreeIPMI que no verifique los códigos de autenticación devueltos por las respuestas de los comandos IPMI 1.5. Funciona como solución alternativa para sistemas que devuelven códigos de autenticación inválidos debido a errores de hashing o de implementación. Se recomienda precaución en el uso de esta opción, ya que elimina una verificación de autenticación que valida la integridad de un paquete. Sin embargo, en la mayoría de las organizaciones, es improbable que sea un problema de seguridad. Aquellos que encuentren este problema pueden ver errores "connection timeout", "session timeout" o "password verification timeout". Problema observado en Xyratex FB-H8-SRAY, Intel Windmill, Quanta Winterfell y Wiwynn

Windmill.

intel20 - Esta bandera de solución alternativa funcionará como solución para varios problemas de autenticación IPMI 2.0 de Intel. Los problemas cubiertos incluyen el relleno de nombres de usuario y el truncamiento de contraseñas si el algoritmo de autenticación es HMAC-MD5-128. Aquellos que encuentren este problema pueden ver errores "username invalid", "password invalid" o "k_g invalid". Problema observado en Intel SE7520AF2 con Intel Server Management Module (Professional Edition)

.

supermicro20 - Esta bandera de solución alternativa funcionará como solución para varios problemas de autenticación IPMI 2.0 de Supermicro en placas base con firmware IPMI de Peppercon. Los problemas cubiertos incluyen el manejo de códigos de autenticación de longitud inválida. Aquellos que encuentren este problema pueden ver errores "password invalid". Problema observado en Supermicro H8QME con tarjeta hija SIMSO. Confirmado como corregido en firmware más

reciente.

sun20 - Esta bandera de solución alternativa funcionará como solución para varios problemas de autenticación IPMI 2.0 de Sun. Los problemas cubiertos incluyen claves hash de longitud inválida, claves hash incorrectamente calculadas y registros de suite de cifrado inválidos. Aquellos que encuentren este problema pueden ver errores "password invalid" o "bmc error". Problema observado en Sun Fire 4100/4200/4500 con ILOM. Esta solución alternativa incluye automáticamente la solución alternativa

"opensesspriv".

opensesspriv - Esta bandera de solución alternativa alterará ligeramente el protocolo de conexión IPMI 2.0 de FreeIPMI para solucionar un algoritmo de hashing inválido utilizado por el sistema remoto. El nivel de privilegio enviado durante la etapa de Apertura de Sesión de una conexión IPMI 2.0 se utiliza para el hashing de claves en lugar del nivel de privilegio enviado durante la etapa de conexión RAKP1. Aquellos que encuentren este problema pueden ver errores "password invalid", "k_g invalid", "bad rmcpplus status code" o "privilege level cannot be obtained for this user". Problema observado en Sun Fire 4100/4200/4500 con ILOM, Inventec 5441/Dell Xanadu II, Supermicro X8DTH, Supermicro X8DTG, Intel S5500WBV/Penguin Relion 700, Intel S2600JF/Appro 512X, Quanta QSSC-S4R/Appro GB812X-CN, Dell C5220 y el BMC de software OpenIPMI. Esta solución alternativa se activa automáticamente con la solución alternativa

"sun20".

integritycheckvalue - Esta bandera de solución alternativa funcionará como solución para un valor de verificación de integridad inválido durante el establecimiento de una sesión IPMI 2.0 al usar el ID de Suite de Cifrado 0. El valor de verificación de integridad debería tener una longitud de 0, sin embargo, la placa base remota responde con un campo no vacío. Aquellos que encuentren este problema pueden ver errores "k_g invalid". Problema observado en Supermicro X8DTG, Supermicro X8DTU, Intel S5500WBV/Penguin Relion 700 e Intel S2600JF/Appro

512X.

guidformat - Un número de proveedores envían los bytes del GUID (como el GUID en --get-device-guid o --get-system-guid) en un formato alternativo que se alinea incorrectamente con IPMI, pero correctamente con otros estándares. Esta bandera de solución alternativa instruirá a bmc-info para leer el GUID y mostrar el GUID basándose en este formato alternativo

común.

Sin soporte para IPMI 1.5 - Se ha encontrado que algunas placas base que soportan IPMI 2.0 no soportan IPMI 1.5. Aquellos que encuentren este problema pueden ver errores "ipmi 2.0 unavailable" o "connection timeout". Este problema se puede solucionar usando IPMI 2.0 en lugar de IPMI 1.5 especificando --driver-type=LAN_2_0. Problema observado en un núme

ro de placas base
de HP y Supermicro.

PROBLEMAS

CONOCIDOS

En sistemas operativos antiguos, si ingresa su nombre de usuario, contraseña y otra información potencialmente relevante para la seguridad en la línea de comandos, esta información puede ser descubierta por otros usuarios cuando se usan herramientas como el comando ps(1) o al mirar en el sistema de archivos /proc. Generalmente es más seguro ingresar información de contraseña con opciones como las opciones -P o -K. Configurar información relevante para la seguridad en el archivo de configuración de FreeIPMI también sería una forma apropiada de ocultar esta

información.

Para prevenir ataques de fuerza bruta, algunos BMC se "bloquearán" temporalmente des

pués de un número de errores de autenticación remota. Puede necesitar esperar un ti
empo para que este "bloqueo" temporal pase antes de que pueda autenticarse de nuevo.
