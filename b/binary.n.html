SCAN

El comando binary scan analiza campos de una cadena binaria, devolviendo el número de conversiones realizadas. String proporciona los bytes de entrada a analizar (un byte por carácter, y los caracteres no representables como un byte tienen sus bits altos recortados) y formatString indica cómo analizarlo. Cada varName proporciona el nombre de una variable; cuando un campo se analiza desde string el resultado se asigna a la variable correspondiente

.

Al igual que con binary format, el formatString consta de una secuencia de cero o más especificadores de campo separados por cero o más espacios. Cada especificador de campo es un carácter de tipo seguido de un carácter de bandera opcional seguido de un count numérico opcional. La mayoría de los especificadores de campo consumen un argumento para obtener la variable en la que los valores analizados deben colocarse. El carácter de tipo especifica cómo se debe interpretar el dato binario. El count típicamente indica cuántos elementos del tipo especificado se toman de los datos. Si está presente, el count es un entero decimal no negativo o *, que normalmente indica que se deben usar todos los elementos restantes en los datos. Si no quedan suficientes bytes después de la posición actual del cursor para satisfacer el especificador de campo actual, entonces la variable correspondiente se deja intacta y binary scan devuelve inmediatamente con el número de variables que se establecieron. Si no hay suficientes argumentos para todos los campos en la cadena de formato que consumen argumentos, entonces se genera un error. El carácter de bandera “u” puede darse para causar que algunos tipos se lean como valores sin signo. La bandera se acepta para todos los tipos de campo pero se ignora para campos no

enteros.

BINARY SCAN

Lee datos de una cadena binaria y los asigna a variables Tcl.

La orden binary scan lee de la cadena, interpreta los octetos como se indica con el tipo, y asigna los resultados a las variables especificadas por char. El valor devuelto es el número de variables que se asignaron con éxito. La cadena es un valor de cadena que contiene los datos binarios que se van a analizar. Los tipos consisten en un carácter que especifica el tipo de datos, seguido opcionalmente por un número que especifica la cantidad de elementos de ese tipo que se deben extraer de la cadena. Si el número se omite, se asume que es 1. Si el número es *, se extraen todos los elementos restantes de ese tipo de la cadena.

Actualmente, se admiten los siguientes tipos:

a
Los datos se interpretan como una cadena de caracteres terminada en nulo. La cadena de caracteres de Tcl resultante no incluirá el carácter nulo terminador. El análisis se detiene en el primer carácter nulo encontrado o cuando se han leído los bytes especificados por recuento. Si recuento es *, el análisis se detiene en el primer carácter nulo o cuando se llega al final de la cadena, lo que ocurra primero. Si recuento se omite, se lee un solo carácter. Por ejemplo:
binary scan \x04hello\x00 world a* var1 var2
devolverá 1 con hello almacenado en var1. El resto de la cadena, world, se dejará sin analizar.
A
Los datos se interpretan como una cadena de caracteres sin terminar. Los caracteres se leen hasta que se hayan leído los bytes especificados por recuento. Si recuento es *, se leen todos los octetos restantes de la cadena. Si recuento se omite, se lee un solo octeto. Por ejemplo:
binary scan \x04hello\x00 world A* var1 var2
devolverá 1 con hello almacenado en var1.
c
Los datos se interpretan como recuento enteros con signo de 8 bits. Por ejemplo,
binary scan \x05\x07\xf0 c2 var1 var2
devolverá 2 con 5 7 almacenados en var1 y -16 almacenado en var2.
C
Los datos se interpretan como recuento enteros sin signo de 8 bits. Por ejemplo,
binary scan \x05\x07\xf0 C2 var1 var2
devolverá 2 con 5 7 almacenados en var1 y 240 almacenado en var2.
s
Los datos se interpretan como recuento enteros con signo de 16 bits en orden de bytes little-endian. Por ejemplo,
binary scan \x05\x00\x07\x00\xf0\xff s2s* var1 var2
devolverá 2 con 5 7 almacenados en var1 y -16 almacenado en var2. Tenga en cuenta que los enteros devueltos son con signo, pero pueden convertirse a cantidades de 16 bits sin signo utilizando una expresión como: 
set num [expr { $num & 0xFFFF }]
S
Esta forma es la misma que s, excepto que los datos se interpretan como recuento enteros con signo de 16 bits representados en orden de bytes big-endian. Por ejemplo,
binary scan \x00\x05\x00\x07\xff\xf0 S2S* var1 var2
devolverá 2 con 5 7 almacenados en var1 y -16 almacenado en var2.
t
Los datos se interpretan como recuento enteros con signo de 16 bits representados en el orden de bytes nativo de la máquina que ejecuta el script Tcl. Por lo demás, es idéntico a s y S. Para determinar cuál es el orden de bytes nativo de la máquina, consulte el elemento byteOrder de la matriz tcl_platform.
i
Los datos se interpretan como recuento enteros con signo de 32 bits representados en orden de bytes little-endian. Los enteros se almacenan en la variable correspondiente como una lista. Si recuento es *, se analizarán todos los bytes restantes en cadena. Si se omite recuento, se analizará un entero de 32 bits. Por ejemplo,
set str \x05\x00\x00\x00\x07\x00\x00\x00\xf0\xff\xff\xff
binary scan $str i2i* var1 var2
devolverá 2 con 5 7 almacenados en var1 y -16 almacenado en var2. Tenga en cuenta que los enteros devueltos son con signo, pero pueden convertirse a cantidades de 32 bits sin signo utilizando una expresión como: 
set num [expr { $num & 0xFFFFFFFF }]
I
Esta forma es la misma que I, excepto que los datos se interpretan como recuento enteros con signo de 32 bits representados en orden de bytes big-endian. Por ejemplo,
set str \x00\x00\x00\x05\x00\x00\x00\x07\xff\xff\xff\xf0
binary scan $str I2I* var1 var2
devolverá 2 con 5 7 almacenados en var1 y -16 almacenado en var2.
n
Los datos se interpretan como recuento enteros con signo de 32 bits representados en el orden de bytes nativo de la máquina que ejecuta el script Tcl. Por lo demás, es idéntico a i e I. Para determinar cuál es el orden de bytes nativo de la máquina, consulte el elemento byteOrder de la matriz tcl_platform.
w
Los datos se interpretan como recuento enteros con signo de 64 bits representados en orden de bytes little-endian. Los enteros se almacenan en la variable correspondiente como una lista. Si recuento es *, se analizarán todos los bytes restantes en cadena. Si se omite recuento, se analizará un entero de 64 bits. Por ejemplo,
set str \x05\x00\x00\x00\x07\x00\x00\x00\xf0\xff\xff\xff
binary scan $str wi* var1 var2
devolverá 2 con 30064771077 almacenado en var1 y -16 almacenado en var2. Tenga en cuenta que los enteros devueltos son con signo y no pueden ser representados por Tcl como valores sin signo.
W
Esta forma es la misma que w, excepto que los datos se interpretan como recuento enteros con signo de 64 bits representados en orden de bytes big-endian. Por ejemplo,
set str \x00\x00\x00\x05\x00\x00\x00\x07\xff\xff\xff\xf0
binary scan $str WI* var1 var2
devolverá 2 con 21474836487 almacenado en var1 y -16 almacenado en var2.
m
Los datos se interpretan como recuento enteros con signo de 64 bits representados en el orden de bytes nativo de la máquina que ejecuta el script Tcl. Por lo demás, es idéntico a w y W. Para determinar cuál es el orden de bytes nativo de la máquina, consulte el elemento byteOrder de la matriz tcl_platform.
f
Los datos se interpretan como recuento números de punto flotante de precisión simple en la representación nativa de la máquina. Los números de punto flotante se almacenan en la variable correspondiente como una lista. Si recuento es *, se analizarán todos los bytes restantes de la cadena. Si se omite recuento, se analizará un número de punto flotante de precisión simple. El tamaño de un número de punto flotante puede variar entre arquitecturas, por lo que el número de bytes que se analizan puede variar. Si los datos no representan un número de punto flotante válido, el valor resultante no está definido y depende del compilador. Por ejemplo, en un sistema Windows que se ejecuta en un procesador Intel Pentium,
binary scan \x3f\xcc\xcc\xcd f var1
devolverá 1 con 1.6000000238418579 almacenado en var1.
r
Esta forma es la misma que f, excepto que los datos se interpretan como recuento números de punto flotante de precisión simple en orden little-endian. Esta conversión no es portable a la minoría de sistemas que no utilizan representaciones de punto flotante IEEE.
R
Esta forma es la misma que f, excepto que los datos se interpretan como recuento números de punto flotante de precisión simple en orden big-endian. Esta conversión no es portable a la minoría de sistemas que no utilizan representaciones de punto flotante IEEE.
d
Esta forma es la misma que f, excepto que los datos se interpretan como recuento números de punto flotante de precisión doble en la representación nativa de la máquina. Por ejemplo, en un sistema Windows que se ejecuta en un procesador Intel Pentium,
binary scan \x9a\x99\x99\x99\x99\x99\xf9\x3f d var1
devolverá 1 con 1.6000000000000001 almacenado en var1.
q
Esta forma es la misma que d, excepto que los datos se interpretan como recuento números de punto flotante de precisión doble en orden little-endian. Esta conversión no es portable a la minoría de sistemas que no utilizan representaciones de punto flotante IEEE.
Q
Esta forma es la misma que d, excepto que los datos se interpretan como recuento números de punto flotante de precisión doble en orden big-endian. Esta conversión no es portable a la minoría de sistemas que no utilizan representaciones de punto flotante IEEE.
x
Mueve el cursor hacia adelante recuento bytes en cadena. Si recuento es * o es mayor que el número de bytes después de la posición actual del cursor, el cursor se posicionará después del último byte de la cadena. Si se omite recuento, el cursor se moverá hacia adelante un byte. Tenga en cuenta que este tipo no consume un argumento. Por ejemplo,
binary scan \x01\x02\x03\x04 x2H* var1
devolverá 1 con 0304 almacenado en var1.
X
Mueve el cursor hacia atrás recuento bytes en cadena. Si recuento es * o es mayor que la posición actual del cursor, el cursor se posicionará en la ubicación 0 para que el siguiente byte que se analice sea el primer byte de la cadena. Si se omite recuento, el cursor se moverá hacia atrás un byte. Tenga en cuenta que este tipo no consume un argumento. Por ejemplo,
binary scan \x01\x02\x03\x04 c2XH* var1 var2
devolverá 2 con 1 2 almacenados en var1 y 020304 almacenado en var2.
@
Mueve el cursor a la ubicación absoluta en la cadena de datos especificada por recuento. Tenga en cuenta que la posición 0 se refiere al primer byte de la cadena. Si recuento se refiere a una posición más allá del final de la cadena, el cursor se posicionará después del último byte. Si se omite recuento, se generará un error. Por ejemplo,
binary scan \x01\x02\x03\x04 c2@1H* var1 var2
devolverá 2 con 1 2 almacenados en var1 y 020304 almacenado en var2.

PROBLEMAS DE PORTABILIDAD

Las conversiones r, R, q y Q solo funcionarán de manera fiable para transferir datos entre ordenadores que utilicen representaciones de punto flotante IEEE. Esto es muy común, pero no universal. Para transferir números de punto flotante de forma portable entre todas las arquitecturas, utilice su representación textual (como la producida por format) en su lugar.

EJEMPLOS

Este es un procedimiento para escribir una cadena Tcl en un canal codificado binariamente como datos UTF-8 precedidos por una palabra de longitud:

proc writeString {channel string} {
    set data [encoding convertto utf-8 $string]
    puts -nonewline [binary format Ia* \
            [string length $data] $data]
}

Este procedimiento lee una cadena de un canal que fue escrita por el procedimiento writeString presentado anteriormente:

proc readString {channel} {
    if {![binary scan [read $channel 4] I length]} {
        error "falta longitud"
    }
    set data [read $channel $length]
    return [encoding convertfrom utf-8 $data]
}

Esto convierte el contenido de un archivo (cuyo nombre se indica en la variable filename) a base64 y lo imprime:

set f [open $filename rb]
set data [read $f]
close $f
puts [binary encode base64 -maxlen 64 $data]
