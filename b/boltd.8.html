BOLTD(8) Manual de bolt BOLTD(8)

NOMBRE

boltd - demonio de gestión de dispositivos thunderbolt

SINOPSIS

boltd [OPCIONES]

DESCRIPCIÓN

boltd es el demonio administrador de dispositivos thunderbolt. Su objetivo es permitir el uso seguro y conveniente de dispositivos thunderbolt utilizando las características de seguridad de los controladores thunderbolt modernos. Proporciona el nombre org.freedesktop.bolt en el bus del sistema. boltd se inicia automáticamente a través de systemd/udev si se conecta un dispositivo thunderbolt.

La tecnología de E/S thunderbolt funciona interconectando PCIe entre los controladores en cada extremo de la conexión, lo que a su vez significa que los dispositivos conectados a través de Thunderbolt están en última instancia conectados a través de PCIe. Por lo tanto, thunderbolt puede lograr velocidades de conexión muy altas, lo suficientemente rápidas como para incluso controlar tarjetas gráficas externas. La desventaja es que también hace posibles ciertos ataques. Para mitigar estos problemas de seguridad, la última versión — conocida como Thunderbolt 3 — soporta diferentes niveles de seguridad:

none

Sin seguridad. El comportamiento es idéntico al de las versiones anteriores de Thunderbolt.

dponly

No se crean túneles PCIe, pero se permiten y funcionan los túneles DisplayPort.

user

Los dispositivos conectados deben ser autorizados por el usuario. Solo entonces se activarán los túneles PCIe.

secure

Básicamente igual que el modo de usuario, pero además se escribirá una clave en el dispositivo la primera vez que se conecte. Esta clave se utilizará para verificar la identidad del dispositivo conectado.

usbonly

Se crea un túnel PCIe a un controlador USB en una base thunderbolt; no se autorizan otros túneles PCIe descendentes (requiere kernel 4.17 y hardware reciente).

La tarea principal de boltd es autorizar los periféricos thunderbolt si el nivel de seguridad es usuario o seguro. Proporciona una API de D-Bus para listar dispositivos, inscribirlos (autorizar y almacenar en la base de datos local) y eliminarlos de nuevo (eliminar dispositivos previamente inscritos). También emite señales si se conectan (o desconectan) nuevos dispositivos. Durante la inscripción, los dispositivos pueden configurarse para ser autorizados automáticamente tan pronto como se conecten. Una herramienta de línea de comandos, llamada boltctl(1), se puede utilizar para controlar el demonio y realizar todas las tareas mencionadas anteriormente.

La característica de lista de control de acceso previo al arranque (BootACL) está activa cuando el firmware la soporta y cuando boltd se ejecuta en un kernel de Linux suficientemente reciente (>= 4.17). El BootACL es una lista de UUID, que se puede escribir en el controlador thunderbolt. Si está habilitado en la BIOS, todos los dispositivos de esa lista serán autorizados por el firmware durante el pre-arranque, lo que significa que estos dispositivos se pueden usar en la configuración de la BIOS y también durante el arranque temprano de Linux. NB: no se realiza ninguna verificación del dispositivo, incluso cuando el nivel de seguridad se establece en modo secure en la BIOS, es decir, el nivel de seguridad efectivo máximo para los dispositivos en el BootACL es solo user. Si está presente el soporte BootACL, todos los dispositivos nuevos se añadirán automáticamente. Los dispositivos que se eliminan (se quitan de boltd) también se eliminarán del BootACL. Cuando un controlador está fuera de línea, los cambios en el BootACL se escribirán en un registro y se sincronizarán de nuevo cuando el controlador vuelva a estar en línea.

Soporte de IOMMU: si el hardware y el firmware soportan el uso de la unidad de gestión de memoria de entrada/salida (IOMMU) para restringir el acceso directo a memoria a ciertas regiones seguras, boltd detectará esa característica y cambiará su comportamiento: Mientras el soporte de iommu esté activo, como lo indica el atributo sysfs iommu_dma_protection del controlador de dominio, los nuevos dispositivos se inscribirán automáticamente con la política iommu y los dispositivos existentes con la política iommu (o auto) serán autorizados automáticamente por boltd sin ninguna interacción del usuario. Cuando iommu no está activo, los dispositivos que fueron inscritos con la política iommu no se autorizarán automáticamente. El estado del soporte de iommu se puede inspeccionar usando boltctl domains.

OPCIONES

-h, --help

Muestra un breve texto de ayuda y sale.

--version

Muestra el número de versión y sale.

-r, --replace

Reemplaza la instancia de boltd actualmente en ejecución.

--journal

Fuerza el registro en el journal.

-v, --verbose

Muestra la salida de depuración.

ENTORNO

RUNTIME_DIRECTORY

Especifica la ruta donde el demonio almacena datos que solo necesitan existir mientras dure el arranque actual. Se establecerá automáticamente cuando se inicie a través de systemd (>= 240). Si no se establece, la ruta predeterminada para los datos en tiempo de ejecución es /run/boltd.

STATE_DIRECTORY

Especifica la ruta donde el demonio almacena información de dispositivos, incluidas las claves utilizadas para la autorización. Sobrescribe la ruta que se estableció en tiempo de compilación. Se establecerá automáticamente cuando se inicie a través de systemd (>= 240).

BOLT_DBPATH

Igual que STATE_DIRECTORY pero tiene precedencia sobre este, si se establece.

ESTADO DE SALIDA

En caso de éxito se devuelve 0, de lo contrario un código de error distinto de cero.
