NAME

bpftool-map

query and manipulate maps

SYNOPSIS

bpftool [-j|-p] [-f] [-n] map { command | help }
bpftool map show [--bpffs]
bpftool map list [--bpffs]
bpftool map dump { id map_id | pinned file }
bpftool map getnext { id map_id | pinned file } key key
bpftool map lookup { id map_id | pinned file } key key
bpftool map update { id map_id | pinned file } key key value value [ flags map_flags ]
bpftool map delete { id map_id | pinned file } key key
bpftool map create [ map_type ] [ key_size ] [ value_size ] [ max_entries ] [ map_flags ] [ inner_map_fd ]
bpftool map pin { id map_id | offload map_offload } file
bpftool map unpin file
bpftool map freeze { id map_id | pinned file }
bpftool map close { id map_id | pinned file }
bpftool map help

MAP COMMANDS

show
Show all maps.
list
Same as show.
dump
Dump all key/value pairs from a map.
getnext
Get the next key in the map after the given key.
lookup
Lookup value for a given key in a map.
update
Update map value for a given key. If the key does not exist, it is created. Map flags can be specified to control update behavior (e.g., no_create).
delete
Delete a key/value pair from a map.
create
Create a new map. If map_type, key_size, value_size, and max_entries are not specified, defaults will be used. Allowed map types are: hash, array, prog_array, perf_event_array, cgroup_array, fd_array, lru_hash, lru_map, stack_trace, ipck_map, bpf_map_type_hash_header, bpf_map_type_trace_pipe, bpf_map_type_struct_ops, bpf_map_type_ringbuf, bpf_map_type_hash_with_core_reloc, bpf_map_type_map_in_map. Map flags can be specified to control map behavior. inner_map_fd can be specified for map-in-map.
pin
Pin map to a specified file path in BPF filesystem.
unpin
Remove map pin.
freeze
Mark map as read-only.
close
Close map file descriptor.
help
Show help information.

DESCRIPTION

The bpftool is a utility to inspect, load, and manipulate BPF applications. It supports maps, programs, links, BTF, cgroups, perf events, struct_ops, iterators and tracing.

This man page describes the map-related commands of bpftool.

Maps are the primary mechanism for communication between BPF programs and between BPF programs and user-space applications. They can be viewed, created, updated, deleted, and dumped. Maps can also be pinned to BPF filesystem for persistence.

Map keys and values are specified as comma-separated hexadecimal values. For example, a key of length 4 could be specified as 0x01,0x02,0x03,0x04. If the value starts with 0x, it is interpreted as hexadecimal. Otherwise, it is interpreted as decimal. For example, key 1,2,3,4 and key 0x1,0x2,0x3,0x4 are equivalent.

The dump command dumps all key/value pairs from a map. The output format is the same as for the lookup command.

The getnext command returns the key following the given key in the map. This can be used to iterate over map contents.

The lookup command displays the value associated with a given key.

The update command replaces the value for a given key with a new value. If the key does not exist, it is created. The optional flags argument can be used to control the update behavior. For example, the no_create flag will prevent the creation of a new entry if the key does not exist.

The delete command removes a key/value pair from a map.

The create command creates a new map. The map type, key size, value size, and maximum number of entries can be specified. If not specified, defaults will be used. The available map types are listed in the command description. Map flags can also be specified to control map behavior.

The pin command pins a map to a specified file path in the BPF filesystem (e.g., /sys/fs/bpf/). This allows the map to persist even after the last reference to it is released. The map can then be accessed later by referencing the pinned file path.

The unpin command removes the pin from a map.

The freeze command marks a map as read-only. This is useful for maps that are updated during initialization and then should not be modified further.

The close command closes the file descriptor associated with a map.

The help command displays help information for the map commands.

OPTIONS

-V, --version
Print bpftool's version number (similar to bpftool version), the number of the libbpf version in use, and optional features that were included when bpftool was compiled. Optional features include linking against LLVM or libbfd to provide the disassembler for JIT-ted programs (bpftool prog dump jited) and usage of BPF skeletons (some features like bpftool prog profile or showing pids associated to BPF objects may rely on it).
-j, --json
Generate JSON output. For commands that cannot produce JSON, this option has no effect.
-p, --pretty
Generate human-readable JSON output. Implies -j.
-d, --debug
Print all logs available, even debug-level information. This includes logs from libbpf as well as from the verifier, when attempting to load programs.
-f, --bpffs
Show file names of pinned maps.
-n, --nomount
Do not automatically attempt to mount any virtual file system (such as tracefs or BPF virtual file system) when necessary.

Note that map update can also be used in order to change the program references hold by a program array map. This can be used, for example, to change the programs used for tail-call jumps at runtime, without having to reload the entry-point program. Below is an example for this use case: we load a program defining a prog array map, and with a main function that contains a tail call to other programs that can be used either to "process" packets or to "debug" processing. Note that the prog array map MUST be pinned into the BPF virtual file system for the map update to work successfully, as kernel flushes prog array maps when they have no more references from user space (and the update would be lost as soon as bpftool exits).
