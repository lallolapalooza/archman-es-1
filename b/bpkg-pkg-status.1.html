DESCRIPCIÓ

N

El comando pkg-status imprime el estado de los paquetes especificados o, si se especifica ver, las versiones de los paquetes. Si no se especificaron paquetes, entonces pkg-status imprime el estado de todos los paquetes retenidos (que son los paquetes que fueron construidos explícitamente; véase bpkg-pkg-build(1)). Este último modo puede modificarse para imprimir el estado de todos los paquetes especificando la opción --all|-a. Adicionalmente, el estado de las dependencias inmediatas o de todos los paquetes anteriores puede imprimirse especificando las opciones --immediate|-i o --recursive|-r, respectivamente. Nótese que el estado se escribe en stdout, no en stderr

.

El formato de salida predeterminado (véase la opción común --stdout-format) es regular con componentes separados por espacios. Cada línea comienza con el nombre del paquete seguido de una de las palabras de estado listadas a continuación. Algunas de ellas pueden ser seguidas opcionalmente por ',' (sin espacios) y una palabra de sub-estado. Las líneas correspondientes a dependencias de configuraciones vinculadas mencionarán adicionalmente el directorio de la configuración entre corchetes después del nombre del

paquete.
unkno
wn

El paquete no forma parte de la configuración ni está disponible en ninguno de los
repositorios.
availab
le

El paquete no forma parte de la configuración pero está disponible en uno de los
repositorios.
fetch
ed

El paquete forma parte de la configuración y ha sido
descargado.
unpack
ed

El paquete forma parte de la configuración y ha sido
desempaquetado.
configur
ed

El paquete forma parte de la configuración y ha sido configurado. Puede ser seguido por el sub-estado system que indica un paquete proveniente del sistema. La versión de dicho paquete del sistema (descrita más adelante) puede ser el valor especial '*' que indica una versión
comodín.
brok
en

El paquete forma parte de la configuración y está roto (los paquetes rotos solo pueden ser purgados; véase bpkg-pkg-p
urge
(1)).

Si solo se especificó el nombre del paquete sin la versión del paquete, entonces la palabra de estado available es seguida por la lista de versiones disponibles. Las versiones que solo están disponibles para actualizar o degradar se imprimen en '[]' (dichas versiones solo están disponibles como dependencias de repositorios previos de otros repositorios). Si se especifica la opción --system, entonces la última versión en esta lista puede tener el prefijo sys: que indica una versión del sistema disponible. Dicha versión del sistema puede ser el valor especial '?' que indica que un paquete puede o no estar disponible desde el sistema y que su versión es

desconocida.

Las palabras de estado fetched, unpacked, configured y broken son seguidas por la versión del paquete. Si se especificó la versión del paquete, entonces la palabra de estado unknown también es seguida por la

versión.

Si el estado es fetched, unpacked, configured o broken y hay versiones más nuevas disponibles, entonces la versión del paquete es seguida por la palabra de estado available y la lista de versiones más nuevas. Para ver en su lugar una lista de todas las versiones, incluyendo las más antiguas, especifique la opción --old-available|-o. En este caso, la versión actualmente seleccionada se imprime en '()'

.

Si se especificó el nombre del paquete con la versión, entonces solo se considera el estado (como configured, available, etc.) de esta

versión.

Si un paquete está retenido, entonces su nombre se imprime con el prefijo '!'. De manera similar, si una versión de paquete está retenida, entonces la versión se imprime con el prefijo '!'. Los paquetes retenidos y las versiones retenidas fueron seleccionadas por el usuario y no se eliminan ni se actualizan automáticamente, respectivamente

.

A continuación se muestran algunos ejemplos, asumiendo que la configuración tiene libfoo 1.0.0 configurado y retenido (tanto el paquete como la versión), así como libfoo 1.1.0 y 1.1.1 disponibles desde la fuente y 1.1.0 desde el

sistema. 
bpkg status libbar
libbar unknown
bpkg status libbar/1.0.0
libbar unknown 1.0.0
bpkg status libfoo/1.0.0
!libfoo configured !1.0.0
bpkg status libfoo/1.1.0
libfoo available 1.1.0
bpkg status --system libfoo/1.1.0
libfoo available 1.1.0 sys:1.1.0
bpkg status libfoo
!libfoo configured !1.0.0 available 1.1.0 1.1.1
bpkg status libfoo/1.1.1 libbar
libfoo available 1.1.1
libbar
unknown

Asumiendo ahora que eliminamos libfoo de la

configuración: 
bpkg status libfoo/1.0.0
libfoo unknown 1.0.0
bpkg status libfoo
libfoo available 1.1.0 1.1.
1

Y asumiendo ahora que construimos libfoo como un paquete del sistema con la versión

comodín: 
bpkg status libfoo
!libfoo configured,system !* available 1.1.0 1.1.
1

Otro ejemplo de la salida del estado esta vez incluyendo

dependencias: 
bpkg status -r libbaz
!libbaz configured 1.0.0
  libfoo configured 1.0.0
    bison [.bpkg/host/] configured 1.0.0
  libbar configured 2.0.
0

Si el formato de salida es json, entonces la salida es un array JSON de objetos que son la representación serializada del siguiente struct de C++ package_

status: 
struct available_version
{
  string version;
  bool   system;
  bool   dependency;
};
struct package_status
{
  string                    name;
  optional<string>          configuration;
  optional<string>          constraint;
  string                    status;
  optional<string>          sub_status;
  optional<string>          version;
  bool                      hold_package;
  bool                      hold_version;
  vector<available_version> available_versions;
  vector<package_status>    dependencies;
}
;

Por

ejemplo: 
[
  {
    "name": "hello",
    "status": "configured",
    "version": "1.0.0",
    "hold_package": true,
    "available_versions": [
      {
        "version": "1.0.1"
      },
      {
        "version": "2.0.0"
      }

      {
        "name": "libhello",

Véase la sección SALIDA JSON en bpkg-common-options(1) para detalles sobre las propiedades generales de este formato y la semántica de la serialización del

struct.

En package_status, el miembro configuration contiene el directorio absoluto de una configuración vinculada si este paquete reside en una configuración vinculada. El miembro constraint está presente solo si se especifica la opción --constraint. El miembro version está ausente si el miembro status es unknown o available y no se especifica una versión del paquete en la línea de comandos. Si el miembro sub_status es system, entonces el miembro version puede ser el especial *. El miembro dependencies está presente solo si se especifican las opciones --immediate|-i o --recursive|-r

.

En available_version, si el miembro system es true, entonces esta versión está disponible desde el sistema, en cuyo caso el miembro version puede ser el especial ? o *. Si el miembro dependency es true, entonces esta versión solo está disponible como de

pendencia de repositorios pr
evios de otros repositorios.
