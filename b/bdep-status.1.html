NOMBRE

bdep-status - imprimir el estado del proyecto y/o de sus dependencias

SINOPSIS

bdep status [opciones] [pkg-spec] [cfg-spec] [dep-spec...]

dep-spec = pkg[/ver]
cfg-spec = (@cfg-name | --config|-c cfg-dir)... | --all|-a
pkg-spec = (--directory|-d pkg-dir)... | prj-spec
prj-spec = --directory|-d prj-dir

DESCRIPCIÓN

El comando status imprime el estado de los paquetes del proyecto y/o de sus dependencias en una o más configuraciones de compilación.

Si no se especifica un directorio de proyecto o de paquete, se asume el directorio de trabajo actual. Si no se especifica una configuración, se asumen las configuraciones predeterminadas. Véase bdep-projects-configs(1) para detalles sobre cómo especificar proyectos y configuraciones.

Si no se especifican argumentos dep-spec , entonces status imprime el estado de los paquetes del proyecto. De lo contrario, se imprime el estado de los paquetes de dependencia especificados. Además, se puede imprimir el estado de las dependencias inmediatas o de todas las dependencias de los paquetes anteriores especificando las opciones --immediate|-i o --recursive|-r , respectivamente.

En el formato de salida predeterminado (véase la opción común --stdout-format ), el estado de cada paquete se imprime en una línea separada. Nótese que el estado se escribe en stdout, no en stderr. La semántica de dep-spec y el formato de la línea de estado se describen en bpkg-pkg-status(1).

Si el formato de salida es json, entonces la salida es un array JSON de objetos que son la representación serializada de la siguiente estructura C++ struct configuration_package_status:

struct configuration
{
  uint64_t         id;
  string           path;
  optional<string> name;
};
struct configuration_package_status
{
  configuration          configuration;
  vector<package_status> packages;
};

Por ejemplo:

[
  {
    "configuration": {
      "id": 1,
      "path": "/tmp/hello-gcc",
      "name": "gcc"
    },
    "packages": [
      {
        "name": "hello",
        "status": "configured",
        "version": "1.0.0",
        "hold_package": true,
        "available_versions": [
          {
            "version": "1.0.1"
          },
          {
            "version": "2.0.0"
          }
        ],
        "dependencies": [
          {
            "name": "libhello",
            "status": "configured",
            "version": "1.0.2"
          }
        ]
      }
    ]
  }
]

Véase la sección SALIDA JSON en bdep-common-options(1) para detalles sobre las propiedades generales de este formato y la semántica de la serialización de la struct .

Refiérase al subcomando list de bdep-config(1) para detalles sobre los miembros de la struct configuration . Refiérase a bpkg-pkg-status(1) para la definición de la structpackage_status . Nótese también que en el formato de salida json ciertas condiciones (no hay configuraciones asociadas, no hay paquetes inicializados, etc.) no se tratan como errores, sino que resultan en una salida válida. Los paquetes no inicializados tienen el valor de estado especial uninitialized .

OPCIONES DE ESTADO

--immediate|-i
Imprimir también el estado de las dependencias inmediatas.
--recursive|-r
Imprimir también el estado de todas las dependencias, recursivamente.
--old-available|-o
Imprimir versiones antiguas disponibles.
--fetch|-f
Realizar el comando fetch antes de imprimir el estado.
--fetch-full|-F
Realizar el comando fetch --full antes de imprimir el estado.
--all|-a
Usar todas las configuraciones de compilación.
--config|-c dir
Especificar la configuración de compilación como un directorio.
--directory|-d dir
Asumir que el proyecto/paquete está en el directorio especificado en lugar de en el directorio de trabajo actual.
--config-name|-n name
Especificar la configuración de compilación como un nombre.
--config-id num
Especificar la configuración de compilación como un id.

OPCIONES COMUNES

Las opciones comunes se resumen a continuación, estando disponible una descripción más detallada en bdep-common-options(1).

-v
Imprimir los comandos subyacentes esenciales que se están ejecutando.
-V
Imprimir todos los comandos subyacentes que se están ejecutando.
--quiet|-q
Ejecutar en silencio, imprimiendo solo mensajes de error.
--verbose level
Establecer la verbosidad del diagnóstico a level entre 0 y 6.
--stdout-format format
Formato de representación a usar para imprimir en stdout.
--jobs|-j num
Número de trabajos a realizar en paralelo.
--progress
Mostrar indicadores de progreso para operaciones de larga duración, como transferencias de red, compilación, etc.
--no-progress
Suprimir los indicadores de progreso para operaciones de larga duración, como transferencias de red, compilación, etc.
--diag-color
Usar color en los diagnósticos.
--no-diag-color
No usar color en los diagnósticos.
--bpkg path
El programa gestor de paquetes a usar para la gestión de la configuración de compilación.
--bpkg-option opt
Opción adicional a pasar al programa gestor de paquetes.
--build path
El programa de compilación a usar para compilar paquetes.
--build-option opt
Opción adicional a pasar al programa de compilación.
--curl path
El programa curl a usar para operaciones de red.
--curl-option opt
Opción adicional a pasar al programa curl.
--pager path
El programa paginador a usar para mostrar texto largo.
--pager-option opt
Opción adicional a pasar al programa paginador.
--options-file file
Leer opciones adicionales de file.
--default-options dir
El directorio desde el cual cargar archivos de opciones predeterminadas adicionales.
--no-default-options
No cargar los archivos de opciones predeterminadas.

ARCHIVOS DE OPCIONES PREDETERMINADAS

Ver bdep-default-options-files(1) para una descripción general de los archivos de opciones predeterminadas. Para el comando status el directorio de inicio de búsqueda es el directorio del proyecto. Se buscan los siguientes archivos de opciones en cada directorio y, si se encuentran, se cargan en el orden indicado:

bdep.options
bdep-status.options

Las siguientes opciones del comando status no se pueden especificar en los archivos de opciones predeterminadas:

--directory|-d

ERRORES

Envíe los informes de errores a la lista de correo users@build2.org.
