SINOPSI

S

Poner datos en un repositorio

bupstash.

bupstash put [OPCIONES] [TAG=VAL...] [::] RUTAS...
bupstash put --exec [OPCIONES] [TAG=VAL...] [::] COMANDO

DESCRIPCIÓ

N

bupstash put cifra archivos, directorios o la salida de un comando y los almacena en un repositorio bupstash de tal manera que solo la clave de descifrado puede

descifrarlos.

Para archivos individuales, el contenido se guarda directamente; para múltiples archivos, los datos se guardan de forma que puedan recuperarse como un archivo tar, y para comandos, el comando se ejecuta y stdout se envía al

repositorio.

Los datos almacenados en un repositorio bupstash se deduplican automáticamente de modo que instantáneas idénticas o similares ocupen el mínimo espacio adicional en disco. Para una operación incremental eficiente, use la opción --send-log descrita en la sección de notas de

uso.

Todas las inserciones pueden asociarse a un conjunto de etiquetas de metadatos cifrados arbitrarios, que se pueden consultar usando bupstash-list(1). Las etiquetas se especifican en un formato simple CLAVE=VALOR en la línea de comandos. Las claves de etiqueta válidas deben coincidir con la expresión regular ^([a-zA-Z0-9\\-_]+)=(.+)$, lo que significa que las claves de etiqueta deben ser alfanuméricas con la adición de - y _. El procesamiento de etiquetas termina en el primer argumento que no coincide con el

patrón.

El argumento marcador especial :: puede usarse para forzar el fin del análisis de etiquetas, pero generalmente no es

necesario.

Tenga en cuenta que múltiples cargas simultáneas al mismo repositorio son seguras y están soportadas siempre que todos los clientes accedan al repositorio desde el mismo servidor y por lo tanto respeten los bloqueos de archivos del repositorio. Algunos sistemas de archivos de red (como NFS y sshfs) no siempre respetan los bloqueos de archivos remotos y por lo tanto no están soportados. Siempre prefiera conectarse a un repositorio remoto a través de una URL con estilo ssh:// o una instancia de bupstash

s
erve.

NOTAS DE

USO

Inserción

incremental

Al enviar datos, bupstash registra metadatos sobre lo que se envió en la operación anterior de ´put´ en un archivo conocido como el log de

envío.

El log de envío sirve para dos propósitos

principales:
○
recuerda los identificadores de los fragmentos de datos que se enviaron al repositorio en el último ´put´, permitiendo a bupstash evitar reenviar esos fragmentos por la red
repetidamente.
○
Almacena un mapeo de rutas de archivo a datos que ya han sido enviados, permitiendo a bupstash omitir el procesamiento de archivos al crear instantáneas del mismo directorio muchas veces
repetidamente.

El log de envío solo recuerda los datos enviados previamente, así que para un uso eficiente de ´put´, dé a cada tarea de respaldo un archivo de log de envío único. Como ejemplo, si tiene un script de respaldo que guarda un directorio como una tarea cron, es mejor darle a ese script su propio log de envío para que todas las ejecuciones posteriores con datos de entrada similares compartan el mismo log de

envío.

Ejemplo

:

$ bupstash put --send-log /root/bupstash-backups.sendlog /home/ #

El segundo respaldo es incremental y rápido porque usa el log de enví
o. $ bupstash put --send-log /root/bupstash-backups.sendlog /home/

Modificación concurrente del sistema de

archivos

Bupstash soporta la carga de un sistema de archivos que está siendo modificado concurrentemente con la advertencia de que bupstash no puede garantizar que el sistema de archivos esté en un estado consistente. Si bupstash está leyendo un archivo o directorio mientras es modificado concurrentemente por una aplicación, puede ocurrir que la instantánea de bupstash contenga datos de múltiples puntos en el tiempo con la combinación potencialmente siendo inválida y/o

corrupta.

La única forma segura de asegurar la consistencia de los datos es usar un sistema de archivos con capacidades de instantánea. Usando instantáneas de sistema de archivos puede crear una vista consistente del sistema de archivos y luego realizar un respaldo de bupstash sobre esa instantánea. En Linux algunas opciones para realizar instantáneas consistentes incluyen ZFS, BTRFS y también instantáneas

LVM

Otra opción es realizar una operación de inserción en un momento en que los

archivos sean menos propensos a ser modificados, esto proporcionará respaldos
suficientemente buenos para muchas personas sin complicaciones adicionales.

NAME

bupstash-put - create snapshots of files and directories

SYNOPSIS

bupstash put [OPTION...] PATH...

DESCRIPTION

The bupstash put command saves files and directories into a bupstash repository. It handles deduplication of repeated files and can work with remote repositories over ssh. This command will typically be used to create new backups or to add new data to an existing backup.

USAGE NOTES

This command snapshots the provided PATHs and saves them to the repository. The bupstash put command is designed to be able to snapshot a directory structure, just like a traditional tar command, but with deduplication.

When snapshotting directories, the command will traverse the directory and hash every file it finds. If a file is found that already exists in the repository, then the existing file blob will be reused. This allows for efficient incremental backups.

The command returns a unique snapshot ID, which can be used to refer to the snapshot in other bupstash commands.

OPTIONS

--cachedir PATH
Use PATH as the directory for cache files. Defaults to $XDG_CACHE_HOME/.cache/bupstash or $HOME/.cache/bupstash.
--exclude FILENAME
Exclude a directory´s content if it contains a file with the given name. May be passed multiple times. This will still backup the folder itself, containing the marker file. Common marker file names are CACHEDIR.TAG, .backupexclude or .no-backup.
--send-log PATH
Path to the send log file, defaults to one of the following, in order, provided the appropriate environment variables are set, $BUPSTASH_SEND_LOG, $XDG_CACHE_HOME/.cache/bupstash/bupstash.sendlog or $HOME/.cache/bupstash/bupstash.sendlog.
--no-send-log
Disable use of a send log, all data will be written over the network. Implies --no-stat-caching.
--no-stat-caching
Do not use stat caching to skip sending files to the repository.
--no-default-tags
Do no set default tags.
--compression ALGO
Compression algorithm, one of ´none´, ´lz4´ or ´zstd[:$level]´. Defaults to ´zstd:3´.
--ignore-permission-errors
Ignore permission denied errors, skipping those files or directories.
--one-file-system
Do not traverse mount points in the file system.
--xattrs
Save directory entry xattrs, only used when saving a directory.
--print-file-actions
Print file actions in the form ´$a $t $path´ to stderr when processing directories, see the section ´File Actions´ for details.
--print-stats
Print put statistics to stderr on completion.
--indexer-threads N
Number of processor threads to use for pipelined parallel file metadata reads. Defaults to 1.
--threads N
Number of processor threads to use for pipelined parallel reading, hashing, compression and encryption. Defaults to the number of processors.
--no-progress
Suppress progress indicators (Progress indicators are also suppressed when stderr is not an interactive terminal).
-q, --quiet
Be quiet, implies --no-progress.
-v, --verbose
Be verbose, implies --print-file-actions and --print-stats.

ENVIRONMENT

BUPSTASH_REPOSITORY
The repository to connect to. May be of the form ssh://$SERVER/$PATH for remote repositories if ssh access is configured.
BUPSTASH_REPOSITORY_COMMAND
A command to run to connect to an instance of bupstash-serve(1). This allows more complex connections to the repository for less common use cases.
BUPSTASH_KEY
Path to the key that will be used to encrypt the data. Only the associated primary key will be able to decrypt the data once sent.
BUPSTASH_KEY_COMMAND
A command to run that must print the key data, can be used instead of BUPSTASH_KEY to fetch the key from arbitrary locations such as the network or other secret storage.
BUPSTASH_SEND_LOG
Path to the send log, overridden by --send-log. See the section ´Incremental backups´ for a description of how to use send logging for efficient incremental uploads.
BUPSTASH_CHECKPOINT_SECONDS
When send logging is enabled, bupstash will checkpoint approximately every BUPSTASH_CHECKPOINT_SECONDS. If an upload is interrupted after a successful checkpoint, data will not need to be resent over the network. The default value of this option is 600, which is 10 minutes.

EXAMPLES

Snapshot a directory

The builtin directory put creates a tarball from a directory, while deduplicating repeated files.

# Snapshot a directory. $ ID="$(bupstash put ./data)" # List snapshot contents. $ bupstash list-contents id="$ID" # Fetch the snapshot. $ bupstash get id="$ID" | tar -xf -

Save files or directory to a repository over ssh

``` export BUPSTASH_KEY="/backups/backups-secret.key" export BUPSTASH_REPOSITORY="ssh://$SERVER/home/me/bupstash-repository"

$ bupstash put ./data.file $ bupstash put ./directory $ bupstash put ./multiple-files.txt ./directory

```

Snapshot the output of a command

# Snapshot a postgres database with pgdump $ bupstash put --exec name=dbdump.sql pgdump mydb

Connecting to an ssh server with a specific ssh config.

$ export BUPSTASH_REPOSITORY_COMMAND="ssh -F ./my-ssh-config me@$SERVER bupstash serve /my/repo" $ bupstash put ./files
