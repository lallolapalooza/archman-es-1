Paquete: borg

BORG-BENCHMARK-CRUD(1) Herramienta de borg backup BORG-BENCHMARK-CRUD(1)

NOMBRE

borg-benchmark-crud - Evalúa el rendimiento de las operaciones CRUD (crear, leer, actualizar, eliminar) para archivos.

SINOPSIS

borg [opciones comunes] benchmark crud [opciones] REPOSITORIO RUTA

DESCRIPCIÓN

Este comando evalúa el rendimiento de las operaciones CRUD de borg (crear, leer, actualizar, eliminar).

Crea datos de entrada en la RUTA especificada y realiza una copia de seguridad de estos datos en el REPOSITORIO dado. El REPOSITORIO debe existir previamente (podría ser un repositorio nuevo y vacío o uno existente; el comando creará / leerá / actualizará / eliminará algunos archivos denominados borg-benchmark-crud* allí.

Asegúrate de tener espacio libre allí, necesitarás aproximadamente 1 GB cada uno (+ sobrecarga).

Si tu repositorio está cifrado y borg necesita una contraseña para desbloquear la clave, usa:

BORG_PASSPHRASE=micontraseña borg benchmark crud REPOSITORIO RUTA

Las mediciones se realizan con diferentes tamaños y recuentos de archivos de entrada. Los contenidos de los archivos son muy artificiales (todos ceros o todos aleatorios), por lo tanto, los resultados de la medición no reflejan necesariamente el rendimiento con datos reales. Además, debido al tipo de contenido utilizado, no se utiliza compresión en estas pruebas de rendimiento.

C- == borg create (1ª creación de archivo, sin compresión, no usar caché de archivos)
C-Z- == archivos todos ceros. deduplicación completa; esto mide principalmente el lector/chunker/hasher. C-R- == archivos aleatorios. sin deduplicación, mide el rendimiento a través de todas las etapas de procesamiento.
R- == borg extract (extraer archivo, simulación, hacer todo, pero no escribir archivos en disco)
R-Z- == archivos todos ceros. Mide archivos altamente duplicados. R-R- == archivos aleatorios. Sin duplicación aquí, mide el rendimiento a través de todas las etapas de procesamiento, excepto la escritura en disco.
U- == borg create (2ª creación de archivo de archivos de entrada sin cambios, mide la velocidad de la caché de archivos)
El valor de rendimiento es, en cierto modo, virtual aquí, no lee el archivo realmente. U-Z- == necesita comprobar la existencia de los dos chunks de cero en el repositorio. U-R- == necesita comprobar la existencia de muchos chunks diferentes en el repositorio.
D- == borg delete archivo (eliminar el último archivo restante, mide la eliminación + compactación)
D-Z- == pocos chunks para eliminar / pocos segmentos para compactar/eliminar. D-R- == muchos chunks para eliminar / muchos segmentos para compactar/eliminar.

Ten en cuenta que puede haber bastante variación en estas mediciones. Intenta realizar varias mediciones y utiliza una máquina (y red, si la usas) que esté libre de otras cargas.

OPCIONES

Consulta borg-common(1) para ver las opciones comunes de los comandos de Borg.

argumentos

REPOSITORIO
repositorio a utilizar para la prueba de rendimiento (debe existir)
RUTA
ruta donde crear los datos de entrada para la prueba de rendimiento
