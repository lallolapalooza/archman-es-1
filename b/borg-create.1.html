Paquete: borg

Licencias: BSD

BORG-CREATE(1) borg backup tool BORG-CREATE(1)

NOMBRE

borg-create - Crear un nuevo archivo

SINOPSIS

borg [opciones comunes] create [opciones] ARCHIVO [RUTA...]

DESCRIPCIÓN

Este comando crea un archivo de respaldo que contiene todos los archivos encontrados al recorrer recursivamente todas las rutas especificadas. Las rutas se añaden al archivo tal como se proporcionan, lo que significa que si se desean rutas relativas, el comando debe ejecutarse desde el directorio correcto.

El hack de slashdot en las rutas (raíces de recursión) se activa usando /./: /esto/se/elimina/./esto/se/archiva significa procesar ese objeto del sistema de archivos, pero eliminar el prefijo del lado izquierdo de ./ de los elementos archivados (en este caso, esto/se/archiva será la ruta en el elemento archivado).

Cuando se proporciona '-' como ruta, Borg leerá datos de la entrada estándar y creará un archivo llamado 'stdin' en el archivo creado a partir de esos datos. En algunos casos, es más apropiado usar --content-from-command. Consulte la sección "Lectura desde stdin" a continuación para obtener más detalles.

El archivo consumirá casi nada de espacio en disco para archivos o partes de archivos que ya se han almacenado en otros archivos.

El nombre del archivo debe ser único. No debe terminar en '.checkpoint' o '.checkpoint.N' (con N siendo un número), ya que estos nombres se utilizan para puntos de control y se tratan de forma especial.

En el nombre del archivo, puede usar los siguientes marcadores de posición: {now}, {utcnow}, {fqdn}, {hostname}, {user} y algunos otros.

La velocidad de respaldo aumenta al no reprocesar archivos que ya forman parte de archivos existentes y que no han sido modificados. La detección de archivos no modificados se realiza comparando varios valores de metadatos de archivo con valores anteriores guardados en la caché de archivos.

Esta comparación puede operar en diferentes modos según lo dado por --files-cache:

  • ctime,size,inode (por defecto)
  • mtime,size,inode (comportamiento por defecto de las versiones de borg anteriores a 1.1.0rc4)
  • ctime,size (ignora el número de inodo)
  • mtime,size (ignora el número de inodo)
  • rechunk,ctime (todos los archivos se consideran modificados - rechunk, caché ctime)
  • rechunk,mtime (todos los archivos se consideran modificados - rechunk, caché mtime)
  • disabled (desactiva la caché de archivos, todos los archivos se consideran modificados - rechunk)

número de inodo: mejor seguridad, pero a menudo inestable en sistemas de archivos de red

Normalmente, la detección de modificaciones de archivos tendrá en cuenta la información del inodo para mejorar la fiabilidad de la detección de cambios en los archivos. Esto es problemático para los archivos ubicados en SSHFS y sistemas de archivos de red similares que no proporcionan números de inodo estables; dichos archivos siempre se considerarán modificados. Puede usar modos sin inode en este caso para mejorar el rendimiento, pero la fiabilidad de la detección de cambios podría reducirse.

ctime vs. mtime: seguridad vs. velocidad

  • ctime es una forma bastante segura de detectar cambios en un archivo (metadatos y contenido) ya que no puede ser establecido desde el espacio de usuario. Sin embargo, un cambio solo de metadatos ya actualizará el ctime, por lo que puede haber algún re-chunking/hashing innecesario incluso sin cambios de contenido. Algunos sistemas de archivos no admiten ctime (tiempo de cambio). Por ejemplo, realizar un chown o chmod a un archivo cambiará su ctime.
  • mtime generalmente funciona y solo se actualiza si el contenido del archivo cambió. Pero mtime puede ser establecido arbitrariamente desde el espacio de usuario, por ejemplo, para establecer mtime de nuevo al mismo valor que tenía antes de que ocurriera un cambio de contenido. Esto puede ser usado maliciosamente así como bien intencionado, pero en ambos casos los modos de caché basados en mtime pueden ser problemáticos.

La opción --files-changed controla cómo Borg detecta si un archivo ha cambiado durante la copia de seguridad:

  • ctime (por defecto): Usa ctime para detectar cambios. Esta es la opción más segura.
  • mtime: Usa mtime para detectar cambios.
  • disabled: Desactiva completamente la detección de "el archivo ha cambiado mientras lo respaldábamos". Esto no se recomienda a menos que sepa lo que está haciendo, ya que podría provocar copias de seguridad inconsistentes si los archivos cambian durante el proceso de copia de seguridad.

Los puntos de montaje de los sistemas de archivos o las instantáneas del sistema de archivos deben ser los mismos para cada creación de un nuevo archivo para garantizar un funcionamiento rápido. Esto se debe a que la caché de archivos que se utiliza para determinar los archivos modificados rápidamente utiliza nombres de archivo absolutos. Si esto no es posible, considere crear un montaje bind a una ubicación estable.

La opción --progress muestra (de izquierda a derecha) Original, Comprimido y Deducplicado (O, C y D, respectivamente), luego el número de archivos (N) procesados hasta el momento, seguido de la ruta que se está procesando actualmente.

Cuando use --stats, obtendrá algunas estadísticas sobre cuántos datos se agregaron - el tamaño deducplicado "Este Archivo" allí es el más interesante, ya que es cuánto crecerá su repositorio. Tenga en cuenta que las estadísticas "Todos los archivos" se refieren al estado después de la creación. Además, las opciones --stats y --dry-run son mutuamente excluyentes porque los datos no se comprimen ni se deduplicican realmente durante una ejecución de prueba.

Para obtener más ayuda sobre los patrones de inclusión/exclusión, consulte la salida del comando borg_patterns.

Para obtener más ayuda sobre los marcadores de posición, consulte la salida del comando borg_placeholders.

LECTURA DESDE STDIN

Si proporciona '-' como una de las rutas a archivar, Borg leerá el contenido del archivo desde la entrada estándar y creará un archivo llamado 'stdin' en el archivo de respaldo. Esto es útil para canalizar la salida de otros programas a Borg.

Por ejemplo, para archivar el resultado de un comando:

$ comando | borg create /ruta/al/repositorio::mi-archivo -

En este caso, el archivo 'stdin' se creará dentro del archivo 'mi-archivo'. Borg intentará deducir el tipo de archivo y los metadatos de la entrada estándar.

Si desea más control sobre el nombre del archivo creado a partir de stdin, el propietario, el grupo o los permisos, puede usar las opciones --stdin-name, --stdin-user, --stdin-group y --stdin-mode.

Para archivar la salida de un comando como si fuera una lista de rutas de archivos, use --paths-from-command en lugar de '-' como ruta. Por ejemplo, para archivar todos los archivos de texto en el directorio actual:

$ find . -name '*.txt' | borg create /ruta/al/repositorio::mi-archivo --paths-from-command

Por defecto, las rutas se separan por saltos de línea. Puede especificar un delimitador diferente con --paths-delimiter.

Si desea archivar el contenido de stdin como un archivo llamado 'stdin' en el repositorio, pero no desea que Borg intente adivinar los metadatos (por ejemplo, si está canalizando un archivo binario y desea mantener sus metadatos originales), puede usar la opción --content-from-command.

$ borg create --content-from-command /ruta/al/repositorio::mi-archivo /ruta/al/archivo

En este caso, Borg tratará la ruta proporcionada como un archivo y leerá su contenido. Si la ruta es '-' (stdin), entonces Borg leerá desde stdin y creará un archivo llamado 'stdin' en el repositorio. Esto es útil si desea archivar la salida de un comando como un archivo en el repositorio, pero desea que Borg maneje la lectura de la entrada estándar.

EJEMPLOS

Crear un archivo de respaldo llamado "backup-2023-10-27_10:00:00"
del directorio "/home/user/documents" en el repositorio
"/mnt/backup/repository":

    --stdin-user root --stdin-group root --stdin-mode 0644 \
    /mnt/backup/repository::log-archive

NOTA

S

Los patrones --exclude no son como en tar. En tar --exclude .bundler/gems excluiría foo/.bundler/gems. En borg no lo hará, necesita usar --exclude '*/.bundler/gems' para obtener el mismo

efecto.

Además de usar patrones --exclude, es posible usar --exclude-if-present para especificar el nombre de un objeto del sistema de archivos (por ejemplo, un nombre de archivo o carpeta) que, al estar contenido dentro de otra carpeta, evitará que la carpeta contenedora sea respaldada. Por omisión, la carpeta contenedora y todo su contenido se omitirán de la copia de seguridad. Sin embargo, si desea incluir solo los objetos especificados por --exclude-if-present en su copia de seguridad, y no incluir ningún otro contenido de la carpeta contenedora, esto se puede habilitar usando la opción --keep-exclude-tags

.

La opción -x o --one-file-system excluye directorios que son puntos de montaje (y todo lo que hay en ellos). Detecta puntos de montaje comparando el número de dispositivo de la salida de stat() del directorio y de su directorio padre. Específicamente, excluye directorios para los cuales stat() reporta un número de dispositivo diferente del número de dispositivo de su padre. En general: tenga en cuenta que hay directorios con números de dispositivo diferentes a los de su padre que el kernel no considera puntos de montaje, y viceversa. Ejemplos en Linux de esto son los montajes bind (posiblemente el mismo número de dispositivo, pero siempre un punto de montaje) y todos los subvolúmenes de un sistema de archivos Btrfs (números de dispositivo diferentes al del padre pero no necesariamente puntos de montaje). Ejemplos en macOS son los montajes APFS de una instalación típica de macOS. Por lo tanto, al usar --one-file-system, debería verificar dos veces que la copia de seguridad funciona como se

pretendía.

SINOPSIS

borg create [OPTIONS] REPO::ARCHIVE [PATH...]

borg create [OPTIONS] REPO::ARCHIVE --paths-from-stdin

borg create [OPTIONS] REPO::ARCHIVE --paths-from-command CMD [ARGS...]

borg create [OPTIONS] REPO::ARCHIVE --content-from-command CMD [ARGS...]

DESCRIPCIÓN

Crea un nuevo archivo (archivo) en el repositorio REPO con el nombre ARCHIVE. Copia los archivos en PATH (y recursivamente sus subdirectorios) a ARCHIVE. Si no se especifican PATHs, borg intentará leer los elementos de entrada del estándar de entrada, ver Lectura de datos de copia de seguridad desde stdin.

Borg hace todo lo posible para hacer que las copias de seguridad sean eficientes. Esto incluye el uso de deduplicación de datos (solo se almacenan bloques de datos únicos), compresión y almacenamiento de metadatos de archivos de manera eficiente. Borg también intenta usar información de archivos existentes en el repositorio para evitar la relectura de datos que ya están allí.

El valor de la opción --files-cache puede influir en cómo se gestionan los datos y los metadatos. La configuración predeterminada es --files-cache = mtime.

OPCIONES

Las opciones generales que se aplican a todos los mandatos de borg se describen en borg-common(1).

Las opciones específicas del mandato create son:

--files-cache MODE
El modo de la caché de archivos. Los modos disponibles son:
  • disabled: no se usa la caché de archivos. Esto puede acelerar las copias de seguridad, pero impide la deduplicación.
  • metadata: la caché solo almacena metadatos de archivos existentes. Esto es útil para la deduplicación de metadatos y para detectar cambios en los metadatos.
  • mtime: la caché almacena metadatos de archivos y tiempos de modificación. Esta es la configuración predeterminada y proporciona un buen equilibrio entre rendimiento y deduplicación.
  • inode: la caché almacena metadatos de archivos, tiempos de modificación y números de inodo. Esto puede ser útil en sistemas de archivos que no son compatibles con mtime de forma fiable o para detectar cambios más precisos.
--chunks-cache-type TYPE
Tipo de caché de bloques utilizada para almacenar bloques de datos en el repositorio. Los tipos disponibles son:
  • btrfs: utiliza la funcionalidad de deduplicación de COW de Btrfs. Esto solo funcionará si el repositorio está en un sistema de archivos Btrfs.
  • reflink: utiliza la funcionalidad reflink de sistemas de archivos compatibles (como ext4 o XFS).
  • hardlink: utiliza hardlinks para la deduplicación. Esto solo funcionará si el repositorio está en un sistema de archivos compatible con hardlinks.
  • copy: copia todos los bloques de datos al repositorio. Esta es la configuración predeterminada.
--content-from-command
Ejecuta el comando especificado y envía su salida estándar a borg. Borg fallará si el comando falla (devuelve un código de salida distinto de cero). Esto es útil para crear copias de seguridad de datos generados dinámicamente o de fuentes que no son archivos normales.
--paths-from-command
Ejecuta el comando especificado y trata su salida estándar como una lista de rutas de archivos a incluir en la copia de seguridad. Borg fallará si el comando falla (devuelve un código de salida distinto de cero).
--paths-from-stdin
Lee una lista de rutas de archivos del estándar de entrada y las incluye en la copia de seguridad. Cada ruta debe estar en una línea separada.
--stdin-name NAME
Establece el nombre del archivo creado a partir de la entrada estándar. El valor predeterminado es stdin.
--compression ALGORITHM
Algoritmo de compresión a utilizar. Los algoritmos disponibles son: none, lz4, zstd, zlib, lzma. El valor predeterminado es zstd.
--exclude PATTERN
Excluye archivos que coincidan con el patrón especificado. Se pueden especificar varios patrones --exclude.
--exclude-from FILE
Lee patrones de exclusión del archivo especificado. Se pueden especificar varios archivos --exclude-from.
--include PATTERN
Incluye archivos que coincidan con el patrón especificado. Esto se puede utilizar para incluir selectivamente archivos que de otro modo serían excluidos por las reglas de exclusión.
--dry-run
No realiza ninguna operación de copia de seguridad real. Solo muestra qué archivos se copiarían de otro modo.
--progress
Muestra una barra de progreso mientras se crea la copia de seguridad.

EJEMPLOS

Crear un archivo llamado backup_2023-10-27 en el repositorio myrepo a partir del directorio /home/user:

borg create myrepo::backup_2023-10-27 /home/user

Crear un archivo a partir de la entrada estándar:

cat files.txt | borg create myrepo::myarchive --paths-from-stdin

Crear un archivo a partir de la salida de un comando:

borg create myrepo::myarchive --paths-from-command find /data -name '*.txt'

Crear un archivo a partir de la salida de un comando, con un nombre de archivo especificado:

backup-vm --id myvm --stdout | borg create REPO::ARCHIVE -

Crear un archivo a partir de la salida de un comando, con manejo de errores mejorado:

borg create --content-from-command REPO::ARCHIVE -- backup-vm --id myvm --stdout

NOTAS

Los códigos de estado de los archivos son:

  • 'A' = archivo regular, añadido (ver también a_status_oddity en el FAQ)
  • 'M' = archivo regular, modificado
  • 'U' = archivo regular, sin cambios
  • 'C' = archivo regular, cambió mientras lo estábamos respaldando
  • 'E' = archivo regular, ocurrió un error al acceder/leer este archivo

Un carácter en minúscula significa un tipo de archivo distinto de un archivo regular, borg generalmente solo almacena sus metadatos:

  • 'd' = directorio
  • 'b' = dispositivo de bloques
  • 'c' = dispositivo de caracteres
  • 'h' = archivo regular, enlace duro (a inodos ya vistos)
  • 's' = enlace simbólico
  • 'f' = fifo

Otras banderas usadas incluyen:

  • 'i' = los datos de copia de seguridad se leyeron de la entrada estándar (stdin)
  • '-' = ejecución de prueba, el elemento no se respaldó
  • 'x' = excluido, el elemento no se respaldó
  • '?' = código de estado faltante (si ves esto, ¡por favor, informa de un error!)

Lectura de datos de copia de seguridad desde stdin

Hay dos métodos para leer desde stdin. O bien especificar - como ruta y canalizar directamente a borg:

backup-vm --id myvm --stdout | borg create REPO::ARCHIVE -

O utilizar --content-from-command para que Borg gestione la ejecución del comando y la canalización. Si lo hace, el primer argumento de PATH se interpreta como el comando a ejecutar y cualquier argumento adicional se trata como argumentos para el comando:

borg create --content-from-command REPO::ARCHIVE -- backup-vm --id myvm --stdout

-- se utiliza para asegurar que --id y --stdout no sean considerados argumentos para borg sino para backup-vm.

La diferencia entre los dos enfoques es que la canalización a borg crea un archivo incluso si el comando que canaliza a borg sale con un fallo. En este caso, se puede terminar con una salida truncada siendo respaldada. Usar --content-from-command, en contraste, garantiza que borg falle sin crear un archivo si el comando falla. El comando se considera fallido cuando devuelve un código de salida distinto de cero.

Leer desde stdin produce solo un flujo de datos sin metadatos de archivo asociados, y la caché de archivos no es necesaria en absoluto. Por lo tanto, es seguro deshabilitarla con --files-cache disabled y acelerar un poco la creación de la copia de seguridad.

Por defecto, el contenido leído desde stdin se almacena en un archivo llamado 'stdin'. Use --stdin-name para cambiar el nombre.

Alimentar todas las rutas de archivo desde externamente

Por lo general, usted le da una ruta de inicio (raíz de recursión) a borg y luego borg itera automáticamente, encuentra y respalda todos los objetos del sistema de archivos contenidos allí (considerando opcionalmente reglas de inclusión/exclusión).

Si necesita más control y quiere darle a borg cada ruta de objeto individual del sistema de archivos (quizás implementando su propia recursión o sus propias reglas), puede usar --paths-from-stdin o --paths-from-command (con este último, borg fallará al crear un archivo si el comando falla).

Borg admite rutas con el truco slashdot para eliminar prefijos de ruta aquí también. Por lo tanto, tenga cuidado de no activarlo involuntariamente.
