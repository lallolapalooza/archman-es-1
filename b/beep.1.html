BEEP(1) Comandos de usuario BEEP(1)

NOMBRE

beep - hacer sonar el altavoz del PC de diversas maneras

SINOPSIS

beep [OPCIONES GLOBALES] [-f FRECUENCIA] [-l DURACION] [-r REPETICIONES] [<-d|-D> RETRASO] [-s] [-c]
beep [OPCIONES GLOBALES] <OPCIONES_TONO> [-n|--new] <OPCIONES_TONO>
beep <-h|--help>
beep <-v|-V|--version>

DESCRIPCIÓN

beep permite al usuario controlar el altavoz del PC con precisión, permitiendo que diferentes sonidos indiquen diferentes eventos. Si bien beep puede ejecutarse sin problemas en la línea de comandos, su uso previsto es dentro de scripts de shell/perl, notificando al usuario cuando ocurre algo interesante. Por supuesto, no tiene noción de qué es *interesante*, pero es bueno en la parte de notificación.

Todas las opciones tienen valores predeterminados, lo que significa que simplemente escribir 'beep' funcionará. Si se especifica una opción más de una vez en la línea de comandos, las opciones posteriores anulan a las anteriores. Por lo tanto, 'beep -f 200 -f 300' emitirá un pitido a 300Hz.

Todas las duraciones se dan en unidades de milisegundos, las frecuencias en Hertz y el número de repeticiones es un número adimensional.

OPCIONES

Opciones globales

-e DISPOSITIVO, --device=DISPOSITIVO
Establece explícitamente el dispositivo que beep usará para generar los tonos de pitido. Cuando no se le da un dispositivo explícitamente, beep recorre una lista interna de dispositivos hasta que uno parece funcionar.
--debug, --verbose
Hace que el programa beep sea más detallado.

Opciones de tono

-f FRECUENCIA
Emitir un pitido con una frecuencia de tono de FRECUENCIA Hz, donde 0 < FRECUENCIA < 20000. Como una estimación general, el pitido de terminal normal es de alrededor de 750 Hz. Para compatibilidad con versiones anteriores, puede dar FRECUENCIA como un número decimal, pero beep lo redondeará a valores enteros ya que las API del kernel los esperan. Valor predeterminado: 440 Hz.
-l DURACION
Emitir un pitido con una duración de tono de DURACION milisegundos. Valor predeterminado: 200 ms.
-r REPETICIONES
Repetir el pitido, incluidos los retrasos, REPETICIONES veces. Valor predeterminado: 1 tono, no repetido.
-d RETRASO | -D RETRASO
Especificar un retraso de RETRASO milisegundos entre repeticiones. La letra minúscula -d especifica que este retraso solo debe ocurrir *entre* pitidos, es decir, no debe ocurrir después de la última repetición. La letra mayúscula -D especifica que el retraso debe ocurrir después de cada repetición, *incluida* la última. Normalmente, -d es lo que desea, pero si, por ejemplo, está encadenando varios comandos beep para reproducir el himno de las guerras de las galaxias, puede que desee controlar cada retraso. Valor predeterminado: retraso de 100 ms entre pitidos sin retraso después del último pitido.
-n, --new
La opción --new le permite encadenar múltiples pitidos en una sola línea de comandos. Cada vez que se usa --new, beep comienza a tratar todos los argumentos posteriores como si fueran para un nuevo pitido. Por ejemplo:


beep -f 1000 -n -f 2000 -n -f 1500

produciría una secuencia de tres pitidos, el primero con una frecuencia de 1000 Hz (y por lo demás valores predeterminados), luego un segundo pitido con una frecuencia de 2000 Hz (de nuevo, con cosas como retraso y repeticiones establecidas en sus valores predeterminados), luego un tercer pitido, a 1500 Hz. Esto es diferente de especificar un valor de -r, ya que -r repite el mismo pitido varias veces, mientras que --new le permite especificar pitidos diferentes. Después de un --new, el nuevo pitido se crea con todos los valores predeterminados, y cualquiera de ellos se puede especificar sin alterar los valores de los pitidos precedentes (o posteriores). Vea la sección de EJEMPLOS si esto logró confundirlo.

-s, -c
Tanto la opción -s como la -c ponen a beep en modo de procesamiento de entrada, leyendo desde stdin y copiando todos los datos recibidos a stdout. Esto facilita la inserción de beep en una tubería de procesamiento de texto para monitorear acústicamente el flujo de datos dentro de esa tubería. Vea la sección de EJEMPLOS.
-c
Emitir un pitido después de cada carácter recibido.
-s
Emitir un pitido después de cada conjunto de datos recibido. Normalmente, esto significa después de que ocurran saltos de línea en tuberías de procesamiento de texto.

En una secuencia de notas especificadas con una o más ocurrencias de -n o --new, solo tiene sentido tener una sola nota marcada con -s o -c adjunta a ella. Entonces beep emitirá todas las notas hasta que llegue a la nota marcada, luego repetirá la nota marcada de acuerdo con la entrada que reciba, y una vez que la entrada alcance EOF, beep continuará con el resto de la secuencia de notas.

El comportamiento de beep con más de una nota marcada con -s o -c no está definido.

Otras acciones

-h, --help Muestra la información de uso de beep y sale.

-v, -V, --version
Muestra la información de versión de beep y sale.

ESTADO DE SALIDA

Cuando tiene éxito, beep regresa con el código de salida 0.

Cualquier código de salida distinto de 0 significa que beep ha encontrado un error y ha fallado.

ENTORNO

BEEP_LOG_LEVEL
Cuando se establece en un número entre -999 y 999, BEEP_LOG_LEVEL se utilizará como el nivel de registro predeterminado hasta que sea anulado por un parámetro de línea de comandos.

ARCHIVOS

Los archivos de dispositivo que beep usa por defecto son los siguientes:
/dev/input/by-path/platform-pcspkr-event-spkr
/dev/tty0
/dev/vc/0

NOTAS

Dispositivos y Permisos

Cuando ejecuta beep sin especificar explícitamente un dispositivo a usar, beep intenta abrir los siguientes dispositivos en secuencia hasta que uno tiene éxito:

/dev/input/by-path/platform-pcspkr-event-spkr
Utiliza la API evdev, y el administrador del sistema puede permitir el acceso a cualquier conjunto de usuarios y grupos usando los permisos de archivo normales.
/dev/tty0
Utiliza la API de consola, y el kernel insiste en que sea root o que posea el TTY.
/dev/vc/0
Utiliza la API de consola, y el kernel insiste en que sea root o que posea el TTY.

beep no soporta ejecutarse como setuid root o a través de sudo(1).

Para usos no root, el administrador del sistema puede configurar una regla de udev(7) para permitir el acceso de escritura a /dev/input/by-path/platform-pcspkr-event-spkr para ciertos usuarios y/o grupos de usuarios. Para más detalles, consulte el archivo /usr/share/doc/beep/PERMISSIONS.md de beep.

NOTAS

Los permisos para este archivo de dispositivo se pueden configurar de manera que cualquier usuario no root que el administrador del sistema desee pueda ejecutar beep.
Abrir este dispositivo lleva del orden de 20 ms en el kernel de Linux cada vez que se inicia el comando beep. Por lo tanto, si necesita reproducir múltiples notas en una secuencia rítmica para una melodía, use una única invocación del comando beep con múltiples notas, no varias invocaciones de beep reproduciendo una nota cada una.
consola
Utiliza la antigua API de consola, lo que significa ejecutar el ioctl(2) KIOCSOUND en un dispositivo tty como /dev/tty0 o /dev/vc/0.
Esto requiere ser root, a menos que el usuario no root esté conectado a la consola virtual y esté utilizando ese dispositivo de consola virtual específico, como por ejemplo /dev/tty4. Esto hace que el controlador de consola sea inútil para usuarios no root conectados a través de ssh, y a menudo de X11 o Wayland.
Utilice la API evdev en su lugar.

Invocaciones Concurrentes

Las invocaciones concurrentes de beep no están soportadas. Solo hay un generador de tonos en el hardware del PC, y no gestionamos el acceso a ese recurso compartido de ninguna manera. Por lo tanto, si un primer proceso beep -f 1000 -l 10000 inicia un pitido largo de 10 segundos a 1000Hz, y 2 segundos después llega un segundo beep -f 2050 -l 100 rápido con 2050Hz, escuchará ese pitido de 2050Hz durante 100 ms, y luego silencio, ya que el pitido rápido silencia el generador de tonos. Ahora no escuchará que el primer proceso beep todavía está en ejecución después de haber esperado los primeros 2100 ms de sus 10000 ms. Tampoco escuchará que el primer proceso beep silenciará el altavoz ya silencioso 7900 ms después, es decir, 10000 ms después de que comenzara el primer beep.

Volumen del Sonido

El hardware del altavoz del PC no tiene forma de ajustar explícitamente el volumen de un pitido.

Si tiene un PC independiente, sin embargo, es probable que tenga un zumbador piezoeléctrico conectado a la placa base. Si prioriza un pitido alto sobre un pitido de cierta frecuencia, puede optar por emitir un pitido a una frecuencia cercana a la frecuencia de resonancia del zumbador piezoeléctrico. Los zumbadores piezoeléctricos típicos tienen una frecuencia de resonancia alrededor de 2000 Hz, por lo que puede probar frecuencias en ese rango. El zumbador piezoeléctrico del autor es más ruidoso a unos 2050 Hz.

Si tiene un portátil PC, es probable que su portátil no tenga hardware de zumbador piezoeléctrico y que dirija la salida del circuito pcspkr a los altavoces internos del portátil a través del mezclador de la tarjeta de sonido. En ese caso, puede y/o debe cambiar el nivel del mezclador para el zumbador utilizando una aplicación de mezclador de tarjeta de sonido.

EJEMPLOS

En su forma más simple (pero aún efectiva)


beep

Una configuración independiente más interesante


beep -f 300.7 -r 2 -d 100 -l 400

Como parte de un pipeline de monitorización de logs


tail -f /var/log/xferlog | grep 'passwd' | beep -f 1000 -r 5 -s

Cuando se usa el modo -c, recomiendo usar un -D corto y un -l más corto, para que los pitidos no se mezclen. Algo como esto le dará un efecto de pitido de "caja registradora" estilo 1970 al teclear cada letra


cat file | beep -c -f 400 -D 50 -l 10

Un ejemplo muy forzado de uso de -n/--new


beep -f 1000 -r 2 -n -r 5 -l 10 --new

producirá primero dos pitidos de 1000 Hz, luego 5 pitidos con el tono predeterminado, pero de solo 10 ms de duración cada uno, seguido de un tercer pitido utilizando toda la configuración predeterminada (ya que no se especificó ninguna).
