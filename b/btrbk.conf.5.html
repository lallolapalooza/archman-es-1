NOMBRE

btrbk.conf - Archivo de configuración de btrbk

SINOPSIS

/etc/btrbk.conf
/etc/btrbk/btrbk.conf

DESCRIPCIÓN

El archivo de configuración de btrbk especifica qué subvolúmenes de btrfs en el sistema de archivos deben ser procesados, qué subvolúmenes de destino deben usarse para crear las copias de seguridad, y dónde deben generarse las instantáneas. La política de retención, así como la mayoría de las otras opciones, se pueden definir de forma global o dentro de una sección.

Las opciones especificadas siempre se aplican a la última sección encontrada, reemplazando los valores establecidos en las secciones de nivel superior. Esto significa que las opciones globales deben establecerse antes de definir cualquier sección.

Las líneas en blanco se ignoran. Un carácter de almohadilla (#) inicia un comentario que se extiende hasta el final de la línea.

SECCIONES

volume <directorio-volumen>|<url> (opcional)

Ruta absoluta que apunta a un sistema de archivos btrfs que contiene los subvolúmenes de origen que se van a respaldar. Normalmente, el punto de montaje de un sistema de archivos btrfs montado con la opción subvolid=5.

subvolume <nombre-subvolumen>

Subvolumen que se va a respaldar, relativo al <directorio-volumen> de la sección volume, o absoluto si se omite la sección volume. Acepta el carácter comodín "*".

Tenga en cuenta que si este subvolumen es la raíz de btrfs (id=5), necesita tener una UUID válida, lo que no es el caso para los sistemas de archivos creados con btrfs-progs < 4.16.

target [send-receive|raw] <directorio-destino>|<url>

Directorio de destino donde se crearán los subvolúmenes de copia de seguridad. El tipo de destino opcional por defecto es “send-receive”, véase TIPOS DE DESTINO para más detalles.

Se permiten múltiples secciones target, en cualquier contexto: un target definido en contexto volume o global se utilizará para todas las secciones subvolume subyacentes (pista: ejecute "btrbk list" o "btrbk config print" para ver la configuración resultante).

Si se especifica una <url>, las acciones de btrbk (comandos shell) se ejecutan remotamente a través de ssh, utilizando las Opciones SSH descritas a continuación. Los formatos aceptados son:

ssh://<nombre-host>[:<puerto>]/<directorio>
<nombre-host>:<directorio>

Donde <nombre-host> es un nombre de host, una dirección IPv4 en formato decimal punteado, o una literal de IP encapsulada entre corchetes (por ejemplo, "[2001:db8::7]").

Si se está conectando a máquinas virtuales, considere configurar varias secciones volume para un <nombre-host>, con números de <puerto> distintos para cada máquina.

OPCIONES

Las opciones descritas aquí se pueden especificar en el contexto global, así como en las secciones volume, subvolume y target, a menos que se indique lo contrario.

Opciones Básicas

timestamp_format short|long|long-iso

Formato de marca de tiempo utilizado como sufijo para los nombres de los nuevos subvolúmenes de instantánea. Por defecto es “long”.

short

YYYYMMDD[_N] (por ejemplo, "20150825", "20150825_1")

long

YYYYMMDD<T>hhmm[_N] (por ejemplo, "20150825T1531")

long-iso

YYYYMMDD<T>hhmmss&plusmn;hhmm[_N] (por ejemplo, "20150825T153123+0200")

Tenga en cuenta que se añade un sufijo "_N" a la marca de tiempo si ya existe una instantánea o copia de seguridad con la marca de tiempo de la fecha/hora actual.

Utilice “long-iso” si desea asegurarse de que btrbk nunca crea marcas de tiempo ambiguas (lo que puede ocurrir si se crean múltiples instantáneas durante un cambio de reloj de horario de verano).

Tenga en cuenta que usar “long-iso” tiene implicaciones en la planificación, véase Hora de Referencia más abajo.

snapshot_dir <directorio>

Directorio en el que se crean las instantáneas de btrfs, relativo al <directorio-volumen> de la sección volume, o absoluto si se omite la sección volume. Tenga en cuenta que btrbk no crea automáticamente este directorio, y la creación de instantáneas fallará si no está presente.

snapshot_name <nombre-base>

Nombre base de la instantánea (y copia de seguridad) creada. Esta opción solo es válida en la sección subvolume. Por defecto es <nombre-subvolumen>.

snapshot_create always|onchange|ondemand|no

Si se establece en “always”, las instantáneas siempre se crean. Si se establece en “onchange”, las instantáneas solo se crean si la última instantánea no está actualizada, es decir, si el subvolumen de origen ha cambiado (más precisamente: la generación de btrfs ha aumentado) desde que se creó la última instantánea. Si se establece en “ondemand”, las instantáneas solo se crean si al menos un subvolumen de destino es accesible (útil si tiene poco espacio en disco y solo necesita btrbk para copias de seguridad en un disco externo que no siempre está conectado). Si se establece en “no”, las instantáneas nunca se crean (útil si otra instancia de btrbk se encarga de la creación de instantáneas). Por defecto es “always”.

incremental yes|no|strict

Si se establece, se crean copias de seguridad incrementales. Si se establece en “strict”, nunca se crean copias de seguridad no incrementales (iniciales), y las copias de seguridad incrementales se restringen a padres relacionados (por relación parent-uuid). Por defecto es “yes”.

Tenga en cuenta que incluso si la cadena parent-uuid se rompe, las instantáneas y las copias de seguridad aún pueden compartir datos (lo que es especialmente cierto para las copias de seguridad creadas con la opción incremental habilitada), y son perfectamente adecuadas como padres para operaciones de send-receive incrementales. Pero como btrbk no puede estar seguro de esto, tales operaciones están prohibidas en el modo "incremental strict".

noauto yes|no

Si se establece, el contexto es omitido por todas las acciones de btrbk a menos que se habilite explícitamente mediante un argumento de línea de comandos de <filter> de btrbk coincidente (por ejemplo, "btrbk run myfilter").

Opciones de Agrupación

group <nombre-grupo> [<nombre-grupo>]...

Añade la sección actual (volumen, subvolumen o destino) a grupos definidos por el usuario, que pueden utilizarse como filtro para la mayoría de los comandos de btrbk (véase DECLARACIONES DE FILTRO de btrbk(1)). Esta opción se puede establecer varias veces dentro del mismo contexto.

Opciones de Política de Retención

preserve_day_of_week monday|tuesday|...|sunday

Define en qué día una instantánea/copia de seguridad se considera una copia de seguridad "semanal". Las copias de seguridad semanales, mensuales y anuales se conservan en este día de la semana (véase POLÍTICA DE RETENCIÓN más abajo). Por defecto es “sunday”.

preserve_hour_of_day [0..23]

Define a partir de qué hora (en horas completas desde la medianoche) una instantánea/copia de seguridad se considera una copia de seguridad "diaria". Las copias de seguridad diarias, semanales, mensuales y anuales se conservan en esta hora (véase POLÍTICA DE RETENCIÓN más abajo). Ignorado en instantáneas o copias de seguridad sin información de tiempo (timestamp_format short). Por defecto es “0”.

snapshot_preserve no|<política_retención>

Establece la política de retención para instantáneas (véase POLÍTICA DE RETENCIÓN más abajo). Si se establece en “no”, conserva las instantáneas según snapshot_preserve_min solamente. Por defecto es “no”.

Tenga en cuenta que snapshot_preserve no tiene efecto si snapshot_preserve_min se establece en “all” (el valor por defecto).

snapshot_preserve_min all|latest|<número>{h,d,w,m,y}

Conserva todas las instantáneas durante un mínimo de horas (h), días (d), semanas (w), meses (m) o años (y), independientemente de cuántas haya. Si se establece en “all”, conserva todas las instantáneas para siempre. Si se establece en “latest”, conserva la última instantánea. Por defecto es “all”.

Tipos de Destino

target_type send-receive|raw

El tipo de destino a utilizar. Por defecto es “send-receive”.

send-receive

Utiliza la función send/receive de btrfs para crear copias de seguridad incrementales. Si una copia de seguridad no existe, se crea una instantánea completa. Si existe, se crea una copia de seguridad incremental basada en la instantánea más antigua.

raw

Copia el subvolumen de origen de forma bruta. Esto no es incremental y puede consumir mucho espacio en disco.

Otras Opciones

backup yes|no

Si se establece en “yes”, se crean copias de seguridad del subvolumen de origen en el directorio de destino. Por defecto es “yes”.

send yes|no

Si se establece en “yes”, se crea una copia de seguridad incremental del subvolumen de origen utilizando la función send/receive de btrfs. Por defecto es “yes”.

receive yes|no

Si se establece en “yes”, se recibe una copia de seguridad incremental. Por defecto es “yes”.

compress zlib|lzo|zstd|no

Algoritmo de compresión para la copia de seguridad. “zstd” es generalmente el más rápido y eficiente. Por defecto es “zstd”.

compression_level [1..10]

Nivel de compresión (solo para zstd). Por defecto es “3”.

prune yes|no

Si se establece en “yes”, se eliminan las copias de seguridad antiguas según la política de retención. Por defecto es “yes”.

prune_readonly yes|no

Si se establece en “yes”, se eliminan las copias de seguridad antiguas de los subvolúmenes de destino de solo lectura. Por defecto es “no”.

prune_snapshot yes|no

Si se establece en “yes”, se eliminan las instantáneas antiguas según la política de retención. Por defecto es “yes”.

prune_backups yes|no

Si se establece en “yes”, se eliminan las copias de seguridad antiguas según la política de retención. Por defecto es “yes”.

prune_expire <tiempo>

Tiempo después del cual las copias de seguridad se consideran obsoletas y se pueden eliminar. El tiempo se especifica como un número seguido de una unidad: h (horas), d (días), w (semanas), m (meses), y (años). Por ejemplo, 7d para 7 días.

POLÍTICA DE RETENCIÓN

La política de retención se define mediante las opciones snapshot_preserve y snapshot_preserve_min para las instantáneas, y target_preserve y target_preserve_min para las copias de seguridad. También se pueden utilizar las opciones prune_expire, prune_day_of_week, prune_hour_of_day, etc. para la eliminación automática de copias de seguridad y de instantáneas antiguas.

En general, btrbk intenta conservar un número de instantáneas/copias de seguridad de acuerdo con la política definida. La política se define como una combinación de:

  • Se conserva al menos una instantánea/copia de seguridad cada ...
  • Se conserva al menos una instantánea/copia de seguridad en ...

Las unidades de tiempo son: h (horas), d (días), w (semanas), m (meses), y (años).

Por ejemplo:

snapshot_preserve 1d 2w 1m 1y

Esto significa que se conservará al menos una instantánea por día, una por semana, una por mes y una por año. La instantánea más reciente siempre se conserva.

Las opciones de preservación son:

snapshot_preserve no|<retention_policy>

Retención de instantáneas. Si se establece en “no”, se aplica solo snapshot_preserve_min.

snapshot_preserve_min all|latest|<number>{h,d,w,m,y}

Número mínimo de instantáneas a conservar.

target_preserve no|<retention_policy>

Retención de copias de seguridad. Si se establece en “no”, se aplica solo target_preserve_min.

target_preserve_min all|latest|<number>{h,d,w,m,y}

Número mínimo de copias de seguridad a conservar.

También se puede especificar la política de retención usando palabras clave:

daily, weekly, monthly, yearly

Por ejemplo:

snapshot_preserve daily 1w 1m 1y

Esto conserva las instantáneas diarias, además de una semanal, una mensual y una anual.

La opción preserve_day_of_week y preserve_hour_of_day determinan qué día y hora se consideran para las instantáneas semanales y diarias, respectivamente.

La opción prune_expire se utiliza para eliminar copias de seguridad que son más antiguas que el tiempo especificado. Por ejemplo, prune_expire 7d eliminará las copias de seguridad de más de 7 días.

HORA DE REFERENCIA

Para la retención de copias de seguridad y la eliminación, btrbk utiliza la hora de la última copia de seguridad o instantánea como tiempo de referencia. Si se utiliza el formato de marca de tiempo long-iso, btrbk tendrá en cuenta la zona horaria y el posible cambio de horario de verano.

EJEMPLOS

Cree instantáneas diarias y semanales de un subvolumen en un sistema de archivos btrfs externo:

volume /mnt/btrfs
  snapshot_dir /mnt/btrfs/snapshots
  subvolume /home
    snapshot_name home
    snapshot_preserve daily 1w

Haga copias de seguridad incrementales de varios subvolúmenes a un servidor remoto usando ssh:

volume /
  snapshot_dir /mnt/backup/snapshots
  subvolume /srv/data
    target send-receive ssh://backup-server:/srv/backup/data
    snapshot_preserve 1d 1w 1m 1y
  subvolume /srv/web
    target send-receive ssh://backup-server:/srv/backup/web
    snapshot_preserve 1d 1w 1m 1y

POLÍTICA DE

RETENCIÓN

Las políticas de retención se definen individualmente para las instantáneas, las copias de seguridad y los archivos (resumidos como "copias de seguridad" en el siguiente texto), usando una combinación

de:

*_preserve_min all|latest|no|<number>{h,d,w,m,

y}
Cantidad de tiempo (duración) durante la cual se conservan todas las copias de
seguridad.

*_preserve no|<retention_policy

>
Programación (puntos únicos en el tiempo) para los que se conservan copias de seguridad
individuales.

Ten en cuenta que si "preserve_min" está establecido en “all” (el valor por defecto), cualquier configuración de "preserve" obviamente no tiene

efecto.

El formato para <retention_policy>

es: 
[<hourly>h] [<daily>
d] [<weekly>w] [<mo
nthly>m] [<yearly>y]

hourl

y
Define cuántas horas hacia atrás deben conservarse las copias de seguridad horarias. La primera copia de seguridad de una hora se considera una copia de seguridad
horaria.

dail

y
Define cuántos días hacia atrás deben conservarse las copias de seguridad diarias. La primera copia de seguridad de un día (comenzando en preserve_hour_of_day) se considera una copia de seguridad
diaria.

weekl

y
Define cuántas semanas hacia atrás deben conservarse las copias de seguridad semanales. La primera copia de seguridad diaria creada en preserve_day_of_week (o la primera copia de seguridad en esta semana si no se hizo en el día exacto) se considera una copia de seguridad
semanal.

monthl

y
Define cuántos meses hacia atrás deben conservarse las copias de seguridad mensuales. Cada primera copia de seguridad semanal en un mes se considera una copia de seguridad
mensual.

yearl

y
Define durante cuántos años hacia atrás deben conservarse las copias de seguridad anuales. Cada primera copia de seguridad mensual en un año se considera una copia de seguridad
anual.

Usa un asterisco para “all” (p. ej., "target_preserve 60d *m" indica: "conservar copias de seguridad diarias durante 60 días hacia atrás, y todas las copias de seguridad mensuales")

.

Consejo: Ejecuta btrbk con la -S, opción --print-schedule para obtener una salida completa de los resultados del

programador.

Tiempo de

referencia

La hora local en el host que ejecuta btrbk define el tiempo de referencia para todos los cálculos de fecha/hora, especialmente para "inicio de un día", y como consecuencia para las primeras copias de seguridad diarias, semanales, mensuales o anuales. La hora local en hosts remotos (fuente/destino ssh) nunca se

utiliza.

A menos que se establezca "timestamp_format long-iso", las copias de seguridad diarias se conservan en "preserve_hour_of_day" (por defecto a medianoche) de la zona horaria respectiva (y no para "00:00 UTC", que sería "14:00" en Honolulu). Esto se vuelve relevante para configuraciones con múltiples instancias de btrbk, p. ej., muchas instancias solo de instantáneas (dispersas por el mundo), y una instancia solo de obtención en el servidor de

respaldo.

Advertenci

a:
•Si se establece "timestamp_format long-iso", cada instancia de
btrbk tiene una interpretación diferente de "primero en el día".
Asegúrate de ejecutar btrbk con la misma zona horaria en cada host
, p. ej. estableciendo la variable de entorno TZ (ver tzset(3)).

TIPOS DE

DESTINO

send-receiv

e
Copia de seguridad a un sistema de archivos btrfs, usando "btrfs send/receive". Este es el tipo de destino recomendado (estándar). El <target-directory> debe ser una ruta absoluta y apuntar a un subvolumen o directorio dentro de un sistema de archivos btrfs. Ver btrfs-send(8), btrfs-receive(8)
.

raw *experimental

*
Copia de seguridad a un archivo crudo (independiente del sistema de archivos) de la salida de btrfs-send(8), con compresión y cifrado opcionales.

Ten en cuenta que el mecanismo de conservación de destino está actualmente deshabilitado para las copias de seguridad incrementales crudas (¡btrbk no elimina ningún archivo incremental crudo)

!

Las copias de seguridad crudas consisten en dos archivos: el archivo de datos principal que contiene el flujo de envío de btrfs, y un archivo auxiliar ".info" que contiene

metadatos: 
<snapshot-name>.<timestamp>[_N].btrfs[.g
z|.bz2|...][.gpg] <snapshot-name>.<times
tamp>[_N].btrfs[.gz|.bz2|...][.gpg].info

Para las copias de seguridad incrementales ("incremental yes"), ten en cuenta

que:
•Tan pronto como un solo archivo de copia de seguridad incremental se pierda o dañe, todas las copias de seguridad incrementales posteriores se vuelven inválidas, ya que ya no hay un padre común para las imágenes incrementales siguientes. Esto podría ser un buen compromiso para un plan de copias de seguridad de vacaciones, pero a largo plazo asegúrate de que se active una copia de seguridad no incremental de vez en
cuando.
•Actualmente no hay soporte para la rotación de copias de seguridad incrementales: si incremental está establecido, se debe activar manualmente una copia de seguridad completa de vez en cuando para poder eliminar copias de seguridad
antiguas.
