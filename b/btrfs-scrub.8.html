Advertencia

:
Tal como está implementado actualmente, establecer el atributo de archivo NOCOW (mediante chattr +C) en un archivo habilita implícitamente NODATASUM. Esto significa que, aunque los metadatos de estos archivos continúan siendo validados y corregidos por la depuración, los datos

reales del archivo no lo son. Además, btrfs actualmente no marca los discos ausentes o con fallos como poco fiables, por lo que continuará distribuyendo la carga de lecturas hacia réplicas potencialmente dañadas. Esto normalmente no es un problema porque el daño se detecta mediante la validación de las sumas de comprobación, pero como los archivos NOCOW no están protegidos por sumas de comprobación, btrfs no sabe cuál es la réplica buena, por lo que puede devolver el

reanudar [-BdqrR] <ruta>|<dispositivo>
Reanuda una verificación cancelada o interrumpida en el sistema de archivos identificado por ruta o en un dispositivo dado. El punto de inicio se lee del archivo de estado si existe.

Esto no inicia una nueva verificación si la última verificación finalizó con éxito.

Opciones

ver scrub start.

iniciar [opciones] <ruta>|<dispositivo>
Inicia una verificación en todos los dispositivos del sistema de archivos montado identificado por ruta o en un solo dispositivo. Si ya hay una verificación en curso, la nueva no se iniciará. Un dispositivo de un sistema de archivos desmontado no puede ser verificado de esta manera.

Sin opciones, la verificación se inicia como un proceso en segundo plano. Las reparaciones automáticas de copias dañadas se realizan por defecto para perfiles de grupo de bloques con redundancia. La no reparación se puede habilitar con la opción -r.

Opciones

-B
no ejecutar en segundo plano e imprimir estadísticas de verificación al finalizar
-d
imprimir estadísticas separadas para cada dispositivo del sistema de archivos (solo -B) al final
-r
ejecutar en modo de solo lectura, no intentar corregir nada, se puede ejecutar en un sistema de archivos de solo lectura

Tenga en cuenta que una verificación de solo lectura en un sistema de archivos de lectura/escritura aún puede causar escrituras en el sistema de archivos debido a algunas limitaciones internas. Solo una verificación de solo lectura en un sistema de archivos de solo lectura puede evitar escrituras de la verificación.

-R
modo de impresión cruda, imprimir datos completos en lugar de resumen
--limit <límite>
establecer el límite de rendimiento de la verificación para cada dispositivo.

Si la verificación es para todo el sistema de archivos, es lo mismo que btrfs scrub limit --all --limit <valor>. Si la verificación es para un solo dispositivo, es lo mismo que btrfs scrub limit --devid <devid> -l <valor>.

El valor es bytes por segundo, y acepta los sufijos usuales KMGT. Después de que la verificación finalice, el límite de rendimiento se restablecerá al valor anterior de cada dispositivo.

-f
forzar el inicio de una nueva verificación incluso si ya hay una en curso, esto puede ser útil si el archivo de estado de la verificación está dañado y reporta una verificación en curso aunque no lo esté, pero normalmente no debería ser necesario

Opciones obsoletas

La configuración de prioridad solo funciona con ciertos planificadores, en particular, *no* funcionan con el más común, *mq-deadline*.

-c <clase_ioprio>
establecer la clase de prioridad de IO (ver la página del manual de ionice(1) https://man7.org/linux/man-pages/man1/ionice.1.html) si el planificador de IO configurado para el dispositivo soporta ionice. Esto solo es compatible con BFQ o Kyber, pero *no* con mq-deadline. Por favor, lea la sección sobre limitación de IO <btrfs-scrub//#scrub-io-limiting>.
-n <datos_clase_ioprio>
establecer los datos de la clase de prioridad de IO (ver la página del manual de ionice(1) https://man7.org/linux/man-pages/man1/ionice.1.html)
-q
(obsoleto) alias para la opción global -q
estado [opciones] <ruta>|<dispositivo>
Muestra el estado de una verificación en curso para el sistema de archivos identificado por ruta o para el dispositivo especificado.

Si no hay ninguna verificación en curso, muestra estadísticas de la última verificación finalizada o cancelada para ese sistema de archivos o dispositivo. El estado se lee del archivo ubicado en /var/lib/btrfs.

Opciones

-d
imprimir estadísticas separadas para cada dispositivo del sistema de archivos
-R
imprimir todas las estadísticas crudas sin postprocesamiento tal como las devuelve el ioctl de estado
--raw
imprimir todos los números en valores crudos en bytes sin el sufijo B
--human-readable
imprimir números amigables para humanos, base 1024, este es el valor por defecto
--iec
seleccionar la base 1024 para las siguientes opciones, de acuerdo con el estándar IEC
--si
seleccionar la base 1000 para las siguientes opciones, de acuerdo con el estándar SI
--kbytes
mostrar tamaños en KiB, o kB con --si
--mbytes
mostrar tamaños en MiB, o MB con --si
--gbytes
mostrar tamaños en GiB, o GB con --si
--tbytes
mostrar tamaños en TiB, o TB con --si

El estado de un sistema de archivos sin errores se ve así:

# btrfs scrub start /
# btrfs scrub status /
UUID:             76fac721-2294-4f89-a1af-620cde7a1980
Scrub started:    Mié Abr 10 12:34:56 2023
Status:           corriendo
Duración:         0:00:05
Tiempo restante:    0:00:05
ETA:              Mié Abr 10 12:35:01 2023
Total a verificar:   28.32GiB
Bytes verificados:   13.76GiB  (48.59%)
Tasa:             2.75GiB/s
Resumen de errores:   no se encontraron errores

Con algunos errores encontrados:

Resumen de errores:   csum=72
  Corregidos:      2
  Incorregibles:  72
  No verificados:     0
  • Corregidos -- número de bloques defectuosos que fueron reparados de otra copia
  • Incorregibles -- errores detectados al leer pero imposibles de reparar desde otra copia
  • No verificados -- errores transitorios, la primera lectura falló pero un reintento tuvo éxito, pueden verse afectados por capas inferiores que agrupan o dividen solicitudes de IO
  • Resumen de errores -- seguido de una lista más detallada de los errores encontrados
  • csum -- discrepancia de suma de verificación
  • super -- errores de superbloque, a menos que el error se corrija inmediatamente, el próximo commit sobrescribirá el superbloque
  • verify -- errores de cabecera de bloque de metadatos
  • read -- los bloques no se pueden leer debido a errores de IO

Es posible establecer un límite por dispositivo a través del archivo sysfs/fs/btrfs/FSID/devinfo/scrub_speed_max. En ese caso, el límite se imprime en la línea Rate: si se especifica la opción -d, o sin ella en un sistema de archivos de un solo dispositivo. Lea más sobre eso en la sección sobre limitación de IO de verificación <btrfs-scrub//#scrub-io-limiting>.

Tasa:             989.0MiB/s (límite 1.0G/s)

En un sistema de archivos multidispositivo con al menos un dispositivo con límite, las estadísticas generales no pueden imprimir el límite sin -d, por lo que hay una nota indicando que se han establecido algunos límites:

Tasa:             36.37MiB/s (se establecieron algunos límites de dispositivo)

ESTADO DE SALIDA

btrfs scrub devuelve un estado de salida cero si tiene éxito. Se devuelve un valor distinto de cero en caso de fallo:

1
no se pudo realizar la verificación
2
no hay nada que reanudar
3
la verificación encontró errores incorregibles
