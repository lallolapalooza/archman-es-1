NOMBRE

bup-midx - crear un archivo multi-índice (.midx) a partir de varios archivos .idx

SINOPSIS

bup midx [-o archivo_salida] <-a|-f|nombres_idx...>

DESCRIPCIÓN

bup midx crea un archivo multi-índice (.midx) a partir de uno o más archivos de índice de paquete de git (.idx).

Nota: ya no deberías necesitar ejecutar este comando manualmente. Se ejecuta automáticamente por bup-save(1) y comandos similares.

OPCIONES

-o, --output=nombre_archivo.midx
usa el nombre de archivo de salida dado para el archivo .midx. El valor predeterminado se genera automáticamente.
-a, --auto
genera automáticamente nuevos archivos .midx para cualquier archivo .idx donde sea apropiado.
-f, --force
fuerza la generación de un nuevo archivo .midx único que contenga todos tus archivos .idx, incluso si ya existen otros archivos .midx. Esto resultará en el rendimiento de copia de seguridad más rápido, pero puede llevar mucho tiempo ejecutarlo.
--dir=directorio_paquetes
especifica el directorio que contiene los archivos .idx/.midx con los que trabajar. El valor predeterminado es $BUP_DIR/objects/pack.
--max-files
número máximo de archivos .idx para abrir a la vez. Puedes usar esto si tienes un número especialmente pequeño de descriptores de archivo disponibles, de modo que midx pueda completarse (aunque posiblemente no de forma óptima) incluso si no puede abrir todos tus archivos .idx a la vez. El valor predeterminado de esta opción debería ser suficiente para la mayoría de las personas.
--check
valida un archivo .midx asegurando que todos los objetos en sus archivos .idx contenidos existan dentro del .midx. Puede ser útil para depuración.

EJEMPLOS

$ bup midx -a
Fusionando 21 índices (2278559 objetos).
Tamaño de tabla: 524288 (17 bits)
Leyendo índices: 100.00% (2278559/2278559), hecho.
midx-b66d7c9afc4396187218f2936a87b865cf342672.midx

DISCUSIÓN

Por defecto, bup utiliza archivos de paquete con formato git, que consisten en un archivo de paquete (que contiene objetos) y un archivo idx (que contiene una lista ordenada de nombres de objetos y sus desplazamientos en el archivo .pack).

Los archivos idx normales son convenientes porque significa que puedes usar git(1) para acceder a tus conjuntos de copias de seguridad. Sin embargo, los archivos idx pueden volverse lentos cuando tienes muchos paquetes muy grandes (que git normalmente no tiene, pero bup a menudo sí).

Los archivos .midx de bup consisten en una única lista ordenada de todos los objetos contenidos en todos los archivos .pack a los que hace referencia. Esta lista se puede buscar binariamente en aproximadamente log2(m) pasos, donde m es el número total de objetos.

Para acelerar aún más la búsqueda, los archivos midx también tienen una tabla de dispersión de tamaño variable que reduce los primeros n pasos de la búsqueda binaria. Con la ayuda de esta tabla de dispersión, bup puede reducir en qué página del archivo midx se encontraría un ID de objeto dado (si existe) con una sola consulta. Por lo tanto, las búsquedas típicas solo necesitarán cargar dos páginas: una para la tabla de dispersión y otra para el ID del objeto.

Los archivos midx son más útiles al crear nuevas copias de seguridad, ya que la búsqueda de un objeto inexistente en el repositorio requiere necesariamente buscar en *todos* los archivos de índice para asegurar que no exista. (La búsqueda de objetos que *sí* existen se puede optimizar; por ejemplo, los objetos consecutivos a menudo se almacenan en el mismo paquete, por lo que podemos buscar ese primero usando un algoritmo MRU).
