ci envía la solicitud de prueba de los paquetes del proyecto a un servidor CI. Si no se especifica un directorio de proyecto o de paquete, se asume el directorio de trabajo actual. Si no se especifica una configuración, se utilizan las configuraciones predeterminadas. Si el directorio especificado es un directorio de proyecto, se envían todos los paquetes inicializados en las configuraciones, a menos que se especifique la opción--forward(véase más abajo). Véase bdep-projects-configs(1) para obtener detalles sobre cómo especificar proyectos y configuraciones. Una solicitud de CI consiste en los paquetes especificados y sus versiones, así como la URL del repositorio de control de versiones remoto del proyecto correspondiente al estado actual (local) del proyecto. El servidor CI debe poder obtener estas versiones de los paquetes desde este repositorio, así como cualquier dependencia de este repositorio o de sus repositorios complementarios/prerrequisitos, de acuerdo con el
repositories.manifest de cada paquete. Si no se especifica explícitamente el servidor CI con la opción--server [[68]], la solicitud se envía por defecto a ci.cppget.org [[70]]. A menos que se especifique la URL del repositorio

remoto con
la opción

--repository [[73]], se derivará automáticamente de la URL "remota" del control de versiones. En

el caso de

git(1) [[75]], se basará en el valor de configuración remote.origin.

a menos que se anule con remote.origin.build2Url [[79]]. La URL del repositorio se ajusta entonces para que corresponda al estado actual (local) del proyecto. En el caso de git(1) [[81]], la rama actual y el id del commit se añaden como fragmento de la URL del repositorio

(véase

Tenga también en cuenta que las anulaciones de valores del grupo de restricciones de compilación comunes y específicas de la configuración del paquete de compilación son mutuamente excluyentes. Si se anulan las restricciones de compilación comunes, se eliminan todas las restricciones específicas de la configuración. De lo contrario, si se anula alguna restricción específica de la configuración, para las configuraciones restantes las restricciones de compilación se restablecen abuilds: none [[136]]. De manera similar a los grupos de restricciones de compilación, las anulaciones de valores de la clave pública del bot personalizado comunes y específicas de la configuración del paquete de compilación son mutuamente excluyentes. Si se anulan las claves públicas del bot personalizado de compilación comunes, se eliminan todas las claves públicas del bot personalizado específicas de la configuración. De lo contrario, si se anula alguna clave pública del bot personalizado específica de la configuración, para las configuraciones restantes las claves públicas del bot personalizado se dejan sin cambios. De manera similar a lo anterior, las anulaciones de valores del grupo de correos electrónicos de compilación comunes y específicas de la configuración del paquete de compilación son mutuamente excluyentes. Si se anulan los correos electrónicos de compilación comunes, se eliminan todos los correos electrónicos específicos de la configuración. De lo contrario, si se anula algún correo electrónico específico de la configuración, para las configuraciones restantes los correos electrónicos de compilación se restablecen a valores vacíos y se eliminan los correos electrónicos de advertencia y error de compilación (lo que desactiva eficazmente las notificaciones por correo electrónico para dichas configuraciones). Si el servicio de CI lo admite, se puede probar un paquete de forma interactiva en una configuración de compilación específica utilizando la opción--interactive|

-i [[142]]. En este modo, el servicio de CI proporciona la información de acceso para el entorno de ejecución y pausa la prueba en el punto de interrupción especificado. Aunque la interpretación exacta de la solicitud de CI depende del servicio específico, normalmente el servidor CI responderá con una referencia que se puede utilizar para consultar los resultados. Véase Package CI (#ci) para obtener detalles sobre el manejo de las solicitudes de CI. Si se especifica la opción --forward [[146]], se utilizan las configuraciones reenviadas en lugar de las configuraciones predeterminadas. En particular, esto significa que en este modo el proyecto no necesita estar inicializado y todo lo que se requiere es que los directorios de origen del paquete estén configurados para reenviar a una configuración de compilación

fuera de origen (véase

para obtener detalles sobre las configuraciones reenviadas). Esto, por ejemplo, se puede utilizar para enviar paquetes que no utilizan el

estándar.

COMMON OPTIONS

The common options are summarized below with a more detailed description available in bdep-common-options(1).

-v
Print essential underlying commands being executed.
-V
Print all underlying commands being executed.
--quiet|-q
Run quietly, only printing error messages.
--verbose level
Set the diagnostics verbosity to level between 0 and 6.
--stdout-format format
Representation format to use for printing to stdout.
--jobs|-j num
Number of jobs to perform in parallel.
--progress
Display progress indicators for long-lasting operations, such as network transfers, building, etc.
--no-progress
Suppress progress indicators for long-lasting operations, such as network transfers, building, etc.
--diag-color
Use color in diagnostics.
--no-diag-color
Don't use color in diagnostics.
--bpkg path
The package manager program to be used for build configuration management.
--bpkg-option opt
Additional option to be passed to the package manager program.
--build path
The build program to be used to build packages.
--build-option opt
Additional option to be passed to the build program.
--curl path
The curl program to be used for network operations.
--curl-option opt
Additional option to be passed to the curl program.
--pager path
The pager program to be used to show long text.
--pager-option opt
Additional option to be passed to the pager program.
--options-file file
Read additional options from file.
--default-options dir
The directory to load additional default options files from.
--no-default-options
Don't load default options files.

DEFAULT OPTIONS FILES

See bdep-default-options-files(1) for an overview of the default options files. For the ci command the search start directory is the project directory. The following options files are searched for in each directory and, if found, loaded in the order listed:

bdep.options
bdep-ci.options

The following ci command options cannot be specified in the default options files:

--directory|-d
