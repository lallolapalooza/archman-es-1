DESCRIPCIÓN basic_ldap_auth permite a Squid conectarse a un directorio LDAP para validar el nombre de usuario y la contraseña de la autenticación HTTP Basic. Las opciones LDAP se especifican como parámetros en la línea de comandos, mientras que los nombres de usuario y contraseñas que se verificarán contra el directorio LDAP se especifican en líneas posteriores de entrada al ayudante, un par de nombre de usuario/contraseña por línea separado por un espacio. Como se espera por el constructo de autenticación básica de Squid, después de especificar un nombre de usuario y una contraseña seguidos de una nueva línea, este ayudante producirá OK o ERR en la siguiente línea para mostrar si las credenciales especificadas son correctas según el directorio LDAP. El programa tiene dos modos principales de operación. En el modo de operación predeterminado, el DN del usuario se construye utilizando el DN base y el atributo de usuario. En el otro modo de operación, se utiliza un filtro de búsqueda para localizar los DN de usuarios válidos por debajo del DN base.

GURACIÓN
Para directorios que usan el diseño RFC2307 con
un solo dominio, todo lo que normalmente neces
ita especificar es el DN base bajo el cual se en
cuentran sus usuarios y el nombre del servidor:

basic_ldap_auth -b ou=people,dc=your,dc=domain

ldapserver

Si tiene subdominios, entonces necesita usar un enfoque de filtro de búsqueda para localizar sus DN de usuarios, ya que estos ya no pueden construirse directamente a partir del DN base y el nombre de inicio de sesión

solamente:
basic_ldap_auth -b dc=your,dc=domain -f uid=%s
ldapserver

Y de manera similar, si solo desea permitir el acceso a usuarios que tengan un atributo

específico
basic_ldap_auth -b dc=your,dc=domain -f (&(uid=%s)(specialattribute=value))
ldapserver

O si el atributo de usuario del DN del usuario

es
c
n

en lugar de uid y no quiere tener que buscar los usuarios, podría usar algo como el siguiente ejemplo para Active

Directory:
basic_ldap_auth -u cn -b cn=Users,dc=your,dc=domain
ldapserver

Si desea buscar el DN del usuario y su directorio no permite búsquedas anónimas, entonces también debe usar las -D y -w banderas para especificar un DN de usuario y una contraseña con los que iniciar sesión para realizar las búsquedas, como en el siguiente complejo ejemplo de Active Directory:ejemplo de historia

basic_ldap_auth -P -R -b dc=your,dc=domain -D cn=squid,cn=users,dc=your,dc=domain -w secretsquidpassword -f (&(userPrincipalName=%s)(objectClass=Person)) activedirectoryserver

NOTA: Al construir filtros de búsqueda, se recomienda encarecidamente probar el filtro utilizando ldapsearch antes de intentar usar basic_ldap_auth. Esto es para verificar que el filtro coincida con lo que espera.
