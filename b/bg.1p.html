BG(1P) Manual del Programador POSIX BG(1P)

PRÓLOGO

Esta página del manual forma parte del Manual del Programador POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página del manual de Linux correspondiente para detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

bg — ejecutar trabajos en segundo plano

SINOPSIS

bg [job_id...]

DESCRIPCIÓN

Si el control de trabajos está habilitado (véase la descripción de set -m), la utilidad bg reanudará los trabajos suspendidos del entorno actual (véase Sección 2.12, Entorno de Ejecución del Shell) ejecutándolos como trabajos en segundo plano. Si el trabajo especificado por job_id ya es un trabajo en segundo plano en ejecución, la utilidad bg no tendrá ningún efecto y terminará con éxito.

Usar bg para colocar un trabajo en segundo plano hará que su ID de proceso se convierta en «conocido en el entorno de ejecución del shell actual», como si se hubiera iniciado como una lista asíncrona; véase Sección 2.9.3.1, Ejemplos.

OPCIONES

Ninguna.

OPERANDOS

Se admitirá el siguiente operando:

job_id
Especifica el trabajo que se reanudará como trabajo en segundo plano. Si no se proporciona el operando job_id , se usará el trabajo suspendido más reciente. El formato de job_id está descrito en el Volumen de Definiciones Base de POSIX.1‐2017, Sección 3.204, ID de Trabajo del Control de Trabajos.

ENTRADA ESTÁNDAR

No se usa.

ARCHIVOS DE ENTRADA

Ninguno.

VARIABLES DE ENTORNO

Las siguientes variables de entorno afectarán la ejecución de bg:

LANG
Proporciona un valor por defecto para las variables de internacionalización que no están definidas o son nulas. (Véase el Volumen de Definiciones Base de POSIX.1‐2017, Sección 8.2, Variables de Internacionalización para la precedencia de las variables de internacionalización usadas para determinar los valores de las categorías de configuración regional.)
LC_ALL
Si se establece en un valor de cadena no vacío, anula los valores de todas las demás variables de internacionalización.
LC_CTYPE
Determina la configuración regional para la interpretación de secuencias de bytes de datos de texto como caracteres (por ejemplo, caracteres de un solo byte en oposición a multibyte en los argumentos).
LC_MESSAGES

Determina la configuración regional que debe usarse para afectar el formato y el contenido de los mensajes de diagnóstico escritos en la salida de error estándar.
NLSPATH
Determina la ubicación de los catálogos de mensajes para el procesamiento de LC_MESSAGES.

EVENTOS ASÍNCRONOS

Por defecto.

SALIDA ESTÁNDAR

La salida de bg consistirá en una línea con el formato:

"[%d] %s\n", <número-de-trabajo>, <comando>

donde los campos son los siguientes:

<número-de-trabajo>
Un número que puede usarse para identificar el trabajo para las utilidades wait, fgy kill . Usando estas utilidades, el trabajo puede identificarse anteponiendo el número de trabajo con '%'.
<comando>
El comando asociado que se dio al shell.

SALIDA DE ERROR

La salida de error estándar se usará solo para mensajes de diagnóstico.

ARCHIVOS DE SALIDA

Ninguno.

DESCRIPCIÓN EXTENDIDA

Ninguna.

ESTADO DE SALIDA

Se devolverán los siguientes valores de salida:

0
Finalización exitosa.
>0
Ocurrió un error.

CONSECUENCIAS DE ERRORES

Si el control de trabajos está deshabilitado, la utilidad bg terminará con un error y ningún trabajo será colocado en segundo plano.

Las siguientes secciones son informativas.

USO DE LA APLICACIÓN

Un trabajo generalmente se suspende escribiendo el carácter SUSP (<control>‐Z en la mayoría de los sistemas); véase el Volumen de Definiciones Base de POSIX.1‐2017, Capítulo 11, Interfaz de Terminal General. En ese punto, bg puede poner el trabajo en segundo plano. Esto es más efectivo cuando el trabajo no espera ninguna entrada de terminal y su salida ha sido redirigida a archivos que no son de terminal. Se puede forzar a un trabajo en segundo plano a detenerse cuando tiene salida de terminal emitiendo el comando:

stty tostop

Un trabajo en segundo plano puede detenerse con el comando:

kill -s stop job ID

La utilidad bg no funciona como se espera cuando se ejecuta en su propio entorno de ejecución de utilidad porque ese entorno no tiene trabajos suspendidos. En los siguientes ejemplos:

... | xargs bg
(bg)

cada bg opera en un entorno diferente y no comparte la comprensión de trabajos de su shell padre. Por esta razón, bg generalmente se implementa como un comando incorporado regular del shell.

JUSTIFICATIVA

Las extensiones al shell especificadas en este volumen de POSIX.1‐2017 se han basado principalmente en características proporcionadas por el KornShell. Las características de control de trabajos proporcionadas por bg, fgy jobs también se basan en el KornShell. Los desarrolladores de estándares examinaron las características de las versiones de estas utilidades del C shell y encontraron que existen diferencias. A pesar del uso generalizado del C shell, se seleccionaron las versiones del KornShell para este volumen de POSIX.1‐2017 para mantener un grado de uniformidad con el resto de las características del KornShell seleccionadas (como las muy populares características de edición de línea de comandos).

Se espera que la utilidad bg ajuste su salida si la salida excede el número de columnas de pantalla.
