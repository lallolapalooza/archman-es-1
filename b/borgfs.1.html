NOMBRE

borgfs - Montar archivo o un repositorio completo como un sistema de archivos FUSE

SINOPSIS

borgfs [opciones] REPOSITORIO_O_ARCHIVO PUNTO_DE_MONTAJE [RUTA...]

DESCRIPCION

Este comando monta un repositorio o un archivo como un sistema de archivos FUSE. Esto puede ser útil para explorar o restaurar archivos individuales.

Al restaurar, ten en cuenta que la implementación actual de FUSE no soporta indicadores especiales del sistema de archivos ni ACLs.

Al montar un repositorio, los directorios superiores se nombrarán como los archivos y la estructura de directorios debajo de estos se cargará bajo demanda desde el repositorio al entrar en estos directorios, así que espera alguna demora.

A menos que se proporcione la opción --foreground, el comando se ejecutará en segundo plano hasta que el sistema de archivos se desmonte.

Consejos de rendimiento:

  • al realizar un montaje de "repositorio completo": no entres en directorios de archivos si no es necesario; esto evita la carga bajo demanda.
  • monta solo un archivo específico, no todo el repositorio.
  • monta solo rutas específicas en un archivo específico, no el archivo completo.

El comando borgfs proporciona un envoltorio para borg mount. Esto también se puede usar en entradas fstab: /ruta/a/repo /punto/de/montaje fuse.borgfs por_defecto,sin_auto 0 0

Para permitir que un usuario normal utilice entradas fstab, añade la opción user: /ruta/a/repo /punto/de/montaje fuse.borgfs por_defecto,sin_auto,user 0 0

Para la configuración de FUSE y las opciones de montaje, consulta la página de manual de mount.fuse(8).

El comportamiento predeterminado de Borg es usar los nombres de usuario y grupo archivados de cada archivo y mapearlos a los identificadores de usuario y grupo respectivos del sistema. Alternativamente, usar numeric-ids utilizará en su lugar los identificadores de usuario y grupo archivados sin ningún mapeo.

Las opciones de montaje uid y gid (implementadas por Borg) se pueden usar para anular los identificadores de usuario y grupo de todos los archivos (es decir, borg mount -o uid=1000,gid=1000).

La página de manual hace referencia a las opciones de montaje user_id y group_id (implementadas por FUSE) que especifican el identificador de usuario y grupo del propietario del montaje (también conocido como el usuario que realiza el montaje). Se establece automáticamente por libfuse (o el sistema de archivos si no se usa libfuse). Sin embargo, no debes especificarlos manualmente. A diferencia de las opciones de montaje uid y gid que afectan a todos los archivos, user_id y group_id afectan al identificador de usuario y grupo del directorio (base) montado.

Opciones de montaje adicionales soportadas por borg:

  • versions: cuando se usa con un montaje de repositorio, esto proporciona una vista fusionada y versionada de los archivos en los archivos. EXPERIMENTAL; el diseño puede cambiar en el futuro.
  • allow_damaged_files: por defecto, los archivos dañados (donde los fragmentos faltantes fueron reemplazados por secuencias de ceros por borg check --repair) no son legibles y devuelven EIO (error de E/S). Establece esta opción para leer dichos archivos.
  • ignore_permissions: por razones de seguridad, la opción de montaje default_permissions se aplica internamente por borg. ignore_permissions se puede proporcionar para no aplicar default_permissions.

La variable de entorno BORG_MOUNT_DATA_CACHE_ENTRIES está pensada para usuarios avanzados para ajustar el rendimiento. Establece el número de fragmentos de datos cacheados; el uso de memoria adicional puede ser de hasta aproximadamente 8 MiB por este número. El valor predeterminado es el número de núcleos de CPU.

Cuando el proceso demonizado recibe una señal o falla, no se desmonta. Desmontar en estos casos podría hacer que un proceso rsync activo o similar elimine datos no intencionadamente.

Cuando se ejecuta en primer plano, ^C/SIGINT desmonta limpiamente el sistema de archivos, pero otras señales o fallos no lo hacen.

Depuración:

borg mount generalmente se demoniza y el proceso demonio envía stdout/stderr a /dev/null. Por lo tanto, necesitas usar -f / --foreground para que permanezca en primer plano y no se demonice, o usar BORG_LOGGING_CONF para reconfigurar el registrador para que escriba en un archivo.

OPCIONES

Consulta borg-common(1) para ver las opciones comunes de los comandos de Borg.

argumentos

REPOSITORIO_O_ARCHIVO
repositorio o archivo a montar
PUNTO_DE_MONTAJE
dónde montar el sistema de archivos
RUTA
rutas a extraer; se admiten patrones

opciones

-V, --version
mostrar número de versión y salir
--consider-checkpoints
Mostrar archivos de puntos de control en la lista de contenidos del repositorio (predeterminado: ocultos).
-f, --foreground
permanecer en primer plano, no demonizar
-o
Opciones de montaje adicionales
--numeric-owner
obsoleto, usar --numeric-ids en su lugar
--numeric-ids
usar identificadores numéricos de usuario y grupo del/los archivo(s)

Filtros de archivo

-P PREFIJO, --prefix PREFIJO
considerar solo nombres de archivo que comiencen con este prefijo. (obsoleto)
-a GLOB, --glob-archives GLOB
considerar solo nombres de archivo que coincidan con el glob. Se aplican las reglas de sh (sin usar realmente el prefijo sh:), consulta "borg help patterns".
--sort-by CLAVES
Lista separada por comas de claves de ordenación; claves válidas son: timestamp, archive, name, id; por defecto es: timestamp
--first N
considerar los primeros N archivos después de aplicar otros filtros
--last N
considerar los últimos N archivos después de aplicar otros filtros

Opciones de Incluir/Excluir

-e PATRON, --exclude PATRON
excluir rutas que coincidan con PATRON
--exclude-from ARCHIVO_EXCLUIDO
leer patrones de exclusión de ARCHIVO_EXCLUIDO, uno por línea
--pattern PATRON
incluir/excluir rutas que coincidan con PATRON
--patterns-from ARCHIVO_PATRONES
leer patrones de inclusión/exclusión de ARCHIVO_PATRONES, uno por línea
--strip-components NÚMERO
Eliminar el número especificado de elementos de ruta iniciales. Las rutas con menos elementos se omitirán silenciosamente.
