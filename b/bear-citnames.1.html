NOMBRE

bear-citnames - deducir el significado del comando

SINOPSIS

bear citnames [opciones] --input <archivo> --output <archivo>

DESCRIPCIÓN

El nombre citnames proviene de invertir la palabra "semantic" (semántico).

Porque cuando escribes un comando, conoces tu intención. La ejecución del comando es solo un medio para lograr tu objetivo. Este programa toma el comando que se ejecutó e intenta averiguar cuál era la intención al ejecutar ese comando. Deducir el significado del comando.

Esto es útil para generar una base de datos de compilación. Citnames toma una lista de comandos y crea una base de datos de compilación en formato JSON. (Este es actualmente el único resultado de la herramienta).

OPCIONES

--version
Imprime el número de versión.
--help
Imprime el mensaje de ayuda.
--verbose
Habilita el registro detallado.
--input archivo
Especifica el archivo de entrada. (Se proporciona un nombre de archivo predeterminado). La entrada es una lista de ejecuciones de comandos, con información adicional. La sintaxis se detalla en una sección separada.
--output archivo
Especifica el archivo de salida. (Se proporciona un nombre de archivo predeterminado). La salida es actualmente una base de datos de compilación en formato JSON.
--append
Utiliza el archivo de salida generado previamente y agrega las nuevas entradas. De esta manera, puede ejecutar continuamente durante el trabajo y mantener actualizada la base de datos de compilación. Se consideran tanto la eliminación como la adición de archivos. Sin embargo, los cambios en el proceso de compilación (cambios en las banderas del compilador) podrían causar entradas duplicadas.
--run-checks
Permite al programa verificar la ubicación de los archivos en la máquina actual en la que se ejecuta. (Se proporciona el valor predeterminado. Ejecute `help` para consultarlo). Esto es importante si la lista de ejecución no proviene del host actual.
--config archivo
Especifica un archivo de configuración. El archivo de configuración captura cómo se debe formatear la salida y qué entradas debe contener.

ESTADO DE SALIDA

El estado de salida de Citnames es distinto de cero en caso de problemas de E/S, de lo contrario es cero. El estado de salida es independiente de cuántos comandos reconoció o si fueron reconocidos o no.

OBSERVABILIDAD

Cualquier información sobre la lógica de reconocimiento de comandos se puede observar con la opción --verbose en la salida de error estándar. De lo contrario, el comando es silencioso.

ARCHIVO DE ENTRADA

Es un archivo JSON, con el historial de ejecución de comandos. (Más algunos metadatos, que son útiles para depurar la aplicación que lo produjo). Este archivo puede ser producido por el comando `bear intercept`, que registra las ejecuciones de procesos de una compilación.

Lea más sobre la sintaxis del archivo en la página man de `bear-intercept(1)`.

ARCHIVO DE SALIDA

Actualmente, el único formato de salida es la base de datos de compilación en formato JSON. Lea más sobre la sintaxis de eso en la página man de `bear(1)`.

ARCHIVO DE CONFIGURACIÓN

El archivo de configuración influye en el reconocimiento de comandos (mediante la sección "compilation") y el formato de salida (mediante la sección "output").

El archivo de configuración es opcional. El programa utilizará valores predeterminados, que se pueden volcar con las opciones --verbose.

Algunas partes del archivo se superponen con los argumentos de la línea de comandos. Si ambos están presentes, el argumento de la línea de comandos anula los valores del archivo de configuración.

{
  "compilation": {
    "compilers_to_recognize": [
      {
        "executable": "/usr/bin/mpicc",
        "flags_to_add": ["-I/opt/MPI/include"],
        "flags_to_remove": ["-Wall"]
      }
    ],
    "compilers_to_exclude": []
  },
  "output": {
    "content": {
      "include_only_existing_source": true,
      "paths_to_include": [],
      "paths_to_exclude": [],
      "duplicate_filter_fields": "file_output"
    },
    "format": {
      "command_as_array": true,
      "drop_output_field": false
    }
  }
}
compilation.compilers_to_recognize
donde se puede especificar un compilador que aún no es reconocido por defecto. El ejecutable es una ruta absoluta al compilador. `flags_to_add` es un atributo opcional, que contiene banderas que se agregarán a la salida final. (Es un buen candidato para usar esto para agregar banderas de envoltura del compilador de OpenMPI de la salida `mpicc --showme:compile`). `flags_to_remove` es un atributo opcional, donde las banderas dadas se eliminarán de la lista de argumentos final. (Las banderas se verifican solo por igualdad, no hay coincidencia de expresiones regulares. Las banderas con argumentos no son buenos candidatos para poner aquí, porque la lógica de eliminación es demasiado simple para eso).
compilation.compilers_to_exclude
esta es una lista opcional de ejecutables (con ruta absoluta) que deben eliminarse de la salida.
output.content
`paths_to_include` y `paths_to_exclude` son para filtrar entradas de estos directorios. (Los nombres de los directorios pueden ser rutas absolutas o relativas al directorio de trabajo actual si se pasa la opción `--run-checks`). `include_only_existing_source` habilita o deshabilita la verificación de archivos para la salida. La opción `--run-checks` anula este valor de configuración. `duplicate_filter_fields` selecciona el método para detectar entradas duplicadas en la salida. Los valores posibles para este campo son: `all`, `file` y `file_output`.
output.format
`command_as_array` controla qué campo de comando se emite en la salida. `true` produce argumentos, `false` produce el campo de comando. `drop_output_field` deshabilitará el campo de salida de la salida.
