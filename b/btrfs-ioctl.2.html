btrfs-ioctl - documentación sobre ioctls de btrfs

NOMBRE

btrfs-ioctl - documentación para la interfaz ioctl de btrfs

DESCRIPCIÓN

La llamada al sistema ioctl() es una forma de solicitar acciones personalizadas realizadas en un sistema de archivos más allá de las interfaces estándar (como las llamadas al sistema). Un ioctl se especifica mediante un número y una estructura de datos asociada que implementan una característica, generalmente no disponible en otros sistemas de archivos. El número de ioctls crece con el tiempo y en algunos casos se promocionan a un ioctl a nivel de VFS una vez que otros sistemas de archivos adoptan la funcionalidad. Se mantiene la compatibilidad hacia atrás y un número de ioctl anteriormente privado podría estar disponible a nivel de VFS.

RESUMEN

Los ioctls se definen por un número y se asocian con una estructura de datos que contiene información adicional. Todos los ioctls utilizan un descriptor de archivo (fd) como punto de referencia, podría ser el sistema de archivos o un directorio dentro del sistema de archivos.

Un ioctl se puede usar en la siguiente forma esquemática:

struct btrfs_ioctl_args args;
memset(&args, 0, sizeof(args));
args.key = value;
ret = ioctl(fd, BTRFS_IOC_NUMBER, &args);

El fd es el punto de entrada al sistema de archivos y para la mayoría de los ioctls no importa qué directorio sea ese. Una distinción entre archivos y directorios a veces importa, cuando importa se menciona explícitamente. El args es la estructura de datos asociada para la solicitud. Se recomienda encarecidamente inicializar toda la estructura a ceros, ya que esto garantiza la compatibilidad futura cuando el ioctl reciba más extensiones. No hacer esto podría llevar a una incompatibilidad entre versiones antiguas de espacio de usuario y nuevas del kernel, o viceversa. El BTRFS_IOC_NUMBER indica qué operación se debe realizar con los argumentos dados. Algunos ioctls toman una estructura de datos específica, algunos comparten una común, y también existen ioctls sin estructura de argumentos. Los datos pasados a un ioctl pueden ser de entrada, de salida o ambos.

La biblioteca libbtrfsutil encapsula algunos ioctls por conveniencia. El uso de ioctls directos no está desaconsejado pero puede ser engorroso, aunque no necesita una dependencia adicional de la biblioteca. Se garantiza la compatibilidad hacia atrás y los cambios incompatibles generalmente conducen a una nueva versión del ioctl. Las mejoras de ioctls existentes pueden ocurrir y dependen de la configuración de indicadores adicionales. El espacio no utilizado puesto a cero se entiende comúnmente como un mecanismo para comunicar la compatibilidad entre el kernel y el espacio de usuario, y por lo tanto, poner a cero es realmente importante. En casos excepcionales, esto no es suficiente y se deben pasar indicadores adicionales para distinguir entre cero como inicialización implícita no utilizada y un valor cero válido. Tales casos están documentados.

Los descriptores de archivo de archivos regulares se obtienen mediante int fd = open(), los directorios abiertos como DIR *dir = opendir() se pueden convertir al descriptor de archivo correspondiente mediante fd = dirfd(dir).
