NOMBRE

bdep-new - crear e inicializar nuevo proyecto

SINOPSIS

bdep new [opciones] [--no-init] espec [nombre]
bdep new [opciones] --config-add|-A dir-cfg [@nombre-cfg] espec [nombre]
bdep new [opciones] --config-create|-C dir-cfg [@nombre-cfg] espec [nombre]
         [args-cfg]
bdep new [opciones] --package [espec-pr] espec [nombre]
bdep new [opciones] --source [espec-pr] espec [nombre]

espec     = [lang] [tipo] [vcs]
lang     = --lang|-l (c|c++)[,opt-lang...]
tipo     = --type|-t (exe|lib|bare|empty)[,opt-tipo...]
vcs      = --vcs|-s (git|none)[,opt-vcs...]
espec-pr = --directory|-d dir-pr
args-cfg = [-- [opc-bpkg]] [--existing|-e | (módulo | var-cfg)...]

DESCRIPCIÓN

El comando new crea e inicializa un nuevo proyecto (las tres primeras formas), un nuevo paquete en un proyecto ya existente (la forma --package), o un nuevo subdirectorio fuente en un proyecto/paquete ya existente (la forma --source). Todas las formas excepto --source primero crean, según espec, un nuevo proyecto/paquete build2 llamado nombre en el subdirectorio nombre del directorio de trabajo actual (a menos que se anule con --output-dir|-o o, en el caso de --package, con --directory|-d). Si nombre contiene un componente de directorio, entonces el proyecto/paquete se crea en este directorio, como si se hubiera especificado con --output-dir|-o.

La primera forma, a menos que se especifique la opción --no-init, inicializa una base de datos de proyecto vacía como si se ejecutara el comando bdep-init(1) con la opción --empty. Por ejemplo:

$ bdep new -l c++ -t exe hello
$ tree hello/
hello/
|-- hello/
|   |-- hello.cxx
|   `-- buildfile
|-- buildfile
`-- manifest

De manera similar, la segunda y tercera forma añaden una configuración de compilación existente o crean una nueva y luego inicializan el proyecto en esa configuración como si se ejecutara el comando bdep-init(1) con la opción --config-add o --config-create respectivamente. Por ejemplo:

$ bdep new -l c++ -t exe -C @gcc hello cc config.cxx=g++

La forma --package añade el nuevo paquete al archivo packages.manifest creándolo si es necesario. Si no se especifica explícitamente ningún directorio de proyecto con --directory|-d, entonces se deducirá del directorio de trabajo actual (ver bdep-projects-configs(1) para detalles sobre la especificación de proyectos). Tenga en cuenta que no se permiten paquetes anidados. Por ejemplo:

$ bdep new -t empty hello
$ cd hello
$ bdep new --package -l c++ -t lib libhello
$ bdep new --package -l c++ -t exe hello
$ bdep init -C @gcc cc config.cxx=g++
$ cd ..
$ tree hello/
hello/
|-- hello/
|   |-- hello/
|   |   |-- hello.cxx
|   |   `-- buildfile
|   |-- buildfile
|   `-- manifest
|-- libhello/
|   |-- libhello/
|   |   |-- hello.hxx
|   |   |-- hello.cxx
|   |   `-- buildfile
|   |-- buildfile
|   `-- manifest
`-- packages.manifest

La forma --source opera *como si* primero creara, según espec, un proyecto temporal llamado nombre y luego copiara su subdirectorio fuente (nombre/nombre/ por defecto) al directorio de trabajo actual (a menos que se anule con --output-dir|-o). Si no se especifica explícitamente ningún directorio de proyecto/paquete con --directory|-d, entonces se asume el directorio de trabajo actual. Por ejemplo:

$ bdep new -l c++ -t bare hello
$ cd hello
$ bdep new --source -l c++ -t lib libhello
$ bdep new --source -l c++ -t exe hello
$ bdep init -C @gcc cc config.cxx=g++
$ cd ..
$ tree hello/
hello/
|-- hello/
|   |-- hello.cxx
|   `-- buildfile
|-- libhello/
|   |-- hello.hxx
|   |-- hello.cxx
|   `-- buildfile
|-- buildfile
`-- manifest

En todas las formas, si se omite nombre, entonces se utiliza el nombre del directorio de trabajo actual (a menos que se anule con --output-dir|-o) como nombre del subdirectorio del proyecto/paquete/fuente. Ver Nombre de Paquete (#package-name) para detalles sobre los nombres de proyectos/paquetes.

El subdirectorio fuente puede personalizarse con la subopción del tipo de proyecto subdir (ver más abajo para detalles). Por ejemplo:

$ bdep new -l c++ -t lib,subdir=libhello/io libhello-io
$ tree libhello-io/
libhello-io/
`-- libhello/
    `-- io/
        |-- hello-io.hxx
        `-- hello-io.cxx

Por defecto, el subdirectorio fuente se crea en el directorio raíz del proyecto/paquete y contiene tanto cabeceras (incluyendo cabeceras públicas para bibliotecas) como fuentes. Esto se puede personalizar de varias maneras utilizando las subopciones prefix* y split del tipo de proyecto (ver más abajo para detalles). Por ejemplo, para mover el subdirectorio fuente dentro de src/:

$ bdep new -l c++ -t exe,prefix=src hello
$ tree hello/
hello/
`-- src/
    `-- hello/
        `-- hello.cxx

Y para dividir el subdirectorio fuente de la biblioteca en cabeceras públicas y otros archivos fuente:

$ bdep new -l c++ -t lib,split libhello
$ tree libhello/
libhello/
|-- include/
|   `-- libhello/
|       `-- hello.hxx
`-- src/
    `-- libhello/
        `-- hello.cxx

Ver la sección DISEÑO DE FUENTE para detalles y más ejemplos.

El directorio de salida puede contener ya archivos existentes siempre que no entren en conflicto con los archivos a crear. El comando new también reconoce ciertos archivos conocidos e intenta usar la información extraída en el archivo manifest del paquete. Específicamente, intenta adivinar la licencia del archivo LICENSE así como extraer el resumen de README.md. Esto permite el siguiente flujo de trabajo:

# Crear un proyecto con LICENSE y README.md en uno de los servicios de
# alojamiento Git (GitHub, GitLab, etc.).
$ git clone .../libhello.git
$ cd libhello
$ bdep new -l c++ -t lib

Los parámetros del proyecto como el lenguaje, tipo (ejecutable, biblioteca, etc.) y sistema de control de versiones se pueden personalizar como se describe a continuación. Algunos de estos parámetros también admiten subopciones específicas del parámetro (como las extensiones de archivo a usar en un proyecto C++) que se pueden especificar con una coma después del valor del parámetro.

El lenguaje del proyecto se puede especificar con la opción --lang|-l. Los valores válidos para esta opción y sus semánticas se describen a continuación. Si no se especifica, se crea un proyecto C++ por defecto.

El proyecto, paquete o subdirectorio de código fuente creado puede personalizarse aún más usando los ganchos pre y post-creación especificados con las opciones --pre-hook y --post-hook, respectivamente. Los ganchos pre se ejecutan antes de que se cree ningún archivo nuevo y el gancho post – después de que se hayan creado todos los archivos. Los comandos de los ganchos se ejecutan en el directorio del proyecto, paquete o código fuente como su directorio de trabajo actual. Por

ejemplo: 
$ bdep new --post-hook "echo .idea/ >>.gitignore"
hello

Los ganchos pre son principalmente útiles para mover/renombrar archivos existentes que de otro modo entrarían en conflicto con los archivoscreado por el comando new. Por ejemplo:

$ bdep new --pre-hook  "mv .gitignore .gitignore.bak" \
           --post-hook "cat .gitignore.bak >>.gitignore" \
           --post-hook "rm .gitignore.bak" ...

Ver la documentación de las opciones --pre-hook y --post-hook a continuación para más detalles.

NUEVAS OPCIONES

--no-init
No inicializar un conjunto de configuración de compilación vacío.
--package
Crear un nuevo paquete dentro de un proyecto ya existente en lugar de un proyecto nuevo.
--source
Crear un nuevo subdirectorio de fuente dentro de un proyecto o paquete ya existente en lugar de un proyecto nuevo.
--output-dir|-o dir
Crear el proyecto, paquete o subdirectorio de fuente en el directorio especificado.
--directory|-d dir
Asumir que el proyecto/paquete está en el directorio especificado en lugar del directorio de trabajo actual. Solo se usa con --package o --source.
--type|-t type[,opt...]
Especificar el tipo de proyecto y opciones. Los valores válidos para type son exe (proyecto ejecutable, por defecto), lib (proyecto de biblioteca), bare (proyecto vacío sin código fuente) y empty (proyecto vacío listo para ser llenado con paquetes). Los valores válidos para opt son específicos del tipo.
--lang|-l lang[,opt...]
Especificar el lenguaje del proyecto y opciones. Los valores válidos para lang son c y c++ (por defecto). Los valores válidos para opt son específicos del lenguaje.
--vcs|-s vcs[,opt...]
Especificar el sistema de control de versiones del proyecto y opciones. Los valores válidos para vcs son git (por defecto) y none. Los valores válidos para opt son específicos del sistema.
--pre-hook command
--post-hook command
Ejecutar el comando especificado antes/después de crear el proyecto, paquete o directorio fuente.

El valor de command se interpreta como una línea de comando separada por espacios, potencialmente entrecomillada, que consiste en un programa o un comando integrado portable (testscript#builtins) seguido opcionalmente por argumentos y redirecciones. Específicamente, un solo nivel de comillas (simples o dobles) se elimina y los espacios no se tratan como separadores dentro de dichos fragmentos entrecomillados. Actualmente solo se admite la redirección de stdout a un archivo. Por ejemplo:

$ bdep new --post-hook "echo '.idea/ # IDE' >>.gitignore" hello

Los elementos de la línea de comandos (programa, argumentos, etc.) pueden contener opcionalmente sustituciones – nombres de variables encerrados entre el símbolo de sustitución @ – que se reemplazan con los valores de variables correspondientes para producir el comando real. Los siguientes nombres de variables se reconocen, sirviendo el doble símbolo de sustitución (@@) como secuencia de escape.

@mode@ - uno de 'project', 'package', o 'source'
@name@ - nombre del proyecto, paquete o subdirectorio fuente
@base@ - base del nombre (nombre sin extensión)
@stem@ - tallo del nombre (base del nombre sin el prefijo 'lib')
@root@ - directorio raíz del proyecto/paquete
@pfx@  - prefijo combinado relativo a la raíz del proyecto/paquete
@inc@  - prefijo de cabecera dividido relativo a la raíz del proyecto/paquete
@src@  - prefijo de fuente dividido relativo a la raíz del proyecto/paquete
@sub@  - subdirectorio fuente relativo al prefijo de cabecera/fuente
@type@ - valor de --type|-t: 'exe', 'lib', etc.
@lang@ - valor de --lang|-l: 'c', 'c++', etc.
@vcs@  - valor de --vcs|-s: 'git', etc.

Tenga en cuenta que las variables @inc@ y @src@ solo se establecen si el prefijo de cabecera/fuente se divide con la variable combinada @pfx@; de lo contrario, se establece la variable combinada.

Por ejemplo:

$ bdep new --post-hook "echo bin/ >>@name@/.gitignore" hello

Estas variables de sustitución también están disponibles para el programa de hook como variables de entorno BDEP_NEW_* (BDEP_NEW_MODE, BDEP_NEW_NAME, etc.).
