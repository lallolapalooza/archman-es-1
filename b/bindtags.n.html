NOMBRE

bindtags - Determinar qué enlaces se aplican a una ventana y el orden de evaluación

SINOPSIS

bindtags ventana ?listaEtiquetas?

DESCRIPCIÓN

Cuando se crea un enlace con el comando bind, se asocia ya sea a una ventana particular como .a.b.c, un nombre de clase como Button, la palabra clave all, o cualquier otra cadena. Todas estas formas se llaman etiquetas de enlace. Cada ventana contiene una lista de etiquetas de enlace que determinan cómo se procesan los eventos para la ventana. Cuando ocurre un evento en una ventana, se aplica a cada una de las etiquetas de la ventana en orden: para cada etiqueta, se ejecuta el enlace más específico que coincida con la etiqueta y el evento dados. Consulte el comando bind para obtener más información sobre el proceso de coincidencia.

Por defecto, cada ventana tiene cuatro etiquetas de enlace que consisten en el nombre de la ventana, el nombre de la clase de la ventana, el nombre del antepasado de nivel superior más cercano de la ventana y all, en ese orden. Las ventanas de nivel superior solo tienen tres etiquetas por defecto, ya que el nombre de nivel superior es el mismo que el de la ventana. El comando bindtags permite leer y modificar las etiquetas de enlace de una ventana.

Si bindtags se invoca con un solo argumento, se devuelve el conjunto actual de etiquetas de enlace para ventana como una lista. Si se especifica el argumento listaEtiquetas a bindtags, entonces debe ser una lista correcta; las etiquetas para ventana se cambian a los elementos de la lista. Los elementos de listaEtiquetas pueden ser cadenas arbitrarias; sin embargo, cualquier etiqueta que comience con un punto se trata como el nombre de una ventana; si no existe ninguna ventana con ese nombre en el momento en que se procesa un evento, entonces la etiqueta se ignora para ese evento. El orden de los elementos en listaEtiquetas determina el orden en que se ejecutan los scripts de enlace en respuesta a los eventos. Por ejemplo, el comando

bindtags .b {all . Button .b}
invierte el orden en que se evaluarán los scripts de enlace para un botón llamado .b de modo que los enlaces all se invoquen primero, seguidos de los enlaces para el nivel superior de .b (“.”), seguidos de los enlaces de clase, seguidos de los enlaces para .b. Si listaEtiquetas es una lista vacía, las etiquetas de enlace para ventana vuelven al estado predeterminado descrito anteriormente.

El comando bindtags se puede usar para introducir etiquetas de enlace adicionales arbitrarias para una ventana, o para eliminar etiquetas estándar. Por ejemplo, el comando

bindtags .b {.b TrickyButton . all}
reemplaza la etiqueta Button para .b con TrickyButton. Esto significa que los enlaces de widget predeterminados para los botones, que están asociados con la etiqueta Button, ya no se aplicarán a .b, pero cualquier enlace asociado con TrickyButton (quizás algún comportamiento nuevo del botón) se aplicará.

EJEMPLO

Si tiene un conjunto de widgets frame anidados y desea que los eventos enviados a un widget button también se entreguen a todos los widgets hasta el toplevel actual (en contraste con el comportamiento predeterminado de Tk, donde los eventos no se entregan a esas ventanas intermedias) para facilitar la creación de aceleradores que solo estén activos para parte de una ventana, podría usar un procedimiento auxiliar como este para ayudar a configurarlo:

proc setupBindtagsForTreeDelivery {widget} {
    set tags [list $widget [winfo class $widget]]
    set w $widget
    set t [winfo toplevel $w]
    while {$w ne $t} {
        set w [winfo parent $w]
        lappend tags $w
    }
    lappend tags all
    bindtags $widget $tags
}
