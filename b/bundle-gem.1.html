NOMBRE

bundle-gem - Genera un esqueleto de proyecto para crear un rubygem

SINOPSIS

bundle gem NOMBRE_GEM OPCIONES

DESCRIPCIÓN

Genera un directorio llamado NOMBRE_GEM con un Rakefile, NOMBRE_GEM.gemspec, y otros archivos y directorios de soporte que pueden ser usados para desarrollar un rubygem con ese nombre.

Ejecuta rake -T en el proyecto resultante para obtener una lista de tareas Rake que pueden ser usadas para probar y publicar el gem en rubygems.org.

El esqueleto de proyecto generado puede ser personalizado con OPCIONES, como se explica a continuación. Ten en cuenta que estas opciones también pueden ser especificadas a través del archivo de configuración global de Bundler usando los siguientes nombres:

  • gem.coc
  • gem.mit
  • gem.test

OPCIONES

--exe, --bin, -b
Especifica que Bundler debe crear un ejecutable binario (como exe/NOMBRE_GEM) en el proyecto de rubygem generado. Este binario también se añadirá al manifiesto de NOMBRE_GEM.gemspec. Este comportamiento está deshabilitado por defecto.
--no-exe
No crear un binario (anula --exe especificado en la configuración global).
--coc
Añade un archivo CODE_OF_CONDUCT.md a la raíz del proyecto generado. Si esta opción no se especifica, se mostrará una solicitud interactiva y la respuesta se guardará en la configuración global de Bundler para su uso futuro en bundle gem.
--no-coc
No crear un CODE_OF_CONDUCT.md (anula --coc especificado en la configuración global).
--changelog
Añade un archivo CHANGELOG.md a la raíz del proyecto generado. Si esta opción no se especifica, se mostrará una solicitud interactiva y la respuesta se guardará en la configuración global de Bundler para su uso futuro en bundle gem. Actualiza el valor predeterminado con bundle config set --global gem.changelog <true|false>.
--no-changelog
No crear un CHANGELOG.md (anula --changelog especificado en la configuración global).
--ext=c, --ext=rust
Añade código base para extensiones C o Rust (actualmente basado en magnus https://docs.rs/magnus) al proyecto generado. Este comportamiento está deshabilitado por defecto.
--no-ext
No añadir código de extensión (anula --ext especificado en la configuración global).
--git
Inicializa un repositorio git dentro de tu librería.
--github-username=NOMBRE_USUARIO_GITHUB
Rellena el nombre de usuario de GitHub en README para que no tengas que hacerlo manualmente. Establece un valor predeterminado con bundle config set --global gem.github_username <tu_usuario>.
--mit
Añade una licencia MIT a un archivo LICENSE.txt en la raíz del proyecto generado. Tu nombre de la configuración git global se utiliza para la declaración de derechos de autor. Si esta opción no se especifica, se mostrará una solicitud interactiva y la respuesta se guardará en la configuración global de Bundler para su uso futuro en bundle gem.
--no-mit
No crear un LICENSE.txt (anula --mit especificado en la configuración global).
-t, --test=minitest, --test=rspec, --test=test-unit
Especifica el framework de pruebas que Bundler debe usar al generar el proyecto. Los valores aceptables son minitest, rspec y test-unit. El NOMBRE_GEM.gemspec se configurará y se creará un directorio de esqueleto de pruebas/especificaciones basado en esta opción. Si no se especifica ninguna opción:
Cuando Bundler está configurado para generar pruebas, esto se establece por defecto en la configuración global de Bundler gem.test.
Cuando Bundler está configurado para no generar pruebas, se mostrará una solicitud interactiva y la respuesta se utilizará para el proyecto de rubygem actual.
Cuando Bundler no está configurado, se mostrará una solicitud interactiva y la respuesta se guardará en la configuración global de Bundler para su uso futuro en bundle gem.
--no-test
No usar un framework de pruebas (anula --test especificado en la configuración global).
--ci, --ci=circle, --ci=github, --ci=gitlab
Especifica el servicio de integración continua que Bundler debe usar al generar el proyecto. Los valores aceptables son github, gitlab y circle. Se generará un archivo de configuración en el directorio del proyecto. Si no se especifica ninguna opción:
Cuando Bundler está configurado para generar archivos CI, esto se establece por defecto en la configuración global de Bundler gem.ci.
Cuando Bundler está configurado para no generar archivos CI, se mostrará una solicitud interactiva y la respuesta se utilizará para el proyecto de rubygem actual.
Cuando Bundler no está configurado, se mostrará una solicitud interactiva y la respuesta se guardará en la configuración global de Bundler para su uso futuro en bundle gem.
--no-ci
No usar un servicio de integración continua (anula --ci especificado en la configuración global).
--linter, --linter=rubocop, --linter=standard
Especifica el linter y formateador de código que Bundler debe añadir a las dependencias de desarrollo del proyecto. Los valores aceptables son rubocop y standard. Se generará un archivo de configuración en el directorio del proyecto. Si no se especifica ninguna opción:
Cuando Bundler está configurado para añadir un linter, esto se establece por defecto en la configuración global de Bundler gem.linter.
Cuando Bundler está configurado para no añadir un linter, se mostrará una solicitud interactiva y la respuesta se utilizará para el proyecto de rubygem actual.
Cuando Bundler no está configurado, se mostrará una solicitud interactiva y la respuesta se guardará en la configuración global de Bundler para su uso futuro en bundle gem.
--no-linter
No añadir un linter (anula --linter especificado en la configuración global).
--rubocop
Añade rubocop al Rakefile y gemspec generados. Establece un valor predeterminado con bundle config set --global gem.rubocop true.
--edit=EDIT, -e=EDIT
Abre el NOMBRE_GEM.gemspec resultante en EDIT, o en el editor predeterminado si no se especifica. El valor predeterminado es $BUNDLER_EDITOR, $VISUAL, o $EDITOR.
--bundle
Ejecuta bundle install después de crear el gem.
--no-bundle
No ejecutar bundle install después de crear el gem.
