Sufijos de unidad opcionales [k|K|m|M|g|G|t|T] (predeterminado: M). Las minúsculas son base 1000 mientras que las mayúsculas son base 1024.

-onlynet=<red>

Realizar conexiones salientes automáticas solo a la red <red> (ipv4, ipv6, onion, i2p, cjdns). Las conexiones entrantes y manuales no se ven afectadas por esta opción. Se puede especificar varias veces para permitir múltiples redes.

-peerblockfilters

-peerbloomfilters

-port=<puerto>

Escuchar conexiones en el <puerto> (predeterminado: 8333, testnet3: 18333, testnet4: 48333, signet: 38333, regtest: 18444). No relevante para I2P (ver doc/i2p.md). Si se establece en un valor x, el puerto de escucha onion predeterminado se establecerá en x+1.

-proxy=<ip:puerto|ruta>

Conectarse a través de un proxy SOCKS5, establecer -noproxy para deshabilitar (predeterminado: deshabilitado). Puede ser una ruta de archivo local prefijada con 'unix:' si el proxy lo soporta.

-proxyrandomize

Aleatorizar credenciales para cada conexión de proxy. Esto habilita el aislamiento de streams de Tor (predeterminado: 1)

-seednode=<ip>

Conectarse a un nodo para obtener direcciones de pares y desconectarse. Esta opción se puede especificar varias veces para conectarse a varios nodos. Durante el inicio, se intentarán los nodos semilla antes que los nodos DNS.

-timeout=<n>

Especificar el tiempo de espera de conexión del socket en milisegundos. Si un intento inicial de conexión no tiene éxito después de esta cantidad de tiempo, se cancela (mínimo: 1, predeterminado: 5000)

-torcontrol=<ip>:<puerto>

Host y puerto de control de Tor a utilizar si la escucha onion está habilitada (predeterminado: 127.0.0.1:9051). Si no se especifica puerto, se usará el puerto predeterminado 9051.

-torpassword=<pass>

Contraseña del puerto de control de Tor (predeterminado: vacío)

-upnp

Utilizar UPnP para mapear el puerto de escucha (predeterminado: 0)

-v2transport

Soportar transporte v2 (predeterminado: 1)

-whitebind=<[permisos@]dir>

Enlazar a la dirección dada y añadir permisos a los pares que se conecten a ella. Usar la notación [host]:puerto para IPv6. Permisos permitidos: bloomfilter (permitir solicitar bloques y transacciones filtradas por BIP 37), noban (no banear por mal comportamiento; implica download), forcerelay (retransmitir transacciones que ya están en el mempool; implica relay), relay (retransmitir incluso en modo -blocksonly, y anuncios de transacciones ilimitados), mempool (permitir solicitar contenido del mempool BIP 35), download (permitir getheaders durante IBD, no desconectar después del límite de maxuploadtarget), addr (las respuestas a GETADDR evitan el caché y contienen registros aleatorios con la información más actualizada). Especificar múltiples permisos separados por comas (predeterminado: download,noban,mempool,relay). Se puede especificar varias veces.

-whitelist=<[permisos@]dirección IP o red>

Añadir permisos a los pares que usan la dirección IP dada (ej. 1.2.3.4) o red con notación CIDR (ej. 1.2.3.0/24). Usa los mismos permisos que -whitebind. Los permisos adicionales "in" y "out" controlan si los permisos se aplican a conexiones entrantes y/o manuales (predeterminado: solo entrantes). Se puede especificar varias veces.

Opciones de la billetera:

-addresstype

Qué tipo de direcciones usar ("legacy", "p2sh-segwit", "bech32", o "bech32m", predeterminado: "bech32")

-avoidpartialspends

Agrupar salidas por dirección, seleccionando muchas (posiblemente todas) o ninguna, en lugar de seleccionar por salida individual. La privacidad mejora ya que las direcciones se barren en su mayoría con menos transacciones y las salidas se agregan en direcciones de cambio limpias. Puede resultar en comisiones más altas debido a una selección de monedas menos óptima causada por esta limitación adicional y posiblemente un número mayor de lo necesario de entradas utilizadas. Siempre habilitado para billeteras con "avoid_reuse" habilitado, de lo contrario predeterminado: 0.

-changetype

Qué tipo de cambio usar ("legacy", "p2sh-segwit", "bech32", o "bech32m"). El predeterminado es "legacy" cuando -addresstype=legacy, de lo contrario es un detalle de implementación.

-consolidatefeerate=<amt>

La tarifa de transacción máxima (en BTC/kvB) a la que la construcción de transacciones puede usar más entradas de las estrictamente necesarias para que el grupo de UTXO de la billetera pueda reducirse (predeterminado: 0.0001).

-disablewallet

No cargar la billetera y deshabilitar las llamadas RPC de la billetera.

-discardfee=<amt>

La tasa de comisión (en BTC/kvB) que indica su tolerancia a descartar cambio añadiéndolo a la comisión (predeterminado: 0.0001). Nota: Una salida se descarta si es polvo a esta tasa, pero siempre descartaremos hasta la tarifa de retransmisión de polvo y una tarifa de descarte superior a esa estará limitada por la estimación de tarifa para el objetivo más largo.

-fallbackfee=<amt>

Una tasa de comisión (en BTC/kvB) que se utilizará cuando la estimación de comisión no tenga datos suficientes. 0 para deshabilitar completamente la función de tarifa de reserva. (predeterminado: 0.00)

-keypool=<n>

Establecer el tamaño del pool de claves en <n> (predeterminado: 1000). Advertencia: Tamaños más pequeños pueden aumentar el riesgo de perder fondos al restaurar desde una copia de seguridad antigua, si ninguna de las direcciones en el pool de claves original ha sido utilizada.

-maxapsfee=<n>

Gastar hasta esta cantidad en comisiones adicionales (absolutas) (en BTC) si permite el uso de la evitación de gastos parciales (predeterminado: 0.00)

-mintxfee=<amt>

Tasas de comisión (en BTC/kvB) inferiores a esta se consideran comisión cero para la creación de transacciones (por defecto: 0.00001)

-paytxfee=<amt>

Tasa de comisión (en BTC/kvB) a añadir a las transacciones que envías (por defecto: 0.00)

-signer=<cmd>

Herramienta de firma externa, ver doc/external-signer.md

-spendzeroconfchange

Gastar cambio no confirmado al enviar transacciones (por defecto: 1)

-txconfirmtarget=<n>

Si paytxfee no está configurado, incluir suficiente comisión para que las transacciones comiencen a confirmarse en promedio dentro de n bloques (por defecto: 6)

-wallet=<path>

Especificar la ruta de la billetera a cargar al inicio. Se puede usar varias veces para cargar varias billeteras. La ruta es a un directorio que contiene los datos de la billetera y los archivos de registro. Si la ruta no es absoluta, se interpreta en relación con <walletdir>. Esto solo carga billeteras existentes y no crea nuevas. Para compatibilidad con versiones anteriores, también acepta nombres de archivos de datos de nivel superior existentes en <walletdir>.

-walletbroadcast

Hacer que la billetera transmita transacciones (por defecto: 1)

-walletdir=<dir>

Especificar el directorio para albergar las billeteras (por defecto: <datadir>/wallets si existe, de lo contrario <datadir>)

-walletnotify=<cmd>

Ejecutar comando cuando una transacción de billetera cambia. %s en cmd se reemplaza por TxID, %w se reemplaza por el nombre de la billetera, %b se reemplaza por el hash del bloque que incluye la transacción (se establece en 'unconfirmed' si la transacción no está incluida) y %h se reemplaza por la altura del bloque (-1 si no está incluida). %w no se implementa actualmente en windows. En sistemas donde %w es compatible, NO debe citarse, ya que esto rompería el escape del shell utilizado para invocar el comando.

-walletrbf

Enviar transacciones con la opción de reemplazo por comisión (RBF) completa habilitada (solo RPC, por defecto: 1)

Opciones de depuración/pruebas:

-debug=<category>

Salida de registro de depuración y seguimiento (por defecto: -nodebug, el suministro de <category> es opcional). Si no se proporciona <category> o si <category> es 1 o "all", se genera todo el registro de depuración. Si <category> es 0 o "none", se ignoran las demás categorías. Otros valores válidos para <category> son: addrman, bench, blockstorage, cmpctblock, coindb, estimatefee, http, i2p, ipc, leveldb, libevent, mempool, mempoolrej, net, proxy, prune, qt, rand, reindex, rpc, scan, selectcoins, tor, txpackages, txreconciliation, validation, walletdb, zmq. Esta opción se puede especificar varias veces para generar varias categorías.

-debugexclude=<category>

Excluir el registro de depuración y seguimiento para una categoría. Se puede usar en conjunción con -debug=1 para generar el registro de depuración y seguimiento para todas las categorías excepto la especificada. Esta opción se puede especificar varias veces para excluir varias categorías. Esto tiene prioridad sobre "-debug".

-help-debug

Imprimir mensaje de ayuda con opciones de depuración y salir

-logips

Incluir direcciones IP en la salida de depuración (por defecto: 0)

-loglevelalways

Siempre anteponer una categoría y nivel (por defecto: 0)

-logsourcelocations

Anteponer la salida de depuración con el nombre de la ubicación de origen (archivo de origen, número de línea y nombre de la función) (por defecto: 0)

-logthreadnames

Anteponer la salida de depuración con el nombre del hilo de origen (por defecto: 0)

-logtimestamps

Anteponer la salida de depuración con una marca de tiempo (por defecto: 1)

-maxtxfee=<amt>

-printtoconsole

-uacomment=<cmt>

Opciones de selección de cadena:

-chain=<chain>

Usar la cadena <chain> (por defecto: main). Valores permitidos: main, test, testnet4, signet, regtest

-signet

Usar la cadena signet. Equivalente a -chain=signet. Tenga en cuenta que la red se define por el parámetro -signetchallenge.

-signetchallenge

Los bloques deben satisfacer el script dado para ser considerados válidos (solo para redes signet; por defecto es el desafío global predeterminado de la red de prueba signet)

-signetseednode

Especificar un nodo semilla para la red signet, en formato hostname[:port], por ejemplo, sig.net:1234 (se puede usar varias veces para especificar varios nodos semilla; por defecto son los nodos semilla predeterminados globales de la red de prueba signet)

-testnet

Usar la cadena testnet3. Equivalente a -chain=test. El soporte para testnet3 está obsoleto y se eliminará en una próxima versión. Considere migrar a testnet4 ahora usando -testnet4.

-testnet4

Usar la cadena testnet4. Equivalente a -chain=testnet4.

Opciones de retransmisión de nodos:

-bytespersigop
