INTRODUCCIÓ

N

Esta página documenta el servidor BadVPN, que es utilizado en una red VPN BadVPN por los pares para comunicarse entre sí con el fin de establecer conexiones de datos. Para una descripción general de BadVPN, véase badvp

n(7
).

DESCRIPCIÓ

N

El servidor BadVPN es un servidor de chat utilizado por los nodos en la

red VPN para comunicarse entre sí con el fin de establecer conexiones de
datos. Una vez inicializado, el servidor solo termina si recibe una señal.

OPCIONE

S

El servidor BadVPN se configura completamente desde la línea de

comandos.
--he
lp
Imprime la versión y la sintaxis de la línea de comandos y
sale.
--versi
on
Imprime la versión y
sale.
--logger
<stdout/syslog>
Selecciona dónde registrar los mensajes. Por defecto es stdout. Syslog no está disponible en
Windows.
--syslog-facility
<string>
Al registrar en syslog, establece la facilidad de registro. El nombre de la facilidad debe estar en
minúsculas.
--syslog-ident
<string>
Al registrar en syslog, establece el
ident.
--loglevel <0-5/none/error/warning/notice/info/deb
ug>
Establece el nivel de registro
predeterminado.
--channel-loglevel <channel-name> <0-5/none/error/warning/notice/info/deb
ug>
Establece el nivel de registro para un canal de registro
específico.
--listen-addr
<addr>
Añade una dirección para que el servidor escuche. Véase más abajo el formato de la
dirección.
--s
sl
Usa TLS. Requiere --nssdb y --server-cert-na
me.
--nssdb
<string>
Al usar TLS, la base de datos NSS a utilizar. Probablemente algo como sql:
/some/folder.
--server-cert-name
<string>
Al usar TLS, el nombre del certificado a utilizar. El certificado debe ser fácilmente
accesible.
--comm-predicate
<string>
Establece un predicado para definir qué pares de clientes pueden comunicarse. El predicado es una expresión lógica; véase más abajo para más detalles. Funciones disponibles:
p1name(string) - verdadero si el nombre común TLS del par 1 es igual al cadena dada. Si no se usa TLS, el nombre común se asume como una cadena vacía.
p1addr(string) - verdadero si la dirección IP del par 1 es igual a la cadena dada. La cadena no debe ser un nombre.
p2name(string) - verdadero si el nombre común TLS del par 2 es igual al cadena dada. Si no se usa TLS, el nombre común se asume como una cadena vacía.
p2addr(string) - verdadero si la dirección IP del par 2 es igual a la cadena dada. La cadena no debe ser un nombre.
No hay regla sobre cuál es el par 1 y cuál el par 2. Cuando el servidor necesita determinar si permitir que dos pares se comuniquen, evalúa el predicado una vez y sin un orden
específico.
--relay-predicate
<string>
Establece un predicado para definir cómo los pares pueden retransmitir datos a través de otros pares. El predicado es una expresión lógica; véase más abajo para más detalles. Si el predicado evalúa a verdadero, el par P puede retransmitir datos a través del par R. Funciones disponibles:
pname(string) - verdadero si el nombre común TLS del par P es igual al cadena dada. Si no se usa TLS, el nombre común se asume como una cadena vacía.
paddr(string) - verdadero si la dirección IP del par P es igual a la cadena dada. La cadena no debe ser un nombre.
rname(string) - verdadero si el nombre común TLS del par R es igual al cadena dada. Si no se usa TLS, el nombre común se asume como una cadena vacía.
raddr(string) - verdadero si la dirección IP del par R es igual a la cadena dada. La cadena no debe ser un nombre.
--client-socket-sndbuf <bytes
/ 0>
Establece el valor de la opción de socket SO_SNDBUF para los sockets TCP de clientes (
cero para no establecer). Valores más bajos mejorarán la equidad cuando se envía
n datos de múltiples pares a un par dado, pero pueden resultar en un ancho de ban
da menor si el producto de ancho de banda-retardo de la red es demasiado grande.

PREDICADO

S

El servidor BadVPN incluye un pequeño lenguaje de predicados utilizado para definir ciertas políticas. La sintaxis y semántica del lenguaje se describen

aquí.
tr
ue
Constante lógica verdadera. Evalúa
a 1.
fal
se
Constante lógica falsa. Evalúa
a 0.
NOT expre
ssion
Negación lógica. Si la expresión evalúa a error, la negación evalúa a
error.
expression OR expres
sion
Disyunción lógica. La segunda expresión solo se evalúa si la primera expresión evalúa a falso. Si una sub-expresión evalúa a error, la disyunción evalúa a
error.
expression AND expre
ssion
Conjunión lógica. La segunda expresión solo se evalúa si la primera expresión evalúa a verdadero. Si una sub-expresión evalúa a error, la conjunción evalúa a
error.
function(arg, ..., arg
)
Evaluación de una función proporcionada por el usuario (function es el nombre de la función, [a-zA-Z0-9_]+). Si la función con el nombre dado no existe, evalúa a error. Los argumentos se evalúan de izquierda a derecha. Cad
a argumento puede ser una expresión lógica o una cadena (caracteres encerrados en comillas dobles, sin ninguna comilla doble). Si se encuentra un argumento, pero todos los argumentos necesarios ya han sido evaluados, la fu
nción evalúa a error. Si un argumento es de un tipo incorrecto, no se evalúa y la función evalúa a error. Si un argumento evalúa a error, la función evalúa a error. Si después de que todos los argumentos han sido evaluado
s, la función necesita más argumentos, evalúa a error. Luego se llama a la función manejadora. Si devuelve algo distinto de 1 y 0, la función evalúa a error. De lo contrario, evalúa a lo que devolvió la función manejadora.
