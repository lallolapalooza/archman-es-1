Al restaurar la propiedad, bup implementa semántica similar a tar/rsync. Normalmente preferirá nombres de usuario y grupo a uids y gids cuando estén disponibles, pero no intentará restaurar el usuario a menos que se ejecute como root, y recurrirá al uid o gid numérico siempre que los metadatos contengan un nombre de usuario o grupo que no exista en el sistema actual. El uso de nombres de usuario y grupo se puede deshabilitar mediante --numeric-ids (lo cual puede ser importante al restaurar un chroot, por ejemplo), y como caso especial, un uid o gid de 0 nunca será remapeado por nombre. Además, algunos sistemas no permiten establecer un uid/gid que no corresponda con un usuario/grupo conocido. En esos sistemas, bup registrará un error para cada ruta relevante. Las opciones --map-user, --map-group, --map-uid, --map-gid se pueden usar para ajustar la información de

propiedad

disponible antes de que se apliquen cualquiera de las reglas anteriores, pero tenga en cuenta que debido a esas reglas, --map-uid y --map-gid no tendrán efecto siempre que una ruta tenga un usuario o grupo válido. En esos casos, o bien debe especificarse --numeric-ids, o el usuario o el grupo debe ser borrado mediante un --map-user foo= adecuado o --map-group foo=. Los enlaces duros también se restaurarán cuando sea posible, pero al menos actualmente, no se harán enlaces a obj
