NOMBRE

bear-intercept - interceptar ejecuciones de comandos en el espacio de usuario.

SINOPSIS

bear intercept [opciones] -- [comando de compilación]

DESCRIPCIÓN

El comando ejecuta el comando de compilación dado y genera un archivo de salida que contiene todos los eventos relacionados con la ejecución de procesos que ocurrieron durante la compilación.

Los eventos de ejecución de procesos son: inicio, señal, terminación. La salida solo contendrá los procesos hijos. Dependiendo del modo de interceptación, la salida podría contener solo un subconjunto de los comandos ejecutados. Los modos de interceptación son:

•
preload usa los mecanismos LD_PRELOAD o DYLD_INSERT_LIBRARIES proporcionados por el enlazador dinámico. La biblioteca precargada secuestra las llamadas de ejecución de procesos y ejecuta un proceso supervisor, que informa de la ejecución. El método falla cuando el ejecutable está enlazado estáticamente o la protección de seguridad deshabilita el enlazador dinámico.
•
El modo wrapper interpone un programa envoltorio en la compilación. El envoltorio envía un informe de ejecución y llama al programa original. El método falla cuando el sistema de compilación no es lo suficientemente flexible para interponer herramientas de compilación.

Los informes son recopilados por el interceptor a través de una interfaz gRPC y escritos en un archivo de salida.

OPCIONES

--version
Imprimir el número de versión.
--help
Imprimir mensaje de ayuda.
--verbose
Habilitar registro detallado.
--output archivo
Especificar archivo de salida. (Nombre de archivo predeterminado proporcionado.) La salida es una lista de ejecución de comandos, con información adicional. La sintaxis se detalla en una sección separada.
--force-preload
Forzar el uso del método preload para interceptar los procesos hijos.
--force-wrapper
Forzar el uso del método wrapper para interceptar los procesos hijos.

ESTADO DE SALIDA

El estado de salida del programa es el estado de salida del comando de compilación. Excepto cuando el programa se bloquea, en cuyo caso se establece a un valor distinto de cero.

ARCHIVO DE SALIDA

El archivo de salida tiene formato de líneas JSON (https://jsonlines.org/), donde cada línea está terminada con el separador de línea \n y cada línea es un objeto JSON.

Los objetos JSON son eventos de ejecución de procesos: inicio de proceso, proceso recibió señal, proceso terminado. (Para el esquema de estos eventos, por favor consulte el código fuente de este proyecto).

SOLUCIÓN DE PROBLEMAS

Los problemas potenciales que puedes encontrar son: la compilación con y sin la interceptación se comporta de manera diferente (por ejemplo, la compilación falla con la herramienta de interceptación, pero tiene éxito de lo contrario). La salida está vacía y falló al interceptar la ejecución de procesos hijos por el comando de compilación.

La causa más común de salidas vacías es que el comando de compilación no ejecutó ningún comando. La razón de esto podría ser que las compilaciones incrementales no ejecutan los compiladores si todo está actualizado. Recuerda, este programa no entiende el archivo de compilación (por ejemplo, makefile), sino que intercepta los comandos ejecutados.

Puede haber muchas razones para cualquiera de estos fallos. Es mejor consultar la página wiki del proyecto para problemas conocidos, antes de abrir un informe de error.
