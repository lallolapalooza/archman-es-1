NOMBRE

btrfs-subvolume - gestionar subvolúmenes btrfs

SINOPSIS

btrfs subvolume <subcomando> [<argumentos>]

DESCRIPCIÓN

btrfs subvolume se usa para crear/eliminar/listar/mostrar subvolúmenes y instantáneas de btrfs.

Un subvolumen BTRFS es una parte del sistema de archivos con su propia jerarquía independiente de archivos/directorios y espacio de nombres de números de inodo. Los subvolúmenes pueden compartir extensiones de archivo. Una instantánea es también un subvolumen, pero con un contenido inicial dado del subvolumen original. Un subvolumen siempre tiene el número de inodo 256 (ver más en Números de inodo (en Subvolúmenes) <Subvolumes//#subvolume-inode-numbers>).

Nota:

Un subvolumen en BTRFS no es como un volumen lógico LVM, que es una instantánea a nivel de bloque, mientras que los subvolúmenes BTRFS se basan en extensiones de archivo.

Un subvolumen se parece a un directorio normal, con algunas operaciones adicionales descritas más abajo. Los subvolúmenes pueden ser renombrados o movidos, anidar subvolúmenes no está restringido pero tiene algunas implicaciones con respecto a la instantaneación. El id numérico (llamado subvolid o rootid) del subvolumen es persistente y no puede ser cambiado.

Un subvolumen en BTRFS puede ser accedido de dos maneras:

  • como cualquier otro directorio accesible para el usuario
  • como un sistema de archivos montado por separado (opciones subvol o subvolid)

En el último caso, el directorio padre no es visible ni accesible. Esto es similar a un enlace de montaje (bind mount), y de hecho el montaje del subvolumen hace exactamente eso.

Un sistema de archivos recién creado es también un subvolumen, llamado de nivel superior, internamente tiene un id 5. Este subvolumen no puede ser eliminado ni reemplazado por otro subvolumen. Este es también el subvolumen que será montado por defecto, a menos que el subvolumen por defecto haya sido cambiado (ver btrfs subvolume set-default).

Una instantánea es un subvolumen como cualquier otro, con un contenido inicial dado. Por defecto, las instantáneas se crean de solo lectura-escritura. Las modificaciones de archivos en una instantánea no afectan los archivos en el subvolumen original.

A los subvolúmenes se les pueden dar límites de capacidad, a través de la facilidad de qgroups/cuotas, pero de otro modo comparten el único almacén de datos de todo el sistema de archivos btrfs. Incluso pueden compartir datos entre sí (a través de deduplicación o instantaneación).

Nota:

Una instantánea no es una copia de seguridad: las instantáneas funcionan mediante el uso del comportamiento de copia-en-escritura (copy-on-write) de BTRFS. Una instantánea y el original del que fue tomada inicialmente comparten todos los mismos bloques de datos. Si esos datos son dañados de alguna manera (rayos cósmicos, un sector de disco defectuoso, un accidente con dd al disco), entonces la instantánea y el original serán ambos dañados. Las instantáneas son útiles para tener "copias" locales en línea del sistema de archivos a las que se puede volver a referir, o para implementar una forma de deduplicación, o para fijar el estado de un sistema de archivos para hacer una copia de seguridad completa sin que nada cambie por debajo. No hacen sus datos más seguros en sí mismos.

BANDERAS DE SUBVOLUMEN

La bandera de subvolumen actualmente implementada es la propiedad ro (estado de solo lectura). Los subvolúmenes de lectura-escritura tienen eso establecido a false, las instantáneas a true. Además de eso, una instantánea simple también tendrá la generación del último cambio y la generación de creación iguales.

Las instantáneas de solo lectura son los componentes de construcción del envío incremental (ver btrfs-send(8) <>) y todo el caso de uso se basa en instantáneas sin modificar de las cuales se generan los cambios relativos. Por lo tanto, cambiar las banderas del subvolumen de solo lectura a lectura-escritura romperá las suposiciones y puede llevar a cambios inesperados en el flujo incremental resultante.

Una instantánea que fue creada por send/receive será de solo lectura, con diferente generación del último cambio, y con establecido received_uuid que identifica el subvolumen en el sistema de archivos que produjo el flujo. El caso de uso se basa en que los datos coincidan en ambos lados. Cambiar el subvolumen a lectura-escritura después de que ha sido recibido requiere restablecer el received_uuid. Como esto es un cambio notable y podría potencialmente romper el caso de uso de envío incremental, realizarlo por btrfs property set <#man-property-set> requiere forzar si eso es realmente deseado por el usuario.

Nota:

Las comprobaciones de seguridad han sido implementadas en 5.14.2, cualquier subvolumen previamente recibido (con un received_uuidválido) y estado de lectura-escritura puede existir y aún podría llevar a problemas con send/receive. Puedes usar btrfs subvolume show para identificarlos. Cambiar las banderas a solo lectura y de vuelta a lectura-escritura restablecerá el received_uuid manualmente. Puede existir una herramienta de conveniencia en el futuro.

SUBVOLÚMENES ANIDADOS

No hay restricciones para la creación de subvolúmenes, así que depende del usuario cómo organizarlos, ya sea tener un diseño plano (todos los subvolúmenes son descendientes directos del de nivel superior), o anidados.

Lo que debería mencionarse temprano es que la instantaneación no es recursiva, así que un subvolumen o una instantánea es efectivamente una barrera y ningún archivo en los subvolúmenes anidados aparece en la instantánea. En su lugar, hay un subvolumen stub, también a veces llamado subvolumen vacío, con el mismo nombre que el subvolumen original y con número de inodo 2. Esto puede ser usado intencionalmente pero podría ser confuso en caso de diseños anidados.

$ btrfs subvolume create subvol1
$ btrfs subvolume create subvol1/subvol2
$ btrfs subvolume snapshot subvol1 snap1
$ find -ls
121093  0  drwxr-xr-x  1  user  users    24  Jul 30  12:34  .
   256  0  drwxr-xr-x  1  user  users    14  Jul 30  12:34  ./subvol1
   256  0  drwxr-xr-x  1  user  users     0  Jul 30  12:34  ./subvol1/subvol2
   257  0  -rw-r--r--  1  user  users     0  Jul 30  12:34  ./subvol1/subvol2/file
   256  0  drwxr-xr-x  1  user  users    14  Jul 30  12:34  ./snap1
     2  0  drwxr-xr-x  1  user  users     0  Jul 30  12:34  ./snap1/subvol2

Los números en las primeras columnas son números de inodo, 256 es para un subvolumen regular (o instantánea), 2 es el subvolumen vacío. El directorio instantaneado que representa subvol2 no contiene el archivo.

Nota:

El subvolumen vacío no será enviado (btrfs-send(8) <>) y por lo tanto no será creado en el lado de recepción (btrfs-receive(8) <>).

Estudio de caso: diseños de raíz del sistema

Hay dos maneras en las que el directorio raíz del sistema y el diseño de subvolúmenes podrían ser organizados. El caso de uso interesante para la raíz es permitir retrocesos a versiones anteriores, como un paso atómico. Si toda la jerarquía del sistema de archivos que comienza en / está en un subvolumen, tomar una instantánea abarcará todos los archivos. Esto es fácil para la parte de instantaneación pero tiene consecuencias indeseables para el retroceso. Por ejemplo, los archivos de registro también serían retrocedidos, o cualquier dato que esté almacenado en el sistema de archivos raíz pero que tampoco esté destinado a ser retrocedido (archivos de bases de datos, imágenes de máquinas virtuales, ...).

Aquí podríamos utilizar la barrera de instantaneación mencionada arriba, haciendo que cada directorio que almacena datos a preservar a través de los retrocesos sea su propio subvolumen. Esto podría ser, por ejemplo, /var. Una particionamiento más fino podría hacerse, por ejemplo, agregando subvolúmenes separados para /var/log, /var/cache etc.

El hecho de que haya subvolúmenes separados requiere acciones separadas para tomar las instantáneas (aquí, se desconecta de las instantáneas de la raíz del sistema). Esto necesita ser atendido por herramientas del sistema, instaladores, junto con la selección de qué directorios es altamente recomendado que sean subvolúmenes separados.

OPCIONES DE MONTAJE

Las opciones de montaje son de dos tipos, genéricas (que son manejadas por la capa VFS) y específicas, manejadas por el sistema de archivos. La siguiente lista muestra cuáles son aplicables a montajes individuales de subvolúmenes, mientras que hay más opciones que siempre afectan a todo el sistema de archivos:

  • Genéricas: noatime/relatime/..., nodev, nosuid, ro, rw, dirsync
  • Específicas del sistema de archivos: compress, autodefrag, nodatacow, nodatasum

Ejemplos de opciones de todo el sistema de archivos son, por ejemplo, space_cache, rescue, device, skip_balance, etc. Las opciones excepcionales son subvol y subvolid que en realidad son usadasd para montar un subvolumen dado y solo se puede especificar una vez para el montaje.

Los subvolúmenes pertenecen a un único sistema de archivos y, tal como están implementados ahora, todos comparten las mismas opciones de montaje específicas. Además, los cambios realizados por remount tienen efecto inmediato. Esto puede cambiar en el futuro.

Es posible montar una instantánea de solo lectura/escritura como solo lectura y esto no cambiará la propiedad y el indicador ro del subvolumen.

El nombre del subvolumen montado se almacena en el archivo /proc/self/mountinfo en la cuarta columna:

27 21 0:19 /subv1 /mnt rw,relatime - btrfs /dev/sda rw,space_cache
           ^^^^^^

NUMEROS DE INODO

Un directorio que representa un subvolumen siempre tiene el número de inodo 256 (a veces también llamado raíz del subvolumen):

$ ls -lis
total 0
389111 0 drwxr-xr-x 1 user users 0 Jan 20 12:13 dir
389110 0 -rw-r--r-- 1 user users 0 Jan 20 12:13 file
   256 0 drwxr-xr-x 1 user users 0 Jan 20 12:13 snap1
   256 0 drwxr-xr-x 1 user users 0 Jan 20 12:13 subv1

Si un subvolumen está anidado y luego se toma una instantánea, la entrada del directorio clonada que representa el subvolumen queda vacía y el inodo tiene el número 2. Todos los demás archivos y directorios en la instantánea de destino conservan sus números de inodo originales.

Nota:

El número de inodo no es un identificador único en todo el sistema de archivos, algunas aplicaciones asumen que sí lo es. Por favor, utilice el par subvolumeid:inodenumber para este propósito. El ID del subvolumen se puede leer con btrfs inspect-internal rootid <#man-inspect-rootid> o mediante el ioctl BTRFS_IOC_INO_LOOKUP <#btrfs-ioc-ino-lookup>.

RENDIMIENTO

La creación de subvolúmenes requiere vaciar los datos sucios que pertenecen al subvolumen y este paso puede llevar algún tiempo. De lo contrario, una vez que no hay nada más que hacer, la instantánea es instantánea y solo crea una nueva copia de la raíz del árbol en los metadatos.

La eliminación de instantáneas tiene dos fases: primero se elimina su directorio y el subvolumen se añade a una lista de cola, luego la lista se procesa una por una y los datos relacionados con el subvolumen se eliminan. Esto se llama generalmente limpieza y puede llevar algún tiempo dependiendo de la cantidad de bloques compartidos (puede haber muchas actualizaciones de metadatos) y el número de subvolúmenes eliminados en cola actualmente.

SUBVOLUMEN Y INSTANTANEA

Un subvolumen es una parte del sistema de archivos con su propia jerarquía independiente de archivos/directorios. Los subvolúmenes pueden compartir extensiones de archivos. Una instantánea es también un subvolumen, pero con un contenido inicial dado del subvolumen original.

Nota:

Un subvolumen en btrfs no es como un volumen lógico de LVM, que es una instantánea a nivel de bloque, mientras que los subvolúmenes de btrfs se basan en extensiones de archivo.

Un subvolumen se parece a un directorio normal, con algunas operaciones adicionales descritas a continuación. Los subvolúmenes se pueden renombrar o mover, anidar subvolúmenes no está restringido pero tiene algunas implicaciones con respecto a la toma de instantáneas.

Un subvolumen en btrfs se puede acceder de dos maneras:

  • como cualquier otro directorio accesible para el usuario
  • como un sistema de archivos montado por separado (opciones subvol o subvolid)

En este último caso, el directorio padre no es visible ni accesible. Esto es similar a un montaje bind, y de hecho el montaje de subvolumen hace exactamente eso.

Un sistema de archivos recién creado también es un subvolumen, llamado top-level, internamente tiene un ID 5. Este subvolumen no se puede eliminar ni reemplazar por otro subvolumen. Este es también el subvolumen que se montará por defecto, a menos que se haya cambiado el subvolumen predeterminado (consulte el subcomando set-default).

Una instantánea es un subvolumen como cualquier otro, con un contenido inicial dado. Por defecto, las instantáneas se crean de solo lectura/escritura. Las modificaciones de archivos en una instantánea no afectan a los archivos del subvolumen original.

SUBCOMANDO

crear [opciones] [<dest>/]<nombre> [[<dest2>/]<nombre2> ...]
Crear subvolumen(es) en el(los) destino(s).

Si no se proporciona la parte dest de la ruta, el subvolumen nombre se creará en el directorio actual.

Si se proporcionan varios destinos, las opciones dadas se aplican a todos los subvolúmenes.

Si ocurre un error para alguno de los destinos, el comando aún intentará los destinos restantes, pero devolverá 1 para indicar el fallo (similar a lo que haría mkdir).

Opciones

-i <qgroupid>
Añadir el subvolumen recién creado a un qgroup. Esta opción se puede dar varias veces.
-p|--padres
Crear cualquier directorio padre faltante para cada argumento (como mkdir -p).
eliminar [opciones] [<subvolumen> [<subvolumen>...]], eliminar -i|--subvolid <subvolid> <ruta>
Eliminar el(los) subvolumen(es) del sistema de archivos.

Si subvolumen no es un subvolumen, el comando devuelve un error pero continúa si hay más argumentos que procesar.

Si se utiliza --subvolid, ruta debe apuntar a un sistema de archivos btrfs. Consulte btrfs subvolume list o btrfs inspect-internal rootid <#man-inspect-rootid> para saber cómo obtener el ID del subvolumen.

El directorio correspondiente se elimina instantáneamente, pero los bloques de datos se eliminan más tarde en segundo plano. El comando devuelve inmediatamente. Consulte btrfs subvolume sync para saber cómo esperar hasta que el subvolumen se elimine por completo.

La eliminación no implica un commit completo de la transacción por defecto debido a razones de rendimiento. Como consecuencia, el subvolumen puede reaparecer después de un fallo. Utilice una de las opciones --commit para esperar hasta que la operación se almacene de forma segura en el dispositivo antes de que el comando devuelva.

La eliminación de subvolúmenes requiere permisos suficientes, por defecto el propietario no puede eliminarlo a menos que esté habilitado por una opción de montaje user_subvol_rm_allowed, o la eliminación se ejecute como root. El subvolumen predeterminado (consulte btrfs subvolume set-default) no se puede eliminar y devuelve un error (EPERM) y esto se registra en el registro del sistema. Un subvolumen que esté actualmente involucrado en un envío (consulte btrfs-send(8) <>) tampoco se puede eliminar hasta que el envío haya finalizado. Esto también se registra en el registro del sistema.

Opciones

-c|--commit-despues
esperar al commit de la transacción al final de la operación.
-C|--commit-cada
esperar al commit de la transacción después de eliminar cada subvolumen.
-i|--subvolid <subvolid>
ID del subvolumen a eliminar en lugar de la <ruta> que debe apuntar al sistema de archivos con el subvolumen.
-R|--recursivo
eliminar subvolúmenes debajo de cada subvolumen recursivamente.

Esto requiere CAP_SYS_ADMIN o que el sistema de archivos esté montado con la opción de montaje user_subvol_rm_allowed. En el caso no privilegiado, se omiten los subvolúmenes a los que no se puede acceder. La eliminación no es atómica.

-v|--verbose
(obsoleto) alias de la opción global -v
buscar-nuevos <subvolumen> <ultima_gen>
Listar los archivos modificados recientemente en un subvolumen, después de la generación ultima_gen.
obtener-predeterminado <ruta>
Obtener el subvolumen predeterminado del sistema de archivos ruta.

El formato de salida es similar al comando subvolume list.

listar [opciones] [-G [+|-]<valor>] [-C [+|-]<valor>] [--sort=rootid,gen,ogen,path] <ruta>
Listar los subvolúmenes presentes en el sistema de archivos ruta.

Para cada subvolumen se muestra la siguiente información por defecto:

ID ID gen generación top level ID_padre path ruta

donde ID es el ID (raíz) del subvolumen, generación es un contador interno que se actualiza en cada transacción, ID_padre es el mismo que el ID del subvolumen padre, y ruta es la ruta relativa del subvolumen a la raíz superior. El ID del subvolumen puede ser utilizado por el comando subvolume set-default, o en el momento del montaje a través de la opción subvolid=.

Opciones

Filtrado de rutas:

-o
Mostrar solo subvolúmenes debajo de la <ruta> especificada. Tenga en cuenta que este no es un comando recursivo y no mostrará subvolúmenes anidados bajo <ruta>.
-a
mostrar todos los subvolúmenes en el sistema de archivos y distinguir entre ruta absoluta y relativa con respecto a la ruta dada.

Selección de campos:

-p
mostrar el ID del padre (padre aquí significa el subvolumen que contiene este subvolumen).
-c
mostrar la ogeneración del subvolumen, alias: ogen o generación de origen.
-g
mostrar la generación del subvolumen (por defecto).
-u
mostrar el UUID del subvolumen.
-q
mostrar el UUID del padre del subvolumen (padre aquí significa el subvolumen del cual este subvolumen es una instantánea).
-R
mostrar

SUBVOLUME AND SNAPSHOT

A btrfs filesystem contains a tree of subvolumes. Subvolumes can be thought of as separate directories that have their own independent history and can be snapshotted. A snapshot is a point-in-time copy of a subvolume.

Snapshots share data with their parent subvolume, and possibly with other snapshots of the same parent, until data is changed. This mechanism is called copy-on-write.

A filesystem may contain many subvolumes and snapshots. Usually, one subvolume is mounted as the filesystem root (i.e. the subvolume with ID 5). Other subvolumes can be mounted explicitly using the subvol= or subvolid= mount options.

Snapshots can be read-only or read-write. Read-only snapshots are immutable and provide a stable point-in-time view of the subvolume. Read-write snapshots are writable and behave like normal subvolumes.

Subvolumes and snapshots are identified by their path relative to the filesystem root. They can also be identified by a unique subvolume ID, which is assigned by btrfs. The ID 5 is special: it always refers to the top-level subvolume of the filesystem.

A filesystem may also contain subvolumes that have been deleted but not yet cleaned up. These are still visible to some commands and may consume space until they are fully removed.

SUBCOMMAND

The general form of the btrfs subvolume command is:

btrfs subvolume subcommand <path> [args]

where subcommand is one of the following:

list [-s|-r|-d] [-t] [-G[+|-]<value>] [-C[+|-]<value>] [--sort=rootid,gen,ogen,path] <path>
List all subvolumes and snapshots in the filesystem mounted at path. The subvolumes are listed in a tree-like format, showing their relationship to each other.
id <path>
Show the subvolume ID of the subvolume at path.
get-default <path>
Get the current default subvolume for the filesystem mounted at path.
destroy [--recursive] <subvolume> [...]
Destroy the specified subvolume(s). The subvolume(s) are specified by path. If the subvolume is a snapshot, it is destroyed like any other subvolume.

WARNING: Destroying a subvolume is irreversible. Ensure that you specify the correct subvolume.

If the subvolume contains other subvolumes or snapshots, the command fails unless the --recursive option is used.

The destroyed subvolume may not be immediately removed from the filesystem. Use btrfs subvolume sync(8) to wait for the cleanup.

The following options can be used to filter the output of list:

uuid
Also print the UUID of the sent subvolume, where the subvolume is the result of a receive operation.

Type filtering:

-s
only snapshot subvolumes in the filesystem will be listed.
-r
only readonly subvolumes in the filesystem will be listed.
-d
list deleted subvolumes that are not yet cleaned.

Other:

-t
print the result as a table.

Sorting:

By default the subvolumes will be sorted by subvolume ID ascending.

-G [+|-]<value>
list subvolumes in the filesystem that its generation is >=, <= or = value. '+' means >= value, '-' means <= value, If there is neither '+' nor '-', it means = value.
-C [+|-]<value>
list subvolumes in the filesystem that its ogeneration is >=, <= or = value. The usage is the same to -G option.
--sort=rootid,gen,ogen,path
list subvolumes in order by specified items. you can add + or - in front of each items, + means ascending, - means descending. The default is ascending.

for --sort you can combine some items together by ,, just like --sort=+ogen,-gen,path,rootid.

set-default [<subvolume>|<id> <path>]
Set the default subvolume for the (mounted) filesystem.

Set the default subvolume for the (mounted) filesystem at path. This will hide the top-level subvolume (i.e. the one mounted with subvol=/ or subvolid=5). Takes action on next mount.

There are two ways how to specify the subvolume, by id or by the subvolume path. The id can be obtained from btrfs subvolume list btrfs subvolume show or btrfs inspect-internal rootid <#man-inspect-rootid>.

show [options] <path>
Show more information about a subvolume (UUIDs, generations, times, flags, related snapshots).
/mnt/btrfs/subvolume
        Name:                   subvolume
        UUID:                   5e076a14-4e42-254d-ac8e-55bebea982d1
        Parent UUID:            -
        Received UUID:          -
        Creation time:          2018-01-01 12:34:56 +0000
        Subvolume ID:           79
        Generation:             2844
        Gen at creation:        2844
        Parent ID:              5
        Top level ID:           5
        Flags:                  -
        Snapshot(s):

Options

-r|--rootid <ID>
show details about subvolume with root ID, looked up in path
-u|--uuid UUID
show details about subvolume with the given UUID, looked up in path
snapshot [-r] [-i <qgroupid>] <source> <dest>|[<dest>/]<name>
Create a snapshot of the subvolume source with the name name in the dest directory.

If only dest is given, the subvolume will be named the basename of source. If source is not a subvolume, btrfs returns an error.

Options

-r
Make the new snapshot read only.
-i <qgroupid>
Add the newly created subvolume to a qgroup. This option can be given multiple times.
sync <path> [subvolid...]
Wait until given subvolume(s) are completely removed from the filesystem after deletion. If no subvolume id is given, wait until all current deletion requests are completed, but do not wait for subvolumes deleted in the meantime.

If the filesystem status changes to read-only then the waiting is interrupted.

Options

-s <N>
sleep N seconds between checks (default: 1)

EXAMPLES

Deleting a subvolume

If we want to delete a subvolume called foo from a btrfs volume mounted at /mnt/bar we could run the following:

btrfs subvolume delete /mnt/bar/foo

EXIT STATUS

btrfs subvolume returns a zero exit status if it succeeds. A non-zero value is returned in case of failure.
