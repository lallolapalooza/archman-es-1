BIO_connect(3ssl)

Paquete: openssl

Licencias: Apache-2.0

BIO_CONNECT(3ssl) OpenSSL BIO_CONNECT(3ssl)

NOMBRE

BIO_socket, BIO_bind, BIO_connect, BIO_listen, BIO_accept_ex, BIO_closesocket - Rutinas de configuración de comunicación de sockets BIO

SINOPSIS

#include <openssl/bio.h>
int BIO_socket(int domain, int socktype, int protocol, int options);
int BIO_bind(int sock, const BIO_ADDR *addr, int options);
int BIO_connect(int sock, const BIO_ADDR *addr, int options);
int BIO_listen(int sock, const BIO_ADDR *addr, int options);
int BIO_accept_ex(int accept_sock, BIO_ADDR *peer, int options);
int BIO_closesocket(int sock);

DESCRIPCIÓN

BIO_socket() crea un socket en el dominio domain, de tipo socktype y protocol. Las options del socket actualmente no se utilizan, pero están presentes para uso futuro.

BIO_bind() enlaza la dirección de origen y el servicio a un socket y puede ser útil antes de llamar a BIO_connect(). Las opciones pueden incluir BIO_SOCK_REUSEADDR, que se describe en "FLAGS" más abajo.

BIO_connect() conecta sock a la dirección y servicio dados por addr. Las options de conexión pueden ser cero o cualquier combinación de BIO_SOCK_KEEPALIVE, BIO_SOCK_NONBLOCK y BIO_SOCK_NODELAY. Las banderas se describen en "FLAGS" más abajo.

BIO_listen() hace que sock comience a escuchar en la dirección y servicio dados por addr. Las options de conexión pueden ser cero o cualquier combinación de BIO_SOCK_KEEPALIVE, BIO_SOCK_NONBLOCK, BIO_SOCK_NODELAY, BIO_SOCK_REUSEADDR y BIO_SOCK_V6_ONLY. Las banderas se describen en "FLAGS" más abajo.

BIO_accept_ex() espera conexiones entrantes en el socket dado accept_sock. Cuando recibe una conexión, la dirección y el puerto del par se almacenan en peer si este no es NULL. Las options de aceptación pueden ser cero o BIO_SOCK_NONBLOCK, y se aplican al socket aceptado. Las banderas se describen en "FLAGS" más abajo.

BIO_closesocket() cierra sock.

FLAGS

BIO_SOCK_KEEPALIVE
Habilita el envío regular de mensajes keep-alive.
BIO_SOCK_NONBLOCK
Establece el socket en modo no bloqueante.
BIO_SOCK_NODELAY
Corresponde a TCP_NODELAY y deshabilita el algoritmo de Nagle. Con esto activado, cualquier dato se enviará tan pronto como sea posible en lugar de ser almacenado en búfer hasta que haya suficiente para que el socket envíe de una vez.
BIO_SOCK_REUSEADDR
Intenta reutilizar la combinación de dirección y puerto para un puerto cerrado recientemente.
BIO_SOCK_V6_ONLY
Al crear un socket IPv6, haz que solo escuche direcciones IPv6 y no direcciones IPv4 mapeadas a IPv6.
BIO_SOCK_TFO
Habilita TCP Fast Open en el socket. Utiliza las APIs apropiadas en sistemas operativos compatibles, incluyendo Linux, macOS y FreeBSD. Puede usarse con BIO_connect(), BIO_set_conn_mode(), BIO_set_bind_mode() y BIO_listen(). En kernels de Linux anteriores a 4.14, usa BIO_set_conn_address() para especificar la dirección del par antes de iniciar el handshake TLS.

Estas banderas son banderas de bits, por lo que deben combinarse con el operador "|", por ejemplo:

BIO_connect(sock, addr, BIO_SOCK_KEEPALIVE | BIO_SOCK_NONBLOCK);

VALORES DE RETORNO

BIO_socket() devuelve el número de socket en caso de éxito o INVALID_SOCKET (-1) en caso de error. Cuando ha ocurrido un error, la pila de errores de OpenSSL contendrá los datos del error y errno tendrá el error del sistema.

BIO_bind(), BIO_connect() y BIO_listen() devuelven 1 en caso de éxito o 0 en caso de error. Cuando ha ocurrido un error, la pila de errores de OpenSSL contendrá los datos del error y errno tendrá el error del sistema.

BIO_accept_ex() devuelve el socket aceptado en caso de éxito o INVALID_SOCKET (-1) en caso de error. Cuando ha ocurrido un error, la pila de errores de OpenSSL contendrá los datos del error y errno tendrá el error del sistema.

HISTORIA

BIO_gethostname(), BIO_get_port(), BIO_get_host_ip(), BIO_get_accept_socket() y BIO_accept() fueron obsoletos en OpenSSL 1.1.0. Utilice las funciones descritas anteriormente en su lugar.
