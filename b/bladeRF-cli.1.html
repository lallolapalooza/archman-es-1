Uso: flash_backup <archivo> (<tipo> | <dirección> <longitud>)

Copia de seguridad de los datos de la flash en el archivo especificado. Este comando toma dos o cuatro argumentos. La invocación de dos argumentos se recomienda generalmente para el uso no relacionado con el

desarrollo.

Parámetros

:
<type> - Tipo de copia de seguridad.

Esto selecciona los valores de dirección y longitud apropiados basándose en el tipo seleccionado.

Opciones válidas son:

Opción Descripción
cal Datos de calibración
fw Firmware
fpga40 Metadatos y bitstream para FPGA de 40 kLE
fpga115 Metadatos y bitstream para FPGA de 115 kLE
fpgaA4 Metadatos y bitstream para FPGA de 49 kLE (A4)
fpgaA5 Metadatos y bitstream para FPGA de 77 kLE (A5)
fpgaA9 Metadatos y bitstream para FPGA de 301 kLE (A9)
•
<address> - Dirección de los datos a respaldar. Debe estar alineada con el bloque de borrado.
•
<len> - Longitud de la región a respaldar. Debe estar alineada con el bloque de borrado.

Nota: Cuando se proporcionan una dirección y una longitud, el tipo de imagen será raw por defecto.

Ejemplos:

•

Respaldar la región de datos de calibración.

•

Respaldar la región de calibración como una imagen de datos raw.

xb

Uso: xb <board_model> <subcommand> [parameters]

Habilita o configura una placa de expansión.

Valores válidos para board_model:

•
100

Placa de expansión GPIO XB-100

•
200

Placa de expansión transvertidora XB-200 LF/MF/HF/VHF

•
300

Placa de amplificador XB-300

Subcomandos comunes:

•
enable

Habilita la placa de expansión XB-100, XB-200 o XB-300.

Subcomandos de XB-200:

•
filter [rx|tx] [50|144|222|custom|auto_1db|auto_3db]

Selecciona el filtro RX o TX especificado en la placa XB-200. A continuación se describen cada una de las opciones de filtro.

•
50
Selecciona el filtro de 50-54 MHz (banda de 6 metros).
•
144
Selecciona el filtro de 144-148 MHz (banda de 2 metros).
•
222
Selecciona el filtro de 222-225 MHz (banda de 1.25 metros). Realmente, esta opción de filtro es en realidad un poco más ancha, cubriendo 206 MHz - 235 MHz.
•
custom
Selecciona la ruta de filtro personalizada. El usuario debe conectar un filtro a lo largo de las conexiones FILT y FILT-ANT correspondientes al usar esta opción. Alternativamente, se pueden puentear las conexiones FILT y FILT-ANT para lograr "sin filtro" en la recepción. (Sin embargo, esto es _altamente_ desaconsejado para transmisiones.)
•
auto_1db
Selecciona automáticamente una de las opciones anteriores basándose en la frecuencia y los puntos de 1dB de los filtros. La ruta personalizada se usa para casos que no están asociados con los filtros a bordo.
•
auto_3db
Selecciona automáticamente una de las opciones anteriores basándose en la frecuencia y los puntos de 3dB de los filtros. La ruta personalizada se usa para casos que no están asociados con los filtros a bordo.

Subcomandos XB-300:

•
<pa|lna|aux> [on|off]

Habilita o deshabilita el amplificador de potencia (PA), el amplificador de bajo ruido (lna) o el LNA auxiliar (aux). Se imprime el estado actual si el dispositivo especificado es [on|off] si no se especifica.

Nota: La ruta auxiliar en el XB-300 no está poblada con componentes por defecto; el control aux no tendrá ningún efecto sobre la señal RX. Esta opción está disponible para que los usuarios modifiquen su placa con hardware personalizado.

•
<pwr>

Lee el voltaje actual del Detector de Potencia (PDET) y calcula la potencia de salida.

•
trx <rx|tx>

La configuración de hardware XB-300 por defecto incluye rutas RX y TX separadas. Sin embargo, los usuarios que deseen usar una sola antena para TRX pueden hacerlo mediante una modificación de las opciones de población de resistencias en el XB-300 y usar este comando para cambiar entre operación RX y TX. (Ver R8, R10 y R23 en el esquemático).

Ejemplos:

•
xb 200 enable

Habilita y configura la placa de expansión transverter XB-200.

•
xb 200 filter rx 144

Selecciona el filtro de recepción de 144-148 MHz en la placa de expansión transverter XB-200.

•
xb 300 enable

Habilita y configura el uso de GPIOs para interactuar con el XB-300. El PA y el LNA estarán deshabilitados por defecto.

•
xb 300 lna on

Habilita el LNA RX en el XB-300. El LED D1 (verde) se ilumina cuando el LNA está habilitado, y se apaga cuando está deshabilitado.

•
xb 300 pa off

Deshabilita el PA TX en el XB-300. El LED D2 (azul) se ilumina cuando el PA está habilitado, y se apaga cuando está deshabilitado.

Uso: recover [<bus> <direccion> <archivo de firmware>]

Carga firmware en un dispositivo que se ejecuta en modo bootloader, o lista todos los dispositivos que se ejecutan actualmente en modo bootloader.

rx

Uso: rx <start | stop | wait | config [param=val [param=val [...]]]>

Recibe muestras IQ y las escribe en el archivo especificado. La recepción se controla y configura con uno de los siguientes comandos:

Comando Descripción
start Inicia la recepción de muestras
stop Detiene la recepción de muestras
wait Espera a que se complete la transmisión de muestras, o hasta que transcurra un tiempo especificado
config Configura la recepción de muestras. Si no se proporcionan parámetros, se imprimen los parámetros actuales.

Ejecutar rx sin comandos adicionales es una forma abreviada válida de ejecutar rx config.

El comando wait acepta un parámetro opcional de tiempo de espera. Este parámetro está en unidades de milisegundos (ms) de forma predeterminada. La unidad del tiempo de espera puede especificarse usando los sufijos ms o s. Si no se proporciona este parámetro, el comando esperará hasta que se complete la recepción o se presione Ctrl-C.

Los parámetros de configuración tienen la forma param=value, y pueden especificarse en una o varias invocaciones de rx config. A continuación se muestra una lista de los parámetros disponibles.

Parámetro Descripción
n Número de muestras a recibir. 0 = infinito.
file Nombre del archivo donde escribir las muestras recibidas
format Formato del archivo de salida. Uno de los siguientes:
csv: CSV de muestras SC16 Q11
bin: muestras DAC SC16 Q11 en bruto
samples Número de muestras por búfer a usar en el flujo asíncrono. Debe ser divisible por 1024 y >= 1024.
buffers Número de búferes de muestras a usar en el flujo asíncrono. El valor mínimo es 4.
xfers Número de transferencias simultáneas permitidas para el flujo asíncrono. Debe ser menor que el parámetro buffers.
timeout Tiempo de espera del flujo de datos. Sin sufijo, la unidad predeterminada es ms. El valor predeterminado es 1000 ms (1 s). Los sufijos válidos son ms y s.
channel Lista de canales RF físicos a usar, delimitados por comas

Ejemplo:

•
rx config file=/tmp/data.bin format=bin n=10K

Recibe (10240 = 10 * 1024) muestras, escribiéndolas en /tmp/data.bin en el formato binario DAC.

•
rx config file=mimo.csv format=csv n=32768 channel=1,2

Recibe 32768 muestras de RX1 y RX2, escribiéndolas en un archivo llamado mimo.csv, con cuatro columnas (RX1 I, RX1 Q, RX2 I, RX2 Q).

Notas:

•
Los parámetros n, samples, buffers y xfers admiten los sufijos K, M y G, que son múltiplos de 1024.
•
Un rx stop seguido de un rx start hará que el archivo de muestras se trunque. Si esto no es deseable, asegúrese de ejecutar rx config para establecer otro archivo antes de reiniciar el flujo rx.
•
Para tasas de muestreo más altas, se recomienda usar el formato de salida binario y escribir el archivo de salida en RAM (por ejemplo, /tmp, /dev/shm), si hay espacio disponible. Para capturas más grandes a tasas de muestreo más altas, considere usar un SSD en lugar de un HDD.
•
El formato CSV produce dos columnas por canal, con las dos primeras columnas correspondientes al par I,Q del primer canal configurado con el parámetro channel; las dos columnas siguientes correspondientes al I,Q del segundo canal, y así sucesivamente.

trigger

Uso: trigger [<trigger> <tx | rx> [<off slave master fire>]]

Si se usa sin parámetros, este comando imprime el estado de todos los triggers. Cuando se proporcionan y , se imprime el trigger especificado.

A continuación se muestran las opciones disponibles para :

Trigger Descripción
J71-4 La señal de trigger está en mini_exp1 (bladeRF x40/x115, J71, pin 4).
J51-1 La señal de trigger está en mini_exp1 (bladeRF xA4/xA5/xA9, J51, pin 1).
Miniexp-1 La señal de trigger está en mini_exp1, independiente del hardware

Tenga en cuenta que las tres opciones anteriores corresponden al mismo puerto lógico en todos los dispositivos (mini_exp[1]). Se proporcionan múltiples opciones por compatibilidad con versiones anteriores y por claridad.

El trigger se controla y configura proporcionando el último argumento, que puede ser uno de los siguientes:

Comando Descripción
off Borra la solicitud de disparo y desactiva la funcionalidad del trigger.
slave Configura el trigger como esclavo, borra la solicitud de disparo y arma el dispositivo.
master Configura el trigger como maestro, borra la solicitud de disparo y arma el dispositivo.
fire Establece la solicitud de disparo. Solo aplicable al maestro.

Una cadena de triggers consta de una o varias unidades bladeRF y puede contener módulos TX y RX. Si se usan múltiples unidades bladeRF, deben conectarse mediante la señal especificada por y una tierra común.

Debe usarse la siguiente secuencia de comandos para garantizar una sincronización adecuada. Se asume que todos los triggers están desactivados inicialmente.

1.
Configure el trigger maestro designado

IMPORTANTE

Nunca configure dos dispositivos como triggers maestros en una sola
cadena. La contención en la misma señal podría dañar los dispositivos.
2.
Configure todos los demás dispositivos como triggers esclavos
3.
Configure e inicie los flujos de transmisión o recepción.
La operación se detendrá hasta que se disparen los triggers. Como tal,
deben usarse tiempos de espera lo suficientemente grandes para permitir que
la señal de trigger sea emitida por el maestro y recibida por los esclavos
antes de que libbladeRF devuelva BLADERF_ERR_TIMEOUT.
4.
Establezca la solicitud de disparo en el trigger maestro
Todos los dispositivos comenzarán a transmitir o recibir datos de forma
sincrónica.
5.
Finalice las tareas de transmisión y recepción como de costumbre
6.
Vuelva a configurar el maestro y los esclavos para borrar las solicitudes de disparo y rearmar.
Los pasos 1 a 5 pueden repetirse según sea necesario.
7.
Desactive el triggering en todos los esclavos
8.
Desactive el triggering en el maestro

Notas:

•
Sincronizar transmisores y receptores en una sola cadena causará un desfase de 11 muestras entre TX y RX; estas muestras deben descartarse. Esto es causado por diferentes longitudes de las tuberías de procesamiento de TX y RX. Este valor podría cambiar si el código FPGA se actualiza en el futuro.

Comando Descripción

stop Detiene la transmisión de muestras

config Configura la transmisión de muestras. Si no se proporcionan parámetros, se imprimen los parámetros actuales.

Ejecutar tx sin comandos adicionales es una forma abreviada válida de ejecutar tx config.

El comando wait acepta un parámetro opcional de tiempo de espera. Este parámetro está en unidades de milisegundos (ms) de forma predeterminada. La unidad del tiempo de espera puede especificarse usando los sufijos ms o s. Si no se proporciona este parámetro, el comando esperará hasta que se complete la transmisión o se presione Ctrl-C.
