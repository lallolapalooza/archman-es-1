BWRAP(1) Comandos de usuario BWRAP(1)

NOMBRE

bwrap - utilidad de configuración de contenedores

SINOPSIS

bwrap [OPCIÓN...] [COMANDO]

DESCRIPCIÓN

bwrap es una herramienta de aislamiento (sandboxing) de bajo nivel no privilegiada (opcionalmente setuid en distribuciones antiguas). Es poco probable que la uses directamente desde la línea de comandos, aunque es posible.

Funciona creando un namespace de sistema de archivos nuevo y completamente vacío, donde la raíz está en un tmpfs que es invisible desde el host y que se limpiará automáticamente cuando el último proceso salga. Luego puedes usar opciones de línea de comandos para construir el sistema de archivos raíz y el entorno del proceso para el comando que se ejecutará en el namespace.

Por defecto, bwrap crea un nuevo namespace de montaje para el sandbox. Opcionalmente, también configura nuevos namespaces de usuario, ipc, pid, red y uts (pero ten en cuenta que el namespace de usuario es necesario si bwrap no está instalado como setuid root).

Si es necesario (por ejemplo, al usar un namespace de PID), bwrap está ejecutando un proceso mínimo pid 1 en el sandbox que es responsable de recoger los zombies. También detecta cuándo el proceso de aplicación inicial (pid 2) muere e informa su estado de salida al iniciador original. El proceso pid 1 sale para limpiar el sandbox cuando no quedan otros procesos en él.

OPCIONES

Cuando las opciones se usan varias veces, la última opción tiene efecto, a menos que se especifique lo contrario.

Opciones generales:

--help

Muestra la ayuda y sale

--version

Muestra la versión

--args FD

Analiza argumentos separados por nulos desde el descriptor de archivo dado. Esta opción se puede usar varias veces para analizar opciones de múltiples fuentes.

--argv0 VALOR

Establece argv[0] al valor VALOR antes de ejecutar el programa

--level-prefix

Prefija cada línea de salida de diagnóstico con un nivel de severidad numérico entre corchetes angulares. Los niveles de severidad utilizados se basan en las constantes usadas por syslog(3): por ejemplo, <4> indica una advertencia, ya que LOG_WARNING tiene el valor numérico 4. Los números menores que 4 indican errores fatales, y los números mayores que 4 indican mensajes informativos. Estos prefijos pueden ser analizados por herramientas compatibles con logger --prio-prefix (ver logger(1)) o systemd-cat --level-prefix=1 (ver systemd-cat(1)).

Opciones relacionadas con namespaces del kernel:

--unshare-user

Crea un nuevo namespace de usuario

--unshare-user-try

Crea un nuevo namespace de usuario si es posible, de lo contrario, omítelo

--unshare-ipc

Crea un nuevo namespace ipc

--unshare-pid

Crea un nuevo namespace pid

--unshare-net

Crea un nuevo namespace de red

--unshare-uts

Crea un nuevo namespace uts

--unshare-cgroup

Crea un nuevo namespace cgroup

--unshare-cgroup-try

Crea un nuevo namespace cgroup si es posible, de lo contrario, omítelo

--unshare-all

Desasocia todos los namespaces posibles. Actualmente equivalente a: --unshare-user-try --unshare-ipc --unshare-pid --unshare-net --unshare-uts --unshare-cgroup-try

--share-net

Conserva el namespace de red, anulando un --unshare-all o --unshare-net anterior

--userns FD

Usa un namespace de usuario existente en lugar de crear uno nuevo. El namespace debe cumplir los requisitos de permisos para setns(), lo que generalmente significa que debe ser un descendiente del namespace de usuario actualmente activo, y ser propiedad del mismo usuario.

Esto es incompatible con --unshare-user, y no funciona en la versión setuid de bubblewrap.

--userns2 FD

Después de configurar el nuevo namespace, cambia al namespace especificado. Para que esto funcione, el namespace especificado debe ser un descendiente del namespace de usuario utilizado para la configuración, por lo que esto solo es útil en combinación con --userns.

Esto es útil porque a veces bubblewrap crea namespaces de usuario anidados (para solucionar problemas del kernel) y --userns2 se puede usar para entrar en ellos.

--disable-userns

Impide que el proceso en el sandbox cree más namespaces de usuario, para que no pueda reorganizar el namespace del sistema de archivos ni realizar otras modificaciones de namespace más complejas. Esto se implementa actualmente estableciendo el sysctl user.max_user_namespaces a 1, y luego entrando en un namespace de usuario anidado que no puede aumentar ese límite en el namespace externo. Esta opción requiere --unshare-user, y no funciona en la versión setuid de bubblewrap.

--assert-userns-disabled

Confirma que se ha impedido al proceso en el sandbox crear más namespaces de usuario, pero sin tomar ninguna acción particular para evitarlo. Por ejemplo, esto se puede combinar con --userns para comprobar que el namespace de usuario dado ya se ha configurado para impedir la creación de más namespaces de usuario.

--pidns FD

Usa un namespace de pid existente en lugar de crear uno. Esto se usa a menudo con --userns, porque el namespace de pid debe ser propiedad del mismo namespace de usuario que utiliza bwrap.

Ten en cuenta que esto se puede combinar con --unshare-pid, y en ese caso significa que el sandbox estará en su propio namespace de pid, que es un hijo del proporcionado.

--uid UID

Usa un ID de usuario personalizado en el sandbox (requiere --unshare-user)

--gid GID

Usa un ID de grupo personalizado en el sandbox (requiere --unshare-user)

--hostname HOSTNAME

Usa un nombre de host personalizado en el sandbox (requiere --unshare-uts)

Opciones sobre la configuración del entorno:

--chdir DIR

Cambia el directorio a DIR

--setenv VAR VALOR

Establece una variable de entorno

--unsetenv VAR

Elimina una variable de entorno

--clearenv

Elimina todas las variables de entorno, excepto PWD y cualquier otra que se establezca posteriormente con --setenv

Opciones para monitorizar el sandbox desde el exterior:

--lock-file DEST

Toma un bloqueo en DEST mientras el sandbox está en ejecución. Esta opción se puede usar varias veces para tomar bloqueos en múltiples archivos.

--sync-fd FD

Mantén abierto este descriptor de archivo mientras el sandbox está en ejecución

Opciones relacionadas con el sistema de archivos. Todas estas son operaciones que modifican el sistema de archivos directamente, o montan cosas en el sistema de archivos. Estas se aplican en el orden en que se dan como argumentos.

Los directorios padre faltantes que sean necesarios para crear un destino especificado se crearán automáticamente según sea necesario. Sus permisos normalmente se establecen en 0755 (rwxr-xr-x). Sin embargo, si una opción --perms está en vigor y establece los permisos para grupo o otros a cero, entonces los directorios padre recién creados también tendrán sus permisos correspondientes establecidos a cero. --size modifica el tamaño del montaje creado cuando precede a una acción --tmpfs; --perms y --size se pueden combinar.

--perms OCTAL

Esta opción no hace nada por sí sola y debe ir seguida de una de las opciones que afecta. Establece los permisos para la siguiente operación a OCTAL. Las operaciones subsiguientes no se ven afectadas: por ejemplo, --perms 0700 --tmpfs /a --tmpfs /b montará /a con permisos 0700, luego volverá a los permisos predeterminados para /b. Ten en cuenta que --perms y --size se pueden combinar: --perms 0700 --size 10485760 --tmpfs /s aplicará permisos así como un tamaño máximo al tmpfs creado.
