buildah-push - Envía una imagen, una lista

de manifiestos o un índice de imágenes d
esde el almacenamiento local a otro lugar.

SINOPSI

S

buildah push [opciones] imagen [dest

in
o]

DESCRIPCIÓ

N

Envía una imagen desde el almacenamiento local

a un destino especificado, descomprimiendo y
recomprimiendo las capas según sea necesario.

imageI

D

Imagen almacenada en

el almacenamiento l
ocal de contenedores

DESTIN

O

DESTINO es la ubicación a la que se envía la imagen del contenedor. Soporta todos los transportes de containers-transports(5) (vea los ejemplos a continuación). Si no se especifica un transporte, se utiliza el transporte docker (es decir, el regis

tro de c
ontenedores).

OPCIONE

S

--al

l

Si la imagen especificada es una lista de manifiestos o un índice de imágenes, envía las imágenes además de la propia lista o

índice.

--authfile rut

a

Ruta del archivo de autenticación. El valor predeterminado es ${XDG_RUNTIME_DIR}/containers/auth.json. Vea containers-auth.json(5) para más información. Este archivo se crea utilizando buildah l

ogin.

Si el estado de autorización no se encuentra allí, se comprueba $HOME/.docker/config.json, que se establece utilizando docker

login.

Nota: También puede anular la ruta predeterminada del archivo de autenticación estableciendo la variable de entorno REGISTRY_AUTH_FILE. export REGISTRY_AUTH_FILE=rut

a

--cert-dir rut

a

Utiliza los certificados en ruta (*.crt, *.cert, *.key) para conectarse al registro. El directorio de certificados predeterminado es /etc/containers/

certs.d.

--compression-format format

o

Especifica el formato de compresión a utilizar. Los valores admitidos son: gzip, zstd y zstd:chunked. zstd:chunked es incompatible con el cifrado de imágenes y se tratará como zstd con una advertencia en ese

caso.

--compression-level nive

l

Especifica el nivel de compresión utilizado con la

compresión.

Especifica el nivel de compresión a utilizar. El valor es específico del algoritmo de compresión utilizado; por ejemplo, para zstd los valores aceptados están en el rango 1-20 (inclusive), mientras que para gzip es 1-9 (inclusive)

.

--creds credencial

es

El [usuario[:contraseña]] a utilizar para autenticarse con el registro si es necesario. Si no se proporciona uno o ambos valores, aparecerá un indicador en la línea de comandos y se puede introducir el valor. La contraseña se introduce sin

eco.

--digestfile ArchivoDiges

t

Después de copiar la imagen, escribe el resumen de la imagen resultante en el

archivo.

--disable-compression, -

D

No comprimir las copias de las capas del sistema de archivos que se

enviarán.

--encrypt-layer capa(s

)

Capa(s) a cifrar: índices de capas con base 0 que admiten indexación negativa (por ejemplo, 0 es la primera capa, -1 es la última capa). Si no se define, se cifrarán todas las capas si se especifica la opción

encryption-key.

--encryption-key clav

e

El [protocolo:archivo_clave] especifica el protocolo de cifrado, que puede ser JWE (RFC7516), PGP (RFC4880) y PKCS7 (RFC2315), y el material de clave necesario para el cifrado de imágenes. Por ejemplo, jwe:/ruta/a/key.pem o pgp:admin@example.com o pkcs7:/ruta/a/archivo-x509

.

--force-compressio

n

Si se establece, push utiliza el algoritmo de compresión especificado incluso si el destino ya contiene una variante comprimida de manera diferente. Por defecto es true si --compression-format se especifica explícitamente en la línea de comandos, false en caso

contrario.

--format, -

f

Tipo de manifiesto (oci, v2s2 o v2s1) a utilizar al enviar una imagen. (el valor predeterminado es el tipo de manifiesto de la imagen de origen, con alternativas de

reserva)

--quiet, -

q

Al escribir la imagen de salida, suprime la salida de

progreso.

--remove-signature

s

No copiar las firmas al enviar

imágenes.

--retry intento

s

Número de veces a reintentar en caso de fallo al realizar el envío de imágenes al

registro.

Por defecto es 3

.

--retry-delay duració

n

Duración de la demora entre intentos de reintento en caso de fallo al realizar el envío de imágenes al

registro.

Por defecto es 2s

.

--r

m

Al enviar una lista de manifiestos o un índice de imágenes, elimínalos del almacenamiento local si el envío tiene

éxito.

--sign-by huella_digita

l

Firma la imagen enviada utilizando la clave GPG que coincide con la huella digital

especificada.

--tls-verify valor_boolean

o

Requiere HTTPS y verificación de certificados al comunicarse con

registros de contenedores (por defecto es true). La verificación T
LS no se puede utilizar al comunicarse con un registro no seguro.

especificado.

# buildah push --digestfile=/tmp/miresumen imageID docker://registry.example.com/repositorio:

ENTORN

O

BUILD_REGISTRY_SOURCE

S

BUILD_REGISTRY_SOURCES, si se establece, se trata como un objeto JSON que contiene listas de nombres de registros bajo las claves insecureRegistries, blockedRegistries y allowedRegistries

.

Al enviar una imagen a un registro, si la parte del nombre de la imagen de destino que corresponde a un registro se compara con los elementos de la lista blockedRegistries, y si coincide con alguno de ellos, se deniega el intento de envío. Si hay registros en la lista allowedRegistries, y la parte del nombre que corresponde al registro no está en la lista, se deniega el intento de

envío.

TMPDIR La variable de entorno TMPDIR permite al usuario especificar dónde se almacenan l

os archivos temporales mientras se extraen y
envían imágenes. Por defecto es '/var/tmp'.

ARCHIVO

S

registries.conf (/etc/containers/regis

tries.conf)

registries.conf es el archivo de configuración que especifica qué registros de contenedores dedeben consultarse al completar los nombres de imagen que no incluyen un registro o una parte de

dominio.

policy.json (/etc/containers/pol

icy.json)

Archivo de política de firmas. Define la política de confianza para las

imágenes de contenedores. Controla qué registros de contenedores pueden
usarse para las imágenes, y si la herramienta debe confiar en ellas.
