DESCRIPCIÓNBogofilter es un filtro de correo basura bayesiano. En su modo de operación normal, toma un mensaje de correo electrónico u otro texto de la entrada estándar, realiza una comprobación estadística contra listas de palabras "buenas" y "malas", y devuelve un código de estado que indica si el mensaje es spam o no. Bogofilter está diseñado con un algoritmo rápido, utiliza Berkeley DB para un inicio y búsquedas rápidos, está codificado directamente en C y está optimizado para la velocidad, por lo que puede ser utilizado en producción por sitios que procesan una gran cantidad de correo.TEORÍA DE FUNCIO

NAMIENTO

Bogofilter trata su entrada como una bolsa de tokens. Cada token se comprueba contra una lista de palabras, que mantiene recuentos del número de veces que ha ocurrido en correos no spam y spam. Estos números se utilizan para calcular una estimación de la probabilidad de que un mensaje en el que aparece el token sea spam. Se combinan para indicar si el mensaje es

spam o no spam.

Aunque este método parece crudo en comparación con el enfoque más habitual de coincidencia de patrones, resulta ser extremadamente eficaz. El artículo de Paul GrahamA Plan For

Spam

[1] es una lectura recomendada. Este programa mejora sustancialmente la propuesta de Paul al realizar un análisis léxico más inteligente. Bogofilter realiza una decodificación MIME adecuada y un análisis HTML razonable. Tipos especiales de tokens, como nombres de host y direcciones IP, se conservan como características de reconocimiento en lugar de dividirse. Se ignoran varios tipos de elementos propios de los MTA, como fechas e identificadores de mensajes, para no inflar la lista de palabras. Los tokens encontrados en varios campos de cabecera se marcan

de forma
apropiada.

Otra mejora es que este programa ofrece las modificaciones sugeridas por Gary Robinson a los cálculos (véanse los parámetros robx y robs más abajo). Estas modificaciones se describen en el artículo

de Robinson

Spam

Det
ection

[2]

.

Desde entonces, Robinson (véase su artículo en Linux

Journal

A Statistical Approach to the Spam Problem [3]) y otros han reconocido que el cálculo puede optimizarse aún más utilizando el método de

Fisher.

Otra

mejora

[4] compensa la redundancia de tokens aplicando factores de tamaño efectivo (ESF) separados a los cálculos de probabilidades de spam y no spam. En resumen, así es como funciona: las estimaciones de las probabilidades de spam de los tokens individuales se combinan utilizando la "función chi-cuadrado inversa". Su valor indica cuánto falla la hipótesis nula de que el mensaje es simplemente una colección aleatoria de palabras independientes con probabilidades dadas por nuestras estimaciones anteriores. Esta función es muy sensible a las probabilidades pequeñas (palabras no spam), pero no a las probabilidades altas (palabras spam); por lo tanto, el valor solo indica fuertes señales de no spam en un mensaje. Ahora, utilizando probabilidades inversas para los tokens, se realiza el mismo cálculo de nuevo, lo que proporciona un indicador de que un mensaje parece fuertemente spam. Finalmente, esos dos indicadores se restan (y se escalan a un intervalo de 0-1). Este indicador combinado (bogosidad) está cerca de 0 si las señales de un mensaje no spam son más fuertes que las de un mensaje spam, y cerca de 1 si la situación es la contraria. Si las señales de ambos son igualmente fuertes, el valor estará cerca de 0,5. Dado que esos mensajes no proporcionan una indicación clara, bogofilter tiene un modo de tres estados para marcar esos mensajes como inciertos, mientras que los mensajes claros se marcan como spam o no spam, respectivamente. En modo

de dos estados, cada mensaje se marca como spam o no spam.

Varios parámetros influyen en estos cálculos, los más importantes son: robx: la puntuación dada a un token que no se ha visto antes. robx es la probabilidad de que el token sea spam. robs: un peso sobre robx que mueve la probabilidad de un token poco visto hacia

robx.

min-dev: una distancia mínima de 0,5 para los tokens a utilizar en el cálculo. Solo se utilizan los tokens que están más lejos de 0,5 que este

valor.

spam-cutoff: los mensajes con puntuaciones mayores o iguales a este valor se marcarán como

spam.

ham-cutoff: Si es cero o igual a spam-cutoff, todos los mensajes con valores estrictamente inferiores a spam-cutoff se marcan como no spam, y todos los demás como spam (dos estados). En caso contrario, los valores menores o iguales a ham-cutoff se marcan como no spam, los mensajes con valores estrictamente entre ham-cutoff y spam-cutoff se marcan como inciertos; el resto como spam (tres

estados)

sp-esf: el factor de tamaño efectivo (ESF) para

spam.

ns-esf: el ESF para no spam. Estos valores ESF tienen un valor predeterminado de 1,0, que es lo mismo que no usar ESF en el cálculo. Los valores adecuados para la población de correo electrónico de un usuario pueden determinarse con la ayuda del programa

bogotune.

OPCIONES DE

CLASIFICACIÓN

La opción -p (passthrough) emite el mensaje con una línea X-Bogosity al final de la cabecera del mensaje. Esto requiere mantener el mensaje completo en memoria cuando se lee de stdin (o de una tubería o socket). Si el mensaje se lee de un archivo que se puede rebobinar, bogofilter lo leerá una segunda

vez.

La opción -e (embed) indica a bogofilter que salga con el código 0 si el mensaje se puede clasificar, es decir, si no hay un error. Normalmente, bogofilter utiliza códigos diferentes para las clasificaciones de spam, no spam e incierto, pero esto simplifica el uso de bogofilter con procmail o

maildrop.

La opción -t (terse) indica a bogofilter que imprima un mensaje de spamicity abreviado que contiene 1 letra y la puntuación. El spam se indica con "Y", el no spam con "N" y el incierto con "U". Nota: el formato se puede personalizar utilizando el archivo de

configuración.

opción -T proporciona un modo conciso invariante para que lo utilicen los scripts. bogofilter imprimirá un mensaje de spamicity abreviado que contiene 1 letra y la puntuación. El spam se indica con "S", el no spam con "H" y el incierto con

"U".

La opción

-TT

proporciona un modo conciso invariante para que lo utilicen los scripts. Bogofilter imprime solo la puntuación y la muestra con 16 dígitos significativos. L

a

opción -u indica a bogofilter que registre el texto del mensaje después de clasificarlo como spam o no spam. Un mensaje spam se registrará en la lista de spam y un mensaje no spam en la lista de buenas. Si la clasificación es "incierto", el mensaje no se registrará. De hecho, esta opción ejecuta bogofilter con

el

indicador -s o -

n

según corresponda. Se recomienda precaución en el uso de esta capacidad, ya que cualquier error de clasificación que pueda cometer bogofilter se conservará y se acumulará hasta que se corrija manualmente con las combinaciones de opciones -Sn y -Ns [[135]]. Tenga en cuenta que esta opción hace que la base de datos se abra para acceso de escritura, lo que puede acarrear una ralentización masiva debido a la contención de bloqueos y a operaciones de E/S síncronas. La opción

-H

indica a bogofilter que no etiquete los tokens de la cabecera. Esta opción es para pruebas, no debería usarla en la operación normal. L

a

opción -M indica a bogofilter que procese su entrada como formato de archivo mbox. Si también se proporciona la opción -v o -t, se imprimirá una línea de spam para cada mensaje.

La opción -b (modo masivo de transmisión) indica a bogofilter que clasifique varios objetos cuyos nombres se leen desde stdin. Si también se proporciona la opción -v o -t, bogofilter imprimirá una línea que proporcionará el nombre del archivo e información de clasificación para cada archivo. Esta es una alternativa a -B, que enumera los objetos en la línea de comandos.

Un objeto en este contexto será un maildir (autodetectado) o, si no es un maildir, un solo correo a menos que se proporcione -M, en cuyo caso se procesa como mbox. (Actualmente, la cabecera Content-Length: no se tiene en cuenta).

Al leer el formato mbox, bogofilter se basa en la línea vacía después de un correo. Si es necesario, formail -es garantizará que esto sea así.

La opción -B objeto ... (modo masivo) indica a bogofilter que clasifique varios objetos nombrados en la línea de comandos. Los objetos pueden ser nombres de archivo (para mensajes individuales), buzones (archivos con múltiples mensajes) o directorios (de formato maildir y MH). Si también se proporciona la opción -v o -t, bogofilter imprimirá una línea que proporcionará el nombre del archivo e información de clasificación para cada archivo. Esta es una alternativa a -b, que enumera los objetos en stdin.

La opción -R indica a bogofilter que genere un marco de datos R en formato de texto en la salida estándar. Consulte la sección sobre integración con R, a continuación, para obtener más detalles.

OPCIONES DE REGISTRO

La opción -s indica a bogofilter que registre el texto presentado como spam. La base de datos se crea si está ausente.

La opción -n indica a bogofilter que registre el texto presentado como no spam.

Bogofilter no detecta si un mensaje se registra dos veces. Si lo hace por accidente, los recuentos de tokens estarán desfasados en 1 de lo que realmente desea y las puntuaciones de spam correspondientes estarán ligeramente desfasadas. Dado un gran número de tokens y mensajes en la lista de palabras, esto no importa. El problema *puede* corregirse utilizando la opción -S o la opción -N.

La opción -S indica a bogofilter que deshaga un registro previo del mismo mensaje como spam. Si un mensaje se ingresó incorrectamente como spam mediante -s o -u y desea eliminarlo e ingresarlo como no spam, use -Sn. Si se usa -S para un mensaje que no se registró como spam, los recuentos aún se decrementarán.

La opción -N indica a bogofilter que deshaga un registro previo del mismo mensaje como no spam. Si un mensaje se ingresó incorrectamente como no spam mediante -n o -u y desea eliminarlo e ingresarlo como spam, entonces use -Ns. Si se usa -N para un mensaje que no se registró como no spam, los recuentos aún se decrementarán.

OPCIONES GENERALES

La opción -c nombre_archivo indica a bogofilter que lea el archivo de configuración especificado.

La opción -C evita que bogofilter lea archivos de configuración.

La opción -d directorio permite establecer el directorio para la base de datos. Consulte la sección ENTORNO para ver otras opciones de configuración de directorio.

La opción -k tamaño_caché establece el tamaño de la caché para el subsistema BerkeleyDB, en unidades de 1 MiB (1,048,576 bytes). El dimensionamiento adecuado de la caché mejora el rendimiento de bogofilter. El tamaño recomendado es un tercio del tamaño del archivo de la base de datos. Puede ejecutar el script bogotune (en el directorio de ajuste) para determinar el tamaño recomendado.

La opción -l escribe una línea informativa en el registro del sistema cada vez que se ejecuta bogofilter. La información registrada depende de cómo se ejecute bogofilter.

La opción -L etiqueta configura una etiqueta que puede incluirse en la información que se registra mediante la opción -l, pero requiere un formato personalizado que incluya la cadena %l por ahora. Esta opción implica -l.

La opción -I nombre_archivo indica a bogofilter que lea su entrada del archivo especificado, en lugar de stdin.

La opción -O nombre_archivo indica a bogofilter dónde escribir su salida en modo de traspaso. Tenga en cuenta que esto solo funciona cuando se proporciona explícitamente -p.

OPCIONES DE PARÁMETROS

La opción -E valor[,valor] permite establecer el valor sp-esf y el valor ns-esf. Con dos valores, se establecen tanto sp-esf como ns-esf. Si solo se proporciona un valor, los parámetros se establecen como se describe en la nota a continuación.

La opción -m valor[,valor][,valor] permite establecer el valor min-dev y, opcionalmente, los valores robs y robx. Con tres valores, se establecen min-dev, robs y robx. Si se proporcionan menos valores, los parámetros se establecen como se describe en la nota a continuación.

La opción -o valor[,valor] permite establecer los valores spam-cutoff y ham-cutoff. Con dos valores, se establecen tanto spam-cutoff como ham-cutoff. Si solo se proporciona un valor, los parámetros se establecen como se describe en la nota a continuación.

Nota: Todas estas opciones permiten proporcionar menos valores. Los valores pueden omitirse utilizando solo el delimitador de coma, en cuyo caso los parámetros correspondientes no se modificarán. Si solo se proporciona el primer valor, solo se establece el primer parámetro. Los valores finales pueden omitirse, en cuyo caso los parámetros correspondientes no se modificarán. Dentro de la lista de parámetros, no se permiten espacios después de las comas.

OPCIONES DE INFORMACIÓN

La opción -v produce un informe en la salida estándar sobre el análisis de la entrada por parte de bogofilter. Cada v adicional aumentará la verbosidad de la salida, hasta un máximo de 4. Con -vv, el informe enumera los tokens con la mayor desviación de una media de 0.5 de asociación con spam.

La opción -y fecha se puede utilizar para anular la fecha actual al marcar los tokens con fecha. Un valor de cero (0) desactiva el marcado de fecha.

La opción -D redirige la salida de depuración a stdout.

La opción -x flags permite establecer banderas de depuración para imprimir información de depuración. Consulte el archivo de encabezado debug.h para ver la lista de banderas utilizables.

OPCIONES DE ARCHIVO DE CONFIGURACIÓN

Utilizando la sintaxis GNU longopt --, la declaración nombre=valor de un archivo de configuración se convierte en --opción=valor de una línea de comandos. Utilice el comando bogofilter --help para obtener una lista de opciones y consulte bogofilter.cf.example para obtener más información sobre ellas. Por ejemplo, para cambiar la cabecera X-Bogosity a "X-Spam-Header", use:

--spam-header-name=X-Spam-Header

ENTORNO

Bogofilter utiliza un directorio de base de datos, que se puede configurar en el archivo de configuración. Si no se establece allí, bogofilter utilizará el valor de BOGOFILTER_DIR. Ambos pueden ser anulados por la opción -d directorio. Si nada de eso está disponible, bogofilter utilizará el directorio $HOME/.bogofilter.

CONFIGURACIÓN

La línea de comandos de bogofilter permite establecer muchas opciones que determinan cómo opera bogofilter. El archivo /etc/bogofilter/bogofilter.cf se puede utilizar para establecer parámetros adicionales que afectan su operación. El archivo /etc/bogofilter/bogofilter.cf.example tiene ejemplos de todos los parámetros. Los mensajes de estado y registro se pueden personalizar para cada sitio.

VALORES DE RETORNO

0 para spam; 1 para no spam; 2 para inseguro; 3 para errores de E/S u otros.

Si se utilizan tanto -p como -e, los valores de retorno son: 0 para spam o no spam; 3 para errores de E/S u otros.

El error 3 generalmente significa que falta el archivo de lista de palabras que bogofilter desea leer al inicio o que el disco duro se ha llenado en modo -p.

INTEGRACIÓN CON OTRAS HERRAMIENTAS

Uso con procmail

La siguiente receta (a) clasifica como spam cualquier cosa que bogofilter califique como spam, (b) registra las palabras en los mensajes calificados como spam como tales, y (c) registra las palabras en los mensajes calificados como no spam como tales. Con esto implementado, normalmente solo será necesario que el usuario intervenga (con -Ns o -Sn) cuando bogofilter clasifique algo incorrectamente.

# filtra el correo a través de bogofilter, etiquetándolo como Ham, Spam o Unsure,
# y actualizando la lista de palabras
:0fw
| bogofilter -u -e -p
# si bogofilter falló, devuelve el correo a la cola;
# el MTA lo intentará entregar más tarde
# 75 es el valor para EX_TEMPFAIL en /usr/include/sysexits.h
:0e
{ EXITCODE=75 HOST }
# archiva el correo en spam-bogofilter si es spam.
:0:
* ^X-Bogosity: Spam, tests=bogofilter
spam-bogofilter
# archiva el correo en unsure-bogofilter
# si no es ni ham ni spam.
:0:
* ^X-Bogosity: Unsure, tests=bogofilter
unsure-bogofilter
# Con esta receta, puedes entrenar bogofilter comenzando con una lista de
# palabras vacía. Asegúrate de revisar tu carpeta unsure regularmente, saca
# los mensajes de ella, clasifícalos como ham (o spam) y úsalos para entrenar
# bogofilter.

La siguiente regla de procmail tomará el correo de stdin y lo guardará en el archivo spam si bogofilter cree que es spam:

:0HB:
* ? bogofilter
spam

y esta regla similar registrará los tokens en el correo de acuerdo con la clasificación de bogofilter:

:0HB:
* ? bogofilter -u
spam

Si bogofilter falla (devolviendo 3) el mensaje se tratará como no spam.

Este es para maildrop, automáticamente difiere el correo e intenta más tarde cuando el comando xfilter falla, úsalo en tu ~/.mailfilter:

xfilter "bogofilter -u -e -p"
if (/^X-Bogosity: Spam, tests=bogofilter/)
{
  to "spam-bogofilter"
}

Las siguientes líneas de .muttrc crearán macros de mutt para despachar correo a bogofilter.

macro index d "<enter-command>unset wait_key\n\
<pipe-entry>bogofilter -n\n\
<enter-command>set wait_key\n\
<delete-message>" "eliminar mensaje como no spam"
macro index \ed "<enter-command>unset wait_key\n\
<pipe-entry>bogofilter -s\n\
<enter-command>set wait_key\n\
<delete-message>" "eliminar mensaje como spam"

INTEGRATION WITH OTHER TOOLS

Bogofilter can be integrated with procmail(1), maildrop(1), sendmail(8) and other Mail Transfer Agents (MTAs). A typical setup would involve having the MTA pass incoming mail to bogofilter and then having bogofilter, if it decides the message is spam, pass it to a separate directory or discard it. If bogofilter decides the message is not spam, it passes it on to the user's mailbox.

Here are some steps for integrating bogofilter with an MTA:

1. Set up the training database. The easiest way to do this is to
    classify a few hundred messages as either spam or not spam using the
    -s, -n, -S, and -N options and the -u
    option to update the database.
2. Set up the MTA to invoke bogofilter on each message. While this is an
    MTA specific step, you'll probably need to use the -p, -u,
    and -e options.
3. Set up a mechanism for users to register spam/non-spam messages, as
    well as to correct mis-classifications. The most generic solution is to
    set up alias email addresses to which users bounce messages.
4. See the doc and contrib directories for more information.

Use of R to verify bogofilter's calculations

The -R option tells bogofilter to generate an R data frame. The data frame contains one row per token analyzed. Each such row contains the token, the sum of its database "good" and "spam" counts, the "good" count divided by the number of non-spam messages used to create the training database, the "spam" count divided by the spam message count, Robinson's f(w) for the token, the natural logs of (1 - f(w)) and f(w), and an indicator character (+ if the token's f(w) value exceeded the minimum deviation from 0.5, - if it didn't). There is one additional row at the end of the table that contains a label in the token field, followed by the number of words actually used (the ones with + indicators), Robinson's P, Q, S, s and x values and the minimum deviation.

The R data frame can be saved to a file and later read into an R session (see the R project website[5] for information about the mathematics package R). Provided with the bogofilter distribution is a simple R script (file bogo.R) that can be used to verify bogofilter's calculations. Instructions for its use are included in the script in the form of comments.

LOG MESSAGES

Bogofilter writes messages to the system log when the -l option is used. What is written depends on which other flags are used.

A classification run will generate (we are not showing the date and host part here):

bogofilter[1412]: X-Bogosity: Ham, spamicity=0.000227
bogofilter[1415]: X-Bogosity: Spam, spamicity=0.998918

Using -u to classify a message and update a wordlist will produce (one a single line):

bogofilter[1426]: X-Bogosity: Spam, spamicity=0.998918,
  register -s, 329 words, 1 messages

Registering words (-l and -s, -n, -S, or -N) will produce:

bogofilter[1440]: register-n, 255 words, 1 messages

A registration run (using -s, -n, -N, or -S) will generate messages like:

bogofilter[17330]: register-n, 574 words, 3 messages
bogofilter[6244]: register-s, 1273 words, 4 messages
