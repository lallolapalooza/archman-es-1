DESCRIPCIÓ

N

Recrea el contenido de archivos

existentes.

Recreate es una operación potencialmente peligrosa y podría llevar a pérdida de datos (si se usa incorrectamente). ¡SEA MUY

CUIDADOSO!

Importante: el espacio en disco del repositorio no se libera hasta que ejecute borg comp

act.

--exclude, --exclude-from, --exclude-if-present, --keep-exclude-tags y RUTA tienen la misma semántica exacta que en "borg create", pero solo verifican archivos en los archivos (archives) y no en el sistema de archivos local. Si se especifican RUTAS, los archivos resultantes solo contendrán archivos de estas

RUTAS.

Tenga en cuenta que todas las rutas en un archivo son relativas, por lo tanto, patrones/rutas absolutas no coincidirán (--exclude, --exclude-from, RUTAS)

.

--recompress permite cambiar la compresión de datos existentes en los archivos. Debido a la forma en que Borg almacena la información de tamaño comprimido, esto podría mostrar información incorrecta para archivos que no fueron recreados al mismo tiempo. No hay riesgo de pérdida de datos por

esto.

--chunker-params volverá a dividir en trozos (re-chunk) todos los archivos en el archivo; esto se puede usar para hacer que archivos de Borg 0.xx o Attic actualizados dedupliquen con archivos de Borg 1.

x.

ÚSESE CON PRECAUCIÓN. Dependiendo de las RUTAS y patrones dados, recreate se puede usar para eliminar archivos permanentemente de los archivos. En caso de duda, use --dry-run --verbose --list para ver cómo se interpretan los patrones/RUTAS. Vea list_item_flags en borg create para

detalles.

El archivo que se está recreando solo se elimina después de que la operación se completa. El archivo que se construye durante la operación existe al mismo tiempo en "<ARCHIVO>.recreate". El nuevo archivo tendrá un ID de archivo

diferente.

Con --target el archivo original no se reemplaza; en su lugar, se crea un nuevo

archivo.

Al volver a dividir en trozos (o recomprimir), el uso de espacio puede ser sustancial - espere al menos todo el tamaño deduplicado de los archivos usando los parámetros anteriores de división en trozos (o compresión)

.

Si ejecutó recientemente borg check --repair y tuvo que reparar trozos perdidos con trozos de reemplazo de todos ceros, por favor ejecute primero otra copia de seguridad para los mismos datos y vuelva a ejecutar borg check --repair después para sanar cualquier archivo que haya perdido trozos que aún se generan a partir de los datos de

entrada.

Importante: ejecutar borg recreate para volver a dividir en trozos eliminará los metadatos chunks_healthy de todos los elementos con trozos de reemplazo, por lo que la sanación ya no será posible después de volver a dividir en trozos (también es improbable que

alguna vez funcione: debido al cambio de parámetros de división en trozos, el trozo faltan
te probablemente nunca se verá de nuevo incluso si aún tiene los datos que lo produjeron).

EJEMPLO

S 
# Hacer que archivos antiguos (Attic/Borg 0.xx) dedupliquen con archivos de
# Borg 1.x. Los archivos creados con Borg 1.1+ y los parámetros predeterminados
# del divisor de trozos se omiten (el ID del archivo permanece igual).
$ borg recreate /mnt/backup --chunker-params default --progress
# Crear una copia de seguridad con compresión baja pero rápida.
$ borg create /mnt/backup::archivo /algunos/archivos --compression lz4
# Luego comprímalo — esto podría tardar más, pero la copia de seguridad ya ha
# completado, por lo que no hay inconsistencias de un trabajo de copia de
# seguridad de larga duración.
$ borg recreate /mnt/backup::archivo --recompress --compression zlib,9
# Eliminar archivos no deseados de todos los archivos en un repositorio.
# Note la ruta relativa para la opción --exclude — los archivos soloain relative paths.
$ borg recreate /mnt/backup --exclude home/icke/Pictures/drunk_photos
