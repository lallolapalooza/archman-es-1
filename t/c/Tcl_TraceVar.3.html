Tcl_TraceVar(3)

Paquete: tcl

Licencias: TCL

Tcl_TraceVar(3) Procedimientos de la biblioteca Tcl Tcl_TraceVar(3)

NOMBRE

Tcl_TraceVar, Tcl_TraceVar2, Tcl_UntraceVar, Tcl_UntraceVar2, Tcl_VarTraceInfo, Tcl_VarTraceInfo2 - monitorizar accesos a una variable

SINOPSIS

#include <tcl.h>

int
Tcl_TraceVar(interp, varName, flags, proc, clientData)

int
Tcl_TraceVar2(interp, name1, name2, flags, proc, clientData)

Tcl_UntraceVar(interp, varName, flags, proc, clientData)

Tcl_UntraceVar2(interp, name1, name2, flags, proc, clientData)

ClientData
Tcl_VarTraceInfo(interp, varName, flags, proc, prevClientData)

ClientData
Tcl_VarTraceInfo2(interp, name1, name2, flags, proc, prevClientData)

ARGUMENTOS

Tcl_Interp *interp (in)
Intérprete que contiene la variable.
const char *varName (in)
Nombre de la variable. Puede referirse a una variable escalar, a una variable de matriz sin índice, o a una variable de matriz con un índice entre paréntesis.
int flags (in)
Combinación OR de los valores TCL_TRACE_READS, TCL_TRACE_WRITES, TCL_TRACE_UNSETS, TCL_TRACE_ARRAY, TCL_GLOBAL_ONLY, TCL_NAMESPACE_ONLY, TCL_TRACE_RESULT_DYNAMIC y TCL_TRACE_RESULT_OBJECT. No todos los flags son usados por todos los procedimientos. Ver más abajo para más información.
Tcl_VarTraceProc *proc (in)
Procedimiento a invocar cada vez que ocurra una de las operaciones trazadas.
ClientData clientData (in)
Valor arbitrario de una palabra para pasar a proc.
const char *name1 (in)
Nombre de la variable escalar o de matriz (sin índice de matriz).
const char *name2 (in)
Para un rastreo de un elemento de una matriz, da el índice del elemento. Para rastreos en variables escalares o en matrices completas, es NULL.
ClientData prevClientData (in)
Si no es NULL, da el último valor devuelto por Tcl_VarTraceInfo o Tcl_VarTraceInfo2, por lo que esta llamada devolverá información sobre el siguiente rastreo. Si es NULL, esta llamada devolverá información sobre el primer rastreo.

DESCRIPCIÓN

Tcl_TraceVar permite a un procedimiento C monitorizar y controlar el acceso a una variable Tcl, de modo que el procedimiento C sea invocado cada vez que la variable sea leída, escrita o eliminada. Si la creación del rastreo tiene éxito, Tcl_TraceVar devuelve TCL_OK. Si ocurrió un error (p. ej., varName especifica un elemento de una matriz, pero la variable real no es una matriz), entonces se devuelve TCL_ERROR y se deja un mensaje de error en el resultado del intérprete.

El argumento flags de Tcl_TraceVar indica cuándo se invocará el procedimiento de rastreo y proporciona información para configurar el rastreo. Consiste en una combinación OR de cualquiera de los siguientes valores:

TCL_GLOBAL_ONLY
Normalmente, la variable se buscará en el nivel actual de llamada al procedimiento; si este bit está establecido, la variable se buscará a nivel global, ignorando cualquier procedimiento activo.
TCL_NAMESPACE_ONLY
Normalmente, la variable se buscará en el nivel actual de llamada al procedimiento; si este bit está establecido, la variable se buscará en el espacio de nombres actual, ignorando cualquier procedimiento activo.
TCL_TRACE_READS
Invocar proc cada vez que se intente leer la variable.
TCL_TRACE_WRITES
Invocar proc cada vez que se intente modificar la variable.
TCL_TRACE_UNSETS
Invocar proc cada vez que se elimine la variable. Una variable puede ser eliminada explícitamente mediante un comando unset, o implícitamente cuando un procedimiento retorna (sus variables locales se eliminan automáticamente) o cuando se elimina el intérprete (todas las variables se eliminan automáticamente).
TCL_TRACE_ARRAY
Invocar proc cada vez que se invoque el comando array. Esto da al procedimiento de rastreo la oportunidad de actualizar la matriz antes de que se llamen los nombres de matriz o array get. Tenga en cuenta que esto se llama antes de un array set, pero eso activará los rastreos de escritura.
TCL_TRACE_RESULT_DYNAMIC
El resultado de invocar proc es una cadena asignada dinámicamente que será liberada por la biblioteca Tcl mediante una llamada a ckfree. No se puede especificar al mismo tiempo que TCL_TRACE_RESULT_OBJECT.
TCL_TRACE_RESULT_OBJECT
El resultado de invocar proc es un Tcl_Obj* (convertido a char*) con un recuento de referencias de al menos uno. La propiedad de esa referencia se transferirá al núcleo de Tcl para su liberación (cuando el núcleo haya terminado con él) mediante una llamada a Tcl_DecrRefCount. No se puede especificar al mismo tiempo que TCL_TRACE_RESULT_DYNAMIC.

Cada vez que ocurra una de las operaciones especificadas en la variable, se invocará proc. Debería tener argumentos y resultado que coincidan con el tipo Tcl_VarTraceProc:

typedef char *Tcl_VarTraceProc(
        ClientData clientData,
        Tcl_Interp *interp,
        const char *name1,
        const char *name2,
        int flags);

Los parámetros clientData e interp tendrán los mismos valores que los pasados a Tcl_TraceVar cuando se creó el rastreo. ClientData típicamente apunta a una estructura de datos específica de la aplicación que describe qué hacer cuando se invoca proc. Name1 y name2 dan el nombre de la variable trazada en la forma normal de dos partes (ver la descripción de Tcl_TraceVar2 abajo para detalles). Flags es una combinación OR de bits que proporcionan varias piezas de información. Uno de los bits TCL_TRACE_READS, TCL_TRACE_WRITES, TCL_TRACE_ARRAY, o TCL_TRACE_UNSETS se establecerá en flags para indicar qué operación se está realizando en la variable. El bit TCL_GLOBAL_ONLY se establecerá siempre que la variable que se está accediendo sea una variable global no accesible desde el nivel actual de llamada al procedimiento: el procedimiento de rastreo deberá pasar este flag de vuelta a procedimientos relacionados con variables como Tcl_GetVar si intenta acceder a la variable. El bit TCL_NAMESPACE_ONLY se establecerá siempre que la variable que se está accediendo sea una variable de espacio de nombres no accesible desde el nivel actual de llamada al procedimiento: el procedimiento de rastreo deberá pasar este flag de vuelta a procedimientos relacionados con variables como Tcl_GetVar si intenta acceder a la variable. El bit TCL_TRACE_DESTROYED se establecerá en flags si el rastreo está a punto de ser destruido; esta información puede ser útil para proc para que pueda limpiar sus propias estructuras de datos internas (ver la sección TCL_TRACE_DESTROYED abajo para más detalles). Por último, el bit TCL_INTERP_DESTROYED se establecerá si se está destruyendo todo el intérprete. Cuando este bit está establecido, proc debe ser especialmente cuidadoso con las cosas que hace (ver la sección TCL_INTERP_DESTROYED abajo). El valor de retorno del procedimiento de rastreo normalmente debería ser NULL; ver RETORNOS DE ERROR abajo para información sobre otras posibilidades.

Tcl_UntraceVar se puede usar para eliminar un rastreo. Si la variable especificada por interp, varName, y flags tiene un rastreo establecido con flags, proc, y clientData, entonces se elimina el rastreo correspondiente. Si no existe dicho rastreo, la llamada a Tcl_UntraceVar no tiene efecto. Los mismos bits son válidos para flags que para las llamadas a Tcl_TraceVar.

Tcl_VarTraceInfo se puede usar para recuperar información sobre rastreos establecidos en una variable dada. El valor de retorno de Tcl_VarTraceInfo es el clientData asociado con un rastreo particular. El rastreo debe estar en la variable especificada por los argumentos interp, varName, y flags (solo los bits TCL_GLOBAL_ONLY y TCL_NAMESPACE_ONLY de flags se usan; otros bits se ignoran) y su procedimiento de rastreo debe ser el mismo que el argumento proc. Si el argumento prevClientData es NULL, entonces el valor de retorno corresponde al primer rastreo coincidente (el creado más recientemente), o NULL si no hay rastreos coincidentes

Si el argumento prevClientData no es NULL, entonces debe ser el valor devuelto de una llamada previa a Tcl_VarTraceInfo. En este caso, el nuevo valor devuelto corresponderá al próximo registro de seguimiento que coincida con el clientData del registro cuyo prevClientData coincide con prevClientData, o NULL si no hay registros de seguimiento que coincidan con prevClientData o si no hay más registros de seguimiento después de él. Este mecanismo permite pasar por todos los registros de seguimiento de una variable dada que tienen el mismo proc.

NOMBRES DE DOS PARTES

Los procedimientos Tcl_TraceVar2, Tcl_UntraceVar2 y Tcl_VarTraceInfo2 son idénticos a Tcl_TraceVar, Tcl_UntraceVar y Tcl_VarTraceInfo, respectivamente, excepto que el nombre de la variable consta de dos partes. Name1 da el nombre de una variable escalar o array, y name2 da el nombre de un elemento dentro de un array. Cuando name2 es NULL, name1 puede contener tanto el nombre de un array como de un elemento. Si el nombre contiene una paréntesis abierta y termina con una cerrada, el valor entre ellas se trata como un nombre de elemento (que puede tener cualquier valor de cadena) y los caracteres antes de la primera paréntesis se tratan como el nombre de un array. Si name2 es NULL y name1 no se refiere a un elemento de array, significa que el variable es escalar o el seguimiento se establece en el array completo en lugar de en un elemento individual (ver más información en SEGUIMIENTOS DE ARRAY ENTEROS).

ACCESOS A VARIABLES DURANTE LOS SEGUIMIENTOS

Durante los seguimientos de lectura, escritura y array, el procedimiento de seguimiento puede leer, escribir o quitar el variable seguimiento usando Tcl_GetVar2, Tcl_SetVar2 y otros procedimientos. Mientras proc se ejecuta, los seguimientos están temporariamente desactivados para la variable, así que llamadas a Tcl_GetVar2 y Tcl_SetVar2 no causan la invocación de proc o otros procedimientos de seguimiento. Solo se desactiva el seguimiento para la variable cuyo procedimiento de seguimiento está activo; los accesos a otras variables seguirán siendo registrados. Sin embargo, si la variable se quita durante un seguimiento de lectura o escritura, se invocarán seguimientos de quita.

Durante los seguimientos de quita, la variable ya ha sido completamente eliminada. Es posible que el procedimiento de seguimiento lea o escriba la variable, pero esto será una versión nueva de la variable. Los seguimientos no están desactivados durante los seguimientos de quita, como en los de lectura y escritura, pero las existentes han sido eliminadas de la variable antes de que se invoquen los procedimientos de seguimiento. Si nuevos seguimientos se establecen mediante procedimientos de quita, estos se invocarán al acceder a la variable por parte de los procedimientos de seguimiento de seguimiento.

TIEMPO DE LOS CALLBACK

Cuando se especifica el seguimiento de lectura para una variable, el procedimiento de seguimiento se invoca cada vez que se lee el valor de la variable. Esto incluye comandos set de Tcl, notación $ en comandos de Tcl, y invocaciones a las procedimientos Tcl_GetVar y Tcl_GetVar2. Proc se invoca justo antes de devolver el valor de la variable. Puede modificar el valor de la variable para afectar lo que se devuelve por el acceso seguimiento. Si lo quita, el acceso devolverá un error, como si la variable nunca existiera.

Cuando se especifica el seguimiento de escritura para una variable, el procedimiento de seguimiento se invoca cada vez que el valor de la variable se modifica. Esto incluye comandos set, comandos que modifican variables como efecto secundario (como catch y scan), y llamadas a las procedimientos Tcl_SetVar y Tcl_SetVar2. Proc se invoca después de que el valor de la variable haya sido modificado, pero antes de que el nuevo valor de la variable se devuelva. Puede modificar el valor de la variable para sobreescalar la modificación y para determinar el valor realmente devuelto por el acceso seguimiento. Si elimina la variable, el acceso seguimiento devolverá una cadena vacía.

Cuando se especifica un seguimiento de array, el procedimiento de seguimiento se invoca al principio del implentamiento de los comandos de array, antes de que se invoquen las operaciones como get, set o nombres. El procedimiento de seguimiento puede modificar los elementos de array con Tcl_SetVar y Tcl_SetVar2.

Cuando se especifica un seguimiento de quita, el procedimiento de seguimiento se invoca cada vez que la variable es destruida. Los seguimientos se invocan después de que la variable haya sido completamente destruida.

SEGUIMIENTOS DE ARRAY ENTERO

Si una llamada a Tcl_TraceVar o Tcl_TraceVar2 especifica el nombre de un array sin un índice dentro del array, el seguimiento se establecerá en el array en su totalidad. Esto significa que proc se invocará cada vez que se acceda a cualquier elemento del array en las formas especificadas por flags. Cuando un array se desactiva, un seguimiento de array se invoca solo una vez, con name1 igual al nombre del array y name2 NULL; no se invoca una vez por cada elemento.

MÚLTIPLES SEGUIMIENTOS

Es posible tener varios seguimientos en la misma variable. Cuando ocurre esto, todos los procedimientos de seguimiento se invocan en cada acceso, en orden desde el más reciente a menos reciente. Cuando existen seguimientos de array en un array y seguimientos en elementos individuales, los seguimientos de array se invocan antes que los de elementos individuales. Si un seguimiento de lectura o escritura quita la variable, todos los seguimientos de quita se invocan, pero los restantes seguimientos de lectura y escritura se omiten.

DEVOLUCIONES DE ERROR

Durante condiciones normales, los procedimientos de seguimiento deben devolver NULL, indicando el éxito. Si proc devuelve un valor no NULL, significa que ocurrió un error. El valor devuelto debe ser un puntero a una cadena estática que contenga un mensaje de error, no salvo si (exactamente) uno de los flags TCL_TRACE_RESULT_DYNAMIC y TCL_TRACE_RESULT_OBJECT está establecido, que especifican que el resultado sea una cadena dinámica (a ser liberada con ckfree) o un Tcl_Obj* (casted a char* y liberado con Tcl_DecrRefCount) que contenga el mensaje de error. Si un procedimiento de seguimiento devuelve un error, no se invocan más seguimientos para el acceso y el acceso seguimiento se aborta con el mensaje dado. Los procedimientos de seguimiento pueden usar esta funcionalidad para hacer las variables leídas solo, por ejemplo (pero note que el valor de la variable ya fue modificado antes del procedimiento de seguimiento, así que el procedimiento de seguimiento tendrá que restaurar el valor correcto).

El valor devuelto por proc solo se usa durante los seguimientos de lectura y escritura. Durante los seguimientos de quita, el valor se ignora y todos los procedimientos de seguimiento relevantes siempre se invocan.

RESTRICCIONES

Un procedimiento de seguimiento puede llamarse en cualquier momento, incluso cuando hay resultados parcialmente formados almacenados en el interpretador. Si el procedimiento de seguimiento realiza alguna acción que pueda dañar este resultado (como llamar a Tcl_Eval), debe usar Tcl_SaveInterpState y rutinas relacionadas para guardar y restaurar el estado original del interpretador antes de devolverlo.

VARIABLES NO DEFINIDAS

Es legal establecer un seguimiento en una variable no definida. La variable aún se muestra como no definida hasta que su valor se establezca por primera vez. Si una variable no definida se registra y luego se quita, el quita fallará con un error (“no such variable”), pero el procedimiento de seguimiento se seguirá invocando.

FLAG TCL_TRACE_DESTROYED

En una callback de quita a proc, el bit TCL_TRACE_DESTROYED se establece en flags si el seguimiento se está eliminando como parte del borrado de la variable. Todos los seguimientos en una variable se eliminan siempre que la variable se elimine; el único tiempo en que TCL_TRACE_DESTROYED no se establece es cuando se invoca un seguimiento de array cuando solo se elimina un elemento individual de un array.

BIT TCL_INTERP_DESTROYED

Cuando un interpretador se elimina, se invocan los seguimientos para todas sus variables. El bit TCL_INTERP_DESTROYED se establece en el argumento flags pasado a los procedimientos de seguimiento. Los procedimientos de seguimiento deben ser extremadamente cuidadosos con lo que hagan si el bit TCL_INTERP_DESTROYED está establecido. No es seguro invocar cualquier procedimiento Tcl en el interpretador, ya que su estado parte de ser eliminado. Todo lo que los procedimientos de seguimiento deben hacer en estos casos es limpiar y liberar sus estructuras internas.

BUGS

Tcl no realiza ninguna verificación de errores para evitar que los procedimientos de seguimiento mal usen el interpretador cuando el bit TCL_INTERP_DESTROYED esté activo.

Los seguimientos de array no están integrados aún con el comando Tcl info exists, ni hay acceso a los seguimientos de array a nivel de Tcl.
