NOMBRE

Tcl_RegExpMatch, Tcl_RegExpCompile, Tcl_RegExpExec, Tcl_RegExpRange, Tcl_GetRegExpFromObj, Tcl_RegExpMatchObj, Tcl_RegExpExecObj, Tcl_RegExpGetInfo - Concordancia de patrones con expresiones regulares

SINOPSIS

#include <tcl.h>

int
Tcl_RegExpMatchObj(interp, textObj, patObj)

int
Tcl_RegExpMatch(interp, text, pattern)

Tcl_RegExp
Tcl_RegExpCompile(interp, pattern)

int
Tcl_RegExpExec(interp, regexp, text, start)

void
Tcl_RegExpRange(regexp, index, startPtr, endPtr)

Tcl_RegExp
Tcl_GetRegExpFromObj(interp, patObj, cflags)

int
Tcl_RegExpExecObj(interp, regexp, textObj, offset, nmatches, eflags)

void
Tcl_RegExpGetInfo(regexp, infoPtr)

ARGUMENTOS

Tcl_Interp *interp (in)
Intérprete de Tcl a utilizar para la notificación de errores. El intérprete puede ser NULL si no se desea notificación de errores.
Tcl_Obj *textObj (in/out)
Se refiere al valor del que se obtendrá el texto a buscar. La representación interna del valor puede ser convertida a un formato que pueda ser buscado eficientemente.
Tcl_Obj *patObj (in/out)
Se refiere al valor del que se obtendrá una expresión regular. La expresión regular compilada se almacena en caché en el valor.
const char *text (in)
Texto en el que buscar una coincidencia con una expresión regular.
const char *pattern (in)
Cadena en forma de patrón de expresión regular.
Tcl_RegExp regexp (in)
Expresión regular compilada. Debe haber sido devuelta previamente por Tcl_GetRegExpFromObj o Tcl_RegExpCompile.
const char *start (in)
Si text es solo una porción de alguna otra cadena, este argumento identifica el inicio de la cadena más grande. Si no es el mismo que text, entonces no se permitirán coincidencias de “^”.
int index (in)
Especifica qué rango se desea: 0 significa el rango de toda la coincidencia, 1 o mayor significa el rango que coincidió con una subexpresión entre paréntesis.
const char **startPtr (out)
La dirección del primer carácter en el rango se almacena aquí, o NULL si no existe tal rango.
const char **endPtr (out)
La dirección del carácter justo después del último en el rango se almacena aquí, o NULL si no existe tal rango.
int cflags (in)
Combinación OR de los indicadores de compilación TCL_REG_ADVANCED, TCL_REG_EXTENDED, TCL_REG_BASIC, TCL_REG_EXPANDED, TCL_REG_QUOTE, TCL_REG_NOCASE, TCL_REG_NEWLINE, TCL_REG_NLSTOP, TCL_REG_NLANCH, TCL_REG_NOSUB, y TCL_REG_CANMATCH. Véase más abajo para más información.
int offset (in)
El desplazamiento de caracteres en el texto donde debe comenzar la coincidencia. El valor del desplazamiento no tiene impacto en las coincidencias de ^. Este comportamiento está controlado por eflags.
int nmatches (in)
El número de subexpresiones coincidentes que deben recordarse para su uso posterior. Si este valor es 0, entonces no se calculará información de coincidencia de subexpresiones. Si el valor es -1, entonces se recordarán todas las subexpresiones coincidentes. Cualquier otro valor se tomará como el número máximo de subexpresiones a recordar.
int eflags (in)
Combinación OR de los indicadores de ejecución TCL_REG_NOTBOL y TCL_REG_NOTEOL. Véase más abajo para más información.
Tcl_RegExpInfo *infoPtr (out)
La dirección de la ubicación donde la información sobre una coincidencia previa debe ser almacenada por Tcl_RegExpGetInfo.

DESCRIPCIÓN

Tcl_RegExpMatch determina si su argumento pattern coincide con regexp, donde regexp se interpreta como una expresión regular utilizando las reglas de la página de referencia re_syntax. Si hay una coincidencia, Tcl_RegExpMatch devuelve 1. Si no hay coincidencia, Tcl_RegExpMatch devuelve 0. Si ocurre un error en el proceso de coincidencia (por ejemplo, pattern no es una expresión regular válida), entonces Tcl_RegExpMatch devuelve -1 y deja un mensaje de error en el resultado del intérprete. Tcl_RegExpMatchObj es similar a Tcl_RegExpMatch excepto que opera en los valores Tcl textObj y patObj en lugar de cadenas UTF. Tcl_RegExpMatchObj es generalmente más eficiente que Tcl_RegExpMatch, por lo que es la interfaz preferida.

Tcl_RegExpCompile, Tcl_RegExpExec y Tcl_RegExpRange proporcionan acceso de bajo nivel al comparador de patrones de expresiones regulares. Tcl_RegExpCompile compila una cadena de expresión regular en el formato interno utilizado para la comparación eficiente de patrones. El valor de retorno es un token para este formato compilado, que puede ser utilizado en llamadas posteriores a Tcl_RegExpExec o Tcl_RegExpRange. Si ocurre un error al compilar la expresión regular, Tcl_RegExpCompile devuelve NULL y deja un mensaje de error en el resultado del intérprete. Nota: el valor de retorno de Tcl_RegExpCompile solo es válido hasta la próxima llamada a Tcl_RegExpCompile; no es seguro conservar estos valores durante períodos prolongados.

Tcl_RegExpExec ejecuta el comparador de patrones de expresiones regulares. Devuelve 1 si text contiene un rango de caracteres que coinciden con regexp, 0 si no se encuentra coincidencia y -1 si ocurre un error. En caso de error, Tcl_RegExpExec deja un mensaje de error en el resultado del intérprete. Al buscar en una cadena múltiples coincidencias de un patrón, es importante distinguir entre el inicio de la cadena original y el inicio de la búsqueda actual. Por ejemplo, al buscar la segunda ocurrencia de una coincidencia, el argumento text podría apuntar al carácter justo después de la primera coincidencia; sin embargo, es importante que el comparador de patrones sepa que este no es el inicio de la cadena completa, para que no permita que los átomos “^” en el patrón coincidan. El argumento start proporciona esta información apuntando al inicio de la cadena general que contiene text. Start será menor o igual a text; si es menor que text, no se permitirán coincidencias de ^.

Tcl_RegExpRange puede ser invocado después de que Tcl_RegExpExec devuelva; proporciona información detallada sobre qué rangos de la cadena coincidieron con qué partes del patrón. Tcl_RegExpRange devuelve un par de punteros en *startPtr y *endPtr que identifican un rango de caracteres en la cadena fuente para la llamada más reciente a Tcl_RegExpExec. Index indica cuál de varios rangos se desea: si index es 0, se devuelve información sobre el rango general de caracteres que coincidió con el patrón completo; de lo contrario, se devuelve información sobre el rango de caracteres que coincidió con la subexpresión entre paréntesis index dentro del patrón. Si no existe un rango correspondiente a index, se almacena NULL en *startPtr y *endPtr.

Tcl_GetRegExpFromObj, Tcl_RegExpExecObj y Tcl_RegExpGetInfo son interfaces de valor que proporcionan el control más directo de la biblioteca de expresiones regulares de Henry Spencer. Para los usuarios que necesiten modificar las opciones de compilación y ejecución directamente, se recomienda utilizar estas interfaces en lugar de llamar a las funciones internas de regexp. Estas interfaces manejan los detalles de las traducciones de UTF a Unicode, además de proporcionar un rendimiento mejorado a través del almacenamiento en caché en los valores del patrón y la cadena.

Tcl_GetRegExpFromObj intenta devolver una expresión regular compilada de patObj. Si el valor no contiene ya una expresión regular compilada, intentará crear una a partir de la cadena en el valor y la asignará a la representación interna de patObj. El valor de retorno de esta función es de tipo Tcl_RegExp. El valor de retorno es un token para este formato compilado, que puede ser utilizado en llamadas posteriores a Tcl_RegExpExecObj o Tcl_RegExpGetInfo. Si ocurre un error al compilar la expresión regular, Tcl_GetRegExpFromObj devuelve NULL y deja un mensaje de error en el resultado del intérprete. El token de la expresión regular puede ser utilizado siempre que la representación interna de patObj haga referencia al formato compilado. NAME

Tcl_RegExpExec, Tcl_RegExpExecObj, Tcl_RegExpGetInfo – execute Tcl regular expression match

SYNOPSIS

#include <tcl.h>

int
Tcl_RegExpExec(Tcl_Interp *interp,
        const char *string, const char *regexp, const char *stringEnd,
        long offset, int nmatches, int *matchCoords);
int
Tcl_RegExpExecObj(Tcl_Interp *interp,
        const Tcl_Obj *objPtr, const char *regexp,
        long offset, int nmatches, int eflags,
        Tcl_RegExpInfo *infoPtr);
int
Tcl_RegExpGetInfo(Tcl_Interp *interp,
        const char *regexp, Tcl_RegExpInfo *infoPtr);

ARGUMENTS

TCL_REG_ADVANCED
Compile advanced regular expressions (“ARE”s). This mode corresponds to the normal regular expression syntax accepted by the Tcl regexp and regsub commands.
TCL_REG_EXTENDED
Compile extended regular expressions (“ERE”s). This mode corresponds to the regular expression syntax recognized by Tcl 8.0 and earlier versions.
TCL_REG_BASIC
Compile basic regular expressions (“BRE”s). This mode corresponds to the regular expression syntax recognized by common Unix utilities like sed and grep. This is the default if no flags are specified.
TCL_REG_EXPANDED
Compile the regular expression (basic, extended, or advanced) using an expanded syntax that allows comments and whitespace. This mode causes non-backslashed non-bracket-expression white space and #-to-end-of-line comments to be ignored.
TCL_REG_QUOTE
Compile a literal string, with all characters treated as ordinary characters.
TCL_REG_NOCASE
Compile for matching that ignores upper/lower case distinctions.
TCL_REG_NEWLINE
Compile for newline-sensitive matching. By default, newline is a completely ordinary character with no special meaning in either regular expressions or strings. With this flag, “[^” bracket expressions and “.” never match newline, “^” matches an empty string after any newline in addition to its normal function, and “$” matches an empty string before any newline in addition to its normal function. REG_NEWLINE is the bit-wise OR of REG_NLSTOP and REG_NLANCH.
TCL_REG_NLSTOP
Compile for partial newline-sensitive matching, with the behavior of “[^” bracket expressions and “.” affected, but not the behavior of “^” and “$”. In this mode, “[^” bracket expressions and “.” never match newline.
TCL_REG_NLANCH
Compile for inverse partial newline-sensitive matching, with the behavior of “^” and “$” (the “anchors”) affected, but not the behavior of “[^” bracket expressions and “.”. In this mode “^” matches an empty string after any newline in addition to its normal function, and “$” matches an empty string before any newline in addition to its normal function.
TCL_REG_NOSUB
Compile for matching that reports only success or failure, not what was matched. This reduces compile overhead and may improve performance. Subsequent calls to Tcl_RegExpGetInfo or Tcl_RegExpRange will not report any match information.
TCL_REG_CANMATCH
Compile for matching that reports the potential to complete a partial match given more text (see below).

Only one of TCL_REG_EXTENDED, TCL_REG_ADVANCED, TCL_REG_BASIC, and TCL_REG_QUOTE may be specified.

Tcl_RegExpExecObj executes the regular expression pattern matcher. It returns 1 if objPtr contains a range of characters that match regexp, 0 if no match is found, and -1 if an error occurs. In the case of an error, Tcl_RegExpExecObj leaves an error message in the interpreter result. The nmatches value indicates to the matcher how many subexpressions are of interest. If nmatches is 0, then no subexpression match information is recorded, which may allow the matcher to make various optimizations. If the value is -1, then all of the subexpressions in the pattern are remembered. If the value is a positive integer, then only that number of subexpressions will be remembered. Matching begins at the specified Unicode character index given by offset. Unlike Tcl_RegExpExec, the behavior of anchors is not affected by the offset value. Instead the behavior of the anchors is explicitly controlled by the eflags argument, which is a bit-wise OR of zero or more of the following flags:

TCL_REG_NOTBOL
The starting character will not be treated as the beginning of a line or the beginning of the string, so “^” will not match there. Note that this flag has no effect on how “\A” matches.
TCL_REG_NOTEOL
The last character in the string will not be treated as the end of a line or the end of the string, so “$” will not match there. Note that this flag has no effect on how “\Z” matches.

Tcl_RegExpGetInfo retrieves information about the last match performed with a given regular expression regexp. The infoPtr argument contains a pointer to a structure that is defined as follows:

typedef struct Tcl_RegExpInfo {
    int nsubs;
    Tcl_RegExpIndices *matches;
    long extendStart;
} Tcl_RegExpInfo;

The nsubs field contains a count of the number of parenthesized subexpressions within the regular expression. If the TCL_REG_NOSUB was used, then this value will be zero. The matches field points to an array of nsubs+1 values that indicate the bounds of each subexpression matched. The first element in the array refers to the range matched by the entire regular expression, and subsequent elements refer to the parenthesized subexpressions in the order that they appear in the pattern. Each element is a structure that is defined as follows:

typedef struct Tcl_RegExpIndices {
    long start;
    long end;
} Tcl_RegExpIndices;

The start and end values are Unicode character indices relative to the offset location within objPtr where matching began. The start index identifies the first character of the matched subexpression. The end index identifies the first character after the matched subexpression. If the subexpression matched the empty string, then start and end will be equal. If the subexpression did not participate in the match, then start and end will be set to -1.

The extendStart field in Tcl_RegExpInfo is only set if the TCL_REG_CANMATCH flag was used. It indicates the first character in the string where a match could occur. If a match was found, this will be the same as the beginning of the current match. If no match was found, then it indicates the earliest point at which a match might occur if additional text is appended to the string. If it is no match is possible even with further text, this field will be set to -1.
