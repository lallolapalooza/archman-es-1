DESCRIPTION

The Tcl channel mechanism provides a device-independent and platform-independent mechanism for performing buffered input and output operations on a variety of file, socket, and device types. The channel mechanism is extensible to new channel types, by providing a low-level channel driver for the new type; the channel driver interface is described in the manual entry for Tcl_CreateChannel. The channel mechanism provides a buffering scheme modeled after Unix's standard I/O, and it also allows for nonblocking I/O on channels.

The procedures described in this manual entry comprise the C APIs of the generic layer of the channel architecture. For a description of the channel driver architecture and how to implement channel drivers for new types of channels, see the manual entry for Tcl_CreateChannel.

TCL_OPENFILECHANNEL

Opens a file specified by fileName and returns a Tcl channel handle for it. The file is opened with the specified mode and permissions. The mode argument is a string such as "r", "w", "a", "r+", etc., just like the mode argument to the Tcl open command. The permissions argument specifies the access permissions for the file if it is created (e.g., 0644); it is ignored if the file already exists. If an error occurs, an error message is set in interp and NULL is returned.

TCL_OPENCOMMANDCHANNEL

Creates a channel that represents a pipeline of commands. The commands to execute are given by argv, and argc specifies the number of commands. The flags argument controls how the standard input, output, and error handles of the first child in the pipeline are handled. See the flags argument description for details.

TCL_MAKEFILECHANNEL

Creates a Tcl channel handle from an existing operating system file handle (e.g., a file descriptor or a Windows HANDLE). The handle argument is the operating system handle, and readOrWrite specifies whether the handle is readable (TCL_READABLE) or writable (TCL_WRITABLE) or both. This procedure is useful for associating Tcl channels with existing I/O handles, such as those inherited from a parent process or obtained from an operating system library.

TCL_GETCHANNEL

Returns a handle to the Tcl channel named channelName. If modePtr is not NULL, it points to an integer variable that will receive an OR-ed combination of TCL_READABLE and TCL_WRITABLE indicating the access modes of the channel.

TCL_GETCHANNELNAMES

Returns a Tcl list object containing the names of all currently registered Tcl channels. The names are stored in the interpreter's result object.

TCL_GETCHANNELNAMESEX

Returns a Tcl list object containing the names of all currently registered Tcl channels whose names match the glob-style pattern. If pattern is NULL, it behaves like Tcl_GetChannelNames.

TCL_REGISTERCHANNEL

Registers the given channel with the interpreter interp under its name. This makes the channel available for use by Tcl commands such as puts and gets.

TCL_UNREGISTERCHANNEL

Unregisters the given channel from the interpreter interp. The channel handle remains valid, but the channel can no longer be accessed by its name in Tcl scripts. This is typically done when a channel is being closed or replaced.

TCL_DETACHCHANNEL

Detaches the channel from the interpreter. This means that the channel will not be closed automatically when the interpreter is destroyed. The caller is responsible for closing the channel eventually. This is useful for channels that are managed externally.

TCL_ISSTANDARDCHANNEL

Returns true (1) if the given channel is one of the standard channels (stdin, stdout, stderr) associated with the interpreter, and false (0) otherwise.

TCL_CLOSE

Closes the channel channel. Any buffered output is flushed before the channel is closed. If an error occurs during closing (e.g., flushing output fails), an error message is set in interp and a non-zero value is returned. Otherwise, zero is returned.

TCL_READCHARS

Reads up to charsToRead characters from the channel and stores them in the Tcl object pointed to by readObjPtr. If appendFlag is true, the characters are appended to the object's current value; otherwise, the object is replaced with the characters read. The channel must be readable. Returns the number of characters actually read, or -1 if an error occurred. A return value less than charsToRead may indicate end-of-file or that the channel is currently blocked on input.

TCL_READ

Reads up to bytesToRead bytes from the channel and stores them in the buffer readBuf. The buffer must be large enough to hold bytesToRead bytes. The channel must be readable. Returns the number of bytes actually read, or -1 if an error occurred. A return value less than bytesToRead may indicate end-of-file or that the channel is currently blocked on input. This function is suitable for reading binary data.

TCL_GETSOBJ

Reads characters from the channel until a newline character is encountered or end-of-file is reached. The characters read (not including the newline, if any) are stored in the Tcl object pointed to by lineObjPtr, replacing its current value. The channel must be readable. Returns the number of characters read, or -1 if an error occurred. A return value less than the number of characters requested may indicate end-of-file or that the channel is currently blocked on input.

TCL_GETS

Reads characters from the channel until a newline character is encountered or end-of-file is reached. The characters read (not including the newline, if any) are appended to the Tcl dynamic string lineRead. The channel must be readable. Returns the number of characters read, or -1 if an error occurred. A return value less than the number of characters requested may indicate end-of-file or that the channel is currently blocked on input.

TCL_UNGETS

Pushes the string input of length inputLen back onto the channel's input buffer. If addAtEnd is true, the input is added to the end of the buffer; otherwise, it is added to the beginning. This is useful for implementing lookahead in channel input processing.

TCL_WRITEOBJ

Writes the contents of the Tcl object writeObjPtr to the channel. The channel must be writable. Returns the number of bytes written, or -1 if an error occurred. A return value less than the number of bytes available may indicate that the channel is currently blocked on output.

TCL_WRITECHARS

Writes up to bytesToWrite characters from the buffer charBuf to the channel. The channel must be writable. Returns the number of bytes written, or -1 if an error occurred. A return value less than bytesToWrite may indicate that the channel is currently blocked on output.

TCL_WRITE

Writes up to bytesToWrite bytes from the buffer byteBuf to the channel. The channel must be writable. Returns the number of bytes written, or -1 if an error occurred. A return value less than bytesToWrite may indicate that the channel is currently blocked on output. This function is suitable for writing binary data.

TCL_READRAW

Reads up to bytesToRead bytes from the channel and stores them in the buffer readBuf. This function bypasses any character encoding or decoding conversions that might be configured for the channel, treating the channel as a raw byte stream. The channel must be readable. Returns the number of bytes actually read, or -1 if an error occurred. A return value less than bytesToRead may indicate end-of-file or that the channel is currently blocked on input.

TCL_WRITERAW

Writes up to bytesToWrite bytes from the buffer byteBuf to the channel. This function bypasses any character encoding or decoding conversions that might be configured for the channel, treating the channel as a raw byte stream. The channel must be writable. Returns the number of bytes written, or -1 if an error occurred. A return value less than bytesToWrite may indicate that the channel is currently blocked on output.

TCL_EOF

Returns true (1) if end-of-file has been reached on the channel, and false (0) otherwise. Note that this checks the buffered input; characters may still be available in the buffer even if EOF has been reached on the underlying device.

TCL_FLUSH

Flushes any buffered output to the channel. If an error occurs during the flush operation, an error message is set in interp and a non-zero value is returned. Otherwise, zero is returned.

TCL_INPUTBLOCKED

Returns true (1) if the channel is currently blocked on input (i.e., a nonblocking read operation would fail), and false (0) otherwise. This indicates that no data is currently available for reading.

TCL_INPUTBUFFERED

Returns the number of bytes currently available in the input buffer of the channel.

TCL_OUTPUTBUFFERED

Returns the number of bytes currently waiting in the output buffer of the channel.

TCL_SEEK

Sets the current position in the channel to the byte offset specified by offset, relative to the position specified by seekMode. seekMode can be SEEK_SET (relative to the beginning of the file), SEEK_CUR (relative to the current position), or SEEK_END (relative to the end of the file). Returns the new absolute byte offset in the file from the beginning of the file, or -1 if an error occurred. This operation is only supported on channels that support seeking (e.g., regular files).

TCL_TELL

Returns the current byte offset in the channel from the beginning of the file. Returns -1 if the channel does not support seeking or if an error occurred. This operation is only supported on channels that support seeking.

TCL_TRUNCATECHANNEL

Truncates the file associated with the channel to the specified length in bytes. If length is greater than the current size of the file, the file is extended and filled with null bytes. This operation is only supported on files that are open for writing.

TCL_GETCHANNELOPTION

Retrieves the value of the channel option specified by optionName and stores it in the Tcl dynamic string pointed to by optionValue. The optionName can be any valid option for the Tcl fconfigure command (e.g., "-blocking", "-buffering", "-encoding"). If the option is not set or an error occurs, the dynamic string will be empty.

TCL_SETCHANNELOPTION

Sets the channel option specified by optionName to the value specified by newValue. The optionName and newValue arguments are strings representing the option name and its new value, similar to how they are used with the Tcl fconfigure command.

TCL_OPENFILECHANNEL

Tcl_OpenFileChannel abre un archivo especificado por fileName y devuelve un manejador de canal que se puede utilizar para realizar operaciones de entrada y salida en el archivo. Esta API está modelada según el procedimiento fopen de la biblioteca estándar de E/S de Unix. La sintaxis y el significado de todos los argumentos son similares a los dados en el comando open de Tcl al abrir un archivo. Si ocurre un error al abrir el canal, Tcl_OpenFileChannel devuelve NULL y registra un código de error POSIX que puede recuperarse con Tcl_GetErrno. Además, si interp no es NULL, Tcl_OpenFileChannel deja un mensaje de error en el resultado de interp después de cualquier error. A partir de Tcl 8.4, la API basada en valor Tcl_FSOpenFileChannel debe usarse preferentemente a Tcl_OpenFileChannel siempre que sea posible.

El canal recién creado no se registra en el intérprete proporcionado; para registrarlo, use Tcl_RegisterChannel, descrito a continuación. Si uno de los canales estándar, stdin, stdout o stderr se cerró previamente, el acto de crear el nuevo canal también lo asigna como reemplazo del canal estándar.

TCL_OPENCOMMANDCHANNEL

Tcl_OpenCommandChannel proporciona una interfaz a nivel de C para las funciones de los comandos exec y open. Crea una secuencia de subprocesos especificados por los argumentos argv y argc y devuelve un canal que se puede utilizar para comunicarse con estos subprocesos. El argumento flags indica qué tipo de comunicación existirá con la tubería de comandos.

Si la bandera TCL_STDIN está establecida, la entrada estándar del primer subproceso estará vinculada al canal: escribir en el canal proporcionará entrada al subproceso. Si TCL_STDIN no está establecida, la entrada estándar del primer subproceso será la misma que la entrada estándar de esta aplicación. Si TCL_STDOUT está establecida, la salida estándar del último subproceso se puede leer del canal; de lo contrario, va a la salida estándar de esta aplicación. Si TCL_STDERR está establecida, la salida de error estándar de todos los subprocesos se devuelve al canal y resulta en un error cuando se cierra el canal; de lo contrario, va al error estándar de esta aplicación. Si TCL_ENFORCE_MODE no está establecida, entonces argc y argv pueden redirigir los manejadores stdio para anular TCL_STDIN, TCL_STDOUT y TCL_STDERR; si está establecida, entonces es un error que argc y argv anulen los canales stdio para los cuales se han establecido TCL_STDIN, TCL_STDOUT y TCL_STDERR.

Si ocurre un error al abrir el canal, Tcl_OpenCommandChannel devuelve NULL y registra un código de error POSIX que puede recuperarse con Tcl_GetErrno. Además, Tcl_OpenCommandChannel deja un mensaje de error en el resultado del intérprete. interp no puede ser NULL.

El canal recién creado no se registra en el intérprete proporcionado; para registrarlo, use Tcl_RegisterChannel, descrito a continuación. Si uno de los canales estándar, stdin, stdout o stderr se cerró previamente, el acto de crear el nuevo canal también lo asigna como reemplazo del canal estándar.

TCL_MAKEFILECHANNEL

Tcl_MakeFileChannel crea un Tcl_Channel a partir de un manejador de archivo existente y específico de la plataforma. El canal recién creado no se registra en el intérprete proporcionado; para registrarlo, use Tcl_RegisterChannel, descrito a continuación. Si uno de los canales estándar, stdin, stdout o stderr se cerró previamente, el acto de crear el nuevo canal también lo asigna como reemplazo del canal estándar.

TCL_GETCHANNEL

Tcl_GetChannel devuelve un canal dado el channelName utilizado para crearlo con Tcl_CreateChannel y un puntero a un intérprete de Tcl en interp. Si no hay un canal con ese nombre registrado en ese intérprete, el procedimiento devuelve NULL. Si el argumento modePtr no es NULL, apunta a una variable entera que recibirá una combinación OR de TCL_READABLE y TCL_WRITABLE que describe si el canal está abierto para lectura y escritura.

Tcl_GetChannelNames y Tcl_GetChannelNamesEx escriben los nombres de los canales registrados en el resultado del intérprete como un valor de lista. Tcl_GetChannelNamesEx filtrará estos nombres según el pattern. Si pattern es NULL, no realizará ningún filtrado. El valor de retorno es TCL_OK si no ocurrieron errores al escribir en el resultado, de lo contrario es TCL_ERROR, y el mensaje de error se deja en el resultado del intérprete.

TCL_REGISTERCHANNEL

Tcl_RegisterChannel agrega un canal al conjunto de canales accesibles en interp. Después de esta llamada, los programas de Tcl que se ejecutan en ese intérprete pueden referirse al canal en operaciones de entrada o salida utilizando el nombre dado en la llamada a Tcl_CreateChannel. Después de esta llamada, el canal se convierte en propiedad del intérprete, y el llamador no debe llamar a Tcl_Close para el canal; el canal se cerrará automáticamente cuando se desregistre del intérprete.

El código que se ejecuta fuera de cualquier intérprete de Tcl puede llamar a Tcl_RegisterChannel con interp como NULL, para indicar que desea mantener una referencia a este canal. Posteriormente, el canal puede registrarse en un intérprete de Tcl y solo se cerrará cuando se hayan realizado el número correspondiente de llamadas a Tcl_UnregisterChannel. Esto permite que el código que se ejecuta fuera de cualquier intérprete mantenga de forma segura una referencia a un canal que también está registrado en un intérprete de Tcl.

Este procedimiento interactúa con el código que administra los canales estándar. Si no se inicializaron canales estándar antes de la primera llamada a Tcl_RegisterChannel, se inicializarán con esa llamada. Consulte Tcl_StandardChannels para obtener un tratado general sobre los canales estándar y el comportamiento de la biblioteca Tcl con respecto a ellos.

TCL_UNREGISTERCHANNEL

Tcl_UnregisterChannel elimina un canal del conjunto de canales accesibles en interp. Después de esta llamada, los programas de Tcl ya no podrán utilizar el nombre del canal para referirse al canal en ese intérprete. Si esta operación eliminó el último registro del canal en cualquier intérprete, el canal también se cierra y se destruye.

El código que no está asociado con un intérprete de Tcl puede llamar a Tcl_UnregisterChannel con interp como NULL, para indicar a Tcl que ya no mantiene una referencia a ese canal. Si esta es la última referencia al canal, se cerrará. Tcl_UnregisterChannel es muy similar a Tcl_DetachChannel excepto que también cerrará el canal si no existen más referencias a él.

TCL_DETACHCHANNEL

Tcl_DetachChannel elimina un canal del conjunto de canales accesibles en interp. Después de esta llamada, los programas de Tcl ya no podrán utilizar el nombre del canal para referirse al canal en ese intérprete. Más allá de eso, este comando no tiene ningún efecto adicional. No se puede utilizar en los canales estándar (stdout, stderr, stdin), y devolverá TCL_ERROR si se le pasa uno de esos canales.

El código que no está asociado con un intérprete de Tcl puede llamar a Tcl_DetachChannel con interp como NULL, para indicar a Tcl que ya no mantiene una referencia a ese canal. Si esta es la última referencia al canal, a diferencia de Tcl_UnregisterChannel, no se cerrará.

TCL_ISSTANDARDCHANNEL

Tcl_IsStandardChannel prueba si un canal es uno de los tres canales estándar, stdin, stdout o stderr. Si es así, devuelve 1, de lo contrario 0.

No se intenta comprobar si el canal dado o los canales estándar están inicializados o son válidos de alguna otra manera.

TCL_CLOSE

Tcl_Close destruye el canal channel, que debe denotar un canal actualmente abierto. El canal no debe estar registrado en ningún intérprete cuando se llama a Tcl_Close. La salida en búfer se vacía al dispositivo de salida del canal antes de destruir el canal, y cualquier entrada en búfer se descarta. Si este es un canal bloqueante, la llamada no regresa hasta que todos los datos en búfer se envían correctamente al dispositivo de salida del canal. Si este es un canal no bloqueante y hay salida en búfer que no se puede escribir sin bloquear, la llamada regresa inmediatamente; la salida se vacía en segundo plano y el canal se cerrará una vez que todos los datos en búfer se hayan enviado. En este caso, los errores durante el vaciado no se informan.

Si el canal se cerró correctamente, Tcl_Close devuelve TCL_OK. Si ocurre un error, Tcl_Close devuelve TCL_ERROR y registra un código de error POSIX que puede recuperarse con Tcl_GetErrno. Si el canal se está cerrando de forma síncrona y ocurre un error durante el cierre del canal y interp no es NULL, se deja un mensaje de error en el resultado del intérprete.

Nota: no es seguro llamar a Tcl_Close en un canal que ha sido registrado usando Tcl_RegisterChannel; consulte la documentación de Tcl_RegisterChannel, arriba, para obtener detalles. Si el canal ha sido proporcionado alguna vez como el argumento chan en una llamada a Tcl_RegisterChannel, debe usar en su lugar Tcl_UnregisterChannel, que llamará internamente a Tcl_Close cuando todas las llamadas a Tcl_RegisterChannel hayan sido igualadas por llamadas correspondientes a Tcl_UnregisterChannel.

TCL_READCHARS AND TCL_READ

Tcl_ReadChars consume bytes del channel, convirtiendo los bytes a UTF-8 basándose en la codificación del canal y almacenando los datos producidos en la representación de cadena de readObjPtr. El valor de retorno de Tcl_ReadChars es el número de caracteres, hasta charsToRead, que se almacenaron en readObjPtr. Si ocurre un error al leer, el valor de retorno es -1 y Tcl_ReadChars registra un código de error POSIX que puede recuperarse con Tcl_GetErrno.

Establecer ch

TCL_READCHARS, TCL_READOBJECTIONS, Y TCL_READ

Tcl_ReadChars lee hasta charsToRead caracteres del channel y los almacena en el buffer de Tcl value especificado por readObjPtr. Si charsToRead es negativo, el comando leera todos los caracteres actualmente disponibles (no bloqueante) o todo hasta eof (modo bloqueante).

El valor de retorno puede ser menor que el valor a leer, indicando que había menos datos de los solicitados disponibles. Esto se llama una lectura corta. En modo bloqueante, esto solo puede ocurrir en un final de archivo. En modo no bloqueante, una lectura corta también puede ocurrir si no hay suficiente entrada actualmente disponible: Tcl_ReadChars devuelve un recuento corto en lugar de esperar más datos.

Si el canal está en modo bloqueante, un valor de retorno de cero indica una condición de fin de archivo. Si el canal está en modo no bloqueante, un valor de retorno de cero indica que no hay entrada actualmente disponible o una condición de fin de archivo. Use Tcl_Eof y Tcl_InputBlocked para saber cuál de estas condiciones ocurrió realmente.

Tcl_ReadChars traduce las diversas representaciones de fin de línea a la representación interna canónica de \n según el modo de reconocimiento de fin de línea actual. El reconocimiento de fin de línea y los diversos modos específicos de la plataforma se describen en la entrada del manual para el comando Tcl fconfigure.

Como optimización de rendimiento, al leer de un canal con la codificación binary, los bytes no se convierten a UTF-8 a medida que se leen. En su lugar, se almacenan en la representación interna de readObjPtr como un valor de arreglo de bytes. La representación de cadena de este valor solo se construirá si es necesaria (por ejemplo, debido a una llamada a Tcl_GetStringFromObj). De esta manera, los datos orientados a bytes se pueden leer de un canal, manipular llamando a Tcl_GetByteArrayFromObj y funciones relacionadas, y luego escribirlos en un canal sin el costo de la conversión a UTF-8 o desde UTF-8.

Tcl_Read es similar a Tcl_ReadChars, excepto que no realiza conversiones de codificación, independientemente de la codificación del canal. Está obsoleto y existe para compatibilidad con versiones anteriores de extensiones Tcl no internacionalizadas. Consume bytes del channel y los almacena en readBuf, realizando traducciones de fin de línea en el camino. El valor de retorno de Tcl_Read es el número de bytes, hasta bytesToRead, escritos en readBuf. El buffer producido por Tcl_Read no está terminado en nulo. Su contenido es válido desde la posición cero hasta, y excluyendo, la posición indicada por el valor de retorno.

Tcl_ReadRaw es lo mismo que Tcl_Read pero no compensa el apilamiento. Mientras que Tcl_Read (y las otras funciones de la API) siempre obtienen sus datos del canal superior en la pila de la que forma parte el canal proporcionado, Tcl_ReadRaw no lo hace. Por lo tanto, esta función solo es usable para controladores de canal transformacionales, es decir, controladores utilizados en el medio de una pila de canales, para mover datos del canal inferior a la transformación.

TCL_GETSOBJ Y TCL_GETS

Tcl_GetsObj consume bytes del channel, convirtiendo los bytes a UTF-8 basándose en la codificación del canal, hasta que se haya visto una línea completa de entrada. Si la codificación del canal es binary, cada byte leído del canal se trata como un carácter Unicode individual. Todos los caracteres de la línea, excepto los caracteres de fin de línea terminantes, se añaden a la representación de cadena de lineObjPtr. Los caracteres de fin de línea se leen y se descartan.

Si se leyó una línea correctamente, el valor de retorno es mayor o igual a cero e indica el número de bytes almacenados en lineObjPtr. Si ocurre un error, Tcl_GetsObj devuelve -1 y registra un código de error POSIX que se puede recuperar con Tcl_GetErrno. Tcl_GetsObj también devuelve -1 si se alcanza el fin del archivo; el procedimiento Tcl_Eof se puede usar para distinguir un error de una condición de fin de archivo.

Si el canal está en modo no bloqueante, el valor de retorno también puede ser -1 si no había datos disponibles o si los datos disponibles no contenían un carácter de fin de línea. Cuando se devuelve -1, el procedimiento Tcl_InputBlocked puede invocarse para determinar si el canal está bloqueado debido a la falta de entrada.

Tcl_Gets es lo mismo que Tcl_GetsObj excepto que los caracteres resultantes se añaden a la cadena dinámica dada por lineRead en lugar de un valor Tcl.

TCL_UNGETS

Tcl_Ungets se utiliza para agregar datos a la cola de entrada de un canal, ya sea en la cabeza o en la cola de la cola. El puntero input apunta a los datos que se van a agregar. La longitud de la entrada a agregar está dada por inputLen. Un valor distinto de cero de addAtEnd indica que los datos se agregarán al final de la cola; de lo contrario, se agregarán al principio de la cola. Si channel tiene un marcador EOF "pegajoso", no se agregarán datos a la cola de entrada. Tcl_Ungets devuelve inputLen o -1 si ocurre un error.

TCL_WRITECHARS, TCL_WRITEOBJ, Y TCL_WRITE

Tcl_WriteChars acepta bytesToWrite bytes de datos de caracteres en charBuf. Los caracteres UTF-8 en el buffer se convierten a la codificación del canal y se ponen en cola para su salida al channel. Si bytesToWrite es negativo, Tcl_WriteChars espera que charBuf esté terminado en nulo y saca todo hasta el nulo.

Los datos puestos en cola para su salida pueden no aparecer en el dispositivo de salida inmediatamente, debido al almacenamiento en búfer interno. Si los datos deben aparecer inmediatamente, llame a Tcl_Flush después de la llamada a Tcl_WriteChars, o configure la opción -buffering en el canal a none. Si desea que los datos aparezcan tan pronto como se acepte una línea completa para su salida, configure la opción -buffering en el canal en modo line.

El valor de retorno de Tcl_WriteChars es un recuento de cuántos bytes se aceptaron para su salida al canal. Esto es mayor que cero para indicar éxito o -1 para indicar que ocurrió un error. Si ocurre un error, Tcl_WriteChars registra un código de error POSIX que puede recuperarse con Tcl_GetErrno.

Los caracteres de nueva línea en los datos de salida se traducen a secuencias de fin de línea específicas de la plataforma según la opción -translation para el canal. Esto se hace incluso si el canal no tiene codificación.

Tcl_WriteObj es similar a Tcl_WriteChars excepto que acepta un valor Tcl cuyos contenidos se enviarán al canal. Los caracteres UTF-8 en la representación de cadena de writeObjPtr se convierten a la codificación del canal y se ponen en cola para su salida al channel. Como optimización de rendimiento, al escribir en un canal con la codificación binary, los caracteres UTF-8 no se convierten al escribirse. En su lugar, los bytes en la representación interna de writeObjPtr como un valor de arreglo de bytes se escriben en el canal. La representación de arreglo de bytes del valor se construirá si es necesaria. De esta manera, los datos orientados a bytes se pueden leer de un canal, manipular llamando a Tcl_GetByteArrayFromObj y funciones relacionadas, y luego escribir en un canal sin el costo de la conversión a UTF-8 o desde UTF-8.

Tcl_Write es similar a Tcl_WriteChars excepto que no realiza conversiones de codificación, independientemente de la codificación del canal. Está obsoleto y existe para compatibilidad con versiones anteriores de extensiones Tcl no internacionalizadas. Acepta bytesToWrite bytes de datos en byteBuf y los pone en cola para su salida al channel. Si bytesToWrite es negativo, Tcl_Write espera que byteBuf esté terminado en nulo y saca todo hasta el nulo.

Tcl_WriteRaw es lo mismo que Tcl_Write pero no compensa el apilamiento. Mientras que Tcl_Write (y las otras funciones de la API) siempre alimentan su entrada al canal superior en la pila de la que forma parte el canal proporcionado, Tcl_WriteRaw no lo hace. Por lo tanto, esta función solo es usable para controladores de canal transformacionales, es decir, controladores utilizados en el medio de una pila de canales, para mover datos de la transformación al canal de abajo.

TCL_FLUSH

Tcl_Flush hace que todos los datos de salida almacenados en búfer para el channel se escriban en su archivo o dispositivo subyacente tan pronto como sea posible. Si el canal está en modo bloqueante, la llamada no retorna hasta que todos los datos en búfer se hayan enviado al canal o haya ocurrido algún error. La llamada retorna inmediatamente si el canal no es bloqueante; inicia un vaciado en segundo plano que escribirá los datos en búfer en el canal eventualmente, tan rápido como el canal pueda absorberlo.

El valor de retorno es normalmente TCL_OK. Si ocurre un error, Tcl_Flush devuelve TCL_ERROR y registra un código de error POSIX que puede recuperarse con Tcl_GetErrno.

TCL_SEEK

Tcl_Seek mueve el punto de acceso en el channel donde se leerán o escribirán datos posteriores. La salida en búfer se vacía al canal y la entrada en búfer se descarta, antes de la operación de búsqueda.

Tcl_Seek normalmente devuelve el nuevo punto de acceso. Si ocurre un error, Tcl_Seek devuelve -1 y registra un código de error POSIX que puede recuperarse con Tcl_GetErrno. Después de un error, el punto de acceso puede haberse movido o no.

TCL_TELL

Tcl_Tell devuelve el punto de acceso actual para un canal. El valor devuelto es -1 si el canal no admite la búsqueda.

TCL_TRUNCATECHANNEL

Tcl_TruncateChannel trunca el archivo subyacente del channel a una length dada de bytes. Devuelve TCL_OK si la operación tuvo éxito y TCL_ERROR en caso contrario.

TCL_GETCHANNELOPTION

Tcl_GetChannelOption recupera, en optionValue, el valor de una de las opciones actualmente en vigor para un canal, o una lista de todas las opciones y sus valores. El argumento channel identifica el canal para el que se va a consultar una opción o recuperar todas las opciones y sus valores. Si optionName no es NULL, es el nombre de la opción a consultar; el valor de la opción se copia a la cadena dinámica Tcl denotada por optionValue. Si optionName es NULL, la función almacena una lista alterna de nombres de opciones y sus valores en optionValue

>, utilizando una serie de llamadas a Tcl_DStringAppendElement. Las diversas opciones preexistentes y sus posibles valores se describen en la entrada del manual del comando fconfigure de Tcl. Otras opciones pueden ser añadidas por cada tipo de canal. Estas opciones específicas del tipo de canal se describen en la entrada del manual del comando Tcl que crea un canal de ese tipo; por ejemplo, las opciones adicionales para canales basados en TCP se describen en la entrada del manual del comando socket de Tcl. El procedimiento normalmente devuelve TCL_OK. Si ocurre un error, devuelve TCL_ERROR y llama a Tcl_SetErrno para almacenar un código de error POSIX apropiado.

TCL_SETCHANNELOPTION

Tcl_SetChannelOption establece un nuevo valor newValue para una opción optionName en channel. El procedimiento normalmente devuelve TCL_OK. Si ocurre un error, devuelve TCL_ERROR; además, si interp no es NULL, Tcl_SetChannelOption deja un mensaje de error en el resultado del intérprete.

TCL_EOF

Tcl_Eof devuelve un valor distinto de cero si el channel encontró un fin de archivo durante la última operación de entrada.

TCL_INPUTBLOCKED

Tcl_InputBlocked devuelve un valor distinto de cero si el channel está en modo no bloqueante y la última operación de entrada devolvió menos datos de los solicitados porque había datos insuficientes disponibles. La llamada siempre devuelve cero si el canal está en modo bloqueante.

TCL_INPUTBUFFERED

Tcl_InputBuffered devuelve el número de bytes de entrada actualmente almacenados en búfer en los búferes internos de un canal. Si el canal no está abierto para lectura, esta función siempre devuelve cero.

TCL_OUTPUTBUFFERED

Tcl_OutputBuffered devuelve el número de bytes de salida actualmente almacenados en búfer en los búferes internos de un canal. Si el canal no está abierto para escritura, esta función siempre devuelve cero.

PLATFORM ISSUES

Los identificadores devueltos por Tcl_GetChannelHandle dependen de la plataforma y del tipo de canal. En plataformas Unix, el identificador es siempre un descriptor de archivo Unix tal como se devuelve de la llamada al sistema open. En plataformas Windows, el identificador es un HANDLE de archivo cuando el canal fue creado con Tcl_OpenFileChannel, Tcl_OpenCommandChannel o Tcl_MakeFileChannel. Otros tipos de canal pueden devolver un tipo diferente de identificador en plataformas Windows.
