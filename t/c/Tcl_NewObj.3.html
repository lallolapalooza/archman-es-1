INTRODUCCION

Esta página del manual presenta una visión general de los valores Tcl (llamados Tcl_Obj por razones históricas) y cómo se utilizan. También describe procedimientos genéricos para gestionar valores Tcl. Estos procedimientos se utilizan para crear y copiar valores, e incrementar y decrementar el recuento de referencias (punteros) a valores. Los procedimientos se utilizan junto con los que operan sobre tipos específicos de valores, como Tcl_GetIntFromObj y Tcl_ListObjAppendElement. Los procedimientos individuales se describen junto con las estructuras de datos que manipulan.

Los valores de doble puerto de Tcl proporcionan un mecanismo de propósito general para almacenar e intercambiar valores Tcl. Reemplazan en gran medida el uso de cadenas en Tcl. Por ejemplo, se utilizan para almacenar valores de variables, argumentos de comandos, resultados de comandos y scripts. Los valores Tcl se comportan como cadenas, pero también mantienen una representación interna que puede manipularse de forma más eficiente. Por ejemplo, una lista Tcl ahora se representa como un valor que contiene la representación de cadena de la lista, así como una matriz de punteros a los valores de cada elemento de la lista. Los valores de doble puerto evitan la mayoría de las conversiones de tipos en tiempo de ejecución. También mejoran la velocidad de muchas operaciones, ya que una representación adecuada está inmediatamente disponible. El propio compilador utiliza valores Tcl para almacenar en caché los códigos de bytes de instrucciones resultantes de la compilación de scripts.

Las dos representaciones son una caché la una de la otra y se calculan perezosamente. Es decir, cada representación solo se calcula cuando es necesario, se calcula a partir de la otra representación y, una vez calculada, se guarda. Además, un cambio en una representación invalida la otra. Como ejemplo, un programa Tcl que realiza cálculos enteros puede operar directamente sobre la representación de enteros de máquina interna de una variable sin tener que convertir constantemente entre enteros y cadenas. Solo cuando necesita una cadena que represente el valor de la variable, digamos para imprimirla, el programa regenerará la representación de cadena a partir del entero. A pesar de que los valores contienen una representación interna, su semántica se define en términos de cadenas: siempre se puede obtener una cadena actualizada, y cualquier cambio en el valor se reflejará en esa cadena cuando se obtenga la representación de cadena del valor. Debido a esta invalidación y regeneración de la representación, es peligroso que los escritores de extensiones accedan directamente a los campos de Tcl_Obj. Es mejor acceder a la información de Tcl_Obj utilizando procedimientos como Tcl_GetStringFromObj y Tcl_GetString.

Los valores se asignan en el montículo y se referencian mediante un puntero a su estructura Tcl_Obj. Los valores se comparten tanto como sea posible. Esto reduce significativamente los requisitos de almacenamiento, ya que algunos valores, como las listas largas, son muy grandes. Además, la mayoría de los valores Tcl solo se leen y nunca se modifican. Esto es especialmente cierto para los argumentos de los procedimientos, que pueden compartirse entre el llamador y el procedimiento llamado. La asignación y la vinculación de argumentos se realizan simplemente asignando un puntero al valor. Se utiliza el recuento de referencias para determinar cuándo es seguro reclamar el almacenamiento de un valor.

Los valores Tcl tienen tipo. La representación interna de un valor está controlada por su tipo. Varios tipos están predefinidos en el núcleo de Tcl, incluyendo entero, doble, lista y códigos de bytes. Los escritores de extensiones pueden ampliar el conjunto de tipos definiendo sus propias estructuras Tcl_ObjType.

LA ESTRUCTURA TCL_OBJ

Cada valor Tcl se representa mediante una estructura Tcl_Obj, que se define de la siguiente manera.

typedef struct Tcl_Obj {
    int refCount;
    char *bytes;
    int length;
    const Tcl_ObjType *typePtr;
    union {
        long longValue;
        double doubleValue;
        void *otherValuePtr;
        Tcl_WideInt wideValue;
        struct {
            void *ptr1;
            void *ptr2;
        } twoPtrValue;
        struct {
            void *ptr;
            unsigned long value;
        } ptrAndLongRep;
    } internalRep;
} Tcl_Obj;

Los miembros bytes y length juntos contienen la representación de cadena UTF-8 de un valor, que es una *cadena contada* que no contiene bytes nulos (los caracteres nulos UTF-8 deben codificarse como una secuencia de dos bytes: 192, 128). bytes apunta al primer byte de la representación de cadena. El miembro length da el número de bytes. El array de bytes siempre debe tener un byte nulo después del último byte de datos, en el desplazamiento length; esto permite que las representaciones de cadena se traten como cadenas C convencionales terminadas en nulo. Los programas C utilizan Tcl_GetStringFromObj y Tcl_GetString para obtener la representación de cadena de un valor. Si bytes es NULL, la representación de cadena no es válida.

El tipo de un valor gestiona su representación interna. El miembro typePtr apunta a la estructura Tcl_ObjType que describe el tipo. Si typePtr es NULL, la representación interna no es válida.

El miembro de la unión internalRep contiene la representación interna de un valor. Puede ser un entero (long), un número de punto flotante de doble precisión, un puntero a un valor que contiene información adicional necesaria por el tipo del valor para representar el valor, un entero Tcl_WideInt, dos punteros arbitrarios o un par formado por un entero unsigned long y un puntero.

El miembro refCount se utiliza para saber cuándo es seguro liberar el almacenamiento de un valor. Contiene el recuento de referencias activas al valor. Mantener el recuento de referencias correcto es una responsabilidad clave de los escritores de extensiones. El recuento de referencias se discute a continuación en la sección GESTION DE ALMACENAMIENTO DE VALORES.

Aunque los escritores de extensiones pueden acceder directamente a los miembros de una estructura Tcl_Obj, es mucho mejor utilizar los procedimientos y macros apropiados. Por ejemplo, los escritores de extensiones nunca deben leer ni actualizar refCount directamente; deben utilizar macros como Tcl_IncrRefCount y Tcl_IsShared en su lugar.

Una propiedad clave de los valores Tcl es que contienen dos representaciones. Un valor normalmente comienza conteniendo solo una representación de cadena: no tiene tipo y tiene un typePtr NULL. Un valor que contiene una cadena vacía o una copia de una cadena especificada se crea utilizando Tcl_NewObj o Tcl_NewStringObj respectivamente. El valor de cadena de un valor se obtiene con Tcl_GetStringFromObj o Tcl_GetString y se cambia con Tcl_SetStringObj. Si posteriormente el valor se pasa a un procedimiento como Tcl_GetIntFromObj que requiere una representación interna específica, el procedimiento creará una y establecerá el typePtr del valor. La representación interna se calcula a partir de la representación de cadena. Las dos representaciones de un valor son duales entre sí: los cambios realizados en una se reflejan en la otra. Por ejemplo, Tcl_ListObjReplace modificará la representación interna de un valor y la siguiente llamada a Tcl_GetStringFromObj o Tcl_GetString reflejará ese cambio.

Las representaciones se recalculan perezosamente por eficiencia. Un cambio en una representación realizado por un procedimiento como Tcl_ListObjReplace no se refleja inmediatamente en la otra representación. En su lugar, la otra representación se marca como no válida para que solo se regenere si es necesaria más adelante. La mayoría de los programadores C nunca tienen que preocuparse por cómo se hace esto y simplemente utilizan procedimientos como Tcl_GetBooleanFromObj o Tcl_ListObjIndex. Los programadores que implementan sus propios tipos de valor deben comprobar las representaciones no válidas y marcarlas como no válidas cuando sea necesario. El procedimiento Tcl_InvalidateStringRep se utiliza para marcar la representación de cadena de un valor como no válida y para liberar cualquier almacenamiento asociado con la representación de cadena antigua.

INTRODUCCIÓN

Tcl utiliza internamente un modelo de datos de objetos para todos sus valores. Las operaciones como la asignación de variables, la manipulación de listas y la ejecución de comandos se realizan sobre estos objetos. La forma en que los valores se representan internamente se puede optimizar para tipos comunes como enteros, cadenas de caracteres, listas, diccionarios, etc. Esto mejora el rendimiento al evitar conversiones repetidas y al permitir que las operaciones se realicen en el formato de datos más eficiente. Por ejemplo, cuando un comando necesita realizar una operación matemática en una variable, intentará obtener una representación entera del valor en lugar de tratarlo siempre como una cadena de caracteres.

Los objetos Tcl (estructuras Tcl_Obj) son el bloque de construcción fundamental para los valores en Tcl. Cada objeto contiene información sobre su tipo y una o más representaciones internas de su valor. Tcl admite la conversión automática de tipos, de modo que un objeto puede tener varias representaciones internas (por ejemplo, una cadena y un entero) y Tcl elegirá la más apropiada para una operación determinada.

LA ESTRUCTURA TCL_OBJ

Cada valor Tcl se representa mediante una estructura Tcl_Obj. Esta estructura contiene un puntero a una estructura Tcl_ObjType que define el tipo del objeto (por ejemplo, entero, cadena, lista) y punteros a las representaciones internas del valor. La estructura Tcl_Obj incluye los siguientes campos clave:

refCount
Un contador de referencias que se utiliza para gestionar la vida útil del objeto. Cuando el contador llega a cero, el objeto se libera.
typePtr
Un puntero a la estructura Tcl_ObjType que describe el tipo del objeto. Si es NULL, el objeto se considera una cadena de caracteres genérica.
internal.bytes
Un puntero a la representación de cadena de caracteres del objeto. Este campo solo es válido si typePtr es NULL o si el tipo específico indica que la representación de cadena es válida.
internal.longValue
Almacena la representación entera del objeto si el tipo es entero.
...
Otros campos para diferentes representaciones internas (por ejemplo, listas, diccionarios).

Las funciones que comienzan con Tcl_Db... son versiones de depuración que realizan comprobaciones adicionales y registran información sobre el uso de objetos, útil para detectar fugas de memoria o corrupción de memoria.

La creación de objetos se realiza principalmente mediante funciones como Tcl_NewObj (crea un objeto vacío), Tcl_NewStringObj (crea un objeto a partir de una cadena), Tcl_NewIntObj (crea un objeto entero), Tcl_NewListObj, etc.

Los objetos se comparten siempre que sea posible. Por ejemplo, cuando se pasa un valor como argumento a un comando, el intérprete no copia el objeto, sino que incrementa su contador de referencias (Tcl_IncrRefCount). Cuando el objeto ya no es necesario, se decrementa su contador (Tcl_DecrRefCount). Si el contador llega a cero, el objeto se libera.

Si un comando necesita modificar un objeto que está siendo compartido (detectado por Tcl_IsShared), debe crear una copia del objeto antes de modificarlo, usando Tcl_DuplicateObj. Esto asegura que las modificaciones no afecten a otras partes del intérprete que puedan estar utilizando el mismo objeto original.

La invalidación de la representación en cadena se realiza con Tcl_InvalidateStringRep. Esto indica que la representación de cadena actual ya no es válida porque el valor interno ha cambiado. La representación se volverá a generar la próxima vez que se necesite.

Los programadores de extensiones pueden definir nuevos tipos de objetos utilizando Tcl_RegisterObjType. Esto permite extender Tcl con tipos de datos personalizados y sus operaciones asociadas.

Para acceder a los elementos de una lista almacenada en un objeto, se puede usar Tcl_ListObjIndex para extraer un elemento de la lista. El mismo valor que contiene el mismo valor de cadena puede tener varias representaciones internas diferentes en diferentes momentos. Los escritores de extensiones también pueden forzar que un valor se convierta de un tipo a otro utilizando el procedimiento Tcl_ConvertToType. Solo los programadores que crean nuevos tipos de valores necesitan preocuparse por cómo se hace esto. Un procedimiento definido como parte de la implementación del tipo de valor crea una nueva representación interna para un valor y cambia su typePtr. Consulte la página man de Tcl_RegisterObjType para ver cómo crear un nuevo tipo de valor.

EJEMPLO DE LA VIDA DE UN VALOR

Como ejemplo de la vida de un valor, considere la siguiente secuencia de comandos:

set x 123

Esto asigna a x un valor sin tipo cuyo miembro bytes apunta a 123 y su miembro length contiene 3. El miembro typePtr del valor es NULL.

puts "x is $x"

La representación en cadena de x es válida (ya que bytes no es NULL) y se recupera para el comando.

incr x

El comando incr primero obtiene un entero del valor de x llamando a Tcl_GetIntFromObj. Este procedimiento verifica si el valor ya es un valor entero. Como no lo es, convierte el valor estableciendo la representación interna del valor al entero 123 y estableciendo el typePtr del valor para que apunte a la estructura de tipo entero Tcl_ObjType. Ambas representaciones son ahora válidas. incr incrementa la representación entera del valor y luego invalida su representación en cadena (llamando a Tcl_InvalidateStringRep) ya que la representación en cadena ya no corresponde a la representación interna.

puts "x is now $x"

Se necesita la representación en cadena del valor de x y se vuelve a calcular. La representación en cadena es ahora 124 y ambas representaciones son nuevamente válidas.

GESTIÓN DE ALMACENAMIENTO DE VALORES

Los valores Tcl se asignan en el heap y se comparten tanto como sea posible para reducir los requisitos de almacenamiento. Se utiliza el recuento de referencias para determinar cuándo un valor ya no es necesario y puede liberarse de forma segura. Un valor recién creado por Tcl_NewObj o Tcl_NewStringObj tiene refCount 0. La macro Tcl_IncrRefCount incrementa el contador de referencias cuando se crea una nueva referencia al valor. La macro Tcl_DecrRefCount decrementa el contador cuando una referencia ya no es necesaria y, si el contador de referencias del valor cae a cero, libera su almacenamiento. Un valor compartido por diferentes códigos o estructuras de datos tiene refCount mayor que 1. Incrementar el contador de referencias de un valor asegura que no se liberará demasiado pronto o que su valor cambiará accidentalmente.

Como ejemplo, el intérprete de bytecode comparte valores de argumento entre procedimientos Tcl que llaman y que son llamados para evitar tener que copiar valores. Asigna los valores de argumento de la llamada a las variables de parámetros formales del procedimiento. Al hacerlo, llama a Tcl_IncrRefCount para incrementar el contador de referencias de cada argumento, ya que ahora hay una nueva referencia a él desde el parámetro formal. Cuando el procedimiento llamado regresa, el intérprete llama a Tcl_DecrRefCount para decrementar el contador de referencias de cada argumento. Cuando el contador de referencias de un valor cae a menos o igual a cero, Tcl_DecrRefCount recupera su almacenamiento. La mayoría de los procedimientos de comando no tienen que preocuparse por el recuento de referencias, ya que utilizan el valor de un valor inmediatamente y no conservan un puntero al valor después de que regresan. Sin embargo, si conservan un puntero a un valor en una estructura de datos, deben tener cuidado de incrementar su contador de referencias, ya que el puntero conservado es una nueva referencia.

Los procedimientos de comando que modifican directamente los valores, como los de lappend y linsert, deben tener cuidado de copiar un valor compartido antes de cambiarlo. Primero deben verificar si el valor está compartido llamando a Tcl_IsShared. Si el valor está compartido, deben copiar el valor usando Tcl_DuplicateObj; esto devuelve un nuevo duplicado del valor original que tiene refCount 0. Si el valor no está compartido, el procedimiento de comando "posee" el valor y puede modificarlo directamente de forma segura. Por ejemplo, el siguiente código aparece en el procedimiento de comando que implementa linsert. Este procedimiento modifica el valor de la lista que se le pasa en objv[1] insertando objc-3 nuevos elementos antes de index.

listPtr = objv[1];
if (Tcl_IsShared(listPtr)) {
    listPtr = Tcl_DuplicateObj(listPtr);
}
result = Tcl_ListObjReplace(interp, listPtr, index, 0,
        (objc-3), &(objv[3]));

Como otro ejemplo, el procedimiento de comando de incr debe verificar si el valor de la variable está compartido antes de incrementar el entero en su representación interna. Si está compartido, necesita duplicar el valor para evitar cambiar accidentalmente los valores en otras estructuras de datos.
