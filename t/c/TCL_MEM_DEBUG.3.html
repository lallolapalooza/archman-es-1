TCL_MEM_DEBUG(3) Procedimientos de biblioteca de Tcl TCL_MEM_DEBUG(3)

NOMBRE

TCL_MEM_DEBUG - Bandera de compilación para habilitar la depuración de memoria de Tcl

DESCRIPCIÓN

Cuando Tcl se compila con TCL_MEM_DEBUG definido, se incluye un potente conjunto de herramientas de depuración de memoria en el binario compilado. Esto incluye funciones de C y Tcl que pueden ayudar a depurar fugas de memoria, desbordamientos de asignación de memoria y otros errores relacionados con la memoria.

HABILITACIÓN DE LA DEPURACIÓN DE MEMORIA

Para habilitar la depuración de memoria, Tcl debe recompilarse desde cero con TCL_MEM_DEBUG definido (por ejemplo, pasando la opción --enable-symbols=mem al script configure al compilar). Esto también compilará una versión no stub de Tcl_InitMemory para agregar el comando memory a Tcl.

TCL_MEM_DEBUG debe dejarse definido para todos los módulos o indefinido para todos los módulos que se van a enlazar juntos. Si no es así, se producirán errores de enlace, con Tcl_DbCkfree y Tcl_DbCkalloc o Tcl_Alloc y Tcl_Free indefinidos.

Una vez que la compatibilidad con la depuración de memoria se haya compilado en Tcl, las funciones de C Tcl_ValidateAllMemory y Tcl_DumpActiveMemory, y el comando Tcl memory se pueden usar para validar y examinar el uso de memoria.

ZONAS DE GUARDA

Cuando la depuración de memoria está habilitada, cada vez que se realiza una llamada a ckalloc, se asigna un poco más de memoria de la solicitada para que el código de depuración de memoria pueda rastrear la memoria asignada, y se colocan "zonas de guarda" de ocho bytes delante y detrás del espacio que se devolverá al llamador. (Los tamaños de las zonas de guarda se definen por las definiciones de C #define LOW_GUARD_SIZE y #define HIGH_GUARD_SIZE en el archivo generic/tclCkalloc.c — se puede extender si sospecha problemas de sobrescritura grandes, a costa de un rendimiento reducido.) Se escribe un patrón conocido en las zonas de guarda y, en una llamada a ckfree, se verifican las zonas de guarda del espacio que se está liberando para ver si alguna de las zonas ha sido modificada de alguna manera. Si alguna lo ha sido, se identifican los bytes de guarda y su nuevo contenido, y se emite un mensaje de "zona de guarda baja fallida" o "zona de guarda alta fallida". El mensaje de "zona de guarda fallida" incluye la dirección del paquete de memoria y el nombre del archivo y el número de línea del código que llamó a ckfree. Esto le permite detectar los tipos comunes de problemas de un solo error, donde no se asignó suficiente espacio para contener los datos escritos, por ejemplo.

DEPURACIÓN DE PROBLEMAS DIFÍCILES DE CORRUPCIÓN DE MEMORIA

Normalmente, Tcl compilado con depuración de memoria habilitada facilitará el aislamiento de un problema de corrupción. Habilitar la validación de memoria con el comando memory puede ayudar a aislar problemas difíciles. Si sospecha (o sabe) que la corrupción ocurre antes de que el intérprete de Tcl se inicialice lo suficiente como para que pueda emitir comandos, puede establecer la definición MEM_VALIDATE, recompilar tclCkalloc.c y reconstruir Tcl. Esto habilitará la validación de memoria desde la primera llamada a ckalloc, nuevamente, con un gran impacto en el rendimiento.

Si está desesperado y la validación de memoria en cada llamada a ckalloc y ckfree no es suficiente, puede llamar explícitamente Tcl_ValidateAllMemory directamente en cualquier momento. Toma un char * y un int que normalmente son el nombre del archivo y el número de línea del llamador, pero en realidad pueden ser cualquier cosa que desee. Recuerde eliminar las llamadas una vez que encuentre el problema.

VER TAMBIÉN

ckalloc, memory, Tcl_ValidateAllMemory, Tcl_DumpActiveMemory
