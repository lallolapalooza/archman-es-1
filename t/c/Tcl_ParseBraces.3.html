NOMBRE

Tcl_ParseCommand, Tcl_ParseExpr, Tcl_ParseBraces, Tcl_ParseQuotedString, Tcl_ParseVarName, Tcl_ParseVar, Tcl_FreeParse, Tcl_EvalTokens, Tcl_EvalTokensStandard - analizar scripts y expresiones Tcl

SINOPSIS

#include <tcl.h>

int
Tcl_ParseCommand(interp, start, numBytes, nested, parsePtr)

int
Tcl_ParseExpr(interp, start, numBytes, parsePtr)

int
Tcl_ParseBraces(interp, start, numBytes, parsePtr, append, termPtr)

int
Tcl_ParseQuotedString(interp, start, numBytes, parsePtr, append, termPtr)

int
Tcl_ParseVarName(interp, start, numBytes, parsePtr, append)

const char *
Tcl_ParseVar(interp, start, termPtr)

Tcl_FreeParse(usedParsePtr)

Tcl_Obj *
Tcl_EvalTokens(interp, tokenPtr, numTokens)

int
Tcl_EvalTokensStandard(interp, tokenPtr, numTokens)

ARGUMENTOS

Tcl_Interp *interp (salida)
Para procedimientos distintos de Tcl_FreeParse, Tcl_EvalTokens y Tcl_EvalTokensStandard, se usa solo para reportar errores; si es NULL, entonces no se dejan mensajes de error después de los errores. Para Tcl_EvalTokens y Tcl_EvalTokensStandard, determina el contexto para evaluar el script y también se usa para reportar errores; no debe ser NULL.
const char *start (entrada)
Puntero al primer carácter de la cadena a analizar.
int numBytes (entrada)
Número de bytes en la cadena a analizar, sin incluir ningún carácter nulo terminador. Si es menor que 0, entonces el script consiste en todos los caracteres siguientes a start hasta el primer carácter nulo.
int nested (entrada)
Distinto de cero significa que el script es parte de una sustitución de comando, por lo que un corchete de cierre sin comillas debe tratarse como un terminador de comando. Si es cero, los corchetes de cierre no tienen significado especial.
int append (entrada)
Distinto de cero significa que *parsePtr ya contiene tokens válidos; los nuevos tokens deben agregarse a los ya presentes. Cero significa que *parsePtr no está inicializado; cualquier información en él se ignora. Este argumento normalmente es 0.
Tcl_Parse *parsePtr (salida)
Punta a la estructura para completar con información sobre el comando analizado, la expresión, el nombre de la variable, etc. Cualquier información previa en esta estructura se ignora, a menos que append sea distinto de cero en una llamada a Tcl_ParseBraces, Tcl_ParseQuotedString o Tcl_ParseVarName.
const char **termPtr (salida)
Si no es NULL, apunta a una ubicación donde Tcl_ParseBraces, Tcl_ParseQuotedString y Tcl_ParseVar almacenarán un puntero al carácter justo después del carácter terminador (el corchete de cierre, el último carácter del nombre de la variable o la comilla de cierre, respectivamente) si el análisis fue exitoso.
Tcl_Parse *usedParsePtr (entrada)
Punta a la estructura que fue completada por una llamada previa a Tcl_ParseCommand, Tcl_ParseExpr, Tcl_ParseVarName, etc.

DESCRIPCIÓN

Estos procedimientos analizan comandos Tcl o porciones de comandos Tcl como expresiones o referencias a variables. Cada procedimiento toma un puntero a un script (o una porción del mismo) y completa la estructura apuntada por parsePtr con una colección de tokens que describen la información que fue analizada. Los procedimientos normalmente devuelven TCL_OK. Sin embargo, si ocurre un error, devuelven TCL_ERROR, dejan un mensaje de error en el resultado de interp (si interp no es NULL), y no dejan nada en parsePtr.

Tcl_ParseCommand es un procedimiento que analiza scripts Tcl. Dado un puntero a un script, analiza el primer comando del script. Si el comando fue analizado exitosamente, Tcl_ParseCommand devuelve TCL_OK y completa la estructura apuntada por parsePtr con información sobre la estructura del comando (ver abajo para detalles). Si ocurrió un error al analizar el comando, se devuelve TCL_ERROR, se deja un mensaje de error en el resultado de interp y no se deja información en *parsePtr.

Tcl_ParseExpr analiza expresiones Tcl. Dado un puntero a un script que contiene una expresión, Tcl_ParseExpr analiza la expresión. Si la expresión fue analizada exitosamente, Tcl_ParseExpr devuelve TCL_OK y completa la estructura apuntada por parsePtr con información sobre la estructura de la expresión (ver abajo para detalles). Si ocurrió un error al analizar el comando, se devuelve TCL_ERROR, se deja un mensaje de error en el resultado de interp y no se deja información en *parsePtr.

Tcl_ParseBraces analiza una cadena o argumento de comando entre corchetes como {hola} o {cadena \t con \t tabulaciones} desde el principio de su argumento start. El primer carácter de start debe ser {. Si la cadena entre corchetes fue analizada exitosamente, Tcl_ParseBraces devuelve TCL_OK, completa la estructura apuntada por parsePtr con información sobre la estructura de la cadena (ver abajo para detalles) y almacena un puntero al carácter justo después del } terminador en la ubicación dada por *termPtr. Si ocurre un error al analizar la cadena, se devuelve TCL_ERROR, se deja un mensaje de error en el resultado de interp y no se deja información en *parsePtr ni en *termPtr.

Tcl_ParseQuotedString analiza una cadena entre comillas dobles como "la suma es [expr {$a+$b}]" desde el principio del argumento start. El primer carácter de start debe ser ". Si la cadena entre comillas dobles fue analizada exitosamente, Tcl_ParseQuotedString devuelve TCL_OK, completa la estructura apuntada por parsePtr con información sobre la estructura de la cadena (ver abajo para detalles) y almacena un puntero al carácter justo después del " terminador en la ubicación dada por *termPtr. Si ocurre un error al analizar la cadena, se devuelve TCL_ERROR, se deja un mensaje de error en el resultado de interp y no se deja información en *parsePtr ni en *termPtr.

Tcl_ParseVarName analiza una referencia de variable Tcl como $abc o $x([expr {$index + 1}]) desde el principio de su argumento start. El primer carácter de start debe ser $. Si un nombre de variable fue analizado exitosamente, Tcl_ParseVarName devuelve TCL_OK y completa la estructura apuntada por parsePtr con información sobre la estructura del nombre de la variable (ver abajo para detalles). Si ocurre un error al analizar el comando, se devuelve TCL_ERROR, se deja un mensaje de error en el resultado de interp (si interp no es NULL) y no se deja información en *parsePtr.

Tcl_ParseVar analiza una referencia de variable Tcl como $abc o $x([expr {$index + 1}]) desde el principio de su argumento start. El primer carácter de start debe ser $. Si el nombre de la variable se analiza exitosamente, Tcl_ParseVar devuelve un puntero al valor de cadena de la variable. Si ocurre un error al analizar, entonces se devuelve NULL y se deja un mensaje de error en el resultado de interp.

La información dejada en *parsePtr por Tcl_ParseCommand, Tcl_ParseExpr, Tcl_ParseBraces, Tcl_ParseQuotedString y Tcl_ParseVarName puede incluir memoria asignada dinámicamente. Si estos cinco procedimientos de análisis devuelven TCL_OK, el llamador debe invocar Tcl_FreeParse para liberar el almacenamiento en *parsePtr. Estos procedimientos ignoran cualquier información existente en *parsePtr (a menos que append sea distinto de cero), por lo que si se realizan llamadas repetidas a cualquiera de ellos, se debe invocar Tcl_FreeParse una vez después de cada llamada.

Tcl_EvalTokensStandard evalúa una secuencia de tokens de análisis de una estructura Tcl_Parse. Los tokens típicamente consisten en todos los tokens de una palabra o todos los tokens que componen el índice para una referencia a una variable de matriz. Tcl_EvalTokensStandard realiza las sustituciones solicitadas por los tokens y concatena los valores resultantes. El valor de retorno de Tcl_EvalTokensStandard es un código de finalización Tcl con uno de los valores TCL_OK, TCL_ERROR, TCL_RETURN, TCL_BREAK o TCL_CONTINUE, o posiblemente algún otro valor entero originado en una extensión. Además, se deja un valor de resultado o mensaje de error en el resultado de interp; se puede recuperar usando Tcl_GetObjResult.

ESTRUCTURA TCL_PARSE

Tcl_ParseCommand, Tcl_ParseExpr, Tcl_ParseBraces, Tcl_ParseQuotedString y Tcl_ParseVarName devuelven información de análisis en dos estructuras de datos, Tcl_Parse y Tcl_Token:

typedef struct Tcl_Parse {
    const char *commentStart;
    int commentSize;
    const char *commandStart;
    int commandSize;
    int numWords;
    Tcl_Token *tokenPtr;
    int numTokens;
    ...
} Tcl_Parse;
typedef struct Tcl_Token {
    int type;
    const char *start;
    int size;
    int numComponents;
} Tcl_Token;

Los primeros cinco campos de una estructura Tcl_Parse solo son completados por Tcl_ParseCommand. Estos campos no son utilizados por los otros procedimientos de análisis.

Tcl_ParseCommand rellena una estructura Tcl_Parse con información que describe un comando Tcl y cualquier comentario que preceda al comando. Si hay comentarios, el campo commentStart apunta al carácter # que inicia el primer comentario y commentSize indica el número de bytes en todos los comentarios que preceden al comando, incluyendo el carácter de nueva línea que termina el último comentario. Si el comando no va precedido de comentarios, commentSize es 0. Tcl_ParseCommand también establece el campo commandStart para que apunte al primer carácter de la primera palabra del comando (saltándose comentarios y espacios iniciales) y commandSize da el número total de bytes en el comando, incluyendo el carácter al que apunta commandStart hasta e incluyendo el carácter de nueva línea, corchete de cierre o punto y coma que termina el comando. El campo numWords da el número total de palabras en el comando.

Todos los procedimientos de análisis establecen los campos restantes, tokenPtr y numTokens. El campo tokenPtr apunta al primero de una matriz de estructuras Tcl_Token que describen los componentes de la entidad que se está analizando. El campo numTokens da el número total de tokens presentes en la matriz. Cada token contiene cuatro campos. El campo type selecciona uno de varios tipos de tokens que se describen a continuación. El campo start apunta al primer carácter del token y el campo size da el número total de caracteres en el token. Algunos tipos de token, como TCL_TOKEN_WORD y TCL_TOKEN_VARIABLE, consisten en varios tokens componentes, que siguen inmediatamente al token padre; el campo numComponents describe cuántos de estos hay. El campo type tiene uno de los siguientes valores:

TCL_TOKEN_WORD
Este token normalmente describe una palabra de un comando, pero también puede describir una cadena entre comillas o llaves en una expresión. El token describe un componente del script que es el resultado de concatenar una secuencia de subcomponentes, cada uno descrito por un subtoken separado. El token comienza con el primer carácter no en blanco del componente (que puede ser una comilla doble o una llave de apertura) y incluye todos los caracteres del componente hasta, pero sin incluir, el espacio, punto y coma, corchete de cierre, comilla de cierre o llave de cierre que termina el componente. El campo numComponents cuenta el número total de subtokens que componen la palabra, incluidos los subtokens de tokens TCL_TOKEN_VARIABLE y TCL_TOKEN_BS.
TCL_TOKEN_SIMPLE_WORD
Este token tiene el mismo significado que TCL_TOKEN_WORD, excepto que se garantiza que la palabra consiste en un único subtoken TCL_TOKEN_TEXT. El campo numComponents es siempre 1.
TCL_TOKEN_EXPAND_WORD
Este token tiene el mismo significado que TCL_TOKEN_WORD, excepto que el analizador de comandos nota que esta palabra comenzó con el prefijo de expansión {*}, indicando que después de la sustitución, el valor de lista de esta palabra debe ser expandido para formar múltiples argumentos en la evaluación del comando. Este tipo de token solo puede ser creado por Tcl_ParseCommand.
TCL_TOKEN_TEXT
El token describe un rango de texto literal que forma parte de una palabra. El campo numComponents es siempre 0.
TCL_TOKEN_BS
El token describe una secuencia de barra invertida como \n o \0xA3. El campo numComponents es siempre 0.
TCL_TOKEN_COMMAND
El token describe un comando cuyo resultado debe sustituirse en la palabra. El token incluye los corchetes que rodean al comando. El campo numComponents es siempre 0 (el comando anidado no se analiza; llame a Tcl_ParseCommand recursivamente si desea ver sus tokens).
TCL_TOKEN_VARIABLE
El token describe una sustitución de variable, incluyendo el $, el nombre de la variable y el índice de matriz (si lo hay) hasta el corchete de cierre que termina el índice. Este token va seguido de uno o más tokens adicionales que describen el nombre de la variable y el índice de matriz. Si numComponents es 1, entonces la variable es escalar y el siguiente token es un token TCL_TOKEN_TEXT que proporciona el nombre de la variable. Si numComponents es mayor que 1, entonces la variable es una matriz: el primer subtoken es un token TCL_TOKEN_TEXT que proporciona el nombre de la matriz y los subtokens restantes son tokens TCL_TOKEN_TEXT, TCL_TOKEN_BS, TCL_TOKEN_COMMAND y TCL_TOKEN_VARIABLE que deben concatenarse para producir el índice de la matriz. El campo numComponents incluye subtokens anidados que forman parte de tokens TCL_TOKEN_VARIABLE en el índice de la matriz.
TCL_TOKEN_SUB_EXPR
El token describe una subexpresión de una expresión (o una expresión completa). Una subexpresión puede consistir en un valor como un literal entero, sustitución de variable o subexpresión entre paréntesis; también puede consistir en un operador y sus operandos. El token comienza con el primer carácter no en blanco de la subexpresión hasta, pero sin incluir, el espacio, llave, paréntesis de cierre o corchete que termina la subexpresión. Este token va seguido de uno o más tokens adicionales que describen la subexpresión. Si el primer subtoken después del token TCL_TOKEN_SUB_EXPR es un token TCL_TOKEN_OPERATOR, la subexpresión consta de un operador y sus operandos de token. Si el operador no tiene operandos, la subexpresión consta solo del token TCL_TOKEN_OPERATOR. Cada operando se describe mediante un token TCL_TOKEN_SUB_EXPR. De lo contrario, la subexpresión es un valor descrito por uno de los tipos de token TCL_TOKEN_WORD, TCL_TOKEN_TEXT, TCL_TOKEN_BS, TCL_TOKEN_COMMAND, TCL_TOKEN_VARIABLE y TCL_TOKEN_SUB_EXPR. El campo numComponents cuenta el número total de subtokens que componen la subexpresión; esto incluye los subtokens para cualquier token anidado TCL_TOKEN_SUB_EXPR.
TCL_TOKEN_OPERATOR
El token describe un operador de una expresión como && o hypot. Un token TCL_TOKEN_OPERATOR siempre va precedido por un token TCL_TOKEN_SUB_EXPR que describe el operador y sus operandos; el campo numComponents del token TCL_TOKEN_SUB_EXPR se puede usar para determinar el número de operandos. Un operador binario como * va seguido de dos tokens TCL_TOKEN_SUB_EXPR que describen sus operandos. Un operador unario como - va seguido de un solo token TCL_TOKEN_SUB_EXPR para su operando. Si el operador es una función matemática como log10, el token TCL_TOKEN_OPERATOR dará su nombre y los siguientes tokens TCL_TOKEN_SUB_EXPR describirán sus operandos; si no hay operandos (como con rand), no seguirán tokens TCL_TOKEN_SUB_EXPR. Existe un operador ternario, ?, que aparece en subexpresiones de if-then-else como x?y:z; en este caso, el token ? TCL_TOKEN_OPERATOR va seguido de tres tokens TCL_TOKEN_SUB_EXPR para los operandos x, y y z. El campo numComponents para un token TCL_TOKEN_OPERATOR es siempre 0.

Después de que Tcl_ParseCommand devuelve, el primer token al que apunta el campo tokenPtr de la estructura Tcl_Parse siempre tiene el tipo TCL_TOKEN_WORD, TCL_TOKEN_SIMPLE_WORD o TCL_TOKEN_EXPAND_WORD. Le siguen los subtokens que deben concatenarse para producir el valor de esa palabra. El siguiente token es el token TCL_TOKEN_WORD, TCL_TOKEN_SIMPLE_WORD o TCL_TOKEN_EXPAND_WORD para la segunda palabra, seguido de los subtokens para esa palabra, y así sucesivamente hasta que se hayan tenido en cuenta todas las numWords.

Después de que Tcl_ParseExpr devuelve, el primer token al que apunta el campo tokenPtr de la estructura Tcl_Parse siempre tiene el tipo TCL_TOKEN_SUB_EXPR. Le siguen los subtokens que deben evaluarse para producir el valor de la expresión. Solo se modifica la información del token en la estructura Tcl_Parse: los campos commentStart, commentSize, commandStart y commandSize no son modificados por Tcl_ParseExpr.

Después de que Tcl_ParseBraces devuelve, la matriz de tokens a la que apunta el campo tokenPtr de la estructura Tcl_Parse contendrá un único token TCL_TOKEN_TEXT si la cadena entre llaves no contiene ninguna barra invertida seguida de nueva línea. Si la cadena contiene barras invertidas seguidas de nueva línea, la matriz de tokens contendrá uno o más subtokens TCL_TOKEN_TEXT o TCL_TOKEN_BS que deben concatenarse para producir el valor de la cadena. Si la cadena entre llaves era simplemente {} (es decir, la cadena estaba vacía), el único token TCL_TOKEN_TEXT tendrá un campo size que contiene cero; esto asegura que aparezca al menos un token para describir la cadena entre llaves. Solo se modifica la información del token en la estructura Tcl_Parse: los campos commentStart,

TCL_PARSE STRUCTURE

The fields commentStart, commentSize, commandStart, and commandSize are not modified by Tcl_ParseBraces.

After Tcl_ParseQuotedString returns, the array of tokens pointed to by the tokenPtr field of the Tcl_Parse structure depends on the contents of the quoted string. It will consist of one or more TCL_TOKEN_TEXT, TCL_TOKEN_BS, TCL_TOKEN_COMMAND, and TCL_TOKEN_VARIABLE sub-tokens. The array always contains at least one token; for example, if the argument start is empty, the array returned consists of a single TCL_TOKEN_TEXT token with a zero size field. Only the token information in the Tcl_Parse structure is modified: the commentStart, commentSize, commandStart, and commandSize fields are not modified.

After Tcl_ParseVarName returns, the first token pointed to by the tokenPtr field of the Tcl_Parse structure always has type TCL_TOKEN_VARIABLE. It is followed by the sub-tokens that make up the variable name as described above. The total length of the variable name is contained in the size field of the first token. As in Tcl_ParseExpr, only the token information in the Tcl_Parse structure is modified by Tcl_ParseVarName: the commentStart, commentSize, commandStart, and commandSize fields are not modified.

All of the character pointers in the Tcl_Parse and Tcl_Token structures refer to characters in the start argument passed to Tcl_ParseCommand, Tcl_ParseExpr, Tcl_ParseBraces, Tcl_ParseQuotedString, and Tcl_ParseVarName.

There are additional fields in the Tcl_Parse structure after the numTokens field, but these are for the private use of Tcl_ParseCommand, Tcl_ParseExpr, Tcl_ParseBraces, Tcl_ParseQuotedString, and Tcl_ParseVarName; they should not be referenced by code outside of these procedures.
