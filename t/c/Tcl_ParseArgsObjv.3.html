Tcl_ParseArgsObjv(3) Procedimientos de la Biblioteca Tcl Tcl_ParseArgsObjv(3)

NOMBRE

Tcl_ParseArgsObjv - analizar argumentos según una descripción tabular

SINOPSIS

#include <tcl.h>

int
Tcl_ParseArgsObjv(interp, argTable, objcPtr, objv, remObjv)

ARGUMENTOS

Tcl_Interp *interp (salida)
Dónde almacenar los mensajes de error.
const Tcl_ArgvInfo *argTable (entrada)
Puntero a un array de descriptores de opciones.
int *objcPtr (entrada/salida)
Un puntero a una variable que contiene el número de argumentos en objv. Se modificará para contener el número de argumentos restantes en la lista de argumentos no procesados almacenada en remObjv.
Tcl_Obj *const *objv (entrada)
El array de argumentos a analizar.
Tcl_Obj ***remObjv (salida)
Puntero a una variable que contendrá el array de argumentos no procesados. Debe ser NULL si no se requiere la devolución de argumentos no procesados. Si objcPtr se actualiza a un valor distinto de cero, el array devuelto a través de este debe ser liberado usando ckfree.

DESCRIPCION

La función Tcl_ParseArgsObjv proporciona un sistema para analizar listas de argumentos de la forma “-nombreAlguna valorAlguna ...”. Dichas listas de argumentos se encuentran comúnmente tanto en los argumentos de un programa como en los argumentos de un comando Tcl individual. Este analizador asume que el orden de los argumentos no importa, excepto en la medida en que las copias posteriores de una opción duplicada anulan las anteriores.

El array de argumentos se describe mediante los parámetros objcPtr y objv, y se devuelve un array de argumentos no procesados a través de los parámetros objcPtr y remObjv; si no se desea la devolución de argumentos no procesados, el parámetro remObjv debe ser NULL. Si ocurre algún problema, incluyendo si se selecciona la opción de “generar ayuda”, se deja un mensaje de error en el resultado del intérprete y se devuelve TCL_ERROR. De lo contrario, el resultado del intérprete se deja sin cambios y se devuelve TCL_OK.

La colección de argumentos a analizar se describe mediante el parámetro argTable. Este apunta a una tabla de estructuras descriptores que termina con una entrada cuyo campo type está establecido en TCL_ARGV_END. Como conveniencia, se proporcionan las siguientes entradas prototípicas:

TCL_ARGV_AUTO_HELP
Permite al procesador de argumentos proporcionar ayuda cuando se le pasa el argumento “-ayuda”.
TCL_ARGV_AUTO_REST
Instruye al procesador de argumentos que los argumentos posteriores a “--” no deben ser procesados.
TCL_ARGV_TABLE_END
Marca el final de la tabla de descriptores de argumentos.

ENTRADAS DESCRIPTORA DE ARGUMENTOS

Cada entrada de la tabla de descriptores de argumentos debe ser una estructura del tipo Tcl_ArgvInfo. La estructura se define así:

typedef struct {
    int type;
    const char *keyStr;
    void *srcPtr;
    void *dstPtr;
    const char *helpStr;
    ClientData clientData;
} Tcl_ArgvInfo;

El campo keyStr contiene el nombre de la opción; por convención, normalmente comenzará con un carácter “-”. Los campos type, srcPtr, dstPtr y clientData describen la interpretación del valor del argumento, como se describe a continuación. El campo helpStr proporciona un texto que se utiliza para ofrecer ayuda a los usuarios cuando la solicitan.

Como se mencionó anteriormente, el campo type se utiliza para describir la interpretación del valor del argumento. Los siguientes valores son aceptables para type:

TCL_ARGV_CONSTANT
El argumento no toma ningún valor posterior. Si este argumento está presente, el valor (entero) del campo srcPtr se copia a la variable apuntada por el campo dstPtr. El campo clientData se ignora.
TCL_ARGV_END
Este valor marca el final de todos los descriptores de opciones en la tabla. Todos los demás campos se ignoran.
TCL_ARGV_FLOAT
Este argumento toma un valor flotante posterior. El valor (una vez analizado por Tcl_GetDoubleFromObj) se almacenará como un valor de doble precisión en la variable apuntada por el campo dstPtr. Los campos srcPtr y clientData se ignoran.
TCL_ARGV_FUNC
Este argumento toma opcionalmente un valor posterior; depende de la función de devolución de llamada del manejador pasada en srcPtr decidir. Esa función tendrá la siguiente firma:
typedef int (Tcl_ArgvFuncProc)(
        ClientData clientData,
        Tcl_Obj *objPtr,
        void *dstPtr);

El resultado es un valor booleano que indica si consumir el argumento siguiente. El clientData es el valor de la entrada de la tabla, el objPtr es el valor que representa el argumento siguiente o NULL si no hay argumentos siguientes, y el argumento dstPtr a Tcl_ArgvFuncProc es la ubicación donde escribir el valor analizado.

TCL_ARGV_GENFUNC
Este argumento toma cero o más argumentos posteriores; la función de devolución de llamada del manejador pasada en srcPtr devuelve cuántos (o un número negativo para señalar un error, en cuyo caso también debe establecer el resultado del intérprete). La función tendrá la siguiente firma:
typedef int (Tcl_ArgvGenFuncProc)(
        ClientData clientData,
        Tcl_Interp *interp,
        int objc,
        Tcl_Obj *const *objv,
        void *dstPtr);

El clientData es el valor de la entrada de la tabla, el interp es dónde almacenar los mensajes de error, objc y objv describen un array de todos los argumentos restantes, y el argumento dstPtr a Tcl_ArgvGenFuncProc es la ubicación donde escribir el valor (o valores) analizado(s).

TCL_ARGV_HELP
Este argumento especial no toma ningún valor posterior, sino que hace que Tcl_ParseArgsObjv genere un mensaje de error que describe los argumentos admitidos. Todos los demás campos, excepto el campo helpStr, se ignoran.
TCL_ARGV_INT
Este argumento toma un valor entero posterior. El valor (una vez analizado por Tcl_GetIntFromObj) se almacenará como un int en la variable apuntada por el campo dstPtr. El campo srcPtr se ignora.
TCL_ARGV_REST
Este argumento especial no toma ningún valor posterior, sino que marca todos los argumentos posteriores para que no se procesen. Los campos srcPtr, dstPtr y clientData se ignoran.
TCL_ARGV_STRING
Este argumento toma un valor de cadena posterior. Se almacenará un puntero a la cadena en dstPtr; la cadena interior tendrá una vida útil vinculada a la vida útil de la representación de cadena del valor del argumento del que provino, y por lo tanto, debe copiarse si necesita ser conservada. Los campos srcPtr y clientData se ignoran.
