Tcl_Interp *interp (entrada)
Se utiliza para la notificación de errores y para buscar un canal registrado en él.

El nombre de un archivo local o de red.
const char *mode (entrada)
Especifica cómo se debe acceder al archivo. Puede tener cualquiera de los valores permitidos para el argumento mode del comando Tcl open.

Indicadores de permisos de estilo POSIX, como 0644. Si se crea un archivo nuevo, estos permisos se establecerán en el archivo creado.
int argc (entrada)
El número de elementos en argv.
const char **argv (entrada)
Argumentos para construir una tubería de comandos. Estos valores tienen el mismo significado que los argumentos sin opción del comando Tcl exec.
int flags (entrada)
Especifica la disposición de los manejadores stdio en la tubería: combinación OR de TCL_STDIN, TCL_STDOUT, TCL_STDERR y TCL_ENFORCE_MODE. Si se establece TCL_STDIN, la entrada estándar del primer hijo en la tubería es el canal de la tubería, de lo contrario, es la misma que la entrada estándar del proceso invocador; lo mismo ocurre con TCL_STDOUT y TCL_STDERR. Si TCL_ENFORCE_MODE no se establece, la tubería puede redirigir los manejadores stdio para anular los manejadores stdio para los que se han establecido TCL_STDIN, TCL_STDOUT y TCL_STDERR. Si está establecido, tales redirecciones causan un error.
ClientData handle (entrada)
Manejador específico del sistema operativo para E/S a un archivo. Para Unix, este es un descriptor de archivo; para Windows, es un HANDLE.

const char *channelName (entrada)
El nombre del canal.

Un puntero a un valor Tcl en el que se almacenarán los caracteres leídos del canal.

El número de caracteres a leer del canal. Si la codificación del canal es binary, esto es equivalente al número de bytes a leer del canal.

DESCRIPCIÓN

El mecanismo de canales de Tcl proporciona un mecanismo independiente de dispositivos y de plataformas para realizar operaciones de entrada y salida en búfer en una variedad de tipos de archivos, sockets y dispositivos. El mecanismo de canales es extensible a nuevos tipos de canales, proporcionando un controlador de canal de bajo nivel para el nuevo tipo; la interfaz del controlador de canal se describe en la entrada del manual de Tcl_CreateChannel. El mecanismo de canales proporciona un esquema de búfer modelado según la E/S estándar de Unix, y también permite E/S no bloqueante en los canales.

Los procedimientos descritos en esta entrada del manual comprenden las API de C de la capa genérica de la arquitectura de canales. Para una descripción de la arquitectura del controlador de canal y cómo implementar controladores de canal para nuevos tipos de canales, consulte la entrada del manual de Tcl_CreateChannel.

TCL_OPENFILECHANNEL

Abre un canal para la entrada/salida en el archivo llamado fileName. El argumento mode especifica cómo se accede al archivo y tiene el mismo significado que el argumento mode del comando Tcl open. El argumento permissions especifica los permisos de archivo que se aplicarán si se crea un archivo nuevo.

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

TCL_OPENFILECHANNEL

Tcl_OpenFileChannel abre un archivo especificado por fileName y devuelve un manejador de canal que puede ser utilizado para realizar E/S en el archivo. Esta API está modelada según el procedimiento fopen de la biblioteca estándar de E/S de Unix. La sintaxis y el significado de todos los argumentos son similares a los dados en el comando open de Tcl al abrir un archivo. Si ocurre un error al abrir el canal, Tcl_OpenFileChannel devuelve NULL y registra un código de error POSIX que puede recuperarse con Tcl_GetErrno. Además, si interp no es NULL, Tcl_OpenFileChannel deja un mensaje de error en el resultado de interp después de cualquier error. A partir de Tcl 8.4, se debe preferir la API basada en valores Tcl_FSOpenFileChannel a Tcl_OpenFileChannel siempre que sea posible.

El canal recién creado no se registra en el intérprete proporcionado; para registrarlo, use Tcl_RegisterChannel, descrito a continuación. Si uno de los canales estándar, stdin, stdout o stderr se cerró previamente, el acto de crear el nuevo canal también lo asigna como reemplazo del canal estándar.

TCL_OPENCOMMANDCHANNEL

Tcl_OpenCommandChannel proporciona una interfaz a nivel de C para las funciones de los comandos exec y open. Crea una secuencia de subprocesos especificados por los argumentos argv y argc y devuelve un canal que puede utilizarse para comunicarse con estos subprocesos. El argumento flags indica qué tipo de comunicación existirá con la tubería del comando.

Si la bandera TCL_STDIN está activada, la entrada estándar del primer subproceso se vinculará al canal: escribir en el canal proporcionará entrada al subproceso. Si TCL_STDIN no está activada, la entrada estándar del primer subproceso será la misma que la entrada estándar de esta aplicación. Si TCL_STDOUT está activada, la salida estándar del último subproceso se puede leer del canal; de lo contrario, va a la salida estándar de esta aplicación. Si TCL_STDERR está activada, la salida de error estándar de todos los subprocesos se devuelve al canal y resulta en un error al cerrar el canal; de lo contrario, va al error estándar de esta aplicación. Si TCL_ENFORCE_MODE no está activada, entonces argc y argv pueden redirigir los manejadores de stdio para anular TCL_STDIN, TCL_STDOUT y TCL_STDERR; si está activada, entonces es un error que argc y argv anulen los canales stdio para los que se han establecido TCL_STDIN, TCL_STDOUT y TCL_STDERR.

Si ocurre un error al abrir el canal, Tcl_OpenCommandChannel devuelve NULL y registra un código de error POSIX que puede recuperarse con Tcl_GetErrno. Además, Tcl_OpenCommandChannel deja un mensaje de error en el resultado del intérprete. interp no puede ser NULL.

El canal recién creado no se registra en el intérprete proporcionado; para registrarlo, use Tcl_RegisterChannel, descrito a continuación. Si uno de los canales estándar, stdin, stdout o stderr se cerró previamente, el acto de crear el nuevo canal también lo asigna como reemplazo del canal estándar.

TCL_MAKEFILECHANNEL

Tcl_MakeFileChannel crea un Tcl_Channel a partir de un manejador de archivo existente y específico de la plataforma. El canal recién creado no se registra en el intérprete proporcionado; para registrarlo, use Tcl_RegisterChannel, descrito a continuación. Si uno de los canales estándar, stdin, stdout o stderr se cerró previamente, el acto de crear el nuevo canal también lo asigna como reemplazo del canal estándar.

TCL_GETCHANNEL

Tcl_GetChannel devuelve un canal dado el channelName utilizado para crearlo con Tcl_CreateChannel y un puntero a un intérprete de Tcl en interp. Si no se registra un canal con ese nombre en ese intérprete, el procedimiento devuelve NULL. Si el argumento modePtr no es NULL, apunta a una variable entera que recibirá una combinación OR de TCL_READABLE y TCL_WRITABLE que describe si el canal está abierto para lectura y escritura.

Tcl_GetChannelNames y Tcl_GetChannelNamesEx escriben los nombres de los canales registrados en el resultado del intérprete como un valor de lista. Tcl_GetChannelNamesEx filtrará estos nombres según el pattern. Si pattern es NULL, entonces no realizará ningún filtrado. El valor de retorno es TCL_OK si no ocurrieron errores al escribir en el resultado, de lo contrario es TCL_ERROR, y el mensaje de error se deja en el resultado del intérprete.

TCL_REGISTERCHANNEL

Tcl_RegisterChannel agrega un canal al conjunto de canales accesibles en interp. Después de esta llamada, los programas de Tcl que se ejecutan en ese intérprete pueden referirse al canal en operaciones de entrada o salida utilizando el nombre dado en la llamada a Tcl_CreateChannel. Después de esta llamada, el canal se convierte en propiedad del intérprete, y el llamador no debe llamar a Tcl_Close para el canal; el canal se cerrará automáticamente cuando se desregistre del intérprete.

El código que se ejecuta fuera de cualquier intérprete de Tcl puede llamar a Tcl_RegisterChannel con interp como NULL, para indicar que desea mantener una referencia a este canal. Posteriormente, el canal puede registrarse en un intérprete de Tcl y solo se cerrará cuando el número correspondiente de llamadas a Tcl_UnregisterChannel se hayan realizado. Esto permite que el código que se ejecuta fuera de cualquier intérprete mantenga de forma segura una referencia a un canal que también está registrado en un intérprete de Tcl.

Este procedimiento interactúa con el código que administra los canales estándar. Si no se inicializaron canales estándar antes de la primera llamada a Tcl_RegisterChannel, se inicializarán con esa llamada. Consulte Tcl_StandardChannels para un tratado general sobre los canales estándar y el comportamiento de la biblioteca Tcl con respecto a ellos.

TCL_UNREGISTERCHANNEL

Tcl_UnregisterChannel elimina un canal del conjunto de canales accesibles en interp. Después de esta llamada, los programas de Tcl ya no podrán usar el nombre del canal para referirse al canal en ese intérprete. Si esta operación eliminó el último registro del canal en cualquier intérprete, el canal también se cierra y se destruye.

El código no asociado con un intérprete de Tcl puede llamar a Tcl_UnregisterChannel con interp como NULL, para indicar a Tcl que ya no mantiene una referencia a ese canal. Si esta es la última referencia al canal, se cerrará. Tcl_UnregisterChannel es muy similar a Tcl_DetachChannel, excepto que también cerrará el canal si no existen más referencias a él.

TCL_DETACHCHANNEL

Tcl_DetachChannel elimina un canal del conjunto de canales accesibles en interp. Después de esta llamada, los programas de Tcl ya no podrán usar el nombre del canal para referirse al canal en ese intérprete. Más allá de eso, este comando no tiene ningún efecto adicional. No se puede utilizar en los canales estándar (stdout, stderr, stdin), y devolverá TCL_ERROR si se le pasa uno de esos canales.

El código no asociado con un intérprete de Tcl puede llamar a Tcl_DetachChannel con interp como NULL, para indicar a Tcl que ya no mantiene una referencia a ese canal. Si esta es la última referencia al canal, a diferencia de Tcl_UnregisterChannel, no se cerrará.

TCL_ISSTANDARDCHANNEL

Tcl_IsStandardChannel comprueba si un canal es uno de los tres canales estándar, stdin, stdout o stderr. Si es así, devuelve 1, de lo contrario, 0.

No se hace ningún intento de comprobar si el canal dado o los canales estándar están inicializados o son válidos de otra manera.

TCL_CLOSE

Tcl_Close destruye el canal channel, que debe denotar un canal actualmente abierto. El canal no debe estar registrado en ningún intérprete cuando se llame a Tcl_Close. La salida en búfer se vacía en el dispositivo de salida del canal antes de destruir el canal, y cualquier entrada en búfer se descarta. Si se trata de un canal de bloqueo, la llamada no regresa hasta que todos los datos en búfer se envían con éxito al dispositivo de salida del canal. Si se trata de un canal sin bloqueo y hay salida en búfer que no se puede escribir sin bloquear, la llamada regresa inmediatamente; la salida se vacía en segundo plano y el canal se cerrará una vez que se hayan enviado todos los datos en búfer. En este caso, los errores durante el vaciado no se informan.

Si el canal se cerró correctamente, Tcl_Close devuelve TCL_OK. Si ocurre un error, Tcl_Close devuelve TCL_ERROR y registra un código de error POSIX que puede recuperarse con Tcl_GetErrno. Si el canal se está cerrando de forma síncrona y ocurre un error durante el cierre del canal y interp no es NULL, se deja un mensaje de error en el resultado del intérprete.

Nota: no es seguro llamar a Tcl_Close en un canal que ha sido registrado usando Tcl_RegisterChannel; consulte la documentación de Tcl_RegisterChannel, arriba, para obtener detalles. Si el canal se ha proporcionado alguna vez como argumento chan en una llamada a Tcl_RegisterChannel, debe usar Tcl_UnregisterChannel en su lugar, que llamará internamente a Tcl_Close cuando todas las llamadas a Tcl_RegisterChannel se hayan emparejado con llamadas correspondientes a Tcl_UnregisterChannel.

TCL_READCHARS Y TCL_READ

Tcl_ReadChars consume bytes del channel, convirtiendo los bytes a UTF-8 basándose en la codificación del canal y almacenando los datos producidos en la representación de cadena de readObjPtr. El valor de retorno de Tcl_ReadChars es el número de caracteres, hasta charsToRead, que se almacenaron en readObjPtr. Si ocurre un error al leer, el valor de retorno es -1 y Tcl_ReadChars registra un código de error POSIX que puede recuperarse con Tcl_GetErrno.

TCL_READCHARS, TCL_READOBJS, TCL_READ, AND TCL_READRAW

The Tcl_ReadChars procedure reads up to charsToRead characters from the channel channel and stores them in the Tcl value pointed to by readObjPtr. If charsToRead is negative, the command reads all characters currently available (non-blocking) or everything until eof (blocking mode).

The return value may be smaller than the value to read, indicating that less data than requested was available. This is called a short read. In blocking mode, this can only happen on an end-of-file. In nonblocking mode, a short read can also occur if there is not enough input currently available: Tcl_ReadChars returns a short count rather than waiting for more data.

If the channel is in blocking mode, a return value of zero indicates an end-of-file condition. If the channel is in nonblocking mode, a return value of zero indicates either that no input is currently available or an end-of-file condition. Use Tcl_Eof and Tcl_InputBlocked to tell which of these conditions actually occurred.

Tcl_ReadChars translates the various end-of-line representations into the canonical \n internal representation according to the current end-of-line recognition mode. End-of-line recognition and the various platform-specific modes are described in the manual entry for the Tcl fconfigure command.

As a performance optimization, when reading from a channel with the encoding binary, the bytes are not converted to UTF-8 as they are read. Instead, they are stored in readObjPtr's internal representation as a byte-array value. The string representation of this value will only be constructed if it is needed (e.g., because of a call to Tcl_GetStringFromObj). In this way, byte-oriented data can be read from a channel, manipulated by calling Tcl_GetByteArrayFromObj and related functions, and then written to a channel without the expense of ever converting to or from UTF-8.

Tcl_Read is similar to Tcl_ReadChars, except that it does not do encoding conversions, regardless of the channel's encoding. It is deprecated and exists for backwards compatibility with non-internationalized Tcl extensions. It consumes bytes from channel and stores them in readBuf, performing end-of-line translations on the way. The return value of Tcl_Read is the number of bytes, up to bytesToRead, written in readBuf. The buffer produced by Tcl_Read is not null-terminated. Its contents are valid from the zeroth position up to and excluding the position indicated by the return value.

Tcl_ReadRaw is the same as Tcl_Read but does not compensate for stacking. While Tcl_Read (and the other functions in the API) always get their data from the topmost channel in the stack the supplied channel is part of, Tcl_ReadRaw does not. Thus this function is only usable for transformational channel drivers, i.e. drivers used in the middle of a stack of channels, to move data from the channel below into the transformation.

TCL_GETSOBJ AND TCL_GETS

Tcl_GetsObj consumes bytes from channel, converting the bytes to UTF-8 based on the channel's encoding, until a full line of input has been seen. If the channel's encoding is binary, each byte read from the channel is treated as an individual Unicode character. All of the characters of the line except for the terminating end-of-line character(s) are appended to lineObjPtr's string representation. The end-of-line character(s) are read and discarded.

If a line was successfully read, the return value is greater than or equal to zero and indicates the number of bytes stored in lineObjPtr. If an error occurs, Tcl_GetsObj returns -1 and records a POSIX error code that can be retrieved with Tcl_GetErrno. Tcl_GetsObj also returns -1 if the end of the file is reached; the Tcl_Eof procedure can be used to distinguish an error from an end-of-file condition.

If the channel is in nonblocking mode, the return value can also be -1 if no data was available or the data that was available did not contain an end-of-line character. When -1 is returned, the Tcl_InputBlocked procedure may be invoked to determine if the channel is blocked because of input unavailability.

Tcl_Gets is the same as Tcl_GetsObj except the resulting characters are appended to the dynamic string given by lineRead rather than a Tcl value.

TCL_UNGETS

Tcl_Ungets is used to add data to the input queue of a channel, at either the head or tail of the queue. The pointer input points to the data that is to be added. The length of the input to add is given by inputLen. A non-zero value of addAtEnd indicates that the data is to be added at the end of queue; otherwise it will be added at the head of the queue. If channel has a “sticky” EOF set, no data will be added to the input queue. Tcl_Ungets returns inputLen or -1 if an error occurs.

TCL_WRITECHARS, TCL_WRITEOBJ, AND TCL_WRITE

Tcl_WriteChars accepts bytesToWrite bytes of character data at charBuf. The UTF-8 characters in the buffer are converted to the channel's encoding and queued for output to channel. If bytesToWrite is negative, Tcl_WriteChars expects charBuf to be null-terminated and it outputs everything up to the null.

Data queued for output may not appear on the output device immediately, due to internal buffering. If the data should appear immediately, call Tcl_Flush after the call to Tcl_WriteChars, or set the -buffering option on the channel to none. If you wish the data to appear as soon as a complete line is accepted for output, set the -buffering option on the channel to line mode.

The return value of Tcl_WriteChars is a count of how many bytes were accepted for output to the channel. This is either greater than zero to indicate success or -1 to indicate that an error occurred. If an error occurs, Tcl_WriteChars records a POSIX error code that may be retrieved with Tcl_GetErrno.

Newline characters in the output data are translated to platform-specific end-of-line sequences according to the -translation option for the channel. This is done even if the channel has no encoding.

Tcl_WriteObj is similar to Tcl_WriteChars except it accepts a Tcl value whose contents will be output to the channel. The UTF-8 characters in writeObjPtr's string representation are converted to the channel's encoding and queued for output to channel. As a performance optimization, when writing to a channel with the encoding binary, UTF-8 characters are not converted as they are written. Instead, the bytes in writeObjPtr's internal representation as a byte-array value are written to the channel. The byte-array representation of the value will be constructed if it is needed. In this way, byte-oriented data can be read from a channel, manipulated by calling Tcl_GetByteArrayFromObj and related functions, and then written to a channel without the expense of ever converting to or from UTF-8.

Tcl_Write is similar to Tcl_WriteChars except that it does not do encoding conversions, regardless of the channel's encoding. It is deprecated and exists for backwards compatibility with non-internationalized Tcl extensions. It accepts bytesToWrite bytes of data at byteBuf and queues them for output to channel. If bytesToWrite is negative, Tcl_Write expects byteBuf to be null-terminated and it outputs everything up to the null.

Tcl_WriteRaw is the same as Tcl_Write but does not compensate for stacking. While Tcl_Write (and the other functions in the API) always feed their input to the topmost channel in the stack the supplied channel is part of, Tcl_WriteRaw does not. Thus this function is only usable for transformational channel drivers, i.e. drivers used in the middle of a stack of channels, to move data from the transformation into the channel below it.

TCL_FLUSH

Tcl_Flush causes all of the buffered output data for channel to be written to its underlying file or device as soon as possible. If the channel is in blocking mode, the call does not return until all the buffered data has been sent to the channel or some error occurred. The call returns immediately if the channel is nonblocking; it starts a background flush that will write the buffered data to the channel eventually, as fast as the channel is able to absorb it.

The return value is normally TCL_OK. If an error occurs, Tcl_Flush returns TCL_ERROR and records a POSIX error code that can be retrieved with Tcl_GetErrno.

TCL_SEEK

Tcl_Seek moves the access point in channel where subsequent data will be read or written. Buffered output is flushed to the channel and buffered input is discarded, prior to the seek operation.

Tcl_Seek normally returns the new access point. If an error occurs, Tcl_Seek returns -1 and records a POSIX error code that can be retrieved with Tcl_GetErrno. After an error, the access point may or may not have been moved.

TCL_TELL

Tcl_Tell returns the current access point for a channel. The returned value is -1 if the channel does not support seeking.

TCL_TRUNCATECHANNEL

Tcl_TruncateChannel truncates the file underlying channel to a given length of bytes. It returns TCL_OK if the operation succeeded, and TCL_ERROR otherwise.

TCL_GETCHANNELOPTION

Tcl_GetChannelOption retrieves, in optionValue, the value of one of the options currently in effect for a channel, or a list of all options and their values. The channel argument identifies the channel for which to query an option or retrieve all options and their values. If optionName is not NULL, it is the name of the option to query; the option's value is copied to the Tcl dynamic string denoted by optionValue. If optionName is NULL, the function stores an alternating list of option names and their values in optionValue.

Tcl_OpenCommandChannel(3)

NAME

Tcl_OpenCommandChannel, Tcl_MakeCommandChannel, Tcl_GetCommandChannel, Tcl_GetChannelCommand - manage Tcl channels

SYNOPSIS

#include <tcl.h>

Tcl_Channel
Tcl_OpenCommandChannel(interp, readChan, writeChan, closeOwn);
int
Tcl_GetChannelCommand(interp, channelName);
Tcl_Channel
Tcl_MakeCommandChannel(interp, readChan, writeChan, closeOwn);
Tcl_Channel
Tcl_GetChannel(interp, channelName);

ARGUMENTS

Tcl_Interp *interp
Interpreter to use for error reporting.
Tcl_Channel readChan
Channel to read from. Must be open for reading.
Tcl_Channel writeChan
Channel to write to. Must be open for writing.
int closeOwn
If non-zero, then Tcl will close the channels when the command channel is closed.
const char *channelName
Name of the channel.

DESCRIPTION

Tcl channels are implemented by channel drivers. A channel driver is a collection of procedures that implement the common Tcl channel interface for a particular type of channel. For example, Tcl includes drivers for file channels, socket channels, and pipe channels. This document describes the low-level channel interface, which is used to implement new channel types within Tcl.

The basic Tcl channel interface is defined by a set of functions that are common to all channel types. These functions include functions to open a channel, close a channel, read from a channel, write to a channel, flush a channel, seek on a channel, and get/set channel options. These functions are described in the manual entries for the Tcl commands that manipulate channels, such as open, close, read, write, fconfigure, and puts.

In addition to the common interface, each channel type may define its own set of operations. These operations are exposed to Tcl scripts through the fconfigure command. The additional options for each channel type are described in the manual entry for the Tcl command that creates a channel of that type; for example, the additional options for socket channels are described in the manual entry for the socket command.

The low-level channel interface is documented in this manual entry. It is intended for use by Tcl extensions that need to implement new channel types or to interact with Tcl channels at a lower level than is possible using the standard Tcl commands.

TCL_OPENFILECHANNEL

Tcl_OpenFileChannel opens a channel for accessing a file. The fileName argument specifies the name of the file to open. The mode argument specifies how the file should be opened (e.g., read, write, binary, text). This function returns a Tcl_Channel handle for the newly opened file channel, or NULL if an error occurs.

The possible values for mode are the same as those used by the standard C library function fopen. If an error occurs, an error message is left in the interpreter's result if interp is not NULL.

TCL_OPENCOMMANDCHANNEL

Tcl_OpenCommandChannel creates a new channel that connects two existing channels, readChan and writeChan. This is useful for creating channels that represent connections between processes or other entities. The closeOwn argument determines whether Tcl should close the underlying channels when the command channel is closed. This function returns a Tcl_Channel handle for the new command channel, or NULL if an error occurs.

If an error occurs, an error message is left in the interpreter's result if interp is not NULL.

TCL_MAKEFILECHANNEL

Tcl_MakeFileChannel associates a Tcl channel with an existing file descriptor or other underlying channel representation. This is useful when a Tcl extension needs to take over management of an existing channel, such as one returned by a system call like socket or pipe. The readProc and writeProc arguments specify the procedures to use for reading and writing on the channel. The myname argument is the name to give the channel. This function returns a Tcl_Channel handle for the new channel, or NULL if an error occurs.

If an error occurs, an error message is left in the interpreter's result if interp is not NULL.

TCL_GETCHANNEL

Tcl_GetChannel returns a Tcl_Channel handle for the channel named channelName in the interpreter interp. If no channel with that name exists, or if the name is not a valid channel name, it returns NULL and leaves an error message in the interpreter's result.

TCL_REGISTERCHANNEL

Tcl_RegisterChannel registers a channel driver named driverName with the Tcl interpreter interp. The driverProc argument is a pointer to the procedure that implements the driver's operations. The clientData argument can be used to pass arbitrary data to the driver procedures. This function allows new channel types to be added to Tcl dynamically. The procedure returns TCL_OK on success and TCL_ERROR on failure.

TCL_UNREGISTERCHANNEL

Tcl_UnregisterChannel unregisters the channel driver named driverName from the Tcl interpreter interp. This function should only be called when there are no open channels of the type being unregistered.

TCL_DETACHCHANNEL

Tcl_DetachChannel removes a channel from the Tcl interpreter's management. This is useful when a Tcl extension needs to take ownership of a channel that was previously managed by Tcl. The channel's underlying I/O descriptors are not closed. The function returns the Tcl_Channel handle if successful, or NULL if an error occurs.

TCL_ISSTANDARDCHANNEL

Tcl_IsStandardChannel returns a non-zero value if the channel chan is one of Tcl's standard channels (stdin, stdout, or stderr), and zero otherwise.

TCL_CLOSE

Tcl_Close closes the channel chan. Any buffered output is flushed before the channel is closed. If an error occurs during closing (e.g., flushing buffered output), an error message is left in the interpreter's result if interp is not NULL.

The procedure returns TCL_OK on success, or TCL_ERROR if an error occurs.

TCL_READCHARS AND TCL_READ

Tcl_ReadChars reads up to numChars characters from chan into the buffer buf. If interp is non-NULL, error messages are left in the interpreter's result. Tcl_Read reads up to numBytes bytes from chan into the buffer buf.

Both functions return the number of characters or bytes actually read. If end-of-file is encountered, the return value may be less than requested. If an error occurs during the read operation, the return value is -1 and an error message is left in the interpreter's result (if interp is non-NULL). If the channel is in non-blocking mode and no data is available, the return value is 0.

TCL_GETSOBJ AND TCL_GETS

Tcl_Gets reads a line from channel chan into the buffer line. The line is terminated by a newline character, which is read but not stored in the buffer. The maximum number of characters that may be read is lineLen-1. If end-of-file is encountered before any characters are read, -1 is returned. If end-of-file is encountered after some characters have been read, the number of characters read is returned. If an error occurs, -1 is returned and an error message is left in the interpreter's result if interp is non-NULL.

Tcl_GetObj reads a line from channel chan and returns it as a Tcl object. It handles internal buffering and character encoding automatically. This is the preferred way to read lines from Tcl channels.

TCL_UNGETS

Tcl_Ungets pushes the string str back onto the input buffer of channel chan. This allows characters that have been read to be rescanned. If interp is non-NULL, error messages are left in the interpreter's result. The procedure normally returns TCL_OK. If an error occurs, it returns TCL_ERROR.

TCL_WRITECHARS, TCL_WRITEOBJ, AND TCL_WRITE

Tcl_WriteChars writes the characters in chars to channel chan. Tcl_WriteObj writes the characters in the Tcl object objPtr to channel chan. Tcl_Write writes the bytes in bytes to channel chan.

These functions attempt to write the specified amount of data. They return the number of characters or bytes actually written. If the channel is in non-blocking mode and no data could be written immediately, the return value may be less than requested (possibly zero). If an error occurs, the return value is -1 and an error message is left in the interpreter's result if interp is non-NULL.

TCL_FLUSH

Tcl_Flush flushes any buffered output for channel chan. If interp is non-NULL, error messages are left in the interpreter's result. The procedure normally returns TCL_OK. If an error occurs, it returns TCL_ERROR.

TCL_SEEK

Tcl_Seek repositions the read/write access point for channel chan. The offset argument specifies the new position, and the seekMode argument specifies how the offset is interpreted. seekMode can be SEEK_SET (offset from beginning of file), SEEK_CUR (offset from current position), or SEEK_END (offset from end of file). This function returns the new access position, or -1 if an error occurs.

If an error occurs, an error message is left in the interpreter's result if interp is non-NULL.

TCL_TELL

Tcl_Tell returns the current access position for channel chan. If an error occurs, it returns -1 and leaves an error message in the interpreter's result if interp is non-NULL.

TCL_TRUNCATECHANNEL

Tcl_TruncateChannel truncates the file associated with channel chan to the specified length. This operation is only supported for file channels opened for writing. The length argument specifies the new length of the file in bytes. If an error occurs, an error message is left in the interpreter's result if interp is non-NULL.

The procedure returns TCL_OK on success and TCL_ERROR on failure.

TCL_GETCHANNELOPTION

Tcl_GetChannelOption retrieves the value of the option named optionName for the channel channel. The value is returned as a Tcl object, and the caller is responsible for disposing of the object when done. The option name should be a Tcl string (e.g., "buffering", "blocking"). The possible options and their values are described in the manual entry for the Tcl fconfigure command. Other options may be added by each channel type.

The procedure normally returns TCL_OK. If an error occurs, it returns TCL_ERROR and leaves an error message in the interpreter's result.

This function is intended to be used primarily by channel drivers to implement the fconfigure command. Tcl scripts should use fconfigure to get channel options.

The procedure normally returns TCL_OK. If an error occurs, it returns TCL_ERROR and leaves an error message in the interpreter's result.

The option value is returned as a Tcl object in *objPtrPtr. The caller is responsible for disposing of the object when done. If an error occurs, *objPtrPtr is set to NULL.

The procedure normally returns TCL_OK. If an error occurs, it returns TCL_ERROR and leaves an error message in the interpreter's result.

The various options are described in the manual entry for the Tcl fconfigure command. The Tcl library maintains a default set of options that are available for all channel types. Additional options can be added by each channel type. These channel type specific options are described in the manual entry for the Tcl command that creates a channel of that type; for example, the additional options for TCP-based channels are described in the manual entry for the Tcl socket command. The procedure normally returns TCL_OK. If an error occurs, it returns TCL_ERROR and calls Tcl_SetErrno to store an appropriate POSIX error code.

TCL_SETCHANNELOPTION

Tcl_SetChannelOption sets a new value newValue for an option optionName on channel. The procedure normally returns TCL_OK. If an error occurs, it returns TCL_ERROR; in addition, if interp is non-NULL, Tcl_SetChannelOption leaves an error message in the interpreter's result.

TCL_EOF

Tcl_Eof returns a nonzero value if channel encountered an end of file during the last input operation.

TCL_INPUTBLOCKED

Tcl_InputBlocked returns a nonzero value if channel is in nonblocking mode and the last input operation returned less data than requested because there was insufficient data available. The call always returns zero if the channel is in blocking mode.

TCL_INPUTBUFFERED

Tcl_InputBuffered returns the number of bytes of input currently buffered in the internal buffers for a channel. If the channel is not open for reading, this function always returns zero.

TCL_OUTPUTBUFFERED

Tcl_OutputBuffered returns the number of bytes of output currently buffered in the internal buffers for a channel. If the channel is not open for writing, this function always returns zero.

PLATFORM ISSUES

The handles returned from Tcl_GetChannelHandle depend on the platform and the channel type. On Unix platforms, the handle is always a Unix file descriptor as returned from the open system call. On Windows platforms, the handle is a file HANDLE when the channel was created with Tcl_OpenFileChannel, Tcl_OpenCommandChannel, or Tcl_MakeFileChannel. Other channel types may return a different type of handle on Windows platforms.
