ARGUMENTOS

Tcl_Interp *interp (entrada)
Intérprete en el que registrar la información.

int code El código devuelto por la evaluación del script.
Tcl_Obj *options Un diccionario de opciones de retorno.

const char *message (entrada)
Para Tcl_AddErrorInfo, esta es una cadena C convencional para añadir a la opción de retorno -errorinfo. Para Tcl_AddObjErrorInfo, esto apunta al primer byte de una matriz de length bytes que contiene una cadena para añadir a la opción de retorno -errorinfo. Esta matriz de bytes puede contener bytes nulos incrustados a menos que length sea negativo.
Tcl_Obj *objPtr (entrada)
Un mensaje que se añadirá a la opción de retorno -errorinfo en forma de un valor Tcl_Obj.
int length (entrada)
El número de bytes a copiar de message al añadir a la opción de retorno -errorinfo. Si es negativo, se utilizan todos los bytes hasta el primer byte nulo.
Tcl_Obj *errorObjPtr (entrada)
La opción de retorno -errorcode se establecerá en este valor.
const char *element (entrada)
Cadena a registrar como un elemento de la opción de retorno -errorcode. El último argumento element debe ser (char *)NULL.
va_list argList (entrada)
Una lista de argumentos que debe haber sido inicializada usando va_start y limpiada usando va_end.

int lineNum El número de línea de un script donde ocurrió un error.
const char *script (entrada)
Puntero al primer carácter en el script que contiene el comando (debe ser <= comando)
const char *command (entrada)
Puntero al primer carácter en el comando que generó el error
int commandLength (entrada)
Número de bytes en el comando; -1 significa usar todos los bytes hasta el primer byte nulo.

DESCRIPCIÓN

Las rutinas Tcl_SetReturnOptions y Tcl_GetReturnOptions exponen las mismas capacidades que los comandos return y catch, respectivamente, en forma de una interfaz C.

Tcl_GetReturnOptions recupera el diccionario de opciones de retorno de un intérprete después de la evaluación de un script. Rutinas como Tcl_Eval se utilizan para evaluar un script en un intérprete. Estas rutinas devuelven un código de finalización entero. Estas rutinas también dejan en el intérprete tanto un resultado como un diccionario de opciones de retorno generado por la evaluación del script. Al igual que Tcl_GetObjResult recupera el resultado, Tcl_GetReturnOptions recupera el diccionario de opciones de retorno. El código de finalización entero debe pasarse como el argumento code a Tcl_GetReturnOptions para que todas las opciones requeridas estén presentes en el diccionario. Específicamente, un valor de code de TCL_ERROR garantizará que las entradas para las claves -errorinfo, -errorcode y -errorline aparezcan en el diccionario. Además, las entradas para las claves -code y -level se ajustarán si es necesario para que coincidan con el valor de code. El (Tcl_Obj *) devuelto por Tcl_GetReturnOptions apunta a un Tcl_Obj no compartido con un contador de referencias cero. El diccionario puede modificarse, añadiendo, eliminando o sobrescribiendo cualquier entrada en él, sin necesidad de comprobar si está compartido. Como con cualquier Tcl_Obj con un contador de referencias cero, depende del llamador organizar su disposición con Tcl_DecrRefCount o una referencia a él a través de Tcl_IncrRefCount (o una de las muchas funciones que llaman a esta, incluyendo notablemente Tcl_SetObjResult y Tcl_SetVar2Ex).

Un uso típico para Tcl_GetReturnOptions es recuperar el trazado de pila cuando la evaluación del script devuelve TCL_ERROR, como se muestra a continuación:

int code = Tcl_Eval(interp, script);
if (code == TCL_ERROR) {
    Tcl_Obj *options = Tcl_GetReturnOptions(interp, code);
    Tcl_Obj *key = Tcl_NewStringObj("-errorinfo", -1);
    Tcl_Obj *stackTrace;
    Tcl_IncrRefCount(key);
    Tcl_DictObjGet(NULL, options, key, &stackTrace);
    Tcl_DecrRefCount(key);
    /* Hacer algo con stackTrace */
    Tcl_DecrRefCount(options);
}

Tcl_SetReturnOptions establece las opciones de retorno de interp a ser options. Si options contiene algún valor inválido para alguna clave, se devolverá TCL_ERROR, y el resultado del intérprete se establecerá a un mensaje de error apropiado. De lo contrario, se devolverá un código de finalización de acuerdo con las claves -code y -level en options.

Por ejemplo, el propio comando return de Tcl podría implementarse en términos de Tcl_SetReturnOptions de la siguiente manera:

if ((objc % 2) == 0) { /* argumento de resultado explícito */
    objc--;
    Tcl_SetObjResult(interp, objv[objc]);
}
return Tcl_SetReturnOptions(interp, Tcl_NewListObj(objc-1, objv+1));

(En realidad no está implementado de esa manera. Los privilegios de acceso interno permiten una alternativa más eficiente que se integra mejor con el compilador de bytecode.)

Tenga en cuenta que se puede pasar un Tcl_Obj recién creado como argumento options sin necesidad de gestionar ningún conteo de referencias. Esto es análogo a Tcl_SetObjResult.

Si bien Tcl_SetReturnOptions proporciona una interfaz general para establecer cualquier colección de opciones de retorno, hay un puñado de opciones de retorno que se utilizan con mucha frecuencia. En particular, las opciones de retorno -errorinfo y -errorcode deben establecerse correctamente cuando el procedimiento de comando de un comando devuelve TCL_ERROR. La opción de retorno -errorline también es leída por los comandos que evalúan scripts y desean proporcionar información detallada de ubicación del error en el texto del trazado de pila que añaden a la opción -errorinfo. Tcl proporciona varias interfaces más sencillas para establecer directamente estas opciones de retorno.

La opción -errorinfo contiene un trazado de pila de las operaciones que estaban en progreso cuando ocurrió un error, y está destinada a ser legible por humanos. La opción -errorcode contiene una lista de Tcl de elementos destinados a ser legibles por máquinas. El primer elemento en el valor -errorcode identifica la clase de error que ocurrió (por ejemplo, POSIX significa que ocurrió un error en una llamada al sistema POSIX) y los elementos adicionales contienen piezas adicionales de información que dependen de la clase. Consulte la entrada del manual sobre la variable errorCode para obtener detalles sobre los diversos formatos para la opción -errorcode utilizados por los comandos integrados de Tcl.

El valor de la opción -errorinfo se construye gradualmente a medida que un error se desenrolla a través de las operaciones anidadas. Cada vez que un código de error se devuelve a Tcl_Eval, o a cualquiera de las rutinas que realiza la evaluación de scripts, se llama al procedimiento Tcl_AddErrorInfo para añadir texto adicional al valor -errorinfo que describe el comando que se estaba ejecutando cuando ocurrió el error. Para cuando el error ha sido pasado completamente a la aplicación, contendrá un rastro completo de la actividad en progreso cuando ocurrió el error.

A veces es útil añadir información adicional al valor -errorinfo más allá de lo que pueden suministrar automáticamente las rutinas de evaluación de scripts. Tcl_AddErrorInfo puede usarse para este propósito: su argumento message es una cadena adicional para ser añadida a la opción -errorinfo. Por ejemplo, cuando surge un error durante el comando source, se llama al procedimiento Tcl_AddErrorInfo para registrar el nombre del archivo que se está procesando y el número de línea en el que ocurrió el error. DESCRIPCIÓN

Tcl_AppendObjToErrorInfo(3) es una interfaz alternativa a la misma funcionalidad que Tcl_AddErrorInfo(3). Tcl_AppendObjToErrorInfo(3) se llama cuando el valor de la cadena que se va a añadir a la opción -errorinfo está disponible como un Tcl_Obj en lugar de como un array de char.

Tcl_AddErrorInfo(3) registra el nombre del procedimiento y el número de línea dentro del procedimiento a efectos de reporte de errores. El mejor momento para llamar a Tcl_AddErrorInfo(3) es justo después de que una rutina de evaluación de scripts haya devuelto TCL_ERROR. El valor de la opción de retorno -errorline (obtenido mediante una llamada a Tcl_GetReturnOptions(3)) a menudo constituye una parte útil del mensaje pasado a Tcl_AddErrorInfo(3).

Tcl_AddObjErrorInfo(3) es casi idéntica a Tcl_AddErrorInfo(3), excepto que tiene un argumento de longitud adicional. Esto permite que la cadena del mensaje contenga bytes nulos incrustados. Esto es esencialmente una mala idea. Si el mensaje necesita contener el carácter nulo U+0000, se deben utilizar las reglas de codificación internas habituales de Tcl para evitar la necesidad de un byte nulo. Si se utiliza la interfaz Tcl_AddObjErrorInfo(3), debería ser con un valor de longitud negativo.

El procedimiento Tcl_SetObjErrorCode(3) se utiliza para establecer la opción de retorno -errorcode al valor de lista errorObjPtr construido por el llamador. Tcl_SetObjErrorCode(3) se invoca típicamente justo antes de devolver un error. Si se devuelve un error sin llamar a Tcl_SetObjErrorCode(3) o Tcl_SetErrorCode(3), el intérprete Tcl establece automáticamente la opción de retorno -errorcode a NONE.

El procedimiento Tcl_SetErrorCode(3) también se utiliza para establecer la opción de retorno -errorcode. Sin embargo, toma una o más cadenas para registrar en lugar de un valor. Por lo demás, es similar a Tcl_SetObjErrorCode(3) en su comportamiento.

Tcl_SetErrorCodeVA(3) es lo mismo que Tcl_SetErrorCode(3) excepto que en lugar de tomar un número variable de argumentos, toma una lista de argumentos.

El procedimiento Tcl_GetErrorLine(3) se utiliza para leer el valor entero de la opción de retorno -errorline sin la sobrecarga de una llamada completa a Tcl_GetReturnOptions(3). Del mismo modo, Tcl_SetErrorLine(3) establece el valor de la opción de retorno -errorline.

Tcl_PosixError(3) establece la variable -errorcode después de un error en una llamada al kernel POSIX. Lee el valor de la variable C errno y llama a Tcl_SetErrorCode(3) para establecer la opción de retorno -errorcode en formato POSIX. El llamador debe haber llamado previamente a Tcl_SetErrno(3) para establecer errno; esto es necesario en algunas plataformas (por ejemplo, Windows) donde Tcl se enlaza a una aplicación como una biblioteca compartida, o cuando el error ocurre en una extensión cargada dinámicamente. Consulte la entrada del manual de Tcl_SetErrno(3) para obtener más información.

Tcl_PosixError(3) devuelve un mensaje de diagnóstico legible por humanos para el error (este es el mismo valor que aparecerá como el tercer elemento en el valor -errorcode). Puede ser conveniente incluir esta cadena como parte del mensaje de error devuelto a la aplicación en el resultado del intérprete.

Tcl_LogCommandInfo(3) se invoca después de que ocurre un error en un intérprete. Añade información sobre el comando que se estaba ejecutando cuando ocurrió el error al valor -errorinfo, y el número de línea almacenado internamente en el intérprete se establece.

En versiones anteriores de Tcl, no existía la rutina Tcl_GetReturnOptions(3). En su lugar, las variables globales de Tcl errorInfo y errorCode eran el único lugar para recuperar la información de error. Mucho código existente escrito para versiones anteriores de Tcl todavía accede a esta información a través de esas variables globales.

Es importante darse cuenta de que, si bien la lectura de esas variables globales sigue siendo una forma admitida de acceder a estos valores de opciones de retorno, es importante no asumir que la escritura en esas variables globales establecerá correctamente las opciones de retorno correspondientes. Se ha enfatizado durante mucho tiempo en esta página del manual que es importante llamar a los procedimientos descritos aquí en lugar de establecer errorInfo o errorCode directamente con Tcl_ObjSetVar2(3).

Si se llama al procedimiento Tcl_ResetResult(3), borra todo el estado del intérprete asociado con la evaluación de scripts, incluido todo el diccionario de opciones de retorno. En particular, se restablecen las opciones -errorinfo y -errorcode. Si hubiera ocurrido un error, la llamada a Tcl_ResetResult(3) borrará el estado de error para que parezca que no ha ocurrido ningún error después de todo. Las variables globales errorInfo y errorCode no son modificadas por Tcl_ResetResult(3), por lo que continúan manteniendo un registro de información sobre el error más reciente visto en un intérprete.
