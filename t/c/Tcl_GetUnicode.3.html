ARGUMENTOS

const char *bytes (entrada)
Punta al primer byte de una matriz de bytes codificados en UTF-8 utilizada para establecer o añadir a un valor de cadena. Esta matriz de bytes puede contener caracteres nulos incrustados a menos que numChars sea negativo. (Las aplicaciones que necesitan bytes nulos deberían representarlos como la secuencia de dos bytes \300\200, usar Tcl_ExternalToUtf para convertir, o Tcl_NewByteArrayObj si la cadena es una colección de bytes no interpretados.)
int length (entrada)
El número de bytes a copiar de bytes al inicializar, establecer o añadir a un valor de cadena. Si es negativo, se usan todos los bytes hasta el primer nulo.
const Tcl_UniChar *unicode (entrada)
Punta al primer byte de una matriz de caracteres Unicode utilizada para establecer o añadir a un valor de cadena. Esta matriz de bytes puede contener caracteres nulos incrustados a menos que numChars sea negativo.
int numChars (entrada)
El número de caracteres Unicode a copiar de unicode al inicializar, establecer o añadir a un valor de cadena. Si es negativo, se usan todos los caracteres hasta el primer carácter nulo.
int index (entrada)
El índice del carácter Unicode a devolver.
int first (entrada)
El índice del primer carácter Unicode en el rango Unicode a devolver como un nuevo valor.
int last (entrada)

const char *string (entrada)

DESCRIPCIÓN

Los procedimientos descritos en esta entrada del manual permiten que los valores Tcl se manipulen como valores de cadena. Utilizan la representación interna del valor para almacenar información adicional y hacer que las manipulaciones de cadenas sean más eficientes. En particular, hacen que una serie de operaciones de adición sean eficientes al asignar espacio de almacenamiento adicional para la cadena, de modo que no tenga que copiarse en cada adición. Además, los cálculos de indexación y longitud se optimizan porque la representación de cadena Unicode se calcula y se almacena en caché según sea necesario. Al utilizar la familia de funciones Tcl_Append* donde el resultado del intérprete es el valor al que se está añadiendo, es importante llamar a Tcl_ResetResult primero para asegurarse de que no se está añadiendo inadvertidamente a datos existentes en el valor de resultado.

Tcl_NewStringObj y Tcl_SetStringObj crean un nuevo valor o modifican un valor existente para que contenga una copia de la cadena proporcionada por bytes y length. Tcl_NewUnicodeObj y Tcl_SetUnicodeObj crean un nuevo valor o modifican un valor existente para que contenga una copia de la cadena Unicode proporcionada por unicode y numChars. Tcl_NewStringObj y Tcl_NewUnicodeObj devuelven un puntero a un valor recién creado con recuento de referencias cero. Los cuatro procedimientos establecen el valor para que contenga una copia de la cadena especificada. Tcl_SetStringObj y Tcl_SetUnicodeObj liberan cualquier representación de cadena antigua, así como cualquier representación interna antigua del valor.

Tcl_GetStringFromObj y Tcl_GetString devuelven la representación de cadena de un valor. Esto se proporciona mediante el puntero de retorno y (para Tcl_GetStringFromObj) la longitud, que se almacena en lengthPtr si no es NULL. Si la representación de cadena UTF del valor no es válida (su puntero de bytes es NULL), la representación de cadena se regenera a partir de la representación interna del valor. El almacenamiento referenciado por el puntero de bytes devuelto es propiedad del gestor de valores. Se pasa como un puntero escribible para que el autor de la extensión que crea su propia Tcl_ObjType pueda modificar la representación de cadena dentro de la Tcl_UpdateStringProc de su Tcl_ObjType. Excepto para ese propósito limitado, el puntero devuelto por Tcl_GetStringFromObj o Tcl_GetString debe tratarse como de solo lectura. Se recomienda que este puntero se asigne a una variable (const char *). Incluso en las situaciones limitadas en las que escribir en este puntero es aceptable, se debe tener cuidado de respetar las semánticas de copia en escritura requeridas por los Tcl_Obj, con llamadas apropiadas a Tcl_IsShared y Tcl_DuplicateObj antes de cualquier modificación in situ de la representación de cadena. El procedimiento Tcl_GetString se utiliza en el caso común en el que el llamador no necesita la longitud de la representación de cadena.

Tcl_GetUnicodeFromObj y Tcl_GetUnicode devuelven el valor de un valor como una cadena Unicode. Esto se proporciona mediante el puntero devuelto y (para Tcl_GetUnicodeFromObj) la longitud, que se almacena en lengthPtr si no es NULL. El almacenamiento referenciado por el puntero de bytes devuelto es propiedad del gestor de valores y no debe ser modificado por el llamador. El procedimiento Tcl_GetUnicode se utiliza en el caso común en el que el llamador no necesita la longitud de la representación de cadena unicode.

Tcl_GetUniChar devuelve el carácter *index* en la representación Unicode del valor. Se asume que el índice está en el rango apropiado.

Tcl_GetRange devuelve un nuevo valor compuesto por los caracteres entre first y last (inclusive) en la representación Unicode del valor. Si la representación Unicode del valor no es válida, la representación Unicode se regenera a partir de la representación de cadena del valor. Si first < 0, entonces la cadena devuelta comienza al principio del valor. Si last < 0, entonces la cadena devuelta termina al final del valor.

DESCRIPCIÓN

Las siguientes funciones de Tcl proporcionan mecanismos para construir y manipular valores de objetos Tcl, particularmente sus representaciones de cadena. Se centran en agregar datos a objetos existentes, formatear datos en objetos y establecer la longitud de la cadena de un objeto.

Tcl_AppendToObj agrega los datos dados por bytes y length a la representación de cadena del valor especificado por objPtr. Si el valor tiene una representación de cadena inválida, se intenta convertir bytes al formato Unicode. Si la conversión es exitosa, se agrega la forma convertida de bytes a la representación Unicode del valor. De lo contrario, la representación Unicode del valor se invalida y se convierte al formato UTF, y bytes se agrega a la nueva representación de cadena del valor. Eventualmente, el crecimiento del búfer se realiza mediante asignaciones grandes para optimizar llamadas múltiples.

Tcl_AppendUnicodeToObj agrega la cadena Unicode dada por unicode y numChars al valor especificado por objPtr. Si el valor tiene una representación Unicode inválida, unicode se convierte al formato UTF y se agrega a la representación de cadena del valor. Las adiciones se optimizan para manejar adiciones repetidas de manera relativamente eficiente (sobreasigna el espacio de cadena o Unicode para evitar reasignaciones y copias repetidas del valor de cadena del valor).

Tcl_AppendObjToObj es similar a Tcl_AppendToObj, pero agrega el valor de cadena o Unicode (el que exista y sea más adecuado para agregarse a objPtr) de appendObjPtr a objPtr.

Tcl_AppendStringsToObj es similar a Tcl_AppendToObj excepto que se le pueden pasar más de un valor para agregar y cada valor debe ser una cadena terminada en nulo (es decir, ninguno de los valores puede contener caracteres nulos internos). Se puede proporcionar cualquier número de argumentos string, pero el último argumento debe ser (char *)NULL para indicar el final de la lista.

Tcl_AppendStringsToObjVA es lo mismo que Tcl_AppendStringsToObj excepto que en lugar de tomar un número variable de argumentos, toma una lista de argumentos.

Tcl_AppendLimitedToObj es similar a Tcl_AppendToObj excepto que impone un límite en la cantidad de bytes que se agregan. Esto puede ser útil cuando la cadena que se va a agregar puede ser muy grande, pero no se debe permitir que el valor que se está construyendo crezca sin límites. Un uso común es al construir un mensaje de error, donde el resultado final debe mantenerse lo suficientemente corto como para ser leído. Los bytes de bytes se agregan a objPtr, pero no se agregan más de limit bytes en total. Si el límite impide que se agreguen todos los length bytes disponibles, la adición se realiza de manera que los últimos bytes agregados provienen de la cadena ellipsis. Esto permite una indicación de la truncación que se deja en la cadena. Cuando length es -1, se agregan todos los bytes hasta el primer byte cero, sujeto al límite. Cuando ellipsis es NULL, se usa la cadena predeterminada .... Cuando ellipsis no es NULL, debe apuntar a una cadena terminada en byte cero en la codificación UTF interna de Tcl. El número de bytes agregados puede ser menor que el menor de length y limit cuando es necesario agregar menos bytes para agregar solo caracteres de varios bytes completos.

Tcl_Format es la interfaz a nivel de C del motor del comando format. El procedimiento de comando real para format es poco más que

Tcl_Format(interp, Tcl_GetString(objv[1]), objc-2, objv+2);

Los valores Tcl_Obj objc en objv se formatean en una cadena de acuerdo con la especificación de conversión en el argumento format, siguiendo la documentación del comando format. La cadena formateada resultante se convierte en un nuevo Tcl_Obj con un recuento de referencia de cero y se devuelve. Si ocurre algún error durante la producción de la cadena formateada, se devuelve NULL y se registra un mensaje de error en interp, si interp no es NULL.

Tcl_AppendFormatToObj es una forma alternativa de agregar de Tcl_Format con funcionalidad equivalente a:

Tcl_Obj *newPtr = Tcl_Format(interp, format, objc, objv);
if (newPtr == NULL) return TCL_ERROR;
Tcl_AppendObjToObj(objPtr, newPtr);
Tcl_DecrRefCount(newPtr);
return TCL_OK;

pero con mayor conveniencia y eficiencia cuando se necesita la funcionalidad de agregar.

Tcl_ObjPrintf sirve como un reemplazo para la secuencia común

char buf[SOME_SUITABLE_LENGTH];
sprintf(buf, format, ...);
Tcl_NewStringObj(buf, -1);

pero con mayor conveniencia y sin necesidad de determinar SOME_SUITABLE_LENGTH. El formateo se realiza con el mismo motor de formateo central utilizado por Tcl_Format. Esto significa que el conjunto de especificadores de conversión compatibles es el del comando format, pero el comportamiento es lo más similar posible a sprintf. Los especificadores de formato que fueron agregados por C99 (como "hh", "ll", "j", "z", "t", "L") no son compatibles. Cuando un especificador de conversión pasado a Tcl_ObjPrintf incluye una precisión, el valor se toma como un número de bytes, como lo hace sprintf, y no como un número de caracteres, como lo hace format. Esto se hace bajo el supuesto de que el código C es más propenso a saber cuántos bytes está manejando que cuántos caracteres codificados representan esos bytes. Los argumentos variables pasados deben ser de los tipos que serían adecuados para pasar a sprintf. Tenga en cuenta en este ejemplo de uso, x es de tipo int.

int x = 5;
Tcl_Obj *objPtr = Tcl_ObjPrintf("Value is %d", x);

Si el valor de format contiene inconsistencias internas o formatos de especificador inválidos, la cadena resultante formateada producida por Tcl_ObjPrintf será un mensaje de error que describe el error. Sin embargo, es imposible proporcionar protección en tiempo de ejecución contra discrepancias entre el formato y cualquier argumento posterior. Algunos compiladores pueden proporcionar protección en tiempo de compilación.

Tcl_AppendPrintfToObj es una forma alternativa de agregar de Tcl_ObjPrintf con funcionalidad equivalente a

Tcl_Obj *newPtr = Tcl_ObjPrintf(format, ...);
Tcl_AppendObjToObj(objPtr, newPtr);
Tcl_DecrRefCount(newPtr);

pero con mayor conveniencia y eficiencia cuando se necesita la funcionalidad de agregar.

El procedimiento Tcl_SetObjLength cambia la longitud del valor de cadena de su argumento objPtr. Si el argumento newLength es mayor que el espacio asignado para la cadena del valor, el espacio de cadena se reasigna y el valor antiguo se copia al nuevo espacio; los bytes entre la longitud antigua de la cadena y la nueva longitud pueden tener valores arbitrarios. Si el argumento newLength es menor que la longitud actual de la cadena del valor, con objPtr->length se reduce sin reasignar el espacio de cadena; el tamaño de asignación original para la cadena se registra en el valor, de modo que la longitud de la cadena se pueda ampliar en una llamada posterior a Tcl_SetObjLength sin reasignar el almacenamiento. En todos los casos, Tcl_SetObjLength deja un carácter nulo en objPtr->bytes[newLength].

Tcl_AttemptSetObjLength es idéntico en función a Tcl_SetObjLength excepto que si no se puede asignar suficiente memoria para satisfacer la solicitud, no hace que el intérprete Tcl entre en panic. Por lo tanto, si newLength es mayor que el espacio asignado para la cadena del valor, y no hay suficiente memoria disponible para satisfacer la solicitud, Tcl_AttemptSetObjLength no tomará ninguna acción y devolverá 0 para indicar un fallo. Si hay suficiente memoria para satisfacer la solicitud, Tcl_AttemptSetObjLength se comporta igual que Tcl_SetObjLength y devuelve 1 para indicar éxito.

La función Tcl_ConcatObj devuelve un nuevo valor de cadena cuyo valor es la concatenación separada por espacios de las representaciones de cadena de todos los valores en la matriz objv. Tcl_ConcatObj elimina los espacios en blanco iniciales y finales al copiar las representaciones de cadena de la matriz objv al resultado. Si un elemento de la matriz objv consiste únicamente en espacios en blanco, ese valor se ignora por completo. Esta eliminación de espacios en blanco se agregó para que la salida del comando concat se vea más limpia. Tcl_ConcatObj devuelve un puntero a un valor recién creado con un recuento de referencia de cero.
