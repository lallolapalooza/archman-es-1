Tcl_ParseCommand(3) Procedimientos de la biblioteca Tcl Tcl_ParseCommand(3)

NOMBRE

Tcl_ParseCommand, Tcl_ParseExpr, Tcl_ParseBraces, Tcl_ParseQuotedString, Tcl_ParseVarName, Tcl_ParseVar, Tcl_FreeParse, Tcl_EvalTokens, Tcl_EvalTokensStandard - analizar scripts y expresiones de Tcl

SINOPSIS

#include <tcl.h>

int
Tcl_ParseCommand(interp, start, numBytes, nested, parsePtr)

int
Tcl_ParseExpr(interp, start, numBytes, parsePtr)

int
Tcl_ParseBraces(interp, start, numBytes, parsePtr, append, termPtr)

int
Tcl_ParseQuotedString(interp, start, numBytes, parsePtr, append, termPtr)

int
Tcl_ParseVarName(interp, start, numBytes, parsePtr, append)

const char *
Tcl_ParseVar(interp, start, termPtr)

Tcl_FreeParse(usedParsePtr)

Tcl_Obj *
Tcl_EvalTokens(interp, tokenPtr, numTokens)

int
Tcl_EvalTokensStandard(interp, tokenPtr, numTokens)

ARGUMENTOS

Tcl_Interp *interp (salida)
Para procedimientos distintos de Tcl_FreeParse, Tcl_EvalTokens y Tcl_EvalTokensStandard, solo se usa para la notificación de errores; si es NULL, entonces no se dejan mensajes de error después de los errores. Para Tcl_EvalTokens y Tcl_EvalTokensStandard, determina el contexto para evaluar el script y también se usa para la notificación de errores; no debe ser NULL.
const char *start (entrada)
Puntero al primer carácter de la cadena a analizar.
int numBytes (entrada)
Número de bytes en la cadena a analizar, sin incluir ningún carácter nulo de terminación. Si es menor que 0, entonces el script consiste en todos los caracteres que siguen a start hasta el primer carácter nulo.
int nested (entrada)
Distinto de cero significa que el script es parte de una sustitución de comando, por lo que un corchete de cierre sin comillas se tratará como un terminador de comando. Si es cero, los corchetes de cierre no tienen ningún significado especial.
int append (entrada)
Distinto de cero significa que *parsePtr ya contiene tokens válidos; los nuevos tokens deben agregarse a los que ya están presentes. Cero significa que *parsePtr no está inicializado; cualquier información en él se ignora. Este argumento es normalmente 0.
Tcl_Parse *parsePtr (salida)
Punta a la estructura que se llenará con información sobre el comando analizado, expresión, nombre de variable, etc. Cualquier información previa en esta estructura se ignora, a menos que append sea distinto de cero en una llamada a Tcl_ParseBraces, Tcl_ParseQuotedString o Tcl_ParseVarName.
const char **termPtr (salida)
Si no es NULL, apunta a una ubicación donde Tcl_ParseBraces, Tcl_ParseQuotedString y Tcl_ParseVar almacenarán un puntero al carácter justo después del carácter de terminación (el corchete de cierre, el último carácter del nombre de la variable o la comilla de cierre (respectivamente)) si el análisis fue exitoso.
Tcl_Parse *usedParsePtr (entrada)
Punta a la estructura que fue llenada por una llamada previa a Tcl_ParseCommand, Tcl_ParseExpr, Tcl_ParseVarName, etc.

DESCRIPCIÓN

Estos procedimientos analizan comandos de Tcl o porciones de comandos de Tcl tales como expresiones o referencias a variables. Cada procedimiento toma un puntero a un script (o una porción del mismo) y llena la estructura apuntada por parsePtr con una colección de tokens que describen la información que se analizó. Los procedimientos normalmente devuelven TCL_OK. Sin embargo, si ocurre un error, devuelven TCL_ERROR, dejan un mensaje de error en el resultado de interp (si interp no es NULL), y no dejan nada en parsePtr.

Tcl_ParseCommand es un procedimiento que analiza scripts de Tcl. Dado un puntero a un script, analiza el primer comando del script. Si el comando se analizó correctamente, Tcl_ParseCommand devuelve TCL_OK y llena la estructura apuntada por parsePtr con información sobre la estructura del comando (ver más abajo para detalles). Si ocurrió un error al analizar el comando, se devuelve TCL_ERROR, se deja un mensaje de error en el resultado de interp y no se deja información en *parsePtr.

Tcl_ParseExpr analiza expresiones de Tcl. Dado un puntero a un script que contiene una expresión, Tcl_ParseExpr analiza la expresión. Si la expresión se analizó correctamente, Tcl_ParseExpr devuelve TCL_OK y llena la estructura apuntada por parsePtr con información sobre la estructura de la expresión (ver más abajo para detalles). Si ocurrió un error al analizar el comando, se devuelve TCL_ERROR, se deja un mensaje de error en el resultado de interp y no se deja información en *parsePtr.

Tcl_ParseBraces analiza una cadena o argumento de comando entre llaves como {hola} o {cadena\t con\t tabulaciones} desde el principio de su argumento start. El primer carácter de start debe ser {. Si la cadena entre llaves se analizó correctamente, Tcl_ParseBraces devuelve TCL_OK, llena la estructura apuntada por parsePtr con información sobre la estructura de la cadena (ver más abajo para detalles), y almacena un puntero al carácter justo después de la } de terminación en la ubicación dada por *termPtr. Si ocurre un error al analizar la cadena, se devuelve TCL_ERROR, se deja un mensaje de error en el resultado de interp y no se deja información en *parsePtr ni en *termPtr.

Tcl_ParseQuotedString analiza una cadena entre comillas dobles como "la suma es [expr {$a+$b}]" desde el principio del argumento start. El primer carácter de start debe ser ". Si la cadena entre comillas dobles se analizó correctamente, Tcl_ParseQuotedString devuelve TCL_OK, llena la estructura apuntada por parsePtr con información sobre la estructura de la cadena (ver más abajo para detalles), y almacena un puntero al carácter justo después de la " de terminación en la ubicación dada por *termPtr. Si ocurre un error al analizar la cadena, se devuelve TCL_ERROR, se deja un mensaje de error en el resultado de interp y no se deja información en *parsePtr ni en *termPtr.

Tcl_ParseVarName analiza una referencia a variable de Tcl como $abc o $x([expr {$indice + 1}]) desde el principio de su argumento start. El primer carácter de start debe ser $. Si el nombre de la variable se analizó correctamente, Tcl_ParseVarName devuelve TCL_OK y llena la estructura apuntada por parsePtr con información sobre la estructura del nombre de la variable (ver más abajo para detalles). Si ocurre un error al analizar el comando, se devuelve TCL_ERROR, se deja un mensaje de error en el resultado de interp (si interp no es NULL) y no se deja información en *parsePtr.

Tcl_ParseVar analiza una referencia a variable de Tcl como $abc o $x([expr {$indice + 1}]) desde el principio de su argumento start. El primer carácter de start debe ser $. Si el nombre de la variable se analiza correctamente, Tcl_ParseVar devuelve un puntero al valor de cadena de la variable. Si ocurre un error al analizar, se devuelve NULL y se deja un mensaje de error en el resultado de interp.

La información que queda en *parsePtr por Tcl_ParseCommand, Tcl_ParseExpr, Tcl_ParseBraces, Tcl_ParseQuotedString y Tcl_ParseVarName puede incluir memoria asignada dinámicamente. Si estos cinco procedimientos de análisis devuelven TCL_OK, el llamador debe invocar Tcl_FreeParse para liberar el almacenamiento en *parsePtr. Estos procedimientos ignoran cualquier información existente en *parsePtr (a menos que append sea distinto de cero), por lo que si se realizan llamadas repetidas a cualquiera de ellos, Tcl_FreeParse debe ser invocado una vez después de cada llamada.

Tcl_EvalTokensStandard evalúa una secuencia de tokens de análisis de una estructura Tcl_Parse. Los tokens normalmente consisten en todos los tokens en una palabra o todos los tokens que componen el índice para una referencia a una variable de matriz. Tcl_EvalTokensStandard realiza las sustituciones solicitadas por los tokens y concatena los valores resultantes. El valor de retorno de Tcl_EvalTokensStandard es un código de finalización de Tcl con uno de los valores TCL_OK, TCL_ERROR, TCL_RETURN, TCL_BREAK o TCL_CONTINUE, o posiblemente algún otro valor entero originario de una extensión. Además, se deja un valor de resultado o un mensaje de error en el resultado de interp; se puede recuperar usando Tcl_GetObjResult.

Tcl_EvalTokens difiere de Tcl_EvalTokensStandard solo en el retorno

ESTRUCTURA DE PARSEO DE TCL

Tcl_ParseCommand, Tcl_ParseExpr, Tcl_ParseBraces, Tcl_ParseQuotedString, y Tcl_ParseVarName devuelven información de parseo en dos estructuras, Tcl_Parse y Tcl_Token:

typedef struct Tcl_Parse {
    const char *commentStart;
    int commentSize;
    const char *commandStart;
    int commandSize;
    int numWords;
    Tcl_Token *tokenPtr;
    int numTokens;
    ...
} Tcl_Parse;
typedef struct Tcl_Token {
    int type;
    const char *start;
    int size;
    int numComponents;
} Tcl_Token;

Los primeros cinco campos de una estructura Tcl_Parse son completados solo por Tcl_ParseCommand. Estos campos no son utilizados por otros procedimientos de parseo.

Tcl_ParseCommand completa una estructura Tcl_Parse con información que describe un comando Tcl y cualquier comentario que preceda al comando. Si hay comentarios, el campo commentStart apunta al carácter # que inicia el primer comentario y commentSize indica el número de bytes en todos los comentarios que preceden al comando, incluyendo el carácter de nueva línea que finaliza el último comentario. Si el comando no está precedido por comentarios, commentSize es 0. Tcl_ParseCommand también establece el campo commandStart para apuntar al primer carácter de la primera palabra del comando (ignorando cualquier comentario y espacio en blanco inicial) y commandSize indica el número total de bytes en el comando, incluyendo el carácter apuntado por commandStart hasta el carácter de nueva línea, corchete de cierre o punto y coma que finaliza el comando. El campo numWords indica el número total de palabras en el comando.

Todos los procedimientos de parseo establecen los campos restantes, tokenPtr y numTokens. El campo tokenPtr apunta al primero de un array de estructuras Tcl_Token que describen los componentes de la entidad que se está parseando. El campo numTokens indica el número total de tokens presentes en el array. Cada token contiene cuatro campos. El campo type selecciona uno de varios tipos de token que se describen a continuación. El campo start apunta al primer carácter del token y el campo size indica el número total de caracteres en el token. Algunos tipos de token, como TCL_TOKEN_WORD y TCL_TOKEN_VARIABLE, consisten en varios componentes de tokens, que siguen inmediatamente al token padre; el campo numComponents describe cuántos de estos hay. El campo type tiene uno de los siguientes valores:

TCL_TOKEN_WORD
Este token generalmente describe una palabra de un comando, pero también puede describir una cadena entrecomillada o entre corchetes en una expresión. El token describe un componente del script que es el resultado de concatenar una secuencia de subcomponentes, cada una descrita por un subtóken separado. El token comienza con el primer carácter no blanco del componente (que puede ser una comilla doble o un corchete de apertura) e incluye todos los caracteres del componente hasta el carácter de espacio en blanco, punto y coma, corchete de cierre, comilla o corchete de cierre que finaliza el componente. El campo numComponents cuenta el número total de subtokens que forman la palabra, incluyendo subtokens de TCL_TOKEN_VARIABLE y TCL_TOKEN_BS.
TCL_TOKEN_SIMPLE_WORD
Este token tiene el mismo significado que TCL_TOKEN_WORD, excepto que se garantiza que la palabra consistirá en un único subtóken TCL_TOKEN_TEXT. El campo numComponents siempre es 1.
TCL_TOKEN_EXPAND_WORD
Este token tiene el mismo significado que TCL_TOKEN_WORD, excepto que el analizador de comandos notifica que esta palabra comenzó con el prefijo de expansión {*}, lo que indica que después de la sustitución, el valor de lista de esta palabra debe expandirse para formar múltiples argumentos en la evaluación del comando. Este tipo de token solo puede ser creado por Tcl_ParseCommand.
TCL_TOKEN_TEXT
El token describe un rango de texto literal que es parte de una palabra. El campo numComponents siempre es 0.
TCL_TOKEN_BS
El token describe una secuencia de barra invertida como \n o \0xA3. El campo numComponents siempre es 0.
TCL_TOKEN_COMMAND
El token describe un comando cuyo resultado debe ser sustituido en la palabra. El token incluye los corchetes que rodean al comando. El campo numComponents siempre es 0 (el comando anidado no se analiza; llame a Tcl_ParseCommand recursivamente si desea ver sus tokens).
TCL_TOKEN_VARIABLE
El token describe una sustitución de variable, incluyendo el $, el nombre de la variable y el índice del array (si lo hay) hasta el paréntesis de cierre que finaliza el índice. Este token va seguido de uno o más tokens adicionales que describen el nombre de la variable y el índice. Si numComponents es 1, entonces la variable es escalar y el siguiente token es un TCL_TOKEN_TEXT que da el nombre de la variable. Si numComponents es mayor que 1, entonces la variable es un array: el primer subtóken es un TCL_TOKEN_TEXT que da el nombre del array y los subtokens restantes son TCL_TOKEN_TEXT, TCL_TOKEN_BS, TCL_TOKEN_COMMAND o TCL_TOKEN_VARIABLE que deben concatenarse para producir el índice del array. El campo numComponents incluye los subtokens que forman parte de los tokens TCL_TOKEN_VARIABLE en el índice del array.
TCL_TOKEN_SUB_EXPR
El token describe una subexpresión de una expresión (o una expresión entera). Una subexpresión puede consistir en un valor como un entero literal, una sustitución de variable o una subexpresión entre paréntesis; también puede consistir en un operador y sus operandos. El token comienza con el primer carácter no blanco de la subexpresión hasta el carácter de espacio en blanco, corchete, paréntesis de cierre o corchete que finaliza la subexpresión. Este token va seguido de uno o más tokens adicionales que describen la subexpresión. Si el primer subtóken después del token TCL_TOKEN_SUB_EXPR es un token TCL_TOKEN_OPERATOR, la subexpresión consiste en un operador y sus operandos. Si el operador no tiene operandos, la subexpresión consiste únicamente en el token TCL_TOKEN_OPERATOR. Cada operando se describe mediante un token TCL_TOKEN_SUB_EXPR. De lo contrario, la subexpresión es un valor descrito por uno de los tipos de token TCL_TOKEN_WORD, TCL_TOKEN_TEXT, TCL_TOKEN_BS, TCL_TOKEN_COMMAND, TCL_TOKEN_VARIABLE o TCL_TOKEN_SUB_EXPR. El campo numComponents cuenta el número total de subtokens que forman la subexpresión; esto incluye los subtokens de cualquier token TCL_TOKEN_SUB_EXPR anidado.
TCL_TOKEN_OPERATOR
El token describe una operación de una expresión como && o hypot. Un token TCL_TOKEN_OPERATOR siempre va precedido por un token TCL_TOKEN_SUB_EXPR que describe la operación y sus operandos; el campo numComponents del token TCL_TOKEN_SUB_EXPR puede usarse para determinar el número de operandos. Un operador binario como * va seguido de dos tokens TCL_TOKEN_SUB_EXPR que describen sus operandos. Un operador unario como - va seguido de un solo token TCL_TOKEN_SUB_EXPR para su operando. Si el operador es una función matemática como log10, el token TCL_TOKEN_OPERATOR dará su nombre y los siguientes tokens TCL_TOKEN_SUB_EXPR describirán sus operandos; si no tiene operandos (como con rand), no habrá tokens TCL_TOKEN_SUB_EXPR después. Hay una operación ternaria, ?, que aparece en subexpresiones if-then-else como x?y:z; en este caso, el token ? TCL_TOKEN_OPERATOR va seguido de tres tokens TCL_TOKEN_SUB_EXPR para los operandos x, y, y z. El campo numComponents para un token TCL_TOKEN_OPERATOR siempre es 0.

Después de que Tcl_ParseCommand retorna, el primer token apuntado por el campo tokenPtr de la estructura Tcl_Parse siempre tiene el tipo TCL_TOKEN_WORD o TCL_TOKEN_SIMPLE_WORD o TCL_TOKEN_EXPAND_WORD. Le siguen los subtokens que deben concatenarse para producir el valor de esa palabra. El siguiente token es el TCL_TOKEN_WORD o TCL_TOKEN_SIMPLE_WORD del token TCL_TOKEN_EXPAND_WORD para la segunda palabra, seguido por los subtokens de esa palabra, y así sucesivamente hasta que se hayan contado todas las numWords.

Después de que Tcl_ParseExpr retorna, el primer token apuntado por el campo tokenPtr de la estructura Tcl_Parse siempre tiene el tipo TCL_TOKEN_SUB_EXPR. Le siguen los subtokens que deben evaluarse para producir el valor de la expresión. Solo la información de token en la estructura Tcl_Parse se modifica: los campos commentStart, commentSize, commandStart y commandSize no son modificados por Tcl_ParseExpr.

Después de que Tcl_ParseBraces retorna, el array de tokens apuntado por el campo tokenPtr de la estructura Tcl_Parse contendrá un único token TCL_TOKEN_TEXT si la cadena entre corchetes no contiene ninguna secuencia de barra invertida-nueva línea. Si la cadena contiene secuencias de barra invertida-nueva línea, el array de tokens contendrá uno o más subtokens TCL_TOKEN_TEXT o TCL_TOKEN_BS que deben concatenarse para producir el valor de la cadena. Si la cadena entre corchetes era solo {} (es decir, la cadena estaba vacía), el único token TCL_TOKEN_TEXT tendrá un campo size con cero; esto garantiza que aparezca al menos un token para describir la cadena entre corchetes. Solo la información de token en la estructura Tcl_Parse se modifica: los campos commentStart

> , tamañoComentario, inicioComando y tamañoComando no son modificados por Tcl_ParseBraces.

Después de que Tcl_ParseQuotedString retorna, el array de tokens al que apunta el campo tokenPtr de la estructura Tcl_Parse depende del contenido de la cadena entre comillas. Consistirá en uno o más sub-tokens TCL_TOKEN_TEXT, TCL_TOKEN_BS, TCL_TOKEN_COMMAND y TCL_TOKEN_VARIABLE. El array siempre contiene al menos un token; por ejemplo, si el argumento start está vacío, el array devuelto consiste en un único token TCL_TOKEN_TEXT con un campo size cero. Solo la información del token en la estructura Tcl_Parse es modificada: los campos inicioComentario, tamañoComentario, inicioComando y tamañoComando no son modificados.

Después de que Tcl_ParseVarName retorna, el primer token al que apunta el campo tokenPtr de la estructura Tcl_Parse siempre tiene el tipo TCL_TOKEN_VARIABLE. Le siguen los sub-tokens que conforman el nombre de la variable, como se describe anteriormente. La longitud total del nombre de la variable está contenida en el campo size del primer token. Al igual que en Tcl_ParseExpr, solo la información del token en la estructura Tcl_Parse es modificada por Tcl_ParseVarName: los campos inicioComentario, tamañoComentario, inicioComando y tamañoComando no son modificados.

Todos los punteros a caracteres en las estructuras Tcl_Parse y Tcl_Token se refieren a caracteres en el argumento start pasado a Tcl_ParseCommand, Tcl_ParseExpr, Tcl_ParseBraces, Tcl_ParseQuotedString y Tcl_ParseVarName.

Hay campos adicionales en la estructura Tcl_Parse después del campo numTokens, pero estos son para uso privado de Tcl_ParseCommand, Tcl_ParseExpr, Tcl_ParseBraces, Tcl_ParseQuotedString y Tcl_ParseVarName; no deben ser referenciados por código fuera de estos procedimientos.
