Tcl_TraceVar(3) Procedimientos de la biblioteca Tcl Tcl_TraceVar(3)

NOMBRE

Tcl_TraceVar, Tcl_TraceVar2, Tcl_UntraceVar, Tcl_UntraceVar2, Tcl_VarTraceInfo, Tcl_VarTraceInfo2 - monitorizar accesos a una variable

SINOPSIS

#include <tcl.h>

int
Tcl_TraceVar(interp, varName, flags, proc, clientData)

int
Tcl_TraceVar2(interp, name1, name2, flags, proc, clientData)

Tcl_UntraceVar(interp, varName, flags, proc, clientData)

Tcl_UntraceVar2(interp, name1, name2, flags, proc, clientData)

ClientData
Tcl_VarTraceInfo(interp, varName, flags, proc, prevClientData)

ClientData
Tcl_VarTraceInfo2(interp, name1, name2, flags, proc, prevClientData)

ARGUMENTOS

Tcl_Interp *interp (entrada)
Intérprete que contiene la variable.
const char *varName (entrada)
Nombre de la variable. Puede referirse a una variable escalar, a una variable de array sin índice, o a una variable de array con un índice entre paréntesis.
int flags (entrada)
Combinación OR de los valores TCL_TRACE_READS, TCL_TRACE_WRITES, TCL_TRACE_UNSETS, TCL_TRACE_ARRAY, TCL_GLOBAL_ONLY, TCL_NAMESPACE_ONLY, TCL_TRACE_RESULT_DYNAMIC y TCL_TRACE_RESULT_OBJECT. No todos los flags son utilizados por todos los procedimientos. Véase más abajo para más información.
Tcl_VarTraceProc *proc (entrada)
Procedimiento a invocar cada vez que ocurra una de las operaciones rastreadas.
ClientData clientData (entrada)
Valor arbitrario de una palabra a pasar a proc.
const char *name1 (entrada)
Nombre de la variable escalar o de array (sin el índice del array).
const char *name2 (entrada)
Para un rastreo en un elemento de un array, proporciona el índice del elemento. Para rastreos en variables escalares o en arrays completos, es NULL.
ClientData prevClientData (entrada)
Si no es NULL, proporciona el último valor devuelto por Tcl_VarTraceInfo o Tcl_VarTraceInfo2, por lo que esta llamada devolverá información sobre el siguiente rastreo. Si es NULL, esta llamada devolverá información sobre el primer rastreo.

DESCRIPCIÓN

Tcl_TraceVar permite a un procedimiento C monitorizar y controlar el acceso a una variable Tcl, de modo que el procedimiento C sea invocado cada vez que la variable se lea, se escriba o se des Establezca. Si el rastreo se crea con éxito, Tcl_TraceVar devuelve TCL_OK. Si ocurrió un error (p. ej. varName especifica un elemento de un array, pero la variable real no es un array) entonces se devuelve TCL_ERROR y se deja un mensaje de error en el resultado del intérprete.

El argumento flags de Tcl_TraceVar indica cuándo se invocará el procedimiento de rastreo y proporciona información para configurar el rastreo. Consta de una combinación OR de cualquiera de los siguientes valores:

TCL_GLOBAL_ONLY
Normalmente, la variable se buscará en el nivel actual de llamada al procedimiento; si este bit está activado, la variable se buscará a nivel global, ignorando cualquier procedimiento activo.
TCL_NAMESPACE_ONLY
Normalmente, la variable se buscará en el nivel actual de llamada al procedimiento; si este bit está activado, la variable se buscará en el espacio de nombres actual, ignorando cualquier procedimiento activo.
TCL_TRACE_READS
Invoca proc cada vez que se intenta leer la variable.
TCL_TRACE_WRITES
Invoca proc cada vez que se intenta modificar la variable.
TCL_TRACE_UNSETS
Invoca proc cada vez que la variable se des Establece. Una variable puede ser des Establecida ya sea explícitamente por un comando unset, o implícitamente cuando un procedimiento regresa (sus variables locales se des Establecen automáticamente) o cuando se elimina el intérprete (todas las variables se des Establecen automáticamente).
TCL_TRACE_ARRAY
Invoca proc cada vez que se invoca el comando array. Esto da al procedimiento de rastreo la oportunidad de actualizar el array antes de que se llame a nombres de array o array get. Tenga en cuenta que esto se llama antes de un array set, pero eso activará rastreos de escritura.
TCL_TRACE_RESULT_DYNAMIC
El resultado de invocar proc es una cadena asignada dinámicamente que será liberada por la biblioteca Tcl mediante una llamada a ckfree. No se debe especificar al mismo tiempo que TCL_TRACE_RESULT_OBJECT.
TCL_TRACE_RESULT_OBJECT
El resultado de invocar proc es un Tcl_Obj* (convertido a char*) con un contador de referencias de al menos uno. La propiedad de esa referencia se transferirá al núcleo de Tcl para su liberación (cuando el núcleo haya terminado con él) mediante una llamada a Tcl_DecrRefCount. No se debe especificar al mismo tiempo que TCL_TRACE_RESULT_DYNAMIC.

Cada vez que ocurra una de las operaciones especificadas en la variable, se invocará proc. Debe tener argumentos y resultado que coincidan con el tipo Tcl_VarTraceProc:

typedef char *Tcl_VarTraceProc(
        ClientData clientData,
        Tcl_Interp *interp,
        const char *name1,
        const char *name2,
        int flags);

Los parámetros clientData e interp tendrán los mismos valores que los pasados a Tcl_TraceVar cuando se creó el rastreo. ClientData típicamente apunta a una estructura de datos específica de la aplicación que describe qué hacer cuando se invoca proc. Name1 y name2 dan el nombre de la variable rastreada en la forma normal de dos partes (ver la descripción de Tcl_TraceVar2 abajo para detalles). Flags es una combinación OR de bits que proporciona varias piezas de información. Uno de los bits TCL_TRACE_READS, TCL_TRACE_WRITES, TCL_TRACE_ARRAY, o TCL_TRACE_UNSETS se establecerá en flags para indicar qué operación se está realizando en la variable. El bit TCL_GLOBAL_ONLY se establecerá cada vez que la variable que se está accediendo sea una variable global no accesible desde el nivel actual de llamada al procedimiento: el procedimiento de rastreo deberá pasar este flag de vuelta a procedimientos relacionados con variables como Tcl_GetVar si intenta acceder a la variable. El bit TCL_NAMESPACE_ONLY se establecerá cada vez que la variable que se está accediendo sea una variable de espacio de nombres no accesible desde el nivel actual de llamada al procedimiento: el procedimiento de rastreo deberá pasar este flag de vuelta a procedimientos relacionados con variables como Tcl_GetVar si intenta acceder a la variable. El bit TCL_TRACE_DESTROYED se establecerá en flags si el rastreo está a punto de ser destruido; esta información puede ser útil para proc para que pueda limpiar sus propias estructuras de datos internas (ver la sección TCL_TRACE_DESTROYED abajo para más detalles). Por último, el bit TCL_INTERP_DESTROYED se establecerá si el intérprete completo está siendo destruido. Cuando este bit está activado, proc debe tener especial cuidado con las cosas que hace (ver la sección TCL_INTERP_DESTROYED abajo). El valor de retorno del procedimiento de rastreo normalmente debe ser NULL; ver RETORNOS DE ERROR abajo para información sobre otras posibilidades.

Tcl_UntraceVar puede usarse para eliminar un rastreo. Si la variable especificada por interp, varName, y flags tiene un rastreo establecido con flags, proc, y clientData, entonces el rastreo correspondiente se elimina. Si no existe dicho rastreo, la llamada a Tcl_UntraceVar no tiene efecto. Los mismos bits son válidos para flags que para las llamadas a Tcl_TraceVar.

Tcl_VarTraceInfo puede usarse para recuperar información sobre rastreos establecidos en una variable dada. El valor de retorno de Tcl_VarTraceInfo es el clientData asociado con un rastreo particular. El rastreo debe estar en la variable especificada por los argumentos interp, varName, y flags (solo los bits TCL_GLOBAL_ONLY y TCL_NAMESPACE_ONLY de flags se usan; otros bits se ignoran) y su procedimiento de rastreo debe ser el mismo que el argumento proc. Si el argumento prevClientData es NULL, el valor de retorno corresponde al primer rastreo coincidente (el creado más recientemente), o NULL si no hay coincidencias.

TCL_TRACINFO

Tcl_VarTraceInfo, Tcl_TraceVar2, Tcl_UntraceVar2, Tcl_VarTraceInfo2 ?TCL_TRACINFO?

Tcl_VarTraceInfo may be used to iterate through all traces for a particular variable. The varName argument is the name of the variable to query. The flags argument is an OR-ed combination of bits, described below. If the prevClientData argument is NULL, then the first call to Tcl_VarTraceInfo will return information about the first trace for varName that matches flags, or NULL if no traces match. Otherwise, prevClientData should be the return value from a previous call to Tcl_VarTraceInfo. In this case, the new return value will correspond to the next matching trace after the one whose clientData matches prevClientData, or NULL if no trace matches prevClientData or if there are no more matching traces after it. This mechanism makes it possible to step through all of the traces for a given variable that have the same proc.

NOMBRES DE DOS PARTES

Los procedimientos Tcl_TraceVar2, Tcl_UntraceVar2 y Tcl_VarTraceInfo2 son idénticos a Tcl_TraceVar, Tcl_UntraceVar y Tcl_VarTraceInfo, respectivamente, excepto que el nombre de la variable consta de dos partes. Name1 proporciona el nombre de una variable escalar o un array, y name2 proporciona el nombre de un elemento dentro de un array. Cuando name2 es NULL, name1 puede contener tanto el nombre del array como el del elemento: si el nombre contiene un paréntesis de apertura y termina con un paréntesis de cierre, entonces el valor entre los paréntesis se trata como un nombre de elemento (que puede tener cualquier valor de cadena) y los caracteres antes del primer paréntesis de apertura se tratan como el nombre de una variable de array. Si name2 es NULL y name1 no se refiere a un elemento de array, significa que la variable es escalar o que el rastreo se establecerá en todo el array en lugar de en un elemento individual (consulte RASTREOS DE ARRAYS COMPLETOS a continuación para obtener más información).

ACCESO A VARIABLES DURANTE LOS RASTREOS

Durante los rastreos de lectura, escritura y array, el procedimiento de rastreo puede leer, escribir o anular la variable rastreada usando Tcl_GetVar2, Tcl_SetVar2 y otros procedimientos. Mientras proc se está ejecutando, los rastreos se deshabilitan temporalmente para la variable, de modo que las llamadas a Tcl_GetVar2 y Tcl_SetVar2 no provoquen que proc u otros procedimientos de rastreo se invoquen de nuevo. La deshabilitación solo ocurre para la variable cuyo procedimiento de rastreo está activo; los accesos a otras variables aún serán rastreados. Sin embargo, si una variable se anula durante un rastreo de lectura o escritura, se invocarán rastreos de anulación.

Durante los rastreos de anulación, la variable ya ha sido completamente eliminada. Es posible que el procedimiento de rastreo lea o escriba la variable, pero será una nueva versión de la variable. Los rastreos no se deshabilitan durante los rastreos de anulación, como sí lo hacen para los rastreos de lectura y escritura, pero los rastreos existentes se han eliminado de la variable antes de invocar cualquier procedimiento de rastreo. Si los rastreos nuevos son establecidos por procedimientos de rastreo de anulación, estos rastreos se invocarán en los accesos a la variable por parte de los procedimientos de rastreo.

TIEMPO DE LOS DEVOLUCIONES DE LLAMADA

Cuando se ha especificado un rastreo de lectura para una variable, el procedimiento de rastreo se invocará cada vez que se lea el valor de la variable. Esto incluye los comandos Tcl set, la notación de dólares ($) en comandos Tcl e invocaciones de los procedimientos Tcl_GetVar y Tcl_GetVar2. Proc se invoca justo antes de que se devuelva el valor de la variable. Puede modificar el valor de la variable para afectar lo que devuelve el acceso rastreado. Si anula la variable, el acceso devolverá un error como si la variable nunca hubiera existido.

Cuando se ha especificado un rastreo de escritura, el procedimiento de rastreo se invocará cada vez que se modifique el valor de la variable. Esto incluye los comandos set, los comandos que modifican variables como efectos secundarios (como catch y scan), y las llamadas a los procedimientos Tcl_SetVar y Tcl_SetVar2). Proc se invocará después de que se haya modificado el valor de la variable, pero antes de que se devuelva el nuevo valor de la variable. Puede modificar el valor de la variable para anular el cambio y determinar el valor que realmente devuelve el acceso rastreado. Si elimina la variable, el acceso rastreado devolverá una cadena vacía.

Cuando se ha especificado un rastreo de array, el procedimiento de rastreo se invocará al principio de la implementación del comando array, antes de que se invoquen las operaciones como get, set o names. El procedimiento de rastreo puede modificar los elementos del array con Tcl_SetVar y Tcl_SetVar2.

Cuando se ha especificado un rastreo de anulación, el procedimiento de rastreo se invocará cada vez que se destruya la variable. Las devoluciones de llamada de rastreo se invocarán después de que la variable se haya anulado completamente.

RASTREOS DE ARRAYS COMPLETOS

Si una llamada a Tcl_TraceVar o Tcl_TraceVar2 especifica el nombre de una variable de array sin un índice en el array, el rastreo se establecerá en el array en su conjunto. Esto significa que proc se invocará cada vez que se acceda a cualquier elemento del array de las maneras especificadas por flags. Cuando se anula un array, se invocará un rastreo de array completo una sola vez, con name1 igual al nombre del array y name2 NULL; no se invocará una vez por cada elemento.

RASTREOS MÚLTIPLES

Es posible que existan varios rastreos en la misma variable. Cuando esto sucede, todos los procedimientos de rastreo se invocarán en cada acceso, en orden desde el más recientemente creado hasta el menos recientemente creado. Cuando existen rastreos de arrays completos para un array, así como rastreos en elementos individuales, los rastreos de arrays completos se invocan antes que los rastreos de elementos individuales. Si un rastreo de lectura o escritura anula la variable, se invocarán todos los rastreos de anulación, pero se omitirán los rastreos de lectura y escritura restantes.

DEVOLUCIONES DE ERROR

En condiciones normales, los procedimientos de rastreo deben devolver NULL, lo que indica una finalización exitosa. Si proc devuelve un valor distinto de NULL, significa que ocurrió un error. El valor de retorno debe ser un puntero a una cadena de caracteres estática que contenga un mensaje de error, a menos que se establezca (exactamente una de) las banderas TCL_TRACE_RESULT_DYNAMIC y TCL_TRACE_RESULT_OBJECT, que especifican que el resultado es una cadena dinámica (que se liberará con ckfree) o un Tcl_Obj* (convertido a char* y que se liberará con Tcl_DecrRefCount) que contenga el mensaje de error. Si un procedimiento de rastreo devuelve un error, no se invocarán más rastreos para el acceso y el acceso rastreado abortará con el mensaje dado. Los procedimientos de rastreo pueden usar esta funcionalidad para hacer que las variables no sean modificables, por ejemplo (pero tenga en cuenta que el valor de la variable ya habrá sido modificado antes de llamar al procedimiento de rastreo, por lo que el procedimiento de rastreo tendrá que restaurar el valor correcto).

El valor de retorno de proc solo se utiliza durante los rastreos de lectura y escritura. Durante los rastreos de anulación, el valor de retorno se ignora y todos los procedimientos de rastreo relevantes siempre se invocarán.

RESTRICCIONES

Un procedimiento de rastreo puede ser llamado en cualquier momento, incluso cuando hay resultados parcialmente formados almacenados en el intérprete. Si el procedimiento de rastreo hace algo que pueda dañar este resultado (como llamar a Tcl_Eval) entonces debe usar las rutinas Tcl_SaveInterpState y relacionadas para guardar y restaurar el estado original del intérprete antes de devolver.

VARIABLES NO DEFINIDAS

Es legal establecer un rastreo en una variable no definida. La variable todavía parecerá no definida hasta la primera vez que se establezca su valor. Si se rastrea una variable no definida y luego se anula, la anulación fallará con un error ("no existe tal variable"), pero el procedimiento de rastreo aún se invocará.

BANDERA TCL_TRACE_DESTROYED

En una devolución de llamada de anulación a proc, el bit TCL_TRACE_DESTROYED se establece en flags si el rastreo se está eliminando como parte de la eliminación. Los rastreos de una variable siempre se eliminan cuando la variable se elimina; la única vez que TCL_TRACE_DESTROYED no se establece es para un rastreo de array completo invocado cuando solo se anula un solo elemento de un array.

TCL_INTERP_DESTROYED

Cuando se destruye un intérprete, se llaman los rastreos de anulación para todas sus variables. El bit TCL_INTERP_DESTROYED se establecerá en el argumento flags pasado a los procedimientos de rastreo. Los procedimientos de rastreo deben ser extremadamente cuidadosos en lo que hacen si el bit TCL_INTERP_DESTROYED está establecido. No es seguro que los procedimientos invoquen ningún procedimiento Tcl en el intérprete, ya que su estado está parcialmente eliminado. Todo lo que los procedimientos de rastreo deben hacer en estas circunstancias es limpiar y liberar sus propias estructuras de datos internas.

ERRORES

Tcl no realiza ninguna verificación de errores para evitar que los procedimientos de rastreo abusen del intérprete durante los rastreos con TCL_INTERP_DESTROYED establecido.

Los rastreos de arrays aún no están integrados con el comando Tcl info exists, ni hay acceso a nivel de Tcl para rastreos de arrays.

Tcl_UntraceVar(3)

NAME

Tcl_UntraceVar, Tcl_UntraceVar2, Tcl_TraceVar, Tcl_TraceVar2 - remove a variable trace

SYNOPSIS

#include <tcl.h>

void
Tcl_UntraceVar(
    Tcl_Interp *interp,
    const char *varName,
    int flags,
    Tcl_VarTraceProc *traceProc,
    ClientData clientData)

void
Tcl_UntraceVar2(
    Tcl_Interp *interp,
    const char *rootName,
    const char *elementName,
    int flags,
    Tcl_VarTraceProc *traceProc,
    ClientData clientData)

ARGUMENTS

interp (in)
Interpreter in which to remove the trace.
varName (in)
Name of the variable for which to remove the trace. May include array elements like name(index).
rootName (in)
Name of the variable (without array index).
elementName (in)
Index of the array element (e.g. “index” or NULL if not an array element).
flags (in)
Any combination of TCL_TRACE_READS, TCL_TRACE_WRITES, TCL_TRACE_UNSETS, TCL_TRACE_ARRAY. See Tcl_TraceVar(3) for details.
traceProc (in)
Procedure to remove from the trace list. Must match the procedure passed to Tcl_TraceVar.
clientData (in)
Arbitrary data associated with the trace. Must match the data passed to Tcl_TraceVar.

DESCRIPTION

The Tcl_UntraceVar and Tcl_UntraceVar2 functions remove traces that were previously added with Tcl_TraceVar or Tcl_TraceVar2.

Tcl_UntraceVar removes traces associated with the variable named varName. Tcl_UntraceVar2 removes traces associated with the variable named rootName and, if elementName is not NULL, with the array element given by elementName.

The flags argument specifies which types of operations should no longer trigger the trace. The traceProc and clientData arguments must match the values that were passed to Tcl_TraceVar or Tcl_TraceVar2 when the trace was created. If multiple traces were added for the same variable using the same traceProc and clientData, then calling Tcl_UntraceVar removes all of them. If a trace was added multiple times with different flags, then calling Tcl_UntraceVar with a subset of those flags will remove only the traces associated with those specific flags.

The trace will be removed from the list of active traces for the specified interpreter. If no matching trace is found, the function does nothing.

TWO-PART NAMES

Variables with names that contain the characters ( and ), such as array elements, are handled specially. Tcl_TraceVar handles these names as a single unit, whereas Tcl_TraceVar2 splits the name into a rootName and an elementName.

For example, if you want to trace array element myArray(1), you could call Tcl_TraceVar with varName = "myArray(1)", or you could call Tcl_TraceVar2 with rootName = "myArray" and elementName = "1".

When removing traces, you must use the same method (single name or two-part name) that was used to add the trace. For example, if you added a trace using Tcl_TraceVar with varName = "myArray(1)", you must remove it using Tcl_UntraceVar with varName = "myArray(1)". You cannot remove it using Tcl_UntraceVar2 with rootName = "myArray" and elementName = "1".

ACCESSING VARIABLES DURING TRACES

A trace procedure is invoked whenever a traced variable is read, written, or unset. The trace procedure is called with arguments describing the operation that occurred.

The trace procedure is called before the operation is actually performed. This allows the trace procedure to examine the variable’s current value and, in the case of writes, the new value. The trace procedure can modify the variable’s value, or it can prevent the operation entirely by returning a non-zero error code.

CALLBACK TIMING

Traces are invoked in the following order:

  1. Read traces are invoked in the order they were added.
  2. Write traces are invoked in the order they were added.
  3. Unset traces are invoked in the order they were added.

If an unset trace is invoked, the variable is unset immediately after the trace procedure returns.

WHOLE-ARRAY TRACES

If the TCL_TRACE_ARRAY flag is specified when adding a trace, the trace procedure will be called whenever the array variable itself is written or unset. This does not affect traces on individual array elements.

MULTIPLE TRACES

Multiple traces can be active for the same variable. The trace procedures will be called in the order in which the traces were added.

ERROR RETURNS

If a trace procedure returns a non-zero return code (indicating an error), the operation that triggered the trace is aborted, and the error code is propagated up to the caller of the command that initiated the variable access.

RESTRICTIONS

Trace procedures cannot modify the interpreter’s state in ways that would conflict with the operation being traced. For example, a read trace cannot modify the variable being read.

UNDEFINED VARIABLES

If a trace is set on a variable that does not yet exist, the trace will be activated when the variable is first created or written to. Read and unset traces will not be triggered until the variable exists.

TCL_TRACE_DESTROYED FLAG

The TCL_TRACE_DESTROYED flag is used internally by Tcl to manage traces. User code should not use this flag.

TCL_INTERP_DESTROYED

If the interpreter is destroyed while traces are still active, Tcl will automatically remove all active traces.

BUGS

None.
