ARGUMENTOS

Tcl_Interp *interp (entrada)
El intérprete donde se almacenarán los datos comprimidos o descomprimidos resultantes. También donde se escribirán los mensajes de error. Para Tcl_ZlibStreamInit, este puede ser NULL para crear un flujo que no esté vinculado a un comando.
int format (entrada)
Qué formato de datos comprimidos se va a utilizar. Debe ser uno de TCL_ZLIB_FORMAT_ZLIB para datos en formato zlib, TCL_ZLIB_FORMAT_GZIP para datos en formato gzip, o TCL_ZLIB_FORMAT_RAW para datos comprimidos sin procesar. Además, solo para descompresión, también se puede elegir TCL_ZLIB_FORMAT_AUTO, que puede detectar automáticamente si los datos comprimidos estaban en formato zlib o gzip.
Tcl_Obj *dataObj (entrada/salida)
Un valor de matriz de bytes que contiene los datos a comprimir o descomprimir, o al que se añaden los datos extraídos del flujo al pasar a Tcl_ZlibStreamGet.
int level (entrada)
Qué nivel de compresión usar. Debe ser un número de 0 a 9 o uno de los siguientes: TCL_ZLIB_COMPRESS_NONE para sin compresión, TCL_ZLIB_COMPRESS_FAST para compresión rápida pero ineficiente, TCL_ZLIB_COMPRESS_BEST para compresión lenta pero máxima, o TCL_ZLIB_COMPRESS_DEFAULT para el nivel recomendado por la biblioteca zlib.
Tcl_Obj *dictObj (entrada/salida)
Un diccionario que contiene, o que se actualizará para contener, una descripción de la cabecera gzip asociada con los datos comprimidos. Solo útil cuando el parámetro format es TCL_ZLIB_FORMAT_GZIP o TCL_ZLIB_FORMAT_AUTO. Si se pasa NULL, se usará una cabecera por defecto en la compresión y la cabecera se ignorará (aparte de las comprobaciones de integridad) en la descompresión. Consulte la sección DICCIONARIO DE OPCIONES GZIP para obtener detalles sobre el contenido de este diccionario.
unsigned int initValue (entrada)
El valor inicial para el algoritmo de suma de verificación.
int bufferSize (entrada)
Una indicación del tamaño del búfer que se va a utilizar para recibir los datos. Utilice 0 para usar una estimación genérica basada en los datos de entrada.
unsigned char *bytes (entrada)
Una matriz de bytes sobre la que ejecutar el algoritmo de suma de verificación, o NULL para obtener el valor inicial recomendado para el algoritmo de suma de verificación.
int length (entrada)
El número de bytes en la matriz.
int mode (entrada)
En qué modo operar el flujo. Debe ser TCL_ZLIB_STREAM_DEFLATE para un flujo de compresión o TCL_ZLIB_STREAM_INFLATE para un flujo de descompresión.
Tcl_ZlibStream *zshandlePtr (salida)
Un puntero a una variable en la que escribir el token abstracto para el flujo tras su creación exitosa.
Tcl_ZlibStream zshandle (entrada)
El token abstracto para el flujo sobre el que operar.
int flush (entrada)
Si y cómo vaciar el flujo después de escribirle los datos. Debe ser uno de: TCL_ZLIB_NO_FLUSH si no se debe realizar ningún vaciado, TCL_ZLIB_FLUSH si los datos comprimidos actualmente deben estar disponibles para su acceso mediante Tcl_ZlibStreamGet, TCL_ZLIB_FULLFLUSH si el flujo debe ponerse en un estado en el que el descompresor pueda recuperarse en caso de corrupción, o TCL_ZLIB_FINALIZE para garantizar que el flujo ha finalizado y que se escribe cualquier remolque exigido por el formato.
int count (entrada)
El número máximo de bytes a obtener del flujo, o -1 para obtener todos los bytes restantes de los búferes del flujo.
Tcl_Obj *compDict (entrada)
Un valor de matriz de bytes que es el diccionario de compresión a utilizar con el flujo. Tenga en cuenta que esto *no es un diccionario Tcl*, y se recomienda que solo se utilice con flujos que se crearon con su format establecido en TCL_ZLIB_FORMAT_ZLIB porque los otros formatos no tienen ningún mecanismo para indicar si estaba presente un diccionario de compresión, salvo fallar en la descompresión.

DESCRIPCIÓN

Estas funciones forman la interfaz de la biblioteca Tcl a la biblioteca Zlib de Jean-loup Gailly y Mark Adler.

Tcl_ZlibDeflate y Tcl_ZlibInflate respectivamente comprimen y descomprimen los datos contenidos en el argumento dataObj, de acuerdo con los argumentos format y, para la compresión, level. El diccionario en el parámetro dictObj se utiliza para transmitir información adicional de cabecera sobre los datos comprimidos cuando el formato de compresión lo admite; actualmente, el diccionario solo se utiliza cuando el parámetro format es TCL_ZLIB_FORMAT_GZIP o TCL_ZLIB_FORMAT_AUTO. Para obtener detalles sobre el contenido del diccionario, consulte la sección DICCIONARIO DE OPCIONES GZIP a continuación. Tras el éxito, ambas funciones dejan los datos comprimidos o descomprimidos resultantes en un valor de matriz de bytes que es el resultado del intérprete Tcl; el valor devuelto es un código de resultado Tcl estándar.

Tcl_ZlibAdler32 y Tcl_ZlibCRC32 calculan sumas de verificación sobre matrices de bytes, devolviendo la suma de verificación calculada. Las sumas de verificación se calculan incrementalmente, lo que permite procesar los datos bloque a bloque, pero esto requiere que el llamante mantenga la suma de verificación actual y la pase como parámetro initValue; el valor inicial a utilizar para esto se puede obtener utilizando NULL para el parámetro bytes en lugar de un puntero a la matriz de bytes sobre la que calcular la suma de verificación. Por lo tanto, el uso típico en el caso de un solo bloque de datos es el siguiente:

checksum = Tcl_ZlibCRC32(Tcl_ZlibCRC32(0,NULL,0), data, length);

Tenga en cuenta que el algoritmo Adler-32 no es una suma de verificación real, sino un tipo de hash relacionado que funciona mejor con datos largos.

FLUJOS ZLIB

Tcl_ZlibStreamInit crea un flujo de compresión o descompresión que está vinculado a un comando Tcl, de acuerdo con sus argumentos, y proporciona un token abstracto para el flujo y devuelve un código de resultado Tcl normal; Tcl_ZlibStreamGetCommandName devuelve el nombre de ese comando dado el token del flujo, o NULL si el flujo no tiene comando. Los flujos no están diseñados para ser seguros para hilos; cada flujo solo debe utilizarse desde el hilo que lo creó. Al trabajar con flujos gzip, se puede proporcionar un diccionario (campos según lo indicado en la sección DICCIONARIO DE OPCIONES GZIP) a través del parámetro dictObj que, en la compresión, permite controlar las cabeceras generadas, y en la descompresión, permite descubrir las cabeceras existentes. Tenga en cuenta que el diccionario se escribirá en la descompresión una vez que se hayan leído suficientes datos para tener una cabecera completa. Esto significa que el diccionario debe ser un valor no compartido en ese caso; se sugiere un valor en blanco creado con Tcl_NewObj.

Una vez construido un flujo, se utiliza Tcl_ZlibStreamPut para añadir datos al flujo y Tcl_ZlibStreamGet para recuperar datos del flujo después del procesamiento. Ambos devuelven códigos de resultado Tcl normales y dejan un mensaje de error en el resultado del intérprete al que está registrado el flujo (si se ha realizado dicha inscripción). Con Tcl_ZlibStreamPut, el valor del búfer de datos que se le pasa no debe modificarse después. Con Tcl_ZlibStreamGet, el valor del búfer de datos que se le pasa tendrá los bytes de datos añadidos. Internamente al flujo, los datos se mantienen comprimidos para minimizar el coste del espacio del búfer.

Tcl_ZlibStreamChecksum devuelve la suma de verificación calculada sobre los datos descomprimidos según el formato, y Tcl_ZlibStreamEof devuelve un valor booleano que indica si se ha llegado al final de los datos descomprimidos.

Tcl_ZlibStreamSetCompressionDictionary se utiliza para controlar el diccionario de compresión utilizado con el flujo. Un diccionario de compresión es un array de bytes (como los que se pueden crear con Tcl_NewByteArrayObj) que se utiliza para inicializar el motor de compresión en lugar de dejar que lo cree sobre la marcha a partir de los datos que se están comprimiendo. Establecer un diccionario de compresión permite una compresión más eficiente en el caso de que el inicio de los datos sea muy regular, pero requiere que tanto el compresor como el descompresor acuerden el valor a utilizar. Los diccionarios de compresión solo se admiten completamente para datos en formato zlib; en la compresión, deben establecerse antes de que se envíen datos con Tcl_ZlibStreamPut, y en la descompresión deben establecerse cuando Tcl_ZlibStreamGet produce un error con su -errorcode establecido en “ZLIB NEED_DICT código”; el código será la suma de verificación Adler-32 (ver Tcl_ZlibAdler32) del diccionario de compresión buscado. (Tenga en cuenta que esto solo es cierto para flujos en formato zlib; los flujos gzip ignoran los diccionarios de compresión ya que la especificación del formato no los permite, y los flujos raw simplemente producen un error de datos si el diccionario de compresión falta o es incorrecto).

Si desea borrar un flujo y reutilizarlo para una nueva acción de compresión o descompresión, Tcl_ZlibStreamReset lo hará y devolverá un código de resultado normal de Tcl para indicar si tuvo éxito; si el flujo está registrado con un intérprete, se dejará un mensaje de error en el resultado del intérprete cuando esta función devuelva TCL_ERROR. Finalmente, Tcl_ZlibStreamClose limpiará el flujo y eliminará el comando asociado: usar Tcl_DeleteCommand en el comando del flujo es equivalente (cuando dicho comando existe).

GZIP OPCIONES DICCIONARIO

El parámetro dictObj para Tcl_ZlibDeflate, Tcl_ZlibInflate y Tcl_ZlibStreamInit se utiliza para pasar un diccionario de opciones sobre cómo se describe la cabecera gzip en los datos comprimidos. Al crear datos comprimidos, se lee el diccionario y al desempaquetar datos comprimidos, se escribe el diccionario (en cuyo caso el parámetro dictObj debe referirse a un valor de diccionario no compartido).

Se entienden los siguientes campos en el valor del diccionario. Todos los demás campos se ignoran. No se requiere ningún campo al crear un flujo en formato gzip.

comment
Contiene el campo de comentario de la cabecera, si está presente. Si está ausente, no se proporcionó ningún comentario (en la descompresión) ni se creará (en la compresión).
crc
Un valor booleano que describe si se calcula una CRC de la cabecera. Tenga en cuenta que el programa gzip no utiliza ni permite una CRC en la cabecera.
filename
El nombre del archivo que contenía los datos sin comprimir. No debe contener separadores de directorio y debe limpiarse antes de usarse en la descompresión con file tail.
os
El campo del código del tipo de sistema operativo de la cabecera (si no es el valor “desconocido”). Ver RFC 1952 para el significado de estos códigos. En la compresión, si está ausente, el campo se establecerá en el valor “desconocido”.
size
El tamaño de los datos sin comprimir. Se ignora en la compresión; el tamaño de los datos comprimidos depende de cuántos datos se suministran al motor de compresión.
time
El campo de tiempo de la cabecera si es distinto de cero, se espera que sea la hora en que se modificó el archivo llamado por el campo filename. Adecuado para usar con clock format. Al crear, el valor correcto a usar es el de clock seconds o file mtime.
type
El tipo de los datos sin comprimir (ya sea binary o text) si se conoce.

NOTAS DE PORTABILIDAD

Estas funciones fallarán de forma controlada si Tcl no está enlazado con la biblioteca zlib.
