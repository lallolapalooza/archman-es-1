INTRODUCCIÓN

Esta página de manual presenta una introducción a los valores Tcl (llamados Tcl_Obj por razones históricas) y cómo se utilizan. También describe procedimientos generales para gestionar los valores Tcl. Estos procedimientos se utilizan para crear y copiar valores, e incrementar y decrementar el recuento de referencias (punteros) a los valores. Estos procedimientos se utilizan junto con otros que operan en tipos específicos de valores, como Tcl_GetIntFromObj y Tcl_ListObjAppendElement. Los procedimientos individuales se describen junto con las estructuras de datos que manipulan.

Los valores Tcl se representan de dos maneras: una caché y se calculan de forma perezosa. Es decir, cada representación se calcula solo cuando sea necesaria, se calcula a partir de la otra representación y, una vez calculada, se guarda. Además, un cambio en una representación invalida la otra. Por ejemplo, un programa Tcl que realiza cálculos enteros puede operar directamente sobre la representación entera interna de una variable sin tener que convertir constantes entre enteros y cadenas. Solo cuando se necesite una representación de cadena de la variable, por ejemplo, para imprimirla, el programa regenerará la representación de cadena a partir del entero. Aunque los valores contienen una representación interna, su semántica se define en términos de cadenas: siempre se puede obtener una representación actual, y cualquier cambio en el valor se reflejará en esa cadena cuando se obtenga la representación de cadena del valor. Debido a esta invalidación de representación y generación, es peligroso para los escritores de extensiones acceder directamente a los campos Tcl_Obj de los valores. Es mejor acceder a la información de Tcl_Obj utilizando procedimientos como Tcl_GetStringFromObj y Tcl_GetString.

Los valores se asignan en la memoria de la pila y se refieren mediante un puntero a la estructura Tcl_Obj. Los valores se comparten tanto como sea posible. Esto reduce significativamente los requisitos de almacenamiento, ya que algunos valores, como las listas largas, son muy grandes. Además, la mayoría de los valores Tcl se leen y nunca se modifican. Esto es especialmente cierto para los argumentos de los procedimientos, que pueden compartirse entre el llamador y el procedimiento llamado. La asignación y el enlace de argumentos se realizan simplemente asignando un puntero al valor. El recuento de referencias se utiliza para determinar cuándo es seguro recuperar el almacenamiento de un valor.

Los valores Tcl están tipados. La representación interna de un valor está controlada por su tipo. Varios tipos son predefinidos en el núcleo de Tcl, incluyendo entero, doble, lista y bytecode. Los escritores de extensiones pueden extender el conjunto de tipos definiendo sus propias estructuras Tcl_ObjType.

LA ESTRUCTURA DE TCL_OBJ

Cada valor Tcl se representa mediante una estructura Tcl_Obj que se define de la siguiente manera.

typedef struct Tcl_Obj {
    int refCount;
    char *bytes;
    int length;
    const Tcl_ObjType *typePtr;
    union {
        long longValue;
        double doubleValue;
        void *otherValuePtr;
        Tcl_WideInt wideValue;
        struct {
            void *ptr1;
            void *ptr2;
        } twoPtrValue;
        struct {
            void *ptr;
            unsigned long value;
        } ptrAndLongRep;
    } internalRep;
} Tcl_Obj;

Los miembros bytes y length juntos contienen la representación UTF-8 del valor, que es una cadena contada sin terminación nula (los nulos UTF-8 deben codificarse como una secuencia de dos bytes: 192, 128). bytes apunta al primer byte de la representación de cadena. El miembro length da el número de bytes. El array de bytes debe tener un byte nulo después del último byte de datos, en la posición length; esto permite tratar las representaciones de cadenas como cadenas C normales terminadas en nulo. Los programas C usan Tcl_GetStringFromObj y Tcl_GetString para obtener la representación de cadena de un valor. Si bytes es NULL, la representación de cadena no es válida.

El miembro typePtr apunta a la estructura Tcl_ObjType que describe el tipo. Si typePtr es NULL, la representación interna no es válida.

El miembro internalRep de la unión contiene la representación interna del valor. Esta es o un entero (long), un número de punto flotante de doble precisión, un puntero a un valor que contiene información adicional necesaria para representar el valor por el tipo del valor, un entero Tcl_WideInt, dos punteros arbitrarios o un par formado por un entero unsigned long y un puntero.

El miembro refCount se utiliza para determinar cuándo es seguro liberar el almacenamiento del valor. Almacena el número de referencias activas al valor. Mantener el recuento de referencias correcto es una responsabilidad clave para los escritores de extensiones. El recuento de referencias se discute más adelante en la sección MANEJO DEL ALMACENAMIENTO DE VALORES.

Aunque los escritores de extensiones pueden acceder directamente a los miembros de la estructura Tcl_Obj, es mejor utilizar los procedimientos y macros adecuados. Por ejemplo, los escritores de extensiones nunca deben leer ni actualizar refCount directamente; deberían usar macros como Tcl_IncrRefCount y Tcl_IsShared en su lugar.

Una propiedad clave de los valores Tcl es que poseen dos representaciones. Un valor típicamente comienza conteniendo solo una representación de cadena: no tiene tipo y tiene un typePtr nulo. Un valor que contiene una cadena vacía o una copia de una cadena especificada se crea utilizando Tcl_NewObj o Tcl_NewStringObj respectivamente. La representación de cadena del valor se obtiene con Tcl_GetStringFromObj o Tcl_GetString, y se modifica con Tcl_SetStringObj. Si posteriormente el valor se pasa a un procedimiento como Tcl_GetIntFromObj, que requiere una representación interna específica, el procedimiento creará una y establecerá el typePtr del valor. La representación interna se calcula a partir de la representación de cadena. Las dos representaciones de un valor son duales entre sí: los cambios en una se reflejan en la otra. Por ejemplo, Tcl_ListObjReplace modificará la representación interna de un valor y la siguiente llamada a Tcl_GetStringFromObj o Tcl_GetString reflejará ese cambio.

Las representaciones se recalculan de forma eficiente. Un cambio en una representación realizada por un procedimiento como Tcl_ListObjReplace no se refleja inmediatamente en la otra representación. En su lugar, la otra representación se marca como inválida para que se genere solo si es necesaria más tarde. Los programadores que implementan sus propios tipos de valores no deben preocuparse por cómo se realiza esto y simplemente deben usar procedimientos como Tcl_GetBooleanFromObj o Tcl_ListObjIndex. Los programadores que implementan sus propios tipos de valores deben comprobar las representaciones inválidas y marcarlas como inválidas cuando sea necesario. El procedimiento Tcl_InvalidateStringRep se utiliza para marcar la representación de cadena de un valor como inválida y liberar cualquier almacenamiento asociado con la antigua representación de cadena.

Los valores suelen mantener su tipo durante su vida, aunque a veces deben convertirse de un tipo a otro. Por ejemplo, un programa C puede construir una cadena en un valor mediante llamadas repetidas a Tcl_AppendToObj, y luego pasar el valor a un procedimiento como Tcl_GetIntFromObj, que requiere una representación interna específica. La representación interna se calcula a partir de la representación de cadena. Las dos representaciones de un valor son duales entre sí: los cambios en una se reflejan en la otra. Por ejemplo, Tcl_ListObjReplace modificará la representación interna de un valor y la siguiente llamada a Tcl_GetStringFromObj o Tcl_GetString reflejará ese cambio.

Las representaciones se recalculan de forma eficiente. Un cambio en una representación realizada por un procedimiento como Tcl_ListObjReplace no se refleja inmediatamente en la otra representación. En su lugar, la otra representación se marca como inválida para que se genere solo si es necesaria más tarde. Los programadores que implementan sus propios tipos de valores no deben preocuparse por cómo se realiza esto y simplemente deben usar procedimientos como Tcl_GetBooleanFromObj o Tcl_ListObjIndex. Los programadores que implementan sus propios tipos de valores deben comprobar las representaciones inválidas y marcarlas como inválidas cuando sea necesario. El procedimiento Tcl_InvalidateStringRep se utiliza para marcar la representación de cadena de un valor como inválida y liberar cualquier almacenamiento asociado con la antigua representación de cadena.

MANEJO DEL ALMACENAMIENTO DE LOS VALORES

Los valores Tcl se gestionan usando una técnica de recuento de referencias. Cada valor tiene un miembro refCount que almacena el número de punteros activos actualmente al valor. Cuando un valor se crea inicialmente, su refCount es 1. Los procedimientos que toman prestados punteros a valores Tcl deben incrementar el recuento de referencias del valor. Cuando un puntero ya no se necesita, el recuento de referencias debe decrementarse. Cuando el recuento de referencias de un valor alcanza cero, el valor es destruido y su almacenamiento se recupera.

Los procedimientos Tcl_IncrRefCount y Tcl_DecrRefCount se utilizan para manipular el recuento de referencias de un valor. Normalmente, se usan en pares: el código que adquiere un puntero a un valor llama a Tcl_IncrRefCount, y el código que libera el puntero llama a Tcl_DecrRefCount. Por ejemplo, cuando un procedimiento Tcl devuelve un nuevo valor, debe llamar a Tcl_IncrRefCount en el valor antes de devolverlo.

El procedimiento Tcl_DuplicateObj crea una copia de un valor Tcl. La copia tendrá su propio almacenamiento y un recuento de referencias inicial de 1. Esto es útil cuando se necesita modificar un valor que de otro modo se compartiría. El procedimiento Tcl_IsShared se puede usar para determinar si un valor está siendo compartido por más de un puntero (es decir, si refCount > 1).

Un programa C puede devolver un puntero a un valor Tcl que se crea internamente. El programa es responsable de establecer el recuento de referencias del valor a 1 antes de devolverlo. El código de Tcl que recibe el puntero (generalmente el intérprete que llama al procedimiento de extensión) incrementará el recuento de referencias para indicar que también está interesado en el valor.

A continuación se presenta un ejemplo de cómo gestionar los recuentos de referencias:

Tcl_Obj *myObjPtr;

// Crear un nuevo valor
myObjPtr = Tcl_NewStringObj("hola", 4);

// Registrar el valor con el intérprete Tcl (esto puede incrementar el refCount)
Tcl_ObjSetVar2(interp, Tcl_NewStringObj("myVar", 5), NULL, myObjPtr, 0);

// Como resultado de Tcl_ObjSetVar2, myObjPtr puede tener refCount > 1.
// Si queremos obtener un puntero seguro y poder modificarlo sin afectar
// el original en myVar, debemos duplicarlo.
if (Tcl_IsShared(myObjPtr)) {
    myObjPtr = Tcl_DuplicateObj(myObjPtr);
    // Ahora myObjPtr apunta a una copia, y su refCount es 1.
}

// Modificar la copia
Tcl_AppendToObj(myObjPtr, ", mundo!");

// ... usar la copia ...

// Liberar la copia cuando ya no se necesite
Tcl_DecrRefCount(myObjPtr);

En el ejemplo anterior, se crea un nuevo valor. Si el valor se establece como variable Tcl, su recuento de referencias se incrementará. Si se quiere modificar el valor sin afectar la variable original, primero se debe duplicar. Después de usar la copia, su recuento de referencias debe decrementarse.

El procedimiento Tcl_InvalidateStringRep se utiliza para marcar la representación de cadena de un valor como obsoleta y para liberar la memoria que la representa. Esto es útil cuando la representación interna de un valor cambia, pero la representación de cadena aún no se ha recalculado. Por ejemplo, si una lista se modifica, su representación de cadena ya no es válida y debe ser invalidada. Tcl llama automáticamente a Tcl_InvalidateStringRep en los valores siempre que sus representaciones internas se modifican.

PROCEDIMIENTOS

Tcl_NewObj, Tcl_DuplicateObj, Tcl_IncrRefCount, Tcl_DecrRefCount, Tcl_IsShared y Tcl_InvalidateStringRep se utilizan para gestionar valores Tcl y sus recuentos de referencias.

Tcl_NewObj
Crea un nuevo valor Tcl vacío y sin tipo. El recuento de referencias del nuevo valor se inicializa a 1. La representación de cadena del valor es una cadena vacía.
Tcl_DuplicateObj(objPtr)
Crea y devuelve un nuevo valor Tcl que es una copia exacta de objPtr. El recuento de referencias del nuevo valor se inicializa a 1. El valor original objPtr no se ve afectado, pero su recuento de referencias tampoco se ve alterado.
Tcl_IncrRefCount(objPtr)
Incrementa el recuento de referencias del valor al que apunta objPtr. Esto se debe utilizar cuando se crea un nuevo puntero a un valor que ya existe o se pasa un puntero a un procedimiento que puede conservarlo. Si se pasa un valor a un comando Tcl que lo conserva, o si un valor se pasa a un procedimiento de extensión que lo retiene, se debe incrementar su recuento de referencias.
Tcl_DecrRefCount(objPtr)
Decrementa el recuento de referencias del valor al que apunta objPtr. Si el recuento de referencias se reduce a cero, el valor se destruye y su almacenamiento se libera. Esto se debe utilizar cuando un puntero a un valor ya no es necesario. Por ejemplo, después de que un valor se ha utilizado en un comando, su recuento de referencias debe decrementarse, a menos que se vaya a reutilizar el valor o se esté conservando para su uso posterior.
Tcl_IsShared(objPtr)
Devuelve verdadero (1) si el valor al que apunta objPtr está siendo compartido por más de un puntero (es decir, si su recuento de referencias es mayor que 1), falso (0) en caso contrario.
Tcl_InvalidateStringRep(objPtr)
Marca la representación de cadena del valor al que apunta objPtr como inválida. También libera cualquier memoria previamente asignada para la representación de cadena. Esto se debe utilizar cuando se modifica la representación interna de un valor, de modo que la representación de cadena ya no es correcta. Tcl se encarga de llamar a este procedimiento internamente cuando sea necesario, pero los escritores de extensiones pueden necesitar llamarlo explícitamente si modifican directamente las representaciones internas de los valores.

DESCRIPTION

Tcl utiliza una representación de objetos para manejar los valores. Cada objeto tiene un tipo, una representación de cadena y potencialmente otras representaciones internas (por ejemplo, entera, doble, lista). Las representaciones de cadena se generan bajo demanda y se almacenan en caché en el objeto. Las representaciones internas, como la entera o la doble, se generan bajo demanda. Cuando se accede a un objeto, Tcl intenta acceder a la representación interna más adecuada. Por ejemplo, cuando se necesita una representación entera de un objeto, Tcl llama a Tcl_GetIntFromObj. Si el objeto ya tiene una representación entera, se devuelve. De lo contrario, Tcl intenta convertir la representación de cadena del objeto en una representación entera. Si la conversión tiene éxito, el objeto se actualiza con la nueva representación y su tipo se establece en el tipo entero.

El procedimiento Tcl_ConvertToType se puede utilizar para forzar que un objeto se convierta en un tipo específico. Si `typePtr` apunta a una estructura `Tcl_ObjType` válida, Tcl intentará convertir la representación interna del objeto al tipo especificado. Si `typePtr` es NULL, Tcl intentará eliminar la representación interna del objeto, dejando solo la representación de cadena. Esto se puede usar para liberar el almacenamiento ocupado por representaciones internas innecesarias.

Los procedimientos Tcl_IncrRefCount y Tcl_DecrRefCount se utilizan para gestionar las referencias a los objetos. Cuando se crea una nueva referencia a un objeto, se llama a Tcl_IncrRefCount para incrementar su recuento de referencias. Cuando una referencia ya no es necesaria, se llama a Tcl_DecrRefCount para disminuir el recuento. Si el recuento de referencias cae a cero, el objeto se libera. Esto permite compartir objetos de forma segura entre diferentes partes del sistema Tcl.

Tcl_IsShared devuelve verdadero si un objeto es compartido (es decir, tiene un recuento de referencias mayor que 1). Tcl_DuplicateObj crea una copia duplicada de un objeto. Si un objeto se comparte y se va a modificar, se debe duplicar primero para evitar afectar a otras referencias al objeto original.

Tcl_InvalidateStringRep marca la representación de cadena de un objeto como obsoleta. Esto fuerza la regeneración de la cadena la próxima vez que se acceda a ella. Tcl_UpdateStringOfObj actualiza la representación de cadena de un objeto a partir de su representación interna actual.

Tcl_GetObjectType devuelve el tipo actual de un objeto. Tcl_SetObjType establece el tipo de un objeto. Esto generalmente lo hacen los procedimientos de conversión de tipos cuando establecen una nueva representación interna para un objeto.

Tcl_FreeObj libera la memoria asociada a un objeto. Esto generalmente lo llama Tcl_DecrRefCount cuando el recuento de referencias de un objeto cae a cero.

EJEMPLO DE LA VIDA DE UN VALOR

Como ejemplo de la vida de un valor, considere la siguiente secuencia de comandos:

set x 123

Esto asigna a x un valor sin tipo cuyo miembro bytes apunta a 123 y cuyo miembro length contiene 3. El miembro typePtr del valor es NULL.

puts "x es $x"

La representación de cadena de x es válida (ya que bytes no es NULL) y se recupera para el comando.

incr x

El comando incr primero obtiene un entero del valor de x llamando a Tcl_GetIntFromObj. Este procedimiento comprueba si el valor ya es un valor entero. Como no lo es, convierte el valor estableciendo la representación interna del valor en el entero 123 y estableciendo el typePtr del valor para que apunte a la estructura de tipo entero Tcl_ObjType. Ambas representaciones son ahora válidas. incr incrementa la representación interna entera del valor y luego invalida su representación de cadena (llamando a Tcl_InvalidateStringRep) ya que la representación de cadena ya no corresponde a la representación interna.

puts "x es ahora $x"

Se necesita la representación de cadena del valor de x y se vuelve a calcular. La representación de cadena es ahora 124 y ambas representaciones son nuevamente válidas.

GESTIÓN DEL ALMACENAMIENTO DE VALORES

Los valores de Tcl se asignan en el heap y se comparten tanto como sea posible para reducir los requisitos de almacenamiento. Se utiliza el recuento de referencias para determinar cuándo un valor ya no es necesario y puede liberarse de forma segura. Un valor recién creado por Tcl_NewObj o Tcl_NewStringObj tiene refCount 0. La macro Tcl_IncrRefCount incrementa el recuento de referencias cuando se crea una nueva referencia al valor. La macro Tcl_DecrRefCount decrementa el recuento cuando una referencia ya no es necesaria y, si el recuento de referencias del valor cae a cero, libera su almacenamiento. Un valor compartido por diferentes códigos o estructuras de datos tiene refCount mayor que 1. Incrementar el recuento de referencias de un valor garantiza que no se liberará demasiado pronto ni que su valor cambiará accidentalmente.

Como ejemplo, el intérprete de bytecode comparte valores de argumentos entre procedimientos Tcl que llaman y que son llamados para evitar tener que copiar valores. Asigna los valores de los argumentos de la llamada a las variables de parámetros formales del procedimiento. Al hacerlo, llama a Tcl_IncrRefCount para incrementar el recuento de referencias de cada argumento, ya que ahora existe una nueva referencia a él desde el parámetro formal. Cuando el procedimiento llamado regresa, el intérprete llama a Tcl_DecrRefCount para decrementar el recuento de referencias de cada argumento. Cuando el recuento de referencias de un valor cae por debajo o igual a cero, Tcl_DecrRefCount recupera su almacenamiento. La mayoría de los procedimientos de comando no tienen que preocuparse por el recuento de referencias, ya que utilizan el valor de un valor inmediatamente y no retienen un puntero al valor después de que regresan. Sin embargo, si retienen un puntero a un valor en una estructura de datos, deben tener cuidado de incrementar su recuento de referencias, ya que el puntero retenido es una nueva referencia.

Los procedimientos de comando que modifican directamente los valores, como los de lappend y linsert, deben tener cuidado de copiar un valor compartido antes de cambiarlo. Primero deben verificar si el valor está compartido llamando a Tcl_IsShared. Si el valor está compartido, deben copiar el valor utilizando Tcl_DuplicateObj; esto devuelve un nuevo duplicado del valor original que tiene refCount 0. Si el valor no está compartido, el procedimiento de comando "posee" el valor y puede modificarlo directamente de forma segura. Por ejemplo, el siguiente código aparece en el procedimiento de comando que implementa linsert. Este procedimiento modifica el valor de la lista que se le pasa en objv[1] insertando objc-3 nuevos elementos antes de index.

listPtr = objv[1];
if (Tcl_IsShared(listPtr)) {
    listPtr = Tcl_DuplicateObj(listPtr);
}
result = Tcl_ListObjReplace(interp, listPtr, index, 0,
        (objc-3), &(objv[3]));

Como otro ejemplo, el procedimiento de comando de incr debe verificar si el valor de la variable está compartido antes de incrementar el entero en su representación interna. Si está compartido, necesita duplicar el valor para evitar cambiar accidentalmente los valores en otras estructuras de datos.
