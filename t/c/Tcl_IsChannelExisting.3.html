ARGUMENTOS

const Tcl_ChannelType *typePtr (entrada)
Punta a una estructura que contiene las direcciones de los procedimientos que se pueden llamar para realizar E/S y otras funciones en el canal.
const char *channelName (entrada)
El nombre de este canal, como por ejemplo file3; no debe estar en uso por ningún otro canal. Puede ser NULL, en cuyo caso el canal se crea sin nombre. Si al canal creado se le asignan uno de los canales estándar (stdin, stdout o stderr), el nombre del canal asignado será el nombre del canal estándar.
ClientData instanceData (entrada)
Valor arbitrario de una palabra para asociar con este canal. Este valor se pasa a los procedimientos en typePtr cuando se invocan.
int mask (entrada)
Combinación OR de TCL_READABLE y TCL_WRITABLE para indicar si un canal es legible y escribible.
Tcl_Channel channel (entrada)
El canal a operar.
int direction (entrada)
TCL_READABLE significa que se desea el manejador de entrada; TCL_WRITABLE significa que se desea el manejador de salida.
ClientData *handlePtr (salida)
Punta a la ubicación donde se debe almacenar el manejador específico del SO.
int size (entrada)
El tamaño, en bytes, de los búferes a asignar en este canal.
int mask (entrada)
Una combinación OR de TCL_READABLE, TCL_WRITABLE y TCL_EXCEPTION que indica los eventos que han ocurrido en este canal.
Tcl_Interp *interp (entrada)
Intérprete actual. (puede ser NULL)
const char *optionName (entrada)
Nombre de la opción inválida.
const char *optionList (entrada)
Lista de opciones específicas (palabras separadas por espacios, sin el guion) para añadir a la lista de opciones genéricas estándar. Puede ser NULL solo para el mensaje de error de opciones genéricas.

DESCRIPCIÓN

Tcl utiliza una arquitectura de canales de dos capas. Proporciona una capa superior genérica para permitir que los programas C y Tcl realicen entrada y salida utilizando las mismas API para una variedad de archivos, dispositivos, sockets, etc. Las API C genéricas se describen en la entrada del manual de Tcl_OpenFileChannel.

La capa inferior proporciona controladores de canales específicos del tipo para cada tipo de dispositivo admitido en cada plataforma. Esta entrada del manual describe las API C utilizadas para comunicarse entre la capa genérica y los controladores de canales específicos del tipo. También explica cómo se pueden agregar nuevos tipos de canales proporcionando nuevos controladores de canales.

Los controladores de canales constan de varios componentes: Primero, cada controlador de canales proporciona una estructura Tcl_ChannelType que contiene punteros a funciones que implementan las diversas operaciones utilizadas por la capa genérica para comunicarse con el controlador de canales. La estructura Tcl_ChannelType y las funciones a las que hace referencia se describen en la sección TCL_CHANNELTYPE, a continuación.

Segundo, los controladores de canales suelen proporcionar un comando Tcl para crear instancias de ese tipo de canal. Por ejemplo, el comando Tcl open crea canales que utilizan los controladores de canales de archivos y comandos, y el comando Tcl socket crea canales que utilizan sockets TCP para la comunicación en red.

Tercero, un controlador de canales opcionalmente proporciona una función C para abrir instancias de canal de ese tipo. Por ejemplo, Tcl_OpenFileChannel abre un canal que utiliza el controlador de canales de archivos, y Tcl_OpenTcpClient abre un canal que utiliza el protocolo de red TCP. Estas funciones de creación suelen utilizar Tcl_CreateChannel internamente para abrir el canal.

Para agregar un nuevo tipo de canal, debe implementar una API C o un comando Tcl que abra un canal invocando Tcl_CreateChannel. Cuando su controlador llame a Tcl_CreateChannel, pasará una estructura Tcl_ChannelType que describe los procedimientos de E/S del controlador. Luego, la capa genérica invocará las funciones referenciadas en esa estructura para realizar operaciones en el canal.

Tcl_CreateChannel abre un nuevo canal y asocia typePtr y instanceData con él. El canal se abre en el modo indicado por mask. Para una discusión de los controladores de canales, sus operaciones y la estructura Tcl_ChannelType, consulte la sección TCL_CHANNELTYPE, a continuación.

Tcl_CreateChannel interactúa con el código que administra los canales estándar. Una vez que un canal estándar se inicializó a través de una llamada a Tcl_GetStdChannel o una llamada a Tcl_SetStdChannel, cerrar este canal estándar hará que la próxima llamada a Tcl_CreateChannel convierta también el nuevo canal en el nuevo canal estándar. Consulte Tcl_StandardChannels para obtener un tratado general sobre los canales estándar y el comportamiento de la biblioteca Tcl con respecto a ellos.

Tcl_GetChannelInstanceData devuelve los datos de instancia asociados con el canal en channel. Esto es lo mismo que el argumento instanceData en la llamada a Tcl_CreateChannel que creó este canal.

Tcl_GetChannelType devuelve un puntero a la estructura Tcl_ChannelType utilizada por el canal en el argumento channel. Esto es lo mismo que el argumento typePtr en la llamada a Tcl_CreateChannel que creó este canal.

Tcl_GetChannelName devuelve una cadena que contiene el nombre asociado con el canal, o NULL si el argumento channelName de Tcl_CreateChannel era NULL.

Tcl_GetChannelHandle coloca el manejador de dispositivo específico del sistema operativo asociado con channel para la direction dada en el

TCL_GETCHANNELHANDLE

Devuelve el descriptor de dispositivo para la dirección especificada del canal dado por handlePtr y retorna TCL_OK. Si el canal no tiene un descriptor de dispositivo para la dirección especificada, entonces se retorna TCL_ERROR. Diferentes drivers de canal retornarán diferentes tipos de descriptor. Consulte las entradas del manual para cada driver para determinar qué tipo de descriptor se retorna.

Tcl_GetChannelThread retorna el id del hilo que está gestionando actualmente el channel especificado. Esto permite a los drivers de canal enviar sus eventos de archivo a la cola de eventos correcta, incluso para un núcleo multihilo.

Tcl_GetChannelMode retorna una combinación OR de TCL_READABLE y TCL_WRITABLE, indicando si el canal está abierto para entrada y salida.

Tcl_GetChannelBufferSize retorna el tamaño, en bytes, de los buffers asignados para almacenar entrada o salida en el channel. Si el valor no fue establecido por una llamada previa a Tcl_SetChannelBufferSize, descrita a continuación, entonces se retorna el valor predeterminado de 4096.

Tcl_SetChannelBufferSize establece el tamaño, en bytes, de los buffers que se asignarán en operaciones posteriores en el canal para almacenar entrada o salida. El argumento size debe estar entre uno y un millón, permitiendo buffers de un byte a un millón de bytes. Si size está fuera de este rango, Tcl_SetChannelBufferSize establece el tamaño del buffer en 4096.

Tcl_NotifyChannel es llamado por un driver de canal para indicar a la capa genérica que los eventos especificados por mask han ocurrido en el canal. Los drivers de canal son responsables de invocar esta función cada vez que los manejadores de canal necesiten ser llamados para el canal (o se deban realizar otras tareas pendientes como un vaciado de escritura). Ver WATCHPROC abajo para más detalles.

Tcl_BadChannelOption es llamado desde el setOptionProc o getOptionProc específico del driver para generar un mensaje de error completo.

Tcl_ChannelBuffered retorna el número de bytes de entrada actualmente almacenados en el buffer interno (área de retroceso) del propio canal. No informa sobre los datos en los buffers generales de la pila de canales de la que forma parte el canal proporcionado.

Tcl_IsChannelShared verifica el contador de referencias del channel especificado y retorna si el channel fue compartido entre múltiples intérpretes (resultado == 1) o no (resultado == 0).

Tcl_IsChannelRegistered verifica si el channel especificado está registrado en el interp o intérprete dado (resultado == 1) o no (resultado == 0).

Tcl_IsChannelExisting verifica si un canal con el nombre especificado está registrado en la lista global (del hilo) de todos los canales (resultado == 1) o no (resultado == 0).

Tcl_CutChannel elimina el channel especificado de la lista global (del hilo) de todos los canales (del hilo actual). No se permite la aplicación a un canal aún registrado en algún intérprete. También notifica al driver si la versión de Tcl_ChannelType es TCL_CHANNEL_VERSION_4 (o superior), y Tcl_DriverThreadActionProc está definida para él.

Tcl_SpliceChannel añade el channel especificado a la lista global (del hilo) de todos los canales (del hilo actual). No se permite la aplicación a un canal registrado en algún intérprete. También notifica al driver si la versión de Tcl_ChannelType es TCL_CHANNEL_VERSION_4 (o superior), y Tcl_DriverThreadActionProc está definida para él.

Tcl_ClearChannelHandlers elimina todos los manejadores de canal y scripts de eventos asociados con el channel especificado, cerrando así todo el procesamiento de eventos para este canal.

TCL_CHANNELTYPE

Un driver de canal proporciona una estructura Tcl_ChannelType que contiene punteros a funciones que implementan las diversas operaciones en un canal; estas operaciones se invocan según sea necesario por la capa genérica. La estructura fue versionada a partir de Tcl 8.3.2/8.4 para corregir un problema con los drivers de canal apilados. Ver la sección OLD CHANNEL TYPES abajo para detalles sobre la estructura antigua.

La estructura Tcl_ChannelType contiene los siguientes campos:

typedef struct Tcl_ChannelType {
        const char *typeName;
        Tcl_ChannelTypeVersion version;
        Tcl_DriverCloseProc *closeProc;
        Tcl_DriverInputProc *inputProc;
        Tcl_DriverOutputProc *outputProc;
        Tcl_DriverSeekProc *seekProc;
        Tcl_DriverSetOptionProc *setOptionProc;
        Tcl_DriverGetOptionProc *getOptionProc;
        Tcl_DriverWatchProc *watchProc;
        Tcl_DriverGetHandleProc *getHandleProc;
        Tcl_DriverClose2Proc *close2Proc;
        Tcl_DriverBlockModeProc *blockModeProc;
        Tcl_DriverFlushProc *flushProc;
        Tcl_DriverHandlerProc *handlerProc;
        Tcl_DriverWideSeekProc *wideSeekProc;
        Tcl_DriverThreadActionProc *threadActionProc;
        Tcl_DriverTruncateProc *truncateProc;
} Tcl_ChannelType;

No es necesario proporcionar implementaciones para todas las operaciones del canal. Aquellas que no son necesarias pueden establecerse en NULL en la estructura: blockModeProc, seekProc, setOptionProc, getOptionProc, getHandleProc y close2Proc, además de flushProc, handlerProc, threadActionProc y truncateProc. Otras funciones que no se pueden implementar de forma significativa deben retornar EINVAL al ser llamadas, para indicar que las operaciones que representan no están disponibles. Tenga en cuenta también que wideSeekProc puede ser NULL si seekProc lo es.

El usuario solo debe usar la estructura anterior para la instanciación de Tcl_ChannelType. Al referenciar campos en una estructura Tcl_ChannelType, se deben usar las siguientes funciones para obtener los valores: Tcl_ChannelName, Tcl_ChannelVersion, Tcl_ChannelBlockModeProc, Tcl_ChannelCloseProc, Tcl_ChannelClose2Proc, Tcl_ChannelInputProc, Tcl_ChannelOutputProc, Tcl_ChannelSeekProc, Tcl_ChannelWideSeekProc, Tcl_ChannelThreadActionProc, Tcl_ChannelTruncateProc, Tcl_ChannelSetOptionProc, Tcl_ChannelGetOptionProc, Tcl_ChannelWatchProc, Tcl_ChannelGetHandleProc, Tcl_ChannelFlushProc o Tcl_ChannelHandlerProc.

El cambio en las estructuras se realizó de tal manera que los tipos de canal estándar son binariamente compatibles. Sin embargo, los tipos de canal que utilizan canales apilados (es decir, TLS, Trf) tienen nuevas versiones para corresponder al cambio anterior, ya que el código anterior para canales apilados tenía problemas.

TYPENAME

El campo typeName contiene una cadena terminada en nulo que identifica el tipo del dispositivo implementado por este driver, por ejemplo, file o socket.

Este valor se puede recuperar con Tcl_ChannelName, que retorna un puntero a la cadena.

VERSION

El campo version debe establecerse en la versión de la estructura que necesita. TCL_CHANNEL_VERSION_2 es el mínimo recomendado. TCL_CHANNEL_VERSION_3 debe establecerse para especificar el miembro wideSeekProc. TCL_CHANNEL_VERSION_4 debe establecerse para especificar el miembro threadActionProc (incluye wideSeekProc). TCL_CHANNEL_VERSION_5 debe establecerse para especificar los miembros truncateProc (incluye wideSeekProc y threadActionProc). Si no se establece en ninguno de estos, entonces se asume que este Tcl_ChannelType tiene la estructura original. Ver OLD CHANNEL TYPES para más detalles. Si bien Tcl reconocerá y funcionará con ambas estructuras, los canales apilados deben ser de al menos TCL_CHANNEL_VERSION_2 para funcionar correctamente.

Este valor se puede recuperar con Tcl_ChannelVersion, que retorna uno de TCL_CHANNEL_VERSION_5, TCL_CHANNEL_VERSION_4, TCL_CHANNEL_VERSION_3, TCL_CHANNEL_VERSION_2 o TCL_CHANNEL_VERSION_1.

BLOCKMODEPROC

El campo blockModeProc contiene la dirección de una función llamada por la capa genérica para establecer el modo bloqueante y no bloqueante en el dispositivo. BlockModeProc debe coincidir con el siguiente prototipo:

typedef int Tcl_DriverBlockModeProc(
        ClientData instanceData,
        int mode);

El argumento instanceData es el mismo que el valor pasado a Tcl_CreateChannel cuando se creó este canal. El argumento mode es TCL_MODE_BLOCKING o TCL_MODE_NONBLOCKING para establecer el dispositivo en modo bloqueante o no bloqueante. La función debe retornar cero si la operación fue exitosa, o un código de error POSIX distinto de cero si la operación falló.

Si la operación es exitosa, la función puede modificar el instanceData proporcionado para registrar que el canal entró en modo bloqueante o no bloqueante y para implementar el comportamiento bloqueante o no bloqueante. Para algunos tipos de dispositivo, el comportamiento bloqueante y no bloqueante puede ser implementado por el sistema operativo subyacente; para otros tipos de dispositivo, el comportamiento debe ser emulado en el driver del canal.

Este valor se puede recuperar con Tcl_ChannelBlockModeProc, que retorna un puntero a la función.

Un driver de canal que **no** proporcione un blockModeProc debe ser muy, muy cuidadoso. Debe informar a la capa genérica exactamente qué modo bloqueante es aceptable para él, y también debe documentar esto para el usuario, de modo que el modo bloqueante del canal no se cambie a un valor inaceptable. Cualquier confusión aquí puede llevar al intérprete a un interbloqueo (falso y difícil de encontrar).

CLOSEPROC Y CLOSE2PROC

El campo closeProc contiene la dirección de una función llamada por la capa genérica para limpiar la información relacionada con el driver cuando el canal se cierra. CloseProc debe coincidir con el siguiente prototipo:

typedef int Tcl_DriverCloseProc(
        ClientData instanceData,
        Tcl_Interp *interp);

El argumento instanceData es el mismo que el valor proporcionado a Tcl_CreateChannel cuando se creó el canal. La función debe liberar cualquier almacenamiento mantenido por el driver del canal para este canal, y cerrar los dispositivos de entrada y salida encapsulados por este canal. Toda la salida en cola se habrá vaciado al dispositivo antes de que se llame a esta función, y no se invocarán más operaciones del driver sobre esta instancia después de llamar a closeProc. TCL_CHANNELTYPE STRUCT

The structure Tcl_ChannelType contains information about a channel driver. It is used to register new channel types with the Tcl interpreter.

typedef struct Tcl_ChannelType {
    const char *typeName;
    Tcl_DriverBlockModeProc *blockModeProc;
    Tcl_DriverCloseProc *closeProc;
    Tcl_DriverInputProc *inputProc;
    Tcl_DriverOutputProc *outputProc;
    Tcl_DriverSeekProc *seekProc;
    Tcl_DriverSetOptionProc *setOptionProc;
    Tcl_DriverGetOptionProc *getOptionProc;
    Tcl_DriverWatchProc *watchProc;
    Tcl_DriverGetHandleProc *getHandleProc;
    Tcl_DriverClose2Proc *close2Proc;
    Tcl_DriverBlockModeProc *blockModeProc;
    Tcl_DriverFlushProc *flushProc;
    Tcl_DriverHandlerProc *handlerProc;
    Tcl_DriverThreadActionProc *threadActionProc;
    Tcl_DriverTruncateProc *truncateProc;
} Tcl_ChannelType;

The fields in this structure are described below. Note that this is the current structure definition; earlier versions of Tcl had a different set of fields (see OLD CHANNEL TYPES below).

typeName
This field is the name of the channel type, used in error messages and for registering the type with Tcl_CreateChannelType.
blockModeProc
This field contains the address of the procedure to be called by the generic channel code to set the blocking mode of the channel. It can be NULL. The procedure should match the following prototype:
typedef int Tcl_DriverBlockModeProc(
        ClientData instanceData,
        int blockMode);

InstanceData is the same as the value passed to Tcl_CreateChannel when this channel was created. blockMode is either TCL_BLOCKING or TCL_NONBLOCKING. The procedure should return 0 on success and an error code (suitable for use with Tcl_SetErrno) on failure.

closeProc
This field contains the address of a procedure called by the generic layer to close the channel. It can be NULL, but this is generally not a good idea. The procedure should match the following prototype:
typedef int Tcl_DriverCloseProc(
        ClientData instanceData);

InstanceData is the same as the value passed to Tcl_CreateChannel when this channel was created. The procedure should perform any necessary cleanup for the channel, releasing any resources associated with it. It should return 0 on success or an error code (suitable for use with Tcl_SetErrno) on failure.

inputProc
This field contains the address of the procedure to be called by the generic layer to read input from the channel. It can be NULL. The procedure should match the following prototype:
typedef int Tcl_DriverInputProc(
        ClientData instanceData,
        char *buf,
        int bufSize,
        int *errorCodePtr);

InstanceData is the same as the value passed to Tcl_CreateChannel when this channel was created. The procedure should read up to bufSize bytes from the channel into the buffer pointed to by buf. It should return the number of bytes actually read. If an error occurs, the procedure should set errorCodePtr to the POSIX error code and return -1. If the channel is nonblocking and no input is available, it should return 0.

outputProc
This field contains the address of the procedure to be called by the generic layer to write output to the channel. It can be NULL. The procedure should match the following prototype:
typedef int Tcl_DriverOutputProc(
        ClientData instanceData,
        const char *buf,
        int toWrite,
        int *errorCodePtr);

InstanceData is the same as the value passed to Tcl_CreateChannel when this channel was created. The procedure should write up to toWrite bytes from the buffer pointed to by buf to the channel. It should return the number of bytes actually written. If an error occurs, the procedure should set errorCodePtr to the POSIX error code and return -1. If the channel is nonblocking and no output can be written, it should return 0.

seekProc
This field contains the address of the procedure to be called by the generic layer to seek on the channel. It can be NULL. The procedure should match the following prototype:
typedef int Tcl_DriverSeekProc(
        ClientData instanceData,
        Tcl_WideInt offset,
        int seekMode);

InstanceData is the same as the value passed to Tcl_CreateChannel when this channel was created. offset is the amount to seek, and seekMode is one of SEEK_SET, SEEK_CUR, or SEEK_END. The procedure should return the new file position on success, or -1 on failure. If an error occurs, the procedure should call Tcl_SetErrno to store an appropriate POSIX error code.

setOptionProc
This field contains the address of the procedure to be called by the generic layer to set an option on the channel. It can be NULL. The procedure should match the following prototype:
typedef int Tcl_DriverSetOptionProc(
        ClientData instanceData,
        const char *optionName,
        const Tcl_Obj *optionValue,
        Tcl_Interp *interp);

InstanceData is the same as the value passed to Tcl_CreateChannel when this channel was created. optionName and optionValue specify the option to set. The procedure should return TCL_OK on success or TCL_ERROR on failure. If an error occurs, the procedure should leave an error message in interp's result and call Tcl_SetErrno to store an appropriate POSIX error code.

getOptionProc
This field contains the address of the procedure to be called by the generic layer to get an option value from the channel. It can be NULL. The procedure should match the following prototype:
typedef int Tcl_DriverGetOptionProc(
        ClientData instanceData,
        const char *optionName,
        Tcl_Interp *interp);

InstanceData is the same as the value passed to Tcl_CreateChannel when this channel was created. optionName specifies the option to retrieve. The procedure should set the result in interp to the value of the option and return TCL_OK. If the option is not recognized or an error occurs, the procedure should return TCL_ERROR. If a system call error occurs, the function should leave an error message in the result of interp if interp is not NULL. The function should also call Tcl_SetErrno to store an appropriate POSIX error code.

Some options are handled by the generic code and this function is never called to retrieve their value, e.g. -blockmode. Other options are specific to each channel type and the getOptionProc procedure of the channel driver will get called to implement them. The getOptionProc field can be NULL, which indicates that this channel type supports no type specific options.

This value can be retrieved with Tcl_ChannelGetOptionProc, which returns a pointer to the function.

watchProc
The watchProc field contains the address of a function called by the generic layer to initialize the event notification mechanism to notice events of interest on this channel. WatchProc should match the following prototype:
typedef void Tcl_DriverWatchProc(
        ClientData instanceData,
        int mask);

The instanceData is the same as the value passed to Tcl_CreateChannel when this channel was created. The mask argument is an OR-ed combination of TCL_READABLE, TCL_WRITABLE and TCL_EXCEPTION; it indicates events the caller is interested in noticing on this channel.

The function should initialize device type specific mechanisms to notice when an event of interest is present on the channel. When one or more of the designated events occurs on the channel, the channel driver is responsible for calling Tcl_NotifyChannel to inform the generic channel module. The driver should take care not to starve other channel drivers or sources of callbacks by invoking Tcl_NotifyChannel too frequently. Fairness can be insured by using the Tcl event queue to allow the channel event to be scheduled in sequence with other events. See the description of Tcl_QueueEvent for details on how to queue an event.

This value can be retrieved with Tcl_ChannelWatchProc, which returns a pointer to the function.

getHandleProc
The getHandleProc field contains the address of a function called by the generic layer to retrieve a device-specific handle from the channel. GetHandleProc should match the following prototype:
typedef int Tcl_DriverGetHandleProc(
        ClientData instanceData,
        int direction,
        ClientData *handlePtr);

InstanceData is the same as the value passed to Tcl_CreateChannel when this channel was created. The direction argument is either TCL_READABLE to retrieve the handle used for input, or TCL_WRITABLE to retrieve the handle used for output.

If the channel implementation has device-specific handles, the function should retrieve the appropriate handle associated with the channel, according the direction argument. The handle should be stored in the location referred to by handlePtr, and TCL_OK should be returned. If the channel is not open for the specified direction, or if the channel implementation does not use device handles, the function should return TCL_ERROR.

This value can be retrieved with Tcl_ChannelGetHandleProc, which returns a pointer to the function.

close2Proc
This field contains the address of a procedure called by the generic layer to close the channel. It can be NULL. The procedure should match the following prototype:
typedef void Tcl_DriverClose2Proc(
        ClientData instanceData,
        Tcl_Interp *interp);

InstanceData is the same as the value passed to Tcl_CreateChannel when this channel was created. The procedure should perform any necessary cleanup for the channel, releasing any resources associated with it. It is called after the closeProc and should be used for cleanup that may require an interpreter.

blockModeProc
This field contains the address of the procedure to be called by the generic layer to set the blocking mode of the channel. It can be NULL. The procedure should match the following prototype:
typedef int Tcl_DriverBlockModeProc(
        ClientData instanceData,
        int blockMode);

InstanceData is the same as the value passed to Tcl_CreateChannel when this channel was created. blockMode is either TCL_BLOCKING or TCL_NONBLOCKING. The procedure should return 0 on success and an error code (suitable for use with Tcl_SetErrno) on failure.

Note: This is the second instance of this field in the structure definition. This is a documentation error and should be ignored.

flushProc
The flushProc field is currently reserved for future use. It should be set to NULL. FlushProc should match the following prototype:
typedef int Tcl_DriverFlushProc(
        ClientData instanceData);

This value can be retrieved with Tcl_ChannelFlushProc, which returns a pointer to the function.

handlerProc
The handlerProc field contains the address of a function called by the generic layer to notify the channel that an event occurred. It should be defined for stacked channel drivers that wish to be notified of events that occur on the underlying (stacked) channel. HandlerProc should match the following prototype:
typedef int Tcl_DriverHandlerProc(
        ClientData instanceData,
        int interestMask);

InstanceData is the same as the value passed to Tcl_CreateChannel when this channel was created. The interestMask is an OR-ed combination of TCL_READABLE or TCL_WRITABLE; it indicates what type of event occurred on this channel.

This value can be retrieved with Tcl_ChannelHandlerProc, which returns a pointer to the function.

threadActionProc
The threadActionProc field contains the address of the function called by the generic layer when a channel is created, closed, or going to move to a different thread, i.e. whenever thread-specific driver state might have to initialized or updated. It can be NULL. The action TCL_CHANNEL_THREAD_REMOVE is used to notify the driver that it should update or remove any thread-specific data it might be maintaining for the channel.

The action TCL_CHANNEL_THREAD_INSERT is used to notify the driver that it should update or initialize any thread-specific data it might be maintaining using the calling thread as the associate. See Tcl_CutChannel and Tcl_SpliceChannel for more detail.

typedef void Tcl_DriverThreadActionProc(
        ClientData instanceData,
        int action);

InstanceData is the same as the value passed to Tcl_CreateChannel when this channel was created.

These values can be retrieved with Tcl_ChannelThreadActionProc, which returns a pointer to the function.

truncateProc
The truncateProc field contains the address of the function called by the generic layer when a channel is truncated to some length. It can be NULL.
typedef int Tcl_DriverTruncateProc(
        ClientData instanceData,
        Tcl_WideInt length);

InstanceData is the same as the value passed to Tcl_CreateChannel when this channel was created, and length is the new length of the underlying file, which should not be negative. The result should be 0 on success or an errno code (suitable for use with Tcl_SetErrno) on failure.

These values can be retrieved with Tcl_ChannelTruncateProc, which returns a pointer to the function.

TCL_BADCHANNELOPTION

This procedure generates a “bad option” error message in an (optional) interpreter. It is used by channel drivers when an invalid Set/Get option is requested. Its purpose is to concatenate the generic options list to the specific ones and factorize the generic options error message string.

It always returns TCL_ERROR

An error message is generated in interp's result value to indicate that a command was invoked with a bad option. The message has the form

    bad option "blah": should be one of
    <...generic options...>+<...specific options...>
so you get for instance: 
    bad option "-blah": should be one of -blocking,
    -buffering, -buffersize, -eofchar, -translation,
    -peername, or -sockname
when called with optionList equal to “peername sockname”

“blah” is the optionName argument and “<specific options>” is a space separated list of specific option words. The function takes good care of inserting minus signs before each option, commas after, and an “or” before the last option.

OLD CHANNEL TYPES

The original (8.3.1 and below) Tcl_ChannelType structure contains the following fields:

typedef struct Tcl_ChannelType {
    const char *typeName;
    Tcl_DriverBlockModeProc *blockModeProc;
    Tcl_DriverCloseProc *closeProc;
    Tcl_DriverInputProc *inputProc;
    Tcl_DriverOutputProc *outputProc;
    Tcl_DriverSeekProc *seekProc;
    Tcl_DriverSetOptionProc *setOptionProc;
    Tcl_DriverGetOptionProc *getOptionProc;
    Tcl_DriverWatchProc *watchProc;
    Tcl_DriverGetHandleProc *getHandleProc;
    Tcl_DriverClose2Proc *close2Proc;
} Tcl_ChannelType;

It is still possible to create channel with the above structure. The internal channel code will determine the version. It is imperative to use the new Tcl_ChannelType structure if you are creating a stacked channel driver, due to problems with the earlier stacked channel implementation (in 8.2.0 to 8.3.1).

Prior to 8.4.0 (i.e. during the later releases of 8.3 and early part of the 8.4 development cycle) the Tcl_ChannelType structure contained the following fields:

typedef struct Tcl_ChannelType {
    const char *typeName;
    Tcl_ChannelTypeVersion version;
    Tcl_DriverCloseProc *closeProc;
    Tcl_DriverInputProc *inputProc;
    Tcl_DriverOutputProc *outputProc;
    Tcl_DriverSeekProc *seekProc;
    Tcl_DriverSetOptionProc *setOptionProc;
    Tcl_DriverGetOptionProc *getOptionProc;
    Tcl_DriverWatchProc *watchProc;
    Tcl_DriverGetHandleProc *getHandleProc;
    Tcl_DriverClose2Proc *close2Proc;
    Tcl_DriverBlockModeProc *blockModeProc;
    Tcl_DriverFlushProc *flushProc;
    Tcl_DriverHandlerProc *handlerProc;
    Tcl_DriverTruncateProc *truncateProc;
} Tcl_ChannelType;

When the above structure is registered as a channel type, the version field should always be TCL_CHANNEL_VERSION_2.
