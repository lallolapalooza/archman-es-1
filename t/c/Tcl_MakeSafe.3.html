DESCRIPCIÓN

Estos procedimientos están destinados al acceso a la instalación de múltiples intérpretes desde programas C. Permiten gestionar múltiples intérpretes en una relación jerárquica, y la gestión de alias, comandos que al ser invocados en un intérprete ejecutan un comando en otro intérprete. El valor de retorno para aquellos procedimientos que devuelven un int es ya sea TCL_OK o TCL_ERROR. Si se devuelve TCL_ERROR, el resultado del intérprete contiene un mensaje de error.

Tcl_CreateSlave crea un nuevo intérprete como hijo de interp. También crea un comando hijo llamado childName en interp que permite a interp manipular al nuevo hijo. Si isSafe es cero, el comando crea un hijo confiable en el que el código Tcl tiene acceso a todos los comandos Tcl. Si es 1, el comando crea un hijo “seguro” en el que el código Tcl tiene acceso solo a un conjunto de comandos Tcl definidos como “Safe Tcl”; consulte la entrada del manual del comando interp de Tcl para obtener más detalles. Si la creación del nuevo intérprete hijo falló, se devuelve NULL.

Tcl_CreateChild es un sinónimo de Tcl_CreateSlave.

Tcl_IsSafe devuelve 1 si interp es “seguro” (fue creado con el flag TCL_SAFE_INTERPRETER especificado), 0 en caso contrario.

Tcl_MakeSafe marca interp como “seguro”, de modo que las llamadas futuras a Tcl_IsSafe devuelvan 1. También elimina toda la funcionalidad central potencialmente insegura conocida (tanto comandos como variables) de interp. Sin embargo, no puede saber qué partes de una extensión o aplicación son seguras y no intenta eliminar esas partes, por lo que la seguridad no está garantizada después de llamar a Tcl_MakeSafe. Los llamadores deberán tener cuidado con su uso de Tcl_MakeSafe para evitar afirmaciones falsas de seguridad. Para muchas situaciones, Tcl_CreateSlave puede ser una mejor opción, ya que crea intérpretes en un estado de seguridad conocido.

Tcl_GetSlave devuelve un puntero a un intérprete hijo de interp. El intérprete hijo se identifica por childName. Si no existe tal intérprete hijo, se devuelve NULL.

Tcl_GetChild es un sinónimo de Tcl_GetSlave.

Tcl_GetMaster devuelve un puntero al intérprete maestro de interp. Si interp no tiene maestro (es un intérprete de nivel superior), se devuelve NULL.

Tcl_GetParent es un sinónimo de Tcl_GetMaster.

Tcl_GetInterpPath almacena en el resultado de interp la ruta relativa entre interp y childInterp; childInterp debe ser un hijo de interp. Si el cálculo de la ruta relativa tiene éxito, se devuelve TCL_OK, de lo contrario, se devuelve TCL_ERROR y se almacena un mensaje de error como resultado de interp.

Tcl_CreateAlias crea un comando llamado childCmd en childInterp que, cuando se invoca, hará que el comando targetCmd se invoque en targetInterp. Los argumentos especificados por las cadenas contenidas en argv siempre se anteponen a cualquier argumento proporcionado en la invocación de childCmd y se pasan a targetCmd. Esta operación devuelve TCL_OK si tiene éxito, o TCL_ERROR si falla; en ese caso, se deja un mensaje de error en el resultado de valor de childInterp. Tenga en cuenta que no hay restricciones en la relación de ascendencia (creada por Tcl_CreateSlave) entre childInterp y targetInterp. Se pueden utilizar dos intérpretes cualesquiera, sin restricciones sobre cómo están relacionados.

Tcl_CreateAliasObj es similar a Tcl_CreateAlias excepto que toma un vector de valores para pasar como argumentos adicionales en lugar de un vector de cadenas.

Tcl_GetAliasObj devuelve información en forma de un puntero a un vector de estructuras Tcl_Obj sobre un alias aliasName en interp. Cualquiera de los campos de resultado puede ser NULL, en cuyo caso no se devuelve el dato correspondiente. Si un campo de resultado no es NULL, se establece la dirección indicada al dato correspondiente. Por ejemplo, si targetCmdPtr no es NULL, se establece a un puntero a la cadena que contiene el nombre del comando de destino.

Tcl_GetAlias es similar a Tcl_GetAliasObj excepto que devuelve un puntero a un vector de cadenas en lugar de un vector de estructuras Tcl_Obj. Tcl_GetAlias está obsoleto

NAME

Tcl_MakeSafe, Tcl_MakeGlobal, Tcl_HideCommand, Tcl_ExposeCommand - manage command visibility in Tcl interpreters

SYNOPSIS

#include <tcl.h>

int
Tcl_MakeSafe(interp, cmdName, script)
Tcl_Interp *interp;
const char *cmdName;
const char *script;
int
Tcl_MakeGlobal(interp, cmdName, script)
Tcl_Interp *interp;
const char *cmdName;
const char *script;
int
Tcl_HideCommand(interp, cmdName, hiddenCmdName)
Tcl_Interp *interp;
const char *cmdName;
const char *hiddenCmdName;
int
Tcl_ExposeCommand(interp, hiddenCmdName, cmdName)
Tcl_Interp *interp;
const char *hiddenCmdName;
const char *cmdName;

ARGUMENTS

Tcl_Interp *interp (in)
Interpreter for which to create a new command.
const char *cmdName (in)
The name of the command to make safe or global.
const char *script (in)
The script to be executed when the new command is invoked.
const char *hiddenCmdName (in)
The name of the hidden command.
const char *cmdName (in)
The name of the exposed command.

DESCRIPTION

These functions manage the visibility and accessibility of commands within Tcl interpreters.

Tcl_MakeSafe creates a new command named cmdName in the interpreter interp. When this command is invoked, it will execute the script. The command created by Tcl_MakeSafe is a "safe" command. This means that its execution environment is restricted, preventing it from accessing sensitive Tcl commands or operations. This is useful for creating sandboxed environments or for defining commands that should have limited privileges. If a command named cmdName already exists, the operation returns TCL_ERROR and leaves an error message as the result of interp. If the operation succeeds, it returns TCL_OK.

Tcl_MakeGlobal is similar to Tcl_MakeSafe, but it creates a "global" command. Global commands have full access to the interpreter's capabilities, including potentially sensitive operations. This function should be used with caution, as it can expose the interpreter to security risks if the provided script is not trusted. If a command named cmdName already exists, the operation returns TCL_ERROR and leaves an error message as the result of interp. If the operation succeeds, it returns TCL_OK.

Tcl_HideCommand moves the command named cmdName from the set of exposed commands to the set of hidden commands, under the name hiddenCmdName. CmdName must be the name of an existing exposed command, or the operation will return TCL_ERROR and leave an error message as the result of interp. Currently both cmdName and hiddenCmdName must not contain namespace qualifiers, or the operation will return TCL_ERROR and leave an error message as the result of interp. The CmdName will be looked up in the global namespace, and not relative to the current namespace, even if the current namespace is not the global one. If a hidden command whose name is hiddenCmdName already exists, the operation also returns TCL_ERROR and an error message is left as the result of interp. If the operation succeeds, it returns TCL_OK. After executing this command, attempts to use cmdName in any script evaluation mechanism will fail.

Tcl_ExposeCommand moves the command named hiddenCmdName from the set of hidden commands to the set of exposed commands, putting it under the name cmdName. HiddenCmdName must be the name of an existing hidden command, or the operation will return TCL_ERROR and leave an error message as the result of interp. If an exposed command named cmdName already exists, the operation returns TCL_ERROR and leaves an error message as the result of interp. If the operation succeeds, it returns TCL_OK. After executing this command, attempts to use cmdName in any script evaluation mechanism will again succeed.

For a description of the Tcl interface to multiple interpreters, see interp(n).
