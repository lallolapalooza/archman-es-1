ARGUMENTOS

Tcl_Interp *interp (entrada)
Se utiliza para la notificación de errores y para buscar un canal registrado en él.
const char *fileName (entrada)
El nombre de un archivo local o de red.
const char *mode (entrada)
Especifica cómo se debe acceder al archivo. Puede tener cualquiera de los valores permitidos para el argumento mode del comando Tcl open.
int permissions (entrada)
Marcas de permisos estilo POSIX como 0644. Si se crea un archivo nuevo, estos permisos se establecerán en el archivo creado.
int argc (entrada)
El número de elementos en argv.
const char **argv (entrada)
Argumentos para construir una tubería de comandos. Estos valores tienen el mismo significado que los argumentos sin modificador del comando Tcl exec.
int flags (entrada)
Especifica la disposición de los manejadores stdio en la tubería: una combinación OR de TCL_STDIN, TCL_STDOUT, TCL_STDERR y TCL_ENFORCE_MODE. Si se establece TCL_STDIN, la entrada estándar para el primer hijo de la tubería es el canal de la tubería, de lo contrario es la misma que la entrada estándar del proceso invocador; lo mismo ocurre con TCL_STDOUT y TCL_STDERR. Si no se establece TCL_ENFORCE_MODE, la tubería puede redirigir los manejadores stdio para anular los manejadores stdio para los que se han establecido TCL_STDIN, TCL_STDOUT y TCL_STDERR. Si está establecido, tales redirecciones causan un error.
ClientData handle (entrada)
Manejador específico del sistema operativo para E/S a un archivo. Para Unix es un descriptor de archivo, para Windows es un HANDLE.

Combinación OR de TCL_READABLE y TCL_WRITABLE para indicar qué operaciones son válidas en handle.
const char *channelName (entrada)
El nombre del canal.

Un canal Tcl para entrada o salida. Debe haber sido el valor de retorno de un procedimiento como Tcl_OpenFileChannel.

Un puntero a un valor Tcl en el que se almacenarán los caracteres leídos del canal.
int charsToRead (entrada)
El número de caracteres a leer del canal. Si la codificación del canal es binary, esto es equivalente al número de bytes a leer del canal.
int appendFlag (entrada)
Si es distinto de cero, los datos leídos del canal se añadirán al valor. De lo contrario, los datos reemplazarán el contenido existente del valor.

Un búfer que contiene los bytes a enviar al canal.

El número de bytes a consumir de charBuf o byteBuf y enviar al canal.

DESCRIPCIÓN

El mecanismo de canales de Tcl proporciona un mecanismo independiente de dispositivos y de plataforma para realizar operaciones de entrada y salida con búfer en una variedad de tipos de archivos, sockets y dispositivos. El mecanismo de canales es extensible a nuevos tipos de canales, proporcionando un controlador de canal de bajo nivel para el nuevo tipo; la interfaz del controlador de canal se describe en la entrada del manual de Tcl_CreateChannel. El mecanismo de canales proporciona un esquema de búfer modelado después de la E/S estándar de Unix, y también permite la E/S no bloqueante en los canales.

Los procedimientos descritos en esta entrada del manual comprenden la capa genérica de la arquitectura de canales de las APIs de C. Para una descripción de la arquitectura del controlador de canal y cómo implementar controladores de canal para nuevos tipos de canales, consulte la entrada del manual de Tcl_CreateChannel.

TCL_OPENFILECHANNEL

Tcl_OpenFileChannel abre un archivo especificado por fileName y devuelve un manejador de canal que puede usarse para realizar entrada y salida en el archivo. Esta API está modelada después del procedimiento fopen de la biblioteca de E/S estándar de Unix. La sintaxis y el significado de todos los argumentos son similares a los proporcionados en el comando open de Tcl al abrir un archivo. Si ocurre un error al abrir el canal, Tcl_OpenFileChannel devuelve NULL y registra un código de error POSIX que se puede recuperar con Tcl_GetErrno. Además, si interp no es NULL, Tcl_OpenFileChannel deja un mensaje de error en el resultado de interp después de cualquier error. A partir de Tcl 8.4, se debe preferir la API basada en valores Tcl_FSOpenFileChannel sobre Tcl_OpenFileChannel siempre que sea posible.

El canal recién creado no se registra en el intérprete proporcionado; para registrarlo, use Tcl_RegisterChannel, descrito a continuación. Si uno de los canales estándar, stdin, stdout o stderr se cerró previamente, el acto de crear el nuevo canal también lo asigna como reemplazo del canal estándar.

TCL_OPENCOMMANDCHANNEL

Tcl_OpenCommandChannel proporciona una interfaz de nivel C a las funciones de los comandos exec y open. Crea una secuencia de subprocesos especificados por los argumentos argv y argc y devuelve un canal que se puede utilizar para comunicarse con estos subprocesos. El argumento flags indica qué tipo de comunicación existirá con la canalización de comandos.

Si el indicador TCL_STDIN está establecido, la entrada estándar del primer subproceso se vinculará al canal: escribir en el canal proporcionará entrada al subproceso. Si TCL_STDIN no está establecido, la entrada estándar del primer subproceso será la misma que la entrada estándar de esta aplicación. Si TCL_STDOUT está establecido, la salida estándar del último subproceso se puede leer del canal; de lo contrario, va a la salida estándar de esta aplicación. Si TCL_STDERR está establecido, la salida de error estándar de todos los subprocesos se devuelve al canal y resulta en un error cuando se cierra el canal; de lo contrario, va al error estándar de esta aplicación. Si TCL_ENFORCE_MODE no está establecido, entonces argc y argv pueden redirigir los manejadores de E/S para anular TCL_STDIN, TCL_STDOUT y TCL_STDERR; si está establecido, entonces es un error que argc y argv anulen los canales de E/S para los que se han establecido TCL_STDIN, TCL_STDOUT y TCL_STDERR.

Si ocurre un error al abrir el canal, Tcl_OpenCommandChannel devuelve NULL y registra un código de error POSIX que se puede recuperar con Tcl_GetErrno. Además, Tcl_OpenCommandChannel deja un mensaje de error en el resultado del intérprete. interp no puede ser NULL.

El canal recién creado no se registra en el intérprete proporcionado; para registrarlo, use Tcl_RegisterChannel, descrito a continuación. Si uno de los canales estándar, stdin, stdout o stderr se cerró previamente, el acto de crear el nuevo canal también lo asigna como reemplazo del canal estándar.

TCL_MAKEFILECHANNEL

Tcl_MakeFileChannel crea un Tcl_Channel a partir de un manejador de archivo existente y específico de la plataforma. El canal recién creado no se registra en el intérprete proporcionado; para registrarlo, use Tcl_RegisterChannel, descrito a continuación. Si uno de los canales estándar, stdin, stdout o stderr se cerró previamente, el acto de crear el nuevo canal también lo asigna como reemplazo del canal estándar.

TCL_GETCHANNEL

Tcl_GetChannel devuelve un canal dado el channelName utilizado para crearlo con Tcl_CreateChannel y un puntero a un intérprete de Tcl en interp. Si no hay un canal con ese nombre registrado en ese intérprete, el procedimiento devuelve NULL. Si el argumento modePtr no es NULL, apunta a una variable entera que recibirá una combinación OR de TCL_READABLE y TCL_WRITABLE que describe si el canal está abierto para lectura y escritura.

Tcl_GetChannelNames y Tcl_GetChannelNamesEx escriben los nombres de los canales registrados en el resultado del intérprete como un valor de lista. Tcl_GetChannelNamesEx filtrará estos nombres según el pattern. Si pattern es NULL, entonces no realizará ningún filtrado. El valor de retorno es TCL_OK si no ocurrieron errores al escribir en el resultado, de lo contrario, es TCL_ERROR, y el mensaje de error se deja en el resultado del intérprete.

TCL_REGISTERCHANNEL

Tcl_RegisterChannel agrega un canal al conjunto de canales accesibles en interp. Después de esta llamada, los programas Tcl que se ejecuten en ese intérprete podrán referirse al canal en operaciones de entrada o salida utilizando el nombre proporcionado en la llamada a Tcl_CreateChannel. Después de esta llamada, el canal se convierte en propiedad del intérprete, y el llamador no debe llamar a Tcl_Close para el canal; el canal se cerrará automáticamente cuando se desvincule del intérprete.

El código que se ejecuta fuera de cualquier intérprete Tcl puede llamar a Tcl_RegisterChannel con interp como NULL, para indicar que desea mantener una referencia a este canal. Posteriormente, el canal se puede registrar en un intérprete Tcl y solo se cerrará cuando se hayan realizado el número correspondiente de llamadas a Tcl_UnregisterChannel. Esto permite que el código que se ejecuta fuera de cualquier intérprete mantenga de forma segura una referencia a un canal que también está registrado en un intérprete Tcl.

Este procedimiento interactúa con el código que administra los canales estándar. Si no se inicializaron canales estándar antes de la primera llamada a Tcl_RegisterChannel, se inicializarán con esa llamada. Consulte Tcl_StandardChannels para un tratado general sobre los canales estándar y el comportamiento de la biblioteca Tcl con respecto a ellos.

TCL_UNREGISTERCHANNEL

Tcl_UnregisterChannel elimina un canal del conjunto de canales accesibles en interp. Después de esta llamada, los programas Tcl ya no podrán usar el nombre del canal para referirse al canal en ese intérprete. Si esta operación eliminó el último registro del canal en cualquier intérprete, el canal también se cierra y se destruye.

El código no asociado con un intérprete Tcl puede llamar a Tcl_UnregisterChannel con interp como NULL, para indicar a Tcl que ya no tiene una referencia a ese canal. Si esta es la última referencia al canal, ahora se cerrará. Tcl_UnregisterChannel es muy similar a Tcl_DetachChannel, excepto que también cerrará el canal si no existen más referencias a él.

TCL_DETACHCHANNEL

Tcl_DetachChannel elimina un canal del conjunto de canales accesibles en interp. Después de esta llamada, los programas Tcl ya no podrán usar el nombre del canal para referirse al canal en ese intérprete. Más allá de eso, este comando no tiene ningún efecto adicional. No se puede usar en los canales estándar (stdout, stderr, stdin) y devolverá TCL_ERROR si se le pasa uno de esos canales.

El código no asociado con un intérprete Tcl puede llamar a Tcl_DetachChannel con interp como NULL, para indicar a Tcl que ya no tiene una referencia a ese canal. Si esta es la última referencia al canal, a diferencia de Tcl_UnregisterChannel, no se cerrará.

TCL_ISSTANDARDCHANNEL

Tcl_IsStandardChannel prueba si un canal es uno de los tres canales estándar, stdin, stdout o stderr. Si es así, devuelve 1, de lo contrario, 0.

No se hace ningún intento de verificar si el canal dado o los canales estándar están inicializados o son válidos de otra manera.

TCL_CLOSE

Tcl_Close destruye el canal channel, que debe denotar un canal actualmente abierto. El canal no debe estar registrado en ningún intérprete cuando se llama a Tcl_Close. La salida en búfer se vacía en el dispositivo de salida del canal antes de destruir el canal, y cualquier entrada en búfer se descarta. Si este es un canal de bloqueo, la llamada no regresa hasta que todos los datos en búfer se envían correctamente al dispositivo de salida del canal. Si este es un canal sin bloqueo y hay salida en búfer que no se puede escribir sin bloquear, la llamada regresa inmediatamente; la salida se vacía en segundo plano y el canal se cerrará una vez que se hayan enviado todos los datos en búfer. En este caso, los errores durante el vaciado no se informan.

Si el canal se cerró correctamente, Tcl_Close devuelve TCL_OK. Si ocurre un error, Tcl_Close devuelve TCL_ERROR y registra un código de error POSIX que se puede recuperar con Tcl_GetErrno. Si el canal se está cerrando de forma síncrona y ocurre un error al cerrar el canal y interp no es NULL, se deja un mensaje de error en el resultado del intérprete.

Nota: no es seguro llamar a Tcl_Close en un canal que ha sido registrado usando Tcl_RegisterChannel; consulte la documentación de Tcl_RegisterChannel, arriba, para obtener detalles. Si el canal se ha proporcionado alguna vez como argumento chan en una llamada a Tcl_RegisterChannel, debe usar Tcl_UnregisterChannel en su lugar, que llamará internamente a Tcl_Close cuando todas las llamadas a Tcl_RegisterChannel hayan sido correspondidas por llamadas a Tcl_UnregisterChannel.

TCL_READCHARS Y TCL_READ

Tcl_ReadChars consume bytes del channel, convirtiendo los bytes a UTF-8 basándose en la codificación del canal y almacenando los datos producidos en la representación de cadena de readObjPtr. El valor de retorno de Tcl_ReadChars es el número de caracteres, hasta charsToRead, que se almacenaron en readObjPtr. Si ocurre un error al leer, el valor de retorno es -1 y Tcl_ReadChars registra un código de error POSIX que se puede recuperar con Tcl_GetErrno.

TCL_READCHARS, TCL_READOBJ, AND TCL_READ

Tcl_ReadChars lee como máximo charsToRead caracteres del canal especificado por channel y los almacena en el objeto Tcl representado por readObjPtr. Una llamada a Tcl_ReadChars con un valor de charsToRead de -1 hará que el comando lea todos los caracteres actualmente disponibles (no bloqueante) o todo hasta el fin de archivo (modo bloqueante).

El valor de retorno puede ser menor que el valor a leer, lo que indica que se dispuso de menos datos de los solicitados. Esto se llama una lectura corta. En modo bloqueante, esto solo puede suceder en un fin de archivo. En modo no bloqueante, una lectura corta también puede ocurrir si no hay suficiente entrada actualmente disponible: Tcl_ReadChars devuelve un recuento corto en lugar de esperar más datos.

Si el canal está en modo bloqueante, un valor de retorno de cero indica una condición de fin de archivo. Si el canal está en modo no bloqueante, un valor de retorno de cero indica que no hay entrada disponible actualmente o una condición de fin de archivo. Utilice Tcl_Eof y Tcl_InputBlocked para saber cuál de estas condiciones ocurrió realmente.

Tcl_ReadChars traduce las diversas representaciones de fin de línea a la representación interna canónica \n de acuerdo con el modo de reconocimiento de fin de línea actual. El reconocimiento de fin de línea y los diversos modos específicos de la plataforma se describen en la entrada del manual para el comando Tcl fconfigure.

Como optimización de rendimiento, al leer de un canal con la codificación binary, los bytes no se convierten a UTF-8 a medida que se leen. En su lugar, se almacenan en la representación interna de readObjPtr como un valor de arreglo de bytes. La representación de cadena de este valor solo se construirá si es necesaria (por ejemplo, debido a una llamada a Tcl_GetStringFromObj). De esta manera, los datos orientados a bytes se pueden leer de un canal, manipularlos llamando a Tcl_GetByteArrayFromObj y funciones relacionadas, y luego escribirlos en un canal sin el costo de convertirlos de o a UTF-8.

Tcl_Read es similar a Tcl_ReadChars, excepto que no realiza conversiones de codificación, independientemente de la codificación del canal. Está obsoleto y existe para compatibilidad retroactiva con extensiones Tcl no internacionalizadas. Consume bytes de channel y los almacena en readBuf, realizando traducciones de fin de línea en el camino. El valor de retorno de Tcl_Read es el número de bytes, hasta bytesToRead, escritos en readBuf. El búfer producido por Tcl_Read no está terminado en nulo. Su contenido es válido desde la posición cero hasta, y sin incluir, la posición indicada por el valor de retorno.

Tcl_ReadRaw es lo mismo que Tcl_Read pero no compensa el apilamiento. Mientras que Tcl_Read (y las otras funciones de la API) siempre obtienen sus datos del canal superior en la pila de la que forma parte el canal proporcionado, Tcl_ReadRaw no lo hace. Por lo tanto, esta función solo es utilizable para controladores de canal transformacionales, es decir, controladores utilizados en el medio de una pila de canales, para mover datos del canal inferior hacia la transformación.

TCL_GETSOBJ Y TCL_GETS

Tcl_GetsObj consume bytes del channel, convirtiendo los bytes a UTF-8 basándose en la codificación del canal, hasta que se haya visto una línea completa de entrada. Si la codificación del canal es binary, cada byte leído del canal se trata como un carácter Unicode individual. Todos los caracteres de la línea, excepto los caracteres de fin de línea terminadores, se agregan a la representación de cadena de lineObjPtr. Los caracteres de fin de línea se leen y se descartan.

Si se leyó una línea correctamente, el valor de retorno es mayor o igual a cero e indica el número de bytes almacenados en lineObjPtr. Si ocurre un error, Tcl_GetsObj devuelve -1 y registra un código de error POSIX que se puede recuperar con Tcl_GetErrno. Tcl_GetsObj también devuelve -1 si se llega al fin del archivo; el procedimiento Tcl_Eof se puede usar para distinguir un error de una condición de fin de archivo.

Si el canal está en modo no bloqueante, el valor de retorno puede ser -1 si no había datos disponibles o si los datos disponibles no contenían un carácter de fin de línea. Cuando se devuelve -1, el procedimiento Tcl_InputBlocked puede invocarse para determinar si el canal está bloqueado debido a la falta de entrada.

Tcl_Gets es lo mismo que Tcl_GetsObj excepto que los caracteres resultantes se agregan a la cadena dinámica dada por lineRead en lugar de un valor Tcl.

TCL_UNGETS

Tcl_Ungets se utiliza para agregar datos a la cola de entrada de un canal, ya sea al principio o al final de la cola. El puntero input apunta a los datos que se van a agregar. La longitud de la entrada a agregar está dada por inputLen. Un valor distinto de cero de addAtEnd indica que los datos se agregarán al final de la cola; de lo contrario, se agregarán al principio de la cola. Si channel tiene un EOF "pegajoso" establecido, no se agregarán datos a la cola de entrada. Tcl_Ungets devuelve inputLen o -1 si ocurre un error.

TCL_WRITECHARS, TCL_WRITEOBJ, Y TCL_WRITE

Tcl_WriteChars acepta bytesToWrite bytes de datos de carácter en charBuf. Los caracteres UTF-8 en el búfer se convierten a la codificación del canal y se ponen en cola para su salida al channel. Si bytesToWrite es negativo, Tcl_WriteChars espera que charBuf termine en nulo y emite todo hasta el nulo.

Los datos puestos en cola para la salida pueden no aparecer en el dispositivo de salida inmediatamente, debido al almacenamiento en búfer interno. Si los datos deben aparecer inmediatamente, llame a Tcl_Flush después de la llamada a Tcl_WriteChars, o establezca la opción -buffering en el canal a none. Si desea que los datos aparezcan tan pronto como se acepte una línea completa para la salida, establezca la opción -buffering en el canal en modo line.

El valor de retorno de Tcl_WriteChars es un recuento de cuántos bytes fueron aceptados para la salida al canal. Esto es mayor que cero para indicar éxito o -1 para indicar que ocurrió un error. Si ocurre un error, Tcl_WriteChars registra un código de error POSIX que puede recuperarse con Tcl_GetErrno.

Los caracteres de nueva línea en los datos de salida se traducen a secuencias de fin de línea específicas de la plataforma según la opción -translation para el canal. Esto se hace incluso si el canal no tiene codificación.

Tcl_WriteObj es similar a Tcl_WriteChars excepto que acepta un valor Tcl cuyos contenidos se emitirán al canal. Los caracteres UTF-8 en la representación de cadena de writeObjPtr se convierten a la codificación del canal y se ponen en cola para su salida al channel. Como optimización de rendimiento, al escribir en un canal con la codificación binary, los caracteres UTF-8 no se convierten a medida que se escriben. En su lugar, los bytes en la representación interna de writeObjPtr como un valor de arreglo de bytes se escriben en el canal. La representación de arreglo de bytes del valor se construirá si es necesaria. De esta manera, los datos orientados a bytes se pueden leer de un canal, manipularlos llamando a Tcl_GetByteArrayFromObj y funciones relacionadas, y luego escribirlos en un canal sin el costo de convertirlos de o a UTF-8.

Tcl_Write es similar a Tcl_WriteChars excepto que no realiza conversiones de codificación, independientemente de la codificación del canal. Está obsoleto y existe para compatibilidad retroactiva con extensiones Tcl no internacionalizadas. Acepta bytesToWrite bytes de datos en byteBuf y los pone en cola para su salida al channel. Si bytesToWrite es negativo, Tcl_Write espera que byteBuf termine en nulo y emite todo hasta el nulo.

Tcl_WriteRaw es lo mismo que Tcl_Write pero no compensa el apilamiento. Mientras que Tcl_Write (y las otras funciones de la API) siempre alimentan su entrada al canal superior en la pila de la que forma parte el canal proporcionado, Tcl_WriteRaw no lo hace. Por lo tanto, esta función solo es utilizable para controladores de canal transformacionales, es decir, controladores utilizados en el medio de una pila de canales, para mover datos de la transformación al canal inferior.

TCL_FLUSH

Tcl_Flush hace que todos los datos de salida en búfer del channel se escriban en su archivo o dispositivo subyacente tan pronto como sea posible. Si el canal está en modo bloqueante, la llamada no retorna hasta que todos los datos en búfer se hayan enviado al canal o haya ocurrido algún error. La llamada retorna inmediatamente si el canal no es bloqueante; inicia una operación de vaciado en segundo plano que escribirá los datos en búfer en el canal eventualmente, tan rápido como el canal pueda absorberlos.

El valor de retorno es normalmente TCL_OK. Si ocurre un error, Tcl_Flush devuelve TCL_ERROR y registra un código de error POSIX que puede recuperarse con Tcl_GetErrno.

TCL_SEEK

Tcl_Seek mueve el punto de acceso en el channel donde se leerán o escribirán datos posteriores. La salida en búfer se vacía al canal y la entrada en búfer se descarta, antes de la operación de búsqueda.

Tcl_Seek normalmente devuelve el nuevo punto de acceso. Si ocurre un error, Tcl_Seek devuelve -1 y registra un código de error POSIX que puede recuperarse con Tcl_GetErrno. Después de un error, el punto de acceso puede o no haberse movido.

TCL_TELL

Tcl_Tell devuelve el punto de acceso actual para un canal. El valor devuelto es -1 si el canal no admite la búsqueda.

TCL_TRUNCATECHANNEL

Tcl_TruncateChannel trunca el archivo subyacente del channel a una longitud dada de length bytes. Devuelve TCL_OK si la operación tuvo éxito, y TCL_ERROR en caso contrario.

TCL_GETCHANNELOPTION

Tcl_GetChannelOption recupera, en optionValue, el valor de una de las opciones actualmente en vigor para un canal, o una lista de todas las opciones y sus valores. El argumento channel identifica el canal para el que se consulta una opción o se recuperan todas las opciones y sus valores. Si optionName no es NULL, es el nombre de la opción a consultar; el valor de la opción se copia en la cadena dinámica Tcl denotada por optionValue. Si optionName es NULL, la función almacena una lista alterna de nombres de opciones y sus valores en optionValue,

TCL_GETCHANNELOPTION

Tcl_GetChannelOption returns the current value of option optionName for channel. The value is returned as a Tcl object in the interpreter's result. The procedure normally returns TCL_OK. If an error occurs, it returns TCL_ERROR and leaves an error message in the interpreter's result. If optionName is not a valid option for the channel, or if the option is not readable, an error occurs. The valid options for each channel are described in the manual entry for the Tcl command that creates a channel of that type; for example, the additional options for TCP-based channels are described in the manual entry for the Tcl socket command. The manual entry for the Tcl fconfigure command describes the options that are common to all Tcl channels. The procedure uses a Tcl_DString to build the value and then converts the Tcl_DString to a Tcl object. This is done to handle options that may return values represented by multiple elements, such as the -blocking option. The various preexisting options and their possible values are described in the manual entry for the Tcl fconfigure command. Other options can be added by each channel type. These channel type specific options are described in the manual entry for the Tcl command that creates a channel of that type; for example, the additional options for TCP-based channels are described in the manual entry for the Tcl socket command. The procedure normally returns TCL_OK. If an error occurs, it returns TCL_ERROR and calls Tcl_SetErrno to store an appropriate POSIX error code.

TCL_SETCHANNELOPTION

Tcl_SetChannelOption sets a new value newValue for an option optionName on channel. The procedure normally returns TCL_OK. If an error occurs, it returns TCL_ERROR; in addition, if interp is non-NULL, Tcl_SetChannelOption leaves an error message in the interpreter's result.

TCL_EOF

Tcl_Eof returns a nonzero value if channel encountered an end of file during the last input operation.

TCL_INPUTBLOCKED

Tcl_InputBlocked returns a nonzero value if channel is in nonblocking mode and the last input operation returned less data than requested because there was insufficient data available. The call always returns zero if the channel is in blocking mode.

TCL_INPUTBUFFERED

Tcl_InputBuffered returns the number of bytes of input currently buffered in the internal buffers for a channel. If the channel is not open for reading, this function always returns zero.

TCL_OUTPUTBUFFERED

Tcl_OutputBuffered returns the number of bytes of output currently buffered in the internal buffers for a channel. If the channel is not open for writing, this function always returns zero.

PLATFORM ISSUES

The handles returned from Tcl_GetChannelHandle depend on the platform and the channel type. On Unix platforms, the handle is always a Unix file descriptor as returned from the open system call. On Windows platforms, the handle is a file HANDLE when the channel was created with Tcl_OpenFileChannel, Tcl_OpenCommandChannel, or Tcl_MakeFileChannel. Other channel types may return a different type of handle on Windows platforms.
