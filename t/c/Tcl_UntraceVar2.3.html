Tcl_TraceVar(3) Tcl Library Procedures Tcl_TraceVar(3)

NOMBRE

Tcl_TraceVar, Tcl_TraceVar2, Tcl_UntraceVar, Tcl_UntraceVar2, Tcl_VarTraceInfo, Tcl_VarTraceInfo2 - monitorizar accesos a una variable

SINOPSIS

#include <tcl.h>

int
Tcl_TraceVar(interp, varName, flags, proc, clientData)

int
Tcl_TraceVar2(interp, name1, name2, flags, proc, clientData)

Tcl_UntraceVar(interp, varName, flags, proc, clientData)

Tcl_UntraceVar2(interp, name1, name2, flags, proc, clientData)

ClientData
Tcl_VarTraceInfo(interp, varName, flags, proc, prevClientData)

ClientData
Tcl_VarTraceInfo2(interp, name1, name2, flags, proc, prevClientData)

ARGUMENTOS

Tcl_Interp *interp (entrada)
Intérprete que contiene la variable.
const char *varName (entrada)
Nombre de la variable. Puede referirse a una variable escalar, a una variable de array sin índice, o a una variable de array con un índice entre paréntesis.
int flags (entrada)
Combinación OR de los valores TCL_TRACE_READS, TCL_TRACE_WRITES, TCL_TRACE_UNSETS, TCL_TRACE_ARRAY, TCL_GLOBAL_ONLY, TCL_NAMESPACE_ONLY, TCL_TRACE_RESULT_DYNAMIC y TCL_TRACE_RESULT_OBJECT. No todos los flags son usados por todos los procedimientos. Ver más abajo para más información.
Tcl_VarTraceProc *proc (entrada)
Procedimiento a invocar cada vez que ocurra una de las operaciones rastreadas.
ClientData clientData (entrada)
Valor arbitrario de una palabra para pasar a proc.
const char *name1 (entrada)
Nombre de la variable escalar o de array (sin el índice del array).
const char *name2 (entrada)
Para un rastreo en un elemento de un array, da el índice del elemento. Para rastreos en variables escalares o en arrays completos, es NULL.
ClientData prevClientData (entrada)
Si no es NULL, da el último valor devuelto por Tcl_VarTraceInfo o Tcl_VarTraceInfo2, por lo que esta llamada devolverá información sobre el siguiente rastreo. Si es NULL, esta llamada devolverá información sobre el primer rastreo.

DESCRIPCIÓN

Tcl_TraceVar permite a un procedimiento C monitorizar y controlar el acceso a una variable Tcl, de forma que el procedimiento C sea invocado cada vez que la variable sea leída, escrita o desestablecida. Si el rastreo se crea con éxito, Tcl_TraceVar devuelve TCL_OK. Si ocurrió un error (p.ej., varName especifica un elemento de un array, pero la variable real no es un array), entonces se devuelve TCL_ERROR y se deja un mensaje de error en el resultado del intérprete.

El argumento flags a Tcl_TraceVar indica cuándo se invocará el procedimiento de rastreo y proporciona información para configurar el rastreo. Consiste en una combinación OR de cualquiera de los siguientes valores:

TCL_GLOBAL_ONLY
Normalmente, la variable se buscará en el nivel actual de llamada a procedimiento; si este bit está establecido, la variable se buscará en el nivel global, ignorando cualquier procedimiento activo.
TCL_NAMESPACE_ONLY
Normalmente, la variable se buscará en el nivel actual de llamada a procedimiento; si este bit está establecido, la variable se buscará en el namespace actual, ignorando cualquier procedimiento activo.
TCL_TRACE_READS
Invoca proc cada vez que se intenta leer la variable.
TCL_TRACE_WRITES
Invoca proc cada vez que se intenta modificar la variable.
TCL_TRACE_UNSETS
Invoca proc cada vez que la variable es desestablecida. Una variable puede ser desestablecida explícitamente mediante un comando unset, o implícitamente cuando un procedimiento retorna (sus variables locales son desestablecidas automáticamente) o cuando el intérprete es eliminado (todas las variables son desestablecidas automáticamente).
TCL_TRACE_ARRAY
Invoca proc cada vez que se invoca el comando array. Esto le da al procedimiento de rastreo la oportunidad de actualizar el array antes de que se llamen array names o array get. Nótese que esto se llama antes de un array set, pero eso activará los rastreos de escritura.
TCL_TRACE_RESULT_DYNAMIC
El resultado de invocar proc es una cadena asignada dinámicamente que será liberada por la biblioteca Tcl mediante una llamada a ckfree. No debe especificarse al mismo tiempo que TCL_TRACE_RESULT_OBJECT.
TCL_TRACE_RESULT_OBJECT
El resultado de invocar proc es un Tcl_Obj* (convertido a char*) con un contador de referencias de al menos uno. La propiedad de esa referencia se transferirá al núcleo de Tcl para su liberación (cuando el núcleo haya terminado con él) mediante una llamada a Tcl_DecrRefCount. No debe especificarse al mismo tiempo que TCL_TRACE_RESULT_DYNAMIC.

Cada vez que ocurra una de las operaciones especificadas en la variable, se invocará proc. Debe tener argumentos y un resultado que coincidan con el tipo Tcl_VarTraceProc:

typedef char *Tcl_VarTraceProc(
        ClientData clientData,
        Tcl_Interp *interp,
        const char *name1,
        const char *name2,
        int flags);

Los parámetros clientData e interp tendrán los mismos valores que los pasados a Tcl_TraceVar cuando se creó el rastreo. ClientData típicamente apunta a una estructura de datos específica de la aplicación que describe qué hacer cuando se invoca proc. Name1 y name2 dan el nombre de la variable rastreada en la forma normal de dos partes (ver la descripción de Tcl_TraceVar2 abajo para detalles). Flags es una combinación OR de bits que proporciona varias piezas de información. Uno de los bits TCL_TRACE_READS, TCL_TRACE_WRITES, TCL_TRACE_ARRAY, o TCL_TRACE_UNSETS se establecerá en flags para indicar qué operación se está realizando en la variable. El bit TCL_GLOBAL_ONLY se establecerá siempre que la variable que se está accediendo sea una variable global no accesible desde el nivel actual de llamada a procedimiento: el procedimiento de rastreo deberá pasar este flag de vuelta a procedimientos relacionados con variables como Tcl_GetVar si intenta acceder a la variable. El bit TCL_NAMESPACE_ONLY se establecerá siempre que la variable que se está accediendo sea una variable de namespace no accesible desde el nivel actual de llamada a procedimiento: el procedimiento de rastreo deberá pasar este flag de vuelta a procedimientos relacionados con variables como Tcl_GetVar si intenta acceder a la variable. El bit TCL_TRACE_DESTROYED se establecerá en flags si el rastreo está a punto de ser destruido; esta información puede ser útil para proc para que pueda limpiar sus propias estructuras de datos internas (ver la sección TCL_TRACE_DESTROYED abajo para más detalles). Finalmente, el bit TCL_INTERP_DESTROYED se establecerá si el intérprete completo está siendo destruido. Cuando este bit se establece, proc debe tener especial cuidado en las cosas que hace (ver la sección TCL_INTERP_DESTROYED abajo). El valor de retorno del procedimiento de rastreo normalmente debería ser NULL; ver ERROR RETURNS abajo para información sobre otras posibilidades.

Tcl_UntraceVar puede usarse para eliminar un rastreo. Si la variable especificada por interp, varName y flags tiene un rastreo establecido con flags, proc y clientData, entonces se elimina el rastreo correspondiente. Si no existe tal rastreo, la llamada a Tcl_UntraceVar no tiene efecto. Los mismos bits son válidos para flags que para las llamadas a Tcl_TraceVar.

Tcl_VarTraceInfo puede usarse para recuperar información sobre los rastreos establecidos en una variable dada. El valor de retorno de Tcl_VarTraceInfo es el clientData asociado con un rastreo particular. El rastreo debe estar en la variable especificada por los argumentos interp, varName y flags (solo se utilizan los bits TCL_GLOBAL_ONLY y TCL_NAMESPACE_ONLY de flags; se ignoran otros bits) y su procedimiento de rastreo debe ser el mismo que el argumento proc. Si el argumento prevClientData es NULL, entonces el valor de retorno corresponde al primer rastreo coincidente (el creado más recientemente), o NULL si no hay coincidencias.

Tcl_TraceVar2 y Tcl_UntraceVar2 son similares a Tcl_TraceVar y Tcl_UntraceVar, respectivamente, excepto que le permiten especificar un nombre de variable en dos partes. Esto es útil para rastrear elementos de arrays o variables que contienen caracteres especiales.

Tcl_VarTraceInfo2 es similar a Tcl_VarTraceInfo, excepto que utiliza la especificación de nombre de dos partes de Tcl_TraceVar2.

El procedimiento de rastreo proc debe ser capaz de manejar las siguientes condiciones de error:

TCL_TRACE_DESTROYED
Este bit se establecerá en el argumento flags si el rastreo está a punto de ser destruido. Por ejemplo, si el usuario ejecuta un comando unset en la variable o si el intérprete se está eliminando. En esta circunstancia, proc debería realizar cualquier limpieza necesaria para sus propias estructuras de datos internas. Si se establece TCL_TRACE_DESTROYED, entonces el valor de retorno de proc es ignorado.
TCL_INTERP_DESTROYED
Este bit se establecerá en el argumento flags si el intérprete completo se está destruyendo. Cuando este bit está establecido, proc debe ser extremadamente cuidadoso en las acciones que realiza. Por ejemplo, no debería intentar acceder a ninguna variable o llamar a ninguna función Tcl que pueda acceder a variables, ya que podrían haber sido desvinculadas. El valor de retorno de proc se ignora en esta circunstancia.

Si proc devuelve un valor distinto de NULL, entonces ese valor se convierte en el nuevo valor de la variable. Si el tipo de datos del valor devuelto es incompatible con el tipo de datos de la variable, entonces se genera un error.

Si el procedimiento de rastreo devuelve un puntero a una cadena, se asume que la cadena es una copia de la cadena original y que ha sido asignada dinámicamente. Tcl se encargará de liberar la memoria de esta cadena. Si se especifica el flag TCL_TRACE_RESULT_DYNAMIC, el valor de retorno debe ser de este tipo. Si se especifica el flag TCL_TRACE_RESULT_OBJECT, el valor de retorno debe ser un puntero a un Tcl_Obj, y Tcl se encargará de decrementar su contador de referencias.

En caso de error al intentar establecer un rastreo, Tcl_TraceVar y Tcl_TraceVar2 devuelven TCL_ERROR y dejan un mensaje de error en el resultado del intérprete. En caso de éxito, devuelven TCL_OK.

La llamada a Tcl_UntraceVar y Tcl_UntraceVar2 siempre tiene éxito y devuelve void.

La llamada a Tcl_VarTraceInfo y Tcl_VarTraceInfo2 devuelve el clientData asociado con el rastreo solicitado, o NULL si no se encuentra ningún rastreo coincidente.

NOMBRE

Tcl_TraceVar, Tcl_UntraceVar, Tcl_VarTraceInfo, Tcl_TraceVar2, Tcl_UntraceVar2, Tcl_VarTraceInfo2 - registrar procedimientos de rastreo para variables Tcl

SINOPSIS

#include <tcl.h>

    Tcl_Interp *interp,
    const char *varName,
    int mask,
    Tcl_VarTraceProc *proc,
    ClientData clientData)

    Tcl_Interp *interp,
    const char *varName,
    int mask,
    Tcl_VarTraceProc *proc,
    ClientData clientData)

ClientData
Tcl_VarTraceInfo(
    Tcl_Interp *interp,
    const char *varName,
    int mask,
    Tcl_VarTraceProc *proc,
    ClientData prevClientData)

int
Tcl_TraceVar2(
    Tcl_Interp *interp,
    const char *name1,
    const char *name2,
    int mask,
    Tcl_VarTraceProc *proc,
    ClientData clientData)

int
Tcl_UntraceVar2(
    Tcl_Interp *interp,
    const char *name1,
    const char *name2,
    int mask,
    Tcl_VarTraceProc *proc,
    ClientData clientData)

ClientData
Tcl_VarTraceInfo2(
    Tcl_Interp *interp,
    const char *name1,
    const char *name2,
    int mask,
    Tcl_VarTraceProc *proc,
    ClientData prevClientData)

DESCRIPCIÓN

Estas procedimientos permiten que las aplicaciones C registren procedimientos de devolución de llamada (callbacks) que se invocarán automáticamente cuando se acceda o modifique una variable Tcl específica. Las variables Tcl se pueden rastrear para leer, escribir, eliminar o para cambios en matrices enteras. Las máscaras de bits mask especifican qué tipos de accesos activarán el rastreo; puede ser una combinación OR bit a bit de los siguientes valores:

  • TCL_TRACE_READ: El rastreo se activará cuando se lea el valor de la variable.
  • TCL_TRACE_WRITE: El rastreo se activará cuando se modifique el valor de la variable.
  • TCL_TRACE_UNSET: El rastreo se activará cuando la variable sea eliminada.
  • TCL_TRACE_ARRAY: El rastreo se activará cuando se acceda a cualquier elemento de un array.

El procedimiento proc tiene la siguiente interfaz:

void
Tcl_VarTraceProc(
    ClientData clientData,
    Tcl_Interp *interp,
    const char *name1,
    const char *name2,
    int flags)

Cuando se invoca proc, el argumento clientData es el valor que se pasó a Tcl_TraceVar o Tcl_TraceVar2 cuando se estableció el rastreo. El argumento interp es el intérprete en el que se produjo el acceso. Los argumentos name1 y name2 identifican la variable rastreada. Si el rastreo es para una variable escalar, name2 será NULL. Si el rastreo es para un elemento de array, name1 será el nombre del array y name2 será el índice del elemento. El argumento flags contiene información adicional sobre el acceso:

  • TCL_TRACE_READ, TCL_TRACE_WRITE, TCL_TRACE_UNSET, TCL_TRACE_ARRAY: Estos bits estarán configurados en flags para indicar el tipo de acceso que activó el rastreo.
  • TCL_TRACE_CONNECTED: Este bit se establece si el acceso a la variable está ocurriendo en el contexto de una conexión (por ejemplo, usando source -comm).
  • TCL_TRACE_FOREIGN: Este bit se establece si el acceso a la variable está ocurriendo en el contexto de otro intérprete, como se describe en Tcl_TransferToCommand.
  • TCL_TRACE_DESTROYED: Este bit se establece en un callback de unset si el rastreo se está eliminando como parte de la eliminación de la variable.
  • TCL_INTERP_DESTROYED: Este bit se establece si el intérprete está siendo destruido.

Las funciones Tcl_TraceVar, Tcl_UntraceVar y Tcl_VarTraceInfo operan en variables cuyos nombres se proporcionan como una única cadena de caracteres. Las funciones Tcl_TraceVar2, Tcl_UntraceVar2 y Tcl_VarTraceInfo2 operan en variables cuyos nombres se proporcionan como dos partes, lo que permite el rastreo de elementos de array específicos y el manejo de nombres de array y elemento más complejos.

Los procedimientos de rastreo devuelven NULL si se completan con éxito. Si un procedimiento de rastreo devuelve un valor distinto de NULL, indica que se produjo un error. El valor de retorno debe ser un puntero a una cadena de caracteres estática que contenga un mensaje de error, a menos que se establezcan las marcas TCL_TRACE_RESULT_DYNAMIC o TCL_TRACE_RESULT_OBJECT. Si se produce un error, no se invocarán más rastreos para el acceso y el acceso rastreado se abortará con el mensaje dado.

La función Tcl_VarTraceInfo se puede utilizar para iterar a través de los rastreos existentes para una variable determinada. Si el argumento prevClientData es NULL, la función devolverá el clientData del primer rastreo que coincida con los otros argumentos. Si prevClientData no es NULL, entonces debe ser el valor devuelto de una llamada anterior a Tcl_VarTraceInfo. En este caso, el nuevo valor de retorno corresponderá al siguiente rastreo coincidente después del cual cuyo clientData coincida con prevClientData, o NULL si no hay ningún rastreo que coincida con prevClientData o si no hay más rastreos coincidentes después de él. Este mecanismo hace posible recorrer todos los rastreos de una variable dada que tienen el mismo proc.

DOS-PARTES NOMBRES

Los procedimientos Tcl_TraceVar2, Tcl_UntraceVar2 y Tcl_VarTraceInfo2 son idénticos a Tcl_TraceVar, Tcl_UntraceVar y Tcl_VarTraceInfo, respectivamente, excepto que el nombre de la variable consta de dos partes. Name1 da el nombre de una variable escalar o array, y name2 da el nombre de un elemento dentro de un array. Cuando name2 es NULL, name1 puede contener tanto un nombre de array como un nombre de elemento: si el nombre contiene un paréntesis de apertura y termina con un paréntesis de cierre, entonces el valor entre los paréntesis se trata como un nombre de elemento (que puede tener cualquier valor de cadena) y los caracteres antes del primer paréntesis de apertura se tratan como el nombre de una variable de array. Si name2 es NULL y name1 no se refiere a un elemento de array, significa que la variable es escalar o que el rastreo se establecerá en todo el array en lugar de un elemento individual (ver RASTREOS DE ARRAY COMPLETOS a continuación para más información).

ACCESO A VARIABLES DURANTE RASTREOS

Durante los rastreos de lectura, escritura y array, el procedimiento de rastreo puede leer, escribir o eliminar la variable rastreada usando Tcl_GetVar2, Tcl_SetVar2 y otros procedimientos. Mientras proc se está ejecutando, los rastreos se deshabilitan temporalmente para la variable, de modo que las llamadas a Tcl_GetVar2 y Tcl_SetVar2 no provoquen que se invoque proc u otros procedimientos de rastreo nuevamente. La deshabilitación solo ocurre para la variable cuyo procedimiento de rastreo está activo; los accesos a otras variables aún serán rastreados. Sin embargo, si una variable es eliminada durante un rastreo de lectura o escritura, se invocarán rastreos de eliminación.

Durante los rastreos de eliminación, la variable ya ha sido completamente eliminada. Es posible que el procedimiento de rastreo lea o escriba la variable, pero esta será una nueva versión de la variable. Los rastreos no se deshabilitan durante los rastreos de eliminación, como lo son para los rastreos de lectura y escritura, pero los rastreos existentes se han eliminado de la variable antes de que se invoquen los procedimientos de rastreo. Si los rastreos de eliminación establecen nuevos rastreos, estos rastreos se invocarán en los accesos a la variable por parte de los procedimientos de rastreo.

TEMPORIZACIÓN DE DEVOLUCIONES DE LLAMADA

Cuando se ha especificado el rastreo de lectura para una variable, el procedimiento de rastreo se invocará cada vez que se lea el valor de la variable. Esto incluye los comandos Tcl set, la notación de $-notación en comandos Tcl e invocaciones de los procedimientos Tcl_GetVar y Tcl_GetVar2. Proc se invoca justo antes de que se devuelva el valor de la variable. Puede modificar el valor de la variable para afectar lo que devuelve el acceso rastreado. Si elimina la variable, el acceso devolverá un error, como si la variable nunca hubiera existido.

Cuando se ha especificado el rastreo de escritura para una variable, el procedimiento de rastreo se invocará cada vez que se modifique el valor de la variable. Esto incluye los comandos set, los comandos que modifican variables como efectos secundarios (como catch y scan) y las llamadas a los procedimientos Tcl_SetVar y Tcl_SetVar2). Proc se invocará después de que se haya modificado el valor de la variable, pero antes de que se haya devuelto el nuevo valor de la variable. Puede modificar el valor de la variable para anular el cambio y para determinar el valor que realmente devuelve el acceso rastreado. Si elimina la variable, el acceso rastreado devolverá una cadena vacía.

Cuando se ha especificado el rastreo de array, el procedimiento de rastreo se invocará al principio de la implementación del comando de array, antes de que se invoquen las operaciones como get, set o names. El procedimiento de rastreo puede modificar los elementos del array con Tcl_SetVar y Tcl_SetVar2.

Cuando se ha especificado el rastreo de eliminación, el procedimiento de rastreo se invocará cada vez que se destruya la variable. Los rastreos se llamarán después de que la variable se haya eliminado por completo.

RASTREOS DE ARRAY COMPLETOS

Si una llamada a Tcl_TraceVar o Tcl_TraceVar2 especifica el nombre de una variable de array sin un índice en el array, entonces el rastreo se establecerá en el array en su conjunto. Esto significa que proc se invocará cada vez que se acceda a cualquier elemento del array de las maneras especificadas por flags. Cuando se elimina un array, se invocará un rastreo de array completo una sola vez, con name1 igual al nombre del array y name2 NULL; no se invocará una vez por cada elemento.

RASTREOS MÚLTIPLES

Es posible que existan varios rastreos en la misma variable. Cuando esto sucede, todos los procedimientos de rastreo se invocarán en cada acceso, en orden desde el más recientemente creado hasta el menos recientemente creado. Cuando existen rastreos de array completos para un array, así como rastreos en elementos individuales, los rastreos de array completos se invocan antes que los rastreos de elementos individuales. Si un rastreo de lectura o escritura elimina la variable, se invocarán todos los rastreos de eliminación, pero se omitirán los rastreos de lectura y escritura restantes.

RETORNOS DE ERROR

En condiciones normales, los procedimientos de rastreo deben devolver NULL, lo que indica una finalización exitosa. Si proc devuelve un valor distinto de NULL, significa que se produjo un error. El valor de retorno debe ser un puntero a una cadena de caracteres estática que contenga un mensaje de error, a menos que (exactamente una de) las marcas TCL_TRACE_RESULT_DYNAMIC y TCL_TRACE_RESULT_OBJECT estén establecidas, que especifican que el resultado es una cadena dinámica (que debe liberarse con ckfree) o un Tcl_Obj* (convertido a char* y que debe liberarse con Tcl_DecrRefCount) que contenga el mensaje de error. Si un procedimiento de rastreo devuelve un error, no se invocarán más rastreos para el acceso y el acceso rastreado se abortará con el mensaje dado. Los procedimientos de rastreo pueden usar esta facilidad para hacer que las variables no se puedan escribir, por ejemplo (pero tenga en cuenta que el valor de la variable ya habrá sido modificado antes de que se llame al procedimiento de rastreo, por lo que el procedimiento de rastreo tendrá que restaurar el valor correcto).

El valor de retorno de proc solo se utiliza durante los rastreos de lectura y escritura. Durante los rastreos de eliminación, se ignora el valor de retorno y todos los procedimientos de rastreo relevantes se invocarán siempre.

RESTRICCIONES

Un procedimiento de rastreo puede ser llamado en cualquier momento, incluso cuando hay resultados parcialmente formados almacenados en el intérprete. Si el procedimiento de rastreo hace algo que pueda dañar este resultado (como llamar a Tcl_Eval), debe usar las rutinas Tcl_SaveInterpState y relacionadas para guardar y restaurar el estado original del intérprete antes de que devuelva.

VARIABLES NO DEFINIDAS

Es legal establecer un rastreo en una variable no definida. La variable aún parecerá no definida hasta la primera vez que se establezca su valor. Si se rastrea una variable no definida y luego se elimina, la eliminación fallará con un error (“no such variable”), pero el procedimiento de rastreo aún se invocará.

MARCA TCL_TRACE_DESTROYED

En una devolución de llamada de eliminación a proc, el bit TCL_TRACE_DESTROYED se establece en flags si el rastreo se está eliminando como parte de la eliminación. Los rastreos en una variable siempre se eliminan cuando se elimina la variable; la única vez que TCL_TRACE_DESTROYED no se establece es para un rastreo de array completo invocado cuando solo se elimina un solo elemento de un array.

TCL_INTERP_DESTROYED

Cuando se destruye un intérprete, se llaman los rastreos de eliminación para todas sus variables. El bit TCL_INTERP_DESTROYED se establecerá en el argumento flags pasado a los procedimientos de rastreo. Los procedimientos de rastreo deben ser extremadamente cuidadosos en lo que hacen si el bit TCL_INTERP_DESTROYED está establecido. No es seguro que los procedimientos invoquen ningún procedimiento Tcl en el intérprete, ya que su estado está parcialmente eliminado. Todo lo que los procedimientos de rastreo deben hacer en estas circunstancias es limpiar y liberar sus propias estructuras de datos internas.

ERRORES

Tcl no realiza ninguna comprobación de errores para evitar que los procedimientos de rastreo utilicen incorrectamente el intérprete durante los rastreos con TCL_INTERP_DESTROYED establecido.

Los rastreos de array aún no están integrados con el comando Tcl info exists, ni hay acceso a nivel de Tcl a los rastreos de array.
