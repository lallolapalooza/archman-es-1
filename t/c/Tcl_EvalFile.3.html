Tcl_Eval(3) Procedimientos de la biblioteca Tcl Tcl_Eval(3)

NOMBRE

Tcl_EvalObjEx, Tcl_EvalFile, Tcl_EvalObjv, Tcl_Eval, Tcl_EvalEx, Tcl_GlobalEval, Tcl_GlobalEvalObj, Tcl_VarEval, Tcl_VarEvalVA - ejecutar scripts de Tcl

SINOPSIS

#include <tcl.h>

int
Tcl_EvalObjEx(interp, objPtr, flags)

int
Tcl_EvalFile(interp, fileName)

int
Tcl_EvalObjv(interp, objc, objv, flags)

int
Tcl_Eval(interp, script)

int
Tcl_EvalEx(interp, script, numBytes, flags)

int
Tcl_GlobalEval(interp, script)

int
Tcl_GlobalEvalObj(interp, objPtr)

int
Tcl_VarEval(interp, part, part, ... (char *)NULL)

int
Tcl_VarEvalVA(interp, argList)

ARGUMENTOS

Tcl_Interp *interp (entrada)
Intérprete en el que ejecutar el script. El resultado del intérprete se modifica para contener el resultado o el mensaje de error del script.
Tcl_Obj *objPtr (entrada)
Un valor Tcl que contiene el script a ejecutar.
int flags (entrada)
Combinación OR de bits de bandera que especifican opciones adicionales. Actualmente se admiten TCL_EVAL_GLOBAL y TCL_EVAL_DIRECT.
const char *fileName (entrada)
Nombre de un archivo que contiene un script Tcl.
int objc (entrada)
El número de valores en la matriz apuntada por objv; este es también el número de palabras en el comando.
Tcl_Obj **objv (entrada)
Puntero a una matriz de punteros a valores; cada valor contiene el valor de una sola palabra en el comando a ejecutar.
int numBytes (entrada)
El número de bytes en script, sin incluir ningún carácter de terminación nula. Si es -1, se utilizan todos los caracteres hasta el primer byte nulo.
const char *script (entrada)
Puntero al primer byte del script a ejecutar (terminado en nulo y UTF-8).
const char *part (entrada)
Cadena que forma parte de un script Tcl.
va_list argList (entrada)
Una lista de argumentos que debe haber sido inicializada con va_start y limpiada con va_end.

DESCRIPCIÓN

Los procedimientos descritos aquí se invocan para ejecutar scripts Tcl en diversas formas. Tcl_EvalObjEx es el procedimiento principal y es utilizado por muchos de los otros. Ejecuta los comandos en el script almacenado en objPtr hasta que ocurre un error o se alcanza el final del script. Si esta es la primera vez que se ejecuta objPtr, sus comandos se compilan en instrucciones de bytecode que luego se ejecutan. Los bytecodes se guardan en objPtr para que el paso de compilación pueda omitirse si el valor se evalúa de nuevo en el futuro.

El valor de retorno de Tcl_EvalObjEx (y de todos los demás procedimientos descritos aquí) es un código de finalización Tcl con uno de los valores TCL_OK, TCL_ERROR, TCL_RETURN, TCL_BREAK, o TCL_CONTINUE, o posiblemente algún otro valor entero originado en una extensión. Además, se deja un valor de resultado o un mensaje de error en el resultado de interp; se puede recuperar usando Tcl_GetObjResult.

Tcl_EvalFile lee el archivo proporcionado por fileName y evalúa su contenido como un script Tcl. Devuelve la misma información que Tcl_EvalObjEx. Si el archivo no se pudo leer, se devuelve un error Tcl para describir por qué no se pudo leer. El carácter de fin de archivo para los archivos es “\32” (^Z) para todas las plataformas. Si requiere un “^Z” en código para comparación de cadenas, puede usar “\032” o “\u001a”, que serán sustituidos de forma segura por el intérprete Tcl en “^Z”.

Tcl_EvalObjv ejecuta un solo comando pre-analizado en lugar de un script. Los argumentos objc y objv contienen los valores de las palabras para el comando Tcl, una palabra en cada valor de objv. Tcl_EvalObjv evalúa el comando y devuelve un código de finalización y un resultado como Tcl_EvalObjEx. El llamante de Tcl_EvalObjv tiene que gestionar el contador de referencias de los elementos de objv, asegurando que los valores sean válidos hasta que Tcl_EvalObjv retorne.

Tcl_Eval es similar a Tcl_EvalObjEx excepto que el script a ejecutar se proporciona como una cadena en lugar de un valor y no ocurre ninguna compilación. La cadena debe ser una cadena UTF-8 correcta, tal como la convierte Tcl_ExternalToUtfDString o Tcl_ExternalToUtf cuando se sabe que puede contener caracteres ASCII superiores cuyas posibles combinaciones podrían ser un código especial de UTF-8. La cadena se analiza y se ejecuta directamente (usando Tcl_EvalObjv) en lugar de compilarla y ejecutar los bytecodes. En situaciones en las que se sabe que el script nunca se ejecutará de nuevo, Tcl_Eval puede ser más rápido que Tcl_EvalObjEx.
Tcl_Eval devuelve un código de finalización y un resultado como Tcl_EvalObjEx. Nota: para compatibilidad con versiones anteriores a Tcl 8.0, Tcl_Eval copia el resultado del valor en interp a interp->result (su uso está obsoleto) donde se puede acceder directamente.
Esto hace que Tcl_Eval sea algo más lento que Tcl_EvalEx, que no realiza la copia.

Tcl_EvalEx es una versión extendida de Tcl_Eval que toma argumentos adicionales numBytes y flags. Por la razón de eficiencia dada anteriormente, Tcl_EvalEx es generalmente preferido sobre Tcl_Eval.

Tcl_GlobalEval y Tcl_GlobalEvalObj son procedimientos más antiguos que ahora están obsoletos. Son similares a Tcl_EvalEx y Tcl_EvalObjEx excepto que el script se evalúa en el espacio de nombres global y su contexto de variables consiste solo en variables globales (ignora cualquier procedimiento Tcl que esté activo). Estas funciones son equivalentes a usar la bandera TCL_EVAL_GLOBAL (ver más abajo).

Tcl_VarEval toma cualquier número de argumentos de cadena de cualquier longitud, los concatena en una sola cadena, y luego llama a Tcl_Eval para ejecutar esa cadena como un comando Tcl. Devuelve el resultado del comando y también modifica interp->result de la misma manera que Tcl_Eval. El último argumento para Tcl_VarEval debe ser (char *)NULL para indicar el final de los argumentos.

Tcl_VarEvalVA es lo mismo que Tcl_VarEval excepto que en lugar de tomar un número variable de argumentos, toma una lista de argumentos. Tcl_VarEvalVA está ahora obsoleto.

BITS DE BANDERA

Se puede usar cualquier combinación OR de los siguientes valores para el argumento flags de procedimientos como Tcl_EvalObjEx:

TCL_EVAL_DIRECT
Esta bandera solo la usa Tcl_EvalObjEx; es ignorada por otros procedimientos. Si este bit de bandera está activado, el script no se compila a bytecodes; en su lugar, se ejecuta directamente como lo hace Tcl_EvalEx. La bandera TCL_EVAL_DIRECT es útil en situaciones en las que el contenido de un valor va a cambiar inmediatamente, por lo que los bytecodes no se reutilizarán en una ejecución futura. En este caso, es más rápido ejecutar el script directamente.
TCL_EVAL_GLOBAL
Si esta bandera está activada, el script se evalúa en el espacio de nombres global en lugar del espacio de nombres actual y su contexto de variables consiste solo en variables globales (ignora cualquier procedimiento Tcl que esté activo).

DETALLES VARIOS

Durante el procesamiento de un comando Tcl es legal hacer llamadas anidadas para evaluar otros comandos (así es como se implementan los procedimientos y algunas estructuras de control). Si un código distinto de TCL_OK se devuelve desde una invocación anidada de Tcl_EvalObjEx, entonces el llamante normalmente debe devolver inmediatamente, pasando ese mismo código de retorno a su llamante, y así sucesivamente hasta que se alcance la aplicación de nivel superior. Algunos comandos, como for, comprobarán ciertos códigos de retorno, como TCL_BREAK y TCL_CONTINUE, y los procesarán especialmente sin devolver.

Tcl_EvalObjEx realiza un seguimiento de cuántas invocaciones anidadas de Tcl_EvalObjEx están en progreso para interp. Si un código de TCL_RETURN, TCL_BREAK o TCL_CONTINUE está a punto de ser devuelto desde la invocación de nivel superior de Tcl_EvalObjEx para interp, convierte el código de retorno a TCL_ERROR y establece el resultado de interp a un mensaje de error que indica que el return, break

Tcl_EvalFile(3) - Tcl manual page

NAME

Tcl_EvalObjEx, Tcl_EvalObjv, Tcl_EvalEx, Tcl_Eval, Tcl_EvalFile, Tcl_GlobalEval, Tcl_EvalTokens - evaluate Tcl commands

SYNOPSIS

#include <tcl.h>

int
Tcl_EvalObjEx(interp, objPtr, flags)
int
Tcl_EvalObjv(interp, objc, objv, flags)
int
Tcl_EvalEx(interp, script, scriptLen, flags)
int
Tcl_Eval(interp, script)
int
Tcl_EvalFile(interp, fileName)
int
Tcl_GlobalEval(interp, script)
int
Tcl_EvalTokens(interp, tokenPtr, numTokens)

ARGUMENTS

Tcl_Interp *interp
Interpreter to use for evaluation.
Tcl_Obj *objPtr
Pointer to the object containing the script to evaluate.
int objc
Number of objects in the objv array.
Tcl_Obj *CONST objv[]
Array of objects, each representing a word in the command to evaluate.
const char *script
String containing the Tcl script to evaluate.
int scriptLen
Length of the script string. If -1, then strlen is used.
int flags
Bitmask of flags, as described below.
const char *fileName
Path to the file containing the Tcl script to evaluate.
Tcl_Token *tokenPtr
Pointer to an array of tokens representing the script to evaluate. This is typically generated by Tcl_Tokenize.
int numTokens
The number of tokens in the tokenPtr array.

DESCRIPTION

These functions all evaluate Tcl scripts. They differ in the form of the script they accept, the context in which they are evaluated, and the mechanisms they use for parsing and execution.

The most fundamental evaluation function is Tcl_EvalObjEx. It evaluates the Tcl script represented by the Tcl object objPtr within the interpreter interp. The result of the evaluation is stored in the interpreter's result object, which can be retrieved using Tcl_GetObjResult. The return value is a Tcl return code (e.g., TCL_OK, TCL_ERROR, TCL_RETURN, TCL_BREAK, TCL_CONTINUE). The flags argument is a bitmask and can be used to modify evaluation behavior. Currently, only the TCL_EVAL_GLOBAL and TCL_EVAL_IMPLICIT_NS flags are supported.

Tcl_EvalObjv is similar to Tcl_EvalObjEx, but it accepts the script as an array of Tcl objects objv, where objc is the number of objects in the array.

Tcl_EvalEx evaluates the script specified by the C string script, with length scriptLen. If scriptLen is -1, the length is determined using strlen. This function internally converts the C string to a Tcl object and then calls Tcl_EvalObjEx. The flags argument is passed directly to Tcl_EvalObjEx.

Tcl_Eval is a simplified version of Tcl_EvalEx that evaluates the script specified by the C string script without any flags. It is equivalent to calling Tcl_EvalEx(interp, script, -1, 0).

Tcl_EvalFile reads the Tcl script from the file specified by fileName and evaluates it in the interpreter interp. The file is read as a single string and then evaluated using Tcl_EvalEx. If an error occurs during file reading or evaluation, an error is reported in the interpreter's result.

Tcl_GlobalEval is similar to Tcl_Eval, but it evaluates the script in the global context of the interpreter, regardless of the current namespace. This is useful for executing commands that should always operate at the global level.

Tcl_EvalTokens evaluates a script that has already been tokenized using Tcl_Tokenize. This can be more efficient if the script needs to be evaluated multiple times, as tokenization is done only once.

All these functions return a Tcl return code. TCL_OK indicates successful completion. TCL_ERROR indicates that an error occurred during evaluation, and the interpreter's result will contain error information. Other return codes (TCL_RETURN, TCL_BREAK, TCL_CONTINUE) are propagated from commands executed within the script.

It is important to note that applications calling these functions should never encounter return codes other than TCL_OK or TCL_ERROR, as these indicate the completion or failure of the script evaluation itself. Internal Tcl commands might return other codes, but these are typically handled by the Tcl core and do not propagate to top-level application calls.

FLAG BITS

TCL_EVAL_GLOBAL
Evaluate the script in the global context, as if Tcl_GlobalEval was called.
TCL_EVAL_IMPLICIT_NS
If the script is not fully qualified, it will be evaluated in the namespace of the caller.

MISCELLANEOUS DETAILS

The continue command was invoked in an inappropriate place. This means that top-level applications should never see a return code from Tcl_EvalObjEx other than TCL_OK or TCL_ERROR.
