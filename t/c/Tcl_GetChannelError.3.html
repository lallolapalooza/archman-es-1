Tcl_SetChannelError(3) Procedimientos de la biblioteca Tcl Tcl_SetChannelError(3)

NOMBRE

Tcl_SetChannelError, Tcl_SetChannelErrorInterp, Tcl_GetChannelError, Tcl_GetChannelErrorInterp - funciones para crear/interceptar errores de Tcl por controladores de canal.

SINOPSIS

#include <tcl.h>

void
Tcl_SetChannelError(chan, msg)

void
Tcl_SetChannelErrorInterp(interp, msg)

void
Tcl_GetChannelError(chan, msgPtr)

void
Tcl_GetChannelErrorInterp(interp, msgPtr)

ARGUMENTOS

Tcl_Channel chan (entrada)
Se refiere al canal Tcl cuya área de bypass se accede.
Tcl_Interp* interp (entrada)
Se refiere al intérprete Tcl cuya área de bypass se accede.
Tcl_Obj* msg (entrada)
Mensaje de error insertado en un área de bypass. Una lista de opciones y valores de retorno, seguida de un mensaje de cadena. Tanto el mensaje como la información de opción/valor son opcionales.
Tcl_Obj** msgPtr (salida)
Referencia a un lugar donde se puede almacenar el mensaje guardado en el área de bypass accedida.

DESCRIPCIÓN

La definición actual de un controlador de canal Tcl no permite la devolución directa de mensajes de error arbitrarios, excepto para el establecimiento y recuperación de opciones de canal. Todas las demás funciones están restringidas a códigos de error POSIX.

Las funciones descritas aquí superan esta limitación. Se permite a los controladores de canal utilizar Tcl_SetChannelError y Tcl_SetChannelErrorInterp para colocar mensajes de error arbitrarios en las áreas de bypass definidas para canales e intérpretes. Y la capa genérica de E/S utiliza Tcl_GetChannelError y Tcl_GetChannelErrorInterp para buscar mensajes en las áreas de bypass y organizar su devolución como errores. Los códigos de error POSIX establecidos por un controlador se utilizan ahora si y solo si no hay mensajes presentes.

Tcl_SetChannelError almacena información de error en el área de bypass del canal especificado. El número de referencias al valor msg aumenta en uno. La información almacenada previamente se descartará, liberando la referencia que tiene el canal. La referencia del canal no debe ser NULL.

Tcl_SetChannelErrorInterp almacena información de error en el área de bypass del intérprete especificado. El número de referencias al valor msg aumenta en uno. La información almacenada previamente se descartará, liberando la referencia que tiene el intérprete. La referencia del intérprete no debe ser NULL.

Tcl_GetChannelError coloca el mensaje de error que tiene el área de bypass del canal especificado en msgPtr, o NULL; y restablece el bypass, es decir, después de una invocación, todas las invocaciones siguientes devolverán NULL, hasta una invocación intermedia de Tcl_SetChannelError con un mensaje distinto de NULL. El msgPtr no debe ser NULL. El recuento de referencias del mensaje no se modifica. La referencia previamente mantenida por el canal ahora la tiene el llamador de la función y es su responsabilidad liberar esa referencia cuando termine con el valor.

Tcl_GetChannelErrorInterp coloca el mensaje de error que tiene el área de bypass del intérprete especificado en msgPtr, o NULL; y restablece el bypass, es decir, después de una invocación, todas las invocaciones siguientes devolverán NULL, hasta una invocación intermedia de Tcl_SetChannelErrorInterp con un mensaje distinto de NULL. El msgPtr no debe ser NULL. El recuento de referencias del mensaje no se modifica. La referencia previamente mantenida por el intérprete ahora la tiene el llamador de la función y es su responsabilidad liberar esa referencia cuando termine con el valor.

Qué funciones de un controlador de canal pueden utilizar qué función de bypass se enumera a continuación, al igual que qué funciones de la API pública de canal pueden dejar mensajes en las áreas de bypass.

Tcl_DriverCloseProc
Puede usar Tcl_SetChannelErrorInterp, y solo esta función.
Tcl_DriverInputProc
Puede usar Tcl_SetChannelError, y solo esta función.
Tcl_DriverOutputProc
Puede usar Tcl_SetChannelError, y solo esta función.
Tcl_DriverSeekProc
Puede usar Tcl_SetChannelError, y solo esta función.
Tcl_DriverWideSeekProc
Puede usar Tcl_SetChannelError, y solo esta función.
Tcl_DriverSetOptionProc
Ya tiene la capacidad de pasar mensajes de error arbitrarios. No debe usar ninguna de las nuevas funciones.
Tcl_DriverGetOptionProc
Ya tiene la capacidad de pasar mensajes de error arbitrarios. No debe usar ninguna de las nuevas funciones.
Tcl_DriverWatchProc
No debe usar ninguna de las nuevas funciones. Se llama internamente y no tiene capacidad para devolver ningún tipo de error.
Tcl_DriverBlockModeProc
Puede usar Tcl_SetChannelError, y solo esta función.
Tcl_DriverGetHandleProc
No debe usar ninguna de las nuevas funciones. Es solo una función de bajo nivel y no es utilizada por comandos Tcl.
Tcl_DriverHandlerProc
No debe usar ninguna de las nuevas funciones. Se llama internamente y no tiene capacidad para devolver ningún tipo de error.

Dada la información anterior, las siguientes funciones públicas de la API C de Tcl se ven afectadas por estos cambios; cuando se llamen estas funciones, el canal ahora puede contener un mensaje de error arbitrario almacenado que requiere procesamiento por parte del llamador.

Tcl_Flush	Tcl_GetsObj	Tcl_Gets
Tcl_ReadChars	Tcl_ReadRaw	Tcl_Read
Tcl_Seek	Tcl_StackChannel	Tcl_Tell
Tcl_WriteChars	Tcl_WriteObj	Tcl_WriteRaw
Tcl_Write

Todas las demás funciones de la API no han cambiado. En particular, las siguientes funciones dejan toda su información de error en el resultado del intérprete.

Tcl_Close	Tcl_UnstackChannel	Tcl_UnregisterChannel

VER TAMBIÉN

Tcl_Close(3), Tcl_OpenFileChannel(3), Tcl_SetErrno(3)

Tcl_GetChannelError(3)

en · es

NOMBRE

Tcl_GetChannelError - Obtiene información sobre el último error de canal.

SINOPSIS

#include <tcl.h>

const char *
Tcl_GetChannelError(
    Tcl_Channel channel
);

DESCRIPCIÓN

La función Tcl_GetChannelError devuelve un puntero a una cadena de caracteres que describe el último error que ocurrió en el canal especificado por channel. Si no ha ocurrido ningún error en el canal, o si el canal no existe, devuelve NULL.

La información del error se almacena de forma interna por Tcl y puede ser sobrescrita por operaciones posteriores en el mismo canal o en otros canales. Por lo tanto, si necesita conservar la información del error, debe copiarla inmediatamente después de llamar a Tcl_GetChannelError.

ARGUMENTOS

  • channel: El identificador del canal para el que se desea obtener información del error.

VALOR DE RETORNO

Devuelve un puntero a una cadena de caracteres que describe el último error del canal, o NULL si no ha ocurrido ningún error o el canal no existe.

EJEMPLO

Tcl_Channel chan;
/* ... abrir o crear el canal ... */

if (Tcl_WriteChars(chan, "datos inválidos", -1) == -1) {
    const char *errorMsg = Tcl_GetChannelError(chan);
    if (errorMsg != NULL) {
        fprintf(stderr, "Error al escribir en el canal: %s\n", errorMsg);
    }
    /* ... manejar el error ... */
}
