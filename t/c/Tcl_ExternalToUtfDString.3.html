INTRODUCCIÓN

Estas rutinas convierten entre la representación de caracteres interna de Tcl, UTF-8, y las representaciones de caracteres utilizadas por varios sistemas operativos o sistemas de archivos, como Unicode, ASCII o Shift-JIS. Al operar sobre cadenas, como obtener los nombres de archivos o mostrar caracteres utilizando fuentes internacionales, las cadenas deben traducirse a uno o posiblemente a múltiples formatos que las diversas llamadas al sistema puedan usar. Por ejemplo, en una estación de trabajo Unix japonesa, un usuario podría obtener un nombre de archivo representado en la codificación de archivo EUC-JP y luego traducir los caracteres a la codificación de fuente jisx0208 para mostrar el nombre del archivo en un widget Tk. El propósito del paquete de codificación es ayudar a cerrar la brecha de traducción. UTF-8 proporciona un punto intermedio para todas las diversas codificaciones. En el ejemplo anterior, el texto se traduciría a UTF-8 desde la codificación de archivo que esté utilizando el sistema operativo. Luego se traduciría de UTF-8 a la codificación de fuente que requieran las rutinas de visualización.

Algunas codificaciones básicas están compiladas en Tcl. Otras pueden ser definidas por el usuario o cargadas dinámicamente desde archivos de codificación de manera independiente de la plataforma.

DESCRIPCIÓN

Tcl_GetEncoding busca una codificación dado su name. El nombre puede referirse a una codificación incorporada de Tcl, una codificación definida por el usuario registrada llamando a Tcl_CreateEncoding, o un archivo de codificación cargable dinámicamente. El valor de retorno es un token que representa la codificación y puede ser utilizado en llamadas posteriores a procedimientos como Tcl_GetEncodingName, Tcl_FreeEncoding y Tcl_UtfToExternal. Si el nombre no se refirió a ninguna codificación conocida o cargable, se devuelve NULL y se devuelve un mensaje de error en interp.

El paquete de codificación mantiene una base de datos de todas las codificaciones actualmente en uso. La primera vez que se ve name, Tcl_GetEncoding devuelve una codificación con un contador de referencia de 1. Si se solicitan el mismo name varias veces más, el contador de referencia para esa codificación se incrementa sin el costo general de asignar una nueva codificación y todas sus estructuras de datos asociadas.

Cuando una encoding ya no es necesaria, se debe llamar a Tcl_FreeEncoding para liberarla. Cuando una encoding ya no está en uso en ninguna parte (es decir, se ha liberado tantas veces como se ha obtenido), Tcl_FreeEncoding liberará todo el almacenamiento que la codificación estaba utilizando y la eliminará de la base de datos.

Tcl_GetEncodingFromObj trata la representación de cadena de objPtr como un nombre de codificación, y busca una codificación con ese nombre, al igual que lo hace Tcl_GetEncoding. Cuando se encuentra una codificación, se almacena en caché dentro del valor objPtr para referencia futura, el token Tcl_Encoding se escribe en el almacenamiento

Al igual que con Tcl_GetEncoding, el llamador debe llamar a Tcl_FreeEncoding sobre el token de codificación resultante cuando ya no se utilice.

Tcl_ExternalToUtfDString convierte un búfer fuente src de la codificación especificada encoding a UTF-8. Los bytes convertidos se almacenan en dstPtr, que luego se termina con un nulo. El llamador debe eventualmente llamar a Tcl_DStringFree para liberar cualquier información almacenada en dstPtr. Al convertir, si alguno de los caracteres del búfer fuente no se puede representar en la codificación de destino, se utilizará un carácter de reserva predeterminado. El valor de retorno es un puntero al valor almacenado en el DString.

Tcl_ExternalToUtf convierte un búfer fuente src de la codificación especificada encoding a UTF-8. Se convierten hasta srcLen bytes del búfer fuente y se almacenan hasta dstLen bytes convertidos en dst. En todos los casos, *srcReadPtr se rellena con el número de bytes que se convirtieron correctamente de src y *dstWrotePtr se rellena con el número correspondiente de bytes que se almacenaron en dst. El valor de retorno es uno de los siguientes:

TCL_OK
Todos los bytes de src fueron convertidos.
TCL_CONVERT_NOSPACE
El búfer de destino no era lo suficientemente grande para todos los datos convertidos; sin embargo, se convirtieron tantos caracteres como cupieron.
TCL_CONVERT_MULTIBYTE
Los últimos bytes del búfer fuente eran el principio de una secuencia de múltiples bytes, pero se necesitaban más bytes para completar esta secuencia. Una llamada posterior a la rutina de conversión debería pasar un búfer que contenga los bytes no convertidos que quedaron en src más algunos bytes adicionales del flujo fuente para convertir correctamente la secuencia multibyte anteriormente dividida.
TCL_CONVERT_SYNTAX
El búfer fuente contenía una secuencia de caracteres inválida. Esto puede ocurrir si el flujo de entrada ha sido dañado o si el método de codificación de entrada fue mal identificado.
TCL_CONVERT_UNKNOWN
El búfer fuente contenía un carácter que no se podía representar en la codificación de destino y se especificó TCL_ENCODING_STOPONERROR.

Tcl_UtfToExternalDString convierte un búfer fuente src de UTF-8 a la codificación especificada encoding. Los bytes convertidos se almacenan en dstPtr, que luego se termina con el nulo específico de la codificación apropiada. El llamador debe eventualmente llamar a Tcl_DStringFree para liberar cualquier información almacenada en dstPtr. Al convertir, si alguno de los caracteres del búfer fuente no se puede representar en la codificación de destino, se utilizará un carácter de reserva predeterminado. El valor de retorno es un puntero al valor almacenado en el DString.

Tcl_UtfToExternal convierte un búfer fuente src de UTF-8 a la codificación especificada encoding. Se convierten hasta srcLen bytes del búfer fuente y se almacenan hasta dstLen bytes convertidos en dst. En todos los casos, *srcReadPtr se rellena con el número de bytes que se convirtieron correctamente de src y *dstWrotePtr se rellena con el número correspondiente de bytes que se almacenaron en dst. Los valores de retorno son los mismos que los valores de retorno para Tcl_ExternalToUtf.

Tcl_WinUtfToTChar y Tcl_WinTCharToUtf son funciones de conveniencia exclusivas de Windows para convertir entre UTF-8 y cadenas de Windows basadas en el tipo TCHAR, que por convención es un carácter Unicode en Windows NT.

Tcl_GetEncodingName es aproximadamente la inversa de Tcl_GetEncoding. Dado un encoding, el valor de retorno es el argumento name que se utilizó para crear la codificación. La cadena devuelta por Tcl_GetEncodingName solo se garantiza que persiste hasta que se elimine el encoding. El llamador no debe modificar esta cadena.

Tcl_SetSystemEncoding establece la codificación predeterminada que debe utilizarse cada vez que el usuario pase un valor NULL para el argumento encoding a cualquiera de las otras funciones de codificación. Si name es NULL, la codificación del sistema se restablece a la codificación del sistema predeterminada, binary. Si el nombre no se refería a ninguna codificación conocida o cargable, se devuelve TCL_ERROR y se deja un mensaje de error en interp. De lo contrario, este procedimiento incrementa el recuento de referencias de la nueva codificación del sistema, decrementa el recuento de referencias de la codificación del sistema anterior y devuelve TCL_OK.

Tcl_GetEncodingNameFromEnvironment proporciona un medio para que la biblioteca Tcl informe el nombre de codificación que cree que es el correcto para usar como codificación del sistema, basándose en llamadas al sistema y en el examen del entorno adecuado para la plataforma. Acepta bufPtr, un puntero a un Tcl_DString no inicializado o liberado, y escribe el nombre de la codificación en él. Se devuelve Tcl_DStringValue.

Tcl_GetEncodingNames establece el resultado de interp a una lista que consta de los nombres de todas las codificaciones que están actualmente definidas o que se pueden cargar dinámicamente, buscando en la ruta de codificación especificada por Tcl_SetDefaultEncodingDir. Este procedimiento no garantiza que los archivos de codificación cargables dinámicamente contengan datos válidos, sino simplemente que existen.

Tcl_CreateEncoding define una nueva codificación y registra los procedimientos C que se llaman para convertir entre la codificación y UTF-8. Las codificaciones creadas por Tcl_CreateEncoding son a partir de entonces visibles en la base de datos utilizada por Tcl_GetEncoding. Al igual que con el procedimiento Tcl_GetEncoding, el valor de retorno es un token que representa la codificación y puede utilizarse en llamadas posteriores a otras funciones de codificación. Tcl_CreateEncoding devuelve una codificación con un recuento de referencias de 1. Si ya existe una codificación con el nombre especificado name, su entrada en la base de datos se reemplaza por la nueva codificación; el token de la codificación antigua seguirá siendo válido y continuará comportándose como antes, pero los usuarios del nuevo token ahora llamarán a los nuevos procedimientos de codificación.

El argumento typePtr a Tcl_CreateEncoding contiene información sobre el nombre de la codificación y los procedimientos que se llamarán para convertir entre esta codificación y UTF-8. Se define de la siguiente manera:

typedef struct Tcl_EncodingType {
    const char *encodingName;
    Tcl_EncodingConvertProc *toUtfProc;
    Tcl_EncodingConvertProc *fromUtfProc;
    Tcl_EncodingFreeProc *freeProc;
    ClientData clientData;
    int nullSize;
} Tcl_EncodingType;

encodingName proporciona un nombre de cadena para la codificación, por el cual se puede referir en otros procedimientos como Tcl_GetEncoding. toUtfProc se refiere a un procedimiento de devolución de llamada para invocar a fin de convertir texto de esta codificación a UTF-8. fromUtfProc se refiere a un procedimiento de devolución de llamada para invocar a fin de convertir texto de UTF-8 a esta codificación. freeProc se refiere a un procedimiento de devolución de llamada para invocar cuando se elimina esta codificación. El campo freeProc puede ser NULL. clientData contiene un valor arbitrario de una palabra pasado a toUtfProc, fromUtfProc y freeProc siempre que se llamen. Típicamente, este es un puntero a una estructura de datos que contiene información específica de la codificación que pueden utilizar los procedimientos de devolución de llamada. Por ejemplo, dos codificaciones muy similares como ascii y macRoman pueden utilizar el mismo procedimiento de devolución de llamada, pero usar diferentes valores de clientData para controlar su comportamiento. nullSize especifica el número de bytes cero que significan fin de cadena en esta codificación. Debe ser 1 (para codificaciones de un solo byte o multibyte como ASCII o Shift-JIS) o 2 (para codificaciones de doble byte como Unicode). Las codificaciones de tamaño constante con 3 o más bytes por carácter (como CNS11643) no se aceptan.

Los procedimientos de devolución de llamada toUtfProc y fromUtfProc deben coincidir con el tipo Tcl_EncodingConvertProc:

typedef int Tcl_EncodingConvertProc(
        ClientData clientData,
        const char *src,
        int srcLen,
        int flags,
        Tcl_EncodingState *statePtr,
        char *dst,
        int dstLen,
        int *srcReadPtr,
        int *dstWrotePtr,
        int *dstCharsPtr);

Los procedimientos toUtfProc y fromUtfProc son llamados por la familia de funciones Tcl_ExternalToUtf o Tcl_UtfToExternal para realizar la conversión real. El parámetro clientData a estos procedimientos es el mismo que el campo clientData especificado a Tcl_CreateEncoding cuando se creó la codificación. Los argumentos restantes a los procedimientos de devolución de llamada son los mismos que los argumentos, documentados en la parte superior, de Tcl_ExternalToUtf o Tcl_UtfToExternal, con las siguientes excepciones. Si el argumento srcLen a una de esas funciones de alto nivel es negativo, el valor pasado al procedimiento de devolución de llamada será la longitud de cadena específica de la codificación apropiada de src. Si alguno de los argumentos srcReadPtr, dstWrotePtr o dstCharsPtr a una de las funciones de alto nivel es NULL, el valor correspondiente pasado al procedimiento de devolución de llamada será una ubicación no NULL.

El procedimiento de devolución de llamada freeProc, si no es NULL, debe coincidir con el tipo Tcl_EncodingFreeProc:

typedef void Tcl_EncodingFreeProc(
        ClientData clientData);

Esta función freeProc se llama cuando se elimina la codificación. El parámetro clientData es el mismo que el campo clientData especificado a Tcl_CreateEncoding cuando se creó la codificación.

Tcl_GetEncodingSearchPath y Tcl_SetEncodingSearchPath se llaman para acceder y establecer la lista de directorios del sistema de archivos que se buscan para los archivos de datos de codificación.

El valor devuelto por Tcl_GetEncodingSearchPath es el valor almacenado por la última llamada exitosa a Tcl_SetEncodingSearchPath. INTRODUCTION

This manual page describes functions for converting between Tcl's internal Unicode representation and external byte-based encodings. It also describes functions for managing the list of directories Tcl searches for encoding data files, and functions for loading and managing encodings.

DESCRIPTION

External encodings are byte-based representations of character sets. Tcl's internal representation is Unicode, a superset of virtually all common external encodings. The functions described here allow Tcl to convert between these two representations.

Tcl_ExternalToUtfDString converts a string in an external encoding into Tcl's internal UTF-8 representation. The src argument is a pointer to the source string, and srcLen is its length in bytes. The converted string is appended to the Tcl_DString referenced by dstPtr. If an error occurs during conversion (e.g., an invalid byte sequence), an error message is left in interp and the function returns 0. Otherwise, it returns a non-zero value.

Tcl_UtfToExternalDString converts a string in Tcl's internal UTF-8 representation into an external encoding. The arguments are the same as for Tcl_ExternalToUtfDString. The conversion uses the encoding specified by encodingName. If an error occurs, an error message is left in interp and the function returns 0. Otherwise, it returns a non-zero value.

Tcl_GetEncodingSearchPath returns the current search path for encoding data files. The path is returned as a newly allocated string, which is the responsibility of the caller to free using Tcl_Free. If no path has been set, an empty string is returned. If an error occurs, an error message is left in interp and NULL is returned.

Tcl_SetEncodingSearchPath sets the search path for encoding data files. The path argument is a string containing a list of directories, separated by colons. Tcl will search these directories in order when looking for encoding data files. Directories in the path

Tcl_GetDefaultEncodingDir and Tcl_SetDefaultEncodingDir are obsolete interfaces best replaced with calls to Tcl_GetEncodingSearchPath and Tcl_SetEncodingSearchPath. They are called to access and set the first element of the searchPath list. Since Tcl searches searchPath for encoding data files in list order, these routines establish the “default” directory in which to find encoding data files.

ENCODING FILES

Space would prohibit precompiling into Tcl every possible encoding algorithm, so many encodings are stored on disk as dynamically-loadable encoding files. This behavior also allows the user to create additional encoding files that can be loaded using the same mechanism. These encoding files contain information about the tables and/or escape sequences used to map between an external encoding and Unicode. The external encoding may consist of single-byte, multi-byte, or double-byte characters.

Each dynamically-loadable encoding is represented as a text file. The initial line of the file, beginning with a “#” symbol, is a comment that provides a human-readable description of the file. The next line identifies the type of encoding file. It can be one of the following letters:

[1] S
A single-byte encoding, where one character is always one byte long in the encoding. An example is iso8859-1, used by many European languages.
[2] D
A double-byte encoding, where one character is always two bytes long in the encoding. An example is big5, used for Chinese text.
[3] M
A multi-byte encoding, where one character may be either one or two bytes long. Certain bytes are lead bytes, indicating that another byte must follow and that together the two bytes represent one character. Other bytes are not lead bytes and represent themselves. An example is shiftjis, used by many Japanese computers.
[4] E
An escape-sequence encoding, specifying that certain sequences of bytes do not represent characters, but commands that describe how following bytes should be interpreted.

The rest of the lines in the file depend on the type.

Cases [1], [2], and [3] are collectively referred to as table-based encoding files. The lines in a table-based encoding file are in the same format as this example taken from the shiftjis encoding (this is not the complete file):

The third line of the file is three numbers. The first number is the fallback character (in base 16) to use when converting from UTF-8 to this encoding. The second number is a 1 if this file represents the encoding for a symbol font, or 0 otherwise. The last number (in base 10) is how many pages of data follow.

Subsequent lines in the example above are pages that describe how to map from the encoding into 2-byte Unicode. The first line in a page identifies the page number. Following it are 256 double-byte numbers, arranged as 16 rows of 16 numbers. Given a character in the encoding, the high byte of that character is used to select which page, and the low byte of that character is used as an index to select one of the double-byte numbers in that page - the value obtained being the corresponding Unicode character. By examination of the example above, one can see that the characters 0x7E and 0x8163 in shiftjis map to 203E and 2026 in Unicode, respectively.

Following the first page will be all the other pages, each in the same format as the first: one number identifying the page followed by 256 double-byte Unicode characters. If a character in the encoding maps to the Unicode character 0000, it means that the character does not actually exist. If all characters on a page would map to 0000, that page can be omitted.

Case [4] is the escape-sequence encoding file. The lines in an this type of file are in the same format as this example taken from the iso2022-jp encoding:

# Encoding file: iso2022-jp, escape-driven
E
init		{}
final		{}
iso8859-1	\x1b(B
jis0201		\x1b(J
jis0208		\x1b$@
jis0208		\x1b$B
jis0212		\x1b$(D
gb2312		\x1b$A
ksc5601		\x1b$(C

In the file, the first column represents an option and the second column is the associated value. init is a string to emit or expect before the first character is converted, while final is a string to emit or expect after the last character. All other options are names of table-based encodings; the associated value is the escape-sequence that marks that encoding. Tcl syntax is used for the values; in the above example, for instance, “{}” represents the empty string and “\x1b” represents character 27.

Tcl_LoadEncoding loads an encoding file. It is called by Tcl_GetEncoding when it encounters an encoding name that has not yet been loaded. encodingName is the name of the encoding to load, and encodingFile is the path to the file containing the encoding data. clientData is passed to the encoding file's initialization routine. Returns 0 on success, or -1 on error (in which case an error message is left in interp).

Tcl_GetEncoding returns a handle to an encoding structure corresponding to encodingName. If the encoding is already loaded, its handle is returned immediately. Otherwise, Tcl searches the encoding search path for an encoding file named encodingName.enc. If found, the encoding is loaded using Tcl_LoadEncoding. If the encoding cannot be found or loaded, an error message is left in interp and NULL is returned. The returned handle is valid until Tcl_FreeEncoding is called with it.

Tcl_FreeEncoding decrements the reference count for the encoding specified by encoding. If the reference count drops to zero, the encoding is unloaded and its resources are freed.

Tcl_NameOfEncoding returns the name associated with the encoding handle encoding. This is the name that was originally used to load the encoding.

Tcl_GetEncodingFromUserWorld is similar to Tcl_GetEncoding, but it first attempts to use the user's default character set if encodingName is NULL or empty.

Tcl_SetDefaultCharSet sets the default character set for the interpreter to encodingName. This character set is used by Tcl_GetEncodingFromUserWorld when no specific encoding is requested.

Tcl_GetDefaultCharSet returns the name of the default character set for the interpreter.

Tcl_GetEncodingCharSet returns the name of the character set associated with the encoding specified by encodingName. The character set name is stored in the Tcl_Obj pointed to by charSetPtr. Returns 0 on success, or -1 on error.
