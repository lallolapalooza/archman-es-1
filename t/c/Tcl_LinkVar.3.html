NOMBRE

Tcl_LinkVar, Tcl_UnlinkVar, Tcl_UpdateLinkedVar - vincular variable Tcl a variable C

SINOPSIS

#include <tcl.h>

int
Tcl_LinkVar(interp, varName, addr, type)

Tcl_UnlinkVar(interp, varName)

Tcl_UpdateLinkedVar(interp, varName)

ARGUMENTOS

Tcl_Interp *interp (entrada)
Intérprete que contiene varName. También es utilizado por Tcl_LinkVar para devolver mensajes de error.
const char *varName (entrada)
Nombre de la variable global.
char *addr (entrada)
Dirección de la variable C que se vinculará a varName.
int type (entrada)
Tipo de la variable C. Debe ser uno de TCL_LINK_INT, TCL_LINK_UINT, TCL_LINK_CHAR, TCL_LINK_UCHAR, TCL_LINK_SHORT, TCL_LINK_USHORT, TCL_LINK_LONG, TCL_LINK_ULONG, TCL_LINK_WIDE_INT, TCL_LINK_WIDE_UINT, TCL_LINK_FLOAT, TCL_LINK_DOUBLE, TCL_LINK_BOOLEAN, o TCL_LINK_STRING, opcionalmente combinado con TCL_LINK_READ_ONLY para hacer que la variable Tcl sea de solo lectura.

DESCRIPCIÓN

Tcl_LinkVar utiliza trazas de variables para mantener la variable Tcl llamada varName sincronizada con la variable C en la dirección dada por addr. Cada vez que se lee la variable Tcl, se devolverá el valor de la variable C, y cada vez que se escribe la variable Tcl, la variable C se actualizará para tener el mismo valor. Tcl_LinkVar normalmente devuelve TCL_OK; si ocurre un error al establecer el vínculo (por ejemplo, porque varName es el nombre de un arreglo) entonces se devuelve TCL_ERROR y el resultado del intérprete contiene un mensaje de error.

El argumento type especifica el tipo de la variable C y debe tener uno de los siguientes valores, opcionalmente combinado con TCL_LINK_READ_ONLY:

TCL_LINK_INT
La variable C es de tipo int. Cualquier valor escrito en la variable Tcl debe tener una forma entera adecuada aceptable para Tcl_GetIntFromObj; los intentos de escribir valores no enteros en varName serán rechazados con errores de Tcl. Las representaciones enteras incompletas (como la cadena vacía, '+', '-' o el prefijo hexadecimal/octal/binario) también se aceptan como si fueran válidas.
TCL_LINK_UINT
La variable C es de tipo unsigned int. Cualquier valor escrito en la variable Tcl debe tener una forma entera sin signo adecuada aceptable para Tcl_GetWideIntFromObj y dentro del rango definido por la plataforma para el tipo unsigned int; los intentos de escribir valores no enteros (o valores fuera de rango) en varName serán rechazados con errores de Tcl. Las representaciones enteras incompletas (como la cadena vacía, '+', '-' o el prefijo hexadecimal/octal/binario) también se aceptan como si fueran válidas.
TCL_LINK_CHAR
La variable C es de tipo char. Cualquier valor escrito en la variable Tcl debe tener una forma entera adecuada aceptable para Tcl_GetIntFromObj y estar dentro del rango del tipo de dato char; los intentos de escribir valores no enteros o fuera de rango en varName serán rechazados con errores de Tcl. Las representaciones enteras incompletas (como la cadena vacía, '+', '-' o el prefijo hexadecimal/octal/binario) también se aceptan como si fueran válidas.
TCL_LINK_UCHAR
La variable C es de tipo unsigned char. Cualquier valor escrito en la variable Tcl debe tener una forma entera sin signo adecuada aceptable para Tcl_GetIntFromObj y dentro del rango definido por la plataforma para el tipo unsigned char; los intentos de escribir valores no enteros (o valores fuera de rango) en varName serán rechazados con errores de Tcl. Las representaciones enteras incompletas (como la cadena vacía, '+', '-' o el prefijo hexadecimal/octal/binario) también se aceptan como si fueran válidas.
TCL_LINK_SHORT
La variable C es de tipo short. Cualquier valor escrito en la variable Tcl debe tener una forma entera adecuada aceptable para Tcl_GetIntFromObj y estar dentro del rango del tipo de dato short; los intentos de escribir valores no enteros o fuera de rango en varName serán rechazados con errores de Tcl. Las representaciones enteras incompletas (como la cadena vacía, '+', '-' o el prefijo hexadecimal/octal/binario) también se aceptan como si fueran válidas.
TCL_LINK_USHORT
La variable C es de tipo unsigned short. Cualquier valor escrito en la variable Tcl debe tener una forma entera sin signo adecuada aceptable para Tcl_GetIntFromObj y dentro del rango definido por la plataforma para el tipo unsigned short; los intentos de escribir valores no enteros (o valores fuera de rango) en varName serán rechazados con errores de Tcl. Las representaciones enteras incompletas (como la cadena vacía, '+', '-' o el prefijo hexadecimal/octal/binario) también se aceptan como si fueran válidas.
TCL_LINK_LONG
La variable C es de tipo long. Cualquier valor escrito en la variable Tcl debe tener una forma entera adecuada aceptable para Tcl_GetLongFromObj; los intentos de escribir valores no enteros o fuera de rango en varName serán rechazados con errores de Tcl. Las representaciones enteras incompletas (como la cadena vacía, '+', '-' o el prefijo hexadecimal/octal/binario) también se aceptan como si fueran válidas.
TCL_LINK_ULONG
La variable C es de tipo unsigned long. Cualquier valor escrito en la variable Tcl debe tener una forma entera sin signo adecuada aceptable para Tcl_GetWideIntFromObj y dentro del rango definido por la plataforma para el tipo unsigned long; los intentos de escribir valores no enteros (o valores fuera de rango) en varName serán rechazados con errores de Tcl. Las representaciones enteras incompletas (como la cadena vacía, '+', '-' o el prefijo hexadecimal/octal/binario) también se aceptan como si fueran válidas.
TCL_LINK_DOUBLE
La variable C es de tipo double. Cualquier valor escrito en la variable Tcl debe tener una forma real adecuada aceptable para Tcl_GetDoubleFromObj; los intentos de escribir valores no reales en varName serán rechazados con errores de Tcl. Las representaciones enteras o reales incompletas (como la cadena vacía, '.', '+', '-' o el prefijo hexadecimal/octal/binario) también se aceptan como si fueran válidas.
TCL_LINK_FLOAT
La variable C es de tipo float. Cualquier valor escrito en la variable Tcl debe tener una forma real adecuada aceptable para Tcl_GetDoubleFromObj y debe estar dentro del rango aceptable para un float; los intentos de escribir valores no reales (o valores fuera de rango) en varName serán rechazados con errores de Tcl. Las representaciones enteras o reales incompletas (como la cadena vacía, '.', '+', '-' o el prefijo hexadecimal/octal/binario) también se aceptan como si fueran válidas.
TCL_LINK_WIDE_INT
La variable C es de tipo Tcl_WideInt (que es un tipo entero de al menos 64 bits en todas las plataformas que pueden soportarlo.) Cualquier valor escrito en la variable Tcl debe tener una forma entera adecuada aceptable para Tcl_GetWideIntFromObj; los intentos de escribir valores no enteros en varName serán rechazados con errores de Tcl. Las representaciones enteras incompletas (como la cadena vacía, '+', '-' o el prefijo hexadecimal/octal/binario) también se aceptan como si fueran válidas.
TCL_LINK_WIDE_UINT
La variable C es de tipo Tcl_WideUInt (que es un tipo entero sin signo de al menos 64 bits en todas las plataformas que pueden soportarlo.) Cualquier valor escrito en la variable Tcl debe tener una forma entera sin signo adecuada aceptable para Tcl_GetWideIntFromObj (se convertirá a sin signo); los intentos de escribir valores no enteros en varName serán rechazados con errores de Tcl. Las representaciones enteras incompletas (como la cadena vacía, '+', '-' o el prefijo hexadecimal/octal/binario) también se aceptan como si fueran válidas.
TCL_LI
La variable C es de tipo bool. Cualquier valor escrito en la variable Tcl debe tener una forma booleana adecuada aceptable para Tcl_GetBooleanFromObj; los intentos de escribir valores no booleanos en varName serán rechazados con errores de Tcl. Los valores de cadena "0" y "1" y los valores de cadena que representan a los enteros 0 y 1 (como "0", "1", "true", "false", "yes", "no", etc.) son aceptados como válidos.
TCL_LINK_STRING
La variable C es de tipo char *. El valor de la variable Tcl se copiará en el búfer C. Si el valor es demasiado largo para caber en el búfer C, se generará un error de Tcl. El búfer C no se puede liberar automáticamente y el usuario es responsable de administrar su memoria. Si se escribe una cadena vacía en la variable Tcl, se copia una cadena vacía en el búfer C. Si se escribe en la variable Tcl un valor que no es una cadena, se convertirá a una cadena antes de copiarse.
Si desea vincular una cadena Tcl a una variable C de tipo char*, pero quiere que el sistema Tcl maneje la asignación y liberación de memoria de la cadena, entonces debe usar TCL_LINK_STRING y asegurarse de que la variable C sea un puntero a un puntero de tipo char**. Tcl se encargará de liberar la memoria anterior (si la hay) y de asignar nueva memoria para la cadena vinculada. Si addr apunta a un char**, entonces la memoria se asignará con Tcl_Alloc y se liberará con Tcl_Free.

El marcador TCL_LINK_READ_ONLY se puede combinar (usando el operador bit a bit OR) con cualquiera de los tipos anteriores para hacer que la variable Tcl vinculada sea de solo lectura. Si un intento de escribir en una variable de solo lectura se detecta, se generará un error de Tcl.

Tcl_UnlinkVar elimina el vínculo entre la variable Tcl llamada varName y la variable C correspondiente. Después de llamar a esto, los cambios en la variable Tcl ya no afectarán a la variable C, y vice versa.

Tcl_UpdateLinkedVar se puede usar para forzar una actualización de la variable C desde la variable Tcl. Normalmente no es necesario llamar a esto porque el vínculo se mantiene automáticamente mediante trazas de variable.

EJEMPLO

Aquí hay un ejemplo de cómo vincular una variable Tcl llamada "myCounter" a una variable C de tipo int:

int myCounter = 10;
if (Tcl_LinkVar(interp, "myCounter", (char*)&myCounter, TCL_LINK_INT) == TCL_ERROR) {
    // Error handling
}

Ahora, si ejecuta el comando Tcl:

puts $myCounter

Imprimirá "10". Si ejecuta:

set myCounter 20

El valor de la variable C `myCounter` se actualizará a 20.

NAME

Tcl_LinkVar — link a Tcl variable to a C variable

SYNOPSIS

#include <tcl.h>

int
Tcl_LinkVar(interp, varName, varAddr, type);
void
Tcl_UnlinkVar(interp, varName);
int
Tcl_UpdateLinkedVar(interp, varName);

ARGUMENTS

Tcl_Interp *interp
Interpreter to create variable in.
const char *varName
Name of Tcl variable to link.
char *varAddr
Address of C variable.
int type
Type of C variable and linking behavior.

DESCRIPTION

The Tcl_LinkVar procedure creates a Tcl variable with name varName in the interpreter interp. The Tcl variable is linked to the C variable whose address is given by varAddr. The link is controlled by the type argument, which is a bit mask.

The following bits may be used in type:

TCL_LINK_INT
The C variable is of type int. It will be read from Tcl as an integer. Whenever the Tcl variable is modified, the C variable will be updated to the new integer value.
TCL_LINK_DOUBLE
The C variable is of type double. It will be read from Tcl as a floating-point number. Whenever the Tcl variable is modified, the C variable will be updated to the new floating-point value.
TCL_LINK_BOOLEAN
The C variable is of type int. If its value is zero then it will read from Tcl as “0”; otherwise it will read from Tcl as “1”. Whenever varName is modified, the C variable will be set to a 0 or 1 value. Any value written into the Tcl variable must have a proper boolean form acceptable to Tcl_GetBooleanFromObj; attempts to write non-boolean values into varName will be rejected with Tcl errors.
TCL_LINK_STRING
The C variable is of type char *. If its value is not NULL then it must be a pointer to a string allocated with Tcl_Alloc or ckalloc. Whenever the Tcl variable is modified the current C string will be freed and new memory will be allocated to hold a copy of the variable's new value. If the C variable contains a NULL pointer then the Tcl variable will read as “NULL”.

If the TCL_LINK_READ_ONLY flag is present in type then the variable will be read-only from Tcl, so that its value can only be changed by modifying the C variable. Attempts to write the variable from Tcl will be rejected with errors.

Tcl_UnlinkVar removes the link previously set up for the variable given by varName. If there does not exist a link for varName then the procedure has no effect.

Tcl_UpdateLinkedVar may be invoked after the C variable has changed to force the Tcl variable to be updated immediately. In many cases this procedure is not needed, since any attempt to read the Tcl variable will return the latest value of the C variable. However, if a trace has been set on the Tcl variable (such as a Tk widget that wishes to display the value of the variable), the trace will not trigger when the C variable has changed. Tcl_UpdateLinkedVar ensures that any traces on the Tcl variable are invoked.

Note that, as with any call to a Tcl interpreter, Tcl_UpdateLinkedVar must be called from the same thread that created the interpreter. The safest mechanism is to ensure that the C variable is only ever updated from the same thread that created the interpreter (possibly in response to an event posted with Tcl_ThreadQueueEvent), but when it is necessary to update the variable in a separate thread, it is advised that Tcl_AsyncMark be used to indicate to the thread hosting the interpreter that it is ready to run Tcl_UpdateLinkedVar.
