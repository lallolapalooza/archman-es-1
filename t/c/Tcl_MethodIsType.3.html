DESCRIPCION

Un método es una operación que se lleva a cabo sobre un objeto y que está asociado a dicho objeto. Cada método debe estar adjunto a un objeto o a una clase; los métodos adjuntos a una clase están asociados con todas las instancias (directas e indirectas) de esa clase.

Dado un método, la entidad que lo declaró se puede encontrar usando Tcl_MethodDeclarerClass, que devuelve la clase a la que está adjunto el método (o NULL si el método no está adjunto a ninguna clase), y Tcl_MethodDeclarerObject, que devuelve el objeto al que está adjunto el método (o NULL si el método no está adjunto a un objeto). El nombre del método se puede recuperar con Tcl_MethodName y si el método está exportado se recupera con Tcl_MethodIsPublic. El tipo del método también se puede introspeccionar hasta cierto punto; la función Tcl_MethodIsType devuelve si un método es de un tipo particular, asignando el clientData por método a la variable apuntada por clientDataPtr si (que no sea NULL) si el tipo coincide.

CREACIÓN DE MÉTODOS

Los métodos se crean mediante Tcl_NewMethod y Tcl_NewInstanceMethod, que crean un método adjunto a una clase o a un objeto, respectivamente. En ambos casos, el argumento nameObj da el nombre del método a crear, el argumento isPublic indica si el método debe exportarse inicialmente, el argumento methodTypePtr describe la implementación del método (ver la sección TIPOS DE MÉTODOS a continuación) y el argumento clientData proporciona algunos datos específicos de la implementación que se pasan a la implementación del método cuando se llama.

Cuando el argumento nameObj de Tcl_NewMethod es NULL, se crea un método sin nombre, que se utiliza para constructores y destructores. Los constructores deben instalarse en su clase usando la función Tcl_ClassSetConstructor, y los destructores (que no deben requerir ningún argumento) deben instalarse en su clase usando la función Tcl_ClassSetDestructor. Los métodos sin nombre no deben usarse para ningún otro propósito, y los métodos con nombre no deben usarse como constructores ni destructores. Tenga en cuenta también que un methodTypePtr NULL se utiliza para proporcionar una señalización interna y no debe usarse en código de cliente.

CONTEXTOS DE LLAMADA A MÉTODOS

Cuando se llama a un método, se pasa una referencia de contexto de llamada a método como uno de los argumentos de la función de implementación. Este contexto se puede inspeccionar para proporcionar información sobre el llamador, pero no debe conservarse más allá del momento en que finaliza la llamada al método.

El método que se está llamando se puede recuperar del contexto usando Tcl_ObjectContextMethod, y el objeto que provocó la invocación del método se puede recuperar con Tcl_ObjectContextObject. El número de argumentos que se deben omitir (por ejemplo, el nombre del objeto y el nombre del método en una llamada a método normal) se lee con Tcl_ObjectContextSkippedArgs, y el contexto también puede informar si está funcionando como un filtro para otro método a través de Tcl_ObjectContextIsFiltering.

Durante la ejecución de un método, la implementación del método puede optar por invocar las etapas de la cadena de llamada a método que vienen después de la implementación del método actual. Esto (el núcleo del comando next) se hace usando Tcl_ObjectContextInvokeNext. Tenga en cuenta que esta función no manipula la pila de marcos de llamada, a diferencia del comando next; si la implementación del método ha introducido uno o más marcos adicionales en la pila como parte de su implementación, también es responsable de eliminar temporalmente esos marcos de la pila mientras se ejecuta la función Tcl_ObjectContextInvokeNext. Tenga en cuenta también que el contexto de llamada a método *nunca* se elimina durante la ejecución de esta función.

TIPOS DE MÉTODOS

Los tipos de métodos se describen mediante un puntero a una estructura Tcl_MethodType, que se define como:

typedef struct {
    int version;
    const char *name;
    Tcl_MethodCallProc *callProc;
    Tcl_MethodDeleteProc *deleteProc;
    Tcl_CloneProc *cloneProc;
} Tcl_MethodType;

El campo version permite la expansión futura de la estructura y siempre debe declararse igual a TCL_OO_METHOD_VERSION_CURRENT. El campo name proporciona un nombre legible por humanos para el tipo y es el valor que se expone a través de los comandos de Tcl info class methodtype e info object methodtype.

El campo callProc proporciona una función que se llama cuando se invoca el método; nunca debe ser NULL.

El campo deleteProc proporciona una función que se utiliza para eliminar un método particular y se llama cuando el método se reemplaza o se elimina; si el campo es NULL, se asume que el clientData del método no necesita ninguna acción especial para eliminarse.

El campo cloneProc es una función que se utiliza para copiar el clientData de un método (como parte de Tcl_CopyObjectInstance) o NULL para indicar que el clientData se puede copiar directamente.

NAME

DESCRIPTION

TclOO provides a system for creating and manipulating objects and classes. Methods are fundamental to this system, encapsulating behavior that can be invoked on objects. The procedures described here allow C code to interact with TclOO's method system.

Tcl_MethodIsType checks if the given method associated with the object belongs to the specified method typeName. It returns 1 if the method is of the specified type, and 0 otherwise.

Tcl_NewMethod creates a new method named methodName for the given object. The method's behavior is defined by the callProc function pointer, which is invoked when the method is called. The clientData argument is arbitrary data that is passed to both callProc and deleteProc. The deleteProc is called when the method is destroyed, either explicitly or when the object itself is destroyed. It is used to free any resources associated with the method. This is the generic method creation function.

Tcl_NewNamespaceMethod creates a new method named methodName for the given object. This method executes the Tcl script provided in scriptPtr when called. The deleteProc and clientData arguments serve the same purpose as in Tcl_NewMethod.

Tcl_NewInstanceMethod creates a new method named methodName for the given object. This method is intended to be called on instances of the object's class. The callProc, deleteProc, and clientData arguments are used as described for Tcl_NewMethod.

The procedures Tcl_MethodCallProc, Tcl_MethodDeleteProc, and Tcl_CloneProc define the signatures for the callback functions used by the TclOO method system.

METHOD TYPES

TCL_METHODCALLPROC FUNCTION SIGNATURE

Functions matching this signature are called when the method is invoked.

typedef int Tcl_MethodCallProc(
        ClientData clientData,
        Tcl_Interp *interp,
        Tcl_ObjectContext objectContext,
        int objc,
        Tcl_Obj *const *objv);

The clientData argument to a Tcl_MethodCallProc is the value that was given when the method was created, the interp is a place in which to execute scripts and access variables as well as being where to put the result of the method, and the objc and objv fields give the parameter objects to the method. The calling context of the method can be discovered through the objectContext argument, and the return value from a Tcl_MethodCallProc is any Tcl return code (e.g. TCL_OK, TCL_ERROR).

TCL_METHODDELETEPROC FUNCTION SIGNATURE

Functions matching this signature are used when a method is deleted, whether through a new method being created or because the object or class is deleted.

typedef void Tcl_MethodDeleteProc(
        ClientData clientData);

The clientData argument to a Tcl_MethodDeleteProc will be the same as the value passed to the clientData argument to Tcl_NewMethod or Tcl_NewInstanceMethod when the method was created.

TCL_CLONEPROC FUNCTION SIGNATURE

Functions matching this signature are used to copy a method when the object or class is copied using Tcl_CopyObjectInstance (or oo::copy).

typedef int Tcl_CloneProc(
        Tcl_Interp *interp,
        ClientData oldClientData,
        ClientData *newClientDataPtr);

The interp argument gives a place to write an error message when the attempt to clone the object is to fail, in which case the clone procedure must also return TCL_ERROR; it should return TCL_OK otherwise. The oldClientData field to a Tcl_CloneProc gives the value from the method being copied from, and the newClientDataPtr field will point to a variable in which to write the value for the method being copied to.
