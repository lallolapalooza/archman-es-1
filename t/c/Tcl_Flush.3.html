ARGUMENTOS

Tcl_Interp *interp (entrada)
Se utiliza para la notificación de errores y para buscar un canal registrado en él.
const char *fileName (entrada)
El nombre de un archivo local o de red.
const char *mode (entrada)
Especifica cómo se debe acceder al archivo. Puede tener cualquiera de los valores permitidos para el argumento mode del comando Tcl open.
int permissions (entrada)
Indicadores de permisos estilo POSIX como 0644. Si se crea un nuevo archivo, estos permisos se establecerán en el archivo creado.
int argc (entrada)
El número de elementos en argv.
const char **argv (entrada)
Argumentos para construir una tubería de comandos. Estos valores tienen el mismo significado que los argumentos que no son de opción para el comando Tcl exec.
int flags (entrada)
Especifica la disposición de los manejadores stdio en la tubería: combinación OR de TCL_STDIN, TCL_STDOUT, TCL_STDERR y TCL_ENFORCE_MODE. Si TCL_STDIN está establecido, la entrada estándar para el primer hijo en la tubería es el canal de la tubería, de lo contrario es la misma que la entrada estándar del proceso invocador; lo mismo ocurre para TCL_STDOUT y TCL_STDERR. Si TCL_ENFORCE_MODE no está establecido, entonces la tubería puede redirigir los manejadores stdio para anular los manejadores stdio para los cuales se han establecido TCL_STDIN, TCL_STDOUT y TCL_STDERR. Si está establecido, entonces tales redirecciones causan un error.
ClientData handle (entrada)
Manejador específico del sistema operativo para E/S a un archivo. Para Unix es un descriptor de archivo, para Windows es un HANDLE.
int readOrWrite (entrada)
Combinación OR de TCL_READABLE y TCL_WRITABLE para indicar qué operaciones son válidas en handle.
const char *channelName (entrada)
El nombre del canal.
int *modePtr (salida)
Punta a una variable entera que recibirá una combinación OR de TCL_READABLE y TCL_WRITABLE indicando si el canal está abierto para lectura y escritura.
const char *pattern (entrada)
El patrón a coincidir, pasado a Tcl_StringMatch, o NULL.
Tcl_Channel channel (entrada)
Un canal Tcl para entrada o salida. Debe haber sido el valor de retorno de un procedimiento como Tcl_OpenFileChannel.
Tcl_Obj *readObjPtr (entrada/salida)
Un puntero a un valor Tcl en el que se almacenarán los caracteres leídos del canal.
int charsToRead (entrada)
El número de caracteres a leer del canal. Si la codificación del canal es binary, esto es equivalente al número de bytes a leer del canal.
int appendFlag (entrada)
Si es distinto de cero, los datos leídos del canal se añadirán al valor. De lo contrario, los datos reemplazarán el contenido existente del valor.
char *readBuf (salida)
Un búfer en el que se almacenarán los bytes leídos del canal.
int bytesToRead (entrada)
El número de bytes a leer del canal. El búfer readBuf debe ser lo suficientemente grande para contener esta cantidad de bytes.
Tcl_Obj *lineObjPtr (entrada/salida)
Un puntero a un valor Tcl en el que se almacenará la línea leída del canal. La línea leída se añadirá al valor actual del valor.
Tcl_DString *lineRead (entrada/salida)
Un puntero a una cadena dinámica Tcl en la que se almacenará la línea leída del canal. Debe haber sido inicializada por el llamador. La línea leída se añadirá a cualquier dato que ya esté en la cadena dinámica.
const char *input (entrada)
La entrada a añadir a un búfer de canal.
int inputLen (entrada)
Longitud de la entrada
int addAtEnd (entrada)
Indicador que indica si la entrada debe añadirse al final o al principio del búfer del canal.
Tcl_Obj *writeObjPtr (entrada)
Un puntero a un valor Tcl cuyo contenido se enviará al canal.
const char *charBuf (entrada)
Un búfer que contiene los caracteres a enviar al canal.
const char *byteBuf (entrada)
Un búfer que contiene los bytes a enviar al canal.
int bytesToWrite (entrada)
El número de bytes a consumir de charBuf o byteBuf y enviarlos al canal.
Tcl_WideInt offset (entrada)
Cuánto mover el punto de acceso en el canal en el que se aplicará la próxima operación de entrada o salida, medido en bytes desde la posición dada por seekMode. Puede ser positivo o negativo.
int seekMode (entrada)
Desde qué punto buscar; se utiliza con offset para calcular el nuevo punto de acceso para el canal. Los valores legales son SEEK_SET, SEEK_CUR y SEEK_END.
Tcl_WideInt length (entrada)
La longitud (no negativa) a la que se truncará el canal.
const char *optionName (entrada)
El nombre de una opción aplicable a este canal, como -blocking. Puede tener cualquiera de los valores aceptados por el comando fconfigure.
Tcl_DString *optionValue (entrada)
Dónde almacenar el valor de una opción o una lista de todas las opciones y sus valores. Debe haber sido inicializado por el llamador.
const char *newValue (entrada)
Nuevo valor para la opción dada por optionName.

DESCRIPCIÓN

El mecanismo de canales de Tcl proporciona un mecanismo independiente de dispositivo y plataforma para realizar operaciones de entrada y salida con búfer en una variedad de tipos de archivos, sockets y dispositivos. El mecanismo de canales es extensible a nuevos tipos de canales, proporcionando un controlador de canal de bajo nivel para el nuevo tipo; la interfaz del controlador de canal se describe en la entrada del manual para Tcl_CreateChannel. El mecanismo de canales proporciona un esquema de almacenamiento en búfer modelado según la E/S estándar de Unix, y también permite E/S no bloqueantes en canales.

Los procedimientos descritos en esta entrada del manual comprenden las API de C de la capa genérica de la arquitectura de canales. Para una descripción de la arquitectura del controlador de canales y cómo implementar controladores de canales para nuevos tipos de canales, consulte la entrada del manual para Tcl_CreateChannel.

TCL_OPENFILECHANNEL

Abre un canal para la entrada y/o salida asociada con un archivo local o de red especificado por fileName. El argumento mode es una cadena que especifica cómo se debe acceder al archivo; puede tener cualquiera de los valores permitidos para el argumento mode del comando Tcl open (por ejemplo, "r", "w", "rb", "a+", etc.). El argumento permissions se utiliza para establecer los permisos del archivo si se crea un nuevo archivo; se utiliza un valor de 0644 si permissions es -1. Si la operación es exitosa, se devuelve un identificador de canal. Si falla, se devuelve NULL y se genera una excepción de Tcl en interp.

TCL_OPENCOMMANDCHANNEL

Abre un canal de tubería para la entrada y salida asociadas con un proceso externo que se crea mediante la invocación de un comando. El comando a invocar se especifica mediante el argumento argv, que es una lista de cadenas que representan el nombre del comando y sus argumentos. El argumento argc es el número de elementos en argv. El argumento flags especifica qué manejadores estándar (entrada, salida, error) del proceso hijo deben conectarse a la tubería y si se debe forzar la coincidencia de modo. Vea la entrada del manual para el comando Tcl exec para obtener una descripción más detallada de estos argumentos y de cómo se utiliza el sistema operativo para crear un proceso hijo y conectarlo a un conjunto de canales.

La tubería creada se representa mediante un solo canal de Tcl. Si se abre el canal con éxito, se devuelve un identificador de canal. Si falla, se devuelve NULL y se genera una excepción de Tcl en interp.

TCL_MAKEFILECHANNEL

Crea un nuevo canal de Tcl a partir de un manejador de E/S existente proporcionado por el sistema operativo. El argumento handle es el manejador de E/S, que es un descriptor de archivo en Unix y un HANDLE en Windows. El argumento readOrWrite es una combinación OR de las banderas TCL_READABLE y TCL_WRITABLE para indicar si el manejador se puede leer o escribir. Los canales creados de esta manera deben ser registrados explícitamente con Tcl_RegisterChannel para que sean accesibles a través de nombres de canal Tcl.

Si la operación es exitosa, se devuelve un identificador de canal. Si falla, se devuelve NULL.

TCL_GETCHANNEL

Devuelve el identificador de canal asociado con el nombre de canal channelName. El argumento interp se utiliza para buscar el canal registrado en el intérprete de Tcl. El argumento modePtr es opcional; si no es NULL, apuntará a una variable que contendrá una combinación OR de las banderas TCL_READABLE y TCL_WRITABLE para indicar el modo de operación actual del canal.

Si se encuentra el canal, se devuelve su identificador. Si no se encuentra ningún canal con ese nombre, se devuelve NULL.

TCL_GETCHANNELNAMES

Rellena el valor del objeto de resultado de interp con una lista de todos los nombres de canal actualmente registrados en el intérprete de Tcl. Los canales estándar (entrada, salida y error estándar) siempre estarán en esta lista.

Devuelve TCL_OK si tiene éxito o TCL_ERROR si ocurre un error.

TCL_GETCHANNELNAMESEX

Similar a Tcl_GetChannelNames, pero solo devuelve los nombres de canal que coinciden con el patrón dado por pattern. El patrón se evalúa utilizando la coincidencia de cadenas de Tcl.

Devuelve TCL_OK si tiene éxito o TCL_ERROR si ocurre un error.

TCL_REGISTERCHANNEL

Registra el canal especificado por channel con el intérprete interp, haciéndolo accesible mediante su nombre de canal Tcl. Los canales creados con Tcl_MakeFileChannel o que no se abrieron automáticamente con el comando open deben ser registrados de esta manera.

TCL_UNREGISTERCHANNEL

Anula el registro del canal especificado por channel del intérprete interp. El canal se cierra automáticamente si no se ha cerrado ya. Una vez anulado el registro, el canal ya no es accesible por su nombre de canal Tcl.

Devuelve TCL_OK si tiene éxito o TCL_ERROR si ocurre un error.

TCL_DETACHCHANNEL

Desvincula el canal especificado por channel del intérprete interp. El canal se cierra automáticamente si no se ha cerrado ya. A diferencia de Tcl_UnregisterChannel, esta operación no genera un error si el canal aún no está registrado.

Devuelve TCL_OK si tiene éxito o TCL_ERROR si ocurre un error.

TCL_ISTANDARDCHANNEL

Devuelve verdadero si el canal es uno de los canales estándar de Tcl (entrada, salida o error estándar).

TCL_CLOSE

Cierra el canal especificado por channel. Todos los búferes pendientes se vacían y se liberan los recursos asociados con el canal. Si se ha escrito algo en el canal que aún no se ha vaciado, esto intentará vaciarlo. Si se produce un error durante el cierre, se generará una excepción de Tcl en interp.

Devuelve TCL_OK si tiene éxito o TCL_ERROR si ocurre un error.

TCL_READCHARS

Intenta leer hasta charsToRead caracteres del canal especificado por channel y almacenarlos en el valor Tcl apuntado por readObjPtr. Si appendFlag es distinto de cero, los caracteres leídos se añadirán al final del valor existente; de lo contrario, el valor se establecerá en los caracteres leídos. Si el canal está abierto en modo binario, esto lee bytes en lugar de caracteres.

Devuelve el número de caracteres (o bytes en modo binario) leídos. Si se alcanza el final del archivo antes de leer el número solicitado de caracteres, se devolverá el número de caracteres leídos hasta ese punto. Si se produce un error de E/S, se devolverá -1 y se generará una excepción de Tcl en interp.

TCL_READ

Intenta leer hasta bytesToRead bytes del canal especificado por channel y almacenarlos en el búfer de bytes especificado por readBuf. El búfer readBuf debe ser lo suficientemente grande para almacenar bytesToRead bytes.

Devuelve el número de bytes leídos. Si se alcanza el final del archivo antes de leer el número solicitado de bytes, se devolverá el número de bytes leídos hasta ese punto. Si se produce un error de E/S, se devolverá -1 y se generará una excepción de Tcl en interp.

TCL_GETSOBJ

Intenta leer una línea del canal especificado por channel y almacenarla en el valor Tcl apuntado por lineObjPtr. La línea se lee hasta un carácter de nueva línea, que se lee pero no se incluye en el valor resultante. Si se alcanza el final del archivo antes de leer una nueva línea, se devuelve la línea parcial (o una cadena vacía si el final del archivo se alcanza inmediatamente). Si el canal está abierto en modo binario, esta función leerá hasta un byte de nueva línea (0x0A).

Si se lee una línea completa (incluida la nueva línea), devuelve 1. Si se alcanza el final del archivo antes de leer una nueva línea, devuelve 0. Si se produce un error de E/S, devuelve -1 y se genera una excepción de Tcl en interp.

TCL_GETS

Similar a Tcl_GetsObj, pero lee la línea en una cadena dinámica Tcl especificada por lineRead. El contenido anterior de la cadena dinámica se preserva y la línea leída se anexa.

Devuelve 1 si se lee una línea completa, 0 si se alcanza el final del archivo y -1 si se produce un error de E/S.

TCL_UNGETS

Devuelve la cadena input de longitud inputLen al búfer de entrada del canal especificado por channel. Si addAtEnd es distinto de cero, la entrada se añade al final del búfer; de lo contrario, se añade al principio. Esto es útil para implementar analizadores de entrada que necesitan leer datos adicionales antes de procesar los datos que ya se han leído.

Devuelve TCL_OK si tiene éxito o TCL_ERROR si ocurre un error (por ejemplo, si el canal no está abierto para lectura).

TCL_WRITEISTD

Escribe el contenido del valor Tcl apuntado por writeObjPtr en el canal especificado por channel. Si el canal está abierto en modo binario, se escriben los bytes del valor Tcl; de lo contrario, se escriben los caracteres del valor Tcl.

Devuelve el número de bytes (o caracteres en modo binario) escritos. Si se produce un error de E/S, se devuelve -1 y se genera una excepción de Tcl en interp.

TCL_WRITECHARS

Escribe hasta bytesToWrite caracteres del búfer de caracteres especificado por charBuf en el canal especificado por channel. Si el canal está abierto en modo binario, se escriben los bytes del búfer de caracteres.

Devuelve el número de bytes (o caracteres en modo binario) escritos. Si se alcanza la capacidad del búfer de salida o se produce un error de E/S, se devuelve el número de bytes escritos hasta ese punto. Si se produce un error de E/S, se devuelve -1 y se genera una excepción de Tcl en interp.

TCL_WRITE

Escribe hasta bytesToWrite bytes del búfer de bytes especificado por byteBuf en el canal especificado por channel.

Devuelve el número de bytes escritos. Si se alcanza la capacidad del búfer de salida o se produce un error de E/S, se devuelve el número de bytes escritos hasta ese punto. Si se produce un error de E/S, se devuelve -1 y se genera una excepción de Tcl en interp.

TCL_READRAW

Similar a Tcl_Read, pero lee bytes directamente del canal sin ninguna conversión de codificación o de fin de línea. El canal debe estar en modo binario.

Devuelve el número de bytes leídos, 0 si se alcanza el final del archivo, o -1 si se produce un error de E/S.

TCL_WRITERAW

Similar a Tcl_Write, pero escribe bytes directamente en el canal sin ninguna conversión de codificación o de fin de línea. El canal debe estar en modo binario.

Devuelve el número de bytes escritos o -1 si se produce un error de E/S.

TCL_EOF

Devuelve verdadero si se ha alcanzado el final del archivo en el canal especificado por channel.

TCL_FLUSH

Fuerza la escritura de todos los datos del búfer de salida del canal especificado por channel al dispositivo subyacente. Si se produce un error durante el vaciado, se genera una excepción de Tcl en interp.

Devuelve TCL_OK si tiene éxito o TCL_ERROR si ocurre un error.

TCL_INPUTBLOCKED

Devuelve verdadero si una operación de lectura en el canal especificado por channel se bloquearía hasta que haya más datos disponibles. Esto solo es significativo si el canal está en modo de E/S no bloqueante.

TCL_INPUTBUFFERED

Devuelve el número de bytes disponibles actualmente en el búfer de entrada del canal especificado por channel.

TCL_OUTPUTBUFFERED

Devuelve el número de bytes actualmente en el búfer de salida del canal especificado por channel que aún no se han escrito en el dispositivo subyacente.

TCL_SEEK

Cambia la posición de lectura/escritura actual del canal especificado por channel. El argumento offset especifica cuánto mover la posición, y seekMode especifica si el desplazamiento es relativo al principio del archivo (SEEK_SET), a la posición actual (SEEK_CUR) o al final del archivo (SEEK_END). El nuevo desplazamiento desde el principio del archivo se devuelve como un valor Tcl_WideInt. Tenga en cuenta que no todos los canales (por ejemplo, sockets) admiten la búsqueda.

Devuelve el nuevo desplazamiento desde el principio del archivo en bytes, o -1 si se produce un error (por ejemplo, si el canal no admite la búsqueda o si la búsqueda falla).

TCL_TELL

Devuelve la posición de lectura/escritura actual del canal especificado por channel, medida en bytes desde el principio del archivo. Tenga en cuenta que no todos los canales (por ejemplo, sockets) admiten esta operación.

Devuelve la posición actual en bytes, o -1 si se produce un error (por ejemplo, si el canal no admite la obtención de la posición).

TCL_TRUNCATECHANNEL

Trunca el archivo asociado con el canal especificado por channel a la longitud especificada por length. Esto acortará el archivo si es más largo que length, o lo extenderá (rellenándolo con ceros) si es más corto. Solo los canales abiertos para escritura pueden ser truncados.

Devuelve TCL_OK si tiene éxito o TCL_ERROR si ocurre un error.

TCL_GETCHANNELOPTION

Obtiene el valor de la opción especificada por optionName para el canal especificado por channel. El valor se almacena en la cadena dinámica Tcl apuntada por optionValue. El argumento interp se utiliza para la notificación de errores.

Devuelve TCL_OK si tiene éxito o TCL_ERROR si ocurre un error (por ejemplo, si el nombre de la opción no es válido).

TCL_SETCHANNELOPTION

Establece el valor de la opción especificada por optionName para el canal especificado por channel en el valor dado por newValue. El argumento interp se utiliza para la notificación de errores.

Devuelve TCL_OK si tiene éxito o TCL_ERROR si ocurre un error (por ejemplo, si el nombre de la opción no es válido o si el nuevo valor no es válido para la opción).

Las opciones disponibles incluyen:

-blocking
Determina si las operaciones de lectura y escritura en el canal son bloqueantes o no bloqueantes. Los valores legales son "true" y "false".
-buffering
Controla el tipo de almacenamiento en búfer para el canal. Los valores legales son "none", "line" y "full".
-encoding
Establece la codificación de caracteres utilizada para leer y escribir en el canal. Los valores legales son nombres de codificación válidos de Tcl.
-translation
Controla la traducción de fin de línea para los canales de texto. Los valores legales son "auto", "lf" y "crlf".

VALOR DE RETORNO

Las funciones que devuelven un valor de cadena o un puntero a una estructura (por ejemplo, Tcl_OpenFileChannel) devuelven un valor nulo si se produce un error y establecen el campo result de interp en un mensaje de error.

Las funciones que devuelven un entero devuelven TCL_OK o un valor distinto de cero si tienen éxito, y TCL_ERROR o 0 si se produce un error. En caso de error, se genera una excepción de Tcl en interp.

Las funciones que devuelven un número de bytes leídos o escritos devuelven el número de bytes y devuelven -1 si se produce un error de E/S. En caso de error, se genera una excepción de Tcl en interp.

TCL_GETSOBJ Y TCL_GETS

Tcl_GetsObj consume bytes de channel, convirtiendo los bytes a UTF-8 según la codificación del canal, hasta que se haya visto una línea completa de entrada. Si la codificación del canal es binary, cada byte leído del canal se trata como un carácter Unicode individual. Todos los caracteres de la línea, excepto los caracteres de fin de línea terminantes, se agregan a la representación de cadena de lineObjPtr. Los caracteres de fin de línea se leen y descartan.

Si se leyó una línea correctamente, el valor de retorno es mayor o igual a cero e indica el número de bytes almacenados en lineObjPtr. Si ocurre un error, Tcl_GetsObj devuelve -1 y registra un código de error POSIX que se puede recuperar con Tcl_GetErrno. Tcl_GetsObj también devuelve -1 si se llega al final del archivo; el procedimiento Tcl_Eof se puede utilizar para distinguir un error de una condición de fin de archivo.

Si el canal está en modo no bloqueante, el valor de retorno también puede ser -1 si no había datos disponibles o si los datos disponibles no contenían un carácter de fin de línea. Cuando se devuelve -1, el procedimiento Tcl_InputBlocked puede invocarse para determinar si el canal está bloqueado debido a la falta de entrada disponible.

Tcl_Gets es lo mismo que Tcl_GetsObj excepto que los caracteres resultantes se agregan a la cadena dinámica dada por lineRead en lugar de un valor Tcl.

TCL_UNGETS

Tcl_Ungets se utiliza para agregar datos a la cola de entrada de un canal, ya sea al principio o al final de la cola. El puntero input apunta a los datos que se van a agregar. La longitud de la entrada a agregar viene dada por inputLen. Un valor distinto de cero de addAtEnd indica que los datos se agregarán al final de la cola; de lo contrario, se agregarán al principio de la cola. Si channel tiene un EOF "pegajoso" establecido, no se agregarán datos a la cola de entrada. Tcl_Ungets devuelve inputLen o -1 si ocurre un error.

TCL_WRITECHARS, TCL_WRITEOBJ, Y TCL_WRITE

Tcl_WriteChars acepta bytesToWrite bytes de datos de caracteres en charBuf. Los caracteres UTF-8 en el búfer se convierten a la codificación del canal y se ponen en cola para su salida a channel. Si bytesToWrite es negativo, Tcl_WriteChars espera que charBuf termine en nulo y envía todo hasta el nulo.

Los datos puestos en cola para la salida pueden no aparecer en el dispositivo de salida inmediatamente, debido al almacenamiento en búfer interno. Si los datos deben aparecer inmediatamente, llame a Tcl_Flush después de la llamada a Tcl_WriteChars, o establezca la opción -buffering en el canal en none. Si desea que los datos aparezcan tan pronto como se acepte una línea completa para la salida, establezca la opción -buffering en el canal en modo line.

El valor de retorno de Tcl_WriteChars es un recuento de cuántos bytes se aceptaron para la salida al canal. Es mayor que cero para indicar éxito o -1 para indicar que ocurrió un error. Si ocurre un error, Tcl_WriteChars registra un código de error POSIX que puede recuperarse con Tcl_GetErrno.

Los caracteres de nueva línea en los datos de salida se traducen a secuencias de fin de línea específicas de la plataforma según la opción -translation para el canal. Esto se hace incluso si el canal no tiene codificación.

Tcl_WriteObj es similar a Tcl_WriteChars excepto que acepta un valor Tcl cuyo contenido se enviará al canal. Los caracteres UTF-8 en la representación de cadena de writeObjPtr se convierten a la codificación del canal y se ponen en cola para su salida a channel. Como optimización de rendimiento, al escribir en un canal con la codificación binary, los caracteres UTF-8 no se convierten al escribirse. En su lugar, los bytes en la representación interna de writeObjPtr como un valor de matriz de bytes se escriben en el canal. La representación de matriz de bytes del valor se construirá si es necesario. De esta manera, los datos orientados a bytes se pueden leer de un canal, manipularse llamando a Tcl_GetByteArrayFromObj y funciones relacionadas, y luego escribirse en un canal sin el gasto de convertir a o desde UTF-8.

Tcl_Write es similar a Tcl_WriteChars excepto que no realiza conversiones de codificación, independientemente de la codificación del canal. Está obsoleto y existe para compatibilidad con versiones anteriores con extensiones Tcl no internacionalizadas. Acepta bytesToWrite bytes de datos en byteBuf y los pone en cola para su salida a channel. Si bytesToWrite es negativo, Tcl_Write espera que byteBuf termine en nulo y envía todo hasta el nulo.

Tcl_WriteRaw es lo mismo que Tcl_Write pero no compensa el apilamiento. Mientras que Tcl_Write (y las otras funciones de la API) siempre alimentan su entrada al canal superior en la pila del canal proporcionado, Tcl_WriteRaw no lo hace. Por lo tanto, esta función es solo utilizable para controladores de canal transformacionales, es decir, controladores utilizados en medio de una pila de canales, para mover datos de la transformación al canal debajo de él.

TCL_FLUSH

Tcl_Flush hace que todos los datos de salida almacenados en búfer para channel se escriban en su archivo o dispositivo subyacente tan pronto como sea posible. Si el canal está en modo de bloqueo, la llamada no regresa hasta que todos los datos almacenados en búfer se hayan enviado al canal o haya ocurrido algún error. La llamada regresa inmediatamente si el canal no está bloqueado; inicia un vaciado en segundo plano que escribirá los datos almacenados en búfer en el canal eventualmente, tan rápido como el canal pueda absorberlos.

El valor de retorno es normalmente TCL_OK. Si ocurre un error, Tcl_Flush devuelve TCL_ERROR y registra un código de error POSIX que se puede recuperar con Tcl_GetErrno.

TCL_SEEK

Tcl_Seek mueve el punto de acceso en channel donde los datos posteriores se leerán o escribirán. La salida en búfer se vacía al canal y la entrada en búfer se descarta, antes de la operación de búsqueda.

Tcl_Seek normalmente devuelve el nuevo punto de acceso. Si ocurre un error, Tcl_Seek devuelve -1 y registra un código de error POSIX que se puede recuperar con Tcl_GetErrno. Después de un error, el punto de acceso puede haberse movido o no.

TCL_TELL

Tcl_Tell devuelve el punto de acceso actual para un canal. El valor devuelto es -1 si el canal no admite la búsqueda.

TCL_TRUNCATECHANNEL

Tcl_TruncateChannel trunca el archivo subyacente de channel a una longitud dada de length bytes. Devuelve TCL_OK si la operación tuvo éxito, y TCL_ERROR en caso contrario.

TCL_GETCHANNELOPTION

Tcl_GetChannelOption recupera, en optionValue, el valor de una de las opciones actualmente en vigor para un canal, o una lista de todas las opciones y sus valores. El argumento channel identifica el canal para el que se consulta una opción o se recuperan todas las opciones y sus valores. Si optionName no es NULL, es el nombre de la opción a consultar; el valor de la opción se copia a la cadena dinámica Tcl denotada por optionValue. TCL_GETCHANNELOPTION

Tcl_GetChannelOption recupera el valor de la opción optionName para el canal channel. Si el valor no se puede almacenar en la cadena de texto dinámica de Tcl valueList, entonces el valor se deja en el resultado del intrérprete Tcl. Si el canal no se encontró o si la opción no se encontró para el canal, entonces el valor de retorno es TCL_ERROR y el resultado del intrérprete se establece en un mensaje de error. En caso contrario, el procedimiento devuelve TCL_OK. La lista de opciones disponibles para un canal se describe utilizando una serie de llamadas a Tcl_DStringAppendElement. Las diversas opciones preexistentes y sus posibles valores se describen en la entrada del manual del comando Tcl fconfigure. Otras opciones pueden ser agregadas por cada tipo de canal. Estas opciones específicas del tipo de canal se describen en la entrada del manual del comando Tcl que crea un canal de ese tipo; por ejemplo, las opciones adicionales para canales basados en TCP se describen en la entrada del manual del comando Tcl socket. El procedimiento normalmente devuelve TCL_OK. Si ocurre un error, devuelve TCL_ERROR y llama a Tcl_SetErrno para almacenar un código de error POSIX apropiado.

TCL_SETCHANNELOPTION

Tcl_SetChannelOption establece un nuevo valor newValue para una opción optionName en el channel. El procedimiento normalmente devuelve TCL_OK. Si ocurre un error, devuelve TCL_ERROR; además, si interp no es NULL, Tcl_SetChannelOption deja un mensaje de error en el resultado del intrérprete.

TCL_EOF

Tcl_Eof devuelve un valor distinto de cero si el channel encontró un fin de archivo durante la última operación de entrada.

TCL_INPUTBLOCKED

Tcl_InputBlocked devuelve un valor distinto de cero si el channel está en modo no bloqueante y la última operación de entrada devolvió menos datos de los solicitados porque no había suficientes datos disponibles. La llamada siempre devuelve cero si el canal está en modo bloqueante.

TCL_INPUTBUFFERED

Tcl_InputBuffered devuelve el número de bytes de entrada actualmente en búfer en los búferes internos de un canal. Si el canal no está abierto para lectura, esta función siempre devuelve cero.

TCL_OUTPUTBUFFERED

Tcl_OutputBuffered devuelve el número de bytes de salida actualmente en búfer en los búferes internos de un canal. Si el canal no está abierto para escritura, esta función siempre devuelve cero.

PLATFORM ISSUES

Los identificadores devueltos por Tcl_GetChannelHandle dependen de la plataforma y del tipo de canal. En plataformas Unix, el identificador es siempre un descriptor de archivo Unix, tal como lo devuelve la llamada al sistema open. En plataformas Windows, el identificador es un HANDLE de archivo cuando el canal se creó con Tcl_OpenFileChannel, Tcl_OpenCommandChannel o Tcl_MakeFileChannel. Otros tipos de canales pueden devolver un tipo diferente de identificador en plataformas Windows.
