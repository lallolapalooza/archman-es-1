ARGUMENTOS

Tcl_Interp *interp (entrada/salida)
El intérprete que contiene el objeto o clase para crear o actualizar un método en.
Tcl_Object object (entrada)
El objeto en el que crear el método.
Tcl_Class class (entrada)
La clase en la que crear el método.
Tcl_Obj *nameObj (entrada)
El nombre del método a crear. No debe ser NULL a menos que se creen constructores o destructores.
int isPublic (entrada)
Una bandera que indica la visibilidad del método. Los únicos valores públicos soportados de esta bandera son 0 para un método no exportado y 1 para un método exportado.
Tcl_MethodType *methodTypePtr (entrada)
Una descripción del tipo de método a crear, o el tipo de método contra el que comparar.
ClientData clientData (entrada)
Un fragmento de datos que se pasa a la implementación del método sin interpretación.
ClientData *clientDataPtr (salida)
Un puntero a una variable en la que escribir el valor de clientData proporcionado al crear el método. Si es NULL, el valor de clientData no se recuperará.
Tcl_Method method (entrada)
Una referencia a un método para consultar.
Tcl_ObjectContext context (entrada)
Una referencia a un contexto de llamada a método. Tenga en cuenta que el código cliente *no* debe conservar una referencia a un contexto.
int objc (entrada)
El número de argumentos que se pasarán a la implementación del método.
Tcl_Obj *const *objv (entrada)
Una matriz de argumentos que se pasarán a la implementación del método.
int skip (entrada)
El número de argumentos pasados a la implementación del método que no representan argumentos "reales".

DESCRIPCIÓN

Un método es una operación que se lleva a cabo sobre un objeto y que está asociada a dicho objeto. Cada método debe estar asociado a un objeto o a una clase; los métodos asociados a una clase se asocian a todas las instancias (directas e indirectas) de esa clase.

Dado un método, la entidad que lo declaró se puede encontrar usando Tcl_MethodDeclarerClass, que devuelve la clase a la que está asociado el método (o NULL si el método no está asociado a ninguna clase), y Tcl_MethodDeclarerObject, que devuelve el objeto al que está asociado el método (o NULL si el método no está asociado a un objeto). El nombre del método se puede recuperar con Tcl_MethodName y si el método se exporta o no, con Tcl_MethodIsPublic. El tipo del método también se puede introspeccionar hasta cierto punto; la función Tcl_MethodIsType devuelve si un método es de un tipo particular, asignando el clientData por método a la variable apuntada por clientDataPtr (si no es NULL) si el tipo coincide.

CREACIÓN DE MÉTODOS

Los métodos se crean mediante Tcl_NewMethod y Tcl_NewInstanceMethod, que crean un método asociado a una clase o a un objeto respectivamente. En ambos casos, el argumento nameObj indica el nombre del método a crear, el argumento isPublic indica si el método debe exportarse inicialmente, el argumento methodTypePtr describe la implementación del método (ver la sección TIPOS DE MÉTODOS más abajo) y el argumento clientData proporciona algunos datos específicos de la implementación que se pasan a la implementación del método cuando se llama.

Cuando el argumento nameObj de Tcl_NewMethod es NULL, se crea un método sin nombre, que se utiliza para constructores y destructores. Los constructores deben instalarse en su clase utilizando la función Tcl_ClassSetConstructor, y los destructores (que no deben requerir ningún argumento) deben instalarse en su clase utilizando la función Tcl_ClassSetDestructor. Los métodos sin nombre no deben utilizarse para ningún otro propósito, y los métodos con nombre no deben utilizarse ni como constructores ni como destructores. Tenga en cuenta también que un methodTypePtr NULL se utiliza para proporcionar señalización interna y no debe utilizarse en código de cliente.

CONTEXTOS DE LLAMADA A MÉTODOS

Cuando se llama a un método, se pasa una referencia de contexto de llamada a método como uno de los argumentos a la función de implementación. Este contexto se puede inspeccionar para proporcionar información sobre el llamador, pero no debe conservarse más allá del momento en que finaliza la llamada al método.

El método que se está llamando se puede recuperar del contexto utilizando Tcl_ObjectContextMethod, y el objeto que provocó la invocación del método se puede recuperar con Tcl_ObjectContextObject. El número de argumentos que se deben omitir (por ejemplo, el nombre del objeto y el nombre del método en una llamada de método normal) se lee con Tcl_ObjectContextSkippedArgs, y el contexto también puede informar si está funcionando como un filtro para otro método a través de Tcl_ObjectContextIsFiltering.

Durante la ejecución de un método, la implementación del método puede optar por invocar las etapas de la cadena de llamada de métodos que vienen después de la implementación del método actual. Esto (el núcleo del comando next) se hace usando Tcl_ObjectContextInvokeNext. Tenga en cuenta que esta función no manipula la pila de marcos de llamada, a diferencia del comando next; si la implementación del método ha insertado uno o más marcos adicionales en la pila como parte de su implementación, también es responsable de extraer temporalmente esos marcos de la pila mientras se ejecuta la función Tcl_ObjectContextInvokeNext. Tenga en cuenta también que el contexto de llamada a método *nunca* se elimina durante la ejecución de esta función.

TIPOS DE MÉTODOS

Los tipos de métodos se describen mediante un puntero a una estructura Tcl_MethodType, que se define como:

typedef struct {
    int version;
    const char *name;
    Tcl_MethodCallProc *callProc;
    Tcl_MethodDeleteProc *deleteProc;
    Tcl_CloneProc *cloneProc;
} Tcl_MethodType;

El campo version permite la expansión futura de la estructura y siempre debe declararse igual a TCL_OO_METHOD_VERSION_CURRENT. El campo name proporciona un nombre legible por humanos para el tipo y es el valor que se expone a través de los comandos Tcl info class methodtype y info object methodtype.

El campo callProc proporciona una función que se llama cuando se invoca el método; nunca debe ser NULL.

El campo deleteProc proporciona una función que se utiliza para eliminar un método particular y se llama cuando el método se reemplaza o se elimina; si el campo es NULL, se asume que el clientData del método no necesita ninguna acción especial para eliminarse.

El campo cloneProc es una función que se utiliza para copiar el clientData de un método (como parte de Tcl_CopyObjectInstance) o NULL para indicar que el clientData puede copiarse directamente.

FIRMA DE FUNCIÓN TCL_METHODCALLPROC

La firma de la función de tipo Tcl_MethodCallProc es:

typedef int (*Tcl_MethodCallProc)(
        ClientData clientData,
        Tcl_Interp *interp,
        int objc,
        Tcl_Obj *const objv[],
        Tcl_ObjectContext context);

El argumento clientData es el dato específico de la implementación que se asoció con el método cuando se creó. El argumento interp es el intérprete en el que se está ejecutando la llamada al método. Los argumentos objc y objv son el número y la matriz de argumentos pasados al método respectivamente (incluyendo el nombre del objeto y el nombre del método, si se invocan de la forma estándar). El argumento context es un puntero a una estructura opaca que describe el contexto de la llamada al método y que debe pasarse a Tcl_ObjectContext InvokeNext si se llama a ese método.

NOMBRE

Tcl_NewMethod, Tcl_NewInstanceMethod, Tcl_NewClassMethod - crear un nuevo método para una clase o una instancia

SINOPSIS

#include <tclOO.h>

Tcl_Method
Tcl_NewMethod(interp, name, proc, clientData, deleteProc);

Tcl_Method
Tcl_NewInstanceMethod(interp, name, proc, clientData, deleteProc);

Tcl_Method
Tcl_NewClassMethod(interp, name, proc, clientData, deleteProc);

ARGUMENTOS

Tcl_Interp *interp
Intérprete de Tcl a usar para la creación del método.
const char *name
El nombre del método que se va a crear.
Tcl_MethodCallProc *proc
El puntero a la función que implementa la lógica del método.
ClientData clientData
Datos específicos del cliente que se pasan al método cuando se llama.
Tcl_MethodDeleteProc *deleteProc
Un puntero a una función que se llama cuando el método es eliminado.

DESCRIPCIÓN

Estos procedimientos crean y registran un nuevo método. El método creado se asocia con la clase o la instancia de objeto actual dentro del contexto del intérprete especificado. El name es el nombre de la variable en la que se almacenará el método. El proc es el puntero a la función que se ejecutará cuando se invoque el método. El clientData es un puntero a datos arbitrarios que se pasan a la función del método. El deleteProc es un puntero a una función que se llama cuando el método es destruido (ya sea porque la clase o instancia que contiene el método es destruida, o porque se sobrescribe el método existente con uno nuevo). Si deleteProc es NULL, no se realiza ninguna limpieza de datos del cliente.

La diferencia entre Tcl_NewMethod y Tcl_NewInstanceMethod es que el primer método se asocia con la definición de la clase (por lo que es accesible a través de la jerarquía de herencia de la clase), mientras que el segundo se asocia directamente con una instancia de objeto específica (y no es heredado).

Tcl_NewClassMethod es un alias para Tcl_NewMethod.

Los métodos pueden ser sobrescritos. Si un método con el mismo nombre ya existe, el método anterior se elimina y se llama a su deleteProc (si existe) antes de que se registre el nuevo método.

El valor de retorno es un valor de tipo Tcl_Method que puede ser utilizado para referirse al método creado. Si ocurre un error durante la creación, se devuelve un valor NULL y el nivel de error se establece en el intérprete.

Los métodos se implementan mediante una de las tres firmas de procedimiento:

FIRMA DE FUNCIÓN DE TCL_METHODCALLPROC

Las funciones que coinciden con esta firma se llaman cuando se invoca el método.

typedef int Tcl_MethodCallProc(
        ClientData clientData,
        Tcl_Interp *interp,
        Tcl_ObjectContext objectContext,
        int objc,
        Tcl_Obj *const *objv);

El argumento clientData de un Tcl_MethodCallProc es el valor que se proporcionó cuando se creó el método, el interp es un lugar para ejecutar scripts y acceder a variables, así como para colocar el resultado del método, y los campos objc y objv dan los objetos parámetro al método. El contexto de llamada del método se puede descubrir a través del argumento objectContext, y el valor de retorno de un Tcl_MethodCallProc es cualquier código de retorno de Tcl (por ejemplo, TCL_OK, TCL_ERROR).

FIRMA DE FUNCIÓN DE TCL_METHODDELETEPROC

Las funciones que coinciden con esta firma se utilizan cuando se elimina un método, ya sea porque se crea un nuevo método o porque se elimina el objeto o la clase.

typedef void Tcl_MethodDeleteProc(
        ClientData clientData);

El argumento clientData de un Tcl_MethodDeleteProc será el mismo que el valor pasado al argumento clientData de Tcl_NewMethod o Tcl_NewInstanceMethod cuando se creó el método.

FIRMA DE FUNCIÓN DE TCL_CLONEPROC

Las funciones que coinciden con esta firma se utilizan para copiar un método cuando el objeto o la clase se copia usando Tcl_CopyObjectInstance (o oo::copy).

typedef int Tcl_CloneProc(
        Tcl_Interp *interp,
        ClientData oldClientData,
        ClientData *newClientDataPtr);

El argumento interp proporciona un lugar para escribir un mensaje de error cuando el intento de clonar el objeto falla, en cuyo caso el procedimiento de clonación también debe devolver TCL_ERROR; de lo contrario, debe devolver TCL_OK. El campo oldClientData de un Tcl_CloneProc proporciona el valor del método que se está copiando, y el campo newClientDataPtr apuntará a una variable en la que se escribirá el valor para el método al que se está copiando.
