ARGUMENTOS

Tcl_Interp *interp (entrada)
El intérprete donde se almacenarán los datos comprimidos o descomprimidos resultantes. También es donde se escribirán los mensajes de error. Para Tcl_ZlibStreamInit, esto puede ser NULL para crear un stream que no esté vinculado a un comando.
int format (entrada)
Qué formato de datos comprimidos se va a procesar. Debe ser uno de TCL_ZLIB_FORMAT_ZLIB para datos en formato zlib, TCL_ZLIB_FORMAT_GZIP para datos en formato gzip, o TCL_ZLIB_FORMAT_RAW para datos comprimidos sin formato. Además, solo para descompresión, también se puede elegir TCL_ZLIB_FORMAT_AUTO, que puede detectar automáticamente si los datos comprimidos estaban en formato zlib o gzip.
Tcl_Obj *dataObj (entrada/salida)
Un valor de tipo array de bytes que contiene los datos a comprimir o descomprimir, o al que se añaden los datos extraídos del stream cuando se pasa a Tcl_ZlibStreamGet.
int level (entrada)
Qué nivel de compresión usar. Debe ser un número del 0 al 9 o una de las siguientes opciones: TCL_ZLIB_COMPRESS_NONE para ninguna compresión, TCL_ZLIB_COMPRESS_FAST para compresión rápida pero ineficiente, TCL_ZLIB_COMPRESS_BEST para compresión lenta pero máxima, o TCL_ZLIB_COMPRESS_DEFAULT para el nivel recomendado por la biblioteca zlib.
Tcl_Obj *dictObj (entrada/salida)
Un diccionario que contiene, o que se actualizará para contener, una descripción de la cabecera gzip asociada con los datos comprimidos. Solo es útil cuando el parámetro format es TCL_ZLIB_FORMAT_GZIP o TCL_ZLIB_FORMAT_AUTO. Si se pasa NULL, se usará una cabecera por defecto en la compresión y la cabecera será ignorada (aparte de las comprobaciones de integridad) en la descompresión. Consulte la sección DICCIONARIO DE OPCIONES GZIP para obtener detalles sobre el contenido de este diccionario.
unsigned int initValue (entrada)
El valor inicial para el algoritmo de checksum.
int bufferSize (entrada)
Una pista sobre el tamaño del búfer que se utilizará para recibir los datos. Use 0 para usar una suposición genérica basada en los datos de entrada.
unsigned char *bytes (entrada)
Un array de bytes sobre el que ejecutar el algoritmo de checksum, o NULL para obtener el valor inicial recomendado para el algoritmo de checksum.
int length (entrada)
El número de bytes en el array.
int mode (entrada)
En qué modo operar el stream. Debe ser TCL_ZLIB_STREAM_DEFLATE para un stream de compresión o TCL_ZLIB_STREAM_INFLATE para un stream de descompresión.
Tcl_ZlibStream *zshandlePtr (salida)
Un puntero a una variable en la que se escribirá el token abstracto para el stream tras su creación exitosa.
Tcl_ZlibStream zshandle (entrada)
El token abstracto para el stream sobre el que operar.
int flush (entrada)
Si y cómo vaciar el stream después de escribir los datos en él. Debe ser una de las siguientes opciones: TCL_ZLIB_NO_FLUSH si no se va a hacer ningún vaciado, TCL_ZLIB_FLUSH si los datos comprimidos actualmente deben estar disponibles para su acceso mediante Tcl_ZlibStreamGet, TCL_ZLIB_FULLFLUSH si el stream debe ponerse en un estado en el que el descompresor pueda recuperarse de una corrupción, o TCL_ZLIB_FINALIZE para asegurar que el stream se ha completado y que se escribe cualquier marcador final exigido por el formato.
int count (entrada)
El número máximo de bytes a obtener del stream, o -1 para obtener todos los bytes restantes de los búferes del stream.
Tcl_Obj *compDict (entrada)
Un valor de tipo array de bytes que es el diccionario de compresión a usar con el stream. Tenga en cuenta que esto *no es un diccionario Tcl*, y se recomienda que solo se utilice con streams que se crearon con su format establecido en TCL_ZLIB_FORMAT_ZLIB porque los otros formatos no tienen ningún mecanismo para indicar si estaba presente un diccionario de compresión, aparte de fallar en la descompresión.

DESCRIPCIÓN

Estas funciones forman la interfaz de la biblioteca Tcl a la biblioteca Zlib de Jean-loup Gailly y Mark Adler.

Tcl_ZlibDeflate y Tcl_ZlibInflate respectivamente comprimen y descomprimen los datos contenidos en el argumento dataObj, de acuerdo con los argumentos format y, para la compresión, level. El diccionario en el parámetro dictObj se utiliza para transmitir información adicional de cabecera sobre los datos comprimidos cuando el formato de compresión lo admite; actualmente, el diccionario solo se utiliza cuando el parámetro format es TCL_ZLIB_FORMAT_GZIP o TCL_ZLIB_FORMAT_AUTO. Para obtener detalles sobre el contenido del diccionario, consulte la sección DICCIONARIO DE OPCIONES GZIP más abajo. Tras el éxito, ambas funciones dejan los datos comprimidos o descomprimidos resultantes en un valor de tipo array de bytes que es el resultado del intérprete Tcl; el valor devuelto es un código de resultado Tcl estándar.

Tcl_ZlibAdler32 y Tcl_ZlibCRC32 calculan checksums sobre arrays de bytes, devolviendo el checksum calculado. Los checksums se calculan de forma incremental, lo que permite procesar los datos bloque a bloque, pero esto requiere que el llamador mantenga el checksum actual y lo pase como parámetro initValue; el valor inicial a utilizar para esto se puede obtener usando NULL para el parámetro bytes en lugar de un puntero al array de bytes sobre el que calcular el checksum. Por lo tanto, el uso típico en el caso de un único bloque de datos es el siguiente:

checksum = Tcl_ZlibCRC32(Tcl_ZlibCRC32(0,NULL,0), data, length);

Tenga en cuenta que el algoritmo Adler-32 no es un checksum real, sino un tipo de hash relacionado que funciona mejor en datos más largos.

STREAMS ZLIB

Tcl_ZlibStreamInit crea un stream de compresión o descompresión que está vinculado a un comando Tcl, de acuerdo con sus argumentos, y proporciona un token abstracto para el stream y devuelve un código de resultado Tcl normal; Tcl_ZlibStreamGetCommandName devuelve el nombre de ese comando dado el token del stream, o NULL si el stream no tiene comando. Los streams no están diseñados para ser seguros para hilos; cada stream solo debe usarse desde el hilo que lo creó. Al trabajar con streams gzip, se puede proporcionar un diccionario (campos según se indica en la sección DICCIONARIO DE OPCIONES GZIP) a través del parámetro dictObj, que en la compresión permite controlar las cabeceras generadas, y en la descompresión permite descubrir las cabeceras existentes. Tenga en cuenta que el diccionario se escribirá en la descompresión una vez leídos suficientes datos para tener una cabecera completa. Esto significa que el diccionario debe ser un valor no compartido en ese caso; se sugiere un valor en blanco creado con Tcl_NewObj.

Una vez que se ha construido un stream, se utiliza Tcl_ZlibStreamPut para añadir datos al stream y Tcl_ZlibStreamGet para recuperar datos del stream después del procesamiento. Ambos devuelven códigos de resultado Tcl normales y dejan un mensaje de error en el resultado del intérprete con el que está registrado el stream (si se ha realizado dicho registro). Con Tcl_ZlibStreamPut, el valor del búfer de datos que se le pasa no debe modificarse después. Con Tcl_ZlibStreamGet, el valor del búfer de datos que se le pasa tendrá los bytes de datos añadidos. Internamente al stream, los datos se mantienen comprimidos para minimizar el costo del espacio de búfer.

Tcl_ZlibStreamChecksum devuelve el checksum calculado sobre los datos descomprimidos según el formato, y 

Tcl_ZlibStreamClose cierra el stream y libera todos los recursos asociados. Tcl_ZlibStreamEof
    devuelve un valor distinto de cero si se ha llegado al final de los datos
    de entrada del stream. Tcl_ZlibStreamReset restablece el stream a su
    estado inicial, lo que le permite ser reutilizado. Si el stream se está
    comprimiendo, se descartará cualquier dato que no se haya escrito todavía. Si
    el stream se está descomprimiendo, se descartará cualquier dato que no se haya
    leído todavía.

Tcl_ZlibStreamSetCompressionDictionary permite establecer un diccionario de compresión para su uso posterior con el stream. Nota: Este diccionario se proporciona como un array de bytes, no como un objeto de diccionario Tcl, y su uso está principalmente destinado a streams creados con el formato TCL_ZLIB_FORMAT_ZLIB, ya que otros formatos pueden no tener un mecanismo para indicar la presencia de dicho diccionario.

DICCIONARIO DE OPCIONES GZIP

El diccionario de opciones gzip es un objeto Tcl de tipo diccionario que se puede pasar a las funciones de compresión y descompresión de streams gzip. Las siguientes claves se pueden utilizar dentro de este diccionario:

name
Un nombre de archivo opcional que se puede incrustar en la cabecera gzip. Debe ser una cadena Tcl. El nombre se truncará si es demasiado largo para caber en la cabecera gzip.
comment
Un comentario opcional que se puede incrustar en la cabecera gzip. Debe ser una cadena Tcl. El comentario se truncará si es demasiado largo para caber en la cabecera gzip.
mtime
La hora de modificación opcional del archivo original, especificada como un número entero de segundos desde la época Unix. Si se omite, se utilizará la hora actual.
os
El campo de sistema operativo opcional en la cabecera gzip. Debe ser un valor entero. El valor predeterminado es el sistema operativo del host. Consulte la especificación gzip para ver una lista de los valores válidos para el campo OS.
extra
Datos de cabecera extra opcionales que se pueden incrustar en la cabecera gzip. Debe ser un valor de tipo array de bytes.
extrafield
Datos de campo extra opcionales que se pueden incrustar en la cabecera gzip. Debe ser un valor de tipo array de bytes.
comment
Un comentario opcional que se puede incrustar en la cabecera gzip. Debe ser una cadena Tcl. El comentario se truncará si es demasiado largo para caber en la cabecera gzip.

En la descompresión, los campos de nombre, comentario, mtime, os, extra y extrafield se pueden leer del diccionario de opciones gzip que se pasa a la función de descompresión. Tenga en cuenta que el diccionario se actualizará con la información leída de la cabecera gzip. Si el diccionario ya contiene valores para estas claves, se sobrescribirán con la información de la cabecera gzip.

VALORES DE RETORNO

Las funciones de checksum devuelven el checksum calculado. Las funciones de compresión/descompresión y stream devuelven TCL_OK si tienen éxito, o un código de error Tcl estándar si se produce un error.

OPCIONES_GZIP_DICCIONARIO

El parámetro dictObj de Tcl_ZlibDeflate, Tcl_ZlibInflate y Tcl_ZlibStreamInit se utiliza para pasar un diccionario de opciones sobre ese que describe la cabecera de gzip en los datos comprimidos. Cuando se crean los datos comprimidos, el diccionario se lee y cuando se descomprimen los datos comprimidos, se escribe (en este caso, el parámetro dictObj debe referirse a un valor no compartido).

Los siguientes campos en el valor del diccionario se entienden. Todos los otros campos se ignoran. Ningún campo es necesario cuando se crea un flujo de formato gzip.

comment
Esto almacena el campo de comentario de la cabecera, si está presente. Si no está presente, no se proporcionó (en descompresión) o se creará (en compresión).
crc
Un valor booleano que indica si se ha calculado un CRC de la cabecera. Nota: el programa gzip no utiliza ni permite un CRC en la cabecera.
filename
Nombre del archivo que almacenó los datos descomprimidos. Este no debe contener separadores de directorio y debe ser sanitizado antes de usarse en descompresión con file tail.
os
Valor del campo de tipo de sistema operativo de la cabecera (si no es el valor "unknown"). Ver RFC 1952 para el significado de estos códigos. En compresión, si este valor no está presente, se establecerá como "unknown".
size
Tamaño de los datos descomprimidos. Esto se ignora en compresión; el tamaño de los datos comprimidos depende del volumen de datos proporcionado al motor de compresión.
time
Valor del campo de tiempo de la cabecera si no es cero, que se espera que sea el momento en que se modificó el archivo nombrado por el campo filename. Es adecuado para usar con clock format. En la creación, el valor correcto a usar es el de clock seconds o file mtime.
type
Tipo de los datos descomprimidos (binario o texto) si se conoce.
