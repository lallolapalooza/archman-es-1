NOMBRE

Tcl_RegisterObjType, Tcl_GetObjType, Tcl_AppendAllObjTypes, Tcl_ConvertToType - manipular tipos de valores Tcl

SINOPSIS

#include <tcl.h>

Tcl_RegisterObjType(typePtr)

const Tcl_ObjType *
Tcl_GetObjType(typeName)

int
Tcl_AppendAllObjTypes(interp, objPtr)

int
Tcl_ConvertToType(interp, objPtr, typePtr)

ARGUMENTOS

const Tcl_ObjType *typePtr (in)
Punta a la estructura que contiene información sobre el tipo de valor Tcl. Este almacenamiento debe permanecer para siempre, típicamente siendo asignado estáticamente.
const char *typeName (in)
El nombre de un tipo de valor Tcl que Tcl_GetObjType debe buscar.
Tcl_Interp *interp (in)
Intérprete a usar para reportar errores.
Tcl_Obj *objPtr (in)
Para Tcl_AppendAllObjTypes, esto apunta al valor al que se anexa el nombre de cada tipo de valor como un elemento de lista. Para Tcl_ConvertToType, esto apunta a un valor que debe haber sido el resultado de una llamada previa a Tcl_NewObj.

DESCRIPCIÓN

Los procedimientos en esta página de manual gestionan los tipos de valores Tcl (a veces referidos como tipos de objetos o Tcl_ObjTypes por razones históricas). Se utilizan para registrar nuevos tipos de valores, buscar tipos y forzar conversiones de un tipo a otro.

Tcl_RegisterObjType registra un nuevo tipo de valor Tcl en la tabla de todos los tipos de valores que Tcl_GetObjType puede buscar por nombre. Hay otros tipos de valores soportados por Tcl también, que Tcl elige no registrar. Las extensiones pueden de manera similar elegir registrar los tipos de valores que crean o no. El argumento typePtr apunta a una estructura Tcl_ObjType que describe el nuevo tipo al dar su nombre y al proporcionar punteros a cuatro procedimientos que implementan el tipo. Si la tabla de tipos ya contiene un tipo con el mismo nombre que en typePtr, se reemplaza con el nuevo tipo. La estructura Tcl_ObjType se describe en la sección LA ESTRUCTURA TCL_OBJTYPE a continuación.

Tcl_GetObjType devuelve un puntero al Tcl_ObjType registrado con el nombre typeName. Devuelve NULL si no hay ningún tipo registrado con ese nombre.

Tcl_AppendAllObjTypes anexa el nombre de cada tipo de valor registrado como un elemento de lista al valor Tcl referenciado por objPtr. El valor de retorno es TCL_OK a menos que haya habido un error al convertir objPtr a un valor de lista; en ese caso se devuelve TCL_ERROR.

Tcl_ConvertToType convierte un valor de un tipo a otro si es posible. Crea una nueva representación interna para objPtr apropiada para el tipo de destino typePtr y establece su miembro typePtr según lo determinado al llamar a la rutina typePtr->setFromAnyProc. Cualquier representación interna del tipo anterior de objPtr se libera. Si ocurre un error durante la conversión, devuelve TCL_ERROR y deja un mensaje de error en el valor resultante para interp a menos que interp sea NULL. De lo contrario, devuelve TCL_OK. Pasar un interp NULL permite que este procedimiento se utilice como una prueba para ver si la conversión se puede hacer (y de hecho se hizo).

En muchos casos, la rutina typePtr->setFromAnyProc establecerá objPtr->typePtr al valor de argumento typePtr, pero eso ya no está garantizado. El setFromAnyProc es libre de establecer la representación interna para objPtr para hacer uso de otro Tcl_ObjType relacionado, si lo considera oportuno.

LA ESTRUCTURA TCL_OBJTYPE

Los escritores de extensiones pueden definir nuevos tipos de valores definiendo cuatro procedimientos e inicializando una estructura Tcl_ObjType para describir el tipo. Los escritores de extensiones también pueden pasar un puntero a su estructura Tcl_ObjType a Tcl_RegisterObjType si desean permitir que otras extensiones busquen su Tcl_ObjType por nombre con la rutina Tcl_GetObjType. La estructura Tcl_ObjType se define de la siguiente manera:

typedef struct Tcl_ObjType {
    const char *name;
    Tcl_FreeInternalRepProc *freeIntRepProc;
    Tcl_DupInternalRepProc *dupIntRepProc;
    Tcl_UpdateStringProc *updateStringProc;
    Tcl_SetFromAnyProc *setFromAnyProc;
} Tcl_ObjType;

EL CAMPO NAME

El miembro name describe el nombre del tipo, p.ej., int. Cuando se registra un tipo, este es el nombre que los llamadores de Tcl_GetObjType utilizan para buscar el tipo. Para tipos no registrados, el campo name es principalmente útil para depuración. Los cuatro miembros restantes son punteros a procedimientos llamados por el código genérico de valores Tcl:

EL CAMPO SETFROMANYPROC

El miembro setFromAnyProc contiene la dirección de una función llamada para crear una representación interna válida a partir de la representación de cadena de un valor.

typedef int Tcl_SetFromAnyProc(
        Tcl_Interp *interp,
        Tcl_Obj *objPtr);

Si no se puede crear una representación interna a partir de la cadena, devuelve TCL_ERROR y pone un mensaje que describe el error en el valor resultante para interp a menos que interp sea NULL. Si setFromAnyProc tiene éxito, almacena la nueva representación interna, establece el miembro typePtr de objPtr para que apunte a la estructura Tcl_ObjType correspondiente a la nueva representación interna y devuelve TCL_OK. Antes de establecer la nueva representación interna, el setFromAnyProc debe liberar cualquier representación interna del tipo antiguo de objPtr; lo hace llamando al freeIntRepProc del tipo antiguo si no es NULL.

Como ejemplo, el setFromAnyProc para el tipo de lista Tcl incorporado obtiene una representación de cadena actualizada para objPtr llamando a Tcl_GetStringFromObj. Analiza la cadena para verificar que está en un formato de lista válido y para obtener cada valor de elemento en la lista, y, si esto tiene éxito, almacena los elementos de la lista en la representación interna de objPtr y establece el miembro typePtr de objPtr para que apunte a la estructura Tcl_ObjType del tipo lista.

No libere la representación interna anterior de objPtr a menos que la reemplace con una nueva o restablezca el miembro typePtr a NULL.

El miembro setFromAnyProc puede establecerse en NULL, si las rutinas que utilizan la representación interna no necesitan derivar esa representación interna de un valor de cadena arbitrario. Sin embargo, en este caso, pasar un puntero al tipo a Tcl_ConvertToType provocará un error grave, por lo que para evitar esta posibilidad, el tipo no debe ser registrado.

EL CAMPO UPDATESTRINGPROC

El miembro updateStringProc contiene la dirección de una función llamada para crear una representación de cadena válida a partir de la representación interna de un valor.

typedef void Tcl_UpdateStringProc(
        Tcl_Obj *objPtr);

El miembro bytes de objPtr siempre es NULL cuando se llama. Siempre debe establecer bytes en no NULL antes de devolver. Exigimos que el array de bytes de la representación de cadena tenga un nulo después del último byte, en el desplazamiento length, y que no tenga bytes nulos antes de eso; esto permite que las representaciones de cadena se traten como cadenas C convencionales terminadas en nulo. Estas restricciones se cumplen fácilmente utilizando la codificación interna UTF de Tcl para la representación de cadena, igual que se haría para otras rutinas Tcl que aceptan valores de cadena como argumentos. El almacenamiento para el array de bytes debe ser asignado en el heap por Tcl_Alloc o ckalloc. Tenga en cuenta que los updateStringProcs deben asignar suficiente espacio para los bytes de la cadena y el byte nulo de terminación.

El updateStringProc para el tipo double incorporado de Tcl, por ejemplo, llama a Tcl_PrintDouble para escribir en un búfer de tamaño TCL_DOUBLE_SPACE, luego asigna y copia la representación de cadena a solo espacio suficiente para contenerla. Un puntero al espacio asignado se almacena en el miembro bytes.

El miembro updateStringProc puede establecerse en NULL, si las rutinas que utilizan la representación interna están escritas de manera que la representación de cadena nunca se invalide. Fallar en me

Tcl_GetObjType

Tcl Object Types

3

8.0 Tcl

NAME

Tcl_GetObjType, Tcl_RegisterObjType, Tcl_FetchStringBytes, Tcl_InvalidateStringRep — manipulate Tcl object types

SYNOPSIS

#include <tcl.h>

const Tcl_ObjType *
Tcl_GetObjType(const char *name);

void
Tcl_RegisterObjType(const Tcl_ObjType *typePtr);

const char *
Tcl_FetchStringBytes(Tcl_Obj *objPtr, int *lengthPtr);

void
Tcl_InvalidateStringRep(Tcl_Obj *objPtr);

ARGUMENTS

const char *name (input)
Name of the object type to look up.
const Tcl_ObjType *typePtr (input)
Pointer to the object type structure to register.
Tcl_Obj *objPtr (input)
Pointer to the object whose string representation is desired.
int *lengthPtr (output)
If non-NULL, this will be set to the length of the string representation.

DESCRIPTION

Tcl objects have a type, which is represented by a Tcl_ObjType structure. This structure contains information about the object type, including its name and pointers to functions that perform type-specific operations such as converting the object to other internal representations or to a string. The Tcl_ObjType structure is defined as follows:

typedef struct Tcl_ObjType {
    const char *name;
    Tcl_FreeInternalRepProc *freeIntRepProc;
    Tcl_DupInternalRepProc *dupIntRepProc;
    Tcl_UpdateStringProc *updateStringProc;
} Tcl_ObjType;

The name field is a string that uniquely identifies the type (e.g., "int", "list", "dict"). The other fields are pointers to procedures that implement the type's behavior.

Tcl_GetObjType returns a pointer to the Tcl_ObjType structure corresponding to the given name. If no type with that name is registered, it returns NULL. This is useful for querying the capabilities of an object type.

Tcl_RegisterObjType adds a new object type to Tcl's registry of types. This is typically done by extension writers who are defining new object types. The typePtr argument should point to a statically allocated Tcl_ObjType structure. The type's name must not be NULL, and it must be unique among registered types.

Tcl_FetchStringBytes returns a pointer to the string representation of the object objPtr. If the object does not currently have a string representation, Tcl will create one by calling the object's type-specific updateStringProc procedure. The returned pointer is valid as long as the object is not modified and its reference count does not drop to zero. If lengthPtr is not NULL, it will be set to the length of the string representation. Note that the string representation is owned by the Tcl object; it should not be freed by the caller.

Tcl_InvalidateStringRep marks the object's string representation as invalid. The next time the string representation is requested (e.g., via Tcl_FetchStringBytes), it will be regenerated. This is useful when the object's internal representation has changed in a way that makes the existing string representation incorrect, but the change is not severe enough to require freeing the entire object.

THE TCL_OBJTYPE STRUCTURE

The Tcl_ObjType structure contains the following members:

const char *name
The name of the object type. This name is used internally by Tcl to refer to the type and is also used by commands like string is and set to determine the type of an object.
Tcl_FreeInternalRepProc *freeIntRepProc
A pointer to a procedure that is called to free the internal representation of an object when it is no longer needed. If the internal representation does not require any special freeing (e.g., it's just a simple integer), this pointer can be NULL.
Tcl_DupInternalRepProc *dupIntRepProc
A pointer to a procedure that is called to duplicate the internal representation of an object. This is used when an object is copied, for example, when passing an object by value to a procedure or when creating a new object with the same value as an existing one.
Tcl_UpdateStringProc *updateStringProc
A pointer to a procedure that is called to create or update the string representation of an object. This procedure is responsible for converting the object's internal representation into a human-readable string.

The internal representation of an object is stored in the internalRep union within the Tcl_Obj structure. The layout of this union is type-specific. The dupIntRepProc and freeIntRepProc procedures are responsible for managing the memory associated with these internal representations.

For example, the integer type's internal representation is simply an integer. Its dupIntRepProc just copies the integer, and its freeIntRepProc does nothing. The list type's internal representation is a pointer to a structure containing an array of object pointers. Its dupIntRepProc creates a new list structure and increments the reference counts of the elements in the original list. Its freeIntRepProc decrements the reference counts of the elements and frees the list structure itself if it is no longer shared.

The updateStringProc is called when the string representation of an object is needed and is not currently available. It should convert the object's internal representation into a string and store it in the bytes field of the Tcl_Obj structure. If the string representation is large, it may be allocated dynamically. The updateStringProc should also set the length field of the Tcl_Obj structure to the length of the string. If the string representation is not needed, the bytes and length fields should be set to NULL and 0, respectively.

Calling Tcl_InvalidateStringRep is important when the internal representation of an object changes but its string representation does not need to be immediately updated. This avoids unnecessary work if the string representation is never actually used. However, if an object's internal representation is modified in a way that might affect its string representation, Tcl_InvalidateStringRep should be called to ensure that the string representation is up-to-date when it is next requested.

A common mistake is to assume that the string representation returned by Tcl_FetchStringBytes is null-terminated. While it usually is, this is not guaranteed. The length should always be used to determine the extent of the string data.

Another potential issue is that an object might have multiple internal representations. For example, a string that also represents an integer might have both a string representation and an integer representation. Tcl tries to maintain consistency between these representations. If an operation modifies the internal representation (e.g., converting a string to an integer), it may need to invalidate the string representation to prevent inconsistencies. If the internal representation is modified in a way that invalidates the string representation, the updateStringProc should be called to regenerate it. The Tcl core handles this automatically in many cases, but custom type implementations may need to do it explicitly.

The freeIntRepProc field is crucial for preventing memory leaks. If an object's internal representation involves dynamically allocated memory, the freeIntRepProc must be implemented to release that memory when the object is destroyed or when its internal representation is changed.

The dupIntRepProc ensures that shared internal representations are handled correctly. When an object is duplicated, its internal representation should also be duplicated in a way that maintains any necessary sharing or ownership semantics. For simple types like integers, this is just a value copy. For more complex types like lists or dictionaries, it might involve reference counting or copying shared structures.

Failure to implement these procedures correctly can lead to crashes, memory leaks, or incorrect behavior. For instance, if freeIntRepProc is missing or incorrect, memory allocated for the internal representation might not be freed. If dupIntRepProc does not correctly duplicate shared resources, modifying one object might unintentionally affect another. The updateStringProc is essential for operations that rely on the string form of an object, and its absence or incorrect implementation in this obligation will lead to panics or crashes when Tcl_GetStringFromObj or other similar routines ask for the string representation.

THE DUPINTREPPROC FIELD

The dupIntRepProc member contains the address of a function called to copy an internal representation from one value to another.

typedef void Tcl_DupInternalRepProc(
        Tcl_Obj *srcPtr,
        Tcl_Obj *dupPtr);

dupPtr's internal representation is made a copy of srcPtr's internal representation. Before the call, srcPtr's internal representation is valid and dupPtr's is not. srcPtr's value type determines what copying its internal representation means.

For example, the dupIntRepProc for the Tcl integer type simply copies an integer. The built-in list type's dupIntRepProc uses a far more sophisticated scheme to continue sharing storage as much as it reasonably can.

THE FREEINTREPPROC FIELD

The freeIntRepProc member contains the address of a function that is called when a value is freed.

typedef void Tcl_FreeInternalRepProc(
        Tcl_Obj *objPtr);

The freeIntRepProc function can deallocate the storage for the value's internal representation and do other type-specific processing necessary when a value is freed.

For example, the list type's freeIntRepProc respects the storage sharing scheme established by the dupIntRepProc so that it only frees storage when the last value sharing it is being freed.

The freeIntRepProc member can be set to NULL to indicate that the internal representation does not require freeing. The freeIntRepProc implementation must not access the bytes member of the value, since Tcl makes its own internal uses of that field during value deletion. The defined tasks for the freeIntRepProc have no need to consult the bytes member.
