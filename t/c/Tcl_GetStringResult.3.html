ARGUMENTOS

Tcl_Interp *interp (salida)
Intérprete cuyo resultado se va a modificar o leer.
Tcl_Obj *objPtr (entrada)
Valor Tcl que se convertirá en el resultado para interp.
char *result (entrada)
Valor de cadena que se convertirá en el resultado para interp o que se añadirá al resultado existente.
const char *element (entrada)
Valor de cadena que se añadirá como elemento de lista al resultado existente de interp.
Tcl_FreeProc *freeProc (entrada)
Dirección del procedimiento que se llamará para liberar el almacenamiento en result, o TCL_STATIC, TCL_DYNAMIC, o TCL_VOLATILE.
va_list argList (entrada)
Una lista de argumentos que debe haber sido inicializada con va_start y limpiada con va_end.
Tcl_Interp *sourceInterp (entrada)
Intérprete desde el cual se transferirán el resultado y las opciones de retorno.
Tcl_Interp *targetInterp (entrada)
Intérprete al cual se transferirán el resultado y las opciones de retorno.
int code (entrada)
Valor del código de retorno que controla la transferencia de opciones de retorno.

DESCRIPCIÓN

Los procedimientos descritos aquí son utilidades para manipular el valor de resultado en un intérprete Tcl. El resultado del intérprete puede ser un valor Tcl o una cadena. Por ejemplo, Tcl_SetObjResult y Tcl_SetResult establecen el resultado del intérprete a, respectivamente, un valor y una cadena. De manera similar, Tcl_GetObjResult y Tcl_GetStringResult devuelven el resultado del intérprete como valor y como cadena. Los procedimientos siempre mantienen la coherencia entre la forma de cadena y la forma de valor del resultado del intérprete. Por ejemplo, si se llama a Tcl_SetObjResult para establecer el resultado a un valor, y luego se llama a Tcl_GetStringResult, devolverá la representación en cadena de ese valor.

Tcl_SetObjResult organiza para que objPtr sea el resultado para interp, reemplazando cualquier resultado existente. El resultado se deja apuntando al valor referenciado por objPtr. El contador de referencias de objPtr se incrementa ya que ahora hay una nueva referencia a él desde interp. El contador de referencias de cualquier valor de resultado antiguo se decrementa y el valor de resultado antiguo se libera si ya no quedan referencias a él.

Tcl_GetObjResult devuelve el resultado para interp como un valor. El contador de referencias del valor no se incrementa; si la persona que llama necesita retener un puntero a largo plazo al valor, debe usar Tcl_IncrRefCount para incrementar su contador de referencias para evitar que se libere demasiado pronto o se modifique accidentalmente.

Tcl_SetResult organiza para que result sea el resultado para el comando Tcl actual en interp, reemplazando cualquier resultado existente. El argumento freeProc especifica cómo gestionar el almacenamiento para el argumento result; se discute en la sección EL ARGUMENTO TCL_FREEPROC PARA TCL_SETRESULT a continuación. Si result es NULL, entonces se ignora freeProc y Tcl_SetResult reinicializa el resultado de interp para que apunte a una cadena vacía.

Tcl_GetStringResult devuelve el resultado para interp como una cadena. Si el resultado se estableció como un valor mediante una llamada a Tcl_SetObjResult, la forma de valor se convertirá a una cadena y se devolverá. Si la representación en cadena del valor contiene bytes nulos, esta conversión provocará una pérdida de información. Por esta razón, se anima a los programadores a escribir su código para usar los nuevos procedimientos de API de valor y a llamar a Tcl_GetObjResult en su lugar.

Tcl_ResetResult limpia el resultado para interp y deja el resultado en su estado inicial vacío normal. Si el resultado es un valor, su contador de referencias se decrementa y el resultado se deja apuntando a un valor no compartido que representa una cadena vacía. Si el resultado es una cadena asignada dinámicamente, su memoria se libera y el resultado se deja como una cadena vacía. Tcl_ResetResult también limpia el estado de error gestionado por Tcl_AddErrorInfo, Tcl_AddObjErrorInfo y Tcl_SetErrorCode.

Tcl_AppendResult facilita la construcción de resultados Tcl en piezas. Toma cada uno de sus argumentos result y los añade en orden al resultado actual asociado con interp. Si el resultado está en su estado inicial vacío (por ejemplo, se acaba de invocar un procedimiento de comando o se acaba de llamar a Tcl_ResetResult), entonces Tcl_AppendResult establece el resultado a la concatenación de sus argumentos result. Tcl_AppendResult puede llamarse repetidamente a medida que se producen piezas adicionales del resultado. Tcl_AppendResult se encarga de todas las cuestiones de gestión de almacenamiento asociadas con la gestión del resultado de interp, como la asignación de un área de resultado más grande si es necesario. También gestiona la conversión desde y hacia el campo result del interp para manejar la retrocompatibilidad con extensiones de estilo antiguo. Se puede pasar cualquier número de argumentos result en una sola llamada; el último argumento de la lista debe ser (char *)NULL.

Tcl_AppendResultVA es lo mismo que Tcl_AppendResult excepto que en lugar de tomar un número variable de argumentos toma una lista de argumentos.

Tcl_TransferResult transfiere el estado del intérprete de sourceInterp a targetInterp. Los dos intérpretes deben haber sido creados en el mismo hilo. Si sourceInterp y targetInterp son los mismos, no se hace nada. De lo contrario, Tcl_TransferResult mueve el resultado de sourceInterp a targetInterp y restablece el resultado en sourceInterp. También mueve el diccionario de opciones de retorno según lo controlado por el valor del código de retorno code de la misma manera que Tcl_GetReturnOptions.

INTERFACES OBSOLETAS

PROCEDIMIENTOS DE CADENA ANTIGUOS

El uso de los siguientes procedimientos está obsoleto ya que manipulan el resultado de Tcl como una cadena. Procedimientos como Tcl_SetObjResult que manipulan el resultado como un valor pueden ser significativamente más eficientes.

Tcl_AppendElement es similar a Tcl_AppendResult en que permite que los resultados se construyan en piezas. Sin embargo, Tcl_AppendElement solo toma un único argumento element y añade ese argumento al resultado actual como un elemento de lista Tcl válido. Tcl_AppendElement añade barras invertidas o llaves si es necesario para garantizar que el resultado de interp pueda analizarse como una lista y que element se extraiga como un único elemento. En condiciones normales, Tcl_AppendElement añadirá un carácter de espacio al resultado de interp justo antes de añadir el nuevo elemento de lista, de modo que los elementos de lista en el resultado estén correctamente separados. Sin embargo, si el nuevo elemento de lista es el primero en una lista o sublista (es decir, el resultado actual de interp está vacío, o consiste en el carácter único “{”, o termina en los caracteres “ {”) entonces no se añade ningún espacio.

Tcl_FreeResult realiza parte del trabajo de Tcl_ResetResult. Libera la memoria asociada con el resultado de interp. También establece interp->freeProc a cero, pero no cambia interp->result ni borra el estado de error. Tcl_FreeResult se usa más comúnmente cuando un procedimiento está a punto de reemplazar un valor de resultado con otro.

INTERFACES DEPRECADAS

Los Tcl_Eval, Tcl_EvalFile, Tcl_EvalToList y Tcl_GlobalEval, junto con Tcl_EvalEx, invocan de forma interna el comando Tcl_EvalObj. Este último puede ser invocado directamente si su código usa los objetos Tcl. Las interfaces de nivel superior son más fáciles de usar para la mayoría de los propósitos y no se deprecian. Los Tcl_EvalObj y Tcl_EvalEx que usan la representación de string de Tcl para los comandos también pueden hacer que el código sea menos eficiente que si usa directamente los comandos de objetos.

Las siguientes rutinas de configuración de resultados son soportadas:

Tcl_GetObjResult,
    Tcl_GetStringResult, Tcl_SetObjResult, y
    Tcl_SetResult.

Como ayuda de migración, el acceso se puede restaurar con la directiva del compilador

#define USE_INTERP_RESULT

pero esto solo pretende ofrecer soporte vital a código muerto que de otra manera no funcionaría.

EL ARGUMENTO TCL_FREEPROC A TCL_SETRESULT

El argumento freeProc de Tcl_SetResult especifica cómo el sistema Tcl gestionará el almacenamiento para el argumento result. Si Tcl_SetResult o Tcl_SetObjResult se llaman en un momento en que interp tiene un resultado de string, hacen lo necesario para desechar el antiguo resultado de string (ver la entrada del manual de Tcl_Interp para más detalles).

Si freeProc es TCL_STATIC significa que result se refiere a un área de almacenamiento estático que se garantiza que no se modificará hasta al menos la próxima llamada a Tcl_Eval. Si freeProc es TCL_DYNAMIC significa que result fue asignado con una llamada a Tcl_Alloc y ahora es propiedad del sistema Tcl. Tcl_SetResult se encargará de liberar el almacenamiento del string llamando a Tcl_Free cuando ya no sea necesario. Si freeProc es TCL_VOLATILE significa que result apunta a un área de memoria que probablemente será sobrescrita cuando Tcl_SetResult retorne (por ejemplo, apunta a algo en un marco de pila). En este caso, Tcl_SetResult hará una copia del string en almacenamiento asignado dinámicamente y se encargará de que la copia sea el resultado del comando Tcl actual.

Si freeProc no es uno de los valores TCL_STATIC, TCL_DYNAMIC y TCL_VOLATILE, entonces es la dirección de un procedimiento que Tcl debe llamar para liberar el string. Esto permite a las aplicaciones usar asignadores de memoria no estándar. Cuando Tcl ya no necesite el almacenamiento para el string, llamará a freeProc. FreeProc debe tener argumentos y un resultado que coincidan con el tipo Tcl_FreeProc:

typedef void Tcl_FreeProc(
        char *blockPtr);

Cuando se llama a freeProc, su blockPtr se establecerá al valor de result pasado a Tcl_SetResult.
