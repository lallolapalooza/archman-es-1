Tcl_ParseCommand(3) Procedimientos de la biblioteca Tcl Tcl_ParseCommand(3)

NOMBRE

Tcl_ParseCommand, Tcl_ParseExpr, Tcl_ParseBraces, Tcl_ParseQuotedString, Tcl_ParseVarName, Tcl_ParseVar, Tcl_FreeParse, Tcl_EvalTokens, Tcl_EvalTokensStandard - analizar scripts y expresiones Tcl

SINOPSIS

#include <tcl.h>

int
Tcl_ParseCommand(interp, start, numBytes, nested, parsePtr)

int
Tcl_ParseExpr(interp, start, numBytes, parsePtr)

int
Tcl_ParseBraces(interp, start, numBytes, parsePtr, append, termPtr)

int
Tcl_ParseQuotedString(interp, start, numBytes, parsePtr, append, termPtr)

int
Tcl_ParseVarName(interp, start, numBytes, parsePtr, append)

const char *
Tcl_ParseVar(interp, start, termPtr)

Tcl_FreeParse(usedParsePtr)

Tcl_Obj *
Tcl_EvalTokens(interp, tokenPtr, numTokens)

int
Tcl_EvalTokensStandard(interp, tokenPtr, numTokens)

ARGUMENTOS

Tcl_Interp *interp (out)
Para procedimientos distintos de Tcl_FreeParse, Tcl_EvalTokens y Tcl_EvalTokensStandard, se usa solo para informar errores; si es NULL, no se dejan mensajes de error después de los errores. Para Tcl_EvalTokens y Tcl_EvalTokensStandard, determina el contexto para evaluar el script y también se usa para informar errores; no debe ser NULL.
const char *start (in)
Puntero al primer carácter de la cadena a analizar.
int numBytes (in)
Número de bytes en la cadena a analizar, sin incluir ningún carácter nulo terminador. Si es menor que 0, entonces el script consiste en todos los caracteres que siguen a start hasta el primer carácter nulo.
int nested (in)
Si es distinto de cero, significa que el script es parte de una sustitución de comando, por lo que un corchete de cierre sin comillas debe tratarse como un terminador de comando. Si es cero, los corchetes de cierre no tienen un significado especial.
int append (in)
Si es distinto de cero, significa que *parsePtr ya contiene tokens válidos; los nuevos tokens deben añadirse a los ya presentes. Si es cero, significa que *parsePtr no está inicializado; cualquier información en él se ignora. Este argumento normalmente es 0.
Tcl_Parse *parsePtr (out)
Punta a la estructura que se llenará con información sobre el comando analizado, la expresión, el nombre de la variable, etc. Cualquier información previa en esta estructura se ignora, a menos que append sea distinto de cero en una llamada a Tcl_ParseBraces, Tcl_ParseQuotedString o Tcl_ParseVarName.
const char **termPtr (out)
Si no es NULL, apunta a una ubicación donde Tcl_ParseBraces, Tcl_ParseQuotedString y Tcl_ParseVar almacenarán un puntero al carácter justo después del carácter terminador (el corchete de cierre, el último carácter del nombre de la variable o la comilla de cierre (respectivamente)) si el análisis fue exitoso.
Tcl_Parse *usedParsePtr (in)
Punta a la estructura que fue llenada por una llamada anterior a Tcl_ParseCommand, Tcl_ParseExpr, Tcl_ParseVarName, etc.

DESCRIPCIÓN

Estos procedimientos analizan comandos Tcl o porciones de comandos Tcl como expresiones o referencias a variables. Cada procedimiento toma un puntero a un script (o una porción del mismo) y llena la estructura apuntada por parsePtr con una colección de tokens que describen la información que fue analizada. Los procedimientos normalmente devuelven TCL_OK. Sin embargo, si ocurre un error, devuelven TCL_ERROR, dejan un mensaje de error en el resultado de interp (si interp no es NULL), y no dejan nada en parsePtr.

Tcl_ParseCommand es un procedimiento que analiza scripts Tcl. Dado un puntero a un script, analiza el primer comando del script. Si el comando fue analizado con éxito, Tcl_ParseCommand devuelve TCL_OK y llena la estructura apuntada por parsePtr con información sobre la estructura del comando (ver abajo para detalles). Si ocurrió un error al analizar el comando, se devuelve TCL_ERROR, se deja un mensaje de error en el resultado de interp y no se deja información en *parsePtr.

Tcl_ParseExpr analiza expresiones Tcl. Dado un puntero a un script que contiene una expresión, Tcl_ParseExpr analiza la expresión. Si la expresión fue analizada con éxito, Tcl_ParseExpr devuelve TCL_OK y llena la estructura apuntada por parsePtr con información sobre la estructura de la expresión (ver abajo para detalles). Si ocurrió un error al analizar el comando, se devuelve TCL_ERROR, se deja un mensaje de error en el resultado de interp y no se deja información en *parsePtr.

Tcl_ParseBraces analiza una cadena o argumento de comando encerrado en llaves como {hola} o {cadena \t con \t tabulaciones} desde el principio de su argumento start. El primer carácter de start debe ser {. Si la cadena entre llaves fue analizada con éxito, Tcl_ParseBraces devuelve TCL_OK, llena la estructura apuntada por parsePtr con información sobre la estructura de la cadena (ver abajo para detalles), y almacena un puntero al carácter justo después de la } terminadora en la ubicación dada por *termPtr. Si ocurre un error al analizar la cadena, se devuelve TCL_ERROR, se deja un mensaje de error en el resultado de interp y no se deja información en *parsePtr ni en *termPtr.

Tcl_ParseQuotedString analiza una cadena entre comillas dobles como "la suma es [expr {$a+$b}]" desde el principio del argumento start. El primer carácter de start debe ser ". Si la cadena entre comillas dobles fue analizada con éxito, Tcl_ParseQuotedString devuelve TCL_OK, llena la estructura apuntada por parsePtr con información sobre la estructura de la cadena (ver abajo para detalles), y almacena un puntero al carácter justo después de la " terminadora en la ubicación dada por *termPtr. Si ocurre un error al analizar la cadena, se devuelve TCL_ERROR, se deja un mensaje de error en el resultado de interp y no se deja información en *parsePtr ni en *termPtr.

Tcl_ParseVarName analiza una referencia a una variable Tcl como $abc o $x([expr {$indice + 1}]) desde el principio de su argumento start. El primer carácter de start debe ser $. Si el nombre de la variable fue analizado con éxito, Tcl_ParseVarName devuelve TCL_OK y llena la estructura apuntada por parsePtr con información sobre la estructura del nombre de la variable (ver abajo para detalles). Si ocurre un error al analizar el comando, se devuelve TCL_ERROR, se deja un mensaje de error en el resultado de interp (si interp no es NULL) y no se deja información en *parsePtr.

Tcl_ParseVar analiza una referencia a una variable Tcl como $abc o $x([expr {$indice + 1}]) desde el principio de su argumento start. El primer carácter de start debe ser $. Si el nombre de la variable se analiza con éxito, Tcl_ParseVar devuelve un puntero al valor de cadena de la variable. Si ocurre un error al analizar, entonces se devuelve NULL y se deja un mensaje de error en el resultado de interp.

La información dejada en *parsePtr por Tcl_ParseCommand, Tcl_ParseExpr, Tcl_ParseBraces, Tcl_ParseQuotedString y Tcl_ParseVarName puede incluir memoria asignada dinámicamente. Si estos cinco procedimientos de análisis devuelven TCL_OK, entonces la llamada debe invocar Tcl_FreeParse para liberar el almacenamiento en *parsePtr. Estos procedimientos ignoran cualquier información existente en *parsePtr (a menos que append sea distinto de cero), por lo que si se realizan llamadas repetidas a alguno de ellos, se debe invocar Tcl_FreeParse una vez después de cada llamada.

Tcl_EvalTokensStandard evalúa una secuencia de tokens de análisis de una estructura Tcl_Parse. Los tokens típicamente consisten en todos los tokens de una palabra o todos los tokens que componen el índice para una referencia a una variable de arreglo. Tcl_EvalTokensStandard realiza las sustituciones solicitadas por los tokens y concatena los valores resultantes. El valor de retorno de Tcl_EvalTokensStandard es un código de finalización Tcl con uno de los valores TCL_OK, TCL_ERROR, TCL_RETURN, TCL_BREAK o TCL_CONTINUE, o posiblemente algún otro valor entero originado en una extensión. Además, se deja un valor de resultado o un mensaje de error en el resultado de interp; se puede recuperar usando Tcl_GetObjResult.

Tcl_EvalTokens difiere de Tcl_EvalTokensStandard solo en la convención de retorno

ESTRUCTURA DE ANÁLISIS TCL

Tcl_ParseCommand, Tcl_ParseExpr, Tcl_ParseBraces, Tcl_ParseQuotedString y Tcl_ParseVarName devuelven información de análisis en dos estructuras de datos, Tcl_Parse y Tcl_Token:

typedef struct Tcl_Parse {
    const char *commentStart;
    int commentSize;
    const char *commandStart;
    int commandSize;
    int numWords;
    Tcl_Token *tokenPtr;
    int numTokens;
    ...
} Tcl_Parse;
typedef struct Tcl_Token {
    int type;
    const char *start;
    int size;
    int numComponents;
} Tcl_Token;

Los primeros cinco campos de una estructura Tcl_Parse solo se rellenan con Tcl_ParseCommand. Estos campos no son utilizados por los otros procedimientos de análisis.

Tcl_ParseCommand rellena una estructura Tcl_Parse con información que describe un comando Tcl y cualquier comentario que preceda al comando. Si hay comentarios, el campo commentStart apunta al carácter # que inicia el primer comentario y commentSize indica el número de bytes en todos los comentarios que preceden al comando, incluido el carácter de nueva línea que termina el último comentario. Si el comando no va precedido por ningún comentario, commentSize es 0. Tcl_ParseCommand también establece el campo commandStart para que apunte al primer carácter de la primera palabra del comando (saltándose cualquier comentario y espacios en blanco iniciales) y commandSize da el número total de bytes en el comando, incluido el carácter apuntado por commandStart hasta e incluyendo el carácter de nueva línea, corchete de cierre o punto y coma que termina el comando. El campo numWords da el número total de palabras en el comando.

Todos los procedimientos de análisis establecen los campos restantes, tokenPtr y numTokens. El campo tokenPtr apunta al primero de una matriz de estructuras Tcl_Token que describen los componentes de la entidad que se está analizando. El campo numTokens da el número total de tokens presentes en la matriz. Cada token contiene cuatro campos. El campo type selecciona uno de varios tipos de tokens que se describen a continuación. El campo start apunta al primer carácter del token y el campo size da el número total de caracteres del token. Algunos tipos de token, como TCL_TOKEN_WORD y TCL_TOKEN_VARIABLE, consisten en varios tokens componentes, que siguen inmediatamente al token padre; el campo numComponents describe cuántos de estos hay. El campo type tiene uno de los siguientes valores:

TCL_TOKEN_WORD
Este token describe ordinariamente una palabra de un comando, pero también puede describir una cadena entrecomillada o entre llaves en una expresión. El token describe un componente del script que es el resultado de concatenar una secuencia de subcomponentes, cada uno descrito por un subtoken separado. El token comienza con el primer carácter que no sea un espacio en blanco del componente (que puede ser una comilla doble o una llave de apertura) e incluye todos los caracteres del componente hasta, pero sin incluir, el espacio, punto y coma, corchete de cierre, comilla de cierre o llave de cierre que termina el componente. El campo numComponents cuenta el número total de subtokens que componen la palabra, incluidos los subtokens de los tokens TCL_TOKEN_VARIABLE y TCL_TOKEN_BS.
TCL_TOKEN_SIMPLE_WORD
Este token tiene el mismo significado que TCL_TOKEN_WORD, excepto que se garantiza que la palabra consiste en un único subtoken TCL_TOKEN_TEXT. El campo numComponents es siempre 1.
TCL_TOKEN_EXPAND_WORD
Este token tiene el mismo significado que TCL_TOKEN_WORD, excepto que el analizador de comandos nota que esta palabra comenzó con el prefijo de expansión {*}, lo que indica que después de la sustitución, el valor de lista de esta palabra debe expandirse para formar múltiples argumentos en la evaluación del comando. Este tipo de token solo puede ser creado por Tcl_ParseCommand.
TCL_TOKEN_TEXT
El token describe un rango de texto literal que forma parte de una palabra. El campo numComponents es siempre 0.
TCL_TOKEN_BS
El token describe una secuencia de barra invertida como \n o \0xA3. El campo numComponents es siempre 0.
TCL_TOKEN_COMMAND
El token describe un comando cuyo resultado debe sustituirse en la palabra. El token incluye los corchetes que rodean el comando. El campo numComponents es siempre 0 (el comando anidado no se analiza; llame a Tcl_ParseCommand recursivamente si desea ver sus tokens).
TCL_TOKEN_VARIABLE
El token describe una sustitución de variable, incluido el símbolo $, el nombre de la variable y el índice de la matriz (si existe) hasta el corchete de cierre que termina el índice. Este token va seguido de uno o más tokens adicionales que describen el nombre de la variable y el índice de la matriz. Si numComponents es 1, la variable es escalar y el siguiente token es un token TCL_TOKEN_TEXT que da el nombre de la variable. Si numComponents es mayor que 1, la variable es una matriz: el primer subtoken es un token TCL_TOKEN_TEXT que da el nombre de la matriz y los tokens restantes son tokens TCL_TOKEN_TEXT, TCL_TOKEN_BS, TCL_TOKEN_COMMAND y TCL_TOKEN_VARIABLE que deben concatenarse para producir el índice de la matriz. El campo numComponents incluye subtokens anidados que forman parte de los tokens TCL_TOKEN_VARIABLE en el índice de la matriz.
TCL_TOKEN_SUB_EXPR
El token describe una subexpresión de una expresión (o una expresión completa). Una subexpresión puede consistir en un valor como un literal entero, una sustitución de variable o una subexpresión entre paréntesis; también puede consistir en un operador y sus operandos. El token comienza con el primer carácter que no sea un espacio en blanco de la subexpresión hasta, pero sin incluir, el espacio, llave, paréntesis de cierre o corchete que termina la subexpresión. Este token va seguido de uno o más tokens adicionales que describen la subexpresión. Si el primer subtoken después del token TCL_TOKEN_SUB_EXPR es un token TCL_TOKEN_OPERATOR, la subexpresión consiste en un operador y sus operandos en forma de token. Si el operador no tiene operandos, la subexpresión consiste solo en el token TCL_TOKEN_OPERATOR. Cada operando se describe mediante un token TCL_TOKEN_SUB_EXPR. De lo contrario, la subexpresión es un valor descrito por uno de los tipos de token TCL_TOKEN_WORD, TCL_TOKEN_TEXT, TCL_TOKEN_BS, TCL_TOKEN_COMMAND, TCL_TOKEN_VARIABLE y TCL_TOKEN_SUB_EXPR. El campo numComponents cuenta el número total de subtokens que componen la subexpresión; esto incluye los subtokens de cualquier token TCL_TOKEN_SUB_EXPR anidado.
TCL_TOKEN_OPERATOR
El token describe un operador de una expresión como && o hypot. Un token TCL_TOKEN_OPERATOR siempre va precedido por un token TCL_TOKEN_SUB_EXPR que describe el operador y sus operandos; el campo numComponents del token TCL_TOKEN_SUB_EXPR se puede usar para determinar el número de operandos. Un operador binario como * va seguido de dos tokens TCL_TOKEN_SUB_EXPR que describen sus operandos. Un operador unario como - va seguido de un único token TCL_TOKEN_SUB_EXPR para su operando. Si el operador es una función matemática como log10, el token TCL_TOKEN_OPERATOR dará su nombre y los siguientes tokens TCL_TOKEN_SUB_EXPR describirán sus operandos; si no hay operandos (como con rand), no seguirán tokens TCL_TOKEN_SUB_EXPR. Hay un operador ternario, ?, que aparece en subexpresiones if-then-else como x?y:z; en este caso, el token ? TCL_TOKEN_OPERATOR va seguido de tres tokens TCL_TOKEN_SUB_EXPR para los operandos x, y y z. El campo numComponents para un token TCL_TOKEN_OPERATOR es siempre 0.

Después de que Tcl_ParseCommand retorna, el primer token apuntado por el campo tokenPtr de la estructura Tcl_Parse siempre tiene el tipo TCL_TOKEN_WORD, TCL_TOKEN_SIMPLE_WORD o TCL_TOKEN_EXPAND_WORD. Le siguen los subtokens que deben concatenarse para producir el valor de esa palabra. El siguiente token es el token TCL_TOKEN_WORD, TCL_TOKEN_SIMPLE_WORD o TCL_TOKEN_EXPAND_WORD para la segunda palabra, seguido de los subtokens para esa palabra, y así sucesivamente hasta que se hayan contabilizado todas las numWords.

Después de que Tcl_ParseExpr retorna, el primer token apuntado por el campo tokenPtr de la estructura Tcl_Parse siempre tiene el tipo TCL_TOKEN_SUB_EXPR. Le siguen los subtokens que deben evaluarse para producir el valor de la expresión. Solo se modifica la información de los tokens en la estructura Tcl_Parse: los campos commentStart, commentSize, commandStart y commandSize no son modificados por Tcl_ParseExpr.

Después de que Tcl_ParseBraces retorna, la matriz de tokens apuntada por el campo tokenPtr de la estructura Tcl_Parse contendrá un único token TCL_TOKEN_TEXT si la cadena entre llaves no contiene ninguna barra invertida y nueva línea. Si la cadena contiene barras invertidas y nuevas líneas, la matriz de tokens contendrá uno o más subtokens TCL_TOKEN_TEXT o TCL_TOKEN_BS que deben concatenarse para producir el valor de la cadena. Si la cadena entre llaves era solo {} (es decir, la cadena estaba vacía), el único token TCL_TOKEN_TEXT tendrá un campo size que contendrá cero; esto asegura que aparezca al menos un token para describir la cadena entre llaves. Solo se modifica la información de los tokens en la estructura Tcl_Parse: los campos commentStart, los campos commentSize, commandStart y commandSize no son modificados por Tcl_ParseBraces.

Después de que Tcl_ParseQuotedString retorna, el array de tokens apuntado por el campo tokenPtr de la estructura Tcl_Parse depende del contenido de la cadena entre comillas. Consistirá en uno o más subtokens de tipo TCL_TOKEN_TEXT, TCL_TOKEN_BS, TCL_TOKEN_COMMAND y TCL_TOKEN_VARIABLE. El array siempre contiene al menos un token; por ejemplo, si el argumento start está vacío, el array retornado consiste en un único token TCL_TOKEN_TEXT con un campo size cero. Solo la información de los tokens en la estructura Tcl_Parse se modifica: los campos commentStart, commentSize, commandStart y commandSize no se modifican.

Después de que Tcl_ParseVarName retorna, el primer token apuntado por el campo tokenPtr de la estructura Tcl_Parse siempre tiene el tipo TCL_TOKEN_VARIABLE. Le siguen los subtokens que componen el nombre de la variable, como se describe anteriormente. La longitud total del nombre de la variable está contenida en el campo size del primer token. Al igual que en Tcl_ParseExpr, Tcl_ParseVarName solo modifica la información de los tokens en la estructura Tcl_Parse: los campos commentStart, commentSize, commandStart y commandSize no se modifican.

Todos los punteros de caracteres en las estructuras Tcl_Parse y Tcl_Token se refieren a caracteres en el argumento start pasado a Tcl_ParseCommand, Tcl_ParseExpr, Tcl_ParseBraces, Tcl_ParseQuotedString y Tcl_ParseVarName.

Hay campos adicionales en la estructura Tcl_Parse después del campo numTokens, pero estos son para uso privado de Tcl_ParseCommand, Tcl_ParseExpr, Tcl_ParseBraces, Tcl_ParseQuotedString y Tcl_ParseVarName; no deben ser referenciados por código fuera de estos procedimientos.
