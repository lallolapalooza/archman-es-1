ARGUMENTOS

Tcl_HashTable *tablePtr (entrada)
Dirección de la estructura de la tabla hash (para todos los procedimientos excepto Tcl_InitHashTable, esta debe haber sido inicializada por una llamada previa a Tcl_InitHashTable).
int keyType (entrada)
Tipo de claves a usar para la nueva tabla hash. Debe ser TCL_STRING_KEYS, TCL_ONE_WORD_KEYS, TCL_CUSTOM_TYPE_KEYS, TCL_CUSTOM_PTR_KEYS, o un valor entero mayor que 1.
Tcl_HashKeyType *typePtr (entrada)
Dirección de la estructura que define el comportamiento de la tabla hash.
const void *key (entrada)
Clave a usar para la búsqueda en la tabla. La forma exacta depende del keyType usado para crear la tabla.
int *newPtr (salida)
La palabra en *newPtr se establece en 1 si se creó una nueva entrada y 0 si ya existía una entrada para key.
Tcl_HashEntry *entryPtr (entrada)
Puntero a la entrada de la tabla hash.
ClientData value (entrada)
Nuevo valor a asignar a la entrada de la tabla hash. No necesita tener el tipo ClientData, pero debe caber en el mismo espacio que ClientData.
Tcl_HashSearch *searchPtr (entrada)
Puntero al registro a usar para mantener el seguimiento del progreso en la enumeración de todas las entradas en una tabla hash.

DESCRIPCIÓN

Una tabla hash consiste en cero o más entradas, cada una compuesta por una clave y un valor. Dada la clave de una entrada, las rutinas hash pueden localizar muy rápidamente la entrada y, por lo tanto, su valor. Puede haber como máximo una entrada en una tabla hash con una clave particular, pero muchas entradas pueden tener el mismo valor. Las claves pueden tener una de las cuatro formas: cadenas, valores de una palabra, matrices de enteros o claves personalizadas definidas por una estructura Tcl_HashKeyType (ver sección LA ESTRUCTURA TCL_HASHKEYTYPE abajo). Todas las claves en una tabla dada tienen la misma forma, que se especifica cuando se inicializa la tabla.

El valor de una entrada de tabla hash puede ser cualquier cosa que quepa en el mismo espacio que un puntero “char *”. Los valores para las entradas de la tabla hash son gestionados completamente por los clientes, no por el propio módulo hash. Típicamente, el valor de cada entrada es un puntero a una estructura de datos gestionada por el código del cliente.

Las tablas hash crecen de manera flexible a medida que aumenta el número de entradas, de modo que siempre hay menos de tres entradas por cubo hash, en promedio. Esto permite búsquedas rápidas independientemente del número de entradas en una tabla.

El núcleo proporciona tres funciones para la inicialización de tablas hash: Tcl_InitHashTable, Tcl_InitObjHashTable y Tcl_InitCustomHashTable.

Tcl_InitHashTable inicializa una estructura que describe una nueva tabla hash. El espacio para la estructura es proporcionado por el llamador, no por el módulo hash. El valor de keyType indica qué tipos de claves se utilizarán para todas las entradas de la tabla. Se permiten todos los tipos de clave descritos más adelante, con la excepción de TCL_CUSTOM_TYPE_KEYS y TCL_CUSTOM_PTR_KEYS.

Tcl_InitObjHashTable es un envoltorio alrededor de Tcl_InitCustomHashTable e inicializa una tabla hash cuyas claves son Tcl_Obj *.

Tcl_InitCustomHashTable inicializa una estructura que describe una nueva tabla hash. El espacio para la estructura es proporcionado por el llamador, no por el módulo hash. El valor de keyType indica qué tipos de claves se utilizarán para todas las entradas de la tabla. KeyType debe tener uno de los siguientes valores:

TCL_STRING_KEYS
Las claves son cadenas terminadas en nulo. Se pasan a las rutinas hash utilizando la dirección del primer carácter de la cadena.
TCL_ONE_WORD_KEYS
Las claves son valores de una sola palabra; se pasan a las rutinas hash y se almacenan en las entradas de la tabla hash como valores “char *”. El valor del puntero es la clave; no necesita (y generalmente no lo hace) apuntar realmente a una cadena.
TCL_CUSTOM_TYPE_KEYS
Las claves son de tipo arbitrario y se almacenan en la entrada. El hashing y la comparación se determinan por typePtr. La estructura Tcl_HashKeyType se describe en la sección LA ESTRUCTURA TCL_HASHKEYTYPE a continuación.
TCL_CUSTOM_PTR_KEYS
Las claves son punteros a un tipo arbitrario y se almacenan en la entrada. El hashing y la comparación se determinan por typePtr. La estructura Tcl_HashKeyType se describe en la sección LA ESTRUCTURA TCL_HASHKEYTYPE a continuación.
otro
Si keyType no es una de las anteriores, debe ser un valor entero mayor que 1. En este caso, las claves serán matrices de valores “int”, donde keyType da el número de enteros en cada clave. Esto permite usar estructuras como claves. Todas las claves deben tener el mismo tamaño. Las claves de matriz se pasan a las funciones hash utilizando la dirección del primer entero en la matriz.

Tcl_DeleteHashTable elimina todas las entradas de una tabla hash y libera la memoria asociada con el array de cubos y las entradas de la tabla. No libera la estructura de la tabla en sí (apuntada por tablePtr), ya que se supone que esa memoria es gestionada por el cliente. Tcl_DeleteHashTable tampoco libera ni manipula de ninguna otra manera los valores de las entradas de la tabla hash. Si los valores de las entradas apuntan a memoria asignada dinámicamente, es responsabilidad del cliente liberar estas estructuras antes de eliminar la tabla.

Tcl_CreateHashEntry localiza la entrada correspondiente a una clave particular, creando una nueva entrada en la tabla si aún no existía una con la clave dada. Si ya existía una entrada con la clave dada, entonces *newPtr se establece en cero. Si se creó una nueva entrada, entonces *newPtr se establece en un valor distinto de cero y el valor de la nueva entrada se establecerá en cero. El valor de retorno de Tcl_CreateHashEntry es un puntero a la entrada, que puede ser utilizado para recuperar y modificar el valor de la entrada o para eliminar la entrada de la tabla.

Tcl_DeleteHashEntry eliminará una entrada existente de una tabla. La memoria asociada con la entrada en sí será liberada, pero el cliente es responsable de cualquier limpieza asociada con el valor de la entrada, como liberar una estructura a la que apunta.

Tcl_FindHashEntry es similar a Tcl_CreateHashEntry excepto que no crea una nueva entrada si la clave no existe; en su lugar, devuelve NULL como resultado.

Tcl_GetHashValue y Tcl_SetHashValue se utilizan para leer y escribir el valor de una entrada, respectivamente. Los valores se almacenan y recuperan como tipo “ClientData”, que es lo suficientemente grande como para contener un valor de puntero. En casi todas las máquinas, esto también es lo suficientemente grande como para contener un valor entero.

Tcl_GetHashKey devuelve la clave para una entrada dada de la tabla hash, ya sea como un puntero a una cadena, una clave de una sola palabra (“char *”), o como un puntero a la primera palabra de una matriz de enteros, dependiendo del keyType utilizado para crear una tabla hash. En todos los casos, Tcl_GetHashKey devuelve un resultado con tipo “char *”. Cuando la clave es una cadena o una matriz, el resultado de Tcl_GetHashKey apunta a información en la entrada de la tabla; esta información permanecerá válida hasta que la entrada sea eliminada o su tabla sea eliminada.

Tcl_FirstHashEntry y Tcl_NextHashEntry pueden ser utilizados para recorrer todas las entradas de una tabla hash.

ESTRUCTURA TCL_HASHKEYTYPE

Los escritores de extensiones pueden definir nuevos tipos de claves hash definiendo cuatro procedimientos, inicializando una estructura Tcl_HashKeyType para describir el tipo y llamando a Tcl_InitCustomHashTable. La estructura Tcl_HashKeyType se define de la siguiente manera:

typedef struct Tcl_HashKeyType {
    int version;
    int flags;
    Tcl_HashKeyProc *hashKeyProc;
    Tcl_CompareHashKeysProc *compareKeysProc;
    Tcl_AllocHashEntryProc *allocEntryProc;
    Tcl_FreeHashEntryProc *freeEntryProc;
} Tcl_HashKeyType;

El miembro version es la versión de la tabla. Si esta estructura se amplía en el futuro, la versión se puede utilizar para distinguir entre diferentes estructuras. Debe establecerse en TCL_HASH_KEY_TYPE_VERSION.

El miembro flags es 0 o uno o más de los siguientes valores OR'ed juntos:

TCL_HASH_KEY_RANDOMIZE_HASH
Hay algunas cosas, como los punteros, que no se hash bien porque no utilizan los bits inferiores. Si este flag está activado, la tabla hash intentará rectificar esto aleatorizando los bits y luego utilizando los N bits superiores como índice en la tabla.
TCL_HASH_KEY_SYSTEM_HASH
Este flag obliga a Tcl a utilizar los procedimientos de asignación de memoria proporcionados por el sistema operativo al asignar y liberar memoria utilizada para almacenar las estructuras de datos de la tabla hash, y no a ninguna de las rutinas de asignación de memoria personalizadas de Tcl. Esto es importante si la tabla hash se va a utilizar en la implementación de un conjunto personalizado de rutinas de asignación, o algo de lo que podría depender un conjunto personalizado de rutinas de asignación, para evitar cualquier dependencia circular.

El miembro hashKeyProc contiene la dirección de una función que se llama para calcular un valor hash para la clave.

typedef unsigned int Tcl_HashKeyProc(
        Tcl_HashTable *tablePtr,
        void *keyPtr);

Si esto es NULL, se utiliza keyPtr y se asume TCL_HASH_KEY_RANDOMIZE_HASH.

El miembro compareKeysProc contiene la dirección de una función que se llama para comparar dos claves.

typedef int Tcl_CompareHashKeysProc(
        void *keyPtr,
        Tcl_HashEntry *hPtr);

Si esto es NULL, se comparan los punteros keyPtr. Si las claves no coinciden, la función devuelve 0; de lo contrario, devuelve 1.

El miembro allocEntryProc contiene la dirección de una función que se llama para asignar espacio para una entrada e inicializar la clave y clientData.

typedef Tcl_HashEntry *Tcl_AllocHashEntryProc(
        Tcl_HashTable *tablePtr,
        void *keyPtr);

Si esto es NULL, se utiliza Tcl_Alloc para asignar suficiente espacio para una Tcl_HashEntry, el puntero de clave se asigna a key.oneWordValue y clientData se establece en NULL. Las claves de cadena y las claves de matriz utilizan esta función para asignar suficiente espacio para la entrada y la clave en un solo bloque, en lugar de hacerlo en dos bloques. Esto ahorra espacio para un puntero a la clave desde la entrada y otra asignación de memoria. Las claves Tcl_Obj* utilizan esta función para asignar suficiente espacio para una entrada e incrementar el recuento de referencias en el valor.

El miembro freeEntryProc contiene la dirección de una función que se llama para liberar espacio para una entrada.

typedef void Tcl_FreeHashEntryProc(
        Tcl_HashEntry *hPtr);

Si esto es NULL, se utiliza Tcl_Free para liberar el espacio de la entrada. Las claves Tcl_Obj* utilizan esta función para decrementar el recuento de referencias en el valor.
