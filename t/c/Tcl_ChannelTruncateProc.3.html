ARGUMENTOS

const Tcl_ChannelType *typePtr (entrada)
Punta a una estructura que contiene las direcciones de los procedimientos que se pueden llamar para realizar E/S y otras funciones en el canal.
const char *channelName (entrada)
El nombre de este canal, como file3; no debe estar en uso por ningún otro canal. Puede ser NULL, en cuyo caso el canal se crea sin nombre. Si el canal creado se asigna a uno de los canales estándar (stdin, stdout o stderr), el nombre del canal asignado será el nombre del canal estándar.
ClientData instanceData (entrada)
Valor arbitrario de una palabra para asociar con este canal. Este valor se pasa a los procedimientos en typePtr cuando se invocan.
int mask (entrada)
Combinación OR de TCL_READABLE y TCL_WRITABLE para indicar si un canal es legible y escribible.
Tcl_Channel channel (entrada)
El canal sobre el que operar.
int direction (entrada)
TCL_READABLE significa que se desea el manejador de entrada; TCL_WRITABLE significa que se desea el manejador de salida.
ClientData *handlePtr (salida)
Punta a la ubicación donde se debe almacenar el manejador específico del sistema operativo.
int size (entrada)
El tamaño, en bytes, de los búferes a asignar en este canal.
int mask (entrada)
Una combinación OR de TCL_READABLE, TCL_WRITABLE y TCL_EXCEPTION que indica los eventos que han ocurrido en este canal.

Intérprete actual. (puede ser NULL)

Lista de opciones específicas (palabras separadas por espacios, sin "-") para añadir a la lista estándar de opciones genéricas. Puede ser NULL solo para el mensaje de error de opciones genéricas.

DESCRIPCIÓN

Tcl utiliza una arquitectura de canales de dos capas. Proporciona una capa superior genérica para permitir que los programas C y Tcl realicen entrada y salida utilizando las mismas API para una variedad de archivos, dispositivos, sockets, etc. Las API C genéricas se describen en la entrada del manual para Tcl_OpenFileChannel.

La capa inferior proporciona controladores de canales específicos del tipo para cada tipo de dispositivo compatible en cada plataforma. Esta entrada del manual describe las API C utilizadas para comunicarse entre la capa genérica y los controladores de canales específicos del tipo. También explica cómo se pueden añadir nuevos tipos de canales proporcionando nuevos controladores de canales.

Los controladores de canales consisten en varios componentes: Primero, cada controlador de canales proporciona una estructura Tcl_ChannelType que contiene punteros a funciones que implementan las diversas operaciones utilizadas por la capa genérica para comunicarse con el controlador de canales. La estructura Tcl_ChannelType y las funciones referenciadas por ella se describen en la sección TCL_CHANNELTYPE, más abajo.

Segundo, los controladores de canales suelen proporcionar un comando Tcl para crear instancias de ese tipo de canal. Por ejemplo, el comando Tcl open crea canales que utilizan los controladores de canales de archivo y de comando, y el comando Tcl socket crea canales que utilizan sockets TCP para la comunicación de red.

Tercero, un controlador de canales proporciona opcionalmente una función C para abrir instancias de canal de ese tipo. Por ejemplo, Tcl_OpenFileChannel abre un canal que utiliza el controlador de canales de archivo, y Tcl_OpenTcpClient abre un canal que utiliza el protocolo de red TCP. Estas funciones de creación suelen utilizar Tcl_CreateChannel internamente para abrir el canal.

Para añadir un nuevo tipo de canal, debe implementar una API C o un comando Tcl que abra un canal invocando Tcl_CreateChannel. Cuando su controlador llama a Tcl_CreateChannel, pasa una estructura Tcl_ChannelType que describe los procedimientos de E/S del controlador. La capa genérica invocará entonces las funciones referenciadas en esa estructura para realizar operaciones en el canal.

Tcl_CreateChannel abre un nuevo canal y asocia los typePtr e instanceData proporcionados con él. El canal se abre en el modo indicado por mask. Para una discusión de los controladores de canales, sus operaciones y la estructura Tcl_ChannelType, consulte la sección TCL_CHANNELTYPE, más abajo.

Tcl_CreateChannel interactúa con el código que administra los canales estándar. Una vez que se inicializó un canal estándar a través de una llamada a Tcl_GetStdChannel o una llamada a Tcl_SetStdChannel, cerrar este canal estándar hará que la próxima llamada a Tcl_CreateChannel también convierta el nuevo canal en el nuevo canal estándar. Consulte Tcl_StandardChannels para obtener un tratado general sobre los canales estándar y el comportamiento de la biblioteca Tcl con respecto a ellos.

Tcl_GetChannelInstanceData devuelve los datos de instancia asociados con el canal en channel. Esto es lo mismo que el argumento instanceData en la llamada a Tcl_CreateChannel que creó este canal.

Tcl_GetChannelType devuelve un puntero a la estructura Tcl_ChannelType utilizada por el canal en el argumento channel. Esto es lo mismo que el argumento typePtr en la llamada a Tcl_CreateChannel que creó este canal.

Tcl_GetChannelName devuelve una cadena que contiene el nombre asociado con el canal, o NULL si el argumento channelName de Tcl_CreateChannel era NULL.

Tcl_GetChannelHandle coloca el manejador de dispositivo específico del sistema operativo asociado con channel para la dirección dada direction en el

especificada por handlePtr y devuelve TCL_OK. Si el canal no tiene un manejador de dispositivo para la dirección especificada, entonces se devuelve TCL_ERROR. Los diferentes controladores de canal devuelven diferentes tipos de manejadores. Consulte las entradas del manual para cada controlador para determinar qué tipo de manejador se devuelve.

Tcl_GetChannelThread devuelve el id del hilo que está gestionando actualmente el channel especificado. Esto permite a los controladores de canal enviar sus eventos de archivo a la cola de eventos correcta, incluso para un núcleo multihilo.

Tcl_GetChannelMode devuelve una combinación OR de TCL_READABLE y TCL_WRITABLE, que indica si el canal está abierto para entrada y salida.

Tcl_GetChannelBufferSize devuelve el tamaño, en bytes, de los búferes asignados para almacenar la entrada o salida en channel. Si el valor no fue establecido por una llamada anterior a Tcl_SetChannelBufferSize, descrita a continuación, entonces se devuelve el valor predeterminado de 4096.

Tcl_SetChannelBufferSize establece el tamaño, en bytes, de los búferes que se asignarán en operaciones posteriores en el canal para almacenar entrada o salida. El argumento size debe estar entre uno y un millón, permitiendo búferes de un byte a un millón de bytes. Si size está fuera de este rango, Tcl_SetChannelBufferSize establece el tamaño del búfer en 4096.

Tcl_NotifyChannel es llamada por un controlador de canal para indicar a la capa genérica que los eventos especificados por mask han ocurrido en el canal. Los controladores de canal son responsables de invocar esta función siempre que los manejadores de canal necesiten ser llamados para el canal (o se deban realizar otras tareas pendientes como un vaciado de escritura). Consulte WATCHPROC a continuación para más detalles.

Tcl_BadChannelOption es llamada desde el setOptionProc o getOptionProc específico del controlador para generar un mensaje de error completo.

Tcl_ChannelBuffered devuelve el número de bytes de entrada actualmente en el búfer interno (área de retroceso) del propio canal. No informa sobre los datos en los búferes generales para la pila de canales de la que forma parte el canal suministrado.

Tcl_IsChannelShared comprueba el contador de referencias del channel especificado y devuelve si el channel fue compartido entre varios intérpretes (resultado == 1) o no (resultado == 0).

Tcl_IsChannelRegistered comprueba si el channel especificado está registrado en el interpretador dado (resultado == 1) o no (resultado == 0).

Tcl_IsChannelExisting comprueba si un canal con el nombre especificado está registrado en la lista global (de todos los hilos) de todos los canales (resultado == 1) o no (resultado == 0).

Tcl_CutChannel elimina el channel especificado de la lista global (de todos los hilos) de todos los canales (del hilo actual). No se permite la aplicación a un canal todavía registrado en algún intérprete. También notifica al controlador si la versión de Tcl_ChannelType es TCL_CHANNEL_VERSION_4 (o superior), y si Tcl_DriverThreadActionProc está definida para él.

Tcl_SpliceChannel agrega el channel especificado a la lista global (de todos los hilos) de todos los canales (del hilo actual). No se permite la aplicación a un canal registrado en algún intérprete. También notifica al controlador si la versión de Tcl_ChannelType es TCL_CHANNEL_VERSION_4 (o superior), y si Tcl_DriverThreadActionProc está definida para él.

Tcl_ClearChannelHandlers elimina todos los manejadores de canal y scripts de eventos asociados con el channel especificado, cerrando así todo el procesamiento de eventos para este canal.

TCL_CHANNELTYPE

Un controlador de canal proporciona una estructura Tcl_ChannelType que contiene punteros a funciones que implementan las diversas operaciones en un canal; estas operaciones se invocan según sea necesario por la capa genérica. La estructura fue versionada a partir de Tcl 8.3.2/8.4 para corregir un problema con los controladores de canal apilados. Consulte la sección OLD CHANNEL TYPES a continuación para obtener más detalles sobre la estructura antigua.

La estructura Tcl_ChannelType contiene los siguientes campos:

typedef struct Tcl_ChannelType {
        const char *typeName;
        Tcl_ChannelTypeVersion version;
        Tcl_DriverCloseProc *closeProc;
        Tcl_DriverInputProc *inputProc;
        Tcl_DriverOutputProc *outputProc;
        Tcl_DriverSeekProc *seekProc;
        Tcl_DriverSetOptionProc *setOptionProc;
        Tcl_DriverGetOptionProc *getOptionProc;
        Tcl_DriverWatchProc *watchProc;
        Tcl_DriverGetHandleProc *getHandleProc;
        Tcl_DriverClose2Proc *close2Proc;
        Tcl_DriverBlockModeProc *blockModeProc;
        Tcl_DriverFlushProc *flushProc;
        Tcl_DriverHandlerProc *handlerProc;
        Tcl_DriverWideSeekProc *wideSeekProc;
        Tcl_DriverThreadActionProc *threadActionProc;
        Tcl_DriverTruncateProc *truncateProc;
} Tcl_ChannelType;

No es necesario proporcionar implementaciones para todas las operaciones del canal. Aquellas que no sean necesarias pueden establecerse en NULL en la estructura: blockModeProc, seekProc, setOptionProc, getOptionProc, getHandleProc y close2Proc, además de flushProc, handlerProc, threadActionProc y truncateProc. Otras funciones que no se puedan implementar de forma significativa deben devolver EINVAL cuando se llamen, para indicar que las operaciones que representan no están disponibles. Tenga en cuenta también que wideSeekProc puede ser NULL si seekProc lo es.

El usuario solo debe utilizar la estructura anterior para la instanciación de Tcl_ChannelType. Al hacer referencia a los campos en una estructura Tcl_ChannelType, se deben utilizar las siguientes funciones para obtener los valores: Tcl_ChannelName, Tcl_ChannelVersion, Tcl_ChannelBlockModeProc, Tcl_ChannelCloseProc, Tcl_ChannelClose2Proc, Tcl_ChannelInputProc, Tcl_ChannelOutputProc, Tcl_ChannelSeekProc, Tcl_ChannelWideSeekProc, Tcl_ChannelThreadActionProc, Tcl_ChannelTruncateProc, Tcl_ChannelSetOptionProc, Tcl_ChannelGetOptionProc, Tcl_ChannelWatchProc, Tcl_ChannelGetHandleProc, Tcl_ChannelFlushProc o Tcl_ChannelHandlerProc.

El cambio en las estructuras se realizó de manera que los tipos de canal estándar sean compatibles binariamente. Sin embargo, los tipos de canal que utilizan canales apilados (es decir, TLS, Trf) tienen nuevas versiones para corresponder al cambio anterior, ya que el código anterior para canales apilados tenía problemas.

TYPENAME

El campo typeName contiene una cadena terminada en nulo que identifica el tipo de dispositivo implementado por este controlador, por ejemplo, file o socket.

Este valor se puede recuperar con Tcl_ChannelName, que devuelve un puntero a la cadena.

VERSION

El campo version debe establecerse en la versión de la estructura que requiere. TCL_CHANNEL_VERSION_2 es el mínimo recomendado. TCL_CHANNEL_VERSION_3 debe establecerse para especificar el miembro wideSeekProc. TCL_CHANNEL_VERSION_4 debe establecerse para especificar el miembro threadActionProc (incluye wideSeekProc). TCL_CHANNEL_VERSION_5 debe establecerse para especificar los miembros truncateProc (incluye wideSeekProc y threadActionProc). Si no se establece en ninguno de estos, se asume que este Tcl_ChannelType tiene la estructura original. Consulte OLD CHANNEL TYPES para más detalles. Mientras que Tcl reconocerá y funcionará con ambas estructuras, los canales apilados deben ser de al menos TCL_CHANNEL_VERSION_2 para funcionar correctamente.

Este valor se puede recuperar con Tcl_ChannelVersion, que devuelve una de las siguientes: TCL_CHANNEL_VERSION_5, TCL_CHANNEL_VERSION_4, TCL_CHANNEL_VERSION_3, TCL_CHANNEL_VERSION_2 o TCL_CHANNEL_VERSION_1.

BLOCKMODEPROC

El campo blockModeProc contiene la dirección de una función llamada por la capa genérica para establecer el modo de bloqueo y no bloqueo en el dispositivo. BlockModeProc debe coincidir con el siguiente prototipo:

typedef int Tcl_DriverBlockModeProc(
        ClientData instanceData,
        int mode);

El instanceData es el mismo valor que se pasó a Tcl_CreateChannel cuando se creó este canal. El argumento mode es TCL_MODE_BLOCKING o TCL_MODE_NONBLOCKING para establecer el dispositivo en modo de bloqueo o no bloqueo. La función debe devolver cero si la operación fue exitosa, o un código de error POSIX distinto de cero si la operación falló.

Si la operación es exitosa, la función puede modificar el instanceData suministrado para registrar que el canal entró en modo de bloqueo o no bloqueo y para implementar el comportamiento de bloqueo o no bloqueo. Para algunos tipos de dispositivos, el comportamiento de bloqueo y no bloqueo puede ser implementado por el sistema operativo subyacente; para otros tipos de dispositivos, el comportamiento debe ser emulado en el controlador del canal.

Este valor se puede recuperar con Tcl_ChannelBlockModeProc, que devuelve un puntero a la función.

Un controlador de canal que ** no ** suministra un blockModeProc debe ser muy, muy cuidadoso. Debe indicar a la capa genérica exactamente qué modo de bloqueo es aceptable para él, y también debe documentar esto para el usuario, de modo que el modo de bloqueo del canal no se cambie a un valor inaceptable. Cualquier confusión aquí puede llevar al intérprete a un interbloqueo (falso y difícil de encontrar).

INPUTPROC

El campo inputProc contiene la dirección de una función llamada por la capa general para leer datos de un archivo o dispositivo y almacenarlos en un búfer interno. InputProc debe corresponder al siguiente prototipo:

typedef int Tcl_DriverInputProc(
        ClientData instanceData,
        char *buf,
        int bufSize,
        int *errorCodePtr);

InstanceData es el mismo que el valor que se pasó a Tcl_CreateChannel cuando el canal fue creado. El argumento buf apunta a un arreglo de bytes en el cual se almacenarán los datos de entrada del dispositivo, y el argumento bufSize indica cuántos bytes están disponibles en buf.

El argumento errorCodePtr apunta a una variable entera proporcionada por la capa general. Si ocurre un error, la función debe establecer este valor en un código de error POSIX que identifique el error.

La función debe leer los datos del dispositivo encapsulado por el canal y almacenarlos en buf. En caso de éxito, debe retornar un número no negativo indicando cuántos bytes se leyeron del dispositivo y almacenaron en buf. En caso de error, retornará -1. Si ocurre un error después de que se hayan leído algunos datos del dispositivo, esos datos se perderán.

Si inputProc puede determinar que el dispositivo tiene datos disponibles pero menos de lo solicitado por el argumento bufSize, la función solo debe intentar leer la cantidad de datos disponible y retornar sin bloquear. Si el dispositivo no tiene datos disponibles y el canal está en modo no bloqueante, la función debe retornar un error EAGAIN. Si el dispositivo no tiene datos disponibles y el canal está en modo bloqueante, la función debe bloquear por el tiempo más corto posible hasta que se pueda leer al menos un byte del dispositivo, y luego retornar los datos que se puedan leer sin bloquear.

Este valor puede obtenerse con Tcl_ChannelInputProc, que retorna un puntero a la función.

OUTPUTPROC

El campo outputProc contiene la dirección de una función llamada por la capa general para transferir datos del búfer interno al dispositivo de salida. OutputProc debe corresponder al siguiente prototipo:

typedef int Tcl_DriverOutputProc(
        ClientData instanceData,
        const char *buf,
        int toWrite,
        int *errorCodePtr);

InstanceData es el mismo que el valor que se pasó a Tcl_CreateChannel cuando el canal fue creado. El argumento buf contiene un arreglo de bytes que se escribirán en el dispositivo, y el argumento toWrite indica cuántos bytes se escribirán desde el argumento buf.

El argumento errorCodePtr apunta a una variable entera proporcionada por la capa general. Si ocurre un error, la función debe establecer este valor en un código de error POSIX que identifique el error.

La función debe escribir los datos en buf en el dispositivo de salida encapsulado por el canal. En caso de éxito, debe retornar un número no negativo indicando cuántos bytes se escribieron en el dispositivo de salida. El valor de retorno es normalmente el mismo que toWrite, pero puede ser menor en algunos casos, como cuando la operación de salida se interrumpe por un señal. Si ocurre un error, la función debe retornar -1. En caso de error, algunos datos podrían haber sido escritos en el dispositivo.

Si el canal está en modo no bloqueante y el dispositivo de salida no puede absorber ninguna data, la función debe retornar -1 con un error EAGAIN sin escribir ningún dato.

Este valor puede obtenerse con Tcl_ChannelOutputProc, que retorna un puntero a la función.

SEEKPROC Y WIDESEEKPROC

El campo seekProc contiene la dirección de una función llamada por la capa general para mover el punto de acceso en el cual se aplicarán las operaciones de entrada o salida siguientes. SeekProc debe corresponder al siguiente prototipo:

typedef int Tcl_DriverSeekProc(
        ClientData instanceData,
        long offset,
        int seekMode,
        int *errorCodePtr);

El argumento instanceData es el mismo que el valor que se pasó a Tcl_CreateChannel cuando este canal fue creado. Offset y seekMode tienen el mismo significado que en la procedura Tcl_Seek (descripción en el manual de Tcl_OpenFileChannel).

El argumento errorCodePtr apunta a una variable entera proporcionada por la capa general para devolver valores de errno de la función. La función debe establecer este valor en un código de error POSIX si ocurre un error. La función debe almacenar un código de error EINVAL si el tipo de canal no implementa el posicionamiento.

El valor de retorno es el nuevo punto de acceso o -1 en caso de error. Si ocurre un error, la función no debe mover el punto de acceso.

Si existe un seekProc no nulo, el campo wideSeekProc puede contener la dirección de una función alternativa que maneje desplazamientos (es decir, offsets mayores que 32 bits), permitiendo posiciones dentro de archivos mayores que 2 GB. La función wideSeekProc se llama en preferencia a seekProc, pero ambos deben estar definidos si el wideSeekProc está definido. WideSeekProc debe corresponder al siguiente prototipo:

typedef Tcl_WideInt Tcl_DriverWideSeekProc(
        ClientData instanceData,
        Tcl_WideInt offset,
        int seekMode,
        int *errorCodePtr);

Los argumentos y los valores de retorno son lo mismo que en seekProc, a menos que el tipo de offset y el tipo de retorno sean diferentes.

El campo seekProc puede obtenerse con Tcl_ChannelSeekProc, que retorna un puntero a la función, y el campo wideSeekProc puede obtenerse con Tcl_ChannelWideSeekProc.

SETOPTIONPROC

El campo setOptionProc contiene la dirección de una función llamada por la capa general para establecer una opción específica del tipo de canal en un canal. setOptionProc debe corresponder al siguiente prototipo:

typedef int Tcl_DriverSetOptionProc(
        ClientData instanceData,
        Tcl_Interp *interp,
        const char *optionName,
        const char *newValue);

optionName es el nombre de una opción a establecer, y newValue es el valor nuevo para esa opción, como cadena. instanceData es el mismo que el valor que se pasó a Tcl_CreateChannel cuando este canal fue creado. La función debe realizar cualquier acción específica del tipo de canal necesaria para implementar el nuevo valor de la opción.

Algunas opciones son gestionadas por la capa general y esta función nunca se llama para establecerlas, por ejemplo, -blockmode. Otras opciones son específicas de cada tipo de canal y la función setOptionProc del driver del canal se llama para implementarlas. El campo setOptionProc puede ser nulo, lo que indica que este tipo de canal no soporta opciones específicas.

Si el valor de la opción se modifica correctamente a su nuevo valor, la función retorna TCL_OK. Debe llamar a Tcl_BadChannelOption, que a su vez retorna TCL_ERROR si el optionName no es reconocido. Si el newValue especifica un valor que no es soportado o si ocurre un error en una llamada de sistema, la función debe dejar un mensaje de error en el resultado de interp si interp no es nulo. La función también debe llamar a Tcl_SetErrno para almacenar un código de error POSIX apropiado.

Este valor puede obtenerse con Tcl_ChannelSetOptionProc, que retorna un puntero a la función.

GETOPTIONPROC

El campo getOptionProc contiene la dirección de una función llamada por la capa general para obtener el valor de una opción específica del tipo de canal en un canal. getOptionProc debe corresponder al siguiente prototipo:

typedef int Tcl_DriverGetOptionProc(
        ClientData instanceData,
        Tcl_Interp *interp,
        const char *optionName,
        Tcl_DString *optionValue);

OptionName es el nombre de una opción soportada por este tipo de canal. Si el nombre de la opción no es nulo, la función almacena su valor actual, como cadena, en el string Tcl dynamic optionValue. Si optionName es nulo, la función almacena en optionValue una lista alternativa de todas las opciones soportadas y sus valores actuales. En caso de éxito, la función retorna TCL_OK. Debe llamar a Tcl_BadChannelOption, que a su vez retorna TCL_ERROR si el optionName no es reconocido.
