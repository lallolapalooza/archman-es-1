ARGUMENTOS

Tcl_Interp *interp (entrada)
Se utiliza para la notificación de errores y para buscar un canal registrado en él.
const char *fileName (entrada)
El nombre de un archivo local o de red.
const char *mode (entrada)
Especifica cómo se debe acceder al archivo. Puede tener cualquiera de los valores permitidos para el argumento mode del comando Tcl open.
int permissions (entrada)
Marcas de permisos estilo POSIX, como 0644. Si se crea un nuevo archivo, estos permisos se establecerán en el archivo creado.
int argc (entrada)
El número de elementos en argv.
const char **argv (entrada)
Argumentos para construir una tubería de comandos. Estos valores tienen el mismo significado que los argumentos sin opciones del comando Tcl exec.
int flags (entrada)
Especifica la disposición de los manejadores stdio en la tubería: combinación OR de TCL_STDIN, TCL_STDOUT, TCL_STDERR y TCL_ENFORCE_MODE. Si se establece TCL_STDIN, la entrada estándar del primer hijo de la tubería es el canal de la tubería, de lo contrario es la misma que la entrada estándar del proceso invocador; asimismo para TCL_STDOUT y TCL_STDERR. Si no se establece TCL_ENFORCE_MODE, entonces la tubería puede redirigir los manejadores stdio para anular los manejadores stdio para los cuales se han establecido TCL_STDIN, TCL_STDOUT y TCL_STDERR. Si se establece, dichas redirecciones causan un error.
ClientData handle (entrada)
Manejador específico del sistema operativo para E/S a un archivo. Para Unix es un descriptor de archivo, para Windows es un HANDLE.
int readOrWrite (entrada)
Combinación OR de TCL_READABLE y TCL_WRITABLE para indicar qué operaciones son válidas en handle.
const char *channelName (entrada)
El nombre del canal.
int *modePtr (salida)
Punta a una variable entera que recibirá una combinación OR de TCL_READABLE y TCL_WRITABLE indicando si el canal está abierto para lectura y escritura.
const char *pattern (entrada)
El patrón a comparar, pasado a Tcl_StringMatch, o NULL.
Tcl_Channel channel (entrada)
Un canal Tcl para entrada o salida. Debe haber sido el valor de retorno de un procedimiento como Tcl_OpenFileChannel.
Tcl_Obj *readObjPtr (entrada/salida)
Un puntero a un valor Tcl en el que se almacenarán los caracteres leídos del canal.
int charsToRead (entrada)
El número de caracteres a leer del canal. Si la codificación del canal es binary, esto es equivalente al número de bytes a leer del canal.
int appendFlag (entrada)
Si es distinto de cero, los datos leídos del canal se añadirán al valor. De lo contrario, los datos reemplazarán el contenido existente del valor.
char *readBuf (salida)
Un búfer en el que se almacenarán los bytes leídos del canal.
int bytesToRead (entrada)
El número de bytes a leer del canal. El búfer readBuf debe ser lo suficientemente grande para contener esta cantidad de bytes.
Tcl_Obj *lineObjPtr (entrada/salida)
Un puntero a un valor Tcl en el que se almacenará la línea leída del canal. La línea leída se añadirá al valor actual del valor.
Tcl_DString *lineRead (entrada/salida)
Un puntero a una cadena dinámica Tcl en la que se almacenará la línea leída del canal. Debe haber sido inicializada por el llamador. La línea leída se añadirá a cualquier dato que ya esté en la cadena dinámica.
const char *input (entrada)
La entrada a añadir a un búfer de canal.
int inputLen (entrada)
Longitud de la entrada
int addAtEnd (entrada)
Bandera que indica si la entrada debe añadirse al final o al principio del búfer del canal.
Tcl_Obj *writeObjPtr (entrada)
Un puntero a un valor Tcl cuyo contenido se enviará al canal.
const char *charBuf (entrada)
Un búfer que contiene los caracteres a enviar al canal.
const char *byteBuf (entrada)
Un búfer que contiene los bytes a enviar al canal.
int bytesToWrite (entrada)
El número de bytes a consumir de charBuf o byteBuf y enviar al canal.
Tcl_WideInt offset (entrada)
Hasta dónde mover el punto de acceso en el canal en el que se aplicará la siguiente operación de entrada o salida, medido en bytes desde la posición dada por seekMode. Puede ser positivo o negativo.
int seekMode (entrada)
A partir de qué punto buscar; se utiliza junto con offset para calcular el nuevo punto de acceso para el canal. Los valores legales son SEEK_SET, SEEK_CUR y SEEK_END.
Tcl_WideInt length (entrada)
La longitud (no negativa) a la que truncar el canal.
const char *optionName (entrada)
El nombre de una opción aplicable a este canal, como -blocking. Puede tener cualquiera de los valores aceptados por el comando fconfigure.
Tcl_DString *optionValue (entrada)
Dónde almacenar el valor de una opción o una lista de todas las opciones y sus valores. Debe haber sido inicializado por el llamador.
const char *newValue (entrada)
Nuevo valor para la opción dada por optionName.

DESCRIPCIÓN

El mecanismo de canales de Tcl proporciona un mecanismo independiente de dispositivo y de plataforma para realizar operaciones de entrada y salida con búferes en una variedad de tipos de archivos, sockets y dispositivos. El mecanismo de canales es extensible a nuevos tipos de canales, proporcionando un controlador de canal de bajo nivel para el nuevo tipo; la interfaz del controlador de canal se describe en la entrada del manual para Tcl_CreateChannel. El mecanismo de canales proporciona un esquema de búferes modelado según la E/S estándar de Unix, y también permite E/S no bloqueante en canales.

Los procedimientos descritos en esta entrada del manual comprenden las API de C de la capa genérica de la arquitectura de canales. Para una descripción de la arquitectura del controlador de canales y cómo implementar controladores de canales para nuevos tipos de canales, consulte la entrada del manual para Tcl_CreateChannel.

TCL_OPENFILECHANNEL

Tcl_OpenFileChannel abre un archivo especificado por fileName en el modo especificado por mode. El argumento mode es una cadena que especifica cómo se debe acceder al archivo. Sus valores son los mismos que los permitidos para el argumento mode del comando Tcl open. Por ejemplo, "r" abre un archivo para leer, "w" lo abre para escribir (truncándolo si ya existe), y "r+" lo abre para leer y escribir. Si se crea un nuevo archivo, se le aplican los permisos especificados en permissions. Los permisos se especifican como un número entero de tres dígitos que representa los permisos POSIX (por ejemplo, 0644). Si se produce un error, la rutina devolverá un canal nulo y dejará una entrada de error en el campo result de interp.

TCL_OPENCOMMANDCHANNEL

Tcl_OpenCommandChannel crea un canal Tcl que conecta a los procesos hijo creados por la ejecución de un comando con los manejadores de E/S estándar del proceso padre. El comando y sus argumentos se especifican en argv y argc. La bandera flags controla la redirección de la E/S estándar: TCL_STDIN, TCL_STDOUT y TCL_STDERR especifican qué manejadores estándar se redirigirán a la tubería. Si TCL_ENFORCE_MODE no está establecido, la tubería puede anular estos manejadores; si está establecido, dicha anulación provocará un error.

TCL_MAKEFILECHANNEL

Tcl_MakeFileChannel crea un canal Tcl a partir de un manejador de archivo existente proporcionado por el sistema operativo. El argumento handle es el manejador de archivo (por ejemplo, un descriptor de archivo en Unix o un HANDLE en Windows). El argumento readOrWrite es una combinación OR de TCL_READABLE y TCL_WRITABLE que indica qué operaciones son válidas en el manejador. El canal devuelto se registrará automáticamente en el intérprete.

TCL_GETCHANNEL

Tcl_GetChannel recupera un canal registrado en el intérprete actual con el nombre dado por channelName. Si modePtr no es NULL, la variable apuntada por modePtr se establecerá en una combinación OR de TCL_READABLE y TCL_WRITABLE, indicando si el canal está abierto para lectura y escritura, respectivamente. Si el canal no se encuentra o no se puede acceder a él, se devuelve un canal nulo.

TCL_GETCHANNELNAMES

Tcl_GetChannelNames devuelve el número de canales registrados en el intérprete actual. Los nombres de los canales se almacenan en un valor de objeto Tcl, que se adjunta al intérprete con la clave ``channelNames''. Si ya existe un valor con esa clave, se sobrescribe. Las llamadas posteriores a Tcl_GetChannelNames reutilizarán el mismo valor de objeto, pero los valores de los canales que se añadan o eliminen se actualizarán en el objeto. Si un canal es un canal estándar (entrada, salida o error estándar), se añade un sufijo especial a su nombre en la lista de nombres de canales para indicarlo.

Tcl_GetChannelNamesEx es similar a Tcl_GetChannelNames, pero solo devuelve los nombres de los canales que coinciden con el patrón dado (usando Tcl_StringMatch).

TCL_REGISTERCHANNEL

Tcl_RegisterChannel registra el channel dado con el intérprete interp. Los canales deben registrarse antes de poder ser accedidos por nombre usando Tcl_GetChannel. El canal se asocia con el intérprete y se incluirá en la lista devuelta por Tcl_GetChannelNames.

TCL_UNREGISTERCHANNEL

Tcl_UnregisterChannel elimina el channel dado del intérprete interp. El canal y todos sus recursos asociados se liberan automáticamente. Se devuelve 0 si el canal se desregistró con éxito, o un valor distinto de cero si el canal no estaba registrado en el intérprete.

TCL_DETACHCHANNEL

Tcl_DetachChannel elimina el channel dado del intérprete interp, pero no libera el canal ni sus recursos asociados. Esto es útil cuando se quiere transferir la propiedad de un canal a otro subsistema. El canal ya no se puede acceder por nombre, pero el código que lo recuperó todavía puede utilizarlo. Se devuelve 0 si el canal se desvinculó con éxito, o un valor distinto de cero si el canal no estaba registrado en el intérprete.

TCL_ISTANDARDCHANNEL

Tcl_IsStandardChannel devuelve 1 si el channel dado es uno de los canales estándar (entrada, salida o error estándar), y 0 en caso contrario.

TCL_CLOSE

Tcl_Close cierra el channel dado. Esto provoca que se liberen todos los búferes asociados y que se cierren los recursos subyacentes. Si se están escribiendo datos en el canal, se intentará vaciar el búfer antes de cerrarlo. Si se produce un error durante el cierre (por ejemplo, durante el vaciado), se devolverá un valor distinto de cero; de lo contrario, se devolverá 0.

TCL_READCHARS

Tcl_ReadChars lee hasta charsToRead caracteres del channel dado y los almacena en el valor de objeto Tcl al que apunta readObjPtr. Si appendFlag es distinto de cero, los caracteres leídos se añadirán al valor existente; de lo contrario, se reemplazarán. El número de caracteres leídos se devuelve como resultado. Si se alcanza el fin del archivo, se devuelve un valor negativo. Si se produce un error, se devuelve un valor negativo distinto de -1 y se deja una entrada de error en el intérprete.

Si la codificación del canal es binaria, entonces charsToRead se interpreta como el número de bytes a leer.

TCL_READ

Tcl_Read lee hasta bytesToRead bytes del channel dado y los almacena en el búfer readBuf. El número de bytes leídos se devuelve como resultado. Si se alcanza el fin del archivo, se devuelve un valor negativo. Si se produce un error, se devuelve un valor negativo distinto de -1 y se deja una entrada de error en el intérprete.

Esta rutina está pensada para su uso con canales codificados como binarios. Para canales de texto, se debe usar Tcl_ReadChars.

TCL_GETSOBJ

Tcl_GetsObj lee caracteres del channel hasta que se encuentra un carácter de nueva línea o se alcanza el fin del archivo. Los caracteres leídos (sin el carácter de nueva línea, si está presente) se almacenan en el valor de objeto Tcl al que apunta lineObjPtr. El valor existente de lineObjPtr se borra antes de almacenar los caracteres leídos. La rutina devuelve el número de caracteres leídos (sin incluir el carácter de nueva línea). Si se alcanza el fin del archivo antes de leer algún carácter, se devuelve -1. Si se produce un error, se devuelve un valor negativo distinto de -1 y se deja una entrada de error en el intérprete.

TCL_GETS

Tcl_Gets es similar a Tcl_GetsObj, pero en lugar de almacenar la línea leída en un valor de objeto Tcl, la almacena en una cadena dinámica Tcl (*lineRead). La cadena dinámica debe haber sido inicializada por el llamador. Los caracteres leídos se añaden a la cadena dinámica. La rutina devuelve el número de caracteres añadidos a la cadena dinámica (sin incluir el carácter de nueva línea). Si se alcanza el fin del archivo antes de leer algún carácter, se devuelve -1. Si se produce un error, se devuelve un valor negativo distinto de -1 y se deja una entrada de error en el intérprete.

TCL_UNGETS

Tcl_Ungets antepone el búfer input de longitud inputLen al búfer de entrada del channel. Si addAtEnd es distinto de cero, la entrada se añade al final del búfer de entrada en lugar de al principio. Esto es útil para implementar comandos que necesitan leer datos adicionales de un canal, como leer un carácter y luego devolverlo para que sea procesado como parte de la siguiente llamada de lectura.

TCL_WRITE.................................................CH.

Tcl_WriteObj escribe el contenido del valor de objeto Tcl al que apunta writeObjPtr al channel dado. Tcl_WriteChars escribe bytesToWrite caracteres del búfer charBuf al canal. Tcl_Write escribe bytesToWrite bytes del búfer byteBuf al canal. En todos los casos, la rutina devuelve el número de caracteres o bytes escritos con éxito. Si se produce un error durante la escritura, se devuelve un valor negativo y se deja una entrada de error en el intérprete. La escritura puede no ser inmediata; los datos pueden permanecer en el búfer de salida hasta que se llame a Tcl_Flush o se cierre el canal.

Tcl_WriteObj está pensada para su uso con canales de texto. Las rutinas Tcl_WriteChars y Tcl_Write se utilizan para canales de texto y binarios, respectivamente. Sin embargo, si la codificación de un canal de texto es binaria, entonces se comportará de manera idéntica a Tcl_Write.

TCL_READRAW

Tcl_ReadRaw lee hasta bytesToRead bytes del channel dado y los almacena en el búfer readBuf. Devuelve el número de bytes leídos, o un valor negativo si se alcanza el fin del archivo o se produce un error.

Esta rutina está diseñada para su uso con canales binarios. Para canales de texto, se debe usar Tcl_ReadChars.

TCL_WRITERAW

Tcl_WriteRaw escribe bytesToWrite bytes del búfer byteBuf al channel dado. Devuelve el número de bytes escritos, o un valor negativo si se produce un error.

Esta rutina está diseñada para su uso con canales binarios. Para canales de texto, se debe usar Tcl_WriteChars.

TCL_EOF

Tcl_Eof devuelve 1 si se ha alcanzado el fin del archivo en el channel dado, y 0 en caso contrario. Esto es útil para determinar si se han leído todos los datos de un canal.

TCL_FLUSH

Tcl_Flush fuerza la escritura de todos los datos pendientes en el búfer de salida del channel dado al dispositivo subyacente. Esto es útil para garantizar que todos los datos se envíen, por ejemplo, antes de cerrar un canal o antes de esperar una respuesta de un dispositivo remoto. Devuelve 0 si el vaciado se completó correctamente, o un valor distinto de cero si se produjo un error.

TCL_INPUTBLOCKED

Tcl_InputBlocked devuelve 1 si la última operación de lectura en el channel dado no pudo leer ningún dato porque no había datos disponibles y el canal está en modo no bloqueante. De lo contrario, devuelve 0. Esto es útil para distinguir entre un fin de archivo y un bloqueo temporal en operaciones de E/S no bloqueantes.

TCL_INPUTBUFFERED

Tcl_InputBuffered devuelve el número de bytes que están actualmente en el búfer de entrada del channel y que aún no han sido leídos por la aplicación.

TCL_OUTPUTBUFFERED

Tcl_OutputBuffered devuelve el número de bytes que están actualmente en el búfer de salida del channel y que aún no han sido escritos en el dispositivo subyacente.

TCL_SEEK

Tcl_Seek cambia el punto de acceso actual para el channel dado. El argumento offset especifica cuántos bytes mover el punto de acceso, y seekMode especifica si el desplazamiento es relativo al principio del archivo (SEEK_SET), a la posición actual (SEEK_CUR) o al final del archivo (SEEK_END). La rutina devuelve la nueva posición de acceso en el canal como un valor Tcl_WideInt. Si se produce un error, se devuelve un valor de -1 y se deja una entrada de error en el intérprete.

Esta operación solo es válida para canales que admiten búsqueda, como archivos regulares. Intentar buscar en un canal no buscable (por ejemplo, un socket) provocará un error.

TCL_TELL

Tcl_Tell devuelve la posición actual del punto de acceso en el channel dado como un valor Tcl_WideInt. Si se produce un error, se devuelve un valor de -1 y se deja una entrada de error en el intérprete.

Esta operación solo es válida para canales que admiten búsqueda.

TCL_TRUNCATECHANNEL

Tcl_TruncateChannel trunca el channel dado a la longitud especificada por length. Solo es aplicable a canales de salida que admiten truncamiento, como archivos regulares. Si la operación tiene éxito, se devuelve 0; de lo contrario, se devuelve un valor distinto de cero y se deja una entrada de error en el intérprete.

TCL_GETCHANNELOPTION

Tcl_GetChannelOption recupera el valor de una opción específica del channel dado. El nombre de la opción se especifica en optionName (por ejemplo, -blocking o -buffering). El valor de la opción se almacena en la cadena dinámica Tcl al que apunta optionValue, la cual debe haber sido inicializada por el llamador. La rutina devuelve 0 si la opción se recuperó correctamente, o un valor distinto de cero si la opción no existe o se produjo un error.

Para recuperar todos los nombres de opciones y sus valores, se puede llamar a Tcl_GetChannelOption con optionName establecido en NULL. En este caso, optionValue contendrá una lista de todas las opciones y sus valores en el formato que usa el comando fconfigure.

TCL_SETCHANNELOPTION

Tcl_SetChannelOption establece el valor de una opción específica del channel dado. El nombre de la opción se especifica en optionName y el nuevo valor se proporciona en newValue. La rutina devuelve 0 si la opción se estableció correctamente, o un valor distinto de cero si la opción no existe o se produjo un error.

Las opciones que se pueden establecer incluyen -blocking, -buffering, -translation, -eofchar y -encoding. Consulte la documentación del comando Tcl fconfigure para obtener una lista completa de las opciones y sus significados.

TCL_OPENFILECHANNEL

Tcl_OpenFileChannel abre un archivo especificado por fileName y devuelve un manejador de canal que se puede usar para realizar operaciones de entrada y salida en el archivo. Esta API está modelada después del procedimiento fopen de la biblioteca estándar de E/S de Unix. La sintaxis y el significado de todos los argumentos son similares a los proporcionados en el comando open de Tcl al abrir un archivo. Si ocurre un error al abrir el canal, Tcl_OpenFileChannel devuelve NULL y registra un código de error POSIX que se puede recuperar con Tcl_GetErrno. Además, si interp no es NULL, Tcl_OpenFileChannel deja un mensaje de error en el resultado de interp después de cualquier error. A partir de Tcl 8.4, la API basada en valores Tcl_FSOpenFileChannel debe usarse en preferencia a Tcl_OpenFileChannel siempre que sea posible.

El canal recién creado no está registrado en el intérprete proporcionado; para registrarlo, use Tcl_RegisterChannel, que se describe a continuación. Si uno de los canales estándar, stdin, stdout o stderr se cerró previamente, el acto de crear el nuevo canal también lo asigna como un reemplazo para el canal estándar.

TCL_OPENCOMMANDCHANNEL

Tcl_OpenCommandChannel proporciona una interfaz de nivel C a las funciones de los comandos exec y open. Crea una secuencia de subprocesos especificados por los argumentos argv y argc y devuelve un canal que se puede utilizar para comunicarse con estos subprocesos. El argumento flags indica qué tipo de comunicación existirá con la tubería de comandos.

Si se establece la bandera TCL_STDIN, la entrada estándar del primer subproceso se vinculará al canal: escribir en el canal proporcionará entrada al subproceso. Si TCL_STDIN no está establecido, la entrada estándar del primer subproceso será la misma que la entrada estándar de esta aplicación. Si se establece TCL_STDOUT, la salida estándar del último subproceso se puede leer del canal; de lo contrario, irá a la salida estándar de esta aplicación. Si se establece TCL_STDERR, la salida de error estándar para todos los subprocesos se devuelve al canal y resulta en un error cuando se cierra el canal; de lo contrario, va al error estándar de esta aplicación. Si TCL_ENFORCE_MODE no está establecido, entonces argc y argv pueden redirigir los manejadores de stdio para anular TCL_STDIN, TCL_STDOUT y TCL_STDERR; si está establecido, entonces es un error que argc y argv anulen los canales stdio para los que se han establecido TCL_STDIN, TCL_STDOUT y TCL_STDERR.

Si ocurre un error al abrir el canal, Tcl_OpenCommandChannel devuelve NULL y registra un código de error POSIX que se puede recuperar con Tcl_GetErrno. Además, Tcl_OpenCommandChannel deja un mensaje de error en el resultado del intérprete. interp no puede ser NULL.

El canal recién creado no está registrado en el intérprete proporcionado; para registrarlo, use Tcl_RegisterChannel, que se describe a continuación. Si uno de los canales estándar, stdin, stdout o stderr se cerró previamente, el acto de crear el nuevo canal también lo asigna como un reemplazo para el canal estándar.

TCL_MAKEFILECHANNEL

Tcl_MakeFileChannel crea un Tcl_Channel a partir de un manejador de archivo existente y específico de la plataforma. El canal recién creado no está registrado en el intérprete proporcionado; para registrarlo, use Tcl_RegisterChannel, que se describe a continuación. Si uno de los canales estándar, stdin, stdout o stderr se cerró previamente, el acto de crear el nuevo canal también lo asigna como un reemplazo para el canal estándar.

TCL_GETCHANNEL

Tcl_GetChannel devuelve un canal dado el channelName utilizado para crearlo con Tcl_CreateChannel y un puntero a un intérprete Tcl en interp. Si no hay un canal con ese nombre registrado en ese intérprete, el procedimiento devuelve NULL. Si el argumento modePtr no es NULL, apunta a una variable entera que recibirá una combinación OR de TCL_READABLE y TCL_WRITABLE que describe si el canal está abierto para lectura y escritura.

Tcl_GetChannelNames y Tcl_GetChannelNamesEx escriben los nombres de los canales registrados en el resultado del intérprete como un valor de lista. Tcl_GetChannelNamesEx filtrará estos nombres según el pattern. Si pattern es NULL, no realizará ningún filtrado. El valor de retorno es TCL_OK si no ocurrieron errores al escribir en el resultado, de lo contrario es TCL_ERROR, y el mensaje de error se deja en el resultado del intérprete.

TCL_REGISTERCHANNEL

Tcl_RegisterChannel agrega un canal al conjunto de canales accesibles en interp. Después de esta llamada, los programas Tcl que se ejecuten en ese intérprete podrán referirse al canal en operaciones de entrada o salida utilizando el nombre dado en la llamada a Tcl_CreateChannel. Después de esta llamada, el canal se convierte en propiedad del intérprete, y el llamador no debe llamar a Tcl_Close para el canal; el canal se cerrará automáticamente cuando se desregistre del intérprete.

El código que se ejecuta fuera de cualquier intérprete Tcl puede llamar a Tcl_RegisterChannel con interp como NULL, para indicar que desea mantener una referencia a este canal. Posteriormente, el canal puede registrarse en un intérprete Tcl y solo se cerrará cuando el número correspondiente de llamadas a Tcl_UnregisterChannel se haya realizado. Esto permite que el código que se ejecuta fuera de cualquier intérprete mantenga de forma segura una referencia a un canal que también está registrado en un intérprete Tcl.

Este procedimiento interactúa con el código que administra los canales estándar. Si no se inicializaron canales estándar antes de la primera llamada a Tcl_RegisterChannel, se inicializarán con esa llamada. Consulte Tcl_StandardChannels para un tratado general sobre los canales estándar y el comportamiento de la biblioteca Tcl con respecto a ellos.

TCL_UNREGISTERCHANNEL

Tcl_UnregisterChannel elimina un canal del conjunto de canales accesibles en interp. Después de esta llamada, los programas Tcl ya no podrán utilizar el nombre del canal para referirse al canal en ese intérprete. Si esta operación eliminó el último registro del canal en cualquier intérprete, el canal también se cierra y se destruye.

El código no asociado con un intérprete Tcl puede llamar a Tcl_UnregisterChannel con interp como NULL, para indicar a Tcl que ya no tiene una referencia a ese canal. Si esta es la última referencia al canal, ahora se cerrará. Tcl_UnregisterChannel es muy similar a Tcl_DetachChannel excepto que también cerrará el canal si no existen más referencias a él.

TCL_DETACHCHANNEL

Tcl_DetachChannel elimina un canal del conjunto de canales accesibles en interp. Después de esta llamada, los programas Tcl ya no podrán utilizar el nombre del canal para referirse al canal en ese intérprete. Más allá de eso, este comando no tiene ningún efecto adicional. No se puede utilizar en los canales estándar (stdout, stderr, stdin), y devolverá TCL_ERROR si se le pasa uno de esos canales.

El código no asociado con un intérprete Tcl puede llamar a Tcl_DetachChannel con interp como NULL, para indicar a Tcl que ya no tiene una referencia a ese canal. Si esta es la última referencia al canal, a diferencia de Tcl_UnregisterChannel, no se cerrará.

TCL_ISSTANDARDCHANNEL

Tcl_IsStandardChannel verifica si un canal es uno de los tres canales estándar, stdin, stdout o stderr. Si es así, devuelve 1, de lo contrario 0.

No se intenta verificar si el canal dado o los canales estándar están inicializados o son válidos de otra manera.

TCL_CLOSE

Tcl_Close destruye el canal channel, que debe denotar un canal actualmente abierto. El canal no debe estar registrado en ningún intérprete cuando se llama a Tcl_Close. La salida en búfer se vacía en el dispositivo de salida del canal antes de destruir el canal, y cualquier entrada en búfer se descarta. Si este es un canal de bloqueo, la llamada no retorna hasta que todos los datos en búfer se envían exitosamente al dispositivo de salida del canal. Si este es un canal sin bloqueo y hay salida en búfer que no se puede escribir sin bloquear, la llamada retorna inmediatamente; la salida se vacía en segundo plano y el canal se cerrará una vez que todos los datos en búfer se hayan emitido. En este caso, los errores durante el vaciado no se informan.

Si el canal se cerró correctamente, Tcl_Close devuelve TCL_OK. Si ocurre un error, Tcl_Close devuelve TCL_ERROR y registra un código de error POSIX que se puede recuperar con Tcl_GetErrno. Si el canal se está cerrando sincrónicamente y ocurre un error durante el cierre del canal y interp no es NULL, se deja un mensaje de error en el resultado del intérprete.

Nota: no es seguro llamar a Tcl_Close en un canal que ha sido registrado usando Tcl_RegisterChannel; consulte la documentación de Tcl_RegisterChannel, arriba, para obtener más detalles. Si el canal alguna vez se ha proporcionado como el argumento chan en una llamada a Tcl_RegisterChannel, debe usar Tcl_UnregisterChannel en su lugar, que llamará internamente a Tcl_Close cuando todas las llamadas a Tcl_RegisterChannel hayan sido igualadas por llamadas correspondientes a Tcl_UnregisterChannel.

TCL_READCHARS Y TCL_READ

Tcl_ReadChars consume bytes del channel, convirtiendo los bytes a UTF-8 basándose en la codificación del canal y almacenando los datos producidos en la representación de cadena de readObjPtr. El valor de retorno de Tcl_ReadChars es el número de caracteres, hasta charsToRead, que se almacenaron en readObjPtr. Si ocurre un error al leer, el valor de retorno es -1 y Tcl_ReadChars registra un código de error POSIX que se puede recuperar con Tcl_GetErrno.

TCL_GETCHANNELOPTION

Tcl_GetChannelOption returns the current value for an option optionName on channel. If optionName is not a valid option for the channel, then Tcl_GetChannelOption leaves an error message in interp's result and returns TCL_ERROR. Otherwise, it returns TCL_OK and the value is stored in the Tcl object valuePtr. The object should have been initialized by the caller, and will be overwritten by the call. The options for channels are described in the Tcl fconfigure manual entry. The configuration options for a channel can be set using a series of calls to Tcl_DStringAppendElement. The various preexisting options and their possible values are described in the manual entry for the Tcl fconfigure command. Other options can be added by each channel type. These channel type specific options are described in the manual entry for the Tcl command that creates a channel of that type; for example, the additional options for TCP-based channels are described in the manual entry for the Tcl socket command. The procedure normally returns TCL_OK. If an error occurs, it returns TCL_ERROR and calls Tcl_SetErrno to store an appropriate POSIX error code.

TCL_SETCHANNELOPTION

Tcl_SetChannelOption sets a new value newValue for an option optionName on channel. The procedure normally returns TCL_OK. If an error occurs, it returns TCL_ERROR; in addition, if interp is non-NULL, Tcl_SetChannelOption leaves an error message in the interpreter's result.

TCL_EOF

Tcl_Eof returns a nonzero value if channel encountered an end of file during the last input operation.

TCL_INPUTBLOCKED

Tcl_InputBlocked returns a nonzero value if channel is in nonblocking mode and the last input operation returned less data than requested because there was insufficient data available. The call always returns zero if the channel is in blocking mode.

TCL_INPUTBUFFERED

Tcl_InputBuffered returns the number of bytes of input currently buffered in the internal buffers for a channel. If the channel is not open for reading, this function always returns zero.

TCL_OUTPUTBUFFERED

Tcl_OutputBuffered returns the number of bytes of output currently buffered in the internal buffers for a channel. If the channel is not open for writing, this function always returns zero.

PLATFORM ISSUES

The handles returned from Tcl_GetChannelHandle depend on the platform and the channel type. On Unix platforms, the handle is always a Unix file descriptor as returned from the open system call. On Windows platforms, the handle is a file HANDLE when the channel was created with Tcl_OpenFileChannel, Tcl_OpenCommandChannel, or Tcl_MakeFileChannel. Other channel types may return a different type of handle on Windows platforms.
