Tcl_CreateInterp(3) Procedimientos de la biblioteca Tcl Tcl_CreateInterp(3)

NOMBRE

Tcl_CreateInterp, Tcl_DeleteInterp, Tcl_InterpActive, Tcl_InterpDeleted - crear y eliminar intérpretes de comandos Tcl

SINOPSIS

#include <tcl.h>

Tcl_Interp *
Tcl_CreateInterp()

Tcl_DeleteInterp(interp)

int
Tcl_InterpDeleted(interp)

int
Tcl_InterpActive(interp)

ARGUMENTOS

Tcl_Interp *interp (entrada)
Token para el intérprete a destruir o consultar.

DESCRIPCIÓN

Tcl_CreateInterp crea una nueva estructura de intérprete y devuelve un token para ella. El token es necesario en las llamadas a la mayoría de los demás procedimientos Tcl, como Tcl_CreateCommand, Tcl_Eval y Tcl_DeleteInterp. El token devuelto por Tcl_CreateInterp solo puede pasarse a rutinas Tcl que se llamen desde el mismo hilo que la llamada original a Tcl_CreateInterp. No es seguro que varios hilos pasen el mismo token a las rutinas de Tcl. El nuevo intérprete se inicializa con los comandos Tcl integrados y con variables estándar como tcl_platform y env. Para vincular comandos adicionales, llame a Tcl_CreateCommand, y para crear variables adicionales, llame a Tcl_SetVar.

Tcl_DeleteInterp marca un intérprete como eliminado; el intérprete se eliminará finalmente cuando todas las llamadas a Tcl_Preserve para él se hayan emparejado con llamadas a Tcl_Release. En ese momento, se eliminarán todos los recursos asociados a él, incluidas variables, procedimientos y enlaces de comandos específicos de la aplicación. Después de que Tcl_DeleteInterp devuelva cualquier intento de usar Tcl_Eval en el intérprete fallará y devolverá TCL_ERROR. Después de la llamada a Tcl_DeleteInterp es seguro examinar el resultado del intérprete, consultar o establecer los valores de las variables, definir, anular la definición o recuperar procedimientos, y examinar la pila de evaluación en tiempo de ejecución. Consulte a continuación, en la sección INTÉRPRETES Y GESTIÓN DE MEMORIA para obtener más detalles.

Tcl_InterpDeleted devuelve un valor distinto de cero si Tcl_DeleteInterp se llamó con interp como argumento; esto indica que el intérprete se eliminará finalmente, cuando la última llamada a Tcl_Preserve para él se empareje con una llamada a Tcl_Release. Si se devuelve un valor distinto de cero, las llamadas posteriores a Tcl_Eval en este intérprete devolverán TCL_ERROR.

Tcl_InterpDeleted es útil en los callbacks de eliminación para distinguir entre cuándo solo se está eliminando la memoria de la que es responsable el callback y cuándo se está eliminando todo el intérprete. En el primer caso, el callback puede recrear los datos que se están eliminando, pero esto provocaría un bucle infinito si el intérprete se estuviera eliminando.

Tcl_InterpActive es útil para determinar si hay alguna ejecución de scripts en curso en un intérprete, lo cual es una información útil cuando Tcl está incrustado en un entorno con recolección de basura y es necesario determinar si el intérprete es un candidato para su eliminación. La función devuelve un valor verdadero si el intérprete tiene al menos una ejecución activa ejecutándose dentro de él, y un valor falso en caso contrario.

INTÉRPRETES Y GESTIÓN DE MEMORIA

Tcl_DeleteInterp se puede llamar en cualquier momento en un intérprete que pueda ser utilizado por evaluaciones anidadas y código C en varias extensiones. Tcl implementa un mecanismo simple que permite a los llamadores usar intérpretes sin preocuparse de que el intérprete se elimine en una llamada anidada, y sin requerir código especial para proteger el intérprete, en la mayoría de los casos. Este mecanismo garantiza que los usos anidados de un intérprete puedan seguir utilizándolo de forma segura incluso después de que se haya llamado a Tcl_DeleteInterp.

El mecanismo se basa en emparejar llamadas a Tcl_Preserve con llamadas a Tcl_Release. Si se ha llamado a Tcl_DeleteInterp, el intérprete solo se liberará cuando la última llamada a Tcl_Preserve se empareje con una llamada a Tcl_Release. Consulte la entrada del manual de Tcl_Preserve para obtener una descripción de estas funciones.

Las reglas para cuándo el usuario de un intérprete debe llamar a Tcl_Preserve y Tcl_Release son simples:

Intérpretes Pasados Como Argumentos
Las funciones que reciben un intérprete como argumento pueden usarlo de forma segura sin ninguna protección especial. Por lo tanto, cuando escriba una extensión que consista en nuevos comandos Tcl, no se necesita código especial para proteger los intérpretes recibidos como argumentos. Esto cubre la mayoría de todos los usos.
Creación y Eliminación de Intérpretes
Cuando se crea un nuevo intérprete y se utiliza en una llamada a Tcl_Eval, Tcl_VarEval, Tcl_GlobalEval, Tcl_SetVar o Tcl_GetVar, se debe envolver un par de llamadas a Tcl_Preserve y Tcl_Release alrededor de todos los usos del intérprete. Recuerde que no es seguro usar el intérprete una vez que se ha llamado a Tcl_Release. Para garantizar que el intérprete se elimine correctamente cuando ya no se necesite, llame a Tcl_InterpDeleted para probar si algún otro código ya llamó a Tcl_DeleteInterp; si no es así, llame a Tcl_DeleteInterp antes de llamar a Tcl_Release en su propio código.
Recuperando un Intérprete de una Estructura de Datos
Cuando un intérprete se recupera de una estructura de datos (por ejemplo, los datos del cliente de un callback) para usarlo en una de las funciones de evaluación (Tcl_Eval, Tcl_VarEval, Tcl_GlobalEval, Tcl_EvalObjv, etc.) o funciones de acceso a variables (Tcl_SetVar, Tcl_GetVar, Tcl_SetVar2Ex, etc.), se debe envolver un par de llamadas a Tcl_Preserve y Tcl_Release alrededor de todos los usos del intérprete; no es seguro reutilizar el intérprete una vez que se ha llamado a Tcl_Release. Si un intérprete se almacena dentro de una estructura de datos de callback, se debe configurar un mecanismo de limpieza de eliminación adecuado por el código que crea la estructura de datos para que el intérprete se elimine de la estructura de datos (por ejemplo, estableciendo el campo a NULL) cuando se elimine el intérprete. De lo contrario, puede estar usando un intérprete que se ha liberado y cuya memoria ya se ha reutilizado.

Todos los usos de intérpretes en Tcl y Tk ya han sido protegidos. Los escritores de extensiones deben asegurarse de que su código también proteja adecuadamente cualquier intérprete adicional utilizado, como se describe anteriormente.

Tenga en cuenta que los mecanismos de protección no funcionan bien con los sistemas de recolección de basura convencionales. Cuando esté en dicho entorno administrado, se debe usar Tcl_InterpActive para determinar cuándo un intérprete es un candidato para su eliminación debido a la inactividad.
