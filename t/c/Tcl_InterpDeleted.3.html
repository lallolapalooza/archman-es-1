Tcl_CreateInterp(3) Procedimientos de la biblioteca Tcl Tcl_CreateInterp(3)

NOMBRE

Tcl_CreateInterp, Tcl_DeleteInterp, Tcl_InterpActive, Tcl_InterpDeleted - crear y eliminar intérpretes de comandos Tcl

SINOPSIS

#include <tcl.h>

Tcl_Interp *
Tcl_CreateInterp()

Tcl_DeleteInterp(interp)

int
Tcl_InterpDeleted(interp)

int
Tcl_InterpActive(interp)

ARGUMENTOS

Tcl_Interp *interp (entrada)
Token para el intérprete a destruir o consultar.

DESCRIPCIÓN

Tcl_CreateInterp crea una nueva estructura de intérprete y devuelve un token para ella. El token se requiere en las llamadas a la mayoría de los otros procedimientos Tcl, como Tcl_CreateCommand, Tcl_Eval y Tcl_DeleteInterp. El token devuelto por Tcl_CreateInterp solo puede pasarse a rutinas Tcl llamadas desde el mismo hilo que la llamada original a Tcl_CreateInterp. No es seguro que múltiples hilos pasen el mismo token a las rutinas de Tcl. El nuevo intérprete se inicializa con los comandos Tcl incorporados y con variables estándar como tcl_platform y env. Para vincular comandos adicionales, llame a Tcl_CreateCommand, y para crear variables adicionales, llame a Tcl_SetVar.

Tcl_DeleteInterp marca un intérprete como eliminado; el intérprete se eliminará eventualmente cuando todas las llamadas a Tcl_Preserve para él se hayan emparejado con llamadas a Tcl_Release. En ese momento, todos los recursos asociados con él, incluidas variables, procedimientos y enlaces de comandos específicos de la aplicación, se eliminarán. Después de que Tcl_DeleteInterp devuelva, cualquier intento de usar Tcl_Eval en el intérprete fallará y devolverá TCL_ERROR. Después de la llamada a Tcl_DeleteInterp es seguro examinar el resultado del intérprete, consultar o establecer los valores de las variables, definir, eliminar o recuperar procedimientos, y examinar la pila de evaluación en tiempo de ejecución. Consulte a continuación, en la sección INTÉRPRETES Y GESTIÓN DE MEMORIA para obtener más detalles.

Tcl_InterpDeleted devuelve un valor distinto de cero si Tcl_DeleteInterp se llamó con interp como argumento; esto indica que el intérprete se eliminará eventualmente, cuando la última llamada a Tcl_Preserve para él se empareje con una llamada a Tcl_Release. Si se devuelve un valor distinto de cero, las llamadas posteriores a Tcl_Eval en este intérprete devolverán TCL_ERROR.

Tcl_InterpDeleted es útil en las devoluciones de llamada de eliminación para distinguir entre cuándo solo se está eliminando la memoria de la que es responsable la devolución de llamada y cuándo se está eliminando todo el intérprete. En el primer caso, la devolución de llamada puede recrear los datos que se eliminan, pero esto conduciría a un bucle infinito si se estuviera eliminando el intérprete.

Tcl_InterpActive es útil para determinar si hay alguna ejecución de scripts en curso en un intérprete, lo cual es una información útil cuando Tcl se incrusta en un entorno con recolección de basura y es necesario determinar si el intérprete es un candidato para su eliminación. La función devuelve un valor verdadero si el intérprete tiene al menos una ejecución activa en curso, y un valor falso en caso contrario.

INTÉRPRETES Y GESTIÓN DE MEMORIA

Tcl_DeleteInterp se puede llamar en cualquier momento en un intérprete que puede ser utilizado por evaluaciones anidadas y código C en varias extensiones. Tcl implementa un mecanismo simple que permite a los llamadores usar intérpretes sin preocuparse de que el intérprete se elimine en una llamada anidada, y sin requerir código especial para proteger el intérprete, en la mayoría de los casos. Este mecanismo garantiza que los usos anidados de un intérprete puedan continuar usándolo de forma segura incluso después de que se haya llamado a Tcl_DeleteInterp.

El mecanismo se basa en emparejar llamadas a Tcl_Preserve con llamadas a Tcl_Release. Si se ha llamado a Tcl_DeleteInterp, solo cuando la última llamada a Tcl_Preserve se empareje con una llamada a Tcl_Release, se liberará el intérprete. Consulte la entrada del manual de Tcl_Preserve para obtener una descripción de estas funciones.

Las reglas para cuándo el usuario de un intérprete debe llamar a Tcl_Preserve y Tcl_Release son simples:

Intérpretes Pasados Como Argumentos
Las funciones a las que se les pasa un intérprete como argumento pueden utilizar el intérprete de forma segura sin ninguna protección especial. Por lo tanto, cuando escriba una extensión que consista en nuevos comandos Tcl, no se necesita código especial para proteger los intérpretes recibidos como argumentos. Esto cubre la mayoría de todos los usos.
Creación Y Eliminación De Intérpretes
Cuando se crea un nuevo intérprete y se utiliza en una llamada a Tcl_Eval, Tcl_VarEval, Tcl_GlobalEval, Tcl_SetVar o Tcl_GetVar, se debe envolver un par de llamadas a Tcl_Preserve y Tcl_Release alrededor de todos los usos del intérprete. Recuerde que no es seguro usar el intérprete una vez que se haya llamado a Tcl_Release. Para garantizar que el intérprete se elimine correctamente cuando ya no sea necesario, llame a Tcl_InterpDeleted para probar si algún otro código ya llamó a Tcl_DeleteInterp; si no, llame a Tcl_DeleteInterp antes de llamar a Tcl_Release en su propio código.
Recuperación De Un Intérprete De Una Estructura De Datos
Cuando se recupera un intérprete de una estructura de datos (por ejemplo, los datos del cliente de una devolución de llamada) para usarlo en una de las funciones de evaluación (Tcl_Eval, Tcl_VarEval, Tcl_GlobalEval, Tcl_EvalObjv, etc.) o funciones de acceso a variables (Tcl_SetVar, Tcl_GetVar, Tcl_SetVar2Ex, etc.), se debe envolver un par de llamadas a Tcl_Preserve y Tcl_Release alrededor de todos los usos del intérprete; no es seguro reutilizar el intérprete una vez que se haya llamado a Tcl_Release. Si un intérprete se almacena dentro de una estructura de datos de devolución de llamada, el código que crea la estructura de datos debe configurar un mecanismo de limpieza de eliminación adecuado para que el intérprete se elimine de la estructura de datos (por ejemplo, estableciendo el campo en NULL) cuando se elimine el intérprete. De lo contrario, puede estar utilizando un intérprete que ha sido liberado y cuya memoria ya puede haber sido reutilizada.

Todos los usos de intérpretes en Tcl y Tk ya han sido protegidos. Los escritores de extensiones deben asegurarse de que su código también proteja adecuadamente cualquier intérprete adicional que se utilice, como se describe anteriormente.

Tenga en cuenta que los mecanismos de protección no funcionan bien con los sistemas convencionales de recolección de basura. Cuando se encuentre en un entorno administrado de este tipo, se debe utilizar Tcl_InterpActive para determinar cuándo un intérprete es un candidato para su eliminación debido a inactividad.

Tcl_InterpDeleted

3 Tcl Library Commands

Nombre

Tcl_InterpDeleted - indica si un intérprete Tcl ha sido destruido.

Sintaxis

int Tcl_InterpDeleted(interp)
    Tcl_Interp *interp;

Descripción

La función Tcl_InterpDeleted devuelve 1 si el intérprete especificado por interp ha sido destruido, y 0 en caso contrario. Esta función es útil en aplicaciones multihilo donde un hilo puede estar realizando una operación en un intérprete mientras otro hilo está destruyendo el mismo intérprete. Una llamada a Tcl_InterpDeleted puede ayudar a evitar condiciones de carrera.

Argumentos

interp (in)
Un puntero al intérprete Tcl que se va a comprobar.

Véase también

Tcl_CreateInterp(3)
Tcl_DeleteInterp(3)
Tcl_Interp(3)

Palabras clave

destruido, intérprete, multihilo, condición de carrera
