ARGUMENTOS

Tcl_Interp *interp (entrada)
Se utiliza para informar de errores y para buscar un canal registrado en él.
const char *fileName (entrada)
El nombre de un archivo local o de red.
const char *mode (entrada)
Especifica cómo se debe acceder al archivo. Puede tener cualquiera de los valores permitidos para el argumento mode del comando Tcl open.
int permissions (entrada)
Indicadores de permisos estilo POSIX, como 0644. Si se crea un archivo nuevo, estos permisos se aplicarán al archivo creado.
int argc (entrada)
El número de elementos en argv.
const char **argv (entrada)
Argumentos para construir una tubería de comandos. Estos valores tienen el mismo significado que los argumentos sin modificadores del comando Tcl exec.
int flags (entrada)
Especifica la disposición de los identificadores de E/S estándar en la tubería: combinación OR de TCL_STDIN, TCL_STDOUT, TCL_STDERR y TCL_ENFORCE_MODE. Si se establece TCL_STDIN, la entrada estándar para el primer hijo de la tubería es el canal de la tubería, de lo contrario, es la misma que la entrada estándar del proceso invocador; lo mismo ocurre con TCL_STDOUT y TCL_STDERR. Si no se establece TCL_ENFORCE_MODE, entonces la tubería puede redirigir los identificadores de E/S estándar para invalidar los identificadores de E/S para los que se han establecido TCL_STDIN, TCL_STDOUT y TCL_STDERR. Si se establece, dichas redirecciones provocan un error.
ClientData handle (entrada)
Identificador específico del sistema operativo para la E/S de un archivo. En Unix es un descriptor de archivo, en Windows es un HANDLE.
int readOrWrite (entrada)
Combinación OR de TCL_READABLE y TCL_WRITABLE para indicar qué operaciones son válidas en handle.
const char *channelName (entrada)
El nombre del canal.
int *modePtr (salida)
Puntero a una variable entera que recibirá una combinación OR de TCL_READABLE y TCL_WRITABLE que indica si el canal está abierto para lectura y escritura.
const char *pattern (entrada)
El patrón a comparar, pasado a Tcl_StringMatch, o NULL.
Tcl_Channel channel (entrada)
Un canal Tcl para entrada o salida. Debe haber sido el valor de retorno de un procedimiento como Tcl_OpenFileChannel.
Tcl_Obj *readObjPtr (entrada/salida)
Un puntero a un valor Tcl en el que se almacenarán los caracteres leídos del canal.
int charsToRead (entrada)
El número de caracteres a leer del canal. Si la codificación del canal es binary, esto es equivalente al número de bytes a leer del canal.
int appendFlag (entrada)
Si es distinto de cero, los datos leídos del canal se añadirán al valor. De lo contrario, los datos reemplazarán el contenido existente del valor.
char *readBuf (salida)
Un búfer en el que se almacenarán los bytes leídos del canal.
int bytesToRead (entrada)
El número de bytes a leer del canal. El búfer readBuf debe ser lo suficientemente grande para contener esta cantidad de bytes.
Tcl_Obj *lineObjPtr (entrada/salida)
Un puntero a un valor Tcl en el que se almacenará la línea leída del canal. La línea leída se añadirá al valor actual del valor.
Tcl_DString *lineRead (entrada/salida)
Un puntero a una cadena dinámica Tcl en la que se almacenará la línea leída del canal. Debe haber sido inicializada por el llamador. La línea leída se añadirá a cualquier dato ya existente en la cadena dinámica.
const char *input (entrada)
La entrada a añadir a un búfer de canal.
int inputLen (entrada)
Longitud de la entrada
int addAtEnd (entrada)
Indicador que señala si la entrada debe añadirse al final o al principio del búfer del canal.
Tcl_Obj *writeObjPtr (entrada)
Un puntero a un valor Tcl cuyo contenido se enviará al canal.
const char *charBuf (entrada)
Un búfer que contiene los caracteres a enviar al canal.
const char *byteBuf (entrada)
Un búfer que contiene los bytes a enviar al canal.
int bytesToWrite (entrada)
El número de bytes a consumir de charBuf o byteBuf y enviarlos al canal.
Tcl_WideInt offset (entrada)
Hasta dónde mover el punto de acceso en el canal en el que se aplicará la próxima operación de entrada o salida, medido en bytes desde la posición dada por seekMode. Puede ser positivo o negativo.
int seekMode (entrada)
Desde qué punto buscar; se utiliza con offset para calcular el nuevo punto de acceso para el canal. Los valores legales son SEEK_SET, SEEK_CUR y SEEK_END.
Tcl_WideInt length (entrada)
La longitud (no negativa) a la que se truncará el canal.
const char *optionName (entrada)
El nombre de una opción aplicable a este canal, como -blocking. Puede tener cualquiera de los valores aceptados por el comando fconfigure.
Tcl_DString *optionValue (entrada/salida)
Dónde almacenar el valor de una opción o una lista de todas las opciones y sus valores. Debe haber sido inicializado por el llamador.
const char *newValue (entrada)
Nuevo valor para la opción dada por optionName.

DESCRIPCIÓN

El mecanismo de canales Tcl proporciona un mecanismo independiente de dispositivos y de plataformas para realizar operaciones de entrada y salida con búfer en una variedad de tipos de archivos, sockets y dispositivos. El mecanismo de canales es extensible a nuevos tipos de canales, proporcionando un controlador de canal de bajo nivel para el nuevo tipo; la interfaz del controlador de canal se describe en la entrada del manual para Tcl_CreateChannel. El mecanismo de canales proporciona un esquema de búfer modelado según la E/S estándar de Unix, y también permite E/S no bloqueantes en los canales.

Los procedimientos descritos en esta entrada del manual comprenden las API de C de la capa genérica de la arquitectura de canales. Para una descripción de la arquitectura del controlador de canales y cómo implementar controladores de canales para nuevos tipos de canales, consulte la entrada del manual para Tcl_CreateChannel.

TCL_OPENFILECHANNEL

Abre un archivo especificado por fileName y lo devuelve como un canal Tcl. El argumento mode especifica cómo se debe acceder al archivo y tiene el mismo significado que el argumento mode para el comando Tcl open. El argumento permissions especifica los permisos POSIX del archivo si se crea uno nuevo (por ejemplo, 0644). Si se produce un error, el valor de retorno es NULL y interp->result se establece para describir el error.

TCL_OPENCOMMANDCHANNEL

Crea una tubería de uno o más procesos y devuelve un canal Tcl que representa la tubería. Los argumentos argc y argv especifican los comandos a ejecutar en la tubería, y tienen el mismo significado que los argumentos no modificadores del comando Tcl exec. El argumento flags controla la redirección de la entrada/salida estándar de los procesos de la tubería y debe ser una combinación OR de TCL_STDIN, TCL_STDOUT, TCL_STDERR y TCL_ENFORCE_MODE.

Si se establece TCL_STDIN, la entrada estándar del primer proceso de la tubería será el canal de la tubería devuelto. Si no, será la misma que la entrada estándar del proceso invocador. De manera similar, si se establece TCL_STDOUT, la salida estándar del último proceso de la tubería será el canal de la tubería devuelto; si se establece TCL_STDERR, el error estándar del último proceso de la tubería será el canal de la tubería devuelto. Si no se establece TCL_ENFORCE_MODE, los procesos de la tubería pueden redirigir sus propios identificadores de E/S estándar, lo que podría anular los identificadores que se habrían asignado a los canales Tcl. Si se establece TCL_ENFORCE_MODE, cualquier intento de redireccionar los identificadores de E/S estándar de un proceso de la tubería provocará un error.

El canal devuelto permitirá la lectura y escritura simultáneas, aunque la lectura y la escritura se gestionarán como operaciones separadas en el canal de tubería del sistema operativo.

Si se produce un error, el valor de retorno es NULL y interp->result se establece para describir el error.

TCL_MAKEFILECHANNEL

Crea un canal Tcl a partir de un identificador de archivo existente (un descriptor de archivo en Unix, un HANDLE en Windows). El argumento handle es el identificador de archivo, y readOrWrite es una combinación OR de TCL_READABLE y TCL_WRITABLE que indica si el identificador de archivo está abierto para lectura y/o escritura. Este procedimiento se utiliza típicamente cuando se necesita interactuar con identificadores de archivo que no fueron creados por Tcl, como los identificadores de archivo devueltos por la llamada al sistema socket() o los identificadores de archivo estándar heredados de un proceso padre.

Una vez que se ha creado un canal Tcl a partir de un identificador de archivo, el identificador de archivo subyacente ya no debe ser manipulado o cerrado directamente por el programa Tcl; todas las operaciones de E/S deben realizarse a través del canal Tcl. Tcl se encargará de cerrar el identificador de archivo cuando se cierre el canal Tcl.

El canal devuelto se registrará automáticamente en el intérprete proporcionado por el controlador de canal que maneja el tipo de identificador de archivo. El nombre del canal será un nombre genérico que puede ser substituido por un nombre más significativo si se utiliza Tcl_RegisterChannel.

Si se produce un error, el valor de retorno es NULL y interp->result se establece para describir el error.

TCL_GETCHANNEL

Busca un canal existente utilizando su nombre, channelName. Si se encuentra el canal, se devuelve un puntero al canal. Si el argumento modePtr no es NULL, la variable a la que apunta se establecerá con una combinación OR de TCL_READABLE y TCL_WRITABLE para indicar si el canal está abierto para lectura y escritura, respectivamente. Si no se encuentra el canal, se devuelve NULL y interp->result se establece para describir el error.

TCL_GETCHANNELNAMES

Devuelve un número entero que es el número de canales registrados actualmente en interp. El resultado se almacena en interp->result como una cadena de caracteres que contiene los nombres de todos los canales registrados, separados por espacios. Si no hay canales registrados, se devuelve una cadena vacía.

TCL_GETCHANNELNAMESEX

Devuelve un número entero que es el número de canales registrados actualmente en interp cuyos nombres coinciden con el patrón pattern. El resultado se almacena en interp->result como una cadena de caracteres que contiene los nombres de todos los canales coincidentes, separados por espacios. El patrón se evalúa utilizando el mismo algoritmo que el comando Tcl string match. Si pattern es NULL, se comportará como Tcl_GetChannelNames.

TCL_REGISTERCHANNEL

Registra el channel dado en el intérprete interp. Esto hace que el canal sea visible para los comandos Tcl de alto nivel como puts y gets. El nombre del canal se obtiene del controlador del canal. Si un canal con el mismo nombre ya está registrado, se producirá un error (y se establecerá el resultado del intérprete).

TCL_UNREGISTERCHANNEL

Anula el registro del channel dado del intérprete interp. Esto hace que el canal sea invisible para los comandos Tcl de alto nivel. El canal subyacente no se cierra; debe cerrarse explícitamente llamando a Tcl_Close. Se devuelve 0 si el canal se anuló correctamente, o -1 si no se encontró ningún canal con ese nombre o si el canal estaba en uso (por ejemplo, si se estaba ejecutando un evento de E/S). Si se devuelve -1, el resultado del intérprete se establecerá para describir el error.

TCL_DETACHCHANNEL

Desvincula el channel dado del intérprete interp. Esto hace que el canal sea invisible para los comandos Tcl de alto nivel y detiene cualquier operación de E/S que esté ocurriendo en el canal. El canal subyacente no se cierra; debe cerrarse explícitamente llamando a Tcl_Close. Se devuelve 0 si el canal se desvinculó correctamente, o -1 si no se encontró ningún canal con ese nombre. Si se devuelve -1, el resultado del intérprete se establecerá para describir el error.

TCL_ISSTANDARDCHANNEL

Devuelve 1 si el channel es uno de los canales estándar (entrada, salida o error estándar) y 0 en caso contrario.

TCL_CLOSE

Cierra el channel dado. Esto fuerza la escritura de cualquier dato en búfer y libera los recursos asociados con el canal. Si el canal se cerró correctamente, se devuelve 0; de lo contrario, se devuelve -1 y interp->result se establece para describir el error.

TCL_READCHARS

Lee hasta charsToRead caracteres del channel y los almacena en el objeto Tcl al que apunta readObjPtr. Si appendFlag es distinto de cero, los caracteres leídos se añaden al valor existente del objeto; de lo contrario, el valor existente se reemplaza. El número de caracteres leídos se devuelve como un entero. Si se produce un error de lectura, se devuelve -1 y el resultado del intérprete se establece para describir el error. Si se alcanza el final del archivo, se devuelve el número de caracteres leídos hasta ese punto (que puede ser 0).

Si el canal está abierto en modo binario, charsToRead realmente se interpreta como el número de bytes a leer.

TCL_READ

Lee hasta bytesToRead bytes del channel y los almacena en el búfer readBuf. El número de bytes leídos se devuelve como un entero. Si se produce un error de lectura, se devuelve -1 y el resultado del intérprete se establece para describir el error. Si se alcanza el final del archivo, se devuelve el número de bytes leídos hasta ese punto (que puede ser 0).

Este procedimiento está destinado a la lectura de datos en modo binario; para leer datos en modo texto, utilice Tcl_ReadChars o Tcl_GetsObj.

TCL_GETSOBJ

Lee una línea del channel y la almacena en el objeto Tcl al que apunta lineObjPtr. La línea leída se añade al valor existente del objeto. Se considera que una línea termina en un carácter de nueva línea (‘\n’). Si se lee un carácter de nueva línea, se incluye al final de la cadena almacenada en lineObjPtr. El número de caracteres leídos en la línea se devuelve como un entero. Si se produce un error de lectura, se devuelve -1 y el resultado del intérprete se establece para describir el error. Si se alcanza el final del archivo antes de leer algún carácter, se devuelve 0. Si se alcanza el final del archivo después de leer algunos caracteres, se devuelve el número de caracteres leídos.

Si el canal está abierto en modo binario, este procedimiento no estará disponible.

TCL_GETS

Lee una línea del channel y la almacena en la cadena dinámica Tcl al que apunta lineRead. La línea leída se añade a cualquier dato ya existente en la cadena dinámica. Se considera que una línea termina en un carácter de nueva línea (‘\n’). Si se lee un carácter de nueva línea, se incluye al final de la cadena almacenada en lineRead. El número de caracteres leídos en la línea se devuelve como un entero. Si se produce un error de lectura, se devuelve -1 y el resultado del intérprete se establece para describir el error. Si se alcanza el final del archivo antes de leer algún carácter, se devuelve 0. Si se alcanza el final del archivo después de leer algunos caracteres, se devuelve el número de caracteres leídos.

Este procedimiento está destinado a la lectura de datos en modo texto; para leer datos en modo binario, utilice Tcl_Read o Tcl_ReadRaw.

TCL_UNGETS

Añade la cadena input de longitud inputLen al principio o al final del búfer de entrada del channel, según el valor de addAtEnd. Si addAtEnd es distinto de cero, la entrada se añade al final del búfer; de lo contrario, se añade al principio. Se devuelve el número de caracteres añadidos. Si se produce un error, se devuelve -1 y el resultado del intérprete se establece para describir el error.

Este procedimiento es útil para simular la entrada de caracteres que ya se han leído pero que deben ser procesados de nuevo.

TCL_WRITEОВJ

Escribe el contenido del objeto Tcl al que apunta writeObjPtr en el channel. El número de bytes escritos se devuelve como un entero. Si se produce un error de escritura, se devuelve -1 y el resultado del intérprete se establece para describir el error.

Este procedimiento está destinado a la escritura de datos en modo texto.

TCL_WRITECHARS

Escribe hasta bytesToWrite caracteres del búfer charBuf en el channel. El número de bytes escritos se devuelve como un entero. Si se produce un error de escritura, se devuelve -1 y el resultado del intérprete se establece para describir el error.

Si el canal está abierto en modo binario, bytesToWrite realmente se interpreta como el número de bytes a escribir.

TCL_WRITE

Escribe hasta bytesToWrite bytes del búfer byteBuf en el channel. El número de bytes escritos se devuelve como un entero. Si se produce un error de escritura, se devuelve -1 y el resultado del intérprete se establece para describir el error.

Este procedimiento está destinado a la escritura de datos en modo binario; para escribir datos en modo texto, utilice Tcl_WriteObj o Tcl_WriteChars.

TCL_READRAW

Lee exactamente bytesToRead bytes del channel y los almacena en el búfer readBuf. Si no se pueden leer tantos bytes (por ejemplo, al llegar al final del archivo o porque la operación de lectura se bloquea), el procedimiento devolverá el número de bytes que realmente se leyeron. Si se produce un error de lectura, se devuelve -1 y el resultado del intérprete se establece para describir el error. Este procedimiento ignora las conversiones de codificación o de fin de línea.

Este procedimiento está pensado para la lectura de datos en modo binario o para la lectura de metadatos sin procesar de un canal.

TCL_WRITERAW

Escribe exactamente bytesToWrite bytes del búfer byteBuf en el channel. Si no se pueden escribir tantos bytes (por ejemplo, porque el búfer de salida del sistema operativo está lleno o la operación de escritura se bloquea), el procedimiento devolverá el número de bytes que realmente se escribieron. Si se produce un error de escritura, se devuelve -1 y el resultado del intérprete se establece para describir el error. Este procedimiento ignora las conversiones de codificación o de fin de línea.

Este procedimiento está pensado para la escritura de datos en modo binario o para la escritura de metadatos sin procesar en un canal.

TCL_EOF

Devuelve 1 si se ha alcanzado el final del archivo en el channel para la lectura, y 0 en caso contrario. Esto solo tiene sentido si el canal está abierto para lectura.

TCL_FLUSH

Fuerza la escritura de cualquier dato en búfer en el channel. Esto es útil para asegurarse de que los datos se envían a un dispositivo o a otro proceso inmediatamente. Si la operación de vaciado se realiza correctamente, se devuelve 0; de lo contrario, se devuelve -1 y interp->result se establece para describir el error.

TCL_INPUTBLOCKED

Devuelve 1 si el canal channel está actualmente en modo no bloqueante y la próxima operación de lectura se bloquearía, y 0 en caso contrario. Esto solo tiene sentido si el canal está abierto para lectura.

TCL_INPUTBUFFERED

Devuelve el número de bytes que están actualmente en el búfer de entrada para el channel. Esto solo tiene sentido si el canal está abierto para lectura.

TCL_OUTPUTBUFFERED

Devuelve el número de bytes que están actualmente en el búfer de salida para el channel. Esto solo tiene sentido si el canal está abierto para escritura.

TCL_SEEK

Cambia la posición actual de acceso del channel. El argumento offset especifica cuánto mover la posición, y seekMode indica si el desplazamiento es relativo al principio del archivo (SEEK_SET), a la posición actual (SEEK_CUR) o al final del archivo (SEEK_END). El nuevo valor de la posición de acceso (en bytes desde el principio del archivo) se devuelve como un Tcl_WideInt. Si se produce un error, se devuelve -1 y el resultado del intérprete se establece para describir el error.

Este procedimiento solo es aplicable a canales que soportan la posición de acceso, como los archivos regulares.

TCL_TELL

Devuelve la posición actual de acceso del channel (en bytes desde el principio del archivo) como un Tcl_WideInt. Si el canal no soporta la posición de acceso, se devuelve -1 y el resultado del intérprete se establece para describir el error.

TCL_TRUNCATECHANNEL

Trunca el channel a la longitud especificada por length. Si la longitud es menor que la longitud actual del canal, se descartan los datos posteriores a esa posición. Si la longitud es mayor, el canal se extiende y se rellena con bytes nulos (dependiendo del sistema operativo). Si la operación se realiza correctamente, se devuelve 0; de lo contrario, se devuelve -1 y el resultado del intérprete se establece para describir el error.

Este procedimiento solo es aplicable a canales que soportan el truncamiento, como los archivos regulares.

TCL_GETCHANNELOPTION

Devuelve el valor de la opción especificada por optionName para el channel dado. El valor se almacena en el Tcl_DString al que apunta optionValue. Si la opción no existe o se produce un error, se devuelve -1 y el resultado del intérprete se establece para describir el error. Si la opción se recupera correctamente, se devuelve 0. Si optionName es NULL, se devolverá una lista de todas las opciones disponibles y sus valores actuales.

Los nombres de las opciones son los mismos que los utilizados por el comando Tcl fconfigure (por ejemplo, -blocking, -buffering, -encoding, -eof, -translation).

TCL_SETCHANNELOPTION

Establece el valor de la opción especificada por optionName para el channel dado al valor dado por newValue. Si la opción se establece correctamente, se devuelve 0; de lo contrario, se devuelve -1 y el resultado del intérprete se establece para describir el error.

Los nombres de las opciones son los mismos que los utilizados por el comando Tcl fconfigure.

UTILIDADES ADICIONALES

Los siguientes procedimientos son utilidades adicionales para trabajar con canales:

Tcl_InputBlocked
Devuelve 1 si el canal está en modo no bloqueante y la operación de lectura actual se bloquearía, 0 en caso contrario. Útil para determinar si se debe esperar a que haya más datos disponibles antes de intentar leer.
Tcl_InputBuffered
Devuelve el número de bytes que hay actualmente en el búfer de entrada del canal. Útil para saber cuántos datos se pueden leer sin realizar una llamada al sistema.
Tcl_OutputBuffered
Devuelve el número de bytes que hay actualmente en el búfer de salida del canal. Útil para saber cuántos datos aún no se han escrito en el dispositivo subyacente.

TCL_OPENFILECHANNEL

Tcl_OpenFileChannel abre un archivo especificado por fileName y devuelve un manejador de canal que se puede utilizar para realizar operaciones de entrada y salida en el archivo. Esta API está modelada después del procedimiento fopen de la biblioteca estándar de E/S de Unix. La sintaxis y el significado de todos los argumentos son similares a los dados en el comando open de Tcl al abrir un archivo. Si ocurre un error al abrir el canal, Tcl_OpenFileChannel devuelve NULL y registra un código de error POSIX que se puede recuperar con Tcl_GetErrno. Además, si interp no es NULL, Tcl_OpenFileChannel deja un mensaje de error en el resultado de interp después de cualquier error. A partir de Tcl 8.4, la API basada en valores Tcl_FSOpenFileChannel debe usarse preferentemente a Tcl_OpenFileChannel siempre que sea posible.

El canal recién creado no se registra en el intérprete proporcionado; para registrarlo, use Tcl_RegisterChannel, descrito a continuación. Si uno de los canales estándar, stdin, stdout o stderr se cerró previamente, el acto de crear el nuevo canal también lo asigna como reemplazo del canal estándar.

TCL_OPENCOMMANDCHANNEL

Tcl_OpenCommandChannel proporciona una interfaz de nivel C a las funciones de los comandos exec y open. Crea una secuencia de subprocesos especificados por los argumentos argv y argc y devuelve un canal que se puede utilizar para comunicarse con estos subprocesos. El argumento flags indica qué tipo de comunicación existirá con la tubería del comando.

Si se establece la bandera TCL_STDIN, la entrada estándar del primer subproceso se vinculará al canal: escribir en el canal proporcionará entrada al subproceso. Si TCL_STDIN no está establecido, la entrada estándar del primer subproceso será la misma que la entrada estándar de esta aplicación. Si se establece TCL_STDOUT, la salida estándar del último subproceso se puede leer del canal; de lo contrario, va a la salida estándar de esta aplicación. Si se establece TCL_STDERR, la salida de error estándar de todos los subprocesos se devuelve al canal y da como resultado un error al cerrar el canal; de lo contrario, va al error estándar de esta aplicación. Si TCL_ENFORCE_MODE no está establecido, entonces argc y argv pueden redirigir los manejadores de stdio para anular TCL_STDIN, TCL_STDOUT y TCL_STDERR; si está establecido, entonces es un error que argc y argv anulen los canales de stdio para los cuales se han establecido TCL_STDIN, TCL_STDOUT y TCL_STDERR.

Si ocurre un error al abrir el canal, Tcl_OpenCommandChannel devuelve NULL y registra un código de error POSIX que se puede recuperar con Tcl_GetErrno. Además, Tcl_OpenCommandChannel deja un mensaje de error en el resultado del intérprete. interp no puede ser NULL.

El canal recién creado no se registra en el intérprete proporcionado; para registrarlo, use Tcl_RegisterChannel, descrito a continuación. Si uno de los canales estándar, stdin, stdout o stderr se cerró previamente, el acto de crear el nuevo canal también lo asigna como reemplazo del canal estándar.

TCL_MAKEFILECHANNEL

Tcl_MakeFileChannel crea un Tcl_Channel a partir de un manejador de archivo existente y específico de la plataforma. El canal recién creado no se registra en el intérprete proporcionado; para registrarlo, use Tcl_RegisterChannel, descrito a continuación. Si uno de los canales estándar, stdin, stdout o stderr se cerró previamente, el acto de crear el nuevo canal también lo asigna como reemplazo del canal estándar.

TCL_GETCHANNEL

Tcl_GetChannel devuelve un canal dado el channelName utilizado para crearlo con Tcl_CreateChannel y un puntero a un intérprete de Tcl en interp. Si un canal con ese nombre no está registrado en ese intérprete, el procedimiento devuelve NULL. Si el argumento modePtr no es NULL, apunta a una variable entera que recibirá una combinación OR de TCL_READABLE y TCL_WRITABLE que describe si el canal está abierto para lectura y escritura.

Tcl_GetChannelNames y Tcl_GetChannelNamesEx escriben los nombres de los canales registrados en el resultado del intérprete como un valor de lista. Tcl_GetChannelNamesEx filtrará estos nombres de acuerdo con el pattern. Si pattern es NULL, entonces no realizará ningún filtrado. El valor de retorno es TCL_OK si no ocurrieron errores al escribir en el resultado, de lo contrario es TCL_ERROR, y el mensaje de error se deja en el resultado del intérprete.

TCL_REGISTERCHANNEL

Tcl_RegisterChannel agrega un canal al conjunto de canales accesibles en interp. Después de esta llamada, los programas Tcl que se ejecutan en ese intérprete pueden referirse al canal en operaciones de entrada o salida utilizando el nombre dado en la llamada a Tcl_CreateChannel. Después de esta llamada, el canal se convierte en propiedad del intérprete, y el llamador no debe llamar a Tcl_Close para el canal; el canal se cerrará automáticamente cuando se desregistre del intérprete.

El código que se ejecuta fuera de cualquier intérprete Tcl puede llamar a Tcl_RegisterChannel con interp como NULL, para indicar que desea mantener una referencia a este canal. Posteriormente, el canal se puede registrar en un intérprete Tcl y solo se cerrará cuando el número correspondiente de llamadas a Tcl_UnregisterChannel se hayan realizado. Esto permite que el código que se ejecuta fuera de cualquier intérprete mantenga de forma segura una referencia a un canal que también está registrado en un intérprete Tcl.

Este procedimiento interactúa con el código que gestiona los canales estándar. Si no se inicializaron canales estándar antes de la primera llamada a Tcl_RegisterChannel, se inicializarán con esa llamada. Consulte Tcl_StandardChannels para obtener un tratado general sobre los canales estándar y el comportamiento de la biblioteca Tcl con respecto a ellos.

TCL_UNREGISTERCHANNEL

Tcl_UnregisterChannel elimina un canal del conjunto de canales accesibles en interp. Después de esta llamada, los programas Tcl ya no podrán utilizar el nombre del canal para referirse al canal en ese intérprete. Si esta operación eliminó el último registro del canal en cualquier intérprete, el canal también se cierra y se destruye.

El código no asociado con un intérprete Tcl puede llamar a Tcl_UnregisterChannel con interp como NULL, para indicar a Tcl que ya no tiene una referencia a ese canal. Si esta es la última referencia al canal, ahora se cerrará. Tcl_UnregisterChannel es muy similar a Tcl_DetachChannel excepto que también cerrará el canal si no existen más referencias a él.

TCL_DETACHCHANNEL

Tcl_DetachChannel elimina un canal del conjunto de canales accesibles en interp. Después de esta llamada, los programas Tcl ya no podrán utilizar el nombre del canal para referirse al canal en ese intérprete. Más allá de eso, este comando no tiene ningún otro efecto. No se puede usar en los canales estándar (stdout, stderr, stdin) y devolverá TCL_ERROR si se le pasa uno de esos canales.

El código no asociado con un intérprete Tcl puede llamar a Tcl_DetachChannel con interp como NULL, para indicar a Tcl que ya no tiene una referencia a ese canal. Si esta es la última referencia al canal, a diferencia de Tcl_UnregisterChannel, no se cerrará.

TCL_ISSTANDARDCHANNEL

Tcl_IsStandardChannel comprueba si un canal es uno de los tres canales estándar, stdin, stdout o stderr. Si es así, devuelve 1, de lo contrario 0.

No se intenta comprobar si el canal dado o los canales estándar están inicializados o son válidos de otro modo.

TCL_CLOSE

Tcl_Close destruye el canal channel, que debe denotar un canal actualmente abierto. El canal no debe estar registrado en ningún intérprete cuando se llama a Tcl_Close. La salida en búfer se vacía en el dispositivo de salida del canal antes de destruir el canal, y cualquier entrada en búfer se descarta. Si se trata de un canal de bloqueo, la llamada no se devuelve hasta que todos los datos en búfer se envían correctamente al dispositivo de salida del canal. Si se trata de un canal sin bloqueo y hay salida en búfer que no se puede escribir sin bloquear, la llamada devuelve inmediatamente; la salida se vacía en segundo plano y el canal se cerrará una vez que todos los datos en búfer se hayan enviado. En este caso, los errores durante el vaciado no se informan.

Si el canal se cerró correctamente, Tcl_Close devuelve TCL_OK. Si ocurre un error, Tcl_Close devuelve TCL_ERROR y registra un código de error POSIX que se puede recuperar con Tcl_GetErrno. Si el canal se está cerrando de forma síncrona y ocurre un error durante el cierre del canal y interp no es NULL, se deja un mensaje de error en el resultado del intérprete.

Nota: no es seguro llamar a Tcl_Close en un canal que ha sido registrado usando Tcl_RegisterChannel; consulte la documentación para Tcl_RegisterChannel, arriba, para obtener más detalles. Si el canal se ha pasado alguna vez como argumento chan en una llamada a Tcl_RegisterChannel, debe usar en su lugar Tcl_UnregisterChannel, que llamará internamente a Tcl_Close cuando todas las llamadas a Tcl_RegisterChannel se hayan correspondido con llamadas a Tcl_UnregisterChannel.

TCL_READCHARS AND TCL_READ

Tcl_ReadChars consume bytes del channel, convirtiendo los bytes a UTF-8 basándose en la codificación del canal y almacenando los datos producidos en la representación de cadena de readObjPtr. El valor de retorno de Tcl_ReadChars es el número de caracteres, hasta charsToRead, que se almacenaron en readObjPtr. Si ocurre un error al leer, el valor de retorno es -1 y Tcl_ReadChars registra un código de error POSIX que se puede recuperar con Tcl_GetErrno.

TCL_READCHARS, TCL_READOBJ, TCL_READ, AND TCL_READRAW

Tcl_ReadChars consume up to charsToRead bytes from channel and store them in readObjPtr's internal representation. The bytes are converted to UTF-8 according to the channel's current encoding. If the channel's encoding is binary, each byte read from the channel is treated as an individual Unicode character. Setting charsToRead to -1 will cause the command to read all characters currently available (non-blocking) or everything until eof (blocking mode).

The return value may be smaller than the value to read, indicating that less data than requested was available. This is called a short read. In blocking mode, this can only happen on an end-of-file. In nonblocking mode, a short read can also occur if there is not enough input currently available: Tcl_ReadChars returns a short count rather than waiting for more data.

If the channel is in blocking mode, a return value of zero indicates an end-of-file condition. If the channel is in nonblocking mode, a return value of zero indicates either that no input is currently available or an end-of-file condition. Use Tcl_Eof and Tcl_InputBlocked to tell which of these conditions actually occurred.

Tcl_ReadChars translates the various end-of-line representations into the canonical \n internal representation according to the current end-of-line recognition mode. End-of-line recognition and the various platform-specific modes are described in the manual entry for the Tcl fconfigure command.

As a performance optimization, when reading from a channel with the encoding binary, the bytes are not converted to UTF-8 as they are read. Instead, they are stored in readObjPtr's internal representation as a byte-array value. The string representation of this value will only be constructed if it is needed (e.g., because of a call to Tcl_GetStringFromObj). In this way, byte-oriented data can be read from a channel, manipulated by calling Tcl_GetByteArrayFromObj and related functions, and then written to a channel without the expense of ever converting to or from UTF-8.

Tcl_Read is similar to Tcl_ReadChars, except that it does not do encoding conversions, regardless of the channel's encoding. It is deprecated and exists for backwards compatibility with non-internationalized Tcl extensions. It consumes bytes from channel and stores them in readBuf, performing end-of-line translations on the way. The return value of Tcl_Read is the number of bytes, up to bytesToRead, written in readBuf. The buffer produced by Tcl_Read is not null-terminated. Its contents are valid from the zeroth position up to and excluding the position indicated by the return value.

Tcl_ReadRaw is the same as Tcl_Read but does not compensate for stacking. While Tcl_Read (and the other functions in the API) always get their data from the topmost channel in the stack the supplied channel is part of, Tcl_ReadRaw does not. Thus this function is only usable for transformational channel drivers, i.e. drivers used in the middle of a stack of channels, to move data from the channel below into the transformation.

TCL_GETSOBJ AND TCL_GETS

Tcl_GetsObj consumes bytes from channel, converting the bytes to UTF-8 based on the channel's encoding, until a full line of input has been seen. If the channel's encoding is binary, each byte read from the channel is treated as an individual Unicode character. All of the characters of the line except for the terminating end-of-line character(s) are appended to lineObjPtr's string representation. The end-of-line character(s) are read and discarded.

If a line was successfully read, the return value is greater than or equal to zero and indicates the number of bytes stored in lineObjPtr. If an error occurs, Tcl_GetsObj returns -1 and records a POSIX error code that can be retrieved with Tcl_GetErrno. Tcl_GetsObj also returns -1 if the end of the file is reached; the Tcl_Eof procedure can be used to distinguish an error from an end-of-file condition.

If the channel is in nonblocking mode, the return value can also be -1 if no data was available or the data that was available did not contain an end-of-line character. When -1 is returned, the Tcl_InputBlocked procedure may be invoked to determine if the channel is blocked because of input unavailability.

Tcl_Gets is the same as Tcl_GetsObj except the resulting characters are appended to the dynamic string given by lineRead rather than a Tcl value.

TCL_UNGETS

Tcl_Ungets is used to add data to the input queue of a channel, at either the head or tail of the queue. The pointer input points to the data that is to be added. The length of the input to add is given by inputLen. A non-zero value of addAtEnd indicates that the data is to be added at the end of queue; otherwise it will be added at the head of the queue. If channel has a “sticky” EOF set, no data will be added to the input queue. Tcl_Ungets returns inputLen or -1 if an error occurs.

TCL_WRITECHARS, TCL_WRITEOBJ, AND TCL_WRITE

Tcl_WriteChars accepts bytesToWrite bytes of character data at charBuf. The UTF-8 characters in the buffer are converted to the channel's encoding and queued for output to channel. If bytesToWrite is negative, Tcl_WriteChars expects charBuf to be null-terminated and it outputs everything up to the null.

Data queued for output may not appear on the output device immediately, due to internal buffering. If the data should appear immediately, call Tcl_Flush after the call to Tcl_WriteChars, or set the -buffering option on the channel to none. If you wish the data to appear as soon as a complete line is accepted for output, set the -buffering option on the channel to line mode.

The return value of Tcl_WriteChars is a count of how many bytes were accepted for output to the channel. This is either greater than zero to indicate success or -1 to indicate that an error occurred. If an error occurs, Tcl_WriteChars records a POSIX error code that may be retrieved with Tcl_GetErrno.

Newline characters in the output data are translated to platform-specific end-of-line sequences according to the -translation option for the channel. This is done even if the channel has no encoding.

Tcl_WriteObj is similar to Tcl_WriteChars except it accepts a Tcl value whose contents will be output to the channel. The UTF-8 characters in writeObjPtr's string representation are converted to the channel's encoding and queued for output to channel. As a performance optimization, when writing to a channel with the encoding binary, UTF-8 characters are not converted as they are written. Instead, the bytes in writeObjPtr's internal representation as a byte-array value are written to the channel. The byte-array representation of the value will be constructed if it is needed. In this way, byte-oriented data can be read from a channel, manipulated by calling Tcl_GetByteArrayFromObj and related functions, and then written to a channel without the expense of ever converting to or from UTF-8.

Tcl_Write is similar to Tcl_WriteChars except that it does not do encoding conversions, regardless of the channel's encoding. It is deprecated and exists for backwards compatibility with non-internationalized Tcl extensions. It accepts bytesToWrite bytes of data at byteBuf and queues them for output to channel. If bytesToWrite is negative, Tcl_Write expects byteBuf to be null-terminated and it outputs everything up to the null.

Tcl_WriteRaw is the same as Tcl_Write but does not compensate for stacking. While Tcl_Write (and the other functions in the API) always feed their input to the topmost channel in the stack the supplied channel is part of, Tcl_WriteRaw does not. Thus this function is only usable for transformational channel drivers, i.e. drivers used in the middle of a stack of channels, to move data from the transformation into the channel below it.

TCL_FLUSH

Tcl_Flush causes all of the buffered output data for channel to be written to its underlying file or device as soon as possible. If the channel is in blocking mode, the call does not return until all the buffered data has been sent to the channel or some error occurred. The call returns immediately if the channel is nonblocking; it starts a background flush that will write the buffered data to the channel eventually, as fast as the channel is able to absorb it.

The return value is normally TCL_OK. If an error occurs, Tcl_Flush returns TCL_ERROR and records a POSIX error code that can be retrieved with Tcl_GetErrno.

TCL_SEEK

Tcl_Seek moves the access point in channel where subsequent data will be read or written. Buffered output is flushed to the channel and buffered input is discarded, prior to the seek operation.

Tcl_Seek normally returns the new access point. If an error occurs, Tcl_Seek returns -1 and records a POSIX error code that can be retrieved with Tcl_GetErrno. After an error, the access point may or may not have been moved.

TCL_TELL

Tcl_Tell returns the current access point for a channel. The returned value is -1 if the channel does not support seeking.

TCL_TRUNCATECHANNEL

Tcl_TruncateChannel truncates the file underlying channel to a given length of bytes. It returns TCL_OK if the operation succeeded, and TCL_ERROR otherwise.

TCL_GETCHANNELOPTION

Tcl_GetChannelOption retrieves, in optionValue, the value of one of the options currently in effect for a channel, or a list of all options and their values. The channel argument identifies the channel for which to query an option or retrieve all options and their values. If optionName is not NULL, it is the name of the option to query; the option's value is copied to the Tcl dynamic string denoted by optionValue. If optionName is NULL, the function stores an alternating list of option names and their values in optionValue.

, utilizando una serie de llamadas a Tcl_DStringAppendElement. Las diversas opciones preexistentes y sus posibles valores se describen en la entrada del manual para el comando fconfigure de Tcl. Otras opciones pueden ser añadidas por cada tipo de canal. Estas opciones específicas del tipo de canal se describen en la entrada del manual del comando Tcl que crea un canal de ese tipo; por ejemplo, las opciones adicionales para canales basados en TCP se describen en la entrada del manual para el comando socket de Tcl. El procedimiento normalmente devuelve TCL_OK. Si ocurre un error, devuelve TCL_ERROR y llama a Tcl_SetErrno para almacenar un código de error POSIX apropiado.

TCL_SETCHANNELOPTION

Tcl_SetChannelOption establece un nuevo valor newValue para una opción optionName en el channel. El procedimiento normalmente devuelve TCL_OK. Si ocurre un error, devuelve TCL_ERROR; además, si interp no es NULL, Tcl_SetChannelOption deja un mensaje de error en el resultado del intérprete.

TCL_EOF

Tcl_Eof devuelve un valor distinto de cero si el channel encontró un fin de archivo durante la última operación de entrada.

TCL_INPUTBLOCKED

Tcl_InputBlocked devuelve un valor distinto de cero si el channel está en modo no bloqueante y la última operación de entrada devolvió menos datos de los solicitados porque había datos insuficientes disponibles. La llamada siempre devuelve cero si el canal está en modo bloqueante.

TCL_INPUTBUFFERED

Tcl_InputBuffered devuelve el número de bytes de entrada actualmente almacenados en búfer en los búferes internos de un canal. Si el canal no está abierto para lectura, esta función siempre devuelve cero.

TCL_OUTPUTBUFFERED

Tcl_OutputBuffered devuelve el número de bytes de salida actualmente almacenados en búfer en los búferes internos de un canal. Si el canal no está abierto para escritura, esta función siempre devuelve cero.

PLATFORM ISSUES

Los identificadores devueltos por Tcl_GetChannelHandle dependen de la plataforma y del tipo de canal. En plataformas Unix, el identificador es siempre un descriptor de archivo de Unix tal como lo devuelve la llamada al sistema open. En plataformas Windows, el identificador es un HANDLE de archivo cuando el canal se creó con Tcl_OpenFileChannel, Tcl_OpenCommandChannel o Tcl_MakeFileChannel. Otros tipos de canales pueden devolver un tipo diferente de identificador en plataformas Windows.
