ARGUMENTOS

Tcl_Interp *interp (in)
The interpreter to which compressed or uncompressed data is stored. It is also where error messages are written. For Tcl_ZlibStreamInit, this may be NULL to create a stream not bound to a command.
int format (in)
Which format of compressed data to work with. Must be one of the following: TCL_ZLIB_FORMAT_ZLIB for zlib compressed data, TCL_ZLIB_FORMAT_GZIP for gzip compressed data, or TCL_ZLIB_FORMAT_RAW for raw compressed data. Additionally, for compression only, TCL_ZLIB_FORMAT_AUTO may be selected, which can automatically detect whether compressed data was in zlib or gzip format.
Tcl_Obj *dataObj (in/out)
A byte-array value containing the data to be compressed or decompressed, or which is appended to with the data extracted from the stream when passed to Tcl_ZlibStreamGet.
int level (in)
Which compression level to use. Must be a number from 0 to 9 or one of the following: TCL_ZLIB_COMPRESS_NONE for no compression, TCL_ZLIB_COMPRESS_FAST for fast but inefficient compression, TCL_ZLIB_COMPRESS_BEST for slow but maximum compression, or TCL_ZLIB_COMPRESS_DEFAULT for the level recommended by the zlib library.
Tcl_Obj *dictObj (in/out)
A dictionary containing, or to be updated to contain, a description of the gzip header associated with compressed data. This is only useful when the format argument is TCL_ZLIB_FORMAT_GZIP or TCL_ZLIB_FORMAT_AUTO. If a NULL is passed, a default header will be used on compression and the header will be ignored (unless integrity checks are performed) on decompression. For more details about the contents of this dictionary, see the GZIP OPTIONS DICTIONARY section.
unsigned int initValue (in)
Initial value for the checksum verification algorithm.
int bufferSize (in)
What is the approximate size of the buffer to use for receiving data. Use 0 to use an estimate based on input data.
unsigned char *bytes (in)
A byte array to run the checksum verification algorithm on, or NULL to obtain the recommended initial value for the checksum verification algorithm.
int length (in)
The number of bytes in the array.
int mode (in)
Which mode to operate the stream in. Must be one of the following: TCL_ZLIB_STREAM_DEFLATE for a compression stream or TCL_ZLIB_STREAM_INFLATE for a decompression stream.
Tcl_ZlibStream *zshandlePtr (out)
A pointer to a variable in which the abstract token for the stream will be written after its creation.
Tcl_ZlibStream zshandle (in)
The abstract token for the stream to operate on.
int flush (in)
And how should it be flushed after writing data into it. Must be one of the following: TCL_ZLIB_NO_FLUSH if no flush should be performed, TCL_ZLIB_FLUSH if the current compressed data should be accessible via Tcl_ZlibStreamGet, TCL_ZLIB_FULLFLUSH if the stream should be in a state from which the decompressor can recover from corruption, or TCL_ZLIB_FINALIZE to ensure the stream is finished and that any trailer required by the format is written.
int count (in)
The maximum number of bytes to obtain from the stream, or -1 to obtain all remaining bytes from the stream's buffers.
Tcl_Obj *compDict (in)
A byte-array value which will be used as the compression dictionary for the stream. Note that this is not a Tcl dictionary and is recommended for use only with streams that were created with their format set to TCL_ZLIB_FORMAT_ZLIB, as the other formats have no mechanism for indicating whether a compression dictionary was present except by failing decompression.

DESCRIPCIÓN

These routines form the interface from the Tcl library to the Zlib library by Jean-loup Gailly and Mark Adler.

Tcl_ZlibDeflate and Tcl_ZlibInflate respectively compress and decompress the data contained in the dataObj argument, according to the format argument and, for compression, level. The dictionary in the dictObj argument is used to transmit additional information about the compressed data when the compression format supports it; currently, the dictionary is only used when the format argument is TCL_ZLIB_FORMAT_GZIP or TCL_ZLIB_FORMAT_AUTO. For more details about the dictionary's contents, see the GZIP OPTIONS DICTIONARY section. Upon success, both routines will leave the compressed or decompressed data in a byte-array value that is the result of the Tcl interpreter; the return value is a standard Tcl result code.

Tcl_ZlibAdler32 and Tcl_ZlibCRC32 compute checksums on byte arrays, returning the computed checksum. The checksums are computed incrementally, allowing data to be processed one block at a time, but this requires that the caller maintain the current checksum value and pass it as the initValue parameter; the initial value for this may be obtained by using NULL for the bytes parameter instead of a pointer to a byte array to compute the checksum. Thus, the typical use in the case of a single data block is thus:

checksum = Tcl_ZlibCRC32(Tcl_ZlibCRC32(0,NULL,0), data, length);

Note: The Adler-32 algorithm is not a true checksum, but rather a related form of hash which works better on long data.

ZLIB STREAMS

Tcl_ZlibStreamInit creates a compression or decompression stream bound to a Tcl command, according to its arguments, and provides an abstract token for the stream, returning a standard Tcl result code; Tcl_ZlibStreamGetCommandName returns the name of the command given the stream token, or NULL if the stream does not have a command. Streams are not designed to be thread safe; each stream should only be used from the thread that created it. When working with gzip streams, a dictionary (as described in the GZIP OPTIONS DICTIONARY section) can be supplied via the dictObj parameter, allowing control over the headers generated on compression and discovery of existing headers on decompression. Note that the dictionary will be written to in the case of decompression once enough data has been read to have a complete header. This means that the dictionary must be an unshared value in that case; an empty value created with Tcl_NewObj is suggested.

Once a stream has been constructed, Tcl_ZlibStreamPut is used to feed data into the stream and Tcl_ZlibStreamGet is used to obtain data from the stream after processing. Both return standard Tcl result codes and leave an error message in the result of the interpreter that the stream is registered with in the case of an error (if such registration has been performed). With Tcl_ZlibStreamPut, the data buffer passed to it must not be modified afterwards. With Tcl_ZlibStreamGet, the data buffer passed to it will have bytes of data appended to it. Internally to the stream, data is kept compressed to minimize buffer space cost.

Tcl_ZlibStreamGet

dictObj

Tcl_ZlibStreamGet devuelve un valor booleano que indica si se ha alcanzado el final de los datos descomprimidos.

El parámetro dictObj de Tcl_ZlibDeflate, Tcl_ZlibInflate y Tcl_ZlibStreamInit se utiliza para pasar un diccionario de opciones que describe la cabecera gzip en los datos comprimidos. Al crear los datos comprimidos, el diccionario se lee y al descomprimir, se escribe (en este caso, dictObj debe referirse a un valor de diccionario no compartido).

Los siguientes campos del valor del diccionario se entienden. Todos los demás campos se ignoran. No se requiere ningún campo al crear un flujo de formato gzip.

comment
Esto almacena el campo de comentario de la cabecera, si está presente. Si no está presente, no se proporcionó ningún comentario (en descompresión) o se creará (en compresión).
crc
Un valor booleano que indica si se calcula un CRC de la cabecera. Nota: el programa gzip no utiliza ni permite un CRC en la cabecera.
filename
El nombre del archivo que contenía los datos sin comprimir. Debe evitar cualquier separador de directorio y debe ser saneado antes de su uso en descompresión con file tail.
os
El código de tipo de sistema operativo de la cabecera (si no es el valor desconocido). Ver RFC 1952 para el significado de estos códigos. En compresión, si no está presente, el campo se establecerá en el valor desconocido.
size
El tamaño de los datos sin comprimir. Este campo se ignora en compresión; el tamaño de los datos comprimidos depende del volumen de datos proporcionado al motor de compresión.
time
El campo de tiempo de la cabecera, si no es cero, que se espera que sea la fecha de modificación del archivo especificado por filename. Es adecuado para usar con clock format. En la creación, el valor correcto a usar es el de clock seconds o file mtime.
type
El tipo de los datos sin comprimir (binario o texto) si se conoce.

Estas funciones se comportarán correctamente si Tcl no está enlazado con la biblioteca zlib.
