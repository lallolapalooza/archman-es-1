Tcl_CreateCommand(3)

Paquete: tcl

Licencias: TCL

Tcl_CreateCommand(3) Procedimientos de la biblioteca Tcl Tcl_CreateCommand(3)

NOMBRE

Tcl_CreateCommand - implementar nuevos comandos en C

SINOPSIS

#include <tcl.h>

Tcl_Command
Tcl_CreateCommand(interp, cmdName, proc, clientData, deleteProc)

ARGUMENTOS

Tcl_Interp *interp (entrada)
Intérprete en el que crear el nuevo comando.
const char *cmdName (entrada)
Nombre del comando.
Tcl_CmdProc *proc (entrada)
Implementación del nuevo comando: se llamará a proc cada vez que se invoque cmdName como comando.
ClientData clientData (entrada)
Valor arbitrario de una palabra para pasar a proc y deleteProc.
Tcl_CmdDeleteProc *deleteProc (entrada)
Procedimiento a llamar antes de que se elimine cmdName del intérprete; permite la limpieza específica del comando. Si es NULL, no se llama a ningún procedimiento antes de que se elimine el comando.

DESCRIPCIÓN

Tcl_CreateCommand define un nuevo comando en interp y lo asocia con el procedimiento proc de tal manera que cada vez que se invoque cmdName como un comando Tcl (mediante una llamada a Tcl_Eval) el intérprete Tcl llamará a proc para procesar el comando. Se diferencia de Tcl_CreateObjCommand en que define un nuevo comando basado en cadenas; es decir, se define un procedimiento de comando que toma una matriz de cadenas de argumentos en lugar de valores. Los procedimientos de comando basados en valores registrados por Tcl_CreateObjCommand pueden ejecutarse significativamente más rápido que los procedimientos de comando basados en cadenas definidos por Tcl_CreateCommand. Esto se debe a que toman valores Tcl como argumentos y esos valores pueden conservar una representación interna que puede ser manipulada de manera más eficiente. Además, el intérprete de Tcl ahora usa valores internamente. Para invocar un procedimiento de comando basado en cadenas registrado por Tcl_CreateCommand, debe generar y obtener una representación de cadena de cada valor de argumento antes de la llamada. Los nuevos comandos deben definirse utilizando Tcl_CreateObjCommand. Admitimos Tcl_CreateCommand por compatibilidad con versiones anteriores.

Los procedimientos Tcl_DeleteCommand, Tcl_GetCommandInfo y Tcl_SetCommandInfo se utilizan junto con Tcl_CreateCommand.

Tcl_CreateCommand eliminará un comando existente cmdName, si ya está asociado con el intérprete. Devuelve un token que puede usarse para referirse al comando en llamadas posteriores a Tcl_GetCommandName. Si cmdName contiene algún calificador de espacio de nombres ::, entonces el comando se agrega al espacio de nombres especificado; de lo contrario, el comando se agrega al espacio de nombres global. Si se llama a Tcl_CreateCommand para un intérprete que está en proceso de ser eliminado, no crea un nuevo comando y devuelve NULL. Proc debe tener argumentos y un resultado que coincidan con el tipo Tcl_CmdProc:

typedef int Tcl_CmdProc(
        ClientData clientData,
        Tcl_Interp *interp,
        int argc,
        const char *argv[]);

Cuando se invoca proc, los parámetros clientData e interp serán copias de los argumentos clientData e interp dados a Tcl_CreateCommand. Típicamente, clientData apunta a una estructura de datos específica de la aplicación que describe qué hacer cuando se invoca el procedimiento del comando. Argc y argv describen los argumentos del comando, argc indica el número de argumentos (incluido el nombre del comando) y argv indica los valores de los argumentos como cadenas. La matriz argv contendrá argc+1 valores; los primeros argc valores apuntan a las cadenas de argumentos, y el último valor es NULL. Tenga en cuenta que las cadenas de argumentos no deben modificarse, ya que pueden apuntar a cadenas constantes o compartirse con otras partes del intérprete.

Tenga en cuenta que las cadenas de argumentos están codificadas en UTF-8 normalizado desde la versión 8.1 de Tcl.

Proc debe devolver un código entero que se espera que sea uno de TCL_OK, TCL_ERROR, TCL_RETURN, TCL_BREAK o TCL_CONTINUE. Consulte la página del manual de descripción general de Tcl para obtener detalles sobre el significado de estos códigos. La mayoría de los comandos normales solo devolverán TCL_OK o TCL_ERROR. Además, proc debe establecer el resultado del intérprete; en el caso de un código de retorno TCL_OK, este es el resultado del comando, y en el caso de TCL_ERROR, es un mensaje de error. El procedimiento Tcl_SetResult proporciona una interfaz fácil para establecer el valor de retorno; para obtener detalles completos sobre cómo se gestiona el campo de resultado del intérprete, consulte la página del manual de Tcl_Interp. Antes de invocar un procedimiento de comando, Tcl_Eval establece el resultado del intérprete para que apunte a una cadena vacía, por lo que los comandos simples pueden devolver un resultado vacío sin hacer nada más.

Los contenidos de la matriz argv pertenecen a Tcl y no se garantiza que persistan una vez que proc devuelve: proc no debe modificarlos, ni debe establecer el resultado del intérprete para que apunte a cualquier lugar dentro de los valores de argv. Llame a Tcl_SetResult con el estado TCL_VOLATILE si desea devolver algo de la matriz argv.

DeleteProc será invocado cuando (si) cmdName sea eliminado. Esto puede ocurrir a través de una llamada a Tcl_DeleteCommand o Tcl_DeleteInterp, o reemplazando cmdName en otra llamada a Tcl_CreateCommand. DeleteProc se invoca antes de que se elimine el comando y le da a la aplicación la oportunidad de liberar cualquier estructura asociada con el comando. DeleteProc debe tener argumentos y un resultado que coincidan con el tipo Tcl_CmdDeleteProc:

typedef void Tcl_CmdDeleteProc(
        ClientData clientData);

El argumento clientData será el mismo que el argumento clientData pasado a Tcl_CreateCommand.
