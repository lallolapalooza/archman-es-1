ARGUMENTOS

const char *bytes (entrada)
Punta al primer byte de un array de bytes codificados en UTF-8 utilizados para establecer o añadir a un valor de cadena. Este array de bytes puede contener caracteres nulos incrustados a menos que numChars sea negativo. (Las aplicaciones que necesiten bytes nulos deberían representarlos como la secuencia de dos bytes \300\200, usar Tcl_ExternalToUtf para convertir, o Tcl_NewByteArrayObj si la cadena es una colección de bytes no interpretados.)
int length (entrada)
El número de bytes a copiar de bytes al inicializar, establecer o añadir a un valor de cadena. Si es negativo, se utilizan todos los bytes hasta el primer nulo.
const Tcl_UniChar *unicode (entrada)
Punta al primer byte de un array de caracteres Unicode utilizados para establecer o añadir a un valor de cadena. Este array de bytes puede contener caracteres nulos incrustados a menos que numChars sea negativo.
int numChars (entrada)
El número de caracteres Unicode a copiar de unicode al inicializar, establecer o añadir a un valor de cadena. Si es negativo, se utilizan todos los caracteres hasta el primer carácter nulo.
int index (entrada)
El índice del carácter Unicode a devolver.
int first (entrada)
El índice del primer carácter Unicode en el rango Unicode a devolver como un nuevo valor.
int last (entrada)
El índice del último carácter Unicode en el rango Unicode a devolver como un nuevo valor.
Tcl_Obj *objPtr (entrada/salida)
Punta a un valor a manipular.
Tcl_Obj *appendObjPtr (entrada)
El valor a añadir a objPtr en Tcl_AppendObjToObj.
int *lengthPtr (salida)
Si no es NULL, la ubicación donde Tcl_GetStringFromObj almacenará la longitud de la representación de cadena del valor.
const char *string (entrada)
Valor de cadena terminado en nulo a añadir a objPtr.
va_list argList (entrada)
Una lista de argumentos que debe haber sido inicializada con va_start y limpiada con va_end.
int limit (entrada)
Número máximo de bytes a añadir.
const char *ellipsis (entrada)
Sufijo a añadir cuando el límite conduce a la truncación de la cadena. Si se pasa NULL, se usa el sufijo “...”.
const char *format (entrada)
Cadena de control de formato incluyendo especificadores de conversión %.
int objc (entrada)
El número de elementos a formatear o concatenar.
Tcl_Obj *objv[] (entrada)
El array de valores a formatear o concatenar.
int newLength (entrada)
Nueva longitud para el valor de cadena de objPtr, sin incluir el carácter nulo final.

DESCRIPCIÓN

Los procedimientos descritos en esta entrada del manual permiten manipular valores Tcl como valores de cadena. Utilizan la representación interna del valor para almacenar información adicional y hacer que las manipulaciones de cadena sean más eficientes. En particular, hacen que una serie de operaciones de adición sean eficientes al asignar espacio de almacenamiento adicional para la cadena, de modo que no tenga que ser copiada en cada adición. Además, la indexación y los cálculos de longitud se optimizan porque la representación de cadena Unicode se calcula y se almacena en caché según sea necesario. Al usar la familia de funciones Tcl_Append* donde el resultado del intérprete es el valor al que se está añadiendo, es importante llamar primero a Tcl_ResetResult para asegurar que no estás añadiendo inadvertidamente a datos existentes en el valor de resultado.

Tcl_NewStringObj y Tcl_SetStringObj crean un nuevo valor o modifican un valor existente para que contenga una copia de la cadena dada por bytes y length. Tcl_NewUnicodeObj y Tcl_SetUnicodeObj crean un nuevo valor o modifican un valor existente para que contenga una copia de la cadena Unicode dada por unicode y numChars. Tcl_NewStringObj y Tcl_NewUnicodeObj devuelven un puntero a un valor recién creado con un contador de referencias cero. Los cuatro procedimientos establecen el valor para que contenga una copia de la cadena especificada. Tcl_SetStringObj y Tcl_SetUnicodeObj liberan cualquier representación de cadena antigua, así como cualquier representación interna antigua del valor.

Tcl_GetStringFromObj y Tcl_GetString devuelven la representación de cadena de un valor. Esta se proporciona mediante el puntero devuelto y (para Tcl_GetStringFromObj) la longitud, que se almacena en lengthPtr si no es NULL. Si la representación de cadena UTF del valor es inválida (su puntero de bytes es NULL), la representación de cadena se regenera a partir de la representación interna del valor. El almacenamiento referenciado por el puntero devuelto es propiedad del gestor de valores. Se pasa como un puntero escribible para que el autor de extensiones que cree su propio Tcl_ObjType pueda modificar la representación de cadena dentro de Tcl_UpdateStringProc de su Tcl_ObjType. Excepto para ese propósito limitado, el puntero devuelto por Tcl_GetStringFromObj o Tcl_GetString debe tratarse como de solo lectura. Se recomienda asignar este puntero a una variable (const char *). Incluso en las situaciones limitadas donde escribir en este puntero es aceptable, se debe tener cuidado de respetar la semántica de copia en escritura requerida por Tcl_Obj, con llamadas apropiadas a Tcl_IsShared y Tcl_DuplicateObj antes de cualquier modificación en el lugar de la representación de cadena. El procedimiento Tcl_GetString se utiliza en el caso común en el que el llamador no necesita la longitud de la representación de cadena.

Tcl_GetUnicodeFromObj y Tcl_GetUnicode devuelven el valor como una cadena Unicode. Esto se proporciona mediante el puntero devuelto y (para Tcl_GetUnicodeFromObj) la longitud, que se almacena en lengthPtr si no es NULL. El almacenamiento referenciado por el puntero de bytes devuelto es propiedad del gestor de valores y el llamador no debe modificarlo. El procedimiento Tcl_GetUnicode se utiliza en el caso común en el que el llamador no necesita la longitud de la representación de cadena Unicode.

Tcl_GetUniChar devuelve el carácter en el índice index en la representación Unicode del valor. Se supone que el índice está en el rango apropiado.

Tcl_GetRange devuelve un nuevo valor creado compuesto por los caracteres entre first y last (inclusive) en la representación Unicode del valor. Si la representación Unicode del valor es inválida, la representación Unicode se regenera a partir de la representación de cadena del valor. Si first < 0, entonces la cadena devuelta comienza al principio del valor. Si last < 0, entonces la cadena devuelta termina al final del valor.

Tcl_Bytes devuelve el número de caracteres (en lugar de bytes) en el valor de la cadena.

Tcl_AppendToObj añade los datos dados por bytes y length a la representación de cadena del valor especificado por objPtr. Si el valor tiene una representación inválida de cadena, se intenta convertir bytes a formato Unicode. Si la conversión es exitosa, la representación Unicode del bytes convertido se añade a la representación de cadena del valor. En caso de no poder convertirlo, la representación Unicode del valor se invalida y se convierte a formato UTF, y bytes se añade a la nueva representación de cadena del valor. El crecimiento de búfer se realiza mediante allocations grandes para optimizar múltiples llamadas.

Tcl_AppendUnicodeToObj añade la cadena Unicode dada por unicode y numChars al valor especificado por objPtr. Si el valor tiene una representación inválida de Unicode, unicode se convierte a formato UTF y se añade a la representación de cadena del valor. Las apendices son optimizadas para manejar apendices repetidos de manera eficiente (sobrecargando el espacio de cadena o de Unicode para evitar realocaciones y copias repetidas de valor).

Tcl_AppendObjToObj es similar a Tcl_AppendToObj, pero añade el valor de appendObjPtr (la cadena o la representación Unicode, según sea más adecuada para ser añadida a objPtr) a objPtr.

Tcl_AppendStringsToObj es similar a Tcl_AppendToObj excepto que puede pasar más de un valor a añadir y cada valor debe ser una cadena terminada en nula (es decir, ninguno de los valores puede contener caracteres nulos internos). Se pueden proporcionar varios argumentos de tipo string, pero el último argumento debe ser (char *)NULL para indicar el final de la lista.

Tcl_AppendStringsToObjVA es el mismo que Tcl_AppendStringsToObj excepto que toma un argumento de lista en lugar de un número variable de argumentos.

Tcl_AppendLimitedToObj es similar a Tcl_AppendToObj excepto que imponen un límite en el número de bytes que se pueden añadir. Esto puede ser útil cuando la cadena a añadir sea muy larga, pero el valor a construir no debe permitir crecer sin límite. Una utilización común es cuando se construye un mensaje de error, donde el resultado final debe ser breve para ser leída. Los bytes de bytes se añaden a objPtr, pero no más de limit bytes. Si el límite impide añadir todos los length bytes disponibles, el añadido se realiza de manera que los últimos bytes añadidos provengan de la cadena ellipsis. Esto deja una indicación de truncación en la cadena. Cuando length es -1, se añaden todos los bytes hasta la primera cero, sujetos al límite. Cuando ellipsis es NULL, se usa por defecto la cadena .... Cuando ellipsis es no nulo, debe apuntar a una cadena terminada en cero en el formato UTF interno de Tcl. El número de bytes añadidos puede ser menor que el menor de length y limit cuando se añada menos bytes, pero se añada solo una parte completa de caracteres múltiples.

Tcl_Format es la interfaz C del motor del comando format. La procedura de comando real de format es poco más que 

Tcl_Format(interp, Tcl_GetString(objv[1]), objc-2, objv+2);

Los valores de objc de objv se formatean en una cadena según la especificación de conversión en el argumento format, siguiendo la documentación del comando format. La cadena resultante se convierte en un nuevo Tcl_Obj con contador de referencias cero y se devuelve. Si ocurre un error durante la producción de la cadena formateada, se devuelve NULL y un mensaje de error se registra en interp, si interp no es nulo.

Tcl_AppendFormatToObj es una forma alternativa de apendice de Tcl_Format con funcionalidad equivalente a: 

Tcl_Obj *newPtr = Tcl_Format(interp, format, objc, objv);
if (newPtr == NULL) return TCL_ERROR;
Tcl_AppendObjToObj(objPtr, newPtr);
Tcl_DecrRefCount(newPtr);
return TCL_OK;

pero con mayor comodidad y eficiencia cuando se necesita la funcionalidad de apendice.

Tcl_ObjPrintf sirve como reemplazo para la secuencia común 

char buf[SOME_SUITABLE_LENGTH];
sprintf(buf, format, ...);
Tcl_NewStringObj(buf, -1);

pero con mayor comodidad y sin necesidad de determinar SOME_SUITABLE_LENGTH. La formateación se realiza con el mismo motor de formateo básico utilizado por Tcl_Format. Esto significa que el conjunto de especificadores de conversión soportados es el mismo que el del comando format, pero el comportamiento es lo más similar posible a sprintf. Los especificadores de formato adicionados por C99 (como hh, ll, j, z, t, L) no son soportados. Si un especificador de formato se pasa a Tcl_ObjPrintf que incluya una precisión, el valor se toma como número de bytes, como sprintf hace, y no como número de caracteres, como format hace. Esto se realiza asumiendo que el código C es más probable que sepa cuántos bytes se está pasando que cuántos caracteres codificados esos bytes representan. Los argumentos variables que se pasan deben ser de los tipos que serían adecuados para pasar a sprintf. Nota en este ejemplo de uso, x es de tipo int. 

int x = 5;
Tcl_Obj *objPtr = Tcl_ObjPrintf("Value is %d", x);

Si el valor de format contiene inconsistencias internas o formatos de especificador inválidos, el resultado de la cadena formateada producida por Tcl_ObjPrintf será un mensaje de error describiendo la error. Sin embargo, es imposible proporcionar protección runtime contra malas coincidencias entre el formato y los argumentos posteriores. La protección compile-time puede proporcionarse mediante algunos compiladores.

Tcl_AppendPrintfToObj es una forma alternativa de apendice de Tcl_ObjPrintf con funcionalidad equivalente a 

Tcl_Obj *newPtr = Tcl_ObjPrintf(format, ...);
Tcl_AppendObjToObj(objPtr, newPtr);
Tcl_DecrRefCount(newPtr);

pero con mayor comodidad y eficiencia cuando se necesita la funcionalidad de apendice.

La función Tcl_SetObjLength cambia el largo de la valor de la cadena de su objPtr. Si el newLength es mayor que el espacio asignado para la cadena del valor, se realecata la espacio de cadena y el valor antiguo se copia al nuevo espacio; los bytes entre el largo antiguo de la cadena y el nuevo largo pueden tener valores arbitrarios. Si el newLength es menor que el largo actual de la cadena del valor, con objPtr->length se reduce sin re-allocar el espacio de la cadena; el tamaño original asignado para la cadena se registra en el valor, así que el largo de la cadena puede ser aumentado en una llamada posterior a Tcl_SetObjLength sin re-allocar el espacio de almacenamiento. En todos los casos Tcl_SetObjLength deja un carácter nulo en objPtr->bytes[newLength].

Tcl_AttemptSetObjLength tiene la misma función que Tcl_SetObjLength excepto que si no se puede asignar memoria suficiente para satisfacer la solicitud, no causa que el intérprete Tcl panic. Por lo tanto, si newLength es mayor que el espacio asignado para la cadena del valor, y no hay memoria suficiente para satisfacer la solicitud, Tcl_AttemptSetObjLength no hace nada y devuelve 0 para indicar el fracaso. Si hay memoria suficiente para satisfacer la solicitud, Tcl_AttemptSetObjLength se comporta como Tcl_SetObjLength y devuelve 1 para indicar el éxito.

La función Tcl_ConcatObj devuelve un valor de cadena nuevo cuyo valor es la concatenación separada por espacios de los representados de todas las entradas de objv. Tcl_ConcatObj elimina espacios de inicio y fin como copia de los representados de las entradas de objv a la salida. Si un elemento de objv consiste de solo espacios, ese valor es ignorado. Esta eliminación de espacios fue agregada para hacer el output del comando concat más limpio. Tcl_ConcatObj devuelve un puntero a un valor nuevo cuyo contador de referencias es cero.
