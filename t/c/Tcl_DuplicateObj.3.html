Tcl_Obj(3) Procedimientos de la biblioteca Tcl Tcl_Obj(3)

NOMBRE

Tcl_NewObj, Tcl_DuplicateObj, Tcl_IncrRefCount, Tcl_DecrRefCount, Tcl_IsShared, Tcl_InvalidateStringRep - manipular valores Tcl

SINOPSIS

#include <tcl.h>

Tcl_Obj *
Tcl_NewObj()

Tcl_Obj *
Tcl_DuplicateObj(objPtr)

Tcl_IncrRefCount(objPtr)

Tcl_DecrRefCount(objPtr)

int
Tcl_IsShared(objPtr)

Tcl_InvalidateStringRep(objPtr)

ARGUMENTOS

Tcl_Obj *objPtr (entrada)
Punta a un valor; debe haber sido el resultado de una llamada previa a Tcl_NewObj.

INTRODUCCION

Esta página del manual presenta una visión general de los valores Tcl (llamados Tcl_Obj por razones históricas) y cómo se utilizan. También describe procedimientos genéricos para la gestión de valores Tcl. Estos procedimientos se utilizan para crear y copiar valores, e incrementar y decrementar el contador de referencias (punteros) a valores. Los procedimientos se utilizan junto con los que operan sobre tipos específicos de valores, como Tcl_GetIntFromObj y Tcl_ListObjAppendElement. Los procedimientos individuales se describen junto con las estructuras de datos que manipulan.

Los valores dual-ported de Tcl proporcionan un mecanismo de propósito general para almacenar e intercambiar valores Tcl. Reemplazan en gran medida el uso de cadenas en Tcl. Por ejemplo, se utilizan para almacenar valores de variables, argumentos de comandos, resultados de comandos y scripts. Los valores Tcl se comportan como cadenas pero también mantienen una representación interna que se puede manipular de manera más eficiente. Por ejemplo, una lista Tcl ahora se representa como un valor que mantiene la representación de cadena de la lista, así como una matriz de punteros a los valores de cada elemento de la lista. Los valores dual-ported evitan la mayoría de las conversiones de tipo en tiempo de ejecución. También mejoran la velocidad de muchas operaciones, ya que una representación adecuada está disponible de inmediato. El propio compilador utiliza valores Tcl para almacenar en caché los bytecodes de instrucciones resultantes de la compilación de scripts.

Las dos representaciones son un caché de la otra y se calculan perezosamente. Es decir, cada representación solo se calcula cuando es necesaria, se calcula a partir de la otra representación y, una vez calculada, se guarda. Además, un cambio en una representación invalida la otra. Como ejemplo, un programa Tcl que realiza cálculos enteros puede operar directamente sobre la representación interna de enteros de la máquina de una variable sin tener que convertir constantemente entre enteros y cadenas. Solo cuando se necesita una cadena que represente el valor de la variable, por ejemplo, para imprimirla, el programa regenerará la representación de cadena a partir del entero. A pesar de que los valores contienen una representación interna, su semántica se define en términos de cadenas: siempre se puede obtener una cadena actualizada, y cualquier cambio en el valor se reflejará en esa cadena cuando se obtenga la representación de cadena del valor. Debido a esta invalidación y regeneración de representaciones, es peligroso para los escritores de extensiones acceder directamente a los campos de Tcl_Obj. Es mejor acceder a la información de Tcl_Obj utilizando procedimientos como Tcl_GetStringFromObj y Tcl_GetString.

Los valores se asignan en el heap y se referencian utilizando un puntero a su estructura Tcl_Obj. Los valores se comparten tanto como sea posible. Esto reduce significativamente los requisitos de almacenamiento porque algunos valores, como listas largas, son muy grandes. Además, la mayoría de los valores Tcl solo se leen y nunca se modifican. Esto es especialmente cierto para los argumentos de los procedimientos, que pueden ser compartidos entre el llamador y el procedimiento llamado. La asignación y la vinculación de argumentos se realizan simplemente asignando un puntero al valor. Se utiliza el conteo de referencias para determinar cuándo es seguro recuperar el almacenamiento de un valor.

Los valores Tcl están tipificados. La representación interna de un valor está controlada por su tipo. Varios tipos están predefinidos en el núcleo de Tcl, incluidos entero, doble, lista y bytecode. Los escritores de extensiones pueden extender el conjunto de tipos definiendo sus propias estructuras Tcl_ObjType.

LA ESTRUCTURA TCL_OBJ

Cada valor Tcl se representa mediante una estructura Tcl_Obj que se define de la siguiente manera.

typedef struct Tcl_Obj {
    int refCount;
    char *bytes;
    int length;
    const Tcl_ObjType *typePtr;
    union {
        long longValue;
        double doubleValue;
        void *otherValuePtr;
        Tcl_WideInt wideValue;
        struct {
            void *ptr1;
            void *ptr2;
        } twoPtrValue;
        struct {
            void *ptr;
            unsigned long value;
        } ptrAndLongRep;
    } internalRep;
} Tcl_Obj;

Los miembros bytes y length juntos contienen la representación de cadena UTF-8 de un valor, que es una cadena contada que no contiene bytes nulos (los caracteres nulos UTF-8 deben codificarse como una secuencia de dos bytes: 192, 128.) bytes apunta al primer byte de la representación de cadena. El miembro length da el número de bytes. El array de bytes siempre debe tener un byte nulo después del último byte de datos, en el desplazamiento length; esto permite que las representaciones de cadena se traten como cadenas C convencionales terminadas en nulo. Los programas C utilizan Tcl_GetStringFromObj y Tcl_GetString para obtener la representación de cadena de un valor. Si bytes es NULL, la representación de cadena no es válida.

El tipo de un valor gestiona su representación interna. El miembro typePtr apunta a la estructura Tcl_ObjType que describe el tipo. Si typePtr es NULL, la representación interna no es válida.

El miembro de la unión internalRep contiene la representación interna de un valor. Puede ser un entero (long), un número de punto flotante de doble precisión, un puntero a un valor que contiene información adicional necesaria por el tipo del valor para representar el valor, un entero Tcl_WideInt, dos punteros arbitrarios o un par compuesto por un entero unsigned long y un puntero.

El miembro refCount se utiliza para saber cuándo es seguro liberar el almacenamiento de un valor. Contiene el recuento de referencias activas al valor. Mantener el recuento de referencias correcto es una responsabilidad clave de los escritores de extensiones. El conteo de referencias se discute a continuación en la sección GESTIÓN DE ALMACENAMIENTO DE VALORES.

Aunque los escritores de extensiones pueden acceder directamente a los miembros de una estructura Tcl_Obj, es mucho mejor utilizar los procedimientos y macros apropiados. Por ejemplo, los escritores de extensiones nunca deben leer ni actualizar refCount directamente; deben utilizar macros como Tcl_IncrRefCount y Tcl_IsShared en su lugar.

Una propiedad clave de los valores Tcl es que contienen dos representaciones. Un valor normalmente comienza conteniendo solo una representación de cadena: no tiene tipo y tiene un typePtr NULO. Un valor que contiene una cadena vacía o una copia de una cadena especificada se crea utilizando Tcl_NewObj o Tcl_NewStringObj respectivamente. El valor de cadena de un valor se obtiene con Tcl_GetStringFromObj o Tcl_GetString y se cambia con Tcl_SetStringObj. Si más tarde el valor se pasa a un procedimiento como Tcl_GetIntFromObj que requiere una representación interna específica, el procedimiento creará una y establecerá el typePtr del valor. La representación interna se calcula a partir de la representación de cadena. Las dos representaciones de un valor son duales entre sí: los cambios realizados en una se reflejan en la otra. Por ejemplo, Tcl_ListObjReplace modificará la representación interna de un valor y la siguiente llamada a Tcl_GetStringFromObj o Tcl_GetString reflejará ese cambio.

Las representaciones se recalculan perezosamente por eficiencia. Un cambio en una representación realizado por un procedimiento como Tcl_ListObjReplace no se refleja inmediatamente en la otra representación. En su lugar, la otra representación se marca como inválida para que solo se regenere si se necesita más tarde. La mayoría de los programadores de C nunca tienen que preocuparse por cómo se hace esto y simplemente usan procedimientos como Tcl_GetBooleanFromObj o Tcl_ListObjIndex. Los programadores que implementan sus propios tipos de valores deben verificar las representaciones inválidas y marcar las representaciones como inválidas cuando sea necesario. El procedimiento Tcl_InvalidateStringRep se utiliza para marcar la representación de cadena de un valor como inválida y para liberar cualquier almacenamiento asociado con la antigua representación de cadena.

Tcl_DuplicateObj(3)

NAME

Tcl_DuplicateObj, Tcl_IsShared, Tcl_InvalidateStringRep, Tcl_MakeMutable, Tcl_TakeOwnership — crear duplicados de objetos de Tcl

SYNOPSIS

#include <tcl.h>

Tcl_Obj *
Tcl_DuplicateObj(objPtr);

int
Tcl_IsShared(objPtr);

void
Tcl_InvalidateStringRep(objPtr);

void
Tcl_MakeMutable(objPtr);

void
Tcl_TakeOwnership(objPtr);

ARGUMENTS

Tcl_Obj *objPtr
Objeto de Tcl para duplicar, compartir o modificar.

INTRODUCTION

Tcl utiliza una representación interna de objetos para almacenar valores. Estos objetos pueden tener varias representaciones internas (por ejemplo, cadena, entero, lista). La representación de cadena de un objeto se puede generar a partir de su representación interna cuando sea necesario.

A menudo, Tcl puede compartir la misma representación de objeto entre varias variables para ahorrar memoria. Sin embargo, esto significa que el objeto no debe modificarse directamente, ya que podría afectar a otras variables que comparten el mismo objeto. Las funciones Tcl_DuplicateObj, Tcl_IsShared, Tcl_MakeMutable y Tcl_TakeOwnership se utilizan para gestionar la compartición y la mutabilidad de los objetos de Tcl.

THE Tcl_Obj STRUCTURE

La estructura Tcl_Obj es la estructura de datos fundamental para representar valores en Tcl. Contiene la siguiente información:

typePtr
Un puntero a una estructura Tcl_ObjType que describe el tipo de la representación interna del valor (p. ej., entero, lista). Si es NULL, el objeto solo tiene una representación de cadena.
refCount
Un entero que indica cuántas referencias hay a este objeto. Cuando es 0, el objeto puede ser liberado de forma segura.
InternalRep
Una unión que almacena la representación interna del valor. El contenido de esta unión depende del tipo del valor.

Las representaciones de cadena y otras representaciones se gestionan por separado y se vinculan a la estructura Tcl_Obj. La representación de cadena se puede invalidar explícitamente para forzar su regeneración la próxima vez que se acceda a ella.

Los usuarios pueden obtener un nuevo objeto Tcl utilizando Tcl_NewObj, Tcl_NewStringObj, Tcl_NewIntObj, etc. Para obtener un elemento de una lista, se puede usar Tcl_ListObjIndex. El mismo valor que tiene el mismo valor de cadena puede tener varias representaciones internas diferentes en diferentes momentos. Los escritores de extensiones también pueden forzar que un valor se convierta de un tipo a otro usando el procedimiento Tcl_ConvertToType. Solo los programadores que crean nuevos tipos de valor necesitan preocuparse de cómo se hace esto. Un procedimiento definido como parte de la implementación del tipo de valor crea una nueva representación interna para un valor y cambia su typePtr. Consulte la página man de Tcl_RegisterObjType para ver cómo crear un nuevo tipo de valor.

EJEMPLO DE LA VIDA ÚTIL DE UN VALOR

Como ejemplo de la vida útil de un valor, considere la siguiente secuencia de comandos:

set x 123

Esto asigna a x un valor sin tipo cuyo miembro bytes apunta a 123 y cuyo miembro length contiene 3. El miembro typePtr del valor es NULL.

puts "x es $x"

La representación de cadena de x es válida (ya que bytes no es NULL) y se recupera para el comando.

incr x

El comando incr primero obtiene un entero del valor de x llamando a Tcl_GetIntFromObj. Este procedimiento comprueba si el valor ya es un valor entero. Como no lo es, convierte el valor estableciendo la representación interna del valor al entero 123 y estableciendo el typePtr del valor para que apunte a la estructura Tcl_ObjType del entero. Ambas representaciones son ahora válidas. incr incrementa la representación interna entera del valor y luego invalida su representación de cadena (llamando a Tcl_InvalidateStringRep) ya que la representación de cadena ya no corresponde a la representación interna.

puts "x es ahora $x"

Se necesita la representación de cadena del valor de x y se recalcula. La representación de cadena es ahora 124 y ambas representaciones son nuevamente válidas.

GESTIÓN DEL ALMACENAMIENTO DE VALORES

Los valores de Tcl se asignan en el montículo y se comparten tanto como sea posible para reducir los requisitos de almacenamiento. Se utiliza el recuento de referencias para determinar cuándo un valor ya no es necesario y se puede liberar de forma segura. Un valor recién creado por Tcl_NewObj o Tcl_NewStringObj tiene refCount 0. La macro Tcl_IncrRefCount incrementa el recuento de referencias cuando se crea una nueva referencia al valor. La macro Tcl_DecrRefCount decrementa el recuento cuando una referencia ya no es necesaria y, si el recuento de referencias del valor cae a cero, libera su almacenamiento. Un valor compartido por diferentes códigos o estructuras de datos tiene refCount mayor que 1. Incrementar el recuento de referencias de un valor asegura que no se liberará demasiado pronto o que su valor cambiará accidentalmente.

Como ejemplo, el intérprete de bytecode comparte los valores de los argumentos entre los procedimientos de Tcl que llaman y los llamados para evitar tener que copiar valores. Asigna los valores de los argumentos de la llamada a las variables de parámetros formales del procedimiento. Al hacerlo, llama a Tcl_IncrRefCount para incrementar el recuento de referencias de cada argumento, ya que ahora hay una nueva referencia a él desde el parámetro formal. Cuando el procedimiento llamado regresa, el intérprete llama a Tcl_DecrRefCount para decrementar el recuento de referencias de cada argumento. Cuando el recuento de referencias de un valor cae a menos o igual a cero, Tcl_DecrRefCount recupera su almacenamiento. La mayoría de los procedimientos de comando no tienen que preocuparse por el recuento de referencias, ya que utilizan el valor de un valor inmediatamente y no conservan un puntero al valor después de que regresan. Sin embargo, si conservan un puntero a un valor en una estructura de datos, deben tener cuidado de incrementar su recuento de referencias, ya que el puntero conservado es una nueva referencia.

Los procedimientos de comando que modifican directamente los valores, como los de lappend y linsert, deben tener cuidado de copiar un valor compartido antes de cambiarlo. Primero deben verificar si el valor se comparte llamando a Tcl_IsShared. Si el valor se comparte, deben copiar el valor usando Tcl_DuplicateObj; esto devuelve un duplicado nuevo del valor original que tiene refCount 0. Si el valor no se comparte, el procedimiento de comando "posee" el valor y puede modificarlo directamente de forma segura. Por ejemplo, el siguiente código aparece en el procedimiento de comando que implementa linsert. Este procedimiento modifica el valor de la lista que se le pasa en objv[1] insertando objc-3 nuevos elementos antes de index.

listPtr = objv[1];
if (Tcl_IsShared(listPtr)) {
    listPtr = Tcl_DuplicateObj(listPtr);
}
result = Tcl_ListObjReplace(interp, listPtr, index, 0,
        (objc-3), &(objv[3]));

Como otro ejemplo, el procedimiento de comando de incr debe verificar si el valor de la variable se comparte antes de incrementar el entero en su representación interna. Si se comparte, necesita duplicar el valor para evitar cambiar accidentalmente los valores en otras estructuras de datos.

Tcl_MakeMutable se puede usar para garantizar que un objeto no esté compartido. Si el objeto está compartido, se duplica internamente; de lo contrario, no hace nada. Esto es útil cuando se sabe que un objeto necesita ser modificado y se desea evitar la sobrecarga de comprobar explícitamente si está compartido. Tenga en cuenta que Tcl_MakeMutable no incrementa el recuento de referencias del objeto devuelto.

Tcl_TakeOwnership se utiliza para indicar que el llamador ahora es responsable de la gestión del ciclo de vida del objeto. El recuento de referencias se establece en 0 para indicar que el objeto no está siendo compartido externamente y que el llamador debe liberarlo eventualmente. Esto se usa típicamente para devolver un objeto de una función que creó o duplicó un objeto, transfiriendo la responsabilidad de la gestión de memoria al llamador.
