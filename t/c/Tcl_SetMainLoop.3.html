Tcl_Main(3) Procedimientos de biblioteca Tcl Tcl_Main(3)

NOMBRE

Tcl_Main, Tcl_MainEx, Tcl_MainExW, Tcl_SetStartupScript, Tcl_GetStartupScript, Tcl_SetMainLoop - programa principal, script de inicio y definición del bucle de eventos para aplicaciones basadas en Tcl

SINOPSIS

#include <tcl.h>

Tcl_Main(argc, argv, appInitProc)

Tcl_MainEx(argc, charargv, appInitProc, interp)

Tcl_MainExW(argc, wideargv, appInitProc, interp)

Tcl_SetStartupScript(path, encoding)

Tcl_Obj *
Tcl_GetStartupScript(encodingPtr)

Tcl_SetMainLoop(mainLoopProc)

ARGUMENTOS

int argc (entrada)
Número de elementos en argv.
char *argv[] (entrada)
Matriz de cadenas que contienen argumentos de línea de comandos. En Windows, cuando se usa -DUNICODE, el tipo del parámetro cambia a wchar_t *.
char *charargv[] (entrada)
Como argv, pero no cambia el tipo a wchar_t.
char *wideargv[] (entrada)
Como argv, pero el tipo es siempre wchar_t.
Tcl_AppInitProc *appInitProc (entrada)
Dirección de un procedimiento de inicialización específico de la aplicación. El valor para este argumento suele ser Tcl_AppInit.
Tcl_Obj *path (entrada)
Nombre del archivo a usar como script de inicio, o NULL.
const char *encoding (entrada)
Codificación del archivo a usar como script de inicio, o NULL.
const char **encodingPtr (salida)
Si no es NULL, ubicación para escribir una copia del puntero (const char *) que apunta al nombre de la codificación.
Tcl_MainLoopProc *mainLoopProc (entrada)
Dirección de un procedimiento de bucle de eventos específico de la aplicación.
Tcl_Interp *interp (entrada)
Intérprete Tcl ya creado.

DESCRIPCIÓN

Tcl_Main puede servir como programa principal para aplicaciones de shell basadas en Tcl. Una “aplicación de shell” es un programa como tclsh o wish que admite tanto la interpretación interactiva de Tcl como la evaluación de un script contenido en un archivo dado como argumento de línea de comandos. Tcl_Main se ofrece como una conveniencia para los desarrolladores de aplicaciones de shell, para que no tengan que reproducir todo el código necesario para la inicialización adecuada de la biblioteca Tcl y la operación del shell interactivo. Otros estilos de incrustar Tcl en una aplicación no son compatibles con Tcl_Main. Estos deben lograrse llamando directamente a funciones de nivel inferior en la biblioteca Tcl.

La función Tcl_Main ha sido ofrecida por la biblioteca Tcl desde la versión Tcl 7.4. En versiones anteriores de Tcl, la propia biblioteca Tcl definía una función main, pero carecía de flexibilidad en el estilo de incrustación y tener una función main en una biblioteca (particularmente una biblioteca compartida) causa problemas en muchos sistemas. Tener main en la biblioteca Tcl también dificultaría el uso de Tcl en programas C++, ya que los programas C++ deben tener funciones main de C++ especiales.

Normalmente, cada aplicación de shell contiene una pequeña función main que no hace nada más que invocar Tcl_Main. Tcl_Main realiza entonces todo el trabajo de crear y ejecutar una aplicación similar a tclsh.

Tcl_Main no es proporcionada por la interfaz pública de la biblioteca de stubs de Tcl. Los programas que llaman a Tcl_Main deben enlazarse contra la biblioteca Tcl estándar. Las extensiones (con o sin stubs) no están destinadas a llamar a Tcl_Main.

Tcl_Main no es segura para hilos. Solo debe ser llamada por un único hilo principal de una aplicación multihilo. Esta restricción no es un problema con el uso normal descrito anteriormente.

Tcl_Main y, por lo tanto, todas las aplicaciones basadas en ella, como tclsh, utilizan Tcl_GetStdChannel para inicializar los canales estándar a sus valores predeterminados. Consulte Tcl_StandardChannels para obtener más información.

Tcl_Main admite dos modos de operación, dependiendo de si el nombre de archivo y la codificación de un script de inicio se han establecido. Las rutinas Tcl_SetStartupScript y Tcl_GetStartupScript son las herramientas para controlar esta configuración de Tcl_Main.

Tcl_SetStartupScript registra el valor path como el nombre del archivo que Tcl_Main debe evaluar como su script de inicio. El valor encoding es el nombre de Tcl para la codificación utilizada para almacenar el texto en ese archivo. Un valor de NULL para encoding es una señal para usar la codificación del sistema. Un valor de NULL para path borra cualquier registro existente para que Tcl_Main no evalúe ningún script de inicio.

Tcl_GetStartupScript consulta el nombre de archivo y la codificación registrados establecidos por la llamada más reciente a Tcl_SetStartupScript en el mismo hilo. Se devuelve el nombre de archivo almacenado y el nombre de codificación almacenado se escribe en el espacio apuntado por encodingPtr, cuando este no es NULL.

Los valores del nombre de archivo y la codificación gestionados por las rutinas Tcl_SetStartupScript y Tcl_GetStartupScript se almacenan por hilo. Aunque las funciones de almacenamiento y recuperación de estas rutinas funcionan en cualquier hilo, solo aquellas llamadas en el mismo hilo principal que Tcl_Main pueden tener alguna influencia en ella.

El llamante de Tcl_Main puede llamar a Tcl_SetStartupScript primero para establecer su script de inicio deseado. Si Tcl_Main descubre que no se ha establecido ningún script de inicio, consulta los primeros argumentos en argv. Si coinciden con ?-encoding name? fileName, donde fileName no comienza con el carácter -, entonces fileName se toma como el nombre de un archivo que contiene un script de inicio, y name se toma como el nombre de la codificación del contenido de ese archivo. Tcl_Main llama entonces a Tcl_SetStartupScript con estos valores.

Tcl_Main define entonces en su intérprete principal las variables Tcl argc, argv, argv0 y tcl_interactive, como se describe en la documentación de tclsh.

Cuando ha terminado su propia inicialización, pero antes de procesar comandos, Tcl_Main llama al procedimiento proporcionado por el argumento appInitProc. Este procedimiento proporciona un “gancho” para que la aplicación realice su propia inicialización del intérprete creado por Tcl_Main, como la definición de comandos específicos de la aplicación. La rutina de inicialización de la aplicación también podría llamar a Tcl_SetStartupScript para (re)establecer el archivo y la codificación que se utilizarán como script de inicio. El procedimiento debe tener una interfaz que coincida con el tipo Tcl_AppInitProc:

typedef int Tcl_AppInitProc(
        Tcl_Interp *interp);

AppInitProc es casi siempre un puntero a Tcl_AppInit; para más detalles sobre este procedimiento, consulte la documentación de Tcl_AppInit.

Cuando el appInitProc termina, Tcl_Main llama a Tcl_GetStartupScript para determinar qué script de inicio se ha solicitado, si lo hay. Si se ha proporcionado un script de inicio, Tcl_Main intenta evaluarlo. De lo contrario, el modo interactivo comienza con el examen de la variable tcl_rcFileName en el intérprete principal. Si esa variable existe y contiene el nombre de un archivo legible, el contenido de ese archivo se evalúa en el intérprete principal. Luego comienzan las operaciones interactivas, con indicaciones y resultados de evaluación de comandos escritos en el canal de salida estándar, y comandos leídos del canal de entrada estándar y luego evaluados. Las indicaciones escritas en el canal de salida estándar pueden ser personalizadas definiendo las variables Tcl tcl_prompt1 y tcl_prompt2 como se describe en la documentación de tclsh. Las indicaciones y los resultados de la evaluación de comandos se escriben en el canal de salida estándar solo si la variable Tcl tcl_interactive en el intérprete principal contiene un valor entero distinto de cero.

Tcl_SetMainLoop permite establecer un procedimiento de bucle de eventos para ser ejecutado. Esto permite, por ejemplo, que Tk sea cargado dinámicamente y establezca su bucle de eventos. El bucle de eventos se ejecutará después del script de inicio. Si está en modo interactivo, establecer el procedimiento del bucle principal hará que la indicación se base en fileevent y luego se llame al procedimiento del bucle. Cuando el procedimiento del bucle regresa en modo interactivo, la operación interactiva continuará. El procedimiento del bucle principal debe tener una interfaz que coincida con el tipo Tcl_MainLoopProc:

typedef void Tcl_MainLoopProc(void);

Tcl_Main no regresa. Normalmente, un programa basado en Tcl_Main terminará cuando se evalúe el comando exit. En modo interactivo, si se encuentra un EOF o un error de canal en el canal de entrada estándar, Tcl_Main evaluará el comando exit

Tcl_SetMainLoop(3) — Tcl

NAME

Tcl_SetMainLoop — specifies a procedure to be called by Tcl_Main instead of the default event loop.

SYNOPSIS

#include <tcl.h>
void
Tcl_SetMainLoop(
    Tcl_MainLoopProc *proc
);

ARGUMENTS

-

proc (in) The procedure to call as the main loop. This procedure should have the following signature:

typedef void Tcl_MainLoopProc(
    int argc,
    char **argv
);

If proc is NULL, the default Tcl event loop will be used.

DESCRIPTION

The Tcl_SetMainLoop function allows an application to override the default main event loop that Tcl_Main uses. By default, Tcl_Main calls Tcl_EventLoop to process events.

If Tcl_SetMainLoop is called with a non-NULL procedure pointer, then Tcl_Main will call that procedure instead of Tcl_EventLoop when it enters the main loop. The provided procedure should take the same arguments as Tcl_Main (an argument count and an array of argument strings) and should be responsible for processing Tcl events.

A common use for this is to embed Tcl in a larger application. The embedding application can then call Tcl_SetMainLoop to have Tcl run its event loop within the application's existing event loop structure.

The procedure passed to Tcl_SetMainLoop will be called after Tcl_Main has processed any command-line arguments and called the application-specific initialization procedure (see Tcl_AppInit). The procedure should not return until the application is shutting down. When the procedure returns, Tcl_Main will perform any cleanup actions and then exit.

In interactive mode, after the main loop procedure (if any) returns. In non-interactive mode, after Tcl_Main evaluates the startup script, and the main loop procedure (if any) returns, Tcl_Main will also evaluate the exit command.

SEE ALSO

tclsh(1), Tcl_GetStdChannel(3), Tcl_StandardChannels(3), Tcl_AppInit(3), exit(n), encoding(n)

KEYWORDS

application-specific initialization, command-line arguments, main program
