ARGUMENTOS

Tcl_Interp *interp (entrada)
El intérprete donde se almacenarán los datos comprimidos o descomprimidos resultantes. También donde se escribirán los mensajes de error. Para Tcl_ZlibStreamInit, esto puede ser NULL para crear un flujo que no esté vinculado a un comando.
int format (entrada)
Qué formato de datos comprimidos manipular. Debe ser uno de TCL_ZLIB_FORMAT_ZLIB para datos en formato zlib, TCL_ZLIB_FORMAT_GZIP para datos en formato gzip, o TCL_ZLIB_FORMAT_RAW para datos comprimidos sin procesar. Además, solo para descompresión, también se puede elegir TCL_ZLIB_FORMAT_AUTO, que puede detectar automáticamente si los datos comprimidos estaban en formato zlib o gzip.
Tcl_Obj *dataObj (entrada/salida)
Un valor de tipo array de bytes que contiene los datos a comprimir o descomprimir, o al que se añaden los datos extraídos del flujo cuando se pasa a Tcl_ZlibStreamGet.
int level (entrada)
Qué nivel de compresión usar. Debe ser un número del 0 al 9 o uno de los siguientes: TCL_ZLIB_COMPRESS_NONE para ninguna compresión, TCL_ZLIB_COMPRESS_FAST para compresión rápida pero ineficiente, TCL_ZLIB_COMPRESS_BEST para compresión lenta pero máxima, o TCL_ZLIB_COMPRESS_DEFAULT para el nivel recomendado por la biblioteca zlib.
Tcl_Obj *dictObj (entrada/salida)
Un diccionario que contiene, o que se actualizará para contener, una descripción de la cabecera gzip asociada con los datos comprimidos. Solo es útil cuando el parámetro format es TCL_ZLIB_FORMAT_GZIP o TCL_ZLIB_FORMAT_AUTO. Si se pasa NULL, se usará una cabecera por defecto en la compresión y la cabecera se ignorará (aparte de las comprobaciones de integridad) en la descompresión. Consulte la sección DICCIONARIO DE OPCIONES GZIP para obtener detalles sobre el contenido de este diccionario.
unsigned int initValue (entrada)
El valor inicial para el algoritmo de suma de verificación.
unsigned char *bytes (entrada)
Un array de bytes sobre el que ejecutar el algoritmo de suma de verificación, o NULL para obtener el valor inicial recomendado para el algoritmo de suma de verificación.
int length (entrada)
El número de bytes en el array.
int mode (entrada)
En qué modo operar el flujo. Debe ser TCL_ZLIB_STREAM_DEFLATE para un flujo de compresión o TCL_ZLIB_STREAM_INFLATE para un flujo de descompresión.
Tcl_ZlibStream *zshandlePtr (salida)
Un puntero a una variable en la que se escribirá el token abstracto para el flujo tras su creación exitosa.
Tcl_ZlibStream zshandle (entrada)
El token abstracto para el flujo a manipular.
int flush (entrada)
Si y cómo vaciar el flujo después de escribirle los datos. Debe ser uno de: TCL_ZLIB_NO_FLUSH si no se va a realizar ningún vaciado, TCL_ZLIB_FLUSH si los datos actualmente comprimidos deben estar disponibles para su acceso mediante Tcl_ZlibStreamGet, TCL_ZLIB_FULLFLUSH si el flujo debe ponerse en un estado desde el cual el descompresor pueda recuperarse de una corrupción, o TCL_ZLIB_FINALIZE para asegurar que el flujo ha terminado y que se escribirá cualquier remolque exigido por el formato.
int count (entrada)
El número máximo de bytes a obtener del flujo, o -1 para obtener todos los bytes restantes de los búferes del flujo.
Tcl_Obj *compDict (entrada)
Un valor de array de bytes que es el diccionario de compresión a usar con el flujo. Tenga en cuenta que esto *no es un diccionario Tcl*, y se recomienda que solo se use con flujos que se crearon con su format establecido a TCL_ZLIB_FORMAT_ZLIB, ya que los otros formatos no tienen ningún mecanismo para indicar si estaba presente un diccionario de compresión, excepto fallar en la descompresión.

DESCRIPCIÓN

Estas funciones forman la interfaz de la biblioteca Tcl a la biblioteca Zlib de Jean-loup Gailly y Mark Adler.

Tcl_ZlibDeflate y Tcl_ZlibInflate respectivamente comprimen y descomprimen los datos contenidos en el argumento dataObj, de acuerdo con los argumentos format y, para la compresión, level. El diccionario en el parámetro dictObj se usa para transmitir información adicional de cabecera sobre los datos comprimidos cuando el formato de compresión lo soporta; actualmente, el diccionario solo se usa cuando el parámetro format es TCL_ZLIB_FORMAT_GZIP o TCL_ZLIB_FORMAT_AUTO. Para obtener detalles sobre el contenido del diccionario, consulte la sección DICCIONARIO DE OPCIONES GZIP más abajo. Tras el éxito, ambas funciones dejan los datos comprimidos o descomprimidos resultantes en un valor de array de bytes que es el resultado del intérprete Tcl; el valor devuelto es un código de resultado Tcl estándar.

Tcl_ZlibAdler32 y Tcl_ZlibCRC32 calculan sumas de verificación sobre arrays de bytes, devolviendo la suma de verificación calculada. Las sumas de verificación se calculan incrementalmente, permitiendo que los datos se procesen bloque a bloque, pero esto requiere que el llamador mantenga la suma de verificación actual y la pase como el parámetro initValue; el valor inicial a usar para esto se puede obtener usando NULL para el parámetro bytes en lugar de un puntero al array de bytes sobre el que calcular la suma de verificación. Por lo tanto, el uso típico en el caso de un solo bloque de datos es el siguiente:

checksum = Tcl_ZlibCRC32(Tcl_ZlibCRC32(0,NULL,0), data, length);

Tenga en cuenta que el algoritmo Adler-32 no es una suma de verificación real, sino un tipo de hash relacionado que funciona mejor con datos más largos.

FLUJOS ZLIB

Tcl_ZlibStreamInit crea un flujo de compresión o descompresión que está vinculado a un comando Tcl, de acuerdo con sus argumentos, y proporciona un token abstracto para el flujo y devuelve un código de resultado Tcl normal; Tcl_ZlibStreamGetCommandName devuelve el nombre de ese comando dado el token del flujo, o NULL si el flujo no tiene comando. Los flujos no están diseñados para ser seguros en hilos; cada flujo solo debe usarse desde el hilo que lo creó. Al trabajar con flujos gzip, se puede proporcionar un diccionario (campos como se indican en la sección DICCIONARIO DE OPCIONES GZIP) a través del parámetro dictObj que, en la compresión, permite controlar las cabeceras generadas, y en la descompresión, permite descubrir las cabeceras existentes. Tenga en cuenta que el diccionario se escribirá en la descompresión una vez que se hayan leído suficientes datos para tener una cabecera completa. Esto significa que el diccionario debe ser un valor no compartido en ese caso; se sugiere un valor en blanco creado con Tcl_NewObj.

Una vez que se ha construido un flujo, Tcl_ZlibStreamPut se utiliza para añadir datos al flujo y Tcl_ZlibStreamGet se utiliza para recuperar datos del flujo después del procesamiento. Ambos devuelven códigos de resultado Tcl normales y dejan un mensaje de error en el resultado del intérprete con el que está registrado el flujo (si se ha realizado tal registro). Con Tcl_ZlibStreamPut, el valor del búfer de datos que se le pasa no debe modificarse después. Con Tcl_ZlibStreamGet, el valor del búfer de datos que se le pasa tendrá los bytes de datos añadidos. Internamente al flujo, los datos se mantienen comprimidos para minimizar el costo del espacio del búfer.

ARGUMENTS

Tcl_Obj *streamObj
The stream object to operate on.

The data to be compressed.

The number of bytes in the bytes argument.
Tcl_Obj **resultPtr
Where to store the result of the operation.
const unsigned char *dict

DESCRIPTION

The Tcl zlib extension provides stream-oriented compression and decompression facilities via the Tcl command zlib. This manual page describes the C API for these facilities.

Tcl_ZlibStreamPut is used to pass data to a zlib stream for compression. The bytes and len arguments specify the data to be compressed, and the result is stored in the Tcl object pointed to by resultPtr. The value stored will be the compressed data as a Tcl byte array object. This function may be called multiple times to compress multiple chunks of data. The return value is a standard Tcl result code; if the stream is registered with an interpreter, an error message will be left in the interpreter result when this function returns TCL_ERROR.

Tcl_ZlibStreamGet is used to retrieve decompressed data from a zlib stream. The result is stored in the Tcl object pointed to by resultPtr. The value stored will be the decompressed data as a Tcl byte array object. This function may be called multiple times to retrieve multiple chunks of data. If the stream is registered with an interpreter, an error message will be left in the interpreter result when this function returns TCL_ERROR. The return value is a standard Tcl result code.

Tcl_ZlibStreamEof returns a boolean value indicating whether the end of the uncompressed data has been reached.

Tcl_ZlibStreamSetCompressionDictionary is used to control the compression dictionary used with the stream, a compression dictionary being an array of bytes (such as might be created with Tcl_NewByteArrayObj) that is used to initialize the compression engine rather than leaving it to create it on the fly from the data being compressed. Setting a compression dictionary allows for more efficient compression in the case where the start of the data is highly regular, but it does require both the compressor and the decompressor to agreee on the value to use. Compression dictionaries are only fully supported for zlib-format data; on compression, they must be set before any data is sent in with Tcl_ZlibStreamPut, and on decompression they should be set when Tcl_ZlibStreamGet produces an error with its -errorcode set to “ZLIB NEED_DICT code”; the code will be the Adler-32 checksum (see Tcl_ZlibAdler32) of the compression dictionary sought. (Note that this is only true for zlib-format streams; gzip streams ignore compression dictionaries as the format specification doesn't permit them, and raw streams just produce a data error if the compression dictionary is missing or incorrect.)

If you wish to clear a stream and reuse it for a new compression or decompression action, Tcl_ZlibStreamReset will do this and return a normal Tcl result code to indicate whether it was successful; if the stream is registered with an interpreter, an error message will be left in the interpreter result when this function returns TCL_ERROR. Finally, Tcl_ZlibStreamClose will clean up the stream and delete the associated command: using Tcl_DeleteCommand on the stream's command is equivalent (when such a command exists).

GZIP OPTIONS DICTIONARY

The dictObj parameter to Tcl_ZlibDeflate, Tcl_ZlibInflate and Tcl_ZlibStreamInit is used to pass a dictionary of options about that is used to describe the gzip header in the compressed data. When creating compressed data, the dictionary is read and when unpacking compressed data the dictionary is written (in which case the dictObj parameter must refer to an unshared dictionary value).

The following fields in the dictionary value are understood. All other fields are ignored. No field is required when creating a gzip-format stream.

comment
This holds the comment field of the header, if present. If absent, no comment was supplied (on decompression) or will be created (on compression).
crc
A boolean value describing whether a CRC of the header is computed. Note that the gzip program does not use or allow a CRC on the header.
filename
The name of the file that held the uncompressed data. This should not contain any directory separators, and should be sanitized before use on decompression with file tail.
os
The operating system type code field from the header (if not the “unknown” value). See RFC 1952 for the meaning of these codes. On compression, if this is absent then the field will be set to the “unknown” value.
size
The size of the uncompressed data. This is ignored on compression; the size of the data compressed depends on how much data is supplied to the compression engine.
time
The time field from the header if non-zero, expected to be the time that the file named by the filename field was modified. Suitable for use with clock format. On creation, the right value to use is that from clock seconds or file mtime.
type
The type of the uncompressed data (either binary or text) if known.

PORTABILITY NOTES

These functions will fail gracefully if Tcl is not linked with the zlib library.
