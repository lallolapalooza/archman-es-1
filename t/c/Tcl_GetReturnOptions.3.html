DESCRIPCIÓN

Las rutinas Tcl_SetReturnOptions y Tcl_GetReturnOptions exponen las mismas capacidades que los comandos return y catch, respectivamente, en forma de una interfaz C.

Tcl_GetReturnOptions recupera el diccionario de opciones de retorno de un intérprete después de una evaluación de script. Rutinas como Tcl_Eval se utilizan para evaluar un script en un intérprete. Estas rutinas devuelven un código de finalización entero. Estas rutinas también dejan en el intérprete tanto un resultado como un diccionario de opciones de retorno generado por la evaluación del script. Al igual que Tcl_GetObjResult recupera el resultado, Tcl_GetReturnOptions recupera el diccionario de opciones de retorno. El código de finalización entero debe pasarse como argumento code a Tcl_GetReturnOptions para que todas las opciones requeridas estén presentes en el diccionario. Específicamente, un valor code de TCL_ERROR asegurará que las entradas para las claves -errorinfo, -errorcode y -errorline aparezcan en el diccionario. Además, las entradas para las claves -code y -level se ajustarán si es necesario para coincidir con el valor de code. El (Tcl_Obj *) devuelto por Tcl_GetReturnOptions apunta a un Tcl_Obj no compartido con un contador de referencias de cero. El diccionario puede ser modificado, ya sea añadiendo, eliminando o sobrescribiendo cualquier entrada en él, sin necesidad de comprobar si es un valor compartido. Como con cualquier Tcl_Obj con contador de referencias de cero, es responsabilidad del llamador organizar su eliminación con Tcl_DecrRefCount o una referencia a él a través de Tcl_IncrRefCount (o una de las muchas funciones que llaman a esta, notablemente incluyendo Tcl_SetObjResult y Tcl_SetVar2Ex).

Un uso típico para Tcl_GetReturnOptions es recuperar el rastreo de pila cuando la evaluación del script devuelve TCL_ERROR, como se muestra a continuación:

int code = Tcl_Eval(interp, script);
if (code == TCL_ERROR) {
    Tcl_Obj *options = Tcl_GetReturnOptions(interp, code);
    Tcl_Obj *key = Tcl_NewStringObj("-errorinfo", -1);
    Tcl_Obj *stackTrace;
    Tcl_IncrRefCount(key);
    Tcl_DictObjGet(NULL, options, key, &stackTrace);
    Tcl_DecrRefCount(key);
    /* Hacer algo con stackTrace */
    Tcl_DecrRefCount(options);
}

Tcl_SetReturnOptions establece las opciones de retorno de interp a ser options. Si options contiene algún valor inválido para alguna clave, se devolverá TCL_ERROR, y el resultado del intérprete se establecerá a un mensaje de error apropiado. De lo contrario, se devolverá un código de finalización coherente con las claves -code y -level en options.

Como ejemplo, el propio comando return de Tcl podría implementarse en términos de Tcl_SetReturnOptions de la siguiente manera:

if ((objc % 2) == 0) { /* argumento de resultado explícito */
    objc--;
    Tcl_SetObjResult(interp, objv[objc]);
}
return Tcl_SetReturnOptions(interp, Tcl_NewListObj(objc-1, objv+1));

(En realidad no está implementado de esa manera. Los privilegios de acceso interno permiten una alternativa más eficiente que se integra mejor con el compilador de bytecode.)

Tenga en cuenta que se puede pasar un Tcl_Obj recién creado como argumento options sin necesidad de gestionar ningún conteo de referencias. Esto es análogo a Tcl_SetObjResult.

Mientras que Tcl_SetReturnOptions proporciona una interfaz general para establecer cualquier colección de opciones de retorno, hay un puñado de opciones de retorno que se utilizan con mucha frecuencia. La mayoría notablemente las opciones de retorno -errorinfo y -errorcode deben establecerse correctamente cuando el procedimiento del comando devuelve TCL_ERROR. La opción de retorno -errorline también es leída por los comandos que evalúan scripts y desean proporcionar información detallada de la ubicación del error en el texto del rastreo de pila que añaden a la opción -errorinfo. Tcl proporciona varias interfaces más simples para establecer estas opciones de retorno de forma más directa.

La opción -errorinfo contiene un rastreo de pila de las operaciones que estaban en progreso cuando ocurrió un error, y está destinada a ser legible por humanos. La opción -errorcode contiene una lista Tcl de elementos que están destinados a ser legibles por máquinas. El primer elemento en el valor de -errorcode identifica la clase de error que ocurrió (por ejemplo, POSIX significa que ocurrió un error en una llamada al sistema POSIX) y los elementos adicionales contienen información adicional que depende de la clase. Consulte la página del manual sobre la variable errorCode para obtener detalles sobre los diversos formatos para la opción -errorcode utilizados por los comandos integrados de Tcl.

El valor de la opción -errorinfo se construye gradualmente a medida que un error se desenrolla a través de las operaciones anidadas. Cada vez que un código de error se devuelve a Tcl_Eval, o a cualquiera de las rutinas que realiza la evaluación de scripts, se llama al procedimiento Tcl_AddErrorInfo para añadir texto adicional al valor de -errorinfo que describe el comando que se estaba ejecutando cuando ocurrió el error. Cuando el error ha sido devuelto completamente a la aplicación, contendrá un rastro completo de la actividad en progreso cuando ocurrió el error.

A veces es útil añadir información adicional al valor de -errorinfo más allá de lo que pueden suministrar automáticamente las rutinas de evaluación de scripts. Tcl_AddErrorInfo puede ser utilizado para este propósito: su argumento message es una cadena adicional que se añadirá a la opción -errorinfo. Por ejemplo, cuando surge un error durante el comando source, se llama al procedimiento Tcl_AddErrorInfo para registrar el nombre del archivo que se está procesando y el número de línea en el que ocurrió el error. DESCRIPCIÓN

Estas funciones proporcionan una forma de manipular la información de error asociada con un intérprete de Tcl. Cuando un comando Tcl devuelve TCL_ERROR, el intérprete almacena información sobre el error en las opciones de retorno -errorinfo y -errorcode. Estas funciones permiten a los programadores C añadir información a estas opciones de retorno, o establecerlas directamente.

Tcl_AddErrorInfo añade la cadena de caracteres message al final de la información de error actual del intérprete. Si se produce un error dentro de un procedimiento Tcl, se registra el nombre del procedimiento y el número de línea dentro del procedimiento, y así sucesivamente. El mejor momento para llamar a Tcl_AddErrorInfo es justo después de que una rutina de evaluación de script haya devuelto TCL_ERROR. El valor de la opción de retorno -errorline (recuperado mediante una llamada a Tcl_GetReturnOptions) a menudo constituye una parte útil del message pasado a Tcl_AddErrorInfo.

Tcl_AppendObjToErrorInfo es una interfaz alternativa a la misma funcionalidad que Tcl_AddErrorInfo. Se llama a Tcl_AppendObjToErrorInfo cuando el valor de cadena a añadir a la opción -errorinfo está disponible como un Tcl_Obj en lugar de como un array de char.

Tcl_AddObjErrorInfo es casi idéntica a Tcl_AddErrorInfo, excepto que tiene un argumento adicional de length. Esto permite que la cadena message contenga bytes nulos incrustados. Esto es esencialmente nunca una buena idea. Si el message necesita contener el carácter nulo U+0000, se deben utilizar las reglas de codificación internas habituales de Tcl para evitar la necesidad de un byte nulo. Si la interfaz Tcl_AddObjErrorInfo se utiliza en absoluto, debe ser con un valor de length negativo.

El procedimiento Tcl_SetObjErrorCode se utiliza para establecer la opción de retorno -errorcode al valor de lista errorObjPtr construido por el llamador. Tcl_SetObjErrorCode se invoca típicamente justo antes de devolver un error. Si se devuelve un error sin llamar a Tcl_SetObjErrorCode o Tcl_SetErrorCode, el intérprete Tcl establece automáticamente la opción de retorno -errorcode a NONE.

El procedimiento Tcl_SetErrorCode también se utiliza para establecer la opción de retorno -errorcode. Sin embargo, toma una o más cadenas para registrar en lugar de un valor. De lo contrario, es similar a Tcl_SetObjErrorCode en su comportamiento.

Tcl_SetErrorCodeVA es lo mismo que Tcl_SetErrorCode excepto que en lugar de tomar un número variable de argumentos, toma una lista de argumentos.

El procedimiento Tcl_GetErrorLine se utiliza para leer el valor entero de la opción de retorno -errorline sin la sobrecarga de una llamada completa a Tcl_GetReturnOptions. De manera similar, Tcl_SetErrorLine establece el valor de la opción de retorno -errorline.

Tcl_PosixError establece la variable -errorcode después de un error en una llamada al kernel POSIX. Lee el valor de la variable errno de C y llama a Tcl_SetErrorCode para establecer la opción de retorno -errorcode en el formato POSIX. El llamador debe haber llamado previamente a Tcl_SetErrno para establecer errno; esto es necesario en algunas plataformas (por ejemplo, Windows) donde Tcl se vincula a una aplicación como una biblioteca compartida, o cuando el error ocurre en una extensión cargada dinámicamente. Vea la entrada del manual para Tcl_SetErrno para más información.

Tcl_PosixError devuelve un mensaje de diagnóstico legible por humanos para el error (este es el mismo valor que aparecerá como el tercer elemento del valor de -errorcode). Puede ser conveniente incluir esta cadena como parte del mensaje de error devuelto a la aplicación en el resultado del intérprete.

Tcl_LogCommandInfo se invoca después de que ocurre un error en un intérprete. Añade información sobre el comando que se estaba ejecutando cuando ocurrió el error al valor de -errorinfo, y el número de línea almacenado internamente en el intérprete se establece.

En versiones anteriores de Tcl, no existía la rutina Tcl_GetReturnOptions. En su lugar, las variables globales de Tcl errorInfo y errorCode eran el único lugar para recuperar la información del error. Gran parte del código existente escrito para versiones antiguas de Tcl todavía accede a esta información a través de esas variables globales.

Es importante darse cuenta de que, si bien la lectura de esas variables globales sigue siendo una forma admitida de acceder a estos valores de opciones de retorno, es importante no asumir que la escritura en esas variables globales establecerá correctamente las opciones de retorno correspondientes. Se ha enfatizado durante mucho tiempo en esta página de manual que es importante llamar a los procedimientos descritos aquí en lugar de establecer errorInfo o errorCode directamente con Tcl_ObjSetVar2.

Si se llama al procedimiento Tcl_ResetResult, borra todo el estado del intérprete asociado con la evaluación de scripts, incluido el diccionario completo de opciones de retorno. En particular, se restablecen las opciones -errorinfo y -errorcode. Si se había producido un error, la llamada a Tcl_ResetResult borrará el estado de error para que parezca como si no hubiera ocurrido ningún error después de todo. Las variables globales errorInfo y errorCode no son modificadas por Tcl_ResetResult, por lo que continúan conteniendo un registro de información sobre el error más reciente visto en un intérprete.
