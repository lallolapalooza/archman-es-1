Nombre de la codificación a cargar.
Tcl_Encoding encoding (entrada)
La codificación a consultar, liberar o usar para convertir texto. Si encoding es NULL, se usa la codificación del sistema actual.
Tcl_Obj *objPtr (entrada)
Nombre de la codificación para obtener el token.
Tcl_Encoding *encodingPtr (salida)
Punta a un espacio de almacenamiento donde se escribirá el token de codificación.
const char *src (entrada)
Para las funciones Tcl_ExternalToUtf, una matriz de bytes en la codificación especificada que se convertirá a UTF-8. Para las funciones Tcl_UtfToExternal y Tcl_WinUtfToTChar, una matriz de caracteres UTF-8 que se convertirán a la codificación especificada.
const TCHAR *tsrc (entrada)
Una matriz de caracteres TCHAR de Windows para convertir a UTF-8.
int srcLen (entrada)
Longitud de src o tsrc en bytes. Si la longitud es negativa, se utiliza la longitud específica de la codificación de la cadena.
Tcl_DString *dstPtr (salida)
Puntero a una Tcl_DString no inicializada o liberada en la que se almacenará el resultado convertido.
int flags (entrada)
Varios bits de bandera OR-ados. TCL_ENCODING_START significa que el buffer de origen es el primer bloque en un flujo de entrada (potencialmente de varios bloques), indicando a la rutina de conversión que se reinicie a un estado inicial y realice cualquier inicialización que deba ocurrir antes de que se convierta el primer byte. TCL_ENCODING_END significa que el buffer de origen es el último bloque en un flujo de entrada (potencialmente de varios bloques), indicando a la rutina de conversión que realice cualquier finalización que deba ocurrir después de que se convierta el último byte y luego que se reinicie a un estado inicial. TCL_ENCODING_STOPONERROR significa que la rutina de conversión debe regresar inmediatamente al leer un carácter de origen que no existe en la codificación de destino; de lo contrario, se sustituirá automáticamente un carácter de reserva predeterminado.
Tcl_EncodingState *statePtr (entrada/salida)
Se utiliza al convertir un flujo de bytes (generalmente largo o de longitud indefinida) de forma gradual. La rutina de conversión almacena su estado actual en *statePtr después de que se ha convertido src (el buffer que contiene el bloque actual); esa información de estado debe ser devuelta al convertir el siguiente bloque del flujo para que la rutina de conversión sepa en qué estado estaba cuando terminó con el último bloque. Puede ser NULL, en cuyo caso el valor especificado para flags se ignora y se asume que el buffer de origen contiene la cadena completa a convertir.
char *dst (salida)
Buffer en el que se almacenará el resultado convertido. No se almacenarán más de dstLen bytes en dst.
int dstLen (entrada)
La longitud máxima del buffer de salida dst en bytes.
int *srcReadPtr (salida)
Se rellena con el número de bytes de src que se convirtieron realmente. Esto puede ser menor que la longitud de origen original si hubo un problema al convertir algunos caracteres de origen. Puede ser NULL.
int *dstWrotePtr (salida)
Se rellena con el número de bytes que se almacenaron realmente en el buffer de salida como resultado de la conversión. Puede ser NULL.
int *dstCharsPtr (salida)
Se rellena con el número de caracteres que corresponden al número de bytes almacenados en el buffer de salida. Puede ser NULL.
Tcl_DString *bufPtr (salida)

INTRODUCCION

Estas rutinas convierten entre la representación interna de caracteres de Tcl, UTF-8, y las representaciones de caracteres utilizadas por varios sistemas operativos o sistemas de archivos, como Unicode, ASCII o Shift-JIS. Al operar en cadenas, como por ejemplo al obtener los nombres de archivos o mostrar caracteres usando fuentes internacionales, las cadenas deben traducirse a uno o posiblemente a múltiples formatos que las diversas llamadas al sistema puedan usar. Por ejemplo, en una estación de trabajo Unix japonesa, un usuario podría obtener un nombre de archivo representado en la codificación de archivo EUC-JP y luego traducir los caracteres a la codificación de fuente jisx0208 para poder mostrar el nombre del archivo en un widget Tk. El propósito del paquete de codificación es ayudar a salvar la brecha de traducción. UTF-8 proporciona un punto de preparación intermedio para todas las diversas codificaciones. En el ejemplo anterior, el texto se traduciría a UTF-8 desde cualquier codificación de archivo que esté utilizando el sistema operativo. Luego se traduciría de UTF-8 a la codificación de fuente que requieran las rutinas de visualización.

Algunas codificaciones básicas están compiladas en Tcl. Otras pueden ser definidas por el usuario o cargadas dinámicamente desde archivos de codificación de manera independiente de la plataforma.

DESCRIPCION

Tcl_GetEncoding busca una codificación dado su name. El nombre puede referirse a una codificación Tcl integrada, una codificación definida por el usuario registrada llamando a Tcl_CreateEncoding, o un archivo de codificación cargable dinámicamente. El valor de retorno es un token que representa la codificación y puede usarse en llamadas posteriores a procedimientos como Tcl_GetEncodingName, Tcl_FreeEncoding y Tcl_UtfToExternal. Si el nombre no se refiere a ninguna codificación conocida o cargable, se devuelve NULL y se devuelve un mensaje de error en interp.

El paquete de codificación mantiene una base de datos de todas las codificaciones actualmente en uso. La primera vez que se ve name, Tcl_GetEncoding devuelve una codificación con un contador de referencia de 1. Si se solicita el mismo name varias veces más, el contador de referencia para esa codificación se incrementa sin la sobrecarga de asignar una nueva codificación y todas sus estructuras de datos asociadas.

Cuando una encoding ya no es necesaria, se debe llamar a Tcl_FreeEncoding para liberarla. Cuando una encoding ya no está en uso en ninguna parte (es decir, se ha liberado tantas veces como se ha obtenido), Tcl_FreeEncoding liberará todo el espacio que la codificación estaba utilizando y la eliminará de la base de datos.

Tcl_GetEncodingFromObj trata la representación de cadena de objPtr como un nombre de codificación, y busca una codificación con ese nombre, al igual que lo hace Tcl_GetEncoding. Cuando se encuentra una codificación, se almacena en caché dentro del valor objPtr para referencia futura, el token Tcl_Encoding se escribe en el espacio de almacenamiento

This is done through the use of an encoding "token", which is a value of type Tcl_Encoding. Encoding tokens are opaque values that are obtained by calling one of the functions described below. Tcl_Encoding tokens are reference-counted. When Tcl_GetEncoding or Tcl_GetEncodingByName returns an encoding token, its reference count is incremented. The caller is responsible for decrementing the reference count when the token is no longer needed by calling Tcl_FreeEncoding. If the reference count reaches zero, the encoding is discarded. Tcl_GetEncoding(interp, name) looks up the encoding named name. If name is NULL, the current system encoding is used. If the encoding is found, a pointer to its token is returned. The reference count for the encoding is incremented. If no such encoding is found, NULL is returned and an error message is left in interp. Tcl_GetEncodingByName(namePtr) is similar to Tcl_GetEncoding, but it takes a pointer to the name string, not the string itself. This is useful when the name is stored in a Tcl_DString. It returns a pointer to the encoding token if found, and NULL otherwise. Tcl_FreeEncoding(encoding) decrements the reference count for the encoding token. When the reference count reaches zero, the encoding is freed. Tcl_ExternalToUtfDString converts a source buffer src from the specified encoding into UTF-8. The converted bytes are stored in dstPtr, which is then null-terminated. The caller should eventually call Tcl_DStringFree to free any information stored in dstPtr. When converting, if any of the characters in the source buffer cannot be represented in the target encoding, a default fallback character will be used. The return value is a pointer to the value stored in the DString. Tcl_ExternalToUtf converts a source buffer src from the specified encoding into UTF-8. Up to srcLen bytes are converted from the source buffer and up to dstLen converted bytes are stored in dst. In all cases, *srcReadPtr is filled with the number of bytes that were successfully converted from src and *dstWrotePtr is filled with the corresponding number of bytes that were stored in dst. The return value is one of the following: TCL_OK All bytes of src were converted. TCL_CONVERT_NOSPACE The destination buffer was not large enough for all of the converted data; as many characters as could fit were converted though. TCL_CONVERT_MULTIBYTE The last few bytes in the source buffer were the beginning of a multibyte sequence, but more bytes were needed to complete this sequence. A subsequent call to the conversion routine should pass a buffer containing the unconverted bytes that remained in src plus some further bytes from the source stream to properly convert the formerly split-up multibyte sequence. TCL_CONVERT_SYNTAX The source buffer contained an invalid character sequence. This may occur if the input stream has been damaged or if the input encoding method was misidentified. TCL_CONVERT_UNKNOWN The source buffer contained a character that could not be represented in the target encoding and TCL_ENCODING_STOPONERROR was specified. Tcl_UtfToExternalDString converts a source buffer src from UTF-8 into the specified encoding. The converted bytes are stored in dstPtr, which is then terminated with the appropriate encoding-specific null. The caller should eventually call Tcl_DStringFree to free any information stored in dstPtr. When converting, if any of the characters in the source buffer cannot be represented in the target encoding, a default fallback character will be used. The return value is a pointer to the value stored in the DString. Tcl_UtfToExternal converts a source buffer src from UTF-8 into the specified encoding. Up to srcLen bytes are converted from the source buffer and up to dstLen converted bytes are stored in dst. In all cases, *srcReadPtr is filled with the number of bytes that were successfully converted from src and *dstWrotePtr is filled with the corresponding number of bytes that were stored in dst. The return values are the same as the return values for Tcl_ExternalToUtf. Tcl_WinUtfToTChar and Tcl_WinTCharToUtf are Windows-only convenience functions for converting between UTF-8 and Windows strings based on the TCHAR type which is by convention a Unicode character on Windows NT. Tcl_GetEncodingName is roughly the inverse of Tcl_GetEncoding. Given an encoding, the return value is the name argument that was used to create the encoding. The string returned by Tcl_GetEncodingName is only guaranteed to persist until the encoding is deleted. The caller must not modify this string. Tcl_SetSystemEncoding sets the default encoding that should be used whenever the user passes a NULL value for the encoding argument to any of the other encoding functions. If name is NULL, the system encoding is reset to the default system encoding, binary. If the name did not refer to any known or loadable encoding, TCL_ERROR is returned and an error message is left in interp. Otherwise, this procedure increments the reference count of the new system encoding, decrements the reference count of the old system encoding, and returns TCL_OK. Tcl_GetEncodingNameFromEnvironment provides a means for the Tcl library to report the encoding name it believes to be the correct one to use as the system encoding, based on system calls and examination of the environment suitable for the platform. It accepts bufPtr, a pointer to an uninitialized or freed Tcl_DString and writes the encoding name to it. The Tcl_DStringValue is returned. Tcl_GetEncodingNames sets the interp result to a list consisting of the names of all the encodings that are currently defined or can be dynamically loaded, searching the encoding path specified by Tcl_SetDefaultEncodingDir. This procedure does not ensure that the dynamically-loadable encoding files contain valid data, but merely that they exist. Tcl_CreateEncoding defines a new encoding and registers the C procedures that are called back to convert between the encoding and UTF-8. Encodings created by Tcl_CreateEncoding are thereafter visible in the database used by Tcl_GetEncoding. Just as with the Tcl_GetEncoding procedure, the return value is a token that represents the encoding and can be used in subsequent calls to other encoding functions. Tcl_CreateEncoding returns an encoding with a reference count of 1. If an encoding with the specified name already exists, then its entry in the database is replaced with the new encoding; the token for the old encoding will remain valid and continue to behave as before, but users of the new token will now call the new encoding procedures. The typePtr argument to Tcl_CreateEncoding contains information about the name of the encoding and the procedures that will be called to convert between this encoding and UTF-8. It is defined as follows: typedef struct Tcl_EncodingType { const char *encodingName; Tcl_EncodingConvertProc *toUtfProc; Tcl_EncodingConvertProc *fromUtfProc; Tcl_EncodingFreeProc *freeProc; ClientData clientData; int nullSize; } Tcl_EncodingType; The encodingName provides a string name for the encoding, by which it can be referred in other procedures such as Tcl_GetEncoding. The toUtfProc refers to a callback procedure to invoke to convert text from this encoding into UTF-8. The fromUtfProc refers to a callback procedure to invoke to convert text from UTF-8 into this encoding. The freeProc refers to a callback procedure to invoke when this encoding is deleted. The freeProc field may be NULL. The clientData contains an arbitrary one-word value passed to toUtfProc, fromUtfProc, and freeProc whenever they are called. Typically, this is a pointer to a data structure containing encoding-specific information that can be used by the callback procedures. For instance, two very similar encodings such as ascii and macRoman may use the same callback procedure, but use different values of clientData to control its behavior. The nullSize specifies the number of zero bytes that signify end-of-string in this encoding. It must be 1 (for single-byte or multi-byte encodings like ASCII or Shift-JIS) or 2 (for double-byte encodings like Unicode). Constant-sized encodings with 3 or more bytes per character (such as CNS11643) are not accepted. The callback procedures toUtfProc and fromUtfProc should match the type Tcl_EncodingConvertProc: typedef int Tcl_EncodingConvertProc( ClientData clientData, const char *src, int srcLen, int flags, Tcl_EncodingState *statePtr, char *dst, int dstLen, int *srcReadPtr, int *dstWrotePtr, int *dstCharsPtr); The toUtfProc and fromUtfProc procedures are called by the Tcl_ExternalToUtf or Tcl_UtfToExternal family of functions to perform the actual conversion. The clientData parameter to these procedures is the same as the clientData field specified to Tcl_CreateEncoding when the encoding was created. The remaining arguments to the callback procedures are the same as the arguments, documented at the top, to Tcl_ExternalToUtf or Tcl_UtfToExternal, with the following exceptions. If the srcLen argument to one of those high-level functions is negative, the value passed to the callback procedure will be the appropriate encoding-specific string length of src. If any of the srcReadPtr, dstWrotePtr, or dstCharsPtr arguments to one of the high-level functions is NULL, the corresponding value passed to the callback procedure will be a non-NULL location. The callback procedure freeProc, if non-NULL, should match the type Tcl_EncodingFreeProc: typedef void Tcl_EncodingFreeProc( ClientData clientData); This freeProc function is called when the encoding is deleted. The clientData parameter is the same as the clientData field specified to Tcl_CreateEncoding when the encoding was created. Tcl_GetEncodingSearchPath and Tcl_SetEncodingSearchPath are called to access and set the list of filesystem directories searched for encoding data files. The value returned by Tcl_GetEncodingSearchPath is the value stored by the last successful call to Tcl_SetEncodingSearchPath. If no calls to Tcl_SetEncodingSearchPath have occurred, Tcl will compute an initial value based on the environment. There is one encoding search path for the entire process, shared by all threads in the process. Tcl_SetEncodingSearchPath stores searchPath and returns TCL_OK, unless searchPath is not a valid Tcl list, which causes TCL_ERROR to be returned. ARGUMENTS

interp (in)
Intérprete de Tcl en el que se opera.
path (in)
Una cadena de texto que representa la nueva ruta de búsqueda de directorios de codificación. La cadena puede ser nula, en cuyo caso la ruta de búsqueda se establece en su valor predeterminado. Si la cadena es no nula, debe ser una lista de directorios separados por el carácter separador de ruta de la plataforma nativa (por ejemplo, ':' en Unix, ';' en Windows).

DESCRIPTION

El conjunto de directorios en los que Tcl busca archivos de datos de codificación se conoce como la *ruta de búsqueda de codificaciones*. La función Tcl_GetEncodingSearchPath devuelve la ruta de búsqueda de codificaciones actual como una cadena de texto. La cadena es una lista de directorios separados por el carácter separador de ruta de la plataforma nativa. Si se produce un error (por ejemplo, debido a una asignación de memoria insuficiente), la función devuelve una cadena nula y deja un mensaje de error en el intérprete especificado por interp.

La función Tcl_SetEncodingSearchPath establece la ruta de búsqueda de codificaciones. El argumento path especifica la nueva ruta de búsqueda. Si path es nulo, la ruta de búsqueda se restablece a su valor predeterminado, que es un único directorio especificado por Tcl_SetDefaultEncodingDir. De lo contrario, path debe ser una lista de directorios separados por el carácter separador de ruta de la plataforma nativa. La función devuelve 0 si se establece la ruta de búsqueda con éxito, o -1 si se produce un error (por ejemplo, debido a una asignación de memoria insuficiente). En caso de error, la función deja un mensaje de error en el intérprete especificado por interp.

El searchPath es una lista de directorios donde Tcl busca archivos de datos de codificación. Cuando se buscan los archivos de datos de codificación, los directorios del searchPath que no existen o no son legibles se ignoran silenciosamente.

Tcl_GetDefaultEncodingDir y Tcl_SetDefaultEncodingDir son interfaces obsoletas que se reemplazan mejor con llamadas a Tcl_GetEncodingSearchPath y Tcl_SetEncodingSearchPath. Se llaman para acceder y establecer el primer elemento de la lista searchPath. Dado que Tcl busca searchPath para archivos de datos de codificación en orden de lista, estas rutinas establecen el directorio "predeterminado" en el que se encuentran los archivos de datos de codificación.

ENCODING FILES

El espacio impediría la precompilación en Tcl de todos los algoritmos de codificación posibles, por lo que muchas codificaciones se almacenan en disco como archivos de codificación cargables dinámicamente. Este comportamiento también permite al usuario crear archivos de codificación adicionales que se pueden cargar utilizando el mismo mecanismo. Estos archivos de codificación contienen información sobre las tablas y/o secuencias de escape utilizadas para mapear entre una codificación externa y Unicode. La codificación externa puede consistir en caracteres de un solo byte, multibyte o doble byte.

Cada codificación cargable dinámicamente se representa como un archivo de texto. La línea inicial del archivo, que comienza con un símbolo "#", es un comentario que proporciona una descripción legible por humanos del archivo. La siguiente línea identifica el tipo de archivo de codificación. Puede ser una de las siguientes letras:

[1] S
Una codificación de un solo byte, donde un carácter siempre tiene un byte de longitud en la codificación. Un ejemplo es iso8859-1, utilizado por muchos idiomas europeos.
[2] D
Una codificación de doble byte, donde un carácter siempre tiene dos bytes de longitud en la codificación. Un ejemplo es big5, utilizado para texto chino.
[3] M
Una codificación multibyte, donde un carácter puede tener uno o dos bytes de longitud. Ciertos bytes son bytes iniciales, lo que indica que otro byte debe seguir y que juntos los dos bytes representan un carácter. Otros bytes no son bytes iniciales y se representan a sí mismos. Un ejemplo es shiftjis, utilizado por muchas computadoras japonesas.
[4] E
Una codificación de secuencia de escape, que especifica que ciertas secuencias de bytes no representan caracteres, sino comandos que describen cómo se deben interpretar los bytes siguientes.

El resto de las líneas del archivo dependen del tipo.

La tercera línea del archivo son tres números. El primer número es el carácter de relleno (en base 16) a utilizar al convertir de UTF-8 a esta codificación. El segundo número es un 1 si este archivo representa la codificación de una fuente de símbolos, o 0 en caso contrario. El último número (en base 10) es cuántas páginas de datos siguen.

Las líneas subsiguientes en el ejemplo anterior son páginas que describen cómo mapear desde la codificación a Unicode de 2 bytes. La primera línea de una página identifica el número de página. Le siguen 256 números de doble byte, dispuestos en 16 filas de 16 números. Dado un carácter en la codificación, el byte superior de ese carácter se utiliza para seleccionar la página, y el byte inferior de ese carácter se utiliza como índice para seleccionar uno de los números de doble byte en esa página, siendo el valor obtenido el carácter Unicode correspondiente. Por examen del ejemplo anterior, se puede ver que los caracteres 0x7E y 0x8163 en shiftjis se mapean a 203E y 2026 en Unicode, respectivamente.

Después de la primera página seguirán todas las demás páginas, cada una en el mismo formato que la primera: un número que identifica la página seguido de 256 caracteres Unicode de doble byte. Si un carácter en la codificación se mapea al carácter Unicode 0000, significa que el carácter no existe realmente. Si todos los caracteres de una página se mapean a 0000, esa página se puede omitir.

El caso [4] es el archivo de codificación de secuencia de escape. Las líneas de este tipo de archivo están en el mismo formato que este ejemplo tomado de la codificación iso2022-jp:

# Encoding file: iso2022-jp, escape-driven
E
init		{}
final		{}
iso8859-1	\x1b(B
jis0201		\x1b(J
jis0208		\x1b$@
jis0208		\x1b$B
jis0212		\x1b$(D
gb2312		\x1b$A
ksc5601		\x1b$(C

En el archivo, la primera columna representa una opción y la segunda columna es el valor asociado. init es una cadena para emitir o esperar antes de que se convierta el primer carácter, mientras que final es una cadena para emitir o esperar después del último carácter. Todas las demás opciones son nombres de codificaciones basadas en tablas; el valor asociado es la secuencia de escape que marca esa codificación. La sintaxis de Tcl se utiliza para los valores; en el ejemplo anterior, por ejemplo, "{}" representa la cadena vacía y "\x1b" representa el carácter 27.

Cuando Tcl_GetEncoding encuentra un nombre de codificación que no se ha cargado, intenta cargar un archivo de codificación llamado name.enc del subdirectorio encoding de cada directorio en el que Tcl busca su biblioteca de scripts. Si el archivo de codificación existe, pero está mal formado, se dejará un mensaje de error en interp.
