El nombre de un archivo local o de red.

Especifica cómo se debe acceder al archivo. Puede tener cualquiera de los valores permitidos para el argumento mode del comando Tcl open.

Indicadores de permisos de estilo POSIX, como 0644. Si se crea un archivo nuevo, estos permisos se establecerán en el archivo creado.

El número de elementos en argv.

Argumentos para construir una canalización de comandos. Estos valores tienen el mismo significado que los argumentos que no son de tipo switch para el comando Tcl exec.

Especifica la disposición de los manejadores stdio en la canalización: combinación OR de TCL_STDIN, TCL_STDOUT, TCL_STDERR y TCL_ENFORCE_MODE. Si no se establece TCL_ENFORCE_MODE, la tubería puede redirigir los manejadores stdio para anular los manejadores stdio para los que se han establecido TCL_STDIN, TCL_STDOUT y TCL_STDERR. Si está establecido, dichas redirecciones provocan un error.

DESCRIPCIÓN

El mecanismo de canales de Tcl proporciona un mecanismo independiente de dispositivos y de plataforma para realizar operaciones de entrada y salida con búfer en una variedad de tipos de archivos, sockets y dispositivos. El mecanismo de canales es extensible a nuevos tipos de canales, proporcionando un controlador de canal de bajo nivel para el nuevo tipo; la interfaz del controlador de canal se describe en la entrada del manual para Tcl_CreateChannel. El mecanismo de canales proporciona un esquema de almacenamiento en búfer modelado según la E/S estándar de Unix, y también permite E/S no bloqueantes en los canales.

Los procedimientos descritos en esta entrada del manual comprenden las APIs C de la capa genérica de la arquitectura de canales. Para una descripción de la arquitectura del controlador de canales y cómo implementar controladores de canales para nuevos tipos de canales, consulte la entrada del manual para Tcl_CreateChannel.

TCL_OPENFILECHANNEL

Tcl_OpenFileChannel abre un archivo especificado por fileName y devuelve un manejador de canal que se puede usar para realizar operaciones de entrada y salida en el archivo. Esta API está modelada siguiendo el procedimiento fopen de la biblioteca de E/S estándar de Unix. La sintaxis y el significado de todos los argumentos son similares a los dados en el comando open de Tcl al abrir un archivo. Si ocurre un error al abrir el canal, Tcl_OpenFileChannel devuelve NULL y registra un código de error POSIX que se puede recuperar con Tcl_GetErrno. Además, si interp no es NULL, Tcl_OpenFileChannel deja un mensaje de error en el resultado de interp después de cualquier error. A partir de Tcl 8.4, se debe preferir la API basada en valores Tcl_FSOpenFileChannel sobre Tcl_OpenFileChannel siempre que sea posible.

El canal recién creado no se registra en el intérprete suministrado; para registrarlo, use Tcl_RegisterChannel, descrito a continuación. Si uno de los canales estándar, stdin, stdout o stderr se cerró previamente, el acto de crear el nuevo canal también lo asigna como reemplazo del canal estándar.

TCL_OPENCOMMANDCHANNEL

Tcl_OpenCommandChannel proporciona una interfaz a nivel de C para las funciones de los comandos exec y open. Crea una secuencia de subprocesos especificados por los argumentos argv y argc y devuelve un canal que se puede utilizar para comunicarse con estos subprocesos. El argumento flags indica qué tipo de comunicación existirá con la tubería de comandos.

Si se establece la bandera TCL_STDIN, la entrada estándar del primer subproceso se vinculará al canal: escribir en el canal proporcionará entrada al subproceso. Si TCL_STDIN no está establecido, la entrada estándar del primer subproceso será la misma que la entrada estándar de esta aplicación. Si se establece TCL_STDOUT, la salida estándar del último subproceso se puede leer del canal; de lo contrario, irá a la salida estándar de esta aplicación. Si se establece TCL_STDERR, la salida de error estándar para todos los subprocesos se devuelve al canal y resulta en un error al cerrar el canal; de lo contrario, irá al error estándar de esta aplicación. Si no se establece TCL_ENFORCE_MODE, entonces argc y argv pueden redirigir los manejadores de stdio para anular TCL_STDIN, TCL_STDOUT y TCL_STDERR; si está establecido, entonces es un error que argc y argv anulen los canales stdio para los cuales se han establecido TCL_STDIN, TCL_STDOUT y TCL_STDERR.

Si ocurre un error al abrir el canal, Tcl_OpenCommandChannel devuelve NULL y registra un código de error POSIX que se puede recuperar con Tcl_GetErrno. Además, Tcl_OpenCommandChannel deja un mensaje de error en el resultado del intérprete. interp no puede ser NULL.

El canal recién creado no se registra en el intérprete suministrado; para registrarlo, use Tcl_RegisterChannel, descrito a continuación. Si uno de los canales estándar, stdin, stdout o stderr se cerró previamente, el acto de crear el nuevo canal también lo asigna como reemplazo del canal estándar.

TCL_MAKEFILECHANNEL

Tcl_MakeFileChannel crea un Tcl_Channel a partir de un manejador de archivo existente y específico de la plataforma. El canal recién creado no se registra en el intérprete suministrado; para registrarlo, use Tcl_RegisterChannel, descrito a continuación. Si uno de los canales estándar, stdin, stdout o stderr se cerró previamente, el acto de crear el nuevo canal también lo asigna como reemplazo del canal estándar.

TCL_GETCHANNEL

Tcl_GetChannel devuelve un canal dado el channelName utilizado para crearlo con Tcl_CreateChannel y un puntero a un intérprete de Tcl en interp. Si no se registra un canal con ese nombre en ese intérprete, el procedimiento devuelve NULL. Si el argumento modePtr no es NULL, apunta a una variable entera que recibirá una combinación OR de TCL_READABLE y TCL_WRITABLE que describe si el canal está abierto para lectura y escritura.

Tcl_GetChannelNames y Tcl_GetChannelNamesEx escriben los nombres de los canales registrados en el resultado del intérprete como un valor de lista. Tcl_GetChannelNamesEx filtrará estos nombres de acuerdo con el pattern. Si pattern es NULL, entonces no realizará ningún filtrado. El valor de retorno es TCL_OK si no ocurrieron errores al escribir en el resultado, de lo contrario es TCL_ERROR, y el mensaje de error se deja en el resultado del intérprete.

TCL_REGISTERCHANNEL

Tcl_RegisterChannel agrega un canal al conjunto de canales accesibles en interp. Después de esta llamada, los programas de Tcl que se ejecutan en ese intérprete pueden referirse al canal en operaciones de entrada o salida utilizando el nombre dado en la llamada a Tcl_CreateChannel. Después de esta llamada, el canal se convierte en propiedad del intérprete, y el llamador no debe llamar a Tcl_Close para el canal; el canal se cerrará automáticamente cuando se desregistre del intérprete.

El código que se ejecuta fuera de cualquier intérprete de Tcl puede llamar a Tcl_RegisterChannel con interp como NULL, para indicar que desea mantener una referencia a este canal. Posteriormente, el canal se puede registrar en un intérprete de Tcl y solo se cerrará cuando el número correspondiente de llamadas a Tcl_UnregisterChannel se hayan realizado. Esto permite que el código que se ejecuta fuera de cualquier intérprete mantenga de forma segura una referencia a un canal que también está registrado en un intérprete de Tcl.

Este procedimiento interactúa con el código que gestiona los canales estándar. Si no se inicializaron canales estándar antes de la primera llamada a Tcl_RegisterChannel, se inicializarán con esa llamada. Consulte Tcl_StandardChannels para obtener un tratado general sobre los canales estándar y el comportamiento de la biblioteca Tcl con respecto a ellos.

TCL_UNREGISTERCHANNEL

Tcl_UnregisterChannel elimina un canal del conjunto de canales accesibles en interp. Después de esta llamada, los programas de Tcl ya no podrán usar el nombre del canal para referirse al canal en ese intérprete. Si esta operación eliminó el último registro del canal en cualquier intérprete, el canal también se cierra y destruye.

El código no asociado con un intérprete de Tcl puede llamar a Tcl_UnregisterChannel con interp como NULL, para indicar a Tcl que ya no tiene una referencia a ese canal. Si esta es la última referencia al canal, se cerrará. Tcl_UnregisterChannel es muy similar a Tcl_DetachChannel, excepto que también cerrará el canal si no existen más referencias a él.

TCL_DETACHCHANNEL

Tcl_DetachChannel elimina un canal del conjunto de canales accesibles en interp. Después de esta llamada, los programas de Tcl ya no podrán usar el nombre del canal para referirse al canal en ese intérprete. Más allá de eso, este comando no tiene ningún otro efecto. No se puede usar en los canales estándar (stdout, stderr, stdin), y devolverá TCL_ERROR si se le pasa uno de esos canales.

El código no asociado con un intérprete de Tcl puede llamar a Tcl_DetachChannel con interp como NULL, para indicar a Tcl que ya no tiene una referencia a ese canal. Si esta es la última referencia al canal, a diferencia de Tcl_UnregisterChannel, no se cerrará.

TCL_ISSTANDARDCHANNEL

Tcl_IsStandardChannel comprueba si un canal es uno de los tres canales estándar, stdin, stdout o stderr. Si es así, devuelve 1, de lo contrario 0.

No se intenta comprobar si el canal dado o los canales estándar están inicializados o son válidos de alguna otra manera.

TCL_CLOSE

Tcl_Close destruye el canal channel, que debe denominar un canal actualmente abierto. El canal no debe estar registrado en ningún intérprete cuando se llama a Tcl_Close. La salida en búfer se descarga al dispositivo de salida del canal antes de destruir el canal, y cualquier entrada en búfer se descarta. Si este es un canal de bloqueo, la llamada no regresa hasta que todos los datos en búfer se envíen exitosamente al dispositivo de salida del canal. Si este es un canal sin bloqueo y hay salida en búfer que no se puede escribir sin bloquear, la llamada regresa inmediatamente; la salida se descarga en segundo plano y el canal se cerrará una vez que todos los datos en búfer se hayan emitido. En este caso, los errores durante la descarga no se informan.

Si el canal se cerró correctamente, Tcl_Close devuelve TCL_OK. Si ocurre un error, Tcl_Close devuelve TCL_ERROR y registra un código de error POSIX que se puede recuperar con Tcl_GetErrno. Si el canal se está cerrando de forma síncrona y ocurre un error durante el cierre del canal y interp no es NULL, se deja un mensaje de error en el resultado del intérprete.

Nota: no es seguro llamar a Tcl_Close en un canal que se ha registrado usando Tcl_RegisterChannel; consulte la documentación de Tcl_RegisterChannel, arriba, para obtener detalles. Si el canal se ha pasado alguna vez como el argumento chan en una llamada a Tcl_RegisterChannel, debe usar Tcl_UnregisterChannel, que llamará internamente a Tcl_Close cuando todas las llamadas a Tcl_RegisterChannel se hayan emparejado con las llamadas correspondientes a Tcl_UnregisterChannel.

TCL_READCHARS AND TCL_READ

Tcl_ReadChars consume bytes del channel, convirtiendo los bytes a UTF-8 basándose en la codificación del canal y almacenando los datos producidos en la representación de cadena de readObjPtr. El valor de retorno de Tcl_ReadChars es el número de caracteres, hasta charsToRead, que se almacenaron en readObjPtr. Si ocurre un error al leer, el valor de retorno es -1 y Tcl_ReadChars registra un código de error POSIX que se puede recuperar con Tcl_GetErrno.

TCL_READCHARS

Tcl_ReadChars lee hasta maxChars caracteres del objeto channel, y los almacena en la representación interna de readObjPtr. El valor de maxChars puede ser diferente de -1 para indicar la cantidad máxima de bytes a leer. Establecer Tcl_ReadChars a -1 hará que el comando lea todos los caracteres actualmente disponibles (no bloqueante) o todo hasta EOF (modo bloqueante).

El valor de retorno puede ser menor que el valor a leer, indicando que había menos datos de los solicitados disponibles. Esto se llama una lectura corta (short read). En modo bloqueante, esto solo puede suceder en un fin de archivo. En modo no bloqueante, una lectura corta puede ocurrir también si no hay suficiente entrada disponible actualmente: Tcl_ReadChars devuelve una cuenta corta en lugar de esperar más datos.

Si el canal está en modo bloqueante, un valor de retorno de cero indica una condición de fin de archivo. Si el canal está en modo no bloqueante, un valor de retorno de cero indica que no hay entrada disponible actualmente o una condición de fin de archivo. Utilice Tcl_Eof y Tcl_InputBlocked para saber cuál de estas condiciones ocurrió realmente.

Tcl_ReadChars traduce las diversas representaciones de fin de línea a la representación interna canónica \n según el modo de reconocimiento de fin de línea actual. El reconocimiento de fin de línea y los diversos modos específicos de plataforma se describen en la entrada del manual del comando Tcl fconfigure.

Como optimización de rendimiento, al leer de un canal con la codificación binary, los bytes no se convierten a UTF-8 mientras se leen. En su lugar, se almacenan en la representación interna de readObjPtr como un valor de array de bytes. La representación de cadena de este valor solo se construirá si es necesaria (por ejemplo, debido a una llamada a Tcl_GetStringFromObj). De esta manera, los datos orientados a bytes se pueden leer de un canal, manipularlos llamando a Tcl_GetByteArrayFromObj y funciones relacionadas, y luego escribirlos en un canal sin el costo de convertirlos a o desde UTF-8.

Tcl_Read es similar a Tcl_ReadChars, excepto que no realiza conversiones de codificación, independientemente de la codificación del canal. Está obsoleto y existe por compatibilidad hacia atrás con extensiones de Tcl no internacionalizadas. Consume bytes de channel y los almacena en readBuf, realizando traducciones de fin de línea en el camino. El valor de retorno de Tcl_Read es el número de bytes, hasta bytesToRead, escritos en readBuf. El búfer producido por Tcl_Read no está terminado en nulo. Su contenido es válido desde la posición cero hasta, y sin incluir, la posición indicada por el valor de retorno.

Tcl_ReadRaw es lo mismo que Tcl_Read pero no compensa el apilamiento. Mientras que Tcl_Read (y las otras funciones de la API) obtienen sus datos siempre del canal superior en la pila de la que forma parte el canal proporcionado, Tcl_ReadRaw no lo hace. Por lo tanto, esta función solo es utilizable para controladores de canal transformacionales, es decir, controladores utilizados en el medio de una pila de canales, para mover datos del canal inferior hacia la transformación.

TCL_GETSOBJ Y TCL_GETS

Tcl_GetsObj consume bytes del channel, convirtiendo los bytes a UTF-8 basándose en la codificación del canal, hasta que se haya visto una línea completa de entrada. Si la codificación del canal es binary, cada byte leído del canal se trata como un carácter Unicode individual. Todos los caracteres de la línea, excepto los caracteres de fin de línea terminales, se añaden a la representación de cadena de lineObjPtr. Los caracteres de fin de línea se leen y se descartan.

Si se leyó una línea correctamente, el valor de retorno es mayor o igual a cero e indica el número de bytes almacenados en lineObjPtr. Si ocurre un error, Tcl_GetsObj devuelve -1 y registra un código de error POSIX que se puede recuperar con Tcl_GetErrno. Tcl_GetsObj también devuelve -1 si se alcanza el fin del archivo; el procedimiento Tcl_Eof se puede utilizar para distinguir un error de una condición de fin de archivo.

Si el canal está en modo no bloqueante, el valor de retorno puede ser también -1 si no había datos disponibles o si los datos disponibles no contenían un carácter de fin de línea. Cuando se devuelve -1, el procedimiento Tcl_InputBlocked puede ser invocado para determinar si el canal está bloqueado debido a la falta de entrada.

Tcl_Gets es lo mismo que Tcl_GetsObj excepto que los caracteres resultantes se añaden a la cadena dinámica dada por lineRead en lugar de un valor Tcl.

TCL_UNGETS

Tcl_Ungets se utiliza para añadir datos a la cola de entrada de un canal, ya sea en la cabeza o en la cola de la cola. El puntero input apunta a los datos que se van a añadir. La longitud de la entrada a añadir viene dada por inputLen. Un valor distinto de cero de addAtEnd indica que los datos se añadirán al final de la cola; de lo contrario, se añadirán al principio de la cola. Si channel tiene un EOF "pegajoso" establecido, no se añadirán datos a la cola de entrada. Tcl_Ungets devuelve inputLen o -1 si ocurre un error.

TCL_WRITECHARS, TCL_WRITEOBJ, Y TCL_WRITE

Tcl_WriteChars acepta bytesToWrite bytes de datos de caracteres en charBuf. Los caracteres UTF-8 en el búfer se convierten a la codificación del canal y se ponen en cola para la salida a channel. Si bytesToWrite es negativo, Tcl_WriteChars espera que charBuf esté terminado en nulo y envía todo hasta el nulo.

Los datos puestos en cola para la salida pueden no aparecer en el dispositivo de salida inmediatamente, debido al almacenamiento en búfer interno. Si los datos deben aparecer inmediatamente, llame a Tcl_Flush después de la llamada a Tcl_WriteChars, o establezca la opción -buffering en el canal a none. Si desea que los datos aparezcan tan pronto como se acepte una línea completa para su salida, establezca la opción -buffering en el canal al modo line.

El valor de retorno de Tcl_WriteChars es un contador de cuántos bytes fueron aceptados para la salida al canal. Es mayor que cero para indicar éxito o -1 para indicar que ocurrió un error. Si ocurre un error, Tcl_WriteChars registra un código de error POSIX que puede ser recuperado con Tcl_GetErrno.

Los caracteres de nueva línea en los datos de salida se traducen a secuencias de fin de línea específicas de la plataforma según la opción -translation para el canal. Esto se hace incluso si el canal no tiene codificación.

Tcl_WriteObj es similar a Tcl_WriteChars excepto que acepta un valor Tcl cuyos contenidos se enviarán al canal. Los caracteres UTF-8 en la representación de cadena de writeObjPtr se convierten a la codificación del canal y se ponen en cola para la salida a channel. Como optimización de rendimiento, al escribir en un canal con la codificación binary, los caracteres UTF-8 no se convierten al escribirse. En su lugar, los bytes en la representación interna de writeObjPtr como un valor de array de bytes se escriben en el canal. La representación de array de bytes del valor se construirá si es necesaria. De esta manera, los datos orientados a bytes se pueden leer de un canal, manipularlos llamando a Tcl_GetByteArrayFromObj y funciones relacionadas, y luego escribirlos en un canal sin el costo de convertirlos a o desde UTF-8.

Tcl_Write es similar a Tcl_WriteChars excepto que no realiza conversiones de codificación, independientemente de la codificación del canal. Está obsoleto y existe por compatibilidad hacia atrás con extensiones de Tcl no internacionalizadas. Acepta bytesToWrite bytes de datos en byteBuf y los pone en cola para la salida a channel. Si bytesToWrite es negativo, Tcl_Write espera que byteBuf esté terminado en nulo y envía todo hasta el nulo.

Tcl_WriteRaw es lo mismo que Tcl_Write pero no compensa el apilamiento. Mientras que Tcl_Write (y las otras funciones de la API) alimentan sus entradas siempre al canal superior en la pila de la que forma parte el canal proporcionado, Tcl_WriteRaw no lo hace. Por lo tanto, esta función solo es utilizable para controladores de canal transformacionales, es decir, controladores utilizados en el medio de una pila de canales, para mover datos de la transformación al canal debajo de él.

TCL_FLUSH

Tcl_Flush hace que todos los datos de salida en búfer para channel se escriban en su archivo o dispositivo subyacente tan pronto como sea posible. Si el canal está en modo bloqueante, la llamada no retorna hasta que todos los datos en búfer hayan sido enviados al canal o haya ocurrido algún error. La llamada retorna inmediatamente si el canal no es bloqueante; inicia un vaciado en segundo plano que escribirá los datos en búfer al canal eventualmente, tan rápido como el canal pueda absorberlo.

El valor de retorno es normalmente TCL_OK. Si ocurre un error, Tcl_Flush retorna TCL_ERROR y registra un código de error POSIX que puede ser recuperado con Tcl_GetErrno.

TCL_SEEK

Tcl_Seek mueve el punto de acceso en channel donde se leerán o escribirán los datos posteriores. La salida en búfer se vacía al canal y la entrada en búfer se descarta, antes de la operación de búsqueda.

Tcl_Seek normalmente retorna el nuevo punto de acceso. Si ocurre un error, Tcl_Seek retorna -1 y registra un código de error POSIX que puede ser recuperado con Tcl_GetErrno. Después de un error, el punto de acceso puede o no haber sido movido.

TCL_TELL

Tcl_Tell retorna el punto de acceso actual para un canal. El valor retornado es -1 si el canal no soporta la búsqueda.

TCL_TRUNCATECHANNEL

Tcl_TruncateChannel trunca el archivo subyacente de channel a una longitud dada de length bytes. Retorna TCL_OK si la operación tuvo éxito, y TCL_ERROR en caso contrario.

TCL_GETCHANNELOPTION

Tcl_GetChannelOption recupera, en optionValue, el valor de una de las opciones actualmente en vigor para un canal, o una lista de todas las opciones y sus valores. El argumento channel identifica el canal para el que se consulta una opción o se recuperan todas las opciones y sus valores. Si optionName no es NULL, es el nombre de la opción a consultar; el valor de la opción se copia a la cadena dinámica Tcl denotada por optionValue. Si optionName es NULL, la función almacena una lista alternada de nombres de opciones y sus valores en optionValue.

>, usando una serie de llamadas a Tcl_DStringAppendElement. Las diversas opciones preexistentes y sus posibles valores se describen en la entrada del manual del comando fconfigure de Tcl. Cada tipo de canal puede agregar otras opciones. Estas opciones específicas del tipo de canal se describen en la entrada del manual del comando Tcl que crea un canal de ese tipo; por ejemplo, las opciones adicionales para canales basados en TCP se describen en la entrada del manual del comando socket de Tcl. El procedimiento normalmente devuelve TCL_OK. Si ocurre un error, devuelve TCL_ERROR y llama a Tcl_SetErrno para almacenar un código de error POSIX apropiado.

TCL_SETCHANNELOPTION

Tcl_SetChannelOption establece un nuevo valor newValue para una opción optionName en el channel. El procedimiento normalmente devuelve TCL_OK. Si ocurre un error, devuelve TCL_ERROR; además, si interp no es NULL, Tcl_SetChannelOption deja un mensaje de error en el resultado del intérprete.

TCL_EOF

Tcl_Eof devuelve un valor distinto de cero si el channel encontró un fin de archivo durante la última operación de entrada.

TCL_INPUTBLOCKED

Tcl_InputBlocked devuelve un valor distinto de cero si el channel está en modo no bloqueante y la última operación de entrada devolvió menos datos de los solicitados porque había datos insuficientes disponibles. La llamada siempre devuelve cero si el canal está en modo bloqueante.

TCL_INPUTBUFFERED

Tcl_InputBuffered devuelve el número de bytes de entrada actualmente en el búfer interno para un canal. Si el canal no está abierto para lectura, esta función siempre devuelve cero.

TCL_OUTPUTBUFFERED

Tcl_OutputBuffered devuelve el número de bytes de salida actualmente en el búfer interno para un canal. Si el canal no está abierto para escritura, esta función siempre devuelve cero.

PLATFORM ISSUES

Los manejadores devueltos por Tcl_GetChannelHandle dependen de la plataforma y del tipo de canal. En plataformas Unix, el manejador es siempre un descriptor de archivo Unix tal como lo devuelve la llamada al sistema open. En plataformas Windows, el manejador es un HANDLE de archivo cuando el canal se creó con Tcl_OpenFileChannel, Tcl_OpenCommandChannel, o Tcl_MakeFileChannel. Otros tipos de canal pueden devolver un tipo de manejador diferente en plataformas Windows.
