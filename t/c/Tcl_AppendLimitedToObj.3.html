ARGUMENTOS

const char *bytes (in)
Punta al primer byte de un arreglo de bytes UTF-8 usado para establecer o apendar a un valor de string. Este arreglo de bytes puede contener caracteres nulos embebidos, a menos que numChars sea negativo. (Aplicaciones que necesiten caracteres nulos deben representarlos como la secuencia de dos bytes \300\200, usar Tcl_ExternalToUtf para convertir, o Tcl_NewByteArrayObj si el string es una colección de bytes no interpretados.)

DESCRIPCIÓN

Los procedimientos descritos en este manual permiten manipular valores Tcl como valores de string. Usan la representación interna del valor para almacenar información adicional, lo que hace que las manipulaciones de string sean más eficientes. En particular, ellos optimizan las operaciones de apendice al allocar espacio adicional para el string, evitando copias para cada append. También, las operaciones de índice y longitud son optimizadas porque la representación de string en Unicode se calcula y caché según sea necesario. Cuando se utilizan los procedimientos Tcl_Append* de la familia de funciones del interprete, es importante llamar a Tcl_ResetResult primero para asegurarse de no apendar accidentalmente a los datos existentes en el valor de resultado.

Tcl_NewStringObj y Tcl_SetStringObj crean un nuevo valor o modifican un valor existente para almacenar una copia del string dado por bytes y length. Tcl_NewUnicodeObj y Tcl_SetUnicodeObj crean un nuevo valor o modifican un valor existente para almacenar una copia de la cadena Unicode dada por unicode y numChars. Tcl_NewStringObj y Tcl_NewUnicodeObj devuelven un puntero a un valor nuevo con reference count cero. Todos los cuatro procedimientos establecen el valor para almacenar una copia del string especificado. Tcl_SetStringObj y Tcl_SetUnicodeObj liberan cualquier representación anterior del string y la representación interna del valor.

Tcl_GetStringFromObj y Tcl_GetString devuelven la representación de string de un valor. Esta se da por el puntero de byte devuelto y (para Tcl_GetStringFromObj) la longitud, que se almacena en lengthPtr si no es NULL. Si la representación de string de UTF del valor es inválida (su puntero de byte es NULL), se regenera la representación de string a partir de la representación interna del valor. El puntero de byte devuelto por el Tcl_GetStringFromObj o Tcl_GetString es propiedad del gestor de valores. Se pasa de vuelta como un puntero de escritura para que los autores de Tcl_ObjType puedan modificar la representación de string dentro de Tcl_UpdateStringProc de su Tcl_ObjType. Excepto por ese propósito limitado, el puntero devuelto por Tcl_GetStringFromObj o Tcl_GetString debe tratarse como read-only. Se recomienda asignarlo a una variable (const char *) de tipo (const char *). Incluso en las situaciones limitadas donde escribir en este puntero es aceptable, uno debe tener cuidado de respetar las semánticas de copia en escritura requeridas por Tcl_Obj, con llamadas apropiadas a Tcl_IsShared y Tcl_DuplicateObj antes de cualquier modificación in situ de la representación de string. El procedimiento Tcl_GetString se usa en el caso común donde el llamador no necesita la longitud del string.

Tcl_GetUnicodeFromObj y Tcl_GetUnicode devuelven el valor de un valor como una cadena Unicode. Esta se da por el puntero devuelto y (para Tcl_GetUnicodeFromObj) la longitud, que se almacena en lengthPtr si no es NULL. El almacenamiento referido por el puntero de byte devuelto es propiedad del gestor de valores y no debe modificarse por el usuario. El procedimiento Tcl_GetUnicode se usa en el caso común donde el llamador no necesita la longitud de la representación de cadena Unicode.

Tcl_GetUniChar devuelve el index-ésimo carácter en la representación Unicode de un valor. Se asume que el índice está en el rango adecuado.

Tcl_GetRange devuelve un valor nuevo compuesto por los caracteres entre first y last (inclusos) en la representación Unicode de un valor. Si la representación Unicode del valor es inválida, la representación Unicode se regenera a partir de la representación de string del valor. Si first < 0, el string devuelto empieza en el principio del valor. Si last < 0, el string devuelto termina al final del valor.

Tcl_GetCharLength devuelve el número de caracteres Unicode en la representación Unicode de un valor. Si la representación Unicode del valor no se ha calculado todavía, se calcula a partir de la representación de string del valor.

Tcl_AppendToObj, Tcl_AppendUnicodeToObj, Tcl_AppendObjToObj, Tcl_AppendStringsToObj, Tcl_AppendStringsToObjVA y Tcl_AppendLimitedToObj apendan el string dado por bytes y length (o el string Unicode, o el valor, o una lista de strings) al final de la representación de string del valor apuntado por objPtr. Las operaciones de apendice se implementan de manera que los datos existentes en el valor de string se conservan. Si el valor ya tiene una representación de string y hay suficiente espacio adicional, los nuevos datos se copian al espacio adicional. De lo contrario, se asigna un nuevo bloque de memoria más grande y se copian los datos existentes y los nuevos datos. Después de la operación, el puntero de string puede ser inválido. Los procedimientos Tcl_AppendStringsToObj y Tcl_AppendStringsToObjVA son convenientes para apendar múltiples strings de C terminados en nulo. Tcl_AppendStringsToObj toma una lista de argumentos de string terminada en nulo. Tcl_AppendStringsToObjVA toma un argumento va_list que contiene una lista de argumentos de string terminada en nulo. Tcl_AppendLimitedToObj apenda hasta limit bytes del string bytes a objPtr. Si la operación de apendice resulta en truncamiento, el string ellipsis se apenda al final del string resultante. Si ellipsis es NULL, el string por defecto es “...”.

Tcl_Format, Tcl_AppendFormatToObj, Tcl_ObjPrintf y Tcl_AppendPrintfToObj permiten crear strings formateados. Tcl_Format genera un nuevo valor formateado usando la cadena de formato C format y los argumentos proporcionados en objc y objv. Tcl_AppendFormatToObj apenda un string formateado al valor existente apuntado por objPtr. Tcl_ObjPrintf crea un nuevo valor formateado usando la cadena de formato C format y argumentos de estilo printf. Tcl_AppendPrintfToObj apenda un string formateado al valor existente apuntado por objPtr. El formato de string y los argumentos deben ser consistentes con la especificación de printf estándar. Las extensiones de Tcl para printf (por ejemplo, %s para objetos Tcl) no están permitidas aquí.

Tcl_SetObjLength y Tcl_AttemptSetObjLength se usan para ajustar la longitud del string de un valor. Tcl_SetObjLength establece la longitud del string de un valor a newLength bytes. Si la longitud se reduce, la memoria se trunca. Si la longitud se incrementa, la memoria adicional se inicializa a cero. Tcl_AttemptSetObjLength es similar a Tcl_SetObjLength, pero intenta truncar la memoria solo si el string del valor no se comparte; si el string está compartido, devuelve FALSE y no modifica el valor. De lo contrario, devuelve TRUE. El nuevo tamaño del string es newLength bytes. Si newLength es mayor que el tamaño actual, la memoria adicional se inicializa a cero.

Tcl_ConcatObj crea y devuelve un nuevo valor que es la concatenación de los valores en el array objv. El número de elementos en objv es objc.

DESCRIPTION

These procedures manipulate the string representation of Tcl objects. Tcl objects can store values in different internal representations, including a string representation (a null-terminated array of bytes in UTF-8 encoding) and a Unicode representation (an array of 16-bit Unicode characters). Tcl may convert between these representations as needed. For example, the string length command uses the string representation, while the Tcl_UtfToUniChar function operates on the Unicode representation. The Tcl_ObjLength function returns the number of characters (as opposed to bytes) in the string value.

Tcl_AppendToObj appends the data given by bytes and length to the string representation of the value specified by objPtr. If the value has an invalid string representation, then an attempt is made to convert bytes to the Unicode format. If the conversion is successful, then the converted form of bytes is appended to the value's Unicode representation. Otherwise, the value's Unicode representation is invalidated and converted to the UTF format, and bytes is appended to the value's new string representation. Eventually buffer growth is done by large allocations to optimize multiple calls.

Tcl_AppendUnicodeToObj appends the Unicode string given by unicode and numChars to the value specified by objPtr. If the value has an invalid Unicode representation, then unicode is converted to the UTF format and appended to the value's string representation. Appends are optimized to handle repeated appends relatively efficiently (it over-allocates the string or Unicode space to avoid repeated reallocations and copies of value's string value).

Tcl_AppendObjToObj is similar to Tcl_AppendToObj, but it appends the string or Unicode value (whichever exists and is best suited to be appended to objPtr) of appendObjPtr to objPtr.

Tcl_AppendStringsToObj is similar to Tcl_AppendToObj except that it can be passed more than one value to append and each value must be a null-terminated string (i.e. none of the values may contain internal null characters). Any number of string arguments may be provided, but the last argument must be (char *)NULL to indicate the end of the list.

Tcl_AppendStringsToObjVA is the same as Tcl_AppendStringsToObj except that instead of taking a variable number of arguments it takes an argument list.

Tcl_AppendLimitedToObj is similar to Tcl_AppendToObj except that it imposes a limit on how many bytes are appended. This can be handy when the string to be appended might be very large, but the value being constructed should not be allowed to grow without bound. A common usage is when constructing an error message, where the end result should be kept short enough to be read. Bytes from bytes are appended to objPtr, but no more than limit bytes total are to be appended. If the limit prevents all length bytes that are available from being appended, then the appending is done so that the last bytes appended are from the string ellipsis. This allows for an indication of the truncation to be left in the string. When length is -1, all bytes up to the first zero byte are appended, subject to the limit. When ellipsis is NULL, the default string ... is used. When ellipsis is non-NULL, it must point to a zero-byte-terminated string in Tcl's internal UTF encoding. The number of bytes appended can be less than the lesser of length and limit when appending fewer bytes is necessary to append only whole multi-byte characters.

Tcl_Format is the C-level interface to the engine of the format command. The actual command procedure for format is little more than

Tcl_Format(interp, Tcl_GetString(objv[1]), objc-2, objv+2);

The objc Tcl_Obj values in objv are formatted into a string according to the conversion specification in format argument, following the documentation for the format command. The resulting formatted string is converted to a new Tcl_Obj with refcount of zero and returned. If some error happens during production of the formatted string, NULL is returned, and an error message is recorded in interp, if interp is non-NULL.

Tcl_AppendFormatToObj is an appending alternative form of Tcl_Format with functionality equivalent to:

Tcl_Obj *newPtr = Tcl_Format(interp, format, objc, objv);
if (newPtr == NULL) return TCL_ERROR;
Tcl_AppendObjToObj(objPtr, newPtr);
Tcl_DecrRefCount(newPtr);
return TCL_OK;

but with greater convenience and efficiency when the appending functionality is needed.

Tcl_ObjPrintf serves as a replacement for the common sequence

char buf[SOME_SUITABLE_LENGTH];
sprintf(buf, format, ...);
Tcl_NewStringObj(buf, -1);

but with greater convenience and no need to determine SOME_SUITABLE_LENGTH. The formatting is done with the same core formatting engine used by Tcl_Format. This means the set of supported conversion specifiers is that of the format command but the behavior is as similar as possible to sprintf. Format specifiers which were added by C99 (like "hh", "ll", "j", "z", "t", "L") are not supported. When a conversion specifier passed to Tcl_ObjPrintf includes a precision, the value is taken as a number of bytes, as sprintf does, and not as a number of characters, as format does. This is done on the assumption that C code is more likely to know how many bytes it is passing around than the number of encoded characters those bytes happen to represent. The variable number of arguments passed in should be of the types that would be suitable for passing to sprintf. Note in this example usage, x is of type int.

int x = 5;
Tcl_Obj *objPtr = Tcl_ObjPrintf("Value is %d", x);

If the value of format contains internal inconsistencies or invalid specifier formats, the formatted string result produced by Tcl_ObjPrintf will be an error message describing the error. It is impossible however to provide runtime protection against mismatches between the format and any subsequent arguments. Compile-time protection may be provided by some compilers.

Tcl_AppendPrintfToObj is an appending alternative form of Tcl_ObjPrintf with functionality equivalent to

Tcl_Obj *newPtr = Tcl_ObjPrintf(format, ...);
Tcl_AppendObjToObj(objPtr, newPtr);
Tcl_DecrRefCount(newPtr);

but with greater convenience and efficiency when the appending functionality is needed.

The Tcl_SetObjLength procedure changes the length of the string value of its objPtr argument. If the newLength argument is greater than the space allocated for the value's string, then the string space is reallocated and the old value is copied to the new space; the bytes between the old length of the string and the new length may have arbitrary values. If the newLength argument is less than the current length of the value's string, with objPtr->length is reduced without reallocating the string space; the original allocated size for the string is recorded in the value, so that the string length can be enlarged in a subsequent call to Tcl_SetObjLength without reallocating storage. In all cases Tcl_SetObjLength leaves a null character at objPtr->bytes[newLength].

Tcl_AttemptSetObjLength is identical in function to Tcl_SetObjLength except that if sufficient memory to satisfy the request cannot be allocated, it does not cause the Tcl interpreter to panic. Thus, if newLength is greater than the space allocated for the value's string, and there is not enough memory available to satisfy the request, Tcl_AttemptSetObjLength will take no action and return 0 to indicate failure. If there is enough memory to satisfy the request, Tcl_AttemptSetObjLength behaves just like Tcl_SetObjLength and returns 1 to indicate success.

The Tcl_ConcatObj function returns a new string value whose value is the space-separated concatenation of the string representations of all of the values in the objv array. Tcl_ConcatObj eliminates leading and trailing white space as it copies the string representations of the objv array to the result. If an element of the objv array consists of nothing but white space, then that value is ignored entirely. This white-space removal was added to make the output of the concat command cleaner-looking. Tcl_ConcatObj returns a pointer to a newly-created value whose ref count is zero.

Configuración de Arch Linux

Este documento describe los pasos necesarios para configurar un sistema Arch Linux. Se asume que ya ha instalado Arch Linux siguiendo la guía oficial.

Actualización del Sistema

Lo primero es asegurarse de que su sistema esté actualizado. Abra una terminal y ejecute: 

sudo pacman -Syu

Esto sincronizará los repositorios y actualizará todos los paquetes instalados.

Configuración de la Zona Horaria

Para configurar la zona horaria, primero liste las zonas horarias disponibles: 

ls /usr/share/zoneinfo

Una vez que encuentre su zona horaria (por ejemplo, `Europe/Madrid`), cree un enlace simbólico: 

sudo ln -sf /usr/share/zoneinfo/Europe/Madrid /etc/localtime

Luego, ejecute `sudo hwclock --systohc` para guardar la hora del sistema en el hardware.

Configuración Regional (Locale)

Edite el archivo `/etc/locale.gen` y descomente las líneas correspondientes a sus locales preferidos (por ejemplo, `en_US.UTF-8 UTF-8` y `es_ES.UTF-8 UTF-8`).

A continuación, genere los locales: 

sudo locale-gen

Cree el archivo `/etc/locale.conf` y establezca su variable `LANG`: 

LANG=es_ES.UTF-8

Configuración de la Red

Puede configurar la red utilizando `networkmanager` o `systemd-networkd`.

Para `networkmanager`: 

sudo pacman -S networkmanager
sudo systemctl enable NetworkManager.service

Para `systemd-networkd`: 

sudo pacman -S systemd-networkd
sudo systemctl enable systemd-networkd.service
sudo systemctl enable systemd-resolved.service

Consulte la Arch Wiki para obtener detalles sobre la configuración específica de su interfaz de red.

Configuración del Hostname

Cree el archivo `/etc/hostname` y escriba el nombre de host deseado en él.

Luego, edite `/etc/hosts` y agregue las siguientes líneas, reemplazando `mi-hostname` con su nombre de host: 

127.0.0.1   localhost
::1         localhost
127.0.1.1   mi-hostname.localdomain  mi-hostname

Instalación de Paquetes Esenciales

Es recomendable instalar algunos paquetes básicos como un editor de texto, herramientas de desarrollo y un navegador web. 

sudo pacman -S nano git base-devel firefox

Este es solo un ejemplo; puede instalar cualquier otro paquete especificado en el paquete correspondiente de Arch Linux.

Este documento es una guía básica y puede no cubrir todas las configuraciones especificadas en el paquete correspondiente de Arch Linux.
