Tcl_Main(3) Procedimientos de la biblioteca Tcl Tcl_Main(3)

NOMBRE

Tcl_Main, Tcl_MainEx, Tcl_MainExW, Tcl_SetStartupScript, Tcl_GetStartupScript, Tcl_SetMainLoop - programa principal, script de inicio y definición del bucle de eventos para aplicaciones basadas en Tcl

SINOPSIS

#include <tcl.h>

Tcl_Main(argc, argv, appInitProc)

Tcl_MainEx(argc, charargv, appInitProc, interp)

Tcl_MainExW(argc, wideargv, appInitProc, interp)

Tcl_SetStartupScript(path, encoding)

Tcl_Obj *
Tcl_GetStartupScript(encodingPtr)

Tcl_SetMainLoop(mainLoopProc)

ARGUMENTOS

int argc (entrada)
Número de elementos en argv.
char *argv[] (entrada)
Matriz de cadenas que contienen los argumentos de la línea de comandos. En Windows, cuando se utiliza -DUNICODE, el tipo del parámetro cambia a wchar_t *.
char *charargv[] (entrada)
Como argv, pero no cambia el tipo a wchar_t.
char *wideargv[] (entrada)
Como argv, pero el tipo es siempre wchar_t.
Tcl_AppInitProc *appInitProc (entrada)
Dirección de un procedimiento de inicialización específico de la aplicación. El valor para este argumento suele ser Tcl_AppInit.
Tcl_Obj *path (entrada)
Nombre del archivo a utilizar como script de inicio, o NULL.
const char *encoding (entrada)
Codificación del archivo a utilizar como script de inicio, o NULL.
const char **encodingPtr (salida)
Si no es NULL, la ubicación para escribir una copia del puntero (const char *) que apunta al nombre de la codificación.
Tcl_MainLoopProc *mainLoopProc (entrada)
Dirección de un procedimiento de bucle de eventos específico de la aplicación.
Tcl_Interp *interp (entrada)
Intérprete Tcl ya creado.

DESCRIPCIÓN

Tcl_Main puede servir como programa principal para aplicaciones de shell basadas en Tcl. Una «aplicación de shell» es un programa como tclsh o wish que admite tanto la interpretación interactiva de Tcl como la evaluación de un script contenido en un archivo dado como argumento de línea de comandos. Tcl_Main se ofrece como una conveniencia para los desarrolladores de aplicaciones de shell, para que no tengan que reproducir todo el código necesario para la inicialización adecuada de la biblioteca Tcl y la operación del shell interactivo. Otros estilos de incrustar Tcl en una aplicación no son compatibles con Tcl_Main. Estos deben lograrse llamando directamente a funciones de nivel inferior de la biblioteca Tcl.

La función Tcl_Main ha sido ofrecida por la biblioteca Tcl desde la versión Tcl 7.4. En versiones anteriores de Tcl, la propia biblioteca Tcl definía una función main, pero esa carecía de flexibilidad en el estilo de incrustación y tener una función main en una biblioteca (particularmente una biblioteca compartida) causa problemas en muchos sistemas. Tener main en la biblioteca Tcl también haría difícil usar Tcl en programas C++, ya que los programas C++ deben tener funciones main específicas de C++.

Normalmente, cada aplicación de shell contiene una pequeña función main que no hace nada más que invocar Tcl_Main. Tcl_Main realiza entonces todo el trabajo de crear y ejecutar una aplicación similar a tclsh.

Tcl_Main no es proporcionado por la interfaz pública de la biblioteca de stubs de Tcl. Los programas que llaman a Tcl_Main deben enlazarse contra la biblioteca Tcl estándar. Las extensiones (con stubs habilitados o no) no están destinadas a llamar a Tcl_Main.

Tcl_Main no es seguro para hilos. Solo debe ser llamado por un único hilo principal de una aplicación multihilo. Esta restricción no es un problema con el uso normal descrito anteriormente.

Tcl_Main y, por lo tanto, todas las aplicaciones basadas en él, como tclsh, utilizan Tcl_GetStdChannel para inicializar los canales estándar a sus valores predeterminados. Consulte Tcl_StandardChannels para obtener más información.

Tcl_Main admite dos modos de operación, dependiendo de si el nombre del archivo y la codificación de un script de inicio se han establecido. Las rutinas Tcl_SetStartupScript y Tcl_GetStartupScript son las herramientas para controlar esta configuración de Tcl_Main.

Tcl_SetStartupScript registra el valor path como el nombre del archivo que Tcl_Main evaluará como su script de inicio. El valor encoding es el nombre de Tcl para la codificación utilizada para almacenar el texto en ese archivo. Un valor de NULL para encoding es una señal para usar la codificación del sistema. Un valor de NULL para path borra cualquier registro existente para que Tcl_Main no evalúe ningún script de inicio.

Tcl_GetStartupScript consulta el nombre del archivo y la codificación registrados establecidos por la llamada más reciente a Tcl_SetStartupScript en el mismo hilo. Se devuelve el nombre del archivo almacenado, y el nombre de la codificación almacenado se escribe en el espacio apuntado por encodingPtr, cuando este no es NULL.

Los valores del nombre del archivo y la codificación gestionados por las rutinas Tcl_SetStartupScript y Tcl_GetStartupScript se almacenan por hilo. Aunque las funciones de almacenamiento y recuperación de estas rutinas funcionan en cualquier hilo, solo aquellas llamadas en el mismo hilo principal que Tcl_Main pueden tener alguna influencia sobre él.

El llamador de Tcl_Main puede llamar primero a Tcl_SetStartupScript para establecer su script de inicio deseado. Si Tcl_Main descubre que no se ha establecido ningún script de inicio, consulta los primeros argumentos en argv. Si coinciden con ?-encoding name? fileName, donde fileName no empieza por el carácter -, entonces fileName se toma como el nombre de un archivo que contiene un script de inicio, y name se toma como el nombre de la codificación del contenido de ese archivo. Tcl_Main llama entonces a Tcl_SetStartupScript con estos valores.

Tcl_Main define entonces en su intérprete principal las variables Tcl argc, argv, argv0 y tcl_interactive, como se describe en la documentación de tclsh.

Cuando ha terminado su propia inicialización, pero antes de procesar comandos, Tcl_Main llama al procedimiento proporcionado por el argumento appInitProc. Este procedimiento proporciona un «gancho» para que la aplicación realice su propia inicialización del intérprete creado por Tcl_Main, como definir comandos específicos de la aplicación. La rutina de inicialización de la aplicación también podría llamar a Tcl_SetStartupScript para (re)establecer el archivo y la codificación que se utilizarán como script de inicio. El procedimiento debe tener una interfaz que coincida con el tipo Tcl_AppInitProc:

typedef int Tcl_AppInitProc(
        Tcl_Interp *interp);

AppInitProc es casi siempre un puntero a Tcl_AppInit; para más detalles sobre este procedimiento, consulte la documentación de Tcl_AppInit.

Cuando el appInitProc termina, Tcl_Main llama a Tcl_GetStartupScript para determinar qué script de inicio se ha solicitado, si lo hay. Si se ha proporcionado un script de inicio, Tcl_Main intenta evaluarlo. De lo contrario, el modo interactivo comienza con el examen de la variable tcl_rcFileName en el intérprete principal. Si esa variable existe y contiene el nombre de un archivo legible, el contenido de ese archivo se evalúa en el intérprete principal. Luego comienzan las operaciones interactivas, con indicaciones y resultados de evaluación de comandos escritos en el canal de salida estándar, y comandos leídos del canal de entrada estándar y luego evaluados. Las indicaciones escritas en el canal de salida estándar pueden personalizarse definiendo las variables Tcl tcl_prompt1 y tcl_prompt2 como se describe en la documentación de tclsh. Las indicaciones y los resultados de la evaluación de comandos se escriben en el canal de salida estándar solo si la variable Tcl tcl_interactive en el intérprete principal contiene un valor entero distinto de cero.

Tcl_SetMainLoop permite establecer un procedimiento de bucle de eventos para que se ejecute. Esto permite, por ejemplo, que Tk se cargue dinámicamente y establezca su bucle de eventos. El bucle de eventos se ejecutará después del script de inicio. Si está en modo interactivo, establecer el procedimiento de bucle principal hará que la indicación se base en fileevent y luego se llame al procedimiento del bucle. Cuando el procedimiento del bucle regrese en modo interactivo, la operación interactiva continuará. El procedimiento del bucle principal debe tener una interfaz que coincida con el tipo Tcl_MainLoopProc:

typedef void Tcl_MainLoopProc(void);

Tcl_Main no devuelve. Normalmente, un programa basado en Tcl_Main terminará cuando se evalúe el comando exit. En modo interactivo, si se encuentra un EOF o un error de canal en el canal de entrada estándar, entonces Tcl_Main mismo evaluará el comando exit.

Tcl_GetStartupScript(3)

NAME

Tcl_GetStartupScript - get the startup script for Tcl applications

SYNOPSIS

#include <tcl.h>

const char *
Tcl_GetStartupScript(interp, argcPtr, argvPtr);

ARGUMENTS

interp (in)
Interpreter to use for evaluating the startup script.
argcPtr (in)
Pointer to the number of command-line arguments.
argvPtr (in)
Pointer to the array of command-line arguments.

DESCRIPTION

The Tcl_GetStartupScript function is used by tclsh and wish to determine the script to evaluate when the application starts up. The function looks for a script in the following locations, in order:

  1. A file specified by the TCLLIBPATH environment variable.
  2. The user's Tcl initialization file (~/.tclshrc or ~/.wishrc).
  3. The application-specific initialization file specified by the TCL_APP_INIT_FILE environment variable.

If a script is found, its name is returned as a string. The caller is responsible for evaluating the script. If no script is found, the function returns NULL.

The argcPtr and argvPtr arguments are used to pass the command-line arguments to the function. This allows the function to determine if a script was specified on the command line.

In non-interactive mode, after Tcl_Main evaluates the startup script, and the main loop procedure (if any) returns, Tcl_Main will also evaluate the exit command.
