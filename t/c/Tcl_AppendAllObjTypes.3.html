Tcl_ObjType(3) Procedimientos de la biblioteca Tcl Tcl_ObjType(3)

NOMBRE

Tcl_RegisterObjType, Tcl_GetObjType, Tcl_AppendAllObjTypes, Tcl_ConvertToType - manipular tipos de valores Tcl

SINOPSIS

#include <tcl.h>

Tcl_RegisterObjType(typePtr)

const Tcl_ObjType *
Tcl_GetObjType(typeName)

int
Tcl_AppendAllObjTypes(interp, objPtr)

int
Tcl_ConvertToType(interp, objPtr, typePtr)

ARGUMENTOS

const Tcl_ObjType *typePtr (entrada)
Punta a la estructura que contiene información sobre el tipo de valor Tcl. Este almacenamiento debe vivir para siempre, típicamente siendo asignado estáticamente.
const char *typeName (entrada)
El nombre de un tipo de valor Tcl que Tcl_GetObjType debería buscar.
Tcl_Interp *interp (entrada)
Intérprete a utilizar para la notificación de errores.
Tcl_Obj *objPtr (entrada)
Para Tcl_AppendAllObjTypes, esto apunta al valor al que se anexa el nombre de cada tipo de valor como un elemento de lista. Para Tcl_ConvertToType, esto apunta a un valor que debe haber sido el resultado de una llamada anterior a Tcl_NewObj.

DESCRIPCIÓN

Los procedimientos en esta página del manual gestionan los tipos de valores Tcl (a veces denominados tipos de objetos o Tcl_ObjTypes por razones históricas). Se utilizan para registrar nuevos tipos de valores, buscar tipos y forzar conversiones de un tipo a otro.

Tcl_RegisterObjType registra un nuevo tipo de valor Tcl en la tabla de todos los tipos de valores que Tcl_GetObjType puede buscar por nombre. Hay otros tipos de valores compatibles con Tcl, que Tcl elige no registrar. Las extensiones también pueden optar por registrar los tipos de valores que crean o no. El argumento typePtr apunta a una estructura Tcl_ObjType que describe el nuevo tipo, proporcionando su nombre y punteros a cuatro procedimientos que implementan el tipo. Si la tabla de tipos ya contiene un tipo con el mismo nombre que en typePtr, se reemplaza con el nuevo tipo. La estructura Tcl_ObjType se describe en la sección LA ESTRUCTURA TCL_OBJTYPE más abajo.

Tcl_GetObjType devuelve un puntero al Tcl_ObjType registrado con el nombre typeName. Devuelve NULL si no hay ningún tipo con ese nombre registrado.

Tcl_AppendAllObjTypes anexa el nombre de cada tipo de valor registrado como un elemento de lista al valor Tcl referenciado por objPtr. El valor de retorno es TCL_OK a menos que haya habido un error al convertir objPtr a un valor de lista; en ese caso, se devuelve TCL_ERROR.

Tcl_ConvertToType convierte un valor de un tipo a otro si es posible. Crea una nueva representación interna para objPtr adecuada para el tipo de destino typePtr y establece su miembro typePtr según lo determinado por la llamada a la rutina typePtr->setFromAnyProc. Cualquier representación interna del tipo antiguo de objPtr se libera. Si ocurre un error durante la conversión, devuelve TCL_ERROR y deja un mensaje de error en el valor de resultado para interp a menos que interp sea NULL. De lo contrario, devuelve TCL_OK. Pasar un interp NULL permite que este procedimiento se utilice como una prueba para ver si la conversión se puede realizar (y de hecho se realizó).

En muchos casos, la rutina typePtr->setFromAnyProc establecerá objPtr->typePtr al valor del argumento typePtr, pero eso ya no está garantizado. El setFromAnyProc es libre de establecer la representación interna de objPtr para aprovechar otro Tcl_ObjType relacionado, si lo considera oportuno.

LA ESTRUCTURA TCL_OBJTYPE

Los escritores de extensiones pueden definir nuevos tipos de valores definiendo cuatro procedimientos e inicializando una estructura Tcl_ObjType para describir el tipo. Los escritores de extensiones también pueden pasar un puntero a su estructura Tcl_ObjType a Tcl_RegisterObjType si desean permitir que otras extensiones busquen su Tcl_ObjType por nombre con la rutina Tcl_GetObjType. La estructura Tcl_ObjType se define como sigue:

typedef struct Tcl_ObjType {
    const char *name;
    Tcl_FreeInternalRepProc *freeIntRepProc;
    Tcl_DupInternalRepProc *dupIntRepProc;
    Tcl_UpdateStringProc *updateStringProc;
    Tcl_SetFromAnyProc *setFromAnyProc;
} Tcl_ObjType;

EL CAMPO NOMBRE

El miembro name describe el nombre del tipo, por ejemplo, int. Cuando se registra un tipo, este es el nombre que los llamadores de Tcl_GetObjType utilizan para buscar el tipo. Para los tipos no registrados, el campo name es principalmente valioso para la depuración. Los cuatro miembros restantes son punteros a procedimientos llamados por el código genérico de valores de Tcl:

EL CAMPO SETFROMANYPROC

El miembro setFromAnyProc contiene la dirección de una función llamada para crear una representación interna válida a partir de la representación en cadena de un valor.

typedef int Tcl_SetFromAnyProc(
        Tcl_Interp *interp,
        Tcl_Obj *objPtr);

Si no se puede crear una representación interna a partir de la cadena, devuelve TCL_ERROR y coloca un mensaje que describe el error en el valor de resultado para interp a menos que interp sea NULL. Si setFromAnyProc tiene éxito, almacena la nueva representación interna, establece el miembro typePtr de objPtr para que apunte a la estructura Tcl_ObjType correspondiente a la nueva representación interna y devuelve TCL_OK. Antes de establecer la nueva representación interna, el setFromAnyProc debe liberar cualquier representación interna del tipo antiguo de objPtr; lo hace llamando al freeIntRepProc del tipo antiguo si no es NULL.

Como ejemplo, el setFromAnyProc para el tipo de lista Tcl integrado obtiene una representación de cadena actualizada para objPtr llamando a Tcl_GetStringFromObj. Analiza la cadena para verificar que está en un formato de lista válido y para obtener cada valor de elemento en la lista, y, si esto tiene éxito, almacena los elementos de la lista en la representación interna de objPtr y establece el miembro typePtr de objPtr para que apunte a la estructura Tcl_ObjType del tipo de lista.

No libere la representación interna antigua de objPtr a menos que la reemplace con una nueva o restablezca el miembro typePtr a NULL.

El miembro setFromAnyProc puede establecerse a NULL, si las rutinas que utilizan la representación interna no necesitan derivar esa representación interna de una cadena de valor arbitraria. Sin embargo, en este caso, pasar un puntero al tipo a Tcl_ConvertToType provocará un pánico, por lo que para evitar esta posibilidad, el tipo no debe ser registrado.

EL CAMPO UPDATESTRINGPROC

El miembro updateStringProc contiene la dirección de una función llamada para crear una representación de cadena válida a partir de la representación interna de un valor.

typedef void Tcl_UpdateStringProc(
        Tcl_Obj *objPtr);

El miembro bytes de objPtr siempre es NULL cuando se llama. Siempre debe establecer bytes en no NULL antes de devolver. Requerimos que el array de bytes de la representación de cadena tenga un nulo después del último byte, en el desplazamiento length, y que no tenga bytes nulos antes de eso; esto permite que las representaciones de cadena se traten como cadenas C convencionales terminadas en nulo. Estas restricciones se cumplen fácilmente utilizando la codificación interna UTF de Tcl para la representación de cadena, igual que se haría para otras rutinas Tcl que aceptan valores de cadena como argumentos. El almacenamiento para el array de bytes debe ser asignado en el heap por Tcl_Alloc o ckalloc. Tenga en cuenta que los updateStringProc deben asignar suficiente almacenamiento para los bytes de la cadena y el byte nulo terminador.

El updateStringProc para el tipo double integrado de Tcl, por ejemplo, llama a Tcl_PrintDouble para escribir en un buffer de tamaño TCL_DOUBLE_SPACE, luego asigna y copia la representación de cadena a espacio suficiente para contenerla. Se almacena un puntero al espacio asignado en el miembro bytes.

El miembro updateStringProc puede establecerse a NULL, si las rutinas que utilizan la representación interna están escritas de manera que la representación de cadena nunca se invalida. Fallo

EL CAMPO DUPINTREPPROC

El miembro dupIntRepProc contiene la dirección de una función que se llama para copiar una representación interna de un valor a otro.

typedef void Tcl_DupInternalRepProc(
        Tcl_Obj *srcPtr,
        Tcl_Obj *dupPtr);

La representación interna de dupPtr se convierte en una copia de la representación interna de srcPtr. Antes de la llamada, la representación interna de srcPtr es válida y la de dupPtr no lo es. El tipo de valor de srcPtr determina qué significa copiar su representación interna.

Por ejemplo, el dupIntRepProc para el tipo entero de Tcl simplemente copia un entero. El dupIntRepProc del tipo de lista incorporado utiliza un esquema mucho más sofisticado para continuar compartiendo almacenamiento tanto como sea razonablemente posible.

EL CAMPO FREEINTREPPROC

El miembro freeIntRepProc contiene la dirección de una función que se llama cuando se libera un valor.

typedef void Tcl_FreeInternalRepProc(
        Tcl_Obj *objPtr);

La función freeIntRepProc puede desasignar el almacenamiento para la representación interna del valor y realizar otros procesamientos específicos del tipo necesarios cuando se libera un valor.

Por ejemplo, el freeIntRepProc del tipo de lista respeta el esquema de compartición de almacenamiento establecido por el dupIntRepProc para que solo libere almacenamiento cuando se esté liberando el último valor que lo comparte.

El miembro freeIntRepProc se puede establecer en NULL para indicar que la representación interna no requiere ser liberada. La implementación de freeIntRepProc no debe acceder al miembro bytes del valor, ya que Tcl hace sus propios usos internos de ese campo durante la eliminación del valor. Las tareas definidas para freeIntRepProc no necesitan consultar el miembro bytes.
