Tcl_SplitPath(3) Procedimientos de la biblioteca Tcl Tcl_SplitPath(3)

NOMBRE

Tcl_SplitPath, Tcl_JoinPath, Tcl_GetPathType - manipular rutas de archivos dependientes de la plataforma

SINOPSIS

#include <tcl.h>

Tcl_SplitPath(path, argcPtr, argvPtr)

char *
Tcl_JoinPath(argc, argv, resultPtr)

Tcl_PathType
Tcl_GetPathType(path)

ARGUMENTOS

const char *path (in)
Ruta de archivo en un formato apropiado para la plataforma actual (consulte la entrada del manual filename para ver formas aceptables para nombres de ruta).
int *argcPtr (out)
Se rellena con el número de elementos de ruta en path.
const char ***argvPtr (out)
*argvPtr se rellenará con la dirección de una matriz de punteros a las cadenas que son los elementos extraídos de path. Habrá *argcPtr entradas válidas en la matriz, seguidas de una entrada NULL.
int argc (in)
Número de elementos en argv.
const char *const *argv (in)
Matriz de elementos de ruta para unir en una única ruta.
Tcl_DString *resultPtr (in/out)
Un puntero a un Tcl_DString inicializado al que se añadirá el resultado de Tcl_JoinPath.

DESCRIPCIÓN

Estos procedimientos han sido sustituidos por los procedimientos conscientes de valores Tcl en la página del manual FileSystem, que son más eficientes.

Estos procedimientos pueden utilizarse para desmontar y volver a montar rutas de archivos de forma independiente de la plataforma: proporcionan acceso a nivel de C a la misma funcionalidad que los comandos file split, file join y file pathtype.

Tcl_SplitPath descompone una ruta en sus elementos constituyentes, devolviendo una matriz de punteros a los elementos utilizando argcPtr y argvPtr. El área de memoria apuntada por *argvPtr se asigna dinámicamente; además de la matriz de punteros, también contiene copias de todos los elementos de la ruta. Es responsabilidad del llamante liberar todo este almacenamiento. Por ejemplo, supongamos que ha llamado a Tcl_SplitPath con el siguiente código:

int argc;
char *path;
char **argv;
...
Tcl_SplitPath(string, &argc, &argv);

Entonces, eventualmente debería liberar el almacenamiento con una llamada como la siguiente:

Tcl_Free((char *) argv);

Tcl_JoinPath es el inverso de Tcl_SplitPath: toma una colección de elementos de ruta dados por argc y argv y genera una cadena de resultado que es una ruta construida correctamente. La cadena de resultado se añade a resultPtr. ResultPtr debe hacer referencia a un Tcl_DString inicializado.

Si el resultado de Tcl_SplitPath se pasa a Tcl_JoinPath, el resultado hará referencia a la misma ubicación, pero puede que no esté en el mismo formato. Esto se debe a que Tcl_SplitPath y Tcl_JoinPath eliminan los separadores de ruta duplicados y devuelven una forma normalizada para cada plataforma.

Tcl_GetPathType devuelve el tipo de la ruta especificada path, donde Tcl_PathType es uno de TCL_PATH_ABSOLUTE, TCL_PATH_RELATIVE, o TCL_PATH_VOLUME_RELATIVE. Consulte la entrada del manual filename para ver una descripción de los tipos de ruta para cada plataforma.
