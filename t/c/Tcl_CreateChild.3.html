DESCRIPCIÓN

Estos procedimientos están destinados al acceso a las instalaciones de múltiples intérpretes desde dentro de programas C. Permiten gestionar múltiples intérpretes en una relación jerárquica y la gestión de alias, comandos que al ser invocados en un intérprete ejecutan un comando en otro intérprete. El valor de retorno para aquellos procedimientos que devuelven un int es TCL_OK o TCL_ERROR. Si se devuelve TCL_ERROR, el resultado del intérprete contiene un mensaje de error.

Tcl_CreateSlave crea un nuevo intérprete como hijo de interp. También crea un comando hijo llamado childName en interp que permite a interp manipular al nuevo hijo. Si isSafe es cero, el comando crea un hijo confiable en el que el código Tcl tiene acceso a todos los comandos Tcl. Si es 1, el comando crea un hijo “seguro” en el que el código Tcl solo tiene acceso a un conjunto de comandos Tcl definidos como “Safe Tcl”; ver la entrada del manual para el comando interp de Tcl para más detalles. Si la creación del nuevo intérprete hijo falló, se devuelve NULL.

Tcl_CreateChild es un sinónimo de Tcl_CreateSlave.

Tcl_IsSafe devuelve 1 si interp es “seguro” (fue creado con el indicador TCL_SAFE_INTERPRETER especificado), 0 en caso contrario.

Tcl_MakeSafe marca interp como “seguro”, de modo que las llamadas futuras a Tcl_IsSafe devuelvan 1. También elimina toda la funcionalidad central potencialmente insegura conocida (tanto comandos como variables) de interp. Sin embargo, no puede conocer qué partes de una extensión o aplicación son seguras y no intenta eliminar esas partes, por lo que la seguridad no está garantizada después de llamar a Tcl_MakeSafe. Los llamadores querrán tener cuidado con su uso de Tcl_MakeSafe para evitar falsas afirmaciones de seguridad. Para muchas situaciones, Tcl_CreateSlave puede ser una mejor opción, ya que crea intérpretes en un estado conocido como seguro.

Tcl_GetSlave devuelve un puntero a un intérprete hijo de interp. El intérprete hijo se identifica por childName. Si no existe tal intérprete hijo, se devuelve NULL.

Tcl_GetChild es un sinónimo de Tcl_GetSlave.

Tcl_GetMaster devuelve un puntero al intérprete maestro de interp. Si interp no tiene maestro (es un intérprete de nivel superior), se devuelve NULL.

Tcl_GetParent es un sinónimo de Tcl_GetMaster.

Tcl_GetInterpPath almacena en el resultado de interp la ruta relativa entre interp y childInterp; childInterp debe ser un hijo de interp. Si el cálculo de la ruta relativa tiene éxito, se devuelve TCL_OK, de lo contrario se devuelve TCL_ERROR y se almacena un mensaje de error como resultado de interp.

Tcl_CreateAlias crea un comando llamado childCmd en childInterp que, cuando se invoca, provocará que el comando targetCmd se invoque en targetInterp. Los argumentos especificados por las cadenas contenidas en argv se anteponen siempre a cualquier argumento proporcionado en la invocación de childCmd y se pasan a targetCmd. Esta operación devuelve TCL_OK si tiene éxito, o TCL_ERROR si falla; en ese caso, se deja un mensaje de error en el resultado de valor de childInterp. Tenga en cuenta que no hay restricciones en la relación de ascendencia (tal como se crea por Tcl_CreateSlave) entre childInterp y targetInterp. Se pueden usar dos intérpretes cualesquiera, sin restricciones sobre cómo están relacionados.

Tcl_CreateAliasObj es similar a Tcl_CreateAlias excepto que toma un vector de valores para pasar como argumentos adicionales en lugar de un vector de cadenas.

Tcl_GetAliasObj devuelve información en forma de un puntero a un vector de estructuras Tcl_Obj sobre un alias aliasName en interp. Cualquiera de los campos de resultado puede ser NULL, en cuyo caso el dato correspondiente no se devuelve. Si un campo de resultado no es NULL, la dirección indicada se establece en el dato correspondiente. Por ejemplo, si targetCmdPtr no es NULL, se establece en un puntero a la cadena que contiene el nombre del comando de destino.

Tcl_GetAlias es similar a Tcl_GetAliasObj excepto que devuelve un puntero a un vector de cadenas en lugar de un vector de estructuras Tcl_Obj. Tcl_GetAlias está obsoleto.

Tcl_ExposeCommand permite que un comando oculto sea visible en interp bajo el nombre cmdName. El comando originalmente oculto se puede invocar usando hiddenCmdName. Si el comando no existe, o si cmdName ya está en uso, se devolverá TCL_ERROR.

Tcl_HideCommand hace que el comando llamado cmdName en interp sea invisible para la invocación directa. Si se proporciona hiddenCmdName, se puede acceder al comando oculto usando ese nombre. Si el comando no existe, o si hiddenCmdName ya está en uso, se devolverá TCL_ERROR.

NAME

Tcl_CreateChild, Tcl_ExposeCommand, Tcl_HideCommand - manage interpreter nesting and command visibility

SYNOPSIS

#include <tcl.h>

Tcl_Interp *
Tcl_CreateChild(parentInterp, childInterpSpec);
void
Tcl_ExposeCommand(interp, hiddenCmdName, cmdName);
int
Tcl_HideCommand(interp, cmdName, hiddenCmdName);

ARGUMENTS

parentInterp (in)
Interpreter in which the new child interpreter will be created.
childInterpSpec (in)
A string specifying how to initialize the child interpreter. It follows the rules for the Tcl interp create command.
interp (in)
Interpreter in which the command is to be exposed or hidden.
hiddenCmdName (in)
The name for the command in the hidden set.
cmdName (in)
The name for the command in the exposed set.

DESCRIPTION

The Tcl_CreateChild function creates a new Tcl interpreter that is a child of parentInterp. The child interpreter is initialized according to childInterpSpec. The function returns a pointer to the new child interpreter or NULL if an error occurred during creation. The child interpreter is automatically linked to its parent, meaning that certain commands in the parent (like exit) will affect the child and vice-versa. This nesting of interpreters is primarily intended for implementing Tcl extensions that require sandboxing or multiple execution contexts.

Tcl_ExposeCommand and Tcl_HideCommand are used to manage the visibility of commands between a parent and child interpreter. When a child interpreter is created, it inherits a copy of the parent interpreter's global namespace commands. However, these commands are initially "hidden" from the child. The parent can selectively "expose" commands to the child using Tcl_ExposeCommand. Similarly, the parent can "hide" commands from the child using Tcl_HideCommand.

Tcl_ExposeCommand moves the command named hiddenCmdName from the set of hidden commands to the set of exposed commands, putting it under the name cmdName. HiddenCmdName must be the name of an existing hidden command, or the operation will return TCL_ERROR and leave an error message as the result of interp. If an exposed command named cmdName already exists, the operation returns TCL_ERROR and leaves an error message as the result of interp. If the operation succeeds, it returns TCL_OK. After executing this command, attempts to use cmdName in any script evaluation mechanism will again succeed.

Tcl_HideCommand moves the command named cmdName from the set of exposed commands to the set of hidden commands, under the name hiddenCmdName. CmdName must be the name of an existing exposed command, or the operation will return TCL_ERROR and leave an error message as the result of interp. Currently both cmdName and hiddenCmdName must not contain namespace qualifiers, or the operation will return TCL_ERROR and leave an error message as the result of interp. The CmdName will be looked up in the global namespace, and not relative to the current namespace, even if the current namespace is not the global one. If a hidden command whose name is hiddenCmdName already exists, the operation also returns TCL_ERROR and an error message is left as the result of interp. If the operation succeeds, it returns TCL_OK. After executing this command, attempts to use cmdName in any script evaluation mechanism will fail.

For a description of the Tcl interface to multiple interpreters, see interp(n).
