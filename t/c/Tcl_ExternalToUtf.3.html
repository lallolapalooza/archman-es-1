Nombre de la codificación a cargar.
Tcl_Encoding encoding (in)
Codificación a consultar, liberar o usar para convertir texto. Si encoding es NULL, se usa la codificación del sistema actual.
Tcl_Obj *objPtr (in)
Nombre de la codificación para obtener el token.
Tcl_Encoding *encodingPtr (out)
El token de la codificación se escribe aquí.
const char *src (in)
Para los procedimientos Tcl_ExternalToUtf, un array de bytes en la codificación especificada que se convertirán a UTF-8. Para los procedimientos Tcl_UtfToExternal y Tcl_WinUtfToTChar, un array de caracteres UTF-8 que se convertirán a la codificación especificada.
const TCHAR *tsrc (in)
Un array de caracteres Windows TCHAR que se convertirán a UTF-8.
int srcLen (in)
Longitud de src o tsrc en bytes. Si la longitud es negativa, se usa la longitud especificada por la codificación.
Tcl_DString *dstPtr (out)
Un DString no inicializado o liberado en el que se almacenará el resultado convertido.
int flags (in)
Bits de flag ORados. TCL_ENCODING_START indica que el buffer de entrada es el primer bloque en un flujo (potencialmente multi-bloque) y que el rutín de conversión se debe reiniciar a un estado inicial y realizar cualquier inicialización necesaria antes de convertir el primer byte. TCL_ENCODING_END indica que el buffer de entrada es el último bloque en un flujo (potencialmente multi-bloque), indicando que el rutín de conversión debe realizar cualquier finalización necesaria después de convertir el último byte y luego reiniciar a un estado inicial. TCL_ENCODING_STOPONERROR indica que el rutín de conversión debe devolver inmediatamente al leer un carácter de entrada que no existe en la codificación objetivo; de lo contrario, un carácter de sustitución predeterminado se substituirá automáticamente.
Tcl_EncodingState *statePtr (in/out)
Se usa cuando se convierte un flujo de bytes (generalmente largo o indefinido) en un pie por pie. El rutín de conversión almacena su estado actual en *statePtr después de src (el buffer que contiene el pie actual) ha sido convertido; esta información del estado debe ser pasada de nuevo cuando se convierta el siguiente pie del flujo para que el rutín de conversión sepa qué estado estaba en cuando se dejó de lado al final del último pie. Puede ser NULL, en cuyo caso el valor especificado para flags se ignora y el buffer de entrada se asume que contiene el texto completo a convertir.
char *dst (out)
El buffer en el que se almacenará el resultado de la conversión. No se almacenará más de dstLen bytes en dst.
int dstLen (in)
La longitud máxima del buffer de salida dst en bytes.
int *srcReadPtr (out)
Se llenará con el número de bytes de src que se hayan convertido realmente. Esto puede ser menor que el largo original de los caracteres de entrada si hubo un problema con la conversión de algunos caracteres de entrada. Puede ser NULL.
int *dstWrotePtr (out)
Se llenará con el número de bytes que se almacenaron en el buffer de salida como resultado de la conversión. Puede ser NULL.
int *dstCharsPtr (out)
Se llenará con el número de caracteres que corresponden al número de bytes almacenados en el buffer de salida. Puede ser NULL.
Tcl_DString *bufPtr (out)
Almacenamiento para el nombre del sistema de codificación especificado.
const Tcl_EncodingType *typePtr (in)
estructura que define un nuevo tipo de codificación.
Tcl_Obj *searchPath (in)
Lista de directorios de archivos en los cuales se buscarán archivos de codificación.

Una ruta a la ubicación del archivo de codificación.

Introducción

Estos rutínas convierten entre la representación de caracteres interna de Tcl, UTF-8, y las representaciones de caracteres usadas por diversos sistemas operativos o sistemas de archivos, como Unicode, ASCII, o Shift-JIS. Cuando se opera sobre strings, como obtener el nombre de archivos o mostrar caracteres usando fuentes internacionales, los strings deben ser traducidos a uno o varios formatos que las diferentes llamadas de sistema puedan usar. Por ejemplo, en un trabajo de Unix japonés, un usuario podría obtener un nombre de archivo representado en la codificación EUC-JP y luego traducir los caracteres a la codificación jisx0208 para mostrar el nombre del archivo en un widget de Tk. El propósito del paquete de codificación es ayudar a calzar la brecha de traducción. UTF-8 proporciona un punto de intermedio para todas las codificaciones diferentes. En el ejemplo anterior, el texto se traduciría a UTF-8 desde la codificación que usa el sistema operativo, y luego se traduciría de UTF-8 a la codificación que requiere las rutínas de visualización.

Algunas codificaciones básicas están incluidas en Tcl. Otros pueden ser definidos por el usuario o cargados dinámicamente desde archivos de codificación de forma independiente de la plataforma.

Descripción

Tcl_GetEncoding encuentra una codificación dada su nombre. El nombre puede referirse a una codificación predefinida de Tcl, a una codificación definida por el usuario registrada mediante Tcl_CreateEncoding, o a una codificación dinámicamente cargable. El valor devuelto es un token que representa la codificación y puede ser utilizado en llamadas posteriores a procedimientos como Tcl_GetEncodingName, Tcl_FreeEncoding, y Tcl_UtfToExternal. Si el nombre no refería a ninguna codificación conocida o cargable, se devuelve NULL y un mensaje de error se devuelve en interp.

El paquete de codificación mantiene un banco de codificaciones actualmente en uso. La primera vez que name se ve, Tcl_GetEncoding devuelve una codificación con un contador de referencias de 1. Si se requiere nuevamente la misma name, el contador de referencias para esa codificación se incrementa sin el overhead de asignar una nueva codificación y sus estructuras asociadas.

Cuando una codificación no es más necesaria, Tcl_FreeEncoding debe llamarse para liberarla. Cuando una codificación no es más utilizada (es decir, ha sido liberada tantas veces como se ha obtenido), Tcl_FreeEncoding liberará todos los espacios de memoria que utilizaba la codificación y eliminará la codificación de la base de datos.

Tcl_GetEncodingFromObj trata la representación de string del objPtr como un nombre de codificación y encuentra una codificación con ese nombre, justo como Tcl_GetEncoding. Cuando se encuentra una codificación, se cachea en el valor objPtr para futuras referencias, y el token Tcl_Encoding se escribe en el puntero de almacenamiento.

Al igual que con Tcl_GetEncoding, el llamador debe llamar a Tcl_FreeEncoding sobre el token de codificación resultante cuando ese token ya no se vaya a utilizar.

Tcl_ExternalToUtfDString convierte un búfer fuente src de la codificación especificada a UTF-8. Los bytes convertidos se almacenan en dstPtr, que luego se termina con nulo. El llamador debe llamar eventualmente a Tcl_DStringFree para liberar cualquier información almacenada en dstPtr. Al convertir, si alguno de los caracteres del búfer fuente no se puede representar en la codificación de destino, se utilizará un carácter de sustitución predeterminado. El valor de retorno es un puntero al valor almacenado en el DString.

Tcl_ExternalToUtf convierte un búfer fuente src de la codificación especificada a UTF-8. Se convierten hasta srcLen bytes del búfer fuente y se almacenan hasta dstLen bytes convertidos en dst. En todos los casos, *srcReadPtr se rellena con el número de bytes que se convirtieron correctamente de src y *dstWrotePtr se rellena con el número correspondiente de bytes que se almacenaron en dst. El valor de retorno es uno de los siguientes:

TCL_OK
Se convirtieron todos los bytes de src.
TCL_CONVERT_NOSPACE
El búfer de destino no era lo suficientemente grande para todos los datos convertidos; sin embargo, se convirtieron tantos caracteres como cupieron.
TCL_CONVERT_MULTIBYTE
Los últimos bytes del búfer fuente eran el principio de una secuencia multibyte, pero se necesitaron más bytes para completar esta secuencia. Una llamada posterior a la rutina de conversión debería pasar un búfer que contenga los bytes no convertidos que quedaron en src más algunos bytes adicionales del flujo fuente para convertir correctamente la secuencia multibyte previamente dividida.
TCL_CONVERT_SYNTAX
El búfer fuente contenía una secuencia de caracteres inválida. Esto puede ocurrir si el flujo de entrada ha sido dañado o si se identificó incorrectamente el método de codificación de entrada.
TCL_CONVERT_UNKNOWN
El búfer fuente contenía un carácter que no se podía representar en la codificación de destino y se especificó TCL_ENCODING_STOPONERROR.

Tcl_UtfToExternalDString convierte un búfer fuente src de UTF-8 a la codificación especificada. Los bytes convertidos se almacenan en dstPtr, que luego se termina con el nulo apropiado específico de la codificación. El llamador debe llamar eventualmente a Tcl_DStringFree para liberar cualquier información almacenada en dstPtr. Al convertir, si alguno de los caracteres del búfer fuente no se puede representar en la codificación de destino, se usará un carácter de sustitución predeterminado. El valor de retorno es un puntero al valor almacenado en el DString.

Tcl_UtfToExternal convierte un búfer fuente src de UTF-8 a la codificación especificada. Se convierten hasta srcLen bytes del búfer fuente y se almacenan hasta dstLen bytes convertidos en dst. En todos los casos, *srcReadPtr se rellena con el número de bytes que se convirtieron correctamente de src y *dstWrotePtr se rellena con el número correspondiente de bytes que se almacenaron en dst. Los valores de retorno son los mismos que los valores de retorno para Tcl_ExternalToUtf.

Tcl_WinUtfToTChar y Tcl_WinTCharToUtf son funciones de conveniencia exclusivas de Windows para convertir entre UTF-8 y cadenas de Windows basadas en el tipo TCHAR, que por convención es un carácter Unicode en Windows NT.

Tcl_GetEncodingName es aproximadamente la inversa de Tcl_GetEncoding. Dado un encoding, el valor de retorno es el argumento name que se utilizó para crear la codificación. La cadena devuelta por Tcl_GetEncodingName solo se garantiza que persista hasta que se elimine el encoding. El llamador no debe modificar esta cadena.

Tcl_SetSystemEncoding establece la codificación predeterminada que debe usarse cada vez que el usuario pase un valor NULL para el argumento encoding a cualquiera de las otras funciones de codificación. Si name es NULL, la codificación del sistema se restablece a la codificación del sistema predeterminada, binary. Si el nombre no se refiere a ninguna codificación conocida o cargable, se devuelve TCL_ERROR y se deja un mensaje de error en interp. De lo contrario, este procedimiento incrementa el recuento de referencias de la nueva codificación del sistema, decrementa el recuento de referencias de la codificación antigua del sistema y devuelve TCL_OK.

Tcl_GetEncodingNameFromEnvironment proporciona un medio para que la biblioteca Tcl informe el nombre de codificación que cree que es el correcto para usar como codificación del sistema, basándose en llamadas al sistema y examen del entorno adecuado para la plataforma. Acepta bufPtr, un puntero a un Tcl_DString no inicializado o liberado, y escribe el nombre de codificación en él. Se devuelve Tcl_DStringValue.

Tcl_GetEncodingNames establece el resultado del interp en una lista que consta de los nombres de todas las codificaciones que están actualmente definidas o que se pueden cargar dinámicamente, buscando en la ruta de codificación especificada por Tcl_SetDefaultEncodingDir. Este procedimiento no garantiza que los archivos de codificación cargables dinámicamente contengan datos válidos, sino simplemente que existen.

Tcl_CreateEncoding define una nueva codificación y registra los procedimientos C que se llaman para convertir entre la codificación y UTF-8. Las codificaciones creadas por Tcl_CreateEncoding son visibles a partir de entonces en la base de datos utilizada por Tcl_GetEncoding. Al igual que con el procedimiento Tcl_GetEncoding, el valor de retorno es un token que representa la codificación y se puede usar en llamadas posteriores a otras funciones de codificación. Tcl_CreateEncoding devuelve una codificación con un recuento de referencias de 1. Si ya existe una codificación con el name especificado, su entrada en la base de datos se reemplaza con la nueva codificación; el token para la codificación antigua seguirá siendo válido y continuará comportándose como antes, pero los usuarios del nuevo token llamarán ahora a los nuevos procedimientos de codificación.

El argumento typePtr para Tcl_CreateEncoding contiene información sobre el nombre de la codificación y los procedimientos que se llamarán para convertir entre esta codificación y UTF-8. Se define de la siguiente manera:

typedef struct Tcl_EncodingType {
    const char *encodingName;
    Tcl_EncodingConvertProc *toUtfProc;
    Tcl_EncodingConvertProc *fromUtfProc;
    Tcl_EncodingFreeProc *freeProc;
    ClientData clientData;
    int nullSize;
} Tcl_EncodingType;

El encodingName proporciona un nombre de cadena para la codificación, por el cual se puede hacer referencia en otros procedimientos como Tcl_GetEncoding. El toUtfProc se refiere a un procedimiento de llamada para invocar la conversión de texto de esta codificación a UTF-8. El fromUtfProc se refiere a un procedimiento de llamada para invocar la conversión de texto de UTF-8 a esta codificación. El freeProc se refiere a un procedimiento de llamada para invocar cuando se elimine esta codificación. El campo freeProc puede ser NULL. El clientData contiene un valor arbitrario de una palabra pasado a toUtfProc, fromUtfProc y freeProc siempre que se llamen. Típicamente, este es un puntero a una estructura de datos que contiene información específica de la codificación que pueden usar los procedimientos de llamada. Por ejemplo, dos codificaciones muy similares como ascii y macRoman pueden usar el mismo procedimiento de llamada, pero usar diferentes valores de clientData para controlar su comportamiento. El nullSize especifica el número de bytes cero que significan fin de cadena en esta codificación. Debe ser 1 (para codificaciones de un solo byte o multibyte como ASCII o Shift-JIS) o 2 (para codificaciones de dos bytes como Unicode). No se aceptan codificaciones de tamaño constante con 3 o más bytes por carácter (como CNS11643).

Los procedimientos de llamada toUtfProc y fromUtfProc deben coincidir con el tipo Tcl_EncodingConvertProc:

typedef int Tcl_EncodingConvertProc(
        ClientData clientData,
        const char *src,
        int srcLen,
        int flags,
        Tcl_EncodingState *statePtr,
        char *dst,
        int dstLen,
        int *srcReadPtr,
        int *dstWrotePtr,
        int *dstCharsPtr);

Los procedimientos toUtfProc y fromUtfProc son llamados por la familia de funciones Tcl_ExternalToUtf o Tcl_UtfToExternal para realizar la conversión real. El parámetro clientData para estos procedimientos es el mismo que el campo clientData especificado a Tcl_CreateEncoding cuando se creó la codificación. Los argumentos restantes a los procedimientos de llamada son los mismos que los argumentos, documentados en la parte superior, para Tcl_ExternalToUtf o Tcl_UtfToExternal, con las siguientes excepciones. Si el argumento srcLen en una de esas funciones de alto nivel es negativo, el valor pasado al procedimiento de llamada será la longitud de cadena específica de la codificación apropiada de src. Si alguno de los argumentos srcReadPtr, dstWrotePtr o dstCharsPtr en una de las funciones de alto nivel es NULL, el valor correspondiente pasado al procedimiento de llamada será una ubicación no NULL.

El procedimiento de llamada freeProc, si no es NULL, debe coincidir con el tipo Tcl_EncodingFreeProc:

typedef void Tcl_EncodingFreeProc(
        ClientData clientData);

Esta función freeProc se llama cuando se elimina la codificación. El parámetro clientData es el mismo que el campo clientData especificado a Tcl_CreateEncoding cuando se creó la codificación.

Tcl_GetEncodingSearchPath y Tcl_SetEncodingSearchPath se llaman para acceder y establecer la lista de directorios del sistema de archivos que se buscan para los archivos de datos de codificación.

El valor devuelto por Tcl_GetEncodingSearchPath es el valor almacenado por la última llamada exitosa a Tcl_SetEncodingSearchPath. Si no ha habido llamadas a Tcl_SetEncodingSearchPath, Tcl calculará un valor inicial basado en el entorno. Existe una ruta de búsqueda de codificación para todo el proceso, compartida por todos los hilos del proceso.
