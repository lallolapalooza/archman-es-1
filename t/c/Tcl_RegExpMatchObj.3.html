ARGUMENTOS

Tcl_Interp *interp (in)
Intérprete Tcl a utilizar para la notificación de errores. El intérprete puede ser NULL si no se desea notificación de errores.
Tcl_Obj *textObj (in/out)
Se refiere al valor del que se obtendrá el texto a buscar. La representación interna del valor puede ser convertida a un formato que pueda ser buscado eficientemente.
Tcl_Obj *patObj (in/out)
Se refiere al valor del que se obtendrá una expresión regular. La expresión regular compilada se almacena en caché en el valor.
const char *text (in)
Texto en el que buscar una coincidencia con una expresión regular.
const char *pattern (in)
Cadena en formato de patrón de expresión regular.
Tcl_RegExp regexp (in)
Expresión regular compilada. Debe haber sido devuelta previamente por Tcl_GetRegExpFromObj o Tcl_RegExpCompile.
const char *start (in)
Si text es solo una porción de alguna otra cadena, este argumento identifica el principio de la cadena mayor. Si no es igual a text, entonces no se permitirán coincidencias de “^”.
int index (in)
Especifica qué rango se desea: 0 significa el rango de toda la coincidencia, 1 o mayor significa el rango que coincidió con una subexpresión entre paréntesis.
const char **startPtr (out)
La dirección del primer carácter del rango se almacena aquí, o NULL si no existe dicho rango.
const char **endPtr (out)
La dirección del carácter justo después del último carácter del rango se almacena aquí, o NULL si no existe dicho rango.
int cflags (in)
Combinación OR de los indicadores de compilación TCL_REG_ADVANCED, TCL_REG_EXTENDED, TCL_REG_BASIC, TCL_REG_EXPANDED, TCL_REG_QUOTE, TCL_REG_NOCASE, TCL_REG_NEWLINE, TCL_REG_NLSTOP, TCL_REG_NLANCH, TCL_REG_NOSUB y TCL_REG_CANMATCH. Vea a continuación para más información.
int offset (in)
El desplazamiento de caracteres en el texto donde debe comenzar la coincidencia. El valor del desplazamiento no tiene impacto en las coincidencias de ^. Este comportamiento está controlado por eflags.
int nmatches (in)
El número de subexpresiones coincidentes que deben ser recordadas para su uso posterior. Si este valor es 0, entonces no se calculará información de coincidencia de subexpresiones. Si el valor es -1, entonces se recordarán todas las subexpresiones coincidentes. Cualquier otro valor se tomará como el número máximo de subexpresiones a recordar.
int eflags (in)
Combinación OR de los indicadores de ejecución TCL_REG_NOTBOL y TCL_REG_NOTEOL. Vea a continuación para más información.
Tcl_RegExpInfo *infoPtr (out)
La dirección de la ubicación donde se almacenará la información sobre una coincidencia anterior por Tcl_RegExpGetInfo.

DESCRIPCIÓN

Tcl_RegExpMatch determina si su argumento pattern coincide con regexp, donde regexp se interpreta como una expresión regular utilizando las reglas de la página de referencia re_syntax. Si hay una coincidencia, Tcl_RegExpMatch devuelve 1. Si no hay coincidencia, Tcl_RegExpMatch devuelve 0. Si ocurre un error en el proceso de coincidencia (por ejemplo, pattern no es una expresión regular válida), entonces Tcl_RegExpMatch devuelve -1 y deja un mensaje de error en el resultado del intérprete. Tcl_RegExpMatchObj es similar a Tcl_RegExpMatch excepto que opera sobre los valores Tcl textObj y patObj en lugar de cadenas UTF. Tcl_RegExpMatchObj es generalmente más eficiente que Tcl_RegExpMatch, por lo que es la interfaz preferida.

Tcl_RegExpCompile, Tcl_RegExpExec y Tcl_RegExpRange proporcionan acceso de bajo nivel al motor de expresiones regulares. Tcl_RegExpCompile compila una cadena de expresión regular en el formato interno utilizado para una coincidencia eficiente de patrones. El valor de retorno es un token para esta forma compilada, que puede ser utilizado en llamadas posteriores a Tcl_RegExpExec o Tcl_RegExpRange. Si ocurre un error al compilar la expresión regular, Tcl_RegExpCompile devuelve NULL y deja un mensaje de error en el resultado del intérprete. Nota: el valor de retorno de Tcl_RegExpCompile solo es válido hasta la siguiente llamada a Tcl_RegExpCompile; no es seguro retener estos valores durante largos períodos de tiempo.

Tcl_RegExpExec ejecuta el motor de expresiones regulares. Devuelve 1 si text contiene un rango de caracteres que coinciden con regexp, 0 si no se encuentra ninguna coincidencia y -1 si ocurre un error. En caso de error, Tcl_RegExpExec deja un mensaje de error en el resultado del intérprete. Al buscar en una cadena múltiples coincidencias de un patrón, es importante distinguir entre el inicio de la cadena original y el inicio de la búsqueda actual. Por ejemplo, al buscar la segunda ocurrencia de una coincidencia, el argumento text podría apuntar al carácter justo después de la primera coincidencia; sin embargo, es importante que el motor de patrones sepa que este no es el inicio de toda la cadena, para que no permita que los átomos “^” en el patrón coincidan. El argumento start proporciona esta información apuntando al inicio de la cadena general que contiene text. Start será menor o igual a text; si es menor que text, no se permitirán coincidencias de ^.

Tcl_RegExpRange puede ser invocado después de que Tcl_RegExpExec devuelva; proporciona información detallada sobre qué rangos de la cadena coincidieron con qué partes del patrón. Tcl_RegExpRange devuelve un par de punteros en *startPtr y *endPtr que identifican un rango de caracteres en la cadena fuente para la llamada más reciente a Tcl_RegExpExec. Index indica cuál de varios rangos se desea: si index es 0, se devuelve información sobre el rango general de caracteres que coincidió con todo el patrón; de lo contrario, se devuelve información sobre el rango de caracteres que coincidió con la subexpresión entre paréntesis número index dentro del patrón. Si no hay un rango correspondiente a index, se almacena NULL en *startPtr y *endPtr.

Tcl_GetRegExpFromObj, Tcl_RegExpExecObj y Tcl_RegExpGetInfo son interfaces de valores que proporcionan el control más directo de la biblioteca de expresiones regulares de Henry Spencer. Para los usuarios que necesitan modificar las opciones de compilación y ejecución directamente, se recomienda utilizar estas interfaces en lugar de llamar a las funciones internas de expresiones regulares. Estas interfaces manejan los detalles de las traducciones de UTF a Unicode, además de proporcionar un rendimiento mejorado a través del almacenamiento en caché en los valores de patrón y cadena.

Tcl_GetRegExpFromObj intenta devolver una expresión regular compilada desde patObj. Si el valor no contiene ya una expresión regular compilada, intentará crear una a partir de la cadena en el valor y asignarla a la representación interna de patObj. El valor de retorno de esta función es de tipo Tcl_RegExp. El valor de retorno es un token para esta forma compilada, que puede ser utilizado en llamadas posteriores a Tcl_RegExpExecObj o Tcl_RegExpGetInfo. Si ocurre un error al compilar la expresión regular, Tcl_GetRegExpFromObj devuelve NULL y deja un mensaje de error en el resultado del intérprete. El token de expresión regular puede ser utilizado siempre que la representación interna de patObj se refiera a la forma compilada. El argumento cflags es un OR a nivel de bits de cero o más de los siguientes indicadores que controlan la compilación de patObj:

TCL_REG_ADVANCED
Permite el uso de sintaxis avanzada de expresiones regulares como enclosures, backreferences, etc. La sintaxis de las expresiones regulares avanzadas está documentada en la página del manual re_syntax.
TCL_REG_EXTENDED
Habilita el dialecto de expresiones regulares extendidas, que es el dialecto por defecto si no se especifica ni TCL_REG_BASIC ni TCL_REG_ADVANCED. Los detalles se encuentran en re_syntax.
TCL_REG_BASIC
Habilita el dialecto de expresiones regulares básicas. Los detalles se encuentran en re_syntax.
TCL_REG_EXPANDED
Permite que el patrón se escriba en un formato más legible, con espacios en blanco y comentarios ignorados de forma similar al modificador /x de Perl. Los detalles se encuentran en re_syntax.
TCL_REG_QUOTE
Trata a la cadena del patrón como una secuencia literal de caracteres, sin ningún significado especial de metacaracteres de expresión regular. Esto es similar a la orden string equal, pero con la capacidad de buscar en subcadenas.
TCL_REG_NOCASE
Hace que la coincidencia no distinga entre mayúsculas y minúsculas.
TCL_REG_NEWLINE
Cambia el comportamiento de los anclajes ^ y $. Con esta opción, ^ coincide con el inicio de la cadena o justo después de un carácter de nueva línea. $ coincide con el final de la cadena o justo antes de un carácter de nueva línea.
TCL_REG_NLSTOP
Hace que los caracteres de nueva línea detengan el motor de coincidencia. Cuando se encuentra un carácter de nueva línea, el motor deja de intentar la coincidencia en esa posición. Esto es útil para evitar que las coincidencias se extiendan a través de múltiples líneas de texto cuando no se desea.
TCL_REG_NLANCH
Trata a los caracteres de nueva línea como anclajes de línea. Con esta opción, ^ coincide con el inicio de la cadena o justo después de un carácter de nueva línea. $ coincide con el final de la cadena o justo antes de un carácter de nueva línea. Esto es similar a TCL_REG_NEWLINE, pero puede tener efectos diferentes en otros metacaracteres.
TCL_REG_NOSUB
Suprime la computación de información de subexpresión. Esto puede hacer que la coincidencia sea más rápida si no necesita los detalles de las subexpresiones.
TCL_REG_CANMATCH
Indica que la llamada puede ser más rápida si solo se necesita saber si hay *alguna* coincidencia, en lugar de la coincidencia más larga posible. No se garantiza un aumento de velocidad, pero el motor puede optimizar para este caso.

Tcl_RegExpExecObj ejecuta el motor de expresiones regulares sobre la cadena representada por textObj. Devuelve 1 si se encuentra una coincidencia, 0 si no se encuentra ninguna, y -1 si ocurre un error. El argumento regexp es un token para una expresión regular compilada devuelto previamente por Tcl_GetRegExpFromObj. El argumento offset especifica el desplazamiento de caracteres en el texto donde debe comenzar la coincidencia. El valor del desplazamiento no tiene impacto en las coincidencias de ^. Este comportamiento se controla mediante eflags. El argumento nmatches especifica el número máximo de subexpresiones coincidentes que se deben recordar. Si es 0, no se calcula información de subexpresión. Si es -1, se recuerdan todas las subexpresiones. Cualquier otro valor especifica el número máximo de subexpresiones a recordar. El argumento eflags es una combinación OR de los siguientes indicadores:

TCL_REG_NOTBOL
Suprime el comportamiento especial del anclaje ^. Con esta opción, ^ coincide solo con el carácter literal '^', no con el inicio de la cadena ni con el inicio de una línea.
TCL_REG_NOTEOL
Suprime el comportamiento especial del anclaje $. Con esta opción, $ coincide solo con el carácter literal '$', no con el final de la cadena ni con el final de una línea.

Tcl_RegExpGetInfo se utiliza para recuperar información sobre la última coincidencia realizada por el motor de expresiones regulares. El argumento regexp debe ser un token para una expresión regular compilada. El argumento infoPtr debe apuntar a una estructura Tcl_RegExpInfo que será llenada por la función. La estructura Tcl_RegExpInfo tiene los siguientes campos:

int nSpacings
El número de rangos de subexpresiones que fueron capturados en la última coincidencia. Este valor puede ser mayor que el número de paréntesis en el patrón si el patrón contiene secuencias como `(a)?(b)?`.
const char **spacing
Un puntero a una matriz de punteros a caracteres. Cada puntero en la matriz corresponde a un rango de subexpresión. El primer elemento, spacing[0], apunta al inicio de la coincidencia completa. Los elementos posteriores, spacing[1], spacing[2], etc., apuntan al inicio de las subexpresiones correspondientes entre paréntesis en el patrón. Si una subexpresión no coincidió, el puntero correspondiente será NULL.
const char *end
Un puntero al final de la coincidencia completa. Es decir, apunta al carácter inmediatamente posterior al último carácter de la coincidencia completa.

Los campos spacing y end solo son válidos si nSpacings es mayor que 0.

DESCRIPCION

Estas funciones proporcionan una interfaz para compilar y ejecutar expresiones regulares en Tcl.

La función Tcl_RegExpCompileObj compila la expresión regular contenida en regexpPtr según las marcas especificadas en flags. Las marcas de compilación disponibles son:

TCL_REG_ADVANCED
Compilar expresiones regulares avanzadas (AREs). Este modo corresponde a la sintaxis normal de expresiones regulares aceptada por los comandos regexp y regsub de Tcl.
TCL_REG_EXTENDED
Compilar expresiones regulares extendidas (EREs). Este modo corresponde a la sintaxis de expresiones regulares reconocida por Tcl 8.0 y versiones anteriores.
TCL_REG_BASIC
Compilar expresiones regulares básicas (BREs). Este modo corresponde a la sintaxis de expresiones regulares reconocida por utilidades comunes de Unix como sed y grep. Este es el valor predeterminado si no se especifican marcas.
TCL_REG_EXPANDED
Compilar la expresión regular (básica, extendida o avanzada) utilizando una sintaxis expandida que permite comentarios y espacios en blanco. Este modo provoca que se ignoren los espacios en blanco no escapados, no entre corchetes, y los comentarios de #-hasta-fin-de-línea.
TCL_REG_QUOTE
Compilar una cadena literal, con todos los caracteres tratados como caracteres ordinarios.
TCL_REG_NOCASE
Compilar para coincidencias que ignoran las distinciones entre mayúsculas y minúsculas.
TCL_REG_NEWLINE
Compilar para coincidencias sensibles a saltos de línea. Por defecto, el salto de línea es un carácter completamente ordinario sin significado especial ni en las expresiones regulares ni en las cadenas. Con esta marca, las expresiones entre corchetes [^] y el carácter '.' nunca coinciden con un salto de línea, '^' coincide con una cadena vacía después de cualquier salto de línea además de su función normal, y '$' coincide con una cadena vacía antes de cualquier salto de línea además de su función normal. REG_NEWLINE es el OR a nivel de bits de REG_NLSTOP y REG_NLANCH.
TCL_REG_NLSTOP
Compilar para coincidencias parciales sensibles a saltos de línea, con el comportamiento de las expresiones entre corchetes [^] y '.' afectadas, pero no el comportamiento de '^' y '$'. En este modo, las expresiones entre corchetes [^] y '.' nunca coinciden con un salto de línea.
TCL_REG_NLANCH
Compilar para coincidencias parciales inversas sensibles a saltos de línea, con el comportamiento de '^' y '$' (las "anclas") afectadas, pero no el comportamiento de las expresiones entre corchetes [^] y '.'. En este modo, '^' coincide con una cadena vacía después de cualquier salto de línea además de su función normal, y '$' coincide con una cadena vacía antes de cualquier salto de línea además de su función normal.
TCL_REG_NOSUB
Compilar para coincidencias que solo informan de éxito o fracaso, no de lo que se coincidió. Esto reduce la sobrecarga de compilación y puede mejorar el rendimiento. Las llamadas posteriores a Tcl_RegExpGetInfo o Tcl_RegExpRange no informarán de ninguna información de coincidencia.
TCL_REG_CANMATCH
Compilar para coincidencias que informan de la posibilidad de completar una coincidencia parcial dada más texto (ver más abajo).

Solo se puede especificar una de las marcas TCL_REG_EXTENDED, TCL_REG_ADVANCED, TCL_REG_BASIC y TCL_REG_QUOTE.

Tcl_RegExpExecObj ejecuta el motor de coincidencias de patrones de expresiones regulares. Devuelve 1 si objPtr contiene un rango de caracteres que coincide con regexp, 0 si no se encuentra ninguna coincidencia y -1 si se produce un error. En caso de error, Tcl_RegExpExecObj deja un mensaje de error en el resultado del intérprete. El valor nmatches indica al motor cuántas subexpresiones son de interés. Si nmatches es 0, entonces no se registra información de coincidencia de subexpresiones, lo que puede permitir al motor realizar varias optimizaciones. Si el valor es -1, entonces se recuerdan todas las subexpresiones del patrón. Si el valor es un entero positivo, entonces solo se recordará ese número de subexpresiones. La búsqueda comienza en el índice de carácter Unicode especificado por offset. A diferencia de Tcl_RegExpExec, el comportamiento de las anclas no se ve afectado por el valor de offset. En su lugar, el comportamiento de las anclas se controla explícitamente mediante el argumento eflags, que es un OR a nivel de bits de cero o más de las siguientes marcas:

TCL_REG_NOTBOL
El carácter inicial no se tratará como el principio de una línea o el principio de la cadena, por lo que '^' no coincidirá allí. Tenga en cuenta que esta marca no tiene ningún efecto sobre cómo coincide '\A'.
TCL_REG_NOTEOL
El último carácter de la cadena no se tratará como el final de una línea o el final de la cadena, por lo que '$' no coincidirá allí. Tenga en cuenta que esta marca no tiene ningún efecto sobre cómo coincide '\Z'.

Tcl_RegExpGetInfo recupera información sobre la última coincidencia realizada con una expresión regular dada regexp. El argumento infoPtr contiene un puntero a una estructura que se define de la siguiente manera:

typedef struct Tcl_RegExpInfo {
    int nsubs;
    Tcl_RegExpIndices *matches;
    long extendStart;
} Tcl_RegExpInfo;

El campo nsubs contiene un recuento del número de subexpresiones entre paréntesis dentro de la expresión regular. Si se utilizó TCL_REG_NOSUB, entonces este valor será cero. El campo matches apunta a una matriz de nsubs+1 valores que indican los límites de cada subexpresión coincidente. El primer elemento de la matriz se refiere al rango coincidente por toda la expresión regular, y los elementos subsiguientes se refieren a las subexpresiones entre paréntesis en el orden en que aparecen en el patrón. Cada elemento es una estructura que se define de la siguiente manera:

typedef struct Tcl_RegExpIndices {
    long start;
    long end;
} Tcl_RegExpIndices;

Los valores start y end son índices de caracteres Unicode relativos a la ubicación offset dentro de objPtr donde comenzó la búsqueda. El índice start identifica el primer carácter de la subexpresión coincidente. El índice end identifica el primer carácter después de la subexpresión coincidente. Si la subexpresión coincidió con la cadena vacía, entonces start y end serán iguales. Si la subexpresión no participó en la coincidencia, entonces start y end se establecerán en -1.

El campo extendStart en Tcl_RegExpInfo solo se establece si se utilizó la marca TCL_REG_CANMATCH. Indica el primer carácter de la cadena donde podría ocurrir una coincidencia. Si se encontró una coincidencia, este será el mismo que el principio de la coincidencia actual. Si no se encontró ninguna coincidencia, entonces indica el punto más temprano en el que podría ocurrir una coincidencia si se agregan datos adicionales a la cadena. Si no es posible ninguna coincidencia incluso con texto adicional, este campo se establecerá en -1.
