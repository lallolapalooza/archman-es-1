Tcl_DString *dstPtr (salida)
Punta a una Tcl_DString sin inicializar o liberada donde se almacenará el resultado convertido.
int flags (entrada)
Varios bits de indicador activados con OR. TCL_ENCODING_START indica que el búfer de origen es el primer bloque en un flujo de entrada (potencialmente de varios bloques), indicando a la rutina de conversión que se reinicie a un estado inicial y realice cualquier inicialización que deba ocurrir antes de que se convierta el primer byte. TCL_ENCODING_END indica que el búfer de origen es el último bloque en un flujo de entrada (potencialmente de varios bloques), indicando a la rutina de conversión que realice cualquier finalización que deba ocurrir después de que se convierta el último byte y luego se reinicie a un estado inicial. TCL_ENCODING_STOPONERROR indica que la rutina de conversión debe retornar inmediatamente al leer un carácter de origen que no existe en la codificación de destino; de lo contrario, se sustituirá automáticamente un carácter de reserva predeterminado.
Tcl_EncodingState *statePtr (entrada/salida)
Se utiliza al convertir un flujo de bytes (generalmente largo o de longitud indefinida) pieza por pieza. La rutina de conversión almacena su estado actual en *statePtr después de que src (el búfer que contiene la pieza actual) ha sido convertido; esa información de estado debe pasarse de nuevo al convertir la siguiente pieza del flujo para que la rutina de conversión sepa en qué estado estaba cuando terminó al final de la última pieza. Puede ser NULL, en cuyo caso se ignora el valor especificado para flags y se asume que el búfer de origen contiene la cadena completa a convertir.
char *dst (salida)
Búfer donde se almacenará el resultado convertido. No se almacenarán más de dstLen bytes en dst.
int dstLen (entrada)
La longitud máxima del búfer de salida dst en bytes.
int *srcReadPtr (salida)
Se llena con el número de bytes de src que se convirtieron realmente. Esto puede ser menor que la longitud de origen original si hubo un problema al convertir algunos caracteres de origen. Puede ser NULL.
int *dstWrotePtr (salida)
Se llena con el número de bytes que se almacenaron realmente en el búfer de salida como resultado de la conversión. Puede ser NULL.
int *dstCharsPtr (salida)
Se llena con el número de caracteres que corresponden al número de bytes almacenados en el búfer de salida. Puede ser NULL.
Tcl_DString *bufPtr (salida)

INTRODUCCION

Estas rutinas convierten entre la representación interna de caracteres de Tcl, UTF-8, y las representaciones de caracteres utilizadas por varios sistemas operativos o sistemas de archivos, como Unicode, ASCII o Shift-JIS. Al operar sobre cadenas, como al obtener nombres de archivos o mostrar caracteres usando fuentes internacionales, las cadenas deben ser traducidas a uno o posiblemente múltiples formatos que las diversas llamadas al sistema puedan usar. Por ejemplo, en una estación de trabajo Unix japonesa, un usuario podría obtener un nombre de archivo representado en la codificación de archivo EUC-JP y luego traducir los caracteres a la codificación de fuente jisx0208 para mostrar el nombre de archivo en un widget Tk. El propósito del paquete de codificación es ayudar a cerrar la brecha de traducción. UTF-8 proporciona un terreno intermedio para todas las diversas codificaciones. En el ejemplo anterior, el texto se traduciría a UTF-8 desde la codificación de archivo que esté utilizando el sistema operativo. Luego se traduciría de UTF-8 a la codificación de fuente que requieran las rutinas de visualización.

Algunas codificaciones básicas están compiladas en Tcl. Otras pueden ser definidas por el usuario o cargadas dinámicamente desde archivos de codificación de manera independiente de la plataforma.

DESCRIPCION

Tcl_GetEncoding encuentra una codificación dado su name. El nombre puede referirse a una codificación incorporada de Tcl, una codificación definida por el usuario registrada llamando a Tcl_CreateEncoding, o un archivo de codificación cargable dinámicamente. El valor de retorno es un token que representa la codificación y puede ser utilizado en llamadas posteriores a procedimientos como Tcl_GetEncodingName, Tcl_FreeEncoding y Tcl_UtfToExternal. Si el nombre no se refiere a ninguna codificación conocida o cargable, se devuelve NULL y se devuelve un mensaje de error en interp.

El paquete de codificación mantiene una base de datos de todas las codificaciones actualmente en uso. La primera vez que se ve name, Tcl_GetEncoding devuelve una codificación con un contador de referencias de 1. Si se solicita el mismo name varias veces más, el contador de referencias para esa codificación se incrementa sin la sobrecarga de asignar una nueva codificación y todas sus estructuras de datos asociadas.

Cuando una encoding ya no es necesaria, se debe llamar a Tcl_FreeEncoding para liberarla. Cuando una encoding ya no está en uso en ningún lugar (es decir, ha sido liberada tantas veces como ha sido obtenida), Tcl_FreeEncoding liberará todo el almacenamiento que la codificación estaba usando y la eliminará de la base de datos.

Tcl_GetEncodingFromObj trata la representación de cadena de objPtr como un nombre de codificación, y encuentra una codificación con ese nombre, al igual que lo hace Tcl_GetEncoding. Cuando se encuentra una codificación, se almacena en caché dentro del valor de objPtr para referencia futura, el token Tcl_Encoding se escribe en el almacenamiento apuntado por

Al igual que con Tcl_GetEncoding, el llamador debe llamar a Tcl_FreeEncoding en el token de codificación resultante cuando dicho token ya no se vaya a utilizar.

Tcl_ExternalToUtfDString convierte un búfer de origen src de la codificación especificada a UTF-8. Los bytes convertidos se almacenan en dstPtr, que luego se termina con nulo. El llamador debe llamar eventualmente a Tcl_DStringFree para liberar cualquier información almacenada en dstPtr. Al convertir, si alguno de los caracteres del búfer de origen no se puede representar en la codificación de destino, se utilizará un carácter de sustitución por defecto. El valor de retorno es un puntero al valor almacenado en el DString.

Tcl_ExternalToUtf convierte un búfer de origen src de la codificación especificada a UTF-8. Se convierten hasta srcLen bytes del búfer de origen y se almacenan hasta dstLen bytes convertidos en dst. En todos los casos, *srcReadPtr se rellena con el número de bytes que se convirtieron correctamente de src y *dstWrotePtr se rellena con el número correspondiente de bytes que se almacenaron en dst. El valor de retorno es uno de los siguientes:

TCL_OK
Todos los bytes de src se convirtieron.
TCL_CONVERT_NOSPACE
El búfer de destino no era lo suficientemente grande para todos los datos convertidos; sin embargo, se convirtieron tantos caracteres como cupieron.
TCL_CONVERT_MULTIBYTE
Los últimos bytes del búfer de origen eran el principio de una secuencia multibyte, pero se necesitaban más bytes para completar esta secuencia. Una llamada posterior a la rutina de conversión debe pasar un búfer que contenga los bytes no convertidos que quedaron en src más algunos bytes adicionales del flujo de origen para convertir correctamente la secuencia multibyte previamente dividida.
TCL_CONVERT_SYNTAX
El búfer de origen contenía una secuencia de caracteres inválida. Esto puede ocurrir si el flujo de entrada ha sido dañado o si el método de codificación de entrada se identificó incorrectamente.
TCL_CONVERT_UNKNOWN
El búfer de origen contenía un carácter que no se podía representar en la codificación de destino y se especificó TCL_ENCODING_STOPONERROR.

Tcl_UtfToExternalDString convierte un búfer de origen src de UTF-8 a la codificación especificada. Los bytes convertidos se almacenan en dstPtr, que luego se termina con el nulo específico de la codificación apropiado. El llamador debe llamar eventualmente a Tcl_DStringFree para liberar cualquier información almacenada en dstPtr. Al convertir, si alguno de los caracteres del búfer de origen no se puede representar en la codificación de destino, se utilizará un carácter de sustitución por defecto. El valor de retorno es un puntero al valor almacenado en el DString.

Tcl_UtfToExternal convierte un búfer de origen src de UTF-8 a la codificación especificada. Se convierten hasta srcLen bytes del búfer de origen y se almacenan hasta dstLen bytes convertidos en dst. En todos los casos, *srcReadPtr se rellena con el número de bytes que se convirtieron correctamente de src y *dstWrotePtr se rellena con el número correspondiente de bytes que se almacenaron en dst. Los valores de retorno son los mismos que los valores de retorno para Tcl_ExternalToUtf.

Tcl_WinUtfToTChar y Tcl_WinTCharToUtf son funciones de conveniencia exclusivas de Windows para convertir entre UTF-8 y cadenas de Windows basadas en el tipo TCHAR, que por convención es un carácter Unicode en Windows NT.

Tcl_GetEncodingName es aproximadamente la inversa de Tcl_GetEncoding. Dado una codificación, el valor de retorno es el argumento name que se utilizó para crear la codificación. La cadena devuelta por Tcl_GetEncodingName solo se garantiza que persista hasta que la codificación se elimine. El llamador no debe modificar esta cadena.

Tcl_SetSystemEncoding establece la codificación por defecto que debe utilizarse siempre que el usuario pase un valor NULL para el argumento encoding a cualquiera de las otras funciones de codificación. Si name es NULL, la codificación del sistema se restablece a la codificación del sistema por defecto, binary. Si el nombre no se refería a ninguna codificación conocida o cargable, se devuelve TCL_ERROR y se deja un mensaje de error en interp. De lo contrario, este procedimiento incrementa el recuento de referencias de la nueva codificación del sistema, decrementa el recuento de referencias de la codificación antigua del sistema y devuelve TCL_OK.

Tcl_GetEncodingNameFromEnvironment proporciona un medio para que la biblioteca Tcl informe el nombre de la codificación que considera que es la correcta para usar como codificación del sistema, basándose en llamadas al sistema y en el examen del entorno adecuado para la plataforma. Acepta bufPtr, un puntero a un Tcl_DString no inicializado o liberado, y escribe el nombre de la codificación en él. Se devuelve Tcl_DStringValue.

Tcl_GetEncodingNames establece el resultado de interp a una lista que consta de los nombres de todas las codificaciones que están actualmente definidas o que se pueden cargar dinámicamente, buscando en la ruta de codificación especificada por Tcl_SetDefaultEncodingDir. Este procedimiento no garantiza que los archivos de codificación cargables dinámicamente contengan datos válidos, sino simplemente que existen.

Tcl_CreateEncoding define una nueva codificación y registra los procedimientos C que se llaman para convertir entre la codificación y UTF-8. Las codificaciones creadas por Tcl_CreateEncoding son posteriormente visibles en la base de datos utilizada por Tcl_GetEncoding. Al igual que con el procedimiento Tcl_GetEncoding, el valor de retorno es un token que representa la codificación y puede usarse en llamadas posteriores a otras funciones de codificación. Tcl_CreateEncoding devuelve una codificación con un recuento de referencias de 1. Si ya existe una codificación con el name especificado, su entrada en la base de datos se reemplaza por la nueva codificación; el token de la codificación antigua seguirá siendo válido y continuará comportándose como antes, pero los usuarios del nuevo token llamarán ahora a los nuevos procedimientos de codificación.

El argumento typePtr a Tcl_CreateEncoding contiene información sobre el nombre de la codificación y los procedimientos que se llamarán para convertir entre esta codificación y UTF-8. Se define como sigue:

typedef struct Tcl_EncodingType {
    const char *encodingName;
    Tcl_EncodingConvertProc *toUtfProc;
    Tcl_EncodingConvertProc *fromUtfProc;
    Tcl_EncodingFreeProc *freeProc;
    ClientData clientData;
    int nullSize;
} Tcl_EncodingType;

encodingName proporciona un nombre de cadena para la codificación, por el cual se puede hacer referencia en otros procedimientos como Tcl_GetEncoding. toUtfProc se refiere a un procedimiento de devolución de llamada que se invocará para convertir texto de esta codificación a UTF-8. fromUtfProc se refiere a un procedimiento de devolución de llamada que se invocará para convertir texto de UTF-8 a esta codificación. freeProc se refiere a un procedimiento de devolución de llamada que se invocará cuando se elimine esta codificación. El campo freeProc puede ser NULL. clientData contiene un valor arbitrario de una palabra que se pasa a toUtfProc, fromUtfProc y freeProc cada vez que se llaman. Típicamente, este es un puntero a una estructura de datos que contiene información específica de la codificación que pueden utilizar los procedimientos de devolución de llamada. Por ejemplo, dos codificaciones muy similares como ascii y macRoman pueden usar el mismo procedimiento de devolución de llamada, pero usan diferentes valores de clientData para controlar su comportamiento. nullSize especifica el número de bytes cero que significan fin de cadena en esta codificación. Debe ser 1 (para codificaciones monobyte o multibyte como ASCII o Shift-JIS) o 2 (para codificaciones doble byte como Unicode). Las codificaciones de tamaño constante con 3 o más bytes por carácter (como CNS11643) no se aceptan.

Los procedimientos de devolución de llamada toUtfProc y fromUtfProc deben coincidir con el tipo Tcl_EncodingConvertProc:

typedef int Tcl_EncodingConvertProc(
        ClientData clientData,
        const char *src,
        int srcLen,
        int flags,
        Tcl_EncodingState *statePtr,
        char *dst,
        int dstLen,
        int *srcReadPtr,
        int *dstWrotePtr,
        int *dstCharsPtr);

Los procedimientos toUtfProc y fromUtfProc son llamados por la familia de funciones Tcl_ExternalToUtf o Tcl_UtfToExternal para realizar la conversión real. El parámetro clientData a estos procedimientos es el mismo que el campo clientData especificado a Tcl_CreateEncoding cuando se creó la codificación. Los argumentos restantes a los procedimientos de devolución de llamada son los mismos que los argumentos, documentados al principio, a Tcl_ExternalToUtf o Tcl_UtfToExternal, con las siguientes excepciones. Si el argumento srcLen a una de esas funciones de alto nivel es negativo, el valor pasado al procedimiento de devolución de llamada será la longitud de cadena específica de la codificación apropiada de src. Si alguno de los argumentos srcReadPtr, dstWrotePtr, o dstCharsPtr a una de las funciones de alto nivel es NULL, el valor correspondiente pasado al procedimiento de devolución de llamada será una ubicación no NULL.

El procedimiento de devolución de llamada freeProc, si no es NULL, debe coincidir con el tipo Tcl_EncodingFreeProc:

typedef void Tcl_EncodingFreeProc(
        ClientData clientData);

Esta función freeProc se llama cuando se elimina la codificación. El parámetro clientData es el mismo que el campo clientData especificado a Tcl_CreateEncoding cuando se creó la codificación.

Tcl_GetEncodingSearchPath y Tcl_SetEncodingSearchPath se llaman para acceder y establecer la lista de directorios del sistema de archivos que se buscan para los archivos de datos de codificación.

El valor devuelto por Tcl_GetEncodingSearchPath es el valor almacenado por la última llamada exitosa a Tcl_SetEncodingSearchPath. Si no se han producido llamadas a Tcl_SetEncodingSearchPath, Tcl calculará un valor inicial basado en el entorno. Existe una ruta de búsqueda de codificación para todo el proceso, compartida por todos los hilos del proceso.

INTRODUCTION

Tcl supports a wide variety of character encodings, such as ASCII, UTF-8, iso-8859-1, big5, and shiftjis. Tcl's internal string representation is always Unicode (UTF-8). These functions provide mechanisms for converting between Tcl strings and external encodings.

DESCRIPTION

Tcl_GetEncodingFromObj is the high-level procedure for obtaining a handle to an encoding. It takes an interpreter and an object containing the encoding name. It returns a Tcl_Encoding handle if successful, or NULL if the encoding cannot be found or loaded. If an error occurs, it also leaves an error message in the interpreter.

Tcl_GetEncoding is similar to Tcl_GetEncodingFromObj, but takes the encoding name as a string. The first time an encoding is requested, Tcl attempts to load it from disk. If it cannot be loaded, an error is returned.

The encoding handle returned by Tcl_GetEncoding must be released when it is no longer needed by calling Tcl_FreeEncoding. This decrements the encoding's reference count. If the reference count drops to zero, the encoding is unloaded.

Tcl_SetEncoding associates a name with a given encoding handle. This is normally used internally by Tcl when loading dynamically loadable encodings. It is unlikely that application code will need to call this procedure.

Tcl_EncodingType returns a pointer to a static structure describing the type of the encoding. The structure contains fields for the encoding's name, the name of the encoding's type (e.g. "single-byte", "multi-byte", "escape-sequence"), and procedures for converting to and from Unicode. This is mainly used internally by Tcl.

Tcl_NameOfEncoding returns a pointer to a string which is the name associated with the given encoding. This might not be the same name as was used to look up the encoding.

Tcl_GetEncodingSearchPath returns a list object containing the list of directories Tcl searches for encoding data files. The list is ordered, and Tcl searches the directories in that order. The list is owned by Tcl, and should not be modified; a copy should be made if modifications are needed. An empty list is returned if the search path is not set.

Tcl_SetEncodingSearchPath sets the list of directories Tcl searches for encoding data files. The path argument is a list object containing the desired directory names. Any existing search path is discarded. If path is NULL, then the default search path is restored.

The default search path consists of the subdirectory "encoding" within each directory in the Tcl library path. For example, if the Tcl library path is /usr/lib/tcl8.6:/usr/share/tcl8.6, then Tcl searches the directories /usr/lib/tcl8.6/encoding and /usr/share/tcl8.6/encoding.

The directories specified in the searchPath argument to Tcl_SetEncodingSearchPath are checked in order. If the first directory in the list contains an encoding file, Tcl uses it and does not search any further directories. If Tcl cannot find the encoding file in a directory, or if the file is not readable, the directory is silently ignored and Tcl proceeds to the next directory in the list.

Tcl_GetDefaultEncodingDir and Tcl_SetDefaultEncodingDir are obsolete interfaces best replaced with calls to Tcl_GetEncodingSearchPath and Tcl_SetEncodingSearchPath. They are called to access and set the first element of the searchPath list. Since Tcl searches searchPath for encoding data files in list order, these routines establish the “default” directory in which to find encoding data files.

ENCODING FILES

Space would prohibit precompiling into Tcl every possible encoding algorithm, so many encodings are stored on disk as dynamically-loadable encoding files. This behavior also allows the user to create additional encoding files that can be loaded using the same mechanism. These encoding files contain information about the tables and/or escape sequences used to map between an external encoding and Unicode. The external encoding may consist of single-byte, multi-byte, or double-byte characters.

Each dynamically-loadable encoding is represented as a text file. The initial line of the file, beginning with a “#” symbol, is a comment that provides a human-readable description of the file. The next line identifies the type of encoding file. It can be one of the following letters:

[1] S
A single-byte encoding, where one character is always one byte long in the encoding. An example is iso8859-1, used by many European languages.
[2] D
A double-byte encoding, where one character is always two bytes long in the encoding. An example is big5, used for Chinese text.
[3] M
A multi-byte encoding, where one character may be either one or two bytes long. Certain bytes are lead bytes, indicating that another byte must follow and that together the two bytes represent one character. Other bytes are not lead bytes and represent themselves. An example is shiftjis, used by many Japanese computers.
[4] E
An escape-sequence encoding, specifying that certain sequences of bytes do not represent characters, but commands that describe how following bytes should be interpreted.

The rest of the lines in the file depend on the type.

Cases [1], [2], and [3] are collectively referred to as table-based encoding files. The lines in a table-based encoding file are in the same format as this example taken from the shiftjis encoding (this is not the complete file):

The third line of the file is three numbers. The first number is the fallback character (in base 16) to use when converting from UTF-8 to this encoding. The second number is a 1 if this file represents the encoding for a symbol font, or 0 otherwise. The last number (in base 10) is how many pages of data follow.

Subsequent lines in the example above are pages that describe how to map from the encoding into 2-byte Unicode. The first line in a page identifies the page number. Following it are 256 double-byte numbers, arranged as 16 rows of 16 numbers. Given a character in the encoding, the high byte of that character is used to select which page, and the low byte of that character is used as an index to select one of the double-byte numbers in that page - the value obtained being the corresponding Unicode character. By examination of the example above, one can see that the characters 0x7E and 0x8163 in shiftjis map to 203E and 2026 in Unicode, respectively.

Following the first page will be all the other pages, each in the same format as the first: one number identifying the page followed by 256 double-byte Unicode characters. If a character in the encoding maps to the Unicode character 0000, it means that the character does not actually exist. If all characters on a page would map to 0000, that page can be omitted.

Case [4] is the escape-sequence encoding file. The lines in an this type of file are in the same format as this example taken from the iso2022-jp encoding:

# Encoding file: iso2022-jp, escape-driven
E
init		{}
final		{}
iso8859-1	\x1b(B
jis0201		\x1b(J
jis0208		\x1b$@
jis0208		\x1b$B
jis0212		\x1b$(D
gb2312		\x1b$A
ksc5601		\x1b$(C

In the file, the first column represents an option and the second column is the associated value. init is a string to emit or expect before the first character is converted, while final is a string to emit or expect after the last character. All other options are names of table-based encodings; the associated value is the escape-sequence that marks that encoding. Tcl syntax is used for the values; in the above example, for instance, “{}” represents the empty string and “\x1b” represents character 27.

When Tcl_GetEncoding encounters an encoding name that has not been loaded, it attempts to load an encoding file called name.enc from the encoding subdirectory of each directory that Tcl searches for its script library. If the encoding file exists, but is malformed, an error message will be left in interp.
