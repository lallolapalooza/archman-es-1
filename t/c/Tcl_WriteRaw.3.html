ARGUMENTOS

Tcl_Interp *interp (entrada)
Se utiliza para informar de errores y para buscar un canal registrado en él.
const char *fileName (entrada)
El nombre de un archivo local o de red.
const char *mode (entrada)
Especifica cómo se debe acceder al archivo. Puede tener cualquiera de los valores permitidos para el argumento mode del comando Tcl open.
int permissions (entrada)
Indicadores de permisos estilo POSIX, como 0644. Si se crea un nuevo archivo, estos permisos se establecerán en el archivo creado.
int argc (entrada)
El número de elementos en argv.
const char **argv (entrada)
Argumentos para construir una canalización de comandos. Estos valores tienen el mismo significado que los argumentos que no son de opción para el comando Tcl exec.
int flags (entrada)
Especifica la disposición de los manejadores stdio en la canalización: combinación OR de TCL_STDIN, TCL_STDOUT, TCL_STDERR y TCL_ENFORCE_MODE. Si se establece TCL_STDIN, la entrada estándar del primer hijo en la canalización es el canal de la tubería, de lo contrario es la misma que la entrada estándar del proceso que llama; lo mismo ocurre con TCL_STDOUT y TCL_STDERR. Si TCL_ENFORCE_MODE no está establecido, entonces la tubería puede redirigir los manejadores stdio para anular los manejadores stdio para los cuales se han establecido TCL_STDIN, TCL_STDOUT y TCL_STDERR. Si está establecido, dichas redirecciones causan un error.
ClientData handle (entrada)
Manejador específico del sistema operativo para E/S a un archivo. Para Unix es un descriptor de archivo, para Windows es un HANDLE.
int readOrWrite (entrada)
Combinación OR de TCL_READABLE y TCL_WRITABLE para indicar qué operaciones son válidas en handle.
const char *channelName (entrada)
El nombre del canal.
int *modePtr (salida)
Punta a una variable entera que recibirá una combinación OR de TCL_READABLE y TCL_WRITABLE que indica si el canal está abierto para lectura y escritura.
const char *pattern (entrada)
El patrón a comparar, pasado a Tcl_StringMatch, o NULL.
Tcl_Channel channel (entrada)
Un canal Tcl para entrada o salida. Debe haber sido el valor de retorno de un procedimiento como Tcl_OpenFileChannel.
Tcl_Obj *readObjPtr (entrada/salida)
Un puntero a un valor Tcl en el que se almacenarán los caracteres leídos del canal.
int charsToRead (entrada)
El número de caracteres a leer del canal. Si la codificación del canal es binary, esto es equivalente al número de bytes a leer del canal.
int appendFlag (entrada)
Si es distinto de cero, los datos leídos del canal se añadirán al valor. De lo contrario, los datos reemplazarán el contenido existente del valor.
char *readBuf (salida)
Un búfer en el que se almacenarán los bytes leídos del canal.
int bytesToRead (entrada)
El número de bytes a leer del canal. El búfer readBuf debe ser lo suficientemente grande como para contener esta cantidad de bytes.
Tcl_Obj *lineObjPtr (entrada/salida)
Un puntero a un valor Tcl en el que se almacenará la línea leída del canal. La línea leída se añadirá al valor actual del valor.
Tcl_DString *lineRead (entrada/salida)
Un puntero a una cadena dinámica Tcl en la que se almacenará la línea leída del canal. Debe haber sido inicializada por el llamador. La línea leída se añadirá a cualquier dato que ya esté en la cadena dinámica.
const char *input (entrada)
La entrada a añadir a un búfer de canal.
int inputLen (entrada)
Longitud de la entrada
int addAtEnd (entrada)
Indicador que indica si la entrada debe añadirse al final o al principio del búfer del canal.
Tcl_Obj *writeObjPtr (entrada)
Un puntero a un valor Tcl cuyo contenido se enviará al canal.
const char *charBuf (entrada)
Un búfer que contiene los caracteres a enviar al canal.
const char *byteBuf (entrada)
Un búfer que contiene los bytes a enviar al canal.
int bytesToWrite (entrada)
El número de bytes a consumir de charBuf o byteBuf y enviar al canal.
Tcl_WideInt offset (entrada)
Qué tan lejos mover el punto de acceso en el canal en el que la siguiente operación de entrada o salida se aplicará, medido en bytes desde la posición dada por seekMode. Puede ser positivo o negativo.
int seekMode (entrada)
Relativo a qué punto buscar; se usa con offset para calcular el nuevo punto de acceso para el canal. Los valores legales son SEEK_SET, SEEK_CUR y SEEK_END.
Tcl_WideInt length (entrada)
La longitud (no negativa) a la que truncar el canal.
const char *optionName (entrada)
El nombre de una opción aplicable a este canal, como -blocking. Puede tener cualquiera de los valores aceptados por el comando fconfigure.
Tcl_DString *optionValue (entrada)
Dónde almacenar el valor de una opción o una lista de todas las opciones y sus valores. Debe haber sido inicializado por el llamador.
const char *newValue (entrada)
Nuevo valor para la opción dada por optionName.

DESCRIPCIÓN

El mecanismo de canales de Tcl proporciona un mecanismo independiente del dispositivo y de la plataforma para realizar operaciones de entrada y salida con búfer en una variedad de tipos de archivos, sockets y dispositivos. El mecanismo de canales es extensible a nuevos tipos de canales, proporcionando un controlador de canal de bajo nivel para el nuevo tipo; la interfaz del controlador de canal se describe en la entrada del manual de Tcl_CreateChannel. El mecanismo de canales proporciona un esquema de búfer modelado a partir de la E/S estándar de Unix, y también permite E/S no bloqueante en canales.

Los procedimientos descritos en esta entrada del manual comprenden las API de C de la capa genérica de la arquitectura de canales. Para una descripción de la arquitectura del controlador de canales y cómo implementar controladores de canales para nuevos tipos de canales, consulte la entrada del manual de Tcl_CreateChannel.

TCL_OPENFILECHANNEL

Abre un archivo especificado por fileName y devuelve un identificador de canal para el archivo. El argumento mode especifica cómo se debe abrir el archivo (por ejemplo, "r" para lectura, "w" para escritura, "rb" para lectura binaria, "a" para añadir). El argumento permissions se utiliza solo si se crea un nuevo archivo y especifica los permisos POSIX para ese archivo (por ejemplo, 0644).

Si se produce un error durante la apertura del archivo, se establece una entrada de error en el intérprete interp y se devuelve un valor NULL. De lo contrario, se devuelve un identificador de canal para el archivo abierto.

TCL_OPENCOMMANDCHANNEL

Abre un canal de tubería que ejecuta un comando externo y lo conecta a la entrada estándar y/o salida estándar y/o error estándar del comando. El comando y sus argumentos se especifican en argc y argv. Los flags especifican cómo se manejan los descriptores de archivo estándar del proceso padre:

  • TCL_STDIN: Conecta la entrada estándar del primer proceso hijo a la tubería.
  • TCL_STDOUT: Conecta la salida estándar del último proceso hijo a la tubería.
  • TCL_STDERR: Conecta el error estándar del último proceso hijo a la tubería.
  • TCL_ENFORCE_MODE: Si se establece, cualquier intento de redirigir los descriptores de archivo estándar del proceso padre resultará en un error.
Si se produce un error, se establece una entrada de error en interp y se devuelve NULL. De lo contrario, se devuelve un identificador de canal.

TCL_MAKEFILECHANNEL

Crea un canal Tcl a partir de un manejador de archivo existente (por ejemplo, un descriptor de archivo de Unix o un HANDLE de Windows). El argumento readOrWrite especifica si el canal se utilizará para lectura (TCL_READABLE) o escritura (TCL_WRITABLE).

Este procedimiento se utiliza típicamente cuando Tcl se incrusta en otra aplicación y la aplicación ya ha abierto un archivo o socket. El canal creado se registra automáticamente en el intérprete.

TCL_GETCHANNEL

Devuelve un identificador de canal para el canal llamado channelName. Si se proporciona modePtr, se establece en un valor que indica si el canal está abierto para lectura (TCL_READABLE) y/o escritura (TCL_WRITABLE).

Si el canal no se encuentra o no se puede acceder a él en el modo especificado, se establece una entrada de error en interp y se devuelve NULL.

TCL_GETCHANNELNAMES

Devuelve el número de canales registrados actualmente en el intérprete interp. Los nombres de todos los canales registrados se añaden como elementos a la lista de resultados del intérprete.

TCL_GETCHANNELNAMESEX

Similar a Tcl_GetChannelNames, pero solo devuelve los nombres de los canales que coinciden con el patrón pattern especificado. Si pattern es NULL, se comporta como Tcl_GetChannelNames.

TCL_REGISTERCHANNEL

Registra el canal especificado en el intérprete interp, haciéndolo visible para los comandos Tcl como puts y gets.

TCL_UNREGISTERCHANNEL

Anula el registro del canal especificado del intérprete interp. Esto impide que el canal se utilice en comandos Tcl posteriores. El canal no se cierra por este procedimiento; debe cerrarse explícitamente utilizando Tcl_Close.

Si el canal se anula correctamente, devuelve 0. De lo contrario, devuelve -1.

TCL_DETACHCHANNEL

Desvincula el canal especificado del intérprete interp. El canal ya no será gestionado por el sistema de canales Tcl, pero seguirá abierto hasta que se cierre explícitamente llamando a Tcl_Close. Esto es útil para pasar el control de un canal a otro sistema o para cerrar un canal sin liberar los recursos asociados.

Si el canal se desvincula correctamente, devuelve 0. De lo contrario, devuelve -1.

TCL_ISSTANDARDCHANNEL

Devuelve 1 si el canal especificado es uno de los canales estándar (entrada, salida o error) para el intérprete, y 0 en caso contrario.

TCL_CLOSE

Cierra el canal especificado. Si el canal está abierto para escritura, se vaciará primero cualquier búfer de salida pendiente. Después de cerrar el canal, se liberan todos los recursos asociados con él.

Si el cierre se realiza correctamente, devuelve 0. En caso de error, se establece una entrada de error en interp y se devuelve -1.

TCL_READCHARS

Lee hasta charsToRead caracteres del canal especificado y los almacena en el valor Tcl apuntado por readObjPtr. Si appendFlag es distinto de cero, los caracteres leídos se añadirán al valor existente; de lo contrario, reemplazarán el contenido actual del valor. Si el canal tiene una codificación, los caracteres se convertirán a esa codificación. Si el canal está en modo binario, lee bytes en lugar de caracteres.

Devuelve el número de caracteres (o bytes, en modo binario) leídos. Si se alcanza el fin del archivo, devuelve un valor menor que charsToRead (o 0 si no se pudieron leer caracteres). Si se produce un error, devuelve -1.

TCL_READ

Lee hasta bytesToRead bytes del canal especificado y los almacena en el búfer readBuf. Este procedimiento debe usarse solo para canales configurados en modo binario.

Devuelve el número de bytes leídos. Si se alcanza el fin del archivo, devuelve un valor menor que bytesToRead (o 0 si no se pudieron leer bytes). Si se produce un error, devuelve -1.

TCL_GETSOBJ

Lee una línea del canal especificado (hasta un carácter de nueva línea) y la almacena en el valor Tcl apuntado por lineObjPtr. El carácter de nueva línea no se incluye en el valor resultante. Si se alcanzan los datos al final del archivo antes de encontrar una nueva línea, se devuelve la línea parcial. Si se alcanza el fin del archivo y no se lee ningún dato, el valor Tcl permanece sin cambios y la función devuelve 0. Si se lee un carácter de nueva línea, se devuelve 1.

Si se produce un error de E/S, devuelve -1.

TCL_GETS

Lee una línea del canal especificado (hasta un carácter de nueva línea) y la almacena en la cadena dinámica lineRead. El carácter de nueva línea no se incluye en la cadena resultante. Si se alcanzan los datos al final del archivo antes de encontrar una nueva línea, se devuelve la línea parcial. Si se alcanza el fin del archivo y no se lee ningún dato, la cadena dinámica permanece sin cambios y la función devuelve 0. Si se lee un carácter de nueva línea, se devuelve 1.

Si se produce un error de E/S, devuelve -1.

TCL_UNGETS

Devuelve la cadena input de longitud inputLen al búfer de entrada del canal. Si addAtEnd es 0, la entrada se inserta al principio del búfer; de lo contrario, se inserta al final. Esto es útil para permitir que un analizador lea datos adicionales de un canal que ya ha sido leído.

Devuelve el número de caracteres añadidos al búfer. Si se produce un error, devuelve -1.

TCL_WRITEOBJ

Escribe el contenido del valor Tcl apuntado por writeObjPtr en el canal especificado. Si el canal tiene una codificación, los datos se codificarán antes de escribirse. Si el canal está en modo binario, los datos se escribirán tal cual.

Devuelve el número de bytes escritos. Si se produce un error, devuelve -1.

TCL_WRITECHARS

Escribe hasta bytesToWrite caracteres del búfer charBuf en el canal especificado. Los caracteres se convertirán a la codificación del canal si es necesario. Si el canal está en modo binario, este procedimiento se comporta igual que Tcl_Write.

Devuelve el número de caracteres escritos. Si se produce un error, devuelve -1.

TCL_WRITE

Escribe hasta bytesToWrite bytes del búfer byteBuf en el canal especificado. Este procedimiento debe usarse solo para canales configurados en modo binario.

Devuelve el número de bytes escritos. Si se produce un error, devuelve -1.

TCL_READRAW

Lee hasta bytesToRead bytes sin procesar del canal especificado y los almacena en el búfer readBuf. Este procedimiento debe usarse solo para canales configurados en modo binario y cuando no se desea ninguna conversión de codificación.

Devuelve el número de bytes leídos. Si se alcanza el fin del archivo, devuelve un valor menor que bytesToRead (o 0 si no se pudieron leer bytes). Si se produce un error, devuelve -1.

TCL_WRITERAW

Escribe hasta bytesToWrite bytes sin procesar del búfer byteBuf en el canal especificado. Este procedimiento debe usarse solo para canales configurados en modo binario y cuando no se desea ninguna conversión de codificación.

Devuelve el número de bytes escritos. Si se produce un error, devuelve -1.

TCL_EOF

Devuelve 1 si se ha alcanzado el final del archivo en el canal especificado, y 0 en caso contrario. Nota: Esto solo es fiable para canales que son capaces de alcanzar el final del archivo (por ejemplo, archivos, no sockets).

TCL_FLUSH

Vacia el búfer de salida del canal especificado, asegurándose de que todos los datos pendientes se escriban en el dispositivo subyacente. Esto es útil para garantizar que los datos se envíen inmediatamente, especialmente en canales interactivos.

Si el vaciado se realiza correctamente, devuelve 0. En caso de error, se establece una entrada de error en interp y se devuelve -1.

TCL_INPUTBLOCKED

Devuelve 1 si la operación de lectura más reciente en el canal especificado se bloqueó (es decir, no había datos disponibles para leer en ese momento), y 0 en caso contrario. Esto es útil para la E/S no bloqueante.

TCL_INPUTBUFFERED

Devuelve el número de bytes que están actualmente en el búfer de entrada del canal especificado y que aún no han sido leídos por la aplicación.

TCL_OUTPUTBUFFERED

Devuelve el número de bytes que están actualmente en el búfer de salida del canal especificado y que aún no se han escrito en el dispositivo subyacente.

TCL_SEEK

Cambia la posición de acceso actual del canal especificado. El nuevo punto de acceso se calcula sumando offset (que puede ser positivo o negativo) a la posición dada por seekMode. Los valores de seekMode son:

  • SEEK_SET: El desplazamiento es relativo al principio del canal.
  • SEEK_CUR: El desplazamiento es relativo a la posición actual del canal.
  • SEEK_END: El desplazamiento es relativo al final del canal.
Devuelve la nueva posición de acceso en el canal, medida en bytes desde el principio del canal. Si se produce un error, devuelve -1.

TCL_TELL

Devuelve la posición de acceso actual del canal especificado, medida en bytes desde el principio del canal.

Si se produce un error, devuelve -1.

TCL_TRUNCATECHANNEL

Recorta el canal especificado a la longitud dada por length. Si la longitud actual del canal es menor que length, el canal se extiende y se rellena con bytes nulos. Este procedimiento solo se puede utilizar en canales que admiten la operación de truncamiento (normalmente archivos).

Si la operación se realiza correctamente, devuelve 0. En caso de error, se establece una entrada de error en interp y se devuelve -1.

TCL_GETCHANNELOPTION

Obtiene el valor de la opción especificada por optionName para el canal dado. El valor de la opción se almacena en la cadena dinámica optionValue. Las opciones disponibles son las mismas que se pueden configurar con el comando Tcl fconfigure (por ejemplo, "-blocking", "-buffering", "-translation").

Si la opción se recupera correctamente, devuelve 0. En caso de error (por ejemplo, si la opción no existe o el canal no la admite), se establece una entrada de error en interp y se devuelve -1.

TCL_SETCHANNELOPTION

Establece el valor de la opción especificada por optionName para el canal dado en newValue. Las opciones disponibles son las mismas que se pueden obtener con Tcl_GetChannelOption.

Si la opción se establece correctamente, devuelve 0. En caso de error (por ejemplo, si la opción no existe, el valor no es válido o el canal no admite la configuración de esta opción), se establece una entrada de error en interp y se devuelve -1.

ESPERANDO DATOS Y FIN DE ARCHIVO

Las funciones Tcl_ReadChars, Tcl_Read, Tcl_GetsObj y Tcl_Gets devuelven un valor que indica si se leyeron datos, si se alcanzó el fin del archivo o si se produjo un error.

  • Un valor positivo indica el número de caracteres o bytes leídos.
  • Un valor de 0 en Tcl_GetsObj o Tcl_Gets indica que se alcanzó el fin del archivo sin leer ningún dato.
  • Un valor devuelto menor que la cantidad solicitada (en Tcl_ReadChars y Tcl_Read) o un valor de 0 (en Tcl_GetsObj y Tcl_Gets) indica que se alcanzó el fin del archivo.
  • Un valor de -1 indica que se produjo un error de E/S. En este caso, se puede obtener más información sobre el error utilizando Tcl_GetErrno o consultando la entrada de error del intérprete.

La función Tcl_Eof se puede utilizar para comprobar explícitamente si se ha alcanzado el final del archivo.

TCL_OPENFILECHANNEL

Tcl_OpenFileChannel abre un archivo especificado por fileName y devuelve un identificador de canal que se puede usar para realizar operaciones de entrada y salida en el archivo. Esta API está modelada según el procedimiento fopen de la biblioteca de E/S estándar de Unix. La sintaxis y el significado de todos los argumentos son similares a los proporcionados en el comando Tcl open al abrir un archivo. Si ocurre un error al abrir el canal, Tcl_OpenFileChannel devuelve NULL y registra un código de error POSIX que se puede recuperar con Tcl_GetErrno. Además, si interp no es NULL, Tcl_OpenFileChannel deja un mensaje de error en el resultado de interp después de cualquier error. A partir de Tcl 8.4, la API basada en valores Tcl_FSOpenFileChannel debe usarse preferentemente a Tcl_OpenFileChannel siempre que sea posible.

El canal recién creado no se registra en el intérprete suministrado; para registrarlo, use Tcl_RegisterChannel, descrito a continuación. Si uno de los canales estándar, stdin, stdout o stderr se cerró previamente, el acto de crear el nuevo canal también lo asigna como reemplazo del canal estándar.

TCL_OPENCOMMANDCHANNEL

Tcl_OpenCommandChannel proporciona una interfaz de nivel C a las funciones de los comandos exec y open. Crea una secuencia de subprocesos especificados por los argumentos argv y argc y devuelve un canal que se puede usar para comunicarse con estos subprocesos. El argumento flags indica qué tipo de comunicación existirá con la canalización de comandos.

Si la bandera TCL_STDIN está establecida, la entrada estándar del primer subproceso se vinculará al canal: escribir en el canal proporcionará entrada al subproceso. Si TCL_STDIN no está establecida, la entrada estándar del primer subproceso será la misma que la entrada estándar de esta aplicación. Si TCL_STDOUT está establecida, la salida estándar del último subproceso se puede leer del canal; de lo contrario, va a la salida estándar de esta aplicación. Si TCL_STDERR está establecida, la salida de error estándar para todos los subprocesos se devuelve al canal y resulta en un error cuando se cierra el canal; de lo contrario, va al error estándar de esta aplicación. Si TCL_ENFORCE_MODE no está establecida, entonces argc y argv pueden redirigir los identificadores de stdio para anular TCL_STDIN, TCL_STDOUT y TCL_STDERR; si está establecida, entonces es un error que argc y argv anulen los canales stdio para los cuales se han establecido TCL_STDIN, TCL_STDOUT y TCL_STDERR.

Si ocurre un error al abrir el canal, Tcl_OpenCommandChannel devuelve NULL y registra un código de error POSIX que se puede recuperar con Tcl_GetErrno. Además, Tcl_OpenCommandChannel deja un mensaje de error en el resultado del intérprete. interp no puede ser NULL.

El canal recién creado no se registra en el intérprete suministrado; para registrarlo, use Tcl_RegisterChannel, descrito a continuación. Si uno de los canales estándar, stdin, stdout o stderr se cerró previamente, el acto de crear el nuevo canal también lo asigna como reemplazo del canal estándar.

TCL_MAKEFILECHANNEL

Tcl_MakeFileChannel crea un Tcl_Channel a partir de un identificador de archivo existente y específico de la plataforma. El canal recién creado no se registra en el intérprete suministrado; para registrarlo, use Tcl_RegisterChannel, descrito a continuación. Si uno de los canales estándar, stdin, stdout o stderr se cerró previamente, el acto de crear el nuevo canal también lo asigna como reemplazo del canal estándar.

TCL_GETCHANNEL

Tcl_GetChannel devuelve un canal dado el channelName utilizado para crearlo con Tcl_CreateChannel y un puntero a un intérprete Tcl en interp. Si no hay un canal con ese nombre registrado en ese intérprete, el procedimiento devuelve NULL. Si el argumento modePtr no es NULL, apunta a una variable entera que recibirá una combinación OR de TCL_READABLE y TCL_WRITABLE que describe si el canal está abierto para lectura y escritura.

Tcl_GetChannelNames y Tcl_GetChannelNamesEx escriben los nombres de los canales registrados en el resultado del intérprete como un valor de lista. Tcl_GetChannelNamesEx filtrará estos nombres según el pattern. Si pattern es NULL, entonces no realizará ningún filtrado. El valor de retorno es TCL_OK si no ocurrieron errores al escribir en el resultado, de lo contrario es TCL_ERROR, y el mensaje de error se deja en el resultado del intérprete.

TCL_REGISTERCHANNEL

Tcl_RegisterChannel agrega un canal al conjunto de canales accesibles en interp. Después de esta llamada, los programas Tcl que se ejecutan en ese intérprete pueden referirse al canal en operaciones de entrada o salida utilizando el nombre dado en la llamada a Tcl_CreateChannel. Después de esta llamada, el canal se convierte en propiedad del intérprete, y el llamador no debe llamar a Tcl_Close para el canal; el canal se cerrará automáticamente cuando se desregistre del intérprete.

El código que se ejecuta fuera de cualquier intérprete Tcl puede llamar a Tcl_RegisterChannel con interp como NULL, para indicar que desea mantener una referencia a este canal. Posteriormente, el canal se puede registrar en un intérprete Tcl y solo se cerrará cuando el número de llamadas coincidentes a Tcl_UnregisterChannel se haya realizado. Esto permite que el código que se ejecuta fuera de cualquier intérprete mantenga de forma segura una referencia a un canal que también está registrado en un intérprete Tcl.

Este procedimiento interactúa con el código que gestiona los canales estándar. Si no se inicializaron canales estándar antes de la primera llamada a Tcl_RegisterChannel, se inicializarán con esa llamada. Vea Tcl_StandardChannels para un tratado general sobre los canales estándar y el comportamiento de la biblioteca Tcl con respecto a ellos.

TCL_UNREGISTERCHANNEL

Tcl_UnregisterChannel elimina un canal del conjunto de canales accesibles en interp. Después de esta llamada, los programas Tcl ya no podrán utilizar el nombre del canal para referirse al canal en ese intérprete. Si esta operación eliminó el último registro del canal en cualquier intérprete, el canal también se cierra y se destruye.

El código no asociado con un intérprete Tcl puede llamar a Tcl_UnregisterChannel con interp como NULL, para indicar a Tcl que ya no tiene una referencia a ese canal. Si esta es la última referencia al canal, ahora se cerrará. Tcl_UnregisterChannel es muy similar a Tcl_DetachChannel, excepto que también cerrará el canal si no existen más referencias a él.

TCL_DETACHCHANNEL

Tcl_DetachChannel elimina un canal del conjunto de canales accesibles en interp. Después de esta llamada, los programas Tcl ya no podrán utilizar el nombre del canal para referirse al canal en ese intérprete. Más allá de eso, este comando no tiene ningún otro efecto. No se puede utilizar en los canales estándar (stdout, stderr, stdin), y devolverá TCL_ERROR si se le pasa uno de esos canales.

El código no asociado con un intérprete Tcl puede llamar a Tcl_DetachChannel con interp como NULL, para indicar a Tcl que ya no tiene una referencia a ese canal. Si esta es la última referencia al canal, a diferencia de Tcl_UnregisterChannel, no se cerrará.

TCL_ISSTANDARDCHANNEL

Tcl_IsStandardChannel prueba si un canal es uno de los tres canales estándar, stdin, stdout o stderr. Si es así, devuelve 1, de lo contrario 0.

No se intenta verificar si el canal dado o los canales estándar están inicializados o son válidos de otra manera.

TCL_CLOSE

Tcl_Close destruye el canal channel, que debe denotar un canal actualmente abierto. El canal no debe estar registrado en ningún intérprete cuando se llama a Tcl_Close. La salida en búfer se descarga en el dispositivo de salida del canal antes de destruir el canal, y cualquier entrada en búfer se descarta. Si este es un canal bloqueante, la llamada no regresa hasta que todos los datos en búfer se envíen exitosamente al dispositivo de salida del canal. Si este es un canal no bloqueante y hay salida en búfer que no se puede escribir sin bloquear, la llamada regresa inmediatamente; la salida se descarga en segundo plano y el canal se cerrará una vez que todos los datos en búfer se hayan enviado. En este caso, los errores durante la descarga no se informan.

Si el canal se cerró correctamente, Tcl_Close devuelve TCL_OK. Si ocurre un error, Tcl_Close devuelve TCL_ERROR y registra un código de error POSIX que se puede recuperar con Tcl_GetErrno. Si el canal se está cerrando de forma síncrona y ocurre un error durante el cierre del canal y interp no es NULL, se deja un mensaje de error en el resultado del intérprete.

Nota: no es seguro llamar a Tcl_Close en un canal que se ha registrado usando Tcl_RegisterChannel; vea la documentación para Tcl_RegisterChannel, arriba, para más detalles. Si el canal se ha proporcionado alguna vez como el argumento chan en una llamada a Tcl_RegisterChannel, debería usar Tcl_UnregisterChannel en su lugar, que llamará internamente a Tcl_Close cuando todas las llamadas a Tcl_RegisterChannel hayan sido igualadas por las llamadas correspondientes a Tcl_UnregisterChannel.

TCL_READCHARS Y TCL_READ

Tcl_ReadChars consume bytes del channel, convirtiendo los bytes a UTF-8 basándose en la codificación del canal y almacenando los datos producidos en la representación de cadena de readObjPtr. El valor de retorno de Tcl_ReadChars es el número de caracteres, hasta charsToRead, que se almacenaron en readObjPtr. Si ocurre un error al leer, el valor de retorno es -1 y Tcl_ReadChars registra un código de error POSIX que se puede recuperar con Tcl_GetErrno.

Establecer charsToRead

TCL_READCHARS AND TCL_READ

reading a -1 causará que el comando lea todos los caracteres actualmente disponibles (no bloqueante) o todo hasta eof (modo bloqueante).

El valor de retorno puede ser menor que el valor a leer, indicando que había menos datos de los solicitados disponibles. Esto se llama una lectura corta. En modo bloqueante, esto solo puede ocurrir en un fin de archivo. En modo no bloqueante, una lectura corta también puede ocurrir si no hay suficiente entrada actualmente disponible: Tcl_ReadChars devuelve un recuento corto en lugar de esperar más datos.

Si el canal está en modo bloqueante, un valor de retorno de cero indica una condición de fin de archivo. Si el canal está en modo no bloqueante, un valor de retorno de cero indica que no hay entrada actualmente disponible o una condición de fin de archivo. Utilice Tcl_Eof y Tcl_InputBlocked para saber cuál de estas condiciones ocurrió realmente.

Tcl_ReadChars traduce las diversas representaciones de fin de línea a la representación interna canónica de \n según el modo de reconocimiento de fin de línea actual. El reconocimiento de fin de línea y los diversos modos específicos de plataforma se describen en la entrada del manual para el comando Tcl fconfigure.

Como optimización de rendimiento, al leer de un canal con la codificación binary, los bytes no se convierten a UTF-8 a medida que se leen. En su lugar, se almacenan en la representación interna de readObjPtr como un valor de matriz de bytes. La representación de cadena de este valor solo se construirá si es necesario (por ejemplo, debido a una llamada a Tcl_GetStringFromObj). De esta manera, los datos orientados a bytes se pueden leer de un canal, manipular llamando a Tcl_GetByteArrayFromObj y funciones relacionadas, y luego escribir en un canal sin el costo de la conversión a UTF-8 o desde UTF-8.

Tcl_Read es similar a Tcl_ReadChars, excepto que no realiza conversiones de codificación, independientemente de la codificación del canal. Está obsoleto y existe para compatibilidad retroactiva con extensiones Tcl no internacionalizadas. Consume bytes de channel y los almacena en readBuf, realizando traducciones de fin de línea en el camino. El valor de retorno de Tcl_Read es el número de bytes, hasta bytesToRead, escritos en readBuf. El búfer producido por Tcl_Read no está terminado en nulo. Su contenido es válido desde la posición cero hasta la posición indicada por el valor de retorno, sin incluirla.

Tcl_ReadRaw es lo mismo que Tcl_Read pero no se compensa por el apilamiento. Mientras que Tcl_Read (y las otras funciones de la API) siempre obtienen sus datos del canal superior en la pila de la que forma parte el canal proporcionado, Tcl_ReadRaw no lo hace. Por lo tanto, esta función solo es utilizable para controladores de canal transformacionales, es decir, controladores utilizados en medio de una pila de canales, para mover datos del canal inferior a la transformación.

TCL_GETSOBJ Y TCL_GETS

Tcl_GetsObj consume bytes del channel, convirtiendo los bytes a UTF-8 basándose en la codificación del canal, hasta que se ha visto una línea completa de entrada. Si la codificación del canal es binary, cada byte leído del canal se trata como un carácter Unicode individual. Todos los caracteres de la línea, excepto los caracteres de fin de línea terminadores, se añaden a la representación de cadena de lineObjPtr. Los caracteres de fin de línea se leen y se descartan.

Si se leyó una línea con éxito, el valor de retorno es mayor o igual a cero e indica el número de bytes almacenados en lineObjPtr. Si ocurre un error, Tcl_GetsObj devuelve -1 y registra un código de error POSIX que puede recuperarse con Tcl_GetErrno. Tcl_GetsObj también devuelve -1 si se llega al final del archivo; el procedimiento Tcl_Eof se puede utilizar para distinguir un error de una condición de fin de archivo.

Si el canal está en modo no bloqueante, el valor de retorno también puede ser -1 si no había datos disponibles o si los datos disponibles no contenían un carácter de fin de línea. Cuando se devuelve -1, el procedimiento Tcl_InputBlocked puede invocarse para determinar si el canal está bloqueado debido a la indisponibilidad de entrada.

Tcl_Gets es lo mismo que Tcl_GetsObj excepto que los caracteres resultantes se añaden a la cadena dinámica dada por lineRead en lugar de un valor Tcl.

TCL_UNGETS

Tcl_Ungets se utiliza para añadir datos a la cola de entrada de un canal, ya sea al principio o al final de la cola. El puntero input apunta a los datos que se van a añadir. La longitud de la entrada a añadir está dada por inputLen. Un valor distinto de cero de addAtEnd indica que los datos se añadirán al final de la cola; de lo contrario, se añadirán al principio de la cola. Si channel tiene un fin de archivo "pegajoso" establecido, no se añadirán datos a la cola de entrada. Tcl_Ungets devuelve inputLen o -1 si ocurre un error.

TCL_WRITECHARS, TCL_WRITEOBJ, Y TCL_WRITE

Tcl_WriteChars acepta bytesToWrite bytes de datos de caracteres en charBuf. Los caracteres UTF-8 en el búfer se convierten a la codificación del canal y se ponen en cola para su salida al channel. Si bytesToWrite es negativo, Tcl_WriteChars espera que charBuf esté terminado en nulo y saca todo hasta el nulo.

Los datos puestos en cola para la salida pueden no aparecer en el dispositivo de salida inmediatamente, debido al almacenamiento en búfer interno. Si los datos deben aparecer inmediatamente, llame a Tcl_Flush después de la llamada a Tcl_WriteChars, o establezca la opción -buffering en el canal a none. Si desea que los datos aparezcan tan pronto como se acepte una línea completa para la salida, establezca la opción -buffering en el canal en modo line.

El valor de retorno de Tcl_WriteChars es un recuento de cuántos bytes se aceptaron para la salida al canal. Es mayor que cero para indicar éxito o -1 para indicar que ocurrió un error. Si ocurre un error, Tcl_WriteChars registra un código de error POSIX que puede recuperarse con Tcl_GetErrno.

Los caracteres de nueva línea en los datos de salida se traducen a secuencias de fin de línea específicas de la plataforma según la opción -translation para el canal. Esto se hace incluso si el canal no tiene codificación.

Tcl_WriteObj es similar a Tcl_WriteChars excepto que acepta un valor Tcl cuyos contenidos se sacarán al canal. Los caracteres UTF-8 en la representación de cadena de writeObjPtr se convierten a la codificación del canal y se ponen en cola para su salida al channel. Como optimización de rendimiento, al escribir en un canal con la codificación binary, los caracteres UTF-8 no se convierten a medida que se escriben. En su lugar, los bytes en la representación interna de writeObjPtr como un valor de matriz de bytes se escriben en el canal. La representación de matriz de bytes del valor se construirá si es necesario. De esta manera, los datos orientados a bytes se pueden leer de un canal, manipular llamando a Tcl_GetByteArrayFromObj y funciones relacionadas, y luego escribir en un canal sin el costo de la conversión a UTF-8 o desde UTF-8.

Tcl_Write es similar a Tcl_WriteChars excepto que no realiza conversiones de codificación, independientemente de la codificación del canal. Está obsoleto y existe para compatibilidad retroactiva con extensiones Tcl no internacionalizadas. Acepta bytesToWrite bytes de datos en byteBuf y los pone en cola para su salida al channel. Si bytesToWrite es negativo, Tcl_Write espera que byteBuf esté terminado en nulo y saca todo hasta el nulo.

Tcl_WriteRaw es lo mismo que Tcl_Write pero no se compensa por el apilamiento. Mientras que Tcl_Write (y las otras funciones de la API) siempre alimentan su entrada al canal superior en la pila de la que forma parte el canal proporcionado, Tcl_WriteRaw no lo hace. Por lo tanto, esta función solo es utilizable para controladores de canal transformacionales, es decir, controladores utilizados en medio de una pila de canales, para mover datos de la transformación al canal inferior.

TCL_FLUSH

Tcl_Flush hace que todos los datos de salida en búfer para el channel se escriban en su archivo o dispositivo subyacente tan pronto como sea posible. Si el canal está en modo bloqueante, la llamada no regresa hasta que todos los datos en búfer se hayan enviado al canal o haya ocurrido algún error. La llamada regresa inmediatamente si el canal no está bloqueante; inicia un volcado en segundo plano que escribirá los datos en búfer al canal eventualmente, tan rápido como el canal pueda absorberlos.

El valor de retorno es normalmente TCL_OK. Si ocurre un error, Tcl_Flush devuelve TCL_ERROR y registra un código de error POSIX que puede recuperarse con Tcl_GetErrno.

TCL_SEEK

Tcl_Seek mueve el punto de acceso en el channel donde se leerán o escribirán datos posteriores. La salida en búfer se vacía al canal y la entrada en búfer se descarta, antes de la operación de búsqueda.

Tcl_Seek normalmente devuelve el nuevo punto de acceso. Si ocurre un error, Tcl_Seek devuelve -1 y registra un código de error POSIX que puede recuperarse con Tcl_GetErrno. Después de un error, el punto de acceso puede o no haberse movido.

TCL_TELL

Tcl_Tell devuelve el punto de acceso actual para un canal. El valor devuelto es -1 si el canal no admite la búsqueda.

TCL_TRUNCATECHANNEL

Tcl_TruncateChannel trunca el archivo subyacente del channel a una longitud dada de length bytes. Devuelve TCL_OK si la operación tuvo éxito, y TCL_ERROR en caso contrario.

TCL_GETCHANNELOPTION

El argumento channel identifica el canal para el que se consulta una opción o se recuperan todas las opciones y sus valores. Si optionName no es NULL, es el nombre de la opción a consultar; el valor de la opción se copia a la cadena dinámica Tcl denotada por optionValue. TCL_GETCHANNELOPTION

Tcl_GetChannelOption returns the current value of the option optionName for channel. The value is returned in the DString value; the caller is responsible for initializing and freeing this DString. The procedure may make a series of calls to Tcl_DStringAppendElement. The various preexisting options and their possible values are described in the manual entry for the Tcl fconfigure command. Other options can be added by each channel type. These channel type specific options are described in the manual entry for the Tcl command that creates a channel of that type; for example, the additional options for TCP-based channels are described in the manual entry for the Tcl socket command. The procedure normally returns TCL_OK. If an error occurs, it returns TCL_ERROR and calls Tcl_SetErrno to store an appropriate POSIX error code.

TCL_SETCHANNELOPTION

Tcl_SetChannelOption sets a new value newValue for an option optionName on channel. The procedure normally returns TCL_OK. If an error occurs, it returns TCL_ERROR; in addition, if interp is non-NULL, Tcl_SetChannelOption leaves an error message in the interpreter's result.

TCL_EOF

Tcl_Eof returns a nonzero value if channel encountered an end of file during the last input operation.

TCL_INPUTBLOCKED

Tcl_InputBlocked returns a nonzero value if channel is in nonblocking mode and the last input operation returned less data than requested because there was insufficient data available. The call always returns zero if the channel is in blocking mode.

TCL_INPUTBUFFERED

Tcl_InputBuffered returns the number of bytes of input currently buffered in the internal buffers for a channel. If the channel is not open for reading, this function always returns zero.

TCL_OUTPUTBUFFERED

Tcl_OutputBuffered returns the number of bytes of output currently buffered in the internal buffers for a channel. If the channel is not open for writing, this function always returns zero.

PLATFORM ISSUES

The handles returned from Tcl_GetChannelHandle depend on the platform and the channel type. On Unix platforms, the handle is always a Unix file descriptor as returned from the open system call. On Windows platforms, the handle is a file HANDLE when the channel was created with Tcl_OpenFileChannel, Tcl_OpenCommandChannel, or Tcl_MakeFileChannel. Other channel types may return a different type of handle on Windows platforms.
