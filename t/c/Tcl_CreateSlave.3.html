DESCRIPCIÓN

Estos procedimientos están pensados para acceder a la instalación de múltiples intérpretes desde programas C. Permiten gestionar múltiples intérpretes en una relación jerárquica y la gestión de alias, comandos que, al invocarse en un intérprete, ejecutan un comando en otro intérprete. El valor de retorno para aquellos procedimientos que devuelven un int es ya sea TCL_OK o TCL_ERROR. Si se devuelve TCL_ERROR, el resultado del intérprete contiene un mensaje de error.

Tcl_CreateSlave crea un nuevo intérprete como hijo de interp. También crea un comando hijo llamado childName en interp que permite a interp manipular al nuevo hijo. Si isSafe es cero, el comando crea un hijo confiable en el que el código Tcl tiene acceso a todos los comandos Tcl. Si es 1, el comando crea un hijo "seguro" en el que el código Tcl solo tiene acceso a un conjunto de comandos Tcl definidos como "Safe Tcl"; consulte la entrada del manual para el comando interp de Tcl para obtener detalles. Si la creación del nuevo intérprete hijo falló, se devuelve NULL.

Tcl_CreateChild es un sinónimo de Tcl_CreateSlave.

Tcl_IsSafe devuelve 1 si interp es "seguro" (fue creado con el indicador TCL_SAFE_INTERPRETER especificado), 0 en caso contrario.

Tcl_MakeSafe marca interp como "seguro", para que futuras llamadas a Tcl_IsSafe devuelvan 1. También elimina toda la funcionalidad central potencialmente insegura conocida (comandos y variables) de interp. Sin embargo, no puede saber qué partes de una extensión o aplicación son seguras y no intenta eliminar esas partes, por lo que la seguridad no está garantizada después de llamar a Tcl_MakeSafe. Los llamantes querrán tener cuidado con su uso de Tcl_MakeSafe para evitar falsas afirmaciones de seguridad. Para muchas situaciones, Tcl_CreateSlave puede ser una mejor opción, ya que crea intérpretes en un estado seguro conocido.

Tcl_GetSlave devuelve un puntero a un intérprete hijo de interp. El intérprete hijo se identifica por childName. Si no existe tal intérprete hijo, se devuelve NULL.

Tcl_GetChild es un sinónimo de Tcl_GetSlave.

Tcl_GetMaster devuelve un puntero al intérprete maestro de interp. Si interp no tiene maestro (es un intérprete de nivel superior), se devuelve NULL.

Tcl_GetParent es un sinónimo de Tcl_GetMaster.

Tcl_GetInterpPath almacena en el resultado de interp la ruta relativa entre interp y childInterp; childInterp debe ser un hijo de interp. Si el cálculo de la ruta relativa tiene éxito, se devuelve TCL_OK, de lo contrario se devuelve TCL_ERROR y se almacena un mensaje de error como resultado de interp.

Tcl_CreateAlias crea un comando llamado childCmd en childInterp que, al invocarse, hará que el comando targetCmd se invoque en targetInterp. Los argumentos especificados por las cadenas contenidas en argv se anteponen siempre a cualquier argumento proporcionado en la invocación de childCmd y se pasan a targetCmd. Esta operación devuelve TCL_OK si tiene éxito, o TCL_ERROR si falla; en ese caso, se deja un mensaje de error en el resultado de valor de childInterp. Tenga en cuenta que no hay restricciones en la relación de ascendencia (tal como se crea por Tcl_CreateSlave) entre childInterp y targetInterp. Se pueden usar dos intérpretes cualesquiera, sin restricciones sobre cómo están relacionados.

Tcl_CreateAliasObj es similar a Tcl_CreateAlias excepto que toma un vector de valores para pasar como argumentos adicionales en lugar de un vector de cadenas.

Tcl_GetAliasObj devuelve información en forma de un puntero a un vector de estructuras Tcl_Obj sobre un alias aliasName en interp. Cualquiera de los campos de resultado puede ser NULL, en cuyo caso el dato correspondiente no se devuelve. Si un campo de resultado no es NULL, se establece la dirección indicada al dato correspondiente. Por ejemplo, si targetCmdPtr no es NULL, se establece a un puntero a la cadena que contiene el nombre del comando de destino.

Tcl_GetAlias es similar a Tcl_GetAliasObj excepto que devuelve un puntero a un vector de cadenas en lugar de un vector de estructuras Tcl_Obj. Tcl_GetAlias está obsoleto

NAME

Tcl_CreateSlave, Tcl_DeleteSlave, Tcl_GetSlave, Tcl_HideCommand, Tcl_ExposeCommand - create, manage, and control interpreters

SYNOPSIS

#include <tcl.h>

Tcl_Interp *
Tcl_CreateSlave(Tcl_Interp *interp, const char *slaveName, Tcl_CmdProc *deleteProc, ClientData clientData);

int
Tcl_DeleteSlave(Tcl_Interp *interp, const char *slaveName, int assertDeleted);

Tcl_Interp *
Tcl_GetSlave(Tcl_Interp *interp, const char *slaveName);

int
Tcl_HideCommand(Tcl_Interp *interp, const char *cmdName, const char *hiddenCmdName);

int
Tcl_ExposeCommand(Tcl_Interp *interp, const char *hiddenCmdName, const char *cmdName);

ARGUMENTS

interp
Interpreters for which to create a slave, or the interpreter in which to hide or expose a command.
slaveName
Name for the new slave interpreter or name of an existing slave interpreter.
deleteProc
Procedure to call when the slave interpreter is deleted.
clientData
Arbitrary data to pass to deleteProc.
assertDeleted
If non-zero, cause an error if the slave is not empty.
cmdName
The name of an exposed command.
hiddenCmdName
The name of a hidden command.

DESCRIPTION

A Tcl interpreter can contain other Tcl interpreters as children. Such children are called slaves, and the parent interpreter is called the master. Tcl provides mechanisms for creating, destroying, and managing these interpeter relationships. It also provides mechanisms for controlling the visibility of commands within an interpreter.

Tcl_CreateSlave creates a new Tcl interpreter which is a slave to the interpreter named by interp. The new interpreter is created with the name slaveName within the master interpreter. The master interpreter will have a command named slaveName which, when invoked, will invoke the Tcl interpreter execution engine within the newly created slave interpreter. If deleteProc is non-NULL, then this procedure will be called with clientData as its argument just before the slave interpreter is destroyed. This procedure should perform any cleanup actions required for the slave interpreter, such as freeing any resources that were allocated when the slave was created. The initial state of the slave interpreter is a copy of the master interpreter, except that it has no commands defined in it other than the command used to execute scripts within it. If slaveName is already in use as a command name in interp, then Tcl_CreateSlave returns NULL and leaves an error message in interp's result. Otherwise, it returns a pointer to the newly created slave interpreter.

Tcl_DeleteSlave destroys the slave interpreter named slaveName within the interpreter interp. If assertDeleted is non-zero, an error is raised if the slave interpreter contains any commands (i.e., if it is not empty). This is a useful safety check to prevent accidental destruction of slave interpreters that are still in use. If deleteProc was specified when the slave was created (see Tcl_CreateSlave), it is called before the slave is destroyed. After the slave interpreter is destroyed, the command used to invoke it in the master interpreter is also removed.

Tcl_GetSlave returns a pointer to the slave interpreter named slaveName within the interpreter interp. If no slave with that name exists, it returns NULL.

By default, all commands defined in a Tcl interpreter are available for execution within that interpreter. It is possible, however, to hide commands from the interpreter's command table. This is useful when you want to provide access to a command in a child interpreter but don't want the command to be generally available.

Tcl_HideCommand moves the command named cmdName from the set of exposed commands to the set of hidden commands, renaming it to hiddenCmdName. CmdName must be the name of an existing exposed command, or the operation will return TCL_ERROR and leave an error message as the result of interp. Currently both cmdName and hiddenCmdName must not contain namespace qualifiers, or the operation will return TCL_ERROR and leave an error message as the result of interp. The CmdName will be looked up in the global namespace, and not relative to the current namespace, even if the current namespace is not the global one. If a hidden command named hiddenCmdName already exists, the operation also returns TCL_ERROR and an error message is left as the result of interp. If the operation succeeds, it returns TCL_OK. After executing this command, attempts to use cmdName in any script evaluation mechanism will fail.

Tcl_ExposeCommand moves the command named hiddenCmdName from the set of hidden commands to the set of exposed commands, renaming it to cmdName. HiddenCmdName must be the name of an existing hidden command, or the operation will return TCL_ERROR and leave an error message as the result of interp. If an exposed command named cmdName already exists, the operation returns TCL_ERROR and leaves an error message as the result of interp. If the operation succeeds, it returns TCL_OK. After executing this command, attempts to use cmdName in any script evaluation mechanism will again succeed.

For a description of the Tcl interface to multiple interpreters, see interp(n).
