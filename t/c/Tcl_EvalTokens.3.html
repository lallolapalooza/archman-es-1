Tcl_ParseCommand(3) Procedimientos de la biblioteca Tcl Tcl_ParseCommand(3)

NOMBRE

Tcl_ParseCommand, Tcl_ParseExpr, Tcl_ParseBraces, Tcl_ParseQuotedString, Tcl_ParseVarName, Tcl_ParseVar, Tcl_FreeParse, Tcl_EvalTokens, Tcl_EvalTokensStandard - analizar scripts y expresiones Tcl

SINOPSIS

#include <tcl.h>

int
Tcl_ParseCommand(interp, start, numBytes, nested, parsePtr)

int
Tcl_ParseExpr(interp, start, numBytes, parsePtr)

int
Tcl_ParseBraces(interp, start, numBytes, parsePtr, append, termPtr)

int
Tcl_ParseQuotedString(interp, start, numBytes, parsePtr, append, termPtr)

int
Tcl_ParseVarName(interp, start, numBytes, parsePtr, append)

const char *
Tcl_ParseVar(interp, start, termPtr)

Tcl_FreeParse(usedParsePtr)

Tcl_Obj *
Tcl_EvalTokens(interp, tokenPtr, numTokens)

int
Tcl_EvalTokensStandard(interp, tokenPtr, numTokens)

ARGUMENTOS

Tcl_Interp *interp (salida)
Para procedimientos distintos de Tcl_FreeParse, Tcl_EvalTokens y Tcl_EvalTokensStandard, se usa solo para reportar errores; si es NULL, no se dejarán mensajes de error después de los errores. Para Tcl_EvalTokens y Tcl_EvalTokensStandard, determina el contexto para evaluar el script y también se usa para reportar errores; no debe ser NULL.
const char *start (entrada)
Puntero al primer carácter en la cadena a analizar.
int numBytes (entrada)
Número de bytes en la cadena a analizar, sin incluir el carácter nulo. Si es menor que 0, el script consiste en todos los caracteres siguientes a start hasta el primer carácter nulo.
int nested (entrada)
Si es distinto de cero, significa que el script es parte de una sustitución de comando, por lo que un corchete de cierre sin comillas debe tratarse como un terminador de comando. Si es cero, los corchetes de cierre no tienen un significado especial.
int append (entrada)
Si es distinto de cero, significa que *parsePtr ya contiene tokens válidos; los nuevos tokens deben agregarse a los existentes. Si es cero, *parsePtr se inicializa; cualquier información en él se ignora. Este argumento es normalmente 0.
Tcl_Parse *parsePtr (salida)
Puntero a la estructura que se llenará con información sobre el comando analizado, la expresión, el nombre de la variable, etc. Cualquier información previa en esta estructura se ignora, a menos que append sea distinto de cero en una llamada a Tcl_ParseBraces, Tcl_ParseQuotedString o Tcl_ParseVarName.
const char **termPtr (salida)
Si no es NULL, apunta a un lugar donde Tcl_ParseBraces, Tcl_ParseQuotedString y Tcl_ParseVar almacenarán un puntero al carácter después del carácter de terminación (el corchete de cierre, el último carácter del nombre de la variable o el comilla de cierre, respectivamente) si el análisis fue exitoso.
Tcl_Parse *usedParsePtr (entrada)
Puntero a la estructura que fue llenada por una llamada previa a Tcl_ParseCommand, Tcl_ParseExpr, Tcl_ParseVarName, etc.

DESCRIPCIÓN

Estos procedimientos analizan comandos Tcl o partes de comandos Tcl, como expresiones o referencias a variables. Cada procedimiento toma un puntero a un script (o parte de él) y llena la estructura apuntada por parsePtr con una colección de tokens que describen la información analizada. Los procedimientos normalmente devuelven TCL_OK. Sin embargo, si ocurre un error, devuelven TCL_ERROR, dejan un mensaje de error en el resultado de interp (si interp no es NULL) y no dejan nada en *parsePtr.

Tcl_ParseCommand es un procedimiento que analiza scripts Tcl. Dado un puntero a un script, lo analiza primero. Si el comando se analizó correctamente, Tcl_ParseCommand devuelve TCL_OK y llena la estructura apuntada por parsePtr con información sobre la estructura del comando (ver detalles más adelante). Si ocurrió un error al analizar el comando, devuelve TCL_ERROR, deja un mensaje de error en el resultado de interp y no deja nada en *parsePtr.

Tcl_ParseExpr analiza expresiones Tcl. Dado un puntero a un script que contiene una expresión, Tcl_ParseExpr analiza la expresión. Si la expresión se analizó correctamente, devuelve TCL_OK y llena la estructura apuntada por parsePtr con información sobre la estructura de la expresión (ver detalles más adelante). Si ocurre un error al analizar, devuelve TCL_ERROR, deja un mensaje de error en el resultado de interp y no deja nada en *parsePtr.

Tcl_ParseBraces analiza una cadena o argumento de comando encerrado entre corchetes, como {hola} o {cadena \t con \t tabulaciones}, comenzando desde el principio de su argumento start. El primer carácter de start debe ser {. Si la cadena encerrada entre corchetes se analizó correctamente, Tcl_ParseBraces devuelve TCL_OK, llenando la estructura apuntada por parsePtr con información sobre la estructura de la cadena (ver detalles más adelante) y almacena un puntero al carácter después del corchete de cierre en el lugar proporcionado por *termPtr. Si ocurre un error durante el análisis, devuelve TCL_ERROR, deja un mensaje de error en el resultado de interp y no deja nada en *parsePtr o *termPtr.

Tcl_ParseQuotedString analiza una cadena entre comillas dobles como "la suma es [expr {$a+$b}]" comenzando desde el principio del argumento start. El primer carácter de start debe ser ". Si la cadena entre comillas dobles se analizó correctamente, Tcl_ParseQuotedString devuelve TCL_OK, llenando la estructura apuntada por parsePtr con información sobre la estructura de la cadena (ver detalles más adelante) y almacena un puntero al carácter después del comilla de cierre en el lugar proporcionado por *termPtr. Si ocurre un error durante el análisis, devuelve TCL_ERROR, deja un mensaje de error en el resultado de interp y no deja nada en *parsePtr o *termPtr.

Tcl_ParseVarName analiza una referencia a una variable Tcl como $abc o $x([expr {$indice + 1}]), comenzando desde el principio de su argumento start. El primer carácter de start debe ser $. Si una variable se analizó correctamente, Tcl_ParseVarName devuelve TCL_OK y llena la estructura apuntada por parsePtr con información sobre la estructura de la variable (ver detalles más adelante). Si ocurre un error durante el análisis, devuelve TCL_ERROR, deja un mensaje de error en el resultado de interp (si interp no es NULL) y no deja nada en *parsePtr.

Tcl_ParseVar analiza una referencia a una variable Tcl como $abc o $x([expr {$indice + 1}]), comenzando desde el principio de su argumento start. El primer carácter de start debe ser $. Si la variable se analizó correctamente, devuelve un puntero al valor de la variable. Si ocurre un error durante el análisis, devuelve NULL y deja un mensaje de error en el resultado de interp.

La información en *parsePtr de Tcl_ParseCommand, Tcl_ParseExpr, Tcl_ParseBraces, Tcl_ParseQuotedString y Tcl_ParseVarName puede incluir memoria dinámica. Si estos cinco procedimientos de análisis devuelven TCL_OK, el llamador debe invocar Tcl_FreeParse para liberar la memoria en *parsePtr. Estos procedimientos ignoran cualquier información existente en *parsePtr (a menos que append sea distinto de cero), por lo que si se realizan varias llamadas a ellos, debe invocar Tcl_FreeParse una vez después de cada llamada.

Tcl_EvalTokensStandard evalúa una secuencia de tokens analizados de una estructura Tcl. Los tokens suelen consistir en todos los tokens de una palabra o todos los tokens que componen el índice de una referencia a una variable de matriz. Tcl_EvalTokensStandard realiza las sustituciones solicitadas por los tokens y concatena los valores resultantes. El valor de retorno de Tcl_EvalTokensStandard es un código de finalización Tcl con uno de los valores TCL_OK, TCL_ERROR, TCL_RETURN, TCL_BREAK o TCL_CONTINUE, o puede ser otro valor entero que proviene de una extensión. Además, se deja un valor de resultado o mensaje de error en el resultado de interp; este puede ser recuperado usando Tcl_GetObjResult.

Tcl_EvalTokens difiere de Tcl_EvalTokensStandard solo en la convención de retorno.

ESTRUCTURA TCL_PARSE

Tcl_ParseCommand, Tcl_ParseExpr, Tcl_ParseBraces, Tcl_ParseQuotedString y Tcl_ParseVarName devuelven información de análisis en dos estructuras de datos, Tcl_Parse y Tcl_Token:

typedef struct Tcl_Parse {
    const char *commentStart;
    int commentSize;
    const char *commandStart;
    int commandSize;
    int numWords;
    Tcl_Token *tokenPtr;
    int numTokens;
    ...
} Tcl_Parse;
typedef struct Tcl_Token {
    int type;
    const char *start;
    int size;
    int numComponents;
} Tcl_Token;

Los primeros cinco campos de una estructura Tcl_Parse se rellenan únicamente por Tcl_ParseCommand. Estos campos no son utilizados por los otros procedimientos de análisis.

Tcl_ParseCommand rellena una estructura Tcl_Parse con información que describe un comando Tcl y cualquier comentario que preceda al comando. Si hay comentarios, el campo commentStart apunta al carácter # que inicia el primer comentario y commentSize indica el número de bytes en todos los comentarios que preceden al comando, incluido el carácter de nueva línea que termina el último comentario. Si el comando no va precedido de ningún comentario, commentSize es 0. Tcl_ParseCommand también establece el campo commandStart para que apunte al primer carácter de la primera palabra del comando (saltándose cualquier comentario y espacios en blanco iniciales) y commandSize da el número total de bytes en el comando, incluido el carácter al que apunta commandStart hasta e incluyendo el carácter de nueva línea, corchete de cierre o punto y coma que termina el comando. El campo numWords da el número total de palabras en el comando.

Todos los procedimientos de análisis establecen los campos restantes, tokenPtr y numTokens. El campo tokenPtr apunta al primer elemento de un array de estructuras Tcl_Token que describen los componentes de la entidad que se está analizando. El campo numTokens da el número total de tokens presentes en el array. Cada token contiene cuatro campos. El campo type selecciona uno de varios tipos de tokens que se describen a continuación. El campo start apunta al primer carácter del token y el campo size da el número total de caracteres del token. Algunos tipos de tokens, como TCL_TOKEN_WORD y TCL_TOKEN_VARIABLE, consisten en varios tokens componentes, que siguen inmediatamente al token padre; el campo numComponents describe cuántos de estos hay. El campo type tiene uno de los siguientes valores:

TCL_TOKEN_WORD
Este token normalmente describe una palabra de un comando, pero también puede describir una cadena entre comillas o llaves en una expresión. El token describe un componente del script que es el resultado de concatenar una secuencia de subcomponentes, cada uno descrito por un subtoken separado. El token comienza con el primer carácter que no es un espacio en blanco del componente (que puede ser una comilla doble o una llave de apertura) y incluye todos los caracteres del componente hasta, pero sin incluir, el espacio, el punto y coma, el corchete de cierre, la comilla de cierre o la llave de cierre que terminan el componente. El campo numComponents cuenta el número total de subtokens que componen la palabra, incluidos los subtokens de tokens TCL_TOKEN_VARIABLE y TCL_TOKEN_BS.
TCL_TOKEN_SIMPLE_WORD
Este token tiene el mismo significado que TCL_TOKEN_WORD, excepto que la palabra está garantizada para consistir en un solo subtoken TCL_TOKEN_TEXT. El campo numComponents es siempre 1.
TCL_TOKEN_EXPAND_WORD
Este token tiene el mismo significado que TCL_TOKEN_WORD, excepto que el analizador de comandos observa que esta palabra comenzó con el prefijo de expansión {*}, indicando que después de la sustitución, el valor de lista de esta palabra debe ser expandido para formar múltiples argumentos en la evaluación del comando. Este tipo de token solo puede ser creado por Tcl_ParseCommand.
TCL_TOKEN_TEXT
El token describe un rango de texto literal que forma parte de una palabra. El campo numComponents es siempre 0.
TCL_TOKEN_BS
El token describe una secuencia de barra invertida, como \n o \0xA3. El campo numComponents es siempre 0.
TCL_TOKEN_COMMAND
El token describe un comando cuyo resultado debe ser sustituido en la palabra. El token incluye los corchetes que rodean al comando. El campo numComponents es siempre 0 (el comando anidado no se analiza; llame a Tcl_ParseCommand recursivamente si desea ver sus tokens).
TCL_TOKEN_VARIABLE
El token describe una sustitución de variable, incluyendo el $, el nombre de la variable y el índice del array (si lo hay) hasta el paréntesis de cierre que termina el índice. Este token va seguido de uno o más tokens adicionales que describen el nombre de la variable y el índice del array. Si numComponents es 1, entonces la variable es escalar y el siguiente token es un token TCL_TOKEN_TEXT que proporciona el nombre de la variable. Si numComponents es mayor que 1, entonces la variable es un array: el primer subtoken es un token TCL_TOKEN_TEXT que proporciona el nombre del array y los tokens restantes son tokens TCL_TOKEN_TEXT, TCL_TOKEN_BS, TCL_TOKEN_COMMAND y TCL_TOKEN_VARIABLE que deben concatenarse para producir el índice del array. El campo numComponents incluye subtokens anidados que forman parte de tokens TCL_TOKEN_VARIABLE en el índice del array.
TCL_TOKEN_SUB_EXPR
El token describe una subexpresión de una expresión (o una expresión completa). Una subexpresión puede consistir en un valor como un literal entero, una sustitución de variable o una subexpresión entre paréntesis; también puede consistir en un operador y sus operandos. El token comienza con el primer carácter que no es un espacio en blanco de la subexpresión hasta, pero sin incluir, el espacio, la llave, el paréntesis de cierre o el corchete que terminan la subexpresión. Este token va seguido de uno o más tokens adicionales que describen la subexpresión. Si el primer subtoken después del token TCL_TOKEN_SUB_EXPR es un token TCL_TOKEN_OPERATOR, la subexpresión consiste en un operador y sus operandos de token. Si el operador no tiene operandos, la subexpresión consiste solo en el token TCL_TOKEN_OPERATOR. Cada operando es descrito por un token TCL_TOKEN_SUB_EXPR. De lo contrario, la subexpresión es un valor descrito por uno de los tipos de token TCL_TOKEN_WORD, TCL_TOKEN_TEXT, TCL_TOKEN_BS, TCL_TOKEN_COMMAND, TCL_TOKEN_VARIABLE y TCL_TOKEN_SUB_EXPR. El campo numComponents cuenta el número total de subtokens que componen la subexpresión; esto incluye los subtokens de cualquier token anidado TCL_TOKEN_SUB_EXPR.
TCL_TOKEN_OPERATOR
El token describe un operador de una expresión, como && o hypot. Un token TCL_TOKEN_OPERATOR siempre va precedido por un token TCL_TOKEN_SUB_EXPR que describe el operador y sus operandos; el campo numComponents del token TCL_TOKEN_SUB_EXPR se puede utilizar para determinar el número de operandos. Un operador binario, como *, va seguido de dos tokens TCL_TOKEN_SUB_EXPR que describen sus operandos. Un operador unario, como -, va seguido de un solo token TCL_TOKEN_SUB_EXPR para su operando. Si el operador es una función matemática, como log10, el token TCL_TOKEN_OPERATOR proporcionará su nombre y los siguientes tokens TCL_TOKEN_SUB_EXPR describirán sus operandos; si no hay operandos (como con rand), no siguen tokens TCL_TOKEN_SUB_EXPR. Existe un operador ternario, ?, que aparece en subexpresiones condicionales, como x?y:z; en este caso, el token TCL_TOKEN_OPERATOR ? va seguido de tres tokens TCL_TOKEN_SUB_EXPR para los operandos x, y y z. El campo numComponents para un token TCL_TOKEN_OPERATOR es siempre 0.

Después de que Tcl_ParseCommand retorna, el primer token apuntado por el campo tokenPtr de la estructura Tcl_Parse siempre tiene el tipo TCL_TOKEN_WORD o TCL_TOKEN_SIMPLE_WORD o TCL_TOKEN_EXPAND_WORD. Le siguen los subtokens que deben concatenarse para producir el valor de esa palabra. El siguiente token es el token TCL_TOKEN_WORD o TCL_TOKEN_SIMPLE_WORD o TCL_TOKEN_EXPAND_WORD para la segunda palabra, seguido de los subtokens para esa palabra, y así sucesivamente hasta que se hayan tenido en cuenta las numWords.

Después de que Tcl_ParseExpr retorna, el primer token apuntado por el campo tokenPtr de la estructura Tcl_Parse siempre tiene el tipo TCL_TOKEN_SUB_EXPR. Le siguen los subtokens que deben evaluarse para producir el valor de la expresión. NAME

Tcl_EvalTokens, Tcl_EvalTokensToFile, Tcl_EvalLex — evaluate a list of tokens

SYNOPSIS

#include <tcl.h>

int
Tcl_EvalTokens(interp, tokenPtr, numTokens);

int
Tcl_EvalTokensToFile(interp, tokenPtr, numTokens,
    filePtr);

int
Tcl_EvalLex(interp, string);

ARGUMENTS 

Tcl_Interp *interp
    (in) Tcl interpreter to use for evaluation.
Tcl_Token *tokenPtr
    (in) Pointer to the first token in a list of tokens.
int numTokens
    (in) Number of tokens in the list.
FILE *filePtr
    (in) File pointer to write output to.
const char *string
    (in) A string to be parsed and evaluated.

DESCRIPTION

The Tcl_EvalTokens and Tcl_EvalTokensToFile procedures evaluate a list of tokens. The tokens are assumed to have been generated by a call to Tcl_Tokenize, or some other procedure that produces the same format of Tcl_Token structures. The tokens are evaluated in the context of the interpreter given by interp. The result of the evaluation is stored in the interpreter's result (`interp->result`) as if it had been executed as Tcl commands. Both procedures return the same result as Tcl_Eval, generally `TCL_OK` on success, or `TCL_ERROR` or `TCL_RETURN` on error or return.

Tcl_EvalTokens evaluates the tokens and makes the result available in the interpreter's result. Tcl_EvalTokensToFile is similar, but instead of storing the result in the interpreter's result, it writes the result directly to the file specified by filePtr. This is useful for redirecting command output without affecting the interpreter's result value.

The Tcl_EvalLex procedure is a convenience procedure that combines parsing and evaluation. It takes a string, parses it into tokens using Tcl_Tokenize, and then evaluates those tokens using Tcl_EvalTokens. The result is stored in the interpreter's result and returned.

The tokens passed to Tcl_EvalTokens and Tcl_EvalTokensToFile must be valid. The tokens may represent arbitrary Tcl code, including commands, expressions, variable substitutions, brace expansion, etc. The procedures will handle the interpretation and execution of these constructs.

The procedures do not modify the tokens themselves. They are read-only operations.

TCL_PARSE STRUCTURE

The procedures Tcl_ParseCommand, Tcl_ParseExpr, Tcl_ParseBraces, Tcl_ParseQuotedString, and Tcl_ParseVarName all operate on a Tcl_Parse structure. This structure is used to hold information about the parsing process. The structure contains the following fields:

Tcl_Obj *result
The result of the parsing operation, often a list of tokens.
Tcl_Token *tokenPtr
A pointer to an array of Tcl_Token structures representing the parsed tokens.
int numTokens
The number of tokens in the array pointed to by tokenPtr.
int error
A flag indicating whether an error occurred during parsing.
int errorChar
The character offset within the input string where the error occurred.
const char *parseStart
A pointer to the beginning of the portion of the input string currently being parsed.
const char *parseEnd
A pointer to the end of the portion of the input string currently being parsed.
const char *commentStart
If a comment is encountered during parsing, this points to the start of the comment. Otherwise, it is NULL.
int commentSize
The length of the comment, if one was found.
const char *commandStart
If a command substitution is encountered (e.g., `[command]`), this points to the start of the command substitution. Otherwise, it is NULL.
int commandSize
The length of the command substitution, if one was found.

After Tcl_ParseCommand returns, the tokenPtr field points to an array of Tcl_Token structures representing the parsed command. The first token is always of type TCL_TOKEN_COMMAND, and subsequent tokens represent the arguments to the command. The numTokens field indicates the number of tokens in the array.

After Tcl_ParseExpr returns, the tokenPtr field points to an array of tokens representing the parsed expression. The tokens can be of various types, including TCL_TOKEN_TEXT, TCL_TOKEN_BS (backslash substitution), TCL_TOKEN_COMMAND, and TCL_TOKEN_VARIABLE. The `result` field of the Tcl_Parse structure will contain a Tcl_Obj representing the evaluated expression value. The commentStart, commentSize, commandStart, and commandSize fields are not modified by Tcl_ParseExpr.

After Tcl_ParseBraces returns, the tokenPtr field points to an array of tokens representing the contents of the braces. The tokens can be of various types, including TCL_TOKEN_TEXT, TCL_TOKEN_BS, TCL_TOKEN_COMMAND, and TCL_TOKEN_VARIABLE. The commentStart, commentSize, commandStart, and commandSize fields are not modified by Tcl_ParseBraces.

After Tcl_ParseQuotedString returns, the array of tokens pointed to by the tokenPtr field of the Tcl_Parse structure depends on the contents of the quoted string. It will consist of one or more TCL_TOKEN_TEXT, TCL_TOKEN_BS, TCL_TOKEN_COMMAND, and TCL_TOKEN_VARIABLE sub-tokens. The array always contains at least one token; for example, if the argument start is empty, the array returned consists of a single TCL_TOKEN_TEXT token with a zero size field. Only the token information in the Tcl_Parse structure is modified: the commentStart, commentSize, commandStart, and commandSize fields are not modified.

After Tcl_ParseVarName returns, the first token pointed to by the tokenPtr field of the Tcl_Parse structure always has type TCL_TOKEN_VARIABLE. It is followed by the sub-tokens that make up the variable name as described above. The total length of the variable name is contained in the size field of the first token. As in Tcl_ParseExpr, only the token information in the Tcl_Parse structure is modified by Tcl_ParseVarName: the commentStart, commentSize, commandStart, and commandSize fields are not modified.

All of the character pointers in the Tcl_Parse and Tcl_Token structures refer to characters in the start argument passed to Tcl_ParseCommand, Tcl_ParseExpr, Tcl_ParseBraces, Tcl_ParseQuotedString, and Tcl_ParseVarName.

There are additional fields in the Tcl_Parse structure after the numTokens field, but these are for the private use of Tcl_ParseCommand, Tcl_ParseExpr, Tcl_ParseBraces, Tcl_ParseQuotedString, and Tcl_ParseVarName; they should not be referenced by code outside of these procedures.
