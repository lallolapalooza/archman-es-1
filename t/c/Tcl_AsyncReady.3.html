Tcl_AsyncCreate(3) Procedimientos de biblioteca Tcl Tcl_AsyncCreate(3)

NOMBRE

Tcl_AsyncCreate, Tcl_AsyncMark, Tcl_AsyncInvoke, Tcl_AsyncDelete, Tcl_AsyncReady - manejar eventos asíncronos

SINOPSIS

#include <tcl.h>

Tcl_AsyncHandler
Tcl_AsyncCreate(proc, clientData)

void
Tcl_AsyncMark(async)

int
Tcl_AsyncInvoke(interp, code)

void
Tcl_AsyncDelete(async)

int
Tcl_AsyncReady()

ARGUMENTOS

Tcl_AsyncProc *proc (entrada)
Procedimiento a invocar para manejar un evento asíncrono.
ClientData clientData (entrada)
Valor de una palabra a pasar a proc.
Tcl_AsyncHandler async (entrada)
Token para el manejador de eventos asíncronos.
Tcl_Interp *interp (entrada)
Intérprete de Tcl en el cual se estaba evaluando un comando cuando se invocó el manejador, o NULL si el manejador se invocó cuando no había ningún intérprete activo.
int code (entrada)
Código de finalización del comando que acaba de completarse en interp, o 0 si interp es NULL.

DESCRIPCIÓN

Estos procedimientos proporcionan un mecanismo seguro para tratar eventos asíncronos como señales. Si ocurre un evento como una señal mientras se está evaluando un script de Tcl, no es seguro tomar ninguna acción sustantiva para procesar el evento. Por ejemplo, no es seguro evaluar un script de Tcl ya que el intérprete puede estar en medio de la evaluación de un script; puede que ni siquiera sea seguro asignar memoria, ya que la asignación de memoria podría haber estado en progreso cuando ocurrió el evento. El único enfoque seguro es establecer una bandera indicando que el evento ocurrió, y luego manejar el evento más tarde cuando el mundo haya vuelto a un estado limpio, como después de que el comando actual se complete.

Tcl_AsyncCreate, Tcl_AsyncDelete y Tcl_AsyncReady son sensibles a hilos. Acceden y/o establecen una estructura de datos específica del hilo en caso de un núcleo compilado con --enable-threads. El token creado por Tcl_AsyncCreate contiene la información de hilo necesaria desde la que se llamó para que la llamada a Tcl_AsyncMark(token) solo entregue el hilo de origen al manejador asíncrono.

Tcl_AsyncCreate crea un manejador asíncrono y devuelve un token para él. El manejador asíncrono debe crearse antes de cualquier ocurrencia del evento asíncrono que se pretende manejar (no es seguro crear un manejador en el momento de un evento). Cuando ocurre un evento asíncrono, el código que detecta el evento (como un manejador de señales) debe llamar a Tcl_AsyncMark con el token del manejador. Tcl_AsyncMark marcará el manejador como listo para ejecutarse, pero no invocará al manejador inmediatamente. Tcl llamará al proc asociado con el manejador más tarde, cuando el mundo esté en un estado seguro, y el proc podrá entonces llevar a cabo las acciones asociadas con el evento asíncrono. El proc debe tener argumentos y resultados que coincidan con el tipo Tcl_AsyncProc:

typedef int Tcl_AsyncProc(
        ClientData clientData,
        Tcl_Interp *interp,
        int code);

El clientData será el mismo que el argumento clientData pasado a Tcl_AsyncCreate cuando se creó el manejador. Si se invoca proc justo después de que un comando haya completado su ejecución en un intérprete, entonces interp identificará el intérprete en el que se evaluó el comando y code será el código de finalización devuelto por ese comando. El resultado del comando estará presente en el resultado del intérprete. Cuando proc regrese, lo que sea que deje en el resultado del intérprete se devolverá como el resultado del comando y el valor entero devuelto por proc se usará como el nuevo código de finalización del comando.

También es posible que se invoque proc cuando no hay un intérprete activo. Esto puede ocurrir, por ejemplo, si un evento asíncrono ocurre mientras la aplicación está esperando entrada interactiva o un evento X. En este caso interp será NULL y code será 0, y el valor de retorno de proc será ignorado.

El procedimiento Tcl_AsyncInvoke se llama para invocar a todos los manejadores que están listos. El procedimiento Tcl_AsyncReady devolverá un valor distinto de cero siempre que haya manejadores asíncronos listos; se puede comprobar para evitar llamadas a Tcl_AsyncInvoke cuando no hay manejadores listos. Tcl llama a Tcl_AsyncReady después de que cada comando se evalúa y llama a Tcl_AsyncInvoke si es necesario. Las aplicaciones también pueden llamar a Tcl_AsyncInvoke en momentos interesantes para esa aplicación. Por ejemplo, el manejador de eventos de Tcl llama a Tcl_AsyncReady después de cada evento y llama a Tcl_AsyncInvoke si es necesario. Los argumentos interp y code a Tcl_AsyncInvoke tienen el mismo significado que para proc: identifican el intérprete activo, si lo hay, y el código de finalización del comando que acaba de completarse.

Tcl_AsyncDelete elimina un manejador asíncrono para que su proc nunca se vuelva a invocar. Se puede eliminar un manejador incluso cuando está listo, y aun así no se invocará.

Si varios manejadores se activan al mismo tiempo, los manejadores se invocan en el orden en que fueron creados (manejador más antiguo primero). El code y el resultado del intérprete para manejadores posteriores reflejan los valores devueltos por los manejadores anteriores, de modo que el manejador creado más recientemente tiene la última palabra sobre el resultado y el código de finalización del intérprete. Si se activan nuevos manejadores mientras los manejadores se están ejecutando, Tcl_AsyncInvoke los invocará a todos; en cada punto, invoca al manejador listo de mayor prioridad (más antiguo), repitiendo esto una y otra vez hasta que ya no queden manejadores listos.

ADVERTENCIA

Casi siempre es una mala idea que un manejador de eventos asíncrono modifique el resultado del intérprete o devuelva un código diferente de su argumento code. Este tipo de comportamiento puede interrumpir la ejecución de scripts de manera sutil y resultar en errores extremadamente difíciles de rastrear. Si un manejador de eventos asíncronos necesita evaluar scripts de Tcl, primero debe guardar el estado del intérprete llamando a Tcl_SaveInterpState, pasando el argumento code. Cuando el manejador asíncrono termine, debe restaurar el estado del intérprete llamando a Tcl_RestoreInterpState, y luego devolver el argumento code.
