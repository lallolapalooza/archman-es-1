Tcl_Interp(3) Procedimientos de la biblioteca Tcl Tcl_Interp(3)

NOMBRE

Tcl_Interp - campos visibles para el cliente de las estructuras del intérprete

SINOPSIS

#include <tcl.h>

typedef struct {
    char *result;
    Tcl_FreeProc *freeProc;
    int errorLine;
} Tcl_Interp;
typedef void Tcl_FreeProc(
        char *blockPtr);

DESCRIPCIÓN

El procedimiento Tcl_CreateInterp devuelve un puntero a una estructura Tcl_Interp. Los llamadores de Tcl_CreateInterp deben usar este puntero como un token opaco, adecuado para nada más que pasarlo de vuelta a otras rutinas de la interfaz Tcl. El acceso directo a los campos a través del puntero, como se describe a continuación, ya no está soportado. En su lugar, deben utilizarse las rutinas públicas soportadas: Tcl_SetResult, Tcl_GetResult, Tcl_SetErrorLine, Tcl_GetErrorLine.

Para programas y extensiones heredados que ya no se mantienen, las compilaciones contra los archivos de cabecera de Tcl 8.6 solo son posibles con las directivas del compilador

#define USE_INTERP_RESULT
y/o 
#define USE_INTERP_ERRORLINE
dependiendo de qué campos de la estructura Tcl_Interp se accedan. Estas directivas pueden estar incrustadas en el código o proporcionarse a través de opciones del compilador.

Los campos result y freeProc se utilizan para devolver resultados o mensajes de error de los comandos. Esta información es devuelta por los procedimientos de comando a Tcl_Eval, y por Tcl_Eval a sus llamadores. El campo result apunta a la cadena que representa el resultado o mensaje de error, y el campo freeProc indica cómo desechar el almacenamiento de la cadena cuando ya no sea necesaria. La forma más fácil para que los procedimientos de comando manipulen estos campos es llamar a procedimientos como Tcl_SetResult o Tcl_AppendResult; estos ocultarán todos los detalles de la gestión de los campos. La descripción a continuación es para aquellos procedimientos que manipulan los campos directamente.

Siempre que un procedimiento de comando devuelve, debe asegurarse de que el campo result de su intérprete apunte a la cadena que está siendo devuelta por el comando. El campo result debe apuntar siempre a una cadena válida. Si un comando desea devolver ningún resultado, entonces interp->result debe apuntar a una cadena vacía. Normalmente, se supone que los resultados se asignan de forma estática, lo que significa que el contenido no cambiará antes de la próxima vez que se llame a Tcl_Eval o se invoque algún otro procedimiento de comando. En este caso, el campo freeProc debe ser cero. Alternativamente, un procedimiento de comando puede asignar dinámicamente su valor de retorno (por ejemplo, usando Tcl_Alloc) y almacenar un puntero a él en interp->result. En este caso, el procedimiento de comando también debe establecer interp->freeProc a la dirección de un procedimiento que pueda liberar el valor, o TCL_DYNAMIC si el almacenamiento fue asignado directamente por Tcl o por una llamada a Tcl_Alloc. Si interp->freeProc no es cero, entonces Tcl llamará a freeProc para liberar el espacio apuntado por interp->result antes de invocar el siguiente comando. Si un procedimiento cliente sobrescribe interp->result cuando interp->freeProc no es cero, entonces es responsable de llamar a freeProc para liberar el interp->result antiguo (la macro Tcl_FreeResult debe usarse para este propósito).

FreeProc debe tener argumentos y resultados que coincidan con la declaración Tcl_FreeProc anterior: recibe un solo argumento que es un puntero al valor de resultado a liberar. En la mayoría de las aplicaciones, TCL_DYNAMIC es el único valor distinto de cero que se usa alguna vez para freeProc. Sin embargo, una aplicación puede almacenar una dirección de procedimiento diferente en freeProc para usar un asignador de memoria alternativo o para realizar otra limpieza cuando se libere la memoria del resultado.

Como parte del procesamiento de cada comando, Tcl_Eval inicializa interp->result y interp->freeProc justo antes de llamar al procedimiento de comando. El campo freeProc se inicializará a cero, y interp->result apuntará a una cadena vacía. Los comandos que no devuelven ningún valor pueden simplemente dejar los campos solos. Además, la cadena vacía apuntada por result es en realidad parte de una matriz de TCL_RESULT_SIZE caracteres (aproximadamente 200). Si un comando desea devolver una cadena corta, simplemente puede copiarla al área apuntada por interp->result. O, puede usar el procedimiento sprintf para generar una cadena de resultado corta en la ubicación apuntada por interp->result.

Es una convención general en las aplicaciones basadas en Tcl que el resultado de un intérprete está normalmente en el estado inicializado descrito en el párrafo anterior. Los procedimientos que manipulan el resultado de un intérprete (por ejemplo, devolviendo un error) generalmente asumirán que el resultado ha sido inicializado cuando se llama al procedimiento. Si dicho procedimiento va a ser llamado después de que el resultado haya sido modificado, entonces se debe llamar a Tcl_ResetResult primero para restablecer el resultado a su estado inicializado. El uso directo de interp->result está fuertemente desaconsejado (ver Tcl_SetResult).

El campo errorLine es válido solo después de que Tcl_Eval devuelve un código de retorno TCL_ERROR. En esta situación, el campo errorLine identifica el número de línea del comando que se está ejecutando cuando ocurrió el error. Los números de línea son relativos al comando que se está ejecutando: 1 significa la primera línea del comando pasado a Tcl_Eval, 2 significa la segunda línea, y así sucesivamente. El campo errorLine se utiliza típicamente junto con Tcl_AddErrorInfo para informar sobre dónde ocurrió un error. ErrorLine normalmente no debe ser modificado excepto por Tcl_Eval.
