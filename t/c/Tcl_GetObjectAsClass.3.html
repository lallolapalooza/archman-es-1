DESCRIPCIÓN

Los objetos son entidades tipadas que tienen un conjunto de operaciones ("métodos") asociadas a ellas. Las clases son objetos que pueden fabricar objetos. Cada clase puede ser vista como un objeto en sí misma; la vista de objeto se puede recuperar usando Tcl_GetClassAsObject que siempre devuelve el objeto cuando se aplica a una clase no destruida, y un objeto puede ser visto como una clase con la ayuda de Tcl_GetObjectAsClass (que devuelve la clase o NULL si el objeto no es una clase). Un objeto puede ser buscado usando la función Tcl_GetObjectFromObj, que devuelve un objeto o NULL (con un mensaje de error en el resultado del intérprete) si el objeto no se encuentra. La forma correcta de buscar una clase por nombre es buscar el objeto con ese nombre, y luego usar Tcl_GetObjectAsClass.

Cada objeto tiene su propio comando y espacio de nombres asociados. El comando se puede recuperar usando la función Tcl_GetObjectCommand, el nombre del objeto (y por lo tanto el nombre del comando) con Tcl_GetObjectName, y el espacio de nombres se puede recuperar usando la función Tcl_GetObjectNamespace. Tenga en cuenta que la referencia Tcl_Obj devuelta por Tcl_GetObjectName es una referencia compartida. También puede obtener si el objeto ha sido marcado para su eliminación con Tcl_ObjectDeleted (devuelve verdadero si la eliminación del objeto ha comenzado); esto puede ser útil durante el procesamiento de métodos.

Las instancias de clases se crean usando Tcl_NewObjectInstance, que crea un objeto a partir de cualquier clase (y que es llamado internamente tanto por los métodos create como new de la clase oo::class). Toma parámetros que opcionalmente dan el nombre del objeto y el espacio de nombres a crear, y que describen los argumentos a pasar al constructor de la clase (si lo hay). El resultado de la función será una referencia al objeto recién creado, o NULL si la creación falló (cuando se dejará un mensaje de error en el resultado del intérprete). Además, los objetos pueden copiarse usando Tcl_CopyObjectInstance que crea una copia de un objeto sin ejecutar ningún constructor.

Tenga en cuenta que la gestión del ciclo de vida de los objetos se maneja internamente dentro de TclOO, y no utiliza Tcl_Preserve. *No es seguro poner un* *manejador Tcl_Object en una estructura C con una vida útil diferente a la del objeto;* debe usar el nombre del comando del objeto (tal como se recupera con Tcl_GetObjectName) en su lugar. Es seguro usar un manejador Tcl_Object durante la vida útil de una llamada a un método sobre ese objeto; los manejadores no se vuelven inválidos mientras haya una llamada pendiente sobre su objeto (incluso si la única operación garantizada para ser segura sobre ellos es Tcl_ObjectDeleted; las otras operaciones solo están garantizadas para funcionar en objetos no eliminados).

METADATOS DE OBJETO Y CLASE

Cada objeto y cada clase pueden tener cantidades arbitrarias de metadatos adjuntos a él, a los que el objeto o la clase no les atribuyen ningún significado más allá de lo descrito en una instancia de estructura Tcl_ObjectMetadataType. Los metadatos a adjuntar se describen por el tipo de los metadatos (dado en el argumento metaTypePtr) y un puntero arbitrario (el argumento metadata) que se dan a Tcl_ObjectSetMetadata y Tcl_ClassSetMetadata, y un metadato particular puede ser recuperado dado su tipo usando Tcl_ObjectGetMetadata y Tcl_ClassGetMetadata. Si el parámetro metadata para Tcl_ObjectSetMetadata o Tcl_ClassSetMetadata es NULL, los metadatos se eliminan si estaban adjuntos, y los resultados de Tcl_ObjectGetMetadata y Tcl_ClassGetMetadata son NULL si el tipo de metadatos dado no estaba adjunto. No es un error solicitar o eliminar un metadato que no estaba adjunto.

ESTRUCTURA TCL_OBJECTMETADATATYPE

El contenido de la estructura Tcl_ObjectMetadataType es el siguiente:

typedef const struct {
    int version;
    const char *name;
    Tcl_ObjectMetadataDeleteProc *deleteProc;
    Tcl_CloneProc *cloneProc;
} Tcl_ObjectMetadataType;

El campo version permite la expansión futura de la estructura, y siempre debe declararse igual a TCL_OO_METADATA_VERSION_CURRENT. El campo name proporciona un nombre legible por humanos para el tipo, y está reservado para depuración.

El campo deleteProc da una función de tipo Tcl_ObjectMetadataDeleteProc que se utiliza para eliminar un metadato particular, y se llama cuando el metadato adjunto se reemplaza o se elimina; el campo no debe ser NULL.

El campo cloneProc da una función que se utiliza para copiar un metadato (utilizado cuando se crea una copia de un objeto usando Tcl_CopyObjectInstance); si es NULL, el metadato se copiará directamente.

FIRMA DE FUNCIÓN TCL_OBJECTMETADATADELETEPROC

Las funciones que coinciden con esta firma se utilizan para eliminar metadatos asociados con una clase u objeto.

DESCRIPTION

These functions provide low-level access to TclOO objects and classes.

TCL_GETOBJECTASCLASS FUNCTION SIGNATURE

This function attempts to find a class definition for the given object. If the clsPtr argument is not NULL, it will be used as the class of the object. If it is NULL, the class will be determined by looking up the object's class name in the interpreter's namespace stack. The object's class will be set to the class found. The function returns TCL_OK on success, and TCL_ERROR on failure (e.g., if the class name cannot be found).

TCL_OBJECTGETCLASS FUNCTION SIGNATURE

Returns the class of the given object.

TCL_OBJECTSETCLASS FUNCTION SIGNATURE

Sets the class of the given object to clsPtr. This function may be used to change an object's class dynamically. It returns TCL_OK on success, and TCL_ERROR on failure (e.g., if clsPtr is not a valid class).

TCL_OBJECTMETHODDELETED FUNCTION SIGNATURE

This function is called to notify TclOO that a method has been deleted from the given object. The methodNameObj argument specifies the name of the method that was deleted.

OBJECT AND CLASS METADATA

TclOO allows arbitrary client-specific data to be attached to objects and classes. This data is known as metadata.

TCL_OBJECTMETADATADELETEPROC FUNCTION SIGNATURE

Functions matching this signature are called when metadata associated with an object or class is to be destroyed.

typedef void Tcl_ObjectMetadataDeleteProc(
                        ClientData metadata);

The metadata argument gives the address of the metadata to be deleted.

TCL_CLONEPROC FUNCTION SIGNATURE

Functions matching this signature are used to create copies of metadata associated with a class or object.

typedef int Tcl_CloneProc(
                        Tcl_Interp *interp,
                        ClientData srcMetadata,
                        ClientData *dstMetadataPtr);

The interp argument gives a place to write an error message when the attempt to clone the object is to fail, in which case the clone procedure must also return TCL_ERROR; it should return TCL_OK otherwise. The srcMetadata argument gives the address of the metadata to be cloned, and the cloned metadata should be written into the variable pointed to by dstMetadataPtr; a NULL should be written if the metadata is to not be cloned but the overall object copy operation is still to succeed.

OBJECT METHOD NAME MAPPING

It is possible to control, on a per-object basis, what methods are invoked when a particular method is invoked. Normally this is done by looking up the method name in the object and then in the class hierarchy, but fine control of exactly what the value used to perform the look up is afforded through the ability to set a method name mapper callback via Tcl_ObjectSetMethodNameMapper (and its introspection counterpart, Tcl_ObjectGetMethodNameMapper, which returns the current mapper). The current mapper (if any) is invoked immediately before looking up what chain of method implementations is to be used.

TCL_OBJECTMAPMETHODNAMEPROC FUNCTION SIGNATURE

The Tcl_ObjectMapMethodNameProc callback is defined as follows:

typedef int Tcl_ObjectMapMethodNameProc(
                        Tcl_Interp *interp,
                        Tcl_Object object,
                        Tcl_Class *startClsPtr,
                        Tcl_Obj *methodNameObj);

If the result is TCL_OK, the remapping is assumed to have been done. If the result is TCL_ERROR, an error message will have been left in interp and the method call will fail. If the result is TCL_BREAK, the standard method name lookup rules will be used; the behavior of other result codes is currently undefined. The object parameter says which object is being processed. The startClsPtr parameter points to a variable that contains the first class to provide a definition in the method chain to process, or NULL if the whole chain is to be processed (the argument itself is never NULL); this variable may be updated by the callback. The methodNameObj parameter gives an unshared object containing the name of the method being invoked, as provided by the user; this object may be updated by the callback.
