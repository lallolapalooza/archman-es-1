Tcl_Hash(3) Procedimientos de la biblioteca Tcl Tcl_Hash(3)

NOMBRE

Tcl_InitHashTable, Tcl_InitCustomHashTable, Tcl_InitObjHashTable, Tcl_DeleteHashTable, Tcl_CreateHashEntry, Tcl_DeleteHashEntry, Tcl_FindHashEntry, Tcl_GetHashValue, Tcl_SetHashValue, Tcl_GetHashKey, Tcl_FirstHashEntry, Tcl_NextHashEntry, Tcl_HashStats - procedimientos para gestionar tablas hash

SINOPSIS

#include <tcl.h>

Tcl_InitHashTable(tablePtr, keyType)

Tcl_InitCustomHashTable(tablePtr, keyType, typePtr)

Tcl_InitObjHashTable(tablePtr)

Tcl_DeleteHashTable(tablePtr)

Tcl_HashEntry *
Tcl_CreateHashEntry(tablePtr, key, newPtr)

Tcl_DeleteHashEntry(entryPtr)

Tcl_HashEntry *
Tcl_FindHashEntry(tablePtr, key)

ClientData
Tcl_GetHashValue(entryPtr)

Tcl_SetHashValue(entryPtr, value)

void *
Tcl_GetHashKey(tablePtr, entryPtr)

Tcl_HashEntry *
Tcl_FirstHashEntry(tablePtr, searchPtr)

Tcl_HashEntry *
Tcl_NextHashEntry(searchPtr)

char *
Tcl_HashStats(tablePtr)

ARGUMENTOS

Tcl_HashTable *tablePtr (entrada)
Dirección de la estructura de la tabla hash (para todos los procedimientos excepto Tcl_InitHashTable, esta debe haber sido inicializada por una llamada anterior a Tcl_InitHashTable).
int keyType (entrada)
Tipo de claves a usar para la nueva tabla hash. Debe ser TCL_STRING_KEYS, TCL_ONE_WORD_KEYS, TCL_CUSTOM_TYPE_KEYS, TCL_CUSTOM_PTR_KEYS, o un valor entero mayor que 1.
Tcl_HashKeyType *typePtr (entrada)
Dirección de la estructura que define el comportamiento de la tabla hash.
const void *key (entrada)
Clave a usar para la búsqueda en la tabla. El formato exacto depende de keyType utilizado para crear la tabla.
int *newPtr (salida)
La palabra en *newPtr se establece en 1 si se creó una nueva entrada y en 0 si ya existía una entrada para key.
Tcl_HashEntry *entryPtr (entrada)
Puntero a la entrada de la tabla hash.
ClientData value (entrada)
Nuevo valor a asignar a la entrada de la tabla hash. No necesita tener el tipo ClientData, pero debe caber en el mismo espacio que ClientData.
Tcl_HashSearch *searchPtr (entrada)
Puntero al registro a usar para realizar un seguimiento del progreso al enumerar todas las entradas de una tabla hash.

DESCRIPCIÓN

Una tabla hash consiste en cero o más entradas, cada una compuesta por una clave y un valor. Dada la clave de una entrada, las rutinas de hashing pueden localizar muy rápidamente la entrada y, por lo tanto, su valor. Puede haber como máximo una entrada en una tabla hash con una clave particular, pero muchas entradas pueden tener el mismo valor. Las claves pueden tener uno de cuatro formatos: cadenas, valores de una palabra, arreglos de enteros o claves personalizadas definidas por una estructura Tcl_HashKeyType (ver sección LA ESTRUCTURA TCL_HASHKEYTYPE abajo). Todas las claves de una tabla dada tienen el mismo formato, que se especifica al inicializar la tabla.

El valor de una entrada de tabla hash puede ser cualquier cosa que quepa en el mismo espacio que un puntero “char *”. Los valores para las entradas de tabla hash son gestionados completamente por los clientes, no por el propio módulo hash. Típicamente, el valor de cada entrada es un puntero a una estructura de datos gestionada por el código del cliente.

Las tablas hash crecen de forma gradual a medida que aumenta el número de entradas, de modo que siempre haya menos de tres entradas por cubo hash, en promedio. Esto permite búsquedas rápidas independientemente del número de entradas en una tabla.

El núcleo proporciona tres funciones para la inicialización de tablas hash: Tcl_InitHashTable, Tcl_InitObjHashTable y Tcl_InitCustomHashTable.

Tcl_InitHashTable inicializa una estructura que describe una nueva tabla hash. El espacio para la estructura lo proporciona el llamador, no el módulo hash. El valor de keyType indica qué tipos de claves se utilizarán para todas las entradas de la tabla. Se permiten todos los tipos de clave descritos más adelante, con la excepción de TCL_CUSTOM_TYPE_KEYS y TCL_CUSTOM_PTR_KEYS.

Tcl_InitObjHashTable es un envoltorio alrededor de Tcl_InitCustomHashTable e inicializa una tabla hash cuyas claves son Tcl_Obj *.

Tcl_InitCustomHashTable inicializa una estructura que describe una nueva tabla hash. El espacio para la estructura lo proporciona el llamador, no el módulo hash. El valor de keyType indica qué tipos de claves se utilizarán para todas las entradas de la tabla. KeyType debe tener uno de los siguientes valores:

TCL_STRING_KEYS
Las claves son cadenas terminadas en nulo. Se pasan a las rutinas de hashing utilizando la dirección del primer carácter de la cadena.
TCL_ONE_WORD_KEYS
Las claves son valores de una sola palabra; se pasan a las rutinas de hashing y se almacenan en las entradas de la tabla hash como valores de “char *”. El valor del puntero es la clave; no necesita (y normalmente no lo hace) apuntar a una cadena.
TCL_CUSTOM_TYPE_KEYS
Las claves son de tipo arbitrario y se almacenan en la entrada. El hashing y la comparación se determinan mediante typePtr. La estructura Tcl_HashKeyType se describe en la sección LA ESTRUCTURA TCL_HASHKEYTYPE abajo.
TCL_CUSTOM_PTR_KEYS
Las claves son punteros a un tipo arbitrario y se almacenan en la entrada. El hashing y la comparación se determinan mediante typePtr. La estructura Tcl_HashKeyType se describe en la sección LA ESTRUCTURA TCL_HASHKEYTYPE abajo.
otro
Si keyType no es uno de los anteriores, debe ser un valor entero mayor que 1. En este caso, las claves serán arreglos de valores “int”, donde keyType da el número de enteros en cada clave. Esto permite usar estructuras como claves. Todas las claves deben tener el mismo tamaño. Las claves de arreglo se pasan a las funciones de hashing utilizando la dirección del primer entero en el arreglo.

Tcl_DeleteHashTable elimina todas las entradas de una tabla hash y libera la memoria asociada con el arreglo de cubos y las entradas de la tabla. No libera la estructura de la tabla en sí (apuntada por tablePtr), ya que se asume que la memoria es gestionada por el cliente. Tcl_DeleteHashTable tampoco libera ni manipula de ninguna manera los valores de las entradas de la tabla hash. Si los valores de las entradas apuntan a memoria asignada dinámicamente, el cliente es responsable de liberar estas estructuras antes de eliminar la tabla.

Tcl_CreateHashEntry localiza la entrada correspondiente a una clave particular, creando una nueva entrada en la tabla si aún no existía una con la clave dada. Si ya existía una entrada con la clave dada, *newPtr se establece en cero. Si se creó una nueva entrada, *newPtr se establece en un valor distinto de cero y el valor de la nueva entrada se establecerá en cero. El valor de retorno de Tcl_CreateHashEntry es un puntero a la entrada, que puede usarse para recuperar y modificar el valor de la entrada o para eliminar la entrada de la tabla.

Tcl_DeleteHashEntry eliminará una entrada existente de una tabla. Se liberará la memoria asociada con la entrada misma, pero el cliente es responsable de cualquier limpieza asociada con el valor de la entrada, como liberar una estructura a la que apunta.

Tcl_FindHashEntry es similar a Tcl_CreateHashEntry excepto que no crea una nueva entrada si la clave no existe; en su lugar, devuelve NULL como resultado.

Tcl_GetHashValue y Tcl_SetHashValue se utilizan para leer y escribir el valor de una entrada, respectivamente. Los valores se almacenan y recuperan como tipo “ClientData”, que es lo suficientemente grande como para contener un valor de puntero. En casi todas las máquinas, esto es suficiente para contener también un valor entero.

Tcl_GetHashKey devuelve la clave de una entrada de tabla hash dada, ya sea como un puntero a una cadena, una clave de una palabra (“char *”), o como un puntero a la primera palabra de un arreglo de enteros, dependiendo del keyType utilizado para crear una tabla hash. En todos los casos, Tcl_GetHashKey devuelve un resultado de tipo “char *”. Cuando la clave es una cadena o un arreglo, el resultado de Tcl_GetHashKey apunta a información en la entrada de la tabla; esta información permanecerá válida hasta que la entrada sea eliminada o su tabla sea eliminada.

Tcl_FirstHashEntry y Tcl_NextHashEntry se pueden utilizar para escanear todas las entradas de una tabla hash

Tcl_NextHashEntry(3) - Arch Linux

NAME

Tcl_NextHashEntry, Tcl_FirstHashEntry, Tcl_HashStats - iterate through hash table entries

SYNOPSIS

#include <tcl.h>

Tcl_HashEntry *
Tcl_FirstHashEntry(tablePtr, searchPtr)
Tcl_HashEntry *
Tcl_NextHashEntry(searchPtr)
Tcl_HashStats *
Tcl_HashStats(tablePtr)

ARGUMENTS

Tcl_HashTable *tablePtr (in)
    Pointer to the hash table to iterate over.
Tcl_HashSearch *searchPtr (in/out)
    Pointer to a Tcl_HashSearch structure used to keep track of
    progress through the table.

DESCRIPTION

These procedures provide a mechanism for iterating through all the entries in a hash table. A structure of type Tcl_HashSearch, provided by the client, is used to keep track of progress through the table. Tcl_FirstHashEntry initializes the search record and returns the first entry in the table (or NULL if the table is empty). Each subsequent call to Tcl_NextHashEntry returns the next entry in the table or NULL if the end of the table has been reached. A call to Tcl_FirstHashEntry followed by calls to Tcl_NextHashEntry will return each of the entries in the table exactly once, in an arbitrary order. It is inadvisable to modify the structure of the table, e.g. by creating or deleting entries, while the search is in progress, with the exception of deleting the entry returned by Tcl_FirstHashEntry or Tcl_NextHashEntry.

Tcl_HashStats returns a dynamically-allocated string with overall information about a hash table, such as the number of entries it contains, the number of buckets in its hash array, and the utilization of the buckets. It is the caller's responsibility to free the result string by passing it to ckfree.

The header file tcl.h defines the actual data structures used to implement hash tables. This is necessary so that clients can allocate Tcl_HashTable structures and so that macros can be used to read and write the values of entries. However, users of the hashing routines should never refer directly to any of the fields of any of the hash-related data structures; use the procedures and macros defined here.

THE TCL_HASHKEYTYPE STRUCTURE

Extension writers can define new hash key types by defining four procedures, initializing a Tcl_HashKeyType structure to describe the type, and calling Tcl_InitCustomHashTable. The Tcl_HashKeyType structure is defined as follows:

typedef struct Tcl_HashKeyType {
    int version;
    int flags;
    Tcl_HashKeyProc *hashKeyProc;
    Tcl_CompareHashKeysProc *compareKeysProc;
    Tcl_AllocHashEntryProc *allocEntryProc;
    Tcl_FreeHashEntryProc *freeEntryProc;
} Tcl_HashKeyType;

The version member is the version of the table. If this structure is extended in future then the version can be used to distinguish between different structures. It should be set to TCL_HASH_KEY_TYPE_VERSION.

The flags member is 0 or one or more of the following values OR'ed together:

TCL_HASH_KEY_RANDOMIZE_HASH
There are some things, pointers for example which do not hash well because they do not use the lower bits. If this flag is set then the hash table will attempt to rectify this by randomizing the bits and then using the upper N bits as the index into the table.
TCL_HASH_KEY_SYSTEM_HASH
This flag forces Tcl to use the memory allocation procedures provided by the operating system when allocating and freeing memory used to store the hash table data structures, and not any of Tcl's own customized memory allocation routines. This is important if the hash table is to be used in the implementation of a custom set of allocation routines, or something that a custom set of allocation routines might depend on, in order to avoid any circular dependency.

The hashKeyProc member contains the address of a function called to calculate a hash value for the key.

typedef unsigned int Tcl_HashKeyProc(
        Tcl_HashTable *tablePtr,
        void *keyPtr);

If this is NULL then keyPtr is used and TCL_HASH_KEY_RANDOMIZE_HASH is assumed.

The compareKeysProc member contains the address of a function called to compare two keys.

typedef int Tcl_CompareHashKeysProc(
        void *keyPtr,
        Tcl_HashEntry *hPtr);

If this is NULL then the keyPtr pointers are compared. If the keys do not match then the function returns 0, otherwise it returns 1.

The allocEntryProc member contains the address of a function called to allocate space for an entry and initialize the key and clientData.

typedef Tcl_HashEntry *Tcl_AllocHashEntryProc(
        Tcl_HashTable *tablePtr,
        void *keyPtr);

If this is NULL then Tcl_Alloc is used to allocate enough space for a Tcl_HashEntry, the key pointer is assigned to key.oneWordValue and the clientData is set to NULL. String keys and array keys use this function to allocate enough space for the entry and the key in one block, rather than doing it in two blocks. This saves space for a pointer to the key from the entry and another memory allocation. Tcl_Obj* keys use this function to allocate enough space for an entry and increment the reference count on the value.

The freeEntryProc member contains the address of a function called to free space for an entry.

typedef void Tcl_FreeHashEntryProc(
        Tcl_HashEntry *hPtr);

If this is NULL then Tcl_Free is used to free the space for the entry. Tcl_Obj* keys use this function to decrement the reference count on the value.

KEYWORDS

hash table, key, lookup, search, value
