Tcl_Main(3) Procedimientos de la biblioteca Tcl Tcl_Main(3)

NOMBRE

Tcl_Main, Tcl_MainEx, Tcl_MainExW, Tcl_SetStartupScript, Tcl_GetStartupScript, Tcl_SetMainLoop - programa principal, script de inicio y definición del bucle de eventos para aplicaciones basadas en Tcl

SINOPSIS

#include <tcl.h>

Tcl_Main(argc, argv, appInitProc)

Tcl_MainEx(argc, charargv, appInitProc, interp)

Tcl_MainExW(argc, wideargv, appInitProc, interp)

Tcl_SetStartupScript(path, encoding)

Tcl_Obj *
Tcl_GetStartupScript(encodingPtr)

Tcl_SetMainLoop(mainLoopProc)

ARGUMENTOS

int argc (entrada)
Número de elementos en argv.
char *argv[] (entrada)
Matriz de cadenas que contienen argumentos de línea de comandos. En Windows, cuando se usa -DUNICODE, el tipo del parámetro cambia a wchar_t *.
char *charargv[] (entrada)
Como argv, pero no cambia su tipo a wchar_t.
char *wideargv[] (entrada)
Como argv, pero su tipo es siempre wchar_t.
Tcl_AppInitProc *appInitProc (entrada)
Dirección de un procedimiento de inicialización específico de la aplicación. El valor para este argumento suele ser Tcl_AppInit.
Tcl_Obj *path (entrada)
Nombre del archivo a usar como script de inicio, o NULL.
const char *encoding (entrada)
Codificación del archivo a usar como script de inicio, o NULL.
const char **encodingPtr (salida)
Si no es NULL, ubicación para escribir una copia del (const char *) que apunta al nombre de la codificación.
Tcl_MainLoopProc *mainLoopProc (entrada)
Dirección de un procedimiento de bucle de eventos específico de la aplicación.
Tcl_Interp *interp (entrada)
Intérprete Tcl ya creado.

DESCRIPCIÓN

Tcl_Main puede servir como programa principal para aplicaciones de shell basadas en Tcl. Una “aplicación de shell” es un programa como tclsh o wish que admite tanto la interpretación interactiva de Tcl como la evaluación de un script contenido en un archivo dado como argumento de línea de comandos. Tcl_Main se ofrece como una conveniencia para los desarrolladores de aplicaciones de shell, para que no tengan que reproducir todo el código para la inicialización adecuada de la biblioteca Tcl y la operación de shell interactivo. Otros estilos de incrustar Tcl en una aplicación no son compatibles con Tcl_Main. Estos deben lograrse llamando directamente a las funciones de nivel inferior de la biblioteca Tcl.

La función Tcl_Main ha sido ofrecida por la biblioteca Tcl desde la versión Tcl 7.4. En versiones anteriores de Tcl, la propia biblioteca Tcl definía una función main, pero esa carece de flexibilidad en el estilo de incrustación y tener una función main en una biblioteca (particularmente una biblioteca compartida) causa problemas en muchos sistemas. Tener main en la biblioteca Tcl también dificultaría el uso de Tcl en programas C++, ya que los programas C++ deben tener funciones main especiales de C++.

Normalmente, cada aplicación de shell contiene una pequeña función main que no hace nada más que invocar Tcl_Main. Tcl_Main entonces hace todo el trabajo de crear y ejecutar una aplicación similar a tclsh.

Tcl_Main no es proporcionada por la interfaz pública de la biblioteca de *stubs* de Tcl. Los programas que llaman a Tcl_Main deben enlazarse contra la biblioteca Tcl estándar. Las extensiones (con *stubs* o sin ellos) no están destinadas a llamar a Tcl_Main.

Tcl_Main no es *thread-safe*. Solo debe ser llamada por el hilo principal de una aplicación multihilo. Esta restricción no es un problema en el uso normal descrito anteriormente.

Tcl_Main y, por lo tanto, todas las aplicaciones basadas en ella, como tclsh, utilizan Tcl_GetStdChannel para inicializar los canales estándar a sus valores predeterminados. Consulte Tcl_StandardChannels para obtener más información.

Tcl_Main admite dos modos de operación, dependiendo de si el nombre del archivo y la codificación de un script de inicio se han establecido. Las rutinas Tcl_SetStartupScript y Tcl_GetStartupScript son las herramientas para controlar esta configuración de Tcl_Main.

Tcl_SetStartupScript registra el valor path como el nombre del archivo que Tcl_Main evaluará como su script de inicio. El valor encoding es el nombre Tcl para la codificación utilizada para almacenar el texto en ese archivo. Un valor de NULL para encoding es una señal para usar la codificación del sistema. Un valor de NULL para path borra cualquier registro existente para que Tcl_Main no evalúe ningún script de inicio.

Tcl_GetStartupScript consulta el nombre de archivo y la codificación registrados establecidos por la llamada más reciente a Tcl_SetStartupScript en el mismo hilo. Se devuelve el nombre de archivo almacenado y el nombre de codificación almacenado se escribe en el espacio apuntado por encodingPtr, cuando este no es NULL.

Los valores del nombre de archivo y la codificación administrados por las rutinas Tcl_SetStartupScript y Tcl_GetStartupScript se almacenan por hilo. Aunque las funciones de almacenamiento y recuperación de estas rutinas funcionan en cualquier hilo, solo las llamadas en el mismo hilo principal que Tcl_Main pueden tener alguna influencia sobre ella.

El llamador de Tcl_Main puede llamar primero a Tcl_SetStartupScript para establecer su script de inicio deseado. Si Tcl_Main determina que no se ha establecido ningún script de inicio, consulta los primeros argumentos en argv. Si coinciden con ?-encoding nombre? fileName, donde fileName no comienza con el carácter -, entonces fileName se toma como el nombre de un archivo que contiene un script de inicio, y name se toma como el nombre de la codificación del contenido de ese archivo. Luego, Tcl_Main llama a Tcl_SetStartupScript con estos valores.

A continuación, Tcl_Main define en su intérprete principal las variables Tcl argc, argv, argv0 y tcl_interactive, como se describe en la documentación de tclsh.

Cuando termina su propia inicialización, pero antes de procesar comandos, Tcl_Main llama al procedimiento proporcionado por el argumento appInitProc. Este procedimiento proporciona un “gancho” para que la aplicación realice su propia inicialización del intérprete creado por Tcl_Main, como la definición de comandos específicos de la aplicación. La rutina de inicialización de la aplicación también podría llamar a Tcl_SetStartupScript para (re)establecer el archivo y la codificación que se utilizarán como script de inicio. El procedimiento debe tener una interfaz que coincida con el tipo Tcl_AppInitProc:

typedef int Tcl_AppInitProc(
        Tcl_Interp *interp);

AppInitProc es casi siempre un puntero a Tcl_AppInit; para obtener más detalles sobre este procedimiento, consulte la documentación de Tcl_AppInit.

Cuando el appInitProc termina, Tcl_Main llama a Tcl_GetStartupScript para determinar qué script de inicio se ha solicitado, si alguno. Si se ha proporcionado un script de inicio, Tcl_Main intenta evaluarlo. De lo contrario, el modo interactivo comienza con el examen de la variable tcl_rcFileName en el intérprete principal. Si esa variable existe y contiene el nombre de un archivo legible, el contenido de ese archivo se evalúa en el intérprete principal. Luego comienzan las operaciones interactivas, con los prompts y los resultados de la evaluación de comandos escritos en el canal de salida estándar, y los comandos leídos del canal de entrada estándar y luego evaluados. Los prompts escritos en el canal de salida estándar pueden personalizarse definiendo las variables Tcl tcl_prompt1 y tcl_prompt2 como se describe en la documentación de tclsh. Los prompts y los resultados de la evaluación de comandos se escriben en el canal de salida estándar solo si la variable Tcl tcl_interactive en el intérprete principal contiene un valor entero distinto de cero.

Tcl_SetMainLoop permite establecer un procedimiento de bucle de eventos para ser ejecutado. Esto permite, por ejemplo, que Tk se cargue dinámicamente y establezca su bucle de eventos. El bucle de eventos se ejecutará después del script de inicio. Si está en modo interactivo, establecer el procedimiento de bucle principal hará que el prompt se base en *fileevent* y luego se llamará al procedimiento de bucle. Cuando el procedimiento de bucle regrese en modo interactivo, la operación interactiva continuará. El procedimiento de bucle principal debe tener una interfaz que coincida con el tipo Tcl_MainLoopProc:

typedef void Tcl_MainLoopProc(void);

Tcl_Main no regresa. Normalmente, un programa basado en Tcl_Main terminará cuando se evalúe el comando exit. En modo interactivo, si se encuentra un EOF o un error de canal en el canal de entrada estándar, entonces Tcl_Main evaluará el comando **exit**.

Tcl_MainExW(3) — Tcl

NAME

Tcl_MainExW — Tcl application initialization

SYNOPSIS

#include <tcl.h>

int
Tcl_MainExW(
    int argc,
    Tcl_Obj *CONST objv[],
    Tcl_AppInitProc *appInitProc,
    Tcl_Interp *interp
);

ARGUMENTS

int argc
Number of elements in objv.
Tcl_Obj *CONST objv[]
Argument values for the application. The first element objv[0] is the name used to invoke the application. The remaining elements are any additional arguments. These are Tcl objects, not C strings.
Tcl_AppInitProc *appInitProc
Procedure to call to perform application-specific initialization. See Tcl_AppInit for details.
Tcl_Interp *interp
Interpreter to use for the application. If NULL, a new interpreter will be created.

DESCRIPTION

Tcl_MainExW is the main entry point for Tcl applications that accept Tcl objects as command-line arguments. It is similar to Tcl_Main, but it takes command-line arguments as an array of Tcl objects rather than C strings.

The function performs the following steps:

  1. If interp is NULL, it creates a new Tcl interpreter using Tcl_CreateInterp.
  2. It initializes the interpreter's standard channels (stdin, stdout, stderr) by calling Tcl_StandardChannels. The standard channels are configured based on the platform and interpreter settings.
  3. It calls the procedure pointed to by appInitProc. This procedure is responsible for application-specific initialization, such as creating custom commands or loading Tcl packages.
  4. It converts the command-line arguments from an array of Tcl objects (objv) into a Tcl list and sets this list as the value of the global variable argc. The first element of the list (argv[0]) is the name used to invoke the application.
  5. If a startup script was specified (e.g., via the -E option or the TCLLIBPATH environment variable), it evaluates that script using Tcl_FClose.
  6. It enters the Tcl event loop by calling Tcl_DoOneEvent repeatedly. This loop processes Tcl events, such as I/O events, timers, and child process events.
  7. When the main loop procedure (if any) returns, Tcl_MainExW evaluates the exit command. This typically terminates the application.

In interactive mode (when stdin is connected to a terminal), Tcl_MainExW will continue to read and evaluate commands from stdin after the main loop procedure (if any) returns. In non-interactive mode, after Tcl_MainExW evaluates the startup script, and the main loop procedure (if any) returns, Tcl_MainExW will also evaluate the exit command.

tclsh(1), Tcl_GetStdChannel(3), Tcl_StandardChannels(3), Tcl_AppInit(3), exit(n), encoding(n)

KEYWORDS

application-specific initialization, command-line arguments, main program
