ARGUMENTOS

Tcl_Interp *interp (entrada)
El intérprete al cual se almacenarán los datos comprimidos o sin comprimir. También es donde se escribirán los mensajes de error. Para Tcl_ZlibStreamInit, este puede ser NULL para crear un flujo que no esté ligado a un comando.
int format (entrada)
Cuál es el formato de los datos comprimidos que se utilizará. Debe ser uno de TCL_ZLIB_FORMAT_ZLIB para datos de formato zlib, TCL_ZLIB_FORMAT_GZIP para datos de formato gzip, o TCL_ZLIB_FORMAT_RAW para datos comprimidos en bruto. Además, para la descompresión, también puede ser elegido TCL_ZLIB_FORMAT_AUTO, que puede detectar automáticamente si los datos comprimidos estaban en formato zlib o gzip.
Tcl_Obj *dataObj (entrada/salida)
Un valor de array de bytes que contiene los datos a comprimir o descomprimir, o el que se añadirá al dato extraído del flujo cuando se le pasa a Tcl_ZlibStreamGet.
int level (entrada)
Qué nivel de compresión se utilizará. Debe ser un número entre 0 y 9 o uno de los siguientes: TCL_ZLIB_COMPRESS_NONE para ninguna compresión, TCL_ZLIB_COMPRESS_FAST para compresión rápida pero ineficiente, TCL_ZLIB_COMPRESS_BEST para compresión lenta pero máxima, o TCL_ZLIB_COMPRESS_DEFAULT para el nivel recomendado por la biblioteca zlib.
Tcl_Obj *dictObj (entrada/salida)
Un diccionario que contiene, o que será actualizado para contener, una descripción del encabezado gzip asociado con los datos comprimidos. Solo es útil cuando el formato es TCL_ZLIB_FORMAT_GZIP o TCL_ZLIB_FORMAT_AUTO. Si se pasa un NULL, se usará un encabezado por defecto en la compresión y el encabezado se ignorará (excepto para los controles de integridad) en la descompresión. Ver la sección DICCIONARIO DE OPCIONES GZIP para detalles sobre el contenido de este diccionario.
unsigned int initValue (entrada)
El valor inicial para el algoritmo de suma de verificación.
int bufferSize (entrada)
Un indicador de qué tamaño de buffer se utilizará para recibir los datos. Use 0 para usar una estimación basada en los datos de entrada.
unsigned char *bytes (entrada)
Un array de bytes para ejecutar el algoritmo de suma de verificación, o NULL para obtener el valor inicial recomendado para el algoritmo de suma de verificación.
int length (entrada)
El número de bytes en el array.
int mode (entrada)
Cuál es el modo en el cual operará el flujo. Debe ser uno de TCL_ZLIB_STREAM_DEFLATE para un flujo de compresión o TCL_ZLIB_STREAM_INFLATE para un flujo de descompresión.
Tcl_ZlibStream *zshandlePtr (salida)
Un puntero a una variable en la cual se escribirá el token abstracto del flujo al crearlo con éxito.
Tcl_ZlibStream zshandle (entrada)
El token abstracto del flujo sobre el cual se operará.
int flush (entrada)
Y cómo se debe vaciar el flujo después de escribir los datos en él. Debe ser uno de: TCL_ZLIB_NO_FLUSH si no se va a vaciar, TCL_ZLIB_FLUSH si el dato actualmente comprimido debe ser accesible mediante Tcl_ZlibStreamGet, TCL_ZLIB_FULLFLUSH si el flujo debe ser puesto en un estado donde el descompresor pueda recuperarse de la corrupción, o TCL_ZLIB_FINALIZE para asegurar que el flujo esté terminado y que cualquier trailer solicitado por el formato se escriba.
int count (entrada)
El número máximo de bytes a obtener del flujo, o -1 para obtener todos los bytes restantes de los buffers del flujo.
Tcl_Obj *compDict (entrada)
Un valor de array de bytes que se utilizará como el diccionario de compresión para el flujo. Cabe destacar que este no es un diccionario Tcl, y se recomienda solo usarlo con flujos creados con su formato establecido a TCL_ZLIB_FORMAT_ZLIB, ya que otros formatos no tienen un mecanismo para indicar si se utilizó un diccionario de compresión, excepto fallar en la descompresión.

DESCRIPCIÓN

Estas funciones son la interfaz desde la biblioteca Tcl a la biblioteca Zlib de Jean-loup Gailly y Mark Adler.

Tcl_ZlibDeflate y Tcl_ZlibInflate respectivamente comprimen y descomprimen los datos contenidos en el argumento dataObj, según el format y, para la compresión, el argumento level. El diccionario en el dictObj se utiliza para transmitir información adicional sobre el encabezado de datos comprimidos cuando el formato de compresión lo soporta; actualmente, el diccionario se usa solo cuando el formato es TCL_ZLIB_FORMAT_GZIP o TCL_ZLIB_FORMAT_AUTO. Para detalles sobre el contenido del diccionario, vea la sección DICCIONARIO DE OPCIONES GZIP. Una vez que se realiza la operación con éxito, ambas funciones dejan los datos comprimidos o descomprimidos en un valor de array de bytes que es el resultado del intérprete Tcl; el valor devuelto es un código de resultado estándar de Tcl.

Tcl_ZlibAdler32 y Tcl_ZlibCRC32 calculan sumas de verificación en arrays de bytes, devolviendo la suma calculada. Las sumas de verificación se calculan incrementalmente, lo que permite procesar los datos de un bloque a otro, pero esto requiere que el llamador mantenga el valor actual de la suma y lo pase como el parámetro initValue; el valor inicial para esto puede obtenerse usando NULL para el parámetro bytes en lugar de un puntero a un array de bytes para calcular la suma sobre. Por lo tanto, la utilización típica en un solo bloque de datos es la siguiente:

checksum = Tcl_ZlibCRC32(Tcl_ZlibCRC32(0,NULL,0), data, length);

Nota: el algoritmo Adler-32 no es una verificación real, sino un tipo de hash relacionado que funciona mejor en datos más largos.

FLUJOS ZLIB

Tcl_ZlibStreamInit crea un flujo de compresión o descompresión ligado a un comando Tcl, según sus argumentos, y proporciona un token abstracto para el flujo y devuelve un código de resultado normal; Tcl_ZlibStreamGetCommandName devuelve el nombre del comando dado el token del flujo, o NULL si el flujo no tiene un comando. Los flujos no están diseñados para ser seguros en multihilo; cada flujo debe ser utilizado solo en el hilo que lo creó. Cuando se trabaja con flujos gzip, un diccionario (valores como los dados en la sección DICCIONARIO DE OPCIONES GZIP) puede ser dado a través del parámetro dictObj, que permite controlar los encabezados generados en la compresión y descubrir los encabezados existentes en la descompresión. Tenga en cuenta que el diccionario se escribirá en el momento en que se hayan leído suficientes datos para tener un encabezado completo. Esto significa que el diccionario debe ser un valor no compartido en ese caso; se sugiere utilizar un valor vacío creado con Tcl_NewObj.

Una vez construido un flujo, se utiliza Tcl_ZlibStreamPut para añadir datos al flujo y Tcl_ZlibStreamGet para obtener datos del flujo después de procesar. Ambos devuelven códigos de resultado normales y dejan un mensaje de error en el resultado del intérprete con el que está registrado el flujo (si se ha realizado un registro de error). Con Tcl_ZlibStreamPut, el valor del buffer de datos pasado a él no debe modificarse después. Con Tcl_ZlibStreamGet, el valor del buffer de datos pasado a él tendrá los bytes de datos añadidos a él. Internamente al flujo, los datos se mantienen comprimidos para minimizar el costo del espacio de buffer.

Eof devuelve un valor booleano que indica si se ha alcanzado el final de los datos descomprimidos.

Tcl_ZlibStreamSetCompressionDictionary se utiliza para controlar el diccionario de compresión utilizado con el flujo, un diccionario de compresión es un array de bytes (tal como podría crearse con Tcl_NewByteArrayObj) que se utiliza para inicializar el motor de compresión en lugar de dejar que lo cree sobre la marcha a partir de los datos que se comprimen. Establecer un diccionario de compresión permite una compresión más eficiente en el caso de que el inicio de los datos sea muy regular, pero requiere que tanto el compresor como el descompresor acuerden el valor a utilizar. Los diccionarios de compresión solo son totalmente compatibles con datos en formato zlib; al comprimir, deben establecerse antes de que se envíen datos con Tcl_ZlibStreamPut, y al descomprimir deben establecerse cuando Tcl_ZlibStreamGet produce un error con su -errorcode establecido en “ZLIB NEED_DICT código”; el código será la suma de verificación Adler-32 (ver Tcl_ZlibAdler32) del diccionario de compresión buscado. (Tenga en cuenta que esto solo es cierto para flujos en formato zlib; los flujos gzip ignoran los diccionarios de compresión ya que la especificación del formato no los permite, y los flujos sin formato simplemente producen un error de datos si el diccionario de compresión falta o es incorrecto).

Si desea borrar un flujo y reutilizarlo para una nueva acción de compresión o descompresión, Tcl_ZlibStreamReset lo hará y devolverá un código de resultado Tcl normal para indicar si tuvo éxito; si el flujo está registrado con un intérprete, se dejará un mensaje de error en el resultado del intérprete cuando esta función devuelva TCL_ERROR. Finalmente, Tcl_ZlibStreamClose limpiará el flujo y eliminará el comando asociado: usar Tcl_DeleteCommand en el comando del flujo es equivalente (cuando dicho comando existe).

OPCIONES GZIP DICIONARIO

El parámetro dictObj a Tcl_ZlibDeflate, Tcl_ZlibInflate y Tcl_ZlibStreamInit se utiliza para pasar un diccionario de opciones sobre el cual se utiliza para describir la cabecera gzip en los datos comprimidos. Al crear datos comprimidos, el diccionario se lee y al desempaquetar datos comprimidos, el diccionario se escribe (en cuyo caso el parámetro dictObj debe referirse a un valor de diccionario no compartido).

Los siguientes campos en el valor del diccionario son entendidos. Todos los demás campos se ignoran. Ningún campo es requerido al crear un flujo en formato gzip.

comment
Esto contiene el campo de comentario de la cabecera, si está presente. Si está ausente, no se proporcionó ningún comentario (al descomprimir) ni se creará (al comprimir).
crc
Un valor booleano que describe si se calcula una CRC de la cabecera. Tenga en cuenta que el programa gzip no utiliza ni permite una CRC en la cabecera.
filename
El nombre del archivo que contenía los datos sin comprimir. No debe contener separadores de directorio y debe ser saneado antes de su uso al descomprimir con file tail.
os
El campo del código de tipo del sistema operativo de la cabecera (si no es el valor “unknown”). Ver RFC 1952 para el significado de estos códigos. Al comprimir, si esto está ausente, el campo se establecerá en el valor “unknown”.
size
El tamaño de los datos sin comprimir. Esto se ignora al comprimir; el tamaño de los datos comprimidos depende de cuántos datos se suministran al motor de compresión.
time
El campo de tiempo de la cabecera si no es cero, se espera que sea la hora en que se modificó el archivo nombrado por el campo filename. Adecuado para su uso con clock format. Al crear, el valor correcto a usar es el de clock seconds o file mtime.
type
El tipo de los datos sin comprimir (ya sea binary o text) si se conoce.

NOTAS DE PORTABILIDAD

Estas funciones fallarán de forma controlada si Tcl no está enlazado con la biblioteca zlib.
