Tcl_CreateFileHandler(3) Procedimientos de la biblioteca Tcl Tcl_CreateFileHandler(3)

NOMBRE

Tcl_CreateFileHandler, Tcl_DeleteFileHandler - asociar devoluciones de llamada de procedimiento con archivos o dispositivos (solo Unix)

SINOPSIS

#include <tcl.h>

Tcl_CreateFileHandler(fd, mask, proc, clientData)

Tcl_DeleteFileHandler(fd)

ARGUMENTOS

int fd (entrada)
Descriptor de archivo de Unix para un archivo o dispositivo abierto.
int mask (entrada)
Condiciones bajo las cuales se debe llamar a proc: combinación OR de TCL_READABLE, TCL_WRITABLE y TCL_EXCEPTION. Puede establecerse a 0 para deshabilitar temporalmente un manejador.
Tcl_FileProc *proc (entrada)
Procedimiento a invocar cada vez que el archivo o dispositivo indicado por file cumpla las condiciones especificadas por mask.
ClientData clientData (entrada)
Valor arbitrario de una palabra para pasar a proc.

DESCRIPCIÓN

Tcl_CreateFileHandler organiza para que se invoque proc en el futuro cada vez que la E/S sea posible en un archivo o exista una condición excepcional para el archivo. El archivo se indica mediante fd, y las condiciones de interés se indican mediante mask. Por ejemplo, si mask es TCL_READABLE, se llamará a proc cuando el archivo sea legible. La devolución de llamada a proc la realiza Tcl_DoOneEvent, por lo que Tcl_CreateFileHandler solo es útil en programas que despachan eventos a través de Tcl_DoOneEvent o a través de comandos de Tcl como vwait.

Proc debe tener argumentos y resultados que coincidan con el tipo Tcl_FileProc:

typedef void Tcl_FileProc(
        ClientData clientData,
        int mask);

El parámetro clientData para proc es una copia del parámetro clientData dado a Tcl_CreateFileHandler cuando se creó la devolución de llamada. Típicamente, clientData apunta a una estructura de datos que contiene información específica de la aplicación sobre el archivo. Mask es una máscara entera que indica cuáles de las condiciones solicitadas existen realmente para el archivo; contendrá un subconjunto de los bits del argumento mask a Tcl_CreateFileHandler.

Solo puede existir un manejador para un archivo determinado en un momento dado. Si se llama a Tcl_CreateFileHandler cuando ya existe un manejador para fd, la nueva devolución de llamada reemplaza la información que se registró previamente.

Se puede llamar a Tcl_DeleteFileHandler para eliminar el manejador de archivo para fd; si no existe ningún manejador para el archivo proporcionado por fd, el procedimiento no tiene ningún efecto.

El propósito de los manejadores de archivo es permitir que una aplicación responda a eventos mientras espera que los archivos estén listos para E/S. Para que esto funcione correctamente, la aplicación puede necesitar utilizar operaciones de E/S no bloqueantes en los archivos para los que se declaran manejadores. De lo contrario, la aplicación puede bloquearse si lee o escribe demasiados datos; mientras espera que la E/S se complete, la aplicación no podrá atender otros eventos. Use Tcl_SetChannelOption con -blocking para establecer el canal en modo bloqueante o no bloqueante según sea necesario.

Tenga en cuenta que estas interfaces solo son compatibles con la implementación de Unix del notificador de Tcl.
