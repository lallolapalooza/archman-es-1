Tcl_RegExpMatch, Tcl_RegExpCompile, Tcl_RegExpExec, Tcl_RegExpRange, Tcl_GetRegExpFromObj, Tcl_RegExpMatchObj, Tcl_RegExpExecObj, Tcl_RegExpGetInfo - Coincidencia de patrones con expresiones regulares

Tcl_RegExpExec(interp, regexp, text, start)

Tcl_RegExpRange(regexp, index, startPtr, endPtr)

Tcl_RegExp
Tcl_GetRegExpFromObj(interp, patObj, cflags)

Tcl_RegExpExecObj(interp, regexp, textObj, offset, nmatches, eflags)

ARGUMENTOS

Tcl_Interp *interp (entrada)
Intérprete de Tcl a usar para la notificación de errores. El intérprete puede ser NULL si no se desea notificación de errores.
Tcl_Obj *textObj (entrada/salida)
Se refiere al valor del cual obtener el texto a buscar. La representación interna del valor puede ser convertida a un formato que pueda ser buscado eficientemente.
Tcl_Obj *patObj (entrada/salida)
Se refiere al valor del cual obtener una expresión regular. La expresión regular compilada se almacena en caché en el valor.
const char *text (entrada)
Texto a buscar para una coincidencia con una expresión regular.
const char *pattern (entrada)
Cadena con el formato de un patrón de expresión regular.
Tcl_RegExp regexp (entrada)
Expresión regular compilada. Debe haber sido devuelta previamente por Tcl_GetRegExpFromObj o Tcl_RegExpCompile.
const char *start (entrada)
Si text es solo una porción de alguna otra cadena, este argumento identifica el principio de la cadena mayor. Si no es lo mismo que text, entonces no se permitirán coincidencias de “^”.
int index (entrada)
Especifica qué rango se desea: 0 significa el rango de la coincidencia completa, 1 o mayor significa el rango que coincidió con una subexpresión entre paréntesis.
const char **startPtr (salida)
La dirección del primer carácter en el rango se almacena aquí, o NULL si no existe tal rango.
const char **endPtr (salida)
La dirección del carácter justo después del último en el rango se almacena aquí, o NULL si no existe tal rango.
int cflags (entrada)
Combinación OR de las banderas de compilación TCL_REG_ADVANCED, TCL_REG_EXTENDED, TCL_REG_BASIC, TCL_REG_EXPANDED, TCL_REG_QUOTE, TCL_REG_NOCASE, TCL_REG_NEWLINE, TCL_REG_NLSTOP, TCL_REG_NLANCH, TCL_REG_NOSUB, y TCL_REG_CANMATCH. Ver más abajo para más información.
int offset (entrada)
El desplazamiento de caracteres en el texto donde debe comenzar la coincidencia. El valor del desplazamiento no tiene impacto en las coincidencias de ^. Este comportamiento está controlado por eflags.
int nmatches (entrada)
El número de subexpresiones coincidentes que deben ser recordadas para uso posterior. Si este valor es 0, entonces no se calculará información de coincidencia de subexpresiones. Si el valor es -1, entonces se recordarán todas las subexpresiones coincidentes. Cualquier otro valor se tomará como el número máximo de subexpresiones a recordar.
int eflags (entrada)
Combinación OR de las banderas de ejecución TCL_REG_NOTBOL y TCL_REG_NOTEOL. Ver más abajo para más información.
Tcl_RegExpInfo *infoPtr (salida)
La dirección de la ubicación donde la información sobre una coincidencia previa debe ser almacenada por Tcl_RegExpGetInfo.

DESCRIPCIÓN

Tcl_RegExpMatch determina si su argumento pattern coincide con regexp, donde regexp se interpreta como una expresión regular usando las reglas de la página de referencia re_syntax. Si hay una coincidencia, Tcl_RegExpMatch devuelve 1. Si no hay coincidencia, Tcl_RegExpMatch devuelve 0. Si ocurre un error en el proceso de coincidencia (por ejemplo, pattern no es una expresión regular válida), entonces Tcl_RegExpMatch devuelve -1 y deja un mensaje de error en el resultado del intérprete. Tcl_RegExpMatchObj es similar a Tcl_RegExpMatch excepto que opera en los valores Tcl textObj y patObj en lugar de cadenas UTF. Tcl_RegExpMatchObj es generalmente más eficiente que Tcl_RegExpMatch, por lo que es la interfaz preferida.

Tcl_RegExpCompile, Tcl_RegExpExec y Tcl_RegExpRange proporcionan acceso de bajo nivel al motor de búsqueda de patrones de expresiones regulares. Tcl_RegExpCompile compila una cadena de expresión regular a la forma interna utilizada para una coincidencia de patrones eficiente. El valor de retorno es un token para esta forma compilada, que puede usarse en llamadas posteriores a Tcl_RegExpExec o Tcl_RegExpRange. Si ocurre un error al compilar la expresión regular, Tcl_RegExpCompile devuelve NULL y deja un mensaje de error en el resultado del intérprete. Nota: el valor de retorno de Tcl_RegExpCompile solo es válido hasta la próxima llamada a Tcl_RegExpCompile; no es seguro conservar estos valores durante largos períodos de tiempo.

Tcl_RegExpExec ejecuta el motor de búsqueda de patrones de expresiones regulares. Devuelve 1 si text contiene un rango de caracteres que coincide con regexp, 0 si no se encuentra ninguna coincidencia y -1 si ocurre un error. En caso de error, Tcl_RegExpExec deja un mensaje de error en el resultado del intérprete. Al buscar en una cadena múltiples coincidencias de un patrón, es importante distinguir entre el inicio de la cadena original y el inicio de la búsqueda actual. Por ejemplo, al buscar la segunda ocurrencia de una coincidencia, el argumento text podría apuntar al carácter justo después de la primera coincidencia; sin embargo, es importante que el motor de búsqueda sepa que este no es el inicio de toda la cadena, para que no permita que los átomos “^” en el patrón coincidan. El argumento start proporciona esta información apuntando al inicio de la cadena general que contiene text. Start será menor o igual que text; si es menor que text, entonces no se permitirán coincidencias de ^.

Tcl_RegExpRange puede invocarse después de que Tcl_RegExpExec devuelva; proporciona información detallada sobre qué rangos de la cadena coincidieron con qué partes del patrón. Tcl_RegExpRange devuelve un par de punteros en *startPtr y *endPtr que identifican un rango de caracteres en la cadena fuente para la llamada más reciente a Tcl_RegExpExec. Index indica cuál de varios rangos se desea: si index es 0, se devuelve información sobre el rango general de caracteres que coincidió con el patrón completo; de lo contrario, se devuelve información sobre el rango de caracteres que coincidió con la subexpresión entre paréntesis index-ésima dentro del patrón. Si no hay un rango que corresponda a index, entonces se almacena NULL en *startPtr y *endPtr.

Tcl_GetRegExpFromObj, Tcl_RegExpExecObj y Tcl_RegExpGetInfo son interfaces de valores que proporcionan el control más directo de la biblioteca de expresiones regulares de Henry Spencer. Para los usuarios que necesitan modificar las opciones de compilación y ejecución directamente, se recomienda usar estas interfaces en lugar de llamar a las funciones internas de expresiones regulares. Estas interfaces manejan los detalles de las traducciones de UTF a Unicode, además de proporcionar un rendimiento mejorado a través del almacenamiento en caché en los valores de patrón y cadena.

Tcl_GetRegExpFromObj intenta devolver una expresión regular compilada del patObj. Si el valor no contiene ya una expresión regular compilada, intentará crear una a partir de la cadena en el valor y asignarla a la representación interna del patObj. El valor de retorno de esta función es de tipo Tcl_RegExp. El valor de retorno es un token para esta forma compilada, que puede usarse en llamadas posteriores a Tcl_RegExpExecObj o Tcl_RegExpGetInfo. Si ocurre un error al compilar la expresión regular, Tcl_GetRegExpFromObj devuelve NULL y deja un mensaje de error en el resultado del intérprete. El token de expresión regular puede usarse siempre que la representación interna de patObj se refiera a la forma compilada. ARGUMENTOS

Se puede especificar uno de los siguientes flags de compilación cuando se llama a Tcl_RegExpCompile o Tcl_RegExpCompileObj:

TCL_REG_ADVANCED
Compilar expresiones regulares avanzadas (ERAs). Este modo corresponde a la sintaxis normal de expresiones regulares aceptada por los comandos regexp y regsub de Tcl.
TCL_REG_EXTENDED
Compilar expresiones regulares extendidas (EREs). Este modo corresponde a la sintaxis de expresiones regulares reconocida por Tcl 8.0 y versiones anteriores.
TCL_REG_BASIC
Compilar expresiones regulares básicas (BREs). Este modo corresponde a la sintaxis de expresiones regulares reconocida por utilidades comunes de Unix como sed y grep. Este es el valor predeterminado si no se especifican flags.
TCL_REG_EXPANDED
Compilar la expresión regular (básica, extendida o avanzada) utilizando una sintaxis expandida que permite comentarios y espacios en blanco. Este modo hace que los espacios en blanco no escapados y no encerrados en expresiones de corchetes, y los comentarios de # a fin de línea se ignoren.
TCL_REG_QUOTE
Compilar una cadena literal, con todos los caracteres tratados como caracteres ordinarios.
TCL_REG_NOCASE
Compilar para coincidencias que ignoran las distinciones entre mayúsculas y minúsculas.
TCL_REG_NEWLINE
Compilar para coincidencias sensibles a saltos de línea. Por defecto, el salto de línea es un carácter completamente ordinario sin significado especial en expresiones regulares o cadenas. Con este flag, las expresiones de corchetes "[^...]" y el punto "." nunca coinciden con un salto de línea, "^" coincide con una cadena vacía después de cualquier salto de línea además de su función normal, y "$" coincide con una cadena vacía antes de cualquier salto de línea además de su función normal. REG_NEWLINE es el OR a nivel de bits de REG_NLSTOP y REG_NLANCH.
TCL_REG_NLSTOP
Compilar para coincidencias parciales sensibles a saltos de línea, con el comportamiento de las expresiones de corchetes "[^...]" y el punto "." afectado, pero no el comportamiento de "^" y "$". En este modo, las expresiones de corchetes "[^...]" y el punto "." nunca coinciden con un salto de línea.
TCL_REG_NLANCH
Compilar para coincidencias parciales inversas sensibles a saltos de línea, con el comportamiento de "^" y "$" (los "anclajes") afectado, pero no el comportamiento de las expresiones de corchetes "[^...]" y el punto ".". En este modo, "^" coincide con una cadena vacía después de cualquier salto de línea además de su función normal, y "$" coincide con una cadena vacía antes de cualquier salto de línea además de su función normal.
TCL_REG_NOSUB
Compilar para coincidencias que solo informan de éxito o fracaso, no de lo que coincidió. Esto reduce la sobrecarga de compilación y puede mejorar el rendimiento. Las llamadas posteriores a Tcl_RegExpGetInfo o Tcl_RegExpRange no informarán de ninguna información sobre la coincidencia.
TCL_REG_CANMATCH
Compilar para coincidencias que informan de la posibilidad de completar una coincidencia parcial dados más texto (ver más abajo).

Solo se puede especificar uno de TCL_REG_EXTENDED, TCL_REG_ADVANCED, TCL_REG_BASIC y TCL_REG_QUOTE.

Tcl_RegExpExecObj ejecuta el comparador de patrones de expresiones regulares. Devuelve 1 si objPtr contiene un rango de caracteres que coincide con regexp, 0 si no se encuentra ninguna coincidencia y -1 si se produce un error. En caso de error, Tcl_RegExpExecObj deja un mensaje de error en el resultado del intérprete. El valor nmatches indica al comparador cuántos subexpresiones son de interés. Si nmatches es 0, entonces no se registra información de coincidencia de subexpresiones, lo que puede permitir al comparador realizar varias optimizaciones. Si el valor es -1, entonces se recuerdan todas las subexpresiones del patrón. Si el valor es un entero positivo, entonces solo se recordará ese número de subexpresiones. La coincidencia comienza en el índice de carácter Unicode especificado por offset. A diferencia de Tcl_RegExpExec, el comportamiento de los anclajes no se ve afectado por el valor de offset. En su lugar, el comportamiento de los anclajes se controla explícitamente mediante el argumento eflags, que es un OR a nivel de bits de cero o más de los siguientes flags:

TCL_REG_NOTBOL
El carácter de inicio no se tratará como el principio de una línea o el principio de la cadena, por lo que "^" no coincidirá allí. Tenga en cuenta que este flag no tiene ningún efecto en cómo coincide "\A".
TCL_REG_NOTEOL
El último carácter de la cadena no se tratará como el final de una línea o el final de la cadena, por lo que "$" no coincidirá allí. Tenga en cuenta que este flag no tiene ningún efecto en cómo coincide "\Z".

Tcl_RegExpGetInfo recupera información sobre la última coincidencia realizada con una expresión regular regexp dada. El argumento infoPtr contiene un puntero a una estructura que se define de la siguiente manera:

typedef struct Tcl_RegExpInfo {
    int nsubs;
    Tcl_RegExpIndices *matches;
    long extendStart;
} Tcl_RegExpInfo;

El campo nsubs contiene un recuento del número de subexpresiones entre paréntesis dentro de la expresión regular. Si se usó TCL_REG_NOSUB, entonces este valor será cero. El campo matches apunta a una matriz de nsubs+1 valores que indican los límites de cada subexpresión coincidente. El primer elemento de la matriz se refiere al rango coincidente por toda la expresión regular, y los elementos subsiguientes se refieren a las subexpresiones entre paréntesis en el orden en que aparecen en el patrón. Cada elemento es una estructura que se define de la siguiente manera:

typedef struct Tcl_RegExpIndices {
    long start;
    long end;
} Tcl_RegExpIndices;

Los valores start y end son índices de caracteres Unicode relativos a la ubicación de desplazamiento dentro de objPtr donde comenzó la coincidencia. El índice start identifica el primer carácter de la subexpresión coincidente. El índice end identifica el primer carácter después de la subexpresión coincidente. Si la subexpresión coincidió con la cadena vacía, entonces start y end serán iguales. Si la subexpresión no participó en la coincidencia, entonces start y end se establecerán en -1.

El campo extendStart en Tcl_RegExpInfo solo se establece si se usó el flag TCL_REG_CANMATCH. Indica el primer carácter de la cadena donde podría ocurrir una coincidencia. Si se encontró una coincidencia, este será el mismo que el principio de la coincidencia actual. Si no se encontró ninguna coincidencia, entonces indica el punto más temprano en el que podría ocurrir una coincidencia si se agregan más texto a la cadena. Si no es posible ninguna coincidencia incluso con texto adicional, este campo se establecerá en -1.
