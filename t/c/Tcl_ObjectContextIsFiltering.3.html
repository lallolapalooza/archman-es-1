DESCRIPCIÓN

Un método es una operación realizada sobre un objeto asociado con el objeto. Cada método debe estar asociado con un objeto o una clase; los métodos asociados a una clase están asociados a todas las instancias (directas e indirectas) de esa clase.

Dado un método, la entidad que lo declaró se puede encontrar usando Tcl_MethodDeclarerClass, que devuelve la clase a la que está asociado el método (o NULL si el método no está asociado a ninguna clase) y Tcl_MethodDeclarerObject, que devuelve el objeto al cual está asociado el método (o NULL si el método no está asociado a ningún objeto). El nombre del método se puede obtener con Tcl_MethodName y si el método es exportado, se puede obtener con Tcl_MethodIsPublic. También se puede inspeccionar el tipo del método de forma limitada; la función Tcl_MethodIsType devuelve si un método es de un tipo específico, asignando el valor clientData a la variable apuntada por clientDataPtr si (aunque no sea NULL) el tipo coincide.

CREACIÓN DE MÉTODOS

Los métodos se crean con Tcl_NewMethod y Tcl_NewInstanceMethod, que crean un método asociado a una clase o a un objeto respectivamente. En ambos casos, el argumento nameObj da el nombre del método a crear, el argumento isPublic indica si el método debe ser exportado inicialmente, el argumento methodTypePtr describe la implementación del método (ver la sección TIPOS DE MÉTODOS siguiente) y el argumento clientData proporciona datos específicos de implementación que se pasan a la implementación del método cuando se llama.

Cuando el argumento nameObj de Tcl_NewMethod es NULL, se crea un método sin nombre, que se usa para constructores y destructores. Los constructores deben instalarse en su clase con Tcl_ClassSetConstructor, y los destructores (que no requieren argumentos) deben instalarse en su clase con Tcl_ClassSetDestructor. Los métodos sin nombre no deben usarse para otros propósitos que no sean constructores o destructores, y los métodos nombrados no deben usarse como constructores o destructores. También se debe tener en cuenta que un NULL methodTypePtr se utiliza para proporcionar señal interna y no debe usarse en código de cliente.

CONTEXTOS DE LLAMADA DE MÉTODOS

Cuando se llama un método, se pasa una referencia de contexto de llamada como uno de los argumentos de la función de implementación. Este contexto puede ser inspeccionado para obtener información sobre el llamador, pero no debe conservarse más allá del momento en que termina la llamada al método.

El método que se está llamando puede recuperarse del contexto con Tcl_ObjectContextMethod, y el objeto que provocó la invocación del método puede recuperarse con Tcl_ObjectContextObject. El número de argumentos que se omiten (por ejemplo, el nombre del objeto y del método en una llamada normal) se lee con Tcl_ObjectContextSkippedArgs, y el contexto también puede informar si está funcionando como un filtro para otro método con Tcl_ObjectContextIsFiltering.

Durante la ejecución de un método, la implementación del método puede elegir invocar las etapas de la cadena de llamada de métodos que vienen después de la implementación actual del método. Esto (el núcleo del comando next) se realiza con Tcl_ObjectContextInvokeNext. Debe tenerse en cuenta que esta función no modifica la pila de llamadas, al igual que el comando next; si la implementación del método ha colocado una o más entradas adicionales en la pila durante su implementación, también debe ser responsable de vaciar esas entradas de la pila mientras se ejecuta la función Tcl_ObjectContextInvokeNext. También debe tenerse en cuenta que el contexto de llamada no se elimina durante la ejecución de esta función.

TIPOS DE MÉTODOS

Los tipos de métodos se describen mediante un puntero a una estructura Tcl_MethodType, que se define como:

typedef struct {
    int version;
    const char *name;
    Tcl_MethodCallProc *callProc;
    Tcl_MethodDeleteProc *deleteProc;
    Tcl_CloneProc *cloneProc;
} Tcl_MethodType;

El campo version permite la expansión futura de la estructura y debe ser declarado igual a TCL_OO_METHOD_VERSION_CURRENT. El campo name proporciona un nombre legible por humanos para el tipo, y es el valor que se expone mediante los comandos info class methodtype y info object methodtype de Tcl.

El campo callProc proporciona una función que se ejecuta cuando se invoca el método; esta función nunca debe ser nula.

El campo deleteProc proporciona una función que se usa para eliminar un método específico, y se ejecuta cuando el método se reemplaza o se elimina; si este campo es nulo, se supone que el clientData del método no necesita ninguna acción especial para su eliminación.

El campo cloneProc es un puntero a una función que se usa para copiar el clientData de un método (como parte de Tcl_CopyObjectInstance), o NULL para indicar que el clientData puede ser copiado directamente.

FIRMA DE LA FUNCIÓN Tcl_MethodCallProc

La firma de la función callProc es la siguiente:

typedef int Tcl_MethodCallProc(Tcl_Interp *interp,
    Tcl_ObjectContext context, int objc, Tcl_Obj *const objv[]);

La función recibe el intérprete, el contexto de llamada, el número de argumentos y una matriz de objetos que representan los argumentos. La función debe devolver TCL_OK o TCL_ERROR y el valor de retorno del comando. Si la llamada devuelve TCL_ERROR, debe dejar un registro de error en el intérprete.

NAME

TclOO object context information - methods, accessors, and constructors

SYNOPSIS

#include <tclOO.h>

ARGUMENTS

ClientData clientData
A pointer to arbitrary user-defined data. This is used to associate arbitrary data with a method, constructor, or accessor.
Tcl_Interp *interp
The interpreter in which the operation is taking place.
Tcl_ObjectContext objectContext
The context in which the object is being invoked.
int objc
The number of arguments in objv.
Tcl_Obj *const *objv
The arguments to the method, constructor, or accessor.
Tcl_Object *objPtr
The object to clone or delete.
Tcl_Object *newObjPtr
The new object after cloning.
Tcl_Method *methodPtr
The method to clone or delete.
Tcl_Method *newMethodPtr
The new method after cloning.
ClientData *newClientDataPtr
A pointer to where the new client data for the cloned method should be written.

DESCRIPTION

TclOO methods can be associated with arbitrary C data. This C data can be passed to the method when it is invoked, or be used to clean up associated resources when the method is deleted.

The TclOO system provides a flexible system for defining methods that can be attached to objects. These methods can be implemented in C and called through a standard Tcl C API.

TCL_METHODCALLPROC FUNCTION SIGNATURE

Functions matching this signature are called when the method is invoked.

typedef int Tcl_MethodCallProc(
        ClientData clientData,
        Tcl_Interp *interp,
        Tcl_ObjectContext objectContext,
        int objc,
        Tcl_Obj *const *objv);

The clientData argument to a Tcl_MethodCallProc is the value that was given when the method was created, the interp is a place in which to execute scripts and access variables as well as being where to put the result of the method, and the objc and objv fields give the parameter objects to the method. The calling context of the method can be discovered through the objectContext argument, and the return value from a Tcl_MethodCallProc is any Tcl return code (e.g. TCL_OK, TCL_ERROR).

TCL_METHODDELETEPROC FUNCTION SIGNATURE

Functions matching this signature are used when a method is deleted, whether through a new method being created or because the object or class is deleted.

typedef void Tcl_MethodDeleteProc(
        ClientData clientData);

The clientData argument to a Tcl_MethodDeleteProc will be the same as the value passed to the clientData argument to Tcl_NewMethod or Tcl_NewInstanceMethod when the method was created.

TCL_CLONEPROC FUNCTION SIGNATURE

Functions matching this signature are used to copy a method when the object or class is copied using Tcl_CopyObjectInstance (or oo::copy).

typedef int Tcl_CloneProc(
        Tcl_Interp *interp,
        ClientData oldClientData,
        ClientData *newClientDataPtr);

The interp argument gives a place to write an error message when the attempt to clone the object is to fail, in which case the clone procedure must also return TCL_ERROR; it should return TCL_OK otherwise. The oldClientData field to a Tcl_CloneProc gives the value from the method being copied from, and the newClientDataPtr field will point to a variable in which to write the value for the method being copied to.
