DESCRIPCIÓN

Existen varias razones para llamar a las funciones de la API Tcl_FS (por ejemplo, Tcl_FSAccess y Tcl_FSStat) en lugar de llamar directamente a funciones de nivel de sistema como access y stat. Primero, funcionarán multiplataforma, por lo que una extensión que las llama debería funcionar sin modificaciones en Unix y Windows. Segundo, la implementación de Windows de algunas de estas funciones corrige algunos errores en las llamadas de nivel de sistema. Tercero, estas llamadas a funciones manejan cualquier conversión de ruta de "Utf a nativo de plataforma" que pueda ser necesaria (y pueden almacenar en caché los resultados de dichas conversiones para una mayor eficiencia en llamadas posteriores). Cuarto, y quizás lo más importante, todas estas funciones son "conscientes del sistema de archivos virtual" (virtual filesystem aware). Cualquier sistema de archivos virtual (VFS, por sus siglas en inglés) que se haya registrado (a través de Tcl_FSRegister) puede redirigir el acceso a archivos a medios o métodos de acceso alternativos. Esto significa que todas estas funciones (y, por lo tanto, los comandos de Tcl correspondientes file, glob, pwd, cd, open, etc.) pueden operar sobre "archivos" que no son archivos nativos en el sistema de archivos nativo. Esto también significa que cualquier extensión de Tcl que acceda al sistema de archivos (FS, por sus siglas en inglés) a través de esta API es automáticamente "consciente del sistema de archivos virtual". Por supuesto, si una extensión accede al sistema de archivos nativo directamente (a través de APIs específicas de plataforma, por ejemplo), Tcl no puede interceptar tales llamadas.

Si se han registrado VFS apropiados, los "archivos" pueden ser, para dar dos ejemplos, remotos (por ejemplo, situados en un servidor ftp remoto) o archivados (por ejemplo, dentro de un archivo .zip). Dichos sistemas de archivos registrados proporcionan una tabla de consulta de funciones para implementar toda o parte de la funcionalidad enumerada aquí. Finalmente, las llamadas Tcl_FSStat y Tcl_FSLstat abstraen lo que es realmente el búfer de "struct stat", lo que permite usar el mismo código tanto en sistemas con como sin soporte para archivos de más de 2 GB de tamaño.

La API Tcl_FS está "Tcl_Obj"-ificada y puede almacenar en caché representaciones internas y otras cadenas relacionadas con rutas (por ejemplo, el directorio de trabajo actual). Un efecto secundario de esto es que no se deben pasar valores con un recuento de referencias de cero a ninguna de estas funciones. Si tales llamadas se manejaran, podrían resultar en fugas de memoria (en algunas circunstancias, el código del sistema de archivos puede desear retener una referencia al valor pasado, y por lo tanto no se puede asumir que después de que alguna de estas llamadas regrese, el valor todavía tiene un recuento de referencias de cero - puede haber sido incrementado) o en una falla de segmentación directa (u otro error de acceso a memoria) debido a que el valor sea liberado a mitad de la manipulación compleja del valor requerida para asegurar que la ruta esté completamente normalizada y sea absoluta para la determinación del sistema de archivos. La lección práctica a aprender de esto es que

Tcl_Obj *path = Tcl_NewStringObj(...);
Tcl_FSWhatever(path);
Tcl_DecrRefCount(path);

es incorrecto y puede causar errores de memoria. El recuento de referencias de path debe incrementarse antes de pasarlo, o decrementarse. Por esta razón, los valores con un recuento de referencias de cero se consideran rutas de sistema de archivos no válidas y llamar a cualquier función de la API Tcl_FS con dicho valor no tendrá ningún efecto.

FUNCIONES DE LA API FS

Tcl_FSCopyFile intenta copiar el archivo dado por srcPathPtr a la ruta dada por destPathPtr. Si las dos rutas dadas se encuentran en el mismo sistema de archivos (según Tcl_FSGetFileSystemForPath), entonces se llama a la función de "copiar archivo" de ese sistema de archivos (si no es NULL). De lo contrario, la función devuelve -1 y establece la variable global de C errno al código de error POSIX "EXDEV" (que significa un "enlace entre dominios").

Tcl_FSCopyDirectory intenta copiar el directorio dado por srcPathPtr a la ruta dada por destPathPtr. Si las dos rutas dadas se encuentran en el mismo sistema de archivos (según Tcl_FSGetFileSystemForPath), entonces se llama a la función de "copiar directorio" de ese sistema de archivos (si no es NULL). De lo contrario, la función devuelve -1 y establece la variable global de C errno al código de error POSIX "EXDEV" (que significa un "enlace entre dominios").

Tcl_FSCreateDirectory intenta crear el directorio dado por pathPtr llamando a la función de "crear directorio" del sistema de archivos propietario.

Tcl_FSDeleteFile intenta eliminar el archivo dado por pathPtr llamando a la función de "eliminar archivo" del sistema de archivos propietario.

Tcl_FSRemoveDirectory intenta eliminar el directorio dado por pathPtr llamando a la función de "eliminar directorio" del sistema de archivos propietario.

Tcl_FSRenameFile intenta renombrar el archivo o directorio dado por srcPathPtr a la ruta dada por destPathPtr. Si las dos rutas dadas se encuentran en el mismo sistema de archivos (según Tcl_FSGetFileSystemForPath), entonces se llama a la función de "renombrar archivo" de ese sistema de archivos (si no es NULL). De lo contrario, la función devuelve -1 y establece la variable global de C errno al código de error POSIX "EXDEV" (que significa un "enlace entre dominios").

Tcl_FSListVolumes llama a cada sistema de archivos que tiene una función de "listar volúmenes" no NULL y les pide que devuelvan su lista de volúmenes raíz. Acumula los valores de retorno en una lista que se devuelve al llamador (con un recuento de referencias de 0).

Tcl_FSEvalFileEx lee el archivo dado por pathPtr utilizando la codificación identificada por encodingName y evalúa su contenido como un script Tcl. Devuelve la misma información que Tcl_EvalObjEx. Si encodingName es NULL, se utiliza la codificación del sistema para leer el contenido del archivo. Si el archivo no se pudo leer, se devuelve un error de Tcl para describir por qué no se pudo leer. El carácter eof para los archivos es "\x1A" (^Z) para todas las plataformas. Si requiere un "^Z" en código para comparación de cadenas, puede usar "\x1A", que será sustituido de forma segura por el intérprete Tcl en "^Z". Tcl_FSEvalFile es una versión más simple de Tcl_FSEvalFileEx que siempre utiliza la codificación del sistema al leer el archivo.

Tcl_FSLoadFile carga dinámicamente un archivo de código binario en memoria y devuelve las direcciones de dos procedimientos dentro de ese archivo, si están definidos. Se llamará a la función apropiada para el sistema de archivos al que pertenece pathPtr. Si ese sistema de archivos no implementa esta función (la mayoría de los sistemas de archivos virtuales no lo harán, debido a limitaciones del sistema operativo en la carga dinámica de código binario), Tcl intentará copiar el archivo a un directorio temporal y cargar ese archivo temporal. Tcl_FSUnloadFile invierte la operación, solicitando que la biblioteca indicada por loadHandle se elimine del proceso. Tenga en cuenta que, a diferencia del comando unload, esto no da a la biblioteca ninguna oportunidad de limpiar.

Ambas funciones anteriores devuelven un código de finalización de Tcl estándar. Si ocurre un error, se deja un mensaje de error en el resultado del interp.

El token proporcionado a través de la variable indicada por loadHandlePtr puede usarse con Tcl_FindSymbol.

Tcl_FSMatchInDirectory es utilizado por el código de globbing para buscar en un directorio todos los archivos que coincidan con un patrón dado. Se llamará a la función apropiada para el sistema de archivos al que pertenece pathPtr.

El valor de retorno es un resultado estándar de Tcl que indica si se produjo un error en el globbing. Los mensajes de error se colocan en interp (a menos que interp sea NULL, lo cual está permitido), pero los buenos resultados se colocan en el resultPtr proporcionado.

Tenga en cuenta que el código glob implementa patrones recursivos internamente, por lo que esta función solo recibirá patrones simples, que se pueden hacer coincidir utilizando la lógica de string match. Para manejar la recursión, Tcl llamará a esta función con frecuencia solicitando solo directorios. Un caso especial de ser llamado con un patrón NULL indica que la ruta solo debe verificarse para el tipo correcto.

Tcl_FSLink reemplaza la versión de biblioteca de readlink y la extiende para admitir la creación de enlaces. Se llamará a la función apropiada para el sistema de archivos al que pertenece linkNamePtr.

Si toPtr es NULL, se realiza una acción de "leer enlace". El resultado es un Tcl_Obj que especifica el contenido del enlace simbólico dado por linkNamePtr, o NULL si el enlace no se pudo leer. El resultado es propiedad del llamador, que debe llamar a Tcl_DecrRefCount cuando el resultado ya no sea necesario. Si toPtr no es NULL, Tcl debe crear un enlace de uno de los tipos pasados en el flag linkAction. Este flag es una combinación OR-ed de TCL_CREATE_SYMBOLIC_LINK y TCL_CREATE_HARD_LINK. Donde existe una opción (es decir, se pasa más de un flag), la convención de Tcl es preferir los enlaces simbólicos. Cuando se crea un enlace con éxito, el valor de retorno debe ser toPtr (que, por lo tanto, ya es propiedad del llamador). Si no tiene éxito, se devuelve NULL.

Tcl_FSLstat rellena la estructura Tcl_StatBuf statPtr con información sobre el archivo especificado. No necesita ningún derecho de acceso al archivo para obtener esta información, pero necesita derechos de búsqueda en todos los directorios nombrados en la ruta que conduce al archivo. La estructura Tcl_StatBuf incluye información sobre el dispositivo, inodo (siempre 0 en Windows), modo de privilegios, nlink (siempre 1 en Windows), id de usuario (siempre 0 en Windows), id de grupo (siempre 0 en Windows), rdev (igual que el dispositivo en Windows), tamaño, último a

tiempo de acceso, tiempo de última modificación y tiempo de último cambio de metadatos. Consulte la API PORTABLE STAT RESULT para obtener una descripción de cómo escribir código portable para asignar y acceder a la estructura Tcl_StatBuf.

Si path existe, Tcl_FSLstat devuelve 0 y la estructura stat se rellena con datos. De lo contrario, se devuelve -1 y no se proporciona información de stat.

Tcl_FSUtime reemplaza la versión de biblioteca de utime.

Esto devuelve 0 en caso de éxito y -1 en caso de error (según la documentación de utime). Si tiene éxito, la función actualizará los valores "atime" y "mtime" del archivo proporcionado.

Tcl_FSFileAttrsGet implementa el acceso de lectura para el subcomando file attributes que se puede enganchar. Se llamará a la función apropiada para el sistema de archivos al que pertenece pathPtr.

Si el resultado es TCL_OK, entonces se colocó un valor en objPtrRef, que solo será válido temporalmente (a menos que se llame a Tcl_IncrRefCount).

Tcl_FSFileAttrsSet implementa el acceso de escritura para el subcomando file attributes que se puede enganchar. Se llamará a la función apropiada para el sistema de archivos al que pertenece pathPtr.

Tcl_FSFileAttrStrings implementa parte del subcomando file attributes que se puede enganchar. Se llamará a la función apropiada para el sistema de archivos al que pertenece pathPtr.

El procedimiento llamado puede devolver una matriz de cadenas o puede devolver NULL y colocar una lista Tcl en objPtrRef. Tcl tomará esa lista y primero incrementará su recuento de referencias antes de usarla. Al finalizar ese uso, Tcl disminuirá su recuento de referencias. Por lo tanto, si Tcl debe desechar la lista cuando termine, debe tener un recuento de referencias de cero, y si la lista no debe desecharse, el sistema de archivos debe asegurarse de retener un recuento de referencias del valor.

Tcl_FSAccess comprueba si al proceso se le permitiría leer, escribir o probar la existencia del archivo (u otro objeto del sistema de archivos) cuyo nombre es pathname. Si pathname es un enlace simbólico en Unix, se prueban los permisos del archivo al que se refiere este enlace simbólico.

En caso de éxito (todos los permisos solicitados concedidos), se devuelve cero. En caso de error (al menos un bit en el modo solicitó un permiso que se deniega, o ocurrió algún otro error), se devuelve -1.

Tcl_FSStat rellena la estructura Tcl_StatBuf statPtr con información sobre el archivo especificado. No necesita ningún derecho de acceso al archivo para obtener esta información, pero necesita derechos de búsqueda a todos los directorios nombrados en la ruta que conduce al archivo. La estructura Tcl_StatBuf incluye información sobre el dispositivo, inodo (siempre 0 en Windows), modo de privilegio, nlink (siempre 1 en Windows), id de usuario (siempre 0 en Windows), id de grupo (siempre 0 en Windows), rdev (igual que el dispositivo en Windows), tamaño, tiempo de último acceso, tiempo de última modificación y tiempo de último cambio de metadatos. Consulte la API PORTABLE STAT RESULT para obtener una descripción de cómo escribir código portable para asignar y acceder a la estructura Tcl_StatBuf.

Si path existe, Tcl_FSStat devuelve 0 y la estructura stat se rellena con datos. De lo contrario, se devuelve -1 y no se proporciona información de stat.

Tcl_FSOpenFileChannel abre un archivo especificado por pathPtr y devuelve un manejador de canal que se puede utilizar para realizar entrada y salida en el archivo. Esta API está modelada después del procedimiento fopen de la biblioteca estándar de E/S de Unix. La sintaxis y el significado de todos los argumentos son similares a los dados en el comando Tcl open al abrir un archivo. Si ocurre un error al abrir el canal, Tcl_FSOpenFileChannel devuelve NULL y registra un código de error POSIX que se puede recuperar con Tcl_GetErrno. Además, si interp no es NULL, Tcl_FSOpenFileChannel deja un mensaje de error en el resultado de interp después de cualquier error.

El canal recién creado no está registrado en el intérprete suministrado; para registrarlo, use Tcl_RegisterChannel. Si uno de los canales estándar, stdin, stdout o stderr se cerró previamente, el acto de crear el nuevo canal también lo asigna como reemplazo del canal estándar.

Tcl_FSGetCwd reemplaza la versión de biblioteca de getcwd.

Devuelve el directorio de trabajo actual de la biblioteca Tcl. Este puede ser diferente del directorio de trabajo de la plataforma nativa, lo que ocurre cuando el directorio de trabajo actual no está en el sistema de archivos nativo.

El resultado es un puntero a un Tcl_Obj que especifica el directorio actual, o NULL si no se pudo determinar el directorio actual. Si se devuelve NULL, se deja un mensaje de error en el resultado de interp.

El resultado ya tiene su recuento de referencias incrementado para el llamador. Cuando ya no sea necesario, se debe disminuir ese recuento de referencias. Esto es necesario por motivos de seguridad de subprocesos, para permitir que varios subprocesos accedan a esta y a funciones relacionadas, garantizando al mismo tiempo que los resultados sean siempre válidos.

Tcl_FSChdir reemplaza la versión de biblioteca de chdir. La ruta se normaliza y luego se pasa al sistema de archivos que la reclama. Si ese sistema de archivos no implementa esta función, Tcl recurrirá a una combinación de stat y access para comprobar si el directorio existe y tiene los permisos adecuados.

Para obtener resultados, consulte la documentación de chdir. Si tiene éxito, mantenemos un registro de la ruta exitosa en cwdPathPtr para llamadas posteriores a Tcl_FSGetCwd.

Tcl_FSPathSeparator devuelve el carácter separador que se utilizará para el elemento más específico de la ruta especificada por pathPtr (es decir, la última parte de la ruta).

El separador se devuelve como un Tcl_Obj que contiene una cadena de longitud 1. Si la ruta no es válida, se devuelve NULL.

Tcl_FSJoinPath toma el Tcl_Obj dado, que debe ser una lista válida (a la que se le permite tener un recuento de referencias de cero), y devuelve el valor de ruta dado considerando los primeros elements elementos como segmentos de ruta válidos (cada segmento de ruta puede ser una ruta completa, una ruta parcial o simplemente un solo directorio o nombre de archivo posible). Si algún segmento de ruta es realmente una ruta absoluta, se descartan todos los segmentos de ruta anteriores. Si elements es menor que 0, usamos toda la lista.

Es posible que el valor devuelto sea en realidad un elemento de la lista dada, por lo que el llamador debe tener cuidado de incrementar el recuento de referencias del resultado antes de liberar la lista.

El valor devuelto, que normalmente tiene un recuento de referencias de cero (pero podría compartirse bajo algunas condiciones), contiene la ruta unida. El llamador debe agregar un recuento de referencias al valor antes de usarlo. En particular, el valor devuelto podría ser un elemento de la lista dada, por lo que liberar la lista podría liberar el valor prematuramente si no se ha tomado ningún recuento de referencias. Si el número de elementos es cero, el valor devuelto será un Tcl_Obj de cadena vacía.

Tcl_FSSplitPath toma el Tcl_Obj dado, que debería ser una ruta válida, y devuelve un valor de lista Tcl que contiene cada segmento de esa ruta como un elemento. Devuelve un valor de lista con un recuento de referencias de cero. Si lenPtr es distinto de NULL, la variable a la que apunta se actualizará para contener el número de elementos en la lista devuelta.

Tcl_FSEqualPaths comprueba si las dos rutas dadas representan el mismo objeto del sistema de archivos. Devuelve 1 si las rutas son iguales y 0 si son diferentes. Si alguna de las rutas es NULL, siempre se devuelve 0.

Tcl_FSGetNormalizedPath intenta extraer del Tcl_Obj dado una representación de ruta normalizada única, cuyo valor de cadena se puede utilizar como identificador único del archivo.

Devuelve el valor de ruta normalizada, propiedad de Tcl, o NULL si la ruta no era válida o no se pudo convertir correctamente. La extracción de rutas absolutas y normalizadas es muy eficiente (porque el sistema de archivos opera internamente sobre estas representaciones), aunque el resultado cuando el sistema de archivos contiene numerosos enlaces simbólicos puede no ser la versión más amigable para el usuario de una ruta. El valor de retorno es propiedad de Tcl y tiene una vida útil equivalente a la de pathPtr pasado (a menos que sea una ruta relativa, en cuyo caso el valor de ruta normalizada puede liberarse en cualquier momento en que cambie la cwd): el llamador puede, por supuesto, incrementar el recuento de referencias si desea mantener una copia por más tiempo.

Tcl_FSJoinToPath toma el valor dado, que normalmente debería ser una ruta válida o NULL, y une a él la matriz de segmentos de ruta proporcionados.

Devuelve un valor, que normalmente tiene un recuento de referencias de cero (pero podría compartirse bajo algunas condiciones), que contiene la ruta unida. El llamador debe agregar un recuento de referencias al valor antes de usarlo. Si alguno de los valores pasados a esta función (pathPtr o elementos de path) tiene un recuento de referencias de cero, se liberarán cuando esta función devuelva.

Tcl_FSConvertToPathType intenta convertir el Tcl_Obj dado a un tipo de ruta Tcl válido, teniendo en cuenta el hecho de que la cwd puede haber cambiado incluso si este valor supuestamente ya es del tipo correcto. El nombre de archivo puede comenzar con "~" (para indicar el directorio principal del usuario actual) o "~" (para indicar el directorio principal de cualquier usuario).

Si la conversión tiene éxito (es decir, el valor es una ruta válida en uno de los sistemas de archivos actuales), se devuelve TCL_OK. De lo contrario, se devuelve TCL_ERROR y se puede dejar un mensaje de error en el intérprete.

Tcl_FSGetInternalRep extrae la representación interna de un valor de ruta dado, en el sistema de archivos dado. Si el valor de ruta pertenece a un sistema de archivos diferente, devolvemos NULL. Si la representación interna es actualmente NULL, intentamos generarla, llamando a Tcl_FSCreateInternalRepProc del sistema de archivos.

Devuelve NULL o una representación de ruta interna válida. Esta representación interna se almacena en caché, de modo que las llamadas repetidas a esta función no requerirán conversiones adicionales.

Tcl_FSGetTranslatedPath intenta extraer la ruta traducida del Tcl_Obj dado.

Si la traducción tiene éxito (es decir, el valor es una ruta válida), se devuelve. De lo contrario, se devolverá NULL y se puede dejar un mensaje de error en el intérprete. Una ruta "traducida" es aquella que no contiene secuencias "~" o "~usuario" (estas se han expandido a su representación actual en el sistema de archivos). El valor devuelto pertenece al llamador, que debe almacenarlo o llamar a Tcl_DecrRefCount para garantizar que se libere la memoria. Esta función tiene poca utilidad práctica, y Tcl_FSGetNormalizedPath o Tcl_FSGetNativePath suelen ser funciones mejores para la mayoría de los propósitos.

Tcl_FSGetTranslatedStringPath hace lo mismo que Tcl_FSGetTranslatedPath, pero devuelve una cadena de caracteres o NULL. La cadena devuelta se asigna dinámicamente.

INFRAESTRUCTURA DEL SISTEMA DE ARCHIVOS

Estos campos contienen información básica sobre la estructura del sistema de archivos y las direcciones de las funciones que se utilizan para asociar un sistema de archivos particular con una ruta de archivo, y para manejar internamente las representaciones de rutas, por ejemplo, para copiar y liberar dichas representaciones.

NOMBRE DEL TIPO

El campo typeName contiene una cadena terminada en nulo que identifica el tipo de sistema de archivos implementado, por ejemplo, "nativo", "zip" o "vfs".

LONGITUD DE LA ESTRUCTURA

El campo structureLength se implementa generalmente como *sizeof(Tcl_Filesystem)*, y está ahí para permitir una compatibilidad binaria retroactiva más fácil si el tamaño de la estructura cambia en una futura versión de Tcl.

VERSIÓN

El campo version debe establecerse en TCL_FILESYSTEM_VERSION_1.

PROC_RUTA_EN_SISTEMA_DE_ARCHIVOS

El campo pathInFilesystemProc contiene la dirección de una función que se llama para determinar si un valor de ruta dado pertenece a este sistema de archivos o no. Tcl solo llamará al resto de las funciones del sistema de archivos con una ruta para la cual esta función ha devuelto TCL_OK. Si la ruta no pertenece, se debe devolver -1 (el comportamiento de Tcl para cualquier otro valor de retorno no está definido). Si se devuelve TCL_OK, entonces el parámetro de salida opcional *clientDataPtr* se puede usar para devolver una representación interna (específica del sistema de archivos) de la ruta, que se almacenará en caché dentro del valor de la ruta, y puede ser recuperada eficientemente por las otras funciones del sistema de archivos. Tcl almacenará simultáneamente en caché el hecho de que esta ruta pertenece a este sistema de archivos. Dichas cachés se invalidan cuando se agregan o eliminan estructuras de sistemas de archivos de la lista interna de sistemas de archivos conocidos de Tcl.

typedef int Tcl_FSPathInFilesystemProc(
        Tcl_Obj *pathPtr,
        ClientData *clientDataPtr);

PROC_DUPLICAR_REPRESENTACION_INTERNA

Esta función crea una copia de la representación interna de una ruta y se llama cuando Tcl necesita duplicar un valor de ruta. Si es nulo, Tcl simplemente no copiará la representación interna, que luego puede ser necesario regenerar más tarde.

typedef ClientData Tcl_FSDupInternalRepProc(
        ClientData clientData);

PROC_LIBERAR_REPRESENTACION_INTERNA

Libera la representación interna. Esto debe implementarse si las representaciones internas necesitan ser liberadas (es decir, si se asigna memoria cuando se genera una representación interna), pero de lo contrario puede ser nulo.

typedef void Tcl_FSFreeInternalRepProc(
        ClientData clientData);

PROC_INTERNO_A_NORMALIZADO

Función para convertir la representación interna a una ruta normalizada. Solo se requiere si el sistema de archivos crea valores de ruta puros sin representación de cadena/ruta. El valor de retorno es un valor de Tcl cuya representación de cadena es la ruta normalizada.

typedef Tcl_Obj *Tcl_FSInternalToNormalizedProc(
        ClientData clientData);

PROC_CREAR_REPRESENTACION_INTERNA

Función para tomar un valor de ruta, calcular una representación interna para él y almacenar esa representación nativa en el valor. Puede ser nulo si las rutas no tienen representación interna, o si el *Tcl_FSPathInFilesystemProc* para este sistema de archivos siempre crea inmediatamente una representación interna para las rutas que acepta.

typedef ClientData Tcl_FSCreateInternalRepProc(
        Tcl_Obj *pathPtr);

PROC_NORMALIZAR_RUTA

Función para normalizar una ruta. Debe implementarse para todos los sistemas de archivos que pueden tener múltiples representaciones de cadena para el mismo valor de ruta. En Tcl, cada "ruta" debe tener una única representación de cadena "normalizada". Dependiendo del sistema de archivos, puede haber más de una representación de cadena no normalizada que se refiera a esa ruta (por ejemplo, una ruta relativa, una ruta con una capitalización diferente si el sistema de archivos no distingue entre mayúsculas y minúsculas, una ruta que contiene una referencia a un directorio de inicio como "~", una ruta que contiene enlaces simbólicos, etc.). Si el último componente de la ruta es un enlace simbólico, no debe convertirse en el valor al que apunta (pero su capitalización u otros aspectos deben hacerse únicos). Todos los demás componentes de la ruta deben convertirse desde enlaces simbólicos. Esta única excepción es necesaria para concordar con la semántica de Tcl con las operaciones de file delete, file rename, file copy que operan sobre enlaces simbólicos. Esta función puede ser llamada con *nextCheckpoint* ya sea al principio de la ruta (es decir, cero), al final de la ruta, o en cualquier separador de archivo intermedio en la ruta. Nunca apuntará a ninguna otra posición arbitraria en la ruta. En el último de los tres casos válidos, la implementación puede suponer que la ruta hasta el separador de archivo, inclusive, se conoce y está normalizada.

typedef int Tcl_FSNormalizePathProc(
        Tcl_Interp *interp,
        Tcl_Obj *pathPtr,
        int nextCheckpoint);

OPERACIONES DEL SISTEMA DE ARCHIVOS

Los campos de esta sección de la estructura contienen las direcciones de las funciones que se llaman para llevar a cabo las operaciones básicas del sistema de archivos. Un sistema de archivos que se espera que se utilice con el conjunto completo de comandos estándar de Tcl debe implementar todas estas. Si no se implementan algunas de ellas, ciertos comandos de Tcl pueden fallar al operar en rutas dentro de ese sistema de archivos. Sin embargo, en algunos casos esto puede ser deseable (por ejemplo, un sistema de archivos de solo lectura no debe implementar las últimas cuatro funciones, y un sistema de archivos que no admite enlaces simbólicos no necesita implementar la función *readlink*, etc. El núcleo de Tcl espera que los sistemas de archivos se comporten de esta manera).

PROC_TIPO_RUTA_SISTEMA_DE_ARCHIVOS

El "tipo" se utiliza solo con fines informativos y debe devolverse como la representación de cadena del Tcl_Obj devuelto. Un valor de retorno típico podría ser "networked", "zip" o "ftp". El resultado Tcl_Obj es propiedad del sistema de archivos, por lo que Tcl incrementará el recuento de referencias de ese valor si desea conservar una referencia a él.

typedef Tcl_Obj *Tcl_FSFilesystemPathTypeProc(

Función para devolver el (los) carácter(es) separador(es) para este sistema de archivos. Esto solo necesita implementarse si el sistema de archivos desea utilizar un separador diferente al de la cadena estándar "/". Entre otros usos, se devuelve mediante el comando *file separator*. El valor de retorno debe ser un valor con un recuento de referencias de cero.

typedef Tcl_Obj *Tcl_FSFilesystemSeparatorProc(
        Tcl_Obj *pathPtr);

PROC_STAT

Función para procesar una llamada a *Tcl_FSStat*. Debe implementarse para cualquier sistema de archivos razonable, ya que muchos comandos a nivel de Tcl dependen crucialmente de ella (por ejemplo, *file atime*, *file isdirectory*, *file size*, *glob*).

typedef int Tcl_FSStatProc(
        Tcl_Obj *pathPtr,
        Tcl_StatBuf *statPtr);

El *Tcl_FSStatProc* rellena la estructura stat *statPtr* con información sobre el archivo especificado. No necesita ningún derecho de acceso al archivo para obtener esta información, pero necesita derechos de búsqueda en todos los directorios nombrados en la ruta que conduce al archivo. La estructura stat incluye información sobre el dispositivo, el inodo (siempre 0 en Windows), el modo de privilegios, nlink (siempre 1 en Windows), el ID de usuario (siempre 0 en Windows), el ID de grupo (siempre 0 en Windows), rdev (igual que el dispositivo en Windows), tamaño, tiempo del último acceso, tiempo de la última modificación y tiempo del último cambio de metadatos.

Si el archivo representado por *pathPtr* existe, el *Tcl_FSStatProc* devuelve 0 y la estructura stat se rellena con datos. De lo contrario, se devuelve -1 y no se proporciona información de stat.

PROC_ACCESO

Función para procesar una llamada a *Tcl_FSAccess*. Debe implementarse para cualquier sistema de archivos razonable, ya que muchos comandos a nivel de Tcl dependen crucialmente de ella (por ejemplo, *file exists*, *file readable*).

typedef int Tcl_FSAccessProc(
        Tcl_Obj *pathPtr,
        int mode);

El *Tcl_FSAccessProc* comprueba si se permitiría al proceso leer, escribir o probar la existencia del archivo (u otro objeto del sistema de archivos) cuyo nombre está en *pathPtr*. Si el nombre del camino se refiere a un enlace simbólico, se deben probar los permisos del archivo al que se refiere ese enlace simbólico.

En caso de éxito (se conceden todos los permisos solicitados), se devuelve cero. En caso de error (al menos un bit en el modo solicitó un permiso denegado, o ocurrió algún otro error), se devuelve -1.

PROC_ABRIR_CANAL_ARCHIVO

Función para procesar una llamada a *Tcl_FSOpenFileChannel*. Debe implementarse para cualquier sistema de archivos que admita la apertura de archivos para lectura, escritura o ambos. Los comandos como *open*, *read*, *write*, *puts*, *gets*, etc., dependen de esta función. Tcl proporciona una implementación de referencia para sistemas de archivos nativos, pero las implementaciones personalizadas serán necesarias para otros tipos de sistemas de archivos.

typedef Tcl_Channel Tcl_FSOpenFileChannelProc(
        Tcl_Interp *interp,
        Tcl_Obj *pathPtr,
        int mode,
        int permissions);

La función *Tcl_FSOpenFileChannelProc* abre el archivo especificado por *pathPtr* en el modo especificado por *mode*. El argumento *mode* es una combinación de las siguientes marcas: *TCL_READABLE*, *TCL_WRITABLE*, *TCL_APPEND* y *TCL_MODE_BINARY*. El argumento *permissions* se utiliza para establecer los permisos del archivo si se está creando. En caso de éxito, devuelve un identificador de canal Tcl. En caso de error, devuelve NULL y establece una condición de error en el intérprete.

PROC_COPIAR_ARCHIVO

typedef int Tcl_FSCopyFileProc(

PROC_LSTAT

Función para procesar una llamada a *Tcl_FSlstat*. Es similar a *Tcl_FSStatProc*, pero si el nombre del camino se refiere a un enlace simbólico, entonces *Tcl_FSlstatProc* devuelve información sobre el propio enlace simbólico en lugar de la información sobre el archivo al que apunta el enlace.

typedef int Tcl_FSlstatProc(
        Tcl_Obj *pathPtr,
        Tcl_StatBuf *statPtr);

Si el archivo representado por *pathPtr* existe, el *Tcl_FSlstatProc* devuelve 0 y la estructura stat se rellena con datos. De lo contrario, se devuelve -1 y no se proporciona información de stat.

PROC_CARGAR_ARCHIVO

Función para procesar una llamada a *Tcl_FSLoadFile*. Carga un archivo como una biblioteca dinámica y devuelve un identificador de módulo. Tcl proporciona una implementación de referencia para sistemas de archivos nativos, pero los sistemas de archivos personalizados pueden necesitar proporcionar la suya propia.

typedef Tcl_LoadHandle Tcl_FSLoadFileProc(
        Tcl_Interp *interp,
        Tcl_Obj *pathPtr,
        Tcl_Platform specifically);

En caso de éxito, se devuelve un identificador de módulo. En caso de error, se devuelve NULL y se establece una condición de error en el intérprete.

OPENFILECHANNELPROC

Función para procesar una llamada a Tcl_FSOpenFileChannel. Debe ser implementada para cualquier sistema de archivos razonable, ya que cualquier operación que requiera abrir o acceder al contenido de un archivo la utilizará (por ejemplo, open, encoding y muchos comandos de Tk).

typedef Tcl_Channel Tcl_FSOpenFileChannelProc(
        Tcl_Interp *interp,
        Tcl_Obj *pathPtr,
        int mode,
        int permissions);

El Tcl_FSOpenFileChannelProc abre un archivo especificado por pathPtr y devuelve un identificador de canal que se puede utilizar para realizar operaciones de entrada y salida en el archivo. Esta API está modelada según el procedimiento fopen de la biblioteca estándar de E/S de Unix. La sintaxis y el significado de todos los argumentos son similares a los proporcionados en el comando open de Tcl al abrir un archivo, donde el argumento mode es una combinación de las banderas POSIX O_RDONLY, O_WRONLY, etc. Si ocurre un error al abrir el canal, el Tcl_FSOpenFileChannelProc devuelve NULL y registra un código de error POSIX que se puede recuperar con Tcl_GetErrno. Además, si interp no es NULL, el Tcl_FSOpenFileChannelProc deja un mensaje de error en el resultado de interp después de cualquier error.

El canal recién creado no debe ser registrado en el intérprete proporcionado por un Tcl_FSOpenFileChannelProc; esa tarea corresponde al llamador de Tcl_FSOpenFileChannel (si es necesario). Si uno de los canales estándar, stdin, stdout o stderr se cerró previamente, el acto de crear el nuevo canal también lo asigna como un reemplazo para el canal estándar.

MATCHINDIRECTORYPROC

Función para procesar una llamada a Tcl_FSMatchInDirectory. Si no se implementa, entonces la funcionalidad de glob y copia recursiva faltará en el sistema de archivos (y esto puede afectar a comandos como encoding names que utilizan funcionalidad de glob internamente).

typedef int Tcl_FSMatchInDirectoryProc(
        Tcl_Interp *interp,
        Tcl_Obj *resultPtr,
        Tcl_Obj *pathPtr,
        const char *pattern,
        Tcl_GlobTypeData *types);

La función debe devolver todos los archivos o directorios (u otros objetos del sistema de archivos) que coincidan con el patrón dado y concuerden con la especificación de types. Hay dos formas en las que esta función puede ser llamada. Si pattern es NULL, entonces pathPtr es una especificación de ruta completa de un solo archivo o directorio que debe ser verificado por existencia y tipo correcto. De lo contrario, pathPtr es un directorio, cuyo contenido la función debe buscar archivos o directorios que tengan el tipo correcto. En cualquier caso, se puede asumir que pathPtr no es NULL ni vacío. Actualmente no se documenta si pathPtr tendrá o no un separador de archivo al final, por lo que el código debe ser flexible a ambas posibilidades.

El valor de retorno es un resultado estándar de Tcl que indica si ocurrió un error en el proceso de coincidencia. Los mensajes de error se colocan en interp, a menos que interp sea NULL, en cuyo caso no es necesario generar ningún mensaje de error; en un resultado TCL_OK, los resultados deben agregarse al valor de resultPtr proporcionado (que se puede asumir que es una lista válida no compartida de Tcl). Las coincidencias agregadas a resultPtr deben incluir cualquier prefijo de ruta dado en pathPtr (esto generalmente significa que serán especificaciones de ruta absolutas). Tenga en cuenta que si no se encuentran coincidencias, eso simplemente conduce a un resultado vacío; los errores solo se señalan para problemas reales de archivo o sistema de archivos que puedan ocurrir durante el proceso de coincidencia.

La estructura Tcl_GlobTypeData pasada en el parámetro types contiene los siguientes campos:

typedef struct Tcl_GlobTypeData {
    /* Corresponde a bcdpfls como en 'find -t' */
    int type;
    /* Corresponde a permisos de archivo */
    int perm;
    /* Tipo MAC aceptable */
    Tcl_Obj *macType;
    /* Creador MAC aceptable */
    Tcl_Obj *macCreator;
} Tcl_GlobTypeData;

Hay dos casos específicos que es importante manejar correctamente, ambos cuando types no es NULL. Los dos casos son cuando types->types & TCL_GLOB_TYPE_DIR o types->types & TCL_GLOB_TYPE_MOUNT son verdaderos (y en particular cuando las otras banderas son falsas). En el primero de estos casos, la función debe enumerar los directorios contenidos. Tcl utiliza esto para implementar globbing recursivo, por lo que es fundamental que los sistemas de archivos implementen la coincidencia de directorios correctamente. En el segundo de estos casos, con TCL_GLOB_TYPE_MOUNT, el sistema de archivos debe enumerar los puntos de montaje que se encuentran dentro de pathPtr dado (y en este caso, pathPtr no necesita estar dentro del mismo sistema de archivos; diferente a todos los demás casos en los que se llama a esta función). El soporte para esto es fundamental si Tcl va a tener transiciones perfectas entre un sistema de archivos y otro.

UTIMEPROC

Función para procesar una llamada a Tcl_FSUtime. Requerida para permitir el establecimiento (no la lectura) de tiempos con file mtime, file atime y la implementación de apertura-lectura/apertura-escritura/fcopy de file copy.

typedef int Tcl_FSUtimeProc(
        Tcl_Obj *pathPtr,
        struct utimbuf *tval);

Los tiempos de acceso y modificación del archivo especificado por pathPtr deben cambiarse a los valores dados en la estructura tval.

El valor de retorno debe ser 0 en caso de éxito y -1 en caso de error, al igual que con la llamada del sistema utime.

LINKPROC

Función para procesar una llamada a Tcl_FSLink. Solo debe ser implementada si el sistema de archivos soporta enlaces, y de lo contrario puede ser NULL.

typedef Tcl_Obj *Tcl_FSLinkProc(
        Tcl_Obj *linkNamePtr,
        Tcl_Obj *toPtr,
        int linkAction);

Si toPtr es NULL, se le está pidiendo a la función que lea el contenido de un enlace. El resultado es un Tcl_Obj que especifica el contenido del enlace dado por linkNamePtr, o NULL si el enlace no se pudo leer. El resultado es propiedad del llamador (y por lo tanto, se debe incrementar su contador de referencias antes de devolverlo). Cualquier llamador debe llamar a Tcl_DecrRefCount en este resultado cuando ya no se necesite. Si toPtr no es NULL, la función debe intentar crear un enlace. El resultado en este caso debe ser toPtr si el enlace fue exitoso y NULL en caso contrario. En este caso, el resultado no es propiedad del llamador (es decir, no se necesitan manipulaciones de contador de referencias en ningún extremo). Consulte la documentación de Tcl_FSLink para la interpretación correcta de las banderas linkAction.

LISTVOLUMESPROC

Función para listar cualquier volumen de sistema de archivos agregado por este sistema de archivos. Solo debe implementarse si el sistema de archivos agrega volúmenes al principio del sistema de archivos, para que puedan ser devueltos por file volumes.

typedef Tcl_Obj *Tcl_FSListVolumesProc(void);

El resultado debe ser una lista de volúmenes agregados por este sistema de archivos, o NULL (o una lista vacía) si no se proporcionan volúmenes. El valor del resultado se considera propiedad del sistema de archivos (no del núcleo de Tcl), pero se le debe dar un contador de referencias para Tcl. Tcl utilizará el contenido de la lista y luego disminuirá ese contador de referencias. Esto permite a los sistemas de archivos elegir si realmente desean conservar una "lista global" de volúmenes o no (si no, generan la lista sobre la marcha y la pasan a Tcl con un contador de referencias de 1 y luego se olvidan de la lista; si sí, entonces simplemente incrementan el contador de referencias de su lista global y la pasan a Tcl, que copiará el contenido y luego disminuirá el contador de vuelta a donde estaba).

Por lo tanto, Tcl considera que los valores de retorno de este proc son de solo lectura.

FILEATTRSTRINGSPROC

Función para listar todas las cadenas de atributos que son válidas para este sistema de archivos. Si no se implementa, el sistema de archivos no admitirá el comando file attributes. Esto permite adjuntar información adicional arbitraria a los archivos en el sistema de archivos. Si no se implementa, no es necesario implementar los métodos get y set.

typedef const char *const *Tcl_FSFileAttrStringsProc(
        Tcl_Obj *pathPtr,
        Tcl_Obj **objPtrRef);

La función llamada puede devolver una matriz de cadenas o puede devolver NULL y colocar una lista de Tcl en el objPtrRef proporcionado. Tcl tomará esa lista y primero incrementará su contador de referencias antes de usarla. Al completar ese uso, Tcl disminuirá su contador de referencias. Por lo tanto, si la lista debe ser descartada por Tcl cuando termine, debería tener un contador de referencias de cero, y si la lista no debe ser descartada, el sistema de archivos debe asegurarse de devolver un valor con un contador de referencias de al menos uno.

FILEATTRSGETPROC

Función para procesar una llamada a Tcl_FSFileAttrsGet, utilizada por file attributes.

typedef int Tcl_FSFileAttrsGetProc(
        Tcl_Interp *interp,
        int index,
        Tcl_Obj *pathPtr,
        Tcl_Obj **objPtrRef);

Devuelve un código de retorno estándar de Tcl. El valor del atributo recuperado, que corresponde al elemento de índice index en la lista devuelta por Tcl_FSFileAttrStringsProc, es un Tcl_Obj colocado en objPtrRef (si se devolvió TCL_OK) y es probable que tenga un contador de referencias de cero. En cualquier caso, debemos almacenarlo en algún lugar (por ejemplo, el resultado de Tcl), o incrementar/decrementar su contador de referencias para asegurar que se libere correctamente.

FILEATTRSSETPROC

Función para procesar una llamada a Tcl_FSFileAttrsSet, utilizada por file attributes. Si el sistema de archivos es de solo lectura, no es necesario implementar esto.

typedef int Tcl_FSFileAttrsSetProc(
        Tcl_Interp *interp,
        int index,
        Tcl_Obj *pathPtr,
        Tcl_Obj *objPtr);

El valor del atributo del elemento de índice index en la lista devuelta por Tcl_FSFileAttrStringsProc debe establecerse en el objPtr proporcionado.

CREATEDIRECTORYPROC

DESCRIPTION

This module defines the interface between Tcl's generic file subsystem and the specific implementations of filesystems Tcl may access. It is assumed that the reader is familiar with the Tcl file system subsystem API.

FILESYSTEM OPERATIONS

These functions must be implemented for any filesystem that Tcl will access, unless the filesystem is intended to be read-only.

CREATEDIRECTORYPROC

Function to process a Tcl_FSCreateDirectory call. Should be implemented unless the FS is read-only.

typedef int Tcl_FSCreateDirectoryProc(
        Tcl_Obj *pathPtr);

The return value is a standard Tcl result indicating whether an error occurred in the process. If successful, a new directory should have been added to the filesystem in the location specified by pathPtr.

REMOVEDIRECTORYPROC

Function to process a Tcl_FSRemoveDirectory call. Should be implemented unless the FS is read-only.

typedef int Tcl_FSRemoveDirectoryProc(
        Tcl_Obj *pathPtr,
        int recursive,
        Tcl_Obj **errorPtr);

The return value is a standard Tcl result indicating whether an error occurred in the process. If successful, the directory specified by pathPtr should have been removed from the filesystem. If the recursive flag is given, then a non-empty directory should be deleted without error. If this flag is not given, then and the directory is non-empty a POSIX “EEXIST” error should be signaled. If an error does occur, the name of the file or directory which caused the error should be placed in errorPtr.

DELETEFILEPROC

Function to process a Tcl_FSDeleteFile call. Should be implemented unless the FS is read-only.

typedef int Tcl_FSDeleteFileProc(
        Tcl_Obj *pathPtr);

The return value is a standard Tcl result indicating whether an error occurred in the process. If successful, the file specified by pathPtr should have been removed from the filesystem. Note that, if the filesystem supports symbolic links, Tcl will always call this function and not Tcl_FSRemoveDirectoryProc when needed to delete them (even if they are symbolic links to directories).

FILESYSTEM EFFICIENCY

These functions need not be implemented for a particular filesystem because the core has a fallback implementation available. See each individual description for the consequences of leaving the field NULL.

LSTATPROC

Function to process a Tcl_FSLstat call. If not implemented, Tcl will attempt to use the statProc defined above instead. Therefore it need only be implemented if a filesystem can differentiate between stat and lstat calls.

typedef int Tcl_FSLstatProc(
        Tcl_Obj *pathPtr,
        Tcl_StatBuf *statPtr);

The behavior of this function is very similar to that of the Tcl_FSStatProc defined above, except that if it is applied to a symbolic link, it returns information about the link, not about the target file.

COPYFILEPROC

Function to process a Tcl_FSCopyFile call. If not implemented Tcl will fall back on open-r, open-w and fcopy as a copying mechanism. Therefore it need only be implemented if the filesystem can perform that action more efficiently.

typedef int Tcl_FSCopyFileProc(
        Tcl_Obj *srcPathPtr,
        Tcl_Obj *destPathPtr);

The return value is a standard Tcl result indicating whether an error occurred in the copying process. Note that, destPathPtr is the name of the file which should become the copy of srcPathPtr. It is never the name of a directory into which srcPathPtr could be copied (i.e. the function is much simpler than the Tcl level file copy subcommand). Note that, if the filesystem supports symbolic links, Tcl will always call this function and not copyDirectoryProc when needed to copy them (even if they are symbolic links to directories). Finally, if the filesystem determines it cannot support the file copy action, calling Tcl_SetErrno(EXDEV) and returning a non-TCL_OK result will tell Tcl to use its standard fallback mechanisms.

RENAMEFILEPROC

Function to process a Tcl_FSRenameFile call. If not implemented, Tcl will fall back on a copy and delete mechanism. Therefore it need only be implemented if the filesystem can perform that action more efficiently.

typedef int Tcl_FSRenameFileProc(
        Tcl_Obj *srcPathPtr,
        Tcl_Obj *destPathPtr);

The return value is a standard Tcl result indicating whether an error occurred in the renaming process. If the filesystem determines it cannot support the file rename action, calling Tcl_SetErrno(EXDEV) and returning a non-TCL_OK result will tell Tcl to use its standard fallback mechanisms.

COPYDIRECTORYPROC

Function to process a Tcl_FSCopyDirectory call. If not implemented, Tcl will fall back on a recursive file mkdir, file copy mechanism. Therefore it need only be implemented if the filesystem can perform that action more efficiently.

typedef int Tcl_FSCopyDirectoryProc(
        Tcl_Obj *srcPathPtr,
        Tcl_Obj *destPathPtr,
        Tcl_Obj **errorPtr);

The return value is a standard Tcl result indicating whether an error occurred in the copying process. If an error does occur, the name of the file or directory which caused the error should be placed in errorPtr. Note that, destPathPtr is the name of the directory-name which should become the mirror-image of srcPathPtr. It is not the name of a directory into which srcPathPtr should be copied (i.e. the function is much simpler than the Tcl level file copy subcommand). Finally, if the filesystem determines it cannot support the directory copy action, calling Tcl_SetErrno(EXDEV) and returning a non-TCL_OK result will tell Tcl to use its standard fallback mechanisms.

LOADFILEPROC

Function to process a Tcl_FSLoadFile call. If not implemented, Tcl will fall back on a copy to native-temp followed by a Tcl_FSLoadFile on that temporary copy. Therefore it need only be implemented if the filesystem can load code directly, or it can be implemented simply to return TCL_ERROR to disable load functionality in this filesystem entirely.

typedef int Tcl_FSLoadFileProc(
        Tcl_Interp *interp,
        Tcl_Obj *pathPtr,
        Tcl_LoadHandle *handlePtr,
        Tcl_FSUnloadFileProc *unloadProcPtr);

Returns a standard Tcl completion code. If an error occurs, an error message is left in the interp's result. The function dynamically loads a binary code file into memory. On a successful load, the handlePtr should be filled with a token for the dynamically loaded file, and the unloadProcPtr should be filled in with the address of a procedure. The unload procedure will be called with the given Tcl_LoadHandle as its only parameter when Tcl needs to unload the file. For example, for the native filesystem, the Tcl_LoadHandle returned is currently a token which can be used in the private TclpFindSymbol to access functions in the new code. Each filesystem is free to define the Tcl_LoadHandle as it requires. Finally, if the filesystem determines it cannot support the file load action, calling Tcl_SetErrno(EXDEV) and returning a non-TCL_OK result will tell Tcl to use its standard fallback mechanisms.

UNLOADFILEPROC

Function to unload a previously successfully loaded file. If load was implemented, then this should also be implemented, if there is any cleanup action required.

typedef void Tcl_FSUnloadFileProc(
        Tcl_LoadHandle loadHandle);

GETCWDPROC

Function to process a Tcl_FSGetCwd call. Most filesystems need not implement this. It will usually only be called once, if getcwd is called before chdir. May be NULL.

typedef Tcl_Obj *Tcl_FSGetCwdProc(
        Tcl_Interp *interp);

If the filesystem supports a native notion of a current working directory (which might perhaps change independent of Tcl), this function should return that cwd as the result, or NULL if the current directory could not be determined (e.g. the user does not have appropriate permissions on the cwd directory). If NULL is returned, an error message is left in the interp's result.

CHDIRPROC

Function to process a Tcl_FSChdir call. If filesystems do not implement this, it will be emulated by a series of directory access checks. Otherwise, virtual filesystems which do implement it need only respond with a positive return result if the pathPtr is a valid, accessible directory in their filesystem. They need not remember the result, since that will be automatically remembered for use by Tcl_FSGetCwd. Real filesystems should carry out the correct action (i.e. call the correct system chdir API).

typedef int Tcl_FSChdirProc(
        Tcl_Obj *pathPtr);

The Tcl_FSChdirProc changes the applications current working directory to the value specified in pathPtr. The function returns -1 on error or 0 on success.
