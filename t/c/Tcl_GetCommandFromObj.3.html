DESCRIPCION

Tcl_CreateObjCommand define una nueva comand en interp y la asocia con el procedimiento proc de tal manera que cuando name se invoque como comand (por ejemplo, mediante una llamada a Tcl_EvalObjEx), el intérprete llamará proc para procesar la comand.

Tcl_CreateObjCommand elimina cualquier comand existente name ya asociada al intérprete (aunque hay una excepción donde la comand no se elimina). Devuelve un token que puede usarse para referirse a la comand en llamadas posteriores a Tcl_GetCommandName. Si name contiene cualquier calificador ::, la comand se añade al namespace especificado; de lo contrario, se añade al namespace global. Si Tcl_CreateObjCommand se llama para un intérprete que está en proceso de eliminación, no crea una nueva comand y devuelve NULL. proc debe tener argumentos y resultado que correspondan al tipo Tcl_ObjCmdProc:

typedef int Tcl_ObjCmdProc(
        ClientData clientData,
        Tcl_Interp *interp,
        int objc,
        Tcl_Obj *const objv[]);

Cuando proc es invocado, clientData y interp serán copias de los argumentos dados a Tcl_CreateObjCommand. Generalmente, clientData apunta a una estructura de datos de aplicación que describe lo que se debe hacer cuando se invoca el procedimiento de comand. Objc y objv describen los argumentos de la comand, objc da el número de valores de argumento (incluyendo el nombre de la comand) y objv da los valores de los argumentos. El array objv contendrá objc valores, apuntando a los valores de los argumentos. A diferencia de argv[argv] usado en un procedimiento de comand basado en string, objv[objc] no contendrá NULL.

Además, cuando proc es invocado, no debe modificar el contenido de objv cambiando los valores de cualquier elemento del array (por ejemplo, objv[2] = NULL), ya que esto causará pérdida de memoria y corrupción de la pila de ejecución. El const en la declaración de objv hará que los compiladores ANSI reporten cualquier asignación como un error. Sin embargo, es aceptable modificar la representación interna de cualquier valor de argumento individual. Por ejemplo, el usuario puede llamar a Tcl_GetIntFromObj en objv[2] para obtener la representación entera del valor; esta llamada puede cambiar el tipo del valor que objv[2] apunta, pero no cambiará dónde objv[2] apunta.

El proc debe devolver un código entero que sea TCL_OK, TCL_ERROR, TCL_RETURN, TCL_BREAK o TCL_CONTINUE. Véase la página de guía Tcl para detalles sobre lo que significa cada código. Las comands normales devolverán generalmente TCL_OK o TCL_ERROR. Además, si proc necesita devolver un resultado no vacío, puede llamar a Tcl_SetObjResult para establecer el resultado del intérprete. En el caso de retorno de TCL_OK, esto da el resultado de la comand, y en el caso de TCL_ERROR, da un mensaje de error. Antes de invocar el procedimiento de comand, Tcl_EvalObjEx establece el resultado del intérprete para apuntar a un valor que representa una cadena vacía, por lo que las comands simples pueden devolver un resultado vacío simplemente sin hacer nada.

Los elementos del array objv pertenecen a Tcl y no se garantiza que persistan una vez que proc se ejecute: proc no debe modificarlos. Si quieres devolver algo desde el array objv, debes llamar a Tcl_SetObjResult.

Ordinariamente, Tcl_CreateObjCommand elimina cualquier comand existente name ya asociada al intérprete. Sin embargo, si la comand existente fue creada previamente mediante una llamada a Tcl_CreateCommand, Tcl_CreateObjCommand no la elimina, sino que arranca para que el intérprete llame al Tcl_ObjCmdProc proc en el futuro. El procedimiento de comand anterior basado en string Tcl_CmdProc asociado a la comand se mantiene y su dirección puede obtenerse mediante llamadas posteriores a Tcl_GetCommandInfo. Esto se hace por compatibilidad retroactiva.

El DeleteProc se llama cuando (si) name es eliminado. Esto puede ocurrir mediante llamadas a Tcl_DeleteCommand, Tcl_DeleteCommandFromToken, o Tcl_DeleteInterp, o al reemplazar name en otra llamada a Tcl_CreateObjCommand. DeleteProc se llama antes de la eliminación de la comand, dando a la aplicación una oportunidad para liberar cualquier estructura asociada a la comand. DeleteProc debe tener argumentos y resultado que coincidan con el tipo Tcl_CmdDeleteProc:

typedef void Tcl_CmdDeleteProc(
        ClientData clientData);

El argumento clientData será el mismo que el argumento clientData pasado a Tcl_CreateObjCommand.

La comand Tcl_DeleteCommand elimina una comand de un intérprete de comand. Una vez que la llamada termina, intentar invocar cmdName en interp dará errores. Si cmdName no está asociado como comand en interp, Tcl_DeleteCommand no hace nada y devuelve -1; de lo contrario, devuelve 0. No hay restricciones sobre cmdName: puede referirse a una comand incorporada, una comand de aplicación, o un procedimiento Tcl. Si name contiene cualquier calificador ::, la comand se elimina del namespace especificado.

Dado un token devuelto por Tcl_CreateObjCommand, Tcl_DeleteCommandFromToken elimina la comand de un intérprete de comand. Esto incluso si la comand ha sido renombrada. Una vez que la llamada termina, intentar invocar la comand en interp dará errores. Si la comand correspondiente a token ya ha sido eliminada de interp, Tcl_DeleteCommand no hace nada y devuelve -1; de lo contrario, devuelve 0.

Tcl_GetCommandInfo comprueba si su argumento cmdName existe como comand en interp. cmdName puede incluir calificadores :: para identificar una comand en un namespace particular. Si la comand no se encuentra, devuelve 0. De lo contrario, coloca información sobre la comand en la estructura Tcl_CmdInfo apuntada por infoPtr y devuelve 1. DESCRIPTION

The structure Tcl_CmdInfo is defined as follows:

typedef struct Tcl_CmdInfo {
    int isNativeObjectProc;
    Tcl_ObjCmdProc *objProc;
    ClientData objClientData;
    Tcl_CmdProc *proc;
    ClientData clientData;
    Tcl_CmdDeleteProc *deleteProc;
    ClientData deleteData;
    Tcl_Namespace *namespacePtr;
} Tcl_CmdInfo;

The isNativeObjectProc field has the value 1 if Tcl_CreateObjCommand was called to register the command; it is 0 if only Tcl_CreateCommand was called. It allows a program to determine whether it is faster to call objProc or proc: objProc is normally faster if isNativeObjectProc has the value 1. The fields objProc and objClientData have the same meaning as the proc and clientData arguments to Tcl_CreateObjCommand; they hold information about the value-based command procedure that the Tcl interpreter calls to implement the command. The fields proc and clientData hold information about the string-based command procedure that implements the command. If Tcl_CreateCommand was called for this command, this is the procedure passed to it; otherwise, this is a compatibility procedure registered by Tcl_CreateObjCommand that simply calls the command's value-based procedure after converting its string arguments to Tcl values. The field deleteData is the ClientData value to pass to deleteProc; it is normally the same as clientData but may be set independently using the Tcl_SetCommandInfo procedure. The field namespacePtr holds a pointer to the Tcl_Namespace that contains the command.

Tcl_GetCommandInfoFromToken is identical to Tcl_GetCommandInfo except that it uses a command token returned from Tcl_CreateObjCommand in place of the command name. If the token parameter is NULL, it returns 0; otherwise, it returns 1 and fills in the structure designated by infoPtr.

Tcl_SetCommandInfo is used to modify the procedures and ClientData values associated with a command. Its cmdName argument is the name of a command in interp. cmdName may include :: namespace qualifiers to identify a command in a particular namespace. If this command does not exist then Tcl_SetCommandInfo returns 0. Otherwise, it copies the information from *infoPtr to Tcl's internal structure for the command and returns 1.

Tcl_SetCommandInfoFromToken is identical to Tcl_SetCommandInfo except that it takes a command token as returned by Tcl_CreateObjCommand instead of the command name. If the token parameter is NULL, it returns 0. Otherwise, it copies the information from *infoPtr to Tcl's internal structure for the command and returns 1.

Note that Tcl_SetCommandInfo and Tcl_SetCommandInfoFromToken both allow the ClientData for a command's deletion procedure to be given a different value than the ClientData for its command procedure.

Note that neither Tcl_SetCommandInfo nor Tcl_SetCommandInfoFromToken will change a command's namespace. Use Tcl_Eval to call the rename command to do that.

Tcl_GetCommandName provides a mechanism for tracking commands that have been renamed. Given a token returned by Tcl_CreateObjCommand when the command was created, Tcl_GetCommandName returns the string name of the command. If the command has been renamed since it was created, then Tcl_GetCommandName returns the current name. This name does not include any :: namespace qualifiers. The command corresponding to token must not have been deleted. The string returned by Tcl_GetCommandName is in dynamic memory owned by Tcl and is only guaranteed to retain its value as long as the command is not deleted or renamed; callers should copy the string if they need to keep it for a long time.

Tcl_GetCommandFullName produces the fully qualified name of a command from a command token. The name, including all namespace prefixes, is appended to the value specified by objPtr.

Tcl_GetCommandFromObj returns a token for the command specified by the name in a Tcl_Obj. The command name is resolved relative to the current namespace. Returns NULL if the command is not found.
