Tcl_AsyncCreate(3) Procedimientos de la biblioteca Tcl Tcl_AsyncCreate(3)

NOMBRE

Tcl_AsyncCreate, Tcl_AsyncMark, Tcl_AsyncInvoke, Tcl_AsyncDelete, Tcl_AsyncReady - manejo de eventos asíncronos

SINTAXIS

#include <tcl.h>

Tcl_AsyncHandler
Tcl_AsyncCreate(proc, clientData)

void
Tcl_AsyncMark(async)

int
Tcl_AsyncInvoke(interp, code)

void
Tcl_AsyncDelete(async)

int
Tcl_AsyncReady()

ARGUMENTOS

Tcl_AsyncProc *proc (entrada)
Procedimiento a invocar para manejar un evento asíncrono.
ClientData clientData (entrada)
Valor de datos del cliente para pasar a proc.
Tcl_AsyncHandler async (entrada)
Token para el manejador de evento asíncrono.
Tcl_Interp *interp (entrada)
Intérprete Tcl en el cual se estaba evaluando el comando cuando el manejador fue invocado, o NULL si el manejador fue invocado cuando no había intérprete activo.
int code (entrada)
Código de finalización del comando que terminó en interp, o 0 si interp es NULL.

DESCRIPCIÓN

Estas funciones proporcionan un mecanismo seguro para manejar eventos asíncronos como señales. Si un evento como una señal ocurre mientras se está evaluando un script Tcl, no es seguro tomar ninguna acción significativa para procesarlo. Por ejemplo, no es seguro evaluar un script Tcl ya que el intérprete podría estar en medio de la evaluación de un script; podría no ser seguro incluso asignar memoria, ya que una asignación de memoria podría haber estado en progreso cuando ocurrió el evento. La única forma segura es marcar un indicador de que el evento ocurrió, luego manejar el evento cuando el mundo esté en un estado limpio, como después de que el comando actual termine.

Tcl_AsyncCreate, Tcl_AsyncDelete y Tcl_AsyncReady son conscientes de los hilos. Acceden y/o establecen una estructura de datos específica del hilo en caso de que el core esté construido con --enable-threads. El token creado por Tcl_AsyncCreate contiene la información necesaria de dónde se llamó para que al llamar a Tcl_AsyncMark(token) solo se devuelva el hilo de origen en el manejador asíncrono.

Tcl_AsyncCreate crea un manejador asíncrono y devuelve un token para él. El manejador asíncrono debe crearse antes de cualquier ocurrencia de eventos asíncronos que se espere manejar (no es seguro crear un manejador en el momento de una ocurrencia). Cuando ocurre un evento asíncrono, el código que detecta el evento (como un manejador de señal) debe llamar a Tcl_AsyncMark con el token del manejador. Tcl_AsyncMark marcará el manejador como listo para ejecutarse, pero no lo invocará inmediatamente. Tcl invocará a proc asociado con el manejador más tarde, cuando el mundo esté en un estado seguro, y proc podrá realizar las acciones asociadas con el evento asíncrono. Proc debe tener los argumentos y resultados que coincidan con el tipo Tcl_AsyncProc:

typedef int Tcl_AsyncProc(
        ClientData clientData,
        Tcl_Interp *interp,
        int code);

El clientData será el mismo que el clientData pasado a Tcl_AsyncCreate cuando se creó el manejador. Si proc es invocado justo después de que un comando complete en un intérprete, entonces interp identificará el intérprete en el que se evaluó el comando y code será el código de finalización devuelto por ese comando. El resultado del comando se presentará en el resultado del intérprete. Cuando proc devuelve, el valor que deja en el resultado del intérprete se devolverá como el resultado del comando y el valor devuelto por proc se usará como el nuevo código de finalización para el comando.

También es posible que proc sea invocado cuando no hay un intérprete activo. Esto puede ocurrir, por ejemplo, si un evento asíncrono ocurre mientras la aplicación está esperando entrada interactiva o un evento X. En este caso, interp será NULL y code será 0, y el valor devuelto por proc se ignorará.

La función Tcl_AsyncInvoke se llama para invocar a todos los manejadores que estén listos. La función Tcl_AsyncReady devolverá un valor distinto de cero cuando haya manejadores asíncronos listos; se puede verificar para evitar llamadas a Tcl_AsyncInvoke cuando no hay manejadores listos. Tcl llama a Tcl_AsyncReady después de cada comando evaluada y llama a Tcl_AsyncInvoke si es necesario. Las aplicaciones también pueden llamar a Tcl_AsyncInvoke en momentos interesantes para esa aplicación. Por ejemplo, el manejador de eventos de Tcl llama a Tcl_AsyncReady después de cada evento y llama a Tcl_AsyncInvoke si es necesario. Los argumentos interp y code de Tcl_AsyncInvoke tienen el mismo significado que para proc: identifican el intérprete activo, si lo hay, y el código de finalización del comando que terminó.

Tcl_AsyncDelete elimina un manejador asíncrono de manera que su proc nunca sea invocado de nuevo. Un manejador puede ser eliminado incluso cuando esté listo y aun así no será invocado.

Si múltiples manejadores se activan simultáneamente, los manejadores se invocan en el orden en que fueron creados (el manejador más antiguo primero). Los valores de code y el resultado del intérprete para los manejadores posteriores reflejan los valores devueltos por los manejadores anteriores, lo que permite que el manejador más reciente tenga la última palabra sobre el resultado del intérprete y el código de finalización. Si nuevos manejadores se vuelven listos mientras los manejadores se están ejecutando, Tcl_AsyncInvoke los invocará a todos; en cada punto, invoca el manejador de mayor prioridad (el más antiguo) y repite este proceso hasta que no haya más manejadores listos.

ADVERTENCIA

Es casi siempre una mala idea que un manejador de evento asíncrono modifique el resultado del intérprete o devuelva un código diferente al argumento code. Este tipo de comportamiento puede romper la ejecución de scripts de forma sutil y resultar en errores difíciles de encontrar. Si un manejador de evento asíncrono necesita evaluar scripts Tcl, debe primero guardar el estado del intérprete llamando a Tcl_SaveInterpState, pasando el argumento code. Al terminar el manejador asíncrono, debe restaurar el estado del intérprete llamando a Tcl_RestoreInterpState, y luego devolver el argumento code.
