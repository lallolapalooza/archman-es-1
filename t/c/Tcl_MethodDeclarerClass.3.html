DESCRIPCIÓN

Un método es una operación que se realiza sobre un objeto y que está asociada a él. Cada método debe estar asociado a un objeto o a una clase; los métodos asociados a una clase se asocian a todas las instancias (directas e indirectas) de esa clase.

Dado un método, la entidad que lo declaró se puede encontrar utilizando Tcl_MethodDeclarerClass, que devuelve la clase a la que está asociado el método (o NULL si el método no está asociado a ninguna clase), y Tcl_MethodDeclarerObject, que devuelve el objeto al que está asociado el método (o NULL si el método no está asociado a ningún objeto). El nombre del método se puede recuperar con Tcl_MethodName y si el método está exportado o no, con Tcl_MethodIsPublic. El tipo del método también se puede introspeccionar hasta cierto punto; la función Tcl_MethodIsType devuelve si un método es de un tipo particular, asignando el clientData por método a la variable apuntada por clientDataPtr (si no es NULL) si el tipo coincide.

CREACIÓN DE MÉTODOS

Los métodos se crean mediante Tcl_NewMethod y Tcl_NewInstanceMethod, que crean un método asociado a una clase o a un objeto, respectivamente. En ambos casos, el argumento nameObj indica el nombre del método a crear, el argumento isPublic indica si el método debe exportarse inicialmente, el argumento methodTypePtr describe la implementación del método (ver la sección TIPOS DE MÉTODOS) y el argumento clientData proporciona algunos datos específicos de la implementación que se pasan a la implementación del método cuando se llama.

Cuando el argumento nameObj de Tcl_NewMethod es NULL, se crea un método sin nombre, que se utiliza para constructores y destructores. Los constructores deben instalarse en su clase utilizando la función Tcl_ClassSetConstructor, y los destructores (que no deben requerir ningún argumento) deben instalarse en su clase utilizando la función Tcl_ClassSetDestructor. Los métodos sin nombre no deben utilizarse para ningún otro propósito, y los métodos con nombre no deben utilizarse como constructores ni destructores. Tenga en cuenta también que un methodTypePtr NULL se utiliza para proporcionar señalización interna y no debe utilizarse en código de cliente.

CONTEXTOS DE LLAMADA A MÉTODOS

Cuando se llama a un método, se pasa una referencia de contexto de llamada a método como uno de los argumentos a la función de implementación. Este contexto se puede inspeccionar para proporcionar información sobre el llamador, pero no debe conservarse más allá del momento en que finaliza la llamada al método.

El método que se está llamando se puede recuperar del contexto utilizando Tcl_ObjectContextMethod, y el objeto que provocó la invocación del método se puede recuperar con Tcl_ObjectContextObject. El número de argumentos que se deben omitir (por ejemplo, el nombre del objeto y el nombre del método en una llamada de método normal) se lee con Tcl_ObjectContextSkippedArgs, y el contexto también puede informar si está funcionando como un filtro para otro método a través de Tcl_ObjectContextIsFiltering.

Durante la ejecución de un método, la implementación del método puede optar por invocar las etapas de la cadena de llamadas al método que vienen después de la implementación del método actual. Esto (el núcleo del comando next) se hace utilizando Tcl_ObjectContextInvokeNext. Tenga en cuenta que esta función no manipula la pila de marcos de pila, a diferencia del comando next; si la implementación del método ha colocado uno o más marcos adicionales en la pila como parte de su implementación, también es responsable de extraer temporalmente esos marcos de la pila mientras se ejecuta la función Tcl_ObjectContextInvokeNext. Tenga en cuenta también que el contexto de llamada al método nunca se elimina durante la ejecución de esta función.

TIPOS DE MÉTODOS

Los tipos de métodos se describen mediante un puntero a una estructura Tcl_MethodType, que se define como:

typedef struct {
    int version;
    const char *name;
    Tcl_MethodCallProc *callProc;
    Tcl_MethodDeleteProc *deleteProc;
    Tcl_CloneProc *cloneProc;
} Tcl_MethodType;

El campo version permite futuras expansiones de la estructura y siempre debe declararse igual a TCL_OO_METHOD_VERSION_CURRENT. El campo name proporciona un nombre legible por humanos para el tipo y es el valor que se expone a través de los comandos Tcl info class methodtype y info object methodtype.

El campo callProc proporciona una función que se llama cuando se invoca el método; nunca debe ser NULL.

El campo deleteProc proporciona una función que se utiliza para eliminar un método particular y se llama cuando el método se reemplaza o se elimina; si el campo es NULL, se supone que el clientData del método no necesita ninguna acción especial para eliminarse.

El campo cloneProc es una función que se utiliza para copiar el clientData de un método (como parte de Tcl_CopyObjectInstance) o NULL para indicar que el clientData se puede copiar directamente.

FIRMA DE LA FUNCIÓN TCL_METHODCALLPROC

La firma de la función `callProc` es la siguiente:

typedef int Tcl_MethodCallProc(Tcl_Interp *interp,
        Tcl_ObjectContext context, int objc, Tcl_Obj *const objv[]);

El valor de retorno es el código de resultado de Tcl (TCL_OK, TCL_ERROR, etc.). El parámetro context se refiere al contexto de llamada a método; consulte la descripción de Tcl_ObjectContextInvokeNext para obtener más detalles.

FIRMA DE LA FUNCIÓN TCL_METHODDELETEPROC

La firma de la función `deleteProc` es la siguiente:

typedef void Tcl_MethodDeleteProc(ClientData clientData);

Esta función solo se llama si `deleteProc` no es NULL.

FIRMA DE LA FUNCIÓN TCL_CLONEPROC

La firma de la función `cloneProc` es la siguiente:

typedef void *Tcl_CloneProc(ClientData clientData);

Esta función solo se llama si `cloneProc` no es NULL. Debe devolver un puntero a una copia de los datos del cliente. Si los datos del cliente son simplemente copiados por valor, esta función puede ser implementada simplemente para devolver los datos del cliente tal cual.

NAME

Tcl_MethodDeclarerClass, Tcl_MethodCallProc, Tcl_MethodDeleteProc, Tcl_CloneProc - method definitions and invocation for TclOO

SYNOPSIS

#include <tclOO.h>
typedef struct Tcl_Method {
    Tcl_MethodType *type;
    ClientData data;
} Tcl_Method;
typedef struct Tcl_MethodType {
    Tcl_MethodCallProc *call;
    Tcl_MethodDeleteProc *delete;
    Tcl_CloneProc *clone;
    const char *name;
} Tcl_MethodType;

ARGUMENTS

ClientData clientData
Arbitrary client-specific data associated with a method. This is typically a pointer to a structure containing method-specific information.
Tcl_Interp *interp
The interpreter in which to execute the method. It is used to access variables, execute scripts, and store the method's result or error message.
Tcl_ObjectContext objectContext
The context in which the method is being called. This provides access to the object (or class) instance on which the method was invoked, as well as the method's class.
int objc
The number of arguments passed to the method.
Tcl_Obj *const *objv
An array of Tcl objects representing the arguments passed to the method. The first argument (objv[0]) is typically the method name.
ClientData *newClientDataPtr
A pointer to where the new clientData for a cloned method should be stored.

DESCRIPTION

TclOO provides a powerful object-oriented programming model within Tcl. Methods are fundamental components of this model, representing actions that can be performed by objects or classes. TclOO uses a dispatch mechanism based on Tcl_MethodType structures to define how methods are created, invoked, cleaned up, and copied.

A Tcl_Method structure holds a pointer to a Tcl_MethodType and clientData. The Tcl_MethodType structure defines the behavior of the method through function pointers, and the clientData holds any method-specific data. The name field in Tcl_MethodType is used for debugging and introspection.

TCL_METHODCALLPROC FUNCTION SIGNATURE

Functions matching this signature are called when the method is invoked.

typedef int Tcl_MethodCallProc(
        ClientData clientData,
        Tcl_Interp *interp,
        Tcl_ObjectContext objectContext,
        int objc,
        Tcl_Obj *const *objv);

The clientData argument to a Tcl_MethodCallProc is the value that was given when the method was created, the interp is a place in which to execute scripts and access variables as well as being where to put the result of the method, and the objc and objv fields give the parameter objects to the method. The calling context of the method can be discovered through the objectContext argument, and the return value from a Tcl_MethodCallProc is any Tcl return code (e.g. TCL_OK, TCL_ERROR).

TCL_METHODDELETEPROC FUNCTION SIGNATURE

Functions matching this signature are used when a method is deleted, whether through a new method being created or because the object or class is deleted.

typedef void Tcl_MethodDeleteProc(
        ClientData clientData);

The clientData argument to a Tcl_MethodDeleteProc will be the same as the value passed to the clientData argument to Tcl_NewMethod or Tcl_NewInstanceMethod when the method was created.

TCL_CLONEPROC FUNCTION SIGNATURE

Functions matching this signature are used to copy a method when the object or class is copied using Tcl_CopyObjectInstance (or oo::copy).

typedef int Tcl_CloneProc(
        Tcl_Interp *interp,
        ClientData oldClientData,
        ClientData *newClientDataPtr);

The interp argument gives a place to write an error message when the attempt to clone the object is to fail, in which case the clone procedure must also return TCL_ERROR; it should return TCL_OK otherwise. The oldClientData field to a Tcl_CloneProc gives the value from the method being copied from, and the newClientDataPtr field will point to a variable in which to write the value for the method being copied to.
