INTRODUCCION

Esta página de manual presenta una visión general de los valores Tcl (llamados Tcl_Obj por razones históricas) y cómo se utilizan. También describe procedimientos genéricos para gestionar valores Tcl. Estos procedimientos se utilizan para crear y copiar valores, e incrementar y decrementar el número de referencias (punteros) a los valores. Los procedimientos se describen junto con los que operan en tipos específicos de valores, como Tcl_GetIntFromObj y Tcl_ListObjAppendElement. Los procedimientos individuales se describen junto con las estructuras de datos que manipulan.

Los valores de doble puerto de Tcl proporcionan un mecanismo de propósito general para almacenar e intercambiar valores Tcl. Reemplazan en gran medida el uso de cadenas en Tcl. Por ejemplo, se utilizan para almacenar valores de variables, argumentos de comandos, resultados de comandos y scripts. Los valores Tcl se comportan como cadenas pero también mantienen una representación interna que puede manipularse de manera más eficiente. Por ejemplo, una lista Tcl ahora se representa como un valor que contiene la representación de cadena de la lista, así como una matriz de punteros a los valores de cada elemento de la lista. Los valores de doble puerto evitan la mayoría de las conversiones de tipos en tiempo de ejecución. También mejoran la velocidad de muchas operaciones, ya que una representación adecuada está disponible de inmediato. El propio compilador utiliza valores Tcl para almacenar en caché los códigos de bytes de instrucciones resultantes de la compilación de scripts.

Las dos representaciones son una caché la una de la otra y se calculan de forma perezosa. Es decir, cada representación solo se calcula cuando es necesario, se calcula a partir de la otra representación y, una vez calculada, se guarda. Además, un cambio en una representación invalida la otra. Como ejemplo, un programa Tcl que realiza cálculos de enteros puede operar directamente en la representación de enteros de la máquina interna de una variable sin tener que convertir constantemente entre enteros y cadenas. Solo cuando necesita una cadena que represente el valor de la variable, digamos para imprimirla, el programa regenerará la representación de cadena a partir del entero. Debido a esta invalidación y regeneración de la representación, es peligroso que los escritores de extensiones accedan directamente a los campos de Tcl_Obj. Es mejor acceder a la información de Tcl_Obj utilizando procedimientos como Tcl_GetStringFromObj y Tcl_GetString.

Los valores se asignan en el heap y se referencian mediante un puntero a su estructura Tcl_Obj. Los valores se comparten tanto como sea posible. Esto reduce significativamente los requisitos de almacenamiento, ya que algunos valores, como las listas largas, son muy grandes. Además, la mayoría de los valores Tcl solo se leen y nunca se modifican. Esto es especialmente cierto para los argumentos de procedimiento, que pueden compartirse entre el llamador y el procedimiento llamado. La asignación y la vinculación de argumentos se realizan simplemente asignando un puntero al valor. El recuento de referencias se utiliza para determinar cuándo es seguro reclamar el almacenamiento de un valor.

Los valores Tcl tienen tipos. La representación interna de un valor está controlada por su tipo. Varios tipos están predefinidos en el núcleo de Tcl, incluidos entero, doble, lista y bytecode. Los escritores de extensiones pueden ampliar el conjunto de tipos definiendo sus propias estructuras Tcl_ObjType.

LA ESTRUCTURA TCL_OBJ

Cada valor Tcl se representa mediante una estructura Tcl_Obj que se define de la siguiente manera.

typedef struct Tcl_Obj {
    int refCount;
    char *bytes;
    int length;
    const Tcl_ObjType *typePtr;
    union {
        long longValue;
        double doubleValue;
        void *otherValuePtr;
        Tcl_WideInt wideValue;
        struct {
            void *ptr1;
            void *ptr2;
        } twoPtrValue;
        struct {
            void *ptr;
            unsigned long value;
        } ptrAndLongRep;
    } internalRep;
} Tcl_Obj;

Los miembros bytes y length juntos contienen la representación de cadena UTF-8 de un valor, que es una cadena contada que no contiene bytes nulos (los caracteres nulos UTF-8 deben codificarse como una secuencia de dos bytes: 192, 128.) bytes apunta al primer byte de la representación de cadena. El miembro length indica el número de bytes. La matriz de bytes siempre debe tener un byte nulo después del último byte de datos, en el desplazamiento length; esto permite que las representaciones de cadena se traten como cadenas C convencionales terminadas en nulo. Los programas C utilizan Tcl_GetStringFromObj y Tcl_GetString para obtener la representación de cadena de un valor. Si bytes es NULL, la representación de cadena no es válida.

El tipo de un valor gestiona su representación interna. El miembro typePtr apunta a la estructura Tcl_ObjType que describe el tipo. Si typePtr es NULL, la representación interna no es válida.

El miembro de unión internalRep contiene la representación interna de un valor. Puede ser un entero (long), un número de punto flotante de doble precisión, un puntero a un valor que contiene información adicional necesaria para que el tipo del valor represente el valor, un entero Tcl_WideInt, dos punteros arbitrarios o un par formado por un entero unsigned long y un puntero.

El miembro refCount se utiliza para saber cuándo es seguro liberar el almacenamiento de un valor. Contiene el recuento de referencias activas al valor. Mantener el recuento de referencias correcto es una responsabilidad clave de los escritores de extensiones. El recuento de referencias se discute a continuación en la sección GESTION DE ALMACENAMIENTO DE VALORES.

Aunque los escritores de extensiones pueden acceder directamente a los miembros de una estructura Tcl_Obj, es mucho mejor utilizar los procedimientos y macros apropiados. Por ejemplo, los escritores de extensiones nunca deben leer ni actualizar refCount directamente; deben utilizar macros como Tcl_IncrRefCount y Tcl_IsShared en su lugar.

Una propiedad clave de los valores Tcl es que contienen dos representaciones. Un valor normalmente comienza conteniendo solo una representación de cadena: no tiene tipo y tiene un typePtr NULL. Un valor que contiene una cadena vacía o una copia de una cadena especificada se crea utilizando Tcl_NewObj o Tcl_NewStringObj respectivamente. El valor de cadena de un valor se obtiene con Tcl_GetStringFromObj o Tcl_GetString y se cambia con Tcl_SetStringObj. Si más tarde el valor se pasa a un procedimiento como Tcl_GetIntFromObj que requiere una representación interna específica, el procedimiento creará una y establecerá el typePtr del valor. La representación interna se calcula a partir de la representación de cadena. Las dos representaciones de un valor son duales entre sí: los cambios realizados en una se reflejan en la otra. Por ejemplo, Tcl_ListObjReplace modificará la representación interna de un valor y la siguiente llamada a Tcl_GetStringFromObj o Tcl_GetString reflejará ese cambio.

Las representaciones se recalculan de forma perezosa por eficiencia. Un cambio en una representación realizado por un procedimiento como Tcl_ListObjReplace no se refleja inmediatamente en la otra representación. En su lugar, la otra representación se marca como inválida para que solo se regenere si es necesaria más adelante. La mayoría de los programadores de C nunca tienen que preocuparse por cómo se hace esto y simplemente utilizan procedimientos como Tcl_GetBooleanFromObj o Tcl_ListObjIndex. Los programadores que implementan sus propios tipos de valor deben comprobar las representaciones inválidas y marcar las representaciones como inválidas cuando sea necesario. El procedimiento Tcl_InvalidateStringRep se utiliza para marcar la representación de cadena de un valor como inválida y para liberar cualquier almacenamiento asociado con la representación de cadena antigua.

Tcl_DecrRefCount

Tcl_DecrRefCount, Tcl_IncrRefCount, Tcl_IsShared, Tcl_DuplicateObj - manipulate reference counts for Tcl values

SYNOPSIS

#include <tcl.h>

void
Tcl_DecrRefCount(
    Tcl_Obj *objPtr);

void
Tcl_IncrRefCount(
    Tcl_Obj *objPtr);

int
Tcl_IsShared(
    Tcl_Obj *objPtr);

Tcl_Obj *
Tcl_DuplicateObj(
    Tcl_Obj *objPtr);

ARGUMENTS

Tcl_Obj *objPtr
An object whose reference count is to be manipulated. The object must not be NULL.

DESCRIPTION

Tcl uses the object type system to manage values. In this system, values are represented by Tcl objects, which are stored in structures of type Tcl_Obj. Tcl objects are allocated on the heap and are shared between different parts of Tcl and between different Tcl commands to reduce memory usage. For example, when a value is passed as an argument to a Tcl command, and the command needs to use that value later, Tcl will typically increment the value's reference count rather than making a copy. When the value is no longer needed, its reference count is decremented.

A Tcl object's reference count is stored in the refCount field of the Tcl_Obj structure. When a Tcl object is first created (e.g., via Tcl_NewObj or Tcl_NewStringObj), its reference count is initialized to zero. Tcl code that obtains a pointer to a Tcl object and wants to keep that pointer after the current operation returns should increment the object's reference count using Tcl_IncrRefCount. This ensures that the object will not be freed prematurely. The reference count should be decremented using Tcl_DecrRefCount when the pointer is no longer needed.

Tcl_DecrRefCount decrements the reference count for objPtr. If the reference count becomes zero as a result of this call, the object is freed. Note that Tcl_DecrRefCount should only be called if the reference count was previously incremented by a call to Tcl_IncrRefCount, or if the object was created specifically for the current operation and is guaranteed not to be shared.

Tcl_IncrRefCount increments the reference count for objPtr. This is used when a new reference to an object is taken, for example, when a value is passed as an argument to a procedure and that procedure needs to hold onto the value beyond its execution. It is crucial to call Tcl_IncrRefCount to ensure that shared objects are not freed while they are still in use.

Tcl_IsShared returns a non-zero value if the reference count for objPtr is greater than 1, and zero otherwise. This function is useful for determining if modifying an object will affect other parts of the Tcl interpreter that might be using the same object. If an object is shared, and it needs to be modified, it should be duplicated first using Tcl_DuplicateObj.

Tcl_DuplicateObj creates a new copy of the Tcl object objPtr. The new object has its own internal representation and its reference count is initialized to zero. The original object is unchanged. This function is essential when a command needs to modify an object that is shared by other parts of the interpreter. By duplicating the object, the command can modify the copy without affecting the original or other users of the original.

Many Tcl commands and procedures manage the reference counts for objects implicitly. For example, when a variable is set, its old value's reference count is decremented, and the new value's reference count is incremented. However, when Tcl extension writers directly manipulate Tcl objects, they must be careful to manage the reference counts correctly.

VALUE REPRESENTATIONS

A Tcl object can have multiple internal representations (e.g., integer, string, list). The Tcl interpreter automatically converts between these representations as needed. For example, if an object is created as a string and then incremented using the incr command, Tcl will convert it to an integer representation. This conversion is done using the Tcl_Convert procedure (not exported but called internally) which internally calls procedures like Tcl_GetIntFromObj, Tcl_GetBooleanFromObj, etc. These procedures check if the object already has the desired representation; if not, they attempt to convert it. After a successful conversion, the object's internal representation is updated, and its string representation is invalidated (marked as needing to be recomputed). Extension writers can also force conversions using Tcl_ConvertToType.

The string representation of an object is computed on demand and is cached. When the object's internal representation changes, the cached string representation becomes invalid and must be recomputed the next time it is needed. The Tcl_InvalidateStringRep procedure can be used to explicitly invalidate the string representation of an object.

The list representation of an object can be accessed using functions like Tcl_ListObjIndex to extract a list element from the value. The same value holding the same string value can have several different internal representations at different times. Extension writers can also force a value to be converted from one type to another using the Tcl_ConvertToType procedure. Only programmers that create new value types need to be concerned about how this is done. A procedure defined as part of the value type's implementation creates a new internal representation for a value and changes its typePtr. See the man page for Tcl_RegisterObjType to see how to create a new value type.

EXAMPLE OF THE LIFETIME OF A VALUE

As an example of the lifetime of a value, consider the following sequence of commands:

set x 123

This assigns to x an untyped value whose bytes member points to 123 and length member contains 3. The value's typePtr member is NULL.

puts "x is $x"

x's string representation is valid (since bytes is non-NULL) and is fetched for the command.

incr x

The incr command first gets an integer from x's value by calling Tcl_GetIntFromObj. This procedure checks whether the value is already an integer value. Since it is not, it converts the value by setting the value's internal representation to the integer 123 and setting the value's typePtr to point to the integer Tcl_ObjType structure. Both representations are now valid. incr increments the value's integer internal representation then invalidates its string representation (by calling Tcl_InvalidateStringRep) since the string representation no longer corresponds to the internal representation.

puts "x is now $x"

The string representation of x's value is needed and is recomputed. The string representation is now 124 and both representations are again valid.

STORAGE MANAGEMENT OF VALUES

Tcl values are allocated on the heap and are shared as much as possible to reduce storage requirements. Reference counting is used to determine when a value is no longer needed and can safely be freed. A value just created by Tcl_NewObj or Tcl_NewStringObj has refCount 0. The macro Tcl_IncrRefCount increments the reference count when a new reference to the value is created. The macro Tcl_DecrRefCount decrements the count when a reference is no longer needed and, if the value's reference count drops to zero, frees its storage. A value shared by different code or data structures has refCount greater than 1. Incrementing a value's reference count ensures that it will not be freed too early or have its value change accidentally.

As an example, the bytecode interpreter shares argument values between calling and called Tcl procedures to avoid having to copy values. It assigns the call's argument values to the procedure's formal parameter variables. In doing so, it calls Tcl_IncrRefCount to increment the reference count of each argument since there is now a new reference to it from the formal parameter. When the called procedure returns, the interpreter calls Tcl_DecrRefCount to decrement each argument's reference count. When a value's reference count drops less than or equal to zero, Tcl_DecrRefCount reclaims its storage. Most command procedures do not have to be concerned about reference counting since they use a value's value immediately and do not retain a pointer to the value after they return. However, if they do retain a pointer to a value in a data structure, they must be careful to increment its reference count since the retained pointer is a new reference.

Command procedures that directly modify values such as those for lappend and linsert must be careful to copy a shared value before changing it. They must first check whether the value is shared by calling Tcl_IsShared. If the value is shared they must copy the value by using Tcl_DuplicateObj; this returns a new duplicate of the original value that has refCount 0. If the value is not shared, the command procedure “owns” the value and can safely modify it directly. For example, the following code appears in the command procedure that implements linsert. This procedure modifies the list value passed to it in objv[1] by inserting objc-3 new elements before index.

listPtr = objv[1];
if (Tcl_IsShared(listPtr)) {
    listPtr = Tcl_DuplicateObj(listPtr);
}
result = Tcl_ListObjReplace(interp, listPtr, index, 0,
        (objc-3), &(objv[3]));

As another example, incr's command procedure must check whether the variable's value is shared before incrementing the integer in its internal representation. If it is shared, it needs to duplicate the value in order to avoid accidentally changing values in other data structures.
