ARGUMENTOS

Tcl_Interp *interp (entrada)
El intérprete donde se almacenarán los datos comprimidos o descomprimidos resultantes. También donde se escribirán los mensajes de error. Para Tcl_ZlibStreamInit, esto puede ser NULL para crear un stream que no esté enlazado a un comando.
int format (entrada)
Qué formato de datos comprimidos manejar. Debe ser uno de TCL_ZLIB_FORMAT_ZLIB para datos en formato zlib, TCL_ZLIB_FORMAT_GZIP para datos en formato gzip, o TCL_ZLIB_FORMAT_RAW para datos comprimidos sin formato. Además, para descompresión solamente, también se puede elegir TCL_ZLIB_FORMAT_AUTO que puede detectar automáticamente si los datos comprimidos estaban en formato zlib o gzip.
Tcl_Obj *dataObj (entrada/salida)
Un valor de tipo array de bytes que contiene los datos a comprimir o descomprimir, o al que se añadirán los datos extraídos del stream cuando se pase a Tcl_ZlibStreamGet.
int level (entrada)
Qué nivel de compresión usar. Debe ser un número del 0 al 9 o uno de los siguientes: TCL_ZLIB_COMPRESS_NONE para no comprimir, TCL_ZLIB_COMPRESS_FAST para compresión rápida pero ineficiente, TCL_ZLIB_COMPRESS_BEST para compresión lenta pero máxima, o TCL_ZLIB_COMPRESS_DEFAULT para el nivel recomendado por la librería zlib.
Tcl_Obj *dictObj (entrada/salida)
Un diccionario que contiene, o que se actualizará para contener, una descripción de la cabecera gzip asociada a los datos comprimidos. Solo es útil cuando el parámetro format es TCL_ZLIB_FORMAT_GZIP o TCL_ZLIB_FORMAT_AUTO. Si se pasa un NULL, se usará una cabecera por defecto en la compresión y la cabecera se ignorará (aparte de las comprobaciones de integridad) en la descompresión. Consulte la sección DICCIONARIO DE OPCIONES GZIP para obtener detalles sobre el contenido de este diccionario.
unsigned int initValue (entrada)
El valor inicial para el algoritmo de checksum.
int bufferSize (entrada)
Una pista sobre el tamaño del buffer que se utilizará para recibir los datos. Use 0 para usar una estimación genérica basada en los datos de entrada.
unsigned char *bytes (entrada)
Un array de bytes sobre el que ejecutar el algoritmo de checksum, o NULL para obtener el valor inicial recomendado para el algoritmo de checksum.
int length (entrada)
El número de bytes en el array.
int mode (entrada)
En qué modo operar el stream. Debe ser TCL_ZLIB_STREAM_DEFLATE para un stream de compresión o TCL_ZLIB_STREAM_INFLATE para un stream de descompresión.
Tcl_ZlibStream *zshandlePtr (salida)
Un puntero a una variable en la que escribir el token abstracto para el stream tras su creación exitosa.
Tcl_ZlibStream zshandle (entrada)
El token abstracto para operar sobre el stream.
int flush (entrada)
Si y cómo vaciar el stream después de escribirle los datos. Debe ser uno de: TCL_ZLIB_NO_FLUSH si no se va a realizar ningún vaciado, TCL_ZLIB_FLUSH si los datos comprimidos actualmente deben estar disponibles para su acceso usando Tcl_ZlibStreamGet, TCL_ZLIB_FULLFLUSH si el stream debe ponerse en un estado donde el descompresor pueda recuperarse de una corrupción, o TCL_ZLIB_FINALIZE para asegurar que el stream se ha completado y que cualquier tráiler exigido por el formato se ha escrito.
int count (entrada)
El número máximo de bytes a obtener del stream, o -1 para obtener todos los bytes restantes de los buffers del stream.
Tcl_Obj *compDict (entrada)
Un valor de array de bytes que es el diccionario de compresión a usar con el stream. Tenga en cuenta que esto no es un diccionario Tcl, y se recomienda que solo se use con streams que fueron creados con su format establecido a TCL_ZLIB_FORMAT_ZLIB porque los otros formatos no tienen un mecanismo para indicar si se presentó un diccionario de compresión aparte de fallar en la descompresión.

DESCRIPCIÓN

Estas funciones forman la interfaz de la librería Tcl a la librería Zlib de Jean-loup Gailly y Mark Adler.

Tcl_ZlibDeflate y Tcl_ZlibInflate respectivamente comprimen y descomprimen los datos contenidos en el argumento dataObj, de acuerdo con los argumentos format y, para la compresión, level. El diccionario en el parámetro dictObj se utiliza para transmitir información adicional de cabecera sobre los datos comprimidos cuando el formato de compresión lo soporta; actualmente, el diccionario solo se usa cuando el parámetro format es TCL_ZLIB_FORMAT_GZIP o TCL_ZLIB_FORMAT_AUTO. Para detalles sobre el contenido del diccionario, consulte la sección DICCIONARIO DE OPCIONES GZIP más abajo. Tras el éxito, ambas funciones dejan los datos comprimidos o descomprimidos resultantes en un valor de array de bytes que es el resultado del intérprete Tcl; el valor devuelto es un código de resultado Tcl estándar.

Tcl_ZlibAdler32 y Tcl_ZlibCRC32 calculan checksums sobre arrays de bytes, devolviendo el checksum calculado. Los checksums se calculan incrementalmente, permitiendo procesar los datos bloque a bloque, pero esto requiere que el llamante mantenga el checksum actual y lo pase como parámetro initValue; el valor inicial a usar para esto se puede obtener usando NULL para el parámetro bytes en lugar de un puntero al array de bytes sobre el que calcular el checksum. Por lo tanto, el uso típico en el caso de un solo bloque de datos es el siguiente:

checksum = Tcl_ZlibCRC32(Tcl_ZlibCRC32(0,NULL,0), data, length);

Tenga en cuenta que el algoritmo Adler-32 no es un checksum real, sino un tipo de hash relacionado que funciona mejor en datos largos.

STREAMS ZLIB

Tcl_ZlibStreamInit crea un stream de compresión o descompresión que está enlazado a un comando Tcl, de acuerdo con sus argumentos, y proporciona un token abstracto para el stream y devuelve un código de resultado Tcl normal; Tcl_ZlibStreamGetCommandName devuelve el nombre de ese comando dado el token del stream, o NULL si el stream no tiene comando. Los streams no están diseñados para ser seguros en hilos; cada stream solo debe usarse desde el hilo que lo creó. Al trabajar con streams gzip, se puede proporcionar un diccionario (campos como se indica en la sección DICCIONARIO DE OPCIONES GZIP) a través del parámetro dictObj que en la compresión permite controlar las cabeceras generadas, y en la descompresión permite el descubrimiento de las cabeceras existentes. Tenga en cuenta que el diccionario se escribirá en la descompresión una vez que se hayan leído suficientes datos para tener una cabecera completa. Esto significa que el diccionario debe ser un valor no compartido en ese caso; se sugiere un valor en blanco creado con Tcl_NewObj.

Una vez que se ha construido un stream, Tcl_ZlibStreamPut se utiliza para añadir datos al stream y Tcl_ZlibStreamGet se utiliza para recuperar datos del stream después del procesamiento. Ambos devuelven códigos de resultado Tcl normales y dejan un mensaje de error en el resultado del intérprete con el que está registrado el stream (si dicha registro se ha realizado). Con Tcl_ZlibStreamPut, el valor del buffer de datos pasado a él no debe modificarse después. Con Tcl_ZlibStreamGet, el valor del buffer de datos pasado a él tendrá los bytes de datos añadidos. Internamente al stream, los datos se mantienen comprimidos para minimizar el coste del espacio en el buffer.

Tcl_ZlibStreamChecksum devuelve el checksum calculado sobre los datos descomprimidos de acuerdo con el formato, y Tcl_ZlibStream

Eof devuelve un valor booleano que indica si se ha alcanzado el final de los datos sin comprimir.

Tcl_ZlibStreamSetCompressionDictionary se utiliza para controlar el diccionario de compresión utilizado con el flujo, siendo un diccionario de compresión un array de bytes (como podría crearse con Tcl_NewByteArrayObj) que se utiliza para inicializar el motor de compresión en lugar de dejar que lo cree sobre la marcha a partir de los datos que se están comprimiendo. Establecer un diccionario de compresión permite una compresión más eficiente en el caso de que el inicio de los datos sea muy regular, pero requiere que tanto el compresor como el descompresor acuerden el valor a utilizar. Los diccionarios de compresión solo se admiten completamente para datos en formato zlib; en la compresión, deben establecerse antes de que se envíen datos con Tcl_ZlibStreamPut, y en la descompresión deben establecerse cuando Tcl_ZlibStreamGet produzca un error con su -errorcode establecido en “ZLIB NEED_DICT código”; el código será la suma de verificación Adler-32 (ver Tcl_ZlibAdler32) del diccionario de compresión buscado. (Tenga en cuenta que esto solo es cierto para flujos en formato zlib; los flujos gzip ignoran los diccionarios de compresión ya que la especificación del formato no los permite, y los flujos raw simplemente producen un error de datos si el diccionario de compresión falta o es incorrecto).

Si desea limpiar un flujo y reutilizarlo para una nueva acción de compresión o descompresión, Tcl_ZlibStreamReset lo hará y devolverá un código de resultado Tcl normal para indicar si fue exitoso; si el flujo está registrado en un intérprete, se dejará un mensaje de error en el resultado del intérprete cuando esta función devuelva TCL_ERROR. Finalmente, Tcl_ZlibStreamClose limpiará el flujo y eliminará el comando asociado: usar Tcl_DeleteCommand en el comando del flujo es equivalente (cuando dicho comando existe).

OPCIONES GZIP DICIONARIO

El parámetro dictObj a Tcl_ZlibDeflate, Tcl_ZlibInflate y Tcl_ZlibStreamInit se utiliza para pasar un diccionario de opciones sobre cómo describir la cabecera gzip en los datos comprimidos. Al crear datos comprimidos, se lee el diccionario y al desempaquetar datos comprimidos se escribe el diccionario (en cuyo caso el parámetro dictObj debe hacer referencia a un valor de diccionario no compartido).

Se entienden los siguientes campos en el valor del diccionario. Todos los demás campos se ignoran. No se requiere ningún campo al crear un flujo en formato gzip.

comment
Contiene el campo comentario de la cabecera, si está presente. Si está ausente, no se proporcionó ningún comentario (en descompresión) ni se creará (en compresión).
crc
Un valor booleano que describe si se calcula una CRC de la cabecera. Tenga en cuenta que el programa gzip no utiliza ni permite una CRC en la cabecera.
filename
El nombre del archivo que contenía los datos sin comprimir. No debe contener separadores de directorio y debe ser saneado antes de su uso en descompresión con file tail.
os
El campo del código del tipo de sistema operativo de la cabecera (si no es el valor “desconocido”). Consulte RFC 1952 para conocer el significado de estos códigos. En compresión, si está ausente, el campo se establecerá al valor “desconocido”.
size
El tamaño de los datos sin comprimir. Se ignora en la compresión; el tamaño de los datos comprimidos depende de cuántos datos se suministren al motor de compresión.
time
El campo de tiempo de la cabecera si no es cero, se espera que sea la hora en que se modificó el archivo nombrado por el campo filename. Adecuado para usar con clock format. En la creación, el valor correcto a usar es el de clock seconds o file mtime.
type
El tipo de los datos sin comprimir (ya sea binary o text) si se conoce.

NOTAS DE PORTABILIDAD

Estas funciones fallarán elegantemente si Tcl no está enlazado con la biblioteca zlib.
