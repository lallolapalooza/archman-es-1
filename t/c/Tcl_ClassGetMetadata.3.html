DESCRIPCIÓN

Los objetos son entidades tipadas que tienen un conjunto de operaciones ("métodos") asociadas a ellos. Las clases son objetos que pueden fabricar objetos. Cada clase puede ser vista como un objeto en sí misma; la vista de objeto se puede recuperar usando Tcl_GetClassAsObject, que siempre devuelve el objeto cuando se aplica a una clase no destruida, y un objeto puede ser visto como una clase con la ayuda de Tcl_GetObjectAsClass (que o bien devuelve la clase, o NULL si el objeto no es una clase). Un objeto puede ser buscado usando la función Tcl_GetObjectFromObj, que o bien devuelve un objeto o NULL (con un mensaje de error en el resultado del intérprete) si el objeto no puede ser encontrado. La forma correcta de buscar una clase por nombre es buscar el objeto con ese nombre, y luego usar Tcl_GetObjectAsClass.

Cada objeto tiene su propio comando y namespace asociados. El comando se puede recuperar usando la función Tcl_GetObjectCommand, el nombre del objeto (y por lo tanto el nombre del comando) con Tcl_GetObjectName, y el namespace se puede recuperar usando la función Tcl_GetObjectNamespace. Tenga en cuenta que la referencia Tcl_Obj devuelta por Tcl_GetObjectName es una referencia compartida. También puede obtener si el objeto ha sido marcado para eliminación con Tcl_ObjectDeleted (devuelve verdadero si la eliminación del objeto ha comenzado); esto puede ser útil durante el procesamiento de métodos.

Las instancias de clases se crean usando Tcl_NewObjectInstance, que crea un objeto a partir de cualquier clase (y que es llamado internamente tanto por los métodos create como new de la clase oo::class). Toma parámetros que opcionalmente dan el nombre del objeto y namespace a crear, y que describen los argumentos a pasar al constructor de la clase (si lo hay). El resultado de la función será ya sea una referencia al nuevo objeto creado, o NULL si la creación falló (cuando se dejará un mensaje de error en el resultado del intérprete). Además, los objetos pueden ser copiados usando Tcl_CopyObjectInstance, que crea una copia de un objeto sin ejecutar ningún constructor.

Tenga en cuenta que la gestión de la vida útil de los objetos es manejada internamente dentro de TclOO, y no utiliza Tcl_Preserve. No es seguro poner un manejador Tcl_Object en una estructura C con una vida útil diferente a la del objeto; debería usar el nombre del comando del objeto (recuperado con Tcl_GetObjectName) en su lugar. Es seguro usar un manejador Tcl_Object durante la vida útil de una llamada a un método sobre ese objeto; los manejadores no se vuelven inválidos mientras haya una llamada pendiente a su objeto (incluso si la única operación garantizada como segura sobre ellos es Tcl_ObjectDeleted; las otras operaciones solo están garantizadas para funcionar en objetos no eliminados).

METADATOS DE OBJETO Y CLASE

Cada objeto y cada clase pueden tener cantidades arbitrarias de metadatos adjuntos a ellos, a los que el objeto o la clase no les adjunta más significado que el descrito en una instancia de estructura Tcl_ObjectMetadataType. Los metadatos a adjuntar se describen por el tipo de los metadatos (dado en el argumento metaTypePtr) y un puntero arbitrario (el argumento metadata) que se dan a Tcl_ObjectSetMetadata y Tcl_ClassSetMetadata, y una pieza particular de metadatos se puede recuperar dado su tipo usando Tcl_ObjectGetMetadata y Tcl_ClassGetMetadata. Si el parámetro metadata a Tcl_ObjectSetMetadata o Tcl_ClassSetMetadata es NULL, los metadatos se eliminan si estaban adjuntos, y los resultados de Tcl_ObjectGetMetadata y Tcl_ClassGetMetadata son NULL si el tipo de metadatos dado no estaba adjunto. No es un error solicitar o eliminar una pieza de metadatos que no estaba adjunta.

ESTRUCTURA TCL_OBJECTMETADATATYPE

El contenido de la estructura Tcl_ObjectMetadataType es el siguiente:

typedef const struct {
    int version;
    const char *name;
    Tcl_ObjectMetadataDeleteProc *deleteProc;
    Tcl_CloneProc *cloneProc;
} Tcl_ObjectMetadataType;

El campo version permite la expansión futura de la estructura, y siempre debe declararse igual a TCL_OO_METADATA_VERSION_CURRENT. El campo name proporciona un nombre legible por humanos para el tipo, y está reservado para depuración.

El campo deleteProc da una función de tipo Tcl_ObjectMetadataDeleteProc que se utiliza para eliminar una pieza particular de metadatos, y se llama cuando los metadatos adjuntos son reemplazados o eliminados; el campo no debe ser NULL.

El campo cloneProc da una función que se utiliza para copiar una pieza de metadatos (utilizada cuando se crea una copia de un objeto usando Tcl_CopyObjectInstance); si es NULL, los metadatos se copiarán directamente.

DESCRIPCIÓN

Este documento describe las signaturas de las funciones de devolución de llamada utilizadas por el sistema de objetos de TclOO.

TCL_OBJECTMETADATADELETEPROC FUNCTION SIGNATURE

Las funciones que coinciden con esta signatura se utilizan para liberar la memoria de los metadatos asociados con una clase u objeto cuando esa clase u objeto es destruido.

typedef void Tcl_ObjectMetadataDeleteProc(
        ClientData metadata);

El argumento metadata proporciona la dirección de los metadatos que se van a eliminar.

TCL_CLONEPROC FUNCTION SIGNATURE

Las funciones que coinciden con esta signatura se utilizan para crear copias de los metadatos asociados con una clase u objeto.

typedef int Tcl_CloneProc(
        Tcl_Interp *interp,
        ClientData srcMetadata,
        ClientData *dstMetadataPtr);

El argumento interp proporciona un lugar para escribir un mensaje de error cuando el intento de clonar el objeto falla, en cuyo caso el procedimiento de clonación también debe devolver TCL_ERROR; de lo contrario, debe devolver TCL_OK. El argumento srcMetadata proporciona la dirección de los metadatos que se van a clonar, y los metadatos clonados deben escribirse en la variable apuntada por dstMetadataPtr; se debe escribir un NULL si los metadatos no se van a clonar, pero la operación de copia del objeto en general aún debe tener éxito.

METADATOS DE OBJETO Y CLASE

Los objetos y clases en TclOO pueden tener datos de metadatos asociados. Estos metadatos se pueden establecer y recuperar utilizando los comandos `oo::object metadata` y `oo::class metadata` respectivamente. Las funciones de devolución de llamada Tcl_ObjectMetadataDeleteProc y Tcl_CloneProc se utilizan para gestionar la vida útil de estos metadatos.

Cuando se crea un objeto, se puede especificar un procedimiento de clonación para los metadatos. Este procedimiento se llama cuando se clona el objeto, permitiendo que los metadatos se copien o se compartan según sea necesario.

Cuando un objeto o clase se destruye, se llama a su procedimiento de eliminación de metadatos para liberar cualquier recurso asociado.

MAPEADO DE NOMBRES DE MÉTODOS DE OBJETO

Es posible controlar, por objeto, qué métodos se invocan cuando se invoca un método particular. Normalmente, esto se hace buscando el nombre del método en el objeto y luego en la jerarquía de clases, pero se ofrece un control preciso sobre qué valor se utiliza para realizar la búsqueda a través de la capacidad de establecer una devolución de llamada de mapeo de nombres de métodos mediante Tcl_ObjectSetMethodNameMapper (y su contraparte de introspección, Tcl_ObjectGetMethodNameMapper, que devuelve el mapeador actual). El mapeador actual (si lo hay) se invoca inmediatamente antes de buscar qué cadena de implementaciones de métodos se va a utilizar.

TCL_OBJECTMAPMETHODNAMEPROC FUNCTION SIGNATURE

La devolución de llamada Tcl_ObjectMapMethodNameProc se define de la siguiente manera:

typedef int Tcl_ObjectMapMethodNameProc(
        Tcl_Interp *interp,
        Tcl_Object object,
        Tcl_Class *startClsPtr,
        Tcl_Obj *methodNameObj);

Si el resultado es TCL_OK, se asume que se ha realizado el remapeado. Si el resultado es TCL_ERROR, se habrá dejado un mensaje de error en interp y la llamada al método fallará. Si el resultado es TCL_BREAK, se utilizarán las reglas de búsqueda de nombres de métodos estándar; el comportamiento de otros códigos de resultado no está definido actualmente. El parámetro object indica qué objeto se está procesando. El parámetro startClsPtr apunta a una variable que contiene la primera clase que proporciona una definición en la cadena de métodos a procesar, o NULL si se va a procesar toda la cadena (el argumento en sí nunca es NULL); esta variable puede ser actualizada por la devolución de llamada. El parámetro methodNameObj proporciona un objeto no compartido que contiene el nombre del método que se está invocando, tal como lo proporciona el usuario; este objeto puede ser actualizado por la devolución de llamada.
