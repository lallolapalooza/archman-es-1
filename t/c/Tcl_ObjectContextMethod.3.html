Tcl_Interp *interp (entrada/salida)
El intérprete que contiene el objeto o clase en la que crear o actualizar un método.
Tcl_Object object (entrada)
El objeto en el que crear el método.
Tcl_Class class (entrada)
La clase en la que crear el método.
Tcl_Obj *nameObj (entrada)
El nombre del método a crear. No debe ser NULL a menos que se estén creando constructores o destructores.
int isPublic (entrada)
Una bandera que indica la visibilidad del método. Los únicos valores públicos admitidos para esta bandera son 0 para un método no exportado y 1 para un método exportado.
Tcl_MethodType *methodTypePtr (entrada)
Una descripción del tipo de método a crear, o el tipo de método a comparar.
ClientData clientData (entrada)
Un fragmento de datos que se pasa a la implementación del método sin interpretación.
ClientData *clientDataPtr (salida)
Un puntero a una variable en la que se escribirá el valor clientData suministrado cuando se creó el método. Si es NULL, el valor clientData no se recuperará.

Una referencia a un método para consultar.

El número de argumentos a pasar a la implementación del método.

Una matriz de argumentos a pasar a la implementación del método.
int skip (entrada)
El número de argumentos pasados a la implementación del método que no representan argumentos "reales".

DESCRIPCIÓN

Un método es una operación que se lleva a cabo en un objeto y que está asociada al objeto. Cada método debe adjuntarse a un objeto o a una clase; los métodos adjuntos a una clase se asocian con todas las instancias (directas e indirectas) de esa clase.

Dado un método, la entidad que lo declaró se puede encontrar usando Tcl_MethodDeclarerClass, que devuelve la clase a la que está adjunto el método (o NULL si el método no está adjunto a ninguna clase), y Tcl_MethodDeclarerObject, que devuelve el objeto al que está adjunto el método (o NULL si el método no está adjunto a un objeto). El nombre del método se puede recuperar con Tcl_MethodName y si el método está exportado se recupera con Tcl_MethodIsPublic. El tipo del método también se puede introspeccionar hasta un grado limitado; la función Tcl_MethodIsType devuelve si un método es de un tipo particular, asignando el clientData por método a la variable apuntada por clientDataPtr si (que no es NULL) si el tipo coincide.

CREACIÓN DE MÉTODOS

Los métodos se crean con Tcl_NewMethod y Tcl_NewInstanceMethod, que crean un método adjunto a una clase o a un objeto respectivamente. En ambos casos, el argumento nameObj da el nombre del método a crear, el argumento isPublic indica si el método debe exportarse inicialmente, el argumento methodTypePtr describe la implementación del método (ver la sección TIPOS DE MÉTODOS abajo) y el argumento clientData da algunos datos específicos de la implementación que se pasan a la implementación del método cuando se llama.

Cuando el argumento nameObj a Tcl_NewMethod es NULL, se crea un método sin nombre, que se usa para constructores y destructores. Los constructores deben instalarse en su clase usando la función Tcl_ClassSetConstructor, y los destructores (que no deben requerir ningún argumento) deben instalarse en su clase usando la función Tcl_ClassSetDestructor. Los métodos sin nombre no deben usarse para ningún otro propósito, y los métodos con nombre no deben usarse como constructores ni destructores. Tenga en cuenta también que un methodTypePtr NULL se usa para proporcionar señalización interna y no debe usarse en código cliente.

CONTEXTOS DE LLAMADA A MÉTODOS

Cuando se llama a un método, se pasa una referencia de contexto de llamada a método como uno de los argumentos a la función de implementación. Este contexto se puede inspeccionar para proporcionar información sobre el llamador, pero no debe conservarse más allá del momento en que termina la llamada al método.

El método que se está llamando se puede recuperar del contexto usando Tcl_ObjectContextMethod, y el objeto que provocó la invocación del método se puede recuperar con Tcl_ObjectContextObject. El número de argumentos que se omitirán (por ejemplo, el nombre del objeto y el nombre del método en una llamada normal a método) se lee con Tcl_ObjectContextSkippedArgs, y el contexto también puede informar si está funcionando como un filtro para otro método a través de Tcl_ObjectContextIsFiltering.

Durante la ejecución de un método, la implementación del método puede optar por invocar las etapas de la cadena de llamada de métodos que vienen después de la implementación del método actual. Esto (el núcleo del comando next) se hace usando Tcl_ObjectContextInvokeNext. Tenga en cuenta que esta función no manipula la pila de marcos de llamada, a diferencia del comando next; si la implementación del método ha introducido uno o más marcos adicionales en la pila como parte de su implementación, también es responsable de eliminar temporalmente esos marcos de la pila mientras se ejecuta la función Tcl_ObjectContextInvokeNext. Tenga en cuenta también que el contexto de llamada a método **nunca** se elimina durante la ejecución de esta función.

TIPOS DE MÉTODOS

Los tipos de métodos se describen mediante un puntero a una estructura Tcl_MethodType, que se define como:

typedef struct {
    int version;
    const char *name;
    Tcl_MethodCallProc *callProc;
    Tcl_MethodDeleteProc *deleteProc;
    Tcl_CloneProc *cloneProc;
} Tcl_MethodType;

El campo version permite la expansión futura de la estructura y siempre debe declararse igual a TCL_OO_METHOD_VERSION_CURRENT. El campo name proporciona un nombre legible por humanos para el tipo y es el valor que se expone a través de los comandos Tcl info class methodtype e info object methodtype.

El campo callProc proporciona una función que se llama cuando se invoca el método; nunca debe ser NULL.

El campo deleteProc proporciona una función que se utiliza para eliminar un método específico y se llama cuando el método se reemplaza o elimina; si el campo es NULL, se asume que el clientData del método no necesita ninguna acción especial para eliminarse.

El campo cloneProc es una función que se utiliza para copiar el clientData de un método (como parte de Tcl_CopyObjectInstance) o NULL para indicar que el clientData se puede copiar directamente.

FIRMA DE FUNCIÓN TCL_METHODCALLPROC

La función de llamada a método debe tener la siguiente firma:

typedef int (*Tcl_MethodCallProc)(
    void *clientData,
    Tcl_Interp *interp,
    int objc,
    Tcl_Obj *const objv[]
);

Los argumentos son los mismos que se pasan a Tcl_ObjectContextInvokeNext, pero el marco de contexto se elimina automáticamente. El valor de retorno debe ser un código de resultado Tcl estándar (TCL_OK o un código de error).

FIRMA DE FUNCIÓN TCL_METHODDELETEPROC

La función de eliminación de método debe tener la siguiente firma:

typedef void (*Tcl_MethodDeleteProc)(
    void *clientData
);

Se llama a esta función cuando se elimina el método.

FIRMA DE FUNCIÓN TCL_CLONEPROC

La función de clonación de método debe tener la siguiente firma:

typedef void *(*Tcl_CloneProc)(
    void *clientData
);

Se llama a esta función cuando se clona un objeto que contiene el método. La función debe devolver un puntero a una copia del clientData.

NAME

Tcl_ObjectContextMethod - TclOO method invocation, deletion, and cloning

SYNOPSIS

#include <tclOO.h>

typedef int
Tcl_MethodCallProc(
        ClientData clientData,
        Tcl_Interp *interp,
        Tcl_ObjectContext objectContext,
        int objc,
        Tcl_Obj *const *objv);

typedef void
Tcl_MethodDeleteProc(
        ClientData clientData);

typedef int
Tcl_CloneProc(
        Tcl_Interp *interp,
        ClientData oldClientData,
        ClientData *newClientDataPtr);

ARGUMENTS

clientData
Arbitrary data associated with the method.
interp
The interpreter in which the method is invoked.
objectContext
The context in which the method is invoked.
objc
The number of arguments passed to the method.
objv
The arguments passed to the method, as Tcl objects.
oldClientData
The clientData of the method being copied.
newClientDataPtr
A pointer to where the clientData for the new method should be stored.

DESCRIPTION

The TclOO object system provides mechanisms for defining and managing methods. The types Tcl_MethodCallProc, Tcl_MethodDeleteProc, and Tcl_CloneProc define the signatures of the callback procedures that are invoked when a method is called, deleted, or cloned, respectively.

TCL_METHODCALLPROC FUNCTION SIGNATURE

Functions matching this signature are called when the method is invoked.

typedef int Tcl_MethodCallProc(
        ClientData clientData,
        Tcl_Interp *interp,
        Tcl_ObjectContext objectContext,
        int objc,
        Tcl_Obj *const *objv);

The clientData argument to a Tcl_MethodCallProc is the value that was given when the method was created, the interp is a place in which to execute scripts and access variables as well as being where to put the result of the method, and the objc and objv fields give the parameter objects to the method. The calling context of the method can be discovered through the objectContext argument, and the return value from a Tcl_MethodCallProc is any Tcl return code (e.g. TCL_OK, TCL_ERROR).

TCL_METHODDELETEPROC FUNCTION SIGNATURE

Functions matching this signature are used when a method is deleted, whether through a new method being created or because the object or class is deleted.

typedef void Tcl_MethodDeleteProc(
        ClientData clientData);

The clientData argument to a Tcl_MethodDeleteProc will be the same as the value passed to the clientData argument to Tcl_NewMethod or Tcl_NewInstanceMethod when the method was created.

TCL_CLONEPROC FUNCTION SIGNATURE

Functions matching this signature are used to copy a method when the object or class is copied using Tcl_CopyObjectInstance (or oo::copy).

typedef int Tcl_CloneProc(
        Tcl_Interp *interp,
        ClientData oldClientData,
        ClientData *newClientDataPtr);

The interp argument gives a place to write an error message when the attempt to clone the object is to fail, in which case the clone procedure must also return TCL_ERROR; it should return TCL_OK otherwise. The oldClientData field to a Tcl_CloneProc gives the value from the method being copied from, and the newClientDataPtr field will point to a variable in which to write the value for the method being copied to.
