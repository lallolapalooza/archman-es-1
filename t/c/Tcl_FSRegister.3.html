DESCRIPCIÓN

The Tcl filesystem interface allows Tcl scripts to interact with arbitrary filesystems. It is possible to implement new filesystems that can be transparently used by Tcl scripts. The interface is based around the concept of a Tcl_Filesystem structure, which contains pointers to procedures that perform the various filesystem operations.

The following procedures are provided by the Tcl library:

Tcl_FSRegister
Registers a new filesystem with Tcl. The fsPtr argument points to a Tcl_Filesystem structure containing the addresses of procedures that can be called to perform the various filesystem operations. The clientData argument is arbitrary data that will be passed to the filesystem's procedures. Returns 0 on success, otherwise returns an error code.
Tcl_FSUnregister
Unregisters a filesystem. The fsPtr argument is the same pointer that was passed to Tcl_FSRegister. Returns 0 on success, otherwise returns an error code.
Tcl_FSData
Returns the clientData value associated with the filesystem fsPtr.
Tcl_FSMountsChanged
Notifies Tcl that the mounts managed by the filesystem fsPtr have changed. Tcl will invalidate any cached information about paths within that filesystem.
Tcl_FSGetFileSystemForPath
Returns a pointer to the Tcl_Filesystem structure that manages the path specified by pathPtr. If the path is not managed by any registered filesystem, NULL is returned.
Tcl_FSGetPathType
Returns the type of the path specified by pathPtr. The return value is one of TCL_PATH_RELATIVE, TCL_PATH_ABSOLUTE, or TCL_PATH_ABSOLUTE_RELATIVE.
Tcl_FSCopyFile
Copies the file specified by srcPathPtr to the location specified by destPathPtr. Returns 0 on success, otherwise returns an error code.
Tcl_FSCopyDirectory
Recursively copies the directory specified by srcPathPtr to the location specified by destPathPtr. If errorPtr is not NULL, it is filled with a value containing the name of the file that caused an error. Returns 0 on success, otherwise returns an error code.
Tcl_FSCreateDirectory
Creates a new directory at the location specified by pathPtr. Returns 0 on success, otherwise returns an error code.
Tcl_FSDeleteFile
Deletes the file specified by pathPtr. Returns 0 on success, otherwise returns an error code.
Tcl_FSRemoveDirectory
Removes the directory specified by pathPtr. If recursive is true, the directory and all its contents are removed. If errorPtr is not NULL, it is filled with a value containing the name of the file that caused an error. Returns 0 on success, otherwise returns an error code.
Tcl_FSRenameFile
Renames the file specified by srcPathPtr to the name specified by destPathPtr. Returns 0 on success, otherwise returns an error code.
Tcl_FSListVolumes
Returns a list of all available volumes, where each volume is represented by an object containing the volume name.
Tcl_FSEvalFileEx
Reads the contents of the file specified by pathPtr, evaluates them as Tcl commands, and returns the result. The encodingName parameter specifies the encoding of the file's contents. Returns 0 on success, otherwise returns an error code.
Tcl_FSEvalFile
Equivalent to Tcl_FSEvalFileEx, but uses the default encoding.
Tcl_FSLoadFile
Loads a shared library file specified by pathPtr. The sym1 and sym2 arguments specify the names of procedures to look up in the library's symbol table. The proc1Ptr and proc2Ptr arguments are filled with pointers to the found procedures. The clientDataPtr argument is filled with a value that will be passed to the unload procedure. The loadHandlePtr argument is filled with an abstract token representing the loaded file. The unloadProcPtr argument is filled with the procedure to call to unload the file. Returns 0 on success, otherwise returns an error code.
Tcl_FSUnloadFile
Unloads a shared library previously loaded with Tcl_FSLoadFile. The loadHandle argument is the token returned by Tcl_FSLoadFile. Returns 0 on success, otherwise returns an error code.
Tcl_FSMatchInDirectory
Searches the directory specified by pathPtr for files and/or directories that match the glob pattern. The types parameter can be used to restrict the match to specific types of files or directories. The results are appended to the resultPtr list. Returns 0 on success, otherwise returns an error code.
Tcl_FSLink
Creates a symbolic link named linkNamePtr that points to toPtr. The linkAction argument specifies whether to create a symbolic link or a hard link.
Tcl_FSLstat
Like Tcl_FSStat, except that if the path is a symbolic link, then information about the link itself is returned, rather than information about the file it references.
Tcl_FSUtime
Sets the access and modification times for the file specified by pathPtr using the times in the tval structure.
Tcl_FSFileAttrsGet
Returns the value of the file attribute specified by index for the file specified by pathPtr. The result is stored in objPtrRef.
Tcl_FSFileAttrsSet
Sets the file attribute specified by index for the file specified by pathPtr to the value in objPtr.
Tcl_FSFileAttrStrings
Returns a table of strings describing the file attributes supported by the filesystem that manages pathPtr.
Tcl_FSStat
Returns information about the file specified by pathPtr in the statPtr structure. This is similar to the POSIX stat() function.
Tcl_FSAccess
Checks for the existence and accessibility of the file specified by pathPtr according to the mode specified by mode. Returns 0 if access is allowed, otherwise returns an error code.
Tcl_FSOpenFileChannel
Opens the file specified by pathPtr for access according to modeString. The permissions argument specifies the file permissions to use if a new file is created. Returns a channel handle on success, otherwise returns NULL.
Tcl_FSGetCwd
Returns the current working directory as a Tcl object.
Tcl_FSChdir
Changes the current working directory to the directory specified by pathPtr.
Tcl_FSPathSeparator
Returns the path separator character used by the filesystem that manages pathPtr.
Tcl_FSJoinPath
Joins the elements in the list listObj into a single path. If elements is negative, all elements are joined. Returns the resulting path as a Tcl object.
Tcl_FSSplitPath
Splits the path specified by pathPtr into a list of path elements. The number of elements is stored in lenPtr. Returns the list of elements as a Tcl object.
Tcl_FSEqualPaths
Compares two paths, firstPtr and secondPtr, for equality. Returns 1 if the paths are equal, 0 otherwise.
Tcl_FSGetNormalizedPath
Returns a normalized version of the path specified by pathPtr. Normalization involves resolving symbolic links, removing redundant path separators, and converting the path to its canonical form.
Tcl_FSJoinToPath
Joins a base path, specified by basePtr, with one or more additional path elements, specified by objc and objv. Returns the resulting path as a Tcl object.
Tcl_FSConvertToPathType
Ensures that the path specified by pathPtr has a native path representation.
Tcl_FSGetInternalRep
Returns the internal representation of the path specified by pathPtr for the filesystem specified by fsPtr.
Tcl_FSGetTranslatedPath
Returns a translated version of the path specified by pathPtr. Translation may involve converting the path to a native representation or performing other filesystem-specific transformations.
Tcl_FSGetTranslatedStringPath
Returns a string representation of the translated path specified by pathPtr.
Tcl_FSNewNativePath
Creates a new Tcl object representing a native path. The fsPtr argument specifies the filesystem for which the path is intended, and clientData provides the native representation of the path.
Tcl_FSGetNativePath
Returns the native representation of the path specified by pathPtr.
Tcl_FSFileSystemInfo
Returns information about the filesystem that manages the path specified by pathPtr.
Tcl_AllocStatBuf
Allocates and returns a buffer for use with stat-like functions.
Tcl_GetAccessTimeFromStat
Extracts the access time from a statPtr buffer.
Tcl_GetBlockSizeFromStat
Extracts the block size from a statPtr buffer.
Tcl_GetBlocksFromStat
Extracts the number of blocks allocated to the file from a statPtr buffer.
Tcl_GetChangeTimeFromStat
Extracts the change time from a statPtr buffer.
Tcl_GetDeviceTypeFromStat
Extracts the device type from a statPtr buffer.
Tcl_GetFSDeviceFromStat
Extracts the filesystem device ID from a statPtr buffer.
Tcl_GetFSInodeFromStat
Extracts the filesystem inode number from a statPtr buffer.
Tcl_GetGroupIdFromStat
Extracts the group ID from a statPtr buffer.
Tcl_GetLinkCountFromStat
Extracts the link count from a statPtr buffer.
Tcl_GetModeFromStat
Extracts the mode from a statPtr buffer.
Tcl_GetModificationTimeFromStat
Extracts the modification time from a statPtr buffer.
Tcl_GetSizeFromStat
Extracts the size from a statPtr buffer.
Tcl_GetUserIdFromStat
Extracts the user ID from a statPtr buffer.

DESCRIPCIÓN

Hay varias razones para llamar a las funciones de la API Tcl_FS (por ejemplo, Tcl_FSAccess y Tcl_FSStat) en lugar de llamar directamente a funciones de nivel de sistema como access y stat. Primero, funcionan multiplataforma, por lo que una extensión que las llama debería funcionar sin modificaciones en Unix y Windows. Segundo, la implementación de Windows de algunas de estas funciones corrige algunos errores en las llamadas de nivel de sistema. Tercero, estas llamadas a funciones manejan cualquier conversión de ruta de “Utf a nativo de plataforma” que pueda ser necesaria (y puede almacenar en caché los resultados de dichas conversiones para una mayor eficiencia en llamadas posteriores). Cuarto, y quizás lo más importante, todas estas funciones son “conscientes del sistema de archivos virtual”. Cualquier sistema de archivos virtual (VFS, por sus siglas en inglés) que se haya registrado (a través de Tcl_FSRegister) puede redirigir el acceso a archivos a medios o métodos de acceso alternativos. Esto significa que todas estas funciones (y, por lo tanto, los comandos de Tcl correspondientes file, glob, pwd, cd, open, etc.) pueden operar sobre “archivos” que no son archivos nativos en el sistema de archivos nativo. Esto también significa que cualquier extensión de Tcl que acceda al sistema de archivos (FS, por sus siglas en inglés) a través de esta API es automáticamente “consciente del sistema de archivos virtual”. Por supuesto, si una extensión accede directamente al sistema de archivos nativo (a través de APIs específicas de la plataforma, por ejemplo), Tcl no puede interceptar tales llamadas.

Si se han registrado VFS apropiados, los “archivos” pueden ser, para dar dos ejemplos, remotos (por ejemplo, situados en un servidor ftp remoto) o archivados (por ejemplo, dentro de un archivo .zip). Dichos sistemas de archivos registrados proporcionan una tabla de búsqueda de funciones para implementar toda o parte de la funcionalidad que se enumera aquí. Finalmente, las llamadas Tcl_FSStat y Tcl_FSLstat abstraen el búfer “struct stat” de cómo se declara realmente, lo que permite utilizar el mismo código tanto en sistemas con como sin soporte para archivos mayores de 2 GB de tamaño.

La API Tcl_FS está **Tcl_Obj**-ificada y puede almacenar en caché representaciones internas y otras cadenas relacionadas con rutas (por ejemplo, el directorio de trabajo actual). Un efecto secundario de esto es que no se deben pasar valores con un recuento de referencias de cero a ninguna de estas funciones. Si tales llamadas se manejaran, podrían resultar en fugas de memoria (en algunas circunstancias, el código del sistema de archivos puede desear retener una referencia al valor pasado, y por lo tanto no se puede asumir que después de que cualquiera de estas llamadas regrese, el valor aún tiene un recuento de referencias de cero; puede haber sido incrementado) o en un fallo de segmentación directo (u otro error de acceso a memoria) debido a que el valor se libera a mitad de la manipulación compleja de valores necesaria para garantizar que la ruta se normalice completamente y sea absoluta para la determinación del sistema de archivos. La lección práctica que se aprende de esto es que

Tcl_Obj *path = Tcl_NewStringObj(...);
Tcl_FSWhatever(path);
Tcl_DecrRefCount(path);

es incorrecto y puede causar errores de memoria. El recuento de referencias de path debe incrementarse antes de pasarlo, o decrementarlo. Por esta razón, los valores con un recuento de referencias de cero se consideran rutas de sistema de archivos no válidas y llamar a cualquier función de la API Tcl_FS con dicho valor no tendrá ningún efecto.

FUNCIONES API FS

Tcl_FSCopyFile intenta copiar el archivo dado por srcPathPtr a la ruta dada por destPathPtr. Si las dos rutas dadas se encuentran en el mismo sistema de archivos (según Tcl_FSGetFileSystemForPath), se llama a la función “copiar archivo” de ese sistema de archivos (si no es NULL). De lo contrario, la función devuelve -1 y establece la variable global C **errno** al código de error POSIX “EXDEV” (que significa un “enlace entre dominios”).

Tcl_FSCopyDirectory intenta copiar el directorio dado por srcPathPtr a la ruta dada por destPathPtr. Si las dos rutas dadas se encuentran en el mismo sistema de archivos (según Tcl_FSGetFileSystemForPath), se llama a la función “copiar archivo” de ese sistema de archivos (si no es NULL). De lo contrario, la función devuelve -1 y establece la variable global C **errno** al código de error POSIX “EXDEV” (que significa un “enlace entre dominios”).

Tcl_FSCreateDirectory intenta crear el directorio dado por pathPtr llamando a la función “crear directorio” del sistema de archivos propietario.

Tcl_FSDeleteFile intenta eliminar el archivo dado por pathPtr llamando a la función “eliminar archivo” del sistema de archivos propietario.

Tcl_FSRemoveDirectory intenta eliminar el directorio dado por pathPtr llamando a la función “eliminar directorio” del sistema de archivos propietario.

Tcl_FSRenameFile intenta renombrar el archivo o directorio dado por srcPathPtr a la ruta dada por destPathPtr. Si las dos rutas dadas se encuentran en el mismo sistema de archivos (según Tcl_FSGetFileSystemForPath), se llama a la función “renombrar archivo” de ese sistema de archivos (si no es NULL). De lo contrario, la función devuelve -1 y establece la variable global C **errno** al código de error POSIX “EXDEV” (que significa un “enlace entre dominios”).

Tcl_FSListVolumes llama a cada sistema de archivos que tiene una función “listar volúmenes” no NULL y les pide que devuelvan su lista de volúmenes raíz. Acumula los valores de retorno en una lista que se devuelve al llamador (con un recuento de referencias de 0).

Tcl_FSEvalFileEx lee el archivo dado por pathPtr utilizando la codificación identificada por encodingName y evalúa su contenido como un script de Tcl. Devuelve la misma información que Tcl_EvalObjEx. Si encodingName es NULL, se utiliza la codificación del sistema para leer el contenido del archivo. Si el archivo no se pudo leer, se devuelve un error de Tcl para describir por qué no se pudo leer el archivo. El carácter eof para los archivos es “\x1A” (^Z) para todas las plataformas. Si necesita un “^Z” en el código para comparación de cadenas, puede usar “\x1A”, que será sustituido de forma segura por el intérprete de Tcl por “^Z”. Tcl_FSEvalFile es una versión más simple de Tcl_FSEvalFileEx que siempre utiliza la codificación del sistema al leer el archivo.

Tcl_FSLoadFile carga dinámicamente un archivo de código binario en memoria y devuelve las direcciones de dos procedimientos dentro de ese archivo, si están definidos. Se llamará a la función apropiada para el sistema de archivos al que pertenece pathPtr. Si ese sistema de archivos no implementa esta función (la mayoría de los sistemas de archivos virtuales no lo harán, debido a limitaciones del sistema operativo en la carga dinámica de código binario), Tcl intentará copiar el archivo a un directorio temporal y cargar ese archivo temporal. Tcl_FSUnloadFile invierte la operación, solicitando que la biblioteca indicada por loadHandle se elimine del proceso. Tenga en cuenta que, a diferencia del comando **unload**, esto no da a la biblioteca ninguna oportunidad de realizar limpieza.

Ambas funciones anteriores devuelven un código de finalización estándar de Tcl. Si ocurre un error, se deja un mensaje de error en el resultado del interp.

El token proporcionado a través de la variable indicada por loadHandlePtr puede usarse con Tcl_FindSymbol.

Tcl_FSMatchInDirectory es utilizado por el código de globbing para buscar en un directorio todos los archivos que coincidan con un patrón dado. Se llamará a la función apropiada para el sistema de archivos al que pertenece pathPtr.

FILESYSTEM INFRASTRUCTURE

These fields contain basic information about the filesystem structure and addresses of functions which are used to associate a particular filesystem with a file path, and deal with the internal handling of path representations, for example copying and freeing such representations.

TYPENAME

The typeName field contains a null-terminated string that identifies the type of the filesystem implemented, e.g. “native”, “zip” or “vfs”.

STRUCTURE LENGTH

The structureLength field is generally implemented as sizeof(Tcl_Filesystem), and is there to allow easier binary backwards compatibility if the size of the structure changes in a future Tcl release.

VERSION

The version field should be set to TCL_FILESYSTEM_VERSION_1.

PATHINFILESYSTEMPROC

The pathInFilesystemProc field contains the address of a function which is called to determine whether a given path value belongs to this filesystem or not. Tcl will only call the rest of the filesystem functions with a path for which this function has returned TCL_OK. If the path does not belong, -1 should be returned (the behavior of Tcl for any other return value is not defined). If TCL_OK is returned, then the optional clientDataPtr output parameter can be used to return an internal (filesystem specific) representation of the path, which will be cached inside the path value, and may be retrieved efficiently by the other filesystem functions. Tcl will simultaneously cache the fact that this path belongs to this filesystem. Such caches are invalidated when filesystem structures are added or removed from Tcl's internal list of known filesystems.

typedef int Tcl_FSPathInFilesystemProc(
        Tcl_Obj *pathPtr,
        ClientData *clientDataPtr);

DUPINTERNALREPPROC

This function makes a copy of a path's internal representation, and is called when Tcl needs to duplicate a path value. If NULL, Tcl will simply not copy the internal representation, which may then need to be regenerated later.

typedef ClientData Tcl_FSDupInternalRepProc(
        ClientData clientData);

Free the internal representation. This must be implemented if internal representations need freeing (i.e. if some memory is allocated when an internal representation is generated), but may otherwise be NULL.

typedef void Tcl_FSFreeInternalRepProc(
        ClientData clientData);

Function to convert internal representation to a normalized path. Only required if the filesystem creates pure path values with no string/path representation. The return value is a Tcl value whose string representation is the normalized path.

typedef Tcl_Obj *Tcl_FSInternalToNormalizedProc(
        ClientData clientData);

CREATEINTERNALREPPROC

Function to take a path value, and calculate an internal representation for it, and store that native representation in the value. May be NULL if paths have no internal representation, or if the Tcl_FSPathInFilesystemProc for this filesystem always immediately creates an internal representation for paths it accepts.

typedef ClientData Tcl_FSCreateInternalRepProc(
        Tcl_Obj *pathPtr);

NORMALIZEPATHPROC

Function to normalize a path. Should be implemented for all filesystems which can have multiple string representations for the same path value. In Tcl, every “path” must have a single unique “normalized” string representation. Depending on the filesystem, there may be more than one unnormalized string representation which refers to that path (e.g. a relative path, a path with different character case if the filesystem is case insensitive, a path contain a reference to a home directory such as “~”, a path containing symbolic links, etc). If the very last component in the path is a symbolic link, it should not be converted into the value it points to (but its case or other aspects should be made unique). All other path components should be converted from symbolic links. This one exception is required to agree with Tcl's semantics with file delete, file rename, file copy operating on symbolic links. This function may be called with nextCheckpoint either at the beginning of the path (i.e. zero), at the end of the path, or at any intermediate file separator in the path. It will never point to any other arbitrary position in the path. In the last of the three valid cases, the implementation can assume that the path up to and including the file separator is known and normalized.

typedef int Tcl_FSNormalizePathProc(
        Tcl_Interp *interp,
        Tcl_Obj *pathPtr,
        int nextCheckpoint);

The fields in this section of the structure contain addresses of functions which are called to carry out the basic filesystem operations. A filesystem which expects to be used with the complete standard Tcl command set must implement all of these. If some of them are not implemented, then certain Tcl commands may fail when operating on paths within that filesystem. However, in some instances this may be desirable (for example, a read-only filesystem should not implement the last four functions, and a filesystem which does not support symbolic links need not implement the readlink function, etc. The Tcl core expects filesystems to behave in this way).

        Tcl_Obj *pathPtr,
        Tcl_StatBuf *statPtr);

The Tcl_FSStatProc fills the stat structure statPtr with information about the specified file. You do not need any access rights to the file to get this information but you need search rights to all directories named in the path leading to the file. The stat structure includes info regarding device, inode (always 0 on Windows), privilege mode, nlink (always 1 on Windows), user id (always 0 on Windows), group id (always 0 on Windows), rdev (same as device on Windows), size, last access time, last modification time, and last metadata change time.

DESCRIPCIÓN

Estos procedimientos son utilizados por el sistema de archivos virtual (VFS) de Tcl para implementar la funcionalidad de manejo de archivos de Tcl. Normalmente, los desarrolladores de extensiones de Tcl que definen su propio sistema de archivos virtual implementarán un subconjunto de estas funciones. Las funciones de la biblioteca de Tcl como Tcl_FSCreateDirectory, Tcl_FSRemoveDirectory, etc., se dirigen a la implementación adecuada de un sistema de archivos registrado.

CREATEFILEPROC

Procedimiento para procesar una llamada a Tcl_FSCreateFile. Debe ser implementado a menos que el FS sea de solo lectura.

typedef Tcl_Channel Tcl_FSCreateFileProc(
        Tcl_Interp *interp,
        Tcl_Obj *pathPtr,
        Tcl_OpenMode mode,
        int permissions);

El valor de retorno es un canal Tcl abierto al archivo especificado por pathPtr en el modo especificado por mode. Si ocurre un error, el valor de retorno es NULL y se deja un mensaje de error en el resultado del intérprete.

OPENDIRPROC

Procedimiento para procesar una llamada a Tcl_FSOpenDirectory. Debe ser implementado a menos que el FS no soporte operaciones de directorio.

typedef Tcl_Dir *Tcl_FSOpenDirProc(
        Tcl_Interp *interp,
        Tcl_Obj *pathPtr);

El valor de retorno es un puntero a una estructura opaca Tcl_Dir que representa el directorio abierto. Si ocurre un error, el valor de retorno es NULL y se deja un mensaje de error en el resultado del intérprete.

READDIRPROC

Procedimiento para procesar una llamada a Tcl_FSReadDirectory. Debe ser implementado si openDirProc es implementado.

typedef Tcl_Obj *Tcl_FSReadDirProc(
        Tcl_Interp *interp,
        Tcl_Dir *dirPtr);

El valor de retorno es un Tcl_Obj que contiene el nombre del siguiente archivo o subdirectorio en el directorio. El orden es específico del sistema de archivos. Si no hay más entradas, se devuelve NULL. Si ocurre un error, se devuelve NULL y se deja un mensaje de error en el resultado del intérprete.

CLOSEDIRPROC

Procedimiento para procesar una llamada a Tcl_FSCloseDirectory. Debe ser implementado si openDirProc es implementado.

typedef int Tcl_FSCloseDirProc(
        Tcl_Interp *interp,
        Tcl_Dir *dirPtr);

Cierra el directorio representado por dirPtr. El valor de retorno es un código de resultado estándar de Tcl.

STATPROC

Procedimiento para procesar una llamada a Tcl_FSStat. Este procedimiento debe ser implementado por todos los sistemas de archivos, ya que es necesario para la mayoría de las operaciones de archivos.

typedef int Tcl_FSStatProc(
        Tcl_Obj *pathPtr,
        Tcl_StatBuf *statPtr);

El valor de retorno es un código de resultado estándar de Tcl. El argumento statPtr debe llenarse con información sobre el archivo o directorio especificado por pathPtr.

LISTFILESYSDIRPROC

Procedimiento para procesar una llamada a Tcl_FSListFilesys. Este procedimiento es opcional; si es NULL, Tcl proporcionará una implementación predeterminada que utiliza Tcl_FSOpenDirectory, Tcl_FSReadDirectory y Tcl_FSCloseDirectory.

typedef Tcl_Obj *Tcl_FSListFilesysDirProc(
        Tcl_Interp *interp,
        Tcl_Obj *searchPath);

El valor de retorno es un Tcl_Obj que representa una lista de todos los sistemas de archivos disponibles en el sistema. Si ocurre un error, se devuelve NULL y se deja un mensaje de error en el resultado del intérprete.

GETNATIVEPATHPROC

Procedimiento para procesar una llamada a Tcl_FSGetNativePath. Este procedimiento es opcional; si es NULL, Tcl proporcionará una implementación predeterminada.

typedef Tcl_Obj *Tcl_FSGetNativePathProc(
        Tcl_Obj *pathPtr);

El valor de retorno es un Tcl_Obj que representa la ruta nativa del archivo o directorio especificado por pathPtr en el sistema de archivos subyacente. Si ocurre un error, se devuelve NULL.

GETSPECIALFILEPROC

Procedimiento para procesar una llamada a Tcl_FSSpecialFile. Este procedimiento es opcional.

typedef Tcl_Obj *Tcl_FSSpecialFileProc(
        Tcl_Obj *pathPtr);

El valor de retorno es un Tcl_Obj que representa la ruta especial de un archivo (por ejemplo, el archivo en sí mismo, o el enlace simbólico si corresponde). Si el archivo no es especial o si ocurre un error, se devuelve NULL.

CREATESYMLINKPROC

Procedimiento para procesar una llamada a Tcl_FSCreateSymbolicLink. Debe ser implementado si el sistema de archivos soporta enlaces simbólicos.

typedef int Tcl_FSCreateSymbolicLinkProc(
        Tcl_Obj *readAheadNamePtr,
        Tcl_Obj *linkNamePtr);

El valor de retorno es un código de resultado estándar de Tcl. Crea un enlace simbólico en la ubicación especificada por linkNamePtr que apunta a la ruta especificada por readAheadNamePtr.

READLINKPROC

Procedimiento para procesar una llamada a Tcl_FSReadSymbolicLink. Debe ser implementado si el sistema de archivos soporta enlaces simbólicos.

typedef Tcl_Obj *Tcl_FSReadLinkProc(
        Tcl_Interp *interp,
        Tcl_Obj *linkNamePtr);

El valor de retorno es un Tcl_Obj que contiene la ruta a la que apunta el enlace simbólico especificado por linkNamePtr. Si ocurre un error, se devuelve NULL y se deja un mensaje de error en el resultado del intérprete.

RENAMEFILEPROC

Procedimiento para procesar una llamada a Tcl_FSRenameFile. Debe ser implementado si el sistema de archivos soporta la renombra de archivos.

typedef int Tcl_FSRenameFileProc(
        Tcl_Obj *srcPathPtr,
        Tcl_Obj *destPathPtr);

El valor de retorno es un código de resultado estándar de Tcl. Renombra el archivo o directorio especificado por srcPathPtr a la ruta especificada por destPathPtr.

MAKEDIRECTORYPROC

Procedimiento para procesar una llamada a Tcl_FSMkdir. Este procedimiento es opcional; si es NULL, Tcl proporcionará una implementación predeterminada que utiliza Tcl_FSCreateDirectory.

typedef int Tcl_FSMkdirProc(
        Tcl_Obj *pathPtr);

El valor de retorno es un código de resultado estándar de Tcl. Crea un nuevo directorio en la ubicación especificada por pathPtr.

REMOVEDIRECTORYPROC

Procedimiento para procesar una llamada a Tcl_FSRemoveDirectory. Debe ser implementado a menos que el FS sea de solo lectura.

typedef int Tcl_FSRemoveDirectoryProc(
        Tcl_Obj *pathPtr,
        int recursive,
        Tcl_Obj **errorPtr);

El valor de retorno es un código de resultado estándar de Tcl. Si el flag recursive se proporciona, elimina un directorio no vacío sin error. Si el flag no se proporciona y el directorio no está vacío, se debe señalar un error POSIX "EEXIST". Si ocurre un error, el nombre del archivo o directorio que causó el error debe colocarse en errorPtr.

DELETEFILEPROC

Procedimiento para procesar una llamada a Tcl_FSDeleteFile. Debe ser implementado a menos que el FS sea de solo lectura.

typedef int Tcl_FSDeleteFileProc(
        Tcl_Obj *pathPtr);

El valor de retorno es un código de resultado estándar de Tcl. Elimina el archivo especificado por pathPtr.

EFICIENCIA DEL SISTEMA DE ARCHIVOS

Estas funciones no necesitan ser implementadas para un sistema de archivos particular, ya que el núcleo tiene una implementación de respaldo disponible. Consulte la descripción individual para conocer las consecuencias de dejar el campo NULL.

LSTATPROC

Procedimiento para procesar una llamada a Tcl_FSLstat. Si no se implementa, Tcl intentará usar statProc definido anteriormente en su lugar. Por lo tanto, solo necesita ser implementado si un sistema de archivos puede diferenciar entre llamadas stat y lstat.

typedef int Tcl_FSLstatProc(
        Tcl_Obj *pathPtr,
        Tcl_StatBuf *statPtr);

El comportamiento de esta función es muy similar al de Tcl_FSStatProc definido anteriormente, excepto que si se aplica a un enlace simbólico, devuelve información sobre el enlace, no sobre el archivo destino.

COPYFILEPROC

Procedimiento para procesar una llamada a Tcl_FSCopyFile. Si no se implementa, Tcl recurrirá a open-r, open-w y fcopy como mecanismo de copia. Por lo tanto, solo necesita ser implementado si el sistema de archivos puede realizar esa acción de manera más eficiente.

typedef int Tcl_FSCopyFileProc(
        Tcl_Obj *srcPathPtr,
        Tcl_Obj *destPathPtr);

El valor de retorno es un código de resultado estándar de Tcl. Tenga en cuenta que destPathPtr es el nombre del archivo que se convertirá en la copia de srcPathPtr. Nunca es el nombre de un directorio en el que srcPathPtr podría copiarse (es decir, la función es mucho más simple que el subcomando file copy a nivel de Tcl). Tenga en cuenta que, si el sistema de archivos soporta enlaces simbólicos, Tcl siempre llamará a esta función y no a copyDirectoryProc cuando sea necesario copiarlos (incluso si son enlaces simbólicos a directorios). Finalmente, si el sistema de archivos determina que no puede soportar la acción de file copy, llamar a Tcl_SetErrno(EXDEV) y devolver un resultado no TCL_OK le indicará a Tcl que utilice sus mecanismos de respaldo estándar.

RENAMEFILEPROC

Procedimiento para procesar una llamada a Tcl_FSRenameFile. Si no se implementa, Tcl recurrirá a un mecanismo de copia y eliminación. Por lo tanto, solo necesita ser implementado si el sistema de archivos puede realizar esa acción de manera más eficiente.

typedef int Tcl_FSRenameFileProc(
        Tcl_Obj *srcPathPtr,
        Tcl_Obj *destPathPtr);

El valor de retorno es un código de resultado estándar de Tcl. Si el sistema de archivos determina que no puede soportar la acción de file rename, llamar a Tcl_SetErrno(EXDEV) y devolver un resultado no TCL_OK le indicará a Tcl que utilice sus mecanismos de respaldo estándar.

COPYDIRECTORYPROC

Procedimiento para procesar una llamada a Tcl_FSCopyDirectory. Si no se implementa, Tcl recurrirá a un mecanismo recursivo de file mkdir, file copy. Por lo tanto, solo necesita ser implementado si el sistema de archivos puede realizar esa acción de manera más eficiente.

typedef int Tcl_FSCopyDirectoryProc(
        Tcl_Obj *srcPathPtr,
        Tcl_Obj *destPathPtr,
        Tcl_Obj **errorPtr);

El valor de retorno es un código de resultado estándar de Tcl. Si ocurre un error, el nombre del archivo o directorio que causó el error debe colocarse en errorPtr. Tenga en cuenta que destPathPtr es el nombre del directorio que se convertirá en la imagen especular de srcPathPtr. No es el nombre de un directorio en el que srcPathPtr deba copiarse (es decir, la función es mucho más simple que el subcomando file copy a nivel de Tcl). Finalmente, si el sistema de archivos determina que no puede soportar la acción de copia de directorios, llamar a Tcl_SetErrno(EXDEV) y devolver un resultado no TCL_OK le indicará a Tcl que utilice sus mecanismos de respaldo estándar.

LOADFILEPROC

Procedimiento para procesar una llamada a Tcl_FSLoadFile. Si no se implementa, Tcl recurrirá a una copia a un archivo temporal nativo seguida de una llamada a Tcl_FSLoadFile en esa copia temporal. Por lo tanto, solo necesita ser implementado si el sistema de archivos puede cargar código directamente, o puede implementarse simplemente para devolver TCL_ERROR para deshabilitar completamente la funcionalidad de carga en este sistema de archivos.

typedef int Tcl_FSLoadFileProc(
        Tcl_Interp *interp,
        Tcl_Obj *pathPtr,
        Tcl_LoadHandle *handlePtr,
        Tcl_FSUnloadFileProc *unloadProcPtr);

Devuelve un código de finalización estándar de Tcl. Si ocurre un error, se deja un mensaje de error en el resultado del interp. La función carga dinámicamente un archivo de código binario en memoria. En una carga exitosa, handlePtr debe llenarse con un token para el archivo cargado dinámicamente, y unloadProcPtr debe llenarse con la dirección de un procedimiento. El procedimiento de descarga se llamará con el Tcl_LoadHandle dado como único parámetro cuando Tcl necesite descargar el archivo. Por ejemplo, para el sistema de archivos nativo, el Tcl_LoadHandle devuelto es actualmente un token que se puede utilizar en el TclpFindSymbol privado para acceder a funciones en el nuevo código. Cada sistema de archivos es libre de definir el Tcl_LoadHandle como lo requiera. Finalmente, si el sistema de archivos determina que no puede soportar la acción de carga de archivos, llamar a Tcl_SetErrno(EXDEV) y devolver un resultado no TCL_OK le indicará a Tcl que utilice sus mecanismos de respaldo estándar.

UNLOADFILEPROC

Procedimiento para descargar un archivo cargado previamente con éxito. Si se implementó la carga, entonces esta también debe implementarse, si hay alguna acción de limpieza requerida.

typedef void Tcl_FSUnloadFileProc(
        Tcl_LoadHandle loadHandle);

GETCWDPROC

Procedimiento para procesar una llamada a Tcl_FSGetCwd. La mayoría de los sistemas de archivos no necesitan implementar esto. Por lo general, solo se llamará una vez, si getcwd se llama antes de chdir. Puede ser NULL.

typedef Tcl_Obj *Tcl_FSGetCwdProc(
        Tcl_Interp *interp);

Si el sistema de archivos soporta una noción nativa de directorio de trabajo actual (que quizás podría cambiar independientemente de Tcl), esta función debe devolver ese cwd como resultado, o NULL si no se pudo determinar el directorio actual (por ejemplo, el usuario no tiene los permisos apropiados en el directorio cwd). Si se devuelve NULL, se deja un mensaje de error en el resultado del interp.

CHDIRPROC

Procedimiento para procesar una llamada a Tcl_FSChdir. Si los sistemas de archivos no implementan esto, se emulará mediante una serie de verificaciones de acceso a directorios. De lo contrario, los sistemas de archivos virtuales que sí lo implementan solo necesitan responder con un resultado positivo si pathPtr es un directorio válido y accesible en su sistema de archivos. No necesitan recordar el resultado, ya que este se recordará automáticamente para su uso por Tcl_FSGetCwd. Los sistemas de archivos reales deben llevar a cabo la acción correcta (es decir, llamar a la API chdir del sistema correcta).

typedef int Tcl_FSChdirProc(
        Tcl_Obj *pathPtr);

El Tcl_FSChdirProc cambia el directorio de trabajo actual de la aplicación al valor especificado en pathPtr. La función devuelve -1 en caso de error o 0 en caso de éxito.
