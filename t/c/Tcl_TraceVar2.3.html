Tcl_TraceVar(3) Procedimientos de la biblioteca Tcl Tcl_TraceVar(3)

NOMBRE

Tcl_TraceVar, Tcl_TraceVar2, Tcl_UntraceVar, Tcl_UntraceVar2, Tcl_VarTraceInfo, Tcl_VarTraceInfo2 - monitorizar accesos a una variable

SINOPSIS

#include <tcl.h>

int
Tcl_TraceVar(interp, varName, flags, proc, clientData)

int
Tcl_TraceVar2(interp, name1, name2, flags, proc, clientData)

Tcl_UntraceVar(interp, varName, flags, proc, clientData)

Tcl_UntraceVar2(interp, name1, name2, flags, proc, clientData)

ClientData
Tcl_VarTraceInfo(interp, varName, flags, proc, prevClientData)

ClientData
Tcl_VarTraceInfo2(interp, name1, name2, flags, proc, prevClientData)

ARGUMENTOS

Tcl_Interp *interp (entrada)
Intérprete que contiene la variable.
const char *varName (entrada)
Nombre de la variable. Puede referirse a una variable escalar, a una variable de arreglo sin índice, o a una variable de arreglo con un índice entre paréntesis.
int flags (entrada)
Combinación OR de los valores TCL_TRACE_READS, TCL_TRACE_WRITES, TCL_TRACE_UNSETS, TCL_TRACE_ARRAY, TCL_GLOBAL_ONLY, TCL_NAMESPACE_ONLY, TCL_TRACE_RESULT_DYNAMIC y TCL_TRACE_RESULT_OBJECT. No todos los flags son utilizados por todos los procedimientos. Ver más abajo para más información.
Tcl_VarTraceProc *proc (entrada)
Procedimiento a invocar cada vez que ocurre una de las operaciones rastreadas.
ClientData clientData (entrada)
Valor arbitrario de una palabra para pasar a proc.
const char *name1 (entrada)
Nombre de la variable escalar o de arreglo (sin el índice del arreglo).
const char *name2 (entrada)
Para un rastreo en un elemento de un arreglo, indica el índice del elemento. Para rastreos en variables escalares o en arreglos completos, es NULL.
ClientData prevClientData (entrada)
Si no es NULL, indica el último valor devuelto por Tcl_VarTraceInfo o Tcl_VarTraceInfo2, por lo que esta llamada devolverá información sobre el siguiente rastreo. Si es NULL, esta llamada devolverá información sobre el primer rastreo.

DESCRIPCIÓN

Tcl_TraceVar permite a un procedimiento C monitorizar y controlar el acceso a una variable Tcl, de modo que el procedimiento C sea invocado cada vez que la variable se lea, se escriba o se elimine. Si el rastreo se crea con éxito, Tcl_TraceVar devuelve TCL_OK. Si ocurrió un error (por ejemplo, varName especifica un elemento de un arreglo, pero la variable real no es un arreglo) entonces se devuelve TCL_ERROR y se deja un mensaje de error en el resultado del intérprete.

El argumento flags para Tcl_TraceVar indica cuándo se invocará el procedimiento de rastreo y proporciona información para configurar el rastreo. Consiste en una combinación OR de cualquiera de los siguientes valores:

TCL_GLOBAL_ONLY
Normalmente, la variable se buscará en el nivel actual de llamada al procedimiento; si este bit está establecido, la variable se buscará en el nivel global, ignorando cualquier procedimiento activo.
TCL_NAMESPACE_ONLY
Normalmente, la variable se buscará en el nivel actual de llamada al procedimiento; si este bit está establecido, la variable se buscará en el espacio de nombres actual, ignorando cualquier procedimiento activo.
TCL_TRACE_READS
Invoca proc cada vez que se intenta leer la variable.
TCL_TRACE_WRITES
Invoca proc cada vez que se intenta modificar la variable.
TCL_TRACE_UNSETS
Invoca proc cada vez que se elimina la variable. Una variable puede ser eliminada ya sea explícitamente por un comando unset, o implícitamente cuando un procedimiento retorna (sus variables locales se eliminan automáticamente) o cuando se elimina el intérprete (todas las variables se eliminan automáticamente).
TCL_TRACE_ARRAY
Invoca proc cada vez que se invoca el comando array. Esto le da al procedimiento de rastreo la oportunidad de actualizar el arreglo antes de que se llamen array names o array get. Nótese que esto se llama antes de un array set, pero eso activará rastreos de escritura.
TCL_TRACE_RESULT_DYNAMIC
El resultado de invocar proc es una cadena asignada dinámicamente que será liberada por la biblioteca Tcl mediante una llamada a ckfree. No debe especificarse al mismo tiempo que TCL_TRACE_RESULT_OBJECT.
TCL_TRACE_RESULT_OBJECT
El resultado de invocar proc es un Tcl_Obj* (convertido a char*) con un recuento de referencias de al menos uno. La propiedad de esa referencia se transferirá al núcleo de Tcl para su liberación (cuando el núcleo haya terminado con él) mediante una llamada a Tcl_DecrRefCount. No debe especificarse al mismo tiempo que TCL_TRACE_RESULT_DYNAMIC.

Cada vez que ocurra una de las operaciones especificadas en la variable, se invocará proc. Debe tener argumentos y un resultado que coincidan con el tipo Tcl_VarTraceProc:

typedef char *Tcl_VarTraceProc(
        ClientData clientData,
        Tcl_Interp *interp,
        const char *name1,
        const char *name2,
        int flags);

Los parámetros clientData e interp tendrán los mismos valores que los pasados a Tcl_TraceVar cuando se creó el rastreo. ClientData típicamente apunta a una estructura de datos específica de la aplicación que describe qué hacer cuando se invoca proc. Name1 y name2 dan el nombre de la variable rastreada en el formato normal de dos partes (ver la descripción de Tcl_TraceVar2 a continuación para detalles). Flags es una combinación OR de bits que proporcionan varias piezas de información. Uno de los bits TCL_TRACE_READS, TCL_TRACE_WRITES, TCL_TRACE_ARRAY, o TCL_TRACE_UNSETS estará establecido en flags para indicar qué operación se está realizando en la variable. El bit TCL_GLOBAL_ONLY se establecerá cada vez que la variable que se está accediendo sea una global no accesible desde el nivel actual de llamada al procedimiento: el procedimiento de rastreo deberá pasar este flag de vuelta a procedimientos relacionados con variables como Tcl_GetVar si intenta acceder a la variable. El bit TCL_NAMESPACE_ONLY se establecerá cada vez que la variable que se está accediendo sea una del espacio de nombres no accesible desde el nivel actual de llamada al procedimiento: el procedimiento de rastreo deberá pasar este flag de vuelta a procedimientos relacionados con variables como Tcl_GetVar si intenta acceder a la variable. El bit TCL_TRACE_DESTROYED se establecerá en flags si el rastreo está a punto de ser destruido; esta información puede ser útil para proc para que pueda limpiar sus propias estructuras de datos internas (ver la sección TCL_TRACE_DESTROYED a continuación para más detalles). Finalmente, el bit TCL_INTERP_DESTROYED se establecerá si todo el intérprete está siendo destruido. Cuando este bit está establecido, proc debe ser especialmente cuidadoso con las cosas que hace (ver la sección TCL_INTERP_DESTROYED a continuación).

El valor de retorno del procedimiento de rastreo normalmente debería ser NULL; ver RETORNOS DE ERROR a continuación para obtener información sobre otras posibilidades.

Tcl_UntraceVar se puede usar para eliminar un rastreo. Si la variable especificada por interp, varName y flags tiene un rastreo establecido con flags, proc y clientData, entonces se elimina el rastreo correspondiente. Si no existe dicho rastreo, la llamada a Tcl_UntraceVar no tiene ningún efecto. Los mismos bits son válidos para flags que para las llamadas a Tcl_TraceVar.

Tcl_VarTraceInfo se puede usar para recuperar información sobre rastreos establecidos en una variable dada. El valor de retorno de Tcl_VarTraceInfo es el clientData asociado con un rastreo particular. El rastreo debe estar en la variable especificada por los argumentos interp, varName y flags (solo se usan los bits TCL_GLOBAL_ONLY y TCL_NAMESPACE_ONLY de flags; otros bits se ignoran) y su procedimiento de rastreo debe ser el mismo que el argumento proc. Si el argumento prevClientData es NULL, entonces el valor de retorno corresponde al primer rastreo coincidente (el creado más recientemente), o NULL si no hay ninguno coincidente.

Tcl_TraceVar2 y Tcl_UntraceVar2 son similares a Tcl_TraceVar y Tcl_UntraceVar, respectivamente, excepto que especifican la variable en dos partes. Name1 es el nombre de la variable escalar o el nombre del arreglo. Name2 es el índice del arreglo, o NULL si se está rastreando una variable escalar o un arreglo completo. Por ejemplo, si se rastrea la variable global `a(b)`, entonces `name1` sería `a` y `name2` sería `b`. Si se rastrea la variable global `scalar`, entonces `name1` sería `scalar` y `name2` sería NULL.

Tcl_VarTraceInfo2 es similar a Tcl_VarTraceInfo, excepto que especifica la variable en dos partes, name1 y name2, como se describe anteriormente para Tcl_TraceVar2.

RETORNOS DE ERROR

Si se produce un error (por ejemplo, varName o name1/name2 especifican un elemento de arreglo pero la variable real no es un arreglo, o flags contiene bits incompatibles), Tcl_TraceVar y Tcl_TraceVar2 devuelven TCL_ERROR y dejan un mensaje de error en el resultado del intérprete. De lo contrario, devuelven TCL_OK.

Si el procedimiento de rastreo proc devuelve un valor distinto de NULL, se interpreta como una cadena de reemplazo para la variable que se está leyendo o escribiendo. Si el procedimiento de rastreo devuelve un puntero a una cadena que no es NULL, entonces esa cadena se usa como el nuevo valor de la variable. Si el procedimiento de rastreo devuelve NULL, entonces la operación continúa normalmente (el valor no se cambia si se está leyendo, o se usa el valor proporcionado si se está escribiendo).

Si TCL_TRACE_RESULT_DYNAMIC se especificó en el argumento flags a Tcl_TraceVar o Tcl_TraceVar2, el procedimiento de rastreo debe devolver una cadena asignada dinámicamente que será liberada por el núcleo de Tcl. Si se especifica TCL_TRACE_RESULT_OBJECT, el procedimiento de rastreo debe devolver un Tcl_Obj* con un recuento de referencias de al menos uno, y el núcleo de Tcl tomará posesión de esa referencia.

Si se está eliminando una variable (es decir, se establece el bit TCL_TRACE_UNSETS), el procedimiento de rastreo puede devolver NULL. Si devuelve un valor distinto de NULL, ese valor se utiliza como el nuevo valor de la variable y la operación de eliminación se cancela.

TCL_TRACE_DESTROYED

Cuando se está eliminando un rastreo, ya sea por una llamada a Tcl_UntraceVar, Tcl_UntraceVar2 o porque el intérprete se está destruyendo, el bit TCL_TRACE_DESTROYED se establece en el argumento flags pasado al procedimiento de rastreo proc. Esto le da al procedimiento la oportunidad de limpiar sus propias estructuras de datos internas. Por ejemplo, si el procedimiento de rastreo ha asignado memoria dinámica para un determinado rastreo, puede liberar esa memoria cuando reciba el flag TCL_TRACE_DESTROYED.

TCL_INTERP_DESTROYED

Cuando se está destruyendo el intérprete completo, el bit TCL_INTERP_DESTROYED se establece en el argumento flags pasado al procedimiento de rastreo proc. En este punto, muchos objetos dentro del intérprete ya pueden haber sido destruidos. El procedimiento de rastreo debe ser extremadamente cuidadoso acerca de los objetos a los que intenta acceder. En particular, no debe intentar acceder a variables de Tcl (excepto quizás para leerlas) ni realizar ninguna operación que pueda invocar otros procedimientos de rastreo, ya que es posible que esos procedimientos ya hayan sido destruidos.

Tcl_VarTraceInfo

Tcl_VarTraceInfo, Tcl_TraceVar, Tcl_UntraceVar, Tcl_TraceVar2, Tcl_UntraceVar2, Tcl_VarTraceInfo2 - devolver información sobre los rastreos de variables.

SYNOPSIS

#include <tcl.h>

const char *
Tcl_VarTraceInfo(interp, varName, flags, proc, clientData, prevClientData);

int
Tcl_TraceVar(interp, varName, flags, proc, clientData);

int
Tcl_UntraceVar(interp, varName, flags, proc, clientData);

const char *
Tcl_VarTraceInfo2(interp, name1, name2, flags, proc, clientData, prevClientData);

int
Tcl_TraceVar2(interp, name1, name2, flags, proc, clientData);

int
Tcl_UntraceVar2(interp, name1, name2, flags, proc, clientData);

ARGUMENTS

interp (in)
El intérprete de Tcl en el que se establecerá o consultará el rastreo.
varName (in)
El nombre de la variable a rastrear.
name1 (in)
El primer componente del nombre de la variable. Para variables escalares, es el nombre de la variable. Para elementos de matriz, es el nombre de la matriz. Para todo el rastreo de matrices, es el nombre de la matriz.
name2 (in)
El segundo componente del nombre de la variable. Para variables escalares, es NULL. Para elementos de matriz, es el nombre del índice del elemento de matriz. Para todo el rastreo de matrices, es NULL.
flags (in)
Un OR a nivel de bits de las siguientes banderas:
TCL_TRACE_READ
Invoca el procedimiento de rastreo cuando se lee la variable.
TCL_TRACE_WRITES
Invoca el procedimiento de rastreo cuando se escribe la variable.
TCL_TRACE_UNSETS
Invoca el procedimiento de rastreo cuando se elimina la variable.
TCL_TRACE_ARRAYS
Invoca el procedimiento de rastreo cuando se accede a una matriz (para rastreos de toda la matriz).
TCL_TRACE_ARRAY_ELEMENTS
Invoca el procedimiento de rastreo cuando se accede a un elemento de matriz (para rastreos de elementos de matriz).
TCL_TRACE_PASSIVE
No invocar el procedimiento de rastreo en los accesos que ya han sido rastreados por otro procedimiento de rastreo. Esto es útil para registrar los accesos sin interferir con otros rastreos.
Tcl_TraceVar y Tcl_TraceVar2 solo admiten las marcas TCL_TRACE_READ, TCL_TRACE_WRITES y TCL_TRACE_UNSETS. Tcl_TraceVar2 y Tcl_VarTraceInfo2 también pueden usar TCL_TRACE_ARRAY_ELEMENTS y TCL_TRACE_ARRAYS para rastrear matrices enteras o elementos de matriz individuales, respectivamente. TCL_TRACE_PASSIVE se puede usar con cualquier tipo de rastreo.
proc (in)
El procedimiento de rastreo a invocar. Su prototipo es:
typedef const char * (Tcl_VarTraceProc)(
    ClientData clientData,
    Tcl_Interp *interp,
    const char *name1,
    const char *name2,
    int flags);
El argumento clientData es el mismo que el pasado a Tcl_TraceVar o Tcl_TraceVar2. El argumento name1 es el nombre de la variable (o el nombre de la matriz si name2 no es NULL). El argumento name2 es el nombre del elemento de la matriz (o NULL si no es un elemento de matriz). El argumento flags es el mismo que se pasó a Tcl_TraceVar o Tcl_TraceVar2, más algunas marcas adicionales descritas en las secciones below.
clientData (in)
Datos definidos por el usuario que se pasarán al procedimiento de rastreo cada vez que se invoque.
prevClientData (in)
Si no es NULL, entonces debe ser el valor de retorno de una llamada anterior a Tcl_VarTraceInfo o Tcl_VarTraceInfo2. En este caso, el nuevo valor de retorno corresponderá al siguiente rastreo coincidente después del cual cuyo clientData coincide con prevClientData, o NULL si no hay ningún rastreo que coincida con prevClientData o si no hay más rastreos coincidentes después de él. Este mecanismo permite recorrer todos los rastreos de una variable dada que tienen el mismo proc.

NOMBRES_DE_DOS_PARTES

Los procedimientos Tcl_TraceVar2, Tcl_UntraceVar2 y Tcl_VarTraceInfo2 son idénticos a Tcl_TraceVar, Tcl_UntraceVar y Tcl_VarTraceInfo, respectivamente, excepto que el nombre de la variable consta de dos partes. Name1 da el nombre de una variable escalar o matriz, y name2 da el nombre de un elemento dentro de una matriz. Cuando name2 es NULL, name1 puede contener un nombre de matriz y un nombre de elemento: si el nombre contiene un paréntesis abierto y termina con un paréntesis cerrado, entonces el valor entre los paréntesis se trata como un nombre de elemento (que puede tener cualquier valor de cadena) y los caracteres antes del primer paréntesis abierto se tratan como el nombre de una variable de matriz. Si name2 es NULL y name1 no se refiere a un elemento de matriz, significa que la variable es escalar o que el rastreo se establecerá en toda la matriz en lugar de en un elemento individual (ver RASTREOS_DE_TODA_LA_MATRIZ más adelante para más información).

ACCESO_A_VARIABLES_DURANTE_LOS_RASTREOS

Durante los rastreos de lectura, escritura y matrices, el procedimiento de rastreo puede leer, escribir o anular la variable rastreada usando Tcl_GetVar2, Tcl_SetVar2 y otros procedimientos. Mientras proc se está ejecutando, los rastreos se deshabilitan temporalmente para la variable, de modo que las llamadas a Tcl_GetVar2 y Tcl_SetVar2 no causarán que proc u otros procedimientos de rastreo se invoquen nuevamente. La deshabilitación solo ocurre para la variable cuyo procedimiento de rastreo está activo; los accesos a otras variables aún serán rastreados. Sin embargo, si una variable se anula durante un rastreo de lectura o escritura, se invocarán los rastreos de anulación.

Durante los rastreos de anulación, la variable ya ha sido completamente eliminada. Es posible que el procedimiento de rastreo lea o escriba la variable, pero esta será una nueva versión de la variable. Los rastreos no se deshabilitan durante los rastreos de anulación, como ocurre con los rastreos de lectura y escritura, pero los rastreos existentes se han eliminado de la variable antes de invocar cualquier procedimiento de rastreo. Si los procedimientos de rastreo establecen nuevos rastreos, estos se invocarán en los accesos a la variable por parte de los procedimientos de rastreo.

TIEMPO_DE_EJECUCIÓN_DE_LAS_DEVOLUCIONES_DE_LLAMADA

Cuando se ha especificado el rastreo de lectura para una variable, el procedimiento de rastreo se invocará cada vez que se lea el valor de la variable. Esto incluye los comandos Tcl set, la notación de $ en los comandos Tcl y las invocaciones de los procedimientos Tcl_GetVar y Tcl_GetVar2. Proc se invoca justo antes de que se devuelva el valor de la variable. Puede modificar el valor de la variable para afectar lo que devuelve el acceso rastreado. Si anula la variable, el acceso devolverá un error, como si la variable nunca hubiera existido.

Cuando se ha especificado el rastreo de escritura para una variable, el procedimiento de rastreo se invocará cada vez que se modifique el valor de la variable. Esto incluye los comandos set, los comandos que modifican variables como efectos secundarios (como catch y scan), y las llamadas a los procedimientos Tcl_SetVar y Tcl_SetVar2). Proc se invocará después de que se haya modificado el valor de la variable, pero antes de que se haya devuelto el nuevo valor de la variable. Puede modificar el valor de la variable para anular el cambio y determinar el valor que realmente devuelve el acceso rastreado. Si elimina la variable, el acceso rastreado devolverá una cadena vacía.

Cuando se ha especificado el rastreo de matrices, el procedimiento de rastreo se invocará al inicio de la implementación del comando de matriz, antes de que se invoquen operaciones como get, set o names. El procedimiento de rastreo puede modificar los elementos de la matriz con Tcl_SetVar y Tcl_SetVar2.

Cuando se ha especificado el rastreo de anulación, el procedimiento de rastreo se invocará cada vez que se destruya la variable. Las llamadas de rastreo se realizarán después de que la variable se haya anulado por completo.

RASTREOS_DE_TODA_LA_MATRIZ

Si una llamada a Tcl_TraceVar o Tcl_TraceVar2 especifica el nombre de una variable de matriz sin un índice en la matriz, entonces el rastreo se establecerá en la matriz en su conjunto. Esto significa que proc se invocará cada vez que se acceda a cualquier elemento de la matriz de las maneras especificadas por flags. Cuando se anula una matriz, se invocará un rastreo de toda la matriz solo una vez, con name1 igual al nombre de la matriz y name2 NULL; no se invocará una vez por cada elemento.

RASTREOS_MÚLTIPLES

Es posible que existan varios rastreos en la misma variable. Cuando esto sucede, todos los procedimientos de rastreo se invocarán en cada acceso, en orden desde el más recientemente creado hasta el menos recientemente creado. Cuando existen rastreos de toda la matriz para una matriz, así como rastreos en elementos individuales, los rastreos de toda la matriz se invocan antes que los rastreos de elementos individuales. Si un rastreo de lectura o escritura anula la variable, se invocarán todos los rastreos de anulación, pero se omitirán los rastreos de lectura y escritura restantes.

VALORES_DE_RETORNO_DE_ERROR

En condiciones normales, los procedimientos de rastreo deben devolver NULL, lo que indica una finalización exitosa. Si proc devuelve un valor distinto de NULL, significa que ocurrió un error. El valor de retorno debe ser un puntero a una cadena de caracteres estática que contenga un mensaje de error, a menos que (exactamente una de) las marcas TCL_TRACE_RESULT_DYNAMIC y TCL_TRACE_RESULT_OBJECT estén establecidas, que especifican que el resultado es una cadena dinámica (que se liberará con ckfree) o un Tcl_Obj* (convertido a char* y que se liberará con Tcl_DecrRefCount) que contiene el mensaje de error. Si un procedimiento de rastreo devuelve un error, no se invocarán más rastreos para el acceso y el acceso rastreado se abortará con el mensaje dado. Los procedimientos de rastreo pueden usar esta instalación para hacer que las variables no se puedan escribir, por ejemplo (pero tenga en cuenta que el valor de la variable ya se habrá modificado antes de que se llame al procedimiento de rastreo, por lo que el procedimiento de rastreo tendrá que restaurar el valor correcto).

El valor de retorno de proc solo se utiliza durante los rastreos de lectura y escritura. Durante los rastreos de anulación, el valor de retorno se ignora y todos los procedimientos de rastreo relevantes siempre se invocarán.

RESTRICCIONES

Un procedimiento de rastreo puede ser llamado en cualquier momento, incluso cuando hay resultados parcialmente formados almacenados en el intérprete. Si el procedimiento de rastreo hace algo que pueda dañar este resultado (como llamar a Tcl_Eval), debe usar las rutinas Tcl_SaveInterpState y relacionadas para guardar y restaurar el estado original del intérprete antes de devolver.

VARIABLES_NO_DEFINIDAS

Es legal establecer un rastreo en una variable no definida. La variable todavía parecerá no definida hasta la primera vez que se establezca su valor. Si se rastrea una variable no definida y luego se anula, la anulación fallará con un error ("no existe tal variable"), pero el procedimiento de rastreo se invocará de todos modos.

MARCA_TCL_TRACE_DESTROYED

En una devolución de llamada de anulación a proc, el bit TCL_TRACE_DESTROYED se establece en flags si el rastreo se está eliminando como parte de la eliminación. Los rastreos en una variable siempre se eliminan cuando se elimina la variable; la única vez que TCL_TRACE_DESTROYED no se establece es para un rastreo de toda la matriz invocado cuando solo se anula un solo elemento de una matriz.

TCL_INTERP_DESTROYED

Cuando se destruye un intérprete, se llaman rastreos de anulación para todas sus variables. El bit TCL_INTERP_DESTROYED se establecerá en el argumento flags pasado a los procedimientos de rastreo. Los procedimientos de rastreo deben ser extremadamente cuidadosos con lo que hacen si el bit TCL_INTERP_DESTROYED está establecido. No es seguro que los procedimientos invoquen ningún procedimiento de Tcl en el intérprete, ya que su estado está parcialmente eliminado. Lo único que los procedimientos de rastreo deben hacer en estas circunstancias es limpiar y liberar sus propias estructuras de datos internas.

BUGS

Tcl no realiza ninguna comprobación de errores para evitar que los procedimientos de rastreo hagan un mal uso del intérprete durante los rastreos con TCL_INTERP_DESTROYED establecido.

Los rastreos de matrices aún no están integrados con el comando Tcl info exists, ni hay acceso a nivel de Tcl a los rastreos de matrices.
