Tcl_VarTraceInfo(3) Tcl Library Procedures Tcl_VarTraceInfo(3)

NOMBRE

Tcl_TraceVar, Tcl_TraceVar2, Tcl_UntraceVar, Tcl_UntraceVar2, Tcl_VarTraceInfo, Tcl_VarTraceInfo2 - monitorizar accesos a una variable

SINÓPSIS

#include <tcl.h>

int
Tcl_TraceVar(interp, varName, flags, proc, clientData)

int
Tcl_TraceVar2(interp, name1, name2, flags, proc, clientData)

Tcl_UntraceVar(interp, varName, flags, proc, clientData)

Tcl_UntraceVar2(interp, name1, name2, flags, proc, clientData)

ClientData
Tcl_VarTraceInfo(interp, varName, flags, proc, prevClientData)

ClientData
Tcl_VarTraceInfo2(interp, name1, name2, flags, proc, prevClientData)

ARGUMENTOS

Tcl_Interp *interp (entrada)
Intérprete que contiene la variable.
const char *varName (entrada)
Nombre de la variable. Puede referirse a una variable escalar, a una variable de array sin índice, o a una variable de array con un índice entre paréntesis.
int flags (entrada)
Combinación OR de los valores TCL_TRACE_READS, TCL_TRACE_WRITES, TCL_TRACE_UNSETS, TCL_TRACE_ARRAY, TCL_GLOBAL_ONLY, TCL_NAMESPACE_ONLY, TCL_TRACE_RESULT_DYNAMIC y TCL_TRACE_RESULT_OBJECT. No todos los flags son utilizados por todos los procedimientos. Véase más abajo para más información.
Tcl_VarTraceProc *proc (entrada)
Procedimiento a invocar cada vez que ocurra una de las operaciones trazadas.
ClientData clientData (entrada)
Valor de una palabra arbitraria para pasar a proc.
const char *name1 (entrada)
Nombre de la variable escalar o de array (sin el índice del array).
const char *name2 (entrada)
Para un trace en un elemento de un array, proporciona el índice del elemento. Para traces en variables escalares o en arrays completos, es NULL.
ClientData prevClientData (entrada)
Si no es NULL, proporciona el último valor devuelto por Tcl_VarTraceInfo o Tcl_VarTraceInfo2, por lo que esta llamada devolverá información sobre el siguiente trace. Si es NULL, esta llamada devolverá información sobre el primer trace.

DESCRIPCIÓN

Tcl_TraceVar permite a un procedimiento C monitorizar y controlar el acceso a una variable Tcl, de modo que el procedimiento C sea invocado cada vez que la variable sea leída, escrita o deshecha. Si el trace se crea con éxito, Tcl_TraceVar devuelve TCL_OK. Si ocurrió un error (por ejemplo, varName especifica un elemento de un array, pero la variable real no es un array), entonces TCL_ERROR es devuelto y se deja un mensaje de error en el resultado del intérprete.

El argumento flags a Tcl_TraceVar indica cuándo se invocará el procedimiento de trace y proporciona información para configurar el trace. Consiste en una combinación OR de cualquiera de los siguientes valores:

TCL_GLOBAL_ONLY
Normalmente, la variable se buscará en el nivel actual de la llamada al procedimiento; si este bit está establecido, la variable se buscará a nivel global, ignorando cualquier procedimiento activo.
TCL_NAMESPACE_ONLY
Normalmente, la variable se buscará en el nivel actual de la llamada al procedimiento; si este bit está establecido, la variable se buscará en el namespace actual, ignorando cualquier procedimiento activo.
TCL_TRACE_READS
Invoca proc cada vez que se intenta leer la variable.
TCL_TRACE_WRITES
Invoca proc cada vez que se intenta modificar la variable.
TCL_TRACE_UNSETS
Invoca proc cada vez que la variable es deshecha. Una variable puede ser deshecha explícitamente por un comando unset, o implícitamente cuando un procedimiento retorna (sus variables locales se deshacen automáticamente) o cuando el intérprete se elimina (todas las variables se deshacen automáticamente).
TCL_TRACE_ARRAY
Invoca proc cada vez que se invoca el comando array. Esto da al procedimiento de trace la oportunidad de actualizar el array antes de que se llamen array names o array get. Nótese que esto se llama antes de un array set, pero eso activará traces de escritura.
TCL_TRACE_RESULT_DYNAMIC
El resultado de invocar proc es una cadena asignada dinámicamente que será liberada por la biblioteca Tcl mediante una llamada a ckfree. No se debe especificar al mismo tiempo que TCL_TRACE_RESULT_OBJECT.
TCL_TRACE_RESULT_OBJECT
El resultado de invocar proc es un Tcl_Obj* (convertido a char*) con un contador de referencias de al menos uno. La propiedad de esa referencia se transferirá al núcleo de Tcl para su liberación (cuando el núcleo haya terminado con ella) mediante una llamada a Tcl_DecrRefCount. No se debe especificar al mismo tiempo que TCL_TRACE_RESULT_DYNAMIC.

Cada vez que ocurra una de las operaciones especificadas en la variable, se invocará proc. Debe tener argumentos y un resultado que coincidan con el tipo Tcl_VarTraceProc:

typedef char *Tcl_VarTraceProc(
        ClientData clientData,
        Tcl_Interp *interp,
        const char *name1,
        const char *name2,
        int flags);

Los parámetros clientData e interp tendrán los mismos valores que los pasados a Tcl_TraceVar cuando se creó el trace. ClientData normalmente apunta a una estructura de datos específica de la aplicación que describe qué hacer cuando se invoca proc. Name1 y name2 dan el nombre de la variable trazada en la forma normal de dos partes (ver la descripción de Tcl_TraceVar2 más abajo para más detalles). Flags es una combinación OR de bits que proporciona varias piezas de información. Uno de los bits TCL_TRACE_READS, TCL_TRACE_WRITES, TCL_TRACE_ARRAY, o TCL_TRACE_UNSETS se establecerá en flags para indicar qué operación se está realizando en la variable. El bit TCL_GLOBAL_ONLY se establecerá siempre que la variable que se esté accediendo sea una variable global no accesible desde el nivel actual de llamada al procedimiento: el procedimiento de trace deberá pasar este flag de vuelta a procedimientos relacionados con variables como Tcl_GetVar si intenta acceder a la variable. El bit TCL_NAMESPACE_ONLY se establecerá siempre que la variable que se esté accediendo sea una variable de namespace no accesible desde el nivel actual de llamada al procedimiento: el procedimiento de trace deberá pasar este flag de vuelta a procedimientos relacionados con variables como Tcl_GetVar si intenta acceder a la variable. El bit TCL_TRACE_DESTROYED se establecerá en flags si el trace está a punto de ser destruido; esta información puede ser útil para proc para que pueda limpiar sus propias estructuras de datos internas (ver la sección TCL_TRACE_DESTROYED más abajo para más detalles). Por último, el bit TCL_INTERP_DESTROYED se establecerá si todo el intérprete está siendo destruido. Cuando este bit está establecido, proc debe tener especial cuidado con las cosas que hace (ver la sección TCL_INTERP_DESTROYED más abajo). El valor de retorno del procedimiento de trace normalmente debe ser NULL; ver ERROR RETURNS más abajo para información sobre otras posibilidades.

Tcl_UntraceVar puede usarse para eliminar un trace. Si la variable especificada por interp, varName y flags tiene un trace establecido con flags, proc y clientData, entonces el trace correspondiente se elimina. Si no existe tal trace, la llamada a Tcl_UntraceVar no tiene efecto. Los mismos bits son válidos para flags que para las llamadas a Tcl_TraceVar.

Tcl_VarTraceInfo puede usarse para recuperar información sobre traces establecidos en una variable dada. El valor de retorno de Tcl_VarTraceInfo es el clientData asociado con un trace particular. El trace debe estar en la variable especificada por los argumentos interp, varName y flags (solo los bits TCL_GLOBAL_ONLY y TCL_NAMESPACE_ONLY de flags se usan; otros bits se ignoran) y su procedimiento de trace debe ser el mismo que el argumento proc. Si el argumento prevClientData es NULL, entonces el valor de retorno corresponde al primer trace coincidente (creado más recientemente), o NULL si no hay coincidencias

NAME

tcl.c - Procedures for handling Tcl variable traces

SYNOPSIS

#include <tcl.h>

Tcl_Trace
Tcl_TraceVar(interp, varName, flags, traceProc, clientData)
Tcl_Trace
Tcl_TraceVar2(interp, name1, name2, flags, traceProc, clientData)
void
Tcl_UntraceVar(interp, varName, flags, traceProc, clientData)
void
Tcl_UntraceVar2(interp, name1, name2, flags, traceProc, clientData)
ClientData
Tcl_VarTraceInfo(interp, varName, flags)
ClientData
Tcl_VarTraceInfo2(interp, name1, name2, flags)

DESCRIPTION

The procedures described in this manual page are used to manage traces on Tcl variables. A trace is a C procedure that is called whenever a Tcl variable is read, written, unset, or when an array is modified.

Trace procedures allow you to monitor and control access to Tcl variables. For example, you can use traces to implement read-only variables, to perform automatic type checking, or to log variable accesses.

A trace procedure has the following C type:

typedef int (*Tcl_VarTraceProc)(
    ClientData clientData,
    Tcl_Interp *interp,
    const char *varName,
    const char *element,
    int flags);

The arguments to a trace procedure are:

clientData
The value passed as the clientData argument when the trace was created.
interp
The interpreter in which the trace is active.
varName
If the trace is on a scalar variable, this is the name of the variable. If the trace is on an array variable, this is the name of the array. If the trace is on an array element, this is the name of the array.
element
If the trace is on an array element, this is the name of the element. If the trace is on a scalar variable or on an array as a whole, this is NULL.
flags
A bitmask indicating the reason the trace procedure was invoked. The possible bits are:
TCL_TRACE_READ
The variable is being read.
TCL_TRACE_WRITE
The variable is being written.
TCL_TRACE_UNSET
The variable is being unset.
TCL_TRACE_ARRAY
The trace was set on an array as a whole, and an element of the array is being accessed.
TCL_TRACE_GLOBAL
The trace was set on a global variable.
TCL_TRACE_SUMMARY
This flag is used with Tcl_VarTraceInfo. If set, it indicates that the trace procedure should return a summary of the traces rather than detailed information about each trace.
TCL_TRACE_DESTROYED
This flag is set in the flags argument to an unset trace procedure if the trace is being removed as part of the deletion of the variable. See the TCL_TRACE_DESTROYED FLAG section below.
TCL_TRACE_INTERP_DESTROYED
This flag is set in the flags argument to an unset trace procedure if the interpreter is being destroyed. See the TCL_INTERP_DESTROYED section below.

TCL_TRACE_VAR

Tcl_TraceVar registers a trace procedure, traceProc, to be called when the Tcl variable named varName is accessed. The flags argument specifies the type of accesses to trace (any combination of TCL_TRACE_READ, TCL_TRACE_WRITE, and TCL_TRACE_UNSET). The clientData argument is arbitrary data that will be passed to traceProc whenever it is called. The return value is a handle that can be used later to remove the trace using Tcl_UntraceVar.

TCL_UNTRACE_VAR

Tcl_UntraceVar removes a previously registered trace. The arguments must match those used in the call to Tcl_TraceVar that created the trace. If the trace is successfully removed, it will no longer be invoked.

TCL_VAR_TRACE_INFO

Tcl_VarTraceInfo returns information about the traces registered for the Tcl variable named varName. The flags argument specifies the type of accesses to query (any combination of TCL_TRACE_READ, TCL_TRACE_WRITE, and TCL_TRACE_UNSET). The return value is the clientData associated with the first matching trace, or NULL if no traces match the specified criteria. If prevClientData is not NULL, then it should be the return value from a previous call to Tcl_VarTraceInfo. In this case, the new return value will correspond to the next matching trace after the one whose clientData matches prevClientData, or NULL if no trace matches prevClientData or if there are no more matching traces after it. This mechanism makes it possible to step through all of the traces for a given variable that have the same proc.

TWO-PART NAMES

The procedures Tcl_TraceVar2, Tcl_UntraceVar2, and Tcl_VarTraceInfo2 are identical to Tcl_TraceVar, Tcl_UntraceVar, and Tcl_VarTraceInfo, respectively, except that the name of the variable consists of two parts. Name1 gives the name of a scalar variable or array, and name2 gives the name of an element within an array. When name2 is NULL, name1 may contain both an array and an element name: if the name contains an open parenthesis and ends with a close parenthesis, then the value between the parentheses is treated as an element name (which can have any string value) and the characters before the first open parenthesis are treated as the name of an array variable. If name2 is NULL and name1 does not refer to an array element it means that either the variable is a scalar or the trace is to be set on the entire array rather than an individual element (see WHOLE-ARRAY TRACES below for more information).

ACCESSING VARIABLES DURING TRACES

During read, write, and array traces, the trace procedure can read, write, or unset the traced variable using Tcl_GetVar2, Tcl_SetVar2, and other procedures. While proc is executing, traces are temporarily disabled for the variable, so that calls to Tcl_GetVar2 and Tcl_SetVar2 will not cause proc or other trace procedures to be invoked again. Disabling only occurs for the variable whose trace procedure is active; accesses to other variables will still be traced. However, if a variable is unset during a read or write trace then unset traces will be invoked.

During unset traces the variable has already been completely expunged. It is possible for the trace procedure to read or write the variable, but this will be a new version of the variable. Traces are not disabled during unset traces as they are for read and write traces, but existing traces have been removed from the variable before any trace procedures are invoked. If new traces are set by unset trace procedures, these traces will be invoked on accesses to the variable by the trace procedures.

CALLBACK TIMING

When read tracing has been specified for a variable, the trace procedure will be invoked whenever the variable's value is read. This includes set Tcl commands, $-notation in Tcl commands, and invocations of the Tcl_GetVar and Tcl_GetVar2 procedures. Proc is invoked just before the variable's value is returned. It may modify the value of the variable to affect what is returned by the traced access. If it unsets the variable then the access will return an error just as if the variable never existed.

When write tracing has been specified for a variable, the trace procedure will be invoked whenever the variable's value is modified. This includes set commands, commands that modify variables as side effects (such as catch and scan), and calls to the Tcl_SetVar and Tcl_SetVar2 procedures). Proc will be invoked after the variable's value has been modified, but before the new value of the variable has been returned. It may modify the value of the variable to override the change and to determine the value actually returned by the traced access. If it deletes the variable then the traced access will return an empty string.

When array tracing has been specified, the trace procedure will be invoked at the beginning of the array command implementation, before any of the operations like get, set, or names have been invoked. The trace procedure can modify the array elements with Tcl_SetVar and Tcl_SetVar2.

When unset tracing has been specified, the trace procedure will be invoked whenever the variable is destroyed. The traces will be called after the variable has been completely unset.

WHOLE-ARRAY TRACES

If a call to Tcl_TraceVar or Tcl_TraceVar2 specifies the name of an array variable without an index into the array, then the trace will be set on the array as a whole. This means that proc will be invoked whenever any element of the array is accessed in the ways specified by flags. When an array is unset, a whole-array trace will be invoked just once, with name1 equal to the name of the array and name2 NULL; it will not be invoked once for each element.

MULTIPLE TRACES

It is possible for multiple traces to exist on the same variable. When this happens, all of the trace procedures will be invoked on each access, in order from most-recently-created to least-recently-created. When there exist whole-array traces for an array as well as traces on individual elements, the whole-array traces are invoked before the individual-element traces. If a read or write trace unsets the variable then all of the unset traces will be invoked but the remainder of the read and write traces will be skipped.

ERROR RETURNS

Under normal conditions trace procedures should return NULL, indicating successful completion. If proc returns a non-NULL value it signifies that an error occurred. The return value must be a pointer to a static character string containing an error message, unless (exactly one of) the TCL_TRACE_RESULT_DYNAMIC and TCL_TRACE_RESULT_OBJECT flags is set, which specify that the result is either a dynamic string (to be released with ckfree) or a Tcl_Obj* (cast to char* and to be released with Tcl_DecrRefCount) containing the error message. If a trace procedure returns an error, no further traces are invoked for the access and the traced access aborts with the given message. Trace procedures can use this facility to make variables read-only, for example (but note that the value of the variable will already have been modified before the trace procedure is called, so the trace procedure will have to restore the correct value).

The return value from proc is only used during read and write tracing. During unset traces, the return value is ignored and all relevant trace procedures will always be invoked.

RESTRICTIONS

A trace procedure can be called at any time, even when there are partially formed results stored in the interpreter. If the trace procedure does anything that could damage this result (such as calling Tcl_Eval) then it must use the Tcl_SaveInterpState and related routines to save and restore the original state of the interpreter before it returns.

UNDEFINED VARIABLES

It is legal to set a trace on an undefined variable. The variable will still appear to be undefined until the first time its value is set. If an undefined variable is traced and then unset, the unset will fail with an error (“no such variable”), but the trace procedure will still be invoked.

TCL_TRACE_DESTROYED FLAG

In an unset callback to proc, the TCL_TRACE_DESTROYED bit is set in flags if the trace is being removed as part of the deletion. Traces on a variable are always removed whenever the variable is deleted; the only time TCL_TRACE_DESTROYED is not set is for a whole-array trace invoked when only a single element of an array is unset.

TCL_INTERP_DESTROYED

When an interpreter is destroyed, unset traces are called for all of its variables. The TCL_INTERP_DESTROYED bit will be set in the flags argument passed to the trace procedures. Trace procedures must be extremely careful in what they do if the TCL_INTERP_DESTROYED bit is set. It is not safe for the procedures to invoke any Tcl procedures on the interpreter, since its state is partially deleted. All that trace procedures should do under these circumstances is to clean up and free their own internal data structures.

BUGS

Tcl does not do any error checking to prevent trace procedures from misusing the interpreter during traces with TCL_INTERP_DESTROYED set.

Array traces are not yet integrated with the Tcl info exists command, nor is there Tcl-level access to array traces.
