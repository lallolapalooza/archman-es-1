Threads(3) Procedimientos de la biblioteca Tcl Threads(3)

NOMBRE

Tcl_ConditionNotify, Tcl_ConditionWait, Tcl_ConditionFinalize, Tcl_GetThreadData, Tcl_MutexLock, Tcl_MutexUnlock, Tcl_MutexFinalize, Tcl_CreateThread, Tcl_JoinThread - Soporte de hilos Tcl

SINOPSIS

#include <tcl.h>

void
Tcl_ConditionNotify(condPtr)

void
Tcl_ConditionWait(condPtr, mutexPtr, timePtr)

void
Tcl_ConditionFinalize(condPtr)

Void *
Tcl_GetThreadData(keyPtr, size)

void
Tcl_MutexLock(mutexPtr)

void
Tcl_MutexUnlock(mutexPtr)

void
Tcl_MutexFinalize(mutexPtr)

int
Tcl_CreateThread(idPtr, proc, clientData, stackSize, flags)

int
Tcl_JoinThread(id, result)

ARGUMENTOS

Tcl_Condition *condPtr (entrada)
Una variable de condición, que debe estar asociada a un bloqueo mutex.
Tcl_Mutex *mutexPtr (entrada)
Un bloqueo mutex.
const Tcl_Time *timePtr (entrada)
Un límite de tiempo para la espera de la condición. NULL para esperar indefinidamente. ¡Tenga en cuenta que un valor de sondeo de 0 segundos no tiene mucho sentido!
Tcl_ThreadDataKey *keyPtr (entrada)
Esto identifica un bloque de almacenamiento local del hilo. La clave debe ser estática y válida para todo el proceso, pero cada hilo terminará asociando un bloque de almacenamiento diferente con esta clave.
int *size (entrada)
El tamaño del bloque de almacenamiento local del hilo. Esta cantidad de datos se asigna y se inicializa a cero la primera vez que cada hilo llama a Tcl_GetThreadData.
Tcl_ThreadId *idPtr (salida)
El almacenamiento referenciado contendrá el ID del nuevo hilo tal como lo devuelve el sistema operativo.
Tcl_ThreadId id (entrada)
ID del hilo esperado.
Tcl_ThreadCreateProc *proc (entrada)
Este procedimiento actuará como el main() del nuevo hilo. El clientData especificado será su único argumento.
ClientData clientData (entrada)
Información arbitraria. Se pasa como único argumento a proc.
int stackSize (entrada)
El tamaño de la pila dado al nuevo hilo.
int flags (entrada)
Máscara de bits que contiene indicadores que permiten al llamante modificar el comportamiento del nuevo hilo.
int *result (salida)
El almacenamiento referenciado se utiliza para colocar el código de salida del hilo esperado en él.

INTRODUCCIÓN

A partir de la versión 8.1, el núcleo Tcl es seguro para hilos, lo que permite incorporar Tcl en aplicaciones multihilo sin personalizar el núcleo Tcl. A partir de la versión 8.6, el soporte de subprocesos Tcl está activado por defecto. Para deshabilitar el soporte de subprocesos Tcl, debe incluir la opción --disable-threads en configure al configurar y compilar su núcleo Tcl.

Una restricción importante de la implementación de hilos Tcl es que *solo el hilo que creó un intérprete Tcl puede usar ese intérprete*. En otras palabras, varios hilos no pueden acceder al mismo intérprete Tcl. (Sin embargo, un solo hilo puede crear y usar múltiples intérpretes de forma segura).

DESCRIPCIÓN

Tcl proporciona Tcl_CreateThread para crear hilos. El llamante puede determinar el tamaño de la pila que se le da al nuevo hilo y modificar el comportamiento a través de los flags proporcionados. El valor TCL_THREAD_STACK_DEFAULT para stackSize indica que se debe usar el tamaño predeterminado según lo especificado por el sistema operativo para el nuevo hilo. En cuanto a los flags, actualmente solo se definen los valores TCL_THREAD_NOFLAGS y TCL_THREAD_JOINABLE. El primero de ellos invoca el comportamiento predeterminado sin ajustes especiales. Usar el segundo valor marca el nuevo hilo como *unible*. Esto significa que otro hilo puede esperar a que dicho hilo marcado salga y se una a él.

Restricciones: En algunos sistemas UNIX, la biblioteca pthread no contiene la funcionalidad para especificar el tamaño de la pila de un hilo. El valor especificado para el tamaño de la pila se ignora en estos sistemas. Windows actualmente no admite hilos unibles. Por lo tanto, este valor de flag se ignora en esta plataforma.

Tcl proporciona las funciones Tcl_ExitThread y Tcl_FinalizeThread para terminar hilos e invocar manejadores de salida opcionales por hilo. Consulte la página Tcl_Exit para obtener más información sobre estos procedimientos.

La función Tcl_JoinThread se proporciona para permitir que los hilos esperen la salida de otro hilo, que debe haber sido marcado como unible mediante el uso del flag TCL_THREAD_JOINABLE durante su creación a través de Tcl_CreateThread.

Intentar esperar la salida de un hilo no unible o de un hilo que ya está siendo esperado resultará en un error. Esperar a un hilo unible que ya salió es posible, el sistema retendrá la información necesaria hasta después de la llamada a Tcl_JoinThread. Esto significa que no llamar a Tcl_JoinThread para un hilo unible causará una fuga de memoria.

La llamada Tcl_GetThreadData devuelve un puntero a un bloque de datos privados del hilo. Su argumento es una clave que es compartida por todos los hilos y un tamaño para el bloque de almacenamiento. El almacenamiento se asigna automáticamente y se inicializa a todos ceros la primera vez que cada hilo lo solicita. El almacenamiento se libera automáticamente mediante Tcl_FinalizeThread.

SINCRONIZACIÓN Y COMUNICACIÓN

Tcl proporciona Tcl_ThreadQueueEvent y Tcl_ThreadAlert para manejar la cola de eventos en aplicaciones multihilo. Consulte la página del manual de Notifier para obtener más información sobre estos procedimientos.

Un mutex es un bloqueo que se utiliza para serializar todos los hilos a través de una sección de código llamando a Tcl_MutexLock y Tcl_MutexUnlock. Si un hilo tiene un mutex, cualquier otro hilo que llame a Tcl_MutexLock se bloqueará hasta que se llame a Tcl_MutexUnlock. Un mutex puede destruirse después de su uso llamando a Tcl_MutexFinalize. El resultado de bloquear un mutex dos veces desde el mismo hilo no está definido. En algunas plataformas resultará en una condición de interbloqueo (deadlock). Los procedimientos Tcl_MutexLock, Tcl_MutexUnlock y Tcl_MutexFinalize se definen como macros vacías si no se compila con hilos habilitados. Para la declaración de mutexes, se debe usar la macro TCL_DECLARE_MUTEX. Esta macro asegura el manejo correcto de mutexes incluso cuando el núcleo se compila sin hilos habilitados.

Una variable de condición se utiliza como mecanismo de señalización: un hilo puede bloquear un mutex y luego esperar en una variable de condición con Tcl_ConditionWait. Esto libera atómicamente el bloqueo del mutex y bloquea el hilo que espera hasta que otro hilo llame a Tcl_ConditionNotify. El llamante de Tcl_ConditionNotify debe tener el mutex asociado bloqueado llamando previamente a Tcl_MutexLock, pero esto no se impone. Notificar la variable de condición desbloquea todos los hilos que esperan en la variable de condición, pero no proceden hasta que el mutex se libera con Tcl_MutexUnlock. La implementación de Tcl_ConditionWait bloquea automáticamente el mutex antes de devolver.

El llamante de Tcl_ConditionWait debe estar preparado para notificaciones espurias llamando a Tcl_ConditionWait dentro de un bucle while que prueba algún invariante.

Una variable de condición puede destruirse después de su uso llamando a Tcl_ConditionFinalize.

Los procedimientos Tcl_ConditionNotify, Tcl_ConditionWait y Tcl_ConditionFinalize se definen como macros vacías si no se compila con hilos habilitados.

INICIALIZACIÓN

Todos estos objetos de sincronización son auto-inicializables. Se implementan como punteros opacos que deben ser NULL en su primer uso. Los mutexes y las variables de condición se limpian mediante manejadores de salida del proceso (si viven tanto tiempo) o explícitamente mediante llamadas a Tcl_MutexFinalize o Tcl_ConditionFinalize. El almacenamiento local del hilo se recupera durante Tcl_FinalizeThread.

ACCESO A HILOS A NIVEL DE SCRIPT

Tcl no proporciona comandos integrados para que los scripts creen, gestionen o unan hilos, ni ningún acceso a nivel de script a variables mutex o de condición. Proporciona tales facilidades solo a través de interfaces C, y deja que los paquetes se encarguen de exponerlos a los scripts.

INTRODUCCIÓN

El paquete Thread proporciona acceso a nivel de script a las capacidades de subprocesos de Tcl. Puede crear nuevos subprocesos, unirse a subprocesos para esperar a que terminen, y acceder a otros mecanismos de sincronización de subprocesos como mutuos y variables de condición.

DESCRIPCIÓN

El paquete Thread expone las siguientes funciones Tcl:

Tcl_CreateThread ?nombre?
Crea un nuevo subproceso.
Tcl_ExitThread ?valor_salida?
Termina el subproceso actual.
Tcl_FinalizeThread ?valor_salida?
Termina el subproceso actual y libera todos los recursos asociados. Esto solo se puede llamar desde el subproceso que se está finalizando.
Tcl_GetCurrentThread
Devuelve el identificador del subproceso actual.
Tcl_GetThreadData id ?clave?
Devuelve los datos del subproceso asociados con el id dado. Si se especifica la clave, se devuelven los datos del subproceso asociados con esa clave específica. Si no se especifica la clave, se devuelven los datos del subproceso de nivel superior.
Tcl_GetThreadId
Devuelve el identificador del subproceso actual. Esto es lo mismo que Tcl_GetCurrentThread.
Tcl_JoinThread id ?varName?
Espera a que el subproceso especificado por id termine.
Tcl_SetThreadData id ?clave? datos
Establece los datos del subproceso asociados con el id dado. Si se especifica la clave, se establecen los datos del subproceso asociados con esa clave específica. Si no se especifica la clave, se establecen los datos del subproceso de nivel superior.
Tcl_ThreadAlert id
Alerta al subproceso especificado por id. Esto se puede usar para despertar a un subproceso que está esperando en una operación de bloqueo.
Tcl_ThreadCreateExitHandler proc ?clientData?
Registra un manejador de salida para el subproceso actual.
Tcl_ThreadDeleteExitHandler proc ?clientData?
Elimina un manejador de salida registrado para el subproceso actual.
Tcl_ThreadQueueEvent id type ?data?
Encola un evento para el subproceso especificado por id. El evento se procesará cuando el subproceso vuelva a entrar en el bucle de eventos Tcl.

ACCESO A NIVEL DE SCRIPT A LOS SUBPROCESOS

El paquete Thread se puede cargar en un intérprete Tcl usando el comando:

package require Thread

Una vez cargado, puede usar las funciones Tcl expuestas por el paquete para crear y administrar subprocesos desde su script Tcl. Por ejemplo, el siguiente script crea un nuevo subproceso que duerme durante 5 segundos y luego termina:

package require Thread

proc myThreadFunc {data} {
    puts "Subproceso iniciado con datos: $data"
    after 5000
    puts "Subproceso terminando"
}

set id [Tcl_CreateThread myThreadFunc "hola mundo"]
puts "Subproceso creado con id: $id"

# Esperar a que el subproceso termine
Tcl_JoinThread $id
puts "Subproceso terminado"

Este es un ejemplo simple. El paquete Thread proporciona muchas más funcionalidades para un control más detallado de los subprocesos, incluida la creación de manejadores de salida, el acceso a datos locales de subproceso y la notificación a otros subprocesos. Para obtener más información, consulte la documentación de las funciones individuales.

La mayoría de las operaciones de creación y administración de subprocesos requieren que se ejecute en un contexto de nivel de comando Tcl. Sin embargo, la creación de subprocesos de nivel de biblioteca se puede realizar de forma segura desde código C/C++ que llama a las API de Tcl correspondientes. Exponer estas funcionalidades a nivel de script es el propósito de exponer estas funciones Tcl a través del paquete Thread.

EJEMPLO

Para crear un subproceso con código portable, su función de implementación debe declararse de la siguiente manera:

static Tcl_ThreadCreateProc MyThreadImplFunc;

Luego, debe definirse de esta manera, que simplemente cuenta hasta un valor dado y luego termina.

static Tcl_ThreadCreateType
MyThreadImplFunc(
    ClientData clientData)
{
    int i, limit = (int) clientData;
    for (i=0 ; i<limit ; i++) {
        /* no haciendo nada aquí en absoluto */
    }
    TCL_THREAD_CREATE_RETURN;
}

Para crear el subproceso anterior, hacerlo ejecutar y esperar a que termine, haríamos esto:

int limit = 1000000000;
ClientData limitData = (void*)((intptr_t) limit);
Tcl_ThreadId id;    /* contiene la identidad del subproceso creado */
int result;
if (Tcl_CreateThread(&id, MyThreadImplFunc, limitData,
        TCL_THREAD_STACK_DEFAULT,
        TCL_THREAD_JOINABLE) != TCL_OK) {
    /* El subproceso no se creó correctamente */
    return;
}
/* Haz algo más durante un tiempo aquí */
if (Tcl_JoinThread(id, &result) != TCL_OK) {
    /* El subproceso no terminó correctamente */
    return;
}
/* Todo limpio y ordenado */
