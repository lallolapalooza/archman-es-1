ARGUMENTOS

Tcl_Interp *interp (entrada)
Se usa para informar de errores y para buscar un canal registrado en él.
const char *fileName (entrada)
El nombre de un archivo local o de red.
const char *mode (entrada)
Especifica cómo se debe acceder al archivo. Puede tener cualquiera de los valores permitidos para el argumento mode del comando Tcl open.
int permissions (entrada)
Indicadores de permisos al estilo POSIX, como 0644. Si se crea un archivo nuevo, estos permisos se aplicarán al archivo creado.
int argc (entrada)
El número de elementos en argv.
const char **argv (entrada)
Argumentos para construir una tubería de comandos. Estos valores tienen el mismo significado que los argumentos que no son opciones del comando Tcl exec.
int flags (entrada)
Especifica la disposición de los manejadores stdio en la tubería: combinación OR de TCL_STDIN, TCL_STDOUT, TCL_STDERR y TCL_ENFORCE_MODE. Si se establece TCL_STDIN, la entrada estándar del primer hijo en la tubería es el canal de la tubería, de lo contrario es la misma que la entrada estándar del proceso invocador; lo mismo ocurre con TCL_STDOUT y TCL_STDERR. Si no se establece TCL_ENFORCE_MODE, entonces la tubería puede redirigir los manejadores stdio para anular los manejadores stdio para los que se han establecido TCL_STDIN, TCL_STDOUT y TCL_STDERR. Si está establecido, entonces tales redirecciones causan un error.
ClientData handle (entrada)
Manejador específico del sistema operativo para E/S de un archivo. Para Unix es un descriptor de archivo, para Windows es un HANDLE.
int readOrWrite (entrada)
Combinación OR de TCL_READABLE y TCL_WRITABLE para indicar qué operaciones son válidas en handle.
const char *channelName (entrada)
El nombre del canal.
int *modePtr (salida)
Apunta a una variable entera que recibirá una combinación OR de TCL_READABLE y TCL_WRITABLE que indica si el canal está abierto para lectura y escritura.
const char *pattern (entrada)
El patrón a coincidir, pasado a Tcl_StringMatch, o NULL.
Tcl_Channel channel (entrada)
Un canal Tcl para entrada o salida. Debe haber sido el valor de retorno de un procedimiento como Tcl_OpenFileChannel.
Tcl_Obj *readObjPtr (entrada/salida)
Un puntero a un valor Tcl en el que se almacenarán los caracteres leídos del canal.
int charsToRead (entrada)
El número de caracteres a leer del canal. Si la codificación del canal es binary, esto es equivalente al número de bytes a leer del canal.
int appendFlag (entrada)
Si es distinto de cero, los datos leídos del canal se añadirán al valor. De lo contrario, los datos reemplazarán el contenido existente del valor.
char *readBuf (salida)
Un búfer en el que almacenar los bytes leídos del canal.
int bytesToRead (entrada)
El número de bytes a leer del canal. El búfer readBuf debe ser lo suficientemente grande para contener este número de bytes.
Tcl_Obj *lineObjPtr (entrada/salida)
Un puntero a un valor Tcl en el que se almacenará la línea leída del canal. La línea leída se añadirá al valor actual del valor.
Tcl_DString *lineRead (entrada/salida)
Un puntero a una cadena dinámica Tcl en la que se almacenará la línea leída del canal. Debe haber sido inicializado por el llamador. La línea leída se añadirá a cualquier dato que ya esté en la cadena dinámica.
const char *input (entrada)
La entrada a añadir a un búfer de canal.
int inputLen (entrada)
Longitud de la entrada
int addAtEnd (entrada)
Indicador que muestra si la entrada debe añadirse al final o al principio del búfer del canal.
Tcl_Obj *writeObjPtr (entrada)
Un puntero a un valor Tcl cuyo contenido se enviará al canal.
const char *charBuf (entrada)
Un búfer que contiene los caracteres a enviar al canal.
const char *byteBuf (entrada)
Un búfer que contiene los bytes a enviar al canal.
int bytesToWrite (entrada)
El número de bytes a consumir de charBuf o byteBuf y enviar al canal.
Tcl_WideInt offset (entrada)
A qué distancia mover el punto de acceso en el canal en el que se aplicará la siguiente operación de entrada o salida, medido en bytes desde la posición dada por seekMode. Puede ser positivo o negativo.
int seekMode (entrada)
Desde qué punto buscar; se usa con offset para calcular el nuevo punto de acceso para el canal. Los valores legales son SEEK_SET, SEEK_CUR y SEEK_END.
Tcl_WideInt length (entrada)
La longitud (no negativa) a la que truncar el canal.
const char *optionName (entrada)
El nombre de una opción aplicable a este canal, como -blocking. Puede tener cualquiera de los valores aceptados por el comando fconfigure.
Tcl_DString *optionValue (entrada)
Dónde almacenar el valor de una opción o una lista de todas las opciones y sus valores. Debe haber sido inicializado por el llamador.
const char *newValue (entrada)
Nuevo valor para la opción dada por optionName.

DESCRIPCIÓN

El mecanismo de canales de Tcl proporciona un mecanismo independiente de dispositivo y plataforma para realizar operaciones de entrada y salida con búfer en una variedad de tipos de archivos, sockets y dispositivos. El mecanismo de canales es extensible a nuevos tipos de canales, proporcionando un controlador de canal de bajo nivel para el nuevo tipo; la interfaz del controlador de canal se describe en la entrada del manual para Tcl_CreateChannel. El mecanismo de canales proporciona un esquema de búfer modelado después de la E/S estándar de Unix, y también permite E/S no bloqueante en canales.

Los procedimientos descritos en esta entrada del manual comprenden las API de C de la capa genérica de la arquitectura de canales. Para una descripción de la arquitectura del controlador de canales y cómo implementar controladores de canales para nuevos tipos de canales, consulte la entrada del manual para Tcl_CreateChannel.

TCL_OPENFILECHANNEL

Tcl_OpenFileChannel abre un archivo llamado fileName y lo devuelve como un canal Tcl. El argumento mode especifica cómo se debe acceder al archivo: los valores permitidos son los mismos que los argumentos mode del comando Tcl open. El argumento permissions especifica los permisos POSIX para el archivo; sólo se utiliza si se crea un archivo nuevo. El valor devuelto es un manejador de canal opaco o NULL si ocurre un error. Si se devuelve NULL, la información del error se puede recuperar del registro de errores del intérprete.

Los siguientes modos están disponibles:

r
Abrir para leer.
w
Abrir para escribir. Si el archivo existe, su contenido se trunca. Si no existe, se crea.
a
Abrir para añadir. Los datos se escribirán al final del archivo. Si el archivo no existe, se crea.
r+
Abrir para leer y escribir. El puntero del archivo está al principio del archivo.
w+
Abrir para leer y escribir. Trunca el archivo si existe, o lo crea si no existe.
a+
Abrir para leer y añadir. Los datos siempre se escriben al final del archivo, pero la lectura puede ocurrir en cualquier lugar. Si el archivo no existe, se crea.

Los modos r, w, a, r+, w+ y a+ se pueden añadir con una b (por ejemplo, rb) para indicar que el archivo se está abriendo en modo binario. Por defecto, los archivos se abren en modo texto, lo que puede implicar conversiones de caracteres (por ejemplo, CRLF a LF en Windows).

Estos modos se pueden combinar con una t (por ejemplo, rt) para indicar explícitamente que el archivo se está abriendo en modo texto. Esto es lo contrario de b.

Si el modo contiene b, el canal se abre en modo binario. Si el modo contiene t, el canal se abre en modo texto. Si ni b ni t están presentes, el modo por defecto es texto.

TCL_OPENCOMMANDCHANNEL

Tcl_OpenCommandChannel abre una tubería para comunicar con un proceso externo ejecutando el comando especificado en argv. argc es el número de argumentos en argv. Los argumentos de la línea de comandos se pasan al comando externo. El argumento flags controla la redirección de la entrada/salida estándar del proceso externo. Puede ser una combinación OR de TCL_STDIN, TCL_STDOUT, TCL_STDERR y TCL_ENFORCE_MODE. Si TCL_STDIN está establecido, la entrada estándar del primer hijo en la tubería es el canal de la tubería, de lo contrario, es la misma que la entrada estándar del proceso invocador; lo mismo ocurre con TCL_STDOUT y TCL_STDERR. Si TCL_ENFORCE_MODE no está establecido, entonces la tubería puede redirigir los manejadores stdio para anular los manejadores stdio para los que se han establecido TCL_STDIN, TCL_STDOUT y TCL_STDERR. Si está establecido, entonces tales redirecciones causan un error.

El valor devuelto es un manejador de canal opaco o NULL si ocurre un error. Si se devuelve NULL, la información del error se puede recuperar del registro de errores del intérprete.

TCL_MAKEFILECHANNEL

Tcl_MakeFileChannel envuelve un manejador de archivo existente (por ejemplo, un descriptor de archivo de Unix o un HANDLE de Windows) en un canal Tcl. El argumento handle es el manejador del sistema operativo. El argumento readOrWrite es una combinación OR de TCL_READABLE y TCL_WRITABLE para indicar si el manejador está abierto para lectura y/o escritura. El valor devuelto es el nuevo canal Tcl, o NULL si ocurre un error. El canal devuelto no se registrará en el intérprete; debe hacerlo explícitamente usando Tcl_RegisterChannel.

TCL_GETCHANNEL

Tcl_GetChannel busca un canal registrado en el intérprete interp con el nombre channelName. Si se encuentra, devuelve un puntero al canal opaco. Si modePtr no es NULL, el entero al que apunta se establecerá con una combinación OR de TCL_READABLE y TCL_WRITABLE para indicar si el canal está abierto para lectura y/o escritura.

Si el canal no se encuentra, o si ocurre un error, devuelve NULL y establece el registro de errores del intérprete.

TCL_GETCHANNELNAMES

Tcl_GetChannelNames devuelve una lista de todos los nombres de canales actualmente registrados en el intérprete interp. Los nombres se almacenan en el valor del resultado del intérprete (result string) como una lista de Tcl. El valor devuelto es TCL_OK si la operación tuvo éxito, o TCL_ERROR si ocurrió un error.

Tcl_GetChannelNamesEx funciona de manera similar, pero solo devuelve los nombres de los canales que coinciden con el pattern.

TCL_REGISTERCHANNEL

Tcl_RegisterChannel registra un canal previamente creado (por ejemplo, por Tcl_OpenFileChannel o Tcl_MakeFileChannel) en el intérprete interp bajo su nombre de canal asociado. Después de registrar un canal, el intérprete se hace responsable de cerrar el canal cuando el intérprete se destruye o se libera el canal. Un canal solo puede estar registrado una vez.

TCL_UNREGISTERCHANNEL

Tcl_UnregisterChannel elimina un canal registrado del intérprete interp. El canal aún puede ser utilizado después de ser desregistrado, pero el intérprete ya no será responsable de él. Por ejemplo, el canal debe cerrarse explícitamente llamando a Tcl_Close. Esta operación es útil para mover canales entre intérpretes, o para gestionar canales que son abiertos y cerrados dinámicamente.

El canal debe estar abierto; si no lo está, se devuelve TCL_ERROR.

TCL_DETACHCHANNEL

Tcl_DetachChannel desasocia un canal registrado del intérprete interp. El canal se cierra y se libera su memoria asociada, pero no se cierra el descriptor de archivo subyacente. El manejador del sistema operativo para el canal se devuelve de la función. Esto es útil para transferir la propiedad de un canal a un proceso externo, por ejemplo, al ejecutar un comando hijo que necesita heredar un descriptor de archivo abierto.

Si el canal no está registrado, o si ocurre un error, se devuelve un valor de manejador de sistema operativo no válido (por ejemplo, -1 en Unix) y se establece el registro de errores del intérprete.

TCL_ISTANDARDCHANNEL

Tcl_IsStandardChannel devuelve 1 si el canal channel es uno de los canales estándar (entrada, salida o error) y 0 en caso contrario.

TCL_CLOSE

Tcl_Close cierra el canal channel. Esto fuerza la escritura de cualquier dato en el búfer de salida y libera los recursos asociados con el canal. Si el canal fue abierto por Tcl_OpenFileChannel, el archivo subyacente también se cerrará.

El valor devuelto es TCL_OK si el canal se cerró correctamente, o TCL_ERROR si ocurrió un error (por ejemplo, al intentar escribir datos en un canal de solo lectura). Si ocurre un error, se establece el registro de errores del intérprete.

TCL_READCHARS

Tcl_ReadChars lee hasta charsToRead caracteres del canal channel y los almacena en el valor Tcl apuntado por readObjPtr. Si appendFlag es distinto de cero, los caracteres leídos se añadirán al valor existente de readObjPtr; de lo contrario, el valor se establecerá con los caracteres recién leídos. Si se lee menos de charsToRead caracteres (por ejemplo, al final del archivo o porque el canal está bloqueado y no hay datos disponibles), se leerán todos los caracteres disponibles.

El valor devuelto es el número de caracteres leídos. Se devuelve -1 si ocurre un error (por ejemplo, si se intenta leer de un canal de solo escritura). Si ocurre un error, se establece el registro de errores del intérprete.

TCL_READ

Tcl_Read lee hasta bytesToRead bytes del canal channel y los almacena en el búfer readBuf. A diferencia de Tcl_ReadChars, esta función siempre opera en modo binario y lee bytes sin decodificación. Si se leen menos de bytesToRead bytes (por ejemplo, al final del archivo o porque el canal está bloqueado y no hay datos disponibles), se leerán todos los bytes disponibles.

El valor devuelto es el número de bytes leídos. Se devuelve -1 si ocurre un error (por ejemplo, si se intenta leer de un canal de solo escritura). Si ocurre un error, se establece el registro de errores del intérprete.

TCL_GETSOBJ

Tcl_GetsObj lee caracteres del canal channel hasta que se encuentra un carácter de nueva línea, se alcanza el final del archivo, o se produce un error. La línea leída (sin el carácter de nueva línea final, si está presente) se almacena en el valor Tcl apuntado por lineObjPtr. La línea se añadirá al valor existente de lineObjPtr.

El valor devuelto es el número de caracteres leídos. Se devuelve -1 si ocurre un error. Se devuelve 0 si se alcanza el final del archivo antes de leer algún carácter, o si el canal está bloqueado y no hay datos disponibles. Si se produce un error, se establece el registro de errores del intérprete.

TCL_GETS

Tcl_Gets lee caracteres del canal channel hasta que se encuentra un carácter de nueva línea, se alcanza el final del archivo, o se produce un error. La línea leída (sin el carácter de nueva línea final, si está presente) se almacena en la cadena dinámica Tcl apuntada por lineRead. La línea se añadirá a cualquier dato que ya esté en la cadena dinámica.

El valor devuelto es el número de caracteres leídos. Se devuelve -1 si ocurre un error. Se devuelve 0 si se alcanza el final del archivo antes de leer algún carácter, o si el canal está bloqueado y no hay datos disponibles. Si se produce un error, se establece el registro de errores del intérprete.

TCL_UNGETS

Tcl_Ungets pone el argumento input (una cadena de longitud inputLen) de nuevo en el búfer de entrada del canal channel. Si addAtEnd es distinto de cero, la entrada se añade al final del búfer de entrada; de lo contrario, se añade al principio. Esto es útil para implementar analizadores que necesitan "desleer" algunos caracteres para reexaminarlos en un contexto diferente.

El valor devuelto es el número de caracteres que se pusieron de nuevo en el búfer. Se devuelve -1 si ocurre un error.

TCL_WRITECHARSOBJECT

Tcl_WriteObj escribe el contenido del valor Tcl apuntado por writeObjPtr en el canal channel. Si el canal está abierto para escritura, se escriben todos los datos. Si el canal está bloqueado y no se pueden escribir todos los datos, la operación se detendrá después de escribir tantos datos como sea posible. El resto de los datos permanecerán en el búfer de salida y se escribirán en una llamada posterior a Tcl_WriteObj o Tcl_Flush.

El valor devuelto es el número de caracteres escritos en el canal. Se devuelve -1 si ocurre un error (por ejemplo, si se intenta escribir en un canal de solo lectura). Si ocurre un error, se establece el registro de errores del intérprete.

TCL_WRITECHARS

Tcl_WriteChars escribe hasta bytesToWrite caracteres del búfer charBuf en el canal channel. Si el canal está abierto para escritura, se escriben todos los datos. Si el canal está bloqueado y no se pueden escribir todos los datos, la operación se detendrá después de escribir tantos datos como sea posible. El resto de los datos permanecerán en el búfer de salida y se escribirán en una llamada posterior a Tcl_WriteChars o Tcl_Flush.

El valor devuelto es el número de caracteres escritos en el canal. Se devuelve -1 si ocurre un error (por ejemplo, si se intenta escribir en un canal de solo lectura). Si ocurre un error, se establece el registro de errores del intérprete.

TCL_WRITE

Tcl_Write escribe hasta bytesToWrite bytes del búfer byteBuf en el canal channel. A diferencia de Tcl_WriteChars, esta función siempre opera en modo binario y escribe bytes sin codificación. Si el canal está abierto para escritura, se escriben todos los datos. Si el canal está bloqueado y no se pueden escribir todos los datos, la operación se detendrá después de escribir tantos datos como sea posible. El resto de los datos permanecerán en el búfer de salida y se escribirán en una llamada posterior a Tcl_Write o Tcl_Flush.

El valor devuelto es el número de bytes escritos en el canal. Se devuelve -1 si ocurre un error (por ejemplo, si se intenta escribir en un canal de solo lectura). Si ocurre un error, se establece el registro de errores del intérprete.

TCL_READRAW

Tcl_ReadRaw lee hasta bytesToRead bytes del canal channel y los almacena en el búfer readBuf. Esto es idéntico a Tcl_Read.

TCL_WRITERAW

Tcl_WriteRaw escribe hasta bytesToWrite bytes del búfer byteBuf en el canal channel. Esto es idéntico a Tcl_Write.

TCL_EOF

Tcl_Eof devuelve 1 si se ha alcanzado el final del archivo en el canal channel, y 0 en caso contrario. El final del archivo se alcanza cuando una operación de lectura devuelve 0 bytes de datos.

TCL_FLUSH

Tcl_Flush fuerza la escritura de todos los datos en el búfer de salida del canal channel al dispositivo subyacente. Esto es útil para asegurarse de que los datos escritos sean visibles inmediatamente por otros procesos o por el sistema operativo.

El valor devuelto es TCL_OK si el búfer se vació correctamente, o TCL_ERROR si ocurrió un error. Si ocurre un error, se establece el registro de errores del intérprete.

TCL_INPUTBLOCKED

Tcl_InputBlocked devuelve 1 si una operación de lectura en el canal channel actualmente estaría bloqueada porque no hay datos disponibles, y 0 en caso contrario. Esto es útil para la E/S no bloqueante, para verificar si se puede leer más antes de intentar una lectura.

TCL_INPUTBUFFERED

Tcl_InputBuffered devuelve el número de bytes que están actualmente en el búfer de entrada del canal channel y que están listos para ser leídos sin necesidad de realizar una operación de E/S en el dispositivo subyacente.

TCL_OUTPUTBUFFERED

Tcl_OutputBuffered devuelve el número de bytes que están actualmente en el búfer de salida del canal channel y que aún no se han escrito en el dispositivo subyacente.

TCL_SEEK

Tcl_Seek establece la posición actual del archivo (el punto en el que se aplicará la próxima operación de lectura o escritura) en el canal channel. El nuevo punto de acceso se calcula sumando offset bytes a la posición dada por seekMode. Los valores legales para seekMode son SEEK_SET (desde el principio del archivo), SEEK_CUR (desde la posición actual) y SEEK_END (desde el final del archivo). El valor devuelto es la nueva posición del archivo en bytes, o -1 si ocurre un error.

TCL_TELL

Tcl_Tell devuelve la posición actual del archivo en el canal channel, en bytes desde el principio del archivo. Se devuelve -1 si ocurre un error.

TCL_TRUNCATECHANNEL

Tcl_TruncateChannel trunca el canal channel a la longitud especificada por length. Si la longitud actual es menor que length, el canal se extiende con bytes nulos. Si la longitud actual es mayor que length, el contenido del canal más allá de la nueva longitud se descarta. El valor devuelto es 0 si la operación tiene éxito, o -1 si ocurre un error.

TCL_GETCHANNELOPTION

Tcl_GetChannelOption recupera el valor de una opción para el canal channel. El argumento optionName especifica la opción a recuperar (por ejemplo, "-blocking"). El valor de la opción se almacena en la cadena dinámica Tcl apuntada por optionValue. Si se solicita una opción inexistente, se devuelve TCL_ERROR y se establece el registro de errores del intérprete.

Para obtener una lista de todas las opciones y sus valores, apague optionName a NULL. En este caso, todos los nombres de opciones y sus valores actuales se escribirán en optionValue, formateados como una lista de Tcl.

El valor devuelto es TCL_OK si la opción se recuperó correctamente, o TCL_ERROR si ocurrió un error.

TCL_SETCHANNELOPTION

Tcl_SetChannelOption establece el valor de una opción para el canal channel. El argumento optionName especifica la opción a establecer (por ejemplo, "-blocking"). El argumento newValue especifica el nuevo valor para la opción. Las opciones disponibles y sus valores permitidos son los mismos que los aceptados por el comando fconfigure.

El valor devuelto es TCL_OK si la opción se estableció correctamente, o TCL_ERROR si ocurrió un error (por ejemplo, si se intenta establecer una opción inválida o si el nuevo valor no es válido). Si ocurre un error, se establece el registro de errores del intérprete.

TCL_OPENFILECHANNEL

Tcl_OpenFileChannel abre un archivo especificado por fileName y devuelve un manejador de canal que puede ser utilizado para realizar operaciones de entrada y salida en el archivo. Esta API está modelada a partir del procedimiento fopen de la biblioteca de E/S estándar de Unix. La sintaxis y el significado de todos los argumentos son similares a los proporcionados en el comando open de Tcl al abrir un archivo. Si ocurre un error al abrir el canal, Tcl_OpenFileChannel devuelve NULL y registra un código de error POSIX que puede ser recuperado con Tcl_GetErrno. Además, si interp no es NULL, Tcl_OpenFileChannel deja un mensaje de error en el resultado de interp después de cualquier error. A partir de Tcl 8.4, se debe preferir la API basada en valores Tcl_FSOpenFileChannel sobre Tcl_OpenFileChannel siempre que sea posible.

El canal recién creado no se registra en el intérprete proporcionado; para registrarlo, use Tcl_RegisterChannel, descrito a continuación. Si uno de los canales estándar, stdin, stdout o stderr se cerró previamente, el acto de crear el nuevo canal también lo asigna como reemplazo para el canal estándar.

TCL_OPENCOMMANDCHANNEL

Tcl_OpenCommandChannel proporciona una interfaz de nivel C a las funciones de los comandos exec y open. Crea una secuencia de subprocesos especificados por los argumentos argv y argc y devuelve un canal que puede ser utilizado para comunicarse con estos subprocesos. El argumento flags indica qué tipo de comunicación existirá con la tubería de comandos.

Si se establece la bandera TCL_STDIN, la entrada estándar del primer subproceso se vinculará al canal: escribir en el canal proporcionará entrada al subproceso. Si TCL_STDIN no está establecida, la entrada estándar del primer subproceso será la misma que la entrada estándar de esta aplicación. Si se establece TCL_STDOUT, la salida estándar del último subproceso se puede leer del canal; de lo contrario, va a la salida estándar de esta aplicación. Si se establece TCL_STDERR, la salida de error estándar de todos los subprocesos se devuelve al canal y resulta en un error al cerrar el canal; de lo contrario, va al error estándar de esta aplicación. Si TCL_ENFORCE_MODE no está establecida, entonces argc y argv pueden redirigir los manejadores de stdio para anular TCL_STDIN, TCL_STDOUT y TCL_STDERR; si está establecida, entonces es un error que argc y argv anulen los canales de stdio para los cuales se han establecido TCL_STDIN, TCL_STDOUT y TCL_STDERR.

Si ocurre un error al abrir el canal, Tcl_OpenCommandChannel devuelve NULL y registra un código de error POSIX que puede ser recuperado con Tcl_GetErrno. Además, Tcl_OpenCommandChannel deja un mensaje de error en el resultado del intérprete. interp no puede ser NULL.

El canal recién creado no se registra en el intérprete proporcionado; para registrarlo, use Tcl_RegisterChannel, descrito a continuación. Si uno de los canales estándar, stdin, stdout o stderr se cerró previamente, el acto de crear el nuevo canal también lo asigna como reemplazo para el canal estándar.

TCL_MAKEFILECHANNEL

Tcl_MakeFileChannel crea un Tcl_Channel a partir de un manejador de archivo existente y específico de la plataforma. El canal recién creado no se registra en el intérprete proporcionado; para registrarlo, use Tcl_RegisterChannel, descrito a continuación. Si uno de los canales estándar, stdin, stdout o stderr se cerró previamente, el acto de crear el nuevo canal también lo asigna como reemplazo para el canal estándar.

TCL_GETCHANNEL

Tcl_GetChannel devuelve un canal dado el channelName utilizado para crearlo con Tcl_CreateChannel y un puntero a un intérprete de Tcl en interp. Si no hay un canal con ese nombre registrado en ese intérprete, el procedimiento devuelve NULL. Si el argumento modePtr no es NULL, apunta a una variable entera que recibirá una combinación OR de TCL_READABLE y TCL_WRITABLE describiendo si el canal está abierto para lectura y escritura.

Tcl_GetChannelNames y Tcl_GetChannelNamesEx escriben los nombres de los canales registrados en el resultado del intérprete como un valor de lista. Tcl_GetChannelNamesEx filtrará estos nombres según el pattern. Si pattern es NULL, no realizará ningún filtrado. El valor de retorno es TCL_OK si no ocurrieron errores al escribir en el resultado, de lo contrario es TCL_ERROR y el mensaje de error se deja en el resultado del intérprete.

TCL_REGISTERCHANNEL

Tcl_RegisterChannel agrega un canal al conjunto de canales accesibles en interp. Después de esta llamada, los programas de Tcl que se ejecutan en ese intérprete pueden referirse al canal en operaciones de entrada o salida utilizando el nombre dado en la llamada a Tcl_CreateChannel. Después de esta llamada, el canal se convierte en propiedad del intérprete, y el llamador no debe llamar a Tcl_Close para el canal; el canal se cerrará automáticamente cuando se desregistre del intérprete.

El código que se ejecuta fuera de cualquier intérprete de Tcl puede llamar a Tcl_RegisterChannel con interp como NULL, para indicar que desea mantener una referencia a este canal. Posteriormente, el canal puede registrarse en un intérprete de Tcl y solo se cerrará cuando el número correspondiente de llamadas a Tcl_UnregisterChannel se hayan realizado. Esto permite que el código que se ejecuta fuera de cualquier intérprete mantenga de forma segura una referencia a un canal que también está registrado en un intérprete de Tcl.

Este procedimiento interactúa con el código que administra los canales estándar. Si no se inicializaron canales estándar antes de la primera llamada a Tcl_RegisterChannel, se inicializarán con esa llamada. Consulte Tcl_StandardChannels para un tratado general sobre los canales estándar y el comportamiento de la biblioteca Tcl con respecto a ellos.

TCL_UNREGISTERCHANNEL

Tcl_UnregisterChannel elimina un canal del conjunto de canales accesibles en interp. Después de esta llamada, los programas de Tcl ya no podrán usar el nombre del canal para referirse al canal en ese intérprete. Si esta operación eliminó el último registro del canal en cualquier intérprete, el canal también se cierra y destruye.

El código no asociado con un intérprete de Tcl puede llamar a Tcl_UnregisterChannel con interp como NULL, para indicar a Tcl que ya no tiene una referencia a ese canal. Si esta es la última referencia al canal, ahora se cerrará. Tcl_UnregisterChannel es muy similar a Tcl_DetachChannel, excepto que también cerrará el canal si no existen más referencias a él.

TCL_DETACHCHANNEL

Tcl_DetachChannel elimina un canal del conjunto de canales accesibles en interp. Después de esta llamada, los programas de Tcl ya no podrán usar el nombre del canal para referirse al canal en ese intérprete. Más allá de eso, este comando no tiene ningún efecto adicional. No se puede utilizar en los canales estándar (stdout, stderr, stdin), y devolverá TCL_ERROR si se le pasa uno de esos canales.

El código no asociado con un intérprete de Tcl puede llamar a Tcl_DetachChannel con interp como NULL, para indicar a Tcl que ya no tiene una referencia a ese canal. Si esta es la última referencia al canal, a diferencia de Tcl_UnregisterChannel, no se cerrará.

TCL_ISSTANDARDCHANNEL

Tcl_IsStandardChannel prueba si un canal es uno de los tres canales estándar, stdin, stdout o stderr. Si es así, devuelve 1, de lo contrario 0.

No se hace ningún intento de verificar si el canal dado o los canales estándar están inicializados o son válidos de otra manera.

TCL_CLOSE

Tcl_Close destruye el canal channel, que debe denotar un canal actualmente abierto. El canal no debe estar registrado en ningún intérprete cuando se llama a Tcl_Close. La salida en búfer se vacía al dispositivo de salida del canal antes de destruir el canal, y la entrada en búfer se descarta. Si este es un canal bloqueante, la llamada no regresa hasta que todos los datos en búfer se envíen con éxito al dispositivo de salida del canal. Si este es un canal no bloqueante y hay salida en búfer que no se puede escribir sin bloquear, la llamada regresa inmediatamente; la salida se vacía en segundo plano y el canal se cerrará una vez que todos los datos en búfer se hayan enviado. En este caso, los errores durante el vaciado no se informan.

Si el canal se cerró correctamente, Tcl_Close devuelve TCL_OK. Si ocurre un error, Tcl_Close devuelve TCL_ERROR y registra un código de error POSIX que puede ser recuperado con Tcl_GetErrno. Si el canal se está cerrando de forma síncrona y ocurre un error durante el cierre del canal y interp no es NULL, se deja un mensaje de error en el resultado del intérprete.

Nota: no es seguro llamar a Tcl_Close en un canal que se ha registrado usando Tcl_RegisterChannel; consulte la documentación de Tcl_RegisterChannel, arriba, para obtener detalles. Si el canal se ha pasado alguna vez como argumento chan en una llamada a Tcl_RegisterChannel, debe usar Tcl_UnregisterChannel, que llamará internamente a Tcl_Close cuando todas las llamadas a Tcl_RegisterChannel se hayan correspondido con llamadas a Tcl_UnregisterChannel.

TCL_READCHARS Y TCL_READ

Tcl_ReadChars consume bytes del channel, convirtiendo los bytes a UTF-8 basándose en la codificación del canal y almacenando los datos producidos en la representación de cadena de readObjPtr. El valor de retorno de Tcl_ReadChars es el número de caracteres, hasta charsToRead, que se almacenaron en readObjPtr. Si ocurre un error al leer, el valor de retorno es -1 y Tcl_ReadChars registra un código de error POSIX que puede ser recuperado con Tcl_GetErrno.

TCL_READCHARS AND TCL_READ

Tcl_ReadChars lee hasta charsToRead caracteres del canal channel y los almacena en la representación interna del objeto en readObjPtr. Un valor de charsToRead de -1 hará que el comando lea todos los caracteres disponibles actualmente (no bloqueante) o todo hasta eof (modo bloqueante).

El valor de retorno puede ser menor que el valor a leer, lo que indica que menos datos de los solicitados estaban disponibles. Esto se denomina una lectura corta. En modo bloqueante, esto solo puede ocurrir en un fin de archivo. En modo no bloqueante, una lectura corta también puede ocurrir si no hay suficiente entrada disponible actualmente: Tcl_ReadChars devuelve un recuento corto en lugar de esperar más datos.

Si el canal está en modo bloqueante, un valor de retorno de cero indica una condición de fin de archivo. Si el canal está en modo no bloqueante, un valor de retorno de cero indica que no hay entrada disponible actualmente o una condición de fin de archivo. Use Tcl_Eof y Tcl_InputBlocked para saber cuál de estas condiciones ocurrió realmente.

Tcl_ReadChars traduce las diversas representaciones de fin de línea a la representación interna canónica de \n según el modo de reconocimiento de fin de línea actual. El reconocimiento de fin de línea y los diversos modos específicos de la plataforma se describen en la entrada del manual del comando Tcl fconfigure.

Como optimización de rendimiento, al leer de un canal con la codificación binary, los bytes no se convierten a UTF-8 a medida que se leen. En su lugar, se almacenan en la representación interna de readObjPtr como un valor de matriz de bytes. La representación de cadena de este valor solo se construirá si es necesaria (por ejemplo, debido a una llamada a Tcl_GetStringFromObj). De esta manera, los datos orientados a bytes se pueden leer de un canal, manipular llamando a Tcl_GetByteArrayFromObj y funciones relacionadas, y luego escribirlos en un canal sin el costo de la conversión a o desde UTF-8.

Tcl_Read es similar a Tcl_ReadChars, excepto que no realiza conversiones de codificación, independientemente de la codificación del canal. Está obsoleto y existe para compatibilidad con versiones anteriores de extensiones Tcl no internacionalizadas. Consume bytes del channel y los almacena en readBuf, realizando traducciones de fin de línea en el camino. El valor de retorno de Tcl_Read es el número de bytes, hasta bytesToRead, escritos en readBuf. El búfer producido por Tcl_Read no está terminado en nulo. Su contenido es válido desde la posición cero hasta, y sin incluir, la posición indicada por el valor de retorno.

Tcl_ReadRaw es lo mismo que Tcl_Read pero no compensa el apilamiento. Mientras que Tcl_Read (y las otras funciones de la API) siempre obtienen sus datos del canal superior en la pila de la que forma parte el canal proporcionado, Tcl_ReadRaw no lo hace. Por lo tanto, esta función solo es utilizable para controladores de canales transformacionales, es decir, controladores utilizados en medio de una pila de canales, para mover datos del canal inferior a la transformación.

TCL_GETSOBJ Y TCL_GETS

Tcl_GetsObj consume bytes del channel, convirtiendo los bytes a UTF-8 basándose en la codificación del canal, hasta que se haya visto una línea completa de entrada. Si la codificación del canal es binary, cada byte leído del canal se trata como un carácter Unicode individual. Todos los caracteres de la línea, excepto los caracteres de fin de línea terminadores, se añaden a la representación de cadena de lineObjPtr. Los caracteres de fin de línea se leen y se descartan.

Si se leyó una línea correctamente, el valor de retorno es mayor o igual a cero e indica el número de bytes almacenados en lineObjPtr. Si ocurre un error, Tcl_GetsObj devuelve -1 y registra un código de error POSIX que se puede recuperar con Tcl_GetErrno. Tcl_GetsObj también devuelve -1 si se llega al final del archivo; el procedimiento Tcl_Eof se puede utilizar para distinguir un error de una condición de fin de archivo.

Si el canal está en modo no bloqueante, el valor de retorno también puede ser -1 si no había datos disponibles o los datos que estaban disponibles no contenían un carácter de fin de línea. Cuando se devuelve -1, el procedimiento Tcl_InputBlocked puede invocarse para determinar si el canal está bloqueado debido a la falta de entrada disponible.

Tcl_Gets es lo mismo que Tcl_GetsObj excepto que los caracteres resultantes se añaden a la cadena dinámica dada por lineRead en lugar de un valor Tcl.

TCL_UNGETS

Tcl_Ungets se utiliza para añadir datos a la cola de entrada de un canal, ya sea al principio o al final de la cola. El puntero input apunta a los datos que se van a añadir. La longitud de la entrada a añadir se da por inputLen. Un valor distinto de cero de addAtEnd indica que los datos se añadirán al final de la cola; de lo contrario, se añadirán al principio de la cola. Si channel tiene un EOF "pegajoso" establecido, no se añadirán datos a la cola de entrada. Tcl_Ungets devuelve inputLen o -1 si ocurre un error.

TCL_WRITECHARS, TCL_WRITEOBJ, Y TCL_WRITE

Tcl_WriteChars acepta bytesToWrite bytes de datos de caracteres en charBuf. Los caracteres UTF-8 en el búfer se convierten a la codificación del canal y se ponen en cola para la salida al channel. Si bytesToWrite es negativo, Tcl_WriteChars espera que charBuf esté terminado en nulo y saca todo hasta el nulo.

Los datos en cola para la salida pueden no aparecer en el dispositivo de salida inmediatamente, debido al almacenamiento en búfer interno. Si los datos deben aparecer inmediatamente, llame a Tcl_Flush después de la llamada a Tcl_WriteChars, o establezca la opción -buffering en el canal a none. Si desea que los datos aparezcan tan pronto como se acepte una línea completa para la salida, establezca la opción -buffering en el canal en modo line.

El valor de retorno de Tcl_WriteChars es un recuento de cuántos bytes se aceptaron para la salida al canal. Esto es mayor que cero para indicar éxito o -1 para indicar que ocurrió un error. Si ocurre un error, Tcl_WriteChars registra un código de error POSIX que puede ser recuperado con Tcl_GetErrno.

Los caracteres de nueva línea en los datos de salida se traducen a secuencias de fin de línea específicas de la plataforma según la opción -translation para el canal. Esto se hace incluso si el canal no tiene codificación.

Tcl_WriteObj es similar a Tcl_WriteChars excepto que acepta un valor Tcl cuyos contenidos se sacarán al canal. Los caracteres UTF-8 en la representación de cadena de writeObjPtr se convierten a la codificación del canal y se ponen en cola para la salida al channel. Como optimización de rendimiento, al escribir en un canal con la codificación binary, los caracteres UTF-8 no se convierten a medida que se escriben. En su lugar, los bytes en la representación interna de writeObjPtr como un valor de matriz de bytes se escriben en el canal. La representación de matriz de bytes del valor se construirá si es necesaria. De esta manera, los datos orientados a bytes se pueden leer de un canal, manipular llamando a Tcl_GetByteArrayFromObj y funciones relacionadas, y luego escribir en un canal sin el costo de la conversión a o desde UTF-8.

Tcl_Write es similar a Tcl_WriteChars excepto que no realiza conversiones de codificación, independientemente de la codificación del canal. Está obsoleto y existe para compatibilidad con versiones anteriores de extensiones Tcl no internacionalizadas. Acepta bytesToWrite bytes de datos en byteBuf y los pone en cola para su salida al channel. Si bytesToWrite es negativo, Tcl_Write espera que byteBuf esté terminado en nulo y saca todo hasta el nulo.

Tcl_WriteRaw es lo mismo que Tcl_Write pero no compensa el apilamiento. Mientras que Tcl_Write (y las otras funciones de la API) siempre alimentan su entrada al canal superior en la pila de la que forma parte el canal proporcionado, Tcl_WriteRaw no lo hace. Por lo tanto, esta función solo es utilizable para controladores de canales transformacionales, es decir, controladores utilizados en medio de una pila de canales, para mover datos de la transformación al canal debajo de ella.

TCL_FLUSH

Tcl_Flush hace que todos los datos de salida en búfer para el channel se escriban en su archivo o dispositivo subyacente tan pronto como sea posible. Si el canal está en modo bloqueante, la llamada no retorna hasta que todos los datos en búfer se hayan enviado al canal o haya ocurrido algún error. La llamada retorna inmediatamente si el canal no está bloqueante; inicia un vaciado en segundo plano que escribirá los datos en búfer al canal eventualmente, tan rápido como el canal pueda absorberlo.

El valor de retorno es normalmente TCL_OK. Si ocurre un error, Tcl_Flush devuelve TCL_ERROR y registra un código de error POSIX que se puede recuperar con Tcl_GetErrno.

TCL_SEEK

Tcl_Seek mueve el punto de acceso en el channel donde se leerán o escribirán datos posteriores. La salida en búfer se vacía al canal y la entrada en búfer se descarta, antes de la operación de búsqueda.

Tcl_Seek normalmente devuelve el nuevo punto de acceso. Si ocurre un error, Tcl_Seek devuelve -1 y registra un código de error POSIX que se puede recuperar con Tcl_GetErrno. Después de un error, el punto de acceso puede o no haberse movido.

TCL_TELL

Tcl_Tell devuelve el punto de acceso actual para un canal. El valor devuelto es -1 si el canal no admite búsqueda.

TCL_TRUNCATECHANNEL

Tcl_TruncateChannel trunca el archivo subyacente del channel a una longitud dada de bytes. Devuelve TCL_OK si la operación tuvo éxito, y TCL_ERROR en caso contrario.

TCL_GETCHANNELOPTION

Tcl_GetChannelOption recupera, en optionValue, el valor de una de las opciones actualmente en vigor para un canal, o una lista de todas las opciones y sus valores. El argumento channel identifica el canal para el cual consultar una opción o recuperar todas las opciones y sus valores. Si optionName no es NULL, es el nombre de la opción a consultar; el valor de la opción se copia a la cadena dinámica Tcl denotada por optionValue. Si optionName es NULL, la función almacena una lista alterna de nombres de opciones y sus valores en optionValue.

, usando una serie de llamadas a Tcl_DStringAppendElement. Las diversas opciones preexistentes y sus posibles valores se describen en la entrada del manual del comando fconfigure de Tcl. Otras opciones pueden ser añadidas por cada tipo de canal. Estas opciones específicas del tipo de canal se describen en la entrada del manual del comando Tcl que crea un canal de ese tipo; por ejemplo, las opciones adicionales para canales basados en TCP se describen en la entrada del manual del comando socket de Tcl. El procedimiento normalmente devuelve TCL_OK. Si ocurre un error, devuelve TCL_ERROR y llama a Tcl_SetErrno para almacenar un código de error POSIX apropiado.

TCL_SETCHANNELOPTION

Tcl_SetChannelOption establece un nuevo valor newValue para una opción optionName en el canal channel. El procedimiento normalmente devuelve TCL_OK. Si ocurre un error, devuelve TCL_ERROR; además, si interp no es NULL, Tcl_SetChannelOption deja un mensaje de error en el resultado del intérprete.

TCL_EOF

Tcl_Eof devuelve un valor distinto de cero si channel encontró un fin de archivo durante la última operación de entrada.

TCL_INPUTBLOCKED

Tcl_InputBlocked devuelve un valor distinto de cero si channel está en modo no bloqueante y la última operación de entrada devolvió menos datos de los solicitados porque había datos insuficientes disponibles. La llamada siempre devuelve cero si el canal está en modo bloqueante.

TCL_INPUTBUFFERED

Tcl_InputBuffered devuelve el número de bytes de entrada actualmente en búfer en los búferes internos de un canal. Si el canal no está abierto para lectura, esta función siempre devuelve cero.

TCL_OUTPUTBUFFERED

Tcl_OutputBuffered devuelve el número de bytes de salida actualmente en búfer en los búferes internos de un canal. Si el canal no está abierto para escritura, esta función siempre devuelve cero.

PLATFORM ISSUES

Los manejadores devueltos por Tcl_GetChannelHandle dependen de la plataforma y del tipo de canal. En plataformas Unix, el manejador es siempre un descriptor de archivo Unix tal como se devuelve de la llamada al sistema open. En plataformas Windows, el manejador es un HANDLE de archivo cuando el canal se creó con Tcl_OpenFileChannel, Tcl_OpenCommandChannel o Tcl_MakeFileChannel. Otros tipos de canales pueden devolver un tipo diferente de manejador en plataformas Windows.
