ARGUMENTOS

Tcl_Interp *interp (salida)
Para procedimientos distintos de Tcl_FreeParse, Tcl_EvalTokens y Tcl_EvalTokensStandard, utilizado solo para reportar errores; si es NULL, entonces no se dejarán mensajes de error después de un error. Para Tcl_EvalTokens y Tcl_EvalTokensStandard, determina el contexto para evaluar el script y también se usa para reportar errores; no puede ser NULL.
const char *start (entrada)
Puntero al primer carácter en la cadena a parsear.
int numBytes (entrada)
Cantidad de bytes en la cadena a parsear, sin incluir el carácter nulo final. Si es menor que 0, el script consiste en todos los caracteres siguientes a start hasta el primer carácter nulo.
int nested (entrada)
Si es distinto de cero, significa que el script es parte de una sustitución de comandos, por lo que un corchete de cierre sin comillas debe tratarse como un terminador de comandos. Si es cero, los corchetes de cierre no tienen un significado especial.
int append (entrada)
Si es distinto de cero, significa que *parsePtr ya contiene tokens válidos; los nuevos tokens deben añadirse a los existentes. Cero significa que *parsePtr se inicializa; cualquier información en él se ignora. Este argumento es normalmente 0.
Tcl_Parse *parsePtr (salida)
Puntero a la estructura que se llenará con información sobre la estructura parseada del comando, expresión, nombre de variable, etc. Cualquier información previa en esta estructura se ignora, a menos que append no sea cero en una llamada a Tcl_ParseBraces, Tcl_ParseQuotedString o Tcl_ParseVarName.
const char **termPtr (salida)
Si no es NULL, apunta a un lugar donde Tcl_ParseBraces, Tcl_ParseQuotedString y Tcl_ParseVar almacenarán un puntero al carácter justo después del delimitador (el corchete de cierre, el último carácter del nombre de la variable o el corchete de cierre, respectivamente) si el parseo fue exitoso.
Tcl_Parse *usedParsePtr (entrada)
Puntero a la estructura que fue previamente llenada por una llamada a Tcl_ParseCommand, Tcl_ParseExpr, Tcl_ParseVarName, etc.

DESCRIPCIÓN

Estos procedimientos parsean comandos de Tcl o partes de comandos de Tcl como expresiones o referencias a variables. Cada procedimiento toma un puntero a un script (o parte de él) y llena la estructura apuntada por parsePtr con un conjunto de tokens que describen la información que fue parseada. Los procedimientos normalmente devuelven TCL_OK. Sin embargo, si ocurre un error, devuelven TCL_ERROR, dejando un mensaje de error en el resultado de interp (si interp no es NULL), y no dejando nada en parsePtr.

Tcl_ParseCommand es un procedimiento que parsea scripts de Tcl. Dado un puntero a un script, parsea el primer comando del script. Si el comando fue parseado con éxito, Tcl_ParseCommand devuelve TCL_OK y llena la estructura apuntada por parsePtr con información sobre la estructura del comando (ver detalles más abajo). Si ocurrió un error durante el parseo del comando, devuelve TCL_ERROR, deja un mensaje de error en el resultado de interp, y no deja nada en parsePtr.

Tcl_ParseExpr parsea expresiones de Tcl. Dado un puntero a un script que contiene una expresión, Tcl_ParseExpr parsea la expresión. Si la expresión fue parseada con éxito, Tcl_ParseExpr devuelve TCL_OK y llena la estructura apuntada por parsePtr con información sobre la estructura de la expresión (ver detalles más abajo). Si ocurrió un error durante el parseo, devuelve TCL_ERROR, deja un mensaje de error en el resultado de interp, y no deja nada en parsePtr.

Tcl_ParseBraces parsea una cadena o argumento de comando entre corchetes, como {hola} o {cadena \t con \t tabulaciones}, comenzando desde el principio de su argumento start. El primer carácter de start debe ser {. Si la cadena entre corchetes fue parseada con éxito, Tcl_ParseBraces devuelve TCL_OK, llena la estructura apuntada por parsePtr con información sobre la estructura de la cadena (ver detalles más abajo), y almacena un puntero al carácter justo después del delimitador } en la ubicación dada por *termPtr. Si ocurre un error durante el parseo de la cadena, devuelve TCL_ERROR, deja un mensaje de error en el resultado de interp, y no deja nada en parsePtr o *termPtr.

Tcl_ParseQuotedString parsea una cadena entre comillas dobles, como "la suma es [expr {$a+$b}]", comenzando desde el principio del argumento start. El primer carácter de start debe ser ". Si la cadena entre comillas dobles fue parseada con éxito, Tcl_ParseQuotedString devuelve TCL_OK, llena la estructura apuntada por parsePtr con información sobre la estructura de la cadena (ver detalles más abajo), y almacena un puntero al carácter justo después del delimitador " en la ubicación dada por *termPtr. Si ocurre un error durante el parseo de la cadena, devuelve TCL_ERROR, deja un mensaje de error en el resultado de interp, y no deja nada en parsePtr o *termPtr.

Tcl_ParseVarName parsea una referencia a una variable Tcl, como $abc o $x([expr {$índice + 1}]), comenzando desde el principio de su argumento start. El primer carácter de start debe ser $. Si la variable fue parseada con éxito, Tcl_ParseVarName devuelve TCL_OK y llena la estructura apuntada por parsePtr con información sobre la estructura de la variable (ver detalles más abajo). Si ocurrió un error durante el parseo, devuelve TCL_ERROR, deja un mensaje de error en el resultado de interp (si interp no es NULL), y no deja nada en parsePtr.

Tcl_ParseVar parsea una referencia a una variable Tcl, como $abc o $x([expr {$índice + 1}]), comenzando desde el principio de su argumento start. El primer carácter de start debe ser $. Si la variable fue parseada con éxito, devuelve un puntero al valor de la variable. Si ocurre un error durante el parseo, devuelve NULL y deja un mensaje de error en el resultado de interp.

La información en *parsePtr dejada por Tcl_ParseCommand, Tcl_ParseExpr, Tcl_ParseBraces, Tcl_ParseQuotedString y Tcl_ParseVarName puede incluir memoria dinámica. Si estos cinco procedimientos de parseo devuelven TCL_OK, el llamador debe invocar Tcl_FreeParse para liberar el espacio en *parsePtr. Estos procedimientos ignoran cualquier información existente en *parsePtr (a menos que append no sea cero), por lo que si se realizan múltiples llamadas a cualquiera de ellos, se debe invocar Tcl_FreeParse una vez después de cada llamada.

Tcl_EvalTokensStandard evalúa una secuencia de tokens parseados de una estructura de Tcl. Los tokens suelen consistir en todos los tokens de una palabra o todos los tokens que componen el índice de una referencia a una variable de tipo array. Tcl_EvalTokensStandard realiza las sustituciones solicitadas por los tokens y concatena los valores resultantes. El valor devuelto por Tcl_EvalTokensStandard es un código de finalización de Tcl con uno de los valores TCL_OK, TCL_ERROR, TCL_RETURN, TCL_BREAK, o TCL_CONTINUE, o tal valor podría ser otro valor entero originado en una extensión. Además, un valor de resultado o un mensaje de error se deja en el resultado de interp; puede recuperarse usando Tcl_GetObjResult.

Tcl_EvalTokens difiere de Tcl_EvalTokensStandard solo en el valor devuelto.

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

La convención utilizada devuelve el resultado en un nuevo Tcl_Obj. El contador de referencias del valor devuelto como resultado ha sido incrementado, por lo que el llamador debe invocar Tcl_DecrRefCount cuando finalice con el valor. Si ocurre un error u otra excepción durante la evaluación de los tokens (como una referencia a una variable no existente), el valor devuelto es NULL y un mensaje de error queda en el interp. El uso de Tcl_EvalTokens está obsoleto.

ESTRUCTURA DE PARSEO DE TCL

Tcl_ParseCommand, Tcl_ParseExpr, Tcl_ParseBraces, Tcl_ParseQuotedString y Tcl_ParseVarName devuelven información de análisis en dos estructuras, Tcl_Parse y Tcl_Token:

typedef struct Tcl_Parse {
    const char *commentStart;
    int commentSize;
    const char *commandStart;
    int commandSize;
    int numWords;
    Tcl_Token *tokenPtr;
    int numTokens;
    ...
} Tcl_Parse;
typedef struct Tcl_Token {
    int type;
    const char *start;
    int size;
    int numComponents;
} Tcl_Token;

Los primeros cinco campos de una estructura Tcl_Parse se completan solo por Tcl_ParseCommand. Estos campos no son utilizados por otros procedimientos de análisis.

Tcl_ParseCommand completa una estructura Tcl_Parse con información que describe un comando Tcl y cualquier comentario que preceda al comando. Si hay comentarios, commentStart apunta al carácter # que inicia el primer comentario y commentSize indica el número de bytes en todos los comentarios anteriores al comando, incluido el carácter de nueva línea que finaliza el último comentario. Si el comando no está precedido por comentarios, commentSize es 0. Tcl_ParseCommand también establece commandStart para apuntar al primer carácter de la primera palabra del comando (saltándose comentarios y espacios en blanco iniciales) y commandSize da el número total de bytes del comando, incluido el carácter al que apunta commandStart hasta el carácter de nueva línea, corchete de cierre o punto y coma que finaliza el comando. El campo numWords da el número total de palabras del comando.

Todos los procedimientos de análisis establecen los campos restantes, tokenPtr y numTokens. El campo tokenPtr apunta al primer elemento de un array de estructuras Tcl_Token que describen los componentes de la entidad que se está analizando. El campo numTokens da el número total de tokens presentes en el array. Cada token contiene cuatro campos. El campo type selecciona uno de varios tipos de token que se describen a continuación. El campo start apunta al primer carácter del token y el campo size da el número total de caracteres del token. Algunos tipos de token, como TCL_TOKEN_WORD y TCL_TOKEN_VARIABLE, constan de varios componentes de token, que siguen inmediatamente al token padre; el campo numComponents describe cuántos de estos hay. El campo type tiene uno de los siguientes valores:

TCL_TOKEN_WORD
Este token generalmente describe una palabra de un comando, pero también puede describir una cadena entre comillas o entre llaves en una expresión. El token describe un componente del script que es el resultado de concatenar una secuencia de subcomponentes, cada uno descrito por un subtoken separado. El token comienza con el primer carácter no blanco del componente (que puede ser una comilla doble o un corchete de apertura) e incluye todos los caracteres del componente hasta el espacio, punto y coma, corchete de cierre, comilla de cierre o corchete de cierre que finaliza el componente. El campo numComponents cuenta el número total de subtokens que forman la palabra, incluidos los subtokens de los tokens TCL_TOKEN_VARIABLE y TCL_TOKEN_BS.
TCL_TOKEN_SIMPLE_WORD
Este token tiene el mismo significado que TCL_TOKEN_WORD, excepto que se garantiza que la palabra consistirá en un único sub-token TCL_TOKEN_TEXT. El campo numComponents es siempre 1.
TCL_TOKEN_EXPAND_WORD
Este token tiene el mismo significado que TCL_TOKEN_WORD, excepto que el analizador de comandos nota que esta palabra comenzó con el prefijo de expansión {*}, lo que indica que después de la sustitución, el valor de lista de esta palabra debe expandirse para formar múltiples argumentos en la evaluación del comando. Este tipo de token solo puede ser creado por Tcl_ParseCommand.
TCL_TOKEN_TEXT
El token describe un rango de texto literal que forma parte de una palabra. El campo numComponents es siempre 0.
TCL_TOKEN_BS
El token describe una secuencia de barra invertida como \n o \0xA3. El campo numComponents es siempre 0.
TCL_TOKEN_COMMAND
El token describe un comando cuyo resultado debe sustituirse en la palabra. El token incluye los corchetes que rodean al comando. El campo numComponents es siempre 0 (el comando anidado no se analiza; si desea ver sus tokens, llame recursivamente a Tcl_ParseCommand).
TCL_TOKEN_VARIABLE
El token describe una sustitución de variable, incluyendo el $, el nombre de la variable y el índice de array (si existe) hasta el corchete de cierre que finaliza el índice. Este token va seguido de uno o más tokens adicionales que describen el nombre de la variable y el índice. Si numComponents es 1, la variable es escalar y el siguiente token es un TCL_TOKEN_TEXT que da el nombre de la variable. Si numComponents es mayor que 1, la variable es un array: el primer subtoken es un TCL_TOKEN_TEXT que da el nombre del array y los subtokens restantes son TCL_TOKEN_TEXT, TCL_TOKEN_BS, TCL_TOKEN_COMMAND y TCL_TOKEN_VARIABLE que deben concatenarse para producir el índice del array. El campo numComponents incluye los subtokens que forman parte de TCL_TOKEN_VARIABLE en el índice del array.
TCL_TOKEN_SUB_EXPR
El token describe una subexpresión de una expresión (o toda la expresión). Una subexpresión puede consistir en un valor como un literal entero, una sustitución de variable o una subexpresión entre paréntesis; también puede consistir en un operador y sus operandos. El token comienza con el primer carácter no blanco de la subexpresión hasta el espacio, corchete, paréntesis de cierre o corchete de cierre que finaliza la subexpresión. Este token va seguido de uno o más tokens adicionales que describen la subexpresión. Si el primer subtoken después del token TCL_TOKEN_SUB_EXPR es un token TCL_TOKEN_OPERATOR, la subexpresión consiste en un operador y sus operandos. Si el operador no tiene operandos, la subexpresión consiste únicamente en el token TCL_TOKEN_OPERATOR. Cada operando se describe mediante un token TCL_TOKEN_SUB_EXPR. De lo contrario, la subexpresión es un valor descrito por uno de los tipos de token TCL_TOKEN_WORD, TCL_TOKEN_TEXT, TCL_TOKEN_BS, TCL_TOKEN_COMMAND, TCL_TOKEN_VARIABLE o TCL_TOKEN_SUB_EXPR. El campo numComponents cuenta el número total de subtokens que componen la subexpresión; esto incluye los subtokens de cualquier TCL_TOKEN_SUB_EXPR anidado.
TCL_TOKEN_OPERATOR
El token describe un operador de una expresión como && o hypot. Un token TCL_TOKEN_OPERATOR siempre va precedido por un token TCL_TOKEN_SUB_EXPR que describe el operador y sus operandos; el campo numComponents del token TCL_TOKEN_SUB_EXPR se puede usar para determinar el número de operandos. Un operador binario como * va seguido de dos tokens TCL_TOKEN_SUB_EXPR que describen sus operandos. Un operador unario como - va seguido de un único token TCL_TOKEN_SUB_EXPR que describe su operando. Si el operador es una función matemática como log10, el token TCL_TOKEN_OPERATOR dará su nombre y los siguientes tokens TCL_TOKEN_SUB_EXPR describirán sus operandos; si no hay operandos (como con rand), no hay tokens TCL_TOKEN_SUB_EXPR siguientes. Hay una operación ternaria, ?, que aparece en expresiones condicionales como x?y:z; en este caso, el token ? TCL_TOKEN_OPERATOR va seguido de tres tokens TCL_TOKEN_SUB_EXPR para los operandos x, y y z. El campo numComponents del token TCL_TOKEN_OPERATOR es siempre 0.

Después de que Tcl_ParseCommand devuelva, el primer token al que apunta el campo tokenPtr de la estructura Tcl_Parse siempre tiene el tipo TCL_TOKEN_WORD, TCL_TOKEN_SIMPLE_WORD o TCL_TOKEN_EXPAND_WORD. Le siguen los subtokens que deben concatenarse para producir el valor de esa palabra. El siguiente token es el TCL_TOKEN_WORD, TCL_TOKEN_SIMPLE_WORD o TCL_TOKEN_EXPAND_WORD de la segunda palabra, seguido de sus subtokens, y así sucesivamente hasta que se cuenten todas las numWords.

Después de que Tcl_ParseExpr devuelva, el primer token al que apunta el campo tokenPtr de la estructura Tcl_Parse siempre tiene el tipo TCL_TOKEN_SUB_EXPR. Le siguen los subtokens que deben evaluarse para producir el valor de la expresión. Solo la información de token en la estructura Tcl_Parse se modifica: los campos commentStart, commentSize, commandStart y commandSize no son modificados por Tcl_ParseExpr.

Después de que Tcl_ParseBraces devuelva, el array de tokens al que apunta el campo tokenPtr de la estructura Tcl_Parse contendrá un único token TCL_TOKEN_TEXT si la cadena entre llaves no contiene ninguna secuencia entre comillas. Si la cadena contiene secuencias entre comillas, el array de tokens contendrá uno o más subtokens TCL_TOKEN_TEXT o TCL_TOKEN_BS que deben concatenarse para producir el valor de la cadena. Si la cadena entre llaves era solo {} (es decir, la cadena estaba vacía), el único token TCL_TOKEN_TEXT contendrá un campo size con 0; esto asegura que aparezca al menos un token para describir la cadena entre llaves. Solo la información de token en la estructura Tcl_Parse se modifica: los campos commentStart, commentSize, commandStart y commandSize no son modificados por Tcl_ParseExpr.

Descripción

Después de que Tcl_ParseQuotedString retorna, el array de tokens apuntado por el campo tokenPtr de la estructura Tcl_Parse depende del contenido de la cadena entrecomillada. Consistirá en uno o más sub-tokens TCL_TOKEN_TEXT, TCL_TOKEN_BS, TCL_TOKEN_COMMAND y TCL_TOKEN_VARIABLE. El array siempre contiene al menos un token; por ejemplo, si el argumento start está vacío, el array devuelto consiste en un único token TCL_TOKEN_TEXT con un campo size de cero. Solo la información del token en la estructura Tcl_Parse se modifica: los campos commentStart, commentSize, commandStart y commandSize no se modifican.

Después de que Tcl_ParseVarName retorna, el primer token apuntado por el campo tokenPtr de la estructura Tcl_Parse siempre tiene el tipo TCL_TOKEN_VARIABLE. Le siguen los sub-tokens que componen el nombre de la variable, como se describe anteriormente. La longitud total del nombre de la variable está contenida en el campo size del primer token. Al igual que en Tcl_ParseExpr, solo la información del token en la estructura Tcl_Parse es modificada por Tcl_ParseVarName: los campos commentStart, commentSize, commandStart y commandSize no se modifican.

Todos los punteros de caracteres en las estructuras Tcl_Parse y Tcl_Token se refieren a caracteres en el argumento start pasado a Tcl_ParseCommand, Tcl_ParseExpr, Tcl_ParseBraces, Tcl_ParseQuotedString y Tcl_ParseVarName.

Hay campos adicionales en la estructura Tcl_Parse después del campo numTokens, pero estos son para uso privado de Tcl_ParseCommand, Tcl_ParseExpr, Tcl_ParseBraces, Tcl_ParseQuotedString y Tcl_ParseVarName; no deben ser referenciados por código fuera de estos procedimientos.
