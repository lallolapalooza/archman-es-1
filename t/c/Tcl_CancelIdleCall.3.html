Tcl_DoWhenIdle(3) Procedimientos de la biblioteca Tcl Tcl_DoWhenIdle(3)

NOMBRE

Tcl_DoWhenIdle, Tcl_CancelIdleCall - invoca un procedimiento cuando no hay eventos pendientes

SINOPSIS

#include <tcl.h>

Tcl_DoWhenIdle(proc, clientData)

Tcl_CancelIdleCall(proc, clientData)

ARGUMENTOS

Tcl_IdleProc *proc (entrada)
Procedimiento a invocar.
ClientData clientData (entrada)
Valor arbitrario de una palabra para pasar a proc.

DESCRIPCIÓN

Tcl_DoWhenIdle organiza que proc se invoque cuando la aplicación queda inactiva. La aplicación se considera inactiva cuando se ha llamado a Tcl_DoOneEvent, no se han encontrado eventos para manejar y está a punto de dormirse esperando que ocurra un evento. En este punto, se invocan todos los manejadores pendientes de Tcl_DoWhenIdle. Por cada llamada a Tcl_DoWhenIdle habrá una única llamada a proc; después de que se invoque proc, el manejador se elimina automáticamente. Tcl_DoWhenIdle solo es utilizable en programas que utilizan Tcl_DoOneEvent para distribuir eventos.

Proc debe tener argumentos y resultado que coincidan con el tipo Tcl_IdleProc:

typedef void Tcl_IdleProc(
        ClientData clientData);

El parámetro clientData de proc es una copia del argumento clientData dado a Tcl_DoWhenIdle. Típicamente, clientData apunta a una estructura de datos que contiene información específica de la aplicación sobre lo que debe hacer proc.

Tcl_CancelIdleCall se puede utilizar para cancelar una o más llamadas anteriores a Tcl_DoWhenIdle: si hay un manejador de Tcl_DoWhenIdle registrado para proc y clientData, entonces se elimina sin invocarlo. Si hay más de un manejador en la lista de inactividad que se refiere a proc y clientData, se eliminan todos los manejadores. Si no hay manejadores existentes que coincidan con proc y clientData, no sucede nada.

Tcl_DoWhenIdle es más útil en situaciones donde (a) habrá que realizar un trabajo pero (b) es posible que algo suceda en un futuro cercano que cambie lo que debe hacerse o requiera que se haga algo diferente. Tcl_DoWhenIdle permite que el trabajo real se posponga hasta que se hayan procesado todos los eventos pendientes. En ese punto, presumiblemente se conocerá el trabajo exacto a realizar y se podrá hacer exactamente una vez.

Por ejemplo, un editor podría usar Tcl_DoWhenIdle para posponer las actualizaciones de la pantalla hasta que se hayan procesado todos los comandos pendientes. Sin esta característica, podrían ocurrir redibujos redundantes en algunas situaciones, como el procesamiento de un archivo de comandos.

ERRORES

En la actualidad, no es seguro que una llamada de inactividad se reschedule continuamente. Esto interactuará mal con ciertas características de Tk que intentan esperar a que todas las llamadas de inactividad se completen. Si desea que una llamada de inactividad se reschedule continuamente, es mejor utilizar un manejador de temporizador con un período de tiempo de espera de cero.
