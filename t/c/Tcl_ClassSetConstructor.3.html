DESCRIPCIÓN

Un método es una operación que se realiza sobre un objeto y que está asociada al objeto. Cada método debe estar asociado a un objeto o a una clase; los métodos asociados a una clase están asociados a todas las instancias (directas e indirectas) de esa clase.

Dado un método, la entidad que lo declaró se puede encontrar usando Tcl_MethodDeclarerClass, que devuelve la clase a la que está asociado el método (o NULL si el método no está asociado a ninguna clase), y Tcl_MethodDeclarerObject, que devuelve el objeto al que está asociado el método (o NULL si el método no está asociado a un objeto). El nombre del método se puede obtener con Tcl_MethodName y si el método está exportado se obtiene con Tcl_MethodIsPublic. El tipo del método también se puede introspeccionar hasta cierto punto; la función Tcl_MethodIsType indica si un método es de un tipo particular, asignando los clientData por método a la variable apuntada por clientDataPtr si (y solo si este es distinto de NULL) el tipo coincide.

CREACIÓN DE MÉTODOS

Los métodos se crean mediante Tcl_NewMethod y Tcl_NewInstanceMethod, que crean un método asociado a una clase o a un objeto respectivamente. En ambos casos, el argumento nameObj indica el nombre del método a crear, el argumento isPublic especifica si el método debe exportarse inicialmente, el argumento methodTypePtr describe la implementación del método (ver la sección TIPOS DE MÉTODOS más abajo) y el argumento clientData proporciona datos específicos de la implementación que se pasan a la implementación del método cuando se llama a ésta.

Cuando el argumento nameObj para Tcl_NewMethod es NULL, se crea un método sin nombre, que se utiliza para constructores y destructores. Los constructores deben instalarse en su clase usando la función Tcl_ClassSetConstructor, y los destructores (que no deben requerir ningún argumento) deben instalarse en su clase usando la función Tcl_ClassSetDestructor. Los métodos sin nombre no deben utilizarse para ningún otro propósito, y los métodos con nombre no deben utilizarse como constructores ni destructores. Tenga en cuenta también que un methodTypePtr NULL se utiliza para proporcionar una señalización interna y no debe utilizarse en código cliente.

CONTEXTOS DE LLAMADA A MÉTODOS

Cuando se llama a un método, se pasa una referencia de contexto de llamada a método como uno de los argumentos a la función de implementación. Este contexto se puede inspeccionar para proporcionar información sobre el llamador, pero no debe conservarse más allá del momento en que finaliza la llamada al método.

El método que se está llamando se puede obtener del contexto usando Tcl_ObjectContextMethod, y el objeto que provocó la invocación del método se puede obtener con Tcl_ObjectContextObject. El número de argumentos que se deben omitir (por ejemplo, el nombre del objeto y el nombre del método en una llamada a método normal) se lee con Tcl_ObjectContextSkippedArgs, y el contexto también puede informar si está funcionando como un filtro para otro método a través de Tcl_ObjectContextIsFiltering.

Durante la ejecución de un método, la implementación del método puede optar por invocar las etapas de la cadena de llamadas de métodos que siguen a la implementación del método actual. Esto (el núcleo del comando next) se hace usando Tcl_ObjectContextInvokeNext. Tenga en cuenta que esta función no manipula la pila de marcos de llamada, a diferencia del comando next; si la implementación del método ha empujado uno o más marcos adicionales en la pila como parte de su implementación, también es responsable de extraer temporalmente esos marcos de la pila mientras se ejecuta la función Tcl_ObjectContextInvokeNext. Tenga en cuenta también que el contexto de llamada a método nunca se elimina durante la ejecución de esta función.

TIPOS DE MÉTODOS

Los tipos de métodos se describen mediante un puntero a una estructura Tcl_MethodType, que se define como:

typedef struct {
    int version;
    const char *name;
    Tcl_MethodCallProc *callProc;
    Tcl_MethodDeleteProc *deleteProc;
    Tcl_CloneProc *cloneProc;
} Tcl_MethodType;

El campo version permite la expansión futura de la estructura y siempre debe declararse igual a TCL_OO_METHOD_VERSION_CURRENT. El campo name proporciona un nombre legible por humanos para el tipo y es el valor que se expone a través de los comandos Tcl info class methodtype y info object methodtype.

El campo callProc proporciona una función que se llama cuando se invoca el método; nunca debe ser NULL.

El campo deleteProc proporciona una función que se utiliza para eliminar un método particular y se llama cuando el método se reemplaza o elimina; si el campo es NULL, se asume que el clientData del método no necesita ninguna acción especial para eliminarse.

El campo cloneProc es una función que se utiliza para copiar el clientData de un método (como parte de Tcl_CopyObjectInstance) o NULL para indicar que el clientData se puede copiar directamente.

FIRMA DE FUNCIÓN DE Tcl_MethodCallProc

La firma de la función a la que apunta callProc es:

typedef int Tcl_MethodCallProc(
        ClientData clientData,
        Tcl_Interp *interp,
        int objc,
        Tcl_Obj *const objv[]);

El parámetro clientData es el valor que se proporcionó cuando se creó el método. El parámetro interp es el intérprete en el que se está ejecutando el método. Los parámetros objc y objv son el número y los argumentos de la llamada al método respectivamente.

FIRMA DE FUNCIÓN DE Tcl_MethodDeleteProc

La firma de la función a la que apunta deleteProc es:

typedef void Tcl_MethodDeleteProc(
        ClientData clientData);

El parámetro clientData es el valor que se proporcionó cuando se creó el método.

FIRMA DE FUNCIÓN DE Tcl_CloneProc

La firma de la función a la que apunta cloneProc es:

typedef ClientData Tcl_CloneProc(
        ClientData clientData,
        Tcl_Interp *interp);

El parámetro clientData es el valor que se proporcionó cuando se creó el método. El parámetro interp es el intérprete en el que se está realizando la clonación.

DESCRIPTION

The TclOO object system provides a powerful mechanism for defining and managing methods within classes and objects. The functions described here allow for the programmatic definition, deletion, and invocation of these methods.

Tcl_ClassSetConstructor

This function associates a constructor procedure with a given class. When an object of this class is created, the specified procedure will be invoked.

Tcl_ClassSetMethod

This function defines a method for a given class. The method is identified by its name and is implemented by the provided procedure. The deleteProc is called when the method is unset or when the class is destroyed.

Tcl_ClassUnsetMethod

This function removes a method from a class. If a deleteProc was associated with the method, it will be called.

Tcl_ObjectSetMethod

This function defines a method specifically for a given object, overriding any class-level methods with the same name. The deleteProc is called when the method is unset or when the object is destroyed.

Tcl_ObjectUnsetMethod

This function removes a method from a specific object.

Tcl_MethodObjectKind

This function is used to specify the kind of a method associated with a class. The kind determines how the method is inherited and dispatched. Common kinds include "constructor", "destructor", and "normal".

Tcl_MethodObjectKindForClass

Similar to Tcl_MethodObjectKind, but operates on a class object pointer.

Tcl_ObjectMethodDeclarations

Returns a Tcl object containing a list of all methods declared for a given object, including inherited methods.

Tcl_ClassMethodDeclarations

Returns a Tcl object containing a list of all methods declared for a given class, including inherited methods.

Tcl_MethodInvoke

This function directly invokes a method within a given context. It is useful for internal Tcl implementation or advanced extension development.

METHOD TYPES

TCL_METHODCALLPROC FUNCTION SIGNATURE

Functions matching this signature are called when the method is invoked.

typedef int Tcl_MethodCallProc(
        ClientData clientData,
        Tcl_Interp *interp,
        Tcl_ObjectContext objectContext,
        int objc,
        Tcl_Obj *const *objv);

The clientData argument to a Tcl_MethodCallProc is the value that was given when the method was created, the interp is a place in which to execute scripts and access variables as well as being where to put the result of the method, and the objc and objv fields give the parameter objects to the method. The calling context of the method can be discovered through the objectContext argument, and the return value from a Tcl_MethodCallProc is any Tcl return code (e.g. TCL_OK, TCL_ERROR).

TCL_METHODDELETEPROC FUNCTION SIGNATURE

Functions matching this signature are used when a method is deleted, whether through a new method being created or because the object or class is deleted.

typedef void Tcl_MethodDeleteProc(
        ClientData clientData);

The clientData argument to a Tcl_MethodDeleteProc will be the same as the value passed to the clientData argument to Tcl_NewMethod or Tcl_NewInstanceMethod when the method was created.

TCL_CLONEPROC FUNCTION SIGNATURE

Functions matching this signature are used to copy a method when the object or class is copied using Tcl_CopyObjectInstance (or oo::copy).

typedef int Tcl_CloneProc(
        Tcl_Interp *interp,
        ClientData oldClientData,
        ClientData *newClientDataPtr);

The interp argument gives a place to write an error message when the attempt to clone the object is to fail, in which case the clone procedure must also return TCL_ERROR; it should return TCL_OK otherwise. The oldClientData field to a Tcl_CloneProc gives the value from the method being copied from, and the newClientDataPtr field will point to a variable in which to write the value for the method being copied to.
