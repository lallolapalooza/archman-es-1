#include <tcl.h>

Tcl_SetObjResult(interp, objPtr)

Tcl_Obj *
Tcl_GetObjResult(interp)

const char *
Tcl_GetStringResult(interp)

Tcl_AppendResult(interp, result, result, ... , (char *)NULL)

Tcl_AppendResultVA(interp, argList)

Tcl_ResetResult(interp)

Tcl_TransferResult(sourceInterp, code, targetInterp)

Tcl_AppendElement(interp, element)

ARGUMENTOS

Tcl_Interp *interp (salida)
Intérprete cuyo resultado se va a modificar o leer.
Tcl_Obj *objPtr (entrada)
Valor Tcl que se convertirá en el resultado para interp.
char *result (entrada)
Valor de cadena que se convertirá en el resultado para interp o que se añadirá al resultado existente.
const char *element (entrada)
Valor de cadena que se añadirá como elemento de lista al resultado existente de interp.
Tcl_FreeProc *freeProc (entrada)
Dirección del procedimiento que se llamará para liberar el almacenamiento en result, o TCL_STATIC, TCL_DYNAMIC o TCL_VOLATILE.
va_list argList (entrada)
Una lista de argumentos que debe haber sido inicializada usando va_start, y limpiada usando va_end.
Tcl_Interp *sourceInterp (entrada)
Intérprete del que se transferirán el resultado y las opciones de retorno.
Tcl_Interp *targetInterp (entrada)
Intérprete al que se transferirán el resultado y las opciones de retorno.
int code (entrada)
Valor del código de retorno que controla la transferencia de opciones de retorno.

DESCRIPCIÓN

Los procedimientos descritos aquí son utilidades para manipular el valor de resultado en un intérprete Tcl. El resultado del intérprete puede ser un valor Tcl o una cadena. Por ejemplo, Tcl_SetObjResult y Tcl_SetResult establecen el resultado del intérprete a un valor y a una cadena respectivamente. De manera similar, Tcl_GetObjResult y Tcl_GetStringResult devuelven el resultado del intérprete como valor y como cadena. Los procedimientos siempre mantienen consistentes las formas de cadena y valor del resultado del intérprete. Por ejemplo, si se llama a Tcl_SetObjResult para establecer el resultado a un valor, y luego se llama a Tcl_GetStringResult, devolverá la representación de cadena del valor.

Tcl_SetObjResult organiza para que objPtr sea el resultado de interp, reemplazando cualquier resultado existente. El resultado se deja apuntando al valor referenciado por objPtr. El contador de referencias de objPtr se incrementa ya que ahora hay una nueva referencia a él desde interp. El contador de referencias de cualquier valor de resultado antiguo se decrementa y el valor de resultado antiguo se libera si no quedan referencias a él.

Tcl_GetObjResult devuelve el resultado de interp como un valor. El contador de referencias del valor no se incrementa; si la llamada necesita retener un puntero a largo plazo al valor, debe usar Tcl_IncrRefCount para incrementar su contador de referencias para evitar que se libere demasiado pronto o se cambie accidentalmente.

Tcl_SetResult organiza para que result sea el resultado del comando Tcl actual en interp, reemplazando cualquier resultado existente. El argumento freeProc especifica cómo gestionar el almacenamiento para el argumento result; se discute en la sección EL ARGUMENTO TCL_FREEPROC PARA TCL_SETRESULT a continuación. Si result es NULL, entonces freeProc se ignora y Tcl_SetResult re-inicializa el resultado de interp para que apunte a una cadena vacía.

Tcl_GetStringResult devuelve el resultado de interp como una cadena. Si el resultado se estableció como un valor mediante una llamada a Tcl_SetObjResult, la forma de valor se convertirá a una cadena y se devolverá. Si la representación de cadena del valor contiene bytes nulos, esta conversión perderá información. Por esta razón, se anima a los programadores a escribir su código para utilizar los nuevos procedimientos de API de valor y a llamar a Tcl_GetObjResult en su lugar.

Tcl_ResetResult borra el resultado de interp y deja el resultado en su estado normal de inicialización vacía. Si el resultado es un valor, su contador de referencias se decrementa y el resultado se deja apuntando a un valor no compartido que representa una cadena vacía. Si el resultado es una cadena asignada dinámicamente, su memoria se libera y el resultado se deja como una cadena vacía. Tcl_ResetResult también borra el estado de error gestionado por Tcl_AddErrorInfo, Tcl_AddObjErrorInfo y Tcl_SetErrorCode.

Tcl_AppendResult facilita la construcción de resultados Tcl en piezas. Toma cada uno de sus argumentos result y los añade en orden al resultado actual asociado con interp. Si el resultado está en su estado inicial vacío (por ejemplo, se acaba de invocar un procedimiento de comando o se acaba de llamar a Tcl_ResetResult), entonces Tcl_AppendResult establece el resultado a la concatenación de sus argumentos result. Tcl_AppendResult puede llamarse repetidamente a medida que se producen piezas adicionales del resultado. Tcl_AppendResult se encarga de todos los problemas de gestión de memoria asociados con la gestión del resultado de interp, como la asignación de un área de resultado más grande si es necesario. También gestiona la conversión hacia y desde el campo result de interp para manejar la retrocompatibilidad con extensiones de estilo antiguo. Se puede pasar cualquier número de argumentos result en una sola llamada; el último argumento de la lista debe ser (char *)NULL.

Tcl_AppendResultVA es lo mismo que Tcl_AppendResult, excepto que en lugar de tomar un número variable de argumentos, toma una lista de argumentos.

Tcl_TransferResult transfiere el estado del intérprete de sourceInterp a targetInterp. Los dos intérpretes deben haber sido creados en el mismo hilo. Si sourceInterp y targetInterp son los mismos, no se hace nada. De lo contrario, Tcl_TransferResult mueve el resultado de sourceInterp a targetInterp, y restablece el resultado en sourceInterp. También mueve el diccionario de opciones de retorno según lo controlado por el valor del código de retorno code de la misma manera que Tcl_GetReturnOptions.

INTERFACES OBSOLETAS

PROCEDIMIENTOS DE CADENA ANTIGUOS

Se desaconseja el uso de los siguientes procedimientos ya que manipulan el resultado de Tcl como una cadena. Procedimientos como Tcl_SetObjResult que manipulan el resultado como un valor pueden ser significativamente más eficientes.

Tcl_AppendElement es similar a Tcl_AppendResult en que permite construir resultados en piezas. Sin embargo, Tcl_AppendElement solo toma un único argumento element y añade ese argumento al resultado actual como un elemento de lista Tcl adecuado. Tcl_AppendElement añade barras invertidas o llaves si es necesario para asegurar que el resultado de interp pueda ser analizado como una lista y que element se extraiga como un único elemento. En condiciones normales, Tcl_AppendElement añadirá un carácter de espacio al resultado de interp justo antes de añadir el nuevo elemento de lista, para que los elementos de lista en el resultado estén correctamente separados. Sin embargo, si el nuevo elemento de lista es el primero en una lista o sublista (es decir, el resultado actual de interp está vacío, o consiste en el carácter único “{”, o termina en los caracteres “ {”) entonces no se añade ningún espacio.

Tcl_FreeResult realiza parte del trabajo de Tcl_ResetResult. Libera la memoria asociada con el resultado de interp. También establece interp->freeProc a cero, pero no cambia interp->result ni borra el estado de error. Tcl_FreeResult se usa más comúnmente cuando un procedimiento está a punto de reemplazar un valor de resultado con otro.

NAME

Tcl_ResetResult, Tcl_GetObjResult, Tcl_GetStringResult, Tcl_SetObjResult, Tcl_SetResult - set or get the result of a Tcl command

SYNOPSIS

#include <tcl.h>

void
Tcl_ResetResult(interp);

Tcl_Obj *
Tcl_GetObjResult(interp);

const char *
Tcl_GetStringResult(interp);

void
Tcl_SetObjResult(interp, objPtr);

void
Tcl_SetResult(interp, string, freeProc);

ARGUMENTS

char * string (in)
String to be used as the result.
Tcl_FreeProc freeProc (in)
Procedure to call to free string, or one of TCL_STATIC, TCL_DYNAMIC, or TCL_VOLATILE.
Tcl_Interp *interp (in)
Interpreter to use.
Tcl_Obj *objPtr (in)
Pointer to Tcl object to be used as result.

DESCRIPTION

These functions manage the result that is returned to the caller of a Tcl command procedure. There are two forms of Tcl results: string results and Tcl object results. String results are easier to use but are less efficient than Tcl object results.

Tcl_SetResult is the traditional way to set the result of a Tcl command. It takes a string and a procedure to manage the string's storage. The freeProc argument tells Tcl how to manage the storage for string. See the section below, "THE TCL_FREEPROC ARGUMENT TO TCL_SETRESULT", for details.

Tcl_SetObjResult is the preferred way to set the result of a Tcl command. It takes a pointer to a Tcl object. Tcl takes ownership of the object and will manage its storage. The application should not free the object after calling this function; Tcl will do it when appropriate.

Tcl_ResetResult clears the result of the interpreter. It is called automatically at the beginning of each command evaluation.

Tcl_GetStringResult returns the current result of the interpreter as a string. If the result is not already a string, it will be converted to one. The returned string is owned by the interpreter and should not be freed or modified by the application.

Tcl_GetObjResult returns the current result of the interpreter as a Tcl object. If the result is not already an object, it will be converted to one. The returned object is owned by the interpreter. The application should not free or modify the object.

DEPRECATED INTERFACES

The functions Tcl_SetResult and Tcl_ResetResult are deprecated. They are part of the older string-based result mechanism. The newer Tcl object-based functions, Tcl_SetObjResult and Tcl_GetObjResult, should be used instead. Access to the older string-based Tcl result is provided by the new Tcl object-based functions. The deprecated functions are still supported for backward compatibility, but they are implemented in terms of the new object-based functions.

Applications that use the deprecated string-based result functions may experience performance degradation. The new Tcl object result mechanism is significantly more efficient, especially for commands that return lists or other complex data structures.

As a migration aid, access to the old string result mechanism can be restored with the compiler directive

#define USE_INTERP_RESULT

but this is meant only to offer life support to otherwise dead code.

THE TCL_FREEPROC ARGUMENT TO TCL_SETRESULT

Tcl_SetResult's freeProc argument specifies how the Tcl system is to manage the storage for the result argument. If Tcl_SetResult or Tcl_SetObjResult are called at a time when interp holds a string result, they do whatever is necessary to dispose of the old string result (see the Tcl_Interp manual entry for details on this).

If freeProc is TCL_STATIC it means that result refers to an area of static storage that is guaranteed not to be modified until at least the next call to Tcl_Eval. If freeProc is TCL_DYNAMIC it means that result was allocated with a call to Tcl_Alloc and is now the property of the Tcl system. Tcl_SetResult will arrange for the string's storage to be released by calling Tcl_Free when it is no longer needed. If freeProc is TCL_VOLATILE it means that result points to an area of memory that is likely to be overwritten when Tcl_SetResult returns (e.g. it points to something in a stack frame). In this case Tcl_SetResult will make a copy of the string in dynamically allocated storage and arrange for the copy to be the result for the current Tcl command.

If freeProc is not one of the values TCL_STATIC, TCL_DYNAMIC, and TCL_VOLATILE, then it is the address of a procedure that Tcl should call to free the string. This allows applications to use non-standard storage allocators. When Tcl no longer needs the storage for the string, it will call freeProc. FreeProc should have arguments and result that match the type Tcl_FreeProc:

typedef void Tcl_FreeProc(
                char *blockPtr);

When freeProc is called, its blockPtr will be set to the value of result passed to Tcl_SetResult.
