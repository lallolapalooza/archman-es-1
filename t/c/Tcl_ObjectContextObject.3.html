DESCRIPCIÓN

Un método es una operación realizada en un objeto asociado con el objeto. Cada método debe estar asociado con un objeto o una clase; los métodos asociados a una clase están asociados con todas las instancias (directas e indirectas) de esa clase.

Dado un método, se puede encontrar la entidad que lo declaró utilizando Tcl_MethodDeclarerClass, que devuelve la clase a la que está asociado el método (o NULL si el método no está asociado a ninguna clase) y Tcl_MethodDeclarerObject, que devuelve el objeto al que está asociado el método (o NULL si el método no está asociado a ningún objeto). El nombre del método se puede obtener con Tcl_MethodName y la exportación del método se puede obtener con Tcl_MethodIsPublic. También se puede inspeccionar el tipo del método hasta cierto punto; la función Tcl_MethodIsType devuelve si un método es de un tipo específico, asignando el valor de clientData a la variable señalada por clientDataPtr (si no es NULL) si el tipo coincide.

CREACIÓN DE MÉTODOS

Los métodos se crean mediante Tcl_NewMethod y Tcl_NewInstanceMethod, que crean un método asociado a una clase o a un objeto respectivamente. En ambos casos, el argumento nameObj proporciona el nombre del método a crear, el argumento isPublic indica si el método debe ser exportado inicialmente, el argumento methodTypePtr describe la implementación del método (ver la sección TIPOS DE MÉTODOS más adelante) y el argumento clientData proporciona algunos datos específicos de implementación que se pasan a la implementación del método cuando se llama.

Cuando el argumento nameObj de Tcl_NewMethod es NULL, se crea un método sin nombre, utilizado para constructores y destructores. Los constructores deben instalarse en su clase mediante Tcl_ClassSetConstructor, y los destructores (que no requieren argumentos) deben instalarse en su clase mediante Tcl_ClassSetDestructor. Los métodos sin nombre no deben utilizarse para otros fines, y los métodos con nombre no deben utilizarse como constructores o destructores. También cabe señalar que un methodTypePtr NULL se utiliza para proporcionar señal interna y no debe ser utilizado en código cliente.

CONTEXTOS DE LLAMADA DE MÉTODOS

Cuando se llama a un método, se pasa una referencia de contexto de llamada de método como uno de los argumentos de la función de implementación. Este contexto puede ser inspeccionado para obtener información sobre el llamador, pero no debe ser retenido después de que termine la llamada al método.

El método que se está llamando se puede recuperar del contexto utilizando Tcl_ObjectContextMethod, y el objeto que causó la invocación del método se puede recuperar con Tcl_ObjectContextObject. El número de argumentos omitidos (por ejemplo, el nombre del objeto y el nombre del método en una invocación normal) se lee con Tcl_ObjectContextSkippedArgs, y el contexto también puede informar si está actuando como filtro para otro método con Tcl_ObjectContextIsFiltering.

Durante la ejecución de un método, la implementación del método puede optar por invocar las etapas de la cadena de llamada de métodos que siguen a la implementación actual del método. Esto (el núcleo del comando next) se realiza mediante Tcl_ObjectContextInvokeNext. Cabe señalar que esta función no manipula la pila de llamadas, a diferencia del comando next; si la implementación del método ha colocado una o más pilas adicionales en la pila durante su implementación, también debe ser responsable de retirar temporalmente esas pilas de la pila mientras se ejecuta Tcl_ObjectContextInvokeNext. También cabe señalar que el contexto de llamada de método nunca se elimina durante la ejecución de esta función.

TIPOS DE MÉTODOS

Los tipos de métodos se describen mediante un puntero a una estructura Tcl_MethodType, que se define de la siguiente manera:

typedef struct {
    int version;
    const char *name;
    Tcl_MethodCallProc *callProc;
    Tcl_MethodDeleteProc *deleteProc;
    Tcl_CloneProc *cloneProc;
} Tcl_MethodType;

El campo version permite la expansión futura de la estructura y siempre debe declararse igual a TCL_OO_METHOD_VERSION_CURRENT. El campo name proporciona un nombre legible por humanos para el tipo, y es el valor que expone los comandos de Tcl info class methodtype y info object methodtype.

El campo callProc proporciona una función que se llama cuando se invoca el método; nunca debe ser NULL.

El campo deleteProc proporciona una función que se utiliza para eliminar un método específico y se llama cuando el método es reemplazado o eliminado; si el campo es NULL, se asume que el clientData del método no requiere ninguna acción especial para su eliminación.

El campo cloneProc es una función que se utiliza para copiar el clientData de un método (como parte de Tcl_CopyObjectInstance) o NULL para indicar que el clientData puede simplemente copiarse directamente.

FIRMA DE FUNCIÓN DE PROCEDIMIENTO PARA TCL_METHODCALLPROC

void (*Tcl_MethodCallProc)(ClientData clientData, Tcl_Obj *objv, int objc, Tcl_Obj *obj, int skip, Tcl_Obj *result);

NAME

Tcl_ObjectContext - information about the object context of a method call

SYNOPSIS

#include <tclOO.h>

typedef struct Tcl_ObjectContext {
    Tcl_Object object;
    Tcl_Object method;
    Tcl_Class class;
    Tcl_Method methodType;
    Tcl_Obj *methodName;
} Tcl_ObjectContext;

typedef int Tcl_MethodCallProc(
        ClientData clientData,
        Tcl_Interp *interp,
        Tcl_ObjectContext objectContext,
        int objc,
        Tcl_Obj *const *objv);

typedef void Tcl_MethodDeleteProc(
        ClientData clientData);

typedef int Tcl_CloneProc(
        Tcl_Interp *interp,
        ClientData oldClientData,
        ClientData *newClientDataPtr);

ARGUMENTS

Tcl_Interp *interp
The interpreter in which to execute code.
Tcl_Object object
The object on which the method is invoked.
Tcl_Object method
The method being invoked. This is the specific instance of the method.
Tcl_Class class
The class of the object on which the method is invoked.
Tcl_MethodType *methodType
The type of the method being invoked (e.g. constructor, method, filter).
Tcl_Obj *methodName
The name of the method being invoked.
objc
The number of arguments to the method.
objv
An array of Tcl objects representing the arguments to the method.

DESCRIPTION

The TclOO object system provides a mechanism for defining and managing objects and their methods. When a method is invoked on an object, the TclOO core needs to determine which method implementation to call. This involves looking up the method in the object's class hierarchy and then calling the appropriate C procedure. The context of this call is provided by the Tcl_ObjectContext structure.

The Tcl_ObjectContext structure is passed to method invocation procedures and contains information about the object, the method, the class, and the method type. It also includes the name of the method being called.

TCL_METHODCALLPROC FUNCTION SIGNATURE

Functions matching this signature are called when the method is invoked.

typedef int Tcl_MethodCallProc(
        ClientData clientData,
        Tcl_Interp *interp,
        Tcl_ObjectContext objectContext,
        int objc,
        Tcl_Obj *const *objv);

The clientData argument to a Tcl_MethodCallProc is the value that was given when the method was created, the interp is a place in which to execute scripts and access variables as well as being where to put the result of the method, and the objc and objv fields give the parameter objects to the method. The calling context of the method can be discovered through the objectContext argument, and the return value from a Tcl_MethodCallProc is any Tcl return code (e.g. TCL_OK, TCL_ERROR).

TCL_METHODDELETEPROC FUNCTION SIGNATURE

Functions matching this signature are used when a method is deleted, whether through a new method being created or because the object or class is deleted.

typedef void Tcl_MethodDeleteProc(
        ClientData clientData);

The clientData argument to a Tcl_MethodDeleteProc will be the same as the value passed to the clientData argument to Tcl_NewMethod or Tcl_NewInstanceMethod when the method was created.

TCL_CLONEPROC FUNCTION SIGNATURE

Functions matching this signature are used to copy a method when the object or class is copied using Tcl_CopyObjectInstance (or oo::copy).

typedef int Tcl_CloneProc(
        Tcl_Interp *interp,
        ClientData oldClientData,
        ClientData *newClientDataPtr);

The interp argument gives a place to write an error message when the attempt to clone the object is to fail, in which case the clone procedure must also return TCL_ERROR; it should return TCL_OK otherwise. The oldClientData field to a Tcl_CloneProc gives the value from the method being copied from, and the newClientDataPtr field will point to a variable in which to write the value for the method being copied to.
