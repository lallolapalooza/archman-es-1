NOMBRE

Tcl_LinkVar, Tcl_UnlinkVar, Tcl_UpdateLinkedVar - vincular variable Tcl a variable C

SINOPSIS

#include <tcl.h>

int
Tcl_LinkVar(interp, varName, addr, type)

Tcl_UnlinkVar(interp, varName)

Tcl_UpdateLinkedVar(interp, varName)

ARGUMENTOS

Tcl_Interp *interp (entrada)
Intérprete que contiene varName. También es utilizado por Tcl_LinkVar para devolver mensajes de error.
const char *varName (entrada)
Nombre de la variable global.
char *addr (entrada)
Dirección de la variable C que se vinculará a varName.
int type (entrada)
Tipo de la variable C. Debe ser uno de TCL_LINK_INT, TCL_LINK_UINT, TCL_LINK_CHAR, TCL_LINK_UCHAR, TCL_LINK_SHORT, TCL_LINK_USHORT, TCL_LINK_LONG, TCL_LINK_ULONG, TCL_LINK_WIDE_INT, TCL_LINK_WIDE_UINT, TCL_LINK_FLOAT, TCL_LINK_DOUBLE, TCL_LINK_BOOLEAN, o TCL_LINK_STRING, opcionalmente OR'ed con TCL_LINK_READ_ONLY para hacer que la variable Tcl sea de solo lectura.

DESCRIPCIÓN

Tcl_LinkVar utiliza rastreadores de variables para mantener la variable Tcl llamada varName sincronizada con la variable C en la dirección proporcionada por addr. Cada vez que se lee la variable Tcl, se devolverá el valor de la variable C, y cada vez que se escribe la variable Tcl, la variable C se actualizará para tener el mismo valor. Tcl_LinkVar normalmente devuelve TCL_OK; si ocurre un error al configurar el enlace (por ejemplo, porque varName es el nombre de un array) entonces se devuelve TCL_ERROR y el resultado del intérprete contiene un mensaje de error.

El argumento type especifica el tipo de la variable C y debe tener uno de los siguientes valores, opcionalmente OR'ed con TCL_LINK_READ_ONLY:

TCL_LINK_INT
La variable C es de tipo int. Cualquier valor escrito en la variable Tcl debe tener una forma entera adecuada aceptable para Tcl_GetIntFromObj; los intentos de escribir valores no enteros en varName serán rechazados con errores de Tcl. Las representaciones enteras incompletas (como la cadena vacía, '+', '-' o el prefijo hexadecimal/octal/binario) se aceptan como si fueran válidas también.
TCL_LINK_UINT
La variable C es de tipo unsigned int. Cualquier valor escrito en la variable Tcl debe tener una forma entera sin signo adecuada aceptable para Tcl_GetWideIntFromObj y dentro del rango definido en la plataforma para el tipo unsigned int; los intentos de escribir valores no enteros (o valores fuera de rango) en varName serán rechazados con errores de Tcl. Las representaciones enteras incompletas (como la cadena vacía, '+', '-' o el prefijo hexadecimal/octal/binario) se aceptan como si fueran válidas también.
TCL_LINK_CHAR
La variable C es de tipo char. Cualquier valor escrito en la variable Tcl debe tener una forma entera adecuada aceptable para Tcl_GetIntFromObj y estar dentro del rango del tipo char; los intentos de escribir valores no enteros o fuera de rango en varName serán rechazados con errores de Tcl. Las representaciones enteras incompletas (como la cadena vacía, '+', '-' o el prefijo hexadecimal/octal/binario) se aceptan como si fueran válidas también.
TCL_LINK_UCHAR
La variable C es de tipo unsigned char. Cualquier valor escrito en la variable Tcl debe tener una forma entera sin signo adecuada aceptable para Tcl_GetIntFromObj y dentro del rango definido en la plataforma para el tipo unsigned char; los intentos de escribir valores no enteros (o valores fuera de rango) en varName serán rechazados con errores de Tcl. Las representaciones enteras incompletas (como la cadena vacía, '+', '-' o el prefijo hexadecimal/octal/binario) se aceptan como si fueran válidas también.
TCL_LINK_SHORT
La variable C es de tipo short. Cualquier valor escrito en la variable Tcl debe tener una forma entera adecuada aceptable para Tcl_GetIntFromObj y estar dentro del rango del tipo short; los intentos de escribir valores no enteros o fuera de rango en varName serán rechazados con errores de Tcl. Las representaciones enteras incompletas (como la cadena vacía, '+', '-' o el prefijo hexadecimal/octal/binario) se aceptan como si fueran válidas también.
TCL_LINK_USHORT
La variable C es de tipo unsigned short. Cualquier valor escrito en la variable Tcl debe tener una forma entera sin signo adecuada aceptable para Tcl_GetIntFromObj y dentro del rango definido en la plataforma para el tipo unsigned short; los intentos de escribir valores no enteros (o valores fuera de rango) en varName serán rechazados con errores de Tcl. Las representaciones enteras incompletas (como la cadena vacía, '+', '-' o el prefijo hexadecimal/octal/binario) se aceptan como si fueran válidas también.
TCL_LINK_LONG
La variable C es de tipo long. Cualquier valor escrito en la variable Tcl debe tener una forma entera adecuada aceptable para Tcl_GetLongFromObj; los intentos de escribir valores no enteros o fuera de rango en varName serán rechazados con errores de Tcl. Las representaciones enteras incompletas (como la cadena vacía, '+', '-' o el prefijo hexadecimal/octal/binario) se aceptan como si fueran válidas también.
TCL_LINK_ULONG
La variable C es de tipo unsigned long. Cualquier valor escrito en la variable Tcl debe tener una forma entera sin signo adecuada aceptable para Tcl_GetWideIntFromObj y dentro del rango definido en la plataforma para el tipo unsigned long; los intentos de escribir valores no enteros (o valores fuera de rango) en varName serán rechazados con errores de Tcl. Las representaciones enteras incompletas (como la cadena vacía, '+', '-' o el prefijo hexadecimal/octal/binario) se aceptan como si fueran válidas también.
TCL_LINK_DOUBLE
La variable C es de tipo double. Cualquier valor escrito en la variable Tcl debe tener una forma real adecuada aceptable para Tcl_GetDoubleFromObj; los intentos de escribir valores no reales en varName serán rechazados con errores de Tcl. Las representaciones enteras o reales incompletas (como la cadena vacía, '.', '+', '-' o el prefijo hexadecimal/octal/binario) se aceptan como si fueran válidas también.
TCL_LINK_FLOAT
La variable C es de tipo float. Cualquier valor escrito en la variable Tcl debe tener una forma real adecuada aceptable para Tcl_GetDoubleFromObj y debe estar dentro del rango aceptable para un float; los intentos de escribir valores no reales (o valores fuera de rango) en varName serán rechazados con errores de Tcl. Las representaciones enteras o reales incompletas (como la cadena vacía, '.', '+', '-' o el prefijo hexadecimal/octal/binario) se aceptan como si fueran válidas también.
TCL_LINK_WIDE_INT
La variable C es de tipo Tcl_WideInt (que es un tipo entero de al menos 64 bits de ancho en todas las plataformas que lo soportan.) Cualquier valor escrito en la variable Tcl debe tener una forma entera adecuada aceptable para Tcl_GetWideIntFromObj; los intentos de escribir valores no enteros en varName serán rechazados con errores de Tcl. Las representaciones enteras incompletas (como la cadena vacía, '+', '-' o el prefijo hexadecimal/octal/binario) se aceptan como si fueran válidas también.
TCL_LINK_WIDE_UINT
La variable C es de tipo Tcl_WideUInt (que es un tipo entero sin signo de al menos 64 bits de ancho en todas las plataformas que lo soportan.) Cualquier valor escrito en la variable Tcl debe tener una forma entera sin signo adecuada aceptable para Tcl_GetWideIntFromObj (será casteado a sin signo); los intentos de escribir valores no enteros en varName serán rechazados con errores de Tcl. Las representaciones enteras incompletas (como la cadena vacía, '+', '-' o el prefijo hexadecimal/octal/binario) se aceptan como si fueran válidas también.
TCL_LINK_BOOLEAN
La variable C es de tipo int. Cualquier valor escrito en la variable Tcl debe tener una forma booleana adecuada aceptable para Tcl_GetBooleanFromObj; los intentos de escribir valores no booleanos en varName serán rechazados con errores de Tcl.
TCL_LINK_STRING
La variable C es de tipo char *. Cualquier valor escrito en la variable Tcl se convertirá a una cadena de caracteres y se copiará en la memoria asignada dinámicamente. La cadena original se liberará usando Tcl_Free y se reemplazará por la nueva cadena. El programador es responsable de asegurarse de que el puntero de la variable C se mantenga válido durante toda la vida del enlace. Si el valor de la variable Tcl se establece en un valor vacío, la cadena en la variable C se establecerá en una cadena vacía. Si se intenta vincular una variable C de tipo char * a una variable Tcl que no es una cadena, se producirá un error.

Tcl_UnlinkVar elimina el enlace entre la variable Tcl varName y la variable C correspondiente. Si no existe ningún enlace para varName, no se hace nada. Si el enlace era de tipo TCL_LINK_STRING, la cadena en memoria asignada dinámicamente se liberará.

Tcl_UpdateLinkedVar se puede utilizar para forzar una actualización inmediata de la variable Tcl desde la variable C vinculada. Esto es útil si la variable C se modifica de alguna manera que no sea a través del intérprete Tcl (por ejemplo, por otra parte de la aplicación C). Si no existe ningún enlace para varName, no se hace nada.

EJEMPLO

El siguiente código vincula una variable C llamada myGlobalInt a la variable Tcl llamada globalVar:

int myGlobalInt = 5;
/* ... */
if (Tcl_LinkVar(interp, "globalVar", (char *) &myGlobalInt, TCL_LINK_INT) != TCL_OK) {
    fprintf(stderr, "%s\n", Tcl_GetStringResult(interp));
    return 1;
}

A partir de este momento, cualquier lectura de la variable Tcl globalVar devolverá el valor de myGlobalInt, y cualquier escritura en globalVar actualizará myGlobalInt. Para eliminar el enlace:

Tcl_UnlinkVar(interp, "globalVar");

Para forzar una actualización de la variable Tcl desde la C variable:

Tcl_UpdateLinkedVar(interp, "globalVar");

PALABRAS CLAVE

variable, enlace, rastreador

NAME

Tcl_LinkVar, Tcl_UnlinkVar, Tcl_UpdateLinkedVar — link Tcl variables to C variables

SYNOPSIS

#include <tcl.h>

int
Tcl_LinkVar(
    Tcl_Interp *interp,
    const char *varName,
    char *varAddr,
    int type);
int
Tcl_UnlinkVar(
    Tcl_Interp *interp,
    const char *varName);
int
Tcl_UpdateLinkedVar(
    Tcl_Interp *interp,
    const char *varName);

ARGUMENTS

varName
Name of Tcl variable to link.
varAddr
Address of C variable.
type
Type of variable and access permissions.

DESCRIPTION

Tcl_LinkVar establishes a link between a Tcl variable named varName and a C variable whose address is given by varAddr. The type argument specifies the type of the C variable and also controls how the variable may be accessed from Tcl. Legal values for type are formed by OR-ing together one of the following types with zero or more of the following flags:

TCL_LINK_INT

The C variable is of type int. Whenever the Tcl variable is modified, the C variable will be updated. Whenever the C variable is modified, the Tcl variable will be updated.

TCL_LINK_DOUBLE

The C variable is of type double. Whenever the Tcl variable is modified, the C variable will be updated. Whenever the C variable is modified, the Tcl variable will be updated.

TCL_LINK_BOOLEAN

The C variable is of type int. If its value is zero then it will read from Tcl as “0”; otherwise it will read from Tcl as “1”. Whenever varName is modified, the C variable will be set to a 0 or 1 value. Any value written into the Tcl variable must have a proper boolean form acceptable to Tcl_GetBooleanFromObj; attempts to write non-boolean values into varName will be rejected with Tcl errors.

TCL_LINK_STRING

The C variable is of type char *. If its value is not NULL then it must be a pointer to a string allocated with Tcl_Alloc or ckalloc. Whenever the Tcl variable is modified the current C string will be freed and new memory will be allocated to hold a copy of the variable's new value. If the C variable contains a NULL pointer then the Tcl variable will read as “NULL”.

If the TCL_LINK_READ_ONLY flag is present in type then the variable will be read-only from Tcl, so that its value can only be changed by modifying the C variable. Attempts to write the variable from Tcl will be rejected with errors.

Tcl_UnlinkVar removes the link previously set up for the variable given by varName. If there does not exist a link for varName then the procedure has no effect.

Tcl_UpdateLinkedVar may be invoked after the C variable has changed to force the Tcl variable to be updated immediately. In many cases this procedure is not needed, since any attempt to read the Tcl variable will return the latest value of the C variable. However, if a trace has been set on the Tcl variable (such as a Tk widget that wishes to display the value of the variable), the trace will not trigger when the C variable has changed. Tcl_UpdateLinkedVar ensures that any traces on the Tcl variable are invoked.

Note that, as with any call to a Tcl interpreter, Tcl_UpdateLinkedVar must be called from the same thread that created the interpreter. The safest mechanism is to ensure that the C variable is only ever updated from the same thread that created the interpreter (possibly in response to an event posted with Tcl_ThreadQueueEvent), but when it is necessary to update the variable in a separate thread, it is advised that Tcl_AsyncMark be used to indicate to the thread hosting the interpreter that it is ready to run Tcl_UpdateLinkedVar.
