ARGUMENTOS

Tcl_Interp *interp (entrada)
El intérprete donde se almacenarán los datos comprimidos o descomprimidos resultantes. También es donde se escribirán los mensajes de error. Para Tcl_ZlibStreamInit, este puede ser NULL para crear un stream que no esté vinculado a un comando.
int format (entrada)
Qué formato de datos comprimidos se va a utilizar. Debe ser uno de TCL_ZLIB_FORMAT_ZLIB para datos en formato zlib, TCL_ZLIB_FORMAT_GZIP para datos en formato gzip, o TCL_ZLIB_FORMAT_RAW para datos comprimidos en bruto. Además, solo para descompresión, también se puede elegir TCL_ZLIB_FORMAT_AUTO, que puede detectar automáticamente si los datos comprimidos estaban en formato zlib o gzip.
Tcl_Obj *dataObj (entrada/salida)
Un valor de array de bytes que contiene los datos a comprimir o descomprimir, o al que se añadirán los datos extraídos del stream cuando se pase a Tcl_ZlibStreamGet.
int level (entrada)
Qué nivel de compresión usar. Debe ser un número de 0 a 9 o uno de los siguientes: TCL_ZLIB_COMPRESS_NONE para ninguna compresión, TCL_ZLIB_COMPRESS_FAST para compresión rápida pero ineficiente, TCL_ZLIB_COMPRESS_BEST para compresión lenta pero máxima, o TCL_ZLIB_COMPRESS_DEFAULT para el nivel recomendado por la biblioteca zlib.
Tcl_Obj *dictObj (entrada/salida)
Un diccionario que contiene, o que se actualizará para contener, una descripción de la cabecera gzip asociada con los datos comprimidos. Solo es útil cuando el parámetro format es TCL_ZLIB_FORMAT_GZIP o TCL_ZLIB_FORMAT_AUTO. Si se pasa NULL, se usará una cabecera por defecto en la compresión y la cabecera se ignorará (aparte de las comprobaciones de integridad) en la descompresión. Consulte la sección DICCIONARIO DE OPCIONES GZIP para obtener más detalles sobre el contenido de este diccionario.
unsigned int initValue (entrada)
El valor inicial para el algoritmo de suma de verificación.
int bufferSize (entrada)
Una pista sobre el tamaño del búfer que se utilizará para recibir los datos. Use 0 para usar una suposición genérica basada en los datos de entrada.
unsigned char *bytes (entrada)
Un array de bytes sobre el que ejecutar el algoritmo de suma de verificación, o NULL para obtener el valor inicial recomendado para el algoritmo de suma de verificación.
int length (entrada)
El número de bytes en el array.
int mode (entrada)
En qué modo operar el stream. Debe ser TCL_ZLIB_STREAM_DEFLATE para un stream de compresión o TCL_ZLIB_STREAM_INFLATE para un stream de descompresión.
Tcl_ZlibStream *zshandlePtr (salida)
Un puntero a una variable en la que se escribirá el token abstracto para el stream tras su creación exitosa.
Tcl_ZlibStream zshandle (entrada)
El token abstracto para el stream sobre el que operar.
int flush (entrada)
Si se debe vaciar el stream después de escribir los datos en él y cómo. Debe ser uno de: TCL_ZLIB_NO_FLUSH si no se va a hacer ningún vaciado, TCL_ZLIB_FLUSH si los datos comprimidos actuales deben estar disponibles para ser accedidos usando Tcl_ZlibStreamGet, TCL_ZLIB_FULLFLUSH si el stream debe ponerse en un estado desde el que el descompresor pueda recuperarse ante una corrupción, o TCL_ZLIB_FINALIZE para asegurar que el stream ha terminado y que se escribe cualquier trailer exigido por el formato.
int count (entrada)
El número máximo de bytes a obtener del stream, o -1 para obtener todos los bytes restantes de los búferes del stream.
Tcl_Obj *compDict (entrada)
Un valor de array de bytes que es el diccionario de compresión a usar con el stream. Tenga en cuenta que este *no es un diccionario Tcl*, y se recomienda que solo se use con streams que se crearon con su format establecido a TCL_ZLIB_FORMAT_ZLIB porque los otros formatos no tienen un mecanismo para indicar si un diccionario de compresión estaba presente, aparte de fallar en la descompresión.

DESCRIPCIÓN

Estas funciones forman la interfaz desde la biblioteca Tcl a la biblioteca Zlib de Jean-loup Gailly y Mark Adler.

Tcl_ZlibDeflate y Tcl_ZlibInflate respectivamente comprimen y descomprimen los datos contenidos en el argumento dataObj, de acuerdo con los argumentos format y, para la compresión, level. El diccionario en el parámetro dictObj se utiliza para transmitir información adicional de cabecera sobre los datos comprimidos cuando el formato de compresión lo soporta; actualmente, el diccionario solo se utiliza cuando el parámetro format es TCL_ZLIB_FORMAT_GZIP o TCL_ZLIB_FORMAT_AUTO. Para obtener detalles sobre el contenido del diccionario, consulte la sección DICCIONARIO DE OPCIONES GZIP más abajo. Tras el éxito, ambas funciones dejan los datos comprimidos o descomprimidos resultantes en un valor de array de bytes que es el resultado del intérprete Tcl; el valor devuelto es un código de resultado Tcl estándar.

Tcl_ZlibAdler32 y Tcl_ZlibCRC32 calculan sumas de verificación sobre arrays de bytes, devolviendo la suma de verificación calculada. Las sumas de verificación se calculan de forma incremental, lo que permite procesar los datos bloque a bloque, pero esto requiere que el llamador mantenga la suma de verificación actual y la pase como parámetro initValue; el valor inicial a usar para esto se puede obtener usando NULL para el parámetro bytes en lugar de un puntero al array de bytes sobre el que calcular la suma de verificación. Por lo tanto, el uso típico en el caso de un solo bloque de datos es así:

checksum = Tcl_ZlibCRC32(Tcl_ZlibCRC32(0,NULL,0), data, length);

Tenga en cuenta que el algoritmo Adler-32 no es una suma de verificación real, sino un tipo de hash relacionado que funciona mejor con datos largos.

STREAMS ZLIB

Tcl_ZlibStreamInit crea un stream de compresión o descompresión que está vinculado a un comando Tcl, de acuerdo con sus argumentos, y proporciona un token abstracto para el stream y devuelve un código de resultado Tcl normal; Tcl_ZlibStreamGetCommandName devuelve el nombre de ese comando dado el token del stream, o NULL si el stream no tiene un comando. Los streams no están diseñados para ser seguros en hilos; cada stream solo debe usarse desde el hilo que lo creó. Al trabajar con streams gzip, se puede proporcionar un diccionario (campos como se indica en la sección DICCIONARIO DE OPCIONES GZIP) a través del parámetro dictObj que, en la compresión, permite controlar las cabeceras generadas y, en la descompresión, permite descubrir las cabeceras existentes. Tenga en cuenta que el diccionario se escribirá al descomprimir una vez que se hayan leído suficientes datos para tener una cabecera completa. Esto significa que el diccionario debe ser un valor no compartido en ese caso; se sugiere un valor en blanco creado con Tcl_NewObj.

Una vez que se ha construido un stream, se utiliza Tcl_ZlibStreamPut para añadir datos al stream y se utiliza Tcl_ZlibStreamGet para recuperar datos del stream después del procesamiento. Ambos devuelven códigos de resultado Tcl normales y dejan un mensaje de error en el resultado del intérprete con el que está registrado el stream en caso de error (si dicha registración se ha realizado). Con Tcl_ZlibStreamPut, el valor del búfer de datos pasado a él no debe modificarse después. Con Tcl_ZlibStreamGet, el valor del búfer de datos pasado a él tendrá los bytes de datos añadidos. Internamente al stream, los datos se mantienen comprimidos para minimizar el costo del espacio de búfer.

NAME

Tcl_ZlibStreamClose, Tcl_ZlibStreamReset, Tcl_ZlibStreamGet, Tcl_ZlibStreamPut, Tcl_ZlibStreamEof, Tcl_ZlibStreamSetCompressionDictionary - API for zlib stream manipulation

SYNOPSIS

#include <tclZlib.h>

int
Tcl_ZlibStreamClose(zlibStream);
int
Tcl_ZlibStreamReset(zlibStream);
int
Tcl_ZlibStreamGet(zlibStream, Tcl_Obj **objPtr);
int
Tcl_ZlibStreamPut(zlibStream, Tcl_Obj *objPtr, int flush);
int
Tcl_ZlibStreamEof(zlibStream);
int
Tcl_ZlibStreamSetCompressionDictionary(zlibStream, const unsigned char *dict,
    int dictLen);

ARGUMENTS

zlibStream
Handle to an open zlib stream, such as returned by Tcl_ZlibStreamInit.
objPtr
A pointer to a Tcl object pointer. This is filled in by Tcl_ZlibStreamGet with the decompressed data, or it is used by Tcl_ZlibStreamPut to supply compressed data.
flush
Flag indicating how the data supplied by Tcl_ZlibStreamPut should be handled. Valid values are Z_NO_FLUSH, Z_SYNC_FLUSH, and Z_FINISH.
dict
A pointer to a buffer containing the compression dictionary to be used.
dictLen
The length of the compression dictionary buffer.

DESCRIPTION

These functions provide the API for the Tcl zlib stream interface.

Tcl_ZlibStreamInit (not shown) creates and returns a zlib stream handle, which is then used with the other functions. The initial creation of the stream is controlled by a dictionary of options, described below.

Tcl_ZlibStreamPut is used to supply data to the compression or decompression engine. It takes a Tcl object, converts it to a byte array, and feeds it into the stream. The flush parameter controls the output of the stream. A value of Z_NO_FLUSH means that the engine should buffer the data as much as possible. Z_SYNC_FLUSH causes the engine to flush all buffered output data, but does not end the stream. Z_FINISH should be used when all input data has been supplied; it causes the engine to flush all remaining output and terminate the stream. Use of Z_FINISH is necessary for the compressed data to be valid.

Tcl_ZlibStreamGet is used to retrieve data from the stream. On decompression, it fills objPtr with a Tcl object containing the decompressed data. On compression, it retrieves the compressed output from the stream and fills objPtr with a Tcl object containing that data. The function returns a normal Tcl result code (TCL_OK, TCL_ERROR, or TCL_RETURN). TCL_OK indicates that data was successfully retrieved. TCL_ERROR indicates that an error occurred. TCL_RETURN indicates that the end of the stream has been reached and no more data can be retrieved.

Tcl_ZlibStreamEof returns a boolean value indicating whether the end of the uncompressed data has been reached.

Tcl_ZlibStreamSetCompressionDictionary is used to control the compression dictionary used with the stream, a compression dictionary being an array of bytes (such as might be created with Tcl_NewByteArrayObj) that is used to initialize the compression engine rather than leaving it to create it on the fly from the data being compressed. Setting a compression dictionary allows for more efficient compression in the case where the start of the data is highly regular, but it does require both the compressor and the decompressor to agreee on the value to use. Compression dictionaries are only fully supported for zlib-format data; on compression, they must be set before any data is sent in with Tcl_ZlibStreamPut, and on decompression they should be set when Tcl_ZlibStreamGet produces an error with its -errorcode set to “ZLIB NEED_DICT code”; the code will be the Adler-32 checksum (see Tcl_ZlibAdler32) of the compression dictionary sought. (Note that this is only true for zlib-format streams; gzip streams ignore compression dictionaries as the format specification doesn't permit them, and raw streams just produce a data error if the compression dictionary is missing or incorrect.)

If you wish to clear a stream and reuse it for a new compression or decompression action, Tcl_ZlibStreamReset will do this and return a normal Tcl result code to indicate whether it was successful; if the stream is registered with an interpreter, an error message will be left in the interpreter result when this function returns TCL_ERROR. Finally, Tcl_ZlibStreamClose will clean up the stream and delete the associated command: using Tcl_DeleteCommand on the stream's command is equivalent (when such a command exists).

GZIP OPTIONS DICTIONARY

The dictObj parameter to Tcl_ZlibDeflate, Tcl_ZlibInflate and Tcl_ZlibStreamInit is used to pass a dictionary of options about that is used to describe the gzip header in the compressed data. When creating compressed data, the dictionary is read and when unpacking compressed data the dictionary is written (in which case the dictObj parameter must refer to an unshared dictionary value).

The following fields in the dictionary value are understood. All other fields are ignored. No field is required when creating a gzip-format stream.

comment
This holds the comment field of the header, if present. If absent, no comment was supplied (on decompression) or will be created (on compression).
crc
A boolean value describing whether a CRC of the header is computed. Note that the gzip program does not use or allow a CRC on the header.
filename
The name of the file that held the uncompressed data. This should not contain any directory separators, and should be sanitized before use on decompression with file tail.
os
The operating system type code field from the header (if not the “unknown” value). See RFC 1952 for the meaning of these codes. On compression, if this is absent then the field will be set to the “unknown” value.
size
The size of the uncompressed data. This is ignored on compression; the size of the data compressed depends on how much data is supplied to the compression engine.
time
The time field from the header if non-zero, expected to be the time that the file named by the filename field was modified. Suitable for use with clock format. On creation, the right value to use is that from clock seconds or file mtime.
type
The type of the uncompressed data (either binary or text) if known.

PORTABILITY NOTES

These functions will fail gracefully if Tcl is not linked with the zlib library.
