Tcl_VarTraceInfo2(3) Procedimientos de la Biblioteca Tcl Tcl_TraceVar(3)

NOMBRE

Tcl_TraceVar, Tcl_TraceVar2, Tcl_UntraceVar, Tcl_UntraceVar2, Tcl_VarTraceInfo, Tcl_VarTraceInfo2 - rastrear accesos a una variable

SINOSIS

#include <tcl.h>

int
Tcl_TraceVar(interp, varName, flags, proc, clientData)

int
Tcl_TraceVar2(interp, name1, name2, flags, proc, clientData)

Tcl_UntraceVar(interp, varName, flags, proc, clientData)

Tcl_UntraceVar2(interp, name1, name2, flags, proc, clientData)

ClientData
Tcl_VarTraceInfo(interp, varName, flags, proc, prevClientData)

ClientData
Tcl_VarTraceInfo2(interp, name1, name2, flags, proc, prevClientData)

ARGUMENTOS

Tcl_Interp *interp (in)
Intérprete que contiene la variable.
const char *varName (in)
Nombre de la variable. Puede referirse a una variable escalar, a una variable array sin índice, o a una variable array con índice entre paréntesis.
int flags (in)
OR de los valores TCL_TRACE_READS, TCL_TRACE_WRITES, TCL_TRACE_UNSETS, TCL_TRACE_ARRAY, TCL_GLOBAL_ONLY, TCL_NAMESPACE_ONLY, TCL_TRACE_RESULT_DYNAMIC y TCL_TRACE_RESULT_OBJECT. No todos los flags se usan en todos los procedimientos. Véase más abajo.
Tcl_VarTraceProc *proc (in)
Procedimiento a invocar cuando se produzca una de las operaciones rastreadas.
ClientData clientData (in)
Valor de una palabra arbitraria para pasar a proc.
const char *name1 (in)
Nombre de la variable escalar o array (sin índice de array).
const char *name2 (in)
Para un rastreo en un elemento de un array, proporciona el índice del elemento. Para rastreos en variables escalares o arrays enteros, es NULL.
ClientData prevClientData (in)
Si no es NULL, proporciona el valor devuelto más recientemente por Tcl_VarTraceInfo o Tcl_VarTraceInfo2, de modo que esta llamada devuelva información sobre el siguiente rastreo. Si es NULL, esta llamada devolverá información sobre el primer rastreo.

DESCRIPCIÓN

Tcl_TraceVar permite a un procedimiento C monitorear y controlar el acceso a una variable Tcl, de forma que el procedimiento C sea invocado cada vez que se lea, escriba o elimine una variable. Si el rastreo se crea correctamente, Tcl_TraceVar devuelve TCL_OK. Si ocurre un error (por ejemplo, varName especifica un elemento de un array, pero la variable real no es un array), se devuelve TCL_ERROR y se deja un mensaje de error en el resultado del intérprete.

El argumento flags de Tcl_TraceVar indica cuándo se invoca el procedimiento de rastreo y proporciona información para configurar el rastreo. Se forma con un OR de cualquiera de los siguientes valores:

TCL_GLOBAL_ONLY
Normalmente, la variable se busca en el nivel de llamada de procedimiento actual; si este bit está establecido, la variable se busca en el nivel global, ignorando cualquier procedimiento activo.
TCL_NAMESPACE_ONLY
Normalmente, la variable se busca en el nivel de llamada de procedimiento actual; si este bit está establecido, la variable se busca en el espacio de nombres actual, ignorando cualquier procedimiento activo.
TCL_TRACE_READS
Se invoca proc cada vez que se intenta leer la variable.
TCL_TRACE_WRITES
Se invoca proc cada vez que se intenta modificar la variable.
TCL_TRACE_UNSETS
Se invoca proc cada vez que la variable es eliminada. Una variable puede ser eliminada explícitamente con el comando unset, o implícitamente cuando un procedimiento devuelve (sus variables locales son automáticamente eliminadas), o cuando se elimina el intérprete (todas las variables son automáticamente eliminadas).
TCL_TRACE_ARRAY
Se invoca proc cada vez que se invoca el comando array. Esto da al procedimiento de rastreo la oportunidad de actualizar el array antes de que se invoque el nombre del array o el acceso al array. Nota: esto se llama antes de un array set, pero eso provocará rastreos de escritura.
TCL_TRACE_RESULT_DYNAMIC
El resultado de invocar proc es una cadena dinámica alojada por la biblioteca Tcl, que se liberará mediante una llamada a ckfree. No debe especificarse simultáneamente con TCL_TRACE_RESULT_OBJECT.
TCL_TRACE_RESULT_OBJECT
El resultado de invocar proc es un Tcl_Obj* (convertido a puntero a char), con un contador de referencias de al menos uno. La propiedad de esa referencia se transferirá a la biblioteca Tcl para su liberación (cuando la biblioteca haya terminado con él) mediante una llamada a Tcl_DecrRefCount. No debe especificarse simultáneamente con TCL_TRACE_RESULT_DYNAMIC.

Cuando ocurre una de las operaciones especificadas en la variable, se invoca proc. Debe tener argumentos y resultados que coincidan con el tipo Tcl_VarTraceProc:

typedef char *Tcl_VarTraceProc(
        ClientData clientData,
        Tcl_Interp *interp,
        const char *name1,
        const char *name2,
        int flags);

Los parámetros clientData e interp tendrán los mismos valores que se pasaron a Tcl_TraceVar cuando se creó el rastreo. clientData normalmente apunta a un conjunto de datos de aplicación que describe qué hacer cuando se invoca proc. name1 y name2 proporcionan el nombre de la variable rastreada en el formato normal de dos partes (véase la descripción de Tcl_TraceVar2 para detalles). flags es un OR de bits que proporcionan varios elementos de información. Uno de los bits TCL_TRACE_READS, TCL_TRACE_WRITES, TCL_TRACE_ARRAY o TCL_TRACE_UNSETS estará establecido en flags para indicar qué operación se está realizando en la variable. El bit TCL_GLOBAL_ONLY estará establecido cuando la variable accedida sea global y no se pueda acceder desde el nivel de llamada de procedimiento actual: el procedimiento de rastreo tendrá que pasar este flag a procedimientos de variable como Tcl_GetVar si intenta acceder a la variable. El bit TCL_NAMESPACE_ONLY estará establecido cuando la variable accedida sea de espacio de nombres y no se pueda acceder desde el nivel de llamada de procedimiento actual: el procedimiento de rastreo tendrá que pasar este flag a procedimientos de variable como Tcl_GetVar si intenta acceder a la variable. El bit TCL_TRACE_DESTROYED estará establecido en flags si el rastreo está a punto de ser destruido; esta información puede ser útil para proc para limpiar sus estructuras internas (véase la sección TCL_TRACE_DESTROYED para más detalles). Por último, el bit TCL_INTERP_DESTROYED estará establecido si el entorno completo del intérprete está siendo destruido. Cuando este bit esté establecido, proc debe ser especialmente cuidadoso con lo que hace (véase la sección TCL_INTERP_DESTROYED para más detalles). El valor de retorno del procedimiento de rastreo debería ser normalmente NULL; véase VALORES DE RETORNO DE ERRORES para obtener información sobre otros posibles valores.

Tcl_UntraceVar puede usarse para eliminar un rastreo. Si la variable especificada por interp, varName y flags tiene un rastreo con flags, proc y clientData, entonces se elimina el rastreo correspondiente. Si no existe dicho rastreo, la llamada a Tcl_UntraceVar no tiene ningún efecto. Los mismos bits son válidos para flags que para las llamadas a Tcl_TraceVar.

Tcl_VarTraceInfo puede usarse para recuperar información sobre los rastreos establecidos en una variable dada. El valor devuelto por Tcl_VarTraceInfo es el clientData asociado a un rastreo particular. El rastreo debe estar en la variable especificada por los argumentos interp, varName y flags (solo se usan los bits TCL_GLOBAL_ONLY y TCL_NAMESPACE_ONLY de flags; otros bits se ignoran) y su procedimiento de rastreo debe ser el mismo que el argumento proc. Si el argumento prevClientData es NULL, el valor devuelto corresponde al primer (más reciente) rastreo coincidente, o NULL si no hay coincidencias.

PREVCLIENTDATA

Si el argumento prevClientData no es NULL, entonces debe ser el valor de retorno de una llamada anterior a Tcl_VarTraceInfo. En este caso, el nuevo valor de retorno corresponderá al siguiente rastreo coincidente después de aquel cuyo clientData coincide con prevClientData, o NULL si ningún rastreo coincide con prevClientData o si no quedan más rastreos coincidentes después de él. Este mecanismo hace posible recorrer todos los rastreos de una variable dada que tienen el mismo proc.

NOMBRES DE DOS PARTES

Los procedimientos Tcl_TraceVar2, Tcl_UntraceVar2 y Tcl_VarTraceInfo2 son idénticos a Tcl_TraceVar, Tcl_UntraceVar y Tcl_VarTraceInfo, respectivamente, excepto que el nombre de la variable consta de dos partes. Name1 da el nombre de una variable escalar o de un array, y name2 da el nombre de un elemento dentro de un array. Cuando name2 es NULL, name1 puede contener tanto el nombre de un array como el de un elemento: si el nombre contiene un paréntesis de apertura y termina con un paréntesis de cierre, entonces el valor entre los paréntesis se trata como un nombre de elemento (que puede tener cualquier valor de cadena) y los caracteres antes del primer paréntesis de apertura se tratan como el nombre de una variable de array. Si name2 es NULL y name1 no se refiere a un elemento de array, significa que la variable es escalar o que el rastreo se establece en todo el array en lugar de en un elemento individual (ver RASTREOS DE ARRAY COMPLETOS más abajo para más información).

ACCESO A VARIABLES DURANTE LOS RASTREOS

Durante los rastreos de lectura, escritura y de array, el procedimiento de rastreo puede leer, escribir o anular la variable rastreada usando Tcl_GetVar2, Tcl_SetVar2 y otros procedimientos. Mientras proc se está ejecutando, los rastreos se deshabilitan temporalmente para la variable, de modo que las llamadas a Tcl_GetVar2 y Tcl_SetVar2 no provoquen que proc u otros procedimientos de rastreo se invoquen de nuevo. La deshabilitación solo ocurre para la variable cuyo procedimiento de rastreo está activo; los accesos a otras variables todavía serán rastreados. Sin embargo, si una variable se anula durante un rastreo de lectura o escritura, se invocarán los rastreos de anulación.

Durante los rastreos de anulación, la variable ya ha sido completamente eliminada. Es posible que el procedimiento de rastreo lea o escriba la variable, pero esta será una nueva versión de la variable. Los rastreos no se deshabilitan durante los rastreos de anulación, como sí ocurre para los rastreos de lectura y escritura, pero los rastreos existentes se han eliminado de la variable antes de que se invoquen los procedimientos de rastreo. Si los procedimientos de rastreo de anulación establecen nuevos rastreos, estos se invocarán en los accesos a la variable por parte de los procedimientos de rastreo.

MOMENTO DE LOS CALLBACKs

Cuando se ha especificado el rastreo de lectura para una variable, el procedimiento de rastreo se invocará cada vez que se lea el valor de la variable. Esto incluye comandos Tcl set, notación de $ en comandos Tcl e invocaciones de los procedimientos Tcl_GetVar y Tcl_GetVar2. Proc se invoca justo antes de que se devuelva el valor de la variable. Puede modificar el valor de la variable para afectar lo que devuelve el acceso rastreado. Si anula la variable, el acceso devolverá un error, como si la variable nunca hubiera existido.

Cuando se ha especificado el rastreo de escritura, el procedimiento de rastreo se invocará cada vez que se modifique el valor de la variable. Esto incluye comandos set, comandos que modifican variables como efectos secundarios (como catch y scan) y llamadas a los procedimientos Tcl_SetVar y Tcl_SetVar2). Proc se invocará después de que se haya modificado el valor de la variable, pero antes de que se haya devuelto el nuevo valor de la variable. Puede modificar el valor de la variable para anular el cambio y determinar el valor que realmente devuelve el acceso rastreado. Si elimina la variable, el acceso rastreado devolverá una cadena vacía.

Cuando se ha especificado el rastreo de array, el procedimiento de rastreo se invocará al comienzo de la implementación del comando de array, antes de que se invoquen operaciones como get, set o names. El procedimiento de rastreo puede modificar los elementos del array con Tcl_SetVar y Tcl_SetVar2.

Cuando se ha especificado el rastreo de anulación, el procedimiento de rastreo se invocará cada vez que se destruya la variable. Los rastreos se llamarán después de que la variable haya sido completamente anulada.

RASTREOS DE ARRAY COMPLETOS

Si una llamada a Tcl_TraceVar o Tcl_TraceVar2 especifica el nombre de una variable de array sin un índice en el array, entonces el rastreo se establecerá en el array en su conjunto. Esto significa que proc se invocará cada vez que se acceda a cualquier elemento del array de las maneras especificadas por flags. Cuando se anula un array, se invocará un rastreo de array completo solo una vez, con name1 igual al nombre del array y name2 NULL; no se invocará una vez por cada elemento.

RASTREOS MULTIPLES

Es posible que existan múltiples rastreos en la misma variable. Cuando esto sucede, todos los procedimientos de rastreo se invocarán en cada acceso, en orden de más reciente a menos reciente. Cuando existen rastreos de array completos para un array, así como rastreos en elementos individuales, los rastreos de array completos se invocan antes que los rastreos de elementos individuales. Si un rastreo de lectura o escritura anula la variable, se invocarán todos los rastreos de anulación, pero se omitirán los rastreos restantes de lectura y escritura.

VALORES DE RETORNO DE ERROR

En condiciones normales, los procedimientos de rastreo deben devolver NULL, lo que indica una finalización exitosa. Si proc devuelve un valor distinto de NULL, significa que ocurrió un error. El valor de retorno debe ser un puntero a una cadena de caracteres estática que contenga un mensaje de error, a menos que (exactamente uno de) los flags TCL_TRACE_RESULT_DYNAMIC y TCL_TRACE_RESULT_OBJECT estén establecidos, que especifican que el resultado es una cadena dinámica (que se liberará con ckfree) o un Tcl_Obj* (convertido a char* y que se liberará con Tcl_DecrRefCount) que contenga el mensaje de error. Si un procedimiento de rastreo devuelve un error, no se invocan más rastreos para el acceso y el acceso rastreado se interrumpe con el mensaje dado. Los procedimientos de rastreo pueden usar esta facilidad para hacer que las variables no sean escribibles, por ejemplo (pero tenga en cuenta que el valor de la variable ya se habrá modificado antes de que se llame al procedimiento de rastreo, por lo que el procedimiento de rastreo tendrá que restaurar el valor correcto).

El valor de retorno de proc solo se utiliza durante los rastreos de lectura y escritura. Durante los rastreos de anulación, el valor de retorno se ignora y todos los procedimientos de rastreo relevantes siempre se invocarán.

RESTRICCIONES

Un procedimiento de rastreo puede ser llamado en cualquier momento, incluso cuando hay resultados parcialmente formados almacenados en el intérprete. Si el procedimiento de rastreo hace algo que pueda dañar este resultado (como llamar a Tcl_Eval), debe usar las rutinas Tcl_SaveInterpState y relacionadas para guardar y restaurar el estado original del intérprete antes de devolver.

VARIABLES NO DEFINIDAS

Es legal establecer un rastreo en una variable no definida. La variable aún parecerá no definida hasta la primera vez que se establezca su valor. Si se rastrea una variable no definida y luego se anula, la anulación fallará con un error ("no such variable"), pero el procedimiento de rastreo aún se invocará.

FLAG TCL_TRACE_DESTROYED

En un callback de anulación a proc, el bit TCL_TRACE_DESTROYED se establece en flags si el rastreo se está eliminando como parte de la eliminación. Los rastreos de una variable siempre se eliminan cuando se elimina la variable; la única vez que TCL_TRACE_DESTROYED no se establece es para un rastreo de array completo invocado cuando solo se anula un solo elemento de un array.

TCL_INTERP_DESTROYED

Cuando se destruye un intérprete, se llaman los rastreos de anulación para todas sus variables. El bit TCL_INTERP_DESTROYED se establecerá en el argumento flags pasado a los procedimientos de rastreo. Los procedimientos de rastreo deben ser extremadamente cuidadosos en lo que hacen si el bit TCL_INTERP_DESTROYED está establecido. No es seguro que los procedimientos invoquen ningún procedimiento Tcl en el intérprete, ya que su estado está parcialmente eliminado. Lo único que deben hacer los procedimientos de rastreo en estas circunstancias es limpiar y liberar sus propias estructuras de datos internas.

ERRORES CONOCIDOS

Tcl no realiza ninguna comprobación de errores para evitar que los procedimientos de rastreo utilicen incorrectamente el intérprete durante los rastreos con TCL_INTERP_DESTROYED establecido.

Los rastreos de array aún no están integrados con el comando Tcl info exists, ni existe acceso a nivel de Tcl para rastreos de array.
