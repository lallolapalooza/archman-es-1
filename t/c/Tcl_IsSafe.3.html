DESCRIPCIÓN

Estos procedimientos están destinados al acceso a la instalación de múltiples intérpretes desde programas C. Permiten administrar múltiples intérpretes en una relación jerárquica y la administración de alias, comandos que al ser invocados en un intérprete ejecutan un comando en otro intérprete. El valor de retorno para aquellos procedimientos que devuelven un int es TCL_OK o TCL_ERROR. Si se devuelve TCL_ERROR, el resultado del intérprete contiene un mensaje de error.

Tcl_CreateSlave crea un nuevo intérprete como hijo de interp. También crea un comando hijo llamado childName en interp que permite a interp manipular al nuevo hijo. Si isSafe es cero, el comando crea un hijo confiable en el que el código Tcl tiene acceso a todos los comandos Tcl. Si es 1, el comando crea un hijo “seguro” en el que el código Tcl solo tiene acceso al conjunto de comandos Tcl definidos como “Safe Tcl”; consulte la entrada del manual del comando interp de Tcl para obtener más detalles. Si la creación del nuevo intérprete hijo falló, se devuelve NULL.

Tcl_CreateChild es un sinónimo de Tcl_CreateSlave.

Tcl_IsSafe devuelve 1 si interp es “seguro” (fue creado con el flag TCL_SAFE_INTERPRETER especificado), 0 en caso contrario.

Tcl_MakeSafe marca interp como “seguro”, de modo que las futuras llamadas a Tcl_IsSafe devuelvan 1. También elimina toda la funcionalidad central potencialmente insegura conocida (tanto comandos como variables) de interp. Sin embargo, no puede saber qué partes de una extensión o aplicación son seguras y no hace ningún intento de eliminar esas partes, por lo que la seguridad no está garantizada después de llamar a Tcl_MakeSafe. Los llamadores querrán tener cuidado con su uso de Tcl_MakeSafe para evitar afirmaciones falsas de seguridad. Para muchas situaciones, Tcl_CreateSlave puede ser una mejor opción, ya que crea intérpretes en un estado conocido como seguro.

Tcl_GetSlave devuelve un puntero a un intérprete hijo de interp. El intérprete hijo se identifica por childName. Si no existe dicho intérprete hijo, se devuelve NULL.

Tcl_GetChild es un sinónimo de Tcl_GetSlave.

Tcl_GetMaster devuelve un puntero al intérprete maestro de interp. Si interp no tiene maestro (es un intérprete de nivel superior) entonces se devuelve NULL.

Tcl_GetParent es un sinónimo de Tcl_GetMaster.

Tcl_GetInterpPath almacena en el resultado de interp la ruta relativa entre interp y childInterp; childInterp debe ser un hijo de interp. Si el cálculo de la ruta relativa tiene éxito, se devuelve TCL_OK, de lo contrario se devuelve TCL_ERROR y se almacena un mensaje de error como resultado de interp.

Tcl_CreateAlias crea un comando llamado childCmd en childInterp que, al ser invocado, hará que el comando targetCmd se invoque en targetInterp. Los argumentos especificados por las cadenas contenidas en argv siempre se anteponen a cualquier argumento proporcionado en la invocación de childCmd y se pasan a targetCmd. Esta operación devuelve TCL_OK si tiene éxito, o TCL_ERROR si falla; en ese caso, se deja un mensaje de error en el resultado de valor de childInterp. Tenga en cuenta que no hay restricciones en la relación de ascendencia (creada por Tcl_CreateSlave) entre childInterp y targetInterp. Se pueden utilizar dos intérpretes cualesquiera, sin restricciones sobre cómo están relacionados.

Tcl_CreateAliasObj es similar a Tcl_CreateAlias excepto que toma un vector de valores para pasar como argumentos adicionales en lugar de un vector de cadenas.

Tcl_GetAliasObj devuelve información en forma de un puntero a un vector de estructuras Tcl_Obj sobre un alias aliasName en interp. Cualquiera de los campos de resultado puede ser NULL, en cuyo caso el dato correspondiente no se devuelve. Si un campo de resultado no es NULL, la dirección indicada se establece en el dato correspondiente. Por ejemplo, si targetCmdPtr no es NULL, se establece en un puntero a la cadena que contiene el nombre del comando de destino.

Tcl_GetAlias es similar a Tcl_GetAliasObj excepto que devuelve un puntero a un vector de cadenas en lugar de un vector de estructuras Tcl_Obj. Tcl_GetAlias está obsoleto

Tcl_IsSafe(3) - Tcl API

NAME

Tcl_IsSafe, Tcl_CreateSlave, Tcl_MakeSafe, Tcl_MakeShared, Tcl_AllowExceptions - Determine whether an interpreter is safe, create slave interpreters, make interpreters safe or shared, and control exceptions

SYNOPSIS

#include <tcl.h>

int
Tcl_IsSafe(interp);

int
Tcl_CreateSlave(interp, slaveName, isSafe);

void
Tcl_MakeSafe(interp);

void
Tcl_MakeShared(interp);

void
Tcl_AllowExceptions(interp);

ARGUMENTS

Tcl_Interp *interp (in)
Interpreter to query or modify.
const char *slaveName (in)
Name for the new slave interpreter.
int isSafe (in)
Whether the new slave should be safe (1) or unsafe (0). See below.

DESCRIPTION

These functions manage the safety and security of Tcl interpreters. Tcl uses a security model where interpreters can be designated as "safe" or "unsafe". Safe interpreters have restricted access to the system and Tcl commands, preventing potentially malicious scripts from causing harm. Unsafe interpreters have full access.

Tcl_IsSafe(interp) returns non-zero if interp is a safe interpreter, and zero otherwise.

Tcl_CreateSlave(interp, slaveName, isSafe) creates a new interpreter that is a child (slave) of interp. The new interpreter is given the name slaveName within interp's namespace hierarchy. If isSafe is true, the new interpreter is created as a safe interpreter. Otherwise, it is created as an unsafe interpreter. Tcl_CreateSlave returns the new slave interpreter's handle if successful, or NULL if an error occurred (e.g., if slaveName already exists). The error is reported in interp's result.

Tcl_MakeSafe(interp) converts the interpreter interp into a safe interpreter. This involves restricting the available commands, potentially removing access to file system operations, network sockets, and other potentially dangerous operations. This function should be called on an interpreter *before* any untrusted code is evaluated in it.

Tcl_MakeShared(interp) marks the interpreter interp as "shared". Shared interpreters are a special kind of unsafe interpreter. They can execute scripts in other interpreters, but they have a restricted set of commands available. They are intended for use in implementing application infrastructure where some level of scripting is needed, but full access is not required.

Tcl_AllowExceptions(interp) allows a safe interpreter to raise exceptions. By default, safe interpreters cannot raise exceptions. This function is used to permit specific safe interpreters to use commands like error and catch.

The safety model of Tcl interpreters is hierarchical. An unsafe interpreter can create safe or unsafe slaves. A safe interpreter can only create safe slaves. A shared interpreter can create shared or unsafe slaves.

For a description of the Tcl interface to multiple interpreters, see interp(n).
