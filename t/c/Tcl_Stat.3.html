Tcl_Access(3) Procedimientos de la biblioteca Tcl Tcl_Access(3)

NOMBRE

Tcl_Access, Tcl_Stat - comprobar permisos y otros atributos de archivos

SINOPSIS

#include <tcl.h>

int
Tcl_Access(path, mode)

int
Tcl_Stat(path, statPtr)

ARGUMENTOS

const char *path (entrada)
Nombre nativo del archivo cuyos atributos se van a comprobar.
int mode (entrada)
Máscara que consiste en uno o más de R_OK, W_OK, X_OK y F_OK. R_OK, W_OK y X_OK solicitan la comprobación de si el archivo existe y tiene permisos de lectura, escritura y ejecución, respectivamente. F_OK solo solicita una comprobación de la existencia del archivo.
struct stat *statPtr (salida)
La estructura que contiene el resultado.

DESCRIPCIÓN

A partir de Tcl 8.4, se deben preferir las API basadas en objetos Tcl_FSAccess y Tcl_FSStat sobre Tcl_Access y Tcl_Stat siempre que sea posible. Estas funciones también admiten la capa de sistema de archivos virtual de Tcl, que estas no.

FUNCIONES OBSOLETAS

Hay dos razones para llamar a Tcl_Access y Tcl_Stat en lugar de llamar directamente a las funciones a nivel de sistema access y stat. Primero, la implementación de Windows de ambas funciones corrige algunos errores en las llamadas a nivel de sistema. Segundo, tanto Tcl_Access como Tcl_Stat (así como Tcl_OpenFileChannelProc) se conectan a una lista enlazada de funciones. Esto permite la posibilidad de redirigir el acceso a archivos a medios o métodos de acceso alternativos.

Tcl_Access comprueba si se permitiría al proceso leer, escribir o probar la existencia del archivo (u otro objeto del sistema de archivos) cuyo nombre es path. Si path es un enlace simbólico en Unix, entonces se prueban los permisos del archivo al que se refiere este enlace simbólico.

En caso de éxito (se conceden todos los permisos solicitados), se devuelve cero. En caso de error (al menos un bit en `mode` solicitó un permiso que se deniega, o ocurrió algún otro error), se devuelve -1.

Tcl_Stat rellena la estructura stat `statPtr` con información sobre el archivo especificado. No necesita ningún derecho de acceso al archivo para obtener esta información, pero necesita derechos de búsqueda en todos los directorios mencionados en la ruta que conduce al archivo. La estructura stat incluye información sobre el dispositivo, inodo (siempre 0 en Windows), modo de privilegios, nlink (siempre 1 en Windows), id de usuario (siempre 0 en Windows), id de grupo (siempre 0 en Windows), rdev (igual que el dispositivo en Windows), tamaño, hora del último acceso, hora de la última modificación y hora de creación.

Si path existe, Tcl_Stat devuelve 0 y la estructura stat se rellena con datos. De lo contrario, se devuelve -1 y no se proporciona información de stat.
