Tcl_DeleteTrace(3)

Paquete: tcl

Licencias: TCL

Tcl_CreateTrace(3) Procedimientos de la biblioteca Tcl Tcl_CreateTrace(3)

NOMBRE

Tcl_CreateTrace, Tcl_CreateObjTrace, Tcl_DeleteTrace - organizar la ejecución de comandos para ser rastreados

SINOPSIS

#include <tcl.h>

Tcl_Trace
Tcl_CreateTrace(interp, level, proc, clientData)

Tcl_Trace
Tcl_CreateObjTrace(interp, level, flags, objProc, clientData, deleteProc)

Tcl_DeleteTrace(interp, trace)

ARGUMENTOS

Tcl_Interp *interp (entrada)
Intérprete que contiene el comando a rastrear o no rastrear.
int level (entrada)
Solo los comandos en este nivel de anidamiento o inferiores serán rastreados a menos que se especifique 0. 1 significa solo comandos de nivel superior, 2 significa comandos de nivel superior o aquellos que se invocan como consecuencias inmediatas de la ejecución de comandos de nivel superior (cuerpos de procedimientos, comandos entre corchetes, etc.) y así sucesivamente. Un valor de 0 significa que los comandos en cualquier nivel son rastreados.
int flags (entrada)
Banderas que rigen la ejecución del rastreo. Ver abajo para más detalles.
Tcl_CmdObjTraceProc *objProc (entrada)
Procedimiento a llamar para cada comando que se ejecuta. Ver abajo para más detalles de la secuencia de llamada.
Tcl_CmdTraceProc *proc (entrada)
Procedimiento a llamar para cada comando que se ejecuta. Ver abajo para más detalles de la secuencia de llamada.
ClientData clientData (entrada)
Valor arbitrario de una palabra para pasar a objProc o proc.
Tcl_CmdObjTraceDeleteProc *deleteProc (entrada)
Procedimiento a llamar cuando se elimina el rastreo. Ver abajo para más detalles de la secuencia de llamada. Un puntero NULL es permisible y resulta en ninguna devolución de llamada cuando se elimina el rastreo.
Tcl_Trace trace (entrada)
Token para el rastreo a eliminar (valor de retorno de una llamada anterior a Tcl_CreateTrace).

DESCRIPCIÓN

Tcl_CreateObjTrace organiza el rastreo de comandos. Después de ser llamado, objProc será invocado antes de que el intérprete Tcl llame a cualquier procedimiento de comando al evaluar comandos en interp. El valor de retorno de Tcl_CreateObjTrace es un token para el rastreo, que puede pasarse a Tcl_DeleteTrace para eliminar el rastreo. Puede haber muchos rastreos en efecto simultáneamente para el mismo intérprete.

objProc debe tener argumentos y un resultado que coincidan con el tipo, Tcl_CmdObjTraceProc:

typedef int Tcl_CmdObjTraceProc(
        ClientData clientData,
        Tcl_Interp* interp,
        int level,
        const char *command,
        Tcl_Command commandToken,
        int objc,
        Tcl_Obj *const objv[]);

Los parámetros clientData e interp son copias de los argumentos correspondientes dados a Tcl_CreateTrace. ClientData típicamente apunta a una estructura de datos específica de la aplicación que describe qué hacer cuando se invoca objProc. El parámetro level da el nivel de anidamiento del comando (1 para comandos de nivel superior pasados a Tcl_Eval por la aplicación, 2 para los comandos de nivel siguiente pasados a Tcl_Eval como parte del análisis o interpretación de comandos de nivel 1, y así sucesivamente). El parámetro command apunta a una cadena que contiene el texto del comando, antes de cualquier sustitución de argumento. El parámetro commandToken es un token de comando Tcl que identifica el comando a invocar. El token puede pasarse a Tcl_GetCommandName, Tcl_GetCommandInfoFromToken o Tcl_SetCommandInfoFromToken para manipular la definición del comando. Los parámetros objc y objv designan el recuento final de parámetros y el vector de parámetros que se pasarán al comando, y han tenido todas las sustituciones realizadas.

Se espera que la devolución de llamada objProc devuelva un código de estado estándar de Tcl. Si este código es TCL_OK (el caso normal), el intérprete Tcl invocará el comando. Cualquier otro código de retorno se trata como si el comando hubiera devuelto ese estado, y el comando *no* se invoca.

La devolución de llamada objProc no debe modificar objv de ninguna manera.

El rastreo solo ocurrirá para comandos en niveles de anidamiento menores o iguales al parámetro level (es decir, el parámetro level para objProc siempre será menor o igual al parámetro level para Tcl_CreateTrace).

El rastreo tiene un efecto significativo en el rendimiento en tiempo de ejecución porque hace que el compilador de bytecode se abstenga de generar código en línea para comandos Tcl como if y while para que puedan ser rastreados. Si no se requieren rastreos para los comandos incorporados, el parámetro flags puede establecerse en el valor constante TCL_ALLOW_INLINE_COMPILATION. En este caso, los rastreos en comandos incorporados pueden o no resultar en devoluciones de llamada de rastreo, dependiendo del estado del intérprete, pero el rendimiento en tiempo de ejecución mejorará significativamente. (Esta funcionalidad es deseable, por ejemplo, al usar Tcl_CreateObjTrace para implementar un generador de perfiles de tiempo de ejecución.)

Las llamadas a objProc serán realizadas por el analizador Tcl inmediatamente antes de que llame al procedimiento del comando (cmdProc). Esto ocurre después del análisis y la sustitución de argumentos, por lo que el rastreo de comandos sustituidos ocurre antes del rastreo de los comandos que contienen las sustituciones. Si hay un error de sintaxis en un comando, o si no hay un procedimiento de comando asociado con un nombre de comando, entonces no ocurrirá ningún rastreo para ese comando. Si una cadena pasada a Tcl_Eval contiene múltiples comandos (entre corchetes o en diferentes líneas), entonces ocurrirán múltiples llamadas a objProc, una por cada comando.

Tcl_DeleteTrace elimina un rastreo, de modo que no se realizarán llamadas futuras al procedimiento asociado con el rastreo. Después de que Tcl_DeleteTrace devuelva, el llamador nunca debe volver a usar el token trace.

Cuando se llama a Tcl_DeleteTrace, el intérprete invoca el deleteProc que se pasó como parámetro a Tcl_CreateObjTrace. El deleteProc debe coincidir con el tipo, Tcl_CmdObjTraceDeleteProc:

typedef void Tcl_CmdObjTraceDeleteProc(
        ClientData clientData);

El parámetro clientData será el mismo que el parámetro clientData que se pasó originalmente a Tcl_CreateObjTrace.

Tcl_CreateTrace es una interfaz alternativa para el rastreo de comandos, no recomendada para nuevas aplicaciones. Se proporciona para compatibilidad con versiones anteriores con código que se desarrolló para versiones anteriores del intérprete Tcl. Es similar a Tcl_CreateObjTrace, excepto que su parámetro proc debe tener argumentos y un resultado que coincidan con el tipo Tcl_CmdTraceProc:

typedef void Tcl_CmdTraceProc(
        ClientData clientData,
        Tcl_Interp *interp,
        int level,
        char *command,
        Tcl_CmdProc *cmdProc,
        ClientData cmdClientData,
        int argc,
        const char *argv[]);

Los parámetros de la devolución de llamada proc son similares a los de la devolución de llamada objProc anterior. El commandToken se reemplaza con cmdProc, un puntero al procedimiento de comando (basado en cadenas) que se invocará; y cmdClientData, los datos del cliente que se pasarán al procedimiento. El parámetro objc se reemplaza con un parámetro argv, que da los argumentos del comando como cadenas de caracteres. Proc no debe modificar las cadenas de command o argv.

Si un rastreo creado con Tcl_CreateTrace está en efecto, la compilación en línea de comandos Tcl como if y while se deshabilita siempre. No hay notificación cuando se elimina un rastreo creado con Tcl_CreateTrace. No hay forma de ser notificado cuando se elimina el rastreo creado por Tcl_CreateTrace. No hay forma de que *proc* asociado con una llamada a Tcl_CreateTrace pueda abortar la ejecución de *command*.
