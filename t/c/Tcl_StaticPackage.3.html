Tcl_StaticPackage(3) Procedimientos de la biblioteca Tcl Tcl_StaticPackage(3)

NOMBRE

Tcl_StaticPackage - hacer que un paquete enlazado estáticamente esté disponible a través del comando 'load'

SINOPSIS

#include <tcl.h>

Tcl_StaticPackage(interp, prefix, initProc, safeInitProc)

ARGUMENTOS

Tcl_Interp *interp (entrada)
Si no es NULL, apunta a un intérprete en el que el paquete ya se ha cargado (es decir, el llamador ya ha invocado el procedimiento de inicialización apropiado). NULL significa que el paquete aún no se ha incorporado a ningún intérprete.
const char *prefix (entrada)
Prefijo para la función de inicialización de la biblioteca; debe estar correctamente capitalizado (primera letra mayúscula, el resto minúsculas).
Tcl_PackageInitProc *initProc (entrada)
Procedimiento a invocar para incorporar este paquete a un intérprete de confianza.
Tcl_PackageInitProc *safeInitProc (entrada)
Procedimiento a llamar para incorporar este paquete a un intérprete seguro (uno que ejecutará scripts no confiables). NULL significa que el paquete no se puede usar en intérpretes seguros.

DESCRIPCIÓN

Este procedimiento puede invocarse para anunciar que un paquete se ha enlazado estáticamente con una aplicación Tcl y, opcionalmente, que ya se ha cargado en un intérprete. Una vez que se ha invocado Tcl_StaticPackage para un paquete, este puede cargarse en intérpretes utilizando el comando load. Tcl_StaticPackage normalmente solo lo invoca el procedimiento Tcl_AppInit para la aplicación, no los paquetes para sí mismos (Tcl_StaticPackage solo debe invocarse para paquetes cargados estáticamente, y el código del paquete en sí no necesita saber si el paquete se carga dinámicamente o estáticamente).

Cuando se utiliza el comando load más adelante para cargar el paquete en un intérprete, se invocará uno de initProc o safeInitProc, dependiendo de si el intérprete de destino es seguro o no. initProc y safeInitProc deben coincidir con el siguiente prototipo:

typedef int Tcl_PackageInitProc(
        Tcl_Interp *interp);

El argumento interp identifica el intérprete en el que se cargará el paquete. El procedimiento de inicialización debe devolver TCL_OK o TCL_ERROR para indicar si se completó con éxito o no; en caso de error, debe establecer el resultado del intérprete para que apunte a un mensaje de error. El resultado o error del procedimiento de inicialización se devolverá como el resultado del comando load que provocó la invocación del procedimiento de inicialización.
