DESCRIPCIÓN

Las rutinas Tcl_SetReturnOptions y Tcl_GetReturnOptions exponen las mismas capacidades que los comandos return y catch, respectivamente, en forma de una interfaz C.

Tcl_GetReturnOptions recupera el diccionario de opciones de retorno de un intérprete después de una evaluación de script. Rutinas como Tcl_Eval se llaman para evaluar un script en un intérprete. Estas rutinas devuelven un código de finalización entero. Estas rutinas también dejan en el intérprete tanto un resultado como un diccionario de opciones de retorno generado por la evaluación del script. Así como Tcl_GetObjResult recupera el resultado, Tcl_GetReturnOptions recupera el diccionario de opciones de retorno. El código de finalización entero debe pasarse como el argumento code a Tcl_GetReturnOptions para que todas las opciones requeridas estén presentes en el diccionario. Específicamente, un valor code de TCL_ERROR asegurará que las entradas para las claves -errorinfo, -errorcode y -errorline aparezcan en el diccionario. Además, las entradas para las claves -code y -level se ajustarán si es necesario para coincidir con el valor de code. El (Tcl_Obj *) devuelto por Tcl_GetReturnOptions apunta a un Tcl_Obj no compartido con un contador de referencias de cero. El diccionario puede ser escrito, añadiendo, eliminando o sobrescribiendo cualquiera de sus entradas, sin necesidad de comprobar un valor compartido. Como con cualquier Tcl_Obj con un contador de referencias de cero, depende del llamador organizar su eliminación con Tcl_DecrRefCount o tomar una referencia a él mediante Tcl_IncrRefCount (o una de las muchas funciones que llaman a esta, incluyendo notablemente Tcl_SetObjResult y Tcl_SetVar2Ex).

Un uso típico para Tcl_GetReturnOptions es recuperar el rastreo de pila cuando la evaluación del script devuelve TCL_ERROR, como sigue:

int code = Tcl_Eval(interp, script);
if (code == TCL_ERROR) {
    Tcl_Obj *options = Tcl_GetReturnOptions(interp, code);
    Tcl_Obj *key = Tcl_NewStringObj("-errorinfo", -1);
    Tcl_Obj *stackTrace;
    Tcl_IncrRefCount(key);
    Tcl_DictObjGet(NULL, options, key, &stackTrace);
    Tcl_DecrRefCount(key);
    /* Haz algo con stackTrace */
    Tcl_DecrRefCount(options);
}

Tcl_SetReturnOptions establece las opciones de retorno de interp a options. Si options contiene algún valor no válido para alguna clave, se devolverá TCL_ERROR, y el resultado del intérprete se establecerá a un mensaje de error apropiado. De lo contrario, se devolverá un código de finalización coherente con las claves -code y -level en options.

Como ejemplo, el propio comando return de Tcl podría implementarse en términos de Tcl_SetReturnOptions de la siguiente manera:

if ((objc % 2) == 0) { /* argumento de resultado explícito */
    objc--;
    Tcl_SetObjResult(interp, objv[objc]);
}
return Tcl_SetReturnOptions(interp, Tcl_NewListObj(objc-1, objv+1));

(En realidad, no está implementado de esa manera. Los privilegios de acceso interno permiten una alternativa más eficiente que se integra mejor con el compilador de bytecode.)

Tenga en cuenta que se puede pasar un Tcl_Obj recién creado como argumento options sin necesidad de preocuparse por ningún recuento de referencias. Esto es análogo a Tcl_SetObjResult.

Si bien Tcl_SetReturnOptions proporciona una interfaz general para establecer cualquier colección de opciones de retorno, existen un puñado de opciones de retorno que se utilizan con mucha frecuencia. En particular, las opciones de retorno -errorinfo y -errorcode deben establecerse correctamente cuando el procedimiento del comando de un comando devuelve TCL_ERROR. La opción de retorno -errorline también es leída por los comandos que evalúan scripts y desean proporcionar información detallada de ubicación de error en el texto del rastreo de pila que añaden a la opción -errorinfo. Tcl proporciona varias interfaces más sencillas para establecer estas opciones de retorno de forma más directa.

La opción -errorinfo contiene un rastreo de pila de las operaciones que estaban en curso cuando ocurrió un error, y está destinada a ser legible por humanos. La opción -errorcode contiene una lista Tcl de elementos destinados a ser legibles por máquinas. El primer elemento en el valor -errorcode identifica la clase de error que ocurrió (por ejemplo, POSIX significa que ocurrió un error en una llamada al sistema POSIX) y los elementos adicionales contienen piezas de información adicionales que dependen de la clase. Consulte la entrada del manual sobre la variable errorCode para obtener detalles sobre los diversos formatos para la opción -errorcode utilizados por los comandos integrados de Tcl.

El valor de la opción -errorinfo se va construyendo gradualmente a medida que un error se desenrolla a través de las operaciones anidadas. Cada vez que un código de error se devuelve a Tcl_Eval, o a cualquiera de las rutinas que realiza la evaluación de scripts, se llama al procedimiento Tcl_AddErrorInfo para añadir texto adicional al valor -errorinfo que describe el comando que se estaba ejecutando cuando ocurrió el error. Para cuando el error ha sido devuelto completamente a la aplicación, contendrá un rastreo completo de la actividad en curso cuando ocurrió el error.

A veces es útil añadir información adicional al valor -errorinfo más allá de lo que pueden suministrar automáticamente las rutinas de evaluación de scripts. Tcl_AddErrorInfo puede utilizarse para este propósito: su argumento message es una cadena adicional que se añadirá a la opción -errorinfo. Por ejemplo, cuando surge un error durante el comando source, se llama al procedimiento Tcl_AddErrorInfo para registrar el nombre del archivo que se está procesando y el número de línea en el que ocurrió el error. DESCRIPCION

Estas funciones se utilizan para gestionar la información de error asociada a un intérprete de Tcl. Cuando un comando Tcl falla, el intérprete almacena información sobre el error, que puede ser consultada posteriormente. Las funciones descritas aquí proporcionan una forma de construir y acceder a esta información de error.

Tcl_AddErrorInfo añade el message proporcionado al final de la opción de retorno -errorinfo del intérprete. La información de error se almacena como una cadena de varias líneas, donde cada línea representa un nivel de la pila de llamadas. Cuando se produce un error en una llamada a procedimiento Tcl, se registra el nombre del procedimiento y el número de línea dentro del procedimiento, etc. El mejor momento para llamar a Tcl_AddErrorInfo es justo después de que una rutina de evaluación de scripts haya devuelto TCL_ERROR. El valor de la opción de retorno -errorline (recuperado mediante una llamada a Tcl_GetReturnOptions) a menudo constituye una parte útil del message pasado a Tcl_AddErrorInfo.

Tcl_AppendObjToErrorInfo es una interfaz alternativa a la misma funcionalidad que Tcl_AddErrorInfo. Tcl_AppendObjToErrorInfo se llama cuando el valor de cadena a añadir a la opción -errorinfo está disponible como un Tcl_Obj en lugar de como un array de char.

Tcl_AddObjErrorInfo es casi idéntica a Tcl_AddErrorInfo, excepto que tiene un argumento adicional length. Esto permite que la cadena message contenga bytes nulos incrustados. Esto es esencialmente una mala idea. Si el message necesita contener el carácter nulo U+0000, se deben utilizar las reglas de codificación internas habituales de Tcl para evitar la necesidad de un byte nulo. Si la interfaz Tcl_AddObjErrorInfo se utiliza en absoluto, debería ser con un valor length negativo.

El procedimiento Tcl_SetObjErrorCode se utiliza para establecer la opción de retorno -errorcode al valor de lista errorObjPtr construido por el llamante. Tcl_SetObjErrorCode se invoca típicamente justo antes de devolver un error. Si se devuelve un error sin llamar a Tcl_SetObjErrorCode o Tcl_SetErrorCode, el intérprete de Tcl establece automáticamente la opción de retorno -errorcode a NONE.

El procedimiento Tcl_SetErrorCode también se utiliza para establecer la opción de retorno -errorcode. Sin embargo, toma una o más cadenas para registrar en lugar de un valor. De lo contrario, es similar en comportamiento a Tcl_SetObjErrorCode.

Tcl_SetErrorCodeVA es lo mismo que Tcl_SetErrorCode excepto que en lugar de tomar un número variable de argumentos toma una lista de argumentos.

El procedimiento Tcl_GetErrorLine se utiliza para leer el valor entero de la opción de retorno -errorline sin la sobrecarga de una llamada completa a Tcl_GetReturnOptions. Del mismo modo, Tcl_SetErrorLine establece el valor de la opción de retorno -errorline.

Tcl_PosixError establece la variable -errorcode después de un error en una llamada al kernel POSIX. Lee el valor de la variable C errno y llama a Tcl_SetErrorCode para establecer la opción de retorno -errorcode en el formato POSIX. El llamante debe haber llamado previamente a Tcl_SetErrno para establecer errno; esto es necesario en algunas plataformas (por ejemplo, Windows) donde Tcl se vincula a una aplicación como una biblioteca compartida, o cuando el error ocurre en una extensión cargada dinámicamente. Consulte la página del manual de Tcl_SetErrno para obtener más información.

Tcl_PosixError devuelve un mensaje de diagnóstico legible por humanos para el error (este es el mismo valor que aparecerá como el tercer elemento en el valor de -errorcode). Puede ser conveniente incluir esta cadena como parte del mensaje de error devuelto a la aplicación en el resultado del intérprete.

Tcl_LogCommandInfo se invoca después de que ocurre un error en un intérprete. Añade información sobre el comando que se estaba ejecutando cuando ocurrió el error al valor -errorinfo, y se establece el número de línea almacenado internamente en el intérprete.

En versiones anteriores de Tcl, no existía la rutina Tcl_GetReturnOptions. En su lugar, las variables globales de Tcl errorInfo y errorCode eran el único lugar para recuperar la información de error. Mucho código existente escrito para versiones anteriores de Tcl todavía accede a esta información a través de esas variables globales.

Es importante darse cuenta de que, si bien leer de esas variables globales sigue siendo una forma admitida de acceder a estos valores de opciones de retorno, es importante no asumir que escribir en esas variables globales establecerá correctamente las opciones de retorno correspondientes. Se ha enfatizado durante mucho tiempo en esta página del manual que es importante llamar a los procedimientos descritos aquí en lugar de establecer errorInfo o errorCode directamente con Tcl_ObjSetVar2.

Si se llama al procedimiento Tcl_ResetResult, se borra todo el estado del intérprete asociado con la evaluación de scripts, incluido el diccionario completo de opciones de retorno. En particular, las opciones -errorinfo y -errorcode se restablecen. Si se hubiera producido un error, la llamada a Tcl_ResetResult borrará el estado de error para que parezca que no ha ocurrido ningún error después de todo. Las variables globales errorInfo y errorCode no son modificadas por Tcl_ResetResult, por lo que continúan conteniendo un registro de información sobre el error más reciente visto en un intérprete.
