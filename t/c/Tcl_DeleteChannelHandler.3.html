Tcl_CreateChannelHandler(3) Procedimientos de la biblioteca Tcl Tcl_CreateChannelHandler(3)

NOMBRE

Tcl_CreateChannelHandler, Tcl_DeleteChannelHandler - llamar a un procedimiento cuando un canal sea legible o escribible

SINOPSIS

#include <tcl.h>

void
Tcl_CreateChannelHandler(canal, máscara, proc, datosCliente)

void
Tcl_DeleteChannelHandler(canal, proc, datosCliente)

ARGUMENTOS

Tcl_Channel canal (entrada)
Canal Tcl como el devuelto por Tcl_CreateChannel.
int máscara (entrada)
Condiciones bajo las cuales se debe llamar a proc: combinación OR de TCL_READABLE, TCL_WRITABLE y TCL_EXCEPTION. Especificar un valor cero para deshabilitar temporalmente un manejador existente.
Tcl_FileProc *proc (entrada)
Procedimiento a invocar siempre que el canal indicado por canal cumpla las condiciones especificadas por máscara.
ClientData datosCliente (entrada)
Valor arbitrario de una palabra para pasar a proc.

DESCRIPCIÓN

Tcl_CreateChannelHandler organiza la llamada a proc en el futuro siempre que la entrada o salida sea posible en el canal identificado por canal, o siempre que exista una condición excepcional para canal. Las condiciones de interés bajo las cuales se invocará proc se especifican mediante el argumento máscara. Consulte la entrada del manual para fileevent para una descripción precisa de lo que significa que un canal sea legible o escribible. Proc debe conformarse al siguiente prototipo:

typedef void Tcl_ChannelProc(
        ClientData datosCliente,
        int máscara);

El argumento datosCliente es el mismo que el valor pasado a Tcl_CreateChannelHandler cuando se creó el manejador. Típicamente, datosCliente apunta a una estructura de datos que contiene información específica de la aplicación sobre el canal. Máscara es una máscara entera que indica cuáles de las condiciones solicitadas existen realmente para el canal; contendrá un subconjunto de los bits del argumento máscara a Tcl_CreateChannelHandler cuando se creó el manejador.

Cada manejador de canal se identifica por una combinación única de canal, proc y datosCliente. Puede haber muchos manejadores para un canal dado siempre que no tengan el mismo canal, proc y datosCliente. Si se invoca Tcl_CreateChannelHandler cuando ya existe un manejador para canal, proc y datosCliente, entonces no se crea ningún manejador nuevo; en su lugar, se cambia la máscara para el manejador existente.

Tcl_DeleteChannelHandler elimina un manejador de canal identificado por canal, proc y datosCliente; si no existe dicho manejador, la llamada no tiene ningún efecto.

Los manejadores de canal se invocan a través del mecanismo de eventos de Tcl, por lo que solo son útiles en aplicaciones basadas en eventos. Tenga en cuenta también que las condiciones especificadas en el argumento máscara a proc pueden ya no existir cuando se invoca proc: por ejemplo, si hay dos manejadores para TCL_READABLE en el mismo canal, el primer manejador podría consumir toda la entrada disponible para que el canal ya no sea legible cuando se invoque el segundo manejador. Por esta razón, puede ser útil utilizar E/S no bloqueantes en canales para los que existen manejadores de eventos.
