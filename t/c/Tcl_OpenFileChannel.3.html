ARGUMENTOS

Tcl_Interp *interp (in)
Se usa para informar de errores y para buscar un canal registrado en él.
const char *fileName (in)
El nombre de un archivo local o de red.
const char *mode (in)
Especifica cómo se va a acceder al archivo. Puede tener cualquiera de los valores permitidos para el argumento mode del comando Tcl open.
int permissions (in)
Indicadores de permisos de estilo POSIX, como 0644. Si se crea un archivo nuevo, estos permisos se aplicarán al archivo creado.
int argc (in)
El número de elementos en argv.
const char **argv (in)
Argumentos para construir una tubería de comandos. Estos valores tienen el mismo significado que los argumentos que no son opciones del comando Tcl exec.
int flags (in)
Especifica la disposición de los manejadores de stdio en la tubería: combinación OR de TCL_STDIN, TCL_STDOUT, TCL_STDERR y TCL_ENFORCE_MODE. Si se establece TCL_STDIN, la entrada estándar del primer hijo en la tubería es el canal de la tubería, de lo contrario es la misma que la entrada estándar del proceso invocador; lo mismo para TCL_STDOUT y TCL_STDERR. Si no se establece TCL_ENFORCE_MODE, entonces la tubería puede redirigir los manejadores de stdio para anular los manejadores de stdio para los que se han establecido TCL_STDIN, TCL_STDOUT y TCL_STDERR. Si está establecido, tales redirecciones causan un error.
ClientData handle (in)
Manejador específico del sistema operativo para E/S a un archivo. Para Unix es un descriptor de archivo, para Windows es un HANDLE.
int readOrWrite (in)
Combinación OR de TCL_READABLE y TCL_WRITABLE para indicar qué operaciones son válidas en handle.
const char *channelName (in)
El nombre del canal.
int *modePtr (out)
Punta a una variable entera que recibirá una combinación OR de TCL_READABLE y TCL_WRITABLE indicando si el canal está abierto para lectura y escritura.
const char *pattern (in)
El patrón a igualar, pasado a Tcl_StringMatch, o NULL.
Tcl_Channel channel (in)
Un canal Tcl para entrada o salida. Debe haber sido el valor de retorno de un procedimiento como Tcl_OpenFileChannel.
Tcl_Obj *readObjPtr (in/out)
Un puntero a un valor Tcl en el que se almacenarán los caracteres leídos del canal.
int charsToRead (in)
El número de caracteres a leer del canal. Si la codificación del canal es binary, esto es equivalente al número de bytes a leer del canal.
int appendFlag (in)
Si es distinto de cero, los datos leídos del canal se añadirán al valor. De lo contrario, los datos reemplazarán el contenido existente del valor.
char *readBuf (out)
Un búfer en el que se almacenarán los bytes leídos del canal.
int bytesToRead (in)
El número de bytes a leer del canal. El búfer readBuf debe ser lo suficientemente grande como para contener esta cantidad de bytes.
Tcl_Obj *lineObjPtr (in/out)
Un puntero a un valor Tcl en el que se almacenará la línea leída del canal. La línea leída se añadirá al valor actual del valor.
Tcl_DString *lineRead (in/out)
Un puntero a una cadena dinámica Tcl en la que se almacenará la línea leída del canal. Debe haber sido inicializada por el llamador. La línea leída se añadirá a cualquier dato que ya esté en la cadena dinámica.
const char *input (in)
La entrada a añadir a un búfer de canal.
int inputLen (in)
Longitud de la entrada
int addAtEnd (in)
Indicador que indica si la entrada debe añadirse al final o al principio del búfer del canal.
Tcl_Obj *writeObjPtr (in)
Un puntero a un valor Tcl cuyo contenido se enviará al canal.
const char *charBuf (in)
Un búfer que contiene los caracteres a enviar al canal.
const char *byteBuf (in)
Un búfer que contiene los bytes a enviar al canal.
int bytesToWrite (in)
El número de bytes a consumir de charBuf o byteBuf y enviar al canal.
Tcl_WideInt offset (in)
A qué distancia mover el punto de acceso en el canal en el que se aplicará la próxima operación de entrada o salida, medido en bytes desde la posición dada por seekMode. Puede ser positivo o negativo.
int seekMode (in)
Respecto a qué punto buscar; se utiliza junto con offset para calcular el nuevo punto de acceso para el canal. Los valores legales son SEEK_SET, SEEK_CUR y SEEK_END.
Tcl_WideInt length (in)
La longitud (no negativa) a la que truncar el canal.
const char *optionName (in)
El nombre de una opción aplicable a este canal, como -blocking. Puede tener cualquiera de los valores aceptados por el comando fconfigure.
Tcl_DString *optionValue (in)
Dónde almacenar el valor de una opción o una lista de todas las opciones y sus valores. Debe haber sido inicializado por el llamador.
const char *newValue (in)
Nuevo valor para la opción dada por optionName.

DESCRIPCIÓN

El mecanismo de canales de Tcl proporciona un mecanismo independiente de dispositivo y de plataforma para realizar operaciones de entrada y salida con búfer en una variedad de tipos de archivos, sockets y dispositivos. El mecanismo de canales es extensible a nuevos tipos de canales, proporcionando un controlador de canal de bajo nivel para el nuevo tipo; la interfaz del controlador de canal se describe en la entrada del manual para Tcl_CreateChannel. El mecanismo de canales proporciona un esquema de búfer modelado según la E/S estándar de Unix, y también permite E/S no bloqueante en canales.

Los procedimientos descritos en esta entrada del manual comprenden las API de C de la capa genérica de la arquitectura de canales. Para una descripción de la arquitectura del controlador de canales y cómo implementar controladores de canales para nuevos tipos de canales, consulte la entrada del manual para Tcl_CreateChannel.

TCL_OPENFILECHANNEL

Abre un canal que se puede utilizar para acceder a un archivo. El argumento fileName es el nombre del archivo a abrir, y mode especifica el modo de acceso. El argumento permissions se utiliza cuando se crea un archivo nuevo; especifica los permisos POSIX para el nuevo archivo. El valor devuelto es un manipulador de canal o NULL si se produce un error.

TCL_OPENCOMMANDCHANNEL

Crea un canal que implementa una tubería de comandos. El argumento argv y argc especifican el comando y sus argumentos. Los indicadores flags controlan cómo se redirigen los manejadores de stdio del proceso invocador. Por ejemplo, si se establece TCL_STDIN, la entrada estándar del primer proceso hijo de la tubería será el canal de la tubería recién creado, en lugar de la entrada estándar del proceso padre. El valor de retorno es un manipulador de canal o NULL si se produce un error.

TCL_MAKEFILECHANNEL

Convierte un manejador de E/S del sistema operativo existente (un descriptor de archivo en Unix, un HANDLE en Windows) en un canal Tcl. El argumento readOrWrite es una combinación OR de TCL_READABLE y TCL_WRITABLE que indica qué operaciones son válidas en el manejador. El valor devuelto es un manipulador de canal Tcl o NULL si se produce un error.

TCL_GETCHANNEL

Busca un canal registrado en el intérprete interp con el nombre channelName. Si se proporciona modePtr, se establece en una combinación OR de TCL_READABLE y TCL_WRITABLE para indicar si el canal está abierto para lectura y escritura.

TCL_GETCHANNELNAMES

Devuelve el número de canales actualmente registrados en el intérprete interp. Además, almacena una lista de los nombres de los canales registrados en la variable Tcl nombrada por Tcl_GetVar ("tcl_channelNames").

TCL_GETCHANNELNAMESEX

Similar a Tcl_GetChannelNames, pero solo devuelve los nombres de los canales que coinciden con el patrón dado. El patrón se evalúa usando la misma lógica que el comando Tcl string match. Si pattern es NULL, se comportará como Tcl_GetChannelNames.

TCL_REGISTERCHANNEL

Registra el canal channel en el intérprete interp. Una vez registrado, el canal será visible para los comandos Tcl como fconfigure y read.

TCL_UNREGISTERCHANNEL

Anula el registro del canal channel del intérprete interp. El canal se cerrará si no ha sido explícitamente cerrado por el usuario, y sus recursos se liberarán.

TCL_DETACHCHANNEL

Desvincula el canal channel del intérprete interp. El canal Tcl ya no se puede acceder a través de Tcl, pero el controlador subyacente del canal no se cierra. Esto es útil cuando se intercambian canales entre intérpretes Tcl o cuando se pasan a un proceso externo.

TCL_ISTANDARDCHANNEL

Devuelve 1 si el canal channel es uno de los canales estándar (entrada, salida o error estándar) para el intérprete interp, y 0 en caso contrario.

TCL_CLOSE

Cierra el canal channel. Esto fuerza la escritura de todos los datos en búfer y libera los recursos asociados con el canal. Si se produce un error durante el cierre, se establecerá una condición de error en el intérprete interp y la función devolverá -1; de lo contrario, devolverá 0.

TCL_READCHARS

Lee hasta charsToRead caracteres del canal channel. Los caracteres leídos se almacenan en el objeto Tcl al que apunta readObjPtr. Si appendFlag es distinto de cero, los caracteres se añadirán al valor existente del objeto; de lo contrario, reemplazarán el valor existente. La función devuelve el número de caracteres leídos o -1 si se produce un error o se alcanza el final del archivo. Tenga en cuenta que esta función sólo funciona correctamente para canales con codificación de caracteres.

TCL_READ

Lee hasta bytesToRead bytes del canal channel y los almacena en el búfer readBuf. La función devuelve el número de bytes leídos o -1 si se produce un error o se alcanza el final del archivo.

TCL_GETSOBJ

Lee una línea de entrada del canal channel, hasta el primer carácter de nueva línea. La línea leída se almacena en el objeto Tcl al que apunta lineObjPtr, añadiéndose al final de su valor actual. La función devuelve el número de caracteres leídos o -1 si se produce un error o se alcanza el final del archivo. Tenga en cuenta que esta función sólo funciona correctamente para canales con codificación de caracteres.

TCL_GETS

Similar a Tcl_GetsObj, pero lee la línea en una cadena dinámica Tcl (proporcionada por lineRead) en lugar de un objeto Tcl.

TCL_UNGETS

Añade la cadena input de longitud inputLen al principio (si addAtEnd es 0) o al final (si addAtEnd es distinto de cero) del búfer de entrada del canal channel. Esto es útil para implementar comandos que necesitan consumir parte de la entrada de un canal y luego devolverla para que sea procesada posteriormente.

TCL_WRITEOBJ

Escribe el contenido del objeto Tcl al que apunta writeObjPtr en el canal channel. La función devuelve el número de bytes escritos o -1 si se produce un error.

TCL_WRITECHARS

Escribe bytesToWrite caracteres del búfer charBuf en el canal channel. La función devuelve el número de bytes escritos o -1 si se produce un error.

TCL_WRITE

Escribe bytesToWrite bytes del búfer byteBuf en el canal channel. La función devuelve el número de bytes escritos o -1 si se produce un error.

TCL_READRAW

Similar a Tcl_Read, pero no realiza ninguna conversión de codificación. Esto es útil para leer datos binarios sin procesar.

TCL_WRITERAW

Similar a Tcl_Write, pero no realiza ninguna conversión de codificación. Esto es útil para escribir datos binarios sin procesar.

TCL_EOF

Devuelve 1 si se ha alcanzado el final del archivo en el canal channel, y 0 en caso contrario.

TCL_FLUSH

Fuerza la escritura de todos los datos en búfer del canal channel al dispositivo subyacente. Devuelve 0 si tiene éxito, o -1 si se produce un error.

TCL_INPUTBLOCKED

Devuelve 1 si el canal channel está en modo no bloqueante y no hay datos disponibles para leer, y 0 en caso contrario.

TCL_INPUTBUFFERED

Devuelve el número de bytes de entrada que están actualmente en el búfer del canal channel y que aún no han sido leídos por la aplicación.

TCL_OUTPUTBUFFERED

Devuelve el número de bytes de salida que están actualmente en el búfer del canal channel y que aún no han sido escritos en el dispositivo subyacente.

TCL_SEEK

Cambia la posición actual de lectura/escritura en el canal channel. El nuevo desplazamiento se calcula sumando offset a la posición dada por seekMode (que puede ser SEEK_SET para el principio del archivo, SEEK_CUR para la posición actual, o SEEK_END para el final del archivo). La función devuelve la nueva posición en bytes o un valor de error Tcl.

TCL_TELL

Devuelve la posición actual de lectura/escritura en bytes en el canal channel, o un valor de error Tcl si se produce un error.

TCL_TRUNCATECHANNEL

Trunca el canal channel a la longitud dada por length. Esto es útil para archivos regulares. Devuelve 0 si tiene éxito, o -1 si se produce un error.

TCL_GETCHANNELOPTION

Obtiene el valor de la opción optionName para el canal channel y lo almacena en el búfer optionValue. Si se pide una opción que no existe, se genera un error. Si optionName es NULL, se devuelven todas las opciones y sus valores.

TCL_SETCHANNELOPTION

Establece el valor de la opción optionName para el canal channel al valor dado por newValue. Devuelve 0 si tiene éxito, o -1 si se produce un error.

TCL_REGISTERCHANNEL

Tcl_RegisterChannel agrega un canal al conjunto de canales accesibles en interp. Después de esta llamada, los programas Tcl que se ejecutan en ese intérprete pueden referirse al canal en operaciones de entrada o salida utilizando el nombre dado en la llamada a Tcl_CreateChannel. TCL_READCHARS, TCL_READOBJA, TCL_READ, AND TCL_READRAW

Tcl_ReadChars lee hasta charsToRead caracteres del canal especificado por channel y los almacena en el Tcl object apuntado por readObjPtr. Si charsToRead es mayor o igual a cero, esta función intentará leer exactamente esa cantidad de caracteres. Si charsToRead es igual a -1, el comando leerá todos los caracteres actualmente disponibles (no bloqueante) o todo hasta EOF (modo bloqueante).

El valor de retorno puede ser menor que el valor a leer, indicando que había menos datos de los solicitados disponibles. Esto se llama una lectura corta. En modo bloqueante, esto solo puede ocurrir en un fin de archivo. En modo no bloqueante, una lectura corta también puede ocurrir si no hay suficiente entrada actualmente disponible: Tcl_ReadChars devuelve un recuento corto en lugar de esperar más datos.

Si el canal está en modo bloqueante, un valor de retorno de cero indica una condición de fin de archivo. Si el canal está en modo no bloqueante, un valor de retorno de cero indica que no hay entrada disponible actualmente o una condición de fin de archivo. Use Tcl_Eof y Tcl_InputBlocked para saber cuál de estas condiciones ocurrió realmente.

Tcl_ReadChars traduce las diversas representaciones de fin de línea a la representación interna canónica de \n de acuerdo con el modo de reconocimiento de fin de línea actual. El reconocimiento de fin de línea y los diversos modos específicos de plataforma se describen en la entrada del manual para el comando Tcl fconfigure.

Como optimización de rendimiento, al leer desde un canal con la codificación binary, los bytes no se convierten a UTF-8 a medida que se leen. En su lugar, se almacenan en la representación interna de readObjPtr como un valor de arreglo de bytes. La representación de cadena de este valor solo se construirá si es necesaria (por ejemplo, debido a una llamada a Tcl_GetStringFromObj). De esta manera, los datos orientados a bytes pueden leerse desde un canal, manipularse llamando a Tcl_GetByteArrayFromObj y funciones relacionadas, y luego escribirse en un canal sin el gasto de convertir de o a UTF-8.

Tcl_Read es similar a Tcl_ReadChars, excepto que no realiza conversiones de codificación, independientemente de la codificación del canal. Está obsoleto y existe para compatibilidad hacia atrás con extensiones Tcl no internacionalizadas. Consume bytes del channel y los almacena en readBuf, realizando traducciones de fin de línea en el camino. El valor de retorno de Tcl_Read es el número de bytes, hasta bytesToRead, escritos en readBuf. El buffer producido por Tcl_Read no termina en nulo. Su contenido es válido desde la posición cero hasta, y excluyendo, la posición indicada por el valor de retorno.

Tcl_ReadRaw es lo mismo que Tcl_Read pero no compensa el apilamiento. Mientras que Tcl_Read (y las otras funciones de la API) siempre obtienen sus datos del canal superior en la pila de la que forma parte el canal proporcionado, Tcl_ReadRaw no. Por lo tanto, esta función solo es utilizable para drivers de canal transformacionales, es decir, drivers utilizados en el medio de una pila de canales, para mover datos del canal inferior hacia la transformación.

TCL_GETSOBJ Y TCL_GETS

Tcl_GetsObj consume bytes del channel, convirtiendo los bytes a UTF-8 basándose en la codificación del canal, hasta que se haya visto una línea completa de entrada. Si la codificación del canal es binary, cada byte leído del canal se trata como un carácter Unicode individual. Todos los caracteres de la línea, excepto los caracteres de fin de línea terminadores, se añaden a la representación de cadena de lineObjPtr. Los caracteres de fin de línea se leen y se descartan.

Si se leyó una línea correctamente, el valor de retorno es mayor o igual a cero e indica el número de bytes almacenados en lineObjPtr. Si ocurre un error, Tcl_GetsObj devuelve -1 y registra un código de error POSIX que puede recuperarse con Tcl_GetErrno. Tcl_GetsObj también devuelve -1 si se llega al fin del archivo; el procedimiento Tcl_Eof puede usarse para distinguir un error de una condición de fin de archivo.

Si el canal está en modo no bloqueante, el valor de retorno también puede ser -1 si no había datos disponibles o los datos disponibles no contenían un carácter de fin de línea. Cuando se devuelve -1, el procedimiento Tcl_InputBlocked puede invocarse para determinar si el canal está bloqueado debido a la indisponibilidad de entrada.

Tcl_Gets es lo mismo que Tcl_GetsObj excepto que los caracteres resultantes se añaden a la cadena dinámica dada por lineRead en lugar de un valor Tcl.

TCL_UNGETS

Tcl_Ungets se utiliza para agregar datos a la cola de entrada de un canal, ya sea en la cabeza o en la cola de la cola. El puntero input apunta a los datos que se van a agregar. La longitud de la entrada a agregar se da por inputLen. Un valor distinto de cero de addAtEnd indica que los datos se agregarán al final de la cola; de lo contrario, se agregarán al principio de la cola. Si channel tiene un EOF "pegajoso" establecido, no se agregarán datos a la cola de entrada. Tcl_Ungets devuelve inputLen o -1 si ocurre un error.

TCL_WRITECHARS, TCL_WRITEOBJ, Y TCL_WRITE

Tcl_WriteChars acepta bytesToWrite bytes de datos de carácter en charBuf. Los caracteres UTF-8 en el buffer se convierten a la codificación del canal y se ponen en cola para su salida al channel. Si bytesToWrite es negativo, Tcl_WriteChars espera que charBuf termine en nulo y saca todo hasta el nulo.

Los datos puestos en cola para salida pueden no aparecer en el dispositivo de salida inmediatamente, debido al almacenamiento en búfer interno. Si los datos deben aparecer inmediatamente, llame a Tcl_Flush después de la llamada a Tcl_WriteChars, o establezca la opción -buffering en el canal a none. Si desea que los datos aparezcan tan pronto como se acepte una línea completa para la salida, establezca la opción -buffering en el canal al modo line.

El valor de retorno de Tcl_WriteChars es un recuento de cuántos bytes fueron aceptados para la salida al canal. Es mayor que cero para indicar éxito o -1 para indicar que ocurrió un error. Si ocurre un error, Tcl_WriteChars registra un código de error POSIX que puede recuperarse con Tcl_GetErrno.

Los caracteres de nueva línea en los datos de salida se traducen a secuencias de fin de línea específicas de la plataforma según la opción -translation para el canal. Esto se hace incluso si el canal no tiene codificación.

Tcl_WriteObj es similar a Tcl_WriteChars excepto que acepta un valor Tcl cuyo contenido se sacará al canal. Los caracteres UTF-8 en la representación de cadena de writeObjPtr se convierten a la codificación del canal y se ponen en cola para su salida al channel. Como optimización de rendimiento, al escribir en un canal con la codificación binary, los caracteres UTF-8 no se convierten a medida que se escriben. En su lugar, los bytes en la representación interna de writeObjPtr como un valor de arreglo de bytes se escriben en el canal. La representación de arreglo de bytes del valor se construirá si es necesaria. De esta manera, los datos orientados a bytes pueden leerse desde un canal, manipularse llamando a Tcl_GetByteArrayFromObj y funciones relacionadas, y luego escribirse en un canal sin el gasto de convertir de o a UTF-8.

Tcl_Write es similar a Tcl_WriteChars excepto que no realiza conversiones de codificación, independientemente de la codificación del canal. Está obsoleto y existe para compatibilidad hacia atrás con extensiones Tcl no internacionalizadas. Acepta bytesToWrite bytes de datos en byteBuf y los pone en cola para su salida al channel. Si bytesToWrite es negativo, Tcl_Write espera que byteBuf termine en nulo y saca todo hasta el nulo.

Tcl_WriteRaw es lo mismo que Tcl_Write pero no compensa el apilamiento. Mientras que Tcl_Write (y las otras funciones de la API) siempre alimentan su entrada al canal superior en la pila de la que forma parte el canal proporcionado, Tcl_WriteRaw no. Por lo tanto, esta función solo es utilizable para drivers de canal transformacionales, es decir, drivers utilizados en el medio de una pila de canales, para mover datos de la transformación al canal inferior.

TCL_FLUSH

Tcl_Flush provoca que todos los datos de salida en búfer del channel se escriban en su archivo o dispositivo subyacente tan pronto como sea posible. Si el canal está en modo bloqueante, la llamada no regresa hasta que todos los datos en búfer se hayan enviado al canal o haya ocurrido algún error. La llamada regresa inmediatamente si el canal no está bloqueante; inicia un vaciado en segundo plano que escribirá los datos en búfer al canal eventualmente, tan rápido como el canal pueda absorberlos.

El valor de retorno es normalmente TCL_OK. Si ocurre un error, Tcl_Flush devuelve TCL_ERROR y registra un código de error POSIX que puede recuperarse con Tcl_GetErrno.

TCL_SEEK

Tcl_Seek mueve el punto de acceso en el channel donde se leerán o escribirán datos posteriores. La salida en búfer se vacía al canal y la entrada en búfer se descarta, antes de la operación de búsqueda.

Tcl_Seek normalmente devuelve el nuevo punto de acceso. Si ocurre un error, Tcl_Seek devuelve -1 y registra un código de error POSIX que puede recuperarse con Tcl_GetErrno. Después de un error, el punto de acceso puede haberse movido o no.

TCL_TELL

Tcl_Tell devuelve el punto de acceso actual para un canal. El valor devuelto es -1 si el canal no admite la búsqueda.

TCL_TRUNCATECHANNEL

Tcl_TruncateChannel trunca el archivo subyacente del channel a una longitud dada de length bytes. Devuelve TCL_OK si la operación tuvo éxito, y TCL_ERROR en caso contrario.

TCL_GETCHANNELOPTION

Tcl_GetChannelOption recupera, en optionValue, el valor de una de las opciones actualmente en vigor para un canal, o una lista de todas las opciones y sus valores. El argumento channel identifica el canal para el que se consulta una opción o se recuperan todas las opciones y sus valores. Si optionName no es NULL, es el nombre de la opción a consultar; el valor de la opción se copia a la cadena dinámica Tcl denotada por optionValue. Si optionName es NULL, la función almacena una lista alternada de nombres de opciones y sus valores en optionValue.

usa una serie de llamadas a Tcl_DStringAppendElement. Las diversas opciones preexistentes y sus posibles valores se describen en la entrada del manual del comando fconfigure de Tcl. Se pueden añadir otras opciones por cada tipo de canal. Estas opciones específicas del tipo de canal se describen en la entrada del manual del comando Tcl que crea un canal de ese tipo; por ejemplo, las opciones adicionales para canales basados en TCP se describen en la entrada del manual del comando socket de Tcl. El procedimiento normalmente devuelve TCL_OK. Si ocurre un error, devuelve TCL_ERROR y llama a Tcl_SetErrno para almacenar un código de error POSIX apropiado.

TCL_SETCHANNELOPTION

Tcl_SetChannelOption establece un nuevo valor *newValue* para una opción *optionName* en el *channel*. El procedimiento normalmente devuelve TCL_OK. Si ocurre un error, devuelve TCL_ERROR; además, si *interp* no es NULL, Tcl_SetChannelOption deja un mensaje de error en el resultado del intérprete.

TCL_EOF

Tcl_Eof devuelve un valor distinto de cero si el *channel* encontró un fin de archivo durante la última operación de entrada.

TCL_INPUTBLOCKED

Tcl_InputBlocked devuelve un valor distinto de cero si el *channel* está en modo no bloqueante y la última operación de entrada devolvió menos datos de los solicitados porque había datos insuficientes disponibles. La llamada siempre devuelve cero si el canal está en modo bloqueante.

TCL_INPUTBUFFERED

Tcl_InputBuffered devuelve el número de bytes de entrada actualmente en el búfer en los búferes internos de un canal. Si el canal no está abierto para lectura, esta función siempre devuelve cero.

TCL_OUTPUTBUFFERED

Tcl_OutputBuffered devuelve el número de bytes de salida actualmente en el búfer en los búferes internos de un canal. Si el canal no está abierto para escritura, esta función siempre devuelve cero.

PLATFORM ISSUES

Los identificadores devueltos por Tcl_GetChannelHandle dependen de la plataforma y del tipo de canal. En plataformas Unix, el identificador es siempre un descriptor de archivo Unix como el devuelto por la llamada al sistema open. En plataformas Windows, el identificador es un HANDLE del archivo cuando el canal se creó con Tcl_OpenFileChannel, Tcl_OpenCommandChannel o Tcl_MakeFileChannel. Otros tipos de canal pueden devolver un tipo diferente de identificador en plataformas Windows.
