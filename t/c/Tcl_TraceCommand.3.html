Tcl_TraceCommand(3)

Paquete: tcl

Licencias: TCL

Tcl_TraceCommand(3) Procedimientos de la biblioteca Tcl Tcl_TraceCommand(3)

NOMBRE

Tcl_CommandTraceInfo, Tcl_TraceCommand, Tcl_UntraceCommand - supervisar renombramientos y eliminaciones de un comando

SINOPSIS

#include <tcl.h>

ClientData
Tcl_CommandTraceInfo(interp, cmdName, flags, proc, prevClientData)

int
Tcl_TraceCommand(interp, cmdName, flags, proc, clientData)

void
Tcl_UntraceCommand(interp, cmdName, flags, proc, clientData)

ARGUMENTOS

Tcl_Interp *interp (entrada)
Intérprete que contiene el comando.
const char *cmdName (entrada)
Nombre del comando.
int flags (entrada)
Combinación OR de los valores TCL_TRACE_RENAME y TCL_TRACE_DELETE.
Tcl_CommandTraceProc *proc (entrada)
Procedimiento a llamar cuando se realizan operaciones especificadas en cmdName.
ClientData clientData (entrada)
Argumento arbitrario para pasar a proc.
ClientData prevClientData (entrada)
Si no es NULL, proporciona el último valor devuelto por Tcl_CommandTraceInfo, por lo que esta llamada devolverá información sobre el siguiente rastreo. Si es NULL, esta llamada devolverá información sobre el primer rastreo.

DESCRIPCIÓN

Tcl_TraceCommand permite a un procedimiento C monitorizar las operaciones realizadas en un comando Tcl, de modo que el procedimiento C se invoque cada vez que el comando se renombra o se elimina. Si el rastreo se crea con éxito, Tcl_TraceCommand devuelve TCL_OK. Si se produce un error (por ejemplo, cmdName especifica un comando inexistente), se devuelve TCL_ERROR y se deja un mensaje de error en el resultado del intérprete.

El argumento flags de Tcl_TraceCommand indica cuándo se debe invocar el procedimiento de rastreo. Consiste en una combinación OR de cualquiera de los siguientes valores:

TCL_TRACE_RENAME
Invocar proc cada vez que se renombra el comando.
TCL_TRACE_DELETE
Invocar proc cuando se elimina el comando.

Cada vez que ocurre una de las operaciones especificadas en el comando, se invocará proc. Debe tener argumentos y un resultado que coincidan con el tipo Tcl_CommandTraceProc:

typedef void Tcl_CommandTraceProc(
        ClientData clientData,
        Tcl_Interp *interp,
        const char *oldName,
        const char *newName,
        int flags);

Los parámetros clientData e interp tendrán los mismos valores que los pasados a Tcl_TraceCommand cuando se creó el rastreo. ClientData generalmente apunta a una estructura de datos específica de la aplicación que describe qué hacer cuando se invoca proc. OldName proporciona el nombre del comando que se está renombrando, y newName proporciona el nombre al que se está renombrando el comando (o NULL cuando el comando se está eliminando). Flags es una combinación OR de bits que proporciona potencialmente varias piezas de información. Se establecerá uno de los bits TCL_TRACE_RENAME y TCL_TRACE_DELETE en flags para indicar qué operación se está realizando en el comando. Se establecerá el bit TCL_TRACE_DESTROYED en flags si el rastreo está a punto de ser destruido; esta información puede ser útil para proc para que pueda limpiar sus propias estructuras de datos internas (ver la sección TCL_TRACE_DESTROYED a continuación para más detalles). Dado que la eliminación de comandos puede ocurrir como parte de la eliminación del intérprete que los contiene, proc debe tener cuidado al verificar qué se puede llamar en el valor de interp pasado. La rutina Tcl_InterpDeleted es una herramienta importante para esto. Cuando Tcl_InterpDeleted devuelve 1, proc no podrá invocar ningún script en interp. La función de proc en esa circunstancia se limita a la limpieza de sus propias estructuras de datos.

Tcl_UntraceCommand se puede utilizar para eliminar un rastreo. Si el comando especificado por interp, cmdName y flags tiene un rastreo establecido con flags, proc y clientData, entonces se elimina el rastreo correspondiente. Si no existe tal rastreo, la llamada a Tcl_UntraceCommand no tiene efecto. Los mismos bits son válidos para flags que para las llamadas a Tcl_TraceCommand.

Tcl_CommandTraceInfo se puede utilizar para recuperar información sobre los rastreos establecidos en un comando dado. El valor de retorno de Tcl_CommandTraceInfo es el clientData asociado con un rastreo particular. El rastreo debe estar en el comando especificado por los argumentos interp, cmdName y flags (tenga en cuenta que actualmente los flags se ignoran; flags debe establecerse en 0 para compatibilidad futura) y su procedimiento de rastreo debe ser el mismo que el argumento proc. Si el argumento prevClientData es NULL, el valor de retorno corresponde al primer rastreo coincidente (creado más recientemente), o NULL si no hay rastreos coincidentes. Si el argumento prevClientData no es NULL, entonces debe ser el valor de retorno de una llamada anterior a Tcl_CommandTraceInfo. En este caso, el nuevo valor de retorno corresponderá al siguiente rastreo coincidente después de aquel cuyo clientData coincide con prevClientData, o NULL si ningún rastreo coincide con prevClientData o si no hay más rastreos coincidentes después de él. Este mecanismo hace posible recorrer todos los rastreos de un comando dado que tienen el mismo proc.

LLAMANDO COMANDOS DURANTE RASTREOS

Durante los rastreos de renombramiento, el comando que se renombra es visible con ambos nombres simultáneamente, y el comando todavía existe durante los rastreos de eliminación, a menos que se esté eliminando el intérprete que lo contiene. Sin embargo, no hay un mecanismo para señalar que ocurrió un error en un procedimiento de rastreo, por lo que se debe tener gran cuidado para que los errores no se pierdan silenciosamente.

MULTIPLES RASTREOS

Es posible que existan varios rastreos en el mismo comando. Cuando esto sucede, todos los procedimientos de rastreo se invocarán en cada acceso, en orden desde el más recientemente creado hasta el menos recientemente creado. Los intentos de eliminar el comando durante un rastreo de eliminación fallarán silenciosamente, ya que el comando ya está programado para su eliminación. Si el comando que se renombra es renombrado por uno de sus rastreos de renombramiento, ese renombramiento tiene prioridad sobre el que activó el rastreo y la colección de rastreos no se volverá a ejecutar; si varios rastreos renombra el comando, el último renombramiento tiene prioridad.

BANDERA TCL_TRACE_DESTROYED

En una devolución de llamada de eliminación a proc, el bit TCL_TRACE_DESTROYED se establece en flags.

PALABRAS CLAVE

clientData, rastreo, comando
