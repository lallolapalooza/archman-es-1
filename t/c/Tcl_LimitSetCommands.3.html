ARGUMENTOS

Tcl_Interp *interp (in)
Intérprete al que se aplican o que tendrá sus límites comprobados.
int type (in)
El tipo de límite al que se refiere la operación. Debe ser TCL_LIMIT_COMMANDS o TCL_LIMIT_TIME.
int commandLimit (in)
El número máximo de comandos (tal como se informa con info cmdcount) que pueden ejecutarse en el intérprete.
Tcl_Time *timeLimitPtr (in/out)
Un puntero a una estructura que recibirá el nuevo límite de tiempo (de Tcl_LimitSetTime) o escribirá el tiempo actual (de Tcl_LimitGetTime).
int granularity (in)
El divisor que indica con qué frecuencia se debe realizar realmente una comprobación de límite. Debe ser al menos 1.
Tcl_LimitHandlerProc *handlerProc (in)
La función a llamar cuando se excede un límite. Si el handlerProc elimina o aumenta el límite durante su ejecución, el intérprete limitado permitirá continuar procesando después de que el manejador regrese. Muchos manejadores pueden estar asociados a un mismo intérprete; su orden de ejecución no está definido y deben identificarse por handlerProc y clientData cuando se eliminen.
ClientData clientData (in)
Un puntero de tamaño arbitrario que se usa para pasar contexto a la función handlerProc.
Tcl_LimitHandlerDeleteProc *deleteProc (in)
La función a llamar cuando se elimina un manejador. Puede ser NULL si el clientData no requiere eliminación.

DESCRIPCIÓN

El subsistema de límites de tiempo de Tcl permite tener un control cercano sobre cuánto tiempo puede ser utilizado por un script y es útil para casos donde un programa está dividido en múltiples piezas donde algunas son más confiables que otras (por ejemplo, servidores de aplicaciones web).

Cada intérprete puede tener un límite en el tiempo de ejecución y un límite en el número de comandos que puede ejecutar. Dado que la comprobación de estos límites puede ser costosa (en especial el límite de tiempo), cada límite también tiene una política de granularidad, que es un divisor para un conteo interno de puntos donde se puede realizar una comprobación (que es inmediatamente antes de ejecutar un comando y en una frecuencia no especificada entre la ejecución de comandos, lo que puede ocurrir en bucles vacíos while).

El componente final del motor de límites es un esquema de notificación que permite notificar cuando se ha excedido un límite. Estas notificaciones pueden solo proporcionar logging, o pueden asignar más recursos al intérprete para que pueda continuar procesando más tiempo.

Cuando se excede un límite (y los callbacks se han ejecutado; el orden de ejecución de los callbacks no está definido), la ejecución en el intérprete limitado se detiene lanzando un error y estableciendo un flag que previene que el comando catch en ese intérprete pueda capturar ese error. Es el contexto que inició la ejecución en ese intérprete (generalmente el intérprete principal) quien debe manejar el error.

API DE COMPROBACIÓN DE LÍMITES

Para comprobar los límites de un intérprete, llama a Tcl_LimitCheck, que devuelve TCL_OK si el límite no fue excedido (después de procesar los callbacks) y TCL_ERROR si el límite fue excedido (en el que se coloca también un mensaje de error en el resultado del intérprete). Esta función debe llamarse solo cuando Tcl_LimitReady devuelva un valor distinto de cero, para que se ejecute la política de granularidad. Esta API está diseñada para ser usada de manera similar a Tcl_AsyncReady y Tcl_AsyncInvoke).

Cuando escribas código que pueda comportarse como catch en cuanto a errores, deberás capturar solo un error si Tcl_LimitExceeded devuelve cero. Si devuelve distinto de cero, el intérprete está en un estado de límite excedido y los errores deben propagarse al contexto de llamada. También puedes verificar si un tipo específico de límite ha sido excedido usando Tcl_LimitTypeExceeded.

CONFIGURACIÓN DE LÍMITES

Para verificar si un límite ha sido establecido (pero no si ha sido excedido) en un intérprete, llama a Tcl_LimitTypeEnabled con el tipo de límite que deseas verificar. Para habilitar un límite, llama a Tcl_LimitTypeSet, y para deshabilitar un límite, llama a Tcl_LimitTypeReset.

El nivel de un límite de comandos puede establecerse usando Tcl_LimitSetCommands, y se puede recuperar con Tcl_LimitGetCommands. De manera similar, el límite de tiempo puede establecerse con Tcl_LimitSetTime y recuperarse con Tcl_LimitGetTime, pero con esa API el límite de tiempo se copia de la estructura Tcl_Time en la que apunta el argumento timeLimitPtr.

La granularidad del límite puede establecerse con Tcl_LimitSetGranularity y recuperarse con Tcl_LimitGetGranularity. Debes notar que las granularidades deben ser positivas.

CALLBACKS DE LÍMITES

Para agregar un callback de manejador a ser invocado cuando se exceda un límite, llama a Tcl_LimitAddHandler. El argumento handlerProc describe la función que se llamará realmente; debe tener el siguiente prototipo:

typedef void Tcl_LimitHandlerProc(
        ClientData clientData,
        Tcl_Interp *interp);

El argumento clientData de la función de manejador será el que se pasó al argumento clientData de Tcl_LimitAddHandler, y interp es el intérprete que tuvo su límite excedido.

El argumento deleteProc de Tcl_LimitAddHandler es una función a llamar para eliminar el valor de clientData. Puede ser TCL_STATIC o NULL si no se necesita ninguna acción de eliminación, o TCL_DYNAMIC si solo se necesita liberar la estructura con Tcl_Free. De lo contrario, debe referirse a una función con el siguiente prototipo:

typedef void Tcl_LimitHandlerDeleteProc(
        ClientData clientData);

Un manejador de límite puede ser eliminado usando Tcl_LimitRemoveHandler; el manejador eliminado será el primero encontrado (de los manejadores añadidos con Tcl_LimitAddHandler) con exactamente los mismos argumentos type, handlerProc y clientData. Esta función siempre invoca el deleteProc en el clientData (a menos que el deleteProc sea NULL o TCL_STATIC).
