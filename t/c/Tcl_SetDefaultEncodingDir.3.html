ARGUMENTOS

Tcl_Interp *interp (entrada)
Intérprete a utilizar para la notificación de errores, o NULL si no se desea notificación de errores.
const char *name (entrada)
Nombre de la codificación a cargar.
Tcl_Encoding encoding (entrada)
La codificación a consultar, liberar o usar para convertir texto. Si encoding es NULL, se utiliza la codificación del sistema actual.
Tcl_Obj *objPtr (entrada)
Nombre de la codificación para obtener el token.
Tcl_Encoding *encodingPtr (salida)
Puntero al almacenamiento donde se escribirá el token de codificación.
const char *src (entrada)
Para las funciones Tcl_ExternalToUtf, una matriz de bytes en la codificación especificada que se convertirá a UTF-8. Para las funciones Tcl_UtfToExternal y Tcl_WinUtfToTChar, una matriz de caracteres UTF-8 a convertir a la codificación especificada.
const TCHAR *tsrc (entrada)
Una matriz de caracteres TCHAR de Windows para convertir a UTF-8.
int srcLen (entrada)
Longitud de src o tsrc en bytes. Si la longitud es negativa, se utiliza la longitud específica de la codificación de la cadena.
Tcl_DString *dstPtr (salida)
Puntero a un Tcl_DString no inicializado o liberado en el que se almacenará el resultado convertido.
int flags (entrada)
Varios bits de bandera OR-ados juntos. TCL_ENCODING_START indica que el búfer de origen es el primer bloque en un flujo de entrada (potencialmente de múltiples bloques), diciendo a la rutina de conversión que restablezca un estado inicial y realice cualquier inicialización que deba ocurrir antes de que se convierta el primer byte. TCL_ENCODING_END indica que el búfer de origen es el último bloque en un flujo de entrada (potencialmente de múltiples bloques), diciendo a la rutina de conversión que realice cualquier finalización que deba ocurrir después de que se convierta el último byte y luego restablezca un estado inicial. TCL_ENCODING_STOPONERROR indica que la rutina de conversión debe regresar inmediatamente al leer un carácter de origen que no existe en la codificación de destino; de lo contrario, se sustituirá automáticamente un carácter de relleno predeterminado.
Tcl_EncodingState *statePtr (entrada/salida)
Se utiliza al convertir un flujo de bytes (generalmente largo o de longitud indefinida) pieza por pieza. La rutina de conversión almacena su estado actual en *statePtr después de que src (el búfer que contiene la pieza actual) haya sido convertido; esa información de estado debe pasarse nuevamente al convertir la siguiente pieza del flujo para que la rutina de conversión sepa en qué estado estaba cuando terminó al final de la última pieza. Puede ser NULL, en cuyo caso el valor especificado para flags se ignora y se asume que el búfer de origen contiene la cadena completa a convertir.
char *dst (salida)
Búfer en el que se almacenará el resultado convertido. No se almacenarán más de dstLen bytes en dst.
int dstLen (entrada)
La longitud máxima del búfer de salida dst en bytes.
int *srcReadPtr (salida)
Se rellena con el número de bytes de src que se convirtieron realmente. Esto puede ser menor que la longitud de origen original si hubo un problema al convertir algunos caracteres de origen. Puede ser NULL.
int *dstWrotePtr (salida)
Se rellena con el número de bytes que se almacenaron realmente en el búfer de salida como resultado de la conversión. Puede ser NULL.
int *dstCharsPtr (salida)
Se rellena con el número de caracteres que corresponden al número de bytes almacenados en el búfer de salida. Puede ser NULL.
Tcl_DString *bufPtr (salida)
Almacenamiento para el nombre de codificación del sistema prescrito.
const Tcl_EncodingType *typePtr (entrada)
Estructura que define un nuevo tipo de codificación.
Tcl_Obj *searchPath (entrada)
Lista de directorios del sistema de archivos en los que buscar archivos de datos de codificación.
const char *path (entrada)
Una ruta a la ubicación del archivo de codificación.

INTRODUCCIÓN

Estas rutinas convierten entre la representación interna de caracteres de Tcl, UTF-8, y las representaciones de caracteres utilizadas por varios sistemas operativos o sistemas de archivos, como Unicode, ASCII o Shift-JIS. Al operar sobre cadenas, como al obtener nombres de archivos o mostrar caracteres utilizando fuentes internacionales, las cadenas deben traducirse a uno o posiblemente a múltiples formatos que las diversas llamadas del sistema puedan usar. Por ejemplo, en una estación de trabajo Unix japonesa, un usuario podría obtener un nombre de archivo representado en la codificación de archivo EUC-JP y luego traducir los caracteres a la codificación de fuente jisx0208 para mostrar el nombre de archivo en un widget Tk. El propósito del paquete de codificación es ayudar a tender el puente entre las brechas de traducción. UTF-8 proporciona un punto de transferencia intermedio para todas las diversas codificaciones. En el ejemplo anterior, el texto se traduciría a UTF-8 desde la codificación de archivo que esté utilizando el sistema operativo. Luego, se traduciría de UTF-8 a la codificación de fuente que requieran las rutinas de visualización.

Algunas codificaciones básicas están compiladas en Tcl. Otras pueden ser definidas por el usuario o cargadas dinámicamente desde archivos de codificación de manera independiente de la plataforma.

DESCRIPCIÓN

Tcl_GetEncoding busca una codificación dado su nombre. El nombre puede referirse a una codificación incorporada de Tcl, una codificación definida por el usuario registrada llamando a Tcl_CreateEncoding, o un archivo de codificación cargable dinámicamente. El valor de retorno es un token que representa la codificación y puede usarse en llamadas posteriores a procedimientos como Tcl_GetEncodingName, Tcl_FreeEncoding y Tcl_UtfToExternal. Si el nombre no se refiere a ninguna codificación conocida o cargable, se devuelve NULL y se devuelve un mensaje de error en interp.

El paquete de codificación mantiene una base de datos de todas las codificaciones actualmente en uso. La primera vez que se ve name, Tcl_GetEncoding devuelve una codificación con un contador de referencias de 1. Si se solicita el mismo name varias veces más, el contador de referencias para esa codificación se incrementa sin la sobrecarga de asignar una nueva codificación y todas sus estructuras de datos asociadas.

Cuando una encoding ya no es necesaria, se debe llamar a Tcl_FreeEncoding para liberarla. Cuando una encoding ya no está en uso en ningún lugar (es decir, se ha liberado tantas veces como se ha obtenido) Tcl_FreeEncoding liberará todo el almacenamiento que la codificación estaba utilizando y la eliminará de la base de datos.

Tcl_GetEncodingFromObj trata la representación de cadena de objPtr como un nombre de codificación, y busca una codificación con ese nombre, al igual que lo hace Tcl_GetEncoding. Cuando se encuentra una codificación, se almacena en caché dentro del valor objPtr para referencia futura, el token Tcl_Encoding se escribe en el almacenamiento

Tcl_ExternalToUtfDString convierte un búfer de origen src de la codificación especificada encoding a UTF-8. Los bytes convertidos se almacenan en dstPtr, que luego se termina con nulo. El llamador eventualmente debe llamar a Tcl_DStringFree para liberar cualquier información almacenada en dstPtr. Al convertir, si alguno de los caracteres del búfer de origen no se puede representar en la codificación de destino, se utilizará un carácter de sustitución por defecto. El valor de retorno es un puntero al valor almacenado en el DString.

Tcl_ExternalToUtf convierte un búfer de origen src de la codificación especificada encoding a UTF-8. Se convierten hasta srcLen bytes del búfer de origen y se almacenan hasta dstLen bytes convertidos en dst. En todos los casos, *srcReadPtr se rellena con el número de bytes que se convirtieron correctamente de src y *dstWrotePtr se rellena con el número correspondiente de bytes que se almacenaron en dst. El valor de retorno es uno de los siguientes:

TCL_OK
Se convirtieron todos los bytes de src.
TCL_CONVERT_NOSPACE
El búfer de destino no era lo suficientemente grande para todos los datos convertidos; sin embargo, se convirtieron tantos caracteres como cupieron.
TCL_CONVERT_MULTIBYTE
Los últimos bytes del búfer de origen eran el comienzo de una secuencia multibyte, pero se necesitaban más bytes para completar esta secuencia. Una llamada posterior a la rutina de conversión debería pasar un búfer que contenga los bytes no convertidos que quedaron en src más algunos bytes adicionales del flujo de origen para convertir correctamente la secuencia multibyte previamente dividida.
TCL_CONVERT_SYNTAX
El búfer de origen contenía una secuencia de caracteres inválida. Esto puede ocurrir si el flujo de entrada se ha dañado o si se identificó incorrectamente el método de codificación de entrada.
TCL_CONVERT_UNKNOWN
El búfer de origen contenía un carácter que no se podía representar en la codificación de destino y se especificó TCL_ENCODING_STOPONERROR.

Tcl_UtfToExternalDString convierte un búfer de origen src de UTF-8 a la codificación especificada encoding. Los bytes convertidos se almacenan en dstPtr, que luego se termina con el nulo específico de la codificación apropiado. El llamador eventualmente debe llamar a Tcl_DStringFree para liberar cualquier información almacenada en dstPtr. Al convertir, si alguno de los caracteres del búfer de origen no se puede representar en la codificación de destino, se utilizará un carácter de sustitución por defecto. El valor de retorno es un puntero al valor almacenado en el DString.

Tcl_UtfToExternal convierte un búfer de origen src de UTF-8 a la codificación especificada encoding. Se convierten hasta srcLen bytes del búfer de origen y se almacenan hasta dstLen bytes convertidos en dst. En todos los casos, *srcReadPtr se rellena con el número de bytes que se convirtieron correctamente de src y *dstWrotePtr se rellena con el número correspondiente de bytes que se almacenaron en dst. Los valores de retorno son los mismos que los valores de retorno para Tcl_ExternalToUtf.

Tcl_WinUtfToTChar y Tcl_WinTCharToUtf son funciones de conveniencia exclusivas de Windows para convertir entre UTF-8 y cadenas de Windows basadas en el tipo TCHAR, que por convención es un carácter Unicode en Windows NT.

Tcl_GetEncodingName es aproximadamente la inversa de Tcl_GetEncoding. Dado una encoding, el valor de retorno es el argumento name que se utilizó para crear la codificación. La cadena devuelta por Tcl_GetEncodingName solo se garantiza que persistirá hasta que la encoding sea eliminada. El llamador no debe modificar esta cadena.

Tcl_SetSystemEncoding establece la codificación por defecto que se debe utilizar siempre que el usuario pase un valor NULL para el argumento encoding a cualquiera de las otras funciones de codificación. Si name es NULL, la codificación del sistema se restablece a la codificación del sistema por defecto, binary. Si el nombre no se refiere a ninguna codificación conocida o cargable, se devuelve TCL_ERROR y se deja un mensaje de error en interp. De lo contrario, este procedimiento incrementa el recuento de referencias de la nueva codificación del sistema, decrementa el recuento de referencias de la vieja codificación del sistema y devuelve TCL_OK.

Tcl_GetEncodingNameFromEnvironment proporciona un medio para que la biblioteca Tcl informe el nombre de la codificación que considera correcto usar como codificación del sistema, basándose en llamadas al sistema y el examen del entorno adecuado para la plataforma. Acepta bufPtr, un puntero a un Tcl_DString no inicializado o liberado, y escribe el nombre de la codificación en él. Se devuelve Tcl_DStringValue.

Tcl_GetEncodingNames establece el resultado del interp a una lista que consta de los nombres de todas las codificaciones que están actualmente definidas o que se pueden cargar dinámicamente, buscando en la ruta de codificación especificada por Tcl_SetDefaultEncodingDir. Este procedimiento no garantiza que los archivos de codificación cargables dinámicamente contengan datos válidos, sino meramente que existen.

Tcl_CreateEncoding define una nueva codificación y registra los procedimientos C que se llaman para convertir entre la codificación y UTF-8. Las codificaciones creadas por Tcl_CreateEncoding son posteriormente visibles en la base de datos utilizada por Tcl_GetEncoding. Al igual que con el procedimiento Tcl_GetEncoding, el valor de retorno es un token que representa la codificación y puede usarse en llamadas posteriores a otras funciones de codificación. Tcl_CreateEncoding devuelve una codificación con un recuento de referencias de 1. Si ya existe una codificación con el nombre especificado name, su entrada en la base de datos se reemplaza con la nueva codificación; el token para la codificación antigua seguirá siendo válido y continuará comportándose como antes, pero los usuarios del nuevo token ahora llamarán a los nuevos procedimientos de codificación.

El argumento typePtr para Tcl_CreateEncoding contiene información sobre el nombre de la codificación y los procedimientos que se llamarán para convertir entre esta codificación y UTF-8. Se define de la siguiente manera:

typedef struct Tcl_EncodingType {
    const char *encodingName;
    Tcl_EncodingConvertProc *toUtfProc;
    Tcl_EncodingConvertProc *fromUtfProc;
    Tcl_EncodingFreeProc *freeProc;
    ClientData clientData;
    int nullSize;
} Tcl_EncodingType;

encodingName proporciona un nombre de cadena para la codificación, por el cual se puede referir en otros procedimientos como Tcl_GetEncoding. toUtfProc se refiere a un procedimiento de callback para invocar para convertir texto de esta codificación a UTF-8. fromUtfProc se refiere a un procedimiento de callback para invocar para convertir texto de UTF-8 a esta codificación. freeProc se refiere a un procedimiento de callback para invocar cuando esta codificación sea eliminada. El campo freeProc puede ser NULL. clientData contiene un valor arbitrario de una palabra pasado a toUtfProc, fromUtfProc y freeProc siempre que se llamen. Típicamente, este es un puntero a una estructura de datos que contiene información específica de la codificación que pueden utilizar los procedimientos de callback. Por ejemplo, dos codificaciones muy similares como ascii y macRoman pueden usar el mismo procedimiento de callback, pero usar diferentes valores de clientData para controlar su comportamiento. nullSize especifica el número de bytes cero que significan fin de cadena en esta codificación. Debe ser 1 (para codificaciones de un solo byte o multibyte como ASCII o Shift-JIS) o 2 (para codificaciones de dos bytes como Unicode). Las codificaciones de tamaño constante con 3 o más bytes por carácter (como CNS11643) no se aceptan.

Los procedimientos de callback toUtfProc y fromUtfProc deben coincidir con el tipo Tcl_EncodingConvertProc:

typedef int Tcl_EncodingConvertProc(
        ClientData clientData,
        const char *src,
        int srcLen,
        int flags,
        Tcl_EncodingState *statePtr,
        char *dst,
        int dstLen,
        int *srcReadPtr,
        int *dstWrotePtr,
        int *dstCharsPtr);

Los procedimientos toUtfProc y fromUtfProc son llamados por la familia de funciones Tcl_ExternalToUtf o Tcl_UtfToExternal para realizar la conversión real. El parámetro clientData para estos procedimientos es el mismo que el campo clientData especificado a Tcl_CreateEncoding cuando se creó la codificación. Los argumentos restantes a los procedimientos de callback son los mismos que los argumentos, documentados en la parte superior, de Tcl_ExternalToUtf o Tcl_UtfToExternal, con las siguientes excepciones. Si el argumento srcLen a una de esas funciones de alto nivel es negativo, el valor pasado al procedimiento de callback será la longitud de cadena específica de la codificación apropiada de src. Si alguno de los argumentos srcReadPtr, dstWrotePtr o dstCharsPtr a una de las funciones de alto nivel es NULL, el valor correspondiente pasado al procedimiento de callback será una ubicación no NULL.

El procedimiento de callback freeProc, si no es NULL, debe coincidir con el tipo Tcl_EncodingFreeProc:

typedef void Tcl_EncodingFreeProc(
        ClientData clientData);

Esta función freeProc se llama cuando se elimina la codificación. El parámetro clientData es el mismo que el campo clientData especificado a Tcl_CreateEncoding cuando se creó la codificación.

Tcl_GetEncodingSearchPath y Tcl_SetEncodingSearchPath se llaman para acceder y establecer la lista de directorios del sistema de archivos que se buscan para los archivos de datos de codificación.

El valor devuelto por Tcl_GetEncodingSearchPath es el valor almacenado por la última llamada exitosa a Tcl_SetEncodingSearchPath. Si no se ha producido ninguna llamada a Tcl_SetEncodingSearchPath, Tcl calculará un valor inicial basado en el entorno. Existe una ruta de búsqueda de codificación para todo el proceso, compartida por todos los hilos del proceso.

Tcl_SetDefaultEncodingDir y Tcl_GetDefaultEncodingDir son interfaces obsoletas que es mejor reemplazar con llamadas a Tcl_SetEncodingSearchPath y Tcl_GetEncodingSearchPath. Se utilizan para acceder y establecer el primer elemento de la lista searchPath. Dado que Tcl busca en searchPath los archivos de datos de codificación en orden de lista, estas rutinas establecen el directorio "predeterminado" en el que encontrar los archivos de datos de codificación.

El searchPath es una lista de rutas de directorios en las que Tcl buscará archivos de codificación. Cuando se llama a Tcl_GetEncoding para una codificación que no se ha cargado, buscará en los directorios de searchPath en orden de lista. Los directorios que no existan o que no se puedan leer en el searchPath se ignoran silenciosamente.

ARCHIVOS DE CODIFICACIÓN

El espacio prohibiría precompilar en Tcl cada algoritmo de codificación posible, por lo que muchas codificaciones se almacenan en disco como archivos de codificación cargables dinámicamente. Este comportamiento también permite al usuario crear archivos de codificación adicionales que se pueden cargar utilizando el mismo mecanismo. Estos archivos de codificación contienen información sobre las tablas y/o secuencias de escape utilizadas para mapear entre una codificación externa y Unicode. La codificación externa puede consistir en caracteres de un solo byte, multibyte o doble byte.

Cada codificación cargable dinámicamente se representa como un archivo de texto. La línea inicial del archivo, que comienza con un símbolo "#", es un comentario que proporciona una descripción legible por humanos del archivo. La siguiente línea identifica el tipo de archivo de codificación. Puede ser una de las siguientes letras:

[1] S
Una codificación de un solo byte, donde un carácter tiene siempre un byte de longitud en la codificación. Un ejemplo es iso8859-1, utilizada por muchos idiomas europeos.
[2] D
Una codificación de doble byte, donde un carácter tiene siempre dos bytes de longitud en la codificación. Un ejemplo es big5, utilizada para texto chino.
[3] M
Una codificación multibyte, donde un carácter puede tener uno o dos bytes de longitud. Ciertos bytes son bytes de liderazgo, lo que indica que otro byte debe seguir y que juntos los dos bytes representan un carácter. Otros bytes no son bytes de liderazgo y se representan a sí mismos. Un ejemplo es shiftjis, utilizado por muchas computadoras japonesas.
[4] E
Una codificación de secuencia de escape, que especifica que ciertas secuencias de bytes no representan caracteres, sino comandos que describen cómo deben interpretarse los bytes siguientes.

El resto de las líneas del archivo dependen del tipo.

Los casos [1], [2] y [3] se denominan colectivamente archivos de codificación basados en tablas. Las líneas en un archivo de codificación basado en tablas tienen el mismo formato que este ejemplo tomado de la codificación shiftjis (este no es el archivo completo):

La tercera línea del archivo son tres números. El primer número es el carácter de reserva (en base 16) a utilizar al convertir de UTF-8 a esta codificación. El segundo número es un 1 si este archivo representa la codificación de una fuente de símbolos, o 0 en caso contrario. El último número (en base 10) indica cuántas páginas de datos siguen.

Las líneas subsiguientes en el ejemplo anterior son páginas que describen cómo mapear desde la codificación a Unicode de 2 bytes. La primera línea de una página identifica el número de página. Le siguen 256 números de doble byte, organizados como 16 filas de 16 números. Dado un carácter en la codificación, el byte alto de ese carácter se utiliza para seleccionar la página, y el byte bajo de ese carácter se utiliza como índice para seleccionar uno de los números de doble byte en esa página, siendo el valor obtenido el carácter Unicode correspondiente. Por el examen del ejemplo anterior, se puede ver que los caracteres 0x7E y 0x8163 en shiftjis se mapean a 203E y 2026 en Unicode, respectivamente.

Después de la primera página seguirán todas las demás páginas, cada una en el mismo formato que la primera: un número que identifica la página seguido de 256 caracteres Unicode de doble byte. Si un carácter en la codificación se mapea al carácter Unicode 0000, significa que el carácter no existe realmente. Si todos los caracteres de una página se mapearan a 0000, esa página se puede omitir.

El caso [4] es el archivo de codificación de secuencia de escape. Las líneas en un archivo de este tipo tienen el mismo formato que este ejemplo tomado de la codificación iso2022-jp:

# Archivo de codificación: iso2022-jp, impulsado por escape
E
init		{}
final		{}
iso8859-1	\x1b(B
jis0201		\x1b(J
jis0208		\x1b$@
jis0208		\x1b$B
jis0212		\x1b$(D
gb2312		\x1b$A
ksc5601		\x1b$(C

En el archivo, la primera columna representa una opción y la segunda columna es el valor asociado. init es una cadena que se emite o se espera antes de que se convierta el primer carácter, mientras que final es una cadena que se emite o se espera después del último carácter. Todas las demás opciones son nombres de codificaciones basadas en tablas; el valor asociado es la secuencia de escape que marca esa codificación. La sintaxis de Tcl se utiliza para los valores; en el ejemplo anterior, por ejemplo, "{}" representa la cadena vacía y "\x1b" representa el carácter 27.

Cuando Tcl_GetEncoding encuentra un nombre de codificación que no se ha cargado, intenta cargar un archivo de codificación llamado name.enc desde el subdirectorio encoding de cada directorio en el que Tcl busca su biblioteca de scripts. Si el archivo de codificación existe, pero está mal formado, se dejará un mensaje de error en interp.
