Tcl_GetChannelErrorInterp(3)

Paquete: tcl

Licencias: TCL

Tcl_SetChannelError(3) Procedimientos de la biblioteca Tcl Tcl_SetChannelError(3)

NOMBRE

Tcl_SetChannelError, Tcl_SetChannelErrorInterp, Tcl_GetChannelError, Tcl_GetChannelErrorInterp - funciones para crear/interceptar errores de Tcl por controladores de canal.

SINOPSIS

#include <tcl.h>

void
Tcl_SetChannelError(chan, msg)

void
Tcl_SetChannelErrorInterp(interp, msg)

void
Tcl_GetChannelError(chan, msgPtr)

void
Tcl_GetChannelErrorInterp(interp, msgPtr)

ARGUMENTOS

Tcl_Channel chan (entrada)
Se refiere al canal Tcl cuya área de bypass se accede.
Tcl_Interp* interp (entrada)
Se refiere al intérprete Tcl cuya área de bypass se accede.
Tcl_Obj* msg (entrada)
Mensaje de error introducido en un área de bypass. Una lista de opciones y valores de retorno, seguida de un mensaje de cadena. Tanto el mensaje como la información de opción/valor son opcionales.
Tcl_Obj** msgPtr (salida)
Referencia a un lugar donde se puede almacenar el mensaje guardado en el área de bypass accedida.

DESCRIPCIÓN

La definición actual de un controlador de canal Tcl no permite la devolución directa de mensajes de error arbitrarios, excepto para el establecimiento y la recuperación de opciones de canal. Todas las demás funciones están restringidas a códigos de error POSIX.

Las funciones descritas aquí superan esta limitación. Se permite a los controladores de canal utilizar Tcl_SetChannelError y Tcl_SetChannelErrorInterp para colocar mensajes de error arbitrarios en las áreas de bypass definidas para canales e intérpretes. Y la capa genérica de E/S utiliza Tcl_GetChannelError y Tcl_GetChannelErrorInterp para buscar mensajes en las áreas de bypass y organizar su devolución como errores. Los códigos de error POSIX establecidos por un controlador se utilizan ahora si y solo si no hay mensajes presentes.

Tcl_SetChannelError almacena información de error en el área de bypass del canal especificado. El número de referencias al valor msg aumenta en uno. La información previamente almacenada se descartará, liberando la referencia que tiene el canal. La referencia del canal no debe ser NULL.

Tcl_SetChannelErrorInterp almacena información de error en el área de bypass del intérprete especificado. El número de referencias al valor msg aumenta en uno. La información previamente almacenada se descartará, liberando la referencia que tiene el intérprete. La referencia del intérprete no debe ser NULL.

Tcl_GetChannelError coloca el mensaje de error que tiene el área de bypass del canal especificado en msgPtr, o NULL; y reinicia el bypass, es decir, después de una invocación, todas las invocaciones siguientes devolverán NULL, hasta una invocación intermedia de Tcl_SetChannelError con un mensaje no NULL. El msgPtr no debe ser NULL. El recuento de referencias del mensaje no se modifica. La referencia previamente mantenida por el canal ahora es mantenida por el llamador de la función y es su responsabilidad liberar esa referencia cuando haya terminado con el valor.

Tcl_GetChannelErrorInterp coloca el mensaje de error que tiene el área de bypass del intérprete especificado en msgPtr, o NULL; y reinicia el bypass, es decir, después de una invocación, todas las invocaciones siguientes devolverán NULL, hasta una invocación intermedia de Tcl_SetChannelErrorInterp con un mensaje no NULL. El msgPtr no debe ser NULL. El recuento de referencias del mensaje no se modifica. La referencia previamente mantenida por el intérprete ahora es mantenida por el llamador de la función y es su responsabilidad liberar esa referencia cuando haya terminado con el valor.

Qué funciones de un controlador de canal pueden utilizar qué función de bypass se enumera a continuación, al igual que qué funciones de la API pública de canal pueden dejar mensajes en las áreas de bypass.

Tcl_DriverCloseProc
Puede utilizar Tcl_SetChannelErrorInterp, y solo esta función.
Tcl_DriverInputProc
Puede utilizar Tcl_SetChannelError, y solo esta función.
Tcl_DriverOutputProc
Puede utilizar Tcl_SetChannelError, y solo esta función.
Tcl_DriverSeekProc
Puede utilizar Tcl_SetChannelError, y solo esta función.
Tcl_DriverWideSeekProc
Puede utilizar Tcl_SetChannelError, y solo esta función.
Tcl_DriverSetOptionProc
Ya tiene la capacidad de pasar mensajes de error arbitrarios. No debe utilizar ninguna de las nuevas funciones.
Tcl_DriverGetOptionProc
Ya tiene la capacidad de pasar mensajes de error arbitrarios. No debe utilizar ninguna de las nuevas funciones.
Tcl_DriverWatchProc
No debe utilizar ninguna de las nuevas funciones. Se llama internamente y no tiene capacidad para devolver ningún tipo de error.
Tcl_DriverBlockModeProc
Puede utilizar Tcl_SetChannelError, y solo esta función.
Tcl_DriverGetHandleProc
No debe utilizar ninguna de las nuevas funciones. Es solo una función de bajo nivel y no es utilizada por comandos Tcl.
Tcl_DriverHandlerProc
No debe utilizar ninguna de las nuevas funciones. Se llama internamente y no tiene capacidad para devolver ningún tipo de error.

Dada la información anterior, las siguientes funciones públicas de la API C de Tcl se ven afectadas por estos cambios; cuando se llaman estas funciones, el canal ahora puede contener un mensaje de error arbitrario almacenado que requiere procesamiento por parte del llamador.

Tcl_Flush	Tcl_GetsObj	Tcl_Gets
Tcl_ReadChars	Tcl_ReadRaw	Tcl_Read
Tcl_Seek	Tcl_StackChannel	Tcl_Tell
Tcl_WriteChars	Tcl_WriteObj	Tcl_WriteRaw
Tcl_Write

Todas las demás funciones de la API no cambian. En particular, las funciones siguientes dejan toda su información de error en el resultado del intérprete.

Tcl_Close	Tcl_UnstackChannel	Tcl_UnregisterChannel

VER TAMBIÉN

Tcl_Close(3), Tcl_OpenFileChannel(3), Tcl_SetErrno(3)
