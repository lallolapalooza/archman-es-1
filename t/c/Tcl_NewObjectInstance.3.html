ARGUMENTOS

Tcl_Interp *interp (entrada/salida)
Intérprete que proporciona el contexto para buscar o crear un objeto, y en cuyo resultado se escribirán los mensajes de error en caso de fallo.
Tcl_Obj *objPtr (entrada)
El nombre del objeto a buscar.
Tcl_Object object (entrada)
Referencia al objeto sobre el que operar.
Tcl_Class class (entrada)
Referencia a la clase sobre la que operar.
const char *name (entrada)
El nombre del objeto a crear, o NULL si se va a seleccionar automáticamente un nuevo nombre no utilizado.
const char *nsName (entrada)
El nombre del espacio de nombres a crear para uso privado del objeto, o NULL si se va a seleccionar automáticamente un nuevo nombre no utilizado. El espacio de nombres no debe existir previamente.
int objc (entrada)
El número de elementos en la matriz objv.
Tcl_Obj *const *objv (entrada)
Los argumentos del comando para crear la instancia de la clase.
int skip (entrada)
El número de argumentos al principio de la matriz de argumentos, objv, que no son argumentos para ningún constructor. Esto permite la generación de mensajes de error correctos incluso cuando se utilizan patrones de llamada complicados (por ejemplo, a través del comando next).
Tcl_ObjectMetadataType *metaTypePtr (entrada)
El tipo de metadata que se establece con Tcl_ClassSetMetadata o se recupera con Tcl_ClassGetMetadata.
ClientData metadata (entrada)
Un elemento de metadata para adjuntar a la clase, o NULL para eliminar la metadata asociada con un metaTypePtr particular.
Tcl_ObjectMapMethodNameProc methodNameMapper (entrada)
Un puntero a una función que se llamará para ajustar el mapeo de objetos y nombres de métodos a implementaciones, o NULL cuando no se requiere dicho mapeo.

DESCRIPCION

Los objetos son entidades tipadas que tienen un conjunto de operaciones ("métodos") asociadas a ellas. Las clases son objetos que pueden fabricar objetos. Cada clase puede verse como un objeto en sí misma; la vista de objeto se puede recuperar utilizando Tcl_GetClassAsObject, que siempre devuelve el objeto cuando se aplica a una clase no destruida, y un objeto puede verse como una clase con la ayuda de Tcl_GetObjectAsClass (que devuelve la clase o NULL si el objeto no es una clase). Un objeto puede buscarse utilizando la función Tcl_GetObjectFromObj, que devuelve un objeto o NULL (con un mensaje de error en el resultado del intérprete) si el objeto no se encuentra. La forma correcta de buscar una clase por nombre es buscar el objeto con ese nombre y luego usar Tcl_GetObjectAsClass.

Cada objeto tiene su propio comando y espacio de nombres asociados. El comando se puede recuperar utilizando la función Tcl_GetObjectCommand, el nombre del objeto (y, por lo tanto, el nombre del comando) con Tcl_GetObjectName, y el espacio de nombres se puede recuperar utilizando la función Tcl_GetObjectNamespace. Tenga en cuenta que la referencia Tcl_Obj devuelta por Tcl_GetObjectName es una referencia compartida. También puede obtener si el objeto ha sido marcado para eliminación con Tcl_ObjectDeleted (devuelve verdadero si la eliminación del objeto ha comenzado); esto puede ser útil durante el procesamiento de métodos.

Las instancias de clases se crean utilizando Tcl_NewObjectInstance, que crea un objeto de cualquier clase (y que es llamado internamente tanto por los métodos create como new de la clase oo::class). Toma parámetros que opcionalmente dan el nombre del objeto y el espacio de nombres a crear, y que describen los argumentos a pasar al constructor de la clase (si lo hay). El resultado de la función será una referencia al objeto recién creado, o NULL si la creación falló (cuando se dejará un mensaje de error en el resultado del intérprete). Además, los objetos pueden copiarse utilizando Tcl_CopyObjectInstance, que crea una copia de un objeto sin ejecutar ningún constructor.

Tenga en cuenta que la gestión del ciclo de vida de los objetos se maneja internamente dentro de TclOO y no utiliza Tcl_Preserve. No es seguro colocar un manejador Tcl_Object en una estructura C con una vida útil diferente a la del objeto; debe usar el nombre del comando del objeto (recuperado con Tcl_GetObjectName) en su lugar. Es seguro usar un manejador Tcl_Object durante la vida útil de una llamada a un método sobre ese objeto; los manejadores no se invalidan mientras haya una llamada pendiente sobre su objeto (incluso si la única operación garantizada para ser segura en ellos es Tcl_ObjectDeleted; las otras operaciones solo están garantizadas para funcionar en objetos no eliminados).

METADATA DE OBJETOS Y CLASES

Cada objeto y cada clase pueden tener cantidades arbitrarias de metadata adjuntas a ella, a las que el objeto o la clase no les asignan ningún significado más allá de lo descrito en una instancia de estructura Tcl_ObjectMetadataType. La metadata a adjuntar se describe por el tipo de la metadata (dado en el argumento metaTypePtr) y un puntero arbitrario (el argumento metadata) que se dan a Tcl_ObjectSetMetadata y Tcl_ClassSetMetadata, y se puede recuperar una pieza de metadata particular dado su tipo usando Tcl_ObjectGetMetadata y Tcl_ClassGetMetadata. Si el parámetro metadata a Tcl_ObjectSetMetadata o Tcl_ClassSetMetadata es NULL, la metadata se elimina si estaba adjunta, y los resultados de Tcl_ObjectGetMetadata y Tcl_ClassGetMetadata son NULL si el tipo dado de metadata no estaba adjunto. No es un error solicitar o eliminar una pieza de metadata que no estaba adjunta.

ESTRUCTURA TCL_OBJECTMETADATATYPE

Los contenidos de la estructura Tcl_ObjectMetadataType son los siguientes:

typedef const struct {
    int version;
    const char *name;
    Tcl_ObjectMetadataDeleteProc *deleteProc;
    Tcl_CloneProc *cloneProc;
} Tcl_ObjectMetadataType;

El campo version permite la expansión futura de la estructura y siempre debe declararse igual a TCL_OO_METADATA_VERSION_CURRENT. El campo name proporciona un nombre legible por humanos para el tipo y está reservado para depuración.

El campo deleteProc proporciona una función del tipo Tcl_ObjectMetadataDeleteProc que se utiliza para eliminar una pieza de metadata particular y se llama cuando la metadata adjunta se reemplaza o elimina; el campo no debe ser NULL.

El campo cloneProc proporciona una función que se utiliza para copiar una pieza de metadata (utilizada cuando se crea una copia de un objeto usando Tcl_CopyObjectInstance); si es NULL, la metadata se copiará directamente.

FIRMA DE FUNCIÓN TCL_OBJECTMETADATADELETEPROC

Las funciones que coinciden con esta firma se utilizan para eliminar metadata asociada con una clase u objeto.

NAME


Tcl_NewObjectInstance, Tcl_ObjectDeleteProc, Tcl_CloneProc, Tcl_ObjectMapMethodNameProc — object system procedure callbacks






SYNOPSIS


typedef void Tcl_ObjectDeleteProc(
        ClientData metadata);
typedef int Tcl_CloneProc(
        Tcl_Interp *interp,
        ClientData srcMetadata,
        ClientData *dstMetadataPtr);
typedef int Tcl_ObjectMapMethodNameProc(
        Tcl_Interp *interp,
        Tcl_Object object,
        Tcl_Class *startClsPtr,
        Tcl_Obj *methodNameObj);







DESCRIPTION


These are callback procedures used by the TclOO object system. They
    allow object types (classes) to define how instances are created, destroyed,
    copied, and how method lookups are performed.




TCL_OBJECTDELETEPROC FUNCTION SIGNATURE


Functions matching this signature are used to clean up any
    allocated memory or resources associated with an object or class instance
    when it is destroyed. When an object or class is deleted, its associated
    metadata pointer is passed to the registered Tcl_ObjectDeleteProc
    procedure.




typedef void Tcl_ObjectDeleteProc(
        ClientData metadata);




The metadata argument gives the address of the metadata to
    be deleted.






TCL_CLONEPROC FUNCTION SIGNATURE


Functions matching this signature are used to create copies of
    metadata associated with a class or object.




typedef int Tcl_CloneProc(
        Tcl_Interp *interp,
        ClientData srcMetadata,
        ClientData *dstMetadataPtr);




The interp argument gives a place to write an error message
    when the attempt to clone the object is to fail, in which case the clone
    procedure must also return TCL_ERROR; it should return TCL_OK otherwise. The
    srcMetadata argument gives the address of the metadata to be cloned,
    and the cloned metadata should be written into the variable pointed to by
    dstMetadataPtr; a NULL should be written if the metadata is to not be
    cloned but the overall object copy operation is still to succeed.








OBJECT METHOD NAME MAPPING


It is possible to control, on a per-object basis, what methods are
    invoked when a particular method is invoked. Normally this is done by
    looking up the method name in the object and then in the class hierarchy,
    but fine control of exactly what the value used to perform the look up is
    afforded through the ability to set a method name mapper callback via
    Tcl_ObjectSetMethodNameMapper (and its introspection counterpart,
    Tcl_ObjectGetMethodNameMapper, which returns the current mapper). The
    current mapper (if any) is invoked immediately before looking up what chain
    of method implementations is to be used.




TCL_OBJECTMAPMETHODNAMEPROC FUNCTION SIGNATURE


The Tcl_ObjectMapMethodNameProc callback is defined as
    follows:




typedef int Tcl_ObjectMapMethodNameProc(
        Tcl_Interp *interp,
        Tcl_Object object,
        Tcl_Class *startClsPtr,
        Tcl_Obj *methodNameObj);




If the result is TCL_OK, the remapping is assumed to have been
    done. If the result is TCL_ERROR, an error message will have been left in
    interp and the method call will fail. If the result is TCL_BREAK, the
    standard method name lookup rules will be used; the behavior of other result
    codes is currently undefined. The object parameter says which object
    is being processed. The startClsPtr parameter points to a variable
    that contains the first class to provide a definition in the method chain to
    process, or NULL if the whole chain is to be processed (the argument itself
    is never NULL); this variable may be updated by the callback. The
    methodNameObj parameter gives an unshared object containing the name
    of the method being invoked, as provided by the user; this object may be
    updated by the callback.
