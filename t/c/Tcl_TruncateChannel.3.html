ARGUMENTOS

Tcl_Interp *interp (in)
Se utiliza para la notificación de errores y para buscar un canal registrado en él.
const char *fileName (in)
El nombre de un archivo local o de red.
const char *mode (in)
Especifica cómo se debe acceder al archivo. Puede tener cualquiera de los valores permitidos para el argumento mode del comando Tcl open.
int permissions (in)
Indicadores de permisos estilo POSIX, como 0644. Si se crea un archivo nuevo, estos permisos se aplicarán al archivo creado.
int argc (in)
El número de elementos en argv.
const char **argv (in)
Argumentos para la construcción de una tubería de comandos. Estos valores tienen el mismo significado que los argumentos sin opciones del comando Tcl exec.
int flags (in)
Especifica la disposición de los manejadores stdio en la tubería: combinación OR de TCL_STDIN, TCL_STDOUT, TCL_STDERR y TCL_ENFORCE_MODE. Si se establece TCL_STDIN, la entrada estándar del primer hijo en la tubería es el canal de la tubería, de lo contrario es la misma que la entrada estándar del proceso invocador; lo mismo ocurre con TCL_STDOUT y TCL_STDERR. Si no se establece TCL_ENFORCE_MODE, entonces la tubería puede redirigir los manejadores stdio para anular los manejadores stdio para los que se han establecido TCL_STDIN, TCL_STDOUT y TCL_STDERR. Si está establecido, tales redirecciones causan un error.
ClientData handle (in)
Manejador específico del sistema operativo para E/S de un archivo. Para Unix es un descriptor de archivo, para Windows es un HANDLE.
int readOrWrite (in)
Combinación OR de TCL_READABLE y TCL_WRITABLE para indicar qué operaciones son válidas en handle.
const char *channelName (in)
El nombre del canal.
int *modePtr (out)
Punta a una variable entera que recibirá una combinación OR de TCL_READABLE y TCL_WRITABLE, indicando si el canal está abierto para lectura y escritura.
const char *pattern (in)
El patrón a coincidir, pasado a Tcl_StringMatch, o NULL.
Tcl_Channel channel (in)
Un canal Tcl para entrada o salida. Debe haber sido el valor de retorno de un procedimiento como Tcl_OpenFileChannel.
Tcl_Obj *readObjPtr (in/out)
Un puntero a un valor Tcl en el que se almacenarán los caracteres leídos del canal.
int charsToRead (in)
El número de caracteres a leer del canal. Si la codificación del canal es binary, esto es equivalente al número de bytes a leer del canal.
int appendFlag (in)
Si es distinto de cero, los datos leídos del canal se añadirán al valor. De lo contrario, los datos reemplazarán el contenido existente del valor.
char *readBuf (out)
Un búfer en el que se almacenarán los bytes leídos del canal.
int bytesToRead (in)
El número de bytes a leer del canal. El búfer readBuf debe ser lo suficientemente grande para contener esta cantidad de bytes.
Tcl_Obj *lineObjPtr (in/out)
Un puntero a un valor Tcl en el que se almacenará la línea leída del canal. La línea leída se añadirá al valor actual del valor.
Tcl_DString *lineRead (in/out)
Un puntero a una cadena dinámica Tcl en la que se almacenará la línea leída del canal. Debe haber sido inicializada por el llamador. La línea leída se añadirá a cualquier dato que ya esté en la cadena dinámica.
const char *input (in)
La entrada a añadir a un búfer de canal.
int inputLen (in)
Longitud de la entrada
int addAtEnd (in)
Indicador de si la entrada debe añadirse al final o al principio del búfer del canal.
Tcl_Obj *writeObjPtr (in)
Un puntero a un valor Tcl cuyos contenidos se enviarán al canal.
const char *charBuf (in)
Un búfer que contiene los caracteres a enviar al canal.
const char *byteBuf (in)
Un búfer que contiene los bytes a enviar al canal.
int bytesToWrite (in)
El número de bytes a consumir de charBuf o byteBuf y enviar al canal.
Tcl_WideInt offset (in)
Hasta dónde mover el punto de acceso en el canal en el que se aplicará la próxima operación de entrada o salida, medido en bytes desde la posición dada por seekMode. Puede ser positivo o negativo.
int seekMode (in)
Desde qué punto buscar; se utiliza con offset para calcular el nuevo punto de acceso para el canal. Los valores legales son SEEK_SET, SEEK_CUR y SEEK_END.
Tcl_WideInt length (in)
La longitud (no negativa) a la que se truncará el canal.
const char *optionName (in)
El nombre de una opción aplicable a este canal, como -blocking. Puede tener cualquiera de los valores aceptados por el comando fconfigure.

DESCRIPCIÓN

El mecanismo de canales de Tcl proporciona un mecanismo independiente de dispositivo y de plataforma para realizar operaciones de entrada y salida con búfer en una variedad de tipos de archivos, sockets y dispositivos. El mecanismo de canales es extensible a nuevos tipos de canales, proporcionando un controlador de canal de bajo nivel para el nuevo tipo; la interfaz del controlador de canal se describe en la entrada del manual para Tcl_CreateChannel. El mecanismo de canales proporciona un esquema de búfer modelado después de la E/S estándar de Unix, y también permite la E/S no bloqueante en los canales.

Los procedimientos descritos en esta entrada del manual comprenden las APIs de C de la capa genérica de la arquitectura de canales. Para una descripción de la arquitectura del controlador de canal y cómo implementar controladores de canal para nuevos tipos de canales, consulte la entrada del manual para Tcl_CreateChannel.

TCL_OPENFILECHANNEL

El procedimiento Tcl_OpenFileChannel abre el archivo especificado por fileName en el modo especificado por mode y con los permisos especificados por permissions. El modo es una cadena que consiste en caracteres que indican cómo se debe acceder al archivo. Los modos comunes son:

  • r Abrir para lectura.
  • w Abrir para escritura, truncando el archivo a cero longitud si ya existía.
  • a Abrir para añadir al final del archivo.
  • r+ Abrir para lectura y escritura.
  • w+ Abrir para lectura y escritura, truncando el archivo a cero longitud si ya existía.
  • a+ Abrir para lectura y añadir al final del archivo.

Se pueden añadir caracteres opcionales como b para indicar modo binario (en sistemas que distinguen entre modo texto y binario, como Windows).

Si el archivo se abre correctamente, se devuelve un descriptor de canal. Si se produce un error, se establece una entrada de error en interp y se devuelve un valor NULL.

Los permisos son un valor entero que representa el permiso de acceso POSIX para el archivo. Solo se aplica si el archivo se crea (por ejemplo, si se abre en modo escritura).

TCL_OPENCOMMANDCHANNEL

El procedimiento Tcl_OpenCommandChannel crea una tubería de procesos ejecutando el comando especificado por argc y argv. Los argumentos argc y argv tienen el mismo significado que los argumentos sin opciones del comando Tcl exec.

El argumento flags se utiliza para controlar la disposición de los manejadores estándar (stdin, stdout, stderr) del proceso hijo. Los valores posibles son una combinación OR de TCL_STDIN, TCL_STDOUT, TCL_STDERR y TCL_ENFORCE_MODE.

Si se establece TCL_STDIN, la entrada estándar del primer proceso hijo en la tubería es el canal de la tubería. Si no, es la misma que la entrada estándar del proceso invocador.

Si se establece TCL_STDOUT, la salida estándar del último proceso hijo en la tubería es el canal de la tubería. Si no, es la misma que la salida estándar del proceso invocador.

Si se establece TCL_STDERR, la salida de error estándar del último proceso hijo en la tubería es el canal de la tubería. Si no, es la misma que la salida de error estándar del proceso invocador.

Si no se establece TCL_ENFORCE_MODE, la tubería puede redirigir los manejadores estándar para anular los manejadores estándar para los que se han establecido TCL_STDIN, TCL_STDOUT y TCL_STDERR. Si está establecido, tales redirecciones causan un error.

Si la tubería se crea correctamente, se devuelve un descriptor de canal. Si se produce un error, se establece una entrada de error en interp y se devuelve un valor NULL.

TCL_MAKEFILECHANNEL

El procedimiento Tcl_MakeFileChannel crea un nuevo canal Tcl a partir de un descriptor de archivo del sistema operativo existente. handle es el descriptor de archivo y readOrWrite indica si el descriptor de archivo está abierto para lectura, escritura o ambos. Tcl_MakeFileChannel devuelve el nuevo descriptor de canal.

TCL_GETCHANNEL

El procedimiento Tcl_GetChannel recupera un canal existente con el nombre dado por channelName del intérprete dado por interp. Si modePtr no es NULL, entonces se establece en un valor que indica si el canal está abierto para lectura (TCL_READABLE) o escritura (TCL_WRITABLE).

Si se encuentra el canal, se devuelve el descriptor del canal. Si no, se devuelve NULL y se establece una entrada de error en interp.

TCL_GETCHANNELNAMES

El procedimiento Tcl_GetChannelNames devuelve un valor de Tcl que contiene una lista de los nombres de todos los canales actualmente abiertos en el intérprete dado por interp. Si se produce un error, se devuelve un valor de error y se establece una entrada de error en interp.

TCL_GETCHANNELNAMESEX

Similar a Tcl_GetChannelNames, pero solo devuelve los nombres de los canales que coinciden con el patrón dado por pattern. Si pattern es NULL, se comportará igual que Tcl_GetChannelNames.

TCL_REGISTERCHANNEL

El procedimiento Tcl_RegisterChannel registra el canal dado por channel en el intérprete dado por interp. Esto hace que el canal sea visible para los comandos Tcl como puts y gets.

TCL_UNREGISTERCHANNEL

El procedimiento Tcl_UnregisterChannel anula el registro del canal dado por channel del intérprete dado por interp. Si el canal no está registrado, no se hace nada.

TCL_DETACHCHANNEL

El procedimiento Tcl_DetachChannel desvincula el canal dado por channel del intérprete dado por interp. Esto hace que el canal no sea visible para los comandos Tcl, pero el canal permanece abierto y se puede seguir utilizando a través de la API C. Si el canal ya está desvinculado, no se hace nada.

TCL_ISSTANDARDCHANNEL

El procedimiento Tcl_IsStandardChannel devuelve 1 si el canal dado por channel es uno de los canales estándar (entrada, salida o error estándar), y 0 en caso contrario.

TCL_CLOSE

El procedimiento Tcl_Close cierra el canal dado por channel. Si el canal está abierto para escritura, se vaciarán los búferes de salida antes de cerrar el canal. Si se produce un error durante el cierre, se establece una entrada de error en interp y se devuelve -1. En caso contrario, se devuelve 0.

TCL_READCHARS

El procedimiento Tcl_ReadChars lee hasta charsToRead caracteres del canal dado por channel y los almacena en el objeto Tcl apuntado por readObjPtr. Si appendFlag es distinto de cero, los caracteres leídos se añadirán al valor existente de readObjPtr. De lo contrario, se reemplazarán.

Si se produce un error durante la lectura, se establece una entrada de error en interp y se devuelve -1. Si se alcanza el final del archivo antes de leer charsToRead caracteres, se devuelve el número de caracteres leídos. En caso contrario, se devuelve el número de caracteres leídos.

TCL_READ

El procedimiento Tcl_Read lee hasta bytesToRead bytes del canal dado por channel y los almacena en el búfer dado por readBuf. El búfer readBuf debe ser lo suficientemente grande para contener bytesToRead bytes.

Si se produce un error durante la lectura, se establece una entrada de error en interp y se devuelve -1. Si se alcanza el final del archivo antes de leer bytesToRead bytes, se devuelve el número de bytes leídos. En caso contrario, se devuelve el número de bytes leídos.

TCL_GETSOBJ

El procedimiento Tcl_GetsObj lee una línea del canal dado por channel y la almacena en el objeto Tcl apuntado por lineObjPtr. La línea se lee hasta el primer carácter de nueva línea (‘\n’) o hasta el final del archivo. El carácter de nueva línea se consume pero no se incluye en el resultado. Si se produce un error durante la lectura, se establece una entrada de error en interp y se devuelve -1. Si se alcanza el final del archivo, se devuelve 1. En caso contrario, se devuelve 0.

TCL_GETS

El procedimiento Tcl_Gets lee una línea del canal dado por channel y la almacena en la cadena dinámica Tcl apuntada por lineRead. La línea se lee hasta el primer carácter de nueva línea (‘\n’) o hasta el final del archivo. El carácter de nueva línea se consume pero no se incluye en el resultado. Si se produce un error durante la lectura, se establece una entrada de error en interp y se devuelve -1. Si se alcanza el final del archivo, se devuelve 1. En caso contrario, se devuelve 0.

TCL_UNGETS

El procedimiento Tcl_Ungets coloca la cadena dada por input (de longitud inputLen) de nuevo en el búfer de entrada del canal dado por channel. Si addAtEnd es distinto de cero, la entrada se añade al final del búfer de entrada. De lo contrario, se añade al principio.

Si se produce un error, se devuelve -1. En caso contrario, se devuelve 0.

TCL_WRITEOBJ

El procedimiento Tcl_WriteObj escribe el contenido del objeto Tcl apuntado por writeObjPtr en el canal dado por channel. Si se produce un error durante la escritura, se establece una entrada de error en interp y se devuelve -1. En caso contrario, se devuelve el número de bytes escritos.

TCL_WRITECHARS

El procedimiento Tcl_WriteChars escribe los caracteres del búfer dado por charBuf (de longitud bytesToWrite) en el canal dado por channel. Si se produce un error durante la escritura, se establece una entrada de error en interp y se devuelve -1. En caso contrario, se devuelve el número de bytes escritos.

TCL_WRITE

El procedimiento Tcl_Write escribe los bytes del búfer dado por byteBuf (de longitud bytesToWrite) en el canal dado por channel. Si se produce un error durante la escritura, se establece una entrada de error en interp y se devuelve -1. En caso contrario, se devuelve el número de bytes escritos.

TCL_READRAW

Similar a Tcl_Read, pero lee bytes sin decodificar según la codificación del canal. Útil para leer datos binarios.

TCL_WRITERAW

Similar a Tcl_Write, pero escribe bytes sin codificar según la codificación del canal. Útil para escribir datos binarios.

TCL_EOF

El procedimiento Tcl_Eof devuelve 1 si se ha alcanzado el final del archivo en el canal dado por channel, y 0 en caso contrario. Esto es útil para comprobar si se ha llegado al final del archivo sin intentar leer más allá.

TCL_FLUSH

El procedimiento Tcl_Flush fuerza la escritura de cualquier dato en el búfer de salida del canal dado por channel. Esto asegura que los datos se escriban en el dispositivo subyacente inmediatamente. Si se produce un error durante el vaciado, se establece una entrada de error en interp y se devuelve -1. En caso contrario, se devuelve 0.

TCL_INPUTBLOCKED

El procedimiento Tcl_InputBlocked devuelve 1 si una operación de lectura en el canal dado por channel se bloquearía porque no hay datos disponibles, y 0 en caso contrario. Esto es útil para implementar E/S no bloqueante.

TCL_INPUTBUFFERED

El procedimiento Tcl_InputBuffered devuelve el número de bytes que están actualmente en el búfer de entrada del canal dado por channel y que aún no han sido leídos por la aplicación.

TCL_OUTPUTBUFFERED

El procedimiento Tcl_OutputBuffered devuelve el número de bytes que están actualmente en el búfer de salida del canal dado por channel y que aún no han sido escritos en el dispositivo subyacente.

TCL_SEEK

El procedimiento Tcl_Seek cambia el punto de acceso actual del canal dado por channel. El nuevo punto de acceso se calcula añadiendo offset (en bytes) al punto de referencia especificado por seekMode. Los valores legales para seekMode son SEEK_SET (principio del archivo), SEEK_CUR (posición actual) y SEEK_END (final del archivo). El procedimiento devuelve la nueva posición de acceso en bytes desde el principio del archivo, o -1 si se produce un error.

TCL_TELL

El procedimiento Tcl_Tell devuelve la posición actual del punto de acceso en el canal dado por channel, en bytes desde el principio del archivo. Si se produce un error, devuelve -1.

TCL_TRUNCATECHANNEL

El procedimiento Tcl_TruncateChannel trunca el canal dado por channel a la longitud especificada por length. Si la longitud especificada es menor que la longitud actual del canal, se descartan los datos que exceden la nueva longitud. Si la longitud especificada es mayor que la longitud actual, el efecto es específico del sistema operativo, pero normalmente el archivo se rellena con bytes nulos.

Si se produce un error, se devuelve -1. En caso contrario, se devuelve 0.

Este procedimiento solo está disponible para canales que admiten la operación de truncamiento, como los archivos regulares.

TCL_GETCHANNELOPTION

El procedimiento Tcl_GetChannelOption recupera el valor de una opción específica del canal dado por channel. El nombre de la opción se proporciona en optionName y el valor recuperado se almacena en la cadena dinámica Tcl apuntada por optionValue. Si se produce un error, se devuelve -1 y se establece una entrada de error en interp. En caso contrario, se devuelve 0.

Las opciones disponibles son las mismas que las aceptadas por el comando Tcl fconfigure.

TCL_SETCHANNELOPTION

El procedimiento Tcl_SetChannelOption establece el valor de una opción específica del canal dado por channel. El nombre de la opción se proporciona en optionName y el nuevo valor se proporciona en newValue. Si se produce un error, se devuelve -1 y se establece una entrada de error en interp. En caso contrario, se devuelve 0.

Las opciones disponibles son las mismas que las aceptadas por el comando Tcl fconfigure.

TCL_GETSOBJ Y TCL_GETS

Tcl_GetsObj consume bytes del channel, convirtiendo los bytes a UTF-8 basándose en la codificación del canal, hasta que se haya visto una línea completa de entrada. Si la codificación del canal es binary, cada byte leído del canal se trata como un carácter Unicode individual. Todos los caracteres de la línea, excepto los caracteres de fin de línea terminadores, se añaden a la representación de cadena de lineObjPtr. Los caracteres de fin de línea se leen y descartan.

Si se leyó una línea correctamente, el valor de retorno es mayor o igual a cero e indica el número de bytes almacenados en lineObjPtr. Si ocurre un error, Tcl_GetsObj devuelve -1 y registra un código de error POSIX que se puede recuperar con Tcl_GetErrno. Tcl_GetsObj también devuelve -1 si se llega al final del archivo; el procedimiento Tcl_Eof se puede utilizar para distinguir un error de una condición de fin de archivo.

Si el canal está en modo no bloqueante, el valor de retorno también puede ser -1 si no había datos disponibles o si los datos disponibles no contenían un carácter de fin de línea. Cuando se devuelve -1, se puede invocar el procedimiento Tcl_InputBlocked para determinar si el canal está bloqueado debido a la falta de entrada.

Tcl_Gets es lo mismo que Tcl_GetsObj excepto que los caracteres resultantes se añaden a la cadena dinámica dada por lineRead en lugar de un valor Tcl.

TCL_UNGETS

Tcl_Ungets se utiliza para añadir datos a la cola de entrada de un canal, ya sea al principio o al final de la cola. El puntero input apunta a los datos que se van a añadir. La longitud de la entrada a añadir viene dada por inputLen. Un valor distinto de cero para addAtEnd indica que los datos se añadirán al final de la cola; de lo contrario, se añadirán al principio de la cola. Si channel tiene un marcador EOF "pegajoso", no se añadirán datos a la cola de entrada. Tcl_Ungets devuelve inputLen o -1 si ocurre un error.

TCL_WRITECHARS, TCL_WRITEOBJ, Y TCL_WRITE

Tcl_WriteChars acepta bytesToWrite bytes de datos de caracteres en charBuf. Los caracteres UTF-8 del búfer se convierten a la codificación del canal y se ponen en cola para su salida al channel. Si bytesToWrite es negativo, Tcl_WriteChars espera que charBuf termine en nulo y saca todo hasta el nulo.

Los datos puestos en cola para la salida pueden no aparecer en el dispositivo de salida inmediatamente, debido al almacenamiento en búfer interno. Si los datos deben aparecer inmediatamente, llame a Tcl_Flush después de la llamada a Tcl_WriteChars, o establezca la opción -buffering en el canal a none. Si desea que los datos aparezcan tan pronto como se acepte una línea completa para la salida, establezca la opción -buffering en el canal en modo line.

El valor de retorno de Tcl_WriteChars es un recuento de cuántos bytes fueron aceptados para la salida al canal. Este es un número mayor que cero para indicar éxito o -1 para indicar que ocurrió un error. Si ocurre un error, Tcl_WriteChars registra un código de error POSIX que puede recuperarse con Tcl_GetErrno.

Los caracteres de nueva línea en los datos de salida se traducen a secuencias de fin de línea específicas de la plataforma según la opción -translation del canal. Esto se hace incluso si el canal no tiene codificación.

Tcl_WriteObj es similar a Tcl_WriteChars excepto que acepta un valor Tcl cuyos contenidos se sacarán al canal. Los caracteres UTF-8 de la representación de cadena de writeObjPtr se convierten a la codificación del canal y se ponen en cola para su salida al channel. Como optimización de rendimiento, al escribir en un canal con la codificación binary, los caracteres UTF-8 no se convierten al escribirse. En su lugar, los bytes de la representación interna de writeObjPtr como un valor de matriz de bytes se escriben en el canal. La representación de matriz de bytes del valor se construirá si es necesario. De esta manera, los datos orientados a bytes se pueden leer de un canal, manipular llamando a Tcl_GetByteArrayFromObj y funciones relacionadas, y luego escribir en un canal sin el costo de convertir desde o hacia UTF-8.

Tcl_Write es similar a Tcl_WriteChars excepto que no realiza conversiones de codificación, independientemente de la codificación del canal. Está obsoleto y existe para compatibilidad con versiones anteriores con extensiones Tcl no internacionalizadas. Acepta bytesToWrite bytes de datos en byteBuf y los pone en cola para su salida al channel. Si bytesToWrite es negativo, Tcl_Write espera que byteBuf termine en nulo y saca todo hasta el nulo.

Tcl_WriteRaw es lo mismo que Tcl_Write pero no compensa el apilamiento. Mientras que Tcl_Write (y las otras funciones de la API) siempre alimentan su entrada al canal superior en la pila de la que forma parte el canal proporcionado, Tcl_WriteRaw no lo hace. Por lo tanto, esta función solo es utilizable para controladores de canal transformacionales, es decir, controladores utilizados en medio de una pila de canales, para mover datos de la transformación al canal de abajo.

TCL_FLUSH

Tcl_Flush provoca que todos los datos de salida almacenados en el búfer para channel se escriban en su archivo o dispositivo subyacente lo antes posible. Si el canal está en modo bloqueante, la llamada no regresa hasta que todos los datos almacenados en el búfer se hayan enviado al canal o haya ocurrido algún error. La llamada regresa inmediatamente si el canal no está bloqueante; inicia una operación de vaciado en segundo plano que escribirá los datos almacenados en el búfer en el canal eventualmente, tan rápido como el canal sea capaz de absorberlos.

El valor de retorno es normalmente TCL_OK. Si ocurre un error, Tcl_Flush devuelve TCL_ERROR y registra un código de error POSIX que puede recuperarse con Tcl_GetErrno.

TCL_SEEK

Tcl_Seek mueve el punto de acceso en channel donde se leerán o escribirán datos posteriores. La salida almacenada en búfer se vacía al canal y la entrada almacenada en búfer se descarta, antes de la operación de búsqueda. Por ejemplo, para mover el punto de acceso al principio del archivo, use Tcl_Seek(channel, 0, TCL_SEEK_SET).

Tcl_Seek normalmente devuelve el nuevo punto de acceso. Si ocurre un error, Tcl_Seek devuelve -1 y registra un código de error POSIX que puede recuperarse con Tcl_GetErrno. Después de un error, el punto de acceso puede haberse movido o no.

TCL_TELL

Tcl_Tell devuelve el punto de acceso actual para un canal. El valor devuelto es -1 si el canal no admite la búsqueda.

TCL_TRUNCATECHANNEL

Tcl_TruncateChannel trunca el archivo subyacente de channel a una longitud dada de length bytes. Devuelve TCL_OK si la operación tuvo éxito y TCL_ERROR en caso contrario.

TCL_GETCHANNELOPTION

Tcl_GetChannelOption recupera, en optionValue, el valor de una de las opciones actualmente en vigor para un canal, o una lista de todas las opciones y sus valores. El argumento channel identifica el canal para el que se va a consultar una opción o se van a recuperar todas las opciones y sus valores. Si optionName no es NULL, es el nombre de la opción a consultar; el valor de la opción se copia a la cadena dinámica Tcl denotada por optionValue. Si optionName es NULL, la función almacena una lista alterna de nombres de opciones y sus valores en optionValue.

TCL_GETCHANNELOPTION

Tcl_GetChannelOption returns the value of the option optionName for channel. If interp is non-NULL, the procedure leaves the value in the interpreter's result. The procedure normally returns TCL_OK. If an error occurs, it returns TCL_ERROR and, if interp is non-NULL, leaves an error message in the interpreter's result. The options are described using a series of calls to Tcl_DStringAppendElement. The various preexisting options and their possible values are described in the manual entry for the Tcl fconfigure command. Other options can be added by each channel type. These channel type specific options are described in the manual entry for the Tcl command that creates a channel of that type; for example, the additional options for TCP-based channels are described in the manual entry for the Tcl socket command. The procedure normally returns TCL_OK. If an error occurs, it returns TCL_ERROR and calls Tcl_SetErrno to store an appropriate POSIX error code.

TCL_SETCHANNELOPTION

Tcl_SetChannelOption sets a new value newValue for an option optionName on channel. The procedure normally returns TCL_OK. If an error occurs, it returns TCL_ERROR; in addition, if interp is non-NULL, Tcl_SetChannelOption leaves an error message in the interpreter's result.

TCL_EOF

Tcl_Eof returns a nonzero value if channel encountered an end of file during the last input operation.

TCL_INPUTBLOCKED

Tcl_InputBlocked returns a nonzero value if channel is in nonblocking mode and the last input operation returned less data than requested because there was insufficient data available. The call always returns zero if the channel is in blocking mode.

TCL_INPUTBUFFERED

Tcl_InputBuffered returns the number of bytes of input currently buffered in the internal buffers for a channel. If the channel is not open for reading, this function always returns zero.

TCL_OUTPUTBUFFERED

Tcl_OutputBuffered returns the number of bytes of output currently buffered in the internal buffers for a channel. If the channel is not open for writing, this function always returns zero.

PLATFORM ISSUES

The handles returned from Tcl_GetChannelHandle depend on the platform and the channel type. On Unix platforms, the handle is always a Unix file descriptor as returned from the open system call. On Windows platforms, the handle is a file HANDLE when the channel was created with Tcl_OpenFileChannel, Tcl_OpenCommandChannel, or Tcl_MakeFileChannel. Other channel types may return a different type of handle on Windows platforms.
