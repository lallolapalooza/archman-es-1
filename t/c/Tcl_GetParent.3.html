DESCRIPCIÓN

Estos procedimientos están destinados al acceso a la instalación de múltiples intérpretes desde programas C. Permiten administrar múltiples intérpretes en una relación jerárquica y la administración de alias, comandos que al invocarse en un intérprete ejecutan un comando en otro intérprete. El valor de retorno para aquellos procedimientos que devuelven un int es ya sea TCL_OK o TCL_ERROR. Si se devuelve TCL_ERROR, el resultado del intérprete contiene un mensaje de error.

Tcl_CreateSlave crea un nuevo intérprete como hijo de interp. También crea un comando hijo llamado childName en interp que permite a interp manipular el nuevo hijo. Si isSafe es cero, el comando crea un hijo confiable en el cual el código Tcl tiene acceso a todos los comandos Tcl. Si es 1, el comando crea un hijo “seguro” en el cual el código Tcl solo tiene acceso a un conjunto de comandos Tcl definidos como “Safe Tcl”; ver la entrada del manual del comando interp de Tcl para más detalles. Si la creación del nuevo intérprete hijo falló, se devuelve NULL.

Tcl_CreateChild es un sinónimo de Tcl_CreateSlave.

Tcl_IsSafe devuelve 1 si interp es “seguro” (fue creado con el flag TCL_SAFE_INTERPRETER especificado), 0 de lo contrario.

Tcl_MakeSafe marca interp como “seguro”, de modo que las llamadas futuras a Tcl_IsSafe devuelvan 1. También elimina toda la funcionalidad central potencialmente insegura conocida (tanto comandos como variables) de interp. Sin embargo, no puede saber qué partes de una extensión o aplicación son seguras y no hace ningún intento de eliminar esas partes, por lo que la seguridad no está garantizada después de llamar a Tcl_MakeSafe. Los llamadores querrán tener cuidado con su uso de Tcl_MakeSafe para evitar falsas afirmaciones de seguridad. Para muchas situaciones, Tcl_CreateSlave puede ser una mejor opción, ya que crea intérpretes en un estado conocido como seguro.

Tcl_GetSlave devuelve un puntero a un intérprete hijo de interp. El intérprete hijo se identifica por childName. Si no existe dicho intérprete hijo, se devuelve NULL.

Tcl_GetChild es un sinónimo de Tcl_GetSlave.

Tcl_GetMaster devuelve un puntero al intérprete maestro de interp. Si interp no tiene maestro (es un intérprete de nivel superior), se devuelve NULL.

Tcl_GetParent es un sinónimo de Tcl_GetMaster.

Tcl_GetInterpPath almacena en el resultado de interp la ruta relativa entre interp y childInterp; childInterp debe ser un hijo de interp. Si la computación de la ruta relativa tiene éxito, se devuelve TCL_OK, de lo contrario se devuelve TCL_ERROR y se almacena un mensaje de error como resultado de interp.

Tcl_CreateAlias crea un comando llamado childCmd en childInterp que, cuando se invoca, provocará la invocación del comando targetCmd en targetInterp. Los argumentos especificados por las cadenas contenidas en argv siempre se anteponen a cualquier argumento suministrado en la invocación de childCmd y se pasan a targetCmd. Esta operación devuelve TCL_OK si tiene éxito, o TCL_ERROR si falla; en ese caso, se deja un mensaje de error en el resultado de valor de childInterp. Tenga en cuenta que no hay restricciones en la relación de ascendencia (tal como se crea por Tcl_CreateSlave) entre childInterp y targetInterp. Se pueden usar dos intérpretes cualesquiera, sin restricciones sobre cómo están relacionados.

Tcl_CreateAliasObj es similar a Tcl_CreateAlias excepto que toma un vector de valores para pasar como argumentos adicionales en lugar de un vector de cadenas.

Tcl_GetAliasObj devuelve información en forma de un puntero a un vector de estructuras Tcl_Obj sobre un alias aliasName en interp. Cualquiera de los campos de resultado puede ser NULL, en cuyo caso el dato correspondiente no se devuelve. Si un campo de resultado no es NULL, la dirección indicada se establece en el dato correspondiente. Por ejemplo, si targetCmdPtr no es NULL, se establece en un puntero a la cadena que contiene el nombre del comando de destino.

Tcl_GetAlias es similar a Tcl_GetAliasObj excepto que devuelve un puntero a un vector de cadenas en lugar de un vector de estructuras Tcl_Obj. Tcl_GetAlias está obsoleto

NAME

Tcl_CreateAlias, Tcl_CreateCommand, Tcl_DeleteCommand, Tcl_ExposeCommand, Tcl_HideCommand, Tcl_ListCommandNums, Tcl_ListCommands — interpreter commands and aliases

SYNOPSIS

#include <tcl.h>

int
Tcl_CreateAlias(interp, name, cmdProc, clientData, deleteProc);
int
Tcl_CreateCommand(interp, cmdName, proc, clientData, deleteProc);
int
Tcl_DeleteCommand(interp, cmdName);
int
Tcl_ExposeCommand(interp, hiddenCmdName, cmdName);
int
Tcl_HideCommand(interp, cmdName, hiddenCmdName);
Tcl_Obj *
Tcl_ListCommandNums(interp);
int
Tcl_ListCommands(interp, varNamePtr);

ARGUMENTS

Tcl_Interp *interp (in)
    Interprete to modify.
const char *cmdName (in)
    Name of command to create or delete.
const char *hiddenCmdName (in)
    Name of hidden command.
Tcl_CmdProc *proc (in)
    Procedure to be invoked when command is executed.
Tcl_CmdDeleteProc *deleteProc (in)
    Procedure to be invoked when command is deleted.
ClientData clientData (in)
    Arbitrary data associated with the command.
Tcl_Obj **varNamePtr (in)
    Pointer to variable to hold list of command names.

DESCRIPTION

The Tcl interpreter provides a number of commands for manipulating and querying the commands within an interpreter.

Tcl_CreateAlias creates an alias command in the interpreter interp. When the alias command named name is executed, it will invoke the command specified by cmdProc with arguments clientData and interp. The alias command is created under the name name. If deleteProc is non-NULL, then it will be called with clientData as its argument when the alias command is deleted.

Tcl_CreateCommand creates a new command in the interpreter interp. The command will be called cmdName. When the command is invoked, the procedure proc will be called with arguments clientData and interp. The command will be created in the current namespace, unless cmdName contains namespace qualifiers. If a command named cmdName already exists, then the old command is removed and the new one is created. If deleteProc is non-NULL, then it will be called with clientData as its argument when the command is deleted.

Tcl_DeleteCommand removes the command named cmdName from the interpreter interp. If a delete procedure was associated with the command when it was created (see Tcl_CreateCommand or Tcl_CreateAlias), then that procedure will be called with the command’s client data as its argument. If the command does not exist, then Tcl_DeleteCommand returns TCL_ERROR and leaves an error message as the result of interp. Otherwise, it returns TCL_OK. The command is looked up in the global namespace, and not relative to the current namespace.

Tcl_ExposeCommand moves the command named hiddenCmdName from the set of hidden commands to the set of exposed commands, putting it under the name cmdName. HiddenCmdName must be the name of an existing hidden command, or the operation will return TCL_ERROR and leave an error message as the result of interp. If an exposed command named cmdName already exists, the operation returns TCL_ERROR and leaves an error message as the result of interp. If the operation succeeds, it returns TCL_OK. After executing this command, attempts to use cmdName in any script evaluation mechanism will again succeed.

Tcl_HideCommand moves the command named cmdName from the set of exposed commands to the set of hidden commands, under the name hiddenCmdName. CmdName must be the name of an existing exposed command, or the operation will return TCL_ERROR and leave an error message as the result of interp. Currently both cmdName and hiddenCmdName must not contain namespace qualifiers, or the operation will return TCL_ERROR and leave an error message as the result of interp. The CmdName will be looked up in the global namespace, and not relative to the current namespace, even if the current namespace is not the global one. If a hidden command whose name is hiddenCmdName already exists, the operation also returns TCL_ERROR and an error message is left as the result of interp. If the operation succeeds, it returns TCL_OK. After executing this command, attempts to use cmdName in any script evaluation mechanism will fail.

For a description of the Tcl interface to multiple interpreters, see interp(n).
