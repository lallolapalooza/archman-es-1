Tcl_OpenTcpClient(3)

Paquete: tcl

Licencias: TCL

Tcl_OpenTcpClient(3) Procedimientos de la biblioteca Tcl Tcl_OpenTcpClient(3)

NOMBRE

Tcl_OpenTcpClient, Tcl_MakeTcpClientChannel, Tcl_OpenTcpServer - procedimientos para abrir canales usando sockets TCP

SINOPSIS

#include <tcl.h> 

Tcl_Channel
Tcl_OpenTcpClient(interp, port, host, myaddr, myport, async)

Tcl_Channel
Tcl_MakeTcpClientChannel(sock)

Tcl_Channel
Tcl_OpenTcpServer(interp, port, myaddr, proc, clientData)

ARGUMENTOS

Tcl_Interp *interp (entrada)
Intérprete de Tcl a utilizar para la notificación de errores. Si no es NULL y ocurre un error, se deja un mensaje de error en el resultado del intérprete.
int port (entrada)
Un número de puerto al que conectarse como cliente o en el que escuchar como servidor.
const char *host (entrada)
Una cadena que especifica un nombre de host o dirección del extremo remoto de la conexión.
int myport (entrada)
Un número de puerto para el extremo del socket del cliente. Si es 0, se asigna aleatoriamente un número de puerto.
const char *myaddr (entrada)
Una cadena que especifica el nombre de host o dirección de la interfaz de red a utilizar para el extremo local de la conexión. Si es NULL, se elige una interfaz predeterminada.
int async (entrada)
Si es distinto de cero, el socket del cliente se conecta de forma asíncrona al servidor.
ClientData sock (entrada)
Identificador específico de la plataforma para un socket TCP de cliente.
Tcl_TcpAcceptProc *proc (entrada)
Puntero a un procedimiento que se invocará cada vez que se acepte una nueva conexión a través del socket.
ClientData clientData (entrada)
Valor arbitrario de una palabra para pasar a proc.

DESCRIPCIÓN

Estas funciones son procedimientos de conveniencia para crear canales que se comunican a través de sockets TCP. Las operaciones sobre un canal se describen en la entrada del manual de Tcl_OpenFileChannel.

TCL_OPENTCPCLIENT

Tcl_OpenTcpClient abre un socket TCP de cliente conectado a un puerto en un host específico, y devuelve un canal que puede utilizarse para comunicarse con el servidor. El host al que conectarse puede especificarse como un nombre de estilo de dominio (p. ej., www.sunlabs.com) o como una cadena que contiene la representación alfanumérica de su dirección de cuatro bytes (p. ej., 127.0.0.1). Utilice la cadena localhost para conectarse a un socket TCP en el host en el que se invoca la función.

Los argumentos myaddr y myport permiten a un cliente especificar una dirección para el extremo local de la conexión. Si myaddr es NULL, el sistema operativo elige automáticamente una interfaz. Si myport es 0, el sistema operativo elige aleatoriamente un número de puerto.

Si async es cero, la llamada a Tcl_OpenTcpClient solo regresa después de que el socket del cliente se haya conectado correctamente al servidor, o si el intento de conexión ha fallado. Si async es distinto de cero, el socket se conecta de forma asíncrona y el canal devuelto puede que aún no esté conectado al servidor cuando la llamada a Tcl_OpenTcpClient regrese. Si el canal está en modo de bloqueo y se realiza una operación de entrada o salida en el canal antes de que la conexión se complete o falle, esa operación esperará hasta que la conexión se complete con éxito o falle. Si el canal está en modo no bloqueante, la operación de entrada o salida regresará inmediatamente y una llamada posterior a Tcl_InputBlocked en el canal devolverá un valor distinto de cero.

El canal devuelto se abre para lectura y escritura. Si ocurre un error al abrir el socket, Tcl_OpenTcpClient devuelve NULL y registra un código de error POSIX que puede recuperarse con Tcl_GetErrno. Además, si interp no es NULL, se deja un mensaje de error en el resultado del intérprete.

El canal recién creado no se registra en el intérprete suministrado; para registrarlo, use Tcl_RegisterChannel. Si uno de los canales estándar, stdin, stdout o stderr se cerró previamente, el acto de crear el nuevo canal también lo asigna como reemplazo del canal estándar.

TCL_MAKETCPCLIENTCHANNEL

Tcl_MakeTcpClientChannel crea un Tcl_Channel alrededor de un identificador existente, específico de la plataforma, para un socket TCP de cliente.

El canal recién creado no se registra en el intérprete suministrado; para registrarlo, use Tcl_RegisterChannel. Si uno de los canales estándar, stdin, stdout o stderr se cerró previamente, el acto de crear el nuevo canal también lo asigna como reemplazo del canal estándar.

TCL_OPENTCPSERVER

Tcl_OpenTcpServer abre un socket TCP en el host local en un puerto especificado y utiliza el mecanismo de eventos de Tcl para aceptar solicitudes de clientes para conectarse a él. El argumento myaddr especifica la interfaz de red. Si myaddr es NULL, se debe usar la dirección especial INADDR_ANY para permitir conexiones desde cualquier interfaz de red. Cada vez que un cliente se conecta a este socket, Tcl crea un canal para la nueva conexión e invoca a proc con información sobre el canal. Proc debe coincidir con el siguiente prototipo:

typedef void Tcl_TcpAcceptProc(
        ClientData clientData,
        Tcl_Channel channel,
        char *hostName,
        int port);

El argumento clientData será el mismo que el argumento clientData para Tcl_OpenTcpServer, channel será el identificador para el nuevo canal, hostName apunta a una cadena que contiene el nombre del host del cliente que realiza la conexión, y port contendrá el número de puerto del cliente. El nuevo canal se abre tanto para entrada como para salida. Si proc genera un error, la conexión se cierra automáticamente. Proc no tiene valor de retorno, pero si desea rechazar la conexión, puede cerrar channel.

Tcl_OpenTcpServer normalmente devuelve un puntero a un canal que representa el socket del servidor. Si ocurre un error, Tcl_OpenTcpServer devuelve NULL y registra un código de error POSIX que puede recuperarse con Tcl_GetErrno. Además, si el intérprete no es NULL, se deja un mensaje de error en el resultado del intérprete.

El canal devuelto por Tcl_OpenTcpServer no puede usarse para entrada ni salida. Es simplemente un identificador para el socket que se utiliza para aceptar conexiones. El llamador puede cerrar el canal para cerrar el servidor y prohibir conexiones futuras de nuevos clientes.

Los canales de servidor TCP solo funcionan correctamente en aplicaciones que distribuyen eventos a través de Tcl_DoOneEvent o a través de comandos de Tcl como vwait; de lo contrario, Tcl nunca notará que una solicitud de conexión de un cliente remoto está pendiente.

El canal recién creado no se registra en el intérprete suministrado; para registrarlo, use Tcl_RegisterChannel. Si uno de los canales estándar, stdin, stdout o stderr se cerró previamente, el acto de crear el nuevo canal también lo asigna como reemplazo del canal estándar.

PROBLEMAS DE PLATAFORMA

En plataformas Unix, el identificador del socket es un descriptor de archivo de Unix tal como lo devuelve la llamada del sistema socket. En la plataforma Windows, el identificador del socket es un SOCKET tal como se define en la API de WinSock.
