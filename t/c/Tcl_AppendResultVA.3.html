DESCRIPCIÓN

Las procedimientos descritas aquí son herramientas para manipular el valor de resultado en un interprete Tcl. El resultado del interprete puede ser una valor Tcl o un string. Por ejemplo, Tcl_SetObjResult y Tcl_SetResult establecen el resultado del interprete a, respectivamente, un valor y un string. Además, Tcl_GetObjResult y Tcl_GetStringResult devuelven el resultado del interprete como valor y como string. Las procedimientos siempre mantienen consistente la forma string y valor del resultado del interprete. Por ejemplo, si se llama Tcl_SetObjResult para establecer el resultado a un valor, entonces Tcl_GetStringResult devolverá la representación string del valor.

Tcl_SetObjResult asegura que objPtr sea el resultado para interp, reemplazando cualquier resultado existente. El resultado queda apuntando al valor referenciado por objPtr. La cuenta de referencia de objPtr aumenta ya que ahora hay un nuevo referenciado de él desde interp. La cuenta de referencia del valor antiguo se decrementa y se libera si no hay referencias a él.

Tcl_GetObjResult devuelve el resultado para interp como valor. La cuenta de referencia del valor no aumenta; si el llamador necesita mantener un long-term pointer a este valor, debe usar Tcl_IncrRefCount para incrementar su cuenta de referencia para evitar que se libere demasiado pronto o se cambie accidentalmente.

Tcl_SetResult asegura que result sea el resultado para el comando Tcl actual en interp, reemplazando cualquier resultado existente. El argumento freeProc especifica cómo gestionar la memoria para el argumento result; se discute en la sección THE TCL_FREEPROC ARGUMENT TO TCL_SETRESULT siguiente. Si result es NULL, entonces freeProc se ignora y Tcl_SetResult re-inicializa el resultado de interp para apuntar a una cadena vacía.

Tcl_GetStringResult devuelve el resultado para interp como string. Si el resultado fue establecido a un valor mediante una llamada a Tcl_SetObjResult, el valor se convertirá a string y se devolverá. Si la representación string del valor contiene bytes nulos, esta conversión perderá información. Por esta razón, los programadores se recomienda escribir su código usando las nuevas APIs de valor y llamar a Tcl_GetObjResult en lugar.

Tcl_ResetResult limpia el resultado de interp y deja el resultado en su estado normal vacío inicializado. Si el resultado es un valor, su cuenta de referencia se decrementa y el resultado queda apuntando a un valor no compartido representando una cadena vacía. Si el resultado es una cadena dinámica, su memoria se libera y el resultado queda como cadena vacía. Tcl_ResetResult también limpia el estado de error gestionado por Tcl_AddErrorInfo, Tcl_AddObjErrorInfo, y Tcl_SetErrorCode.

Tcl_AppendResult facilita la construcción de resultados Tcl en fragmentos. Recibe cada uno de sus argumentos result y los apende a la result actual asociada con interp. Si el resultado está en su estado inicial vacío (por ejemplo, una procedura de comando fue invocada o Tcl_ResetResult fue llamada), entonces Tcl_AppendResult establece el resultado a la concatenación de sus argumentos result. Tcl_AppendResult puede llamarse repetidamente como piezas adicionales del resultado se producen. Tcl_AppendResult maneja todos los problemas de gestión de memoria asociados con el resultado de interp, como la asignación de un área más grande si es necesario. También gestiona la conversión a y desde el campo result del interp para manejar la compatibilidad con extensiones antiguas. Pueden pasar cualquier número de argumentos result en una sola llamada; el último argumento en la lista debe ser (char *)NULL.

Tcl_AppendResultVA es el mismo que Tcl_AppendResult, salvo que en lugar de tomar un número variable de argumentos, toma un argumento list.

Tcl_TransferResult traslada el estado de interprete de sourceInterp a targetInterp. Los dos interpretes deben haber sido creados en el mismo hilo. Si sourceInterp y targetInterp son los mismos, nada se hace. De lo contrario, Tcl_TransferResult mueve el resultado de sourceInterp a targetInterp, y resetea el resultado en sourceInterp. También mueve el diccionario de opciones de retorno controlado por el valor de código code en el mismo sentido que Tcl_GetReturnOptions.

INTERFACES DEPRECATED

PROCEDURAS DE STRING ANTEJADAS

La utilización de las siguientes proceduras es obsoleta, ya que manipulan el resultado de Tcl como string. Las proceduras como Tcl_SetObjResult, que manipulan el resultado como valor, pueden ser significativamente más eficientes.

Tcl_AppendElement es similar a Tcl_AppendResult en que permite construir resultados en fragmentos. Sin embargo, Tcl_AppendElement solo acepta un argumento element y lo agrega al resultado actual como elemento de lista apropiado. Tcl_AppendElement agrega backslash o corchetes si es necesario para asegurar que el resultado de interp pueda parsearse como lista y que element pueda extraerse como elemento único. En condiciones normales, Tcl_AppendElement agrega un espacio en la result de interp justo antes de añadir el nuevo elemento de lista, para que los elementos de la lista en el resultado estén correctamente separados. Sin embargo, si el nuevo elemento de lista es el primero en una lista o sub-lista (es decir, el resultado actual de interp es vacío, o consiste en la única caracter “{”), entonces no se agrega espacio.

Tcl_FreeResult realiza parte del trabajo de Tcl_ResetResult. Libera la memoria asociada con el resultado de interp. También establece interp->freeProc a cero, pero no cambia interp->result o limpia el estado de error. Tcl_FreeResult se utiliza comúnmente cuando una procedura está a punto de reemplazar un valor de resultado con otro.

DESCRIPTION

These procedures provide the Tcl interpreter with an interface for constructing results, evaluating commands, and manipulating variables.

The procedures Tcl_SetResult, Tcl_SetObjResult, Tcl_GetStringResult, and Tcl_GetObjResult are used to manage the result of a command. Tcl_SetResult sets the result of the interpreter to be the value of the string pointed to by string. The freeProc argument determines how the storage for string is managed. Tcl_SetObjResult sets the result to be the value of the Tcl object objPtr. This is the preferred method for setting results, as it avoids unnecessary conversions between strings and objects.

Tcl_GetStringResult returns the current result of the interpreter as a C string. Tcl_GetObjResult returns the current result as a Tcl object.

The procedures Tcl_AppendResult, Tcl_AppendPrintf, Tcl_AppendLimitedToObj, and Tcl_AppendToObj are used to append strings or formatted output to the current result of the interpreter. Tcl_AppendResult takes a variable number of string arguments, each of which is appended to the result. Tcl_AppendPrintf appends a formatted string, similar to C's sprintf. Tcl_AppendLimitedToObj appends at most length bytes from the string str to the interpreter's result object. Tcl_AppendToObj appends the string str, of length length, to the interpreter's result object.

The procedures Tcl_ObjSetVar2, Tcl_SetVar2Ex, Tcl_SetVar, and Tcl_SetVar2 are used to set the value of a Tcl variable. Tcl_ObjSetVar2 sets the variable specified by varNamePtr and elementPtr to the value specified by valuePtr. Tcl_SetVar2Ex sets the variable specified by name1 and name2 to the value specified by newValuePtr. Tcl_SetVar and Tcl_SetVar2 set the variable to a string value. The flags argument controls how the variable is set (e.g., whether it should be created if it doesn't exist).

The procedures Tcl_GetVariable and Tcl_GetVariable2 are used to retrieve the value of a Tcl variable. They return the value as a C string. The flags argument controls how the variable is accessed.

The procedures Tcl_GlobalEval, Tcl_GlobalEvalVar, Tcl_EvalFile, Tcl_EvalObj, Tcl_EvalObjEx, Tcl_EvalTokens, Tcl_EvalWordObj, and Tcl_EvalWords are used to evaluate Tcl scripts. Tcl_GlobalEval evaluates the script in the global scope of the interpreter. Tcl_GlobalEvalVar evaluates the script stored in the variable varName in the global scope. Tcl_EvalFile reads and evaluates the script from the file specified by fileName. Tcl_EvalObj evaluates the Tcl object objPtr as a script. Tcl_EvalObjEx is similar to Tcl_EvalObj but allows the script object to be modified during evaluation. Tcl_EvalTokens evaluates a script represented as an array of tokens. Tcl_EvalWordObj evaluates a single word (treated as a script) represented by wordObjPtr. Tcl_EvalWords evaluates a list of words as a script.

DEPRECATED INTERFACES

The following interfaces are deprecated because they rely on the interpreter's internal result string buffer, which is not safe for use in commands that call other Tcl commands. The preferred interfaces are Tcl_GetObjResult and Tcl_SetObjResult.

Supported routines Tcl_GetObjResult, Tcl_GetStringResult, Tcl_SetObjResult, and Tcl_SetResult. As a migration aid, access can be restored with the compiler directive

#define USE_INTERP_RESULT

but this is meant only to offer life support to otherwise dead code.

THE TCL_FREEPROC ARGUMENT TO TCL_SETRESULT

Tcl_SetResult's freeProc argument specifies how the Tcl system is to manage the storage for the result argument. If Tcl_SetResult or Tcl_SetObjResult are called at a time when interp holds a string result, they do whatever is necessary to dispose of the old string result (see the Tcl_Interp manual entry for details on this).

If freeProc is TCL_STATIC it means that result refers to an area of static storage that is guaranteed not to be modified until at least the next call to Tcl_Eval. If freeProc is TCL_DYNAMIC it means that result was allocated with a call to Tcl_Alloc and is now the property of the Tcl system. Tcl_SetResult will arrange for the string's storage to be released by calling Tcl_Free when it is no longer needed. If freeProc is TCL_VOLATILE it means that result points to an area of memory that is likely to be overwritten when Tcl_SetResult returns (e.g. it points to something in a stack frame). In this case Tcl_SetResult will make a copy of the string in dynamically allocated storage and arrange for the copy to be the result for the current Tcl command.

If freeProc is not one of the values TCL_STATIC, TCL_DYNAMIC, and TCL_VOLATILE, then it is the address of a procedure that Tcl should call to free the string. This allows applications to use non-standard storage allocators. When Tcl no longer needs the storage for the string, it will call freeProc. FreeProc should have arguments and result that match the type Tcl_FreeProc:

typedef void Tcl_FreeProc(
        char *blockPtr);

When freeProc is called, its blockPtr will be set to the value of result passed to Tcl_SetResult.
