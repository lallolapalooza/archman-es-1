ARGUMENTOS

const char *bytes (in)
Punta al primer byte de un array de bytes codificados en UTF-8 utilizados para establecer o añadir a un valor de cadena. Este array de bytes puede contener caracteres nulos incrustados a menos que numChars sea negativo. (Las aplicaciones que necesiten caracteres nulos deben representarlos como la secuencia de dos bytes \300\200, usar Tcl_ExternalToUtf para convertir, o Tcl_NewByteArrayObj si la cadena es una colección de bytes no interpretados).
int length (in)
El número de bytes a copiar de bytes al inicializar, establecer o añadir un valor de cadena. Si es negativo, se usan todos los bytes hasta el primer nulo.
const Tcl_UniChar *unicode (in)
Punta al primer byte de un array de caracteres Unicode utilizados para establecer o añadir a un valor de cadena. Este array de bytes puede contener caracteres nulos incrustados a menos que numChars sea negativo.
int numChars (in)
El número de caracteres Unicode a copiar de unicode al inicializar, establecer o añadir un valor de cadena. Si es negativo, se usan todos los caracteres hasta el primer carácter nulo.
int index (in)
El índice del carácter Unicode a devolver.
int first (in)
El índice del primer carácter Unicode en el rango Unicode a devolver como un nuevo valor.
int last (in)
El índice del último carácter Unicode en el rango Unicode a devolver como un nuevo valor.
Tcl_Obj *objPtr (in/out)
Punta a un valor a manipular.
Tcl_Obj *appendObjPtr (in)
El valor a añadir a objPtr en Tcl_AppendObjToObj.
int *lengthPtr (out)
Si no es NULL, la ubicación donde Tcl_GetStringFromObj almacenará la longitud de la representación en cadena del valor.
const char *string (in)
Valor de cadena terminado en nulo a añadir a objPtr.
va_list argList (in)
Una lista de argumentos que debe haber sido inicializada con va_start y limpiada con va_end.
int limit (in)
Número máximo de bytes a añadir.
const char *ellipsis (in)
Sufijo a añadir cuando el límite provoca la truncación de la cadena. Si se pasa NULL, se usa el sufijo “...”.
const char *format (in)
Cadena de control de formato que incluye especificadores de conversión %.
int objc (in)
El número de elementos a formatear o concatenar.
Tcl_Obj *objv[] (in)
El array de valores a formatear o concatenar.
int newLength (in)
Nueva longitud para el valor de cadena de objPtr, sin incluir el carácter nulo final.

DESCRIPCIÓN

Los procedimientos descritos en esta entrada del manual permiten que los valores Tcl se manipulen como valores de cadena. Utilizan la representación interna del valor para almacenar información adicional y hacer que las manipulaciones de cadenas sean más eficientes. En particular, hacen que una serie de operaciones de adición sean eficientes al asignar espacio de almacenamiento adicional para la cadena, de modo que no tenga que copiarse en cada adición. Además, los cálculos de indexación y longitud se optimizan porque la representación de cadena Unicode se calcula y almacena en caché según sea necesario. Al utilizar la familia de funciones Tcl_Append* donde el resultado del intérprete es el valor que se está añadiendo, es importante llamar a Tcl_ResetResult primero para asegurarse de que no se está añadiendo de forma no intencionada a datos existentes en el valor resultante.

Tcl_NewStringObj y Tcl_SetStringObj crean un nuevo valor o modifican un valor existente para que contenga una copia de la cadena proporcionada por bytes y length. Tcl_NewUnicodeObj y Tcl_SetUnicodeObj crean un nuevo valor o modifican un valor existente para que contenga una copia de la cadena Unicode proporcionada por unicode y numChars. Tcl_NewStringObj y Tcl_NewUnicodeObj devuelven un puntero a un valor recién creado con contador de referencias cero. Los cuatro procedimientos establecen el valor para que contenga una copia de la cadena especificada. Tcl_SetStringObj y Tcl_SetUnicodeObj liberan cualquier representación de cadena antigua, así como cualquier representación interna antigua del valor.

Tcl_GetStringFromObj y Tcl_GetString devuelven la representación en cadena de un valor. Esta viene dada por el puntero devuelto y (para Tcl_GetStringFromObj) la longitud, que se almacena en lengthPtr si no es NULL. Si la representación en cadena UTF del valor es inválida (su puntero de bytes es NULL), la representación en cadena se regenera a partir de la representación interna del valor. El almacenamiento referenciado por el puntero devuelto es propiedad del gestor de valores. Se devuelve como un puntero escribible para que el autor de extensiones que cree su propio Tcl_ObjType pueda modificar la representación en cadena dentro del Tcl_UpdateStringProc de su Tcl_ObjType. Excepto para ese propósito limitado, el puntero devuelto por Tcl_GetStringFromObj o Tcl_GetString debe tratarse como de solo lectura. Se recomienda que este puntero se asigne a una variable (const char *). Incluso en las situaciones limitadas donde escribir en este puntero es aceptable, se debe tener cuidado de respetar las semánticas de copia en escritura requeridas por los Tcl_Obj, con llamadas apropiadas a Tcl_IsShared y Tcl_DuplicateObj antes de cualquier modificación en el lugar de la representación en cadena. El procedimiento Tcl_GetString se utiliza en el caso común en el que el llamador no necesita la longitud de la representación de la cadena.

Tcl_GetUnicodeFromObj y Tcl_GetUnicode devuelven el valor de un valor como una cadena Unicode. Esto viene dado por el puntero devuelto y (para Tcl_GetUnicodeFromObj) la longitud, que se almacena en lengthPtr si no es NULL. El almacenamiento referenciado por el puntero devuelto es propiedad del gestor de valores y el llamador no debe modificarlo. El procedimiento Tcl_GetUnicode se utiliza en el caso común en el que el llamador no necesita la longitud de la representación de la cadena Unicode.

Tcl_GetUniChar devuelve el carácter index en la representación Unicode del valor. Se supone que el índice está en el rango apropiado.

Tcl_GetRange devuelve un valor recién creado compuesto por los caracteres entre first y last (inclusive) en la representación Unicode del valor. Si la representación Unicode del valor es inválida, la representación Unicode se regenera a partir de la representación en cadena del valor. Si first < 0, la cadena devuelta comienza al principio del valor. Si last < 0, la cadena devuelta termina al final del valor.

DESCRIPCIÓN

El valor de un objeto Tcl puede tener una representación de cadena y una representación Unicode. Estas funciones proporcionan formas de construir o modificar estas representaciones.

Tcl_GetStringFromObj devuelve un puntero a la representación de cadena del valor del objeto especificado por objPtr. La llamada devuelve el número de bytes en la cadena. La longitud se devuelve en *longitudPtr si este es no NULL. Si el objeto no tiene actualmente una representación de cadena válida, se creará una. Si el valor de longitud es lo suficientemente grande, se puede utilizar `bytesPtr` para devolver un puntero a los bytes de la cadena, y `longitudPtr` para devolver su longitud. Esto puede ser usado para evitar copias si el objeto ya está en el formato deseado.

Tcl_SetObjLength cambia la longitud de la representación de cadena del valor de objPtr. Si newLength es mayor que el espacio asignado, se reasigna el espacio y se copia el valor antiguo. Los bytes entre la longitud antigua y la nueva pueden tener valores arbitrarios. Si newLength es menor que la longitud actual, solo se reduce la longitud del objeto, sin reasignar el espacio. En todos los casos, se añade un carácter nulo al final de la nueva longitud.

Tcl_AttemptSetObjLength es idéntica a Tcl_SetObjLength excepto que si no hay suficiente memoria para satisfacer la petición, no causa que el intérprete Tcl entre en pánico. Devuelve 1 si tiene éxito y 0 si falla por falta de memoria.

Tcl_AppendToObj añade los datos dados por bytes y length a la representación de cadena del valor especificado por objPtr. Si el valor tiene una representación de cadena inválida, se intenta convertir bytes al formato Unicode. Si la conversión tiene éxito, se añade la forma convertida de bytes a la representación Unicode del valor. De lo contrario, se invalida la representación Unicode del valor, se convierte al formato UTF y se añaden bytes a la nueva representación de cadena del valor. Las reasignaciones de memoria se hacen con grandes asignaciones para optimizar múltiples llamadas.

Tcl_AppendUnicodeToObj añade la cadena Unicode dada por unicode y numChars al valor especificado por objPtr. Si el valor tiene una representación Unicode inválida, unicode se convierte al formato UTF y se añade a la representación de cadena del valor. Las adiciones se optimizan para manejar adiciones repetidas de manera relativamente eficiente (sobreasigna el espacio de cadena o Unicode para evitar reasignaciones y copias repetidas del valor de cadena del valor).

Tcl_AppendObjToObj es similar a Tcl_AppendToObj, pero añade el valor de cadena o Unicode (el que exista y sea más adecuado para añadir a objPtr) de appendObjPtr a objPtr.

Tcl_AppendStringsToObj es similar a Tcl_AppendToObj excepto que puede recibir más de un valor para añadir, y cada valor debe ser una cadena terminada en nulo (es decir, ninguno de los valores puede contener caracteres nulos internos). Se puede proporcionar cualquier número de argumentos string, pero el último argumento debe ser (char *)NULL para indicar el final de la lista.

Tcl_AppendStringsToObjVA es lo mismo que Tcl_AppendStringsToObj excepto que en lugar de tomar un número variable de argumentos, toma una lista de argumentos.

Tcl_AppendLimitedToObj es similar a Tcl_AppendToObj excepto que impone un límite en cuántos bytes se añaden. Esto puede ser útil cuando la cadena a añadir puede ser muy grande, pero no se debe permitir que el valor que se está construyendo crezca sin límite. Un uso común es al construir un mensaje de error, donde el resultado final debe mantenerse lo suficientemente corto como para ser leído. Se añaden bytes de bytes a objPtr, pero no más de limit bytes en total. Si el límite impide que se añadan los length bytes disponibles, la adición se realiza de manera que los últimos bytes añadidos provienen de la cadena ellipsis. Esto permite dejar una indicación de la truncación en la cadena. Cuando length es -1, se añaden todos los bytes hasta el primer byte nulo, sujeto al límite. Cuando ellipsis es NULL, se usa la cadena predeterminada .... Cuando ellipsis no es NULL, debe apuntar a una cadena terminada en nulo en la codificación interna UTF de Tcl. El número de bytes añadidos puede ser menor que el menor de length y limit cuando es necesario añadir menos bytes para añadir solo caracteres multibyte completos.

Tcl_Format es la interfaz de nivel C del motor del comando format. El procedimiento de comando real para format es poco más que

Tcl_Format(interp, Tcl_GetString(objv[1]), objc-2, objv+2);

Los valores de objeto Tcl objc en objv se formatean en una cadena según la especificación de conversión en el argumento format, siguiendo la documentación del comando format. La cadena formateada resultante se convierte en un nuevo Tcl_Obj con un contador de referencias de cero y se devuelve. Si ocurre algún error durante la producción de la cadena formateada, se devuelve NULL y se registra un mensaje de error en interp, si interp no es NULL.

Tcl_AppendFormatToObj es una forma de adición alternativa de Tcl_Format con funcionalidad equivalente a:

Tcl_Obj *newPtr = Tcl_Format(interp, format, objc, objv);
if (newPtr == NULL) return TCL_ERROR;
Tcl_AppendObjToObj(objPtr, newPtr);
Tcl_DecrRefCount(newPtr);
return TCL_OK;

pero con mayor conveniencia y eficiencia cuando se necesita la funcionalidad de adición.

Tcl_ObjPrintf sirve como reemplazo para la secuencia común

char buf[SOME_SUITABLE_LENGTH];
sprintf(buf, format, ...);
Tcl_NewStringObj(buf, -1);

pero con mayor conveniencia y sin necesidad de determinar SOME_SUITABLE_LENGTH. El formateo se realiza con el mismo motor de formateo central utilizado por Tcl_Format. Esto significa que el conjunto de especificadores de conversión soportados es el del comando format, pero el comportamiento es lo más similar posible a sprintf. Los especificadores de formato añadidos por C99 (como "hh", "ll", "j", "z", "t", "L") no son compatibles. Cuando un especificador de conversión pasado a Tcl_ObjPrintf incluye una precisión, el valor se toma como un número de bytes, como hace sprintf, y no como un número de caracteres, como hace format. Esto se hace asumiendo que el código C tiene más probabilidades de saber cuántos bytes está manejando que el número de caracteres codificados que esos bytes representan. Los argumentos de número variable pasados deben ser de los tipos que serían adecuados para pasar a sprintf. Tenga en cuenta en este ejemplo de uso, x es de tipo int.

int x = 5;
Tcl_Obj *objPtr = Tcl_ObjPrintf("Value is %d", x);

Si el valor de format contiene inconsistencias internas o formatos de especificador inválidos, la cadena de resultado formateada producida por Tcl_ObjPrintf será un mensaje de error que describe el error. Sin embargo, es imposible proporcionar protección en tiempo de ejecución contra incompatibilidades entre el formato y cualquier argumento posterior. Algunos compiladores pueden proporcionar protección en tiempo de compilación.

Tcl_AppendPrintfToObj es una forma de adición alternativa de Tcl_ObjPrintf con funcionalidad equivalente a

Tcl_Obj *newPtr = Tcl_ObjPrintf(format, ...);
Tcl_AppendObjToObj(objPtr, newPtr);
Tcl_DecrRefCount(newPtr);

pero con mayor conveniencia y eficiencia cuando se necesita la funcionalidad de adición.

El procedimiento Tcl_ConcatObj devuelve un nuevo valor de cadena cuyo valor es la concatenación separada por espacios de las representaciones de cadena de todos los valores en el array objv. Tcl_ConcatObj elimina los espacios en blanco iniciales y finales al copiar las representaciones de cadena del array objv al resultado. Si un elemento del array objv consiste únicamente en espacios en blanco, ese valor se ignora por completo. Esta eliminación de espacios en blanco se añadió para que la salida del comando concat tuviera un aspecto más limpio. Tcl_ConcatObj devuelve un puntero a un valor recién creado con un contador de referencias de cero.
