DESCRIPCIÓN

Un método es una operación que se lleva a cabo en un objeto y que está asociada con el objeto. Cada método debe estar adjunto a un objeto o a una clase; los métodos adjuntos a una clase se asocian con todas las instancias (directas e indirectas) de esa clase.

Dado un método, la entidad que lo declaró se puede encontrar utilizando Tcl_MethodDeclarerClass, que devuelve la clase a la que está adjunto el método (o NULL si el método no está adjunto a ninguna clase), y Tcl_MethodDeclarerObject, que devuelve el objeto al que está adjunto el método (o NULL si el método no está adjunto a un objeto). El nombre del método se puede recuperar con Tcl_MethodName y si el método está exportado se recupera con Tcl_MethodIsPublic. El tipo del método también se puede introspeccionar hasta un grado limitado; la función Tcl_MethodIsType devuelve si un método es de un tipo particular, asignando el clientData por método a la variable apuntada por clientDataPtr si (que no sea NULL) si el tipo coincide.

CREACIÓN DE MÉTODOS

Los métodos se crean mediante Tcl_NewMethod y Tcl_NewInstanceMethod, que crean un método adjunto a una clase o a un objeto respectivamente. En ambos casos, el argumento nameObj proporciona el nombre del método a crear, el argumento isPublic indica si el método debe exportarse inicialmente, el argumento methodTypePtr describe la implementación del método (ver la sección TIPOS DE MÉTODOS más abajo) y el argumento clientData proporciona algunos datos específicos de la implementación que se pasan a la implementación del método cuando se llama.

Cuando el argumento nameObj de Tcl_NewMethod es NULL, se crea un método sin nombre, que se utiliza para constructores y destructores. Los constructores deben instalarse en su clase utilizando la función Tcl_ClassSetConstructor, y los destructores (que no deben requerir ningún argumento) deben instalarse en su clase utilizando la función Tcl_ClassSetDestructor. Los métodos sin nombre no deben utilizarse para ningún otro propósito, y los métodos con nombre no deben utilizarse como constructores ni destructores. Tenga en cuenta también que un methodTypePtr NULL se utiliza para proporcionar señalización interna y no debe utilizarse en el código del cliente.

CONTEXTOS DE LLAMADA A MÉTODOS

Cuando se llama a un método, se pasa una referencia de contexto de llamada a método como uno de los argumentos a la función de implementación. Este contexto se puede inspeccionar para proporcionar información sobre el llamador, pero no debe conservarse más allá del momento en que finaliza la llamada al método.

El método que se está llamando se puede recuperar del contexto utilizando Tcl_ObjectContextMethod, y el objeto que provocó la invocación del método se puede recuperar con Tcl_ObjectContextObject. El número de argumentos que se omitirán (por ejemplo, el nombre del objeto y el nombre del método en una llamada a método normal) se lee con Tcl_ObjectContextSkippedArgs, y el contexto también puede informar si está funcionando como un filtro para otro método a través de Tcl_ObjectContextIsFiltering.

Durante la ejecución de un método, la implementación del método puede optar por invocar las etapas de la cadena de llamadas a métodos que vienen después de la implementación del método actual. Esto (el núcleo del comando next) se hace utilizando Tcl_ObjectContextInvokeNext. Tenga en cuenta que esta función no manipula la pila de marcos de llamada, a diferencia del comando next; si la implementación del método ha insertado uno o más marcos adicionales en la pila como parte de su implementación, también es responsable de extraer temporalmente esos marcos de la pila mientras se ejecuta la función Tcl_ObjectContextInvokeNext. Tenga en cuenta también que el contexto de llamada a método nunca se elimina durante la ejecución de esta función.

TIPOS DE MÉTODOS

Los tipos de métodos se describen mediante un puntero a una estructura Tcl_MethodType, que se define como:

typedef struct {
    int version;
    const char *name;
    Tcl_MethodCallProc *callProc;
    Tcl_MethodDeleteProc *deleteProc;
    Tcl_CloneProc *cloneProc;
} Tcl_MethodType;

El campo version permite la expansión futura de la estructura y siempre debe declararse igual a TCL_OO_METHOD_VERSION_CURRENT. El campo name proporciona un nombre legible por humanos para el tipo y es el valor que se expone a través de los comandos de Tcl info class methodtype e info object methodtype.

El campo callProc proporciona una función que se llama cuando se invoca el método; nunca debe ser NULL.

El campo deleteProc proporciona una función que se utiliza para eliminar un método en particular y se llama cuando el método se reemplaza o elimina; si el campo es NULL, se asume que el clientData del método no necesita ninguna acción especial para eliminarlo.

El campo cloneProc es una función que se utiliza para copiar el clientData de un método (como parte de Tcl_CopyObjectInstance) o NULL para indicar que el clientData se puede copiar directamente.

FIRMA DE LA FUNCIÓN Tcl_MethodCallProc

La firma de la función que se pasa en el campo callProc de Tcl_MethodType es:

typedef int (*Tcl_MethodCallProc)(
    Tcl_Interp *interp,
    const Tcl_Method *method,
    Tcl_Object object,
    int objc,
    Tcl_Obj *const *objv
);

Cada vez que se llama al método, la función callProc se invoca con el intérprete, una referencia al método que se está llamando, el objeto para el que se está invocando el método, el número de argumentos y una matriz de los argumentos.

Si la función se ejecuta correctamente, debe devolver TCL_OK y el valor de retorno de la función debe ser el resultado del comando, si lo hubiera.

Si la función falla, debe establecer el nivel de error apropiado en el intérprete y devolver TCL_ERROR.

Si se llama a la función desde el código C, se espera que devuelva un código de retorno estándar de Tcl.

FIRMA DE LA FUNCIÓN Tcl_MethodDeleteProc

La firma de la función que se pasa en el campo deleteProc de Tcl_MethodType es:

typedef void (*Tcl_MethodDeleteProc)(
    ClientData clientData
);

Esta función se llama cuando el método se elimina o se reemplaza, y se le pasa el clientData que se asoció con el método cuando se creó.

FIRMA DE LA FUNCIÓN Tcl_CloneProc

La firma de la función que se pasa en el campo cloneProc de Tcl_MethodType es:

typedef ClientData (*Tcl_CloneProc)(
    ClientData clientData
);

Esta función se llama cuando se copia un objeto que tiene métodos, y se le pasa el clientData asociado con el método que se está clonando. Debe devolver un puntero a una copia del clientData.

VER TAMBIÉN

TclOO, Tcl_NewClass, Tcl_NewObject

SIGNATURA DE FUNCIÓN TCL_METHODCALLPROC

Las funciones que coinciden con esta firma se llaman cuando se invoca el método.

typedef int Tcl_MethodCallProc(
        ClientData clientData,
        Tcl_Interp *interp,
        Tcl_ObjectContext objectContext,
        int objc,
        Tcl_Obj *const *objv);

El argumento clientData de un Tcl_MethodCallProc es el valor que se proporcionó cuando se creó el método, interp es un lugar para ejecutar scripts y acceder a variables, además de ser donde se coloca el resultado del método, y los campos objc y objv proporcionan los objetos de parámetro al método. El contexto de llamada del método se puede descubrir a través del argumento objectContext, y el valor de retorno de un Tcl_MethodCallProc es cualquier código de retorno de Tcl (por ejemplo, TCL_OK, TCL_ERROR).

SIGNATURA DE FUNCIÓN TCL_METHODDELETEPROC

Las funciones que coinciden con esta firma se utilizan cuando se elimina un método, ya sea porque se crea un nuevo método o porque se elimina el objeto o la clase.

typedef void Tcl_MethodDeleteProc(
        ClientData clientData);

El argumento clientData de un Tcl_MethodDeleteProc será el mismo que el valor pasado al argumento clientData de Tcl_NewMethod o Tcl_NewInstanceMethod cuando se creó el método.

SIGNATURA DE FUNCIÓN TCL_CLONEPROC

Las funciones que coinciden con esta firma se utilizan para copiar un método cuando el objeto o la clase se copian usando Tcl_CopyObjectInstance (o oo::copy).

typedef int Tcl_CloneProc(
        Tcl_Interp *interp,
        ClientData oldClientData,
        ClientData *newClientDataPtr);

El argumento interp proporciona un lugar para escribir un mensaje de error cuando el intento de clonar el objeto falla, en cuyo caso el procedimiento de clonación también debe devolver TCL_ERROR; de lo contrario, debe devolver TCL_OK. El campo oldClientData de un Tcl_CloneProc proporciona el valor del método que se está copiando, y el campo newClientDataPtr apuntará a una variable en la que escribir el valor del método al que se está copiando.
