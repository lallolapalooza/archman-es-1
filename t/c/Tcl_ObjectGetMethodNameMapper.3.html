DESCRIPCIÓN

Los objetos son entidades tipadas que tienen un conjunto de operaciones ("métodos") asociadas a ellas. Las clases son objetos que pueden fabricar objetos. Cada clase puede ser vista como un objeto en sí misma; la vista de objeto se puede obtener usando Tcl_GetClassAsObject que siempre devuelve el objeto cuando se aplica a una clase no destruida, y un objeto puede ser visto como una clase con la ayuda de Tcl_GetObjectAsClass (que devuelve la clase o NULL si el objeto no es una clase). Un objeto puede ser buscado usando la función Tcl_GetObjectFromObj, que devuelve un objeto o NULL (con un mensaje de error en el resultado del intérprete) si el objeto no puede ser encontrado. La forma correcta de buscar una clase por nombre es buscar el objeto con ese nombre y luego usar Tcl_GetObjectAsClass.

Cada objeto tiene su propio comando y espacio de nombres asociado. El comando se puede obtener usando la función Tcl_GetObjectCommand, el nombre del objeto (y por lo tanto el nombre del comando) con Tcl_GetObjectName, y el espacio de nombres se puede obtener usando la función Tcl_GetObjectNamespace. Tenga en cuenta que la referencia Tcl_Obj devuelta por Tcl_GetObjectName es una referencia compartida. También puede obtener si el objeto ha sido marcado para su eliminación con Tcl_ObjectDeleted (devuelve verdadero si la eliminación del objeto ha comenzado); esto puede ser útil durante el procesamiento de métodos.

Las instancias de clases se crean usando Tcl_NewObjectInstance, que crea un objeto a partir de cualquier clase (y que es llamado internamente tanto por los métodos create como new de la clase oo::class). Toma parámetros que opcionalmente dan el nombre del objeto y el espacio de nombres a crear, y que describen los argumentos a pasar al constructor de la clase (si lo hay). El resultado de la función será una referencia al objeto recién creado, o NULL si la creación falló (cuando se dejará un mensaje de error en el resultado del intérprete). Además, los objetos pueden ser copiados usando Tcl_CopyObjectInstance que crea una copia de un objeto sin ejecutar ningún constructor.

Tenga en cuenta que la gestión del ciclo de vida de los objetos es manejada internamente dentro de TclOO y no utiliza Tcl_Preserve. *No es seguro colocar un manejador* Tcl_Object en una estructura C con una vida útil diferente a la del objeto; debe usar el nombre del comando del objeto (obtenido con Tcl_GetObjectName) en su lugar. Es seguro utilizar un manejador Tcl_Object durante la vida útil de una llamada a un método sobre ese objeto; los manejadores no se vuelven inválidos mientras haya una llamada pendiente en su objeto (incluso si la única operación que garantiza ser segura sobre ellos es Tcl_ObjectDeleted; las otras operaciones solo se garantizan que funcionen en objetos no eliminados).

METADATOS DE OBJETOS Y CLASES

Cada objeto y cada clase pueden tener cantidades arbitrarias de metadata adjunta, a la que el objeto o la clase no atribuyen ningún significado más allá de lo descrito en una instancia de estructura Tcl_ObjectMetadataType. La metadata a adjuntar se describe por el tipo de la metadata (dado en el argumento metaTypePtr) y un puntero arbitrario (el argumento metadata) que se pasan a Tcl_ObjectSetMetadata y Tcl_ClassSetMetadata, y una pieza particular de metadata puede ser recuperada dado su tipo usando Tcl_ObjectGetMetadata y Tcl_ClassGetMetadata. Si el parámetro metadata para Tcl_ObjectSetMetadata o Tcl_ClassSetMetadata es NULL, la metadata se elimina si estaba adjunta, y los resultados de Tcl_ObjectGetMetadata y Tcl_ClassGetMetadata son NULL si el tipo de metadata dado no estaba adjunto. No es un error solicitar o eliminar una pieza de metadata que no estaba adjunta.

ESTRUCTURA TCL_OBJECTMETADATATYPE

El contenido de la estructura Tcl_ObjectMetadataType es el siguiente:

typedef const struct {
    int version;
    const char *name;
    Tcl_ObjectMetadataDeleteProc *deleteProc;
    Tcl_CloneProc *cloneProc;
} Tcl_ObjectMetadataType;

El campo version permite la expansión futura de la estructura y siempre debe declararse igual a TCL_OO_METADATA_VERSION_CURRENT. El campo name proporciona un nombre legible por humanos para el tipo y está reservado para depuración.

El campo deleteProc proporciona una función del tipo Tcl_ObjectMetadataDeleteProc que se utiliza para eliminar una pieza de metadata particular y se llama cuando la metadata adjunta se reemplaza o elimina; el campo no debe ser NULL.

El campo cloneProc proporciona una función que se utiliza para copiar una pieza de metadata (utilizada cuando se crea una copia de un objeto usando Tcl_CopyObjectInstance); si es NULL, la metadata se copiará directamente.

FIRMA DE LA FUNCIÓN TCL_OBJECTMETADATADELETEPROC

Las funciones que coinciden con esta firma se utilizan para eliminar metadata asociada con una clase u objeto.

Tcl_ObjectGetMethodNameMapper(3) - Arch Linux

NAME

Tcl_ObjectGetMethodNameMapper, Tcl_ObjectSetMethodNameMapper - query and set object method name mapper callbacks

SYNOPSIS

#include <tclOO.h>

typedef int (*
Tcl_ObjectMapMethodNameProc)(
        Tcl_Interp *interp,
        Tcl_Object object,
        Tcl_Class *startClsPtr,
        Tcl_Obj *methodNameObj);

void
Tcl_ObjectSetMethodNameMapper(
        Tcl_Object object,
        Tcl_ObjectMapMethodNameProc *mapper,
        ClientData mapperData,
        Tcl_ObjectMetadataDeleteProc *deleteProc);

int
Tcl_ObjectGetMethodNameMapper(
        Tcl_Object object,
        Tcl_ObjectMapMethodNameProc **mapperPtr,
        ClientData *mapperDataPtr);

ARGUMENTS

ClientData
The type of data that is associated with a callback, for passing arbitrary context to it.

The type of data that is associated with a callback, for passing arbitrary context to it.

deleteProc
A pointer to a callback used to free callback data when it is no longer needed.
interp
The interpreter context in which to operate.
mapper
The method name mapper callback to register.
mapperData
The callback data to associate with the mapper.
mapperDataPtr
A pointer to a location where the callback data associated with the current mapper will be written.
mapperPtr
A pointer to a location where the method name mapper callback will be written.
methodNameObj
A Tcl value object representing the name of the method being invoked.
object
The object whose method name mapper is to be queried or set.
startClsPtr
A pointer to the class from which to start searching for method implementations.

DESCRIPTION

The TclOO object system provides a default mechanism for mapping method names to method implementations. This involves looking up the method name in the object and then proceeding up the class hierarchy. However, it is possible to override this default behavior on a per-object basis using a method name mapper callback.

A method name mapper is a callback function that is invoked just before the default method lookup mechanism begins. The mapper is given the method name and has the opportunity to modify it, or to directly find and execute a method implementation, or to perform some other custom logic.

The Tcl_ObjectSetMethodNameMapper function registers a method name mapper callback, mapper, for the given object. The mapperData argument is arbitrary client data that will be passed to the mapper whenever it is invoked. The deleteProc argument is a callback function that will be invoked to free mapperData when the mapper is no longer needed (e.g., when the object is destroyed or a new mapper is set). If deleteProc is NULL, then no cleanup action is performed.

The Tcl_ObjectGetMethodNameMapper function retrieves the current method name mapper for object and writes it into the location pointed to by mapperPtr. It also retrieves the associated client data and writes it into the location pointed to by mapperDataPtr. If no mapper is currently set for the object, then *mapperPtr will be set to NULL and *mapperDataPtr will be set to NULL.

A method name mapper callback has the signature Tcl_ObjectMapMethodNameProc. It is invoked with the interpreter, the object, the class from which to start the search (or NULL if the mapper wants to ignore the class hierarchy and handle the lookup entirely itself), and an unshared Tcl object containing the method name.

The mapper should return TCL_OK if it has completed its work. If it returns TCL_OK, it may have modified the methodNameObj passed to it; this modified name will then be used by the default lookup mechanism. If the mapper wishes to bypass the default lookup mechanism entirely and perform its own method dispatch, it should return TCL_OK and ensure that the *methodNameObj argument is NULL.

If the mapper wishes to indicate an error, it should leave an error message in the interpreter and return TCL_ERROR. The method invocation will then fail.

If the mapper returns TCL_BREAK, the default method lookup rules will be used without modification.

The initial method name mapper for an object is NULL. This means that by default, the standard method lookup mechanism is always used.

TCL_OBJECTMETADATADELETEPROC FUNCTION SIGNATURE

The callback used to free metadata associated with an object or class is defined as follows:

typedef void Tcl_ObjectMetadataDeleteProc(
        ClientData metadata);

The metadata argument gives the address of the metadata to be deleted.

TCL_CLONEPROC FUNCTION SIGNATURE

Functions matching this signature are used to create copies of metadata associated with a class or object.

typedef int Tcl_CloneProc(
        Tcl_Interp *interp,
        ClientData srcMetadata,
        ClientData *dstMetadataPtr);

The interp argument gives a place to write an error message when the attempt to clone the object is to fail, in which case the clone procedure must also return TCL_ERROR; it should return TCL_OK otherwise. The srcMetadata argument gives the address of the metadata to be cloned, and the cloned metadata should be written into the variable pointed to by dstMetadataPtr; a NULL should be written if the metadata is to not be cloned but the overall object copy operation is still to succeed.

OBJECT METHOD NAME MAPPING

It is possible to control, on a per-object basis, what methods are invoked when a particular method is invoked. Normally this is done by looking up the method name in the object and then in the class hierarchy, but fine control of exactly what the value used to perform the look up is afforded through the ability to set a method name mapper callback via Tcl_ObjectSetMethodNameMapper (and its introspection counterpart, Tcl_ObjectGetMethodNameMapper, which returns the current mapper). The current mapper (if any) is invoked immediately before looking up what chain of method implementations is to be used.

TCL_OBJECTMAPMETHODNAMEPROC FUNCTION SIGNATURE

The Tcl_ObjectMapMethodNameProc callback is defined as follows:

typedef int Tcl_ObjectMapMethodNameProc(
        Tcl_Interp *interp,
        Tcl_Object object,
        Tcl_Class *startClsPtr,
        Tcl_Obj *methodNameObj);

If the result is TCL_OK, the remapping is assumed to have been done. If the result is TCL_ERROR, an error message will have been left in interp and the method call will fail. If the result is TCL_BREAK, the standard method name lookup rules will be used; the behavior of other result codes is currently undefined. The object parameter says which object is being processed. The startClsPtr parameter points to a variable that contains the first class to provide a definition in the method chain to process, or NULL if the whole chain is to be processed (the argument itself is never NULL); this variable may be updated by the callback. The methodNameObj parameter gives an unshared object containing the name of the method being invoked, as provided by the user; this object may be updated by the callback.
