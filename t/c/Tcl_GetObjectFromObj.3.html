El nombre del espacio de nombres a crear para uso privado del objeto, o NULL si se va a seleccionar automáticamente un nuevo nombre no utilizado. El espacio de nombres no debe existir previamente.

El número de elementos en la matriz objv.

Los argumentos del comando para crear la instancia de la clase.

El número de argumentos al principio de la matriz de argumentos, objv, que no son argumentos para ningún constructor. Esto permite la generación de mensajes de error correctos incluso cuando se utilizan patrones de llamada complicados (por ejemplo, a través del comando next).

Un puntero a una función que se llamará para ajustar el mapeo de objetos y nombres de métodos a implementaciones, o NULL cuando no se requiere dicho mapeo.

DESCRIPCIÓN

Los objetos son entidades tipificadas que tienen un conjunto de operaciones ("métodos") asociadas a ellas. Las clases son objetos que pueden fabricar objetos. Cada clase puede ser vista como un objeto en sí misma; la vista de objeto se puede recuperar usando Tcl_GetClassAsObject que siempre devuelve el objeto cuando se aplica a una clase no destruida, y un objeto puede ser visto como una clase con la ayuda de Tcl_GetObjectAsClass (que devuelve la clase o NULL si el objeto no es una clase). Un objeto puede ser buscado usando la función Tcl_GetObjectFromObj, que devuelve un objeto o NULL (con un mensaje de error en el resultado del intérprete) si el objeto no se puede encontrar. La forma correcta de buscar una clase por nombre es buscar el objeto con ese nombre, y luego usar Tcl_GetObjectAsClass.

Cada objeto tiene su propio comando y espacio de nombres asociados. El comando se puede recuperar usando la función Tcl_GetObjectCommand, el nombre del objeto (y por lo tanto el nombre del comando) con Tcl_GetObjectName, y el espacio de nombres se puede recuperar usando la función Tcl_GetObjectNamespace. Tenga en cuenta que la referencia Tcl_Obj devuelta por Tcl_GetObjectName es una referencia compartida. También puede obtener si el objeto ha sido marcado para eliminación con Tcl_ObjectDeleted (devuelve verdadero si la eliminación del objeto ha comenzado); esto puede ser útil durante el procesamiento de métodos.

Las instancias de clases se crean usando Tcl_NewObjectInstance, que crea un objeto de cualquier clase (y que es llamado internamente por los métodos create y new de la clase oo::class). Toma parámetros que opcionalmente dan el nombre del objeto y el espacio de nombres a crear, y que describen los argumentos a pasar al constructor de la clase (si lo hay). El resultado de la función será una referencia al objeto recién creado, o NULL si la creación falló (cuando se dejará un mensaje de error en el resultado del intérprete). Además, los objetos pueden ser copiados usando Tcl_CopyObjectInstance que crea una copia de un objeto sin ejecutar ningún constructor.

Tenga en cuenta que la gestión del ciclo de vida de los objetos se maneja internamente dentro de TclOO, y no utiliza Tcl_Preserve. No es seguro poner un handle de Tcl_Object en una estructura de C con una vida útil diferente a la del objeto; debe usar el nombre del comando del objeto (tal como se recupera con Tcl_GetObjectName) en su lugar. Es seguro usar un handle de Tcl_Object durante la vida útil de una llamada a un método sobre ese objeto; los handles no se invalidan mientras haya una llamada pendiente sobre su objeto (incluso si la única operación garantizada de ser segura sobre ellos es Tcl_ObjectDeleted; las otras operaciones solo están garantizadas para funcionar en objetos no eliminados).

METADATOS DE OBJETOS Y CLASES

Cada objeto y cada clase pueden tener cantidades arbitrarias de metadatos adjuntos, a los que el objeto o la clase no les atribuye ningún significado más allá de lo descrito en una instancia de estructura Tcl_ObjectMetadataType. Los metadatos a adjuntar se describen por el tipo de los metadatos (dado en el argumento metaTypePtr) y un puntero arbitrario (el argumento metadata) que se proporcionan a Tcl_ObjectSetMetadata y Tcl_ClassSetMetadata, y una pieza particular de metadatos se puede recuperar dado su tipo usando Tcl_ObjectGetMetadata y Tcl_ClassGetMetadata. Si el parámetro metadata para Tcl_ObjectSetMetadata o Tcl_ClassSetMetadata es NULL, los metadatos se eliminan si estaban adjuntos, y los resultados de Tcl_ObjectGetMetadata y Tcl_ClassGetMetadata son NULL si el tipo de metadatos dado no estaba adjunto. No es un error solicitar o eliminar una pieza de metadatos que no estaba adjunta.

ESTRUCTURA TCL_OBJECTMETADATATYPE

Los contenidos de la estructura Tcl_ObjectMetadataType son los siguientes:

typedef const struct {
    int version;
    const char *name;
    Tcl_ObjectMetadataDeleteProc *deleteProc;
    Tcl_CloneProc *cloneProc;
} Tcl_ObjectMetadataType;

El campo version permite la expansión futura de la estructura y siempre debe declararse igual a TCL_OO_METADATA_VERSION_CURRENT. El campo name proporciona un nombre legible por humanos para el tipo y está reservado para depuración.

El campo deleteProc proporciona una función del tipo Tcl_ObjectMetadataDeleteProc que se utiliza para eliminar una pieza particular de metadatos y se llama cuando los metadatos adjuntos se reemplazan o eliminan; el campo no debe ser NULL.

El campo cloneProc proporciona una función que se utiliza para copiar una pieza de metadatos (utilizada cuando se crea una copia de un objeto usando Tcl_CopyObjectInstance); si es NULL, los metadatos se copiarán directamente.

TCL_CLONEPROC FIRMA DE FUNCIÓN

Las funciones que coinciden con esta firma se utilizan para crear copias de metadatos asociados con una clase u objeto.

typedef int Tcl_CloneProc(
        Tcl_Interp *interp,
        ClientData srcMetadata,
        ClientData *dstMetadataPtr);

El argumento interp proporciona un lugar para escribir un mensaje de error cuando el intento de clonar el objeto falla, en cuyo caso el procedimiento de clonación también debe devolver TCL_ERROR; de lo contrario, debe devolver TCL_OK. El argumento srcMetadata proporciona la dirección de los metadatos que se van a clonar, y los metadatos clonados deben escribirse en la variable a la que apunta dstMetadataPtr; se debe escribir NULL si los metadatos no se van a clonar pero la operación general de copia del objeto aún debe tener éxito.

ASIGNACIÓN DE NOMBRES DE MÉTODOS DE OBJETOS

Es posible controlar, por objeto, qué métodos se invocan cuando se invoca un método particular. Normalmente, esto se hace buscando el nombre del método en el objeto y luego en la jerarquía de clases, pero el control fino de exactamente qué valor se utiliza para realizar la búsqueda se ofrece a través de la capacidad de establecer una devolución de llamada para asignar nombres de métodos mediante Tcl_ObjectSetMethodNameMapper (y su contraparte de introspección, Tcl_ObjectGetMethodNameMapper, que devuelve el asignador actual). El asignador actual (si lo hay) se invoca inmediatamente antes de buscar qué cadena de implementaciones de métodos se va a utilizar.

TCL_OBJECTMAPMETHODNAMEPROC FIRMA DE FUNCIÓN

La devolución de llamada Tcl_ObjectMapMethodNameProc se define de la siguiente manera:

typedef int Tcl_ObjectMapMethodNameProc(
        Tcl_Interp *interp,
        Tcl_Object object,
        Tcl_Class *startClsPtr,
        Tcl_Obj *methodNameObj);

Si el resultado es TCL_OK, se asume que la reasignación se ha realizado. Si el resultado es TCL_ERROR, se habrá dejado un mensaje de error en interp y la llamada al método fallará. Si el resultado es TCL_BREAK, se utilizarán las reglas de búsqueda de nombres de métodos estándar; el comportamiento de otros códigos de resultado no está definido actualmente. El parámetro object indica qué objeto se está procesando. El parámetro startClsPtr apunta a una variable que contiene la primera clase que proporciona una definición en la cadena de métodos a procesar, o NULL si se va a procesar toda la cadena (el argumento en sí nunca es NULL); esta variable puede ser actualizada por la devolución de llamada. El parámetro methodNameObj proporciona un objeto no compartido que contiene el nombre del método que se está invocando, tal como lo proporciona el usuario; este objeto puede ser actualizado por la devolución de llamada.
