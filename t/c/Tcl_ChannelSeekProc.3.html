DESCRIPCIÓN

Tcl utiliza una arquitectura de canales de dos capas. Proporciona una capa superior genérica para permitir que programas C y Tcl realicen entrada y salida utilizando las mismas APIs para una variedad de archivos, dispositivos, sockets, etc. Las APIs genéricas de C se describen en la entrada del manual para Tcl_OpenFileChannel.

La capa inferior proporciona controladores de canales específicos de tipo para cada tipo de dispositivo soportado en cada plataforma. Esta entrada del manual describe las APIs de C utilizadas para comunicarse entre la capa genérica y los controladores de canales específicos de tipo. También explica cómo se pueden añadir nuevos tipos de canales proporcionando nuevos controladores de canales.

Los controladores de canales consisten en varios componentes: Primero, cada controlador de canales proporciona una estructura Tcl_ChannelType que contiene punteros a funciones que implementan las diversas operaciones utilizadas por la capa genérica para comunicarse con el controlador de canales. La estructura Tcl_ChannelType y las funciones referenciadas por ella se describen en la sección TCL_CHANNELTYPE, más abajo.

Segundo, los controladores de canales suelen proporcionar un comando Tcl para crear instancias de ese tipo de canal. Por ejemplo, el comando Tcl open crea canales que utilizan los controladores de canales de archivo y de comando, y el comando Tcl socket crea canales que utilizan sockets TCP para la comunicación en red.

Tercero, un controlador de canales opcionalmente proporciona una función C para abrir instancias de canal de ese tipo. Por ejemplo, Tcl_OpenFileChannel abre un canal que utiliza el controlador de canales de archivo, y Tcl_OpenTcpClient abre un canal que utiliza el protocolo de red TCP. Estas funciones de creación suelen utilizar Tcl_CreateChannel internamente para abrir el canal.

Para añadir un nuevo tipo de canal, debes implementar una API C o un comando Tcl que abra un canal invocando Tcl_CreateChannel. Cuando tu controlador llame a Tcl_CreateChannel, pasará una estructura Tcl_ChannelType que describe los procedimientos de E/S del controlador. La capa genérica invocará entonces las funciones referenciadas en esa estructura para realizar operaciones en el canal.

Tcl_CreateChannel abre un nuevo canal y asocia el typePtr y instanceData proporcionados con él. El canal se abre en el modo indicado por mask. Para una discusión de los controladores de canales, sus operaciones y la estructura Tcl_ChannelType, ver la sección TCL_CHANNELTYPE, más abajo.

Tcl_CreateChannel interactúa con el código que gestiona los canales estándar. Una vez que se inicializó un canal estándar a través de una llamada a Tcl_GetStdChannel o una llamada a Tcl_SetStdChannel, el cierre de este canal estándar hará que la siguiente llamada a Tcl_CreateChannel convierta también el nuevo canal en el nuevo canal estándar. Ver Tcl_StandardChannels para un tratado general sobre los canales estándar y el comportamiento de la biblioteca Tcl con respecto a ellos.

Tcl_GetChannelInstanceData devuelve los datos de instancia asociados con el canal en channel. Esto es lo mismo que el argumento instanceData en la llamada a Tcl_CreateChannel que creó este canal.

Tcl_GetChannelType devuelve un puntero a la estructura Tcl_ChannelType utilizada por el canal en el argumento channel. Esto es lo mismo que el argumento typePtr en la llamada a Tcl_CreateChannel que creó este canal.

Tcl_GetChannelName devuelve una cadena que contiene el nombre asociado con el canal, o NULL si el argumento channelName de Tcl_CreateChannel era NULL.

TCL_GETCHANNELOPTION

Tcl_GetChannelOption returns the value of a channel-specific option. If the option is not supported by the channel driver, then TCL_ERROR is returned. The option name must be one of the symbols defined by the channel driver. The value of the option is stored in the variable pointed to by valuePtr. The return value is TCL_OK if the option was found and the value stored successfully.

Tcl_GetChannelHandle returns a pointer to the device handle for the specified direction (either TCL_READABLE or TCL_WRITABLE) associated with the channel specified by handlePtr and returns TCL_OK. If the channel does not have a device handle for the specified direction, then TCL_ERROR is returned instead. Different channel drivers will return different types of handle. Refer to the manual entries for each driver to determine what type of handle is returned.

Tcl_GetChannelThread returns the id of the thread currently managing the specified channel. This allows channel drivers to send their file events to the correct event queue even for a multi-threaded core.

Tcl_GetChannelMode returns an OR-ed combination of TCL_READABLE and TCL_WRITABLE, indicating whether the channel is open for input and output.

Tcl_GetChannelBufferSize returns the size, in bytes, of buffers allocated to store input or output in channel. If the value was not set by a previous call to Tcl_SetChannelBufferSize, described below, then the default value of 4096 is returned.

Tcl_SetChannelBufferSize sets the size, in bytes, of buffers that will be allocated in subsequent operations on the channel to store input or output. The size argument should be between one and one million, allowing buffers of one byte to one million bytes. If size is outside this range, Tcl_SetChannelBufferSize sets the buffer size to 4096.

Tcl_NotifyChannel is called by a channel driver to indicate to the generic layer that the events specified by mask have occurred on the channel. Channel drivers are responsible for invoking this function whenever the channel handlers need to be called for the channel (or other pending tasks like a write flush should be performed). See WATCHPROC below for more details.

Tcl_BadChannelOption is called from driver specific setOptionProc or getOptionProc to generate a complete error message.

Tcl_ChannelBuffered returns the number of bytes of input currently buffered in the internal buffer (push back area) of the channel itself. It does not report about the data in the overall buffers for the stack of channels the supplied channel is part of.

Tcl_IsChannelShared checks the refcount of the specified channel and returns whether the channel was shared among multiple interpreters (result == 1) or not (result == 0).

Tcl_IsChannelRegistered checks whether the specified channel is registered in the given interpreter (result == 1) or not (result == 0).

Tcl_IsChannelExisting checks whether a channel with the specified name is registered in the (thread)-global list of all channels (result == 1) or not (result == 0).

Tcl_CutChannel removes the specified channel from the (thread)global list of all channels (of the current thread). Application to a channel still registered in some interpreter is not allowed. Also notifies the driver if the Tcl_ChannelType version is TCL_CHANNEL_VERSION_4 (or higher), and Tcl_DriverThreadActionProc is defined for it.

Tcl_SpliceChannel adds the specified channel to the (thread)global list of all channels (of the current thread). Application to a channel registered in some interpreter is not allowed. Also notifies the driver if the Tcl_ChannelType version is TCL_CHANNEL_VERSION_4 (or higher), and Tcl_DriverThreadActionProc is defined for it.

Tcl_ClearChannelHandlers removes all channel handlers and event scripts associated with the specified channel, thus shutting down all event processing for this channel.

TCL_CHANNELTYPE

Un controlador de canales proporciona una estructura Tcl_ChannelType que contiene punteros a funciones que implementan las diversas operaciones en un canal; estas operaciones se invocan según sea necesario por la capa genérica. La estructura fue versionada a partir de Tcl 8.3.2/8.4 para corregir un problema con los canales apilados. Consulte la sección OLD CHANNEL TYPES más abajo para obtener detalles sobre la estructura antigua.

La estructura Tcl_ChannelType contiene los siguientes campos:

typedef struct Tcl_ChannelType {
        const char *typeName;
        Tcl_ChannelTypeVersion version;
        Tcl_DriverCloseProc *closeProc;
        Tcl_DriverInputProc *inputProc;
        Tcl_DriverOutputProc *outputProc;
        Tcl_DriverSeekProc *seekProc;
        Tcl_DriverSetOptionProc *setOptionProc;
        Tcl_DriverGetOptionProc *getOptionProc;
        Tcl_DriverWatchProc *watchProc;
        Tcl_DriverGetHandleProc *getHandleProc;
        Tcl_DriverClose2Proc *close2Proc;
        Tcl_DriverBlockModeProc *blockModeProc;
        Tcl_DriverFlushProc *flushProc;
        Tcl_DriverHandlerProc *handlerProc;
        Tcl_DriverWideSeekProc *wideSeekProc;
        Tcl_DriverThreadActionProc *threadActionProc;
        Tcl_DriverTruncateProc *truncateProc;
} Tcl_ChannelType;

No es necesario proporcionar implementaciones para todas las operaciones de canal. Aquellas que no sean necesarias pueden establecerse en NULL en la estructura: blockModeProc, seekProc, setOptionProc, getOptionProc, getHandleProc, y close2Proc, además de flushProc, handlerProc, threadActionProc, y truncateProc. Otras funciones que no se puedan implementar de forma significativa deben devolver EINVAL cuando se llamen, para indicar que las operaciones que representan no están disponibles. Tenga en cuenta también que wideSeekProc puede ser NULL si seekProc lo es.

El usuario solo debe utilizar la estructura anterior para la instanciación de Tcl_ChannelType. Al hacer referencia a campos en una estructura Tcl_ChannelType, se deben utilizar las siguientes funciones para obtener los valores: Tcl_ChannelName, Tcl_ChannelVersion, Tcl_ChannelBlockModeProc, Tcl_ChannelCloseProc, Tcl_ChannelClose2Proc, Tcl_ChannelInputProc, Tcl_ChannelOutputProc, Tcl_ChannelSeekProc, Tcl_ChannelWideSeekProc, Tcl_ChannelThreadActionProc, Tcl_ChannelTruncateProc, Tcl_ChannelSetOptionProc, Tcl_ChannelGetOptionProc, Tcl_ChannelWatchProc, Tcl_ChannelGetHandleProc, Tcl_ChannelFlushProc, o Tcl_ChannelHandlerProc.

El cambio en las estructuras se realizó de tal manera que los tipos de canal estándar son compatibles binariamente. Sin embargo, los tipos de canal que utilizan canales apilados (es decir, TLS, Trf) tienen nuevas versiones para corresponder al cambio anterior, ya que el código anterior para canales apilados tenía problemas.

TYPENAME

El campo typeName contiene una cadena terminada en nulo que identifica el tipo de dispositivo implementado por este controlador, por ejemplo, file o socket.

Este valor se puede recuperar con Tcl_ChannelName, que devuelve un puntero a la cadena.

VERSION

El campo version debe establecerse en la versión de la estructura que necesite. TCL_CHANNEL_VERSION_2 es el mínimo recomendado. TCL_CHANNEL_VERSION_3 debe establecerse para especificar el miembro wideSeekProc. TCL_CHANNEL_VERSION_4 debe establecerse para especificar el miembro threadActionProc (incluye wideSeekProc). TCL_CHANNEL_VERSION_5 debe establecerse para especificar los miembros truncateProc (incluye wideSeekProc y threadActionProc). Si no se establece en ninguno de estos, se asume que esta Tcl_ChannelType tiene la estructura original. Consulte OLD CHANNEL TYPES para obtener más detalles. Si bien Tcl reconocerá y funcionará con ambas estructuras, los canales apilados deben ser como mínimo de TCL_CHANNEL_VERSION_2 para funcionar correctamente.

Este valor se puede recuperar con Tcl_ChannelVersion, que devuelve uno de TCL_CHANNEL_VERSION_5, TCL_CHANNEL_VERSION_4, TCL_CHANNEL_VERSION_3, TCL_CHANNEL_VERSION_2 o TCL_CHANNEL_VERSION_1.

BLOCKMODEPROC

El campo blockModeProc contiene la dirección de una función llamada por la capa genérica para establecer el modo de bloqueo y no bloqueo en el dispositivo. BlockModeProc debe coincidir con el siguiente prototipo:

typedef int Tcl_DriverBlockModeProc(
        ClientData instanceData,
        int mode);

El instanceData es el mismo que el valor pasado a Tcl_CreateChannel cuando se creó este canal. El argumento mode es TCL_MODE_BLOCKING o TCL_MODE_NONBLOCKING para establecer el dispositivo en modo de bloqueo o no bloqueo. La función debe devolver cero si la operación fue exitosa, o un código de error POSIX distinto de cero si la operación falló.

Si la operación es exitosa, la función puede modificar el instanceData proporcionado para registrar que el canal entró en modo de bloqueo o no bloqueo y para implementar el comportamiento de bloqueo o no bloqueo. Para algunos tipos de dispositivos, el comportamiento de bloqueo y no bloqueo puede ser implementado por el sistema operativo subyacente; para otros tipos de dispositivos, el comportamiento debe ser emulado en el controlador de canal.

Este valor se puede recuperar con Tcl_ChannelBlockModeProc, que devuelve un puntero a la función.

Un controlador de canal que no proporcione un blockModeProc debe ser muy, muy cuidadoso. Debe decirle a la capa genérica exactamente qué modo de bloqueo es aceptable para él, y esto también debe documentarse para el usuario para que el modo de bloqueo del canal no se cambie a un valor inaceptable. Cualquier confusión aquí puede llevar al intérprete a un punto muerto (falso y difícil de encontrar).

typedef int Tcl_DriverCloseProc(
        ClientData instanceData,

El argumento instanceData es el mismo que el valor proporcionado a Tcl_CreateChannel cuando se creó el canal. Toda la salida en cola se habrá vaciado al dispositivo antes de llamar a esta función, y no se invocarán más operaciones del controlador en esta instancia después de llamar a closeProc. NAME

Tcl_ChannelType, Tcl_CreateChannel, Tcl_GetChannelType, Tcl_RegisterChannel`, Tcl_UnregisterChannel, Tcl_SetChannelOption, Tcl_GetChannelOption, Tcl_GetChannelName, Tcl_IsChannel`, Tcl_IsChannelRegistered, Tcl_BadChannelOption - channel driver interface

SYNOPSIS

#include <tcl.h>

typedef struct Tcl_ChannelType {
    const char *typeName;
    Tcl_DriverBlockModeProc *blockModeProc;
    Tcl_DriverCloseProc *closeProc;
    Tcl_DriverInputProc *inputProc;
    Tcl_DriverOutputProc *outputProc;
    Tcl_DriverSeekProc *seekProc;
    Tcl_DriverSetOptionProc *setOptionProc;
    Tcl_DriverGetOptionProc *getOptionProc;
    Tcl_DriverWatchProc *watchProc;
    Tcl_DriverGetHandleProc *getHandleProc;
    Tcl_DriverClose2Proc *close2Proc;
    Tcl_DriverFlushProc *flushProc;
    Tcl_DriverHandlerProc *handlerProc;
    Tcl_DriverThreadActionProc *threadActionProc;
    Tcl_DriverTruncateProc *truncateProc;
} Tcl_ChannelType;

int
Tcl_CreateChannel(typePtr, channelName, instanceData, permissions);

Tcl_ChannelType *
Tcl_GetChannelType(channel);

int
Tcl_RegisterChannel(interp, channel);

void
Tcl_UnregisterChannel(interp, channel);

int
Tcl_SetChannelOption(interp, channel, optionName, value);

int
Tcl_GetChannelOption(interp, channel, optionName, valuePtr);

Tcl_GetChannelName(channel);

Tcl_IsChannel(token);

Tcl_IsChannelRegistered(channel);

Tcl_BadChannelOption(interp, optionName, optionList);

DESCRIPTION

These procedures are used by Tcl channel drivers to create and manage Tcl channels. A channel driver is a set of procedures that Tcl uses to perform I/O operations on a particular type of device. New channel types are created by defining a Tcl_ChannelType structure and registering it with Tcl using Tcl_RegisterChannel.

The Tcl_ChannelType structure is defined in the Synopsis. It contains pointers to functions that implement the behavior of the channel driver. The fields are:

typeName
A null-terminated string giving the name of the channel type. This name is used in the Tcl command to create a channel of this type, e.g. {@code open |command}.
blockModeProc
A pointer to a procedure that sets the blocking mode of the channel. See Tcl_DriverBlockModeProc below.
closeProc
A pointer to a procedure that closes the channel. See Tcl_DriverCloseProc below.
inputProc
A pointer to a procedure that reads data from the channel. See Tcl_DriverInputProc below.
outputProc
A pointer to a procedure that writes data to the channel. See Tcl_DriverOutputProc below.
seekProc
A pointer to a procedure that seeks to a position in the channel. See Tcl_DriverSeekProc below.
setOptionProc
A pointer to a procedure that sets channel-specific options. See Tcl_DriverSetOptionProc below.
getOptionProc
A pointer to a procedure that gets channel-specific options. See Tcl_DriverGetOptionProc below.
watchProc
A pointer to a procedure that registers interest in channel events. See Tcl_DriverWatchProc below.
getHandleProc
A pointer to a procedure that returns a device-specific handle for the channel. See Tcl_DriverGetHandleProc below.
close2Proc
A pointer to a procedure that closes the channel, potentially freeing resources associated with it. See Tcl_DriverClose2Proc below.
flushProc
A pointer to a procedure that flushes any buffered output on the channel. See Tcl_DriverFlushProc below.
handlerProc
A pointer to a procedure that is called when an event occurs on the channel. See Tcl_DriverHandlerProc below.
threadActionProc
A pointer to a procedure that is called when the channel is moved between threads. See Tcl_DriverThreadActionProc below.
truncateProc
A pointer to a procedure that truncates the channel to a specified length. See Tcl_DriverTruncateProc below.

TCL_DRIVERBLOCKMODEPROC

The blockModeProc field contains the address of a procedure that sets the blocking mode of the channel. It should match the following prototype:

typedef int Tcl_DriverBlockModeProc(
        ClientData instanceData,
        int nonBlocking);

InstanceData is the same as the value passed to Tcl_CreateChannel when this channel was created. The nonBlocking argument is non-zero to set non-blocking mode and zero to set blocking mode. The procedure should return 0 on success, or an appropriate POSIX error code.

This value can be retrieved with Tcl_ChannelBlockModeProc, which returns a pointer to the function.

TCL_DRIVERCLOSEPROC

The closeProc field contains the address of a procedure that closes the channel. It should match the following prototype:

typedef int Tcl_DriverCloseProc(
        ClientData instanceData,
        Tcl_Interp *interp);

InstanceData is the same as the value passed to Tcl_CreateChannel when this channel was created. The interp argument is the interpreter in which the channel was created. The procedure should perform any necessary cleanup for the channel, and may leave an error message in interp if an error occurs. The procedure should return 0 on success or an appropriate POSIX error code on failure.

This value can be retrieved with Tcl_ChannelCloseProc, which returns a pointer to the function.

TCL_DRIVERINPUTPROC

The inputProc field contains the address of a procedure that reads data from the channel. It should match the following prototype:

typedef int Tcl_DriverInputProc(
        ClientData instanceData,
        char *buf,
        int bufSize,
        Tcl_Errno *errorPtr);

InstanceData is the same as the value passed to Tcl_CreateChannel when this channel was created. The buf argument is a buffer to store the read data, and bufSize is the maximum number of bytes to read. The errorPtr argument is a pointer to a Tcl_Errno structure where any POSIX error code should be stored. The procedure should return the number of bytes read, or -1 on error.

This value can be retrieved with Tcl_ChannelInputProc, which returns a pointer to the function.

TCL_DRIVEROUPUTPROC

The outputProc field contains the address of a procedure that writes data to the channel. It should match the following prototype:

typedef int Tcl_DriverOutputProc(
        ClientData instanceData,
        const char *buf,
        int toWrite,
        Tcl_Errno *errorPtr);

InstanceData is the same as the value passed to Tcl_CreateChannel when this channel was created. The buf argument is the data to write, and toWrite is the number of bytes to write. The errorPtr argument is a pointer to a Tcl_Errno structure where any POSIX error code should be stored. The procedure should return the number of bytes written, or -1 on error.

This value can be retrieved with Tcl_ChannelOutputProc, which returns a pointer to the function.

TCL_DRIVERSEEKPROC

The seekProc field contains the address of a procedure that seeks to a position in the channel. It should match the following prototype:

typedef long Tcl_DriverSeekProc(
        ClientData instanceData,
        long offset,
        int seekMode);

InstanceData is the same as the value passed to Tcl_CreateChannel when this channel was created. The offset argument is the number of bytes to seek, and seekMode is one of TCL_SEEK_SET, TCL_SEEK_CUR, or TCL_SEEK_END. The procedure should return the new file position, or -1 on error.

This value can be retrieved with Tcl_ChannelSeekProc, which returns a pointer to the function.

TCL_DRIVERSETOPTIONPROC

The setOptionProc field contains the address of a procedure that sets channel-specific options. It should match the following prototype:

typedef int Tcl_DriverSetOptionProc(
        ClientData instanceData,
        const char *optionName,
        const char *value,
        Tcl_Interp *interp);

InstanceData is the same as the value passed to Tcl_CreateChannel when this channel was created. The optionName argument is the name of the option to set, and value is the value to set it to. The interp argument is the interpreter in which the channel was created. The procedure should return TCL_OK on success, or TCL_ERROR on failure. If an error occurs, an error message should be left in interp.

This value can be retrieved with Tcl_ChannelSetOptionProc, which returns a pointer to the function.

TCL_DRIVERGETOPTIONPROC

The getOptionProc field contains the address of a procedure that gets channel-specific options. It should match the following prototype:

typedef int Tcl_DriverGetOptionProc(
        ClientData instanceData,
        const char *optionName,
        Tcl_Interp *interp);

InstanceData is the same as the value passed to Tcl_CreateChannel when this channel was created. The optionName argument is the name of the option to get. The interp argument is the interpreter in which the channel was created. The procedure should set the result of the interpreter to the value of the option on success, and return TCL_OK. If the option is not supported, it should return TCL_ERROR.

If a system call error occurs, the function should leave an error message in the result of interp if interp is not NULL. The function should also call Tcl_SetErrno to store an appropriate POSIX error code.

Some options are handled by the generic code and this function is never called to retrieve their value, e.g. -blockmode. Other options are specific to each channel type and the getOptionProc procedure of the channel driver will get called to implement them. The getOptionProc field can be NULL, which indicates that this channel type supports no type specific options.

This value can be retrieved with Tcl_ChannelGetOptionProc, which returns a pointer to the function.

WATCHPROC

The watchProc field contains the address of a function called by the generic layer to initialize the event notification mechanism to notice events of interest on this channel. WatchProc should match the following prototype:

typedef void Tcl_DriverWatchProc(
        ClientData instanceData,
        int mask);

The instanceData is the same as the value passed to Tcl_CreateChannel when this channel was created. The mask argument is an OR-ed combination of TCL_READABLE, TCL_WRITABLE and TCL_EXCEPTION; it indicates events the caller is interested in noticing on this channel.

The function should initialize device type specific mechanisms to notice when an event of interest is present on the channel. When one or more of the designated events occurs on the channel, the channel driver is responsible for calling Tcl_NotifyChannel to inform the generic channel module. The driver should take care not to starve other channel drivers or sources of callbacks by invoking Tcl_NotifyChannel too frequently. Fairness can be insured by using the Tcl event queue to allow the channel event to be scheduled in sequence with other events. See the description of Tcl_QueueEvent for details on how to queue an event.

This value can be retrieved with Tcl_ChannelWatchProc, which returns a pointer to the function.

GETHANDLEPROC

The getHandleProc field contains the address of a function called by the generic layer to retrieve a device-specific handle from the channel. GetHandleProc should match the following prototype:

typedef int Tcl_DriverGetHandleProc(
        ClientData instanceData,
        int direction,
        ClientData *handlePtr);

InstanceData is the same as the value passed to Tcl_CreateChannel when this channel was created. The direction argument is either TCL_READABLE to retrieve the handle used for input, or TCL_WRITABLE to retrieve the handle used for output.

If the channel implementation has device-specific handles, the function should retrieve the appropriate handle associated with the channel, according the direction argument. The handle should be stored in the location referred to by handlePtr, and TCL_OK should be returned. If the channel is not open for the specified direction, or if the channel implementation does not use device handles, the function should return TCL_ERROR.

This value can be retrieved with Tcl_ChannelGetHandleProc, which returns a pointer to the function.

FLUSHPROC

The flushProc field is currently reserved for future use. It should be set to NULL. FlushProc should match the following prototype:

typedef int Tcl_DriverFlushProc(
        ClientData instanceData);

This value can be retrieved with Tcl_ChannelFlushProc, which returns a pointer to the function.

HANDLERPROC

The handlerProc field contains the address of a function called by the generic layer to notify the channel that an event occurred. It should be defined for stacked channel drivers that wish to be notified of events that occur on the underlying (stacked) channel. HandlerProc should match the following prototype:

typedef int Tcl_DriverHandlerProc(
        ClientData instanceData,
        int interestMask);

InstanceData is the same as the value passed to Tcl_CreateChannel when this channel was created. The interestMask is an OR-ed combination of TCL_READABLE or TCL_WRITABLE; it indicates what type of event occurred on this channel.

This value can be retrieved with Tcl_ChannelHandlerProc, which returns a pointer to the function.

THREADACTIONPROC

The threadActionProc field contains the address of the function called by the generic layer when a channel is created, closed, or going to move to a different thread, i.e. whenever thread-specific driver state might have to initialized or updated. It can be NULL. The action TCL_CHANNEL_THREAD_REMOVE is used to notify the driver that it should update or remove any thread-specific data it might be maintaining for the channel.

The action TCL_CHANNEL_THREAD_INSERT is used to notify the driver that it should update or initialize any thread-specific data it might be maintaining using the calling thread as the associate. See Tcl_CutChannel and Tcl_SpliceChannel for more detail.

typedef void Tcl_DriverThreadActionProc(
        ClientData instanceData,
        int action);

InstanceData is the same as the value passed to Tcl_CreateChannel when this channel was created.

These values can be retrieved with Tcl_ChannelThreadActionProc, which returns a pointer to the function.

TRUNCATEPROC

The truncateProc field contains the address of the function called by the generic layer when a channel is truncated to some length. It can be NULL.

typedef int Tcl_DriverTruncateProc(
        ClientData instanceData,
        Tcl_WideInt length);

InstanceData is the same as the value passed to Tcl_CreateChannel when this channel was created, and length is the new length of the underlying file, which should not be negative. The result should be 0 on success or an errno code (suitable for use with Tcl_SetErrno) on failure.

These values can be retrieved with Tcl_ChannelTruncateProc, which returns a pointer to the function.

TCL_BADCHANNELOPTION

This procedure generates a “bad option” error message in an (optional) interpreter. It is used by channel drivers when an invalid Set/Get option is requested. Its purpose is to concatenate the generic options list to the specific ones and factorize the generic options error message string.

It always returns TCL_ERROR

An error message is generated in interp's result value to indicate that a command was invoked with a bad option. The message has the form

    bad option "blah": should be one of
    <...generic options...>+<...specific options...>
so you get for instance: 
    bad option "-blah": should be one of -blocking,
    -buffering, -buffersize, -eofchar, -translation,
    -peername, or -sockname
when called with optionList equal to “peername sockname”

“blah” is the optionName argument and “<specific options>” is a space separated list of specific option words. The function takes good care of inserting minus signs before each option, commas after, and an “or” before the last option.

OLD CHANNEL TYPES

The original (8.3.1 and below) Tcl_ChannelType structure contains the following fields:

typedef struct Tcl_ChannelType {
    const char *typeName;
    Tcl_DriverBlockModeProc *blockModeProc;
    Tcl_DriverCloseProc *closeProc;
    Tcl_DriverInputProc *inputProc;
    Tcl_DriverOutputProc *outputProc;
    Tcl_DriverSeekProc *seekProc;
    Tcl_DriverSetOptionProc *setOptionProc;
    Tcl_DriverGetOptionProc *getOptionProc;
    Tcl_DriverWatchProc *watchProc;
    Tcl_DriverGetHandleProc *getHandleProc;
    Tcl_DriverClose2Proc *close2Proc;
} Tcl_ChannelType;

It is still possible to create channel with the above structure. The internal channel code will determine the version. It is imperative to use the new Tcl_ChannelType structure if you are creating a stacked channel driver, due to problems with the earlier stacked channel implementation (in 8.2.0 to 8.3.1).

Prior to 8.4.0 (i.e. during the later releases of 8.3 and early part of the 8.4 development cycle) the Tcl_ChannelType structure contained the following fields:

typedef struct Tcl_ChannelType {
    const char *typeName;
    Tcl_ChannelTypeVersion version;
    Tcl_DriverCloseProc *closeProc;
    Tcl_DriverInputProc *inputProc;
    Tcl_DriverOutputProc *outputProc;
    Tcl_DriverSeekProc *seekProc;
    Tcl_DriverSetOptionProc *setOptionProc;
    Tcl_DriverGetOptionProc *getOptionProc;
    Tcl_DriverWatchProc *watchProc;
    Tcl_DriverGetHandleProc *getHandleProc;
    Tcl_DriverClose2Proc *close2Proc;
    Tcl_DriverBlockModeProc *blockModeProc;
    Tcl_DriverFlushProc *flushProc;
    Tcl_DriverHandlerProc *handlerProc;
    Tcl_DriverTruncateProc *truncateProc;
} Tcl_ChannelType;

When the above structure is registered as a channel type, the version field should always be TCL_CHANNEL_VERSION_2.

NAME

Tcl_ChannelSeekProc - procedure for seeking in a Tcl channel

SYNOPSIS

#include <tcl.h>

typedef int Tcl_ChannelSeekProc(
    ClientData instanceData,
    Tcl_SeekOffset offset,
    int mode);

ARGUMENTS

ClientData instanceData (in)
The platform-specific data for the channel.
Tcl_SeekOffset offset (in)
The offset to seek to. The type `Tcl_SeekOffset` is a `long long int`.
int mode (in)
Specifies how to interpret offset. It can be one of TCL_SEEK_SET, TCL_SEEK_CUR, or TCL_SEEK_END.

DESCRIPTION

The Tcl_ChannelSeekProc is a function pointer type for procedures that handle seeking operations on Tcl channels. It is part of the Tcl channel driver interface.

A channel driver implements the Tcl_ChannelSeekProc to support the `seek` command for channels it manages. This procedure is called when the Tcl interpreter executes a seek command on a channel for which this driver is registered.

The procedure should attempt to move the current position within the channel to a new location specified by offset and mode.

The mode argument can have one of the following values:

TCL_SEEK_SET
The offset is relative to the beginning of the channel.
TCL_SEEK_CUR
The offset is relative to the current position in the channel.
TCL_SEEK_END
The offset is relative to the end of the channel.

The procedure should return the new current position in the channel relative to the beginning of the channel. If an error occurs during the seek operation, the procedure should set a Tcl error message using Tcl_SetErrno or Tcl_AppendResult and return -1.

TCL_CHANNELTYPE

This procedure is a member of the Tcl_ChannelType structure. The seekProc field of this structure is used to register the procedure that implements seeking.

TCL_BADCHANNELOPTION

If a channel driver does not support seeking, its seekProc field in Tcl_ChannelType should be set to NULL. In this case, the seek command will return an error indicating that the option is not supported for this channel.

OLD CHANNEL TYPES

In older versions of Tcl, seeking might have been handled differently. The `Tcl_ChannelSeekProc` is the modern way to handle seeking in Tcl channels.
