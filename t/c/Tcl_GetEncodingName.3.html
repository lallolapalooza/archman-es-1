Intérprete a utilizar para la notificación de errores, o NULL si no se desea notificación de errores.
const char *name (entrada)
Nombre de la codificación a cargar.
Tcl_Encoding encoding (entrada)
La codificación a consultar, liberar o usar para convertir texto. Si encoding es NULL, se utiliza la codificación del sistema actual.
Tcl_Obj *objPtr (entrada)
Nombre de la codificación para obtener su token.
Tcl_Encoding *encodingPtr (salida)
Puntero al almacenamiento donde se escribirá el token de codificación.
const char *src (entrada)
Para las funciones Tcl_ExternalToUtf, una matriz de bytes en la codificación especificada que se convertirán a UTF-8. Para las funciones Tcl_UtfToExternal y Tcl_WinUtfToTChar, una matriz de caracteres UTF-8 a convertir a la codificación especificada.
const TCHAR *tsrc (entrada)
Una matriz de caracteres TCHAR de Windows para convertir a UTF-8.
int srcLen (entrada)
Longitud de src o tsrc en bytes. Si la longitud es negativa, se utiliza la longitud específica de la codificación de la cadena.
Tcl_DString *dstPtr (salida)
Puntero a un Tcl_DString no inicializado o liberado en el que se almacenará el resultado convertido.
int flags (entrada)
Varios bits de bandera OR-eados. TCL_ENCODING_START indica que el buffer de origen es el primer bloque en un flujo de entrada (potencialmente de varios bloques), indicando a la rutina de conversión que reinicie a un estado inicial y realice cualquier inicialización que deba ocurrir antes de que se convierta el primer byte. TCL_ENCODING_END indica que el buffer de origen es el último bloque en un flujo de entrada (potencialmente de varios bloques), indicando a la rutina de conversión que realice cualquier finalización que deba ocurrir después de que se convierta el último byte y luego reinicie a un estado inicial. TCL_ENCODING_STOPONERROR indica que la rutina de conversión debe retornar inmediatamente al leer un carácter de origen que no existe en la codificación de destino; de lo contrario, se sustituirá automáticamente un carácter de relleno predeterminado.
Tcl_EncodingState *statePtr (entrada/salida)
Se utiliza al convertir un flujo de bytes (generalmente largo o de longitud indefinida) pieza por pieza. La rutina de conversión almacena su estado actual en *statePtr después de que src (el buffer que contiene la pieza actual) haya sido convertido; esa información de estado debe pasarse de nuevo al convertir la siguiente pieza del flujo para que la rutina de conversión sepa en qué estado se encontraba cuando terminó al final de la última pieza. Puede ser NULL, en cuyo caso se ignora el valor especificado para flags y se asume que el buffer de origen contiene la cadena completa a convertir.
char *dst (salida)
Buffer en el que se almacenará el resultado convertido. No se almacenarán más de dstLen bytes en dst.
int dstLen (entrada)
La longitud máxima del buffer de salida dst en bytes.
int *srcReadPtr (salida)
Se rellena con el número de bytes de src que se convirtieron realmente. Puede ser menor que la longitud original de origen si hubo un problema al convertir algunos caracteres de origen. Puede ser NULL.
int *dstWrotePtr (salida)
Se rellena con el número de bytes que se almacenaron realmente en el buffer de salida como resultado de la conversión. Puede ser NULL.
int *dstCharsPtr (salida)
Se rellena con el número de caracteres que corresponden al número de bytes almacenados en el buffer de salida. Puede ser NULL.
Tcl_DString *bufPtr (salida)
Almacenamiento para el nombre de codificación del sistema prescrito.
const Tcl_EncodingType *typePtr (entrada)
Estructura que define un nuevo tipo de codificación.
Tcl_Obj *searchPath (entrada)
Lista de directorios del sistema de archivos en los que buscar archivos de datos de codificación.
const char *path (entrada)
Una ruta a la ubicación del archivo de codificación.

INTRODUCCION

Estas rutinas convierten entre la representación interna de caracteres de Tcl, UTF-8, y las representaciones de caracteres utilizadas por diversos sistemas operativos o sistemas de archivos, como Unicode, ASCII o Shift-JIS. Al operar sobre cadenas, como al obtener nombres de archivos o mostrar caracteres utilizando fuentes internacionales, las cadenas deben traducirse a uno o posiblemente múltiples formatos que las diversas llamadas al sistema puedan utilizar. Por ejemplo, en una estación de trabajo Unix japonesa, un usuario podría obtener un nombre de archivo representado en la codificación de archivo EUC-JP y luego traducir los caracteres a la codificación de fuente jisx0208 para mostrar el nombre de archivo en un widget Tk. El propósito del paquete de codificación es ayudar a cerrar la brecha de traducción. UTF-8 proporciona un punto intermedio para todas las diversas codificaciones. En el ejemplo anterior, el texto se traduciría a UTF-8 desde la codificación de archivo que esté utilizando el sistema operativo. Luego se traduciría de UTF-8 a la codificación de fuente que requieran las rutinas de visualización.

Algunas codificaciones básicas están compiladas en Tcl. Otras pueden ser definidas por el usuario o cargadas dinámicamente desde archivos de codificación de manera independiente de la plataforma.

DESCRIPCION

Tcl_GetEncoding busca una codificación dado su nombre. El nombre puede referirse a una codificación incorporada de Tcl, una codificación definida por el usuario registrada llamando a Tcl_CreateEncoding, o un archivo de codificación cargable dinámicamente. El valor de retorno es un token que representa la codificación y puede usarse en llamadas posteriores a procedimientos como Tcl_GetEncodingName, Tcl_FreeEncoding y Tcl_UtfToExternal. Si el nombre no se refiere a ninguna codificación conocida o cargable, se devuelve NULL y se devuelve un mensaje de error en interp.

El paquete de codificación mantiene una base de datos de todas las codificaciones actualmente en uso. La primera vez que se ve name, Tcl_GetEncoding devuelve una codificación con un contador de referencia de 1. Si se solicita el mismo name más veces, el contador de referencia para esa codificación se incrementa sin el sobrecosto de asignar una nueva codificación y todas sus estructuras de datos asociadas.

Cuando una codificación ya no es necesaria, se debe llamar a Tcl_FreeEncoding para liberarla. Cuando una codificación ya no se usa en ninguna parte (es decir, ha sido liberada tantas veces como se ha obtenido), Tcl_FreeEncoding liberará todo el almacenamiento que la codificación estaba utilizando y la eliminará de la base de datos.

Tcl_GetEncodingFromObj trata la representación de cadena de objPtr como un nombre de codificación, y encuentra una codificación con ese nombre, al igual que lo hace Tcl_GetEncoding. Cuando se encuentra una codificación, se almacena en caché dentro del valor objPtr para referencia futura, el token Tcl_Encoding se escribe en el puntero de almacenamiento

uedo por encodingPtr, y se devuelve el valor TCL_OK. Si no se encuentra dicha codificación, se devuelve el valor TCL_ERROR y no se realiza ninguna escritura en *encodingPtr. Al igual que con Tcl_GetEncoding, el llamante debe llamar a Tcl_FreeEncoding en el token de codificación resultante cuando dicho token ya no se necesite.

Tcl_ExternalToUtfDString convierte un búfer de origen src de la codificación especificada a UTF-8. Los bytes convertidos se almacenan en dstPtr, que luego se termina con nulo. El llamante debe llamar eventualmente a Tcl_DStringFree para liberar cualquier información almacenada en dstPtr. Al convertir, si alguno de los caracteres en el búfer de origen no se puede representar en la codificación de destino, se utilizará un carácter de sustitución predeterminado. El valor de retorno es un puntero al valor almacenado en el DString.

Tcl_ExternalToUtf convierte un búfer de origen src de la codificación especificada a UTF-8. Se convierten hasta srcLen bytes del búfer de origen y se almacenan hasta dstLen bytes convertidos en dst. En todos los casos, se rellena *srcReadPtr con el número de bytes que se convirtieron exitosamente de src y *dstWrotePtr con el número correspondiente de bytes que se almacenaron en dst. El valor de retorno es uno de los siguientes:

TCL_OK
Se convirtieron todos los bytes de src.
TCL_CONVERT_NOSPACE
El búfer de destino no era lo suficientemente grande para todos los datos convertidos; sin embargo, se convirtieron tantos caracteres como cupieron.
TCL_CONVERT_MULTIBYTE
Los últimos bytes del búfer de origen eran el principio de una secuencia multibyte, pero se necesitaban más bytes para completar esta secuencia. Una llamada posterior a la rutina de conversión debería pasar un búfer que contenga los bytes no convertidos que quedaron en src más algunos bytes adicionales del flujo de origen para convertir adecuadamente la secuencia multibyte anteriormente dividida.
TCL_CONVERT_SYNTAX
El búfer de origen contenía una secuencia de caracteres inválida. Esto puede ocurrir si el flujo de entrada se ha dañado o si se identificó incorrectamente el método de codificación de entrada.
TCL_CONVERT_UNKNOWN
El búfer de origen contenía un carácter que no se podía representar en la codificación de destino y se especificó TCL_ENCODING_STOPONERROR.

Tcl_UtfToExternalDString convierte un búfer de origen src de UTF-8 a la codificación especificada. Los bytes convertidos se almacenan en dstPtr, que luego se termina con el nulo específico de la codificación apropiado. El llamante debe llamar eventualmente a Tcl_DStringFree para liberar cualquier información almacenada en dstPtr. Al convertir, si alguno de los caracteres en el búfer de origen no se puede representar en la codificación de destino, se utilizará un carácter de sustitución predeterminado. El valor de retorno es un puntero al valor almacenado en el DString.

Tcl_UtfToExternal convierte un búfer de origen src de UTF-8 a la codificación especificada. Se convierten hasta srcLen bytes del búfer de origen y se almacenan hasta dstLen bytes convertidos en dst. En todos los casos, se rellena *srcReadPtr con el número de bytes que se convirtieron exitosamente de src y *dstWrotePtr con el número correspondiente de bytes que se almacenaron en dst. Los valores de retorno son los mismos que los valores de retorno de Tcl_ExternalToUtf.

Tcl_WinUtfToTChar y Tcl_WinTCharToUtf son funciones de conveniencia exclusivas de Windows para convertir entre UTF-8 y cadenas de Windows basadas en el tipo TCHAR, que por convención es un carácter Unicode en Windows NT.

Tcl_GetEncodingName es aproximadamente la inversa de Tcl_GetEncoding. Dado una encoding, el valor de retorno es el argumento name que se utilizó para crear la codificación. La cadena devuelta por Tcl_GetEncodingName solo se garantiza que persistirá hasta que la encoding sea eliminada. El llamante no debe modificar esta cadena.

Tcl_SetSystemEncoding establece la codificación predeterminada que se debe utilizar siempre que el usuario pase un valor NULL para el argumento encoding a cualquiera de las otras funciones de codificación. Si name es NULL, la codificación del sistema se restablece a la codificación del sistema predeterminada, binary. Si el nombre no se refiere a ninguna codificación conocida o cargable, se devuelve TCL_ERROR y se deja un mensaje de error en interp. De lo contrario, este procedimiento incrementa el recuento de referencias de la nueva codificación del sistema, decrementa el recuento de referencias de la codificación del sistema anterior y devuelve TCL_OK.

Tcl_GetEncodingNameFromEnvironment proporciona un medio para que la biblioteca Tcl informe el nombre de codificación que cree que es el correcto para usar como codificación del sistema, basándose en llamadas al sistema y examen del entorno adecuado para la plataforma. Acepta bufPtr, un puntero a un Tcl_DString no inicializado o liberado, y escribe el nombre de codificación en él. Se devuelve Tcl_DStringValue.

Tcl_GetEncodingNames establece el resultado de interp a una lista que consta de los nombres de todas las codificaciones que están actualmente definidas o que se pueden cargar dinámicamente, buscando en la ruta de codificación especificada por Tcl_SetDefaultEncodingDir. Este procedimiento no garantiza que los archivos de codificación cargables dinámicamente contengan datos válidos, sino simplemente que existen.

Tcl_CreateEncoding define una nueva codificación y registra los procedimientos C que se llaman para convertir entre la codificación y UTF-8. Las codificaciones creadas por Tcl_CreateEncoding son posteriormente visibles en la base de datos utilizada por Tcl_GetEncoding. Al igual que con el procedimiento Tcl_GetEncoding, el valor de retorno es un token que representa la codificación y se puede utilizar en llamadas posteriores a otras funciones de codificación. Tcl_CreateEncoding devuelve una codificación con un recuento de referencias de 1. Si ya existe una codificación con el nombre especificado, su entrada en la base de datos se reemplaza con la nueva codificación; el token para la codificación antigua seguirá siendo válido y continuará comportándose como antes, pero los usuarios del nuevo token ahora llamarán a los nuevos procedimientos de codificación.

El argumento typePtr a Tcl_CreateEncoding contiene información sobre el nombre de la codificación y los procedimientos que se llamarán para convertir entre esta codificación y UTF-8. Se define de la siguiente manera:

typedef struct Tcl_EncodingType {
    const char *encodingName;
    Tcl_EncodingConvertProc *toUtfProc;
    Tcl_EncodingConvertProc *fromUtfProc;
    Tcl_EncodingFreeProc *freeProc;
    ClientData clientData;
    int nullSize;
} Tcl_EncodingType;

encodingName proporciona un nombre de cadena para la codificación, por el cual se puede referir en otros procedimientos como Tcl_GetEncoding. toUtfProc se refiere a un procedimiento de callback para invocar para convertir texto de esta codificación a UTF-8. fromUtfProc se refiere a un procedimiento de callback para invocar para convertir texto de UTF-8 a esta codificación. freeProc se refiere a un procedimiento de callback para invocar cuando se elimine esta codificación. El campo freeProc puede ser NULL. clientData contiene un valor de palabra arbitraria pasado a toUtfProc, fromUtfProc y freeProc siempre que se llamen. Típicamente, este es un puntero a una estructura de datos que contiene información específica de la codificación que puede ser utilizada por los procedimientos de callback. Por ejemplo, dos codificaciones muy similares como ascii y macRoman pueden usar el mismo procedimiento de callback, pero usar diferentes valores de clientData para controlar su comportamiento. nullSize especifica el número de bytes cero que significan fin de cadena en esta codificación. Debe ser 1 (para codificaciones de un solo byte o multibyte como ASCII o Shift-JIS) o 2 (para codificaciones de doble byte como Unicode). Las codificaciones de tamaño constante con 3 o más bytes por carácter (como CNS11643) no se aceptan.

Los procedimientos de callback toUtfProc y fromUtfProc deben coincidir con el tipo Tcl_EncodingConvertProc:

typedef int Tcl_EncodingConvertProc(
        ClientData clientData,
        const char *src,
        int srcLen,
        int flags,
        Tcl_EncodingState *statePtr,
        char *dst,
        int dstLen,
        int *srcReadPtr,
        int *dstWrotePtr,
        int *dstCharsPtr);

Los procedimientos toUtfProc y fromUtfProc son llamados por la familia de funciones Tcl_ExternalToUtf o Tcl_UtfToExternal para realizar la conversión real. El parámetro clientData a estos procedimientos es el mismo que el campo clientData especificado a Tcl_CreateEncoding cuando se creó la codificación. Los argumentos restantes a los procedimientos de callback son los mismos que los argumentos, documentados en la parte superior, de Tcl_ExternalToUtf o Tcl_UtfToExternal, con las siguientes excepciones. Si el argumento srcLen a una de esas funciones de alto nivel es negativo, el valor pasado al procedimiento de callback será la longitud de cadena específica de la codificación apropiada de src. Si alguno de los argumentos srcReadPtr, dstWrotePtr o dstCharsPtr a una de las funciones de alto nivel es NULL, el valor correspondiente pasado al procedimiento de callback será una ubicación no NULL.

El procedimiento de callback freeProc, si no es NULL, debe coincidir con el tipo Tcl_EncodingFreeProc:

typedef void Tcl_EncodingFreeProc(
        ClientData clientData);

Esta función freeProc se llama cuando se elimina la codificación. El parámetro clientData es el mismo que el campo clientData especificado a Tcl_CreateEncoding cuando se creó la codificación.

Tcl_GetEncodingSearchPath y Tcl_SetEncodingSearchPath se llaman para acceder y establecer la lista de directorios del sistema de archivos que se buscan para los archivos de datos de codificación.

El valor devuelto por Tcl_GetEncodingSearchPath es el valor almacenado por la última llamada exitosa a Tcl_SetEncodingSearchPath. Si no se han producido llamadas a Tcl_SetEncodingSearchPath, Tcl calculará un valor inicial basado en el entorno. Existe una ruta de búsqueda de codificación para todo el proceso, compartida por todos los hilos del proceso.

INTRODUCTION

Tcl provides facilities for converting between Unicode and other character encodings. This mechanism is used internally by Tcl for I/O and by the user for string conversions.

DESCRIPTION

The Tcl encoding system allows Tcl scripts to work with character encodings other than the internal Unicode representation. When Tcl needs to read or write data in an external encoding, it uses the facilities described here.

Tcl_SetEncoding is used to set the default encoding for the interpreter specified by interp. The name argument should be the name of an encoding recognized by Tcl. Tcl recognizes a set of built-in encodings and can also load additional encodings from dynamically loadable encoding files. If name is NULL, then the default encoding is set to Unicode. The function returns a handle for the encoding, or NULL if an error occurs (e.g. the encoding is not known). The encoding handle should be passed to Tcl_FreeEncoding when it is no longer needed.

Tcl_GetEncodingName returns the name corresponding to the encoding handle encoding. This is useful for getting the name of the current default encoding.

Tcl searches for encoding files in a list of directories specified by the encoding search path. Tcl_GetEncodingSearchPath returns the current search path as a NULL-terminated array of strings. The caller is responsible for freeing the returned array and its contents using Tcl_Free. The default search path is initialized based on the value of the TCL_ENCODING_PATH environment variable and platform-specific default directories.

Tcl_SetEncodingSearchPath sets the encoding search path for the interpreter interp to the list of directories given by path. The path argument should be a NULL-terminated array of strings, where each string is a directory name. If path is NULL, the search path is reset to its default value. The caller is responsible for freeing the path array and its contents if they were dynamically allocated.

The directories in the encoding search path are searched in order. If a directory in the search path does not exist or is not readable, it is silently ignored. This means that only existing, readable filesystem directories are considered. This check is performed only when Tcl is actively searching for encoding data files.

Tcl_GetDefaultEncodingDir and Tcl_SetDefaultEncodingDir are obsolete interfaces best replaced with calls to Tcl_GetEncodingSearchPath and Tcl_SetEncodingSearchPath. They are called to access and set the first element of the searchPath list. Since Tcl searches searchPath for encoding data files in list order, these routines establish the “default” directory in which to find encoding data files.

ENCODING FILES

Space would prohibit precompiling into Tcl every possible encoding algorithm, so many encodings are stored on disk as dynamically-loadable encoding files. This behavior also allows the user to create additional encoding files that can be loaded using the same mechanism. These encoding files contain information about the tables and/or escape sequences used to map between an external encoding and Unicode. The external encoding may consist of single-byte, multi-byte, or double-byte characters.

Each dynamically-loadable encoding is represented as a text file. The initial line of the file, beginning with a “#” symbol, is a comment that provides a human-readable description of the file. The next line identifies the type of encoding file. It can be one of the following letters:

[1] S
A single-byte encoding, where one character is always one byte long in the encoding. An example is iso8859-1, used by many European languages.
[2] D
A double-byte encoding, where one character is always two bytes long in the encoding. An example is big5, used for Chinese text.
[3] M
A multi-byte encoding, where one character may be either one or two bytes long. Certain bytes are lead bytes, indicating that another byte must follow and that together the two bytes represent one character. Other bytes are not lead bytes and represent themselves. An example is shiftjis, used by many Japanese computers.
[4] E
An escape-sequence encoding, specifying that certain sequences of bytes do not represent characters, but commands that describe how following bytes should be interpreted.

The rest of the lines in the file depend on the type.

Subsequent lines in the example above are pages that describe how to map from the encoding into 2-byte Unicode. The first line in a page identifies the page number. Following it are 256 double-byte numbers, arranged as 16 rows of 16 numbers. Given a character in the encoding, the high byte of that character is used to select which page, and the low byte of that character is used as an index to select one of the double-byte numbers in that page - the value obtained being the corresponding Unicode character. By examination of the example above, one can see that the characters 0x7E and 0x8163 in shiftjis map to 203E and 2026 in Unicode, respectively.

Following the first page will be all the other pages, each in the same format as the first: one number identifying the page followed by 256 double-byte Unicode characters. If a character in the encoding maps to the Unicode character 0000, it means that the character does not actually exist. If all characters on a page would map to 0000, that page can be omitted.

Case [4] is the escape-sequence encoding file. The lines in an this type of file are in the same format as this example taken from the iso2022-jp encoding:

# Encoding file: iso2022-jp, escape-driven
E
init		{}
final		{}
iso8859-1	\x1b(B
jis0201		\x1b(J
jis0208		\x1b$@
jis0208		\x1b$B
jis0212		\x1b$(D
gb2312		\x1b$A
ksc5601		\x1b$(C

In the file, the first column represents an option and the second column is the associated value. init is a string to emit or expect before the first character is converted, while final is a string to emit or expect after the last character. All other options are names of table-based encodings; the associated value is the escape-sequence that marks that encoding. Tcl syntax is used for the values; in the above example, for instance, “{}” represents the empty string and “\x1b” represents character 27.

When Tcl_GetEncoding encounters an encoding name that has not been loaded, it attempts to load an encoding file called name.enc from the encoding subdirectory of each directory that Tcl searches for its script library. If the encoding file exists, but is malformed, an error message will be left in interp.
