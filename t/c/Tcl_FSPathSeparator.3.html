const Tcl_Filesystem *fsPtr (in)
Punta a una estructura que contiene las direcciones de los procedimientos que se pueden llamar para realizar las diversas operaciones del sistema de archivos.
Tcl_Obj *pathPtr (in)
La ruta representada por este valor se utiliza para la operación en cuestión. Si el valor aún no tiene una representación interna de ruta, se convertirá para tener una.
Tcl_Obj *srcPathPtr (in)
Como para pathPtr, pero se utiliza para el archivo de origen para una operación de copia o renombre.
Tcl_Obj *destPathPtr (in)
Como para pathPtr, pero se utiliza para el nombre del archivo de destino para una operación de copia o renombre.
int recursive (in)
Si se deben eliminar también los subdirectorios y su contenido.
const char *encodingName (in)
La codificación de los datos almacenados en el archivo identificado por pathPtr y que se va a evaluar.
const char *pattern (in)
Solo se devolverán archivos o directorios que coincidan con este patrón.
Tcl_GlobTypeData *types (in)
Solo se devolverán archivos o directorios que coincidan con las descripciones de tipo contenidas en esta estructura. Este parámetro puede ser NULL.
Tcl_Interp *interp (in)
Intérprete a utilizar para resultados, evaluación o para informar mensajes de error.
void *clientData (in)
La descripción nativa del valor de ruta a crear.
Tcl_Obj *firstPtr (in)
El primero de los dos valores de ruta a comparar. El valor puede convertirse al tipo ruta.
Tcl_Obj *secondPtr (in)
El segundo de los dos valores de ruta a comparar. El valor puede convertirse al tipo ruta.
Tcl_Obj *listObj (in)
La lista de elementos de ruta sobre los que operar con una operación de unión.
int elements (in)
El número de elementos en listObj que deben unirse. Si es negativo, se unen todos los elementos.
Tcl_Obj **errorPtr (out)
En caso de error, se rellena con un valor que contiene el nombre del archivo que causó el error en las diversas operaciones de copia/renombre.
int index (in)
El índice del atributo en cuestión.
Tcl_Obj *objPtr (in)
El valor a establecer en la operación.
Tcl_Obj **objPtrRef (out)
Se rellena con un valor que contiene el resultado de la operación.
int mode (in)
Máscara que consiste en uno o más de R_OK, W_OK, X_OK y F_OK. R_OK, W_OK y X_OK solicitan comprobar si el archivo existe y tiene permisos de lectura, escritura y ejecución, respectivamente. F_OK solo solicita comprobar la existencia del archivo.
Tcl_StatBuf *statPtr (out)
La estructura que contiene el resultado de una operación stat o lstat.
const char *sym1 (in)
Nombre de un procedimiento a buscar en la tabla de símbolos del archivo
const char *sym2 (in)
Nombre de un procedimiento a buscar en la tabla de símbolos del archivo
Tcl_PackageInitProc **proc1Ptr (out)
Se rellena con la función de inicialización para este código.
Tcl_PackageInitProc **proc2Ptr (out)
Se rellena con la función de inicialización segura para este código.
void **clientDataPtr (out)
Se rellena con el valor clientData para pasar a la función de descarga de este código cuando se llame.
Tcl_LoadHandle *loadHandlePtr (out)
Se rellena con un token abstracto que representa el archivo cargado.
Tcl_FSUnloadFileProc **unloadProcPtr (out)
Se rellena con la función a utilizar para descargar este fragmento de código.
Tcl_LoadHandle loadHandle (in)
Identificador de la biblioteca cargada que se va a descargar.
utimbuf *tval (in)
Los tiempos de acceso y modificación en esta estructura se leen y se utilizan para establecer esos valores para un archivo determinado.
const char *modeString (in)
Especifica cómo se debe acceder al archivo. Puede tener cualquiera de los valores permitidos para el argumento mode del comando Tcl open.
int permissions (in)
Indicadores de permisos de estilo POSIX como 0644. Si se crea un archivo nuevo, estos permisos se establecerán en el archivo creado.

Tcl_FSFileAttrsGet implementa el acceso de lectura para el subcomando file attributes (atributos de archivo) que se puede interceptar. Se llamará a la función apropiada para el sistema de archivos al que pertenece pathPtr.

Si el resultado es TCL_OK, entonces se colocó un valor en objPtrRef, que solo será válido temporalmente (a menos que se llame a Tcl_IncrRefCount).

Tcl_FSFileAttrsSet implementa el acceso de escritura para el subcomando file attributes (atributos de archivo) que se puede interceptar. Se llamará a la función apropiada para el sistema de archivos al que pertenece pathPtr.

Tcl_FSFileAttrStrings implementa parte del subcomando file attributes (atributos de archivo) que se puede interceptar. Se llamará a la función apropiada para el sistema de archivos al que pertenece pathPtr.

El procedimiento llamado puede devolver una matriz de cadenas o puede devolver NULL y colocar una lista de Tcl en objPtrRef. Tcl tomará esa lista y primero incrementará su recuento de referencias antes de usarla. Al finalizar ese uso, Tcl disminuirá su recuento de referencias. Por lo tanto, si Tcl debe desechar la lista cuando termine, debería tener un recuento de referencias de cero, y si Tcl no debe desechar la lista, el sistema de archivos debe asegurarse de que conserve un recuento de referencias al valor.

Tcl_FSAccess comprueba si al proceso se le permitiría leer, escribir o probar la existencia del archivo (u otro objeto del sistema de archivos) cuyo nombre es pathname. Si pathname es un enlace simbólico en Unix, se prueban los permisos del archivo al que se refiere este enlace simbólico.

En caso de éxito (se otorgan todos los permisos solicitados), se devuelve cero. En caso de error (al menos un bit en el modo solicitado para un permiso denegado, o se produjo algún otro error), se devuelve -1.

Tcl_FSStat rellena la estructura Tcl_StatBuf statPtr con información sobre el archivo especificado. No necesita ningún derecho de acceso al archivo para obtener esta información, pero necesita derechos de búsqueda en todos los directorios mencionados en la ruta que conduce al archivo. La estructura Tcl_StatBuf incluye información sobre el dispositivo, inodo (siempre 0 en Windows), modo de privilegio, nlink (siempre 1 en Windows), id de usuario (siempre 0 en Windows), id de grupo (siempre 0 en Windows), rdev (igual que el dispositivo en Windows), tamaño, tiempo de último acceso, tiempo de última modificación y tiempo de último cambio de metadatos. Consulte la API DE RESULTADOS DE STAT PORTÁTILES para obtener una descripción de cómo escribir código portátil para asignar y acceder a la estructura Tcl_StatBuf.

Si path existe, Tcl_FSStat devuelve 0 y la estructura stat se rellena con datos. De lo contrario, se devuelve -1 y no se proporciona información de estado.

Tcl_FSOpenFileChannel abre un archivo especificado por pathPtr y devuelve un identificador de canal que se puede utilizar para realizar operaciones de entrada y salida en el archivo. Esta API está modelada a partir del procedimiento fopen de la biblioteca estándar de E/S de Unix. La sintaxis y el significado de todos los argumentos son similares a los proporcionados en el comando Tcl open al abrir un archivo. Si se produce un error al abrir el canal, Tcl_FSOpenFileChannel devuelve NULL y registra un código de error POSIX que se puede recuperar con Tcl_GetErrno. Además, si interp no es NULL, Tcl_FSOpenFileChannel deja un mensaje de error en el resultado de interp después de cualquier error.

El canal recién creado no se registra en el intérprete suministrado; para registrarlo, utilice Tcl_RegisterChannel. Si uno de los canales estándar, stdin, stdout o stderr se cerró previamente, el acto de crear el nuevo canal también lo asigna como reemplazo del canal estándar.

Tcl_FSGetCwd reemplaza la versión de biblioteca de getcwd.

Devuelve el directorio de trabajo actual de la biblioteca de Tcl. Este puede ser diferente al directorio de trabajo de la plataforma nativa, lo que ocurre cuando el directorio de trabajo actual no está en el sistema de archivos nativo.

El resultado es un puntero a un Tcl_Obj que especifica el directorio actual, o NULL si no se pudo determinar el directorio actual. Si se devuelve NULL, se deja un mensaje de error en el resultado de interp.

El resultado ya tiene su recuento de referencias incrementado para el llamador. Cuando ya no sea necesario, se debe disminuir ese recuento de referencias. Esto es necesario por motivos de seguridad de hilos, para permitir que varios hilos accedan a esta y a funciones relacionadas, garantizando al mismo tiempo que los resultados sean siempre válidos.

Tcl_FSChdir reemplaza la versión de biblioteca de chdir. La ruta se normaliza y luego se pasa al sistema de archivos que la reclama. Si ese sistema de archivos no implementa esta función, Tcl recurrirá a una combinación de stat y access para verificar si el directorio existe y tiene los permisos apropiados.

Para obtener resultados, consulte la documentación de chdir. Si tiene éxito, conservamos un registro de la ruta exitosa en cwdPathPtr para llamadas posteriores a Tcl_FSGetCwd.

Tcl_FSPathSeparator devuelve el carácter separador que se utilizará para el elemento más específico de la ruta especificada por pathPtr (es decir, la última parte de la ruta).

El separador se devuelve como un Tcl_Obj que contiene una cadena de longitud 1. Si la ruta no es válida, se devuelve NULL.

Tcl_FSJoinPath toma el Tcl_Obj dado, que debe ser una lista válida (a la que se le permite tener un recuento de referencias de cero), y devuelve el valor de la ruta dado considerando los primeros elements elementos como segmentos de ruta válidos (cada segmento de ruta puede ser una ruta completa, una ruta parcial o simplemente un solo directorio o nombre de archivo posible). Si algún segmento de ruta es en realidad una ruta absoluta, se descartan todos los segmentos de ruta anteriores. Si elements es menor que 0, usamos toda la lista.

Es posible que el valor devuelto sea en realidad un elemento de la lista dada, por lo que el llamador debe tener cuidado de incrementar el recuento de referencias del resultado antes de liberar la lista.

El valor devuelto, típicamente con un recuento de referencias de cero (pero podría ser compartido bajo algunas condiciones), contiene la ruta unida. El llamador debe agregar un recuento de referencias al valor antes de usarlo. En particular, el valor devuelto podría ser un elemento de la lista dada, por lo que liberar la lista podría liberar el valor prematuramente si no se ha tomado ninguna referencia. Si el número de elementos es cero, el valor devuelto será un Tcl_Obj de cadena vacía.

Tcl_FSSplitPath toma el Tcl_Obj dado, que debería ser una ruta válida, y devuelve un valor de lista de Tcl que contiene cada segmento de esa ruta como un elemento. Devuelve un valor de lista con un recuento de referencias de cero. Si el lenPtr pasado no es NULL, la variable a la que apunta se actualizará para contener el número de elementos en la lista devuelta.

Tcl_FSEqualPaths prueba si las dos rutas dadas representan el mismo objeto del sistema de archivos. Devuelve 1 si las rutas son iguales y 0 si son diferentes. Si alguna ruta es NULL, siempre se devuelve 0.

Tcl_FSGetNormalizedPath intenta extraer del Tcl_Obj dado una representación única de ruta normalizada, cuyo valor de cadena se puede utilizar como identificador único del archivo.

Devuelve el valor de la ruta normalizada, propiedad de Tcl, o NULL si la ruta no era válida o no se pudo convertir correctamente. La extracción de rutas absolutas y normalizadas es muy eficiente (porque el sistema de archivos opera internamente sobre estas representaciones), aunque el resultado cuando el sistema de archivos contiene numerosos enlaces simbólicos puede no ser la versión más fácil de usar de una ruta. El valor devuelto es propiedad de Tcl y tiene una vida útil equivalente a la de pathPtr pasado (a menos que sea una ruta relativa, en cuyo caso el valor de la ruta normalizada puede liberarse en cualquier momento en que cambie el cwd); el llamador, por supuesto, puede incrementar el recuento de referencias si desea mantener una copia por más tiempo.

Tcl_FSJoinToPath toma el valor dado, que normalmente debería ser una ruta válida o NULL, y le une la matriz de segmentos de ruta dados.

Devuelve un valor, típicamente con un recuento de referencias de cero (pero podría ser compartido bajo algunas condiciones), que contiene la ruta unida. El llamador debe agregar un recuento de referencias al valor antes de usarlo. Si alguno de los valores pasados a esta función (pathPtr o los elementos de path) tiene un recuento de referencias de cero, se liberarán cuando esta función devuelva.

Tcl_FSConvertToPathType intenta convertir el Tcl_Obj dado a un tipo de ruta Tcl válido, teniendo en cuenta el hecho de que el cwd puede haber cambiado incluso si este valor ya es supuestamente del tipo correcto. El nombre del archivo puede comenzar con "~" (para indicar el directorio de inicio del usuario actual) o "~" (para indicar el directorio de inicio de cualquier usuario).

Si la conversión tiene éxito (es decir, el valor es una ruta válida en uno de los sistemas de archivos actuales), se devuelve TCL_OK. De lo contrario, se devuelve TCL_ERROR y se puede dejar un mensaje de error en el intérprete.

Tcl_FSGetInternalRep extrae la representación interna de un valor de ruta dado, en el sistema de archivos dado. Si el valor de la ruta pertenece a un sistema de archivos diferente, devolvemos NULL. Si la representación interna es actualmente NULL, intentamos generarla, llamando a la Tcl_FSCreateInternalRepProc del sistema de archivos.

Devuelve NULL o una representación de ruta interna válida. Esta representación interna se almacena en caché, de modo que las llamadas repetidas a esta función no requerirán conversiones adicionales.

Tcl_FSGetTranslatedPath intenta extraer la ruta traducida del Tcl_Obj dado.

Si la traducción tiene éxito (es decir, el valor es una ruta válida), se devuelve. De lo contrario, se devolverá NULL y se puede dejar un mensaje de error en el intérprete. Una ruta "traducida" es aquella que no contiene secuencias "~" o "~usuario" (estas se han expandido a su representación actual en el sistema de archivos). El valor devuelto es propiedad del llamador, que debe almacenarlo o llamar a Tcl_DecrRefCount para asegurar que la memoria se libere. Esta función tiene poca utilidad práctica, y Tcl_FSGetNormalizedPath o Tcl_FSGetNativePath son funciones generalmente mejores para usar en la mayoría de los casos.

Tcl_FSGetTranslatedStringPath hace lo mismo que Tcl_FSGetTranslatedPath, pero devuelve una cadena de caracteres o NULL. La cadena devuelta está asignada dinámicamente

y el propietario del llamador, quien debe almacenarlo o llamar a ckfree para asegurarse de que se libere. De nuevo, Tcl_FSGetNormalizedPath o Tcl_FSGetNativePath son funciones que generalmente es mejor usar para la mayoría de los propósitos.

Tcl_FSNewNativePath realiza algo así como lo inverso de las conversiones habituales obj->path->nativerep. Si algún código recupera una ruta en formato nativo (de, por ejemplo, readlink o un diálogo nativo), y esa ruta se va a utilizar a nivel de Tcl, entonces llamar a esta función es una forma eficiente de crear el tipo de valor de ruta apropiado.

El valor resultante es un valor de "ruta" puro, que solo recibirá una representación de cadena UTF-8 si es requerido por algún código Tcl.

Tcl_FSGetNativePath es para uso de los sistemas de archivos nativos Win/Unix, para que puedan recuperar fácilmente la representación nativa (char* o TCHAR*) de una ruta. Esta función es un envoltorio conveniente para Tcl_FSGetInternalRep. Puede ser deseable en el futuro tener representaciones nativas no basadas en cadenas (por ejemplo, en macOS, una representación que use una estructura FSRef de fileSpec probablemente sería más eficiente). En Windows, una representación Unicode completa permitiría rutas de longitud ilimitada. Actualmente, la representación es simplemente una cadena de caracteres que puede contener la ruta relativa o una ruta completa, absoluta y normalizada en la codificación nativa (condiciones complejas dictan cuál de estas se proporcionará, por lo que ninguna puede confiarse, a menos que se sepa que la ruta es absoluta). Si necesita una ruta nativa que deba ser absoluta, debería solicitar la versión nativa de una ruta normalizada. Si por alguna razón se necesita una versión de la ruta no absoluta y no normalizada, esta debe construirse por separado (por ejemplo, usando Tcl_FSGetTranslatedPath).

La representación nativa se almacena en caché para que las llamadas repetidas a esta función no requieran conversiones adicionales. El valor de retorno es propiedad de Tcl y tiene una vida útil equivalente a la del pathPtr pasado (a menos que sea una ruta relativa, en cuyo caso la representación nativa puede liberarse en cualquier momento en que cambie el cwd).

Tcl_FSFileSystemInfo devuelve una lista de dos elementos. El primer elemento es el nombre del sistema de archivos (por ejemplo, "native", "vfs", "zip", o "prowrap", quizás), y el segundo es el tipo particular de la ruta dada dentro de ese sistema de archivos (que depende del sistema de archivos). El segundo elemento puede estar vacío si el sistema de archivos no proporciona una categorización adicional de los archivos.

Se devuelve un valor de lista válido, a menos que el valor de la ruta no sea reconocido, en cuyo caso se devolverá NULL.

Tcl_FSGetFileSystemForPath devuelve un puntero al Tcl_Filesystem que acepta esta ruta como válida.

Si ningún sistema de archivos acepta la ruta, se devuelve NULL.

Tcl_FSGetPathType determina si la ruta dada es relativa al directorio actual, relativa al volumen actual o absoluta.

Devuelve uno de TCL_PATH_ABSOLUTE, TCL_PATH_RELATIVE, o TCL_PATH_VOLUME_RELATIVE

LA API DEL SISTEMA DE ARCHIVOS VIRTUAL

Un sistema de archivos proporciona una estructura Tcl_Filesystem que contiene punteros a funciones que implementan las diversas operaciones en un sistema de archivos; estas operaciones se invocan según sea necesario por la capa genérica, lo que generalmente ocurre a través de las funciones enumeradas anteriormente.

Las estructuras Tcl_Filesystem se manipulan utilizando los siguientes métodos.

Tcl_FSRegister toma un puntero a una estructura de sistema de archivos y un dato opcional para asociar con ese sistema de archivos. Al llamar a esta función, Tcl adjuntará el sistema de archivos a la lista de sistemas de archivos conocidos, y se volverá completamente funcional de inmediato. Tcl no verifica si el mismo sistema de archivos está registrado varias veces (y en general, eso no es algo bueno de hacer). Se devolverá TCL_OK.

Tcl_FSUnregister elimina la estructura de sistema de archivos dada de la lista de sistemas de archivos conocidos, si es conocida, y devuelve TCL_OK. Si el sistema de archivos no está registrado actualmente, se devuelve TCL_ERROR.

Tcl_FSData devolverá el clientData asociado con el sistema de archivos dado, si ese sistema de archivos está registrado. De lo contrario, devolverá NULL.

Tcl_FSMountsChanged se utiliza para informar al núcleo de Tcl que el conjunto de puntos de montaje para el sistema de archivos dado (ya registrado) ha cambiado, y que las representaciones de archivos almacenadas en caché, por lo tanto, pueden no ser correctas.

Las muchas funciones en esta estructura se dividen en tres categorías: funciones de infraestructura (casi todas las cuales deben implementarse), funciones operativas (que deben implementarse si se proporciona un sistema de archivos completo) y funciones de eficiencia (que solo necesitan implementarse si se pueden hacer de manera eficiente, o si tienen efectos secundarios que son requeridos por el sistema de archivos; Tcl tiene emulaciones menos eficientes a las que puede recurrir). Es importante notar que, en la versión actual de Tcl, la mayoría de estas soluciones alternativas solo se utilizan para manejar comandos iniciados en Tcl, no en C. Lo que esto significa es que, si se emite un comando file rename en Tcl, y los sistemas de archivos relevantes no implementan su Tcl_FSRenameFileProc, el núcleo de Tcl recurrirá a una combinación de otras funciones del sistema de archivos (usará Tcl_FSCopyFileProc seguido de Tcl_FSDeleteFileProc, y si Tcl_FSCopyFileProc no está implementado, hay una solución alternativa adicional). Sin embargo, si se emite un comando Tcl_FSRenameFileProc a nivel de C, no ocurre ninguna de estas soluciones alternativas. Esto es cierto, excepto para las últimas cuatro entradas en la tabla del sistema de archivos (lstat, load, getcwd y chdir) para las cuales efectivamente ocurren soluciones alternativas a nivel de C.

Cualquier función que tome nombres de ruta en forma Tcl_Obj las toma en forma UTF-8. La API de infraestructura del sistema de archivos está diseñada para admitir la conversión eficiente y en caché de estas rutas UTF-8 a otras representaciones nativas.

EFICIENCIA DEL SISTEMA DE ARCHIVOS

Estas funciones no necesitan implementarse para un sistema de archivos particular porque el núcleo tiene una implementación de respaldo disponible. Vea cada descripción individual para conocer las consecuencias de dejar el campo en NULL.

LSTATPROC

Función para procesar una llamada Tcl_FSLstat. Si no se implementa, Tcl intentará usar la statProc definida anteriormente en su lugar. Por lo tanto, solo necesita implementarse si un sistema de archivos puede diferenciar entre llamadas stat y lstat.

typedef int Tcl_FSLstatProc(
        Tcl_Obj *pathPtr,
        Tcl_StatBuf *statPtr);

El comportamiento de esta función es muy similar al de la Tcl_FSStatProc definida anteriormente, excepto que si se aplica a un enlace simbólico, devuelve información sobre el enlace, no sobre el archivo de destino.

COPYFILEPROC

Función para procesar una llamada Tcl_FSCopyFile. Si no se implementa, Tcl recurrirá a open-r, open-w y fcopy como mecanismo de copia. Por lo tanto, solo necesita implementarse si el sistema de archivos puede realizar esa acción de manera más eficiente.

typedef int Tcl_FSCopyFileProc(
        Tcl_Obj *srcPathPtr,
        Tcl_Obj *destPathPtr);

El valor de retorno es un resultado estándar de Tcl que indica si ocurrió un error en el proceso de copia. Tenga en cuenta que destPathPtr es el nombre del archivo que debe convertirse en la copia de srcPathPtr. Nunca es el nombre de un directorio en el que se pueda copiar srcPathPtr (es decir, la función es mucho más simple que el subcomando file copy a nivel de Tcl). Tenga en cuenta que, si el sistema de archivos admite enlaces simbólicos, Tcl siempre llamará a esta función y no a copyDirectoryProc cuando sea necesario copiarlos (incluso si son enlaces simbólicos a directorios). Finalmente, si el sistema de archivos determina que no puede admitir la acción file copy, llamar a Tcl_SetErrno(EXDEV) y devolver un resultado que no sea TCL_OK indicará a Tcl que utilice sus mecanismos de respaldo estándar.

RENAMEFILEPROC

Función para procesar una llamada Tcl_FSRenameFile. Si no se implementa, Tcl recurrirá a un mecanismo de copia y eliminación. Por lo tanto, solo necesita implementarse si el sistema de archivos puede realizar esa acción de manera más eficiente.

typedef int Tcl_FSRenameFileProc(
        Tcl_Obj *srcPathPtr,
        Tcl_Obj *destPathPtr);

El valor de retorno es un resultado estándar de Tcl que indica si ocurrió un error en el proceso de renombrado. Si el sistema de archivos determina que no puede admitir la acción file rename, llamar a Tcl_SetErrno(EXDEV) y devolver un resultado que no sea TCL_OK indicará a Tcl que utilice sus mecanismos de respaldo estándar.

COPYDIRECTORYPROC

Función para procesar una llamada Tcl_FSCopyDirectory. Si no se implementa, Tcl recurrirá a un mecanismo recursivo de file mkdir, file copy. Por lo tanto, solo necesita implementarse si el sistema de archivos puede realizar esa acción de manera más eficiente.

typedef int Tcl_FSCopyDirectoryProc(
        Tcl_Obj *srcPathPtr,
        Tcl_Obj *destPathPtr,
        Tcl_Obj **errorPtr);

El valor de retorno es un resultado estándar de Tcl que indica si ocurrió un error en el proceso de copia. Si ocurre un error, el nombre del archivo o directorio que causó el error debe colocarse en errorPtr. Tenga en cuenta que destPathPtr es el nombre del nombre del directorio que debe convertirse en la imagen especular de srcPathPtr. No es el nombre de un directorio en el que se deba copiar srcPathPtr (es decir, la función es mucho más simple que el subcomando file copy a nivel de Tcl). Finalmente, si el sistema de archivos determina que no puede admitir la acción de copia de directorio, llamar a Tcl_SetErrno(EXDEV) y devolver un resultado que no sea TCL_OK indicará a Tcl que utilice sus mecanismos de respaldo estándar.

LOADFILEPROC

Función para procesar una llamada Tcl_FSLoadFile. Si no se implementa, Tcl recurrirá a una copia a un archivo temporal nativo seguido de un Tcl_FSLoadFile en esa copia temporal. Por lo tanto, solo necesita implementarse si el sistema de archivos puede cargar código directamente, o puede implementarse simplemente para devolver TCL_ERROR para deshabilitar completamente la funcionalidad de carga en este sistema de archivos.

typedef int Tcl_FSLoadFileProc(
        Tcl_Interp *interp,
        Tcl_Obj *pathPtr,
        Tcl_LoadHandle *handlePtr,
        Tcl_FSUnloadFileProc *unloadProcPtr);

Devuelve un código de finalización estándar de Tcl. Si ocurre un error, se deja un mensaje de error en el resultado del interp. La función carga dinámicamente un archivo de código binario en memoria. En una carga exitosa, handlePtr se completará con un token para el archivo cargado dinámicamente, y unloadProcPtr se completará con la dirección de un procedimiento. El procedimiento de descarga se llamará con el Tcl_LoadHandle dado como su único parámetro cuando Tcl necesite descargar el archivo. Por ejemplo, para el sistema de archivos nativo, el Tcl_LoadHandle devuelto es actualmente un token que se puede usar en el TclpFindSymbol privado para acceder a funciones en el nuevo código. Cada sistema de archivos es libre de definir el Tcl_LoadHandle según lo requiera. Finalmente, si el sistema de archivos determina que no puede admitir la acción de carga de archivos, llamar a Tcl_SetErrno(EXDEV) y devolver un resultado que no sea TCL_OK indicará a Tcl que utilice sus mecanismos de respaldo estándar.

UNLOADFILEPROC

Función para descargar un archivo previamente cargado con éxito. Si la carga se implementó, entonces esta también debería implementarse, si hay alguna acción de limpieza requerida.

typedef void Tcl_FSUnloadFileProc(
        Tcl_LoadHandle loadHandle);

GETCWDPROC

Función para procesar una llamada Tcl_FSGetCwd. La mayoría de los sistemas de archivos no necesitan implementar esto. Por lo general, solo se llamará una vez, si getcwd se llama antes de chdir. Puede ser NULL.

typedef Tcl_Obj *Tcl_FSGetCwdProc(
        Tcl_Interp *interp);

Si el sistema de archivos admite una noción nativa de un directorio de trabajo actual (que podría cambiar independientemente de Tcl), esta función debe devolver ese cwd como resultado, o NULL si no se pudo determinar el directorio actual (por ejemplo, el usuario no tiene los permisos adecuados en el directorio cwd). Si se devuelve NULL, se deja un mensaje de error en el resultado del interp.

CHDIRPROC

Función para procesar una llamada Tcl_FSChdir. Si los sistemas de archivos no implementan esto, se emulará mediante una serie de verificaciones de acceso al directorio. De lo contrario, los sistemas de archivos virtuales que sí lo implementan solo necesitan responder con un resultado de retorno positivo si el pathPtr es un directorio válido y accesible en su sistema de archivos. No necesitan recordar el resultado, ya que se recordará automáticamente para su uso por Tcl_FSGetCwd. Los sistemas de archivos reales deben realizar la acción correcta (es decir, llamar a la API de chdir del sistema correcta).

typedef int Tcl_FSChdirProc(
        Tcl_Obj *pathPtr);

El Tcl_FSChdirProc cambia el directorio de trabajo actual de la aplicación al valor especificado en pathPtr. La función devuelve -1 en caso de error o 0 en caso de éxito.
