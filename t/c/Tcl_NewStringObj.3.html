ARGUMENTOS

const char * bytes (in)
Punta al primer byte de un array de bytes UTF-8 utilizado para establecer o añadir a un valor de cadena. Este array de bytes puede contener nulos incrustados, a menos que numChars sea negativo. (Las aplicaciones que necesiten nulos deben representarlos como la secuencia de dos bytes \300\200, usar Tcl_ExternalToUtf para convertir, o usar Tcl_NewByteArrayObj si la cadena es una colección de bytes no interpretados.)
int length (in)
El número de bytes a copiar de bytes al inicializar, establecer o añadir a un valor de cadena. Si es negativo, se utilizan todos los bytes hasta el primer nulo.
const Tcl_UniChar * unicode (in)
Punta al primer byte de un array de caracteres Unicode utilizado para establecer o añadir a un valor de cadena. Este array de bytes puede contener nulos incrustados a menos que numChars sea negativo.
int numChars (in)
El número de caracteres Unicode a copiar de unicode al inicializar, establecer o añadir a un valor de cadena. Si es negativo, se utilizan todos los caracteres hasta el primer carácter nulo.
int index (in)
El índice del carácter Unicode a devolver.
int first (in)
El índice del primer carácter Unicode en el rango Unicode a devolver como nuevo valor.
int last (in)
El índice del último carácter Unicode en el rango Unicode a devolver como nuevo valor.
Tcl_Obj * objPtr (in/out)
Punta a un valor a manipular.
Tcl_Obj * appendObjPtr (in)
El valor a añadir a objPtr en Tcl_AppendObjToObj.
int * lengthPtr (out)
Si no es NULL, el lugar donde Tcl_GetStringFromObj almacenará la longitud de la representación de cadena de un valor.
const char * string (in)
Cadena terminada en nulo a añadir a objPtr.
va_list argList (in)
Una lista de argumentos que debe haber sido inicializada con va_start, y limpiada con va_end.
int limit (in)
Número máximo de bytes a añadir.
const char * ellipsis (in)
El sufijo a añadir cuando el límite lleva a truncamiento de cadena. Si se pasa NULL, se usa el sufijo "...".
const char * format (in)
Cadena de control de formato incluyendo especificadores de conversión %.
int objc (in)
El número de elementos a formatear o concatenar.
Tcl_Obj * objv[] (in)
El array de valores a formatear o concatenar.
int newLength (in)
La longitud nueva para el valor de cadena de objPtr, sin incluir el carácter nulo final.

DESCRIPCIÓN

Los procedimientos descritos en esta página de manual permiten manipular valores de Tcl como cadenas. Utilizan la representación interna del valor para almacenar información adicional, haciendo así las operaciones de manipulación de cadena más eficientes. En particular, optimizan las operaciones de adición al asignar espacio adicional para la cadena, evitando copias para cada adición. También optimizan los índices y cálculos de longitud al calcular y almacenar en caché la representación Unicode del valor. Cuando se utilizan las familias de funciones Tcl_Append* donde el resultado del intérprete es el valor a añadir, es importante llamar primero a Tcl_ResetResult para asegurarse de no añadir intencionalmente datos existentes en el valor de resultado.

Tcl_NewStringObj y Tcl_SetStringObj crean un nuevo valor o modifican un valor existente para almacenar una copia de la cadena dada por bytes y length. Tcl_NewUnicodeObj y Tcl_SetUnicodeObj crean un nuevo valor o modifican un valor existente para almacenar una copia de la cadena Unicode dada por unicode y numChars. Tcl_NewStringObj y Tcl_NewUnicodeObj devuelven un puntero a un valor nuevo con contador de referencias cero. Los cuatro procedimientos establecen el valor para almacenar una copia de la cadena especificada. Tcl_SetStringObj y Tcl_SetUnicodeObj liberan cualquier representación anterior de cadena o interna del valor.

Tcl_GetStringFromObj y Tcl_GetString devuelven la representación de cadena de un valor. Se proporciona mediante el puntero de byte devuelto y (para Tcl_GetStringFromObj) la longitud, que se almacena en lengthPtr si no es NULL. Si la representación UTF de un valor es inválida (su puntero de byte es NULL), se regenera la representación de cadena a partir de la representación interna del valor. El almacenamiento al que apunta el puntero de byte devuelto es propiedad del gestor de valores. Se pasa de vuelta como un puntero de escritura para que los autores de extensiones puedan modificar la representación de cadena dentro del Tcl_UpdateStringProc de su Tcl_ObjType. Excepto para este propósito limitado, el puntero devuelto por Tcl_GetStringFromObj o Tcl_GetString debe tratarse como de solo lectura. Se recomienda asignarlo a una variable (const char *). Incluso en las situaciones limitadas en las que escribir en este puntero es aceptable, se debe tener cuidado de respetar las semánticas de copia en escritura requeridas por Tcl_Obj, con llamadas apropiadas a Tcl_IsShared y Tcl_DuplicateObj antes de cualquier modificación en el lugar de la representación de cadena. El procedimiento Tcl_GetString se utiliza en el caso común en el que el llamante no necesita la longitud de la representación de cadena.

Tcl_GetUnicodeFromObj y Tcl_GetUnicode devuelven el valor de un valor como cadena Unicode. Se proporciona mediante el puntero devuelto y (para Tcl_GetUnicodeFromObj) la longitud, que se almacena en lengthPtr si no es NULL. El almacenamiento al que apunta el puntero de byte es propiedad del gestor de valores y no debe ser modificado por el llamante. El procedimiento Tcl_GetUnicode se utiliza en el caso común en el que el llamante no necesita la longitud de la representación de cadena Unicode.

Tcl_GetUniChar devuelve el carácter en la representación Unicode del valor en el índice dado. Se asume que el índice está en el rango adecuado.

Tcl_GetRange devuelve un nuevo valor compuesto por los caracteres entre first y last (incluidos) en la representación Unicode del valor. Si la representación Unicode del valor es inválida, se regenera la representación Unicode del valor a partir de la representación de cadena del valor. Si first < 0, la cadena devuelta comienza al principio del valor. Si last < 0, la cadena devuelta termina al final del valor.

Tcl_GetCharLength devuelve la longitud del carácter en la representación Unicode del valor. Se asume que el índice está en el rango adecuado.

DESCRIPTION

These procedures provide a C-language interface to Tcl's internal object representation. Tcl objects (Tcl_Obj) are a way of representing values that can have multiple internal representations (e.g., string, integer, double, list, dictionary). The object system automatically converts between representations as needed, optimizing for performance. This can make C code more efficient and easier to write.

Tcl_NewObj creates a new, empty object with a string representation and a reference count of 1. The string representation is initially empty. The new object has a reference count of 1.

Tcl_NewStringObj creates a new object and initializes its string representation from the given byte string bytes of length length. If length is -1, then bytes is treated as a null-terminated string. The new object has a reference count of 1.

Tcl_NewUnicodeObj creates a new object and initializes its internal representation using the Unicode characters in unicode, which has length numChars. The new object has a reference count of 1.

Tcl_NewBinaryObj creates a new object and initializes its internal representation using the binary data in bytes, which has length length. The new object has a reference count of 1.

Tcl_DuplicateObj creates a new object that is a duplicate of objPtr. The new object is given a reference count of 1. If the original object's value is shared, the duplicate object initially shares the same internal representation. If the duplicated object is modified later, it will be internally copied to ensure that the modification only affects the duplicate. Note that this does not increment the reference count of the original object.

Tcl_InvalidateObj marks an object's internal representation as invalid. This forces Tcl to recompute the representation the next time it is needed. This is useful when an object's value has been changed in a way that is not reflected in its current internal representation.

Tcl_NewDictObj creates a new, empty dictionary object. The new object has a reference count of 1.

Tcl_DictObjPut inserts or replaces a key-value pair in the dictionary dictPtr. keyPtr specifies the key and valuePtr specifies the value. If the key already exists, its value is replaced with valuePtr. If the key does not exist, the new key-value pair is added to the dictionary. This procedure returns TCL_OK on success and TCL_ERROR if an error occurs (e.g., if dictPtr is not a dictionary).

Tcl_DictObjAppendFile reads the contents of the channel chan and appends them as values to the dictionary dictPtr. The mode argument specifies how the file contents should be interpreted. This procedure returns TCL_OK on success and TCL_ERROR if an error occurs.

Tcl_DictObjGet retrieves the value associated with the key keyPtr from the dictionary dictPtr. If the key is found, the associated value is stored in the object pointed to by valuePtrPtr, and the procedure returns TCL_OK. If the key is not found, the procedure returns TCL_ERROR.

Tcl_DictObjRemove removes the key-value pair associated with the key keyPtr from the dictionary dictPtr. If the key is found and removed, the procedure returns TCL_OK. If the key is not found, the procedure returns TCL_ERROR.

Tcl_DictObjSize returns the number of key-value pairs in the dictionary dictPtr by storing the result in the integer pointed to by sizePtr. This procedure returns TCL_OK on success and TCL_ERROR if dictPtr is not a dictionary.

Tcl_GetObjType returns a pointer to a string identifying the type of the object's internal representation. This is useful for debugging and can be used to determine if an object has a particular representation. Note that the returned string is statically allocated and should not be modified.

Tcl_SetObjType changes the internal representation of an object to the one specified by typePtr. This is typically used only internally by Tcl to switch representations. The type information is provided by a Tcl_RegisterObjType.

Tcl_GetObjectType returns a pointer to the Tcl_ObjType structure that describes the object's internal representation.

Tcl_InitHashTable initializes a hash table pointed to by tablePtr. keyType specifies the type of keys that will be used in the hash table. Tcl provides several standard key types, such as TCL_STRING_KEYS and TCL_ONE_WORD_KEYS.

Tcl_Alloc, Tcl_Realloc, and Tcl_Free are Tcl's memory allocation procedures. They are generally preferred over the standard C library functions for memory allocation within Tcl, as they may provide better performance and error handling.

Tcl_AppendToObj appends the data given by bytes and length to the string representation of the value specified by objPtr. If the value has an invalid string representation, then an attempt is made to convert bytes to the Unicode format. If the conversion is successful, then the converted form of bytes is appended to the value's Unicode representation. Otherwise, the value's Unicode representation is invalidated and converted to the UTF format, and bytes is appended to the value's new string representation. Eventually buffer growth is done by large allocations to optimize multiple calls.

Tcl_AppendUnicodeToObj appends the Unicode string given by unicode and numChars to the value specified by objPtr. If the value has an invalid Unicode representation, then unicode is converted to the UTF format and appended to the value's string representation. Appends are optimized to handle repeated appends relatively efficiently (it over-allocates the string or Unicode space to avoid repeated reallocations and copies of value's string value).

Tcl_AppendObjToObj is similar to Tcl_AppendToObj, but it appends the string or Unicode value (whichever exists and is best suited to be appended to objPtr) of appendObjPtr to objPtr.

Tcl_AppendStringsToObj is similar to Tcl_AppendToObj except that it can be passed more than one value to append and each value must be a null-terminated string (i.e. none of the values may contain internal null characters). Any number of string arguments may be provided, but the last argument must be (char *)NULL to indicate the end of the list.

Tcl_AppendStringsToObjVA is the same as Tcl_AppendStringsToObj except that instead of taking a variable number of arguments it takes an argument list.

Tcl_AppendLimitedToObj is similar to Tcl_AppendToObj except that it imposes a limit on how many bytes are appended. This can be handy when the string to be appended might be very large, but the value being constructed should not be allowed to grow without bound. A common usage is when constructing an error message, where the end result should be kept short enough to be read. Bytes from bytes are appended to objPtr, but no more than limit bytes total are to be appended. If the limit prevents all length bytes that are available from being appended, then the appending is done so that the last bytes appended are from the string ellipsis. This allows for an indication of the truncation to be left in the string. When length is -1, all bytes up to the first zero byte are appended, subject to the limit. When ellipsis is NULL, the default string ... is used. When ellipsis is non-NULL, it must point to a zero-byte-terminated string in Tcl's internal UTF encoding. The number of bytes appended can be less than the lesser of length and limit when appending fewer bytes is necessary to append only whole multi-byte characters.

Tcl_Format is the C-level interface to the engine of the format command. The actual command procedure for format is little more than

Tcl_Format(interp, Tcl_GetString(objv[1]), objc-2, objv+2);

The objc Tcl_Obj values in objv are formatted into a string according to the conversion specification in format argument, following the documentation for the format command. The resulting formatted string is converted to a new Tcl_Obj with refcount of zero and returned. If some error happens during production of the formatted string, NULL is returned, and an error message is recorded in interp, if interp is non-NULL.

Tcl_AppendFormatToObj is an appending alternative form of Tcl_Format with functionality equivalent to:

Tcl_Obj *newPtr = Tcl_Format(interp, format, objc, objv);
if (newPtr == NULL) return TCL_ERROR;
Tcl_AppendObjToObj(objPtr, newPtr);
Tcl_DecrRefCount(newPtr);
return TCL_OK;

but with greater convenience and efficiency when the appending functionality is needed.

Tcl_ObjPrintf serves as a replacement for the common sequence

char buf[SOME_SUITABLE_LENGTH];
sprintf(buf, format, ...);
Tcl_NewStringObj(buf, -1);

but with greater convenience and no need to determine SOME_SUITABLE_LENGTH. The formatting is done with the same core formatting engine used by Tcl_Format. This means the set of supported conversion specifiers is that of the format command but the behavior is as similar as possible to sprintf. Format specifiers which were added by C99 (like "hh", "ll", "j", "z", "t", "L") are not supported. When a conversion specifier passed to Tcl_ObjPrintf includes a precision, the value is taken as a number of bytes, as sprintf does, and not as a number of characters, as format does. This is done on the assumption that C code is more likely to know how many bytes it is passing around than the number of encoded characters those bytes happen to represent. The variable number of arguments passed in should be of the types that would be suitable for passing to sprintf. Note in this example usage, x is of type int.

int x = 5;
Tcl_Obj *objPtr = Tcl_ObjPrintf("Value is %d", x);

If the value of format contains internal inconsistencies or invalid specifier formats, the formatted string result produced by Tcl_ObjPrintf will be an error message describing the error. It is impossible however to provide runtime protection against mismatches between the format and any subsequent arguments. Compile-time protection may be provided by some compilers.

Tcl_AppendPrintfToObj is an appending alternative form of Tcl_ObjPrintf with functionality equivalent to

Tcl_Obj *newPtr = Tcl_ObjPrintf(format, ...);
Tcl_AppendObjToObj(objPtr, newPtr);
Tcl_DecrRefCount(newPtr);

but with greater convenience and efficiency when the appending functionality is needed.

The Tcl_SetObjLength procedure changes the length of the string value of its objPtr argument. If the newLength argument is greater than the space allocated for the value's string, then the string space is reallocated and the old value is copied to the new space; the bytes between the old length of the string and the new length may have arbitrary values. If the newLength argument is less than the current length of the value's string, with objPtr->length is reduced without reallocating the string space; the original allocated size for the string is recorded in the value, so that the string length can be enlarged in a subsequent call to Tcl_SetObjLength without reallocating storage. In all cases Tcl_SetObjLength leaves a null character at objPtr->bytes[newLength].

Tcl_AttemptSetObjLength is identical in function to Tcl_SetObjLength except that if sufficient memory to satisfy the request cannot be allocated, it does not cause the Tcl interpreter to panic. Thus, if newLength is greater than the space allocated for the value's string, and there is not enough memory available to satisfy the request, Tcl_AttemptSetObjLength will take no action and return 0 to indicate failure. If there is enough memory to satisfy the request, Tcl_AttemptSetObjLength behaves just like Tcl_SetObjLength and returns 1 to indicate success.

The Tcl_ConcatObj function returns a new string value whose value is the space-separated concatenation of the string representations of all of the values in the objv array. Tcl_ConcatObj eliminates leading and trailing white space as it copies the string representations of the objv array to the result. If an element of the objv array consists of nothing but white space, then that value is ignored entirely. This white-space removal was added to make the output of the concat command cleaner-looking. Tcl_ConcatObj returns a pointer to a newly-created value whose ref count is zero.

Tcl_GetString returns a pointer to the string representation of the object objPtr. The caller must not modify the string; if the string needs to be modified, the object should be duplicated first using Tcl_DuplicateObj. The string is guaranteed to be null-terminated. If the object does not currently have a string representation, one is created on the fly.

Tcl_GetBoolean, Tcl_GetInt, Tcl_GetDouble, Tcl_GetNumElements, Tcl_GetIndex, Tcl_GetLong, and Tcl_GetWideInt attempt to convert the object objPtr into the specified type. If the conversion is successful, the value is stored in the location pointed to by the corresponding pointer argument (e.g., boolPtr, intPtr) and the procedure returns TCL_OK. If the conversion fails, an error message is left in the interpreter's error channel (if interp is not NULL) and the procedure returns TCL_ERROR. For Tcl_GetIndex, the names array provides a list of valid string values for the object. The msg argument is a prefix for error messages. The fixed flag indicates whether the list of names is fixed or may contain values that are also valid integers. The index of the matched name is stored in indexPtr*. For Tcl_GetNumElements, the number of elements is stored in numPtr*. If the object does not have a suitable internal representation, Tcl will attempt to convert it to one.

Tcl_NewBooleanObj, Tcl_NewIntObj, Tcl_NewDoubleObj, Tcl_NewLongObj, and Tcl_NewWideIntObj create new Tcl objects with the specified boolean, integer, double, long, or wide integer value, respectively. The new objects have a reference count of 1.

Tcl_FreeObj decrements the reference count of objPtr. If the reference count becomes zero, the object's internal representation is freed.

Tcl_IncrRefCount increments the reference count of objPtr. This should be called whenever a pointer to an object is saved for later use.

Tcl_DecrRefCount decrements the reference count of objPtr. This should be called whenever a saved pointer to an object is no longer needed. If the reference count drops to zero, the object's internal representation is freed.

Tcl_IsShared returns true if objPtr is currently shared (i.e., its reference count is greater than 1).

Tcl_IsSharedString returns true if the string representation of objPtr is shared. This is a quick check that can be useful if you only care about modifying the string representation.

Tcl_GetLength returns the length of the string representation of the object objPtr. If the object does not have a string representation, one is created on the fly. This function is equivalent to calling Tcl_GetString and then using strlen() on the result, except that it has been optimized to avoid unnecessary string conversions.
