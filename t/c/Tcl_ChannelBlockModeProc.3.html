DESCRIPCIÓN

Tcl utiliza una arquitectura de canales de dos niveles. Ofrece un nivel general para permitir que los programas C y Tcl realicen entrada y salida utilizando las mismas APIs para una variedad de archivos, dispositivos, sockets, etc. Las APIs de C del nivel general se describen en la página del manual Tcl_OpenFileChannel.

El nivel inferior proporciona drivers de canal específicos para cada tipo de dispositivo soportado en cada plataforma. Esta página del manual describe las APIs que comunican entre el nivel general y los drivers de canal específicos. También explica cómo se pueden añadir nuevos tipos de canales proporcionando nuevos drivers de canal.

Los drivers de canal consisten en varios componentes: Primero, cada driver de canal proporciona una estructura Tcl_ChannelType que contiene punteros a los procedimientos que implementan las diferentes operaciones utilizadas por el nivel general para comunicarse con el driver de canal. La estructura Tcl_ChannelType y los procedimientos referenciados por ella se describen en la sección TCL_CHANNELTYPE, más adelante.

Segundo, los drivers de canal suelen proporcionar un comando Tcl para crear instancias de ese tipo de canal. Por ejemplo, el comando Tcl open crea canales que utilizan los drivers de canal de archivo y de comandos, y el comando Tcl socket crea canales que utilizan protocolos de red TCP.

Tercero, un driver de canal opcionalmente proporciona una función C para abrir instancias de ese tipo de canal. Por ejemplo, Tcl_OpenFileChannel abre un canal que utiliza el driver de canal de archivo, y Tcl_OpenTcpClient abre un canal que utiliza el protocolo de red TCP. Estas funciones de creación suelen utilizar Tcl_CreateChannel internamente para abrir el canal.

Para añadir un nuevo tipo de canal, debes implementar una API C o un comando Tcl que abra un canal invocando Tcl_CreateChannel. Cuando tu driver llama a Tcl_CreateChannel, pasa una estructura Tcl_ChannelType que describe los procedimientos de entrada/salida de tu driver. El nivel general invocará entonces los procedimientos referenciados en esa estructura para realizar operaciones en el canal.

Tcl_CreateChannel abre un nuevo canal y asocia typePtr y instanceData con él. El canal se abre en el modo indicado por mask. Para una discusión sobre los drivers de canal, sus operaciones y la estructura Tcl_ChannelType, véase la sección TCL_CHANNELTYPE, más adelante.

Tcl_CreateChannel interactúa con el código que gestiona los canales estándar. Una vez que un canal estándar ha sido inicializado mediante una llamada a Tcl_GetStdChannel o una llamada a Tcl_SetStdChannel, el cierre de este canal hará que la siguiente llamada a Tcl_CreateChannel restablezca el canal como el canal estándar. Véase Tcl_StandardChannels para una generalización sobre los canales estándar y el comportamiento de la biblioteca Tcl con respecto a ellos.

Tcl_GetChannelInstanceData devuelve los datos de instancia asociados con el canal en channel. Esto es lo mismo que el argumento instanceData en la llamada a Tcl_CreateChannel que creó este canal.

Tcl_GetChannelType devuelve un puntero a la estructura Tcl_ChannelType utilizada por el canal en el argumento channel. Esto es lo mismo que el argumento typePtr en la llamada a Tcl_CreateChannel que creó este canal.

Tcl_GetChannelName devuelve una cadena que contiene el nombre asociado con el canal, o NULL si el argumento channelName de Tcl_CreateChannel fue NULL.

Tcl_GetChannelHandle coloca el handle del dispositivo del sistema operativo asociado con channel para la direction dada en handlePtr.

TCL_CHANNELTYPE

Un controlador de canal proporciona una estructura Tcl_ChannelType que contiene punteros a funciones que implementan las diversas operaciones en un canal; estas operaciones se invocan según sea necesario por la capa genérica. La estructura fue versionada a partir de Tcl 8.3.2/8.4 para corregir un problema con los controladores de canal apilados. Vea la sección OLD CHANNEL TYPES a continuación para más detalles sobre la estructura antigua.

La estructura Tcl_ChannelType contiene los siguientes campos:

typedef struct Tcl_ChannelType {
        const char *typeName;
        Tcl_ChannelTypeVersion version;
        Tcl_DriverCloseProc *closeProc;
        Tcl_DriverInputProc *inputProc;
        Tcl_DriverOutputProc *outputProc;
        Tcl_DriverSeekProc *seekProc;
        Tcl_DriverSetOptionProc *setOptionProc;
        Tcl_DriverGetOptionProc *getOptionProc;
        Tcl_DriverWatchProc *watchProc;
        Tcl_DriverGetHandleProc *getHandleProc;
        Tcl_DriverClose2Proc *close2Proc;
        Tcl_DriverBlockModeProc *blockModeProc;
        Tcl_DriverFlushProc *flushProc;
        Tcl_DriverHandlerProc *handlerProc;
        Tcl_DriverWideSeekProc *wideSeekProc;
        Tcl_DriverThreadActionProc *threadActionProc;
        Tcl_DriverTruncateProc *truncateProc;
} Tcl_ChannelType;

No es necesario proporcionar implementaciones para todas las operaciones del canal. Las que no sean necesarias pueden establecerse en NULL en la estructura: blockModeProc, seekProc, setOptionProc, getOptionProc, getHandleProc y close2Proc, además de flushProc, handlerProc, threadActionProc y truncateProc. Otras funciones que no se pueden implementar de forma significativa deben devolver EINVAL cuando se llamen, para indicar que las operaciones que representan no están disponibles. Tenga en cuenta también que wideSeekProc puede ser NULL si seekProc lo es.

El usuario solo debe usar la estructura anterior para la instanciación de Tcl_ChannelType. Al referenciar campos en una estructura Tcl_ChannelType, se deben usar las siguientes funciones para obtener los valores: Tcl_ChannelName, Tcl_ChannelVersion, Tcl_ChannelBlockModeProc, Tcl_ChannelCloseProc, Tcl_ChannelClose2Proc, Tcl_ChannelInputProc, Tcl_ChannelOutputProc, Tcl_ChannelSeekProc, Tcl_ChannelWideSeekProc, Tcl_ChannelThreadActionProc, Tcl_ChannelTruncateProc, Tcl_ChannelSetOptionProc, Tcl_ChannelGetOptionProc, Tcl_ChannelWatchProc, Tcl_ChannelGetHandleProc, Tcl_ChannelFlushProc o Tcl_ChannelHandlerProc.

El cambio en las estructuras se realizó de tal manera que los tipos de canal estándar son binariamente compatibles. Sin embargo, los tipos de canal que usan canales apilados (es decir, TLS, Trf) tienen nuevas versiones para corresponder al cambio anterior, ya que el código anterior para canales apilados tenía problemas.

TYPENAME

El campo typeName contiene una cadena terminada en nulo que identifica el tipo de dispositivo implementado por este controlador, por ejemplo, file o socket.

Este valor se puede recuperar con Tcl_ChannelName, que devuelve un puntero a la cadena.

VERSION

El campo version debe establecerse a la versión de la estructura que requiera. TCL_CHANNEL_VERSION_2 es el mínimo recomendado. TCL_CHANNEL_VERSION_3 debe establecerse para especificar el miembro wideSeekProc. TCL_CHANNEL_VERSION_4 debe establecerse para especificar el miembro threadActionProc (incluye wideSeekProc). TCL_CHANNEL_VERSION_5 debe establecerse para especificar los miembros truncateProc (incluye wideSeekProc y threadActionProc). Si no se establece en ninguno de estos, se asume que esta Tcl_ChannelType tiene la estructura original. Vea OLD CHANNEL TYPES para más detalles. Si bien Tcl reconocerá y funcionará con ambas estructuras, los canales apilados deben ser de al menos TCL_CHANNEL_VERSION_2 para funcionar correctamente.

Este valor se puede recuperar con Tcl_ChannelVersion, que devuelve una de TCL_CHANNEL_VERSION_5, TCL_CHANNEL_VERSION_4, TCL_CHANNEL_VERSION_3, TCL_CHANNEL_VERSION_2 o TCL_CHANNEL_VERSION_1.

BLOCKMODEPROC

El campo blockModeProc contiene la dirección de una función llamada por la capa genérica para establecer el modo de bloqueo y no bloqueo en el dispositivo. BlockModeProc debe coincidir con el siguiente prototipo:

typedef int Tcl_DriverBlockModeProc(
        ClientData instanceData,
        int mode);

instanceData es el mismo que el valor pasado a Tcl_CreateChannel cuando se creó este canal. El argumento mode es ya sea TCL_MODE_BLOCKING o TCL_MODE_NONBLOCKING para establecer el dispositivo en modo de bloqueo o no bloqueo. La función debe devolver cero si la operación fue exitosa, o un código de error POSIX distinto de cero si la operación falló.

Si la operación es exitosa, la función puede modificar el instanceDataSupplied para registrar que el canal entró en modo de bloqueo o no bloqueo y para implementar el comportamiento de bloqueo o no bloqueo. Para algunos tipos de dispositivos, el comportamiento de bloqueo y no bloqueo puede ser implementado por el sistema operativo subyacente; para otros tipos de dispositivos, el comportamiento debe ser emulado en el controlador de canal.

Este valor se puede recuperar con Tcl_ChannelBlockModeProc, que devuelve un puntero a la función.

Un controlador de canal que no proporciona un blockModeProc tiene que ser muy, muy cuidadoso. Tiene que decir a la capa genérica exactamente qué modo de bloqueo es aceptable para él, y esto también debería documentarse para el usuario, de modo que el modo de bloqueo del canal no se cambie a un valor inaceptable. Cualquier confusión aquí puede llevar al intérprete a un punto muerto (falso y difícil de encontrar).

CLOSEPROC Y CLOSE2PROC

El campo closeProc contiene la dirección de una función llamada por la capa genérica para limpiar la información relacionada con el controlador cuando se cierra el canal. CloseProc debe coincidir con el siguiente prototipo:

typedef int Tcl_DriverCloseProc(
        ClientData instanceData,
        Tcl_Interp *interp);

El argumento instanceData es el mismo que el valor proporcionado a Tcl_CreateChannel cuando se creó el canal. La función debe liberar cualquier almacenamiento mantenido por el controlador de canal para este canal y cerrar los dispositivos de entrada y salida encapsulados por este canal. Toda la salida en cola se habrá vaciado al dispositivo antes de que se llame a esta función, y no se invocarán más operaciones del controlador en esta instancia después de llamar al closeProc. NAME

Tcl_DriverBlockModeProc, Tcl_DriverCloseProc, Tcl_DriverClose2Proc, Tcl_DriverGetHandleProc, Tcl_DriverGetOptionProc, Tcl_DriverInputProc, Tcl_DriverOutputProc, Tcl_DriverSeekProc, Tcl_DriverSetOptionProc, Tcl_DriverWatchProc, Tcl_DriverThreadActionProc, Tcl_DriverTruncateProc, Tcl_ChannelType, Tcl_ChannelNewOptions, Tcl_ChannelOldOptions, Tcl_CreateChannel, Tcl_DriverData, Tcl_ChannelFlushProc, Tcl_ChannelHandlerProc, Tcl_ChannelThreadActionProc, Tcl_ChannelTruncateProc, Tcl_BadChannelOption - channel driver procedures and structures

SYNOPSIS

#include <tcl.h>

typedef struct Tcl_ChannelType {
    const char *typeName;
    Tcl_DriverBlockModeProc *blockModeProc;
    Tcl_DriverCloseProc *closeProc;
    Tcl_DriverInputProc *inputProc;
    Tcl_DriverOutputProc *outputProc;
    Tcl_DriverSeekProc *seekProc;
    Tcl_DriverSetOptionProc *setOptionProc;
    Tcl_DriverGetOptionProc *getOptionProc;
    Tcl_DriverWatchProc *watchProc;
    Tcl_DriverGetHandleProc *getHandleProc;
    Tcl_DriverClose2Proc *close2Proc;
    Tcl_DriverThreadActionProc *threadActionProc;
    Tcl_DriverTruncateProc *truncateProc;
} Tcl_ChannelType;

DESCRIPTION

Tcl provides a generic channel system that manages I/O for Tcl interpreters. This system allows applications to implement custom I/O devices as Tcl channels. This document describes the interface between the Tcl generic channel code and channel drivers, which are the Tcl_ChannelType structures that provide device-specific I/O operations.

The following table lists the Tcl_ChannelType fields and their purpose.

typeName
The name of the channel type. This is used by Tcl_GetChannelType to retrieve the Tcl_ChannelType structure by name. It is also used in error messages.
blockModeProc
This field contains the address of a function that is called by the generic layer to change the blocking mode of the channel. See Tcl_SetChannelOption for more details. If the channel driver does not support changing the blocking mode, this field should be NULL.
closeProc
This field contains the address of a function that is called by the generic layer to close the channel. This procedure should perform any device-specific cleanup actions required to close the channel. It should free any dynamically allocated storage associated with the channel. The procedure should return the value of the Tcl_SetErrno error code if an error occurs during closing, or 0 if the close was successful. The generic channel code may call this procedure multiple times on the same channel, so the procedure must be prepared to handle this.
inputProc
This field contains the address of a function that is called by the generic layer to read data from the channel. See Tcl_Read for more details. If the channel is write-only, this field should be NULL.
outputProc
This field contains the address of a function that is called by the generic layer to write data to the channel. See Tcl_Write for more details. If the channel is read-only, this field should be NULL.
seekProc
This field contains the address of a function that is called by the generic layer to seek within the channel. See Tcl_Seek for more details. If the channel does not support seeking, this field should be NULL.
setOptionProc
This field contains the address of a function that is called by the generic layer to set channel-specific options. See Tcl_SetChannelOption for more details. If the channel driver does not support any type-specific options, this field should be NULL.
getOptionProc
This field contains the address of a function that is called by the generic layer to get channel-specific options. See Tcl_GetChannelOption for more details. If the channel driver does not support any type-specific options, this field should be NULL.
watchProc
This field contains the address of a function that is called by the generic layer to initialize the event notification mechanism to notice events of interest on this channel. See Tcl_NotifyChannel for more details. If the channel driver does not support event notification, this field should be NULL.
getHandleProc
This field contains the address of a function that is called by the generic layer to retrieve a device-specific handle from the channel. See Tcl_GetChannelHandle for more details. If the channel does not use device-specific handles, this field should be NULL.
close2Proc
This field contains the address of a function that is called by the generic layer to close the channel, just before the channel is destroyed. This procedure is similar to the closeProc field, but it is only called once. It should be used to perform any device specific cleanup actions required to close the channel. It should free any dynamically allocated storage associated with the channel. The procedure should return the value of the Tcl_SetErrno error code if an error occurs during closing, or 0 if the close was successful. If this field is NULL, the generic channel code will call the closeProc instead.
threadActionProc
This field contains the address of the function called by the generic layer when a channel is created, closed, or going to move to a different thread, i.e. whenever thread-specific driver state might have to initialized or updated. See Tcl_CutChannel and Tcl_SpliceChannel for more detail. It can be NULL.
truncateProc
This field contains the address of the function called by the generic layer when a channel is truncated to some length. See Tcl_TruncateChannel for more details. It can be NULL.

TCL_CHANNEL_VERSION_1

This is the version number for the original Tcl_ChannelType structure (used before Tcl 8.4).

#define TCL_CHANNEL_VERSION_1 1

TCL_CHANNEL_VERSION_2

This is the version number for the Tcl_ChannelType structure used from Tcl 8.4 up to Tcl 8.6. This structure includes the threadActionProc and truncateProc fields.

#define TCL_CHANNEL_VERSION_2 2

TCL_CHANNEL_VERSION_3

This is the version number for the Tcl_ChannelType structure used from Tcl 8.7 onwards. This structure includes the version field.

#define TCL_CHANNEL_VERSION_3 3

TCL_CHANNEL_MAKE_BLOCKING

Used to set the blocking mode of a channel.

typedef int Tcl_DriverBlockModeProc(
        ClientData instanceData,
        int nonBlocking);

instanceData is the same as the value passed to Tcl_CreateChannel when this channel was created. nonBlocking is true if the mode should be non-blocking, false otherwise. The procedure should return 0 on success, or an error code suitable for use with Tcl_SetErrno on failure.

TCL_CHANNEL_CLOSE

Used to close a channel.

typedef int Tcl_DriverCloseProc(
        ClientData instanceData);

instanceData is the same as the value passed to Tcl_CreateChannel when this channel was created. The procedure should return 0 on success, or an error code suitable for use with Tcl_SetErrno on failure.

TCL_CHANNEL_CLOSE2

Used to close a channel just before it is destroyed.

typedef int Tcl_DriverClose2Proc(
        ClientData instanceData,
        Tcl_Interp *interp);

instanceData is the same as the value passed to Tcl_CreateChannel when this channel was created. interp is the interpreter to use for reporting errors. The procedure should return 0 on success, or an error code suitable for use with Tcl_SetErrno on failure.

TCL_CHANNEL_INPUT

Used to read data from a channel.

typedef int Tcl_DriverInputProc(
        ClientData instanceData,
        char *buf,
        int bufSize,
        Tcl_Error *errorCodePtr);

instanceData is the same as the value passed to Tcl_CreateChannel when this channel was created. buf is a buffer to store the read data. bufSize is the maximum amount of data to read. errorCodePtr is a pointer to a Tcl_Error structure that will be filled with error information if an error occurs.

The procedure should return the number of bytes read, or -1 if an error occurred. If an error occurred, the Tcl_Error structure pointed to by errorCodePtr should be filled with information about the error.

Note: The original Tcl_DriverInputProc prototype did not include the errorCodePtr argument. For compatibility with older channel drivers, the generic channel code will provide a NULL value for errorCodePtr if the driver was created using the older Tcl_ChannelType structure.

TCL_CHANNEL_OUTPUT

Used to write data to a channel.

typedef int Tcl_DriverOutputProc(
        ClientData instanceData,
        const char *buf,
        int toWrite,
        Tcl_Error *errorCodePtr);

instanceData is the same as the value passed to Tcl_CreateChannel when this channel was created. buf is a buffer containing the data to write. toWrite is the number of bytes to write. errorCodePtr is a pointer to a Tcl_Error structure that will be filled with error information if an error occurs.

The procedure should return the number of bytes written, or -1 if an error occurred. If an error occurred, the Tcl_Error structure pointed to by errorCodePtr should be filled with information about the error.

Note: The original Tcl_DriverOutputProc prototype did not include the errorCodePtr argument. For compatibility with older channel drivers, the generic channel code will provide a NULL value for errorCodePtr if the driver was created using the older Tcl_ChannelType structure.

TCL_CHANNEL_SEEK

Used to seek within a channel.

typedef Tcl_WideInt Tcl_DriverSeekProc(
        ClientData instanceData,
        Tcl_WideInt offset,
        int seekMode);

instanceData is the same as the value passed to Tcl_CreateChannel when this channel was created. offset is the offset to seek to. seekMode is one of SEEK_SET, SEEK_CUR, or SEEK_END.

The procedure should return the new offset from the beginning of the channel, or -1 if an error occurred. If an error occurred, the error code should be set using Tcl_SetErrno.

TCL_CHANNEL_SETOPTION

Used to set channel-specific options.

typedef int Tcl_DriverSetOptionProc(
        ClientData instanceData,
        const char *optionName,
        const Tcl_Obj *optionValue,
        Tcl_Interp *interp);

instanceData is the same as the value passed to Tcl_CreateChannel when this channel was created. optionName is the name of the option to set. optionValue is the value to set the option to. interp is the interpreter to use for reporting errors.

The procedure should return TCL_OK on success, or TCL_ERROR on failure. If an error occurred, an error message should be set in interp.

Note: The original Tcl_DriverSetOptionProc prototype took the option value as a string. For compatibility with older channel drivers, the generic channel code will convert the Tcl_Obj to a string if the driver was created using the older Tcl_ChannelType structure.

TCL_CHANNEL_GETOPTION

Used to get channel-specific options.

typedef int Tcl_DriverGetOptionProc(
        ClientData instanceData,
        const char *optionName,
        Tcl_Interp *interp);

instanceData is the same as the value passed to Tcl_CreateChannel when this channel was created. optionName is the name of the option to get. interp is the interpreter to use for reporting errors. The value of the option should be set in the interpreter's result.

The procedure should return TCL_OK on success, or TCL_ERROR on failure. If an error occurred, an error message should be set in interp.

Note: The original Tcl_DriverGetOptionProc prototype did not take the interp argument. For compatibility with older channel drivers, the generic channel code will provide a NULL value for interp if the driver was created using the older Tcl_ChannelType structure.

The generic channel code handles the following options for all channel types: -blocking, -buffering, -buffersize, -eofchar, -translation. If an optionName is not recognized by the driver's setOptionProc or getOptionProc, and if it is one of the generic options, the generic channel code will handle it. If the optionName is not recognized by the driver or the generic code, an error message will be generated in the interpreter's result. The message will list all generic options and all specific options supported by the channel driver. If a system call error occurs, the function should leave an error message in the result of interp if interp is not NULL. The function should also call Tcl_SetErrno to store an appropriate POSIX error code.

Some options are handled by the generic code and this function is never called to retrieve their value, e.g. -blockmode. Other options are specific to each channel type and the getOptionProc procedure of the channel driver will get called to implement them. The getOptionProc field can be NULL, which indicates that this channel type supports no type specific options.

This value can be retrieved with Tcl_ChannelGetOptionProc, which returns a pointer to the function.

WATCHPROC

The watchProc field contains the address of a function called by the generic layer to initialize the event notification mechanism to notice events of interest on this channel. WatchProc should match the following prototype:

typedef void Tcl_DriverWatchProc(
        ClientData instanceData,
        int mask);

The instanceData is the same as the value passed to Tcl_CreateChannel when this channel was created. The mask argument is an OR-ed combination of TCL_READABLE, TCL_WRITABLE and TCL_EXCEPTION; it indicates events the caller is interested in noticing on this channel.

The function should initialize device type specific mechanisms to notice when an event of interest is present on the channel. When one or more of the designated events occurs on the channel, the channel driver is responsible for calling Tcl_NotifyChannel to inform the generic channel module. The driver should take care not to starve other channel drivers or sources of callbacks by invoking Tcl_NotifyChannel too frequently. Fairness can be insured by using the Tcl event queue to allow the channel event to be scheduled in sequence with other events. See the description of Tcl_QueueEvent for details on how to queue an event.

This value can be retrieved with Tcl_ChannelWatchProc, which returns a pointer to the function.

GETHANDLEPROC

The getHandleProc field contains the address of a function called by the generic layer to retrieve a device-specific handle from the channel. GetHandleProc should match the following prototype:

typedef int Tcl_DriverGetHandleProc(
        ClientData instanceData,
        int direction,
        ClientData *handlePtr);

InstanceData is the same as the value passed to Tcl_CreateChannel when this channel was created. The direction argument is either TCL_READABLE to retrieve the handle used for input, or TCL_WRITABLE to retrieve the handle used for output.

If the channel implementation has device-specific handles, the function should retrieve the appropriate handle associated with the channel, according the direction argument. The handle should be stored in the location referred to by handlePtr, and TCL_OK should be returned. If the channel is not open for the specified direction, or if the channel implementation does not use device handles, the function should return TCL_ERROR.

This value can be retrieved with Tcl_ChannelGetHandleProc, which returns a pointer to the function.

FLUSHPROC

The flushProc field is currently reserved for future use. It should be set to NULL. FlushProc should match the following prototype:

typedef int Tcl_DriverFlushProc(
        ClientData instanceData);

This value can be retrieved with Tcl_ChannelFlushProc, which returns a pointer to the function.

HANDLERPROC

The handlerProc field contains the address of a function called by the generic layer to notify the channel that an event occurred. It should be defined for stacked channel drivers that wish to be notified of events that occur on the underlying (stacked) channel. HandlerProc should match the following prototype:

typedef int Tcl_DriverHandlerProc(
        ClientData instanceData,
        int interestMask);

InstanceData is the same as the value passed to Tcl_CreateChannel when this channel was created. The interestMask is an OR-ed combination of TCL_READABLE or TCL_WRITABLE; it indicates what type of event occurred on this channel.

This value can be retrieved with Tcl_ChannelHandlerProc, which returns a pointer to the function.

THREADACTIONPROC

The threadActionProc field contains the address of the function called by the generic layer when a channel is created, closed, or going to move to a different thread, i.e. whenever thread-specific driver state might have to initialized or updated. It can be NULL. The action TCL_CHANNEL_THREAD_REMOVE is used to notify the driver that it should update or remove any thread-specific data it might be maintaining for the channel.

The action TCL_CHANNEL_THREAD_INSERT is used to notify the driver that it should update or initialize any thread-specific data it might be maintaining using the calling thread as the associate. See Tcl_CutChannel and Tcl_SpliceChannel for more detail.

typedef void Tcl_DriverThreadActionProc(
        ClientData instanceData,
        int action);

InstanceData is the same as the value passed to Tcl_CreateChannel when this channel was created.

These values can be retrieved with Tcl_ChannelThreadActionProc, which returns a pointer to the function.

TRUNCATEPROC

The truncateProc field contains the address of the function called by the generic layer when a channel is truncated to some length. It can be NULL.

typedef int Tcl_DriverTruncateProc(
        ClientData instanceData,
        Tcl_WideInt length);

InstanceData is the same as the value passed to Tcl_CreateChannel when this channel was created, and length is the new length of the underlying file, which should not be negative. The result should be 0 on success or an errno code (suitable for use with Tcl_SetErrno) on failure.

These values can be retrieved with Tcl_ChannelTruncateProc, which returns a pointer to the function.

TCL_BADCHANNELOPTION

This procedure generates a “bad option” error message in an (optional) interpreter. It is used by channel drivers when an invalid Set/Get option is requested. Its purpose is to concatenate the generic options list to the specific ones and factorize the generic options error message string.

It always returns TCL_ERROR

An error message is generated in interp's result value to indicate that a command was invoked with a bad option. The message has the form

    bad option "blah": should be one of
    <...generic options...>+<...specific options...>
so you get for instance: 
    bad option "-blah": should be one of -blocking,
    -buffering, -buffersize, -eofchar, -translation,
    -peername, or -sockname
when called with optionList equal to “peername sockname”

“blah” is the optionName argument and “<specific options>” is a space separated list of specific option words. The function takes good care of inserting minus signs before each option, commas after, and an “or” before the last option.

OLD CHANNEL TYPES

The original (8.3.1 and below) Tcl_ChannelType structure contains the following fields:

typedef struct Tcl_ChannelType {
    const char *typeName;
    Tcl_DriverBlockModeProc *blockModeProc;
    Tcl_DriverCloseProc *closeProc;
    Tcl_DriverInputProc *inputProc;
    Tcl_DriverOutputProc *outputProc;
    Tcl_DriverSeekProc *seekProc;
    Tcl_DriverSetOptionProc *setOptionProc;
    Tcl_DriverGetOptionProc *getOptionProc;
    Tcl_DriverWatchProc *watchProc;
    Tcl_DriverGetHandleProc *getHandleProc;
    Tcl_DriverClose2Proc *close2Proc;
} Tcl_ChannelType;

It is still possible to create channel with the above structure. The internal channel code will determine the version. It is imperative to use the new Tcl_ChannelType structure if you are creating a stacked channel driver, due to problems with the earlier stacked channel implementation (in 8.2.0 to 8.3.1).

Prior to 8.4.0 (i.e. during the later releases of 8.3 and early part of the 8.4 development cycle) the Tcl_ChannelType structure contained the following fields:

typedef struct Tcl_ChannelType {
    const char *typeName;
    Tcl_ChannelTypeVersion version;
    Tcl_DriverCloseProc *closeProc;
    Tcl_DriverInputProc *inputProc;
    Tcl_DriverOutputProc *outputProc;
    Tcl_DriverSeekProc *seekProc;
    Tcl_DriverSetOptionProc *setOptionProc;
    Tcl_DriverGetOptionProc *getOptionProc;
    Tcl_DriverWatchProc *watchProc;
    Tcl_DriverGetHandleProc *getHandleProc;
    Tcl_DriverClose2Proc *close2Proc;
    Tcl_DriverBlockModeProc *blockModeProc;
    Tcl_DriverFlushProc *flushProc;
    Tcl_DriverHandlerProc *handlerProc;
    Tcl_DriverTruncateProc *truncateProc;
} Tcl_ChannelType;

When the above structure is registered as a channel type, the version field should always be TCL_CHANNEL_VERSION_2.
