Tcl(n) Tcl Built-In Commands Tcl(n)

NOMBRE

Tcl - Tool Command Language

SINOPSIS

Resumen de la sintaxis del lenguaje Tcl.

DESCRIPCIÓN

Las siguientes reglas definen la sintaxis y semántica del lenguaje Tcl:

[1] Comandos.
Un script Tcl es una cadena que contiene uno o más comandos. Los puntos y comas y los saltos de línea son separadores de comandos a menos que se citen como se describe a continuación. Los corchetes de cierre son terminadores de comandos durante la sustitución de comandos (ver más adelante) a menos que se citen.
[2] Evaluación.
Un comando se evalúa en dos pasos. Primero, el intérprete Tcl divide el comando en palabras y realiza las sustituciones descritas a continuación. Estas sustituciones se realizan de la misma manera para todos los comandos. En segundo lugar, la primera palabra se utiliza para localiza un procedimiento de comando para llevar a cabo el comando, luego todas las palabras del comando se pasan al procedimiento de comando. El procedimiento de comando es libre de interpretar cada una de sus palabras como quiera, ya sea como un entero, nombre de variable, lista o script Tcl. Diferentes comandos interpretan sus palabras de manera diferente.
[3] Palabras.
Las palabras de un comando están separadas por espacios en blanco (excepto los saltos de línea, que son separadores de comandos).
[4] Comillas dobles.
Si el primer carácter de una palabra es una comilla doble (“"”) entonces la palabra se termina con la siguiente comilla doble. Si los puntos y comas, corchetes de cierre o caracteres de espacio en blanco (incluidos los saltos de línea) aparecen entre las comillas, entonces se tratan como caracteres ordinarios y se incluyen en la palabra. La sustitución de comandos, la sustitución de variables y la sustitución de barras inversas se realizan en los caracteres entre las comillas como se describe a continuación. Las comillas dobles no se conservan como parte de la palabra.
[5] Expansión de argumentos.
Si una palabra comienza con la cadena “{*}” seguida de un carácter que no sea espacio en blanco, entonces el “{*}” inicial se elimina y el resto de la palabra se analiza y sustituye como cualquier otra palabra. Después de la sustitución, la palabra se analiza como una lista (sin sustituciones de comandos o variables; las sustituciones de barras inversas se realizan según lo normal para una lista y las palabras internas individuales pueden estar rodeadas de llaves o comillas) y sus palabras se añaden al comando que se está sustituyendo. Por ejemplo, “cmd a {*}{b [c]} d {*}{$e f {g h}}” es equivalente a “cmd a b {[c]} d {$e} f {g h}”.
[6] Llaves.
Si el primer carácter de una palabra es una llave de apertura (“{”) y la regla [5] no se aplica, entonces la palabra se termina con la llave de cierre correspondiente (“}”). Las llaves se anidan dentro de la palabra: por cada llave de apertura adicional debe haber una llave de cierre adicional (sin embargo, si una llave de apertura o cierre dentro de la palabra está citada con una barra invertida, entonces no se cuenta para localizar la llave de cierre correspondiente). No se realizan sustituciones en los caracteres entre las llaves, excepto para las sustituciones de barra invertida-salto de línea descritas a continuación, ni los puntos y comas, saltos de línea, corchetes de cierre o espacios en blanco reciben ninguna interpretación especial. La palabra consistirá exactamente en los caracteres entre las llaves exteriores, sin incluir las propias llaves.
[7] Sustitución de comandos.
Si una palabra contiene un corchete de apertura (“[”) entonces Tcl realiza la sustitución de comandos. Para hacerlo, invoca al intérprete Tcl recursivamente para procesar los caracteres siguientes al corchete de apertura como un script Tcl. El script puede contener cualquier número de comandos y debe terminar con un corchete de cierre (“]”). El resultado del script (es decir, el resultado de su último comando) se sustituye en la palabra en lugar de los corchetes y todos los caracteres entre ellos. Puede haber cualquier número de sustituciones de comandos en una sola palabra. La sustitución de comandos no se realiza en palabras encerradas entre llaves.
[8] Sustitución de variables.
Si una palabra contiene un signo de dólar (“$”) seguido de una de las formas descritas a continuación, entonces Tcl realiza la sustitución de variables: el signo de dólar y los caracteres siguientes son reemplazados en la palabra por el valor de una variable. La sustitución de variables puede tomar cualquiera de las siguientes formas:
$nombre
Nombre es el nombre de una variable escalar; el nombre es una secuencia de uno o más caracteres que son letras, dígitos, guiones bajos o separadores de namespaces (dos o más dos puntos). Las letras y los dígitos son únicamente los estándar ASCII (0–9, A–Z y a–z).
$nombre(índice)
Nombre da el nombre de una variable de array y índice da el nombre de un elemento dentro de ese array. Nombre solo puede contener letras, dígitos, guiones bajos y separadores de namespaces, y puede ser una cadena vacía. Las letras y los dígitos son únicamente los estándar ASCII (0–9, A–Z y a–z). Las sustituciones de comandos, las sustituciones de variables y las sustituciones de barras inversas se realizan en los caracteres del índice.
${nombre}
Nombre es el nombre de una variable escalar o un elemento de array. Puede contener cualquier carácter excepto llaves de cierre. Indica un elemento de array si nombre tiene el formato “nombreArray(índice)” donde nombreArray no contiene caracteres de paréntesis de apertura, “(”, ni caracteres de llave de cierre, “}”, y índice puede ser cualquier secuencia de caracteres excepto caracteres de llave de cierre. No se realizan sustituciones adicionales durante el análisis de nombre.

Puede haber cualquier número de sustituciones de variables en una sola palabra. La sustitución de variables no se realiza en palabras encerradas entre llaves.

Tenga en cuenta que las variables pueden contener secuencias de caracteres distintas de las enumeradas anteriormente, pero en ese caso se deben utilizar otros mecanismos para acceder a ellas (por ejemplo, a través de la forma de un solo argumento del comando set).

[9] Sustitución de barra invertida.
Si aparece una barra invertida (“\”) dentro de una palabra, entonces ocurre la sustitución de barra invertida. En todos los casos excepto en los descritos a continuación, la barra invertida se elimina y el carácter siguiente se trata como un carácter ordinario y se incluye en la palabra. Esto permite que caracteres como comillas dobles, corchetes de cierre y signos de dólar se incluyan en palabras sin activar un procesamiento especial. La siguiente tabla enumera las secuencias de barra invertida que se manejan de forma especial, junto con el valor que reemplaza cada secuencia.
\a
Alerta audible (campana) (Unicode U+000007).
\b
Retroceso (Backspace) (Unicode U+000008).
\f
Salto de página (Form feed) (Unicode U+00000C).
\n
Salto de línea (Newline) (Unicode U+00000A).
\r
Retorno de carro (Carriage-return) (Unicode U+00000D).
\t
Tabulación (Tab) (Unicode U+000009).
\v
Tabulación vertical (Vertical tab) (Unicode U+00000B).
\<newline>whiteSpace
Un único carácter de espacio reemplaza la barra invertida, el salto de línea y todos los espacios y tabulaciones después del salto de línea. Esta secuencia de barra invertida es única en el sentido de que se reemplaza en una pasada previa separada antes de que el comando sea realmente analizado. Esto significa que se reemplazará incluso cuando ocurra entre llaves, y el espacio resultante se tratará como un separador de palabras si no está entre llaves o comillas.
\\
Barra invertida (“\”).
\ooo
Los dígitos ooo (uno, dos o tres de ellos) dan un valor octal de ocho bits para el carácter Unicode que se insertará, en el rango 000–377 (es decir, el rango U+000000–U+0000FF). El analizador se detendrá justo antes de que este rango desborde, o cuando se alcance el máximo de tres dígitos. Los bits superiores del carácter Unicode serán 0.
\xhh
Los dígitos hexadecimales hh (uno o dos de ellos) dan un valor hexadecimal de ocho bits para el carácter Unicode que se insertará. Los bits superiores del carácter Unicode serán 0 (es decir, el carácter estará en el rango U+000000–U+0000FF).
\u
Este comando, introducido en Tcl 8.6, permite la sustitución de caracteres Unicode usando secuencias de escape hexadecimales de hasta 6 dígitos. Por ejemplo, `\u00E9` representa ‘é’.
“\caracter”
Cualquier otro carácter seguido de una barra invertida se trata como un carácter literal. Por ejemplo, `\$` se sustituye por `$`, `\]` por `]` y `\"` por `"`. Esto es útil para incluir caracteres especiales que de otro modo se interpretarían de forma especial.

Cuando se utilizan llaves para citar texto (regla [6]), solo se procesan las secuencias de barra invertida-salto de línea para eliminar el salto de línea y el texto posterior. Todas las demás sustituciones de barra invertida se omiten, excepto por la secuencia de barra invertida-salto de línea.

[10] Comentarios.
Cualquier texto que comience con un carácter de almohadilla (“#”) y continúe hasta el final de la línea es un comentario y es ignorado por el intérprete Tcl.
[11] Resultado del comando.
El resultado de la evaluación de un comando es el valor devuelto por el procedimiento del comando. El resultado es una cadena de caracteres.
[12] Comprobación de tipo.
Aunque Tcl es un lenguaje de tipos dinámicos, muchos comandos intentan interpretar sus argumentos como tipos específicos (enteros, flotantes, listas, etc.). Si un argumento no se puede interpretar del tipo esperado, se genera un error de tipo.

Los dígitos hexadecimales hhhh (uno, dos, tres o cuatro de ellos) proporcionan un valor hexadecimal de dieciséis bits para el carácter Unicode que se insertará. Los bits superiores del carácter Unicode serán 0 (es decir, el carácter estará en el rango U+000000–U+00FFFF).
\Uhhhhhhhh
Los dígitos hexadecimales hhhhhhhh (de uno a ocho de ellos) proporcionan un valor hexadecimal de veintiún bits para el carácter Unicode que se insertará, en el rango U+000000–U+10FFFF. El analizador se detendrá justo antes de que este rango desborde, o cuando se alcance el máximo de ocho dígitos. Los bits superiores del carácter Unicode serán 0.

El rango U+010000–U+10FFFD está reservado para el futuro.

La sustitución de barras invertidas no se realiza en palabras encerradas entre llaves, excepto para la barra invertida-nueva línea como se describe anteriormente.

[10] Comentarios.
Si aparece un carácter de almohadilla (“#”) en un punto donde Tcl espera el primer carácter de la primera palabra de un comando, entonces el carácter de almohadilla y los caracteres que le siguen, hasta la siguiente nueva línea, se tratan como un comentario y se ignoran. El carácter de comentario solo tiene significado cuando aparece al principio de un comando.
[11] Orden de sustitución.
Cada carácter es procesado exactamente una vez por el intérprete Tcl como parte de la creación de las palabras de un comando. Por ejemplo, si ocurre una sustitución de variable, no se realizan sustituciones adicionales en el valor de la variable; el valor se inserta en la palabra tal cual. Si ocurre una sustitución de comando, el comando anidado es procesado completamente por la llamada recursiva al intérprete Tcl; no se realizan sustituciones antes de hacer la llamada recursiva y no se realizan sustituciones adicionales en el resultado del script anidado.

Las sustituciones se realizan de izquierda a derecha, y cada sustitución se evalúa completamente antes de intentar evaluar la siguiente. Por lo tanto, una secuencia como

set y [set x 0][incr x][incr x]

siempre asignará a la variable y el valor 012.

[12] Sustitución y límites de palabras.
Las sustituciones no afectan los límites de palabras de un comando, excepto la expansión de argumentos según lo especificado en la regla [5]. Por ejemplo, durante la sustitución de variables, el valor completo de la variable se convierte en parte de una sola palabra, incluso si el valor de la variable contiene espacios.
