ARGUMENTS

Tcl_Interp *interp (in)
Interprete en el cual se registrará la información.

int code El código devuelto por la evaluación de la script.
Tcl_Obj *options Un diccionario de opciones de retorno.

const char *message (in)
Para Tcl_AddErrorInfo, este es un string de C convencional para append a la opción de retorno -errorinfo. Para Tcl_AddObjErrorInfo, este apunta al primer byte de un array de length bytes que contiene un string para append a la opción de retorno -errorinfo. Este array de bytes puede contener bytes nulos a menos que length sea negativo.
Tcl_Obj *objPtr (in)
Un mensaje a append a la opción de retorno -errorinfo en el formato de un valor Tcl_Obj.
int length (in)
El número de bytes a copiar de message cuando append a la opción de retorno -errorinfo. Si es negativo, se usan todos los bytes hasta el primer byte nulo.
Tcl_Obj *errorObjPtr (in)
El valor -errorcode de la opción de retorno se establecerá en este valor.
const char *element (in)
La cadena a registrar como un elemento de la opción de retorno -errorcode. El último argumento debe ser (char *)NULL.
va_list argList (in)
Un argumento list que debe haber sido inicializado usando va_start, y limpiado usando va_end.

int lineNum El número de línea donde ocurrió un error en un script.
const char *script (in)
El puntero a la primera caracter en el script que contiene la comand (debe ser <= command)
const char *command (in)
El puntero a la primera caracter en el command que generó el error
int commandLength (in)
El número de bytes en el command; -1 significa usar todos los bytes hasta el primer byte nulo.

DESCRIPTION

Las rutinas Tcl_SetReturnOptions y Tcl_GetReturnOptions exponen las mismas capacidades que las comandos return y catch respectivamente en forma de interfaz C.

Tcl_GetReturnOptions obtiene el diccionario de opciones de retorno de un interpretador después de la evaluación de un script. Las rutinas como Tcl_Eval se llaman para evaluar un script en un interpretador. Estas rutinas devuelven un código de completación entero. Estas rutinas también mantienen en el interpretador tanto el resultado como el diccionario de opciones de retorno generados por la evaluación del script. De manera similar a Tcl_GetObjResult, Tcl_GetReturnOptions obtiene el diccionario de opciones de retorno. El código de completación entero debe ser pasado como el argumento code a Tcl_GetReturnOptions para que todos los argumentos necesarios estén presentes en el diccionario. Específicamente, un valor code de TCL_ERROR asegurará que los entries para las claves -errorinfo, -errorcode y -errorline estén en el diccionario. También se ajustarán las entradas para las claves -code y -level si es necesario para que coincidan con el valor de code. El objeto (Tcl_Obj *) devuelto por Tcl_GetReturnOptions apunta a un objeto Tcl_Obj no compartido con un contador de referencias de cero. El diccionario puede ser escrito, añadiendo, eliminando o sobrescribiendo cualquier entrada en él sin necesidad de verificar un valor compartido. Como con cualquier Tcl_Obj con un contador de referencias de cero, es hasta el responsable del llamante organizar su disposición con Tcl_DecrRefCount o un referenciado a él mediante Tcl_IncrRefCount (o una de las muchas funciones que llaman a ese, como Tcl_SetObjResult y Tcl_SetVar2Ex).

Uso típico de Tcl_GetReturnOptions es recuperar el stack trace cuando el script devuelve TCL_ERROR, como así:

int code = Tcl_Eval(interp, script);
if (code == TCL_ERROR) {
    Tcl_Obj *options = Tcl_GetReturnOptions(interp, code);
    Tcl_Obj *key = Tcl_NewStringObj("-errorinfo", -1);
    Tcl_Obj *stackTrace;
    Tcl_IncrRefCount(key);
    Tcl_DictObjGet(NULL, options, key, &stackTrace);
    Tcl_DecrRefCount(key);
    /* Hacer algo con stackTrace */
    Tcl_DecrRefCount(options);
}

Tcl_SetReturnOptions establece las opciones de retorno del interpretador interp en options. Si options contiene cualquier valor inválido para cualquier clave, se devolverá TCL_ERROR y el resultado del interpretador se establecerá en un mensaje de error adecuado. De lo contrario, se devolverá un código de completación en acuerdo con los valores de las claves -code y -level en options.

Como un ejemplo, la comand return de Tcl podría implementarse en términos de Tcl_SetReturnOptions así:

if ((objc % 2) == 0) { /* argumento resultado explícito */
    objc--;
    Tcl_SetObjResult(interp, objv[objc]);
}
return Tcl_SetReturnOptions(interp, Tcl_NewListObj(objc-1, objv+1));

(No está implementado realmente así. Las privilegios internos permiten una alternativa más eficiente que se alinea mejor con el compilador de bytecode.)

Nota: Un objeto nuevo Tcl_Obj puede ser pasado como el argumento options sin necesidad de gestionar el contador de referencias. Esto es análoga a Tcl_SetObjResult.

Aunque Tcl_SetReturnOptions proporciona una interfaz general para establecer cualquier colección de opciones de retorno, hay un número limitado de opciones de retorno que son muy frecuentemente utilizadas. Las más notables son las opciones -errorinfo y -errorcode que deben ser establecidas correctamente cuando el procedimiento de comando devuelva TCL_ERROR. La opción -errorline también es leída por los comandos que evalúan scripts y desean proporcionar información de ubicación detallada en la información de stack trace que se append a la opción -errorinfo. Tcl proporciona varias interfaces más sencillas para establecer estas opciones de retorno de forma más directa.

La opción -errorinfo mantiene un stack trace de las operaciones que se ejecutaron cuando ocurrió un error, y es intencionalmente legible para humanos. La opción -errorcode mantiene una lista de elementos Tcl que son intencionalmente legibles para el sistema de máquina. El primer elemento en el valor -errorcode identifica el tipo de error que ocurrió (por ejemplo, POSIX significa que un error ocurrió en una llamada a un sistema POSIX) y otros elementos contienen información adicional que depende del tipo de error. Véase el manual de la variable errorCode para detalles sobre los diversos formatos usados por las opciones -errorcode de las comandos de Tcl builtin.

La opción -errorinfo se gradualmente construye como se unwinds el error a través de las operaciones nested. Cada vez que se devuelve un código de error a Tcl_Eval o a cualquiera de las rutinas que realicen la evaluación de scripts, se llama la procedimiento Tcl_AddErrorInfo para añadir más texto a la opción de retorno -errorinfo describiendo la comand que se estaba ejecutando cuando el error ocurrió. Cuando el error ha sido pasado todo el camino hacia el aplicativo, contendrá una traza completa de la actividad en curso cuando el error ocurrió.

Es útil a veces añadir información adicional a la opción -errorinfo más allá de lo que puede ser proporcionada por las rutinas de evaluación de scripts. Se puede utilizar Tcl_AddErrorInfo para este propósito: su argumento message es una cadena adicional para append a la opción de retorno -errorinfo. Por ejemplo, cuando se produce un error durante la comand source, se llama a la procedimiento Tcl_AddErrorInfo para registrar el nombre del archivo que se está procesando y el número de línea en que se produce el error. Así mismo, cuando se produce un error durante la evaluación de un script, se llama a la procedimiento Tcl_AddErrorInfo para registrar la información necesaria.

También hay utilidades para añadir de forma más fácil información a las opciones -errorcode y -errorinfo.

El procedimiento Tcl_AppendObjToErrorInfo se puede utilizar para añadir información adicional a la opción de retorno -errorinfo. El argumento objPtr apunta a un Tcl_Obj que contiene el texto que se añadirá. Es útil cuando se tiene la información de error en un Tcl_Obj y se desea añadirla a la información de error existente. El procedimiento Tcl_AddObjErrorInfo es similar, pero toma un puntero a un array de bytes y su longitud como argumentos. Esto es útil para añadir información de error que contiene caracteres nulos o información binaria.

El procedimiento Tcl_SetObjErrorCode permite establecer la opción de retorno -errorcode a un valor de Tcl_Obj dado. Esto es útil cuando se desea establecer el código de error a un valor complejo o estructurado.

Los procedimientos Tcl_SetErrorCode y Tcl_SetErrorCodeVA permiten establecer la opción de retorno -errorcode a una lista de cadenas de caracteres. La lista de cadenas de caracteres se pasa como una serie de argumentos de cadena de caracteres terminada por NULL en Tcl_SetErrorCode, o como una va_list en Tcl_SetErrorCodeVA. El primer elemento de la lista se utiliza para identificar el tipo de error, y los elementos subsiguientes proporcionan información adicional sobre el error. Por ejemplo, para registrar un error POSIX, se podría llamar a Tcl_SetErrorCode con los argumentos "POSIX", "ENOENT", (char *)NULL.

El procedimiento Tcl_GetErrorLine devuelve el número de línea asociado con un error. Este valor es establecido por las rutinas de evaluación de scripts como Tcl_Eval cuando se produce un error durante la evaluación de un script. El procedimiento Tcl_SetErrorLine permite establecer explícitamente el número de línea asociado con un error. Esto es útil cuando se está generando un error y se desea proporcionar información detallada sobre la ubicación del error en el código fuente.

El procedimiento Tcl_PosixError devuelve una cadena de caracteres legible por humanos que describe el error POSIX actual. Esto es útil cuando el código de error POSIX se establece para indicar un error del sistema operativo. Por ejemplo, si el código de error es "POSIX" y el segundo elemento es "ENOENT", Tcl_PosixError devolverá una cadena como "No such file or directory".

El procedimiento Tcl_LogCommandInfo se utiliza para registrar información sobre un comando que se está ejecutando. Esta información se puede utilizar posteriormente para depurar problemas. Los argumentos script y command apuntan a las porciones de la cadena de comandos que están siendo evaluadas. El argumento commandLength especifica la longitud del comando en bytes. Si commandLength es -1, se asumirá que la cadena de comandos termina en un carácter nulo.

RETURN

Tcl_GetReturnOptions devuelve un objeto Tcl_Obj que representa el diccionario de opciones de retorno. El llamante es responsable de decrementar el contador de referencias de este objeto cuando ya no se necesite.

Tcl_SetReturnOptions devuelve TCL_OK si las opciones se establecieron correctamente, o TCL_ERROR si las opciones eran inválidas. En caso de TCL_ERROR, el resultado del interpretador se establece en un mensaje de error apropiado.

Tcl_AddErrorInfo, Tcl_AppendObjToErrorInfo, Tcl_AddObjErrorInfo, Tcl_SetObjErrorCode, Tcl_SetErrorCode, Tcl_SetErrorCodeVA, Tcl_GetErrorLine, Tcl_SetErrorLine, Tcl_PosixError y Tcl_LogCommandInfo no devuelven ningún valor.

EXAMPLE

Para obtener el stack trace cuando un error ocurre:

int code = Tcl_Eval(interp, script);
if (code == TCL_ERROR) {
    Tcl_Obj *options = Tcl_GetReturnOptions(interp, code);
    Tcl_Obj *key = Tcl_NewStringObj("-errorinfo", -1);
    Tcl_Obj *stackTrace;
    Tcl_IncrRefCount(key);
    if (Tcl_DictObjGet(interp, options, key, &stackTrace) == TCL_OK) {
        // Utilizar stackTrace
        const char *trace = Tcl_GetString(stackTrace);
        fprintf(stderr, "Stack Trace:\n%s\n", trace);
    }
    Tcl_DecrRefCount(key);
    Tcl_DecrRefCount(options);
}

Para establecer el código de error POSIX:

Tcl_SetErrorCode(interp, "POSIX", "ENOENT", (char *)NULL);

Esto corresponderá a la entrada -errorcode que se establecerá a {POSIX ENOENT}.

Para registrar información adicional sobre un error:

Tcl_AddErrorInfo(interp, "\n    while processing file foo.tcl");

DESCRIPCIÓN

Estas funciones se utilizan para gestionar la información de error que devuelve una rutina de evaluación de scripts de Tcl. Cuando un script Tcl produce un error, el intérprete de Tcl almacena información sobre el error en un conjunto de "opciones de retorno". Las opciones de retorno más comunes son -errorinfo y -errorcode. La opción -errorinfo contiene una traza de pila de las llamadas a procedimientos que condujeron al error. La opción -errorcode contiene un valor de código de error más estructurado, útil para el procesamiento programático de errores. Las opciones de retorno se pueden recuperar mediante una llamada a Tcl_GetReturnOptions después de que una rutina de evaluación de scripts haya devuelto TCL_ERROR.

La función Tcl_SetErrorInfo añade una cadena de texto message a la opción de retorno -errorinfo. Si -errorinfo no está establecido, se crea una nueva cadena. La cadena message se antepone al valor existente de -errorinfo, con un salto de línea intermedio. Esta función se utiliza normalmente para añadir información de contexto a un error. Por ejemplo, podría añadir el nombre de la función que ha detectado el error y cualquier información relevante sobre el estado local.

La función Tcl_AppendErrorInfo es similar a Tcl_SetErrorInfo, excepto que message se añade al final del valor existente de -errorinfo en lugar de anteponerse. Esto se usa para añadir información adicional a una traza de error existente.

La función Tcl_AddErrorInfo es una alternativa a Tcl_AppendErrorInfo. Añade el message al final del valor de -errorinfo. La diferencia principal es que Tcl_AddErrorInfo está diseñado para ser llamado después de que una rutina de evaluación de scripts haya devuelto TCL_ERROR, y utiliza la información de la traza de pila del intérprete para añadir el nombre del procedimiento y el número de línea dentro del procedimiento, si están disponibles. El mejor momento para llamar a Tcl_AddErrorInfo es justo después de que una rutina de evaluación de scripts haya devuelto TCL_ERROR. El valor de la opción de retorno -errorline (recuperado mediante una llamada a Tcl_GetReturnOptions) a menudo constituye una parte útil del message pasado a Tcl_AddErrorInfo.

Tcl_AppendObjToErrorInfo es una interfaz alternativa a la misma funcionalidad que Tcl_AddErrorInfo. Se llama a Tcl_AppendObjToErrorInfo cuando el valor de cadena que se va a añadir a la opción -errorinfo está disponible como un Tcl_Obj en lugar de como un array de char.

Tcl_AddObjErrorInfo es casi idéntico a Tcl_AddErrorInfo, excepto que tiene un argumento adicional length. Esto permite que la cadena message contenga bytes nulos incrustados. Esto es esencialmente una mala idea. Si el message necesita contener el carácter nulo U+0000, se deben utilizar las reglas de codificación internas habituales de Tcl para evitar la necesidad de un byte nulo. Si la interfaz Tcl_AddObjErrorInfo se utiliza en absoluto, debería ser con un valor length negativo.

La función Tcl_SetObjErrorCode se utiliza para establecer la opción de retorno -errorcode en el valor de lista errorObjPtr construido por el llamante. Tcl_SetObjErrorCode se invoca típicamente justo antes de devolver un error. Si se devuelve un error sin llamar a Tcl_SetObjErrorCode o Tcl_SetErrorCode, el intérprete de Tcl establece automáticamente la opción de retorno -errorcode en NONE.

La función Tcl_SetErrorCode también se utiliza para establecer la opción de retorno -errorcode. Sin embargo, toma una o más cadenas para registrar en lugar de un valor. De lo contrario, es similar a Tcl_SetObjErrorCode en comportamiento.

Tcl_SetErrorCodeVA es lo mismo que Tcl_SetErrorCode excepto que en lugar de tomar un número variable de argumentos, toma una lista de argumentos.

La función Tcl_GetErrorLine se utiliza para leer el valor entero de la opción de retorno -errorline sin la sobrecarga de una llamada completa a Tcl_GetReturnOptions. Del mismo modo, Tcl_SetErrorLine establece el valor de la opción de retorno -errorline.

Tcl_PosixError establece la variable -errorcode después de un error en una llamada al kernel POSIX. Lee el valor de la variable C errno y llama a Tcl_SetErrorCode para establecer la opción de retorno -errorcode en el formato POSIX. El llamante debe haber llamado previamente a Tcl_SetErrno para establecer errno; esto es necesario en algunas plataformas (por ejemplo, Windows) donde Tcl está enlazado a una aplicación como una biblioteca compartida, o cuando el error ocurre en una extensión cargada dinámicamente. Consulte la entrada del manual para Tcl_SetErrno para obtener más información.

Tcl_PosixError devuelve un mensaje de diagnóstico legible por humanos para el error (este es el mismo valor que aparecerá como el tercer elemento en el valor de -errorcode). Puede ser conveniente incluir esta cadena como parte del mensaje de error devuelto a la aplicación en el resultado del intérprete.

Tcl_LogCommandInfo se invoca después de que ocurre un error en un intérprete. Añade información sobre el comando que se estaba ejecutando cuando ocurrió el error al valor de -errorinfo, y se establece el número de línea almacenado internamente en el intérprete.

En versiones anteriores de Tcl, no existía la rutina Tcl_GetReturnOptions. En su lugar, las variables globales de Tcl errorInfo y errorCode eran el único lugar para recuperar la información de error. Mucho código existente escrito para versiones anteriores de Tcl todavía accede a esta información a través de esas variables globales.

Es importante darse cuenta de que, si bien leer de esas variables globales sigue siendo una forma compatible de acceder a estos valores de opción de retorno, es importante no asumir que escribir en esas variables globales establecerá correctamente las opciones de retorno correspondientes. Se ha enfatizado durante mucho tiempo en esta página del manual que es importante llamar a los procedimientos descritos aquí en lugar de establecer errorInfo o errorCode directamente con Tcl_ObjSetVar2.

Si se llama a la función Tcl_ResetResult, borra todo el estado del intérprete asociado con la evaluación de scripts, incluido todo el diccionario de opciones de retorno. En particular, se restablecen las opciones -errorinfo y -errorcode. Si hubiera ocurrido un error, la llamada a Tcl_ResetResult borrará el estado de error para que parezca que no ha ocurrido ningún error después de todo. Las variables globales errorInfo y errorCode no son modificadas por Tcl_ResetResult, por lo que continúan manteniendo un registro de información sobre el error más reciente visto en un intérprete.
