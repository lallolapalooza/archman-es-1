Tcl_SetResult(3) Procedimientos de la biblioteca Tcl Tcl_SetResult(3)

NOMBRE

SINOPSIS

#include <tcl.h>

Tcl_SetObjResult(interp, objPtr)

Tcl_Obj *
Tcl_GetObjResult(interp)

Tcl_SetResult(interp, result, freeProc)

const char *
Tcl_GetStringResult(interp)

Tcl_AppendResult(interp, result, result, ... , (char *)NULL)

Tcl_AppendResultVA(interp, argList)

Tcl_ResetResult(interp)

Tcl_TransferResult(sourceInterp, code, targetInterp)

Tcl_AppendElement(interp, element)

Tcl_FreeResult(interp)

ARGUMENTOS

Tcl_Interp *interp (salida)
Intérprete cuyo resultado será modificado o leído.
Tcl_Obj *objPtr (entrada)
Valor Tcl que se convertirá en el resultado para interp.
char *result (entrada)
Valor de cadena que se convertirá en el resultado para interp o que se añadirá al resultado existente.
const char *element (entrada)
Valor de cadena que se añadirá como elemento de lista al resultado existente de interp.
Tcl_FreeProc *freeProc (entrada)
Dirección del procedimiento a llamar para liberar el almacenamiento en result, o TCL_STATIC, TCL_DYNAMIC o TCL_VOLATILE.
va_list argList (entrada)
Una lista de argumentos que debe haber sido inicializada usando va_start y limpiada usando va_end.
Tcl_Interp *sourceInterp (entrada)
Intérprete del cual se transferirán el resultado y las opciones de retorno.
Tcl_Interp *targetInterp (entrada)
Intérprete al cual se transferirán el resultado y las opciones de retorno.
int code (entrada)
Valor del código de retorno que controla la transferencia de opciones de retorno.

DESCRIPCIÓN

Los procedimientos descritos aquí son utilidades para manipular el valor del resultado en un intérprete Tcl. El resultado del intérprete puede ser un valor Tcl o una cadena. Por ejemplo, Tcl_SetObjResult y Tcl_SetResult establecen el resultado del intérprete a, respectivamente, un valor y una cadena. De manera similar, Tcl_GetObjResult y Tcl_GetStringResult devuelven el resultado del intérprete como valor y como cadena. Los procedimientos siempre mantienen consistentes las formas de cadena y de valor del resultado del intérprete. Por ejemplo, si se llama a Tcl_SetObjResult para establecer el resultado a un valor, y luego se llama a Tcl_GetStringResult, esta devolverá la representación en cadena de dicho valor.

Tcl_SetObjResult hace que objPtr sea el resultado para interp, reemplazando cualquier resultado existente. El resultado queda apuntando al valor referenciado por objPtr. El contador de referencias de objPtr se incrementa ya que ahora hay una nueva referencia a él desde interp. El contador de referencias de cualquier valor de resultado antiguo se decrementa y el valor de resultado antiguo se libera si no quedan referencias a él.

Tcl_GetObjResult devuelve el resultado para interp como un valor. El contador de referencias del valor no se incrementa; si la llamada necesita retener un puntero a largo plazo al valor, debe usar Tcl_IncrRefCount para incrementar su contador de referencias con el fin de evitar que se libere demasiado pronto o se cambie accidentalmente.

Tcl_SetResult hace que result sea el resultado para el comando Tcl actual en interp, reemplazando cualquier resultado existente. El argumento freeProc especifica cómo gestionar el almacenamiento para el argumento result; se discute en la sección EL ARGUMENTO TCL_FREEPROC PARA TCL_SETRESULT más abajo. Si result es NULL, entonces freeProc se ignora y Tcl_SetResult reinicializa el resultado de interp para que apunte a una cadena vacía.

Tcl_GetStringResult devuelve el resultado para interp como una cadena. Si el resultado se estableció a un valor mediante una llamada a Tcl_SetObjResult, se convertirá la forma de valor a cadena y se devolverá. Si la representación en cadena del valor contiene bytes nulos, esta conversión perderá información. Por esta razón, se anima a los programadores a escribir su código para usar los nuevos procedimientos de la API de valores y a llamar a Tcl_GetObjResult en su lugar.

Tcl_ResetResult borra el resultado para interp y deja el resultado en su estado normal inicializado vacío. Si el resultado es un valor, se decrementa su contador de referencias y el resultado queda apuntando a un valor no compartido que representa una cadena vacía. Si el resultado es una cadena asignada dinámicamente, se libera su memoria y el resultado queda como una cadena vacía. Tcl_ResetResult también borra el estado de error gestionado por Tcl_AddErrorInfo, Tcl_AddObjErrorInfo y Tcl_SetErrorCode.

Tcl_AppendResult facilita la construcción de resultados de Tcl en partes. Toma cada uno de sus argumentos result y los añade en orden al resultado actual asociado con interp. Si el resultado está en su estado inicial vacío (por ejemplo, se acaba de invocar un procedimiento de comando o se acaba de llamar a Tcl_ResetResult), entonces Tcl_AppendResult establece el resultado a la concatenación de sus argumentos result. Tcl_AppendResult puede llamarse repetidamente a medida que se producen piezas adicionales del resultado. Tcl_AppendResult se encarga de todos los problemas de gestión de memoria asociados con la gestión del resultado de interp, como la asignación de un área de resultado más grande si es necesario. También gestiona la conversión hacia y desde el campo result de interp para manejar la retrocompatibilidad con extensiones antiguas. Se puede pasar cualquier número de argumentos result en una sola llamada; el último argumento de la lista debe ser (char *)NULL.

Tcl_AppendResultVA es igual a Tcl_AppendResult excepto que en lugar de tomar un número variable de argumentos, toma una lista de argumentos.

Tcl_TransferResult transfiere el estado del intérprete de sourceInterp a targetInterp. Los dos intérpretes deben haber sido creados en el mismo hilo. Si sourceInterp y targetInterp son los mismos, no se hace nada. De lo contrario, Tcl_TransferResult mueve el resultado de sourceInterp a targetInterp y reinicia el resultado en sourceInterp. También mueve el diccionario de opciones de retorno controlado por el valor del código de retorno code de la misma manera que Tcl_GetReturnOptions.

INTERFACES OBSOLETAS

PROCEDIMIENTOS ANTIGUOS DE CADENA

Se desaconseja el uso de los siguientes procedimientos ya que manipulan el resultado de Tcl como una cadena. Procedimientos como Tcl_SetObjResult que manipulan el resultado como un valor pueden ser significativamente más eficientes.

Tcl_AppendElement es similar a Tcl_AppendResult en que permite construir resultados en partes. Sin embargo, Tcl_AppendElement toma solo un argumento element y añade ese argumento al resultado actual como un elemento de lista Tcl válido. Tcl_AppendElement añade barras invertidas o llaves si es necesario para asegurar que el resultado de interp pueda ser analizado como una lista y que element sea extraído como un solo elemento. En condiciones normales, Tcl_AppendElement añadirá un carácter de espacio al resultado de interp justo antes de añadir el nuevo elemento de lista, de modo que los elementos de la lista en el resultado estén correctamente separados. Sin embargo, si el nuevo elemento de lista es el primero en una lista o sublista (es decir, el resultado actual de interp está vacío, o consiste en el único carácter “{”, o termina en los caracteres “ {”) entonces no se añade espacio.

Tcl_FreeResult realiza parte del trabajo de Tcl_ResetResult. Libera la memoria asociada con el resultado de interp. También establece interp->freeProc a cero, pero no cambia interp->result ni borra el estado de error. Tcl_FreeResult se usa más comúnmente cuando un procedimiento está a punto de reemplazar un valor de resultado por otro.

Tcl_FreeResult(3) - Tcl - Arch Linux

NAME

Tcl_FreeResult, Tcl_GetObjResult, Tcl_GetStringResult, Tcl_SetObjResult, Tcl_SetResult - manage the result of a Tcl command

SYNOPSIS

#include <tcl.h>

const char *
Tcl_GetStringResult(interp);

const Tcl_Obj *
Tcl_GetObjResult(interp);

void
Tcl_SetResult(interp, string, freeProc);

void
Tcl_SetObjResult(interp, objPtr);

ARGUMENTS

Tcl_Interp *interp (in)
Interpreter to use for accessing or modifying the result.
const char *string (in)
String value to set as the interpreter's result.
Tcl_FreeProc *freeProc (in)
Specifies how to manage the storage for string. May be one of the values TCL_STATIC, TCL_DYNAMIC, TCL_VOLATILE, or the address of a procedure to call to free the string.
const Tcl_Obj *objPtr (in)
Pointer to the Tcl object to set as the interpreter's result.

DESCRIPTION

These are the core procedures for managing the result of a Tcl command. A Tcl interpreter stores its result in an internal structure. This result can be accessed either as a string or as a Tcl object. The procedures described here allow C code to set and retrieve the result of a command execution.

Tcl_GetStringResult returns the result of the interpreter as a C string. The string is valid until the interpreter's result is next modified.

Tcl_GetObjResult returns the result of the interpreter as a Tcl object. The object is valid until the interpreter's result is next modified.

Tcl_SetResult sets the interpreter's result to the string specified by string. The freeProc argument specifies how the storage for string should be managed. If freeProc is TCL_STATIC, the string is assumed to be static storage that won't be modified. If freeProc is TCL_DYNAMIC, the string was allocated with Tcl_Alloc and Tcl will free it using Tcl_Free when it's no longer needed. If freeProc is TCL_VOLATILE, the string might be in temporary storage (like a stack frame), and Tcl will make a copy. If freeProc is a procedure address, Tcl will call that procedure to free the string when it's no longer needed. See the section "THE Tcl_FreeProc ARGUMENT TO Tcl_SetResult" below for more details.

Tcl_SetObjResult sets the interpreter's result to the Tcl object specified by objPtr. Tcl takes ownership of the object. If the interpreter already had a result, it will be disposed of according to the rules described in the Tcl_Interp manual page.

DEPRECATED INTERFACES

The procedures Tcl_GetResult and Tcl_AppendResult are deprecated. Code should use Tcl_GetStringResult and Tcl_Append, respectively. The procedures Tcl_GetObjResult, Tcl_GetStringResult, Tcl_SetObjResult, and Tcl_SetResult were ported routines.

As a migration aid, access can be restored with the compiler directive

#define USE_INTERP_RESULT

but this is meant only to offer life support to otherwise dead code.

THE TCL_FREEPROC ARGUMENT TO TCL_SETRESULT

Tcl_SetResult's freeProc argument specifies how the Tcl system is to manage the storage for the result argument. If Tcl_SetResult or Tcl_SetObjResult are called at a time when interp holds a string result, they do whatever is necessary to dispose of the old string result (see the Tcl_Interp manual entry for details on this).

If freeProc is TCL_STATIC it means that result refers to an area of static storage that is guaranteed not to be modified until at least the next call to Tcl_Eval. If freeProc is TCL_DYNAMIC it means that result was allocated with a call to Tcl_Alloc and is now the property of the Tcl system. Tcl_SetResult will arrange for the string's storage to be released by calling Tcl_Free when it is no longer needed. If freeProc is TCL_VOLATILE it means that result points to an area of memory that is likely to be overwritten when Tcl_SetResult returns (e.g. it points to something in a stack frame). In this case Tcl_SetResult will make a copy of the string in dynamically allocated storage and arrange for the copy to be the result for the current Tcl command.

If freeProc is not one of the values TCL_STATIC, TCL_DYNAMIC, and TCL_VOLATILE, then it is the address of a procedure that Tcl should call to free the string. This allows applications to use non-standard storage allocators. When Tcl no longer needs the storage for the string, it will call freeProc. FreeProc should have arguments and result that match the type Tcl_FreeProc:

typedef void Tcl_FreeProc(
                char *blockPtr);

When freeProc is called, its blockPtr will be set to the value of result passed to Tcl_SetResult.
