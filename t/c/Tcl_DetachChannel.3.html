DESCRIPCIÓN

El mecanismo de canales Tcl proporciona un mecanismo independiente de dispositivo e independiente de la plataforma para realizar operaciones de entrada y salida con búfer en una variedad de tipos de archivos, sockets y dispositivos. El mecanismo de canales es extensible a nuevos tipos de canales, proporcionando un controlador de canal de bajo nivel para el nuevo tipo; la interfaz del controlador de canal se describe en la entrada del manual de Tcl_CreateChannel. El mecanismo de canales proporciona un esquema de almacenamiento en búfer modelado a partir de la E/S estándar de Unix, y también permite E/S no bloqueante en canales.

Los procedimientos descritos en esta entrada del manual comprenden las API de C de la capa genérica de la arquitectura de canales. Para obtener una descripción de la arquitectura del controlador de canales y de cómo implementar controladores de canales para nuevos tipos de canales, consulte la entrada del manual de Tcl_CreateChannel.

TCL_OPENFILECHANNEL

Abre un canal de tipo archivo para la operación especificada por mode. fileName es el nombre del archivo a abrir. Si el archivo se abre para escritura y no existe, se creará el archivo. Las permissions se aplican sólo si se crea un archivo nuevo y se especifican en formato octal POSIX.

Los modos permitidos son los mismos que los del comando Tcl open:

  • r (lectura),
    r+ (lectura/escritura),
    w (escritura, truncar si existe),
    w+ (lectura/escritura, truncar si existe),
    a (añadir/escribir, crear si no existe),
    a+ (lectura/añadir/escribir, crear si no existe).
Las opciones binario/texto pueden especificarse mediante un sufijo 'b' o 't' (por ejemplo, rb). Si el modo especifica una operación de escritura, el canal estará abierto para escritura; si especifica una operación de lectura, el canal estará abierto para lectura. Si se abre un canal para escritura y se especifica el modo binario, el sistema operativo no realizará ninguna traducción de fin de línea. Si se abre un canal para lectura y se especifica el modo binario, tampoco se realizará ninguna traducción de fin de línea. Por defecto, Tcl_OpenFileChannel usa el modo texto. Los caracteres de nueva línea se normalizan a "\n" en entrada y se traducen a los finales de línea específicos del sistema operativo en salida.

Si el modo especifica que se abra el canal para la entrada, se devuelve un canal de lectura. Si el modo especifica que se abra el canal para la salida, se devuelve un canal de salida. Si se abre el canal para lectura y escritura, se devuelven un canal de lectura y un canal de salida.

En caso de error, la rutina devuelve un canal nulo y establece la variable de error de interp.

TCL_OPENCOMMANDCHANNEL

Abre una tubería de comandos ejecutando el comando especificado por argc y argv, y conectando la entrada estándar, la salida estándar y/o el error estándar de la tubería a canales Tcl. Los flags controlan cómo se manejan los canales stdio.

Si el comando se ejecuta correctamente, se devuelve un canal de tipo tubería. De lo contrario, se devuelve un canal nulo y se establece la variable de error de interp. Se puede obtener el código de salida del comando ejecutado usando Tcl_Wait o el comando Tcl wait después de que el canal haya sido cerrado.

TCL_MAKEFILECHANNEL

Crea un canal Tcl a partir de un manejador de archivo existente. handle es un descriptor de archivo o un HANDLE de Windows. readOrWrite es una combinación OR de TCL_READABLE y TCL_WRITABLE para indicar qué operaciones son válidas en el manejador.

Esta rutina es útil para crear canales Tcl a partir de descriptores de archivo que no fueron creados por Tcl, como los manejados por bibliotecas externas.

TCL_GETCHANNEL

Busca y devuelve el canal Tcl asociado con el nombre channelName. Si modePtr no es NULL, se establece en una combinación OR de TCL_READABLE y TCL_WRITABLE para indicar si el canal está abierto para lectura y/o escritura.

Si el canal no se encuentra, la rutina devuelve un canal nulo y establece la variable de error de interp.

TCL_GETCHANNELNAMES

Devuelve el número de canales registrados actualmente en interp. El nombre de cada canal se almacena en la variable Tcl auto_channel_names.

TCL_GETCHANNELNAMESEX

Devuelve el número de canales registrados actualmente en interp cuyos nombres coinciden con el pattern especificado. Si pattern es NULL, todos los canales registrados se consideran una coincidencia. Los nombres de los canales que coinciden se almacenan en la variable Tcl auto_channel_names.

TCL_REGISTERCHANNEL

Registra el canal channel en el intérprete interp, haciéndolo accesible mediante su nombre. Los canales registrados de esta manera se cierran automáticamente cuando el intérprete se destruye.

TCL_UNREGISTERCHANNEL

Anula el registro del canal channel en el intérprete interp. El canal se cierra si se estaba esperando un cierre pendiente y ya no está asociado con ningún intérprete. Si el canal se cerró con éxito, la rutina devuelve 1, de lo contrario devuelve 0.

TCL_DETACHCHANNEL

Desasocia el canal channel del intérprete interp. El canal permanece abierto pero ya no está asociado con ningún intérprete. El canal se cierra si el recuento de referencias para el canal llega a cero. Devuelve 1 si el canal se desasoció con éxito, de lo contrario devuelve 0.

Esta rutina es útil para transferir la propiedad de un canal a otro intérprete o para evitar que un canal se cierre cuando se destruye un intérprete.

TCL_ISTANDARDCHANNEL

Devuelve 1 si el canal channel es uno de los canales estándar (entrada, salida o error estándar), 0 en caso contrario.

TCL_CLOSE

Cierra el canal channel. Todos los búferes pendientes se vacían antes de cerrar el canal. Si el canal fue abierto por Tcl_OpenFileChannel y se abrió para escritura, cualquier dato restante en el búfer de salida se escribe en el archivo. Si el canal fue abierto por Tcl_OpenCommandChannel, el código de salida del comando se recupera.

Devuelve 0 si el cierre se realizó correctamente, o -1 si se produjo un error durante el cierre (por ejemplo, un error de escritura en el archivo). En caso de error, se establece la variable de error de interp.

TCL_READCHARS

Lee hasta charsToRead caracteres del canal channel y los almacena en el objeto readObjPtr. Si appendFlag es distinto de cero, los caracteres leídos se añaden al final del valor actual de readObjPtr; de lo contrario, reemplazan el contenido existente. El objeto readObjPtr debe ser un objeto de tipo cadena o nulo.

Devuelve el número de caracteres leídos. Si se alcanza el final del archivo, puede devolver un valor menor que charsToRead o 0 si no se leyeron caracteres. Si se produce un error, devuelve -1 y establece la variable de error de interp.

TCL_READ

Lee hasta bytesToRead bytes del canal channel y los almacena en el búfer readBuf. El búfer readBuf debe ser lo suficientemente grande para contener bytesToRead bytes.

Devuelve el número de bytes leídos. Si se alcanza el final del archivo, puede devolver un valor menor que bytesToRead o 0 si no se leyeron bytes. Si se produce un error, devuelve -1 y establece la variable de error de interp.

TCL_GETSOBJ

Lee una línea del canal channel, hasta el siguiente carácter de nueva línea, y la almacena en el objeto lineObjPtr. La línea leída se añade al valor actual de lineObjPtr. Los caracteres de nueva línea se incluyen en la línea leída.

Devuelve el número de caracteres leídos. Si se alcanza el final del archivo antes de leer cualquier carácter, devuelve 0. Si se alcanza el final del archivo después de leer algunos caracteres, la línea leída se devuelve sin el carácter de nueva línea final. Si se produce un error, devuelve -1 y establece la variable de error de interp.

TCL_GETS

Lee una línea del canal channel, hasta el siguiente carácter de nueva línea, y la almacena en la cadena dinámica lineRead. La línea leída se añade a cualquier dato ya presente en lineRead. Los caracteres de nueva línea se incluyen en la línea leída.

Devuelve el número de caracteres leídos. Si se alcanza el final del archivo antes de leer cualquier carácter, devuelve 0. Si se alcanza el final del archivo después de leer algunos caracteres, la línea leída se devuelve sin el carácter de nueva línea final. Si se produce un error, devuelve -1 y establece la variable de error de interp.

TCL_UNGETS

Devuelve los datos de entrada al canal channel. Los datos devueltos se anteponen a cualquier dato pendiente en el búfer de entrada del canal. Si addAtEnd es distinto de cero, los datos se añaden al final del búfer de entrada en lugar de al principio. El parámetro inputLen especifica la longitud de los datos a devolver.

Devuelve el número de bytes que se antepusieron al búfer de entrada del canal, o -1 si se produjo un error.

'TCL_WRITE'>TCL_WRITE

Escribe el contenido del objeto writeObjPtr en el canal channel. Si se produce un error, devuelve -1 y establece la variable de error de interp. De lo contrario, devuelve el número de bytes escritos.

TCL_WRITECHARS

Escribe los caracteres del búfer charBuf en el canal channel. bytesToWrite especifica el número de caracteres a escribir. Si se produce un error, devuelve -1 y establece la variable de error de interp. De lo contrario, devuelve el número de bytes escritos.

TCL_WRITE

Escribe los bytes del búfer byteBuf en el canal channel. bytesToWrite especifica el número de bytes a escribir. Si se produce un error, devuelve -1 y establece la variable de error de interp. De lo contrario, devuelve el número de bytes escritos.

TCL_READRAW

Lee hasta bytesToRead bytes del canal channel y los almacena en el búfer readBuf. A diferencia de Tcl_Read, esta operación no realiza ninguna decodificación basada en la codificación del canal.

Devuelve el número de bytes leídos. Si se alcanza el final del archivo, puede devolver un valor menor que bytesToRead o 0 si no se leyeron bytes. Si se produce un error, devuelve -1 y establece la variable de error de interp.

TCL_WRITERAW

Escribe los bytes del búfer byteBuf en el canal channel. bytesToWrite especifica el número de bytes a escribir. A diferencia de Tcl_Write, esta operación no realiza ninguna codificación basada en la codificación del canal.

Devuelve el número de bytes escritos. Si se produce un error, devuelve -1 y establece la variable de error de interp.

TCL_EOF

Devuelve 1 si se ha alcanzado el final del archivo en el canal channel, 0 en caso contrario.

TCL_FLUSH

Vacía cualquier dato pendiente en el búfer de salida del canal channel. Si se produce un error, devuelve -1 y establece la variable de error de interp. De lo contrario, devuelve 0.

TCL_INPUTBLOCKED

Devuelve 1 si una operación de lectura en el canal channel está bloqueada actualmente (es decir, no hay datos disponibles para leer y el canal no está en modo no bloqueante), 0 en caso contrario.

TCL_INPUTBUFFERED

Devuelve el número de bytes actualmente en el búfer de entrada del canal channel.

TCL_OUTPUTBUFFERED

Devuelve el número de bytes actualmente en el búfer de salida del canal channel.

TCL_SEEK

Cambia la posición de lectura/escritura actual en el canal channel. offset especifica cuántos bytes mover la posición, y seekMode especifica el punto de referencia (SEEK_SET para el principio del archivo, SEEK_CUR para la posición actual, SEEK_END para el final del archivo). Los canales que no son de archivo, como los sockets, no admiten esta operación.

Devuelve la nueva posición de lectura/escritura en el canal en bytes desde el principio del archivo, o -1 si se produjo un error.

TCL_TELL

Devuelve la posición de lectura/escritura actual en el canal channel en bytes desde el principio del archivo. Los canales que no son de archivo, como los sockets, no admiten esta operación.

Devuelve -1 si se produjo un error.

TCL_TRUNCATECHANNEL

Trunca el canal channel a la longitud especificada por length. La longitud debe ser no negativa. Esta operación solo es apropiada para canales de tipo archivo que se han abierto para escritura. Si se produce un error, devuelve -1 y establece la variable de error de interp. De lo contrario, devuelve 0.

TCL_GETCHANNELOPTION

Devuelve el valor de la opción optionName para el canal channel. El valor se almacena en el búfer optionValue. Si optionName es NULL, se devuelve una lista de todas las opciones y sus valores en optionValue.

Devuelve 0 si la opción se recuperó correctamente, o -1 si se produjo un error (por ejemplo, nombre de opción inválido o canal desconocido).

TCL_SETCHANNELOPTION

Establece la opción optionName del canal channel al valor newValue. Las opciones admitidas son las mismas que las del comando Tcl fconfigure, como -blocking, -buffering, -encoding, -translation y -eof.

Devuelve 0 si la opción se estableció correctamente, o -1 si se produjo un error (por ejemplo, nombre de opción inválido, valor inválido o canal desconocido).

VEASE TAMBIÉN

Tcl_CreateChannel(3), Tcl_RegisterChannel(3), Tcl_Wait(3)

TCL_OPENFILECHANNEL

Tcl_OpenFileChannel abre un archivo especificado por fileName y devuelve un manejador de canal que puede usarse para realizar entrada y salida en el archivo. Esta API está modelada según el procedimiento fopen de la biblioteca de E/S estándar de Unix. La sintaxis y el significado de todos los argumentos son similares a los dados en el comando Tcl open al abrir un archivo. Si ocurre un error al abrir el canal, Tcl_OpenFileChannel devuelve NULL y registra un código de error POSIX que puede recuperarse con Tcl_GetErrno. Además, si interp no es NULL, Tcl_OpenFileChannel deja un mensaje de error en el resultado de interp después de cualquier error. A partir de Tcl 8.4, la API basada en valores Tcl_FSOpenFileChannel debe usarse en preferencia a Tcl_OpenFileChannel siempre que sea posible.

El canal recién creado no está registrado en el intérprete suministrado; para registrarlo, use Tcl_RegisterChannel, descrito a continuación. Si uno de los canales estándar, stdin, stdout o stderr se cerró previamente, el acto de crear el nuevo canal también lo asigna como reemplazo del canal estándar.

TCL_OPENCOMMANDCHANNEL

Tcl_OpenCommandChannel proporciona una interfaz de nivel C a las funciones de los comandos exec y open. Crea una secuencia de subprocesos especificados por los argumentos argv y argc y devuelve un canal que puede usarse para comunicarse con estos subprocesos. El argumento flags indica qué tipo de comunicación existirá con la tubería del comando.

Si la bandera TCL_STDIN está establecida, la entrada estándar del primer subproceso se vinculará al canal: escribir en el canal proporcionará entrada al subproceso. Si TCL_STDIN no está establecida, la entrada estándar del primer subproceso será la misma que la entrada estándar de esta aplicación. Si TCL_STDOUT está establecida, la salida estándar del último subproceso se puede leer del canal; de lo contrario, va a la salida estándar de esta aplicación. Si TCL_STDERR está establecida, la salida de error estándar de todos los subprocesos se devuelve al canal y resulta en un error al cerrar el canal; de lo contrario, va al error estándar de esta aplicación. Si TCL_ENFORCE_MODE no está establecida, entonces argc y argv pueden redirigir los manejadores stdio para anular TCL_STDIN, TCL_STDOUT y TCL_STDERR; si está establecida, entonces es un error que argc y argv anulen los canales stdio para los cuales se han establecido TCL_STDIN, TCL_STDOUT y TCL_STDERR.

Si ocurre un error al abrir el canal, Tcl_OpenCommandChannel devuelve NULL y registra un código de error POSIX que puede recuperarse con Tcl_GetErrno. Además, Tcl_OpenCommandChannel deja un mensaje de error en el resultado del intérprete. interp no puede ser NULL.

El canal recién creado no está registrado en el intérprete suministrado; para registrarlo, use Tcl_RegisterChannel, descrito a continuación. Si uno de los canales estándar, stdin, stdout o stderr se cerró previamente, el acto de crear el nuevo canal también lo asigna como reemplazo del canal estándar.

TCL_MAKEFILECHANNEL

Tcl_MakeFileChannel crea un Tcl_Channel a partir de un manejador de archivo existente y específico de la plataforma. El canal recién creado no está registrado en el intérprete suministrado; para registrarlo, use Tcl_RegisterChannel, descrito a continuación. Si uno de los canales estándar, stdin, stdout o stderr se cerró previamente, el acto de crear el nuevo canal también lo asigna como reemplazo del canal estándar.

TCL_GETCHANNEL

Tcl_GetChannel devuelve un canal dado el channelName utilizado para crearlo con Tcl_CreateChannel y un puntero a un intérprete de Tcl en interp. Si un canal con ese nombre no está registrado en ese intérprete, el procedimiento devuelve NULL. Si el argumento modePtr no es NULL, apunta a una variable entera que recibirá una combinación OR de TCL_READABLE y TCL_WRITABLE que describe si el canal está abierto para lectura y escritura.

Tcl_GetChannelNames y Tcl_GetChannelNamesEx escriben los nombres de los canales registrados en el resultado del intérprete como un valor de lista. Tcl_GetChannelNamesEx filtrará estos nombres según el pattern. Si pattern es NULL, entonces no hará ningún filtrado. El valor de retorno es TCL_OK si no ocurrieron errores al escribir en el resultado, de lo contrario es TCL_ERROR, y el mensaje de error se deja en el resultado del intérprete.

TCL_REGISTERCHANNEL

Tcl_RegisterChannel agrega un canal al conjunto de canales accesibles en interp. Después de esta llamada, los programas Tcl que se ejecutan en ese intérprete pueden referirse al canal en operaciones de entrada o salida utilizando el nombre dado en la llamada a Tcl_CreateChannel. Después de esta llamada, el canal se convierte en propiedad del intérprete, y el llamador no debe llamar a Tcl_Close para el canal; el canal se cerrará automáticamente cuando se desregistre del intérprete.

El código que se ejecuta fuera de cualquier intérprete de Tcl puede llamar a Tcl_RegisterChannel con interp como NULL, para indicar que desea mantener una referencia a este canal. Posteriormente, el canal puede registrarse en un intérprete de Tcl y solo se cerrará cuando el número correspondiente de llamadas a Tcl_UnregisterChannel se haya realizado. Esto permite que el código que se ejecuta fuera de cualquier intérprete mantenga de forma segura una referencia a un canal que también está registrado en un intérprete de Tcl.

Este procedimiento interactúa con el código que administra los canales estándar. Si no se inicializaron canales estándar antes de la primera llamada a Tcl_RegisterChannel, se inicializarán con esa llamada. Vea Tcl_StandardChannels para un tratado general sobre los canales estándar y el comportamiento de la biblioteca Tcl con respecto a ellos.

TCL_UNREGISTERCHANNEL

Tcl_UnregisterChannel elimina un canal del conjunto de canales accesibles en interp. Después de esta llamada, los programas Tcl ya no podrán usar el nombre del canal para referirse al canal en ese intérprete. Si esta operación eliminó el último registro del canal en cualquier intérprete, el canal también se cierra y destruye.

El código no asociado con un intérprete de Tcl puede llamar a Tcl_UnregisterChannel con interp como NULL, para indicar a Tcl que ya no mantiene una referencia a ese canal. Si esta es la última referencia al canal, ahora se cerrará. Tcl_UnregisterChannel es muy similar a Tcl_DetachChannel excepto que también cerrará el canal si no existen más referencias a él.

TCL_DETACHCHANNEL

Tcl_DetachChannel elimina un canal del conjunto de canales accesibles en interp. Después de esta llamada, los programas Tcl ya no podrán usar el nombre del canal para referirse al canal en ese intérprete. Más allá de eso, este comando no tiene ningún efecto adicional. No se puede utilizar en los canales estándar (stdout, stderr, stdin), y devolverá TCL_ERROR si se le pasa uno de esos canales.

El código no asociado con un intérprete de Tcl puede llamar a Tcl_DetachChannel con interp como NULL, para indicar a Tcl que ya no mantiene una referencia a ese canal. Si esta es la última referencia al canal, a diferencia de Tcl_UnregisterChannel, no se cerrará.

TCL_ISSTANDARDCHANNEL

Tcl_IsStandardChannel prueba si un canal es uno de los tres canales estándar, stdin, stdout o stderr. Si es así, devuelve 1, de lo contrario 0.

No se hace ningún intento de verificar si el canal dado o los canales estándar están inicializados o son válidos de otra manera.

TCL_CLOSE

Tcl_Close destruye el canal channel, que debe denotar un canal actualmente abierto. El canal no debe estar registrado en ningún intérprete cuando se llama a Tcl_Close. La salida en búfer se vacía en el dispositivo de salida del canal antes de destruir el canal, y la entrada en búfer se descarta. Si este es un canal de bloqueo, la llamada no regresa hasta que todos los datos en búfer se envían correctamente al dispositivo de salida del canal. Si este es un canal sin bloqueo y hay salida en búfer que no se puede escribir sin bloquear, la llamada regresa inmediatamente; la salida se vacía en segundo plano y el canal se cerrará una vez que se haya producido toda la salida de datos en búfer. En este caso, los errores durante el vaciado no se informan.

Si el canal se cerró correctamente, Tcl_Close devuelve TCL_OK. Si ocurre un error, Tcl_Close devuelve TCL_ERROR y registra un código de error POSIX que puede recuperarse con Tcl_GetErrno. Si el canal se está cerrando sincrónicamente y ocurre un error durante el cierre del canal y interp no es NULL, se deja un mensaje de error en el resultado del intérprete.

Nota: no es seguro llamar a Tcl_Close en un canal que se ha registrado utilizando Tcl_RegisterChannel; consulte la documentación de Tcl_RegisterChannel, arriba, para obtener detalles. Si el canal se ha proporcionado alguna vez como argumento chan en una llamada a Tcl_RegisterChannel, debe usar en su lugar Tcl_UnregisterChannel, que llamará internamente a Tcl_Close cuando todas las llamadas a Tcl_RegisterChannel se hayan emparejado con llamadas correspondientes a Tcl_UnregisterChannel.

TCL_READCHARS Y TCL_READ

Tcl_ReadChars consume bytes del channel, convirtiendo los bytes a UTF-8 basándose en la codificación del canal y almacenando los datos producidos en la representación de cadena de readObjPtr. El valor de retorno de Tcl_ReadChars es el número de caracteres, hasta charsToRead, que se almacenaron en readObjPtr. Si ocurre un error al leer, el valor de retorno es -1 y Tcl_ReadChars registra un código de error POSIX que puede recuperarse con Tcl_GetErrno.

TCL_READCHARS, TCL_READOBJEJ, AND TCL_READ

Tcl_ReadChars lee hasta charsToRead caracteres del canal channel. Los caracteres leídos se añaden a la representación de cadena del objeto Tcl dado por readObjPtr. El valor de retorno es el número de caracteres leídos, o -1 si ocurre un error. Si charsToRead es negativo, Tcl_ReadChars lee todos los caracteres disponibles en el canal.

Si el canal está en modo de bloqueo, leer hasta eof (fin de archivo) hará que el comando lea todos los caracteres actualmente disponibles (no bloqueante) o todo hasta eof (modo bloqueante).

El valor de retorno puede ser menor que el valor a leer, lo que indica que menos datos de los solicitados estaban disponibles. Esto se denomina lectura corta. En modo de bloqueo, esto solo puede ocurrir en un fin de archivo. En modo no bloqueante, una lectura corta también puede ocurrir si no hay suficiente entrada actualmente disponible: Tcl_ReadChars devuelve un recuento corto en lugar de esperar más datos.

Si el canal está en modo de bloqueo, un valor de retorno de cero indica una condición de fin de archivo. Si el canal está en modo no bloqueante, un valor de retorno de cero indica que no hay entrada disponible actualmente o una condición de fin de archivo. Use Tcl_Eof y Tcl_InputBlocked para saber cuál de estas condiciones ocurrió realmente.

Tcl_ReadChars traduce las diversas representaciones de fin de línea a la representación interna canónica de \n de acuerdo con el modo de reconocimiento de fin de línea actual. El reconocimiento de fin de línea y los diversos modos específicos de plataforma se describen en la entrada del manual del comando Tcl fconfigure.

Como optimización de rendimiento, al leer de un canal con la codificación binary, los bytes no se convierten a UTF-8 a medida que se leen. En su lugar, se almacenan en la representación interna de readObjPtr como un valor de matriz de bytes. La representación de cadena de este valor solo se construirá si es necesario (por ejemplo, debido a una llamada a Tcl_GetStringFromObj). De esta manera, los datos orientados a bytes se pueden leer de un canal, manipularse llamando a Tcl_GetByteArrayFromObj y funciones relacionadas, y luego escribirse en un canal sin el costo de la conversión a o desde UTF-8.

Tcl_Read es similar a Tcl_ReadChars, excepto que no realiza conversiones de codificación, independientemente de la codificación del canal. Está obsoleto y existe para compatibilidad con versiones anteriores de extensiones Tcl no internacionalizadas. Consume bytes de channel y los almacena en readBuf, realizando traducciones de fin de línea en el camino. El valor de retorno de Tcl_Read es el número de bytes, hasta bytesToRead, escritos en readBuf. El búfer producido por Tcl_Read no está terminado en nulo. Su contenido es válido desde la posición cero hasta, y sin incluir, la posición indicada por el valor de retorno.

Tcl_ReadRaw es lo mismo que Tcl_Read pero no compensa el apilamiento. Mientras que Tcl_Read (y las otras funciones de la API) siempre obtienen sus datos del canal superior en la pila de la que forma parte el canal proporcionado, Tcl_ReadRaw no lo hace. Por lo tanto, esta función solo es utilizable para controladores de canal transformacionales, es decir, controladores utilizados en el medio de una pila de canales, para mover datos del canal inferior a la transformación.

TCL_GETSOBJ Y TCL_GETS

Tcl_GetsObj consume bytes del channel, convirtiendo los bytes a UTF-8 basándose en la codificación del canal, hasta que se haya visto una línea completa de entrada. Si la codificación del canal es binary, cada byte leído del canal se trata como un carácter Unicode individual. Todos los caracteres de la línea, excepto los caracteres de fin de línea terminales, se añaden a la representación de cadena de lineObjPtr. Los caracteres de fin de línea se leen y se descartan.

Si se leyó una línea correctamente, el valor de retorno es mayor o igual a cero e indica el número de bytes almacenados en lineObjPtr. Si ocurre un error, Tcl_GetsObj devuelve -1 y registra un código de error POSIX que se puede recuperar con Tcl_GetErrno. Tcl_GetsObj también devuelve -1 si se alcanza el fin del archivo; el procedimiento Tcl_Eof se puede utilizar para distinguir un error de una condición de fin de archivo.

Si el canal está en modo no bloqueante, el valor de retorno también puede ser -1 si no había datos disponibles o si los datos disponibles no contenían un carácter de fin de línea. Cuando se devuelve -1, el procedimiento Tcl_InputBlocked puede invocarse para determinar si el canal está bloqueado debido a la falta de entrada.

Tcl_Gets es lo mismo que Tcl_GetsObj excepto que los caracteres resultantes se añaden a la cadena dinámica dada por lineRead en lugar de un valor Tcl.

TCL_UNGETS

Tcl_Ungets se utiliza para añadir datos a la cola de entrada de un canal, en la cabeza o en la cola de la cola. El puntero input apunta a los datos que se van a añadir. La longitud de la entrada a añadir está dada por inputLen. Un valor distinto de cero de addAtEnd indica que los datos se añadirán al final de la cola; de lo contrario, se añadirán al principio de la cola. Si channel tiene un EOF "pegajoso" establecido, no se añadirán datos a la cola de entrada. Tcl_Ungets devuelve inputLen o -1 si ocurre un error.

TCL_WRITECHARS, TCL_WRITEOBJ, Y TCL_WRITE

Tcl_WriteChars acepta bytesToWrite bytes de datos de caracteres en charBuf. Los caracteres UTF-8 en el búfer se convierten a la codificación del canal y se ponen en cola para su salida a channel. Si bytesToWrite es negativo, Tcl_WriteChars espera que charBuf esté terminado en nulo y envía todo hasta el nulo.

Los datos puestos en cola para salida pueden no aparecer en el dispositivo de salida inmediatamente, debido al almacenamiento en búfer interno. Si los datos deben aparecer inmediatamente, llame a Tcl_Flush después de la llamada a Tcl_WriteChars, o establezca la opción -buffering en el canal a none. Si desea que los datos aparezcan tan pronto como se acepte una línea completa para su salida, establezca la opción -buffering en el canal en modo line.

El valor de retorno de Tcl_WriteChars es un recuento de cuántos bytes se aceptaron para su salida al canal. Es mayor que cero para indicar éxito o -1 para indicar que ocurrió un error. Si ocurre un error, Tcl_WriteChars registra un código de error POSIX que puede recuperarse con Tcl_GetErrno.

Los caracteres de nueva línea en los datos de salida se traducen a secuencias de fin de línea específicas de la plataforma según la opción -translation para el canal. Esto se hace incluso si el canal no tiene codificación.

Tcl_WriteObj es similar a Tcl_WriteChars excepto que acepta un valor Tcl cuyos contenidos se enviarán al canal. Los caracteres UTF-8 en la representación de cadena de writeObjPtr se convierten a la codificación del canal y se ponen en cola para su salida a channel. Como optimización de rendimiento, al escribir en un canal con la codificación binary, los caracteres UTF-8 no se convierten a medida que se escriben. En su lugar, los bytes en la representación interna de writeObjPtr como un valor de matriz de bytes se escriben en el canal. La representación de matriz de bytes del valor se construirá si es necesaria. De esta manera, los datos orientados a bytes se pueden leer de un canal, manipularse llamando a Tcl_GetByteArrayFromObj y funciones relacionadas, y luego escribirse en un canal sin el costo de la conversión a o desde UTF-8.

Tcl_Write es similar a Tcl_WriteChars excepto que no realiza conversiones de codificación, independientemente de la codificación del canal. Está obsoleto y existe para compatibilidad con versiones anteriores de extensiones Tcl no internacionalizadas. Acepta bytesToWrite bytes de datos en byteBuf y los pone en cola para su salida a channel. Si bytesToWrite es negativo, Tcl_Write espera que byteBuf esté terminado en nulo y envía todo hasta el nulo.

Tcl_WriteRaw es lo mismo que Tcl_Write pero no compensa el apilamiento. Mientras que Tcl_Write (y las otras funciones de la API) siempre alimentan su entrada al canal superior en la pila de la que forma parte el canal proporcionado, Tcl_WriteRaw no lo hace. Por lo tanto, esta función solo es utilizable para controladores de canal transformacionales, es decir, controladores utilizados en el medio de una pila de canales, para mover datos de la transformación al canal inferior.

TCL_FLUSH

Tcl_Flush hace que todos los datos de salida en búfer para channel se escriban en su archivo o dispositivo subyacente lo antes posible. Si el canal está en modo de bloqueo, la llamada no retorna hasta que todos los datos en búfer se hayan enviado al canal o haya ocurrido algún error. La llamada retorna inmediatamente si el canal no está en modo de bloqueo; inicia un vaciado en segundo plano que escribirá los datos en búfer en el canal eventualmente, tan rápido como el canal pueda absorberlo.

El valor de retorno es normalmente TCL_OK. Si ocurre un error, Tcl_Flush devuelve TCL_ERROR y registra un código de error POSIX que se puede recuperar con Tcl_GetErrno.

TCL_SEEK

Tcl_Seek mueve el punto de acceso en channel donde se leerán o escribirán los datos posteriores. La salida en búfer se vacía al canal y la entrada en búfer se descarta, antes de la operación de búsqueda.

Tcl_Seek normalmente devuelve el nuevo punto de acceso. Si ocurre un error, Tcl_Seek devuelve -1 y registra un código de error POSIX que puede recuperarse con Tcl_GetErrno. Después de un error, el punto de acceso puede o no haberse movido.

TCL_TELL

Tcl_Tell devuelve el punto de acceso actual para un canal. El valor devuelto es -1 si el canal no admite la búsqueda.

TCL_TRUNCATECHANNEL

Tcl_TruncateChannel trunca el archivo subyacente de channel a una longitud dada de bytes. Devuelve TCL_OK si la operación tuvo éxito y TCL_ERROR en caso contrario.

TCL_GETCHANNELOPTION

Tcl_GetChannelOption recupera, en optionValue, el valor de una de las opciones actualmente en vigor para un canal, o una lista de todas las opciones y sus valores. El argumento channel identifica el canal para el que se va a consultar una opción o recuperar todas las opciones y sus valores. Si optionName no es NULL, es el nombre de la opción a consultar; el valor de la opción se copia a la cadena dinámica Tcl denotada por optionValue. Si optionName es NULL, la función almacena una lista alterna de nombres de opciones y sus valores en optionValue.

TCL_GETCHANNELOPTION

Tcl_GetChannelOption devuelve el valor de la opción optionName para el canal channel. Si la opción no es reconocida o si ocurre un error al recuperar su valor, la opción es dejada como un mensaje de error en el resultado del interprete interp y se devuelve TCL_ERROR. De lo contrario, el valor de la opción es copiado al buffer value (que puede tener como máximo *length* bytes, incluido el terminador nulo) y se devuelve TCL_OK. Si el valor de la opción requiere más espacio que *length* bytes, entonces se devuelve TCL_ERROR y el valor correcto se deja en el resultado del interprete.

Las opciones de configuración del canal que no son específicas de un tipo de canal se describen en la página del manual de la commande Tcl fconfigure. Las opciones específicas de tipo de canal se describen en la página del manual de la commande Tcl que crea el canal; por ejemplo, las opciones adicionales para canales basados en TCP se describen en la página del manual de la commande Tcl socket. Los manejadores de canales usan un campo de opciones privado que se pasa entre ellos. El procedimiento para configurar una opción especifica de canal debe usar Tcl_DStringAppend para recopilar los valores de las opciones que pueden tomar múltiples valores, y Tcl_DStringAppendElement para añadir cada elemento a una opción multielemento.

TCL_SETCHANNELOPTION

Tcl_SetChannelOption establece un nuevo valor newValue para una opción optionName en channel. La procedimiento normalmente devuelve TCL_OK. Si ocurre un error, devuelve TCL_ERROR; en adición, si interp es no-NULL, Tcl_SetChannelOption deja un mensaje de error en el resultado del interprete.

TCL_EOF

Tcl_Eof devuelve un valor no cero si channel detectó el fin de archivo durante la última operación de entrada.

TCL_INPUTBLOCKED

Tcl_InputBlocked devuelve un valor no cero si channel está en modo no bloqueado y la última operación de entrada devolvió menos datos que se solicitó debido a la insuficiente disponibilidad de datos. La llamada siempre devuelve cero si el canal está en modo bloqueado.

TCL_INPUTBUFFERED

Tcl_InputBuffered devuelve el número de bytes de entrada actualmente bufferizados en los buffers internos de un canal. Si el canal no está abierto para lectura, esta función siempre devuelve cero.

TCL_OUTPUTBUFFERED

Tcl_OutputBuffered devuelve el número de bytes de salida actualmente bufferizados en los buffers internos de un canal. Si el canal no está abierto para escritura, esta función siempre devuelve cero.

PLATFORM ISSUES

Los handles devueltos de Tcl_GetChannelHandle dependen del sistema operativo y del tipo de canal. En los sistemas Unix, el handle siempre es un descriptor de archivo Unix como se devuelve de la llamada open. En los sistemas Windows, el handle es un objeto HANDLE cuando el canal fue creado con Tcl_OpenFileChannel, Tcl_OpenCommandChannel o Tcl_MakeFileChannel. Otros tipos de canal pueden devolver un tipo diferente de handle en los sistemas Windows.
