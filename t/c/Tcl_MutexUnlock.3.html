Threads(3) Procedimientos de la biblioteca Tcl Threads(3)

NOMBRE

Tcl_ConditionNotify, Tcl_ConditionWait, Tcl_ConditionFinalize, Tcl_GetThreadData, Tcl_MutexLock, Tcl_MutexUnlock, Tcl_MutexFinalize, Tcl_CreateThread, Tcl_JoinThread - Soporte de hilos Tcl

SINOPSIS

#include <tcl.h>

void
Tcl_ConditionNotify(condPtr)

void
Tcl_ConditionWait(condPtr, mutexPtr, timePtr)

void
Tcl_ConditionFinalize(condPtr)

Void *
Tcl_GetThreadData(keyPtr, size)

void
Tcl_MutexLock(mutexPtr)

void
Tcl_MutexUnlock(mutexPtr)

void
Tcl_MutexFinalize(mutexPtr)

int
Tcl_CreateThread(idPtr, proc, clientData, stackSize, flags)

int
Tcl_JoinThread(id, result)

ARGUMENTOS

Tcl_Condition *condPtr (entrada)
Una variable de condición, que debe estar asociada a un bloqueo de mutex.
Tcl_Mutex *mutexPtr (entrada)
Un bloqueo de mutex.
const Tcl_Time *timePtr (entrada)
Un límite de tiempo para la espera de la condición. NULL para esperar indefinidamente. Tenga en cuenta que un valor de sondeo de 0 segundos no tiene mucho sentido.
Tcl_ThreadDataKey *keyPtr (entrada)
Esto identifica un bloque de almacenamiento local del hilo. La clave debe ser estática y válida para todo el proceso, pero cada hilo terminará asociando un bloque de almacenamiento diferente con esta clave.
int *size (entrada)
El tamaño del bloque de almacenamiento local del hilo. Esta cantidad de datos se asigna y se inicializa a cero la primera vez que cada hilo llama a Tcl_GetThreadData.
Tcl_ThreadId *idPtr (salida)
El almacenamiento al que se refiere contendrá el id del hilo recién creado, tal como lo devuelve el sistema operativo.
Tcl_ThreadId id (entrada)
Id del hilo sobre el que se espera.
Tcl_ThreadCreateProc *proc (entrada)
Este procedimiento actuará como el main() del hilo recién creado. El clientData especificado será su único argumento.
ClientData clientData (entrada)
Información arbitraria. Se pasa como único argumento al proc.
int stackSize (entrada)
El tamaño de la pila dada al nuevo hilo.
int flags (entrada)
Máscara de bits que contiene indicadores que permiten al llamador modificar el comportamiento del nuevo hilo.
int *result (salida)
El almacenamiento al que se refiere se utiliza para colocar el código de salida del hilo sobre el que se espera.

INTRODUCCIÓN

A partir de la versión 8.1, el núcleo de Tcl es seguro para hilos, lo que le permite incorporar Tcl en aplicaciones multihilo sin personalizar el núcleo de Tcl. A partir de la versión 8.6, el soporte de multihilo de Tcl está activado por defecto. Para deshabilitar el soporte de multihilo de Tcl, debe incluir la opción --disable-threads en configure cuando configure y compile su núcleo de Tcl.

Una restricción importante de la implementación de hilos de Tcl es que solo el hilo que creó un intérprete de Tcl puede usar ese intérprete. En otras palabras, múltiples hilos no pueden acceder al mismo intérprete de Tcl. (Sin embargo, un solo hilo puede crear y usar múltiples intérpretes de forma segura).

DESCRIPCIÓN

Tcl proporciona Tcl_CreateThread para crear hilos. El llamador puede determinar el tamaño de la pila que se da al nuevo hilo y modificar el comportamiento a través de los flags proporcionados. El valor TCL_THREAD_STACK_DEFAULT para stackSize indica que se debe utilizar el tamaño predeterminado según lo especificado por el sistema operativo para el nuevo hilo. En cuanto a los flags, actualmente solo se definen los valores TCL_THREAD_NOFLAGS y TCL_THREAD_JOINABLE. El primer valor invoca el comportamiento predeterminado sin configuraciones especiales. Usar el segundo valor marca el nuevo hilo como unible. Esto significa que otro hilo puede esperar a que dicho hilo marcado termine y unirse a él.

Restricciones: En algunos sistemas UNIX, la biblioteca pthread no contiene la funcionalidad para especificar el tamaño de la pila de un hilo. El valor especificado para el tamaño de la pila se ignora en estos sistemas. Windows actualmente no admite hilos unibles. Por lo tanto, este valor de flag se ignora en esta plataforma.

Tcl proporciona las funciones Tcl_ExitThread y Tcl_FinalizeThread para terminar hilos e invocar manejadores de salida opcionales por hilo. Consulte la página Tcl_Exit para obtener más información sobre estos procedimientos.

La función Tcl_JoinThread se proporciona para permitir que los hilos esperen la salida de otro hilo, que debe haber sido marcado como unible mediante el uso del flag TCL_THREAD_JOINABLE durante su creación a través de Tcl_CreateThread.

Intentar esperar la salida de un hilo no unible o de un hilo sobre el que ya se está esperando resultará en un error. Es posible esperar un hilo unible que ya haya salido; el sistema conservará la información necesaria hasta después de la llamada a Tcl_JoinThread. Esto significa que no llamar a Tcl_JoinThread para un hilo unible provocará una fuga de memoria.

La llamada Tcl_GetThreadData devuelve un puntero a un bloque de datos privados del hilo. Su argumento es una clave que es compartida por todos los hilos y un tamaño para el bloque de almacenamiento. El almacenamiento se asigna automáticamente y se inicializa a ceros la primera vez que cada hilo lo solicita. El almacenamiento se libera automáticamente mediante Tcl_FinalizeThread.

SINCRONIZACIÓN Y COMUNICACIÓN

Tcl proporciona Tcl_ThreadQueueEvent y Tcl_ThreadAlert para manejar la cola de eventos en aplicaciones multihilo. Consulte la página del manual Notifier para obtener más información sobre estos procedimientos.

Un mutex es un bloqueo que se utiliza para serializar todos los hilos a través de un fragmento de código llamando a Tcl_MutexLock y Tcl_MutexUnlock. Si un hilo tiene un mutex, cualquier otro hilo que llame a Tcl_MutexLock se bloqueará hasta que se llame a Tcl_MutexUnlock. Un mutex puede ser destruido después de su uso llamando a Tcl_MutexFinalize. El resultado de bloquear un mutex dos veces desde el mismo hilo no está definido. En algunas plataformas, resultará en un interbloqueo. Los procedimientos Tcl_MutexLock, Tcl_MutexUnlock y Tcl_MutexFinalize se definen como macros vacías si no se compila con hilos habilitados. Para la declaración de mutex, se debe usar la macro TCL_DECLARE_MUTEX. Esta macro asegura un manejo correcto de los mutex incluso cuando el núcleo se compila sin hilos habilitados.

Una variable de condición se utiliza como mecanismo de señalización: un hilo puede bloquear un mutex y luego esperar en una variable de condición con Tcl_ConditionWait. Esto libera atómicamente el bloqueo del mutex y bloquea el hilo que espera hasta que otro hilo llama a Tcl_ConditionNotify. El llamador de Tcl_ConditionNotify debe tener el mutex asociado bloqueado previamente llamando a Tcl_MutexLock, pero esto no se impone. Notificar la variable de condición desbloquea todos los hilos que esperan en la variable de condición, pero estos no proceden hasta que el mutex se libera con Tcl_MutexUnlock. La implementación de Tcl_ConditionWait bloquea automáticamente el mutex antes de devolverlo.

El llamador de Tcl_ConditionWait debe estar preparado para notificaciones espurias llamando a Tcl_ConditionWait dentro de un bucle while que prueba algún invariante.

Una variable de condición puede ser destruida después de su uso llamando a Tcl_ConditionFinalize.

Los procedimientos Tcl_ConditionNotify, Tcl_ConditionWait y Tcl_ConditionFinalize se definen como macros vacías si no se compila con hilos habilitados.

INICIALIZACIÓN

Todos estos objetos de sincronización se autoinicializan. Se implementan como punteros opacos que deben ser NULL en el primer uso. Los mutex y las variables de condición se limpian mediante manejadores de salida del proceso (si viven tanto) o explícitamente mediante llamadas a Tcl_MutexFinalize o Tcl_ConditionFinalize. El almacenamiento local del hilo se recupera durante Tcl_FinalizeThread.

Tcl_MutexUnlock(3)

NAME

Tcl_MutexUnlock - libera un mutex previamente bloqueado

SYNOPSIS

#include <tcl.h>

int
Tcl_MutexUnlock(mutexPtr);

ARGUMENTS

mutexPtr (in) Puntero al mutex que se va a desbloquear.

INTRODUCTION

El paquete Thread proporciona primitivas para crear y gestionar hilos, así como para sincronizar su ejecución. A menudo se necesita un control de acceso seguro a las estructuras de datos compartidas entre hilos. Los mutexes son uno de los mecanismos que se pueden utilizar para proporcionar este control de acceso.

Se puede acceder a la funcionalidad del paquete Thread desde el nivel de script utilizando el comando thread.

DESCRIPTION

La rutina Tcl_MutexUnlock desbloquea el mutex especificado por mutexPtr. El llamador debe haber adquirido previamente el mutex utilizando Tcl_MutexLock. Si el mutex no está bloqueado por el llamador, el comportamiento es indefinido. Tras desbloquear el mutex, uno de los hilos que esperan en el mutex (si los hay) se despertará y adquirirá el bloqueo.

El valor de retorno es TCL_OK si el mutex se desbloqueó correctamente, o TCL_ERROR si se produjo un error.

ACCESO A HILOS A NIVEL DE SCRIPT

Se puede acceder a la funcionalidad del paquete Thread desde el nivel de script. Por ejemplo, para crear un hilo portátil, su función de implementación debe declararse como:

static Tcl_ThreadCreateProc MyThreadImplFunc;

Luego debe definirse como este ejemplo, que simplemente cuenta hasta un valor dado y luego finaliza.

static Tcl_ThreadCreateType
MyThreadImplFunc(
    ClientData clientData)
{
    int i, limit = (int) clientData;
    for (i=0 ; i<limit ; i++) {
        /* no haciendo nada aquí */
    }
    TCL_THREAD_CREATE_RETURN;
}

Para crear el hilo anterior, hacerlo ejecutar y esperar a que termine, haríamos esto:

int limit = 1000000000;
ClientData limitData = (void*)((intptr_t) limit);
Tcl_ThreadId id;    /* guarda la identidad del hilo creado */
int result;
if (Tcl_CreateThread(&id, MyThreadImplFunc, limitData,
        TCL_THREAD_STACK_DEFAULT,
        TCL_THREAD_JOINABLE) != TCL_OK) {
    /* El hilo no se creó correctamente */
    return;
}
/* Haz algo más por un tiempo aquí */
if (Tcl_JoinThread(id, &result) != TCL_OK) {
    /* El hilo no terminó correctamente */
    return;
}
/* Todo limpio y ordenado */
