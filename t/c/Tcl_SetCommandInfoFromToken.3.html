ARGUMENTOS

Intérprete en el que crear un nuevo comando o que contiene un comando.

Nombre del comando.

Implementación del nuevo comando: proc será llamado cada vez que cmdName sea invocado como comando.

DESCRIPCIÓN

Tcl_CreateObjCommand define un nuevo comando en interp y lo asocia con el procedimiento proc de tal manera que siempre que name sea invocado como un comando Tcl (por ejemplo, a través de una llamada a Tcl_EvalObjEx) el intérprete Tcl llamará a proc para procesar el comando.

Tcl_CreateObjCommand elimina cualquier comando existente name ya asociado con el intérprete (sin embargo, vea abajo una excepción donde el comando existente no es eliminado). Devuelve un token que puede ser usado para referirse al comando en llamadas posteriores a Tcl_GetCommandName. Si name contiene calificadores de espacio de nombres ::, entonces el comando se añade al espacio de nombres especificado; de lo contrario, el comando se añade al espacio de nombres global. Si se llama a Tcl_CreateObjCommand para un intérprete que está en proceso de ser eliminado, entonces no crea un nuevo comando y devuelve NULL. proc debe tener argumentos y un resultado que coincidan con el tipo Tcl_ObjCmdProc:

typedef int Tcl_ObjCmdProc(
        ClientData clientData,
        Tcl_Interp *interp,
        int objc,
        Tcl_Obj *const objv[]);

Cuando se invoca proc, los parámetros clientData e interp serán copias de los argumentos clientData e interp pasados a Tcl_CreateObjCommand. Típicamente, clientData apunta a una estructura de datos específica de la aplicación que describe qué hacer cuando se invoca el procedimiento del comando. Objc y objv describen los argumentos del comando, objc da el número de valores de argumento (incluyendo el nombre del comando) y objv da los valores de los argumentos. El array objv contendrá objc valores, apuntando a los valores de los argumentos. A diferencia de argv[argv] usado en un procedimiento de comando basado en cadenas, objv[objc] no contendrá NULL.

Además, cuando se invoca proc, no debe modificar el contenido del array objv asignando nuevos valores de puntero a cualquier elemento del array (por ejemplo, objv[2] = NULL) porque esto causará pérdida de memoria y corrupción de la pila de ejecución. El const en la declaración de objv hará que los compiladores compatibles con ANSI informen de cualquier intento de asignación de este tipo como un error. Sin embargo, es aceptable modificar la representación interna de cualquier valor de argumento individual. Por ejemplo, el usuario puede llamar a Tcl_GetIntFromObj en objv[2] para obtener la representación entera de ese valor; esa llamada puede cambiar el tipo del valor al que apunta objv[2], pero no cambiará dónde apunta objv[2].

proc debe devolver un código entero que sea TCL_OK, TCL_ERROR, TCL_RETURN, TCL_BREAK o TCL_CONTINUE. Consulte la página del manual de descripción general de Tcl para obtener detalles sobre el significado de estos códigos. La mayoría de los comandos normales solo devolverán TCL_OK o TCL_ERROR. Además, si proc necesita devolver un resultado no vacío, puede llamar a Tcl_SetObjResult para establecer el resultado del intérprete. En el caso de un código de retorno TCL_OK, este da el resultado del comando, y en el caso de TCL_ERROR, este da un mensaje de error. Antes de invocar un procedimiento de comando, Tcl_EvalObjEx establece el resultado del intérprete para que apunte a un valor que representa una cadena vacía, por lo que los comandos simples pueden devolver un resultado vacío sin hacer nada.

El contenido del array objv pertenece a Tcl y no se garantiza que persista una vez que proc devuelva: proc no debe modificarlos. Llame a Tcl_SetObjResult si desea devolver algo del array objv.

Normalmente, Tcl_CreateObjCommand elimina cualquier comando existente name ya asociado con el intérprete. Sin embargo, si el comando existente fue creado por una llamada anterior a Tcl_CreateCommand, Tcl_CreateObjCommand no elimina el comando, sino que organiza el intérprete Tcl para que llame al Tcl_ObjCmdProc proc en el futuro. El antiguo Tcl_CmdProc basado en cadenas asociado con el comando se conserva y su dirección se puede obtener mediante llamadas posteriores a Tcl_GetCommandInfo. Esto se hace por compatibilidad con versiones anteriores.

DeleteProc será invocado cuando (si) name sea eliminado. Esto puede ocurrir a través de una llamada a Tcl_DeleteCommand, Tcl_DeleteCommandFromToken, o Tcl_DeleteInterp, o reemplazando name en otra llamada a Tcl_CreateObjCommand. DeleteProc se invoca antes de que se elimine el comando, y le da a la aplicación la oportunidad de liberar cualquier estructura asociada con el comando. DeleteProc debe tener argumentos y un resultado que coincidan con el tipo Tcl_CmdDeleteProc:

typedef void Tcl_CmdDeleteProc(
        ClientData clientData);

El argumento clientData será el mismo que el argumento clientData pasado a Tcl_CreateObjCommand.

Tcl_DeleteCommand elimina un comando de un intérprete de comandos. Una vez completada la llamada, los intentos de invocar cmdName en interp resultarán en errores. Si cmdName no está enlazado como comando en interp, entonces Tcl_DeleteCommand no hace nada y devuelve -1; de lo contrario, devuelve 0. No hay restricciones sobre cmdName: puede referirse a un comando incorporado, un comando específico de la aplicación o un procedimiento Tcl. Si name contiene calificadores de espacio de nombres ::, el comando se elimina del espacio de nombres especificado.

Dado un token devuelto por Tcl_CreateObjCommand, Tcl_DeleteCommandFromToken elimina el comando de un intérprete de comandos. Eliminará un comando incluso si ese comando ha sido renombrado. Una vez completada la llamada, los intentos de invocar el comando en interp resultarán en errores. Si el comando correspondiente al token ya ha sido eliminado de interp, entonces Tcl_DeleteCommand no hace nada y devuelve -1; de lo contrario, devuelve 0.

Tcl_GetCommandInfo comprueba si su argumento cmdName existe como comando en interp. cmdName puede incluir calificadores de espacio de nombres :: para identificar un comando en un espacio de nombres particular. Si no se encuentra el comando, devuelve 0. De lo contrario, coloca información sobre el comando en la estructura Tcl_CmdInfo apuntada por infoPtr y devuelve 1. Una estructura Tcl_CmdInfo tiene los siguientes campos:

typedef struct Tcl_CmdInfo {
  Tcl_ObjCmdProc *objProc;
  ClientData clientData;
  Tcl_CmdDeleteProc *deleteProc;
  const char *cmdName;
  const char *cmdNamespace;
} Tcl_CmdInfo;

El campo objProc contiene un puntero al procedimiento de implementación del comando, o NULL si el comando no se implementó mediante un procedimiento basado en objetos. El campo clientData contiene los datos del cliente asociados con el comando. El campo deleteProc contiene un puntero al procedimiento de eliminación del comando, o NULL si no hay ninguno. El campo cmdName contiene el nombre del comando en el intérprete. El campo cmdNamespace contiene el nombre del espacio de nombres en el que reside el comando. Si el comando está en el espacio de nombres global, este campo será NULL.

Tcl_SetCommandInfo establece información sobre un comando existente en el intérprete interp. El cmdName especifica el comando. infoPtr apunta a una estructura Tcl_CmdInfo que contiene la nueva información para el comando. Actualmente, esta función solo puede modificar clientData y deleteProc. Los otros campos de la estructura Tcl_CmdInfo se ignoran. Si el comando no existe, devuelve 0, de lo contrario devuelve 1.

Tcl_GetCommandInfoFromToken es similar a Tcl_GetCommandInfo, pero toma un token de comando en lugar de un nombre de comando. Recupera información sobre el comando asociado con el token y la almacena en la estructura apuntada por infoPtr. Devuelve 1 si el comando se encontró y la información se recuperó correctamente, y 0 en caso contrario.

Tcl_SetCommandInfoFromToken es similar a Tcl_SetCommandInfo, pero toma un token de comando en lugar de un nombre de comando. Establece la información para el comando asociado con el token. Devuelve 1 si la información se estableció correctamente, y 0 en caso contrario.

Tcl_GetCommandName devuelve el nombre completo del comando asociado con el token dado. El nombre devuelto es un puntero a una cadena que pertenece al intérprete y no debe ser modificado ni liberado por la aplicación. Si el token no es válido o ya no está asociado con un comando, devuelve NULL.

Tcl_GetCommandFullName recupera el nombre completo del comando asociado con el token dado y lo almacena en el objeto Tcl apuntado por objPtr. Este objeto Tcl contendrá el nombre completo del comando como una cadena. Si el token no es válido o ya no está asociado con un comando, el objeto Tcl resultante estará vacío.

Tcl_GetCommandFromObj busca un comando en el intérprete interp cuyo nombre se especifica en el objeto Tcl objPtr. Si se encuentra un comando, devuelve un token para ese comando. Si no se encuentra ningún comando, o si objPtr no contiene un nombre de comando válido, devuelve NULL.

DESCRIPTION

The structure Tcl_CmdInfo is used to hold information about a Tcl command. The fields are:

    int isNativeObjectProc;
    Tcl_ObjCmdProc *objProc;
    ClientData objClientData;
    Tcl_CmdProc *proc;
    ClientData clientData;
    Tcl_CmdDeleteProc *deleteProc;
    ClientData deleteData;
    Tcl_Namespace *namespacePtr;
} Tcl_CmdInfo;

The isNativeObjectProc field has the value 1 if Tcl_CreateObjCommand was called to register the command; it is 0 if only Tcl_CreateCommand was called. It allows a program to determine whether it is faster to call objProc or proc: objProc is normally faster if isNativeObjectProc has the value 1. The fields objProc and objClientData have the same meaning as the proc and clientData arguments to Tcl_CreateObjCommand; they hold information about the value-based command procedure that the Tcl interpreter calls to implement the command. The fields proc and clientData hold information about the string-based command procedure that implements the command. If Tcl_CreateCommand was called for this command, this is the procedure passed to it; otherwise, this is a compatibility procedure registered by Tcl_CreateObjCommand that simply calls the command's value-based procedure after converting its string arguments to Tcl values. The field deleteData is the ClientData value to pass to deleteProc; it is normally the same as clientData but may be set independently using the Tcl_SetCommandInfo procedure. The field namespacePtr holds a pointer to the Tcl_Namespace that contains the command.

Tcl_GetCommandInfoFromToken is identical to Tcl_GetCommandInfo except that it uses a command token returned from Tcl_CreateObjCommand in place of the command name. If the token parameter is NULL, it returns 0; otherwise, it returns 1 and fills in the structure designated by infoPtr.

Tcl_SetCommandInfo is used to modify the procedures and ClientData values associated with a command. Its cmdName argument is the name of a command in interp. cmdName may include :: namespace qualifiers to identify a command in a particular namespace. If this command does not exist then Tcl_SetCommandInfo returns 0. Otherwise, it copies the information from *infoPtr to Tcl's internal structure for the command and returns 1.

Tcl_SetCommandInfoFromToken is identical to Tcl_SetCommandInfo except that it takes a command token as returned by Tcl_CreateObjCommand instead of the command name. If the token parameter is NULL, it returns 0. Otherwise, it copies the information from *infoPtr to Tcl's internal structure for the command and returns 1.

Note that Tcl_SetCommandInfo and Tcl_SetCommandInfoFromToken both allow the ClientData for a command's deletion procedure to be given a different value than the ClientData for its command procedure.

Note that neither Tcl_SetCommandInfo nor Tcl_SetCommandInfoFromToken will change a command's namespace. Use Tcl_Eval to call the rename command to do that.

Tcl_GetCommandName provides a mechanism for tracking commands that have been renamed. Given a token returned by Tcl_CreateObjCommand when the command was created, Tcl_GetCommandName returns the string name of the command. If the command has been renamed since it was created, then Tcl_GetCommandName returns the current name. This name does not include any :: namespace qualifiers. The command corresponding to token must not have been deleted. The string returned by Tcl_GetCommandName is in dynamic memory owned by Tcl and is only guaranteed to retain its value as long as the command is not deleted or renamed; callers should copy the string if they need to keep it for a long time.

Tcl_GetCommandFullName produces the fully qualified name of a command from a command token. The name, including all namespace prefixes, is appended to the value specified by objPtr.

Tcl_GetCommandFromObj returns a token for the command specified by the name in a Tcl_Obj. The command name is resolved relative to the current namespace. Returns NULL if the command is not found.
