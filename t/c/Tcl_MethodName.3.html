DESCRIPCION

Un método es una operación que se lleva a cabo en un objeto y que está asociada a él. Cada método debe estar asociado a un objeto o a una clase; los métodos asociados a una clase se asocian a todas las instancias (directas e indirectas) de esa clase.

Dado un método, la entidad que lo declaró se puede encontrar usando Tcl_MethodDeclarerClass, que devuelve la clase a la que está asociado el método (o NULL si el método no está asociado a ninguna clase), y Tcl_MethodDeclarerObject, que devuelve el objeto al que está asociado el método (o NULL si el método no está asociado a un objeto). El nombre del método se puede obtener con Tcl_MethodName y si el método está exportado se obtiene con Tcl_MethodIsPublic. El tipo del método también se puede introspeccionar hasta cierto punto; la función Tcl_MethodIsType devuelve si un método es de un tipo particular, asignando el clientData por método a la variable apuntada por clientDataPtr si (que no es NULL) si el tipo coincide.

CREACIÓN DE MÉTODOS

Los métodos se crean con Tcl_NewMethod y Tcl_NewInstanceMethod, que crean un método asociado a una clase o a un objeto respectivamente. En ambos casos, el argumento nameObj da el nombre del método a crear, el argumento isPublic indica si el método debe exportarse inicialmente, el argumento methodTypePtr describe la implementación del método (ver la sección TIPOS DE MÉTODOS a continuación) y el argumento clientData proporciona algunos datos específicos de la implementación que se pasan a la implementación del método cuando se llama.

Cuando el argumento nameObj de Tcl_NewMethod es NULL, se crea un método sin nombre, que se utiliza para constructores y destructores. Los constructores deben instalarse en su clase usando la función Tcl_ClassSetConstructor, y los destructores (que no deben requerir ningún argumento) deben instalarse en su clase usando la función Tcl_ClassSetDestructor. Los métodos sin nombre no deben usarse para ningún otro propósito, y los métodos con nombre no deben usarse como constructores ni destructores. Tenga en cuenta también que un methodTypePtr NULL se utiliza para proporcionar una señalización interna y no debe usarse en código de cliente.

CONTEXTOS DE LLAMADA DE MÉTODOS

Cuando se llama a un método, se pasa una referencia de contexto de llamada de método como uno de los argumentos a la función de implementación. Este contexto puede inspeccionarse para proporcionar información sobre el llamador, pero no debe conservarse más allá del momento en que finaliza la llamada al método.

El método que se está llamando se puede recuperar del contexto utilizando Tcl_ObjectContextMethod, y el objeto que provocó la invocación del método se puede recuperar con Tcl_ObjectContextObject. El número de argumentos que deben omitirse (por ejemplo, el nombre del objeto y el nombre del método en una llamada de método normal) se lee con Tcl_ObjectContextSkippedArgs, y el contexto también puede informar si está funcionando como un filtro para otro método a través de Tcl_ObjectContextIsFiltering.

Durante la ejecución de un método, la implementación del método puede optar por invocar las etapas de la cadena de llamadas de métodos que vienen después de la implementación actual del método. Esto (el núcleo del comando next) se hace utilizando Tcl_ObjectContextInvokeNext. Tenga en cuenta que esta función no manipula la pila de marcos de llamada, a diferencia del comando next; si la implementación del método ha insertado uno o más marcos adicionales en la pila como parte de su implementación, también es responsable de extraer temporalmente esos marcos de la pila mientras se ejecuta la función Tcl_ObjectContextInvokeNext. Tenga en cuenta también que el contexto de llamada de método *nunca* se elimina durante la ejecución de esta función.

TIPOS DE MÉTODOS

Los tipos de métodos se describen mediante un puntero a una estructura Tcl_MethodType, que se define como:

typedef struct {
    int version;
    const char *name;
    Tcl_MethodCallProc *callProc;
    Tcl_MethodDeleteProc *deleteProc;
    Tcl_CloneProc *cloneProc;
} Tcl_MethodType;

El campo version permite la expansión futura de la estructura y siempre debe declararse igual a TCL_OO_METHOD_VERSION_CURRENT. El campo name proporciona un nombre legible por humanos para el tipo y es el valor que se expone a través de los comandos Tcl info class methodtype e info object methodtype.

El campo callProc proporciona una función que se llama cuando se invoca el método; nunca debe ser NULL.

El campo deleteProc proporciona una función que se utiliza para eliminar un método particular y se llama cuando el método se reemplaza o se elimina; si el campo es NULL, se asume que el clientData del método no necesita ninguna acción especial para eliminarse.

El campo cloneProc es una función que se utiliza para copiar el clientData de un método (como parte de Tcl_CopyObjectInstance) o NULL para indicar que el clientData se puede copiar directamente.

FIRMA DE FUNCIÓN TCL_METHODCALLPROC

La firma de la función callProc es:

typedef int (*Tcl_MethodCallProc)(
    ClientData clientData,
    Tcl_Interp *interp,
    int objc,
    Tcl_Obj *const objv[]);

Los métodos que se delegan a un método de una clase base (es decir, los métodos que son el resultado de una llamada a next) tienen un contexto de llamada de método adicional en el argumento clientData. En tales casos, el campo clientData de la llamada al método será en realidad un puntero a una estructura Tcl_ObjectContext.

DESCRIPTION

TclOO proporciona un sistema de objetos potente y flexible. Los métodos son un componente central de este sistema, permitiendo a los objetos y clases definir comportamiento. Las funciones descritas en esta página de manual son las interfaces C para crear, acceder y gestionar estos métodos.

Tcl_NewMethod

Crea un nuevo método de clase. Los métodos de clase se heredan de las clases base y pueden ser invocados en instancias de la clase, pero también en la propia clase.

Tcl_NewInstanceMethod

Crea un nuevo método de instancia. Los métodos de instancia sólo pueden ser invocados en instancias de la clase, no en la clase misma.

Tcl_CreateMethod

Crea un nuevo método y lo asocia con el contexto de objeto especificado (una clase o una instancia). El método creado es accesible a través de la interfaz Tcl.

Tcl_GetMethod

Recupera un método existente de un contexto de objeto dado. Las banderas pueden usarse para controlar la búsqueda del método (por ejemplo, buscar en las clases base).

Tcl_MethodName

Devuelve el nombre del método especificado.

Tcl_MethodPackage

Devuelve el nombre del paquete al que pertenece el método, o NULL si el método no pertenece a ningún paquete.

Tcl_MethodKind

Devuelve el tipo del método (por ejemplo, método de clase, método de instancia, método de avance).

METHOD TYPES

Los métodos en TclOO pueden ser de varios tipos. Las siguientes firmas de función definen los procedimientos que pueden ser utilizados para implementar estos tipos de métodos:

TCL_METHODCALLPROC FUNCTION SIGNATURE

Las funciones que coinciden con esta firma se llaman cuando se invoca el método.

typedef int Tcl_MethodCallProc(
        ClientData clientData,
        Tcl_Interp *interp,
        Tcl_ObjectContext objectContext,
        int objc,
        Tcl_Obj *const *objv);

El argumento clientData para un Tcl_MethodCallProc es el valor que se proporcionó cuando se creó el método, el interp es un lugar para ejecutar scripts y acceder a variables, así como para poner el resultado del método, y los campos objc y objv proporcionan los objetos de parámetro para el método. El contexto de llamada del método se puede descubrir a través del argumento objectContext, y el valor de retorno de un Tcl_MethodCallProc es cualquier código de retorno de Tcl (por ejemplo, TCL_OK, TCL_ERROR).

TCL_METHODDELETEPROC FUNCTION SIGNATURE

Las funciones que coinciden con esta firma se utilizan cuando se elimina un método, ya sea porque se crea un nuevo método o porque se elimina el objeto o la clase.

typedef void Tcl_MethodDeleteProc(
        ClientData clientData);

El argumento clientData para un Tcl_MethodDeleteProc será el mismo que el valor pasado al argumento clientData de Tcl_NewMethod o Tcl_NewInstanceMethod cuando se creó el método.

TCL_CLONEPROC FUNCTION SIGNATURE

Las funciones que coinciden con esta firma se utilizan para copiar un método cuando el objeto o la clase se copian usando Tcl_CopyObjectInstance (o oo::copy).

typedef int Tcl_CloneProc(
        Tcl_Interp *interp,
        ClientData oldClientData,
        ClientData *newClientDataPtr);

El argumento interp proporciona un lugar para escribir un mensaje de error cuando el intento de clonar el objeto falla, en cuyo caso el procedimiento de clonación también debe devolver TCL_ERROR; de lo contrario, debe devolver TCL_OK. El campo oldClientData de un Tcl_CloneProc proporciona el valor del método que se está copiando, y el campo newClientDataPtr apuntará a una variable en la que se escribirá el valor para el método al que se está copiando.
