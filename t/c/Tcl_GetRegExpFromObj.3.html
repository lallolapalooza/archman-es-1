NOMBRE

Tcl_RegExpMatch, Tcl_RegExpCompile, Tcl_RegExpExec, Tcl_RegExpRange, Tcl_GetRegExpFromObj, Tcl_RegExpMatchObj, Tcl_RegExpExecObj, Tcl_RegExpGetInfo - Coincidencia de patrones con expresiones regulares

SINOPSIS

#include <tcl.h>

int
Tcl_RegExpMatchObj(interp, textObj, patObj)

int
Tcl_RegExpMatch(interp, text, pattern)

Tcl_RegExp
Tcl_RegExpCompile(interp, pattern)

int
Tcl_RegExpExec(interp, regexp, text, start)

void
Tcl_RegExpRange(regexp, index, startPtr, endPtr)

Tcl_RegExp
Tcl_GetRegExpFromObj(interp, patObj, cflags)

int
Tcl_RegExpExecObj(interp, regexp, textObj, offset, nmatches, eflags)

void
Tcl_RegExpGetInfo(regexp, infoPtr)

ARGUMENTOS

Tcl_Interp *interp (entrada)
Intérprete Tcl a utilizar para la notificación de errores. El intérprete puede ser NULL si no se desea notificación de errores.
Tcl_Obj *textObj (entrada/salida)
Se refiere al valor del cual obtener el texto a buscar. La representación interna del valor puede ser convertida a un formato que pueda ser buscado eficientemente.
Tcl_Obj *patObj (entrada/salida)
Se refiere al valor del cual obtener una expresión regular. La expresión regular compilada se almacena en caché en el valor.
const char *text (entrada)
Texto en el que buscar una coincidencia con una expresión regular.
const char *pattern (entrada)
Cadena en forma de patrón de expresión regular.
Tcl_RegExp regexp (entrada)
Expresión regular compilada. Debe haber sido devuelta previamente por Tcl_GetRegExpFromObj o Tcl_RegExpCompile.
const char *start (entrada)
Si text es solo una porción de alguna otra cadena, este argumento identifica el inicio de la cadena más grande. Si no es el mismo que text, entonces no se permitirán coincidencias de “^”.
int index (entrada)
Especifica qué rango se desea: 0 significa el rango de la coincidencia completa, 1 o mayor significa el rango que coincidió con una subexpresión entre paréntesis.
const char **startPtr (salida)
La dirección del primer carácter en el rango se almacena aquí, o NULL si no existe dicho rango.
const char **endPtr (salida)
La dirección del carácter justo después del último carácter del rango se almacena aquí, o NULL si no existe dicho rango.
int cflags (entrada)
Combinación OR de las banderas de compilación TCL_REG_ADVANCED, TCL_REG_EXTENDED, TCL_REG_BASIC, TCL_REG_EXPANDED, TCL_REG_QUOTE, TCL_REG_NOCASE, TCL_REG_NEWLINE, TCL_REG_NLSTOP, TCL_REG_NLANCH, TCL_REG_NOSUB y TCL_REG_CANMATCH. Ver más abajo para más información.
int offset (entrada)
El desplazamiento de caracteres en el texto donde debe comenzar la coincidencia. El valor del desplazamiento no tiene impacto en las coincidencias de ^. Este comportamiento está controlado por eflags.
int nmatches (entrada)
El número de subexpresiones coincidentes que deben recordarse para su uso posterior. Si este valor es 0, entonces no se calculará ninguna información de coincidencia de subexpresión. Si el valor es -1, entonces se recordarán todas las subexpresiones coincidentes. Cualquier otro valor se tomará como el número máximo de subexpresiones a recordar.
int eflags (entrada)
Combinación OR de las banderas de ejecución TCL_REG_NOTBOL y TCL_REG_NOTEOL. Ver más abajo para más información.
Tcl_RegExpInfo *infoPtr (salida)
La dirección de la ubicación donde se debe almacenar información sobre una coincidencia previa por Tcl_RegExpGetInfo.

DESCRIPCIÓN

Tcl_RegExpMatch determina si su argumento pattern coincide con regexp, donde regexp se interpreta como una expresión regular utilizando las reglas de la página de referencia re_syntax. Si hay una coincidencia, Tcl_RegExpMatch devuelve 1. Si no hay coincidencia, Tcl_RegExpMatch devuelve 0. Si ocurre un error en el proceso de coincidencia (por ejemplo, pattern no es una expresión regular válida), Tcl_RegExpMatch devuelve -1 y deja un mensaje de error en el resultado del intérprete. Tcl_RegExpMatchObj es similar a Tcl_RegExpMatch excepto que opera sobre los valores Tcl textObj y patObj en lugar de cadenas UTF. Tcl_RegExpMatchObj es generalmente más eficiente que Tcl_RegExpMatch, por lo que es la interfaz preferida.

Tcl_RegExpCompile, Tcl_RegExpExec y Tcl_RegExpRange proporcionan acceso de nivel inferior al coincidador de patrones de expresiones regulares. Tcl_RegExpCompile compila una cadena de expresión regular a la forma interna utilizada para una coincidencia de patrones eficiente. El valor de retorno es un token para esta forma compilada, que puede usarse en llamadas posteriores a Tcl_RegExpExec o Tcl_RegExpRange. Si ocurre un error al compilar la expresión regular, Tcl_RegExpCompile devuelve NULL y deja un mensaje de error en el resultado del intérprete. Nota: el valor de retorno de Tcl_RegExpCompile solo es válido hasta la próxima llamada a Tcl_RegExpCompile; no es seguro conservar estos valores durante períodos prolongados.

Tcl_RegExpExec ejecuta el coincidador de patrones de expresiones regulares. Devuelve 1 si text contiene un rango de caracteres que coincide con regexp, 0 si no se encuentra ninguna coincidencia y -1 si ocurre un error. En caso de error, Tcl_RegExpExec deja un mensaje de error en el resultado del intérprete. Al buscar en una cadena múltiples coincidencias de un patrón, es importante distinguir entre el inicio de la cadena original y el inicio de la búsqueda actual. Por ejemplo, al buscar la segunda ocurrencia de una coincidencia, el argumento text podría apuntar al carácter justo después de la primera coincidencia; sin embargo, es importante que el coincidador de patrones sepa que este no es el inicio de toda la cadena, para que no permita que los átomos “^” en el patrón coincidan. El argumento start proporciona esta información al apuntar al inicio de la cadena general que contiene text. Start será menor o igual que text; si es menor que text, entonces no se permitirán coincidencias de ^.

Tcl_RegExpRange puede invocarse después de que Tcl_RegExpExec devuelva; proporciona información detallada sobre qué rangos de la cadena coincidieron con qué partes del patrón. Tcl_RegExpRange devuelve un par de punteros en *startPtr y *endPtr que identifican un rango de caracteres en la cadena de origen para la llamada más reciente a Tcl_RegExpExec. Index indica cuál de varios rangos se desea: si index es 0, se devuelve información sobre el rango general de caracteres que coincidió con el patrón completo; de lo contrario, se devuelve información sobre el rango de caracteres que coincidió con la subexpresión entre paréntesis index dentro del patrón. Si no existe un rango correspondiente a index, se almacena NULL en *startPtr y *endPtr.

Tcl_GetRegExpFromObj, Tcl_RegExpExecObj y Tcl_RegExpGetInfo son interfaces de valor que proporcionan el control más directo de la biblioteca de expresiones regulares de Henry Spencer. Para los usuarios que necesiten modificar las opciones de compilación y ejecución directamente, se recomienda utilizar estas interfaces en lugar de llamar a las funciones internas de expresiones regulares. Estas interfaces manejan los detalles de las traducciones de UTF a Unicode, además de proporcionar un rendimiento mejorado a través de la caché en los valores del patrón y la cadena.

Tcl_GetRegExpFromObj intenta devolver una expresión regular compilada desde patObj. Si el valor aún no contiene una expresión regular compilada, intentará crear una a partir de la cadena en el valor y la asignará a la representación interna de patObj. El valor de retorno de esta función es de tipo Tcl_RegExp. El valor de retorno es un token para esta forma compilada, que puede usarse en llamadas posteriores a Tcl_RegExpExecObj o Tcl_RegExpGetInfo. Si ocurre un error al compilar la expresión regular, Tcl_GetRegExpFromObj devuelve NULL y deja un mensaje de error en el resultado del intérprete. El token de la expresión regular puede usarse siempre que la representación interna de patObj se refiera a la forma compilada. El argumento cflags es una combinación bit a bit de cero o más de las siguientes banderas que controlan la compilación de patObj:

TCL_REG_ADV
Habilita las características avanzadas de expresiones regulares de Henry Spencer, que incluyen la coincidencia de no retroceso y otras características que no están disponibles en la sintaxis de expresiones regulares POSIX. Esto está habilitado por defecto en las versiones recientes de Tcl. Si no se especifica esta bandera, se utilizan las expresiones regulares extendidas de POSIX, que son un subconjunto de las expresiones regulares avanzadas.
TCL_REG_EXTENDED
Interpreta el patrón como una expresión regular extendida de POSIX, tal como se describe en el manual re_syntax. Todas las expresiones regulares en Tcl se interpretan de esta manera de forma predeterminada. Si no se especifica esta bandera, se utilizan expresiones regulares básicas de POSIX.
TCL_REG_BASIC
Interpreta el patrón como una expresión regular básica de POSIX. Esto generalmente solo se usa cuando se necesita compatibilidad con sistemas más antiguos.
TCL_REG_EXPANDED
Permite el uso de espacios en blanco y comentarios en el patrón de expresión regular para mejorar la legibilidad. Los espacios en blanco se ignoran, excepto cuando están precedidos por una barra invertida o forman parte de una clase de caracteres. Los comentarios comienzan con “#” y continúan hasta el final de la línea.
TCL_REG_QUOTE
Trata el patrón como una cadena literal en lugar de una expresión regular. Esto es útil cuando se desea buscar una cadena que podría contener caracteres especiales de expresiones regulares, pero se desea tratarlos como caracteres literales.
TCL_REG_NOCASE
Realiza una coincidencia sin distinción entre mayúsculas y minúsculas. Esto afecta a todas las comparaciones de caracteres, incluidas las que se realizan dentro de las clases de caracteres.
TCL_REG_NEWLINE
Cambia el comportamiento de los anclajes “^” y “$”. Normalmente, “^” solo coincide con el principio de la cadena, y “$” solo coincide con el final de la cadena. Cuando se establece esta bandera, “^” coincide con el principio de la cadena o justo después de un carácter de nueva línea. “$” coincide con el final de la cadena o justo antes de un carácter de nueva línea.
TCL_REG_NLSTOP
Hace que los caracteres de nueva línea (“\n”) detengan la coincidencia de los metacaracteres “.”, “*”, “+”, “?”, y el cuantificador “{m,n}” como si la coincidencia terminara en el carácter de nueva línea. Esto es útil cuando se busca en texto que contiene múltiples líneas y no se desea que las coincidencias se extiendan a través de las líneas.
TCL_REG_NLANCH
Hace que “^” coincida con el principio de la cadena o justo después de un carácter de nueva línea. Hace que “$” coincida con el final de la cadena o justo antes de un carácter de nueva línea. Este es el comportamiento predeterminado cuando se utiliza la bandera TCL_REG_NEWLINE.
TCL_REG_NOSUB
Si se especifica esta bandera, Tcl_RegExpExec y Tcl_RegExpExecObj solo informarán si hubo una coincidencia o no. No se calcularán ni se almacenarán los detalles de las subexpresiones coincidentes. Esto puede mejorar el rendimiento si solo necesita saber si hay una coincidencia.
TCL_REG_CANMATCH
Esta bandera se utiliza en combinación con Tcl_GetRegExpFromObj para compilar un patrón que puede ser usado por la primitiva string match. En particular, esto significa que el patrón solo puede contener los comodines de Tcl estándar (“*”, “?”, “[...]”, “...?”) y no expresiones regulares más complejas.

Tcl_RegExpExecObj ejecuta el coincidador de patrones de expresiones regulares. El argumento regexp es un token de expresión regular compilada, típicamente obtenido de una llamada previa a Tcl_GetRegExpFromObj. El argumento textObj es un valor Tcl que contiene el texto en el que buscar. El argumento offset especifica el desplazamiento de caracteres dentro del texto donde debe comenzar la coincidencia. El argumento nmatches especifica cuántas subexpresiones coincidentes se deben registrar. Si es 0, no se registra ninguna subexpresión. Si es -1, se registran todas las subexpresiones. Si es un entero positivo, se registran como máximo ese número de subexpresiones. El argumento eflags es una combinación OR de las siguientes banderas: TCL_REG_NOTBOL y TCL_REG_NOTEOL. Si estas banderas se establecen, el comportamiento de los anclajes de inicio de línea (“^”) y final de línea (“$”) se modifica. Ver más abajo para más información. La función devuelve 1 si se encuentra una coincidencia, 0 si no se encuentra ninguna y -1 si ocurre un error.

Tcl_RegExpGetInfo rellena la estructura Tcl_RegExpInfo con información sobre la coincidencia más reciente realizada por Tcl_RegExpExecObj. La estructura Tcl_RegExpInfo tiene los siguientes campos:

int nmatches
El número de subexpresiones coincidentes que fueron encontradas.
int extendendis
El número de subexpresiones coincidentes que fueron encontradas.
Tcl_RegExpInfo.matches[]
Una matriz de estructuras de rango, cada una con campos start y end. El índice 0 contiene la información de rango para la coincidencia completa, y los índices posteriores contienen la información de rango para las subexpresiones entre paréntesis correspondientes.

Las banderas eflags para Tcl_RegExpExecObj son:

TCL_REG_NOTBOL
Si se especifica esta bandera, el carácter “^” no coincidirá con el principio de la cadena de texto, incluso si el texto proporcionado está al principio de la cadena original. Solo coincidirá con el principio de la cadena si el texto proporcionado es la cadena completa y el offset es cero.
TCL_REG_NOTEOL
Si se especifica esta bandera, el carácter “$” no coincidirá con el final de la cadena de texto, incluso si el texto proporcionado está al final de la cadena original. Solo coincidirá con el final de la cadena si el texto proporcionado es la cadena completa y el offset es el final de la cadena.

El uso de la bandera TCL_REG_ADV en Tcl_GetRegExpFromObj habilita las extensiones de Henry Spencer a la sintaxis de expresiones regulares POSIX. Estas extensiones incluyen características como la coincidencia de no retroceso (ej. \P), las clases de caracteres de Unicode (ej. \p{L}) y otras construcciones avanzadas. Si TCL_REG_ADV no se especifica, Tcl utiliza la sintaxis de expresiones regulares extendidas POSIX por defecto. La bandera TCL_REG_EXTENDED se utiliza explícitamente para indicar el uso de esta sintaxis, mientras que TCL_REG_BASIC especifica el uso de la sintaxis de expresiones regulares básicas de POSIX, que es más restrictiva.

La bandera TCL_REG_NEWLINE modifica el comportamiento de los anclajes de inicio de línea (“^”) y final de línea (“$”). Cuando se utiliza, “^” coincide con el principio de la cadena o inmediatamente después de un carácter de nueva línea. De manera similar, “$” coincide con el final de la cadena o inmediatamente antes de un carácter de nueva línea. Las banderas TCL_REG_NLSTOP y TCL_REG_NLANCH ofrecen un control más fino sobre cómo los caracteres de nueva línea interactúan con los metacaracteres y anclajes, permitiendo limitar las coincidencias a una sola línea si es necesario.

NOMBRE

Tcl_GetRegExpFromObj, Tcl_RegExpExecObj, Tcl_RegExpGetInfo - compilar y ejecutar expresiones regulares de Tcl

SINOPSIS

#include <tcl.h>
Tcl_RegExp GetRegExpFromObj(Tcl_Interp *interp, Tcl_Obj *objPtr);
int Tcl_RegExpExecObj(Tcl_Interp *interp, Tcl_RegExp regexp, Tcl_Obj *objPtr,
        int offset, int nmatches, int eflags);
int Tcl_RegExpGetInfo(Tcl_Interp *interp, Tcl_RegExp regexp,
        Tcl_RegExpInfo *infoPtr);

ARGUMENTOS

TCL_REG_ADVANCED
Compilar expresiones regulares avanzadas (“ARE”s). Este modo corresponde a la sintaxis normal de expresiones regulares aceptada por los comandos regexp y regsub de Tcl.
TCL_REG_EXTENDED
Compilar expresiones regulares extendidas (“ERE”s). Este modo corresponde a la sintaxis de expresiones regulares reconocida por Tcl 8.0 y versiones anteriores.
TCL_REG_BASIC
Compilar expresiones regulares básicas (“BRE”s). Este modo corresponde a la sintaxis de expresiones regulares reconocida por utilidades comunes de Unix como sed y grep. Este es el valor por defecto si no se especifican flags.
TCL_REG_EXPANDED
Compilar la expresión regular (básica, extendida o avanzada) usando una sintaxis expandida que permite comentarios y espacios en blanco. Este modo hace que los espacios en blanco no escapados y no entre corchetes, así como los comentarios de estilo #-a-fin-de-línea, sean ignorados.
TCL_REG_QUOTE
Compilar una cadena literal, con todos los caracteres tratados como caracteres ordinarios.
TCL_REG_NOCASE
Compilar para coincidencias que ignoran las distinciones entre mayúsculas y minúsculas.
TCL_REG_NEWLINE
Compilar para coincidencias sensibles a saltos de línea. Por defecto, el salto de línea es un carácter completamente ordinario sin significado especial ni en expresiones regulares ni en cadenas. Con este flag, los corchetes “[^” y el “.” nunca coinciden con el salto de línea, el “^” coincide con una cadena vacía después de cualquier salto de línea además de su función normal, y el “$” coincide con una cadena vacía antes de cualquier salto de línea además de su función normal. REG_NEWLINE es el OR a nivel de bits de REG_NLSTOP y REG_NLANCH.
TCL_REG_NLSTOP
Compilar para coincidencias parciales sensibles a saltos de línea, con el comportamiento de los corchetes “[^” y el “.” afectado, pero no el comportamiento del “^” y el “$”. En este modo, los corchetes “[^” y el “.” nunca coinciden con el salto de línea.
TCL_REG_NLANCH
Compilar para coincidencias inversas parciales sensibles a saltos de línea, con el comportamiento del “^” y el “$” (los “anclajes”) afectado, pero no el comportamiento de los corchetes “[^” y el “.”. En este modo, el “^” coincide con una cadena vacía después de cualquier salto de línea además de su función normal, y el “$” coincide con una cadena vacía antes de cualquier salto de línea además de su función normal.
TCL_REG_NOSUB
Compilar para coincidencias que solo reportan éxito o fracaso, no lo que coincidió. Esto reduce la sobrecarga de compilación y puede mejorar el rendimiento. Las llamadas posteriores a Tcl_RegExpGetInfo o Tcl_RegExpRange no reportarán información de coincidencia.
TCL_REG_CANMATCH
Compilar para coincidencias que reportan la posibilidad de completar una coincidencia parcial dada más texto (ver más abajo).

Solo se puede especificar uno de TCL_REG_EXTENDED, TCL_REG_ADVANCED, TCL_REG_BASIC y TCL_REG_QUOTE.

Tcl_RegExpExecObj ejecuta el compilador de patrones de expresiones regulares. Devuelve 1 si objPtr contiene un rango de caracteres que coinciden con regexp, 0 si no se encuentra ninguna coincidencia, y -1 si ocurre un error. En caso de error, Tcl_RegExpExecObj deja un mensaje de error en el resultado del intérprete. El valor nmatches indica al compilador cuántos subexpresiones son de interés. Si nmatches es 0, entonces no se graba información de coincidencia de subexpresiones, lo que puede permitir al compilador realizar varias optimizaciones. Si el valor es -1, entonces todas las subexpresiones del patrón se recuerdan. Si el valor es un entero positivo, entonces solo se recordará ese número de subexpresiones. La coincidencia comienza en el índice de carácter Unicode especificado por offset. A diferencia de Tcl_RegExpExec, el comportamiento de los anclajes no se ve afectado por el valor de offset. En su lugar, el comportamiento de los anclajes está controlado explícitamente por el argumento eflags, que es un OR a nivel de bits de cero o más de los siguientes flags:

TCL_REG_NOTBOL
El carácter inicial no se tratará como el principio de una línea o el principio de la cadena, por lo que “^” no coincidirá allí. Tenga en cuenta que este flag no tiene ningún efecto sobre cómo coincide “\A”.
TCL_REG_NOTEOL
El último carácter de la cadena no se tratará como el final de una línea o el final de la cadena, por lo que “$” no coincidirá allí. Tenga en cuenta que este flag no tiene ningún efecto sobre cómo coincide “\Z”.

Tcl_RegExpGetInfo recupera información sobre la última coincidencia realizada con una expresión regular regexp dada. El argumento infoPtr contiene un puntero a una estructura que se define de la siguiente manera:

typedef struct Tcl_RegExpInfo {
    int nsubs;
    Tcl_RegExpIndices *matches;
    long extendStart;
} Tcl_RegExpInfo;

El campo nsubs contiene un recuento del número de subexpresiones entre paréntesis dentro de la expresión regular. Si se usó TCL_REG_NOSUB, entonces este valor será cero. El campo matches apunta a un array de nsubs+1 valores que indican los límites de cada subexpresión que coincidió. El primer elemento del array se refiere al rango coincidente por toda la expresión regular, y los elementos subsiguientes se refieren a las subexpresiones entre paréntesis en el orden en que aparecen en el patrón. Cada elemento es una estructura que se define de la siguiente manera:

typedef struct Tcl_RegExpIndices {
    long start;
    long end;
} Tcl_RegExpIndices;

Los valores start y end son índices de caracteres Unicode relativos a la ubicación offset dentro de objPtr donde comenzó la coincidencia. El índice start identifica el primer carácter de la subexpresión que coincidió. El índice end identifica el primer carácter después de la subexpresión que coincidió. Si la subexpresión coincidió con la cadena vacía, entonces start y end serán iguales. Si la subexpresión no participó en la coincidencia, entonces start y end se establecerán a -1.

El campo extendStart en Tcl_RegExpInfo solo se establece si se utilizó el flag TCL_REG_CANMATCH. Indica el primer carácter de la cadena donde podría ocurrir una coincidencia. Si se encontró una coincidencia, este será el mismo que el principio de la coincidencia actual. Si no se encontró ninguna coincidencia, entonces indica el punto más temprano en el que podría ocurrir una coincidencia si se añaden más datos a la cadena. Si no es posible ninguna coincidencia incluso con texto adicional, este campo se establecerá a -1.
