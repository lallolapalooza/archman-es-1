ARGUMENTOS

Tcl_Interp *interp (in)
Intérprete al que se aplica el límite o cuyos límites se van a comprobar.
int type (in)
El tipo de límite al que se refiere la operación. Debe ser TCL_LIMIT_COMMANDS o TCL_LIMIT_TIME.
int commandLimit (in)
El número máximo de comandos (tal como se informa con info cmdcount) que pueden ejecutarse en el intérprete.
Tcl_Time *timeLimitPtr (in/out)
Un puntero a una estructura que recibirá el nuevo límite de tiempo (de Tcl_LimitSetTime) o el límite actual (de Tcl_LimitGetTime).
int granularity (in)
Divisor que indica con qué frecuencia se debe comprobar realmente un límite. Debe ser al menos 1.
Tcl_LimitHandlerProc *handlerProc (in)
Función a llamar cuando se exceda un límite. Si el handlerProc elimina o aumenta el límite durante su ejecución, el intérprete limitado podrá continuar procesando después de que el handler regrese. Se pueden asociar muchos handlers a un mismo límite de intérprete; el orden de ejecución no está definido y deben identificarse por handlerProc y clientData cuando se eliminen.
ClientData clientData (in)
Un puntero de tamaño arbitrario que se utiliza para pasar algún contexto a la función handlerProc.
Tcl_LimitHandlerDeleteProc *deleteProc (in)
Función a llamar cuando se elimina un handler. Puede ser NULL si el clientData no requiere eliminación.

DESCRIPCIÓN

El sistema de límites de tiempo de la biblioteca Tcl permite un control estricto sobre la cantidad de tiempo computacional que un script puede utilizar, y es útil en casos en los que un programa se divide en varias partes, algunas de las cuales son más confiables que otras (por ejemplo, servidores de aplicaciones web).

Cada intérprete puede tener un límite en el tiempo de ejecución y un límite en el número de comandos que puede ejecutar. Dado que la comprobación de estos límites puede ser potencialmente costosa (especialmente el límite de tiempo), cada límite también tiene una política de granularidad, que es un divisor para un conteo interno de los puntos en los que se puede realizar una comprobación (que se ejecuta inmediatamente antes de ejecutar un comando y con una frecuencia no especificada entre la ejecución de comandos, lo que puede ocurrir en bucles vacíos de while).

La parte final del motor de límites es un esquema de notificación que permite notificaciones cuando se ha excedido un límite. Estas notificaciones pueden simplemente proporcionar un registro o pueden asignar más recursos al intérprete para permitirle continuar procesando durante más tiempo.

Cuando se excede un límite (y se han ejecutado los callbacks; el orden de ejecución de los callbacks no está definido), el procesamiento en el intérprete limitado se detiene lanzando un error y estableciendo una bandera que evita que el comando catch en ese intérprete capture ese error. Es responsabilidad del contexto que inició el procesamiento en ese intérprete (generalmente el intérprete principal) manejar el error.

API DE COMPROBACIÓN DE LÍMITES

Para comprobar los límites de un intérprete, llame a Tcl_LimitCheck, que devuelve TCL_OK si el límite no se ha excedido (después de procesar los callbacks) y TCL_ERROR si el límite se ha excedido (en cuyo caso también se coloca un mensaje de error en el resultado del intérprete). Esta función solo debe llamarse cuando Tcl_LimitReady devuelve un valor distinto de cero, para que se aplique la política de granularidad. Esta API está diseñada para ser utilizada de forma similar a Tcl_AsyncReady y Tcl_AsyncInvoke.

Cuando escriba código que pueda comportarse como catch en cuanto a errores, solo debe capturar un error si Tcl_LimitExceeded devuelve cero. Si devuelve un valor distinto de cero, el intérprete está en un estado de límite excedido y los errores deben propagarse al contexto de llamada. También puede comprobar si un tipo particular de límite se ha excedido utilizando Tcl_LimitTypeExceeded.

CONFIGURACIÓN DE LÍMITES

Para comprobar si un límite está establecido (pero no si se ha excedido) en un intérprete, llame a Tcl_LimitTypeEnabled con el tipo de límite que desea comprobar. Para establecer un límite específico, llame a Tcl_LimitTypeSet, y para desactivar un límite, llame a Tcl_LimitTypeReset.

El nivel de un límite de comandos puede establecerse utilizando Tcl_LimitSetCommands y recuperarse utilizando Tcl_LimitGetCommands. De forma similar, el límite de tiempo puede establecerse utilizando Tcl_LimitSetTime y recuperarse utilizando Tcl_LimitGetTime, pero con esta API el límite de tiempo se copia desde y hacia la estructura Tcl_Time a la que apunta el argumento timeLimitPtr.

La granularidad del límite puede establecerse utilizando Tcl_LimitSetGranularity y recuperarse utilizando Tcl_LimitGetGranularity. Debe tener en cuenta que las granularidades siempre deben ser positivas.

CALLBACKS DE LÍMITES

Para añadir un callback de handler que se invocará cuando se exceda un límite, llame a Tcl_LimitAddHandler. El argumento handlerProc describe la función que se va a llamar; debe tener el siguiente prototipo:

typedef void Tcl_LimitHandlerProc(
        ClientData clientData,
        Tcl_Interp *interp);

El argumento clientData de la función handler se pasará como cualquier valor que se haya pasado al argumento clientData de Tcl_LimitAddHandler, y interp es el intérprete cuyo límite se ha excedido.

El argumento deleteProc de Tcl_LimitAddHandler es una función a llamar para eliminar el valor de clientData. Puede ser TCL_STATIC o NULL si no se necesita ninguna acción de eliminación, o TCL_DYNAMIC si solo se necesita liberar la estructura con Tcl_Free. De lo contrario, debe referirse a una función con el siguiente prototipo:

typedef void Tcl_LimitHandlerDeleteProc(
        ClientData clientData);

Un handler de límite puede eliminarse utilizando Tcl_LimitRemoveHandler; el handler eliminado será el primero que se encuentre (de los handlers añadidos con Tcl_LimitAddHandler) con exactamente los mismos argumentos type, handlerProc y clientData. Esta función siempre invoca el deleteProc en el clientData (a menos que el deleteProc sea NULL o TCL_STATIC).
