DESCRIPCIÓN

Un método es una operación que se realiza sobre un objeto y que está asociada a él. Cada método debe estar adjunto a un objeto o a una clase; los métodos adjuntos a una clase se asocian a todas las instancias (directas e indirectas) de esa clase.

Dado un método, la entidad que lo declaró se puede encontrar usando Tcl_MethodDeclarerClass, que devuelve la clase a la que está adjunto el método (o NULL si el método no está adjunto a ninguna clase), y Tcl_MethodDeclarerObject, que devuelve el objeto al que está adjunto el método (o NULL si el método no está adjunto a un objeto). El nombre del método se puede obtener con Tcl_MethodName y si el método está exportado se obtiene con Tcl_MethodIsPublic. El tipo del método también se puede introspeccionar hasta cierto punto; la función Tcl_MethodIsType devuelve si un método es de un tipo particular, asignando el clientData por método a la variable apuntada por clientDataPtr si (esa es distinta de NULL) si el tipo coincide.

CREACIÓN DE MÉTODOS

Los métodos se crean mediante Tcl_NewMethod y Tcl_NewInstanceMethod, que crean un método adjunto a una clase o a un objeto respectivamente. En ambos casos, el argumento nameObj indica el nombre del método a crear, el argumento isPublic indica si el método debe exportarse inicialmente, el argumento methodTypePtr describe la implementación del método (ver la sección TIPOS DE MÉTODOS a continuación) y el argumento clientData proporciona datos específicos de la implementación que se pasan a la implementación del método cuando se llama.

Cuando el argumento nameObj de Tcl_NewMethod es NULL, se crea un método sin nombre, que se utiliza para constructores y destructores. Los constructores deben instalarse en su clase utilizando la función Tcl_ClassSetConstructor, y los destructores (que no deben requerir ningún argumento) deben instalarse en su clase utilizando la función Tcl_ClassSetDestructor. Los métodos sin nombre no deben utilizarse para ningún otro propósito, y los métodos con nombre no deben utilizarse como constructores ni como destructores. Tenga en cuenta también que un methodTypePtr NULL se utiliza para proporcionar señalización interna y no debe utilizarse en código de cliente.

CONTEXTOS DE LLAMADA A MÉTODOS

Cuando se llama a un método, se pasa una referencia al contexto de llamada a método como uno de los argumentos a la función de implementación. Este contexto se puede inspeccionar para proporcionar información sobre el llamador, pero no debe conservarse más allá del momento en que finaliza la llamada al método.

El método que se está llamando se puede recuperar del contexto usando Tcl_ObjectContextMethod, y el objeto que provocó la invocación del método se puede recuperar con Tcl_ObjectContextObject. El número de argumentos que deben omitirse (por ejemplo, el nombre del objeto y el nombre del método en una llamada a método normal) se lee con Tcl_ObjectContextSkippedArgs, y el contexto también puede informar si está funcionando como un filtro para otro método a través de Tcl_ObjectContextIsFiltering.

Durante la ejecución de un método, la implementación del método puede optar por invocar las etapas de la cadena de llamadas a método que vienen después de la implementación del método actual. Esto (el núcleo del comando next) se hace usando Tcl_ObjectContextInvokeNext. Tenga en cuenta que esta función no manipula la pila de marcos de llamada, a diferencia del comando next; si la implementación del método ha insertado uno o más marcos adicionales en la pila como parte de su implementación, también es responsable de extraer temporalmente esos marcos de la pila mientras se ejecuta la función Tcl_ObjectContextInvokeNext. Tenga en cuenta también que el contexto de llamada a método *nunca* se elimina durante la ejecución de esta función.

TIPOS DE MÉTODOS

Los tipos de métodos se describen mediante un puntero a una estructura Tcl_MethodType, que se define como:

typedef struct {
    int version;
    const char *name;
    Tcl_MethodCallProc *callProc;
    Tcl_MethodDeleteProc *deleteProc;
    Tcl_CloneProc *cloneProc;
} Tcl_MethodType;

El campo version permite la expansión futura de la estructura y siempre debe declararse igual a TCL_OO_METHOD_VERSION_CURRENT. El campo name proporciona un nombre legible por humanos para el tipo y es el valor que se expone a través de los comandos Tcl info class methodtype e info object methodtype.

El campo callProc proporciona una función que se llama cuando se invoca el método; nunca debe ser NULL.

El campo deleteProc proporciona una función que se utiliza para eliminar un método particular y se llama cuando el método es reemplazado o eliminado; si el campo es NULL, se asume que el clientData del método no necesita ninguna acción especial para ser eliminado.

El campo cloneProc es una función que se utiliza para copiar el clientData de un método (como parte de Tcl_CopyObjectInstance) o NULL para indicar que el clientData se puede copiar directamente.

FIRMA DE FUNCIÓN DE TCL_METHODCALLPROC

typedef int (*Tcl_MethodCallProc)(ClientData clientData, Tcl_Interp *interp,
    int objc, Tcl_Obj *const objv[], Tcl_ObjectContext context);

La función callProc recibe los siguientes argumentos:

ClientData clientData
Los datos específicos de la implementación del método, tal como se proporcionaron a Tcl_NewMethod o Tcl_NewInstanceMethod.
Tcl_Interp *interp
El intérprete en el que se está ejecutando la llamada al método.
int objc
El número de argumentos para la llamada al método.
Tcl_Obj *const *objv
Una matriz de los argumentos para la llamada al método. El primer elemento de esta matriz es el objeto en el que se llamó al método, y el segundo es el nombre del método.
Tcl_ObjectContext context
El contexto de la llamada al método. Este contexto solo debe usarse dentro de la ejecución de esta función.

La función callProc debe devolver 0 si la llamada al método fue exitosa, o TCL_ERROR si la llamada al método falló.

FIRMA DE FUNCIÓN DE TCL_METHODDELETEPROC

typedef void (*Tcl_MethodDeleteProc)(ClientData clientData);

La función deleteProc recibe los siguientes argumentos:

ClientData clientData
Los datos específicos de la implementación del método, tal como se proporcionaron a Tcl_NewMethod o Tcl_NewInstanceMethod.

La función deleteProc se llama cuando se elimina o reemplaza un método, y es responsable de liberar cualquier recurso asociado con el método.

FIRMA DE FUNCIÓN DE TCL_CLONEPROC

typedef ClientData (*Tcl_CloneProc)(ClientData clientData);

La función cloneProc recibe los siguientes argumentos:

ClientData clientData
Los datos específicos de la implementación del método, tal como se proporcionaron a Tcl_NewMethod o Tcl_NewInstanceMethod.

La función cloneProc debe devolver una copia de los datos de cliente proporcionados, que se utilizará cuando el objeto o clase al que está asociado el método se copie.

NAME

Tcl_MethodIsPublic, Tcl_MethodIsPrivate, Tcl_MethodIsProtected, Tcl_MethodIsPackage, Tcl_MethodIsProtectedPackage, Tcl_MethodIsPrivatePackage — query object method visibility

SYNOPSIS

int
Tcl_MethodIsProtectedPackage(Tcl_Method *method);
int

ARGUMENTS

Tcl_Method *method

The method to query.

DESCRIPTION

These functions query the visibility of a method, which is determined at the time the method is created by the way it is defined within its class definition.

The visibility modifiers are:

  • Public: Methods that are public are visible and callable from any context.
  • Private: Methods that are private are only visible and callable from within the object or class where they are defined.
  • Protected: Methods that are protected are visible and callable from within the object or class where they are defined, and from within any subclasses.
  • Package: Methods that are package private are visible and callable from within the object or class where they are defined, and from within any other class that is defined within the same Tcl package.
  • Protected Package: Methods that are protected package private are visible and callable from within the object or class where they are defined, from within any subclasses, and from within any other class that is defined within the same Tcl package.
  • Private Package: Methods that are private package private are visible and callable only from within the object or class where they are defined, and from within any other class that is defined within the same Tcl package.

Each of these functions returns true (1) if the method has the specified visibility, and false (0) otherwise.

METHOD TYPES

The visibility of a method is determined by the way it is defined. A method defined using oo::define or oo::class will have its visibility determined by the visibility modifiers.

TCL_METHODCALLPROC FUNCTION SIGNATURE

Functions matching this signature are called when the method is invoked.

typedef int Tcl_MethodCallProc(
        ClientData clientData,
        Tcl_Interp *interp,
        Tcl_ObjectContext objectContext,
        int objc,
        Tcl_Obj *const *objv);

The clientData argument to a Tcl_MethodCallProc is the value that was given when the method was created, the interp is a place in which to execute scripts and access variables as well as being where to put the result of the method, and the objc and objv fields give the parameter objects to the method. The calling context of the method can be discovered through the objectContext argument, and the return value from a Tcl_MethodCallProc is any Tcl return code (e.g. TCL_OK, TCL_ERROR).

TCL_METHODDELETEPROC FUNCTION SIGNATURE

Functions matching this signature are used when a method is deleted, whether through a new method being created or because the object or class is deleted.

typedef void Tcl_MethodDeleteProc(
        ClientData clientData);

The clientData argument to a Tcl_MethodDeleteProc will be the same as the value passed to the clientData argument to Tcl_NewMethod or Tcl_NewInstanceMethod when the method was created.

TCL_CLONEPROC FUNCTION SIGNATURE

Functions matching this signature are used to copy a method when the object or class is copied using Tcl_CopyObjectInstance (or oo::copy).

typedef int Tcl_CloneProc(
        Tcl_Interp *interp,
        ClientData oldClientData,
        ClientData *newClientDataPtr);

The interp argument gives a place to write an error message when the attempt to clone the object is to fail, in which case the clone procedure must also return TCL_ERROR; it should return TCL_OK otherwise. The oldClientData field to a Tcl_CloneProc gives the value from the method being copied from, and the newClientDataPtr field will point to a variable in which to write the value for the method being copied to.
