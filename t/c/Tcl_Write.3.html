ARGUMENTOS

Tcl_Interp *interp (in)
Se utiliza para la notificación de errores y para buscar un canal registrado en él.
const char *fileName (in)
El nombre de un archivo local o de red.
const char *mode (in)
Especifica cómo se debe acceder al archivo. Puede tener cualquiera de los valores permitidos para el argumento mode del comando Tcl open.
int permissions (in)
Indicadores de permisos al estilo POSIX, como 0644. Si se crea un nuevo archivo, estos permisos se establecerán en el archivo creado.
int argc (in)
El número de elementos en argv.
const char **argv (in)
Argumentos para construir una tubería de comandos. Estos valores tienen el mismo significado que los argumentos que no son de conmutador para el comando Tcl exec.
int flags (in)
Especifica la disposición de los manejadores stdio en la tubería: combinación OR de TCL_STDIN, TCL_STDOUT, TCL_STDERR y TCL_ENFORCE_MODE. Si se establece TCL_STDIN, la entrada estándar del primer hijo en la tubería es el canal de tubería, de lo contrario es la misma que la entrada estándar del proceso invocador; lo mismo para TCL_STDOUT y TCL_STDERR. Si no se establece TCL_ENFORCE_MODE, la tubería puede redirigir los manejadores stdio para anular los manejadores stdio para los que se han establecido TCL_STDIN, TCL_STDOUT y TCL_STDERR. Si está establecido, dichas redirecciones causan un error.
ClientData handle (in)
Manejador específico del sistema operativo para E/S a un archivo. Para Unix es un descriptor de archivo, para Windows es un HANDLE.
int readOrWrite (in)
Combinación OR de TCL_READABLE y TCL_WRITABLE para indicar qué operaciones son válidas en handle.
const char *channelName (in)
El nombre del canal.

Punta a una variable entera que recibirá una combinación OR de TCL_READABLE y TCL_WRITABLE, que indica si el canal está abierto para lectura y escritura.
const char *pattern (in)
El patrón a emparejar, pasado a Tcl_StringMatch, o NULL.
Tcl_Channel channel (in)
Un canal Tcl para entrada o salida. Debe haber sido el valor de retorno de un procedimiento como Tcl_OpenFileChannel.
Tcl_Obj *readObjPtr (in/out)
Un puntero a un valor Tcl en el que se almacenarán los caracteres leídos del canal.
int charsToRead (in)
El número de caracteres a leer del canal. Si la codificación del canal es binary, esto es equivalente al número de bytes a leer del canal.
int appendFlag (in)
Si es distinto de cero, los datos leídos del canal se añadirán al valor. De lo contrario, los datos reemplazarán el contenido existente del valor.

Un búfer en el que se almacenarán los bytes leídos del canal.

El número de bytes a leer del canal. El búfer readBuf debe ser lo suficientemente grande como para contener esta cantidad de bytes.

Un puntero a un valor Tcl en el que se almacenará la línea leída del canal. La línea leída se añadirá al valor actual del valor.

Un puntero a una cadena dinámica Tcl en la que se almacenará la línea leída del canal. Debe haber sido inicializada por el llamador. La línea leída se añadirá a cualquier dato que ya esté en la cadena dinámica.

Longitud de la entrada

Indicador que indica si la entrada debe añadirse al final o al principio del búfer del canal.

Un búfer que contiene los caracteres a enviar al canal.
const char *byteBuf (in)
Un búfer que contiene los bytes a enviar al canal.

El número de bytes a consumir de charBuf o byteBuf y enviar al canal.

DESCRIPCIÓN

El mecanismo de canales de Tcl proporciona un mecanismo independiente de dispositivos y multiplataforma para realizar operaciones de entrada y salida con búfer en una variedad de tipos de archivos, sockets y dispositivos. El mecanismo de canales es extensible a nuevos tipos de canales, proporcionando un controlador de canal de bajo nivel para el nuevo tipo; la interfaz del controlador de canal se describe en la entrada del manual para Tcl_CreateChannel. El mecanismo de canales proporciona un esquema de búfer modelado después de la E/S estándar de Unix, y también permite E/S no bloqueantes en canales.

Los procedimientos descritos en esta entrada del manual comprenden las APIs de C de la capa genérica de la arquitectura de canales. Para una descripción de la arquitectura del controlador de canal y cómo implementar controladores de canal para nuevos tipos de canales, consulte la entrada del manual para Tcl_CreateChannel.

TCL_OPENFILECHANNEL

TCL_OPENFILECHANNEL

Tcl_OpenFileChannel abre un archivo especificado por fileName y devuelve un manejador de canal que se puede usar para realizar operaciones de entrada y salida en el archivo. Esta API está modelada a partir del procedimiento fopen de la biblioteca de E/S estándar de Unix. La sintaxis y el significado de todos los argumentos son similares a los dados en el comando Tcl open al abrir un archivo. Si ocurre un error al abrir el canal, Tcl_OpenFileChannel devuelve NULL y registra un código de error POSIX que se puede recuperar con Tcl_GetErrno. Además, si interp no es NULL, Tcl_OpenFileChannel deja un mensaje de error en el resultado de interp después de cualquier error. A partir de Tcl 8.4, se debe preferir la API basada en valores Tcl_FSOpenFileChannel sobre Tcl_OpenFileChannel siempre que sea posible.

El canal recién creado no se registra en el intérprete suministrado; para registrarlo, use Tcl_RegisterChannel, descrito a continuación. Si uno de los canales estándar, stdin, stdout o stderr se cerró previamente, el acto de crear el nuevo canal también lo asigna como reemplazo del canal estándar.

TCL_OPENCOMMANDCHANNEL

Tcl_OpenCommandChannel proporciona una interfaz de nivel C a las funciones de los comandos exec y open. Crea una secuencia de subprocesos especificados por los argumentos argv y argc y devuelve un canal que se puede usar para comunicarse con estos subprocesos. El argumento flags indica qué tipo de comunicación existirá con la tubería de comandos.

Si el indicador TCL_STDIN está activado, la entrada estándar del primer subproceso estará vinculada al canal: escribir en el canal proporcionará entrada al subproceso. Si TCL_STDIN no está activado, la entrada estándar del primer subproceso será la misma que la entrada estándar de esta aplicación. Si TCL_STDOUT está activado, la salida estándar del último subproceso se puede leer del canal; de lo contrario, va a la salida estándar de esta aplicación. Si TCL_STDERR está activado, la salida de error estándar de todos los subprocesos se devuelve al canal y resulta en un error al cerrar el canal; de lo contrario, va al error estándar de esta aplicación. Si TCL_ENFORCE_MODE no está activado, entonces argc y argv pueden redirigir los manejadores de E/S para anular TCL_STDIN, TCL_STDOUT y TCL_STDERR; si está activado, es un error que argc y argv anulen los canales de E/S para los cuales se han establecido TCL_STDIN, TCL_STDOUT y TCL_STDERR.

Si ocurre un error al abrir el canal, Tcl_OpenCommandChannel devuelve NULL y registra un código de error POSIX que se puede recuperar con Tcl_GetErrno. Además, Tcl_OpenCommandChannel deja un mensaje de error en el resultado del intérprete. interp no puede ser NULL.

El canal recién creado no se registra en el intérprete suministrado; para registrarlo, use Tcl_RegisterChannel, descrito a continuación. Si uno de los canales estándar, stdin, stdout o stderr se cerró previamente, el acto de crear el nuevo canal también lo asigna como reemplazo del canal estándar.

TCL_MAKEFILECHANNEL

Tcl_MakeFileChannel crea un Tcl_Channel a partir de un manejador de archivo existente y específico de la plataforma. El canal recién creado no se registra en el intérprete suministrado; para registrarlo, use Tcl_RegisterChannel, descrito a continuación. Si uno de los canales estándar, stdin, stdout o stderr se cerró previamente, el acto de crear el nuevo canal también lo asigna como reemplazo del canal estándar.

TCL_GETCHANNEL

Tcl_GetChannel devuelve un canal dado el channelName utilizado para crearlo con Tcl_CreateChannel y un puntero a un intérprete de Tcl en interp. Si no se registra un canal con ese nombre en ese intérprete, el procedimiento devuelve NULL. Si el argumento modePtr no es NULL, apunta a una variable entera que recibirá una combinación OR de TCL_READABLE y TCL_WRITABLE que describe si el canal está abierto para lectura y escritura.

Tcl_GetChannelNames y Tcl_GetChannelNamesEx escriben los nombres de los canales registrados en el resultado del intérprete como un valor de lista. Tcl_GetChannelNamesEx filtrará estos nombres de acuerdo con el pattern. Si pattern es NULL, no realizará ningún filtrado. El valor de retorno es TCL_OK si no ocurrieron errores al escribir en el resultado, de lo contrario es TCL_ERROR y el mensaje de error se deja en el resultado del intérprete.

TCL_REGISTERCHANNEL

Tcl_RegisterChannel agrega un canal al conjunto de canales accesibles en interp. Después de esta llamada, los programas Tcl que se ejecuten en ese intérprete podrán referirse al canal en operaciones de entrada o salida utilizando el nombre dado en la llamada a Tcl_CreateChannel. Después de esta llamada, el canal se convierte en propiedad del intérprete, y el llamador no debe llamar a Tcl_Close para el canal; el canal se cerrará automáticamente cuando se desregistre del intérprete.

El código que se ejecuta fuera de cualquier intérprete Tcl puede llamar a Tcl_RegisterChannel con interp como NULL, para indicar que desea mantener una referencia a este canal. Posteriormente, el canal puede ser registrado en un intérprete Tcl y solo se cerrará cuando el número correspondiente de llamadas a Tcl_UnregisterChannel se hayan realizado. Esto permite que el código que se ejecuta fuera de cualquier intérprete mantenga de forma segura una referencia a un canal que también está registrado en un intérprete Tcl.

Este procedimiento interactúa con el código que administra los canales estándar. Si no se inicializaron canales estándar antes de la primera llamada a Tcl_RegisterChannel, se inicializarán con esa llamada. Vea Tcl_StandardChannels para un tratado general sobre canales estándar y el comportamiento de la biblioteca Tcl con respecto a ellos.

TCL_UNREGISTERCHANNEL

Tcl_UnregisterChannel elimina un canal del conjunto de canales accesibles en interp. Después de esta llamada, los programas Tcl ya no podrán usar el nombre del canal para referirse al canal en ese intérprete. Si esta operación eliminó el último registro del canal en cualquier intérprete, el canal también se cierra y destruye.

El código no asociado con un intérprete Tcl puede llamar a Tcl_UnregisterChannel con interp como NULL, para indicar a Tcl que ya no tiene una referencia a ese canal. Si esta es la última referencia al canal, ahora se cerrará. Tcl_UnregisterChannel es muy similar a Tcl_DetachChannel excepto que también cerrará el canal si no existen más referencias a él.

TCL_DETACHCHANNEL

Tcl_DetachChannel elimina un canal del conjunto de canales accesibles en interp. Después de esta llamada, los programas Tcl ya no podrán usar el nombre del canal para referirse al canal en ese intérprete. Más allá de eso, este comando no tiene ningún otro efecto. No se puede usar en los canales estándar (stdout, stderr, stdin) y devolverá TCL_ERROR si se le pasa uno de esos canales.

El código no asociado con un intérprete Tcl puede llamar a Tcl_DetachChannel con interp como NULL, para indicar a Tcl que ya no tiene una referencia a ese canal. Si esta es la última referencia al canal, a diferencia de Tcl_UnregisterChannel, no se cerrará.

TCL_ISSTANDARDCHANNEL

Tcl_IsStandardChannel prueba si un canal es uno de los tres canales estándar, stdin, stdout o stderr. Si es así, devuelve 1, de lo contrario 0.

No se intenta comprobar si el canal dado o los canales estándar están inicializados o son válidos de otra manera.

TCL_CLOSE

Tcl_Close destruye el canal channel, que debe denotar un canal actualmente abierto. El canal no debe estar registrado en ningún intérprete cuando se llama a Tcl_Close. La salida en búfer se vaciará en el dispositivo de salida del canal antes de destruir el canal, y cualquier entrada en búfer se descartará. Si este es un canal de bloqueo, la llamada no regresa hasta que todos los datos en búfer se envíen exitosamente al dispositivo de salida del canal. Si este es un canal sin bloqueo y hay salida en búfer que no se puede escribir sin bloquear, la llamada regresa inmediatamente; la salida se vacía en segundo plano y el canal se cerrará una vez que se haya emitido todo el dato en búfer. En este caso, los errores durante el vaciado no se informan.

Si el canal se cerró con éxito, Tcl_Close devuelve TCL_OK. Si ocurre un error, Tcl_Close devuelve TCL_ERROR y registra un código de error POSIX que se puede recuperar con Tcl_GetErrno. Si el canal se está cerrando de forma síncrona y ocurre un error durante el cierre del canal y interp no es NULL, se deja un mensaje de error en el resultado del intérprete.

Nota: no es seguro llamar a Tcl_Close en un canal que se ha registrado usando Tcl_RegisterChannel; vea la documentación de Tcl_RegisterChannel, arriba, para más detalles. Si el canal se ha proporcionado alguna vez como el argumento chan en una llamada a Tcl_RegisterChannel, debe usar en su lugar Tcl_UnregisterChannel, que llamará internamente a Tcl_Close cuando todas las llamadas a Tcl_RegisterChannel hayan sido igualadas por llamadas correspondientes a Tcl_UnregisterChannel.

TCL_READCHARS Y TCL_READ

Tcl_ReadChars consume bytes del channel, convirtiendo los bytes a UTF-8 basándose en la codificación del canal y almacenando los datos producidos en la representación de cadena de readObjPtr. El valor de retorno de Tcl_ReadChars es el número de caracteres, hasta charsToRead, que se almacenaron en readObjPtr. Si ocurre un error al leer, el valor de retorno es -1 y Tcl_ReadChars registra un código de error POSIX que se puede recuperar con Tcl_GetErrno.

Establecer charsToRead

> a -1 provocará que el comando lea todos los caracteres actualmente disponibles (no bloqueante) o todo hasta el fin de archivo (modo bloqueante).

El valor de retorno puede ser menor que el valor a leer, lo que indica que había menos datos de los solicitados disponibles. Esto se llama una lectura corta. En modo bloqueante, esto solo puede ocurrir al final del archivo. En modo no bloqueante, una lectura corta también puede ocurrir si actualmente no hay suficiente entrada disponible: Tcl_ReadChars devuelve una cuenta corta en lugar de esperar más datos.

Si el canal está en modo bloqueante, un valor de retorno de cero indica una condición de fin de archivo. Si el canal está en modo no bloqueante, un valor de retorno de cero indica que actualmente no hay entrada disponible o una condición de fin de archivo. Utilice Tcl_Eof y Tcl_InputBlocked para determinar cuál de estas condiciones ocurrió realmente.

Tcl_ReadChars traduce las diversas representaciones de fin de línea a la representación interna canónica \n de acuerdo con el modo de reconocimiento de fin de línea actual. El reconocimiento de fin de línea y los diversos modos específicos de la plataforma se describen en la entrada del manual para el comando fconfigure de Tcl.

Como optimización de rendimiento, al leer de un canal con la codificación binary, los bytes no se convierten a UTF-8 al leerlos. En cambio, se almacenan en la representación interna de readObjPtr como un valor de matriz de bytes. La representación de cadena de este valor solo se construirá si es necesario (por ejemplo, debido a una llamada a Tcl_GetStringFromObj). De esta manera, los datos orientados a bytes se pueden leer de un canal, manipular llamando a Tcl_GetByteArrayFromObj y funciones relacionadas, y luego escribirlos en un canal sin el costo de convertirlos a o desde UTF-8.

Tcl_Read es similar a Tcl_ReadChars, excepto que no realiza conversiones de codificación, independientemente de la codificación del canal. Está obsoleto y existe por compatibilidad retroactiva con extensiones de Tcl no internacionalizadas. Consume bytes de channel y los almacena en readBuf, realizando traducciones de fin de línea en el camino. El valor de retorno de Tcl_Read es el número de bytes, hasta bytesToRead, escritos en readBuf. El búfer producido por Tcl_Read no termina en nulo. Su contenido es válido desde la posición cero hasta, pero sin incluir, la posición indicada por el valor de retorno.

Tcl_ReadRaw es lo mismo que Tcl_Read pero no compensa el apilamiento. Mientras que Tcl_Read (y las otras funciones de la API) siempre obtienen sus datos del canal superior en la pila de la que forma parte el canal proporcionado, Tcl_ReadRaw no lo hace. Por lo tanto, esta función solo es usable para controladores de canal transformacionales, es decir, controladores utilizados en el medio de una pila de canales, para mover datos del canal inferior a la transformación.

TCL_GETSOBJ Y TCL_GETS

Tcl_GetsObj consume bytes del channel, convirtiendo los bytes a UTF-8 basándose en la codificación del canal, hasta que se haya visto una línea completa de entrada. Si la codificación del canal es binary, cada byte leído del canal se trata como un carácter Unicode individual. Todos los caracteres de la línea, excepto los caracteres de fin de línea terminantes, se agregan a la representación de cadena de lineObjPtr. Los caracteres de fin de línea se leen y descartan.

Si se leyó una línea correctamente, el valor de retorno es mayor o igual a cero e indica el número de bytes almacenados en lineObjPtr. Si ocurre un error, Tcl_GetsObj devuelve -1 y registra un código de error POSIX que se puede recuperar con Tcl_GetErrno. Tcl_GetsObj también devuelve -1 si se alcanza el final del archivo; el procedimiento Tcl_Eof se puede usar para distinguir un error de una condición de fin de archivo.

Si el canal está en modo no bloqueante, el valor de retorno también puede ser -1 si no había datos disponibles o si los datos disponibles no contenían un carácter de fin de línea. Cuando se devuelve -1, el procedimiento Tcl_InputBlocked puede invocarse para determinar si el canal está bloqueado debido a la falta de entrada.

Tcl_Gets es lo mismo que Tcl_GetsObj, excepto que los caracteres resultantes se agregan a la cadena dinámica dada por lineRead en lugar de un valor de Tcl.

TCL_UNGETS

Tcl_Ungets se utiliza para agregar datos a la cola de entrada de un canal, al principio o al final de la cola. El puntero input apunta a los datos que se van a agregar. La longitud de la entrada a agregar se da por inputLen. Un valor distinto de cero de addAtEnd indica que los datos se agregarán al final de la cola; de lo contrario, se agregarán al principio de la cola. Si channel tiene un EOF "pegajoso" establecido, no se agregarán datos a la cola de entrada. Tcl_Ungets devuelve inputLen o -1 si ocurre un error.

TCL_WRITECHARS, TCL_WRITEOBJ, Y TCL_WRITE

Tcl_WriteChars acepta bytesToWrite bytes de datos de caracteres en charBuf. Los caracteres UTF-8 en el búfer se convierten a la codificación del canal y se ponen en cola para su salida al channel. Si bytesToWrite es negativo, Tcl_WriteChars espera que charBuf termine en nulo y saca todo hasta el nulo.

Los datos puestos en cola para la salida pueden no aparecer en el dispositivo de salida inmediatamente, debido al almacenamiento en búfer interno. Si los datos deben aparecer inmediatamente, llame a Tcl_Flush después de la llamada a Tcl_WriteChars, o establezca la opción -buffering en el canal a none. Si desea que los datos aparezcan tan pronto como se acepte una línea completa para la salida, establezca la opción -buffering en el canal en modo line.

El valor de retorno de Tcl_WriteChars es un recuento de cuántos bytes se aceptaron para la salida al canal. Es mayor que cero para indicar éxito o -1 para indicar que ocurrió un error. Si ocurre un error, Tcl_WriteChars registra un código de error POSIX que puede recuperarse con Tcl_GetErrno.

Los caracteres de nueva línea en los datos de salida se traducen a secuencias de fin de línea específicas de la plataforma de acuerdo con la opción -translation para el canal. Esto se hace incluso si el canal no tiene codificación.

Tcl_WriteObj es similar a Tcl_WriteChars, excepto que acepta un valor de Tcl cuyos contenidos se enviarán al canal. Los caracteres UTF-8 en la representación de cadena de writeObjPtr se convierten a la codificación del canal y se ponen en cola para su salida al channel. Como optimización de rendimiento, al escribir en un canal con la codificación binary, los caracteres UTF-8 no se convierten al escribirlos. En cambio, los bytes en la representación interna de writeObjPtr como un valor de matriz de bytes se escriben en el canal. La representación de matriz de bytes del valor se construirá si es necesaria. De esta manera, los datos orientados a bytes se pueden leer de un canal, manipular llamando a Tcl_GetByteArrayFromObj y funciones relacionadas, y luego escribirlos en un canal sin el costo de convertirlos a o desde UTF-8.

Tcl_Write es similar a Tcl_WriteChars, excepto que no realiza conversiones de codificación, independientemente de la codificación del canal. Está obsoleto y existe por compatibilidad retroactiva con extensiones de Tcl no internacionalizadas. Acepta bytesToWrite bytes de datos en byteBuf y los pone en cola para su salida al channel. Si bytesToWrite es negativo, Tcl_Write espera que byteBuf termine en nulo y saca todo hasta el nulo.

Tcl_WriteRaw es lo mismo que Tcl_Write pero no compensa el apilamiento. Mientras que Tcl_Write (y las otras funciones de la API) siempre alimentan su entrada al canal superior en la pila de la que forma parte el canal proporcionado, Tcl_WriteRaw no lo hace. Por lo tanto, esta función solo es usable para controladores de canal transformacionales, es decir, controladores utilizados en el medio de una pila de canales, para mover datos de la transformación al canal inferior.

TCL_FLUSH

Tcl_Flush hace que todos los datos de salida en búfer para channel se escriban en su archivo o dispositivo subyacente lo más rápido posible. Si el canal está en modo bloqueante, la llamada no regresa hasta que todos los datos en búfer se hayan enviado al canal o haya ocurrido algún error. La llamada regresa inmediatamente si el canal no está bloqueante; inicia una operación de vaciado en segundo plano que escribirá los datos en búfer al canal eventualmente, tan rápido como el canal pueda absorberlos.

El valor de retorno es normalmente TCL_OK. Si ocurre un error, Tcl_Flush devuelve TCL_ERROR y registra un código de error POSIX que se puede recuperar con Tcl_GetErrno.

TCL_SEEK

Tcl_Seek mueve el punto de acceso en channel donde se leerán o escribirán datos posteriores. La salida en búfer se vacía al canal y la entrada en búfer se descarta, antes de la operación de búsqueda. La llamada a Tcl_Seek con un valor de offset de 0, TCL_SEEK_SET y un valor de seekMode de 0 causa que se ignoren los datos pendientes de lectura.

Tcl_Seek normalmente devuelve el nuevo punto de acceso. Si ocurre un error, Tcl_Seek devuelve -1 y registra un código de error POSIX que se puede recuperar con Tcl_GetErrno. Después de un error, el punto de acceso puede o no haberse movido.

TCL_TELL

Tcl_Tell devuelve el punto de acceso actual para un canal. El valor devuelto es -1 si el canal no admite la búsqueda.

TCL_TRUNCATECHANNEL

Tcl_TruncateChannel trunca el archivo subyacente de channel a una length de bytes dada. Devuelve TCL_OK si la operación tuvo éxito y TCL_ERROR en caso contrario.

TCL_GETCHANNELOPTION

Tcl_GetChannelOption recupera, en optionValue, el valor de una de las opciones actualmente en vigor para un canal, o una lista de todas las opciones y sus valores. El argumento channel identifica el canal para el que se va a consultar una opción o recuperar todas las opciones y sus valores. Si optionName no es NULL, es el nombre de la opción a consultar; el valor de la opción se copia a la cadena dinámica de Tcl denotada por optionValue. Si optionName es NULL, la función almacena una lista alternada de nombres de opciones y sus valores en optionValue, utili

Una llamada a Tcl_DStringAppendElement. Las diversas opciones preexistentes y sus posibles valores se describen en la entrada del manual para el comando fconfigure de Tcl. Se pueden añadir otras opciones por cada tipo de canal. Estas opciones específicas del tipo de canal se describen en la entrada del manual para el comando Tcl que crea un canal de ese tipo; por ejemplo, las opciones adicionales para canales basados en TCP se describen en la entrada del manual para el comando socket de Tcl. El procedimiento normalmente devuelve TCL_OK. Si ocurre un error, devuelve TCL_ERROR y llama a Tcl_SetErrno para almacenar un código de error POSIX apropiado.

TCL_SETCHANNELOPTION

Tcl_SetChannelOption establece un nuevo valor newValue para una opción optionName en channel. El procedimiento normalmente devuelve TCL_OK. Si ocurre un error, devuelve TCL_ERROR; además, si interp no es NULL, Tcl_SetChannelOption deja un mensaje de error en el resultado del intérprete.

TCL_EOF

Tcl_Eof devuelve un valor distinto de cero si channel encontró un fin de archivo durante la última operación de entrada.

TCL_INPUTBLOCKED

Tcl_InputBlocked devuelve un valor distinto de cero si channel está en modo no bloqueante y la última operación de entrada devolvió menos datos de los solicitados porque había datos insuficientes disponibles. La llamada siempre devuelve cero si el canal está en modo bloqueante.

TCL_INPUTBUFFERED

Tcl_InputBuffered devuelve el número de bytes de entrada actualmente en búfer en los búferes internos de un canal. Si el canal no está abierto para lectura, esta función siempre devuelve cero.

TCL_OUTPUTBUFFERED

Tcl_OutputBuffered devuelve el número de bytes de salida actualmente en búfer en los búferes internos de un canal. Si el canal no está abierto para escritura, esta función siempre devuelve cero.

PLATFORM ISSUES

Los manejadores devueltos por Tcl_GetChannelHandle dependen de la plataforma y del tipo de canal. En plataformas Unix, el manejador es siempre un descriptor de archivo Unix, tal como lo devuelve la llamada al sistema open. En plataformas Windows, el manejador es un HANDLE de archivo cuando el canal se creó con Tcl_OpenFileChannel, Tcl_OpenCommandChannel o Tcl_MakeFileChannel. Otros tipos de canal pueden devolver un tipo diferente de manejador en plataformas Windows.
