ARGUMENTOS

Tcl_Interp *interp (entrada)
Intérprete Tcl a utilizar para la notificación de errores. El intérprete puede ser NULL si no se desea notificación de errores.
Tcl_Obj *textObj (entrada/salida)
Se refiere al valor del cual obtener el texto a buscar. La representación interna del valor puede ser convertida a una forma que pueda ser buscada eficientemente.
Tcl_Obj *patObj (entrada/salida)
Se refiere al valor del cual obtener una expresión regular. La expresión regular compilada se almacena en caché en el valor.
const char *text (entrada)
Texto en el cual buscar una coincidencia con una expresión regular.
const char *pattern (entrada)
Cadena de texto con el formato de un patrón de expresión regular.
Tcl_RegExp regexp (entrada)
Expresión regular compilada. Debe haber sido devuelta previamente por Tcl_GetRegExpFromObj o Tcl_RegExpCompile.
const char *start (entrada)
Si text es solo una porción de alguna otra cadena, este argumento identifica el inicio de la cadena más grande. Si no es lo mismo que text, entonces no se permitirán coincidencias de “^”.
int index (entrada)
Especifica qué rango se desea: 0 significa el rango de la coincidencia completa, 1 o mayor significa el rango que coincidió con una subexpresión entre paréntesis.
const char **startPtr (salida)
La dirección del primer carácter en el rango se almacena aquí, o NULL si no existe tal rango.
const char **endPtr (salida)
La dirección del carácter justo después del último en el rango se almacena aquí, o NULL si no existe tal rango.
int cflags (entrada)
Combinación OR de las banderas de compilación TCL_REG_ADVANCED, TCL_REG_EXTENDED, TCL_REG_BASIC, TCL_REG_EXPANDED, TCL_REG_QUOTE, TCL_REG_NOCASE, TCL_REG_NEWLINE, TCL_REG_NLSTOP, TCL_REG_NLANCH, TCL_REG_NOSUB, y TCL_REG_CANMATCH. Ver más abajo para más información.
int offset (entrada)
El desplazamiento de caracteres dentro del texto donde debe comenzar la coincidencia. El valor del desplazamiento no tiene impacto en las coincidencias de ^. Este comportamiento está controlado por eflags.
int nmatches (entrada)
El número de subexpresiones coincidentes que deben ser recordadas para uso posterior. Si este valor es 0, entonces no se calculará ninguna información de coincidencia de subexpresiones. Si el valor es -1, entonces se recordarán todas las subexpresiones coincidentes. Cualquier otro valor se tomará como el número máximo de subexpresiones a recordar.
int eflags (entrada)
Combinación OR de las banderas de ejecución TCL_REG_NOTBOL y TCL_REG_NOTEOL. Ver más abajo para más información.
Tcl_RegExpInfo *infoPtr (salida)
La dirección de la ubicación donde la información sobre una coincidencia previa debe ser almacenada por Tcl_RegExpGetInfo.

DESCRIPCIÓN

Tcl_RegExpMatch determina si su argumento pattern coincide con regexp, donde regexp se interpreta como una expresión regular utilizando las reglas de la página de referencia re_syntax. Si hay una coincidencia, Tcl_RegExpMatch devuelve 1. Si no hay coincidencia, Tcl_RegExpMatch devuelve 0. Si ocurre un error en el proceso de coincidencia (por ejemplo, pattern no es una expresión regular válida), entonces Tcl_RegExpMatch devuelve -1 y deja un mensaje de error en el resultado del intérprete. Tcl_RegExpMatchObj es similar a Tcl_RegExpMatch excepto que opera en los valores Tcl textObj y patObj en lugar de cadenas UTF. Tcl_RegExpMatchObj es generalmente más eficiente que Tcl_RegExpMatch, por lo que es la interfaz preferida.

Tcl_RegExpCompile, Tcl_RegExpExec y Tcl_RegExpRange proporcionan acceso de bajo nivel al motor de expresiones regulares. Tcl_RegExpCompile compila una cadena de expresión regular a la forma interna utilizada para una coincidencia de patrones eficiente. El valor de retorno es un token para esta forma compilada, que puede ser utilizado en llamadas posteriores a Tcl_RegExpExec o Tcl_RegExpRange. Si ocurre un error al compilar la expresión regular, Tcl_RegExpCompile devuelve NULL y deja un mensaje de error en el resultado del intérprete. Nota: el valor de retorno de Tcl_RegExpCompile solo es válido hasta la siguiente llamada a Tcl_RegExpCompile; no es seguro retener estos valores durante largos períodos de tiempo.

Tcl_RegExpExec ejecuta el motor de patrones de expresiones regulares. Devuelve 1 si text contiene un rango de caracteres que coincide con regexp, 0 si no se encuentra ninguna coincidencia y -1 si ocurre un error. En caso de error, Tcl_RegExpExec deja un mensaje de error en el resultado del intérprete. Al buscar en una cadena múltiples coincidencias de un patrón, es importante distinguir entre el inicio de la cadena original y el inicio de la búsqueda actual. Por ejemplo, al buscar la segunda ocurrencia de una coincidencia, el argumento text podría apuntar al carácter justo después de la primera coincidencia; sin embargo, es importante que el motor de patrones sepa que este no es el inicio de toda la cadena, para que no permita que los átomos “^” en el patrón coincidan. El argumento start proporciona esta información apuntando al inicio de la cadena general que contiene text. Start será menor o igual que text; si es menor que text, entonces no se permitirán coincidencias ^.

Tcl_RegExpRange puede ser invocado después de que Tcl_RegExpExec devuelva un valor; proporciona información detallada sobre qué rangos de la cadena coincidieron con qué partes del patrón. Tcl_RegExpRange devuelve un par de punteros en *startPtr y *endPtr que identifican un rango de caracteres en la cadena fuente para la llamada más reciente a Tcl_RegExpExec. Index indica cuál de varios rangos se desea: si index es 0, se devuelve información sobre el rango general de caracteres que coincidió con el patrón completo; de lo contrario, se devuelve información sobre el rango de caracteres que coincidió con la subexpresión entre paréntesis index-ésima dentro del patrón. Si no existe un rango correspondiente a index, se almacena NULL en *startPtr y *endPtr.

Tcl_GetRegExpFromObj, Tcl_RegExpExecObj y Tcl_RegExpGetInfo son interfaces de valores que proporcionan el control más directo de la biblioteca de expresiones regulares de Henry Spencer. Para los usuarios que necesiten modificar directamente las opciones de compilación y ejecución, se recomienda que utilicen estas interfaces en lugar de llamar a las funciones internas de expresiones regulares. Estas interfaces manejan los detalles de las traducciones de UTF a Unicode, además de proporcionar un rendimiento mejorado a través del almacenamiento en caché en los valores del patrón y la cadena.

Tcl_GetRegExpFromObj intenta devolver una expresión regular compilada desde patObj. Si el valor no contiene ya una expresión regular compilada, intentará crear una a partir de la cadena en el valor y asignarla a la representación interna de patObj. El valor de retorno de esta función es de tipo Tcl_RegExp. El valor de retorno es un token para esta forma compilada, que puede ser utilizado en llamadas posteriores a Tcl_RegExpExecObj o Tcl_RegExpGetInfo. Si ocurre un error al compilar la expresión regular, Tcl_GetRegExpFromObj devuelve NULL y deja un mensaje de error en el resultado del intérprete. El token de la expresión regular puede ser utilizado siempre que la representación interna de patObj se refiera a la forma compilada. El argumento cflags es una combinación a nivel de bits de cero o más de las siguientes banderas que controlan la compilación de patObj:

TCL_REG_ADVANCED
Permite la sintaxis avanzada de expresiones regulares. Sin esta bandera, solo se permite la sintaxis de expresiones regulares básicas.
TCL_REG_BASIC
Permite la sintaxis de expresiones regulares básicas. Este es el modo por defecto.
TCL_REG_EXTENDED
Permite la sintaxis de expresiones regulares extendidas. Este es un conjunto de sintaxis más rico que el de expresiones regulares básicas (y más cercano a perl, aunque no idéntico). Este es el modo por defecto.
TCL_REG_EXPANDED
Permite expresiones regulares con espacios en blanco y comentarios. Los espacios en blanco se ignoran y los caracteres # seguidos de una nueva línea se ignoran. La bandera TCL_REG_NEWLINE puede ser utilizada para permitir que el carácter ^ coincida al principio de la cadena y el carácter $ coincida al final de la cadena.
TCL_REG_QUOTE
Todos los caracteres en el patrón se tratan como literales, excepto los caracteres \. Se trata como una forma de escapar todos los metacaracteres. Esto es útil para hacer coincidir una cadena que puede contener metacaracteres de expresiones regulares.
TCL_REG_NOCASE
Realiza comparaciones sin distinguir entre mayúsculas y minúsculas. La bandera TCL_REG_NEWLINE también se ve afectada por esta bandera: si está activa, las coincidencias sin distinción entre mayúsculas y minúsculas no distinguen entre \n y \N.
TCL_REG_NEWLINE
Permite que el carácter “^” coincida al principio de la cadena y el carácter “$” al final de la cadena. Por defecto, “^” coincide al principio de la cadena y “$” coincide al final de la cadena o inmediatamente antes de una nueva línea al final de la cadena. Esta bandera hace que “^” coincida justo después de cualquier carácter de nueva línea en la cadena, y “$” coincida justo antes de cualquier carácter de nueva línea en la cadena.
TCL_REG_NLSTOP
Si esta bandera está activa, el carácter “.” no coincidirá con un carácter de nueva línea. Por defecto, “.” coincide con cualquier carácter, incluidas las nuevas líneas.
TCL_REG_NLANCH
Si esta bandera está activa, los anclajes “^” y “$” coincidirán en los inicios y finales de las líneas dentro de la cadena, respectivamente. “^” coincide justo después de un carácter de nueva línea, y “$” coincide justo antes de un carácter de nueva línea. Esta bandera está desactivada por defecto.
TCL_REG_NOSUB
Si esta bandera está activa, no se realizará ninguna información de subexpresión. Esto puede acelerar la coincidencia si no se necesitan información de subexpresión.
TCL_REG_CANMATCH
Si esta bandera está activa, la llamada a Tcl_RegExpExecObj o Tcl_RegExpExec devolverá 1 si la expresión regular puede coincidir en alguna parte de la cadena, incluso si no coincide con la cadena completa. Por defecto, la función devolverá 1 solo si el patrón coincide con la cadena completa.

Tcl_RegExpExecObj ejecuta una expresión regular compilada contra el texto proporcionado. El argumento regexp debe ser un token devuelto por Tcl_GetRegExpFromObj. El argumento textObj es el valor de Tcl que contiene el texto que se va a buscar. El argumento offset especifica el desplazamiento de caracteres dentro de textObj donde debe comenzar la búsqueda. El argumento nmatches especifica cuántas subexpresiones coincidentes deben recordarse para uso posterior. Si es 0, no se guarda información de subexpresión. Si es -1, se recuerdan todas las subexpresiones coincidentes. Cualquier otro valor especifica el número máximo de subexpresiones a recordar. El argumento eflags es una combinación a nivel de bits de cero o más de las siguientes banderas que controlan la ejecución de la coincidencia:

TCL_REG_NOTBOL
Si esta bandera está activa, el ancla “^” no coincidirá con el inicio de la cadena (o inmediatamente después de una nueva línea, si se usa la bandera TCL_REG_NEWLINE). Por defecto, “^” coincide con el inicio de la cadena.
TCL_REG_NOTEOL
Si esta bandera está activa, el ancla “$” no coincidirá con el final de la cadena (o inmediatamente antes de una nueva línea, si se usa la bandera TCL_REG_NEWLINE). Por defecto, “$” coincide con el final de la cadena.

Tcl_RegExpExecObj devuelve 1 si se encuentra una coincidencia, 0 si no se encuentra ninguna coincidencia y -1 si ocurre un error. Si se encuentra una coincidencia y nmatches es mayor que 0, la información sobre las subexpresiones coincidentes se almacena en la caché de resultados del intérprete. La información se organiza como una lista de listas. Cada sublista representa una subexpresión coincidente y contiene dos elementos: el índice de la subexpresión y la subcadena que coincidió.

Tcl_RegExpGetInfo recupera información sobre la coincidencia más reciente realizada por Tcl_RegExpExecObj o Tcl_RegExpExec. La información se almacena en la estructura a la que apunta infoPtr. La estructura Tcl_RegExpInfo tiene los siguientes campos:

int nreg
El número de subexpresiones coincidentes (incluida la coincidencia completa).
const char *str
Un puntero a la cadena de entrada sobre la que se realizó la coincidencia.
const char **வுகளில்
Una matriz de punteros a caracteres. El elemento en el índice 0 apunta al inicio de la coincidencia completa. El elemento en el índice i apunta al inicio de la i-ésima subexpresión coincidente (para i > 0). Si una subexpresión no coincidió, el puntero asociado será NULL.
const char **endt
Una matriz de punteros a caracteres. El elemento en el índice 0 apunta al carácter inmediatamente posterior al final de la coincidencia completa. El elemento en el índice i apunta al carácter inmediatamente posterior al final de la i-ésima subexpresión coincidente (para i > 0). Si una subexpresión no coincidió, el puntero asociado será NULL.

ARGUMENTOS

``interp''
Intérprete de Tcl a usar para generar errores.
``pattern''
Cadena que contiene el patrón de expresión regular.
``len''
Longitud del patrón en bytes.
``numChars''
Número de caracteres Unicode en el patrón. Si es negativo, se calculará a partir de len.
``flags''
Indicadores de compilación de expresiones regulares (ver abajo).
``error''
Puntero a un Tcl_RegExp para almacenar el resultado de la compilación. Este valor puede ser utilizado posteriormente por las funciones de ejecución. Si ocurre un error durante la compilación, este valor se establecerá en NULL.
``regexp''
Un valor Tcl_RegExp compilado previamente.
``string''
Cadena en la que realizar la coincidencia. Si es NULL, se usará la cadena del objeto objPtr. numChars debe ser el número de caracteres Unicode si string no es NULL. Si es -1, se calculará a partir de la longitud de la cadena.
``start''
Índice del primer carácter en string donde comenzar la búsqueda de coincidencias. Si el valor es negativo, se tratará como un desplazamiento desde el final de la cadena.
``nmatches''
Número de subexpresiones para las que se debe conservar la información de coincidencia. Si es 0, no se almacena información de coincidencia. Si es -1, se almacena información para todas las subexpresiones. Si es un entero positivo, se almacena información solo para esa cantidad de subexpresiones.

DESCRIPCIÓN

Las funciones Tcl_RegExpCompile y las funciones de ejecución correlacionadas proporcionan la funcionalidad de expresiones regulares de Tcl a través de una API C. Las funciones Tcl_RegExpMacroCompile y Tcl_RegExpMacroMatch son equivalentes a Tcl_RegExpCompile y Tcl_RegExpExec, respectivamente, pero devuelven un valor Tcl_RegExp en lugar de un puntero opaco. Esto permite que los patrones de expresiones regulares se almacenen como objetos Tcl.

La función Tcl_RegExpCompile compila el patrón de expresión regular especificado por pattern y len en un formato interno que puede ser utilizado para la ejecución. La compilación se realiza de acuerdo con el modo especificado por flags. Si la compilación tiene éxito, el valor resultante se almacena en el búfer apuntado por error y la función devuelve TCL_OK. Si ocurre un error durante la compilación, se deja un mensaje de error en el resultado del intérprete, el valor en *error se establece en NULL y la función devuelve TCL_ERROR.

Los siguientes son los indicadores de compilación que se pueden proporcionar en el argumento flags:

TCL_REG_ADVANCED
Compilar expresiones regulares avanzadas (AREs). Este modo corresponde a la sintaxis normal de expresiones regulares aceptada por los comandos regexp y regsub de Tcl.
TCL_REG_EXTENDED
Compilar expresiones regulares extendidas (EREs). Este modo corresponde a la sintaxis de expresiones regulares reconocida por Tcl 8.0 y versiones anteriores.
TCL_REG_BASIC
Compilar expresiones regulares básicas (BREs). Este modo corresponde a la sintaxis de expresiones regulares reconocida por utilidades comunes de Unix como sed y grep. Este es el valor predeterminado si no se especifican indicadores.
TCL_REG_EXPANDED
Compilar la expresión regular (básica, extendida o avanzada) utilizando una sintaxis expandida que permite comentarios y espacios en blanco. Este modo hace que los espacios en blanco no escapados y no de expresiones de corchetes, y los comentarios de # a fin de línea se ignoren.
TCL_REG_QUOTE
Compilar una cadena literal, con todos los caracteres tratados como caracteres ordinarios.
TCL_REG_NOCASE
Compilar para coincidencias que ignoran las distinciones entre mayúsculas y minúsculas.
TCL_REG_NEWLINE
Compilar para coincidencias sensibles a saltos de línea. Por defecto, el salto de línea es un carácter completamente ordinario sin significado especial ni en expresiones regulares ni en cadenas. Con este indicador, las expresiones de corchetes ([^...]) y el carácter de punto (.) nunca coinciden con un salto de línea, '^' coincide con una cadena vacía después de cualquier salto de línea además de su función normal, y '$' coincide con una cadena vacía antes de cualquier salto de línea además de su función normal. REG_NEWLINE es el OR a nivel de bits de REG_NLSTOP y REG_NLANCH.
TCL_REG_NLSTOP
Compilar para coincidencias parciales sensibles a saltos de línea, con el comportamiento de las expresiones de corchetes ([^...]) y el carácter de punto (.) afectado, pero no el comportamiento de '^' y '$'. En este modo, las expresiones de corchetes ([^...]) y el carácter de punto (.) nunca coinciden con un salto de línea.
TCL_REG_NLANCH
Compilar para coincidencias parciales inversas sensibles a saltos de línea, con el comportamiento de '^' y '$' (las "anclas") afectado, pero no el comportamiento de las expresiones de corchetes ([^...]) y el carácter de punto (.). En este modo, '^' coincide con una cadena vacía después de cualquier salto de línea además de su función normal, y '$' coincide con una cadena vacía antes de cualquier salto de línea además de su función normal.
TCL_REG_NOSUB
Compilar para coincidencias que solo informan éxito o fracaso, no lo que coincidió. Esto reduce la sobrecarga de compilación y puede mejorar el rendimiento. Las llamadas posteriores a Tcl_RegExpGetInfo o Tcl_RegExpRange no informarán ninguna información de coincidencia.
TCL_REG_CANMATCH
Compilar para coincidencias que informan la posibilidad de completar una coincidencia parcial dados más texto (ver abajo).

Solo uno de TCL_REG_EXTENDED, TCL_REG_ADVANCED, TCL_REG_BASIC y TCL_REG_QUOTE puede ser especificado.

Tcl_RegExpExecObj ejecuta el compilador de patrones de expresión regular. Devuelve 1 si objPtr contiene un rango de caracteres que coinciden con regexp, 0 si no se encuentra ninguna coincidencia y -1 si ocurre un error. En caso de error, Tcl_RegExpExecObj deja un mensaje de error en el resultado del intérprete. El valor nmatches indica al compilador cuántas subexpresiones son de interés. Si nmatches es 0, entonces no se registra ninguna información de coincidencia de subexpresión, lo que puede permitir al compilador realizar varias optimizaciones. Si el valor es -1, entonces se recuerdan todas las subexpresiones del patrón. Si el valor es un entero positivo, entonces solo se recordará esa cantidad de subexpresiones. La coincidencia comienza en el índice de carácter Unicode especificado por offset. A diferencia de Tcl_RegExpExec, el comportamiento de las anclas no se ve afectado por el valor de desplazamiento. En cambio, el comportamiento de las anclas está controlado explícitamente por el argumento eflags, que es un OR a nivel de bits de cero o más de los siguientes indicadores:

TCL_REG_NOTBOL
El carácter de inicio no se tratará como el principio de una línea o el principio de la cadena, por lo que '^' no coincidirá allí. Tenga en cuenta que este indicador no tiene ningún efecto sobre cómo coincide '\A'.
TCL_REG_NOTEOL
El último carácter de la cadena no se tratará como el final de una línea o el final de la cadena, por lo que '$' no coincidirá allí. Tenga en cuenta que este indicador no tiene ningún efecto sobre cómo coincide '\Z'.

Tcl_RegExpGetInfo recupera información sobre la última coincidencia realizada con una expresión regular dada regexp. El argumento infoPtr contiene un puntero a una estructura que se define de la siguiente manera:

typedef struct Tcl_RegExpInfo {
    int nsubs;
    Tcl_RegExpIndices *matches;
    long extendStart;
} Tcl_RegExpInfo;

El campo nsubs contiene un recuento del número de subexpresiones entre paréntesis dentro de la expresión regular. Si se usó TCL_REG_NOSUB, entonces este valor será cero. El campo matches apunta a una matriz de nsubs+1 valores que indican los límites de cada subexpresión que coincidió. El primer elemento de la matriz se refiere al rango coincidente por la expresión regular completa, y los elementos subsiguientes se refieren a las subexpresiones entre paréntesis en el orden en que aparecen en el patrón. Cada elemento es una estructura que se define de la siguiente manera:

typedef struct Tcl_RegExpIndices {
    long start;
    long end;
} Tcl_RegExpIndices;

Los valores start y end son índices de caracteres Unicode relativos a la ubicación del desplazamiento dentro de objPtr donde comenzó la coincidencia. El índice start identifica el primer carácter de la subexpresión coincidente. El índice end identifica el primer carácter después de la subexpresión coincidente. Si la subexpresión coincidió con la cadena vacía, entonces start y end serán iguales. Si la subexpresión no participó en la coincidencia, entonces start y end se establecerán en -1.

El campo extendStart en Tcl_RegExpInfo solo se establece si se utilizó el indicador TCL_REG_CANMATCH. Indica el primer carácter de la cadena donde podría ocurrir una coincidencia. Si se encontró una coincidencia, este será el mismo que el comienzo de la coincidencia actual. Si no se encontró ninguna coincidencia, entonces indica el punto más temprano en el que podría ocurrir una coincidencia si se agregan más texto a la cadena. Si no es posible ninguna coincidencia incluso con más texto, este campo se establecerá en -1.
