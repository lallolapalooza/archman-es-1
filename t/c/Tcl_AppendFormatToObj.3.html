ARGUMENTOS

const char *bytes (in)
Punta al primer byte de un array de bytes UTF-8 utilizado para establecer o agregar a un valor de cadena. Este array de bytes puede contener caracteres nulos incrustados, excepto si numChars es negativo. (Aplicaciones que necesitan caracteres nulos deberían representarlos como la secuencia de dos bytes \300\200, usar Tcl_ExternalToUtf para convertir, o Tcl_NewByteArrayObj si el string es una colección de bytes no interpretados.)
int length (in)
El número de bytes a copiar desde bytes al inicializar, establecer o agregar a un valor de cadena. Si es negativo, se usan todos los bytes hasta el primer nulo.
const Tcl_UniChar *unicode (in)
Punta al primer byte de un array de caracteres Unicode utilizado para establecer o agregar a un valor de cadena. Este array de bytes puede contener caracteres nulos incrustados, excepto si numChars es negativo.
int numChars (in)
El número de caracteres Unicode a copiar desde unicode al inicializar, establecer o agregar a un valor de cadena. Si es negativo, se usan todos los caracteres hasta el primer nulo.
int index (in)
El índice del carácter Unicode a devolver.
int first (in)
El índice del primer carácter Unicode en el rango de caracteres Unicode a devolver como un nuevo valor.
int last (in)
El índice del último carácter Unicode en el rango de caracteres Unicode a devolver como un nuevo valor.
Tcl_Obj *objPtr (in/out)
Punta a un valor a manipular.
Tcl_Obj *appendObjPtr (in)
El valor a añadir a objPtr en Tcl_AppendObjToObj.
int *lengthPtr (out)
Si no es NULL, el lugar donde Tcl_GetStringFromObj almacenará la longitud de la representación de cadena de un valor.
const char *string (in)
Valor de cadena terminado en nulo a añadir a objPtr.
va_list argList (in)
Una lista de argumentos que debe haber sido inicializada con va_start, y vaciada con va_end.
int limit (in)
Número máximo de bytes a añadir.
const char *ellipsis (in)
El sufijo a añadir cuando el límite hace que la cadena se trunque. Si se pasa NULL, se usa el sufijo “...”.
const char *format (in)
Controlador de formato incluyendo especificadores de conversión %.
int objc (in)
El número de elementos a formatear o concatenar.
Tcl_Obj *objv[] (in)
El array de valores a formatear o concatenar.
int newLength (in)
La nueva longitud de la representación de cadena de objPtr, sin incluir el carácter nulo final.

DESCRIPCIÓN

Los procedimientos descritos en esta página de manual permiten manipular valores Tcl como cadenas. Utilizan la representación interna del valor para almacenar información adicional y hacer más eficientes las manipulaciones de cadenas. En particular, hacen que una serie de operaciones de adición sean eficientes al reservar espacio adicional para la cadena, evitando copiarla cada vez que se añade. Además, los cálculos de índice y longitud se optimizan porque la representación de cadena Unicode se calcula y almacena en caché cuando sea necesario. Cuando se utilizan las funciones de la familia Tcl_Append*, donde el resultado del intérprete es el valor a añadir, es importante llamar a Tcl_ResetResult primero para asegurarse de no añadir intencionalmente a datos existentes en el valor de resultado.

Tcl_NewStringObj y Tcl_SetStringObj crean un nuevo valor o modifican un valor existente para almacenar una copia de la cadena dada por bytes y length. Tcl_NewUnicodeObj y Tcl_SetUnicodeObj crean un nuevo valor o modifican un valor existente para almacenar una copia de la cadena Unicode dada por unicode y numChars. Tcl_NewStringObj y Tcl_NewUnicodeObj devuelven un puntero a un nuevo valor con un contador de referencias cero. Los cuatro procedimientos establecen el valor para almacenar una copia de la cadena especificada. Tcl_SetStringObj y Tcl_SetUnicodeObj liberan cualquier representación antigua de cadena y de interior del valor.

Tcl_GetStringFromObj y Tcl_GetString devuelven la representación de cadena de un valor. Esta se da por el puntero de byte devuelto y (para Tcl_GetStringFromObj) la longitud, que se almacena en lengthPtr si no es NULL. Si la representación de cadena UTF-8 del valor es inválida (su puntero de byte es NULL), se regenera la representación de cadena a partir de la representación interna del valor. El almacenamiento al que apunta el puntero de byte devuelto es propiedad del gestor de valores. Se devuelve como un puntero escribible para que los autores de Tcl_ObjType puedan modificar la representación de cadena dentro de Tcl_UpdateStringProc de su Tcl_ObjType. Excepto por este propósito limitado, el puntero devuelto por Tcl_GetStringFromObj o Tcl_GetString debe tratarse como de solo lectura. Se recomienda asignar este puntero a una variable de tipo (const char *). Incluso en las situaciones limitadas en las que se permite escribir en este puntero, se debe tener cuidado de respetar las semánticas de copia en escritura requeridas por Tcl_Obj, con llamadas apropiadas a Tcl_IsShared y Tcl_DuplicateObj antes de cualquier modificación in situ de la representación de cadena. El procedimiento Tcl_GetString se utiliza en el caso común en el que el llamador no necesita la longitud de la representación de cadena.

Tcl_GetUnicodeFromObj y Tcl_GetUnicode devuelven el valor de un valor como una cadena Unicode. Esto se da por el puntero devuelto y (para Tcl_GetUnicodeFromObj) la longitud, que se almacena en lengthPtr si no es NULL. El almacenamiento al que apunta el puntero de byte devuelto es propiedad del gestor de valores y no debe ser modificado por el llamador. El procedimiento Tcl_GetUnicode se utiliza en el caso común en el que el llamador no necesita la longitud de la representación de cadena Unicode.

Tcl_GetUniChar devuelve el carácter en el índice index en la representación Unicode del valor. Se asume que el índice está en el rango adecuado.

Tcl_GetRange devuelve un nuevo valor compuesto por los caracteres entre first y last (inclusive) en la representación Unicode del valor. Si la representación Unicode del valor es inválida, se regenera la representación Unicode a partir de la representación de cadena del valor. Si first < 0, entonces la cadena devuelta comienza al principio del valor. Si last < 0, entonces la cadena devuelta termina al final del valor.

Tcl_GetChar devuelve el carácter en la representación Unicode del valor. Se asume que el índice está en el rango adecuado.

EJEMPLO

Este ejemplo muestra cómo se pueden usar las funciones mencionadas.

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

Longitud devuelve el número de caracteres (en lugar de bytes) en el valor de la cadena.

Tcl_AppendToObj anexa los datos proporcionados por bytes y length a la representación de cadena del valor especificado por objPtr. Si el valor tiene una representación de cadena inválida, se intenta convertir bytes al formato Unicode. Si la conversión es exitosa, la forma convertida de bytes se anexa a la representación Unicode del valor. De lo contrario, la representación Unicode del valor se invalida y se convierte al formato UTF, y bytes se anexa a la nueva representación de cadena del valor. Eventualmente, el crecimiento del búfer se realiza mediante asignaciones grandes para optimizar llamadas múltiples.

Tcl_AppendUnicodeToObj anexa la cadena Unicode proporcionada por unicode y numChars al valor especificado por objPtr. Si el valor tiene una representación Unicode inválida, unicode se convierte al formato UTF y se anexa a la representación de cadena del valor. Las anexiones se optimizan para manejar anexiones repetidas de manera relativamente eficiente (sobreasigna el espacio de cadena o Unicode para evitar reasignaciones y copias repetidas del valor de cadena del valor).

Tcl_AppendObjToObj es similar a Tcl_AppendToObj, pero anexa el valor de cadena o Unicode (el que exista y sea más adecuado para ser anexado a objPtr) de appendObjPtr a objPtr.

Tcl_AppendStringsToObj es similar a Tcl_AppendToObj excepto que se le pueden pasar varios valores para anexar y cada valor debe ser una cadena terminada en nulo (es decir, ninguno de los valores puede contener caracteres nulos internos). Se puede proporcionar cualquier número de argumentos string, pero el último argumento debe ser (char *)NULL para indicar el final de la lista.

Tcl_AppendStringsToObjVA es lo mismo que Tcl_AppendStringsToObj excepto que en lugar de tomar un número variable de argumentos, toma una lista de argumentos.

Tcl_AppendLimitedToObj es similar a Tcl_AppendToObj excepto que impone un límite en la cantidad de bytes que se anexan. Esto puede ser útil cuando la cadena que se va a anexar puede ser muy grande, pero no se debe permitir que el valor que se está construyendo crezca sin límites. Un uso común es al construir un mensaje de error, donde el resultado final debe mantenerse lo suficientemente corto como para ser leído. Los bytes de bytes se anexan a objPtr, pero no se anexan más de limit bytes en total. Si el límite impide que se anexen los length bytes disponibles, la anexión se realiza de manera que los últimos bytes anexados provienen de la cadena ellipsis. Esto permite indicar la truncación que queda en la cadena. Cuando length es -1, se anexan todos los bytes hasta el primer byte cero, sujeto al límite. Cuando ellipsis es NULL, se utiliza la cadena predeterminada .... Cuando ellipsis no es NULL, debe apuntar a una cadena terminada en byte cero en la codificación UTF interna de Tcl. El número de bytes anexados puede ser menor que el menor de length y limit cuando sea necesario anexar menos bytes para anexar solo caracteres de bytes múltiples completos.

Tcl_Format es la interfaz de nivel C del motor del comando format. El procedimiento de comando real para format es poco más que

Tcl_Format(interp, Tcl_GetString(objv[1]), objc-2, objv+2);

Los valores de Tcl_Obj objc en objv se formatean en una cadena según la especificación de conversión en el argumento format, siguiendo la documentación del comando format. La cadena formateada resultante se convierte en un nuevo Tcl_Obj con recuento de referencias cero y se devuelve. Si ocurre algún error durante la producción de la cadena formateada, se devuelve NULL y se registra un mensaje de error en interp, si interp no es NULL.

Tcl_AppendFormatToObj es una forma de anexión alternativa a Tcl_Format con funcionalidad equivalente a:

Tcl_Obj *newPtr = Tcl_Format(interp, format, objc, objv);
if (newPtr == NULL) return TCL_ERROR;
Tcl_AppendObjToObj(objPtr, newPtr);
Tcl_DecrRefCount(newPtr);
return TCL_OK;

pero con mayor comodidad y eficiencia cuando se necesita la funcionalidad de anexión.

Tcl_ObjPrintf sirve como reemplazo para la secuencia común

char buf[SOME_SUITABLE_LENGTH];
sprintf(buf, format, ...);
Tcl_NewStringObj(buf, -1);

pero con mayor comodidad y sin necesidad de determinar SOME_SUITABLE_LENGTH. El formateo se realiza con el mismo motor de formateo principal utilizado por Tcl_Format. Esto significa que el conjunto de especificadores de conversión compatibles es el del comando format, pero el comportamiento es lo más similar posible a sprintf. Los especificadores de formato que fueron agregados por C99 (como "hh", "ll", "j", "z", "t", "L") no son compatibles. Cuando un especificador de formato pasado a Tcl_ObjPrintf incluye una precisión, el valor se toma como un número de bytes, como lo hace sprintf, y no como un número de caracteres, como lo hace format. Esto se hace asumiendo que el código C es más propenso a saber cuántos bytes está manejando que el número de caracteres codificados que esos bytes representan. Los argumentos variables pasados deben ser de los tipos que serían adecuados para pasar a sprintf. Tenga en cuenta que en este ejemplo de uso, x es de tipo int.

int x = 5;
Tcl_Obj *objPtr = Tcl_ObjPrintf("Value is %d", x);

Si el valor de format contiene inconsistencias internas o formatos de especificador inválidos, la cadena formateada resultante producida por Tcl_ObjPrintf será un mensaje de error que describe el error. Sin embargo, es imposible proporcionar protección en tiempo de ejecución contra desajustes entre el formato y cualquier argumento posterior. Algunos compiladores pueden proporcionar protección en tiempo de compilación.

Tcl_AppendPrintfToObj es una forma de anexión alternativa a Tcl_ObjPrintf con funcionalidad equivalente a

Tcl_Obj *newPtr = Tcl_ObjPrintf(format, ...);
Tcl_AppendObjToObj(objPtr, newPtr);
Tcl_DecrRefCount(newPtr);

pero con mayor comodidad y eficiencia cuando se necesita la funcionalidad de anexión.

El procedimiento Tcl_SetObjLength cambia la longitud del valor de cadena de su argumento objPtr. Si el argumento newLength es mayor que el espacio asignado para la cadena del valor, entonces el espacio de cadena se reasigna y el valor antiguo se copia al nuevo espacio; los bytes entre la longitud antigua de la cadena y la nueva longitud pueden tener valores arbitrarios. Si el argumento newLength es menor que la longitud actual de la cadena del valor, con objPtr->length se reduce sin reasignar el espacio de la cadena; el tamaño de asignación original para la cadena se registra en el valor, de modo que la longitud de la cadena se pueda ampliar en una llamada posterior a Tcl_SetObjLength sin reasignar almacenamiento. En todos los casos, Tcl_SetObjLength deja un carácter nulo en objPtr->bytes[newLength].

Tcl_AttemptSetObjLength es idéntico en función a Tcl_SetObjLength excepto que si no se puede asignar suficiente memoria para satisfacer la solicitud, no hace que el intérprete de Tcl entre en **panic**. Por lo tanto, si newLength es mayor que el espacio asignado para la cadena del valor, y no hay suficiente memoria disponible para satisfacer la solicitud, Tcl_AttemptSetObjLength no realizará ninguna acción y devolverá 0 para indicar un fallo. Si hay suficiente memoria para satisfacer la solicitud, Tcl_AttemptSetObjLength se comporta igual que Tcl_SetObjLength y devuelve 1 para indicar éxito.

La función Tcl_ConcatObj devuelve un nuevo valor de cadena cuyo valor es la concatenación separada por espacios de las representaciones de cadena de todos los valores en la matriz objv. Tcl_ConcatObj elimina los espacios en blanco iniciales y finales al copiar las representaciones de cadena de la matriz objv al resultado. Si un elemento de la matriz objv consta únicamente de espacios en blanco, ese valor se ignora por completo. Esta eliminación de espacios en blanco se agregó para que la salida del comando concat tenga una apariencia más limpia. Tcl_ConcatObj devuelve un puntero a un valor recién creado con un recuento de referencias cero.
