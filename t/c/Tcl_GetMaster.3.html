DESCRIPCIÓN

Estos procedimientos están destinados al acceso a la instalación de múltiples intérpretes desde programas C. Permiten administrar múltiples intérpretes en una relación jerárquica, y la administración de alias, comandos que, al invocarse en un intérprete, ejecutan un comando en otro intérprete. El valor de retorno para aquellos procedimientos que devuelven un int es TCL_OK o TCL_ERROR. Si se devuelve TCL_ERROR, el resultado del intérprete contiene un mensaje de error.

Tcl_CreateSlave crea un nuevo intérprete como hijo de interp. También crea un comando hijo llamado childName en interp que permite a interp manipular al nuevo hijo. Si isSafe es cero, el comando crea un hijo confiable en el que el código Tcl tiene acceso a todos los comandos Tcl. Si es 1, el comando crea un hijo “seguro” en el que el código Tcl tiene acceso solo a un conjunto de comandos Tcl definidos como “Safe Tcl”; consulte la entrada del manual para el comando interp de Tcl para obtener detalles. Si la creación del nuevo intérprete hijo falló, se devuelve NULL.

Tcl_CreateChild es un sinónimo de Tcl_CreateSlave.

Tcl_IsSafe devuelve 1 si interp es “seguro” (fue creado con el flag TCL_SAFE_INTERPRETER especificado), 0 de lo contrario.

Tcl_MakeSafe marca interp como “seguro”, de modo que las futuras llamadas a Tcl_IsSafe devuelvan 1. También elimina toda la funcionalidad básica potencialmente insegura conocida (tanto comandos como variables) de interp. Sin embargo, no puede saber qué partes de una extensión o aplicación son seguras y no intenta eliminar esas partes, por lo que la seguridad no está garantizada después de llamar a Tcl_MakeSafe. Los llamadores querrán tener cuidado con su uso de Tcl_MakeSafe para evitar falsas afirmaciones de seguridad. Para muchas situaciones, Tcl_CreateSlave puede ser una mejor opción, ya que crea intérpretes en un estado seguro conocido.

Tcl_GetSlave devuelve un puntero a un intérprete hijo de interp. El intérprete hijo se identifica por childName. Si no existe dicho intérprete hijo, se devuelve NULL.

Tcl_GetChild es un sinónimo de Tcl_GetSlave.

Tcl_GetMaster devuelve un puntero al intérprete maestro de interp. Si interp no tiene maestro (es un intérprete de nivel superior), se devuelve NULL.

Tcl_GetParent es un sinónimo de Tcl_GetMaster.

Tcl_GetInterpPath almacena en el resultado de interp la ruta relativa entre interp y childInterp; childInterp debe ser un hijo de interp. Si el cálculo de la ruta relativa tiene éxito, se devuelve TCL_OK, de lo contrario, se devuelve TCL_ERROR y se almacena un mensaje de error como resultado de interp.

Tcl_CreateAlias crea un comando llamado childCmd en childInterp que, al invocarse, hará que el comando targetCmd se invoque en targetInterp. Los argumentos especificados por las cadenas contenidas en argv siempre se anteponen a cualquier argumento suministrado en la invocación de childCmd y se pasan a targetCmd. Esta operación devuelve TCL_OK si tiene éxito, o TCL_ERROR si falla; en ese caso, se deja un mensaje de error en el resultado de valor de childInterp. Tenga en cuenta que no hay restricciones en la relación de ascendencia (tal como la crea Tcl_CreateSlave) entre childInterp y targetInterp. Se pueden usar dos intérpretes cualesquiera, sin restricciones sobre cómo están relacionados.

Tcl_CreateAliasObj es similar a Tcl_CreateAlias, excepto que toma un vector de valores para pasar como argumentos adicionales en lugar de un vector de cadenas.

Tcl_GetAliasObj devuelve información en forma de un puntero a un vector de estructuras Tcl_Obj sobre un alias aliasName en interp. Cualquiera de los campos de resultado puede ser NULL, en cuyo caso el dato correspondiente no se devuelve. Si un campo de resultado no es NULL, la dirección indicada se establece en el dato correspondiente. Por ejemplo, si targetCmdPtr no es NULL, se establece en un puntero a la cadena que contiene el nombre del comando de destino.

Tcl_GetAlias es similar a Tcl_GetAliasObj, excepto que devuelve un puntero a un vector de cadenas en lugar de un vector de estructuras Tcl_Obj. Tcl_GetAlias está obsoleto.

Tcl_HideCommand elimina el comando cmdName de la tabla de comandos de nivel superior del intérprete interp. El comando se puede recuperar más tarde usando Tcl_ExposeCommand.

Tcl_ExposeCommand hace que el comando previamente oculto con el nombre hiddenCmdName esté disponible como el comando cmdName en el intérprete interp. El comando original (el que fue ocultado) debe ser accesible de alguna manera a través del intérprete de destino.

NOMBRE

Tcl_ExposeCommand, Tcl_HideCommand - mover comandos entre los conjuntos de comandos ocultos y expuestos

SINOPSIS

#include <tcl.h>

int
Tcl_ExposeCommand(interp, hiddenCmdName, cmdName);
int
Tcl_HideCommand(interp, cmdName, hiddenCmdName);

ARGUMENTOS

Tcl_Interp *interp
Intérprete de Tcl en el que se va a realizar la operación.
const char *hiddenCmdName
Nombre del comando oculto.
const char *cmdName
Nombre del comando expuesto.

DESCRIPCION

La función Tcl_ExposeCommand mueve el comando llamado hiddenCmdName del conjunto de comandos ocultos al conjunto de comandos expuestos, poniéndolo bajo el nombre cmdName. hiddenCmdName debe ser el nombre de un comando oculto existente, o la operación devolverá TCL_ERROR y dejará un mensaje de error como resultado de interp. Si ya existe un comando expuesto llamado cmdName, la operación devuelve TCL_ERROR y deja un mensaje de error como resultado de interp. Si la operación tiene éxito, devuelve TCL_OK. Después de ejecutar este comando, los intentos de usar cmdName en cualquier mecanismo de evaluación de scripts volverán a tener éxito.

La función Tcl_HideCommand mueve el comando llamado cmdName del conjunto de comandos expuestos al conjunto de comandos ocultos, bajo el nombre hiddenCmdName. cmdName debe ser el nombre de un comando expuesto existente, o la operación devolverá TCL_ERROR y dejará un mensaje de error como resultado de interp. Actualmente, tanto cmdName como hiddenCmdName no deben contener calificadores de espacio de nombres, o la operación devolverá TCL_ERROR y dejará un mensaje de error como resultado de interp. Se buscará cmdName en el espacio de nombres global, y no en relación con el espacio de nombres actual, incluso si el espacio de nombres actual no es el global. Si ya existe un comando oculto cuyo nombre es hiddenCmdName, la operación también devuelve TCL_ERROR y se deja un mensaje de error como resultado de interp. Si la operación tiene éxito, devuelve TCL_OK. Después de ejecutar este comando, los intentos de usar cmdName en cualquier mecanismo de evaluación de scripts fallarán.

Para una descripción de la interfaz Tcl para múltiples intérpretes, véase interp(n).
