ARGUMENTS

Tcl_Interp *interp (in)
Si se produce un error al convertir un valor en un valor de diccionario, se dejará un mensaje de error en el valor de resultado del interprete, excepto si interp es NULL.
Tcl_Obj *dictPtr (in/out)
Se refiere al valor de diccionario a manipular. Si dictPtr no ya apunta a un valor de diccionario, se intentará convertirlo.
Tcl_Obj *keyPtr (in)
Apunta a la clave del par de clave/valor a manipular dentro del valor de diccionario.
Tcl_Obj **keyPtrPtr (out)
Apunta a una variable que contendrá la clave del par de clave/valor. Puede ser NULL para indicar que el llamante no está interesado en la clave.
Tcl_Obj *valuePtr (in)
Apunta al valor del par de clave/valor a manipular dentro del valor de diccionario (o sub-valor en el caso de Tcl_DictObjPutKeyList).
Tcl_Obj **valuePtrPtr (out)
Apunta a una variable que contendrá el valor del par de clave/valor. Para Tcl_DictObjFirst y Tcl_DictObjNext, puede ser NULL para indicar que el llamante no está interesado en el valor.
int *sizePtr (out)
Apunta a una variable que contendrá el número de pares clave/valor dentro del diccionario.
Tcl_DictSearch *searchPtr (in/out)
Apuntador a un registro para mantener el seguimiento de los pares clave/valor en un diccionario. Los contenidos del registro se inicializan con el llamado a Tcl_DictObjFirst. Si se debe terminar la enumeración antes de que todos los valores del diccionario hayan sido devueltos, el registro de búsqueda deben ser pasado a Tcl_DictObjDone para liberar los bloqueos internos.
int *donePtr (out)
Apunta a una variable que contendrá un valor no cero cuando la enumeración de pares clave/valor en un diccionario ha terminado, y cero de lo contrario.
int keyc (in)
Indica el número de claves que se proporcionarán en el arreglo keyv.
Tcl_Obj *const *keyv (in)
Arreglo de keyc apuntadores a valores que Tcl_DictObjPutKeyList y Tcl_DictObjRemoveKeyList utilizarán para localizar el par de clave/valor a manipular dentro de los sub-diccionarios del valor principal del diccionario.

DESCRIPCIÓN

Los valores de diccionario de Tcl tienen una representación interna que permite una mapa eficiente de claves a valores y que garantiza que el orden de las claves dentro del diccionario sea el mismo, excepto cuando se eliminen (que los removen del orden) o se añadan (que los añaden al final del orden). Si se interpreta como una lista, los valores en las posiciones pares del lista serán las claves del diccionario, y cada una se seguirá (en la posición impar) por el valor asociado a esa clave.

Las procedimientos descritos en esta página de man son utilizados para crear, modificar, indexar y iterar sobre valores de diccionario desde el código C.

Tcl_NewDictObj crea un nuevo valor de diccionario vacío. La representación string del valor será inválida y el contador de referencias del valor será cero.

Tcl_DictObjGet busca la clave dada dentro del diccionario y escribe un apuntador al valor asociado con esa clave en la variable indicada por valuePtrPtr, o un valor nulo si no hay mapa para esa clave en el diccionario. El resultado de esta operación es TCL_OK, o TCL_ERROR si el dictPtr no puede ser convertido a un diccionario.

Tcl_DictObjPut actualiza el diccionario para que la clave dada mapa a valor dado; cualquier clave puede existir máximo una vez en cualquier diccionario. El diccionario no debe compartirse, pero la clave y el valor pueden. Esta operación puede aumentar la cuenta de referencias de la clave y el valor si es necesario para almacenarlos. Neither clave ni valor debe ser nulo. El resultado de esta operación es TCL_OK, o TCL_ERROR si el dictPtr no puede ser convertido a un diccionario.

Tcl_DictObjRemove actualiza el diccionario para que la clave dada no mapa a ningún valor. El diccionario no debe compartirse, pero la clave puede ser. La clave realmente almacenada en el diccionario decrementará su cuenta de referencias si estaba presente. No es un error si la clave no existía previamente. El resultado de esta operación es TCL_OK, o TCL_ERROR si el dictPtr no puede ser convertido a un diccionario.

Tcl_DictObjSize actualiza la variable dada con el número de pares clave/valor actuales en el diccionario. El resultado de esta operación es TCL_OK, o TCL_ERROR si el dictPtr no puede ser convertido a un diccionario.

Tcl_DictObjFirst comienza una iteración sobre todos los pares clave/valor en el diccionario, colocando la clave y el valor en las variables indicadas por keyPtrPtr y valuePtrPtr (que pueden ser NULL para indicar que el llamante no está interesado en la clave o la variable respectivamente). El siguiente par clave/valor en el diccionario puede ser obtenido con Tcl_DictObjNext. Las actualizaciones concurrentes de la representación interna del diccionario no modificarán la procesión de iteración, a menos que el diccionario sea no compartido, en cuyo caso esto provocará la terminación anticipada de la iteración (que no puede ser provocada por el comando dict de Tcl). El argumento searchPtr apunta a un contexto que se usa para identificar cuál iteración está siendo realizada, y se inicializa con el llamado a Tcl_DictObjFirst. El argumento donePtr apunta a una variable que se actualiza a cero si hay más pares clave/valor por iterar, o a no cero si la iteración está completa. El orden de iteración es definido de forma implementada. Si el dictPtr no puede ser convertido a un diccionario, Tcl_DictObjFirst devuelve TCL_ERROR y la iteración no se iniciará, y de lo contrario devuelve TCL_OK.

Cuando Tcl_DictObjFirst es llamado sobre un diccionario, un bloqueo se coloca en el diccionario para permitir que el diccionario sea iterado sobre de manera segura, sin importar si el diccionario es modificado durante la iteración. Debido a esto, una vez que la iteración sobre las claves de un diccionario ha terminado (ya sea porque todos los valores han sido iterados sobre como indicado por la variable indicada por el donePtr ha sido establecida a uno, o porque no se requieren más valores), debe llamarse con el mismo searchPtr que se pasó a Tcl_DictObjFirst con Tcl_DictObjDone para liberar los bloqueos internos. Una vez que un searchPtr particular ha sido pasado a Tcl_DictObjDone, pasar a Tcl_DictObjNext (sin primero inicializarlo con Tcl_DictObjFirst) resultará en la producción de ningún valor y la variable indicada por donePtr será establecida a uno. Es seguro llamar a Tcl_DictObjDone múltiples veces en la misma searchPtr para cada llamada a Tcl_DictObjFirst

Las procedimientos Tcl_DictObjPutKeyList y Tcl_DictObjRemoveKeyList son los análogos cerrados de Tcl_DictObjPut y Tcl_DictObjRemove respectivamente, a menos que trabajen con un único diccionario, pero se diseñen para operar en una arboles de diccionarios anidados, con diccionarios internos almacenados como valores dentro de los diccionarios externos. Los argumentos keyc y keyv especifican una lista de claves (con claves externas primero) que actúa como un camino para el par de clave/valor a afectar. Nota: No hay operación correspondiente para leer un valor

ARGUMENTS

The name of the function is a mnemonic for its intended purpose: the KeyList functions operate on lists of keys rather than a single key. They are intended for use with nested dictionaries where a list of keys describes a path into the nested structure.

Tcl_DictObjPutKeyList puts a value into a dictionary object, creating nested dictionaries as needed. The keyList argument is an array of Tcl_Obj pointers representing the sequence of keys to traverse to reach the target value. The last key in the list is the key for the valuePtr. If any intermediate keys do not exist, or do not refer to a dictionary, then they will be created as dictionaries. If the final key already exists, its value will be replaced. If the final key does not exist, it will be created. The function returns TCL_OK on success, and TCL_ERROR on failure (e.g., if interp is null, or if a key is invalid). The caller is responsible for managing the reference counts of the objects in keyList and valuePtr.

Tcl_DictObjGetKeyList retrieves a value from a dictionary object using a list of keys. valuePtrPtr is set to point to the Tcl_Obj representing the value, or to the Tcl_Obj representing the last key in the path if the value is not found. The reference count of the returned object is not incremented. The function returns TCL_OK on success, and TCL_ERROR on failure.

Tcl_DictObjRemoveKeyList removes a value from a dictionary object using a list of keys. All keys in the keyList must exist and refer to dictionaries, except for the last key, which refers to the value to be removed. If any intermediate keys do not exist or do not refer to dictionaries, the function will return TCL_ERROR. The function returns TCL_OK on success, and TCL_ERROR on failure.

Tcl_DictObjGet, Tcl_DictObjPut, and Tcl_DictObjRemove are the basic dictionary operations for getting, putting, and removing a single key-value pair. They are used when operating on a flat dictionary (i.e., one without nested dictionaries). Their behavior is analogous to the Tcl_DictObjGetKeyList, Tcl_DictObjPutKeyList, and Tcl_DictObjRemoveKeyList functions, respectively, when the keyList contains only a single key.

Tcl_DictObjFirst, Tcl_DictObjNext, Tcl_DictObjDone, and Tcl_DictObjSearch provide an interface for iterating over the key-value pairs in a dictionary. Tcl_DictObjSearch initializes a dictionary search structure. Tcl_DictObjFirst retrieves the first key-value pair and initializes the iteration. Tcl_DictObjNext retrieves subsequent key-value pairs. Tcl_DictObjDone cleans up the search structure. It is important to call Tcl_DictObjDone when done with the iteration, even if an error occurred. The functions return TCL_OK on success and TCL_ERROR on failure.

DESCRIPTION

The KeyList functions allow for convenient manipulation of nested dictionaries. A path into a nested dictionary can be specified as a list of keys. For example, if you have a dictionary that looks like this:

{a {b {c 1}}}

Then the path to the value 1 is specified by the key list {a b c}.

Tcl_DictObjPutKeyList is useful for creating nested dictionaries. For example, if the dictionary is initially empty, calling Tcl_DictObjPutKeyList with the key list {a b c} and value 1 will result in the dictionary {a {b {c 1}}}. If the dictionary already contained {a {b 2}}, calling Tcl_DictObjPutKeyList with the same key list and value 1 would result in {a {b {c 1}}}, overwriting the previous value associated with the key c.

Tcl_DictObjGetKeyList allows you to retrieve a value from a nested dictionary using a path. If the path does not exist, or if any intermediate element is not a dictionary, Tcl_DictObjGetKeyList will return TCL_ERROR.

Tcl_DictObjRemoveKeyList removes an element from a nested dictionary. All intermediate keys in the path must exist and refer to dictionaries. If any intermediate key does not exist or does not refer to a dictionary, Tcl_DictObjRemoveKeyList will return TCL_ERROR.

The basic dictionary operations Tcl_DictObjGet, Tcl_DictObjPut, and Tcl_DictObjRemove provide a simpler interface for working with flat dictionaries (dictionaries that do not contain other dictionaries as values).

The iteration functions Tcl_DictObjFirst, Tcl_DictObjNext, Tcl_DictObjDone, and Tcl_DictObjSearch provide a way to iterate over all the key-value pairs in a dictionary. This can be useful for tasks such as searching for a specific key or value, or for performing some operation on all elements of the dictionary. The iteration interface can be used with nested dictionaries as well, although it iterates over the top-level key-value pairs only. For a path as this is easy to construct from repeated use of Tcl_DictObjGet. With Tcl_DictObjPutKeyList, nested dictionaries are created for non-terminal keys where they do not already exist. With Tcl_DictObjRemoveKeyList, all non-terminal keys must exist and have dictionaries as their values.

EXAMPLE

Using the dictionary iteration interface to search determine if there is a key that maps to itself:

Tcl_DictSearch search;
Tcl_Obj *key, *value;
int done;
/*
 * Assume interp and objPtr are parameters.  This is the
 * idiomatic way to start an iteration over the dictionary; it
 * sets a lock on the internal representation that ensures that
 * there are no concurrent modification issues when normal
 * reference count management is also used.  The lock is
 * released automatically when the loop is finished, but must
 * be released manually when an exceptional exit from the loop
 * is performed. However it is safe to try to release the lock
 * even if we've finished iterating over the loop.
 */
if (Tcl_DictObjFirst(interp, objPtr, &search,
        &key, &value, &done) != TCL_OK) {
    return TCL_ERROR;
}
for (; !done ; Tcl_DictObjNext(&search, &key, &value, &done)) {
    /*
     * Note that strcmp() is not a good way of comparing
     * values and is just used here for demonstration
     * purposes.
     */
    if (!strcmp(Tcl_GetString(key), Tcl_GetString(value))) {
        break;
    }
}
Tcl_DictObjDone(&search);
Tcl_SetObjResult(interp, Tcl_NewBooleanObj(!done));
return TCL_OK;
