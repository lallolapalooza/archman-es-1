Tcl_Eval(3) Procedimientos de la biblioteca Tcl Tcl_Eval(3)

NOMBRE

Tcl_EvalObjEx, Tcl_EvalFile, Tcl_EvalObjv, Tcl_Eval, Tcl_EvalEx, Tcl_GlobalEval, Tcl_GlobalEvalObj, Tcl_VarEval, Tcl_VarEvalVA - ejecutar scripts Tcl

SINOPSIS

#include <tcl.h>

int
Tcl_EvalObjEx(interp, objPtr, flags)

int
Tcl_EvalFile(interp, fileName)

int
Tcl_EvalObjv(interp, objc, objv, flags)

int
Tcl_Eval(interp, script)

int
Tcl_EvalEx(interp, script, numBytes, flags)

int
Tcl_GlobalEval(interp, script)

int
Tcl_GlobalEvalObj(interp, objPtr)

int
Tcl_VarEval(interp, part, part, ... (char *)NULL)

int
Tcl_VarEvalVA(interp, argList)

ARGUMENTOS

Tcl_Interp *interp (entrada)
Intérprete en el que ejecutar el script. El resultado del intérprete se modifica para contener el resultado o el mensaje de error del script.
Tcl_Obj *objPtr (entrada)
Un valor Tcl que contiene el script a ejecutar.
int flags (entrada)
Combinación OR de bits de bandera que especifican opciones adicionales. Actualmente se admiten TCL_EVAL_GLOBAL y TCL_EVAL_DIRECT.
const char *fileName (entrada)
Nombre de un archivo que contiene un script Tcl.
int objc (entrada)
El número de valores en la matriz apuntada por objv; este es también el número de palabras en el comando.
Tcl_Obj **objv (entrada)
Punta a una matriz de punteros a valores; cada valor contiene el valor de una palabra individual en el comando a ejecutar.
int numBytes (entrada)
El número de bytes en script, sin incluir ningún carácter de terminación nula. Si es -1, entonces se utilizan todos los caracteres hasta el primer byte nulo.
const char *script (entrada)
Punta al primer byte del script a ejecutar (terminado en nulo y UTF-8).
const char *part (entrada)
Cadena que forma parte de un script Tcl.
va_list argList (entrada)
Una lista de argumentos que debe haber sido inicializada con va_start y limpiada con va_end.

DESCRIPCIÓN

Los procedimientos descritos aquí se invocan para ejecutar scripts Tcl en diversas formas. Tcl_EvalObjEx es el procedimiento central y es utilizado por muchos de los otros. Ejecuta los comandos en el script almacenado en objPtr hasta que ocurra un error o se alcance el final del script. Si es la primera vez que se ejecuta objPtr, sus comandos se compilan en instrucciones de bytecode que luego se ejecutan. Los bytecodes se guardan en objPtr para que el paso de compilación se pueda omitir si el valor se evalúa nuevamente en el futuro.

El valor de retorno de Tcl_EvalObjEx (y de todos los demás procedimientos descritos aquí) es un código de finalización Tcl con uno de los valores TCL_OK, TCL_ERROR, TCL_RETURN, TCL_BREAK, o TCL_CONTINUE, o posiblemente algún otro valor entero originario de una extensión. Además, se deja un valor de resultado o mensaje de error en el resultado de interp; se puede recuperar usando Tcl_GetObjResult.

Tcl_EvalFile lee el archivo proporcionado por fileName y evalúa su contenido como un script Tcl. Devuelve la misma información que Tcl_EvalObjEx. Si el archivo no se pudo leer, se devuelve un error Tcl para describir por qué no se pudo leer el archivo. El carácter eof de los archivos es “\32” (^Z) para todas las plataformas. Si requiere un “^Z” en el código para la comparación de cadenas, puede usar “\032” o “\u001a”, que serán sustituidos de forma segura por el intérprete Tcl en “^Z”.

Tcl_EvalObjv ejecuta un solo comando pre-analizado en lugar de un script. Los argumentos objc y objv contienen los valores de las palabras para el comando Tcl, una palabra en cada valor de objv. Tcl_EvalObjv evalúa el comando y devuelve un código de finalización y resultado al igual que Tcl_EvalObjEx. El llamador de Tcl_EvalObjv debe gestionar el contador de referencias de los elementos de objv, asegurando que los valores sean válidos hasta que Tcl_EvalObjv retorne.

Tcl_Eval es similar a Tcl_EvalObjEx excepto que el script a ejecutar se suministra como una cadena en lugar de un valor y no se realiza ninguna compilación. La cadena debe ser una cadena UTF-8 adecuada, como la convertida por Tcl_ExternalToUtfDString o Tcl_ExternalToUtf cuando se sabe que puede contener caracteres ASCII superiores cuyas posibles combinaciones podrían ser un código especial UTF-8. La cadena se analiza y ejecuta directamente (usando Tcl_EvalObjv) en lugar de compilarla y ejecutar los bytecodes. En situaciones donde se sabe que el script nunca se ejecutará de nuevo, Tcl_Eval puede ser más rápido que Tcl_EvalObjEx.
Tcl_Eval devuelve un código de finalización y resultado al igual que Tcl_EvalObjEx. Nota: para compatibilidad con versiones anteriores a Tcl 8.0, Tcl_Eval copia el resultado del valor en interp a interp->result (su uso está obsoleto) donde se puede acceder directamente.
Esto hace que Tcl_Eval sea algo más lento que Tcl_EvalEx, que no realiza la copia.

Tcl_EvalEx es una versión extendida de Tcl_Eval que toma argumentos adicionales numBytes y flags. Por la razón de eficiencia dada anteriormente, Tcl_EvalEx es generalmente preferible a Tcl_Eval.

Tcl_GlobalEval y Tcl_GlobalEvalObj son procedimientos más antiguos que ahora están obsoletos. Son similares a Tcl_EvalEx y Tcl_EvalObjEx excepto que el script se evalúa en el espacio de nombres global y su contexto de variables consiste solo en variables globales (ignora cualquier procedimiento Tcl activo). Estas funciones son equivalentes a usar la bandera TCL_EVAL_GLOBAL (ver abajo).

Tcl_VarEval toma cualquier número de argumentos de cadena de cualquier longitud, los concatena en una sola cadena, luego llama a Tcl_Eval para ejecutar esa cadena como un comando Tcl. Devuelve el resultado del comando y también modifica interp->result de la misma manera que Tcl_Eval. El último argumento a Tcl_VarEval debe ser (char *)NULL para indicar el fin de los argumentos.

Tcl_VarEvalVA es lo mismo que Tcl_VarEval excepto que en lugar de tomar un número variable de argumentos, toma una lista de argumentos. Tcl_VarEvalVA está ahora obsoleto.

BITS DE BANDERA

Cualquier combinación OR de los siguientes valores puede usarse para el argumento flags de procedimientos como Tcl_EvalObjEx:

TCL_EVAL_DIRECT
Esta bandera solo es utilizada por Tcl_EvalObjEx; es ignorada por otros procedimientos. Si este bit de bandera está establecido, el script no se compila a bytecodes; en su lugar, se ejecuta directamente como lo hace Tcl_EvalEx. La bandera TCL_EVAL_DIRECT es útil en situaciones donde el contenido de un valor va a cambiar inmediatamente, por lo que los bytecodes no se reutilizarán en una ejecución futura. En este caso, es más rápido ejecutar el script directamente.
TCL_EVAL_GLOBAL
Si esta bandera está establecida, el script se evalúa en el espacio de nombres global en lugar del espacio de nombres actual y su contexto de variables consiste solo en variables globales (ignora cualquier procedimiento Tcl activo).

DETALLES VARIOS

Durante el procesamiento de un comando Tcl es legal realizar llamadas anidadas para evaluar otros comandos (así es como se implementan los procedimientos y algunas estructuras de control). Si un código que no sea TCL_OK se devuelve de una invocación anidada de Tcl_EvalObjEx, entonces el llamador normalmente debería devolver inmediatamente, pasando ese mismo código de retorno a su llamador, y así sucesivamente hasta que se alcance la aplicación de nivel superior. Algunos comandos, como for, verificarán ciertos códigos de retorno, como TCL_BREAK y TCL_CONTINUE, y los procesarán especialmente sin devolver.

Tcl_EvalObjEx realiza un seguimiento de cuántas invocaciones anidadas de Tcl_EvalObjEx están en progreso para interp. Si un código de TCL_RETURN, TCL_BREAK o TCL_CONTINUE está a punto de ser devuelto desde la invocación de Tcl_EvalObjEx de nivel superior para interp, convierte el código de retorno a TCL_ERROR y establece el resultado de interp en un mensaje de error que indica que la operación return, break,

or continue se invocó en un lugar inapropiado. Esto significa que las aplicaciones de nivel superior nunca deberían ver un código de retorno de Tcl_EvalObjEx que no sea TCL_OK o TCL_ERROR.
