ARGUMENTOS

Tcl_Interp *interp (entrada)
El intérprete donde se almacenarán los datos comprimidos o descomprimidos resultantes. También donde se escribirán los mensajes de error. Para Tcl_ZlibStreamInit, esto puede ser NULL para crear un flujo que no esté vinculado a un comando.
int format (entrada)
Qué formato de datos comprimidos se utilizará. Debe ser uno de TCL_ZLIB_FORMAT_ZLIB para datos en formato zlib, TCL_ZLIB_FORMAT_GZIP para datos en formato gzip, o TCL_ZLIB_FORMAT_RAW para datos comprimidos sin procesar. Además, solo para descompresión, también se puede elegir TCL_ZLIB_FORMAT_AUTO, que puede detectar automáticamente si los datos comprimidos estaban en formato zlib o gzip.
Tcl_Obj *dataObj (entrada/salida)
Un valor de matriz de bytes que contiene los datos a comprimir o descomprimir, o al que se añaden los datos extraídos del flujo cuando se pasa a Tcl_ZlibStreamGet.
int level (entrada)
Qué nivel de compresión utilizar. Debe ser un número del 0 al 9 o una de las siguientes opciones: TCL_ZLIB_COMPRESS_NONE para sin compresión, TCL_ZLIB_COMPRESS_FAST para compresión rápida pero ineficiente, TCL_ZLIB_COMPRESS_BEST para compresión lenta pero máxima, o TCL_ZLIB_COMPRESS_DEFAULT para el nivel recomendado por la biblioteca zlib.
Tcl_Obj *dictObj (entrada/salida)
Un diccionario que contiene, o que se actualizará para contener, una descripción de la cabecera gzip asociada con los datos comprimidos. Solo es útil cuando el parámetro format es TCL_ZLIB_FORMAT_GZIP o TCL_ZLIB_FORMAT_AUTO. Si se pasa NULL, se utilizará una cabecera predeterminada en la compresión y la cabecera se ignorará (aparte de las comprobaciones de integridad) en la descompresión. Consulte la sección DICCIONARIO DE OPCIONES GZIP para obtener detalles sobre el contenido de este diccionario.
unsigned int initValue (entrada)
El valor inicial para el algoritmo de suma de verificación.
int bufferSize (entrada)
Una pista sobre el tamaño del búfer que se utilizará para recibir los datos. Utilice 0 para usar una estimación genérica basada en los datos de entrada.
unsigned char *bytes (entrada)
Una matriz de bytes sobre la que ejecutar el algoritmo de suma de verificación, o NULL para obtener el valor inicial recomendado para el algoritmo de suma de verificación.
int length (entrada)
El número de bytes en la matriz.
int mode (entrada)
En qué modo operar el flujo. Debe ser TCL_ZLIB_STREAM_DEFLATE para un flujo de compresión o TCL_ZLIB_STREAM_INFLATE para un flujo de descompresión.
Tcl_ZlibStream *zshandlePtr (salida)
Un puntero a una variable en la que se escribirá el token abstracto para el flujo tras una creación exitosa.
Tcl_ZlibStream zshandle (entrada)
El token abstracto para el flujo sobre el que operar.
int flush (entrada)
Si y cómo vaciar el flujo después de escribirle los datos. Debe ser una de las siguientes opciones: TCL_ZLIB_NO_FLUSH si no se va a realizar ningún vaciado, TCL_ZLIB_FLUSH si los datos comprimidos actuales deben estar disponibles para su acceso mediante Tcl_ZlibStreamGet, TCL_ZLIB_FULLFLUSH si el flujo debe ponerse en un estado en el que el descompresor pueda recuperarse de una corrupción, o TCL_ZLIB_FINALIZE para asegurar que el flujo se ha completado y que se escribe cualquier tráiler exigido por el formato.
int count (entrada)
El número máximo de bytes a obtener del flujo, o -1 para obtener todos los bytes restantes de los búferes del flujo.
Tcl_Obj *compDict (entrada)
Un valor de matriz de bytes que es el diccionario de compresión a usar con el flujo. Tenga en cuenta que esto *no es un diccionario Tcl*, y se recomienda que solo se use con flujos creados con su format establecido en TCL_ZLIB_FORMAT_ZLIB porque los otros formatos no tienen ningún mecanismo para indicar si estaba presente un diccionario de compresión aparte de fallar en la descompresión.

DESCRIPCIÓN

Estas funciones forman la interfaz de la biblioteca Tcl a la biblioteca Zlib de Jean-loup Gailly y Mark Adler.

Tcl_ZlibDeflate y Tcl_ZlibInflate respectivamente comprimen y descomprimen los datos contenidos en el argumento dataObj, de acuerdo con los argumentos format y, para la compresión, level. El diccionario en el parámetro dictObj se utiliza para transmitir información adicional de cabecera sobre los datos comprimidos cuando el formato de compresión lo admite; actualmente, el diccionario solo se utiliza cuando el parámetro format es TCL_ZLIB_FORMAT_GZIP o TCL_ZLIB_FORMAT_AUTO. Para obtener detalles sobre el contenido del diccionario, consulte la sección DICCIONARIO DE OPCIONES GZIP a continuación. Tras el éxito, ambas funciones dejan los datos comprimidos o descomprimidos resultantes en un valor de matriz de bytes que es el resultado del intérprete Tcl; el valor devuelto es un código de resultado Tcl estándar.

Tcl_ZlibAdler32 y Tcl_ZlibCRC32 calculan sumas de verificación en matrices de bytes, devolviendo la suma de verificación calculada. Las sumas de verificación se calculan de forma incremental, lo que permite procesar los datos bloque a bloque, pero esto requiere que el llamador mantenga la suma de verificación actual y la pase como parámetro initValue; el valor inicial a utilizar para esto se puede obtener usando NULL para el parámetro bytes en lugar de un puntero a la matriz de bytes sobre la que calcular la suma de verificación. Por lo tanto, el uso típico en el caso de un solo bloque de datos es el siguiente:

checksum = Tcl_ZlibCRC32(Tcl_ZlibCRC32(0,NULL,0), data, length);

Tenga en cuenta que el algoritmo Adler-32 no es una suma de verificación real, sino un tipo de hash relacionado que funciona mejor con datos largos.

FLUJOS ZLIB

Tcl_ZlibStreamInit crea un flujo de compresión o descompresión que está vinculado a un comando Tcl, de acuerdo con sus argumentos, y proporciona un token abstracto para el flujo y devuelve un código de resultado Tcl normal; Tcl_ZlibStreamGetCommandName devuelve el nombre de ese comando dado el token del flujo, o NULL si el flujo no tiene un comando. Los flujos no están diseñados para ser seguros para subprocesos; cada flujo solo debe usarse desde el hilo que lo creó. Al trabajar con flujos gzip, se puede proporcionar un diccionario (campos como se indica en la sección DICCIONARIO DE OPCIONES GZIP) a través del parámetro dictObj que, en la compresión, permite controlar las cabeceras generadas y, en la descompresión, permite descubrir las cabeceras existentes. Tenga en cuenta que el diccionario se escribirá al descomprimir una vez que se hayan leído suficientes datos para tener una cabecera completa. Esto significa que el diccionario debe ser un valor no compartido en ese caso; se sugiere un valor en blanco creado con Tcl_NewObj.

Una vez construido un flujo, Tcl_ZlibStreamPut se utiliza para añadir datos al flujo y Tcl_ZlibStreamGet se utiliza para recuperar datos del flujo después del procesamiento. Ambos devuelven códigos de resultado Tcl normales y dejan un mensaje de error en el resultado del intérprete con el que está registrado el flujo (si se ha realizado dicha registración). Con Tcl_ZlibStreamPut, el valor del búfer de datos que se le pasa no debe modificarse posteriormente. Con Tcl_ZlibStreamGet, el valor del búfer de datos que se le pasa tendrá los bytes de datos añadidos. Internamente al flujo, los datos se mantienen comprimidos para minimizar el costo del espacio del búfer.

Tcl_ZlibStreamSetCompressionDictionary se usa para controlar el diccionario de compresión utilizado con el flujo, un diccionario de compresión siendo un array de bytes (como podría ser creado con Tcl_NewByteArrayObj) que se usa para inicializar el motor de compresión, en lugar de dejarlo crearlo en el momento de la compresión. Establecer un diccionario de compresión permite una compresión más eficiente en el caso de datos que empiezan de manera regular, pero requiere que el comprador y el descompressor coincidan en el valor a usar. Los diccionarios de compresión son solo completamente soportados para datos en formato zlib; antes de enviar cualquier datos con Tcl_ZlibStreamPut, deben ser establecidos antes, y durante la descompresión, deben ser establecidos cuando Tcl_ZlibStreamGet produzca un error con su -errorcode establecido a ZLIB NEED_DICT; código será el checksum de Adler-32 (véase Tcl_ZlibAdler32) del diccionario de compresión buscado. (Nota que esta es solo válida para flujos de compresión en formato zlib; los flujos de gzip ignoran los diccionarios de compresión ya que el formato no permite ello, y los flujos brutos producen un error de datos si el diccionario de compresión falta o está mal).

Si deseas limpiar un flujo y volver a usarlo para una nueva acción de compresión o descompresión, Tcl_ZlibStreamReset lo hará y devolverá un código de resultado normal de Tcl para indicar si fue exitosa; si el flujo está registrado con un interprete, una mensaje de error se dejará en el resultado del interprete cuando este función devuelva TCL_ERROR. Finalmente, Tcl_ZlibStreamClose limpiará el flujo y eliminará el comando asociado: usar Tcl_DeleteCommand en el comando del flujo es equivalente (cuando tal comando existe).

GZIP OPTIONS DICTIONARY

El parámetro dictObj a Tcl_ZlibDeflate, Tcl_ZlibInflate y Tcl_ZlibStreamInit se usa para pasar un diccionario de opciones sobre ese que se usa para describir el encabezado de gzip en los datos compresionados. Al crear datos compresionados, el diccionario se lee y al descomprimir datos compresionados, se escribe (en este caso, el dictObj debe referir a un valor de diccionario no compartido).

Los siguientes campos en el valor del diccionario se entienden. Todos los otros campos se ignoran. No hay campo obligatorio cuando se crea un flujo de formato gzip.

comment
Esta contiene el campo de comentario del encabezado, si es presente. Si no está presente, no se proporcionó (en descompresión) o se creará (en compresión).
crc
Un valor booleano que describa si se ha calculado un CRC del encabezado. Nota que el programa gzip no utiliza ni permite un CRC en el encabezado.
filename
El nombre del archivo que almacenó los datos descompresionados. Debe evitar cualquier separador de directorio y debe ser sanitizado antes de su uso en descompresión con file tail.
os
El código de campo de sistema operativo del encabezado (si no es el valor desconocido). Véase RFC 1952 para el significado de estos códigos. En compresión, si este campo es ausente, se establecerá a valor desconocido.
size
El tamaño de los datos descompresionados. Este se ignora en compresión; el tamaño de los datos comprimidos depende de cuánto datos se proporciona al motor de compresión.
time
El campo de tiempo del encabezado si no es cero, esperado para ser el tiempo en el que el archivo nombrado por el campo filename fue modificado. Es adecuado para usar con clock format. En creación, el valor correcto a usar es el del clock seconds o file mtime.
type
El tipo de los datos descompresionados (either binary o text) si es conocido.

PORTABILITY NOTES

Estas funciones se comportarán de forma gracia si Tcl no está vinculado con la biblioteca zlib.
