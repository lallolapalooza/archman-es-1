DESCRIPCIÓN

Las rutinas Tcl_SetReturnOptions y Tcl_GetReturnOptions exponen las mismas capacidades que los comandos return y catch, respectivamente, en forma de una interfaz C.

Tcl_GetReturnOptions recupera el diccionario de opciones de retorno de un intérprete después de la evaluación de un script. Rutinas como Tcl_Eval se utilizan para evaluar un script en un intérprete. Estas rutinas devuelven un código de finalización entero. Estas rutinas también dejan en el intérprete tanto un resultado como un diccionario de opciones de retorno generado por la evaluación del script. Al igual que Tcl_GetObjResult recupera el resultado, Tcl_GetReturnOptions recupera el diccionario de opciones de retorno. El código de finalización entero debe pasarse como argumento code a Tcl_GetReturnOptions para que todas las opciones requeridas estén presentes en el diccionario. Específicamente, un valor de code de TCL_ERROR asegurará que las entradas para las claves -errorinfo, -errorcode y -errorline aparezcan en el diccionario. Además, las entradas para las claves -code y -level se ajustarán si es necesario para que coincidan con el valor de code. El (Tcl_Obj *) devuelto por Tcl_GetReturnOptions apunta a un Tcl_Obj no compartido con un contador de referencias cero. El diccionario puede modificarse, añadiendo, eliminando o sobrescribiendo cualquier entrada, sin necesidad de comprobar si está compartido. Como con cualquier Tcl_Obj con contador de referencias cero, es responsabilidad del llamante organizar su disposición con Tcl_DecrRefCount o hacer referencia a él a través de Tcl_IncrRefCount (o una de las muchas funciones que la llaman, incluyendo notablemente Tcl_SetObjResult y Tcl_SetVar2Ex).

Un uso típico para Tcl_GetReturnOptions es recuperar el rastreo de la pila cuando la evaluación del script devuelve TCL_ERROR, así:

int code = Tcl_Eval(interp, script);
if (code == TCL_ERROR) {
    Tcl_Obj *options = Tcl_GetReturnOptions(interp, code);
    Tcl_Obj *key = Tcl_NewStringObj("-errorinfo", -1);
    Tcl_Obj *stackTrace;
    Tcl_IncrRefCount(key);
    Tcl_DictObjGet(NULL, options, key, &stackTrace);
    Tcl_DecrRefCount(key);
    /* Haz algo con stackTrace */
    Tcl_DecrRefCount(options);
}

Tcl_SetReturnOptions establece las opciones de retorno de interp a ser options. Si options contiene algún valor inválido para alguna clave, se devolverá TCL_ERROR y el resultado del intérprete se establecerá en un mensaje de error apropiado. De lo contrario, se devolverá un código de finalización coherente con las claves -code y -level en options.

Como ejemplo, el propio comando return de Tcl podría implementarse en términos de Tcl_SetReturnOptions así:

if ((objc % 2) == 0) { /* argumento de resultado explícito */
    objc--;
    Tcl_SetObjResult(interp, objv[objc]);
}
return Tcl_SetReturnOptions(interp, Tcl_NewListObj(objc-1, objv+1));

(En realidad no está implementado de esa manera. Los privilegios de acceso interno permiten una alternativa más eficiente que se integra mejor con el compilador de bytecode.)

Tenga en cuenta que se puede pasar un Tcl_Obj recién creado como argumento options sin necesidad de preocuparse por ningún conteo de referencias. Esto es análogo a Tcl_SetObjResult.

Mientras que Tcl_SetReturnOptions proporciona una interfaz general para establecer cualquier colección de opciones de retorno, hay un puñado de opciones de retorno que se utilizan con mucha frecuencia. La más notable es la opción -errorinfo y -errorcode, que deben establecerse correctamente cuando el procedimiento del comando devuelve TCL_ERROR. La opción -errorline también es leída por los comandos que evalúan scripts y desean proporcionar información detallada de la ubicación del error en el texto del rastreo de la pila que agregan a la opción -errorinfo. Tcl proporciona varias interfaces más simples para establecer estas opciones de retorno de forma más directa.

La opción -errorinfo contiene un rastreo de la pila de las operaciones que estaban en curso cuando ocurrió un error, y está destinada a ser legible por humanos. La opción -errorcode contiene una lista Tcl de elementos destinados a ser legibles por máquinas. El primer elemento en el valor de -errorcode identifica la clase de error que ocurrió (por ejemplo, POSIX significa que ocurrió un error en una llamada al sistema POSIX) y elementos adicionales contienen información adicional que depende de la clase. Consulte la página del manual sobre la variable errorCode para obtener detalles sobre los diversos formatos para la opción -errorcode utilizados por los comandos integrados de Tcl.

El valor de la opción -errorinfo se construye gradualmente a medida que un error se desenrolla a través de las operaciones anidadas. Cada vez que un código de error se devuelve a Tcl_Eval, o a cualquiera de las rutinas que realiza la evaluación de scripts, se llama al procedimiento Tcl_AddErrorInfo para agregar texto adicional al valor -errorinfo que describe el comando que se estaba ejecutando cuando ocurrió el error. Para cuando el error ha sido devuelto completamente a la aplicación, contendrá un rastreo completo de la actividad en curso cuando ocurrió el error.

A veces es útil agregar información adicional al valor -errorinfo más allá de lo que pueden suministrar automáticamente las rutinas de evaluación de scripts. Tcl_AddErrorInfo puede usarse para este propósito: su argumento message es una cadena adicional que se agregará a la opción -errorinfo. Por ejemplo, cuando surge un error durante el comando source, se llama al procedimiento Tcl_AddErrorInfo para registrar el nombre del archivo que se está procesando y el número de línea en el que ocurrió el error. DESCRIPTION

These procedures provide an interface for Tcl extensions to add error information to an interpreter. Error information is stored in the interpreter and can be retrieved by Tcl scripts using the errorInfo and errorCode global variables, or by C code using Tcl_GetVar.

Tcl_AddErrorInfo appends message to the interpreter's -errorinfo return option. The -errorinfo return option is a string that contains a stack trace of Tcl commands and procedures that were active when an error occurred. It typically includes the name of the command or procedure, and the line number within the procedure.

The -errorline return option is also useful. This option holds the line number within the current Tcl procedure where the error occurred. The procedure Tcl_LogCommandInfo is called implicitly by Tcl whenever an error is detected during script execution. It adds information about the command that was being executed when the error occurred to the -errorinfo value, and sets the -errorline value.

The best time to call Tcl_AddErrorInfo is just after a script evaluation routine has returned TCL_ERROR. The value of the -errorline return option (retrieved via a call to Tcl_GetReturnOptions) often makes up a useful part of the message passed to Tcl_AddErrorInfo.

Tcl_AppendObjToErrorInfo is an alternative interface to the same functionality as Tcl_AddErrorInfo. Tcl_AppendObjToErrorInfo is called when the string value to be appended to the -errorinfo option is available as a Tcl_Obj instead of as a char array.

Tcl_AddObjErrorInfo is nearly identical to Tcl_AddErrorInfo, except that it has an additional length argument. This allows the message string to contain embedded null bytes. This is essentially never a good idea. If the message needs to contain the null character U+0000, Tcl's usual internal encoding rules should be used to avoid the need for a null byte. If the Tcl_AddObjErrorInfo interface is used at all, it should be with a negative length value.

The procedure Tcl_SetObjErrorCode is used to set the -errorcode return option to the list value errorObjPtr built up by the caller. Tcl_SetObjErrorCode is typically invoked just before returning an error. If an error is returned without calling Tcl_SetObjErrorCode or Tcl_SetErrorCode the Tcl interpreter automatically sets the -errorcode return option to NONE.

The procedure Tcl_SetErrorCode is also used to set the -errorcode return option. However, it takes one or more strings to record instead of a value. Otherwise, it is similar to Tcl_SetObjErrorCode in behavior.

Tcl_SetErrorCodeVA is the same as Tcl_SetErrorCode except that instead of taking a variable number of arguments it takes an argument list.

The procedure Tcl_GetErrorLine is used to read the integer value of the -errorline return option without the overhead of a full call to Tcl_GetReturnOptions. Likewise, Tcl_SetErrorLine sets the -errorline return option value.

Tcl_PosixError sets the -errorcode variable after an error in a POSIX kernel call. It reads the value of the errno C variable and calls Tcl_SetErrorCode to set the -errorcode return option in the POSIX format. The caller must previously have called Tcl_SetErrno to set errno; this is necessary on some platforms (e.g. Windows) where Tcl is linked into an application as a shared library, or when the error occurs in a dynamically loaded extension. See the manual entry for Tcl_SetErrno for more information.

Tcl_PosixError returns a human-readable diagnostic message for the error (this is the same value that will appear as the third element in the -errorcode value). It may be convenient to include this string as part of the error message returned to the application in the interpreter's result.

Tcl_LogCommandInfo is invoked after an error occurs in an interpreter. It adds information about the command that was being executed when the error occurred to the -errorinfo value, and the line number stored internally in the interpreter is set.

In older releases of Tcl, there was no Tcl_GetReturnOptions routine. In its place, the global Tcl variables errorInfo and errorCode were the only place to retrieve the error information. Much existing code written for older Tcl releases still access this information via those global variables.

It is important to realize that while reading from those global variables remains a supported way to access these return option values, it is important not to assume that writing to those global variables will properly set the corresponding return options. It has long been emphasized in this manual page that it is important to call the procedures described here rather than setting errorInfo or errorCode directly with Tcl_ObjSetVar2.

If the procedure Tcl_ResetResult is called, it clears all of the state of the interpreter associated with script evaluation, including the entire return options dictionary. In particular, the -errorinfo and -errorcode options are reset. If an error had occurred, the Tcl_ResetResult call will clear the error state to make it appear as if no error had occurred after all. The global variables errorInfo and errorCode are not modified by Tcl_ResetResult so they continue to hold a record of information about the most recent error seen in an interpreter.
