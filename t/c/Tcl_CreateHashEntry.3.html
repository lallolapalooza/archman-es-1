ARGUMENTOS

Tcl_HashTable *tablePtr (entrada)
Dirección de la estructura de la tabla hash (para todos los procedimientos excepto Tcl_InitHashTable, esta debe haber sido inicializada por una llamada previa a Tcl_InitHashTable).
int keyType (entrada)
Tipo de claves a utilizar para la nueva tabla hash. Debe ser TCL_STRING_KEYS, TCL_ONE_WORD_KEYS, TCL_CUSTOM_TYPE_KEYS, TCL_CUSTOM_PTR_KEYS, o un valor entero mayor que 1.
Tcl_HashKeyType *typePtr (entrada)
Dirección de la estructura que define el comportamiento de la tabla hash.
const void *key (entrada)
Clave a utilizar para la búsqueda en la tabla. El formato exacto depende del keyType utilizado para crear la tabla.
int *newPtr (salida)
La palabra en *newPtr se establece en 1 si se creó una nueva entrada y 0 si ya existía una entrada para key.
Tcl_HashEntry *entryPtr (entrada)
Puntero a la entrada de la tabla hash.
ClientData value (entrada)
Nuevo valor a asignar a la entrada de la tabla hash. No es necesario que tenga el tipo ClientData, pero debe caber en el mismo espacio que ClientData.
Tcl_HashSearch *searchPtr (entrada)
Puntero al registro a utilizar para realizar un seguimiento del progreso en la enumeración de todas las entradas de una tabla hash.

DESCRIPCIÓN

Una tabla hash consiste en cero o más entradas, cada una formada por una clave y un valor. Dada la clave de una entrada, las rutinas de hash pueden localizar muy rápidamente la entrada y, por lo tanto, su valor. Puede haber como máximo una entrada en una tabla hash con una clave particular, pero muchas entradas pueden tener el mismo valor. Las claves pueden tener uno de cuatro formatos: cadenas, valores de una palabra, arrays de enteros o claves personalizadas definidas por una estructura Tcl_HashKeyType (Ver sección LA ESTRUCTURA TCL_HASHKEYTYPE a continuación). Todas las claves de una tabla dada tienen el mismo formato, que se especifica al inicializar la tabla.

El valor de una entrada de tabla hash puede ser cualquier cosa que quepa en el mismo espacio que un puntero de tipo “char *”. Los valores de las entradas de la tabla hash son gestionados completamente por los clientes, no por el propio módulo de hash. Normalmente, el valor de cada entrada es un puntero a una estructura de datos gestionada por el código del cliente.

Las tablas hash crecen de forma flexible a medida que aumenta el número de entradas, de modo que siempre haya menos de tres entradas por cubo de hash, en promedio. Esto permite búsquedas rápidas independientemente del número de entradas de una tabla.

El núcleo proporciona tres funciones para la inicialización de tablas hash: Tcl_InitHashTable, Tcl_InitObjHashTable y Tcl_InitCustomHashTable.

Tcl_InitHashTable inicializa una estructura que describe una nueva tabla hash. El espacio para la estructura lo proporciona el llamador, no el módulo de hash. El valor de keyType indica qué tipos de claves se utilizarán para todas las entradas de la tabla. Se permiten todos los tipos de claves descritos más adelante, con la excepción de TCL_CUSTOM_TYPE_KEYS y TCL_CUSTOM_PTR_KEYS.

Tcl_InitObjHashTable es un envoltorio alrededor de Tcl_InitCustomHashTable e inicializa una tabla hash cuyas claves son Tcl_Obj *.

Tcl_InitCustomHashTable inicializa una estructura que describe una nueva tabla hash. El espacio para la estructura lo proporciona el llamador, no el módulo de hash. El valor de keyType indica qué tipos de claves se utilizarán para todas las entradas de la tabla. keyType debe tener uno de los siguientes valores:

TCL_STRING_KEYS
Las claves son cadenas terminadas en nulo. Se pasan a las rutinas de hash utilizando la dirección del primer carácter de la cadena.
TCL_ONE_WORD_KEYS
Las claves son valores de una sola palabra; se pasan a las rutinas de hash y se almacenan en las entradas de la tabla hash como valores “char *”. El valor del puntero es la clave; no es necesario (y normalmente no lo es) que apunte realmente a una cadena.
TCL_CUSTOM_TYPE_KEYS
Las claves son de tipo arbitrario y se almacenan en la entrada. El hash y la comparación se determinan mediante typePtr. La estructura Tcl_HashKeyType se describe en la sección LA ESTRUCTURA TCL_HASHKEYTYPE a continuación.
TCL_CUSTOM_PTR_KEYS
Las claves son punteros a un tipo arbitrario y se almacenan en la entrada. El hash y la comparación se determinan mediante typePtr. La estructura Tcl_HashKeyType se describe en la sección LA ESTRUCTURA TCL_HASHKEYTYPE a continuación.
otro
Si keyType no es una de las anteriores, entonces debe ser un valor entero mayor que 1. En este caso, las claves serán arrays de valores “int”, donde keyType indica el número de enteros en cada clave. Esto permite utilizar estructuras como claves. Todas las claves deben tener el mismo tamaño. Las claves de array se pasan a las funciones de hash utilizando la dirección del primer int del array.

Tcl_DeleteHashTable elimina todas las entradas de una tabla hash y libera la memoria asociada con el array de cubos de la tabla y las entradas. No libera la estructura de la tabla en sí (apuntada por tablePtr), ya que se asume que el cliente gestiona esa memoria. Tcl_DeleteHashTable tampoco libera ni manipula de ninguna otra forma los valores de las entradas de la tabla hash. Si los valores de las entradas apuntan a memoria asignada dinámicamente, es responsabilidad del cliente liberar esas estructuras antes de eliminar la tabla.

Tcl_CreateHashEntry localiza la entrada correspondiente a una clave particular, creando una nueva entrada en la tabla si aún no existía una con la clave dada. Si ya existía una entrada con la clave dada, entonces *newPtr se establece en cero. Si se creó una nueva entrada, entonces *newPtr se establece en un valor distinto de cero y el valor de la nueva entrada se establecerá en cero. El valor de retorno de Tcl_CreateHashEntry es un puntero a la entrada, que puede utilizarse para recuperar y modificar el valor de la entrada o para eliminar la entrada de la tabla.

Tcl_DeleteHashEntry eliminará una entrada existente de una tabla. Se liberará la memoria asociada a la entrada en sí, pero el cliente es responsable de cualquier limpieza asociada al valor de la entrada, como la liberación de una estructura a la que apunte.

Tcl_FindHashEntry es similar a Tcl_CreateHashEntry excepto que no crea una nueva entrada si la clave no existe; en su lugar, devuelve NULL como resultado.

Tcl_GetHashValue y Tcl_SetHashValue se utilizan para leer y escribir el valor de una entrada, respectivamente. Los valores se almacenan y se recuperan como tipo “ClientData”, que es lo suficientemente grande como para contener un valor de puntero. En casi todas las máquinas, esto es lo suficientemente grande como para contener también un valor entero.

Tcl_GetHashKey devuelve la clave de una entrada dada de la tabla hash, ya sea como un puntero a una cadena, una clave de una palabra (“char *”), o como un puntero a la primera palabra de un array de enteros, dependiendo del keyType utilizado para crear la tabla hash. En todos los casos Tcl_GetHashKey devuelve un resultado de tipo “char *”. Cuando la clave es una cadena o un array, el resultado de Tcl_GetHashKey apunta a información en la entrada de la tabla; esta información seguirá siendo válida hasta que la entrada se elimine o su tabla se elimine.

Tcl_FirstHashEntry y Tcl_NextHashEntry se pueden utilizar para recorrer todas las entradas de una tabla hash

typedef struct Tcl_HashTable {
    int numEntries;
    Tcl_HashKeyType *typePtr;
    Tcl_HashEntry *bucketNextPtr;
    Tcl_HashEntry **buckets;
    int numBuckets;
} Tcl_HashTable;

typedef struct Tcl_HashEntry {
    Tcl_HashEntry *nextPtr;
    void *clientData;
    union {
        int oneWordValue;
        int intValue;
        long longValue;
        double doubleValue;
        Tcl_Obj *objValuePtr;
        char *stringValuePtr;
        void *ptrValue;
    } value;
    int id;
} Tcl_HashEntry;

typedef struct Tcl_HashSearch {
    Tcl_HashEntry *nextPtr;
    Tcl_HashEntry *bucketPtr;
} Tcl_HashSearch;

ARGUMENTS

tablePtr
A pointer to a Tcl_HashTable structure to be used for the hash table. This structure will be initialized by the routine.
type
An integer specifying the type of keys used in the hash table. Legal values are TCL_STRING_KEYS, TCL_ONE_WORD_KEYS, TCL_CUSTOM_KEYS. See Tcl_InitCustomHashTable for more details.
typePtr
A pointer to a Tcl_HashKeyType structure which defines the hashing algorithm and other information for a custom key type. This is only used when type is TCL_CUSTOM_KEYS.
hPtr
A pointer to a Tcl_HashEntry structure that identifies an entry in the hash table.
keyPtr
A pointer to the key for the hash table entry. The type of the key depends on the type argument passed to Tcl_InitHashTable.
newValuePtr
A pointer to the value to be associated with the key. If TCL_INTEGER_KEYS or TCL_ONE_WORD_KEYS were used then this value will be stored in the oneWordValue or intValue field of the hash entry. If TCL_STRING_KEYS was used, this will be stored in stringValuePtr. If TCL_OBJ_KEYS was used, this will be stored in objValuePtr. If TCL_CUSTOM_KEYS was used, it is up to the custom key type to interpret this value.
searchPtr
A pointer to a Tcl_HashSearch structure used to keep track of progress through the hash table.

DESCRIPTION

These routines provide a general-purpose hash table implementation. The hash table itself is stored in a structure of type Tcl_HashTable. Each entry in the table is stored in a structure of type Tcl_HashEntry. The key and client data are stored in the entry. The key is typically a pointer to a string or an integer, and the client data is a void pointer. The specific types of keys and values supported depend on the type specified when the table is initialized.

Tcl_InitHashTable initializes the hash table structure pointed to by tablePtr. The type argument specifies the type of keys that will be used in the hash table. Legal values are:

TCL_STRING_KEYS
Keys are pointers to null-terminated strings. The strings are copied by the hashing routines, so the caller is free to modify or free the original string after calling Tcl_CreateHashEntry.
TCL_ONE_WORD_KEYS
Keys are pointers to values that fit in a single word (e.g., integers, pointers). The key value is copied by the hashing routines.
TCL_INTEGER_KEYS
Similar to TCL_ONE_WORD_KEYS, but the key is treated as an integer. This is useful for hashing integer keys.
TCL_OBJ_KEYS
Keys are pointers to Tcl_Obj objects. The object reference count is incremented by the hashing routines.
TCL_CUSTOM_KEYS
Keys are of a custom type defined by the caller. The behavior of the hash table is determined by the Tcl_HashKeyType structure passed to Tcl_InitCustomHashTable.

Tcl_InitCustomHashTable is similar to Tcl_InitHashTable, but allows the caller to specify a custom key type through the typePtr argument. This provides maximum flexibility for defining hash table behavior.

Tcl_DeleteHashTable frees all memory associated with the hash table, including all entries and keys. The Tcl_HashTable structure itself is not freed.

Tcl_CreateHashEntry creates a new entry in the hash table. It computes the hash of the key, finds the appropriate bucket, and inserts a new entry. If an entry with the same key already exists, the old entry is returned and the new value is ignored. If newValuePtr is NULL, the new entry will have a NULL clientData. Otherwise, the client data is set to newValuePtr. The function returns a pointer to the new or existing hash entry.

Tcl_DeleteHashEntry deletes the entry identified by hPtr from the hash table. The memory associated with the entry (including the key if it was copied) is freed.

Tcl_FindHashEntry searches the hash table for an entry with the key specified by keyPtr. If found, it returns a pointer to the entry; otherwise, it returns NULL.

The routines Tcl_FirstHashEntry and Tcl_NextHashEntry can be used to iterate through all the entries in a hash table. A structure of type Tcl_HashSearch, provided by the client, is used to keep track of progress through the table. Tcl_FirstHashEntry initializes the search record and returns the first entry in the table (or NULL if the table is empty). Each subsequent call to Tcl_NextHashEntry returns the next entry in the table or NULL if the end of the table has been reached. A call to Tcl_FirstHashEntry followed by calls to Tcl_NextHashEntry will return each of the entries in the table exactly once, in an arbitrary order. It is inadvisable to modify the structure of the table, e.g. by creating or deleting entries, while the search is in progress, with the exception of deleting the entry returned by Tcl_FirstHashEntry or Tcl_NextHashEntry.

Tcl_HashStats returns a dynamically-allocated string with overall information about a hash table, such as the number of entries it contains, the number of buckets in its hash array, and the utilization of the buckets. It is the caller's responsibility to free the result string by passing it to ckfree.

The header file tcl.h defines the actual data structures used to implement hash tables. This is necessary so that clients can allocate Tcl_HashTable structures and so that macros can be used to read and write the values of entries. However, users of the hashing routines should never refer directly to any of the fields of any of the hash-related data structures; use the procedures and macros defined here.

THE TCL_HASHKEYTYPE STRUCTURE

Extension writers can define new hash key types by defining four procedures, initializing a Tcl_HashKeyType structure to describe the type, and calling Tcl_InitCustomHashTable. The Tcl_HashKeyType structure is defined as follows:

typedef struct Tcl_HashKeyType {
    int version;
    int flags;
    Tcl_HashKeyProc *hashKeyProc;
    Tcl_CompareHashKeysProc *compareKeysProc;
    Tcl_AllocHashEntryProc *allocEntryProc;
    Tcl_FreeHashEntryProc *freeEntryProc;
} Tcl_HashKeyType;

The version member is the version of the table. If this structure is extended in future then the version can be used to distinguish between different structures. It should be set to TCL_HASH_KEY_TYPE_VERSION.

The flags member is 0 or one or more of the following values OR'ed together:

TCL_HASH_KEY_RANDOMIZE_HASH
There are some things, pointers for example which do not hash well because they do not use the lower bits. If this flag is set then the hash table will attempt to rectify this by randomizing the bits and then using the upper N bits as the index into the table.
TCL_HASH_KEY_SYSTEM_HASH
This flag forces Tcl to use the memory allocation procedures provided by the operating system when allocating and freeing memory used to store the hash table data structures, and not any of Tcl's own customized memory allocation routines. This is important if the hash table is to be used in the implementation of a custom set of allocation routines, or something that a custom set of allocation routines might depend on, in order to avoid any circular dependency.

The hashKeyProc member contains the address of a function called to calculate a hash value for the key.

typedef unsigned int Tcl_HashKeyProc(
        Tcl_HashTable *tablePtr,
        void *keyPtr);

If this is NULL then keyPtr is used and TCL_HASH_KEY_RANDOMIZE_HASH is assumed.

The compareKeysProc member contains the address of a function called to compare two keys.

typedef int Tcl_CompareHashKeysProc(
        void *keyPtr,
        Tcl_HashEntry *hPtr);

If this is NULL then the keyPtr pointers are compared. If the keys do not match then the function returns 0, otherwise it returns 1.

The allocEntryProc member contains the address of a function called to allocate space for an entry and initialize the key and clientData.

typedef Tcl_HashEntry *Tcl_AllocHashEntryProc(
        Tcl_HashTable *tablePtr,
        void *keyPtr);

If this is NULL then Tcl_Alloc is used to allocate enough space for a Tcl_HashEntry, the key pointer is assigned to key.oneWordValue and the clientData is set to NULL. String keys and array keys use this function to allocate enough space for the entry and the key in one block, rather than doing it in two blocks. This saves space for a pointer to the key from the entry and another memory allocation. Tcl_Obj* keys use this function to allocate enough space for an entry and increment the reference count on the value.

The freeEntryProc member contains the address of a function called to free space for an entry.

typedef void Tcl_FreeHashEntryProc(
        Tcl_HashEntry *hPtr);

If this is NULL then Tcl_Free is used to free the space for the entry. Tcl_Obj* keys use this function to decrement the reference count on the value.
