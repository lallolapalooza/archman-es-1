DESCRIPCIÓN

Los objetos son entidades tipadas que tienen un conjunto de operaciones ("métodos") asociadas con ellas. Las clases son objetos que pueden fabricar objetos. Cada clase puede verse como un objeto en sí misma; la vista de objeto puede obtenerse usando Tcl_GetClassAsObject que siempre devuelve el objeto cuando se aplica a una clase no destruida, y un objeto puede verse como una clase con la ayuda de Tcl_GetObjectAsClass (que devuelve la clase, o NULL si el objeto no es una clase). Un objeto puede buscarse usando la función Tcl_GetObjectFromObj, que devuelve un objeto o NULL (con un mensaje de error en el resultado del intérprete) si el objeto no puede encontrarse. La forma correcta de buscar una clase por nombre es buscar el objeto con ese nombre y luego usar Tcl_GetObjectAsClass.

Cada objeto tiene su propio comando y espacio de nombres asociados. El comando puede ser recuperado usando la función Tcl_GetObjectCommand, el nombre del objeto (y por lo tanto el nombre del comando) con Tcl_GetObjectName, y el espacio de nombres puede ser recuperado con la función Tcl_GetObjectNamespace. Debe notarse que la referencia de objeto devuelta por Tcl_GetObjectName es una referencia compartida. También puedes obtener si el objeto ha sido marcado para eliminación con Tcl_ObjectDeleted (devuelve verdadero si la eliminación del objeto ha comenzado); esto puede ser útil durante el procesamiento de métodos.

Las instancias de clases se crean usando Tcl_NewObjectInstance, que crea un objeto de cualquier clase (y que se llama internamente por ambos métodos create y new de la clase oo::class). Toma parámetros que opcionalmente dan el nombre del objeto y el espacio de nombres a crear, y que describen los argumentos a pasar al constructor de la clase (si los hay). El resultado de la función será o bien una referencia al objeto creado, o NULL si la creación falló (cuando se dejará un mensaje de error en el resultado del intérprete). Además, los objetos pueden ser copiados usando Tcl_CopyObjectInstance que crea una copia de un objeto sin ejecutar ningún constructor.

Nota: El manejo de la vida útil de los objetos es gestionado internamente por TclOO y no utiliza Tcl_Preserve. No es seguro colocar un Tcl_Object en una estructura C con una vida útil diferente a la del objeto; debes usar el nombre del comando del objeto (obtenido con Tcl_GetObjectName) en su lugar. Es seguro usar un Tcl_Object durante la vida de una llamada de método en ese objeto; los manejadores no se vuelven inválidos mientras haya una llamada de método en su objeto (incluso si la única operación garantizada para ser segura en ellos es Tcl_ObjectDeleted; las otras operaciones solo se garantizan que funcionen en objetos no eliminados).

METADATOS DE OBJETO Y CLASE

Cada objeto y cada clase pueden tener un conjunto arbitrario de metadatos adjuntos a ellos, que el objeto o la clase no interpretan más allá de lo descrito en un instanciador de estructura Tcl_ObjectMetadataType. Los metadatos que se adjuntan se describen por el tipo de metadatos (dado en el argumento metaTypePtr) y un puntero arbitrario (el argumento metadata) que se dan a Tcl_ObjectSetMetadata y Tcl_ClassSetMetadata, y un dato específico de metadatos puede ser recuperado según su tipo usando Tcl_ObjectGetMetadata y Tcl_ClassGetMetadata. Si el parámetro metadata a Tcl_ObjectSetMetadata o Tcl_ClassSetMetadata es NULL, los metadatos se eliminan si estaban adjuntos, y los resultados de Tcl_ObjectGetMetadata y Tcl_ClassGetMetadata serán NULL si el tipo de metadatos dado no estaba adjuntado. No es un error solicitar o eliminar datos de metadatos que no estaban adjuntos.

Estructura TCL_OBJECTMETADATATYPE

Los contenidos de la estructura Tcl_ObjectMetadataType son los siguientes:

typedef const struct {
    int version;
    const char *name;
    Tcl_ObjectMetadataDeleteProc *deleteProc;
    Tcl_CloneProc *cloneProc;
} Tcl_ObjectMetadataType;

El campo version permite la expansión futura de la estructura, y debe ser declarado siempre igual a TCL_OO_METADATA_VERSION_CURRENT. El campo name proporciona un nombre legible por humanos para el tipo, y se reserva para depuración.

El campo deleteProc da una función de tipo Tcl_ObjectMetadataDeleteProc que se usa para eliminar datos específicos de metadatos, y se llama cuando los metadatos adjuntos se reemplazan o se eliminan; el campo no puede ser NULL.

El campo cloneProc da una función que se usa para copiar datos de metadatos (usado cuando se crea una copia de un objeto con Tcl_CopyObjectInstance); si es NULL, los metadatos se copiarán directamente.

NAME

Tcl_ObjectSetMetadata, Tcl_ObjectGetMetadata, Tcl_ObjectDeleteMetadata, Tcl_CloneProc, Tcl_ObjectMapMethodNameProc - manipulate object-specific metadata

SYNOPSIS

#include <tclOO.h>

int
Tcl_ObjectSetMetadata(
        Tcl_Interp *interp,
        Tcl_Object object,
        const char *key,
        Tcl_Obj *value);

Tcl_Obj *
Tcl_ObjectGetMetadata(
        Tcl_Object object,
        const char *key);

int
Tcl_ObjectDeleteMetadata(
        Tcl_Interp *interp,
        Tcl_Object object,
        const char *key);

typedef int
    (*Tcl_CloneProc)(
        Tcl_Interp *interp,
        ClientData srcMetadata,
        ClientData *dstMetadataPtr);

typedef int
    (*Tcl_ObjectMapMethodNameProc)(
        Tcl_Interp *interp,
        Tcl_Object object,
        Tcl_Class *startClsPtr,
        Tcl_Obj *methodNameObj);

ARGUMENTS

Tcl_Interp *interp
Interpreter to use for error reporting.
Tcl_Object object
The object to operate on.
const char *key
The key for the metadata.
Tcl_Obj *value
The value for the metadata.
ClientData srcMetadata
The metadata to be cloned.
ClientData *dstMetadataPtr
Pointer to where the cloned metadata should be written.

DESCRIPTION

The TclOO object system supports attaching arbitrary metadata to objects, keyed by strings. The metadata is intended to be associated with the object itself, and not with its class or instance, although it may be accessed via Tcl_ObjectGetMetadata calls on the object. When an object is created using Tcl_ObjectNew, it has no metadata associated with it. Metadata may be added using Tcl_ObjectSetMetadata.

When an object is cloned using Tcl_ObjectNew, any metadata associated with the source object is also cloned. This is done via a callback procedure, a Tcl_CloneProc. If no such procedure is registered for the object's class, no metadata is cloned. The procedure is invoked once for each piece of metadata attached to the source object. If the procedure returns TCL_OK, the new metadata is written into the variable pointed to by dstMetadataPtr. If the procedure returns TCL_ERROR, an error message is left in interp, and the object cloning fails. If the procedure returns TCL_BREAK, the metadata is not cloned, but the object cloning proceeds. The default implementation of Tcl_ObjectSetMetadata copies the value object.

When an object is destroyed using Tcl_ObjectDelete, any associated metadata is also destroyed. This is done via a callback procedure, a Tcl_ObjectDeleteProc. If no such procedure is registered for the object's class, no metadata is destroyed. The procedure is invoked once for each piece of metadata attached to the source object.

Metadata can be retrieved using Tcl_ObjectGetMetadata. This function returns a pointer to the Tcl value associated with the given key. The caller should not modify the returned value, and should use Tcl_DecrRefCount when done with it.

Metadata can be deleted using Tcl_ObjectDeleteMetadata. This function removes the metadata associated with the given key from the object. The associated value object is disposed of using Tcl_DecrRefCount.

TCL_CLONEPROC FUNCTION SIGNATURE

Functions matching this signature are used to create copies of metadata associated with a class or object.

typedef int Tcl_CloneProc(
        Tcl_Interp *interp,
        ClientData srcMetadata,
        ClientData *dstMetadataPtr);

The interp argument gives a place to write an error message when the attempt to clone the object is to fail, in which case the clone procedure must also return TCL_ERROR; it should return TCL_OK otherwise. The srcMetadata argument gives the address of the metadata to be cloned, and the cloned metadata should be written into the variable pointed to by dstMetadataPtr; a NULL should be written if the metadata is to not be cloned but the overall object copy operation is still to succeed.

OBJECT METHOD NAME MAPPING

It is possible to control, on a per-object basis, what methods are invoked when a particular method is invoked. Normally this is done by looking up the method name in the object and then in the class hierarchy, but fine control of exactly what the value used to perform the look up is afforded through the ability to set a method name mapper callback via Tcl_ObjectSetMethodNameMapper (and its introspection counterpart, Tcl_ObjectGetMethodNameMapper, which returns the current mapper). The current mapper (if any) is invoked immediately before looking up what chain of method implementations is to be used.

TCL_OBJECTMAPMETHODNAMEPROC FUNCTION SIGNATURE

The Tcl_ObjectMapMethodNameProc callback is defined as follows:

typedef int Tcl_ObjectMapMethodNameProc(
        Tcl_Interp *interp,
        Tcl_Object object,
        Tcl_Class *startClsPtr,
        Tcl_Obj *methodNameObj);

If the result is TCL_OK, the remapping is assumed to have been done. If the result is TCL_ERROR, an error message will have been left in interp and the method call will fail. If the result is TCL_BREAK, the standard method name lookup rules will be used; the behavior of other result codes is currently undefined. The object parameter says which object is being processed. The startClsPtr parameter points to a variable that contains the first class to provide a definition in the method chain to process, or NULL if the whole chain is to be processed (the argument itself is never NULL); this variable may be updated by the callback. The methodNameObj parameter gives an unshared object containing the name of the method being invoked, as provided by the user; this object may be updated by the callback.
