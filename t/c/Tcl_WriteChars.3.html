ARGUMENTOS

Tcl_Interp *interp (entrada)
Se utiliza para la notificación de errores y para buscar un canal registrado en él.
const char *fileName (entrada)
El nombre de un archivo local o de red.
const char *mode (entrada)
Especifica cómo se debe acceder al archivo. Puede tener cualquiera de los valores permitidos para el argumento mode del comando Tcl open.
int permissions (entrada)
Indicadores de permisos estilo POSIX, como 0644. Si se crea un archivo nuevo, estos permisos se aplicarán al archivo creado.
int argc (entrada)
El número de elementos en argv.
const char **argv (entrada)
Argumentos para construir una tubería de comandos. Estos valores tienen el mismo significado que los argumentos sin interruptor del comando Tcl exec.
int flags (entrada)
Especifica la disposición de los manejadores stdio en la tubería: combinación OR de TCL_STDIN, TCL_STDOUT, TCL_STDERR y TCL_ENFORCE_MODE. Si se establece TCL_STDIN, la entrada estándar del primer hijo en la tubería es el canal de la tubería, de lo contrario es la misma que la entrada estándar del proceso invocador; lo mismo para TCL_STDOUT y TCL_STDERR. Si no se establece TCL_ENFORCE_MODE, entonces la tubería puede redirigir los manejadores stdio para anular los manejadores stdio para los que se han establecido TCL_STDIN, TCL_STDOUT y TCL_STDERR. Si está establecido, dichas redirecciones causan un error.
ClientData handle (entrada)
Manejador específico del sistema operativo para E/S a un archivo. Para Unix, es un descriptor de archivo, para Windows es un HANDLE.
int readOrWrite (entrada)
Combinación OR de TCL_READABLE y TCL_WRITABLE para indicar qué operaciones son válidas en handle.
const char *channelName (entrada)
El nombre del canal.
int *modePtr (salida)
Punta a una variable entera que recibirá una combinación OR de TCL_READABLE y TCL_WRITABLE indicando si el canal está abierto para lectura y escritura.
const char *pattern (entrada)
El patrón a comparar, pasado a Tcl_StringMatch, o NULL.
Tcl_Channel channel (entrada)
Un canal Tcl para entrada o salida. Debe haber sido el valor de retorno de un procedimiento como Tcl_OpenFileChannel.
Tcl_Obj *readObjPtr (entrada/salida)
Un puntero a un valor Tcl en el que se almacenarán los caracteres leídos del canal.
int charsToRead (entrada)
El número de caracteres a leer del canal. Si la codificación del canal es binary, esto es equivalente al número de bytes a leer del canal.
int appendFlag (entrada)
Si es distinto de cero, los datos leídos del canal se añadirán al valor. De lo contrario, los datos reemplazarán el contenido existente del valor.
char *readBuf (salida)
Un búfer en el que se almacenarán los bytes leídos del canal.
int bytesToRead (entrada)
El número de bytes a leer del canal. El búfer readBuf debe ser lo suficientemente grande para contener esta cantidad de bytes.
Tcl_Obj *lineObjPtr (entrada/salida)
Un puntero a un valor Tcl en el que se almacenará la línea leída del canal. La línea leída se añadirá al valor actual del valor.
Tcl_DString *lineRead (entrada/salida)
Un puntero a una cadena dinámica Tcl en la que se almacenará la línea leída del canal. Debe haber sido inicializada por el llamador. La línea leída se añadirá a cualquier dato que ya esté en la cadena dinámica.
const char *input (entrada)
La entrada a añadir a un búfer de canal.
int inputLen (entrada)
Longitud de la entrada.
int addAtEnd (entrada)
Indicador que especifica si la entrada debe añadirse al final o al principio del búfer del canal.
Tcl_Obj *writeObjPtr (entrada)
Un puntero a un valor Tcl cuyo contenido se enviará al canal.
const char *charBuf (entrada)
Un búfer que contiene los caracteres a enviar al canal.
const char *byteBuf (entrada)
Un búfer que contiene los bytes a enviar al canal.
int bytesToWrite (entrada)
El número de bytes a consumir de charBuf o byteBuf y enviar al canal.
Tcl_WideInt offset (entrada)
A qué distancia mover el punto de acceso en el canal en el que se aplicará la próxima operación de entrada o salida, medido en bytes desde la posición dada por seekMode. Puede ser positivo o negativo.
int seekMode (entrada)
Desde qué punto buscar; se utiliza con offset para calcular el nuevo punto de acceso para el canal. Los valores legales son SEEK_SET, SEEK_CUR y SEEK_END.
Tcl_WideInt length (entrada)
La longitud (no negativa) a la que truncar el canal.
const char *optionName (entrada)
El nombre de una opción aplicable a este canal, como -blocking. Puede tener cualquiera de los valores aceptados por el comando fconfigure.
Tcl_DString *optionValue (entrada)
Dónde almacenar el valor de una opción o una lista de todas las opciones y sus valores. Debe haber sido inicializado por el llamador.
const char *newValue (entrada)
Nuevo valor para la opción dada por optionName.

DESCRIPCIÓN

El mecanismo de canales Tcl proporciona un mecanismo independiente del dispositivo y de la plataforma para realizar operaciones de entrada y salida con búferes en una variedad de tipos de archivos, sockets y dispositivos. El mecanismo de canales es extensible a nuevos tipos de canales, proporcionando un controlador de canal de bajo nivel para el nuevo tipo; la interfaz del controlador de canal se describe en la entrada del manual de Tcl_CreateChannel. El mecanismo de canales proporciona un esquema de búfer modelado según la E/S estándar de Unix, y también permite E/S no bloqueante en los canales.

Los procedimientos descritos en esta entrada del manual comprenden las APIs de C de la capa genérica de la arquitectura de canales. Para una descripción de la arquitectura del controlador de canales y cómo implementar controladores de canales para nuevos tipos de canales, consulte la entrada del manual de Tcl_CreateChannel.

TCL_OPENFILECHANNEL

Tcl_OpenFileChannel abre un archivo o dispositivo especificado por fileName y devuelve un canal Tcl que puede usarse para E/S. El argumento mode especifica cómo se abre el archivo (por ejemplo, "r" para lectura, "w" para escritura, "r+" para lectura y escritura). El argumento permissions se utiliza para establecer los permisos del archivo si se crea uno nuevo; las entradas del sistema operativo, como open(2), pueden modificar estos permisos.

El valor de retorno es un manejador de canal Tcl, o NULL si ocurrió un error. Si se devuelve NULL, la información del error se puede encontrar en el campo result del intérprete.

TCL_OPENCOMMANDCHANNEL

Tcl_OpenCommandChannel crea un canal Tcl que se vincula a una tubería de procesos. Los argumentos argc y argv especifican el comando y sus argumentos para el primer proceso en la tubería. El argumento flags controla cómo se manejan los manejadores estándar (stdin, stdout, stderr) para el primer proceso en la tubería. Consulte la sección de argumentos para obtener más detalles.

El valor de retorno es un manejador de canal Tcl, o NULL si ocurrió un error.

TCL_MAKEFILECHANNEL

Tcl_MakeFileChannel crea un canal Tcl a partir de un manejador de archivo existente, como un descriptor de archivo de Unix o un HANDLE de Windows. El argumento readOrWrite indica si el manejador está abierto para lectura, escritura o ambos. Este procedimiento es útil para convertir manejadores de archivos preexistentes (por ejemplo, los abiertos por el comando Tcl open) en canales Tcl gestionados por el sistema de canales.

El valor de retorno es un manejador de canal Tcl, o NULL si ocurrió un error.

TCL_GETCHANNEL

Tcl_GetChannel recupera un canal Tcl existente registrado en el intérprete interp con el nombre channelName. Si modePtr no es NULL, entonces se escribe en el entero al que apunta una combinación OR de TCL_READABLE y TCL_WRITABLE para indicar la dirección del canal.

El valor de retorno es el canal Tcl si se encuentra, o NULL si no se encuentra o si el nombre del canal está prohibido.

TCL_GETCHANNELNAMES

Tcl_GetChannelNames crea una lista de todos los nombres de canales actualmente registrados en el intérprete interp y la almacena en el campo result del intérprete. El valor de retorno es el número de nombres de canales en la lista (que puede ser 0 si no hay canales), o -1 si se produjo un error.

Tcl_GetChannelNamesEx hace lo mismo, pero solo devuelve los nombres de canales que coinciden con el pattern proporcionado, usando la correspondencia de cadenas Tcl estándar.

TCL_REGISTERCHANNEL

Tcl_RegisterChannel registra un canal Tcl existente, channel, con el intérprete interp. Esto hace que el canal sea accesible a través de su nombre de canal. El nombre del canal se puede obtener usando Tcl_GetChannelName.

TCL_UNREGISTERCHANNEL

Tcl_UnregisterChannel elimina un canal Tcl registrado del intérprete interp. El canal ya no será accesible por su nombre. Si el canal está abierto, no se cerrará; sin embargo, cualquier intento posterior de acceder a él por su nombre fallará.

El valor de retorno es 1 si el canal se eliminó correctamente, o 0 si el canal no estaba registrado en el intérprete.

TCL_DETACHCHANNEL

Tcl_DetachChannel desvincula un canal de un intérprete Tcl. El canal se puede volver a adjuntar más tarde usando Tcl_AttachChannel. Esto es útil cuando se desea mover un canal de un intérprete Tcl a otro.

El valor de retorno es 1 si el canal se desvinculó correctamente, o 0 si el canal no estaba registrado en el intérprete.

TCL_ISTANDARDCHANNEL

Tcl_IsStandardChannel devuelve 1 si el channel proporcionado es uno de los canales estándar (entrada, salida o error estándar), o 0 en caso contrario.

TCL_CLOSE

Tcl_Close cierra un canal Tcl abierto. Si el canal está asociado con un archivo, la operación de cierre del sistema operativo se realiza en el archivo. Cualquier búfer asociado con el canal se vacía antes de cerrar el canal. Después de llamar a Tcl_Close, el canal ya no es válido y no se debe utilizar.

El valor de retorno es 0 si el cierre fue exitoso, o -1 si ocurrió un error (por ejemplo, un error de escritura al vaciar el búfer). Si se produce un error, se puede encontrar información adicional en el campo result del intérprete.

TCL_READCHARS

Tcl_ReadChars lee hasta charsToRead caracteres del canal channel y almacena el resultado en el objeto Tcl apuntado por readObjPtr. Si appendFlag es distinto de cero, los caracteres leídos se añaden al valor existente en readObjPtr. De lo contrario, el valor existente en readObjPtr se borra y se reemplaza con los caracteres leídos. El número de caracteres realmente leídos se devuelve en el campo result del intérprete.

Los caracteres se leen según la codificación del canal. Si el canal está en modo binario, entonces charsToRead especifica el número de bytes a leer.

El valor de retorno es el número de caracteres leídos, o -1 si ocurrió un error. Si se produce un error de E/S, se puede encontrar información adicional en el campo result del intérprete. Si se alcanza el final del archivo, el valor de retorno puede ser menor que charsToRead.

TCL_READ

Tcl_Read lee hasta bytesToRead bytes sin procesar del canal channel y los almacena en el búfer readBuf. El número de bytes realmente leídos se devuelve como el valor de retorno. Este procedimiento no realiza ninguna decodificación basada en la codificación del canal; lee los bytes brutos directamente del canal.

El valor de retorno es el número de bytes leídos, o -1 si ocurrió un error. Si se produce un error de E/S, se puede encontrar información adicional en el campo result del intérprete. Si se alcanza el final del archivo, el valor de retorno puede ser menor que bytesToRead.

TCL_GETSOBJ

Tcl_GetsObj lee una línea del canal channel y la almacena en el objeto Tcl apuntado por lineObjPtr. La línea leída incluye el carácter de nueva línea final, si está presente. Si se alcanza el final del archivo antes de leer algún carácter, se devuelve un valor de retorno de 0 y el objeto Tcl no se modifica. Si ocurre un error de E/S, se devuelve -1 y se registra la información del error en el campo result del intérprete.

Esta función es la contraparte orientada a objetos de Tcl_Gets.

TCL_GETS

Tcl_Gets lee una línea del canal channel y la almacena en la cadena dinámica Tcl apuntada por lineRead. La línea leída incluye el carácter de nueva línea final, si está presente. Si se alcanza el final del archivo antes de leer algún carácter, se devuelve un valor de retorno de 0 y la cadena dinámica no se modifica. Si ocurre un error de E/S, se devuelve -1 y se registra la información del error en el campo result del intérprete.

Esta función es la contraparte heredada de Tcl_GetsObj.

TCL_UNGETS

Tcl_Ungets inserta la cadena de entrada input de longitud inputLen en el búfer de entrada del canal channel. Si addAtEnd es 0, la entrada se inserta al principio del búfer de entrada, lo que hace que se lea antes de cualquier dato que ya esté en el búfer. Si addAtEnd es distinto de cero, la entrada se añade al final del búfer de entrada.

El valor de retorno es 0 si la operación fue exitosa, o -1 si ocurrió un error.

TCL_WRITEOBJ

Tcl_WriteObj escribe el contenido del objeto Tcl apuntado por writeObjPtr en el canal channel. La escritura se realiza de acuerdo con la codificación del canal. Si el canal está en modo binario, el objeto Tcl se trata como una secuencia de bytes.

El valor de retorno es el número de bytes (o caracteres, si el canal no está en modo binario) escritos en el canal, o -1 si ocurrió un error. Si se produce un error de E/S, se puede encontrar información adicional en el campo result del intérprete.

TCL_WRITECHARS

Tcl_WriteChars escribe hasta bytesToWrite caracteres del búfer charBuf en el canal channel. Los caracteres se escriben según la codificación del canal. Si el canal está en modo binario, este procedimiento escribe los bytes brutos directamente en el canal. El número de caracteres (o bytes) realmente escritos se devuelve como el valor de retorno.

El valor de retorno es el número de caracteres (o bytes) escritos, o -1 si ocurrió un error. Si se produce un error de E/S, se puede encontrar información adicional en el campo result del intérprete.

TCL_WRITE

Tcl_Write escribe hasta bytesToWrite bytes sin procesar del búfer byteBuf en el canal channel. La escritura no se ve afectada por la codificación del canal. El número de bytes realmente escritos se devuelve como el valor de retorno.

El valor de retorno es el número de bytes escritos, o -1 si ocurrió un error. Si se produce un error de E/S, se puede encontrar información adicional en el campo result del intérprete.

TCL_READRAW

Tcl_ReadRaw es equivalente a Tcl_Read.

TCL_WRITERAW

Tcl_WriteRaw es equivalente a Tcl_Write.

TCL_EOF

Tcl_Eof devuelve 1 si se ha alcanzado el final del archivo en el canal channel, o 0 en caso contrario. Si se ha alcanzado el final del archivo, no se pueden leer más datos del canal.

TCL_FLUSH

Tcl_Flush fuerza la escritura de cualquier dato de salida búferizado en el canal channel al dispositivo subyacente. Esto es útil para asegurarse de que todos los datos se envíen antes de esperar una respuesta o cerrar el canal.

El valor de retorno es 0 si el vaciado fue exitoso, o -1 si ocurrió un error. Si se produce un error, se puede encontrar información adicional en el campo result del intérprete.

TCL_INPUTBLOCKED

Tcl_InputBlocked devuelve 1 si una operación de lectura en el canal channel se bloquearía porque no hay datos disponibles, o 0 en caso contrario. Esto es útil para la E/S no bloqueante.

TCL_INPUTBUFFERED

Tcl_InputBuffered devuelve el número de bytes que están actualmente en el búfer de entrada del canal channel y que están listos para ser leídos. Esto puede ser útil para determinar cuántos datos se pueden leer sin bloquear.

TCL_OUTPUTBUFFERED

Tcl_OutputBuffered devuelve el número de bytes que están actualmente en el búfer de salida del canal channel y que aún no se han escrito en el dispositivo subyacente. Esto puede ser útil para determinar cuánto espacio queda en el búfer de salida.

TCL_SEEK

Tcl_Seek cambia la posición actual del archivo del canal channel. El nuevo punto de acceso se calcula sumando offset a la posición dada por seekMode. Los valores legales para seekMode son SEEK_SET (inicio del archivo), SEEK_CUR (posición actual) y SEEK_END (final del archivo). El valor de retorno es la nueva posición del archivo en bytes desde el inicio del archivo, o -1 si ocurrió un error.

Este procedimiento solo está disponible para canales que admiten posicionamiento, como archivos regulares.

TCL_TELL

Tcl_Tell devuelve la posición actual del archivo del canal channel en bytes desde el inicio del archivo. Si el canal no admite posicionamiento, el comportamiento no está definido.

El valor de retorno es la posición actual del archivo, o -1 si ocurrió un error.

TCL_TRUNCATECHANNEL

Tcl_TruncateChannel trunca el archivo asociado con el canal channel a la longitud especificada por length. Si la longitud actual del archivo es menor que length, el archivo se extiende y se rellena con bytes nulos. Si la longitud actual es mayor que length, los datos más allá de length se descartan.

Este procedimiento solo está disponible para canales que admiten truncamiento, como archivos regulares abiertos para escritura.

El valor de retorno es 0 si la operación fue exitosa, o -1 si ocurrió un error.

TCL_GETCHANNELOPTION

Tcl_GetChannelOption recupera el valor de la opción optionName para el canal channel y lo almacena en la cadena dinámica Tcl apuntada por optionValue. El nombre de la opción debe ser uno de los reconocidos por el comando fconfigure.

El valor de retorno es 0 si la opción se recuperó correctamente, o -1 si ocurrió un error (por ejemplo, la opción no existe o el canal no la soporta).

TCL_SETCHANNELOPTION

Tcl_SetChannelOption establece el valor de la opción optionName para el canal channel en newValue. El nombre de la opción debe ser uno de los reconocidos por el comando fconfigure. Las opciones comunes incluyen -blocking, -buffering, -encoding y -translation.

El valor de retorno es 0 si la opción se estableció correctamente, o -1 si ocurrió un error (por ejemplo, la opción no existe, el canal no la soporta o el valor proporcionado no es válido).

TCL_OPENFILECHANNEL

Tcl_OpenFileChannel abre un archivo especificado por fileName y devuelve un manejador de canal que se puede usar para realizar entrada y salida en el archivo. Esta API está modelada según el procedimiento fopen de la biblioteca de E/S estándar de Unix. La sintaxis y el significado de todos los argumentos son similares a los dados en el comando Tcl open al abrir un archivo. Si ocurre un error al abrir el canal, Tcl_OpenFileChannel devuelve NULL y registra un código de error POSIX que se puede recuperar con Tcl_GetErrno. Además, si interp no es NULL, Tcl_OpenFileChannel deja un mensaje de error en el resultado de interp después de cualquier error. A partir de Tcl 8.4, la API basada en valores Tcl_FSOpenFileChannel debe usarse en lugar de Tcl_OpenFileChannel siempre que sea posible.

El canal recién creado no está registrado en el intérprete suministrado; para registrarlo, use Tcl_RegisterChannel, descrito a continuación. Si uno de los canales estándar, stdin, stdout o stderr se cerró previamente, el acto de crear el nuevo canal también lo asigna como reemplazo del canal estándar.

TCL_OPENCOMMANDCHANNEL

Tcl_OpenCommandChannel proporciona una interfaz de nivel C a las funciones de los comandos exec y open. Crea una secuencia de subprocesos especificados por los argumentos argv y argc y devuelve un canal que se puede usar para comunicarse con estos subprocesos. El argumento flags indica qué tipo de comunicación existirá con la tubería del comando.

Si se establece la bandera TCL_STDIN, la entrada estándar del primer subproceso estará vinculada al canal: escribir en el canal proporcionará entrada al subproceso. Si TCL_STDIN no está establecido, la entrada estándar del primer subproceso será la misma que la entrada estándar de esta aplicación. Si se establece TCL_STDOUT, la salida estándar del último subproceso se puede leer del canal; de lo contrario, va a la salida estándar de esta aplicación. Si se establece TCL_STDERR, la salida de error estándar para todos los subprocesos se devuelve al canal y resulta en un error cuando se cierra el canal; de lo contrario, va al error estándar de esta aplicación. Si TCL_ENFORCE_MODE no está establecido, entonces argc y argv pueden redirigir los manejadores stdio para anular TCL_STDIN, TCL_STDOUT y TCL_STDERR; si está establecido, entonces es un error que argc y argv anulen los canales stdio para los cuales se han establecido TCL_STDIN, TCL_STDOUT y TCL_STDERR.

Si ocurre un error al abrir el canal, Tcl_OpenCommandChannel devuelve NULL y registra un código de error POSIX que se puede recuperar con Tcl_GetErrno. Además, Tcl_OpenCommandChannel deja un mensaje de error en el resultado del intérprete. interp no puede ser NULL.

El canal recién creado no está registrado en el intérprete suministrado; para registrarlo, use Tcl_RegisterChannel, descrito a continuación. Si uno de los canales estándar, stdin, stdout o stderr se cerró previamente, el acto de crear el nuevo canal también lo asigna como reemplazo del canal estándar.

TCL_MAKEFILECHANNEL

Tcl_MakeFileChannel crea un Tcl_Channel a partir de un manejador de archivo existente específico de la plataforma. El canal recién creado no está registrado en el intérprete suministrado; para registrarlo, use Tcl_RegisterChannel, descrito a continuación. Si uno de los canales estándar, stdin, stdout o stderr se cerró previamente, el acto de crear el nuevo canal también lo asigna como reemplazo del canal estándar.

TCL_GETCHANNEL

Tcl_GetChannel devuelve un canal dado el channelName utilizado para crearlo con Tcl_CreateChannel y un puntero a un intérprete Tcl en interp. Si no hay un canal con ese nombre registrado en ese intérprete, el procedimiento devuelve NULL. Si el argumento modePtr no es NULL, apunta a una variable entera que recibirá una combinación OR de TCL_READABLE y TCL_WRITABLE que describe si el canal está abierto para lectura y escritura.

Tcl_GetChannelNames y Tcl_GetChannelNamesEx escriben los nombres de los canales registrados en el resultado del intérprete como un valor de lista. Tcl_GetChannelNamesEx filtrará estos nombres según el pattern. Si pattern es NULL, entonces no realizará ningún filtrado. El valor de retorno es TCL_OK si no ocurrieron errores al escribir en el resultado, de lo contrario es TCL_ERROR, y el mensaje de error se deja en el resultado del intérprete.

TCL_REGISTERCHANNEL

Tcl_RegisterChannel agrega un canal al conjunto de canales accesibles en interp. Después de esta llamada, los programas Tcl que se ejecutan en ese intérprete pueden referirse al canal en operaciones de entrada o salida utilizando el nombre dado en la llamada a Tcl_CreateChannel. Después de esta llamada, el canal se convierte en propiedad del intérprete, y el llamador no debe llamar a Tcl_Close para el canal; el canal se cerrará automáticamente cuando se desregistre del intérprete.

El código que se ejecuta fuera de cualquier intérprete Tcl puede llamar a Tcl_RegisterChannel con interp como NULL, para indicar que desea mantener una referencia a este canal. Posteriormente, el canal puede ser registrado en un intérprete Tcl y solo se cerrará cuando el número coincidente de llamadas a Tcl_UnregisterChannel se hayan realizado. Esto permite que el código que se ejecuta fuera de cualquier intérprete mantenga de forma segura una referencia a un canal que también está registrado en un intérprete Tcl.

Este procedimiento interactúa con el código que administra los canales estándar. Si no se inicializaron canales estándar antes de la primera llamada a Tcl_RegisterChannel, se inicializarán con esa llamada. Consulte Tcl_StandardChannels para un tratado general sobre los canales estándar y el comportamiento de la biblioteca Tcl con respecto a ellos.

TCL_UNREGISTERCHANNEL

Tcl_UnregisterChannel elimina un canal del conjunto de canales accesibles en interp. Después de esta llamada, los programas Tcl ya no podrán utilizar el nombre del canal para referirse al canal en ese intérprete. Si esta operación eliminó el último registro del canal en cualquier intérprete, el canal también se cierra y se destruye.

El código no asociado con un intérprete Tcl puede llamar a Tcl_UnregisterChannel con interp como NULL, para indicar a Tcl que ya no mantiene una referencia a ese canal. Si esta es la última referencia al canal, se cerrará. Tcl_UnregisterChannel es muy similar a Tcl_DetachChannel excepto que también cerrará el canal si no existen más referencias a él.

TCL_DETACHCHANNEL

Tcl_DetachChannel elimina un canal del conjunto de canales accesibles en interp. Después de esta llamada, los programas Tcl ya no podrán utilizar el nombre del canal para referirse al canal en ese intérprete. Más allá de eso, este comando no tiene ningún efecto adicional. No se puede utilizar en los canales estándar (stdout, stderr, stdin), y devolverá TCL_ERROR si se le pasa uno de esos canales.

El código no asociado con un intérprete Tcl puede llamar a Tcl_DetachChannel con interp como NULL, para indicar a Tcl que ya no mantiene una referencia a ese canal. Si esta es la última referencia al canal, a diferencia de Tcl_UnregisterChannel, no se cerrará.

TCL_ISSTANDARDCHANNEL

Tcl_IsStandardChannel prueba si un canal es uno de los tres canales estándar, stdin, stdout o stderr. Si es así, devuelve 1, de lo contrario 0.

No se intenta comprobar si el canal dado o los canales estándar están inicializados o son válidos de alguna otra manera.

TCL_CLOSE

Tcl_Close destruye el canal channel, que debe denotar un canal actualmente abierto. El canal no debe estar registrado en ningún intérprete cuando se llama a Tcl_Close. La salida en búfer se vacía al dispositivo de salida del canal antes de destruir el canal, y cualquier entrada en búfer se descarta. Si este es un canal de bloqueo, la llamada no devuelve hasta que todos los datos en búfer se envíen correctamente al dispositivo de salida del canal. Si este es un canal sin bloqueo y hay salida en búfer que no se puede escribir sin bloquear, la llamada devuelve inmediatamente; la salida se vacía en segundo plano y el canal se cerrará una vez que todos los datos en búfer se hayan enviado. En este caso, los errores durante el vaciado no se informan.

Si el canal se cerró correctamente, Tcl_Close devuelve TCL_OK. Si ocurre un error, Tcl_Close devuelve TCL_ERROR y registra un código de error POSIX que se puede recuperar con Tcl_GetErrno. Si el canal se está cerrando de forma síncrona y ocurre un error durante el cierre del canal y interp no es NULL, se deja un mensaje de error en el resultado del intérprete.

Nota: no es seguro llamar a Tcl_Close en un canal que ha sido registrado usando Tcl_RegisterChannel; consulte la documentación para Tcl_RegisterChannel, arriba, para más detalles. Si el canal ha sido alguna vez proporcionado como el argumento chan en una llamada a Tcl_RegisterChannel, debe usar en su lugar Tcl_UnregisterChannel, que llamará internamente a Tcl_Close cuando todas las llamadas a Tcl_RegisterChannel se hayan emparejado con las llamadas correspondientes a Tcl_UnregisterChannel.

TCL_READCHARS Y TCL_READ

Tcl_ReadChars consume bytes del channel, convirtiendo los bytes a UTF-8 basándose en la codificación del canal y almacenando los datos producidos en la representación de cadena de readObjPtr. El valor de retorno de Tcl_ReadChars es el número de caracteres, hasta charsToRead, que se almacenaron en readObjPtr. Si ocurre un error al leer, el valor de retorno es -1 y Tcl_ReadChars registra un código de error POSIX que se puede recuperar con Tcl_GetErrno.

TCL_READCHARS, TCL_READ, AND TCL_READRAW

Tcl_ReadChars lee como máximo charsToRead caracteres de channel y los almacena en el objeto apuntado por readObjPtr. Si charsToRead es negativo, la llamada lee todos los caracteres disponibles actualmente (modo no bloqueante) o hasta el final del archivo (modo bloqueante).

El valor de retorno puede ser menor que el valor a leer, lo que indica que había menos datos de los solicitados disponibles. Esto se denomina una lectura corta. En modo bloqueante, esto solo puede ocurrir al final del archivo. En modo no bloqueante, una lectura corta también puede ocurrir si no hay suficiente entrada disponible actualmente: Tcl_ReadChars devuelve un conteo corto en lugar de esperar más datos.

Si el canal está en modo bloqueante, un valor de retorno de cero indica una condición de fin de archivo. Si el canal está en modo no bloqueante, un valor de retorno de cero indica que no hay entrada disponible actualmente o una condición de fin de archivo. Utilice Tcl_Eof y Tcl_InputBlocked para determinar cuál de estas condiciones ocurrió realmente.

Tcl_ReadChars traduce las diversas representaciones de fin de línea a la representación canónica interna de \n de acuerdo con el modo de reconocimiento de fin de línea actual. El reconocimiento de fin de línea y los diversos modos específicos de la plataforma se describen en la entrada del manual del comando fconfigure de Tcl.

Como optimización de rendimiento, al leer de un canal con la codificación binary, los bytes no se convierten a UTF-8 al ser leídos. En su lugar, se almacenan en la representación interna de readObjPtr como un valor de arreglo de bytes. La representación de cadena de este valor solo se construirá si es necesaria (por ejemplo, debido a una llamada a Tcl_GetStringFromObj). De esta manera, los datos orientados a bytes se pueden leer de un canal, manipular llamando a Tcl_GetByteArrayFromObj y funciones relacionadas, y luego escribirlos en un canal sin el costo de convertir de o a UTF-8.

Tcl_Read es similar a Tcl_ReadChars, excepto que no realiza conversiones de codificación, independientemente de la codificación del canal. Está obsoleto y existe para compatibilidad con extensiones Tcl no internacionalizadas. Consume bytes de channel y los almacena en readBuf, realizando traducciones de fin de línea en el camino. El valor de retorno de Tcl_Read es el número de bytes, hasta bytesToRead, escritos en readBuf. El buffer producido por Tcl_Read no está terminado en nulo. Su contenido es válido desde la posición cero hasta la posición indicada por el valor de retorno, sin incluirla.

Tcl_ReadRaw es lo mismo que Tcl_Read pero no compensa el apilamiento. Mientras que Tcl_Read (y las otras funciones de la API) siempre obtienen sus datos del canal superior en la pila de la que forma parte el canal suministrado, Tcl_ReadRaw no lo hace. Por lo tanto, esta función solo es utilizable para controladores de canales transformacionales, es decir, controladores utilizados en medio de una pila de canales, para mover datos del canal inferior a la transformación.

TCL_GETSOBJ Y TCL_GETS

Tcl_GetsObj consume bytes de channel, convirtiendo los bytes a UTF-8 basándose en la codificación del canal, hasta que se ha visto una línea completa de entrada. Si la codificación del canal es binary, cada byte leído del canal se trata como un carácter Unicode individual. Todos los caracteres de la línea, excepto los caracteres de fin de línea terminantes, se añaden a la representación de cadena de lineObjPtr. Los caracteres de fin de línea se leen y se descartan.

Si se leyó una línea correctamente, el valor de retorno es mayor o igual a cero e indica el número de bytes almacenados en lineObjPtr. Si ocurre un error, Tcl_GetsObj devuelve -1 y registra un código de error POSIX que se puede recuperar con Tcl_GetErrno. Tcl_GetsObj también devuelve -1 si se alcanza el final del archivo; el procedimiento Tcl_Eof se puede usar para distinguir un error de una condición de fin de archivo.

Si el canal está en modo no bloqueante, el valor de retorno también puede ser -1 si no había datos disponibles o si los datos disponibles no contenían un carácter de fin de línea. Cuando se devuelve -1, el procedimiento Tcl_InputBlocked puede ser invocado para determinar si el canal está bloqueado debido a la indisponibilidad de entrada.

Tcl_Gets es lo mismo que Tcl_GetsObj excepto que los caracteres resultantes se añaden a la cadena dinámica dada por lineRead en lugar de un valor Tcl.

TCL_UNGETS

Tcl_Ungets se utiliza para añadir datos a la cola de entrada de un canal, ya sea en la cabeza o en la cola de la cola. El puntero input apunta a los datos que se van a añadir. La longitud de la entrada a añadir viene dada por inputLen. Un valor distinto de cero de addAtEnd indica que los datos se añadirán al final de la cola; de lo contrario, se añadirán al principio de la cola. Si channel tiene un EOF "pegajoso" establecido, no se añadirán datos a la cola de entrada. Tcl_Ungets devuelve inputLen o -1 si ocurre un error.

TCL_WRITECHARS, TCL_WRITEOBJ, Y TCL_WRITE

Tcl_WriteChars acepta bytesToWrite bytes de datos de caracteres en charBuf. Los caracteres UTF-8 en el buffer se convierten a la codificación del canal y se ponen en cola para la salida al channel. Si bytesToWrite es negativo, Tcl_WriteChars espera que charBuf esté terminado en nulo y saca todo hasta el nulo.

Los datos puestos en cola para la salida pueden no aparecer en el dispositivo de salida inmediatamente, debido al almacenamiento en búfer interno. Si los datos deben aparecer inmediatamente, llame a Tcl_Flush después de la llamada a Tcl_WriteChars, o establezca la opción -buffering en el canal a none. Si desea que los datos aparezcan tan pronto como se acepte una línea completa para la salida, establezca la opción -buffering en el canal en modo line.

El valor de retorno de Tcl_WriteChars es un conteo de cuántos bytes fueron aceptados para la salida al canal. Esto es mayor que cero para indicar éxito o -1 para indicar que ocurrió un error. Si ocurre un error, Tcl_WriteChars registra un código de error POSIX que puede ser recuperado con Tcl_GetErrno.

Los caracteres de nueva línea en los datos de salida se traducen a secuencias de fin de línea específicas de la plataforma según la opción -translation para el canal. Esto se hace incluso si el canal no tiene codificación.

Tcl_WriteObj es similar a Tcl_WriteChars excepto que acepta un valor Tcl cuyos contenidos se sacarán al canal. Los caracteres UTF-8 en la representación de cadena de writeObjPtr se convierten a la codificación del canal y se ponen en cola para la salida a channel. Como optimización de rendimiento, al escribir en un canal con la codificación binary, los caracteres UTF-8 no se convierten al ser escritos. En su lugar, los bytes en la representación interna de writeObjPtr como un valor de arreglo de bytes se escriben en el canal. La representación de arreglo de bytes del valor se construirá si es necesaria. De esta manera, los datos orientados a bytes se pueden leer de un canal, manipular llamando a Tcl_GetByteArrayFromObj y funciones relacionadas, y luego escribir en un canal sin el costo de convertir de o a UTF-8.

Tcl_Write es similar a Tcl_WriteChars excepto que no realiza conversiones de codificación, independientemente de la codificación del canal. Está obsoleto y existe para compatibilidad con extensiones Tcl no internacionalizadas. Acepta bytesToWrite bytes de datos en byteBuf y los pone en cola para la salida a channel. Si bytesToWrite es negativo, Tcl_Write espera que byteBuf esté terminado en nulo y saca todo hasta el nulo.

Tcl_WriteRaw es lo mismo que Tcl_Write pero no compensa el apilamiento. Mientras que Tcl_Write (y las otras funciones de la API) siempre alimentan su entrada al canal superior en la pila de la que forma parte el canal suministrado, Tcl_WriteRaw no lo hace. Por lo tanto, esta función solo es utilizable para controladores de canales transformacionales, es decir, controladores utilizados en medio de una pila de canales, para mover datos de la transformación al canal debajo de ella.

TCL_FLUSH

Tcl_Flush hace que todos los datos de salida en búfer para channel se escriban en su archivo o dispositivo subyacente tan pronto como sea posible. Si el canal está en modo bloqueante, la llamada no devuelve hasta que todos los datos en búfer se hayan enviado al canal o haya ocurrido algún error. La llamada devuelve inmediatamente si el canal no está bloqueado; inicia una descarga en segundo plano que escribirá los datos en búfer al canal eventualmente, tan rápido como el canal pueda absorberlo.

El valor de retorno es normalmente TCL_OK. Si ocurre un error, Tcl_Flush devuelve TCL_ERROR y registra un código de error POSIX que se puede recuperar con Tcl_GetErrno.

TCL_SEEK

Tcl_Seek mueve el punto de acceso en channel donde se leerá o escribirán los datos posteriores. La salida en búfer se vacía al canal y la entrada en búfer se descarta, antes de la operación de búsqueda.

Tcl_Seek normalmente devuelve el nuevo punto de acceso. Si ocurre un error, Tcl_Seek devuelve -1 y registra un código de error POSIX que se puede recuperar con Tcl_GetErrno. Después de un error, el punto de acceso puede o no haberse movido.

TCL_TELL

Tcl_Tell devuelve el punto de acceso actual para un canal. El valor devuelto es -1 si el canal no admite búsqueda.

TCL_TRUNCATECHANNEL

Tcl_TruncateChannel trunca el archivo subyacente de channel a una longitud dada de length bytes. Devuelve TCL_OK si la operación tuvo éxito, y TCL_ERROR en caso contrario.

TCL_GETCHANNELOPTION

Tcl_GetChannelOption recupera, en optionValue, el valor de una de las opciones actualmente en vigor para un canal, o una lista de todas las opciones y sus valores. El argumento channel identifica el canal para el que se va a consultar una opción o recuperar todas las opciones y sus valores. Si optionName no es NULL, es el nombre de la opción a consultar; el valor de la opción se copia a la cadena dinámica Tcl denotada por optionValue. Si optionName es NULL, la función almacena una lista alternante de nombres de opciones y sus valores en optionValue.

TCL_GETCHANNELOPTION

Tcl_GetChannelOption retrieves the value of the option optionName for channel. The value is returned as a Tcl object in Tcl's result, and the procedure returns TCL_OK. If optionName is not a valid option for channel, an error is returned and TCL_ERROR is returned. If optionName is valid, but the value cannot be retrieved for some other reason, an error is returned and TCL_ERROR is returned. The procedure returns the value of the option in Tcl's result using a series of calls to Tcl_DStringAppendElement. The various preexisting options and their possible values are described in the manual entry for the Tcl fconfigure command. Other options can be added by each channel type. These channel type specific options are described in the manual entry for the Tcl command that creates a channel of that type; for example, the additional options for TCP-based channels are described in the manual entry for the Tcl socket command. The procedure normally returns TCL_OK. If an error occurs, it returns TCL_ERROR and calls Tcl_SetErrno to store an appropriate POSIX error code.

TCL_SETCHANNELOPTION

Tcl_SetChannelOption sets a new value newValue for an option optionName on channel. The procedure normally returns TCL_OK. If an error occurs, it returns TCL_ERROR; in addition, if interp is non-NULL, Tcl_SetChannelOption leaves an error message in the interpreter's result.

TCL_EOF

Tcl_Eof returns a nonzero value if channel encountered an end of file during the last input operation.

TCL_INPUTBLOCKED

Tcl_InputBlocked returns a nonzero value if channel is in nonblocking mode and the last input operation returned less data than requested because there was insufficient data available. The call always returns zero if the channel is in blocking mode.

TCL_INPUTBUFFERED

Tcl_InputBuffered returns the number of bytes of input currently buffered in the internal buffers for a channel. If the channel is not open for reading, this function always returns zero.

TCL_OUTPUTBUFFERED

Tcl_OutputBuffered returns the number of bytes of output currently buffered in the internal buffers for a channel. If the channel is not open for writing, this function always returns zero.

PLATFORM ISSUES

The handles returned from Tcl_GetChannelHandle depend on the platform and the channel type. On Unix platforms, the handle is always a Unix file descriptor as returned from the open system call. On Windows platforms, the handle is a file HANDLE when the channel was created with Tcl_OpenFileChannel, Tcl_OpenCommandChannel, or Tcl_MakeFileChannel. Other channel types may return a different type of handle on Windows platforms.
