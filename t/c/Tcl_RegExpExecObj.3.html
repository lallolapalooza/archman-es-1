ARGUMENTOS

Tcl_Interp *interp (entrada)
Intérprete de Tcl a utilizar para la notificación de errores. El intérprete puede ser NULL si no se desea notificación de errores.
Tcl_Obj *textObj (entrada/salida)
Se refiere al valor del cual se obtendrá el texto a buscar. La representación interna del valor puede ser convertida a un formato que pueda ser buscado eficientemente.
Tcl_Obj *patObj (entrada/salida)
Se refiere al valor del cual se obtendrá una expresión regular. La expresión regular compilada se almacena en caché en el valor.
const char *text (entrada)
Texto en el que buscar una coincidencia con una expresión regular.
const char *pattern (entrada)
Cadena en forma de patrón de expresión regular.
Tcl_RegExp regexp (entrada)
Expresión regular compilada. Debe haber sido devuelta previamente por Tcl_GetRegExpFromObj o Tcl_RegExpCompile.
const char *start (entrada)
Si text es solo una porción de alguna otra cadena, este argumento identifica el inicio de la cadena más grande. Si no es el mismo que text, entonces no se permitirán coincidencias de “^”.
int index (entrada)
Especifica qué rango se desea: 0 significa el rango de toda la coincidencia, 1 o mayor significa el rango que coincidió con una subexpresión entre paréntesis.
const char **startPtr (salida)
La dirección del primer carácter en el rango se almacena aquí, o NULL si no existe tal rango.
const char **endPtr (salida)
La dirección del carácter justo después del último en el rango se almacena aquí, o NULL si no existe tal rango.
int cflags (entrada)
Combinación OR de las banderas de compilación TCL_REG_ADVANCED, TCL_REG_EXTENDED, TCL_REG_BASIC, TCL_REG_EXPANDED, TCL_REG_QUOTE, TCL_REG_NOCASE, TCL_REG_NEWLINE, TCL_REG_NLSTOP, TCL_REG_NLANCH, TCL_REG_NOSUB, y TCL_REG_CANMATCH. Consulte a continuación para obtener más información.
int offset (entrada)
El desplazamiento de caracteres en el texto donde debe comenzar la coincidencia. El valor del desplazamiento no tiene impacto en las coincidencias de ^. Este comportamiento está controlado por eflags.
int nmatches (entrada)
El número de subexpresiones coincidentes que deben ser recordadas para su uso posterior. Si este valor es 0, entonces no se calculará información de coincidencia de subexpresiones. Si el valor es -1, entonces se recordarán todas las subexpresiones coincidentes. Cualquier otro valor se tomará como el número máximo de subexpresiones a recordar.
int eflags (entrada)
Combinación OR de las banderas de ejecución TCL_REG_NOTBOL y TCL_REG_NOTEOL. Consulte a continuación para obtener más información.
Tcl_RegExpInfo *infoPtr (salida)
La dirección de la ubicación donde debe ser almacenada la información sobre una coincidencia previa por Tcl_RegExpGetInfo.

DESCRIPCIÓN

Tcl_RegExpMatch determina si su argumento pattern coincide con regexp, donde regexp se interpreta como una expresión regular utilizando las reglas de la página de referencia re_syntax. Si hay una coincidencia, Tcl_RegExpMatch devuelve 1. Si no hay coincidencia, Tcl_RegExpMatch devuelve 0. Si ocurre un error en el proceso de coincidencia (por ejemplo, pattern no es una expresión regular válida), Tcl_RegExpMatch devuelve -1 y deja un mensaje de error en el resultado del intérprete. Tcl_RegExpMatchObj es similar a Tcl_RegExpMatch excepto que opera en los valores Tcl textObj y patObj en lugar de cadenas UTF. Tcl_RegExpMatchObj es generalmente más eficiente que Tcl_RegExpMatch, por lo que es la interfaz preferida.

Tcl_RegExpCompile, Tcl_RegExpExec, y Tcl_RegExpRange proporcionan acceso de bajo nivel al motor de búsqueda de patrones de expresiones regulares. Tcl_RegExpCompile compila una cadena de expresión regular en la forma interna utilizada para una coincidencia de patrones eficiente. El valor de retorno es un token para esta forma compilada, que puede ser utilizado en llamadas posteriores a Tcl_RegExpExec o Tcl_RegExpRange. Si ocurre un error al compilar la expresión regular, Tcl_RegExpCompile devuelve NULL y deja un mensaje de error en el resultado del intérprete. Nota: el valor de retorno de Tcl_RegExpCompile solo es válido hasta la próxima llamada a Tcl_RegExpCompile; no es seguro retener estos valores durante largos períodos de tiempo.

Tcl_RegExpExec ejecuta el motor de búsqueda de patrones de expresiones regulares. Devuelve 1 si text contiene un rango de caracteres que coincide con regexp, 0 si no se encuentra ninguna coincidencia, y -1 si ocurre un error. En caso de error, Tcl_RegExpExec deja un mensaje de error en el resultado del intérprete. Al buscar en una cadena múltiples coincidencias de un patrón, es importante distinguir entre el inicio de la cadena original y el inicio de la búsqueda actual. Por ejemplo, al buscar la segunda ocurrencia de una coincidencia, el argumento text podría apuntar al carácter justo después de la primera coincidencia; sin embargo, es importante que el motor de búsqueda de patrones sepa que este no es el inicio de toda la cadena, para que no permita que los átomos “^” en el patrón coincidan. El argumento start proporciona esta información apuntando al inicio de la cadena general que contiene text. Start será menor o igual a text; si es menor que text, no se permitirán coincidencias de ^.

Tcl_RegExpRange puede ser invocado después de que Tcl_RegExpExec devuelva; proporciona información detallada sobre qué rangos de la cadena coincidieron con qué partes del patrón. Tcl_RegExpRange devuelve un par de punteros en *startPtr y *endPtr que identifican un rango de caracteres en la cadena fuente para la llamada más reciente a Tcl_RegExpExec. Index indica cuál de los varios rangos se desea: si index es 0, se devuelve información sobre el rango general de caracteres que coincidió con todo el patrón; de lo contrario, se devuelve información sobre el rango de caracteres que coincidió con la subexpresión entre paréntesis index dentro del patrón. Si no existe un rango correspondiente a index, NULL se almacena en *startPtr y *endPtr.

Tcl_GetRegExpFromObj, Tcl_RegExpExecObj, y Tcl_RegExpGetInfo son interfaces de valor que proporcionan el control más directo de la biblioteca de expresiones regulares de Henry Spencer. Para los usuarios que necesiten modificar las opciones de compilación y ejecución directamente, se recomienda que utilicen estas interfaces en lugar de llamar a las funciones internas de expresiones regulares. Estas interfaces manejan los detalles de las traducciones de UTF a Unicode, además de proporcionar un rendimiento mejorado a través del almacenamiento en caché en los valores del patrón y la cadena.

Tcl_GetRegExpFromObj intenta devolver una expresión regular compilada del patObj. Si el valor no contiene ya una expresión regular compilada, intentará crear una a partir de la cadena en el valor y asignarla a la representación interna del patObj. El valor de retorno de esta función es de tipo Tcl_RegExp. El valor de retorno es un token para esta forma compilada, que puede ser utilizado en llamadas posteriores a Tcl_RegExpExecObj o Tcl_RegExpGetInfo. Si ocurre un error al compilar la expresión regular, Tcl_GetRegExpFromObj devuelve NULL y deja un mensaje de error en el resultado del intérprete. El token de la expresión regular puede ser utilizado mientras la representación interna de patObj se refiera a la forma compilada. El argumento cflags es una combinación OR de cero o más de las siguientes banderas que controlan la compilación de patObj:

TCL_REG_ADVANCED
Permite el uso de sintaxis de expresiones regulares avanzada, como `\A`, `\Z`, `\b`, `\B`, `\w`, `\W`, `\d`, `\D`, `\s`, `\S`, `\s`, `\S`, y `(?...)` para la coincidencia sin captura.
TCL_REG_EXTENDED
Permite el uso de sintaxis de expresiones regulares extendida, como `|`, `?`, `+`, `*?`, `+?`, `??`. Los patrones se interpretan como expresiones regulares POSIX extendidas.
TCL_REG_BASIC
Permite el uso de sintaxis de expresiones regulares básicas, como `\{m,n\}`. Los patrones se interpretan como expresiones regulares POSIX básicas. Este es el valor predeterminado si no se especifica TCL_REG_EXTENDED ni TCL_REG_ADVANCED.
TCL_REG_EXPANDED
Permite que los patrones incluyan espacios en blanco y comentarios. Los espacios en blanco se ignoran, excepto cuando están en una clase de caracteres o escapan con una barra invertida. Los comentarios comienzan con `#` y continúan hasta el final de la línea.
TCL_REG_QUOTE
Trata el patrón como una cadena literal. Todas las caracteres especiales de expresiones regulares se escapan, por lo que coinciden solo consigo mismos.
TCL_REG_NOCASE
Ignora la distinción entre mayúsculas y minúsculas en el patrón y el texto.
TCL_REG_NEWLINE
Los caracteres de nueva línea (`\n`) se tratan como caracteres normales. Por defecto, `^` y `$` coinciden con el inicio y el final de la cadena, respectivamente. Si se utiliza esta bandera, `^` y `$` también coinciden con el inicio y el final de cada línea, respectivamente.
TCL_REG_NLSTOP
Si se especifica esta bandera, los caracteres de nueva línea (`\n`) terminan una coincidencia. Esto significa que `.` no coincidirá con un carácter de nueva línea, y `^` y `$` coincidirán solo con el inicio y el final de la cadena, respectivamente.
TCL_REG_NLANCH
Si se especifica esta bandera, los anclajes `^` y `$` coinciden con el inicio y el final de cada línea, respectivamente. Esto es similar a TCL_REG_NEWLINE, pero `.` también coincidirá con los caracteres de nueva línea.
TCL_REG_NOSUB
Solo se determina si el patrón coincide con el texto. No se almacena información sobre subexpresiones coincidentes. Esto puede mejorar el rendimiento si solo necesita saber si hay una coincidencia.
TCL_REG_CANMATCH
Comprueba si el patrón puede coincidir con el texto dado. Devuelve 1 si puede coincidir, 0 si no. Útil para precalcular la posibilidad de coincidencia.

Tcl_RegExpExecObj ejecuta el motor de búsqueda de patrones de expresiones regulares. Devuelve 1 si el textObj contiene un rango de caracteres que coincide con el regexp compilado, 0 si no se encuentra ninguna coincidencia y -1 si ocurre un error. Si se produce un error, Tcl_RegExpExecObj deja un mensaje de error en el resultado del intérprete. El argumento offset especifica el desplazamiento de caracteres dentro del texto donde debe comenzar la búsqueda. El argumento nmatches especifica el número máximo de subexpresiones coincidentes que se deben guardar para su posterior recuperación. El argumento eflags es una combinación OR de cero o más de las siguientes banderas que controlan la ejecución de la coincidencia:

TCL_REG_NOTBOL
Si se especifica esta bandera, el carácter `^` no coincidirá con el inicio de la cadena, incluso si el desplazamiento es 0.
TCL_REG_NOTEOL
Si se especifica esta bandera, el carácter `$` no coincidirá con el final de la cadena, incluso si el desplazamiento es el final de la cadena.

Tcl_RegExpGetInfo recupera información sobre la coincidencia más reciente realizada por Tcl_RegExpExecObj. La información se almacena en la estructura a la que apunta infoPtr. La estructura Tcl_RegExpInfo contiene los siguientes campos:

int nmatches
El número de subexpresiones coincidentes que se encontraron.
int extendendmatch
El número de subexpresiones coincidentes que se guardaron. Este valor será menor o igual que nmatches. Si se especificó nmatches = -1 en la llamada a Tcl_RegExpExecObj, este valor será igual a nmatches.
int src
La longitud de la cadena de entrada.
const char *str
Un puntero a la cadena de entrada que se buscó.
const char **starts
Un array de punteros a los caracteres de inicio de cada subexpresión coincidente. El tamaño de este array es nmatches.
const char **ends
Un array de punteros a los caracteres finales (justo después del último carácter coincidente) de cada subexpresión coincidente. El tamaño de este array es nmatches.

ARGUMENTS

TCL_REG_ADVANCED
Compile advanced regular expressions (“ARE”s). This mode corresponds to the normal regular expression syntax accepted by the Tcl regexp and regsub commands.
TCL_REG_EXTENDED
Compile extended regular expressions (“ERE”s). This mode corresponds to the regular expression syntax recognized by Tcl 8.0 and earlier versions.
TCL_REG_BASIC
Compile basic regular expressions (“BRE”s). This mode corresponds to the regular expression syntax recognized by common Unix utilities like sed and grep. This is the default if no flags are specified.
TCL_REG_EXPANDED
Compile the regular expression (basic, extended, or advanced) using an expanded syntax that allows comments and whitespace. This mode causes non-backslashed non-bracket-expression white space and #-to-end-of-line comments to be ignored.
TCL_REG_QUOTE
Compile a literal string, with all characters treated as ordinary characters.
TCL_REG_NOCASE
Compile for matching that ignores upper/lower case distinctions.
TCL_REG_NEWLINE
Compile for newline-sensitive matching. By default, newline is a completely ordinary character with no special meaning in either regular expressions or strings. With this flag, “[^” bracket expressions and “.” never match newline, “^” matches an empty string after any newline in addition to its normal function, and “$” matches an empty string before any newline in addition to its normal function. REG_NEWLINE is the bit-wise OR of REG_NLSTOP and REG_NLANCH.
TCL_REG_NLSTOP
Compile for partial newline-sensitive matching, with the behavior of “[^” bracket expressions and “.” affected, but not the behavior of “^” and “$”. In this mode, “[^” bracket expressions and “.” never match newline.
TCL_REG_NLANCH
Compile for inverse partial newline-sensitive matching, with the behavior of “^” and “$” (the “anchors”) affected, but not the behavior of “[^” bracket expressions and “.”. In this mode “^” matches an empty string after any newline in addition to its normal function, and “$” matches an empty string before any newline in addition to its normal function.
TCL_REG_NOSUB
Compile for matching that reports only success or failure, not what was matched. This reduces compile overhead and may improve performance. Subsequent calls to Tcl_RegExpGetInfo or Tcl_RegExpRange will not report any match information.
TCL_REG_CANMATCH
Compile for matching that reports the potential to complete a partial match given more text (see below).

Only one of TCL_REG_EXTENDED, TCL_REG_ADVANCED, TCL_REG_BASIC, and TCL_REG_QUOTE may be specified.

Tcl_RegExpExecObj executes the regular expression pattern matcher. It returns 1 if objPtr contains a range of characters that match regexp, 0 if no match is found, and -1 if an error occurs. In the case of an error, Tcl_RegExpExecObj leaves an error message in the interpreter result. The nmatches value indicates to the matcher how many subexpressions are of interest. If nmatches is 0, then no subexpression match information is recorded, which may allow the matcher to make various optimizations. If the value is -1, then all of the subexpressions in the pattern are remembered. If the value is a positive integer, then only that number of subexpressions will be remembered. Matching begins at the specified Unicode character index given by offset. Unlike Tcl_RegExpExec, the behavior of anchors is not affected by the offset value. Instead the behavior of the anchors is explicitly controlled by the eflags argument, which is a bit-wise OR of zero or more of the following flags:

TCL_REG_NOTBOL
The starting character will not be treated as the beginning of a line or the beginning of the string, so “^” will not match there. Note that this flag has no effect on how “\A” matches.
TCL_REG_NOTEOL
The last character in the string will not be treated as the end of a line or the end of the string, so “$” will not match there. Note that this flag has no effect on how “\Z” matches.

Tcl_RegExpGetInfo retrieves information about the last match performed with a given regular expression regexp. The infoPtr argument contains a pointer to a structure that is defined as follows:

typedef struct Tcl_RegExpInfo {
    int nsubs;
    Tcl_RegExpIndices *matches;
    long extendStart;
} Tcl_RegExpInfo;

The nsubs field contains a count of the number of parenthesized subexpressions within the regular expression. If the TCL_REG_NOSUB was used, then this value will be zero. The matches field points to an array of nsubs+1 values that indicate the bounds of each subexpression matched. The first element in the array refers to the range matched by the entire regular expression, and subsequent elements refer to the parenthesized subexpressions in the order that they appear in the pattern. Each element is a structure that is defined as follows:

typedef struct Tcl_RegExpIndices {
    long start;
    long end;
} Tcl_RegExpIndices;

The start and end values are Unicode character indices relative to the offset location within objPtr where matching began. The start index identifies the first character of the matched subexpression. The end index identifies the first character after the matched subexpression. If the subexpression matched the empty string, then start and end will be equal. If the subexpression did not participate in the match, then start and end will be set to -1.

The extendStart field in Tcl_RegExpInfo is only set if the TCL_REG_CANMATCH flag was used. It indicates the first character in the string where a match could occur. If a match was found, this will be the same as the beginning of the current match. If no match was found, then it indicates the earliest point at which a match might occur if additional text is appended to the string. If it is no match is possible even with further text, this field will be set to -1.
