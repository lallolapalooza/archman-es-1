ARGUMENTOS

Tcl_Interp *interp (entrada)
Intérprete al que se aplica el límite que se está gestionando o cuyos límites se van a comprobar.
int type (entrada)
El tipo de límite al que se refiere la operación. Debe ser TCL_LIMIT_COMMANDS o TCL_LIMIT_TIME.
int commandLimit (entrada)
El número máximo de comandos (según lo informado por info cmdcount) que pueden ejecutarse en el intérprete.
Tcl_Time *timeLimitPtr (entrada/salida)
Un puntero a una estructura de la que se leerá el nuevo límite de tiempo (Tcl_LimitSetTime) o se escribirá el límite de tiempo actual (Tcl_LimitGetTime).
int granularity (entrada)
Divisor que indica con qué frecuencia se debe comprobar realmente un límite determinado. Debe ser al menos 1.
Tcl_LimitHandlerProc *handlerProc (entrada)
Función a llamar cuando se excede un límite determinado. Si el handlerProc elimina o eleva el límite durante su procesamiento, se permitirá al intérprete limitado continuar procesando después de que el manejador devuelva el control. Se pueden adjuntar muchos manejadores al mismo límite del intérprete; su orden de ejecución no está definido y deben ser identificados por handlerProc y clientData cuando se eliminen.
ClientData clientData (entrada)
Palabra de tamaño de puntero arbitrario utilizada para pasar algún contexto a la función handlerProc.
Tcl_LimitHandlerDeleteProc *deleteProc (entrada)
Función a llamar cada vez que se elimina un manejador. Puede ser NULL si el clientData no requiere ninguna eliminación.

DESCRIPCIÓN

El subsistema de límites de recursos del intérprete de Tcl permite un control estricto sobre la cantidad de tiempo de cálculo que puede utilizar un script, y es útil para casos en los que un programa se divide en varias partes, algunas de las cuales son más confiables que otras (por ejemplo, servidores de aplicaciones web).

Cada intérprete puede tener un límite en el tiempo de ejecución real (wall-time) y un límite en el número de comandos que el intérprete puede ejecutar. Dado que la comprobación de estos límites puede ser costosa (especialmente el límite de tiempo), cada límite tiene también una granularidad de comprobación, que es un divisor de un contador interno del número de puntos del núcleo donde se puede realizar una comprobación (que es inmediatamente antes de ejecutar un comando y con una frecuencia no especificada entre la ejecución de comandos, que puede ocurrir en bucles while vacíos).

El componente final del motor de límites es un esquema de devolución de llamadas que permite notificaciones cuando se ha excedido un límite. Estas devoluciones de llamadas pueden simplemente proporcionar registro, o pueden asignar más recursos al intérprete para permitirle continuar procesando por más tiempo.

Cuando se excede un límite (y las devoluciones de llamadas se han ejecutado; el orden de ejecución de las devoluciones de llamadas no está definido), la ejecución en el intérprete limitado se detiene generando un error y estableciendo una bandera que impide que el comando catch en ese intérprete atrape ese error. Depende del contexto que inició la ejecución en ese intérprete (típicamente el intérprete principal) manejar el error.

API DE COMPROBACIÓN DE LÍMITES

Para comprobar los límites de recursos de un intérprete, llame a Tcl_LimitCheck, que devuelve TCL_OK si el límite no se ha excedido (después de procesar las devoluciones de llamadas) y TCL_ERROR si el límite se ha excedido (en cuyo caso también se coloca un mensaje de error en el resultado del intérprete). Esa función solo debe llamarse cuando Tcl_LimitReady devuelve un valor distinto de cero para que se aplique la política de granularidad. Esta API está diseñada para ser similar en uso a Tcl_AsyncReady y Tcl_AsyncInvoke.

Al escribir código que puede comportarse como catch con respecto a los errores, solo debe atrapar un error si Tcl_LimitExceeded devuelve cero. Si devuelve un valor distinto de cero, el intérprete está en un estado de límite excedido y se debe permitir que los errores se propaguen al contexto que llama. También puede comprobar si un tipo particular de límite se ha excedido utilizando Tcl_LimitTypeExceeded.

CONFIGURACIÓN DE LÍMITES

Para comprobar si un límite se ha establecido (pero no si realmente se ha excedido) en un intérprete, llame a Tcl_LimitTypeEnabled con el tipo de límite que desea comprobar. Para habilitar un límite particular, llame a Tcl_LimitTypeSet, y para deshabilitar un límite, llame a Tcl_LimitTypeReset.

El nivel de un límite de comandos puede establecerse utilizando Tcl_LimitSetCommands, y recuperarse utilizando Tcl_LimitGetCommands. De manera similar para un límite de tiempo con Tcl_LimitSetTime y Tcl_LimitGetTime respectivamente, pero con esa API el límite de tiempo se copia desde y hacia la estructura Tcl_Time a la que apunta el argumento timeLimitPtr.

La granularidad de comprobación para un límite particular puede establecerse utilizando Tcl_LimitSetGranularity y recuperarse utilizando Tcl_LimitGetGranularity. Tenga en cuenta que las granularidades deben ser siempre positivas.

DEVOLUCIONES DE LLAMADA DE LÍMITES

Para añadir una devolución de llamada de manejador que se invocará cuando se exceda un límite, llame a Tcl_LimitAddHandler. El argumento handlerProc describe la función que se llamará realmente; debe tener el siguiente prototipo:

typedef void Tcl_LimitHandlerProc(
        ClientData clientData,
        Tcl_Interp *interp);

El argumento clientData del manejador será lo que se pase al argumento clientData a Tcl_LimitAddHandler, y el interp es el intérprete cuyo límite se ha excedido.

El argumento deleteProc a Tcl_LimitAddHandler es una función que se llamará para eliminar el valor clientData. Puede ser TCL_STATIC o NULL si no es necesaria ninguna acción de eliminación, o TCL_DYNAMIC si lo único necesario es liberar la estructura con Tcl_Free. De lo contrario, debe referirse a una función con el siguiente prototipo:

typedef void Tcl_LimitHandlerDeleteProc(
        ClientData clientData);

Un manejador de límites puede eliminarse utilizando Tcl_LimitRemoveHandler; el manejador que se elimine será el primero que se encuentre (de los manejadores añadidos con Tcl_LimitAddHandler) con los argumentos type, handlerProc y clientData que coincidan exactamente. Esta función siempre invoca el deleteProc en el clientData (a menos que el deleteProc fuera NULL o TCL_STATIC).

NAME

Tcl_LimitTypeSet - Configure the resource limits for a Tcl interpreter.

SINOPSIS

#include <tcl.h>

int
Tcl_LimitTypeSet(
    Tcl_Interp *interp,
    int resourceType,
    Tcl_Time *period,
    int count
)

ARGUMENTOS

Tcl_Interp *interp (in)
Interpreter to modify.
int resourceType (in)
Specifies the type of resource limit to configure. See LIMIT CONFIGURATION below.
Tcl_Time *period (in)
Pointer to a Tcl_Time structure specifying the time period (in seconds and nanoseconds) over which the resource limit is enforced. If NULL, the limit is enforced instantaneously.
int count (in)
Specifies the maximum number of times the resource may be used within the given time period.

DESCRIPTION

The Tcl_LimitTypeSet procedure configures the resource limits for a Tcl interpreter. Resource limits are used to control the consumption of system resources by Tcl scripts. This procedure allows you to set the maximum number of times a particular resource can be used within a specified time period.

The resourceType argument specifies the type of resource limit to configure. The following resource types are available:

TCL_LIMIT_CPU_TIME
Limits the total CPU time (in seconds) that can be consumed by Tcl scripts. The period argument is ignored for this resource type. The count argument specifies the maximum CPU time allowed.
TCL_LIMIT_MEMORY_USAGE
Limits the maximum amount of memory (in bytes) that can be allocated by Tcl scripts. The period argument is ignored for this resource type. The count argument specifies the maximum memory usage allowed.
TCL_LIMIT_PROCEDURES
Limits the number of procedure calls that can be made within a given time period. The period argument specifies the time period, and the count argument specifies the maximum number of procedure calls allowed.
TCL_LIMIT_EVENTS
Limits the number of event handlers that can be invoked within a given time period. The period argument specifies the time period, and the count argument specifies the maximum number of event handlers allowed.
TCL_LIMIT_SOURCES
Limits the number of source commands that can be executed within a given time period. The period argument specifies the time period, and the count argument specifies the maximum number of source commands allowed.
TCL_LIMIT_OPERATIONS
Limits the number of arbitrary operations that can be performed within a given time period. The period argument specifies the time period, and the count argument specifies the maximum number of operations allowed.

If period is NULL, the limit is enforced instantaneously. For example, setting TCL_LIMIT_PROCEDURES with period as NULL and count to 100 would mean that no more than 100 procedures can be called in total before the limit is reached.

If period is not NULL, the limit is enforced over the specified time interval. For example, setting TCL_LIMIT_PROCEDURES with a period of 1 second and a count of 100 would mean that no more than 100 procedures can be called within any 1-second interval.

The Tcl_LimitTypeSet procedure returns TCL_OK if the resource limit was successfully configured, and TCL_ERROR otherwise.

LIMIT CHECKING API

The following functions are available for checking resource limits:

Tcl_LimitCheck(interp, resourceType)
Checks if the resource limit for the specified resourceType has been reached. Returns TCL_OK if the limit has not been reached, and TCL_ERROR otherwise.
Tcl_LimitTypeTimeRemaining(interp, resourceType)
Returns the remaining time (in seconds and nanoseconds) until the resource limit is reset. If the limit is not enforced over time, returns a Tcl_Time structure with both fields set to zero.
Tcl_LimitTypeCountRemaining(interp, resourceType)
Returns the remaining number of times the resource can be used before the limit is reached. If the limit is not enforced over time, returns the remaining count.

LIMIT CONFIGURATION

Resource limits can be configured using the limit command in Tcl scripts. The following is a list of available resource types and their corresponding command-line arguments:

cpu
Corresponds to TCL_LIMIT_CPU_TIME. Usage: limit cpu <seconds>
memory
Corresponds to TCL_LIMIT_MEMORY_USAGE. Usage: limit memory <bytes>
proc
Corresponds to TCL_LIMIT_PROCEDURES. Usage: limit proc <count> ?<period>?
event
Corresponds to TCL_LIMIT_EVENTS. Usage: limit event <count> ?<period>?
source
Corresponds to TCL_LIMIT_SOURCES. Usage: limit source <count> ?<period>?
operation
Corresponds to TCL_LIMIT_OPERATIONS. Usage: limit operation <count> ?<period>?

The period argument is optional and specifies the time interval in seconds. If omitted, the limit is enforced instantaneously.

KEYWORDS

limit, resource, interpreter, configure
