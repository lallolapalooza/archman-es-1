DESCRIPCIÓN

Estos procedimientos están pensados para acceder a la instalación de múltiples intérpretes desde programas C. Permiten gestionar múltiples intérpretes en una relación jerárquica, y la gestión de alias, comandos que al ser invocados en un intérprete ejecutan un comando en otro intérprete. El valor de retorno para aquellos procedimientos que devuelven un int es TCL_OK o TCL_ERROR. Si se devuelve TCL_ERROR, el resultado del intérprete contiene un mensaje de error.

Tcl_CreateSlave crea un nuevo intérprete como hijo de interp. También crea un comando hijo llamado childName en interp que permite a interp manipular al nuevo hijo. Si isSafe es cero, el comando crea un hijo confiable en el cual el código Tcl tiene acceso a todos los comandos Tcl. Si es 1, el comando crea un hijo "seguro" en el cual el código Tcl tiene acceso solo a un conjunto de comandos Tcl definidos como "Safe Tcl"; ver la entrada del manual para el comando interp de Tcl para más detalles. Si la creación del nuevo intérprete hijo falló, se devuelve NULL.

Tcl_CreateChild es un sinónimo de Tcl_CreateSlave.

Tcl_IsSafe devuelve 1 si interp es "seguro" (fue creado con el flag TCL_SAFE_INTERPRETER especificado), 0 en caso contrario.

Tcl_MakeSafe marca a interp como "seguro", para que las futuras llamadas a Tcl_IsSafe devuelvan 1. También elimina toda la funcionalidad central potencialmente insegura conocida (tanto comandos como variables) de interp. Sin embargo, no puede saber qué partes de una extensión o aplicación son seguras y no intenta eliminar esas partes, por lo que la seguridad no está garantizada después de llamar a Tcl_MakeSafe. Los llamadores querrán tener cuidado con su uso de Tcl_MakeSafe para evitar falsas afirmaciones de seguridad. Para muchas situaciones, Tcl_CreateSlave puede ser una mejor opción, ya que crea intérpretes en un estado de seguridad conocido.

Tcl_GetSlave devuelve un puntero a un intérprete hijo de interp. El intérprete hijo se identifica por childName. Si no existe dicho intérprete hijo, se devuelve NULL.

Tcl_GetChild es un sinónimo de Tcl_GetSlave.

Tcl_GetMaster devuelve un puntero al intérprete maestro de interp. Si interp no tiene maestro (es un intérprete de nivel superior), se devuelve NULL.

Tcl_GetParent es un sinónimo de Tcl_GetMaster.

Tcl_GetInterpPath almacena en el resultado de interp la ruta relativa entre interp y childInterp; childInterp debe ser un hijo de interp. Si el cálculo de la ruta relativa tiene éxito, se devuelve TCL_OK, de lo contrario se devuelve TCL_ERROR y se almacena un mensaje de error como resultado de interp.

Tcl_CreateAlias crea un comando llamado childCmd en childInterp que, al ser invocado, hará que el comando targetCmd sea invocado en targetInterp. Los argumentos especificados por las cadenas contenidas en argv siempre se anteponen a cualquier argumento suministrado en la invocación de childCmd y se pasan a targetCmd. Esta operación devuelve TCL_OK si tiene éxito, o TCL_ERROR si falla; en ese caso, se deja un mensaje de error en el resultado del valor de childInterp. Tenga en cuenta que no hay restricciones en la relación de ascendencia (tal como se creó con Tcl_CreateSlave) entre childInterp y targetInterp. Se pueden usar dos intérpretes cualesquiera, sin restricciones sobre cómo están relacionados.

Tcl_CreateAliasObj es similar a Tcl_CreateAlias excepto que toma un vector de valores para pasar como argumentos adicionales en lugar de un vector de cadenas.

Tcl_GetAliasObj devuelve información en forma de un puntero a un vector de estructuras Tcl_Obj sobre un alias aliasName en interp. Cualquiera de los campos de resultado puede ser NULL, en cuyo caso el dato correspondiente no se devuelve. Si un campo de resultado no es NULL, la dirección indicada se establece en el dato correspondiente. Por ejemplo, si targetCmdPtr no es NULL, se establece en un puntero a la cadena que contiene el nombre del comando de destino.

Tcl_GetAlias es similar a Tcl_GetAliasObj excepto que devuelve un puntero a un vector de cadenas en lugar de un vector de estructuras Tcl_Obj. Tcl_GetAlias está obsoleto.

Tcl_HideCommand oculta el comando cmdName en interp, y lo pone a disposición bajo el nombre hiddenCmdName. Esto es útil para hacer que un comando esté disponible en un intérprete hijo sin permitir que el código del hijo lo invalide o lo elimine.

Tcl_ExposeCommand deshace la acción de Tcl_HideCommand. El comando que previamente se puso a disposición bajo el nombre hiddenCmdName ahora está disponible bajo el nombre cmdName.

NOMBRE

Tcl_ExposeCommand, Tcl_HideCommand - ocultar o exponer comandos de Tcl

SINOPSIS

#include <tcl.h>

int
Tcl_ExposeCommand(
    Tcl_Interp *interp,
    const char *hiddenCmdName,
    const char *cmdName);
int
Tcl_HideCommand(
    Tcl_Interp *interp,
    const char *cmdName,
    const char *hiddenCmdName);

ARGUMENTOS

-

Nombre de la interfaz para comandos de Tcl que ocultan o exponen comandos.

DESCRIPCIÓN

Estas dos funciones de la API del intérprete de Tcl proporcionan un mecanismo para mover comandos entre el conjunto de comandos ocultos y el conjunto de comandos expuestos.

Tcl_ExposeCommand mueve el comando llamado hiddenCmdName del conjunto de comandos ocultos al conjunto de comandos expuestos, poniéndolo bajo el nombre cmdName. HiddenCmdName debe ser el nombre de un comando oculto existente, o la operación devolverá TCL_ERROR y dejará un mensaje de error como resultado de interp. Si ya existe un comando expuesto llamado cmdName, la operación devuelve TCL_ERROR y deja un mensaje de error como resultado de interp. Si la operación tiene éxito, devuelve TCL_OK. Después de ejecutar este comando, los intentos de usar cmdName en cualquier mecanismo de evaluación de scripts volverán a tener éxito.

Tcl_HideCommand mueve el comando llamado cmdName del conjunto de comandos expuestos al conjunto de comandos ocultos, bajo el nombre hiddenCmdName. CmdName debe ser el nombre de un comando expuesto existente, o la operación devolverá TCL_ERROR y dejará un mensaje de error como resultado de interp. Actualmente, ni cmdName ni hiddenCmdName deben contener calificadores de espacio de nombres, o la operación devolverá TCL_ERROR y dejará un mensaje de error como resultado de interp. CmdName se buscará en el espacio de nombres global y no en relación con el espacio de nombres actual, incluso si el espacio de nombres actual no es el global. Si ya existe un comando oculto cuyo nombre es hiddenCmdName, la operación también devuelve TCL_ERROR y se deja un mensaje de error como resultado de interp. Si la operación tiene éxito, devuelve TCL_OK. Después de ejecutar este comando, los intentos de usar cmdName en cualquier mecanismo de evaluación de scripts fallarán.

Para obtener una descripción de la interfaz Tcl para múltiples intérpretes, consulte interp(n).
