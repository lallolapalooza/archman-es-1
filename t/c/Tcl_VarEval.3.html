Tcl_VarEval(3) Procedimientos de la librería Tcl Tcl_VarEval(3)

NOMBRE

Tcl_VarEvalObjEx, Tcl_VarEvalFile, Tcl_VarEvalObjv, Tcl_VarEval, Tcl_VarEvalEx, Tcl_GlobalEval, Tcl_GlobalEvalObj, Tcl_EvalVar, Tcl_EvalVarVA - ejecutar scripts Tcl

SINOPSIS

#include <tcl.h>

int
Tcl_VarEvalObjEx(interp, objPtr, flags)

int
Tcl_VarEvalFile(interp, fileName)

int
Tcl_VarEvalObjv(interp, objc, objv, flags)

int
Tcl_VarEval(interp, script)

int
Tcl_VarEvalEx(interp, script, numBytes, flags)

int
Tcl_GlobalEval(interp, script)

int
Tcl_GlobalEvalObj(interp, objPtr)

int
Tcl_EvalVar(interp, part, part, ... (char *)NULL)

int
Tcl_EvalVarVA(interp, argList)

ARGUMENTOS

Tcl_Interp *interp (entrada)
Intérprete en el cual se ejecuta el script. El resultado del intérprete se modifica para almacenar el resultado o mensaje de error del script.
Tcl_Obj *objPtr (entrada)
Valor Tcl que contiene el script a ejecutar.
int flags (entrada)
Combinación OR de bits de flag que especifican opciones adicionales. Actualmente se soportan TCL_EVAL_GLOBAL y TCL_EVAL_DIRECT.
const char *fileName (entrada)
Nombre de un archivo que contiene un script Tcl.
int objc (entrada)
El número de valores en el array apuntado por objv; este es también el número de palabras en el comando.
Tcl_Obj **objv (entrada)
Puntero a un array de punteros a valores; cada valor contiene el valor de una palabra en el comando a ejecutar.
int numBytes (entrada)
El número de bytes en script, sin incluir ningún carácter de terminación nula. Si es -1, entonces se usan todos los caracteres hasta el primer carácter nulo.
const char *script (entrada)
Puntero al primer byte del script a ejecutar (nulo terminado y UTF-8).
const char *part (entrada)
Cadena que forma parte de un script Tcl.
va_list argList (entrada)
Una lista de argumentos que debe haber sido inicializada usando va_start, y limpiada usando va_end.

DESCRIPCIÓN

Los procedimientos descritos aquí se invocan para ejecutar scripts Tcl en diversos formatos. Tcl_VarEvalObjEx es el procedimiento principal y es utilizado por muchos de los otros. Ejecuta las instrucciones del script almacenado en objPtr hasta que ocurra un error o se alcance el final del script. Si es la primera vez que objPtr se ejecuta, sus instrucciones se compilan en instrucciones de bytecode que luego se ejecutan. Los bytecodes se guardan en objPtr para que el paso de compilación pueda ser omitido si el valor se evalúa de nuevo en el futuro.

El valor de retorno de Tcl_VarEvalObjEx (y todos los otros procedimientos descritos aquí) es un código de finalización Tcl con uno de los valores TCL_OK, TCL_ERROR, TCL_RETURN, TCL_BREAK o TCL_CONTINUE, o cualquier valor entero que pueda provenir de una extensión. Además, un valor de resultado o mensaje de error se deja en el resultado de interp; puede ser recuperado usando Tcl_GetObjResult.

Tcl_VarEvalFile lee el archivo dado por fileName y evalúa su contenido como un script Tcl. Devuelve la misma información que Tcl_VarEvalObjEx. Si el archivo no puede ser leído, se devuelve un error Tcl para describir por qué el archivo no puede ser leído. El carácter de fin de archivo para archivos es «^Z» para todos los sistemas. Si necesita un «^Z» en código para comparaciones de cadenas, puede usar «\032» o «\u001a» que serán sustituidos de forma segura por el intérprete Tcl en «^Z».

Tcl_VarEvalObjv ejecuta un comando pre-procesado en lugar de un script. objc y objv contienen los valores de las palabras del comando Tcl, una palabra por valor en objv. Tcl_VarEvalObjv evalúa el comando y devuelve un código de finalización y resultado como Tcl_VarEvalObjEx. El llamador de Tcl_VarEvalObjv debe gestionar el contador de referencias de los elementos de objv, asegurando que los valores sean válidos hasta que Tcl_VarEvalObjv devuelva.

Tcl_Eval es similar a Tcl_VarEvalObjEx excepto que el script a ejecutar se proporciona como una cadena en lugar de un valor y no hay compilación. La cadena debe ser una cadena UTF-8 adecuadamente convertida por Tcl_ExternalToUtfDString o Tcl_ExternalToUtf cuando se sabe que el script podría contener caracteres ASCII mayúsculas cuyas combinaciones podrían ser un código especial UTF-8. La cadena se procesa y se ejecuta directamente (usando Tcl_EvalObjv) en lugar de compilarla y ejecutar las instrucciones de bytecode. En situaciones donde se sabe que el script no será ejecutado de nuevo, Tcl_Eval puede ser más rápido que Tcl_VarEvalObjEx.


Tcl_Eval devuelve un código de finalización y resultado como Tcl_VarEvalObjEx. Nota: para compatibilidad con versiones anteriores de Tcl antes de 8.0, Tcl_Eval copia el valor resultado en interp a interp->result (su uso está desaconsejado) donde puede ser accedido directamente.


Esto hace que Tcl_Eval sea un poco más lento que Tcl_EvalEx, que no realiza la copia.

Tcl_EvalEx es una versión extendida de Tcl_Eval que toma argumentos adicionales numBytes y flags. Dada la razón de eficiencia anterior, Tcl_EvalEx es generalmente preferido sobre Tcl_Eval.

Tcl_GlobalEval y Tcl_GlobalEvalObj son procedimientos antiguos que ahora han sido descontinuados. Son similares a Tcl_EvalEx y Tcl_VarEvalObjEx excepto que el script se evalúa en el espacio de nombres global y su contexto de variables consiste en variables globales (ignora cualquier procedimiento Tcl activo). Estas funciones son equivalentes a usar el flag TCL_EVAL_GLOBAL (ver más abajo).

Tcl_VarEval toma cualquier número de argumentos de cadena de cualquier longitud, concatenándolos en una sola cadena, y luego llama a Tcl_Eval para ejecutar esa cadena como un comando Tcl. Devuelve el resultado del comando y también modifica interp->result de la misma manera que Tcl_Eval. El último argumento a Tcl_VarEval debe ser (char *)NULL para indicar el fin de los argumentos.

Tcl_VarEvalVA es lo mismo que Tcl_VarEval excepto que utiliza una lista de argumentos en lugar de un número variable de argumentos. Tcl_VarEvalVA ahora está descontinuado.

BITS DE FLAG

Cualquier combinación OR de los siguientes valores puede usarse para el argumento flags de procedimientos como Tcl_VarEvalObjEx:

TCL_EVAL_DIRECT
Este bit de flag solo lo usa Tcl_VarEvalObjEx; es ignorado por otros procedimientos. Si este bit está activo, el script no se compila en instrucciones de bytecode; en su lugar, se ejecuta directamente como lo hace Tcl_EvalEx. El flag TCL_EVAL_DIRECT es útil en situaciones donde el contenido de un valor va a cambiar inmediatamente, por lo que las instrucciones de bytecode no se reutilizarán en futuras ejecuciones. En este caso, es más rápido ejecutar el script directamente.
TCL_EVAL_GLOBAL
Si este bit está activo, el script se evalúa en el espacio de nombres global en lugar del espacio de nombres actual y su contexto de variables consiste en variables globales (ignora cualquier procedimiento Tcl activo). Estos procedimientos son equivalentes a usar el flag TCL_EVAL_GLOBAL (ver más abajo).

DETALLES DIVERSOS

Durante el procesamiento de un comando Tcl, es legítimo hacer llamadas anidadas para evaluar otros comandos (así es como se implementan las funciones y algunos controladores de estructuras). Si se devuelve un código que no es TCL_OK de una invocación anidada de Tcl_VarEvalObjEx, el llamador debería devolver normalmente inmediatamente, pasando el mismo código de retorno a su llamador, y así sucesivamente hasta que se alcance el aplicativo de nivel superior. Algunos comandos, como for, revisarán ciertos códigos de retorno, como TCL_BREAK y TCL_CONTINUE, y los procesarán de manera especial sin devolver.

Tcl_VarEvalObjEx mantiene un conteo de invocaciones anidadas de Tcl_VarEvalObjEx en progreso para interp. Si se va a devolver un código de retorno como TCL_RETURN, TCL_BREAK o TCL_CONTINUE desde la invocación más alta de Tcl_VarEvalObjEx para interp, se convierte el código de retorno en TCL_ERROR y se establece el resultado de interp como un mensaje de error indicando que se ha ejecutado el return, break

Tcl_VarEval

NAME

Tcl_VarEval, Tcl_EvalObjEx, Tcl_EvalEx, Tcl_Eval - evaluate Tcl commands

SYNOPSIS

#include <tcl.h>

int
Tcl_VarEval(interp, string, length, resultPtr)
void
Tcl_EvalObjEx(interp, objPtr, flags)
void
Tcl_EvalEx(interp, string, length, flags)
int
Tcl_Eval(interp, string)

ARGUMENTS

Tcl_Interp *interp
Interpreter in which to evaluate the script.
const char *string
String containing Tcl commands to evaluate.
int length
Length of string. If -1, then string is null-terminated.
Tcl_Obj **resultPtr
If not NULL, the result of the evaluation is stored in the object pointed to by this pointer. If NULL, the result is stored in the interpreter's result managment structure and can be retrieved using Tcl_GetStringResult or Tcl_GetObjResult.
Tcl_Obj *objPtr
An object containing Tcl commands to evaluate.
int flags
A bitmask of flag bits. The only defined flag bit is TCL_EVAL_GLOBAL.

DESCRIPTION

These functions are used to execute Tcl scripts within an interpreter.

Tcl_VarEval is the original Tcl evaluation function. It takes a string containing Tcl commands and evaluates it in the specified interpreter, interp. If resultPtr is not NULL, the result of the evaluation is stored in the object pointed to by resultPtr. Otherwise, the result is stored in the interpreter's result management structure.

Tcl_EvalObjEx is the modern, object-based interface for evaluating Tcl scripts. It takes an object, objPtr, containing the Tcl commands to evaluate, and evaluates them in the interpreter interp. The flags argument is a bitmask that can be used to modify the behavior of the evaluation. Currently, the only defined flag is TCL_EVAL_GLOBAL.

Tcl_EvalEx is similar to Tcl_VarEval, but it takes an object as its first argument, objPtr, containing the Tcl commands to evaluate. The flags argument is the same as for Tcl_EvalObjEx.

Tcl_Eval is a simplified interface that evaluates a null-terminated string in the interpreter's result management structure.

The return value of these functions is one of the standard Tcl return codes:

TCL_OK
The script executed successfully.
TCL_ERROR
An error occurred during execution. The error message can be retrieved using Tcl_GetObjResult.
TCL_RETURN
The script executed a return command.
TCL_BREAK
The script executed a break command.
TCL_CONTINUE
The script executed a continue command.

Top-level applications should typically only expect to see TCL_OK or TCL_ERROR as return codes from these functions. Other return codes indicate that a control flow command (like return, break, or continue) was invoked in an inappropriate place. This means that top-level applications should never see a return code from Tcl_EvalObjEx other than TCL_OK or TCL_ERROR.

FLAG BITS

TCL_EVAL_GLOBAL
If this flag is set, the script is evaluated in the global context of the interpreter, regardless of the current namespace. This is equivalent to executing the script preceded by the “global” command.

MISCELLANEOUS DETAILS

When Tcl_EvalObjEx, Tcl_EvalEx, or Tcl_VarEval is invoked, the Tcl interpreter's result is cleared. If the script being evaluated invokes a control flow command (e.g., return, break, or continue) in an inappropriate place, this will result in a non-TCL_OK return code. For example, a break command will produce a TCL_BREAK return code if it is executed outside of a loop. A top-level application should never see a return code from Tcl_EvalObjEx other than TCL_OK or TCL_ERROR.

KEYWORDS

execute, file, global, result, script, value
