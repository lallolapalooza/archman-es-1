Tcl_ParseVar(3) Procedimientos de la biblioteca Tcl Tcl_ParseVar(3)

NOMBRE

Tcl_ParseVar, Tcl_ParseExpr, Tcl_ParseBraces, Tcl_ParseQuotedString, Tcl_ParseVarName, Tcl_ParseVar, Tcl_FreeParse, Tcl_EvalTokens, Tcl_EvalTokensStandard - analizar scripts y expresiones de Tcl

SINOPSIS

#include <tcl.h>

int
Tcl_ParseVar(interp, start, termPtr)

int
Tcl_ParseExpr(interp, start, numBytes, parsePtr)

int
Tcl_ParseBraces(interp, start, numBytes, parsePtr, append, termPtr)

int
Tcl_ParseQuotedString(interp, start, numBytes, parsePtr, append, termPtr)

int
Tcl_ParseVarName(interp, start, numBytes, parsePtr, append)

const char *
Tcl_ParseVar(interp, start, termPtr)

Tcl_FreeParse(usedParsePtr)

Tcl_Obj *
Tcl_EvalTokens(interp, tokenPtr, numTokens)

int
Tcl_EvalTokensStandard(interp, tokenPtr, numTokens)

ARGUMENTOS

Tcl_Interp *interp (salida)
Para procedimientos distintos de Tcl_FreeParse, Tcl_EvalTokens y Tcl_EvalTokensStandard, utilizado solo para la notificación de errores; si es NULL, no se muestran mensajes de error después de un error. Para Tcl_EvalTokens y Tcl_EvalTokensStandard, determina el contexto para la evaluación del script y también se utiliza para la notificación de errores; no puede ser NULL.
const char *start (entrada)
Puntero al primer carácter de la cadena a analizar.
int numBytes (entrada)
Número de bytes en la cadena a analizar, sin incluir el carácter nulo. Si es menor que 0, el script consiste en todos los caracteres siguientes a start hasta el primer carácter nulo.
int nested (entrada)
Un valor distinto de cero significa que el script es parte de una sustitución de comando, por lo que un corchete de cierre sin etiquetar debe tratarse como un terminador de comando. Si es cero, los corchetes de cierre no tienen significado especial.
int append (entrada)
Un valor distinto de cero significa que *parsePtr ya contiene tokens válidos; los nuevos tokens deben añadirse a los existentes. Cero significa que *parsePtr se inicializa; cualquier información en él se ignora. Este argumento es normalmente 0.
Tcl_Parse *parsePtr (salida)
Puntero a la estructura que se llenará con información sobre la estructura del comando, la expresión, el nombre de la variable, etc. Se ignora cualquier información previa en esta estructura, a menos que el argumento append sea distinto de cero en una llamada a Tcl_ParseBraces, Tcl_ParseQuotedString o Tcl_ParseVarName.
const char **termPtr (salida)
Si no es NULL, apunta a una ubicación donde Tcl_ParseBraces, Tcl_ParseQuotedString y Tcl_ParseVar almacenarán un puntero al carácter justo después del carácter de terminación (el corchete de cierre, el último carácter del nombre de la variable o el cierre de comillas, respectivamente) si el análisis fue exitoso.
Tcl_Parse *usedParsePtr (entrada)
Puntero a la estructura que fue llenada por una llamada previa a Tcl_ParseCommand, Tcl_ParseExpr, Tcl_ParseVarName, etc.

DESCRIPCIÓN

Estos procedimientos analizan comandos de Tcl o partes de comandos de Tcl, como expresiones o referencias a variables. Cada procedimiento toma un puntero a un script (o parte de él) y lo llena con un conjunto de tokens que describen la información que se analizó. Los procedimientos normalmente devuelven TCL_OK. Sin embargo, si ocurre un error, devuelven TCL_ERROR, dejan un mensaje de error en el resultado de interp (si interp no es NULL) y no dejan nada en *parsePtr.

Tcl_ParseCommand es un procedimiento que analiza scripts de Tcl. Dado un puntero a un script, analiza el primer comando del script. Si el comando se analizó correctamente, Tcl_ParseCommand devuelve TCL_OK y llena la estructura apuntada por parsePtr con información sobre la estructura del comando (ver detalles más abajo). Si ocurrió un error durante el análisis del comando, devuelve TCL_ERROR, deja un mensaje de error en el resultado de interp y no deja nada en *parsePtr.

Tcl_ParseExpr analiza expresiones de Tcl. Dado un puntero a un script que contiene una expresión, Tcl_ParseExpr analiza la expresión. Si la expresión se analizó correctamente, Tcl_ParseExpr devuelve TCL_OK y llena la estructura apuntada por parsePtr con información sobre la estructura de la expresión (ver detalles más abajo). Si ocurrió un error durante el análisis, devuelve TCL_ERROR, deja un mensaje de error en el resultado de interp y no deja nada en *parsePtr.

Tcl_ParseBraces analiza una cadena o argumento de comando delimitado por corchetes, como {hola} o {cadena \t con \t tabulaciones}, desde el principio de su argumento start. El primer carácter de start debe ser {. Si la cadena delimitada por corchetes se analizó correctamente, Tcl_ParseBraces devuelve TCL_OK, llena la estructura apuntada por parsePtr con información sobre la estructura de la cadena (ver detalles más abajo) y almacena un puntero al carácter justo después del corchete de cierre en la ubicación proporcionada por *termPtr. Si ocurre un error durante el análisis de la cadena, devuelve TCL_ERROR, deja un mensaje de error en el resultado de interp y no deja nada en *parsePtr o *termPtr.

Tcl_ParseQuotedString analiza una cadena entre comillas dobles, como "la suma es [expr {$a+$b}]", desde el principio de su argumento start. El primer carácter de start debe ser ". Si la cadena entre comillas dobles se analizó correctamente, Tcl_ParseQuotedString devuelve TCL_OK, llena la estructura apuntada por parsePtr con información sobre la estructura de la cadena (ver detalles más abajo) y almacena un puntero al carácter justo después del cierre de la cadena entre comillas dobles en la ubicación proporcionada por *termPtr. Si ocurre un error durante el análisis de la cadena, devuelve TCL_ERROR, deja un mensaje de error en el resultado de interp y no deja nada en *parsePtr o *termPtr.

Tcl_ParseVarName analiza una referencia a una variable Tcl, como $abc o $x([expr {$índice + 1}]), desde el principio de su argumento start. El primer carácter de start debe ser $. Si la variable se analizó correctamente, Tcl_ParseVarName devuelve TCL_OK y llena la estructura apuntada por parsePtr con información sobre la estructura de la variable (ver detalles más abajo). Si ocurre un error durante el análisis del comando, devuelve TCL_ERROR, deja un mensaje de error en el resultado de interp (si interp no es NULL) y no deja nada en *parsePtr.

Tcl_ParseVar analiza una referencia a una variable Tcl, como $abc o $x([expr {$índice + 1}]), desde el principio de su argumento start. El primer carácter de start debe ser $. Si la variable se analizó correctamente, Tcl_ParseVar devuelve un puntero al valor de la variable. Si ocurre un error durante el análisis, devuelve NULL y un mensaje de error en el resultado de interp.

La información almacenada en *parsePtr por Tcl_ParseCommand, Tcl_ParseExpr, Tcl_ParseBraces, Tcl_ParseQuotedString y Tcl_ParseVarName puede incluir memoria dinámica. Si estos cinco procedimientos de análisis devuelven TCL_OK, el llamador debe invocar Tcl_FreeParse para liberar la memoria en *parsePtr. Estos procedimientos ignoran cualquier información existente en *parsePtr (a menos que el argumento append sea distinto de cero), por lo que si se realizan varias llamadas a cualquiera de ellos, Tcl_FreeParse debe invocarse una vez después de cada llamada.

Tcl_EvalTokensStandard evalúa una secuencia de tokens analizados de una estructura de Tcl. Los tokens normalmente consisten en todos los tokens de una palabra o todos los tokens que componen el índice de una referencia a una variable de tipo array. Tcl_EvalTokensStandard realiza las sustituciones solicitadas por los tokens y concatena los valores resultantes. El valor devuelto por Tcl_EvalTokensStandard es un código de finalización de Tcl con uno de los valores TCL_OK, TCL_ERROR, TCL_RETURN, TCL_BREAK o TCL_CONTINUE, o tal valor podría ser otro número que provenga de una extensión. Además, un valor de resultado o un mensaje de error se deja en el resultado de interp; puede recuperarse utilizando Tcl_GetObjResult.

Tcl_EvalTokens difiere de Tcl_EvalTokensStandard solo en la convención de retorno.

ESTRUCTURA TCL_PARSE

Tcl_ParseCommand, Tcl_ParseExpr, Tcl_ParseBraces, Tcl_ParseQuotedString y Tcl_ParseVarName devuelven información de análisis en dos estructuras de datos, Tcl_Parse y Tcl_Token:

typedef struct Tcl_Parse {
    const char *commentStart;
    int commentSize;
    const char *commandStart;
    int commandSize;
    int numWords;
    Tcl_Token *tokenPtr;
    int numTokens;
    ...
} Tcl_Parse;
typedef struct Tcl_Token {
    int type;
    const char *start;
    int size;
    int numComponents;
} Tcl_Token;

Los primeros cinco campos de una estructura Tcl_Parse se completan únicamente por Tcl_ParseCommand. Estos campos no son utilizados por los otros procedimientos de análisis.

Tcl_ParseCommand completa una estructura Tcl_Parse con información que describe un comando Tcl y cualquier comentario que preceda al comando. Si hay comentarios, el campo commentStart apunta al carácter # que inicia el primer comentario y commentSize indica el número de bytes en todos los comentarios que preceden al comando, incluido el carácter de nueva línea que termina el último comentario. Si el comando no va precedido de comentarios, commentSize es 0. Tcl_ParseCommand también establece el campo commandStart para que apunte al primer carácter de la primera palabra del comando (ignorando comentarios y espacios iniciales) y commandSize da el número total de bytes en el comando, incluido el carácter apuntado por commandStart hasta e incluyendo el carácter de nueva línea, corchete de cierre o punto y coma que termina el comando. El campo numWords da el número total de palabras en el comando.

Todos los procedimientos de análisis establecen los campos restantes, tokenPtr y numTokens. El campo tokenPtr apunta al primer elemento de una matriz de estructuras Tcl_Token que describen los componentes de la entidad que se está analizando. El campo numTokens da el número total de tokens presentes en la matriz. Cada token contiene cuatro campos. El campo type selecciona uno de varios tipos de token que se describen a continuación. El campo start apunta al primer carácter del token y el campo size da el número total de caracteres en el token. Algunos tipos de token, como TCL_TOKEN_WORD y TCL_TOKEN_VARIABLE, consisten en varios tokens componentes, que siguen inmediatamente al token padre; el campo numComponents describe cuántos de estos hay. El campo type tiene uno de los siguientes valores:

TCL_TOKEN_WORD
Este token describe ordinariamente una palabra de un comando, pero también puede describir una cadena entrecomillada o entre llaves en una expresión. El token describe un componente del script que es el resultado de concatenar una secuencia de subcomponentes, cada uno descrito por un subtoke separado. El token comienza con el primer carácter que no sea un espacio en blanco del componente (que puede ser una comilla doble o una llave de apertura) e incluye todos los caracteres del componente hasta, pero sin incluir, el espacio, punto y coma, comilla de cierre o llave de cierre que termina el componente. El campo numComponents cuenta el número total de subtokens que componen la palabra, incluidos los subtokens de los tokens TCL_TOKEN_VARIABLE y TCL_TOKEN_BS.
TCL_TOKEN_SIMPLE_WORD
Este token tiene el mismo significado que TCL_TOKEN_WORD, excepto que se garantiza que la palabra consiste en un único subtoke TCL_TOKEN_TEXT. El campo numComponents es siempre 1.
TCL_TOKEN_EXPAND_WORD
Este token tiene el mismo significado que TCL_TOKEN_WORD, excepto que el analizador de comandos nota que esta palabra comenzó con el prefijo de expansión {*}, lo que indica que después de la sustitución, el valor de lista de esta palabra debe expandirse para formar múltiples argumentos en la evaluación del comando. Este tipo de token solo puede ser creado por Tcl_ParseCommand.
TCL_TOKEN_TEXT
El token describe un rango de texto literal que forma parte de una palabra. El campo numComponents es siempre 0.
TCL_TOKEN_BS
El token describe una secuencia de barra invertida como \n o \0xA3. El campo numComponents es siempre 0.
TCL_TOKEN_COMMAND
El token describe un comando cuyo resultado debe sustituirse en la palabra. El token incluye los corchetes que rodean al comando. El campo numComponents es siempre 0 (el comando anidado no se analiza; llame a Tcl_ParseCommand recursivamente si desea ver sus tokens).
TCL_TOKEN_VARIABLE
El token describe una sustitución de variable, incluyendo el $, el nombre de la variable y el índice del array (si lo hay) hasta el paréntesis de cierre que termina el índice. Este token va seguido de uno o más tokens adicionales que describen el nombre de la variable y el índice del array. Si numComponents es 1, entonces la variable es escalar y el siguiente token es un token TCL_TOKEN_TEXT que da el nombre de la variable. Si numComponents es mayor que 1, entonces la variable es un array: el primer subtoken es un token TCL_TOKEN_TEXT que da el nombre del array y los subtokens restantes son tokens TCL_TOKEN_TEXT, TCL_TOKEN_BS, TCL_TOKEN_COMMAND y TCL_TOKEN_VARIABLE que deben concatenarse para producir el índice del array. El campo numComponents incluye subtokens anidados que forman parte de los tokens TCL_TOKEN_VARIABLE en el índice del array.
TCL_TOKEN_SUB_EXPR
El token describe una subexpresión de una expresión (o una expresión completa). Una subexpresión puede consistir en un valor como un literal entero, una sustitución de variable o una subexpresión entre paréntesis; también puede consistir en un operador y sus operandos. El token comienza con el primer carácter no espacial de la subexpresión hasta, pero sin incluir, el espacio, la llave, el paréntesis de cierre o el corchete que termina la subexpresión. A este token le siguen uno o más tokens adicionales que describen la subexpresión. Si el primer subtoke después del token TCL_TOKEN_SUB_EXPR es un token TCL_TOKEN_OPERATOR, la subexpresión consiste en un operador y sus operandos de token. Si el operador no tiene operandos, la subexpresión consiste únicamente en el token TCL_TOKEN_OPERATOR. Cada operando se describe mediante un token TCL_TOKEN_SUB_EXPR. De lo contrario, la subexpresión es un valor descrito por uno de los tipos de token TCL_TOKEN_WORD, TCL_TOKEN_TEXT, TCL_TOKEN_BS, TCL_TOKEN_COMMAND, TCL_TOKEN_VARIABLE y TCL_TOKEN_SUB_EXPR. El campo numComponents cuenta el número total de subtokens que componen la subexpresión; esto incluye los subtokens de cualquier token TCL_TOKEN_SUB_EXPR anidado.
TCL_TOKEN_OPERATOR
El token describe un operador de una expresión como && o hypot. Un token TCL_TOKEN_OPERATOR siempre va precedido por un token TCL_TOKEN_SUB_EXPR que describe el operador y sus operandos; el campo numComponents del token TCL_TOKEN_SUB_EXPR se puede usar para determinar el número de operandos. Un operador binario como * va seguido de dos tokens TCL_TOKEN_SUB_EXPR que describen sus operandos. Un operador unario como - va seguido de un único token TCL_TOKEN_SUB_EXPR para su operando. Si el operador es una función matemática como log10, el token TCL_TOKEN_OPERATOR dará su nombre y los siguientes tokens TCL_TOKEN_SUB_EXPR describirán sus operandos; si no hay operandos (como con rand), no seguirán tokens TCL_TOKEN_SUB_EXPR. Hay un operador ternario, ?, que aparece en subexpresiones de si-entonces-sino como x?y:z; en este caso, el token ? TCL_TOKEN_OPERATOR va seguido de tres tokens TCL_TOKEN_SUB_EXPR para los operandos x, y y z. El campo numComponents para un token TCL_TOKEN_OPERATOR es siempre 0.

Después de que Tcl_ParseCommand retorna, el primer token al que apunta el campo tokenPtr de la estructura Tcl_Parse siempre tiene el tipo TCL_TOKEN_WORD o TCL_TOKEN_SIMPLE_WORD o TCL_TOKEN_EXPAND_WORD. Va seguido de los subtokens que deben concatenarse para producir el valor de esa palabra. El siguiente token es el token TCL_TOKEN_WORD o TCL_TOKEN_SIMPLE_WORD o TCL_TOKEN_EXPAND_WORD para la segunda palabra, seguido de los subtokens para esa palabra, y así sucesivamente hasta que se hayan contabilizado todas las numWords.

Después de que Tcl_ParseExpr retorna, el primer token al que apunta el campo tokenPtr de la estructura Tcl_Parse siempre tiene el tipo TCL_TOKEN_SUB_EXPR. Va seguido de los subtokens que deben evaluarse para producir el valor de la expresión. Solo se modifica la información del token en la estructura Tcl_Parse: los campos commentStart, commentSize, commandStart y commandSize no son modificados por Tcl_ParseExpr.

Después de que Tcl_ParseBraces retorna, la matriz de tokens apuntada por el campo tokenPtr de la estructura Tcl_Parse contendrá un único token TCL_TOKEN_TEXT si la cadena entre llaves no contiene ninguna nueva línea con barra invertida. Si la cadena contiene nuevas líneas con barra invertida, la matriz de tokens contendrá uno o más subtokens TCL_TOKEN_TEXT o TCL_TOKEN_BS que deben concatenarse para producir el valor de la cadena. Si la cadena entre llaves era solo {} (es decir, la cadena estaba vacía), el único token TCL_TOKEN_TEXT tendrá un campo size que contiene cero; esto asegura que al menos un token aparezca para describir la cadena entre llaves. Solo se modifica la información del token en la estructura Tcl_Parse: los campos commentStart, Tcl_ParseVar(3)

NAME

Tcl_ParseCommand, Tcl_ParseExpr, Tcl_ParseBraces, Tcl_ParseQuotedString, Tcl_ParseVarName — parse Tcl commands, expressions, quoted strings, and variable names

SYNOPSIS

#include <tcl.h>

int
Tcl_ParseCommand(interp, start, length, cmdPtr)
int Tcl_ParseExpr(interp, start, length, cmdPtr)
int Tcl_ParseBraces(interp, start, length, cmdPtr)
int Tcl_ParseQuotedString(interp, start, length, cmdPtr)
int Tcl_ParseVarName(interp, start, length, cmdPtr)

ARGUMENTS

Tcl_Interp *interp
Tcl interpreter to use for processing.
const char *start
Starting character of the string to parse.
int length
Number of characters to parse.
Tcl_Parse *cmdPtr
Pointer to the parsing structure to fill in.

DESCRIPTION

These procedures are low-level parsing utilities used internally by the Tcl interpreter. They are not normally called directly by application code, but they can be useful for implementing custom commands that need to parse Tcl syntax.

Each of these procedures parses a portion of a Tcl string starting at start and extending for length characters. The results of the parse are stored in the Tcl_Parse structure pointed to by cmdPtr. The structure should be initialized to all zeros before being passed to any of these procedures. The procedures return TCL_OK on success and TCL_ERROR on failure.

Tcl_ParseCommand parses a Tcl command. It produces a list of tokens representing the command name and its arguments. The tokens are stored in the Tcl_Parse structure. The Tcl_Parse structure will contain a variable number of Tcl_Token structures, each representing a part of the parsed command. The number of tokens is stored in the numTokens field of the Tcl_Parse structure. The tokenPtr field points to the first token in the array.

Tcl_ParseExpr parses a Tcl expression. The parsing rules for expressions are more complex than for commands. Expressions can contain variable substitutions, command substitutions, and mathematical operators. The tokens produced by Tcl_ParseExpr represent the structure of the expression. The Tcl_Parse structure will contain the tokens produced by the parse.

Tcl_ParseBraces parses a Tcl string enclosed in braces. It handles nested braces correctly. The resulting tokens represent the contents of the braced string. The Tcl_Parse structure will contain the tokens produced by the parse.

Tcl_ParseQuotedString parses a Tcl string enclosed in double quotes. It handles backslash escapes and variable substitutions within the quoted string. The resulting tokens represent the contents of the quoted string. The Tcl_Parse structure will contain the tokens produced by the parse.

Tcl_ParseVarName parses a Tcl variable name. It handles array variables and special characters within variable names. The resulting tokens represent the variable name. The Tcl_Parse structure will contain the tokens produced by the parse.

TCL_PARSE STRUCTURE

The Tcl_Parse structure has the following fields:

Tcl_Token *tokenPtr
Points to an array of Tcl_Token structures that describe the parsed string. The array is dynamically allocated by the parsing procedure.
int numTokens
The number of tokens in the array pointed to by tokenPtr.
int commandStart
The starting index of the command word within the parsed string. This field is only valid for Tcl_ParseCommand.
int commandSize
The length of the command word within the parsed string. This field is only valid for Tcl_ParseCommand.
int commentStart
The starting index of the comment (if any) within the parsed string. This field is only valid for Tcl_ParseCommand.
int commentSize
The length of the comment (if any) within the parsed string. This field is only valid for Tcl_ParseCommand.

The Tcl_Token structure has the following fields:

const char *start
Points to the start of the token in the original string.
int size
The length of the token.
int type
The type of the token. This can be one of the following values:
  • TCL_TOKEN_WORD: A simple word.
  • TCL_TOKEN_TEXT: A piece of plain text.
  • TCL_TOKEN_BS: A backslash sequence.
  • TCL_TOKEN_COMMAND: A command substitution.
  • TCL_TOKEN_VARIABLE: A variable substitution.
  • TCL_TOKEN_DICTIONARY: A dictionary subscript.
  • TCL_TOKEN_SUBST: A substitution that needs further processing.

After Tcl_ParseCommand returns, the array of tokens pointed to by the tokenPtr field of the Tcl_Parse structure depends on the contents of the command. It will consist of one or more tokens representing the command name and its arguments. The commentStart, commentSize, commandStart, and commandSize fields are set appropriately. Only the token information in the Tcl_Parse structure is modified: the commentStart, commentSize, commandStart, and commandSize fields are not modified.

After Tcl_ParseExpr returns, the array of tokens pointed to by the tokenPtr field of the Tcl_Parse structure depends on the contents of the expression. It will consist of one or more tokens representing the expression structure. The commentStart, commentSize, commandStart, and commandSize fields are not modified.

After Tcl_ParseBraces returns, the array of tokens pointed to by the tokenPtr field of the Tcl_Parse structure depends on the contents of the braced string. It will consist of one or more TCL_TOKEN_TEXT, TCL_TOKEN_BS, TCL_TOKEN_COMMAND, and TCL_TOKEN_VARIABLE sub-tokens. The array always contains at least one token; for example, if the argument start is empty, the array returned consists of a single TCL_TOKEN_TEXT token with a zero size field. Only the token information in the Tcl_Parse structure is modified: the commentStart, commentSize, commandStart, and commandSize fields are not modified.

After Tcl_ParseQuotedString returns, the array of tokens pointed to by the tokenPtr field of the Tcl structure depends on the contents of the quoted string. It will consist of one or more TCL_TOKEN_TEXT, TCL_TOKEN_BS, TCL_TOKEN_COMMAND, and TCL_TOKEN_VARIABLE sub-tokens. The array always contains at least one token; for example, if the argument start is empty, the array returned consists of a single TCL_TOKEN_TEXT token with a zero size field. Only the token information in the Tcl_Parse structure is modified: the commentStart, commentSize, commandStart, and commandSize fields are not modified.

After Tcl_ParseVarName returns, the first token pointed to by the tokenPtr field of the Tcl_Parse structure always has type TCL_TOKEN_VARIABLE. It is followed by the sub-tokens that make up the variable name as described above. The total length of the variable name is contained in the size field of the first token. As in Tcl_ParseExpr, only the token information in the Tcl_Parse structure is modified by Tcl_ParseVarName: the commentStart, commentSize, commandStart, and commandSize fields are not modified.

All of the character pointers in the Tcl_Parse and Tcl_Token structures refer to characters in the start argument passed to Tcl_ParseCommand, Tcl_ParseExpr, Tcl_ParseBraces, Tcl_ParseQuotedString, and Tcl_ParseVarName.

There are additional fields in the Tcl_Parse structure after the numTokens field, but these are for the private use of Tcl_ParseCommand, Tcl_ParseExpr, Tcl_ParseBraces, Tcl_ParseQuotedString, and Tcl_ParseVarName; they should not be referenced by code outside of these procedures.

KEYWORDS

backslash substitution, braces, command, expression, parse, token, variable substitution
