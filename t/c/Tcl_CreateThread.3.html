ARGUMENTOS

Tcl_Condition *condPtr (in)
Una variable de condición, que debe estar asociada a un bloqueo mutuo.
Tcl_Mutex *mutexPtr (in)
Un bloqueo mutuo.
const Tcl_Time *timePtr (in)
Un límite de tiempo para la espera de la condición. NULL para esperar indefinidamente. Tenga en cuenta que un valor de sondeo de 0 segundos no tiene mucho sentido.
Tcl_ThreadDataKey *keyPtr (in)
Esto identifica un bloque de datos locales del hilo. La clave debe ser estática y global del proceso, pero cada hilo terminará asociando un bloque de datos diferente con esta clave.
int *size (in)
El tamaño del bloque de datos locales del hilo. Esta cantidad de datos se asigna y se inicializa a cero la primera vez que cada hilo llama a Tcl_GetThreadData.
Tcl_ThreadId *idPtr (out)
El almacenamiento referenciado contendrá el ID del nuevo hilo creado según lo devuelto por el sistema operativo.
Tcl_ThreadId id (in)
ID del hilo esperado.
Tcl_ThreadCreateProc *proc (in)
Este procedimiento actuará como el main() del nuevo hilo creado. El clientData especificado será su único argumento.
ClientData clientData (in)
Información arbitraria. Pasada como único argumento a proc.
int stackSize (in)
El tamaño de la pila dado al nuevo hilo.
int flags (in)
Máscara de bits que contiene indicadores que permiten al llamador modificar el comportamiento del nuevo hilo.
int *result (out)
El almacenamiento referenciado se utiliza para colocar el código de salida del hilo esperado en él.

INTRODUCCIÓN

A partir de la versión 8.1, el núcleo de Tcl es seguro para hilos, lo que le permite incorporar Tcl en aplicaciones multihilo sin personalizar el núcleo de Tcl. A partir de la versión 8.6, el soporte de multihilo de Tcl está activado por defecto. Para deshabilitar el soporte de multihilo de Tcl, debe incluir la opción --disable-threads en configure cuando configure y compile su núcleo de Tcl.

Una restricción importante de la implementación de hilos de Tcl es que solo el hilo que creó un intérprete de Tcl puede usar ese intérprete. En otras palabras, múltiples hilos no pueden acceder al mismo intérprete de Tcl. (Sin embargo, un solo hilo puede crear y usar de forma segura múltiples intérpretes).

DESCRIPCIÓN

Tcl proporciona Tcl_CreateThread para crear hilos. El llamador puede determinar el tamaño de la pila dado al nuevo hilo y modificar el comportamiento a través de los flags proporcionados. El valor TCL_THREAD_STACK_DEFAULT para stackSize indica que se utilizará el tamaño predeterminado según lo especificado por el sistema operativo para el nuevo hilo. En cuanto a los flags, actualmente solo se definen los valores TCL_THREAD_NOFLAGS y TCL_THREAD_JOINABLE. El primer valor invoca el comportamiento predeterminado sin configuraciones especiales. El uso del segundo valor marca el nuevo hilo como joinable. Esto significa que otro hilo puede esperar a que dicho hilo marcado termine y unirse a él.

Restricciones: En algunos sistemas UNIX, la biblioteca pthread no contiene la funcionalidad para especificar el tamaño de la pila de un hilo. El valor especificado para el tamaño de la pila se ignora en estos sistemas. Windows actualmente no admite hilos joinable. Por lo tanto, este valor de flag se ignora en esta plataforma.

Tcl proporciona las funciones Tcl_ExitThread y Tcl_FinalizeThread para terminar hilos e invocar manejadores de salida opcionales por hilo. Consulte la página Tcl_Exit para obtener más información sobre estos procedimientos.

La función Tcl_JoinThread se proporciona para permitir que los hilos esperen la salida de otro hilo, que debe haber sido marcado como joinable mediante el uso del flag TCL_THREAD_JOINABLE durante su creación a través de Tcl_CreateThread.

Intentar esperar la salida de un hilo no joinable o de un hilo que ya está siendo esperado resultará en un error. Esperar a un hilo joinable que ya ha terminado es posible, el sistema conservará la información necesaria hasta después de la llamada a Tcl_JoinThread. Esto significa que no llamar a Tcl_JoinThread para un hilo joinable causará una fuga de memoria.

La llamada Tcl_GetThreadData devuelve un puntero a un bloque de datos privados del hilo. Su argumento es una clave que es compartida por todos los hilos y un tamaño para el bloque de almacenamiento. El almacenamiento se asigna automáticamente y se inicializa a todos ceros la primera vez que cada hilo lo solicita. El almacenamiento se libera automáticamente mediante Tcl_FinalizeThread.

SINCRONIZACIÓN Y COMUNICACIÓN

Tcl proporciona Tcl_ThreadQueueEvent y Tcl_ThreadAlert para manejar la cola de eventos en aplicaciones multihilo. Consulte la página del manual Notifier para obtener más información sobre estos procedimientos.

Un mutuo es un bloqueo que se utiliza para serializar todos los hilos a través de un fragmento de código llamando a Tcl_MutexLock y Tcl_MutexUnlock. Si un hilo tiene un mutuo, cualquier otro hilo que llame a Tcl_MutexLock se bloqueará hasta que se llame a Tcl_MutexUnlock. Un mutuo se puede destruir después de su uso llamando a Tcl_MutexFinalize. El resultado de bloquear un mutuo dos veces desde el mismo hilo es indefinido. En algunas plataformas resultará en un deadlock. Los procedimientos Tcl_MutexLock, Tcl_MutexUnlock y Tcl_MutexFinalize se definen como macros vacías si no se compila con hilos habilitados. Para la declaración de mutuos se debe usar la macro TCL_DECLARE_MUTEX. Esta macro asegura el manejo correcto de los mutuos incluso cuando el núcleo se compila sin hilos habilitados.

Una variable de condición se utiliza como un mecanismo de señalización: un hilo puede bloquear un mutuo y luego esperar en una variable de condición con Tcl_ConditionWait. Esto libera atómicamente el bloqueo mutuo y bloquea el hilo que espera hasta que otro hilo llama a Tcl_ConditionNotify. El llamador de Tcl_ConditionNotify debe tener el mutuo asociado bloqueado previamente llamando a Tcl_MutexLock, pero esto no se aplica. Notificar la variable de condición desbloquea todos los hilos que esperan en la variable de condición, pero no proceden hasta que el mutuo se libera con Tcl_MutexUnlock. La implementación de Tcl_ConditionWait bloquea automáticamente el mutuo antes de devolver.

El llamador de Tcl_ConditionWait debe estar preparado para notificaciones espurias llamando a Tcl_ConditionWait dentro de un bucle while que prueba algún invariante.

Una variable de condición se puede destruir después de su uso llamando a Tcl_ConditionFinalize.

Los procedimientos Tcl_ConditionNotify, Tcl_ConditionWait y Tcl_ConditionFinalize se definen como macros vacías si no se compila con hilos habilitados.

INICIALIZACIÓN

Todos estos objetos de sincronización son auto-inicializables. Se implementan como punteros opacos que deben ser NULL en su primer uso. Los mutuos y las variables de condición se limpian mediante manejadores de salida del proceso (si viven tanto tiempo) o explícitamente mediante llamadas a Tcl_MutexFinalize o Tcl_ConditionFinalize. El almacenamiento local del hilo se recupera durante Tcl_FinalizeThread.

Tcl_CreateThread(3)

NAME

Tcl_CreateThread, Tcl_ThreadId, Tcl_JoinThread, Tcl_GetThreadData, Tcl_SetThreadData — create and manage threads

SYNOPSIS

#include <tcl.h>

int
Tcl_CreateThread(Tcl_ThreadId *idPtr, Tcl_ThreadCreateProc *proc,
        ClientData clientData, int stackSize, int joinable);
void
Tcl_ThreadId();
int
Tcl_JoinThread(Tcl_ThreadId id, int *resultPtr);
ClientData
Tcl_GetThreadData(Tcl_ThreadId id, Tcl_ThreadDataKey *keyPtr);
int
Tcl_SetThreadData(Tcl_ThreadId id, Tcl_ThreadDataKey *keyPtr,
        ClientData data);

ARGUMENTS

Tcl_ThreadId *idPtr (in/out)
Pointer to location to store the new thread’s ID.
Tcl_ThreadCreateProc *proc (in)
The function to be executed by the new thread. See the description below for more details.
ClientData clientData (in)
Arbitrary data to be passed to the new thread’s procedure.
int stackSize (in)
The desired stack size for the new thread, in bytes. A value of TCL_THREAD_STACK_DEFAULT indicates the system default should be used. A value of 0 indicates that the stack size should be determined by the Tcl runtime (which may be the system default).
int joinable (in)
Specifies whether the thread should be joinable or detached. A value of TCL_THREAD_JOINABLE makes the thread joinable. A value of TCL_THREAD_DETACHED makes the thread detached.
Tcl_ThreadId id (in)
The ID of the thread to join or query.
int *resultPtr (out)
If non-NULL, pointer to location to store the return value of the thread procedure. This is only valid for joinable threads.
Tcl_ThreadDataKey *keyPtr (in/out)
Pointer to a key identifying the thread-local data slot.

INTRODUCTION

Tcl provides support for creating and managing operating system threads. These threads are visible to the underlying operating system and are not Tcl interpreters. Tcl threads are used for tasks that require concurrency and cannot be easily accomplished with Tcl’s event-driven programming model. This includes I/O-bound tasks, computationally intensive operations, and accessing libraries that require threads.

DESCRIPTION

The Tcl_CreateThread function creates a new thread. The new thread begins execution in the function pointed to by proc. The clientData argument is passed as the sole argument to proc. The stackSize argument specifies the desired stack size for the new thread. The joinable argument specifies whether the thread should be joinable or detached. Joinable threads can be joined using Tcl_JoinThread, and their return value can be retrieved. Detached threads cannot be joined and their return value is discarded.

The proc function should be declared as follows:

typedef void (Tcl_ThreadCreateProc)(ClientData clientData);

The proc function should return using the TCL_THREAD_CREATE_RETURN macro. This macro is necessary to ensure that the thread is properly cleaned up and terminated.

The Tcl_JoinThread function waits for the specified thread to terminate. If the thread is joinable, its return value is stored in resultPtr. If the thread is detached, Tcl_JoinThread returns an error.

The Tcl_GetThreadData and Tcl_SetThreadData functions provide a mechanism for managing thread-local storage. Each thread can have its own set of data associated with a particular key. The keyPtr argument is used to identify the slot for thread-local data.

A typical use of thread-local storage involves initializing a Tcl_ThreadDataKey structure in the main thread before creating any new threads. This can be done with:

Tcl_ThreadDataKey myKey;

Then, in each thread, you can store and retrieve data associated with that key:

/* Store data */
int myData = 123;
Tcl_SetThreadData(Tcl_GetCurrentThread(), &myKey, (ClientData)myData);
/* Retrieve data */
int data = (int)Tcl_GetThreadData(Tcl_GetCurrentThread(), &myKey);

SCRIPT-LEVEL ACCESS TO THREADS

Tcl’s script-level interface provides access to thread creation and management through the thread package. This package abstracts away many of the low-level details of thread creation and provides a more Tcl-idiomatic way to work with threads. For example, you can use the `thread create` command to create a new thread and execute a Tcl script within it. The `thread join` command allows you to wait for a thread to finish. The thread package also offers commands for thread-local storage, mutexes, and condition variables, providing a comprehensive set of tools for concurrent programming in Tcl. The package handles the initialization and cleanup of threads, making it easier to manage threads without delving into the complexities of the C API. It is generally recommended to use the script-level thread package for thread management in Tcl scripts whenever possible, as it offers a higher level of abstraction and portability. However, the C API functions described here provide greater control and flexibility for situations where direct manipulation of threads is necessary, such as when integrating Tcl with existing C libraries that utilize threads or when implementing custom thread management strategies. Understanding the C API is crucial for advanced Tcl extension development that involves threading. One such package is the Thread package.

EXAMPLE

To create a thread with portable code, its implementation function should be declared as follows:

static Tcl_ThreadCreateProc MyThreadImplFunc;

It should then be defined like this example, which just counts up to a given value and then finishes.

static Tcl_ThreadCreateType
MyThreadImplFunc(
    ClientData clientData)
{
    int i, limit = (int) clientData;
    for (i=0 ; i<limit ; i++) {
        /* doing nothing at all here */
    }
    TCL_THREAD_CREATE_RETURN;
}

To create the above thread, make it execute, and wait for it to finish, we would do this:

int limit = 1000000000;
ClientData limitData = (void*)((intptr_t) limit);
Tcl_ThreadId id;    /* holds identity of thread created */
int result;
if (Tcl_CreateThread(&id, MyThreadImplFunc, limitData,
        TCL_THREAD_STACK_DEFAULT,
        TCL_THREAD_JOINABLE) != TCL_OK) {
    /* Thread did not create correctly */
    return;
}
/* Do something else for a while here */
if (Tcl_JoinThread(id, &result) != TCL_OK) {
    /* Thread did not finish properly */
    return;
}
/* All cleaned up nicely */
