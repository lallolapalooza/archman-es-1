ARGUMENTOS

Tcl_Interp *interp (entrada)
Se utiliza para la notificación de errores y para buscar un canal registrado en él.
const char *fileName (entrada)
El nombre de un archivo local o de red.
const char *mode (entrada)
Especifica cómo se debe acceder al archivo. Puede tener cualquiera de los valores permitidos para el argumento mode del comando Tcl open.
int permissions (entrada)
Marcas de permisos estilo POSIX, como 0644. Si se crea un nuevo archivo, estos permisos se establecerán en el archivo creado.
int argc (entrada)
El número de elementos en argv.
const char **argv (entrada)
Argumentos para construir una tubería de comandos. Estos valores tienen el mismo significado que los argumentos sin opción del comando Tcl exec.
int flags (entrada)
Especifica la disposición de los identificadores stdio en la tubería: una combinación OR de TCL_STDIN, TCL_STDOUT, TCL_STDERR y TCL_ENFORCE_MODE. Si se establece TCL_STDIN, la entrada estándar del primer hijo en la tubería es el canal de la tubería, de lo contrario, es la misma que la entrada estándar del proceso invocador; lo mismo ocurre con TCL_STDOUT y TCL_STDERR. Si no se establece TCL_ENFORCE_MODE, entonces la tubería puede redirigir los identificadores stdio para anular los identificadores stdio para los que se han establecido TCL_STDIN, TCL_STDOUT y TCL_STDERR. Si está establecido, tales redirecciones causan un error.
ClientData handle (entrada)
Identificador específico del sistema operativo para E/S a un archivo. Para Unix es un descriptor de archivo, para Windows es un HANDLE.
int readOrWrite (entrada)
Combinación OR de TCL_READABLE y TCL_WRITABLE para indicar qué operaciones son válidas en handle.
const char *channelName (entrada)
El nombre del canal.
int *modePtr (salida)
Punta a una variable entera que recibirá una combinación OR de TCL_READABLE y TCL_WRITABLE que indica si el canal está abierto para lectura y escritura.
const char *pattern (entrada)
El patrón a casar, pasado a Tcl_StringMatch, o NULL.
Tcl_Channel channel (entrada)
Un canal Tcl para entrada o salida. Debe haber sido el valor de retorno de un procedimiento como Tcl_OpenFileChannel.
Tcl_Obj *readObjPtr (entrada/salida)
Un puntero a un valor Tcl en el que se almacenarán los caracteres leídos del canal.
int charsToRead (entrada)
El número de caracteres a leer del canal. Si la codificación del canal es binary, esto es equivalente al número de bytes a leer del canal.
int appendFlag (entrada)
Si es distinto de cero, los datos leídos del canal se añadirán al valor. De lo contrario, los datos reemplazarán el contenido existente del valor.
char *readBuf (salida)
Un búfer en el que se almacenarán los bytes leídos del canal.
int bytesToRead (entrada)
El número de bytes a leer del canal. El búfer readBuf debe ser lo suficientemente grande para contener esta cantidad de bytes.
Tcl_Obj *lineObjPtr (entrada/salida)
Un puntero a un valor Tcl en el que se almacenará la línea leída del canal. La línea leída se añadirá al valor actual del valor.
Tcl_DString *lineRead (entrada/salida)
Un puntero a una cadena dinámica Tcl en la que se almacenará la línea leída del canal. Debe haber sido inicializada por el llamador. La línea leída se añadirá a cualquier dato que ya esté en la cadena dinámica.
const char *input (entrada)
La entrada a añadir a un búfer de canal.
int inputLen (entrada)
Longitud de la entrada.
int addAtEnd (entrada)
Indicador que especifica si la entrada debe añadirse al final o al principio del búfer del canal.
Tcl_Obj *writeObjPtr (entrada)
Un puntero a un valor Tcl cuyos contenidos se enviarán al canal.
const char *charBuf (entrada)
Un búfer que contiene los caracteres a enviar al canal.
const char *byteBuf (entrada)
Un búfer que contiene los bytes a enviar al canal.
int bytesToWrite (entrada)
El número de bytes a consumir de charBuf o byteBuf y a enviar al canal.
Tcl_WideInt offset (entrada)
A qué distancia mover el punto de acceso en el canal en el que se aplicará la próxima operación de entrada o salida, medido en bytes desde la posición dada por seekMode. Puede ser positivo o negativo.
int seekMode (entrada)
Desde qué punto buscar; se usa junto con offset para calcular el nuevo punto de acceso para el canal. Los valores legales son SEEK_SET, SEEK_CUR y SEEK_END.
Tcl_WideInt length (entrada)
La longitud (no negativa) a la que truncar el canal.
const char *optionName (entrada)
El nombre de una opción aplicable a este canal, como -blocking. Puede tener cualquiera de los valores aceptados por el comando fconfigure.
Tcl_DString *optionValue (entrada)
Dónde almacenar el valor de una opción o una lista de todas las opciones y sus valores. Debe haber sido inicializado por el llamador.
const char *newValue (entrada)
Nuevo valor para la opción dada por optionName.

DESCRIPCIÓN

El mecanismo de canales Tcl proporciona un mecanismo independiente de dispositivos y plataformas para realizar operaciones de entrada y salida con búfer en una variedad de tipos de archivos, sockets y dispositivos. El mecanismo de canales es extensible a nuevos tipos de canales, proporcionando un controlador de canal de bajo nivel para el nuevo tipo; la interfaz del controlador de canal se describe en la entrada del manual para Tcl_CreateChannel. El mecanismo de canales proporciona un esquema de almacenamiento en búfer modelado según la E/S estándar de Unix, y también permite E/S no bloqueante en canales.

Los procedimientos descritos en esta entrada del manual comprenden las API de C de la capa genérica de la arquitectura de canales. Para una descripción de la arquitectura del controlador de canales y cómo implementar controladores de canales para nuevos tipos de canales, consulte la entrada del manual para Tcl_CreateChannel.

TCL_OPENFILECHANNEL

Abre el archivo local o de red llamado fileName. El argumento mode se utiliza para especificar cómo se abre el archivo. Puede tener cualquiera de los valores permitidos para el argumento mode del comando Tcl open. El argumento permissions se utiliza para establecer los permisos del archivo si se crea uno nuevo. Si la operación tiene éxito, devuelve un nuevo identificador de canal Tcl; de lo contrario, devuelve NULL y deja un mensaje de error en el campo result del intérprete.

Los siguientes modos son permitidos:

r
Abrir para leer.
w
Abrir para escribir. Se trunca el archivo si existe.
a
Abrir para añadir. Los datos se escriben al final del archivo.
r+
Abrir para leer y escribir. El archivo debe existir.
w+
Abrir para leer y escribir. Se trunca el archivo si existe.
a+
Abrir para leer y añadir. Los datos se escriben al final del archivo. Los datos de entrada se leen desde el principio del archivo.

A estos modos se les pueden añadir las siguientes letras:

b
Abrir en modo binario. Si no se especifica, se asume el modo texto.
c
El canal se crea si no existe. El archivo ya existente no se trunca.
t
Abrir en modo texto.

El argumento permissions se utiliza para especificar los permisos POSIX del archivo, como 0644. Si el archivo no existe y se abre en un modo que crea el archivo (como w o a), se crea un nuevo archivo con estos permisos.

TCL_OPENCOMMANDCHANNEL

Abre una tubería de comandos ejecutando el comando dado por argv. Los argumentos argc y argv son los mismos que los argumentos no de opción del comando Tcl exec. El argumento flags se utiliza para especificar la disposición de los identificadores stdio en la tubería: una combinación OR de TCL_STDIN, TCL_STDOUT, TCL_STDERR y TCL_ENFORCE_MODE. Si se establece TCL_STDIN, la entrada estándar del primer hijo en la tubería es el canal de la tubería, de lo contrario, es la misma que la entrada estándar del proceso invocador; lo mismo ocurre con TCL_STDOUT y TCL_STDERR. Si no se establece TCL_ENFORCE_MODE, entonces la tubería puede redirigir los identificadores stdio para anular los identificadores stdio para los que se han establecido TCL_STDIN, TCL_STDOUT y TCL_STDERR. Si está establecido, tales redirecciones causan un error. Si la operación tiene éxito, devuelve un nuevo identificador de canal Tcl; de lo contrario, devuelve NULL y deja un mensaje de error en el campo result del intérprete.

TCL_MAKEFILECHANNEL

Asocia un canal Tcl al descriptor de archivo o identificador del sistema operativo dado por handle. El argumento readOrWrite es una combinación OR de TCL_READABLE y TCL_WRITABLE para indicar qué operaciones son válidas en handle. Si la operación tiene éxito, devuelve un nuevo identificador de canal Tcl; de lo contrario, devuelve NULL y deja un mensaje de error en el campo result del intérprete.

Este procedimiento se utiliza normalmente para obtener un canal Tcl para la entrada/salida estándar, o para crear un canal Tcl a partir de un descriptor de archivo existente. Los canales estándar (entrada, salida y error estándar) se registran automáticamente en el intérprete cuando se inicializa. Se pueden obtener haciendo referencia a sus nombres estándar (stdin, stdout, stderr) con Tcl_GetChannel.

TCL_GETCHANNEL

Devuelve el canal Tcl que corresponde al nombre dado por channelName. Si modePtr no es NULL, se establece para indicar si el canal está abierto para lectura y/o escritura.

Si channelName es uno de los canales estándar (por ejemplo, "stdin", "stdout" o "stderr"), este procedimiento devuelve el canal Tcl correspondiente. De lo contrario, busca un canal registrado con el nombre dado por channelName.

TCL_GETCHANNELNAMES

Establece el campo result del intérprete en una lista de todos los nombres de canales actualmente registrados en el intérprete. El valor de retorno es el número de canales registrados, o -1 si ocurre un error.

TCL_GETCHANNELNAMESEX

Similar a Tcl_GetChannelNames, pero sólo devuelve los nombres de canales que casan con el patrón dado por pattern. Se utiliza el algoritmo de casamiento de cadenas de Tcl.

TCL_REGISTERCHANNEL

Registra el canal dado por channel en el intérprete dado por interp. Una vez registrado, el canal puede ser accedido por su nombre usando Tcl_GetChannel.

Los canales registrados son gestionados por Tcl. Cuando el intérprete se destruye, Tcl cerrará automáticamente todos los canales registrados.

TCL_UNREGISTERCHANNEL

Anula el registro del canal dado por channel del intérprete dado por interp. Una vez anulado el registro, el canal ya no puede ser accedido usando Tcl_GetChannel. Si el canal está todavía abierto, el llamador es responsable de cerrarlo.

Si la anulación de registro tiene éxito, devuelve 0. De lo contrario, devuelve un valor distinto de cero y deja un mensaje de error en el campo result del intérprete.

TCL_DETACHCHANNEL

Desvincula el canal dado por channel del intérprete dado por interp. Después de desvincularlo, Tcl ya no gestionará el canal. El llamador es responsable de cerrar el canal y su identificador subyacente.

Si la desvinculación tiene éxito, devuelve 0. De lo contrario, devuelve un valor distinto de cero y deja un mensaje de error en el campo result del intérprete.

TCL_ISSTANDARDCHANNEL

Devuelve 1 si el canal dado es uno de los canales estándar (stdin, stdout, stderr), y 0 en caso contrario.

TCL_CLOSE

Cierra el canal dado por channel. Antes de cerrar el canal, descarga cualquier búfer de salida pendiente. Si la operación tiene éxito, devuelve 0; de lo contrario, devuelve un valor distinto de cero y deja un mensaje de error en el campo result del intérprete.

Si el canal es uno de los canales estándar, este procedimiento no hace nada.

TCL_READCHARS

Lee hasta charsToRead caracteres del canal dado por channel y los almacena en el valor de Tcl apuntado por readObjPtr. Si appendFlag es distinto de cero, los caracteres leídos se añaden al valor existente; de lo contrario, reemplazan el contenido existente. Si la operación tiene éxito, devuelve el número de caracteres leídos; de lo contrario, devuelve -1 y deja un mensaje de error en el campo result del intérprete.

Este procedimiento sólo debe utilizarse en canales que se abren en modo texto. Para canales binarios, utilice Tcl_Read.

TCL_READ

Lee hasta bytesToRead bytes del canal dado por channel y los almacena en el búfer apuntado por readBuf. Si la operación tiene éxito, devuelve el número de bytes leídos; de lo contrario, devuelve -1 y deja un mensaje de error en el campo result del intérprete.

Este procedimiento debe utilizarse en canales que se abren en modo binario. Para canales de texto, utilice Tcl_ReadChars.

TCL_GETSOBJ

Lee una línea del canal dado por channel y la almacena en el valor de Tcl apuntado por lineObjPtr. La línea se lee hasta un carácter de nueva línea (\n). El carácter de nueva línea se lee del canal pero no se almacena en el valor. Si la operación tiene éxito, devuelve el número de caracteres leídos; de lo contrario, devuelve -1 y deja un mensaje de error en el campo result del intérprete.

Si se alcanza el final del archivo antes de leerse ningún carácter, devuelve 0. Si se lee una línea parcial, el valor se establece en la línea leída y la función devuelve el número de caracteres leídos.

Este procedimiento sólo debe utilizarse en canales que se abren en modo texto.

TCL_GETS

Lee una línea del canal dado por channel y la almacena en la cadena dinámica apuntada por lineRead. La línea se lee hasta un carácter de nueva línea (\n). El carácter de nueva línea se lee del canal pero no se almacena en la cadena dinámica. Si la operación tiene éxito, devuelve el número de caracteres leídos; de lo contrario, devuelve -1 y deja un mensaje de error en el campo result del intérprete.

Si se alcanza el final del archivo antes de leerse ningún carácter, devuelve 0. Si se lee una línea parcial, el valor se establece en la línea leída y la función devuelve el número de caracteres leídos.

Este procedimiento sólo debe utilizarse en canales que se abren en modo texto.

TCL_UNGETS

Coloca la cadena dada por input, de longitud inputLen, en el búfer de entrada para el canal dado por channel. Si addAtEnd es distinto de cero, la entrada se añade al final del búfer de entrada; de lo contrario, se añade al principio. La entrada se añadirá a los datos ya presentes en el búfer. La función devuelve el número de caracteres añadidos o un valor de error negativo si ocurre un error.

Este procedimiento es útil para deshacer una lectura previa o para insertar datos en un flujo de entrada. Debe utilizarse sólo en canales de texto.

TCL_WRITEOBJ

Escribe el contenido del valor de Tcl apuntado por writeObjPtr en el canal dado por channel. Si la operación tiene éxito, devuelve el número de bytes escritos; de lo contrario, devuelve -1 y deja un mensaje de error en el campo result del intérprete.

Este procedimiento sólo debe utilizarse en canales que se abren en modo texto.

TCL_WRITECHARS

Escribe los caracteres del búfer dado por charBuf, de longitud bytesToWrite, en el canal dado por channel. Si la operación tiene éxito, devuelve el número de caracteres escritos; de lo contrario, devuelve -1 y deja un mensaje de error en el campo result del intérprete.

Este procedimiento sólo debe utilizarse en canales que se abren en modo texto.

TCL_WRITE

Escribe los bytes del búfer dado por byteBuf, de longitud bytesToWrite, en el canal dado por channel. Si la operación tiene éxito, devuelve el número de bytes escritos; de lo contrario, devuelve -1 y deja un mensaje de error en el campo result del intérprete.

Este procedimiento debe utilizarse en canales que se abren en modo binario. Para canales de texto, utilice Tcl_WriteChars.

TCL_READRAW

Lee hasta bytesToRead bytes del canal dado por channel y los almacena en el búfer apuntado por readBuf. Esto es similar a Tcl_Read, pero se utiliza para leer datos sin ningún tipo de conversión de codificación o final de línea. Si la operación tiene éxito, devuelve el número de bytes leídos; de lo contrario, devuelve -1 y deja un mensaje de error en el campo result del intérprete.

Este procedimiento debe utilizarse cuando se desee leer datos binarios directamente del canal sin ninguna interpretación.

TCL_WRITERAW

Escribe los bytes del búfer dado por byteBuf, de longitud bytesToWrite, en el canal dado por channel. Esto es similar a Tcl_Write, pero se utiliza para escribir datos sin ningún tipo de conversión de codificación o final de línea. Si la operación tiene éxito, devuelve el número de bytes escritos; de lo contrario, devuelve -1 y deja un mensaje de error en el campo result del intérprete.

Este procedimiento debe utilizarse cuando se desee escribir datos binarios directamente en el canal sin ninguna interpretación.

TCL_EOF

Devuelve 1 si se ha alcanzado el final del archivo en el canal dado por channel, y 0 en caso contrario. Si ocurre un error, devuelve -1.

TCL_FLUSH

Descarga cualquier búfer de salida pendiente para el canal dado por channel. Si la operación tiene éxito, devuelve 0; de lo contrario, devuelve un valor distinto de cero y deja un mensaje de error en el campo result del intérprete.

TCL_INPUTBLOCKED

Devuelve 1 si la última operación de lectura en el canal dado por channel se bloqueó, y 0 en caso contrario. Si ocurre un error, devuelve -1.

Este procedimiento sólo es válido en canales configurados para E/S no bloqueante.

TCL_INPUTBUFFERED

Devuelve el número de bytes disponibles para leer en el búfer de entrada del canal dado por channel. Si ocurre un error, devuelve -1.

TCL_OUTPUTBUFFERED

Devuelve el número de bytes en el búfer de salida del canal dado por channel. Si ocurre un error, devuelve -1.

TCL_SEEK

Cambia la posición de acceso actual del canal dado por channel. El argumento offset especifica cuánto mover la posición de acceso, y seekMode especifica desde qué punto moverla (SEEK_SET, SEEK_CUR o SEEK_END). La función devuelve la nueva posición de acceso en bytes desde el principio del archivo, o un valor de error negativo si ocurre un error.

Este procedimiento sólo es válido en canales que admiten búsqueda (archivos regulares y algunos otros tipos de archivos).

TCL_TELL

Devuelve la posición de acceso actual del canal dado por channel en bytes desde el principio del archivo. Si ocurre un error, devuelve un valor de error negativo.

Este procedimiento sólo es válido en canales que admiten búsqueda.

TCL_TRUNCATECHANNEL

Acorta o extiende el archivo asociado con el canal dado por channel a la longitud dada por length. Si la longitud es menor que la longitud actual del archivo, se trunca el archivo. Si la longitud es mayor que la longitud actual del archivo, se extiende el archivo y se rellena el espacio adicional con bytes nulos. Si la operación tiene éxito, devuelve 0; de lo contrario, devuelve un valor distinto de cero y deja un mensaje de error en el campo result del intérprete.

Este procedimiento sólo es válido en canales que admiten truncamiento (archivos regulares abiertos para escritura).

TCL_GETCHANNELOPTION

Obtiene el valor de la opción dada por optionName para el canal dado por channel y almacena el resultado en la cadena dinámica apuntada por optionValue. Si la operación tiene éxito, devuelve 0; de lo contrario, devuelve un valor distinto de cero y deja un mensaje de error en el campo result del intérprete.

Las opciones disponibles para un canal dependen del tipo de canal. Consulte la documentación del comando Tcl fconfigure para obtener una lista de opciones comunes.

TCL_SETCHANNELOPTION

Establece el valor de la opción dada por optionName para el canal dado por channel al valor dado por newValue. Si la operación tiene éxito, devuelve 0; de lo contrario, devuelve un valor distinto de cero y deja un mensaje de error en el campo result del intérprete.

Las opciones disponibles para un canal dependen del tipo de canal. Consulte la documentación del comando Tcl fconfigure para obtener una lista de opciones comunes.

HISTORIA

Esta página de manual resume las interfaces de bajo nivel de la arquitectura de canales Tcl. Para obtener más detalles sobre la arquitectura de canales y cómo implementar controladores de canales, consulte la entrada del manual Tcl_CreateChannel.

TCL_OPENFILECHANNEL

Tcl_OpenFileChannel abre un archivo especificado por fileName y devuelve un manejador de canal que se puede utilizar para realizar operaciones de entrada y salida en el archivo. Esta API se basa en el procedimiento fopen de la biblioteca estándar de E/S de Unix. La sintaxis y el significado de todos los argumentos son similares a los proporcionados en el comando Tcl open al abrir un archivo. Si ocurre un error al abrir el canal, Tcl_OpenFileChannel devuelve NULL y registra un código de error POSIX que se puede recuperar con Tcl_GetErrno. Además, si interp no es NULL, Tcl_OpenFileChannel deja un mensaje de error en el resultado de interp después de cualquier error. A partir de Tcl 8.4, la API basada en valores Tcl_FSOpenFileChannel debe usarse preferentemente a Tcl_OpenFileChannel siempre que sea posible.

El canal recién creado no se registra en el intérprete proporcionado; para registrarlo, use Tcl_RegisterChannel, descrito a continuación. Si uno de los canales estándar, stdin, stdout o stderr se cerró previamente, la creación del nuevo canal también lo asigna como reemplazo del canal estándar.

TCL_OPENCOMMANDCHANNEL

Tcl_OpenCommandChannel proporciona una interfaz de nivel C a las funciones de los comandos exec y open. Crea una secuencia de subprocesos especificados por los argumentos argv y argc y devuelve un canal que se puede utilizar para comunicarse con estos subprocesos. El argumento flags indica qué tipo de comunicación existirá con la canalización del comando.

Si se establece la bandera TCL_STDIN, la entrada estándar del primer subproceso se vinculará al canal: escribir en el canal proporcionará entrada al subproceso. Si TCL_STDIN no está establecido, la entrada estándar del primer subproceso será la misma que la entrada estándar de esta aplicación. Si se establece TCL_STDOUT, la salida estándar del último subproceso se puede leer del canal; de lo contrario, va a la salida estándar de esta aplicación. Si se establece TCL_STDERR, la salida de error estándar de todos los subprocesos se devuelve al canal y resulta en un error cuando se cierra el canal; de lo contrario, va al error estándar de esta aplicación. Si TCL_ENFORCE_MODE no está establecido, entonces argc y argv pueden redirigir los manejadores de E/S para anular TCL_STDIN, TCL_STDOUT y TCL_STDERR; si está establecido, entonces es un error que argc y argv anulen los canales de E/S para los cuales se han establecido TCL_STDIN, TCL_STDOUT y TCL_STDERR.

Si ocurre un error al abrir el canal, Tcl_OpenCommandChannel devuelve NULL y registra un código de error POSIX que se puede recuperar con Tcl_GetErrno. Además, Tcl_OpenCommandChannel deja un mensaje de error en el resultado del intérprete. interp no puede ser NULL.

El canal recién creado no se registra en el intérprete proporcionado; para registrarlo, use Tcl_RegisterChannel, descrito a continuación. Si uno de los canales estándar, stdin, stdout o stderr se cerró previamente, la creación del nuevo canal también lo asigna como reemplazo del canal estándar.

TCL_MAKEFILECHANNEL

Tcl_MakeFileChannel crea un Tcl_Channel a partir de un manejador de archivo existente y específico de la plataforma. El canal recién creado no se registra en el intérprete proporcionado; para registrarlo, use Tcl_RegisterChannel, descrito a continuación. Si uno de los canales estándar, stdin, stdout o stderr se cerró previamente, la creación del nuevo canal también lo asigna como reemplazo del canal estándar.

TCL_GETCHANNEL

Tcl_GetChannel devuelve un canal dado el nombre de canal channelName utilizado para crearlo con Tcl_CreateChannel y un puntero a un intérprete Tcl en interp. Si no se registra un canal con ese nombre en ese intérprete, el procedimiento devuelve NULL. Si el argumento modePtr no es NULL, apunta a una variable entera que recibirá una combinación OR de TCL_READABLE y TCL_WRITABLE que describe si el canal está abierto para lectura y escritura.

Tcl_GetChannelNames y Tcl_GetChannelNamesEx escriben los nombres de los canales registrados en el resultado del intérprete como un valor de lista. Tcl_GetChannelNamesEx filtrará estos nombres según el patrón pattern. Si pattern es NULL, entonces no realizará ningún filtrado. El valor de retorno es TCL_OK si no ocurrieron errores al escribir en el resultado, de lo contrario es TCL_ERROR, y el mensaje de error se deja en el resultado del intérprete.

TCL_REGISTERCHANNEL

Tcl_RegisterChannel agrega un canal al conjunto de canales accesibles en interp. Después de esta llamada, los programas Tcl que se ejecutan en ese intérprete pueden referirse al canal en operaciones de entrada o salida utilizando el nombre dado en la llamada a Tcl_CreateChannel. Después de esta llamada, el canal se convierte en propiedad del intérprete, y el llamador no debe llamar Tcl_Close para el canal; el canal se cerrará automáticamente cuando se desregistre del intérprete.

El código que se ejecuta fuera de cualquier intérprete Tcl puede llamar a Tcl_RegisterChannel con interp como NULL, para indicar que desea mantener una referencia a este canal. Posteriormente, el canal se puede registrar en un intérprete Tcl y solo se cerrará cuando el número correspondiente de llamadas a Tcl_UnregisterChannel se haya realizado. Esto permite que el código que se ejecuta fuera de cualquier intérprete mantenga de forma segura una referencia a un canal que también está registrado en un intérprete Tcl.

Este procedimiento interactúa con el código que administra los canales estándar. Si no se inicializaron canales estándar antes de la primera llamada a Tcl_RegisterChannel, se inicializarán con esa llamada. Consulte Tcl_StandardChannels para obtener un tratado general sobre los canales estándar y el comportamiento de la biblioteca Tcl con respecto a ellos.

TCL_UNREGISTERCHANNEL

Tcl_UnregisterChannel elimina un canal del conjunto de canales accesibles en interp. Después de esta llamada, los programas Tcl ya no podrán utilizar el nombre del canal para referirse al canal en ese intérprete. Si esta operación eliminó el último registro del canal en cualquier intérprete, el canal también se cierra y destruye.

El código no asociado con un intérprete Tcl puede llamar a Tcl_UnregisterChannel con interp como NULL, para indicar a Tcl que ya no mantiene una referencia a ese canal. Si esta es la última referencia al canal, ahora se cerrará. Tcl_UnregisterChannel es muy similar a Tcl_DetachChannel excepto que también cerrará el canal si no existen más referencias a él.

TCL_DETACHCHANNEL

Tcl_DetachChannel elimina un canal del conjunto de canales accesibles en interp. Después de esta llamada, los programas Tcl ya no podrán utilizar el nombre del canal para referirse al canal en ese intérprete. Más allá de eso, este comando no tiene ningún otro efecto. No se puede utilizar en los canales estándar (stdout, stderr, stdin), y devolverá TCL_ERROR si se le pasa uno de esos canales.

El código no asociado con un intérprete Tcl puede llamar a Tcl_DetachChannel con interp como NULL, para indicar a Tcl que ya no mantiene una referencia a ese canal. Si esta es la última referencia al canal, a diferencia de Tcl_UnregisterChannel, no se cerrará.

TCL_ISSTANDARDCHANNEL

Tcl_IsStandardChannel comprueba si un canal es uno de los tres canales estándar, stdin, stdout o stderr. Si es así, devuelve 1, de lo contrario 0.

No se intenta comprobar si el canal dado o los canales estándar están inicializados o son válidos de otra manera.

TCL_CLOSE

Tcl_Close destruye el canal channel, que debe denotar un canal abierto actualmente. El canal no debe estar registrado en ningún intérprete cuando se llama a Tcl_Close. La salida en búfer se vacía en el dispositivo de salida del canal antes de destruir el canal, y cualquier entrada en búfer se descarta. Si se trata de un canal bloqueante, la llamada no devuelve hasta que todos los datos en búfer se envían correctamente al dispositivo de salida del canal. Si se trata de un canal no bloqueante y hay salida en búfer que no se puede escribir sin bloquear, la llamada devuelve inmediatamente; la salida se vacía en segundo plano y el canal se cerrará una vez que todos los datos en búfer se hayan enviado. En este caso, los errores durante el vaciado no se informan.

Si el canal se cerró correctamente, Tcl_Close devuelve TCL_OK. Si ocurre un error, Tcl_Close devuelve TCL_ERROR y registra un código de error POSIX que se puede recuperar con Tcl_GetErrno. Si el canal se está cerrando de forma síncrona y ocurre un error durante el cierre del canal y interp no es NULL, se deja un mensaje de error en el resultado del intérprete.

Nota: no es seguro llamar a Tcl_Close en un canal que ha sido registrado usando Tcl_RegisterChannel; consulte la documentación para Tcl_RegisterChannel, arriba, para obtener detalles. Si el canal se ha proporcionado alguna vez como el argumento chan en una llamada a Tcl_RegisterChannel, debe usar en su lugar Tcl_UnregisterChannel, que llamará internamente a Tcl_Close cuando todas las llamadas a Tcl_RegisterChannel hayan sido igualadas por llamadas correspondientes a Tcl_UnregisterChannel.

TCL_READCHARS Y TCL_READ

Tcl_ReadChars consume bytes del channel, convirtiendo los bytes a UTF-8 basándose en la codificación del canal y almacenando los datos producidos en la representación de cadena de readObjPtr. El valor de retorno de Tcl_ReadChars es el número de caracteres, hasta charsToRead, que se almacenaron en readObjPtr. Si ocurre un error al leer, el valor de retorno es -1 y Tcl_ReadChars registra un código de error POSIX que se puede recuperar con Tcl_GetErrno.

TCL_READCHARS, TCL_READOBJS, Y TCL_READ

The Tcl_ReadChars command reads up to bytesToRead bytes of characters from the channel indicated by channel and stores them in the Tcl value indicated by readObjPtr. The bytes are read into an internal buffer and then converted to UTF-8 according to the channel's current encoding. End-of-line translation is performed on the bytes as they are read from the channel according to the channel's -translation option. If bytesToRead is negative, Tcl_ReadChars will read until end-of-file is reached or an error occurs.

A negative value for bytesToRead in the call to Tcl_ReadChars will cause the command to read all characters currently available (non-blocking) or everything until eof (blocking mode).

The return value may be smaller than the value to read, indicating that less data than requested was available. This is called a short read. In blocking mode, this can only happen on an end-of-file. In nonblocking mode, a short read can also occur if there is not enough input currently available: Tcl_ReadChars returns a short count rather than waiting for more data.

If the channel is in blocking mode, a return value of zero indicates an end-of-file condition. If the channel is in nonblocking mode, a return value of zero indicates either that no input is currently available or an end-of-file condition. Use Tcl_Eof and Tcl_InputBlocked to tell which of these conditions actually occurred.

Tcl_ReadChars translates the various end-of-line representations into the canonical \n internal representation according to the current end-of-line recognition mode. End-of-line recognition and the various platform-specific modes are described in the manual entry for the Tcl fconfigure command.

As a performance optimization, when reading from a channel with the encoding binary, the bytes are not converted to UTF-8 as they are read. Instead, they are stored in readObjPtr's internal representation as a byte-array value. The string representation of this value will only be constructed if it is needed (e.g., because of a call to Tcl_GetStringFromObj). In this way, byte-oriented data can be read from a channel, manipulated by calling Tcl_GetByteArrayFromObj and related functions, and then written to a channel without the expense of ever converting to or from UTF-8.

Tcl_Read is similar to Tcl_ReadChars, except that it does not do encoding conversions, regardless of the channel's encoding. It is deprecated and exists for backwards compatibility with non-internationalized Tcl extensions. It consumes bytes from channel and stores them in readBuf, performing end-of-line translations on the way. The return value of Tcl_Read is the number of bytes, up to bytesToRead, written in readBuf. The buffer produced by Tcl_Read is not null-terminated. Its contents are valid from the zeroth position up to and excluding the position indicated by the return value.

Tcl_ReadRaw is the same as Tcl_Read but does not compensate for stacking. While Tcl_Read (and the other functions in the API) always get their data from the topmost channel in the stack the supplied channel is part of, Tcl_ReadRaw does not. Thus this function is only usable for transformational channel drivers, i.e. drivers used in the middle of a stack of channels, to move data from the channel below into the transformation.

TCL_GETSOBJ Y TCL_GETS

Tcl_GetsObj consumes bytes from channel, converting the bytes to UTF-8 based on the channel's encoding, until a full line of input has been seen. If the channel's encoding is binary, each byte read from the channel is treated as an individual Unicode character. All of the characters of the line except for the terminating end-of-line character(s) are appended to lineObjPtr's string representation. The end-of-line character(s) are read and discarded.

If a line was successfully read, the return value is greater than or equal to zero and indicates the number of bytes stored in lineObjPtr. If an error occurs, Tcl_GetsObj returns -1 and records a POSIX error code that can be retrieved with Tcl_GetErrno. Tcl_GetsObj also returns -1 if the end of the file is reached; the Tcl_Eof procedure can be used to distinguish an error from an end-of-file condition.

If the channel is in nonblocking mode, the return value can also be -1 if no data was available or the data that was available did not contain an end-of-line character. When -1 is returned, the Tcl_InputBlocked procedure may be invoked to determine if the channel is blocked because of input unavailability.

Tcl_Gets is the same as Tcl_GetsObj except the resulting characters are appended to the dynamic string given by lineRead rather than a Tcl value.

TCL_UNGETS

Tcl_Ungets is used to add data to the input queue of a channel, at either the head or tail of the queue. The pointer input points to the data that is to be added. The length of the input to add is given by inputLen. A non-zero value of addAtEnd indicates that the data is to be added at the end of queue; otherwise it will be added at the head of the queue. If channel has a “sticky” EOF set, no data will be added to the input queue. Tcl_Ungets returns inputLen or -1 if an error occurs.

TCL_WRITECHARS, TCL_WRITEOBJ, Y TCL_WRITE

Tcl_WriteChars accepts bytesToWrite bytes of character data at charBuf. The UTF-8 characters in the buffer are converted to the channel's encoding and queued for output to channel. If bytesToWrite is negative, Tcl_WriteChars expects charBuf to be null-terminated and it outputs everything up to the null.

Data queued for output may not appear on the output device immediately, due to internal buffering. If the data should appear immediately, call Tcl_Flush after the call to Tcl_WriteChars, or set the -buffering option on the channel to none. If you wish the data to appear as soon as a complete line is accepted for output, set the -buffering option on the channel to line mode.

The return value of Tcl_WriteChars is a count of how many bytes were accepted for output to the channel. This is either greater than zero to indicate success or -1 to indicate that an error occurred. If an error occurs, Tcl_WriteChars records a POSIX error code that may be retrieved with Tcl_GetErrno.

Newline characters in the output data are translated to platform-specific end-of-line sequences according to the -translation option for the channel. This is done even if the channel has no encoding.

Tcl_WriteObj is similar to Tcl_WriteChars except it accepts a Tcl value whose contents will be output to the channel. The UTF-8 characters in writeObjPtr's string representation are converted to the channel's encoding and queued for output to channel. As a performance optimization, when writing to a channel with the encoding binary, UTF-8 characters are not converted as they are written. Instead, the bytes in writeObjPtr's internal representation as a byte-array value are written to the channel. The byte-array representation of the value will be constructed if it is needed. In this way, byte-oriented data can be read from a channel, manipulated by calling Tcl_GetByteArrayFromObj and related functions, and then written to a channel without the expense of ever converting to or from UTF-8.

Tcl_Write is similar to Tcl_WriteChars except that it does not do encoding conversions, regardless of the channel's encoding. It is deprecated and exists for backwards compatibility with non-internationalized Tcl extensions. It accepts bytesToWrite bytes of data at byteBuf and queues them for output to channel. If bytesToWrite is negative, Tcl_Write expects byteBuf to be null-terminated and it outputs everything up to the null.

Tcl_WriteRaw is the same as Tcl_Write but does not compensate for stacking. While Tcl_Write (and the other functions in the API) always feed their input to the topmost channel in the stack the supplied channel is part of, Tcl_WriteRaw does not. Thus this function is only usable for transformational channel drivers, i.e. drivers used in the middle of a stack of channels, to move data from the transformation into the channel below it.

TCL_FLUSH

Tcl_Flush causes all of the buffered output data for channel to be written to its underlying file or device as soon as possible. If the channel is in blocking mode, the call does not return until all the buffered data has been sent to the channel or some error occurred. The call returns immediately if the channel is nonblocking; it starts a background flush that will write the buffered data to the channel eventually, as fast as the channel is able to absorb it.

The return value is normally TCL_OK. If an error occurs, Tcl_Flush returns TCL_ERROR and records a POSIX error code that can be retrieved with Tcl_GetErrno.

TCL_SEEK

Tcl_Seek moves the access point in channel where subsequent data will be read or written. Buffered output is flushed to the channel and buffered input is discarded, prior to the seek operation.

Tcl_Seek normally returns the new access point. If an error occurs, Tcl_Seek returns -1 and records a POSIX error code that can be retrieved with Tcl_GetErrno. After an error, the access point may or may not have been moved.

TCL_TELL

Tcl_Tell returns the current access point for a channel. The returned value is -1 if the channel does not support seeking.

TCL_TRUNCATECHANNEL

Tcl_TruncateChannel truncates the file underlying channel to a given length of bytes. It returns TCL_OK if the operation succeeded, and TCL_ERROR otherwise.

TCL_GETCHANNELOPTION

Tcl_GetChannelOption retrieves the value of the option optionName for channel. If interp is non-NULL, the value is stored in the interpreter's result. Otherwise, if valuePtr is non-NULL, the value is copied into the string buffer pointed to by valuePtr. The buffer must be large enough to hold the value. The procedure returns TCL_OK if the option was found and its value retrieved successfully, or TCL_ERROR if the option is not valid for the channel type or if there was an error retrieving the value.

If interp is non-NULL, the option can be specified using a Tcl_DString that contains a series of calls to Tcl_DStringAppendElement. The various preexisting options and their possible values are described in the manual entry for the Tcl fconfigure command. Other options can be added by each channel type. These channel type specific options are described in the manual entry for the Tcl command that creates a channel of that type; for example, the additional options for TCP-based channels are described in the manual entry for the Tcl socket command. The procedure normally returns TCL_OK. If an error occurs, it returns TCL_ERROR and calls Tcl_SetErrno to store an appropriate POSIX error code.

TCL_SETCHANNELOPTION

Tcl_SetChannelOption sets a new value newValue for an option optionName on channel. The procedure normally returns TCL_OK. If an error occurs, it returns TCL_ERROR; in addition, if interp is non-NULL, Tcl_SetChannelOption leaves an error message in the interpreter's result.

TCL_EOF

Tcl_Eof returns a nonzero value if channel encountered an end of file during the last input operation.

TCL_INPUTBLOCKED

Tcl_InputBlocked returns a nonzero value if channel is in nonblocking mode and the last input operation returned less data than requested because there was insufficient data available. The call always returns zero if the channel is in blocking mode.

TCL_INPUTBUFFERED

Tcl_InputBuffered returns the number of bytes of input currently buffered in the internal buffers for a channel. If the channel is not open for reading, this function always returns zero.

TCL_OUTPUTBUFFERED

Tcl_OutputBuffered returns the number of bytes of output currently buffered in the internal buffers for a channel. If the channel is not open for writing, this function always returns zero.

PLATFORM ISSUES

The handles returned from Tcl_GetChannelHandle depend on the platform and the channel type. On Unix platforms, the handle is always a Unix file descriptor as returned from the open system call. On Windows platforms, the handle is a file HANDLE when the channel was created with Tcl_OpenFileChannel, Tcl_OpenCommandChannel, or Tcl_MakeFileChannel. Other channel types may return a different type of handle on Windows platforms.
