NOMBRE

Type::Tiny::Manual::UsingWithMoose - cómo usar Type::Tiny con Moose

MANUAL

Primero lee Type::Tiny::Manual::UsingWithMoo, Type::Tiny::Manual::UsingWithMoo2 y Type::Tiny::Manual::UsingWithMoo3. Todo lo de esas partes del manual debería funcionar exactamente igual en Moose.

Esta parte del manual se centrará en los detalles específicos de Moose.

¿Por qué usar Type::Tiny en absoluto?

Moose tiene un sistema de restricciones de tipo incorporado que es bastante conveniente de usar, pero hay varias razones por las que deberías considerar usar Type::Tiny en su lugar.

  • Las restricciones de tipo de Type::Tiny suelen ser más rápidas que las integradas de Moose. Incluso sin Type::Tiny::XS instalado, Type::Tiny generalmente produce código en línea más eficiente que Moose. Las coerciones suelen ser mucho más rápidas.
  • Type::Tiny proporciona métodos útiles como "where" y "plus_coercions" que permiten ajustar fácilmente las restricciones de tipo y las coerciones por atributo.

    Algo como esto es mucho más difícil de hacer con tipos simples de Moose:

    has name => (
  is      => "ro",
  isa     => Str->plus_coercions(
    ArrayRef[Str], sub { join " ", @$_ },
  ),
  coerce  => 1,
);

    Moose tiende a fomentar la definición global de coerciones, así que si quisieras que un atributo Str pudiera ser coercionado desde ArrayRef[Str], entonces todos los atributos Str se coerccionarían desde ArrayRef[Str], y todos lo harían de la misma manera. (¡Incluso si pudiera tener sentido unir por un espacio en algunos lugares, una coma en otros, y un salto de línea en otros!).

  • Type::Tiny proporciona coerciones profundas automáticas, así que si el tipo Xyz tiene una coerción, lo siguiente debería "simplemente funcionar": 
    has xyzlist => ( is => 'ro', isa => ArrayRef[Xyz], coerce => 1 );
  • Type::Tiny ofrece una selección más amplia de tipos incorporados.
  • Al usar Type::Tiny, puedes usar las mismas restricciones de tipo y coerciones para atributos y parámetros de métodos, en código Moose y no Moose.

Type::Utils

Si has usado Moose::Util::TypeConstraints, es posible que estés acostumbrado a usar un DSL para declarar restricciones de tipo:

use Moose::Util::TypeConstraints;

subtype 'Natural',
  as 'Int',
  where { $_ > 0 };

Hay un módulo llamado Type::Utils que proporciona un DSL muy similar para declarar tipos en bibliotecas de tipos basadas en Type::Library.

package My::Types {
  use Type::Library -base;
  use Type::Utils;
  use Types::Standard qw( Int );

  declare 'Natural',
    as Int,
    where { $_ > 0 };
}

Personalmente, prefiero la forma más orientada a objetos de declarar tipos.

Desde Type::Library 1.012, ha habido un atajo disponible para importar Type::Library y Type::Utils al mismo tiempo:

package MyType {
  use Type::Library -base, -utils;

  ...;
}

En Moose, también podrías declarar tipos así dentro de clases y roles. A diferencia de Moose, Type::Tiny no guarda los tipos en un único espacio de nombres plano global, así que esto no funciona exactamente igual con Type::Utils. Todavía crea el tipo, pero no lo almacena en ninguna biblioteca de tipos; el tipo se devuelve.

package My::Class {
  use Moose;
  use Type::Utils;
  use Types::Standard qw( Int );

  my $Natural =          # almacena el tipo en una variable
    declare 'Natural',
    as Int,
    where { $_ > 0 };

  has number => ( is => 'ro', isa => $Natural );
}

Pero en serio, ¿no es la forma orientada a objetos más limpia?

package My::Class {
  use Moose;
  use Types::Standard qw( Int );

  has number => (
    is   => 'ro',
    isa  => Int->where('$_ > 0'),
  );
}

Type::Tiny y MooseX::Types

Types::Standard debería ser un reemplazo directo para MooseX::Types. Y Types::Common::Numeric y Types::Common::String deberían reemplazar fácilmente a MooseX::Types::Common::Numeric y MooseX::Types::Common::String.

Dicho esto, si deseas usar una mezcla de Type::Tiny y MooseX::Types, deberían encajar bastante bien.

use Types::Standard qw( ArrayRef );
use MooseX::Types::Common::Numeric qw( PositiveInt );

# esto debería funcionar sin problemas
my $list_of_nums = ArrayRef[PositiveInt];

# y esto
my $list_or_num = ArrayRef | PositiveInt;

Parámetro de importación "-moose"

Si has leído hasta aquí en el manual, sabrás que esta es la forma habitual de importar restricciones de tipo:

use Types::Standard qw( Int );

Y el "Int" que se importa es una función que no toma argumentos y devuelve la restricción de tipo Int, que es un objeto bendecido en la clase Type::Tiny.

Type::Tiny simula la API de Moose::Meta::TypeConstraint tan bien que la mayoría del código de Moose y MooseX no podrá notar la diferencia.

Pero, ¿y si necesitas un objeto Moose::Meta::TypeConstraint real?

use Types::Standard -moose, qw( Int );

Ahora la función "Int" importada devolverá una genuina restricción de tipo nativa de Moose.

Esta bandera es principalmente un vestigio de cuando los objetos nativos de Type::Tiny *no* funcionaban directamente en Moose. En el 99.9% de los casos, no hay razón para usarla y muchas razones para no hacerlo. (Las restricciones de tipo nativas de Moose no ofrecen métodos útiles como "plus_coercions" y "where").

Método "moose_type"

Otra forma rápida de obtener un objeto de restricción de tipo nativo de Moose desde un objeto Type::Tiny es llamar al método "moose_type":

use Types::Standard qw( Int );

my $tiny_type   = Int;
my $moose_type  = $tiny_type->moose_type;

Internamente, esto es lo que hace la bandera "-moose" en las funciones importadas.
