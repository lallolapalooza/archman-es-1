Type::Utils(3) Documentación de Perl contribuida por el usuario Type::Utils(3)

NOMBRE

Type::Utils - funciones de utilidad para facilitar la definición y el uso de restricciones de tipo

SINOPSIS

package Types::Mine;

use Type::Library -base;
use Type::Utils -all;

BEGIN { extends "Types::Standard" };

declare "AllCaps",
   as "Str",
   where { uc($_) eq $_ },
   inline_as { my $varname = $_[1]; "uc($varname) eq $varname" };

coerce "AllCaps",
   from "Str", via { uc($_) };

ESTADO

Este módulo está cubierto por la política de estabilidad de Type-Tiny.

DESCRIPCIÓN

Este módulo proporciona funciones de utilidad para facilitar la definición y el uso de restricciones de tipo.

Funciones de declaración de tipo

Muchas de las siguientes funciones son similares a las funciones del mismo nombre descritas en Moose::Util::TypeConstraints.

"declare $name, %options"
"declare %options"
Declara una restricción de tipo nombrada o anónima. Utiliza "as" y "where" para especificar el tipo padre (si lo hay) y (posiblemente) refinar su definición. 
declare EvenInt, as Int, where { $_ % 2 == 0 };
my $EvenInt = declare as Int, where { $_ % 2 == 0 };

NOTA: Los tipos nombrados se añadirán automáticamente al registro de tipos del llamador. (Ver Type::Registry.) Si el paquete llamador hereda de Type::Library, los tipos nombrados también se instalarán automáticamente en la biblioteca y estarán disponibles como exportaciones.

Gema oculta: si estás heredando de una restricción de tipo que incluye algunas coerciones, puedes incluir "coercion => 1" en el hash %options para heredar las coerciones.

"subtype $name, %options"
"subtype %options"
Declara una restricción de tipo nombrada o anónima que desciende de una restricción de tipo existente. Utiliza "as" y "where" para especificar el tipo padre y refinar su definición.

En realidad, deberías usar "declare" en su lugar; esto es solo un alias.

Esta función no se exporta por defecto.

"type $name, %options"
"type %options"
Declara una restricción de tipo nombrada o anónima que no desciende de una restricción de tipo existente. Utiliza "where" para proporcionar un coderef que restrinja los valores.

En realidad, deberías usar "declare" en su lugar; esto es solo un alias.

Esta función no se exporta por defecto.

"as $parent"
Se utiliza con "declare" para especificar una restricción de tipo padre: 
declare EvenInt, as Int, where { $_ % 2 == 0 };
"where { BLOCK }"
Se utiliza con "declare" para proporcionar el coderef de restricción: 
declare EvenInt, as Int, where { $_ % 2 == 0 };

El coderef opera sobre $_, que es el valor que se está probando.

"message { BLOCK }"
Genera un mensaje de error personalizado cuando un valor falla la validación. 
declare EvenInt,
   as Int,
   where { $_ % 2 == 0 },
   message {
      Int->validate($_) or "$_ no es divisible por dos";
   };

Sin un mensaje personalizado, los mensajes generados por Type::Tiny son del tipo El valor "33" no pasó la restricción de tipo "EvenInt", lo cual suele ser razonable.

"inline_as { BLOCK }"
Genera una cadena de código Perl que se puede utilizar para insertar la comprobación de tipo en otras funciones. Si tu comprobación de tipo se utiliza dentro de métodos constructores o accesores de Moose o Moo, o si es utilizada por Type::Params, esto puede conducir a mejoras significativas de rendimiento. 
declare EvenInt,
   as Int,
   where { $_ % 2 == 0 },
   inline_as {
      my ($constraint, $varname) = @_;
      my $perlcode = 
         $constraint->parent->inline_check($varname)
         . "&& ($varname % 2 == 0)";
      return $perlcode;
   };

warn EvenInt->inline_check('$xxx');  # demostración

Tu bloque "inline_as" puede devolver una lista, en cuyo caso estas se unirán con "&&". El primer elemento de la lista puede ser indefinido, en cuyo caso el indefinido será reemplazado por la restricción de tipo padre insertada. (Y lanzará una excepción si no hay padre.)

declare EvenInt,
   as Int,
   where { $_ % 2 == 0 },
   inline_as {
      return (undef, "($_ % 2 == 0)");
   };
"class_type $name, { class => $package, %options }"
"class_type { class => $package, %options }"
"class_type $name"
Atajo para declarar una restricción de tipo Type::Tiny::Class.

Si se omite $package, se asume que es el mismo que $name. Si $name contiene "::" (lo que sería un nombre inválido para Type::Tiny), se eliminará.

Por lo tanto, por ejemplo, class_type("Foo::Bar") declara una restricción de tipo Type::Tiny::Class llamada "FooBar" que restringe los valores a objetos bendecidos en el paquete "Foo::Bar".

"role_type $name, { role => $package, %options }"
"role_type { role => $package, %options }"
"role_type $name"
Atajo para declarar una restricción de tipo Type::Tiny::Role.

Si se omite $package, se asume que es el mismo que $name. Si $name contiene "::" (lo que sería un nombre inválido para Type::Tiny), se eliminará.

"duck_type $name, \@methods"
"duck_type \@methods"
Atajo para declarar una restricción de tipo Type::Tiny::Duck.
"union $name, \@constraints"
"union \@constraints"
Atajo para declarar una restricción de tipo Type::Tiny::Union.
"enum $name, \@values"
"enum \@values"
Atajo para declarar una restricción de tipo Type::Tiny::Enum.
"intersection $name, \@constraints"
"intersection \@constraints"
Atajo para declarar una restricción de tipo Type::Tiny::Intersection.

Funciones de declaración de coerción

Muchas de las siguientes funciones son similares a las funciones del mismo nombre descritas en Moose::Util::TypeConstraints.

"coerce $target, @coercions"
Añade coerciones al tipo de restricción de destino. La lista de coerciones es una lista de pares de restricciones de tipo y código de conversión. El código de conversión puede ser una cadena de código Perl o un coderef; en cualquier caso, el valor a convertir es $_.
"from $source"
Azúcar para especificar una restricción de tipo en una lista de coerciones: 
coerce EvenInt, from Int, via { $_ * 2 };  # Como coderef...
coerce EvenInt, from Int, q { $_ * 2 };    # ¡o como cadena!
"via { BLOCK }"
Azúcar para especificar un coderef en una lista de coerciones.
"declare_coercion $name, \%opts, $type1, $code1, ..."
"declare_coercion \%opts, $type1, $code1, ..."
Declara una coerción que no está explícitamente adjunta a ningún tipo en la biblioteca. Por ejemplo: 
declare_coercion "ArrayRefFromAny", from "Any", via { [$_] };

Esta coerción será exportable de la biblioteca como un objeto Type::Coercion, pero el tipo ArrayRef exportado por la biblioteca no la usará automáticamente.

Las coerciones declaradas de esta manera son inmutables (congeladas).

"to_type $type"
Se utiliza con "declare_coercion" para declarar la restricción de tipo de destino para una coerción, pero todavía es un lsin adjuntar explícitamente la coerción a la restricción de tipo: 
declare_coercion "ArrayRefFromAny",
   to_type "ArrayRef",
   from "Any", via { [$_] };

Deberías usar esto casi siempre al declarar una coerción no adjunta porque es extremadamente útil para una coerción de tipo saber a qué se va a coaccionar: esto permite omitir la coerción cuando no es necesaria (por ejemplo, evitar coaccionar "[]" a "[ [] ]") y permite que "assert_coerce" funcione correctamente.

Gestión de bibliotecas de tipos

"extends @libraries"
Indica que esta biblioteca de tipos extiende otras bibliotecas de tipos, importando sus restricciones de tipo.

Generalmente debería ejecutarse en un bloque "BEGIN".

Esto no se exporta por defecto porque no es agradable exportarlo a clases Moo, Moose o Mouse. Se puede usar "use Type::Utils -all" para importarlo a tu biblioteca de tipos.

Otros

"match_on_type $value => ($type => \&action, ..., \&default?)"
Algo parecido a una construcción "switch"/"case" o "given"/"when". Despacha por diferentes rutas de código dependiendo del tipo del valor entrante. Ejemplo robado descaradamente de la documentación de Moose: 
sub to_json
{
   my $value = shift;

   return match_on_type $value => (
      HashRef() => sub {
         my $hash = shift;
         '{ '
            . (
            join ", " =>
            map { '"' . $_ . '" : ' . to_json( $hash->{$_} ) }
            sort keys %$hash
         ) . ' }';
      },
      ArrayRef() => sub {
         my $array = shift;
         '[ '.( join ", " => map { to_json($_) } @$array ).' ]';
      },
      Num()   => q {$_},
      Str()   => q { '"' . $_ . '"' },
      Undef() => q {'null'},
      => sub { die "$_ no es un tipo json aceptable" },
   );
}

Nota que a diferencia de Moose, el código se puede especificar como una cadena en lugar de un coderef. (por ejemplo, para "Num", "Str" y "Undef" arriba).

Para un rendimiento mejorado, prueba "compile_match_on_type".

Esta función no se exporta por defecto.

"my $coderef = compile_match_on_type($type => \&action, ..., \&default?)"
Compila un bloque "match_on_type" en un coderef. El siguiente convertidor JSON es unas dos órdenes de magnitud más rápido que el ejemplo anterior: 
sub to_json;
*to_json = compile_match_on_type(
   HashRef() => sub {
      my $hash = shift;
      '{ '
         . (
         join ", " =>
         map { '"' . $_ . '" : ' . to_json( $hash->{$_} ) }
         sort keys %$hash
      ) . ' }';
   },
   ArrayRef() => sub {
      my $array = shift;
      '[ '.( join ", " => map { to_json($_) } @$array ).' ]';
   },
   Num()   => q {$_},
   Str()   => q { '"' . $_ . '"' },
   Undef() => q {'null'},
   => sub { die "$_ no es un tipo json aceptable" },
);

Recuerda almacenar el coderef en un lugar bastante permanente para no compilarlo una y otra vez. Las variables "state" (en Perl >= 5.10) son buenas para esto. (Misma idea que Type::Params.)

Esta función no se exporta por defecto.

"my $coderef = classifier(@types)"
Devuelve un coderef que puede usarse para clasificar valores según su restricción de tipo. El coderef, al recibir un valor, devuelve una restricción de tipo que el valor satisface. 
use feature qw( say );
use Type::Utils qw( classifier );
use Types::Standard qw( Int Num Str Any );

my $classifier = classifier(Str, Int, Num, Any);

say $classifier->( "42"  )->name;   # Int
say $classifier->( "4.2" )->name;   # Num
say $classifier->( []    )->name;   # Any

Ten en cuenta que, por ejemplo, "42" satisface Int, pero también satisfaría las restricciones de tipo Num, Str y Any. En este caso, el clasificador ha elegido la restricción de tipo más específica que "42" satisface.

Si ningún tipo de restricción es satisfecho por el valor, entonces el clasificador devolverá undef.

"dwim_type($string, %options)"
Dado una cadena como "ArrayRef[Int|CodeRef]", la convierte en un objeto de restricción de tipo, con la esperanza de hacer lo que quieres decir.

Utiliza la sintaxis de Type::Parser. Primero se consulta el Type::Registry del paquete llamante; si este no tiene una coincidencia, se consulta Types::Standard para nombres de restricciones de tipo estándar.

Si ninguna de las opciones anteriores produce una restricción de tipo, y la clase llamante es una clase basada en Moose, entonces "dwim_type" intenta buscar la restricción de tipo en el registro de tipos de Moose. Si es una clase basada en Mouse, se utiliza el registro de tipos de Mouse en su lugar.

Si no se encuentra una restricción de tipo a través de estos métodos normales, hay varias alternativas disponibles:

"lookup_via_moose"
Busca en el registro de Moose incluso si el llamante es una clase no-Moose.
"lookup_via_mouse"
Busca en el registro de Mouse incluso si el llamante es una clase no-Mouse.
"make_class_type"
Crea una nueva restricción de Type::Tiny::Class.
"make_role_type"
Crea una nueva restricción de Type::Tiny::Role.

Puedes alterar cuáles se intentan y en qué orden, pasando una opción a "dwim_type":

my $type = Type::Utils::dwim_type(
   "ArrayRef[Int]",
   fallback      => [ "lookup_via_mouse" , "make_role_type" ],
);

Por razones históricas, por defecto las alternativas intentadas son:

lookup_via_moose, lookup_via_mouse, make_class_type

Puedes establecer "fallback" a un arrayref vacío para evitar usar cualquiera de estas alternativas.

Puedes especificar una alternativa para el llamante usando la opción "for".

my $type = dwim_type("ArrayRef", for => "Moose::Object");

Aunque probablemente sea mejor en general usar la interfaz Type::Registry adecuada para resolver cadenas de restricciones de tipo, esta función a menudo hace lo que quieres.

Nunca debería fallar si no encuentra una restricción de tipo (pero puede fallar si la cadena de restricción de tipo está sintácticamente mal formada), prefiriendo devolver undef.

Esta función no se exporta por defecto.

"is($type, $value)"
Atajo para "$type->check($value)" pero también si $type es una cadena, la buscará a través de "dwim_type".

Esta función no se exporta por defecto. Esta función ni siquiera se exporta con "use Type::Utils -all". Debes solicitarla explícitamente.

use Type::Utils "is";

Ten cuidado al usar esto en scripts de prueba, ya que tiene el mismo nombre que una función exportada por Test::More. Ten en cuenta que puedes renombrar esta función si "is" causa conflictos:

use Type::Utils "is" => { -as => "isntnt" };
"assert($type, $value)"
Como "is" pero en lugar de devolver un booleano, devuelve $value y falla si el valor no pasa la comprobación de tipo.

Esta función no se exporta por defecto, pero se exporta con "use Type::Utils -all".

"english_list(\$conjunction, @items)"
Une los elementos con comas, colocando una conjunción antes del último elemento. La conjunción es opcional, por defecto es "and". 
english_list(qw/foo bar baz/);       # "foo, bar, y baz"
english_list(\"or", qw/quux quuux/); # "quux o quuux"

Esta función no se exporta por defecto.

EXPORTAR

Por defecto, todas las funciones documentadas anteriormente se exportan, excepto "subtype" y "type" (preferir "declare" en su lugar), "extends", "dwim_type", "match_on_type"/"compile_match_on_type", "classifier" y "english_list".

Este módulo utiliza Exporter::Tiny; consulta la documentación de ese módulo para obtener consejos y trucos para importar desde Type::Utils.
