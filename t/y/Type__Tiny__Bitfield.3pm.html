Paquete: perl-type-tiny

Type::Tiny::Bitfield(3) Documentación de Perl aportada por el usuario Type::Tiny::Bitfield(3)

NOMBRE

Type::Tiny::Bitfield - restricciones de tipo bitfield/bitflag

SINOPSIS

Usando la característica de exportación de Type::Tiny::Bitfield:

package LightSource {
  use Moo;

  use Type::Tiny::Bitfield LedSet => {
    RED   => 1,
    GREEN => 2,
    BLUE  => 4,
  };

  has leds => ( is => 'ro', isa => LedSet, default => 0, coerce => 1 );

  sub new_red {
    my $class = shift;
    return $class->new( leds => LEDSET_RED );
  }

  sub new_green {
    my $class = shift;
    return $class->new( leds => LEDSET_GREEN );
  }

  sub new_yellow {
    my $class = shift;
    return $class->new( leds => LEDSET_RED | LEDSET_GREEN );
  }
}

Usando la interfaz orientada a objetos de Type::Tiny::Bitfield:

package LightSource {
  use Moo;
  use Type::Tiny::Bitfield;

  my $LedSet = Type::Tiny::Bitfield->new(
    name   => 'LedSet',
    values => {
      RED   => 1,
      GREEN => 2,
      BLUE  => 4,
    },
    coercion => 1,
  );

  has leds => ( is => 'ro', isa => $LedSet, default => 0, coerce => 1 );

  sub new_red {
    my $class = shift;
    return $class->new( leds => $LedSet->RED );
  }

  sub new_green {
    my $class = shift;
    return $class->new( leds => $LedSet->GREEN );
  }

  sub new_yellow {
    my $class = shift;
    return $class->new( leds => $LedSet->coerce('red|green') );
  }
}

ESTADO

Este módulo está cubierto por la política de estabilidad de Type-Tiny.

DESCRIPCIÓN

Restricciones de tipo de campo de bits.

Este paquete hereda de Type::Tiny; consulta esa documentación para la mayor parte de la información. Las diferencias importantes se enumeran a continuación:

Atributos

"values"
Referencia hashref de los bits permitidos en el campo de bits. Las claves deben ser cadenas en formato UPPER_SNAKE_CASE. Los valores deben ser enteros positivos que sean potencias de dos. El mismo número no se puede usar varias veces.
"constraint"
A diferencia de Type::Tiny, no puedes pasar una referencia de función de restricción al constructor. Confía en el valor predeterminado en su lugar.
"inlined"
A diferencia de Type::Tiny, no puedes pasar una referencia de función de incrustación al constructor. Confía en el valor predeterminado en su lugar.
"parent"
El padre es siempre Types::Common::Numeric::PositiveOrZeroInt y no se puede pasar al constructor.
"coercion"
Si se pasa "coercion => 1" al constructor, el tipo tendrá una coerción automática desde Str. Los tipos creados por el método "import" siempre tendrán "coercion => 1".

En el ejemplo de SYNOPSIS, la coerción desde Str aceptará cadenas como:

"RED"
"red"
"Red Green"
"Red+Blue"
"blue | GREEN"
"LEDSET_RED + LeDsEt_green"

Métodos

Esta clase utiliza "AUTOLOAD" para permitir que los nombres de cada bit en el campo de bits se utilicen como métodos. Estos nombres de método siempre estarán en UPPER_SNAKE_CASE.

Por ejemplo, en la sinopsis, "LedSet->GREEN" devolvería 2.

Otros métodos que proporciona:

from_string( $str )
Proporciona la coerción estándar a partir de una cadena, incluso si esta restricción de tipo no tiene una coerción.
to_string( $int )
Realiza la coerción inversa.
constant_names()
Esto es una conveniencia para permitir:
use base 'Exporter::Tiny';
push our @EXPORT_OK, LineStyle->constant_names;

Exportaciones

Type::Tiny::Bitfield puede usarse como exportador.

use Type::Tiny::Bitfield LedSet => {
  RED    => 1,
  GREEN  => 2,
  BLUE   => 4,
};

Esto exportará las siguientes funciones a tu espacio de nombres:

"LedSet"
is_LedSet( $value )
assert_LedSet( $value )
to_LedSet( $string )
LedSet_to_Str( $value )
"LEDSET_RED"
"LEDSET_GREEN"
"LEDSET_BLUE"

Se pueden exportar varios tipos de campo de bits a la vez:

use Type::Tiny::Enum (
  LedSet     => { RED => 1, GREEN => 2, BLUE => 4 },
  LedPattern => { FLASHING => 1 },
);

Sobrecarga

Es posible combinar dos tipos de Bitfield usando el operador "+".

use Type::Tiny::Enum (
  LedSet     => { RED => 1, GREEN => 2, BLUE => 4 },
  LedPattern => { FLASHING => 8 },
);

has leds => (
  is      => 'ro',
  isa     => LedSet + LedPattern,
  default => 0,
  coerce  => 1
);

Esto permitirá valores como "11" (LEDSET_RED|LEDSET_GREEN|LEDPATTERN_FLASHING).

Se lanzará una excepción si alguno de los nombres en los dos tipos que se combinan entran en conflicto.
