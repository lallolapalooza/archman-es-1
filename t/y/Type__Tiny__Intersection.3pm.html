NOMBRE

Type::Tiny::Intersection - restricciones de tipo de intersección

SINOPSIS

Usando a través de la sobrecarga del operador "&":

package Local::Stash {
  use Moo;
  use Types::Common qw( LowerCaseStr StrLength );

  has identifier => (
    is   => 'ro',
    isa  => (LowerCaseStr) & (StrLength[4, 8]),
  );
}

my $x = Local::Stash->new( data => {} );  # no válido
my $y = Local::Stash->new( data => [] );  # no válido

Es una buena idea encerrar cada tipo que se interseca entre paréntesis para evitar que Perl interprete el "&" como el sigilo para un coderef.

Usando la interfaz orientada a objetos de Type::Tiny::Intersection:

package Local::Stash {
  use Moo;
  use Types::Common qw( LowerCaseStr StrLength );
  use Type::Tiny::Intersection;

  my $ShortLcStr = Type::Tiny::Intersection->new(
    name             => 'AnyData',
    type_constraints => [ LowerCaseStr, StrLength[4, 8] ],
  );

  has identifier => (
    is   => 'ro',
    isa  => $ShortLcStr,
  );
}

Usando la interfaz funcional de Type::Utils:

package Local::Stash {
  use Moo;
  use Types::Common qw( LowerCaseStr StrLength );
  use Type::Utils;

  my $ShortLcStr = intersection ShortLcStr => [ LowerCaseStr, StrLength[4, 8] ];

  has identifier => (
    is   => 'ro',
    isa  => $ShortLcStr,
  );
}

ESTADO

Este módulo está cubierto por la política de estabilidad de Type-Tiny.

DESCRIPCIÓN

Restricciones de tipo de intersección.

Las restricciones de tipo de intersección no son muy útiles con frecuencia. Considere la intersección de HashRef y ArrayRef. Un valor solo pasará si es tanto un hashref como un arrayref. Dado que ninguna de esas restricciones de tipo acepta "undef" u objetos sobrecargados, no hay ningún valor posible que pueda pasar ambas.

Lo cual no quiere decir que las intersecciones no sean nunca útiles, pero sucede con bastante poca frecuencia.

Este paquete hereda de Type::Tiny; consulte ese para la mayor parte de la documentación. Las principales diferencias se enumeran a continuación:

Constructor

El constructor "new" de Type::Tiny sigue funcionando, por supuesto. Pero también existe:

new_by_overload(%atributos)
Al igual que el constructor "new", pero a veces devolverá otra restricción de tipo que no es estrictamente una instancia de Type::Tiny::Intersection, pero que aún encapsula el mismo significado. Este constructor es utilizado por la sobrecarga del operador "&" de Type::Tiny.

Atributos

"type_constraints"
Arrayref de restricciones de tipo.

Cuando se pasa al constructor, si alguna de las restricciones de tipo en la intersección es en sí misma una restricción de tipo de intersección, esta se "explota" en la nueva intersección.

"constraint"
A diferencia de Type::Tiny, no puede pasar un coderef de restricción al constructor. En su lugar, confíe en el valor predeterminado.
"inlined"
A diferencia de Type::Tiny, no puede pasar un coderef de inlining al constructor. En su lugar, confíe en el valor predeterminado.
"parent"
A diferencia de Type::Tiny, no puede pasar un coderef de inlining al constructor. En su lugar, se calculará automáticamente un padre.

(Técnicamente, cualquiera de los tipos en la intersección podría tratarse como un tipo padre; elegimos el primero arbitrariamente).

Métodos

stringifies_to($constraint)
Ver Type::Tiny::ConstrainedObject.
numifies_to($constraint)
Ver Type::Tiny::ConstrainedObject.
"with_attribute_values($attr1 => $constraint1, ...)"
Ver Type::Tiny::ConstrainedObject.

Sobrecarga

•
La arrayrefificación llama a "type_constraints".
