Type::Tiny::Duck(3) Documentación de Perl aportada por el usuario Type::Tiny::Duck(3)

NOMBRE

Type::Tiny::Duck - restricciones de tipo basadas en el método "can"

SINOPSIS

Uso a través de Types::Standard:

package Logger {
  use Moo;
  use Types::Standard qw( HasMethods Bool );

  has debugging => ( is => 'rw', isa => Bool, default => 0 );
  has output    => ( is => 'ro', isa => HasMethods[ 'print' ] );

  sub warn {
    my ( $self, $message ) = @_;
    $self->output->print( "[ADVERTENCIA] $message\n" );
  }

  sub debug {
    my ( $self, $message ) = @_;
    $self->output->print( "[DEBUG] $message\n" ) if $self->debugging;
  }
}

Uso de la función de exportación de Type::Tiny::Duck:

package Logger {
  use Moo;
  use Types::Standard qw( Bool );
  use Type::Tiny::Duck Printable => [ 'print' ];

  has debugging => ( is => 'rw', isa => Bool, default => 0 );
  has output    => ( is => 'ro', isa => Printable );

  sub warn {
    my ( $self, $message ) = @_;
    $self->output->print( "[ADVERTENCIA] $message\n" );
  }

  sub debug {
    my ( $self, $message ) = @_;
    $self->output->print( "[DEBUG] $message\n" ) if $self->debugging;
  }
}

Uso de la interfaz orientada a objetos de Type::Tiny::Duck:

package Logger {
  use Moo;
  use Types::Standard qw( Bool );
  use Type::Tiny::Duck;

  my $Printable = Type::Type::Duck->new(
    name    => 'Printable',
    methods => [ 'print' ],
  );

  has debugging => ( is => 'rw', isa => Bool, default => 0 );
  has output    => ( is => 'ro', isa => $Printable );

  sub warn {
    my ( $self, $message ) = @_;
    $self->output->print( "[ADVERTENCIA] $message\n" );
  }

  sub debug {
    my ( $self, $message ) = @_;
    $self->output->print( "[DEBUG] $message\n" ) if $self->debugging;
  }
}

ESTADO

Este módulo está cubierto por la política de estabilidad de Type-Tiny.

DESCRIPCIÓN

Restricciones de tipo de la forma general "{ $_->can("método") }".

El nombre hace referencia al dicho: "Si parece un pato, nada como un pato y grazna como un pato, entonces probablemente es un pato". La tipificación de pato puede ser una forma más flexible de probar objetos que confiar en "isa", ya que permite a las personas sustituir fácilmente objetos simulados.

Este paquete hereda de Type::Tiny; consulta ese para la mayoría de la documentación. Las diferencias importantes se enumeran a continuación:

Constructores

El constructor "new" de Type::Tiny sigue funcionando, por supuesto. Pero también existe:

"new_intersection( type_constraints => \@ducklings, %opts )"
Crea una nueva restricción de tipo de pato que es la intersección de restricciones de tipo de pato existentes. Esto permite que la intersección de "HasMethods['read']" y "HasMethods['write']" sea simplemente "HasMethods['read', 'write']" en lugar de una restricción de tipo de unión compleja con dos restricciones de tipo de pato como sus hijos.

Atributos

"methods"
Un arrayref de nombres de métodos.
"constraint"
A diferencia de Type::Tiny, no puede pasar una referencia de función de restricción al constructor. En su lugar, confíe en el valor predeterminado.
"inlined"
A diferencia de Type::Tiny, no puede pasar una referencia de función de inserción al constructor. En su lugar, confíe en el valor predeterminado.
"parent"
El padre es siempre Types::Standard::Object y no se puede pasar al constructor.

Métodos

stringifies_to($constraint)
Ver Type::Tiny::ConstrainedObject.
numifies_to($constraint)
Ver Type::Tiny::ConstrainedObject.
"with_attribute_values($attr1 => $constraint1, ...)"
Ver Type::Tiny::ConstrainedObject.

Exportaciones

Type::Tiny::Duck se puede utilizar como exportador.

use Type::Tiny::Duck HttpClient => [ 'get', 'post' ];

Esto exportará las siguientes funciones a su espacio de nombres:

"HttpClient"
is_HttpClient( $value )
assert_HttpClient( $value )
to_HttpClient( $value )

Se pueden exportar varios tipos a la vez:

use Type::Tiny::Duck (
  HttpClient   => [ 'get', 'post' ],
  FtpClient    => [ 'upload', 'download' ],
);
