NOMBRE

Type::Tiny::Manual::UsingWithOther - uso de Type::Tiny con Class::InsideOut, Params::Check y Object::Accessor.

MANUAL

El equipo de antlers no son los únicos kits de herramientas de programación orientada a objetos en Perl. Aunque Type::Tiny puede haber sido construido pensando en Moose, Mouse y Moo, se puede usar con otras herramientas.

Estas herramientas son... bueno... mmm... está bien... existen.

Si está comenzando un nuevo proyecto, hay muy poca razón para no usar Class::Tiny, Moo o Moose. Así que probablemente pueda omitir esta parte del manual y pasar directamente a Type::Tiny::Manual::UsingWithTestMore.

Class::InsideOut

Necesita Class::InsideOut 1.13 o superior, que tiene soporte para objetos bendecidos y sobrecargados (incluyendo las restricciones de tipo de Type::Tiny) para las opciones "get_hook" y "set_hook".

package Person {
  use Class::InsideOut qw( public );
  use Types::Standard qw( Str Int );
  use Types::Common::Numeric qw( PositiveInt );
  use Type::Params qw( signature_for );

  # Las comprobaciones de tipo son realmente fáciles.
  # Simplemente proporciona el tipo como un hook de conjunto.
  public name => my %_name, {
    set_hook => Str,
  };

  # Define un tipo que transforma silenciosamente los valores negativos
  # en positivos. ¡Es tonto, pero funciona como ejemplo!
  my $Years = PositiveInt->plus_coercions(Int, q{ abs($_) });

  # Las transformaciones son más molestas, pero posibles.
  public age => my %_age, {
    set_hook => sub { $_ = $Years->assert_coerce($_) },
  };

  # La comprobación de parámetros para los métodos es como se espera.
  signature_for get_older => ( method => 1, positional => [ $Years ] );

  sub get_older ( $self, $years ) {
    $self->_set_age( $self->age + $years );
  }
}

Params::Check y Object::Accessor

La función allow() de Params::Check, la opción "allow" para la función check() de Params::Check y el mecanismo de validación de entrada para Object::Accessor funcionan todos de la misma manera, que básicamente es una implementación limitada en Pura Perl del operador de coincidencia inteligente (smart match). Si bien esto no soporta directamente las restricciones de Type::Tiny, sí soporta coderefs. Puede usar el método "compiled_check" de Type::Tiny para obtener un coderef adecuado.

Ejemplo de Param::Check:

my $tmpl = {
  name => { allow => Str->compiled_check },
  age  => { allow => Int->compiled_check },
};
check($tmpl, { name => "Bob", age => 32 })
  or die Params::Check::last_error();

Ejemplo de Object::Accessor:

my $obj = Object::Accessor->new;
$obj->mk_accessors(
  { name => Str->compiled_check },
  { age  => Int->compiled_check },
);

Advertencia: Object::Accessor no muere cuando un valor no cumple su restricción de tipo; en su lugar, emite una advertencia a STDERR. Este comportamiento se puede cambiar estableciendo "$Object::Accessor::FATAL = 1".

Class::Struct

Esta es una prueba de concepto de cómo se puede usar Type::Tiny para restringir atributos para Class::Struct. Probablemente no sea una buena idea usar esto en producción, ya que ralentiza "UNIVERSAL::isa" globalmente.

use Types::Standard -types;
use Class::Struct;
{
  my %MAP;
  my $orig_isa = \&UNIVERSAL::isa;
  *UNIVERSAL::isa = sub {
    return $MAP{$1}->check($_[0])
      if $_[1] =~ /^CLASSSTRUCT::TYPETINY::(.+)$/ && exists $MAP{$1};
    goto $orig;
  };
  my $orig_dn = \&Type::Tiny::display_name;
  *Type::Tiny::display_name = sub {
    if (caller(1) eq 'Class::Struct') {
      $MAP{$_[0]{uniq}} = $_[0];
      return "CLASSSTRUCT::TYPETINY::".$_[0]{uniq};
    }
    goto $orig_dn;
  };
}
struct Person => [ name => Str, age => Int ];
my $bob = Person->new(
  name => "Bob",
  age  => 21,
);
$bob->name("Robert");   # ok
$bob->name([]);         # muere

Class::Plain

Actualmente no hay un alto nivel de integración, pero aquí hay un ejemplo rápido de comprobación de tipos de atributos en el constructor.

Si alguno de sus accesorios es ":rw", entonces también debería agregar comprobaciones de tipo a esos.

use Class::Plain;

class Point {
  use Types::Common -types, -sigs;

  field x :reader;
  field y :reader;

  signature_for new => (
    method => !!1,
    bless  => !!0,
    named  => [
      x => Int,
      y => Int,
    ],
  );

  method as_arrayref () {
    return [ $self->x, $self->y ];
  }
}

La siguiente firma también puede ser de interés:

signature_for new => (
  method   => !!1,
  multiple => [
    {
      named => [
        x => Int,
        y => Int,
      ],
      bless => !!0,
    },
    {
      positional => [ Int, Int ],
      goto_next  => sub {
        my ( $class, $x, $y ) = @_;
        return ( $class, { x => $x, y => $y } ),
      },
    },
  ],
);

Esto permitiría que su clase se instanciara utilizando cualquiera de los siguientes:

my $point11 = Point->new( { x => 1, y => 1 } );
my $point22 = Point->new(   x => 2, y => 2   );
my $point33 = Point->new( 3, 3 );
