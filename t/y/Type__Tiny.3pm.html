NOMBRE

Type::Tiny - restricción de tipo diminuta pero compatible con Moo(se)

SINOPSIS

use v5.36;

package Horse {
  use Moo;
  use Types::Standard qw( Str Int Enum ArrayRef Object );
  use Type::Params qw( signature_for );
  use namespace::autoclean;

  has name => (
    is       => 'ro',
    isa      => Str,
    required => 1,
  );

  has gender => (
    is       => 'ro',
    isa      => Enum[qw( f m )],
  );

  has age => (
    is       => 'rw',
    isa      => Int->where( '$_ >= 0' ),
  );

  has children => (
    is       => 'ro',
    isa      => ArrayRef[Object],
    default  => sub { return [] },
  );

  # firma del método
  signature_for add_child => (
    method     => Object,
    positional => [ Object ],
  );

  sub add_child ( $self, $child ) {
    push $self->children->@*, $child;
    return $self;
  }
}

package main;

my $boldruler = Horse->new(
  name    => "Bold Ruler",
  gender  => 'm',
  age     => 16,
);

my $secretariat = Horse->new(
  name    => "Secretariat",
  gender  => 'm',
  age     => 0,
);

$boldruler->add_child( $secretariat );

ESTADO

Este módulo está cubierto por la política de estabilidad de Type-Tiny.

DESCRIPCIÓN

Esto documenta los detalles internos de la clase Type::Tiny. Type::Tiny::Manual es un mejor punto de partida si eres nuevo.

Type::Tiny es una pequeña clase para crear objetos de restricción de tipo similares a Moose que son compatibles con Moo, Moose y Mouse.

use Scalar::Util qw(looks_like_number);
use Type::Tiny;

my $NUM = "Type::Tiny"->new(
   name       => "Number",
   constraint => sub { looks_like_number($_) },
   message    => sub { "$_ no es un número" },
);

package Ermintrude {
   use Moo;
   has favourite_number => (is => "ro", isa => $NUM);
}

package Bullwinkle {
   use Moose;
   has favourite_number => (is => "ro", isa => $NUM);
}

package Maisy {
   use Mouse;
   has favourite_number => (is => "ro", isa => $NUM);
}

Type::Tiny se ajusta a Type::API::Constraint, Type::API::Constraint::Coercible, Type::API::Constraint::Constructor, y Type::API::Constraint::Inlinable.

¿Quizás ahora no necesitemos tener versiones separadas MooseX, MouseX y MooX para todo? Podemos esperar...

Constructor

new(%atributos)
Función constructora estilo Moose.

Atributos

Los atributos son valores nombrados que pueden pasarse al constructor. Para cada atributo, hay un método lector correspondiente. Por ejemplo:

my $type = Type::Tiny->new( name => "Foo" );
print $type->name, "\n";   # dice "Foo"

Atributos importantes

Estos son los atributos que probablemente más te interesará proporcionar al crear tus propias restricciones de tipo, y los que más interesará leer al tratar con objetos de restricción de tipo.

"constraint"
Coderef para validar un valor ($_) contra la restricción de tipo. El coderef no se llamará a menos que se sepa que el valor pasa cualquier restricción de tipo padre (ver "parent" abajo).
Alternativamente, se puede pasar una cadena de código Perl que verifique $_ como parámetro al constructor, y se convertirá a un coderef.
Por defecto es "sub { 1 }" - es decir, un coderef que pasa todos los valores.
"parent"
Atributo opcional; restricción de tipo padre. Por ejemplo, una restricción de tipo "Integer" podría tener un padre "Number".
Si se proporciona, debe ser un objeto Type::Tiny.
"inlined"
Un coderef que devuelve una cadena de código Perl adecuada para incrustar este tipo. Opcional.
(Se llamará al coderef en contexto de lista y puede devolver una lista de cadenas que se unirán con "&&". Si el primer elemento de la lista es undef, se sustituirá con la verificación de incrustación del padre del tipo).
Si el "constraint" (arriba) es un coderef generado a través de Sub::Quote, entonces Type::Tiny *puede* generar "inlined" automáticamente para ti. Si el "constraint" (arriba) es una cadena, podrá hacerlo.
"name"
El nombre de la restricción de tipo. Estos deben cumplir ciertas reglas de nomenclatura (deben comenzar con una letra mayúscula y continuar usando solo letras, dígitos 0-9 y guiones bajos).
Opcional; si no se proporciona, será una restricción de tipo anónima.
"display_name"
Un nombre para mostrar de la restricción de tipo cuando se convierte a cadena. Estos no tienen que cumplir ninguna regla de nomenclatura. Opcional; se calculará un nombre predeterminado a partir del "name".
"library"
El nombre del paquete de la biblioteca de tipos a la que está asociado este tipo. Opcional. Solo informativo: establecer este atributo no instala el tipo en el paquete.
"deprecated"
Booleano opcional que indica si una restricción de tipo está obsoleta. Type::Library emitirá una advertencia si intentas importar una restricción de tipo obsoleta, pero por lo demás el tipo continuará funcionando normalmente. No habrá advertencias de obsolescencia cada vez que valides un valor, por ejemplo. Si se omite, se usará el estado de obsolescencia del padre (o falso si no hay padre).
"message"
Coderef que devuelve un mensaje de error cuando $_ no valida contra la restricción de tipo. Opcional (hay un valor predeterminado vagamente sensato).
"coercion"
Un objeto Type::Coercion asociado con este tipo.
En términos generales, este atributo no debe pasarse al constructor; debes confiar en el objeto de coerción predeterminado construido de forma perezosa.
Puedes pasar "coercion => 1" al constructor para heredar coerciones del padre de la restricción. (Esto requiere que la restricción padre tenga una coerción).
Si se pasa un arrayref al constructor ("coercion => [ ... ]"), el objeto de coerción se construirá de forma perezosa y este array se pasará a su método "add_type_coercions". Si se pasa un coderef al constructor ("coercion => sub { ... }"), el objeto de coerción se construirá de forma perezosa y este código se usará como una coerción desde Any.
"sorter"
Un coderef que puede recibir dos valores que se ajustan a esta restricción de tipo y devuelve -1, 0 o 1 para ponerlos en orden. Alternativamente, un arrayref que contiene un par de coderefs — un clasificador y un pre-procesador para la transformada de Schwarzian. Opcional.
La idea es permitir:
@sorted = Int->sort( 2, 1, 11 );    # => 1, 2, 11
@sorted = Str->sort( 2, 1, 11 );    # => 1, 11, 2
"type_default"
Un coderef que devuelve un valor predeterminado sensato para este tipo. Por ejemplo, para un tipo Counter, un valor predeterminado sensato podría ser "0": 
my $Size = Type::Tiny->new(
  name          => 'Size',
  parent        => Types::Standard::Enum[ qw( XS S M L XL ) ],
  type_default  => sub { return 'M'; },
);

package Tshirt {
  use Moo;
  has size => (
    is       => 'ro',
    isa      => $Size,
    default  => $Size->type_default,
  );
}

Los tipos hijos heredarán un valor predeterminado de tipo de su padre a menos que el hijo tenga una "constraint". Si un tipo no tiene ni hereda un valor predeterminado de tipo, entonces llamar a "type_default" devolverá undef.

Como caso especial, esto:

$type->type_default( @args )

Devolverá:

sub {
  local $_ = \@args;
  $type->type_default->( @_ );
}

Muchos de los tipos definidos en Types::Standard y otras bibliotecas de tipos incluidas tienen valores predeterminados de tipo

of(@parameters)
Un alias bonito para "parameterize". Úsalo como "ArrayRef->of(Int)".
"plus_coercions($type1, $code1, ...)"
Atajo para crear una nueva restricción de tipo hijo con las mismas coerciones que esta, pero añadiendo algunas coerciones extra (con una prioridad mayor que las existentes).
"plus_fallback_coercions($type1, $code1, ...)"
Similar a "plus_coercions", pero añadida con una prioridad menor.
"minus_coercions($type1, ...)"
Atajo para crear una nueva restricción de tipo hijo con menos coerciones de tipo.
"no_coercions"
Atajo para crear una nueva restricción de tipo hijo sin ninguna coerción.

Métodos de introspección de relaciones de tipo

Estos métodos te permiten determinar la relación de una restricción de tipo con otras restricciones de tipo en una jerarquía organizada:

equals($other), is_subtype_of($other), is_supertype_of($other), is_a_type_of($other)
Compara dos tipos. Consulta Moose::Meta::TypeConstraint para saber qué significan todos estos. (Ok, Moose no define "is_supertype_of", pero entiendes la idea, ¿verdad?)

Ten en cuenta que estos tienen un lado ligeramente DWIM (Do What I Mean). Si creas dos objetos Type::Tiny::Class que comprueban la misma clase, se consideran iguales. Y:

my $subtype_of_Num = Types::Standard::Num->create_child_type;
my $subtype_of_Int = Types::Standard::Int->create_child_type;
$subtype_of_Int->is_subtype_of( $subtype_of_Num );  # true
strictly_equals($other), is_strictly_subtype_of($other), is_strictly_supertype_of($other), is_strictly_a_type_of($other)
Versiones más estrictas de las funciones de comparación de tipos. Estas solo consideran la herencia explícita a través de "parent". 
my $subtype_of_Num = Types::Standard::Num->create_child_type;
my $subtype_of_Int = Types::Standard::Int->create_child_type;
$subtype_of_Int->is_strictly_subtype_of( $subtype_of_Num );  # false
"parents"
Devuelve una lista de todas las restricciones de tipo ancestro de esta restricción. Por ejemplo, si se llama en la restricción de tipo "Str", devolvería la lista "(Value, Defined, Item, Any)".

Debido a un malentendido histórico, esto difiere de la implementación de Moose de la método "parents". En Moose, "parents" solo devuelve las restricciones de tipo padre inmediatas, y debido a que las restricciones de tipo solo tienen un padre inmediato, esto es efectivamente un alias para "parent". El módulo de extensión MooseX::Meta::TypeConstraint::Intersection es el único lugar donde se devuelven múltiples restricciones de tipo; y se devuelven como un arrayref violando la documentación de la clase base. Mantengo mi comportamiento ya que parece más útil.

find_parent($coderef)
Recorre las restricciones de tipo padre *incluyendo la invocante* *misma* y devuelve la restricción de tipo ancestro más cercana donde la coderef evalúa a verdadero. Dentro de la coderef, el ancestro que se está comprobando actualmente es $_. Devuelve undef si no hay coincidencia.

En contexto de lista, también devuelve el número de restricciones de tipo que se recorrieron antes de encontrar la restricción coincidente.

"find_constraining_type"
Encuentra la restricción de tipo ancestro más cercana (incluyendo el tipo mismo) que tenga una coderef de "constraint".

Equivalente a:

$type->find_parent(sub { not $_->_is_null_constraint })
"coercibles"
Devuelve una restricción de tipo que es la unión de las restricciones de tipo que pueden ser coaccionadas a esta (incluida esta). Si esta restricción de tipo no tiene coerciones, se devuelve a sí misma.
"type_parameter"
En restricciones de tipo parametrizadas, devuelve el primer elemento de la lista de parámetros; de lo contrario, devuelve undef. Por ejemplo: 
( ArrayRef[Int] )->type_parameter;    # devuelve Int
( ArrayRef[Int] )->parent;            # devuelve ArrayRef

Ten en cuenta que las restricciones de tipo parametrizables pueden, de forma perfectamente legítima, aceptar múltiples parámetros (varias de las restricciones de tipo parametrizables en Types::Standard lo hacen). Este método solo devuelve el primer parámetro. Los "Atributos relacionados con tipos parametrizables y parametrizados" documentan el atributo "parameters", que devuelve un arrayref de todos los parámetros.

"parameterized_from"
Alias más difícil de escribir para "parent" que solo funciona para tipos parametrizados.

Pista para quienes subclasan Type::Tiny: Desde la versión 1.006000, los métodos para determinar el subtipo, supertipo y la igualdad de tipos no deben ser anulados en las subclases de Type::Tiny. Esto se debe al problema de la herencia en diamante. Si X e Y son subclases de Type::Tiny, ambas necesitan ser consultadas para determinar cómo se relacionan las restricciones de tipo; no solo una de ellas debe anular estos métodos. Consulta el código fuente de Type::Tiny::Enum para ver un ejemplo de cómo las subclases pueden dar pistas sobre las relaciones de tipo a Type::Tiny. Resumen: añade una coderef a @Type::Tiny::CMP. Esta coderef recibirá dos restricciones de tipo. Debería devolver una de las constantes Type::Tiny::CMP_SUBTYPE (el primer tipo es un subtipo del segundo tipo), Type::Tiny::CMP_SUPERTYPE (el segundo tipo es un subtipo del primer tipo), Type::Tiny::CMP_EQUAL (los dos tipos son exactamente iguales), Type::Tiny::CMP_EQUIVALENT (los dos tipos son efectivamente iguales), o Type::Tiny::CMP_UNKNOWN (tu coderef no pudo establecer ninguna relación).

Función de introspección de relaciones de tipo

"Type::Tiny::cmp($type1, $type2)"
La relación subtipo/supertipo entre tipos resulta en un orden parcial de las restricciones de tipo.

Esta función devolverá una de las constantes: Type::Tiny::CMP_SUBTYPE (el primer tipo es un subtipo del segundo tipo), Type::Tiny::CMP_SUPERTYPE (el segundo tipo es un subtipo del primer tipo), Type::Tiny::CMP_EQUAL (los dos tipos son exactamente iguales), Type::Tiny::CMP_EQUIVALENT (los dos tipos son efectivamente iguales), o Type::Tiny::CMP_UNKNOWN (no se pudo establecer ninguna relación). En contextos numéricos, estos se evalúan a -1, 1, 0, 0 y 0, lo que lo hace potencialmente utilizable con "sort" (aunque puede que necesites silenciar las advertencias sobre tratar la cadena vacía como un valor numérico).

Métodos de procesamiento de listas

grep(@list)
Filtra una lista para devolver solo los elementos que pasan la verificación de tipo. 
@integers = Int->grep(@list);
first(@list)
Filtra la lista para devolver el primer elemento de la lista que pasa la verificación de tipo, o undef si ninguno lo hace. 
$first_lady = Woman->first(@people);
map(@list)
Coacciona una lista de elementos. Solo funciona en tipos que tienen una coerción. 
@truths = Bool->map(@list);
sort(@list)
Ordena una lista de elementos según el mecanismo de ordenación preferido del tipo, o si el tipo no tiene una coderef de ordenación, utiliza el tipo padre. Si ningún tipo de restricción ancestro tiene una ordenación, lanza una excepción. Las restricciones de tipo "Str", "StrictNum", "LaxNum" y "Enum" incluyen ordenadores. 
@sorted_numbers = Num->sort( Num->grep(@list) );
rsort(@list)
Similar a "sort" pero en orden inverso.
any(@list)
Devuelve verdadero si alguno de los elementos de la lista coincide con el tipo. 
if ( Int->any(@numbers) ) {
  say "había al menos un entero";
}
all(@list)
Devuelve verdadero si todos los elementos de la lista coinciden con el tipo. 
if ( Int->all(@numbers) ) {
  say "eran todos enteros";
}
assert_any(@list)
Similar a "any" pero en lugar de devolver un booleano, devuelve la lista original completa si algún elemento coincide con el tipo, y muere si ninguno lo hace.
assert_all(@list)
Similar a "all" pero en lugar de devolver un booleano, devuelve la lista original si todos los elementos coinciden con el tipo, pero muere tan pronto como encuentra uno que no lo hace.

Métodos de inlining

Los siguientes métodos se utilizan para generar cadenas de código Perl que pueden ser pegadas en subs stringy "eval"uadas para realizar verificaciones de tipo:

"can_be_inlined"
Devuelve un booleano indicando si este tipo puede ser inlined.
inline_check($varname)
Crea una verificación de restricción de tipo para una variable particular como una cadena de código Perl. Por ejemplo: 
print( Types::Standard::Num->inline_check('$foo') );

imprime la siguiente salida:

(!ref($foo) && Scalar::Util::looks_like_number($foo))

Para compatibilidad con Moose, hay un alias "_inline_check" para este método.

inline_assert($varname)
Muy similar a "inline_check" pero genera una declaración de la forma: 
... or die ...;

También se puede llamar como "inline_assert($varname, $typevarname, %extras)". En este caso, generará una cadena de

{ "html": "\n que puede incluir $typevarname que se supone\n que es el nombre de una variable que contiene el tipo en sí. (Esto es algo\n complicado, pero permite que se produzca una cadena útil incluso si el\n tipo no se puede insertar en línea). Los %extras son\n opciones adicionales para pasar al constructor de Error::TypeTiny::Assertion\n y deben ser pares clave-valor de cadenas solamente, sin referencias ni undefs.

Variables de Paquete

\n
\n
$Type::Tiny::DD
\n
\n Por defecto es undef, pero puede configurarse como un coderef que Type::Tiny y\n módulos relacionados utilizarán para volcar estructuras de datos en mensajes\n de error, por ejemplo.\n

De lo contrario, Type::Tiny utiliza su propia rutina para volcar\n estructuras de datos. $DD puede entonces establecerse a un número para\n limitar la longitud de los volcados. (El límite por defecto es 72).\n

\n

Esta es una variable de paquete (en lugar de métodos de clase get/set)\n para permitir una localización fácil.

\n
\n
$Type::Tiny::AvoidCallbacks
\n
\n Si esta variable se establece a verdadero (normalmente debería hacerse en un\n ámbito "local"), actúa como una pista para las restricciones de tipo,\n al generar código insertado, para evitar hacer llamadas a variables y funciones\n definidas fuera del propio código insertado.\n

Esto debería tener el efecto de que\n "$type->inline_check('$foo')" devuelva una cadena de código capaz de verificar el tipo en\n instalaciones de Perl que no tengan Type::Tiny instalado. Esto está destinado a\n permitir que Type::Tiny se utilice con cosas como Mite.\n

\n

La variable funciona bajo el sistema de honor. Los tipos necesitan\n verificarla explícitamente y decidir generar código diferente basándose en su valor de verdad.\n Los tipos incluidos en Types::Standard,\n Types::Common::Numeric y Types::Common::String lo hacen.\n (StrMatch a veces no puede hacerlo y emitirá una advertencia si necesita depender de\n callbacks cuando se le pide que no lo haga).\n

\n

La mayoría de los usuarios normales pueden ignorar esto.

\n
\n
$Type::Tiny::SafePackage
\n
\n Esta es la cadena "package Type::Tiny;" que a veces se inserta en cadenas\n de código insertado para evitar conflictos de nombres. En la mayoría de los casos,\n no necesita cambiar esto. Sin embargo, si está insertando código de restricción\n de tipo, guardando ese código en módulos de Perl y subiéndolos a CPAN,\n es posible que desee cambiarlo para evitar problemas con el indexador de CPAN.\n La mayoría de los usuarios normales de Type::Tiny no necesitan ser conscientes de esto.\n

Type::Tiny(3pm)

NAME

Type::Tiny - A simpler, faster, and more powerful alternative to Moose::Util::TypeTiny

SYNOPSIS

use Type::Tiny;

my $string_type = type "Str";
my $int_type = type "Int";

say $string_type->check("hello");   # OK
# $string_type->check(42);          # Throws exception

say $int_type->check(42);            # OK
# $int_type->check("hello");      # Throws exception

my $array_of_strings_type = type "Array[Str]";
say $array_of_strings_type->check(["a", "b"]); # OK
# $array_of_strings_type->check(["a", 42]);     # Throws exception

STATUS

Production ready. This module is stable.

DESCRIPTION

Type::Tiny is a small, fast, and powerful type constraint library for Perl. It is designed to be a drop-in replacement for Moose::Util::TypeTiny, but with significant improvements in performance and functionality.

Type::Tiny supports a wide range of type constraints, including built-in types like Str, Int, Num, Bool, Undef, Maybe[T], ArrayRef, HashRef, CodeRef, RegexpRef, Object, etc.

It also allows you to define your own custom types using a simple and intuitive syntax.
