NOMBRE

Type::Tiny::Manual::UsingWithMouse - cómo usar Type::Tiny con Mouse

MANUAL

Primero lee Type::Tiny::Manual::UsingWithMoo, Type::Tiny::Manual::UsingWithMoo2, y Type::Tiny::Manual::UsingWithMoo3. Todo en esas partes del manual debería funcionar exactamente igual en Mouse.

Esta parte del manual se centrará en las especificidades de Mouse.

En general, Type::Tiny está menos probado con Mouse que con Moose y Moo, pero todavía hay un buen número de casos de prueba para usar Type::Tiny con Mouse, y no hay problemas importantes conocidos con el soporte de Type::Tiny para Mouse.

¿Por qué usar Type::Tiny en absoluto?

Mouse tiene un sistema de restricciones de tipo incorporado que es bastante conveniente de usar, pero hay varias razones por las que deberías considerar usar Type::Tiny en su lugar.

  • Type::Tiny proporciona métodos útiles como "where" y "plus_coercions" que permiten que las restricciones de tipo y las coerciones se ajusten fácilmente por atributo.

    Algo como esto es mucho más difícil de hacer con tipos de Mouse simples:

    has name => (
  is      => "ro",
  isa     => Str->plus_coercions(
    ArrayRef[Str], sub { join " ", @$_ },
  ),
  coerce  => 1,
);

    Mouse tiende a fomentar la definición global de coerciones, así que si quisieras que un atributo Str pudiera ser coaccionado desde ArrayRef[Str], entonces todos los atributos Str serían coaccionados desde ArrayRef[Str], y todos harían esa coerción de la misma manera. (¡Incluso si pudiera tener sentido unir por un espacio en algunos lugares, una coma en otros, y un salto de línea en otros!)

  • Type::Tiny proporciona coerciones profundas automáticas, por lo que si el tipo Xyz tiene una coerción, lo siguiente debería funcionar "simplemente": 
    has xyzlist => ( is => 'ro', isa => ArrayRef[Xyz], coerce => 1 );
  • Type::Tiny ofrece una selección más amplia de tipos incorporados.
  • Al usar Type::Tiny, puedes usar las mismas restricciones de tipo y coerciones para atributos y parámetros de métodos, en código con y sin Mouse.

Type::Utils

Si has usado Mouse::Util::TypeConstraints, es posible que estés acostumbrado a usar un DSL para declarar restricciones de tipo:

use Mouse::Util::TypeConstraints;

subtype 'Natural',
  as 'Int',
  where { $_ > 0 };

Hay un módulo llamado Type::Utils que proporciona un DSL muy similar para declarar tipos en bibliotecas de tipos basadas en Type::Library.

package My::Types {
  use Type::Library -base;
  use Type::Utils;
  use Types::Standard qw( Int );

  declare 'Natural',
    as Int,
    where { $_ > 0 };
}

Personalmente, prefiero la forma más orientada a objetos de declarar tipos, sin embargo.

En Mouse, también podrías declarar tipos de esta manera dentro de clases y roles. A diferencia de Mouse, Type::Tiny no mantiene los tipos en un único espacio de nombres plano global, por lo que esto no funciona exactamente igual con Type::Utils. Todavía crea el tipo, pero no lo almacena en ninguna biblioteca de tipos; se devuelve el tipo.

package My::Class {
  use Mouse;
  use Type::Utils;
  use Types::Standard qw( Int );

  my $Natural =          # almacena el tipo en una variable
    declare 'Natural',
    as Int,
    where { $_ > 0 };

  has number => ( is => 'ro', isa => $Natural );
}

¿Pero realmente, no es la forma orientada a objetos más limpia?

package My::Class {
  use Mouse;
  use Types::Standard qw( Int );

  has number => (
    is   => 'ro',
    isa  => Int->where('$_ > 0'),
  );
}

Type::Tiny y MouseX::Types

Types::Standard debería ser un reemplazo directo para MooseX::Types. Y Types::Common::Numeric y Types::Common::String deberían reemplazar fácilmente a MouseX::Types::Common::Numeric y MouseX::Types::Common::String.

Dicho esto, si deseas usar una mezcla de Type::Tiny y MouseX::Types, deberían encajar perfectamente.

use Types::Standard qw( ArrayRef );
use MouseX::Types::Mouse qw( Int );

# esto debería funcionar
my $list_of_nums = ArrayRef[Int];

# y esto
my $list_or_num = ArrayRef | Int;

Parámetro de importación "-mouse"

Si has leído hasta aquí en el manual, sabrás que esta es la forma habitual de importar restricciones de tipo:

use Types::Standard qw( Int );

Y el "Int" que se importa es una función que no toma argumentos y devuelve la restricción de tipo Int, que es un objeto bendecido en la clase Type::Tiny.

Type::Tiny imita la API de Mouse::Meta::TypeConstraint tan bien que la mayoría del código de Mouse y MouseX no podrá notar la diferencia.

¿Pero qué pasa si necesitas un objeto Mouse::Meta::TypeConstraint real?

use Types::Standard -mouse, qw( Int );

Ahora la función "Int" importada devolverá una restricción de tipo nativa genuina de Mouse.

Esta bandera es principalmente un remanente de cuando los objetos nativos de Type::Tiny *no* funcionaban directamente en Mouse. En el 99,9% de los casos, no hay razón para usarla y muchas razones para no hacerlo. (Las restricciones de tipo nativas de Mouse no ofrecen métodos útiles como "plus_coercions" y "where".)

Método "mouse_type"

Otra forma rápida de obtener un objeto de restricción de tipo de Mouse nativo a partir de un objeto Type::Tiny es llamar al método "mouse_type":

use Types::Standard qw( Int );

my $tiny_type   = Int;
my $mouse_type  = $tiny_type->mouse_type;

Internamente, esto es lo que hace la bandera "-mouse" en las funciones importadas.

Rendimiento de Type::Tiny

Type::Tiny debería ejecutarse prácticamente tan rápido como los tipos de Mouse. Esto se debe a que, cuando es posible, utilizará las implementaciones XS de Mouse para las comprobaciones de tipos para realizar el trabajo pesado.

Hay algunas restricciones de tipo para las cuales Type::Tiny prefiere hacer las cosas sin la ayuda de Mouse, por consistencia y corrección. Por ejemplo, la implementación XS de Bool en Mouse es... extraña... acepta objetos bendecidos que sobrecargan "bool", pero solo si devuelven falso. Si devuelven verdadero, es un error de restricción de tipo.

Usar Type::Tiny en lugar de las restricciones de tipo de Mouse no debería suponer una diferencia significativa en el rendimiento de tu código.
