Type::Coercion(3) Documentación de Perl contribuida por el usuario Type::Coercion(3)

NOMBRE

Type::Coercion - un conjunto de coerciones a una restricción de tipo particular

ESTADO

Este módulo está cubierto por la política de estabilidad de Type-Tiny.

DESCRIPCIÓN

Constructores

new(%atributos)
Función constructora estilo Moose.
"add($c1, $c2)"
Crea un Type::Coercion a partir de dos objetos Type::Coercion existentes.

Atributos

Los atributos son valores con nombre que pueden pasarse al constructor. Para cada atributo, existe un método lector correspondiente. Por ejemplo:

my $c = Type::Coercion->new( type_constraint => Int );
my $t = $c->type_constraint;  # Int

Atributos importantes

Estos son los atributos que probablemente más te interesará proporcionar al crear tus propias coerciones de tipo, y los que más te interesará leer al tratar con objetos de coerción.

"type_constraint"
Referencia débil a la restricción de tipo objetivo (es decir, la restricción de tipo a la que se espera que se ajuste la salida de las coderefs de coerción).
"type_coercion_map"
Arrayref de pares fuente-tipo/código.
"frozen"
Booleano; por defecto falso. Una coerción congelada no puede tener "add_type_coercions" llamada sobre ella.
"name"
Un nombre para la coerción. Estos deben cumplir ciertas reglas de nomenclatura (deben comenzar con una letra mayúscula y continuar usando solo letras, dígitos 0-9 y guiones bajos).

Opcional; si no se proporciona, será una coerción anónima.

"display_name"
Un nombre para mostrar para la coerción al ser convertida a cadena. Estos no tienen que cumplir ninguna regla de nomenclatura. Opcional; se calculará un nombre por defecto a partir del "name".
"library"
El nombre del paquete de la biblioteca de tipos a la que está asociada esta coerción. Opcional. Solo informativo: establecer este atributo no instala la coerción en el paquete.

Atributos relacionados con coerciones parametrizables y parametrizadas

Los siguientes atributos se utilizan para coerciones parametrizadas, pero no están completamente documentados porque pueden cambiar en un futuro próximo:

"coercion_generator"
"parameters"
"parameterized_from"

Atributos generados perezosamente

Los siguientes atributos no deben pasarse normalmente al constructor; a menos que estés haciendo algo especialmente inusual, deberías confiar en los valores de retorno predeterminados generados perezosamente.

"compiled_coercion"
Coderef para coaccionar un valor ($_[0]).

El punto general de este atributo es que no deberías establecerlo, sino confiar en el valor predeterminado generado perezosamente. Type::Coerce normalmente generará un coderef bastante rápido, incorporando todas las verificaciones de restricciones de tipo, etc.

"moose_coercion"
Un objeto Moose::Meta::TypeCoercion equivalente a este. No establezcas esto manualmente; confía en el generado predeterminado.

Métodos

Métodos predicado

Estos métodos devuelven booleanos que indican información sobre la coerción. Cada uno está estrechamente asociado con un atributo particular. (Ver "Atributos".)

"has_type_constraint", "has_library"
Métodos predicado simples estilo Moose que indican la presencia o ausencia de un atributo.
"is_anon"
Devuelve verdadero si la coerción no tiene un "name".

Los siguientes predicados se utilizan para coerciones parametrizadas, pero no están completamente documentados porque pueden cambiar en un futuro próximo:

"has_coercion_generator"
"has_parameters"
"is_parameterizable"
"is_parameterized"

Coerción

Los siguientes métodos se utilizan para coaccionar valores a una restricción de tipo:

coerce($valor)
Coacciona el valor al tipo objetivo.

Devuelve el valor coaccionado, o el valor original si no fue posible la coerción.

assert_coerce($valor)
Coacciona el valor al tipo objetivo y lanza una excepción si el resultado no valida contra la restricción de tipo objetivo.

Devuelve el valor coaccionado.

Métodos de definición de código de coerción

Todos estos métodos devuelven $self, por lo que son adecuados para encadenar.

"add_type_coercions($type1, $code1, ...)"
Toma uno o más pares de restricciones Type::Tiny y códigos de coerción, creando una lista ordenada de tipos fuente y códigos de coerción.

Los códigos de coerción pueden expresarse como una cadena de código Perl (esto incluye objetos que sobrecargan la representación de cadena), o como un coderef (o un objeto que sobrecarga la representación de coderef). En cualquier caso, el valor a coaccionar es $_.

add_type_coercions($objeto_coercion) también funciona y se puede utilizar para copiar coerciones de otra restricción de tipo:

$type->coercion->add_type_coercions($othertype->coercion)->freeze;
"freeze"
Establece el atributo "frozen" a verdadero. Llamado automáticamente por Type::Tiny a veces.
"i_really_want_to_unfreeze"
Si realmente quieres descongelar una coerción, llama a este método.

No llames a este método. Potencialmente podría llevar a errores sutiles.

Se considera que este método no es estable; versiones futuras de Type::Tiny pueden alterar su comportamiento (por ejemplo, lanzar una excepción si se ha detectado que descongelar esta coerción en particular causará errores).

Parametrización

El siguiente método se utiliza para coerciones parametrizadas, pero no está completamente documentado porque puede cambiar en un futuro próximo:

parameterize(@params)

Métodos de introspección de coerción de tipo

Estos métodos te permiten determinar la relación de una coerción con las restricciones de tipo:

has_coercion_for_type($source_type)
Devuelve verdadero si esta coerción tiene una coerción desde el tipo fuente.

Devuelve la cadena especial "0 but true" si no debería ser necesaria ninguna coerción para este tipo. (Por ejemplo, si una coerción coacciona a un tipo teórico "Number", probablemente no sea necesaria ninguna coerción para los valores que ya cumplen la restricción de tipo "Integer".)

has_coercion_for_value($value)
Devuelve verdadero si el valor podría ser coaccionado por esta coerción.

Devuelve la cadena especial "0 but true" si no sería necesaria ninguna coerción para este valor (debido a que ya cumple la restricción de tipo objetivo).

El atributo "type_constraint" proporciona un objeto de restricción de tipo para la restricción de tipo objetivo de la coerción. Ver "Atributos".

Métodos de inlining

Los siguientes métodos se utilizan para generar cadenas de código Perl que pueden pegarse en subs evaluadas para realizar coerciones de tipo:

"can_be_inlined"
Devuelve verdadero si la coerción puede ser incorporada.
inline_coercion($varname)
Mucho como "inline_coerce"

DESCRIPCIÓN

Este módulo define la clase Type::Coercion.

Constructores

new
Crea un nuevo objeto Type::Coercion.
from
Para un objeto Type::Coercion dado, devuelve una instancia de él.

Otros métodos

"qualified_name"
Para coerciones no anónimas que tienen una biblioteca, devuelve un nombre calificado del tipo "MyLib::MyCoercion". De lo contrario, devuelve lo mismo que "name".
isa($class), can($method), AUTOLOAD(@args)
Si Moose está cargado, entonces la combinación de estos métodos se usa para simular un Moose::Meta::TypeCoercion.

Los siguientes métodos existen para la compatibilidad con Moose/Mouse, pero no hacen nada útil.

"compile_type_coercion"
"meta"

Sobrecarga

  • La boolificación se sobrecarga para devolver siempre verdadero.
  • La codificación de referencia de código se sobrecarga para llamar "coerce".
  • En Perl 5.10.1 y superior, la coincidencia inteligente se sobrecarga para llamar "has_coercion_for_value".

Las versiones anteriores de Type::Coercion sobrecargaban el operador "+" para llamar "add". El soporte para esto se eliminó después de 0.040.

DIAGNÓSTICOS

Intento de añadir código de coerción a un Type::Coercion que ha sido congelado
Los tipos de restricciones de Type::Tiny están diseñados como objetos inmutables. Una vez que has creado una restricción, en lugar de modificarla, generalmente creas restricciones secundarias para hacer lo que necesitas.

Los objetos Type::Coercion, por otro lado, son mutables. Las rutinas de coerción se pueden agregar en cualquier momento durante la vida útil del objeto.

A veces, Type::Tiny necesita congelar un objeto Type::Coercion para evitar esto. En el código de Moose y Mouse, es probable que esto suceda tan pronto como uses una restricción de tipo en un atributo.

Soluciones:

  • Define tantas de tus coerciones como sea posible dentro de las bibliotecas de tipos, no dentro del código que usa las bibliotecas de tipos. La biblioteca de tipos se evaluará relativamente pronto, probablemente antes de que haya alguna razón para congelar una coerción.
  • Si necesitas agregar coerciones a un tipo dentro del código de aplicación fuera de la biblioteca de tipos, en su lugar crea un subtipo y agrega coerciones a ese. El método "plus_coercions" proporcionado por Type::Tiny debería hacer esto simple.
