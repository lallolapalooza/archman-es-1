NOMBRE

Type::Tiny::Manual::UsingWithMite - cómo usar Type::Tiny con Mite

MANUAL

Mite adopta un enfoque poco ortodoxo para el código orientado a objetos. Cuando comiences un proyecto con Mite (que asumiremos se llama Your::Project), Mite creará un módulo llamado Your::Project::Mite para ti.

Luego, todas tus clases usarán código como:

package Your::Project::Widget;

use Your::Project::Mite -all;

has name => (
   is => ro,
   isa => 'Str',
);

has id => (
   is => ro,
   isa => 'PositiveInt',
);

signature_for warble => (
   named => [
      foo   => 'Int',
      bar   => 'ArrayRef',
   ],
);

sub warble {
   my ( $self, $arg ) = @_;
   printf( "%s: %d\n", $self->name, $arg->foo );
   return;
}

1;

Después de escribir o editar cada clase o rol, ejecuta el comando "mite compile" y Mite generará una colección de clases Perl compiladas que no tienen dependencias externas (en Perl 5.14+. Hay un par de dependencias externas en versiones anteriores de Perl.)

Las opciones del atributo "isa" son restricciones de tipo de Type::Tiny expresadas como cadenas. Mite las busca durante la compilación usando "dwim_type" de Type::Utils, y precarga Types::Standard, Types::Common::String y Types::Common::Numeric para ti.

La palabra clave "signature_for" es similar a la función correspondiente en Type::Params. Nuevamente, ten en cuenta que los tipos se expresan como cadenas y se buscan usando "dwim_type".

Cualquier tipo que sea "inlineable" debería funcionar. Si usas coerción, cualquier coerción que sea "inlineable" debería funcionar.

Tipos personalizados en Mite

Puedes definir tu propia biblioteca de tipos (por ejemplo, Your::Project::Types) usando Type::Library como de costumbre:

package Your::Project::Types;

use Type::Library
   -extends => [ 'Types::Standard', 'Types::Common::Numeric' ];

__PACKAGE__->add_type(
   name    => 'Widget',
   parent  => InstanceOf['Your::Project::Widget'],
)->coercion->add_type_coercions(
   HashRef, q{Your::Project::Widget->new($_)},
);

__PACKAGE__->make_immutable;

1;

Ahora, si tus clases cargan Your::Project::Types, de repente tendrán una dependencia de Type::Library, por lo que no tendrás esa agradable sensación de "cero dependencias". Pero puedes añadir esto a tu archivo ".mite/config":

types: Your::Project::Types

Ahora Mite sabrá cargar esa biblioteca de tipos en tiempo de compilación y hará que esos tipos estén disponibles como tipos en cadena en todas partes.

Bibliotecas de tipos compiladas

Realmente se ve muy bien no tener que entrecomillar tus restricciones de tipo:

has name => (
   is   => ro,
   isa  => Str,
);

Una solución para eso es Type::Library::Compiler.

Supongamos que has creado la biblioteca de tipos personalizada anterior, puedes usar Type::Library::Compiler para compilarla en un módulo llamado Your::Project::Types::Compiled, que solo usa Exporter y no depende de Type::Library ni de ninguna otra parte de Type::Tiny.

Entonces tu clase Widget puede usar eso:

package Your::Project::Widget;

use Your::Project::Mite -all;
use Your::Project::Types::Compiled -types;

has name => (
   is   => ro,
   isa  => Str,
);

has id => (
   is   => ro,
   isa  => PositiveInt,
);

signature_for warble => (
   named => [
      foo   => Int,
      bar   => ArrayRef,
   ],
);

sub warble {
   my ( $self, $arg ) = @_;
   printf( "%s: %d\n", $self->name, $arg->foo );
   return;
}

1;

Las bibliotecas de tipos compiladas son más limitadas que las bibliotecas de tipos reales. No puedes, por ejemplo, hacer tipos parametrizados con ellas. Sin embargo, todavía ofrecen algunas características interesantes como:

Foo->check( $value )     # algunos métodos básicos como este
is_Foo( $value )         # comprobaciones booleanas
assert_Foo( $value )     # aserciones que fallan
Foo | Bar                # ¡uniones!

De esta manera, puedes escribir un proyecto con orientación a objetos, roles, modificadores de métodos, atributos con tipos comprobados, firmas con tipos comprobados e incluso coerción, ¡sin dependencias externas! (Las herramientas como Mite y Type::Library::Compiler solo son necesarias para el desarrollador, no para el usuario final.)
