MANUAL

Test::TypeTiny

Este es un módulo para probar que los tipos que has definido aceptan y rechazan los valores que crees que deberían.

should_pass($valor, $tipo);
should_fail($otrovalor, $tipo);

Fácil. (Pero sí, siempre olvido si el tipo va primero o segundo).

También hay una función para probar que las relaciones de subtipo/supertipo están funcionando correctamente.

ok_subtype($tipo, @subtipos);

Por supuesto, puedes simplemente comprobar un tipo así:

ok( $tipo->check($valor) );

Pero la ventaja de "should_pass" es que si la variable de entorno "EXTENDED_TESTING" está establecida a true, "should_pass" también realizará una comprobación estricta del valor, lo que implica subir por el árbol de herencia del tipo (su padre, el padre de su padre, etc.) para asegurarse de que el valor pasa todas sus restricciones.

Si una comprobación normal y una comprobación estricta difieren, esto suele ser un problema en el código de inlining en algún lugar.

Ver Test::TypeTiny para más información.

Type::Tiny como Reemplazo para Test::Deep

Aquí tienes uno de los ejemplos de la documentación de Test::Deep:

my $name_re = re('^(Mr|Mrs|Miss) \w+ \w+$');
cmp_deeply(
  $person,
  {
    Name       => $name_re,
    Phone      => re('^0d{6}$'),
    ChildNames => array_each($name_re)
  },
  "persona ok"
);

Es bastante fácil reescribir esto para usar Types::Standard:

my $name = StrMatch[ qr/^(Mr|Mrs|Miss) \w+ \w+$/ ];
should_pass(
  $person,
  Dict[
    Name         => $name,
    Phone        => StrMatch[ qr/^0d{6}$/ ],
    ChildNames   => ArrayRef[$name]
  ]
);

No hay nada especialmente malo con Test::Deep, pero si ya estás familiarizado con los tipos incorporados de Type::Tiny y quizás también has escrito tus propias bibliotecas de tipos, te ahorrará tener que cambiar entre el uso de dos sistemas de comprobación separados.
