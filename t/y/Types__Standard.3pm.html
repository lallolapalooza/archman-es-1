Types::Standard(3) Documentación de Contribución de Usuarios de Perl Types::Standard(3)

NOMBRE

Types::Standard - conjunto empaquetado de tipos incorporados para Type::Tiny

SINOPSIS

use v5.36;

package Horse {
  use Moo;
  use Types::Standard qw( Str Int Enum ArrayRef Object );
  use Type::Params qw( signature_for );
  use namespace::autoclean;

  has name => (
    is       => 'ro',
    isa      => Str,
    required => 1,
  );

  has gender => (
    is       => 'ro',
    isa      => Enum[qw( f m )],
  );

  has age => (
    is       => 'rw',
    isa      => Int->where( '$_ >= 0' ),
  );

  has children => (
    is       => 'ro',
    isa      => ArrayRef[Object],
    default  => sub { return [] },
  );

  # firma de método
  signature_for add_child => (
    method     => Object,
    positional => [ Object ],
  );

  sub add_child ( $self, $child ) {
    push $self->children->@*, $child;
    return $self;
  }
}

package main;

my $boldruler = Horse->new(
  name    => "Bold Ruler",
  gender  => 'm',
  age     => 16,
);

my $secretariat = Horse->new(
  name    => "Secretariat",
  gender  => 'm',
  age     => 0,
);

$boldruler->add_child( $secretariat );

use Types::Standard qw( is_Object assert_Object );

# is_Object($thing) devuelve un booleano
my $is_it_an_object = is_Object $boldruler;

# assert_Object($thing) devuelve $thing o muere
say assert_Object($boldruler)->name;  # dice "Bold Ruler"

ESTADO

Este módulo está cubierto por la política de estabilidad de Type-Tiny.

DESCRIPCIÓN

Esto documenta los detalles de la biblioteca de tipos Types::Standard. Type::Tiny::Manual es un mejor punto de partida si eres nuevo.

Type::Tiny incluye algunos tipos que parecen ser útiles.

Estilo Moose

Los siguientes tipos son similares a los descritos en Moose::Util::TypeConstraints.

  • Any

    Cualquier valor pasa esta restricción de tipo (incluso undef).

  • Item

    Esencialmente lo mismo que Any. Todas las demás restricciones de tipo en esta biblioteca heredan directa o indirectamente de Item.

  • Bool

    Valores que son booleanos razonables. Acepta 1, 0, la cadena vacía y undef.

    Otros clientes también compraron: BoolLike de Types::TypeTiny.

  • Maybe[`a]

    Dada otra restricción de tipo, también acepta undef. Por ejemplo, Maybe[Int] acepta todos los enteros más undef.

  • Undef

    Solo undef pasa esta restricción de tipo.

  • Defined

    Solo undef falla esta restricción de tipo.

  • Value

    Cualquier valor definido, no de referencia.

  • Str

    Cualquier cadena.

    (La única diferencia entre Value y Str es que la primera acepta typeglobs y vstrings.)

    Otros clientes también compraron: StringLike de Types::TypeTiny.

  • Num

    Ver LaxNum y StrictNum abajo.

  • Int

    Un entero; es decir, una cadena de dígitos del 0 al 9, opcionalmente prefijada con un carácter de guion (menos).

    Espere resultados inconsistentes para dualvars, y números demasiado altos (o números negativos demasiado bajos) para que Perl los represente de forma segura como un entero.

  • ClassName

    El nombre de un paquete cargado. El paquete debe tener @ISA o $VERSION definido, o debe definir al menos una subrutina para ser considerado un paquete cargado.

  • RoleName

    Similar a ClassName, pero el paquete no debe definir un método llamado "new". Esto es sutilmente diferente de la restricción de tipo de Moose del mismo nombre; avísame si esto te causa algún problema. (Sin embargo, no puedo prometer que cambie nada).

  • Ref[`a]

    Cualquier valor de referencia definido, incluyendo objetos bendecidos.

    A diferencia de Moose, Ref es un tipo parametrizado, que permite verificaciones de reftype de Scalar::Util, como

    Ref["HASH"]  # hashrefs, incluyendo hashrefs bendecidos
  • ScalarRef[`a]

    Un valor donde "ref($value) eq "SCALAR" o ref($value) eq "REF"".

    Si está parametrizado, el valor al que se hace referencia debe pasar la restricción adicional. Por ejemplo, ScalarRef[Int] debe ser una referencia a un escalar que contenga un valor entero.

  • ArrayRef[`a]

    Un valor donde "ref($value) eq "ARRAY"".

    Si está parametrizado, los elementos de la matriz deben pasar la restricción adicional. Por ejemplo, ArrayRef[Num] debe ser una referencia a una matriz de números.

    Como una extensión al ArrayRef de Moose, se puede dar una longitud mínima y máxima de matriz:

    ArrayRef[CodeRef, 1]        # ArrayRef de al menos un CodeRef
ArrayRef[FileHandle, 0, 2]  # ArrayRef de hasta dos FileHandles
ArrayRef[Any, 0, 100]       # ArrayRef de hasta 100 elementos

    Otros clientes también compraron: ArrayLike de Types::TypeTiny.

  • HashRef[`a]

    Un valor donde "ref($value) eq "HASH"".

    Si está parametrizado, los valores del hash deben pasar la restricción adicional. Por ejemplo, HashRef[Num] debe ser una referencia a un hash donde los valores son números. Las claves del hash no están restringidas, pero Perl las limita a cadenas; consulte Map a continuación si necesita restringir aún más los valores del hash.

    Otros clientes también compraron: HashLike de Types::TypeTiny.

  • CodeRef

    Un valor donde "ref($value) eq "CODE"".

    Otros clientes también compraron: CodeLike de Types::TypeTiny.

  • RegexpRef

    Una referencia donde re::is_regexp($value) es verdadera, o una referencia bendecida donde "$value->isa("Regexp")" es verdadera.

  • GlobRef

    Un valor donde "ref($value) eq "GLOB"".

  • FileHandle

    Un manejador de archivos.

  • Object

    Un objeto bendecido.

    (Esto también acepta referencias de expresiones regulares).

Estructurado

Bien, robé algunas ideas de MooseX::Types::Structured.

  • Map[`k, `v]

    Similar a HashRef pero parametrizado con restricciones de tipo tanto para la clave como para el valor. La restricción para las claves típicamente sería una subclase de Str.

  • Tuple[...]

    Subclase de ArrayRef, que acepta una lista de restricciones de tipo para cada ranura en la matriz.

    Tuple[Int, HashRef] coincidiría con "[1, {}]" pero no con "[{}, 1]".

  • Dict[...]

    Subclase de HashRef, que acepta una lista de restricciones de tipo para cada ranura en el hash.

    Por ejemplo, Dict[name => Str, id => Int] permite "{ name => "Bob", id => 42 }".

  • Optional[`a]

    Se utiliza en conjunción con Dict y Tuple para especificar ranuras que son opcionales y pueden omitirse (pero no necesariamente establecerse en un undef explícito).

    Dict[name => Str, id => Optional[Int]] permite "{ name => "Bob" }" pero no "{ name => "Bob", id => "BOB" }".

    Tenga en cuenta que cualquier uso de Optional[`a] fuera del contexto de las restricciones de tipo parametrizadas Dict y Tuple tiene poco sentido, y su comportamiento no está definido. (Una excepción: es utilizado por Type::Params para un propósito similar a cómo se usa en Tuple.)

Este módulo también exporta un tipo parametrizado Slurpy, que se puede usar de la siguiente manera.

NAME

Types::Standard - Standard types for Type::Tiny

SYNOPSIS

  use Types::Standard qw(
     Tuple
     Slurpy
     Dict
     InstanceOf
     ConsumerOf
     HasMethods
     Overload
     Tied
     StrMatch
     Enum
     OptList
     LaxNum
     StrictNum
     CycleTuple
     MkOpt
     Split
     Join
  );
  use Type::Tiny; # For declaring types, etc.

  # Tuple example
  my $User = Tuple[ Str, Int ];
  $User->( [ 'Foo', 123 ] ); # ok

  # Dict example
  my $Config = Dict[
     foo => Str,
     bar => Int,
     baz => \%Coerce, # or whatever coercions you like
  ];
  $Config->( { foo => 'baz', bar => 123 } ); # ok

  # Slurpy example
  my $IntPair = Tuple[ Int, Slurpy[Int] ];
  $IntPair->( [ 1, 2, 3, 4 ] ); # ok

  # Object example
  my $Widget = InstanceOf[ 'My::Widget' ];
  my $Doer   = ConsumerOf[ 'My::Doer' ];
  my $Runner = HasMethods[ 'run', 'stop' ];

  # Overload example
  my $Addable = Overload[ '+' ];

  # Tied example
  my $TiedHash = Tied[ HashRef ];

  # StrMatch example
  my $NonNegativeInt = StrMatch[ qr/^[0-9]+$/ ];

  # Enum example
  my $Size = Enum[ qw( S M L ) ];

  # OptList example
  my $OptList = OptList; # Not parameterized

  # LaxNum and StrictNum
  my $Num = Num; # defaults to LaxNum unless PERL_TYPES_STANDARD_STRICTNUM set
  my $Lax = LaxNum;
  my $Strict = StrictNum;

  # CycleTuple example
  my $KeyVals = CycleTuple[ Str, Int ];
  $KeyVals->( [ 'a', 1, 'b', 2 ] ); # ok

  # Coercions
  has options => (
     is     => 'ro',
     isa    => OptList->plus_coercions( MkOpt ),
     coerce => 1,
  );

DESCRIPTION

This module exports a bunch of common type constraints that are useful when validating data, particularly data that comes from parsing configuration files, command-line arguments, or other external sources.

Tuples and Dicts

Tuple and Dict are type constraints which validate arrays and hashrefs respectively. They are parameterised with other type constraints.

  Tuple[ TYPE1, TYPE2, ... ]
  Dict[ KEY1 => TYPE1, KEY2 => TYPE2, ... ]

A Tuple expects an arrayref, and checks that the first element matches TYPE1, the second matches TYPE2, and so on.

  my $pair = Tuple[ Int, Str ];
  $pair->( [ 1, 'foo' ] ); # ok
  $pair->( [ 1, 'foo', 'bar' ] ); # not ok
  $pair->( [ 1, 'foo', 2 ] ); # not ok

A Dict expects a hashref, and checks that the keys specified are present, and that their values match the corresponding type constraints. Extra keys are ignored by default.

  my $config = Dict[
     name => Str,
     port => Int,
  ];
  $config->( { name => 'foo', port => 80 } ); # ok
  $config->( { name => 'foo', port => 80, verbose => 1 } ); # ok
  $config->( { name => 'foo' } ); # not ok
  $config->( { name => 123, port => 80 } ); # not ok

Both Tuple and Dict support the following optional parameters:

  Optional[TYPE]
  Slurpy[TYPE]
  Optional[Slurpy[TYPE]] # same as Slurpy[Optional[TYPE]]

Optional[TYPE] allows zero or one values of TYPE at the end of a Tuple or as the value for a key in a Dict.

  my $tuple = Tuple[ Str, Optional[Int] ];
  $tuple->( ['foo'] ); # ok
  $tuple->( ['foo', 123] ); # ok
  $tuple->( ['foo', 123, 456] ); # not ok

Slurpy[TYPE] allows zero or more values of TYPE at the end of a Tuple, or for any extra keys in a Dict.

  my $tuple = Tuple[ Str, Slurpy[Int] ];
  $tuple->( ['foo'] ); # ok
  $tuple->( ['foo', 1, 2, 3] ); # ok
  $tuple->( ['foo', 1, 'bar'] ); # not ok

  my $dict = Dict[
     name => Str,
     Slurpy[Int], # Keys are strings, values are Ints
  ];
  $dict->( { name => 'foo' } ); # ok
  $dict->( { name => 'foo', 1 => 1, 2 => 2 } ); # ok
  $dict->( { name => 'foo', 1 => 1, 'bar' => 2 } ); # not ok

The Slurpy modifier can cause additional trailing values in a Tuple to be slurped into a structure and validated. For example, slurping into an arrayref:

my $type = Tuple[ Str, Slurpy[ ArrayRef[Int] ] ];

$type->( ["Hello"] );                # ok
$type->( ["Hello", 1, 2, 3] );       # ok
$type->( ["Hello", [1, 2, 3]] );     # not ok

Or into a hashref:

my $type2 = Tuple[ Str, Slurpy[ Map[Int, RegexpRef] ] ];

$type2->( ["Hello"] );                               # ok
$type2->( ["Hello", 1, qr/one/i, 2, qr/two/] );      # ok

It can cause additional values in a Dict to be slurped into a hashref and validated:

my $type3 = Dict[ values => ArrayRef, Slurpy[ HashRef[Str] ] ];

$type3->( { values => [] } );                        # ok
$type3->( { values => [], name => "Foo" } );         # ok
$type3->( { values => [], name => [] } );            # not ok

In either Tuple or Dict, Slurpy[Any] can be used to indicate that additional values are acceptable, but should not be constrained in any way.

Slurpy[Any] is an optimized code path. Although the following are essentially equivalent checks, the former should run a lot faster:

Tuple[ Int, Slurpy[Any] ]
Tuple[ Int, Slurpy[ArrayRef] ]

A function slurpy($type) is also exported which was historically how slurpy types were created.

Outside of Dict and Tuple, Slurpy[Foo] should just act the same as Foo. But don't do that.

Objects

Okay, so I stole some ideas from MooX::Types::MooseLike::Base.

  • InstanceOf[`a]

    Shortcut for a union of Type::Tiny::Class constraints.

    InstanceOf["Foo", "Bar"] allows objects blessed into the "Foo" or "Bar" classes, or subclasses of those.

    Given no parameters, just equivalent to Object.

  • ConsumerOf[`a]

    Shortcut for an intersection of Type::Tiny::Role constraints.

    ConsumerOf["Foo", "Bar"] allows objects where "$o->DOES("Foo")" and "$o->DOES("Bar")" both return true.

    Given no parameters, just equivalent to Object.

  • HasMethods[`a]

    Shortcut for a Type::Tiny::Duck constraint.

    HasMethods["foo", "bar"] allows objects where "$o->can("foo")" and "$o->can("bar")" both return true.

    Given no parameters, just equivalent to Object.

More

There are a few other types exported by this module:

  • Overload[`a]

    With no parameters, checks that the value is an overloaded object. Can be given one or more string parameters, which are specific operations to check are overloaded. For example, the following checks for objects which overload addition and subtraction.

    Overload["+", "-"]
  • Tied[`a]

    A reference to a tied scalar, array or hash.

    Can be parameterized with a type constraint which will be applied to the object returned by the tied() function. As a convenience, can also be parameterized with a string, which will be inflated to a Type::Tiny::Class.

    use Types::Standard qw( Tied );
use Type::Utils qw( class_type );

my $My_Package = class_type { class => "My::Package" };

tie my %h, "My::Package";
\%h ~~ Tied;                   # true
\%h ~~ Tied[ $My_Package ];    # true
\%h ~~ Tied["My::Package"];    # true

tie my $s, "Other::Package";
\$s ~~ Tied;                   # true
$s  ~~ Tied;                   # false !!

    If you need to check that something is specifically a reference to a tied hash, use an intersection:

    use Types::Standard qw( Tied HashRef );

my $TiedHash = (Tied) & (HashRef);

tie my %h, "My::Package";
tie my $s, "Other::Package";

\%h ~~ $TiedHash;     # true
\$s ~~ $TiedHash;     # false
  • StrMatch[`a]

    A string that matches a regular expression:

    declare "Distance",
   as StrMatch[ qr{^([0-9]+)\s*(mm|cm|m|km)$} ];

    You can optionally provide a type constraint for the array of subexpressions:

    declare "Distance",
   as StrMatch[
      qr{^([0-9]+)\s*(.+)$},
      Tuple[
         Int,
         enum(DistanceUnit => [qw/ mm cm m km /]),
      ],
   ];

    Here's an example using Regexp::Common:

    package Local::Host {
   use Moose;
   use Regexp::Common;
   has ip_address => (
      is         => 'ro',
      required   => 1,
      isa        => StrMatch[qr/^$RE{net}{IPv4}$/],
      default    => '127.0.0.1',
   );
}

    On certain versions of Perl, type constraints of the forms StrMatch[qr/../ and StrMatch[qr/\A..\z/ with any number of intervening dots can be optimized to simple length checks.

  • Enum[`a]

    As per MooX::Types::MooseLike::Base:

    has size => (
   is     => "ro",
   isa    => Enum[qw( S M L XL XXL )],
);

    You can enable coercion by passing "\1" before the list of values.

    has size => (
   is     => "ro",
   isa    => Enum[ \1, qw( S M L XL XXL ) ],
   coerce => 1,
);

    This will use the "closest_match" method in Type::Tiny::Enum to coerce closely matching strings.

  • OptList

    An arrayref of arrayrefs in the style of Data::OptList output.

  • LaxNum, StrictNum

    In Moose 2.09, the Num type constraint implementation was changed from being a wrapper around Scalar::Util's "looks_like_number" function to a stricter regexp (which disallows things like "-Inf" and "Nan").

    Types::Standard provides both implementations. LaxNum is measurably faster.

    The Num type constraint is currently an alias for LaxNum unless you set the "PERL_TYPES_STANDARD_STRICTNUM" environment variable to true before loading Types::Standard, in which case it becomes an alias for StrictNum. The constant "Types::Standard::STRICTNUM" can be used to check if Num is being strict.

    Most people should probably use Num or StrictNum. Don't explicitly use LaxNum unless you specifically need an attribute which will accept things like "Inf".

  • CycleTuple[`a]

    Similar to Tuple, but cyclical.

    CycleTuple[Int, HashRef]

    will allow "[1,{}]" and "[1,{},2,{}]" but disallow "[1,{},2]" and "[1,{},2,"not a hashref"]".

    I think you understand CycleTuple already.

    Currently Optional and Slurpy parameters are forbidden. There are fairly limited use cases for them, and it's not exactly clear what they should mean.

    The following is an efficient way of checking for an even-sized arrayref:

    CycleTuple[Any, Any]

    The following is an arrayref which would be suitable for coercing to a hashref:

    CycleTuple[Str, Any]

    All the examples so far have used two parameters, but the following is also a possible CycleTuple:

    CycleTuple[Str, Int, HashRef]

    This will be an arrayref where the 0th, 3rd, 6th, etc values are strings, the 1st, 4th, 7th, etc values are integers, and the 2nd, 5th, 8th, etc values are hashrefs.

Coercions

Most of the types in this type library have no coercions. The exception is Bool as of Types::Standard 1.003_003, which coerces from Any via "!!$_".

Some standalone coercions may be exported. These can be combined with type constraints using the "plus_coercions" method.

  • MkOpt

    A coercion from ArrayRef, HashRef or Undef to OptList. Example usage in a Moose attribute:

    use Types::Standard qw( OptList MkOpt );

has options => (
   is     => "ro",
   isa    => OptList->plus_coercions( MkOpt ),
   coerce => 1,
);
  • Split[`a]

    Split a string on a regexp.

    use Types::Standard qw( ArrayRef Str Split );

has name => (
   is     => "ro",
   isa    => ArrayRef->of(Str)->plus_coercions(Split[qr/\s/]),
   coerce => 1,
);
  • Join[`a]

    Join an array of strings with a delimiter.

    use Types::Standard qw( Str Join );

my $FileLines = Str->plus_coercions(Join["\n"]);

has file_contents => (
   is     => "ro",
   isa    => $FileLines,
   coerce => 1,
);

Constants

"Types::Standard::STRICTNUM"
Indicates whether Num is an alias for StrictNum. (It is usually an alias for LaxNum.)

Environment

"PERL_TYPES_STANDARD_STRICTNUM"
Switches to more strict regexp-based number checking instead of using "looks_like_number".
"PERL_TYPE_TINY_XS"
If set to false, can be used to suppress the loading of XS implementations of some type constraints.
"PERL_ONLY"
If "PERL_TYPE_TINY_XS" does not exist, can be set to "true" to force the use of pure Perl implementations of type checks.

NAME

Types::Standard - The standard set of type constraints for Type::Tiny

SYNOPSIS

    use Types::Standard -all;

    # Type constraints from Types::Standard are loaded, and are available
    # for use by Type::Tiny.

STATUS

This module is intended for internal use by Type::Tiny. You probably don’t need to use it yourself.

Type::Tiny has a mechanism whereby it can be told to export type constraints from other modules. When Type::Tiny is loaded, it checks for the existence of the environment variable $ENV{TYPE_TINY_EXPORT_TYPES}. If this variable is set to a comma-separated list of module names, then Type::Tiny will attempt to load each of those modules, and export any type constraints that they have defined (using Type::Tiny’s API).

The idea is that you can have a single file that defines all of your application’s custom type constraints, and then specify that file in $ENV{TYPE_TINY_EXPORT_TYPES}. Type::Tiny will load it and make all of those types available to you.

This module, Types::Standard, exists so that Type::Tiny can export a default set of useful type constraints, without requiring the user to explicitly tell it to do so.

The default set of types is:

    ArrayRef
    HashRef
    Integer
    Number
    Object
    RegexpRef
    ScalarRef
    Str
    SubRef
    Undef

To prevent these types from being exported, you can set the environment variable $ENV{TYPE_TINY_EXPORT_STANDARD_TYPES} to a true value. For example:

    $ENV{TYPE_TINY_EXPORT_STANDARD_TYPES} = 1;
    use Type::Tiny;

Alternatively, you can prevent the standard types from being exported by passing the -no-standard-types option to the use Type::Tiny line:

    use Type::Tiny -no-standard-types;

And similarly for other modules that export types, such as Types::XSD, Types::Encodings, Types::Common::Numeric, Types::Common::String, etc.

Note that use Types::Standard -all exports all of the types defined by the module, plus all of the types defined by any modules listed in $ENV{TYPE_TINY_EXPORT_TYPES}. This behaviour is consistent with the behaviour of use Module -all.

The use Types::Standard pragma does not export anything by default. You must pass -all to export all the types.

DESCRIPTION

This module defines a set of commonly-used type constraints. It is intended to be used by Type::Tiny itself, to provide a default set of types. It can also be used directly by application code, if desired.

ArrayRef
A type constraint that matches only array references.
HashRef
A type constraint that matches only hash references.
Integer
A type constraint that matches only integers.
Number
A type constraint that matches only numbers (integers or floating-point numbers).
Object
A type constraint that matches only objects (blessed references).
RegexpRef
A type constraint that matches only regexp references.
ScalarRef
A type constraint that matches only scalar references.
Str
A type constraint that matches only strings.
SubRef
A type constraint that matches only sub references.
Undef
A type constraint that matches only undef.
Object-isa-ClassName
A type constraint that matches objects of the given class, or a subclass thereof. For example, Object-isa-DateTime matches DateTime objects and any subclasses.
Object-does-RoleName
A type constraint that matches objects that implement the given role. For example, Object-does-MooseX::Log::Log4perl::Handle matches objects that implement that role.
Object-blessed-ClassName
A type constraint that matches only objects that are blessed into the given class. It does not match objects of subclasses. For example, Object-blessed-DateTime matches DateTime objects, but not objects of subclasses of DateTime.
Object-blessed-ClassName
A type constraint that matches only objects that are blessed into the given class. It does not match objects of subclasses. For example, Object-blessed-DateTime matches DateTime objects, but not objects of subclasses of DateTime.

The -all option to use Types::Standard causes all of the above type constraints to be exported.

To prevent XS usage, you can set the environment variable $ENV{TYPE_TINY_DISABLE_XS} to a true value. This will cause Type::Tiny to use pure Perl implementations for all of its type constraints, instead of the faster XS implementations. This is useful for debugging, or for use in environments where XS modules cannot be installed. (Several other CPAN distributions also pay attention to this environment variable.)
