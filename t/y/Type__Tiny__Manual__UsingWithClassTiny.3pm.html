NOMBRE

Type::Tiny::Manual::UsingWithClassTiny - uso de Type::Tiny con Class::Tiny

MANUAL

Class::Tiny es un constructor de clases aún más pequeño que Moo.

Vamos a traducir la clase clásica Horse de Moo a Class::Tiny.

Moo:

package Horse {
  use Moo;
  use Types::Standard qw( Str Num ArrayRef );
  use namespace::autoclean;

  has name       => ( is => 'ro', isa => Str, required => 1 );
  has gender     => ( is => 'ro', isa => Str );
  has age        => ( is => 'rw', isa => Num );
  has children   => (
    is       => 'ro',
    isa      => ArrayRef,
    default  => sub { return [] },
  );
}

Class::Tiny:

package Horse {
  use Class::Tiny qw( gender age ), {
    name     => sub { die "name is required"; },
    children => sub { return [] },
  };
  use Types::Standard qw( Str Num ArrayRef Dict Optional Slurpy Any Object );
  use Type::Params qw( signature_for );
  use namespace::autoclean;

  # comprobaciones de tipo
  signature_for BUILD => (
    method => Object,
    named  => [
      name       => Str,
      gender     => Optional[Str],
      age        => Optional[Num],
      children   => Optional[ArrayRef],
      ()         => Slurpy[Any],
    ],
    fallback => 1,
  );
  signature_for [ 'name', 'gender', 'children' ] => (
    method     => Object,
    positional => [],
  );
  signature_for age => (
    method     => Object,
    positional => [ Optional[Num] ],
  );
}

¿Qué está pasando aquí?

Bueno, Class::Tiny, después de que haya construido un nuevo objeto, hará esto:

$self->BUILD($args);

(Técnicamente, llama a "BUILD" no solo para la clase actual, sino también para todas las clases padre). Podemos engancharnos a esto para comprobar las restricciones de tipo para el constructor.

Usamos "signature_for" de Type::Params para envolver el método original "BUILD" (que no existe, por lo que "fallback => 1" simplemente asumirá un sub vacío) con una comprobación de tipo para sus argumentos. La comprobación de tipo es solo un Dict que comprueba los atributos requeridos y opcionales de la clase e incluye Slurpy[Any] al final para ser flexible para las subclases que añaden nuevos atributos.

Luego envolvemos los métodos "name", "gender" y "children" con comprobaciones para asegurarnos de que solo se llaman como getters, y envolvemos "age", permitiendo que se llame como setter con un Num.

También hay un par de módulos CPAN que pueden ayudarte.

Class::Tiny::ConstrainedAccessor

Class::Tiny::ConstrainedAccessor crea un "BUILD" y accesores que aplican restricciones de Type::Tiny. Los tipos de atributos se pasan a Class::Tiny::ConstrainedAccessor; los valores por defecto de los atributos se pasan a Class::Tiny.

package Horse {
  use Types::Standard qw( Str Num ArrayRef );
  use Class::Tiny::ConstrainedAccessor {
    name     => Str,
    gender   => Str,
    age      => Num,
    children => ArrayRef,
  };
  use Class::Tiny qw( gender age ), {
    name     => sub { die "name is required"; },
    children => sub { return [] },
  };
}

Class::Tiny::Antlers

Class::Tiny::Antlers proporciona una sintaxis similar a Moose para Class::Tiny, incluyendo soporte para "isa". No necesitas usar Class::Tiny tú mismo.

package Horse {
  use Class::Tiny::Antlers qw(has);
  use Types::Standard qw( Str Num ArrayRef );
  use namespace::autoclean;

  has name       => (
    is        => 'ro',
    isa       => Str,
    default   => sub { die "name is required" },
  );
  has gender     => ( is => 'ro',    isa => Str );
  has age        => ( is => 'rw',    isa => Num );
  has children   => (
    is        => 'ro',
    isa       => ArrayRef,
    default   => sub { return [] },
  );
}
