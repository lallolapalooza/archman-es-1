Type::Tiny::Manual::Optimization(3) Documentación de Perl contribuida por el usuario Type::Tiny::Manual::Optimization(3)

NOMBRE

Type::Tiny::Manual::Optimization - exprime al máximo tu CPU

MANUAL

Type::Tiny está escrito teniendo en cuenta la eficiencia, pero hay técnicas que puedes usar para obtener el mejor rendimiento de él.

XS

Lo más sencillo que puedes hacer para aumentar el rendimiento de muchas de las restricciones de tipo integradas es instalar Type::Tiny::XS, un conjunto de comprobaciones de restricciones de tipo ultrarrápidas implementadas en C.

Type::Tiny intentará cargar Type::Tiny::XS y usar sus comprobaciones de tipo. Si Type::Tiny::XS no está disponible, intentará usar Mouse si ya está cargado, pero Type::Tiny no intentará cargar Mouse por ti.

Ciertas restricciones de tipo también pueden acelerarse si tienes Ref::Util::XS instalado.

Tipos que pueden ser acelerados por Type::Tiny::XS

Las siguientes restricciones de tipo simples de Types::Standard serán aceleradas por Type::Tiny::XS: Any, ArrayRef, Bool, ClassName, CodeRef, Defined, FileHandle, GlobRef, HashRef, Int, Item, Object, Map, Ref, ScalarRef, Str, Tuple, Undef y Value. (Nota: Num y RegexpRef no están en esa lista.)

La forma parametrizada de Ref no puede ser acelerada.

Las formas parametrizadas de ArrayRef, HashRef y Map solo pueden ser aceleradas si sus parámetros lo son.

La forma parametrizada de Tuple puede ser acelerada si sus parámetros lo son, no tiene componentes Optional y no usa Slurpy.

Ciertas restricciones de tipo pueden beneficiarse parcialmente de Type::Tiny::XS. Por ejemplo, RoleName hereda de ClassName, por lo que parte de la comprobación de tipo será realizada por Type::Tiny::XS.

Las restricciones de tipo parametrizadas InstanceOf, HasMethods y Enum serán aceleradas. También lo serán los objetos Type::Tiny::Class, Type::Tiny::Duck y Type::Tiny::Enum.

Las restricciones de tipo PositiveInt y PositiveOrZeroInt de Types::Common::Numeric serán aceleradas, al igual que la restricción de tipo NonEmptyStr de Types::Common::String.

Los tipos StringLike, CodeLike, HashLike y ArrayLike de Types::TypeTiny serán acelerados, incluyendo las versiones parametrizadas de HashLike y ArrayLike.

Type::Tiny::Union y Type::Tiny::Intersection también serán acelerados si sus restricciones de tipo constituyentes lo son.

Tipos que pueden ser acelerados por Mouse

Las siguientes restricciones de tipo simples de Types::Standard serán aceleradas por Type::Tiny::XS: Any, ArrayRef, Bool, ClassName, CodeRef, Defined, FileHandle, GlobRef, HashRef, Ref, ScalarRef, Str, Undef y Value. (Nota: Item, Num, Int, Object y RegexpRef no están en esa lista.)

La forma parametrizada de Ref no puede ser acelerada.

Las formas parametrizadas de ArrayRef y HashRef solo pueden ser aceleradas si sus parámetros lo son.

Ciertas restricciones de tipo pueden beneficiarse parcialmente de Mouse. Por ejemplo, RoleName hereda de ClassName, por lo que parte de la comprobación de tipo será realizada por Mouse.

Las restricciones de tipo parametrizadas InstanceOf y HasMethods serán aceleradas. También lo serán los objetos Type::Tiny::Class y Type::Tiny::Duck.

Inlining Restricciones de Tipo

En el caso de una restricción de tipo como esta:

my $type = Int->where( sub { $_ >= 0 } );

Type::Tiny necesitará llamar a una subrutina para verificar que un valor cumple la restricción de tipo Int, y a tu coderef para comprobar que el valor está por encima de cero.

Las llamadas a subrutinas en Perl son relativamente costosas en términos de uso de memoria y CPU, por lo que sería bueno si se pudiera hacer todo en una sola llamada a subrutina.

La restricción de tipo Int sabe cómo crear una cadena de código Perl que verifica un entero. Es algo parecido a lo siguiente. (En realidad es más complicado, pero esto es lo suficientemente cercano como ejemplo).

$_ =~ /^-?[0-9]+$/

Si proporcionas tu comprobación como una cadena en lugar de un coderef, así:

my $type = Int->where( q{ $_ >= 0 } );

Entonces Type::Tiny podrá combinarlas en una sola cadena:

( $_ =~ /^-?[0-9]+$/ ) && ( $_ >= 0 )

Así que Type::Tiny podrá comprobar los valores en una sola llamada a subrutina. Proporcionar restricciones como cadenas es una forma muy sencilla y fácil de optimizar las comprobaciones de tipo.

Pero se puede hacer aún más eficiente. Type::Tiny necesita localizar $_ y copiar el valor en él para la comprobación anterior. Si estás comprobando ArrayRef[$type], esto se hará para cada elemento del array. Las cosas podrían hacerse más eficientes si Type::Tiny pudiera comprobar directamente:

( $arrayref->[$i] =~ /^-?[0-9]+$/ ) && ( $arrayref->[$i] >= 0 )

Esto se puede hacer proporcionando una subrutina inlinable. A la subrutina se le da un nombre de variable y puede usarlo en la cadena de código que genera.

my $type = Type::Tiny->new(
  parent  => Int,
  inlined => sub ( $self, $varname ) {
    return sprintf(
      '(%s) && ( %s >= 0 )',
      $self->parent->inline_check( $varname ),
      $varname,
    );
  }
);

Dado que es bastante común querer llamar a la comprobación inlinable del padre y hacer un "&&" con tu propia cadena, Type::Tiny proporciona un atajo para esto. Simplemente devuelve una lista de cadenas para fusionar con "&&", y si la primera es "undef", Type::Tiny rellenará el espacio en blanco con la comprobación de tipo padre.

my $type = Type::Tiny->new(
  parent  => Int,
  inlined => sub ( $self, $varname ) {
    return ( undef, sprintf( '%s >= 0', $varname ) );
  },
);

Hay una optimización adicional que se puede aplicar a este caso particular. Notarás que comprobamos que la cadena coincide con "/^-?[0-9+]$/" y luego comprobamos que es mayor o igual a cero. Pero un entero no negativo nunca comenzará con un signo menos, por lo que podríamos inlinar la comprobación a algo como:

$_ =~ /^[0-9]+$/

Si bien una comprobación inlinada *puede* llamar a la comprobación de tipo padre, no está obligada a hacerlo.

my $type = Type::Tiny->new(
  parent  => Int,
  inlined => sub ( $self, $varname ) {
    return sprintf( '%s =~ /^[0-9]+$/', $varname );
  }
);

Si optas por no llamar a la comprobación de tipo padre, entonces necesitas asegurarte de que tu propia comprobación sea al menos tan rigurosa.

Inlining Coerciones

Moo es el único kit de herramientas de programación orientada a objetos que admite plenamente la inlinación de coerciones, pero incluso para Moose y Mouse, proporcionar coerciones como cadenas puede ayudar a Type::Tiny a optimizar sus funciones de coerción.

Para Moo, si quieres que tu coerción sea inlinable, todos los tipos que estás coaccionando desde y hacia deben ser inlinables, además la coerción debe proporcionarse como una cadena de código Perl.

Sentido Común

La restricción de tipo HashRef[ArrayRef] probablemente se pueda comprobar más rápido que HashRef[ArrayRef[Num]]. Si te encuentras usando restricciones de tipo muy complejas y lentas, deberías considerar cambiar a unas más simples y rápidas. (Aunque esto significa que tienes que confiar un poco más en tu llamador para que no te proporcione datos incorrectos.)

(Una excepción contraintuitiva a esto: aunque Int es más restrictivo que Num, en la mayoría de las circunstancias las comprobaciones de Int se ejecutarán más rápido.)

Devel::StrictMode

Una posibilidad es usar comprobaciones de tipo estrictas cuando ejecutas tus pruebas de lanzamiento, y comprobaciones de tipo más rápidas y permisivas en otros momentos. Devel::StrictMode puede facilitar esto.

Esto proporciona una constante "STRICT" que indica si tu código está operando en "modo estricto" basándose en ciertas variables de entorno.

Atributos

use Types::Standard qw( ArrayRef Num );
use Devel::StrictMode qw( STRICT );

Type::Tiny::Manual::Optimization(3pm)

NAME

Type::Tiny::Manual::Optimization - Performance optimisation

MANUAL

This document explains some ways of optimising the performance of your code when using Type::Tiny.

The STRICT Constant

Type::Tiny is designed to be used with Devel::StrictMode. When STRICT is false, Type::Tiny will avoid doing any type checking, at the cost of potentially misleading error messages.

In order to get the most benefit from this, you should ensure that your type constraints are only evaluated when STRICT is true.

    use Types::Standard qw( Num );
    use Devel::StrictMode qw( STRICT );

    has numbers => (
      is      => 'ro',
      isa     => STRICT ? ArrayRef[Num] : ArrayRef,
      default => sub { [] },
    );

It is inadvisible to do this on attributes that have coercions because it can lead to inconsistent and unpredictable behaviour.

Type::Params

Very efficient way which avoids compiling the signature at all if "STRICT" is false:

    use Types::Standard qw( Num Object );
    use Type::Params qw( signature );
    use Devel::StrictMode qw( STRICT );

    sub add_number {
      state $check;
      STRICT and $check //= signature(
        method     => 1,
        positional => [ Num ],
      );

      my ( $self, $num ) = STRICT ? &$check : @_;

      push @{ $self->numbers }, $num;
      return $self;
    }

Again, you need to be careful to ensure consistent behaviour if you're using coercions, defaults, slurpies, etc.

Less efficient way, but more declarative and smart enough to just disable checks which are safe(ish) to disable, while coercions, defaults, and slurpies will continue to work:

    use Types::Standard qw( Num Object );
    use Type::Params qw( signature_for );
    use Devel::StrictMode qw( STRICT );

     signature_for add_number => (
       strictness => STRICT,
       method     => 1,
       positional => [ Num ],
     );

     sub add_number ( $self, $num ) {
       push @{ $self->numbers }, $num;
       return $self;
     }

Ad-Hoc Type Checks

    ...;
    my $x = get_some_number();
    assert_Int $x if STRICT;
    return $x + 1;
    ...;

The Slash Operator

Type::Tiny has some of the same logic as Devel::StrictMode built in. In particular, it overloads the slash (division) operator so that TypeA/TypeB evaluates to TypeB normally, but to TypeA in strict mode.

An example using this feature:

    use Types::Standard -types;

    has numbers => (
      is      => 'ro',
      isa     => ArrayRef[ Num / Any ],
      default => sub { [] },
    );

In strict mode, this attribute would check that its value is an arrayref of numbers (which may be slow if it contains a lot of numbers). Normally though, it will just check that the value is an arrayref.
