NOMBRE

Type::Tiny::Manual::UsingWithMoo3 - uso alternativo de Type::Tiny con Moo

MANUAL

Registros de tipos

En todos los ejemplos hasta ahora, hemos importado una colección de restricciones de tipos en cada clase:

package Horse {
  use Moo;
  use Types::Standard qw( Str ArrayRef HashRef Int Any InstanceOf );
  use Types::Common::Numeric qw( PositiveInt );
  use Types::Common::String qw( NonEmptyStr );

  has name    => ( is => 'ro', isa => Str );
  has father  => ( is => 'ro', isa => InstanceOf["Horse"] );
  ...;
}

Esto crea una serie de subrutinas en el espacio de nombres de Horse, una para cada tipo. Hemos usado namespace::autoclean para limpiarlas más tarde.

Pero también es posible evitar incorporar todas estas al espacio de nombres de Horse. En su lugar, usaremos un registro de tipos:

package Horse {
  use Moo;
  use Type::Registry qw( t );

  t->add_types('-Standard');
  t->add_types('-Common::String');
  t->add_types('-Common::Numeric');

  t->alias_type('InstanceOf["Horse"]' => 'Horsey');

  has name     => ( is => 'ro', isa => t('Str') );
  has father   => ( is => 'ro', isa => t('Horsey') );
  has mother   => ( is => 'ro', isa => t('Horsey') );
  has children => ( is => 'ro', isa => t('ArrayRef[Horsey]') );
  ...;
}

Ni siquiera necesitas importar la función t(). Type::Registry se puede usar de una manera completamente orientada a objetos.

package Horse {
  use Moo;
  use Type::Registry;

  my $reg = Type::Registry->for_me;

  $reg->add_types('-Standard');
  $reg->add_types('-Common::String');
  $reg->add_types('-Common::Numeric');

  $reg->alias_type('InstanceOf["Horse"]' => 'Horsey');

  has name => ( is => 'ro', isa => $reg->lookup('Str') );
  ...;
}

Podrías crear dos registros con definiciones completamente diferentes para el mismo tipo con nombre.

my $dracula = Aristocrat->new(name => 'Dracula');

package AristocracyTracker {
  use Type::Registry;

  my $reg1 = Type::Registry->new;
  $reg1->add_types('-Common::Numeric');
  $reg1->alias_type('PositiveInt' => 'Count');

  my $reg2 = Type::Registry->new;
  $reg2->add_types('-Standard');
  $reg2->alias_type('InstanceOf["Aristocrat"]' => 'Count');

  $reg1->lookup("Count")->assert_valid("1");
  $reg2->lookup("Count")->assert_valid($dracula);
}

Type::Registry usa "AUTOLOAD", por lo que cosas como esta funcionan:

$reg->ArrayRef->of( $reg->Int );

Aunque puedes crear tantos registros como quieras, Type::Registry creará un registro por defecto para cada paquete.

# Crear un nuevo registro vacío.
# 
my $reg = Type::Registry->new;

# Obtener el registro por defecto para mi paquete.
# Estará pre-poblado con cualquier tipo que hayamos importado usando `use`.
#
my $reg = Type::Registry->for_me;

# Obtener el registro por defecto para algún otro paquete.
#
my $reg = Type::Registry->for_class("Horse");

Los registros de tipos son un lugar conveniente para almacenar un montón de tipos sin contaminar tu espacio de nombres. Sin embargo, no son lo mismo que las bibliotecas de tipos. Types::Standard, Types::Common::String y Types::Common::Numeric son bibliotecas de tipos; paquetes que exportan tipos para que otros los usen. Veremos cómo crear una de esas más tarde.

Por ahora, aquí está la mejor manera de pensar en la diferencia:

  • Registro de tipos

    Curar una colección de tipos para que los use aquí en esta clase. Esta colección es un detalle de implementación.

  • Biblioteca de tipos

    Exportar una colección de tipos para ser utilizada en múltiples clases. Esta colección es parte de tu API.

Importación de funciones

Hemos visto cómo, por ejemplo, Types::Standard exporta una subrutina llamada "Int" que devuelve el objeto de tipo Int.

use Types::Standard qw( Int );

my $type = Int;
$type->check($value) or die $type->get_message($value);

Las bibliotecas de tipos también son capaces de exportar otras funciones de conveniencia.

"is_*"

Este es un atajo para verificar si un valor cumple con una restricción de tipo:

use Types::Standard qw( is_Int );

if ( is_Int $value ) {
  ...;
}

Llamar a is_Int($value) a menudo será marginalmente más rápido que llamar a "Int->check($value)" porque evita una llamada a método. (Las llamadas a métodos en Perl terminan siendo más lentas que las llamadas a funciones normales).

Usar cosas como "is_ArrayRef" en tu código podría ser preferible a "ref($value) eq "ARRAY"" porque es más ordenado, conduce a una verificación de tipo más consistente y podría ser incluso más rápido. (Type::Tiny puede ser bastante rápido; a veces puede exportar estas funciones como subs XS).

Si verificas restricciones de tipo como "is_ArrayRef" o "is_InstanceOf", no hay forma de pasar un parámetro. "is_ArrayRef[Int]($value)" no funciona, ni tampoco "is_ArrayRef(Int, $value)" ni "is_ArrayRef($value, Int)". Para algunos tipos como "is_InstanceOf", esto los hace bastante inútiles; sin poder dar un nombre de clase, simplemente actúa igual que "is_Object". Ver "Exportación de Tipos Parametrizados" para una solución. Además, mira isa.

También existe una función genérica "is".

use Types::Standard qw( ArrayRef Int );
use Type::Utils qw( is );

if ( is ArrayRef[Int], \@numbers ) {
  ...;
}

"assert_*"

Mientras que is_Int($value) devuelve un booleano, assert_Int($value) lanzará un error si el valor no cumple la restricción, y devolverá el valor de lo contrario. Así que puedes hacer:

my $sum = assert_Int($x) + assert_Int($y);

¡Y obtendrás la suma de los enteros $x y $y, y una explosión si alguno de ellos no es un entero!

Assert es útil para verificaciones rápidas de parámetros si estás evitando Type::Params por alguna extraña razón:

sub add_numbers {
  my $x = assert_Num(shift);
  my $y = assert_Num(shift);
  return $x + $y;
}

También puedes usar una función genérica "assert".

use Type::Utils qw( assert );

sub add_numbers {
  my $x = assert Num, shift;
  my $y = assert Num, shift;
  return $x + $y;
}

"to_*"

Este es un atajo para la coerción:

my $truthy = to_Bool($value);

Confía en que la coerción ha funcionado bien. Puedes combinarlo con una aserción si quieres asegurarte.

my $truthy = assert_Bool(to_Bool($value));

Atajos para exportar funciones

Esto es un poco verboso:

use Types::Standard qw( Bool is_Bool assert_Bool to_Bool );

¿No es esto un poco mejor?

use Types::Standard qw( +Bool );

El signo más le dice a una biblioteca de tipos que exporte no solo el tipo en sí, sino todas las funciones de conveniencia.

También puedes usar:

use Types::Standard -types;   # exportar Int, Bool, etc
use Types::Standard -is;      # exportar is_Int, is_Bool, etc
use Types::Standard -assert;  # exportar assert_Int, assert_Bool, etc
use Types::Standard -to;      # exportar to_Bool, etc
use Types::Standard -all;     # ¡¡¡simplemente exportar todo!!!

Así que si imaginas las funciones exportadas por Types::Standard son así:

qw(
  Str             is_Str          assert_Str
  Num             is_Num          assert_Num
  Int             is_Int          assert_Int
  Bool            is_Bool         assert_Bool     to_Bool
  ArrayRef        is_ArrayRef     assert_ArrayRef
);
# ... y más

Entonces "+" exporta un grupo horizontal de esos, y "-" exporta un grupo vertical.

Es posible exportar tipos parametrizables como ArrayRef, pero también es posible exportar tipos *parametrizados*.

NAME

Type::Tiny::Manual::UsingWithMoo3 - Use Type::Tiny with Moo

MANUAL

This document explains how to use Type::Tiny with Moo.

For Type::Tiny 2.0+, you can use the type constraints from Types::Standard, Types::Common and other modules with Moo::Role attributes.

use Types::Standard qw( Int Str );
use Moo::Role;

role MyRole {
  has number => (
    is => 'ro',
    isa => Int,
    coerce => 1,
  );

  has string => (
    is => 'rw',
    isa => Str,
  );
}

This will automatically create Int() and Str() type constraints, and because of the coerce => 1, it will attempt to coerce values to Int.

You can also define your own parameterised types and use them:

use Types::Standard::ArrayRef;
use Moo::Role;

has numbers => (
  is => 'ro',
  isa => ArrayRef->of(Int),
);

This creates a type constraint ArrayRef[Int] and assigns it to the numbers attribute.

The is_IntList function is defined for this type constraint:

package MyClass;
use Types::Standard::ArrayRef;
use Moo;

has numbers => (
  is => 'ro',
  isa => IntList, # Defined by: +ArrayRef' of => Int, -as => 'IntList'
);

Using is_IntList($value) should be significantly faster than "ArrayRef->of(Int)->check($value)".

This trick only works for parameterized types that have a single parameter, like ArrayRef, HashRef, InstanceOf, etc. (Sorry, "Dict" and "Tuple"!)

Since Type::Tiny 2.8.0 there has been experimental support for a different way of exporting parameterized versions of certain parameterizable type constraints.

use Types::Standard -types;
use Types::Standard::ArrayRef (
  IntList         => { of => Int },
  StrList         => { of => Str },
  NonEmptyStrList => { of => Str->where( sub { length($_) > 0 } ) },
  StrNonEmptyList => { of => Str, where => sub { @$_ > 0 } },
  NEStrNEList     => {
    of    => Str->where( sub { length($_) > 0 } ),
    where => sub { @$_ > 0 },
  },
);

assert_IntList [ 1.. 5 ];                      # doesn't die

is_NonEmptyStrList [ "foo", "bar" ];           # ==> true
is_NonEmptyStrList [ "foo", "" ];              # ==> false
is_NonEmptyStrList [];                         # ==> true

is_StrNonEmptyList [ "foo", "bar" ];           # ==> true
is_StrNonEmptyList [ "foo", "" ];              # ==> true
is_StrNonEmptyList [];                         # ==> false

is_NEStrNEList [ "foo", "bar" ];               # ==> true
is_NEStrNEList [ "foo", "" ];                  # ==> false
is_NEStrNEList [];                             # ==> false

And of course "where" also accepts a string of Perl code.

Lexical imports

Type::Tiny 2.0 combined with Perl 5.37.2+ allows lexically scoped imports. So:

my $is_ok = do {
  use Types::Standard -lexical, qw( Str ArrayRef );
  ArrayRef->of( Str )->check( \@things );
};

# The Str and ArrayRef types aren't defined here.

Do What I Mean!

use Type::Utils qw( dwim_type );

my $type = dwim_type("ArrayRef[Int]");

"dwim_type" will look up a type constraint from a string and attempt to guess what you meant.

If it's a type constraint that you seem to have imported with "use", then it should find it. Otherwise, if you're using Moose or Mouse, it'll try asking those. Or if it's in Types::Standard, it'll look there. And if it still has no idea, then it will assume dwim_type("Foo") means dwim_type("InstanceOf['Foo']").

It just does a big old bunch of guessing.

The "is" function will use "dwim_type" if you pass it a string as a type.

use Type::Utils qw( is );

if ( is "ArrayRef[Int]", \@numbers ) {
  ...;
}

Types::Common

Notice that in a lot of examples we're importing one or two functions each from a few different modules:

use Types::Common::Numeric qw( PositiveInt );
use Types::Common::String qw( NonEmptyStr );
use Types::Standard qw( ArrayRef Slurpy );
use Type::Params qw( signature_for );

A module called Types::Common exists which acts as a single place you can use for importing most of Type::Tiny's commonly used types and functions.

use Types::Common qw(
  PositiveInt NonEmptyStr ArrayRef Slurpy
  signature_for
);

Types::Common provides:

  • All the types from Types::Standard.
  • All the types from Types::Common::Numeric and Types::Common::String.
  • All the types from Types::TypeTiny.
  • The "-sigs" tag from Type::Params.
  • The t() function from Type::Registry.
