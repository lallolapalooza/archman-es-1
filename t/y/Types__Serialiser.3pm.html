NOMBRE

Types::Serialiser - tipos de datos simples para formatos de serialización comunes

SINOPSIS

DESCRIPCIÓN

Este módulo proporciona algunos tipos de datos adicionales que se utilizan en formatos de serialización comunes como JSON o CBOR. La idea es tener un repositorio de constantes y contenedores simples/pequeños que puedan ser compartidos por diferentes implementaciones para que sean interoperables entre sí.

CONSTANTES ESCALARES SIMPLES

Las constantes escalares simples son valores que se sobrecargan para actuar como valores Perl simples, pero tienen un tipo (de clase) para diferenciarlos de los escalares Perl normales. Esto es necesario porque tienen diferentes representaciones en los formatos de serialización.

En lo siguiente, las funciones con cero o un argumento tienen un prototipo de "()" y "($)", respectivamente, por lo que actúan como constantes y operadores unarios.

BOOLEANOS (clase Types::Serialiser::Boolean)

Este tipo tiene solo dos instancias, verdadero y falso. Una representación natural para estos en Perl es 1 y 0, pero los formatos de serialización necesitan poder diferenciarlos de meros números.

$Types::Serialiser::true, Types::Serialiser::true
Este valor representa el valor "verdadero". En la mayoría de los contextos actúa como el número 1. Tú decides si usas la forma de variable ($Types::Serialiser::true) o la forma de constante ("Types::Serialiser::true").

La constante se representa como una referencia a un escalar que contiene 1; las implementaciones pueden verificar esto directamente.

$Types::Serialiser::false, Types::Serialiser::false
Este valor representa el valor "falso". En la mayoría de los contextos actúa como el número 0. Tú decides si usas la forma de variable ($Types::Serialiser::false) o la forma de constante ("Types::Serialiser::false").

La constante se representa como una referencia a un escalar que contiene 0; las implementaciones pueden verificar esto directamente.

Types::Serialiser::as_bool $valor
Convierte un escalar Perl en un booleano, lo cual es un azúcar sintáctico útil. Estrictamente equivalente a: 
$valor ? $Types::Serialiser::true : $Types::Serialiser::false
$es_bool = Types::Serialiser::is_bool $valor
Devuelve verdadero si y solo si $valor es $Types::Serialiser::true o $Types::Serialiser::false.

Por ejemplo, podrías diferenciar entre un valor Perl verdadero y un "Types::Serialiser::true" usando esto:

$valor && Types::Serialiser::is_bool $valor
$es_verdadero = Types::Serialiser::is_true $valor
Devuelve verdadero si y solo si $valor es $Types::Serialiser::true.
$es_falso = Types::Serialiser::is_false $valor
Devuelve falso si y solo si $valor es $Types::Serialiser::false.

ERROR (clase Types::Serialiser::Error)

Esta clase tiene una sola instancia, "error". Se utiliza para señalar un error de codificación o decodificación. En CBOR, por ejemplo, un objeto que no pudo ser codificado se representará mediante un valor indefinido CBOR, que se representa como el valor de error en Perl.

$Types::Serialiser::error, Types::Serialiser::error
Este valor representa el valor "error". Acceder a valores de este tipo lanzará una excepción.

La constante se representa como una referencia a un escalar que contiene "undef"; las implementaciones pueden verificar esto directamente.

$es_error = Types::Serialiser::is_error $valor
Devuelve falso si y solo si $valor es $Types::Serialiser::error.

NOTAS PARA USUARIOS DE XS

La forma recomendada de detectar si un escalar es uno de estos objetos es verificar si el "stash" (almacén) es el de "Types::Serialiser::Boolean" o "Types::Serialiser::Error", y luego seguir la referencia del escalar para ver si es 1 (verdadero), 0 (falso) o "undef" (error).

Si bien es posible usar una prueba isa, comparar directamente los punteros de "stash" es más rápido y garantizado que funcione.

Por razones históricas, el "stash" de "Types::Serialiser::Boolean" es solo un alias para "JSON::PP::Boolean". Al imprimirse, el nombre de la clase generalmente será "JSON::PP::Boolean", pero las pruebas isa y la comparación de punteros de "stash" normalmente funcionarán correctamente (es decir, Types::Serialiser::true ISA JSON::PP::Boolean, pero también ISA Types::Serialiser::Boolean).

UN PROTOCOLO GENÉRICO DE SERIALIZACIÓN DE OBJETOS

Esta sección explica el protocolo de serialización de objetos utilizado por CBOR::XS. Está diseñado para ser lo suficientemente genérico como para admitir cualquier tipo de serializador de objetos genérico.

Este protocolo se llama "el protocolo de serialización de objetos de Types::Serialiser".

CODIFICACIÓN

Cuando el codificador encuentra un objeto que no puede codificar de otra manera (por ejemplo, CBOR::XS puede codificar algunos tipos especiales por sí mismo y primero intentará usar el protocolo de serialización especial "TO_CBOR"), buscará el método "FREEZE" en el objeto.

Tenga en cuenta que el método "FREEZE" normalmente se llamará *durante* la codificación, y *NO DEBE* cambiar la estructura de datos que se está codificando de ninguna manera, o podría causar corrupción de memoria o algo peor.

Si existe, se llamará con dos argumentos: el objeto a serializar y una cadena constante que indica el nombre del modelo de datos. Por ejemplo, CBOR::XS usa "CBOR", y los módulos JSON y JSON::XS (o cualquier otro serializador JSON), usarían "JSON" como segundo argumento.

El método "FREEZE" puede devolver cero o más valores para identificar la instancia del objeto. Luego, se supone que el serializador codificará el nombre de la clase y todos estos valores de retorno (que deben ser codificables en el formato) utilizando la forma relevante para los objetos Perl. En CBOR, por ejemplo, existe un número de etiqueta registrado para objetos Perl codificados.

Los valores que devuelve "FREEZE" deben ser serializables con el serializador que lo llama. Por lo tanto, se recomienda utilizar tipos simples como cadenas y números, y quizás referencias a arreglos y hashes (básicamente, el modelo de datos JSON). Siempre puedes usar un formato más complejo para un modelo de datos específico verificando el segundo argumento, el modelo de datos.

El "modelo de datos" no es lo mismo que el "formato de datos": el modelo de datos indica qué tipos y clases de valores de retorno se pueden devolver desde "FREEZE". Por ejemplo, en "CBOR" es permisible devolver valores CBOR etiquetados, mientras que JSON no los soporta en absoluto, por lo que "JSON" sería un nombre de modelo de datos válido (pero demasiado limitado) para "CBOR::XS". De manera similar, un formato de serialización que admite un modelo de datos igual o similar a JSON podría usar "JSON" como modelo de datos sin perder nada.

DECODIFICACIÓN

Cuando el decodificador encuentra un objeto perl codificado de este tipo, debe buscar el método "THAW" en el nombre de clase almacenado, e invocarlo con el nombre de clase, la cadena constante que identifica el modelo de datos/formato de datos, y todos los valores de retorno devueltos por "FREEZE".

EJEMPLOS

Vea la sección "OBJECT SERIALISATION" en la página del manual de CBOR::XS para más detalles, un ejemplo de implementación y ejemplos de código.

Aquí hay un par de métodos "FREEZE"/"THAW" de ejemplo:

sub My::Object::FREEZE {
   my ($self, $model) = @_;
   ($self->{type}, $self->{id}, $self->{variant})
}
sub My::Object::THAW {
   my ($class, $model, $type, $id, $variant) = @_;
   $class->new (type => $type, id => $id, variant => $variant)
}

ERRORES

El uso de sobrecarga hace que este módulo sea mucho más pesado de lo que debería ser (en mi sistema, este módulo: 4kB RSS, sobrecarga: 260kB RSS).

VEA TAMBIÉN

Actualmente, JSON::XS y CBOR::XS utilizan estos tipos.
