Throwable(3pm)

Paquete: perl-throwable

Licencias: PerlArtistic, GPL

Throwable(3pm) Documentación de Perl aportada por el usuario Throwable(3pm)

NOMBRE

Throwable - un rol para clases que se pueden lanzar

VERSIÓN

versión 1.001

SINOPSIS

package Redirect;
# NOTA: También se puede usar Moo aquí en lugar de Moose
use Moose;
with 'Throwable';
has url => (is => 'ro');

...luego más tarde...

Redirect->throw({ url => $url });

DESCRIPCIÓN

Throwable es un rol para clases que están destinadas a ser lanzadas como excepciones para el flujo normal del programa. Es muy simple y solo hace dos cosas: guarda cualquier valor previo de $@ y llama a "die $self".

Throwable está implementado con Moo, por lo que puedes usar Moo o Moose, como prefieras.

VERSIÓN DE PERL

Esta biblioteca debería ejecutarse en perls lanzados incluso hace mucho tiempo. Debería funcionar en cualquier versión de perl lanzada en los últimos cinco años.

Aunque puede funcionar en versiones anteriores de perl, no se garantiza que la versión mínima requerida no aumente. La versión puede aumentarse por cualquier motivo, y no hay promesa de que se acepten parches para reducir la versión mínima de perl requerida.

ATRIBUTOS

previous_exception

Este atributo se crea automáticamente y almacena el valor de $@ cuando se crea el objeto Throwable. Esto se hace con el objetivo de hacerlo de la mejor manera posible (best effort). $@ está sujeto a mucha acción espeluznante a distancia. Por ahora, hay claramente formas en las que la excepción previa podría perderse.

MÉTODOS

throw

Something::Throwable->throw({ attr => $value });

Este método llamará a new, pasando todos los argumentos a new, y luego usará el objeto creado como el único argumento para "die".

Si se llama en un objeto que hace Throwable, el objeto será relanzado.

new_with_previous

die Something::Throwable->new_with_previous({ attr => $value });

Construye un objeto de excepción y lo devuelve, mientras intenta asegurarse de que cualquier valor en $@ se almacene de forma segura en "previous_exception" sin ser sobrescrito por evaluaciones en el proceso de construcción.

Esto es más confiable que llamar directamente a "new", pero no incluye el "die" forzado en "throw".
