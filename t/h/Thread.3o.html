type t

El tipo de manejadores de hilos.

Creación y terminación de hilos

val create : ('a -> 'b) -> 'a -> t

Thread.create funct arg crea un nuevo hilo de control, en el que se ejecuta la aplicación de la función funct arg concurrentemente con los otros hilos del dominio. La aplicación de Thread.create devuelve el manejador del hilo recién creado. El nuevo hilo termina cuando la aplicación funct arg retorna, ya sea normalmente o lanzando la excepción Thread.Exit o lanzando cualquier otra excepción no capturada. En este último caso, la excepción no capturada se imprime en la salida de error estándar, pero no se propaga al hilo padre. De manera similar, el resultado de la aplicación funct arg se descarta y no es directamente accesible para el hilo padre.

Ver también Domain.spawn si deseas ejecución paralela en su lugar.

val self : unit -> t

Devuelve el manejador del hilo que se está ejecutando actualmente.

val id : t -> int

Devuelve el identificador del hilo dado. Un identificador de hilo es un entero que identifica de forma única el hilo. Se puede usar para construir estructuras de datos indexadas por hilos.

val set_current_thread_name : string -> unit

Establece el nombre del hilo. Esto debe llamarse desde dentro de la función del hilo. Establecer el nombre del hilo está disponible en la mayoría de los sistemas.

Esto no hace nada si la funcionalidad no está implementada, pero imprimirá una advertencia en la salida de error estándar si está habilitada.

Del mismo modo, se imprime una advertencia si la operación falla.

Desde 5.4

exception Exit

Excepción lanzada por el código del usuario para iniciar la terminación del hilo actual. En un hilo creado por Thread.create funct arg , si la excepción Thread.Exit llega a la parte superior de la aplicación funct arg , tiene el efecto de terminar el hilo actual silenciosamente. En otros contextos, no hay manejo implícito de la excepción Thread.Exit.

val exit : unit -> unit

Obsoleto. Usa 'raise Thread.Exit' en su lugar.

Lanza la excepción Thread.Exit. En un hilo creado por Thread.create , esto provocará que el hilo termine prematuramente, a menos que la función del hilo maneje la excepción por sí misma. Los finalizadores de Fun.protect y los manejadores de excepciones generales se ejecutarán.

Para dejar claro que se lanza una excepción y que activará los finalizadores y los manejadores de excepciones generales, se recomienda escribir raise Thread.Exit en lugar de Thread.exit ().

Antes de 5.0 Se utilizó una implementación diferente, no basada en el lanzamiento de una excepción, y que no ejecutaba finalizadores ni manejadores generales. La implementación anterior tenía un comportamiento diferente cuando se llamaba fuera de un hilo creado por Thread.create.

Suspensión de hilos

val delay : float -> unit

delay d suspende la ejecución del hilo que llama durante d segundos. Los otros hilos del programa continúan ejecutándose durante este tiempo.

val join : t -> unit

join th suspende la ejecución del hilo que llama hasta que el hilo th haya terminado.

val yield : unit -> unit

Reprograma el hilo que llama sin suspenderlo. Esta función se puede utilizar para dar sugerencias de planificación, indicando al planificador que es un buen momento para cambiar a otros hilos.

Espera de descriptores de archivos o procesos

Las funciones a continuación son remanentes de un sistema de hilos anterior, basado en VM. El módulo Unix proporciona funcionalidad equivalente, de una manera más general y más conforme a los estándares. Se recomienda utilizar las funciones de Unix directamente.

val wait_timed_read : Unix.file_descr -> float -> bool

Obsoleto. Usa Unix.select en su lugar.

Ver Thread.wait_timed_write.

val wait_timed_write : Unix.file_descr -> float -> bool

Obsoleto. Usa Unix.select en su lugar.

Suspende la ejecución del hilo que llama hasta que esté disponible al menos un carácter o EOF para leer ( wait_timed_read ) o se pueda escribir un carácter sin bloqueo ( wait_timed_write ) en el descriptor de archivo Unix dado. Espera como máximo el tiempo dado como segundo argumento (en segundos). Devuelve true si el descriptor de archivo está listo para entrada/salida y false si expiró el tiempo de espera. La misma funcionalidad se puede lograr con Unix.select.

val select : Unix.file_descr list -> Unix.file_descr list -> Unix.file_descr list -> float -> Unix.file_descr list * Unix.file_descr list * Unix.file_descr list

Obsoleto. Usa Unix.select en su lugar.

Misma función que Unix.select. Suspende la ejecución del hilo que llama hasta que la entrada/salida sea posible en los descriptores de archivo Unix dados. Los argumentos y los resultados tienen el mismo significado que para Unix.select.

val wait_pid : int -> int * Unix.process_status

Obsoleto. Usa Unix.waitpid en su lugar.

Misma función que Unix.waitpid. wait_pid p suspende la ejecución del hilo que llama hasta que el proceso especificado por el identificador de proceso p termine. Devuelve el pid del hijo capturado y su estado de terminación, según Unix.wait.

Gestión de señales

El manejo de señales sigue el modelo de hilos POSIX: las señales generadas por un hilo se entregan a ese hilo; las señales generadas externamente se entregan a uno de los hilos que no las bloquean. Cada hilo posee un conjunto de señales bloqueadas, que se pueden modificar usando Thread.sigmask. Este conjunto se hereda en el momento de la creación del hilo. Las máscaras de señales por hilo solo son compatibles con la biblioteca de hilos del sistema en Unix, pero no en Win32, ni con la biblioteca de hilos de la VM.

val sigmask : Unix.sigprocmask_command -> int list -> int list

Misma función que Unix.sigprocmask. sigmask cmd sigs cambia el conjunto de señales bloqueadas para el hilo que llama. Si cmd es SIG_SETMASK, las señales bloqueadas se establecen en las de la lista sigs. Si cmd es SIG_BLOCK, las señales en sigs se añaden al conjunto de señales bloqueadas. Si cmd es SIG_UNBLOCK, las señales en sigs se eliminan del conjunto de señales bloqueadas. sigmask devuelve el conjunto de señales previamente bloqueadas para el hilo.

val wait_signal : int list -> int

Misma función que Unix.sigwait. wait_signal sigs suspende la ejecución del hilo que llama hasta que el proceso reciba una de las señales especificadas en la lista sigs. Luego devuelve el número de la señal recibida. Los manejadores de señales adjuntos a las señales en sigs no se invocarán. Se espera que las señales sigs estén bloqueadas antes de llamar a wait_signal.

Excepciones no capturadas

val default_uncaught_exception_handler : exn -> unit

Thread.default_uncaught_exception_handler imprimirá el id del hilo, la excepción y la traza de pila (si está disponible).

val set_uncaught_exception_handler : (exn -> unit) -> unit

Thread.set_uncaught_exception_handler fn registra fn como el manejador de excepciones no capturadas.

Si el manejador de excepciones no capturadas recién establecido lanza una excepción, se llamará a Thread.default_uncaught_exception_handler.
