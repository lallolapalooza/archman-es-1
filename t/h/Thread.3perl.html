Thread(3perl) Guía de referencia para programadores de Perl Thread(3perl)

NOMBRE

Thread - Manipular hilos en Perl (solo para código antiguo)

OBSOLETO

El módulo "Thread" sirvió como frontend para el modelo de hilos antiguo, llamado *5005threads*, que se introdujo en la versión 5.005. Ese modelo estaba obsoleto y se eliminó en la versión 5.10.

Para compatibilidad hacia atrás con código antiguo y transitoria, el módulo "Thread" se ha rediseñado para funcionar como un frontend para el nuevo modelo de hilos de intérprete (*ithreads*). Sin embargo, parte de la funcionalidad anterior no está disponible. Además, los modelos de intercambio de datos entre los dos modelos de hilos son completamente diferentes, y cualquier cosa relacionada con el intercambio de datos debe pensarse de manera distinta. Con *ithreads*, debes explícitamente share() variables entre los hilos.

Se recomienda encarecidamente migrar cualquier código con hilos existente al nuevo modelo (es decir, usar los módulos "threads" y "threads::shared") lo antes posible.

HISTORIAL

En Perl 5.005, el modelo de hilos era que todos los datos se compartían implícitamente, y el acceso compartido a los datos tenía que sincronizarse explícitamente. Este modelo se llama *5005threads*.

En Perl 5.6, se introdujo un nuevo modelo en el que todos los datos son locales del hilo y el acceso compartido a los datos debe declararse explícitamente. Este modelo se llama *ithreads*, de "interpreter threads" (hilos de intérprete).

En Perl 5.6, el modelo *ithreads* no estaba disponible como una API pública; solo como una API interna que estaba disponible para los escritores de extensiones, y para implementar la emulación de fork() en plataformas Win32.

En Perl 5.8, el modelo *ithreads* estuvo disponible a través del módulo "threads", y el modelo *5005threads* se marcó como obsoleto.

En Perl 5.10, el modelo *5005threads* se eliminó del intérprete de Perl.

SINOPSIS

use Thread qw(:DEFAULT async yield);
my $t = Thread->new(\&start_sub, @start_args);
$result = $t->join;
$t->detach;
if ($t->done) {
    $t->join;
}
if($t->equal($another_thread)) {
    # ...
}
yield();
my $tid = Thread->self->tid;
lock($scalar);
lock(@array);
lock(%hash);
my @list = Thread->list;

DESCRIPCIÓN

El módulo "Thread" proporciona soporte de multihilo para Perl.

FUNCIONES

$thread = Thread->new(\&start_sub)
$thread = Thread->new(\&start_sub, LIST)
"new" inicia un nuevo hilo de ejecución en la subrutina referenciada. La lista opcional se pasa como parámetros a la subrutina. La ejecución continúa tanto en la subrutina como en el código después de la llamada a "new".

"Thread->new" devuelve un objeto de hilo que representa el hilo recién creado.

lock VARIABLE
"lock" coloca un bloqueo en una variable hasta que el bloqueo salga del ámbito.

Si la variable está bloqueada por otro hilo, la llamada a "lock" se bloqueará hasta que esté disponible. "lock" es recursivo, por lo que múltiples llamadas a "lock" son seguras: la variable permanecerá bloqueada hasta que el bloqueo más externo en la variable salga del ámbito.

Los bloqueos en variables solo afectan a las llamadas "lock"; *no* afectan al acceso normal a una variable. (Los bloqueos en subs son diferentes y se cubren más adelante). Si realmente, *realmente* quieres que los bloqueos bloqueen el acceso, entonces átalos a algo y gestiona esto tú mismo. Esto se hace a propósito. Si bien gestionar el acceso a las variables es algo bueno, Perl no te obliga a salir de su sala de estar...

Si un objeto contenedor, como un hash o una matriz, está bloqueado, todos los elementos de ese contenedor no están bloqueados. Por ejemplo, si un hilo hace un "lock @a", cualquier otro hilo que haga un lock($a[12]) no se bloqueará.

Finalmente, "lock" recorrerá las referencias exactamente *un* nivel. lock(\$a) es equivalente a lock($a), mientras que lock(\\$a) no lo es.

async BLOQUE;
"async" crea un hilo para ejecutar el bloque que le sigue inmediatamente. Este bloque se trata como una subrutina anónima y, por lo tanto, debe tener un punto y coma después de la llave de cierre. Al igual que "Thread->new", "async" devuelve un objeto de hilo.
Thread->self
La función "Thread->self" devuelve un objeto de hilo que representa el hilo que realiza la llamada a "Thread->self".
Thread->list
Devuelve una lista de todos los objetos Thread que no han sido unidos ni desvinculados.
cond_wait VARIABLE
La función "cond_wait" toma una variable **bloqueada** como parámetro, desbloquea la variable y se bloquea hasta que otro hilo realice una llamada a "cond_signal" o "cond_broadcast" para la misma variable bloqueada. La variable en la que se bloqueó "cond_wait" se vuelve a bloquear después de que se satisfaga "cond_wait". Si hay varios hilos "cond_wait"ando en la misma variable, todos menos uno volverán a bloquearse esperando para volver a adquirir el bloqueo en la variable. (Así que si solo estás usando "cond_wait" para sincronización, libera el bloqueo lo antes posible).
cond_signal VARIABLE
La función "cond_signal" toma una variable bloqueada como parámetro y desbloquea un hilo que está haciendo "cond_wait" en esa variable. Si más de un hilo está bloqueado en un "cond_wait" en esa variable, solo uno (y cuál es indeterminado) será desbloqueado.

Si no hay hilos bloqueados en un "cond_wait" en la variable, la señal se descarta.

cond_broadcast VARIABLE
La función "cond_broadcast" funciona de manera similar a "cond_signal". "cond_broadcast", sin embargo, desbloqueará **todos** los hilos que están bloqueados en un "cond_wait" en la variable bloqueada, en lugar de solo uno.
yield
La función "yield" permite que otro hilo tome el control de la CPU. Los resultados exactos dependen de la implementación.

MÉTODOS

join
"join" espera a que un hilo termine y devuelve cualquier valor con el que el hilo haya finalizado. "join" se bloqueará hasta que el hilo haya terminado, aunque no se bloqueará si el hilo ya ha terminado.

Si el hilo al que se está haciendo "join" ha hecho "die", el error por el que murió se devolverá en este momento. Si no quieres que el hilo que realiza el "join" también muera, deberías envolver el "join" en un "eval" o usar el método de hilo "eval" en lugar de "join".

NAME

threads - thread-based concurrency support

DEPRECATED

The threads module is deprecated in favour of threads::shared and the new threads API. It is only available if threads has been explicitly imported.

HISTORY

This module was originally written by the 5005threads module author, Terry Monroy, as a more object-oriented interface to the underlying pthreads primitives. The ithreads implementation replaces the original 5005threads implementation.

SYNOPSIS

    use threads;
    my $thread = threads->create( sub { ... } );
    # ...
    my $result = $thread->join();
    # or
    my $tid = threads->tid();

DESCRIPTION

This module provides an object-oriented interface to the POSIX threads primitives.

The main thread of a program has tid 0. Subsequent threads are assigned tids starting with 1.

FUNCTIONS

create BLOCK
create CLASS, BLOCK
create CLASS, OBJECT, METHOD
This is the constructor for a thread object. It takes a subroutine reference (BLOCK) and runs it in a new thread. If CLASS is given, it creates a thread of that class. If OBJECT and METHOD are given, it calls the OBJECT-METHOD in the new thread.
Returns a thread object for the newly created thread.
self
Returns the thread object for the current thread.
tid
Returns the tid of the current thread.

METHODS

detach
"detach" tells a thread that it is never going to be joined i.e. that all traces of its existence can be removed once it stops running. Errors in detached threads will not be visible anywhere - if you want to catch them, you should use $SIG{__DIE__} or something like that.
equal
"equal" tests whether two thread objects represent the same thread and returns true if they do.
tid
The "tid" method returns the tid of a thread. The tid is a monotonically increasing integer assigned when a thread is created. The main thread of a program will have a tid of zero, while subsequent threads will have tids assigned starting with one.
done
The "done" method returns true if the thread you're checking has finished, and false otherwise.

DEFUNCT

The following were implemented with 5005threads, but are no longer available with ithreads.

lock(\&sub)
With 5005threads, you could also "lock" a sub such that any calls to that sub from another thread would block until the lock was released.

Also, subroutines could be declared with the ":locked" attribute which would serialize access to the subroutine, but allowed different threads non-simultaneous access.

eval
The "eval" method wrapped an "eval" around a "join", and so waited for a thread to exit, passing along any values the thread might have returned and placing any errors into $@.
flags
The "flags" method returned the flags for the thread - an integer value corresponding to the internal flags for the thread.
