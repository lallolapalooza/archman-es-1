NOMBRE

Tcl_ConditionNotify, Tcl_ConditionWait, Tcl_ConditionFinalize, Tcl_GetThreadData, Tcl_MutexLock, Tcl_MutexUnlock, Tcl_MutexFinalize, Tcl_CreateThread, Tcl_JoinThread - Soporte de hilos de Tcl

SINOPSIS

#include <tcl.h>

void
Tcl_ConditionNotify(condPtr)

void
Tcl_ConditionWait(condPtr, mutexPtr, timePtr)

void
Tcl_ConditionFinalize(condPtr)

Void *
Tcl_GetThreadData(keyPtr, size)

void
Tcl_MutexLock(mutexPtr)

void
Tcl_MutexUnlock(mutexPtr)

void
Tcl_MutexFinalize(mutexPtr)

int
Tcl_CreateThread(idPtr, proc, clientData, stackSize, flags)

int
Tcl_JoinThread(id, result)

ARGUMENTOS

Tcl_Condition *condPtr (in)
Una variable de condición, que debe estar asociada a un bloqueo mutex.
Tcl_Mutex *mutexPtr (in)
Un bloqueo mutex.
const Tcl_Time *timePtr (in)
Un límite de tiempo en la espera de la condición. NULL para esperar indefinidamente. Tenga en cuenta que un valor de sondeo de 0 segundos no tiene mucho sentido.
Tcl_ThreadDataKey *keyPtr (in)
Esto identifica un bloque de almacenamiento local del hilo. La clave debe ser estática y global para el proceso, pero cada hilo terminará asociando un bloque de almacenamiento diferente con esta clave.
int *size (in)
El tamaño del bloque de almacenamiento local del hilo. Esta cantidad de datos se asigna y se inicializa a cero la primera vez que cada hilo llama a Tcl_GetThreadData.
Tcl_ThreadId *idPtr (out)
El almacenamiento al que se hace referencia contendrá el id del hilo recién creado tal como lo devuelve el sistema operativo.
Tcl_ThreadId id (in)
Id del hilo al que se espera.
Tcl_ThreadCreateProc *proc (in)
Este procedimiento actuará como el main() del hilo recién creado. El clientData especificado será su único argumento.
ClientData clientData (in)
Información arbitraria. Se pasa como único argumento a proc.
int stackSize (in)
El tamaño de la pila asignado al nuevo hilo.
int flags (in)
Máscara de bits que contiene banderas que permiten al llamador modificar el comportamiento del nuevo hilo.
int *result (out)
El almacenamiento al que se hace referencia se utiliza para colocar el código de salida del hilo al que se espera.

INTRODUCCIÓN

A partir de la versión 8.1, el núcleo de Tcl es seguro para hilos, lo que le permite incorporar Tcl en aplicaciones multihilo sin personalizar el núcleo de Tcl. A partir de la versión 8.6, el soporte de multihilo de Tcl está activado por defecto. Para deshabilitar el soporte de multihilo de Tcl, debe incluir la opción --disable-threads en configure cuando configure y compile su núcleo de Tcl.

Una restricción importante de la implementación de hilos de Tcl es que solo el hilo que creó un intérprete de Tcl puede usar ese intérprete. En otras palabras, múltiples hilos no pueden acceder al mismo intérprete de Tcl. (Sin embargo, un solo hilo puede crear y usar múltiples intérpretes de forma segura).

DESCRIPCIÓN

Tcl proporciona Tcl_CreateThread para crear hilos. El llamador puede determinar el tamaño de la pila asignado al nuevo hilo y modificar el comportamiento a través de las flags proporcionadas. El valor TCL_THREAD_STACK_DEFAULT para stackSize indica que se debe utilizar el tamaño predeterminado según lo especificado por el sistema operativo para el nuevo hilo. En cuanto a las flags, actualmente solo están definidos los valores TCL_THREAD_NOFLAGS y TCL_THREAD_JOINABLE. El primero de ellos invoca el comportamiento predeterminado sin configuraciones especiales. Usar el segundo valor marca el nuevo hilo como unible. Esto significa que otro hilo puede esperar a que dicho hilo marcado finalice y unirse a él.

Restricciones: En algunos sistemas UNIX, la biblioteca pthread no contiene la funcionalidad para especificar el tamaño de la pila de un hilo. El valor especificado para el tamaño de la pila se ignora en estos sistemas. Windows actualmente no admite hilos unibles. Por lo tanto, este valor de flag se ignora en esta plataforma.

Tcl proporciona las funciones Tcl_ExitThread y Tcl_FinalizeThread para terminar hilos e invocar manejadores de salida opcionales por hilo. Consulte la página Tcl_Exit para obtener más información sobre estos procedimientos.

La función Tcl_JoinThread se proporciona para permitir que los hilos esperen la salida de otro hilo, que debe haber sido marcado como unible mediante el uso de la bandera TCL_THREAD_JOINABLE durante su creación a través de Tcl_CreateThread.

Intentar esperar la salida de un hilo no unible o de un hilo al que ya se está esperando dará como resultado un error. Esperar a un hilo unible que ya ha salido es posible, el sistema conservará la información necesaria hasta después de la llamada a Tcl_JoinThread. Esto significa que no llamar a Tcl_JoinThread para un hilo unible causará una fuga de memoria.

La llamada Tcl_GetThreadData devuelve un puntero a un bloque de datos privados del hilo. Su argumento es una clave que es compartida por todos los hilos y un tamaño para el bloque de almacenamiento. El almacenamiento se asigna automáticamente y se inicializa a todos ceros la primera vez que cada hilo lo solicita. El almacenamiento se desasigna automáticamente mediante Tcl_FinalizeThread.

SINCRONIZACIÓN Y COMUNICACIÓN

Tcl proporciona Tcl_ThreadQueueEvent y Tcl_ThreadAlert para manejar la cola de eventos en aplicaciones multihilo. Consulte la página del manual Notifier para obtener más información sobre estos procedimientos.

Un mutex es un bloqueo que se utiliza para serializar todos los hilos a través de un fragmento de código llamando a Tcl_MutexLock y Tcl_MutexUnlock. Si un hilo tiene un mutex, cualquier otro hilo que llame a Tcl_MutexLock se bloqueará hasta que se llame a Tcl_MutexUnlock. Un mutex puede ser destruido después de su uso llamando a Tcl_MutexFinalize. El resultado de bloquear un mutex dos veces desde el mismo hilo no está definido. En algunas plataformas, dará lugar a un interbloqueo. Los procedimientos Tcl_MutexLock, Tcl_MutexUnlock y Tcl_MutexFinalize se definen como macros vacías si no se compila con hilos habilitados. Para la declaración de mutexes, se debe usar la macro TCL_DECLARE_MUTEX. Esta macro asegura un manejo correcto de los mutexes incluso cuando el núcleo se compila sin hilos habilitados.

Una variable de condición se utiliza como mecanismo de señalización: un hilo puede bloquear un mutex y luego esperar en una variable de condición con Tcl_ConditionWait. Esto libera atómicamente el bloqueo del mutex y bloquea el hilo en espera hasta que otro hilo llame a Tcl_ConditionNotify. El llamador de Tcl_ConditionNotify debería tener el mutex asociado bloqueado llamando previamente a Tcl_MutexLock, pero esto no se impone. Notificar la variable de condición desbloquea todos los hilos que esperan en la variable de condición, pero no proceden hasta que el mutex se libera con Tcl_MutexUnlock. La implementación de Tcl_ConditionWait bloquea automáticamente el mutex antes de devolver.

El llamador de Tcl_ConditionWait debe estar preparado para notificaciones espurias llamando a Tcl_ConditionWait dentro de un bucle while que prueba algún invariante.

Una variable de condición puede ser destruida después de su uso llamando a Tcl_ConditionFinalize.

Los procedimientos Tcl_ConditionNotify, Tcl_ConditionWait y Tcl_ConditionFinalize se definen como macros vacías si no se compila con hilos habilitados.

INICIALIZACIÓN

Todos estos objetos de sincronización se autoinicializan. Se implementan como punteros opacos que deben ser NULL en su primer uso. Los mutexes y las variables de condición se limpian mediante manejadores de salida del proceso (si viven tanto) o explícitamente mediante llamadas a Tcl_MutexFinalize o Tcl_ConditionFinalize. El almacenamiento local del hilo se recupera durante Tcl_FinalizeThread.

ACCESO A HILOS A NIVEL DE SCRIPT

Tcl no proporciona comandos integrados para que los scripts los usen para crear, administrar o unir hilos, ni ningún acceso a nivel de script a mutexes o variables de condición. Proporciona tales facilidades solo a través de interfaces C, y deja a los paquetes la tarea de exponerlos.

EJEMPLO

Para crear un hilo con código portable, su función de implementación debe declararse de la siguiente manera:

static Tcl_ThreadCreateProc MiFuncionImplHilo;

Luego, debe definirse de esta manera de ejemplo, que simplemente cuenta hasta un valor dado y luego termina.

static Tcl_ThreadCreateType
MiFuncionImplHilo(
    ClientData clientData)
{
    int i, limite = (int) clientData;
    for (i=0 ; i<limite ; i++) {
        /* no haciendo nada aquí en absoluto */
    }
    TCL_THREAD_CREATE_RETURN;
}

Para crear el hilo anterior, hacerlo ejecutar y esperar a que termine, haríamos esto:

int limite = 1000000000;
ClientData datosLimite = (void*)((intptr_t) limite);
Tcl_ThreadId id;    /* contiene la identidad del hilo creado */
int resultado;
if (Tcl_CreateThread(&id, MiFuncionImplHilo, datosLimite,
        TCL_THREAD_STACK_DEFAULT,
        TCL_THREAD_JOINABLE) != TCL_OK) {
    /* El hilo no se creó correctamente */
    return;
}
/* Haz algo más por un tiempo aquí */
if (Tcl_JoinThread(id, &resultado) != TCL_OK) {
    /* El hilo no terminó correctamente */
    return;
}
/* Todo bien limpio */
