TAP::Parser::Aggregator(3perl) Guía de referencia del programador de Perl TAP::Parser::Aggregator(3perl)

NOMBRE

TAP::Parser::Aggregator - Agrega resultados de TAP::Parser

VERSIÓN

Versión 3.50

SINOPSIS

use TAP::Parser::Aggregator;
my $aggregate = TAP::Parser::Aggregator->new;
$aggregate->add( 't/00-load.t', $load_parser );
$aggregate->add( 't/10-lex.t',  $lex_parser  );
my $summary = <<'END_SUMMARY';
Pasados:  %s
Fallidos:  %s
Sucedidos inesperadamente: %s
END_SUMMARY
printf $summary,
       scalar $aggregate->passed,
       scalar $aggregate->failed,
       scalar $aggregate->todo_passed;

DESCRIPCIÓN

"TAP::Parser::Aggregator" recopila objetos de parser y permite informar/consultar sus resultados agregados.

MÉTODOS

Métodos de Clase

"new"

my $aggregate = TAP::Parser::Aggregator->new;

Devuelve un nuevo objeto "TAP::Parser::Aggregator".

Métodos de Instancia

"add"

$aggregate->add( $description => $parser );

La $description suele ser un nombre de archivo de prueba (pero solo por convención). Se utiliza como identificador único (ver, por ejemplo, "parsers".) Reutilizar una descripción es un error fatal.

El $parser es un objeto TAP::Parser.

"parsers"

my $count   = $aggregate->parsers;
my @parsers = $aggregate->parsers;
my @parsers = $aggregate->parsers(@descriptions);

En contexto de escalar sin argumentos, este método devuelve el número de parsers agregados. En contexto de lista sin argumentos, devuelve los parsers en el orden en que fueron añadidos.

Si se proporciona @descriptions, estas corresponden a las claves utilizadas en cada llamada al método add(). Devuelve un array de los parsers solicitados (en el orden solicitado) en contexto de lista o una referencia de array en contexto de escalar.

Solicitar un identificador desconocido es un error fatal.

"descriptions"

Obtiene un array de descripciones en el orden en que fueron añadidas al agregador.

"start"

Llama a "start" inmediatamente antes de añadir cualquier resultado al agregador. Entre otras cosas, registra la hora de inicio de la ejecución de las pruebas.

"stop"

Llama a "stop" inmediatamente después de añadir todos los resultados de las pruebas al agregador.

"elapsed"

Elapsed devuelve un objeto Benchmark que representa el tiempo de ejecución de las pruebas agregadas. Para que "elapsed" sea válido, debes llamar a "start" antes de ejecutar las pruebas y a "stop" inmediatamente después.

"elapsed_timestr"

Devuelve una cadena formateada que representa el tiempo de ejecución devuelto por elapsed(). Esto permite al llamador no preocuparse por Benchmark.

"all_passed"

Devuelve verdadero si todas las pruebas pasaron y no se detectaron errores de análisis.

"get_status"

Obtiene una palabra única que describe el estado de las pruebas agregadas. Dependiendo del resultado de las pruebas, devuelve 'PASS', 'FAIL' o 'NOTESTS'. Este token es entendido por CPAN::Reporter.

Métodos de Resumen

Cada uno de los siguientes métodos devolverá el número total de pruebas correspondientes si se llama en contexto de escalar. Si se llama en contexto de lista, devuelve las descripciones de los parsers que contienen las pruebas correspondientes (ver "add" para una explicación de la descripción).

  • failed
  • parse_errors
  • passed
  • planned
  • skipped
  • todo
  • todo_passed
  • wait
  • exit

Por ejemplo, para averiguar cuántas pruebas pasaron inesperadamente (pruebas TODO que pasaron cuando no debían):

my $count        = $aggregate->todo_passed;
my @descriptions = $aggregate->todo_passed;

Tenga en cuenta que "wait" y "exit" son los totales de los estados de espera y salida de cada una de las pruebas. Estos valores se suman solo para proporcionar un valor verdadero si alguno de ellos no es cero.

"total"

my $tests_run = $aggregate->total;

Devuelve el número total de pruebas ejecutadas.

"has_problems"

if ( $parser->has_problems ) {
    ...
}

Idéntico a "has_errors", pero también devuelve verdadero si alguna prueba TODO pasó inesperadamente. Esto se parece más a "advertencias".

"has_errors"

if ( $parser->has_errors ) {
    ...
}

Devuelve verdadero si *algún* de los parsers falló. Esto incluye:

  • Pruebas fallidas
  • Errores de análisis
  • Estado de salida o espera incorrecto

"todo_failed"

# obsoleto en favor de 'todo_passed'. Este método tuvo un nombre horriblemente equivocado.

Este fue un método horriblemente mal nombrado. Indica qué pruebas TODO pasaron inesperadamente. Ahora emitirá una advertencia y llamará a "todo_passed".
