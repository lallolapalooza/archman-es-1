DESCRIPCIÓN

Las implementaciones de listas enlazadas simples, colas de cola enlazadas simples, listas y colas de cola están disponibles para la creación de estructuras de datos enlazadas en el espacio del usuario. Las listas enlazadas simples (SLIST) y las colas de cola enlazadas simples (STAILQ) son estructuras de datos de un solo enlace. Las listas (LIST) y las colas de cola (TAILQ) son estructuras de datos de doble enlace. Las colas de cola enlazadas simples (STAILQ) y las colas de cola (TAILQ) también mantienen un puntero a la cola de la cola.

Las listas enlazadas simples y las colas de cola enlazadas simples son listas enlazadas en una dirección. Las listas y las colas de cola son listas enlazadas en dos direcciones. Las colas de cola enlazadas simples y las colas de cola mantienen un puntero al último elemento.

Estas macros proporcionan las interfaces para operar sobre estas estructuras de datos. Los desarrolladores deben crear una estructura que contenga una o más de estas entradas enlazadas.

Por ejemplo, para crear una cola de cola enlazada simple de enteros, un desarrollador podría definir:

typedef struct my_int_queue my_int_queue_t;

struct my_int_queue {
int data;
STAILQ_ENTRY(my_int_queue) next;
};
STAILQ_HEAD(my_int_queue_head, my_int_queue);

A continuación, un ejemplo de cómo inicializar y usar la cola de cola:

struct my_int_queue_head queue;
STAILQ_INIT(&queue);
struct my_int_queue *item;
item = malloc(sizeof(*item));
item->data = 10;
STAILQ_INSERT_TAIL(&queue, item, next);
STAILQ_FOREACH(item, &queue, next) {
printf("%d\n", item->data);
}

Las macros de las listas están disponibles en dos versiones: una para listas de doble enlace y otra para listas de un solo enlace. Las listas de doble enlace son listas enlazadas bidireccionalmente. Las listas de un solo enlace son listas enlazadas unidireccionalmente.

Las macros de las colas de cola están disponibles en dos versiones: una para colas de cola de doble enlace y otra para colas de cola de un solo enlace. Las colas de cola de doble enlace son colas de cola enlazadas bidireccionalmente. Las colas de cola de un solo enlace son colas de cola enlazadas unidireccionalmente.

Las macros de las listas enlazadas simples y las colas de cola enlazadas simples son listas enlazadas en una dirección.

Las macros de las listas y las colas de cola son listas enlazadas en dos direcciones.

Las macros de las colas de cola enlazadas simples y las colas de cola mantienen un puntero al último elemento.

SLIST_HEAD

Define una estructura de cabeza de lista para una lista enlazada simple. El primer argumento, HEADNAME, es el nombre de la estructura de cabeza de lista. El segundo argumento, TYPE, es el nombre de la estructura del elemento de la lista.

SLIST_HEAD(my_head, my_item);

Define una estructura llamada my_head_t con un miembro slh_first que es un puntero a my_item_t.

SLIST_ENTRY

Define una estructura de entrada para una lista enlazada simple. El argumento TYPE es el nombre de la estructura del elemento de la lista.

SLIST_ENTRY(my_item);

Define una estructura llamada my_item_slh con un miembro slh_next que es un puntero a my_item_t.

SLIST_INIT

Inicializa una lista enlazada simple. El argumento HEAD es un puntero a la estructura de cabeza de lista.

SLIST_INIT(&my_list_head);

SLIST_INSERT_HEAD

Inserta un elemento al principio de una lista enlazada simple. El primer argumento, HEAD, es un puntero a la estructura de cabeza de lista. El segundo argumento, elm, es un puntero al elemento que se va a insertar. El tercer argumento, SLIST_ENTRY NAME, es el nombre del miembro de la estructura de entrada enlazada.

SLIST_INSERT_HEAD(&my_list_head, item, next);

SLIST_INSERT_AFTER

Inserta un elemento después de un elemento existente en una lista enlazada simple. El primer argumento, listelm, es un puntero al elemento existente. El segundo argumento, elm, es un puntero al elemento que se va a insertar. El tercer argumento, SLIST_ENTRY NAME, es el nombre del miembro de la estructura de entrada enlazada.

SLIST_REMOVE_HEAD

Elimina el primer elemento de una lista enlazada simple. El primer argumento, HEAD, es un puntero a la estructura de cabeza de lista. El segundo argumento, SLIST_ENTRY NAME, es el nombre del miembro de la estructura de entrada enlazada.

DESCRIPCIÓN

Estas macros definen y operan sobre cuatro tipos de estructuras de datos que pueden utilizarse tanto en C como en C++:

  1. Lista
  2. Lista enlazada simple
  3. Lista enlazada doble
  4. Cola enlazada doble
Todas las cuatro estructuras soportan la siguiente funcionalidad:
  1. Inserción de un nuevo elemento al frente de la lista.
  2. Inserción de un nuevo elemento después de cualquier elemento de la lista.
  3. Eliminación de un elemento del frente de la lista en O(1).
  4. Recorrido hacia adelante de la lista.
  5. Intercambio de contenido de dos listas.

Las listas enlazadas simples son las más sencillas de las cuatro estructuras de datos y solo soportan la funcionalidad mencionada anteriormente. Las listas enlazadas simples son ideales para aplicaciones con grandes conjuntos de datos y pocas o ninguna eliminación, o para implementar una pila LIFO. Las listas enlazadas simples añaden la siguiente funcionalidad:

  1. Eliminación de cualquier elemento de la lista en O(n).
  2. Concatenación de dos listas en O(n).

Las colas enlazadas simples añaden la siguiente funcionalidad:

  1. Inserción de un elemento al final de la lista.
  2. Eliminación de cualquier elemento de la lista en O(n).
  3. Se pueden concatenar.
Sin embargo:
  1. Las inserciones en cualquier lista deben especificar el frente de la lista.
  2. Cada entrada de cabeza requiere dos punteros en lugar de uno.
  3. El tamaño del código es aproximadamente un 15% mayor y las operaciones toman aproximadamente un 20% más tiempo que en las listas enlazadas simples.

Las colas enlazadas simples son ideales para aplicaciones con grandes conjuntos de datos y pocas o ninguna eliminación, o para implementar una cola FIFO.

Además, los tipos de estructuras de datos doblemente enlazadas (listas y colas de cola) también permiten:

  1. Inserción de un nuevo elemento antes de cualquier elemento de la lista.
  2. Eliminación de cualquier elemento de la lista en O(1).
Sin embargo:
  1. Cada elemento requiere dos punteros en lugar de uno.
  2. El tamaño del código y el tiempo de ejecución de las operaciones (excepto para la eliminación) es aproximadamente el doble que en las estructuras de datos enlazadas simples.

Las listas enlazadas son las más simples de las estructuras de datos doblemente enlazadas. Añaden la siguiente funcionalidad sobre las mencionadas anteriormente:

  1. Concatenación de dos listas en O(n).
  2. Se pueden recorrer en sentido inverso.
Sin embargo:
  1. Para recorrer en sentido inverso, se debe especificar un elemento de inicio del recorrido y la lista en la cual se encuentra dicho elemento.

Las colas de cola añaden la siguiente funcionalidad:

  1. Inserción de un elemento al final de la lista.
  2. Se pueden recorrer en sentido inverso, desde la cola hacia la cabeza.
  3. Se pueden concatenar.
Sin embargo:
  1. Las inserciones y eliminaciones en cualquier lista deben especificar el frente de la lista.
  2. Cada entrada de cabeza requiere dos punteros en lugar de uno.
  3. El tamaño del código es aproximadamente un 15% mayor y las operaciones toman aproximadamente un 20% más tiempo que en las listas enlazadas simples.

En las definiciones de macros, TYPE es el nombre de una estructura definida por el usuario. La estructura debe contener un campo llamado NAME de tipo SLIST_ENTRY, STAILQ_ENTRY, LIST_ENTRY o TAILQ_ENTRY. En las definiciones de macros, CLASSTYPE es el nombre de una clase definida por el usuario. La clase debe contener un campo llamado NAME de tipo SLIST_CLASS_ENTRY, STAILQ_CLASS_ENTRY, LIST_CLASS_ENTRY o TAILQ_CLASS_ENTRY. El argumento HEADNAME es el nombre de una estructura definida por el usuario que debe declararse usando las macros SLIST_HEAD, SLIST_CLASS_HEAD, STAILQ_HEAD, STAILQ_CLASS_HEAD, LIST_HEAD, LIST_CLASS_HEAD, TAILQ_HEAD o TAILQ_CLASS_HEAD. Vea los ejemplos a continuación para una explicación adicional de cómo se utilizan estas macros.

LISTAS ENLAZADAS SIMPLES

Una lista enlazada simple es encabezada por una estructura definida mediante la macro SLIST_HEAD. Esta estructura contiene un único puntero al elemento inicial de la lista. Los elementos se enlazan utilizando la mínima cantidad de espacio y manipulación de punteros, pero con un costo de O(n) para la eliminación de elementos arbitrarios. Se pueden agregar nuevos elementos a la lista después de un elemento existente o al frente de la lista. Una estructura SLIST_HEAD se declara así:

SLIST_HEAD(HEADNAME, TYPE) head;

donde HEADNAME es el nombre de la estructura a definir, y TYPE es el tipo de los elementos de la lista. Posteriormente se puede declarar un puntero a la cabeza de la lista así:

struct HEADNAME *headp;

(Los nombres head y headp son seleccionables por el usuario.)

La macro SLIST_HEAD_INITIALIZER evalúa a un inicializador para la lista head.

La macro SLIST_CONCAT concatena la lista dirigida por head2 al final de la lista dirigida por head1, eliminando todos los elementos de la anterior. Se debe evitar su uso ya que recorre toda la lista head1. Se debería usar una cola enlazada simple si es necesario en rutas de código de alta frecuencia de uso o para operar sobre listas largas.

La macro SLIST_EMPTY evalúa a verdadero si no hay elementos en la lista.

La macro SLIST_ENTRY declara una estructura que conecta los elementos de la lista.

La macro SLIST_FIRST devuelve el primer elemento de la lista o NULL si la lista está vacía.

La macro SLIST_FOREACH recorre la lista dirigida por head en dirección forward, asignando cada elemento en orden a var.

La macro SLIST_FOREACH_FROM se comporta de manera idéntica a SLIST_FOREACH cuando var es NULL, de lo contrario trata var como un elemento previamente encontrado en una lista SLIST y comienza el bucle en var en lugar del primer elemento de la lista dirigida por head.

La macro SLIST_FOREACH_SAFE recorre la lista dirigida por head en dirección forward, asignando cada elemento en orden a var. Sin embargo, a diferencia de SLIST_FOREACH(), aquí se permite tanto eliminar var como liberar memoria de forma segura desde dentro del bucle sin interferir con el recorrido.

La macro SLIST_FOREACH_FROM_SAFE se comporta de manera idéntica a SLIST_FOREACH_SAFE cuando var es NULL, de lo contrario trata var como un elemento previamente encontrado en una lista SLIST y comienza el bucle en var en lugar del primer elemento de la lista dirigida por head.

La macro SLIST_INIT inicializa la lista dirigida por head.

La macro SLIST_INSERT_HEAD inserta el nuevo elemento elm al frente de la lista.

La macro SLIST_INSERT_AFTER inserta el nuevo elemento elm después del elemento listelm en la lista.

SINGLY-LINKED LISTS

A singly-linked list is headed by a structure defined by the SLIST_HEAD macro. This structure contains a single pointer to the first element on the list. The elements are singly linked for minimum space and pointer manipulation overhead at the expense of O(n) removal for arbitrary elements. New elements can be added to the list after an existing element, or at the head of the list. A SLIST_HEAD structure is declared as follows:

SLIST_HEAD(HEADNAME, TYPE) head;

where HEADNAME is the name of the structure to be defined, and TYPE is the type of the elements to be linked into the list. A pointer to the head of the list can later be declared as:

struct HEADNAME *headp;

(The names head and headp are user selectable.)

The macro SLIST_HEAD_INITIALIZER evaluates to an initializer for the list head.

The macro SLIST_CONCAT concatenates the list headed by head2 onto the end of the one headed by head1 removing all entries from the former. Use of this macro should be avoided as it traverses the entirety of the head1 list. A doubly-linked list should be used if this macro is needed in high-usage code paths or to operate on long lists.

The macro SLIST_EMPTY evaluates to true if there are no elements on the list.

The macro SLIST_ENTRY declares a structure that connects the elements in the list.

The macro SLIST_FIRST returns the first element on the list or NULL if the list is empty.

The macro SLIST_FOREACH traverses the list referenced by head in the forward direction, assigning each element in turn to var.

The macro SLIST_FOREACH_FROM behaves identically to SLIST_FOREACH when var is NULL, else it treats var as a previously found SLIST element and begins the loop at var instead of the first element in the SLIST referenced by head.

The macro SLIST_FOREACH_SAFE traverses the list referenced by head in the forward direction, assigning each element in turn to var. However, unlike SLIST_FOREACH() here it is permitted to both remove var as well as free it from within the loop safely without interfering with the traversal.

The macro SLIST_FOREACH_FROM_SAFE behaves identically to SLIST_FOREACH_SAFE when var is NULL, else it treats var as a previously found SLIST element and begins the loop at var instead of the first element in the SLIST referenced by head.

The macro SLIST_INIT initializes the list referenced by head.

The macro SLIST_INSERT_HEAD inserts the new element elm at the head of the list.

The macro SLIST_INSERT_AFTER inserts the new element elm after the element listelm.

The macro SLIST_NEXT returns the next element in the list.

The macro SLIST_REMOVE_AFTER removes the element after elm from the list. Unlike SLIST_REMOVE, this macro does not traverse the entire list.

The macro SLIST_REMOVE_HEAD removes the element elm from the head of the list. For optimum efficiency, elements being removed from the head of the list should explicitly use this macro instead of the generic SLIST_REMOVE macro.

The macro SLIST_REMOVE removes the element elm from the list. Use of this macro should be avoided as it traverses the entire list. A doubly-linked list should be used if this macro is needed in high-usage code paths or to operate on long lists.

The macro SLIST_SWAP swaps the contents of head1 and head2.

SINGLY-LINKED LIST EXAMPLE

SLIST_HEAD(slisthead, entry) head =
    SLIST_HEAD_INITIALIZER(head);
struct slisthead *headp;		/* Singly-linked List head. */
struct entry {
	...
	SLIST_ENTRY(entry) entries;	/* Singly-linked List. */
	...
} *n1, *n2, *n3, *np;

SLIST_INIT(&head);			/* Initialize the list. */

n1 = malloc(sizeof(struct entry));	/* Insert at the head. */
SLIST_INSERT_HEAD(&head, n1, entries);

n2 = malloc(sizeof(struct entry));	/* Insert after. */
SLIST_INSERT_AFTER(n1, n2, entries);

SLIST_REMOVE(&head, n2, entry, entries);/* Deletion. */
free(n2);

n3 = SLIST_FIRST(&head);
SLIST_REMOVE_HEAD(&head, entries);	/* Deletion from the head. */
free(n3);
					/* Forward traversal. */
SLIST_FOREACH(np, &head, entries)
	np-> ...
					/* Safe forward traversal. */
SLIST_FOREACH_SAFE(np, &head, entries, np_temp) {
	np->do_stuff();
	...
	SLIST_REMOVE(&head, np, entry, entries);
	free(np);
}

while (!SLIST_EMPTY(&head)) {		/* List Deletion. */
	n1 = SLIST_FIRST(&head);
	SLIST_REMOVE_HEAD(&head, entries);
	free(n1);
}

SINGLY-LINKED TAIL QUEUES

A singly-linked tail queue is headed by a structure defined by the STAILQ_HEAD macro. This structure contains a pair of pointers, one to the first element in the tail queue and the other to the last element in the tail queue. The elements are singly linked for minimum space and pointer manipulation overhead at the expense of O(n) removal for arbitrary elements. New elements can be added to the tail queue after an existing element, at the head of the tail queue, or at the end of the tail queue. A STAILQ_HEAD structure is declared as follows:

STAILQ_HEAD(HEADNAME, TYPE) head;

where HEADNAME is the name of the structure to be defined, and TYPE is the type of the elements to be linked into the tail queue. A pointer to the head of the tail queue can later be declared as:

struct HEADNAME *headp;

(The names head and headp are user selectable.)

The macro STAILQ_HEAD_INITIALIZER evaluates to an initializer for the tail queue head.

The macro STAILQ_CONCAT concatenates the tail queue headed by head2 onto the end of the one headed by head1 removing all entries from the former.

The macro STAILQ_EMPTY evaluates to true if there are no items on the tail queue.

The macro STAILQ_ENTRY declares a structure that connects the elements in the tail queue.

The macro STAILQ_FIRST returns the first item on the tail queue or NULL if the tail queue is empty.

The macro STAILQ_FOREACH traverses the tail queue referenced by head in the forward direction, assigning each element in turn to var.

The macro STAILQ_FOREACH_FROM behaves identically to STAILQ_FOREACH when var is NULL, else it treats var as a previously found STAILQ element and begins the loop at var instead of the first element in the STAILQ referenced by head.

The macro STAILQ_FOREACH_SAFE traverses the tail queue referenced by head in the forward direction, assigning each element in turn to var. However, unlike STAILQ_FOREACH() here it is permitted to both remove var as well as free it from within the loop safely without interfering with the traversal.

The macro STAILQ_FOREACH_FROM_SAFE behaves identically to STAILQ_FOREACH_SAFE when var is NULL, else it treats var as a previously found STAILQ element and begins the loop at var instead of the first element in the STAILQ referenced by head.

The macro STAILQ_INIT initializes the tail queue referenced by head.

The macro STAILQ_INSERT_HEAD inserts the new element elm at the head of the tail queue.

The macro STAILQ_INSERT_TAIL inserts the new element elm at the end of the tail queue.

The macro STAILQ_INSERT_AFTER inserts the new element elm after the element listelm.

The macro STAILQ_LAST returns the last item on the tail queue. If the tail queue is empty the return value is NULL.

The macro STAILQ_NEXT returns the next item on the tail queue, or NULL this item is the last.

The macro STAILQ_REMOVE_AFTER removes the element after elm from the tail queue. Unlike STAILQ_REMOVE, this macro does not traverse the entire tail queue.

The macro STAILQ_REMOVE_HEAD removes the element at the head of the tail queue. For optimum efficiency, elements being removed from the head of the tail queue should use this macro explicitly rather than the generic STAILQ_REMOVE macro.

The macro STAILQ_REMOVE removes the element elm from the tail queue. Use of this macro should be avoided as it traverses the entire list. A doubly-linked tail queue should be used if this macro is needed in high-usage code paths or to operate on long tail queues.

The macro STAILQ_SWAP swaps the contents of head1 and head2.

LISTS

A list is headed by a structure defined by the LIST_HEAD macro. This structure contains a single pointer to the first element on the list. The elements are doubly linked so that an arbitrary element can be removed without traversing the list. New elements can be added to the list after an existing element, before an existing element, or at the head of the list. A LIST_HEAD structure is declared as follows:

LIST_HEAD(HEADNAME, TYPE) head;

where HEADNAME is the name of the structure to be defined, and TYPE is the type of the elements to be linked into the list. A pointer to the head of the list can later be declared as:

struct HEADNAME *headp;

(The names head and headp are user selectable.)

The macro LIST_HEAD_INITIALIZER evaluates to an initializer for the list head.

The macro LIST_CONCAT concatenates the list headed by head2 onto the end of the one headed by head1 removing all entries from the former. Use of this macro should be avoided as it traverses the entirety of the head1 list. A tail queue should be used if this macro is needed in high-usage code paths or to operate on long lists.

The macro LIST_EMPTY evaluates to true if there are no elements in the list.

The macro LIST_ENTRY declares a structure that connects the elements in the list.

The macro LIST_FIRST returns the first element in the list or NULL if the list is empty.

The macro LIST_FOREACH traverses the list referenced by head in the forward

COLAS DE PUNTA

Una cola de punta se define mediante la macro TAILQ_HEAD. Esta estructura contiene un par de punteros, uno al primer elemento de la cola de punta y el otro al último elemento de la cola de punta. Los elementos están enlazados doblemente de forma que cualquier elemento pueda ser eliminado sin recorrer la cola de punta. Los nuevos elementos pueden ser añadidos a la cola de punta después de un elemento existente, antes de un elemento existente, al principio de la cola de punta o al final de la cola de punta. Una estructura TAILQ_HEAD se declara así:

TAILQ_HEAD(HEADNAME, TYPE) head;

donde HEADNAME es el nombre de la estructura a definir y TYPE es el tipo de los elementos enlazados a la cola de punta. Un puntero a la cabeza de la cola de punta puede ser declarado más tarde así:

struct HEADNAME *headp;

(Los nombres head y headp son elegibles por el usuario.)

La macro TAILQ_HEAD_INITIALIZER se evalúa como un inicializador para la cola de punta head.

La macro TAILQ_CONCAT concatenará la cola de punta dirigida por head2 al final de la cola de punta dirigida por head1, eliminando todos los elementos de la primera cola.

La macro TAILQ_EMPTY se evalúa como true si no hay elementos en la cola de punta.

La macro TAILQ_ENTRY declara una estructura que enlaza los elementos de la cola de punta.

La macro TAILQ_FIRST devuelve el primer elemento de la cola de punta o NULL si la cola está vacía.

La macro TAILQ_FOREACH recorre la cola de punta dirigida por head en la dirección forward, asignando cada elemento a var. var se establece a NULL si el bucle termina normalmente, o a NULL si no hay elementos.

La macro TAILQ_FOREACH_FROM se comporta idénticamente a TAILQ_FOREACH cuando var es NULL, de lo contrario trata var como un elemento previamente encontrado en la cola de punta y comienza el bucle en var en lugar del primer elemento de la cola de punta dirigida por head.

La macro TAILQ_FOREACH_REVERSE recorre la cola de punta dirigida por head en la dirección reverse, asignando cada elemento a var.

La macro TAILQ_FOREACH_REVERSE_FROM se comporta idénticamente a TAILQ_FOREACH_REVERSE cuando var es NULL, de lo contrario trata var como un elemento previamente encontrado en la cola de punta y comienza el bucle en var en lugar del último elemento de la cola de punta dirigida por head.

Las macros TAILQ_FOREACH_SAFE y TAILQ_FOREACH_REVERSE_SAFE recorren la lista dirigida por head en la dirección forward o reverse, asignando cada elemento a var. Sin embargo, a diferencia de sus contrapartes no seguras, TAILQ_FOREACH y TAILQ_FOREACH_REVERSE permiten eliminar var y liberar su contenido dentro del bucle de manera segura sin interferir con el recorrido.

La macro TAILQ_FOREACH_FROM_SAFE se comporta idénticamente a TAILQ_FOREACH_SAFE cuando var es NULL, de lo contrario trata var como un elemento previamente encontrado en la cola de punta y comienza el bucle en var en lugar del primer elemento de la cola de punta dirigida por head.

La macro TAILQ_FOREACH_REVERSE_FROM_SAFE se comporta idénticamente a TAILQ_FOREACH_REVERSE_SAFE cuando var es NULL, de lo contrario trata var como un elemento previamente encontrado en la cola de punta y comienza el bucle en var en lugar del último elemento de la cola de punta dirigida por head.

La macro TAILQ_INIT inicializa la cola de punta dirigida por head.

La macro TAILQ_INSERT_HEAD inserta el nuevo elemento elm al principio de la cola de punta.

La macro TAILQ_INSERT_TAIL inserta el nuevo elemento elm al final de la cola de punta.

La macro TAILQ_INSERT_AFTER inserta el nuevo elemento elm después del elemento listelm.

La macro TAILQ_INSERT_BEFORE inserta el nuevo elemento elm antes del elemento listelm.

La macro TAILQ_LAST devuelve el último elemento de la cola de punta. Si la cola de punta está vacía, el valor devuelto es NULL.

La macro TAILQ_NEXT devuelve el siguiente elemento de la cola de punta, o NULL si este es el último.

La macro TAILQ_PREV devuelve el elemento anterior de la cola de punta, o NULL si este es el primero.

La macro TAILQ_REMOVE elimina el elemento elm de la cola de punta.

La macro TAILQ_SWAP intercambia los contenidos de head1 y head2.

DIAGNÓSTICOS

Al depurar queue(3), puede ser útil trazar los cambios en la cola. Para habilitar el trazado, defina la macro QUEUE_MACRO_DEBUG_TRACE en tiempo de compilación.

También puede ser útil "ensuciar" los punteros que han sido desvinculados de una cola, para detectar el uso después de la eliminación. Para habilitar el "ensuciamiento" de punteros, defina la macro QUEUE_MACRO_DEBUG_TRASH en tiempo de compilación. La macro QMD_IS_TRASHED(void *ptr) devuelve verdadero si ptr ha sido "ensuciado" por la opción QUEUE_MACRO_DEBUG_TRASH.
