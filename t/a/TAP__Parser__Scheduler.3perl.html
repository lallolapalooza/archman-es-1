NOMBRE

TAP::Parser::Scheduler - Planificar pruebas durante la ejecución paralela de pruebas

VERSIÓN

Versión 3.50

SINOPSIS

use TAP::Parser::Scheduler;

DESCRIPCIÓN

MÉTODOS

Métodos de clase

"new"

my $sched = TAP::Parser::Scheduler->new(tests => \@tests);
my $sched = TAP::Parser::Scheduler->new(
    tests => [ ['t/nombre_test.t','Descripción del Test'], ... ],
    rules => \%rules,
);

Dado 'tests' y 'rules' opcionales como entrada, devuelve un nuevo objeto "TAP::Parser::Scheduler". Cada miembro de @tests debe ser un nombre de archivo de prueba, o un arrayref de dos elementos, donde el primer elemento es un nombre de archivo de prueba y el segundo elemento es una descripción de la prueba. Por defecto, utilizaremos el nombre de la prueba como descripción.

El atributo opcional "rules" proporciona instrucciones sobre qué pruebas se deben ejecutar en paralelo y cuáles secuencialmente. Si no se proporciona una estructura de datos de reglas, se utiliza una estructura de datos por defecto que hace que todas las pruebas sean elegibles para ejecutarse en paralelo:

{ par => '**' },

La estructura de datos de reglas se documenta más en la siguiente sección.

Estructura de datos de reglas

La estructura de datos ""rules"" es el corazón del planificador. Permite expresar reglas simples como "ejecutar todas las pruebas en secuencia" o "ejecutar todas las pruebas en paralelo excepto estas cinco pruebas.". Sin embargo, la estructura de reglas también soporta la coincidencia de patrones tipo glob y definiciones recursivas, por lo que también puede expresar patrones arbitrariamente complicados.

La regla debe tener solo una clave de nivel superior: 'par' para "paralelo" o 'seq' para "secuencia".

Los valores deben ser cadenas de texto con posible coincidencia de patrones tipo glob, o arrayrefs de cadenas de texto o hashrefs que sigan este patrón recursivamente.

Cada elemento en un arrayref directamente debajo de una clave 'par' es elegible para ser ejecutado en paralelo, mientras que los valores directamente debajo de una clave 'seq' deben ejecutarse en secuencia.

Ejemplos de reglas

Aquí hay algunos ejemplos:

# Todas las pruebas se ejecutarán en paralelo (la regla por defecto)
{ par => '**' },
# Ejecutar todas las pruebas en secuencia, excepto las que comienzan con "p"
{ par => 't/p*.t' },
# Ejecutar todas las pruebas en paralelo, excepto las que comienzan con "p"
{
    seq => [
              { seq => 't/p*.t' },
              { par => '**'     },
           ],
}
# Ejecutar algunas pruebas de inicio en secuencia, luego algunas pruebas paralelas y luego algunas
# pruebas de finalización en secuencia.
{
    seq => [
        { seq => 't/startup/*.t' },
        { par => ['t/a/*.t','t/b/*.t','t/c/*.t'], }
        { seq => 't/shutdown/*.t' },
    ],
},

Resolución de reglas

  • Por defecto, todas las pruebas son elegibles para ejecutarse en paralelo. La especificación de sus propias reglas elimina esta opción.
  • "La primera coincidencia es válida". La primera regla que coincide con una prueba será la que se aplique.
  • Cualquier prueba que no coincida con una regla se ejecutará en secuencia al final de la ejecución.
  • La existencia de una regla no implica la selección de una prueba. Aún debe especificar las pruebas a ejecutar.
  • La especificación de una regla para permitir que las pruebas se ejecuten en paralelo no hace que la ejecución sea en paralelo. Aún debe especificar el número de "jobs" paralelos en su objeto Harness.

Coincidencia de patrones tipo glob para reglas

Implementamos nuestra propia coincidencia de patrones tipo glob. Estos son los patrones que soporta:

** es cualquier número de caracteres, incluido /, dentro de una ruta de archivo
* son cero o más caracteres dentro de un nombre de archivo/directorio
? es exactamente un carácter dentro de un nombre de archivo/directorio
{foo,bar,baz} es cualquiera de foo, bar o baz.
\ es un carácter de escape

Métodos de instancia

"get_all"

Obtiene una lista de todas las pruebas restantes.

"get_job"

Devuelve el siguiente trabajo disponible como un objeto TAP::Parser::Scheduler::Job o "undef" si no hay ninguno disponible. Devuelve un TAP::Parser::Scheduler::Spinner si el planificador todavía tiene trabajos pendientes pero ninguno está disponible para ejecutarse en este momento.

"as_string"

Devuelve una representación legible por humanos del árbol de planificación. Por ejemplo:

my @tests = (qw{
    t/startup/foo.t 
    t/shutdown/foo.t

    t/a/foo.t t/b/foo.t t/c/foo.t t/d/foo.t
});
my $sched = TAP::Parser::Scheduler->new(
    tests => \@tests,
    rules => {
        seq => [
            { seq => 't/startup/*.t' },
            { par => ['t/a/*.t','t/b/*.t','t/c/*.t'] },
            { seq => 't/shutdown/*.t' },
        ],
    },
);

Produce:

par:
  seq:
    par:
      seq:
        par:
          seq:
            't/startup/foo.t'
        par:
          seq:
            't/a/foo.t'
          seq:
            't/b/foo.t'
          seq:
            't/c/foo.t'
        par:
          seq:
            't/shutdown/foo.t'
    't/d/foo.t'
