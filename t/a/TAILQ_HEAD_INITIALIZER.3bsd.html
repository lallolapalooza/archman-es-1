DESCRIPCIÓN

Estas macros definen y operan sobre cuatro tipos de estructuras de datos que se pueden usar tanto en código fuente C como C++:

  1. Listas
  2. Listas enlazadas simples
  3. Colas de cola simples
  4. Colas de cola
Las cuatro estructuras admiten la siguiente funcionalidad:
  1. Inserción de una nueva entrada al principio de la lista.
  2. Inserción de una nueva entrada después de cualquier elemento de la lista.
  3. Eliminación en tiempo O(1) de una entrada del principio de la lista.
  4. Recorrido hacia adelante a través de la lista.
  5. Intercambio del contenido de dos listas.

Las listas enlazadas simples son las más sencillas de las cuatro estructuras de datos y solo admiten la funcionalidad anterior. Las listas enlazadas simples son ideales para aplicaciones con grandes conjuntos de datos y pocas o ninguna eliminación, o para implementar una cola LIFO. Las listas enlazadas simples añaden la siguiente funcionalidad:

  1. Eliminación en tiempo O(n) de cualquier entrada de la lista.
  2. Concatenación en tiempo O(n) de dos listas.

Las colas de cola simples añaden la siguiente funcionalidad:

  1. Las entradas se pueden añadir al final de una lista.
  2. Eliminación en tiempo O(n) de cualquier entrada de la lista.
  3. Se pueden concatenar.
Sin embargo:
  1. Todas las inserciones de listas deben especificar el encabezado de la lista.
  2. Cada entrada de encabezado requiere dos punteros en lugar de uno.
  3. El tamaño del código es aproximadamente un 15% mayor y las operaciones se ejecutan aproximadamente un 20% más lentas que las listas enlazadas simples.

Las colas de cola simples son ideales para aplicaciones con grandes conjuntos de datos y pocas o ninguna eliminación, o para implementar una cola FIFO.

Todos los tipos de estructuras de datos doblemente enlazadas (listas y colas de cola) permiten adicionalmente:

  1. Inserción de una nueva entrada antes de cualquier elemento de la lista.
  2. Eliminación en tiempo O(1) de cualquier entrada de la lista.
Sin embargo:
  1. Cada elemento requiere dos punteros en lugar de uno.
  2. El tamaño del código y el tiempo de ejecución de las operaciones (excepto la eliminación) es aproximadamente el doble que el de las estructuras de datos enlazadas simples.

Las listas enlazadas son las más sencillas de las estructuras de datos doblemente enlazadas. Añaden la siguiente funcionalidad sobre las anteriores:

  1. Concatenación en tiempo O(n) de dos listas.
  2. Se pueden recorrer hacia atrás.
Sin embargo:
  1. Para recorrer hacia atrás, se debe especificar una entrada para comenzar el recorrido y la lista en la que está contenida.

Las colas de cola añaden la siguiente funcionalidad:

  1. Las entradas se pueden añadir al final de una lista.
  2. Se pueden recorrer hacia atrás, de cola a cabeza.
  3. Se pueden concatenar.
Sin embargo:
  1. Todas las inserciones y eliminaciones de listas deben especificar el encabezado de la lista.
  2. Cada entrada de encabezado requiere dos punteros en lugar de uno.
  3. El tamaño del código es aproximadamente un 15% mayor y las operaciones se ejecutan aproximadamente un 20% más lentas que las listas enlazadas simples.

En las definiciones de macros, TYPE es el nombre de una estructura definida por el usuario. La estructura debe contener un campo llamado NAME que es de tipo SLIST_ENTRY, STAILQ_ENTRY, LIST_ENTRY, o TAILQ_ENTRY. En las definiciones de macros, CLASSTYPE es el nombre de una clase definida por el usuario. La clase debe contener un campo llamado NAME que es de tipo SLIST_CLASS_ENTRY, STAILQ_CLASS_ENTRY, LIST_CLASS_ENTRY, o TAILQ_CLASS_ENTRY. El argumento HEADNAME es el nombre de una estructura definida por el usuario que debe declararse utilizando las macros SLIST_HEAD, SLIST_CLASS_HEAD, STAILQ_HEAD, STAILQ_CLASS_HEAD, LIST_HEAD, LIST_CLASS_HEAD, TAILQ_HEAD, o TAILQ_CLASS_HEAD. Consulte los ejemplos a continuación para obtener más explicaciones sobre cómo se utilizan estas macros.

LISTAS ENLAZADAS SIMPLES

Una lista enlazada simple está encabezada por una estructura definida por la macro SLIST_HEAD. Esta estructura contiene un único puntero al primer elemento de la lista. Los elementos están enlazados simplemente para una mínima sobrecarga de espacio y manipulación de punteros a expensas de una eliminación O(n) para elementos arbitrarios. Se pueden añadir nuevos elementos a la lista después de un elemento existente o al principio de la lista. Una estructura SLIST_HEAD se declara de la siguiente manera:

SLIST_HEAD(HEADNAME, TYPE) head;

donde HEADNAME es el nombre de la estructura a definir, y TYPE es el tipo de los elementos que se enlazarán en la lista. Un puntero al encabezado de la lista se puede declarar posteriormente como:

struct HEADNAME *headp;

(Los nombres head y headp son seleccionables por el usuario.)

La macro SLIST_HEAD_INITIALIZER se evalúa como un inicializador para la lista head.

La macro SLIST_CONCAT concatena la lista encabezada por head2 al final de la encabezada por head1, eliminando todas las entradas de la primera. Se debe evitar el uso de esta macro, ya que recorre la totalidad de la lista head1. Se debe utilizar una cola de cola simple si se necesita esta macro en rutas de código de alto uso o para operar en listas largas.

La macro SLIST_EMPTY se evalúa como verdadero si no hay elementos en la lista.

La macro SLIST_ENTRY declara una estructura que conecta los elementos de la lista.

La macro SLIST_FIRST devuelve el primer elemento de la lista o NULL si la lista está vacía.

La macro SLIST_FOREACH recorre la lista referenciada por head en dirección hacia adelante, asignando cada elemento en turno a var.

La macro SLIST_FOREACH_FROM se comporta idénticamente a SLIST_FOREACH cuando var es NULL, de lo contrario, trata a var como un elemento SLIST encontrado previamente y comienza el bucle en var en lugar del primer elemento de la SLIST referenciada por head.

La macro SLIST_FOREACH_SAFE recorre la lista referenciada por head en dirección hacia adelante, asignando cada elemento en turno a var. Sin embargo, a diferencia de SLIST_FOREACH(), aquí está permitido tanto eliminar var como liberarlo dentro del bucle de forma segura sin interferir con el recorrido.

La macro SLIST_FOREACH_FROM_SAFE se comporta idénticamente a SLIST_FOREACH_SAFE cuando var es NULL, de lo contrario, trata a var como un elemento SLIST encontrado previamente y comienza el bucle en var en lugar del primer elemento de la SLIST referenciada por head.

La macro SLIST_INIT inicializa la lista referenciada por head.

La macro SLIST_INSERT_HEAD inserta el nuevo elemento elm al principio de la lista.

La macro SLIST_INSERT_AFTER inserta el nuevo elemento elm después del elemento

listelm.

La macro SLIST_NEXT devuelve el siguiente elemento de la lista.

La macro SLIST_REMOVE_AFTER elimina el elemento que sigue a elm de la lista. A diferencia de SLIST_REMOVE, esta macro no recorre toda la lista.

La macro SLIST_REMOVE_HEAD elimina el elemento elm de la cabeza de la lista. Para una eficiencia óptima, los elementos que se eliminan de la cabeza de la lista deberían usar explícitamente esta macro en lugar de la macro genérica SLIST_REMOVE.

La macro SLIST_REMOVE elimina el elemento elm de la lista. Se debe evitar el uso de esta macro ya que recorre toda la lista. Se debe usar una lista doblemente enlazada si esta macro es necesaria en rutas de código de alto uso o para operar en listas largas.

La macro SLIST_SWAP intercambia el contenido de head1 y head2.

EJEMPLO DE LISTA SIMPLEMENTE ENLAZADA

SLIST_HEAD(slisthead, entry) head =
    SLIST_HEAD_INITIALIZER(head);
struct slisthead *headp;		/* Cabeza de lista simplemente enlazada. */
struct entry {
	...
	SLIST_ENTRY(entry) entries;	/* Lista simplemente enlazada. */
	...
} *n1, *n2, *n3, *np;

SLIST_INIT(&head);			/* Inicializar la lista. */

n1 = malloc(sizeof(struct entry));	/* Insertar en la cabeza. */
SLIST_INSERT_HEAD(&head, n1, entries);

n2 = malloc(sizeof(struct entry));	/* Insertar después. */
SLIST_INSERT_AFTER(n1, n2, entries);

SLIST_REMOVE(&head, n2, entry, entries);/* Eliminación. */

COLAS CON COLA SIMPLEMENTE ENLAZADA

Una cola con cola simplemente enlazada está encabezada por una estructura definida por la macro STAILQ_HEAD. Esta estructura contiene un par de punteros, uno al primer elemento de la cola con cola y otro al último elemento de la cola con cola. Los elementos están simplemente enlazados para una mínima sobrecarga de espacio y manipulación de punteros a expensas de una eliminación O(n) para elementos arbitrarios. Se pueden agregar nuevos elementos a la cola con cola después de un elemento existente, al principio de la cola con cola o al final de la cola con cola. Una estructura STAILQ_HEAD se declara de la siguiente manera:

STAILQ_HEAD(HEADNAME, TYPE) head;

donde HEADNAME es el nombre de la estructura que se definirá y TYPE es el tipo de los elementos que se enlazarán en la cola con cola. Un puntero a la cabeza de la cola con cola se puede declarar más tarde como:

struct HEADNAME *headp;

(Los nombres head y headp son seleccionables por el usuario.)

La macro STAILQ_HEAD_INITIALIZER se evalúa como un inicializador para la cola con cola head.

La macro STAILQ_CONCAT concatena la cola con cola encabezada por head2 al final de la encabezada por head1, eliminando todas las entradas de la primera.

La macro STAILQ_EMPTY se evalúa como verdadera si no hay elementos en la cola con cola.

La macro STAILQ_ENTRY declara una estructura que conecta los elementos de la cola con cola.

La macro STAILQ_FIRST devuelve el primer elemento de la cola con cola o NULL si la cola con cola está vacía.

La macro STAILQ_FOREACH recorre la cola con cola referenciada por head en dirección hacia adelante, asignando cada elemento en turno a var.

La macro STAILQ_FOREACH_FROM se comporta de manera idéntica a STAILQ_FOREACH cuando var es NULL; de lo contrario, trata a var como un elemento STAILQ encontrado previamente y comienza el bucle en var en lugar del primer elemento de la STAILQ referenciada por head.

La macro STAILQ_FOREACH_SAFE recorre la cola con cola referenciada por head en dirección hacia adelante, asignando cada elemento en turno a var. Sin embargo, a diferencia de STAILQ_FOREACH(), aquí está permitido tanto eliminar var como liberarlo del bucle de forma segura sin interferir con el recorrido.

La macro STAILQ_FOREACH_FROM_SAFE se comporta de manera idéntica a STAILQ_FOREACH_SAFE cuando var es NULL; de lo contrario, trata a var como un elemento STAILQ encontrado previamente y comienza el bucle en var en lugar del primer elemento de la STAILQ referenciada por head.

La macro STAILQ_INIT inicializa la cola con cola referenciada por head.

La macro STAILQ_INSERT_HEAD inserta el nuevo elemento elm al principio de la cola con cola.

La macro STAILQ_INSERT_TAIL inserta el nuevo elemento elm al final de la cola con cola.

La macro STAILQ_INSERT_AFTER inserta el nuevo elemento elm después del elemento listelm.

La macro STAILQ_LAST devuelve el último elemento de la cola con cola. Si la cola con cola está vacía, el valor de retorno es NULL.

La macro STAILQ_NEXT devuelve el siguiente elemento de la cola con cola, o NULL si este elemento es el último.

La macro STAILQ_REMOVE_AFTER elimina el elemento que sigue a elm de la cola con cola. A diferencia de STAILQ_REMOVE, esta macro no recorre toda la cola con cola.

La macro STAILQ_REMOVE_HEAD elimina el elemento al principio de la cola con cola. Para una eficiencia óptima, los elementos que se eliminan de la cabeza de la cola con cola deberían usar explícitamente esta macro en lugar de la macro genérica STAILQ_REMOVE.

La macro STAILQ_REMOVE elimina el elemento elm de la cola con cola. Se debe evitar el uso de esta macro, ya que recorre toda la lista. Se debe usar una cola con cola doblemente enlazada si esta macro se necesita en rutas de código de alto uso o para operar en colas con cola largas.

La macro STAILQ_SWAP intercambia el contenido de head1 y head2.

free(n3);

LISTS

A list is headed by a structure defined by the LIST_HEAD macro. This structure contains a pointer to the first element in the list. The elements are singly linked so that the list is traversed in the forward direction only. New elements can be added to the list before the first element, or after an arbitrary element. A LIST_HEAD structure is declared as follows:

LIST_HEAD(HEADNAME, TYPE) head;

where HEADNAME is the name of the structure to be defined, and TYPE is the type of the elements to be linked into the list. A pointer to the head of the list can later be declared as:

struct HEADNAME *headp;

(The names head and headp are user selectable.)

The macro LIST_HEAD_INITIALIZER evaluates to an initializer for the list head.

The macro LIST_ENTRY declares a structure that connects the elements in the list.

The macro LIST_EMPTY evaluates to true if there are no items on the list.

The macro LIST_FIRST returns the first item on the list, or NULL if the list is empty.

The macro LIST_FOREACH traverses the list referenced by head in the forward direction, assigning each element in turn to var.

The macro LIST_FOREACH_FROM behaves identically to LIST_FOREACH when var is NULL, else it treats var as a previously found LIST element and begins the loop at var instead of the first element in the LIST referenced by head.

The macro LIST_FOREACH_SAFE traverses the list referenced by head in the forward direction, assigning each element in turn to var. However, unlike LIST_FOREACH() here it is permitted to both remove var as well as free it from within the loop safely without interfering with the traversal.

The macro LIST_FOREACH_FROM_SAFE behaves identically to LIST_FOREACH_SAFE when var is NULL, else it treats var as a previously found LIST element and begins the loop at var instead of the first element in the LIST referenced by head.

The macro LIST_INIT initializes the list referenced by head.

The macro LIST_INSERT_HEAD inserts the new element elm at the head of the list.

The macro LIST_INSERT_AFTER inserts the new element elm after the element listelm.

The macro LIST_INSERT_BEFORE inserts the new element elm before the element listelm.

The macro LIST_NEXT returns the next element in the list, or NULL if this is the last.

The macro LIST_PREV returns the previous element in the list, or NULL if this is the first. List head must contain element elm.

The macro LIST_REMOVE removes the element elm from the list.

The macro LIST_SWAP swaps the contents of head1 and head2.

TAIL QUEUES

A tail queue is headed by a structure defined by the TAILQ_HEAD macro. This structure contains a pair of pointers, one to the first element in the tail queue and the other to the last element in the tail queue. The elements are doubly linked so that an arbitrary element can be removed without traversing the tail queue. New elements can be added to the tail queue after an existing element, before an existing element, at the head of the tail queue, or at the end of the tail queue. A TAILQ_HEAD structure is declared as follows:

TAILQ_HEAD(HEADNAME, TYPE) head;

where HEADNAME is the name of the structure to be defined, and TYPE is the type of the elements to be linked into the tail queue. A pointer to the head of the tail queue can later be declared as:

struct HEADNAME *headp;

(The names head and headp are user selectable.)

The macro TAILQ_HEAD_INITIALIZER evaluates to an initializer for the tail queue head.

The macro TAILQ_CONCAT concatenates the tail queue headed by head2 onto the end of the one headed by head1 removing all entries from the former.

The macro TAILQ_EMPTY evaluates to true if there are no items on the tail queue.

The macro TAILQ_ENTRY declares a structure that connects the elements in the tail queue.

The macro TAILQ_FIRST returns the first item on the tail queue or NULL if the tail queue is empty.

The macro TAILQ_FOREACH traverses the tail queue referenced by head in the forward direction, assigning each element in turn to var. var is set to NULL if the loop completes normally, or if there were no elements.

The macro TAILQ_FOREACH_FROM behaves identically to TAILQ_FOREACH when var is NULL, else it treats var as a previously found TAILQ element and begins the loop at var instead of the first element in the TAILQ referenced by head.

The macro TAILQ_FOREACH_REVERSE traverses the tail queue referenced by head in the reverse direction, assigning each element in turn to var.

The macro TAILQ_FOREACH_REVERSE_FROM behaves identically to TAILQ_FOREACH_REVERSE when var is NULL, else it treats var as a previously found TAILQ element and begins the reverse loop at var instead of the last element in the TAILQ referenced by head.

The macros TAILQ_FOREACH_SAFE and TAILQ_FOREACH_REVERSE_SAFE traverse the list referenced by head in the forward or reverse direction respectively, assigning each element in turn to var. However, unlike their unsafe counterparts, TAILQ_FOREACH and TAILQ_FOREACH_REVERSE make it possible to both remove var as well as free it from within the loop safely without interfering with the traversal.

The macro TAILQ_FOREACH_FROM_SAFE behaves identically to TAILQ_FOREACH_SAFE when var is NULL, else it treats var as a previously found TAILQ element and begins the loop at var instead of the first element in the TAILQ referenced by head.

The macro TAILQ_FOREACH_REVERSE_FROM_SAFE behaves identically to TAILQ_FOREACH_REVERSE_SAFE when var is NULL, else it treats var as a previously found TAILQ element and begins the reverse loop at var instead of the last element in the TAILQ referenced by head.

The macro TAILQ_INIT initializes the tail queue referenced by head.

The macro TAILQ_INSERT_HEAD inserts the new element elm at the head of the tail queue.

The macro TAILQ_INSERT_TAIL inserts the new element elm at the end of the tail queue.

The macro TAILQ_INSERT_AFTER inserts the new element elm after the element listelm.

The macro TAILQ_INSERT_BEFORE inserts the new element elm before the element listelm.

The macro TAILQ_LAST returns the last item on the tail queue. If the tail queue is empty the return value is NULL.

The macro TAILQ_NEXT returns the next item on the tail queue, or NULL if this item is the last.

The macro TAILQ_PREV returns the previous item on the tail queue, or NULL if this item is the first.

The macro TAILQ_REMOVE removes the element elm from the tail queue.

The macro TAILQ_SWAP swaps the contents of head1 and head2.

#include <sys/queue.h>

DESCRIPTION

Tail queues are doubly-linked lists that support efficient insertion and deletion at either end of the list. The macros are designed to be used generically with any data structure. The implementation relies on pointers stored within the structure itself.

A tail queue is defined by the macro TAILQ_HEAD. The macro declares a structure that contains a pointer to the first element and a pointer to the last element. The macro TAILQ_HEAD_INITIALIZER can be used to initialize a tail queue.

Elements in the tail queue are declared using the TAILQ_ENTRY macro. This macro declares a structure that contains two pointers, tqe_next and tqe_prev, to link the element into the queue.

The TAILQ_INIT macro initializes an empty tail queue.

The following macros are available for manipulating tail queues:

  • TAILQ_INSERT_HEAD(head, elm, field)

    Insert the element elm at the head of the tail queue head. The macro field is the name of the TAILQ_ENTRY declaration in the structure elm.

  • TAILQ_INSERT_TAIL(head, elm, field)

    Insert the element elm at the tail of the tail queue head.

  • TAILQ_INSERT_AFTER(head, listelm, elm, field)

    Insert the element elm after the element listelm in the tail queue head.

  • TAILQ_INSERT_BEFORE(head, listelm, elm, field)

    Insert the element elm before the element listelm in the tail queue head.

  • TAILQ_REMOVE(head, elm, field)

    Remove the element elm from the tail queue head.

  • TAILQ_REPLACE(head, oldelm, newelm, field)

    Replace the element oldelm with the element newelm in the tail queue head.

  • TAILQ_MOVE(head, elm, field)

    Move the element elm to the tail of the tail queue head.

  • TAILQ_NEXT(elm, field)

    Return a pointer to the next element in the tail queue.

  • TAILQ_PREV(elm, type, field)

    Return a pointer to the previous element in the tail queue. type is the structure type of the tail queue head.

  • TAILQ_LAST(head, type)

    Return a pointer to the last element in the tail queue.

  • TAILQ_FOREACH(var, head)

    Iterate over the tail queue head. The current element is assigned to var.

  • TAILQ_FOREACH_REVERSE(var, head)

    Iterate in reverse over the tail queue head.

  • TAILQ_FOREACH_SAFE(var, head, nextvar)

    A safe version of TAILQ_FOREACH that allows the loop body to safely remove the current element.

  • TAILQ_FOREACH_REVERSE_SAFE(var, head, nextvar)

    A safe version of TAILQ_FOREACH_REVERSE.

  • TAILQ_CONCAT(head1, head2, field)

    Concatenate the tail queue head2 onto the end of the tail queue head1. The head2 queue will be empty after the operation.

  • TAILQ_EMPTY(head)

    Return true if the tail queue head is empty.

  • TAILQ_FIRST(head)

    Return a pointer to the first element in the tail queue.

  • TAILQ_END(head)

    Return a pointer to the element after the last element in the tail queue.

  • TAILQ_SWAP(head1, head2, type)

    Swap the contents of the tail queues head1 and head2.

SINGLY-LINKED LISTS

The queue(3) package also provides macros for manipulating singly-linked lists. These macros are prefixed with SLIST_ instead of TAILQ_.

SINGLY-LINKED LIST EXAMPLE

struct my_entry {
	int data;
	SLIST_ENTRY(my_entry) next;
};

struct my_list {
	SLIST_HEAD(my_list_head, my_entry) head;
};

void example() {
	struct my_list mylist;
	struct my_entry *entry;
	struct my_entry *temp;

	SLIST_INIT(&mylist.head);

	entry = malloc(sizeof(struct my_entry));
	entry->data = 10;
	SLIST_INSERT_HEAD(&mylist.head, entry, next);

	entry = malloc(sizeof(struct my_entry));
	entry->data = 20;
	SLIST_INSERT_TAIL(&mylist.head, entry, next);

	SLIST_FOREACH(entry, &mylist.head) {
		printf("Data: %d\n", entry->data);
	}

	SLIST_FOREACH_SAFE(entry, &mylist.head, temp) {
		SLIST_REMOVE(&mylist.head, entry, my_entry, next);
		free(entry);
	}
}

DIAGNOSTICS

When debugging queue(3), it can be useful to trace queue changes. To enable tracing, define the macro QUEUE_MACRO_DEBUG_TRACE at compile time.

It can also be useful to trash pointers that have been unlinked from a queue, to detect use after removal. To enable pointer trashing, define the macro QUEUE_MACRO_DEBUG_TRASH at compile time. The macro QMD_IS_TRASHED(void *ptr) returns true if ptr has been trashed by the QUEUE_MACRO_DEBUG_TRASH option.
