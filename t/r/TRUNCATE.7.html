TRUNCATE(7)

Paquete: postgresql

Licencias: PostgreSQL

TRUNCATE(7) Documentación de PostgreSQL 18.1 TRUNCATE(7)

NOMBRE

TRUNCATE - vaciar una tabla o un conjunto de tablas

SINOPSIS

TRUNCATE [ TABLE ] [ ONLY ] nombre [ * ] [, ... ]
    [ RESTART IDENTITY | CONTINUE IDENTITY ] [ CASCADE | RESTRICT ]

DESCRIPCIÓN

TRUNCATE elimina rápidamente todas las filas de un conjunto de tablas. Tiene el mismo efecto que un DELETE sin calificar en cada tabla, pero como en realidad no escanea las tablas es más rápido. Además, recupera el espacio en disco inmediatamente, en lugar de requerir una operación VACUUM posterior. Esto es más útil en tablas grandes.

PARÁMETROS

nombre

El nombre (opcionalmente calificado por esquema) de una tabla a truncar. Si se especifica ONLY antes del nombre de la tabla, solo se truncará esa tabla. Si NO se especifica ONLY, la tabla y todas sus tablas descendientes (si las hay) se truncarán. Opcionalmente, se puede especificar * después del nombre de la tabla para indicar explícitamente que se incluyen las tablas descendientes.

RESTART IDENTITY

Reiniciar automáticamente las secuencias propiedad de columnas de las tablas truncadas.

CONTINUE IDENTITY

No cambiar los valores de las secuencias. Esta es la opción predeterminada.

CASCADE

Truncar automáticamente todas las tablas que tengan referencias de clave externa a cualquiera de las tablas nombradas, o a cualquier tabla añadida al grupo debido a CASCADE.

RESTRICT

Rechazar el truncamiento si alguna de las tablas tiene referencias de clave externa de tablas que no están listadas en el comando. Esta es la opción predeterminada.

NOTAS

Debe tener el privilegio TRUNCATE en una tabla para truncarla.

TRUNCATE adquiere un bloqueo ACCESS EXCLUSIVE en cada tabla sobre la que opera, lo que bloquea todas las demás operaciones concurrentes en la tabla. Cuando se especifica RESTART IDENTITY, cualquier secuencia que vaya a reiniciarse también se bloquea exclusivamente. Si se requiere acceso concurrente a una tabla, entonces se debe usar el comando DELETE en su lugar.

TRUNCATE no se puede usar en una tabla que tenga referencias de clave externa de otras tablas, a menos que todas las tablas de referencia también se trunquen en el mismo comando. La verificación de validez en tales casos requeriría escaneos de tabla, y el propósito principal es no hacerlo. La opción CASCADE se puede usar para incluir automáticamente todas las tablas dependientes, ¡pero tenga mucho cuidado al usar esta opción, o podría perder datos que no pretendía! Tenga en cuenta en particular que cuando la tabla a truncar es una partición, las particiones hermanas se dejan intactas, pero el efecto cascada ocurre en todas las tablas de referencia y todas sus particiones sin distinción.

TRUNCATE no activará ningún disparador ON DELETE que pueda existir para las tablas. Pero activará disparadores ON TRUNCATE. Si se definen disparadores ON TRUNCATE para alguna de las tablas, todos los disparadores BEFORE TRUNCATE se activarán antes de que ocurra cualquier truncamiento, y todos los disparadores AFTER TRUNCATE se activarán después de que se realice el último truncamiento y se restablezcan las secuencias. Los disparadores se activarán en el orden en que se procesarán las tablas (primero las listadas en el comando y luego las que se agregaron debido al efecto cascada).

TRUNCATE no es seguro para MVCC. Después del truncamiento, la tabla aparecerá vacía para las transacciones concurrentes, si están utilizando una instantánea tomada antes de que ocurriera el truncamiento. Consulte la Sección 13.6 para obtener más detalles.

TRUNCATE es seguro para transacciones con respecto a los datos en las tablas: el truncamiento se revertirá de forma segura si la transacción circundante no se confirma.

Cuando se especifica RESTART IDENTITY, las operaciones implícitas de ALTER SEQUENCE RESTART también se realizan transaccionalmente; es decir, se revertirán si la transacción circundante no se confirma. Tenga en cuenta que si se realizan operaciones de secuencia adicionales en las secuencias reiniciadas antes de que la transacción se revierta, los efectos de estas operaciones en las secuencias se revertirán, pero no sus efectos en currval(); es decir, después de la transacción, currval() continuará reflejando el último valor de secuencia obtenido dentro de la transacción fallida, aunque la secuencia en sí misma ya no sea consistente con ese valor. Esto es similar al comportamiento habitual de currval() después de una transacción fallida.

TRUNCATE se puede usar para tablas externas si es compatible con el manejador de datos externos, por ejemplo, vea postgres_fdw.

EJEMPLOS

Truncar las tablas bigtable y fattable:

TRUNCATE bigtable, fattable;

Lo mismo, y también restablecer cualquier generador de secuencias asociado:

TRUNCATE bigtable, fattable RESTART IDENTITY;

Truncar la tabla othertable, y aplicar el efecto cascada a las tablas que hagan referencia a othertable a través de restricciones de clave externa:

TRUNCATE othertable CASCADE;

COMPATIBILIDAD

El estándar SQL:2008 incluye un comando TRUNCATE con la sintaxis TRUNCATE TABLE nombre_tabla. Las cláusulas CONTINUE IDENTITY/RESTART IDENTITY también aparecen en ese estándar, pero tienen significados ligeramente diferentes aunque relacionados. Algunos del comportamiento de concurrencia de este comando se dejan definidos por la implementación por el estándar, por lo que las notas anteriores deben ser consideradas y comparadas con otras implementaciones si es necesario.
