NOMBRE

Try::Tiny - try/catch mínimo con preservación adecuada de $@

VERSIÓN

versión 0.32

SINOPSIS

Puedes usar los métodos "try" y "catch" de Try::Tiny para esperar y manejar condiciones excepcionales, evitando las peculiaridades de Perl y errores comunes:

# manejar errores con un manejador catch
try {
  die "foo";
} catch {
  warn "error capturado: $_"; # no es $@
};

También puedes usarlo como un "eval" independiente para capturar e ignorar cualquier condición de error. Obviamente, esta es una medida extrema que no debe tomarse a la ligera:

# simplemente silenciar errores
try {
  die "foo";
};

DESCRIPCIÓN

Este módulo proporciona declaraciones básicas de "try"/"catch"/"finally" que están diseñadas para minimizar errores comunes con bloques eval, y NADA MÁS.

A diferencia de TryCatch, que proporciona una sintaxis agradable y evita añadir otra capa de pila de llamadas, y soporta llamar a "return" desde el bloque "try" para regresar de la subrutina padre. Estas características adicionales tienen un costo de algunas dependencias, específicamente Devel::Declare y Scope::Upper, que ocasionalmente son problemáticas, y el filtrado catch adicional utiliza restricciones de tipo de Moose que pueden no ser deseables tampoco.

El enfoque principal de este módulo es proporcionar un manejo de errores simple y confiable para aquellos que tienen dificultades para instalar TryCatch, pero que aún desean escribir bloques "eval" correctos sin 5 líneas de código repetitivo cada vez.

Está diseñado para funcionar lo más correctamente posible a la luz de varios casos extremos patológicos (ver "ANTECEDENTES") y para ser compatible con cualquier estilo de valores de error (cadenas simples, referencias, objetos, objetos sobrecargados, etc.).

Si el bloque "try" falla (die), devuelve el valor de la última declaración ejecutada en el bloque "catch", si existe. De lo contrario, devuelve "undef" en contexto escalar o la lista vacía en contexto de lista. Los siguientes ejemplos asignan todos "bar" a $x:

my $x = try { die "foo" } catch { "bar" };
my $x = try { die "foo" } || "bar";
my $x = (try { die "foo" }) // "bar";
my $x = eval { die "foo" } || "bar";

Puedes añadir bloques "finally", resultando en lo siguiente:

my $x;
try { die 'foo' } finally { $x = 'bar' };
try { die 'foo' } catch { warn "Atrapado un die: $_" } finally { $x = 'bar' };

Los bloques "finally" siempre se ejecutan, haciéndolos adecuados para código de limpieza que no se puede manejar usando `local`. Puedes añadir tantos bloques "finally" a un bloque "try" dado como desees.

Ten en cuenta que añadir un bloque "finally" sin un bloque "catch" precedente suprime cualquier error. Este comportamiento es consistente con el uso de un "eval" independiente, pero no es consistente con los patrones "try"/"finally" que se encuentran en otros lenguajes de programación, como Java, Python, Javascript o C#. Si aprendiste el patrón "try"/"finally" de uno de estos lenguajes, ten cuidado con esto.

EXPORTACIONES

Todas las funciones se exportan por defecto usando Exporter.

Si necesitas renombrar las palabras clave "try", "catch" o "finally", considera usar Sub::Import para obtener la flexibilidad de Sub::Exporter.

try (&;@)
Toma una subrutina obligatoria "try", una subrutina opcional "catch" y una subrutina opcional "finally".

La subrutina obligatoria se evalúa en el contexto de un bloque "eval".

Si no ocurrió ningún error, se devuelve el valor del primer bloque, preservando el contexto de lista/escalar.

Si hubo un error y se proporcionó la segunda subrutina, se invocará con el error en $_ (localizado) y como el primer y único argumento de ese bloque.

$@ no contiene el error. Dentro del bloque "catch", tiene el mismo valor que tenía antes de que se ejecutara el bloque "try".

Ten en cuenta que el error puede ser falso, pero si eso sucede, el bloque "catch" aún se invocará.

Una vez que toda la ejecución haya terminado, el bloque "finally", si se proporciona, se ejecutará.

catch (&;@)
Destinado a ser utilizado en la segunda posición de argumento de "try".

Devuelve una referencia a la subrutina que se le dio, pero bendecida como "Try::Tiny::Catch", lo que permite a `try` decodificar correctamente qué hacer con este código de referencia.

catch { ... }

Dentro del bloque "catch", el error capturado se almacena en $_, mientras que el valor anterior de $@ todavía está disponible para su uso. Este valor puede ser significativo o no, dependiendo de lo que sucedió antes del bloque "try", pero podría ser una buena idea preservarlo en una pila de errores.

Para el código que captura $@ al lanzar nuevos errores (es decir, Class::Throwable), necesitarás hacer:

local $@ = $_;
finally (&;@)
try     { ... }
catch   { ... }
finally { ... };

O

try     { ... }
finally { ... };

O incluso

try     { ... }
finally { ... }
catch   { ... };

Destinado a ser el segundo o tercer elemento de "try". Los bloques "finally" siempre se ejecutan en caso de un "try" exitoso o si se ejecuta un "catch". Esto te permite ubicar código de limpieza que no se puede hacer a través de local(), por ejemplo, cerrar un manejador de archivo.

Cuando se invoca, al bloque "finally" se le pasa el error que fue capturado. Si no se capturó ningún error, no se le pasa nada. (Nota: el bloque "finally" no localiza $_ con el error, ya que, a diferencia de un bloque "catch", no hay forma de saber si "$_ == undef" implica que no hubo errores.) En otras palabras, el siguiente código hace exactamente lo que esperarías:

try {
  die_sometimes();
} catch {
  # ...código ejecutado en caso de error
} finally {
  if (@_) {
    print "El bloque try falló con: @_\n";
  } else {
    print "El bloque try se ejecutó sin error.\n";
  }
};

Siempre debes hacer tu propio manejo de errores en el bloque "finally". "Try::Tiny" no hará nada para manejar posibles errores provenientes del código ubicado en estos bloques.

Además, las excepciones en los bloques "finally" no son atrapables y no pueden influir en la ejecución de tu programa. Esto se debe a limitaciones de los "protectores de alcance" basados en "DESTROY", sobre los cuales está implementado "finally". Esto puede cambiar en una futura versión de Try::Tiny.

NOMBRE

Try - Simple, lightweight exception handling

VERSIÓN

0.23

SINOPSIS

    use Try;

    # Basic try/catch
    try {
        die "Something went wrong";
        1; # success value
    }
    catch {
        # $_ holds the error message (or the exception object)
        die "Failed: $_";
    };

    # You can catch specific exceptions
    try {
        require Foo;
    }
    catch ( MyError $e ) { # $e is the exception object
        # ...
    }
    catch ( MyOtherError ) { # $_ holds the exception object
        # ...
    };

    # finally block executes always
    try {
        # ...
    }
    catch {
        # ...
    }
    finally {
        # This always runs
    };

    # Or using the object API
    my $try = Try->new( sub { ... } );
    $try->catch( sub { ... } );
    $try->finally( sub { ... } );
    $try->run;

    # Or bless the return value of catch
    my $return_value = try {
      1;
    } catch {
      # $_ contains the exception message
      # die $_ # this would return undef
    };

    # blesses the code reference
    my $catch = sub {
      # $_ contains the exception
      my $err = $_;
      # You can die here, and the exception will be $err
      # Or you can return a value that will be blessed as Try::Tiny::Catch
      return bless { error => $err }, $class;
    };

    # You can use it in a list context
    my ($foo) = try {
        require Foo;
    } catch {
        # $_ is the error
        # $e is the error
    };

DESCRIPCIÓN

Este módulo proporciona una forma más segura y limpia de manejar excepciones que el uso directo del comando "eval" de Perl.

Su sintaxis es similar a la de otros lenguajes como Java o C#.

try BLOCK
El código dentro del bloque "try" se ejecuta en un contexto "eval". Si ocurre una excepción (un "die"), el bloque "try" captura la excepción y la pasa al bloque "catch". Si el bloque "try" se ejecuta sin excepciones, el bloque "catch" se omite y el valor de retorno del bloque "try" se convierte en el valor de retorno de la expresión "try".
catch BLOCK
Este bloque se ejecuta solo si ocurre una excepción dentro del bloque "try". La variable especial $_ contendrá el valor que fue pasado a "die" (o el objeto de excepción si se están usando módulos de excepción). Si el bloque "catch" se ejecuta sin excepciones, el valor de retorno del bloque "catch" se convierte en el valor de retorno de la expresión "try". Si se lanza una excepción dentro del bloque "catch", esta se propagará hacia arriba.
finally BLOCK
Este bloque se ejecuta siempre, independientemente de si ocurrió una excepción o no. Es útil para tareas de limpieza que deben realizarse sin importar el resultado del bloque "try".

El módulo también proporciona una API orientada a objetos:

  • Try->new( sub { ... } ): Crea un nuevo objeto Try y establece el bloque de código a ejecutar.
  • $try->catch( sub { ... } ): Establece el bloque catch.
  • $try->finally( sub { ... } ): Establece el bloque finally.
  • $try->run: Ejecuta el bloque try y maneja los bloques catch y finally. Devuelve el valor del bloque try si no hubo excepciones, o el valor del bloque catch si hubo una excepción.

Se puede usar la sintaxis de "catch" con argumentos para capturar tipos específicos de excepciones, similar a given/when o a la sintaxis de catch en otros lenguajes:

    try {
        # ...
    }
    catch ( qr/Error de red/ ) { # Captura si $_ coincide con la regex
        # ...
    }
    catch ( MyExceptionClass => my $e ) { # Captura si $_ es una instancia de MyExceptionClass
        # $e contendrá la instancia de la excepción
        # ...
    }
    catch { # Captura cualquier otra cosa
        # ...
    };

Si usas la forma "catch ( TYPE => VAR )", la variable VAR (en el ejemplo, $e) contendrá el objeto de excepción. Si usas solo la forma "catch ( TYPE )", el objeto de excepción estará en $_.

Si usas un bloque "catch" sin argumentos, este capturará cualquier excepción que no haya sido capturada por bloques "catch" anteriores.

El módulo Try también puede bendecir la referencia de código devuelta por un bloque catch como "Try::Tiny::Finally". Esto es útil si desea que el bloque catch devuelva un valor que se procesará posteriormente.

De manera similar a como catch() bendice la referencia de código, esta subrutina hace lo mismo excepto que las bendice como "Try::Tiny::Finally".

ANTECEDENTES

Hay una serie de problemas con "eval".

Sobrescribir $@

Cuando ejecutas un bloque "eval" y este tiene éxito, $@ se borrará, potencialmente sobrescribiendo un error que se está capturando actualmente.

Esto causa una acción a distancia, borrando errores previos que su llamador podría no haber manejado aún.

$@ debe ser localizado adecuadamente antes de invocar "eval" para evitar este problema.

Más específicamente, antes de la versión 5.14.0 de Perl, $@ se sobrescribía al principio del "eval", lo que también hacía imposible capturar el error anterior antes de morir (por ejemplo, al crear objetos de excepción con pilas de errores).

Por esta razón, "try" en realidad establecerá $@ a su valor anterior (el que estaba disponible antes de entrar al bloque "try") al principio del bloque "eval".

Localizar $@ silenciosamente oculta errores

Dentro de un bloque "eval", "die" se comporta de manera similar a:

sub die {
  $@ = $_[0];
  return_undef_from_eval();
}

Esto significa que si fuiste educado y localizaste $@, no puedes morir en ese ámbito, o tu error será descartado (imprimiendo "Algo va mal" en su lugar).

La solución es muy fea:

my $error = do {
  local $@;
  eval { ... };
  $@;
};
...
die $error;

$@ podría no ser un valor verdadero

Este código está mal:

if ( $@ ) {
  ...
}

porque debido a las advertencias anteriores, podría haber sido desestablecido.

$@ también podría ser un objeto de error sobrecargado que se evalúa como falso, pero eso es pedir problemas de todos modos.

El modo de fallo clásico (corregido en Perl 5.14.0) es:

sub Object::DESTROY {
  eval { ... }
}
eval {
  my $obj = Object->new;
  die "foo";
};
if ( $@ ) {
}

En este caso, dado que "Object::DESTROY" no localiza $@ pero aún usa "eval", establecerá $@ a "".

El destructor se llama cuando la pila se desenrolla, después de que "die" establece $@ a "foo at Foo.pm line 42\n", por lo que para cuando se evalúa "if ( $@ )", ha sido borrado por "eval" en el destructor.

La solución para esto es aún más fea que las anteriores. A pesar de que no podemos guardar el valor de $@ del código que no se localiza, al menos podemos estar seguros de que el "eval" fue abortado debido a un error:

my $failed = not eval {
  ...
  return 1;
};

Esto se debe a que un "eval" que capturó un "die" siempre devolverá un valor falso.

SINTAXIS ALTERNATIVA

Usando Perl 5.10 puedes usar "Switch statements" en perlsyn (pero por favor no lo hagas, ya que esa sintaxis ha sido deprecada porque había demasiados comportamientos mágicos inesperados).

El bloque "catch" se invoca en un contexto topicalizador (como un bloque "given"), pero ten en cuenta que no puedes devolver un valor útil desde "catch" usando los bloques "when" sin un "return" explícito.

Esto es algo similar a los bloques "CATCH" de Perl 6. Puedes usarlo para hacer coincidir errores de forma concisa:

try {
  require Foo;
} catch {
  when (/^Can't locate .*?\.pm in \@INC/) { } # ignorar
  default { die $_ }
};

ADVERTENCIAS

  • @_ no está disponible dentro del bloque "try", por lo que necesitas copiar tu lista de argumentos. En caso de que quieras trabajar con los valores de los argumentos directamente a través de alias de @_ (es decir, permitir "$_[1] = "foo""), necesitas pasar @_ por referencia: 
    sub foo {
  my ( $self, @args ) = @_;
  try { $self->bar(@args) }
}

    o

    sub bar_in_place {
  my $self = shift;
  my $args = \@_;
  try { $_ = $self->bar($_) for @$args }
}
  • "return" retorna desde el bloque "try", no desde la subrutina padre (ten en cuenta que así es como funciona "eval", pero no cómo funciona TryCatch): 
    sub parent_sub {
  try {
    die;
  }
  catch {
    return;
  };
  say "este texto SÍ se mostrará, aunque se lance una excepción";
}

    En su lugar, deberías capturar el valor de retorno:

    sub parent_sub {
  my $success = try {
    die;
    1;
  };
  return unless $success;
  say "Este texto NUNCA aparecerá!";
}
# O
sub parent_sub_with_catch {
  my $success = try {
    die;
    1;
  }
  catch {
    # haz algo con $_
    return undef; # ver nota
  };
  return unless $success;
  say "Este texto NUNCA aparecerá!";
}

    Ten en cuenta que si tienes un bloque "catch", debe devolver "undef" para que esto funcione, ya que si existe un bloque "catch", su valor de retorno se devuelve en lugar de "undef" cuando se lanza una excepción.

  • "try" introduce otro marco de pila del llamador. No se utiliza Sub::Uplevel. Carp no lo informará al usar rastros de pila completos, porque se utiliza %Carp::Internal. Esta falta de magia se considera una característica.
  • No se garantiza que el valor de $_ en el bloque "catch" sea el valor de la excepción lanzada ($@) en el bloque "try". No hay una forma segura de garantizar esto, ya que "eval" puede ser utilizado de forma poco higiénica en destructores. La única garantía es que el bloque "catch" se llamará si se lanza una excepción.
  • El valor de retorno del bloque "catch" no se ignora, por lo que si se prueba la verdad del resultado de la expresión en caso de éxito, asegúrate de devolver un valor falso desde el bloque "catch": 
    my $obj = try {
  MightFail->new;
} catch {
  ...
  return; # evitar devolver un valor verdadero;
};
return unless $obj;
  • $SIG{__DIE__} todavía está en vigor.

    Aunque se puede argumentar que $SIG{__DIE__} debería estar deshabilitado dentro de los bloques "eval", dado que no lo está, la gente se ha acostumbrado a depender de él. Por lo tanto, en aras de la compatibilidad, "try" no deshabilita $SIG{__DIE__} para el ámbito del código que lanza errores.

  • El $_ léxico puede anular el establecido por "catch".

    Por ejemplo, la forma "given" de Perl 5.10 utiliza un $_ léxico, creando un comportamiento confuso:

    given ($foo) {
  when (...) {
    try {
      ...
    } catch {
      warn $_; # imprimirá $foo, no el error
      warn $_[0]; # en su lugar, obtén el error así
    }
  }
}

    Ten en cuenta que este comportamiento se cambió una vez más en la versión 18 de Perl5 https://metacpan.org/module/perldelta#given-now-aliases-the-global-_. Sin embargo, dado que la totalidad del $_ léxico se considera ahora experimental
    https://metacpan.org/module/perldelta#Lexical-_-is-now-experimental, no está claro si el nuevo comportamiento de la versión 18 es definitivo.

VER TAMBIÉN

Syntax::Keyword::Try
Solo disponible en perls >= 5.14, con una sintaxis ligeramente diferente (por ejemplo, sin ";" al final porque es realmente una palabra clave, no una subrutina, pero esto significa que puedes "return" y "next" dentro de ella). Usa Feature::Compat::Try para cambiar automáticamente a la sintaxis nativa de "try" en perls más recientes (cuando esté disponible). Ver también Try Catch Exception Handling.
TryCatch
Semántica mucho más completa y conveniente, pero a costa de la complejidad de implementación.
autodie
Lanzamiento automático de errores para funciones integradas y más. También diseñado para funcionar bien con "given"/"when".
Throwable
Un rol ligero para crear tus propias clases de excepción.
Error
Implementación de objetos de excepción con una declaración "try". No localiza $@.
Exception::Class::TryCatch
Una forma más orientada a objetos de manejar excepciones, que a menudo se utiliza con Syntax::Keyword::Try.

CAVEATS

Exception::Class::TryCatch
Proporciona una declaración "catch", pero es tu responsabilidad llamar correctamente a "eval".

La palabra clave "try" empuja $@ a una pila de errores, evitando algunos de los problemas con $@, pero aún necesitas localizar para evitar sobrescrituras.
