NAME

Term::ReadLine::Gnu - Perl extension for the GNU Readline/History library

SYNOPSIS

use Term::ReadLine;   # Don't use Term::ReadLine::Gnu;
$term = new Term::ReadLine 'ProgramName';
while ( defined ($_ = $term->readline('prompt>')) ) {
  ...
}

DESCRIPTION

Overview

This is an implementation of Term::ReadLine http://search.cpan.org/dist/Term-ReadLine/ using the GNU Readline/History Library https://tiswww.cwru.edu/php/chet/readline/rltop.html.

It provides an object oriented interface to basic functions. These functions are described in the section titled "Standard Methods" and "Term::ReadLine::Gnu Functions".

This package also has the interface to almost all functions and variables documented in the GNU Readline/History Library. These functions and variables are described in the section titled "Term::ReadLine::Gnu Functions" and "Term::ReadLine::Gnu Variables" briefly. For details about the GNU Readline/History Library, consult the GNU Readline Library Manual https://tiswww.cwru.edu/php/chet/readline/readline.html and the GNU History Library Manual https://tiswww.cwru.edu/php/chet/readline/history.html.

Some original features of Term::ReadLine::Gnu are described in the section titled "Term::ReadLine::Gnu Specific Features".

The example programs in the eg/ directory and the test programs in the t/ directory of the Term::ReadLine::Gnu distribution contain many examples of this library. Consult eg/README.md for details about the eg/ directory.

Standard Methods

These are the standard methods defined in Term::ReadLine http://search.cpan.org/dist/Term-ReadLine/.

"ReadLine"
returns the package that executes the commands. If this package is being used, "Term::ReadLine::Gnu" is returned.
"new(NAME,[IN,OUT])"
returns the handle for subsequent calls to the following functions. The argument is the name of the program. Optionally it can be followed by two arguments for "IN" and "OUT" filehandles. These arguments should be globals.
"readline(PROMPT[,PREPUT])"
gets an input line, with real "GNU Readline" support. The input line is stripped of trailing newline. It returns "undef" in case of "EOF". "PREPUT" is an optional argument which represents the initial value of the input.
"AddHistory(LINE1, LINE2, ...)"
adds the lines to the input history, from where they can be used if the real "readline" package is present.
"IN", "OUT"
returns the input and output filehandles or "undef" if the "readline" package cannot be used for Perl.
MinLine([MAX])
If the argument "MAX" is specified, it is a hint about the minimum size of line to include into the history. "undef" means to include nothing into the history. It returns the previous value.
"findConsole"
returns an array of two strings which give the most suitable names for the input and output files using the conventions "<$in", ">$out".
"Attribs"
returns a reference to a hash which describes the internal settings of the package. The names of the keys in this hash follow standard conventions, with the prefix "rl_" stripped off.
"Features"
returns a reference to a hash with the keys representing features present in the current implementation. Some optional features are used in the minimal interface: "appname" should be present if the first argument to the "new" method is recognized, and "minline" should be present if the "MinLine" method is not a dummy. "autohistory" should be present if lines are automatically added to the history ("MinLine"), and "AddHistory" if the "AddHistory" method is not a dummy. "preput" means the second argument to the "readline" method is processed. "getHistory" and "setHistory" indicate that the corresponding methods are available. "tkRunning" indicates that a Tk application may run while Readline is reading input.
"tkRunning"
makes the Tk event loop run when it is waiting for user input (i.e. during the "readline" method).
"event_loop"
see the description of the "event_loop" method in Term::ReadLine http://search.cpan.org/dist/Term-ReadLine/.
"ornaments"
makes the command line stand out using termcap data. The argument to "ornaments" should be 0, 1, or a string of the format "aa,bb,cc,dd". The four components of this string should be names of terminal capabilities, the first two are emitted to make the prompt stand out, the last two to make the input line stand out.
"newTTY"
will take two arguments which are the input and output filehandles. It will switch to using these filehandles.
"enableUTF8"
enables UTF-8 support. If the input file is in UTF-8 either by the command line parameter "-C" or by the environment variable "PERL_UNICODE", or if the "IN" filehandle has an input layer with "utf8", then UTF-8 support is also enabled. In other cases, you need to use the "enableUTF8" method.

This is an original method of Term::ReadLine:Gnu.

"Term::ReadLine::Gnu" Functions

All these functions of the GNU Readline/History Library can be called through the method interface and have names following standard conventions with the prefix "rl_" stripped off. For example, the function rl_foo() is called like "$term->foo()".

The headings of the following sections are the same as those in the corresponding sections of the GNU Readline Library chapter "Programming with GNU Readline".

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

Manual de Readline https://tiswww.cwru.edu/php/chet/readline/readline.html. Consúltelos para obtener más detalles.

Aunque se prefiere usar la interfaz de métodos, la mayoría de los métodos tienen funciones de nivel inferior en el paquete "Term::ReadLine::Gnu::XS". Para usarlas, se requiere un nombre completo calificado.

Comportamiento Básico

La función readline() imprime un prompt y luego lee y devuelve una sola línea de texto del usuario.

$_ = $term->readline('Introduce una línea: ');

Puede cambiar las asignaciones de teclas usando la función "bind_key(TECLA, FUNCION [,MAPA])". El primer argumento, "TECLA", es el carácter que desea enlazar. El segundo argumento, "FUNCION", es la función a llamar cuando se presiona "TECLA". La "FUNCION" puede ser una referencia a una función de Perl (ver "Funciones Personalizadas") o una "función nombrada" denominada por la función add_defun() o comandos descritos en la sección "Comandos Enlazables de Readline" del Manual de la Biblioteca GNU Readline https://tiswww.cwru.edu/php/chet/readline/readline.html.

$term->bind_key(ord "\ci, 'tab-insert');

El ejemplo anterior enlaza Control-I al comando 'tab-insert'.

Funciones Personalizadas

Puede escribir nuevas funciones usando Perl. La secuencia de llamada para un comando foo se ve así:

sub foo ($count, $key) { ... }

donde $count es el argumento numérico (o 1 si se omite) y $key es la tecla que invocó esta función.

Aquí hay un ejemplo;

sub reverse_line {              # invierte una línea completa
    my($count, $key) = @_;      # ignorado en esta función de ejemplo
    $t->modifying(0, $a->{end}); # guarda la información de deshacer
    $a->{line_buffer} = reverse $a->{line_buffer};
}

Consulte la sección "Escribir una Nueva Función" del Manual de la Biblioteca GNU Readline https://tiswww.cwru.edu/php/chet/readline/readline.html para más detalles.

Agrega un nombre a una función de Perl "FUNCION". Si se especifica el argumento opcional "TECLA", enlácelo a la "FUNCION". Devuelve una referencia a "FunctionPtr".

      $term->add_defun('reverse-line', \&reverse_line, ord "\ct");

Gestión del Archivo del Historial

"ReadHistory([FILENAME [,FROM [,TO]]])"
int     read_history(str filename = '~/.history',
                     int from = 0, int to = -1)
int     read_history_range(str filename = '~/.history',
                           int from = 0, int to = -1)

añade el contenido de "FILENAME" a la lista del historial, una línea a la vez. Si "FILENAME" está vacío, entonces lee desde ~/.history. Comienza a leer en la línea "FROM" y termina en "TO". Si "FROM" se omite o es cero, comienza desde el principio. Si "TO" se omite o es menor que "FROM", entonces lee hasta el final del archivo. Devuelve verdadero si tiene éxito, o falso si no. read_history() es un alias de read_history_range().

WriteHistory([NOMBRE_ARCHIVO])
int     write_history(str filename = '~/.history')

escribe el historial actual en "NOMBRE_ARCHIVO", sobrescribiendo "NOMBRE_ARCHIVO" si es necesario. Si "NOMBRE_ARCHIVO" está vacío, entonces escribe la lista del historial en ~/.history. Devuelve verdadero si tiene éxito, o falso si no.

Completado Personalizado

En esta sección se describen variables y funciones para completado personalizado junto con ejemplos.

La mayoría de las descripciones en esta sección provienen del Manual de la Biblioteca GNU Readline https://tiswww.cwru.edu/php/chet/readline/readline.html.

"completion_entry_function"
Esta variable contiene una referencia a una función generadora para completion_matches().

Una función generadora es llamada repetidamente desde completion_matches(), devolviendo una cadena cada vez. Los argumentos para la función generadora son "TEXT" y "STATE". "TEXT" es la palabra parcial a completar. "STATE" es cero la primera vez que se llama a la función, permitiendo a la generadora realizar cualquier inicialización necesaria, y un entero positivo distinto de cero para cada llamada subsiguiente. Cuando la función generadora devuelve "undef", esto señala a completion_matches() que no quedan más posibilidades.

Si esta variable se establece en undef, se utiliza la "filename_completion_function" integrada.

Una función generadora de ejemplo, "list_completion_function", está definida en Gnu.pm. Puedes usarla de la siguiente manera:

use Term::ReadLine;
...
my $term = new Term::ReadLine 'sample';
my $attribs = $term->Attribs;
...
$attribs->{completion_entry_function} =
    $attribs->{list_completion_function};
...
$attribs->{completion_word} =
    [qw(referencia a una lista de palabras que deseas usar para completado)];
$term->readline("completado personalizado>");

Ver también "completion_matches".

"attempted_completion_function"
Una referencia a una función alternativa para crear coincidencias.

La función se llama con "TEXT", "LINE_BUFFER", "START", y "END". "LINE_BUFFER" es una cadena de búfer de entrada actual. "START" y "END" son índices en "LINE_BUFFER" que indican los límites de "TEXT".

Si esta función existe y devuelve una lista nula o "undef", o si esta variable se establece en "undef", entonces una función interna rl_complete() llamará al valor de "completion_entry_function" para generar coincidencias, de lo contrario se usará la matriz de cadenas devuelta.

El valor predeterminado de esta variable es "undef". Puedes usarla de la siguiente manera:

use Term::ReadLine;
...
my $term = new Term::ReadLine 'sample';
my $attribs = $term->Attribs;
...
sub sample_completion {
    my ($text, $line, $start, $end) = @_;
    # Si es la primera palabra, entonces completado de nombre de usuario, de lo contrario completado de nombre de archivo
    if (substr($line, 0, $start) =~ /^\s*$/) {
        return $term->completion_matches($text,
                                         $attribs->{'username_completion_function'});
    } else {
        return ();
    }
}
...
$attribs->{attempted_completion_function} = \&sample_completion;
"completion_matches(TEXT, ENTRY_FUNC)"
Devuelve una matriz de cadenas que es una lista de completados para "TEXT". Si no hay completados, devuelve "undef". La primera entrada en la matriz devuelta es la sustitución para "TEXT". Las entradas restantes son los completados posibles.

"ENTRY_FUNC" es una función generadora que tiene dos argumentos y devuelve una cadena. El primer argumento es "TEXT". El segundo es un argumento de estado; es cero en la primera llamada y distinto de cero en llamadas subsiguientes. "ENTRY_FUNC" devuelve "undef" al llamador cuando no hay más coincidencias.

Si el valor de "ENTRY_FUNC" es undef, se utiliza la "filename_completion_function" integrada.

"completion_matches" es una función envoltorio de Perl de una función interna completion_matches(). Ver también "completion_entry_function".

"completion_function"
Una variable cuyo contenido es una referencia a una función que devuelve una lista de candidatos para completar.

Esta variable es compatible con Term::ReadLine::Perl http://search.cpan.org/dist/Term-ReadLine-Perl/ y es muy fácil de usar.

use Term::ReadLine;
...
my $term = new Term::ReadLine 'sample';
my $attribs = $term->Attribs;
...
$attribs->{completion_function} = sub {
    my ($text, $line, $start) = @_;
    return qw(una lista de candidatos para completar);
};
"list_completion_function(TEXT, STATE)"
Una función generadora de ejemplo definida por "Term::ReadLine::Gnu". El código de ejemplo en "completion_entry_function" muestra cómo usar esta función.

ARCHIVOS

~/.inputrc
Archivo de inicialización de Readline. Usando este archivo es posible que desees utilizar un conjunto diferente de asignaciones de teclas. Cuando un programa que utiliza la biblioteca GNU Readline se inicia, se lee el archivo de inicialización y se establecen las asignaciones de teclas.

Se admiten las construcciones condicionales de inicialización. El nombre del programa que se especifica mediante el primer argumento del método "new" se utiliza como la construcción de la aplicación.

Por ejemplo, cuando tu programa llama al método "new" de la siguiente manera:

...
$term = new Term::ReadLine 'PerlSh';
...

tu ~/.inputrc puede definir asignaciones de teclas solo para el programa de la siguiente manera:

...
$if PerlSh
Meta-Rubout: backward-kill-word
"\C-x\C-r": re-read-init-file
"\e[11~": "Function Key 1"
$endif
...

Para más detalles, consulta la sección "Readline Init File" en el Manual de la Biblioteca GNU Readline https://tiswww.cwru.edu/php/chet/readline/readline.html
