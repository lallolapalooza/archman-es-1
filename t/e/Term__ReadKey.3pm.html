NOMBRE

Term::ReadKey - Un módulo de Perl para control simple de terminal

SINOPSIS

use Term::ReadKey;
ReadMode 4; # Desactivar teclas de control
while (not defined ($key = ReadKey(-1))) {
    # Todavía no hay tecla
}
print "Obtuve la tecla $key\n";
ReadMode 0; # Restablecer el modo tty antes de salir

DESCRIPCIÓN

Term::ReadKey es un módulo compilado de Perl dedicado a proporcionar un control simple sobre los modos del controlador de terminal (cbreak, raw, cooked, etc.), soporte para lecturas no bloqueantes, si la arquitectura lo permite, y algunas funciones prácticas generalizadas para trabajar con terminales. Uno de los objetivos principales es que las funciones sean lo más portátiles posible, para que pueda simplemente usar "use Term::ReadKey" en cualquier arquitectura y tener una buena probabilidad de que funcione.

Versión 2.30.01: Se agregó manejo de teclas de flecha, avance/retroceso de página, inicio/fin, inserción/eliminación bajo Win32. Estas teclas emiten secuencias compatibles con xterm. Funciona con Term::ReadLine::Perl.

ReadMode MODO [, ArchivoHandle]
Toma un argumento entero o un sinónimo de cadena (sin distinción entre mayúsculas y minúsculas), que actualmente puede ser uno de los siguientes valores: 
ENTERO  SINÓNIMO    DESCRIPCIÓN
0    'restore'   Restaurar configuraciones originales.
1    'normal'    Cambiar a lo que comúnmente es el modo predeterminado,
                 eco activado, con búfer, señales habilitadas, Xon/Xoff
                 posiblemente habilitado, y modo de 8 bits posiblemente
                 deshabilitado.
2    'noecho'    Igual que 1, solo que con eco desactivado. Útil para
                 leer contraseñas.
3    'cbreak'    Eco desactivado, sin búfer, señales habilitadas, Xon/Xoff
                 posiblemente habilitado, y modo de 8 bits posiblemente
                 habilitado.
4    'raw'       Eco desactivado, sin búfer, señales deshabilitadas, Xon/Xoff
                 deshabilitados, y modo de 8 bits posiblemente deshabilitado.
5    'ultra-raw' Eco desactivado, sin búfer, señales deshabilitadas, Xon/Xoff
                 deshabilitados, modo de 8 bits habilitado si la paridad lo
                 permite, y traducción de CR a CR/LF desactivada.

Estas funciones se aplican automáticamente al manejador STDIN si no se proporciona otro manejador. Los modos 0 y 5 tienen propiedades especiales que vale la pena mencionar: el modo 0 no solo restaurará las configuraciones originales, sino que hará que la próxima llamada a ReadMode guarde un nuevo conjunto de configuraciones predeterminadas. El modo 5 es similar al modo 4, excepto que no se realiza ninguna traducción CR/LF, y si es posible, la paridad se deshabilitará (solo si no la está utilizando la terminal; no es diferente del modo 4 en Windows).

Si solo necesita leer una tecla a la vez, los modos 3 o 4 probablemente sean suficientes. El modo 4 es un poco más flexible, pero requiere un poco más de trabajo para controlarlo. Si usa ReadMode 3, debería instalar un manejador SIGINT o END para restablecer la terminal (a través de ReadMode 0) si el usuario aborta el programa con "^C". (Para cualquier modo, un manejador END que consista en "ReadMode 0" es en realidad una buena idea.)

Si está ejecutando otro programa que puede estar cambiando el modo de la terminal, querrá decir:

ReadMode 1;             # igual que ReadMode 'normal'
system('someprogram');
ReadMode 1;

que restablece la configuración después de que el programa se ha ejecutado, o:

$somemode=1;
ReadMode 0;             # igual que ReadMode 'restore'
system('someprogram');
ReadMode 1;

que registra cualquier cambio que el programa pueda haber hecho, antes de restablecer el modo.

ReadKey MODO [, ArchivoHandle]
Toma un argumento entero, que actualmente puede ser uno de los siguientes valores: 
0    Realizar una lectura normal usando getc
-1   Realizar una lectura no bloqueante
>0   Realizar una lectura con tiempo de espera

Si no se proporciona el manejador de archivo, se usará STDIN por defecto. Si no hay nada esperando en el búfer durante una lectura no bloqueante, se devolverá undef. En la mayoría de las situaciones, probablemente querrá usar "ReadKey -1".

NOTA que si el sistema operativo no proporciona ningún mecanismo conocido para lecturas no bloqueantes, una "ReadKey -1" puede fallar con un error fatal. Se espera que esto no sea común.

Si MODO es mayor que cero, entonces ReadKey lo usará como un valor de tiempo de espera en segundos (se permiten segundos fraccionales), y no devolverá "undef" hasta que expire ese tiempo.

NOTA, nuevamente, que algunos sistemas operativos pueden no admitir este comportamiento de tiempo de espera.

Si MODO es menor que cero, entonces se trata como un tiempo de espera de cero, y por lo tanto devolverá inmediatamente si no hay ningún carácter esperando. Sin embargo, un MODO de cero actuará como un getc normal.

NOTA, actualmente existen algunas limitaciones con esta llamada en Windows. Puede ser posible que las lecturas no bloqueantes fallen al leer teclas repetidas de más de una consola.

ReadLine MODO [, ArchivoHandle]
Toma un argumento entero, que actualmente puede ser uno de los siguientes valores: 
0    Realizar una lectura normal usando scalar(<ArchivoHandle>)
-1   Realizar una lectura no bloqueante
>0   Realizar una lectura con tiempo de espera

Si no hay nada esperando en el búfer durante una lectura no bloqueante, se devolverá undef.

NOTA, que si el sistema operativo no proporciona ningún mecanismo conocido para lecturas no bloqueantes, una "ReadLine 1" puede fallar con un error fatal. Se espera que esto no sea común.

NOTA que solo se realiza una prueba no bloqueante para el primer carácter de la línea, no para la línea completa. Esta llamada probablemente **no** hará lo que usted supone, especialmente con los valores de modo "ReadMode" mayores que 1. Por ejemplo, presionar Espacio y luego Retroceso parecería dejarle en el mismo lugar, pero los tiempos de espera ahora estarían suspendidos.

**Esta llamada actualmente no está disponible en Windows**.

GetTerminalSize [ArchivoHandle]
Devuelve un array vacío si esta operación no es compatible, o un array de cuatro elementos que contiene: el ancho de la terminal en caracteres, la altura de la terminal en caracteres, el ancho en píxeles y la altura en píxeles. (El tamaño en píxeles solo será válido en algunos entornos).

NOTA, en Windows, esta función debe llamarse con un manejador de archivo de **salida**, como "STDOUT", o un manejador abierto a "CONOUT$".

SetTerminalSize ANCHO,ALTO,XPIX,YPIX [, ArchivoHandle]
Devuelve -1 en caso de fallo, 0 en caso contrario.

NOTA que este tamaño de terminal es solo de valor **informativo**, y cambiar el tamaño a través de este mecanismo **no** cambiará el tamaño de la pantalla. Por ejemplo, XTerm usa una llamada como esta cuando redimensiona la pantalla. Si alguna de las nuevas mediciones varía de las antiguas, el sistema operativo probablemente enviará una señal SIGWINCH a cualquier cosa que lea ese tty o pty.

**Esta llamada no funciona en Windows**.

GetSpeed [, ArchivoHandle]
Devuelve un array vacío si la operación no es compatible, o un array de dos valores que contiene las velocidades de entrada y salida de la terminal, en **decimal**. Por ejemplo, una velocidad de entrada de 9600 baudios y una velocidad de salida de 4800 baudios se devolverían como (9600,4800). Tenga en cuenta que actualmente las velocidades de entrada y salida siempre serán idénticas en algunos sistemas operativos.

**No se informan velocidades en Windows**.

GetControlChars [, ArchivoHandle]
Devuelve un array que contiene pares clave/valor adecuados para un hash. Los pares consisten en una clave, el nombre del carácter/señal de control y el valor de ese carácter, como un solo carácter.

**Esta llamada no hace nada en Windows**.

Cada clave será una entrada de la siguiente lista:

DISCARD
DSUSPEND
EOF
EOL
EOL2
ERASE
ERASEWORD
INTERRUPT
KILL
MIN
QUIT
QUOTENEXT
REPRINT
START
STATUS
STOP
SUSPEND
SWITCH
TIME

Por lo tanto, lo siguiente siempre devolverá el carácter de interrupción actual, independientemente de la plataforma.

%keys = GetControlChars;
$int = $keys{INTERRUPT};

Term::ReadKey(3pm)

NAME

Term::ReadKey – Provide control over terminal keys

SYNOPSIS

    use Term::ReadKey;

    # Initialise
    ReadMode(3); # Sets the terminal to raw mode, turns off echo, and
                 # turns off line buffering.

    # Get a character
    my $char = ReadKey(0); # Reads a single character without blocking.

    # Get a character with a timeout
    my $char = ReadKey(1); # Reads a single character with a 1 second timeout.

    # Reset terminal settings
    ReadMode(0); # Resets the terminal to its original settings.

    # Get control characters
    my %cchars = GetControlChars();
    my @cnames = keys %cchars;

    # Set control characters
    SetControlChars(Break => "\cZ", Inof => "\cQ");

DESCRIPTION

This module provides an interface to the underlying terminal driver's control character handling, and provides an interface to read single characters from the terminal.

The module defines the following functions:

ReadMode(mode)
Sets the terminal driver to the specified mode. The following modes are supported:
    0 - Reset terminal to its original settings.
    1 - Set terminal to cbreak mode.
    2 - Set terminal to raw mode.
    3 - Set terminal to raw mode, turn off echo, and turn off line buffering.

All modes other than 0 will attempt to store the current terminal settings and restore them when the program exits or when ReadMode(0) is called.

Mode 3 is the most useful for interactive programs, as it allows characters to be read as soon as they are typed, without requiring the user to press Enter, and without echoing the characters to the screen.

This call does nothing under Windows.

ReadKey(timeout)
Reads a single character from the terminal. If timeout is 0, the function will not block. If timeout is greater than 0, the function will block for that many seconds waiting for input. If no input is received within the timeout period, undef is returned. If a character is read, it is returned as a single-character string. Control characters are returned as their character representation, e.g. "\cM" for carriage return. Function keys and other special keys will return multi-character escape sequences. These can be detected by checking if the returned string starts with "\e[".

SetControlChars(%hashref)
Allows you to change the value of one or more control characters. The argument should be a hashref where the keys are the names of the legal control character/signal, and the value should be either a single character, or a number in the range 0-255. SetControlChars will die with a runtime error if an invalid character name is passed or there is an error changing the settings. The list of valid names is easily available via 
%cchars = GetControlChars();
@cnames = keys %cchars;

This call does nothing under Windows.
