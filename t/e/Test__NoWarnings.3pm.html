Test::NoWarnings(3) Documentación de Perl aportada por el usuario Test::NoWarnings(3)

NOMBRE

Test::NoWarnings - Asegúrate de que no has emitido ninguna advertencia mientras pruebas

SINOPSIS

Para scripts que no tienen un plan

use Test::More 'no_plan';
use Test::NoWarnings;

eso es todo, no necesitas hacer nada más

Para scripts que se ven así

use Test::More tests => x;

cambia a

use Test::More tests => x + 1;
use Test::NoWarnings;

Para scripts que usan done_testing, usa:

use Test::More;
use Test::NoWarnings 'had_no_warnings';
... # tus pruebas reales
had_no_warnings;
done_testing;

DESCRIPCIÓN

En general, tus pruebas no deberían producir advertencias. Este módulo hace que cualquier advertencia sea capturada y almacenada. Añade automáticamente una prueba adicional que se ejecutará al final de tu script para comprobar que no hubo advertencias. Si hubo alguna advertencia, la prueba dará un "not ok" y diagnósticos de dónde, cuándo y qué fue la advertencia, incluyendo un rastreo de la pila de lo que estaba sucediendo cuando ocurrió.

Si algunas de tus pruebas se supone que deben producir advertencias, entonces deberías capturarlas y verificarlas con Test::Warn, de esa manera Test::NoWarnings no las verá y por lo tanto no se quejará.

La prueba se ejecuta mediante un bloque "END" en Test::NoWarnings. No se ejecutará cuando hijos creados con fork salgan.

USO

Simplemente al usar el módulo, obtienes automáticamente una prueba adicional al final de tu script que comprueba que no se emitieron advertencias. Así que solo pega

use Test::NoWarnings;

al principio de tu script y continúa como normal.

Si quieres más control puedes invocar la prueba manualmente en cualquier momento con "had_no_warnings".

Las advertencias que tu prueba ha generado hasta ahora se almacenan en un array. Puedes examinarlo y limpiarlo cuando quieras con warnings() y "clear_warnings", sin embargo, si estás haciendo este tipo de cosas entonces probablemente querrás usar Test::Warn en combinación con Test::NoWarnings.

Si tienes un script de prueba escrito usando done_testing y sin plan de pruebas, tienes que llamar "had_no_warnings" antes de llamar a done_testing.

use vs require

Casi siempre querrás hacer

use Test::NoWarnings;

Si haces un "require" en lugar de un "use", entonces no habrá una prueba automática al final de tu script.

Salida

Si se captura una advertencia durante tu prueba, los detalles se emitirán como parte de los diagnósticos. Obtendrás:

  • el número y nombre de la prueba que se ejecutó justo antes de la advertencia (si no se había ejecutado ninguna prueba, estos serán 0 y '')
  • el mensaje pasado a "warn",
  • un volcado completo de la pila cuando se llamó a warn, cortesía del módulo "Carp"

Por defecto, todos los mensajes de advertencia se emitirán en un bloque al final de tu script de prueba.

El pragma :early

Una queja común de las personas que usan Test::NoWarnings es que todas las advertencias se emiten de una vez al final. Si bien este es el momento más seguro y correcto para emitir estos diagnósticos, puede dificultar la depuración de estas advertencias.

Desde Test::NoWarnings 1.04 puedes proporcionar un pragma experimental ":early" al cargar el módulo para forzar que las advertencias se lancen a través de diag en el momento en que ocurren realmente.

use Test::NoWarnings ':early';

Como esto provocará que el diag se emita contra la prueba anterior y no contra la en la que ocurrió realmente la advertencia, se recomienda que el pragma se active solo para depuración y se deje desactivado cuando no sea necesario.

FUNCIONES

had_no_warnings

Esto comprueba que no se han emitido advertencias por tus scripts de prueba. Normalmente no llamarás a esto explícitamente, ya que se llama automáticamente cuando tu script finaliza.

clear_warnings

Esto limpiará el array de advertencias que se han capturado. Si el array está vacío, una llamada a had_no_warnings() producirá un resultado de paso.

warnings

Esto devolverá el array de advertencias capturadas hasta ahora. Cada elemento de este array es un objeto que contiene información sobre la advertencia. Los siguientes métodos están disponibles en estos objetos.

  • $warn->getMessage

    Obtener el mensaje que se habría impreso por la advertencia.

  • $warn->getCarp

    Obtener un rastreo de la pila de lo que estaba sucediendo cuando ocurrió la advertencia, este rastreo de la pila es solo una cadena generada por el módulo Carp.

  • $warn->getTrace

    Obtener un objeto de rastreo de la pila generado por el módulo Devel::StackTrace. Devolverá undef si Devel::StackTrace no está instalado.

  • $warn->getTest

    Obtener el número de la prueba que se ejecutó antes de que se emitiera la advertencia.

  • $warn->getTestName

    Obtener el nombre de la prueba que se ejecutó antes de que se emitiera la advertencia.

TRAMPAS

Al contar tus pruebas para el plan, no olvides incluir la prueba que se ejecuta automáticamente cuando tu script finaliza.

La comprobación de advertencias se realiza utilizando $SIG{__WARN__}. Si otros módulos usan este gancho, puede interferir con el funcionamiento de este módulo. Por ejemplo, usar el módulo Carp::Always hará que este módulo informe siempre de cero advertencias.
