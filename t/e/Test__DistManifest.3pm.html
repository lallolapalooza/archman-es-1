Test::DistManifest(3pm) Documentación de Perl contribuida por el usuario Test::DistManifest(3pm)

NOMBRE

Test::DistManifest - Prueba de autor que valida el MANIFEST de un paquete

VERSIÓN

versión 1.014

SINOPSIS

Este es el modismo común para módulos de prueba de autor como este, pero vea el ejemplo completo en examples/checkmanifest.t y, lo que es más importante, el artículo de Adam Kennedy: http://use.perl.org/use.perl.org/_Alias/journal/38822.html

use Test::More;
eval 'use Test::DistManifest';
if ($@) {
  plan skip_all => 'Se requiere Test::DistManifest para probar MANIFEST';
}
manifest_ok('MANIFEST', 'MANIFEST.SKIP'); # Opciones por defecto
manifest_ok(); # Funcionalmente equivalente a lo anterior

DESCRIPCIÓN

Este módulo proporciona un método simple para probar que un MANIFEST coincide con la distribución.

Prueba tres cosas:

EXPORTACIONES

Por defecto, este módulo exporta las siguientes funciones:

•
manifest_ok
1.
Todo en MANIFEST existe
2.
Todo en el paquete está listado en MANIFEST, o coincide subsiguientemente con una máscara de expresión regular en MANIFEST.SKIP
3.
Nada existe en MANIFEST que también coincida con una máscara en MANIFEST.SKIP, para evitar condiciones de dependencia insatisfechas

Si no se incluye ningún MANIFEST.SKIP en su distribución, este módulo replicará el comportamiento de la cadena de herramientas de usar el archivo MANIFEST.SKIP predeterminado a nivel de sistema. Para ver el contenido de este archivo, use el comando:

$ perldoc -m ExtUtils::MANIFEST.SKIP

FUNCIONES

manifest_ok

manifest_ok( $manifest, $skipfile )

Esta subrutina verifica la lista de manifiestos contenida en $manifest usando "Module::Manifest" para determinar la lista de archivos y luego verifica la existencia de todos esos archivos. Luego, verifica si hay archivos en la distribución que no fueron especificados en el archivo $manifest pero que no coinciden con ninguna expresión regular proporcionada en el archivo de exclusión $skipfile.

Si su archivo MANIFEST es generado por un sistema de cadena de herramientas de instalación de módulos como ExtUtils::MakeMaker, Module::Build o Module::Install, entonces no debería tener problemas con estos archivos. Es solo una prueba útil para recordarle que actualice estos archivos, usando:

$ make manifest # Para ExtUtils::MakeMaker
$ ./Build manifest # Para Module::Build

ERRORES NO FATALES

Por defecto, los errores en los archivos MANIFEST o MANIFEST.SKIP se tratan como fatales, que es realmente el propósito de usar "Test::DistManifest" como parte de su suite de pruebas de autor.

En algunos casos, este no es un comportamiento deseable, como con el Debian Perl Group, que ejecuta todas las pruebas, incluidas las de autor, como parte de su proceso de empaquetado de módulos. Esto causa estragos porque Debian agrega sus archivos de control en "debian/" aguas abajo, y ese directorio o sus archivos generalmente no están en MANIFEST.SKIP.

Al establecer la variable de entorno MANIFEST_WARN_ONLY a un valor verdadero, los errores serán no fatales; aparecerán solo como mensajes de diagnóstico, pero todas las pruebas pasarán desde la perspectiva de "Test::Harness".

Esto se puede usar en un script de prueba como:

$ENV{MANIFEST_WARN_ONLY} = 1;

o desde otros scripts de shell como:

export MANIFEST_WARN_ONLY=1

Tenga en cuenta que los errores de análisis en MANIFEST y las dependencias circulares siempre se considerarán fatales. El autor no es consciente de ningún caso en el que otro comportamiento sería útil.

DETALLES

Este módulo planifica internamente cuatro pruebas:

1.
MANIFEST puede ser analizado por "Module::Manifest"
2.
Comprueba qué archivos existen en el directorio de distribución que no coinciden con una expresión regular existente en MANIFEST.SKIP y no están listados en el archivo MANIFEST. Estos archivos deben ser excluidos de la prueba mediante la adición de una máscara en MANIFEST.SKIP (en el caso de archivos de desarrollo o prueba temporales) o deben incluirse en MANIFEST.
3.
Comprueba qué archivos se especifican en MANIFEST pero no existen en el disco. Esto ocurre normalmente cuando se elimina un script de prueba o similar de la distribución, o se mueve accidentalmente.
4.
Comprueba qué archivos se especifican tanto en MANIFEST como en MANIFEST.SKIP. Esta es claramente una condición insatisfechable, ya que no se puede esperar que el archivo en cuestión se incluya y al mismo tiempo se ignore.

Si desea ejecutar pruebas en múltiples archivos MANIFEST diferentes, puede simplemente pasar 'no_plan' a la función de importación, de esta manera:

use Test::DistManifest 'no_plan';
# Múltiples pruebas funcionan correctamente ahora
manifest_ok('MANIFEST', 'MANIFEST.SKIP');
manifest_ok();
manifest_ok('MANIFEST.OTHER', 'MANIFEST.SKIP');

Dudo que esto sea útil para los usuarios de este módulo. Sin embargo, esto se usa internamente para pruebas y podría serle útil. También puede planificar más pruebas, pero tenga en cuenta que la idea de "3 pruebas internas" puede cambiar en el futuro.

Código de ejemplo:

use Test::DistManifest tests => 5;
manifest_ok(); # 4 pruebas
ok(1, '¿es 1 verdadero?');

ADVERTENCIAS

  • Actualmente no hay forma de probar un MANIFEST/MANIFEST.SKIP sin que los archivos existan realmente en el disco. Planeo que esto cambie en el futuro.
  • Este módulo no ha sido probado muy a fondo con Unicode.
  • Este módulo no produce mensajes de diagnóstico útiles en cuanto a cómo corregir la situación. Esperemos que esto sea obvio para cualquiera que use el módulo; el énfasis debe estar en generar mensajes de error útiles.
