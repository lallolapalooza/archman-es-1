Template::FAQ - Preguntas Frecuentes sobre el Template Toolkit

Lenguaje del Template Toolkit

¿Por qué [% a = b IF c %] no funciona como se espera?

Hay una limitación en el analizador sintáctico de TT2 que significa que el siguiente código no funciona como podrías esperar:

[% a = b IF c %]

El analizador sintáctico lo interpreta como un intento de asignar "a" al resultado de "b IF c", de esta manera:

[% a = (b IF c) %]

Si quieres asignar "a = b" solo si "c" es verdadero, haz esto en su lugar:

[% SET a = b IF c %]

La palabra clave explícita "SET" le da al analizador sintáctico la pista que necesita para hacer lo correcto.

NOTA: esto se corregirá en TT3

Si estoy usando TT para escribir una plantilla TT, ¿hay una buena manera de escapar [% y %]?

Puedes hacer algo como esto:

[% stag = "[\%"
   etag = "%\]"
%]

y luego:

[% stag; 'hola'; etag %]

O puedes usar la directiva "TAGS", así:

[% TAGS [- -] %]
[- INCLUDE foo -]   # es una directiva
[% INCLUDE foo %]   # no es una directiva

¿Cómo itero sobre un hash?

Esto está cubierto en la sección Template::Manual::VMethods del manual. Se puede obtener una lista de todas las claves que están en el hash con el método virtual "keys". Luego puedes iterar sobre esa lista y buscando cada clave en su turno obtener el valor.

[% FOREACH key = product.keys %]
   [% key %] => [% product.$key %]
[% END %]

Plugins

¿Cómo hago que el plugin Table ordene los datos horizontalmente en lugar de verticalmente?

Ordena los datos en filas:

Steve     Karen     Jeff
Brooklyn  Nantucket Fairfax
NY        MA        VA
[% USE table(data, rows=3) %]

Luego pide cada columna

[% FOREACH column = table.cols %]

Y luego imprime cada elemento de la columna yendo a través de las filas de salida

[% FOREACH item = column %]
    <td>[% item %]</td>
[% END %]

Accediendo a las Cookies

Jeff Boes <jboes@nexcerpt.com> pregunta:

¿Alguien tiene un enfoque rápido y sucio para acceder
a las cookies desde las plantillas?

Jonas Liljegren responde:

[% USE CGI %]
<p>El valor es [% CGI.cookie('cookie_name') | html %]

Necesitarás tener instalado Template::Plugin::CGI.

Extender el Template Toolkit

¿Puedo servir plantillas desde una base de datos?

Respuesta corta: sí, Chris Nandor lo ha hecho para Slash. Necesitas subclasar Template::Provider. Consulta los archivos de la lista de correo para más información.

¿Puedo obtener plantillas a través de http?

Para hacer el trabajo correctamente, deberías subclasar Template::Provider a "Template::Provider::HTTP" y usar una opción "PREFIX_MAP" para vincular el prefijo de plantilla "http" a ese proveedor particular (puede que quieras buscar en el archivo de cambios alrededor de la versión 2.01 para más información sobre "PREFIX_MAP" - puede que no esté bien documentado en ningún otro lugar... ¡todavía!). por ejemplo:

use Template::Provider::HTTP;
my $file = Template::Provider( INCLUDE_PATH => [...] );
my $http = Template::Provider::HTTP->new(...);
my $tt2  = Template->new({
    LOAD_TEMPLATES => [ $file, $http ],
    PREFIX_MAP => {
        file    => '0',     # file:foo.html
        http    => '1',     # http:foo.html
        default => '0',     # foo.html => file:foo.html
    }
});

Ahora una plantilla especificada como:

[% INCLUDE foo %]

será servida por el proveedor 'file' (el predeterminado). De lo contrario, puedes añadir explícitamente un prefijo:

[% INCLUDE file:foo.html %]
[% INCLUDE http:foo.html %]
[% INCLUDE http://www.xyz.com/tt2/header.tt2 %]

Este mismo principio se puede usar para crear un proveedor de plantillas DBI. por ejemplo:

[% INCLUDE dbi:foo.html %]

Lamentablemente, todavía no tenemos un proveedor DBI como parte del Template Toolkit. Se ha hablado en la lista de correo sobre esfuerzos para desarrollar proveedores DBI y/o HTTP, pero hasta ahora nadie se ha adelantado para aceptar el desafío...

Mientras tanto, la publicación de Craig Barrat de la lista de correo tiene algunos punteros útiles sobre cómo lograr esto usando módulos existentes. Ver http://tt2.org/pipermail/templates/2001-May/000954.html

Miscelánea

¿Cómo puedo saber el nombre de la plantilla principal que se está procesando?

La variable "template" contiene una referencia al objeto Template::Document para la plantilla principal que estás procesando (es decir, la que se proporciona como primer argumento al método process() de Template). El método "name" devuelve su nombre.

[% template.name %]     # por ejemplo, index.html

¿Cómo puedo saber el nombre de la plantilla actual que se está procesando?

La variable "template" siempre hace referencia a la plantilla *principal* que se está procesando. Así que incluso si llamas a [% INCLUDE header %], y este llama a [% INCLUDE menu %], la variable "template" no cambiará.

index.html:

[% template.name  %]     # index.html
[% INCLUDE header %]

header:

[% template.name  %]     # index.html
[% INCLUDE menu   %]

menu:

[% template.name  %]     # index.html

En contraste, la variable "component" siempre hace referencia a la plantilla *actual* que se está procesando.

index.html

[% component.name %]     # index.html
[% INCLUDE header %]

header:

[% component.name %]     # header
[% INCLUDE menu   %]

menu:

[% component.name  %]     # menu

¿Cómo imprimo la hora de modificación de la plantilla o componente?

Las variables "template" y "component" hacen referencia a la plantilla principal y a la plantilla actual que se está procesando (ver preguntas anteriores). El método "modtime" devuelve la hora de modificación del archivo de plantilla correspondiente como un número de segundos desde la época de Unix (00:00:00 GMT 1 de enero de 1970).

Este número no significa mucho para nadie (excepto quizás para geeks serios de Unix), así que probablemente querrás usar el plugin Date para formatearlo para consumo humano.

[% USE Date %]
[% template.name %] modificado por última vez el [% Date.format(template.modtime) %]

Template Toolkit Language

¿Cómo puedo configurar variables por solicitud?

Una forma fácil de lograr esto es definir una única plantilla "PRE_PROCESS" que cargue otros archivos de configuración basándose en variables definidas u otras condiciones.

Por ejemplo, mi configuración suele ser algo así:

PRE_PROCESS => 'config/main'

config/main:

[%  DEFAULT  style   = 'text'
             section =  template.section or 'home';
    PROCESS  config/site
          +  config/urls
          +  config/macros
          + "config/style/$style"
          + "config/section/$section"
          + ...
%]

Esto me permite establecer una única variable 'style' para controlar qué archivo de configuración se preprocesa para establecer mis diversas opciones de estilo (colores, rutas de imágenes, etc.). Por ejemplo:

config/style/basic:

[%  style = {
        name = style    # guarda la variable 'style' existente como 'style.name'
        # define varias otras variables de estilo....
        col = {
            back => '#ffffff'
            text => '#000000'
                # ...etc...
        }
        logo = {
                # ...etc...
        }
        # ...etc...
    }
%]

Cada plantilla fuente puede declarar en qué sección se encuentra mediante una directiva META:

[% META
     title   = 'Información General'
     section = 'info'
%]
...

Esto controla qué archivo de configuración de sección se carga para establecer varias otras variables para definir el título de la sección, el menú, etc.

config/section/info:

[%  section = {
        name   = section  # guarda la variable 'section' como 'section.name'
        title  = 'Información'
        menu   = [ ... ]
        # ...etc...
    }
%]

Esto ilustra el principio básico, pero puedes extenderlo para realizar prácticamente cualquier tipo de inicialización por documento que necesites.

¿Por qué obtengo basura para mis plantillas utf-8?

Primero que nada, asegúrate de que tus archivos de plantilla definan una Marca de Orden de Bytes http://en.wikipedia.org/wiki/Byte_Order_Mark

Si por alguna razón no deseas agregar BOM a tus plantillas, puedes forzar a Template a usar una codificación particular (por ejemplo, "utf8") para tus plantillas con la opción "ENCODING".

my $template = Template->new({
    ENCODING => 'utf8'
});
