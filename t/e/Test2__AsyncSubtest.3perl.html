NOMBRE

Test2::AsyncSubtest - Objeto que representa una subprueba asíncrona.

DESCRIPCION

Las subpruebas regulares tienen un alcance limitado, comienzan, se generan eventos, luego se cierran y envían un evento Test2::Event::Subtest. Esto es un problema si quieres que la subprueba siga recibiendo eventos mientras se generan otros eventos. Esta clase implementa subpruebas que permanecen abiertas hasta que decides cerrarlas.

Esto es principalmente útil para herramientas que inician una subprueba en un proceso y luego generan procesos hijos. En muchos casos, es conveniente dejar que el proceso padre continúe en lugar de esperar a los hijos.

SINOPSIS

use Test2::AsyncSubtest;
my $ast = Test2::AsyncSubtest->new(name => foo);
$ast->run(sub {
    ok(1, "Evento en el padre" );
});
ok(1, "Evento fuera de la subprueba");
$ast->run_fork(sub {
    ok(1, "Evento en el proceso hijo");
});
...
$ast->finish;
done_testing;

CONSTRUCCION

my $ast = Test2::AsyncSubtest->new( ... );
name => $nombre (requerido)
Nombre de la subprueba. Este argumento de construcción es obligatorio.
send_to => $hub (opcional)
Hub al que se debe enviar el evento final de la subprueba. Debe ser una instancia de Test2::Hub o una subclase. Si no se especifica ninguno, se utilizará el hub superior actual.
trace => $traza (opcional)
Archivo/Línea a la que se atribuirán los errores. Debe ser una instancia de Test2::Util::Trace. Si no se especifica ninguno, se utilizará el archivo/línea donde se llamó al constructor.
hub => $hub (opcional)
Úsalo para especificar un hub que la subprueba debe usar. Por defecto, se genera un nuevo hub. Debe ser una instancia de Test2::AsyncSubtest::Hub.

METODOS

ACCESORES SIMPLES

$booleano = $ast->active
Verdadero si la subprueba está activa. La subprueba está activa si su hub aparece en la pila global de hubs. Esto es verdadero cuando "$ast->run(...)" se está ejecutando.
$arrayref = $ast->children
Obtiene un arrayref de procesos/hilos hijos. Los elementos numéricos son PIDs, los elementos bendecidos son instancias de hilos.
$arrayref = $ast->events
Obtiene un arrayref de eventos que se han enviado al hub de las subpruebas.
$booleano = $ast->finished
Verdadero si finished() ya ha sido llamado.
$hub = $ast->hub
El hub creado para la subprueba.
$entero = $ast->id
Contador de adjuntar/desadjuntar. Se utiliza internamente, no es útil para los usuarios.
$cadena = $ast->name
Nombre de la subprueba.
$pid = $ast->pid
PID en el que se creó la subprueba.
$tid = $ast->tid
ID de hilo en el que se creó la subprueba.
$hub = $ast->send_to
Hub al que se debe enviar el evento final de la subprueba.
$arrayref = $ast->stack
Pila de subpruebas asíncronas en el momento en que se creó esta. Esto es principalmente para uso interno.
$traza = $ast->trace
Instancia de Test2::Util::Trace utilizada para la generación de informes de errores.

INTERFAZ

$ast->attach($id)
Adjunta una subprueba en un hijo/proceso al original.

Nota: "my $id = $ast->cleave" debe haber sido llamado en el proceso/hilo padre antes de que se iniciara el hijo, el id que devuelve debe usarse en la llamada a "$ast->attach($id)"

$id = $ast->cleave
Prepara un espacio para que un proceso/hilo hijo se adjunte. Esto debe hacerse ANTES de que se inicie el proceso o hilo hijo. El ID devuelto lo utiliza attach().

Esto solo debe llamarse en el proceso/hilo original.

$ctx = $ast->context
Obtiene una instancia de Test2::API::Context que se puede utilizar para enviar eventos al contexto en el que se creó el hub. Este no es un contexto canónico, no debes llamar "$ctx->release" en él.
$ast->detach
Desadjuntar del padre en un proceso/hilo hijo. Esto debe llamarse justo antes de que el hijo salga.
$ast->finish
$ast->finish(%opciones)
Finaliza la subprueba, espera a los hijos y envía el evento final de la subprueba.

Esto solo debe llamarse en el proceso/hilo original.

Nota: Esto llama a "$ast->wait".

Estas son las opciones:

collapse => 1
Esto permite de forma inteligente que una subprueba esté vacía.

Si ningún evento aumenta el recuento de pruebas, no se agregará ningún plan final a la subprueba. La subprueba no se considerará un fallo (normalmente una subprueba vacía es un fallo).

Si no hay ningún evento en absoluto, la subprueba se colapsará en un evento Test2::Event::Ok.

silent => 1
Esto evitará que finish genere un evento Test2::Event::Subtest final. Esto efectivamente termina la subprueba sin que afecte a la subprueba padre (o a la prueba de nivel superior).
no_plan => 1
Esto evitará que se agregue un plan final a la subprueba por ti cuando no se especifica directamente ninguno.
skip => "razón"
Esto emitirá un Test2::Event::Skip en lugar de una subprueba. Esto lanzará una excepción si se han visto eventos, o si el estado implica que ha habido eventos.
$salida = $ast->fork
Esta es una interfaz de nivel ligeramente superior para fork. Ejecutarla hará un fork de tu código en el lugar, al igual que fork(). Devolverá un pid en el padre y una instancia de Test2::Util::Guard en el hijo. Se lanzará una excepción si fork falla.

Se recomienda que utilices "$ast->run_fork(sub { ... })" en su lugar.

$booleano = $ast->pending
Verdadero si hay procesos hijos, hilos o subpruebas que dependen de esta.
$booleano = $ast->ready
Esto es esencialmente "!$ast->pending".
$ast->run(sub { ... })
Ejecuta el bloque de código proporcionado dentro de la subprueba. Esto empujará el hub de la subprueba a la pila, ejecutará el código y luego sacará el hub de la pila.
$pid = $ast->run_fork(sub { ... })
Igual que "$ast->run()", excepto que el bloque de código se ejecuta en un proceso hijo.

No necesitas llamar directamente a wait($pid), eso se hará por ti cuando "$ast->wait" o "$ast->finish" se llamen.

my $thr = $ast->run_thread(sub { ... });
** DESACONSEJADO ** Los hilos causan problemas. Este método permanece para cualquiera que REALMENTE lo quiera, pero ya no se admite. Las pruebas para esta funcionalidad ni siquiera se ejecutan a menos que las variables de entorno AUTHOR_TESTING o T2_DO_THREAD_TESTS estén habilitadas.

Igual que "$ast->run()", excepto que el bloque de código se ejecuta en un hilo hijo.

No necesitas llamar directamente a "$thr->join", eso se hace por ti cuando "$ast->wait" o "$ast->finish" se llaman.

$pasando = $ast->start
Empuja el hub de la subprueba a la pila. Devuelve el estado actual de pasar/fallar de la subprueba.
$ast->stop
Saca el hub de la subprueba de la pila. Devuelve el estado actual de pasar/fallar de la subprueba.
$ast->wait
Espera a todos los hilos/procesos que se iniciaron utilizando "$ast->fork", "$ast->run_fork"
