NOMBRE

Test::Script - Pruebas básicas multiplataforma para scripts

VERSIÓN

versión 1.31

SINOPSIS

use Test2::V0;
use Test::Script;

script_compiles('script/myscript.pl');
script_runs(['script/myscript.pl', '--my-argument']);

program_runs(['ls', '/dev']);

done_testing;

DESCRIPCIÓN

La intención de este módulo es proporcionar una serie de pruebas básicas para el 80% de las pruebas que necesitarás hacer para los scripts en las rutas de script (o bin, como también se usa comúnmente) de tu distribución Perl.

También proporciona funcionalidades similares para probar programas que no son scripts de Perl.

Además, tiene como objetivo proporcionar esta funcionalidad con compatibilidad perfecta entre plataformas, y de una manera que sea lo más discreta posible.

Es decir, si el programa funciona en una plataforma, entonces Test::Script siempre debería funcionar también en esa plataforma. Cualquier cosa menos del 100% se considera inaceptable.

Al hacerlo, se espera que Test::Script pueda convertirse en un módulo del que puedas hacer una dependencia segura de todos tus módulos, sin arriesgarte a que tu módulo no se instale en alguna plataforma debido a la dependencia.

Donde exista un conflicto entre querer más funcionalidad y mantener la seguridad de la plataforma, este módulo se inclinará por la seguridad de la plataforma.

FUNCIONES

script_compiles

[versión 1.05]

script_compiles( $script, $test_name );

La prueba "script_compiles" llama al script con "perl -c script.pl" y comprueba que devuelve sin errores.

La ruta que se debe pasar es un nombre de script relativo en formato Unix. Esto se localizará al ejecutar "perl -c" y si la prueba falla, se mostrará el nombre local utilizado en la salida de diagnóstico.

Tenga en cuenta también que la prueba se ejecutará con el mismo intérprete de perl que está ejecutando el script de prueba (y no con el perl predeterminado del sistema). Esto también se mostrará en la salida de diagnóstico en caso de fallo.

script_runs

[versión 1.05]

script_runs( $script, $test_name );
script_runs( \@script_and_arguments, $test_name );
script_runs( $script, \%options, $test_name );
script_runs( \@script_and_arguments, \%options, $test_name );

La prueba "script_runs" ejecuta el script con "perl script.pl" y comprueba que devuelve éxito.

La ruta que se debe pasar es un nombre de script relativo en formato Unix. Esto se localizará al ejecutar "perl -c" y si la prueba falla, se mostrará el nombre local utilizado en la salida de diagnóstico.

La prueba se ejecutará con el mismo intérprete de perl que está ejecutando el script de prueba (y no con el perl predeterminado del sistema). Esto también se mostrará en la salida de diagnóstico en caso de fallo.

[versión 1.09]

Puedes pasar opciones como un hash como segundo argumento (a partir de la versión 1.09).

salida
El valor de salida esperado. El valor predeterminado es utilizar lo que indica éxito en tu plataforma (generalmente 0).
opciones_interprete
[versión 1.25]

Referencia a un array de opciones de Perl que se pasarán al intérprete. Cosas como "-w" o "-x" se pueden pasar de esta manera. Esto puede ser una única cadena o una referencia a un array.

señal
La señal esperada. El valor predeterminado es 0. ¡Úsalo con cuidado! Esto puede no ser portable y se sabe que no funciona en Windows.
stdin
La entrada que se pasará al script a través de stdin. El valor puede ser uno de
escalar simple
Se considera un nombre de archivo.
referencia escalar
En cuyo caso la entrada se extraerá de los datos contenidos en el escalar referenciado.

El comportamiento para cualquier otro tipo no está definido (la implementación actual utiliza Capture::Tiny). Cualquier stdin ya abierto se cerrará.

stdout
A dónde enviar la salida estándar. Si usas esta opción, el comportamiento de las funciones "script_stdout_" a continuación no está definido. El valor puede ser uno de
escalar simple
Se considera un nombre de archivo.
referencia escalar

En cuyo caso la salida estándar se colocará en el escalar referenciado.

El comportamiento para cualquier otro tipo no está definido (la implementación actual utiliza Capture::Tiny).

stderr
Igual que "stdout" arriba, excepto para stderr.

script_fails

[ versión 1.28 ]

script_fails $script, { exit => $expected_exit }, $test_name );
script_fails $script, \%options, $test_name;

"script_runs" puede ser invocado como "script_fails". La opción de salida es obligatoria cuando se usa de esta manera. Desde Perl 5.12, "die" suele devolver 255, pero no promete hacerlo. Los errores fatales como la división por cero también suelen devolver 255, por lo que no es el mejor código de error para una excepción atrapada. script_runs necesita un código de salida que considere éxito, usa "warn; exit;" en lugar de die.

NAME

Test::Script - A framework for testing scripts.

VERSION

This documentation describes version 1.31 of Test::Script.

SYNOPSIS

 use Test::More tests => 2;
 use Test::Script;

 # Run a script and check its exit code
 script_runs 'my_script.pl', $test_name;
 ok $? == 0, "script exits cleanly";

 # Run a script and check its stdout
 script_stdout_like 'my_script.pl', qr/hello/, $test_name;

 # Run a script with arguments
 script_runs 'my_script.pl', 'arg1', 'arg2', $test_name;

 # Run a script with stdin
 script_runs 'my_script.pl', { stdin => 'input' }, $test_name;

 # Run an external program
 program_runs '/bin/ls', $test_name;

 # Run an external program and check its stdout
 program_stdout_is '/bin/ls', $test_name, 'output';

DESCRIPTION

This module provides a framework for testing standalone scripts (Perl or otherwise) from within a Perl test script.

It allows you to easily run a script, capture its standard output and standard error, and check its exit status.

FUNCTIONS

The following functions are exported by default:

script_runs

[version 1.00]

script_runs $script, $test_name;
script_runs $script, \%options, $test_name;

Runs the given script (which should be a Perl script unless use_perl is false). Exits with status 0 if the script exits with status 0. Exits with status 255 if the script exits with a non-zero status.

If %options is provided, it can contain the following keys:

interpreter
The interpreter to use to run the script. Defaults to the same Perl that is running the tests.
interpreter_options
An array reference of options to pass to the interpreter. For example, ['taintmode', 'warnings'].
script_arguments
An array reference of arguments to pass to the script. For example, ['arg1', 'arg2'].
stdin
A string to be passed to the script's standard input.
chdir
Change to this directory before running the script. Defaults to the current directory.
env
A hash reference of environment variables to set for the script. These override the current environment.
timeout
Maximum number of seconds to wait for the script to finish. If the timeout is reached, the test fails.

script_fails

[version 1.00]

script_fails $script, $test_name;
script_fails $script, \%options, $test_name;

Runs the given script. Exits with status 0 if the script exits with a non-zero status. Exits with status 255 if the script exits with status 0.

The %options can be the same as for script_runs. The exit option can be used to specify the expected exit code.

script_fails $script, { exit => 5 }, $test_name;

script_stdout_is

[version 1.00]

script_stdout_is $expected_stdout, $test_name;

Tests if the output to stdout from the previous "script_runs" matches the expected value exactly.

script_stdout_isnt

[version 1.00]

script_stdout_isnt $expected_stdout, $test_name;

Tests if the output to stdout from the previous "script_runs" does NOT match the expected value exactly.

script_stdout_like

[version 1.00]

script_stdout_like $regex, $test_name;

Tests if the output to stdout from the previous "script_runs" matches the regular expression.

script_stdout_unlike

[version 1.00]

script_stdout_unlike $regex, $test_name;

Tests if the output to stdout from the previous "script_runs" does NOT match the regular expression.

script_stderr_is

[version 1.00]

script_stderr_is $expected_stderr, $test_name;

Tests if the output to stderr from the previous "script_runs" matches the expected value exactly.

script_stderr_isnt

[version 1.00]

script_stderr_isnt $expected_stderr, $test_name;

Tests if the output to stderr from the previous "script_runs" does NOT match the expected value exactly.

script_stderr_like

[version 1.00]

script_stderr_like $regex, $test_name;

Tests if the output to stderr from the previous "script_runs" matches the regular expression.

The regular expression is matched against the entire standard error output. Use qr// to create regexes.

script_stderr_unlike

[version 1.09]

script_stderr_unlike $regex, $test_name;

Tests if the output to stderr from the previous "script_runs" does NOT match the regular expression.

program_runs

[version 1.26]

program_runs( $program, $test_name );
program_runs( \@program_and_arguments, $test_name );
program_runs( $program, \%options, $test_name );
program_runs( \@program_and_arguments, \%options, $test_name );

The "program_runs" test executes the given program and checks that it returns success. This function works like "script_runs" except:

  • The path $program or @program_and_arguments is passed as-is to system() https://perldoc.perl.org/functions/system.html. This means "program_runs" can test any program, not just Perl scripts.
  • The %options do not support the "interpreter_options" key.

See File::Spec or Path::Class for routines useful in building pathnames in a cross-platform way.

program_fails

[ version 1.28 ]

program_fails $program, { exit => $expected_exit }, $test_name;
program_fails $program, \%options, $test_name;

"program_runs" may be invoked as "program_fails". "program_fails" needs to know the expected exit value, so exit becomes a required option.

CAVEATS

This module is fully supported back to Perl 5.8.1.

The STDIN handle will be closed when using script_runs with the stdin option. An older version used IPC::Run3, which attempted to save STDIN, but apparently this cannot be done consistently or portably. We now use Capture::Tiny instead and explicitly do not support saving STDIN handles.
