NOMBRE

Template::Tutorial::Datafile - Creación de Archivos de Salida de Datos Usando el Template Toolkit

DESCRIPCIÓN

Introducción al Template Toolkit

Hay una serie de módulos Perl que son universalmente reconocidos como "Lo Correcto a Usar" para ciertas tareas. Si accediera a una base de datos sin usar DBI, extrajera datos de la WWW sin usar uno de los módulos LWP o analizara XML sin usar XML::Parser o alguna de sus subclases, correría el riesgo de ser rechazado por la sociedad Perl educada.

Creo que el año 2000 vio el surgimiento de otro módulo Perl "imprescindible": el Template Toolkit. No creo estar solo en esta creencia, ya que el Template Toolkit ganó el premio al "Mejor Módulo Nuevo" en la Conferencia Perl el verano pasado. La versión 2.0 del Template Toolkit (conocido como TT2 para sus amigos) fue lanzada recientemente al CPAN.

TT2 fue diseñado y escrito por Andy Wardley <abw@wardley.org>. Nació del módulo de plantillas anterior de Andy, Text::Metatext, en el mejor estilo de Fred Brooks "plan para desechar uno"; y tiene como objetivo ser el sistema de plantillas Perl más útil (o, al menos, el más utilizado).

TT2 proporciona una forma de tomar un archivo de texto fijo de plantilla (la plantilla) e incrustar datos variables dentro de él. Un uso obvio de esto es la creación de páginas web dinámicas y aquí es donde se ha centrado gran parte de la atención que ha recibido TT2. En este artículo, espero demostrar que TT2 es igual de útil en aplicaciones no web.

Usando el Template Toolkit

Veamos cómo usaríamos TT2 para procesar un archivo de datos simple. TT2 es un módulo Perl orientado a objetos. Después de descargarlo del CPAN e instalarlo de la manera habitual, usarlo en su programa es tan fácil como poner las líneas

use Template;
my $tt = Template->new;

en su código. La función constructora, "new", toma una serie de parámetros opcionales que están documentados en las copiosas páginas del manual que vienen con el módulo, pero para los propósitos de este artículo mantendremos las cosas lo más simples posible.

Para procesar la plantilla, llamaría al método "process" de esta manera

$tt->process('my_template', \%data)
    || die $tt->error;

Pasamos dos parámetros a "process", el primero es el nombre del archivo que contiene la plantilla a procesar (en este caso, my_template) y el segundo es una referencia a un hash que contiene los elementos de datos que desea utilizar en la plantilla. Si el procesamiento de la plantilla genera algún tipo de error, el programa morirá con un mensaje de error (con suerte) útil.

Entonces, ¿qué tipo de cosas pueden ir en %data? La respuesta es casi cualquier cosa. Aquí hay un ejemplo que muestra datos sobre equipos de fútbol de la Premier League inglesa.

my @teams = ({ name   => 'Man Utd',
               played => 16,
               won    => 12,
               drawn  => 3,
               lost   => 1 },
             { name   => 'Bradford',
               played => 16,
               won    => 2,
               drawn  => 5,
               lost   => 9 });
my %data = ( name   => 'English Premier League',
             season => '2000/01',
             teams  => \@teams );

Esto crea tres elementos de datos que se pueden acceder dentro de la plantilla, llamados "name", "season" y "teams". Nótese que "teams" es una estructura de datos compleja.

Aquí hay una plantilla que podríamos usar para procesar estos datos.

League Standings
League Name: [% name %]
Season     : [% season %]
Teams:
[% FOREACH team = teams -%]
[% team.name %] [% team.played -%] 
 [% team.won %] [% team.drawn %] [% team.lost %]
[% END %]

Ejecutar esta plantilla con estos datos nos da la siguiente salida

            League Standings
League Name: English Premier League
Season     : 2000/01
Teams:
Man Utd 16 12 3 1
Bradford 16 2 5 9

Con suerte, la sintaxis de la plantilla es lo suficientemente simple como para seguirla. Hay algunos puntos a tener en cuenta.

  • Las directivas de procesamiento de plantillas se escriben utilizando un lenguaje simple que no es Perl.
  • Las claves del %data se han convertido en los nombres de las variables de datos dentro de la plantilla.
  • Las directivas de procesamiento de plantillas están rodeadas por secuencias "[%" y "%]".
  • Si estas etiquetas se reemplazan con "[%-" y "-%]", se suprime el salto de línea anterior o posterior.
  • En el bucle "FOREACH", cada elemento de la lista "teams" se asignó, por turnos, a la variable temporal "team".
  • Cada elemento asignado a la variable "team" es un hash de Perl. Los valores individuales dentro del hash se acceden utilizando una notación de punto.

Probablemente el primer y último de estos puntos son los más importantes. El primer punto enfatiza la separación de la lógica de adquisición de datos de la lógica de presentación. La persona que crea la plantilla de presentación no necesita saber Perl, solo necesita conocer los elementos de datos que se pasarán a la plantilla.

El último punto demuestra la forma en que TT2 protege al diseñador de la plantilla de la implementación de las estructuras de datos. Los objetos de datos pasados al procesador de plantillas pueden ser escalares, arrays, hashes, objetos o incluso subrutinas. El procesador de plantillas simplemente interpretará sus datos correctamente y hará lo correcto para devolverle el valor correcto. En este ejemplo, cada equipo era un hash, pero en un sistema más grande, cada equipo podría ser un objeto, en cuyo caso "name", "played", etc., serían métodos accesores de los atributos subyacentes del objeto. No se requerirían cambios en la plantilla, ya que el procesador de plantillas se daría cuenta de que necesitaba llamar a métodos en lugar de acceder a valores de hash.

Un ejemplo más complejo

Las estadísticas de la Liga de Fútbol Inglesa suelen presentarse en un formato un poco más complejo que el que usamos anteriormente. Un conjunto completo de estadísticas mostrará el número de partidos ganados, perdidos o empatados por un equipo, el número de goles marcados y recibidos por el equipo y el número de puntos que tiene el equipo. Los equipos ganan tres puntos por una victoria y un punto por un empate. Cuando los equipos tienen el mismo número de puntos, se separan por la diferencia de goles, es decir, el número de goles que el equipo ha marcado menos el número de goles que el equipo ha recibido. Para complicar aún más las cosas, los partidos ganados, empatados y perdidos, y los goles a favor y en contra, a menudo se dividen entre partidos en casa y fuera.

Por lo tanto, si tiene una fuente de datos que enumera el nombre del equipo junto con los partidos ganados, empatados y perdidos, y los goles a favor y en contra divididos entre casa y fuera (un total de once elementos de datos), puede calcular todos los demás elementos (diferencia de goles, puntos otorgados e incluso posición en la liga). Tomemos un archivo de este tipo, pero solo veremos los tres primeros equipos. Se verá algo como esto:

Man Utd,7,1,0,26,4,5,2,1,15,6
Arsenal,7,1,0,17,4,2,3,3,7,9
Leicester,4,3,1,10,8,4,2,2,7,4

Un script simple para leer estos datos en un array de hashes se verá algo así (he simplificado los nombres de las columnas de datos; w, d y l son partidos ganados, empatados y perdidos, y f y a son goles marcados a favor y en contra; h y a al principio del nombre de un elemento de datos indican si es una estadística local o visitante):

my @cols = qw(name hw hd hl hf ha aw ad al af aa);
my @teams;
while (<>) {
    chomp;
    my %team;
    @team{@cols} = split /,/;
    push @teams, \%team;
}

Luego podemos recorrer los equipos nuevamente y calcular todos los elementos de datos derivados:

foreach (@teams) {
    $_->{w} = $_->{hw} + $_->{aw};
    $_->{d} = $_->{hd} + $_->{ad};
    $_->{l} = $_->{hl} + $_->{al};
    $_->{pl} = $_->{w} + $_->{d} + $_->{l};
    $_->{f} = $_->{hf} + $_->{af};
    $_->{a} = $_->{ha} + $_->{aa};
    $_->{gd} = $_->{f} - $_->{a};
    $_->{pt} = (3 * $_->{w}) + $_->{d};
}

Template::Tutorial::Datafile(3pm) - Arch Linux man pages

NAME

Template::Tutorial::Datafile - Datafile example

DESCRIPTION

This document provides an example of how you might use the Template Toolkit to process data held in a list of hashes.

Introducing the Template Toolkit

The Template Toolkit is a powerful and flexible template processing system. It is written in Perl and is widely used for generating all kinds of text-based output, from web pages to configuration files.

The basic idea is that you have a template file containing static text mixed with template directives. The template processor reads the template file, interpolates any variables you pass in, evaluates any directives, and then outputs the final text.

Using the Template Toolkit

Let's imagine we have some data about a football league stored in a Perl data structure. This might look something like:

  my @teams = (
      { name => 'Man Utd',    pl => 16, hw => 7, hd => 1, hl => 0, hf => 26, ha => 4,
                       aw => 5, ad => 2, al => 1, af => 15, aa => 6, gd => 31, pt => 39, },
      { name => 'Arsenal',    pl => 16, hw => 7, hd => 1, hl => 0, hf => 17, ha => 4,
                       aw => 2, ad => 3, al => 3, af =>  7, aa => 9, gd => 11, pt => 31, },
      { name => 'Leicester',  pl => 16, hw => 4, hd => 3, hl => 1, hf => 10, ha => 8,
                       aw => 4, ad => 2, al => 2, af =>  7, aa => 4, gd =>  5, pt => 29, },
  );

To process this data, we first need to create a Template Toolkit object and then pass the data structure to its process method along with the name of the template file.

  use Template;
  my $tt = Template->new;
  $tt->process('split.tt', { teams => \@teams })
      || die $tt->error;

Now, we need to add the league position data item:

$teams[$_]->{pos} = $_ + 1
    foreach 0 .. $#teams;

Having pulled all of our data into an internal data structure we can start to produce output using out templates. A template to create a CSV file containing the data split between home and away stats would look like this:

[% FOREACH team = teams -%]
[% team.pos %],[% team.name %],[% team.pl %],[% team.hw %],
[%- team.hd %],[% team.hl %],[% team.hf %],[% team.ha %],
[%- team.aw %],[% team.ad %],[% team.al %],[% team.af %],
[%- team.aa %],[% team.gd %],[% team.pt %]
[%- END %]

And processing it like this:

$tt->process('split.tt', { teams => \@teams }, 'split.csv')
  || die $tt->error;

produces the following output:

1,Man Utd,16,7,1,0,26,4,5,2,1,15,6,31,39
2,Arsenal,16,7,1,0,17,4,2,3,3,7,9,11,31
3,Leicester,16,4,3,1,10,8,4,2,2,7,4,5,29

Notice that we've introduced the third parameter to "process". If this parameter is missing then the TT2 sends its output to "STDOUT". If this parameter is a scalar then it is taken as the name of a file to write the output to. This parameter can also be (amongst other things) a filehandle or a reference to an object which is assumed to implement a "print" method.

If we weren't interested in the split between home and away games, then we could use a simpler template like this:

[% FOREACH team = teams -%]
[% team.pos %],[% team.name %],[% team.pl %],[% team.w %],
[%- team.d %],[% team.l %],[% team.f %],[% team.a %],
[%- team.aa %],[% team.gd %],[% team.pt %]
[% END -%]

Which would produce output like this:

1,Man Utd,16,12,3,1,41,10,6,31,39
2,Arsenal,16,9,4,3,24,13,9,11,31
3,Leicester,16,8,5,3,17,12,4,5,29

Producing XML

This is starting to show some of the power and flexibility of TT2, but you may be thinking that you could just as easily produce this output with a "foreach" loop and a couple of "print" statements in your code. This is, of course, true; but that's because I've chosen a deliberately simple example to explain the concepts. What if we wanted to produce an XML file containing the data? And what if (as I mentioned earlier) the league data was held in an object? The code would then look even easier as most of the code we've written earlier would be hidden away in "FootballLeague.pm".

use FootballLeague;
use Template;
my $league = FootballLeague->new(name => 'English Premier');
my $tt = Template->new;
$tt->process('league_xml.tt', { league => $league })
    || die $tt->error;

And the template in "league_xml.tt" would look something like this:

<?xml version="1.0"?>
<!DOCTYPE LEAGUE SYSTEM "league.dtd">
<league name="[% league.name %]" season="[% league.season %]">
[% FOREACH team = league.teams -%]
  <team name="[% team.name %]"
        pos="[% team.pos %]"
        played="[% team.pl %]"
        goal_diff="[% team.gd %]"
        points="[% team.pt %]">
     <stats type="home">
            win="[% team.hw %]"
            draw="[%- team.hd %]"
            lose="[% team.hl %]"
            for="[% team.hf %]"
            against="[% team.ha %]" />
     <stats type="away">
            win="[% team.aw %]"
            draw="[%- team.ad %]"
            lose="[% team.al %]"
            for="[% team.af %]"
            against="[% team.aa %]" />
  </team>
[% END -%]
&/league>

Notice that as we've passed the whole object into "process" then we need to put an extra level of indirection on our template variables - everything is now a component of the "league" variable. Other than that, everything in the template is very similar to what we've used before. Presumably now "team.name" calls an accessor function rather than carrying out a hash lookup, but all of this is transparent to our template designer.

Multiple Formats

As a final example, let's suppose that we need to create output football league tables in a number of formats. Perhaps we are passing this data on to other people and they can't all use the same format. Some of our users need CSV files and others need XML. Some require data split between home and away matches and other just want the totals. In total, then, we'll need four different templates, but the good news is that they can use the same data object. All the script needs to do is to establish which template is required and process it.

use FootballLeague;
use Template;
my ($name, $type, $stats) = @_;
my $league = FootballLeague->new(name => $name);
my $tt = Template->new;
$tt->process("league_${type}_$stats.tt",
             { league => $league }
             "league_$stats.$type")
    || die $tt->error;

For example, you can call this script as

league.pl 'English Premier' xml split

This will process a template called "league_xml_split.tt" and put the results in a file called "league_split.xml".

This starts to show the true strength of the Template Toolkit. If we later wanted to add another file format - perhaps we wanted to create a league table HTML page or even a LaTeX document - then we would just need to create the appropriate template and name it according to our existing naming convention. We would need to make no changes to the code.

I hope you can now see why the Template Toolkit is fast becoming an essential part of many people's Perl installation.
