NOMBRE

Test::Without::Module - Prueba el comportamiento de reserva en ausencia de módulos

SINOPSIS

use Test::Without::Module qw( Mi::Módulo );
# Ahora, la carga de Mi::Módulo falla:
eval { require Mi::Módulo; };
warn $@ if $@;
# Ahora vuelve a funcionar
eval q{ no Test::Without::Module qw( Mi::Módulo ) };
eval { require Mi::Módulo; };
print "Encontrado Mi::Módulo" unless $@;

DESCRIPCIÓN

Este módulo te permite ocultar deliberadamente módulos de un programa aunque estén instalados. Esto es muy útil para probar módulos que tienen un comportamiento de reserva cuando no se instala un módulo de dependencia determinado.

EXPORTAR

Ninguno. Toda la magia se hace a través de "use Test::Without::Module LIST" y "no Test::Without::Module LIST".

Test::Without::Module::obtener_lista_prohibida

Esta función devuelve una referencia a una copia del hash actual de módulos prohibidos o un hash vacío si no hay ninguno prohibido actualmente. Esto es conveniente si estás probando y/o depurando este módulo.

UNA LÍNEA

NUFFIN y Jerrad Pierce me mencionaron un truco interesante para usar este módulo desde la línea de comandos:

perl -MTest::Without::Module=Algun::Módulo -w -Iblib/lib t/SomeModule.t

De esta manera, puedes ver fácilmente cómo se comporta tu módulo o archivo de prueba cuando un módulo determinado no está disponible.

CRÉDITOS

Debo agradecer gran parte de la mejora a Aristotle de PerlMonks, me señaló una forma mucho menos complicada de simular un módulo en https://perlmonks.org?node=192635.

También discutí con él una forma aún más elegante de sobrescribir CORE::GLOBAL::require, pero el análisis de la subrutina sobrescrita no salió como yo quería: CORE::require ya no reconocía los barewords como tales.

NUFFIN y Jerrad Pierce señalaron el uso conveniente desde la línea de comandos para observar interactivamente el comportamiento de la suite de pruebas y el módulo en ausencia de un módulo.
