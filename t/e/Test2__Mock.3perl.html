Test2::Mock(3perl) Perl Programmers Reference Guide Test2::Mock(3perl)

NOMBRE

Test2::Mock - Módulo para gestionar clases y instancias simuladas.

DESCRIPCIÓN

Este módulo te permite añadir y sobrescribir métodos para cualquier paquete temporalmente. Cuando la instancia sea destruida, restaurará el paquete a su estado original.

SINOPSIS

use Test2::Mock;
use MyClass;
my $mock = Test2::Mock->new(
    track => $BOOL, # habilita el seguimiento de llamadas si se desea
    class => 'MyClass',
    override => [
        name => sub { 'fred' },
        ...
    ],
    add => [
        is_mocked => sub { 1 }
        ...
    ],
    ...
);
# Deshacer la simulación del sub 'name'
$mock->restore('name');
...
$mock = undef; # Eliminará toda la simulación

CONSTRUCCIÓN

MÉTODOS

$mock = Test2::Mock->new(class => $CLASS, ...)
Esto creará una nueva instancia de Test2::Mock que gestiona la simulación para la $CLASS especificada.

Cualquier método de "Test2::Mock" puede ser usado como argumento del constructor, cada uno debe ser seguido por un arrayref de argumentos a ser usados dentro del método. Por ejemplo el método add():

my $mock = Test2::Mock->new(
    class => 'AClass',
    add => [foo => sub { 'foo' }],
);

es idéntico a esto:

my $mock = Test2::Mock->new(
    class => 'AClass',
);
$mock->add(foo => sub { 'foo' });
$mock->track($bool)
Activa o desactiva el seguimiento. Cualquier sub añadida/sobrescrita/establecida cuando el seguimiento está activado registrará cada llamada en un hash recuperable a través de "$mock->tracking". Cambiar el modificador de seguimiento no afectará a los subs ya alterados, pero sí afectará a cualquier alteración adicional.
$hashref = $mock->sub_tracking
Los datos de seguimiento se ven así: 
{
    sub_name => [
        {sub_name => $sub_name, sub_ref => $mock_subref, args => [... copia de @_ de la llamada ... ]},
        ...,
        ...,
    ],
}

A diferencia de call_tracking, esto lista todas las llamadas por sub, para que puedas elegir mirar solo las llamadas específicas de sub.

Nota: Los elementos del hashref con el nombre de sub y los argumentos se comparten con call_tracking, modificar uno modifica el otro, ¡así que copia primero!

$arrayref = $mock->call_tracking
Los datos de seguimiento se ven así: 
[
    {sub_name => $sub_name, sub_ref => $mock_subref, args => [... copia de @_ de la llamada ... ]},
    ...,
    ...,
]

A diferencia de sub_tracking, esto lista todas las llamadas a cualquier sub simulada, en el orden en que fueron llamadas. Para filtrar por sub, usa sub_tracking.

Nota: Los elementos del hashref con el nombre de sub y los argumentos se comparten con sub_tracking, modificar uno modifica el otro, ¡así que copia primero!

$mock->clear_sub_tracking()
$mock->clear_sub_tracking(\@subnames)
Borra los datos de seguimiento. Sin argumentos, se borran TODOS los datos de seguimiento. Cuando se proporcionan argumentos, solo se borrarán esas claves específicas.
$mock->clear_call_tracking()
Borra todos los elementos de call_tracking.
$mock->add('symbol' => ..., 'symbol2' => ...)
$mock->override('symbol1' => ..., 'symbol2' => ...)
$mock->set('symbol1' => ..., 'symbol2' => ...)
add() y override() son las principales formas de añadir/modificar métodos para una clase. Ambos aceptan exactamente el mismo tipo de argumentos. La diferencia es que "override" fallará a menos que el símbolo que se está sobrescribiendo ya exista, mientras que "add" fallará si el símbolo ya existe.

set() se añadió más recientemente para casos en los que es posible que no sepas si el sub ya existe. Estos casos son raros y se debe evitar set (piénsalo como 'no strict'). Sin embargo, hay casos de uso válidos, así que se añadió.

Nota: Piensa en override como una operación push. Si llamas a override en el mismo símbolo varias veces, lo rastreará. Puedes usar restore() como una operación pop para volver al mock anterior. "reset" se puede usar para eliminar toda la simulación de un símbolo.

Los argumentos deben ser un nombre de símbolo, con sigilo opcional, seguido de una nueva especificación del símbolo. Si no se especifica sigilo, se asume '&' (sub). Un ejemplo simple de sobrescribir un sub:

$mock->override(foo => sub { 'foo sobrescrito' });
my $val = $class->foo; # Ejecuta nuestra sobrescritura
# $val ahora se establece en 'foo sobrescrito'

También puedes simplemente proporcionar un valor y se envolverá en un sub para ti:

$mock->override( foo => 'foo' );

El ejemplo anterior generará un sub que siempre devuelve la cadena 'foo'.

Hay tres valores *especiales* que se pueden usar para generar accesores:

$mock->add(
    name => 'rw',   # Genera un accesor de lectura/escritura
    age  => 'ro',   # Genera un accesor de solo lectura
    size => 'wo',   # Genera un accesor de solo escritura
);

Si quieres tener un sub que realmente devuelva una de las tres cadenas especiales, o que devuelva un coderef, puedes usar un hashref como especificación:

my $ref = sub { 'mi sub' };
$mock->add(
    rw_string => { val => 'rw' },
    ro_string => { val => 'ro' },
    wo_string => { val => 'wo' },
    coderef   => { val => $ref }, # el método coderef devuelve $ref cada vez
);

También puedes sobrescribir/añadir otros tipos de símbolos, como hashes:

package Foo;
...
$mock->add('%foo' => {a => 1});
print $Foo::foo{a}; # imprime '1'

También puedes decirle a mock que deduzca el tipo de símbolo para add/override de la referencia, las reglas son similares a las asignaciones de glob:

$mock->add(
    -foo => sub { 'foo' },     # Añade el sub &foo al paquete
    -foo => { foo => 1 },      # Añade el hash %foo al paquete
    -foo => [ 'f', 'o', 'o' ], # Añade el array @foo al paquete
    -foo => \"foo",            # Añade el escalar $foo al paquete
);
$mock->restore($SYMBOL)
Restaura el símbolo a lo que era antes de la última sobrescritura. Si el símbolo fue añadido recientemente, se eliminará. Si el símbolo ha sido sobrescrito múltiples veces, SOLO lo restaurará al estado anterior. Piensa en "override" como una operación push, y "restore" como la operación pop.
$mock->reset($SYMBOL)
Elimina toda la simulación del símbolo y restaura el símbolo original. Si el símbolo fue añadido inicialmente, se eliminará por completo.
$mock->orig($SYMBOL)
Esto devolverá el símbolo original, antes de cualquier simulación. Para símbolos que fueron añadidos, esto devolverá undef.
$mock->current($SYMBOL)
Esto devolverá el símbolo actual.
$mock->reset_all
Elimina todos los símbolos añadidos y restaura todos los símbolos sobrescritos a sus originales.
$mock->add_constructor($NAME => $TYPE)
$mock->override_constructor($NAME => $TYPE)
Esto se puede usar para inyectar constructores. El primer argumento debe ser el nombre del constructor. El segundo argumento especifica el tipo de constructor.

El tipo "hash" es el más común, todos los argumentos se usan para crear un nuevo hash que es bendecido.

hash => sub  {
    my ($class, %params) = @_;
    return bless \%params, $class;
};

El tipo "array" es similar al tipo hash, pero acepta una lista en lugar de pares clave/valor:

array => sub {
    my ($class, @params) = @_;
    return bless \@params, $class;
};

El tipo "ref" toma una referencia y la bendice. Esto modificará tu argumento de entrada original.

ref => sub {
    my ($class, $params) = @_;
    return bless $params, $class;
};

El tipo "ref_copy" copiará tu referencia y bendecirá la copia:

ref_copy => sub {
    my ($class, $params) = @_;
    my $type = reftype($params);
    return bless {%$params}, $class
