NOMBRE

Test2::Manual::Anatomy::Context - Documentación interna de los objetos de Contexto.

DESCRIPCIÓN

Este documento explica cómo funciona el objeto Test2::API::Context.

¿QUÉ ES EL OBJETO DE CONTEXTO?

El objeto de contexto es uno de los componentes clave de Test2 y hace posibles muchas características que de otro modo serían imposibles. Cada herramienta de prueba comienza obteniendo un contexto y termina liberándolo. Una herramienta de prueba realiza todo su trabajo entre la obtención y la liberación del contexto. La instancia de contexto es la interfaz principal para enviar eventos a la pila de Test2. Finalmente, el sistema de contexto es responsable de rastrear el archivo y el número de línea en los que opera una herramienta, lo cual es crucial para la depuración.

INTERFAZ PRINCIPAL PARA HERRAMIENTAS DE PRUEBA

Casi todas las herramientas basadas en Test2 deberían comenzar llamando a $ctx = Test2::API::context() para obtener un objeto de contexto, y deberían terminar llamando a "$ctx->release()". Una vez que una herramienta tiene su objeto de contexto, puede llamar a métodos en el objeto para enviar eventos u otros efectos. Casi todo lo que una herramienta de prueba necesita hacer debe hacerse a través del objeto de contexto.

RASTREAR ARCHIVOS Y NÚMEROS DE LÍNEA PARA INFORMAR ERRORES

Cuando llama a "Test2::API::Context", se devolverá un nuevo objeto de contexto. Si ya existe un objeto de contexto en efecto (desde un punto diferente de la pila), obtendrá un clon del existente. Si no hay un contexto actual, se generará uno completamente nuevo. Cuando se genera un nuevo contexto, Test2 determinará el nombre del archivo y el número de línea de su código de prueba; estos se usarán al informar cualquier fallo.

Típicamente, el archivo y el número de línea se determinarán utilizando caller() para examinar la llamada a su herramienta. Se respetará $Test::Builder::Level si se detecta, pero se desaconseja su uso en favor de simplemente usar objetos de contexto en cada nivel.

Al llamar a Test2::API::Context(), puede especificar los argumentos "level => $count" si necesita examinar una llamada más profunda.

PRESERVAR $?, $!, $^E Y $@

Cuando llama a Test2::API::context(), los valores actuales de $?, $!, $^E y $@ se almacenan en el propio objeto de contexto. Siempre que se libera el contexto, se restaurarán los valores originales de estas variables. Esto protege las variables de cualquier efecto secundario causado por las herramientas de prueba.

FINALIZAR EL ESTADO DE LA API

Test2::API funciona a través de una instancia singleton oculta de Test2::API::Instance. El singleton tiene algún estado que no se fija hasta el último momento posible. El último momento posible resulta ser la primera vez que se adquiere un contexto. El estado incluye la instancia IPC, la clase Formateador, el PID raíz, etc.

ENCONTRAR/CREAR EL HUB ACTUAL/RAÍZ

Test2 tiene una pila de hubs; la pila se puede acceder a través de Test2::API::test2_stack. Cuando obtiene un contexto, buscará el hub actual; si no hay un hub actual, se inicializará el hub raíz.

PROPORCIONAR GANCHOS

Hay ganchos que se ejecutan cuando se crean, encuentran y liberan los contextos. Consulte Test2::API para obtener detalles sobre estos ganchos y cómo utilizarlos.
