Test::Alien(3) Documentación de Perl aportada por el usuario Test::Alien(3)

NOMBRE

Test::Alien - Herramientas de prueba para módulos Alien

VERSIÓN

versión 2.84

SINOPSIS

Prueba los comandos que vienen con tu Alien:

use Test2::V0;
use Test::Alien;
use Alien::patch;

alien_ok 'Alien::patch';
run_ok([ 'patch', '--version' ])
  ->success
  # solo aceptamos la version escrita
  # por Larry ...
  ->out_like(qr{Larry Wall});

done_testing;

Prueba que tu librería funciona con "XS":

use Test2::V0;
use Test::Alien;
use Alien::Editline;

alien_ok 'Alien::Editline';
my $xs = do { local $/; <DATA> };
xs_ok $xs, with_subtest {
  my($module) = @_;
  ok $module->version;
};

done_testing;

__DATA__

#include "EXTERN.h"
#include "perl.h"
#include "XSUB.h"
#include <editline/readline.h>

const char *
version(const char *class)
{
  return rl_library_version;
}

MODULE = TA_MODULE PACKAGE = TA_MODULE

const char *version(class);
    const char *class;

Prueba que tu librería funciona con FFI::Platypus:

use Test2::V0;
use Test::Alien;
use Alien::LibYAML;

alien_ok 'Alien::LibYAML';
ffi_ok { symbols => ['yaml_get_version'] }, with_subtest {
  my($ffi) = @_;
  my $get_version = $ffi->function(yaml_get_version => ['int*','int*','int*'] => 'void');
  $get_version->call(\my $major, \my $minor, \my $patch);
  like $major, qr{[0-9]+};
  like $minor, qr{[0-9]+};
  like $patch, qr{[0-9]+};
};

done_testing;

DESCRIPCIÓN

Este módulo proporciona herramientas para probar módulos Alien. Tiene ganchos para trabajar fácilmente con módulos basados en Alien::Base, pero también puede ser utilizado a través de la interfaz sintética para probar módulos Alien no basados en Alien::Base. Tiene requisitos previos muy modestos.

Antes de este módulo, la mejor manera de probar un módulo Alien era a través de Test::CChecker. La principal desventaja de ese módulo es que está fuertemente influenciado y utiliza ExtUtils::CChecker, que es una herramienta para verificar en tiempo de instalación varias cosas sobre tu compilador. También fue escrito antes de que Alien::Base fuera tan estable como lo es hoy. En particular, Test::CChecker realiza sus pruebas creando un ejecutable y ejecutándolo. Desafortunadamente, Perl utiliza extensiones creando bibliotecas dinámicas y vinculándolas al proceso de Perl, lo cual es diferente de maneras sutiles y propensas a errores. Este módulo intenta probar las bibliotecas de la manera en que se usarán realmente, a través de "XS" o FFI::Platypus. También proporciona un mecanismo para probar binarios que son proporcionados por los diversos módulos Alien (por ejemplo, Alien::gmake y Alien::patch).

Los módulos Alien pueden ser utilizables sin un compilador, o sin FFI::Platypus (por ejemplo, si la biblioteca es proporcionada por el sistema, y estás usando FFI::Platypus, o si estás compilando desde la fuente y estás usando "XS"), por lo que las pruebas con prerrequisitos faltantes se omiten automáticamente. Por ejemplo, "xs_ok" se omitirá automáticamente si no se encuentra un compilador, y "ffi_ok" se omitirá automáticamente si FFI::Platypus no está instalado.

FUNCIONES

alien_ok

alien_ok $alien, $message;
alien_ok $alien;

Carga la instancia o clase Alien dada. Comprueba que la instancia o clase se ajusta a la misma interfaz que Alien::Base. Será utilizada por pruebas posteriores. El módulo $alien solo necesita proporcionar estos métodos para ajustarse a la interfaz de Alien::Base:

cflags
Cadena que contiene los flags del compilador
libs
Cadena que contiene los flags del enlazador y las bibliotecas
dynamic_libs
Lista de bibliotecas dinámicas. Devuelve una lista vacía si el módulo Alien no proporciona esto.
bin_dir
Directorio que contiene los binarios de herramientas. Devuelve una lista vacía si el módulo Alien no proporciona esto.

Si tu módulo Alien no se ajusta a esta interfaz, puedes crear un módulo Alien sintético usando la función "synthetic".

synthetic

my $alien = synthetic \%config;

Crea un módulo Alien sintético que puede ser pasado a "alien_ok". "\%config" puede contener estas claves (todas opcionales):

cflags
Cadena que contiene los flags del compilador.
cflags_static
Cadena que contiene los flags estáticos del compilador (opcional).
libs
Cadena que contiene los flags del enlazador y las bibliotecas.
libs_static
Cadena que contiene los flags estáticos del enlazador (opcional).
dynamic_libs
Referencia a una lista que contiene las bibliotecas dinámicas.
bin_dir
Directorio de binarios de herramientas.
runtime_prop
Propiedades de tiempo de ejecución.

Ver Test::Alien::Synthetic para más detalles.

run_ok

my $run = run_ok $command;
my $run = run_ok $command, $message;

Ejecuta el comando dado, recurriendo a cualquier método "Alien::Base#bin_dir" proporcionado por módulos Alien especificados con "alien_ok".

$command puede ser una cadena o una referencia a un array.

Solo falla si el comando no se puede encontrar, o si es terminado por una señal. Devuelve un objeto Test::Alien::Run, que puedes usar para probar el estado de salida, la salida y el error estándar.

Siempre devuelve una instancia de Test::Alien::Run, incluso si el comando no se pudo encontrar.

xs_ok

xs_ok $xs;
xs_ok $xs, $message;

Compila, enlaza el código "XS" dado y se adjunta a Perl.

Si usas el nombre de módulo especial "TA_MODULE" en tu código "XS", será reemplazado por un nombre de paquete generado automáticamente. Esto puede ser útil si deseas pasar el mismo código "XS" a múltiples llamadas a "xs_ok" sin que las llamadas subsiguientes reemplacen a las anteriores.

$xs puede ser una cadena que contiene el código "XS", o una referencia a un hash con estas claves:

xs
El código XS. Este es el único elemento requerido.
pxs
Argumentos adicionales de ExtUtils::ParseXS pasados como una referencia a un hash.
cbuilder_check
La comprobación de compilación que debe realizarse antes de intentar construir. Debe ser una de "have_compiler" o "have_cplusplus". El valor por defecto es "have_compiler".
cbuilder_config
Hash para anular valores normalmente proporcionados por "Config".
cbuilder_compile
Argumentos adicionales de ExtUtils::CBuilder pasados como una referencia a un hash.
cbuilder_link
Argumentos adicionales de ExtUtils::CBuilder pasados como una referencia a un hash.
verbose
Muestra información de depuración copiosa a través de notas de prueba.

Puedes usar la palabra clave "with_subtest" para ejecutar condicionalmente una subprueba si la llamada "xs_ok" tiene éxito. Si "xs_ok" no funciona, entonces la subprueba fallará.

ffi_ok

ffi_ok \%options;
ffi_ok \%options, $message;

Prueba que los símbolos especificados están disponibles en la biblioteca alien.

\%options es un hash de las siguientes claves:

symbols
Un array de referencias de cadenas que contienen los nombres de los símbolos que deben estar disponibles en la biblioteca.
shared_libs
Una lista de referencias de cadenas que contienen los nombres de las bibliotecas compartidas. Si no se especifica, se utilizará "dynamic_libs" de la última llamada a "alien_ok".
xs
Se utilizará si FFI::Platypus no está instalado. Debe ser una cadena que contenga código XS que llame a los símbolos especificados.

Se puede utilizar la palabra clave "with_subtest" para ejecutar condicionalmente una subprueba si la llamada "ffi_ok" tiene éxito. Si "ffi_ok" no funciona, entonces la subprueba fallará.

with_subtest

with_subtest {
  # tu codigo
};

Esto se utiliza para ejecutar condicionalmente una subprueba en caso de éxito de la prueba principal. El código dentro de la subprueba se ejecutará solo si la prueba anterior (como "xs_ok" o "ffi_ok") tuvo éxito. Si la prueba principal falla, la subprueba se omite y la prueba general se marca como exitosa (si todas las demás pruebas lo están).

La subprueba recibe como argumento la instancia de la prueba creada por la llamada anterior (por ejemplo, el objeto de compilación de "xs_ok" o el objeto FFI de "ffi_ok").

NAME

Test::Alien - Alien Build testing helpers

VERSION

v2.84

SYNOPSIS

 use Test::Alien;

 # Check that a given alien is available
 alien_ok $alien_name;
 alien_ok $alien_name, $message;

 # Check that a given alien can be compiled
 alien_ok $alien_name, compile => 1;
 alien_ok $alien_name, compile => 1, $message;

 # Check that a given alien can be compiled and installed
 alien_ok $alien_name, install => 1;
 alien_ok $alien_name, install => 1, $message;

 # Check that a given alien can be compiled and installed into a specific
 # directory
 alien_ok $alien_name, prefix => '/some/path';
 alien_ok $alien_name, prefix => '/some/path', $message;

 # Check that a given alien can be compiled and installed into a specific
 # directory with a custom build option
 alien_ok $alien_name, prefix => '/some/path', configure_args => '--with-foo';
 alien_ok $alien_name, prefix => '/some/path', configure_args => '--with-foo', $message;

 # Check that a given alien can be compiled and installed into a specific
 # directory with custom build options
 alien_ok $alien_name, prefix => '/some/path', configure_args => ['--with-foo', '--enable-bar'];
 alien_ok $alien_name, prefix => '/some/path', configure_args => ['--with-foo', '--enable-bar'], $message;

 # Check that a given alien has a specific version
 alien_ok $alien_name, version => '1.2.3';
 alien_ok $alien_name, version => '1.2.3', $message;

 # Check that a given alien has a version that is at least a specific version
 alien_ok $alien_name, version => '>=1.2.3';
 alien_ok $alien_name, version => '>=1.2.3', $message;

 # Check that a given alien has a version that is at least a specific version,
 # and also ensure it compiles
 alien_ok $alien_name, version => '>=1.2.3', compile => 1;
 alien_ok $alien_name, version => '>=1.2.3', compile => 1, $message;

 # Check that a given alien can be compiled, installed, and has a specific
 # version
 alien_ok $alien_name, version => '>=1.2.3', compile => 1, install => 1;
 alien_ok $alien_name, version => '>=1.2.3', compile => 1, install => 1, $message;

 # Check that the alien is available by running a command provided by it
 alien_run_ok $alien_name, $command;
 alien_run_ok $alien_name, $command, $message;

 # Check that the alien is available by running a command provided by it,
 # and checking that the output matches a regex
 alien_run_ok $alien_name, $command, $regex;
 alien_run_ok $alien_name, $command, $regex, $message;

 # Check that the alien is available by running a command provided by it,
 # and checking that the output matches a string
 alien_run_ok $alien_name, $command, $string;
 alien_run_ok $alien_name, $command, $string, $message;

 # Check that a specific C/C++ library is available
 library_ok $library_name;
 library_ok $library_name, $message;

 # Check that a specific C/C++ library can be compiled into a test executable
 library_ok $library_name, compile => 1;
 library_ok $library_name, compile => 1, $message;

 # Check that a specific C/C++ library can be compiled and installed into a
 # test executable
 library_ok $library_name, install => 1;
 library_ok $library_name, install => 1, $message;

 # Check that a specific C/C++ library can be compiled and installed into a
 # test executable, and can be linked to
 library_ok $library_name, link => 1;
 library_ok $library_name, link => 1, $message;

 # Check that the library is available by running a command provided by it
 library_run_ok $library_name, $command;
 library_run_ok $library_name, $command, $message;

 # Check that the library is available by running a command provided by it,
 # and checking that the output matches a regex
 library_run_ok $library_name, $command, $regex;
 library_run_ok $library_name, $command, $regex, $message;

 # Check that the library is available by running a command provided by it,
 # and checking that the output matches a string
 library_run_ok $library_name, $command, $string;
 library_run_ok $library_name, $command, $string, $message;

 # Check that the given Perl module can be compiled with ExtUtils::MakeMaker
 xs_ok $module_name;
 xs_ok $module_name, $message;

 # Check that the given Perl module can be compiled with ExtUtils::MakeMaker
 # and that the C code passes tests
 xs_ok $module_name, test => 1;
 xs_ok $module_name, test => 1, $message;

 # Check that the given Perl module can be compiled with ExtUtils::MakeMaker
 # and that the C code passes tests, and that the test executable is run
 # with the module name passed into the subtest
 xs_ok $module_name, with_subtest => 1;
 xs_ok $module_name, with_subtest => 1, $message;

 # Check that FFI::Platypus works
 ffi_ok;
 ffi_ok \%opt;
 ffi_ok \%opt, $message;

 # Check that a helper is defined
 helper_ok $helper_name;
 helper_ok $helper_name, $message;

 # Apply a plugin to the interpolator
 plugin_ok $plugin_name;
 plugin_ok [$plugin_name, @args];
 plugin_ok $plugin_name, $message;
 plugin_ok [$plugin_name, @args], $message;

 # Check that a template interpolates correctly
 interpolate_template_is $template, $string;
 interpolate_template_is $template, $string, $message;
 interpolate_template_is $template, $regex;
 interpolate_template_is $template, $regex, $message;

 # Run a command through the interpolator
 interpolate_run_ok $command;
 interpolate_run_ok $command, $message;

DESCRIPTION

This module provides a set of testing utilities for ensuring that foreign libraries and tools can be found, compiled, installed, and used from Perl. It is primarily intended to be used by modules that depend on specific versions of foreign libraries.

The main idea behind Test::Alien is that you can use the Alien Perl module to install and manage foreign libraries, and then use Test::Alien to verify that the installed libraries can be used.

FUNCTIONS

alien_ok

alien_ok $name;
alien_ok $name, $message;
alien_ok $name, \%opt;
alien_ok $name, \%opt, $message;

Checks that the alien named "$name" is available. If "\&\%opt" is specified, it can contain the following keys:

compile
If true, this will also try to compile the alien.
install
If true, this will also try to install the alien.
prefix
If specified, this will install the alien to the specified directory. This is useful for testing that an alien can be installed into a specific location.
configure_args
A string or array reference of arguments to pass to the alien's configure script. This is useful for testing that an alien can be configured with specific options.
version
A version string (e.g., "1.2.3") or a version range (e.g., ">=1.2.3") to check against the installed alien. This requires that the alien has been installed.

If the alien is not found or any of the specified checks fail, the test will fail.

alien_run_ok

alien_run_ok $name, $command;
alien_run_ok $name, $command, $message;
alien_run_ok $name, $command, $regex;
alien_run_ok $name, $command, $regex, $message;
alien_run_ok $name, $command, $string;
alien_run_ok $name, $command, $string, $message;

Checks that the alien named "$name" is available, and that the specified "$command" can be run. If a "$regex" or "$string" is provided, it will also check that the output of the command matches the given regex or string.

This function is useful for testing that an alien provides a specific executable and that it behaves as expected.

library_ok

library_ok $name;
library_ok $name, $message;
library_ok $name, \%opt;
library_ok $name, \%opt, $message;

Checks that the C/C++ library named "$name" is available. If "\&\%opt" is specified, it can contain the following keys:

compile
If true, this will also try to compile a test program that links against the library.
install
If true, this will also try to install the library.
link
If true, this will also try to compile a test program that links against the library and runs it.
version
A version string (e.g., "1.2.3") or a version range (e.g., ">=1.2.3") to check against the installed library. This requires that the library has been installed.

If the library is not found or any of the specified checks fail, the test will fail.

library_run_ok

library_run_ok $name, $command;
library_run_ok $name, $command, $message;
library_run_ok $name, $command, $regex;
library_run_ok $name, $command, $regex, $message;
library_run_ok $name, $command, $string;
library_run_ok $name, $command, $string, $message;

Checks that the library named "$name" is available, and that the specified "$command" can be run. If a "$regex" or "$string" is provided, it will also check that the output of the command matches the given regex or string.

This function is useful for testing that a library provides a specific executable and that it behaves as expected.

xs_ok

xs_ok $module;
xs_ok $module, $message;

Test that the given Perl module can be compiled using ExtUtils::MakeMaker. This is useful for testing modules that have C extensions.

If $message is provided, it will be used as the test description.

xs_ok $module, test => 1;
xs_ok $module, test => 1, $message;

If test => 1 is provided, then the test executable will be run after compilation. The test executable is expected to exit with status 0 if successful.

Note that temporary files generated by the compilation process will be automatically removed if the test fails. They will only be kept if the test passes, and only if the "TEST_ALIEN_ALWAYS_KEEP" environment variable is not set (see "ENVIRONMENT" below).

xs_ok $module, with_subtest => 1;
xs_ok $module, with_subtest => 1, $message;

If with_subtest => 1 is provided, then the test executable will be run after compilation, and its output will be wrapped in a subtest. This is useful for testing XS code that itself uses a testing framework like Test::More. The module name detected during the XS parsing phase will be passed in to the subtest. This is helpful when you are using a generated module name.

If you need to test XS C++ interfaces, see Test::Alien::CPP.

Caveats: "xs_ok" uses ExtUtils::ParseXS, which may call "exit" under certain error conditions. While this is not really good thing to happen in the middle of a test, it usually indicates a real failure condition, and it should return a failure condition so the test should still fail overall.

[version 2.53]

As of version 2.53, "xs_ok" will only remove temporary generated files if the test is successful by default. You can force either always or never removing the temporary generated files using the "TEST_ALIEN_ALWAYS_KEEP" environment variable (see "ENVIRONMENT" below).

ffi_ok

ffi_ok;
ffi_ok \%opt;
ffi_ok \%opt, $message;

Test that FFI::Platypus works.

"\&\%opt" is a hash reference with these keys (all optional):

symbols
List references of symbols that must be found for the test to succeed.
ignore_not_found
Ignores symbols that aren't found. This affects functions accessed via FFI::Platypus#attach and FFI::Platypus#function methods, and does not influence the "symbols" key above.
lang
Set the language. Used primarily for language specific native types.
api
Set the API. "api = 1" requires FFI::Platypus 0.99 or later. This option was added with Test::Alien version 1.90, so your use line should include this version as a safeguard to make sure it works: 
use Test::Alien 1.90;
...
ffi_ok ...;

As with "xs_ok" above, you can use the "with_subtest" keyword to specify a subtest to be run if "ffi_ok" succeeds (it will skip otherwise). The FFI::Platypus instance is passed into the subtest as the first argument. For example:

ffi_ok with_subtest => sub {
  my($ffi) = @_;
  is $ffi->function(foo => [] => 'void')->call, 42;
};

helper_ok

helper_ok $name;
helper_ok $name, $message;

Tests that the given helper has been defined.

plugin_ok

[version 2.52]

plugin_ok $plugin_name, $message;
plugin_ok [$plugin_name, @args], $message;

This applies an Alien::Build::Plugin to the interpolator used by "helper_ok", "interpolate_template_is" and "interpolate_run_ok" so that you can test with any helpers that plugin provides. Useful, for example for getting "%{configure}" from Alien::Build::Plugin::Build::Autoconf.

interpolate_template_is

interpolate_template_is $template, $string;
interpolate_template_is $template, $string, $message;
interpolate_template_is $template, $regex;
interpolate_template_is $template, $regex, $message;

Tests that the given template when evaluated with the appropriate helpers will match either the given string or regular expression.

interpolate_run_ok

[version 2.52]

my $run = interpolate_run_ok $command;
my $run = interpolate_run_ok $command, $message;

This is the same as "run_ok" except it runs the command through the interpolator first.

ENVIRONMENT

"TEST_ALIEN_ALWAYS_KEEP"
If this is defined then it will override the built in logic that decides if the temporary files generated by "xs_ok" should be kept when the test file terminates. If set to true the generated files will always be kept. If set to false, then they will always be removed.
"TEST_ALIEN_ALIENS_MISSING"
By default, this module will warn you if some tools are used without first invoking "alien_ok". This is usually a mistake, but if you really do want to use one of these tools with no aliens loaded, you can set this environment variable to false.
