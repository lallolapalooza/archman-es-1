Template::Plugin(3) Documentación de Perl aportada por el usuario Template::Plugin(3)

NOMBRE

Template::Plugin - Clase base para plugins de Template Toolkit

SINOPSIS

package MyOrg::Template::Plugin::MyPlugin;
use base qw( Template::Plugin );
use Template::Plugin;
use MyModule;
sub new {
    my $class   = shift;
    my $context = shift;
    bless {
        ...
    }, $class;
}

DESCRIPCIÓN

Un "plugin" para Template Toolkit es simplemente un módulo Perl que existe en una ubicación de paquete conocida (por ejemplo, "Template::Plugin::*") y se ajusta a un estándar regular, lo que permite cargarlo y utilizarlo automáticamente.

El módulo "Template::Plugin" define una clase base de la cual se pueden derivar otros módulos de plugin. Un plugin no tiene que derivarse de Template::Plugin, pero al menos debe ajustarse a su interfaz orientada a objetos.

Se recomienda crear plugins en su propio espacio de nombres de paquete para evitar conflictos con los plugins del toolkit. Por ejemplo:

package MyOrg::Template::Plugin::FooBar;

Utilice la opción PLUGIN_BASE para especificar el espacio de nombres que utiliza. Por ejemplo:

use Template;
my $template = Template->new({
    PLUGIN_BASE => 'MyOrg::Template::Plugin',
});

MÉTODOS

Los siguientes métodos forman la interfaz básica entre Template Toolkit y los módulos de plugin.

load($context)

Este método es llamado por Template Toolkit cuando el módulo de plugin se carga por primera vez. Se llama como un método de paquete y, por lo tanto, recibe implícitamente el nombre del paquete como primer parámetro. También se pasa una referencia al objeto Template::Context que carga el plugin. El comportamiento predeterminado para el método load() es simplemente devolver el nombre de la clase. El contexto que llama utiliza entonces este nombre de clase para llamar al método de paquete new().

package MyPlugin;
sub load {               # llamado como MyPlugin->load($context)
    my ($class, $context) = @_;
    return $class;       # devuelve 'MyPlugin'
}

new($context, @params)

Este método se llama para instanciar un nuevo objeto de plugin para la directiva "USE". Se llama como un método de paquete contra el nombre de clase devuelto por load(). Se pasa una referencia al objeto Template::Context que crea el plugin, junto con cualquier parámetro adicional especificado en la directiva "USE".

sub new {                # llamado como MyPlugin->new($context)
    my ($class, $context, @params) = @_;
    bless {
        _CONTEXT => $context,
    }, $class;           # devuelve un objeto MyPlugin bendecido
}

error($error)

Este método, heredado del módulo Template::Base, se utiliza para informar y devolver errores. Puede llamarse como un método de paquete para establecer/devolver la variable de paquete $ERROR, o como un método de objeto para establecer/devolver el miembro de objeto "_ERROR". Cuando se llama con un argumento, establece la variable relevante y devuelve "undef." Cuando se llama sin argumento, devuelve el valor de la variable.

package MyPlugin;
use base 'Template::Plugin';
sub new {
    my ($class, $context, $dsn) = @_;
    return $class->error('No data source specified')
        unless $dsn;
    bless {
        _DSN => $dsn,
    }, $class;
}
package main;
my $something = MyPlugin->new()
    || die MyPlugin->error(), "\n";
$something->do_something()
    || die $something->error(), "\n";

MAGIA MÁS PROFUNDA

El objeto Template::Context que maneja la carga y el uso de plugins llama a los métodos new() y error() contra el nombre del paquete devuelto por el método load(). En pseudocódigo, se parece un poco a esto:

$class  = MyPlugin->load($context);       # devuelve 'MyPlugin'
$object = $class->new($context, @params)  # MyPlugin->new(...)
    || die $class->error();               # MyPlugin->error()

El método load() puede devolver alternativamente una referencia bendecida a una instancia de objeto. En este caso, new() y error() se llaman entonces como métodos de *objeto* contra esa instancia prototipo.

package YourPlugin;
sub load {
    my ($class, $context) = @_;
    bless {
        _CONTEXT => $context,
    }, $class;
}
sub new {
    my ($self, $context, @params) = @_;
    return $self;
}

En este ejemplo, hemos implementado un plugin 'Singleton'. Se crea un objeto cuando se llama a load() y este simplemente se devuelve a sí mismo por cada llamada a new().

Otra implementación podría requerir que se creen objetos individuales para cada llamada a new(), pero con cada objeto compartiendo una referencia a algún otro objeto para mantener datos en caché, manejadores de bases de datos, etc. Este ejemplo de pseudocódigo demuestra el principio.

package MyServer;
sub load {
    my ($class, $context) = @_;
    bless {
        _CONTEXT => $context,
        _CACHE   => { },
    }, $class;
}
sub new {
    my ($self, $context, @params) = @_;
    MyClient->new($self, @params);
}
sub add_to_cache   { ... }
sub get_from_cache { ... }
package MyClient;
sub new {
    my ($class, $server, $blah) = @_;
    bless {
        _SERVER => $server,
        _BLAH   => $blah,
    }, $class;
}
sub get {
    my $self = shift;
    $self->{ _SERVER }->get_from_cache(@_);
}
sub put {
    my $self = shift;
    $self->{ _SERVER }->add_to_cache(@_);
}

Cuando se carga el plugin, se crea una instancia de "MyServer". Se llama al método new() contra este objeto, que instancia y devuelve un objeto "MyClient", preparado para comunicarse con el "MyServer" que lo creó.
