Test2::Manual::Tooling::Nesting(3perl) Guía de referencia del programador de Perl Test2::Manual::Tooling::Nesting(3perl)

NOMBRE

Test2::Manual::Tooling::Nesting - Tutorial para usar otras herramientas dentro de las tuyas.

DESCRIPCIÓN

A veces te encuentras escribiendo el mismo patrón de prueba una y otra vez, en tales casos podrías querer encapsular la lógica en una nueva función de prueba que llama a varias herramientas juntas. Esto suena fácil, pero puede causar dolores de cabeza si no se hace correctamente.

FORMA NAÏVE

Digamos que te encuentras escribiendo el mismo patrón de prueba una y otra vez para múltiples objetos:

my $obj1 = $class1->new;
is($obj1->foo, 'foo', "conseguí foo");
is($obj1->bar, 'bar', "conseguí bar");
my $obj2 = $class1->new;
is($obj2->foo, 'foo', "conseguí foo");
is($obj2->bar, 'bar', "conseguí bar");
... 10 veces más para las clases 2-12

La forma naïve de hacer esto es escribir una función check_class() como esta:

sub check_class {
    my $class = shift;
    my $obj = $class->new;
    is($obj->foo, 'foo', "conseguí foo");
    is($obj->bar, 'bar', "conseguí bar");
}
check_class($class1);
check_class($class2);
check_class($class3);
...

Esto parecerá funcionar bien, y podrías no notar ningún problema, *siempre y cuando las pruebas pasen*.

¿QUÉ ESTÁ MAL EN ELLO?

Los problemas con el enfoque naïve se vuelven obvios si las cosas empiezan a fallar. Los diagnósticos que te dicen en qué archivo y línea ocurrió el fallo serán incorrectos. El fallo se informará en la línea *dentro* de "check_class", no en la línea donde se llamó a check_class(). Esto es un problema porque no te deja saber qué clase está fallando.

CÓMO SOLUCIONARLO

Afortunadamente, esto es extremadamente fácil de solucionar. Necesitas adquirir un objeto de contexto al inicio de tu función, y liberarlo al final... sí, es así de simple.

use Test2::API qw/context/;
sub check_class {
    my $class = shift;
    my $ctx = context();
    my $obj = $class->new;
    is($obj->foo, 'foo', "conseguí foo");
    is($obj->bar, 'bar', "conseguí bar");
    $ctx->release;
}

Ves, fue fácil. Con estas 2 líneas adicionales ahora tenemos un informe adecuado de archivo+línea. Las herramientas anidadas encontrarán el contexto que adquirimos aquí, y sabrán usar sus números de archivo y línea.

*LA VIEJA FORMA (NO LO HAGAS MÁS)*

Con Test::Builder había una variable global llamada $Test::Builder::Level que ayudaba a resolver este problema:

sub check_class {
    my $class = shift;
    local $Test::Builder::Level = $Test::Builder::Level + 1;
    my $obj = $class->new;
    is($obj->foo, 'foo', "conseguí foo");
    is($obj->bar, 'bar', "conseguí bar");
}

Esta variable funcionó lo suficientemente bien (y seguirá funcionando), pero no era muy descubrible. Otro problema con esta variable es que se vuelve engorrosa si tienes una estructura de código más profundamente anidada que llama a las herramientas anidadas, podrías necesitar contar los marcos de la pila, y esperar que nunca cambien debido a un módulo de terceros. La solución de contexto no tiene tales advertencias.
