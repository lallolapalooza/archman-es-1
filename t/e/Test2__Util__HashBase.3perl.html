NOMBRE

Test2::Util::HashBase - Construye clases basadas en hashes.

SINOPSIS

Una clase:

package My::Class;
use strict;
use warnings;
# Genera 3 accesores
use Test2::Util::HashBase qw/foo -bar ^baz <bat >ban +boo/;
# Oportunidad para inicializar valores por defecto
sub init {
    my $self = shift;    # Sin otros argumentos
    $self->{+FOO} ||= "foo";
    $self->{+BAR} ||= "bar";
    $self->{+BAZ} ||= "baz";
    $self->{+BAT} ||= "bat";
    $self->{+BAN} ||= "ban";
    $self->{+BOO} ||= "boo";
}
sub print {
    print join ", " => map { $self->{$_} } FOO, BAR, BAZ, BAT, BAN, BOO;
}

Subclase:

package My::Subclass;
use strict;
use warnings;
# Nota, deberías subclasar antes de cargar HashBase.
use base 'My::Class';
use Test2::Util::HashBase qw/bub/;
sub init {
    my $self = shift;
    # Obtenemos las constantes de la clase base de forma gratuita.
    $self->{+FOO} ||= 'SubFoo';
    $self->{+BUB} ||= 'bub';
    $self->SUPER::init();
}

úselo:

package main;
use strict;
use warnings;
use My::Class;
# Estos son funcionalmente idénticos
my $one   = My::Class->new(foo => 'MyFoo', bar => 'MyBar');
my $two   = My::Class->new({foo => 'MyFoo', bar => 'MyBar'});
my $three = My::Class->new(['MyFoo', 'MyBar']);
# Lectores!
my $foo = $one->foo;    # 'MyFoo'
my $bar = $one->bar;    # 'MyBar'
my $baz = $one->baz;    # Por defecto: 'baz'
my $bat = $one->bat;    # Por defecto: 'bat'
# '>ban' significa solo setter, sin lector
# '+boo' significa sin setter ni lector, solo la constante BOO
# Setters!
$one->set_foo('A Foo');
#'-bar' significa solo lectura, por lo que el setter lanzará una excepción (pero está definido).
$one->set_bar('A bar');
# '^baz' significa setter obsoleto, esto advertirá sobre el setter obsoleto.
$one->set_baz('A Baz');
# '<bat' significa que no hay setter definido en absoluto
# '+boo' significa sin setter ni lector, solo la constante BOO
$one->{+FOO} = 'xxx';

DESCRIPCIÓN

Este paquete se utiliza para generar clases basadas en referencias a hashes. El uso de esta clase te proporcionará un método new(), así como generará los accesores que solicites. Los accesores generados serán lectores (getters), y también se generarán métodos de escritura (setters) "set_ACCESOR". También obtienes constantes para cada accesorio (en mayúsculas) que devuelven la clave en el hash para ese accesorio. La herencia simple también es compatible.

MÉTODOS

PROPORCIONADOS POR HASH BASE

$it = $class->new(%PAIRS)
$it = $class->new(\%PAIRS)
$it = $class->new(\@ORDERED_VALUES)
Crea una nueva instancia.

HashBase no exportará new() si ya existe un método new() en la cadena de herencia de tu paquete.

Si no deseas este método, puedes definir el tuyo propio, solo tienes que declararlo antes de cargar Test2::Util::HashBase.

package My::Package;
# Predeclaramos new() para que HashBase no nos proporcione uno.
sub new;
use Test2::Util::HashBase qw/foo bar baz/;
# Ahora definimos nuestro propio método new.
sub new { ... }

Esto hace que HashBase vea que tienes tu propio método new(). Alternativamente, puedes definir el método antes de cargar HashBase en lugar de solo declararlo, pero eso dispersa tus declaraciones `use`.

La forma más común de crear un objeto es pasar pares clave/valor donde cada clave es un atributo y cada valor es lo que deseas asignar a ese atributo. No se realiza ninguna verificación para verificar si los atributos o valores son válidos; puedes hacerlo en init() si lo deseas.

Si lo deseas, puedes pasar una referencia a hash en lugar de pares. Cuando lo hagas, la referencia a hash se copiará y la copia se devolverá bendecida como un objeto. No hay forma de pedirle a HashBase que bendiga una referencia a hash específica.

En algunos casos, un objeto puede tener solo 1 o 2 atributos, en cuyo caso una referencia a hash puede ser demasiado verbosa para tu gusto. En estos casos, puedes pasar una referencia a array solo con valores. Los valores se asignarán a los atributos en el orden en que se enumeraron los atributos. Cuando hay herencia involucrada, los atributos de las clases padre vendrán antes que las subclases.

GANCHOS

$self->init()
Esto te da la oportunidad de establecer algunos valores predeterminados para tus campos. El único argumento es $self con sus índices ya establecidos desde el constructor.

Nota: Test2::Util::HashBase verifica la existencia de un método init usando "$class->can('init')" durante la construcción. NO llama a can() en el objeto creado. Ten en cuenta también que el resultado de la verificación se almacena en caché, solo se verifica una vez, la primera vez que se crea una instancia de tu clase. Esto significa que agregar un método init() DESPUÉS de la primera construcción resultará en que sea ignorado.

ACCESORES

LECTURA/ESCRITURA

Para generar accesores, enuméralos al usar el módulo:

use Test2::Util::HashBase qw/foo/;

Esto generará los siguientes subs en tu espacio de nombres:

foo()
Lector (getter), se utiliza para obtener el valor del campo "foo".
set_foo()
Escritor (setter), se utiliza para establecer el valor del campo "foo".
FOO()
Constante, devuelve la clave del campo "foo" en el hash de la clase. Las subclases también obtendrán esta función como una constante, no simplemente como un método, lo que significa que se copia en el espacio de nombres de la subclase.

La razón principal para usar estas constantes es ayudar a evitar errores de ortografía y errores tipográficos similares. No te ayudará si olvidas prefijar el '+' de todos modos.

SOLO LECTURA

use Test2::Util::HashBase qw/-foo/;
set_foo()
Lanza una excepción indicando que el atributo es de solo lectura. Esto se exporta para anular cualquier setter activo para el atributo en una clase padre.

SETTER OBSOLETO

use Test2::Util::HashBase qw/^foo/;
set_foo()
Establecerá el valor, pero también te advertirá que el método está obsoleto.

SIN SETTER

use Test2::Util::HashBase qw/<foo/;

Solo proporciona un lector, no se define ningún método "set_foo" en absoluto.

SIN LECTOR

use Test2::Util::HashBase qw/>foo/;

Solo proporciona un método de escritura ("set_foo"), no se define ningún método "foo" en absoluto.

SOLO CONSTANTE

use Test2::Util::HashBase qw/+foo/;

Esto no crea ningún método para ti, solo agrega la constante "FOO".

SUBCLASES

La herencia simple es compatible. Cuando crees una subclase, carga Test2::Util::HashBase para los nuevos atributos de la subclase, pero asegúrate de que la clase base ya esté cargada.

Por ejemplo:

package My::Class;
use Test2::Util::HashBase qw/foo bar/;
package My::SubClass;
use base 'My::Class';
use Test2::Util::HashBase qw/baz/;
# Ahora puedes usar foo, bar, y baz
# Tambien puedes sobrescribir los atributos de la clase base
sub init {
    my $self = shift;
    $self->SUPER::init(); # Asegurate de llamar a la inicializacion base
    $self->{+BAZ} ||= 'baz';
}

SUBCLASSING

Puede crear subclases de una clase HashBase existente.

use base 'Another::HashBase::Class';
use Test2::Util::HashBase qw/foo bar baz/;

La clase base se agrega a @ISA por usted, y todas las constantes de las clases base se agregan a las subclases automáticamente.

OBTENER UNA LISTA DE ATRIBUTOS PARA UNA CLASE

Test2::Util::HashBase proporciona una función para recuperar una lista de atributos para una clase Test2::Util::HashBase.

@list = Test2::Util::HashBase::attr_list($class)
@list = $class->Test2::Util::HashBase::attr_list()
Cualquiera de las formas anteriores funcionará. Esto devolverá una lista de atributos definidos en el objeto. Esta lista se devuelve en el orden de definición de atributos, los atributos de la clase padre se enumeran antes que los atributos de la subclase. Los atributos duplicados se eliminarán antes de devolver la lista.

Nota: Esta lista se utiliza en el constructor "$class->new(\@ARRAY)" para determinar el atributo al que se emparejará cada valor.
