NOMBRE

Test2::V0 - Paquete recomendado de la 0ª edición de Test2.

DESCRIPCIÓN

Este es el paquete principal. Este paquete incluye casi todas las herramientas y varios complementos que usa el autor de Test2. Este paquete se utiliza ampliamente para probar Test2::Suite.

NOMBRADO, USO, DEPENDIENDO

Este paquete no debería cambiar de una manera *severamente* incompatible. Se pueden permitir algunos cambios menores que rompen la compatibilidad, especialmente correcciones de errores. Si se necesitan cambios que rompan la compatibilidad, se debería lanzar un nuevo módulo "Test2::V#" en su lugar.

A medida que se lancen nuevos módulos "V#", los antiguos *pueden* moverse a diferentes distribuciones de cpan. Siempre debes usar una versión específica del paquete y listar esa versión en los requisitos de prueba de tus distribuciones. Nunca debes simplemente listar Test2::Suite como dependencia de tus módulos, en su lugar, lista el paquete específico, o las herramientas y complementos que usas directamente en tus metadatos.

SINOPSIS

use Test2::V0;
ok(1, "pass");
...
done_testing;

RESOLVER CONFLICTOS CON MOOSE

use Test2::V0 '!meta';

Moose y Test2::V0 exportan subs meta() muy diferentes. Añadir '!meta' a los argumentos de importación impedirá que la sub se importe. Este paquete también exporta la sub con el nombre meta_check() para que puedas usar esa ortografía como alternativa.

ETIQUETAS

:DEFAULT
Los siguientes son idénticos: 
use Test2::V0;
use Test2::V0 ':DEFAULT';

RENOMBRAR EN LA IMPORTACIÓN

use Test2::V0 ':DEFAULT', '!ok', ok => {-as => 'my_ok'};

Este paquete utiliza Test2::Util::Importer para exportar, por lo tanto, puedes usar cualquier argumento que acepte.

Explicación:

'!ok'
No exportar ok()
ok => {-as => 'my_ok'}
De hecho, importa ok() pero bajo el nombre my_ok().

Si no hubieras añadido el argumento '!ok', tendrías tanto ok() como my_ok()

PRAGMAS

Todos estos se pueden deshabilitar mediante argumentos de importación individuales, o mediante el argumento "-no_pragmas".

use Test2::V0 -no_pragmas => 1;

ESTRICTO

strict está activado para ti. Puedes deshabilitarlo con los argumentos de importación "-no_strict" o "-no_pragmas":

use Test2::V0 -no_strict => 1;

ADVERTENCIAS

warnings está activado para ti. Puedes deshabilitarlo con los argumentos de importación "-no_warnings" o "-no_pragmas":

use Test2::V0 -no_warnings => 1;

UTF8

Esto se hace en realidad a través del plugin Test2::Plugin::UTF8, consulta la sección "PLUGINS" para más detalles.

Nota: "-no_pragmas => 1" desactivará todo el plugin.

PLUGINS

SRAND

Ver Test2::Plugin::SRand.

Esto establecerá la semilla aleatoria en la fecha de hoy. Puedes proporcionar una semilla alternativa con la opción de importación "-srand":

use Test2::V0 -srand => 1234;

También puedes deshabilitar este comportamiento:

use Test2::V0 -no_srand => 1;

Nota: Cuando srand está activado (por defecto) puede causar problemas con cosas como File::Temp, que terminarán intentando usar los mismos nombres de archivo "aleatorios" para cada proceso de prueba iniciado en un día determinado (o que comparten la misma semilla).

UTF8

Ver Test2::Plugin::UTF8.

Esto establecerá el archivo y todos los manejadores de salida (incluidos los manejadores de formato) a utf8. Esto activará el pragma utf8 para el ámbito actual.

Esto se puede deshabilitar usando los argumentos de importación "-no_utf8 => 1" o "-no_pragmas => 1".

use Test2::V0 -no_utf8 => 1;

RESUMEN DE SALIDA

Este plugin no tiene configuración.

HERRAMIENTAS

OBJETIVO

Ver Test2::Tools::Target.

Puedes especificar una clase objetivo con el argumento de importación "-target". Si no proporcionas un objetivo, $CLASS y CLASS() no se importarán.

use Test2::V0 -target => 'My::Class';
print $CLASS;  # My::Class
print CLASS(); # My::Class

O puedes especificar nombres:

use Test2::V0 -target => { pkg => 'Some::Package' };
pkg()->xxx; # Llama 'xxx' en Some::Package
$pkg->xxx;  # Lo mismo
$CLASS
Variable de paquete que contiene el nombre de la clase objetivo.
$class = CLASS()
Función constante que devuelve el nombre de la clase objetivo.

DIFERIR

Ver Test2::Tools::Defer.

def $func => @args;
do_def()

NAME

Test2::V0 - The core Test2 API

DESCRIPTION

This module exports the core API for the Test2 testing framework.

The primary goal of Test2 is to provide a testing framework that is both powerful and extensible, without being overly difficult to use. It is designed to replace Test::More.

This module exports most of the functions provided by Test2::Bundle::Basic, as well as a few other useful functions.

NAMING, USING, DEPENDING

When you write a test file you should start with:

use Test2::V0;

This will import all the necessary functions for you.

If you need to install other tools for testing you will often need to depend on them.

use Test2::V0 qw(:DEFAULT COMPACT);
use Test2::Tools::Pretty;
use Test2::Tools::Exception;

SYNOPSIS

use Test2::V0 qw(:DEFAULT BUILD);

my $array = [ 1, 2, 3 ];
is($array, [ 1, 2, 3 ], 'Array is correct');

my $hash = { a => 1, b => 2 };
is($hash, { a => 1, b => 2 }, 'Hash is correct');

my $obj = MyClass->new;
can_ok($obj, 'method_name');
isa_ok($obj, 'MyClass');

subtest 'subtest example' => sub {
    ok(1, 'passed');
    done_testing;
};

done_testing;

RESOLVING CONFLICTS WITH MOOSE

If you are using Moose, or any other OO system that exports routines with the same name as routines in Test2, you may run into import conflicts. You can resolve these conflicts by explicitly listing the routines you wish to import, or by using the import tags.

# Explicitly list
use Test2::V0 qw(ok diag plan);

# Or use import tags
use Test2::V0 qw(:DEFAULT diag);

PRAGMAS

Test2 provides a number of pragmas that can be used to control the behavior of tests.

no_plan
Turns off the need for an explicit plan. This is the default behavior in Test2.
plan
Explicitly sets the plan for the test suite. This can be a number, or a string like 'no_plan' or 'skip_all'.
done_testing
Explicitly finishes the test suite. This is useful for tests that do not have a fixed number of test cases.
bail_out
Causes the test suite to exit immediately with an error message. This is useful for fatal errors that prevent further testing.

PLUGINS

Test2 supports a plugin system that allows you to extend its functionality. Plugins can be loaded using the use statement.

use Test2::V0 qw(ok);
use Test2::Plugin::MyCustomPlugin;

See Test2::Plugin for more information.

ENVIRONMENT VARIABLES

Test2 respects the following environment variables:

TEST_LEVEL
Sets the verbosity level of the tests. Higher values mean more verbose output.
TEST_IS_DIAGNOSTIC
If set, diagnostic messages will be printed.
TEST_AUTHOR
If set, author tests will be run.
TEST_SKIP_ALL
If set, all tests will be skipped.
TEST_LOG_FILE
Specifies a file to which all test output should be logged.

API FUNCTIONS

This module exports the following core API functions:

ok($condition, $name)
Asserts that a condition is true.
not_ok($condition, $name)
Asserts that a condition is false.
diag($message)
Prints a diagnostic message. These messages are ignored by default but can be shown with the TEST_IS_DIAGNOSTIC environment variable.
note($message)
Prints a note. These messages are always shown.
plan($type, $count, $details)
Sets the plan for the test suite. $type can be tests, plan_skip, no_plan, or skip_all.
done_testing
Signals that the test suite has finished.
bail_out($reason)
Exits the test suite immediately with the given reason.
