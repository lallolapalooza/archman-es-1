Test2::Tools::Refcount(3perl) Guía de Referencia del Programador Perl Test2::Tools::Refcount(3perl)

NOMBRE

"Test2::Tools::Refcount" - afirmar los recuentos de referencias en objetos

SINOPSIS

use Test2::Tools::Refcount;
use Some::Class;
my $object = Some::Class->new();
is_oneref( $object, '$object tiene un recuento de referencias de 1' );
my $otherref = $object;
is_refcount( $object, 2, '$object ahora tiene 2 referencias' );

DESCRIPCIÓN

El recolector de basura de Perl utiliza un simple conteo de referencias durante la ejecución normal de un programa. Esto significa que los ciclos o las referencias no debilitadas en otras partes del código pueden mantener un objeto en memoria por más tiempo del previsto. Para ayudar a evitar este problema, el recuento de referencias de un nuevo objeto de su constructor de clase debería ser 1. De esta manera, el llamador puede saber que el objeto será debidamente DESTRUIDO cuando descarte todas sus referencias a él.

Este módulo proporciona dos funciones de prueba para ayudar a asegurar que esta propiedad se cumpla para una clase de objeto, a fin de ser respetuoso con sus llamadores.

Si la afirmación falla; es decir, si el recuento de referencias real es diferente de lo esperado, cualquiera de los dos módulos siguientes puede utilizarse para ayudar al desarrollador a encontrar dónde están las referencias.

•
Si Devel::MAT está instalado, este módulo de prueba lo utilizará para volcar el estado de la memoria después de un fallo. Creará un archivo .pmat con el mismo nombre que la prueba unitaria, pero con el sufijo .t reemplazado por -TEST.pmat donde "TEST" es el número de la prueba que falló (en caso de que hubiera más de una).

Vea los ejemplos a continuación para obtener más información.

FUNCIONES

is_refcount

is_refcount( $object, $count, $name )

Prueba que $object tiene $count referencias a él.

is_oneref

is_oneref( $object, $name )

Afirma que el $object tiene solo 1 referencia a él.

refcount

$count = refcount( $object )

Devuelve el recuento de referencias del objeto dado tal como lo usan las funciones de prueba. Esto es útil para crear pruebas que no se preocupan por el recuento antes de comenzar, sino que simplemente afirman que el recuento no ha cambiado al final.

use Test2::Tools::Refcount import => [qw( is_refcount refcount )];
{
   my $count = refcount( $object );
   do_something( $object );
   is_refcount( $object, $count, 'do_something() preserva el recuento de referencias' );
}

EJEMPLO

Supongamos que, tras haber escrito una nueva clase "MyBall", ahora quiere comprobar que su constructor y métodos se comportan bien y no filtran referencias. Considere el siguiente script de prueba:

use Test::More tests => 2;
use Test2::Tools::Refcount;
use MyBall;
my $ball = MyBall->new();
is_oneref( $ball, 'Una referencia después de la construcción' );
$ball->bounce;
# Cualquier otro código aquí que pueda ser parte del script de prueba
is_oneref( $ball, 'Una referencia justo antes del FIN DE ARCHIVO' );

La primera afirmación es justo después del constructor, para comprobar que la referencia devuelta por él es la única referencia a ese objeto. Este hecho es importante si alguna vez queremos que "DESTROY" se comporte correctamente. La segunda llamada está justo al final del archivo, justo antes de que se cierre el ámbito principal. En este punto esperamos que el recuento de referencias también sea uno, para que el objeto se limpie adecuadamente.

Supongamos que, al ejecutarlo, esto produce la siguiente salida (presumiendo que Devel::MAT::Dumper está disponible):

1..2
ok 1 - Una referencia después de la construcción
not ok 2 - Una referencia justo antes del FIN DE ARCHIVO
#   Fallo en la prueba 'Una referencia justo antes del FIN DE ARCHIVO'
#   en ex.pl línea 26.
#   se esperaban 1 referencias, se encontraron 2
# La dirección SV es 0x55e14c310278
# Escribiendo volcado de montón en ex-2.pmat
# Parece que fallaste 1 prueba de 2.

Esto ha escrito un archivo ex-2.pmat que podemos cargar usando la consola "pmat" y usar el comando "identify" en la dirección dada para encontrar dónde fue:

$ pmat ex-2.pmat 
Volcado de memoria Perl de perl 5.28.1 threaded
El montón contiene 25233 objetos
pmat> identify 0x55e14c310278
HASH(0)=MyBall en 0x55e14c310278 es:
├──(vía RV) el léxico $ball en profundidad 1 de CODE() en 0x55e14c3104a0=main_cv, que es:
│ └─el código principal
└─(vía RV) valor {self} de HASH(2) en 0x55e14cacb860, que es (*A):
  └─(vía RV) valor {cycle} de HASH(2) en 0x55e14cacb860, que es:
    sí mismo

(Este documento no pretende ser un tutorial completo sobre Devel::MAT y la consola "pmat"; para eso véase Devel::MAT::UserGuide).

A partir de esta salida, podemos ver que el constructor se comportó bien, pero que se filtró una referencia al final del script: el recuento de referencias era 2, cuando esperábamos solo 1. Leyendo la salida del rastreo, podemos ver que hubo 2 referencias que se pudieron encontrar: una almacenada en el léxico $ball en el programa principal, y otra almacenada en un HASH. Dado que esperábamos encontrar el léxico $ball, sabemos que ahora estamos buscando una fuga en un hash en algún lugar del código. Por la lectura del script de prueba, podemos adivinar que esta fuga probablemente esté en el método bounce(). Además, sabemos que la referencia al objeto se almacenará en un HASH en un miembro llamado "self".

Al leer el código que implementa el método bounce(), podemos ver que este es de hecho el caso:

sub bounce
{
   my $self = shift;
   my $cycle = { self => $self };
   $cycle->{cycle} = $cycle;
}

Al leer la salida del rastreo, encontramos que el HASH en el que se hace referencia a este objeto también contiene una referencia a sí mismo, en un miembro llamado "cycle". Esto proviene de la última línea de esta función, una línea que creó deliberadamente un ciclo, para demostrar el punto. Si bien un programa real probablemente no haría algo tan obvio, el rastreo aún sería útil para encontrar la causa probable de la fuga.

Si "Devel::MAT::Dumper" no está disponible, entonces estos rastreos detallados no se producirán. Las pruebas básicas de recuento de referencias aún se llevarán a cabo, pero se producirá un mensaje más pequeño:

1..2
ok 1 - Una referencia después de la construcción
not ok 2 - Una referencia justo antes del FIN DE ARCHIVO
#   Fallo en la prueba 'Una referencia justo antes del FIN DE ARCHIVO'
#   en demo.pl línea 16.
#   se esperaban 1 referencias, se encontraron 2
# Parece que fallaste 1 prueba de 2.

ERRORES

•
Temporales creados en la pila

El código que crea temporales en la pila, para ser liberados de nuevo cuando la función llamada retorna, no funciona correctamente en perl 5.8 (y probablemente antes). Ejemplos como

is_oneref( [] );

pueden fallar y reclamar un recuento de referencias de 2 en su lugar.

Pasar una variable como

my $array = [];
is_oneref( $array );

funciona bien. Debido a la intención de este módulo de prueba; es decir, afirmar recuentos de referencias en algún objeto almacenado en una variable durante la vida útil del script de prueba, es poco probable que esto cause algún problema.
