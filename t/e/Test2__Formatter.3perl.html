Test2::Formatter(3perl) Guía de programación para Perl Test2::Formatter(3perl)

NOMBRE

Test2::Formatter - Espacio de nombres para formateadores.

DESCRIPCIÓN

Este es el espacio de nombres para los formateadores. Es un paquete vacío.

CREACIÓN DE FORMATADORES

Un formateador es cualquier paquete u objeto con un método "write($event, $num)".

package Test2::Formatter::Foo;
use strict;
use warnings;
sub write {
    my $self_or_class = shift;
    my ($event, $assert_num) = @_;
    ...
}
sub hide_buffered { 1 }
sub terminate { }
sub finalize { }
sub supports_tables { return $BOOL }
sub new_root {
    my $class = shift;
    ...
    $class->new(@_);
}
1;

El método "write" es un método, por lo que recibe una clase o una instancia. Los dos argumentos son el objeto $event que debe registrar, y el $assert_num, que es el número de la aserción actual (ok), o la última aserción si este evento no es en sí mismo una aserción. El número de aserción puede ser cualquier entero mayor o igual a 0, y puede no estar definido en algunos casos.

El método hide_buffered() debe devolver un booleano. Esto se utiliza para indicar a los subtests en búfer si deben o no enviarles eventos mientras se están almacenando en búfer. Consulte "run_subtest(...)" en Test2::API para obtener más información.

Los métodos "terminate" y "finalize" son métodos opcionales que se llaman y que puede implementar si el formato que está generando necesita manejar estos casos, por ejemplo, si está generando XML y necesita cerrar etiquetas abiertas.

El método "terminate" se llama cuando el método "terminate" de un evento devuelve verdadero, por ejemplo, cuando un Test2::Event::Plan tiene un plan 'skip_all', o cuando se envía un evento Test2::Event::Bail. Al método "terminate" se le pasa un único argumento, el objeto Test2::Event que desencadenó la terminación.

El método "finalize" es siempre lo último que se llama en el formateador, *excepto cuando *"terminate"* se llama para un evento Bail*. Se le pasan los siguientes argumentos:

El método "supports_tables" debe ser verdadero si el formateador admite la representación directa de datos de tabla de las facetas "info". Esta es una característica más reciente y muchos formateadores más antiguos pueden no admitirla. Cuando no se admite, el formateador recurre a la representación de "detail" en lugar de los datos de "table".

El método "new_root" se utiliza al construir un formateador raíz. El valor predeterminado es simplemente delegar al método new() normal; la mayoría de los formateadores pueden ignorarlo.

  • El número de pruebas que se planificaron
  • El número de pruebas que se vieron realmente
  • El número de pruebas que fallaron
  • Un booleano que indica si el conjunto de pruebas pasó o no
  • Un booleano que indica si esta llamada es para un subtest o no

El método "new_root" se llama cuando "Test2::API::Stack" inicializa el concentrador raíz por primera vez. La mayoría de los formateadores simplemente llamarán a "$class->new", que es el comportamiento predeterminado. Sin embargo, algunos formateadores pueden querer tomar medidas adicionales durante la construcción del formateador raíz, aquí es donde pueden hacerlo.
