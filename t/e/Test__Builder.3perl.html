Test::Builder(3perl) Perl Programmers Reference Guide Test::Builder(3perl)

NOMBRE

Test::Builder - Backend para construir bibliotecas de pruebas

SINOPSIS

package My::Test::Module;
use base 'Test::Builder::Module';
my $CLASS = __PACKAGE__;
sub ok {
    my($test, $name) = @_;
    my $tb = $CLASS->builder;
    $tb->ok($test, $name);
}

DESCRIPCIÓN

Test::Simple y Test::More han demostrado ser módulos de prueba populares, pero no siempre son lo suficientemente flexibles. Test::Builder proporciona un bloque de construcción sobre el cual escribir sus propias bibliotecas de pruebas que pueden trabajar juntas.

Construcción

new
my $Test = Test::Builder->new;

Devuelve un objeto Test::Builder que representa el estado actual de la prueba. Dado que solo se ejecuta una prueba por programa, "new" siempre devuelve el mismo objeto Test::Builder. No importa cuántas veces llames a new(), obtendrás el mismo objeto. Esto se llama un singleton. Esto se hace para que múltiples módulos compartan información global como el contador de pruebas y dónde va la salida de la prueba.

Si desea un objeto Test::Builder completamente nuevo, diferente del singleton, use "create".

create
my $Test = Test::Builder->create;

Ok, entonces puede haber más de un objeto Test::Builder y así es como lo obtienes. Podrías usar esto en lugar de new() si estás probando un módulo basado en Test::Builder, pero de lo contrario probablemente quieras "new".

NOTA: la implementación no está completa. "level", por ejemplo, todavía es compartido por todos los objetos Test::Builder, incluso los creados usando este método. Además, el nombre del método puede cambiar en el futuro.

subtest
$builder->subtest($name, \&subtests, @args);

Ver la documentación de "subtest" en Test::More.

"subtest" también, y opcionalmente, acepta argumentos que se pasarán a la referencia de subtests.

name
diag $builder->name;

Devuelve el nombre del builder actual. Los builders de nivel superior tienen por defecto $0 (el nombre del ejecutable). Los builders hijos se nombran a través del método "child". Si no se proporciona un nombre, se llamará "Child of $parent->name".

reset
$Test->reset;

Reinicializa el singleton de Test::Builder a su estado original. Útil principalmente para pruebas ejecutadas en entornos persistentes donde la misma prueba puede ejecutarse varias veces en el mismo proceso.

Configuración de pruebas

Estos métodos son para configurar pruebas y declarar cuántas hay. Por lo general, solo querrás llamar a uno de estos métodos.

plan
$Test->plan('no_plan');
$Test->plan( skip_all => $reason );
$Test->plan( tests => $num_tests );

Una forma conveniente de configurar tus pruebas. Llama a esto y Test::Builder imprimirá las cabeceras apropiadas y tomará las acciones apropiadas. Si llamas a plan(), no llames a ninguno de los otros métodos a continuación.

expected_tests
my $max = $Test->expected_tests;
$Test->expected_tests($max);

Obtiene/establece el número de pruebas que esperamos que esta prueba ejecute e imprime las cabeceras apropiadas.

no_plan
$Test->no_plan;

Declara que esta prueba ejecutará un número indeterminado de pruebas.

done_testing
$Test->done_testing();
$Test->done_testing($num_tests);

Declara que has terminado de probar, no se ejecutarán más pruebas después de este punto. Si aún no se ha emitido un plan, lo hará.

$num_tests es el número de pruebas que planeaste ejecutar. Si ya se declaró un plan numerado, y si esto contradice, se ejecutará una prueba fallida para reflejar el error de planificación. Si se declaró "no_plan", esto lo anulará.

Si se llama a done_testing() dos veces, la segunda llamada emitirá una prueba fallida.

Si se omite $num_tests, se utilizará el número de pruebas ejecutadas, como en no_plan.

done_testing() se usa, en efecto, cuando querrías usar "no_plan", pero de forma más segura. Lo usarías así:

$Test->ok($a == $b);
$Test->done_testing();

O para planificar un número variable de pruebas:

for my $test (@tests) {
    $Test->ok($test);
}
$Test->done_testing(scalar @tests);
has_plan
$plan = $Test->has_plan

Averigua si se ha definido un plan. $plan es bien "undef" (no se ha establecido ningún plan), "no_plan" (número indeterminado de pruebas) o un entero (el número de pruebas esperadas).

skip_all
$Test->skip_all;
$Test->skip_all($reason);

Salta todas las pruebas, utilizando la $reason dada. Sale inmediatamente con 0.

exported_to
my $pack = $Test->exported_to;
$Test->exported_to($pack);

Le dice a Test::Builder a qué paquete exportaste tus funciones.

Este método no es muy útil ya que los módulos que comparten el mismo objeto Test::Builder podrían exportarse a diferentes paquetes y solo se honrará el último.

Ejecución de pruebas

Estos en realidad ejecutan las pruebas, de forma análoga a las funciones en Test::More.

Todos devuelven verdadero si la prueba pasó, falso si la prueba falló.

$name es siempre opcional.

ok
$Test->ok($test, $name);

Tu prueba básica. Pasa si $test es verdadero, falla si $test es falso. Igual que ok() de Test::Simple.

is_eq
$Test->is_eq($got, $expected, $name);

Como is() de Test::More. Comprueba si "$got eq $expected". Esta es la versión de cadena.

"undef" solo coincide con otro "undef".

is_num
$Test->is_num($got, $expected, $name);

Como is() de Test::More. Comprueba si "$got == $expected". Esta es la versión numérica.

"undef" solo coincide con otro "undef".

isnt_eq
$Test->isnt_eq($got, $dont_expect, $name);
