NOMBRE

Template::Manual::Intro - Introducción al Template Toolkit

Introducción

El Template Toolkit es una colección de módulos Perl que implementan un sistema de procesamiento de plantillas rápido, flexible, potente y extensible. Se utiliza con mayor frecuencia para generar contenido web dinámico, aunque también se puede utilizar para procesar cualquier tipo de documentos de texto.

En el nivel más simple, proporciona una forma fácil de procesar archivos de plantillas, rellenando las referencias de variables incrustadas con sus valores equivalentes. Aquí tienes un ejemplo de una plantilla.

Estimado/a [% name %],
Hemos notado que su cuenta tiene un saldo pendiente
de [% debt %].
Por favor, liquide su cuenta antes del [% deadline %]
o nos veremos obligados a revocar su Licencia para Emocionar.
La Gerencia.

Por defecto, las directivas de plantilla están incrustadas dentro de las secuencias de caracteres "[%" ... "%]", pero puedes cambiar estas y varias otras opciones para configurar cómo se ve, se siente y funciona el Template Toolkit. Puedes establecer la opción "INTERPOLATE", por ejemplo, si prefieres incrustar tus variables al estilo Perl:

Estimado/a $name,
Hemos notado que su cuenta tiene un saldo pendiente
de $debt.
...etc...

El Módulo Perl Template

El módulo Perl Template es la interfaz para el Template Toolkit para programadores Perl, proporcionando acceso a toda la gama de funcionalidades a través de un único módulo con una interfaz sencilla. Carga los demás módulos según sea necesario e instancia un conjunto predeterminado de objetos para manejar las solicitudes de procesamiento de plantillas subsiguientes. Los parámetros de configuración se pueden pasar al método constructor de Template, new(), que luego se utilizan para configurar el objeto generado.

use Template;
my $tt = Template->new({
    INCLUDE_PATH => '/usr/local/templates',
    INTERPOLATE  => 1,
}) || die "$Template::ERROR\n";

El objeto Template implementa un método process() para procesar archivos o texto de plantillas. El nombre de la plantilla de entrada (o varias otras fuentes) se pasa como primer argumento, seguido de una referencia a un hash de arrays de definiciones de variables para su sustitución en la plantilla.

my $vars = {
    name     => 'Conde Edward van Halen',
    debt     => '3 riffs y un solo',
    deadline => 'el próximo estribillo',
};
$tt->process('cartas/descubierto', $vars)
    || die $tt->error(), "\n";

El método process() devuelve un valor verdadero (1) en caso de éxito e imprime la salida de la plantilla en "STDOUT", por defecto. En caso de error, el método process() devuelve un valor falso ("undef"). Luego se puede llamar al método error() para obtener detalles del error.

Construcción de Contenido Basada en Componentes

Se proporcionan varias directivas especiales, como "INSERT", "INCLUDE" y "PROCESS", que permiten construir contenido a partir de componentes de plantilla más pequeños. Esto permite un enfoque modular para construir un sitio web u otro repositorio de contenido, promoviendo la reutilización, la consistencia entre sitios, la facilidad de construcción y el mantenimiento posterior. Elementos comunes como encabezados, pies de página, barras de menú, tablas, etc., se pueden crear como archivos de plantilla separados que luego se pueden procesar en otros documentos según sea necesario. Todas las variables definidas son heredadas por estas plantillas junto con cualquier valor adicional "local" especificado.

[% PROCESS cabecera
     titulo = "El gato se sentó en la alfombra"
%]
[% PROCESS menu %]
La ubicación del felino desaparecido ha sido establecida.
Gracias por su ayuda.
[% INSERT legal/exencion_responsabilidad %]
[% PROCESS pie_pagina %]

También puedes definir una plantilla como un BLOQUE dentro del mismo archivo y PROCESARLA igual que cualquier otro archivo de plantilla. Esto puede ser invaluable para construir elementos repetitivos como tablas, menús, etc.

[% BLOCK fila_tabla %]
   <tr><td>[% nombre %]</td><td>[% email %]</td></tr>
[% END %]
<table>
[% PROCESS fila_tabla nombre="tom"   email="tom@aqui.org"    %]
[% PROCESS fila_tabla nombre="dick"  email="disk@alli.org"  %]
[% PROCESS fila_tabla nombre="larry" email="larry@donde.org" %]
</table>

Vinculación de Datos y Código

Una de las características clave que distingue al Template Toolkit de otros procesadores de plantillas es la capacidad de vincular variables de plantilla a cualquier tipo de dato Perl: escalares, listas, hash de arrays, subrutinas y objetos.

my $vars = {
    root   => 'http://aqui.com/alli',
    menu   => [ 'módulos', 'autores', 'scripts' ],
    client => {
        name => 'Doctor Joseph von Satriani',
        id   => 'JVSAT',
    },
    checkout => sub { my $total = shift; ...; return $algo },
    shopcart => My::Cool::Shopping::Cart->new(),
};

El Template Toolkit hará automáticamente "lo correcto" para acceder a los datos de una manera apropiada para devolver algún valor que luego pueda ser mostrado. El operador punto '"."' se utiliza para acceder a listas y hashes o para llamar a métodos de objetos. La directiva "FOREACH" se proporciona para iterar a través de listas, y varias pruebas lógicas están disponibles usando directivas como "IF", "UNLESS", "ELSIF", "ELSE", "SWITCH", "CASE", etc.

[% FOREACH sección = menu %]
   <a href="[% root %]/[% sección %]/index.html">[% sección %]</a>
[% END %]
<b>Cliente</b>: [% client.name %] (id: [% client.id %])
[% IF shopcart.nitems %]
   Tu carrito de compras contiene los siguientes artículos:
   <ul>
   [% FOREACH item = shopcart.contents %]
     <li>[% item.name %] : [% item.qty %] @ [% item.price %]
   [% END %]
   </ul>
   [% checkout(shopcart.total) %]
[% ELSE %]
   Actualmente no hay artículos en el carrito de compras.
[% END %]

Características Avanzadas: Filtros, Macros, Excepciones, Plugins

El Template Toolkit también proporciona una serie de directivas adicionales para procesamiento avanzado y funcionalidad programática. Admite filtros de salida (FILTER), permite definir macros personalizadas (MACRO), tiene un sistema de manejo de excepciones con todas las funciones (TRY, THROW, CATCH, FINAL) y admite una arquitectura de plugins (USE) que permite cargar y utilizar módulos de plugins especiales e incluso módulos Perl regulares con el mínimo esfuerzo. El Template Toolkit es "simplemente" un procesador de plantillas, pero puedes extenderlo trivialmente para incorporar la funcionalidad de cualquier módulo Perl que puedas conseguir. Por lo tanto, también es un framework de plantillas escalable y extensible, ideal para gestionar la capa de presentación de servidores de aplicaciones, sistemas de gestión de contenido y otras aplicaciones web.

Separación de la Lógica de Presentación y Aplicación

En lugar de incrustar código Perl o algún otro lenguaje de scripting directamente en los documentos de plantilla, te anima a mantener los componentes funcionales (es decir, código Perl) separados de los componentes de presentación (por ejemplo, plantillas HTML). Las variables de plantilla proporcionan la interfaz entre las dos capas, permitiendo que los datos se generen en código y luego se pasen a un componente de plantilla para su visualización (modelo de tubería) o para que las referencias a subrutinas u objetos se vinculen a variables que luego se pueden llamar desde la plantilla cuando sea necesario (modelo de devolución de llamada).

Las directivas que proporciona el Template Toolkit implementan su propio mini lenguaje de programación, pero no están realmente diseñadas para una programación seria de propósito general. Perl es un lenguaje mucho más apropiado para eso. Si incrustas lógica de aplicación (por ejemplo, fragmentos de código Perl u otro lenguaje de scripting) en plantillas HTML, corres el riesgo de perder la clara separación de preocupaciones entre la funcionalidad y la presentación. NAME

Template::Manual::Intro - Introduction to the Template Toolkit

Introduction

The Template Toolkit is a powerful, flexible, and highly efficient template processing system written entirely in Perl. It provides a clear and simple template language that is easy to learn and use, yet powerful enough to handle complex presentation tasks.

This manual introduces the Template Toolkit, explains its design philosophy, and covers its main features and benefits.

The Template Perl Module

The core of the Template Toolkit is the Template Perl module. This module provides a Perl interface for loading, compiling, and processing template files.

You can use the Template module directly in your Perl scripts to generate output based on data defined in your scripts. Alternatively, you can use it to process template files stored separately, allowing for a clean separation between application logic and presentation.

Component Based Content Construction

The Template Toolkit encourages a component-based approach to content construction. Templates can be broken down into smaller, reusable components (e.g., headers, footers, navigation bars) that can be included or defined within other templates. This promotes modularity and maintainability.

Data and Code Binding

The Template Toolkit provides a straightforward way to bind data to templates. Variables can be defined in Perl code and then accessed and manipulated within the template using a simple, intuitive syntax. This binding mechanism allows for dynamic content generation.

Advanced Features: Filters, Macros, Exceptions, Plugins

Beyond basic variable substitution and control structures, the Template Toolkit offers advanced features:

  • Filters: Modify the output of variables or blocks of text (e.g., for formatting, escaping, or translation).
  • Macros: Define reusable blocks of template code that can be called with arguments, similar to functions in programming languages.
  • Exceptions: Handle errors gracefully within templates, allowing for custom error messages or fallback content.
  • Plugins: Extend the toolkit's functionality by integrating external modules or custom code.

Separating Presentation and Application Logic

A key design principle of the Template Toolkit is the separation of presentation from application logic. It's generally recommended to avoid embedding complex application logic directly within templates. Instead, use Perl modules or scripts to prepare the data and then use templates solely for controlling how that data is presented.

This separation makes applications easier to maintain, modify, and allows designers and developers to work more independently. Designers can focus on the templates, while developers can concentrate on the application logic.

While the Template Toolkit provides the flexibility to embed Perl code within templates using the PERL ... END directive (if the EVAL_PERL option is enabled), this approach should be used sparingly to maintain the separation principle.

Performance

The Template Toolkit is designed for high performance. It employs a fast parser that compiles templates into efficient Perl code. Additionally, it features an advanced caching mechanism that stores compiled templates in memory or on disk for faster subsequent processing. The toolkit's architecture is highly configurable and extensible, making it suitable for building robust content creation and delivery systems while offering a simple interface for general use through the Template front-end module.
