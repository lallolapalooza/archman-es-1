Text::Balanced(3perl) Guía de referencia para programadores de Perl Text::Balanced(3perl)

NOMBRE

Text::Balanced - Extraer secuencias de texto delimitadas de cadenas.

SINOPSIS

use Text::Balanced qw (
    extract_delimited
    extract_bracketed
    extract_quotelike
    extract_codeblock
    extract_variable
    extract_tagged
    extract_multiple
    gen_delimited_pat
    gen_extract_tagged
);
# Extrae la subcadena inicial de $texto que está delimitada por
# dos instancias (sin escapar) del primer carácter en $delim.
($extraida, $resto) = extract_delimited($texto, $delim);
# Extrae la subcadena inicial de $texto que está entre corchetes
# con uno o más delimitadores especificados por $delim (donde la cadena
# en $delim contiene uno o más de '(){}[]<>').
($extraida, $resto) = extract_bracketed($texto, $delim);
# Extrae la subcadena inicial de $texto que está delimitada por
# una etiqueta XML.
($extraida, $resto) = extract_tagged($texto);
# Extrae la subcadena inicial de $texto que está delimitada por
# un par C<BEGIN>...C<END>. No permite etiquetas C<BEGIN> anidadas
($extraida, $resto) =
    extract_tagged($texto, "BEGIN", "END", undef, {bad => ["BEGIN"]});
# Extrae la subcadena inicial de $texto que representa una
# operación de cita o similar en Perl ("quote or quote-like operation")
($extraida, $resto) = extract_quotelike($texto);
# Extrae la subcadena inicial de $texto que representa un bloque
# de código Perl, delimitado por uno o más caracteres especificados por $delim
# (donde la cadena $delim contiene uno o más de '(){}[]<>').
($extraida, $resto) = extract_codeblock($texto, $delim);
# Extrae las subcadenas iniciales de $texto que serían extraídas por
# una o más aplicaciones secuenciales de las funciones especificadas
# o expresiones regulares
@extraidas = extract_multiple($texto,
                              [ \&extract_bracketed,
                                \&extract_quotelike,
                                \&alguna_otra_subrutina_extractora,
                                qr/[xyz]*/,
                                'literal',
                              ]);
# Crea una cadena que representa un patrón optimizado (estilo Friedl)
# que coincide con una subcadena delimitada por cualquiera de los caracteres especificados
# (en este caso: cualquier tipo de cita o una barra)
$patron_cadena = gen_delimited_pat(q{'`"/});
# Genera una referencia a una subrutina anónima que es igual a extract_tagged
# pero precompilada y optimizada para un par específico de etiquetas, y
# consecuentemente mucho más rápida (es decir, 3 veces más rápida). Usa qr// para un mejor
# rendimiento en llamadas repetidas.
$extract_head = gen_extract_tagged('','');
($extraida, $resto) = $extract_head->($texto);

DESCRIPCIÓN

Las diversas subrutinas "extract_..." pueden usarse para extraer una subcadena delimitada, posiblemente después de saltar una cadena de prefijo especificada. Por defecto, ese prefijo es espacio en blanco opcional ("/\s*/"), pero puedes cambiarlo a lo que desees (ver más abajo).

La subcadena a extraer debe aparecer en la "pos" actual de la variable de la cadena (o en el índice cero, si no se define ninguna posición "pos"). En otras palabras, las subrutinas "extract_..." *no* extraen la primera ocurrencia de una subcadena en cualquier lugar de una cadena (como lo haría una expresión regular sin ancla). Más bien, extraen una ocurrencia de la subcadena que aparece inmediatamente en la posición de coincidencia actual de la cadena (como lo haría una expresión regular anclada con "\G").

Comportamiento General en Contextos de Lista

En un contexto de lista, todas las subrutinas devuelven una lista, cuyos tres primeros elementos son siempre:

[0]
La cadena extraída, incluyendo los delimitadores especificados. Si la extracción falla, se devuelve "undef".
[1]
El resto de la cadena de entrada (es decir, los caracteres después de la cadena extraída). En caso de fallo, se devuelve la cadena completa.
[2]
El prefijo omitido (es decir, los caracteres antes de la cadena extraída). En caso de fallo, se devuelve "undef".

Tenga en cuenta que en un contexto de lista, el contenido del texto de entrada original (el primer argumento) no se modifica de ninguna manera.

Sin embargo, si el texto de entrada se pasó en una variable, el valor de "pos" de esa variable se actualiza para apuntar al primer carácter después del texto extraído. Eso significa que en un contexto de lista las diversas subrutinas pueden usarse de manera similar a las expresiones regulares. Por ejemplo:

while ( $siguiente = (extract_quotelike($texto))[0] )
{
    # procesar la siguiente operación de cita o similar (en $siguiente)
}

Comportamiento General en Contextos Escalar y Vacío

En un contexto escalar, se devuelve la cadena extraída, habiendo sido eliminada previamente del texto de entrada. Por lo tanto, el siguiente código también procesa cada operación de cita o similar, pero en realidad las elimina de $texto:

while ( $siguiente = extract_quotelike($texto) )
{
    # procesar la siguiente operación de cita o similar (en $siguiente)
}

Tenga en cuenta que si el texto de entrada es una cadena de solo lectura (es decir, un literal), no se intenta eliminar el texto extraído.

En un contexto vacío, el comportamiento de las subrutinas de extracción es exactamente el mismo que en un contexto escalar, excepto (por supuesto) que la subcadena extraída no se devuelve.

Una Nota Sobre Prefijos

Los patrones de prefijo se comparan sin modificadores finales ("/gimsox" etc.). Esto puede afectarle si espera que una especificación de prefijo como '.*?(?=<H1>)' omita todo hasta la primera etiqueta <H1>. Dicho patrón de prefijo solo tendrá éxito si la etiqueta <H1> está en la línea actual, ya que el punto normalmente no coincide con los saltos de línea.

Para superar esta limitación, necesita activar la coincidencia /s dentro del patrón de prefijo, utilizando la directiva "(?s)": '(?s).*?(?=<H1>)'

Funciones

"extract_delimited"
La función "extract_delimited" formaliza el modismo común de extraer una subcadena delimitada por un solo carácter del inicio de una cadena. Por ejemplo, para extraer una cadena delimitada por comillas simples, se suele utilizar el siguiente código: 
($resto = $texto) =~ s/\A('(\\.|[^'])*')//s;
$extraida = $1;

pero con "extract_delimited" se puede simplificar a:

($extraida, $resto) = extract_delimited($texto, "'");

"extract_delimited" toma hasta cuatro escalares (el texto de entrada, los delimitadores, un patrón de prefijo que debe ser omitido y cualquier carácter de escape) y extrae la subcadena inicial del texto que está adecuadamente delimitada. Si la cadena delimitadora tiene múltiples caracteres, el primero encontrado en el texto se toma para delimitar la subcadena. El tercer argumento especifica un patrón de prefijo que debe omitirse (¡pero debe estar presente!) antes de extraer la subcadena. El último argumento especifica el carácter de escape que se utilizará para cada delimitador.

Todos los argumentos son opcionales. Si no se especifican los caracteres de escape, cada delimitador se escapa con una barra invertida ("\"). Si no se especifica el prefijo, se utiliza el patrón '\s*' - espacio en blanco opcional. Si tampoco se especifica el conjunto de delimitadores, se utiliza el conjunto "/["'`]/". Si tampoco se especifica el texto a procesar, se utiliza $_.

En contexto de lista, "extract_delimited" devuelve un array de tres elementos: la subcadena extraída (incluyendo los delimitadores circundantes), el resto del texto y el prefijo omitido (si lo hay). Si no se encuentra una subcadena delimitada adecuada, el primer elemento del array es la cadena vacía, el segundo es el texto original completo, y el prefijo devuelto en el tercer elemento es una cadena vacía.

En un contexto escalar, solo se devuelve la subcadena extraída. En un contexto vacío, la subcadena extraída (y cualquier prefijo) simplemente se eliminan del principio del primer argumento.

Ejemplos:

        # Ejemplo 1: Extracción simple
        ($str, $rest) = extract_delimited(q{ 'simple' 'quoted' }, "'");
        # $str es "'simple'"
        # $rest es " 'quoted'"

        # Ejemplo 2: Con prefijo de salto
        ($str, $rest, $prefix) = extract_delimited(q{ abc 'quoted' }, "'", qr/\s*abc\s*/);
        # $str es "'quoted'"
        # $rest es ""
        # $prefix es " abc "

        # Ejemplo 3: Especificando múltiples delimitadores
        ($str, $rest) = extract_delimited(q{ `backtick` }, qr/[`"']/);
        # $str es "`backtick`"
        # $rest es ""

        # Ejemplo 4: Especificando caracteres de escape
        ($str, $rest) = extract_delimited(q{ 'escaped \x27 quote' }, "'", undef, "\\");
        # $str es "'escaped \x27 quote'"
        # $rest es ""

        # Ejemplo 5: Manejo de fallos
        ($str, $rest) = extract_delimited(q{ no quotes here }, "'");
        # $str es ""
        # $rest es " no quotes here"
/p> 
# Elimina una subcadena entrecomillada simple del principio de $text:
    $substring = extract_delimited($text, "'", '');
# Elimina una subcadena Pascal entrecomillada simple (es decir, una en la que
# duplicar el carácter de comilla lo escapa) del principio de $text:
    $substring = extract_delimited($text, "'", '', "'");
# Extrae una subcadena entrecomillada simple o doble del
# principio de $text, opcionalmente después de algunos espacios en blanco
# (nota el contexto de lista para proteger $text de modificaciones):
    ($substring) = extract_delimited $text, q{"'};
# Elimina la subcadena delimitada por la primera '/' en $text:
    $text = join '', (extract_delimited($text,'/','[^/]*')[2,1];

Ten en cuenta que este último ejemplo **no** es lo mismo que eliminar el primer patrón similar a una comilla. Por ejemplo, si $text contuviera la cadena:

"if ('./cmd' =~ m/$UNIXCMD/s) { $cmd = $1; }"

entonces después de la eliminación contendría:

"if ('.$UNIXCMD/s) { $cmd = $1; }"

no:

"if ('./cmd' =~ ms) { $cmd = $1; }"

Ver "extract_quotelike" para una solución (parcial) a este problema.

"extract_bracketed"
Al igual que "extract_delimited", la función "extract_bracketed" toma hasta tres argumentos escalares opcionales: una cadena de la que extraer, un especificador de delimitador y un patrón de prefijo. Como antes, un prefijo faltante se traduce por espacios en blanco opcionales y un texto faltante se traduce por $_. Sin embargo, un especificador de delimitador faltante se traduce por '{}()[]<>' (ver más abajo).

"extract_bracketed" extrae una subcadena delimitada por corchetes equilibrados (utilizando cualquiera (o más) de los corchetes delimitadores especificados por el usuario: '(..)', '{..}', '[..]', o '<..>'). Opcionalmente, también respetará los corchetes desequilibrados entrecomillados (ver más abajo).

Un "corchete delimitador" es un corchete en la lista de delimitadores pasados como segundo argumento de "extract_bracketed". Los corchetes delimitadores se especifican proporcionando la versión izquierda o derecha (¡o ambas!) de los corchetes requeridos. Ten en cuenta que el orden en que se especifican dos o más corchetes delimitadores no es significativo.

Una "subcadena delimitada por corchetes equilibrados" es una subcadena limitada por corchetes emparejados, de tal manera que cualquier otro corchete delimitador (izquierdo o derecho) *dentro* de la subcadena también está emparejado por un corchete delimitador opuesto (derecho o izquierdo) *al mismo nivel de anidamiento*. Cualquier tipo de corchete que no esté en la lista de delimitadores se trata como un carácter ordinario.

En otras palabras, cada tipo de corchete especificado como delimitador debe estar equilibrado y correctamente anidado dentro de la subcadena, y cualquier otro tipo de corchete ("no delimitador") en la subcadena se ignora.

Por ejemplo, dada la cadena:

$text = "{ an '[irregularly :-(] {} parenthesized >:-)' string }";

entonces una llamada a "extract_bracketed" en un contexto de lista:

@result = extract_bracketed( $text, '{}' );

devolvería:

( "{ an '[irregularly :-(] {} parenthesized >:-)' string }" , "" , "" )

ya que ambos conjuntos de corchetes '{..}' están correctamente anidados y equilibrados. (En un contexto escalar, solo se devolvería el primer elemento de la matriz. En un contexto vacío, $text sería reemplazado por una cadena vacía).

Igualmente, la llamada en:

@result = extract_bracketed( $text, '{[' );

devolvería el mismo resultado, ya que todos los conjuntos de ambos tipos de corchetes delimitadores especificados están correctamente anidados y equilibrados.

Sin embargo, la llamada en:

@result = extract_bracketed( $text, '{([<' );

fallaría, devolviendo:

( undef , "{ an '[irregularly :-(] {} parenthesized >:-)' string }"  );

debido a que los pares incrustados de '(..)' y '[..]' están "cruzados" y el '>' incrustado está desequilibrado. (En un contexto escalar, esta llamada devolvería una cadena vacía. En un contexto vacío, $text no se modificaría).

Ten en cuenta que las comillas simples incrustadas en la cadena no ayudan en este caso, ya que no se han especificado como delimitadores aceptables y, por lo tanto, se tratan como caracteres no delimitadores (y se ignoran).

Sin embargo, si una especie particular de carácter de comilla se incluye en la especificación del delimitador, entonces ese tipo de comilla se manejará correctamente. Por ejemplo, si $text es:

$text = '<A HREF=">>>>">link</A>';

entonces

@result = extract_bracketed( $text, '<">' );

devuelve:

( '<A HREF=">>>>">', 'link</A>', "" )

como se esperaba. Sin la especificación de """ como citador incrustado:

@result = extract_bracketed( $text, '<>' );

el resultado sería:

( '<A HREF=">', '>>>">link</A>', "" )

Además de los delimitadores de comillas "'", """ y "`", el estilo de comillas completo tipo Perl (es decir, q{cadena}, qq{cadena}, etc.) se puede especificar incluyendo la letra 'q' como delimitador. Por lo tanto:

@result = extract_bracketed( $text, '<q>' );

coincidiría correctamente algo como esto:

$text = '<leftop: conj /and/ conj>';

Ver también: "extract_quotelike" y "extract_codeblock".

"extract_variable"
"extract_variable" extrae cualquier variable válida de Perl o expresión que involucre variables, incluyendo escalares, arrays, hashes, accesos a arrays, búsquedas de hashes, llamadas a métodos a través de objetos, llamadas a subrutinas a través de referencias a subrutinas, etc.

La subrutina toma hasta dos argumentos opcionales:

1.
Una cadena a procesar ($_ si se omite la cadena o es "undef")
2.
Una cadena que especifica un patrón a coincidir como prefijo (que se omitirá). Si se omite, se omiten los espacios en blanco opcionales.

En caso de éxito en un contexto de lista, se devuelve una matriz de 3 elementos. Los elementos son:

[0]
la variable extraída, o expresión variable
[1]
el resto del texto de entrada,
[2]
la subcadena del prefijo (si la hay),

En caso de fallo, todos estos valores (excepto el texto restante) son "undef".

En un contexto escalar, "extract_variable" devuelve solo la subcadena completa que coincidió con una expresión variable. Se devuelve "undef" en caso de fallo. Además, el texto de entrada original tiene la subcadena devuelta (y cualquier prefijo) eliminada.

En un contexto vacío, el texto de entrada simplemente tiene la subcadena coincidente (y cualquier prefijo especificado) eliminada.

"extract_tagged"
"extract_tagged" extrae y segmenta texto entre etiquetas especificadas (equilibradas).

La subrutina toma hasta cinco argumentos opcionales:

1.
Una cadena a procesar ($_ si se omite la cadena o es "undef")
2.
Una cadena que especifica un patrón (es decir, regex) para coincidir como etiqueta de apertura. Si se omite la cadena de patrón (o es "undef"), se utiliza un patrón que coincide con cualquier etiqueta XML estándar.
3.
Una cadena que especifica un patrón a coincidir como etiqueta de cierre. Si se omite la cadena de patrón (o es "undef"), la etiqueta de cierre se construye insertando una "/" después de cualquier carácter de corchete inicial en la etiqueta de apertura real que coincidió ( **no** el patrón que coincidió con la etiqueta). Por ejemplo, si el patrón de etiqueta de apertura se especifica como '{{\w+}}' y realmente coincidió con la etiqueta de apertura "{{DATA}}", entonces la etiqueta de cierre construida sería "{{/DATA}}".
4.
Una cadena que especifica un patrón a coincidir como prefijo (que se omitirá). Si se omite, se omiten los espacios en blanco opcionales.
5.
Una referencia de hash que contiene varias opciones de análisis (ver más abajo)

Las diversas opciones que se pueden especificar son:

"reject => $listref"
La referencia de lista contiene una o más cadenas que especifican patrones que **no** deben aparecer dentro del texto etiquetado.

Por ejemplo, para extraer un enlace HTML (que no debe contener enlaces anidados) usa:

extract_tagged($text, '<A>', '</A>', undef, {reject => ['<A>']} );
"ignore => $listref"
La referencia de lista contiene una o más cadenas que especifican patrones que **no** deben tratarse como etiquetas anidadas dentro del texto etiquetado (incluso si coincidirían con el patrón de etiqueta de inicio).

Por ejemplo, para extraer una etiqueta XML arbitraria, pero ignorar elementos "vacíos":

extract_tagged($text, undef, undef, undef, {ignore => ['<[^>]*/>']} );

(ver también "gen_delimited_pat" a continuación).

"fail => $str"
La opción "fail" indica la acción a tomar si no se encuentra una etiqueta de cierre coincidente (es decir, antes del final de la cadena o si coincide algún patrón de "reject"). Por defecto, un fallo al coincidir una etiqueta de cierre hace que "extract_tagged" falle inmediatamente.

Sin embargo, si el valor de la cadena asociado con <reject> es "MAX", entonces "extract_tagged" devuelve la ccompleta el texto hasta el punto de fallo. Si la cadena es "PARA", "extract_tagged" devuelve solo el primer párrafo después de la etiqueta (hasta la primera línea que esté vacía o que solo contenga caracteres de espacio en blanco). Si la cadena es "", se restablece el comportamiento predeterminado (es decir, fallo).

Por ejemplo, supongamos que la etiqueta de inicio "/para" introduce un párrafo, que luego continúa hasta la siguiente etiqueta "/endpara" o hasta que se encuentre otra etiqueta "/para":

$text = "/para línea 1\n\nlínea 3\n/para línea 4";
extract_tagged($text, '/para', '/endpara', undef,
                        {reject => '/para', fail => MAX );
# EXTRAÍDO: "/para línea 1\n\nlínea 3\n"

Supongamos en cambio que, si no se encuentra ninguna etiqueta "/endpara" coincidente, la etiqueta "/para" se refiere solo al párrafo inmediatamente siguiente:

$text = "/para línea 1\n\nlínea 3\n/para línea 4";
extract_tagged($text, '/para', '/endpara', undef,
                {reject => '/para', fail => MAX );
# EXTRAÍDO: "/para línea 1\n"

Tenga en cuenta que el comportamiento de "fail" especificado se aplica también a las etiquetas anidadas.

En caso de éxito en contexto de lista, se devuelve una matriz de 6 elementos. Los elementos son:

[0]
la subcadena etiquetada extraída (incluyendo las etiquetas exteriores),
[1]
el resto del texto de entrada,
[2]
la subcadena prefijo (si la hay),
[3]
la etiqueta de apertura
[4]
el texto entre las etiquetas de apertura y cierre
[5]
la etiqueta de cierre (o "" si no se encontró ninguna etiqueta de cierre)

En caso de fallo, todos estos valores (excepto el texto restante) son "undef".

En contexto escalar, "extract_tagged" devuelve solo la subcadena completa que coincidió con un texto etiquetado (incluyendo las etiquetas de inicio y fin). Se devuelve "undef" en caso de fallo. Además, el texto de entrada tiene eliminada la subcadena devuelta (y cualquier prefijo).

En contexto void, el texto de entrada simplemente tiene eliminada la subcadena coincidente (y cualquier prefijo especificado).

"gen_extract_tagged"
"gen_extract_tagged" genera una nueva subrutina anónima que extrae texto entre etiquetas especificadas (equilibradas). En otras palabras, genera una función idéntica en función a "extract_tagged".

La diferencia entre "extract_tagged" y las subrutinas anónimas generadas por "gen_extract_tagged" es que las subrutinas generadas:

  • no tienen que volver a analizar la especificación de la etiqueta o las opciones de análisis cada vez que se llaman (mientras que "extract_tagged" tiene que reconstruir efectivamente su analizador de etiquetas en cada llamada);
  • utilizan la nueva construcción qr// para precompilar las expresiones regulares que utilizan (mientras que "extract_tagged" utiliza la interpolación de variables de cadena estándar para crear patrones de coincidencia de etiquetas).

La subrutina toma hasta cuatro argumentos opcionales (el mismo conjunto que "extract_tagged" excepto la cadena a procesar). Devuelve una referencia a una subrutina que, a su vez, toma un solo argumento (el texto del cual extraer).

En otras palabras, la implementación de "extract_tagged" es exactamente equivalente a:

sub extract_tagged
{
        my $text = shift;
        $extractor = gen_extract_tagged(@_);
        return $extractor->($text);
}

(aunque "extract_tagged" no está implementado actualmente de esa manera).

El uso de "gen_extract_tagged" para crear funciones de extracción para etiquetas específicas es una buena idea si esas funciones se van a llamar más de una vez, ya que su rendimiento suele ser el doble que el de "extract_tagged", que es más de propósito general.

"extract_quotelike"
"extract_quotelike" intenta reconocer, extraer y segmentar cualquiera de las diversas comillas y operadores tipo comilla de Perl (ver perlop(3)). Los delimitadores anidados con barra invertida, los delimitadores de corchetes equilibrados incrustados (para los operadores tipo comilla) y los modificadores finales se capturan. Por ejemplo, en: 
extract_quotelike 'q # un octothorpe: \# (¡no es el final del q!) #'
extract_quotelike '  "Dijiste, \"Usa sed\"."  '
extract_quotelike ' s{([A-Z]{1,8}\.[A-Z]{3})} /\L$1\E/; '
extract_quotelike ' tr/\\\/\\\\/\\\//ds; '

las operaciones completas de comillas tipo Perl se extraen correctamente.

Tenga en cuenta también que, al usar el modificador /x en una expresión regular, cualquier comentario que contenga el delimitador del patrón actual hará que la expresión regular termine inmediatamente. En otras palabras:

'm /
        (?i)            # INSENSIBLE A MAYÚSCULAS/MINÚSCULAS
        [a-z_]          # ALFABÉTICO/GUION BAJO INICIAL
        [a-z0-9]*       # SEGUIDO POR CUALQUIER NÚMERO DE ALFANUMÉRICOS
   /x'

se extraerá como si fuera:

'm /
        (?i)            # INSENSIBLE A MAYÚSCULAS/MINÚSCULAS
        [a-z_]          # ALFABÉTICO/GUION BAJO INICIAL
   /          # SEGUIDO POR CUALQUIER NÚMERO DE ALFANUMÉRICOS

Este comportamiento es idéntico al del compilador real.

"extract_quotelike" toma dos argumentos: el texto a procesar y un prefijo a coincidir al principio del texto. Si no se especifica prefijo, el valor predeterminado es espacio en blanco opcional. Si no se proporciona texto, se usa $_.

En contexto de lista, se devuelve una matriz de 11 elementos. Los elementos son:

[0]
la subcadena tipo comilla extraída (incluyendo los modificadores finales),
[1]
el resto del texto de entrada,
[2]
la subcadena prefijo (si la hay),
[3]
el nombre del operador tipo comilla (si lo hay),
[4]
el delimitador izquierdo del primer bloque de la operación,
[5]
el texto del primer bloque de la operación (es decir, el contenido de una comilla, la expresión regular de una coincidencia o sustitución o la lista de destino de una traducción),
[6]
el delimitador derecho del primer bloque de la operación,
[7]
el delimitador izquierdo del segundo bloque de la operación (es decir, si es una "s", "tr" o "y"),
[8]
el texto del segundo bloque de la operación (es decir, el reemplazo de una sustitución o la lista de traducción de una traducción),
[9]
el delimitador derecho del segundo bloque de la operación (si lo hay),
[10]
los modificadores finales de la operación (si los hay).

Para cada uno de los campos marcados como "(si lo hay)", el valor predeterminado en caso de éxito es una cadena vacía. En caso de fallo, todos estos valores (excepto el texto restante) son "undef".

En contexto escalar, "extract_quotelike" devuelve solo la subcadena completa que coincidió con una operación tipo comilla (o "undef" en caso de fallo). En contexto escalar o void, el texto de entrada tiene eliminada la misma subcadena (y cualquier prefijo especificado).

Ejemplos:

# Elimina la primera literal tipo comilla que aparece en el texto
        $quotelike = extract_quotelike($text,'.*?');
# Reemplaza una o más literales tipo comilla separadas por espacios en blanco iniciales en $_ con ""
        do { $_ = join '<QLL>', (extract_quotelike)[2,1] } until $@;
# Aísla el patrón de búsqueda en una operación tipo comilla de $text
        ($op,$pat) = (extract_quotelike $text)[3,5];
        if ($op =~ /[ms]/)
        {
                print "patrón de búsqueda: $pat\n";
        }
        else
        {
                print "$op no es una operación de coincidencia de patrones\n";
        }
"extract_quotelike"
"extract_quotelike" puede extraer correctamente "here documents" de una cadena de entrada, pero con una advertencia importante en contextos de lista.

A diferencia de otros tipos de literales tipo comilla, un "here document" rara vez es una subcadena contigua. Por ejemplo, un fragmento de código típico que utiliza "here document" podría verse así:

<<'EOMSG' || die;
Este es el mensaje.
EOMSG
exit;

Dado esto como una cadena de entrada en contexto escalar, "extract_quotelike" devolvería correctamente la cadena "<<'EOMSG'\nEste es el mensaje.\nEOMSG", dejando la cadena " || die;\nexit;" en la variable original. En otras palabras, las dos partes separadas del "here document" se extraen y concatenan correctamente.

En contexto de lista, "extract_quotelike" devolvería la lista

[0]
"<<'EOMSG'\nEste es el mensaje.\nEOMSG\n" (es decir, el "here document" completo extraído, incluyendo los delimitadores delantero y trasero),
[1]
" || die;\nexit;" (es decir, el resto del texto de entrada, concatenado),
[2]
"" (es decir, la subcadena prefijo, trivial en este caso),
[3]
"<<" (es decir, el "nombre" del operador tipo comilla)
[4]
"'EOMSG'" (es decir, el delimitador izquierdo del "here document", incluyendo cualquier comilla),
[5]
"Este es el mensaje.\n" (es decir, el texto del "here document"),
[6]
"EOMSG" (es decir, el delimitador derecho del "here document"),
[7..10]
"" (un "here document" no tiene segundo delimitador izquierdo, segundo texto, segundo delimitador derecho ni modificadores finales).

Sin embargo, la posición coincidente de la variable de entrada se establecería en "exit;" (es decir, *después* del delimitador de cierre del "here document"), lo que haría que el anterior " || die;\nexit;" se omitiera en cualquier secuencia de extracciones de fragmentos de código.

Para evitar este problema, cuando se encuentra un "here document" mientras se extrae de una cadena modificable, "extract_quotelike" silenciosamente vuelve aarranges la cadena a un fragmento equivalente de Perl:

<<'EOMSG'
Este es el mensaje.
EOMSG
|| die;
exit;

en el que el documento here es contiguo. Todavía deja la posición de coincidencia después del documento here, pero ahora el resto de la línea en la que comienza el documento here no se omite.

Para evitar que <extract_quotelike> manipule la entrada de esta manera (este es el único caso en el que un "extract_quotelike" de contexto de lista lo hace), puedes pasar la variable de entrada como un literal interpolado:

$quotelike = extract_quotelike("$var");
"extract_codeblock"
"extract_codeblock" intenta reconocer y extraer una subcadena delimitada por corchetes equilibrados que puede contener corchetes desequilibrados dentro de comillas de Perl u operaciones de estilo de comillas. Es decir, "extract_codeblock" es como una combinación de "extract_bracketed" y "extract_quotelike".

"extract_codeblock" toma los mismos tres parámetros iniciales que "extract_bracketed": un texto para procesar, un conjunto de corchetes delimitadores a buscar y un prefijo para hacer coincidir primero. También toma un cuarto parámetro opcional, que permite que los corchetes delimitadores más externos se especifiquen por separado (ver abajo), y un quinto parámetro utilizado solo por Parse::RecDescent.

Omitir el primer argumento (texto de entrada) significa procesar $_ en su lugar. Omitir el segundo argumento (corchetes delimitadores) indica que solo se usará '{'. Omitir el tercer argumento (argumento de prefijo) implica espacios en blanco opcionales al principio. Omitir el cuarto argumento (corchetes delimitadores más externos) indica que se utilizará el valor del segundo argumento para los delimitadores más externos.

Una vez que se reconocen el prefijo y el corchete de apertura delimitador más externo, los bloques de código se extraen recorriendo el texto de entrada y probando las siguientes alternativas en secuencia:

1.
Intenta hacer coincidir un corchete de cierre. Si el corchete era de la misma especie que el último corchete de apertura, devuelve la subcadena hasta ese punto. Si el corchete no coincidía, devuelve un error.
2.
Intenta hacer coincidir una cita o un operador de estilo de cita. Si se encuentra, llama a "extract_quotelike" para consumirlo. Si "extract_quotelike" falla, devuelve el error que devolvió. De lo contrario, vuelve al paso 1.
3.
Intenta hacer coincidir un corchete de apertura. Si se encuentra, llama a "extract_codeblock" recursivamente para consumir el bloque incrustado. Si la llamada recursiva falla, devuelve un error. De lo contrario, vuelve al paso 1.
4.
Hace coincidir incondicionalmente una palabra desnuda o cualquier otro carácter individual, y luego vuelve al paso 1.

Ejemplos:

# Encuentra un bucle while en el texto
        if ($text =~ s/.*?while\s*\{/{/)
        {
                $loop = "while " . extract_codeblock($text);
        }
# Elimina la primera lista entre paréntesis (que puede incluir
# bloques de código entre paréntesis curvos o rizados u operadores de estilo de cita)
        extract_codeblock $text, "(){}", '[^(]*';

La capacidad de especificar un corchete delimitador externo diferente es útil en algunas circunstancias. Por ejemplo, en el módulo Parse::RecDescent, las acciones del analizador que solo se realizarán en un análisis exitoso se especifican mediante una directiva "<defer:...>". Por ejemplo:

sentence: subject verb object
                <defer: {$::theVerb = $item{verb}} >

Parse::RecDescent usa "extract_codeblock($text, '{}<>')" para extraer el código dentro de la directiva "<defer:...>", pero hay un problema.

Una acción diferida como esta:

<defer: {if ($count>10) {$count--}} >

se analizará incorrectamente como:

<defer: {if ($count>

porque el operador "menor que" se interpreta como un delimitador de cierre.

Pero, extrayendo la directiva usando "extract_codeblock($text, '{}', undef, '<>')" el carácter '>' solo se trata como un delimitador en el nivel más externo del bloque de código, por lo que la directiva se analiza correctamente.

"extract_multiple"
La subrutina "extract_multiple" toma una cadena para procesar y una lista de extractores (subrutinas o expresiones regulares) para aplicar a esa cadena.

En un contexto de matriz, "extract_multiple" devuelve una matriz de subcadenas de la cadena original, extraídas por los extractores especificados. En un contexto escalar, "extract_multiple" devuelve la primera subcadena extraída con éxito de la cadena original. En contextos escalares y vacíos, la cadena original tiene la primera subcadena extraída con éxito eliminada. En todos los contextos, "extract_multiple" comienza en la "pos" actual de la cadena y establece esa "pos" apropiadamente después de que coincida.

Por lo tanto, el objetivo de una llamada a "extract_multiple" en un contexto de matriz es dividir la cadena procesada en tantos campos no superpuestos como sea posible, aplicando repetidamente cada uno de los extractores especificados al resto de la cadena. Por lo tanto, "extract_multiple" es una forma generalizada de la subrutina "split" de Perl.

La subrutina toma hasta cuatro argumentos opcionales:

1.
Una cadena para procesar ($_ si se omite la cadena o "undef")
2.
Una referencia a una lista de referencias de subrutinas y/o objetos qr// y/o cadenas literales y/o referencias de hash, que especifican los extractores a utilizar para dividir la cadena. Si se omite este argumento (o "undef"), se utiliza la siguiente lista: 
[
        sub { extract_variable($_[0], '') },
        sub { extract_quotelike($_[0],'') },
        sub { extract_codeblock($_[0],'{}','') },
]

se utiliza.

3.
Un número que especifica el número máximo de campos a devolver. Si se omite este argumento (o "undef"), la división continúa tanto como sea posible.

Si el tercer argumento es *N*, la extracción continúa hasta que se hayan extraído *N* campos con éxito, o hasta que la cadena se haya procesado por completo.

Tenga en cuenta que en contextos escalares y vacíos, el valor de este argumento se restablece automáticamente a 1 (con "-w", se emite una advertencia si el argumento tiene que restablecerse).

4.
Un valor que indica si las subcadenas no coincidentes (ver abajo) dentro del texto deben omitirse o devolverse como campos. Si el valor es verdadero, dichas subcadenas se omiten. De lo contrario, se devuelven.

El proceso de extracción funciona aplicando cada extractor en secuencia a la cadena de texto.

Si el extractor es una subrutina, se llama en un contexto de matriz y se espera que devuelva una lista de un solo elemento, es decir, el texto extraído. Opcionalmente, también puede devolver dos argumentos adicionales: una cadena que representa el texto restante después de la extracción (como $′ para una coincidencia de patrón) y una cadena que representa cualquier prefijo omitido antes de la extracción (como $` en una coincidencia de patrón). Tenga en cuenta que esto está diseñado para facilitar el uso de otras subrutinas de Text::Balanced con "extract_multiple". Tenga en cuenta también que el valor devuelto por una subrutina extractora no tiene por qué tener relación con la subcadena correspondiente del texto original (ver ejemplos a continuación).

Si el extractor es una expresión regular precompilada o una cadena, se compara con el texto en un contexto escalar con un '\G' inicial y los modificadores gc habilitados. El valor extraído es o bien $1 si esa variable está definida después de la coincidencia, o bien la coincidencia completa (es decir, $&).

Si el extractor es una referencia a un hash, debe contener exactamente un elemento. El valor de ese elemento es uno de los tipos de extractor anteriores (referencia de subrutina, expresión regular o cadena). La clave de ese elemento es el nombre de una clase en la que se bendecirá el valor de retorno exitoso del extractor.

Si un extractor devuelve un valor definido, ese valor se trata inmediatamente como el siguiente campo extraído y se agrega a la lista de campos. Si el extractor se especificó en una referencia de hash, el campo también se bendice en la clase apropiada.

Si el extractor no coincide (en el caso de un extractor regex), o devuelve una lista vacía o un valor indefinido (en el caso de un extractor de subrutina), se asume que no ha logrado extraer. Si ninguna de las subrutinas extractor tiene éxito, se extrae un carácter del inicio del texto y se vuelven a aplicar las subrutinas de extracción. Los caracteres que se eliminan de esta manera se acumulan y eventualmente se convierten en el siguiente campo (a menos que el cuarto argumento sea verdadero, en cuyo caso se descartan).

Por ejemplo, lo siguiente extrae subcadenas que son variables válidas de Perl:

@fields = extract_multiple($text,
                           [ sub { extract_variable($_[0]) } ],
                           undef, 1);

Este ejemplo separa un texto en campos que son delimitados por comillas, entre llaves y cualquier otra cosa. Las partes delimitadas y entre llaves también se bendicen para identificarlas (el "cualquier otra cosa" no está bendecido):

@fields = extract_multiple($text,
           [
                { Delim => sub { extract_delimited($_[0],q{'"}) } },
                { Brack => sub { extract_bracketed($_[0],'{}') } },
           ]);

Esta llamada extrae la siguiente subcadena única que es un operador válido de estilo de cita de Perl (y la elimina de $text):

$quotelike = extract_multiple($text,
                              [
                                sub { extract_quotelike($_[0]) },
                              ], undef, 1);
