NOMBRE

Test::MockObject::Extends - simula parte de un objeto o clase

SINOPSIS

use Some::Class;
use Test::MockObject::Extends;
# crear un objeto para simular
my $object      = Some::Class->new();
# envolver ese mismo objeto con un envoltorio de simulación
$object         = Test::MockObject::Extends->new( $object );
# ahora encadenar simulación y controlar llamadas
$object->set_true( 'parent_method' )
       ->set_always( -grandparent_method => 1 )
       ->clear();

DESCRIPCIÓN

Test::MockObject::Extends te permite simular uno o más métodos de un objeto o clase existente. Esto puede ser muy útil cuando estás probando un módulo bien estructurado que hace casi exactamente lo que quieres. ¿No sería conveniente tomar el control de uno o dos métodos para asegurarte de que recibes resultados comprobables? Ahora puedes.

MÉTODOS

"new( $object | $class )"
new() toma un argumento opcional, el objeto o clase a simular. Si estás simulando un método para un objeto que mantiene estado interno, crea un objeto apropiado y luego pásalo a este constructor. NOTA: esto modificará el objeto en su lugar.

Si estás simulando un objeto que no necesita estado, como en los casos donde no hay datos internos o solo llamarás a métodos de clase, o donde simularás todo el acceso a datos internos, puedes pasar el nombre de la clase para simular parcialmente.

Si aún no has cargado la clase, este método intentará cargarla por ti. Esto puede fallar, así que ten cuidado.

Si no pasas argumentos, asumirá que realmente querías crear un objeto normal de "Test::MockObject" y te lo proporcionará.

Ten en cuenta que si pasas una clase, el objeto devuelto parecerá ser una instancia de esa clase; esto no simula la clase en sí.

"mock( $methodname, $sub_ref )"
Consulta la documentación de Test::MockObject para conocer todas las formas de simular métodos y recuperar información de registro de métodos. Estos métodos devuelven el invocante, por lo que puedes encadenarlos.
unmock( $methodname )
Elimina cualquier simulación activa del método nombrado. Esto significa que cualquier llamada a ese método alcanzará el método de ese nombre en la clase que se está simulando, si existe. Este método devuelve el invocante, puedes encadenarlo.
isa( $class )
Como esperarías de un objeto simulado, esto devolverá verdadero para la clase que está simulando.

MÉTODOS INTERNOS

Para hacer su magia, este módulo utiliza varios métodos internos:

  • check_class_loaded( $parent_class )

    Esto verifica que tienes definido el simulado. Si no es así, intenta cargar el módulo correspondiente por ti.

  • gen_autoload( $extended )

    Devuelve una subrutina AUTOLOAD para el objeto simulado que verifica que el objeto extendido (o clase) puede realizar el método solicitado, que Test::MockObject puede realizarlo, o que el padre tiene su propio AUTOLOAD apropiado. (Debería tener su propio can() en ese caso también).

  • gen_can( $extended )

    Devuelve un método can() para el objeto simulado que respeta el mismo orden de ejecución que gen_autoload().

  • gen_isa( $extended )

    Devuelve un método isa() para el objeto simulado que afirma ser el objeto $extended apropiadamente.

  • gen_get_parents( $extended )

    Devuelve un método "__get_parents()" para el objeto simulado que afirma ser el objeto $extended apropiadamente.

  • gen_package( $extended )

    Crea un nuevo paquete único para el objeto simulado con los métodos apropiados ya instalados.

  • get_class( $invocant )

    Devuelve el nombre de la clase del invocante, ya sea un objeto o un nombre de clase.

ADVERTENCIAS

Puede haber algunos casos extremos extraños con métodos generados dinámicamente en la clase simulada. Realmente deberías usar declaraciones de subrutinas, o al menos configurar can() apropiadamente.

También existen posibles colisiones de nombres con métodos en este módulo o "Test::MockObject", aunque esto debería ser raro.
