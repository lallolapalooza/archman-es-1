Test::Exception(3) Documentación de Perl contribuida por el usuario Test::Exception(3)

NOMBRE

Test::Exception - Probar código basado en excepciones

SINOPSIS

use Test::More tests => 5;
use Test::Exception;
# o si no necesitas Test::More
use Test::Exception tests => 5;
# entonces...
# Comprueba que la excepción representada como cadena coincide con la expresión regular dada
throws_ok { $foo->method } qr/division by zero/, 'división por cero capturada correctamente';
# Comprueba que se lanza una excepción de la clase dada (o subclase)
throws_ok { $foo->method } 'Error::Simple', 'error simple lanzado';

# todas las subrutinas de Test::Exceptions garantizan preservar el estado
# de $@, por lo que puedes hacer cosas como estas después de throws_ok y dies_ok
like $@, 'cómo debería ser la excepción representada como cadena';
# Comprueba que algo murió - no nos importa por qué
dies_ok { $foo->method } 'esperando que muera';
# Comprueba que algo no murió
lives_ok { $foo->method } 'esperando que viva';
# Comprueba que una prueba se ejecuta sin excepción
lives_and { is $foo->method, 42 } 'el método es 42';

# o si no te gustan las funciones prototipadas

throws_ok( sub { $foo->method }, qr/division by zero/,
    'división por cero capturada correctamente' );
throws_ok( sub { $foo->method }, 'Error::Simple',
    'error simple lanzado' );
dies_ok( sub { $foo->method }, 'esperando que muera' );
lives_ok( sub { $foo->method }, 'esperando que viva' );
lives_and( sub { is $foo->method, 42 }, 'el método es 42' );

DESCRIPCIÓN

Este módulo proporciona algunos métodos de conveniencia para probar código basado en excepciones. Está construido con Test::Builder y funciona bien con Test::More y sus similares.

Si aún no estás familiarizado con Test::More, ahora sería el momento de ir a echarle un vistazo.

Puedes especificar el plan de pruebas cuando haces "use Test::Exception" de la misma manera que con "use Test::More". Consulta Test::More para obtener detalles.

NOTA: Test::Exception solo verifica excepciones. Ignorará otros métodos de detención de la ejecución del programa, incluido exit(). Si tienes un exit() en código evaluado, Test::Exception no lo capturará con ninguna de sus funciones de prueba.

NOTA: Este módulo utiliza Sub::Uplevel y depende de la anulación de "CORE::GLOBAL::caller" para ocultar tus bloques de prueba de la pila de llamadas. Si este uso de anulaciones globales te preocupa, el módulo Test::Fatal ofrece una alternativa más minimalista.

throws_ok
Prueba si se lanza una excepción específica. throws_ok() tiene dos formas: 
throws_ok BLOQUE EXPRESION_REGULAR, DESCRIPCION_PRUEBA
throws_ok BLOQUE CLASE, DESCRIPCION_PRUEBA

En la primera forma, la prueba pasa si la excepción representada como cadena coincide con la expresión regular dada. Por ejemplo:

throws_ok { read_file( 'unreadable' ) } qr/No file/, 'no file';

Si tu perl no soporta "qr//", también puedes pasar una cadena similar a una expresión regular, por ejemplo:

throws_ok { read_file( 'unreadable' ) } '/No file/', 'no file';

La segunda forma de la prueba throws_ok() pasa si la excepción es de la misma clase que la proporcionada, o una subclase de esa clase. Por ejemplo:

throws_ok { $foo->bar } "Error::Simple", 'simple error';

Solo pasará si el método "bar" lanza una excepción Error::Simple, o una subclase de una excepción Error::Simple.

Puedes obtener el mismo efecto pasando una instancia de la excepción que quieres buscar. Lo siguiente es equivalente al ejemplo anterior:

my $SIMPLE = Error::Simple->new;
throws_ok { $foo->bar } $SIMPLE, 'simple error';

Si una prueba throws_ok() falla, produce mensajes de diagnóstico apropiados. Por ejemplo:

not ok 3 - simple error
#     Failed test (test.t at line 48)
# expecting: Error::Simple exception
# found: normal exit

Como todas las demás funciones de Test::Exception, puedes evitar prototipos pasando una subrutina explícitamente:

throws_ok( sub {$foo->bar}, "Error::Simple", 'simple error' );

Se devuelve un valor verdadero si la prueba tiene éxito, de lo contrario, falso. Al salir, se garantiza que $@ es la causa de la muerte (si la hay).

Se utiliza una descripción de la excepción que se está comprobando si no se pasa una descripción de prueba opcional.

NOTA: Recuerda que cuando haces "die $string_without_a_trailing_newline", perl añadirá automáticamente el número de línea del script actual, el número de línea de entrada y una nueva línea. Esto formará parte de la cadena que las expresiones regulares de throws_ok comparan.

dies_ok
Comprueba que un fragmento de código muere, en lugar de devolver normalmente. Por ejemplo: 
sub div {
    my ( $a, $b ) = @_;
    return $a / $b;
};
dies_ok { div( 1, 0 ) } 'detección de división por cero';
# o si no te gustan los prototipos
dies_ok( sub { div( 1, 0 ) }, 'detección de división por cero' );

Se devuelve un valor verdadero si la prueba tiene éxito, de lo contrario, falso. Al salir, se garantiza que $@ es la causa de la muerte (si la hay).

Recuerda: Esta prueba pasará si el código muere por cualquier razón. Si te importa la razón, podría ser más sensato escribir una prueba más específica usando throws_ok().

La descripción de la prueba es opcional, pero recomendada.

lives_ok
Comprueba que un fragmento de código no muere. Esto permite que tu script de prueba continúe, en lugar de abortar si obtienes una excepción inesperada. Por ejemplo: 
sub read_file {
    my $file = shift;
    local $/;
    open my $fh, '<', $file or die "open failed ($!)\n";
    $file = <FILE>;
    return $file;
};
my $file;
lives_ok { $file = read_file('test.txt') } 'lectura de archivo';
# o si no te gustan los prototipos
lives_ok( sub { $file = read_file('test.txt') }, 'lectura de archivo' );

Si una prueba lives_ok() falla, produce mensajes de diagnóstico apropiados. Por ejemplo:

not ok 1 - lectura de archivo
#     Failed test (test.t at line 15)
# died: open failed (No such file or directory)

Se devuelve un valor verdadero si la prueba tiene éxito, de lo contrario, falso. Al salir, se garantiza que $@ es la causa de la muerte (si la hay).

La descripción de la prueba es opcional, pero recomendada.

lives_and
Ejecuta una prueba que puede lanzar una excepción. Por ejemplo, en lugar de hacer: 
my $file;
lives_ok { $file = read_file('answer.txt') } 'read_file funcionó';
is $file, "42", 'la respuesta fue 42';

Puedes usar lives_and() así:

lives_and { is read_file('answer.txt'), "42" } 'la respuesta es 42';
# o si no te gustan los prototipos
lives_and(sub {is read_file('answer.txt'), "42"}, 'la respuesta es 42');

Lo cual es lo mismo que hacer

is read_file('answer.txt'), "42\n", 'la respuesta es 42';

a menos que read_file('answer.txt') muera, en cuyo caso obtienes el mismo tipo de error que con lives_ok()

not ok 1 - la respuesta es 42
#     Failed test (test.t at line 15)
# died: open failed (No such file or directory)

Se devuelve un valor verdadero si la prueba tiene éxito, de lo contrario, falso. Al salir, se garantiza que $@ es la causa de la muerte (si la hay).

La descripción de la prueba es opcional, pero recomendada.

SALTANDO PRUEBAS DE TEST::EXCEPTION

A veces queremos usar pruebas de Test::Exception en un conjunto de pruebas, pero no queremos obligar al usuario a tener Test::Exception instalado. Una forma de hacer esto es saltar las pruebas si Test::Exception no está presente. Puedes hacer esto con código como el siguiente:

use strict;
use warnings;
use Test::More;

BEGIN {
    eval "use Test::Exception";
    plan skip_all => "Test::Exception needed" if $@;
}

plan tests => 2;
# ... pruebas que necesitan Test::Exception ...

Ten en cuenta que cargamos Test::Exception en un bloque "BEGIN" asegurando que los prototipos de subrutina estén en su lugar antes de que se compile el resto del script de prueba.
