Test2::API::Context(3perl) Guía de referencia para programadores de Perl Test2::API::Context(3perl)

NOMBRE

Test2::API::Context - Objeto para representar un contexto de prueba.

DESCRIPCIÓN

El objeto de contexto es la interfaz principal para los autores de herramientas de prueba escritas con Test2. El objeto de contexto representa el contexto en el que se desarrolla una prueba (Archivo y Número de Línea), y proporciona una forma rápida de generar eventos desde ese contexto. El objeto de contexto también se encarga de enviar eventos a la instancia correcta de Test2::Hub.

SINOPSIS

En general, no crearás contextos directamente. Para obtener un contexto, siempre debes usar context(), que es exportado por el módulo Test2::API.

use Test2::API qw/context/;
sub my_ok {
    my ($bool, $name) = @_;
    my $ctx = context();
    if ($bool) {
        $ctx->pass($name);
    }
    else {
        $ctx->fail($name);
    }
    $ctx->release; # ¡DEBES hacer esto!
    return $bool;
}

Los objetos de contexto facilitan el envoltorio de otras herramientas que también utilizan contexto. Una vez que obtienes un contexto, cualquier herramienta que llames antes de liberar tu contexto la heredará:

sub wrapper {
    my ($bool, $name) = @_;
    my $ctx = context();
    $ctx->diag("envolviendo my_ok");
    my $out = my_ok($bool, $name);
    $ctx->release; # ¡DEBES hacer esto!
    return $out;
}

DETALLES CRÍTICOS

SIEMPRE DEBES usar la subrutina context() de Test2::API
Crear tu propio contexto a través de "Test2::API::Context->new()" casi nunca producirá un resultado deseable. Usa context(), que es exportado por Test2::API.

Hay un puñado de casos en los que un autor de herramientas puede querer crear un nuevo contexto manualmente, por eso existe el método "new". A menos que realmente sepas lo que estás haciendo, deberías evitarlo.

SIEMPRE DEBES liberar el contexto cuando termines con él
Liberar el contexto le dice al sistema que has terminado con él. Esto le da la oportunidad de ejecutar cualquier tarea de limpieza o devolución de llamada necesaria. Si olvidas liberar el contexto, intentará detectar el problema y te advertirá sobre ello.
NO DEBES pasar objetos de contexto
Cuando obtienes un objeto de contexto, está hecho específicamente para tu herramienta y cualquier herramienta anidada dentro. Si pasas un contexto, corres el riesgo de contaminar otras herramientas con información de contexto incorrecta.

Si estás seguro de que quieres que otra herramienta use el mismo contexto, puedes pasarle una instantánea. "$ctx->snapshot" te dará un clon superficial del contexto que es seguro pasar o almacenar.

NO DEBES almacenar o almacenar en caché un contexto para más tarde
Mientras exista un contexto para un hub dado, todas las herramientas que intenten obtener un contexto obtendrán la instancia existente. Si intentas almacenar el contexto, contaminarás otras herramientas con información de contexto incorrecta.

Si estás seguro de que quieres guardar el contexto para más tarde, puedes usar una instantánea. "$ctx->snapshot" te dará un clon superficial del contexto que es seguro pasar o almacenar.

context() tiene algunos mecanismos para protegerte si causas que un contexto persista más allá del alcance en el que se obtuvo. En la práctica, no debes depender de estas protecciones, y son bastante ruidosas con las advertencias.

DEBES obtener tu contexto tan pronto como sea posible en una herramienta dada
Nunca sabes qué herramientas llamarás dentro de tu propia herramienta necesitarán un contexto. Obtener el contexto temprano asegura que las herramientas anidadas puedan encontrar el contexto que deseas que encuentren.

MÉTODOS

$ctx->done_testing;
Nota que la prueba ha terminado. Si no se ha establecido un plan, esto generará un evento de Plan.
$clone = $ctx->snapshot()
Esto devolverá un clon superficial del contexto. El clon superficial es seguro para almacenar para más tarde.
$ctx->release()
Esto liberará el contexto. Ejecuta tareas de limpieza y varios ganchos importantes. También restaurará $!, $?, y $@ a como estaban cuando se creó el contexto.

Nota: Si un contexto se adquiere más de una vez, se mantiene un contador de referencias interno. release() decrementa el contador de referencias; ninguna de las otras acciones de release() ocurrirá a menos que el contador de referencias llegue a 0. Esto significa que solo la última llamada a release() restablecerá $?, $!, $@ y ejecutará las tareas de limpieza.

$ctx->throw($message)
Esto lanzará una excepción informando al archivo y número de línea del contexto. Esto también liberará el contexto por ti.
$ctx->alert($message)
Esto emitirá una advertencia desde el archivo y número de línea del contexto.
$stack = $ctx->stack()
Esto devolverá la instancia Test2::API::Stack que el contexto usó para encontrar el hub actual.
$hub = $ctx->hub()
Esto devolverá la instancia Test2::Hub que el contexto reconoce como la actual a la que se deben enviar todos los eventos.
$dbg = $ctx->trace()
Esto devolverá la instancia Test2::EventFacet::Trace utilizada por el contexto.
$ctx->do_in_context(\&code, @args);
A veces tienes un contexto que no es el actual, y quieres que las cosas lo usen como el actual. En estos casos, puedes llamar a "$ctx->do_in_context(sub { ... })". Se ejecutará el bloque de código, y cualquier cosa dentro de él que busque un contexto encontrará el contexto sobre el cual se llamó al método.

Esto NO afecta al contexto en otros hubs, solo al hub utilizado por el contexto se verá afectado.

my $ctx = ...;
$ctx->do_in_context(sub {
    my $ctx = context(); # devuelve el $ctx sobre el que se llama la sub
});

Nota: El contexto se clonará realmente, se usará el clon en lugar del original. Esto permite que el ID del hilo, el ID del proceso y las variables de error sean correctos sin modificar el contexto original.

$ctx->restore_error_vars()
Esto establecerá $!, $?, y $@ a como estaban cuando se creó el contexto. No hay localización ni nada hecho aquí, llamar a este método realmente establecerá estas variables.
$! = $ctx->errno()
El valor (numérico) de $! cuando se creó el contexto.
$? = $ctx->child_error()
El valor de $? cuando se creó el contexto.
$@ = $ctx->eval_error()
El valor de $@ cuando se creó el contexto.

MÉTODOS DE PRODUCCIÓN DE EVENTOS

¿Cuál uso?

Los métodos "pass*" y "fail*" son óptimos si cumplen tu situación, usar uno de ellos siempre será lo más óptimo. Dicho esto, son óptimos al eliminar muchas características.

Métodos como "ok" y "note" son atajos para generar eventos comunes de 1 tarea basados en la API antigua, sin embargo, son compatibles con versiones posteriores y fáciles de usar. Si estos cumplen tus necesidades, adelante y úsallos, pero revisa a menudo si hay alternativas que puedan agregarse.

Si deseas generar eventos de nuevo estilo, eventos que hacen muchas cosas a la vez, entonces quieres los métodos "*ev2*". Estos te permiten especificar directamente qué facetas deseas usar.

$event = $ctx->pass()
$event = $ctx->pass($name)
Esto enviará y devolverá un evento Test2::Event::Pass. Opcionalmente puedes proporcionar un $name para la aserción.

El Test2::Event::Pass es un evento especialmente diseñado y optimizado

METHODS

$bool = $ctx->pass($name)
Sends a Test2::Event::Pass event.

This is the most basic way to indicate that a test has passed. It can take an optional test name.

$bool = $ctx->pass($name, @diagnostics)
This sends a Test2::Event::Pass event along with any diagnostics you provide.
$bool = $ctx->release()
This signals that the context is no longer needed. Any active hooks will be called. If this was the last reference to the context, it will be destroyed.
$bool = $ctx->release($name)
This is the same as release(), but it also sends a Test2::Event::Pass event with the given name. It is a shorthand for calling pass() and then release(). 
# Long form
$ctx->pass($name);
$ctx->release;

# Shorthand
$ctx->release($name);
$true = $ctx->pass_and_release()
$true = $ctx->pass_and_release($name)
This is a combination of pass() and release(). You can use this if you do not plan to do anything with the context after sending the event. This helps write more clear and compact code. 
sub shorthand {
    my ($bool, $name) = @_;
    my $ctx = context();
    return $ctx->pass_and_release($name) if $bool;
    ... Handle a failure ...
}
sub longform {
    my ($bool, $name) = @_;
    my $ctx = context();
    if ($bool) {
        $ctx->pass($name);
        $ctx->release;
        return 1;
    }
    ... Handle a failure ...
}
my $event = $ctx->fail()
my $event = $ctx->fail($name)
my $event = $ctx->fail($name, @diagnostics)
This lets you send an Test2::Event::Fail event. You may optionally provide a $name and @diagnostics messages.

Diagnostics messages can be simple strings, data structures, or instances of Test2::EventFacet::Info::Table (which are converted inline into the Test2::EventFacet::Info structure).

my $false = $ctx->fail_and_release()
my $false = $ctx->fail_and_release($name)
my $false = $ctx->fail_and_release($name, @diagnostics)
This is a combination of fail() and release(). This can be used to write clearer and shorter code. 
sub shorthand {
    my ($bool, $name) = @_;
    my $ctx = context();
    return $ctx->fail_and_release($name) unless $bool;
    ... Handle a success ...
}
sub longform {
    my ($bool, $name) = @_;
    my $ctx = context();
    unless ($bool) {
        $ctx->pass($name);
        $ctx->release;
        return 1;
    }
    ... Handle a success ...
}
$event = $ctx->ok($bool, $name)
$event = $ctx->ok($bool, $name, \@on_fail)
NOTE: Use of this method is discouraged in favor of pass() and fail() which produce Test2::Event::Pass and Test2::Event::Fail events. These newer event types are faster and less crufty.

This will create an Test2::Event::Ok object for you. If $bool is false then an Test2::Event::Diag event will be sent as well with details about the failure. If you do not want automatic diagnostics you should use the send_event() method directly.

The third argument "\@on_fail") is an optional set of diagnostics to be sent in the event of a test failure. Unlike with fail() these diagnostics must be plain strings, data structures are not supported.

$event = $ctx->note($message)
Send an Test2::Event::Note. This event prints a message to STDOUT.
$event = $ctx->diag($message)
Send an Test2::Event::Diag. This event prints a message to STDERR.
$event = $ctx->plan($max)
$event = $ctx->plan(0, 'SKIP', $reason)
This can be used to send an Test2::Event::Plan event. This event usually takes either a number of tests you expect to run. Optionally you can set the expected count to 0 and give the 'SKIP' directive with a reason to cause all tests to be skipped.
$event = $ctx->skip($name, $reason);
Send an Test2::Event::Skip event.
$event = $ctx->bail($reason)
This sends an Test2::Event::Bail event. This event will completely terminate all testing.
$event = $ctx->send_ev2(%facets)
This lets you build and send a V2 event directly from facets. The event is returned after it is sent.

This example sends a single assertion, a note (comment for stdout in Test::Builder talk) and sets the plan to 1.

my $event = $ctx->send_event(
    plan   => {count => 1},
    assert => {pass  => 1, details => "A passing assert"},
    info => [{tag => 'NOTE', details => "This is a note"}],
);
$event = $ctx->build_e2(%facets)
This is the same as send_ev2(), except it builds and returns the event without sending it.
$event = $ctx->send_ev2_and_release($Type, %parameters)
This is a combination of send_ev2() and release(). 
sub shorthand {
    my $ctx = context();
    return $ctx->send_ev2_and_release(assert => {pass => 1, details => 'foo'});
}
sub longform {
    my $ctx = context();
    my $event = $ctx->send_ev2(assert => {pass => 1, details => 'foo'});
    $ctx->release;
    return $event;
}
$event = $ctx->send_event($Type, %parameters)
It is better to use send_ev2() in new code.

This lets you build and send an event of any type. The $Type argument should be the event package name with "Test2::Event::" left off, or a fully qualified package name prefixed with a '+'. The event is returned after it is sent.

my $event = $ctx->send_event('Ok', ...);

or

my $event = $ctx->send_event('+Test2::Event::Ok', ...);
$event = $ctx->build_event($Type, %parameters)
It is better to use build_ev2() in new code.

This is the same as send_event(), except it builds and returns the event without sending it.

$event = $ctx->send_event_and_release($Type, %parameters)
It is better to use send_ev2_and_release() in new code.

This is a combination of send_event() and release().

sub shorthand {
    my $ctx = context();
    return $ctx->send_event_and_release(Pass => { name => 'foo' });
}
sub longform {
    my $ctx = context();
    my $event = $ctx->send_event(Pass => { name => 'foo' });
    $ctx->release;
    return $event;
}

HOOKS

There are 2 types of hooks, init hooks, and release hooks. As the names suggest, these hooks are triggered when contexts are created or released.

INIT HOOKS

These are called whenever a context is initialized. That means when a new instance is created. These hooks are NOT called every time something requests a context, just when a new one is created.

GLOBAL

This is how you add a global init callback. Global callbacks happen for every context for any hub or stack.

Test2::API::test2_add_callback_context_init(sub {
    my $ctx = shift;
    ...
});

PER HUB

This is how you add an init callback for all contexts created for a given hub. These callbacks will not run for other hubs.

$hub->add_context_init(sub {
    my $ctx = shift;
    ...
});

PER CONTEXT

This is how you specify an init hook that will only run if your call to context() generates a new context. The callback will be ignored if context() is returning an existing context.

my $ctx = context(on_init => sub {
    my $ctx = shift;
    ...
});

RELEASE HOOKS

These are called whenever a context is released. That means when the last reference to the instance is about to be destroyed. These hooks are NOT called every time "$ctx->release" is called.

GLOBAL

This is how you add a global release callback. Global callbacks happen for every context for any hub or stack.

Test2::API::test2_add_callback_context_release(sub {
    my $ctx = shift;
    ...
});

PER HUB

This is how you add a release callback for all contexts created for a given hub. These callbacks will not run for other hubs.

$hub->add_context_release(sub {
    my $ctx = shift;
    ...
});

PER CONTEXT

This is how you add release callbacks directly to a context. The callback will ALWAYS be added to the context that gets returned, it does not matter if a new one is generated, or if an existing one is returned.

my $ctx = context(on_release => sub {
    my $ctx = shift;
    ...
});
