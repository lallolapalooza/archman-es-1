Template::Tools::ttree(3) Documentación contribuida por el usuario de Perl Template::Tools::ttree(3)

NOMBRE

Template::Tools::ttree - Procesar árboles de directorios completos de plantillas

SINOPSIS

ttree [opciones] [archivos]

DESCRIPCIÓN

El script ttree se utiliza para procesar árboles de directorios completos que contienen archivos de plantillas. El resultado del procesamiento de cada archivo se escribe en un archivo correspondiente en un directorio de destino. El script compara los tiempos de modificación de los archivos de origen y destino (donde ya existen) y procesa solo aquellos archivos que han sido modificados. En otras palabras, es el equivalente a 'make' para el Template Toolkit.

Soporta una serie de opciones que se pueden usar para configurar el comportamiento, definir ubicaciones y establecer opciones del Template Toolkit. El script primero lee el archivo de configuración .ttreerc en el directorio HOME, o un archivo alternativo especificado en la variable de entorno TTREERC. Luego, procesa los argumentos de la línea de comandos, incluyendo cualquier archivo de configuración adicional especificado mediante la opción "-f" (archivo).

El archivo de configuración .ttreerc

Cuando ejecutas ttree por primera vez, te preguntará si quieres que cree un archivo .ttreerc para ti. Este se creará en tu directorio home.

$ ttree
¿Quieres que cree un archivo de ejemplo '.ttreerc' para ti?
(archivo: /home/abw/.ttreerc)   [y/n]: y
/home/abw/.ttreerc creado.  Por favor, edítalo adecuadamente y vuelve a ejecutar ttree

El propósito de este archivo es establecer cualquier opción de configuración global que desees aplicar cada vez que se ejecute ttree. Por ejemplo, puedes usar las opciones "ignore" y "copy" para proporcionar expresiones regulares que especifiquen qué archivos deben ignorarse y cuáles deben copiarse en lugar de procesarse como plantillas. También podrías querer establecer indicadores como "verbose" y "recurse" según tu preferencia.

Un .ttreerc mínimo:

# ignora estos archivos
ignore = \b(CVS|RCS)\b
ignore = ^#
ignore = ~$
# copia estos archivos
copy   = \.(gif|png|jpg|pdf)$ 
# recursa en directorios
recurse
# proporciona información sobre lo que está sucediendo
verbose

En la mayoría de los casos, querrás crear un archivo de configuración ttree diferente para cada proyecto en el que estés trabajando. La opción "cfg" te permite especificar un directorio donde ttree puede encontrar más archivos de configuración.

cfg = /home/abw/.ttree

La opción de línea de comandos "-f" se puede usar para especificar qué archivo de configuración se debe usar. Puedes especificar un nombre de archivo usando una ruta absoluta o relativa:

$ ttree -f /home/abw/web/example/etc/ttree.cfg
$ ttree -f ./etc/ttree.cfg
$ ttree -f ../etc/ttree.cfg

Si el archivo de configuración no comienza con "/" o "." o algo que parezca una ruta absoluta de MS-DOS (por ejemplo, "C:\\etc\\ttree.cfg"), entonces ttree lo buscará en el directorio especificado por la opción "cfg".

$ ttree -f test1          # /home/abw/.ttree/test1

La opción "cfg" solo se puede usar en el archivo .ttreerc. Todas las demás opciones se pueden usar en el .ttreerc o en cualquier otro archivo de configuración de ttree. Todas ellas también se pueden especificar como opciones de línea de comandos.

Recuerda que .ttreerc siempre se procesa antes que cualquier archivo de configuración especificado con la opción "-f". Ciertas opciones como "lib" se pueden usar cualquier número de veces y acumulan sus valores.

Por ejemplo, considera los siguientes archivos de configuración:

/home/abw/.ttreerc:

cfg = /home/abw/.ttree
lib = /usr/local/tt2/templates

/home/abw/.ttree/myconfig:

lib = /home/abw/web/example/templates/lib

Cuando ttree se invoca de la siguiente manera:

$ ttree -f myconfig

la opción "lib" se establecerá con los siguientes directorios:

/usr/local/tt2/templates
/home/abw/web/example/templates/lib

Cualquier plantilla ubicada en /usr/local/tt2/templates se utilizará con preferencia a las ubicadas en /home/abw/web/example/templates/lib. Esto puede ser lo que quieras, pero tal vez no. Por esta razón, es una buena práctica mantener el .ttreerc lo más simple posible y usar diferentes archivos de configuración para cada proyecto de ttree.

Opciones de Directorio

La opción "src" se usa para definir el directorio que contiene las plantillas fuente a procesar. Se puede proporcionar como una opción de línea de comandos o en un archivo de configuración como se muestra aquí:

src = /home/abw/web/example/templates/src

Cada plantilla en este directorio corresponde típicamente a una única página web u otro documento.

La opción "dest" se usa para especificar el directorio de destino para la salida generada.

dest = /home/abw/web/example/html

La opción "lib" se usa para definir uno o más directorios que contienen plantillas de biblioteca adicionales. Estas plantillas no son documentos en sí mismas y típicamente comprenden componentes más pequeños y modulares como encabezados, pies de página y menús que se incorporan a las plantillas de página.

lib = /home/abw/web/example/templates/lib
lib = /usr/local/tt2/templates

La opción "lib" se puede usar repetidamente para agregar directorios adicionales a la ruta de búsqueda.

Una lista de plantillas se puede pasar a ttree como argumentos de línea de comandos.

$ ttree foo.html bar.html

Busca estas plantillas en el directorio "src" y las procesa a través del Template Toolkit, utilizando cualquier componente de plantilla adicional de los directorios "lib". La salida generada se escribe entonces en el archivo correspondiente en el directorio "dest".

Si ttree se invoca sin especificar explícitamente ninguna plantilla a procesar, entonces procesará cada archivo en el directorio "src". Si se establece la opción "-r" (recurse), entonces iterará adicionalmente a través de los subdirectorios y procesará cualquier otro archivo de plantilla que encuentre allí.

$ ttree -r

Si una plantilla ha sido procesada previamente, ttree comparará los tiempos de modificación de los archivos de origen y destino. Si la plantilla de origen (o alguna de la que depende) no ha sido modificada más recientemente que el archivo de salida generado, entonces ttree no la procesará. La opción -a (all) se puede usar para forzar a ttree a procesar todos los archivos independientemente del tiempo de modificación.

$ ttree -a

Cualquier plantilla nombrada explícitamente como argumento de línea de comandos siempre se procesa y se omite la verificación del tiempo de modificación.

Opciones de Archivo

Las opciones "ignore", "copy" y "accept" se usan para especificar expresiones regulares de Perl para filtrar nombres de archivo. Los archivos que coincidan con cualquiera de las opciones "ignore" no se procesarán. Los archivos restantes que coincidan con cualquiera de las expresiones regulares "copy" se copiarán al directorio de destino. Los archivos restantes que luego coincidan con algún criterio de "accept" se procesarán a través del Template Toolkit. Si no se especifica ningún parámetro de "accept", todos los archivos serán aceptados para su procesamiento si aún no se han copiado o ignorado.

# ignora estos archivos
ignore = \b(CVS|RCS)\b
ignore = ^#
ignore = ~$
# copia estos archivos
copy   = \.(gif|png|jpg|pdf)$ 
# acepta solo plantillas .tt2
accept = \.tt2$

La opción "suffix" se usa para definir mapeos entre las extensiones de archivo para las plantillas fuente y los archivos de salida generados. El siguiente ejemplo especifica que las plantillas fuente con una extensión ".tt2"

ttree(1) - Template Toolkit Manual

NAME

ttree - Template Toolkit file processing utility

SYNOPSIS

ttree [options] [template ...]

DESCRIPTION

The "ttree" utility is a command-line script for processing one or more Template Toolkit template files.

It can be used to generate static HTML files from template files, or to process templates and output the results to standard output.

A number of options are available to control the processing of templates, including:

Configuration Files

Options can be specified in a configuration file, typically named ".ttreerc" or "ttree.conf" in the current directory or in the user's home directory. The file is read and parsed as a series of Perl statements.

A configuration file can also be specified using the "--config" option.

$ ttree --config=/home/abw/web/etc/ttree.conf

Configuration options can also be set using the standard Template Toolkit configuration directive.

Template-Root = src
Include-Path = lib
Compile-Mask = 0022

For a full list of supported configuration directives, see the Template::Tools documentation.

Input and Output Files

By default, "ttree" processes templates specified on the command line. If no templates are specified, it processes all files in the current directory whose names do not begin with a "." character.

The "--src" and "--lib" options specify directories where template files are located. The "--src" directory is searched first, followed by any directories specified in "--lib".

The "--output" option specifies an output directory where processed files will be saved. If this option is not specified, processed files are saved in the same directory as their source templates.

$ ttree --src src --lib lib --output build

The "--ext" option allows you to specify the file extension for input template files. The default is ".tt".

$ ttree --ext tt

The "--suffix" option allows you to specify a suffix for output files. This is useful for changing the file extension of generated files.

For example, to have all processed templates output as ".html" files:

suffix tt2=html

Or on the command line,

--suffix tt2=html

You can provide any number of different suffix mappings by repeating this option.

Template Dependencies

The "depend" and "depend_file" options allow you to specify how any given template file depends on another file or group of files. The "depend" option is used to express a single dependency.

$ ttree --depend foo=bar,baz

This command line example shows the "--depend" option being used to specify that the foo file is dependant on the bar and baz templates. This option can be used many time on the command line:

$ ttree --depend foo=bar,baz --depend crash=bang,wallop

or in a configuration file:

depend foo=bar,baz
depend crash=bang,wallop

The file appearing on the left of the "=" is specified relative to the "src" or "lib" directories. The file(s) appearing on the right can be specified relative to any of these directories or as absolute file paths.

For example:

$ ttree --depend foo=bar,/tmp/baz

To define a dependency that applies to all files, use "*" on the left of the "=".

$ ttree --depend *=header,footer

or in a configuration file:

depend *=header,footer

Any templates that are defined in the "pre_process", "post_process", "process" or "wrapper" options will automatically be added to the list of global dependencies that apply to all templates.

The "depend_file" option can be used to specify a file that contains dependency information.

$ ttree --depend_file=/home/abw/web/example/etc/ttree.dep

Here is an example of a dependency file:

# This is a comment. It is ignored.

index.html: header footer menubar 

header: titlebar hotlinks

menubar: menuitem

# spanning multiple lines with the backslash
another.html: header footer menubar \
sidebar searchform

Lines beginning with the "#" character are comments and are ignored. Blank lines are also ignored. All other lines should provide a filename followed by a colon and then a list of dependant files separated by whitespace, commas or both. Whitespace around the colon is also optional. Lines ending in the "\" character are continued onto the following line.

Files that contain spaces can be quoted. That is only necessary for files after the colon (':'). The file before the colon may be quoted if it contains a colon.

As with the command line options, the "*" character can be used as a wildcard to specify a dependency for all templates.

* : config,header

Template Toolkit Options

ttree also provides access to the usual range of Template Toolkit options. For example, the "--pre_chomp" and "--post_chomp" ttree options correspond to the "PRE_CHOMP" and "POST_CHOMP" options.

Run "ttree -h" for a summary of the options available.
