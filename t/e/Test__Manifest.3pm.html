Test::Manifest(3) Documentación Perl contribuida por el usuario Test::Manifest(3)

NOMBRE

Test::Manifest - interactúa con un archivo t/test_manifest

SINOPSIS

# en Makefile.PL
eval "use Test::Manifest 2.00";
# en Build.PL
my $class = do {
        if( eval 'use Test::Manifest 2.00; 1' ) {
                Test::Manifest->get_module_build_subclass;
                }
        else {
                'Module::Build';
                }
        };
my $build = $class->new( ... )
# en el archivo t/test_manifest, lista las pruebas que quieres
# ejecutar en el orden en que quieres ejecutarlas

DESCRIPCIÓN

"Test::Harness" asume que quieres ejecutar todos los archivos .t del directorio t/ en orden alfabético (ASCII) durante "make test" o "./Build test" a menos que se indique lo contrario. Esto lleva a esquemas de nombres interesantes para los archivos de prueba para que estén en el orden deseado. Estos nombres interesantes se solidifican cuando entran en el control de versiones, y se vuelven aún más interesantes a medida que aparecen más pruebas.

"Test::Manifest" anula el orden predeterminado de los archivos de prueba. En lugar de ejecutar todos los archivos t/*.t en orden alfabético (ASCII), busca en el archivo t/test_manifest para averiguar qué pruebas quieres ejecutar y en qué orden. Construye el valor correcto para que el sistema de compilación haga lo correcto.

En t/test_manifest, simplemente lista las pruebas que quieres ejecutar. Su orden en el archivo es el orden en el que se ejecutan. Puedes comentar líneas con un "#", al igual que en Perl, y "Test::Manifest" eliminará los espacios en blanco al principio y al final de cada línea. También comprueba que el archivo especificado esté realmente en el directorio t/. Si el archivo no existe, no pone su nombre en la lista de archivos de prueba a ejecutar y emitirá una advertencia.

Opcionalmente, puedes añadir un número después del nombre de la prueba en test_manifest para definir conjuntos de pruebas. Véase "get_t_files" para más información.

ExtUtils::MakeMaker

Para anular el comportamiento del orden de las pruebas en "MakeMaker", "Test::Manifest" se inserta en el paso "test_via_harness" proporcionando su propio ejecutor de pruebas. En "Makefile.PL", todo lo que tienes que hacer es cargar "Test::Manifest" antes de llamar a "WriteMakefile". Para hacerlo opcional, cárgalo en un eval:

eval "use Test::Manifest";

Module::Build

Anular partes de "Module::Build" es más complicado si quieres usar el mecanismo de subclasificación y aún así hacer que "Test::Manifest" sea opcional. Si puedes cargar "Test::Manifest" (versión 2.00 o posterior), "Test::Manifest" puede crear la subclase por ti.

my $class = do {
        if( eval 'use Test::Manifest 2.00; 1' ) {
                Test::Manifest->get_module_build_subclass;
                }
        else {
                'Module::Build' # si Test::Manifest no está ahí
                }
        };
$class->new( ... );
$class->create_build_file;

Esto es un problema cuando ya tienes tu propia subclase. "Test::Manifest" anula "find_test_files", por lo que puedes obtener solo ese código para añadirlo a tu propia cadena de código de subclase:

my $code = eval 'use Test::Manifest 2.00; 1'
                ?
        Test::Manifest->get_module_build_code_string
                :
        '';
my $class = Module::Build->subclass(
        ...,
        code => "$code\n...tu cadena de código de subclase...",
        );

Métodos de clase

get_module_build_subclass
Solo para "Module::Build".

Devuelve una subclase de "Module::Build" que anula "find_test_files". Si quieres tener tu propia subclase de "Module::Build" y aún así usar "Test::Manifest", puedes obtener solo la cadena de código con "get_module_build_code_string".

get_module_build_code_string
Solo para "Module::Build".

Devuelve el "find_test_files" anulado como código Perl en una cadena adecuada para la clave "code" en "Module::Build-"subclass()>. Puedes añadir esto a otras partes que estés anulando o extendiendo.

Ver "Module::Build::Base::find_test_files" para ver la implementación base.

Funciones

run_t_manifest( TEST_VERBOSE, INST_LIB, INST_ARCHLIB, TEST_LEVEL )
Solo para "MakeMaker". No tienes que lidiar con esto a nivel de usuario.

Ejecuta todos los archivos en t/test_manifest a través de "Test::Harness:runtests" en el orden en que aparecen en el archivo. Esto se inserta automáticamente

eval "use Test::Manifest";
get_t_files( [LEVEL] )
En contexto escalar devuelve una única cadena que puedes usar directamente en WriteMakefile(). En contexto de lista devuelve una lista de los archivos que encontró en t/test_manifest.

Si un archivo t/test_manifest no existe, get_t_files() no devuelve nada.

get_t_files() te advierte si no puede encontrar t/test_manifest, o si las entradas empiezan con t/. Omite las líneas en blanco y elimina los comentarios estilo Perl del archivo.

Cada línea en t/test_manifest puede tener tres partes: el nombre de la prueba, el nivel de la prueba (un número decimal) y un comentario. Por defecto, el nivel de la prueba es 1.

test_name.t 2  #Ejecutar esto solo para pruebas de nivel 2

Sin argumento, get_t_files() devuelve todos los archivos de prueba que encuentra. Con un argumento que sea verdadero (para que no puedas usar 0 como nivel) y sea un número, omite las pruebas con un nivel mayor que ese argumento. Luego puedes definir conjuntos de pruebas y elegir un conjunto para ejecutar. Por ejemplo, podrías crear un conjunto para usuarios finales, pero también añadir un conjunto para pruebas más profundas para desarrolladores.

Experimentalmente, puedes incluir un comando para obtener nombres de pruebas de otro archivo. El comando empieza con un ";" para distinguirlo de un nombre de archivo real. El nombre del archivo (actualmente) es relativo al directorio de trabajo actual, a diferencia de los nombres de archivo, que son relativos a "t/". Los nombres de archivo en el archivo incluido siguen siendo relativos a "t/".

;include t/file_with_other_test_names.txt

También experimentalmente, puedes hacer que "Test::Manifest" deje de leer nombres de archivo con la directiva ";skip". "Test::Manifest" omitirá los nombres de archivo hasta la directiva ";unskip" (o el final del archivo):

run_this1
;skip
skip_this
;unskip
run_this2

Para seleccionar conjuntos de pruebas, especifica el nivel en la variable de entorno "TEST_LEVEL":

make test # ejecutar todas las pruebas sin importar el nivel
make test TEST_LEVEL=2  # ejecutar todas las pruebas de nivel 2 y por debajo

Eventualmente esto terminará como una opción para Build.PL:

./Build test --testlevel=2  # Todavía no soportado
Test::Manifest 2.026-1 - make_test_manifest, manifest_name

NAME

Test::Manifest - A simple module to generate a test manifest

SYNOPSIS

    use Test::Manifest;
    
    make_test_manifest();
    
    my $manifest_file = manifest_name();

DESCRIPTION

This module provides a simple way to generate a test manifest file for a distribution. The manifest file, named test_manifest by default, lists all the test files in the t/ directory.

make_test_manifest()
Creates the test_manifest file in the t directory by reading the contents of the t/ directory.

TO DO: specify tests in argument lists.

TO DO: specify files to skip.

manifest_name()
Returns the name of the test manifest file, relative to t/.
