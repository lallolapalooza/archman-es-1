NOMBRE

Term::UI - UI de Term::ReadLine hecha fácil

SINOPSIS

use Term::UI;
use Term::ReadLine;
my $term = Term::ReadLine->new('brand');
my $reply = $term->get_reply(
                prompt => '¿Cuál es tu color favorito?',
                choices => [qw|azul rojo verde|],
                default => 'azul',
);
my $bool = $term->ask_yn(
                    prompt => '¿Te gustan las galletas?',
                    default => 's',
            );
my $string = q[comando --opcion --no-foo --quux='esta cosa'];
my ($options,$munged_input) = $term->parse_options($string);
### no hacer que Term::UI emita advertencias -- el valor predeterminado es '1'
$Term::UI::VERBOSE = 0;
### elegir siempre el valor predeterminado (bueno para términos no interactivos)
### -- el valor predeterminado es '0'
$Term::UI::AUTOREPLY = 1;
### Obtener toda la sesión como una cadena imprimible:
$hist = Term::UI::History->history_as_string;
$hist = $term->history_as_string;

DESCRIPCIÓN

"Term::UI" es una forma transparente de eliminar la sobrecarga de tener que formatear una pregunta y luego validar la respuesta, informando al usuario si la respuesta no fue adecuada y volviendo a emitir la pregunta.

Simplemente dale la pregunta que quieres hacer, opcionalmente con opciones de las que el usuario puede elegir y un valor predeterminado, y "Term::UI" hará lo que esperas.

Para hacer una pregunta de sí o no, hay incluso un atajo.

CÓMO FUNCIONA

"Term::UI" se coloca al final del array @ISA de "Term::ReadLine", por lo que puedes llamar a sus funciones a través de tu objeto de terminal.

"Term::UI" utiliza "Term::UI::History" para registrar todas las interacciones con la línea de comandos. Puedes recuperar este historial, o modificar el manejador de archivo al que se imprime la interacción. Consulta la página del manual de "Term::UI::History" o la "SINOPSIS" para obtener detalles.

MÉTODOS

$reply = $term->get_reply( prompt => 'pregunta?', [choices => \@lista, default => $lista[0], preput => "texto para poner como entrada de usuario predeterminada", multi => BOOL, print_me => "texto adicional para imprimir y registrar", allow => $ref] );

"get_reply" hace una pregunta al usuario y luego devuelve la respuesta al que llama. Si la respuesta no es válida (más sobre esto a continuación), se volverá a plantear la pregunta, hasta que se haya introducido una respuesta satisfactoria.

Tienes la opción de proporcionar una lista de opciones de las que el usuario puede elegir utilizando el argumento "choices". Si la respuesta no está en la lista de opciones presentadas, se volverá a plantear la pregunta.

Si proporcionas una respuesta "default", esta se devolverá cuando $AUTOREPLY se establezca en verdadero (ver la sección "VARIABLES GLOBALES" más abajo), o cuando el usuario simplemente presione "enter".

El argumento "preput" permite especificar un texto que se insertará en la línea de indicaciones como entrada inicial que el usuario puede editar, eliminar o aceptar. Si proporcionas la cadena vacía como argumento "preput", entonces el valor "default" se pre-insertará. Solo funcionará si el módulo subyacente de readline proporciona soporte para ello (actualmente solo es compatible con "Term::Readline::Gnu").

Puedes indicar que al usuario se le permite introducir respuestas múltiples activando el indicador "multi". Ten en cuenta que se te devolverá una lista de respuestas, en lugar de una cadena simple.

Especificando un manejador "allow", puedes validar tú mismo la respuesta que da un usuario. Puede ser cualquiera de los tipos que la función "allow" de Params::Check permite, así que por favor consulta esa página del manual para obtener detalles.

Finalmente, tienes la opción de añadir un argumento "print_me", que simplemente se imprime antes de la indicación. Se imprime en el mismo manejador de archivo que el resto de las preguntas, por lo que puedes usarlo para llevar un registro de una sesión completa de preguntas y respuestas con el usuario, y recuperarlo más tarde usando la función "Term::UI->history_as_string".

Consulta la sección "EJEMPLOS" para ver muestras de cómo usar esta función.

$bool = $term->ask_yn( prompt => "tu pregunta", [default => (s|1,n|0), print_me => "texto adicional para imprimir y registrar"] )

Hace una simple pregunta de "sí" o "no" al usuario, devolviendo un valor booleano que indica "verdadero" o "falso" al que llama.

La respuesta "default" se devolverá automáticamente si el usuario presiona "enter" o si $AUTOREPLY está establecido en verdadero. Ver la sección "VARIABLES GLOBALES" más abajo.

Además, tienes la opción de añadir un argumento "print_me", que simplemente se imprime antes de la indicación. Se imprime en el mismo manejador de archivo que el resto de las preguntas, por lo que puedes usarlo para llevar un registro de una sesión completa de preguntas y respuestas con el usuario, y recuperarlo más tarde usando la función "Term::UI->history_as_string".

Consulta la sección "EJEMPLOS" para ver muestras de cómo usar esta función.

($opts, $munged) = $term->parse_options( CADENA );

"parse_options" convertirá todas las opciones dadas de una cadena de entrada a una referencia de hash. Si se llama en contexto de lista, también devolverá la parte de la cadena de entrada en la que no encontró ninguna opción.

Considera este ejemplo:

my $str =   q[comando --no-foo --baz --bar=0 --quux=bleh ] .
            q[--option="algo'cosa" -un-guion -single=blah' arg];
my ($options,$munged) =  $term->parse_options($str);
### $options contendría: ###
$options = {
            'foo'       => 0,
            'bar'       => 0,
            'one-dash'  => 1,
            'baz'       => 1,
            'quux'      => 'bleh',
            'single'    => 'blah\'',
            'option'    => 'algo\'cosa'
};
### y esta es la versión modificada de la cadena de entrada,
### es decir, lo que queda de la entrada menos las opciones
$munged = 'comando arg';

Como puedes ver, puedes usar un guion simple o doble para indicar una opción. Si antepones "no-" a una opción y no le das valor, se establecerá en 0. Si no tiene prefijo ni valor, se establecerá en 1. De lo contrario, se establecerá en su valor. Ten en cuenta también que puede manejar correctamente problemas de comillas simples/dobles.

$str = $term->history_as_string

Esto devolverá toda la interacción entre el usuario y el programa como una cadena de texto.

VARIABLES GLOBALES

$Term::UI::VERBOSE

Si se establece en falso, se omitirán las advertencias de "Term::UI". El valor predeterminado es verdadero, lo que significa que se emitirán advertencias.

$Term::UI::AUTOREPLY

Si se establece en verdadero, las preguntas que tengan un valor predeterminado siempre devolverán ese valor predeterminado sin esperar una entrada del usuario. El valor predeterminado es falso.

EJEMPLOS

Sí/no simple

#!/usr/bin/perl
use strict;
use warnings;
use Term::UI;
use Term::ReadLine;
my $term = Term::ReadLine->new('example');
my $ok = $term->ask_yn( prompt => '¿Este script funciona?', default => 's' );
if ($ok) {
    print "¡Genial!\n";
} else {
    print "Oh, bueno.\n";
}

Opciones con valor predeterminado

#!/usr/bin/perl
use strict;
use warnings;
use Term::UI;
use Term::ReadLine;
my $term = Term::ReadLine->new('example');
my @colors = qw(red green blue yellow);
my $color = $term->get_reply(
    prompt  => '¿Cuál es tu color favorito?',
    choices => \@colors,
    default => 'green',
);
print "Tu color favorito es $color\n";

Análisis de línea de comandos

#!/usr/bin/perl
use strict;
use warnings;
use Term::UI;
use Term::ReadLine;
my $term = Term::ReadLine->new('example');
my $string = q[ls -l --color=auto -a --time-style=long-iso];
my ($options,$munged) = $term->parse_options($string);
# $options contendrá: { 'l' => 1, 'color' => 'auto', 'a' => 1, 'time-style' => 'long-iso' }
# $munged contendrá: 'ls'
use Data::Dumper;
print Dumper($options);
print "Munged: $munged\n"

Entrada de múltiples valores

#!/usr/bin/perl
use strict;
use warnings;
use Term::UI;
use Term::ReadLine;
my $term = Term::ReadLine->new('example');
my $answer = $term->get_reply(
    prompt => '¿Qué usuarios quieres incluir (separados por comas)?',
    multi  => 1,
);
print Dumper($answer);

NAME

Term::UI - A module for building interactive command-line applications.

SYNOPSIS

    use Term::UI;
    my $term = Term::UI->new;
    my $name = $term->get_reply( prompt => 'What is your name?' );
    my $colour = $term->get_reply(
        prompt  => 'What is your favourite colour?',
        choices => [qw|red green blue|] );
    my $drink = $term->get_reply(
        prompt  => 'What is your favourite drink?',
        choices => [qw|water beer wine|],
        default => 'water' );
    my $bool = $term->ask_yn( prompt => 'Do you like this module?' );

DESCRIPTION

Term::UI is a Perl module that provides a simple interface for building command-line applications that require user input.

It allows you to ask users questions, provide them with a list of choices, set default answers, and validate their input.

HOW IT WORKS

Term::UI works by interacting directly with the user's terminal. It prompts the user for input and reads the response. Depending on the method used, it can validate the input against a list of allowed choices or patterns.

The module utilizes `Term::ReadLine` internally if available to provide features like command history and line editing. If `Term::ReadLine` is not available, it falls back to basic input reading.

METHODS

new

Creates a new Term::UI object.

    my $term = Term::UI->new;

get_reply

Prompts the user for a reply. This method accepts several arguments:

prompt (required)
The question to ask the user.
choices (optional)
An array reference of valid choices. If provided, the user's input will be validated against this list.
default (optional)
A default answer. If the user just presses Enter, this default value will be returned. If choices is also provided, the default value must be one of the choices.
multi (optional)
A boolean value. If set to true, the user can select multiple choices. The input is expected to be space-separated numbers corresponding to the choices.
print_me (optional)
A string to print before the prompt and choices. Useful for providing context or instructions.
allow (optional)
A value or a subroutine reference used for custom validation. If it's a value, the user's input must match this value. If it's a subroutine, it will be called with the user's input, and it should return a true value if the input is valid.

Example:

    my $colour = $term->get_reply(
        prompt  => 'Choose a colour:',
        choices => [qw|red green blue|],
        default => 'green' );

ask_yn

A convenience method for asking a yes/no question. It takes the same options as get_reply, but automatically handles 'y'/'n' choices. Returns true for 'yes' and false for 'no'.

prompt (required)
The question to ask.
default (optional)
The default answer ('y' or 'n'). Defaults to 'y'.
print_me (optional)
Text to print before the prompt.

Example:

    if ( $term->ask_yn( prompt => 'Continue?', default => 'n' ) ) {
        print "Continuing...\n";
    }

history_as_string

Returns a string representation of the interaction history (prompts and user replies). This is a convenience wrapper around "Term::UI::History->history_as_string".

Consult the "Term::UI::History" man page for details.

GLOBAL VARIABLES

The behaviour of Term::UI can be altered by changing the following global variables:

$Term::UI::VERBOSE

This controls whether Term::UI will issue warnings and explanations as to why certain things may have failed. If you set it to 0, Term::UI will not output any warnings. The default is 1;

$Term::UI::AUTOREPLY

This will make every question be answered by the default, and warn if there was no default provided. This is particularly useful if your program is run in non-interactive mode. The default is 0;

$Term::UI::INVALID

This holds the string that will be printed when the user makes an invalid choice. You can override this string from your program if you, for example, wish to do localization. The default is "Invalid selection, please try again: "

$Term::UI::History::HISTORY_FH

This is the filehandle all the print statements from this module are being sent to. Please consult the "Term::UI::History" manpage for details.

This defaults to *STDOUT.

EXAMPLES

Basic get_reply sample

### ask a user (with an open question) for their favourite colour
$reply = $term->get_reply( prompt => 'Your favourite colour? );

which would look like:

Your favourite colour?

and $reply would hold the text the user typed.

get_reply with choices

### now provide a list of choices, so the user has to pick one
$reply = $term->get_reply(
            prompt  => 'Your favourite colour?',
            choices => [qw|red green blue|] );

which would look like:

  1> red
  2> green
  3> blue
Your favourite colour?

$reply will hold one of the choices presented. "Term::UI" will repose the question if the user attempts to enter an answer that's not in the list of choices. The string presented is held in the $Term::UI::INVALID variable (see the "GLOBAL VARIABLES" section for details.

get_reply with choices and default

### provide a sensible default option -- everyone loves blue!
$reply = $term->get_reply(
            prompt  => 'Your favourite colour?',
            choices => [qw|red green blue|],
            default => 'blue' );

which would look like:

  1> red
  2> green
  3> blue
Your favourite colour? [3]:

Note the default answer after the prompt. A user can now just hit "enter" (or set $Term::UI::AUTOREPLY -- see the "GLOBAL VARIABLES" section) and the sensible answer 'blue' will be returned.

get_reply using print_me & multi

### allow the user to pick more than one colour and add an
### introduction text
@reply = $term->get_reply(
            print_me    => 'Tell us what colours you like',
            prompt      => 'Your favourite colours?',
            choices     => [qw|red green blue|],
            multi       => 1 );

which would look like:

Tell us what colours you like
  1> red
  2> green
  3> blue
Your favourite colours?

An answer of "3 2 1" would fill @reply with "blue green red"

get_reply & allow

### pose an open question, but do a custom verification on
### the answer, which will only exit the question loop, if
### the answer matches the allow handler.
$reply = $term->get_reply(
            prompt  => "What is the magic number?",
            allow   => 42 );

Unless the user now enters 42, the question will be reposed over and over again. You can use more sophisticated "allow" handlers (even subroutines can be used). The "allow" handler is implemented using "Params::Check"'s "allow" function. Check its manpage for details.

an elaborate ask_yn sample

### ask a user if he likes cookies. Default to a sensible 'yes'
### and inform him first what cookies are.
$bool = $term->ask_yn( prompt   => 'Do you like cookies?',
                       default  => 'y',
                       print_me => 'Cookies are LOVELY!!!' );

would print:

Cookies are LOVELY!!!
Do you like cookies? [Y/n]:

If a user then simply hits "enter", agreeing with the default, $bool would be set to "true". (Simply hitting 'y' would also return "true". Hitting 'n' would return "false")

We could later retrieve this interaction by printing out the Q&A history as follows:

print $term->history_as_string;

which would then print:

Cookies are LOVELY!!!
Do you like cookies? [Y/n]:  y

There's a chance we're doing this non-interactively, because a console is missing, the user indicated he just wanted the defaults, etc.

In this case, simply setting $Term::UI::AUTOREPLY to true, will return from every question with the default answer set for the question. Do note that if "AUTOREPLY" is true, and no default is set, "Term::UI" will warn about this and return "undef".
