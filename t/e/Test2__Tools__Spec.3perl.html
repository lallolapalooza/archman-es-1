Test2::Tools::Spec(3perl) Guía de Referencia para Programadores de Perl Test2::Tools::Spec(3perl)

NOMBRE

Test2::Tools::Spec - Implementación RSPEC sobre Test2::Workflow

DESCRIPCIÓN

Esto usa Test2::Workflow para implementar una variante de RSPEC. Esta variante soporta aislamiento y/o concurrencia mediante bifurcación o hilos.

SINOPSIS

use Test2::Bundle::Extended;
use Test2::Tools::Spec;
describe foo => sub {
    before_all  once => sub { ... };
    before_each many => sub { ... };
    after_all  once => sub { ... };
    after_each many => sub { ... };
    case condition_a => sub { ... };
    case condition_b => sub { ... };
    tests foo => sub { ... };
    tests bar => sub { ... };
};
done_testing;

EXPORTA

Todos estos usan el mismo patrón de argumento. El primer argumento debe ser siempre un nombre para el bloque. El último argumento debe ser siempre una referencia de código. Opcionalmente, se puede insertar un hash de configuración entre el nombre y la referencia de código.

FUNCTION "nombre" => sub { ... };
FUNCTION "nombre" => {...}, sub { ... };
NOMBRE
El primer argumento de una función Test2::Tools::Spec DEBE ser un nombre. El nombre no necesita ser único.
PARÁMETROS
Este argumento es opcional. Si está presente, debe ser un hashref.

Aquí están las claves válidas para el hashref:

flat => $bool
Si esto se establece en verdadero, el bloque no se renderizará como una subprueba, sino que los eventos estarán en línea con la subprueba padre (o la prueba principal).
async => $bool
Establezca esto en verdadero para marcar un bloque como capaz de ejecutarse concurrentemente con otros bloques de prueba. Esto no significa que el bloque SE EJECUTARÁ concurrentemente, solo que puede hacerlo.
iso => $bool
Establezca esto en verdadero si el bloque DEBE ejecutarse de forma aislada. Si esto es verdadero, el bloque se ejecutará en su propio proceso bifurcado.

Estas pruebas se omitirán en cualquier plataforma que no tenga bifurcación real, o hilos funcionales/habilitados.

Los hilos SOLO se usarán si la variable de entorno T2_WORKFLOW_USE_THREADS está establecida. Las pruebas de hilos solo se ejecutan si la variable de entorno T2_DO_THREAD_TESTS está establecida.

todo => $reason
Use esto para marcar un bloque completo como TODO.
skip => $reason
Use esto para evitar que un bloque se ejecute en absoluto.
REFERENCIA DE CÓDIGO
Este argumento es obligatorio. Debe ser una referencia de código que ejecutará algunas aserciones.

ESENCIALES

tests NOMBRE => sub { ... }
tests NOMBRE => \%params, sub { ... }
tests($NOMBRE, \%PARAMS, \&CÓDIGO)
it NOMBRE => sub { ... }
it NOMBRE => \%params, sub { ... }
it($NOMBRE, \%PARAMS, \&CÓDIGO)
Esto define un bloque de prueba. Los bloques de prueba son esencialmente subpruebas. Todos los bloques de prueba se ejecutarán y se espera que produzcan eventos. Los bloques de prueba pueden ejecutarse varias veces si la función case() también se usa.

it() es un alias de tests().

ESTOS NO se heredan por bloques describe anidados.

case NOMBRE => sub { ... }
case NOMBRE => \%params, sub { ... }
case($NOMBRE, \%PARAMS, \&CÓDIGO)
Esto te permite especificar múltiples condiciones en las que se deben ejecutar los bloques de prueba. Cada bloque de prueba dentro del mismo grupo ("describe") se ejecutará una vez por cada caso.

ESTOS NO se heredan por bloques describe anidados, pero los bloques describe anidados se ejecutarán una vez por cada caso.

before_each NOMBRE => sub { ... }
before_each NOMBRE => \%params, sub { ... }
before_each($NOMBRE, \%PARAMS, \&CÓDIGO)
Especifica un bloque de código que debe ejecutarse varias veces, una vez antes de que se ejecute cada bloque de tests(). Estos se ejecutarán DESPUÉS de los bloques de case() pero antes de los bloques de tests().

ESTOS SE HEREDAN por bloques describe anidados.

before_case NOMBRE => sub { ... }
before_case NOMBRE => \%params, sub { ... }
before_case($NOMBRE, \%PARAMS, \&CÓDIGO)
Igual que before_each(), excepto que estos bloques se ejecutan ANTES de los bloques de case().

ESTOS NO se heredan por bloques describe anidados.

before_all NOMBRE => sub { ... }
before_all NOMBRE => \%params, sub { ... }
before_all($NOMBRE, \%PARAMS, \&CÓDIGO)
Especifica un bloque de código que debe ejecutarse una vez, antes de que se ejecuten todos los bloques de prueba.

ESTOS NO se heredan por bloques describe anidados.

around_each NOMBRE => sub { ... }
around_each NOMBRE => \%params, sub { ... }
around_each($NOMBRE, \%PARAMS, \&CÓDIGO)
Especifica un bloque de código que debe envolver cada bloque de prueba. Estos bloques se ejecutan DESPUÉS de los bloques de caso, pero antes de los bloques de prueba. 
around_each wrapit => sub {
    my $cont = shift;
    local %ENV = ( ... );
    $cont->();
    ...
};

El primer argumento para el bloque de código será una llamada de retorno que DEBE ser llamada en algún lugar dentro del sub para que los elementos anidados se ejecuten.

ESTOS SE HEREDAN por bloques describe anidados.

around_case NOMBRE => sub { ... }
around_case NOMBRE => \%params, sub { ... }
around_case($NOMBRE, \%PARAMS, \&CÓDIGO)
Igual que "around_each" excepto que estos se ejecutan ANTES de los bloques de caso.

ESTOS NO se heredan por bloques describe anidados.

around_all NOMBRE => sub { ... }
around_all NOMBRE => \%params, sub { ... }
around_all($NOMBRE, \%PARAMS, \&CÓDIGO)
Igual que "around_each" excepto que solo se ejecuta una vez para envolver TODOS los bloques de prueba.

ESTOS NO se heredan por bloques describe anidados.

after_each NOMBRE => sub { ... }
after_each NOMBRE => \%params, sub { ... }
after_each($NOMBRE, \%PARAMS, \&CÓDIGO)
Igual que "before_each

HOOKS

These are hooks that will be run before and after your test cases. Note that these are run lexically. This means that if you declare before_all inside of a describe block, it will only run for that describe block and its children.

These are NOT exported by default.

before_all NAME => sub { ... }
before_all NAME => \%params, sub { ... }
before_all($NAME, \%PARAMS, \&CODE)
This hook will run once, before any test cases are run.
before_case NAME => sub { ... }
before_case NAME => \%params, sub { ... }
before_case($NAME, \%PARAMS, \&CODE)
This hook will run once, before each test case. Note that this is not inherited by nested describe blocks.
before_each NAME => sub { ... }
before_each NAME => \%params, sub { ... }
before_each($NAME, \%PARAMS, \&CODE)
This hook will run once, before each test block.

These ARE inherited by nested describe blocks.

after_each NAME => sub { ... }
after_each NAME => \%params, sub { ... }
after_each($NAME, \%PARAMS, \&CODE)
Same as "before_each" except it runs right after each test block.

These ARE inherited by nested describe blocks.

after_case NAME => sub { ... }
after_case NAME => \%params, sub { ... }
after_case($NAME, \%PARAMS, \&CODE)
Same as "after_each" except it runs right after the case block, and before the test block.

These ARE NOT inherited by nested describe blocks.

after_all NAME => sub { ... }
after_all NAME => \%params, sub { ... }
after_all($NAME, \%PARAMS, \&CODE)
Same as "before_all" except it runs after all test blocks have been run.

These ARE NOT inherited by nested describe blocks.

SHORTCUTS

These are shortcuts. Each of these is the same as tests() except some parameters are added for you.

These are NOT exported by default/.

mini NAME => sub { ... }
Same as: 
tests NAME => { flat => 1 }, sub { ... }
iso NAME => sub { ... }
Same as: 
tests NAME => { iso => 1 }, sub { ... }
miso NAME => sub { ... }
Same as: 
tests NAME => { mini => 1, iso => 1 }, sub { ... }
async NAME => sub { ... }
Same as: 
tests NAME => { async => 1 }, sub { ... }

Note: This conflicts with the async() exported from threads. Don't import both.

masync NAME => sub { ... }
Same as: 
tests NAME => { minit => 1, async => 1 }, sub { ... }

CUSTOM ATTRIBUTE DEFAULTS

Sometimes you want to apply default attributes to all tests() or case() blocks. This can be done, and is lexical to your describe or package root!

use Test2::Bundle::Extended;
use Test2::Tools::Spec ':ALL';
# All 'tests' blocks after this declaration will have C<<iso => 1>> by default
spec_defaults tests => (iso => 1);
tests foo => sub { ... }; # isolated
tests foo, {iso => 0}, sub { ... }; # Not isolated
spec_defaults tests => (iso => 0); # Turn it off again

Defaults are inherited by nested describe blocks. You can also override the defaults for the scope of the describe:

spec_defaults tests => (iso => 1);
describe foo => sub {
    spec_defaults tests => (async => 1); # Scoped to this describe and any child describes
    tests bar => sub { ... }; # both iso and async
};
tests baz => sub { ... }; # Just iso, no async.

You can apply defaults to any type of blocks:

spec_defaults case => (iso => 1); # All cases are 'iso';

Defaults are not inherited when a builder's return is captured.

spec_defaults tests => (iso => 1);
# Note we are not calling this in void context, that is the key here.
my $d = describe foo => {
    tests bar => sub { ... }; # Not iso
};

EXECUTION ORDER

As each function is encountered it executes, just like any other function. The describe() function will immediately execute the codeblock it is given. All other functions will stash their codeblocks to be run later. When done_testing() is run the workflow will be compiled, at which point all other blocks will run.

Here is an overview of the order in which blocks get called once compiled (at done_testing()).

before_all
    for-each-case {
        before_case
            case
        after_case
        # AND/OR nested describes
        before_each
            tests
        after_each
    }
after_all
