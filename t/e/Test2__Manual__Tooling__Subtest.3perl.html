Test2::Manual::Tooling::Subtest(3perl) Guía de Referencia para Programadores de Perl Test2::Manual::Tooling::Subtest(3perl)

NOMBRE

Test2::Manual::Tooling::Subtest - Cómo implementar una herramienta que utilice subpruebas.

DESCRIPCIÓN

Las subpruebas son una buena forma de hacer que eventos relacionados sean visual y arquitectónicamente distintos.

¿QUÉ TIPO DE SUBPRUEBA NECESITO?

Hay 2 tipos de subpruebas. El primer tipo son subpruebas con coderefs suministrados por el usuario, como la función subtest() en sí. El segundo tipo son subpruebas que no tienen ningún coderef suministrado por el usuario.

Entonces, ¿qué tipo necesitas? La respuesta es simple: si vas a permitir que el usuario defina la subprueba con su propio bloque de código, tienes el primer tipo; de lo contrario, tienes el segundo.

En cualquier caso, seguirás necesitando usar la misma función de API: "Test2::API::run_subtest".

SUBPRUEBA CON CODEREF SUMINISTRADO POR EL USUARIO

Este ejemplo emulará la función "subtest".

use Test2::API qw/context run_subtest/;
sub my_subtest {
    my ($name, $code) = @_;
    # Como cualquier otra herramienta, necesitas adquirir un contexto; si no lo haces,
    # las cosas no informarán el archivo y número de línea correctos.
    my $ctx = context();
    my $bool = run_subtest($name, $code);
    $ctx->release;
    return $bool;
}

Esto parece increíblemente simple... y lo es. run_subtest() hace todo el trabajo duro por ti. Esto emitirá un evento Test2::Event::Subtest con los resultados de la subprueba. El evento de subprueba en sí informará al archivo y número de línea correctos debido al contexto que adquiriste (aunque no parezca que usaste el contexto).

run_subtest() puede tomar argumentos adicionales:

run_subtest($name, $code, \%params, @args);
@args
Esto te permite pasar argumentos al bloque de código que se ejecuta.
\%params
Este es un hashref de parámetros. Actualmente hay 3 parámetros posibles:
buffered => $bool
Esto convertirá la subprueba al nuevo estilo de subprueba con búfer. Este tipo de subprueba es recomendado, pero no es el predeterminado.
inherit_trace => $bool
Esto se utiliza para coderefs del lado de la herramienta.
no_fork => $bool
reacciona a la bifurcación/hilos dentro de la subprueba en sí. En general, es poco probable que necesites/quieras este parámetro.

SUBPRUEBA CON CODEREF DEL LADO DE LA HERRAMIENTA

Esto es particularmente útil si deseas convertir una herramienta que envuelve otras herramientas en una subprueba. Para esto, utilizaremos la herramienta que creamos en Test2::Manual::Tooling::Nesting.

use Test2::API qw/context run_subtest/;
sub check_class {
    my $class = shift;
    my $ctx = context();
    my $code = sub {
        my $obj = $class->new;
        is($obj->foo, 'foo', "got foo");
        is($obj->bar, 'bar', "got bar");
    };
    my $bool = run_subtest($class, $code, {buffered => 1, inherit_trace => 1});
    $ctx->release;
    return $bool;
}

La función run_subtest() hace todo el trabajo pesado por nosotros. Todo lo que necesitamos hacer es darle a la función un nombre, un coderef para ejecutar y el parámetro "inherit_trace => 1". El parámetro "buffered => 1" es opcional, pero recomendado.

El parámetro "inherit_trace" le dice a la herramienta de subprueba que los contextos adquiridos dentro de las herramientas anidadas deben usar el mismo rastreo que la subprueba en sí. Para bloques de código suministrados por el usuario, no usas inherit_trace porque quieres que los errores se informen al archivo+línea suministrado por el usuario.
