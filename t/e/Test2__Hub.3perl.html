Test2::Hub(3perl) Guía de referencia para desarrolladores de Perl Test2::Hub(3perl)

NAME

Test2::Hub - El puente por el cual todos los eventos fluyen.

SYNOPSIS

use Test2::Hub;
my $hub = Test2::Hub->new();
$hub->send(...);

DESCRIPTION

El puente es el lugar donde todas las eventos se procesan y se pasan a la formater. El puente también registra el estado de prueba y ofrece varios hooks en el pipeline de eventos.

TAREAS COMUNES

ENVÍO DE EVENTOS

$hub->send($event)

El método send() se usa para emitir un evento al puente. Este método manejará sincronización de hilos/fork, filtros, escuchadores, salida TAP, etc.

ALTERACIÓN O ELIMINACIÓN DE EVENTOS

Puedes usar tanto filter() como pre_filter(), según tus necesidades. Ambos tienen la misma sintaxis, así que solo filter() se muestra aquí.

$hub->filter(sub {
    my ($hub, $event) = @_;
    my $action = get_action($event);
    # No acción se debe tomar
    return $event if $action eq 'none';
    # Tú quieres que el filtro elimine el evento
    return undef if $action eq 'delete';
    if ($action eq 'do_it') {
        my $new_event = copy_event($event);
        ... Cambia tu copia del evento ...
        return $new_event;
    }
    die "No debería suceder";
});

Por defecto, los filtros no se heredan por hubs hijos. Esto significa que si starts un subtest, el subtest no heredará el filtro. Puedes cambiar esta comportación con el parámetro "inherit":

$hub->filter(sub { ... }, inherit => 1);

ESCUTANDO EVENTOS

$hub->listen(sub {
    my ($hub, $event, $number) = @_;
    ... haz lo que quieras con el evento ...
    # retorno es ignorado
});

Por defecto, los escuchadores no se heredan por hubs hijos como subtests. Esto significa que si starts un subtest, el subtest no heredará el escuchador. Puedes cambiar esta comportación con el parámetro "inherit":

$hub->listen(sub { ... }, inherit => 1);

BEHAVIOS DESPUES DE LAS PRUEBAS

$hub->follow_up(sub {
    my ($trace, $hub) = @_;
    ... haz lo que quieras ...
    # retorno es ignorado
});

Los subs de follow_up se llaman solo una vez, ya sea cuando se llama done_testing o en un bloque END.

CONFIGURAR EL FORMATTER

Por defecto, se crea e usa una instancia de Test2::Formatter::TAP.

my $old = $hub->format(My::Formatter->new);

Cambiar el formater remplazará a cualquier formater existente. Puedes establecer el formater en undef para evitar salida. El viejo formater será devuelto si estaba previamente establecido. Solo se permite una formater por vez.

MÉTODOS

$hub->send($event)
Este es el lugar donde todas las eventos entran al hub para su procesamiento.
$hub->process($event)
Esta se llama después de que el send maneje cualquier IPC. Puedes usar esto para evitar el proceso IPC, pero en general debes evitar usarlo.
$old = $hub->format($formatter)
Reemplaza la instancia actual de formater con una nueva. Los formateres deben ser objetos que implementen un método "$formatter->write($event)".
$sub = $hub->listen(sub { ... }, %optional_params)
Puedes usar esto para registrar todos los eventos después de que hayan sido enviados al formater. No se harán cambios aquí, excepto posiblemente para otros escuchadores. 
$hub->listen(sub {
    my ($hub, $event, $number) = @_;
    ... haz lo que quieras con el evento ...
    # retorno es ignorado
});

Por defecto, los escuchadores no se heredan por hubs hijos como subtests. Puedes agregar el parámetro "inherit => 1" para que un escuchador se herede.

$hub->unlisten($sub)
Puedes usar esto para remover un callback de escucha. Debes pasar el referido por el método listen().
$sub = $hub->filter(sub { ... }, %optional_params)
$sub = $hub->pre_filter(sub { ... }, %optional_params)
Estos pueden usarse para añadir filtros. Los filtros pueden modificar, reemplazar o eliminar eventos antes de que los otros los vean. 
$hub->filter(
    sub {
        my ($hub, $event) = @_;
        return $event;    # No cambios
        return;           // Elimina el evento
        // O puedes modificar un evento antes de retornarlo.
        $event->modify;
        return $event;
    }
);

Si no estás usando hilos, fork, o IPC, la única diferencia entre un filtro y un pre_filter es que los pre_filters se ejecutan primero. Cuando estás usando hilos, fork o IPC, los pre_filters ocurren antes de que los eventos se envíen a su destino proc/thread, mientras que los filtros ocurren solamente en el hub/thread destino.

No puedes agregar un filtro regular a un hub si fue creado en otro proceso o hilo. Puedes siempre agregar un pre_filter.

$hub->unfilter($sub)
$hub->pre_unfilter($sub)
Estos pueden usarse para remover filtros y pre_filters. El argumento $sub es el referido por el método filter() o pre_filter().
$hub->follow_op(sub { ... })
Usa esto para añadir comportamientos que se llaman justo antes de que el hub se finalize. El único argumento al código bloque será un objeto Test2::EventFacet::Trace. 
$hub->follow_up(sub {
    my ($trace, $hub) = @_;
    ... haz lo que quieras ...
    // retorno es ignorado
});

Los subs de follow_up se llaman solo una vez, ya sea cuando se llama done_testing o en un bloque END.

$sub = $hub->add_context_acquire(sub { ... });
Añade un callback que se llama cada vez que alguien intenta obtener un contexto. Se le pasa un argumento único, un referencia de los parámetros que usan para construir el contexto. Esto es tu oportunidad de cambiar los parámetros directamente alterando el hash. 
test2_add_callback_context_acquire(sub {
    my $params = shift;
    $params->{level}++;
});

Este es un API muy inquietante. No lo uses salvo que necesites. Es aquí para Test::Builder y compatibilidad inversa. Esto te directa a modificar el hash en lugar de devolver un nuevo, por razones de rendimiento.

Nota Usar este hook podría tener un impacto muy grande en la rendimiento.

El coderef que proporciones se devuelve y puede usarse para quitar el hook más tarde.

$hub->remove_context_acquire($sub);
Puedes usar esto para remover un hook de obtención de contexto.
$sub = $hub->add_context_init(sub { ... });
Permite añadir callbacks que se ejecutan cada vez que se crea un nuevo contexto para el hub. El único argumento al sub será el objeto Test2::API::Context que fue creado.

Nota Usar este hook podría tener un impacto muy grande en la rendimiento.

El coderef que proporcionas se devuelve y puede usarse para quitar el hook más tarde.

$hub->remove_context_init($sub);
Puedes usar esto para remover un hook de inicialización de contexto.
$sub = $hub->add_context_release(sub { ... });
Permite añadir callbacks que se ejecutan cada vez que el contexto de este hub es liberado. El único argumento al sub será el objeto Test2::API::Context que fue liberado. Estos se ejecutan en orden inverso.

Nota Usar este hook podría tener un impacto muy grande en la rendimiento.

El coderef que proporcionas se devuelve y puede usarse para quitar el hook más tarde.

$hub->remove_context_release($sub);
Puedes usar esto para remover un hook de liberación de contexto.
$hub->cull()
Cull cualquier evento IPC (y procesa ellos).
$pid = $hub->pid()
Devuelve el PID del proceso que creó el hub.
$hub->forked()
Devuelve verdadero si este hub fue creado por fork().
$hub->threaded()
Devuelve verdadero si este hub fue creado por un hilo.

NAME

Test2::Hub — hub for test events

SYNOPSIS

    use Test2::API;

    my $hub = Test2::API::hub();

    # ... do tests ...

    # Get information about the hub
    my $pid = $hub->pid;
    my $tid = $hub->tid;
    my $hid = $hub->hid;
    my $uuid = $hub->uuid; # if enabled
    my $ipc = $hub->ipc;

    # Control hub behavior
    $hub->set_no_ending(1);
    $hub->no_ending(1); # shortcut
    $hub->set_active(1);
    $hub->active(1); # shortcut

    # State
    $hub->reset_state;
    my $count = $hub->count;
    my $failed = $hub->failed;
    my $ended = $hub->ended;
    my $is_passing = $hub->is_passing;
    $hub->is_passing(0); # set to false
    my $plan = $hub->plan;
    $hub->plan(10); # set plan to 10 tests
    my $check = $hub->check_plan;

DESCRIPTION

This is the primary object used to manage test runs. A hub is created when Test2::API->hub is called. It is responsible for managing the flow of events, the test plan, and the state of the test run.

COMMON TASKS

This object has no common tasks that users typically need to perform directly. Most of the functionality is exposed via the Test2::API interface.

METHODS

$pid = $hub->pid()
Get the process id under which the hub was created.
$tid = $hub->tid()
Get the thread id under which the hub was created.
$hud = $hub->hid()
Get the identifier string of the hub.
$uuid = $hub->uuid()
If UUID tagging is enabled (see Test2::API) then the hub will have a UUID.
$ipc = $hub->ipc()
Get the IPC object used by the hub.
$hub->set_no_ending($bool)
$bool = $hub->no_ending
This can be used to disable auto-ending behavior for a hub. The auto-ending behavior is triggered by an end block and is used to cull IPC events, and output the final plan if the plan was 'NO PLAN'.
$bool = $hub->active
$hub->set_active($bool)
These are used to get/set the 'active' attribute. When true this attribute will force "hub->finalize()" to take action even if there is no plan, and no tests have been run. This flag is useful for plugins that add follow-up behaviors that need to run even if no events are seen.

STATE METHODS

$hub->reset_state()
Reset all state to the start. This sets the test count to 0, clears the plan, removes the failures, etc.
$num = $hub->count
Get the number of tests that have been run.
$num = $hub->failed
Get the number of failures (Not all failures come from a test fail, so this number can be larger than the count).
$bool = $hub->ended
True if the testing has ended. This MAY return the stack frame of the tool that ended the test, but that is not guaranteed.
$bool = $hub->is_passing
$hub->is_passing($bool)
Check if the overall test run is a failure. Can also be used to set the pass/fail status.
$hub->plan($plan)
$plan = $hub->plan
Get or set the plan. The plan must be an integer larger than 0, the string 'NO PLAN', or the string 'SKIP'.
$bool = $hub->check_plan
Check if the plan and counts match, but only if the tests have ended. If tests have not ended this will return undef, otherwise it will be a true/false.

THIRD PARTY META-DATA

This object consumes Test2::Util::ExternalMeta which provides a consistent way for you to attach meta-data to instances of this class. This is useful for tools, plugins, and other extensions.
