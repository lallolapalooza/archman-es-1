NOMBRE

Template::Manual::Directivas - Directivas de plantilla

Acceso y actualización de variables de plantilla

GET

La directiva "GET" recupera y muestra el valor de la variable nombrada.

[% GET foo %]

La palabra clave "GET" es opcional. Una variable se puede especificar en una etiqueta de directiva por sí sola.

[% foo %]

La variable puede tener un número ilimitado de elementos, cada uno separado por un punto. Cada elemento puede tener argumentos especificados entre paréntesis.

[% foo %]
[% bar.baz %]
[% biz.baz(10) %]
...etc...

Ver Template::Manual::Variables para una discusión completa sobre variables de plantilla.

También puede especificar expresiones usando los operadores lógicos ("and", "or", "not", "?", ":") y matemáticos ("+", "-", "*", "/", "%", "mod", "div").

[% template.title or default.title %]
[% score * 100 %]
[% order.nitems ? checkout(order.total) : 'no items' %]

El operador "div" devuelve el resultado entero de la división. Tanto "%" como "mod" devuelven el módulo (es decir, el resto) de la división.

[% 15 / 6 %]            # 2.5
[% 15 div 6 %]          # 2
[% 15 mod 6 %]          # 3

CALL

La directiva "CALL" es similar a "GET" al evaluar la variable nombrada, pero no imprime el resultado devuelto. Esto puede ser útil cuando una variable está vinculada a una subrutina o método de objeto que desea llamar pero no le interesa el valor devuelto.

[% CALL dbi.disconnect %]
[% CALL inc_page_counter(page_count) %]

SET

La directiva "SET" le permite asignar nuevos valores a variables existentes o crear nuevas variables temporales.

[% SET title = 'Hola Mundo' %]

La palabra clave "SET" también es opcional.

[% title = 'Hola Mundo' %]

A las variables se les pueden asignar los valores de otras variables, números sin comillas (2.718), texto literal ('comillas simples') o texto entre comillas ("comillas dobles"). En este último caso, cualquier referencia a variable dentro del texto se interpolará cuando se evalúe la cadena. Las variables deben ir precedidas por "$", usando llaves para delimitar explícitamente el nombre de la variable cuando sea necesario.

[% foo  = 'Foo'  %]               # valor literal 'Foo'
[% bar  =  foo   %]               # valor de la variable 'foo'
[% cost = '$100' %]               # valor literal '$100'
[% item = "$bar: ${cost}.00" %]   # valor "Foo: $100.00"

Se pueden asignar múltiples variables en la misma directiva y se evalúan en el orden especificado. Por lo tanto, lo anterior podría haber sido escrito:

[% foo  = 'Foo'
   bar  = foo
   cost = '$100'
   item = "$bar: ${cost}.00"
%]

También se pueden usar expresiones simples, según "GET".

[% ten    = 10
   twenty = 20
   thirty = twenty + ten
   forty  = 2 * twenty
   fifty  = 100 div 2
   six    = twenty mod 7
%]

Puede concatenar cadenas usando el operador guion bajo '_'. En Perl 5, el punto "." se usa para la concatenación de cadenas, pero en Perl 6, al igual que en Template Toolkit, el punto "." se usará como operador de llamada de método y el guion bajo "_" se usará para la concatenación de cadenas. Tenga en cuenta que el operador debe especificarse con espacios en blanco alrededor, lo que, como dice Larry, se considera una característica:

[% copyright = '(C) Copyright' _ year _ ' ' _ author %]

Por supuesto, puede lograr un efecto similar con la interpolación de cadenas entre comillas dobles.

[% copyright = "(C) Copyright $year $author" %]

DEFAULT

La directiva "DEFAULT" es similar a "SET", pero solo actualiza variables que actualmente no están definidas o no tienen un valor "verdadero" (en el sentido de Perl).

[% DEFAULT
    name = 'John Doe'
    id   = 'jdoe'
%]

Esto puede ser particularmente útil en componentes de plantilla comunes para asegurar que se proporcionen algunos valores predeterminados sensatos para variables que de otro modo no estarían definidas.

[% DEFAULT
   title = 'Hola Mundo'
   bgcol = '#ffffff'
%]
<html>
  <head>
    <title>[% title %]</title>
  </head>
  <body bgcolor="[% bgcol %]">
    ...etc...

Procesamiento de archivos y bloques de plantilla

INSERT

La directiva "INSERT" se utiliza para insertar el contenido de un archivo externo en la posición actual.

[% INSERT myfile %]

No se intenta analizar ni procesar el archivo. El contenido, incluyendo cualquier directiva de plantilla incrustada, se inserta intacto.

El nombre del archivo especificado debe ser relativo a uno de los directorios de "INCLUDE_PATH". Los nombres de archivo absolutos (es decir, que comienzan con "/") y relativos (es decir, que comienzan con ".") pueden usarse si las opciones "ABSOLUTE" y "RELATIVE" están configuradas, respectivamente. Ambas opciones están deshabilitadas por defecto.

my $template = Template->new({
    INCLUDE_PATH => '/here:/there',
});
$template->process('myfile');

myfile:

[% INSERT foo %]            # busca /here/foo luego /there/foo
[% INSERT /etc/passwd %]    # error de archivo: ABSOLUTE no configurado
[% INSERT ../secret %]      # error de archivo: RELATIVE no configurado

Para mayor comodidad, el nombre del archivo no necesita estar entre comillas siempre que contenga solo caracteres alfanuméricos, guiones bajos, puntos o barras diagonales. Los nombres que contengan cualquier otro carácter deben ir entre comillas.

[% INSERT misc/legalese.txt            %]
[% INSERT 'dos98/Program Files/stupid' %]

Para evaluar una variable y especificar un nombre de archivo, debe precederla explícitamente con un "$" o usar la interpolación de cadenas entre comillas dobles.

[% language = 'en'
   legalese = 'misc/legalese.txt'
%]
[% INSERT $legalese %]              # misc/legalese.txt
[% INSERT "$language/$legalese" %]  # en/misc/legalese.txt

Se pueden especificar varios archivos usando "+" como delimitador. Todos los archivos deben ser nombres sin comillas o cadenas entre comillas. Cualquier variable debe interpolarse en cadenas entre comillas dobles.

[% INSERT legalese.txt + warning.txt %]
[% INSERT  "$legalese" + warning.txt %]  # requiere comillas

INCLUDE

La directiva "INCLUDE" se utiliza para procesar e incluir la salida de otro archivo o bloque de plantilla.

[% INCLUDE header %]

Si se define un "BLOCK" con el nombre especificado en el mismo archivo, o en un archivo desde el cual se llamó a la plantilla actual (es decir, una plantilla padre), entonces se utilizará en preferencia a cualquier archivo del mismo nombre.

[% INCLUDE table %]     # usa BLOCK definido a continuación
[% BLOCK table %]
   <table>
     ...
   </table>
[% END %]

Si una definición de "BLOCK" no está actualmente visible, entonces el nombre de la plantilla debe ser un archivo relativo a uno de los directorios de "INCLUDE_PATH", o un nombre de archivo absoluto o relativo si las opciones "ABSOLUTE"/"RELATIVE" están habilitadas apropiadamente. La

"INCLUDE" La directiva "INCLUDE" automáticamente pone entre comillas el nombre del archivo especificado, como se describe en "INSERT". Cuando una variable contiene el nombre de la plantilla para la directiva "INCLUDE", debe ir prefijada explícitamente por "$" o entre comillas dobles.

[% mi_cabecera = 'mi/varios/cabecera' %]
[% INCLUDE   mi_cabecera  %]           # 'mi_cabecera'
[% INCLUDE  $mi_cabecera  %]           # 'mi/varios/cabecera'
[% INCLUDE "$mi_cabecera" %]           # 'mi/varios/cabecera'

Cualquier directiva de plantilla incrustada dentro del archivo se procesará en consecuencia. Todas las variables definidas actualmente serán visibles y accesibles desde la plantilla incluida.

[% titulo = 'Hola Mundo' %]
[% INCLUDE cabecera %]
<body>
...

cabecera:

<html>
<title>[% titulo %]</title>

salida:

<html>
<title>Hola Mundo</title>
<body>
...

Las definiciones de variables locales pueden especificarse después del nombre de la plantilla, enmascarando temporalmente cualquier variable existente. Los espacios en blanco insignificantes se ignoran dentro de las directivas, por lo que puede agregar definiciones de variables en la misma línea, en la siguiente línea o divididas en varias líneas con comentarios intercalados, si lo prefiere.

[% INCLUDE tabla %]
[% INCLUDE tabla titulo="Proyectos Activos" %]
[% INCLUDE tabla
     titulo   = "Proyectos Activos"
     bgcolor = "#80ff00"    # verde lima
     border  = 2
%]

La directiva "INCLUDE" localiza (es decir, copia) todas las variables antes de procesar la plantilla. Cualquier cambio realizado dentro de la plantilla incluida no afectará a las variables de la plantilla que la incluye.

[% foo = 10 %]
foo es originalmente [% foo %]
[% INCLUDE bar %]
foo sigue siendo [% foo %]
[% BLOCK bar %]
   foo era [% foo %]
   [% foo = 20 %]
   foo es ahora [% foo %]
[% END %]

salida:

foo es originalmente 10
   foo era 10
   foo es ahora 20
foo sigue siendo 10

Nota Técnica: la localización del stash (es decir, el proceso por el cual se copian las variables antes de un "INCLUDE" para evitar que se sobrescriban) es solo superficial. Se copia el espacio de nombres de variables de nivel superior (hash), pero no se intenta realizar una copia profunda de otras estructuras (hashes, arrays, objetos, etc.). Por lo tanto, una variable "foo" que hace referencia a un hash se copiará para crear una nueva variable "foo" pero que apunta al mismo array hash. Por lo tanto, si actualiza variables compuestas (por ejemplo, "foo.bar"), cambiará la copia original, independientemente de cualquier localización de stash. Si no le preocupa conservar los valores de las variables, o si confía en las plantillas que está incluyendo, puede preferir usar la directiva "PROCESS", que es más rápida al no realizar ninguna localización.

Puede especificar variables con puntos como variables "locales" para una directiva "INCLUDE". Sin embargo, tenga en cuenta que, debido a los problemas de localización explicados anteriormente (si se saltó la nota técnica anterior, es posible que desee volver a leerla o saltarse también esta sección), las variables podrían no ser realmente "locales". Si el primer elemento del nombre de la variable ya hace referencia a un array hash, la actualización de la variable afectará a la variable original.

[% foo = {
       bar = 'Baz'
   }
%]
[% INCLUDE archivo_cualquiera foo.bar='Boz' %]
[% foo.bar %]           # Boz

Este comportamiento puede ser un poco impredecible (y puede que mejore en una versión futura). Si sabe lo que está haciendo con él y está seguro de que las variables en cuestión están definidas (o no) como espera, puede confiar en esta característica para implementar algunas potentes técnicas de intercambio de datos "globales". De lo contrario, podría preferir evitarlo y pasar siempre variables simples (sin puntos) como parámetros a "INCLUDE" y otras directivas similares.

Si desea procesar varias plantillas a la vez, puede especificar cada uno de sus nombres (solo nombres entre comillas o sin comillas, sin $variables sin comillas) unidos por "+". La directiva "INCLUDE" los procesará en orden.

[% INCLUDE html/cabecera + "sitio/$cabecera" + sitio/menu
     titulo = "Mi Sitio Web Genial"
%]

El stash de variables se localiza una vez y luego se procesan las plantillas especificadas en orden, todas dentro de ese mismo contexto de variables. Esto lo hace ligeramente más rápido que especificar varias directivas "INCLUDE" separadas (porque solo clona el stash de variables una vez en lugar de n veces), pero no tan "seguro" porque cualquier cambio de variable en el primer archivo será visible en el segundo, tercero, etc. Esto podría ser lo que desea, por supuesto, pero también podría no serlo.

PROCESS

"PROCESS" La directiva es similar a "INCLUDE" pero no realiza ninguna localización de variables antes de procesar la plantilla. Cualquier cambio realizado en las variables dentro de la plantilla incluida será visible en la plantilla que la incluye.

[% foo = 10 %]
foo es [% foo %]
[% PROCESS bar %]
foo es [% foo %]
[% BLOCK bar %]
   [% foo = 20 %]
   cambié foo a [% foo %]
[% END %]

salida:

foo es 10
   cambié foo a 20
foo es 20

Los parámetros pueden especificarse en la directiva "PROCESS", pero estos también se convertirán en cambios visibles a los valores de variables actuales.

[% foo = 10 %]
foo es [% foo %]
[% PROCESS bar
   foo = 20
%]
foo es [% foo %]
[% BLOCK bar %]
   este es bar, foo es [% foo %]
[% END %]

salida:

foo es 10
   este es bar, foo es 20
foo es 20

"PROCESS" La directiva es ligeramente más rápida que "INCLUDE" porque evita la necesidad de localizar (es decir, copiar) el stash de variables antes de procesar la plantilla. Al igual que con "INSERT" y "INCLUDE", el primer parámetro no necesita ser citado siempre que contenga solo caracteres alfanuméricos, guiones bajos, puntos o barras diagonales. Se puede usar un prefijo "$" para indicar explícitamente una variable que debe interpolarse para proporcionar el nombre de la plantilla:

[% mi_cabecera = 'mi/varios/cabecera' %]
[% PROCESS  mi_cabecera %]              # 'mi_cabecera'
[% PROCESS $mi_cabecera %]              # 'mi/varios/cabecera'

Al igual que con "INCLUDE", se pueden especificar varias plantillas, delimitadas por "+", y se procesan en orden.

[% PROCESS html/cabecera + mi/cabecera %]

WRAPPER

No es inusual encontrarse agregando cabeceras y pies de página comunes a páginas o subsecciones dentro de una página. Algo como esto:

[% INCLUDE seccion/cabecera
   titulo = 'Mecánica Cuántica'
%]
   La mecánica cuántica es un tema muy interesante que
   debería resultar fácil de comprender completamente para el profano.
[% INCLUDE seccion/pie %]
[% INCLUDE seccion/cabecera
   titulo = 'Fusión Nuclear de Escritorio por menos de 50 €'
%]
   Este documento describe un dispositivo simple que genera una
   potencia eléctrica significativa y sostenible a partir de agua del grifo común mediante el proceso
   de fusión nuclear.
[% INCLUDE seccion/pie %]

Los componentes individuales de la plantilla que se incluyen podrían verse así:

seccion/cabecera:

<p>
<h2>[% titulo %]</h2>

seccion/pie:

</p>

"WRAPPER" La directiva proporciona una forma de simplificar esto un poco. Encierra un bloque hasta una directiva "END" coincidente, que primero se procesa para generar alguna salida. Esta salida se pasa luego al archivo de plantilla nombrado o a "BLOCK" como la variable "contenido".

[% WRAPPER seccion
   titulo = 'Mecánica Cuántica'
%]
   La mecánica cuántica es un tema muy interesante que
   debería resultar fácil de comprender completamente para el profano.
[% END %]
[% WRAPPER seccion
   titulo = 'Fusión Nuclear de Escritorio por menos de 50 €'
%]
   Este documento describe un dispositivo simple que genera una
   potencia eléctrica significativa y sostenible a partir de agua del grifo común mediante el proceso
   de fusión nuclear.
[% END %]

La plantilla única 'seccion' se puede definir como:

<h2>[% titulo %]</h2>
<p>
  [% contenido %]
</p>

Como otras directivas de bloque, se puede usar en notación de efectos secundarios:

[% INSERT legalese.txt WRAPPER big_bold_table %]

También es posible especificar múltiples plantillas a una directiva "WRAPPER". El orden de especificación indica las plantillas de envoltura desde la más externa hasta la más interna. Por ejemplo, dadas las siguientes definiciones de bloques de plantilla:

[% BLOCK negrita   %]<b>[% contenido %]</b>[% END %]
[% BLOCK cursiva %]<i>[% contenido %]</i>[% END %]

la directiva

[% WRAPPER negrita+cursiva %]Hola Mundo[% END %]

generaría la siguiente salida:

<b><i>Hola Mundo</i></b>

BLOCK

"BLOCK"..."END" La construcción se puede usar para definir bloques de componentes de plantilla que pueden procesarse con las directivas "INCLUDE", "PROCESS" y "WRAPPER".

[% BLOCK fila_tabla %]
<tr>
  <td>[% nombre %]<td>
  <td>[% email %]</td>
</tr>
[% END %]
<table>
  [% PROCESS fila_tabla  nombre='Fred'  email='fred@nowhere.com' %]
  [% PROCESS fila_tabla  nombre='Alan'  email='alan@nowhere.com' %]
</table>

Una definición de "BLOCK" puede usarse antes de que se defina, siempre que la definición resida en el mismo archivo. La definición del bloque en sí no genera ninguna salida.

[% PROCESS tmpblk %]
[% BLOCK tmpblk %] Esto está bien [% END %]

Puede usar un "BLOCK" anónimo para capturar la salida de un fragmento de plantilla.

[% julio = BLOCK %]
   Y el espíritu de César, en busca de venganza,
   con Ate a su lado recién salido del infierno,
   en estos confines con voz de monarca
   gritará '¡Estruendo!', y soltará a los perros de la guerra;
   Que este vil acto huela por encima de la tierra
   con hombres carroña, gimiendo por sepultura.
[% END %]
