NAME

Test::PerlTidy - verificar que todos tus archivos estén bien formateados.

VERSION

versión 20230226

SYNOPSIS

# En un archivo como 't/perltidy.t':
use Test::PerlTidy qw( run_tests );
run_tests();

DESCRIPCIÓN

Esta mala crítica fue hecha por Ken Arnold en un artículo:

"Perl es un vasto lago de desorden lexical y sintáctico y nadie sabe cómo formatar su propio código bien, pero es el único lenguaje majoritariamente que no tiene al menos un estilo que sea bueno."
          http://www.artima.com/weblogs/viewpost.jsp?thread=74230

Hmm... Es casi correcto en un sentido. Aunque el artículo que escribió estaba relacionado con Python, que es bastante estricto en la formateo de su código.

No te preocupes, ahora puedes tener tu propio gestapo de formateo en el estilo de Test::PerlTidy! Simplemente añade un archivo de prueba como se sugiere arriba y cualquier archivo que termine en .pl, .pm, .t o .PL causará un fallo de prueba si no está exactamente como se espera que esté al usar perltidy.

RAZONES PARA HACER ESTO

Si el estilo es obligatorio en los tests, se cumplirá.

Si perltidy decide qué estilo es bueno, no habrá que discutir.

Si el estilo nunca cambia, los diffs de cvs se detienen en cambios que no son reales.

Puede mejorar la lectura.

HINTS

Si quieres cambiar el estilo por defecto, muda el archivo '.perltidyrc';

Para hacer rápidamente un archivo funcione, prueba 'perltidy -b the_messy_file.pl'.

CÓMO FUNCIONA

Ejecuta perltidy en archivos y reporta errores si algún archivo se diferencia después de haber sido reformatado. No modifica permanentemente los archivos que se están probando.

Por defecto, perltidy se ejecutará en archivos en la actual carpeta y sus subdirectorios con extensiones que coincidan con: ".pm .pl .PL .t"

MÉTODOS

run_tests ( [ path | %args ] )

Es el punto de entrada principal para ejecutar las pruebas.

Se pueden especificar opciones al ejecutar las pruebas, por ejemplo:

run_tests(
          path       => $start_dir,
          perltidyrc => $path_to_config_file,
          exclude    => [ qr{\.t$}, 'inc/'],
);
debug
Establece "debug" a un valor verdadero para habilitar salida diagnóstica adicional, especialmente información sobre cualquier procesamiento hecho como resultado de especificar el "exclude" opción. Valor por defecto es falso.
exclude
run_tests() buscará archivos a probar en la carpeta actual y sus subdirectorios. Por defecto, excluye archivos en la carpeta ""./blib/"". Si deseas especificar reglas adicionales por medio de las que archivos serán excluidos, establece "exclude" a una lista de criterios de exclusión.

Si un elemento en la lista de "exclude" es una cadena, por ejemplo ""./blib/"", se asumirá que es un prefijo de ruta. Los archivos se excluirán si esa cadena coincide con el camino del archivo al inicio.

Si un elemento en la lista de "exclude" es un objeto de regex, por ejemplo ""qr{\.t$}"", los archivos se excluirán si ese regex coincide con su camino.

Nota: Los caminos de los archivos a probar se canonifican usando File::Spec"->canonpath" antes de cualquier coincidencia, lo cual puede afectar cómo los criterios de exclusión se aplican. Si tus criterios de exclusión no parece funcionar, habilita el "debug" opción para ver los caminos de los archivos que se mantienen/excluyen.

path
Establece "path" a la ruta de la carpeta superior que contiene los archivos a probar. Por defecto es la carpeta actual (es decir, ""."").
perltidyrc
Por defecto, perltidy intentará leer sus opciones desde el archivo .perltidyrc en tu sistema. Si quieres controlar las opciones de perltidy durante las pruebas, establece "perltidyrc" a la ruta de un archivo personalizado.
mute
Por defecto, run_tests() mostrará diagnósticos sobre errores reportados por perltidy, así como diferencias entre los archivos antes y después de su reformatación. Establece "mute" a un valor verdadero para desactivar esa salida diagnóstica.
skip_all
Establece "skip_all" a un valor verdadero para saltar todas las pruebas. Valor por defecto es falso.
perltidy_options
Envía estos a Perl::Tidy::perltidy(). (Añadido en la versión 20200411).

list_files ( [ start_path | %args ] )

Genera la lista de archivos a probar. Generalmente no se llama directamente.

load_file ( path_to_file )

Carga el archivo a probar desde el disco y devuelve sus contenidos. Generalmente no se llama directamente.

is_file_tidy ( path_to_file [ , path_to_perltidyrc ] [, $named_args] )

Prueba si un archivo está bien formateado o no. Generalmente no se llama directamente.

$named_args puede ser un hash ref que puede tener una clave llamada 'perltidy_options' que refiere a un hash ref de opciones que se pasarán a Perl::Tidy::perltidy(). ($named_args fue añadido en la versión 20200411).
