NOMBRE

Template::Manual::Filters - Filtros estándar

format(format)

El filtro "format" toma un string de formato como parámetro (como printf()) y forma cada línea de texto según ese string.

[% FILTER format('<!-- %-40s -->') %]
Este es un bloque de texto filtrado
a través del cual se aplicó el formato anterior.
[% END %]

Salida:

<!-- Este es un bloque de texto filtrado        -->
<!-- a través del cual se aplicó el formato anterior.               -->

upper

Convierte el input a mayúsculas.

[% "hello world" FILTER upper %]

Salida:

HELLO WORLD

lower

Convierte el input a minúsculas.

[% "Hello World" FILTER lower %]

Salida:

hello world

ucfirst

Convierte la primera letra del input a mayúscula.

[% "hello" FILTER ucfirst %]

Salida:

Hello

lcfirst

Convierte la primera letra del input a minúscula.

[% "HELLO" FILTER lcfirst %]

Salida:

hELLO

trim

Elimina los espacios en blanco al principio y al final del texto de entrada. Es especialmente útil junto con "INCLUDE", "PROCESS", etc., con el mismo efecto que la opción "TRIM".

[% INCLUDE myfile | trim %]

collapse

Convierte secuencias de espacios en blanco en el texto de entrada a un solo espacio. Los espacios en blanco al principio o al final (que se reducirían a un solo espacio) se eliminan, de forma similar a "TRIM".

[% FILTER collapse %]
   The   cat
   sat    on
   the   mat
[% END %]

Salida:

The cat sat on the mat

html

Convierte los caracteres "<", ">", "&" y """ en "&lt;", "&gt;", "&amp;" y "&quot;", protegiéndolos de ser interpretados como etiquetas HTML o entidades.

[% FILTER html %]
Binary "<=>" returns -1, 0, or 1 depending on...
[% END %]

Salida:

Binary "&lt;=&gt;" returns -1, 0, or 1 depending on...

html_entity

El filtro "html" es rápido y sencillo, pero no codifica el rango completo de entidades HTML que pueda contener tu texto. El filtro "html_entity" utiliza "Apache::Util" (escrito en C y por lo tanto más rápido) o el módulo "HTML::Entities" (escrito en Perl pero igualmente completo) para realizar la codificación.

Si uno o ambos de estos módulos están instalados en tu sistema, el texto será codificado (mediante escape_html() o encode_entities()) para convertir todos los caracteres extendidos en sus correspondientes entidades HTML (por ejemplo, convertir '"?"' en '"&eacute;"'). Si ninguno de los módulos está disponible, se lanzará una excepción "html_entity" con un mensaje adecuado.

Si deseas forzar que TT use uno de los módulos anteriores en preferencia al otro, llama a cualquiera de los métodos de la clase Template::Filters: use_html_entities() o use_apache_util().

use Template::Filters;
Template::Filters->use_html_entities;

Para más información sobre la codificación de entidades HTML, consulta http://www.w3.org/TR/REC-html40/sgml/entities.html.

xml

Es lo mismo que el filtro "html", pero añade "&apos;", que es la quinta entidad XML predefinida.

html_para

Este filtro formatea un bloque de texto en párrafos HTML. Una secuencia de dos o más saltos de línea se utiliza como delimitador de párrafos, que luego se envuelven en etiquetas HTML "<p>"..."</p>".

[% FILTER html_para %]
El gato se sentó en la alfombra.
María tenía un corderito.
[% END %]

Salida:

<p>
El gato se sentó en la alfombra.
</p>
<p>
María tenía un corderito.
</p>

html_break / html_para_break

Similar al filtro "html_para" descrito anteriormente, pero utiliza la secuencia de etiquetas HTML "<br><br>" para unir párrafos.

[% FILTER html_break %]
El gato se sentó en la alfombra.
María tenía un corderito.
[% END %]

Salida:

El gato se sentó en la alfombra.
<br>
<br>
María tenía un corderito.

html_line_break

Este filtro reemplaza cualquier nueva línea con etiquetas HTML "<br>", preservando así las líneas de texto originales en el resultado HTML.

[% FILTER html_line_break %]
El gato se sentó en la alfombra.
María tenía un corderito.
[% END %]

Salida:

El gato se sentó en la alfombra.<br>
María tenía un corderito.<br>

uri

Este filtro codifica el texto de entrada usando la codificación de URI, convirtiendo cualquier carácter fuera del conjunto de caracteres permitidos de URI (definidos por RFC 3986) en una secuencia de escape hexadecimal %nn.

[% 'my file.html' | uri %]

Salida:

my%20file.html

El filtro uri funciona correctamente codificando todos los caracteres reservados, incluyendo "&", "&@", "&/", "&;", "&:", "&=", "&+", "&?" y "&$". Este filtro se utiliza típicamente para codificar parámetros en una URL que podrían ser interpretados como parte de la URL. Aquí tienes un ejemplo:

[% path  = 'http://tt2.org/example'
   back  = '/other?foo=bar&baz=bam'
   title = 'Earth: "Mostly Harmless"'
%]
<a href="[% path %]?back=[% back | uri %]&title=[% title | uri %]">

El resultado generado es bastante largo, así que lo mostraremos dividido en dos líneas:

<a href="http://tt2.org/example?back=%2Fother%3Ffoo%3Dbar%26
baz%3Dbam&title=Earth%3A%20%22Mostly%20Harmless%22">

Sin el filtro uri, el resultado sería este (también dividido en dos líneas).

<a href="http://tt2.org/example?back=/other?foo=bar
&baz=bam&title=Earth: "Mostly Harmless"">

En este ejemplo bastante elaborado hemos logrado generar tanto una URL mal formada (la repetición de "?" no está permitida) como un elemento HTML mal formado (el atributo href termina con la primera """ después de "Earth: ", dejando "MostlyHarmless"" colgado al final de la etiqueta en la forma que no debería colgar cosas así). Por eso, no debes hacer eso. Siempre usa el filtro uri para codificar tus parámetros de URL.

ter para codificar toda una URL.

<a href="[% page_url | uri %]">   # INCORRECTO!

Esto codificará incorrectamente caracteres reservados como ":" y "/", lo cual casi con seguridad no es lo que desea en este caso. En su lugar, debe usar el filtro url (note la ortografía) para este propósito.

<a href="[% page_url | url %]">   # CORRECTO

Tenga en cuenta que este comportamiento se cambió en la versión 2.16 del Template Toolkit. Antes de eso, el filtro uri no codificaba los caracteres reservados, lo que lo hacía técnicamente incorrecto según la especificación RFC 2396 (desde entonces reemplazada por RFC2732 y RFC3986). Así que lo corregimos en la versión 2.16 y proporcionamos el filtro url para implementar el comportamiento anterior de no codificar caracteres reservados.

A partir de la versión 2.28 del Template Toolkit, los filtros "uri" y url utilizan el conjunto de caracteres inseguros definido por RFC3986. Esto significa que ciertos caracteres ("(", ")", "*", "!", "'" y '"') ahora se consideran inseguros y se escaparán como secuencias de caracteres hexadecimales.

La capacidad de usar el conjunto de caracteres RFC3986 se agregó en la versión 2.26 pero no estaba habilitada por defecto; la comilla doble se consideró incorrectamente segura en la versión 2.26 pero se escapó correctamente en la 2.27.

Si desea habilitar el comportamiento anterior, llame al método use_rfc2732() en Template::Filters

use Template::Filters
Template::Filters->use_rfc2732;

url

El filtro url es una versión menos agresiva del filtro uri. Codifica cualquier carácter fuera del conjunto de caracteres URI permitido (según lo definido por RFC 2396) en escapes hexadecimales %nn. Sin embargo, a diferencia del filtro uri, el filtro url **no** codifica los caracteres reservados "&", "@", "/", ";", ":", "=", "+", "?" y "$".

indent(pad)

Indenta el bloque de texto con una cadena de relleno fija o un ancho. El argumento '"pad"' puede especificarse como una cadena o como un valor numérico para indicar un ancho de relleno (espacios). Por defecto, son 4 espacios si no se especifica.

[% FILTER indent('ME> ') %]
blah blah blah
cabbages, rhubard, onions
[% END %]

Salida:

ME> blah blah blah
ME> cabbages, rhubard, onions

truncate(length,dots)

Trunca el bloque de texto a la longitud especificada, o a una longitud predeterminada de 32. El texto truncado se terminará con '"..."' (es decir, los '"..."' caen dentro de la longitud requerida, en lugar de agregarse a ella).

[% FILTER truncate(21) %]
I have much to say on this matter that has previously
been said on more than one occasion.
[% END %]

Salida:

I have much to say...

Si desea utilizar algo diferente de '"..."', puede pasarlo como un segundo argumento.

[% FILTER truncate(26, '&hellip;') %]
I have much to say on this matter that has previously
been said on more than one occasion.
[% END %]

Salida:

I have much to say&hellip;

repeat(iterations)

Repite el bloque de texto tantas veces como se especifique (predeterminado: 1).

[% FILTER repeat(3) %]
We want more beer and we want more beer,
[% END %]
We are the more beer wanters!

Salida:

We want more beer and we want more beer,
We want more beer and we want more beer,
We want more beer and we want more beer,
We are the more beer wanters!

remove(string)

Busca en el texto de entrada cualquier ocurrencia de la cadena especificada y las elimina. Se puede especificar una expresión regular de Perl como cadena de búsqueda.

[% "The  cat  sat  on  the  mat" FILTER remove('\s+') %]

Salida:

Thecatsatonthemat

replace(search, replace)

Similar al filtro remove descrito anteriormente, pero toma un segundo parámetro que se utiliza como cadena de reemplazo para las instancias de la cadena de búsqueda.

[% "The  cat  sat  on  the  mat" | replace('\s+', '_') %]

Salida:

The_cat_sat_on_the_mat

redirect(file, options)

El filtro "redirect" redirige la salida del bloque a un archivo separado, especificado en relación con el elemento de configuración "OUTPUT_PATH".

[% FOREACH user IN myorg.userlist %]
   [% FILTER redirect("users/${user.id}.html") %]
      [% INCLUDE userinfo %]
   [% END %]
[% END %]

o de forma más concisa, utilizando la notación de efectos secundarios:

[%  FOREACH user IN myorg.userlist;
      INCLUDE userinfo
        FILTER redirect("users/${user.id}.html");
    END
%]

Se lanzará una excepción de "file" si la opción "OUTPUT_PATH" no está definida.

Un argumento opcional "binmode" puede seguir al nombre del archivo para establecer explícitamente el archivo de salida en modo binario.

[% PROCESS my/png/generator
     FILTER redirect("images/logo.png", binmode=1) %]

Para compatibilidad con versiones anteriores, se puede usar un único valor verdadero/falso para establecer el modo binario.

[% PROCESS my/png/generator
     FILTER redirect("images/logo.png", 1) %]

Por motivos de compatibilidad futura y claridad, si no es por nada más, le recomendamos encarecidamente que utilice explícitamente la opción con nombre "binmode" como se muestra en el primer ejemplo.

eval / evaltt

El filtro "eval" evalúa el bloque como texto de plantilla, procesando cualquier directiva incrustada en él. Esto permite que las variables de plantilla contengan fragmentos de plantilla, o que algún método proporcione fragmentos de plantilla desde una fuente externa, como una base de datos, que luego se pueden procesar en la plantilla según sea necesario.

my $vars  = {
    fragment => "The cat sat on the [% place %]",
};
$template->process($file, $vars);

El siguiente ejemplo:

[% fragment | eval %]

es, por lo tanto, equivalente a

The cat sat on the [% place %]

El filtro "evaltt" se proporciona como un alias de "eval".

perl / evalperl

El filtro "perl" evalúa el bloque como código Perl. La opción "EVAL_PERL" debe establecerse en un valor verdadero o se lanzará una excepción de "perl".

[% my_perl_code | perl %]

En la mayoría de los casos, el bloque "[% PERL %]" ... "[% END %]" será suficiente para evaluar código Perl, dado que las directivas de plantilla se procesan antes de ser evaluadas como Perl. Por lo tanto, el ejemplo anterior podría haber sido escrito en la forma más verbosa:

[% PERL %]
[% my_perl_code %]
[% END %]

así como

[% FILTER perl %]
[% my_perl_code %]
[% END %]

El filtro "evalperl" se proporciona como un alias de "perl" para compatibilidad con versiones anteriores.

stdout(options)

El filtro stdout imprime la salida generada por el bloque involucrado en "STDOUT". La opción "binmode" se puede pasar como un parámetro con nombre o como un solo argumento para establecer "STDOUT" en modo binario (consulte la función binmode de perl).

[% PROCESS something/cool
       FILTER stdout(binmode=1) # recomendado %]
[% PROCESS something/cool
       FILTER stdout(1)         # alternativo %]

El filtro "stdout" se puede usar para forzar "binmode" en "STDOUT", o también dentro de bloques "redirect", "null" o "stderr" para asegurarse de que una salida particular vaya a "STDOUT". Consulte el filtro "null" a continuación para ver un ejemplo.

stderr

El filtro stderr imprime la salida generada por el bloque envolvente en "STDERR".

null

El filtro "null" no imprime nada. Esto es útil para plugins cuyos métodos devuelven valores que no desea que aparezcan en la salida. En lugar de asignar cada llamada al método del plugin a una variable ficticia para silenciarla, puede envolver el bloque en un filtro nulo:

[% FILTER null;
    USE im = GD.Image(100,100);
    black = im.colorAllocate(0,   0, 0);
    red   = im.colorAllocate(255,0,  0);
    blue  = im.colorAllocate(0,  0,  255);
    im.arc(50,50,95,75,0,360,blue);
    im.fill(50,50,red);
    im.png | stdout(1);
   END;
-%]

Observe el uso del filtro "stdout" para asegurar que una expresión particular genere salida a "STDOUT" (en este caso en modo binario).
