NOMBRE

Test2::API::InterceptResult::Event - Representación de un evento para usar en la prueba de otras herramientas de prueba.

DESCRIPCIÓN

"intercept { ... }" de Test2::API devuelve una instancia de Test2::API::InterceptResult, que es un arrayref bendecido con objetos Test2::API::InterceptResult::Event.

Este POD documenta los métodos de estos eventos, que se proporcionan principalmente para que los uses al probar tus herramientas de prueba.

SINOPSIS

use Test2::V0;
use Test2::API qw/intercept/;
my $events = intercept {
    ok(1, "Una aserción que pasa");
    plan(1);
};
# Esto convertirá todos los eventos en instancias de
# Test2::API::InterceptResult::Event. Hasta que hagamos esto, son las
# instancias originales de Test::Event::*
$events->upgrade(in_place => 1);
# Ahora podemos obtener eventos individuales en este formato
my $assert = $events->[0];
my $plan   = $events->[1];
# O podemos operar sobre todos los eventos a la vez:
my $flattened = $events->flatten;
is(
    $flattened,
    [
      {
        causes_failure => 0,
        name => 'Una aserción que pasa',
        pass => 1,
        trace_file => 'xxx.t',
        trace_line => 5,
      },
      {
        causes_failure => 0,
        plan => 1,
        trace_file => 'xxx.t',
        trace_line => 6,
      },
    ],
    "Ambos eventos aplanados y se devolvió un arrayref de los resultados
);

!!! NOTAS IMPORTANTES SOBRE EL DISEÑO !!!

Por favor, preste atención a lo que devuelven, muchos devuelven un escalar cuando es aplicable o una lista vacía cuando no lo es (en contra de undef). Muchos también devuelven siempre una lista de 0 o más elementos. Algunos siempre devuelven un escalar. Tenga en cuenta que ninguno de los métodos se preocupa por el contexto, su comportamiento es consistente sin importar si está en contexto escalar, de lista o vacío.

Esto se hizo porque esta clase fue diseñada específicamente para ser utilizada en una lista y generar más listas en operaciones masivas. A veces, en un mapa, quieres que no aparezca nada para el evento, y no quieres un undef en su lugar. En general, las instancias de eventos únicos no se usarán solas, aunque eso está permitido.

Como regla general, cualquier método prefijado con "the_" implica que el evento debe tener exactamente 1 del elemento especificado, y se lanzará una excepción si hay 0 o más de 1 elemento.

ATRIBUTOS

$hashref = $event->facet_data
Esto devolverá el hashref de datos de facetas, que es todo lo que Test2 considera importante para cualquier evento dado.
$class = $event->result_class
Esto es normalmente Test2::API::InterceptResult. Esto se establece en la construcción para que los resultados de subpruebas puedan convertirse en instancias de él bajo demanda.

DUPLICACIÓN

$copy = $event->clone
Crea una copia profunda del evento. Modificar cualquiera de los eventos no afectará al otro.

DATOS CONDENSADOS MULTI-FACETA

$bool = $event->causes_failure
$bool = $event->causes_fail
Estos son alias de la misma funcionalidad.

Esto siempre devolverá un valor verdadero o un valor falso. Nunca devuelve una lista.

Este método puede ser relativamente lento (aún súper rápido) porque determina el éxito o el fracaso creando una instancia de Test2::Hub y pidiéndole que procese el evento, y luego le pide al hub su estado de éxito/fracaso. Esto es más lento que incorporar lógica para realizar la comprobación, pero es más fiable ya que siempre te dirá lo que piensa el hub, por lo que la lógica nunca estará desactualizada con respecto a la lógica de Test2 que realmente le importa.

CADENA_O_LISTA_VACÍA = $event->brief
No todos los eventos tienen un resumen, algunos eventos no son renderizados por el formateador, otros no tienen datos de "resumen" dignos de ver. Cuando este es el caso, se devuelve una lista vacía. Esto se hace intencionalmente para que pueda usarse en una operación de mapa sin tener "undef" incluido en el resultado.

Cuando se puede generar un resumen, siempre es una única cadena de 1 línea, y se devuelve tal cual, no en una lista.

Posibles resúmenes:

# De facetas de control
"ABANDONADO"
"ABANDONADO: $why"
# De facetas de error
"ERROR"
"ERROR: $message"
"ERROR: $partial_message [...]"
"ERRORES: $first_error_message [...]"
# De facetas de aserción
"PASADO"
"FALLIDO"
"PASADO con amnistía"
"FALLIDO con amnistía"
# De facetas de plan
"PLAN $count"
"SIN PLAN"
"SALTAR TODO"
"SALTAR TODO: $why"

Tenga en cuenta que solo se devuelve el primer resumen aplicable. Esto es esencialmente un TAP de baja calidad que solo incluye facetas que podrían (pero no necesariamente lo hacen) causar un fallo.

$hashref = $event->flatten
$hashref = $event->flatten(include_subevents => 1)
Esto SIEMPRE devuelve un hashref. Esto pone todos los datos más útiles para las facetas más interesantes en un único hashref para una fácil validación.

Si no hay facetas significativas, devolverá un hashref vacío.

Si se le da el parámetro 'include_subevents', también incluirá datos de subpruebas:

Aquí hay una lista de CADA campo posible. Si un campo no es aplicable, no estará presente.

    "Prometo arreglar esto",
