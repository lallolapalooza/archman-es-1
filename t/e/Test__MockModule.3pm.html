Test::MockModule(3pm) User Contributed Perl Documentation Test::MockModule(3pm)

NOMBRE

Test::MockModule - Anular subrutinas en un módulo para pruebas unitarias

SINOPSIS

    use Module::Name;
    use Test::MockModule;
    {
            my $module = Test::MockModule->new('Module::Name');
            $module->mock('subroutine', sub { ... });
            Module::Name::subroutine(@args); # simulado
            # Mismo efecto, pero esto fallará() si other_subroutine()
            # aún no existe, lo cual es a menudo deseable.
            $module->redefine('other_subroutine', sub { ... });
            # Esto fallará() si another_subroutine() está definida.
            $module->define('another_subroutine', sub { ... });
    }
    {
            # también puedes encadenar new/mock/redefine/define
            Test::MockModule->new('Module::Name')
            ->mock( one_subroutine => sub { ... })
            ->redefine( other_subroutine => sub { ... } )
            ->define( a_new_sub => 1234 );
    }
    Module::Name::subroutine(@args); # subrutina original
    # Trabajando con objetos
    use Foo;
    use Test::MockModule;
    {
            my $mock = Test::MockModule->new('Foo');
            $mock->mock(foo => sub { print "Foo!\n"; });
            my $foo = Foo->new();
            $foo->foo(); # imprime "Foo!\n"
    }
# Si quieres prevenir que noop y mock funcionen, puedes
# cargar Test::MockModule en modo estricto.
use Test::MockModule qw/strict/;
my $module = Test::MockModule->new('Module::Name');
# Redefinió other_subroutine o falla si no existe.
$module->redefine('other_subroutine', sub { ... });
# Falla ya que especificaste que querías modo estricto.
$module->mock('subroutine', sub { ... });
# Desactiva la rigurosidad en este ámbito léxico
{
    use Test::MockModule 'nostrict';
    # ->mock() funciona ahora
    $module->mock('subroutine', sub { ... });
}
# De vuelta en el ámbito estricto, así que mock() falla aquí
$module->mock('subroutine', sub { ... });

DESCRIPCIÓN

"Test::MockModule" te permite redefinir temporalmente subrutinas en otros paquetes con el propósito de realizar pruebas unitarias.

Un objeto "Test::MockModule" se configura para simular subrutinas de un módulo dado. El objeto recuerda la subrutina original para que pueda ser restaurada fácilmente. Esto sucede automáticamente cuando todos los objetos MockModule para el módulo dado salen del ámbito, o cuando desmockeas() la subrutina.

MODO ESTRICTO

Una de las debilidades de probar usando simulacros es que la implementación de la interfaz que estás simulando puede cambiar, mientras que tus simulacros se quedan solos. Ya no estás simulando lo que pensabas que estabas, y tus simulacros podrían ahora estar ocultando errores que solo se detectarán en producción. Para ayudar a prevenir esto, puedes cargar Test::MockModule en modo 'estricto':

use Test::MockModule qw(strict);

Esto deshabilitará el uso del método redefine(), convirtiéndolo en un error fatal en tiempo de ejecución. En su lugar, deberías definir simulacros usando redefine(), que solo simulará cosas que ya existen y fallará si intentas redefinir algo que no existe.

La rigurosidad tiene ámbito léxico, por lo que puedes hacer esto en un archivo:

use Test::MockModule qw(strict);

...->redefine(...);

Y esto en otro:

use Test::MockModule; # el predeterminado es nostrict
...->mock(...);

Incluso puedes mezclar y combinar en diferentes lugares de un mismo archivo así:

use Test::MockModule qw(strict);
# aquí mock() falla
{
    use Test::MockModule qw(nostrict);
    # aquí mock() funciona
}
# aquí mock() vuelve a fallar
use Test::MockModule qw(nostrict);
# y a partir de aquí mock() vuelve a funcionar

Nótese que la rigurosidad debe definirse en tiempo de compilación y establecerse usando "use". Si piensas que vas a intentar ser inteligente llamando al método import() de Test::MockModule en tiempo de ejecución, entonces lo que suceda no está definido, con resultados que difieren de una versión de perl a otra. ¡Qué divertido!

MÉTODOS

new($package[, %options])
Devuelve un objeto que simulará subrutinas en el $package especificado.

Si no hay $VERSION definido en $package, el módulo se cargará automáticamente. Puedes anular este comportamiento estableciendo la opción "no_auto":

my $mock = Test::MockModule->new('Module::Name', no_auto => 1);
get_package()
Devuelve el nombre del paquete de destino para las subrutinas simuladas
is_mocked($subroutine)
Devuelve un valor booleano indicando si la subrutina está actualmente simulada o no
mock($subroutine => \&coderef)
Reemplaza temporalmente una o más subrutinas en el módulo simulado. Una subrutina puede ser simulada con una referencia de código o un escalar. Un escalar se convertirá en una subrutina que devuelve el escalar.

Devuelve el objeto actual de "Test::MockModule", para que puedas encadenar `new` con `mock`.

my $mock = Test::MockModule->new->(...)->mock(...);

Las siguientes declaraciones son equivalentes:

$module->mock(purge => 'purged');
$module->mock(purge => sub { return 'purged'});

Al tratar con referencias, las cosas se comportan de manera ligeramente diferente. Las siguientes declaraciones NO son equivalentes:

# Devuelve la misma referencia de array cada vez, con el localtime() en el momento de la simulación
$module->mock(updated => [localtime()]);
# Devuelve una nueva referencia de array cada vez, con el valor localtime() actualizado
$module->mock(updated => sub { return [localtime()]});

Las siguientes declaraciones son de hecho equivalentes:

my $array_ref = [localtime()]
$module->mock(updated => $array_ref)
$module->mock(updated => sub { return $array_ref });

Sin embargo, "undef" es un caso especial. Si simulas una subrutina con "undef", instalará una subrutina vacía

$module->mock(purge => undef);
$module->mock(purge => sub { });

en lugar de una subrutina que devuelve "undef":

$module->mock(purge => sub { undef });

Puedes llamar a mock() para la misma subrutina muchas veces, pero cuando llamas a unmock(), la subrutina original es restaurada (no la última instancia simulada).

SIMULACIÓN + EXPORTACIÓN

Si estás intentando simular una subrutina exportada desde otro módulo, esto puede no comportarse como esperabas inicialmente, ya que Test::MockModule solo simula en el módulo de destino, no en nada que importe ese módulo. Si simulas el paquete local, o usas un nombre de función completamente calificado, obtendrás el comportamiento que deseas:

use Test::MockModule;
use Test::More;
use POSIX qw/strftime/;
my $posix = Test::MockModule->new("POSIX");
$posix->mock("strftime", "Yesterday");
is strftime("%D", localtime(time)), "Yesterday", "`strftime` fue simulado exitosamente"; # Falla
is POSIX::strftime("%D", localtime(time)), "Yesterday", "`strftime` fue simulado exitosamente"; # Éxito
my $main = Test::MockModule->new("main", no_auto => 1);
$main->mock("strftime", "today");
is strftime("%D", localtime(time)), "today", "`strftime` fue simulado exitosamente"; # Éxito

Si estás intentando simular una subrutina que fue exportada a un módulo que estás intentando probar, en lugar de simular la subrutina en su módulo de origen, puedes simularla en el módulo que estás probando:

package MyModule;
use POSIX qw/strftime/;
sub minus_twentyfour
{
        return strftime("%a, %b %d, %Y", localtime(time - 86400));
}
package main;
use Test::More;
use Test::MockModule;
my $posix = Test::MockModule->new("POSIX");
$posix->mock("strftime", "Yesterday");
is MyModule::minus_twentyfour(), "Yesterday", "`minus-twentyfour` fue simulado"; # falla

Test::MockModule::Method::Mock->new() - Arch manual pages

NAME

Test::MockModule::Method::Mock - a mocked method

SYNOPSIS

    use Test::MockModule;
    my $mymodule = Test::MockModule->new("MyModule", no_auto => 1);
    $mymodule->mock("strftime", "Yesterday");
    is MyModule::minus_twentyfour(), "Yesterday", "`minus-twentyfour` got mocked"; # succeeds

DESCRIPTION

This is a mocked method. The goal is to provide a simple interface for mocking methods with a given return value. This is not a full fledged mocking framework but aims to provide a simple way to mock methods when you do not wish to change the calling code.

The mocking works by creating a new Test::MockModule::Method::Mock object and setting the return value that the mock is to provide.

The Test::MockModule->mock() is a simple interface to this so you do not have to know how to do this manually.

This object behaves like a subroutine reference and so can be assigned directly to a subroutine name.

STRICT MODE

For strict modes please refer to the Test::MockModule documentation.

METHODS

new($class_name_or_package, $options)
A constructor for Test::MockModule.

Takes a package name or package reference to mock. no_auto => 1 will prevent the test from dying if the package does not exist, useful if you are mocking a package that is not available in the current scope.

my $mock = Test::MockModule->new("MyModule");
my $mock = Test::MockModule->new(\&MyModule);
my $mock = Test::MockModule->new("MyModule", no_auto => 1);
mock($subroutine)
Returns a Test::MockModule::Method::Mock object. This object will provide the behavior defined by the given arguments.

The mock object will perform the following:

Subroutine reference
The subroutine reference provided will be called and its return value will be returned.
Scalar value
The scalar value will be returned on every call.
Array reference
The array reference will be dereferenced and the elements returned in list context.
Hash reference
The hash reference will be dereferenced and the elements returned in list context.

The following example shows the effect of mocking strftime.

    my $mymodule = Test::MockModule->new("MyModule", no_auto => 1);
    $mymodule->mock("strftime", "Yesterday");
    is MyModule::minus_twentyfour(), "Yesterday", "`minus-twentyfour` got mocked"; # succeeds
redefine($subroutine)
The same behavior as mock(), but this will preemptively check to be sure that all passed subroutines actually exist. This is useful to ensure that if a mocked module's interface changes the test doesn't just keep on testing a code path that no longer behaves consistently with the mocked behavior.

Note that redefine is also now checking if one of the parent provides the sub and will not die if it's available in the chain.

Returns the current "Test::MockModule" object, so you can chain new with redefine.

my $mock = Test::MockModule->new->(...)->redefine(...);
define($subroutine)
The reverse of redefine, this will fail if the passed subroutine exists. While this use case is rare, there are times where the perl code you are testing is inspecting a package and adding a missing subroutine is actually what you want to do.

By using define, you're asserting that the subroutine you want to be mocked should not exist in advance.

Note: define does not check for inheritance like redefine.

Returns the current "Test::MockModule" object, so you can chain new with define.

my $mock = Test::MockModule->new->(...)->define(...);
original($subroutine)
Returns the original (unmocked) subroutine

Here is a sample how to wrap a function with custom arguments using the original subroutine. This is useful when you cannot (do not) want to alter the original code to abstract one hardcoded argument pass to a function.

package MyModule;
sub sample {
        return get_path_for("/a/b/c/d");
}
sub get_path_for {
        ... # anything goes there...
}
package main;
use Test::MockModule;
my $mock = Test::MockModule->new("MyModule");
# replace all calls to get_path_for using a different argument
$mock->redefine("get_path_for", sub {
        return $mock->original("get_path_for")->("/my/custom/path");
});
# or
$mock->redefine("get_path_for", sub {
        my $path = shift;
        if ( $path && $path eq "/a/b/c/d" ) {
                # only alter calls with path set to "/a/b/c/d"
                return $mock->original("get_path_for")->("/my/custom/path");
        } else { # preserve the original arguments
                return $mock->original("get_path_for")->($path, @_);
        }
});
unmock($subroutine [, ...])
Restores the original $subroutine. You can specify a list of subroutines to unmock() in one go.
unmock_all()
Restores all the subroutines in the package that were mocked. This is automatically called when all "Test::MockObject" objects for the given package go out of scope.
noop($subroutine [, ...])
Given a list of subroutine names, mocks each of them with a no-op subroutine. Handy for mocking methods you want to ignore! 
# Neuter a list of methods in one go
$module->noop('purge', 'updated');
