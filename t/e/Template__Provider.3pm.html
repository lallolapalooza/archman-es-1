Template::Provider(3) Documentación de Perl contribuida por el usuario Template::Provider(3)

NOMBRE

Template::Provider - Módulo proveedor para cargar/compilar plantillas

SINOPSIS

$provider = Template::Provider->new(\%options);
($template, $error) = $provider->fetch($name);

DESCRIPCIÓN

Template::Provider se utiliza para cargar, analizar, compilar y almacenar en caché documentos de plantillas. Este objeto puede ser subclasificado para proporcionar instalaciones más específicas para cargar o, de lo contrario, proporcionar acceso a las plantillas.

Los objetos Template::Context mantienen una lista de objetos Template::Provider que se consultan por turnos (a través de fetch()) para devolver una plantilla solicitada. Cada uno puede devolver una plantilla compilada, generar un error o negarse a atender la solicitud, dando a los proveedores subsiguientes la oportunidad de hacerlo.

Template::Provider también puede ser subclasificado para proporcionar plantillas desde una fuente diferente, por ejemplo, una base de datos. Ver SUBCLASSING abajo.

Esta documentación necesita trabajo.

MÉTODOS PÚBLICOS

new(\%options)

Método constructor que instancia y devuelve un nuevo objeto "Template::Provider". Se puede pasar una referencia a un hash de opciones de configuración.

Ver "OPCIONES DE CONFIGURACIÓN" abajo para un resumen de las opciones de configuración y Template::Manual::Config para obtener detalles completos.

fetch($name)

Devuelve una plantilla compilada para el nombre especificado. Si la plantilla no se puede encontrar, se devuelve "(undef, STATUS_DECLINED)". Si ocurre un error (por ejemplo, error de lectura, error de análisis), se devuelve "($error, STATUS_ERROR)", donde $error es el mensaje de error generado. Si la opción TOLERANT está establecida, el método devuelve "(undef, STATUS_DECLINED)" en lugar de devolver un error.

load($name)

Carga una plantilla sin analizarla ni compilarla. Esto es utilizado por la directiva INSERT.

store($name, $template)

Almacena la plantilla compilada, $template, en la caché bajo el nombre, $name. Las llamadas subsiguientes a fetch($name) devolverán esta plantilla con preferencia a cualquier archivo basado en disco.

include_path(\@newpath)

Método de acceso para la configuración "INCLUDE_PATH". Si se llama con un argumento, este método reemplazará el "INCLUDE_PATH" existente con el nuevo valor.

paths()

Este método genera una copia de la lista "INCLUDE_PATH". Cualquier elemento de la lista que sean generadores dinámicos (por ejemplo, referencias a subrutinas u objetos que implementan un método paths()) se llamarán y la lista de directorios devueltos se fusionará en la lista de salida.

Es posible proporcionar un generador que se devuelva a sí mismo, enviando así este método a un bucle infinito. Para detectar y evitar que esto suceda, la variable de paquete $MAX_DIRS, establecida en 64 por defecto, limita el número máximo de rutas que se pueden agregar o generar para la lista de salida. Si se excede este número, el método devolverá inmediatamente un error informando de ello.

OPCIONES DE CONFIGURACIÓN

La siguiente lista resume las opciones de configuración que se pueden proporcionar al constructor new() de "Template::Provider". Consulte Template::Manual::Config para obtener más detalles y ejemplos de cada opción de configuración en uso.

INCLUDE_PATH

La opción INCLUDE_PATH se utiliza para especificar uno o más directorios en los que se encuentran los archivos de plantilla.

# ruta única
my $provider = Template::Provider->new({
    INCLUDE_PATH => '/usr/local/templates',
});
# rutas múltiples
my $provider = Template::Provider->new({
    INCLUDE_PATH => [ '/usr/local/templates',
                      '/tmp/my/templates' ],
});

ABSOLUTE

El indicador ABSOLUTE se utiliza para indicar si se deben procesar las plantillas especificadas con nombres de archivo absolutos (por ejemplo, '"/foo/bar"'). Está deshabilitado por defecto y cualquier intento de cargar una plantilla con dicho nombre generará una excepción de '"file"'.

my $provider = Template::Provider->new({
    ABSOLUTE => 1,
});

RELATIVE

El indicador RELATIVE se utiliza para indicar si se deben cargar las plantillas especificadas con nombres de archivo relativos al directorio actual (por ejemplo, "./foo/bar" o "../../some/where/else"). También está deshabilitado por defecto y generará un error de "file" si se encuentran dichos nombres de plantilla.

my $provider = Template::Provider->new({
    RELATIVE => 1,
});

DEFAULT

La opción DEFAULT se puede utilizar para especificar una plantilla predeterminada que se utilizará siempre que no se encuentre una plantilla especificada en INCLUDE_PATH.

my $provider = Template::Provider->new({
    DEFAULT => 'notfound.html',
});

Si se solicita una plantilla inexistente a través del método Template process(), o mediante una directiva "INCLUDE", "PROCESS" o "WRAPPER", se procesará en su lugar la plantilla "DEFAULT", si está definida. Tenga en cuenta que la plantilla "DEFAULT" no se utiliza cuando las plantillas se especifican con nombres de archivo absolutos o relativos, o como referencia a un manejador de entrada de archivo o cadena de texto.

ENCODING

Template Toolkit decodificará automáticamente las plantillas Unicode que tengan un Marcador de Orden de Bytes (BOM) al principio del archivo. Esta opción se puede utilizar para establecer la codificación predeterminada para las plantillas que no definen un BOM.

my $provider = Template::Provider->new({
    ENCODING => 'utf8',
});

Ver Encode para más información.

CACHE_SIZE

La opción CACHE_SIZE se puede utilizar para limitar el número de plantillas compiladas que el módulo debe almacenar en caché. Por defecto, CACHE_SIZE no está definido y todas las plantillas compiladas se almacenan en caché.

my $provider = Template::Provider->new({
    CACHE_SIZE => 64,   # solo almacenar en caché 64 plantillas compiladas
});

STAT_TTL

El valor STAT_TTL se puede establecer para controlar cuánto tiempo "Template::Provider" mantendrá una plantilla en caché en memoria antes de verificar si la plantilla fuente ha cambiado.

my $provider = Template::Provider->new({
    STAT_TTL => 60,  # un minuto
});

COMPILE_EXT

La opción COMPILE_EXT se puede proporcionar para especificar una extensión de nombre de archivo para los archivos de plantilla compilados. No está definida por defecto y no se intentará leer ni escribir ningún archivo de plantilla compilado.

my $provider = Template::Provider->new({
    COMPILE_EXT => '.ttc',
});

COMPILE_DIR

La opción COMPILE_DIR se utiliza para especificar un directorio raíz alternativo bajo el cual se compilarán las plantillas

Template::Provider(3pm)

NAME

Template::Provider - Template loading and caching provider

SYNOPSIS

    use Template::Provider;
    my $provider = Template::Provider->new({
        INCLUDE_PATH => ['/path/to/templates', '/etc/templates'],
        COMPILE_DIR  => '/tmp/ttc',
        ENCODING     => 'utf8',
    });
    my $template = $provider->fetch( 'mytemplate.html' );
    $template->print( \%vars );

DESCRIPTION

The "Template::Provider" module handles the loading, parsing and caching of template files. It is used by the "Template" module (via the "Template::Context" object) to locate and retrieve template definitions.

The provider can be configured to search for templates in one or more directories specified by the INCLUDE_PATH configuration option.

It also handles the caching of compiled template code, either to an in-memory cache or to a directory specified by COMPILE_DIR. This allows frequently used templates to be loaded and compiled only once, improving performance.

PUBLIC METHODS

fetch(PATH)
Retrieves a compiled template object for the specified PATH. The path is resolved relative to the INCLUDE_PATH directories. If the template is found and has been compiled before, the cached version is returned. Otherwise, it's loaded, compiled, cached (if enabled) and then returned.
fetch(PATH, OPTIONS)
As above, but accepts an OPTIONS hash ref which can be used to override configuration options for a single template request.
clear(PATH)
Removes the compiled template associated with PATH from the cache. If PATH is omitted, all templates in the cache are cleared.
get_config(KEY)
Returns the value of the specified configuration parameter KEY.
set_config(KEY, VALUE)
Sets the configuration parameter KEY to VALUE. Note that this may not affect already compiled templates.

CONFIGURATION OPTIONS

INCLUDE_PATH
An array reference of directory paths where the provider should search for template files. Defaults to `['.']`.
COMPILE_DIR
The directory where compiled template files should be stored. If not defined, compiled templates are stored only in memory. This should be a writable directory. File::Spec is used to construct the path, so it should be OS-agnostic.
ABSOLUTE
If true, INCLUDE_PATH entries are treated as absolute paths. Defaults to false.
ENCODING
The default input encoding for template files. Defaults to "null-encoding" (i.e. no specific encoding). This can be set to values like "utf8" if your templates are in that encoding.
OUTPUT_ENCODING
The default output encoding for template files. Defaults to the value of ENCODING. Can be set to "null-encoding" if no specific output encoding is required.
DEFAULT_EXT
A file extension (e.g. '.tt') to append to template names if they don't already have one. Defaults to "undef".
PREPEND_PATH
A list of template paths or directories to prepend to the INCLUDE_PATH. Useful for defining a hierarchy of template directories or overriding specific templates from a common library.
STATIC
If true, the provider will not check if a template file has been modified since it was last loaded. This can improve performance in production environments where templates are not expected to change during runtime. Defaults to false.
TOLERANT
If true, the provider will ignore any errors encountered while loading a template and instead return STATUS_DECLINED. Defaults to false.
PARSER
An instance of a Template::Parser module (or a compatible subclass) to use for parsing template files. Defaults to "Template::Parser".
DEBUG
If set to include DEBUG_PROVIDER, debugging messages will be printed to STDERR detailing the provider's operations.

COMPILE_DIR

The COMPILE_DIR option specifies a directory where compiled template files should be stored. If this option is not defined, then template code will only be cached in memory. The directory should exist and be writable by the user running the script. The file path is constructed using File::Spec, so it should be OS-agnostic.

my $provider = Template::Provider->new({
    COMPILE_DIR => '/tmp/ttc',
});

TOLERANT

The TOLERANT flag can be set to indicate that the "Template::Provider" module should ignore any errors encountered while loading a template and instead return "STATUS_DECLINED".

PARSER

The PARSER option can be used to define a parser module other than the default of Template::Parser.

my $provider = Template::Provider->new({
    PARSER => MyOrg::Template::Parser->new({ ... }),
});

DEBUG

The DEBUG option can be used to enable debugging messages from the Template::Provider module by setting it to include the "DEBUG_PROVIDER" value.

use Template::Constants qw( :debug );
my $template = Template->new({
    DEBUG => DEBUG_PROVIDER,
});

SUBCLASSING

The "Template::Provider" module can be subclassed to provide templates from a different source (e.g. a database). In most cases you'll just need to provide custom implementations of the _template_modified() and _template_content() methods. If your provider requires and custom initialisation then you'll also need to implement a new _init() method.

Caching in memory and on disk will still be applied (if enabled) when overriding these methods.

_template_modified(PATH)

Returns a timestamp of the $path passed in by calling stat(). This can be overridden, for example, to return a last modified value from a database. The value returned should be a timestamp value (as returned by time(), although a sequence number should work as well.

_template_content(PATH)

This method returns the content of the template for all "INCLUDE", "PROCESS", and "INSERT" directives.

When called in scalar context, the method returns the content of the template located at $path, or "undef" if $path is not found.

When called in list context it returns "($content, $error, $mtime)", where $content is the template content, $error is an error string (e.g. ""$path: File not found""), and $mtime is the template modification time.
