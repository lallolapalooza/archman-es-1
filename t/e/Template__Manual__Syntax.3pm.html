Template::Manual::Syntax - Sintaxis, estructura y semántica de directivas

Estilos de Etiqueta

Las directivas de plantilla están incrustadas entre marcadores de inicio y fin. Por defecto, estos marcadores de etiqueta son "[%" y "%]".

[% PROCESS header %]
<h1>¡Hola Mundo!</h1>
<a href="[% page.next %]"><img src="[% icon.next %].gif"></a>
[% PROCESS footer %]

Puedes cambiar los caracteres de las etiquetas usando las opciones de configuración "START_TAG", "END_TAG" y "TAG_STYLE". También puedes usar la directiva "TAGS" para definir un nuevo estilo de etiqueta para el archivo de plantilla actual.

También puedes establecer la opción "INTERPOLATE" para permitir que referencias de variables simples se incrusten directamente en las plantillas, prefijadas con un "$".

# INTERPOLATE = 0
<td>[% name %]</td>
<td>[% email %]</td>
# INTERPOLATE = 1
<td>$name</td>
<td>$email</td>

Las directivas pueden incrustarse en cualquier lugar de una línea de texto y pueden dividirse en varias líneas. El espacio en blanco insignificante generalmente se ignora dentro de la directiva.

[% INCLUDE header
     title = 'Hola Mundo'
     bgcol = '#ffffff'
%]
[%INCLUDE menu align='right'%]
Nombre: [% name %]  ([%id%])

Etiquetas de Esquema

A partir de la versión 2.26, Template Toolkit soporta etiquetas de "esquema". Estas tienen un marcador designado al inicio de una línea (por defecto "%%") y continúan hasta el final de la línea. El carácter de nueva línea al final de la línea se descarta (también conocido como "chomped").

Así que en lugar de escribir algo como esto:

[% IF some.list.size -%]
  <ul>
[%   FOREACH item IN some.list -%]
    <li>[% item.html %]</li>
[%   END -%]
  </ul>
[% END -%]

Puedes escribirlo así en su lugar:

%% IF some.list.size
  <ul>
%%   FOREACH item IN some.list
    <li>[% item.html %]</li>
%%   END
  </ul>
%% END

Las etiquetas de esquema no están habilitadas por defecto. Hay varias formas de habilitarlas. La primera es usar la directiva "TAGS" para establecer el estilo de etiqueta a "outline" en cualquier plantilla donde quieras usarlas. Esto habilitará las etiquetas de esquema a partir de ese momento.

[% TAGS outline -%]
%% INCLUDE header

Puedes volver a establecer "TAGS" al valor "default" en algún momento posterior de la plantilla si deseas deshabilitarlas:

[% TAGS default -%]

Puedes establecer la opción de configuración "TAG_STYLE" si deseas habilitarlas en todas las plantillas por defecto. Siempre puedes usar la directiva "[% TAGS default %]" para deshabilitarlas en cualquier plantilla o parte de plantillas si es necesario.

my $tt = Template->new({
    TAG_STYLE => 'outline',
});

La opción "OUTLINE_TAG" te permite establecer el marcador de etiqueta de esquema a otra cosa si no te gustan los signos de porcentaje. Establecer esta opción habilitará automáticamente las etiquetas de esquema.

my $tt = Template->new({
    OUTLINE_TAG => '>>',
});

También puedes usar la directiva "TAGS" para definir tus propias etiquetas personalizadas (inicio, fin y ahora opcionalmente, esquema) para una plantilla o parte de una plantilla.

[% TAGS <* *> >> %]
>> INCLUDE header       # etiqueta de esquema
Hello <* name *>        # etiqueta en línea

Si solo especificas una etiqueta de inicio y fin, las etiquetas de esquema se deshabilitarán.

[% TAGS <* *> %]        # sin etiquetas de esquema

Comentarios

El carácter "#" se usa para indicar comentarios dentro de una directiva. Cuando se coloca inmediatamente dentro de la etiqueta de directiva de apertura, hace que toda la directiva sea ignorada.

[%# esta directiva entera se ignora
    sin importar cuántas líneas abarque
%]

En cualquier otra posición, hace que el resto de la línea actual se trate como un comentario.

[% # esto es un comentario
   theta = 20      # este también
   rho   = 30      # <aol>¡yo también!</aol>
%]

Eliminación de Espacio en Blanco

Puedes añadir "-" o "+" al inicio o final inmediato de una etiqueta de directiva para controlar las opciones de eliminación de espacio en blanco. Consulta las opciones "PRE_CHOMP" y "POST_CHOMP" para más detalles.

[% BLOCK foo -%]    # elimina la nueva línea final
Este es el bloque foo
[%- END %]          # elimina la nueva línea inicial

Directivas Implícitas: GET y SET

Las directivas más simples son "GET" y "SET", que recuperan y actualizan valores de variables respectivamente. Las palabras clave "GET" y "SET" son en realidad opcionales, ya que el analizador es lo suficientemente inteligente como para ver lo que realmente son (pero ten en cuenta la advertencia a continuación sobre el uso de la notación de efectos secundarios). Por lo tanto, generalmente verás:

[% SET foo = 10 %]
[% GET foo %]

escrito como:

[% foo = 10 %]
[% foo %]

También puedes expresar declaraciones lógicas simples como directivas "GET" implícitas:

[% title or template.title or 'Título Predeterminado' %]
[% mode == 'graphics' ? "Modo Gráfico Activado" : "Modo Texto" %]

Todas las demás directivas deben comenzar con una palabra clave especificada en MAYÚSCULAS (pero consulta la opción "ANYCASE"). Todas las palabras clave de las directivas están en MAYÚSCULAS para hacerlas visualmente distintivas y para distinguirlas de variables del mismo nombre pero diferente capitalización. Es perfectamente válido, por ejemplo, definir una variable llamada "stop" que es completamente separada de la directiva "STOP".

[% stop = 'Depósito de Autobuses Clackett Lane' %]
El autobús se detendrá a continuación en [% stop %]    # variable
[% STOP %]                              # directiva

Directivas de Bloque

Directivas como "FOREACH", "WHILE", "BLOCK", "FILTER", etc., marcan el inicio de un bloque que puede contener texto u otras directivas hasta la directiva "END" coincidente. Los bloques pueden anidarse indefinidamente. Las directivas "IF", "UNLESS", "ELSIF" y "ELSE" también definen bloques y pueden agruparse de la manera habitual.

[% FOREACH item = [ 'foo' 'bar' 'baz' ] %]
   * Elemento: [% item %]
[% END %]
[% BLOCK footer %]
   Copyright 2000 [% me %]
   [% INCLUDE company/logo %]
[% END %]
[% IF foo %]
   [% FOREACH thing = foo.things %]
      [% thing %]
   [% END %]
[% ELSIF bar %]
   [% INCLUDE barinfo %]
[% ELSE %]
   no hacer nada...
[% END %]

Las directivas de bloque también se pueden usar en una notación de efectos secundarios conveniente.

[% INCLUDE userinfo FOREACH user = userlist %]
[% INCLUDE debugtxt msg="archivo: $error.info"
     IF debugging %]
[% "Peligro, Will Robinson" IF atrisk %]

versus:

[% FOREACH user = userlist %]
   [% INCLUDE userinfo %]
[% END %]
[% IF debugging %]
   [% INCLUDE debugtxt msg="archivo: $error.info" %]
[% END %]
[% IF atrisk %]
Peligro, Will Robinson
[% END %]

Block Directives

Directives such as "PROCESS", "INCLUDE", "WRAPPER", "INSERT", "CALL", "PERL", "FILTER", "SET", "LOCAL", "VARS", "BLOCK", and "TAGS" may be defined using the BLOCK syntax, which may be more convenient for multi-line content.

[% BLOCK my_block %]
   This is the content of my_block.
   It can span multiple lines.
[% END %]

The content of the block is stored in the template's namespace and may be invoked later using the "PROCESS", "INCLUDE", or "CALL" directives.

[% INCLUDE my_block %]

The "BLOCK" directive may also be used as a synonym for the "CAPTURE" directive, to capture output into a variable.

[% BLOCK my_var = CAPTURE %]
   Some content here...
[% END %]

Capturing Block Output

As shown above, the "BLOCK" directive can be used to define a named block of template text. If the directive is prefixed with a variable name and the "CAPTURE" keyword, then the output generated by the block will be captured into that variable instead of being directly output.

[% CAPTURE output = BLOCK %]
   The current time is [% NOW %].
[% END %]

The variable output will now contain the rendered text:

The current time is 10:30:45.

This is particularly useful for defining reusable pieces of template text that might be manipulated or conditionally outputted.

The "BLOCK" directive may also be used in conjunction with the side-effect notation, but care must be taken when doing so, as the syntax can be ambiguous. For example, the following directive may not behave as expected:

[% var = BLOCK IF condition %]
   value
[% END %]

This is interpreted as:

[% var = IF condition %]
   value
[% END %]

The variable var is assigned the return value of the "IF" directive, which is the rendered text of the block if the condition is true, or an empty string if the condition is false. The "BLOCK" directive itself doesn't directly support side-effect assignment in this manner. The "CAPTURE" directive should be used instead:

[% CAPTURE var = BLOCK IF condition %]
   value
[% END %]

Alternatively, a standard "SET" directive can be used if the block is defined separately:

[% BLOCK my_block %]
   value
[% END %]
[% SET var = INCLUDE my_block IF condition %]

The "BLOCK" directive may also be used as an alias for the "GET" directive when used in conjunction with the "DEFINE" directive.

The "BLOCK" directive can also be used in place of the "CAPTURE" keyword when defining a named block whose output is to be captured into a variable.

[% DEFINE my_block %]
   The boy stood on the burning deck,
   His fleece was white as snow.
   A rolling stone gathers no moss,
   And Keith is sure to follow.
[% END %]

This defines a block named my_block. To capture its output into a variable named poem, you would use the following syntax:

[% poem = BLOCK my_block %]

Note that this is equivalent to:

[% poem = CAPTURE my_block %]

And also equivalent to defining the block inline:

[% poem = BLOCK %]
   The boy stood on the burning deck,
   His fleece was white as snow.
   A rolling stone gathers no moss,
   And Keith is sure to follow.
[% END %]

Note one important caveat of using this syntax in conjunction with side-effect notation. The following directive does not behave as might be expected:

[% var = 'value' IF some_condition %]   # does not work

In this case, the directive is interpreted as (spacing added for clarity)

[% var = IF some_condition %]
   value
[% END %]

rather than

[% IF some_condition %]
   [% var = 'value' %]
[% END %]

The variable is assigned the output of the "IF" block which returns 'value' if true, but nothing if false. In other words, the following directive will always cause 'var' to be cleared.

[% var = 'value' IF 0 %]

To achieve the expected behaviour, the directive should be written as:

[% SET var = 'value' IF some_condition %]

Chaining Filters

Multiple "FILTER" directives can be chained together in sequence. They are called in the order defined, piping the output of one into the input of the next.

[% PROCESS somefile FILTER truncate(100) FILTER html %]

The pipe character, "|", can also be used as an alias for "FILTER".

[% PROCESS somefile | truncate(100) | html %]

Multiple Directive Blocks

Multiple directives can be included within a single tag when delimited by semi-colons. Note however that the "TAGS" directive must always be specified in a tag by itself.

[% IF title;
      INCLUDE header;
   ELSE;
      INCLUDE other/header  title="Some Other Title";
   END
%]

versus

[% IF title %]
   [% INCLUDE header %]
[% ELSE %]
   [% INCLUDE other/header  title="Some Other Title" %]
[% END %]
