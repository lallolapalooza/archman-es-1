NOMBRE

Template::Plugin::Filter - Clase base para filtros de plugins

SINOPSIS

package MiOrg::Template::Plugin::MiFiltro;
use Template::Plugin::Filter;
use base qw( Template::Plugin::Filter );
sub filter {
    my ($self, $text) = @_;
    # ...modificar $text...
    return $text;
}
# ahora cargarlo...
[% USE MiFiltro %]
# ...y usar el objeto devuelto como filtro
[% FILTER $MiFiltro %]
  ...
[% END %]

DESCRIPCIÓN

Este módulo implementa una clase base para filtros de plugins. Oculta la complejidad subyacente involucrada en la creación y uso de filtros que se definen y ponen a disposición cargando un plugin.

Para usar el módulo, simplemente crea tu propio módulo de plugin que herede de la clase "Template::Plugin::Filter".

package MiOrg::Template::Plugin::MiFiltro;
use Template::Plugin::Filter;
use base qw( Template::Plugin::Filter );

Luego, simplemente define tu método filter(). Cuando se llama, se te pasa una referencia a tu objeto de plugin ($self) y el texto a filtrar.

sub filter {
    my ($self, $text) = @_;
    # ...modificar $text...
    return $text;
}

Para usar tu plugin personalizado, debes asegurarte de que Template Toolkit conozca tu espacio de nombres de plugins.

my $tt2 = Template->new({
    PLUGIN_BASE => 'MiOrg::Template::Plugin',
});

O para plugins individuales, puedes hacerlo así:

my $tt2 = Template->new({
    PLUGINS => {
        MiFiltro => 'MiOrg::Template::Plugin::MiFiltro',
    },
});

Luego, "USE" tu plugin de la manera habitual.

[% USE MiFiltro %]

El objeto devuelto se almacena en la variable del mismo nombre, '"MiFiltro"'. Cuando lo usas como "FILTER", deberías añadir un prefijo de dólar. Esto indica que quieres usar el filtro almacenado en la variable '"MiFiltro"' en lugar del filtro llamado '"MiFiltro"', que es algo completamente diferente (ver más adelante para información sobre cómo definir filtros por nombre).

[% FILTER $MiFiltro %]
   ...texto a filtrar...
[% END %]

Por supuesto, puedes asignarlo a una variable diferente.

[% USE blat = MiFiltro %]
[% FILTER $blat %]
   ...texto a filtrar...
[% END %]

Cualquier parámetro de configuración pasado al constructor del plugin desde la directiva "USE" se almacena internamente en el objeto para su inspección por el método filter() (o de hecho, cualquier otro método). Los argumentos posicionales se almacenan como una referencia a una lista en el ítem "_ARGS" mientras que los parámetros de configuración con nombre se almacenan como una referencia a un array hash en el ítem "_CONFIG".

Por ejemplo, cargar un plugin como se muestra aquí:

[% USE blat = MiFiltro 'foo' 'bar' baz = 'blam' %]

permitiría al método filter() hacer algo como esto:

sub filter {
    my ($self, $text) = @_;
    my $args = $self->{ _ARGS   };  # [ 'foo', 'bar' ]
    my $conf = $self->{ _CONFIG };  # { baz => 'blam' }
    # ...modificar $text...
    return $text;
}

Por defecto, los plugins derivados de este módulo crearán filtros estáticos. Un filtro estático se crea una vez cuando el plugin se carga a través de la directiva "USE" y se reutiliza para todas las operaciones posteriores de "FILTER". Eso significa que cualquier argumento especificado con la directiva "FILTER" se ignora.

Los filtros dinámicos, por otro lado, se recrean cada vez que son utilizados por una directiva "FILTER". Esto les permite actuar sobre cualquier parámetro pasado desde la directiva "FILTER" y modificar su comportamiento en consecuencia.

Hay dos maneras de crear un filtro dinámico. La primera es definir una variable de clase $DYNAMIC establecida a un valor verdadero.

package MiOrg::Template::Plugin::MiFiltro;
use base 'Template::Plugin::Filter';
our $DYNAMIC = 1;

La otra manera es establecer el valor interno "_DYNAMIC" dentro del método init(), que es llamado por el constructor new().

sub init {
    my $self = shift;
    $self->{ _DYNAMIC } = 1;
    return $self;
}

Cuando esto se establece a un valor verdadero, el plugin creará automáticamente un filtro dinámico. El resultado es que el método filter() también recibirá una referencia a un array de argumentos posicionales y una referencia a un array hash de parámetros nombrados.

Así, usando un filtro de plugin como este:

[% FILTER $blat 'foo' 'bar' baz = 'blam' %]

permitiría al método filter() funcionar así:

sub filter {
    my ($self, $text, $args, $conf) = @_;
    # $args = [ 'foo', 'bar' ]
    # $conf = { baz => 'blam' }
}

En este caso, puedes pasar parámetros tanto a la directiva USE como a la directiva FILTER, por lo que tu método filter() debería tener eso en cuenta.

[% USE MiFiltro 'foo' wiz => 'waz' %]
[% FILTER $MiFiltro 'bar' biz => 'baz' %]
   ...
[% END %]

Puedes usar los métodos merge_args() y merge_config() para hacer un trabajo rápido y fácil de fusionar los parámetros locales (por ejemplo, de "FILTER") con los valores internos (por ejemplo, de "USE") y devolver nuevos conjuntos de datos conglomerados.

sub filter {
    my ($self, $text, $args, $conf) = @_;
    $args = $self->merge_args($args);
    $conf = $self->merge_config($conf);
    # $args = [ 'foo', 'bar' ]
    # $conf = { wiz => 'waz', biz => 'baz' }
    ...
}

También puedes hacer que tu plugin se instale como un filtro con nombre llamando al método install_filter() desde el método init(). Debes proporcionar un nombre para el filtro, algo que te gustaría convertir en una opción de configuración.

sub init {
    my $self = shift;
    my $name = $self->{ _CONFIG }->{ name } || 'myfilter';
    $self->install_filter($name);
    return $self;
}

Esto permite que el filtro del plugin se use de la siguiente manera:

[% USE MiFiltro %]
[% FILTER myfilter %]
   ...
[% END %]

o

[% USE MiFiltro name = 'swipe' %]
[% FILTER swipe %]
   ...
[% END %]

Alternativamente, puedes permitir que un nombre de filtro se especifique como el primer argumento posicional.

sub init {
    my $self = shift;
    my $name = $self->{ _ARGS }->[0] || 'myfilter';
    $self->install_filter($name);
    return $self;
}
[% USE MiFiltro 'swipe' %]
[% FILTER swipe %]
   ...
[% END %]

EJEMPLO

Aquí tienes un ejemplo completo de un módulo de filtro de plugin.

package Mi::Template::Plugin::Cambio;
use Template::Plugin::Filter;
use base qw( Template::Plugin::Filter );
sub init {
    my $self = shift;
    $self->{ _DYNAMIC } = 1;
    # el primer argumento puede especificar el nombre del filtro
    $self->install_filter($self->{ _ARGS }->[0] || 'cambio');
    return $self;
}
sub filter {
    my ($self, $text, $args, $config) = @_;
    $config = $self->merge_config($config);
    my $regex = join('|', keys %$config);
    $text =~ s/($regex)/$config->{ $1 }/ge;
    return $text;
}
1;
