Test2::Manual::Testing::Introduction(3perl) Manual de Programación de Perl Test2::Manual::Testing::Introduction(3perl)

NOMBRE

Test2::Manual::Testing::Introduction - Introducción a las pruebas con Test2.

DESCRIPCIÓN

Este tutorial es una introducción básica a las pruebas. Te guiará a través de la escritura de un archivo de prueba, la realización de afirmaciones y la ejecución de tu prueba.

PLANTILLA

EL ARCHIVO DE PRUEBA

Los archivos de prueba generalmente se colocan en la carpeta "t/" y terminan con la extensión ".t".

"t/ejemplo.t":

use Test2::V0;

Esto es todo lo que necesitas.

use Test2::V0;
Esto carga una colección de herramientas de prueba que se describirán más adelante en el tutorial. También activa "strict" y "warnings" por ti.
done_testing;
Esto siempre debe estar al final de tus archivos de prueba. Indica a Test2 que has terminado con las afirmaciones. Esto es importante porque "test2" asumirá que la prueba no fue exitosa sin esto, o algún otro tipo de plan de prueba.

CONFIGURACIÓN DE LA DISTRIBUCIÓN

Siempre debes listar los paquetes y herramientas directamente. No deberías simplemente listar Test2::Suite y decir que está hecho, ya que estos pueden ser movidos fuera de Test2::Suite a sus propias distribuciones en cualquier momento.

Dist::Zilla

[Prereqs / TestRequires]
Test2::V0 = 0.000060

ExtUtils::MakeMaker

my %WriteMakefileArgs = (
  ...,
  "TEST_REQUIRES" => {
    "Test2::V0" => "0.000060"
  },
  ...
);

Module::Install

test_requires 'Test2::V0' => '0.000060';

Module::Build

my $build = Module::Build->new(
    ...,
    test_requires => {
        "Test2::V0" => "0.000060",
    },
    ...
);

REALIZAR AFIRMACIONES

La herramienta más simple para hacer afirmaciones es ok(). ok() te permite afirmar que una condición es verdadera.

ok($CONDICIÓN, "Descripción de la condición");

Aquí hay un ejemplo completo del archivo "t/ejemplo.t":

use Test2::V0;
ok(1, "1 es verdadero, así que esta prueba pasará");
done_testing;

EJECUTAR LA PRUEBA

Los archivos de prueba son simplemente scripts. Como cualquier otro script, puedes ejecutar la prueba directamente con perl. Otra opción es usar un "harness" de prueba que ejecute la prueba por ti y te proporcione información adicional y verifique el valor de salida del script.

EJECUCIÓN DIRECTA

$ perl -Ilib t/ejemplo.t

Esto debería producir una salida similar a esto:

# Sembrando srand con la semilla '20161028' de la fecha local.
ok 1 - 1 es verdadero, así que esta prueba pasará
1..1

Si la prueba hubiera fallado ("ok(0, ...)") se vería así:

# Sembrando srand con la semilla '20161028' de la fecha local.
not ok 1 - 0 es falso, así que esta prueba fallará
1..1

Test2 también establece el valor de salida del script. Una ejecución exitosa tendrá un valor de salida 0, mientras que una ejecución fallida tendrá un valor no cero.

USAR YATH

La herramienta de línea de comandos "yath" proporcionada por Test2::Harness, puede que necesites instalarla tú mismo desde cpan. "yath" es el harness específicamente escrito para Test2.

$ yath -Ilib t/ejemplo.t

Esto debería producir una salida similar a esto:

( PASADO )  job  1    t/ejemplo.t
================================================================================
Run ID: 1508027909
¡Todas las pruebas fueron exitosas!

También puedes solicitar una salida detallada con la opción "-v":

$ yath -Ilib -v t/ejemplo.t

Que produce:

( LANZAMIENTO )  job  1    ejemplo.t
(  NOTA  )  job  1    Sembrando srand con la semilla '20171014' de la fecha local.
[  PASADO  ]  job  1  + 1 es verdadero, así que esta prueba pasará
[  PLAN  ]  job  1    Afirmaciones esperadas: 1
( PASADO )  job  1    ejemplo.t
================================================================================
Run ID: 1508028002
¡Todas las pruebas fueron exitosas!

USAR PROVE

La herramienta de línea de comandos "prove" proporcionada por el módulo Test::Harness, que viene con la mayoría de versiones de perl. Test::Harness es dual-life, lo que significa que también puedes instalar la versión más reciente desde cpan.

$ prove -Ilib t/ejemplo.t

Esto debería producir una salida similar a esto:

ejemplo.t .. ok
Todas las pruebas son exitosas.
Archivos=1, Pruebas=1, 0 wallclock secs ( 0.01 usr 0.00 sys + 0.05 cusr 0.00 csys = 0.06 CPU)
Resultado: PASAR

También puedes solicitar una salida detallada con la opción "-v":

$ prove -Ilib -v t/ejemplo.t

La salida detallada se ve así:

ejemplo.t ..
# Sembrando srand con la semilla '20161028' de la fecha local.
ok 1 - 1 es verdadero, así que esta prueba pasará
1..1
ok
Todas las pruebas son exitosas.
Archivos=1, Pruebas=1, 0 wallclock secs ( 0.02 usr 0.00 sys + 0.06 cusr 0.00 csys = 0.08 CPU)
Resultado: PASAR

EL PLAN

Todas las pruebas necesitan un plan. El trabajo del plan es asegurar que hayas ejecutado todas las pruebas que esperabas. El plan previene un resultado de éxito en una prueba que se detiene antes de que todas las pruebas se hayan ejecutado.

Hay dos formas principales de establecer el plan:

done_testing()
La forma más común y recomendada de establecer un plan es agregar "done_testing()" al final de tu archivo de prueba. Esto calculará automáticamente el plan por ti al final de la prueba. Si la prueba se detuviera temprano, "done_testing()" no se ejecutaría y no se encontraría un plan, forzando un fallo.
plan($COUNT)
La función plan() te permite especificar un número exacto de afirmaciones que quieres ejecutar. Si ejecutas demasiadas o muy pocas afirmaciones, el plan no coincidirá y se considerará un fallo. El principal problema con esta forma de planificar es que necesitas sumar el número de afirmaciones y ajustar el contador cuando actualices el archivo de prueba.

plan() debe usarse antes de todas las afirmaciones, o después de todas ellas, y no puede realizarse en medio de la realización de afirmaciones.

HERRAMIENTAS DE AFIRMACIÓN ADICIONALES

El paquete Test2::V0 proporciona mucho más que ok(), plan() y done_testing(). Las herramientas más destacadas son:

is($a, $b, $description)
is() te permite comparar dos estructuras y asegurar que sean idénticas. Puedes usarlo para comparaciones simples de cadenas o incluso comparaciones profundas de estructuras de datos. 
is("foo", "foo", "Ambas cadenas son idénticas");
is(["foo", 1], ["foo", 1], "Ambos arrays contienen los mismos elementos");
like($a, $b, $description)
like() es similar a is() excepto que solo verifica los elementos mencionados en el lado derecho, ignorando cualquier valor adicional encontrado en el lado izquierdo. 
like([1, 2, 3, 4], [1, 2, 3], "Pasa, el elemento extra en el primer array es ignorado")

Test2::Manual::Testing::Introduction(3perl)

NAME

Test2::Manual::Testing::Introduction - Introduction to Testing with Test2

DESCRIPTION

This document is the introduction to the Test2 suite of modules. It will cover the basics of how to write tests using Test2.

Test2 is a framework for testing Perl code. It is designed to be flexible, powerful, and easy to use. Test2 provides a set of tools for writing tests, running them, and reporting the results.

This document will cover the following topics:

  • The basics of writing tests with Test2.

  • How to use Test2's assertion tools.

  • How to run your tests.

  • How to use Test2's reporting features.

This document is intended for anyone who wants to write tests for their Perl code. No prior experience with Test2 is required.

BOILERPLATE

All tests written with Test2 will start with the following boilerplate code:

    use Test2::V0;
    # your tests go here
    done_testing;

The Test2::V0 pragma imports all the necessary modules and functions for you. The done_testing subroutine is used to indicate the end of the test plan. It is optional if you have exactly one test, but it is good practice to include it anyway.

MAKING ASSERTIONS

The most basic assertion is ok. It takes a boolean value and reports whether the test passed or failed.

    ok(1, 'This test passes');
    ok(0, 'This test fails');

The second argument is an optional string that describes the test. If the test fails, this string will be included in the output.

Test2 provides a rich set of assertion tools. Here are a few examples:

is($got, $expected, $diag)
Checks if $got is equal to $expected.
unlike($got, $expected, $diag)
Checks if $got is not equal to $expected.
like($got, $expected, $diag)
Checks if $got looks like $expected. $expected can be a string or a regular expression.
pass($diag)
Always passes. Useful for marking sections of tests.
fail($diag)
Always fails. Useful for marking sections of tests.

For a full list of assertion tools, see Test2::Manual::Assertion.

RUNNING THE TEST

To run your tests, save them in a file with a .t extension (e.g., test.t) and run it from the command line:

    perl test.t

If you have multiple test files, you can run them all using prove, which is part of the Test::Harness module:

    prove test/*.t

THE "PLAN"

Test2 automatically determines the number of tests to run based on how many assertions are made. However, you can explicitly set the plan using the plan subroutine:

    use Test2::V0;
    plan(10); # Expect exactly 10 tests
    # ... your tests ...
    done_testing;

This is useful if your test plan involves skipping tests or if you want to ensure a specific number of tests are run.

ADDITIONAL ASSERTION TOOLS

Test2 provides several other assertion tools, including:

throws($coderef, $expected_exception, $diag)
Checks if calling $coderef throws an exception that matches $expected_exception.
is_deeply($got, $expected, $diag)
Checks if two data structures are deeply equal.

You can also use regular expressions with the like subroutine:

like("foo bar baz", qr/bar/, "The string contains 'bar'");

You can also nest regular expressions:

like([1, 2, 'foo bar baz', 3], [1, 2, qr/bar/], "The array contains a string matching 'bar'");
