Test2::Manual::Tooling::TestBuilder(3perl) Guía de programación de Perl Test2::Manual::Tooling::TestBuilder(3perl)

NOMBRE

Test2::Manual::Tooling::TestBuilder - Esta sección mapea los métodos de Test::Builder a conceptos de Test2.

DESCRIPCIÓN

Con Test::Builder se animaba a los usuarios a utilizar métodos en el objeto singleton de Test::Builder. Test2 tiene un enfoque diferente, cada herramienta debe obtener un nuevo objeto Test2::API::Context y llamar a métodos sobre él. Este documento mapea varios conceptos de Test::Builder a Test2.

CONTEXTO

Lo primero es dejar de usar el singleton de Test::Builder, de hecho, deja de usar o incluso de cargar Test::Builder. En lugar de Test::Builder, cada herramienta que escribas debería seguir esta plantilla:

use Test2::API qw/context/;
sub mi_herramienta {
    my $ctx  = context();
    ... hacer trabajo ...
    $ctx->ok(1, "una aserción que pasa");
    $ctx->release;
    return $lo_que_sea;
}

El estilo original de Test::Builder era este:

use Test::Builder;
my $tb = Test::Builder->new; # obtiene el singleton
sub mi_herramienta {
    ... hacer trabajo ...
    $tb->ok(1, "una aserción que pasa");
    return $lo_que_sea;
}

MÉTODOS DE TEST BUILDER

$tb->BAIL_OUT($razón)
El objeto de contexto tiene un método 'bail': 
$ctx->bail($razón)
$tb->diag($cadena)
$tb->note($cadena)
El objeto de contexto tiene métodos diag y note: 
$ctx->diag($cadena);
$ctx->note($cadena);
$tb->done_testing
El objeto de contexto tiene un método done_testing: 
$ctx->done_testing;

A diferencia de la versión de Test::Builder, no se permiten argumentos.

$tb->like
$tb->unlike
Estos no forman parte del contexto, en su lugar busca en Test2::Compare y Test2::Tools::Compare.
$tb->ok($bool, $nombre)
# Preferido
$ctx->pass($nombre);
$ctx->fail($nombre, @diag);
# Desaconsejado, pero soportado:
$ctx->ok($bool, $nombre, \@fallos_diag)
$tb->subtest
usa la función Test2::API::run_subtest() en su lugar. Ver Test2::API para la documentación.
$tb->todo_start
$tb->todo_end
Ver Test2::Tools::Todo en su lugar.
$tb->output, $tb->failure_output, y $tb->todo_output
Estos ahora se manejan a través de formateadores. Ver Test2::Formatter y Test2::Formatter::TAP.

NIVEL

Test::Builder tenía la variable $Test::Builder::Level que podías modificar para establecer la profundidad de la pila. Esto era útil si necesitabas anidar herramientas y querías asegurarte de que el número de archivo y línea fueran correctos. También era frustrante y propenso a errores. Algunas personas nunca descubrieron la variable de nivel y siempre tenían números de línea incorrectos cuando sus herramientas fallaban.

Test2 usa el sistema de contexto, que resuelve el problema de una mejor manera. La herramienta superior obtiene un contexto y lo mantiene hasta que termina. Cualquier herramienta anidada debajo de la primera encontrará y usará el contexto original en lugar de generar uno nuevo. Esto significa que el problema del nivel se resuelve gratis, sin variables que manipular.

Test2 también es lo suficientemente inteligente como para honrar $Test::Builder::Level si está configurado.

TODO

Test::Builder usaba la variable de paquete $TODO para establecer el estado TODO. Esto era confuso y fácil de hacer mal. Ver Test2::Tools::Todo para la forma moderna de lograr un estado TODO.
