Test::Pod::Coverage(3) Documentación de Perl aportada por el usuario Test::Pod::Coverage(3)

NOMBRE

Test::Pod::Coverage - Comprueba la cobertura de pod en tu distribución.

VERSIÓN

Versión 1.10

SINOPSIS

En uno de los archivos de prueba de tu distribución (ej. "t/pod-coverage.t"):

use Test::Pod::Coverage tests=>1;
pod_coverage_ok( "Foo::Bar", "Foo::Bar está cubierto" );

DESCRIPCIÓN

Test::Pod::Coverage se utiliza para crear una prueba para tu distribución, para asegurar que todos los archivos relevantes de tu distribución estén documentados adecuadamente en pod.

También se puede llamar con parámetros de Pod::Coverage.

use Test::Pod::Coverage tests=>1;
pod_coverage_ok(
    "Foo::Bar",
    { also_private => [ qr/^[A-Z_]+$/ ], },
    "Foo::Bar, con funciones en mayúsculas como privadas",
);

Los parámetros de Pod::Coverage también son útiles para subclases que no redocumentan los métodos de la clase padre. Aquí hay un ejemplo de Mail::SRS.

pod_coverage_ok( "Mail::SRS" ); # Sin excepciones
# Define los tres métodos sobrescritos.
my $trustme = { trustme => [qr/^(new|parse|compile)$/] };
pod_coverage_ok( "Mail::SRS::DB", $trustme );
pod_coverage_ok( "Mail::SRS::Guarded", $trustme );
pod_coverage_ok( "Mail::SRS::Reversable", $trustme );
pod_coverage_ok( "Mail::SRS::Shortcut", $trustme );

Alternativamente, podrías usar Pod::Coverage::CountParents, que siempre permite que una subclase reimplemente los métodos de sus padres sin redocumentarlos. Por ejemplo:

my $trustparents = { coverage_class => 'Pod::Coverage::CountParents' };
pod_coverage_ok( "IO::Handle::Frayed", $trustparents );

(El parámetro "coverage_class" no se pasa a la clase de cobertura junto con otros parámetros.)

Si quieres cobertura POD para tu módulo, pero no quieres hacer de Test::Pod::Coverage un prerrequisito para la instalación, crea el siguiente archivo como tu t/pod-coverage.t:

use Test::More;
eval "use Test::Pod::Coverage";
plan skip_all => "Test::Pod::Coverage requerido para probar la cobertura de pod" if $@;
plan tests => 1;
pod_coverage_ok( "Pod::Master::Html");

Finalmente, los autores de módulos pueden incluir lo siguiente en un archivo t/pod-coverage.t y hacer que "Test::Pod::Coverage" encuentre y compruebe automáticamente todos los módulos de la distribución del módulo:

use Test::More;
eval "use Test::Pod::Coverage 1.00";
plan skip_all => "Test::Pod::Coverage 1.00 requerido para probar la cobertura de POD" if $@;
all_pod_coverage_ok();

FUNCIONES

Todas las funciones listadas a continuación se exportan al espacio de nombres llamador.

all_pod_coverage_ok( [$parms, ] $msg )

Comprueba que el código POD de todos los módulos de la distribución tengan una cobertura POD adecuada.

Si se pasa un hashref de $parms se pasan al objeto "Pod::Coverage" que la función utiliza. Consulta el manual de Pod::Coverage para saber cuáles pueden ser.

La excepción es el parámetro "coverage_class", que especifica una clase a usar para la prueba de cobertura. Por defecto es "Pod::Coverage".

pod_coverage_ok( $module, [$parms, ] $msg )

Comprueba que el código POD de $module tenga una cobertura POD adecuada.

Si se pasa un hashref de $parms se pasan al objeto "Pod::Coverage" que la función utiliza. Consulta el manual de Pod::Coverage para saber cuáles pueden ser.

La excepción es el parámetro "coverage_class", que especifica una clase a usar para la prueba de cobertura. Por defecto es "Pod::Coverage".

all_modules( [@dirs] )

Devuelve una lista de todos los módulos en $dir y en los directorios inferiores. Si no se pasan directorios, por defecto es blib si existe blib, o lib si no.

Ten en cuenta que los módulos son como "Foo::Bar", no como "Foo/Bar.pm".

El orden de los archivos devueltos depende de la máquina. Si los quieres ordenados, tendrás que ordenarlos tú mismo.
