NOMBRE

Test2::Tools::AsyncSubtest - Herramientas para escribir subpruebas asíncronas.

DESCRIPCIÓN

Estas son herramientas para escribir subpruebas asíncronas. Las subpruebas asíncronas son subpruebas que pueden iniciarse y almacenarse para que puedan seguir recibiendo eventos mientras se generan otros eventos.

SINOPSIS

use Test2::Bundle::Extended;
use Test2::Tools::AsyncSubtest;
my $ast1 = async_subtest local => sub {
    ok(1, "Dentro de la subprueba");
};
my $ast2 = fork_subtest child => sub {
    ok(1, "Dentro de la subprueba en otro proceso");
};
# Debes llamar a finish en las subpruebas que crees. Finish esperará/unirá los
# procesos y hilos hijos.
$ast1->finish;
$ast2->finish;
done_testing;

EXPORTACIONES

Todo se exporta por defecto.

$ast = async_subtest $name
$ast = async_subtest $name => sub { ... }
$ast = async_subtest $name => \%hub_params, sub { ... }
Crea una subprueba asíncrona. Ejecuta el bloque de código si se proporciona.
$ast = fork_subtest $name => sub { ... }
$ast = fork_subtest $name => \%hub_params, sub { ... }
Crea una subprueba asíncrona. Ejecuta el bloque de código en un proceso separado.
$ast = thread_subtest $name => sub { ... }
$ast = thread_subtest $name => \%hub_params, sub { ... }
** DESACONSEJADO ** Los hilos son frágiles. Las pruebas de hilos ni siquiera se ejecutan a menos que las variables de entorno AUTHOR_TESTING o T2_DO_THREAD_TESTS estén habilitadas.

Crea una subprueba asíncrona. Ejecuta el bloque de código en un hilo.

NOTAS

Las subpruebas asíncronas siempre se almacenan en búfer.
Siempre almacenadas en búfer.
No uses done_testing() tú mismo.
Usar done_testing() dentro de una subprueba asíncrona no funcionará correctamente; la subprueba asíncrona debe finalizarse llamando a "$st->finish".
