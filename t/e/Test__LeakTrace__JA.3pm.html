NOMBRE

Test::LeakTrace::JA - Rastrea fugas de memoria

VERSIÓN

Este documento describe la versión 0.17 de Test::LeakTrace.

SINOPSIS

use Test::LeakTrace;
# Informe simple
leaktrace{
        # ...
};
# Salida detallada
leaktrace{
        # ...
} -verbose;
# Con callback
leaktrace{
        # ...
} sub {
        my($ref, $file, $line) = @_;
        warn "fuga $ref de $file linea\n";
};
my @refs = leaked_refs{
        # ...
};
my @info = leaked_info{
        # ...
};
my $count = leaked_count{
        # ...
};
# Interfaz de prueba estándar
use Test::LeakTrace;
no_leaks_ok{
        # ...
} "descripción";
leaks_cmp_ok{
        # ...
} '<', 10;

DESCRIPCIÓN

El recolector de basura de Perl utiliza un contador de referencias, por lo que tiene varias ventajas, como un tiempo de liberación de objetos predecible y una alta velocidad. Por otro lado, existen varios problemas, como no poder liberar referencias circulares o errores de manejo en el nivel C. La mayoría de estos problemas están relacionados con la fuga de memoria, por lo que rastrear fugas de memoria es un problema muy importante.

"Test::LeakTrce" proporciona varias utilidades para rastrear fugas de memoria y funciones de prueba basadas en la base de "Test::Builder". Este módulo escanea la memoria asignada por el administrador de memoria de Perl, por lo que puede detectar fugas de memoria del código dado, incluso de código de nivel C o de errores del propio Perl. Es decir, a partir de referencias circulares de nivel Perl, se pueden rastrear fugas de memoria de módulos XS o de errores del propio Perl.

Aquí, fuga significa un valor que se crea nuevo dentro de un ámbito específico y que permanece incluso después de que finaliza ese ámbito. Esto incluye valores globales recién creados o valores que Perl crea de forma encubierta. Por ejemplo, si define un subrutina con nombre recién nombrada mientras rastrea fugas, esa se considerará una fuga. Además, al llamar a métodos heredados o crear objetos, se pueden crear varios cachés, lo que puede generar informes de fugas. Por ejemplo, la creación de un subrutina de método heredado puede generar un caché y este caché se considera una fuga.

INTERFAZ

Funciones exportadas

"leaked_info { BLOCK } "

Ejecuta BLOCK y devuelve el resultado del rastreo como una lista. El resultado es una lista de triplas, es decir, "[$ref, $file, $line]", que contienen la referencia del valor fugado, el nombre del archivo y el número de línea.

Además, esta función puede devolver valores utilizados internamente por Perl. Tenga en cuenta que la modificación de dichos valores internos puede afectar fatalmente al entorno de ejecución de Perl. Además, es posible que se incluyan listas o hashes que no sean referencias como elementos, o que se incluyan hashes de sí mismos. Dichos valores no se pueden manejar normalmente en Perl. Por ejemplo, no se pueden imprimir con "Data::Dumper".

"leaked_refs { BLOCK } "

Ejecuta BLOCK y devuelve una lista de referencias a los SV fugados.

Es lo mismo que "map{ $_->[0] } leaked_info{ BLOCK }", pero es más rápido.

"leaked_count { BLOCK } "

Ejecuta BLOCK y devuelve el número de referencias a SV fugados.

Aunque "leaked_info()" y "leaked_refs()" devuelven el número de elementos en un contexto de lista, "leaked_count()" no depende del contexto de lista.

"leaktrace { BLOCK } ?($mode | \&callback) "

Ejecuta BLOCK y en el medio

NAME

Test::LeakTrace または Test::LeakTrace::Script でメモリリークを模椑する

VERSION

0.10

SYNOPSIS

use Test::More tests => 1;
use Test::LeakTrace;
leaks_cmp_ok {
    my $obj = MyClass->new;
    $obj->method;
} '<', 1, 'No more than 1 leak';

or

use Test::LeakTrace::Script;
leaks_cmp_ok {
    my $obj = MyClass->new;
    $obj->method;
} '<', 1, 'No more than 1 leak';

DESCRIPTION

このモジュールは、Perlプログラムのメモリリークを模椑するためのテスト神を提供します。

メモリリークの検知は、Perlアリーナのスアーライクに相当するSV (Scalar Value)を追跡することで行っています。

The leaks() function

コンテキストの初めの情態と終わりの情態の历史的なSVのリストを取ります。

受け入れる$modeは以下のように制御されます。

-simple
メモリリークのリストを作成するのに、SVのタイプ、アドレス、ファイル名、行号を報告します。
-sv_dump
-simpleと同様です。これに加えて、SVの内容をダンプします。これはDevel::Peek::Dump()の出力と同じです。
-lines
-simpleと同様です。これに加えて、メモリリークしたと見られる行の周辺を出力します。
-verbose
-simple、-sv_dump、-linesの全てを出力します。

以下のように可能なメソッドもあります。

\&callback

当異のSVのメモリリークが検種されたとき、引数として、そのSVのリファレンス、ファイル名、行号を取り取ってこのメソッドが呼出されます。

"no_leaks_ok { BLOCK } ?$description"

メモリリークができないことをテストします。これは"Test::Builder"に基づいたテストです。

変更のために、BLOCKは複数回実行されます。

"leaks_cmp_ok { BLOCK } $cmp_op, $count ?$description"

メモリリークの数と拠定の数値を比較するテストを行います。これは"Test::Builder"に基づいたテストです。

変更のために、BLOCKは複数回実行されます。

Script interface

"Test::LeakTrace"と同様に、スクリプトでメモリリークを模椑するために"Test::LeakTrace::Script"が提供されます。"use Test::LeakTrace::Script"のアルゴリズムはleaktrace()と同じです。

$ TEST_LEAKTRACE=-sv_dump perl -MTest::LeakTrace::Script script.pl
$ perl -MTest::LeakTrace::Script=-verbose script.pl
#!perl
# ...
use Test::LeakTrace::Script sub{
        my($ref, $file, $line) = @_;
        # ...
};
# ...

EXAMPLES

Testing modules

以下はモジュールのメモリリークをチェックするテストスクリプトのテンプレートです。

#!perl -w
use strict;
use constant HAS_LEAKTRACE => eval{ require Test::LeakTrace };
use Test::More HAS_LEAKTRACE ? (tests => 1) : (skip_all => 'require Test::LeakTrace');
use Test::LeakTrace;
use Some::Module;
leaks_cmp_ok{
        my $o = Some::Module->new();
        $o->something();
        $o->something_else();
} '<', 1;

GUTS

"Test::LeakTrace"はアリーナを迷従します。アリーナとは，PerlのSV (Scalar Value)のメモリアロケーションを管理するシステムで、sv.cにてしまり実装されています。アリーナの迷従には、sv.cに存在するS_visit()のコードから取り出されたマクロを使用しています。

このようなことでメモリリークの検出は簡単になります。これらのとおり、こードブロックを実行する前にアリーナを一度迷従し、全てのSVに「使用済み」のフラグをつけます。その後、こードブロックを実行した後にもう一度アリーナを迷従し、「使用済み」フラグがついていないSVがあれば、それはこードブロック内で生成され、、メモリリークされたものであると判定します。そして、その・メモリリークを報告します。

「使用済み」フラグを保存するためには、、SVのインサイドアウトスペースがないため、外部のコンテナに利用しています。このような個特の実装をプルードコードですると以下のようになります。

my %seen_sv;
# Record all SVs
$foo->(); # Execute the code block
my @leaked;
# Iterate again, and record any new SVs
foreach my $sv(@ARENA){
    if(not exists $seen_sv{$sv}){
        push @leaked, $sv;
    }
}
say 'leaked count: ', scalar @leaked;

このような方法で、メモリリークしたSVを取取ることができます。実際に、leaked_refs()およびleaked_count()はこのような分析を行っています。

しかし、メモリリークしたSVのステートメントの情報、つまりファイル名や行号を取り出すためにはこれだけでは不十分です。Perl 5.10以降では、SVが生成されたときのステートメント情報を追跡する機能がありますが、この機能を利用するためには、コンパイララオプションとして"-DDEBUG_LEAKING_SCALARS"を与えてPerlをビルドする必要があります。

その場合、"Test::LeakTrace"は拡張可能な"PL_runops"を利用して、Perl VMがOPコードを実行するごとに一ステートメントごとにアリーナを迷従し、ステートメント情報を記録します。このような方法で、一ステートメントごとにメモリリークを迻跡することができます。

NAME

Test::LeakTrace - Test for memory leaks

VERSION

0.17

SYNOPSIS

    use Test::LeakTrace;
    use Test::More tests => 1;
    
    my $obj = Some::Class->new;
    
    # Ensure no leaks when this code is executed
    no_leaks_ok {
        # Code that might leak memory
        $obj->some_method;
        # ...
    } 'some_method test';
    
    # Or check the count of leaked SVs
    # (This test might fail or succeed depending on the context)
    is( leaked_count(), 0, 'no leaks' );
    
    # Or run leaktrace
    # (This test might fail or succeed depending on the context)
    leaktrace(
        sub {
            my $count = shift;
            is( $count, 0, 'no leaks' );
        },
        'leaktrace test'
    );

DESCRIPTION

This module provides tools for testing for memory leaks in Perl code. It allows you to wrap code blocks and check if they leak memory. It uses internal Perl mechanisms to track memory allocation and deallocation.

The primary functions are:

no_leaks_ok
This function executes a code block and checks if any memory (specifically Perl's internal structures called SVs - Scalar Values) was leaked during its execution. If any leaks are detected, the test fails.
leaked_count
This function returns the number of SVs that have been leaked. This can be used for more fine-grained testing, for example, checking if a specific operation results in exactly zero leaks.
leaktrace
This function executes a code block and captures the number of leaked SVs before and after the block. It then passes this count (the difference, representing leaks *within* the block) to a callback function for assertion.

The overhead of these functions, especially leaktrace, can be significant, making them unsuitable for frequent execution like normal code. However, they are invaluable for debugging and ensuring the memory stability of critical code sections.

Furthermore, test functions like no_leaks_ok() obtain the number of leaked SVs using leaked_count(), and then execute leaktrace() to pinpoint the location of the leaks, provided the test succeeds. Thus, the leak tracking process takes time.

INTERFACE

    no_leaks_ok BLOCK, COMMENT
    leaked_count
    leaktrace BLOCK, COMMENT
    leaktrace BLOCK, CALLER_SUBROUTINE, COMMENT

no_leaks_ok

Executes BLOCK and asserts that no memory leaks occurred. If leaks are detected, the test fails.

leaked_count

Returns the current number of leaked SVs. Note that this count is cumulative and depends on the state of the Perl interpreter.

leaktrace

Executes BLOCK and captures the number of leaked SVs before and after. The difference is passed to the CALLER_SUBROUTINE (or the code within BLOCK if no subroutine is provided) for assertion.

The COMMENT argument is optional and provides a description for the test.

EXAMPLES

    use Test::LeakTrace;
    use Test::More tests => 3;
    
    # Example 1: Using no_leaks_ok
    my $scalar = 'some string';
    no_leaks_ok {
        my $local_scalar = 'another string';
        $scalar = $local_scalar; # Assigning might cause a leak if not handled
    } 'Assignment test';
    
    # Example 2: Using leaked_count directly
    # This assumes that before this point, there were no leaks,
    # or you've accounted for them.
    my $initial_leaks = leaked_count();
    {
        my $temp_obj = Some::Class->new;
        # ... do something with $temp_obj ...
    } # $temp_obj should be freed here
    my $final_leaks = leaked_count();
    is( $final_leaks, $initial_leaks, 'Object was freed correctly' );
    
    # Example 3: Using leaktrace
    leaktrace(
        sub {
            my ($leaked_svs) = @_;
            ok( $leaked_svs == 0, 'No leaks detected by leaktrace' );
        },
        'Detailed leak trace test'
    );

GUTS

The functions no_leaks_ok() and similar operations take considerable time. However, Perl is not required to be built with special conditions and does not use version-dependent functionality, so it can be operated in many environments.

Furthermore, test functions like no_leaks_ok() obtain the number of leaked SVs using leaked_count(), and then execute leaktrace() to pinpoint the location of the leaks, provided the test succeeds. Thus, the leak tracking process takes time.

DEPENDENCIES

Perl 5.8.1 or later, and a C compiler.

CAVEATS

"Test::LeakTrace" cannot run simultaneously with "Devel::Cover". However, when running under "Devel::Cover", test functions are detected and skipped.
