NOMBRE

Template::Tutorial::Web - Generación de contenido web utilizando el Template Toolkit

Resumen

Este documento tutorial proporciona una introducción al Template Toolkit y demuestra algunas de las formas típicas en que se puede utilizar para generar contenido web. Cubre la generación de páginas estáticas a partir de plantillas utilizando los scripts tpage y ttree, y luego pasa a mostrar la generación de contenido dinámico utilizando scripts CGI y manejadores de Apache/mod_perl.

Se introducen y describen brevemente varias características del Template Toolkit y se explican mediante ejemplos. Para obtener más información, consulte Template, Template::Manual y las diversas secciones del mismo. Por ejemplo:

perldoc Template                    # Uso del módulo Template.pm
perldoc Template::Manual            # Índice del manual
perldoc Template::Manual::Config    # por ejemplo, opciones de configuración

La documentación también está disponible en formato HTML para leerla en línea o descargarla del sitio web del Template Toolkit:

http://template-toolkit.org/docs/

Introducción

El Template Toolkit es un conjunto de módulos de Perl que implementan colectivamente un sistema de procesamiento de plantillas.

Una plantilla es un documento de texto con etiquetas de marcado especiales incrustadas en él. Por defecto, el Template Toolkit utiliza '"[%"' y '"%]"' para denotar el inicio y el final de una etiqueta. Aquí tienes un ejemplo:

[% INCLUDE header %]

Gente de [% planet %], ¡atención por favor!

Soy [% captain %] del
Consejo Galáctico de Planificación Hiperspaciales.

Como sin duda sabréis, los planes
de desarrollo de las regiones exteriores
de la Galaxia requieren la construcción de una
ruta exprés hiperspaciales a través de vuestro
sistema estelar y, lamentablemente, vuestro planeta
es uno de los programados para su destrucción.

El proceso llevará algo menos de
[% time %].

Gracias.

[% INCLUDE footer %]

Las etiquetas pueden contener simples *variables* (como "planet" y "captain") y *directivas* más complejas que comienzan con una palabra clave en mayúsculas (como "INCLUDE"). Una directiva es una instrucción que indica al procesador de plantillas que realice alguna acción, como procesar otra plantilla ("header" y "footer" en este ejemplo) e insertar la salida en la plantilla actual. De hecho, las variables simples que mencionamos son en realidad directivas "GET", pero la palabra clave "GET" es opcional.

Gente de [% planet %], ¡atención por favor!      # forma corta
Gente de [% GET planet %], ¡atención por favor!  # forma larga

Otras directivas incluyen "SET" para establecer el valor de una variable (la palabra clave "SET" también es opcional), "FOREACH" para iterar a través de una lista de valores, y "IF", "UNLESS", "ELSIF" y "ELSE" para declarar bloques condicionales.

El Template Toolkit procesa todos los archivos de *texto* por igual, independientemente del tipo de contenido que contengan. Así que puedes usar TT para generar HTML, XML, CSS, Javascript, Perl, RTF, LaTeX o cualquier otro formato basado en texto. En este tutorial, sin embargo, nos centraremos en generar HTML para páginas web.

Generación de contenido web estático

Aquí tienes un ejemplo de una plantilla utilizada para generar un documento HTML.

[%  INCLUDE header
      title = 'Este es un ejemplo de HTML';

    pages = [
      { url   = 'http://foo.org'
        title = 'La Organización Foo' 
      }
      { url   = 'http://bar.org'
        title = 'La Organización Bar' 
      }
    ]
%]
   <h1>Algunos Enlaces Interesantes</h1>
   <ul>
[%  FOREACH page IN pages %]
     <li><a href="[% page.url %]">[% page.title %]</a>
[%  END %]
   </ul>

[% INCLUDE footer %]

Este ejemplo muestra cómo se utiliza la directiva "INCLUDE" para cargar y procesar archivos de plantilla separados de '"header"' y '"footer"', incluyendo la salida en el documento actual. Estos archivos podrían tener un aspecto similar a este:

header:

<html>
  <head>
    <title>[% title %]</title>
  </head>
  <body>

footer:

    <div class="copyright">
      &copy; Copyright 2007 Arthur Dent
    </div>
  </body>
</html>

El ejemplo también utiliza la directiva "FOREACH" para iterar a través de la lista '"pages"' para construir una tabla de enlaces. En este ejemplo, hemos definido esta lista dentro de la plantilla para contener un número de referencias hash, cada una con un miembro '"url"' y '"title"'. La directiva "FOREACH" itera a través de la lista, poniendo como alias '"page"' a cada elemento (en este caso, referencias de arrays hash). Las directivas "[% page.url %]" y "[% page.title %]" luego acceden a los valores individuales en los arrays hash y los insertan en el documento.

Usando tpage

Habiendo creado un archivo de plantilla, ahora podemos procesarlo para generar una salida real. La forma más rápida y fácil de hacerlo es usar el script tpage. Este se proporciona como parte del Template Toolkit y debe instalarse en tu directorio bin de Perl habitual.

Suponiendo que guardaste tu archivo de plantilla como example.html, ejecutarías el comando:

$ tpage example.html

Esto procesará el archivo de plantilla, enviando la salida a "STDOUT" (es decir, pasará rápidamente ante tus ojos en la pantalla). Es posible que desees redirigir la salida a un archivo, pero ten cuidado de no especificar el mismo nombre que el archivo de plantilla, o lo sobrescribirás. Es posible que desees utilizar un prefijo para tus plantillas (por ejemplo, '".tt"') y otro (por ejemplo, '".html"') para los archivos de salida.

$ tpage example.tt > example.html

O puedes redirigir la salida a otro directorio. por ejemplo:

$ tpage templates/example.tt > html/example.html

La salida generada se vería así:

<html>
  <head>
    <title>Este es un ejemplo de HTML</title>
  </head>
  <body>
    <h1>Algunos Enlaces Interesantes</h1>
    <ul>
      <li><a href="http://foo.org">La Organización Foo</a>
      <li><a href="http://bar.org">La Organización Bar</a>
    </ul>
    <div class="copyright">
      &copy; Copyright 2007 Arthur Dent
    </div>
  </body>
</html>

Los archivos de plantilla *header* y *footer* han sido incluidos (asumiendo que los creaste y están en el directorio actual) y los datos del enlace se han construido en una lista HTML.

Usando ttree

El script tpage te proporciona una forma sencilla y fácil de procesar una única plantilla sin tener que escribir código Perl. El script <ttree:Template::Tools::ttree>, también distribuido como parte del Template Toolkit, proporciona una forma más flexible de procesar varios documentos de plantilla a la vez.

La primera vez que ejecutes el script, te preguntará si debe crear un archivo de configuración (.ttreerc) en tu directorio de inicio. Responde "y" para que cree el archivo.

La documentación de <ttree:Template::Tools::ttree> describe cómo puedes cambiar la ubicación de este archivo y también explica la sintaxis y el significado de las diversas opciones en el archivo. Los comentarios se escriben en el archivo de configuración de ejemplo, lo que también debería ayudar.

En resumen, el archivo de configuración describe los directorios en los que se van a encontrar los archivos de plantilla ("src"), dónde se debe escribir la salida correspondiente ("dest"), y cualquier otro directorio ("lib") que pueda contener archivos de plantilla que planeas "I

NCLUDE" en sus documentos fuente. También puede especificar opciones de procesamiento (como "verbose" y "recurse") y proporcionar expresiones regulares para coincidir con archivos que no desea procesar ("ignore", "accept")> o que deben copiarse en lugar de procesarse como plantillas ("copy").

Aquí se muestra un ejemplo de archivo .ttreerc:

$HOME/.ttreerc:

verbose
recurse

# aquí es donde guardo otros archivos de configuración de ttree
cfg = ~/.ttree

src  = ~/websrc/src
lib  = ~/websrc/lib
dest = ~/public_html/test

ignore = \b(CVS|RCS)\b
ignore = ^#

Puede crear muchos archivos de configuración diferentes y almacenarlos en el directorio especificado en la opción "cfg", mostrada anteriormente. Luego puede agregar la opción "-f filename" a "ttree" para que lea ese archivo.

Cuando ejecute el script, comparará todos los archivos del directorio "src" (incluidos los de subdirectorios si la opción "recurse" está configurada) con los del directorio "dest". Si el archivo de destino no existe o tiene una marca de tiempo de modificación anterior a la del archivo de origen correspondiente, el origen se procesará y la salida se escribirá en el archivo de destino. La opción "-a" fuerza el procesamiento de todos los archivos, independientemente de las marcas de tiempo de modificación.

El script no procesa ninguno de los archivos del directorio "lib", pero lo agrega a la "INCLUDE_PATH" para el procesador de plantillas, de modo que pueda localizar estos archivos a través de una directiva "INCLUDE", "PROCESS" o "WRAPPER". Por lo tanto, el directorio "lib" es un lugar excelente para guardar elementos de plantilla, como encabezados, pies de página, etc., que no son documentos completos en sí mismos.

También puede especificar varias opciones de Template Toolkit desde el archivo de configuración. Consulte la documentación de ttree y el resumen de ayuda ("ttree -h") para obtener todos los detalles. por ejemplo:

$HOME/.ttreerc:

pre_process = config
interpolate
post_chomp

La opción "pre_process" le permite especificar un archivo de plantilla que debe procesarse antes de cada archivo. Como era de esperar, también hay una opción "post_process" para agregar una plantilla después de cada archivo. En el fragmento anterior, hemos especificado que la plantilla "config" debe usarse como plantilla de prefijo. Podemos crear este archivo en el directorio "lib" y usarlo para definir algunas variables comunes, incluidas aquellas enlaces de página web que definimos anteriormente y que podríamos querer reutilizar en otras plantillas. También podríamos incluir un encabezado HTML, un título o una barra de menú en este archivo, que luego se antepondrían a cada archivo de plantilla, pero por ahora mantendremos todo eso en un archivo "header" separado.

$lib/config:

[% root     = '~/abw'
   home     = "$root/index.html"
   images   = "$root/images"
   email    = 'abw@wardley.org'
   graphics = 1
   webpages = [
     { url => 'http://foo.org', title => 'The Foo Organsiation' }
     { url => 'http://bar.org', title => 'The Bar Organsiation' }
   ]
%]

Suponiendo que ha creado o copiado los archivos "header" y "footer" del ejemplo anterior en su directorio "lib", ahora puede comenzar a crear páginas web como la siguiente en su directorio "src" y procesarlas con "ttree".

$src/newpage.html:

[% INCLUDE header
   title = 'Another Template Toolkit Test Page'
%]

    <a href="[% home %]">Home</a>
    <a href="mailto:[% email %]">Email</a>

[% IF graphics %]
    <img src="[% images %]/logo.gif" align=right width=60 height=40>
[% END %]

[% INCLUDE footer %]

Aquí hemos mostrado cómo se pueden usar variables predefinidas como indicadores para habilitar ciertas características (por ejemplo, "graphics") y para especificar elementos comunes, como una dirección de correo electrónico y URL para la página de inicio, el directorio de imágenes, etc. Este enfoque le permite definir estos valores una vez para que sean consistentes en todas las páginas y se puedan cambiar fácilmente a nuevos valores.

Cuando ejecute ttree, debería ver una salida similar a la siguiente (suponiendo que tenga activada la opción verbose).

 ttree 2.9 (Template Toolkit version 2.20)

      Source: /home/abw/websrc/src
 Destination: /home/abw/public_html/test
Include Path: [ /home/abw/websrc/lib ]
      Ignore: [ \b(CVS|RCS)\b, ^# ]
        Copy: [  ]
      Accept: [ * ]

 + newpage.html

El signo "+" delante del nombre de archivo "newpage.html" indica que el archivo fue procesado y que la salida se escribió en el directorio de destino. Si ejecuta el mismo comando de nuevo, verá la siguiente línea mostrada en su lugar, indicando un "-" y dando una razón por la que el archivo no se procesó.

- newpage.html                     (not modified)

Ha detectado un "newpage.html" en el directorio de destino que es más reciente que el del directorio de origen, por lo que no ha perdido el tiempo reprocesándolo. Para forzar el procesamiento de todos los archivos, use la opción "-a". También puede especificar uno o más nombres de archivo como argumentos de línea de comandos para "ttree":

tpage newpage.html

Así es como se ve la página de destino.

$dest/newpage.html:

<html>
  <head>
    <title>Another Template Toolkit Test Page</title>
  </head>
  <body>

    <a href="~/abw/index.html">Home</a>
    <a href="mailto:abw@wardley.org">Email me</a>
    <img src="~/abw/images/logo.gif" align=right width=60 height=40>

    <div class="copyright">
      &copy; Copyright 2007 Arthur Dent
    </div>
  </body>
</html>

Puede agregar tantos documentos como desee al directorio "src" y "ttree" aplicará el mismo proceso a todos ellos. De esta manera, es posible construir un árbol completo de contenido estático para un sitio web con un solo comando. El beneficio adicional es que puede estar seguro de la consistencia en los enlaces, el estilo de encabezado o cualquier otra cosa que elija implementar en términos de elementos o variables de plantilla comunes.

Generación de Contenido Dinámico a Través de Script CGI

El módulo Template proporciona una interfaz simple para Template Toolkit para su uso en scripts CGI y controladores Apache/mod_perl. Simplemente use el módulo Template, cree una instancia de objeto con el método new() y luego llame al método process() en el objeto, pasando el nombre del archivo de plantilla como parámetro. El segundo parámetro pasado es una referencia a un hash de arrays de variables que queremos que estén disponibles para la plantilla:

#!/usr/bin/perl
use strict;
use warnings;
use Template;

my $file = 'src/greeting.html';
my $vars = {
   message  => "Hello World\n"
};

my $template = Template->new();

$template->process($file, $vars)
    || die "Template process failed: ", $template->error(), "\n";

Para que nuestros scripts funcionen con los mismos archivos de plantilla que nuestros ejemplos anteriores, podemos agregar algunas opciones de configuración al constructor para indicarle nuestro entorno:

my $template->new({
    # dónde encontrar los archivos de plantilla
    INCLUDE_PATH => ['/home/abw/websrc/src', '/home/abw/websrc/lib'],
    # pre-procesar lib/config para definir cualquier valor adicional
    PRE_PROCESS  => 'config',
});

Tenga en cuenta que aquí especificamos el archivo "config" como una opción "PRE_PROCESS". Esto significa que las plantillas que procesamos pueden usar las mismas variables globales definidas anteriormente para nuestras páginas estáticas. No tenemos que replicar sus definiciones en este script. Sin embargo, podemos suministrar datos y funcionalidad adicionales específicos de este script a través del hash de variables que pasamos al método process().

Las entradas en este hash pueden contener texto simple u otros valores, referencias a listas, otros hashes, subrutinas u objetos. El Template Toolkit aplicará automáticamente el procedimiento correcto para acceder a estos diferentes tipos cuando utilice las variables en una plantilla.

Aquí hay un ejemplo más detallado para revisar. Entre las diferentes variables de plantilla que definimos en $vars, creamos una referencia a un objeto CGI y una subrutina get_user_projects().

#!/usr/bin/perl
use strict;
use warnings;
use Template;
use CGI;

$| = 1;
print "Content-type: text/html\n\n";

my $file = 'userinfo.html';
my $vars = {
    'version'  => 3.14,
    'days'     => [ qw( mon tue wed thu fri sat sun ) ],
    'worklist' => \&get_user_projects,
    'cgi'      => CGI->new(),
    'me'       => {
        'id'     => 'abw',
        'name'   => 'Andy Wardley',
    },
};

sub get_user_projects {
    my $user = shift;
    my @projects = ...   # haz algo para recuperar datos
    return \@projects;
}

my $template = Template->new({
    INCLUDE_PATH => '/home/abw/websrc/src:/home/abw/websrc/lib',
    PRE_PROCESS  => 'config',
});

$template->process($file, $vars)
    || die $template->error();

Aquí hay un archivo de plantilla de ejemplo que podríamos crear para generar la salida para este script.

$src/userinfo.html:

[% INCLUDE header
   title = 'Template Toolkit CGI Test'
%]

<a href="mailto:[% email %]">Email [% me.name %]</a>

<p>This is version [% version %]</p>

<h3>Projects</h3>
<ul>
[% FOREACH project IN worklist(me.id) %]
   <li> <a href="[% project.url %]">[% project.name %]</a>
[% END %]
</ul>

[% INCLUDE footer %]

Generación de Contenido Dinámico

Al igual que con cualquier otro código de procesamiento de texto, el valor de los scripts CGI no se limita a generar datos de forma aislada. La verdadera potencia reside en la capacidad de generar HTML que se adapta dinámicamente a las condiciones y datos de la aplicación. El kit de herramientas de plantillas permite integrar este tipo de funcionalidad dinámica sin problemas en sus scripts.

Imagine que tiene un script CGI que genera una página web que muestra información sobre los usuarios de un sistema. La página podría presentar diferentes secciones y datos dependiendo de la información disponible para un usuario determinado. En lugar de tener que codificar estas variaciones directamente en el script Perl, puede definir la estructura y el contenido básico de la página en un archivo de plantilla.

El script CGI luego extrae los datos necesarios de su base de datos (u otra fuente), se los pasa a un objeto de plantilla y le indica que procese la plantilla. El kit de herramientas de plantillas toma los datos y los "inserta" en los marcadores de posición apropiados dentro de la plantilla, generando la salida HTML final. Esto significa que puede modificar la apariencia o el contenido de la página simplemente editando el archivo de plantilla, sin necesidad de cambiar el código del script CGI.

Por ejemplo, puede usar una plantilla para definir la estructura básica de su página, incluyendo elementos como encabezados y pies de página, etc. Al usar una plantilla para crear la salida de sus scripts CGI, puede darles la misma coherencia que a sus páginas estáticas creadas a través de ttree u otros medios.

Además, podemos modificar nuestro script para que procese cualquiera de varias plantillas diferentes basándose en alguna condición. Un script CGI para mantener una base de datos de usuarios, por ejemplo, podría procesar una plantilla para proporcionar un formulario vacío para nuevos usuarios, el mismo formulario con algunos valores predeterminados establecidos para actualizar un registro de usuario existente, una tercera plantilla para listar todos los usuarios en el sistema, y así sucesivamente. Puede usar cualquier funcionalidad de Perl que desee para implementar la lógica de su aplicación y luego elegir una u otra plantilla para generar la salida deseada para el estado de la aplicación.

Generación de Contenido Dinámico Vía Apache/Mod_Perl Handler

NOTA: El módulo Apache::Template está disponible en CPAN y proporciona una interfaz Apache/mod_perl sencilla y fácil de usar para el Template Toolkit. Aunque básico, implementa la mayor parte, si no todo, de lo que se describe a continuación, y evita la necesidad de escribir su propio manejador. Sin embargo, en muchos casos, querrá escribir su propio manejador para personalizar el procesamiento según sus propias necesidades, y esta sección le mostrará cómo empezar.

El módulo Template se puede usar desde un manejador Apache/mod_perl. Aquí hay un ejemplo de un archivo httpd.conf típico de Apache:

PerlModule CGI;
PerlModule Template
PerlModule MyOrg::Apache::User

PerlSetVar websrc_root   /home/abw/websrc

<Location /user/bin>
    SetHandler     perl-script
    PerlHandler    MyOrg::Apache::User
</Location>

Esto define una ubicación llamada "/user/bin" a la que se reenviarán todas las solicitudes al método handler() del módulo "MyOrg::Apache::User". Ese módulo podría parecerse a esto:

package MyOrg::Apache::User;

use strict;
use Apache::Constants qw( :common );
use Template;
use CGI;

our $VERSION = 1.59;

sub handler {
    my $r = shift;

    my $websrc = $r->dir_config('websrc_root')
        or return fail($r, SERVER_ERROR,
                       "'websrc_root' not specified");

    my $template = Template->new({
        INCLUDE_PATH  => "$websrc/src/user:$websrc/lib",
        PRE_PROCESS   => 'config',
        OUTPUT        => $r,     # direct output to Apache request
    });

    my $params = {
        uri     => $r->uri,
        cgi     => CGI->new,
    };

    # use the path_info to determine which template file to process
    my $file = $r->path_info;
    $file =~ s[^/][];

    $r->content_type('text/html');
    $r->send_http_header;

    $template->process($file, $params)
        || return fail($r, SERVER_ERROR, $template->error());

    return OK;
}

sub fail {
    my ($r, $status, $message) = @_;
    $r->log_reason($message, $r->filename);
    return $status;
}

El manejador acepta la solicitud y la utiliza para determinar el valor "websrc_root" del archivo de configuración. Esto se utiliza luego para definir una "INCLUDE_PATH" para un nuevo objeto Template. La URI se extrae de la solicitud y se crea un objeto CGI. Ambos se definen como variables de plantilla.

El nombre del archivo de plantilla en sí se toma del elemento "PATH_INFO" de la solicitud. En este caso, comprendería la parte de la URL que viene después de "/user/bin", por ejemplo, para "/user/bin/edit", el archivo de plantilla sería "edit" ubicado en "$websrc/src/user". Las cabeceras se envían y se procesa el archivo de plantilla. Toda la salida se envía directamente al método print() del objeto de solicitud de Apache.

Uso de Plugins para Extender la Funcionalidad

Como ya hemos mostrado, es posible vincular datos y funciones de Perl a variables de plantilla al crear contenido dinámico a través de un script CGI o un proceso Apache/mod_perl. El Template Toolkit también soporta una interfaz de plugin que permite definir estos datos y/o funcionalidades adicionales en un módulo separado y luego cargarlo y usarlo según sea necesario con la directiva "USE".

El principal beneficio de este enfoque es que puede cargar la extensión en cualquier documento de plantilla, incluso aquellos que se procesan "estáticamente" con "tpage" o "ttree". Usted no necesita escribir un wrapper de Perl para cargar explícitamente el módulo y hacerlo disponible a través del stash.

Demostremos este principio usando el plugin "DBI" escrito por Simon Matthews (disponible en CPAN). Puede crear esta plantilla en su directorio "src" y procesarla usando "ttree" para ver los resultados. Por supuesto, este ejemplo depende de la existencia de la base de datos SQL apropiada, pero debería poder adaptarlo a sus propios recursos, o al menos usarlo como un ejemplo demostrativo de lo que es posible.

[% INCLUDE header
     title = 'User Info'
%]

[% USE DBI('dbi:mSQL:mydbname') %]

<table border=0 width="100%">
  <tr>
    <th>User ID</th>
    <th>Name</th>
    <th>Email</th>
  </tr>
[% FOREACH user IN DBI.query('SELECT * FROM user ORDER BY id') %]
  <tr>
    <td>[% user.id %]</td>
    <td>[% user.name %]</td>
    <td>[% user.email %]</td>
  </tr>
[% END %]
</table>

[% INCLUDE footer %]

Un plugin es simplemente un módulo de Perl en una ubicación conocida y que cumple con un estándar conocido, de modo que el Template Toolkit pueda encontrarlo y cargarlo automáticamente. Puede crear su propio plugin heredando del módulo Template::Plugin.

Aquí hay un ejemplo que define algunos elementos de datos ("foo" y "people") y también un método de objeto ("bar"). Llamaremos al plugin "FooBar" por falta de un nombre mejor y lo crearemos en el paquete "MyOrg::Template::Plugin::FooBar". Hemos agregado un "MyOrg" al paquete regular "Template::Plugin::*" para evitar cualquier conflicto con plugins existentes.

package MyOrg::Template::Plugin::FooBar;
use base 'Template::Plugin'
our $VERSION = 1.23;

sub new {
    my ($class, $context, @params) = @_;

    bless {
        _CONTEXT => $context,
        foo      => 25,
        people   => [ 'tom', 'dick', 'harry' ],
    }, $class;
}

sub bar {
    my ($self, @params) = @_;
    # ...do something...
    return $some_value;
}

El constructor del plugin new() recibe el nombre de la clase como primer parámetro, como es habitual en Perl, seguido de una referencia a algo llamado objeto Template::Context. No necesita preocuparse demasiado por esto por el momento, más allá de saber que es el objeto de procesamiento principal para el Template Toolkit. Proporciona acceso a la funcionalidad del procesador y algunos plugins pueden necesitar comunicarse con él. Nosotros no lo necesitamos en esta etapa, pero guardaremos la referencia de todos modos en el miembro "_CONTEXT". El guion bajo inicial es una convención que indica que este elemento es privado y el Template Toolkit no intentará acceder a este miembro. Los otros miembros definidos, "foo" y "people" son elementos de datos regulares que estarán disponibles para las plantillas que utilizan este plugin. Después de la referencia de contexto, se pasan los parámetros adicionales especificados con la directiva USE, como el parámetro de origen de datos, "dbi:mSQL:mydbname", que utilizamos en el ejemplo anterior de DBI.

Si no lo instala o no puede instalarlo en la ubicación habitual para sus módulos de Perl (quizás porque no tiene los privilegios necesarios), puede establecer la variable de entorno PERL5LIB para especificar otra ubicación. Si está utilizando "ttree", puede agregar la siguiente línea a su archivo de configuración en su lugar.

$HOME/.ttreerc:

perl5lib = /path/to/modules

Se debe agregar un elemento de configuración adicional para informar al toolkit del nuevo nombre de paquete que hemos adoptado para nuestros plugins:

$HOME/.ttreerc:

plugin_base = 'MyOrg::Template::Plugin'

Si está escribiendo código Perl para controlar los módulos de Plantilla directamente, este valor se puede pasar como un parámetro de configuración cuando cree el módulo.

use Template;

my $template = Template->new({
    PLUGIN_BASE => 'MyOrg::Template::Plugin'
});

Ahora podemos crear una plantilla que utilice este plugin:

[% INCLUDE header
   title = 'FooBar Plugin Test'
%]

[% USE FooBar %]

Some values available from this plugin:
  [% FooBar.foo %] [% FooBar.bar %]

The users defined in the 'people' list:
[% FOREACH uid = FooBar.people %]
  * [% uid %]
[% END %]

[% INCLUDE footer %]

Los elementos "foo", "bar" y "people" del plugin FooBar se resuelven automáticamente a los elementos de datos o llamadas de método apropiados en el objeto subyacente.

Utilizando este enfoque, es posible crear funcionalidad de aplicación en un solo módulo que luego se puede cargar y usar a pedido en cualquier plantilla. La interfaz simple entre las directivas de plantilla y los objetos de plugin permite construir contenido dinámico complejo a partir de unos pocos documentos de plantilla simples sin saber nada sobre la implementación subyacente.

Web Programming Tutorial

NAME

Template::Tutorial::Web - Web Programming Tutorial

Overview

This document provides a brief introduction to using the Template Toolkit with web applications, covering static content generation, dynamic content generation using CGI scripts and Apache/ModPerl handlers, and the use of plugins.

Introduction

The Template Toolkit is a powerful and flexible templating system for Perl. It can be used to generate any kind of text-based output, including HTML, XML, email, and source code. This tutorial focuses on its application in web development.

Generating Static Web Content

For static content, you can simply use the Template Toolkit to process template files and generate HTML files. These files can then be served directly by a web server.

Example:

    # my_template.tt
    
    [% title %]
    
        
Hello, [% name %]!

        
This is a static page generated by the Template Toolkit.

    
    

    # generate_page.pl
    use strict;
    use Template;

    my $template = Template->new();
    my $vars = {
        title => "Static Page",
        name  => "World",
    };

    $template->process("my_template.tt", $vars)
        or die "Error processing template: ", $template->error();

Dynamic Content Generation Via CGI Script

You can embed Template Toolkit processing within a CGI script to generate dynamic HTML content based on user input or other data sources.

Example:

    #!/usr/bin/perl
    use strict;
    use Template;

    my $template = Template->new();
    my $vars = {
        title => "Dynamic Page",
        user  => $ENV{'REMOTE_ADDR'},
        items => [ "Apple", "Banana", "Orange" ],
    };

    print "Content-Type: text/html\n\n";

    $template->process("dynamic_template.tt", $vars)
        or die "Error processing template: ", $template->error();

    # dynamic_template.tt
    
    [% title %]
    
        
Welcome, User!

        
Your IP address is: [% user %]

        
Here are some items:

        
    
        [% FOREACH item IN items %]
            
  • [% item %]
    • 
        [% END %]

Dynamic Content Generation Via Apache/Mod_Perl Handler

For better performance, especially in high-traffic environments, you can integrate Template Toolkit with Apache using the mod_perl module.

Example (using Apache::Template or similar handler:

    # httpd.conf snippet
    <Location /app>
        SetHandler perl-script
        PerlHandler Apache::Template
    </Location>

    # in your Perl module (e.g., MyWebApp.pm)
    package MyWebApp;
    use strict;
    use Template;
    use base qw(Apache::Template);

    sub handler {
        my $self = shift;

        my $template = Template->new();
        my $vars = {
            title => "ModPerl Page",
            message => "This page is served dynamically via ModPerl.",
        };

        $self->send_http_header();
        $template->process("modperl_template.tt", $vars)
            or $self->print($template->error);
    }
    1;

    # modperl_template.tt
    
    [% title %]
    
        
ModPerl Example

        
[% message %]

Using Plugins to Extend Functionality

The Template Toolkit supports plugins that can extend its capabilities. For web development, plugins like Template::Plugin::HTML or custom plugins can simplify tasks like HTML tag generation.

Example:

    # in your Template configuration or directly in code
    my $template = Template->new({
        PLUGINS => [ 'HTML' ],
    });

    # In the template:
    <!DOCTYPE html>
    <html>
    <head>
        [% HTML.title(title) %]
    </head>
    <body>
        [% HTML.h1(greeting) %]
        [% HTML.p("This uses the HTML plugin.") %]
    </body>
    </html>
