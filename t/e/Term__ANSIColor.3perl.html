Term::ANSIColor(3perl) Guía de programación de Perl Term::ANSIColor(3perl)

NOMBRE

Term::ANSIColor - Colorea la salida de la pantalla usando secuencias de escape ANSI

SINOPSIS

use Term::ANSIColor;
print color('bold blue');
print "Este texto es azul negrita.\n";
print color('reset');
print "Este texto es normal.\n";
print colored("Amarillo sobre magenta.", 'amarillo on_magenta'), "\n";
print "Este texto es normal.\n";
print colored(['amarillo on_magenta'], 'Amarillo sobre magenta.', "\n");
print colored(['rojo on_amarillo_brillante'], 'Rojo sobre amarillo brillante.', "\n");
print colored(['rojo_brillante on_negro'], 'Rojo brillante sobre negro.', "\n");
print "\n";
# Mapea secuencias de escape a nombres de color.
use Term::ANSIColor 1.04 qw(uncolor);
my @nombres = uncolor('01;31');
print join(q{ }, @nombres), "\n";
# Elimina todas las secuencias de escape de color.
use Term::ANSIColor 2.01 qw(colorstrip);
print colorstrip("\e[1mEsto es negrita\e[0m"), "\n";
# Determina si un color es válido.
use Term::ANSIColor 2.02 qw(colorvalid);
my $valido = colorvalid('azul negrita', 'on_magenta');
print "La cadena de color es ", $valido ? "válida\n" : "inválida\n";
# Crea nuevos alias para colores.
use Term::ANSIColor 4.00 qw(coloralias);
coloralias('alerta', 'rojo');
print "La alerta es ", coloralias('alerta'), "\n";
print colored("Esto está en rojo.", 'alerta'), "\n";
use Term::ANSIColor qw(:constants);
print BOLD, BLUE, "Este texto está en azul negrita.\n", RESET;
use Term::ANSIColor qw(:constants);
{
    local $Term::ANSIColor::AUTORESET = 1;
    print BOLD BLUE "Este texto está en azul negrita.\n";
    print "Este texto es normal.\n";
}
use Term::ANSIColor 2.00 qw(:pushpop);
print PUSHCOLOR RED ON_GREEN "Este texto es rojo sobre verde.\n";
print PUSHCOLOR BRIGHT_BLUE "Este texto es azul brillante sobre verde.\n";
print RESET BRIGHT_BLUE "Este texto es solo azul brillante.\n";
print POPCOLOR "De vuelta a rojo sobre verde.\n";
print LOCALCOLOR GREEN ON_BLUE "Este texto es verde sobre azul.\n";
print "Este texto es rojo sobre verde.\n";
{
    local $Term::ANSIColor::AUTOLOCAL = 1;
    print ON_BLUE "Este texto es rojo sobre azul.\n";
    print "Este texto es rojo sobre verde.\n";
}
print POPCOLOR "De vuelta a lo que sea que estábamos al principio.\n";

DESCRIPCIÓN

Este módulo tiene dos interfaces, una a través de color() y colored() y la otra a través de constantes. También ofrece las funciones de utilidad uncolor(), colorstrip(), colorvalid() y coloralias(), que deben ser importadas explícitamente para ser utilizadas (ver "SINOPSIS").

Si está utilizando Term::ANSIColor en un comando de consola, considere soportar el estándar CLICOLOR. Ver "Soportando CLICOLOR" para más información.

Ver "COMPATIBILIDAD" para las versiones de Term::ANSIColor que introdujeron características particulares y las versiones de Perl que las incluyeron.

Colores Soportados

Los emuladores de terminal que soportan color se dividen en cuatro tipos: los que solo soportan ocho colores, los que soportan dieciséis, los que soportan 256 y los que soportan color de 24 bits. Este módulo proporciona los códigos de escape ANSI para todos ellos. Estos colores se denominan colores ANSI 0 a 7 (normal), 8 a 15 (16 colores), 16 a 255 (256 colores) y color verdadero (llamado color directo por xterm).

Desafortunadamente, la interpretación de los colores 0 a 7 a menudo depende de si el emulador soporta ocho o dieciséis colores. Los emuladores que solo soportan ocho colores (como la consola de Linux) mostrarán los colores 0 a 7 con brillo normal e ignorarán los colores 8 a 15, tratándolos igual que el blanco. Los emuladores que soportan 16 colores, como gnome-terminal, normalmente muestran los colores 0 a 7 como versiones tenues o más oscuras y los colores 8 a 15 como brillo normal. En tales emuladores, el blanco "normal" (color 7) generalmente se muestra como gris pálido, requiriendo que se use el blanco brillante (15) para obtener un color blanco real. El negro brillante suele ser un color gris oscuro, aunque algunos terminales lo muestran como negro puro. Algunos emuladores de terminal de dieciséis colores también tratan el amarillo normal (color 3) como naranja o marrón, y el amarillo brillante (color 11) como amarillo.

Siguiendo la convención normal de los emuladores de dieciséis colores, este módulo proporciona un par de atributos para cada color. Para cada color normal (0 a 7), el color brillante correspondiente (8 a 15) se obtiene anteponiendo la cadena "bright_" al nombre del color normal. Por ejemplo, "red" es el color 1 y "bright_red" es el color 9. Lo mismo se aplica a los colores de fondo: "on_red" es el color normal y "on_bright_red" es el color brillante. Capitalice estas cadenas para la interfaz de constantes.

Desafortunadamente, no hay forma de saber si el emulador actual soporta más de ocho colores, lo que dificulta la elección de colores. La opción más conservadora es usar solo los colores regulares, que al menos se muestran en todos los emuladores. Sin embargo, aparecerán oscuros en los emuladores de terminal de dieciséis colores, incluidos la mayoría de los emuladores comunes en entornos X de UNIX. Si sabe que la pantalla es uno de esos emuladores, es posible que desee usar las variantes brillantes en su lugar. Aún mejor, ofrezca al usuario una forma de configurar los colores para una aplicación determinada que se adapte a su emulador de terminal.

Para los emuladores de 256 colores, este módulo proporciona adicionalmente "ansi0" a "ansi15", que son los mismos que los colores 0 a 15 en emuladores de dieciséis colores pero usan la sintaxis de escape de 256 colores, "grey0" a "grey23" que van desde casi negro hasta casi blanco, y un conjunto de colores RGB. Los colores RGB tienen la forma "rgbRGB" donde R, G y B son números del 0 al 5 que dan la intensidad del rojo, verde y azul. Los colores grises y RGB también están disponibles como "ansi16" a "ansi255" si desea nombres simples para los 256 colores. También se proporcionan variantes "on_" de todos estos colores. Estos colores pueden ser ignorados por completo en terminales que no son de 256 colores o pueden ser malinterpretados y producir comportamientos aleatorios. Atributos adicionales como parpadeo, cursiva o negrita pueden no funcionar con la paleta de 256 colores.

Para los emuladores de color verdadero, este módulo soporta atributos de la forma "rNNNgNNNbNNN" y "on_rNNNgNNNbNNN" para todos los valores de NNN entre 0 y 255. Estos representan colores de primer plano y de fondo, respectivamente, con los valores RGB dados por los números NNN. Estos colores pueden ser ignorados por completo en terminales que no son de color verdadero o pueden ser malinterpretados y producir comportamientos aleatorios.

Interfaz de Función

La interfaz de funciones utiliza cadenas de atributos para describir los colores y los atributos de texto que se asignarán al texto. Los atributos no de color reconocidos son clear, reset, bold, dark, faint, italic, underline, underscore, blink, reverse y concealed. Clear y reset (restablecer a los atributos predeterminados), dark y faint (tenue y saturado), y underline y underscore son equivalentes, así que use el que le resulte más intuitivo.

Tenga en cuenta que no todos los atributos son compatibles con todos los tipos de terminales, y algunos terminales pueden no admitir ninguna de estas secuencias. Dark y faint, italic, blink y concealed en particular a menudo no se implementan.

Los atributos, una vez establecidos, duran hasta que se deshabilitan (imprimiendo el atributo "clear" o "reset"). Tenga cuidado de hacerlo, o de lo contrario su atributo durará después de que su script termine de ejecutarse, y la gente se molestará mucho por tener su prompt y su escritura cambiados a colores extraños.

color(ATTR[, ATTR ...])
color() toma cualquier número de cadenas como argumentos y las considera listas de atributos separadas por espacios. Luego forma y devuelve la secuencia de escape para establecer esos atributos. No la imprime, solo la devuelve, para que pueda imprimirla usted mismo si lo desea. Esto es para que pueda guardarla como una cadena, pasarla a otra cosa, enviarla a un manejador de archivos o hacer cualquier otra cosa con ella que pueda importarle. color() lanza una excepción si se le da un atributo inválido.
colored(STRING, ATTR[, ATTR ...])
colored(ATTR-REF, STRING[, STRING...])
Como ayuda para restablecer los colores, colored() toma un escalar como primer argumento y cualquier número de cadenas de atributos como segundo argumento, y devuelve el escalar envuelto en códigos de escape para que los atributos se establezcan según lo solicitado antes de la cadena y se restablezcan a la normalidad después de la cadena. Alternativamente, puede pasar una referencia a una matriz como primer argumento, y luego el contenido de esa matriz se tomará como atributos y códigos de color, y el resto de los argumentos como texto para colorear.

Normalmente, colored() simplemente coloca códigos de atributos al principio y al final de la cadena, pero si establece $Term::ANSIColor::EACHLINE a alguna cadena, esa cadena se considerará el delimitador de línea y el atributo se establecerá al principio de cada línea de la cadena pasada y se restablecerá al final de cada línea. Esto es a menudo deseable si la salida contiene saltos de línea y está utilizando colores de fondo, ya que un color de fondo que persiste a través de un salto de línea a menudo es interpretado por la terminal como el color de fondo predeterminado para la siguiente línea. Programas como los paginadores también pueden confundirse con atributos que abarcan líneas. Normalmente querrá establecer $Term::ANSIColor::EACHLINE a "\n" para usar esta característica.

Considere especialmente establecer $Term::ANSIColor::EACHLINE si está intercalando la salida a la salida estándar y al error estándar y no está vaciando la salida estándar (a través de autoflush() o estableciendo $|). Si no lo hace, el código para restablecer el color puede permanecer inesperadamente en el búfer de salida estándar en lugar de ir a la pantalla, lo que hará que la salida de error estándar aparezca con el color incorrecto.

uncolor(ESCAPE)
uncolor() realiza la traducción opuesta a color(), convirtiendo las secuencias de escape en una lista de cadenas correspondientes a los atributos que están siendo establecidos por esas secuencias. uncolor() nunca devolverá "ansi16" a través de "ansi255", prefiriendo en cambio los nombres "grey" y "rgb" (y de manera similar para "on_ansi16" a "on_ansi255").
colorstrip(STRING[, STRING ...])
colorstrip() elimina todas las secuencias de escape de color de las cadenas proporcionadas, devolviendo las cadenas modificadas por separado en contexto de matriz o unidas en contexto escalar. Sus argumentos no se modifican.
colorvalid(ATTR[, ATTR ...])
colorvalid() toma cadenas de atributos al igual que color() y devuelve verdadero si todos los atributos son conocidos y falso de lo contrario.
coloralias(ALIAS[, ATTR ...])
Si se especifica ATTR, se interpreta como una lista de cadenas separadas por espacios que nombran atributos o alias existentes. En este caso, coloralias() establece un alias de ALIAS para el conjunto de atributos dados por ATTR. A partir de ese momento, ALIAS se puede pasar a color(), colored() y colorvalid() y tendrá el mismo significado que la secuencia de atributos dada en ATTR. Un posible uso de esta facilidad es dar nombres más significativos a los colores RGB de 256 colores. Solo se permiten alfanuméricos ASCII, ".", "_" y "-" en los nombres de alias.

Si ATTR incluye alias, esos alias se expandirán en el momento de la definición y sus valores se utilizarán para definir el nuevo alias. Esto significa que si define un alias A en términos de otro alias B, y luego redefine el alias B, el valor del alias A no cambiará.

Si ATTR no se especifica, coloralias() devuelve el atributo o atributos estándar a los que ALIAS está aliasado, si los hay, o undef si ALIAS no existe. Si está aliasado a múltiples atributos, el valor de retorno será una sola cadena y los atributos estarán separados por espacios.

Esta es la misma facilidad utilizada por la variable de entorno ANSI_COLORS_ALIASES (ver "ENVIRONMENT" abajo) pero se puede usar en tiempo de ejecución, no solo cuando se carga el módulo.

Las invocaciones posteriores de coloralias() con el mismo ALIAS anularán los alias anteriores. No hay forma de eliminar un alias.

Los alias no tienen efecto en el valor de retorno de uncolor().

ADVERTENCIA: Los alias son globales y afectan a todos los llamadores en el mismo proceso. No hay forma de establecer un alias limitado a un bloque de código particular o a un objeto particular.

use Term::ANSIColor 4.00 qw(RESET :constants256);

El color verdadero y los alias no son compatibles con la interfaz de constantes.

Al usar las constantes, si no quiere tener que recordar agregar el ", RESET" al final de cada línea de impresión, puede establecer $Term::ANSIColor::AUTORESET a un valor verdadero. print BOLD BLUE "Texto\n";

print BOLD, BLUE, "Texto\n";

NAME

Term::ANSIColor - procedures for colorizing terminal text

SYNOPSIS

    use Term::ANSIColor;
    print FOREGROUND red, "This text is red\n";
    print BACKGROUND blue, "This text is on a blue background\n";
    print BOLD, "This text is bold\n";
    print RESET, "This text is back to normal\n";
    print RED, ON_BLUE, BOLD, "This text is bold red on blue\n", RESET;

    # Or, as a function:
    print color( FOREGROUND=>red, BACKGROUND=>blue, BOLD ), "This text is bold red on blue\n", RESET;

    # Or, a combination:
    print colored("This text is bold red on blue\n", red, on_blue, bold);
    print colored("This text is bold red on blue\n", 'red on_blue bold');

    # Use constants directly:
    print RED, "This text is red\n";
    print RED, ON_BLUE, BOLD, "This text is bold red on blue\n", RESET;

    # You can disable colors:
    local $Term::ANSIColor::AUTOLOCAL = 1;
    print BLUE, "This text is blue.\n"; # AUTOLOCAL makes this safe

    # Or disable them entirely:
    $ENV{ANSI_COLORS_DISABLED} = 1;
    print RED, "This text is not red.\n"; # Outputs nothing

    # Or use the push/pop stack:
    use Term::ANSIColor qw(:pushpop);
    print PUSHCOLOR BLUE, "This text is blue.\n";
    print POPCOLOR; # Resets to previous color state

    # Or use autolocal for a block:
    print LOCALCOLOR BLUE, "This text is blue.\n"; # Resets automatically

DESCRIPTION

Term::ANSIColor exports a number of constants and subroutines that make it easy to produce ANSI escape sequences for controlling the color and attributes of text in a terminal.

The primary interface is via constants such as RED, BLUE, BOLD, UNDERLINE, RESET, etc. These constants expand to the appropriate ANSI escape sequences.

The constant interface is convenient for simple cases, but has a potential pitfall: misspelled constants are not caught until runtime, and can lead to errors such as:

    use Term::ANSIColor;
    print REED, "This text should be red\n";

This will print the literal string "REED" followed by garbage, or possibly just a reset code, depending on what REED happens to expand to.

To avoid this, you can use the subroutines color() or colored(). colored() takes the string to be colored as its first argument, and the color/attributes as subsequent arguments. color() takes the color/attributes as named arguments.

For example:

    print colored("This text is red\n", RED);
    print colored("This text is red\n", 'red'); # You can use strings too
    print color( RED => FOREGROUND, BLUE => BACKGROUND ), "This text is red on blue\n";

The advantage of these subroutines is that misspelled attribute names will be caught at compile time (as runtime errors in the compilation phase). However, there is a trade-off: colors or attributes in calls to color() and colored() won't be caught until runtime whereas misspelled names of constants will be caught at compile time. So, pollute your namespace with almost two dozen subroutines that you may not even use that often, or risk a silly bug by mistyping an attribute. Your choice, TMTOWTDI after all.

The Color Stack

You can import ":pushpop" and maintain a stack of colors using PUSHCOLOR, POPCOLOR, and LOCALCOLOR. PUSHCOLOR takes the attribute string that starts its argument and pushes it onto a stack of attributes. POPCOLOR removes the top of the stack and restores the previous attributes set by the argument of a prior PUSHCOLOR. LOCALCOLOR surrounds its argument in a PUSHCOLOR and POPCOLOR so that the color resets afterward.

If $Term::ANSIColor::AUTOLOCAL is set, each sequence of color constants will be implicitly preceded by LOCALCOLOR. In other words, the following:

{
    local $Term::ANSIColor::AUTOLOCAL = 1;
    print BLUE "Text\n";
}

is equivalent to:

print LOCALCOLOR BLUE "Text\n";

If $Term::ANSIColor::AUTOLOCAL is set, it takes precedence over $Term::ANSIColor::AUTORESET, and the latter is ignored.

When using PUSHCOLOR, POPCOLOR, and LOCALCOLOR, it's particularly important to not put commas between the constants.

print PUSHCOLOR BLUE "Text\n";

will correctly push BLUE onto the top of the stack.

print PUSHCOLOR, BLUE, "Text\n";    # wrong!

will not, and a subsequent pop won't restore the correct attributes. PUSHCOLOR pushes the attributes set by its argument, which is normally a string of color constants. It can't ask the terminal what the current attributes are.

Supporting CLICOLOR

https://bixense.com/clicolors/ proposes a standard for enabling and disabling color output from console commands using two environment variables, CLICOLOR and CLICOLOR_FORCE. Term::ANSIColor cannot automatically support this standard, since the correct action depends on where the output is going and Term::ANSIColor may be used in a context where colors should always be generated even if CLICOLOR is set in the environment. But you can use the supported environment variable ANSI_COLORS_DISABLED to implement CLICOLOR in your own programs with code like this:

if (exists($ENV{CLICOLOR}) && $ENV{CLICOLOR} == 0) {
    if (!$ENV{CLICOLOR_FORCE}) {
        $ENV{ANSI_COLORS_DISABLED} = 1;
    }
}

If you are using the constant interface, be sure to include this code before you use any color constants (such as at the very top of your script), since this environment variable is only honored the first time a color constant is seen.

Be aware that this will export ANSI_COLORS_DISABLED to any child processes of your program as well.

DIAGNOSTICS

Bad color mapping %s
(W) The specified color mapping from ANSI_COLORS_ALIASES is not valid and could not be parsed. It was ignored.
Bad escape sequence %s
(F) You passed an invalid ANSI escape sequence to uncolor().
Bareword "%s" not allowed while "strict subs" in use
(F) You probably mistyped a constant color name such as: 
$Foobar = FOOBAR . "This line should be blue\n";

or:

@Foobar = FOOBAR, "This line should be blue\n";

This will only show up under use strict (another good reason to run under use strict).

Cannot alias standard color %s
(F) The alias name passed to coloralias() matches a standard color name. Standard color names cannot be aliased.
Cannot alias standard color %s in %s
(W) The same, but in ANSI_COLORS_ALIASES. The color mapping was ignored.
Invalid alias name %s
(F) You passed an invalid alias name to coloralias(). Alias names must consist only of alphanumerics, ".", "-", and "_".
Invalid alias name %s in %s
(W) You specified an invalid alias name on the left hand of the equal sign in a color mapping in ANSI_COLORS_ALIASES. The color mapping was ignored.
Invalid attribute name %s
(F) You passed an invalid attribute name to color(), colored(), or coloralias().
Invalid attribute name %s in %s
(W) You specified an invalid attribute name on the right hand of the equal sign in a color mapping in ANSI_COLORS_ALIASES. The color mapping was ignored.
Name "%s" used only once: possible typo
(W) You probably mistyped a constant color name such as: 
print FOOBAR "This text is color FOOBAR\n";

It's probably better to always use commas after constant names in order to force the next error.

No comma allowed after filehandle
(F) You probably mistyped a constant color name such as: 
print FOOBAR, "This text is color FOOBAR\n";

Generating this fatal compile error is one of the main advantages of using the constants interface, since you'll immediately know if you mistype a color name.

No name for escape sequence %s
(F) The ANSI escape sequence passed to uncolor() contains escapes which aren't recognized and can't be translated to names.

ENVIRONMENT

ANSI_COLORS_ALIASES
This environment variable allows the user to specify custom color aliases that will be understood by color(), colored(), and colorvalid(). None of the other functions will be affected, and no new color constants will be created. The custom colors are aliases for existing color names; no new escape sequences can be introduced. Only alphanumerics, ".", "_", and "-" are allowed in alias names.

The format is:

ANSI_COLORS_ALIASES='newcolor1=oldcolor1,newcolor2=oldcolor2'

Whitespace is ignored. The alias value can be a single attribute or a space-separated list of attributes.

For example the Solarized https://ethanschoonover.com/solarized colors can be mapped with:

ANSI_COLORS_ALIASES='\
    base00=bright_yellow, on_base00=on_bright_yellow,\
    base01=bright_green,  on_base01=on_bright_green, \
    base02=black,         on_base02=on_black,        \
    base03=bright_black,  on_base03=on_bright_black, \
    base0=bright_blue,    on_base0=on_bright_blue,   \
    base1=bright_cyan,    on_base1=on_bright_cyan,   \
    base2=white,          on_base2=on_white,         \
    base3=bright_white,   on_base3=on_bright_white,  \
    orange=bright_red,    on_orange=on_bright_red,   \
    violet=bright_magenta,on_violet=on_bright_magenta'

This environment variable is read and applied when the Term::ANSIColor module is loaded and is then subsequently ignored. Changes to ANSI_COLORS_ALIASES after the module is loaded will have no effect. See coloralias() for an equivalent facility that can be used at runtime.

ANSI_COLORS_DISABLED
If this environment variable is set to a true value, all of the functions defined by this module (color(), colored(), and all of the constants) will not output any escape sequences and instead will just return the empty string or pass through the original text as appropriate. This is intended to support easy use of scripts using this module on platforms that don't support ANSI escape sequences.
NO_COLOR
If this environment variable is set to any value, it suppresses generation of escape sequences the same as if ANSI_COLORS_DISABLED is set to a true value. This implements the https://no-color.org/ informal standard. Programs that want to enable color despite NO_COLOR being set will need to unset that environment variable before any constant or function provided by this module is used.

COMPATIBILITY

Term::ANSIColor was first included with Perl in Perl 5.6.0.

The uncolor() function and support for ANSI_COLORS_DISABLED were added in Term::ANSIColor 1.04, included in Perl 5.8.0.

Support for dark was added in Term::ANSIColor 1.08, included in Perl 5.8.4.

The color stack, including the ":pushpop" import tag, PUSHCOLOR, POPCOLOR, LOCALCOLOR, and the $Term::ANSIColor::AUTOLOCAL variable, was added in Term::ANSIColor 2.00, included in Perl 5.10.1.

colorstrip() was added in Term::ANSIColor 2.01 and colorvalid() was added in Term::ANSIColor 2.02, both included in Perl 5.11.0.

Support for colors 8 through 15 (the "bright_" variants) was added in Term::ANSIColor 3.00, included in Perl 5.13.3.

Support for italic was added in Term::ANSIColor 3.02, included in Perl 5.17.1.

Support for colors 16 through 256 (the "ansi", "rgb", and "grey" colors), the ":constants256" import tag, the coloralias() function, and support for the ANSI_COLORS_ALIASES environment variable were added in Term::ANSIColor 4.0

NOMBRE

Term::ANSIColor

SINTAXIS

use Term::ANSIColor;

DESCRIPCIÓN

Term::ANSIColor es un módulo Perl que proporciona soporte para colores ANSI y atributos de color. El módulo permite definir colores ANSI, atributos de color como negrita, tenue, subrayado, parpadeo, inverso, oculto, y otros, y permite usar constantes de color, secuencias de escape y atributos de color en formato de texto. Además, el módulo incluye soporte para el modo de color real (rNNNgNNNbNNN y on_rNNNgNNNbNNN), definición de alias en términos de otros alias, y alias que mapean a múltiples atributos en lugar de solo un atributo.

DIAGNÓSTICOS

El módulo incluye diagnósticos para verificar el estado de la terminal, como la compatibilidad de las secuencias de escape ANSI, la compatibilidad de los atributos de color y el comportamiento del módulo en diferentes entornos.

ENTORNOS

El módulo se puede usar en diversos entornos, como el modo de color real, el modo de texto y el modo de secuencia de escape ANSI. El módulo también se puede usar en entornos de terminal como xterm, linux, rxvt, dtterm, teraterm, aixterm, PuTTY, Windows, Cygwin SSH y Terminal.app.

COMPATIBILIDAD

El módulo está diseñado para ser compatible con diversos sistemas operativos y entornos de terminal. El módulo soporta diferentes versiones de Perl y diferentes tipos de terminal.

RESTRICCIONES

El módulo tiene restricciones para el uso de secuencias de escape ANSI, como el uso de la constante NO_COLOR, el manejo de atributos de color y el comportamiento del módulo en diferentes entornos.

NOTAS

El módulo incluye notas sobre el soporte de diferentes atributos de color, como el manejo de secuencias de escape ANSI, el soporte de colores y el comportamiento del módulo en diferentes entornos.

AUTORES

El módulo fue desarrollado por Zenin con una idea inicial usando constantes, reimplementado por Russ Allbery con subs, y combinado con la idea original por Russ con aportaciones de Zenin. El soporte para 256 colores se basa en el trabajo de Kurt Starsinic. Russ Allbery mantiene actualmente este módulo.

VÉASE TAMBIÉN

El módulo Term::ExtendedColor ofrece una interfaz diferente y más completa para emuladores de 256 colores. El módulo Win32::Console::ANSI ofrece soporte para secuencias de escape ANSI en el entorno de consola Win32. El módulo Term::Chrome ofrece una interfaz diferente utilizando objetos y sobreescritura de operadores.

ECMA-048 está disponible en línea (al menos en el momento de escribir esto) en https://www.ecma-international.org/publications/standards/Ecma-048.htm.

ISO 6429 está disponible en ISO por un costo; el autor de este módulo no posee una copia del estándar. Dado que el material fuente del estándar ISO 6429 era ECMA-048 y este último está disponible gratuitamente, parece haber poca razón para obtener el estándar ISO.

Las secuencias de control de 256 colores están documentadas en https://invisible-island.net/xterm/ctlseqs/ctlseqs.html (buscar 256 colores).

La información sobre el soporte de color real en diferentes emuladores de terminal y programas que se pueden ejecutar para verificar el soporte de color real en su emulador están disponibles en https://gist.github.com/XVilka/8346728.

CLICOLORS https://bixense.com/clicolors/ y NO_COLOR https://no-color.org/ son estándares útiles a considerar y seguir por cualquier aplicación que use color. Term::ANSIColor cumple con el segundo.
