NOMBRE

Text::BibTeX::Name - Interfaz para nombres de autor estilo BibTeX

SINOPSIS

use Text::BibTeX::Name;
$name = Text::BibTeX::Name->new();
$name->split('J. Random Hacker');
# o:
$name = Text::BibTeX::Name->new('J. Random Hacker');
@firstname_tokens = $name->part ('first');
$lastname = join (' ', $name->part ('last'));
$format = Text::BibTeX::NameFormat->new();
# ...personalizar $format...
$formatted = $name->format ($format);

DESCRIPCIÓN

"Text::BibTeX::Name" proporciona una abstracción para nombres estilo BibTeX y algunas operaciones básicas sobre ellos. Un nombre, en el mundo BibTeX, consiste en una lista de tokens que se dividen en cuatro partes: `first', `von', `last' y `jr'.

Los tokens están separados por espacios en blanco o comas a nivel de llave cero. Por lo tanto, el nombre

van der Graaf, Horace Q.

tiene cinco tokens, mientras que el nombre

{Foo, Bar, and Sons}

consiste en un solo token. Desplácese hacia abajo hasta "EJEMPLOS" para ver más ejemplos, o siga leyendo si desea conocer los detalles exactos de cómo los nombres se dividen en tokens y partes.

Cómo los tokens se dividen en partes depende de la forma del nombre. Si el nombre no tiene comas a nivel de llave cero (como en el segundo ejemplo), entonces se asume que está en forma "first last" o "first von last". Si no hay tokens que comiencen con una letra minúscula, entonces se asume la forma "first last": el token final es el apellido, y todos los demás tokens forman el nombre; de lo contrario, la secuencia contigua más temprana de tokens con letras minúsculas iniciales se considera la parte `von'; si esta secuencia incluye el token final, se imprime una advertencia y el token final se fuerza a ser la parte `last'.

Si un nombre tiene una sola coma, entonces se asume que está en forma "von last, first". Una secuencia inicial de tokens con letras minúsculas iniciales, si existe, forma la parte `von'; los tokens entre el `von' y la coma forman la parte `last'; los tokens después de la coma forman la parte `first'. De nuevo, si no hay tokens después de una secuencia inicial de tokens en minúsculas, se imprime una advertencia y el token inmediatamente anterior a la coma se toma como la parte `last'.

Si un nombre tiene más de dos comas, se imprime una advertencia y el nombre se trata como si solo estuvieran presentes las dos primeras comas.

Finalmente, si un nombre tiene dos comas, se asume que está en forma "von last, jr, first". (Esta es la única forma de representar un nombre con una parte `jr'.) El análisis del nombre es el mismo que para un nombre con una coma, excepto que los tokens entre las dos comas se toman como la parte `jr'.

ADVERTENCIA

El código C que realiza el trabajo real de dividir los nombres toma un atajo y hace pocas suposiciones sobre los espacios en blanco. En particular, no debe haber espacios en blanco iniciales, ni finales, ni caracteres de espacio en blanco consecutivos en la cadena, ni caracteres de espacio en blanco que no sean espacios. En otras palabras, todos los espacios en blanco deben consistir en espacios internos solitarios.

EJEMPLOS

Las cadenas "John Smith" y "Smith, John" son representaciones diferentes del mismo nombre, por lo que se dividen en partes y tokens de la misma manera, es decir, como:

first => ('John')
von   => ()
last  => ('Smith')
jr    => ()

Tenga en cuenta que cada parte es una lista de tokens, incluso si solo hay un token en esa parte; las partes vacías obtienen listas de tokens vacías. Cada token es solo una cadena. Escribir este ejemplo en código real es sencillo:

$name = Text::BibTeX::Name->new("John Smith");  # o "Smith, John"
$name->part ('first');       # devuelve la lista ("John")
$name->part ('last');        # devuelve la lista ("Smith")
$name->part ('von');         # devuelve la lista ()
$name->part ('jr');          # devuelve la lista ()

(Omitiremos las partes vacías en el resto de los ejemplos: solo suponga que cualquier parte no mencionada es una lista vacía.) Si se incluyen más de dos tokens y no hay coma, irán al nombre; por lo tanto, "John Q. Smith" se divide en

first => ("John", "Q.")
last  => ("Smith")

y "J. R. R. Tolkein" en

first => ("J.", "R.", "R.")
last  => ("Tolkein")

El nombre ambiguo "Kevin Philips Bong" se divide en

first => ("Kevin", "Philips")
last  => ("Bong")

lo cual puede o no ser lo correcto, dependiendo de la persona en particular. Sin embargo, no hay forma de saberlo, por lo que si el apellido de este individuo es "Philips Bong" y no "Bong", la representación de cadena de su nombre debe desambiguar. Una posibilidad es "Philips Bong, Kevin" que se divide en

first => ("Kevin")
last  => ("Philips", "Bong")

Alternativamente, "Kevin {Philips Bong}" aprovecha el hecho de que los tokens solo se dividen por espacios en blanco a nivel de llave cero, y se convierte en

first => ("Kevin")
last  => ("{Philips Bong}")

lo cual está bien si tus nombres están destinados a ser procesados por TeX, pero podría ser problemático en otros contextos. De manera similar, "St John-Mollusc, Oliver" se convierte en

first => ("Oliver")
last  => ("St", "John-Mollusc")

lo cual también se puede escribir como "Oliver {St John-Mollusc}":

first => ("Oliver")
last  => ("{St John-Mollusc}")

Dado que los tokens se separan puramente por espacios en blanco, los nombres con guiones funcionarán de ambas maneras: tanto "Nigel Incubator-Jones" como "Incubator-Jones, Nigel" resultan en

first => ("Nigel")
last  => ("Incubator-Jones")

Los nombres de familia múltiples con componentes en minúscula — la parte "von" — funcionan bien: tanto "Ludwig van Beethoven" como "van Beethoven, Ludwig" se analizan (correctamente) en

first => ("Ludwig")
von   => ("van")
last  => ("Beethoven")

Esto permite que estos nombres aristocráticos europeos se clasifiquen correctamente, es decir, van Beethoven bajo B en lugar de v. Hablando de nombres aristocráticos europeos, "Charles Louis Xavier Joseph de la Vall{\'e}e Poussin" se maneja muy bien, y se divide en

first => ("Charles", "Louis", "Xavier", "Joseph")
von   => ("de", "la")
last  => ("Vall{\'e}e", "Poussin")

por lo que podría clasificarse bajo V en lugar de d. (Tenga en cuenta que el algoritmo de clasificación en Text::BibTeX::BibSort es una imitación servil de BibTeX 0.99, y por lo tanto hace lo incorrecto con estos nombres: la clave de clasificación comienza con la parte "von".)

Sin embargo, las partes "von" en mayúsculas no funcionan tan bien: "R. J. Van de Graaff" se divide en

first => ("R.", "J.", "Van")
von   => ("de")
last  => ("Graaff")

lo cual es claramente incorrecto. Este nombre debe representarse como "Van de Graaff, R. J."

first => ("R.", "J.")
last  => ("Van", "de", "Graaff")

lo cual es probablemente correcto. (Este Van de Graaff en particular era un estadounidense, por lo que probablemente debería clasificarse bajo V, que es donde mi diccionario (británico) lo pone. Las millas de otros Van de Graaff pueden variar.)

Finalmente, muchos nombres incluyen un sufijo: "Jr.", "III", "fils", etc. Estos se manejan, pero con algunas limitaciones. Si hay una coma antes del sufijo (la convención habitual en EE. UU. para "Jr."), entonces el nombre debe estar en forma last, jr, first, por ejemplo, "Doe, Jr., John" resulta (correctamente) en

first => ("John")
last  => ("Doe")
jr    => ("Jr.")

pero "John Doe, Jr." es ambiguo

Text::BibTeX::Name(3pm)

Text::BibTeX::Name - Parse BibTeX names

    use Text::BibTeX::Name;

    my $name = Text::BibTeX::Name->new( 'von Last, Jr., First' );
    # or
    my $name = Text::BibTeX::Name->new( { binmode => 'utf-8' }, 'von Last, Jr., First' );

    my @first = $name->part( 'first' );
    my @last  = $name->part( 'last' );
    my @jr    = $name->part( 'jr' );
    my @von   = $name->part( 'von' );

    my $name_formatter = Text::BibTeX::NameFormat->new( ... );
    my $formatted_name = $name->format( $name_formatter );

This module is used to parse names in the format used by BibTeX. BibTeX names can be written in either of two forms:

Simple form:
This is the normal way of writing names, e.g. "John Doe". This splits into first and last names.
Separated form:
This is used when you need to specify the order of given names, or when the name contains particles like "von" or "de", or suffixes like "Jr." or "III". The syntax is:
    Last, von First Jr.

For example:

    "Doe, John Jr."
    "Smith, Jr., John"
    "de la Vall{\'e}e Poussin, Charles Louis Xavier Joseph"

If there is no comma before the suffix (e.g. "Gates III, William H."), the suffix is treated as part of the last name.

If there is no comma before the "von" part (e.g. "Charles de la Vall{\'e}e Poussin"), the "von" part is treated as part of the last name.

The following sections describe the parsing strategy in more detail.

BibTeX parsing is a complex topic, and this module doesn't handle every edge case that might be encountered. Specifically, it's hard to distinguish between multi-part last names and given names, or between suffixes and multi-part last names.

For example, the name "Gates, William H. III" is parsed as

first => ("William", "H.")
last  => ("Gates")
jr    => ("III")

but "Gates III, William H." is parsed as

first => ("William", "H.")
last  => ("Gates", "III")

This difference in parsing is due to the comma. If there's no comma before the suffix, then it's assumed to be part of the last name.

Similarly, the name "Doe, Jr., John" is parsed as

first => ("John")
last  => ("Doe")
jr    => ("Jr.")

but "Doe, John Jr." is parsed as

first => ("John")
last  => ("Doe")
jr    => ("Jr.")

So, the comma is essential for distinguishing suffixes.

The "jr" part is parsed only when it follows a comma. If there's no comma before the suffix -- the usual for Roman numerals, and occasionally seen with "Jr." -- then you're stuck and have to make the suffix part of the last name. Thus, "Gates III, William H." comes out

first => ("William", "H.")
last  => ("Gates", "III")

but "William H. Gates III" is ambiguous, and becomes

first => ("William", "H.", "Gates")
last  => ("III")

-- not what you want. Again, the curly-brace trick comes in handy, so "William H. {Gates III}" splits into

first => ("William", "H.")
last  => ("{Gates III}")

There is no way to make a comma-less suffix the "jr" part. (This is an unfortunate consequence of slavishly imitating BibTeX 0.99.)

Finally, names that aren't really names of people but rather are organization or company names should be forced into a single token by wrapping them in curly braces. For example, "Foo, Bar and Sons" should be written "{Foo, Bar and Sons}", which will split as

last  => ("{Foo, Bar and Sons}")

Of course, if this is one name in a BibTeX "authors" or "editors" list, this name has to be wrapped in braces anyways (because of the " and "), but that's another story.

Here are some examples of how names are parsed:

    "Doe, John Jr."
    =>
    first => ("John")
    last  => ("Doe")
    jr    => ("Jr.")

    "Gates III, William H."
    =>
    first => ("William", "H.")
    last  => ("Gates", "III")

    "de la Vall{\'e}e Poussin, Charles Louis Xavier Joseph"
    =>
    first => ("Charles", "Louis", "Xavier", "Joseph")
    von   => ("de", "la")
    last  => ("Vall{\'e}e", "Poussin")

    "Charles Louis Xavier Joseph de la Vall{\'e}e Poussin"
    =>
    first => ("Charles", "Louis", "Xavier", "Joseph")
    last  => ("de", "la", "Vall{\'e}e", "Poussin")

    "John von Doe"
    =>
    first => ("John")
    last  => ("von", "Doe")

    "{Foo, Bar and Sons}"
    =>
    last  => ("{Foo, Bar and Sons}")

    "Jr., John Doe"
    =>
    first => ("John")
    last  => ("Doe")
    jr    => ("Jr.")

Note that the first example is ambiguous. It is parsed as

first => ("Jr.")
last  => ("John", "Doe")

(so don't do it that way). If there's no comma before the suffix -- the usual for Roman numerals, and occasionally seen with "Jr." -- then you're stuck and have to make the suffix part of the last name. Thus, "Gates III, William H." comes out

first => ("William", "H.")
last  => ("Gates", "III")

but "William H. Gates III" is ambiguous, and becomes

first => ("William", "H.", "Gates")
last  => ("III")

-- not what you want. Again, the curly-brace trick comes in handy, so "William H. {Gates III}" splits into

first => ("William", "H.")
last  => ("{Gates III}")

There is no way to make a comma-less suffix the "jr" part. (This is an unfortunate consequence of slavishly imitating BibTeX 0.99.)

Finally, names that aren't really names of people but rather are organization or company names should be forced into a single token by wrapping them in curly braces. For example, "Foo, Bar and Sons" should be written "{Foo, Bar and Sons}", which will split as

last  => ("{Foo, Bar and Sons}")

Of course, if this is one name in a BibTeX "authors" or "editors" list, this name has to be wrapped in braces anyways (because of the " and "), but that's another story.

Putting a split-up name back together again in a flexible, customizable way is the job of another module: see Text::BibTeX::NameFormat.

new([ [OPTS,] NAME [, FILENAME, LINE, NAME_NUM]])
Creates a new "Text::BibTeX::Name" object. If NAME is supplied, it must be a string containing a single name, and it will be be passed to the "split" method for further processing. FILENAME, LINE, and NAME_NUM, if present, are all also passed to "split" to allow better error messages.

If the first argument is a hash reference, it is used to define configuration values. At the moment the available values are:

BINMODE
Set the way Text::BibTeX deals with strings. By default it manages strings as bytes. You can set BINMODE to 'utf-8' to get NFC normalized UTF-8 strings and you can customise the normalization with the NORMALIZATION option. 
Text::BibTeX::Name->new(
       { binmode => 'utf-8', normalization => 'NFD' },
       "Alberto Simões"});
split (NAME [, FILENAME, LINE, NAME_NUM])
Splits NAME (a string containing a single name) into tokens and subsequently into the four parts of a BibTeX-style name (first, von, last, and jr). (Each part is a list of tokens, and tokens are separated by whitespace or commas at brace-depth zero. See above for full details on how a name is split into its component parts.)

The token-lists that make up each part of the name are then stored in the "Text::BibTeX::Name" object for later retrieval or formatting with the "part" and "format" methods.

part (PARTNAME)
Returns the list of tokens in part PARTNAME of a name previously split with "split". For example, suppose a "Text::BibTeX::Name" object is created and initialized like this: 
$name = Text::BibTeX::Name->new();
$name->split ('Charles Louis Xavier Joseph de la Vall{\'e}e Poussin');

Then this code:

$name->part ('von');

would return the list "('de','la')".

format (FORMAT)
Formats a name according to the specifications encoded in FORMAT, which should be a "Text::BibTeX::NameFormat" (or descendant) object. (In short, it must supply a method "apply" which takes a "Text::BibTeX::NameFormat" object as its only argument.) Returns the formatted name as a string.

See Text::BibTeX::NameFormat for full details on formatting names.
