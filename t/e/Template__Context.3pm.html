NOMBRE

Template::Context - Contexto de tiempo de ejecución en el que se procesan las plantillas

SINOPSIS

use Template::Context;
# constructor
$context = Template::Context->new(\%config)
    || die $Template::Context::ERROR;
# obtener (cargar y compilar) una plantilla
$template = $context->template($template_name);
# obtener (cargar e instanciar) un objeto plugin
$plugin = $context->plugin($name, \@args);
# obtener (devolver o crear) una subrutina de filtro
$filter = $context->filter($name, \@args, $alias);
# procesar/incluir una plantilla, los errores se lanzan vía die()
$output = $context->process($template, \%vars);
$output = $context->include($template, \%vars);
# lanzar una excepción vía die()
$context->throw($error_type, $error_message, \$output_buffer);
# capturar una excepción, limpiarla y arreglar el buffer de salida
$exception = $context->catch($exception, \$output_buffer);
# guardar/restaurar el stash para efectuar la localización de variables
$new_stash = $context->localise(\%vars);
$old_stash = $context->delocalise();
# añadir nuevas definiciones de BLOCK o FILTER
$context->define_block($name, $block);
$context->define_filter($name, \&filtersub, $is_dynamic);
# resetear el contexto, vaciando las definiciones de BLOCK importadas
$context->reset();
# métodos para acceder a elementos internos
$stash     = $context->stash();
$tflag     = $context->trim();
$epflag    = $context->eval_perl();
$providers = $context->templates();
$providers = $context->plugins();
$providers = $context->filters();
...

DESCRIPCIÓN

El módulo "Template::Context" define una clase de objeto para representar un contexto de tiempo de ejecución en el que se procesan las plantillas. Proporciona una interfaz para las operaciones fundamentales del motor de procesamiento Template Toolkit a través del cual las plantillas compiladas (es decir, código Perl construido a partir del código fuente de la plantilla) pueden procesar plantillas, cargar plugins y filtros, lanzar excepciones, etc.

Un objeto "Template::Context" por defecto es creado por el módulo Template. Cualquier opción de "Template::Context" puede pasarse al método constructor new() de Template y será reenviada al constructor de "Template::Context".

use Template;
my $template = Template->new({
    TRIM      => 1,
    EVAL_PERL => 1,
    BLOCKS    => {
        header => 'This is the header',
        footer => 'This is the footer',
    },
});

De manera similar, el constructor "Template::Context" reenviará todos los parámetros de configuración a otros objetos por defecto (por ejemplo, Template::Provider, Template::Plugins, Template::Filters, etc.) que pueda necesitar instanciar.

$context = Template::Context->new({
    INCLUDE_PATH => '/home/abw/templates', # opción del proveedor
    TAG_STYLE    => 'html',                # opción del analizador
});

Un objeto "Template::Context" (o subclase) puede ser instanciado explícitamente y pasado al método constructor new() de Template como el elemento de configuración "CONTEXT".

use Template;
use Template::Context;
my $context  = Template::Context->new({ TRIM => 1 });
my $template = Template->new({ CONTEXT => $context });

El módulo Template utiliza el método fábrica context() de Template::Config para crear un objeto de contexto por defecto cuando se requiere. La variable de paquete $Template::Config::CONTEXT puede establecerse para especificar un módulo de contexto alternativo. Este será cargado automáticamente y su método constructor new() será llamado por el método fábrica context() cuando se requiera un objeto de contexto por defecto.

use Template;
$Template::Config::CONTEXT = 'MyOrg::Template::Context';
my $template = Template->new({
    EVAL_PERL   => 1,
    EXTRA_MAGIC => 'red hot',  # tus elementos de configuración adicionales
    ...
});

MÉTODOS

new(\%params)

El método constructor new() se llama para instanciar un objeto "Template::Context". Los parámetros de configuración se pueden especificar como una referencia HASH o como una lista de pares "nombre => valor".

my $context = Template::Context->new({
    INCLUDE_PATH => 'header',
    POST_PROCESS => 'footer',
});
my $context = Template::Context->new( EVAL_PERL => 1 );

El método new() devuelve un objeto "Template::Context" o "undef" en caso de error. En este último caso, se puede recuperar un mensaje de error relevante llamando al método de clase error() o directamente de la variable de paquete $Template::Context::ERROR.

my $context = Template::Context->new(\%config)
    || die Template::Context->error();
my $context = Template::Context->new(\%config)
    || die $Template::Context::ERROR;

Los siguientes elementos de configuración se pueden especificar. Consulte Template::Manual::Config para más detalles.

VARIABLES

La opción VARIABLES se puede usar para especificar un array hash de variables de plantilla.

my $context = Template::Context->new({
    VARIABLES => {
        title   => 'Una Página de Demostración',
        author  => 'Joe Hacker Aleatorio',
        version => 3.14,
    },
};

BLOCKS

La opción BLOCKS se puede usar para predefinir un conjunto por defecto de bloques de plantilla.

my $context = Template::Context->new({
    BLOCKS => {
        header  => 'El Encabezado.  [% title %]',
        footer  => sub { return $some_output_text },
        another => Template::Document->new({ ... }),
    },
});

VIEWS

La opción VIEWS se puede usar para predefinir uno o más objetos Template::View.

my $context = Template::Context->new({
    VIEWS => [
        bottom => { prefix => 'bottom/' },
        middle => { prefix => 'middle/', base => 'bottom' },
        top    => { prefix => 'top/',    base => 'middle' },
    ],
});

TRIM

La opción TRIM se puede establecer para eliminar automáticamente cualquier espacio en blanco inicial y final de la salida de todos los archivos de plantilla y bloques "BLOCK".

ejemplo:

[% BLOCK foo %]
Línea 1 de foo
[% END %]
antes
[% INCLUDE foo %]
después

salida:

antes
Línea 1 de foo
después

EVAL_PERL

EVAL_PERL se usa para indicar si los bloques "PERL" y/o "RAWPERL" deben ser evaluados. Está deshabilitado por defecto.

RECURSION

RECURSION se puede establecer para permitir que las plantillas se procesen recursivamente a sí mismas, ya sea directa (por ejemplo, la plantilla "foo" llama a "INCLUDE foo") o indirectamente (por ejemplo, "foo" llama a "INCLUDE bar" que llama a "INCLUDE foo").

LOAD_TEMPLATES

La opción LOAD_TEMPLATES se puede usar para proporcionar una referencia a una lista de objetos Template::Provider o sus subclases que se harán responsables de cargar y compilar plantillas.

my $context = Template::Context->new({
    LOAD_TEMPLATES => [
        MyOrg::Template::Provider->new({ ... }),
        Template::Provider->new({ ... }),
    ],
});

LOAD_PLUGINS

La opción LOAD_PLUGINS se puede usar para especificar una lista de objetos proveedores responsables de cargar e instanciar objetos plugin de plantillas.

my $context = Template::Context->new({
    LOAD_PLUGINS => [
        MyOrg::Template::Plugins->new({ ... }),
        Template::Plugins->new({ ... }),
    ],
});

LOAD_FILTERS

La opción LOAD_FILTERS se puede usar para especificar una lista de objetos proveedores para devolver y/o crear subrutinas de filtro.

my $context = Template::Context->new({
    LOAD_FILTERS => [
        MyTemplate::Filters->new(),
        Template::Filters->new(),
    ],
});

STASH

La opción STASH se puede usar para especificar un objeto Template::Stash o una subclase que se hará responsable de gestionar las variables de plantilla.

my $stash = MyOrg::Template::Stash->new({ ... });
my $context = Template::Context->new({
    STASH => $stash,
});

DEBUG

La opción DEBUG se puede usar para habilitar varias funciones de depuración del módulo Template::Context.

use Template::Constants qw( :debug );
my $template = Template->new({
    DEBUG => DEBUG_CONTEXT | DEBUG_DIRS,
});

plantilla($nombre)

Devuelve una plantilla compilada consultando cada uno de los proveedores de LOAD_TEMPLATES (instancias de Template::Provider, o sub-clases).

$plantilla = $contexto->plantilla('encabezado');

En caso de error, se lanza un objeto Template::Exception de tipo '"archivo"' por medio de die(). Este puede capturarse envolviendo la llamada a plantilla() en un bloque "eval" y examinando $@.

eval { $plantilla = $contexto->plantilla('encabezado') };
if ($@) {
    print "fallo al obtener plantilla: $@\n";
}

plugin($nombre, \@argumentos)

Instancia un objeto plugin consultando cada uno de los proveedores de LOAD_PLUGINS (instancias de Template::Plugins). El proveedor predeterminado de LOAD_PLUGINS es un objeto Template::Plugins que intenta cargar módulos de plugin según los diversos elementos de configuración, como PLUGIN_BASE, LOAD_PERL, etc., y luego instancia un objeto mediante new(). Se puede pasar como segundo parámetro un referencia a un lista de argumentos de constructor. Estos se pasan al constructor del plugin.

Devuelve una referencia a un plugin (que generalmente es un objeto, pero no tiene que serlo). Los errores se lanzan como objetos Template::Exception con el tipo '"plugin"'.

$plugin = $contexto->plugin('DBI', 'dbi:msql:nombredemibase');

filtro($nombre, \@argumentos, $alias)

Instancia una subrutina de filtro consultando los proveedores de LOAD_FILTERS. El proveedor predeterminado de LOAD_FILTERS es un objeto Template::Filters.

Se pueden pasar argumentos adicionales como referencia de lista junto con un alias opcional bajo el cual se cachará la subrutina para su uso posterior. Si $alias es indefinido, la subrutina se cachará bajo su propio $nombre. Las llamadas posteriores a filtro($nombre) devolverán el registro cacheado si está definido. Específicamente, los argumentos bypassan el mecanismo de caché y siempre crean una nueva subrutina. Los errores se lanzan como objetos Template::Exception con el tipo '"filtro"'.

# filtro estático (sin argumentos)
$filtro = $contexto->filtro('html');
# filtro dinámico (argumentos) aliasado a 'relleno_derecha'
$filtro = $contexto->filtro('formato', '%60s', 'relleno_derecha');
# recuperar filtro anterior mediante alias 'relleno_derecha'
$filtro = $contexto->filtro('relleno_derecha');

procesar($plantilla, \%vars)

Procesa una plantilla nombrada o referida por el primer parámetro y devuelve la salida generada. Se puede pasar como segundo parámetro una referencia a un array asociativo de variables que se establecerán antes de procesar la plantilla. La plantilla se procesa en el contexto actual, sin localizar las variables. Los errores se lanzan como objetos Template::Exception por medio de die().

$salida = $contexto->procesar('encabezado', { titulo => 'Hola Mundo' });

incluir($plantilla, \%vars)

Similar a procesar(), pero usando variables localizadas. Las modificaciones a cualquier variable persisten solo hasta que se complete el método incluir().

$salida = $contexto->incluir('encabezado', { titulo => 'Hola Mundo' });

insertar($plantilla)

Este método devuelve el contenido fuente de un archivo de plantilla sin realizar ninguna evaluación. Se usa para implementar la directiva "INSERTAR".

lanzar($tipo_error, $mensaje_error, \$salida)

Lanza una excepción en forma de un objeto Template::Exception al llamar a die(). Este método puede pasar una referencia a un objeto existente de Template::Exception; un valor único con un mensaje de error que se usa para instanciar un objeto Template::Exception de tipo '"undef"'; o un par de valores representando el tipo y la información de la excepción, de la cual se instancia un objeto Template::Exception. Por ejemplo:

$contexto->lanzar($excepcion);
$contexto->lanzar("Lo siento Dave, no puedo hacer eso");
$contexto->lanzar('denegado', "Lo siento Dave, no puedo hacer eso");

El tercer parámetro opcional puede ser una referencia al buffer de salida actual. Este se almacena en el objeto de excepción cuando se crea, permitiendo al capturador examinar y usar el contenido de la salida hasta el punto en que la excepción fue lanzada.

$salida .= 'blah blah blah';
$salida .= 'más parloteo';
$contexto->lanzar('asco', 'Demasiado parloteo', \$salida);

capturar($excepcion, \$salida)

Captura una excepción lanzada, ya sea como una referencia a un objeto Template::Exception o algún otro valor. En el caso de este último, el mensaje de error se promociona a un objeto Template::Exception de tipo '"undef"'. Este método también acepta una referencia al buffer de salida actual que se pasa al constructor de Template::Exception, o se agrega al buffer de salida almacenado en un objeto existente de Template::Exception, si es único (es decir, no es la misma referencia). Por medio de este proceso, se puede reconstruir correctamente el estado del buffer de salida para lanzamientos simples o anidados.

definir_bloque($nombre, $bloque)

Añade una definición nueva de bloque a la caché interna de BLOQUES. El primer argumento debe contener el nombre del bloque y el segundo una referencia a un objeto Template::Document o una subrutina de plantilla, o texto de plantilla que se compila automáticamente en una subrutina de plantilla.

Devuelve un valor verdadero (la subrutina o referencia a Template::Document) en caso de éxito o undef en caso de fallo. El mensaje de error relevante se puede recuperar llamando al método error().

definir_filtro($nombre, \&filtro, $es_dinamico)

Añade una definición nueva de filtro llamando al método almacenar() en cada uno de los proveedores de LOAD_FILTERS hasta que sea aceptado (en el caso usual, este se acepta inmediatamente por el único proveedor Template::Filters). El primer argumento debe contener el nombre del filtro y el segundo una referencia a una subrutina de filtro. El argumento opcional tercero puede ser cualquier valor verdadero para indicar que la subrutina es un fabricante de filtros dinámicos.

Devuelve un valor verdadero o lanza una excepción '"filtro"' en caso de error.

definir_vmetodo($tipo, $nombre, $codigo)

Este método es un wrapper al método definir_vmetodo() de Template::Stash. Puede usarse para definir nuevos métodos virtuales.

# definir una nueva subrutina (item) virtual
$contexto->definir_vmetodo(
    item => ucfirst => sub {
        my $texto = shift;
        return ucfirst $texto;
    }
)

definir_vista($nombre, \%parametros)

Este método permite definir una vista nombrada.

$contexto->definir_vista(
    mi_vista => {
        prefijo => 'mis_plantillas/'
    }
);

La vista se accede como una variable de plantilla.

[% mi_vista.imprimir(algunos_datos) %]

definir_vistas($vistas)

Este método permite definir múltiples vistas nombradas. Se debe pasar como argumento una referencia a un array asociativo o lista de referencias.

$contexto->definir_vista({     # array asociativo
    mi_vista_uno => {
        prefijo => 'mis_plantillas_uno/'
    },
    mi_vista_dos => {
        prefijo => 'mis_plantillas_dos/'
    }
});

Si estás definiendo múltiples vistas de las cuales una o más están basadas en otras vistas dentro de la misma definición, deberías pasarlas como una referencia de lista. Esto asegura que se creen en el orden correcto (Perl no mantiene el orden de los elementos definidos en un array asociativo, por lo que no puedes garantizar que tu vista de clase base se defina antes que tu vista de clase derivada).

$contexto->definir_vista([     # referencia de lista
    mi_vista_uno => {
        prefijo => 'mis_plantillas_uno/'
    },
    mi_vista_dos => {
        prefijo => 'mis_plantillas_dos/',
        base   => 'mi_vista_uno',
    }
]);

Las vistas se acceden como variables de plantilla.

[% mi_vista_uno.imprimir(algunos_datos) %]
[% mi_vista_dos.imprimir(algunos_datos) %]

Ver también la opción VIEWS.

stash()

Este método devuelve el objeto Template::Stash utilizado internamente para gestionar las variables de plantilla.

localizar(\%vars)

Copia el stash para crear un contexto con variables localizadas. Devuelve una referencia al nuevo stash copiado que también se almacena internamente.

$stash = $contexto->localizar();

delocalise()

Restaura el stash a su estado anterior a la localización.

$stash = $contexto->delocalizar();

visitar(\%bloques)

Este método se llama por objetos Template::Document inmediatamente antes de procesar su contenido. Se llama para registrar cualquier definición local de "BLOQUE" con el objeto contexto así que puedan ser entregados posteriormente.

leave()

Complemento al método visitar(). Se llama por Template::D

Template::Context(3pm) - Arch Linux Man Pages

NAME

Template::Context - Manages the template processing context

SYNOPSIS

    use Template::Context;

    # create a new context object
    my $context = Template::Context->new( ... );

    # retrieve the stash object
    my $stash = $context->stash;

    # ... process templates ...

    # manage BLOCKs
    $context->define_block( ... );
    $context->undef_block( ... );

    # retrieve view object
    my $view = $context->view;

    # control debugging
    $context->debugging( on => 1 );
    $context->debugging( format => '...' );
    $context->debugging( msg => { ... } );

DESCRIPTION

The Template::Context class encapsulates the context in which a template is processed. This includes the stash (variable store), the provider (for loading templates and filters), configuration flags, and any plugin objects loaded.

The context object is created internally by the Template::Service object when a template is compiled and is passed down to all processing stages, including compiled template subroutines, filters, plugins, and various utility methods.

METHODS

new(%args)

Constructor for the Template::Context class.

The following arguments are supported:

stash
A Template::Stash object to use for variable lookup. If not provided, a default one will be created.
provider
A Template::Provider object used to load templates, filters and plugins. If not provided, a default one will be created.
config
A hash reference containing configuration items such as INCLUDE_PATH, ABSOLUTE, COMPILE_DIR, etc.
plugin
A hash reference mapping plugin names to plugin class names or objects. These are loaded via the provider when first accessed.
filters
A hash reference mapping filter names to filter subroutine references or objects.
blocks
A hash reference mapping block names to subroutine references. These are pre-defined blocks that can be invoked using the BLOCK directive.
constants
A hash reference mapping constant names to their values.
trim
A boolean flag. If true, whitespace is automatically trimmed from the start and end of template blocks.
eval_perl
A boolean flag. If true, the PERL directive is enabled, allowing arbitrary Perl code to be executed.
auto_create
A boolean flag. If true, any undefined variables or blocks accessed will be automatically created with a default value (e.g. undef for variables, empty string for blocks).
debug
A boolean flag. If true, debugging output is enabled.
die_on_undef
A boolean flag. If true, the template engine will die() if it encounters an undefined variable or block.
error
A Template::Exception object or one of its subclasses. Used to report errors during template processing.

stash()

Returns the Template::Stash object used by this context.

provider()

Returns the Template::Provider object used by this context.

define_block( NAME, CODEREF )

Registers a named block subroutine (CODEREF) with the context under the name NAME. This allows the block to be invoked using the BLOCK directive.

The subroutine should accept a single argument, the Template::Context object, and return the block's rendered output.

undef_block( NAME )

Removes the definition of a named block from the context.

config( ITEM )

Returns the value of the specified configuration ITEM.

set_trim( FLAG )

Sets the trim flag to FLAG (a boolean value).

trim()

Returns the current value of the trim flag.

set_eval_perl( FLAG )

Sets the eval_perl flag to FLAG (a boolean value).

eval_perl()

Returns the current value of the eval_perl flag.

set_auto_create( FLAG )

Sets the auto_create flag to FLAG (a boolean value).

auto_create()

Returns the current value of the auto_create flag.

set_die_on_undef( FLAG )

Sets the die_on_undef flag to FLAG (a boolean value).

die_on_undef()

Returns the current value of the die_on_undef flag.

error( [EXCEPTION] )

Retrieves or sets the current error object associated with the context.

warn( MESSAGE )

Issues a warning message related to the current template processing.

debug( [FLAG], [@args] )

Enables/disables and controls the debugging output for the template processing.

If FLAG is 'on' or 1, debugging is enabled. If it's 'off' or 0, debugging is disabled.

If FLAG is 'format', the subsequent argument must be a string specifying the debug message format. The format string can contain placeholders like $file, $line, and $text.

If FLAG is 'msg', the subsequent argument must be a hash reference containing the values for the debug message placeholders (file, line, text).

plugin( NAME, [ARGS] )

Loads and returns a plugin object named NAME. If ARGS are provided, they are passed to the plugin's constructor.

filter( NAME, [ARGS] )

Loads and returns a filter object or subroutine named NAME. If ARGS are provided, they are passed to the filter's constructor or initialization.

call_plugin( NAME, [ARGS] )

Calls a method NAME on a loaded plugin object, passing ARGS.

call_filter( NAME, TEXT, [ARGS] )

Applies a filter named NAME to the given TEXT, passing optional ARGS.

define_block( NAME, CODEREF )

Defines a block named NAME using the subroutine reference CODEREF. This block can then be invoked using the BLOCK directive.

undef_block( NAME )

Removes the definition of a block named NAME.

view()

This method creates a Template::View object bound to the context.

reset()

Clears the local BLOCKS cache of any "BLOCK" definitions. Any initial set of BLOCKS specified as a configuration item to the constructor will be reinstated.

debugging($flag, @args)

This method is used to control debugging output. It is used to implement the DEBUG directive.

The first argument can be "on" or "off" to enable or disable debugging respectively. The numerical values 0 and 1 can also be used if you prefer.

$context->debugging('on');

Alternately, the first argument can be "format" to define a new debug message format. The second argument should be the format string which can contain any of the $file, $line or $text symbols to indicate where the relevant values should be inserted.

# note single quotes to prevent interpolated of variables
$context->debugging( format => '## $file line $line: $text' );

The final use of this method is to generate debugging messages themselves. The first argument should be "msg", followed by a reference to a hash array of value to insert into the debugging format string.

$context->debugging(
    msg => {
        line => 20,
        file => 'example.tt',
        text => 'Trampoline! Trampoline!',
    }
);

AUTOLOAD

An "AUTOLOAD" method provides access to context configuration items.

$tflag     = $context->trim();
$epflag    = $context->eval_perl();
