Test2::Tools::Compare(3perl) Guía de referencia del programador de Perl Test2::Tools::Compare(3perl)

NOMBRE

Test2::Tools::Compare - Herramientas para comparar estructuras de datos profundas.

DESCRIPCIÓN

Test::More tenía is_deeply(). Esta biblioteca es la versión de Test2 que se puede usar para comparar estructuras de datos, pero va un paso más allá al proporcionar herramientas para construir una especificación de estructura de datos contra la cual se pueden verificar los datos. Existen versiones 'estrictas' y 'relajadas' de las herramientas.

SINOPSIS

use Test2::Tools::Compare;
# Hash para fines de demostración
my $some_hash = {a => 1, b => 2, c => 3};
# Verificación estricta, todo debe coincidir
is(
    $some_hash,
    {a => 1, b => 2, c => 3},
    "El hash que obtuvimos coincide con nuestras expectativas"
);
# Verificación relajada, solo se verifican los campos que nos interesan, y podemos
# usar una expresión regular para aproximar un campo.
like(
    $some_hash,
    {a => 1, b => qr/\A[0-9]+\z/},
    "'a' es 1, 'b' es un entero, no nos importa 'c'."
);

AVANZADO

Se ofrecen creadores declarativos de hash, array y objetos que permiten generar especificaciones. Son más verbosos que simplemente proporcionar un hash, pero tienen la ventaja de que cada componente que se especifica tiene un número de línea asociado. Esto es útil para la depuración, ya que la salida de error le dirá no solo qué campo fue incorrecto, sino también la línea en la que declaró el campo.

use Test2::Tools::Compare qw{
    is like isnt unlike
    match mismatch validator
    hash array bag object meta number float rounded within string subset bool
    in_set not_in_set check_set
    item field call call_list call_hash prop check all_items all_keys all_vals all_values
    etc end filter_items
    T F D DF E DNE FDNE U L
    event fail_events
    exact_ref
};
is(
    $some_hash,
    hash {
        field a => 1;
        field b => 2;
        field c => 3;
    },
    "El hash coincide con la especificación"
);

HERRAMIENTAS DE COMPARACIÓN

$bool = is($got, $expect)
$bool = is($got, $expect, $name)
$bool = is($got, $expect, $name, @diag)
$got es la estructura de datos que desea comprobar. $expect es lo que desea que $got se parezca. $name es un nombre opcional para la prueba. @diag son mensajes de diagnóstico opcionales que se imprimirán en STDERR en caso de fallo, no se mostrarán cuando la comparación sea exitosa. Se devuelve el resultado booleano verdadero/falso de la comparación.

Este es el verificador estricto. El verificador estricto requiere una coincidencia perfecta entre $got y $expect. Todos los campos de hash deben estar especificados, todos los elementos del array deben estar presentes, etc. Todas las referencias no escalares/hash/array/expresiones regulares deben ser idénticas (misma dirección de memoria). Las referencias escalares, de hash y de array se recorrerán y compararán. Las referencias de expresiones regulares se compararán para ver si tienen el mismo patrón.

is(
    $some_hash,
    {a => 1, b => 2, c => 3},
    "El hash que obtuvimos coincide con nuestras expectativas"
);

La única excepción a la estrictez es cuando se le proporciona un objeto $expect que fue construido a partir de una especificación, en cuyo caso la especificación determina la estrictez. La estrictez solo se aplica a valores/referencias literales que se proporcionan y se convierten en una especificación para usted.

is(
    $some_hash,
    hash {    # Nota: la función hash no se exporta por defecto
        field a => 1;
        field b => match(qr/\A[0-9]+\z/);    # Nota: La función match no se exporta por defecto
        # No nos importan otros campos.
    },
    "La comparación del hash no es estricta"
);

Esto funciona tanto para estructuras profundas como superficiales. Por ejemplo, puede usar esto para comparar dos cadenas:

is('foo', 'foo', "las cadenas coinciden");

Nota: Esta no es la herramienta a usar si desea comprobar si dos referencias son exactamente la misma referencia, use ref_is() del plugin Test2::Tools::Ref en su lugar. La *mayoría* de las veces esto funcionará bien, sin embargo, hay problemas si su referencia contiene un ciclo y se refiere a sí misma en algún momento. Si esto sucede, se lanzará una excepción para romper una recursión de lo contrario infinita.

Nota: Los valores no de referencia se compararán como cadenas usando "eq", lo que significa que las cadenas '2.0' y '2' no coincidirán, pero los números 2.0 y 2 sí, ya que ambos se convertirán a cadena como '2'.

$bool = isnt($got, $expect)
$bool = isnt($got, $expect, $name)
$bool = isnt($got, $expect, $name, @diag)
Lo opuesto a is(). Realiza todas las mismas comprobaciones, pero pasa cuando hay una falta de coincidencia.
$bool = like($got, $expect)
$bool = like($got, $expect, $name)
$bool = like($got, $expect, $name, @diag)
$got es la estructura de datos que desea comprobar. $expect es lo que desea que $got se parezca. $name es un nombre opcional para la prueba. @diag son mensajes de diagnóstico opcionales que se imprimirán en STDERR en caso de fallo, no se mostrarán cuando la comparación sea exitosa. Se devuelve el resultado booleano verdadero/falso de la comparación.

Este es el verificador relajado. Ignorará las claves de hash o los índices de array que no especifique realmente en su estructura $expect. Además, se utilizarán expresiones regulares y referencias de subrutinas como validadores. Si proporciona una expresión regular usando "qr/.../", la expresión regular en sí se utilizará para validar el valor correspondiente en la estructura $got. Lo mismo ocurre con los coderefs, el valor se pasa como primer argumento (y en $_) y la subrutina debe devolver un valor booleano. En esta herramienta, las expresiones regulares convertirán a cadena lo que están comprobando.

like(
    $some_hash,
    {a => 1, b => qr/\A[0-9]+\z/},
    "'a' es 1, 'b' es un entero, no nos importan otros campos"
);

Esto funciona tanto para estructuras profundas como superficiales. Por ejemplo, puede usar esto para comparar dos cadenas:

like('foo bar', qr/^foo/, "la cadena coincide con el patrón");
$bool = unlike($got, $expect)
$bool = unlike($got, $expect, $name)
$bool = unlike($got, $expect, $name, @diag)
Lo opuesto a like(). Realiza todas las mismas comprobaciones, pero pasa cuando hay una falta de coincidencia.

Las funciones is(), isnt(), like() y unlike() pueden hacer que vuelquen $got usando Data::Dumper cuando fallan las pruebas, estableciendo la variable de entorno "T2_AUTO_DUMP" a "1". (Alternativamente, "T2_AUTO_DUMP" puede establecerse al nombre de un módulo Perl que proporcione un método Dump() compatible.) La variable de entorno "T2_AUTO_DEPARSE" se puede usar para habilitar la deconstrucción de coderefs de Data::Dumper.

DNE()

  
Se puede usar con "item" o
      "field" para asegurar que el campo hash o
      el índice de array no existen. También se puede usar con
      "call" para asegurar que un método no
      existe.

Activa la comprobación estricta de arrays/hashes, asegurando que no haya
      claves/índices adicionales presentes.

Ignora cualquier elemento adicional encontrado en el hash/array. Esto es lo
      contrario de end(). Esto se puede usar en cualquier
      lugar del constructor, aunque típicamente se coloca al final.

CONSTRUCTORES DE EVENTOS

Nota: Ninguno de estos se exporta por defecto. Necesitas solicitarlos.

Comprueba que obtuvimos un evento del tipo especificado:

my $check = event 'Ok';

Comprueba los detalles del evento:

my $check = event Ok => sub {
    # Comprueba un fallo
    call pass => 0;
    # Pase efectivo después de contabilizar TODO/SKIP.
    call effective_pass => 1;
    # Comprueba los diagnósticos
    call diag => [ match qr/Failed test foo/ ];
    # Comprueba el archivo al que reporta el evento
    prop file => 'foo.t';
    # Comprueba el número de línea al que reporta el evento
    prop line => '42';
    # También puedes comprobar los valores de todo/skip:
    prop skip => 'broken';
    prop todo => 'fixme';
    # ID de hilo y ID de proceso donde se generó el evento
    prop tid => 123;
    prop pid => 123;
};

También puedes proporcionar un paquete de evento completamente calificado con el prefijo '+' :

my $check = event '+My::Event' => sub { ... }

También puedes proporcionar un hashref en lugar de un sub para comprobar directamente los valores hash del evento:

my $check = event Ok => { pass => 1, ... };

USO EN OTROS CONSTRUCTORES

Puedes usar estos en otros constructores, simplemente úsalos en contexto void para que sus valores se añadan a la construcción.

my $check = array {
    event Ok => { ... };
    event Note => { ... };
    fail_events Ok => { pass => 0 };
    # Obtén un Diag gratis.
};

ESPECIFICACIONES

$check = event $TYPE;
$check = event $TYPE => sub { ... };
$check = event $TYPE => { ... };
Esto funciona igual que un constructor de objetos. Además de admitir todo lo que admite la comprobación de objetos, también debes especificar el tipo de evento, y muchas meta-propiedades adicionales están disponibles.

Las propiedades adicionales son:

'file'
Nombre del archivo al que reporta el evento (para uso en diagnósticos).
'line'
Número de línea al que reporta el evento (para uso en diagnósticos).
'package'
Paquete al que reporta el evento (para uso en diagnósticos).
'subname'
Sub que se llamó para generar el evento (ejemplo: ok()).
'skip'
Establecido al valor de skip si el resultado se generó omitiendo pruebas.
'todo'
Establecido al valor de todo si TODO se estableció cuando se generó el evento.
'trace'
La cadena "at file foo.t line 42" que se usará en los diagnósticos.
'tid'
ID de hilo en el que se generó el evento.
'pid'
ID de proceso en el que se generó el evento.

NOTA: Las comprobaciones de eventos tienen un etc() implícito añadido. Esto significa que necesitas usar end() si quieres fallar en claves hash o índices de array inesperados. Este etc() implícito se extiende a todas las formas, incluyendo constructor, hashref y sin argumentos.

@checks = fail_events $TYPE;
@checks = fail_events $TYPE => sub { ... };
@checks = fail_events $TYPE => { ... };
Igual que event() documentado arriba. La diferencia es que esto produce dos eventos, el que especificas y un "Diag" después de él. No hay comprobaciones adicionales en el Diag.

Usa esto para validar un fallo simple donde no quieres molestarte con los diagnósticos predeterminados. Solo añade una única comprobación de Diag, así que si tu fallo tiene diagnósticos personalizados, necesitarás añadir comprobaciones para ellos.

NAME

Test2::Tools::Compare - Compare values

DESCRIPTION

This module provides a generic comparison tool. It is used internally by Test2.

The primary function is "compare". It takes two arguments, the expected and the actual value, and returns a Test2::Compare::Result object.

The comparison logic is pluggable and can be extended with custom comparators.

SYNOPSIS

use Test2::Tools::Compare qw(compare);

my $result = compare( $expected, $actual );

if ( $result->is_eq ) {
    print "Values are equal!\n";
} else {
    print "Values are not equal:\n";
    print $result->diag;
}

COMPARISON TOOLS

This module ships with several built-in comparison tools:

  • Basic types: Scalars, arrays, hashes are compared by value.

  • Objects: Objects are compared by reference by default. You can override this by implementing an "is_eq" method on your object.

  • References: References are dereferenced and their contents are compared.

  • Subroutines: Subroutines are compared by reference.
