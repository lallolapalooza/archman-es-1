NOMBRE

Text::Template - Expande texto de plantilla con Perl incrustado

VERSIÓN

versión 1.61

SINOPSIS

use Text::Template;
$template = Text::Template->new(TYPE => 'FILE',  SOURCE => 'nombre_archivo.tmpl');
$template = Text::Template->new(TYPE => 'ARRAY', SOURCE => [ ... ] );
$template = Text::Template->new(TYPE => 'FILEHANDLE', SOURCE => $fh );
$template = Text::Template->new(TYPE => 'STRING', SOURCE => '...' );
$template = Text::Template->new(PREPEND => q{use strict;}, ...);
# Usa una sintaxis de archivo de plantilla diferente:
$template = Text::Template->new(DELIMITERS => [$abrir, $cerrar], ...);
$destinatario = 'Rey';
$texto = $template->fill_in();  # Reemplaza `{$destinatario}' con `Rey'
print $texto;
$T::destinatario = 'Josh';
$texto = $template->fill_in(PACKAGE => T);
# Pasa muchas variables explícitamente
$hash = { destinatario => 'Abed-Nego',
          amigos => [ 'yo', 'tú' ],
          enemigos => { detestable => 'Saruman',
                       temible => 'Sauron' },
        };
$texto = $template->fill_in(HASH => $hash, ...);
# $destinatario es Abed-Nego,
# @amigos es ( 'yo', 'tú' ),
# %enemigos es ( detestable => ..., temible => ... )
# Llama a &callback en caso de errores de programación en la plantilla
$texto = $template->fill_in(BROKEN => \&callback, BROKEN_ARG => $ref, ...);
# Evalúa fragmentos de programa en un compartimento seguro (Safe) con permisos restringidos
$texto = $template->fill_in(SAFE => $compartimento, ...);
# Imprime el texto resultante en lugar de devolverlo
$exito = $template->fill_in(OUTPUT => \*FILEHANDLE, ...);
# Analiza la plantilla con una sintaxis de archivo de plantilla diferente:
$texto = $template->fill_in(DELIMITERS => [$abrir, $cerrar], ...);
# Nota que esto es *más rápido* que usar los delimitadores predeterminados
# Añade código perl especificado al principio de cada fragmento antes de evaluarlo:
$texto = $template->fill_in(PREPEND => q{use strict 'vars';}, ...);
use Text::Template 'fill_in_string';
$texto = fill_in_string( <<'EOM', PACKAGE => 'T', ...);
Estimado {$destinatario},
Páguese de inmediato.
       Con amor, 
        G.V.
EOM
use Text::Template 'fill_in_file';
$texto = fill_in_file($nombre_archivo, ...);
# Todas las plantillas siempre tendrán `use strict vars' adjunto a todos los fragmentos
Text::Template->always_prepend(q{use strict 'vars';});

DESCRIPCIÓN

Esta es una biblioteca para generar cartas modelo, construir páginas HTML o rellenar plantillas en general. Una 'plantilla' es un trozo de texto que tiene pequeños programas Perl incrustados aquí y allá. Cuando `rellenas' una plantilla, evalúas los pequeños programas y los reemplazas con sus valores.

Puedes almacenar una plantilla en un archivo fuera de tu programa. Las personas pueden modificar la plantilla sin modificar el programa. Puedes separar los detalles de formato del código principal, y poner las partes de formato del programa en la plantilla. Eso previene la hinchazón del código y fomenta la separación funcional.

Ejemplo

Aquí hay un ejemplo de una plantilla, que supondremos que está almacenada en el archivo "formletter.tmpl":

Estimado {$titulo} {$apellido},
Hemos notado que está moroso en su pago de
{$mes[$ultimo_mes_pagado]}. Por favor, remita
${sprintf("%.2f", $monto)} inmediatamente, o sus rótulas pueden
ser innecesariamente puestas en peligro.
                Con amor,
                Mark "Vizopteryx" Dominus

El resultado de rellenar esta plantilla es una cadena, que podría parecerse a esto:

Estimado Sr. Smith,
Hemos notado que está moroso en su pago de
febrero. Por favor, remita
$392.12 inmediatamente, o sus rótulas pueden
ser innecesariamente puestas en peligro.
                Con amor,
                Mark "Vizopteryx" Dominus

Aquí hay un programa completo que transforma la plantilla de ejemplo en el resultado de ejemplo, y lo imprime:

use Text::Template;
my $template = Text::Template->new(SOURCE => 'formletter.tmpl')
  or die "No se pudo construir la plantilla: $Text::Template::ERROR";
my @mes = qw(Enero Febrero Marzo Abril Mayo Junio
             Julio Agosto Septiembre Octubre Noviembre Diciembre);
my %vars = (titulo           => 'Sr.',
            nombre           => 'John',
            apellido        => 'Smith',
            ultimo_mes_pagado => 1,   # Febrero
            monto          => 392.12,
            mes       => \@mes);
my $resultado = $template->fill_in(HASH => \%vars);
if (defined $resultado) { print $resultado }
else { die "No se pudo rellenar la plantilla: $Text::Template::ERROR" }

Filosofía

Cuando las personas crean un módulo de plantillas como este, casi siempre empiezan inventando una sintaxis especial para las sustituciones. Por ejemplo, lo construyen de tal manera que una cadena como "%%VAR%%" se reemplaza con el valor de $VAR. Luego se dan cuenta de la necesidad de formato adicional, por lo que introducen una sintaxis especial para el formato. Luego necesitan un bucle, así que inventan una sintaxis de bucle. Pronto tienen un pequeño nuevo lenguaje de plantillas.

Este enfoque tiene dos problemas: Primero, su pequeño lenguaje está limitado. Si necesitas hacer algo que el autor no ha pensado, te quedas bloqueado. Segundo: ¿Quién quiere aprender otro lenguaje? Ya sabes Perl, ¿así que por qué no usarlo?

"Text::Template" las plantillas se programan en Perl. Incrustas código Perl en tu plantilla, con "{" al principio y "}" al final. Si quieres que una variable se interpola, la escribes como lo harías en Perl. Si necesitas hacer un bucle, puedes usar cualquiera de las construcciones de bucle de Perl. Todas las funciones incorporadas de Perl están disponibles.

Detalles

Análisis de plantillas

El módulo "Text::Template" escanea la fuente de la plantilla. Una llave de apertura "{" inicia un fragmento de programa, que continúa hasta la llave de cierre correspondiente "}". Cuando la plantilla se rellena, los fragmentos de programa se evalúan, y cada uno se reemplaza con el valor resultante para producir el texto que se devuelve.

Una barra invertida "\" delante de una llave (o de otra barra invertida que esté delante de una llave) escapa su significado especial. El resultado de rellenar esta plantilla:

\{ La suma de 1 y 2 es {1+2}  \}

es

{ La suma de 1 y 2 es 3  }

Si tienes una llave sin emparejar, "Text::Template" devolverá un código de fallo y una advertencia sobre dónde está el problema. Las barras invertidas que no preceden a una llave se pasan sin cambios. Si tienes una plantilla como esta:

{ "Cadena que termina en una nueva línea.\n" }

La barra invertida dentro de la cadena se pasa a Perl sin cambios, por lo que el "\n" realmente se convierte en una nueva línea. Consulte la nota al final para obtener detalles sobre la forma en que funcionan las barras invertidas. El procesamiento de barras invertidas *no* se realiza cuando se especifican delimitadores alternativos con la opción "DELIMITERS". (Ver "Delimitadores alternativos", más abajo).

Cada fragmento de programa debe ser una secuencia de sentencias de Perl, que se evalúan de la forma habitual. El resultado de la última sentencia ejecutada se evaluará en contexto escalar; el resultado de esta sentencia es una cadena, que se interpola en la plantilla en lugar del propio fragmento de programa.

Los fragmentos se evalúan en orden, y los efectos secundarios de los fragmentos anteriores persistirán en los fragmentos posteriores:

{$x = @cosas; ''}El Lord High Chamberlain me ha conseguido {$x}
cosas este año.
{ $diff = $x - 17;
  $mas = 'más'
  if ($diff == 0) {
    $diff = 'ningún';
  } elsif ($diff < 0) {
    $mas = 'menos';
  }
  '';
}
Eso es {$diff} {$mas} de lo que me dio el año pasado.

El valor de $x establecido en la primera línea persistirá en el siguiente fragmento que comience en la tercera línea, y los valores de $diff y $mas establecidos en el segundo fragmento persistirán y se interpolarán en la última línea. La salida se parecerá a esto:

El Lord High Chamberlain me ha conseguido 42
cosas este año.
Eso es 25 más de lo que me dio el año pasado.

Eso es todo lo que hay en cuanto a sintaxis.

La variable $OUT

The $OUT variable

There is one special trick you can play in a template. Here is the motivation for it: Suppose you are going to pass an array, @items, into the template, and you want the template to generate a bulleted list with a header, like this:

Here is a list of the things I have got for you since 1907:
  * Ivory
  * Apes
  * Peacocks
  * ...

One way to do it is with a template like this:

Here is a list of the things I have got for you since 1907:
{ my $blist = '';
  foreach $i (@items) {
      $blist .= qq{  * $i\n};
  }
  $blist;
}

Here we construct the list in a variable called $blist, which we return at the end. This is a little cumbersome. There is a shortcut.

Inside of templates, there is a special variable called $OUT. Anything you append to this variable will appear in the output of the template. Also, if you use $OUT in a program fragment, the normal behavior, of replacing the fragment with its return value, is disabled; instead the fragment is replaced with the value of $OUT. This means that you can write the template above like this:

Here is a list of the things I have got for you since 1907:
{ foreach $i (@items) {
    $OUT .= "  * $i\n";
  }
}

$OUT is reinitialized to the empty string at the start of each program fragment. It is private to "Text::Template", so you can't use a variable named $OUT in your template without invoking the special behavior.

General Remarks

All "Text::Template" functions return "undef" on failure, and set the variable $Text::Template::ERROR to contain an explanation of what went wrong. For example, if you try to create a template from a file that does not exist, $Text::Template::ERROR will contain something like:

Couldn't open file xyz.tmpl: No such file or directory

"new"

$template = Text::Template->new( TYPE => ..., SOURCE => ... );

This creates and returns a new template object. "new" returns "undef" and sets $Text::Template::ERROR if it can't create the template object. "SOURCE" says where the template source code will come from. "TYPE" says what kind of object the source is.

The most common type of source is a file:

Text::Template->new( TYPE => 'FILE', SOURCE => $filename );

This reads the template from the specified file. The filename is opened with the Perl "open" command, so it can be a pipe or anything else that makes sense with "open".

The "TYPE" can also be "STRING", in which case the "SOURCE" should be a string:

Text::Template->new( TYPE => 'STRING',
                     SOURCE => "This is the actual template!" );

The "TYPE" can be "ARRAY", in which case the source should be a reference to an array of strings. The concatenation of these strings is the template:

Text::Template->new( TYPE => 'ARRAY',
                         SOURCE => [ "This is ", "the actual",
                                     " template!",
                                   ]
                   );

The "TYPE" can be FILEHANDLE, in which case the source should be an open filehandle (such as you got from the "FileHandle" or "IO::*" packages, or a glob, or a reference to a glob). In this case "Text::Template" will read the text from the filehandle up to end-of-file, and that text is the template:

# Read template source code from STDIN:
Text::Template->new ( TYPE => 'FILEHANDLE', 
                      SOURCE => \*STDIN  );

If you omit the "TYPE" attribute, it's taken to be "FILE". "SOURCE" is required. If you omit it, the program will abort.

The words "TYPE" and "SOURCE" can be spelled any of the following ways:

TYPE     SOURCE
Type     Source
type     source
-TYPE    -SOURCE
-Type    -Source
-type    -source

Pick a style you like and stick with it.

"DELIMITERS"
You may also add a "DELIMITERS" option. If this option is present, its value should be a reference to an array of two strings. The first string is the string that signals the beginning of each program fragment, and the second string is the string that signals the end of each program fragment. See "Alternative Delimiters", below.
"ENCODING"
You may also add a "ENCODING" option. If this option is present, and the "SOURCE" is a "FILE", then the data will be decoded from the given encoding using the Encode module. You can use any encoding that Encode recognizes. E.g.: 
Text::Template->new(
    TYPE     => 'FILE',
    ENCODING => 'UTF-8',
    SOURCE   => 'xyz.tmpl');
"UNTAINT"
If your program is running in taint mode, you may have problems if your templates are stored in files. Data read from files is considered 'untrustworthy', and taint mode will not allow you to evaluate the Perl code in the file. (It is afraid that a malicious person might have tampered with the file.)

In some environments, however, local files are trustworthy. You can tell "Text::Template" that a certain file is trustworthy by supplying "UNTAINT => 1" in the call to "new". This will tell "Text::Template" to disable taint checks on template code that has come from a file, as long as the filename itself is considered trustworthy. It will also disable taint checks on template code that comes from a filehandle. When used with "TYPE => 'string'" or "TYPE => 'array'", it has no effect.

See perlsec for more complete information about tainting.

Thanks to Steve Palincsar, Gerard Vreeswijk, and Dr. Christoph Baehr for help with this feature.

"PREPEND"
This option is passed along to the "fill_in" call unless it is overridden in the arguments to "fill_in". See "PREPEND" feature and using "strict" in templates> below.
"BROKEN"
This option is passed along to the "fill_in" call unless it is overridden in the arguments to "fill_in". See "BROKEN" below.

"compile"

$template->compile()

Loads all the template text from the template's source, parses and compiles it. If successful, returns true; otherwise returns false and sets $Text::Template::ERROR. If the template is already compiled, it returns true and does nothing.

You don't usually need to invoke this function, because "fill_in" (see below) compiles the template if it isn't compiled already.

If there is an argument to this function, it must be a reference to an array containing alternative delimiter strings. See "Alternative Delimiters", below.

"fill_in"

$template->fill_in(OPTIONS);

Fills in a template. Returns the resulting text if successful. Otherwise, returns "undef" and sets $Text::Template::ERROR.

The OPTIONS are a hash, or a list of key-value pairs. You can write the key names in any of the six usual styles as above; this means that where this manual says "PACKAGE" (for example) you can actually use any of

PACKAGE Package package -PACKAGE -Package -package

Pick a style you like and stick with it. The all-lowercase versions may yield spurious warnings about

Ambiguous use of package => resolved to "package"

so you might like to avoid them and use the capitalized versions.

At present, there are eight legal options: "PACKAGE", "BROKEN", "BROKEN_ARG", "FILENAME", "SAFE", "HASH", "OUTPUT", and "DELIMITERS".

"PACKAGE"
"PACKAGE" specifies the name of a package in which the program fragments should be evaluated. The default is to use the package from which "fill_in" was called. For example, consider this template: 
The value of the variable x is {$x}.

If you use "$template->fill_in(PACKAGE => 'R')" , then the $x in the template is actually replaced with the value of $R::x. If you omit the "PACKAGE" option, $x will be replaced with the value of the $x variable in the package that actually called &q

].

Deberías usar casi siempre "PACKAGE". Si no lo haces y tu plantilla realiza cambios en variables, esos cambios se propagarán de vuelta al programa principal. Evaluar la plantilla en un paquete privado ayuda a prevenir esto. La plantilla aún puede modificar variables en tu programa si lo desea, pero tendrá que hacerlo explícitamente. Consulta la sección al final sobre `Seguridad'.

Aquí tienes un ejemplo de uso de "PACKAGE":

Su Alteza Real,
Adjunto encontrarán una lista de cosas que he conseguido
para usted desde 1907:
{ foreach $item (@items) {
        $item_no++;
    $OUT .= " $item_no. \u$item\n";
  }
}
Firmado,
Gran Chambelán

Queremos pasar una matriz que se asignará a la matriz @items. Así es como se hace:

@items = ('marfil', 'simios', 'pavos reales', );
$template->fill_in();

Esto no es muy seguro. La razón por la que no es tan seguro es que si tuvieras una variable llamada $item_no en el ámbito de tu programa en el punto en que llamaste a "fill_in", su valor se vería afectado por la acción de completar la plantilla. El problema es el mismo que si hubieras escrito una subrutina que usara esas variables de la misma manera que lo hace la plantilla. ($OUT es especial en las plantillas y siempre es seguro).

Una solución a esto es hacer que la variable $item_no sea privada para la plantilla declarándola con "my". Si la plantilla hace esto, estás a salvo.

Pero si usas la opción "PACKAGE", probablemente estarás a salvo incluso si la plantilla *no* declara sus variables con "my":

@Q::items = ('marfil', 'simios', 'pavos reales', );
$template->fill_in(PACKAGE => 'Q');

En este caso, la plantilla afectará a la variable $Q::item_no, que no está relacionada con la que tu programa estaba usando.

Las plantillas no pueden afectar a las variables del programa principal que se declaran con "my", a menos que proporciones referencias a esas variables a la plantilla.

"HASH"
Puede que no quieras poner las variables de la plantilla en un paquete. Los paquetes pueden ser difíciles de gestionar: no se pueden copiar, por ejemplo. "HASH" proporciona una alternativa.

El valor de "HASH" debe ser una referencia a un hash que mapee nombres de variables a valores. Por ejemplo,

$template->fill_in(
    HASH => {
        destinatario => "El Rey",
        elementos     => ['oro', 'incienso', 'mirra'],
        objeto        => \$self,
    }
);

completará la plantilla y usará "El Rey" como valor de $destinatario y la lista de elementos como valor de @elementos. Ten en cuenta que pasamos una referencia de matriz, pero dentro de la plantilla aparece como una matriz. En general, cualquier cosa que no sea una cadena o un número simple debe pasarse por referencia.

También queremos pasar un objeto, que está en $self; ten en cuenta que pasamos una referencia al objeto, "\$self" en su lugar. Como hemos pasado una referencia a un escalar, dentro de la plantilla el objeto aparece como $objeto.

Los detalles completos de cómo funciona son un poco complicados, así que quizás quieras pasar a la siguiente sección.

Supongamos que la clave en el hash es *clave* y el valor es *valor*.

  • Si el *valor* es "undef", entonces cualquier variable llamada $clave, @clave, %clave, etc., no está definida.
  • Si el *valor* es una cadena o un número, entonces $clave se establece en ese valor en la plantilla.
  • Para cualquier otra cosa, debes pasar una referencia.

    Si el *valor* es una referencia a una matriz, entonces @clave se establece en esa matriz. Si el *valor* es una referencia a un hash, entonces %clave se establece en ese hash. Del mismo modo si *valor* es cualquier otro tipo de referencia. Esto significa que

    var => "foo"

    y

    var => \"foo"

    tienen casi exactamente el mismo efecto. (La diferencia es que en el primer caso, el valor se copia, y en el segundo caso se aliña).

  • En particular, si quieres que la plantilla obtenga un objeto o cualquier tipo, debes pasarle una referencia: 
    $template->fill_in(HASH => { manejador_base_datos => \$dbh, ... });

    Si haces esto, la plantilla tendrá una variable $manejador_base_datos que es el objeto manejador de la base de datos. Si omites el "\", la plantilla tendrá un hash %manejador_base_datos, que expone la estructura interna del objeto manejador de la base de datos; no quieres eso.

Normalmente, la forma en que esto funciona es asignando un paquete privado, cargando todas las variables en el paquete y luego completando la plantilla como si hubieras especificado ese paquete. Se asigna un nuevo paquete cada vez. Sin embargo, si *también* usas la opción "PACKAGE", "Text::Template" carga las variables en el paquete que especificaste, y permanecen allí después de que la llamada regrese. Las llamadas posteriores a "fill_in" que usen el mismo paquete recogerán los valores que cargaste.

Si el argumento de "HASH" es una referencia a una matriz en lugar de una referencia a un hash, entonces la matriz debe contener una lista de hashes cuyos contenidos se cargan en el paquete de la plantilla uno tras otro. Puedes usar esta característica si quieres combinar varios conjuntos de variables. Por ejemplo, un conjunto de variables podrían ser los valores predeterminados para un formulario de rellenar, y el segundo conjunto podrían ser las entradas del usuario, que anulan los valores predeterminados cuando están presentes:

$template->fill_in(HASH => [\%defaults, \%user_input]);

También puedes usar esto para establecer dos variables con el mismo nombre:

$template->fill_in(
    HASH => [
        { v => "El Rey" },
        { v => [1,2,3] }
    ]
);

Esto establece $v en "El Rey" y @v en "(1,2,3)".

"BROKEN"
Si alguno de los fragmentos de programa falla al compilar o se aborta por cualquier motivo, y has establecido la opción "BROKEN" a una referencia de función, "Text::Template" invocará la función. Esta función se llama la *función "BROKEN"*. La función "BROKEN" le dirá a "Text::Template" qué hacer a continuación.

Si la función "BROKEN" devuelve "undef", "Text::Template" abortará inmediatamente el procesamiento de la plantilla y devolverá el texto que ha acumulado hasta el momento. Si tu función hace esto, debería establecer una bandera que puedas examinar después de que "fill_in" regrese para que puedas saber si hubo un retorno prematuro o no.

Si la función "BROKEN" devuelve cualquier otro valor, ese valor se interpolará en la plantilla como si ese valor hubiera sido el valor de retorno del fragmento de programa en primer lugar. Por ejemplo, si la función "BROKEN" devuelve una cadena de error, la cadena de error se interpolará en la salida de la plantilla en lugar del fragmento de programa que causó el error.

Si no especificas una función "BROKEN", "Text::Template" proporciona una por defecto que devuelve algo como

Fragmento de programa entregó error ``División ilegal por 0 en
línea 37 de la plantilla''

(Nota que el formato de este mensaje ha cambiado ligeramente desde la versión 1.31.) El valor de retorno de la función "BROKEN" se interpola en la plantilla en el lugar donde ocurrió el error, de modo que esta plantilla:

(3+4)*5 = { 3+4)*5 }

produce este resultado:

(3+4)*5 = Fragmento de programa entregó error ``error de sintaxis en línea 1 de la plantilla''

Si especificas un valor para el atributo "BROKEN", debe ser una referencia a una función que "fill_in" pueda llamar en lugar de la función por defecto.

"fill_in" pasará un hash a la función "broken". El hash tendrá al menos estos tres miembros:

"text"
El código fuente del fragmento de programa que falló
"error"
El texto del mensaje de error ($@) generado por eval.

El texto se ha modificado para omitir el salto de línea final y para incluir el nombre del archivo de la plantilla (si lo hubiera). El número de línea se cuenta desde el principio de la plantilla, no desde el principio del fragmento de programa fallido.

"lineno"
El número de línea de la plantilla en la que comenzó el fragmento de programa.

También puede haber un miembro "arg". Consulta "BROKEN_ARG", a continuación.

"BROKEN_ARG"
Si proporcionas la opción "BROKEN_ARG" a "fill_in", el valor de la opción se pasa a la función "BROKEN" cada vez que se llama. La función "BROKEN" por defecto ignora el "BROKEN_ARG", pero puedes escribir una función "BROKEN" personalizada que use el "BROKEN_ARG" para obtener más
información sobre lo que salió mal.

La función "BROKEN" también podría usar "BROKEN_ARG" como referencia para almacenar un mensaje de error o alguna otra información que desee comunicar al que llama. Por ejemplo:

$error = '';
sub my_broken {
   my %args = @_;
   my $err_ref = $args{arg};
   ...
   $$err_ref = "Some error message";
   return undef;
}
$template->fill_in(
    BROKEN     => \&my_broken,
    BROKEN_ARG => \$error
);
if ($error) {
  die "It didn't work: $error";
}

Si uno de los fragmentos del programa en la plantilla falla, llamará a la función "BROKEN", "my_broken", y le pasará "BROKEN_ARG", que es una referencia a $error. "my_broken" puede almacenar un mensaje de error en $error de esta manera. Luego, la función que llamó a "fill_in" puede ver si "my_broken" ha dejado un mensaje de error para que lo encuentre, y proceder en consecuencia.

"FILENAME"
Si le da a "fill_in" una opción "FILENAME", entonces este es el nombre del archivo del cual cargó el código fuente de la plantilla. Esto solo afecta al mensaje de error que se proporciona para los errores de la plantilla. Si cargó la plantilla desde "foo.txt", por ejemplo, y pasa "foo.txt" como parámetro "FILENAME", los errores se verán como "... at foo.txt line N" en lugar de "... at template line N".

Tenga en cuenta que esto NO tiene nada que ver con cargar una plantilla desde el nombre de archivo dado. Vea fill_in_file() para eso.

Por ejemplo:

my $template = Text::Template->new(
    TYPE   => 'string',
    SOURCE => 'The value is {1/0}');
$template->fill_in(FILENAME => 'foo.txt') or die $Text::Template::ERROR;

fallará con un error que contiene

Illegal division by zero at at foo.txt line 1
"SAFE"
Si le da a "fill_in" una opción "SAFE", su valor debe ser un objeto de compartimento seguro del paquete "Safe". Toda la evaluación de los fragmentos del programa se realizará en este compartimento. Vea Safe para obtener detalles completos sobre dichos compartimentos y cómo restringir las operaciones que se pueden realizar en ellos.

Si utiliza la opción "PACKAGE" con "SAFE", el paquete que especifique se colocará en el compartimento seguro y la evaluación se realizará en ese paquete como de costumbre.

Si no, la operación "SAFE" es un poco diferente de la predeterminada. Normalmente, si no especifica un paquete, la evaluación de los fragmentos del programa ocurre en el paquete desde el cual se invocó la plantilla. Pero en el modo "SAFE" la evaluación ocurre dentro del compartimento seguro y no puede afectar al paquete que llama. Normalmente, si usa "HASH" sin "PACKAGE", las variables hash se importan en un paquete privado de un solo uso. Pero si usa "HASH" y "SAFE" juntos sin "PACKAGE", las variables hash simplemente se cargarán en el espacio de nombres raíz del compartimento "Safe".

"OUTPUT"
Si su plantilla va a generar mucho texto que simplemente va a imprimir de nuevo, puede ahorrar memoria haciendo que "Text::Template" imprima el texto a medida que se genera en lugar de convertirlo en una cadena grande y devolver la cadena. Si proporciona la opción "OUTPUT" a "fill_in", el valor debe ser un manejador de archivos. El texto generado se imprimirá en este manejador de archivos a medida que se construye. Por ejemplo: 
$template->fill_in(OUTPUT => \*STDOUT, ...);

rellena la $template como de costumbre, pero los resultados se imprimen inmediatamente en STDOUT. Esto puede resultar en que la salida aparezca más rápidamente de lo que lo habría hecho de otra manera.

Si usa "OUTPUT", el valor de retorno de "fill_in" sigue siendo verdadero en caso de éxito y falso en caso de error, pero el texto completo no se devuelve al que llama.

"PREPEND"
Puede tener código Perl adicional antepuesto automáticamente al principio de cada fragmento de programa. Vea ""PREPEND" feature and using "strict" in templates" abajo.
"DELIMITERS"
Si esta opción está presente, su valor debe ser una referencia a una lista de dos cadenas. La primera cadena es la cadena que señala el comienzo de cada fragmento de programa, y la segunda cadena es la cadena que señala el final de cada fragmento de programa. Vea "Alternative Delimiters", abajo.

Si especifica "DELIMITERS" en la llamada a "fill_in", anulan cualquier delimitador que haya establecido al crear el objeto de plantilla con "new".

Funciones de conveniencia

"fill_this_in"

La forma básica de rellenar una plantilla es crear un objeto de plantilla y luego llamar a "fill_in" sobre él. Esto es útil si desea rellenar la misma plantilla más de una vez.

En algunos programas, esto puede ser engorroso. "fill_this_in" acepta una cadena, que contiene la plantilla, y una lista de opciones, que se pasan a "fill_in" como se describió anteriormente. Construye el objeto de plantilla para usted, lo rellena según lo especificado y devuelve los resultados. Devuelve "undef" y establece $Text::Template::ERROR si no pudo generar resultados.

Un ejemplo:

$Q::name = 'Donald';
$Q::amount = 141.61;
$Q::part = 'hyoid bone';
$text = Text::Template->fill_this_in( <<'EOM', PACKAGE => Q);
Dear {$name},
You owe me \\${sprintf('%.2f', $amount)}.
Pay or I will break your {$part}.
    Love,
    Grand Vizopteryx of Irkutsk.
EOM

Observe cómo incluimos la plantilla en línea en el programa usando un `here document' con la notación "<<".

"fill_this_in" es una característica obsoleta. Solo está aquí por compatibilidad con versiones anteriores y puede ser eliminada en alguna versión futura de "Text::Template". Debe usar "fill_in_string" en su lugar. Se describe en la siguiente sección.

"fill_in_string"

Es estúpido que "fill_this_in" sea un método de clase. Debería haber sido solo una función importada, para que pudiera omitir "Text::Template->" en el ejemplo anterior. Pero cometí el error hace cuatro años y es demasiado tarde para cambiarlo.

"fill_in_string" es exactamente igual que "fill_this_in" excepto que no es un método y puede omitir "Text::Template->" y simplemente decir

print fill_in_string(<<'EOM', ...);
Dear {$name},
  ...
EOM

Para usar "fill_in_string", necesita decir

use Text::Template 'fill_in_string';

al principio de su programa. Probablemente debería usar "fill_in_string" en lugar de "fill_this_in".

"fill_in_file"

Si importa "fill_in_file", puede decir

$text = fill_in_file(filename, ...);

Los "..." se pasan a "fill_in" como se describió anteriormente. El nombre de archivo es el nombre del archivo que contiene la plantilla que desea rellenar. Devuelve el texto resultante. o "undef", como de costumbre.

Si va a rellenar el mismo archivo más de una vez en el mismo programa, debería usar la secuencia más larga de "new" / "fill_in". Será mucho más rápido porque solo tiene que leer y analizar el archivo una vez.

Incluir archivos en plantillas

La gente siempre pregunta por esto. ``¿Por qué no tienen una función de inclusión?'' preguntan. La respuesta corta es que esto es Perl, y Perl ya tiene una función de inclusión. Si la quiere, puede simplemente poner

{qx{cat filename}}

en su plantilla. Voilà.

Si no desea utilizar "cat", puede escribir una pequeña función de cuatro líneas que abra un archivo y vuelque su contenido, y llamarla desde la plantilla. Escribí una para usted. En la plantilla, puede decir

{Text::Template::_load_text(filename)}

Si eso es demasiado verboso, aquí hay un truco. Suponga que el paquete de la plantilla que va a mencionar en la llamada "fill_in" es el paquete "Q". Entonces, en el programa principal, escriba

*Q::include = \&Text::Template::_load_text;

Esto importa la función "_load_text" al paquete "Q" con el nombre "include". A partir de entonces, cualquier plantilla que rellene con el paquete "Q" puede decir

{in

include() file

para insertar el texto del archivo nombrado en ese punto. Si está utilizando la opción "HASH" en su lugar, simplemente coloque "include => \&Text::Template::_load_text" en el hash en lugar de importarlo explícitamente.

Supongamos que no desea insertar un archivo de texto plano, sino que desea incluir una plantilla dentro de otra. Simplemente use "fill_in_file" en la plantilla misma:

{Text::Template::fill_in_file(filename)}

Puede hacer lo mismo con la importación si esto es demasiado para escribir.

Misceláneo

Variables "my"

La gente se sorprende con frecuencia cuando esto no funciona:

my $recipient = 'El Rey';
my $text = fill_in_file('formletter.tmpl');

El texto "El Rey" no se inserta en la carta modelo. ¿Por qué no? Porque $recipient es una variable "my", y el propósito de las variables "my" es que sean privadas e inaccesibles excepto en el ámbito en el que se declaran. La plantilla no forma parte de ese ámbito, por lo que la plantilla no puede ver $recipient.

Si ese no es el comportamiento que desea, no utilice "my". "my" significa una variable privada, y en este caso no desea que la variable sea privada. Coloque las variables en variables de paquete en algún otro paquete y use la opción "PACKAGE" de "fill_in":

$Q::recipient = $recipient;
my $text = fill_in_file('formletter.tmpl', PACKAGE => 'Q');

o pase los nombres y valores en un hash con la opción "HASH":

my $text = fill_in_file('formletter.tmpl', HASH => { recipient => $recipient });

Asuntos de Seguridad

Todas las variables se evalúan en el paquete que especifica con la opción "PACKAGE" de "fill_in". Si utiliza esta opción, y si sus plantillas no hacen nada flagrantemente estúpido, no tendrá que preocuparse de que la evaluación de los pequeños programas se escape al resto de su programa y lo estropee.

Sin embargo, en realidad no hay forma (excepto con "Safe") de protegerse contra una plantilla que dice

{ $Important::Secret::Security::Enable = 0;
  # Desactiva las comprobaciones de seguridad en este programa
}

o

{ $/ = "ho ho ho";   # Sabotea usos futuros de <FH>.
  # $/ es siempre una variable global
}

o incluso

{ system("rm -rf /") }

así que **no** llene plantillas a menos que esté seguro de lo que contienen. Si está preocupado, o no puede confiar en la persona que escribió la plantilla, utilice la opción "SAFE".

Una advertencia final: los fragmentos de programa corren un pequeño riesgo de dañar accidentalmente las variables locales en la función "fill_in". Todas estas variables tienen nombres que comienzan con $fi_, así que si se aleja de esos nombres estará a salvo. (Por supuesto, si es un verdadero mago puede manipularlos deliberadamente para obtener efectos emocionantes; así es como funciona realmente $OUT.) Puedo arreglar esto, pero hará que el paquete sea más lento, así que preferiría no hacerlo. Si está preocupado por esto, envíeme un correo electrónico y le mostraré qué hacer al respecto.

Delimitadores Alternativos

Lorenzo Valdettaro señaló que si está utilizando "Text::Template" para generar salida TeX, la elección de llaves como delimitadores de fragmentos de programa le hace sufrir mucho. A partir de la versión 1.20, puede cambiar la elección de delimitadores a algo que no sean llaves.

Ya sea en la llamada new() o en la llamada fill_in(), puede especificar un conjunto alternativo de delimitadores con la opción "DELIMITERS". Por ejemplo, si desea que los fragmentos de código estén delimitados por "[@--" y "--@]" en lugar de "{" y "}", use

... DELIMITERS => [ '[@--', '--@]' ], ...

Tenga en cuenta que estos delimitadores son cadenas *literales*, no expresiones regulares. (Intenté con expresiones regulares, pero complica demasiado el análisis léxico). Tenga en cuenta también que "DELIMITERS" deshabilita el significado especial de la barra invertida, por lo que si desea incluir los delimitadores en el texto literal de su archivo de plantilla, está de suerte: depende de usted elegir delimitadores que no entren en conflicto con lo que está haciendo. Las cadenas delimitadoras aún pueden aparecer dentro de los fragmentos de programa siempre que aniden correctamente. Esto significa que si por alguna razón necesita absolutamente un fragmento de programa que mencione uno de los delimitadores, como este:

[@--
    print "Oh no, a delimiter: --@]\n"
--@]

puede que pueda hacerlo funcionar haciendo esto en su lugar:

[@--
    # Falsifica el delimitador coincidente en un comentario: [@--
    print "Oh no, a delimiter: --@]\n"
--@]

Puede ser más seguro elegir delimitadores que comiencen con un carácter de nueva línea.

Dado que el análisis de plantillas se simplifica por la ausencia de escapes de barra invertida, el uso de "DELIMITERS" alternativos puede acelerar el proceso de análisis en un 20-25%. Esto demuestra que mi elección original de "{" y "}" fue muy mala.

Característica "PREPEND" y uso de "strict" en plantillas

Supongamos que desea utilizar "strict" en sus plantillas para detectar variables no declaradas y similares. Pero cada fragmento de código es un ámbito léxico separado, por lo que tiene que activar "strict" al principio de cada fragmento de código:

{ use strict;
  use vars '$foo';
  $foo = 14;
  ...
}
...
{ # olvidamos poner `use strict' aquí
  my $result = $boo + 12;    # $boo está mal escrito y debería ser $foo
  # No se genera ningún error en `$boo'
}

Como no pusimos "use strict" al principio del segundo fragmento, solo estuvo activo en el primer fragmento, y no obtuvimos ninguna comprobación de "strict" en el segundo fragmento. Luego escribimos mal $foo y el error no se detectó.

"Text::Template" versión 1.22 y superior tiene una nueva característica para facilitar esto. Puede especificar que cualquier texto se agregue automáticamente al principio de cada fragmento de programa.

Cuando realiza una llamada a "fill_in", puede especificar una

PREPEND => 'algunas sentencias perl aquí'

opción; las sentencias se antepondrán a cada fragmento de programa solo para esa llamada. Supongamos que la llamada a "fill_in" incluyó una

PREPEND => 'use strict;'

opción, y que la plantilla se veía así:

{ use vars '$foo';
  $foo = 14;
  ...
}
...
{ my $result = $boo + 12;    # $boo está mal escrito y debería ser $foo
  ...
}

El código en el segundo fragmento fallaría, porque $boo no ha sido declarado. Se implicó "use strict", aunque no lo escribió explícitamente, porque la opción "PREPEND" lo agregó automáticamente por usted.

Hay tres formas más de hacerlo. En el momento en que crea el objeto plantilla con "new", también puede proporcionar una opción "PREPEND", en cuyo caso las sentencias se antepondrán cada vez que rellene esa plantilla. Si la llamada a "fill_in" tiene su propia opción "PREPEND", esta anula la especificada en el momento en que creó la plantilla. Finalmente, puede hacer la llamada de método de clase

Text::Template->always_prepend('sentencias perl');

Si hace esto, entonces las llamadas a "fill_in" para *cualquier* plantilla adjuntarán las sentencias perl al principio de cada fragmento de programa, excepto donde se anulen por las opciones "PREPEND" a "new" o "fill_in".

Una alternativa a agregar "use strict;" a la opción PREPEND, puede pasar STRICT => 1 a fill_in cuando también pase la opción HASH.

Supongamos que la llamada "fill_in" incluyó ambas opciones

HASH   => {$foo => ''} y
STRICT => 1

y que la plantilla se veía así:

{
  $foo = 14;
  ...
}
...
{ my $result = $boo + 12;    # $boo está mal escrito y debería ser $foo
  ...
}

El código en el segundo fragmento fallaría, porque $boo no ha sido declarado. Se implicó "use strict", aunque no lo escribió explícitamente, porque la opción "STRICT" lo agregó automáticamente por usted. Cualquier variable referenciada en la plantilla que no esté en la opción "HASH" será un error.

Anteponer en Clases Derivadas

Esta sección es técnica y debe omitirla en las primeras lecturas.

Normalmente hay tres lugares de donde puede provenir el texto antepuesto. Podría provenir de la opción "PREPEND" en la llamada "fill_in", de la opción "PREPEND" en la llamada "new" que creó el objeto plantilla, o del argumento de la llamada "always_prepend".

Descendencia

Cuando un método de "Text::Template" necesita determinar qué texto preceder, busca estas tres cosas en orden y toma la primera que encuentra.

En una subclase de "Text::Template", esta última posibilidad es ambigua. Supongamos que "S" es una subclase de "Text::Template". ¿Debería

Text::Template->always_prepend(...);

afectar a los objetos de la clase "Derived"? La respuesta es que puedes tenerlo de cualquier manera.

El valor de "always_prepend" para "Text::Template" normalmente se almacena en una variable hash llamada %GLOBAL_PREPEND bajo la clave "Text::Template". Cuando "Text::Template" busca qué texto preceder, primero busca en el propio objeto plantilla y, si no lo encuentra, busca en $GLOBAL_PREPEND{clase} donde clase es la clase a la que pertenece el objeto plantilla. Si no encuentra ningún valor, busca en $GLOBAL_PREPEND{'Text::Template'}. Esto significa que los objetos de la clase "Derived" *serán* afectados por

Text::Template->always_prepend(...);

a *menos* que también haya una llamada a

Derived->always_prepend(...);

Así que, al diseñar su clase derivada, puede organizar que sus objetos ignoren las llamadas a "Text::Template::always_prepend" simplemente poniendo "Derived->always_prepend('')" al principio de su módulo.

Por supuesto, también hay una vía de escape final: las plantillas admiten un método "prepend_text" que se utiliza para buscar el texto apropiado que se debe anteponer en el momento de "fill_in". Su clase derivada puede anular este método para obtener un efecto arbitrario.

JavaScript

Jennifer D. St Clair pregunta:

> La mayoría de mis páginas contienen JavaScript y Hojas de Estilo.
> ¿Cómo cambio el identificador de la plantilla?

Jennifer está preocupada por las llaves del JavaScript que se toman como delimitadores de los fragmentos de programa Perl. Por supuesto, ocurrirá un desastre cuando Perl intente evaluarlos como si fueran programas Perl. La mejor opción es encontrar cadenas delimitadoras inequívocas que pueda usar en su plantilla en lugar de llaves, y luego usar la opción "DELIMITERS". Sin embargo, si por alguna razón no puede hacer esto, hay dos soluciones fáciles:

1. Puede anteponer "\" a "{", "}", o "\" para eliminar su significado especial. Así, por ejemplo, en lugar de

if (br== "n3") { 
    // etc.
}

puede poner

if (br== "n3") \{
    // etc.
\}

y saldrá del motor de plantillas como usted desea.

Pero aquí hay otro método que probablemente sea mejor. Para ver cómo funciona, primero considere qué sucede si pone esto en una plantilla:

{ 'foo' }

Como está entre llaves, se evalúa, y obviamente, esto se convertirá en

foo

Así que ahora aquí está el truco: En Perl, "q{...}" es lo mismo que '...'. Así que si escribiéramos

{q{foo}}

se convertiría en

foo

Así que para su JavaScript, simplemente escriba

{q{if (br== "n3") {
   // etc.
   }}
}

y se convertirá en

if (br== "n3") {
    // etc.
}

que es lo que quiere.

head2 ¡Silencio!

A veces la gente intenta poner una sección de inicialización al principio de sus plantillas, así:

{ ...
    $var = 17;
}

Luego se quejan porque hay un 17 al principio de la salida que no querían que estuviera allí.

Recuerde que un fragmento de programa se reemplaza por su propio valor de retorno, y que en Perl el valor de retorno de un bloque de código es el valor de la última expresión evaluada, que en este caso es 17. Si no hiciera eso, no podría escribir "{$recipient}" y que el destinatario se complete.

Para evitar que el 17 aparezca en la salida es muy simple:

{ ...
    $var = 17;
    '';
}

Ahora la última expresión evaluada produce una cadena vacía, que es invisible. Si no le gusta cómo se ve esto, use

{ ...
    $var = 17;
    ($SILENTLY);
}

en su lugar. Presumiblemente, $SILENTLY no tiene valor, por lo que no se interpolará nada. Esto es lo que se conoce como un truco.

Compatibilidad

Se han hecho todos los esfuerzos posibles para que este módulo sea compatible con versiones anteriores. Las únicas excepciones conocidas son las siguientes:

El formato de salida de la subrutina por defecto "BROKEN" ha cambiado dos veces, la última vez entre las versiones 1.31 y 1.40.

A partir de la versión 1.10, la variable $OUT se reserva para un significado especial. Si tenía plantillas anteriores a la versión 1.10 que utilizaban una variable llamada $OUT, tendrá que cambiarla para usar otra variable o se producirán todo tipo de rarezas.

Entre las versiones 0.1b y 1.00, el comportamiento del metacaracter \ cambió. En 0.1b, \\ era especial en todas partes, y el procesador de plantillas siempre lo reemplazaba con una barra invertida simple antes de pasar el código a Perl para su evaluación. La regla ahora es más complicada pero probablemente más conveniente. Consulte la sección sobre procesamiento de barras invertidas, a continuación, para una discusión completa.

Procesamiento de barras invertidas

En las versiones beta de "Text::Template", la barra invertida era especial siempre que aparecía antes de una llave o de otra barra invertida. Esto significaba que mientras "{"\n"}" generaba efectivamente un salto de línea, "{"\\"}" no generaba una barra invertida, porque el código pasado a Perl para su evaluación era "\" que es un error de sintaxis. Si quería una barra invertida, tendría que haber escrito "{"\\\\"}".

En las versiones 1.00 a 1.10 de "Text::Template", había un error: la barra invertida era especial en todas partes. En estas versiones, "{"\n"}" generaba la letra "n".

El error se corrigió en la versión 1.11, pero no volví a la regla antigua exactamente, porque no me gustaba la idea de tener que escribir "{"\\\\"}" para obtener una barra invertida. La regla ahora es más complicada de recordar, pero probablemente más fácil de usar. La regla ahora es: las barras invertidas siempre se pasan a Perl sin cambios *a menos que* ocurran como parte de una secuencia como "\\\\\\{" o "\\\\\\}". En estos contextos, son especiales; "\\" se reemplaza por "\", y "\{" y "\}" señalan una llave literal.

Ejemplos:

\{ foo \}

*no* se evalúa, porque la "\" antes de las llaves indica que deben tomarse literalmente. El resultado en la salida se ve así:

{ foo }

Esto es un error de sintaxis:

{ "foo}" }

porque "Text::Template" piensa que el código termina en la primera "}", y luego se molesta cuando ve la segunda. Para que esto funcione correctamente, use

{ "foo\}" }

Esto pasa "foo}" a Perl para su evaluación. Tenga en cuenta que no hay "\" en el código evaluado. Si realmente quiere una "\" en el código evaluado, use

{ "foo\\\}" }

Esto pasa "foo\}" a Perl para su evaluación.

A partir de la versión 1.20 de "Text::Template", el procesamiento de barras invertidas se deshabilita si usa la opción "DELIMITERS" para especificar cadenas delimitadoras alternativas.

Una breve nota sobre $Text::Template::ERROR

En el pasado, algunas personas se preocuparon por "violar el límite del paquete" al examinar una variable dentro del paquete "Text::Template". No se sienta así. $Text::Template::ERROR es parte de la interfaz publicada y oficial de este paquete. Está perfectamente bien inspeccionar esta variable. La interfaz no va a cambiar.

Si realmente, realmente le molesta, puede importar una función llamada "TTerror" que devuelve el valor actual de la variable $ERROR. Así que puede decir:

use Text::Template 'TTerror';
my $template = Text::Template->new(SOURCE => $filename);
unless ($template) {
    my $err = TTerror;
    die "Couldn't make template: $err; aborting";
}

No veo qué beneficio tiene esto sobre simplemente hacer esto:

use Text::Template;
my $template = Text::Template->new(SOURCE => $filename)
    or die "Couldn't make template: $Text::Template::ERROR; aborting";

Pero si le hace feliz hacerlo de esa manera, adelante.

Widgets Pegajosos en Archivos de Plantilla

El módulo "CGI" proporciona funciones para "widgets pegajosos", que son controles de entrada de formulario que conservan sus valores de una página a otra. A veces la gente quiere saber cómo incluir estos widgets en la salida de sus plantillas.

Es totalmente sencillo. Simplemente llame a las funciones de "CGI" desde dentro de la plantilla:

{ $q->checkbox_group(NAME      => 'toppings',
                     LINEBREAK => true,
                     COLUMNS   => 3,
                     VALUES    =>
\@toppings ); }

Preprocesamiento automático de fragmentos de programa

Puede ser útil preprocesar los fragmentos de programa antes de que se evalúen. Ver "Text::Template::Preprocess" para más detalles.

Postprocesamiento automático de trozos de plantilla

Puede ser útil procesar los trozos de salida antes de que se añadan al texto del resultado. Para ello, cree una subclase y reemplace el método "append_text_to_result". Se le pasa una lista de pares con estas entradas:

handle - un manejador de archivo al que imprimir la salida deseada
out    - una referencia a una cadena a la que añadir, a usar si no se proporciona manejador
text   - el texto que se añadirá
type   - de dónde provino el texto: TEXT para texto literal, PROG para código

Errores y advertencias

Las variables "my" en "fill_in" aún son susceptibles de ser sobrescritas por la evaluación de la plantilla. Todas empiezan con "fi_", así que evita esos nombres en tus plantillas.

La información del número de línea será incorrecta si las líneas de la plantilla no terminan en "\n". Deberías informarme si esto es un problema. Si lo haces, lo arreglaré.

La variable $OUT tiene un significado especial en las plantillas, por lo que no puedes usarla como si fuera una variable normal.

No hay suficientes pruebas en el conjunto de pruebas.
