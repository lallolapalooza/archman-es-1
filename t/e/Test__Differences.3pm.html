Test::Differences(3) Documentación de Perl contribuida por el usuario Test::Differences(3)

NOMBRE

Test::Differences - Prueba cadenas y estructuras de datos y muestra diferencias si no son correctas

SINOPSIS

use Test;    ## O usa Test::More
use Test::Differences;
eq_or_diff $got,  "a\nb\nc\n",   "probando cadenas";
eq_or_diff \@got, [qw( a b c )], "probando arrays";
## Pasando opciones:
eq_or_diff $got, $expected, $name, { context => 300 };  ## opciones
## Usando con estructuras de datos tipo DBI
use DBI;
... abre conexión & prepara sentencia y @expected_... aquí...
eq_or_diff $sth->fetchall_arrayref, \@expected_arrays  "probando arrays DBI";
eq_or_diff $sth->fetchall_hashref,  \@expected_hashes, "probando hashes DBI";
## Para forzar la numeración de líneas de texto o datos (las líneas de texto se numeran 1..):
eq_or_diff_text ...;
eq_or_diff_data ...;

EXPORTAR

Este módulo exporta tres funciones de prueba y cuatro funciones de estilo diff:

•
Funciones de prueba
  • "eq_or_diff"
  • "eq_or_diff_data"
  • "eq_or_diff_text"
•
Funciones de estilo diff
  • "table_diff" (el predeterminado)
  • "unified_diff"
  • "oldstyle_diff"
  • "context_diff"

DESCRIPCIÓN

Cuando el código que estás probando devuelve múltiples líneas, registros o estructuras de datos y son simplemente incorrectos, una utilidad equivalente al "diff" de Unix puede ser exactamente lo que necesitas. Aquí tienes una salida de un script de prueba de ejemplo que comprueba dos documentos de texto y luego dos estructuras de datos (triviales):

t/99example....1..3
not ok 1 - diferencias en texto
#     Failed test ((eval 2) at line 14)
#     +---+----------------+----------------+
#     | Ln|Got             |Expected        |
#     +---+----------------+----------------+
#     |  1|this is line 1  |this is line 1  |
#     *  2|this is line 2  |this is line b  *
#     |  3|this is line 3  |this is line 3  |
#     +---+----------------+----------------+
not ok 2 - diferencias en espacios en blanco
#     Failed test ((eval 2) at line 20)
#     +---+------------------+------------------+
#     | Ln|Got               |Expected          |
#     +---+------------------+------------------+
#     |  1|        indented  |        indented  |
#     *  2|        indented  |\tindented        *
#     |  3|        indented  |        indented  |
#     +---+------------------+------------------+
not ok 3
#     Failed test ((eval 2) at line 22)
#     +----+-------------------------------------+----------------------------+
#     | Elt|Got                                  |Expected                    |
#     +----+-------------------------------------+----------------------------+
#     *   0|bless( [                             |[                           *
#     *   1|  'Move along, nothing to see here'  |  'Dry, humorless message'  *
#     *   2|], 'Test::Builder' )                 |]                           *
#     +----+-------------------------------------+----------------------------+
# Looks like you failed 3 tests of 3.

eq_or_diff_...() compara dos cadenas o estructuras de datos (limitadas) y emite una indicación de éxito o un diff lado a lado. Test::Differences está diseñado para ser utilizado con Test.pm y con Test::Simple, Test::More y otros módulos de prueba basados en Test::Builder. Como muestra la SINOPSIS, otro módulo de prueba debe ser utilizado como base para tu suite de pruebas.

OPCIONES

Las opciones para "eq_or_diff" proporcionan un control detallado sobre la salida.

  • "context"

    Esto te permite controlar la cantidad de contexto que se muestra:

    eq_or_diff $got, $expected, $name, { context => 50000 };

    mostrará mucho, mucho contexto. Normalmente, eq_or_diff() usa algunas heurísticas para determinar si mostrar 3 líneas de contexto (como un diff unificado normal) o 25 líneas.

  • "data_type"

    "text" o "data". Esto normalmente se establece como predeterminado en "data". Si, sin embargo, ninguno de $got o $expected es una referencia, entonces se establece como predeterminado a "text". También puedes forzar uno u otro llamando a "eq_or_diff_text" o "eq_or_diff_data".

    La diferencia es que en modo texto las líneas se numeran desde 1, pero en modo datos desde 0 (y se denominan 'elementos' (Elt) en lugar de líneas):

    # +---+-------+----------+
# | Ln|Got    |Expected  |
# +---+-------+----------+
# *  1|'foo'  |'bar'     *
# +---+-------+----------+
# +----+---------+----+----------+
# | Elt|Got      | Elt|Expected  |
# +----+---------+----+----------+
# *   0|[        *   0|'bar'     *
# *   1|  'foo'  *    |          |
# *   2|]        *    |          |
# +----+---------+----+----------+

    La diferencia es puramente cosmética, no afecta a cómo se realizan las comparaciones.

  • "Sortkeys"

    Si se pasa, el valor que se agregue se usará como argumento para la opción Sortkeys de Data::Dumper. Consulta la documentación de Data::Dumper para entender cómo puedes controlar el comportamiento de Sortkeys.

  • "filename_a" y "filename_b"

    Las cabeceras de columna a utilizar en la salida. Por defecto son 'Got' y 'Expected'.

ESTILOS DIFF

Para cadenas extremadamente largas, un diff de tabla puede salirse de la pantalla y ser difícil de leer. Si te sientes cómodo con diferentes formatos de diff, puedes cambiar a un formato más adecuado para tus datos. Estos son los cuatro formatos compatibles con el módulo Text::Diff y se configuran con las siguientes funciones:

  • "table_diff" (el predeterminado)
  • "unified_diff"
  • "oldstyle_diff"
  • "context_diff"

Puedes ejecutar lo siguiente para entender los diferentes estilos de salida de diff:

use Test::More 'no_plan';
use Test::Differences;
my $long_string = join '' => 1..40;
TODO: {
    local $TODO = 'Testing diff styles';
    # este es el predeterminado y no necesita configurarse explícitamente a menos que necesites
    # restablecerlo desde otro tipo de diff
    table_diff;
    eq_or_diff $long_string, "-$long_string", 'table diff';
    unified_diff;
    eq_or_diff $long_string, "-$long_string", 'unified diff';
    context_diff;
    eq_or_diff $long_string, "-$long_string", 'context diff';
    oldstyle_diff;
    eq_or_diff $long_string, "-$long_string", 'oldstyle diff';
}

UNICODE

En general, encontrarás que la siguiente salida de prueba es decepcionante.

use Test::Differences;
use utf8;
my $want = { 'Traditional Chinese' => '中國' };
my $have = { 'Traditional Chinese' => '中国' };
eq_or_diff $have, $want, 'Unicode, baby';

Aquí tienes lo que obtienes:

#   Failed test 'Unicode, baby'

# +----+-----------------------+-----------------------+
# | Elt|Got                    |Expected               |

# *   1|'\x{4e2d}\x{56fd}'     |'\x{4e2d}\x{570b}'     *

Test::Differences - Manual Page

NAME

Test::Differences - compare data structures with differences

SYNOPSIS

 use Test::Differences;
 use Test::More tests => 3;

 my $foo = {
     'password' => '',
     'method'   => 'login',
     'ctrl'     => 'home',
     'email'    => 'test'
 };

 my $bar = {
     'password' => '',
     'ctrl'     => 'home',
     'email'    => 'test',
     'method'   => 'login'
 };

 my $baz = {
     'password' => '',
     'method'   => 'logout',
     'ctrl'     => 'home',
     'email'    => 'test'
 };

 eq_or_diff($foo, $bar); # should pass
 eq_or_diff($foo, $baz); # should fail

 # Alternative form:
 my $result = eq_or_diff_ok($foo, $bar); # returns 1
 my $result2 = eq_or_diff_ok($foo, $baz); # returns 0

 # You can also specify options:
 eq_or_diff($foo, $bar, { style => 'sidebyside' });

 # Or use a specific diff function:
 my $diff = diff($foo, $bar);
 print $diff->text_diff;

EXPORT

This module exports the following 3 functions by default:

 eq_or_diff
 eq_or_diff_ok
 diff

DESCRIPTION

This module compares two perl data structures and reports the differences between them in a human-readable format. This is particularly useful for testing, where you often want to compare the output of a piece of code against a known expected output.

The module uses Data::Dumper to serialize the data structures, and then compares the serialized strings using a configurable diff algorithm.

The default diff algorithm is a context diff, similar to what you might see from the standard diff utility.

The core functions are:

eq_or_diff
Compares two values. If they are identical, it succeeds. If they are different, it fails and prints a diagnostic message showing the differences. It returns true on success, and false on failure.
eq_or_diff_ok
Similar to eq_or_diff, but it directly calls Test::More::ok() with the result. This is convenient for use in test scripts.
diff
Returns a Test::Differences::Diff object representing the differences between the two values. This object can be further manipulated to display the differences in various formats (e.g., text, side-by-side).

OPTIONS

Both eq_or_diff and eq_or_diff_ok accept an optional third argument, which is a hash reference containing options to control the comparison and output. Currently supported options include:

style
Specifies the style of the diff output. Possible values include 'context' (default), 'sidebyside', and 'sidebyside_long'.
num_context
Sets the number of context lines to show in the diff output. Defaults to 3.
subindent
Specifies the indentation level for sub-elements in the diff output. Defaults to 4.
dumper_args
A hash reference of arguments to pass to Data::Dumper::Dumper(). This allows fine-grained control over how the data structures are serialized.

Example:

 eq_or_diff($foo, $bar, { style => 'sidebyside', num_context => 5 });

DIFF STYLES

The following diff styles are supported:

context
The standard context diff format. Shows lines that are different and a few lines of context around them.
sidebyside
A side-by-side comparison, where differences are highlighted. Shorter lines are preferred.
sidebyside_long
Similar to sidebyside, but designed to handle longer lines more gracefully.

UNICODE

Test::Differences handles Unicode correctly, provided you are using a reasonably modern version of Perl (5.8.0 or later is recommended).

Unknown::Values

In order to correctly compare values that have different internal representations but are considered equal by Perl (e.g., some numeric values and their string equivalents), Test::Differences relies on the Unknown::Values module. If this module is not available, or if it fails to load, Test::Differences may not be able to accurately compare such values.

When Unknown::Values is not available, Test::Differences will issue a warning and proceed with a potentially less accurate comparison. The comparison of certain types of data, especially those involving numeric vs. string comparisons or specific object types, might not be as precise as intended.

The presence and successful loading of Unknown::Values are crucial for the full functionality of Test::Differences. If you encounter unexpected comparison results, ensure that Unknown::Values is installed and accessible. Due to complicated internal reasons, we cannot show you much context. Sorry.

NB that the support for these is experimental and relies on an undocumented unstable interface in Unknown::Values. If that fails then Test::Differences will probably just die when it sees them instead of telling you that the comparison failed.

LIMITATIONS

"Test" or "Test::More"

This module "mixes in" with Test.pm or any of the test libraries based on Test::Builder (Test::Simple, Test::More, etc). It does this by peeking to see whether Test.pm or Test/Builder.pm is in %INC, so if you are not using one of those, it will print a warning and play dumb by not emitting test numbers (or incrementing them). If you are using one of these, it should interoperate nicely.

Exporting

Exports all 3 functions by default (and by design). Use

use Test::Differences ();

to suppress this behavior if you don't like the namespace pollution.

This module will not override functions like ok(), is(), is_deeply(), etc. If it did, then you could "eval "use Test::Differences qw( is_deeply );"" to get automatic upgrading to diffing behaviors without the "sub my_ok" shown above. Test::Differences intentionally does not provide this behavior because this would mean that Test::Differences would need to emulate every popular test module out there, which would require far more coding and maintenance that I'm willing to do. Use the eval and my_ok deployment shown above if you want some level of automation.

Booleans

Historically, true and false (whether resulting from logical-not "!" or from equality checks like "==") were represented in perl as numeric 1 for true and the empty string '' for false. In perl 5.36.0 they became real Boolean values which for backward compatibility also have their old numeric/string values. In 5.38 (and in dev releases from 5.37.2 onwards) Data::Dumper belatedly learned about this, and so Test::Differences (which uses Data::Dumper under the bonnet) can also tell the difference.

This means that `eq_or_diff(1, !!1)` will behave differently depending on whether you are using perl 5.38 or later (in which case it will say they are different) or 5.36 or earlier (which will say they are the same).

Unicode

Perls before 5.6.0 don't support characters > 255 at all, and 5.6.0 seems broken. This means that you might get odd results using perl5.6.0 with unicode strings.

"Data::Dumper" and older Perls.

Relies on Data::Dumper (for now), which, prior to perl5.8, will not always report hashes in the same order. $Data::Dumper::Sortkeys is set to 1, so on more recent versions of Data::Dumper, this should not occur. Check CPAN to see if it's been peeled out of the main perl distribution and backported. Reported by Ilya Martynov <ilya@martynov.org>, although the Sortkeys "future perfect" workaround has been set in anticipation of a new Data::Dumper for a while. Note that the two hashes should report the same here:

not ok 5
#     Failed test (t/ctrl/05-home.t at line 51)
# +----+------------------------+----+------------------------+
# | Elt|Got                     | Elt|Expected                |
# +----+------------------------+----+------------------------+
# |   0|{                       |   0|{                       |
# |   1|  'password' => '',     |   1|  'password' => '',     |
# *   2|  'method' => 'login',  *    |                        |
# |   3|  'ctrl' => 'home',     |   2|  'ctrl' => 'home',     |
# |    |                        *   3|  'method' => 'login',  *
# |   4|  'email' => 'test'     |   4|  'email' => 'test'     |
# |   5|}                       |   5|}                       |
# +----+------------------------+----+------------------------+

Data::Dumper also overlooks the difference between

$a[0] = \$a[1];
$a[1] = \$a[0];   # $a[0] = \$a[1]

and

$x = \$y;
$y = \$x;
@a = ( $x, $y );  # $a[0] = \$y, not \$a[1]

The former involves two scalars, the latter 4: $x, $y, and @a[0,1]. This was carefully explained to me in words of two syllables or less by Yves Orton <demerphq@hotmail.com>. The plan to address this is to allow you to select Data::Denter or some other module of your choice as an option.

Code-refs

Test::Differences turns on $Data::Dumper::Deparse, so any code-refs in your data structures will be turned into text before they are examined, using B::Deparse. The precise text generated for a sub-ref might not be what you expect as it is generated from the compiled version of the code, but it should at least be consistent and spot differences correctly.

You can turn this behaviour off by setting $Test::Differences::NoDeparse.
