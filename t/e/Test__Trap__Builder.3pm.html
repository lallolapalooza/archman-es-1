Test::Trap::Builder(3) Documentación contribuida por usuarios de Perl Test::Trap::Builder(3)

NOMBRE

Test::Trap::Builder - Backend para construir trampas de prueba

VERSIÓN

Versión 0.3.5

SINOPSIS

package My::Test::Trap;
use Test::Trap::Builder;
my $B = Test::Trap::Builder->new;
$B->layer( $layer_name => \&layer_implementation );
$B->accessor( simple => [ $layer_name ] );
$B->multi_layer( $multi_name => @names );
$B->test( $test_name => 'trap, predicate, name', \&test_function );

DESCRIPCIÓN

Test::Trap ni atrapa ni prueba todo lo que podrías querer atrapar o probar. Por lo tanto, Test::Trap::Builder proporciona métodos para escribir tus propias capas de trampas, accesores y callbacks de prueba, preferiblemente para usar con tus propios módulos (tramperos).

Ten en cuenta que las capas son métodos con nombres modificados (los nombres van precedidos por "layer:"), y por lo tanto se heredan como cualquier otro método, mientras que los accesores son métodos ordinarios. Por otro lado, los callbacks de prueba no se referencian en la tabla de símbolos por sí solos, sino solo en combinaciones con accesores, todos los métodos de la forma ACCESOR_TEST.

EXPORTACIONES

Los tramperos no deberían heredar de Test::Trap::Builder, pero pueden importar algunos métodos de conveniencia para usarlos en la creación de trampas. No los uses como métodos de Test::Trap::Builder; están destinados a ser métodos de objetos de trampa. (Si heredas de otro trampero, no necesitas, y probablemente no deberías, importar estos tú mismo; deberías heredar estos métodos como cualquier otro).

Los tramperos pueden importar cualquier número de estos métodos, o todos ellos por medio de la etiqueta ":methods".

Las capas deben implementarse como métodos y, aunque no necesiten llamar a ninguno de estos métodos de conveniencia a su vez, probablemente harán que el código sea más legible que cualquier alternativa. Del mismo modo, los callbacks de prueba pueden usar métodos de conveniencia para un código más legible.

Por supuesto, ciertos métodos de conveniencia también pueden ser útiles en métodos más genéricos que manipulan objetos de trampa o de creación.

Prop [PACKAGE]

Un método que devuelve una referencia a un hash, que contiene las propiedades de etiqueta del paquete (por defecto, el llamador) para el objeto de trampa (actual). Actualmente, Test::Trap::Builder define las siguientes propiedades:

capas
Mientras la trampa se está activando, la cola de capas restantes. Generalmente establecida por el método "trap" y consumida por el método "Next".
desmontaje
Mientras la trampa se está activando, la cola de acciones de desmontaje restantes. Generalmente acumulada a través del método "Teardown" e invocada por el método "trap".
código
El código del usuario atrapado. Generalmente establecido por el método "trap" e invocado por el método "Run".
excepción
Una excepción interna. Generalmente establecida a través del método "Exception" y examinada por el método "trap".
on_test_failure
Un callback invocado por el método "TestFailure". Las capas en particular pueden querer establecer esto.
test_accessor
El nombre y (opcionalmente) el índice del accesor, cuyo contenido estamos probando actualmente. Mejor accedido a través del método "TestAccessor", y generalmente establecido por los métodos "test" y "accessor", pero si estás escribiendo tus propias pruebas o accesores directamente, podrías necesitar establecerlo. Quizás.

Sé amable: trata las propiedades de etiqueta de otro módulo como tratarías las variables globales de otro módulo. No las uses excepto como se documenta.

Ejemplo:

# en una capa, estableciendo el callback para TestFailure:
$self->Prop('Test::Trap::Builder')->{on_test_failure} = \&mydiag;

DESTROY

Esto limpia las propiedades de etiqueta cuando el objeto de trampa es destruido. No intentes crear un trampero que no llame a esto; se confundirá.

Si tu trampero necesita su propio "DESTROY", asegúrate de que también llame a este:

sub DESTROY {
  my $self = shift;
  # haz lo tuyo
  $self->Test::Trap::Builder::DESTROY;
  # y más cosas
}

Run

Una capa que finaliza debería llamar a este método para ejecutar el código del usuario. Solo debe llamarse en un contexto dinámico en el que se estén aplicando capas.

Next

Cada capa no finalizadora debería llamar a este método (o a uno equivalente) para progresar a la siguiente capa. Solo debe llamarse en un contexto dinámico en el que se estén aplicando capas. Ten en cuenta que este método no necesita retornar, por lo que las acciones de desmontaje deberían probablemente registrarse con el método Teardown (ver abajo).

Teardown SUBS

Si tu capa quiere limpiar su configuración, puede usar este método para registrar cualquier número de acciones de desmontaje, que se realizarán (en orden inverso de registro) una vez que se haya ejecutado el código del usuario. Solo debe llamarse en un contexto dinámico en el que se estén aplicando capas.

TestAccessor

Devuelve una cadena de la forma "NOMBRE(INDICE)", donde NOMBRE e INDICE son el nombre del accesor y el índice (si lo hay) que se está probando. Solo debe llamarse en el contexto dinámico de los callbacks de prueba.

Esto está pensado para diagnósticos:

diag( sprintf 'Esperado %s en %s; obtenido %s',
      $expected, $self->TestAccessor, dump($got),
    );

TestFailure

Ejecuta la propiedad de etiqueta "on_test_failure" (si existe) en el objeto de trampa. Si estás escribiendo pruebas no registradas, podrías querer incluir (alguna variación de) esta llamada:

$ok or $self->TestFailure;

Exception STRINGS

Las implementaciones de capas pueden encontrarse con situaciones excepcionales, en las que desean que toda la trampa falle. Desafortunadamente, otra capa puede estar atrapando excepciones ordinarias, por lo que necesitas algún tipo de magia para lanzar una excepción que no se pueda atrapar. Esta es una forma conveniente.

Solo debe llamarse en un contexto dinámico en el que se estén aplicando capas.

Nota: El método Exception no funcionará si se llama fuera del flujo de control regular, como dentro de un método DESTROY o un manejador de señales. Si algo así sucede, CORE::exit se llamará con un código de salida de 8.

Nota: Las llamadas directas al método Exception dentro de closures pueden crear referencias circulares y, por lo tanto, fugas. Para evitar esto, obten un "ExceptionFunction" y llámalo desde el closure en su lugar.

ExceptionFunction

Este método devuelve una función que puede ser llamada con el mismo efecto que llamar al método "Exception", permitiendo que los closures lancen excepciones sin crear referencias circulares al cerrar sobre el propio objeto de trampa.

Para ilustrar:

# esto creará una cadena de referencia circular:
# el objeto de trampa tiene colección de propiedades tiene closure de desmontaje tiene objeto de trampa
$self->Teardown($_) for sub {
  do_stuff() or $self->Exception("Stuff didn't work.");
};
# esto romperá la cadena de referencia circular:
# el closure de desmontaje ya no tiene el objeto de trampa
$Exception = $self->ExceptionFunction;
$self->Teardown($_) for sub {
  do_things() or $Exception->("Things didn't work.");
};

MÉTODOS

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

new

Devuelve un objeto singleton. No espere que este módulo funcione con una instancia diferente de esta clase.

trap TRAPPER, GLOBREF, LAYERARRAYREF, CODE

Implementa una trampa para el módulo TRAPPER, aplicando las capas de LAYERARRAYREF, atrapando varios resultados del CODE del usuario y almacenando el objeto de trampa en la ranura escalar de GLOBREF.

En la mayoría de los casos, el capturador debería exportar convenientemente una función que llame a este método.

layer NAME, CODE

Registra una capa por NAME en el capturador que llama. Cuando se aplica la capa, se invocará el CODE en el objeto de trampa que se está construyendo, sin argumentos, y debería llamar al método Next() o Run() o equivalente.

output_layer NAME, GLOBREF

Registra (por NAME y para el capturador que llama) una capa para capturar la salida en el manejador de archivos de GLOBREF, utilizando NAME también como nombre del atributo.

capture_strategy NAME, [CODE]

Cuando se llama con dos argumentos, registra (por NAME y globalmente) una estrategia para las capas de captura de salida. Cuando se llama con un solo argumento, busca y devuelve la estrategia registrada por NAME (o undef).

Cuando se aplica una capa que utiliza esta estrategia, se llamará al CODE en el objeto de trampa, con el nombre de la capa y el fileno y globref del manejador de salida como argumentos.

output_layer_backend SPEC

Alias de compatibilidad con versiones anteriores del anterior.

first_capture_strategy SPEC

Donde SPEC está vacío, simplemente devuelve.

Donde SPEC es una cadena de nombres separados por comas o punto y coma, recorre los nombres, devolviendo la primera estrategia que encuentra. Muere si no se encuentra ninguna estrategia con ninguno de estos nombres.

first_output_layer_backend SPEC

Alias de compatibilidad con versiones anteriores del anterior.

multi_layer NAME, LAYERS

Registra (por NAME) una capa que simplemente empuja una serie de otras LAYERS en la pila de capas. Si alguna de las LAYERS no es un método anónimo ni el nombre de una capa registrada para el llamador o para un capturador del que hereda, se genera una excepción.

layer_implementation TRAPPER, LAYERS

Devuelve las subrutinas que implementan las LAYERS solicitadas. Si alguna de las LAYERS no es un método anónimo ni el nombre de una capa registrada para o heredada por el TRAPPER, se genera una excepción.

accessor NAMED_ARGS

Genera y registra cualquier número de accesores de acuerdo con NAMED_ARGS, y también genera los métodos de prueba adecuados para estos accesores (ver más abajo).

Se reconocen los siguientes argumentos con nombre:

is_leaveby
Si es verdadero, los métodos de prueba generarán mejores diagnósticos si la trampa no se dejó como se especificó. Además, se generará un método de prueba especial did_ACCESSOR (a menos que ya exista), que simplemente pasará siempre que la trampa se dejara como se especificó.
is_array
Si es verdadero, los accesores simples serán inteligentes sobre el contexto y los argumentos, devolviendo un arrayref sin argumentos (en cualquier contexto), un slice de array en contexto de lista (con cualquier número de argumentos), y el elemento indexado por el primer argumento en caso contrario.
simple
Debería ser una referencia a un array de nombres de accesores. Para cada nombre, se generará y registrará un accesorio (asumiendo una trampa basada en hash con nombres de accesorios como claves).
flexible
Debería ser una referencia a un hash. Para cada par, un nombre y una implementación, se genera y registra un accesorio.

test NAME, ARGSPEC, CODE

Registra una función de devolución de llamada de prueba por NAME y para el capturador que llama.

Los capturadores heredan las funciones de devolución de llamada de prueba como métodos (aunque no se implementan como tales; no espere encontrarlos en la tabla de símbolos).

Los métodos de prueba del formulario ACCESSOR_TEST estarán disponibles (directa o por herencia) para cada capturador que registre o herede tanto el accesorio llamado ACCESSOR como la prueba llamada TEST.

(Con más detalle, el método se generará en cada capturador que (1) registre tanto la prueba como el accesorio, o (2) registre uno y herede el otro).

Cuando se llama al método de prueba, primero se probará cualquier condición implícita de salida y, si pasa (o no había ninguna), se llamará al CODE con argumentos de acuerdo con las palabras encontradas en la cadena ARGSPEC:

trap
El objeto de trampa.
entirety
El valor de retorno del ACCESSOR cuando se llama sin argumentos.
element
El valor de retorno del ACCESSOR cuando se llama con índice, si corresponde (es decir, para accesorios de array). El índice no es aplicable a accesorios escalares, por lo que estos todavía se llaman sin índice.

El índice, cuando sea aplicable, se tomará de los argumentos del método de prueba.

predicate
Contra qué se debe probar el valor de retorno del ACCESSOR (tomado de los argumentos del método de prueba). (Puede haber cualquier número fijo de predicados).
name
El nombre de la prueba (tomado de los argumentos del método de prueba).

EJEMPLO

Un ejemplo completo, que implementa una capa de timeout (dependiendo de la presencia de Time::HiRes::ualarm), una capa de simpletee (imprimiendo stdout/stderr capturado a los manejadores de archivos originales después de que la trampa se haya activado), y una plantilla de método de prueba cmp_ok:

package My::Test::Trap;
use base 'Test::Trap'; # for example
use Test::Trap::Builder;
my $B = Test::Trap::Builder->new;
# example (layer:timeout):
use Time::HiRes qw/ualarm/;
$B->layer( timeout => $_ ) for sub {
  my $self = shift;
  eval {
    local $SIG{ALRM} = sub {
      $self->{timeout} = 1; # simple truth
      $SIG{ALRM} = sub {die};
      die;
    };
    ualarm 1000, 1; # one second max, then die repeatedly!
    $self->Next;
  };
  alarm 0;
  if ($self->{timeout}) {
    $self->{leaveby} = 'timeout';
    delete $self->{$_} for qw/ die exit return /;
  }
};
$B->accessor( is_leaveby => 1,
              simple => ['timeout'],
            );
# example (layer:simpletee):
$B->layer( simpletee => $_ ) for sub {
  my $self = shift;
  for (qw/ stdout stderr /) {
    exists $self->{$_} or $self->Exception("Too late to tee $_");
  }
  $self->Teardown($_) for sub {
    print STDOUT $self->{stdout} if exists $self->{stdout};
    print STDERR $self->{stderr} if exists $self->{stderr};
  };
  $self->Next;
};
# no accessor for this layer
$B->multi_layer( flow => qw/ raw die exit timeout / );
$B->multi_layer( default => qw/ flow stdout stderr warn simpletee / );
$B->test_method( cmp_ok => 1, 2, \&Test::More::cmp_ok );

OBSERVACIONES

La interfaz de este módulo probablemente seguirá en cierta medida en fluctuación durante algún tiempo.

Las diferentes estrategias para las capas de captura de salida tienen sus propias observaciones; consulte Test::Trap::Builder::Tempfile, Test::Trap::Builder::PerlIO, Test::Trap::Builder::SystemSafe.

La herencia múltiple no es (¿todavía?) completamente compatible. Si un padre ha registrado una función de devolución de llamada de prueba "X" y otro ha registrado un accesorio "Y", el método de prueba "Y_X" no se generará.

¿Hilos? Ni idea. Incluso podría funcionar correctamente.
