NOMBRE

Text::CSV_PP - Módulo Perl puro compatible con Text::CSV_XS

SINOPSIS

Esta sección está tomada de Text::CSV_XS.

# Interfaz funcional
use Text::CSV_PP qw( csv );
# Lee el archivo completo en memoria
my $aoa = csv (in => "datos.csv");    # como array de array
my $aoh = csv (in => "datos.csv",
               headers => "auto");   # como array de hash
# Escribe array de arrays como archivo csv
csv (in => $aoa, out => "archivo.csv", sep_char => ";");
# Muestra solo las líneas donde "codigo" es impar
csv (in => "datos.csv", filter => { code => sub { $_ % 2 }});
# Interfaz de objeto
use Text::CSV_PP;
my @filas;
# Lee/analiza CSV
my $csv = Text::CSV_PP->new ({ binary => 1, auto_diag => 1 });
open my $fh, "<:encoding(utf8)", "prueba.csv" or die "prueba.csv: $!";
while (my $fila = $csv->getline ($fh)) {
    $fila->[2] =~ m/patron/ or next; # El 3er campo debe coincidir
    push @filas, $fila;
    }
close $fh;
# y escribe como CSV
open $fh, ">:encoding(utf8)", "nuevo.csv" or die "nuevo.csv: $!";
$csv->say ($fh, $_) for @filas;
close $fh or die "nuevo.csv: $!";

DESCRIPCIÓN

Text::CSV_PP es un módulo Perl puro que proporciona facilidades para la composición y descomposición de valores separados por comas. Es (casi) compatible con el mucho más rápido Text::CSV_XS, y se utiliza principalmente como su módulo de reserva cuando se utiliza el módulo Text::CSV sin haber instalado Text::CSV_XS. Si no tiene ninguna razón para usar este módulo directamente, utilice Text::CSV para obtener un aumento de velocidad y portabilidad (o quizás Text::CSV_XS cuando escriba un script único y no necesite preocuparse por la portabilidad).

Las siguientes advertencias están tomadas de la documentación de Text::CSV_XS.

Saltos de línea incrustados

Nota importante: El comportamiento predeterminado es aceptar solo caracteres ASCII en el rango de 0x20 (espacio) a 0x7E (tilde). Esto significa que los campos no pueden contener saltos de línea. Si sus datos contienen saltos de línea incrustados en campos, o caracteres por encima de 0x7E (tilde), o datos binarios, debe establecer "binary => 1" en la llamada a "new". Para cubrir la gama más amplia de opciones de análisis, siempre querrá establecer binario.

Pero todavía tiene el problema de que tiene que pasar una línea correcta al método "parse", lo cual es más complicado desde el punto de vista habitual de uso:

my $csv = Text::CSV_PP->new ({ binary => 1, eol => $/ });
while (<>) {           #  INCORRECTO!
    $csv->parse ($_);
    my @campos = $csv->fields ();
    }

esto fallará, ya que el "while" podría leer líneas incorrectas: no se preocupa por el entrecomillado. Si necesita admitir saltos de línea incrustados, la forma de proceder es no pasar "eol" en el analizador (acepta "\n", "\r", y "\r\n" por defecto) y luego

my $csv = Text::CSV_PP->new ({ binary => 1 });
open my $fh, "<", $archivo or die "$archivo: $!";
while (my $fila = $csv->getline ($fh)) {
    my @campos = @$fila;
    }

La forma antigua (más antigua) de usar manejadores de archivo globales todavía es compatible

while (my $fila = $csv->getline (*ARGV)) { ... }

Unicode

Unicode solo se prueba para funcionar con perl-5.8.2 y superior.

Ver también "BOM".

La forma más sencilla de asegurar que se utiliza la codificación correcta para la entrada y la salida es estableciendo capas en los manejadores de archivo, o estableciendo el argumento "encoding" para "csv".

 open my $fh, "<:encoding(UTF-8)", "in.csv"  or die "in.csv: $!";
o
 my $aoa = csv (in => "in.csv",     encoding => "UTF-8");
 open my $fh, ">:encoding(UTF-8)", "out.csv" or die "out.csv: $!";
o
 csv (in => $aoa, out => "out.csv", encoding => "UTF-8");

Al analizar (tanto para "getline" como para "parse"), si la fuente está marcada como UTF8, entonces todos los campos que estén marcados como binarios también estarán marcados como UTF8.

Al combinar ("print" e "combine"): si alguno de los campos combinados estaba marcado como UTF8, la cadena resultante se marcará como UTF8. Tenga en cuenta, sin embargo, que todos los campos antes del primer campo marcado como UTF8 y que contenían caracteres de 8 bits que no se actualizaron a UTF8, estos también serán "bytes" en la cadena resultante, lo que posiblemente cause errores inesperados. Si pasa datos de diferente codificación, o no sabe si hay una codificación diferente, fuerce su actualización antes de pasarlos:

$csv->print ($fh, [ map { utf8::upgrade (my $x = $_); $x } @datos ]);

Para un control completo sobre la codificación, utilice Text::CSV::Encoded:

use Text::CSV::Encoded;
my $csv = Text::CSV::Encoded->new ({
    encoding_in  => "iso-8859-1", # la codificación entra en Perl
    encoding_out => "cp1252",     # la codificación sale de Perl
    });
$csv = Text::CSV::Encoded->new ({ encoding  => "utf8" });
# combine () y print () aceptan datos codificados en utf8 *literalmente*
# parse () y getline () devuelven datos codificados en utf8 *literalmente*
$csv = Text::CSV::Encoded->new ({ encoding  => undef }); # predeterminado
# combine () y print () aceptan datos marcados como UTF8
# parse () y getline () devuelven datos marcados como UTF8

BOM

El manejo de BOM (o Byte Order Mark) solo está disponible dentro del método "header". Este método admite las siguientes codificaciones: "utf-8", "utf-1", "utf-32be", "utf-32le", "utf-16be", "utf-16le", "utf-ebcdic", "scsu", "bocu-1", y "gb-18030". Ver Wikipedia https://en.wikipedia.org/wiki/Byte_order_mark.

Si un archivo tiene un BOM, la forma más fácil de lidiar con él es

my $aoh = csv (in => $archivo, detect_bom => 1);

Todos los registros se codificarán según el BOM detectado.

Esto implica una llamada al método "header", que por defecto también establece los "column_names". Así que esto no es lo mismo que

my $aoh = csv (in => $archivo, headers => "auto");

que solo lee el primer registro para establecer "column_names" pero ignora cualquier significado de un posible BOM presente.

MÉTODOS

Esta sección también está tomada de Text::CSV_XS.

version

(Método de clase) Devuelve la versión actual del módulo.

new

(Método de clase) Devuelve una nueva instancia de la clase Text::CSV_PP. Los atributos se describen mediante la referencia hash (opcional) "\%attr".

my $csv = Text::CSV_PP->new ({ atributos ... });

Los siguientes atributos están disponibles:

eol

my $csv = Text::CSV_PP->new ({ eol => $/ });
          $csv->eol (undef);
my $eol = $csv->eol;

El string de fin de línea a añadir a las filas para "print" o el separador de registros para "getline".

Cuando no se pasa en una instancia de parser, el comportamiento predeterminado es aceptar "\n", "\r", y "\r\n", por lo que probablemente sea más seguro no especificar "eol" en absoluto. Pasar "undef" o una cadena vacía se comporta igual.

Cuando no se pasa en una instancia de generación, los registros no se terminan en absoluto, por lo que probablemente sea prudente pasar algo que se espere. Una opción segura para "eol" en salida es $/ o "\r\n".

Los valores comunes para "eol" son

Mantén toda la estructura del archivo.

Si ambos $/ y "eol" igualan "\015", la corrección de líneas que terminan solo con un Retorno de línea sin Salto de línea será "parse" correcta.

El "eol_tipo"

my $eol = $csv->eol_type;

Este método readonly devuelve el estado interno que se considera el EOL válido para el parsing.

El "sep_char"

my $csv = Text::CSV_PP->new ({ sep_char => ";" });
        $csv->sep_char (";");
my $c = $csv->sep_char;

El carácter usado para separar campos, por defecto una coma. (","). Limitado a un carácter único, generalmente en el rango de 0x20 (espacio) a 0x7E (tildes). Cuando se requieran secuencias más largas, use "sep".

El carácter separador no puede ser igual al carácter de comillas o al de escape.

El "sep"

my $csv = Text::CSV_PP->new ({ sep => "\N{FULLWIDTH COMMA}" });
          $csv->sep (";");
my $sep = $csv->sep;

Los caracteres usados para separar campos, por defecto indefinido. Limitado a 8 bytes.

Cuando se establece, sobrescribe "sep_char". Si su longitud es de un byte, actúa como un alias para "sep_char".

El "quote_char"

my $csv = Text::CSV_PP->new ({ quote_char => "'" });
        $csv->quote_char (undef);
my $c = $csv->quote_char;

El carácter para entrecomillar los campos que contienen espacios o datos binarios, por defecto el carácter de comillas doble ("\""). Un valor de undef suprime las comillas (solo en casos simples). Limitado a un carácter único, generalmente en el rango de 0x20 (espacio) a 0x7E (tildes). Cuando se requieran secuencias más largas, use "quote".

"quote_char" no puede ser igual a "sep_char".

El "quote"

my $csv = Text::CSV_PP->new ({ quote => "\N{FULLWIDTH QUOTATION MARK}" });
            $csv->quote ("'");
my $quote = $csv->quote;

Los caracteres usados para entrecomillar los campos, por defecto indefinido. Limitado a 8 bytes.

Cuando se establece, sobrescribe "quote_char". Si su longitud es de un byte, actúa como un alias para "quote_char".

Este método no soporta "undef". Use "quote_char" para desactivar las comillas.

El "escape_char"

my $csv = Text::CSV_PP->new ({ escape_char => "\" });
        $csv->escape_char (":");
my $c = $csv->escape_char;

El carácter para escapar ciertos caracteres dentro de campos entrecomillados. Este se limita a un carácter único, generalmente en el rango de 0x20 (espacio) a 0x7E (tildes).

El "escape_char" por defecto es el carácter de comillas doble ("\""). En otras palabras, es el mismo que el valor por defecto de "quote_char". Esto significa que duplicar el carácter de comillas en un campo lo escapa:

"foo","bar","Escape \"quote mark\" with two \"\"quote marks\"\"","baz"

Si cambias el "quote_char" sin cambiar el "escape_char", el "escape_char" seguirá siendo el carácter de comillas doble ("\""). Si en cambio quieres escapar el "quote_char" duplicándolo, tendrás que cambiar también el "escape_char" para que sea el mismo que el que has cambiado el "quote_char" a.

Establecer "escape_char" a "undef" o "\"" desactivará los escapes y será muy desaconsejado. Esto también desactivará "escape_null".

El carácter de escape no puede ser igual al carácter separador.

El "binary"

my $csv = Text::CSV_PP->new ({ binary => 1 });
        $csv->binary (0);
my $f = $csv->binary;

Si esta propiedad es 1, puedes usar caracteres binarios en campos entrecomillados, incluyendo salto de línea, retorno de carro y bytes "NULL". ("\"" podría ser escapado como "\"0\"".) Por defecto esta función está desactivada.

Si una cadena está marcada como UTF8, "binary" se activará automáticamente cuando se encuentren caracteres binarios no "CR" ni "NL". Nota: una cadena simple como "\x{00a0}" podría ser binaria, pero no marcada como UTF8, por lo que establecer "binary" = 1 aún será una buena opción.

El "strict"

my $csv = Text::CSV_PP->new ({ strict => 1 });
        $csv->strict (0);
my $f = $csv->strict;

Si esta propiedad está establecida en 1, cualquier fila que parsee a un número diferente de campos que la anterior causará un error 2014.

Filas vacías o filas que resulten en cero campos (como líneas de comentario) son excluidas de estos controles.

El "strict_eol"

my $csv = Text::CSV_PP->new ({ strict_eol => 1 });
        $csv->strict_eol (0);
my $f = $csv->strict_eol;

Si esta propiedad está establecida en 0, no se realizan pruebas de consistencia de EOL.

Si esta propiedad está establecida en 1, cualquier fila que parsee con un EOL diferente del EOL de la primera fila causará un aviso. El error se ignorará y el parsing continuará. Este aviso se genera solo una vez. Nota: en datos con diferentes finales de línea, "\r\r" aún generará un error que no puede ignorarse.

Si esta propiedad está establecida en 2 o más, cualquier fila que parsee con un EOL diferente del EOL de la primera fila causará error 2016. La línea que se está parseando en este error podría no estar almacenada en el resultado.

El "skip_empty_rows"

my $csv = Text::CSV_PP->new ({ skip_empty_rows => 1 });
        $csv->skip_empty_rows ("eof");
my $f = $csv->skip_empty_rows;

Esta propiedad define el comportamiento para filas vacías: un "eol" inmediatamente después del inicio de la línea. El comportamiento por defecto es devolver un solo campo vacío.

Esta propiedad solo se usa en parsing. Esta propiedad no es efectiva cuando se utilice "parse" y "fields".

Valores posibles para esta propiedad son

0 | undef
my $csv = Text::CSV_PP->new ({ skip_empty_rows => 0 });
$csv->skip_empty_rows (undef);

No se realiza ninguna acción especial. El resultado será un solo campo vacío.

1 | "skip"
my $csv = Text::CSV_PP->new ({ skip_empty_rows => 1 });
$csv->skip_empty_rows ("skip");

La fila se omite.

2 | "eof" | "stop"
my $csv = Text::CSV_PP->new ({ skip_empty_rows => 2 });
$csv->skip_empty_rows ("eof");

El parsing se detiene como si se hubiera detectado "eof".

3 | "die"
my $csv = Text::CSV_PP->new ({ skip_empty_rows => 3 });
$csv->skip_empty_rows ("die");

El parsing se detiene. El código de error interno se establece en 2015 y el parser se "die".

4 | "croak"
my $csv = Text::CSV_PP->new ({ skip_empty_rows => 4 });
$csv->skip_empty_rows ("croak");

El parsing se detiene. El código de error interno se establece en 2015 y el parser se "croak".

5 | "error"
my $csv = Text::CSV_PP->new ({ skip_empty_rows => 5 });
$csv->skip_empty_rows ("error");

El parsing falla. El código de error interno se establece en 2015.

callback
my $csv = Text::CSV_PP->new ({ skip_empty_rows => sub { [] } });
$csv->skip_empty_rows (sub { [ 42, $., undef, "empty" ] });

La callback se invoca y su resultado se utiliza en su lugar. Si quieres que el parsing se detenga después de la callback, asegúrate de devolver un valor falso.

El valor devuelto de la callback debe ser un array-ref. Cualquier otro tipo causará que el parsing se detenga, por lo que estos son equivalentes en comportamiento:

csv (in => $fh, skip_empty_rows => "stop");
csv (in => $fh. skip_empty_rows => sub { 0; });

Sin parámetros, el valor actual se devuelve: 0, 1, "eof", "die", "croak" o la callback.

combine

This method constructs a CSV record from @fields, returning success or failure. Failure can result from lack of arguments or an argument that contains an invalid character. Upon success, string can be called to retrieve the resultant CSV string. Upon failure, the value returned by string is undefined and error_input could be called to retrieve the invalid argument.

getline

$colref = $csv->getline ($fh);

This is the counterpart to print, just as parse is the counterpart to combine: it parses a row from the filehandle $fh using the getline method associated with $fh and parses this row into an array reference. This array reference is returned by the function, or undef for failure. When $fh does not support getline, you are likely to encounter errors.

When fields are bound with bind_columns the return value is a reference to an empty list.

The string, fields, and status methods become meaningless again.

getline_all

$arrayref = $csv->getline_all ($fh);
$arrayref = $csv->getline_all ($fh, $offset);
$arrayref = $csv->getline_all ($fh, $offset, $length);

This will return a reference to a list of getline ($fh) results. In this call, keep_meta_info is disabled. If $offset is negative, as with splice, only the last abs($offset) records of $fh are taken into consideration. Parameters $offset and $length are expected to be integers. Non-integer values are interpreted as integers without checking.

lines call

0..9  $csv->getline_all ($fh,  0)     # all
8..9  $csv->getline_all ($fh,  8)     # start at 8
-     $csv->getline_all ($fh,  0,  0) # start at 0 first 0 rows
0..4  $csv->getline_all ($fh,  0,  5) # start at 0 first 5 rows
4..5  $csv->getline_all ($fh,  4,  2) # start at 4 first 2 rows
8..9  $csv->getline_all ($fh, -2)     # last 2 rows
6..7  $csv->getline_all ($fh, -4,  2) # first 2 of last  4 rows

getline_hr

The getline_hr and column_names methods work together to allow you to have rows returned as hashrefs. You must call column_names first to declare your column names.

$csv->column_names(qw( code name price description ));
$hr = $csv->getline_hr($fh);
print "Price for $hr->{name} is $hr->{price} EUR\n";

getline_hr will croak if called before column_names.

Note that getline_hr creates a hashref for every row and will be much slower than the combined use of bind_columns and getline, but still offering the same easy-to-use hashref inside the loop:

my @cols = @{$csv->getline($fh)};
$csv->column_names(@cols);
while (my $row = $csv->getline_hr($fh)) {
    print $row->{price};
}

Could easily be rewritten to the much faster:

my @cols = @{$csv->getline($fh)};
my $row = {};
$csv->bind_columns(\@{$row}{@cols});
while ($csv->getline($fh)) {
    print $row->{price};
}

Your mileage may vary depending on the size of the data and the number of rows. With perl-5.14.2, the comparison for a 100,000-line file with 14 columns:

           Rate hashrefs getlines
hashrefs 1.00/s       --     -76%
getlines 4.15/s     313%       --

parse

$status = $csv->parse ($line);

This method decomposes a CSV string into fields, returning success or failure. Failure can result from a lack of argument or the given CSV string being improperly formatted. Upon success, fields can be called to retrieve the decomposed fields. Upon failure, calling fields will return undefined data, and error_input can be called to retrieve the invalid argument.

You may use the types method for setting column types. See the description of types below.

The $line argument is supposed to be a simple scalar. Everything else is supposed to cause a croak and set error 1500.

fragment

This function attempts to implement RFC7111 (URI Fragment Identifiers for the text/csv Media Type) - https://datatracker.ietf.org/doc/html/rfc7111

my $AoA = $csv->fragment ($fh, $spec);

In specifications, "*" is used to specify the *last* item, a dash ("-") to indicate a range. All indices are 1-based: the first row or column has index 1. Selections can be combined with the semicolon (';').

When using this method in combination with column_names, the returned reference will point to a list of hashes instead of a list of lists. A disjointed cell-based combined selection might return rows with different numbers of columns, making the use of hashes unpredictable.

$csv->column_names("Name", "Age");
my $AoH = $csv->fragment($fh, "col=3;8");

If the after_parse callback is active, it is also called on every line parsed and skipped before the fragment.

row
row=4
row=5-7
row=6-*
row=1-2;4;6-*
col
col=2
col=1-3
col=4-*
col=1-2;4;7-*
cell
In cell-based selection, the comma (",") is used to pair row and column 
cell=4,1

The range operator ("-") using cells can be used to define top-left and bottom-right cell locations

cell=3,1-4,6

The "*" is only allowed in the second part of a pair

cell=3,2-*,2    # row 3 till end, only column 2
cell=3,2-3,*    # column 2 till end, only row 3
cell=3,2-*,*    # strip row 1 and 2, and column 1

Cells and cell ranges may be combined with , possibly resulting in rows with different numbers of columns

cell=1,1-2,2;3,3-4,4;1,4;4,1

Disjointed selections will only return selected cells. The cells that are not specified will not be included in the returned set, not even as undef. As an example, given a CSV like

11,12,13,...19
21,22,...28,29
:            :
91,...97,98,99

with "cell=1,1-2,2;3,3-4,4;1,4;4,1" will return:

11,12,14
21,22
33,34
41,43,44

Overlapping cell-specs will return those cells only once. So "cell=1,1-3,3;2,2-4,4;2,3;4,2" will return:

11,12,13
21,22,23,24
31,32,33,34
42,43,44

RFC7111 https://datatracker.ietf.org/doc/html/rfc7111 does not allow different types of specs to be combined (either row *or* col *or* cell). Passing an invalid fragment specification will croak and set error 2013.

Set the "keys" that will be used in the getline_hr calls. If no keys (column names) are passed, it will return the current setting as a list.

column_names accepts a list of scalars (the column names) or a single arrayref, so you can pass the return value from getline too:

"column_names" no comprueba duplicados en absoluto, lo que puede generar resultados inesperados. Las entradas indefinidas se reemplazarán con la cadena "\cAUNDEF\cA", así que

encabezado

Este método NO funciona en perl-5.6.x

Analiza el encabezado CSV y establece "sep", los nombres de columna y la codificación.

my @hdr = $csv->header ($fh);
$csv->header ($fh, { sep_set => [ ";", ",", "|", "\t" ] });
$csv->header ($fh, { detect_bom => 1, munge_column_names => "lc" });

El primer argumento debe ser un manejador de archivo.

Este método restablece algunas propiedades del objeto, ya que se supone que solo se invocará una vez por archivo o flujo. Dejará los atributos "column_names" y "bound_columns" intactos si la configuración de nombres de columna está deshabilitada. La lectura de encabezados en objetos previamente procesados puede fallar en perl-5.8.0 y versiones anteriores.

Suponiendo que el archivo abierto para el análisis tiene un encabezado, y que el encabezado no contiene caracteres problemáticos como saltos de línea incrustados, lea la primera línea del manejador abierto y luego detecte automáticamente si el encabezado separa los nombres de columna con un carácter de la lista de separadores permitidos.

Si alguno de los separadores permitidos coincide y ninguno de los *otros* separadores permitidos coincide, establezca "sep" en ese separador para la instancia actual de CSV_PP y úselo para analizar la primera línea, mapear esos a minúsculas y usar eso para establecer los "column_names" de la instancia:

my $csv = Text::CSV_PP->new ({ binary => 1, auto_diag => 1 });
open my $fh, "<", "file.csv";
binmode $fh; # for Windows
$csv->header ($fh);
while (my $row = $csv->getline_hr ($fh)) {
    ...
    }

Si el encabezado está vacío, contiene más de un separador único entre el conjunto permitido, contiene campos vacíos o contiene campos idénticos (después de la normalización), fallará con los errores 1010, 1011, 1012 o 1013 respectivamente.

Si el encabezado contiene saltos de línea incrustados o no es un CSV válido de alguna otra manera, este método fallará y dejará el error de análisis sin tocar.

Una llamada exitosa a "header" siempre establecerá el "sep" del objeto $csv. Este comportamiento no se puede deshabilitar.

valor de retorno

En caso de error, este método fallará.

En contexto de lista, se devolverán los encabezados, ya sea que se utilicen para establecer "column_names" o no.

En contexto escalar, se devuelve la propia instancia. **Nota**: los valores tal como se encuentran en el encabezado se **perderán** si "set_column_names" es falso.

Opciones

sep_set
$csv->header ($fh, { sep_set => [ ";", ",", "|", "\t" ] });

La lista de separadores legales por defecto es "[ ";", "," ]" y puede cambiarse con esta opción. Como esta es probablemente la opción más utilizada, se puede pasar sola como un argumento sin nombre:

$csv->header ($fh, [ ";", ",", "|", "\t", "::", "\x{2063}" ]);

Se permiten secuencias multibyte, tanto de varios caracteres como Unicode. Ver "sep".

detect_bom
$csv->header ($fh, { detect_bom => 1 });

El comportamiento predeterminado es detectar si la línea de encabezado comienza con un BOM. Si el encabezado tiene un BOM, úselo para establecer la codificación de $fh. Este comportamiento predeterminado se puede deshabilitar pasando un valor falso a "detect_bom".

Las codificaciones compatibles a partir de BOM son: UTF-8, UTF-16BE, UTF-16LE, UTF-32BE y UTF-32LE. BOM también admite UTF-1, UTF-EBCDIC, SCSU, BOCU-1 y GB-18030, pero Encode no (todavía). UTF-7 no es compatible.

Si se detectó un BOM compatible como inicio del flujo, se almacena en el atributo del objeto "ENCODING".

my $enc = $csv->{ENCODING};

La codificación se usa con "binmode" en $fh.

Si el manejador se abrió en una codificación (correcta), este método **no** alterará la codificación, ya que verifica los **bytes** iniciales de la primera línea. En caso de que el flujo comience con un BOM decodificado ("U+FEFF"), "{ENCODING}" será "" (vacío) en lugar del predeterminado "undef".

row_fields

In cases where the number of fields in the current row differs from the number of fields in the previous row (e.g., when a field is inserted or deleted, or when the previous row had more), the first two fields already have been assigned the values of the current row, while the rest of the fields will still hold the values of the previous row. eof

$eof = $csv->eof ();

If "parse" or "getline" was used with an IO stream, this method will return true (1) if the last call hit end of file, otherwise it will return false (''). This is useful to see the difference between a failure and end of file.

Note that if the parsing of the last line caused an error, "eof" is still true. That means that if you are not using "auto_diag", an idiom like

while (my $row = $csv->getline ($fh)) {
    # ...
    }
$csv->eof or $csv->error_diag;

will not report the error. You would have to change that to

while (my $row = $csv->getline ($fh)) {
    # ...
    }
+$csv->error_diag and $csv->error_diag;

0x0004
"CSV_FLAGS_ERROR_IN_FIELD"
The field was invalid.

is_quoted

my $quoted = $csv->is_quoted ($column_idx);

where $column_idx is the (zero-based) index of the column in the last result of "parse".

This returns a true value if the data in the indicated column was enclosed in "quote_char" quotes. This might be important for fields where content ",20070108," is to be treated as a numeric value, and where ","20070108"," is explicitly marked as character string data.

This method is only valid when "keep_meta_info" is set to a true value.

is_binary

my $binary = $csv->is_binary ($column_idx);

where $column_idx is the (zero-based) index of the column in the last result of "parse".

This returns a true value if the data in the indicated column contained any byte in the range "[\x00-\x08,\x10-\x1F,\x7F-\xFF]".

This method is only valid when "keep_meta_info" is set to a true value.

is_missing

my $missing = $csv->is_missing ($column_idx);

where $column_idx is the (zero-based) index of the column in the last result of "getline_hr".

$csv->keep_meta_info (1);
while (my $hr = $csv->getline_hr ($fh)) {
    $csv->is_missing (0) and next; # This was an empty line
    }

When using "getline_hr", it is impossible to tell if the parsed fields are "undef" because they where not filled in the "CSV" stream or because they were not read at all, as all the fields defined by "column_names" are set in the hash-ref. If you still need to know if all fields in each row are provided, you should enable "keep_meta_info" so you can check the flags.

If "keep_meta_info" is "false", "is_missing" will always return "undef", regardless of $column_idx being valid or not. If this attribute is "true" it will return either 0 (the field is present) or 1 (the field is missing).

A special case is the empty line. If the line is completely empty - after dealing with the flags - this is still a valid CSV line: it is a record of just one single empty field. However, if "keep_meta_info" is set, invoking "is_missing" with index 0 will now return true.

status

$status = $csv->status ();

This method returns the status of the last invoked "combine" or "parse" call. Status is success (true: 1) or failure (false: "undef" or 0).

Note that as this only keeps track of the status of above mentioned methods, you are probably looking for "error_diag" instead.

error_input

$bad_argument = $csv->error_input ();

This method returns the erroneous argument (if it exists) of "combine" or "parse", whichever was called more recently. If the last invocation was successful, "error_input" will return "undef".

Depending on the type of error, it might also hold the data for the last error-input of "getline".

If (and only if) an error occurred, this function returns the diagnostics of that error.

If called in void context, this will print the internal error code and the associated error message to STDERR.

If called in list context, this will return the error code and the error message in that order. If the last error was from parsing, the rest of the values returned are a best guess at the location within the line that was being parsed. Their values are 1-based. The position currently is index of the byte at which the parsing failed in the current record. It might change to be the index of the current character in a later release. The records is the index of the record parsed by the csv instance. The field number is the index of the field the parser thinks it is currently trying to parse. See examples/csv-check for how this can be used. If $xs is set, it is the line number in XS where the error was triggered (for debugging). When called as a class method or a direct function call, the diagnostics are that of the last "new" call.

ag

This is the new interface for parsing CSV files. It is recommended over the old csv function.

   use Text::CSV_PP qw( ag );
   my $aoa = ag( 'file.csv' )
   or die Text::CSV_PP->error_diag;
   my $aoh = ag( \$string_data, { headers => 'auto' } )
   or die Text::CSV_PP->error_diag;
   my $error_code = ag(
       in  => \@array_of_arrays,
       out => \*STDOUT,
   );
   if ( $error_code ) {
       warn Text::CSV_PP->error_diag(@$error_code);
   }

This function aims at a simple interface, as opposed to the `new` and `parse` methods which are intended for more fine-grained control.

This function is not exported by default and should be explicitly requested:

   use Text::CSV_PP qw( ag );

The arguments to ag are parsed as follows:

  • If the first argument is a scalar (string), it is treated as the input filename.

  • If the first argument is a filehandle or glob, it is treated as the input source.

  • If the first argument is a reference to a scalar (string), it is treated as the input string.

  • If the first argument is a reference to an array (array-ref), it is treated as the input structure (e.g. AoA or AoH).

  • Any subsequent arguments are treated as key-value pairs for configuring the underlying Text::CSV_PP object.

The return value depends on the context:

  • In list context (or array context), it returns a reference to an array of arrays (AoA) or a reference to an array of hashes (AoH) on success, or an empty list on failure.

  • In scalar context, it returns the number of rows parsed on success, or 0 on failure.

  • If the out attribute is provided, it returns the error code (0 on success, non-zero on failure). The error diagnostic can be retrieved using Text::CSV_PP->error_diag().

Common attributes include:

bom
If set to true, the BOM (Byte Order Mark) will be detected and handled.
binary
If set to true, the CSV is treated as binary data. This is the default.
decoding
Specifies the character encoding for input. Equivalent to the encoding attribute.
eol
Specifies the end-of-line characters. Defaults to "\r\n".
error_diag
When used with out, this attribute can be set to a code reference to capture error diagnostics.
escape_char
Specifies the escape character. Defaults to ".
filter
A code reference or hash reference to filter rows.
headers
Specifies how to handle headers. Can be undef (no headers), 0 (no headers), 1 (use first row as headers), or a string (use as header names).
in
Specifies the input source. Can be a filename, filehandle, glob, or scalar reference.
key
Used when the input is an AoA and the output is an AoH. Specifies the column name to use as the key for the hash.
out
Specifies the output destination. Can be a filename, filehandle, glob, or scalar reference.
parse_default
If set to true, the default parsing behavior of Text::CSV_PP will be used.
quote_char
Specifies the quote character. Defaults to ".
sep_char
Specifies the separator character. Defaults to ,.
strict_eol
If set to true, the end-of-line characters must be strictly matched.
skip_lines
Number of lines to skip at the beginning of the input.

Example of reading a file into an array of arrays:

   use Text::CSV_PP qw( ag );
   my $aoa = ag('data.csv')
   or die Text::CSV_PP->error_diag;
   # $aoa is now an array reference containing arrays of fields.

Example of reading a file into an array of hashes:

   use Text::CSV_PP qw( ag );
   my $aoh = ag('data.csv', headers => 'auto')
   or die Text::CSV_PP->error_diag;
   # $aoh is now an array reference containing hash references,
   # where keys are taken from the first row of the CSV.

Example of writing an array of arrays to a file:

   use Text::CSV_PP qw( ag );
   my $data = [ [ 'Name', 'Age' ], [ 'Alice', 30 ], [ 'Bob', 25 ] ];
   my $err = ag(in => $data, out => 'output.csv');
   if ($err) {
       die Text::CSV_PP->error_diag(@$err);
   }

Example of streaming data from a filehandle to another:

   use Text::CSV_PP qw( ag );
   open my $in_fh, '<', 'input.csv';
   open my $out_fh, '>', 'output.csv';
   my $err = ag(in => $in_fh, out => $out_fh, sep_char => ';');
   if ($err) {
       die Text::CSV_PP->error_diag(@$err);
   }
   close $in_fh;
   close $out_fh;

Note: The ag function automatically handles diagnostics. If you are dealing with errors, you can reset them by calling ag(0).

FUNCTIONS

csv

This function is not exported by default and should be explicitly requested:

use Text::CSV_PP qw( csv );

This is a high-level function that aims at simple (user) interfaces. This can be used to read/parse a "CSV" file or stream (the default behavior) or to produce a file or write to a stream (define the "out" attribute). It returns an array- or hash-reference on parsing (or "undef" on fail) or the numeric value of "error_diag" on writing. When this function fails you can get to the error using the class call to "error_diag"

my $aoa = csv (in => "test.csv") or
    die Text::CSV_PP->error_diag;

Note that failure here is the inability to start the parser, like when the input does not exist or the arguments are unknown or conflicting. Run-time parsing errors will return a valid reference, which can be empty, but still contains all results up till the error. See "on_error".

This function takes the arguments as key-value pairs. This can be passed as a list or as an anonymous hash:

my $aoa = csv (  in => "test.csv", sep_char => ";");
my $aoh = csv ({ in => $fh, headers => "auto" });

The arguments passed consist of two parts: the arguments to "csv" itself and the optional attributes to the "CSV" object used inside the function as enumerated and explained in "new".

If not overridden, the default option used for CSV is

auto_diag   => 1
escape_null => 0
strict_eol  => 1

The option that is always set and cannot be altered is

binary      => 1

As this function will likely be used in one-liners, it allows "quote" to be abbreviated as "quo", and "escape_char" to be abbreviated as "esc" or "escape".

Alternative invocations:

my $aoa = Text::CSV_PP::csv (in => "file.csv");
my $csv = Text::CSV_PP->new ();
my $aoa = $csv->csv (in => "file.csv");

In the latter case, the object attributes are used from the existing object and the attribute arguments in the function call are ignored:

my $csv = Text::CSV_PP->new ({ sep_char => ";" });
my $aoh = $csv->csv (in => "file.csv", bom => 1);

will parse using ";" as "sep_char", not ",".

in

Used to specify the source. "in" can be a file name (e.g. "file.csv"), which will be opened for reading and closed when finished, a file handle (e.g. $fh or "FH"), a reference to a glob (e.g. "\*ARGV"), the glob itself (e.g. *STDIN), or a reference to a scalar (e.g. "\q{1,2,"csv"}").

When used with "out", "in" should be a reference to a CSV structure (AoA or AoH) or a CODE-ref that returns an array-reference or a hash-reference. The code-ref will be invoked with no arguments.

my $aoa = csv (in => "file.csv");
open my $fh, "<", "file.csv";
my $aoa = csv (in => $fh);
my $csv = [ [qw( Foo Bar )], [ 1, 2 ], [ 2, 3 ]];
my $err = csv (in => $csv, out => "file.csv");

If called in void context without the "out" attribute, the resulting ref will be used as input to a subsequent call to csv:

csv (in => "file.csv", filter => { 2 => sub { length > 2 }})

will be a shortcut to

csv (in => csv (in => "file.csv", filter => { 2 => sub { length > 2 }}))

where, in the absence of the "out" attribute, this is a shortcut to

csv (in  => csv (in => "file.csv", filter => { 2 => sub { length > 2 }}),
     out => *STDOUT)

out

csv (in => $aoa,  out => "file.csv");
csv (in => $aoa,  out => $fh);
csv (in => $aoa,  out =>   STDOUT);
csv (in => $aoa,  out =>  *STDOUT);
csv (in => $aoa,  out => \*STDOUT);
csv (in => $aoa,  out => \my $data);
csv (in => $aoa,  out =>  undef);
csv (in => $aoa,  out => \"skip");
csv (in => $fh,   out => \@aoa);
csv (in => $fh,   out => \@aoh, bom => 1);
csv (in => $fh,   out => \%hsh, key => "key");
csv (in => $file, out => $file);
csv (in => $file, out => $fh);
csv (in => $fh,   out => $file);
csv (in => $fh,   out => $fh);

In output mode, the default CSV options when producing CSV are

eol       => "\r\n"

The "fragment" attribute is ignored in output mode.

"out" can be a file name (e.g. "file.csv"), which will be opened for writing and closed when finished, a file handle (e.g. $fh or "FH"), a reference to a glob (e.g. "\*STDOUT"), the glob itself (e.g. *STDOUT), or a reference to a scalar (e.g. "\my $data").

csv (in => sub { $sth->fetch },            out => "dump.csv");
csv (in => sub { $sth->fetchrow_hashref }, out => "dump.csv",
     headers => $sth->{NAME_lc});

When a code-ref is used for "in", the output is generated per invocation, so no buffering is involved. This implies that there is no size restriction on the number of records. The "csv" function ends when the coderef returns a false value.

If "out" is set to a reference of the literal string "skip", the output will be suppressed completely, which might be useful in combination with a filter for side effects only.

my %cache;
csv (in    => "dump.csv",
     out   => \"skip",
     on_in => sub { $cache{$_[1][1]}++ });

Currently, setting "out" to any false value ("undef", "", 0) will be equivalent to "\"skip"".

If the "in" argument point to something to parse, and the "out" is set to a reference to an "ARRAY" or a "HASH", the output is appended to the data in the existing reference. The result of the parse should match what exists in the reference passed. This might come handy when you have to parse a set of files with similar content (like data stored per period) and you want to collect that into a single data structure:

my %hash;
csv (in => $_, out => \%hash, key => "id") for sort glob "foo-[0-9]*.csv";
my @list; # List of arrays
csv (in => $_, out => \@list)              for sort glob "foo-[0-9]*.csv";
my @list; # List of hashes
csv (in => $_, out => \@list, bom => 1)    for sort glob "foo-[0-9]*.csv";

Streaming

If both "in" and "out" are files, file handles or globs, streaming is enforced by injecting an "after_parse" callback that immediately uses the "say ()" method of the same instance to output the result and then rejects the record.

If a "after_parse" was already passed as attribute, that will be included in the injected call. If "on_in" was passed and "after_parse" was not, it will be used instead. If both were passed, "on_in" is ignored.

The EOL of the first record of the "in" source is consistently used as EOL for all records in the "out" destination.

The "filter" attribute is not available.

All other attributes are shared for "in" and "out", so you cannot define different encodings for "in" and "out". You need to pass a $fh, where "binmode" was used to apply the encoding layers.

Note that this is work in progress and things might change.

encoding

If passed, it should be an encoding accepted by the :encoding() option to "open". There is no default value. This attribute does not work in perl 5.6.x. "encoding" can be abbreviated to "enc" for ease of use in command line invocations.

If "encoding" is set to the literal value "auto", the method "header" will be invoked on the opened stream to check if there is a BOM and set the encoding accordingly. This is equal to passing a true value in the option "detect_bom".

Encodings can be stacked, as supported by "binmode":

# Using PerlIO::via::gzip
csv (in       => \@csv,
     out      => "test.csv:via.gz",
     encoding => ":via(gzip):encoding(utf-8)",
     );
$aoa = csv (in => "test.csv:via.gz",  encoding => ":via(gzip)");
# Using PerlIO::gzip
csv (in       => \@csv,
     out      => "test.csv:via.gz",
     encoding => ":gzip:encoding(utf-8)",
     );
$aoa = csv (in => "test.csv:gzip.gz", encoding => ":gzip");

OPTIONS AND CALLBACKS

The csv function and the Text::CSV_PP methods accept a number of options. These are passed as key/value pairs.

input_record_separator

The record separator for the input. Defaults to newline (\n). This is useful for files that use a different convention, like DOS (\r\n) or older Mac files (\r). Note that this is only used when reading from a filehandle. If the input is provided as a string, the separator is assumed to be newline.

binary

Set this to true if you want the parser to treat the input as binary. This means that line endings will be normalized to \n before processing. It also affects how the parser handles invalid byte sequences. See the Text::CSV_PP documentation for details.

auto_diag

If set to true, the parser will automatically die on errors, printing the error message. Defaults to true when using the csv function.

If set to a false value, errors will be stored internally and can be retrieved later using error_diag().

sep

The field separator character. Defaults to comma (,).

eol

The end-of-line character sequence to use when printing. Defaults to newline (\n).

quote_char

The quote character. Defaults to double quote (").

escape_char

The escape character. Defaults to double quote ("). If always_quote is true, this character will be used to escape the quote character itself.

always_quote

If true, all fields will be enclosed in quotes. Defaults to false.

allow_loose_quotes

If true, allows for fields that are not properly quoted. Defaults to false.

allow_whitespace

If true, allows whitespace around fields. Defaults to false.

skip_empty_lines

If true, empty lines in the input will be skipped. Defaults to false.

blank_is_bad

If true, lines with empty fields will be considered errors. Defaults to false.

empty_is_bad

If true, lines where all fields are empty will be considered errors. Defaults to false.

convert_blank_lines_to_nulls

If true, blank lines will be converted to an array reference containing a single undef value. Defaults to false.

csv_parse_callback

A callback function to be executed after each record is parsed. The callback receives the parsed record as an array reference.

csv_print_callback

A callback function to be executed before each record is printed. The callback receives the record to be printed as an array reference.

headers

If set to true, the first line of the input is assumed to be a header row, and the output will be an array of hash references, where the keys are the header names. Defaults to false.

If set to "auto", the header detection is attempted automatically. This will succeed if the first line contains only strings that are valid column names (no control characters, no commas, etc.).

If set to an array reference, this array will be used as the header. This is useful if the header is not present in the input file or if you want to use custom header names.

Note that as the "header" method is invoked, its default is to also set the headers.

set_column_names

If "set_column_names" is passed, the method "header" is invoked on the opened stream with all arguments meant for "header".

If "set_column_names" is passed as a false value, the content of the first row is only preserved if the output is AoA:

3,4,5

will result in

 [ "1",   "2"       ],
 [ "3",   "4",  "5" ]]

and

my $aoa = csv (in => $file, set_column_names => 0, munge => "none");

will result in

[[ "bAr", "foo"     ],
 [ "1",   "2"       ],
 [ "3",   "4",  "5" ]]
csv

The function "csv" can also be called as a method or with an existing Text::CSV_PP object. This could help if the function is to be invoked a lot of times and the overhead of creating the object internally over and over again would be prevented by passing an existing instance.

my $csv = Text::CSV_PP->new ({ binary => 1, auto_diag => 1 });
my $aoa = $csv->csv (in => $fh);
my $aoa = csv (in => $fh, csv => $csv);

both act the same. Running this 20000 times on a 20 lines CSV file, showed a 53% speedup.

Callbacks

Callbacks enable actions triggered from the inside of Text::CSV_PP.

While most of what this enables can easily be done in an unrolled loop as described in the "SYNOPSIS" callbacks can be used to meet special demands or enhance the "csv" function.

error
$csv->callbacks (error => sub { $csv->SetDiag (0) });

the "error" callback is invoked when an error occurs, but only when "auto_diag" is set to a true value. A callback is invoked with the values returned by "error_diag":

my ($c, $s);
sub ignore3006 {
    my ($err, $msg, $pos, $recno, $fldno) = @_;
    if ($err == 3006) {
        # ignore this error
        ($c, $s) = (undef, undef);
        Text::CSV_PP->SetDiag (0);
        }
    # Any other error
    return;
    } # ignore3006
$csv->callbacks (error => \&ignore3006);
$csv->bind_columns (\$c, \$s);
while ($csv->getline ($fh)) {
    # Error 3006 will not stop the loop
    }
after_parse
$csv->callbacks (after_parse => sub { push @{$_[1]}, "NEW" });
while (my $row = $csv->getline ($fh)) {
    $row->[-1] eq "NEW";
    }

This callback is invoked after parsing with "getline" only if no error occurred. The callback is invoked with two arguments: the current "CSV" parser object and an array reference to the fields parsed.

The return code of the callback is ignored unless it is a reference to the string "skip", in which case the record will be skipped in "getline_all".

sub add_from_db {
    my ($csv, $row) = @_;
    $sth->execute ($row->[4]);
    push @$row, $sth->fetchrow_array;
    } # add_from_db
my $aoa = csv (in => "file.csv", callbacks => {
    after_parse => \&add_from_db });

This hook can be used for validation:

FAIL
Die if any of the records does not validate a rule: 
after_parse => sub {
    $_[1][4] =~ m/^[0-9]{4}\s?[A-Z]{2}$/ or
        die "5th field does not have a valid Dutch zipcode";
    }
DEFAULT
Replace invalid fields with a default value: 
after_parse => sub { $_[1][2] =~ m/^\d+$/ or $_[1][2] = 0 }
SKIP
Skip records that have invalid fields (only applies to "getline_all"): 
after_parse => sub { $_[1][0] =~ m/^\d+$/ or return \"skip"; }
before_print
my $idx = 1;
$csv->callbacks (before_print => sub { $_[1][0] = $idx++ });
$csv->print (*STDOUT, [ 0, $_ ]) for @members;

This callback is invoked before printing with "print" only if no error occurred. The callback is invoked with two arguments: the current "CSV" parser object and an array reference to the fields passed.

The return code of the callback is ignored.

sub max_4_fields {
    my ($csv, $row) = @_;
    @$row > 4 and splice @$row, 4;
    } # max_4_fields
csv (in => csv (in => "file.csv"), out => *STDOUT,
    callbacks => { before_print => \&max_4_fields });

This callback is not active for "combine".

Callbacks for csv ()

The "csv" allows for some callbacks that do not integrate in XS internals but only feature the "csv" function.

csv (in        => "file.csv",
     callbacks => {
         filter       => { 6 => sub { $_ > 15 } },    # first
         after_parse  => sub { say "AFTER PARSE";  }, # first
         after_in     => sub { say "AFTER IN";     }, # second
         on_in        => sub { say "ON IN";        }, # third
         },
     );
csv (in        => $aoh,
     out       => "file.csv",
     callbacks => {
         on_in        => sub { say "ON IN";        }, # first
         before_out   => sub { say "BEFORE OUT";   }, # second
         before_print => sub { say "BEFORE PRINT"; }, # third
         },
     );
filter
This callback can be used to filter records. It is called just after a new record has been scanned. The callback accepts a:
hashref
The keys are the index to the row (the field name or field number, 1-based) and the values are subs to return a true or false value. 
csv (in => "file.csv", filter => {
           3 => sub { m/a/ },       # third field should contain an "a"
           5 => sub { length > 4 }, # length of the 5th field minimal 5
           });
csv (in => "file.csv", filter => { foo => sub { $_ > 4 }});

If the keys to the filter hash contain any character that is not a digit it will also implicitly set "headers" to "auto" unless "headers" was already passed as argument. When headers are active, returning an array of hashes, the filter is not applicable to the header itself.

All sub results should match, as in AND.

The context of the callback sets $_ localized to the field indicated by the filter. The two arguments are as with all other callbacks, so the other fields in the current row can be seen:

filter => { 3 => sub { $_ > 100 ? $_[1][1] =~ m/A/ : $_[1][6] =~ m/B/ }}

If the context is set to return a list of hashes ("headers" is defined), the current record will also be available in the localized %_:

filter => { 3 => sub { $_ > 100 && $_{foo} =~ m/A/ && $_{bar} < 1000  }}

If the filter is used to alter the content by changing $_, make sure that the sub returns true in order not to have that record skipped:

filter => { 2 => sub { $_ = uc }}

will upper-case the second field, and then skip it if the resulting content evaluates to false. To always accept, end with truth:

filter => { 2 => sub { $_ = uc; 1 }}
coderef
csv (in => "file.csv", filter => sub { $n++; 0; });

If the argument to "filter" is a coderef, it is an alias or shortcut to a filter on column 0:

csv (filter => sub { $n++; 0 });

is equal to

csv (filter => { 0 => sub { $n++; 0 });
filter-name
csv (in => "file.csv", filter => "not_blank");
csv (in => "file.csv", filter => "not_empty");
csv (in => "file.csv", filter => "filled");

These are predefined filters

Given a file like (line numbers prefixed for doc purpose only):

1:1,2,3
2:
3:,
4:""
5:,,
6:, ,
7:"",
8:" "
9:4,5,6
not_blank
Filter out the blank lines

This filter is a shortcut for

filter => { 0 => sub { @{$_[1]} > 1 or
        defined $_[1][0] && $_[1][0] ne "" } }

Due to the implementation, it is currently impossible to also filter lines that consists only of a quoted empty field. These lines are also considered blank lines.

With the given example, lines 2 and 4 will be skipped.

not_empty
Filter out lines where all the fields are empty.

This filter is a shortcut for

filter => { 0 => sub { grep { defined && $_ ne "" } @{$_[1]} } }

A space is not regarded being empty, so given the example data, lines 2, 3, 4, 5, and 7 are skipped.

filled
Filter out lines that have no visible data

This filter is a shortcut for

filter => { 0 => sub { grep { defined && m/\S/ } @{$_[1]} } }

This filter rejects all lines that not have at least one field that does not evaluate to the empty string.

También se podrían usar módulos como Types::Standard:

use Types::Standard -types;
my $type   = Tuple[Str, Str, Int, Bool, Optional[Num]];
my $check  = $type->compiled_check;
# filtrar con comprobación compilada y advertencias
my $aoa = csv (
   in     => \$data,
   filter => {
       0 => sub {
           my $ok = $check->($_[1]) or
               warn $type->get_message ($_[1]), "\n";
           return $ok;
           },
       },
   );
after_in
Esta devolución de llamada se invoca para cada registro después de que todos los registros han sido analizados, pero antes de devolver la referencia al llamador. El hook se invoca con dos argumentos: el objeto analizador "CSV" actual y una referencia al registro. La referencia puede ser una referencia a un HASH o una referencia a un ARRAY, según lo determinen los argumentos.

Esta devolución de llamada también se puede pasar como un atributo sin el envoltorio "callbacks".

before_out
Esta devolución de llamada se invoca para cada registro antes de que se imprima el registro. El hook se invoca con dos argumentos: el objeto analizador "CSV" actual y una referencia al registro. La referencia puede ser una referencia a un HASH o una referencia a un ARRAY, según lo determinen los argumentos.

Esta devolución de llamada también se puede pasar como un atributo sin el envoltorio "callbacks".

Esta devolución de llamada hace que la fila esté disponible en %_ si la fila es un hashref. En este caso %_ se puede escribir y cambiará la fila original.

on_in
Esta devolución de llamada actúa exactamente como los hooks "after_in" o "before_out".

Esta devolución de llamada también se puede pasar como un atributo sin el envoltorio "callbacks".

Esta devolución de llamada hace que la fila esté disponible en %_ si la fila es un hashref. En este caso %_ se puede escribir y cambiará la fila original. Así, por ejemplo, con

my $aoh = csv (
    in      => \"foo\n1\n2\n",
    headers => "auto",
    on_in   => sub { $_{bar} = 2; },
    );

$aoh será:

[ { foo => 1,
    bar => 2,
    }
  { foo => 2,
    bar => 2,
    }
  ]
on_error
Esta devolución de llamada actúa exactamente como el hook "error". 
my @err;
my $aoa = csv (in => $fh, on_error => sub { @err = @_ });

es idéntico a

my $aoa = csv (in => $fh, callbacks => {
    error => sub { @err = @_ },
    });

Puede usarse para ignorar errores, así como para simplemente guardar el error en caso de análisis después de que la función "csv ()" haya devuelto.

my @err;
my $aoa = csv (in => "bad.csv, on_error => sub { @err = @_ });
die Text::CSV_PP->error_diag if @err or !$aoa;

DIAGNÓSTICOS

Esta sección también se toma de Text::CSV_XS.

Aún en construcción...

Si ocurre un error, "$csv->error_diag" se puede usar para obtener información sobre la causa de la falla. Tenga en cuenta que por razones de velocidad, el valor interno nunca se borra en caso de éxito, por lo que usar el valor devuelto por "error_diag" en casos normales, cuando no ocurrió ningún error, puede causar resultados inesperados.

Si el constructor falló, la causa se puede encontrar usando "error_diag" como un método de clase, como "Text::CSV_PP->error_diag".

El método "$csv->error_diag" se invoca automáticamente en caso de error cuando el constructor se llamó con "auto_diag" establecido en 1 o 2, o cuando autodie está activo. Cuando se establece en 1, esto provocará una "warn" con el mensaje de error, cuando se establece en 2, hará "die". "2012 - EOF" está excluido de los informes "auto_diag".

Los errores pueden ser capturados (individualmente) usando la devolución de llamada "error".

Los errores descritos a continuación están disponibles. He intentado que el error en sí mismo sea lo suficientemente explicativo, pero se agregarán más descripciones. Para la mayoría de estos errores, las primeras tres mayúsculas describen la categoría del error:

  • INI

    Error de inicialización o conflicto de opciones.

  • ECR

    Error de análisis relacionado con el retorno de carro.

  • EOF

    Error de análisis relacionado con el fin de archivo.

  • EIQ

    Error de análisis dentro de una cita.

  • EIF

    Error de análisis dentro de un campo.

  • ECB

    Error de combinación.

  • EHR

    Error relacionado con el análisis de ArrayRef.

Y a continuación debería estar la lista completa de códigos de error que se pueden devolver:

  • 1001 "INI - sep_char es igual a quote_char o escape_char"

    El carácter de separación no puede ser igual al carácter de cita o al carácter de escape, ya que esto invalidaría todas las reglas de análisis.

  • 1002 "INI - allow_whitespace con escape_char o quote_char SP o TAB"

    Usar el atributo "allow_whitespace" cuando "quote_char" o "escape_char" es igual a "SPACE" o "TAB" es demasiado ambiguo para permitirse.

  • 1003 "INI - \r o \n en attr principal no permitidos"

    Usar caracteres de "eol" predeterminados en "sep_char", "quote_char", o "escape_char" no está permitido.

  • 1004 "INI - callbacks debe ser undef o un hashref"

    El atributo "callbacks" solo permite que sea "undef" o una referencia hash.

  • 1005 "INI - EOL demasiado largo"

    El valor pasado para EOL excede su longitud máxima (16).

  • 1006 "INI - SEP demasiado largo"

    El valor pasado para SEP excede su longitud máxima (16).

  • 1007 "INI - QUOTE demasiado largo"

    El valor pasado para QUOTE excede su longitud máxima (16).

  • 1008 "INI - SEP indefinido"

    El valor pasado para SEP debe ser definido y no vacío.

  • 1010 "INI - la cabecera está vacía"

    La línea de cabecera analizada en "header" está vacía.

  • 1011 "INI - la cabecera contiene más de un separador válido"

    La línea de cabecera analizada en "header" contiene más de un (único) carácter separador de entre el conjunto permitido de separadores.

  • 1012 "INI - la cabecera contiene un campo vacío"

    La línea de cabecera analizada en "header" contiene un campo vacío.

  • 1013 "INI - la cabecera contiene campos no únicos"

    La línea de cabecera analizada en "header" contiene al menos dos campos idénticos.

  • 1014 "INI - llamada a header en stream indefinido"

    La línea de cabecera no se puede analizar desde una fuente indefinida.

  • 1500 "PRM - Argumento(s) inválido(s)/no compatible(s)"

    Función o método llamado con argumento(s) o parámetro(s) inválido(s).

  • 1501 "PRM - El atributo clave se pasa como un tipo no compatible"

    El atributo "key" es de un tipo no compatible.

  • 1502 "PRM - El atributo valor se pasa sin el atributo clave"

    El atributo "value" solo se permite cuando se proporciona una clave válida.

  • 1503 "PRM - El atributo valor se pasa como un tipo no compatible"

    El atributo "value" es de un tipo no compatible.

  • 2010 "ECR - Char QUO dentro de comillas seguido por CR no parte de EOL"

    Cuando "eol" se ha establecido en algo que no sea el valor predeterminado, como "\r\t\n", y el "\r" sigue al segundo (cierre) "quote_char", donde los caracteres que siguen a "\r" no forman la secuencia "eol", esto es un error.

  • 2011 "ECR - Caracteres después del final del campo entre comillas"

    Secuencias como "1,foo,"bar"baz,22,1" no están permitidas. "bar" es un campo entre comillas y después de la comilla de cierre, debería haber una secuencia de nueva línea o un carácter separador.

  • 2012 "EOF - Fin de datos en el stream de entrada de análisis"

    Autoexplicativo. Fin de archivo mientras se analiza un stream. Solo puede ocurrir al leer de streams con "getline", ya que "parse" se usa en cadenas que no requieren un "eol" final.

  • 2013 "INI - Especificación de error para fragmentos RFC7111"

    Especificación inválida para la especificación de "fragmento" de URI.

  • 2014 "ENF - Número inconsistente de campos"

    Número inconsistente de campos bajo análisis estricto.

  • 2015 "ERW - Fila vacía"

    No se permitió una fila vacía.

  • 2016 "EOL - EOL inconsistente"

    Se detectó End-Of-Line inconsistente bajo análisis strict_eol.

  • 2021 "EIQ - Carácter NL dentro de comillas, binario desactivado"

    Secuencias como "1,"foo\nbar",22,1" solo están permitidas cuando la opción binaria ha sido seleccionada con el constructor.
