Text::BibTeX::Entry(3pm) Documentación de Perl aportada por el usuario Text::BibTeX::Entry(3pm)

NOMBRE

Text::BibTeX::Entry - leer y analizar archivos BibTeX

SINOPSIS

use Text::BibTeX::Entry;
# ...suponiendo que $bibfile y $newbib son ambos objetos de la clase
# Text::BibTeX::File, abiertos para lectura y escritura (respectivamente):
# Métodos de creación/análisis de entradas:
$entry = Text::BibTeX::Entry->new();
$entry->read ($bibfile);
$entry->parse ($filename, $filehandle);
$entry->parse_s ($entry_text);
# o:
$entry = Text::BibTeX::Entry->new( $bibfile );
$entry = Text::BibTeX::Entry->new( $filename, $filehandle );
$entry = Text::BibTeX::Entry->new( $entry_text );

# Métodos de consulta de entrada
warn "error en la entrada" unless $entry->parse_ok;
$metatype = $entry->metatype;
$type = $entry->type;
# si metatype es BTE_REGULAR o BTE_MACRODEF:
$key = $entry->key;                  # solo para metatype BTE_REGULAR
$num_fields = $entry->num_fields;
@fieldlist = $entry->fieldlist;
$has_title = $entry->exists ('title');
$title = $entry->get ('title');
# o:
($val1,$val2,...$valn) = $entry->get ($field1, $field2, ..., $fieldn);
# si metatype es BTE_COMMENT o BTE_PREAMBLE:
$value = $entry->value;
# Métodos de nombres de autor 
@authors = $entry->split ('author');
($first_author) = $entry->names ('author');
# Métodos de modificación de entrada
$entry->set_type ($new_type);
$entry->set_key ($new_key);
$entry->set ('title', $new_title);
# o:
$entry->set ($field1, $val1, $field2, $val2, ..., $fieldn, $valn);
$entry->delete (@fields);
$entry->set_fieldlist (\@fieldlist);
# Métodos de salida de entrada
$entry->write ($newbib);
$entry->print ($filehandle);
$entry_text = $entry->print_s;
# Restablecer el estado interno del analizador:
$entry = Text::BibTeX::Entry->new();
$entry->parse ($filename, undef);
$entry->parse_s (undef);
# o:
$entry = Text::BibTeX::Entry->new( $filename, undef );
$entry = Text::BibTeX::Entry->new( undef );
# Métodos varios
$entry->warn ($entry_warning);
# o:
$entry->warn ($field_warning, $field);
$entry->clone;

DESCRIPCIÓN

"Text::BibTeX::Entry" realiza todo el trabajo real de leer y analizar archivos BibTeX. (Bueno, en realidad solo proporciona una interfaz Perl orientada a objetos para una biblioteca C que hace todo eso. Pero eso no es importante ahora.)

Las entradas BibTeX se pueden leer desde objetos "Text::BibTeX::File" (usando el método "read"), o directamente desde un manejador de archivos (usando el método "parse"), o desde una cadena (usando "parse_s"). La primera opción es preferible, ya que no tiene que preocuparse por proporcionar el nombre del archivo y debido a la funcionalidad adicional proporcionada por la clase "Text::BibTeX::File". Actualmente, esto significa que puede especificar la estructura de la base de datos a la que se espera que se ajusten las entradas a través de la clase "File". Esto le permite asegurarse de que las entradas sigan las reglas para campos requeridos y campos con restricciones mutuas para un tipo particular de base de datos, y también le da acceso a todos los métodos de la clase de entrada estructurada para esta estructura de base de datos. Consulte Text::BibTeX::Structure para obtener detalles sobre las estructuras de bases de datos.

Una vez que tenga la entrada, puede consultarla o modificarla de varias maneras. Los métodos de consulta son "parse_ok", "type", "key", "num_fields", "fieldlist", "exists" y "get". Los métodos para cambiar la entrada son "set_type", "set_key", "set_fieldlist", "delete" y "set".

Finalmente, puede generar entradas BibTeX, de nuevo, ya sea a un objeto "Text::BibTeX::File" abierto, un manejador de archivos o una cadena. (Un manejador de archivos o un objeto "File" debe, por supuesto, haber sido abierto en modo de escritura.) La salida a un objeto "File" se realiza con el método "write", a un manejador de archivos a través de "print" y a una cadena con "print_s". El uso de la clase "File" se recomienda para la extensibilidad futura, aunque actualmente no ofrece nada adicional.

MÉTODOS

Métodos de creación/análisis de entrada

new ([OPTS ,] [SOURCE])
Crea un nuevo objeto "Text::BibTeX::Entry". Si se proporciona el parámetro SOURCE, debe ser uno de los siguientes: un objeto "Text::BibTeX::File" (o una clase derivada), un par nombre de archivo/manejador de archivos, o una cadena. Llama a "read" para leer desde un objeto "Text::BibTeX::File", "parse" para leer desde un manejador de archivos y "parse_s" para leer desde una cadena.

Un manejador de archivos puede especificarse como una referencia GLOB, o como un objeto "IO::Handle" (o descendientes), o como un objeto "FileHandle" (o descendientes). (Pero realmente no tiene sentido usar objetos "FileHandle", ya que "Text::BibTeX" requiere Perl 5.004, que siempre incluye los módulos "IO".) Sin embargo, *no* puede pasar el nombre de un manejador de archivos como una cadena, porque "Text::BibTeX::Entry" cumple con la pragmática "use strict" (que prohíbe tales referencias simbólicas).

El nombre de archivo correspondiente debe proporcionarse para permitir mensajes de error precisos; si simplemente no tiene el nombre del archivo, puede pasar "undef" y obtendrá mensajes de error sin nombre de archivo. (Probablemente sea mejor reorganizar su código para que el nombre del archivo esté disponible, sin embargo.)

Por lo tanto, los siguientes son equivalentes para leer de un archivo nombrado por $filename (manejo de errores ignorado):

# manejador de archivos y referencia GLOB de la vieja escuela
open (BIBFILE, $filename);
$entry = Text::BibTeX::Entry->new($filename, \*BIBFILE);
# cosa IO::File de última generación
$file = IO::File->new($filename);
$entry = Text::BibTeX::Entry->new($filename, $file);

Pero usar un objeto "Text::BibTeX::File" es más simple y preferido:

$file  = Text::BibTeX::File->new($filename);
$entry = Text::BibTeX::Entry->new($file);

Devuelve el nuevo objeto, a menos que SOURCE se proporcione y la lectura/análisis de la entrada falle (por ejemplo, debido al final del archivo), en cuyo caso devuelve falso.

Puede proporcionar una referencia a un hash de opciones como primer argumento. Las opciones admitidas son:

BINMODE
Establece la forma en que Text::BibTeX maneja las cadenas. Por defecto, gestiona las cadenas como bytes. Puede establecer BINMODE a 'utf-8' para obtener

Text::BibTeX::Entry->new(
{ binmode => 'utf-8', normalization => 'NFD' },
$file });

NORMALIZATION
cadenas UTF-8 y puede personalizar la normalización con la opción NORMALIZATION.
clone
Clona un objeto Text::BibTeX::Entry, devolviendo el clon. Esto reutiliza la referencia a cualquier Text::BibTeX::Structure o Text::BibTeX::File, pero copia todo lo demás, de modo que el clon se puede modificar independientemente del original.
read (BIBFILE)
Lee y analiza una entrada de BIBFILE, que debe ser un objeto "Text::BibTeX::File" (o descendiente). La siguiente entrada se leerá del archivo asociado con ese objeto.

parse (FILENAME, FILEHANDLE)
Lee y analiza la siguiente entrada del FILEHANDLE. (Es decir, escanea la entrada hasta que se ve un signo '@', y luego consume todo hasta el siguiente signo '@'. Todo lo que hay entre los dos signos '@' (incluido el primero, pero no el segundo, que se devuelve al flujo de entrada para la siguiente entrada) se analiza como una entrada BibTeX, construyendo simultáneamente un árbol de sintaxis abstracta (AST). El AST se recorre para extraer la información más interesante, y esta se introduce en un hash de Perl, que resulta ser el objeto "Text::BibTeX::Entry" que has estado manejando. Pero no necesitas saber nada de eso; simplemente pensé que si has leído hasta aquí, quizás quieras saber algo sobre el funcionamiento interno de este módulo).

El éxito del análisis se almacena internamente para que puedas consultarlo más tarde con el método "parse_ok". Incluso en presencia de errores de sintaxis, normalmente obtendrás algo parecido a tu entrada, pero no suele ser aconsejable intentar hacer nada con ello. Simplemente llama a "parse_ok", y si devuelve falso, salta silenciosamente a la siguiente entrada. (Los mensajes de error impresos por el analizador deberían ser adecuados para que el usuario descubra qué está mal. Y no, actualmente no hay forma de capturar o redirigir esos mensajes de error; siempre se imprimen en "stderr" por el código C subyacente. Eso debería cambiar en futuras versiones).

Si no se ven signos '@' en la entrada antes de llegar al final del archivo, hemos agotado todas las entradas del archivo, y "parse" devuelve un valor falso. De lo contrario, devuelve un valor verdadero, incluso si hubo errores de sintaxis. Por lo tanto, es importante comprobar "parse_ok".

El parámetro FILENAME solo se utiliza para generar mensajes de error, ¡pero cualquiera que utilice tu programa apreciará que lo establezcas correctamente!

Pasar "undef" a FILEHANDLE restablecerá el estado del analizador C subyacente, lo cual es necesario para analizar varios archivos.

parse_s (TEXT)
Analiza una entrada BibTeX (siguiendo las reglas anteriores) a partir de la cadena TEXT. La cadena no se modifica; llamar repetidamente a "parse_s" con la misma cadena dará los mismos resultados cada vez. Por lo tanto, no tiene sentido poner varias entradas en una sola cadena.

Pasar "undef" a TEXT restablecerá el estado del analizador C subyacente, lo cual puede ser necesario para analizar varias cadenas.

Métodos de consulta de entrada

parse_ok ()
Devuelve falso si se encontraron errores graves al analizar la entrada. (Un error "grave" es un error léxico o de sintaxis; actualmente, las advertencias como "macro no definida" generan un mensaje de error que se imprime en "stderr" para la edificación del usuario, pero no hay aviso disponible para el código que llama).
type ()
Devuelve el tipo de la entrada. (El `tipo' es la palabra que sigue al signo '@'; por ejemplo, `article', `book', `inproceedings', etc. para los estilos BibTeX estándar).
metatype ()
Devuelve el metatipo de la entrada. (El `metatipo' es un valor numérico utilizado para clasificar los tipos de entrada en cuatro grupos: comentario, preámbulo, definición de macro (entradas @string) y regular (todos los demás tipos de entrada). "Text::BibTeX" exporta cuatro constantes para estos metatipos: "BTE_COMMENT", "BTE_PREAMBLE", "BTE_MACRODEF", y "BTE_REGULAR").
key ()
Devuelve la clave de la entrada. (La clave es el token que sigue inmediatamente a la '{' o '(' de apertura en las entradas "regulares". Devuelve "undef" para las entradas que no tienen clave, como las entradas de definición de macro (@string)).
num_fields ()
Devuelve el número de campos de la entrada. (Tenga en cuenta que, actualmente, esto *no* es equivalente a poner "scalar" delante de una llamada a "fieldlist". Consulte más abajo las consecuencias de llamar a "fieldlist" en contexto escalar).
fieldlist ()
Devuelve la lista de campos de la entrada.

ADVERTENCIA En contexto escalar, ya no devuelve una referencia a la propia lista de campos del objeto.

exists (FIELD)
Devuelve verdadero si un campo llamado FIELD está presente en la entrada, falso en caso contrario.
get (FIELD, ...)
Devuelve el valor de uno o más campos, como una lista de valores. Por ejemplo: 
$author = $entry->get ('author');
($author, $editor) = $entry->get ('author', 'editor');

Si un campo no está presente en la entrada, se devolverá "undef" en su lugar en la lista de retorno. Sin embargo, no puedes confiar completamente en esto como prueba de presencia o ausencia de un campo; es posible que un campo esté presente pero indefinido. Actualmente, esto solo puede ocurrir debido a ciertos errores de sintaxis en la entrada, o si pasas un valor indefinido a "set", o si creas un nuevo campo con "set_fieldlist" (el valor del nuevo campo se establece implícitamente en "undef").

Normalmente, el valor del campo es lo que parece la entrada después del "procesamiento máximo": se eliminan las comillas, se colapsa el espacio en blanco (de la misma manera que BibTeX lo hace), se expanden las macros y se unen varios tokens. (Consulte bt_postprocess para obtener detalles sobre el postprocesamiento realizado por btparse).

Por ejemplo, si tu archivo de entrada tiene lo siguiente:

@string{of = "of"}
@string{foobars = "Foobars"}
@article{foobar,
  title = {   The Mating Habits      } # of # " Adult   " # foobars
}

entonces, usar "get" para consultar el valor del campo "title" de la entrada "foobar" daría la cadena "The Mating Habits of Adult Foobars".

Sin embargo, en ciertas circunstancias, es posible que desees conservar los valores tal como aparecen en la entrada. Esto se hace estableciendo un flag "preserve_values" en algún momento; luego, "get" devolverá no cadenas sino objetos "Text::BibTeX::Value". Cada objeto "Value" es una lista de objetos "Text::BibTeX::SimpleValue", que a su vez consta de un tipo de valor simple (cadena, macro o número) y el texto del valor simple. Diversas formas de establecer el flag "preserve_values" y la interfaz para los objetos "Value" y "SimpleValue" se describen en Text::BibTeX::Value.

value ()
Devuelve la única cadena asociada con las entradas @comment y @preamble. Por ejemplo, la entrada 
@preamble{" This is   a preamble" # 
          {---the concatenation of several strings}}

devolvería un valor de "This is a preamble---the concatenation of several strings".

Si esta entrada se analizó en modo de "preservación de valor", entonces "value" actúa como "get" y devuelve un objeto "Value" en lugar de una cadena simple.

Métodos de nombre de autor

Esta es la única parte del módulo que hace alguna suposición sobre la naturaleza de los datos, a saber, que ciertos campos son listas delimitadas por una simple palabra como "and", y que las subcadenas delimitadas son nombres humanos del estilo "First von Last" o "von Last, Jr., First" utilizado por BibTeX. Si estás utilizando este módulo para algo más que datos bibliográficos, lo más probable es que puedas olvidar estos dos métodos. Sin embargo, si realmente estás trabajando con datos bibliográficos al estilo BibTeX, podrían ser muy útiles: el análisis de nombres realizado por BibTeX no es trivial, y la división de listas también sería una molestia de implementar en Perl porque hay que prestar atención a la profundidad de las llaves. (No es que no fuera una molestia implementarlo en C, es solo que es mucho más eficiente que una implementación en Perl).

Por cierto, ambos métodos asumen que las cadenas que se dividen ya han sido "colapsadas" al estilo BibTeX, es decir, se ha eliminado todo el espacio en blanco al principio y al final y el espacio en blanco interno se ha reducido a espacios simples. Esto siempre debería ser así cuando se utilizan estos dos métodos en un objeto "Text::BibTeX::Entry", pero en realidad son solo interfaces para funciones más generales en "Text::BibTeX". (Más generales en el sentido de que proporcionas la cadena a analizar, en lugar de proporcionar el nombre de un campo de entrada). Si alguna vez utilizas esas funciones más generales directamente, podrías tener que preocuparte por colapsar el espacio en blanco; consulta Text::BibTeX (las funciones "split_list" y "split_name" en particular) para obtener más información.

Tenga en cuenta que la interfaz para el análisis de nombres de autor es experimental, está sujeta a cambios y abierta a discusión. Por favor, házmelo saber si tienes problemas con

Text::BibTeX::Entry(3pm)

NAME

Text::BibTeX::Entry - An object representing a single BibTeX entry

SYNOPSIS

use Text::BibTeX::Entry;

# Constructing an entry
$entry = Text::BibTeX::Entry->new (type => 'article', key => 'doe99',
    author => 'John Doe', title => 'My Paper');

# Accessing fields
$author = $entry->field ('author');
if ($entry->exists ('journal')) {
    $journal = $entry->field ('journal');
}

# Modifying fields
$entry->set ('year', 1999);
$entry->delete ('title');

# Iterating over fields
for $field ($entry->fields) {
    print "$field = $entry->field($field)\n";
}

# Writing the entry out
print $entry->print_s ();

DESCRIPTION

This module implements an object representing a single BibTeX entry. This includes the entry type (e.g., @article), the entry key (e.g., doe99), and the fields and their values (e.g., author = {John Doe}).

Entries are typically created by parsing a BibTeX file using Text::BibTeX::File, but they can also be created manually.

Note that the behavior of certain methods (like line, filename, and warn) depends on how the entry was created. If it was created from a string or by manual construction, line numbers and filenames will not be meaningful.

Constructing entries

new (KEY = VALUE, ...)
Constructs and returns a new Text::BibTeX::Entry object. You may supply any of the valid BibTeX entry components as key-value pairs. The recognized keys are type, key, and any valid BibTeX field name. The values should be simple strings. If you want to specify a metatype (see set_metatype), you must do it with the set_metatype method after construction, or by specifying the type in a way that the parser recognizes (e.g. @string foo = ... will be parsed as type string and key foo).

Entry query methods

type ()
Returns the entry's type (e.g., 'article').
metatype ()
Returns the entry's metatype. This will be one of the four constants "BTE_COMMENT", "BTE_PREAMBLE", "BTE_MACRODEF", or "BTE_REGULAR". (See set_metatype.)
key ()
Returns the entry's key.
field (FIELD [, SUBFIELD])
Returns the value of the specified FIELD. If SUBFIELD is given, it is treated as a subfield of the FIELD value; this is used for parsing author names (see names).
exists (FIELD)
Returns true if the entry contains the specified FIELD, false otherwise. Note that this is different from checking whether the value returned by field is defined; a field may exist but have an undefined value (see set).
fields ()
Returns a list of all fields (including type and key) currently present in the entry.
is_comment ()
Returns true if the entry is a comment (@comment).
is_preamble ()
Returns true if the entry is a preamble (@preamble).
is_macodefine ()
Returns true if the entry is a macro definition (@string or @string).
is_regular ()
Returns true if the entry is a regular BibTeX entry (i.e., none of the above).
split (FIELD [, DELIM [, DESC]])
Splits the value of FIELD on DELIM (default: 'and'). Don't assume that this works the same as Perl's builtin "split" just because the names are the same: in particular, DELIM must be a simple string (no regexps), and delimiters that are at the beginning or end of the string, or at non-zero brace depth, or not surrounded by whitespace, are ignored. Some examples might illuminate matters: 
if field F is...                then split (F) returns...
'Name1 and Name2'               ('Name1', 'Name2')
'Name1 and and Name2'           ('Name1', undef, 'Name2')
'Name1 and'                     ('Name1 and')
'and Name2'                     ('and Name2')
'Name1 {and} Name2 and Name3'   ('Name1 {and} Name2', 'Name3')
'{Name1 and Name2} and Name3'   ('{Name1 and Name2}', 'Name3')

Note that a warning will be issued for empty names (as in the second example above). A warning ought to be issued for delimiters at the beginning or end of a string, but currently this isn't done. (Hmmm.)

DESC is a one-word description of the substrings; it defaults to 'name'. It is only used for generating warning messages.

names (FIELD)
Splits FIELD as described above, and further splits each name into four components: first, von, last, and jr.

Returns a list of "Text::BibTeX::Name" objects, each of which represents one name. Use the "part" method to query these objects; see Text::BibTeX::Name for details on the interface to name objects (and on name-parsing as well).

For example if this entry:

@article{foo,
         author = {John Smith and 
                   Hacker, J. Random and
                   Ludwig van Beethoven and
                   {Foo, Bar and Company}}}

has been parsed into a "Text::BibTeX::Entry" object $entry, then

@names = $entry->names ('author');

will put a list of "Text::BibTeX::Name" objects in @names. These can be queried individually as described in Text::BibTeX::Name; for instance,

@last = $names[0]->part ('last');

would put the list of tokens comprising the last name of the first author into the @last array: "('Smith')".

Entry modification methods

set_type (TYPE)
Sets the entry's type.
set_metatype (METATYPE)
Sets the entry's metatype (must be one of the four constants "BTE_COMMENT", "BTE_PREAMBLE", "BTE_MACRODEF", and "BTE_REGULAR", which are all optionally exported from "Text::BibTeX").
set_key (KEY)
Sets the entry's key.
set (FIELD, VALUE, ...)
Sets the value of field FIELD. (VALUE might be "undef" or unsupplied, in which case FIELD will simply be set to "undef" -- this is where the difference between the "exists" method and testing the definedness of field values becomes clear.)

Multiple (FIELD, VALUE) pairs may be supplied; they will be processed in order (i.e. the input is treated like a list, not a hash). For example:

$entry->set ('author', $author);
$entry->set ('author', $author, 'editor', $editor);

VALUE can be either a simple string or a "Text::BibTeX::Value" object; it doesn't matter if the entry was parsed in "full post-processing" or "preserve input values" mode.

delete (FIELD)
Deletes field FIELD from an entry.
set_fieldlist (FIELDLIST)
Sets the entry's list of fields to FIELDLIST, which must be a list reference. If any of the field names supplied in FIELDLIST are not currently present in the entry, they are created with the value "undef" and a warning is printed. Conversely, if any of the fields currently present in the entry are not named in the list of fields supplied to "set_fields", they are deleted from the entry and another warning is printed.

Entry output methods

write (BIBFILE)
Prints a BibTeX entry on the filehandle associated with BIBFILE (which should be a "Text::BibTeX::File" object, opened for output). Currently the printout is not particularly human-friendly; a highly configurable pretty-printer will be developed eventually.
print (FILEHANDLE)
Prints a BibTeX entry on FILEHANDLE.
print_s ()
Prints a BibTeX entry to a string, which is the return value.

Miscellaneous methods

warn (WARNING [, FIELD])
Prepends a bit of location information (filename and line number(s)) to WARNING, appends a newline, and passes it to Perl's "warn". If FIELD is supplied, the line number given is just that of the field; otherwise, the range of lines for the whole entry is given. (Well, almost -- currently, the line number of the last field is used as the last line of the whole entry. This is a bug.)

For example, if lines 10-15 of file foo.bib look like this:

@article{homer97,
  author = {Homer Simpson and Ned Flanders},
  title = {Territorial Imperatives in Modern Suburbia},
  journal = {Journal of Suburban Studies},
  year = 1997
}

then, after parsing this entry to $entry, the calls

$entry->warn ('what a silly entry');
$entry->warn ('what a silly journal', 'journal');

would result in the following warnings being issued:

foo.bib, lines 10-14: what a silly entry
foo.bib, line 13: what a silly journal
line ([FIELD])
Returns the line number of FIELD. If the entry was parsed from a string, this still works--it's just the line number relative to the start of the string. If the entry was parsed from a file, this works just as you'd expect it to: it returns the absolute line number with respect to the whole file. Line numbers are one-based.

If FIELD is not supplied, returns a two-element list containing the line numbers of the beginning and end of the whole entry. (Actually, the "end" line number is currently inaccurate: it's really the the line number of the last field in the entry. But it's better than nothing.)

filename ()
Returns the name of the file from which the entry was parsed. Only works if the file is represented by a "Text::BibTeX::File" object---if you just passed a filename/filehandle pair to "parse", you can't get the filename back. (Sorry.)
