Test2::Manual::Tooling::Testing(3perl) Guía de referencia para programadores de Perl Test2::Manual::Tooling::Testing(3perl)

NOMBRE

Test2::Manual::Tooling::Testing - Tutorial sobre cómo probar tus herramientas de prueba.

DESCRIPCIÓN

Probar tus herramientas de prueba solía ser una tarea compleja y difícil. Las herramientas antiguas como Test::Tester y Test::Builder::Tester eran limitadas y frágiles. Test2, por otro lado, fue diseñado desde el principio para ser fácilmente probado. Este tutorial te muestra cómo.

EL SANTO GRIAL DE LA PRUEBA DE TUS HERRAMIENTAS

La clave para que Test2 sea fácilmente testeable (especialmente en comparación con Test::Builder) es la función "intercept".

use Test2::API qw/intercept/;
my $events = intercept {
    ok(1, "pasar");
    ok(0, "fallar");
    diag("Un diag");
};

La función intercept te permite usar cualquier herramienta de prueba que desees dentro de un bloque de código. Ningún evento o contexto generado dentro del bloque de código de intercept tendrá ningún efecto en el estado de prueba externo. La función "intercept" aísla completamente las herramientas llamadas desde dentro.

Nota: Los plugins y cosas que afectan el estado global de la API pueden no estar completamente aislados. "intercept" está diseñado específicamente para el aislamiento de eventos.

La función "intercept" devolverá un arrayref que contiene todos los eventos que se generaron dentro del bloque de código. Ahora puedes hacer cualquier aserción que desees sobre los eventos que esperabas que tus herramientas generaran.

[
    bless({...}, 'Test2::Event::Ok'),   # pasar
    bless({...}, 'Test2::Event::Ok'),   # fallar
    bless({...}, 'Test2::Event::Diag'), # Diagnósticos de fallo (no siempre un segundo evento)
    bless({...}, 'Test2::Event::Diag'), # mensaje personalizado 'A diag'
]

La mayoría de las herramientas de prueba eventualmente producen uno o más eventos. Para verificar eficazmente los eventos que obtienes de intercept, realmente deberías leer sobre cómo funcionan los eventos en Test2::Manual::Anatomy::Event. Una vez que conozcas los eventos, puedes pasar a la siguiente sección que te señala algunas ayudas.

AYUDAS ADICIONALES

Test2::Tools::Tester

Este es el conjunto de herramientas más reciente para ayudarte a probar tus eventos. Para entender realmente estas herramientas, deberías familiarizarte con Test2::Manual::Anatomy::Event. Si vas a escribir algo más que herramientas muy simples, deberías saber cómo funcionan los eventos.

La documentación de Test2::Tools::Tester es un buen lugar para lecturas adicionales.

Test2::Tools::HarnessTester

Test2::Tools::HarnessTester puede exportar la herramienta summarize_events(). Esta herramienta te permite ejecutar tu arrayref de eventos a través de Test2::Harness para obtener un resumen de pasado/fallido.

my $summary = summarize_events($events);

El resumen se ve así:

{
    plan       => $plan_facet,         # el facet del evento plan
    pass       => $bool,               # verdadero si los eventos resultan en un pasado
    fail       => $bool,               # verdadero si los eventos resultan en un fallo
    errors     => $error_count,        # Número de facets de error vistos
    failures   => $failure_count,      # Número de aserciones fallidas vistas
    assertions => $assertion_count,    # Número total de aserciones vistas
}

Test2::Tools::Compare

OBSOLETO Estas herramientas fueron escritas antes del cambio a eventos facetados. Seguirán funcionando, pero ya no son la forma recomendada de probar tus herramientas.

La biblioteca Test2::Tools::Compare exporta un puñado de extras para ayudar a probar eventos.

evento $TIPO => ...
Úsalo en una comprobación de array contra $events para comprobar un tipo específico de evento con las propiedades que especifiques.
eventos-fallidos $TIPO => ...
Úsalo cuando esperes una aserción fallida de $TIPO. Esto comprobará automáticamente que el siguiente evento que le sigue es un mensaje de diagnóstico con el texto de fallo predeterminado.

Nota: Esto está desactualizado, ya que un solo evento puede ahora poseer tanto la aserción fallida como el texto de fallo; tales eventos fallarán esta prueba.
