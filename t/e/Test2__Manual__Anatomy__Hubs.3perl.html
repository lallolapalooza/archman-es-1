NOMBRE

Test2::Manual::Anatomy::Hubs - Documentación interna para la pila de hubs y los hubs.

DESCRIPCIÓN

Este documento describe la pila de hubs y los hubs que contiene. Explica por qué tenemos una pila y cuándo añadir/eliminar hubs de ella.

¿QUÉ ES UN HUB?

Test2 es un sistema de eventos, las herramientas generan eventos, esos eventos son procesados para modificar el estado de las pruebas (número de pruebas, número de fallos, etc.). El hub es responsable de recibir y procesar eventos para registrar el cambio de estado. Todos los eventos deben llegar eventualmente a un hub de destino.

El hub base es Test2::Hub. Todas las clases de hub deben heredar de la clase base de hub. La clase base de hub proporciona varios puntos de extensión que le permiten monitorear o modificar eventos. Los hubs también son responsables de reenviar eventos al formateador de salida.

¿POR QUÉ TENEMOS UNA PILA DE HUBS?

Hay casos en los que tiene sentido tener más de un hub:

subpruebas
En Test2, las subpruebas se implementan utilizando la pila de hubs. Cuando inicia una subprueba, se crea una nueva instancia de Test2::Hub::Subtest y se empuja a la pila. Una vez hecho esto, todas las llamadas a "Test2::API::context" encontrarán el nuevo hub y le enviarán todos los eventos. Cuando la herramienta de subprueba finaliza, eliminará el nuevo hub y enviará un evento final de subprueba al hub padre.
probar sus herramientas de prueba
Test2::API::intercept() se implementa utilizando la pila de hubs. La función Test2::API::intercept() añadirá una instancia de Test2::Hub::Interceptor a la pila, cualquier llamada a Test2::API::context() encontrará el nuevo hub y le enviará todos los eventos. El hub de intercepción es especial porque no tiene conexión con el hub padre y generalmente no tiene un formateador.

¿CUÁNDO DEBO AÑADIR UN HUB A LA PILA?

Cada vez que desee interceptar o bloquear eventos para que no afecten el estado de la prueba. Añadir un nuevo hub es esencialmente una forma de crear un sandbox donde tiene control absoluto sobre lo que hacen los eventos. Añadir un nuevo hub asegura que el estado principal de la prueba no se verá afectado.

¿DÓNDE ESTÁ LA PILA?

La pila es una instancia de Test2::API::Stack. Puede acceder a la pila de hubs global usando "Test2::API::test2_stack".

¿QUÉ PASA CONTIGO EL HUB RAÍZ?

El hub raíz se crea automáticamente según sea necesario. Una llamada a "Test2::API::test2_stack->top()" creará el hub raíz si aún no existe.

¿CÓMO GESTIONAN LOS HUBS LA IPC?

Si el sistema de IPC (Test2::IPC) no se cargó, entonces la IPC no se gestiona en absoluto. El bifurcar o crear nuevos hilos sin el sistema de IPC puede causar problemas inesperados.

Todos los hubs rastrean el PID y el ID de Hilo que estaba actual cuando se crearon. Si se envía un evento a un hub en un nuevo proceso/hilo, el hub lo detectará e intentará reenviar el evento al proceso/hilo correcto. Esto se logra utilizando el sistema de IPC.
