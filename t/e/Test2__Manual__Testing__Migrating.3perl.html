Test2::Manual::Testing::Migrating(3perl) Guía de Referencia del Programador de Perl Test2::Manual::Testing::Migrating(3perl)

NOMBRE

Test2::Manual::Testing::Migrating - Cómo migrar pruebas existentes de Test::More a Test2.

DESCRIPCIÓN

Este tutorial cubre la conversión de una prueba existente. Este tutorial asume que tienes una prueba escrita usando Test::More.

PRUEBA LEGADO

Este tutorial convertirá esta prueba de ejemplo sección por sección:

"t/example.t":

#####################
# Boilerplate
use strict;
use warnings;
use Test::More tests => 14;
use_ok 'Scalar::Util';
require_ok 'Exporter';
#####################
# Asertos simples (sin cambios)
ok(1, "pass");
is("apple", "apple", "Comparación simple de cadenas");
like("foo bar baz", qr/bar/, "Coincidencia de expresión regular");
#####################
# Pendiente
{
    local $TODO = "Estos son pendientes";
    ok(0, "ups");
}
#####################
# Comparaciones profundas
is_deeply([1, 2, 3], [1, 2, 3], "Comparación profunda");
#####################
# Comparación de referencias
my $ref = [1];
is($ref, $ref, "Verificar que tenemos la misma referencia ambas veces");
#####################
# Cosas que han desaparecido
ok(eq_array([1], [1]), "comparación de arrays");
ok(eq_hash({a => 1}, {a => 1}), "comparación de hashes");
ok(eq_set([1, 3, 2], [1, 2, 3]), "comparación de conjuntos");
note explain([1, 2, 3]);
{
    package THING;
    sub new { bless({}, shift) }
}
my $thing = new_ok('THING');
#####################
# Herramientas que han cambiado
isa_ok($thing, 'THING', '$thing');
can_ok(__PACKAGE__, qw/ok is/);

BOILERPLATE

ANTES:

use strict;
use warnings;
use Test::More tests => 14;
use_ok 'Scalar::Util';
require_ok 'Exporter';

DESPUÉS:

use Test2::V0;
plan(11);
use Scalar::Util;
require Exporter;
Reemplazar Test::More con Test2::V0
Test2::V0 es el paquete recomendado. En una migración completa, querrás reemplazar Test::More con el paquete Test2::V0.

Nota: Siempre debes verificar la última versión de Test2 para ver si hay un nuevo paquete recomendado. Al escribir una prueba nueva, siempre debes usar el módulo Test::V# más reciente. Números más altos son versiones más nuevas.

NOTA: srand
Cuando srand está activado (por defecto), puede causar problemas con cosas como File::Temp, que intentarán usar los mismos nombres de archivo "aleatorios" para cada proceso de prueba iniciado en un día determinado (o que comparten la misma semilla).

Si esto es un problema para ti, por favor deshabilita srand al cargar Test2::V0:

use Test2::V0 -no_srand => 1;
Dejar de usar use_ok()
use_ok() ha sido eliminado. una declaración "use MODULE" lanzará una excepción en caso de fallo de todos modos, impidiendo que la prueba pase.

Si *realmente* quieres/necesitas asegurar que el archivo se cargó, puedes usar el módulo ok:

use ok 'Scalar::Util';

La principal diferencia aquí es que hay un espacio en lugar de un guion bajo.

Dejar de usar require_ok()
"require_ok" ha sido eliminado al igual que "use_ok". No hay un equivalente del módulo ok aquí. Simplemente usa "require".
Eliminar strict/warnings (opcional)
El paquete Test2::V0 activa strict y warnings por ti.
Cambiar dónde se establece el plan
Test2 no te permite establecer el plan en la importación. En el código antiguo, pasarías "tests => 11" como argumento de importación. En Test2, necesitas usar la función plan() para establecer el plan, o usar done_testing() al final de la prueba.

Si tu prueba ya usa done_testing(), puedes mantenerla y no se necesitan cambios en el plan.

Nota: También estamos cambiando el plan de 14 a 11, esto se debe a que hemos eliminado "use_ok", "require_ok", y eliminaremos uno más más adelante. Es por eso que done_testing() se recomienda sobre un plan establecido.

ASERTOS SIMPLES

La gran mayoría de los asertos no necesitarán ningún cambio:

#####################
# Asertos simples (sin cambios)
ok(1, "pass");
is("apple", "apple", "Comparación simple de cadenas");
like("foo bar baz", qr/bar/, "Coincidencia de expresión regular");

PENDIENTE

{
    local $TODO = "Estos son pendientes";
    ok(0, "ups");
}

La variable de paquete $TODO ha desaparecido. Ahora tienes una función todo().

Hay 2 formas de usar esto:

todo $razón => sub { ... }
todo "Estos son pendientes" => sub {
    ok(0, "ups");
};

Esta es la forma más limpia de hacer un pendiente. Hará que todos los asertos dentro del bloque de código sean asertos PENDIENTES.

{ my $TODO-todo-razon-sub2}
{
    my $TODO = todo "Estos son pendientes";
    ok(0, "ups");
}

Este es un sistema que emula la forma antigua. En lugar de modificar una variable global $TODO, creas un objeto pendiente con la función todo() y lo asignas a una variable léxica. Una vez que el objeto pendiente sale del ámbito, el PENDIENTE termina.

COMPARACIONES PROFUNDAS

is_deeply([1, 2, 3], [1, 2, 3], "Comparación profunda");

Las comparaciones profundas son fáciles, simplemente reemplaza is_deeply() con is().

is([1, 2, 3], [1, 2, 3], "Comparación profunda");

COMPARACIÓN DE REFERENCIAS

my $ref = [1];
is($ref, $ref, "Verificar que tenemos la misma referencia ambas veces");

La función is() proporcionada por Test::More fuerza ambos argumentos a cadenas, lo que hace que esta sea una comparación de las direcciones de las referencias. La función is() de Test2 es una comparación profunda, por lo que esto seguirá pasando, pero no logrará probar lo que queremos (que ambas referencias sean exactamente la misma ref, no solo estructuras idénticas).

Ahora tenemos la función ref_is() que hace lo que realmente queremos, asegura que ambas referencias sean la misma referencia. Esta función hace el trabajo mejor que la original, que podría verse afectada por la sobrecarga de cadenas.

my $ref = [1];
ref_is($ref, $ref, "Verificar que tenemos la misma referencia ambas veces");

HERRAMIENTAS QUE HAN DESAPARECIDO

ok(eq_array([1], [1]), "comparación de arrays");
ok(eq_hash({a => 1}, {a => 1}), "comparación de hashes");
ok(eq_set([1, 3, 2], [1, 2, 3]), "comparación de conjuntos");
note explain([1, 2, 3]);
{
    package THING;
    sub new { bless({}, shift) }
}
my $thing = new_ok('THING');

"eq_array", "eq_hash" y "eq_set" han sido consideradas obsoletas durante mucho tiempo, Test2 no las proporciona en absoluto. En su lugar, puedes usar is():

is([1], [1], "comparación de arrays");
is({a => 1}, {a => 1}, "comparación de hashes");

"eq_set" es un poco más complicado, consulta Test2::Tools::Compare para obtener una explicación:

is([1, 3, 2], bag { item 1; item 2; item 3; end }, "comparación de conjuntos");

explain() tiene un historial complicado. Ha habido argumentos sobre cómo debería funcionar.

Test2::Manual::Testing::Migrating(3perl)

NAME

Test2::Manual::Testing::Migrating - Migrating from Test::More to Test2

DESCRIPTION

This document covers the most common issues when migrating code from Test::More to Test2.

It is generally recommended to use Test2::V0 as this will import all the necessary modules for you. This is done with:

    use Test2::V0;

If you are migrating from Test::More, you may have seen code like this:

    use Test::More tests => 2;
    ok(1);
    is($foo, $bar);

This will work perfectly fine with Test2. All of the functions in Test::More are exported by Test2::V0 (and Test2::API).

However, there are many functions that are either gone, or have changed.

LEGACY TEST

The Test::More module used to have a function called legacy_test. This has been removed and is not available in Test2.

BOILERPLATE

Test2 will use a different boilerplate for tests. This is due to the fact that Test2 uses a different method for determining the number of tests to run.

    use Test::More tests => 10;

This will be replaced with:

    use Test2::V0;
    plan(10);

SIMPLE ASSERTIONS

ok(), is(), like(), unlike(), is_deeply(), is_number(), is_uuid(), skip(), and diag() all work the same way they do in Test::More.

    is([1, 2, 3], [1, 2, 3], "array comparison");
    is({a => 1}, {a => 1}, "hash comparison");

is_deeply() is not exported by Test2::V0, but can be imported from Test2::Tools::Deep.

Test2 also adds bag() for set comparisons:

    use Test2::V0;
    is([1, 3, 2], bag { item 1; item 2; item 3; end }, "set comparison");

TODO

The todo() block has changed slightly. It now requires a name for the todo block.

    use Test2::V0;
    plan(1);
    todo "This test is not working yet" => sub {
        ok(0, "This will fail");
    };

DEEP COMPARISONS

Test2::V0 does not export is_deeply. Instead it exports is, which will do a deep comparison if the two arguments are arrays or hashes.

    is([1, 2, 3], [1, 2, 3], "array comparison");
    is({a => 1}, {a => 1}, "hash comparison");

If you need the old behavior of is_deeply you can import it from Test2::Tools::Deep.

    use Test2::V0;
    use Test2::Tools::Deep 'is_deeply';

However, the bag function mentioned above is available with Test2::V0.

COMPARING REFERENCES

Test2::V0 exports ref_is for comparing references.

    my $ref = [1];
    ref_is($ref, $ref, "Check that we have the same ref both times");

TOOLS THAT ARE GONE

Test2 decided to simply not include explain() to avoid the arguments. You can instead directly use Data::Dumper:

use Data::Dumper;
note Dumper([1, 2, 3]);

new_ok() is gone. The implementation was complicated, and did not add much value:

{
    package THING;
    sub new { bless({}, shift) }
}
my $thing = THING->new;
ok($thing, "made a new thing");

The complete section after the conversion is:

is([1], [1], "array comparison");
is({a => 1}, {a => 1}, "hash comparison");
is([1, 3, 2], bag { item 1; item 2; item 3; end }, "set comparison");
use Data::Dumper;
note Dumper([1, 2, 3]);
{
    package THING;
    sub new { bless({}, shift) }
}
my $thing = THING->new;
ok($thing, "made a new thing");

TOOLS THAT HAVE CHANGED

isa_ok($thing, 'THING', '$thing');
can_ok(__PACKAGE__, qw/ok is/);

In Test::More these functions are very confusing, and most people use them wrong!

isa_ok() from Test::More takes a thing, a class/reftype to check, and then uses the third argument as an alternative display name for the first argument (NOT a test name!).

can_ok() from Test::More is not consistent with "isa_ok" as all arguments after the first are subroutine names.

Test2 fixes this by making both functions consistent and obvious:

isa_ok($thing, ['THING'], 'got a THING');
can_ok(__PACKAGE__, [qw/ok is/], "have expected subs");

You will note that both functions take a thing, an arrayref as the second argument, then a test name as the third argument.

FINAL VERSION

#####################
# Boilerplate
use Test2::V0;
plan(11);
use Scalar::Util;
require Exporter;
#####################
# Simple assertions (no changes)
ok(1, "pass");
is("apple", "apple", "Simple string compare");
like("foo bar baz", qr/bar/, "Regex match");
#####################
# Todo
todo "These are todo" => sub {
    ok(0, "oops");
};
#####################
# Deep comparisons
is([1, 2, 3], [1, 2, 3], "Deep comparison");
#####################
# Comparing references
my $ref = [1];
ref_is($ref, $ref, "Check that we have the same ref both times");
#####################
# Things that are gone
is([1], [1], "array comparison");
is({a => 1}, {a => 1}, "hash comparison");
is([1, 3, 2], bag { item 1; item 2; item 3; end }, "set comparison");
use Data::Dumper;
note Dumper([1, 2, 3]);
{
    package THING;
    sub new { bless({}, shift) }
}
my $thing = THING->new;
#####################
# Tools that changed
isa_ok($thing, ['THING'], 'got a THING');
can_ok(__PACKAGE__, [qw/ok is/], "have expected subs");
