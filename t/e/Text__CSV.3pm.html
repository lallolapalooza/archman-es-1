NOMBRE

Text::CSV - manipulador de valores separados por comas (usando XS o PurePerl)

SINOPSIS

Esta sección está tomada de Text::CSV_XS.

# Interfaz funcional
use Text::CSV qw( csv );
# Leer archivo completo en memoria
my $aoa = csv (in => "data.csv");    # como array de arrays
my $aoh = csv (in => "data.csv",
               headers => "auto");   # como array de hashes
# Escribir array de arrays como archivo csv
csv (in => $aoa, out => "file.csv", sep_char => ";");
# Mostrar solo líneas donde "code" es impar
csv (in => "data.csv", filter => { code => sub { $_ % 2 }});
# Interfaz de objeto
use Text::CSV;
my @rows;
# Leer/analizar CSV
my $csv = Text::CSV->new ({ binary => 1, auto_diag => 1 });
open my $fh, "<:encoding(utf8)", "test.csv" or die "test.csv: $!";
while (my $row = $csv->getline ($fh)) {
    $row->[2] =~ m/patron/ or next; # el 3er campo debe coincidir
    push @rows, $row;
    }
close $fh;
# y escribir como CSV
open $fh, ">:encoding(utf8)", "new.csv" or die "new.csv: $!";
$csv->say ($fh, $_) for @rows;
close $fh or die "new.csv: $!";

DESCRIPCIÓN

Text::CSV es un envoltorio delgado para módulos compatibles con Text::CSV_XS ahora. Todos los módulos backend proporcionan instalaciones para la composición y descomposición de valores separados por comas. Text::CSV utiliza Text::CSV_XS por defecto, y cuando Text::CSV_XS no está disponible, recurre a Text::CSV_PP, que se incluye en la misma distribución que este módulo.

ELECCIÓN DEL BACKEND

Este módulo respeta una variable de entorno llamada "PERL_TEXT_CSV" cuando decide qué módulo backend usar. Si esta variable de entorno no está establecida, intenta cargar Text::CSV_XS, y si Text::CSV_XS no está disponible, recurre a Text::CSV_PP;.

Si nunca quiere que recurra a Text::CSV_PP, establezca la variable de esta manera ( "export" puede ser "setenv", "set" y similares, dependiendo de su entorno):

> export PERL_TEXT_CSV=Text::CSV_XS

Si prefiere Text::CSV_XS a Text::CSV_PP (por defecto), entonces:

> export PERL_TEXT_CSV=Text::CSV_XS,Text::CSV_PP

También puede querer establecer esta variable en la parte superior de sus archivos de prueba, para no ser molestado por incompatibilidades entre backends (necesita envolver esto en "BEGIN", y establecerlo antes de "use"-ar el módulo Text::CSV, ya que decide su backend tan pronto como se carga):

BEGIN { $ENV{PERL_TEXT_CSV}='Text::CSV_PP'; }
use Text::CSV;

Nuevas líneas incrustadas

Nota importante: El comportamiento por defecto es aceptar solo caracteres ASCII en el rango de 0x20 (espacio) a 0x7E (tilde). Esto significa que los campos no pueden contener saltos de línea. Si sus datos contienen saltos de línea incrustados en campos, o caracteres por encima de 0x7E (tilde), o datos binarios, debe establecer "binary => 1" en la llamada a "new". Para cubrir el rango más amplio de opciones de análisis, siempre querrá establecer binario.

Pero todavía tiene el problema de que tiene que pasar una línea correcta al método "parse", lo cual es más complicado que el uso habitual:

my $csv = Text::CSV->new ({ binary => 1, eol => $/ });
while (<>) {           # INCORRECTO!
    $csv->parse ($_);
    my @fields = $csv->fields ();
    }

esto fallará, ya que el bucle "while" puede leer líneas rotas: no le importa el entrecomillado. Si necesita admitir saltos de línea incrustados, la forma de hacerlo es no pasar "eol" en el analizador (acepta "\n", "\r" y "\r\n" por defecto) y luego:

my $csv = Text::CSV->new ({ binary => 1 });
open my $fh, "<", $file or die "$file: $!";
while (my $row = $csv->getline ($fh)) {
    my @fields = @$row;
    }

La forma antigua de usar manejadores de archivos globales todavía es compatible

while (my $row = $csv->getline (*ARGV)) { ... }

Unicode

Unicode solo se prueba que funcione con perl-5.8.2 y superior.

Ver también "BOM".

La forma más sencilla de asegurar que se utiliza la codificación correcta para la entrada y salida es estableciendo capas en los manejadores de archivos, o estableciendo el argumento "encoding" para "csv".

 open my $fh, "<:encoding(UTF-8)", "in.csv"  or die "in.csv: $!";
o
 my $aoa = csv (in => "in.csv",     encoding => "UTF-8");
 open my $fh, ">:encoding(UTF-8)", "out.csv" or die "out.csv: $!";
o
 csv (in => $aoa, out => "out.csv", encoding => "UTF-8");

Al analizar (tanto para "getline" como para "parse"), si la fuente está marcada como UTF8, entonces todos los campos que estén marcados como binarios también estarán marcados como UTF8.

Al combinar ("print" y "combine"): si alguno de los campos combinados estaba marcado como UTF8, la cadena resultante estará marcada como UTF8. Tenga en cuenta, sin embargo, que todos los campos *anteriores* al primer campo marcado como UTF8 y que contenían caracteres de 8 bits que no fueron actualizados a UTF8, estos también serán "bytes" en la cadena resultante, lo que posiblemente cause errores inesperados. Si pasa datos de codificación diferente, o no sabe si hay codificación diferente, fuerce su actualización antes de pasarlos:

$csv->print ($fh, [ map { utf8::upgrade (my $x = $_); $x } @data ]);

Para un control completo sobre la codificación, utilice Text::CSV::Encoded:

use Text::CSV::Encoded;
my $csv = Text::CSV::Encoded->new ({
    encoding_in  => "iso-8859-1", # la codificación entra en  Perl
    encoding_out => "cp1252",     # la codificación sale de Perl
    });
$csv = Text::CSV::Encoded->new ({ encoding  => "utf8" });
# combine () y print () aceptan datos codificados *literalmente* como utf8
# parse () y getline () devuelven datos codificados *literalmente* como utf8
$csv = Text::CSV::Encoded->new ({ encoding  => undef }); # por defecto
# combine () y print () aceptan datos marcados como UTF8
# parse () y getline () devuelven datos marcados como UTF8

BOM

El manejo de BOM (o Marca de Orden de Bytes) solo está disponible dentro del método "header". Este método soporta las siguientes codificaciones: "utf-8", "utf-1", "utf-32be", "utf-32le", "utf-16be", "utf-16le", "utf-ebcdic", "scsu", "bocu-1" y "gb-18030". Ver Wikipedia https://en.wikipedia.org/wiki/Byte_order_mark.

Si un archivo tiene un BOM, la forma más fácil de tratar con él es

my $aoh = csv (in => $file, detect_bom => 1);

Todos los registros se codificarán basándose en el BOM detectado.

Esto implica una llamada al método "header", que por defecto también establece las "column_names". Así que esto no es lo mismo que

my $aoh = csv (in => $file, headers => "auto");

que solo lee el primer registro para establecer "column_names" pero ignora cualquier significado de un BOM posiblemente presente.

callback
my $csv = Text::CSV->new ({ skip_empty_rows => sub { [] } });
$csv->skip_empty_rows (sub { [ 42, $., undef, "empty" ] });

Se invoca la devolución de llamada y se utiliza su resultado en su lugar. Si desea que el análisis se detenga después de la devolución de llamada, asegúrese de devolver un valor falso.

El valor devuelto por la devolución de llamada debe ser una referencia de matriz. Cualquier otro tipo hará que el análisis se detenga, por lo que estos son equivalentes en comportamiento:

csv (in => $fh, skip_empty_rows => "stop");
csv (in => $fh. skip_empty_rows => sub { 0; });

Sin argumentos, se devuelve el valor actual:

0, 1, "eof", "die", "croak" o el callback.

formula_handling

Alias para "formula"

formula

my $csv = Text::CSV->new ({ formula => "none" });
        $csv->formula ("none");
my $f = $csv->formula;

Esto define el comportamiento de las columnas que contienen fórmulas. Dado que las fórmulas se consideran peligrosas en las hojas de cálculo, este atributo puede definir una acción opcional a realizar si una fila comienza con un signo igual ("=").

También se puede escribir de esta manera para mejorar la legibilidad del código:

my $csv = Text::CSV->new ({ formula_handling => "none" });
        $csv->formula_handling ("none");
my $f = $csv->formula_handling;

Los valores posibles para este atributo son:

none
No realizar ninguna acción específica. Este es el valor por defecto.
die
Hace que el proceso se detenga ("die") al encontrar una línea que comience con "=".
croak
Hace que el proceso falle ("croak") al encontrar una línea que comience con "=". (Ver Carp)
diag
Imprime la posición y el contenido de la fila al encontrar una línea que comience con "=". El valor de la fila no cambia.
empty
Reemplaza el contenido de las filas que comienzan con "=" con una cadena vacía.
undef
Reemplaza el contenido de las filas que comienzan con "=" con "undef".
un callback
Modifica el contenido de las filas que comienzan con "=" con el valor devuelto por el callback. El contenido original de la fila está disponible dentro del callback como $_;
# Reemplaza todas las fórmulas con 42
$csv->formula (sub { 42; });
# lo mismo que $csv->formula ("empty") pero más lento
$csv->formula (sub { "" });
# Permite =4+12
$csv->formula (sub { s/^=(\d+\+\d+)$/$1/eer });
# Permite cálculos más complejos
$csv->formula (sub { eval { s{^=([-+*/0-9()]+)$}{$1}ee }; $_ });

Cualquier otro valor generará una advertencia y luego actuará como "diag".

decode_utf8

my $csv = Text::CSV->new ({ decode_utf8 => 1 });
        $csv->decode_utf8 (0);
my $f = $csv->decode_utf8;

Este atributo tiene el valor TRUE por defecto.

Al procesar el archivo, las filas válidamente en UTF-8 se establecen automáticamente como UTF-8, así que:

$csv->parse ("\xC4\xA8\n");

produce:

A veces esto no es deseable. Para evitar estos cambios, establezca este atributo a FALSE y el resultado será:

PV("\304\250"\0)

blank_is_undef

my $csv = Text::CSV->new ({ blank_is_undef => 1 });
        $csv->blank_is_undef (0);
my $f = $csv->blank_is_undef;

En circunstancias normales, los datos "CSV" no distinguen entre campos entrecomillados y sin entrecomillar. Ambos se convierten en una cadena vacía al leer, por lo que:

1,"",," ",2

se lee como:

("1", "", "", " ", "2")

Al escribir "CSV" con "always_quote" o "quote_empty" activados, el campo sin entrecomillar es el resultado de un valor indefinido. Para habilitar esta distinción al leer datos "CSV", el atributo "blank_is_undef" hará que los campos sin entrecomillar se establezcan en "undef", haciendo que la lectura anterior se interprete como:

("1", "", undef, " ", "2")

Tenga en cuenta que esto es particularmente importante al cargar campos "CSV" en una base de datos que permite valores "NULL", ya que el equivalente de "NULL" en DBI es "undef".

empty_is_undef

my $csv = Text::CSV->new ({ empty_is_undef => 1 });
        $csv->empty_is_undef (0);
my $f = $csv->empty_is_undef;

Dando un paso más allá que "blank_is_undef", este atributo convierte todos los campos vacíos en "undef", por lo que:

1,"",," ",2

se lee como:

(1, undef, undef, " ", 2)

Tenga en cuenta que esto solo afecta a los campos que están originalmente vacíos, no a los campos vacíos después de eliminar los espacios permitidos. Su experiencia puede variar.

allow_whitespace

my $csv = Text::CSV->new ({ allow_whitespace => 1 });
        $csv->allow_whitespace (0);
my $f = $csv->allow_whitespace;

Cuando esta opción está establecida en TRUE, los espacios en blanco ( "TAB" y "ESPACIO" ) alrededor del delimitador se eliminan durante el análisis. Si "TAB" o "ESPACIO" es uno de los tres caracteres "sep_char", "quote_char" o "escape_char", no se considera espacio en blanco.

Ahora líneas como:

1 , "foo" , bar , 3 , zapp

se analizan como "CSV" válidos, aunque violen los estándares "CSV".

Tenga en cuenta que **todos** los espacios en blanco se eliminan de ambos lados de cada campo. Esto sería más una característica que una característica para permitir el análisis de líneas "CSV" mal formadas, ya que:

1,   2.0,  3,   ape  , monkey

se analiza como:

("1", "2.0", "3", "ape", "monkey")

aunque la línea original fuera perfectamente aceptable "CSV".

allow_loose_quotes

my $csv = Text::CSV->new ({ allow_loose_quotes => 1 });
        $csv->allow_loose_quotes (0);
my $f = $csv->allow_loose_quotes;

Por defecto, el análisis de campos sin comillas que contienen caracteres "quote_char" como:

1,foo "bar" baz,42

produce un error de análisis 2034. Aunque todavía es práctico evitar este formato, no podemos ayudar a los factores que hacen que algunos proveedores de aplicaciones desechen líneas de este estilo.

Si hay datos "CSV" realmente malos, como:

1,"foo "bar" baz",42

o

1,""foo bar baz"",42

hay una forma de analizar esta línea y dejar las comillas dentro del campo entrecomillado sin cambios. Esto se puede lograr estableciendo "allow_loose_quotes" **y** asegurándose de que el "escape_char" no sea igual al "quote_char").

allow_loose_escapes

my $csv = Text::CSV->new ({ allow_loose_escapes => 1 });
        $csv->allow_loose_escapes (0);
my $f = $csv->allow_loose_escapes;

escape_char

my $csv = Text::CSV->new ({ escape_char => "\"" });
        $csv->escape_char ("\"");
my $f = $csv->escape_char;

The character used to escape the quote_char. Defaults to the quote_char itself. This implies that the "quote_char" must be escaped within a field, or if it is part of a quoted field.

If "escape_char" is set to "1", then the character that follows will be escaped.

my $csv = Text::CSV->new ({ sep_char => ",", escape_char => "1"});
my $row = [qw( a b )];
$csv->print(*STDOUT, \$row);
# a,b
my $row = [qw( a,b )];
$csv->print(*STDOUT, \$row);
# a1,b  -- THIS IS NOT STANDARD CSV --

The example above is not standard CSV, and is only shown for completeness of the attribute.

The character that is escaped is not necessarily the "escape_char" itself.

The default setting will escape the "quote_char" itself.

If "escape_char" is set to "0", then no character is escaped, regardless of the value of "quote_char". This is a potential security risk if the data is not already escaped.

A NULL byte (\0) will never be escaped when "binary" is true.

If escape_char is set to "escape_char => 1" and "escape_char => \"\\\"", this would be illegal:

1,\0,2

Setting this attribute to 1 might help to overcome issues with backward compatibility and allow this style.

my $csv = Text::CSV->new ({ always_quote => 1 });
        $csv->always_quote (0);
my $f = $csv->always_quote;

By default the generated fields are quoted only if they need to be. For example, if they contain the separator character. If you set this attribute to 1 then all defined fields will be quoted. ("undef" fields are not quoted, see "blank_is_undef"). This makes it quite often easier to handle exported data in external applications.

quote_space

my $csv = Text::CSV->new ({ quote_space => 1 });
        $csv->quote_space (0);
my $f = $csv->quote_space;

By default, a space in a field would trigger quotation. As no rule exists this to be forced in "CSV", nor any for the opposite, the default is true for safety. You can exclude the space from this trigger by setting this attribute to 0.

quote_empty

my $csv = Text::CSV->new ({ quote_empty => 1 });
        $csv->quote_empty (0);
my $f = $csv->quote_empty;

By default the generated fields are quoted only if they need to be. An empty (defined) field does not need quotation. If you set this attribute to 1 then empty defined fields will be quoted. ("undef" fields are not quoted, see "blank_is_undef"). See also "always_quote".

quote_binary

my $csv = Text::CSV->new ({ quote_binary => 1 });
        $csv->quote_binary (0);
my $f = $csv->quote_binary;

By default, all "unsafe" bytes inside a string cause the combined field to be quoted. By setting this attribute to 0, you can disable that trigger for bytes ">= 0x7F".

escape_null

my $csv = Text::CSV->new ({ escape_null => 1 });
        $csv->escape_null (0);
my $f = $csv->escape_null;

By default, a "NULL" byte in a field would be escaped. This option enables you to treat the "NULL" byte as a simple binary character in binary mode (the "{ binary => 1 }" is set). The default is true. You can prevent "NULL" escapes by setting this attribute to 0.

When the "escape_char" attribute is set to undefined, this attribute will be set to false.

The default setting will encode "=\x00=" as

"="0="

With "escape_null" set, this will result in

"=\x00="

The default when using the "csv" function is "false".

For backward compatibility reasons, the deprecated old name "quote_null" is still recognized.

keep_meta_info

my $csv = Text::CSV->new ({ keep_meta_info => 1 });
        $csv->keep_meta_info (0);
my $f = $csv->keep_meta_info;

By default, the parsing of input records is as simple and fast as possible. However, some parsing information - like quotation of the original field - is lost in that process. Setting this flag to true enables retrieving that information after parsing with the methods "meta_info", "is_quoted", and "is_binary" described below. Default is false for performance.

If you set this attribute to a value greater than 9, then you can control output quotation style like it was used in the input of the the last parsed record (unless quotation was added because of other reasons).

my $csv = Text::CSV->new ({
   binary         => 1,
   keep_meta_info => 1,
   quote_space    => 0,
   });
my $row = $csv->parse (q{1,,"", ," ",f,"g","h""h",help,"help"});
$csv->print (*STDOUT, \@row);
# 1,,, , ,f,g,"h""h",help,help
$csv->keep_meta_info (11);
$csv->print (*STDOUT, \@row);
# 1,,"", ," ",f,"g","h""h",help,"help"

undef_str

my $csv = Text::CSV->new ({ undef_str => "\\N" });
        $csv->undef_str (undef);
my $s = $csv->undef_str;

This attribute optionally defines the output of undefined fields. The value passed is not changed at all, so if it needs quotation, the quotation needs to be included in the value of the attribute. Use with caution, as passing a value like ",",,,,""" will for sure mess up your output. The default for this attribute is "undef", meaning no special treatment.

This attribute is useful when exporting CSV data to be imported in custom loaders, like for MySQL, that recognize special sequences for "NULL" data.

This attribute has no meaning when parsing CSV data.

comment_str

my $csv = Text::CSV->new ({ comment_str => "#" });
        $csv->comment_str (undef);
my $s = $csv->comment_str;

This attribute optionally defines a string to be recognized as comment. If this attribute is defined, all lines starting with this sequence will not be parsed as CSV but skipped as comment.

This attribute has no meaning when generating CSV.

Comment strings that start with any of the special characters/sequences are not supported (so it cannot start with any of "sep_char", "quote_char", "escape_char", "sep", "quote", or "eol").

For convenience, "comment" is an alias for "comment_str".

verbatim

my $csv = Text::CSV->new ({ verbatim => 1 });
        $csv->verbatim (0);
my $f = $csv->verbatim;

This is a quite controversial attribute to set, but makes some hard things possible.

The rationale behind this attribute is to tell the parser that the normally special characters newline ("NL") and Carriage Return ("CR") will not be special when this flag is set, and be dealt with as being ordinary binary characters. This will ease working with data with embedded newlines.

When "verbatim" is used with "getline", "getline" auto-"chomp"'s every line.

Imagine a file format like

M^^Hans^Janssen^Klas 2\n2A^Ja^11-06-2007#\r\n

where, the line ending is a very specific "#\r\n", and the sep_char is a "^" (caret). None of the fields is quoted, but embedded binary data is likely to be present. With the specific line ending, this should not be too hard to detect.

By default, Text::CSV->parse function is instructed to only know about "\n" and "\r" to be legal line endings, and so has to deal with the embedded newline as a real "end-of-line", so it can scan the next line if binary is true, and the newline is inside a quoted field. With this option, we tell "parse" to parse the line as if "\n" is just nothing more than a binary character.

For "parse" this means that the parser has no more idea about line ending and "getline" "chomp"s line endings on reading.

types

print

my $status = $csv->print (FILEHANDLE, \$row_ref);

This method prints a single row of CSV data to the given FILEHANDLE. The row is passed as a reference to an array of fields.

The row is printed according to the current settings of the Text::CSV object.

The method returns true on success, and false on failure.

On failure, the error reason is available through the "error_diag" method.

The fields in the row can be of any scalar type (strings, numbers, undef).

The method is called print because it is a simple wrapper around the standard Perl print function.

For backward compatibility, the method also accepts a reference to a hash.

my $status = $csv->print (FILEHANDLE, \%hash_ref);

In this case, the keys of the hash are ignored, and only the values are used as fields in the row.

For backward compatibility, the method also accepts an array reference instead of a reference to an array.

my $status = $csv->print (FILEHANDLE, \@array);

This is not recommended, as it is ambiguous and may lead to errors.

If you want to print multiple rows, you should call this method multiple times.

If you need to print a very large number of rows, you might want to consider using the "print_rows" method instead, which is optimized for such cases.

print

$status = $csv->print ($fh, $colref);

Similar a "combine" + "string" + "print", pero mucho más eficiente. Espera una referencia a un array como entrada (¡no un array!) y la cadena resultante no se crea realmente, sino que se escribe inmediatamente en el objeto $fh, típicamente un manejador de IO o cualquier otro objeto que ofrezca un método "print".

Por razones de rendimiento, "print" no crea una cadena de resultado, por lo que todos los métodos "string", "status", "fields" y "error_input" devolverán información indefinida después de ejecutar este método.

Si $colref es "undef" (explícito, no a través de un argumento de variable) y se utilizó "bind_columns" para especificar los campos a imprimir, es posible obtener mejoras de rendimiento, ya que de lo contrario los datos tendrían que copiarse como argumentos a la llamada del método:

$csv->bind_columns (\($foo, $bar));
$status = $csv->print ($fh, undef);

Una breve comparación de rendimiento

my @data = ("aa" .. "zz");
$csv->bind_columns (\(@data));
$csv->print ($fh, [ @data ]);   # 11800 recs/sec
$csv->print ($fh,  \@data  );   # 57600 recs/sec
$csv->print ($fh,   undef  );   # 48500 recs/sec

Similar a "print", pero "eol" tiene por defecto "$\n".

print_hr

$csv->print_hr ($fh, $ref);

Este método construye un registro "CSV" a partir de @fields, devolviendo éxito o fracaso. El fracaso puede deberse a la falta de argumentos o a un argumento que contenga un carácter inválido. En caso de éxito, se puede llamar a "string" para obtener la cadena "CSV" resultante. En caso de fracaso, el valor devuelto por "string" no está definido y se puede llamar a "error_input" para obtener el argumento inválido.

string

Este método devuelve la entrada a "parse" o la cadena "CSV" resultante de "combine", la que se haya llamado más recientemente.

getline

Esta es la contraparte de "print", al igual que "parse" es la contraparte de "combine": analiza una fila del manejador $fh utilizando el método "getline" asociado a $fh y analiza esta fila en una referencia de array. Esta referencia de array es devuelta por la función o "undef" en caso de error. Cuando $fh no soporta "getline", es probable que encuentre errores.

Cuando los campos están enlazados con "bind_columns", el valor de retorno es una referencia a una lista vacía.

Los métodos "string", "fields" y "status" vuelven a carecer de sentido.

getline_all

$arrayref = $csv->getline_all ($fh);

$arrayref = $csv->getline_all ($fh, $offset, $length);

Esto devolverá una referencia a una lista de resultados de getline ($fh). En esta llamada, "keep_meta_info" está deshabilitado. Si $offset es negativo, como con "splice", solo los últimos "abs ($offset)" registros de $fh se tienen en cuenta. Se espera que los parámetros $offset y $length sean enteros. Los valores no enteros se interpretan como enteros sin verificación.

Dado un archivo CSV con 10 líneas:

lines call
----- ---------------------------------------------------------
0..9  $csv->getline_all ($fh)         # all
0..9  $csv->getline_all ($fh,  0)     # all
8..9  $csv->getline_all ($fh,  8)     # start at 8
-     $csv->getline_all ($fh,  0,  0) # start at 0 first 0 rows
0..4  $csv->getline_all ($fh,  0,  5) # start at 0 first 5 rows
4..5  $csv->getline_all ($fh,  4,  2) # start at 4 first 2 rows
8..9  $csv->getline_all ($fh, -2)     # last 2 rows
6..7  $csv->getline_all ($fh, -4,  2) # first 2 of last  4 rows

getline_hr

Los métodos "getline_hr" y "column_names" trabajan juntos para permitirle obtener filas como hashrefs. Debe llamar primero a "column_names" para declarar los nombres de sus columnas.

$csv->column_names (qw( code name price description ));
$hr = $csv->getline_hr ($fh);
print "Price for $hr->{name} is $hr->{price} EUR\n";

"getline_hr" fallará si se llama antes que "column_names".

Tenga en cuenta que "getline_hr" crea un hashref para cada fila y será mucho más lento que el uso combinado de "bind_columns" y "getline", pero seguirá ofreciendo el mismo hashref fácil de usar dentro del bucle:

my @cols = @{$csv->getline ($fh)};
$csv->column_names (@cols);
while (my $row = $csv->getline_hr ($fh)) {
    print $row->{price};
    }

Podría reescribirse fácilmente a lo mucho más rápido:

my @cols = @{$csv->getline ($fh)};
my $row = {};
$csv->bind_columns (\@{$row}{@cols});
while ($csv->getline ($fh)) {
    print $row->{price};
    }

Sus resultados pueden variar según el tamaño de los datos y el número de filas. Con perl-5.14.2, la comparación para un archivo de 100.000 líneas con 14 columnas:

           Rate hashrefs getlines
hashrefs 1.00/s       --     -76%
getlines 4.15/s     313%       --

Esto devolverá una referencia a una lista de resultados de getline_hr ($fh). En esta llamada, "keep_meta_info" está deshabilitado.

$status = $csv->parse ($line);

Este método descompone una cadena "CSV" en campos, devolviendo éxito o fracaso. El fracaso puede deberse a la falta de argumento o a que la cadena "CSV" dada esté mal formada. En caso de éxito, se puede llamar a "fields" para obtener los campos descompuestos. En caso de fracaso, llamar a "fields" devolverá datos indefinidos y se puede llamar a "error_input" para obtener el argumento inválido.

Puede utilizar el método "types" para establecer los tipos de columna. Consulte la descripción de "types" más abajo.

El argumento $line debe ser un escalar simple. Se supone que todo lo demás provocará un error y establecerá el error 1500.

fragment

Esta función intenta implementar RFC7111 (Identificadores de Fragmento URI para el Tipo de Medios text/csv) - https://datatracker.ietf.org/doc/html/rfc7111

my $AoA = $csv->fragment ($fh, $spec);

En las especificaciones, se utiliza ""*"" para especificar el *último* elemento, un guion ("-") para indicar un rango. Todos los índices están basados en 1: la primera fila o columna tiene el índice 1. Las selecciones se pueden combinar con el punto y coma (";").

Al utilizar este método en combinación con "column_names", la referencia devuelta apuntará a una lista de hashes en lugar de a una lista de listas. Una selección combinada disjointa basada en celdas podría devolver filas con un número diferente de columnas, lo que hace impredecible el uso de hashes.

$csv->column_names ("Name", "Age");
my $AoH = $csv->fragment ($fh, "col=3;8");

Si la devolución de llamada "after_parse" está activa, también se llama en cada línea analizada y omitida antes del fragmento.

row

row=5-7
row=6-*
row=1-2;4;6-*
col
col=2
col=1-3
col=4-*
col=1-2;4;7-*
cell
En la selección basada en celdas, la coma (",") se utiliza para emparejar fila y columna

El operador de rango ("-") utilizando "cell"s se puede usar para definir la ubicación de la celda superior izquierda e inferior derecha

cell=3,1-4,6

El "*" solo se permite en la segunda parte de un par

cell=3,2-*,2    # fila 3 hasta el final, solo columna 2
cell=3,2-3,*    # columna 2 hasta el final, solo fila 3
cell=3,2-*,*    # quitar fila 1 y 2, y columna 1

Las celdas y los rangos de celdas se pueden combinar con ";", lo que podría dar lugar a filas con diferentes números de columnas

cell=1,1-2,2;3,3-4,4;1,4;4,1

Las selecciones disjointas solo devolverán las celdas seleccionadas. Las celdas que no se especifican no se incluirán en el conjunto devuelto, ni siquiera como "undef". Como ejemplo, dada una "CSV" como

21,22,...28,29
:            :
91,...97,98,99

con "cell=1,1-2,2;3,3-4,4;1,4;4,1" se devolverá:

Las especificaciones de celdas superpuestas devolverán

DESCRIPTION

Text::CSV_XS is a module for parsing and generating CSV data. This module is a PerlXS wrapper around the CSV parsing engine.

The module is designed to conform to the RFC 4180 standard. However, it has options to relax the standard in various ways, like "allow_loose_quotes" and "allow_loose_escapes".

This document describes the interface to the Text::CSV_XS module.

A new instance of Text::CSV_XS is created using the "new" class method.

my $csv = Text::CSV_XS->new ( \%attribute_hash );

The following attributes can be passed to the constructor:

binary
If set to a true value (the default), the CSV parser will treat all fields as binary data. This is important if your CSV data contains non-ASCII characters. In binary mode, Text::CSV_XS will not try to decode the input using Perl's locale encoding; instead, it will treat the data as a sequence of bytes. The default value is true.
eol
The character(s) used to terminate lines. The default is "\n".
sep_char
The separator character. The default is ",".
quote_char
The quote character. The default is "\"".
escape_char
The escape character. The default is "\"".
allow_loose_quotes
If set to a true value, allows quotes within fields to not be escaped. For example, "a"b"c" will be parsed as "abc" instead of failing. The default is false.
ignore_quorum
If set to a true value, allows fields to contain unescaped quote characters if the field is not quoted. For example, "a,b,c" will be parsed as "a,b,c", where the comma is part of the field. The default is false.
auto_diag
If set to a true value (the default), Text::CSV_XS will automatically diagnose errors and print them to STDERR. If set to false, you need to manually check the return value of methods like "parse" and "getline" and call "error_diag" if an error occurred.
sep_is_set
This attribute is for internal use and indicates whether the separator character has been explicitly set. Do not change this.
skip_space_before_separator
If set to a true value, leading whitespace before the separator character is ignored. For example, "a , b" would be parsed as if it were "a,b". The default is false.
skip_space_after_separator
If set to a true value, whitespace immediately following the separator character is ignored. For example, "a, b" would be parsed as if it were "a,b". The default is false.
allow_whitespace
If set to a true value, whitespace around fields is allowed and ignored. This is equivalent to setting both "skip_space_before_separator" and "skip_space_after_separator" to true. The default is false.
keep_meta_info
If set to a true value, meta information about each field (e.g., whether it was quoted) will be kept. This information can be accessed using methods like "is_quoted", "is_binary", and "is_missing". The default is false.
fields_as_arrayref
If set to a true value, the "parse" and "getline" methods will return an array reference instead of an array. This can be more efficient for large datasets. The default is false.
allow_loose_escapes
If set to a true value, allows loose escapes, meaning that a quote character within a field that is not quoted will be treated as a literal quote. For example, "a\"b" will be parsed as "a\"b". The default is true.
blank_is_def
If set to true, a blank field is treated as undefined. If false, it is treated as an empty string. The default is true.
empty_is_error
If set to true, an empty line is considered an error. The default is false.

parse

@fields = $csv->parse( $string );

Parses a string containing CSV data and returns the fields as a list. If "fields_as_arrayref" is set to true, it returns an array reference.

If an error occurs and "auto_diag" is true, the error will be printed to STDERR. Otherwise, the method will return an empty list (or an empty array reference).

It is possible to bind columns to variables using "bind_columns". If columns are bound, "parse" will return the number of bound columns, and the values will be assigned to the bound variables.

Example:

$csv->bind_columns(\$code, \$name, \$price);
my $num_bound_fields = $csv->parse($string);
# $code, $name, $price now hold the values

If the number of fields in the string does not match the number of bound columns:

  • If there are fewer fields than bound columns, the remaining bound variables are left untouched.
  • If there are more fields than bound columns, the extra fields are ignored.

If "strict" mode is enabled (not directly a parameter, but implied by checks), and the number of fields does not match the number of bound columns, an error will be triggered (error code 2014).

combine

$string = $csv->combine( \@fields );

Generates a CSV-formatted string from a list of fields. The list can be passed as an array reference or as a list of arguments.

Example:

my $string = $csv->combine( "field1", "field2", "field3" );
# or
my @fields = ( "field1", "field2", "field3" );
my $string = $csv->combine( \@fields );

If "auto_diag" is true and an error occurs, the error will be printed to STDERR. Otherwise, the method will return "undef".

getline

@fields = $csv->getline( $fh );

Reads a single line from the filehandle $fh, parses it as CSV, and returns the fields as a list. If "fields_as_arrayref" is set to true, it returns an array reference.

This method internally calls "parse" after reading a line from the filehandle. It also handles end-of-file conditions.

If an error occurs and "auto_diag" is true, the error will be printed to STDERR. Otherwise, the method will return an empty list (or an empty array reference).

Like "parse", "getline" supports column binding. If columns are bound, it returns the number of bound columns and assigns the parsed values to the bound variables.

Example:

while (my @row = $csv->getline(\*STDIN)) {
    # process @row
}

If the number of fields in the line does not match the number of bound columns:

  • If there are fewer fields than bound columns, the remaining bound variables are left untouched.
  • If there are more fields than bound columns, the extra fields are ignored.

If "strict" mode is enabled, and the number of fields does not match the number of bound columns, an error will be triggered (error code 3006 for fewer fields, 2014 for more fields).

getline_hr

my $hashref = $csv->getline_hr( $fh );

Reads a single line from the filehandle $fh, parses it as CSV, and returns the fields as a hash reference. This method requires that the "column_names" attribute has been set.

Example:

$csv->column_names( "code", "name", "price" );
while ( my $row = $csv->getline_hr( \*STDIN ) ) {
    print "Product: $row->{name}\n";
}

If an error occurs and "auto_diag" is true, the error will be printed to STDERR. Otherwise, the method will return "undef".

Note that if "keep_meta_info" is true, the hash returned will contain additional keys like "_quoted", "_binary", and "_missing". These keys provide meta information about the corresponding fields.

bind_columns

$csv->bind_columns( \$col1, \$col2, ... );
$csv->bind_columns( undef );

This method is used to bind columns to specific scalar variables. When "parse" or "getline" is called after binding columns, the parsed values will be automatically assigned to the bound variables.

If you pass a list of scalar variable references to "bind_columns", the first field will be assigned to the first variable, the second field to the second variable, and so on.

If the number of fields in the input does not match the number of bound columns, the behavior depends on the strictness settings. In non-strict mode, extra fields are ignored, and if there are fewer fields than bound columns, the remaining bound variables are left untouched. In strict mode, this situation will cause an error.

To reset or clear all column bindings, call "bind_columns" with the single argument "undef". This will also clear column names.

If no arguments are passed at all, "bind_columns" will return the list of current bindings or "undef" if no binds are active.

Note that in parsing with "bind_columns", the fields are set on the fly. That implies that if the third field of a row causes an error (or this row has just two fields where the previous row had more), the first two fields already have been assigned the values of the current row, while the rest of the fields will still hold the values of the previous row. If you want the parser to fail in these cases, use the "strict" attribute.

$csv->bind_columns (\$code, \$name, \$price, \$description);
while ($csv->getline ($fh)) {
    print "The price of a $name is \x{20ac} $price\n";
    }

To reset or clear all column binding, call "bind_columns" with the single argument "undef". This will also clear column names.

$csv->bind_columns (undef);

If no arguments are passed at all, "bind_columns" will return the list of current bindings or "undef" if no binds are active.

eof

$eof = $csv->eof ();

If "parse" or "getline" was used with an IO stream, this method will return true (1) if the last call hit end of file, otherwise it will return false (''). This is useful to see the difference between a failure and end of file.

Note that if the parsing of the last line caused an error, "eof" is still true. That means that if you are not using "auto_diag", an idiom like

while (my $row = $csv->getline ($fh)) {
    # ...
    }
$csv->eof or $csv->error_diag;

will not report the error. You would have to change that to

while (my $row = $csv->getline ($fh)) {
    # ...
    }
+$csv->error_diag and $csv->error_diag;

types

$csv->types (\@tref);

This method is used to force that (all) columns are of a given type. For example, if you have an integer column, two columns with doubles and a string column, then you might do a

$csv->types ([Text::CSV::IV (),
              Text::CSV::NV (),
              Text::CSV::NV (),
              Text::CSV::PV ()]);

Column types are used only for decoding columns while parsing, in other words by the "parse" and "getline" methods.

You can unset column types by doing a

$csv->types (undef);

or fetch the current type settings with

$types = $csv->types ();

@columns = $csv->fields ();

This method returns the input to "combine" or the resultant decomposed fields of a successful "parse", whichever was called more recently.

Note that the return value is undefined after using "getline", which does not fill the data structures returned by "parse".

meta_info

@flags = $csv->meta_info ();

This method returns the "flags" of the input to "combine" or the flags of the resultant decomposed fields of "parse", whichever was called more recently.

For each field, a meta_info field will hold flags that inform something about the field returned by the "fields" method or passed to the "combine" method. The flags are bit-wise-"or"'d like:

0x0001
"CSV_FLAGS_IS_QUOTED"
The field was quoted.
0x0002
"CSV_FLAGS_IS_BINARY"
The field was binary.
0x0004
"CSV_FLAGS_ERROR_IN_FIELD"
The field was invalid.

Currently only used when "allow_loose_quotes" is active.

0x0010
"CSV_FLAGS_IS_MISSING"
The field was missing.

See the "is_***" methods below.

is_quoted

my $quoted = $csv->is_quoted ($column_idx);

where $column_idx is the (zero-based) index of the column in the last result of "parse".

This returns a true value if the data in the indicated column was enclosed in "quote_char" quotes. This might be important for fields where content ",20070108," is to be treated as a numeric value, and where ","20070108"," is explicitly marked as character string data.

This method is only valid when "keep_meta_info" is set to a true value.

is_binary

my $binary = $csv->is_binary ($column_idx);

where $column_idx is the (zero-based) index of the column in the last result of "parse".

This returns a true value if the data in the indicated column contained any byte in the range "[\x00-\x08,\x10-\x1F,\x7F-\xFF]".

This method is only valid when "keep_meta_info" is set to a true value.

is_missing

my $missing = $csv->is_missing ($column_idx);

where $column_idx is the (zero-based) index of the column in the last result of "getline_hr".

$csv->keep_meta_info (1);
while (my $hr = $csv->getline_hr ($fh)) {
    $csv->is_missing (0) and next; # This was an empty line
    }

When using "getline_hr", it is impossible to tell if the parsed fields are "undef" because they where not filled in the "CSV" stream or because they were not read at all, as all the fields defined by "column_names" are set in the hash-ref. If you still need to know if all fields in each row are provided, you should enable "keep_meta_info" so you can check the flags.

If "keep_meta_info" is "false", "is_missing" will always return "undef", regardless of $column_idx being valid or not. If this attribute is "true" it will return either 0 (the field is present) or 1 (the field is missing).

A special case is the empty line. If the line is completely empty - after dealing with the flags - this is still a valid CSV line: it is a record of just one single empty field. However, if "keep_meta_info" is set, invoking "is_missing" with index 0 will now return true.

status

$status = $csv->status ();

This method returns the status of the last invoked "combine" or "parse" call. Status is success (true: 1) or failure (false: "undef" or 0).

Note that as this only keeps track of the status of above mentioned methods, you are probably looking for "error_diag" instead.

error_input

$bad_argument = $csv->error_input ();

This method returns the erroneous argument (if it exists) of "combine" or "parse", whichever was called more recently. If the last invocation was successful, "error_input" will return "undef".

Depending on the type of error, it might also hold the data for the last error-input of "getline".

error_diag

Text::CSV->error_diag ();
$csv->error_diag ();
$error_code               = 0  + $csv->error_diag ();
$error_str                = "" . $csv->error_diag ();
($cde, $str, $pos, $rec, $fld, $xs) = $csv->error_diag ();

If (and only if) an error occurred, this function returns the diagnostics of that error.

If called in void context, this will print the internal error code and the associated error message to STDERR.

If called in list context, this will return the error code and the error message in that order. If the last error was from parsing, the rest of the values returned are a best guess at the location within the line that was being parsed. Their values are 1-based. The position currently is index of the byte at which the parsing failed in the current record. It might change to be the index of the current character in a later release. The records is the index of the record parsed by the csv instance. The field number is the index of the field the parser thinks it is currently trying to parse. See examples/csv-check for how this can be used. If $xs is set, it is the line number in XS where the error was triggered (for debugging). "XS" will show in void context only when "diag_verbose" is set.

If called in scalar context, it will return the diagnostics in a single scalar, a-la $!.

FUNCIONES

Esta sección también se toma de Text::CSV_XS.

csv

Esta función no se exporta por defecto y debe solicitarse explícitamente:

use Text::CSV qw( csv );

Esta es una función de alto nivel que tiene como objetivo interfaces simples (para el usuario). Se puede usar para leer/analizar un archivo o flujo "CSV" (el comportamiento predeterminado) o para producir un archivo o escribir en un flujo (definir el atributo "out"). Devuelve una referencia a arreglo o hash al analizar (o "undef" en caso de fallo) o el valor numérico de "error_diag" al escribir. Cuando esta función falla, puede acceder al error mediante la llamada de clase a "error_diag"

my $aoa = csv (in => "test.csv") or
    die Text::CSV->error_diag;

Tenga en cuenta que un fallo aquí es la incapacidad de iniciar el analizador, como cuando la entrada no existe o los argumentos son desconocidos o conflictivos. Los errores de análisis en tiempo de ejecución devolverán una referencia válida, que puede estar vacía, pero aún contendrá todos los resultados hasta el error. Consulte "on_error".

Esta función toma los argumentos como pares clave-valor. Esto se puede pasar como una lista o como un hash anónimo:

my $aoa = csv (  in => "test.csv", sep_char => ";");
my $aoh = csv ({ in => $fh, headers => "auto" });

Los argumentos pasados consisten en dos partes: los argumentos para "csv" en sí y los atributos opcionales para el objeto "CSV" utilizado dentro de la función, tal como se enumeran y explican en "new".

Si no se anula, la opción predeterminada utilizada para CSV es

auto_diag   => 1
escape_null => 0
strict_eol  => 1

La opción que siempre se establece y no se puede alterar es

binary      => 1

Dado que esta función probablemente se utilizará en one-liners, permite que "quote" se abrevie como "quo", y "escape_char" como "esc" o "escape".

Invocaciones alternativas:

my $aoa = Text::CSV::csv (in => "file.csv");
my $csv = Text::CSV->new ();
my $aoa = $csv->csv (in => "file.csv");

En este último caso, los atributos del objeto se utilizan del objeto existente y los argumentos de atributos en la llamada a la función se ignoran:

my $csv = Text::CSV->new ({ sep_char => ";" });
my $aoh = $csv->csv (in => "file.csv", bom => 1);

analizará utilizando ";" como "sep_char", no ",".

in

Se utiliza para especificar la fuente. "in" puede ser un nombre de archivo (por ejemplo, "file.csv"), que se abrirá para lectura y se cerrará al finalizar, un manejador de archivo (por ejemplo, $fh o "FH"), una referencia a un glob (por ejemplo, "\*ARGV"), el glob en sí (por ejemplo, *STDIN), o una referencia a un escalar (por ejemplo, "\q{1,2,"csv"}").

Cuando se usa con "out", "in" debe ser una referencia a una estructura CSV (AoA o AoH) o un ref de código que devuelva una referencia de arreglo o una referencia de hash. El ref de código se invocará sin argumentos.

my $aoa = csv (in => "file.csv");
open my $fh, "<", "file.csv";
my $aoa = csv (in => $fh);
my $csv = [ [qw( Foo Bar )], [ 1, 2 ], [ 2, 3 ]];
my $err = csv (in => $csv, out => "file.csv");

Si se llama en contexto nulo sin el atributo "out", la ref resultante se utilizará como entrada para una llamada posterior a csv:

csv (in => "file.csv", filter => { 2 => sub { length > 2 }})

será un atajo para

csv (in => csv (in => "file.csv", filter => { 2 => sub { length > 2 }}))

donde, en ausencia del atributo "out", esto es un atajo para

csv (in  => csv (in => "file.csv", filter => { 2 => sub { length > 2 }}),
     out => *STDOUT)

out

csv (in => $aoa,  out => "file.csv");
csv (in => $aoa,  out => $fh);
csv (in => $aoa,  out =>   STDOUT);
csv (in => $aoa,  out =>  *STDOUT);
csv (in => $aoa,  out => \*STDOUT);
csv (in => $aoa,  out => \my $data);
csv (in => $aoa,  out =>  undef);
csv (in => $aoa,  out => \"skip");
csv (in => $fh,   out => \@aoa);
csv (in => $fh,   out => \@aoh, bom => 1);
csv (in => $fh,   out => \%hsh, key => "key");
csv (in => $file, out => $file);
csv (in => $file, out => $fh);
csv (in => $fh,   out => $file);
csv (in => $fh,   out => $fh);

En modo de salida, las opciones CSV predeterminadas al producir CSV son

eol       => "\r\n"

El atributo "fragment" se ignora en modo de salida.

"out" puede ser un nombre de archivo (por ejemplo, "file.csv"), que se abrirá para escritura y se cerrará al finalizar, un manejador de archivo (por ejemplo, $fh o "FH"), una referencia a un glob (por ejemplo, "\*STDOUT"), el glob en sí (por ejemplo, *STDOUT), o una referencia a un escalar (por ejemplo, "\my $data").

csv (in => sub { $sth->fetch },            out => "dump.csv");
csv (in => sub { $sth->fetchrow_hashref }, out => "dump.csv",
     headers => $sth->{NAME_lc});

Cuando se usa un ref de código para "in", la salida se genera por invocación, por lo que no hay almacenamiento en búfer. Esto implica que no hay restricciones de tamaño en el número de registros. La función "csv" finaliza cuando el ref de código devuelve un valor falso.

Si "out" se establece en una referencia a la cadena literal "skip", la salida se suprimirá por completo, lo que puede ser útil en combinación con un filtro solo para efectos secundarios.

my %cache;
csv (in    => "dump.csv",
     out   => \"skip",
     on_in => sub { $cache{$_[1][1]}++ });

Actualmente, establecer "out" en cualquier valor falso ("undef", "", 0) será equivalente a "\"skip"".

Si el argumento "in" apunta a algo para analizar, y el "out" se establece en una referencia a un "ARRAY" o un "HASH", la salida se agrega a los datos en la referencia existente. El resultado del análisis debe coincidir con lo que existe en la referencia pasada. Esto puede ser útil cuando tiene que analizar un conjunto de archivos con contenido similar (como datos almacenados por período) y desea recopilarlos en una sola estructura de datos:

my %hash;
csv (in => $_, out => \%hash, key => "id") for sort glob "foo-[0-9]*.csv";
my @list; # Lista de arreglos
csv (in => $_, out => \@list)              for sort glob "foo-[0-9]*.csv";
my @list; # Lista de hashes
csv (in => $_, out => \@list, bom => 1)    for sort glob "foo-[0-9]*.csv";

Streaming

Si **ambos** "in" y "out" son archivos, manejadores de archivos o globs, se fuerza el streaming inyectando una devolución de llamada "after_parse" que utiliza inmediatamente el método "say ()" de la misma instancia para generar la salida y luego rechaza el registro.

Si ya se pasó un "after_parse" como atributo, se incluirá en la llamada inyectada. Si se pasó "on_in" y no "after_parse", se utilizará este último. Si se pasaron ambos, "on_in" se ignora.

El EOL del primer registro de la fuente "in" se utiliza de forma consistente como EOL para todos los registros en el destino "out".

El atributo "filter" no está disponible.

Todos los demás atributos se comparten para "in" y "out", por lo que no puede definir diferentes codificaciones para "in" y "out". Necesita pasar un $fh, donde "bi

"nmode" se utilizó para aplicar las capas de codificación.

Tenga en cuenta que esto es un trabajo en progreso y las cosas podrían cambiar.

encoding

Si se pasa, debe ser una codificación aceptada por la opción :encoding() de "open". No hay valor predeterminado. Este atributo no funciona en perl 5.6.x. "encoding" se puede abreviar como "enc" para facilitar su uso en invocaciones de línea de comandos.

Si "encoding" se establece en el valor literal "auto", se invocará el método "header" en el flujo abierto para verificar si hay una BOM y establecer la codificación en consecuencia. Esto es igual a pasar un valor verdadero en la opción "detect_bom".

Las codificaciones se pueden apilar, como lo admite "binmode":

# Usando PerlIO::via::gzip
csv (in       => \@csv,
     out      => "test.csv:via.gz",
     encoding => ":via(gzip):encoding(utf-8)",
     );
$aoa = csv (in => "test.csv:via.gz",  encoding => ":via(gzip)");
# Usando PerlIO::gzip
csv (in       => \@csv,
     out      => "test.csv:via.gz",
     encoding => ":gzip:encoding(utf-8)",
     );
$aoa = csv (in => "test.csv:gzip.gz", encoding => ":gzip");

detect_bom

Si se proporciona "detect_bom", se invocará el método "header" en el flujo abierto para verificar si hay una BOM y establecer la codificación en consecuencia.

"detect_bom" se puede abreviar como "bom".

Esto es lo mismo que establecer "encoding" a "auto".

Tenga en cuenta que, dado que se invoca el método "header", su valor predeterminado es también establecer las cabeceras.

headers

Si no se proporciona este atributo, el comportamiento predeterminado es producir una matriz de matrices.

Si se proporciona "headers", debe ser una lista anónima de nombres de columna, un hashref anónimo, un coderef o una bandera literal: "auto", "lc", "uc", o "skip".

skip
Cuando se usa "skip", la cabecera no se incluirá en la salida. 
my $aoa = csv (in => $fh, headers => "skip");

"skip" es inválido/ignorado en combinaciones con "detect_bom".

auto
Si se usa "auto", la primera línea de la fuente "CSV" se leerá como la lista de cabeceras de campo y se utilizará para producir una matriz de hashes. 
my $aoh = csv (in => $fh, headers => "auto");
lc
Si se usa "lc", la primera línea de la fuente "CSV" se leerá como la lista de cabeceras de campo mapeadas a minúsculas y se utilizará para producir una matriz de hashes. Esta es una variación de "auto". 
my $aoh = csv (in => $fh, headers => "lc");
uc
Si se usa "uc", la primera línea de la fuente "CSV" se leerá como la lista de cabeceras de campo mapeadas a mayúsculas y se utilizará para producir una matriz de hashes. Esta es una variación de "auto". 
my $aoh = csv (in => $fh, headers => "uc");
CODE
Si se usa un coderef, la primera línea de la fuente "CSV" se leerá como la lista de cabeceras de campo modificadas en las que cada campo se pasa como el único argumento al coderef. Esta lista se utiliza para producir una matriz de hashes. 
my $aoh = csv (in      => $fh,
               headers => sub { lc ($_[0]) =~ s/kode/code/gr });

este ejemplo es una variación de usar "lc" donde todas las ocurrencias de "kode" se reemplazan por "code".

ARRAY
Si "headers" es una lista anónima, las entradas de la lista se usarán como nombres de campo. La primera línea se considera datos en lugar de cabeceras. 
my $aoh = csv (in => $fh, headers => [qw( Foo Bar )]);
csv (in => $aoa, out => $fh, headers => [qw( code description price )]);
HASH
Si "headers" es una referencia de hash, esto implica "auto", pero los campos de cabecera que existen como clave en el hashref se reemplazarán por el valor de esa clave. Dada una archivo CSV como 
post-kode,city,name,id number,fubble
1234AA,Duckstad,Donald,13,"X313DF"

usando

csv (headers => { "post-kode" => "pc", "id number" => "ID" }, ...

devolverá una entrada como

{ pc     => "1234AA",
  city   => "Duckstad",
  name   => "Donald",
  ID     => "13",
  fubble => "X313DF",
  }

Ver también "munge_column_names" y "set_column_names".

munge_column_names

"munge_column_names" se puede abreviar como "munge".

keep_headers

Al usar hashes, mantenga los nombres de las columnas en el arrayref pasado, de modo que todas las cabeceras estén disponibles después de la llamada en el orden original.

my $aoh = csv (in => "file.csv", keep_headers => \my @hdr);

Este atributo se puede abreviar como "kh" o pasar como "keep_column_names".

Este atributo implica un valor predeterminado de "auto" para el atributo "headers".

Las cabeceras también se pueden mantener internamente para mantener un orden de cabecera estable:

csv (in      => csv (in => "file.csv", kh => "internal"),
out => "new.csv", kh => "internal");

donde "internal" también puede ser 1, "yes", o "true". Esto es similar a

my @h;
csv (in      => csv (in => "file.csv", kh => \@h),
     out     => "new.csv",
     headers => \@h);

fragment

Solo emite el fragmento tal como se define en el método "fragment". Esta opción se ignora al *generar* "CSV". Ver "out".

Combinando todos ellos podría dar algo como

use Text::CSV qw( csv );
my $aoh = csv (
    in       => "test.txt",
    encoding => "utf-8",
    headers  => "auto",
    sep_char => "|",
    fragment => "row=3;6-9;15-*",
    );
say $aoh->[15]{Foo};

sep_set

Si "sep_set" está configurado, el método "header" se invoca en el flujo abierto para detectar y establecer "sep_char" con el conjunto dado.

"sep_set" puede abreviarse a "seps". Si no se proporciona ni "sep_set" ni "seps", pero se define "sep", "sep_set" por defecto es "[ sep ]". Esto solo se admite para la versión de perl 5.10 y posteriores.

Tenga en cuenta que, dado que se invoca el método "header", su valor predeterminado también es establecer las cabeceras.

set_column_names

Si se pasa "set_column_names", el método "header" se invoca en el flujo abierto con todos los argumentos destinados a "header".

Si se pasa "set_column_names" como un valor falso, el contenido de la primera fila solo se conserva si la salida es AoA:

Con un archivo de entrada como

bAr,foo
1,2
3,4,5

Esta llamada

my $aoa = csv (in => $file, set_column_names => 0);

resultará en

[[ "bar", "foo"     ],
 [ "1",   "2"       ],
 [ "3",   "4",  "5" ]]

y

my $aoa = csv (in => $file, set_column_names => 0, munge => "none");

resultará en

[[ "bAr", "foo"     ],
 [ "1",   "2"       ],
 [ "3",   "4",  "5" ]]

csv

La *función* "csv" también se puede llamar como método o con un objeto Text::CSV existente. Esto podría ayudar si la función se va a invocar muchas veces y la sobrecarga de crear el objeto internamente una y otra vez se evitaría pasando una instancia existente.

my $csv = Text::CSV->new ({ binary => 1, auto_diag => 1 });
my $aoa = $csv->csv (in => $fh);
my $aoa = csv (in => $fh, csv => $csv);

ambos actúan de la misma manera. Ejecutar esto 20000 veces en un archivo CSV de 20 líneas mostró una mejora del 53% en la velocidad.

Callbacks

Los callbacks permiten acciones desencadenadas desde el *interior* de Text::CSV.

Si bien la mayoría de lo que esto permite se puede hacer fácilmente en un bucle desplegado como se describe en el "SYNOPSIS", los callbacks pueden usarse para satisfacer demandas especiales o mejorar la función "csv".

error
$csv->callbacks (error => sub { $csv->SetDiag (0) });

el callback "error" se invoca cuando ocurre un error, pero *solo* cuando "auto_diag" se establece en un valor verdadero. Un callback se invoca con los valores devueltos por "error_diag":

my ($c, $s);
sub ignore3006 {
    my ($err, $msg, $pos, $recno, $fldno) = @_;
    if ($err == 3006) {
        # ignorar este error
        ($c, $s) = (undef, undef);
        Text::CSV->SetDiag (0);
        }
    # Cualquier otro error
    return;
    } # ignore3006
$csv->callbacks (error => \&ignore3006);
$csv->bind_columns (\$c, \$s);
while ($csv->getline ($fh)) {
    # El error 3006 no detendrá el bucle
    }
after_parse
$csv->callbacks (after_parse => sub { push @{$_[1]}, "NEW" });
while (my $row = $csv->getline ($fh)) {
    $row->[-1] eq "NEW";
    }

Este callback se invoca después de analizar con "getline" solo si no ocurrió ningún error. El callback se invoca con dos argumentos: el objeto de análisis "CSV" actual y una referencia de arreglo a los campos analizados.

El código de retorno del callback se ignora a menos que sea una referencia a la cadena "skip", en cuyo caso el registro se omitirá en "getline_all".

sub add_from_db {
    my ($csv, $row) = @_;
    $sth->execute ($row->[4]);
    push @$row, $sth->fetchrow_array;
    } # add_from_db
my $aoa = csv (in => "file.csv", callbacks => {
    after_parse => \&add_from_db });

Este gancho se puede usar para validación:

FAIL
Morir si alguno de los registros no valida una regla: 
after_parse => sub {
    $_[1][4] =~ m/^[0-9]{4}\s?[A-Z]{2}$/ or
        die "El quinto campo no tiene un código postal holandés válido";
    }
DEFAULT
Reemplazar campos inválidos con un valor predeterminado: 
after_parse => sub { $_[1][2] =~ m/^\d+$/ or $_[1][2] = 0 }
SKIP
Omitir registros que tienen campos inválidos (solo se aplica a "getline_all"): 
after_parse => sub { $_[1][0] =~ m/^\d+$/ or return "skip"; }
before_print
my $idx = 1;
$csv->callbacks (before_print => sub { $_[1][0] = $idx++ });
$csv->print (*STDOUT, [ 0, $_ ]) for @members;

Este callback se invoca antes de imprimir con "print" solo si no ocurrió ningún error. El callback se invoca con dos argumentos: el objeto de análisis "CSV" actual y una referencia de arreglo a los campos pasados.

El código de retorno del callback se ignora.

sub max_4_fields {
    my ($csv, $row) = @_;
    @$row > 4 and splice @$row, 4;
    } # max_4_fields
csv (in => csv (in => "file.csv"), out => *STDOUT,
    callbacks => { before_print => \&max_4_fields });

Este callback no está activo para "combine".

Callbacks para csv ()

El método "csv" permite algunos callbacks que no se integran en las internas de XS, sino que solo presentan la función "csv".

csv (in        => "file.csv",
     callbacks => {
         filter       => { 6 => sub { $_ > 15 } },    # primero
         after_parse  => sub { say "DESPUÉS DE ANALIZAR";  }, # primero
         after_in     => sub { say "DESPUÉS DE ENTRADA";     }, # segundo
         on_in        => sub { say "EN ENTRADA";        }, # tercero
         },
     );
csv (in        => $aoh,
     out       => "file.csv",
     callbacks => {
         on_in        => sub { say "EN ENTRADA";        }, # primero
         before_out   => sub { say "ANTES DE SALIDA";   }, # segundo
         before_print => sub { say "ANTES DE IMPRIMIR"; }, # tercero
         },
     );
filter
Este callback se puede usar para filtrar registros. Se llama justo después de que se ha escaneado un nuevo registro. El callback acepta un:
hashref
Las claves son el índice de la fila (el nombre del campo o el número de campo, basado en 1) y los valores son subrutinas para devolver un valor verdadero o falso. 
csv (in => "file.csv", filter => {
           3 => sub { m/a/ },       # el tercer campo debe contener una "a"
           5 => sub { length > 4 }, # la longitud del 5º campo es mínima 5
           });
csv (in => "file.csv", filter => { foo => sub { $_ > 4 }});

Si las claves del hash del filtro contienen algún carácter que no sea un dígito, también establecerá implícitamente "headers" a "auto" a menos que "headers" ya se haya pasado como argumento. Cuando las cabeceras están activas, al devolver un arreglo de hashes, el filtro no es aplicable a la cabecera en sí.

Todos los resultados de las subrutinas deben coincidir, como en un AND.

El contexto del callback establece $_ localizado al campo indicado por el filtro. Los dos argumentos son como en todos los demás callbacks, por lo que se pueden ver los otros campos de la fila actual:

filter => { 3 => sub { $_ > 100 ? $_[1][1] =~ m/A/ : $_[1][6] =~ m/B/ }}

Si el contexto se establece para devolver una lista de hashes ("headers" está definido), el registro actual también estará disponible en el %_ localizado:

filter => { 3 => sub { $_ > 100 && $_{foo} =~ m/A/ && $_{bar} < 1000  }}

Si el filtro se usa para *alterar* el contenido cambiando $_, asegúrese de que la subrutina devuelva verdadero para no omitir ese registro:

filter => { 2 => sub { $_ = uc }}

convertirá el segundo campo a mayúsculas y luego lo omitirá si el contenido resultante se evalúa como falso. Para aceptar siempre, termine con un valor verdadero:

filter => { 2 => sub { $_ = uc; 1 }}
coderef
csv (in => "file.csv", filter => sub { $n++; 0; });

Si el argumento de "filter" es una referencia de código, es un alias o atajo para un filtro en la columna 0:

csv (filter => sub { $n++; 0 });

es igual a

csv (filter => { 0 => sub { $n++; 0 });
filter-name
csv (in => "file.csv", filter => "not_blank");
csv (in => "file.csv", filter => "not_empty");
csv (in => "file.csv", filter => "filled");

Estos son programas predefinidos para filtrar registros, para ejemplo, para omitir filas vacías.

after_in
Este callback se invoca después de que el contenido del archivo de entrada se haya procesado completamente. Recibe el objeto CSV y el resultado de la entrada (por ejemplo, un arreglo de arreglos).
on_in
Este callback se invoca después de que el archivo de entrada se haya analizado, pero antes de procesar las líneas. Recibe el objeto CSV y el conjunto de líneas de entrada.
before_out
Este callback se invoca después de que todos los registros se hayan procesado y se hayan preparado para la salida, pero antes de que se escriba el primer registro en el archivo de salida. Recibe el objeto CSV y los datos que se escribirán.
before_print
Este callback se invoca justo antes de que se imprima cada registro (en la salida o en un archivo). Recibe el objeto CSV y una referencia al registro que se está imprimiendo.

Filtros redefinidos

Dado un archivo como (los números de línea se anteponen solo para fines documentales):

1:1,2,3
2:
3:,
4:""
5:,,
6:, ,
7:"",
8:" "
9:4,5,6
not_blank
Filtra las líneas en blanco.

Este filtro es un atajo para

filter => { 0 => sub { @{$_[1]} > 1 or
        defined $_[1][0] && $_[1][0] ne "" } }

Debido a la implementación, actualmente es imposible filtrar también las líneas que consisten solo en un campo entre comillas vacío. Estas líneas también se consideran líneas en blanco.

Con el ejemplo dado, las líneas 2 y 4 se omitirán.

not_empty
Filtra las líneas donde todos los campos están vacíos.

Este filtro es un atajo para

filter => { 0 => sub { grep { defined && $_ ne "" } @{$_[1]} } }

Un espacio no se considera vacío, por lo que, dados los datos del ejemplo, se omiten las líneas 2, 3, 4, 5 y 7.

filled
Filtra las líneas que no tienen datos visibles.

Este filtro es un atajo para

filter => { 0 => sub { grep { defined && m/\S/ } @{$_[1]} } }

Este filtro rechaza todas las líneas que *no* tienen al menos un campo que no se evalúe como una cadena vacía.

Con los datos del ejemplo proporcionado, este filtro omitiría las líneas 2 a 8.

También se podrían usar módulos como Types::Standard:

use Types::Standard -types;
my $type   = Tuple[Str, Str, Int, Bool, Optional[Num]];
my $check  = $type->compiled_check;
# filter with compiled check and warnings
my $aoa = csv (
   in     => \$data,
   filter => {
       0 => sub {
           my $ok = $check->($_[1]) or
               warn $type->get_message ($_[1]), "\n";
           return $ok;
           },
       },
   );
after_in
Esta devolución de llamada se invoca para cada registro después de que todos los registros han sido analizados, pero antes de devolver la referencia al llamador. El gancho se invoca con dos argumentos: el objeto "CSV" actual y una referencia al registro. La referencia puede ser una referencia a un HASH o una referencia a un ARRAY, según lo determinen los argumentos.

Esta devolución de llamada también se puede pasar como un atributo sin el envoltorio "callbacks".

before_out
Esta devolución de llamada se invoca para cada registro antes de que se imprima. El gancho se invoca con dos argumentos: el objeto "CSV" actual y una referencia al registro. La referencia puede ser una referencia a un HASH o una referencia a un ARRAY, según lo determinen los argumentos.

Esta devolución de llamada también se puede pasar como un atributo sin el envoltorio "callbacks".

Este gancho hace que la fila esté disponible en %_ si la fila es un hashref. En este caso, %_ es escribible y cambiará la fila original.

on_in
Esta devolución de llamada actúa exactamente como los ganchos "after_in" o "before_out".

Esta devolución de llamada también se puede pasar como un atributo sin el envoltorio "callbacks".

Este gancho hace que la fila esté disponible en %_ si la fila es un hashref. En este caso, %_ es escribible y cambiará la fila original. Así, por ejemplo, con

my $aoh = csv (
    in      => "foo\n1\n2\n",
    headers => "auto",
    on_in   => sub { $_{bar} = 2; },
    );

$aoh será:

[ { foo => 1,
    bar => 2,
    }
  { foo => 2,
    bar => 2,
    }
  ]
on_error
Esta devolución de llamada actúa exactamente como el gancho "error". 
my @err;
my $aoa = csv (in => $fh, on_error => sub { @err = @_ });

es idéntico a

my $aoa = csv (in => $fh, callbacks => {
    error => sub { @err = @_ },
    });

Se puede utilizar para ignorar errores, así como para conservar el error en caso de análisis después de que la función "csv ()" haya retornado.

my @err;
my $aoa = csv (in => "bad.csv, on_error => sub { @err = @_ });
die Text::CSV->error_diag if @err or !$aoa;

Todavía en construcción...

Si ocurre un error, "$csv->error_diag" se puede usar para obtener información sobre la causa de la falla. Tenga en cuenta que por razones de velocidad, el valor interno nunca se borra en caso de éxito, por lo que el uso del valor devuelto por "error_diag" en casos normales - cuando no ocurrió ningún error - puede causar resultados inesperados.

NAME

Text::CSV - Comma-Separated Values parser

SYNOPSIS

use Text::CSV;

# create a CSV object
my $csv = Text::CSV->new ({ sep_char => ',', eol => "\n" });

# parse a string
my $rows = $csv->parse_fh($fh); # or $csv->parse($string)

# or process row by row
my $row;
while ($row = $csv->getline($fh)) {
  # $row is an arrayref
  print join("-", @$row), "\n";
}

# or get the flags for the last row
my $flags = $csv->fields();

# and the error code and message
my ($err, $msg) = $csv->error_diag();

# print a string
$csv->print($fh, $row);

DESCRIPTION

This module implements RFC 4180, RFC 2045, RFC 2046, RFC 2047, RFC 2048, RFC 2049, RFC 5987, RFC 7111 and RFC 7303.

CSV is a very common format for storing tabular data, but it lacks a formal specification. This module tries to implement the most common conventions.

The main interface is object-oriented. You create a CSV object and then use its methods to parse or print CSV data.

The module can be used in two modes: strict and loose.

  • 'strict' mode: The parser adheres strictly to the CSV specification. Deviations from the spec result in errors.
  • 'loose' mode: The parser is more lenient and tries to guess the intention of the author of the CSV file. This can lead to unexpected behaviour.

The default behaviour is strict mode.

You can switch between modes by passing arguments to the new method:

my $csv = Text::CSV->new ({ strict_parsing => 0 }); # loose mode
my $csv = Text::CSV->new ({ strict_parsing => 1 }); # strict mode (default)

CHOOSING BACKEND

Text::CSV provides a pure-Perl backend (Text::CSV_PP) and a C backend (Text::CSV_XS). By default, it tries to use the C backend for performance reasons.

If you want to force the use of the pure-Perl backend, you can set the environment variable TEXT_CSV_PP to a true value before loading the module:

export TEXT_CSV_PP=1
perl your_script.pl

Or, within your script:

use Text::CSV_PP; # Forces the pure-Perl backend

Or, use the use_pp method:

use Text::CSV;
Text::CSV->use_pp();
