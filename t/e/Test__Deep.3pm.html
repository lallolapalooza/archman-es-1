Test::Deep(3) Documentación de Perl contribuida por el usuario Test::Deep(3)

NOMBRE

Test::Deep - Comparación profunda extremadamente flexible

VERSIÓN

versión 1.205

SINÓPSIS

use Test::More tests => $Num_Tests;
use Test::Deep;
cmp_deeply(
  $estructura_anidada_horrible_actual,
  $estructura_anidada_horrible_esperada,
  "obtuve la estructura de datos anidada horrible correcta"
);
cmp_deeply(
  $objeto,
  methods(name => "John", phone => "55378008"),
  "métodos del objeto ok"
);
cmp_deeply(
  \@array,
  [$hash1, $hash2, ignore()],
  "los 2 primeros elementos son los esperados, ignorando el tercero"
);
cmp_deeply(
  $objeto,
  noclass({value => 5}),
  "el objeto se ve bien, no verificando su clase"
);
cmp_deeply(
  \@result,
  bag('a', 'b', {key => [1, 2]}),
  "el array tiene las 3 cosas que queríamos en algún orden"
);

DESCRIPCIÓN

Si no sabes nada sobre pruebas automatizadas en Perl, deberías leer sobre Test::Simple y Test::More antes de continuar. Test::Deep utiliza el framework Test::Builder.

Test::Deep te proporciona formas muy flexibles de verificar que el resultado que obtuviste es el resultado que esperabas. En su nivel más sencillo, compara dos estructuras recorriendo cada nivel, asegurando que los valores coinciden, que los arrays y hashes tienen los mismos elementos y que las referencias están bendecidas en la clase correcta. También maneja estructuras de datos circulares sin caer en un bucle infinito.

Donde se vuelve más interesante es al permitirte hacer algo más que simples comparaciones exactas. Con cadenas de texto, el operador "eq" comprueba que 2 cadenas son exactamente iguales, pero a veces eso no es lo que quieres. Cuando no sabes exactamente cuál será la cadena, pero sí sabes algunas cosas sobre cómo debería verse, "eq" no sirve y debes usar en su lugar coincidencia de patrones. Test::Deep proporciona coincidencia de patrones para estructuras de datos complejas.

Test::Deep tiene **muchas** exportaciones. Consulta "EXPORTS" abajo.

VERSIÓN DE PERL

Esta biblioteca debería funcionar en perls lanzados incluso hace mucho tiempo. Debería funcionar en cualquier versión de perl lanzada en los últimos cinco años.

EJEMPLOS

Cómo funciona Test::Deep es mucho más fácil de entender viendo algunos ejemplos.

Sin Test::Deep

Supongamos que quieres probar una función que devuelve una cadena. Sabes que tu cadena debe ser un número de 7 dígitos que comienza con 0. "eq" no sirve en esta situación, necesitas una expresión regular. Así que podrías usar la función like() de Test::More:

like($string, qr/^0[0-9]{6}$/, "el número se ve bien");

De manera similar, para verificar que una cadena parece un nombre, podrías hacer:

like($string, qr/^(Mr|Mrs|Miss) \w+ \w+$/,
  "título, nombre y apellido obtenidos");

Ahora imagina que tu función produce un hash con algunos detalles personales. Quieres asegurarte de que hay 2 claves, Nombre y Teléfono, y que el nombre parece un nombre y el número de teléfono parece un número de teléfono. Podrías hacer:

$hash = make_person();
like($hash->{Name}, qr/^(Mr|Mrs|Miss) \w+ \w+$/, "nombre ok");
like($hash->{Phone}, qr/^0[0-9]{6}$/, "teléfono ok");
is(scalar keys %$hash, 2, "número correcto de claves");

Pero eso no está del todo bien, ¿y si make_person tiene un problema grave y ni siquiera devuelve un hash? Realmente necesitamos escribir

if (ref($hash) eq "HASH")
{
  like($hash->{Name}, qr/^(Mr|Mrs|Miss) \w+ \w+$/, "nombre ok");
  like($hash->{Phone}, qr/^0[0-9]{6}$/, "teléfono ok");
  is(scalar keys %$hash, 2, "número correcto de claves");
}
else
{
  fail("persona no es un hash");
  fail("persona no es un hash");
  fail("persona no es un hash"); # se necesitan 3 para mantener el plan correcto
}

Esto ya se está volviendo complicado, ahora imagina otra entrada en el hash, un array de nombres de hijos. Esto requeriría

if (ref($hash) eq "HASH")
{
  like($hash->{Name}, $name_pat, "nombre ok");
  like($hash->{Phone}, '/^0d{6}$/', "teléfono ok");
  my $cn = $hash->{ChildNames};
  if (ref($cn) eq "ARRAY")
  {
    foreach my $child (@$cn)
    {
      like($child, $name_pat);
    }
  }
  else
  {
      fail("nombres de hijos no es un array")
  }
}
else
{
  fail("persona no es un hash");
}

Este es un lío horrible y como no sabemos de antemano cuántos nombres de hijos habrá, ya no podemos hacer un plan para nuestra prueba (en realidad, podríamos, pero haría las cosas aún más complicadas).

Test::Deep al rescate.

Con Test::Deep

my $name_re = re('^(Mr|Mrs|Miss) \w+ \w+$');
cmp_deeply(
  $person,
  {
    Name => $name_re,
    Phone => re('^0d{6}$'),
    ChildNames => array_each($name_re)
  },
  "persona ok"
);

Esto hará todo lo que hace el código complicado anterior y dará un mensaje sensato que te dirá exactamente qué salió mal si encuentra una parte de $person que no coincide con el patrón. re() y array_each() son funciones especiales importadas de Test::Deep. Crean un marcador que le dice a Test::Deep que algo diferente está sucediendo aquí. En lugar de solo hacer una comparación simple y verificar si dos cosas son exactamente iguales, debería hacer algo más.

Si una persona le pidiera que verificara que 2 estructuras son iguales, podría imprimirlas ambas y compararlas línea por línea. Los marcadores anteriores son similares a escribir una nota en rojo en una de las impresiones, diciéndole a la persona que para esta parte de la estructura, debería dejar de hacer una comparación simple línea por línea y hacer otra cosa.

re($regex) significa que Test::Deep debe verificar que la parte actual de los datos coincide con la regex en $regex. array_each($struct) significa que Test::Deep debe esperar que la parte actual de los datos sea un array y debe verificar que cada elemento de ese array coincida con $struct. En este caso, cada elemento de "$person->{ChildNames}" debería verse como un nombre. Si, por ejemplo, el tercero no lo hiciera, obtendrías un mensaje de error como

Using Regexp on $data->{ChildNames}[3]
   got    : 'Queen John Paul Sartre'
   expect : /^(Mr|Mrs|Miss) \w+ \w+$/

Hay muchas otras comparaciones especiales disponibles, consulta "COMPARACIONES ESPECIALES PROVISTAS" abajo para la lista completa.

Reutilización de estructuras

Test::Deep es bueno para reutilizar estructuras de prueba, así que puedes hacer esto

my $name_re = re('^(Mr|Mrs|Miss) \w+ \w+$');
my $person_cmp = {
  Name => $name_re,
  Phone => re('^0d{6}$'),
  ChildNames => array_each($name_re)
};
cmp_deeply($person1, $person_cmp, "persona ok");
cmp_deeply($person2, $person_cmp, "persona ok");
cmp_deeply($person3, $person_cmp, "persona ok");

Incluso puedes poner $person_cmp en un módulo y dejar que otras personas lo usen al escribir scripts de prueba para módulos que usan tus módulos.

Para hacer las cosas un poco más difíciles, cambiemos la estructura de datos de la persona para que en lugar de una lista de nombres de hijos, contenga una lista de hashes, uno por cada hijo. Así que, de hecho, nuestra estructura de persona contendrá otras estructuras de persona que pueden contener otras estructuras de persona y así sucesivamente. Esto es fácil de manejar con Test::Deep porque las estructuras de Test::Deep pueden incluirse a sí mismas. Simplemente haz

my $name_re = re('^(Mr|Mrs|Miss) \w+ \w+$');
my $person_cmp = {
  Name => $name_re,
  Phone => re('^0d{6}$'),
  # nota, no se menciona Children aquí
};
$person_cmp->{Children} = array_each($person_cmp);
cmp_deeply($person, $person_cmp, "persona ok");

Esto verificará que $person->{Children} sea un array y que cada elemento de ese array también

o coincide $person_cmp, esto incluye verificar que sus hijos también coincidan con el mismo patrón y así sucesivamente.

Estructuras de datos circulares

Una estructura de datos circular es aquella que se repite sobre sí misma, puedes crear una fácilmente haciendo

my @b;
my @a = (1, 2, 3, \@b);
push(@b, \@a);

ahora @a contiene una referencia a @b y @b contiene una referencia a @a. Esto causa problemas si tienes un programa que quiere mirar dentro de @a y seguir mirando cada vez más profundo en cada nivel, podría quedar atrapado en un bucle infinito mirando en @a luego @b luego @a luego @b y así sucesivamente.

Test::Deep evita este problema, por lo que podemos extender nuestro ejemplo diciendo que una persona también debe enumerar a sus padres.

my $name_re = re('^(Sr|Sra|Srta) \w+ \w+$');
my $person_cmp = {
  Name => $name_re,
  Phone => re('^0d{6}$'),
  # nota, no se menciona Children aquí
};
$person_cmp->{Children} = each_array($person_cmp);
$person_cmp->{Parents} = each_array($person_cmp);
cmp_deeply($person, $person_cmp, "persona ok");

Así que esto verificará que por cada hijo $child en "$person->{Children}" que los "$child->{Parents}" coincidan con $person_cmp, sin embargo, es lo suficientemente inteligente como para no quedar atrapado en un bucle infinito donde sigue rebotando entre el mismo Padre e Hijo.

TERMINOLOGÍA

"cmp_deeply($got, $expected, $name)" toma 3 argumentos. $got es la estructura que estás verificando, no debes incluir ninguna comparación especial en esta estructura o obtendrás un error fatal. $expected describe lo que Test::Deep buscará en $got. Puedes incluir comparaciones especiales en $expected si lo deseas.

A medida que Test::Deep desciende a través de las 2 estructuras, las compara una pieza a la vez, por lo que en cualquier momento del proceso, Test::Deep está pensando en 2 cosas: el valor actual de $got y el valor actual de $expected. En la documentación, los llamo $got_v y "exp_v" respectivamente.

FUNCIONES DE COMPARACIÓN

cmp_deeply

my $ok = cmp_deeply($got, $expected, $name)

$got es el resultado a verificar. $expected es la estructura contra la cual $got será verificado. $name es el nombre de la prueba.

Esta es la función de comparación principal, las otras son solo envoltorios alrededor de esta. $got y $expected se comparan recursivamente. Cada valor en $expected define lo que se espera en la ubicación correspondiente en $got. Los escalares simples se comparan con "eq". Las referencias a estructuras como hashes y arrays se comparan recursivamente.

Sin embargo, los elementos en $expected también pueden representar pruebas complejas que verifican números en un rango dado, hashes con al menos un cierto conjunto de claves, una cadena que coincide con una expresión regular, o muchas otras cosas.

Ver "QUÉ SON LAS COMPARACIONES ESPECIALES" para más detalles.

cmp_bag

my $ok = cmp_bag(\@got, \@bag, $name)

Es una abreviatura de cmp_deeply(\@got, bag(@bag), $name)

n.b.: Ambos argumentos deben ser referencias a arrays. Si no lo son, se lanzará una excepción.

cmp_set

my $ok = cmp_set(\@got, \@set, $name)

Es una abreviatura de cmp_deeply(\@got, set(@set), $name)

cmp_methods

my $ok = cmp_methods(\@got, \@methods, $name)

Es una abreviatura de cmp_deeply(\@got, methods(@methods), $name)

eq_deeply

my $ok = eq_deeply($got, $expected)

Es lo mismo que cmp_deeply() excepto que solo devuelve verdadero o falso. No crea diagnósticos ni se comunica con Test::Builder, pero si quieres usarlo en un entorno que no sea de pruebas, deberías importarlo a través de Test::Deep::NoTest. Por ejemplo

use Test::Deep::NoTest;
print "a equals b" unless eq_deeply($a, $b);

de lo contrario, el framework de Test::Builder se cargará y se mostrarán mensajes de prueba al finalizar tu programa.

cmp_details

($ok, $stack) = cmp_details($got, $expected)

Esto se comporta de manera muy similar a eq_deeply, pero además te permite producir diagnósticos en caso de fallo pasando el valor en $stack a "deep_diag".

No hagas suposiciones sobre la estructura o el contenido de $stack y no lo uses si $ok contiene un valor verdadero.

Ver "USANDO TEST::DEEP CON TEST::BUILDER" para ejemplos de uso.

COMPARACIONES ESPECIALES PROPORCIONADAS

En la siguiente documentación, $got_v se utiliza para indicar cualquier valor dado dentro de la estructura $got.

ignore

cmp_deeply( $got, ignore() );

Esto hace que Test::Deep omita las pruebas en $got_v. No importa cuál sea el valor de $got_v, Test::Deep lo considerará correcto. Esto es útil si alguna parte de la estructura que estás probando es muy complicada y ya está probada en otro lugar, o si es impredecible.

cmp_deeply(
  $got,
  {
    name    => 'John',
    random  => ignore(),
    address => [ '5 A street', 'a town', 'a country' ],
  }
);

es el equivalente a verificar que

$got->{name} eq 'John';
exists $got->{random};
cmp_deeply($got->{address}, ['5 A street', 'a town', 'a country']);

methods

cmp_deeply( $got, methods(%hash) );

%hash es un hash de pares llamada de método => valor esperado.

Esto te permite llamar a métodos en un objeto y verificar el resultado de cada llamada. Los métodos se llamarán en el orden en que se suministran. Si deseas pasar argumentos al método, debes envolver el nombre del método y los argumentos en una referencia a un array.

cmp_deeply(
  $obj,
  methods(name => "John", ["favourite", "food"] => "taco")
);

es aproximadamente el equivalente a verificar que

$obj->name eq "John"
$obj->favourite("food") eq "taco"

Los métodos se llamarán en el orden que los proporciones y se llamarán en contexto escalar. Si necesitas probar métodos llamados en contexto de lista, deberías usar listmethods().

NOTA Al igual que en un script de prueba normal, debes tener cuidado si los métodos que llamas tienen efectos secundarios como cambiar el objeto u otros objetos en la estructura. Aunque el orden de los métodos es fijo, el orden de algunas otras pruebas no lo es, por lo que si $expected es

{
  manager => methods(@manager_methods),
  coder => methods(@coder_methods)
}

no hay forma de saber cuál de manager y coder se probará primero. Si los métodos que estás probando dependen y alteran variables globales o si manager y coder son el mismo objeto, podrías tener problemas.

listmethods

cmp_deeply( $got, listmethods(%hash) );

%hash es un hash de pares que mapean nombres de métodos a valores de retorno esperados.

Esto es casi idéntico a methods() excepto que los métodos se llaman en contexto de lista en lugar de contexto escalar. Esto significa que los valores de retorno esperados suministrados deben estar en referencias de array.

cmp_deeply(
  $obj,
  listmethods(
    name => [ "John" ],
    ["favourites", "food"] => ["Mapo tofu", "Gongbao chicken"]
  )
);

es el equivalente a verificar que

cmp_deeply([$obj->name], ["John"]);
cmp_deeply([$obj->favourites("food")], ["Mapo tofu", "Gongbao chicken"]);

Los métodos se llamarán en el orden en que los proporciones.

NOTA Se aplican las mismas advertencias que para methods().

shallow

cmp_deeply( $got, shallow($thing) );

$thing es una referencia.

Esto evita que Test::Deep mire dentro de $thing. Te permite verificar que $got_v y $thing son referencias a la misma variable. Así

my @a = @b = (1, 2, 3);
cmp_deeply(\@a, \@b);

pasará porque @a y @b tienen los mismos elementos sin embargo

cmp_deeply(\@a, shallow(\@b))

fallará porque aunque "\@a" y "\@b" contienen ambos "1, 2, 3", son referencias a arrays diferentes.

noclass

cmp_deeply( $got, noclass($thing) );

$thing es una estructura a comparar contra.

Esto hace que Test::Deep ignore la clase de los objetos, por lo que solo mira los datos que contienen. La verificación de clases se desactivará hasta que Test::Deep termine de comparar $got_v con $thing. Una vez que Test::Deep salga de $thing, volverá a su configuración anterior para verificar la clase.

Esto puede ser útil cuando quieres verificar que los objetos se han construido correctamente pero no quieres escribir muchos "bless". Si @people es un array de objetos Person entonces

cmp_deeply(\@people, [
  bless {name => 'John', phone => '555-5555'}, "Person",
  bless {name => 'Anne', phone => '444-4444'}, "Person",
]);

puede ser reemplazado con

cmp_deeply(\@people, noclass([
  {name => 'John', phone => '555-5555'},
  {name => 'Anne', phone => '444-4444'}
]));

Sin embargo, esto es una prueba, por lo que también deberías verificar que los objetos están blessed correctamente. Podrías usar un mapa para bendecir todos esos hashes o podrías hacer una segunda prueba como

cmp_deeply(\@people, array_each(isa("Person")));

useclass

cmp_deeply( $got, useclass($thing) );

Esto vuelve a activar la comparación de clases dentro de un noclass().

cmp_deeply(
  $got,
  noclass(
    [
      useclass( $object )
    ]
  )
)

En este ejemplo, se ignora la clase de la referencia de matriz en $got, pero se verifica la clase de $object, así como la clase de todo lo que hay dentro de $object.

re

cmp_deeply( $got, re($regexp, $capture_data, $flags) );

$regexp es una referencia a una expresión regular producida con "qr/.../" o una cadena que se utilizará para construir una expresión regular.

$capture_data es opcional y se utiliza para verificar las cadenas capturadas por una expresión regular. Esto puede ser una referencia de matriz o un comparador Test::Deep que funcione con referencias de matriz.

$flags es una cadena opcional que controla si la expresión regular se ejecuta como una coincidencia global. Si $flags es "g", la expresión regular se ejecutará como "m/$regexp/g".

Sin $capture_data, esto simplemente compara $got_v con la expresión regular proporcionada. Por lo tanto,

cmp_deeply($got, [ re("ferg") ])

es el equivalente de

$got->[0] =~ /ferg/

Con $capture_data,

cmp_deeply($got, [re($regex, $capture_data)])

es el equivalente de

my @data = $got->[0] =~ /$regex/;
cmp_deeply(\@data, $capture_data);

Así que puedes hacer algo simple como

cmp_deeply($got, re(qr/(\d\d)(\w\w)/, [25, "ab" ]))

para verificar que "(\d\d)" fue 25 y "(\w\w)" fue "ab", pero también puedes usar objetos Test::Deep para pruebas más complejas de los valores capturados.

cmp_deeply(
  "cat=2,dog=67,sheep=3,goat=2,dog=5",
  re(
    qr/(\D+)=\d+,?/,
    set(qw( cat sheep dog )),
    "g"
  ),
);

aquí, la expresión regular coincidirá con la cadena y capturará los nombres de los animales y verificará que coinciden con el conjunto especificado; en este caso, fallará, quejándose de que "goat" no está en el conjunto.

all

cmp_deeply( $got, all(@expecteds) );

@expecteds es una matriz de estructuras esperadas.

Esto te permite comparar datos con múltiples resultados esperados y asegurarte de que cada uno de ellos coincide.

cmp_deeply($got, all(isa("Person"), methods(name => 'John')))

es equivalente a

$got->isa("Person")
$got->name eq 'John'

Si alguna de las pruebas falla, todo se considera un fallo. Esta es una prueba de cortocircuito, las pruebas se detienen después del primer fallo, aunque en el futuro podría completar todas las pruebas para que se puedan mostrar los diagnósticos de todos los fallos. Al informar de un fallo, las partes se cuentan a partir de 1.

Gracias a la magia de la sobrecarga, puedes escribir

any( re("^wi"), all(isa("Person"), methods(name => 'John')) )

como

re("^wi") | isa("Person") & methods(name => 'John')

Ten en cuenta que es un único "|" y no un doble, ya que "||" no se puede sobrecargar. Esto solo funcionará cuando haya una comparación especial involucrada. Si escribes

"john" | "anne" | "robert"

Perl lo convertirá en

"{onort"

que presumiblemente no es lo que querías. Esto se debe a que perl los combina como cadenas antes de que Test::Deep tenga la oportunidad de realizar trucos de sobrecarga.

any

cmp_deeply( $got, any(@expecteds) );

@expecteds es una matriz de estructuras esperadas.

Esto se puede utilizar para comparar datos con múltiples resultados esperados y asegurarse de que al menos uno de ellos coincide. Esta es una prueba de cortocircuito, por lo que si una prueba tiene éxito, ninguna de las pruebas posteriores se intentará.

También puedes usar la sobrecarga con "|" de manera similar a all().

Isa

cmp_deeply( $got, Isa($class) );

isa

cmp_deeply( $got, isa($class) );

$class es un nombre de clase.

Esto utiliza UNIVERSAL::isa() para verificar que $got_v está bendecido en la clase $class.

NOTA: Isa() hace exactamente lo que se documenta aquí, pero isa() es ligeramente diferente. Si isa() se llama con 1 argumento, pasa a Isa(). Si isa() se llama con 2 argumentos, pasa a "UNIVERSAL::isa". Esto es para evitar roturas cuando importas isa() a un paquete que se utiliza como clase. Sin esto, cualquiera que llame a "Class->isa($other_class)" obtendría la respuesta incorrecta. Esto es un truco para solucionar el hecho de que "isa" se exporta por defecto.

obj_isa

cmp_deeply( $got, obj_isa($class) );

Esta prueba solo acepta objetos que son instancias de $class o una subclase. A diferencia de la prueba "Isa", esta prueba nunca aceptará nombres de clase.

array_each

cmp_deeply( \@got, array_each($thing) );

$thing es una estructura que se compara.

<$got_v> debe ser una referencia de matriz. Cada elemento de ella se comparará con $thing. Esto es útil cuando tienes una matriz de elementos similares, por ejemplo, objetos de un tipo conocido y no quieres tener que repetir la misma prueba para cada uno.

my $common_tests = all(
   isa("MyFile"),
   methods(
     handle => isa("IO::Handle")
     filename => re("^/home/ted/tmp"),
  )
);
cmp_deeply($got, array_each($common_tests));

es similar a

foreach my $got_v (@$got) {
  cmp_deeply($got_v, $common_tests)
}

Excepto que no explotará si $got no es una referencia de matriz. Verificará que cada uno de los objetos en @$got sea un MyFile y que cada uno devuelva los resultados correctos para sus métodos.

Podrías ir más allá, si por ejemplo hubiera 3 archivos y conocieras el tamaño de cada uno podrías hacer esto.

cmp_deeply(
  $got,
  all(
    array_each($common_tests),
    [
      methods(size => 1000),
      methods(size => 200),
      methods(size => 20)
    ]
  )
)
cmp_deeply($got, array_each($structure));

hash_each

cmp_deeply( \%got, hash_each($thing) );

Esta prueba se comporta como "array_each" (ver arriba) pero prueba que cada valor del hash pasa sus pruebas.

str

cmp_deeply( $got, str($string) );

$string es una cadena.

Esto convertirá a cadena $got_v y lo comparará con $string usando "eq", incluso si $got_v es una referencia. Es útil para verificar el valor stringificado de una referencia sobrecargada.

num

cmp_deeply( $got, num($number, $tolerance) );

$number es un número.

$tolerance es un número opcional.

Esto agregará 0 a $got_v y verificará si es numéricamente igual a $number, incluso si $got_v es una referencia. Es útil para verificar el valor numérico de una referencia sobrecargada. Si se proporciona $tolerance, esto verificará que $got_v y $exp_v estén separados por menos de $tolerance. Esto es útil al comparar números de punto flotante, ya que los errores de redondeo pueden hacer que sea difícil o imposible que $got_v sea exactamente igual a $exp_v. Cuando se proporciona $tolerance, la prueba pasa si "abs($got_v - $exp_v) <= $tolerance".

Nota en Perl, ""12blah" == 12" porque Perl será inteligente y convertirá "12blah" en 12. Puede que no quieras esto. Había un modo estricto pero ahora ha desaparecido. Pronto lo reemplazará una prueba de "parece un número". Hasta entonces, generalmente puedes usar la comparación de string() para ser más estricto. Esto funcionará bien para casi todas las situaciones, sin embargo, no funcionará cuando <$got_v> sea un valor sobrecargado cuyo valor de cadena y numérico difieran.

bool, true, false

cmp_deeply( $got, bool($value) );
cmp_deeply( $got, true );
cmp_deeply( $got, false );

$value es cualquier cosa que te guste, pero es mejor usar 0 o 1.

Esto verificará que $got_v y $value tengan el mismo valor de verdad, es decir, que den el mismo resultado cuando se usen en contexto booleano, como en una declaración if().

Nota: "true" y "false" solo se importan por solicitud especial.

code

cmp_deeply( $got, code(\&subref) );

"\&subref" es una referencia a una subrutina a la que se le pasará un solo argumento, y luego debería devolver un valor verdadero o falso y posiblemente una cadena.

Esto pasará $got_v a la subrutina que devuelve verdadero o falso para indicar un éxito o un fallo. Los fallos pueden ir acompañados de una cadena de diagnóstico que explique por qué es un fallo.

sub check_name
{
  my $name = shift;
  if ($boss->likes($name))
  {
    return 1;
  }
  else
  {
    return (0, "the boss doesn't like your name");
  }
}
cmp_deeply("Brian", code(\&check_name));

COMPARACIONES DE ARRAYS

Las comparaciones de arrays con cmp_deeply suelen ser tan sencillas como pasar un array a la función array, set, bag o hash.

Las siguientes implementaciones de set, bag y hash son para facilitar las comparaciones profundas de datos en Perl.

COMPARACIONES DE CONJUNTOS

Las comparaciones de conjuntos dan semánticas especiales a las comparaciones de arrays, donde el orden y la duplicación de los elementos son irrelevantes.

Por lo tanto, los siguientes arrays son iguales:

[ 1, 2 ]
[ 1, 1, 2 ]
[ 1, 2, 1 ]
[ 2, 1, 1 ]
[ 1, 1, 2 ]

Todos son interpretados por la semántica de "set" como si el conjunto solo se especificara como:

[ 1, 2 ]

Todas las funciones "set" devuelven un objeto al que se pueden añadir elementos adicionales:

my $set = set( 1, 2 );
$set->add(1, 3, 1 );  # El conjunto es ahora ( 1, 2, 3 )

Se debe tener especial cuidado al utilizar comparaciones especiales dentro de conjuntos. Consulte "ESPECIAL CUIDADO CON LAS COMPARACIONES ESPECIALES EN CONJUNTOS Y BOLSAS" para más detalles.

set

cmp_deeply( \@got, set(@elements) );

Esto realiza una comparación de conjuntos, es decir, compara dos arrays pero ignora el orden de los elementos y los elementos duplicados, pero asegura que todos los elementos en @elements estarán en $got y todos los elementos en $got estarán en @elements.

Por lo tanto, las siguientes pruebas pasarán y serán equivalentes:

cmp_deeply([1, 2, 2, 3], set(3, 2, 1, 1));
cmp_deeply([1, 2, 3],    set(3, 2, 1));

supersetof

cmp_deeply( \@got, supersetof(@elements) );

Esta función funciona de manera muy similar a "set" y realiza una comparación de conjuntos de $got_v con los elementos de @elements.

"supersetof" es, sin embargo, ligeramente más flexible, de modo que $got puede contener elementos que no están en @elements, pero debe contener al menos todos los elementos de @elements.

Estas dos sentencias son equivalentes y pasarán:

cmp_deeply([1,2,3,3,4,5], supersetof(2,2,3));
cmp_deeply([1,2,3,4,5],   supersetof(2,3));

Pero estas fallarán:

cmp_deeply([1,2,3,4,5],   supersetof(2,3,6)); # 6 no está en el superconjunto
cmp_deeply([1],           supersetof(1,2));   # 2 no está en el superconjunto

subsetof

cmp_deeply( \@got, subsetof(@elements) );

Esta función funciona de manera muy similar a "set" y realiza una comparación de conjuntos de $got_v con los elementos de @elements.

Esta es la inversa de "supersetof", que espera que todos los elementos únicos encontrados en $got_v estén en @elements.

cmp_deeply([1,2,4,5], subsetof(2,3,3)    ) # Fallo: 1, 4 y 5 extras
cmp_deeply([2,3,3],   subsetof(1,2,4,5)  ) # Fallo: 3 extras
cmp_deeply([2,3,3],   subsetof(1,2,4,5,3)) # Pasa

none

cmp_deeply( $got, none(@elements) );

@elements es un array de elementos, donde ningún elemento en @elements puede ser igual a $got_v.

noneof

cmp_deeply( \@got, noneof(@elements) );

@elements es un array de elementos, donde ningún elemento en @elements puede encontrarse en $got_v.

Por ejemplo:

# got no tiene 1, no tiene 2, y no tiene 3
cmp_deeply( [1], noneof( 1, 2, 3 ) ); # falla
cmp_deeply( [5], noneof( 1, 2, 3 ) ); # pasa

COMPARACIONES DE BOLSAS

Las comparaciones de bolsas otorgan semánticas especiales a las comparaciones de arrays, que son similares a las comparaciones de conjuntos, pero ligeramente diferentes.

  • El orden de los elementos en una bolsa es irrelevante
  • La presencia de elementos duplicados en una bolsa se PRESERVA

Como tales, en cualquier comparación de bolsas, los siguientes arrays son iguales:

[ 1, 1, 2 ]
[ 1, 2, 1 ]
[ 2, 1, 1 ]
[ 1, 1, 2 ]

Sin embargo, NO son iguales a ninguno de los siguientes:

[ 1, 2 ]
[ 1, 2, 2 ]
[ 1, 1, 1, 2 ]

Todas las funciones "bag" devuelven un objeto al que se pueden añadir elementos adicionales:

my $bag = bag( 1, 2 );
$bag->add(1, 3, 1 );  # La bolsa es ahora ( 1, 1, 1, 2, 3 )

Se debe tener especial cuidado al utilizar comparaciones especiales dentro de bolsas. Consulte "ESPECIAL CUIDADO CON LAS COMPARACIONES ESPECIALES EN CONJUNTOS Y BOLSAS" para más detalles.

bag

cmp_deeply( \@got, bag(@elements) );

Esto realiza una comparación de bolsas insensible al orden entre $got y @elements, asegurando que:

cada elemento en @elements se encuentra en $got
el número de veces que se encuentra un $expected_v en @elements se refleja en $got
no se encuentran elementos en $got que no estén en @elements.

Como tales, los siguientes son pases y son equivalentes entre sí:

cmp_deeply([1, 2, 2], bag(2, 2, 1))
cmp_deeply([2, 1, 2], bag(2, 2, 1))
cmp_deeply([2, 2, 1], bag(2, 2, 1))

Pero los siguientes son fallos:

cmp_deeply([1, 2, 2],     bag(2, 2, 1, 1)) # No hay suficientes 1s en Got
cmp_deeply([1, 2, 2, 1],  bag(2, 2, 1)   ) # Demasiados 1s en Got

superbagof

cmp_deeply( \@got, superbagof( @elements ) );

Esta función funciona de manera muy similar a "bag" y realiza una comparación de bolsas de $got_v con los elementos de @elements.

"superbagof" es, sin embargo, ligeramente más flexible, de modo que $got puede contener elementos que no están en @elements, pero debe contener al menos todos los elementos de @elements.

Entonces:

# pasa
cmp_deeply( [1, 1, 2], superbagof( 1 )      );
# falla: no hay suficientes 1s en la superbolsa
cmp_deeply( [1, 1, 2], superbagof( 1, 1, 1 ));

subbagof

cmp_deeply( \@got, subbagof(@elements) );

Esta función funciona de manera muy similar a "bag" y realiza una comparación de bolsas de $got_v con los elementos de @elements.

Esta es la inversa de "superbagof", y espera que todos los elementos en $got estén en @elements, mientras permite que haya elementos en @elements que no estén en $got

# pasa
cmp_deeply( [1],        subbagof( 1, 1, 2 ) );
# falla: demasiados 1s en la subbolsa
cmp_deeply( [1, 1, 1],  subbagof( 1, 1, 2 ) );

COMPARACIONES DE HASH

Típicamente, si estás haciendo comparaciones simples de hash,

cmp_deeply( \%got, \%expected )

es suficiente. "cmp_deeply" se asegurará de que %got y %hash tengan claves idénticas, y que cada clave de cualquiera de ellas tenga el mismo valor correspondiente.

superhashof

cmp_deeply( \%got, superhashof(\%hash) );

Esto comprobará que el hash %$got es un "super-hash" de %hash. Es decir, que todos los pares clave-valor en %hash aparecen en %$got, pero %$got puede tener elementos adicionales también.

Por ejemplo

cmp_deeply({a => 1, b => 2}, superhashof({a => 1}))

pasará, pero

cmp_deeply({a => 1, b => 2}, superhashof({a => 1, c => 3}))

fallará.

subhashof

cmp_deeply( \%got, subhashof(\%hash) );

Esto comprobará que el hash %$got es un "sub-hash" de %hash. Es decir, que todos los pares clave-valor en %$got también aparecen en %hash.

Por ejemplo

cmp_deeply({a => 1}, subhashof({a => 1, b => 2}))

pasará, pero

cmp_deeply({a => 1, c => 3}, subhashof({a => 1, b => 2}))

fallará.

FUNCIONES DE DIAGNÓSTICO

deep_diag

my $reason = deep_diag($stack);

$stack es un valor devuelto por cmp_details. No llames a esta función si cmp_details devolvió un valor verdadero para $ok.

deep_diag() devuelve una cadena legible por humanos que describe cómo falló la comparación.

OTRO EJEMPLO

Has escrito un módulo para manejar personas y sus intereses cinematográficos. Digamos que tienes una función que devuelve un array de personas de una consulta, cada persona es un hash con 2 claves: Nombre y Edad, y el array está ordenado por Nombre. Puedes hacer

cmp_deeply(
  $result,
  [
    {Name => 'Anne', Age => 26},
    {Name => "Bill", Age => 47}
    {Name => 'John', Age => 25},
  ]
);

Poco después, tu función de consulta cambia y todos los resultados ahora tienen un campo ID. Ahora tu prueba falla de nuevo porque omitiste ID de cada uno de los hashes. El problema es que los IDs son generados por la base de datos y no tienes forma de saber cuál es el ID de cada persona. Con Test::Deep puedes cambiar tu consulta a

cmp_deeply(
  $result,
  [
    {Name => 'John', Age => 25, ID => ignore()},
    {Name => 'Anne', Age => 26, ID => ignore()},
    {Name => "Bill", Age => 47, ID => ignore()}
  ]
);

Pero tu prueba todavía falla. Ahora, debido a que estás usando una base de datos, ya no sabes en qué orden aparecerán las personas. Podrías añadir una ordenación a la consulta de la base de datos, pero eso podría ralentizar tu aplicación. En su lugar, puedes hacer que Test::Deep ignore el orden del array haciendo una comparación de bolsas en su lugar.

cmp_deeply(
  $result,
  bag(
    {Name => 'John', Age => 25, ID => ignore()},
    {Name => 'Anne', Age => 26, ID => ignore()},
    {Name => "Bill", Age => 47, ID => ignore()}
  )
);

Finalmente, la persona se vuelve aún más complicada e incluye un nuevo campo llamado Películas, esta es una lista de películas que la persona ha visto recientemente, de nuevo estas películas también podrían venir en cualquier orden, por lo que necesitamos una bolsa dentro de nuestra otra comparación de bolsas, lo que nos da algo como

cmp_deeply(
$result,
  bag(
    {Name => 'John', Age => 25, ID => ignore(), Movies => bag(...)},
    {Name => 'Anne', Age => 26, ID => ignore(), Movies => bag(...)},
    {Name => "Bill", Age => 47, ID => ignore(), Movies => bag(...)}
  )
);

USANDO TEST::DEEP CON TEST::BUILDER

La combinación de "cmp_details" y "deep_diag" hace posible usar Test::Deep en tus propias clases de prueba.

En una subclase de Test::Builder, crea un método de prueba con la siguiente forma:

sub behaves_ok {
  my $self = shift;
  my $expected = shift;
  my $test_name = shift;
  my $got = do_the_important_work_here();
  my ($ok, $stack) = cmp_details($got, $expected);
  unless ($Test->ok($ok, $test_name)) {
    my $diag = deep_diag($stack);
    $Test->diag($diag);
  }
}

Como la subclase define una clase de prueba, no las pruebas en sí, asegúrate de que use Test::Deep::NoTest, no "Test::Deep" en sí mismo.

LIMITACIONES

Actualmente, cualquier referencia CODE, GLOB o IO se comparará usando shallow(), lo que significa que solo se compararán sus direcciones de memoria.

BUGS

Hay un error en la comparación de conjuntos y bolsas (set y bag) relacionado con SCs competidores. Solo ocurre cuando pones ciertas comparaciones especiales dentro de comparaciones de bolsas o conjuntos, no tienes que preocuparte por ello. Los detalles completos están en la documentación de bag(). Se corregirá en una próxima versión.

ADVERTENCIAS

CUIDADO ESPECIAL CON COMPARACIONES ESPECIALES EN CONJUNTOS Y BOLSAS

Si utilizas ciertas comparaciones especiales dentro de una comparación de bolsa o conjunto, existe el peligro de que una prueba falle cuando debería haber pasado. Solo puede ocurrir si dos o más comparaciones especiales en la bolsa compiten para coincidir con elementos. Considera esta comparación:

cmp_deeply(['furry', 'furball'], bag(re("^fur"), re("furb")))

Podrían ocurrir dos cosas: con suerte, re("^fur") se empareja con "furry" y re("furb") se empareja con "furball", y todo está bien; pero podría ocurrir que re("^fur") se empareje con "furball" y luego re("furb") no encuentre una coincidencia y por lo tanto la prueba falle. Ejemplos de otras comparaciones competidoras son "bag(1, 2, 2)" contra "set(1, 2)" y "methods(m1 => "v1", m2 => "v2")" contra "methods(m1 => "v1")"

Este problema podría resolverse usando un algoritmo más lento y complejo para la coincidencia de conjuntos y bolsas. Algo para el futuro...

¿QUÉ SON LAS COMPARACIONES ESPECIALES?

Una comparación especial (SC) es simplemente un objeto que hereda de Test::Deep::Cmp. Siempre que $expected_v sea una SC, en lugar de comprobar "$got_v eq $expected_v", pasamos el control a la SC y dejamos que haga lo suyo.

Test::Deep exporta muchos constructores de SC para que te sea fácil usarlos en tus scripts de prueba. Por ejemplo, re("hello") es solo una forma útil de crear un objeto Test::Deep::Regexp que coincidirá con cualquier cadena que contenga "hello". Así:

cmp_deeply([ 'a', 'b', 'hello world'], ['a', 'b', re("^hello")]);

comprobará 'a' eq 'a', 'b' eq 'b', pero cuando se trate de comparar 'hello world' y re("^hello"), verá que $expected_v es una SC y pasará el control a la clase Test::Deep::Regexp haciendo algo como "$expected_v->descend($got_v)". El método descend() solo debería devolver verdadero o falso.

Esto te da suficiente para escribir tus propias SCs, pero no he documentado cómo funcionan los diagnósticos porque están a punto de recibir una revisión (teóricamente).

EXPORTACIONES

Por defecto, Test::Deep exportará todo en su etiqueta "v0", como si hubieras escrito:

use Test::Deep ':v0';

Esas cosas son:

all any array array_each arrayelementsonly arraylength arraylengthonly bag
blessed bool cmp_bag cmp_deeply cmp_methods cmp_set code eq_deeply hash
hash_each hashkeys hashkeysonly ignore Isa isa listmethods methods noclass
none noneof num obj_isa re reftype regexpmatches regexponly regexpref
regexprefonly scalarrefonly scalref set shallow str subbagof subhashof
subsetof superbagof superhashof supersetof useclass

Un conjunto de exportaciones ligeramente mejor es el conjunto "v1". Son todas las mismas cosas, con la excepción de "Isa" y "blessed". Si quieres importar "todo", probablemente querrás escribir "use Test::Deep ':V1';".

Hay otro grupo de exportación mágica: ":preload". Si se especifica, todos los plugins de Test::Deep se cargarán inmediatamente en lugar de perezosamente.
