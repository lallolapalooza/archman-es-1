Test2(3perl) Guía de referencia para programadores de Perl Test2(3perl)

NOMBRE

Test2 - Marco para escribir herramientas de prueba que funcionen conjuntamente.

DESCRIPCIÓN

Test2 es un nuevo marco de pruebas producido mediante la bifurcación de Test::Builder, refactorizándolo completamente, añadiendo muchas funciones y capacidades nuevas.

¿QUÉ ES NUEVO?

Más fácil de probar nuevas herramientas de prueba.
Desde el principio, Test2 se construyó con capacidades de introspección. Con Test::Builder era como mucho difícil capturar la salida de la herramienta de prueba para su verificación. Test2 lo hace fácil con Test2::API::intercept().
Mejores capacidades de diagnóstico.
Test2 utiliza un objeto Test2::API::Context para rastrear el nombre del archivo, el número de línea y los detalles de la herramienta. Este objeto simplifica enormemente el rastreo de dónde se deben informar los errores.
Basado en eventos.
Las herramientas basadas en Test2 producen eventos que pasan por un sistema de procesamiento antes de ser emitidos por un formateador. Este sistema de eventos permite un rico soporte de plugins y extensiones.
API más completa.
Test::Builder solo proporcionaba un puñado de métodos para generar líneas de TAP. Test2 inventarió todo lo que la gente hacía con Test::Builder que requería modificarlo. Test2 creó funciones de API públicas para casi toda la funcionalidad deseada que la gente no tenía previamente.
Soporte para salidas distintas de TAP.
Test::Builder asumía que todo terminaría siendo TAP. Test2 no hace tal suposición. Test2 proporciona formas para que especifiques formateadores alternativos y personalizados.
La implementación de subpruebas es más sensata.
La implementación de subpruebas de Test::Builder era ciertamente insensata. Test2 utiliza un sistema de centros de eventos apilados que mejora enormemente cómo se implementan las subpruebas.
Soporte para hilos/bifurcaciones.
El soporte de Test2 para bifurcaciones e hilos se puede activar usando Test2::IPC. Una vez activado, los hilos y las bifurcaciones funcionan sensatamente y como se espera.

EMPEZANDO

Si estás interesado en escribir pruebas usando herramientas nuevas, deberías mirar Test2::Suite. Test2::Suite es una distribución de cpan separada que contiene muchas herramientas implementadas en Test2.

Si estás interesado en escribir herramientas nuevas, deberías echar un vistazo primero a Test2::API.

DISTRIBUCIÓN DE ESPACIOS DE NOMBRES

Esto describe la distribución del espacio de nombres para el ecosistema Test2. No todos los espacios de nombres listados aquí forman parte de la distribución Test2, algunos se implementan en Test2::Suite.

Test2::Tools::

Este espacio de nombres es para conjuntos de herramientas. Los módulos en este espacio de nombres deben exportar herramientas como ok() y is(). La mayoría de las cosas escritas para Test2 deberían ir aquí. Los módulos en este espacio de nombres NO DEBEN exportar subrutinas de otras herramientas. Mira el espacio de nombres "Test2::Bundle::" si quieres hacer eso.

Test2::Plugin::

Este espacio de nombres es para plugins. Los plugins son módulos que cambian o mejoran el comportamiento de Test2. Un ejemplo de plugin es un módulo que establece la codificación a utf8 globalmente. Otro ejemplo es un módulo que provoca un evento de interrupción (bail-out) después del primer fallo de la prueba.

Test2::Bundle::

Este espacio de nombres es para paquetes de herramientas y plugins. Cargar uno de estos puede cargar múltiples herramientas y plugins. Los módulos en este espacio de nombres no deben implementar herramientas directamente. En general, los módulos en este espacio de nombres deben cargar herramientas y plugins, y luego reexportar cosas al espacio de nombres del consumidor.

Test2::Require::

Este espacio de nombres es para módulos que provocan que una prueba se omita cuando las condiciones no permiten su ejecución. Los ejemplos serían módulos que omiten la prueba en versiones de Perl más antiguas, o cuando no se han instalado módulos no esenciales.

Test2::Formatter::

Los formateadores viven bajo este espacio de nombres. Test2::Formatter::TAP es el único formateador actualmente. Es aceptable que distribuciones de terceros creen nuevos formateadores bajo este espacio de nombres.

Test2::Event::

Los eventos viven bajo este espacio de nombres. Se considera aceptable que distribuciones de terceros añadan nuevos tipos de eventos en este espacio de nombres.

Test2::Hub::

Las subclases de hub (y algunos objetos de utilidad de hub) viven bajo este espacio de nombres. Es perfectamente razonable que distribuciones de terceros añadan nuevas subclases de hub en este espacio de nombres.

Test2::IPC::

El subsistema IPC vive en este espacio de nombres. No hay muchas buenas razones para añadir nada a este espacio de nombres, con la excepción de los controladores IPC.

Test2::IPC::Driver::

Los controladores IPC viven en este espacio de nombres. Está bien crear nuevos controladores IPC y ponerlos en este espacio de nombres.

Test2::Util::

Este espacio de nombres es para utilidades generales usadas por las herramientas de prueba. Por favor, sea considerado al añadir nuevos módulos a este espacio de nombres.

Test2::API::

Esto es para la API de Test2 y paquetes relacionados.

Test2::

El espacio de nombres Test2:: está destinado a extensiones y marcos. Las herramientas, plugins, etc., no deben ir directamente a este espacio de nombres. Sin embargo, las extensiones que se utilizan para construir herramientas y plugins pueden ir aquí.

En resumen: Si el módulo exporta algo que deba ser ejecutado directamente por un script de prueba, probablemente NO debería ir directamente a "Test2::XXX".

VER TAMBIÉN

Test2::API - Funciones principales de la API.

Test2::API::Context - Documentación detallada del objeto de contexto.

Test2::IPC - El sistema IPC utilizado para el soporte de hilos/bifurcaciones.

Test2::Formatter - Los formateadores como TAP viven aquí.

Test2::Event - Los eventos viven en este espacio de nombres.

Test2::Hub - Todos los eventos eventualmente pasan a través de un hub. Los hubs personalizados son cómo se implementan intercept() y run_subtest().
