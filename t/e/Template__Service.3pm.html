NOMBRE

Template::Service - Servicio de procesamiento de plantillas de propósito general

SINOPSIS

use Template::Service;
my $service = Template::Service->new({
    PRE_PROCESS  => [ 'config', 'header' ],
    POST_PROCESS => 'footer',
    ERROR        => {
        user     => 'user/index.html',
        dbi      => 'error/database',
        default  => 'error/default',
    },
});
my $output = $service->process($template_name, \%replace)
    || die $service->error(), "\n";

DESCRIPCIÓN

El módulo "Template::Service" implementa una clase de objeto para proporcionar un servicio de procesamiento de plantillas consistente.

Se pueden especificar plantillas de encabezado (PRE_PROCESS) y pie de página (POST_PROCESS) estándar que se anteponen y se añaden a todas las plantillas procesadas por el servicio (pero no a otras plantillas o bloques "INCLUDE"ados o "PROCESS"ados desde dentro). Se puede especificar un hash de ERROR que redirige el servicio a un archivo de plantilla alternativo en caso de que se produzcan excepciones no capturadas. Esto permite que los errores sean manejados automáticamente por el servicio y se genere una respuesta garantizada válida independientemente de los problemas de procesamiento encontrados.

El módulo Template crea un objeto "Template::Service" por defecto. Se pueden pasar cualquier opción de "Template::Service" al método constructor new() de Template y se reenviarán al constructor de Template::Service.

use Template;
my $template = Template->new({
    PRE_PROCESS  => 'header',
    POST_PROCESS => 'footer',
});

De manera similar, el constructor de "Template::Service" reenviará todos los parámetros de configuración a otros objetos predeterminados (por ejemplo, Template::Context) que pueda necesitar instanciar.

Se puede instanciar explícitamente un objeto "Template::Service" (o una subclase) y pasarlo al método constructor new() de Template como el elemento SERVICE.

use Template;
use Template::Service;
my $service = Template::Service->new({
    PRE_PROCESS  => 'header',
    POST_PROCESS => 'footer',
});
my $template = Template->new({
    SERVICE => $service,
});

El módulo "Template::Service" puede ser subclasificado para crear manejadores de servicio personalizados.

use Template;
use MyOrg::Template::Service;
my $service = MyOrg::Template::Service->new({
    PRE_PROCESS  => 'header',
    POST_PROCESS => 'footer',
    COOL_OPTION  => 'enabled in spades',
});
my $template = Template->new({
    SERVICE => $service,
});

El módulo Template utiliza el método de fábrica service() de Template::Config para crear un objeto de servicio por defecto cuando se requiere. La variable de paquete $Template::Config::SERVICE puede establecerse para especificar un módulo de servicio alternativo. Este se cargará automáticamente y se llamará a su método constructor new() por el método de fábrica service() cuando se requiera un objeto de servicio por defecto. Por lo tanto, el ejemplo anterior podría escribirse como:

use Template;
$Template::Config::SERVICE = 'MyOrg::Template::Service';
my $template = Template->new({
    PRE_PROCESS  => 'header',
    POST_PROCESS => 'footer',
    COOL_OPTION  => 'enabled in spades',
});

MÉTODOS

new(\%config)

El método constructor new() se llama para instanciar un objeto "Template::Service". Se pueden especificar parámetros de configuración como una referencia HASH o como una lista de pares "nombre => valor".

my $service1 = Template::Service->new({
    PRE_PROCESS  => 'header',
    POST_PROCESS => 'footer',
});
my $service2 = Template::Service->new( ERROR => 'error.html' );

El método new() devuelve un objeto "Template::Service" o "undef" en caso de error. En este último caso, se puede recuperar un mensaje de error relevante utilizando el método de clase error() o directamente de la variable de paquete $Template::Service::ERROR.

my $service = Template::Service->new(\%config)
    || die Template::Service->error();
my $service = Template::Service->new(\%config)
    || die $Template::Service::ERROR;

process($input, \%replace)

El método process() se llama para procesar una plantilla especificada como el primer parámetro, $input. Este puede ser un nombre de archivo, un manejador de archivo (por ejemplo, "GLOB" o "IO::Handle") o una referencia a una cadena de texto que contenga el texto de la plantilla. Se puede pasar una referencia adicional a un hash que contenga definiciones de variables de plantilla.

El método procesa la plantilla, añadiendo cualquier plantilla PRE_PROCESS o POST_PROCESS definida, y devuelve el texto de salida. Una excepción no capturada lanzada por la plantilla será manejada por un controlador ERROR relevante si está definido. Los errores que ocurran en las plantillas PRE_PROCESS o POST_PROCESS, o aquellos que ocurran en la plantilla de entrada principal y no sean manejados, hacen que el método devuelva "undef" para indicar fallo. El mensaje de error apropiado se puede recuperar a través del método error().

$service->process('myfile.html', { title => 'Mi Archivo de Prueba' })
    || die $service->error();

context()

Devuelve una referencia al objeto de contexto interno que es, por defecto, una instancia de la clase Template::Context.

OPCIONES DE CONFIGURACIÓN

La siguiente lista resume las opciones de configuración que se pueden proporcionar al constructor "Template::Service" new(). Por favor, consulte Template::Manual::Config para obtener más detalles y ejemplos de cada opción de configuración en uso.

PRE_PROCESS, POST_PROCESS

Las opciones PRE_PROCESS y POST_PROCESS se pueden establecer para contener el/los nombre(s) de los archivos de plantilla que deben procesarse inmediatamente antes y/o después de cada plantilla. Estos no se añaden a las plantillas procesadas en un documento a través de directivas como "INCLUDE" "PROCESS", "WRAPPER", etc.

my $service = Template::Service->new({
    PRE_PROCESS  => 'header',
    POST_PROCESS => 'footer',
};

Se pueden especificar varias plantillas como referencia a una lista. Cada una se procesa en el orden definido.

my $service = Template::Service->new({
    PRE_PROCESS  => [ 'config', 'header' ],
    POST_PROCESS => 'footer',
};

PROCESS

La opción PROCESS se puede establecer para contener el/los nombre(s) de los archivos de plantilla que deben procesarse en lugar de la plantilla principal pasada al método "Template::Service" process(). Esto se puede utilizar para aplicar envoltorios consistentes a todas las plantillas, similar al uso de las plantillas PRE_PROCESS y POST_PROCESS.

my $service = Template::Service->new({
    PROCESS  => 'content',
};
# procesa 'content' en lugar de 'foo.html'
$service->process('foo.html');

Una referencia a la plantilla original está disponible en la variable "template". Los elementos de metadatos se pueden inspeccionar y la plantilla se puede procesar especificándola como una referencia de variable (es decir, prefijada por '"$"') a una directiva "INCLUDE", "PROCESS" o "WRAPPER".

Ejemplo de plantilla "PROCESS":

<html>
  <head>
    <title>[% template.title %]</title>
  </head>
  <body>
  [% PROCESS $template %]
  </body>
</html>

NAME

Template::Service - A templating service interface

SYNOPSIS

    use Template;

    # create a Template::Service object
    my $template = Template->new({
        INCLUDE_PATH => '/path/to/templates',
        COMPILE_DIR  => '/path/to/compiled/templates',
    });

    # process a template
    my $status = $template->process('file.tt', \%vars);

    # process template content directly
    my $status = $template->process(\&{ $template->compile(...)->{'code'} }, \%vars);

    # retrieve an error message from the last process() call
    my $error = $template->error();

    # retrieve the output from the last process() call
    my $output = $template->output();

    # get/set configuration options
    my $config = $template->config();
    $template->config('POST_CHOMP', 1);
    $template->config('RELATIVE', 1);

    # define and use blocks
    $template->define_block('my_block', sub { ... });
    $template->process('file.tt', \%vars, \*OUTPUT);

    # explicitly clear the template cache
    $template->clear_cache();

DESCRIPTION

The Template::Service module is the primary interface to the Template Toolkit. It acts as a factory and manager for Template::Context objects, which hold the state and configuration for template processing.

The Template module is a simple subclass of Template::Service, providing a convenient way to instantiate and use the templating engine with minimal configuration.

When you call the process() method, the Template::Service object instantiates a Template::Context object and calls its process() method. Any configuration options passed to the Template::Service constructor are used to initialize the Template::Context object.

METHODS

new(%args)

Constructor for Template::Service. Accepts a hash reference of configuration options which are passed directly to the Template::Context constructor.

See Template::Context for a full list of configuration options.

process($file, \%vars, $output)

Processes the template specified by $file using the variables defined in the hash reference \%vars. The output is sent to the filehandle specified by $output (defaults to STDOUT).

Returns true on success, false on failure. You can retrieve an error message from the last failed operation using the error() method.

If $file is an array reference, it is treated as a list of template files to be processed in sequence. The output of each template is concatenated.

If $file is a code reference (e.g., returned by compile()), it is executed directly.

error()

Returns the error message from the last operation, or undef if the last operation succeeded.

output()

Returns the accumulated output from the last process() operation. This is only useful if the $output argument was not provided to process().

config(%args)

Used to get or set configuration options for the service. Called with no arguments, it returns a hash reference containing all current configuration options. Called with a single key-value pair, it sets that option.

    my $path = $template->config('INCLUDE_PATH');
    $template->config('RELATIVE', 1);
    my %all_config = $template->config();
define_block($name, \%code)

Defines a reusable block of template code identified by $name. The \%code argument is a hash reference returned by the compile() method, typically containing a 'code' key with a code reference.

    my $compiled = $template->compile(source => <<'...'));
    $template->define_block('MY_BLOCK', $compiled);

This is rarely needed as blocks are usually defined within templates using the BLOCK directive.

clear_cache()

Clears the internal cache of compiled templates. This is useful if you are modifying template files on disk while the service is running.

CONFIGURATION OPTIONS

The following options can be passed to the constructor or set via the config() method. They are used to initialize the Template::Context object.

AUTO_DIR

If set to a true value, the toolkit will automatically add the directory of the currently processed template to the INCLUDE_PATH. This allows templates to include other templates located in the same directory without explicitly listing that directory in the INCLUDE_PATH.

    my $service = Template::Service->new({
        AUTO_DIR => 1,
    });
ERROR / ERRORS

Specifies which template file(s) should be used for error handling. The ERROR configuration item is a convenience alias for ERRORS when only a single (default) error template is defined. (See also the DIE ON ERROR configuration option).

If specified as a single template name (e.g. error.html), then that template will be processed for all uncaught exceptions.

    my $service = Template::Service->new({
        ERROR => 'error.html'
    });

If the ERROR or ERRORS item is a hash reference, the keys are assumed to be exception types (e.g. user, dbi) and the relevant template for a given exception will be selected. A "default" template may be provided for the general case.

    my $service = Template::Service->new({
        ERRORS => {
            user    => 'user/index.html',
            dbi     => 'error/database',
            default => 'error/default',
        },
    });
AUTO_RESET

The AUTO_RESET option is set by default and causes the local "BLOCKS" cache for the Template::Context object to be reset on each call to the Template process() method. This ensures that any "BLOCK"s defined within a template will only persist until that template is finished processing.

DEBUG

The DEBUG option can be used to enable debugging messages from the "Template::Service" module by setting it to include the "DEBUG_SERVICE" value.

    use Template::Constants qw( :debug );
    my $template = Template->new({
        DEBUG => DEBUG_SERVICE,
    });
