NAME

Text::Reform - Manual text wrapping and reformatting

VERSION

This document describes version 1.20 of Text::Reform, released 2009-09-06.

SYNOPSIS

use Text::Reform;
print form $template,
           $data, $to, $fill, $it, $with;
use Text::Reform qw( tag );
print tag 'B', $enboldened_text;

DESCRIPTION

The "form" sub

The form() subroutine may be exported from the module. It takes a series of format (or "picture") strings followed by replacement values, interpolates those values into each picture string, and returns the result. The effect is similar to the inbuilt perl "format" mechanism, although the field specification syntax is simpler and some of the formatting behaviour is more sophisticated.

A picture string consists of sequences of the following characters:

<
Left-justified field indicator. A series of two or more sequential <'s specify a left-justified field to be filled by a subsequent value. A single < is formatted as the literal character '<'
>
Right-justified field indicator. A series of two or more sequential >'s specify a right-justified field to be filled by a subsequent value. A single > is formatted as the literal character '>'
<<<>>>
Fully-justified field indicator. Field may be of any width, and brackets need not balance, but there must be at least 2 '<' and 2 '>'.
^
Centre-justified field indicator. A series of two or more sequential ^'s specify a centred field to be filled by a subsequent value. A single ^ is formatted as the literal character '^'
>>>.<<<<
A numerically formatted field with the specified number of digits to either side of the decimal place. See "Numerical formatting" below.
[
Left-justified block field indicator. Just like a < field, except it repeats as required on subsequent lines. See below. A single [ is formatted as the literal character '['
]
Right-justified block field indicator. Just like a > field, except it repeats as required on subsequent lines. See below. A single ] is formatted as the literal character ']'
[[[]]]
Fully-justified block field indicator. Just like a <<<>>> field, except it repeats as required on subsequent lines. See below. Field may be of any width, and brackets need not balance, but there must be at least 2 '[' and 2 ']'.
|
Centre-justified block field indicator. Just like a ^ field, except it repeats as required on subsequent lines. See below. A single | is formatted as the literal character '|'
]]].[[[[
A numerically formatted block field with the specified number of digits to either side of the decimal place. Just like a >>>.<<<< field, except it repeats as required on subsequent lines. See below.
~
A one-character wide block field.
\
Literal escape of next character (e.g. "\~" is formatted as '~', not a one character wide block field).
Any other character
That literal character.

Any substitution value which is "undef" (either explicitly so, or because it is missing) is replaced by an empty string.

Controlling line filling.

Note that, unlike the a perl "format", "form" preserves whitespace (including newlines) unless called with certain options.

The "squeeze" option (when specified with a true value) causes any sequence of spaces and/or tabs (but not newlines) in an interpolated string to be replaced with a single space.

A true value for the "fill" option causes (only) newlines to be squeezed.

To minimize all whitespace, you need to specify both options. Hence:

$format = "EG> [[[[[[[[[[[[[[[[[[[[[";
$data   = "h  e\t l lo\nworld\t\t\t\t\t";
print form $format, $data;              # all whitespace preserved:
                                        #
                                        # EG> h  e            l lo
                                        # EG> world
print form {squeeze=>1},                # only newlines preserved:
           $format, $data;              #
                                        # EG> h e l lo
                                        # EG> world
print form {fill=>1},                   # only spaces/tabs preserved:
            $format, $data;             #
                                        # EG> h  e        l lo world
print form {squeeze=>1, fill=>1},       # no whitespace preserved:
           $format, $data;              #
                                        # EG> h e l lo world

Whether or not filling or squeezing is in effect, "form" can also be directed to trim any extra whitespace from the end of each line it formats, using the "trim" option. If this option is specified with a true value, every line returned by "form" will automatically have the substitution "s/[ \t]+$//gm" applied to it.

Hence:

print length form "[[[[[[[[[[", "short";
# 11
print length form {trim=>1}, "[[[[[[[[[[", "short";
# 6

It is also possible to control the character used to fill lines that are too short, using the 'filler' option. If this option is specified the value of the 'filler' flag is used as the fill string, rather than the default " ".

For example:

print form { filler=>'*' },
        "Pay bearer: ^^^^^^^^^^^^^^^^^^^",
        '$123.45';

prints:

Pay bearer: ******$123.45******

If the filler string is longer than one character, it is truncated to the appropriate length. So:

print form { filler=>'-->' },
        "Pay bearer: ]]]]]]]]]]]]]]]]]]]",
        ['$1234.50', '$123.45', '$12.34'];

prints:

Pay bearer: ->-->-->-->$1234.50
Pay bearer: -->-->-->-->$123.45
Pay bearer: >-->-->-->-->$12.34

If the value of the 'filler' option is a hash, then it's 'left' and 'right' entries specify separate filler strings for each side of an interpolated value. So:

print form { filler=>{left=>'->', right=>'*'} },
        "Pay bearer: <<<<<<<<<<<<<<<<<<",
        '$123.45',
        "Pay bearer: >>>>>>>>>>>>>>>>>>",
        '$123.45',
        "Pay bearer: ^^^^^^^^^^^^^^^^^^",
        '$123.45';

prints:

Pay bearer: $123.45***********
Pay bearer: >->->->->->$123.45
Pay bearer: >->->$123.45******

Temporary and permanent default options

If "form" is called with options, but no template string or data, it resets it's defaults to the options specified. If called in a void context:

form { squeeze => 1, trim => 1 };

the options become permanent defaults.

However, when called with only options in non-void context, "form" resets its defaults to those options and returns an object. The reset default values persist only until that returned object is destroyed. Hence to temporarily reset "form"'s defaults within a single subroutine:

sub single {
        my $tmp = form { squeeze => 1, trim => 1 };
        # do formatting with the obove defaults
} # form's defaults revert to previous values as $tmp object destroyed

Cómo "form" guioniza

Cualquier línea con un campo de bloque se repite en líneas subsiguientes hasta que todos los campos de bloque en esa línea hayan consumido todos sus datos. Los campos no de bloque en estas líneas se reemplazan por el número apropiado de espacios.

Las palabras se envuelven completas, a menos que no quepan en el campo en absoluto, en cuyo caso se rompen y (por defecto) se guionizan. Se utiliza un guionado simple (es decir, se rompe en el carácter *N-1* y se inserta un '-'), a menos que se especifique una subrutina alternativa adecuada en su lugar.

Las palabras no se romperán si la ruptura dejara menos de 2 caracteres en la línea actual. Este mínimo puede variar estableciendo la opción 'minbreak' a un valor numérico que indique el número mínimo total de caracteres rotos (incluyendo guiones) requeridos en la línea actual. Tenga en cuenta que, para campos muy estrechos, las palabras aún se romperán (pero *sin* guiones). Por ejemplo:

print form '~', 'split';

imprimiría:

s
p
l
i
t

mientras que:

print form {minbreak=>1}, '~', 'split';

imprimiría:

s-
p-
l-
i-
t

Se pueden especificar subrutinas de ruptura alternativas utilizando la opción "break" en un hash de configuración. Por ejemplo:

form { break => \&my_line_breaker }
     $format_str,
     @data;

"form" espera que cualquier subrutina de ruptura de línea definida por el usuario tome tres argumentos (la cadena a romper, la longitud máxima permitida de la sección inicial y el ancho total del campo que se está llenando). La subrutina "hypenate" debe devolver una lista de dos cadenas: la sección inicial (rota) de la palabra y el resto de la cadena respectivamente).

Por ejemplo:

sub tilde_break = sub($$$)
{
        (substr($_[0],0,$_[1]-1).'~', substr($_[0],$_[1]-1));
}
form { break => \&tilde_break }
     $format_str,
     @data;

hace de '~' el carácter de guionado, mientras que:

sub wrap_and_slop = sub($$$)
{
        my ($text, $reqlen, $fldlen) = @_;
        if ($reqlen==$fldlen) { $text =~ m/\A(\s*\S*)(.*)/s }
        else                  { ("", $text) }
}
form { break => \&wrap_and_slop }
     $format_str,
     @data;

envuelve palabras excesivamente largas a la siguiente línea y las "desliza" sobre el margen derecho si es necesario.

El paquete Text::Reform proporciona tres funciones para simplificar el uso de esquemas de guionado variantes. La subrutina exportable "Text::Reform::break_wrap" genera una referencia a una subrutina que implementa el algoritmo "wrap-and-slop" que se muestra en el último ejemplo, que por lo tanto podría reescribirse:

use Text::Reform qw( form break_wrap );
form { break => break_wrap }
     $format_str,
     @data;

La subrutina "Text::Reform::break_with" toma un único argumento de cadena y devuelve una referencia a una subrutina que guioniza cortando el texto en el margen derecho y añadiendo el argumento de cadena. Por lo tanto, el primero de los dos ejemplos podría reescribirse:

use Text::Reform qw( form break_with );
form { break => break_with('-') }
     $format_str,
     @data;

La subrutina "Text::Reform::break_at" toma un único argumento de cadena y devuelve una referencia a una subrutina que guioniza rompiendo inmediatamente después de esa cadena. Por ejemplo:

use Text::Reform qw( form break_at );
form { break => break_at('-') }
       "[[[[[[[[[[[[[[",
       "The Newton-Raphson methodology";
# devuelve:
#
#       "The Newton-
#        Raphson
#        methodology"

Tenga en cuenta que esto difiere del comportamiento de "break_with", que sería:

form { break => break_with('-') }
       "[[[[[[[[[[[[[[",
       "The Newton-Raphson methodology";
# devuelve:
#
#       "The Newton-R-
#        aphson metho-
#        dology"

Por lo tanto, "break_at" es generalmente una mejor opción.

"break_at" también toma una opción 'except', que indica a la subrutina resultante que no rompa en medio de ciertas cadenas. Por ejemplo:

    form { break => break_at('-', {except=>qr/Newton-Raphson/}) }
           "[[[[[[[[[[[[[[",
           "The Newton-Raphson methodology";
    # devuelve:
    #
    #       "The
#        Newton-Raphson
    #        methodology"

Esta opción es particularmente útil para preservar las URL.

La subrutina "Text::Reform::break_TeX" devuelve una referencia a una subrutina que guioniza utilizando el módulo TeX::Hyphen de Jan Pazdziora. Por ejemplo:

use Text::Reform qw( form break_wrap );
form { break => break_TeX }
     $format_str,
     @data;

Tenga en cuenta que en los ejemplos anteriores no hay '\&' delante de "break_wrap", "break_with" o "break_TeX", ya que cada una se está *llamando* directamente (y devuelve una referencia a alguna otra subrutina adecuada);

NAME

form - format data according to specified picture strings

SYNOPSIS

    use Text::Balanced;
    $result = form $picture, $arg1, $arg2, ... ;
    $result = form $picture, $arg1, $arg2, ..., $config;
    $result = form $config, $picture, $arg1, $arg2, ... ;

DESCRIPTION

The form subroutine is the inverse of Text::Balanced::extract_tagged_sections. It takes a format string (a picture) and a list of arguments to be inserted into the picture, returning a formatted string.

The picture is a string containing literal characters interspersed with "fields". Fields are indicated by sequences of the characters <, >, ^, ], and [. These characters are used to define the width and alignment of the fields into which the arguments are substituted.

Fields consisting of only < and/or > characters specify left-justified fields. Fields consisting of only ^ characters specify centered fields. Fields consisting of only ] and/or [ characters specify right-justified fields.

The picture can contain newlines, and can be a multi-line string. The picture string itself is treated as a template, and is filled with the provided arguments.

The form subroutine may be called with optional configuration arguments. These may be passed either as the first argument (if it's a hash reference), or as the last argument (if it's a hash reference). The configuration options are described below.

The following is a detailed description of the formatting process:

  1. The picture string is split into lines.

  2. Each line is processed sequentially. For each line, fields are identified and filled with corresponding arguments from the list. A field is a contiguous sequence of <, >, ^, ], or [ characters.

  3. When a field is encountered:

    1. If the field consists entirely of < and/or > characters, the next argument is taken and left-justified within the field. Excess characters in the argument are truncated. Any remaining space in the field is filled with spaces.

    2. If the field consists entirely of ^ characters, the next argument is taken and centered within the field. Excess characters in the argument are truncated. Any remaining space in the field is filled with spaces.

    3. If the field consists entirely of ] and/or [ characters, the next argument is taken and right-justified within the field. Excess characters in the argument are truncated. Any remaining space in the field is filled with spaces.

    4. Fields made up of different characters (e.g., <>, ^^, ][) are treated as simple literal fields, and the characters within the field are used literally in the output.

    5. If a field contains ., it is treated as a numerical field (see below).

  4. If the picture string contains block fields (fields that span multiple lines), the entire picture is repeated as necessary to accommodate the arguments.

  5. If the arguments are exhausted before the picture is filled, the remaining fields are filled with spaces.

  6. If there are arguments left over after the picture has been filled, those arguments are printed verbatim, one per line.

The form subroutine processes its arguments in a way that mimics the behavior of the standard printf and sprintf functions in C, but with a more flexible picture string.

The form subroutine also supports the concept of "block fields". A block field is a field that is defined over multiple lines in the picture string. When a block field is encountered, the form subroutine will repeat the entire picture, filling the fields in the repeated picture with subsequent arguments, until all arguments have been used.

The following is a breakdown of the formatting process with respect to arguments:

  1. Arguments are consumed from the list as fields are filled. Once an argument is used to fill a field, it is no longer available for subsequent fields *within the same iteration*.

  2. If an argument is a scalar variable, its value is used, and the variable itself is *not* modified.

  3. If an argument is a reference to a scalar variable (e.g., \$scalar), the value of the scalar is used, and *the variable itself is modified* to contain the remaining portion of the string after formatting. This allows for progressive formatting of a single string across multiple calls to form.

  4. If an argument is an array reference (e.g., \@array), the elements of the array are joined together with newline characters, and this resulting string is used to fill the field. The array itself is consumed in this process (i.e., its elements are removed).

  5. If an argument is an anonymous array (e.g., [@array]), the elements are joined with newlines, and this string is used to fill the field. The anonymous array is consumed, but the original array remains unmodified.

The form subroutine can also handle multi-line fields, which are fields that span multiple lines in the picture string. When such a field is encountered, the entire picture is repeated, and the arguments are used to fill the fields in the repeated picture.

Here is a simplified breakdown of the steps involved in processing a multi-line picture:

  1. Split the picture string into individual lines.

  2. For each line, parse it into fields and literal text.

  3. Match fields to arguments one by one.

  4. If a field requires more data than is available in the current argument, the argument is split, and the remainder is used for the next field.

  5. If a field requires more data than is available in *all* remaining arguments, the field is padded with spaces.

  6. If there are arguments remaining after all fields have been filled, they are appended to the output, one per line.

  7. If a field is a block field (a field that spans multiple lines), the entire picture is conceptually repeated, and the process continues with the next available arguments.

  8. If a field is empty (e.g., <>), it is skipped.

  9. The picture string may contain special characters that control formatting:

    • <, >: Left-justified fields.

    • ^: Centered fields.

    • ], [: Right-justified fields.

    • `.` : Decimal point in numerical fields.

  10. The arguments are processed in order. If an argument is a scalar variable, it is not modified. If it is a reference to a scalar variable, it is modified to contain the remainder of the string after formatting.

  11. If an argument is an array reference, its elements are joined by newline characters and used to fill the field. The array is consumed.

  12. If an argument is an anonymous array, its elements are joined by newline characters and used to fill the field. The anonymous array is consumed, but the original array is not.

The following is a step-by-step breakdown of how form consumes its arguments:

  1. The picture string is parsed, and fields are identified.

  2. For each field, the next available argument is taken.

  3. If the argument is a scalar, its value is used to fill the field. The original scalar is unchanged.

  4. If the argument is a reference to a scalar, its value is used. After filling the field, the scalar variable is updated to contain any remaining portion of the original string.

  5. If the argument is an array reference, its elements are joined by newlines, and this string is used to fill the field. The original array is consumed (its elements are effectively removed).

  6. If the argument is an anonymous array, its elements are joined by newlines, and this string is used to fill the field. The anonymous array is consumed, but the original array is not.

  7. If a field is a block field (spanning multiple lines), the entire picture is conceptually repeated, and the process continues with the next available arguments.

  8. If an argument is empty, it is skipped.

  9. If all arguments are exhausted before all fields are filled, the remaining fields are padded with spaces.

  10. If there are remaining arguments after all fields have been filled, they are appended to the output, one per line.

The form subroutine processes its arguments sequentially. For each field in the picture string, it takes the next available argument and uses it to fill the field. The way the argument is used depends on its type:

  1. Scalar: The value of the scalar is used. The original scalar variable is unchanged.

  2. Reference to a scalar: The value of the scalar is used. After filling the field, the scalar variable is updated to contain any remaining portion of the original string.

  3. Array reference: The elements of the array are joined by newline characters, and the resulting string is used to fill the field. The original array is consumed (its elements are removed).

  4. Anonymous array: The elements of the anonymous array are joined by newline characters, and the resulting string is used to fill the field. The anonymous array is consumed, but the original array is not.

The form subroutine can also handle multi-line arguments and block fields. A multi-line argument is an argument that contains newline characters. A block field is a field that spans multiple lines in the picture string.

When form encounters a block field, it effectively repeats the entire picture string, and continues filling fields with subsequent arguments. This allows for the formatting of data that naturally spans multiple lines.

Here's a more detailed look at how form handles arguments, especially in relation to block fields and references:

  1. Fields are filled sequentially from the argument list.

  2. Scalar arguments are used directly and are not modified.

  3. Arguments passed by reference (e.g., \$var) are modified in place. The part of the string used to fill the field is removed from the variable.

  4. Array references (e.g., \@array) are joined by newlines, and the resulting string fills the field. The original array is consumed (its elements are removed).

  5. Anonymous arrays (e.g., [@array]) are joined by newlines, and the resulting string fills the field. The anonymous array is consumed, but the original array is not.

  6. If a field is a "block field" (a field that spans multiple lines in the picture), the entire picture is conceptually repeated, and the process continues with the next available arguments.

  7. If the arguments run out before all fields are filled, the remaining fields are padded with spaces.

  8. If there are arguments left after all fields are filled, they are appended to the output, one per line.

The following illustrates the process when a block field is encountered:

  1. The picture string is parsed, and fields are identified.

  2. Arguments are consumed one by one to fill the fields.

  3. If a field is identified as a block field (meaning it spans multiple lines in the picture), the entire picture string is conceptually repeated.

  4. The process then continues from the beginning of the repeated picture, using the next available arguments to fill the fields.

  5. This continues until all arguments are consumed.

The following describes how form consumes its arguments:

  1. Arguments are consumed sequentially as fields are filled.

  2. Scalar arguments are used, but the original variables are not modified.

  3. Arguments passed by reference (e.g., \$var) are modified in place. The part of the string used to fill the field is removed from the variable.

  4. Array references (e.g., \@array) are joined by newlines, and the resulting string fills the field. The original array is consumed.

  5. Anonymous arrays (e.g., [@array]) are joined by newlines, and the resulting string fills the field. The anonymous array is consumed, but the original array is not.

    CONTROL DE PÁGINA

    La opción "pagefeed" actúa exactamente de la misma manera, para producir un salto de página que se añade después del pie de página. Pero ten en cuenta que el salto de página no se cuenta como parte de la longitud de la página.

    Los tres componentes de página se recalculan al comienzo de cada nueva página, antes de que se formatee el contenido de la página (recalcular la cabecera y el pie de página primero hace posible determinar cuántas líneas de datos formatear para cumplir con la longitud de página especificada).

    Cuando la llamada a "form" se completa y los datos se han formateado por completo, la subrutina de pie de página se llama una última vez, con un argumento adicional de 1. La cadena devuelta por esta llamada final se utiliza como el pie de página final.

    Por ejemplo, un informe de 60 líneas por página, comenzando en la página 7, con cabeceras y pies de página apropiados, podría configurarse de la siguiente manera:

    $page = 7;
form { header => sub { "Página $_[0]\n\n" },
       footer => sub { my ($pagenum, $lastpage) = @_;
                       return "" if $lastpage;
                       return "-"x50 . "\n"
                                     .form ">"x50, "...".($pagenum+1);
                      },
       pagefeed => "\n\n",
       pagelen  => 60
       pagenum => \$page,
     },
     $template,
     @data;

    ¡Observa el uso recursivo de "form" dentro de la opción "footer"!

    Alternativamente, para configurar cabeceras y pies de página de modo que la cabecera en ejecución esté justificada a la derecha en la cabecera y el número de página esté centrado en el pie de página:

    form { header => { right => "Cabecera en ejecución" },
       footer => { centre => sub { "Página $_[0]" } },
       pagelen  => 60
     },
     $template,
     @data;

    El pie de página en el ejemplo anterior también podría haberse especificado de otra manera, como una subrutina que devuelve un hash (en lugar de un hash que contiene una subrutina):

    form { header => { right => "Cabecera en ejecución" },
       footer => sub { return {centre => "Página $_[0]"} },
       pagelen  => 60
     },
     $template,
     @data;

    La opción "cols"

    A veces, los datos que se utilizarán en una llamada a "form" deben extraerse de una estructura de datos anidada. Por ejemplo, si bien es fácil imprimir una tabla si ya tienes los datos en columnas:

    @name  = qw(Tom Dick Harry);
@score = qw( 88   54    99);
@time  = qw( 15   13    18);
print form
'-------------------------------',
'Nombre             Puntuación    Tiempo',
'-------------------------------',
'[[[[[[[[[[[[[[   |||||     ||||',
 \@name,          \@score,  \@time;

    si los datos se agregan por filas:

    @data = (
    { name=>'Tom',   score=>88, time=>15 },
    { name=>'Dick',  score=>54, time=>13 },
    { name=>'Harry', score=>99, time=>18 },
);

    necesitas hacer un mapeo complejo antes de que pueda ser alimentado a "form":

    print form
'-------------------------------',
'Nombre             Puntuación    Tiempo',
'-------------------------------',
'[[[[[[[[[[[[[[   |||||     ||||',
[map $$_{name},  @data],
[map $$_{score}, @data],
[map $$_{time} , @data];

    O podrías simplemente usar la opción 'cols':

    use Text::Reform qw(form columns);
print form
'-------------------------------',
'Nombre             Puntuación    Tiempo',
'-------------------------------',
'[[[[[[[[[[[[[[   |||||     ||||',
{ cols => [qw(name score time)],
  from => \@data
};

    Esta opción toma una matriz de cadenas que especifica las claves de las entradas del hash que se extraerán en columnas. La entrada 'from' (que debe estar presente) también toma una matriz, que se espera que contenga una lista de referencias a hashes. Para cada clave especificada, esta opción inserta en la lista de argumentos de "form" una referencia a una matriz que contiene las entradas para esa clave, extraídas de cada una de las referencias de hash proporcionadas por 'from'. Por lo tanto, por ejemplo, la opción:

    { cols => [qw(name score time)],
  from => \@data
}

    se reemplaza por tres referencias de matriz, la primera contiene las entradas de 'name' para cada hash dentro de @data, la segunda contiene las entradas de 'score' para cada hash dentro de @data, y la tercera contiene las entradas de 'time' para cada hash dentro de @data.

    Si, en cambio, tienes una lista de matrices que contienen los datos:

    @data = (
        # Tiempo  Nombre     Puntuación
        [ 15,   'Tom',   88 ],
        [ 13,   'Dick',  54 ],
        [ 18,   'Harry', 99 ],
);

    la opción 'cols' puede extraer las columnas apropiadas para eso también. Simplemente especificas los índices requeridos, en lugar de las claves:

    print form
'-----------------------------',
'Nombre             Puntuación   Tiempo',
'-----------------------------',
'[[[[[[[[[[[[[[   |||||   ||||',
{ cols => [1,2,0],
  from => \@data
}

    Ten en cuenta que los índices pueden estar en cualquier orden, y las matrices resultantes se devuelven en el mismo orden.

    Si necesitas fusionar columnas extraídas de dos estructuras de datos jerárquicas, simplemente concatena las estructuras de datos primero, así:

    print form
'---------------------------------------',
'Nombre             Puntuación   Tiempo   Ranking
'---------------------------------------',
'[[[[[[[[[[[[[[   |||||   ||||   |||||||',
{ cols => [1,2,0],
  from => [@data, @olddata],
}

    Por supuesto, esto solo funciona si las columnas están en las mismas posiciones en ambos conjuntos de datos (y ambos conjuntos de datos se almacenan en matrices) o si las columnas tienen las mismas claves (y ambos conjuntos de datos están en hashes). Si no es así, tendrías que formatear cada conjunto de datos por separado, así:

    print form
'-----------------------------',
'Nombre             Puntuación   Tiempo'
'-----------------------------',
'[[[[[[[[[[[[[[   |||||   ||||',
{ cols=>[1,2,0],  from=>\@data },
'[[[[[[[[[[[[[[   |||||   ||||',
{ cols=>[3,8,1],  from=>\@olddata },
'[[[[[[[[[[[[[[   |||||   ||||',
{ cols=>[qw(name score time)],  from=>\@otherdata };

    La subrutina "tag"

    La subrutina "tag" puede ser exportada desde el módulo. Toma dos argumentos: un especificador de etiqueta y un texto para ser etiquetado. El especificador de etiqueta indica la indentación de la etiqueta y del texto. La subrutina genera una etiqueta de cierre (usando la variante usual "/etiqueta"), a menos que se proporcione una etiqueta de cierre explícita como tercer argumento.

    El especificador de etiqueta consta de los siguientes componentes (en orden):

    Un espaciador vertical opcional (cero o más saltos de línea separados por espacios en blanco)
    Una o más caracteres de espacio en blanco hasta un salto de línea final obligatorio. Este espacio vertical se inserta antes de la etiqueta y después de la etiqueta de cierre.
    Un espacio de etiqueta opcional
    Cero o más caracteres de espacio en blanco. Tanto la etiqueta como la etiqueta de cierre se indetan con este espacio en blanco.
    Un delimitador de etiqueta izquierdo (de apertura) opcional
    Cero o más caracteres que no son de "palabra" (no alfanuméricos o '_'). Si se omite el delimitador de apertura, se utiliza el carácter '<'.
    Una etiqueta
    Uno o más caracteres de "palabra" (alfanuméricos o '_').
    Argumentos opcionales de etiqueta
    Cualquier número de cualquier carácter.
    Un delimitador de etiqueta derecho (de cierre) opcional
    Cero o más caracteres que no son de "palabra" que equilibran alguna porción secuencial del delimitador de etiqueta de apertura. Por ejemplo, si el delimitador de apertura es "<-(" entonces cualquiera de los siguientes son delimitadores de cierre aceptables: ")->", "->" o ">". Si se omite el delimitador de cierre, se utiliza el "inverso" del delimitador de apertura (por ejemplo, ")->").
    Un espaciador vertical opcional (cero o más saltos de línea)
    Uno o más caracteres de espacio en blanco hasta un salto de línea obligatorio. Este espacio vertical se inserta antes y después del texto completo.
    Un espacio de texto opcional
    Cero o más caracteres de espacio o tabulación. Cada línea de texto se indenta con este espacio en blanco (además del espacio de la etiqueta).

    Por ejemplo:

    $text = "tres líneas\nde texto\netiquetado";
print tag "A HREF=#nextsection", $text;

    imprime:

    <A HREF=#nextsection>tres líneas
de texto
etiquetado</A>

    mientras que:

    print tag "[-:GRIN>>>\n", $text;

    imprime:

    [-:GRIN>>>:-]
tres líneas
de texto
etiquetado
[-:/GRIN>>>:-]

    y:

    print tag "\n\n   <BOLD>\n\n   ", $text, "<END BOLD>";

    imprime:

     

    <BOLD>
   tres líneas
   de texto
   etiquetado
<END BOLD>

NAME
Text::Reform - text formatting and reformatting

VERSION

SYNOPSIS

use Text::Reform qw(reform);

         . "long lines and some short lines, and needs to be presented\n"
         . "in a neat and tidy fashion.";

DESCRIPTION
Text::Reform is a Perl module designed to format and reformat text. It can be used to wrap lines to a specified width, adjust spacing, and generally improve the readability of plain text. It's particularly useful for processing text files, email bodies, or any other text content that requires consistent formatting.

The primary function provided by this module is reform(), which takes a string of text as input and returns a formatted string. Various options can be passed to the reform() function to control the formatting behavior, such as:

  • linesize: The desired maximum width of the output lines. Defaults to 79 characters.
  • nowrap: If set to a true value, the module will not wrap lines, but will still perform other formatting adjustments like collapsing whitespace.
  • break_long_words: If set to a true value, the module will break lines even if it means splitting a word (useful for very long words that exceed the linesize). Defaults to false.
