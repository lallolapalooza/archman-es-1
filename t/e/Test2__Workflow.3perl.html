Test2::Workflow(3perl) Guía de referencia para programadores de Perl Test2::Workflow(3perl)

NOMBRE

Test2::Workflow - Un flujo de trabajo de prueba es una forma de estructurar pruebas usando unidades componibles.

DESCRIPCIÓN

Un flujo de trabajo de prueba es una forma de estructurar pruebas usando unidades componibles. Un ejemplo bien conocido de flujo de trabajo de prueba es RSPEC http://rspec.info/. RSPEC se implementa utilizando Test2::Workflow en Test2::Tools::Spec junto con varias extensiones.

CONCEPTOS IMPORTANTES

BUILD

Test2::Workflow::Build

Un Build se utiliza para componer tareas. Normalmente, un objeto build se inserta en la pila antes de ejecutar código que añade tareas al build. Una vez que el sub de build se completa, el build se extrae y se devuelve. Normalmente, un build se convierte en una tarea raíz o un grupo de tareas.

RUNNER

Test2::Workflow::Runner

Un runner toma las tareas compuestas y las ejecuta en el orden correcto.

TAREA

Test2::Workflow::Task

Una tarea es una unidad de trabajo a realizar. Hay 2 tipos principales de tarea.

ACCIÓN

Una acción es la unidad más simple utilizada en la composición. Una acción es esencialmente un nombre y un bloque de código para ejecutar.

GRUPO

Un grupo es una tarea compuesta por otras tareas.

EXPORTACIONES

Todas las exportaciones son opcionales, debes solicitar las que necesites.

$parsed = parse_args(args => \@args)
$parsed = parse_args(args => \@args, level => $L)
$parsed = parse_args(args => \@args, caller => [caller($L)])
Esto analizará los argumentos de un constructor de tareas "típico". El array @args DEBE contener un nombre (escalar plano que contiene texto) y también una única referencia de código. El array @args PUEDE contener también cualquier cantidad de números de línea o hashrefs. La estructura de datos resultante será un único hashref con todos los hashrefs proporcionados combinados, y las claves 'name', 'code', 'lines' y 'frame' establecidas a partir de otros argumentos. 
{
    # Todos los hashrefs de @args se combinan:
    %datos_hashref_entrada_combinados,
    # @args debe tener exactamente 1 escalar plano que no sea un número, se
    # considera el nombre:
    name => 'nombre de los argumentos de entrada'
    # Los valores enteros se tratan como números de línea
    lines => [ 35, 44 ],
    # Se debe proporcionar exactamente 1 coderef en @args:
    code => \&some_code,
    # 'frame' contiene los datos de 'caller'. Esto puede pasarse directamente,
    # obtenerse del parámetro 'level', o deducirse automáticamente.
    frame => ['A::Package', 'a_file.pm', 42, ...],
}
$build = init_root($pkg, %args)
Esto inicializará (o devolverá el existente) un build para el paquete especificado. %args se pasan al constructor de Test2::Workflow::Build. Esto utiliza los siguientes valores predeterminados (que se pueden sobrescribir usando %args): 
name    => $pkg,
flat    => 1,
iso     => 0,
async   => 0,
is_root => 1,

Tenga en cuenta que %args se ignora completamente si el build del paquete ya ha sido inicializado.

$build = root_build($pkg)
Esto devolverá el build raíz para el paquete especificado.
$build = current_build()
Esto devolverá el build actualmente en la cima de la pila de builds (o undef).
$build = build($name, \%params, sub { ... })
Esto insertará un nuevo objeto build en el stash de builds y luego ejecutará el bloque de código proporcionado. Una vez que el bloque de código haya terminado de ejecutarse, el build se extraerá de la pila y se devolverá.

Ver parse_args() para más detalles sobre el procesamiento de argumentos.
