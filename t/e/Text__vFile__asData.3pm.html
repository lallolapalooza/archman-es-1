NOMBRE

Text::vFile::asData - analizar archivos con formato vFile en estructuras de datos

SINOPSIS

use Text::vFile::asData;
open my $fh, "foo.ics"
  or die "no se pudo abrir ics: $!";
my $data = Text::vFile::asData->new->parse( $fh );

DESCRIPCIÓN

Text::vFile::asData lee archivos en formato vFile, como vCard (RFC 2426) y vCalendar (RFC 2445).

ESTRUCTURA DE DATOS

Un vFile contiene uno o más objetos, delimitados por etiquetas BEGIN y END.

BEGIN:VCARD
...
END:VCARD

Los objetos pueden contener sub-objetos;

BEGIN:VCALENDAR
...
BEGIN:VEVENT
...
END:VEVENT
...
ENV:VCALENDAR

Cada objeto consta de una o más propiedades. Cada propiedad consta de un nombre, cero o más parámetros opcionales y luego un valor. Este fragmento:

DTSTART;VALUE=DATE:19970317

identifica una propiedad con el nombre "DSTART", el parámetro "VALUE", que tiene el valor "DATE", y el valor de la propiedad es 19970317. Aquellos de ustedes con una inclinación XML podrían encontrar esto más reconocible como:

<dtstart value="date">19970317</dtstart>

El valor de retorno del método parse() es una referencia a hash.

La clave de nivel superior, "objects", se refiere a una referencia a arreglo. Cada entrada en la referencia a arreglo es una referencia a hash con dos o tres claves.

El valor de la primera clave, "type", es una cadena que corresponde al tipo del objeto. Por ejemplo, "VCARD", "VEVENT", y así sucesivamente.

El valor de la segunda clave, "properties", es una referencia a hash, con nombres de propiedad como claves y una referencia a arreglo de esos valores de propiedad. Es una referencia a arreglo, porque algunas propiedades pueden aparecer dentro de un objeto varias veces con diferentes valores. Por ejemplo;

BEGIN:VEVENT
ATTENDEE;CN="Nik Clayton":mailto:nik@FreeBSD.org
ATTENDEE;CN="Richard Clamp":mailto:richardc@unixbeard.net
...
END:VEVENT

Cada entrada en la referencia a arreglo es una referencia a hash con una o dos claves.

La primera clave, "value", corresponde al valor de la propiedad.

La segunda clave, "param", contiene una referencia a hash de los parámetros de la propiedad. Las claves en esta referencia a hash son el nombre del parámetro, el valor es el valor del parámetro. (Si habilita la opción "preserve_params", hay una clave adicional poblada, llamada "params". Es una referencia a arreglo de referencias a hash, cada referencia a hash es el nombre del parámetro y el valor del parámetro, estos se recopilan en el orden en que se encuentran para evitar colisiones de hash como se ve en algunas líneas de archivo vCard) .

La tercera clave en la referencia a hash de nivel superior "objects" es "objects". Si existe, indica que se encontraron sub-objetos. El valor de esta clave es una referencia a arreglo de sub-objetos, con claves y comportamiento idénticos a los de la clave "objects" de nivel superior. Esta estructura recursiva continúa, anidándose tan profundamente como había sub-objetos en el archivo de entrada.

El script "bin/v2yaml" que viene con esta distribución muestra el formato de un vFile como YAML. "t/03usage.t" tiene ejemplos de cómo extraer la información relevante de la estructura de datos.
