Test2::Transition(3perl) Guía de referencia para programadores de Perl Test2::Transition(3perl)

NOMBRE

Test2::Transition - Notas de transición al actualizar a Test2

DESCRIPCIÓN

Aquí se documentan las dificultades y roturas relacionadas con la actualización de Test2. La actualización hace que Test::Builder delegue en Test2 internamente. Esta transición es en su mayoría transparente, pero hay algunos casos que pueden causar problemas.

COSAS QUE SE ROMPEN

Esta es la lista de escenarios que se rompen con la nueva implementación interna.

Condicionales de Test::Builder1.5/2

El problema

Hace unos años hubo dos intentos de actualizar/reemplazar Test::Builder. Confusamente, estos se llamaron Test::Builder2 y Test::Builder1.5, en ese orden. Muchas personas incluyeron condicionales en su código para verificar el número de versión de Test::Builder y adaptar su código en consecuencia.

Los proyectos Test::Builder2/1.5 fracasaron. Ahora el código condicional que la gente agregó se ha convertido en un campo minado. La gran mayoría de los módulos rotos por Test2 caen en esta categoría.

La solución

La solución es eliminar todo el código relacionado con Test::Builder1.5/2. Usa la API heredada de Test::Builder o usa Test2 directamente.

Reemplazo del singleton de Test::Builder

El problema

Algunos módulos de prueba reemplazaban la instancia singleton de Test::Builder con su propia instancia o subclase. Esto se hacía generalmente para interceptar o modificar los resultados a medida que ocurrían.

El singleton de Test::Builder es ahora un simple envoltorio de compatibilidad para Test2. El singleton de Test::Builder ya no es el lugar central para los resultados. Muchos resultados evitan por completo el singleton de Test::Builder, lo que rompe cualquier comportamiento que se pretendía al reemplazar el singleton.

La solución

Si solo deseas interceptar todos los resultados en lugar de enviarlos a TAP, deberías consultar la documentación de Test2::API y leer sobre cómo insertar un nuevo hub en la pila de hubs. Reemplazar el hub temporalmente es ahora la forma correcta de interceptar resultados.

Si tu objetivo es puramente la monitorización de eventos, usa el método "Test2::Hub->listen()" exportado por Test::More para observar los eventos a medida que se disparan. Si deseas modificar los resultados antes de que se envíen a TAP, consulta el método "Test2::Hub->filter()".

Acceso directo a elementos de hash

El problema

Algunos módulos miran directamente las claves hash en el singleton de Test::Builder. El problema aquí es que el singleton de Test::Builder ya no contiene nada importante.

La solución

La solución es usar la API especificada en Test2::API para mirar o modificar el estado según sea necesario.

Indentación de subpruebas

El problema

Un cambio temprano, de hecho el cambio que hizo de Test2 una idea, fue un cambio en la indentación de la nota de subprueba. Se decidió que sería más legible sacar la nota de la subprueba en lugar de tenerla en línea con la subprueba:

# subtest foo
    ok 1 - blah
    1..1
ok 1 - subtest foo

El estilo antiguo indentaba la nota:

    # subtest foo
    ok 1 - blah
    1..1
ok 1 - subtest foo

Esto rompe las pruebas que realizan comparaciones de cadenas de la salida TAP.

La solución

my $indent = $INC{'Test2/API.pm'} ? '' : '    ';
is(
    $subtest_output,
    "${indent}# subtest foo",
    "Got subtest note"
);

Comprueba si $INC{'Test2/API.pm'} está establecido; si lo está, no se debe esperar indentación. Si no está establecido, entonces se está usando el antiguo Test::Builder y se debe esperar indentación.

TEST::BUILDER INTERNALS AND TEST2

This document is a guide for developers of test modules who want to ensure compatibility with both Test::Builder and Test2.

INTRODUCTION

Test::Builder has been around for a long time. It is a decent testing framework, but it has some design flaws that make it difficult to work with. Test2 is a new testing framework that aims to fix these flaws.

This document is for authors of testing modules. It is not a user guide.

THE PROBLEM WITH TEST::BUILDER

Test::Builder is a singleton. This means that there is only one instance of Test::Builder in a running Perl program. This is a problem for testing modules, because it makes it difficult to test them in isolation. It also makes it difficult to use multiple testing modules at the same time.

Test::Builder also has a number of internal methods that are not documented and should not be used. These methods are subject to change without notice, and can break your testing modules.

Finally, Test::Builder does not have good support for UTF-8. This can lead to problems when testing modules that use UTF-8 characters.

TEST2 THE SOLUTION

Test2 is a new testing framework that aims to fix the problems with Test::Builder. It is designed to be more flexible and easier to work with.

Test2 is not a singleton. It uses a context object to manage testing state. This makes it easier to test modules in isolation, and to use multiple testing modules at the same time.

Test2 also has a well-defined API. This means that its methods are less likely to change, and that you can rely on them to work.

Finally, Test2 has good support for UTF-8. This makes it easier to test modules that use UTF-8 characters.

MAKE ASSERTIONS -> SEND EVENTS

LEGACY

use Test::Builder;
# A majority of tools out there do this:
# my $TB = Test::Builder->new;
# This works, but has always been wrong, forcing Test::Builder to implement
# subtests as a horrific hack. It also causes problems for tools that try
# to replace the singleton (also discouraged).
sub my_ok($;$) {
    my ($bool, $name) = @_;
    my $TB = Test::Builder->new;
    $TB->ok($bool, $name);
}
sub my_diag($) {
    my ($msg) = @_;
    my $TB = Test::Builder->new;
    $TB->diag($msg);
}

TEST2

use Test2::API qw/context/;
sub my_ok($;$) {
    my ($bool, $name) = @_;
    my $ctx = context();
    $ctx->ok($bool, $name);
    $ctx->release;
}
sub my_diag($) {
    my ($msg) = @_;
    my $ctx = context();
    $ctx->diag($msg);
    $ctx->release;
}

The context object has API compatible implementations of the following methods:

ok($bool, $name)
diag(@messages)
note(@messages)
subtest($name, $code)

If you are looking for helpers with "is", "like", and others, see Test2::Suite.

WRAP EXISTING TOOLS

LEGACY

use Test::More;
sub exclusive_ok {
    my ($bool1, $bool2, $name) = @_;
    # Ensure errors are reported 1 level higher
    local $Test::Builder::Level = $Test::Builder::Level + 1;
    $ok = $bool1 || $bool2;
    $ok &&= !($bool1 && $bool2);
    ok($ok, $name);
    return $bool;
}

Every single tool in the chain from this, to "ok", to anything "ok" calls needs to increment the $Level variable. When an error occurs Test::Builder will do a trace to the stack frame determined by $Level, and report that file+line as the one where the error occurred. If you or any other tool you use forgets to set $Level then errors will be reported to the wrong place.

TEST2

use Test::More;
sub exclusive_ok {
    my ($bool1, $bool2, $name) = @_;
    # Grab and store the context, even if you do not need to use it
    # directly.
    my $ctx = context();
    $ok = $bool1 || $bool2;
    $ok &&= !($bool1 && $bool2);
    ok($ok, $name);
    $ctx->release;
    return $bool;
}

Instead of using $Level to perform a backtrace, Test2 uses a context object. In this sample you create a context object and store it. This locks the context (errors report 1 level up from here) for all wrapped tools to find. You do not need to use the context object, but you do need to store it in a variable. Once the sub ends the $ctx variable is destroyed which lets future tools find their own.

USING UTF8

LEGACY

# Set the mode BEFORE anything loads Test::Builder
use open ':std', ':encoding(utf8)';
use Test::More;

Or

# Modify the filehandles
my $builder = Test::More->builder;
binmode $builder->output,         ":encoding(utf8)";
binmode $builder->failure_output, ":encoding(utf8)";
binmode $builder->todo_output,    ":encoding(utf8)";

TEST2

use Test2::API qw/test2_stack/;
test2_stack->top->format->encoding('utf8');

Though a much better way is to use the Test2::Plugin::UTF8 plugin, which is part of Test2::Suite.
