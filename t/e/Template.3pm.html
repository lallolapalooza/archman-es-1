NOMBRE

Template - Módulo frontal para el Template Toolkit

SINOPSIS

use Template;
# algunas opciones útiles (ver más abajo para la lista completa)
my $config = {
    INCLUDE_PATH => '/ruta/de/búsqueda',  # o una referencia de lista
    INTERPOLATE  => 1,               # expandir "$var" en texto plano
    POST_CHOMP   => 1,               # limpiar espacios en blanco
    PRE_PROCESS  => 'header',        # prefijar cada plantilla
    EVAL_PERL    => 1,               # evaluar bloques de código Perl
};
# crear objeto Template
my $template = Template->new($config);
# definir variables de plantilla para sustitución
my $vars = {
    var1  => $valor,
    var2  => \%hash,
    var3  => \@list,
    var4  => \&code,
    var5  => $object,
};
# especificar nombre de archivo de entrada, o manejador de archivo, referencia de texto, etc.
my $input = 'myfile.html';
# procesar plantilla de entrada, sustituyendo variables
$template->process($input, $vars)
    || die $template->error();

DESCRIPCIÓN

Esta documentación describe el módulo Template, que es la interfaz Perl directa al Template Toolkit. Cubre el uso del módulo y proporciona un breve resumen de las opciones de configuración y las directivas de plantilla. Consulte Template::Manual para obtener el manual de referencia completo, que entra en mucho mayor detalle sobre las características y el uso del Template Toolkit. Template::Tutorial también está disponible como una guía introductoria para usar el Template Toolkit.

MÉTODOS

new(\%config)

El método constructor new() (implementado por la clase base Template::Base) instancia un nuevo objeto "Template". Se puede pasar una referencia a un array hash de elementos de configuración como parámetro.

my $tt = Template->new({
    INCLUDE_PATH => '/usr/local/templates',
    EVAL_PERL    => 1,
}) || die $Template::ERROR, "\n";

Se devuelve una referencia a un nuevo objeto "Template", o undef en caso de error. En este último caso, el mensaje de error se puede recuperar llamando a error() como método de clase o examinando directamente la variable del paquete $Template::ERROR.

my $tt = Template->new(\%config)
    || die Template->error(), "\n";
my $tt = Template->new(\%config)
    || die $Template::ERROR, "\n";

Para mayor comodidad, los elementos de configuración también se pueden especificar como una lista de elementos en lugar de una referencia a un array hash. Estos se pliegan automáticamente en un array hash por el constructor.

my $tt = Template->new(INCLUDE_PATH => '/tmp', POST_CHOMP => 1)
    || die $Template::ERROR, "\n";

process($template, \%vars, $output, %options)

Se llama al método process() para procesar una plantilla. El primer parámetro indica la plantilla de entrada como uno de los siguientes:

  • un nombre de archivo relativo a "INCLUDE_PATH", si está definido
  • una referencia a una cadena de texto que contiene el texto de la plantilla
  • una referencia a un manejador de archivo (por ejemplo, "IO::Handle" o una subclase) o "GLOB" (por ejemplo, "\*STDIN"), desde el cual se puede leer la plantilla.

Se puede pasar una referencia a un array hash como segundo parámetro, que contiene definiciones de variables de plantilla.

# nombre de archivo
$tt->process('welcome.tt2')
    || die $tt->error(), "\n";
# referencia a texto
$text = "[% INCLUDE header %]\nHola mundo!\n[% INCLUDE footer %]";
$tt->process(\$text)
    || die $tt->error(), "\n";
# manejador de archivo (GLOB)
$tt->process(\*DATA)
    || die $tt->error(), "\n";
__END__
[% INCLUDE header %]
Esta es una plantilla definida en la sección __END__, a la que
se puede acceder a través del "manejador de archivo" DATA.
[% INCLUDE footer %]

Por defecto, la salida procesada de la plantilla se imprime en "STDOUT". Luego, el método process() devuelve 1 para indicar éxito. Se puede pasar un tercer parámetro al método process() para especificar una ubicación de salida diferente. Este valor puede ser uno de los siguientes:

  • una cadena de texto plano que indica un nombre de archivo que se abrirá (relativo a "OUTPUT_PATH", si está definido) y se escribirá la salida
  • un GLOB de archivo abierto listo para la salida
  • una referencia a un escalar (por ejemplo, una cadena de texto) al que se agrega la salida/error
  • una referencia a una subrutina que se llama, pasando la salida como un parámetro
  • cualquier referencia de objeto que implemente un método print() (por ejemplo, "IO::Handle", "Apache::Request", etc.) al que se llamará, pasando la salida generada como un parámetro.

Ejemplos:

# nombre de archivo de salida
$tt->process('welcome.tt2', $vars, 'welcome.html')
    || die $tt->error(), "\n";
# referencia a subrutina de salida
sub myout {
    my $output = shift;
    ...
}
$tt->process('welcome.tt2', $vars, \&myout)
    || die $tt->error(), "\n";
# referencia a cadena de texto de salida
my $output = '';
$tt->process('welcome.tt2', $vars, \$output)
    || die $tt->error(), "\n";
print "salida: $output\n";

En un manejador Apache/mod_perl:

sub handler {
    my $req = shift;
    # ...tu código aquí...
    # dirigir salida a Apache::Request a través de $req->print($output)
    $tt->process($file, $vars, $req) || do {
        $req->log_reason($tt->error());
        return SERVER_ERROR;
    };
    return OK;
}

Después del argumento opcional de salida tercero pueden venir una referencia opcional a un hash o una lista de pares "(nombre, valor)" que proporcionan opciones adicionales para la salida. La única opción admitida actualmente es "binmode" que, cuando se establece en cualquier valor verdadero, garantizará que los archivos creados (pero no los manejadores de archivo existentes pasados) se establecerán en modo binario.

# ya sea: referencia a hash de opciones
$tt->process($infile, $vars, $outfile, { binmode => 1 })
    || die $tt->error(), "\n";
# o: lista de pares nombre, valor
$tt->process($infile, $vars, $outfile, binmode => 1)
    || die $tt->error(), "\n";

Alternativamente, el argumento "binmode" puede especificar una capa de IO particular, como ":utf8".

$tt->process($infile, $vars, $outfile, binmode => ':utf8')
    || die $tt->error(), "\n";

El elemento de configuración "OUTPUT" se puede usar para especificar una ubicación de salida predeterminada distinta de "\*STDOUT". "OUTPUT_PATH" especifica un directorio que debe prefijarse a todas las ubicaciones de salida especificadas como nombres de archivo.

my $tt = Template->new({
    OUTPUT      => sub { ... },       # predeterminado
    OUTPUT_PATH => '/tmp',
...
}) || die Template->error(), "\n";
# usar OUTPUT predeterminado (se llama a la subrutina)
$tt->process('welcome.tt2', $vars)
    || die $tt->error(), "\n";
# escribir archivo en '/tmp/welcome.html'
$tt->process('welcome.tt2', $vars, 'welcome.html')
    || die $tt->error(), "\n";

El método process() devuelve 1 en caso de éxito o "undef" en caso de error. El mensaje de error generado en este último caso se puede recuperar llamando al método error(). Consulte también "RESUMEN DE CONFIGURACIÓN", que describe cómo se puede personalizar aún más el manejo de errores.

error()

Cuando se llama como método de clase, devuelve el valor de la variable del paquete $ERROR. Por lo tanto, lo siguiente es equivalente.

my $tt = Template->new()
    || die Template->error(), "\n";
my $tt = Template->new()
    || die $Template::ERROR, "\n";

Cuando se llama como método de objeto, devuelve el valor de la variable interna "_ERROR", tal como la establece una condición de error en una llamada anterior a process().

$tt->process('welcome.tt2')
    || die $tt->error(), "\n";

service()

El módulo "Template" delega la mayor parte del esfuerzo de procesamiento de las plantillas a un objeto subyacente de Template::Service. Este método devuelve una referencia a dicho objeto.

context()

El módulo Template::Service utiliza un objeto central Template::Context para el procesamiento en tiempo de ejecución de las plantillas. Este método devuelve una referencia a dicho objeto y es equivalente a "$template->service->context()".

template($name)

Este método es un simple envoltorio del método Template::Context del mismo nombre. Devuelve una plantilla compilada para la fuente proporcionada como argumento.

RESUMEN DE CONFIGURACIÓN

La siguiente lista ofrece un breve resumen de cada opción de configuración de Template Toolkit. Consulte Template::Manual::Config para obtener detalles completos.

Opciones de Estilo y Análisis de Plantillas

ENCODING

Especifica la codificación de caracteres.

START_TAG, END_TAG

Define los tokens que indican el inicio y el fin de las directivas (por defecto: '"[%"' y '"%]"').

TAG_STYLE

Establece "START_TAG" y "END_TAG" según un estilo predefinido (por defecto: '"template"', como se menciona anteriormente).

PRE_CHOMP, POST_CHOMP

Elimina los espacios en blanco antes/después de las directivas (por defecto: 0/0).

TRIM

Elimina los espacios en blanco iniciales y finales de la salida de la plantilla (por defecto: 0).

INTERPOLATE

Interpola variables incrustadas como $this o "${this}" (por defecto: 0).

ANYCASE

Permite palabras clave de directivas en minúsculas (por defecto: 0 - solo MAYÚSCULAS).

Archivos y Bloques de Plantillas

INCLUDE_PATH

Uno o más directorios para buscar plantillas.

DELIMITER

Delimitador para separar rutas en "INCLUDE_PATH" (por defecto: '":"').

ABSOLUTE

Permite nombres de archivo absolutos, por ejemplo "/foo/bar.html" (por defecto: 0).

RELATIVE

Permite nombres de archivo relativos, por ejemplo "../foo/bar.html" (por defecto: 0).

DEFAULT

Plantilla por defecto a usar cuando no se encuentra otra.

BLOCKS

Array hash que predefine bloques de plantilla.

AUTO_RESET

Habilitado por defecto, haciendo que las definiciones de "BLOCK" se reinicien cada vez que se procesa una plantilla. Deshabilítelo para permitir que las definiciones de "BLOCK" persistan.

RECURSION

Indicador para permitir la recursión en plantillas (por defecto: 0).

Variables de Plantilla

VARIABLES

Array hash de variables y valores para predefinir en el stash.

Opciones de Procesamiento en Tiempo de Ejecución

EVAL_PERL

Indicador para determinar si los bloques "PERL"/"RAWPERL" deben procesarse (por defecto: 0).

PRE_PROCESS, POST_PROCESS

Nombre de la plantilla(s) a procesar antes/después de la plantilla principal.

PROCESS

Nombre de la plantilla(s) a procesar en lugar de la plantilla principal.

ERROR

Nombre de la plantilla de error o referencia a un array hash que mapea tipos de error a plantillas.

OUTPUT

Ubicación o manejador de salida por defecto.

OUTPUT_PATH

Directorio en el que se pueden escribir los archivos de salida.

DEBUG

Habilita mensajes de depuración.

Opciones de Caché y Compilación

CACHE_SIZE

Número máximo de plantillas compiladas para almacenar en caché en memoria (por defecto: undef - caché todo)

COMPILE_EXT

Extensión de nombre de archivo para archivos de plantillas compiladas (por defecto: undef - no compilar).

COMPILE_DIR

Directorio raíz en el que se deben escribir los archivos de plantillas compiladas (por defecto: undef - no compilar).

Plugins y Filtros

PLUGINS

Referencia a un array hash que mapea nombres de plugin a paquetes de Perl.

PLUGIN_BASE

Una o más clases base bajo las cuales se pueden encontrar los plugins.

LOAD_PERL

Indicador para determinar si los módulos Perl normales deben cargarse si no se encuentra un plugin con nombre (por defecto: 0).

FILTERS

Array hash que mapea nombres de filtro a subrutinas o fábricas de filtros.

Personalización y Extensión

LOAD_TEMPLATES

Lista de proveedores de plantillas.

LOAD_PLUGINS

Lista de proveedores de plugins.

LOAD_FILTERS

Lista de proveedores de filtros.

TOLERANT

Establece proveedores para que toleren errores como declinaciones (por defecto: 0).

SERVICE

Referencia a un objeto de servicio personalizado (por defecto: Template::Service).

CONTEXT

Referencia a un objeto de contexto personalizado (por defecto: Template::Context).

STASH

Referencia a un objeto stash personalizado (por defecto: Template::Stash).

PARSER

Referencia a un objeto parser personalizado (por defecto: Template::Parser).

GRAMMAR

Referencia a un objeto grammar personalizado (por defecto: Template::Grammar).

RESUMEN DE DIRECTIVAS

La siguiente lista ofrece un breve resumen de cada directiva de Template Toolkit. Consulte Template::Manual::Directives para obtener detalles completos.

GET

Evalúa e imprime una variable o valor.

[%   GET variable %]    # la palabra clave 'GET' es opcional
[%       variable %]
[%       hash.key %]
[%         list.n %]
[%     code(args) %]
[% obj.meth(args) %]
[%  "valor: $var" %]

CALL

Como GET pero sin imprimir el resultado (p. ej., llamar a código)

[%  CALL variable %]

SET

Asigna valores a variables.

[% SET variable = valor %]    # 'SET' también es opcional
[%     variable = otra_variable
       variable = 'texto literal @ $100'
       variable = "texto interpolado: $var"
       list     = [ val, val, val, val, ... ]
       list     = [ val..val ]
       hash     = { var => val, var => val, ... }
%]

DEFAULT

Similar a SET, pero las variables solo se establecen si no están actualmente definidas (es decir, no tienen un valor verdadero).

[% DEFAULT variable = valor %]

INSERT

Inserta un archivo sin realizar ningún procesamiento sobre el contenido.

[% INSERT legalese.txt %]

PROCESS

Procesa otro archivo de plantilla o bloque e inserta la salida generada. Cualquier BLOQUE de plantilla o variable definido o actualizado en la plantilla "PROCESS"ada estará en adelante definido en la plantilla que llama.

[% PROCESS plantilla %]
[% PROCESS plantilla  var = val, ... %]

INCLUDE

Similar a "PROCESS", pero usando una copia local de las variables actuales. Cualquier BLOQUE de plantilla o variable definida en la plantilla "INCLUDE"ada permanece local a ella.

[% INCLUDE plantilla %]
[% INCLUDE plantilla  var = val, ... %]

WRAPPER

El contenido entre las directivas "WRAPPER" y "END" correspondiente se evalúa primero, y la salida generada se almacena en la variable "content". Luego, la plantilla con nombre se procesa según "INCLUDE".

[% WRAPPER layout %]
   Marcado de plantilla [% blah %]...
[% END %]

Una plantilla de *layout* simple podría parecerse a esto:

Tu encabezado aquí...
[% content %]
Tu pie de página aquí...

NAME

Template::Toolkit - A flexible, powerful, object-oriented template processing system

SYNOPSIS

  use Template::Toolkit;

  # create a template processor object
  my $template = Template::Toolkit->new( {
      INCLUDE_PATH => 'templates', # directory to search for template files
      COMPILE_DIR  => 'compiled',  # directory to cache compiled templates
      INTERPOLATE  => 1,           # interpolate variables (e.g., $foo)
  } );

  # define some template variables
  my $vars = {
      name    => 'World',
      items   => [ 'apple', 'banana', 'cherry' ],
      hash    => { title => 'My Page' },
  };

  # process a template file
  $template->process( 'file.tt', $vars, \my $output );

  # or process a string template
  $template->process( 'Hello [% name %]!', $vars, \my $output );

  # print the output
  print $output;

DESCRIPTION

The Template Toolkit is a mature, feature-rich, object-oriented template processing system written in Perl. It is designed to allow content designers and web developers to easily generate dynamic text-based documents such as HTML, XML, email, SQL, configuration files, etc.

The system processes template files which contain a mix of static text and template directives. These directives are used to control the flow of execution, retrieve and display dynamic data, and manipulate the content. The template engine parses the template, compiles it into an internal representation, and then evaluates it against a set of runtime variables (often referred to as the "stash").

Key features include:

  • Powerful and flexible templating language with support for variables, lists, hashes, control structures (if, unless, while, for-each), macros, substitution, substitution, etc.
  • Object-oriented design allowing for customisation and extension.
  • Extensible plugin interface for loading external modules (e.g., database access, internationalization, configuration) directly from within templates.
  • Template caching for improved performance. Templates can be compiled and cached to disk, avoiding the need for re-parsing and re-compilation on subsequent requests.
  • Support for multiple template directories, allowing templates to be distributed across various locations.
  • Variable interpolation for embedding variable values directly into template text.
  • "Hidden" variables which are not automatically interpolated.
  • Loadable filters for transforming text content (e.g., html, xml, html_entity, indent, trim).
  • User-defined directives and custom template handlers.
  • Perl code evaluation for embedding small Perl snippets directly within templates (requires the "EVAL_PERL" configuration option).
  • Built-in exception handling mechanism (try/catch/finally).
  • Support for Unicode.

METHODS

new(\%config)
Constructor. Creates and returns a new Template::Toolkit object. The \%config hash reference accepts the following configuration options:
COMPILE_DIR
Path to directory for caching compiled template files. If specified, the template will be compiled and the compiled code will be saved to a file in this directory. Subsequent accesses to the template will load the compiled code directly from the file, thus avoiding the overhead of parsing and compiling.
DEBUG
If set to true (1), detailed debugging information will be printed to STDERR during template processing. Default is false (0).
DEFAULT_PLUGIN_OPTIONS
Hash reference containing default options to be passed to all plugins loaded via the USE directive. Example: { AUTO_CREATE => 1 }
EVAL_PERL
If set to true (1), blocks delimited by PERL and END or RAWPERL and END directives will be evaluated as Perl code. Default is false (0).
FILTER_DIR
Path to directory for loading custom filter modules. Default is "Template::Filter".
INTERPOLATE
If set to true (1), variables written as $var or [% var %] will be interpolated into the template output. Default is true (1).
INCLUDE_PATH
A string or array reference specifying one or more directories to search for template files (e.g., via the INCLUDE, PROCESS and WRAPPER directives). If it's an array reference, the directories are searched in order. If it's a string, it's treated as a single directory.
LOAD_PERL
If set to true (1), the USE directive can be used to load any regular Perl module, not just those prefixed with "Template::". Default is false (0).
OUTPUT
A reference to a file handle or an object supporting the print() method, which will be used for output when the target for the process() method is not provided. Default is STDOUT.
PLUGIN_DIR
Path to directory for loading custom plugin modules. Default is "Template::Plugin".
PREPEND_PATH
Similar to INCLUDE_PATH, but the paths are prepended to the list of directories searched. Useful for overriding templates in a system-wide directory with project- specific ones.
STASH_DEBUG
If set to true (1), variable lookups and modifications will be logged to STDERR. Default is false (0).
STRICT
If set to true (1), attempts to access undefined variables or hash keys will generate a runtime error instead of silently returning an empty string. Default is false (0).
TAGS
An array reference defining the opening and closing tag sequences used to delimit template directives. The default is [ '[%', '%]' ]. You can change this to use different delimiters, e.g., [ '<%','%>' ] for ASP-style tags, or [ '<!--','-->' ] for HTML comment-style tags.
TEMPLATE_DIR
Deprecated synonym for INCLUDE_PATH.
THROWABLE_STATES
An array reference specifying the exception types that should be caught by the CATCH directive. Any exceptions thrown (via the THROW directive) that match one of these types (or the generic DEFAULT type) will be caught. Default is [ 'DEFAULT' ].
WHITESPACE
Controls how whitespace is handled within the template. Can be set to 'none', 'preserve', 'smart' (default), or a number representing the number of spaces to be used for indentation.
process(TEMPLATE, HASH, OUTPUT)
Processes the template specified by TEMPLATE, substituting variables from the HASH, and writing the output to OUTPUT.
TEMPLATE
Can be a string containing the template text, or a file path. If a file path is given, the template will be loaded from the path specified in INCLUDE_PATH.
HASH
A hash reference containing the variables to be used in the template. These variables are added to the template's "stash". If HASH is omitted, no new variables are added, but existing variables in the stash remain available.
OUTPUT
A reference to a file handle or an object supporting the print() method. If omitted, the output target defined by the OUTPUT configuration option (default STDOUT) is used.
Returns 1 on success, or 0 on failure. Errors are reported via $template->error().
error()
Returns the last error message generated during template processing, or an empty string if no error occurred.
errorcode()
Returns the last error code generated during template processing, or undef if no error occurred.
stack()
Returns a list of error messages representing the call stack at the time of the last error.
define_block(NAME, BLOCK)
Defines a named template block which can be invoked using the INCLUDE, PROCESS, or WRAPPER directives. NAME is the name of the block (e.g., 'header') and BLOCK is a string containing the template code for the block.
define_macro(NAME, MACRO)
Defines a named macro which can be invoked using its name and optional arguments. NAME is the macro name (e.g., 'link') and MACRO is a string containing the macro definition.

DIRECTIVE SUMMARY

The following directives are recognised by the Template Toolkit:

BLOCK

Define a named template block for INCLUDE, PROCESS and WRAPPER to use.

[% BLOCK hello %]
   Hello World
[% END %]
[% INCLUDE hello %]

FOREACH

Repeat the enclosed "FOREACH" ... "END" block for each value in the list.

[% FOREACH variable IN [ val, val, val ] %]    # either
[% FOREACH variable IN list %]                 # or
   The variable is set to [% variable %]
[% END %]

WHILE

The block enclosed between "WHILE" and "END" block is processed while the specified condition is true.

[% WHILE condition %]
   content
[% END %]

IF / UNLESS / ELSIF / ELSE

The enclosed block is processed if the condition is true / false.

[% IF condition %]
   content
[% ELSIF condition %]
 content
[% ELSE %]
 content
[% END %]
[% UNLESS condition %]
   content
[% # ELSIF/ELSE as per IF, above %]
   content
[% END %]

SWITCH / CASE

Multi-way switch/case statement.

[% SWITCH variable %]
[%   CASE val1 %]
       content
[%   CASE [ val2, val3 ] %]
       content
[%   CASE %]         # or [% CASE DEFAULT %]
       content
[% END %]

MACRO

Define a named macro.

[% MACRO name <directive> %]
[% MACRO name(arg1, arg2) <directive> %]
...
[% name %]
[% name(val1, val2) %]

FILTER

Process enclosed "FILTER" ... "END" block then pipe through a filter.

[% FILTER name %]                       # either
[% FILTER name( params ) %]             # or
[% FILTER alias = name( params ) %]     # or
   content
[% END %]

USE

Load a plugin module (see "Template::Manual::Plugins"), or any regular Perl module when the "LOAD_PERL" option is set.

[% USE name %]                      # either
[% USE name( params ) %]            # or
[% USE var = name( params ) %]      # or
...
[% name.method %]
[% var.method %]

PERL / RAWPERL

Evaluate enclosed blocks as Perl code (requires the "EVAL_PERL" option to be set).

[% PERL %]
 # perl code goes here
 $stash->set('foo', 10);
 print "set 'foo' to ", $stash->get('foo'), "\n";
 print $context->include('footer', { var => $val });
[% END %]
[% RAWPERL %]
   # raw perl code goes here, no magic but fast.
   $output .= 'some output';
[% END %]

TRY / THROW / CATCH / FINAL

Exception handling.

[% TRY %]
 content
   [% THROW type info %]
[% CATCH type %]
 catch content
   [% error.type %] [% error.info %]
[% CATCH %] # or [% CATCH DEFAULT %]
 content
[% FINAL %]
   this block is always processed
[% END %]

NEXT

Jump straight to the next item in a "FOREACH" or "WHILE" loop.

[% NEXT %]

LAST

Break out of "FOREACH" or "WHILE" loop.

[% LAST %]

RETURN

Stop processing current template and return to including templates.

[% RETURN %]

STOP

Stop processing all templates and return to caller.

[% STOP %]

TAGS

Define new tag style or characters (default: "[%" "%]").

[% TAGS html %]
[% TAGS <!-- --> %]

COMMENTS

Ignored and deleted.

[% # this is a comment to the end of line
   foo = 'bar'
%]
[%# placing the '#' immediately inside the directive
    tag comments out the entire directive
%]
