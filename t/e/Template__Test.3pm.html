NOMBRE

Template::Test - Módulo para automatizar scripts de prueba de TT2

SINOPSIS

use Template::Test;
$Template::Test::DEBUG = 0;   # establezca esto en verdadero para ver cada prueba ejecutándose
$Template::Test::EXTRA = 2;   # 2 pruebas adicionales siguen a test_expect()...
# ok() se puede llamar cualquier número de veces antes de test_expect
ok( $verdadero_o_falso )
# test_expect() divide $input en pruebas individuales, procesa cada una
# y compara la salida generada contra la salida esperada
test_expect($input, $template, \%reemplazo );
# $input es texto o manejador de archivo (ej. sección DATA después de __END__)
test_expect( $texto );
test_expect( \*DATA );
# $template es un objeto Template o una configuración hash
my $template_cfg = { ... };
test_expect( $input, $template_cfg );
my $template_obj = Template->new($template_cfg);
test_expect( $input, $template_obj );
# $reemplazo es una referencia hash de variables de plantilla
my $reemplazo = {
    a => 'alfa',
    b => 'bravo'
};
test_expect( $input, $template, $reemplazo );
# ok() llamado después de test_expect debería declararse en $EXTRA (2)
ok( $verdadero_o_falso )
ok( $verdadero_o_falso )

DESCRIPCIÓN

El módulo "Template::Test" define las subrutinas test_expect() y otras relacionadas que se pueden usar para automatizar scripts de prueba para Template Toolkit. Vea las numerosas pruebas en el subdirectorio t de la distribución para ejemplos de uso.

SUBRUTINAS DE PAQUETE

test_expect()

La subrutina test_expect() divide un documento de entrada en un número de pruebas separadas, procesa cada una usando Template Toolkit y luego compara la salida generada contra una salida esperada, también especificada en el documento de entrada. Genera la familiar salida "ok"/"not ok" compatible con "Test::Harness".

La entrada de prueba debe especificarse como una cadena de texto o una referencia a un manejador de archivo (ej. "GLOB" o "IO::Handle") desde el cual se puede leer. En particular, esto permite que la entrada de prueba se coloque después del marcador "__END__" y se lea a través del manejador de archivo "DATA".

use Template::Test;
test_expect(\*DATA);
__END__
# esta es la primera prueba (esto es un comentario)
-- test --
blah blah blah [% foo %]
-- expect --
blah blah blah valor_de_foo
# aquí está la segunda prueba (sin sorpresa, también lo está esta)
-- test --
más blah blah [% bar %]
-- expect --
más blah blah valor_de_bar

Las líneas en blanco entre las secciones de prueba generalmente se ignoran. Cualquier línea que comience con "#" se trata como un comentario y se ignora.

El segundo y tercer parámetro de test_expect() son opcionales. El segundo puede ser una referencia a un objeto Template que debe usarse para procesar los fragmentos de plantilla, o una referencia a un hash que contenga valores de configuración que deben usarse para instanciar un nuevo objeto Template.

# pasar referencia a hash de configuración
my $config = {
    INCLUDE_PATH => '/aquí/allá:/en/todas partes',
    POST_CHOMP   => 1,
};
test_expect(\*DATA, $config);
# o crear objeto Template explícitamente
my $template = Template->new($config);
test_expect(\*DATA, $template);

El tercer parámetro se puede usar para referenciar un hash de variables de plantilla que deben definirse al procesar las pruebas. Esto se pasa al método process() de Template.

my $reemplazo = {
    a => 'alfa',
    b => 'bravo',
};
test_expect(\*DATA, $config, $reemplazo);

El segundo parámetro puede dejarse indefinido para especificar una configuración de Template por defecto.

test_expect(\*DATA, undef, $reemplazo);

Para probar la salida de diferentes configuraciones de Template, una referencia a una lista de objetos Template nombrados también puede pasarse como segundo parámetro.

my $tt1 = Template->new({ ... });
my $tt2 = Template->new({ ... });
my @tts = [ uno => $tt1, dos => $tt1 ];

El primer objeto de la lista se usa por defecto. Otros objetos pueden cambiarse con un marcador '"-- usar $nombre --"'. Esto debería seguir inmediatamente a una línea '"-- test --"'. Ese objeto se usará para el resto de la prueba, o hasta que se seleccione un objeto diferente.

-- test --
-- usar uno --
[% blah %]
-- expect --
blah, blah
-- test --
todavía usando uno...
-- expect --
...
-- test --
-- usar dos --
[% blah %]
-- expect --
blah, blah, más blah

La subrutina test_expect() cuenta el número de pruebas y luego llama a ntests() para generar la familiar línea de encabezado del framework de pruebas ""1..$ntests\n"". Cada prueba definida genera dos números de prueba. El primero indica que la entrada se procesó sin errores, y el segundo que la salida coincide con la esperada.

Pruebas adicionales pueden ejecutarse antes de test_expect() llamando a ok(). Los resultados de estas pruebas se almacenan en caché hasta que se llama a ntests() y se puede calcular el número final de pruebas. Luego, se genera la línea ""1..$ntests"", junto con líneas ""ok $n"" / ""not ok $n"" para cada resultado de prueba almacenado en caché. Las llamadas posteriores a ok() generan una línea de salida inmediatamente.

my $algo = SomeObject->new();
ok( $algo );
my $otro = AnotherThing->new();
ok( $otro );
test_expect(\*DATA);

Si se van a seguir pruebas después de llamar a test_expect(), estas deben pre-declararse estableciendo la variable de paquete $EXTRA. Este valor (por defecto: 0) se agrega al total general calculado por ntests(). Los resultados de las pruebas adicionales también se registran llamando a ok().

$Template::Test::EXTRA = 2;
# se puede llamar ok() cualquier número de veces antes de test_expect()
ok( $eso_funcionó );
ok( $asegúrate );
ok( $muydepropósito );
# <algún> número de pruebas...
test_expect(\*DATA, $config, $reemplazo);
# aquí están esas $EXTRA pruebas
ok( defined $algún_resultado && ref $algún_resultado eq 'ARRAY' );
ok( $algún_resultado->[0] eq 'algún valor esperado' );

Si no quieres llamar a test_expect() en absoluto, puedes llamar a ntests($n) para declarar el número de pruebas y generar la línea de encabezado de prueba. Después de eso, simplemente llama a ok() para cada prueba pasando un valor verdadero o falso para indicar si la prueba pasó o falló.

ntests(2);
ok(1);
ok(0);

Si eres realmente perezoso, puedes simplemente llamar a ok() y no molestarte en declarar el número de pruebas. Todos los resultados de las pruebas se almacenarán en caché hasta el final del script y luego se imprimirán de una vez antes de que el programa termine.

ok( $x );
ok( $y );

Puedes identificar solo una parte específica del archivo de entrada para probar usando los marcadores '"-- start --"' y '"-- stop --"'. Todo lo que esté antes del primer '"-- start --"' se ignora, junto con todo lo que esté después del siguiente marcador '"-- stop --"'.

-- test --
esta es la prueba 1 (no realizada)
-- expect --
esta es la prueba 1 (no realizada)
-- start --
-- test --
esta es la prueba 2
-- expect --
esta es la prueba 2
-- stop --
...

ntests()

Subrutina utilizada para especificar cuántas pruebas se esperan ejecutar.

ok($prueba)

Genera un mensaje ""ok $n"" o ""not ok $n"" si $prueba es verdadero o falso.

not_ok($prueba)

La inversa lógica de ok(). Imprime un mensaje ""ok $n"" si $prueba es falso y viceversa.

callsign()

Por razones históricas y utilidad general, el módulo también define una subrutina callsign() que devuelve un hash que mapea las letras "a" a "z" a su equivalente en el alfabeto fonético (ej. distintivos de llamada de radio). Esto es utilizado por muchos scripts de prueba como una fuente conocida de variables

Template::Test - Arch Linux Man Pages

NAME

Template::Test - A testing utility for Template Toolkit

SYNOPSIS

    use Template::Test;
    use Template::Context;
    use Template::Provider;

    my $context = Template::Context->new(...);
    my $provider = Template::Provider->new(...);

    # Example 1: Simple test
    test_expect(\*DATA, $context, $provider);

    # Example 2: With specific configuration options
    my $config = {
        INCLUDEPATH => '/path/to/templates',
        ABSOLUTE => 1,
    };
    test_expect(\*DATA, $config);

    # Example 3: Using a different 'call back'
    test_expect(\*DATA, $config, \&my_callback);

    # Example 4: Printing a banner
    banner('Testing something-or-other');

DESCRIPTION

This module provides a simple utility for testing Template Toolkit templates. It automates the process of loading a template, processing it with a given context and configuration, and comparing the output against pre-defined expected results.

The core functionality is provided by the test_expect() subroutine, which takes a template source (typically from a __DATA__ section), a configuration hash (or Template::Context object), and an optional callback subroutine.

The banner() subroutine can be used to print formatted banner messages to the test output, which is particularly useful for grouping related tests.

test_expect()

This is the main subroutine for performing tests. It expects to find a block of text within a __DATA__ section that defines the template, input data, and expected output. The block should be formatted as follows:

__DATA__
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE [...]>
<html>
<head>
  <title>Test Page</title>
</head>
<body>
  <h1>Hello, World!</h1>
  <p>The answer is 42.</p>
</body>
</html>
--
VAR name = "World"
VAR number = 42
--
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE [...]>
<html>
<head>
  <title>Test Page</title>
</head>
<body>
  <h1>Hello, [= name !]!</h1>
  <p>The answer is [= number !].</p>
</body>
</html>

The block is divided into three parts by the -- separator:

  • Template: The first part is the template definition. It can span multiple lines.

  • Input Data: The second part defines the input variables for the template. This is typically a series of variable assignments.

  • Expected Output: The third part is the expected output after the template has been processed with the input data.

The test_expect() subroutine can accept the following arguments:

  • $source: A filehandle or glob reference containing the __DATA__ block (e.g. \*DATA).

  • $config: Either a Template::Context object, a Template::Provider object, or a hash reference containing configuration options for the Template::Service object.

  • $callback: An optional subroutine reference that will be called with the processed template output as its argument. This can be used for further processing or validation of the output before it's compared to the expected result. If omitted or set to undef, the output is compared directly.

The subroutine automatically compares the actual output generated from processing the template with the expected output defined in the __DATA__ block. It uses standard Perl testing utilities (like ok() and diag()) to report the test results.

If $config is a hash reference, it's used to create a Template::Service object. If it's a Template::Context or Template::Provider object, it's used directly. This allows for flexibility in how the testing environment is set up.

The example in the synopsis demonstrates how to use test_expect() with a simple data block. The \*DATA argument tells the subroutine to read from the special __DATA__ section of the current file. The $config argument allows you to specify custom configuration options, such as the template search path and whether to use absolute paths. The optional callback function, callsign() in this example, can be used to perform additional checks or modifications on the generated output before it's compared to the expected.

banner()

This subroutine prints a simple banner including any text passed as parameters. The $DEBUG variable must be set for it to generate any output.

banner('Testing something-or-other');

example output:

#------------------------------------------------------------
# Testing something-or-other (27 tests completed)
#------------------------------------------------------------

PACKAGE VARIABLES

$DEBUG

The $DEBUG package variable can be set to enable debugging mode.

$PRESERVE

The $PRESERVE package variable can be set to stop the test_expect() from converting newlines in the output and expected output into the literal strings '\n'.

HISTORY

This module started its butt-ugly life as the "t/texpect.pl" script. It was cleaned up to became the "Template::Test" module some time around version 0.29. It underwent further cosmetic surgery for version 2.00 but still retains some remarkable rear-end resemblances.

Since then the "Test::More" and related modules have appeared on CPAN making this module mostly, but not entirely, redundant.

BUGS / KNOWN "FEATURES"

Imports all methods by default. This is generally a Bad Thing, but this module is only used in test scripts (i.e. at build time) so a) we don't really care and b) it saves typing.

The line splitter may be a bit dumb, especially if it sees lines like "-- this --" that aren't supposed to be special markers. So don't do that.
