NOMBRE

Template::Manual::Variables - Variables de plantilla y enlaces de código

Variables de Plantilla

Se puede pasar una referencia a un array hash como segundo argumento al método process(), conteniendo definiciones de variables de plantilla. La opción "VARIABLES" (también conocida como "PRE_DEFINE") también se puede usar para predefinir variables para todas las plantillas procesadas por el objeto.

my $tt = Template->new({
    VARIABLES => {
        version => 3.14,
        release => 'Sahara',
    },
});
my $vars = {
    serial_no => 271828,
};
$tt->process('myfile', $vars);

Plantilla myfile:

This is version [% version %] ([% release %]).
Serial number: [% serial_no %]

Salida Generada:

This is version 3.14 (Sahara)
Serial number: 271828

Los nombres de las variables pueden contener cualquier carácter alfanumérico o guiones bajos. Pueden ser en minúsculas, mayúsculas o una combinación de ambas, aunque la convención habitual es usar minúsculas. Sin embargo, la capitalización **es** significativa, y '"foo"', '"Foo"' y '"FOO"' son todas variables diferentes. Se permiten nombres de variables en mayúsculas, pero no se recomiendan debido a un posible conflicto con una palabra reservada existente o futura. A partir de la versión 2.00, estas son:

GET CALL SET DEFAULT INSERT INCLUDE PROCESS WRAPPER
IF UNLESS ELSE ELSIF FOR FOREACH WHILE SWITCH CASE
USE PLUGIN FILTER MACRO PERL RAWPERL BLOCK META
TRY THROW CATCH FINAL NEXT LAST BREAK RETURN STOP
CLEAR TO STEP AND OR NOT MOD DIV END

Los valores de las variables pueden ser de prácticamente cualquier tipo de Perl, incluyendo escalares simples, referencias a listas, arrays hash, subrutinas u objetos. Template Toolkit aplicará automáticamente el procedimiento correcto para acceder a estos valores a medida que se utilizan en la plantilla.

Datos de ejemplo:

my $vars = {
    article => 'The Third Shoe',
    person  => {
        id    => 314,
        name  => 'Mr. Blue',
        email => 'blue@nowhere.org',
    },
    primes  => [ 2, 3, 5, 7, 11, 13 ],
    wizard  => sub { return join(' ', 'Abracadabra!', @_) },
    cgi     => CGI->new('mode=submit&debug=1'),
};

Plantilla de ejemplo:

[% article %]
[% person.id %]: [% person.name %] <[% person.email %]>
[% primes.first %] - [% primes.last %], including [% primes.3 %]
[% primes.size %] prime numbers: [% primes.join(', ') %]
[% wizard %]
[% wizard('Hocus Pocus!') %]
[% cgi.param('mode') %]

Salida generada:

The Third Shoe
314: Mr. Blue <blue@nowhere.org>
2 - 13, including 7
6 prime numbers: 2, 3, 5, 7, 11, 13
Abracadabra!
Abracadabra! Hocus Pocus!
submit

Valores Escalares

Las variables escalares regulares se acceden simplemente especificando su nombre. Dado que estas son solo entradas en el hash de variables de nivel superior, pueden considerarse casos especiales de referencias a hash array como se describe a continuación, con el hash del espacio de nombres principal implícito automáticamente.

[% article %]

Referencias a Hash Array

Los miembros de los hash arrays se acceden especificando la referencia hash y la clave separadas por el operador punto '"."'.

Datos de ejemplo:

my $vars = {
    'home' => 'http://www.myserver.com/homepage.html',
    'page' => {
        'this' => 'mypage.html',
        'next' => 'nextpage.html',
        'prev' => 'prevpage.html',
    },
};

Plantilla de ejemplo:

<a href="[% home %]">Home</a>
<a href="[% page.prev %]">Previous Page</a>
<a href="[% page.next %]">Next Page</a>

Salida Generada:

<a href="http://www.myserver.com/homepage.html">Home</a>
<a href="prevpage.html">Previous Page</a>
<a href="nextpage.html">Next Page</a>

Cualquier clave en un hash que comience con un carácter '"_"' o '"."' se considerará privada y no podrá ser evaluada o actualizada desde dentro de una plantilla. El valor indefinido se devolverá para cualquier variable de este tipo a la que se acceda, y Template Toolkit la ignorará silenciosamente (a menos que la opción "DEBUG" esté habilitada).

Datos de ejemplo:

my $vars = {
    message => 'Hello World!',
    _secret => "On the Internet, no-one knows you're a dog",
    thing   => {
        public    => 123,
        _private  => 456,
        '.hidden' => 789,
    },
};

Plantilla de ejemplo:

[% message %]           # outputs "Hello World!"
[% _secret %]           # no output
[% thing.public %]      # outputs "123"
[% thing._private %]    # no output
[% thing..hidden %]     # ERROR: unexpected token (..)

Puedes deshabilitar esta característica estableciendo la variable del paquete $Template::Stash::PRIVATE a un valor falso.

$Template::Stash::PRIVATE = undef;   # now you can thing._private

Para acceder a una entrada hash usando una clave almacenada en otra variable, antepón '$' a la clave de la variable para que se interpole antes de usarla (ver "Variable Interpolation").

[% pagename = 'next' %]
[% page.$pagename %]       # same as [% page.next %]

También puedes acceder a una entrada hash usando el método item(). Esto puede ser útil si tienes nombres de clave complejos.

<pre>
[% files.item('example.txt').content %]
</pre>

Ver Template::Manual::VMethods para más información.

Cuando asignas a una variable que contiene múltiples elementos de espacio de nombres (es decir, tiene uno o más caracteres '"."' en el nombre), se crearán automáticamente los hashes necesarios para representar los espacios de nombres intermedios. En el siguiente ejemplo, la variable "product" aparecerá automáticamente como un hash array a menos que se defina de otra manera.

[% product.id    = 'XYZ-2000'
   product.desc  = 'Bogon Generator'
   product.price = 666
%]
The [% product.id %] [% product.desc %]
costs $[% product.price %].00

Salida Generada:

The XYZ-2000 Bogon Generator
costs $666.00

Puedes usar la familiar construcción de Perl "{" ... "}" para crear explícitamente un hash y asignarlo a una variable. Ten en cuenta que las comas son opcionales entre los pares clave/valor y se puede usar '=' en lugar de '"=>"'.

# estilo TT mínimo
[% product = {
     id    = 'XYZ-2000'
     desc  = 'Bogon Generator'
     price = 666
   }
%]
# estilo perl
[% product = {
     id    => 'XYZ-2000',
     desc  => 'Bogon Generator',
     price => 666,
   }
%]

Referencias a Listas

Los elementos de las listas también se acceden mediante el operador punto.

Datos de ejemplo:

my $vars = {
    people => [ 'Tom', 'Dick', 'Larry' ],
};

Plantilla de ejemplo:

[% people.0 %]          # Tom
[% people.1 %]          # Dick
[% people.2 %]          # Larry

La directiva "FOREACH" se puede utilizar para iterar a través de los elementos de una lista.

[% FOREACH person IN people %]
Hello [% person %]
[% END %]

Salida Generada:

Hello Tom
Hello Dick
Hello Larry

Las listas se pueden construir in situ utilizando la construcción regular de lista anónima "[" ... "]". Las comas entre elementos son opcionales.

[% cols = [ 'red', 'green', 'blue' ] %]
[% FOREACH c IN cols %]
   [% c %]
[% END %]

o:

[% FOREACH c IN [ 'red', 'green', 'blue' ] %]
   [% c %]
[% END %]

También puedes crear secuencias numéricas simples usando el operador de rango "..":

[% n = [ 1 .. 4 ] %]    # n es [ 1, 2, 3, 4 ]
[% x = 4
   y = 8
   z = [x..y]           # z es [ 4, 5, 6, 7, 8 ]
%]

Subrutinas

Las variables de plantilla pueden contener referencias a subrutinas de Perl. Cuando se utiliza la variable, Template Toolkit llamará automáticamente a la subrutina, pasando cualquier argumento adicional especificado. El valor de retorno de la subrutina se utiliza como valor de la variable y se inserta en la salida del documento.

Ejemplo de plantilla:

[% wizard %]                    # ¡Abracadabra!
[% wizard('¡Hocus Pocus!') %]    # ¡Abracadabra! ¡Hocus Pocus!

Objetos

Las variables de plantilla también pueden contener referencias a objetos Perl. Los métodos se llaman usando el operador punto para especificar el método contra la variable del objeto. Se pueden especificar argumentos adicionales como con las subrutinas.

use CGI;
my $vars = {
    # parámetros CGI codificados para el propósito del ejemplo
    cgi  => CGI->new('mode=submit&debug=1'),
};

Ejemplo de plantilla:

[% FOREACH p IN cgi.param %]     # devuelve la lista de claves de parámetro
[% p %] => [% cgi.param(p) %]   # recupera el valor de cada parámetro
[% END %]

Salida generada:

mode => submit
debug => 1

Los métodos de objeto también se pueden llamar como lvalues. Es decir, pueden aparecer en el lado izquierdo de una asignación. El método se llamará pasando el valor que se asigna como argumento.

[% myobj.method = 10 %]

equivalente a:

[% myobj.method(10) %]

Pasar Parámetros y Devolver Valores

Las subrutinas y métodos recibirán cualquier argumento especificado en la plantilla. Cualquier variable de plantilla en la lista de argumentos se evaluará primero y sus valores resultantes se pasarán al código.

my $vars = {
    mycode => sub { return 'recibido ' . join(', ', @_) },
};

plantilla:

[% foo = 10 %]
[% mycode(foo, 20) %]       # recibido 10, 20

También se pueden especificar parámetros con nombre. Estos se recopilan automáticamente en una sola matriz hash que se pasa por referencia como el **último** parámetro a la subrutina. Los parámetros con nombre se pueden especificar usando "=">" o "=" y pueden aparecer en cualquier lugar de la lista de argumentos.

my $vars = {
    myjoin => \&myjoin,
};
sub myjoin {
    # busca una referencia hash como último argumento
    my $params = ref $_[-1] eq 'HASH' ? pop : { };
    return join($params->{ joint } || ' + ', @_);
}

Ejemplo de plantilla:

[% myjoin(10, 20, 30) %]
[% myjoin(10, 20, 30, joint = ' - ') %]
[% myjoin(joint => ' * ', 10, 20, 30) %]

Salida generada:

10 + 20 + 30
10 - 20 - 30
10 * 20 * 30

Se pueden agregar parámetros entre paréntesis a cualquier elemento de una variable, no solo a aquellos que están vinculados a código o métodos de objeto. En la actualidad, los parámetros se ignorarán si la variable no es "llamable", pero se admiten para futuras extensiones. Piense en ellos como "pistas" para esa variable, en lugar de simples argumentos pasados a una función.

[% r = 'Romeo' %]
[% r(100, 99, s, t, v) %]       # muestra "Romeo"

El código de usuario debe devolver un valor para la variable que representa. Este puede ser cualquiera de los tipos de datos Perl descritos anteriormente: un escalar o una referencia a una lista, hash, subrutina u objeto. Cuando el código devuelve una lista de varios valores, los elementos se integran automáticamente en una referencia de lista que se puede acceder como de costumbre.

my $vars = {
    # cualquiera está bien, el primero es el recomendado
    items1 => sub { return [ 'foo', 'bar', 'baz' ] },
    items2 => sub { return ( 'foo', 'bar', 'baz' ) },
};

Ejemplo de plantilla:

[% FOREACH i IN items1 %]
   ...
[% END %]
[% FOREACH i IN items2 %]
   ...
[% END %]

Manejo de Errores

Los errores se pueden reportar desde el código de usuario llamando a `die()`. Los errores generados de esta manera son capturados por Template Toolkit y convertidos en excepciones estructuradas que se pueden manejar desde dentro de la plantilla. Una referencia al objeto de excepción estará disponible como la variable `error`.

my $vars = {
    barf => sub {
        die "ha ocurrido un error enfermo\n";
    },
};

Ejemplo de plantilla:

[% TRY %]
   [% barf %]       # llama a la subrutina que lanza un error a través de die()
[% CATCH %]
   [% error.info %]     # muestra "ha ocurrido un error enfermo\n"
[% END %]

Los mensajes de error lanzados a través de `die()` se convierten en excepciones de tipo `"undef"` (la cadena literal `"undef"` en lugar del valor indefinido). Las excepciones de tipos definidos por el usuario se pueden lanzar llamando a `die()` con una referencia a un objeto Template::Exception.

use Template::Exception;
my $vars = {
    login => sub {
        ...hacer algo...
        die Template::Exception->new( badpwd => 'contraseña demasiado tonta' );
    },
};

Ejemplo de plantilla:

[% TRY %]
   [% login %]
[% CATCH badpwd %]
   Contraseña incorrecta: [% error.info %]
[% CATCH %]
   Otro error de '[% error.type %]': [% error.info %]
[% END %]

Los tipos de excepción `"stop"` y `"return"` se utilizan para implementar las directivas `"STOP"` y `"RETURN"`. Lanzar una excepción como:

die (Template::Exception->new('stop'));

tiene el mismo efecto que la directiva:

[% STOP %]

Métodos Virtuales

Template Toolkit implementa varios "métodos virtuales" que se pueden aplicar a escalares, hashes o listas. Por ejemplo:

[% mylist = [ 'foo', 'bar', 'baz' ] %]
[% newlist = mylist.sort %]

Aquí `mylist` es una referencia normal a una lista, y `sort` es un método virtual que devuelve una nueva lista con los elementos en orden ordenado. Puede encadenar múltiples métodos virtuales juntos. Por ejemplo:

[% mylist.sort.join(', ') %]

Aquí se llama al método virtual `join` para unir la lista ordenada en una sola cadena, generando la siguiente salida:

bar, baz, foo

Vea Template::Manual::VMethods para obtener detalles sobre todos los métodos virtuales disponibles.

Interpolación de Variables

Template Toolkit usa `$` consistentemente para indicar que una variable debe interpolarse en posición. La mayoría de las veces, verá esto en cadenas entre comillas dobles:

[% fullname = "$honorific $firstname $surname" %]

O incrustado en texto plano cuando se establece la opción `INTERPOLATE`:

Estimado/a $honorific $firstname $surname,

Las mismas reglas se aplican dentro de las directivas. Si una variable va precedida de un `$` entonces se reemplaza por su valor antes de ser utilizada. El uso más común es recuperar un elemento de un hash donde la clave está almacenada en una variable.

[% uid = 'abw' %]
[% users.$uid %]         # lo mismo que 'users.abw'

Se pueden usar llaves para delimitar nombres de variables interpoladas cuando sea necesario.

[% users.${me.id}.name %]

Las directivas como `INCLUDE`, `PROCESS`, etc., que aceptan un nombre de plantilla como primer argumento, lo citarán automáticamente para mayor comodidad.

[% INCLUDE foo/bar.txt %]

El ejemplo anterior es equivalente a:

[% INCLUDE "foo/bar.txt" %]

Para `INCLUDE` una plantilla cuyo nombre está almacenado en una variable, simplemente prefije el nombre de la variable con `$` para que se interpola.

[% myfile = 'header' %]
[% INCLUDE $myfile %]

Esto es equivalente a:

[% INCLUDE header %]

Tenga en cuenta también que una variable que contiene una referencia a un objeto Template::Document también puede procesarse de esta manera.

my $vars = {
    header => Template::Document->new({ ... }),
};

Ejemplo de plantilla:

[% INCLUDE $header %]

Variables Locales y Globales

Cualquier variable simple que cree, o cualquier cambio que haga en variables existentes, solo persistirá mientras se procesa la plantilla. El hash de variables de nivel superior se copia antes de que comience el procesamiento y cualquier cambio en las variables se realiza en esta copia, dejando el original intacto.

Lo mismo ocurre cuando `INCLUDE` otra plantilla. El hash de espacio de nombres actual se clona para evitar que cualquier cambio de variable realizado en la plantilla incluida interfiera con las variables existentes. La opción `PROCESS` omite el paso de localización por completo, lo que la hace un poco más rápida, pero requiere una mayor atención a la posibilidad de efectos secundarios causados por la creación o modificación de variables dentro de la plantilla procesada.

[% BLOCK change_name %]
   [% name = 'bar' %]
[% END %]
[% name = 'foo' %]
[% INCLUDE change_name %]
[% name %]              # foo
[% PROCESS change_name %]
[% name %]              # bar

Las variables compuestas con puntos se comportan de manera ligeramente diferente porque el proceso de localización es solo superficial. Se copia el hash del espacio de nombres de variables actual, pero no se intenta realizar una copia profunda de otras estructuras dentro de él (hashes, matrices, objetos, etc.). Una variable que hace referencia a un hash, por ejemplo, se copiará para crear una nueva referencia, pero que apunta al mismo hash. Por lo tanto, la regla general es que las variables simples (variables sin puntos) se localizan, pero las estructuras complejas existentes (variables con puntos) no.

[% BLOCK all_change %]
   [% x = 20 %]         # cambia la copia
   [% y.z = 'zulu' %]       # cambia el original
[% END %]
[% x = 10
   y = { z => 'zebra' }
%]
[% INCLUDE all_change %]
[% x %]             # todavía '10'
[% y.z %]               # ahora 'zulu'

Si crea una estructura compleja, como una referencia a un hash o una lista, dentro de un contexto de plantilla local, esta dejará de existir cuando termine el procesamiento de la plantilla.

[% BLOCK new_stuff %]
   [% # define un nuevo hash 'y' en contexto local
      y = { z => 'zulu' }
   %]
[% END %]
[% x = 10 %]
[% INCLUDE new_stuff %]
[% x %]             # muestra '10'
[% y %]             # nada, y no está definido

De manera similar, si actualiza un elemento de una variable compuesta que *no* existe todavía, se creará automáticamente un hash y se eliminará nuevamente al final del bloque.

[% BLOCK new_stuff %]
   [% y.z = 'zulu' %]
[% END %]

Template::Manual::Variables - Variables in Template Toolkit

Template Variables

Variables are loaded into the template context from a hash reference passed to the "process()" method.

my $vars = {
    name      => 'Fred',
    user      => 'admin',
    items     => [ 'apple', 'banana', 'cherry' ],
    options   => {
        colour => 'red',
        size   => 'large',
    },
};

$template->process('template.tt', $vars)
    || die $template->error(), "\n";

Variables can be accessed within templates using dotted notation:

Hello [% name %]!
Your user is: [% user %]

Your items:
[% FOREACH item = items -%]
  * [% item %]
[% END %]

Options:
  Colour: [% options.colour %]
  Size:   [% options.size %]

A variable may be undefined. In such cases, it is treated as an empty string and generates no output.

A variable may be explicitly set to "undef" within a template (using the "USE" directive), in which case it will also generate no output.

The template processor automatically converts Perl's "undef" value to an empty string for output, but it will still raise a runtime error if you try to access an element of an undefined value.

# This would be an error if $options was undef
[% options.colour %]

You can use the "defined" template operator to check if a variable is defined before attempting to access it.

[% IF defined(options.colour) -%]
  Colour: [% options.colour %]
[% ELSE -%]
  Colour: (not specified)
[% END %]

Alternatively, you can use the "default" operator to provide a default value if the variable is undefined.

Colour: [% options.colour | default('red') %]

Variables referenced by "USE" directives are evaluated within the context of the current namespace, unless explicitly specified otherwise via a "NAMESPACE" directive.

Virtual Methods

If a variable evaluates to an object blessed into a Perl package, then any method calls made on that variable will be delegated to the object. This allows you to interact directly with Perl objects from within your templates.

# In Perl code:
use My::Object;
my $obj = My::Object->new({ name => 'Widget' });
my $vars = { widget => $obj };
$template->process('template.tt', $vars);
# In template.tt:
Widget name: [% widget.name %]
Method call: [% widget.calculate(10, 5) %]

The arguments passed to the method must be literal values or other variables that can be evaluated at runtime. Template Toolkit performs basic type checking and will emit an error if you attempt to call a method that doesn't exist.

The template processor caches method lookups, so repeated calls to the same method on the same object are efficient.

You can also call virtual methods on array or hash references, which will delegate to the underlying object if one is present, or use the built-in virtual method implementations otherwise. See Template::Manual::Cookies for details.

Variable Interpolation

Template Toolkit supports a number of special variables that are automatically defined and populated when the template is processed.

Local and Global Variables

By default, all variables defined within a template are local to that template. This means they are not visible to templates called via "INCLUDE" or "PROCESS" directives, nor are they visible to the calling template.

If you wish to define variables that are visible across multiple templates, you can declare them as global using the "use" directive with the "global" namespace.

[% USE foo = global.my_variable %]

This statement attempts to retrieve the value of "my_variable" from the global namespace. If it doesn't exist, it will be created and initialized to "undef".

You can also directly assign values to the global namespace.

[% global.my_variable = 'some value' %]

Any template that subsequently uses the "global" namespace will see the updated value.

Alternatively, you can define global variables when creating the Template Toolkit object:

my $tt = Template->new({
    VARIABLES => {
        global => {
            version => '1.0',
            title   => 'My Application',
        },
    },
});
