NOMBRE

Test::Pod - comprueba errores de POD en archivos

VERSIÓN

Versión 1.52

SINOPSIS

"Test::Pod" te permite verificar la validez de un archivo POD e informar de sus resultados en el formato estándar de "Test::Simple".

use Test::Pod tests => $num_tests;
pod_file_ok( $file, "Archivo POD válido" );

Los autores de módulos pueden incluir lo siguiente en un archivo t/pod.t y hacer que "Test::Pod" encuentre y compruebe automáticamente todos los archivos POD en una distribución de módulo:

use Test::More;
eval "use Test::Pod 1.00";
plan skip_all => "Se requiere Test::Pod 1.00 para probar POD" if $@;
all_pod_files_ok();

También puedes especificar una lista de archivos para comprobar, utilizando la función all_pod_files() proporcionada:

use strict;
use Test::More;
eval "use Test::Pod 1.00";
plan skip_all => "Se requiere Test::Pod 1.00 para probar POD" if $@;
my @poddirs = qw( blib script );
all_pod_files_ok( all_pod_files( @poddirs ) );

O incluso (si estás ejecutando bajo Apache::Test):

use strict;
use Test::More;
eval "use Test::Pod 1.00";
plan skip_all => "Se requiere Test::Pod 1.00 para probar POD" if $@;
my @poddirs = qw( blib script );
use File::Spec::Functions qw( catdir updir );
all_pod_files_ok(
    all_pod_files( map { catdir updir, $_ } @poddirs )
);

DESCRIPCIÓN

Comprueba archivos POD en busca de errores o advertencias en un archivo de prueba, utilizando "Pod::Simple" para hacer el trabajo pesado.

FUNCIONES

pod_file_ok( NOMBRE_DE_ARCHIVO[, NOMBRE_DE_PRUEBA ] )

pod_file_ok() validará la prueba si el POD se analiza correctamente. Ciertas condiciones aún no se informan, como un archivo sin ningún pod.

Cuando falla, pod_file_ok() mostrará cualquier error de comprobación de pod como diagnóstico.

El segundo argumento opcional NOMBRE_DE_PRUEBA es el nombre de la prueba. Si se omite, pod_file_ok() elige un nombre de prueba predeterminado "Prueba de POD para NOMBRE_DE_ARCHIVO".

all_pod_files_ok( [@entradas] )

Comprueba todos los archivos bajo @entradas para ver si son POD válidos. Ejecuta all_pod_files() en directorios y asume que todo lo demás es un archivo para probar. Llama a la función plan() por ti (una prueba por cada archivo), por lo que no puedes haber llamado ya a "plan".

Si @entradas está vacío o no se pasa, la función encuentra todos los archivos POD en archivos en el directorio blib si existe, o en el directorio lib si no. Un archivo POD coincide con las condiciones especificadas a continuación en "all_pod_files".

Si estás probando un módulo, simplemente crea un t/pod.t:

use Test::More;
eval "use Test::Pod 1.00";
plan skip_all => "Se requiere Test::Pod 1.00 para probar POD" if $@;
all_pod_files_ok();

Devuelve verdadero si todos los archivos pod están bien, o falso si alguno falla.

all_pod_files( [@dirs] )

Devuelve una lista de todos los archivos POD en @dirs y en los directorios inferiores. Si no se pasan directorios, por defecto usa blib si blib existe, o si no lib. Omite cualquier archivo en directorios como CVS, .svn, .git y similares. Ver %Test::Pod::ignore_dirs para una lista de ellos.

Un archivo POD es:

  • Cualquier archivo que termine en .pl, .PL, .pm, .pod, .psgi o .t.
  • Cualquier archivo que tenga una primera línea con un shebang y "perl" en él.
  • Cualquier archivo que termine en .bat y tenga una primera línea con "--*-Perl-*--" en ella.

El orden de los archivos devueltos depende de la máquina. Si los quieres ordenados, tendrás que ordenarlos tú mismo.
