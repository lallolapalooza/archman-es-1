Test::Most(3) Documentación de contribución de usuario de Perl Test::Most(3)

NOMBRE

Test::Most - Las funciones y características de prueba más necesarias.

VERSIÓN

Versión 0.38

SINOPSIS

En lugar de esto:

use strict;
use warnings;
use Test::Exception 0.88;
use Test::Differences 0.500;
use Test::Deep 0.106;
use Test::Warn 0.11;
use Test::More tests => 42;

Escribe esto:

use Test::Most tests => 42;

DESCRIPCIÓN

Test::Most existe para reducir el código repetitivo y hacer tu vida de pruebas más fácil. Proporcionamos "compras en un solo lugar" para los módulos de prueba más comúnmente utilizados. De hecho, a menudo requerimos las últimas versiones para que obtengas correcciones de errores a través de Test::Most y no tengas que actualizar estos módulos por separado.

Este módulo te proporciona las funciones de prueba más utilizadas, junto con la activación automática de `strict` y `warnings`, y te da un control un poco más detallado sobre tu conjunto de pruebas.

use Test::Most tests => 4, 'die';
ok 1, 'Las llamadas normales a ok() deberían tener éxito';
is 2, 2, '... al igual que todas las pruebas que pasan';
eq_or_diff [3], [4], '... pero las pruebas fallidas deberían morir';
ok 4, '... nunca se llegará a este punto';

Como puedes ver, la prueba "eq_or_diff" fallará. Debido a que 'die' está en la lista de importación, el programa de prueba se detendrá en ese punto.

Si no deseas que `strict` y `warnings` estén habilitados, debes deshabilitarlos explícitamente. Por lo tanto, debes ser explícito sobre lo que quieres y ya no tener que preocuparte por olvidarlos accidentalmente.

use Test::Most tests => 4;
no strict;
no warnings;

EXPORTAR

Todas las funciones de los siguientes módulos se exportarán automáticamente a tu espacio de nombres:

  • Test::More
  • Test::Exception
  • Test::Differences
  • Test::Deep
  • Test::Warn

Las funciones que se exportan *opcionalmente* desde cualquiera de esos módulos deben ser referenciadas por su nombre completamente calificado:

Test::Deep::render_stack( $var, $stack );

FUNCIONES

Varias otras funciones también se exportan automáticamente:

"die_on_fail"

die_on_fail;
is_deeply $foo, bar, '... lanzamos una excepción si esto falla';

Esta función, si se llama, hará que el programa de prueba lance una `Test::Most::Exception`, deteniendo efectivamente la prueba.

"bail_on_fail"

bail_on_fail;
is_deeply $foo, bar, '... salimos si esto falla';

Esta función, si se llama, hará que el conjunto de pruebas **SALGA** (`BAIL_OUT()`) si alguna prueba falla después de ella.

"restore_fail"

die_on_fail;
is_deeply $foo, bar, '... lanzamos una excepción si esto falla';
restore_fail;
cmp_bag(\@got, \@bag, '... no lanzaremos una excepción si esto falla';

Esto restaura el comportamiento original de fallo de prueba, por lo que las pruebas subsiguientes ya no lanzarán una excepción ni saldrán (`BAIL_OUT()`).

"set_failure_handler"

Si prefieres otro comportamiento a 'die_on_fail' o 'bail_on_fail', puedes establecer tu propio manejador de fallos:

set_failure_handler( sub {
    my $builder = shift;
    if ( $builder && $builder->{Test_Results}[-1] =~ /critical/ ) {
       send_admin_email("fallo crítico en las pruebas");
    }
} );

Recibe la instancia de "Test::Builder" como su único argumento.

Importante: Ten en cuenta que si la prueba fallida es la última prueba ejecutada, entonces $builder probablemente será indefinido. Este es un desafortunado efecto secundario de cómo ha sido diseñado "Test::Builder".

"explain"

Similar a note(), la salida solo será vista por el usuario usando el modificador "-v" con "prove" o leyendo el TAP sin procesar.

A diferencia de note(), cualquier referencia en la lista de argumentos se expande automáticamente usando "Data::Dumper". Por lo tanto, en lugar de esto:

my $self = Some::Object->new($id);
use Data::Dumper;
explain 'Fui creado ahora', Dumper($self);

Ahora puedes simplemente hacer esto:

my $self = Some::Object->new($id);
explain 'Fui creado ahora:  ', $self;

Esa salida se parecerá a:

Fui creado ahora:  bless( {
  'id' => 2,
  'stack' => []
}, 'Some::Object' )

Ten en cuenta que la salida "dumpered" tiene las variables de "Data::Dumper" $Indent, "Sortkeys" y "Terse" establecidas todas al valor 1 (uno). Esto permite una salida de diagnóstico mucho más limpia y, en el momento actual, no se puede anular.

Ten en cuenta que "explain" de Test::More actúa de manera diferente. Este "explain" es equivalente a "note explain" en Test::More.

"show"

Experimental. Al igual que "explain", pero también intenta mostrarte los nombres de las variables léxicas:

my $var   = 3;
my @array = qw/ foo bar /;
show $var, \@array;
__END__
$var = 3;
@array = [
    'foo',
    'bar'
];

Mostrará $VAR1, $VAR2 ... $VAR_N para cada variable cuyo nombre no pueda determinar:

my @array = qw/ foo bar /;
show @array;
__END__
$VAR1 = 'foo';
$VAR2 = 'bar';

Ten en cuenta que esto se basa en `Data::Dumper::Names` versión 0.03 o superior. Si no está presente, advertirá y llamará a `explain` en su lugar. Además, solo puede mostrar los nombres de las variables léxicas. Las variables globales como %ENV o "%@" no se acceden a través de PadWalker y, por lo tanto, no se pueden mostrar. Sería bueno encontrar una solución para esto.

"always_explain" y "always_show"

Estos son idénticos a "explain" y "show", pero al igual que la función "diag" de Test::More, estos siempre emitirán una salida, independientemente de si estás en modo verboso o no.

"all_done"

**OBSOLETO**. Utiliza el nuevo done_testing() (añadido en Test::More desde 0.87_01). Dejamos esto aquí para un largo ciclo de obsolescencia. Después de un tiempo, podríamos incluso empezar a advertir.

Si el plan se especifica como "defer_plan", puedes llamar a &all_done al final de la prueba con un número de prueba opcional. Esto te permite establecer el plan sin saber el plan antes de ejecutar las pruebas.

Si lo llamas sin un número de prueba, las pruebas aún fallarán si no llegas al final de la prueba. Esto es útil si no quieres especificar un plan, pero las pruebas terminan inesperadamente. Por ejemplo, lo siguiente *pasaría* con "no_plan" pero fallaría con "all_done".

use Test::More 'defer_plan';
ok 1;
exit;
ok 2;
all_done;

Ver "Planes diferidos" para más información.

NOMBRE

Test::Most - Un módulo de Perl para testing

VERSIÓN

Test::Most 0.38-5

SINOPSIS

use Test::Most qw<no_plan die>;
ok $foo, 'Morir si esto falla';
ok factorial(123456),
  '... pero espera mucho tiempo antes de lanzar una excepción';

DESCRIPCIÓN

Test::Most es un módulo de Perl diseñado para proporcionar una forma limpia y eficiente de escribir tests. Ofrece características como la capacidad de saltar tests, manejar diagnósticos y gestionar el plan de tests.

EXPORTAR

Test::Most exporta las siguientes funciones: ok, todo, skip, plan, no_plan, die, use, y import.

FUNCIONES

Test::Most proporciona las siguientes funciones:

  • ok: Verifica que un test pasa.
  • todo: Marca un test como pendiente.
  • skip: Salta un test y opcionalmente proporciona un mensaje.
  • plan: Especifica el número de tests a ejecutar.
  • no_plan: Deshabilita el plan y deja que el ejecutor de tests decida.
  • die: Lanza un error.
  • use: Importa un módulo.
  • import: Importa una función.

EXPORTAR A DEMANDA

Test::Most permite exportar funciones a demanda. Esto significa que puedes elegir qué funciones exportar cuando quieras usarlas.

MORIR O ABORTAR AL FALLAR

Test::Most maneja los fallos muriendo o abortando. Esto se controla mediante las funciones die y use.

MISCELÁNEA

Test::Most incluye características misceláneas como saltar tests, manejar diagnósticos y gestionar el plan de tests.

PRECAUCIONES

Debido a cómo Perl maneja los argumentos, y porque los diagnósticos no son realmente parte del Protocolo de Prueba de Cualquier Cosa (TAP), lo que realmente sucede internamente es que notamos que un test ha fallado y lanzamos una excepción o abortamos tan pronto como se llama al *siguiente* test (pero antes de que se ejecute). Esto significa que sus argumentos se evalúan automáticamente antes de que podamos tomar medidas:

use Test::Most qw<no_plan die>;
ok $foo, 'Morir si esto falla';
ok factorial(123456),
  '... pero espera mucho tiempo antes de lanzar una excepción';
