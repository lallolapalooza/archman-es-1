Term::ProgressBar(3) Documentación de Perl contribuida por el usuario Term::ProgressBar(3)

NOMBRE

Term::ProgressBar - proporcionar un medidor de progreso en una terminal estándar

VERSIÓN

Versión 2.23

SINOPSIS

use Term::ProgressBar;
my $progress = Term::ProgressBar->new ({count => 10_000});
$progress->update(5_000);

DESCRIPCIÓN

Term::ProgressBar proporciona una barra de progreso simple en la terminal, para que el usuario sepa que algo está sucediendo, aproximadamente cuánto se ha hecho y quizás una estimación de cuánto tiempo queda.

Un uso típico configura la barra de progreso con un número de elementos a hacer, y luego llama a `update` para actualizar la barra cada vez que se procesa un elemento.

A menudo, esto implicaría actualizar la barra de progreso muchas veces sin ningún cambio visible para el usuario. Para evitar trabajo innecesario, el método `update` devuelve un valor, siendo el valor de actualización en el que el usuario verá un cambio. Al llamar a `update` solo cuando el valor actual excede el próximo valor de actualización, se reduce la sobrecarga de llamadas.

Recuerda llamar a "$progress->update($max_value)" cuando el trabajo esté terminado para obtener una bonita barra del 100%.

Una barra de progreso, por defecto, es simple; va de izquierda a derecha, llenando la barra con caracteres '='. Estos se llaman caracteres mayores. Para trabajos de larga duración, esto puede ser demasiado lento, por lo que hay dos características adicionales disponibles: un estimador de tiempo de finalización lineal y/o un carácter menor: este es un carácter que se mueve de izquierda a derecha en la barra de progreso (no la llena como lo hace el carácter mayor), recorriéndola una vez por cada carácter mayor añadido. Esto aumenta exponencialmente la granularidad de la barra para el mismo ancho.

EJEMPLOS

Un uso realmente simple

#!/usr/bin/perl
use Term::ProgressBar 2.00;
use constant MAX => 100_000;
my $progress = Term::ProgressBar->new(MAX);
for (0..MAX) {
    my $is_power = 0;
    for (my $i = 0; 2**$i <= $_; $i++) {
        $is_power = 1 if 2**$i == $_;
    }
    if ($is_power) {
        $progress->update($_);
    }
}

ver eg/simle_use.pl

Aquí hay un ejemplo simple. El proceso considera todos los números entre 0 y MAX, y actualiza la barra de progreso cada vez que encuentra uno. Ten en cuenta que la actualización de la barra de progreso será muy errática. Ver abajo para un ejemplo más suave. Ten en cuenta también que la barra de progreso nunca se completará; ver abajo para solucionarlo.

El texto completo de este ejemplo está en examples/powers en el conjunto de distribución (no está instalado como parte del módulo).

Una actualización de barra más suave

my $progress = Term::ProgressBar->new($max);
for (0..$max) {
    my $is_power = 0;
    for (my $i = 0; 2**$i <= $_; $i++) {
        $is_power = 1 if 2**$i == $_;
    }
    $progress->update($_)
}

ver eg/smooth_bar.pl

Este ejemplo llama a `update` por cada valor considerado. Esto resultará en una actualización de progreso mucho más suave, pero se gastará más tiempo de programa actualizando la barra que haciendo el trabajo "real". Ver abajo para remediar esto. Este ejemplo *no* llama a "$progress->update($max);" al final, ya que es innecesario, y ProgressBar lanzará una excepción al intentar actualizar una barra terminada.

El texto completo de este ejemplo está en examples/powers2 en el conjunto de distribución (no está instalado como parte del módulo.

Una (mucho) más eficiente actualización

my $progress = Term::ProgressBar->new({name => 'Powers', count => $max, remove => 1});
$progress->minor(0);
my $next_update = 0;
for (0..$max) {
    my $is_power = 0;
    for (my $i = 0; 2**$i <= $_; $i++) {
        $is_power = 1 if 2**$i == $_;
    }
    $next_update = $progress->update($_) if $_ >= $next_update;
}
$progress->update($max) if $max >= $next_update;

Este ejemplo hace dos cosas para mejorar la eficiencia: primero, utiliza el valor devuelto por `update` para solo llamarlo de nuevo cuando sea necesario; segundo, desactiva el uso de caracteres menores para actualizar mucho menos frecuentemente ("$progress->minor(0);". El uso del valor devuelto por `update` significa que la llamada a "$progress->update($max);" al final es requerida para asegurar que la barra termine en el 100%, lo que da al usuario una buena sensación.

Este ejemplo también establece el nombre de la barra de progreso.

Este ejemplo también demuestra el uso de la bandera 'remove', que elimina la barra de progreso de la terminal cuando termina.

El texto completo de este ejemplo está en examples/powers3 en el conjunto de distribución (no está instalado como parte del módulo.

Cuando el número máximo de elementos a veces es desconocido

A veces, es posible que desees usar la barra de progreso cuando el número de elementos puede ser conocido o no. Un ejemplo común es cuando escribes un script que puede tomar entrada enviada desde la salida de otro comando, y luego enviar la salida a otro comando más. ej:

some_command --arg value | my_script.pl | some_other_command

O...

my_script.pl input_file output_file

Este ejemplo muestra cómo puedes iterar sobre un archivo especificado en la línea de comandos con la barra de progreso. Dado que el archivo de entrada puede ser leído desde STDIN, es posible que no se conozca el número de líneas. Term::ProgressBar maneja esto tomando '-1' como valor de conteo y sin más cambios en el código. Al llamar a `update` con el mismo valor de conteo, te aseguras de que la barra de progreso se elimine después.

my $input_file = shift;
my $output_file = shift;
my $in_fh = \*STDIN;
my $out_fh = \*STDOUT;
my $message_fh = \*STDERR;
my $num_lines = -1;
if (defined($input_file) and $input_file ne '-') {
    open($in_fh, $input_file) or die "Couldn't open file, '$input_file': $!";
    my $wc_output = `wc -l $input_file`;
    chomp($wc_output);
    $wc_output =~ /^\s*(\d+)(\D.*)?/ or die "Couldn't parse wc output: $wc_output";
    $num_lines = $1;
}
if(defined($output_file)) {
    !-f $output_file or die "Specified output file, '$output_file', already exists";
    open($out_fh, '>', $output_file) or die "Couldn't open output file, '$output_file': $!";
}
my $progress = Term::ProgressBar->new({
    name   => 'file processor',
    count  => $num_lines,
    remove => 1,
    fh     => $message_fh,
});
while (my $line = <$in_fh>) {
    chomp($line);
    print $out_fh "I found a line: $line\n";
    $progress->message("Found 10000!") if($line =~ /10000/);
    $progress->update();
}
$progress->update($num_lines);
print $message_fh "Finished\n";

Cuando el archivo se define explícitamente, la barra de progreso muestra el progreso línea por línea a través del archivo. Dado que la barra de progreso, por defecto, imprime la salida a stderr, la salida de tu script a STDOUT no se verá afectada.

Usando la Estimación del Tiempo de Finalización

  my $progress = Term::ProgressBar->new({
      name  => 'Powers',
      count => $max,
      ETA   => 'linear',
  });
  $progress->max_update_rate(1);
  my $next_update = 0;
  for (0..$max) {
      my $is_power = 0;
      for (my $i = 0; 2**$i <= $_; $i++) {
      if ( 2**$i == $_ ) {
          $is_power = 1;
          $progress->message(sprintf "Found %8d to be 2 ** %2d", $_, $i);
      }
  }
  $next_update = $progress->update($_)
    if $_ > $next_update;
}
$progress->update($max)
    if $max >= $next_update;

Este ejemplo utiliza la opción ETA para activar la estimación de finalización. Además, el retorno de `update` se ajusta para intentar actualizar la barra aproximadamente una vez por segundo, con la llamada a `max_update_rate`. Consulta la documentación del método `new` para obtener detalles de los formatos utilizados.

Este ejemplo también proporciona un ejemplo del uso de la función `message` para mostrar mensajes en el mismo manejador de archivos mientras se mantiene intacta la barra de progreso.

El texto completo de este ejemplo está en examples/powers5 en el conjunto de distribución (no está instalado como parte del módulo.

MÉTODOS

new ( [OPTIONS] )
Crea una nueva instancia de Term::ProgressBar. OPTIONS puede ser un escalar que se pasa directamente al constructor (y que se trata como el número de elementos a hacer), o una referencia a un hash de opciones. Las opciones son:
arg
Un argumento escalar pasado al constructor.
bar_char
El carácter a usar para llenar la barra. Por defecto es '='.
bar_width
El ancho de la barra en caracteres. Por defecto es 50.
clear
Un booleano. Si es verdadero, el terminal se borrará al inicio. Por defecto es falso.
count
El número total de elementos a hacer. Si no se especifica, la barra de progreso se comporta como si el número fuera infinito, y la barra se mostrará sólo el progreso y el tiempo transcurrido.
color
El color de la barra. Debe ser un nombre de color ANSI válido (por ejemplo, 'red', 'green', 'blue', 'yellow', 'cyan', 'magenta', 'white', 'black'). Si no se especifica, se utiliza el color por defecto.
done_char
El carácter a usar para la parte completa de la barra. Por defecto es '='.
ETA
Una cadena que indica cómo calcular el tiempo restante estimado (ETA). Los valores posibles son 'linear' (calcula una regresión lineal simple de los tiempos de actualización) o 'none' (desactiva el cálculo de ETA). Por defecto es 'none'.
fh
El manejador de archivo en el que se imprimirá la barra de progreso. Por defecto es STDERR.
frozen_char
El carácter a usar para el final de la barra (la parte que aún no se ha rellenado). Por defecto es ' ' (espacio).
format
Una cadena de formato para la salida de la barra de progreso. Ver `Term::ProgressBar::Style` para más información. Por defecto es `"$name [\e[32m$bar\e[m] $percent\%\n" `.
name
Un nombre para la barra de progreso. Se mostrará al principio de la línea de progreso. Por defecto es "Progress".
message_color
El color del mensaje. Debe ser un nombre de color ANSI válido.
minor_char
El carácter a usar para la barra de movimiento. Por defecto es '>'.
next_char
El carácter a usar para el final de la barra (la parte que aún no se ha rellenado). Por defecto es ' ' (espacio).
object
Si se proporciona un objeto, su método 'message' será llamado con el mensaje de la barra de progreso.
percent_format
Una cadena de formato para el porcentaje. Por defecto es '%3.0f'.
remove
Un booleano. Si es verdadero, la línea de progreso se eliminará de la terminal al finalizar. Por defecto es falso.
status_color
El color del estado (por ejemplo, el tiempo restante). Debe ser un nombre de color ANSI válido.
title_color
El color del título. Debe ser un nombre de color ANSI válido.
update_interval
El número mínimo de segundos entre actualizaciones. Por defecto es 0.1.
wrap
Un booleano. Si es verdadero, el texto se envolverá si es demasiado largo para la línea. Por defecto es verdadero.
wrapped_char
El carácter a usar para el texto envuelto. Por defecto es ' ' (espacio).
wrapped_width
El ancho de la línea envuelta. Por defecto es 78.
new ({ %args })
Crea una nueva barra de progreso. Los argumentos se pasan como un hash. Las claves del hash son los mismos nombres de las opciones anteriores. Los valores son los valores de las opciones.
update ( VALUE )
Actualiza la barra de progreso al valor especificado. Devuelve el valor de la próxima actualización que será visible para el usuario.
message ( MSG )
Imprime un mensaje en la misma línea que la barra de progreso. El mensaje se imprimirá centrado.
inc ( [INCREMENT] )
Incrementa el valor actual de la barra de progreso en INCREMENT. Si INCREMENT no se especifica, se incrementa en 1.
stop ( [MSG] )
Detiene la barra de progreso. Si se proporciona MSG, se imprime como un mensaje final.
filehandle
Devuelve el manejador de archivo en el que se imprime la barra de progreso.
file
Devuelve el nombre del archivo.
format
Devuelve el formato de la barra de progreso.
name
Devuelve el nombre de la barra de progreso.
percent
Devuelve el porcentaje de progreso actual.
message
Devuelve el mensaje actual.
current
Devuelve el valor actual de la barra de progreso.
max
Devuelve el valor máximo de la barra de progreso.
eta
Devuelve el tiempo restante estimado.

CONSTRUCCIÓN DE INSTANCIA

new

Crea y devuelve una nueva instancia de Term::ProgressBar.

ARGUMENTOS
Si se proporciona un argumento, y es un hashref, entonces el hash se trata como un conjunto de pares clave/valor, con las siguientes claves; de lo contrario, se trata como un número, siendo equivalente a la clave "count".
count
El recuento de elementos. El progreso se marca al 100% cuando se invoca update count, y proporcionalmente hasta entonces.

Si especificas un recuento menor que cero, solo se mostrará el nombre (si se especifica) y (si se establece la bandera de eliminación) se eliminará cuando la barra de progreso se actualice con un número inferior a cero. Esto te permite usar la barra de progreso cuando el recuento a veces se conoce y a veces no, sin realizar múltiples cambios en tu código.

name
Un nombre para prefijar la barra de progreso.
fh
El filehandle de salida. Por defecto es stderr. No intentes usar la sintaxis *foo{THING}; no funciona. Pasa una globref en su lugar.
term_width
A veces no podemos determinar correctamente el ancho de la terminal. Puedes usar este parámetro para forzar un ancho de terminal de un tamaño particular. Usa un entero positivo, por favor :)
silent
Si se pasa un valor verdadero, Term::ProgressBar no hará nada en absoluto. Útil en scripts donde la barra de progreso es opcional (o simplemente no funciona debido a problemas con los módulos en los que se basa).

En lugar de eso, dile al constructor que quieres que sea silencioso y no necesitas cambiar el resto de tu programa:

my $progress = Term::ProgressBar->new( { count => $count, silent => $silent } );
# más tarde
$progress->update; # no hace nada
ETA
Una estimación de tiempo total a utilizar. Si está habilitado, se imprime una estimación de tiempo de finalización en el lado derecho (una vez que se han realizado suficientes actualizaciones para que dicha estimación sea factible). Naturalmente, esto es una estimación; no se hacen garantías. El formato de la estimación

Ten en cuenta que el formato está diseñado para ser lo más compacto posible mientras proporciona la información relevante. Dependiendo del tiempo restante, se selecciona el formato para proporcionar alguna resolución mientras se mantiene compacto. A medida que disminuye el tiempo restante, el formato típicamente cambia con el tiempo.

A medida que se acerca la ETA, el formato indicará los minutos y segundos restantes. Esto se identifica por la palabra 'Left' en el lado derecho de la línea. Si la ETA está más lejos, se da una estimación del tiempo de finalización (en lugar del tiempo restante), y se identifica por 'ETA' en el lado izquierdo de la caja ETA (a la derecha de la barra de progreso). Se puede presentar una hora o una fecha; estas son del formato de un reloj de 24 horas, por ejemplo '13:33', una hora más días (por ejemplo, ' 7PM+3' para alrededor de 3 días) o un día/fecha, por ejemplo ' 1Jan' o '27Feb'.

Si la ETA está activada, el valor de retorno de update también se ve afectado: la idea es que si la barra de progreso parece moverse más rápido de lo que el ojo podría esperar (y, por lo tanto, se dedica mucho tiempo a las actualizaciones de progreso en lugar de al trabajo "real"), la próxima llamada se incrementa para ralentizarla. La velocidad máxima a la que se apunta es ajustable a través del componente max_update_rate.

Los valores disponibles para esto son:

undef
No hacer estimación. Por defecto.
linear
Realizar una estimación lineal. Esto es simplemente que la cantidad de tiempo entre la creación de la barra de progreso y ahora se divide por la cantidad actual completada, y se estima la finalización linealmente.
EJEMPLOS
my $progress = Term::ProgressBar->new(100); # cuenta de 1 a 100
my $progress = Term::ProgressBar->new({ count => 100 }); # lo mismo
# Cuenta hasta 200 cosas, saliendo a stdout en lugar de stderr,
# prefijando la barra con 'cosa'
my $progress = Term::ProgressBar->new({ count => 200,
                                        fh    => \*STDOUT,
                                        name  => 'cosa' });

COMPONENTES DE INSTANCIA

Componentes Escalares.

Ver "get_set" en Class::MethodMaker para su uso.

target
El objetivo final. Las actualizaciones se miden en términos de esto. Los cambios no tendrán efecto hasta la próxima actualización, pero el valor de la próxima actualización debe ser relativo al nuevo objetivo. Así 
$p = Term::ProgressBar({count => 20});
# A mitad de camino
$p->update(10);
# Doble escala
$p->target(40)
$p->update(21);

hará que la barra de progreso se actualice al 52.5%

max_update_rate
Se considera que este valor es la velocidad máxima entre actualizaciones a la que apuntar. Solo tiene sentido si la ETA está activada. Por defecto es 0.5, que es el número de segundos entre actualizaciones.

Componentes Booleanos

Ver "get_set" en Class::MethodMaker para su uso.

minor
Por defecto: establecido. Si no está establecido, no se calculará ni actualizará ninguna escala menor.

Los caracteres menores se utilizan en la barra de progreso para dar al usuario la idea de progreso incluso cuando hay tantas tareas más que el ancho de la terminal que la granularidad sería demasiado grande. Por defecto, Term::ProgressBar adivina cuándo los caracteres menores serían valiosos. Sin embargo, es posible que no siempre adivine correctamente, por lo que este método se puede llamar para forzarlo en un sentido u otro. Por supuesto, el ahorro de eficiencia es mínimo a menos que el cliente esté utilizando el valor de retorno de update.

Consulta examples/powers4 y examples/powers3 para ver caracteres menores en acción y no en acción, respectivamente.

Configuración

lbrack
Corchete izquierdo (por defecto es [) 
$progress->lbrack('<');
rbrack
Corchete derecho (por defecto es ]) 
$progress->rbrack('>');

PROCEDIMIENTOS DE MAYOR NIVEL DE INSTANCIA

update

Actualiza la barra de progreso.

ARGUMENTOS
so_far
Punto de progreso actual, en las unidades que se pasaron a "new".

Si no está definido, se asume que es 1 + el valor que tuvo la última vez que se llamó a "update" (comenzando en 0).

RETORNA
next_call
El próximo valor de so_far en el que llamar a "update".

message

Imprime un mensaje. Es muy parecido a print, pero intentamos no perturbar la terminal.

ARGUMENTOS
string
El mensaje a imprimir.

COMPATIBILIDAD

Si se proporcionan exactamente dos argumentos, entonces new opera en modo de compatibilidad v1: los argumentos se consideran nombre y recuento de elementos. Varios otros valores predeterminados se establecen para emular la versión uno (por ejemplo, el carácter de salida principal es '#', el ancho de la barra se establece en 50 caracteres y el filehandle de salida no se trata como una terminal). Este modo está obsoleto.
