NOMBRE

Test2::Manual::Tooling::Plugin::TestExit - Cómo añadir de forma segura comportamientos pre-salida.

DESCRIPCIÓN

Esto describe la forma correcta/segura de añadir comportamientos pre-salida a las pruebas a través de un plugin personalizado.

La forma ingenua de intentar esto sería añadir un bloque "END { ... }". Eso puede funcionar, y puede que no cause problemas... Por otro lado, hay muchas maneras en que esto puede salir mal. Describir todos los problemas potenciales de un bloque END, y cómo podría entrar en conflicto con Test2 (que tiene su propio bloque END) está fuera del alcance de este documento.

CÓDIGO COMPLETO DE ANTEMANO

package Test2::Plugin::MyPlugin;
use Test2::API qw{test2_add_callback_exit};
sub import {
    my $class = shift;
    test2_add_callback_exit(sub {
        my ($ctx, $orig_code, $new_exit_code_ref) = @_;
        return if $orig_code == 42;
        $$new_exit_code_ref = 42;
    });
}
1;

LÍNEA POR LÍNEA

use Test2::API qw{test2_add_callback_exit};
Esto importa la llamada de retorno "(test2_add_callback_exit)".
test2_add_callback_exit(sub { ... });
Esto añade nuestra llamada de retorno para que sea invocada antes de salir.
my ($ctx, $orig_code, $new_exit_code_ref) = @_
La llamada de retorno recibe 3 argumentos. El primero es un objeto de contexto que puedes usar. El segundo es el código de salida original del bloque "END" que está usando Test2. El tercer argumento es una referencia escalar que puedes usar para obtener el código de salida actual o establecer uno nuevo.
return if $orig_code == 42
Este es un atajo para no hacer nada si el código de salida original ya era 42.
$$new_exit_code_ref = 42
Esto cambia el código de salida a 42.
