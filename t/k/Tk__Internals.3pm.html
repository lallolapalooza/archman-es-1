Internals(3) Documentación de Perl aportada por el usuario Internals(3)

NOMBRE

Tk::Internals - qué está haciendo la interfaz Perl Tk cuando llamas a las funciones de Tk.

Esta información es peor que inútil para los usuarios de "perlTk", pero puede ser de alguna ayuda para las personas interesadas en usar una versión modificada de Tk con "perlTk".

Este documento está en construcción. Se cree que la información es pertinente para la versión de "portableTk" disponible cuando fue creada. Todos los detalles están sujetos a cambios.

DESCRIPCIÓN

PreCompilación
Antes de la etapa de compilación real, un script escanea el código fuente y extrae los subcomandos de diferentes comandos. Esta información reside en el archivo "pTk/Methods.def".
Compilación
Durante la compilación, el archivo anterior se incluye en el código fuente de la rutina de arranque de la biblioteca dinámica (o estática). Más precisamente, el código de arranque del módulo "Tk" llama a la subrutina Boot_Glue() del módulo "tkGlue.c", y esta subrutina incluye el archivo (con las definiciones de macro apropiadas).
Dentro de "use Tk;"
El módulo arranca el código C, luego carga las bibliotecas Perl. El corazón del código Perl está contenido en la biblioteca "Tk::Widget", todos los widgets heredan de este módulo. El código para los toplevels se carga desde "Tk::MainWindow".

Durante el arranque del código de pegamento C, se definen los códigos de "Xevent::?" y un puñado de rutinas de "Tk::Widget" y "Tk::Image". (Se crean muchas más XSUBs a partir del código "Tk.xs"). Los subcomandos del widget se conectan a Perl basándose en la lista incluida de "pTk/Methods.def". De hecho, todos los subcomandos se conectan a XSUBs que están relacionadas con la misma subrutina C XStoWidget(), pero tienen diferentes partes de datos.

Durante el arranque del código Perl, se llama al método "Tk::Widget::import". Esta llamada requiere todo el código de los paquetes de widgets particulares.

El código de los paquetes de widgets llama a un comando oscuro como

(bless \"Text")->WidgetClass;

Este comando (en realidad Tk::Widget::WidgetClass()) crea tres rutinas: Tk::Widget::Text(), Tk::Widget::isText(), y Tk::Text::isText(). La primera es básicamente el "new" de "Tk::Text", las otras dos devuelven constantes. También coloca la clase en el depósito.

Dentro de "$top = MainWindow->new;"
Esto es bastante intuitivo. Esta llamada va directamente a "Tk::MainWindow::new", que llama a la XSUB "Tk::MainWindow::CreateMainWindow", que llama a la subrutina C Tk_CreateMainWindow(). Es una subrutina de "Tk", así que aquí termina la magia negra (casi).

La única magia negra que queda es que la rutina de inicialización de "Tk" crea muchos comandos, pero la subrutina para la creación es usurpada por portableTk y los comandos se crean en el paquete "Tk". Están asociados a XSUBs que están relacionadas con una de las tres subrutinas C XStoSubCmd(), XStoBind(), o XStoTk(), pero tienen diferentes partes de datos.

El resultado de la llamada se bendice en "Tk::MainWindow", como debe ser.

Dentro de "$top->title('Text demo');"
El paquete "Tk::Toplevel" define muchos subcomandos sobre la marcha a partir de una lista. Todos los comandos de la lista se convierten a los subcomandos correspondientes del método "wm" del widget. Aquí, el subcomando es un comando con un segundo argumento particular (en este caso "title"). Recuerda que el primer argumento es $self.

Ahora "Tk::Toplevel" @ISA "Tk::Widget", que a su vez @ISA "Tk". Por lo tanto, una llamada a "$top->wm('title','Text demo')" llama a "Tk::wm", que se define durante la llamada a Tk_CreateMainWindow(). Como se describe anteriormente, se llama a la XSUB asociada a XStoSubCmd().

Esta rutina C está definida en "tkGlue.c". Obtiene la parte de datos de la XSUB, crea un "SV" con el nombre del comando y llama a Call_Tk() con los datos de la XSUB como primer argumento, y con el nombre de la XSUB introducido en la pila de Perl en el lugar donde "tk" lo espera. (De hecho, también puede reordenar los argumentos si cree que es lo que quieres).

El último procedimiento extrae el nombre del procedimiento de "tk" y "clientData" del primer argumento y realiza una llamada, utilizando la pila de Perl como "argv" para el procedimiento. Después se realiza mucha magia negra para convertir el resultado del procedimiento en un valor de retorno de array de Perl.

Dentro de "$text = $top->Text(background => $txtBg);"
Anteriormente discutimos cómo se crea el comando "Tk::Widget::Text". El comando anterior lo llama a través de la herencia. Se traduce a 
Tk::Text::new($top, background => $txtBg);

El paquete "Tk::Text" no tiene un método "new", por lo que se llama a "Tk::Widget::new". A su vez, llama a "Tk::Text->DoInit($top)", que es "Tk::Widget::DoInit(Tk::Text,$top)", que inicializa las vinculaciones si es necesario. Luego crea el nombre del widget con el formato ".text0" y llama a "Tk::text('.text0', background => $txtBg)" (nota la minúscula). El resultado de la llamada se bendice en "Tk::Text" y se llama al método "bindtags" para este objeto.

Ahora, lo único que queda por discutir es quién define los métodos "text" y "bindtags". La respuesta es que se definen en "tkWindow.c", y estos comandos se crean en el paquete "Tk" en el mismo barrido que creó el comando "Tk::wm" discutido anteriormente.

Por lo tanto, se llama al mismo código C que corresponde al procesamiento de los comandos TCL correspondientes aquí también (esta vez a través de la interfaz "XStoTk").

Dentro de "$text->insert('insert','Hola, mundo!');"
Como discutimos anteriormente, los subcomandos de los procedimientos de widget corresponden a la XSUB "XStoWidget". Esta XSUB sustituye el primer argumento $text (que es una referencia a un hash) a un valor apropiado de este hash, añade el argumento adicional después del primero que contiene el nombre del subcomando extraído de la parte de datos de la XSUB, y llama a la subrutina C de Tk correspondiente a través de "Call_Tk".
