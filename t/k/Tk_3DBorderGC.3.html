ARGUMENTOS

Tcl_Interp *interp (entrada)
Intérprete a usar para la notificación de errores.
Tk_Window tkwin (entrada)
Token para la ventana (para todos los procedimientos excepto Tk_Get3DBorder, debe ser la ventana para la que se asignó el borde).
Tcl_Obj *objPtr (entrada)
Puntero al valor cuya descripción del valor del color corresponde al fondo (áreas planas). Los bordes iluminados serán más brillantes que este y los bordes sombreados serán más oscuros que este.
const char *colorName (entrada)
Igual que objPtr excepto que el valor se proporciona como una cadena en lugar de un valor.
Drawable drawable (entrada)
Token X para ventana o mapa de bits; indica dónde se deben dibujar los gráficos. Debe ser la ventana X para tkwin o un mapa de bits con la misma pantalla y profundidad que tkwin.
Tk_3DBorder border (entrada)
Token para el borde previamente asignado en la llamada a Tk_Get3DBorder.
int x (entrada)
Coordenada X de la esquina superior izquierda del rectángulo que describe el borde o biselado, en píxeles.
int y (entrada)
Coordenada Y de la esquina superior izquierda del rectángulo que describe el borde o biselado, en píxeles.
int width (entrada)
Ancho del rectángulo que describe el borde o biselado, en píxeles.
int height (entrada)
Alto del rectángulo que describe el borde o biselado, en píxeles.
int borderWidth (entrada)
Ancho del borde en píxeles. Un valor positivo significa que el borde está dentro del rectángulo dado por x, y, width, height; un valor negativo significa que el borde está fuera del rectángulo.
int relief (entrada)
Indica la posición 3D del interior del valor en relación con el exterior; debe ser TK_RELIEF_RAISED, TK_RELIEF_SUNKEN, TK_RELIEF_GROOVE, TK_RELIEF_SOLID, o TK_RELIEF_RIDGE (también puede ser TK_RELIEF_FLAT para Tk_Fill3DRectangle).
XPoint *pointPtr (entrada)
Puntero a un array de puntos que describe el conjunto de vértices de un polígono. El polígono no necesita estar cerrado (se cerrará automáticamente si no lo está).
int numPoints (entrada)
Número de puntos en *pointPtr.
int polyBorderWidth (entrada)
Ancho del borde en píxeles. Si es positivo, el borde se dibuja a la izquierda de la trayectoria dada por pointPtr; si es negativo, el borde se dibuja a la derecha de la trayectoria. Si leftRelief es TK_RELIEF_GROOVE o TK_RELIEF_RIDGE, el borde se centrará en la trayectoria.
int leftRelief (entrada)
Altura del lado izquierdo del camino del polígono en relación con el derecho. TK_RELIEF_RAISED significa que el lado izquierdo debe aparecer más alto y TK_RELIEF_SUNKEN significa que el lado derecho debe aparecer más alto; TK_RELIEF_GROOVE y TK_RELIEF_RIDGE significan lo obvio. Para Tk_Fill3DPolygon, también se puede especificar TK_RELIEF_FLAT para indicar ninguna diferencia en la altura.
int leftBevel (entrada)
Si es distinto de cero, este biselado forma el lado izquierdo del valor; si es cero, forma el lado derecho.
int leftIn (entrada)
Si es distinto de cero, el borde izquierdo del biselado horizontal se inclina hacia adentro, de modo que la parte inferior del borde esté más a la derecha que la parte superior. Si es cero, el borde se inclina hacia afuera, de modo que la parte inferior esté más a la izquierda que la superior.
int rightIn (entrada)
Si es distinto de cero, el borde derecho del biselado horizontal se inclina hacia adentro, de modo que la parte inferior del borde esté más a la izquierda que la parte superior. Si es cero, el borde se inclina hacia afuera, de modo que la parte inferior esté más a la derecha que la superior.
int topBevel (entrada)
Si es distinto de cero, este biselado forma el lado superior del valor; si es cero, forma el lado inferior.
int which (entrada)
Especifica cuál de los contextos gráficos del borde se desea. Debe ser TK_3D_FLAT_GC, TK_3D_LIGHT_GC, o TK_3D_DARK_GC.

DESCRIPCIÓN

Estos procedimientos proporcionan instalaciones para dibujar bordes de ventana de una manera que produce una apariencia tridimensional. Tk_Alloc3DBorderFromObj asigna colores y mapas de bits necesarios para dibujar un borde en la ventana proporcionada por el argumento tkwin. El valor de objPtr es un nombre de color estándar de Tk que determina los colores del borde. El color indicado por objPtr no se usará realmente en el borde; indica el color de fondo de la ventana (es decir, un color para superficies planas). Las porciones iluminadas del borde aparecerán más brillantes que lo indicado por objPtr, y las porciones sombreadas del borde aparecerán más oscuras que objPtr.

Tk_Alloc3DBorderFromObj devuelve un token que puede ser utilizado en llamadas posteriores a Tk_Draw3DRectangle. Si ocurre un error al asignar información para el borde (por ejemplo, se dio un nombre de color no válido), se devuelve NULL y se deja un mensaje de error como resultado del intérprete interp. Si devuelve éxito, Tk_Alloc3DBorderFromObj almacena en caché la información sobre el valor de retorno en objPtr, lo que acelera las llamadas futuras a Tk_Alloc3DBorderFromObj con el mismo objPtr y tkwin.

Tk_Get3DBorder es idéntico a Tk_Alloc3DBorderFromObj excepto que el color se especifica con una cadena en lugar de un valor. Esto evita que Tk_Get3DBorder almacene en caché el valor de retorno, por lo que Tk_Get3DBorder es menos eficiente que Tk_Alloc3DBorderFromObj.

Tk_Get3DBorderFromObj devuelve el token de un borde existente, dado el nombre de la ventana y el color utilizados para crear el borde. Tk_Get3DBorderFromObj no crea realmente el borde; ya debe haber sido creado con una llamada anterior a Tk_Alloc3DBorderFromObj o Tk_Get3DBorder. El valor de retorno se almacena en caché en objPtr, lo que acelera las llamadas futuras a Tk_Get3DBorderFromObj con el mismo objPtr y tkwin.

Una vez que se ha creado una estructura de borde, se puede invocar Tk_Draw3DRectangle para dibujar el borde. El argumento tkwin especifica la ventana para la que se asignó el borde, y drawable especifica una ventana o mapa de bits en el que se dibujará el borde. Drawable no necesita referirse a la misma ventana que tkwin, pero debe referirse a un mapa de bits o ventana compatible: uno asociado con la misma pantalla y profundidad que tkwin. Los argumentos x, y, width y height definen el cuadro delimitador de la región del borde dentro de drawable (normalmente x e y son cero y width y height son las dimensiones de la ventana), y borderWidth especifica el número de píxeles ocupados realmente por el borde. El argumento relief indica cuál de varios efectos tridimensionales se desea: TK_RELIEF_RAISED significa que el interior del rectángulo debe parecer elevado en relación con el exterior del rectángulo, y TK_RELIEF_SUNKEN significa que el interior debe parecer hundido. TK_RELIEF_GROOVE y TK_RELIEF_RIDGE significan que debe parecer haber una ranura o una cresta alrededor del exterior del rectángulo.

ARGUMENTS

All of the procedures described in this section manage borders for creating
three-dimensional effects in Tk widgets. Borders are specified by color
strings (e.g., "red" or "#ff0000") or by Tcl objects containing
color strings. The actual border graphics are created on demand and cached for
reuse.

DESCRIPTION

The procedures Tk_Alloc3DBorderFromObj and Tk_Get3DBorder are used to allocate a border. Tk_Alloc3DBorderFromObj allocates a border from a Tcl object containing a color string; Tk_Get3DBorder allocates a border from a null-terminated string specifying a color. In each case, tkwin is a window within which the border will be used (used to get screen and colormap information), and value or colorString specifies the color to use for the border. If a border with the given characteristics already exists, its token is returned. Otherwise, a new border is created, cached, and its token is returned. The border token should be freed using Tk_Free3DBorderFromObj or Tk_Free3DBorder when it is no longer needed.

The procedures Tk_Fill3DRectangle and Tk_Draw3DRectangle may be used to draw rectangles with a three-dimensional appearance. Tk_Fill3DRectangle fills the rectangular area specified by x, y, width, and height with the background color from the border argument. It then calls Tk_Draw3DRectangle to draw a border around the area. The borderwidth argument specifies how thick the border should be, and relief specifies the type of border to draw. Tk_Draw3DRectangle draws only the border itself, without filling the interior. For both procedures, the relief argument may be one of TK_RELIEF_FLAT, TK_RELIEF_RAISED`, or `TK_RELIEF_SUNKEN. TK_RELIEF_FLAT means no border should be drawn; the rectangle is just filled with the background color. TK_RELIEF_RAISED and TK_RELIEF_SUNKEN produce borders that appear raised or sunken, respectively. The border colors are derived from the border argument. Tk_Fill3DRectangle first fills the rectangular area with the background color (one corresponding to the color used to create border). Then it calls Tk_Draw3DRectangle to draw a border just inside the outer edge of the rectangular area. The argument relief indicates the desired effect (TK_RELIEF_FLAT means no border should be drawn; all that happens is to fill the rectangle with the background color).

The procedure Tk_Draw3DPolygon may be used to draw more complex shapes with a three-dimensional appearance. The pointPtr and numPoints arguments define a trajectory, polyBorderWidth indicates how wide the border should be (and on which side of the trajectory to draw it), and leftRelief indicates which side of the trajectory should appear raised. Tk_Draw3DPolygon draws a border around the given trajectory using the colors from border to produce a three-dimensional appearance. If the trajectory is non-self-intersecting, the appearance will be a raised or sunken polygon shape. The trajectory may be self-intersecting, although it's not clear how useful this is.

Tk_Fill3DPolygon is to Tk_Draw3DPolygon what Tk_Fill3DRectangle is to Tk_Draw3DRectangle: it fills the polygonal area with the background color from border, then calls Tk_Draw3DPolygon to draw a border around the area (unless leftRelief is TK_RELIEF_FLAT; in this case no border is drawn).

The procedures Tk_3DVerticalBevel and Tk_3DHorizontalBevel provide lower-level drawing primitives that are used by procedures such as Tk_Draw3DRectangle. These procedures are also useful in their own right for drawing rectilinear border shapes. Tk_3DVerticalBevel draws a vertical beveled edge, such as the left or right side of a rectangle, and Tk_3DHorizontalBevel draws a horizontal beveled edge, such as the top or bottom of a rectangle. Each procedure takes x, y, width, and height arguments that describe the rectangular area of the beveled edge (e.g., width is the border width for Tk_3DVerticalBevel). The leftBorder and topBorder arguments indicate the position of the border relative to the “inside” of the value, and relief indicates the relief of the inside of the value relative to the outside. Tk_3DVerticalBevel just draws a rectangular region. Tk_3DHorizontalBevel draws a trapezoidal region to generate mitered corners; it should be called after Tk_3DVerticalBevel (otherwise Tk_3DVerticalBevel will overwrite the mitering in the corner). The leftIn and rightIn arguments to Tk_3DHorizontalBevel describe the mitering at the corners; a value of 1 means that the bottom edge of the trapezoid will be shorter than the top, 0 means it will be longer. For example, to draw a rectangular border the top bevel should be drawn with 1 for both leftIn and rightIn, and the bottom bevel should be drawn with 0 for both arguments.

The procedure Tk_SetBackgroundFromBorder will modify the background pixel and/or pixmap of tkwin to produce a result compatible with border. For color displays, the resulting background will just be the color specified when border was created; for monochrome displays, the resulting background will be a light stipple pattern, in order to distinguish the background from the illuminated portion of the border.

Given a token for a border, the procedure Tk_NameOf3DBorder will return the color name that was used to create the border.

The procedure Tk_3DBorderColor returns the XColor structure that will be used for flat surfaces drawn for its border argument by procedures like Tk_Fill3DRectangle. The return value corresponds to the color name that was used to create the border. The XColor, and its associated pixel value, will remain allocated as long as border exists.

The procedure Tk_3DBorderGC returns one of the X graphics contexts that are used to draw the border. The argument which selects which one of the three possible GC's: TK_3D_FLAT_GC returns the context used for flat surfaces, TK_3D_LIGHT_GC returns the context for light shadows, and TK_3D_DARK_GC returns the context for dark shadows.

When a border is no longer needed, Tk_Free3DBorderFromObj or Tk_Free3DBorder should be called to release the resources associated with it. For Tk_Free3DBorderFromObj the border to release is specified with the window and color name used to create the border; for Tk_Free3DBorder the border to release is specified with the Tk_3DBorder token for the border. There should be exactly one call to Tk_Free3DBorderFromObj or Tk_Free3DBorder for each call to Tk_Alloc3DBorderFromObj or Tk_Get3DBorder.
