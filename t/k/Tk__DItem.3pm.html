NOMBRE

Tk::DItem - Elementos de Pantalla de Tix

SINOPSIS

DESCRIPCIÓN

Los Elementos de Pantalla y Tipos de Pantalla de Tix están diseñados para resolver un problema general: muchos widgets de Tix (tanto existentes como planificados) muestran muchos elementos de muchos tipos simultáneamente.

Por ejemplo, un widget de lista de árbol (ver Tk::HList) puede mostrar elementos de imágenes, texto plano y subventanas en forma de jerarquía. Otro widget, el widget de lista tabular (ver Tk::TList) también muestra elementos de los mismos tipos, aunque organiza los elementos en forma tabular. Otro widget, el widget de hoja de cálculo (ver Tk::TixGrid), también muestra elementos de tipos similares, pero en un formato aún diferente.

En estos ejemplos, los elementos de pantalla en diferentes widgets solo difieren en cómo son organizados por el widget anfitrión. En Tix, los elementos de pantalla están claramente separados de los widgets anfitriones. La ventaja es doble: primero, la creación y configuración de elementos de pantalla se vuelven uniformes en diferentes widgets anfitriones. Segundo, se pueden agregar nuevos tipos de elementos de pantalla sin necesidad de modificar los widgets anfitriones existentes.

En cierto modo, los elementos de pantalla de Tix son similares a los elementos dentro del widget canvas de Tk. Sin embargo, a diferencia de los elementos de pantalla de Tix, los elementos del canvas no son independientes del widget canvas; esto hace imposible usar los elementos del canvas dentro de otros tipos de widgets TK.

La apariencia de un elemento de pantalla se controla mediante un conjunto de atributos. Se observa que cada uno de los atributos generalmente cae en una de dos categorías: ``individual'' o ``colectivo''. Por ejemplo, los elementos de texto dentro de un widget HList pueden mostrar una cadena de texto diferente; sin embargo, en la mayoría de los casos, los elementos de texto comparten el mismo color, fuente y espaciado. En lugar de mantener una versión duplicada de los mismos atributos dentro de cada elemento de pantalla, sería ventajoso colocar los atributos colectivos en un objeto especial llamado estilo de pantalla. Primero, está la preocupación por el espacio: un widget anfitrión puede tener muchos miles de elementos; mantener atributos duplicados sería muy desperdiciador. Segundo, cuando sea necesario cambiar un atributo colectivo, como cambiar el color de primer plano de todos los elementos de texto a rojo, será más eficiente cambiar solo el objeto de estilo de pantalla que modificar todos los elementos de texto uno por uno.

Los atributos de un elemento de pantalla se almacenan así en dos lugares: tiene un conjunto de opciones de elemento para almacenar sus atributos individuales. Cada elemento de pantalla también se asocia con un estilo de pantalla, que especifica los atributos colectivos de todos los elementos asociados consigo mismo.

La división entre los atributos individuales y colectivos es fija y no se puede cambiar. Por lo tanto, cuando sea necesario que algunos elementos difieran en sus atributos colectivos, se pueden usar dos o más estilos de pantalla. Por ejemplo, suponga que desea mostrar dos columnas de elementos de texto dentro de un widget HList, una columna en rojo y la otra en azul. Puede crear un objeto TextStyle llamado "$red" que define un fondo rojo, y otro llamado "$blue", que define un fondo azul. Luego puede asociar todos los elementos de texto de la primera columna a "$red" y la segunda columna a "$blue".

TIPOS Y OPCIONES DE ELEMENTOS DE PANTALLA

Actualmente hay tres tipos de elementos de pantalla: texto, imagetext y ventana.

ELEMENTOS IMAGETEXT

Los elementos de pantalla del tipo imagetext se utilizan para mostrar una imagen junto con una cadena de texto. Los elementos Imagetext admiten las siguientes opciones:

Opciones de Elemento Imagetext

Nombre: bitmap
Clase: Bitmap
Switch: -bitmap
Especifica el bitmap a mostrar en el elemento.
Nombre: image
Clase: Image
Switch: -image
Especifica la imagen a mostrar en el elemento. Cuando se especifican tanto la opción -bitmap como la opción -image, solo se mostrará la imagen.
Nombre: imageTextStyle
Clase: ImageTextStyle
Switch: -style
Especifica el estilo de pantalla a usar para este elemento. Debe ser el nombre de un estilo de pantalla imagetext que ya se haya creado con ItemStyle.
Nombre: showImage
Clase: ShowImage
Switch: -showimage
Un valor booleano que especifica si se debe mostrar la imagen/bitmap.
Nombre: showText
Clase: ShowText
Switch: -showtext
Un valor booleano que especifica si se debe mostrar la cadena de texto.
Nombre: text
Clase: Text
Switch: -text
Especifica la cadena de texto a mostrar en el elemento.
Nombre: underline
Clase: Underline
Switch: -underline
Especifica el índice entero de un carácter a subrayar en la cadena de texto en el elemento. 0 corresponde al primer carácter del texto que se muestra en el widget, 1 al siguiente carácter, y así sucesivamente.

Opciones de Estilo Imagetext

La información de estilo de los elementos imagetext se almacena en el estilo de pantalla imagetext. Se admiten las siguientes opciones:

OPCIONES ESTÁNDAR

-activebackground -activeforeground -anchor -background -disabledbackground -disabledforeground -foreground -font -justify -padx -pady -selectbackground -selectforeground -wraplength

Consulte Tk::options para obtener detalles de las opciones estándar.

OPCIONES ESPECÍFICAS DEL ESTILO

Nombre: gap
Clase: Gap
Switch: -gap
Especifica la distancia entre el bitmap/imagen y la cadena de texto, en número de píxeles.
Nombre: textAnchor
Clase: TextAnchor
Switch: -textanchor
La posición de anclaje en la imagen a la que se adjunta la parte de texto. Esta es una adición de perl/Tk. Por defecto es e para compatibilidad con Tix estándar. Los casos interesantes son
n
El texto está centrado encima de la imagen.
s
El texto está centrado debajo de la imagen.
e
El texto está centrado a la derecha de la imagen.
w
El texto está centrado a la izquierda de la imagen.
c
El texto está centrado sobre la imagen.

El sw,

se, ne, y b<nw> los casos parecen verdaderos.

Para que los elementos se alineen correctamente, suele ser necesario especificar -anchor también. Por ejemplo, con el valor predeterminado e, el anclaje del elemento como un todo w hará que las imágenes se alineen arriba, abajo, a la izquierda, con el texto adherido al lado derecho.

Los elementos de tipo text se utilizan para mostrar una cadena de texto en un widget. Los elementos de tipo text soportan las siguientes opciones:

Opciones de Elemento de Texto

Nombre: textStyle
Clase: TextStyle
Switch: -style
Indica el estilo de visualización a usar para este elemento de texto. Debe ser el nombre de un estilo de text que ya ha sido creado con ItemStyle.
Nombre: text
Clase: Text
Switch: -text
Indica la cadena de texto a mostrar en el elemento.
Nombre: underline
Clase: Underline
Switch: -underline
Indica el índice del carácter a subrayar en el elemento. 0 corresponde al primer carácter de la cadena de texto mostrada en el widget, 1 al siguiente y así sucesivamente.

Opciones de Estilo de Texto

OPCIONES ESTÁNDAR

-activebackground -activeforeground -anchor -background -disabledbackground -disabledforeground -foreground -font -justify -padx -pady -selectbackground -selectforeground -wraplength

Ver Tk::options para detalles de las opciones estándar.

ELEMENTOS DE VENTANA

Los elementos de tipo window se utilizan para mostrar una sub-ventana en un widget. Los elementos Window soportan las siguientes opciones:

Opciones de Elemento de Ventana

Nombre: windowStyle
Clase: WindowStyle
Switch: -style
Indica el estilo de visualización a usar para este elemento de ventana. Debe ser el nombre de un estilo de ventana window que ya ha sido creado con el método ItemStyle.
Nombre: window
Clase: Window
Switch: -window
Alias: -widget
Indica la sub-ventana a mostrar en el elemento.

Opciones de Estilo de Ventana

OPCIONES ESTÁNDAR DE ESTILO

-anchor -padx -pady

Ver Tk::options para detalles de las opciones estándar.

CREACIÓN DE ELEMENTOS DE VISUALIZACIÓN

Los elementos de visualización no existen por sí mismos y no pueden ser creados independientemente de los widgets en los que residen. En general, los elementos de visualización se crean mediante métodos especiales de sus widgets ``host''. Por ejemplo, los widgets HList tienen el método item para crear nuevos elementos de visualización. El siguiente código crea un nuevo elemento de texto en la tercera columna de la entrada foo dentro de un widget HList:

my $hlist = $parent->HList(-columns=>3);
$hlist->add('foo');
$hlist->itemCreate('foo', 2, -itemtype=>'text', -text=>'Hello');

El método itemCreate del widget HList acepta un número variable de argumentos. El argumento especial -itemtype especifica qué tipo de elemento de visualización se va a crear. Las opciones válidas para este tipo de elementos pueden especificarse mediante pares de opciones option-value.

Después de crear el elemento de visualización, pueden configurarse o eliminarse usando los métodos proporcionados por el widget que aloja el elemento. Por ejemplo, el widget HList tiene métodos itemConfigure, itemCget y itemDelete para acceder a los elementos de visualización.

CREACIÓN Y MANIPULACIÓN DE ESTILOS DE ELEMENTO

Los estilos de elemento se crean con ItemStyle:

SINTAXIS

   $widget->ItemStyle(itemType ?,-stylename=>name? ?,-refwindow=>pathName? ?,option=>value, ...>?);

itemType debe ser uno de los tipos de elementos de visualización existentes, como text, imagetext, window o cualquier tipo nuevo agregado por el usuario. Los argumentos adicionales pueden proporcionarse en uno o más pares de opciones option-value. option puede ser cualquiera de las opciones válidas para este estilo de elemento o cualquiera de los siguientes:

-stylename => name
Indica un nombre para este estilo. Si no se especifica, se elegirá un nombre por defecto para este estilo.
-refwindow => $otherwidget
Indica una ventana para usar como valor por defecto de los estilos de elemento. Si no se especifica, se utilizará el $widget. Los valores por defecto para los estilos de elemento pueden establecerse mediante las bases de opciones. El siguiente ejemplo establece las opciones -disablebackground y -disabledforeground de un estilo de texto mediante la base de opciones: 
$widget->optionAdd('*table.list*disabledForeground' => 'blue');
$widget->optionAdd('*table.list*disabledBackground' => 'darkgray');
$widget->ItemStyle('text', -refwindow => $table_list, -fg => 'red');

Al usar la base de opciones para establecer las opciones de los estilos de elementos, podemos evitar la codificación hard-coding de los valores de opción y permitir al usuario más flexibilidad en la personalización. Ver Tk::option para una descripción detallada de la base de opciones.

MÉTODOS DE ESTILO

El método ItemStyle crea un objeto. Este objeto soporta los métodos configure y cget descritos en Tk::options, que pueden utilizarse para consultar y modificar las opciones descritas anteriormente.

Los siguientes métodos adicionales están disponibles para los estilos de elemento:

$style->delete
Destruye este objeto de estilo de elemento.

EJEMPLO

El siguiente ejemplo crea dos columnas de datos en un widget HList. La primera columna está en rojo y la segunda en azul. Los colores de las columnas son controlados por dos estilos de texto diferentes. También el ancla y la fuente de la segunda columna se eligen de manera que los datos de entrada se alineen correctamente.

use strict;
use Tk;
use Tk::HList;
use Tk::ItemStyle;
my $mw = MainWindow->new();
my $hlist = $mw->HList(-columns=>2)->pack;
my $red  = $hlist->ItemStyle('text', -foreground=>'#800000');
my $blue = $hlist->ItemStyle('text', -foreground=>'#000080', -anchor=>'e');
my $e;
foreach ([Joe => '$10,000'], [Peter => '$20,000'],
         [Raj => '$90,000'],  [Zinh => '$0']) {
    $e = $hlist->addchild("");
    $hlist->itemCreate($e, 0, -itemtype=>'text',
             -text=>$_->[0], -style=>$red );
    $hlist->itemCreate($e, 1, -itemtype=>'text',
             -text=>$_->[1], -style=>$blue);
}
Tk::MainLoop;
