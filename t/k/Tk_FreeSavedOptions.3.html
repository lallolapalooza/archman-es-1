ARGUMENTOS

Tcl_Interp *interp (entrada)
Un intérprete Tcl. La mayoría de los procedimientos usan esto solo para devolver mensajes de error; si es NULL, no se devuelven mensajes de error. Para Tk_CreateOptionTable el valor no puede ser NULL; da el intérprete en el que se utilizará la tabla de opciones.
const Tk_OptionSpec *templatePtr (entrada)
Punta a una matriz de información estática que describe las opciones de configuración que se admiten. Se utiliza para construir una Tk_OptionTable. La información a la que apunta este argumento debe existir durante la vida útil de la Tk_OptionTable.
Tk_OptionTable optionTable (entrada)
Token para una tabla de opciones. Debe haber sido devuelto por una llamada previa a Tk_CreateOptionTable.
char *recordPtr (entrada/salida)
Punta a una estructura en la que se almacenan los valores de las opciones de configuración; los campos de este registro son modificados por procedimientos como Tk_SetOptions y leídos por procedimientos como Tk_GetOptionValue.
Tk_Window tkwin (entrada)
Para opciones como TK_OPTION_COLOR, este argumento indica la ventana en la que se utilizará la opción. Si optionTable no utiliza opciones dependientes de la ventana, entonces se puede suministrar un valor NULL para este argumento.
int objc (entrada)
Número de valores en objv.
Tcl_Obj *const *objv (entrada)
Argumentos de línea de comandos para establecer opciones de configuración.
Tk_SavedOptions *savePtr (salida)
Si no es NULL, la estructura apuntada por este argumento se rellena con los valores antiguos de las opciones que se modificaron y los valores antiguos se restauran automáticamente si ocurre un error en Tk_SetOptions.
int *maskPtr (salida)
Si no es NULL, la palabra apuntada por maskPtr se rellena con el OR a nivel de bits de los campos typeMask de las opciones que se modificaron.
Tk_SavedOptions *savedPtr (entrada/salida)
Punta a una estructura rellenada previamente por Tk_SetOptions con los valores antiguos de las opciones modificadas.
Tcl_Obj *namePtr (entrada)
El valor de este objeto es el nombre de una opción particular. Si se pasa NULL a Tk_GetOptionInfo, se devuelve información para todas las opciones. No debe ser NULL al llamar a Tk_GetOptionValue.
nombre de tipo type (entrada)
El nombre del tipo de un registro.
nombre de campo field (entrada)
El nombre de un campo en registros del tipo type.

DESCRIPCIÓN

Estos procedimientos manejan la mayoría de los detalles de la interpretación de opciones de configuración, como las de los widgets de Tk. Dada una descripción de las opciones que se admiten, estos procedimientos manejan todos los detalles de la interpretación de opciones y el almacenamiento de sus valores en una estructura C asociada con el widget u objeto. Los procedimientos fueron diseñados principalmente para widgets en Tk, pero también se pueden utilizar para otros tipos de objetos que tengan opciones de configuración. En el resto de esta página del manual, se utilizará “widget” para referirse al objeto cuyas opciones se están gestionando; en la práctica, el objeto puede no ser realmente un widget. El término “registro de widget” se utiliza para referirse a la estructura a nivel de C en la que se almacena información sobre un widget u objeto particular.

Tenga en cuenta que la forma más fácil de aprender a usar estos procedimientos es mirar un ejemplo funcional. En Tk, el ejemplo más simple es el código que implementa la familia de widgets de botones, que se encuentra en tkButton.c. Otros ejemplos se encuentran en tkSquare.c y tkMenu.c.

Para utilizar estos procedimientos, el código que implementa el widget debe contener una matriz estática de estructuras Tk_OptionSpec. Esta es una plantilla que describe las diversas opciones admitidas por esa clase de widget; hay una plantilla separada para cada tipo de widget. La plantilla contiene información como el nombre de cada opción, su tipo, su valor predeterminado y dónde se almacena el valor de la opción en el registro del widget. Consulte PLANTILLAS a continuación para más detalles.

Para procesar las opciones de configuración de manera eficiente, la plantilla estática debe ser aumentada con información adicional que solo está disponible en tiempo de ejecución. El procedimiento Tk_CreateOptionTable crea esta información dinámica a partir de la plantilla y devuelve un token Tk_OptionTable que describe la información estática y dinámica. Todos los demás procedimientos, como Tk_SetOptions, toman un token Tk_OptionTable como argumento. Típicamente, Tk_CreateOptionTable se llama la primera vez que se crea un widget de una clase particular y la Tk_OptionTable resultante se utiliza en el futuro para todos los widgets de esa clase. Una Tk_OptionTable solo se puede usar en un intérprete, dado por el argumento interp a Tk_CreateOptionTable. Cuando una tabla de opciones ya no es necesaria, se debe llamar a Tk_DeleteOptionTable para liberar todos sus recursos. Todas las tablas de opciones para un intérprete Tcl se liberan automáticamente si se elimina el intérprete.

Tk_InitOptions se invoca cuando se crea un nuevo widget para establecer los valores predeterminados. Tk_InitOptions recibe un token para una tabla de opciones (optionTable) y un puntero a un registro de widget (recordPtr), que es la estructura C que contiene información sobre este widget. Tk_InitOptions utiliza la información de la tabla de opciones para elegir un valor predeterminado apropiado para cada opción, y luego almacena el valor predeterminado directamente en el registro del widget, sobrescribiendo cualquier información que ya estuviera presente en el registro del widget. Tk_InitOptions normalmente devuelve TCL_OK. Si ocurrió un error al establecer los valores predeterminados (por ejemplo, porque un valor predeterminado era erróneo), entonces se devuelve TCL_ERROR y se deja un mensaje de error en el resultado de interp si interp no es NULL. Para cualquier opción de configuración de un widget que tenga TK_OPTION_DONT_SET_DEFAULT establecido en su campo flags, la inicialización anterior se omite por completo, véase más abajo.

Tk_SetOptions se invoca para modificar las opciones de configuración basadas en la información especificada en un comando Tcl. El comando podría ser uno que crea un nuevo widget, o un comando que modifica opciones en un widget existente. Los argumentos objc y objv describen los valores de los argumentos del comando Tcl. Objv debe contener un número par de objetos: el primer objeto de cada par da el nombre de una opción y el segundo objeto da el nuevo valor para esa opción. Tk_SetOptions busca cada nombre en optionTable, comprueba que el nuevo valor de la opción se ajuste al tipo en optionTable, y almacena el valor de la opción en el registro del widget dado por recordPtr. Tk_SetOptions normalmente devuelve TCL_OK. Si ocurrió un error (como un nombre de opción desconocido o un valor de opción ilegal), entonces se devuelve TCL_ERROR y se deja un mensaje de error en el resultado de interp si interp no es NULL.

Tk_SetOptions tiene dos características adicionales. Primero, si el argumento maskPtr no es NULL, entonces apunta a un valor entero que se rellena con información sobre las opciones que se modificaron. Para cada opción en la plantilla pasada a Tk_CreateOptionTable hay un campo typeMask. Los bits de este campo los define el código que implementa el widget; por ejemplo, cada bit podría corresponder a una opción de configuración particular. Alternativamente, los bits podrían usarse funcionalmente. Por ejemplo, un bit podría usarse para redibujar: todas las opciones que afectan la visualización del widget, de modo que cambiar la opción requiera que el widget se redibuje, podrían tener ese bit establecido. Otro bit podría indicar que la geometría del widget debe recalcularse, etc. Tk_SetOptions combina los campos typeMask de

The second additional feature of Tk_SetOptions has to do with error recovery. If an error occurs while processing configuration options, this feature makes it possible to restore all the configuration options to their previous values. Errors can occur either while processing options in Tk_SetOptions or later in the caller. In many cases the caller does additional processing after Tk_SetOptions returns; for example, it might use an option value to set a trace on a variable and may detect an error if the variable is an array instead of a scalar. Error recovery is enabled by passing in a non-NULL value for the savePtr argument to Tk_SetOptions; this should be a pointer to an uninitialized Tk_SavedOptions structure on the caller's stack. Tk_SetOptions overwrites the structure pointed to by savePtr with information about the old values of any options modified by the procedure. If Tk_SetOptions returns successfully, the caller uses the structure in one of two ways. If the caller completes its processing of the new options without any errors, then it must pass the structure to Tk_FreeSavedOptions so that the old values can be freed. If the caller detects an error in its processing of the new options, then it should pass the structure to Tk_RestoreSavedOptions, which will copy the old values back into the widget record and free the new values. If Tk_SetOptions detects an error then it automatically restores any options that had already been modified and leaves *savePtr in an empty state: the caller need not call either Tk_FreeSavedOptions or Tk_RestoreSavedOptions. If the savePtr argument to Tk_SetOptions is NULL then Tk_SetOptions frees each old option value immediately when it sets a new value for the option. In this case, if an error occurs in the third option, the old values for the first two options cannot be restored.

Tk_GetOptionValue returns the current value of a configuration option for a particular widget. The namePtr argument contains the name of an option; Tk_GetOptionValue uses optionTable to lookup the option and extract its value from the widget record pointed to by recordPtr, then it returns an object containing that value. If an error occurs (e.g., because namePtr contains an unknown option name) then NULL is returned and an error message is left in interp's result unless interp is NULL.

Tk_GetOptionInfo returns information about configuration options in a form suitable for configure widget commands. If the namePtr argument is not NULL, it points to an object that gives the name of a configuration option; Tk_GetOptionInfo returns an object containing a list with five elements, which are the name of the option, the name and class used for the option in the option database, the default value for the option, and the current value for the option. If the namePtr argument is NULL, then Tk_GetOptionInfo returns information about all options in the form of a list of lists; each sublist describes one option. Synonym options are handled differently depending on whether namePtr is NULL: if namePtr is NULL then the sublist for each synonym option has only two elements, which are the name of the option and the name of the other option that it refers to; if namePtr is non-NULL and names a synonym option then the object returned is the five-element list for the other option that the synonym refers to. If an error occurs (e.g., because namePtr contains an unknown option name) then NULL is returned and an error message is left in interp's result unless interp is NULL.

Tk_FreeConfigOptions must be invoked when a widget is deleted. It frees all of the resources associated with any of the configuration options defined in recordPtr by optionTable.

The Tk_Offset macro is provided as a safe way of generating the objOffset and internalOffset values for entries in Tk_OptionSpec structures. It takes two arguments: the name of a type of record, and the name of a field in that record. It returns the byte offset of the named field in records of the given type.

TEMPLATES

The array of Tk_OptionSpec structures passed to Tk_CreateOptionTable via its templatePtr argument describes the configuration options supported by a particular class of widgets. Each structure specifies one configuration option and has the following fields:

typedef struct {
    Tk_OptionType type;
    const char *optionName;
    const char *dbName;
    const char *dbClass;
    const char *defValue;
    int objOffset;
    int internalOffset;
    int flags;
    const void *clientData;
    int typeMask;
} Tk_OptionSpec;
The type field indicates what kind of configuration option this is (e.g. TK_OPTION_COLOR for a color value, or TK_OPTION_INT for an integer value). Type determines how the value of the option is parsed (more on this below). The optionName field is a string such as -font or -bg; it is the name used for the option in Tcl commands and passed to procedures via the objc or namePtr arguments. The dbName and dbClass fields are used by Tk_InitOptions to look up a default value for this option in the option database; if dbName is NULL then the option database is not used by Tk_InitOptions for this option. The defValue field specifies a default value for this configuration option if no value is specified in the option database. The objOffset and internalOffset fields indicate where to store the value of this option in widget records (more on this below); values for the objOffset and internalOffset fields should always be generated with the Tk_Offset macro. The flags field contains additional information to control the processing of this configuration option (see below for details). ClientData provides additional type-specific data needed by certain types. For instance, for TK_OPTION_COLOR types, clientData is a string giving the default value to use on monochrome displays. See the descriptions of the different types below for details. The last field, typeMask, is used by Tk_SetOptions to return information about which options were modified; see the description of Tk_SetOptions above for details.

When Tk_InitOptions and Tk_SetOptions store the value of an option into the widget record, they can do it in either of two ways. If the objOffset field of the Tk_OptionSpec is greater than or equal to zero, then the value of the option is stored as a (Tcl_Obj *) at the location in the widget record given by objOffset. If the internalOffset field of the Tk_OptionSpec is greater than or equal to zero, then the value of the option is stored in a type-specific internal form at the location in the widget record given by internalOffset. For example, if the option's type is TK_OPTION_INT then the internal form is an integer. If the objOffset or internalOffset field is negative then the value is not stored in that form. At least one of the offsets must be greater than or equal to zero.

The flags field consists of one or more bits ORed together. The following flags are supported:

TK_OPTION_NULL_OK
If this bit is set for an option then an empty string will be accepted as the value for the option and the resulting internal form will be a NULL pointer, a zero value, or None, depending on the type of the option. If the flag is not set then empty strings will result in errors. TK_OPTION_NULL_OK is typically used to allow a feature to be turned off entirely, e.g. set a cursor value to None so that a window simply inherits its parent's cursor. Not all option types support the TK_OPTION_NULL_OK flag; for those that do, there is an explicit indication of that fact in the descriptions below.
TK_OPTION_DONT_SET_DEFAULT
If this bit is set for an option then no default value will be set in Tk_InitOptions for this option. Neither the option database, nor any system default value, nor optionTable are used to give a default value to this option. Instead it is assumed that the caller has already supplied a default value in the widget code.

The type field of each Tk_OptionSpec structure determines how to parse the value of that configuration option. The legal value for type, and the corresponding actions, are described below. If the type requires a tkwin value to be passed into procedures like Tk_SetOptions, or if it uses the clientData field of the Tk_OptionSpec, then it is indicated explicitly; if not mentioned, the type requires neither tkwin nor clientData.

TK_OPTION_ANCHOR
The value must be a standard anchor position such as ne or center. The internal form is a Tk_Anchor value like the ones returned by Tk_GetAnchorFromObj.
TK_OPTION_BITMAP
The value must be a standard Tk bitmap name. The internal form is a Pixmap token like the ones returned by Tk_AllocBitmapFromObj. This option type requires tkwin to be supplied to procedures such as Tk_SetOptions, and it supports the TK_OPTION_NULL_OK flag.
TK_OPTION_BOOLEAN
The value must be a standard boolean value such as true or no. The internal form is an integer with value 0 or 1. Note that if the objOffset field is not used, information about the original value of this option will be lost.
TK_OPTION_BORDER
The value must be a standard color name such as red or #ff8080. The internal form is a Tk_3DBorder token like the ones returned by Tk_Alloc3DBorderFromObj. This option type requires tkwin to be supplied to procedures such as Tk_SetOptions, and it supports the TK_OPTION_NULL_OK flag.

ARGUMENTS

interp
Used for error reporting.
recordPtr
Address of the widget record.
specPtr
Points to an array of Tk_OptionSpec structures that describe the options for the widget.
objc

Arguments from the configuration command (e.g. widget configure ...).

DESCRIPTION

These procedures are used by Tk widgets to implement their configuration option processing. The main work is done by Tk_SetOptions, which processes a list of configuration options and updates the widget record accordingly. Tk_GetOptionValue retrieves the value of a single option, Tk_GetOptionInfo retrieves information about all options, and Tk_RestoreSavedOptions and Tk_FreeSavedOptions are used to manage saved option values.

A widget's configuration options are described by an array of Tk_OptionSpec structures. Each structure in the array contains information about one option, including its name, the type of its value, where to store the value in the widget record, and procedures to call for converting values to and from Tcl objects. The array must be terminated by an entry with a NULL name.

The Tk_OptionSpec structure has the following fields:

name
The name of the option (e.g., "background"). For convenience, this field can be specified as NULL to indicate the end of the array.
objOffset
If non-negative, this is the byte offset within the widget record where a Tcl_Obj* pointer to the option's value will be stored. If negative, the option value is stored at the offset specified by internalOffset.
parseProc
A procedure that converts a Tcl_Obj into the internal representation for the option and stores it in the widget record at the offset specified by internalOffset. This procedure is called by Tk_SetOptions.
printProc
A procedure that converts the internal representation of the option's value into a Tcl_Obj. This procedure is called by Tk_GetOptionValue.
clientData
An arbitrary value that is passed to parseProc and printProc. This is typically used to pass information about the option's type, such as the desired integer range or the names of symbolic constants.
flags
A bitmask containing flags that control how the option is processed. The following flags are supported:
TK_OPTION_NULL_OK
The option's value may be NULL.
TK_OPTION_AUTOSCROLL
For options that specify a scrollbar position (e.g., "xscrollcommand" or "yscrollcommand"), this flag causes the scrollbar to be automatically configured when the widget's size changes.
TK_OPTION_FOREIGN
This option is not settable by the user, but is read-only.
TK_OPTION_READ_ONLY
This option is not settable by the user, but is read-only.
TK_OPTION_SPECIAL
This option is a special-case option that is handled by the widget's own code, not by the generic option processing code.

The procedures parseProc, printProc, restoreProc and freeProc all have the same signature:

clientData
A copy of the clientData field from the Tk_OptionSpec structure.
interp
A pointer to the Tcl interpreter.
tkwin
The widget's window.
value
For parseProc, this points to a string representation of the option's value. For printProc, this points to the internal representation of the option's value. For restoreProc and freeProc, this points to the internal representation of the option's value.
offset
For parseProc, this is the offset within the widget record where the internal representation of the option's value should be stored. For restoreProc and freeProc, this is the offset within the widget record where the internal representation of the option's value is stored.
savedOptionsPtr
For restoreProc and freeProc, this points to the Tk_SavedOptions structure containing the saved value.

The parseProc procedure is invoked by Tk_SetOptions to convert a string representation of an option's value into an internal representation and store it in the widget record. The interp argument is used for error reporting. The value argument is the string representation of the option's value. The offset argument is the offset within the widget record where the internal representation should be stored. ParseProc should return a standard Tcl result (TCL_OK or TCL_ERROR).

The printProc procedure is invoked by Tk_GetOptionValue to convert an internal representation of an option's value into a string representation. The interp argument is used for error reporting. The value argument points to the internal representation of the option's value. The procedure should return a pointer to a dynamically allocated string containing the string representation of the value. The caller is responsible for freeing this string.

The restoreProc procedure is invoked by Tk_RestoreSavedOptions to restore a previously saved internal representation of an option's value. The value argument points to the location in the widget record where the option's value should be stored. The savedOptionsPtr argument points to the Tk_SavedOptions structure containing the saved value. RestoreProc should copy the saved value to the specified location.

The freeProc procedure is invoked by Tk_SetOptions and Tk_FreeSavedOptions to free any dynamically allocated storage associated with an option's internal representation. The value argument points to the location in the widget record containing the option's internal representation. The savedOptionsPtr argument points to the Tk_SavedOptions structure containing the saved value.

The Tk_SetOptions procedure processes a list of option specifications, converting them to internal representations and storing them in the widget record. It returns TCL_OK if all options were processed successfully, or TCL_ERROR if any error occurred. Error messages are left in the interpreter's result.

The Tk_GetOptionValue procedure returns a Tcl_Obj representing the value of a specific option. The objc and objv arguments specify the option name and value pair to be retrieved.

The Tk_GetOptionInfo procedure returns a Tk_OptionLayout structure that describes all the options available for the widget. This structure contains information about option names, types, default values, and whether they are read-only.

The Tk_RestoreSavedOptions procedure restores option values that were previously saved by Tk_SetOptions. This is typically used when processing configure commands that include the "-exactspec" option.

The Tk_FreeSavedOptions procedure frees any storage allocated by Tk_SetOptions to save option values. This is typically called after Tk_RestoreSavedOptions has been used.

TEMPLATES

The following are template procedures for the various option callbacks:

static Tk_OptionParseProc objOffsetParseProc;
static Tk_OptionPrintProc objOffsetPrintProc;
static Tk_OptionParseProc internalOffsetParseProc;
static Tk_OptionPrintProc internalOffsetPrintProc;
static Tk_OptionRestoreProc objOffsetRestoreProc;
static Tk_OptionRestoreProc internalOffsetRestoreProc;
static Tk_OptionFreeProc objOffsetFreeProc;
static Tk_OptionFreeProc internalOffsetFreeProc;

The procedures objOffsetParseProc and objOffsetPrintProc handle options stored as Tcl_Obj* pointers in the widget record. The procedures internalOffsetParseProc and internalOffsetPrintProc handle options stored as internal representations in the widget record.

The objOffsetRestoreProc and internalOffsetRestoreProc procedures handle restoring saved option values. The objOffsetFreeProc and internalOffsetFreeProc procedures handle freeing dynamically allocated storage for option values.

STORAGE MANAGEMENT ISSUES

When the objOffset field of a Tk_OptionSpec is non-negative, Tk_SetOptions stores a Tcl_Obj* pointer in the widget record. The widget is responsible for freeing this Tcl_Obj when it is no longer needed, typically when the widget is destroyed or when the option is changed to a new value. The objOffsetFreeProc should be used for this purpose.

When the objOffset field is negative, the option value is stored at the offset specified by internalOffset. In this case, the widget is responsible for managing the storage for the internal representation. The parseProc is responsible for allocating memory if necessary, and the freeProc is responsible for freeing it.

OBJOFFSET VS. INTERNALOFFSET

The objOffset field specifies the offset where a Tcl_Obj* pointer to the option's value is stored. The internalOffset field specifies the offset where the internal representation of the option's value is stored. If objOffset is non-negative, then internalOffset is ignored, and the option value is stored as a Tcl_Obj* pointer. If objOffset is negative, then internalOffset specifies the offset where the internal representation is stored.

CUSTOM OPTION TYPES

To support custom option types, the Tk_OptionSpec structure can include pointers to procedures that handle the conversion between the internal representation and Tcl objects. These procedures are:

parseProc
This procedure is invoked by Tk_SetOptions to convert a Tcl object into the internal representation for the option. It takes the interpreter, a pointer to the widget record, the offset within the widget record where the internal representation should be stored, and the Tcl object as arguments. It should return a Tcl result (TCL_OK or TCL_ERROR).
printProc
This procedure is invoked by Tk_GetOptionValue to convert the internal representation of an option into a Tcl object. It takes the interpreter, a pointer to the widget record, the offset within the widget record where the internal representation is stored, and the client data as arguments. It should return a pointer to a Tcl object representing the option's value.
restoreProc
This procedure is invoked by Tk_RestoreSavedOptions to restore a previously saved internal representation of a custom option value. It takes the interpreter, a pointer to the widget record, the offset within the widget record where the internal representation should be stored, and a pointer to the saved value as arguments. It does not return a value.
freeProc
This procedure is invoked by Tk_SetOptions and Tk_FreeSavedOptions to free any storage allocated for the internal representation of a custom option. It takes the interpreter, a pointer to the widget record, the offset within the widget record where the internal representation is stored, and the client data as arguments. It does not return a value.

The clientData field in the Tk_OptionSpec structure is passed as the last argument to these procedures. It is typically used to pass information about the option's type, such as the desired integer range or the names of symbolic constants. The restoreProc and freeProc may be NULL, indicating that no function should be called for those operations.

The setProc procedure is invoked by Tk_SetOptions to convert a Tcl_Obj into an internal representation and store the resulting value in the widget record. The arguments are:

clientData
A copy of the clientData field in the Tk_ObjCustomOption structure.
interp
A pointer to a Tcl interpreter, used for error reporting.
Tkwin
A copy of the tkwin argument to Tk_SetOptions
valuePtr
A pointer to a reference to a Tcl_Obj describing the new value for the option; it could have been specified explicitly in the call to Tk_SetOptions or it could come from the option database or a default. If the objOffset for the option is non-negative (the option value is stored as a (Tcl_Obj *) in the widget record), the Tcl_Obj pointer referenced by valuePtr is the pointer that will be stored at the objOffset for the option. SetProc may modify the value if necessary; for example, setProc may change the value to NULL to support the TK_OPTION_NULL_OK flag.
recordPtr
A pointer to the start of the widget record to modify.
internalOffset
Offset in bytes from the start of the widget record to the location where the internal representation of the option value is to be placed.
saveInternalPtr
A pointer to storage allocated in a Tk_SavedOptions structure for the internal representation of the original option value. Before setting the option to its new value, setProc should set the value referenced by saveInternalPtr to the original value of the option in order to support Tk_RestoreSavedOptions.
flags
A copy of the flags field in the Tk_OptionSpec structure for the option

SetProc returns a standard Tcl result: TCL_OK to indicate successful processing, or TCL_ERROR to indicate a failure of any kind. An error message may be left in the Tcl interpreter given by interp in the case of an error.

The getProc procedure is invoked by Tk_GetOptionValue and Tk_GetOptionInfo to retrieve a Tcl_Obj representation of the internal representation of an option. The clientData argument is a copy of the clientData field in the Tk_ObjCustomOption structure. Tkwin is a copy of the tkwin argument to Tk_GetOptionValue or Tk_GetOptionInfo. RecordPtr is a pointer to the beginning of the widget record to query. InternalOffset is the offset in bytes from the beginning of the widget record to the location where the internal representation of the option value is stored. GetProc must return a pointer to a Tcl_Obj representing the value of the option.

The restoreProc procedure is invoked by Tk_RestoreSavedOptions to restore a previously saved internal representation of a custom option value. The clientData argument is a copy of the clientData field in the Tk_ObjCustomOption structure. Tkwin is a copy of the tkwin argument to Tk_GetOptionValue or Tk_GetOptionInfo. InternalPtr is a pointer to the location where internal representation of the option value is stored. SaveInternalPtr is a pointer to the saved value. RestoreProc must copy the value from saveInternalPtr to internalPtr to restore the value. RestoreProc need not free any memory associated with either internalPtr or saveInternalPtr; freeProc will be invoked to free that memory if necessary. RestoreProc has no return value.

The freeProc procedure is invoked by Tk_SetOptions and Tk_FreeSavedOptions to free any storage allocated for the internal representation of a custom option. The clientData argument is a copy of the clientData field in the Tk_ObjCustomOption structure. Tkwin is a copy of the tkwin argument to Tk_GetOptionValue or Tk_GetOptionInfo. InternalPtr is a pointer to the location where the internal representation of the option value is stored. The freeProc must free any storage associated with the option. FreeProc has no return value.
