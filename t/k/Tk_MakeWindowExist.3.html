Tk_CreateWindow(3) Procedimientos de la biblioteca Tk Tk_CreateWindow(3)

NOMBRE

Tk_CreateWindow, Tk_CreateWindowFromPath, Tk_DestroyWindow, Tk_MakeWindowExist - crear o eliminar ventana

SINOPSIS

#include <tk.h>

Tk_Window
Tk_CreateWindow(interp, parent, name, topLevScreen)

Tk_Window
Tk_CreateAnonymousWindow(interp, parent, topLevScreen)

Tk_Window
Tk_CreateWindowFromPath(interp, tkwin, pathName, topLevScreen)

Tk_DestroyWindow(tkwin)

Tk_MakeWindowExist(tkwin)

ARGUMENTOS

Tcl_Interp *interp (salida)
Intérprete Tcl a usar para informar de errores. Si no ocurre ningún error, entonces *interp no se modifica.
Tk_Window parent (entrada)
Token para la ventana que servirá como padre lógico de la nueva ventana.
const char *name (entrada)
Nombre a usar para esta ventana. Debe ser único entre todos los hijos del mismo parent.
const char *topLevScreen (entrada)
Tiene el mismo formato que screenName. Si es NULL, entonces la nueva ventana se crea como una ventana interna. Si es distinto de NULL, la nueva ventana se crea como una ventana de nivel superior en la pantalla topLevScreen. Si topLevScreen es una cadena vacía (“”), entonces la nueva ventana se crea como una ventana de nivel superior de la pantalla de parent.
Tk_Window tkwin (entrada)
Token para la ventana.
const char *pathName (entrada)
Nombre de la nueva ventana, especificado como nombre de ruta dentro de la aplicación (por ejemplo, .a.b.c).

DESCRIPCIÓN

Los procedimientos Tk_CreateWindow, Tk_CreateAnonymousWindow y Tk_CreateWindowFromPath se utilizan para crear nuevas ventanas para su uso en aplicaciones basadas en Tk. Cada uno de los procedimientos devuelve un token que puede usarse para manipular la ventana en otras llamadas a la biblioteca Tk. Si la ventana no se pudo crear con éxito, se devuelve NULL y el resultado del intérprete interp se modifica para contener un mensaje de error.

Tk admite dos tipos diferentes de ventanas: ventanas internas y ventanas de nivel superior. Una ventana interna es una ventana interior de una aplicación Tk, como una barra de desplazamiento, una barra de menú o un botón. Una ventana de nivel superior es aquella que se crea como hija de la ventana raíz de una pantalla, en lugar de como una ventana interior, pero que forma parte lógicamente de alguna ventana principal existente. Ejemplos de ventanas de nivel superior son los menús emergentes y los cuadros de diálogo.

Se pueden crear nuevas ventanas llamando a Tk_CreateWindow. Si el argumento topLevScreen es NULL, entonces la nueva ventana será una ventana interna. Si topLevScreen no es NULL, entonces la nueva ventana será una ventana de nivel superior: topLevScreen indica el nombre de una pantalla y la nueva ventana se creará como hija de la ventana raíz de topLevScreen. En cualquier caso, Tk considerará la nueva ventana como la hija lógica de parent: el nombre de ruta de la nueva ventana reflejará este hecho, se podrán especificar opciones para la nueva ventana bajo esta suposición, y así sucesivamente. La única diferencia es que la nueva ventana X para una ventana de nivel superior no será hija de la ventana X de parent. Por ejemplo, el parent de un menú desplegable sería la ventana similar a un botón utilizada para invocarlo, la cual a su vez sería hija de la ventana de la barra de menú. Un cuadro de diálogo podría tener la ventana principal de la aplicación como su padre.

Tk_CreateAnonymousWindow difiere de Tk_CreateWindow en que crea una ventana sin nombre. Esta ventana solo será manipulable mediante interfaces C y no será visible para los scripts Tcl. Tanto las ventanas internas como las de nivel superior se pueden crear con Tk_CreateAnonymousWindow.

Tk_CreateWindowFromPath ofrece una forma alternativa de especificar nuevas ventanas. En Tk_CreateWindowFromPath, la nueva ventana se especifica con un token para cualquier ventana de la aplicación objetivo (tkwin), más un nombre de ruta para la nueva ventana. Produce el mismo efecto que Tk_CreateWindow y permite crear tanto ventanas de nivel superior como internas, dependiendo del valor de topLevScreen. En las llamadas a Tk_CreateWindowFromPath, al igual que en las llamadas a Tk_CreateWindow, el padre de la nueva ventana debe existir en el momento de la llamada, pero la nueva ventana no debe existir ya.

Los procedimientos de creación de ventanas no emiten realmente el comando a X para crear una ventana. En su lugar, crean una estructura de datos local asociada a la ventana y posponen la creación de la ventana X. La ventana se creará realmente en la primera llamada a Tk_MapWindow. La creación diferida de ventanas permite modificar varios aspectos de la ventana (como su tamaño, color de fondo, etc.) después de su creación sin incurrir en ningún sobrecoste en el servidor X. Cuando la ventana se mapea finalmente, todos los atributos de la ventana se pueden establecer al crear la ventana.

El valor devuelto por un procedimiento de creación de ventanas no es el token X de la ventana (no puede serlo, ya que aún no se le ha pedido a X que cree la ventana). En su lugar, es un token para la estructura de datos local de Tk para la ventana. La mayoría de los procedimientos de la biblioteca Tk toman tokens Tk_Window, en lugar de identificadores X. El identificador real de la ventana X se puede obtener de la estructura de datos local utilizando la macro Tk_WindowId; consulte la página del manual de Tk_WindowId para obtener más detalles.

Tk_DestroyWindow elimina una ventana y todas las estructuras de datos asociadas a ella, incluidos todos los manejadores de eventos creados con Tk_CreateEventHandler. Además, Tk_DestroyWindow eliminará recursivamente todos los hijos de tkwin (donde los hijos se definen en el sentido de Tk, consistiendo en todas las ventanas que se crearon con la ventana dada como parent). Si tkwin es una ventana interna, entonces los manejadores de eventos interesados en eventos de destrucción se invocan inmediatamente. Si tkwin es una ventana de nivel superior o principal, entonces los manejadores de eventos se invocarán más tarde, después de que X haya visto la solicitud y haya devuelto un evento para ella.

Si se ha creado una ventana pero no se ha mapeado, por lo que no existe ninguna ventana X, es posible forzar la creación de la ventana X llamando a Tk_MakeWindowExist. Este procedimiento emite los comandos X para instanciar la ventana dada por tkwin.
