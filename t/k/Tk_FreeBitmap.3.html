DESCRIPCIÓN

Estos procedimientos gestionan una colección de bitmaps (pixmaps de un solo plano) que está utilizando una aplicación. Los procedimientos permiten reutilizar bitmaps de manera eficiente, evitando así la sobrecarga del servidor, y también permiten nombrar bitmaps con cadenas de caracteres.

Tk_AllocBitmapFromObj devuelve un identificador Pixmap para un bitmap que coincide con la descripción en objPtr y es adecuado para su uso en tkwin. Reutiliza un bitmap existente, si es posible, y crea uno nuevo en caso contrario. El valor de objPtr debe tener una de las siguientes formas:

@nombreArchivo
nombreArchivo debe ser el nombre de un archivo que contiene una descripción de bitmap en el formato estándar X11.
nombre
nombre debe ser el nombre de un bitmap definido previamente con una llamada a Tk_DefineBitmap. Los siguientes nombres están predefinidos por Tk:
error
El símbolo internacional de “prohibido”: un círculo con una línea diagonal que lo atraviesa.

Gris 75%: un patrón de tablero de ajedrez donde tres de cada cuatro bits están activados.
gray50
Gris 50%: un patrón de tablero de ajedrez donde cada dos bits están activados.
gray25
Gris 25%: un patrón de tablero de ajedrez donde uno de cada cuatro bits está activado.
gray12
Gris 12.5%: un patrón donde un octavo de los bits están activados, consistiendo en cada cuarto píxel en cada dos filas.
hourglass
Un símbolo de reloj de arena.

Una letra “i” grande.

La silueta de una cabeza humana, con un signo de interrogación dentro.

En condiciones normales, Tk_AllocBitmapFromObj devuelve un identificador para el bitmap solicitado. Si ocurre un error al crear el bitmap, como cuando objPtr hace referencia a un archivo inexistente, se devuelve None y se deja un mensaje de error en el resultado de interp si interp no es NULL. Tk_AllocBitmapFromObj almacena en caché información sobre el valor de retorno en objPtr, lo que acelera las llamadas futuras a procedimientos como Tk_AllocBitmapFromObj y Tk_GetBitmapFromObj.

Tk_GetBitmap es idéntico a Tk_AllocBitmapFromObj excepto que la descripción del bitmap se especifica con una cadena en lugar de un objeto. Esto evita que Tk_GetBitmap almacene en caché el valor de retorno, por lo que Tk_GetBitmap es menos eficiente que Tk_AllocBitmapFromObj.

Tk_GetBitmapFromObj devuelve el token de un bitmap existente, dada la ventana y la descripción utilizada para crear el bitmap. Tk_GetBitmapFromObj no crea realmente el bitmap; el bitmap debe haber sido creado previamente con una llamada a Tk_AllocBitmapFromObj o Tk_GetBitmap. El valor de retorno se almacena en caché en objPtr, lo que acelera las llamadas futuras a Tk_GetBitmapFromObj con el mismo objPtr y tkwin.

Tk_DefineBitmap asocia un nombre con datos de bitmap en memoria para que el nombre pueda ser utilizado en llamadas posteriores a Tk_AllocBitmapFromObj o Tk_GetBitmap. El argumento nameId proporciona un nombre para el bitmap; no debe haber sido utilizado previamente en una llamada a Tk_DefineBitmap. Los argumentos source, width y height describen el bitmap. Tk_DefineBitmap normalmente devuelve TCL_OK; si ocurre un error (por ejemplo, ya se ha definido un bitmap con el nombre nameId), se devuelve TCL_ERROR y se deja un mensaje de error en el resultado del intérprete interp. DESCRIPTION

These procedures manage bitmaps used in Tk applications. A bitmap is simply a pixmap that contains mask bits, typically used for creating stippled patterns. Tk maintains a database of all the bitmaps that are currently in use.

Tk_DefineBitmap defines a new bitmap with the given name. The source argument points to data in the standard X10 bitmap file format. The bitmap is created with the specified width and height. The bitmap data is read at compile-time and incorporated into the application's executable image. See the example below. This form is useful for embedding bitmaps directly into an application.

Tk_GetBitmap returns a handle to a bitmap. The name argument specifies which bitmap to return. If name starts with "@", then it is treated as a file name, and the bitmap is read from that file. Otherwise, name is treated as a name defined using Tk_DefineBitmap. Tk caches bitmaps, so if the same name is requested multiple times, the existing bitmap will be returned rather than reading the file or data again. The tkwin argument is needed to determine the screen and screen depth for the bitmap.

The example below shows how to define a bitmap named foo using Tk_DefineBitmap and then how to retrieve it using Tk_GetBitmap:

Pixmap bitmap;
const char stip_bits[] = {
    0x01, 0x02, 0x04, 0x08, 0x10, 0x20, 0x40, 0x80,
    0x01, 0x02, 0x04, 0x08, 0x10, 0x20, 0x40, 0x80,
    /* ... more data ... */
};
int stip_width = 16;
int stip_height = 16;

/* Define the bitmap at compile time */
Tk_DefineBitmap(interp, "foo", stip_bits, stip_width, stip_height);

/* Later, get the bitmap */
bitmap = Tk_GetBitmap(interp, tkwin, "foo");

This code causes the bitmap data to be read at compile-time and incorporates the bitmap information into the program's executable image. The same bitmap could be read at run-time using Tk_GetBitmap:

Pixmap bitmap;
bitmap = Tk_GetBitmap(interp, tkwin, "@stip.bitmap");

The second form is a bit more flexible (the file could be modified after the program has been compiled, or a different string could be provided to read a different file), but it is a little slower and requires the bitmap file to exist separately from the program.

Tk maintains a database of all the bitmaps that are currently in use. Whenever possible, it will return an existing bitmap rather than creating a new one. When a bitmap is no longer used, Tk will release it automatically. This approach can substantially reduce server overhead, so Tk_AllocBitmapFromObj and Tk_GetBitmap should generally be used in preference to Xlib procedures like XReadBitmapFile.

The bitmaps returned by Tk_AllocBitmapFromObj and Tk_GetBitmap are shared, so callers should never modify them. If a bitmap must be modified dynamically, then it should be created by calling Xlib procedures such as XReadBitmapFile or XCreatePixmap directly.

The procedure Tk_NameOfBitmap is roughly the inverse of Tk_GetBitmap. Given an X Pixmap argument, it returns the textual description that was passed to Tk_GetBitmap when the bitmap was created. Bitmap must have been the return value from a previous call to Tk_AllocBitmapFromObj or Tk_GetBitmap.

Tk_SizeOfBitmap returns the dimensions of its bitmap argument in the words pointed to by the widthPtr and heightPtr arguments. As with Tk_NameOfBitmap, bitmap must have been created by Tk_AllocBitmapFromObj or Tk_GetBitmap.

When a bitmap is no longer needed, Tk_FreeBitmapFromObj or Tk_FreeBitmap should be called to release it. For Tk_FreeBitmapFromObj the bitmap to release is specified with the same information used to create it; for Tk_FreeBitmap the bitmap to release is specified with its Pixmap token. There should be exactly one call to Tk_FreeBitmapFromObj or Tk_FreeBitmap for each call to Tk_AllocBitmapFromObj or Tk_GetBitmap.

BUGS

In determining whether an existing bitmap can be used to satisfy a new request, Tk_AllocBitmapFromObj and Tk_GetBitmap consider only the immediate value of the string description. For example, when a file name is passed to Tk_GetBitmap, Tk_GetBitmap will assume it is safe to re-use an existing bitmap created from the same file name: it will not check to see whether the file itself has changed, or whether the current directory has changed, thereby causing the name to refer to a different file.
