NOMBRE

TableMatrix - Crear y manipular tablas

SINOPSIS

$tabla = $padre->TableMatrix(?opciones?);

OPCIONES ESTÁNDAR

-anchor -background -cursor
-exportselection -font -foreground -highlightbackground -highlightcolor
-highlightthickness -insertbackground -insertborderwidth -insertofftime
-insertontime -insertwidth -invertselected -relief -takefocus
-xscrollcommand -yscrollcommand

Opciones específicas del widget

Switch: -autoclear
Name: autoClear
Class: AutoClear
Un valor booleano que especifica si la primera pulsación de tecla en una celda borrará el texto que había previamente. Por defecto es 0.
Switch: -bordercursor
Name: borderCursor
Class: Cursor
Especifica el nombre del cursor que se mostrará al pasar sobre los bordes, una indicación visual de que el redimensionamiento interactivo está permitido (se ve afectado por el valor de -resizeborders). Por defecto es crosshair.
Switch: -borderwidth o -bd
Name: borderWidth
Class: BorderWidth
Especifica un valor de píxeles no negativo o una lista de valores que indican el ancho del borde 3D a dibujar en las celdas interiores de la tabla (si se está dibujando dicho borde; la opción <Brelief> típicamente determina esto). Si se especifica un valor, se dibujará un rectángulo de este ancho. Si se especifican dos valores, solo los bordes izquierdo y derecho de la celda tendrán bordes. Si se especifican cuatro valores, los valores corresponden a los bordes {izquierdo derecho superior inferior}. Esto puede ser anulado por la opción borderwidth de una etiqueta. También puede verse afectado por el -drawmode definido para la tabla. Cada valor de la lista debe tener una de las formas aceptables para Tk_GetPixels.
Switch: -browsecommand o -browsecmd
Name: browseCommand
Class: BrowseCommand
Especifica un comando (callback) que se evaluará cada vez que cambie la celda activa. El índice anterior y el índice actual se pasan a este comando como argumentos.
Switch: -cache
Name: cache
Class: Cache
Un valor booleano que especifica si se mantendrá una caché interna del contenido de la tabla. Esto mejora enormemente el rendimiento cuando se usa con -command pero consume memoria adicional. Puede mantener el estado cuando tanto -command como -variable están vacíos. La caché se vacía automáticamente cada vez que cambia el valor de -cache o -variable, de lo contrario, deberá llamar explícitamente a clear en ella. Por defecto está desactivada.
Switch: -colorigin
Name: colOrigin
Class: Origin
Especifica qué índice de columna interpretar como la columna más a la izquierda en la tabla. Este valor se utiliza para los índices de usuario en la tabla. Por defecto es 0.
Switch: -cols
Name: cols
Class: Cols
Número de columnas en la tabla. Por defecto es 10.
Switch: -colseparator
Name: colSeparator
Class: Separator
Especifica un carácter separador que se interpretará como separador de columnas al cortar o pegar datos en una tabla. Por defecto, las columnas se separan como elementos de una lista tcl.
Switch: -colstretchmode
Name: colStretchMode
Class: StretchMode
Especifica uno de los siguientes modos de estiramiento para que las columnas llenen el espacio de ventana adicional asignado:
none
Las columnas no se estirarán para llenar el espacio de ventana asignado. Si las columnas son demasiado estrechas, habrá un espacio en blanco a la derecha de la tabla. Este es el valor predeterminado.
unset
Solo las columnas que no tengan un ancho específico establecido se estirarán.
all
Todas las columnas se estirarán en el mismo número de píxeles para llenar el espacio de ventana asignado a la tabla. Este modo puede interferir con el redimensionamiento interactivo de bordes que intenta forzar el ancho de la columna.
last
La última columna se estirará para llenar el espacio de ventana asignado a la tabla.
fill
(solo válido para -rowstretch actualmente)

La tabla obtendrá más o menos columnas según el espacio de ventana asignado a la tabla. Este modo tiene numerosas peculiaridades y puede desaparecer en el futuro.

Switch: -coltagcommand
Name: colTagCommand
Class: TagCommand
Proporciona el nombre de un procedimiento que será evaluado por el widget para determinar la etiqueta que se utilizará para una columna dada. Al mostrar una celda, el widget de tabla primero verificará si se ha definido una etiqueta usando el método de widget tag col. Si no se encuentra ninguna etiqueta, evaluará el procedimiento con nombre pasando el número de columna en cuestión como único argumento. Se espera que el procedimiento devuelva el nombre de una etiqueta a usar, o una cadena nula. Los errores que ocurran durante la evaluación del procedimiento, o el retorno de un nombre de etiqueta inválido, se ignoran silenciosamente.

El número de columna actual se pasa como argumento al comando col.

Switch: -colwidth
Name: colWidth
Class: ColWidth
Ancho de columna predeterminado, interpretado como caracteres en la fuente predeterminada cuando el número es positivo, o píxeles si es negativo. Por defecto es 10.
Switch: -command
Name: command
Class: Command
Especificó un comando para usar como interfaz procedimental para los valores de celda. Si -usecommand es verdadero, este comando se usará en lugar de cualquier referencia a la matriz -variable. Al recuperar los valores de celda, el valor de retorno del comando se usa como el valor para la celda.

Argumentos pasados a este callback: El Flag de Establecimiento (=1 si se está estableciendo, de lo contrario, recuperando), la fila actual, la columna actual, el valor de la celda (si se está estableciendo).

Switch: -drawmode
Name: drawMode
Class: DrawMode
Establece el modo de dibujo de la tabla en una de las siguientes opciones:
slow
La tabla se dibuja en un pixmap fuera de pantalla usando las funciones de borde de Tk (doble buffer). Esto significa que no habrá parpadeo, pero este modo es lento para tablas más grandes.
compatible
La tabla se dibuja directamente en la pantalla usando las funciones de borde de Tk

Ventanas Embebidas

Puede haber cualquier número de ventanas embebidas en un widget de tabla (una por celda), y cualquier widget puede ser utilizado como una ventana embebida (sujeto a las reglas habituales de gestión de geometría, que requieren que la ventana de la tabla sea el padre de la ventana embebida o un descendiente de su padre). La posición de la ventana embebida en la pantalla se actualizará a medida que la tabla se modifique o se desplace, y se mapeará y desmapeará a medida que entre y salga del área visible del widget de tabla. Cada ventana embebida ocupa el espacio de una celda en el widget de tabla, y se hace referencia a ella por el índice de la celda en la tabla. Las ventanas asociadas al widget de tabla se destruyen cuando se destruye el widget de tabla.

Las ventanas se utilizan solo para fines de visualización. Todavía existe un valor para esa celda, pero no se mostrará a menos que la ventana se elimine de alguna manera. Si la ventana es destruida o perdida por el widget de tabla a otro gestor de geometría, entonces cualquier dato asociado con ella se pierde (la celda que ocupaba ya no aparecerá en los nombres de ventana).

la Selección

Las selecciones de tabla están disponibles como tipo STRING. Por defecto, el valor de la selección serán los valores de las celdas seleccionadas en forma de lista anidada de Tcl, donde cada fila es una lista y cada columna es un elemento de una lista de fila. Puede cambiar la forma en que se interpreta este valor estableciendo las opciones -separadorfilas y -separadorcolumnas.
Por ejemplo, el formato predeterminado de Excel sería establecer -separadorfilas a "\n" y -separadorcolumnas a "\t". Cambiar estos valores afecta tanto a cómo la tabla envía la selección como a cómo lee los datos pegados, asegurando que la tabla siempre pueda cortar y pegar consigo misma. Es posible cambiar la forma en que se manejan los pegados editando el procedimiento de la biblioteca de la tabla tk_tablePasteHandler . Esto podría ser necesario si se establece -comandoseleccion.

Combinación de Filas/Columnas

Las celdas individuales pueden abarcar varias filas y/o columnas. Esto se hace a través del comando spans (ver abajo para los argumentos exactos). Las celdas en el área de título que se combinan no pueden extenderse más allá del área de título y se limitarán en consecuencia. Si el área de título se reduce durante una configuración, se realizarán verificaciones de seguridad para garantizar lo anterior. Puede establecer combinaciones en celdas regulares que se extienden más allá del área de fila/columna definida. Estas combinaciones no se limitarán, de modo que cuando el área de fila/columna definida se expanda, la combinación se expandirá con ella.

Al establecer una combinación, se realizan comprobaciones sobre si la combinación se superpondría con una celda que ya está combinada o oculta. Esto es un error y no está permitido. Las combinaciones pueden afectar la velocidad general del dibujo de la tabla, aunque no significativamente. Si no se usan combinaciones, entonces no hay pérdida de rendimiento.

Las celdas ocultas por celdas combinadas aún tienen datos válidos. Esto se verá durante las operaciones de cortar y pegar que involucran celdas ocultas, o a través del acceso directo por un comando como get o set.

Las propiedades de dibujo de las celdas combinadas se aplican solo al área visual de la celda. Por ejemplo, si una celda está justificada al centro en 5 columnas, entonces al ver cualquier parte de esas columnas, aparecerá centrada en el área visible. El área de columna no visible no se considerará en los cálculos de centrado.

Sustitución de Comandos

Los diversos comandos basados en opciones que la tabla admite admiten el familiar modelo de sustitución % de Tk (ver Tk::bind para más detalles).
Las siguientes secuencias % son reconocidas y sustituidas por el widget de tabla:

%c
Para ComandoSeleccion, es el número máximo de columnas en cualquier fila de la selección. De lo contrario, es la columna de la celda activada.
%C
Una sustitución de conveniencia para %r,%c.
%i
Para ComandoSeleccion, es el número total de celdas en la selección. Para Comando, es 0 para una lectura (get) y 1 para una escritura (set). De lo contrario, es la posición actual del cursor en la celda.
%r
Para ComandoSeleccion, es el número de filas en la selección. De lo contrario, es la fila de la celda activada.
%s
Para ComandoValidación, es el valor actual de la celda que se está validando. Para ComandoSeleccion, es el valor predeterminado de la selección. Para ComandoNavegación , es el índice de la última celda activa. Para Comando, está vacío para lecturas (get) y el valor actual de la celda para escrituras (set).
%S
Para ComandoValidación, es el nuevo valor potencial de la celda que se está validando. Para ComandoNavegación, es el índice de la nueva celda activa.
%W
La ruta al widget para el cual se generó el comando.

El método $window->TableMatrix crea un objeto widget. Este objeto admite los métodos configure y cget descritos en Tk::options, que se pueden utilizar para consultar y modificar las opciones descritas anteriormente. El widget también hereda todos los métodos proporcionados por la clase genérica Tk::Widget.

Los siguientes métodos adicionales están disponibles para los widgets de escala:

$tabla->activar(índice)
Establece la celda activa a la indicada por índice.
$tabla->bbox(primero, ?último?)
Devuelve el cuadro delimitador para la celda (rango) especificada como una tupla de 4 elementos de
x, y, ancho y alto en píxeles. Recorta el cuadro a la porción visible, si la hay, de lo contrario, se devuelve una cadena vacía.

$tabla->marcaBorde(x, y, ?fila|columna?)
Registra x e y y el borde de fila y/o columna debajo de ese punto en la ventana de la tabla, si lo hay; se usa en conjunto con los comandos posteriores de arrastrarBorde. Normalmente este comando está asociado a la pulsación de un botón del ratón en el widget. Si no se especifica fila o columna, devuelve una tupla de ambos índices de borde (un elemento vacío significa que no hay borde). De lo contrario, solo se devuelve el elemento especificado.

Este comando calcula la diferencia entre sus argumentos x e y y los argumentos x e y del último comando de marcaBorde para el widget. Luego ajusta el borde previamente marcado según la diferencia. $tabla->obtenerConfig(opción)
Devuelve el valor actual de la opción de configuración dada por opción. Opción puede tener cualquiera de los valores aceptados por el comando tabla.
$tabla->limpiar(opción, ?primero?, ?último?)
Este comando es una rutina de conveniencia para limpiar cierta información de estado gestionada por la tabla. primero y último representan índices válidos de la tabla. Si no se especifica ninguno, el comando opera sobre toda la tabla. Se reconocen las siguientes opciones:

Limpia la sección especificada de la caché, si la tabla ha estado guardándola.
$tabla->limpiarDimensiones(?primero?, ?último?)
Limpia las áreas de filas y columnas especificadas de dimensiones de altura/anchura específicas. Cuando solo se especifica un índice, por ejemplo 2,0, se interpreta como la fila 2 y la columna 0.

Limpia el área especificada de etiquetas (todas las etiquetas de fila, columna y celda).

DESCRIPTION

The TableMatrix widget provides a convenient way to display and edit data in a grid format. It supports features such as row and column spanning, cell spanning, and command substitution for cell values.

The widget displays text in a grid of rows and columns. Each cell in the grid can contain a string of text. The widget provides methods for accessing and modifying the content of individual cells, as well as for controlling the view of the table.

The -command option allows you to specify a script that will be called whenever the value of a cell is requested. This script should return the string value to be displayed in the cell.

The -postcommand option allows you to specify a script that will be called whenever the view of the table is changed. This script is called with the cell coordinates of the top-left cell and the bottom-right cell of the visible area as arguments.

The widget supports row and column spanning, which allows you to create cells that span multiple rows or columns. This is useful for creating table headers or other complex layouts.

Indices

Row and column indices are specified as integers. The default origin for row and column indexing is 0. You can change the origin using the -roworigin and -colorigin options.

Tags

Tags are used to group cells together. For example, you can use tags to apply specific formatting or behavior to a set of cells.

Embedded Windows

You can embed other Tk widgets within the cells of the TableMatrix widget. This allows you to create interactive tables with complex user interfaces.

the Selection

The widget supports various selection modes, including browse, single, multiple, and extended. You can control the selection behavior using the -selectmode option.

Row/Col Spanning

The widget supports row and column spanning. You can use the span method to create cells that span multiple rows or columns.

Command Substitution

The widget supports command substitution for cell values. This means that you can use Tk commands to dynamically generate the content of cells.

Widget Methods

The following methods are available for the TableMatrix widget:

$table->xview(?args?)
This command is used to query and change the horizontal position of the text in the widget's window. It can take any of the following forms:
$table->xview()
Returns a list containing two elements, both of which are real fractions between 0 and 1. The first element indicates the position of the text displayed at the left edge of the window, relative to the entire table width (e.g., 0.5 means halfway through the table's text). The second element indicates the position of the text displayed just after the last visible element in the window, relative to the entire table width. For example, a return value of .6, 20% of the table's text is off-screen to the left, the middle 40% is visible in the window, and 40% of the text is off-screen to the right. These are the same values passed to scrollbars via the -xscrollcommand option.
$table->xview(index)
Adjusts the view in the window so that the column given by index is displayed at the left edge of the window.
$table->xviewMoveto(fraction)
Adjusts the view in the window so that fraction of the total width of the table text is off-screen to the left. fraction must be a fraction between 0 and 1.
$table->xviewScroll(number, what)
This command shifts the view in the window left or right according to number and what. Number must be an integer. What must be either units or pages or an abbreviation of one of these. If what is units, the view adjusts left or right by number cells on the display; if it is pages then the view adjusts by number screenfuls. If number is negative then cells farther to the left become visible; if it is positive then cells farther to the right become visible.
$table->yview(?args?)
This command is used to query and change the vertical position of the text in the widget's window. It can take any of the following forms:
$table->yview()
Returns a list containing two elements, both of which are real fractions between 0 and 1. The first element gives the position of the table element at the top of the window, relative to the table as a whole (0.5 means it is halfway through the table, for example). The second element gives the position of the table element just after the last one in the window, relative to the table as a whole. These are the same values passed to scrollbars via the -yscrollcommand option.
$table->yview(index)
Adjusts the view in the window so that the row given by index is displayed at the top of the window.
$table->yviewMoveto(fraction)
Adjusts the view in the window so that the element given by fraction appears at the top of the window. Fraction is a fraction between 0 and 1; 0 indicates the first element in the table, 0.33 indicates the element one-third the way through the table, and so on.
$table->yviewScroll(number, what)
This command adjusts the view in the window up or down according to number and what. Number must be an integer. What must be either units or pages. If what is units, the view adjusts up or down by number cells; if it is pages then the view adjusts by number screenfuls. If number is negative then earlier elements become visible; if it is positive then later elements become visible.

Performance Issues

The number of rows and columns or a table widget should not significantly affect the speed of redraw. Recalculation and redraw of table parameters and cells is restricted as much as possible. The display cell with the insert cursor is redrawn each time the cursor blinks, which causes a steady stream of graphics traffic. Set the -insertofftime option to 0 avoid this. The use of a -command with the table without a cache can cause significant slow-down, as the command is called once for each request of a cell value.
