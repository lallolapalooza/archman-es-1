Tk_CreateGenericHandler(3) Procedimientos de la Biblioteca Tk Tk_CreateGenericHandler(3)

NOMBRE

Tk_CreateGenericHandler, Tk_DeleteGenericHandler - asociar una función de devolución de llamada con todos los eventos X

SINOPSIS

#include <tk.h>

Tk_CreateGenericHandler(proc, clientData)

Tk_DeleteGenericHandler(proc, clientData)

ARGUMENTOS

Tk_GenericProc *proc (entrada)
Procedimiento a invocar cada vez que ocurra cualquier evento X en cualquier pantalla.
ClientData clientData (entrada)
Valor arbitrario de una palabra para pasar a proc.

DESCRIPCIÓN

Tk_CreateGenericHandler se encarga de que proc se invoque en el futuro cada vez que ocurra cualquier evento X. Este mecanismo *no* está pensado para la distribución de eventos X en ventanas gestionadas por Tk (debería usar Tk_CreateEventHandler para este propósito). Tk_CreateGenericHandler está pensado para otros propósitos, como el rastreo de eventos X, la monitorización de eventos en ventanas no pertenecientes a Tk, el acceso a bibliotecas relacionadas con X que no fueron diseñadas originalmente para su uso con Tk, etc.

La llamada a proc se realizará mediante Tk_HandleEvent; este mecanismo solo funciona en programas que distribuyen eventos a través de Tk_HandleEvent (o a través de otros procedimientos de Tk que llaman a Tk_HandleEvent, como Tcl_DoOneEvent o Tk_MainLoop).

Proc debe tener argumentos y resultados que coincidan con el tipo Tk_GenericProc:

typedef int Tk_GenericProc(
        ClientData clientData,
        XEvent *eventPtr);
El parámetro clientData de proc es una copia del argumento clientData proporcionado a Tk_CreateGenericHandler cuando se creó la llamada. Normalmente, clientData apunta a una estructura de datos que contiene información específica de la aplicación sobre cómo manejar los eventos. EventPtr es un puntero al evento X.

Cada vez que Tk_HandleEvent procesa un evento X, se llama a proc. El valor de retorno de proc es normalmente 0. Un valor de retorno distinto de cero indica que el evento no se va a procesar más; es decir, proc ha realizado todo el procesamiento que se va a permitir para el evento.

Si existen varios manejadores de eventos genéricos, cada uno se llama para cada evento, en el orden en que se establecieron.

Tk_DeleteGenericHandler se puede llamar para eliminar un manejador de eventos genérico creado previamente: elimina cada manejador que encuentra que coincide con los argumentos proc y clientData. Si no existe ningún manejador de este tipo, Tk_DeleteGenericHandler devuelve sin hacer nada. Aunque Tk lo soporta, probablemente sea una mala idea tener más de una llamada con los mismos argumentos proc y clientData.

Establecer un manejador de eventos genérico no garantiza que el proceso reciba realmente los eventos X que el manejador desea procesar. Por ejemplo, es responsabilidad del llamador invocar XSelectInput para seleccionar los eventos deseados, si es necesario.
