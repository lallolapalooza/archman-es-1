NOMBRE

Tk_AllocCursorFromObj, Tk_GetCursor, Tk_GetCursorFromObj, Tk_GetCursorFromData, Tk_NameOfCursor, Tk_FreeCursorFromObj, Tk_FreeCursor - mantener base de datos de cursores

SINOPSIS

#include <tk.h>

Tk_Cursor
Tk_AllocCursorFromObj(interp, tkwin, objPtr)

Tk_Cursor
Tk_GetCursor(interp, tkwin, name)

Tk_Cursor
Tk_GetCursorFromObj(tkwin, objPtr)

Tk_Cursor
Tk_GetCursorFromData(interp, tkwin, source, mask, width, height, xHot, yHot, fg, bg)

const char *
Tk_NameOfCursor(display, cursor)

Tk_FreeCursorFromObj(tkwin, objPtr)

Tk_FreeCursor(display, cursor)

ARGUMENTOS

Tcl_Interp *interp (entrada)
Intérprete a utilizar para la notificación de errores.
Tk_Window tkwin (entrada)
Token de la ventana en la que se utilizará el cursor.
Tcl_Obj *objPtr (entrada/salida)
Descripción del cursor; ver abajo para posibles valores. La representación interna se modificará para almacenar en caché un puntero al Tk_Cursor correspondiente.
const char *name (entrada)
Igual que objPtr excepto que la descripción del cursor se pasa como una cadena y el Tk_Cursor resultante no se almacena en caché.
const char *source (entrada)
Datos para el cursor del cursor, en formato de cursor estándar.
const char *mask (entrada)
Datos para el cursor de máscara, en formato de cursor estándar.
int width (entrada)
Ancho de source y mask.
int height (entrada)
Altura de source y mask.
int xHot (entrada)
Ubicación X del punto activo del cursor.
int yHot (entrada)
Ubicación Y del punto activo del cursor.
Tk_Uid fg (entrada)
Descripción textual del color de primer plano para el cursor.
Tk_Uid bg (entrada)
Descripción textual del color de fondo para el cursor.
Display *display (entrada)
Pantalla para la que se asignó cursor.
Tk_Cursor cursor (entrada)
Identificador opaco de Tk para el cursor. Si se pasa a Tk_FreeCursor, debe haber sido devuelto por alguna llamada anterior a Tk_GetCursor o Tk_GetCursorFromData.

DESCRIPCIÓN

Estos procedimientos gestionan una colección de cursores que está utilizando una aplicación. Los procedimientos permiten reutilizar cursores de manera eficiente, evitando así la sobrecarga del servidor, y también permiten nombrar cursores con cadenas de caracteres.

Tk_AllocCursorFromObj toma como argumento un objeto que describe un cursor y devuelve un identificador opaco de Tk para un cursor que corresponde a la descripción. Reutiliza un cursor existente si es posible y crea uno nuevo en caso contrario. Tk_AllocCursorFromObj almacena en caché información sobre el valor de retorno en objPtr, lo que acelera las llamadas futuras a procedimientos como Tk_AllocCursorFromObj y Tk_GetCursorFromObj. Si ocurre un error al crear el cursor, como cuando objPtr se refiere a un archivo inexistente, se devuelve None y se almacenará un mensaje de error en el resultado de interp si interp no es NULL. ObjPtr debe contener una lista Tcl estándar con una de las siguientes formas:

nombre [fgColor [bgColor]]
Nombre es el nombre de un cursor en el cursor estándar de cursores X, es decir, cualquiera de los nombres definidos en cursorcursor.h, sin el prefijo XC_. Algunos valores de ejemplo son X_cursor, hand2 o left_ptr. El Apéndice B de “The X Window System” de Scheifler & Gettys tiene ilustraciones que muestran cómo se ve cada uno de estos cursores. Si se especifican tanto fgColor como bgColor, dan los colores de primer plano y de fondo que se utilizarán para el cursor (se puede utilizar cualquiera de las formas aceptables para Tk_GetColor). Si solo se especifica fgColor, entonces no habrá color de fondo: el fondo será transparente. Si no se especifican colores, el cursor utilizará negro para su color de primer plano y blanco para su color de fondo.

La versión Macintosh de Tk admite todos los cursores X y también aceptará cualquiera de los cursores estándar de Mac, incluidos ibeam, crosshair, watch, plus y arrow. Además, Tk cargará recursos de cursores de Macintosh de los tipos crsr (color) y CURS (blanco y negro) por el nombre del recurso. Se buscarán en el archivo de recursos de la aplicación y de todas sus bibliotecas dinámicas abiertas los cursores con nombre. Si hay conflictos, los cursores de color siempre se cargarán con preferencia a los cursores en blanco y negro.

@sourceName maskName fgColor bgColor
En esta forma, sourceName y maskName son los nombres de los archivos que describen los cursores para los bits fuente y la máscara del cursor. Cada archivo debe estar en formato de cursor estándar X11. FgColor y bgColor indican los colores que se utilizarán para el cursor, en cualquiera de las formas aceptables para Tk_GetColor. Esta forma del comando no funcionará en equipos Macintosh o Windows.
@sourceName fgColor
Esta forma es similar a la anterior, excepto que la fuente se utiliza también como máscara. Esto significa que el fondo del cursor es transparente. Esta forma del comando no funcionará en equipos Macintosh o Windows.
@sourceName
Esta forma solo funciona en Windows y cargará un cursor del sistema de Windows (.ani o .cur) del archivo especificado en sourceName.

Tk_GetCursor es idéntico a Tk_AllocCursorFromObj excepto que la descripción del cursor se especifica con una cadena en lugar de un objeto. Esto evita que Tk_GetCursor almacene en caché el valor de retorno, por lo que Tk_GetCursor es menos eficiente que Tk_AllocCursorFromObj.

Tk_GetCursorFromObj devuelve el token de un cursor existente, dados la ventana y la descripción utilizadas para crear el cursor. Tk_GetCursorFromObj no crea realmente el cursor; el cursor ya debe haber sido creado con una llamada anterior a Tk_AllocCursorFromObj o Tk_GetCursor. El valor de retorno se almacena en caché en objPtr, lo que acelera las llamadas futuras a Tk_GetCursorFromObj con el mismo objPtr y tkwin.

Tk_GetCursorFromData permite crear cursores a partir de descripciones en memoria de sus cursores fuente y máscara. Source apunta a datos de cursor estándar para los bits fuente del cursor, y mask apunta a datos de cursor estándar que describen qué píxeles de source se dibujarán y cuáles se considerarán transparentes. Width y height dan las dimensiones del cursor, xHot y yHot indican la ubicación del punto activo del cursor (el punto que se informa cuando ocurre un evento), y fg y bg describen los colores de primer plano y de fondo del cursor textualmente (se puede utilizar cualquiera de las formas adecuadas para Tk_GetColor). Típicamente, los argumentos para Tk_GetCursorFromData se crean incluyendo un archivo de cursor directamente en el código fuente de un programa, como en el siguiente ejemplo:

Tk_Cursor cursor;
#include "source.cursor"
#include "mask.cursor"
cursor = Tk_GetCursorFromData(interp, tkwin, source_bits,
    mask_bits, source_width, source_height, source_x_hot,
    source_y_hot, Tk_GetUid("red"), Tk_GetUid("blue"));

En condiciones normales, Tk_GetCursorFromData devolverá un identificador para el cursor solicitado. Si ocurre un error al crear el cursor, se devuelve None y se almacenará un mensaje de error en el resultado de interp.

Tk_AllocCursorFromObj, Tk_GetCursor y Tk_GetCursorFromData mantienen una base de datos de todos los cursores que han creado. Siempre que sea posible, una llamada a Tk_AllocCursorFromObj, Tk_GetCursor o Tk_GetCursorFromData devolverá un cursor existente en lugar de crear uno nuevo. Este enfoque puede reducir sustancialmente la sobrecarga del servidor, por lo que los procedimientos Tk generalmente deben usarse con preferencia a los procedimientos de Xlib como XCreateFontCursor o XCreatePixmapCursor, que crean un nuevo cursor en cada llamada. Los procedimientos Tk también son más portátiles que los procedimientos de nivel inferior de X.

Tk_FreeCursor(3) - Arch Linux

NAME

Tk_FreeCursor, Tk_FreeCursorFromObj, Tk_NameOfCursor - manage cursors

SYNOPSIS

#include <tk.h>
void
Tk_FreeCursor(tkwin, cursor)
	Tk_Window tkwin;
	Tk_Cursor cursor;
void
Tk_FreeCursorFromObj(tkwin, cursorObj)
	Tk_Window tkwin;
	Tk_Object cursorObj;
const char *
Tk_NameOfCursor(cursor)
	Tk_Cursor cursor;

ARGUMENTS

tkwin
Window for which the cursor is allocated. This is needed for cursor caching.
cursor
Token for the cursor to be freed. This is the value returned by Tk_GetCursor.
cursorObj
The Tk_Object which represents the cursor to be freed. This is the value returned by Tk_AllocCursorFromObj.

DESCRIPTION

The Tk_FreeCursor and Tk_FreeCursorFromObj functions should be called to release a cursor that was previously allocated with Tk_GetCursor, Tk_AllocCursorFromObj or Tk_GetCursorFromData. Cursors are reference counted, and the underlying cursor resource will only be freed when the reference count drops to zero.

Tk_NameOfCursor returns a string which is the name of the cursor. This might be a standard cursor name (e.g., "arrow", "hand2") or a hexadecimal string representation of the X identifier for the cursor. The name returned is only guaranteed to be valid until the next call to Tk_NameOfCursor. This call is not portable except for cursors returned by Tk_GetCursor.

When a cursor returned by Tk_AllocCursorFromObj, Tk_GetCursor, or Tk_GetCursorFromData is no longer needed, Tk_FreeCursorFromObj or Tk_FreeCursor should be called to release it. For Tk_FreeCursorFromObj the cursor to release is specified with the same information used to create it; for Tk_FreeCursor the cursor to release is specified with its Tk_Cursor token. There should be exactly one call to Tk_FreeCursor for each call to Tk_AllocCursorFromObj, Tk_GetCursor, or Tk_GetCursorFromData.

BUGS

In determining whether an existing cursor can be used to satisfy a new request, Tk_AllocCursorFromObj, Tk_GetCursor, and Tk_GetCursorFromData consider only the immediate values of their arguments. For example, when a file name is passed to Tk_GetCursor, Tk_GetCursor will assume it is safe to re-use an existing cursor created from the same file name: it will not check to see whether the file itself has changed, or whether the current directory has changed, thereby causing the name to refer to a different file. Similarly, Tk_GetCursorFromData assumes that if the same source pointer is used in two different calls, then the pointers refer to the same data; it does not check to see if the actual data values have changed.
