Tk_ClipboardClear(3) Procedimientos de la biblioteca Tk Tk_ClipboardClear(3)

NOMBRE

Tk_ClipboardClear, Tk_ClipboardAppend - Administrar el portapapeles

SINOPSIS

#include <tk.h>

int
Tk_ClipboardClear(interp, tkwin)

int
Tk_ClipboardAppend(interp, tkwin, target, format, buffer)

ARGUMENTOS

Tcl_Interp *interp (entrada)
Intérprete a utilizar para reportar errores.
Tk_Window tkwin (entrada)
Ventana que determina qué portapapeles de visualización manipular.
Atom target (entrada)
Tipo de conversión para este elemento del portapapeles; tiene el mismo significado que el argumento target de Tk_CreateSelHandler.
Atom format (entrada)
Representación a usar cuando se recuperan los datos; tiene el mismo significado que el argumento format de Tk_CreateSelHandler.
const char *buffer (entrada)
Cadena terminada en nulo que contiene los datos a añadir al portapapeles.

DESCRIPCIÓN

Estos dos procedimientos gestionan el portapapeles para Tk. El portapapeles se gestiona típicamente llamando a Tk_ClipboardClear una vez, y luego llamando a Tk_ClipboardAppend para añadir datos para cualquier número de objetivos.

Tk_ClipboardClear reclama la selección CLIPBOARD y libera cualquier elemento de datos almacenado previamente en el portapapeles en esta aplicación. Normalmente devuelve TCL_OK, pero si ocurre un error, devuelve TCL_ERROR y deja un mensaje de error en el resultado del intérprete interp. Tk_ClipboardClear debe llamarse antes de que se pueda emitir una secuencia de llamadas a Tk_ClipboardAppend.

Tk_ClipboardAppend añade un buffer de datos al portapapeles. El primer buffer para un target dado determina el format para ese target. Cualquier añadido sucesivo para ese target debe tener el mismo formato o se devolverá un error. Tk_ClipboardAppend devuelve TCL_OK si el buffer se copia con éxito en el portapapeles. Si el portapapeles no es actualmente propiedad de la aplicación, ya sea porque no se ha llamado a Tk_ClipboardClear o porque la propiedad del portapapeles ha cambiado desde la última llamada a Tk_ClipboardClear, Tk_ClipboardAppend devuelve TCL_ERROR y deja un mensaje de error en el resultado del intérprete interp.

Para garantizar la atomicidad, no debe ocurrir ningún manejo de eventos entre Tk_ClipboardClear y las siguientes llamadas a Tk_ClipboardAppend (de lo contrario, alguien podría recuperar un portapapeles parcialmente completado o reclamar la propiedad de esta aplicación).

Tk_ClipboardClear puede invocar callbacks, incluyendo scripts Tcl arbitrarios, como resultado de perder la selección CLIPBOARD, por lo que cualquier función llamante debe tener cuidado de ser reentrante en el punto en que se invoca Tk_ClipboardClear.
