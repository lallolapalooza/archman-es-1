DESCRIPCIÓN

Tk_CreateImageType se invoca para definir un nuevo tipo de imagen. Un tipo de imagen corresponde a un valor particular del argumento type para el comando image create. Puede existir cualquier número de tipos de imagen diferentes, y se pueden definir nuevos tipos dinámicamente llamando a Tk_CreateImageType. Por ejemplo, podría haber un tipo para mapas de bits de 2 colores, otro para imágenes multicolores, otro para imágenes tramadas, otro para video, y así sucesivamente.

El código que implementa un nuevo tipo de imagen se llama gestor de imagen. Consiste en una colección de procedimientos más tres tipos diferentes de estructuras de datos. La primera estructura de datos es una estructura Tk_ImageType, que contiene el nombre del tipo de imagen y punteros a cinco procedimientos proporcionados por el gestor de imagen para tratar las imágenes de este tipo:

typedef struct Tk_ImageType {
    const char *name;
    Tk_ImageCreateProc *createProc;
    Tk_ImageGetProc *getProc;
    Tk_ImageDisplayProc *displayProc;
    Tk_ImageFreeProc *freeProc;
    Tk_ImageDeleteProc *deleteProc;
} Tk_ImageType;
Los campos de esta estructura se describirán en subsecciones posteriores de esta entrada.

La segunda estructura de datos principal manipulada por un gestor de imagen se llama modelo de imagen; contiene información general sobre una imagen particular, como los valores de las opciones de configuración especificadas en un comando image create. Normalmente habrá una de estas estructuras por cada invocación del comando image create.

La tercera estructura de datos relacionada con las imágenes es una instancia de imagen. Normalmente habrá una de estas estructuras por cada uso de una imagen en un widget particular. Es posible que una misma imagen aparezca simultáneamente en varios widgets, o incluso varias veces en el mismo widget. Además, diferentes instancias pueden estar en diferentes pantallas o displays. La estructura de datos de la instancia de imagen describe cosas que pueden variar de una instancia a otra, como los colores y los contextos gráficos para el redibujado. Normalmente hay una estructura de instancia por cada opción -image especificada para un widget o un elemento de canvas.

Las siguientes subsecciones describen los campos de un Tk_ImageType con más detalle.

NOMBRE

typePtr->name proporciona un nombre para el tipo de imagen. Una vez que Tk_CreateImageType retorna, este nombre puede utilizarse en comandos image create para crear imágenes del nuevo tipo. Si ya existía un tipo de imagen con este nombre, el nuevo tipo de imagen reemplaza al antiguo.

CREATEPROC

typePtr->createProc proporciona la dirección de un procedimiento que Tk llamará cada vez que se invoque image create para crear una imagen del nuevo tipo. typePtr->createProc debe coincidir con el siguiente prototipo:

typedef int Tk_ImageCreateProc(
        Tcl_Interp *interp,
        const char *name,
        int objc,
        Tcl_Obj *const objv[],
        const Tk_ImageType *typePtr,
        Tk_ImageMaster model,
        ClientData *modelDataPtr);
El argumento interp es el intérprete en el que se invocó el comando image, y name es el nombre de la nueva imagen, que fue especificado explícitamente en el comando image o generado automáticamente por el comando image. Los argumentos objc y objv describen todas las opciones de configuración para la nueva imagen (todo lo que sigue al argumento de nombre de image). El argumento model es un token que se refiere a la información de Tk sobre esta imagen; el gestor de imagen debe devolver este token a Tk al invocar el procedimiento Tk_ImageChanged. Típicamente, createProc analizará objc y objv y creará una estructura de datos del modelo de imagen para la nueva imagen. createProc puede almacenar un valor arbitrario de una palabra en *modelDataPtr, que se devolverá al gestor de imagen al invocar otras callbacks. Típicamente, el valor es un puntero a la estructura de datos del modelo para la imagen.

Si createProc encuentra un error, debe dejar un mensaje de error en el resultado del intérprete y devolver TCL_ERROR; de lo contrario, debe devolver TCL_OK.

createProc debe llamar a Tk_ImageChanged para establecer el tamaño de la imagen y solicitar un redibujado inicial.

GETPROC

Tk invoca typePtr->getProc cada vez que un widget llama a Tk_GetImage para usar una imagen particular. Este procedimiento debe coincidir con el siguiente prototipo:

typedef ClientData Tk_ImageGetProc(
        Tk_Window tkwin,
        ClientData modelData);
El argumento tkwin identifica la ventana en la que se utilizará la imagen y modelData es el valor devuelto por createProc cuando se creó el modelo de imagen. getProc normalmente creará una estructura de datos para la nueva instancia, incluyendo cosas como los recursos necesarios para mostrar la imagen en la ventana dada. getProc devuelve un token de una palabra para la instancia, que es típicamente la dirección de la estructura de datos de la instancia. Tk devolverá este valor al gestor de imagen al invocar sus procedimientos displayProc y freeProc.

DISPLAYPROC

Tk invoca typePtr->displayProc cada vez que una imagen necesita ser mostrada (es decir, cada vez que un widget llama a Tk_RedrawImage). displayProc debe coincidir con el siguiente prototipo:

typedef void Tk_ImageDisplayProc(
        ClientData instanceData,
        Display *display,
        Drawable drawable,
        int imageX,
        int imageY,
        int width,
        int height,
        int drawableX,
        int drawableY);
instanceData será el mismo que el valor devuelto por getProc cuando se creó la instancia. display y drawable indican dónde mostrar la imagen; drawable puede ser un pixmap en lugar de la ventana especificada a getProc (este suele ser el caso, ya que la mayoría de los widgets usan doble buffer para su redibujado para obtener efectos visuales más suaves). imageX, imageY, width e height identifican la región de la imagen que debe ser redibujada. Esta región siempre estará dentro del tamaño de la imagen tal como se especificó en la llamada más reciente a Tk_ImageChanged. drawableX y drawableY indican dónde en drawable se debe mostrar la imagen; displayProc debe mostrar la región dada de la imagen de manera que el punto (imageX, imageY) en la imagen aparezca en (drawableX, drawableY) en drawable.

FREEPROC

typePtr->freeProc contiene la dirección de un procedimiento que Tk invocará cuando se libere una instancia de imagen (es decir, cuando se invoque Tk_FreeImage). Tk_InitImageArgs(3)

NAME

Tk_InitImageArgs, Tk_FreeImageMaster, Tk_DeleteImageMaster, Tk_ImageFreeProc, Tk_ImageDeleteProc, Tk_GetImageMasterData, Tk_InitImageArgs - image management procedures

SYNOPSIS

#include <tk.h>

typedef void Tk_ImageFreeProc(
        ClientData instanceData,
        Display *display);

typedef void Tk_ImageDeleteProc(
        ClientData modelData);

int Tk_InitImageArgs(
        Tcl_Interp *interp,
        char *name,
        int argc,
        char **argv,
        Tk_ImageType *typePtr,
        Tk_ImageMaster master,
        ClientData *modelDataPtr);

void Tk_FreeImageMaster(
        Tk_ImageMaster master);

void Tk_DeleteImageMaster(
        Tk_ImageMaster master);

ClientData Tk_GetImageMasterData(
        Tcl_Interp *interp,
        const char *name,
        Tk_ImageType **typePtrPtr);

ARGUMENTS

ClientData instanceData
For Tk_ImageFreeProc, this is the client data associated with a particular instance of an image. This value is the same as the value that was returned by Tk_GetImage when the instance was created.
ClientData modelData
For Tk_ImageDeleteProc, this is the client data associated with the image model. This value is the same as the value that was stored in *modelDataPtr by Tk_InitImageArgs when the image was created.
ClientData *modelDataPtr
For Tk_InitImageArgs, this is a pointer to where the client data for the image model should be stored. The client data typically points to a structure containing information about the image.
char *name
The name of the image to create or delete. This is the same name that is used in the Tk commands.
int argc
The number of arguments in argv.
char **argv
An array of strings representing the arguments to the image command. The first element of the array is the name of the image type (e.g., "bitmap", "photo"). The subsequent elements are arguments specific to that image type.
Tk_ImageType *typePtr
A pointer to a structure containing information about the image type (e.g., the names of the procedures to call for creating, deleting, and displaying images of this type). This is obtained from Tk_InitImageType.
Tk_ImageMaster master
A handle to the image model. This handle is opaque to the application programmer, but is used internally by Tk to manage the image.
Tcl_Interp *interp
The current interpreter.
Display *display
The display associated with the image instance.
const char *name
The name of the image to query.
Tk_ImageType **typePtrPtr
A pointer to a location where the address of the Tk_ImageType structure for the image will be stored. This can be NULL if the caller does not need this information.

DESCRIPTION

The Tk image manager provides a way to create and manage images that can be used in Tk widgets. An image is defined by an image type, which specifies how to create, display, and delete images of that type. When an image is created, Tk creates an "image model" that represents the image itself, and one or more "image instances" that are used to display the image in specific widgets.

The following procedures are part of the image management interface:

TK_INITIMAGEARGS

Tk_InitImageArgs is called by Tk when an image is created (e.g., via the image create command). It is responsible for parsing the arguments provided for the image, creating the image model, and storing the model's client data. It should return a handle to the newly created image model (an instance of Tk_ImageMaster). If an error occurs, it should return NULL and leave an error message in the interpreter.

The arguments are:

  • interp: The current interpreter.
  • name: The name of the image being created.
  • argc, argv: The arguments to the image creation command. The first argument in argv is expected to be the image type name (e.g., "bitmap", "photo").
  • typePtr: A pointer to the Tk_ImageType structure for this image type. This structure contains pointers to the procedures that Tk will call to manage images of this type.
  • master: This argument is unused and should be ignored.
  • modelDataPtr: A pointer to a location where the client data for the image model should be stored. This client data is typically a pointer to a structure that holds the actual image data and configuration.

The return value is a handle to the image model (Tk_ImageMaster) on success, or NULL on failure.

TK_FREEIMAGEMASTER

Tk_FreeImageMaster is called by Tk to release the resources associated with an image model when there are no longer any instances of that image. It takes a handle to the image model as its argument.

TK_DELETEIMAGEMASTER

Tk_DeleteImageMaster is called by Tk when an image is deleted (e.g., via the image delete command). It takes a handle to the image model as its argument. This procedure should release any resources associated with the image model itself.

TK_IMAGEFREEPROC

typePtr->freeProc is a procedure that Tk invokes when an image instance is no longer needed. This occurs, for example, when a widget displaying the image is destroyed, or when the image is changed to a different one. The procedure should match the following prototype:

typedef void Tk_ImageFreeProc(
                                    ClientData instanceData,
                                    Display *display);

The instanceData will be the same as the value returned by getProc when the instance was created, and display is the display containing the window for the instance. freeProc should release any resources associated with the image instance, since the instance will never be used again.

DELETEPROC

typePtr->deleteProc is a procedure that Tk invokes when an image is being deleted (i.e. when the image delete command is invoked). Before invoking deleteProc Tk will invoke freeProc for each of the image's instances. deleteProc must match the following prototype:

typedef void Tk_ImageDeleteProc(
                                    ClientData modelData);

The modelData argument will be the same as the value stored in *modelDataPtr by createProc when the image was created. deleteProc should release any resources associated with the image.

TK_GETIMAGEMODELDATA

The procedure Tk_GetImageMasterData may be invoked to retrieve information about an image. For example, an image manager can use this procedure to locate its image model data for an image. If there exists an image named name in the interpreter given by interp, then *typePtrPtr is filled in with type information for the image (the typePtr value passed to Tk_CreateImageType when the image type was registered) and the return value is the ClientData value returned by the createProc when the image was created (this is typically a pointer to the image model data structure). If no such image exists then NULL is returned and NULL is stored at *typePtrPtr.

Tk_GetImageModelData is synonym for Tk_GetImageMasterData

LEGACY INTERFACE SUPPORT

In Tk 8.2 and earlier, the definition of Tk_ImageCreateProc was incompatibly different, with the following prototype:

typedef int Tk_ImageCreateProc(
                                Tcl_Interp *interp,
                                char *name,
                                int argc,
                                char **argv,
                                Tk_ImageType *typePtr,
                                Tk_ImageMaster model,
                                ClientData *modelDataPtr);

Legacy programs and libraries dating from those days may still contain code that defines extended Tk image types using the old interface. The Tk header file will still support this legacy interface if the code is compiled with the macro USE_OLD_IMAGE defined.

Tk_ImageModel is synonym for Tk_ImageMaster

When the USE_OLD_IMAGE legacy support is enabled, you may see the routine Tk_InitImageArgs in use. This was a migration tool used to create stub-enabled extensions that could be loaded into interps containing all versions of Tk 8.1 and later. Tk 8.5 no longer provides this routine, but uses a macro to convert any attempted calls of this routine into an empty comment. Any stub-enabled extension providing an extended image type via the legacy interface that is compiled against Tk 8.5 headers and linked against the Tk 8.5 stub library will produce a file that can be loaded only into interps with Tk 8.5 or later; that is, the normal stub-compatibility rules. If a developer needs to generate from such code a file that is loadable into interps with Tk 8.4 or earlier, they must use Tk 8.4 headers and stub libraries to do so.

Any new code written today should not make use of the legacy interfaces. Expect their support to go away in Tk 9.
