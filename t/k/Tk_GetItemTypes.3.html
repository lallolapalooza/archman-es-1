Tk_GetItemTypes(3)

Paquete: tk

Licencias: TCL

Tk_CreateItemType(3) Tk Library Procedures Tk_CreateItemType(3)

NOMBRE

Tk_CreateItemType, Tk_GetItemTypes - define un nuevo tipo de elemento de lienzo

SINOPSIS

#include <tk.h>

Tk_CreateItemType(typePtr)

Tk_ItemType *
Tk_GetItemTypes()

ARGUMENTOS

Tk_ItemType *typePtr (entrada)
Estructura que define el nuevo tipo de elemento de lienzo.

INTRODUCCIÓN

Tk_CreateItemType se invoca para definir un nuevo tipo de elemento de lienzo descrito por el argumento typePtr. Un tipo de elemento corresponde a un valor particular del argumento type del comando de widget create para lienzos, y el código que implementa un tipo de elemento de lienzo se llama un gestor de tipo. Tk define varios tipos de elementos integrados, como rectangle y text e image, pero Tk_CreateItemType permite definir tipos de elementos adicionales. Una vez que Tk_CreateItemType regresa, el nuevo tipo de elemento puede ser utilizado en lienzos nuevos o existentes igual que los tipos de elementos integrados.

Tk_GetItemTypes devuelve un puntero al primero en la lista de todos los tipos de elementos actualmente definidos para lienzos. Las entradas en la lista están enlazadas a través de sus campos nextPtr, con el final de la lista marcado por un nextPtr NULL.

Puede resultarle más fácil entender el resto de esta entrada del manual si consulta el código de un tipo de elemento de lienzo existente, como el bitmap (en el archivo tkCanvBmap.c) o el texto (tkCanvText.c). La forma más sencilla de crear un nuevo gestor de tipo es copiar el código de un tipo existente y modificarlo para el nuevo tipo.

Tk proporciona una serie de procedimientos de utilidad para el uso de gestores de tipos de lienzo, como Tk_CanvasCoords y Tk_CanvasPsColor; estos se describen en entradas de manual separadas.

ESTRUCTURAS DE DATOS

Un gestor de tipo consiste en una colección de procedimientos que proporcionan un conjunto estándar de operaciones sobre elementos de ese tipo. El gestor de tipo maneja tres tipos de estructuras de datos. La primera estructura de datos es un Tk_ItemType; contiene información como el nombre del tipo y punteros a los procedimientos estándar implementados por el gestor de tipo:

typedef struct Tk_ItemType {
    const char *name;
    int itemSize;
    Tk_ItemCreateProc *createProc;
    const Tk_ConfigSpec *configSpecs;
    Tk_ItemConfigureProc *configProc;
    Tk_ItemCoordProc *coordProc;
    Tk_ItemDeleteProc *deleteProc;
    Tk_ItemDisplayProc *displayProc;
    int alwaysRedraw;
    Tk_ItemPointProc *pointProc;
    Tk_ItemAreaProc *areaProc;
    Tk_ItemPostscriptProc *postscriptProc;
    Tk_ItemScaleProc *scaleProc;
    Tk_ItemTranslateProc *translateProc;
    Tk_ItemIndexProc *indexProc;
    Tk_ItemCursorProc *icursorProc;
    Tk_ItemSelectionProc *selectionProc;
    Tk_ItemInsertProc *insertProc;
    Tk_ItemDCharsProc *dCharsProc;
    Tk_ItemType *nextPtr;
} Tk_ItemType;

Los campos de una estructura Tk_ItemType se describen con más detalle más adelante en esta entrada del manual. Cuando se llama a Tk_CreateItemType, su argumento typePtr debe apuntar a una estructura con todos los campos inicializados excepto nextPtr, que Tk establece para enlazar todos los tipos en una lista. La estructura debe estar en memoria permanente (ya sea asignada estáticamente o asignada dinámicamente pero nunca liberada); Tk conserva un puntero a esta estructura.

La segunda estructura de datos manipulada por un gestor de tipo es un registro de elemento. Para cada elemento en un lienzo existe un registro de elemento. Todos los elementos de un tipo determinado generalmente tienen registros de elemento con la misma estructura, pero diferentes tipos suelen tener diferentes formatos para sus registros de elemento. La primera parte de cada registro de elemento es una cabecera con una estructura estándar definida por Tk a través del tipo Tk_Item; el resto del registro de elemento es definido por el gestor de tipo. Un gestor de tipo debe definir sus registros de elemento con un Tk_Item como primer campo. Por ejemplo, el registro de elemento para los elementos de bitmap se define de la siguiente manera:

typedef struct BitmapItem {
    Tk_Item header;
    double x, y;
    Tk_Anchor anchor;
    Pixmap bitmap;
    XColor *fgColor;
    XColor *bgColor;
    GC gc;
} BitmapItem;

La subestructura header contiene información utilizada por Tk para gestionar el elemento, como su identificador, sus etiquetas, su tipo y su cuadro delimitador. Los campos que comienzan con x pertenecen al gestor de tipo: Tk nunca los leerá ni los escribirá. El gestor de tipo no necesitará leer ni escribir ninguno de los campos de la cabecera, excepto cuatro campos cuyos nombres son x1, y1, x2 e y2. Estos campos proporcionan un cuadro delimitador para los elementos utilizando coordenadas enteras del lienzo: el elemento no debe cubrir ningún píxel con una coordenada x inferior a x1 o una coordenada y inferior a y1, ni debe cubrir ningún píxel con una coordenada x igual o superior a x2 o una coordenada y igual o superior a y2. Es responsabilidad del gestor de tipo mantener el cuadro delimitador actualizado a medida que el elemento se mueve y se reconfigura.

Siempre que Tk llama a un procedimiento en un gestor de tipo, le pasa un puntero a un registro de elemento. El argumento se pasa siempre como un puntero a un Tk_Item; el gestor de tipo normalmente lo convertirá a un puntero a su tipo específico, como BitmapItem.

La tercera estructura de datos utilizada por los gestores de tipo tiene el tipo Tk_Canvas; sirve como un identificador opaco para el widget de lienzo en su conjunto. Los gestores de tipo no necesitan saber nada sobre el contenido de esta estructura. Un identificador Tk_Canvas se pasa normalmente a los procedimientos de un gestor de tipo, y el gestor de tipo puede pasar el identificador de vuelta a procedimientos de la biblioteca como Tk_CanvasTkwin para obtener información sobre el lienzo.

CAMPOS DE TK_ITEMTYPE

NOMBRE

Esta sección y las siguientes describen cada uno de los campos de una estructura Tk_ItemType en detalle. El campo name proporciona un nombre de cadena para el tipo de elemento. Una vez que Tk_CreateImageType regresa, este nombre puede ser utilizado en comandos de widget create para crear elementos del nuevo tipo. Si ya existía un tipo de elemento con este nombre, el nuevo tipo de elemento reemplaza al anterior.

BANDERAS (EN ALWAYSREDRAW)

El campo typePtr->alwaysRedraw (nombrado así por razones históricas) contiene una colección de bits de bandera que modifican cómo el núcleo del lienzo interactúa con el elemento. Los siguientes bits están definidos:

1
Indica que el elemento debe ser redibujado siempre que se redibuje alguna parte del lienzo, en lugar de solo cuando el cuadro delimitador del elemento se superpone al área que se está redibujando. Esto se utiliza, por ejemplo, para los elementos de ventana, que necesitan desmapear subventanas que no están en pantalla.
TK_CONFIG_OBJS
Indica que las operaciones que de otro modo tomarían una cadena (o un array de cadenas) en realidad toman una referencia a Tcl_Obj (o un array de tales referencias). Las operaciones a las que se aplica esto son configProc, coordProc, createProc, indexProc y insertProc.
TK_MOVABLE_POINTS
Indica que el elemento soporta dCharsProc, indexProc e insertProc con la misma semántica que los tipos de línea y polígono integrados de Tk, y que por lo tanto los puntos de coordenada individuales pueden moverse. No debe establecerse si alguno de los métodos anteriores es NULL.

ITEMSIZE

typePtr->itemSize proporciona el tamaño en bytes de los registros de elementos de este tipo, incluyendo la cabecera Tk_Item. Tk usa este tamaño para asignar espacio de memoria para elementos del tipo. Todos los registros de elementos para un tipo dado deben tener el mismo tamaño. Si se necesitan campos de longitud variable para un elemento (como una lista de puntos para un polígono), el gestor de tipo puede asignar un objeto separado de longitud variable y mantener un puntero a él en el registro de elemento.

CREATEPROC

typePtr->createProc apunta a un procedimiento que debe ser llamado por el código del lienzo cada vez que se crea un nuevo elemento de este tipo. El procedimiento debe tener la siguiente interfaz:

typedef int Tk_ItemCreateProc _ANSI_PROTO_((ClientData clientData,
        Tk_Canvas canvas, int argc, char **argv));

El argumento clientData es el valor que se le pasó a Tk_CreateItemType cuando se definió este tipo de elemento. El argumento canvas es el identificador del widget de lienzo que está creando el elemento. El argumento argc y argv contienen los argumentos restantes de la opción create del comando del lienzo, que se utilizan para configurar el nuevo elemento. El procedimiento createProc debe parsear estos argumentos, llamar a Tk_ConfigParse para procesar las opciones de configuración estándar, asignar memoria para el nuevo registro de elemento (que debe tener el tamaño especificado por itemSize), inicializar el registro del elemento y devolver un puntero al registro del elemento recién creado. Si ocurre un error, el procedimiento debe devolver NULL; de lo contrario, debe devolver un puntero al registro del elemento.

CONFIGSPECS

typePtr->configSpecs es un puntero a una matriz de estructuras Tk_ConfigSpec que describe las opciones de configuración para elementos de este tipo. La matriz debe estar terminada por una entrada con un campo optionName de NULL. Véase Tk_ConfigureInfo para una descripción de las estructuras Tk_ConfigSpec. La matriz de especificaciones de configuración puede ser la misma que se utiliza para el tipo de elemento base (por ejemplo, Tk_BasicConfigSpecs), o puede ser una matriz que incluya especificaciones adicionales. Si se utiliza Tk_BasicConfigSpecs, el gestor del tipo de elemento aún es responsable de gestionar las opciones que se incluyen en Tk_BasicConfigSpecs (como las opciones de color de primer plano y de fondo), pero no necesita definirlas explícitamente en su propia matriz de especificaciones de configuración.

CONFIGPROC

typePtr->configProc apunta a un procedimiento que debe ser llamado por el código del lienzo cada vez que se modifica un elemento de este tipo utilizando el comando configure del lienzo. El procedimiento debe tener la siguiente interfaz:

typedef void Tk_ItemConfigureProc _ANSI_PROTO_((ClientData clientData,
        Tk_Canvas canvas, Tk_Item *itemPtr, int argc, char **argv));

El argumento clientData es el valor que se le pasó a Tk_CreateItemType cuando se definió este tipo de elemento. El argumento canvas es el identificador del widget de lienzo. itemPtr es un puntero al registro del elemento que se está configurando. Los argumentos argc y argv contienen los argumentos restantes del comando configure del lienzo. El procedimiento configProc debe parsear estos argumentos, llamar a Tk_ConfigParse para procesar las opciones de configuración que se enumeran en configSpecs, y actualizar el registro del elemento como sea necesario. Debe devolver un código de retorno de 0 si la configuración se realizó correctamente, o un código de error si se produjo un error.

COORDPROC

typePtr->coordProc apunta a un procedimiento que debe ser llamado por el código del lienzo cada vez que se modifican las coordenadas de un elemento de este tipo utilizando el comando coords del lienzo. El procedimiento debe tener la siguiente interfaz:

typedef int Tk_ItemCoordProc _ANSI_PROTO_((ClientData clientData,
        Tk_Canvas canvas, Tk_Item *itemPtr, int argc, char **argv));

Los argumentos clientData, canvas, argc y argv son los mismos que para configProc. itemPtr es un puntero al registro del elemento que se está modificando. El procedimiento coordProc debe parsear los argumentos argc y argv para extraer las nuevas coordenadas, actualizar el registro del elemento como sea necesario, y devolver 0 si se realizó correctamente o un código de error si se produjo un error.

DELETEPROC

typePtr->deleteProc apunta a un procedimiento que debe ser llamado por el código del lienzo cada vez que se elimina un elemento de este tipo. El procedimiento debe tener la siguiente interfaz:

typedef void Tk_ItemDeleteProc _ANSI_PROTO_((ClientData clientData,
        Tk_Canvas canvas, Tk_Item *itemPtr));

Los argumentos clientData y canvas son los mismos que para configProc. itemPtr es un puntero al registro del elemento que se está eliminando. El procedimiento deleteProc debe liberar cualquier memoria asignada dinámicamente por el registro del elemento o por el propio gestor de tipo para este elemento, y debe realizar cualquier otra limpieza necesaria. Tk se encargará de liberar el registro del elemento en sí.

DISPLAYPROC

typePtr->displayProc apunta a un procedimiento que debe ser llamado por el código del lienzo cada vez que se necesita redibujar un elemento de este tipo. El procedimiento debe tener la siguiente interfaz:

typedef void Tk_ItemDisplayProc _ANSI_PROTO_((ClientData clientData,
        Tk_Canvas canvas, Tk_Item *itemPtr, Drawable drawable, int x, int y,
        int width, int height));

Los argumentos clientData y canvas son los mismos que para configProc. itemPtr es un puntero al registro del elemento que se va a dibujar. El argumento drawable es el identificador de la ventana o pixmap en la que se debe dibujar el elemento. Los argumentos x, y, width y height especifican un área rectangular dentro de la cual se debe dibujar el elemento (en coordenadas de pantalla). El procedimiento displayProc es responsable de dibujar el elemento en la ventana especificada utilizando los gráficos X y la información del registro del elemento. Solo debe dibujar dentro del área especificada por x, y, width y height.

POINTPROC

typePtr->pointProc apunta a un procedimiento que debe ser llamado por el código del lienzo para determinar si un punto dado cae dentro de un elemento de este tipo. El procedimiento debe tener la siguiente interfaz:

typedef int Tk_ItemPointProc _ANSI_PROTO_((ClientData clientData,
        Tk_Canvas canvas, Tk_Item *itemPtr, int x, int y));

Los argumentos clientData y canvas son los mismos que para configProc. itemPtr es un puntero al registro del elemento. Los argumentos x e y son las coordenadas del punto a comprobar. El procedimiento debe devolver 1 si el punto cae dentro del elemento, y 0 en caso contrario.

AREAPROC

typePtr->areaProc apunta a un procedimiento que debe ser llamado por el código del lienzo para determinar si un área rectangular dada se superpone a un elemento de este tipo. El procedimiento debe tener la siguiente interfaz:

typedef int Tk_ItemAreaProc _ANSI_PROTO_((ClientData clientData,
        Tk_Canvas canvas, Tk_Item *itemPtr, int x1, int y1, int x2, int y2));

Los argumentos clientData y canvas son los mismos que para configProc. itemPtr es un puntero al registro del elemento. Los argumentos x1, y1, x2 e y2 especifican las coordenadas del área rectangular. El procedimiento debe devolver 1 si el área se superpone al elemento, y 0 en caso contrario.

POSTSCRIPTPROC

typePtr->postscriptProc apunta a un procedimiento que debe ser llamado por el código del lienzo para generar código PostScript para un elemento de este tipo. El procedimiento debe tener la siguiente interfaz:

typedef void Tk_ItemPostscriptProc _ANSI_PROTO_((ClientData clientData,
        Tk_Canvas canvas, Tk_Item *itemPtr, FILE *fp, int x, int y, int width,
        int height));

Los argumentos clientData y canvas son los mismos que para configProc. itemPtr es un puntero al registro del elemento. fp es un puntero al archivo en el que se escribirá el código PostScript. Los argumentos x, y, width y height especifican un área rectangular para recortar el PostScript. El procedimiento debe generar código PostScript que dibuje el elemento dentro del área especificada. Si el elemento no se puede dibujar en PostScript, el procedimiento no debe hacer nada.

SCALEPROC

typePtr->scaleProc apunta a un procedimiento que debe ser llamado por el código del lienzo para escalar un elemento de este tipo. El procedimiento debe tener la siguiente interfaz:

typedef void Tk_ItemScaleProc _ANSI_PROTO_((ClientData clientData,
        Tk_Canvas canvas, Tk_Item *itemPtr, double x, double y, double scaleX,
        double scaleY));

Los argumentos clientData y canvas son los mismos que para configProc. itemPtr es un puntero al registro del elemento. Los argumentos x e y son el punto de origen para el escalado. Los argumentos scaleX y scaleY son los factores de escala en las direcciones x e y. El procedimiento debe actualizar las coordenadas del elemento según sea necesario.

TRANSLATEPROC

typePtr->translateProc apunta a un procedimiento que debe ser llamado por el código del lienzo para traducir un elemento de este tipo. El procedimiento debe tener la siguiente interfaz:

typedef void Tk_ItemTranslateProc _ANSI_PROTO_((ClientData clientData,
        Tk_Canvas canvas, Tk_Item *itemPtr, double deltaX, double deltaY));

Los argumentos clientData y canvas son los mismos que para configProc. itemPtr es un puntero al registro del elemento. Los argumentos deltaX y deltaY son las cantidades a trasladar en las direcciones x e y. El procedimiento debe actualizar las coordenadas del elemento según sea necesario.

INDEXPROC

typePtr->indexProc apunta a un procedimiento que debe ser llamado por el código del lienzo para obtener el índice de un elemento de este tipo. El procedimiento debe tener la siguiente interfaz:

typedef int Tk_ItemIndexProc _ANSI_PROTO_((ClientData clientData,
        Tk_Canvas canvas, Tk_Item *itemPtr, char *index));

Los argumentos clientData y canvas son los mismos que para configProc. itemPtr es un puntero al registro del elemento. El argumento index es una cadena que especifica un índice. El procedimiento debe devolver el índice numérico del elemento si se puede interpretar como un índice, o un código de error si no se puede. Por ejemplo, para los tipos de línea y polígono, esta función se utiliza para interpretar índices como "primer", "último" o "último".

ICURSORPROC

typePtr->icursorProc apunta a un procedimiento que debe ser llamado por el código del lienzo para determinar la posición del cursor de inserción dentro de un elemento de este tipo. El procedimiento debe tener la siguiente interfaz:

typedef int Tk_ItemCursorProc _ANSI_PROTO_((ClientData clientData,
        Tk_Canvas canvas, Tk_Item *itemPtr, int index));

Los argumentos clientData y canvas son los mismos que para configProc. itemPtr es un puntero al registro del elemento. El argumento index es un índice dentro del elemento. El procedimiento debe devolver la coordenada x del cursor de inserción en ese índice, o un código de error si el índice no es válido.

SELECTIONPROC

typePtr->selectionProc apunta a un procedimiento que debe ser llamado por el código del lienzo para determinar qué parte de un elemento de este tipo está seleccionada. El procedimiento debe tener la siguiente interfaz:

typedef void Tk_ItemSelectionProc _ANSI_PROTO_((ClientData clientData,
        Tk_Canvas canvas, Tk_Item *itemPtr, char *selectionArg));

Los argumentos clientData y canvas son los mismos que para configProc. itemPtr es un puntero al registro del elemento. El argumento selectionArg es una cadena que especifica la selección deseada (por ejemplo, "subseteq", "first", "last"). El procedimiento debe devolver información sobre la selección en una forma que sea útil para el usuario. Por ejemplo, para los elementos de texto, esto podría ser un rango de caracteres.

INSERTPROC

typePtr->insertProc apunta a un procedimiento que debe ser llamado por el código del lienzo para insertar texto en un elemento de este tipo. El procedimiento debe tener la siguiente interfaz:

typedef int Tk_ItemInsertProc _ANSI_PROTO_((ClientData clientData,
        Tk_Canvas canvas, Tk_Item *itemPtr, char *index, char *string));

Los argumentos clientData y canvas son los mismos que para configProc. itemPtr es un puntero al registro del elemento. El argumento index es una cadena que especifica dónde insertar el texto. El argumento string es el texto a insertar. El procedimiento debe insertar el texto en el elemento y devolver 0 si se realizó correctamente, o un código de error si se produjo un error. Por ejemplo, esto se utiliza para los elementos de texto y los elementos de entrada de lienzo.

DCHARSPROC

typePtr->dCharsProc apunta a un procedimiento que debe ser llamado por el código del lienzo para eliminar caracteres de un elemento de este tipo. El procedimiento debe tener la siguiente interfaz:

typedef int Tk_ItemDCharsProc _ANSI_PROTO_((ClientData clientData,
        Tk_Canvas canvas, Tk_Item *itemPtr, char *index1, char *index2));

Los argumentos clientData y canvas son los mismos que para configProc. itemPtr es un puntero al registro del elemento. Los argumentos index1 y index2 son cadenas que especifican el rango de caracteres a eliminar. El procedimiento debe eliminar los caracteres especificados del elemento y devolver 0 si se realizó correctamente, o un código de error si se produjo un error. Por ejemplo, esto se utiliza para los elementos de texto y los elementos de entrada de lienzo.

NEXTPTR

El campo nextPtr es utilizado internamente por Tk para enlazar todas las estructuras Tk_ItemType en una lista enlazada. Debe ser inicializado a NULL en la estructura Tk_ItemType proporcionada a Tk_CreateItemType.

HISTORIA

Tk 8.0 introdujo el uso de Tcl_Obj para los argumentos de configuración y coordenadas. Si el bit TK_CONFIG_OBJS está establecido en el campo alwaysRedraw, entonces los procedimientos configProc, coordProc, createProc, indexProc e insertProc deben esperar argumentos Tcl_Obj en lugar de cadenas de caracteres C. Los prototipos de procedimiento se ajustan en consecuencia:

typedef int Tk_ItemCreateProc _ANSI_PROTO_((ClientData clientData,
        Tk_Canvas canvas, int objc, Tcl_Obj *const objv[]));
typedef void Tk_ItemConfigureProc _ANSI_PROTO_((ClientData clientData,
        Tk_Canvas canvas, Tk_Item *itemPtr, int objc, Tcl_Obj *const objv[]));
typedef int Tk_ItemCoordProc _ANSI_PROTO_((ClientData clientData,
        Tk_Canvas canvas, Tk_Item *itemPtr, int objc, Tcl_Obj *const objv[]));
typedef int Tk_ItemInsertProc _ANSI_PROTO_((ClientData clientData,
        Tk_Canvas canvas, Tk_Item *itemPtr, Tcl_Obj *indexPtr, Tcl_Obj *stringPtr));
typedef int Tk_ItemIndexProc _ANSI_PROTO_((ClientData clientData,
        Tk_Canvas canvas, Tk_Item *itemPtr, Tcl_Obj *indexPtr));

NAME

Tk_ItemProc - canvas item type procedures

SYNOPSIS

DESCRIPTION

A canvas item type is described by a structure of type Tk_ItemType, which contains pointers to procedures that implement various operations on items of that type. The structure is defined in <tk.h> as:

typedef struct Tk_ItemType {
    char *name;
    Tk_ItemCreateProc *createProc;
    Tk_ItemDeleteProc *deleteProc;
    Tk_ItemDisplayProc *displayProc;
    Tk_ItemPointerProc *pointProc;
    Tk_ItemCoordsProc *coordsProc;
    Tk_ItemNameIndexProc *nameIndexProc;
    Tk_ItemIndexProc *indexProc;
    Tk_ItemSelectstuffs *selectstuffsProc;
    Tk_ItemAreaProc *areaProc;
    Tk_ItemScaleProc *scaleProc;
    Tk_ItemTranslateProc *translateProc;
    Tk_ItemFocusProc *focusProc;
    Tk_ItemTypeVersion version;
    Tk_ItemConfigProc *configProc;
    Tk_ItemPeekProc *peekProc;
    Tk_ItemEquivProc *equivProc;
    Tk_ItemPostscriptProc *postscriptProc;
    Tk_ItemChatProc *chatProc;
    Tk_ItemSetFocusProc *setFocusProc;
    Tk_ItemDissociateProc *dissociateProc;
    Tk_ItemCursorProc *icursorProc;
    Tk_ItemSelectionProc *selectionProc;
    Tk_ItemInsertProc *insertProc;
    Tk_ItemDCharsProc *dCharsProc;
    int alwaysRedraw;
} Tk_ItemType;

The following sections describe the procedures that make up an item type.

CREATEPROC

typePtr->createProc is invoked by Tk to create a new canvas item. It is called when the canvas is created or modified using the create widget command. The procedure must match the following prototype:

typedef int Tk_ItemCreateProc(
        Tcl_Interp *interp,
        Tk_Canvas canvas,
        Tk_Item *itemPtr,
        int argc,
        Tcl_Obj *const argv[]);

interp is the Tcl interpreter, canvas is the canvas widget, and itemPtr is a pointer to the new item structure. The item's type has already been filled in, and its coordinates and configuration options need to be initialized. argc and argv contain the arguments to the create command. createProc should parse these arguments, initialize the item's fields, and set the item's bounding box. If the item is created successfully, createProc should return TCL_OK; otherwise, it should return TCL_ERROR and leave an error message in the interpreter's result.

DELETEPROC

typePtr->deleteProc is invoked by Tk to delete a canvas item. It is called when the item is deleted using the delete widget command, or when the canvas is destroyed. The procedure must match the following prototype:

typedef void Tk_ItemDeleteProc(
        Tk_Canvas canvas,
        Tk_Item *itemPtr);

The canvas and itemPtr arguments have the usual meaning. deleteProc should free any memory that was dynamically allocated by the item (e.g., for text or coordinates) and perform any other cleanup needed for the item.

DISPLAYPROC

typePtr->displayProc is invoked by Tk to draw a canvas item on the screen. The procedure must match the following prototype:

typedef void Tk_ItemDisplayProc(
        Tk_Canvas canvas,
        Tk_Item *itemPtr,
        Display *display,
        Drawable drawable,
        int x,
        int y,
        int width,
        int height);

The canvas and itemPtr arguments have the usual meaning. display is the X server connection, and drawable is the window or pixmap in which to draw. x, y, width, and height define the clipping rectangle for the drawing operation. displayProc should draw the item in the specified window or pixmap, respecting the clipping rectangle. It should only draw those parts of the item that are within the clipping rectangle.

POINTPROC

typePtr->pointProc is invoked by Tk to determine which item is at a given screen coordinate. The procedure must match the following prototype:

typedef double Tk_ItemPointProc(
        Tk_Canvas canvas,
        Tk_Item *itemPtr,
        int x,
        int y);

The canvas and itemPtr arguments have the usual meaning. x and y are screen coordinates. pointProc should return a distance value: 0 if the point (x, y) is inside the item, and a larger value (e.g., the distance from the point to the closest edge of the item) if the point is outside. Tk uses these values to determine which item is closest to the given coordinates when multiple items are present.

COORDSPROC

typePtr->coordsProc is invoked by Tk to modify the coordinates of an existing canvas item. The procedure must match the following prototype:

typedef void Tk_ItemCoordsProc(
        Tk_Item *itemPtr,
        Tcl_Interp *interp);

The itemPtr argument points to the item whose coordinates are to be modified. interp is the Tcl interpreter; the procedure should read the new coordinates from the interpreter's result and update the item's coordinates and bounding box accordingly. It should also update the interpreter's result to reflect the new coordinates.

POSTSCRIPTPROC

typePtr->postscriptProc is invoked by Tk to generate Postscript for a canvas item. The procedure must match the following prototype:

typedef void Tk_ItemPostscriptProc(
        Tk_Canvas canvas,
        Tk_Item *itemPtr,
        Tcl_Interp *interp,
        int prepass);

The canvas and itemPtr arguments have the usual meaning. If prepass is non-zero, this is the first pass of a two-pass Postscript generation process; if prepass is 0, this is the second pass. During the first pass, the type manager should only generate Postscript that is needed to collect font information. This information is collected by calls to procedures such as Tk_CanvasPsFont. The actual Postscript generated during the first pass is discarded. If prepass is non-zero, the procedure should return immediately after collecting font information. If prepass is 0, the procedure should generate the complete Postscript for the item. This Postscript should be appended to the interpreter's result using Tcl_AppendResult. If an error occurs during Postscript generation, the procedure should clear the interpreter's result, replace it with an error message, and return TCL_ERROR. Otherwise, it should return TCL_OK. The prepass argument will be described in more detail below. If postscriptProc completes successfully, it should append Postscript for the item to the information in the interpreter result (e.g. by calling Tcl_AppendResult, not Tcl_SetResult) and return TCL_OK. If an error occurs, postscriptProc should clear the result and replace its contents with an error message; then it should return TCL_ERROR.

Tk provides a collection of utility procedures to simplify postscriptProc. For example, Tk_CanvasPsColor will generate Postscript to set the current color to a given Tk color and Tk_CanvasPsFont will set up font information. When generating Postscript, the type manager is free to change the graphics state of the Postscript interpreter, since Tk places gsave and grestore commands around the Postscript for the item. The type manager can use canvas x coordinates directly in its Postscript, but it must call Tk_CanvasPsY to convert y coordinates from the space of the canvas (where the origin is at the upper left) to the space of Postscript (where the origin is at the lower left).

In order to generate Postscript that complies with the Adobe Document Structuring Conventions, Tk actually generates Postscript in two passes. It calls each item's postscriptProc in each pass. The only purpose of the first pass is to collect font information (which is done by Tk_CanvasPsFont); the actual Postscript is discarded. Tk sets the prepass argument to postscriptProc to 1 during the first pass; the type manager can use prepass to skip all Postscript generation except for calls to Tk_CanvasPsFont. During the second pass prepass will be 0, so the type manager must generate complete Postscript.

SCALEPROC

typePtr->scaleProc is invoked by Tk to rescale a canvas item during the scale widget command. The procedure must match the following prototype:

typedef void Tk_ItemScaleProc(
        Tk_Canvas canvas,
        Tk_Item *itemPtr,
        double originX,
        double originY,
        double scaleX,
        double scaleY);

The canvas and itemPtr arguments have the usual meaning. originX and originY specify an origin relative to which the item is to be scaled, and scaleX and scaleY give the x and y scale factors. The item should adjust its coordinates so that a point in the item that used to have coordinates x and y will have new coordinates x′ and y′, where

x′ = originX + scaleX × (x − originX)
y′ = originY + scaleY × (y − originY)

scaleProc must also update the bounding box in the item's header.

TRANSLATEPROC

typePtr->translateProc is invoked by Tk to translate a canvas item during the move widget command. The procedure must match the following prototype:

typedef void Tk_ItemTranslateProc(
        Tk_Canvas canvas,
        Tk_Item *itemPtr,
        double deltaX,
        double deltaY);

The canvas and itemPtr arguments have the usual meaning, and deltaX and deltaY give the amounts that should be added to each x and y coordinate within the item. The type manager should adjust the item's coordinates and update the bounding box in the item's header.

INDEXPROC

typePtr->indexProc is invoked by Tk to translate a string index specification into a numerical index, for example during the index widget command. It is only relevant for item types that support indexable text or coordinates; typePtr->indexProc may be specified as NULL for non-textual item types if they do not support detailed coordinate addressing. The procedure must match the following prototype:

typedef int Tk_ItemIndexProc(
        Tcl_Interp *interp,
        Tk_Canvas canvas,
        Tk_Item *itemPtr,
        Tcl_Obj *indexObj,
        int *indexPtr);

The interp, canvas, and itemPtr arguments all have the usual meaning. indexObj contains a textual description of an index, and indexPtr points to an integer value that should be filled in with a numerical index. Note that if TK_CONFIG_OBJS is not set in the typePtr->alwaysRedraw field, the indexObj parameter will actually contain a pointer to a constant string. It is up to the type manager to decide what forms of index are supported (e.g., numbers, insert, sel.first, end, etc.). indexProc should return a Tcl completion code and set the interpreter result in the event of an error.

ICURSORPROC

typePtr->icursorProc is invoked by Tk during the icursor widget command to set the position of the insertion cursor in a textual item. It is only relevant for item types that support an insertion cursor; typePtr->icursorProc may be specified as NULL for item types that do not support an insertion cursor. The procedure must match the following prototype:

typedef void Tk_ItemCursorProc(
        Tk_Canvas canvas,
        Tk_Item *itemPtr,
        int index);

canvas and itemPtr have the usual meanings, and index is an index into the item's text, as returned by a previous call to typePtr->insertProc. The type manager should position the insertion cursor in the item just before the character given by index. Whether or not to actually display the insertion cursor is determined by other information provided by Tk_CanvasGetTextInfo.

SELECTIONPROC

typePtr->selectionProc is invoked by Tk during selection retrievals; it must return part or all of the selected text in the item (if any). It is only relevant for item types that support text; typePtr->selectionProc may be specified as NULL for non-textual item types. The procedure must match the following prototype:

typedef int Tk_ItemSelectionProc(
        Tk_Canvas canvas,
        Tk_Item *itemPtr,
        int offset,
        char *buffer,
        int maxBytes);

canvas and itemPtr have the usual meanings. offset is an offset in bytes into the selection where 0 refers to the first byte of the selection; it identifies the first character that is to be returned in this call. buffer points to an area of memory in which to store the requested bytes, and maxBytes specifies the maximum number of bytes to return. selectionProc should extract up to maxBytes characters from the selection and copy them to maxBytes; it should return a count of the number of bytes actually copied, which may be less than maxBytes if there are not offset+maxBytes bytes in the selection.

INSERTPROC

typePtr->insertProc is invoked by Tk during the insert widget command to insert new text or coordinates into a canvas item. It is only relevant for item types that support the insert method; typePtr->insertProc may be specified as NULL for other item types. The procedure must match the following prototype:

typedef void Tk_ItemInsertProc(
        Tk_Canvas canvas,
        Tk_Item *itemPtr,
        int index,
        Tcl_Obj *obj);

canvas and itemPtr have the usual meanings. index is an index into the item's text, as returned by a previous call to typePtr->insertProc, and obj contains new text to insert just before the character given by index. Note that if TK_CONFIG_OBJS is not set in the typePtr->alwaysRedraw field, the obj parameter will actually contain a pointer to a constant string to be inserted. The type manager should insert the text and recompute the bounding box in the item's header.

DCHARSPROC

typePtr->dCharsProc is invoked by Tk during the dchars widget command to delete a range of text from a canvas item or a range of coordinates from a pathed item. It is only relevant for item types that support text; typePtr->dCharsProc may be specified as NULL for non-textual item types that do not want to support coordinate deletion. The procedure must match the following prototype:

typedef void Tk_ItemDCharsProc(
        Tk_Canvas canvas,
        Tk_Item *itemPtr,
        int first,
        int last);

canvas and itemPtr have the usual meanings. first and last give the indices of the first and last bytes to be deleted, as returned by previous calls to typePtr->indexProc. The type manager should delete the specified characters and update the bounding box in the item's header.

NAME
Tk_GetItemTypes — obtain information about the item types supported by a Tk widget

SYNOPSIS

#include <tk.h>
int
Tk_GetItemTypes(interp, tkwin, numPtr, itemTypePtr)
    Tcl_Interp *interp;
    Tk_Window tkwin;
    int *numPtr;
    Tk_ItemType **itemTypePtr;

ARGUMENTS

Tcl_Interp *interp
Interpreter to use for error reporting.
Tk_Window tkwin
Token for the window that the item types are associated with.
int *numPtr
If non-NULL, a pointer to an integer. On return, this will contain the number of item types supported by the widget.
Tk_ItemType **itemTypePtr
If non-NULL, a pointer to a pointer to Tk_ItemType structures. On return, this will point to an array of Tk_ItemType structures, one for each item type supported by the widget. The memory for this array is allocated by this function and must be freed by the caller using Tcl_Free.

INTRODUCTION

The Tk_GetItemTypes function returns information about the item types supported by a given Tk widget. This is typically used by canvas widgets to implement item creation and manipulation commands. The information is returned as an array of Tk_ItemType structures, which contain pointers to functions that implement the item type’s behavior.

DATA STRUCTURES

The Tk_ItemType structure is defined as follows:

typedef struct Tk_ItemType {
    const char *name;
    Tcl_Command deleteCmd;
    Tcl_Command createCmd;
    Tcl_Command postscriptCmd;
    int flags;
    ClientData clientData;
    Tcl_CmdDeleteProc *deleteDataProc;
    Tk_ItemeteriesProc *itemeteriesProc;
    Tk_CoordsProc *coordsProc;
    Tk_DrawProc *drawProc;
    Tk_MoveProc *moveProc;
    Tk_SelectedProc *selectedProc;
    Tk_HasProc *hasProc;
} Tk_ItemType;

TK_ITEMTYPE FIELDS

name
The name of the item type (e.g., "line", "rectangle", "text").
deleteCmd
A Tcl command procedure that is called when an item of this type is deleted.
createCmd
A Tcl command procedure that is called when an item of this type is created.
postscriptCmd
A Tcl command procedure that is called when an item of this type is included in a PostScript output.
flags
A bitmask of flags that control the behavior of the item type. Currently, no flags are defined.
clientData
Arbitrary data associated with the item type.
deleteDataProc
A procedure that is called when the item type is destroyed, to free any data associated with it.
itemeteriesProc
A procedure that is called to get the item’s geometry.
coordsProc
A procedure that is called to get or set the item’s coordinates.
drawProc
A procedure that is called to draw the item.
moveProc
A procedure that is called to move the item.
selectedProc
A procedure that is called to determine if the item is selected.
hasProc
A procedure that is called to determine if the item has a given option.
