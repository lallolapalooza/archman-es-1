getOpenFile(3) Documentación de Contribución de Usuarios de Perl getOpenFile(3)

NOMBRE

Tk::getOpenFile - mostrar un cuadro de diálogo para que el usuario seleccione un archivo para abrir.

SINOPSIS

    $widget->getOpenFile(?-opcion=>valor, ...>?)

    $widget->getSaveFile(?-opcion=>valor, ...>?)

DESCRIPCIÓN

Los métodos getOpenFile y getSaveFile muestran un cuadro de diálogo para que el usuario seleccione un archivo para abrir o guardar.

El método getOpenFile suele estar asociado con el comando Abrir en el menú Archivo. Su propósito es que el usuario seleccione un archivo existente únicamente. Si el usuario introduce un archivo inexistente, el cuadro de diálogo muestra un mensaje de error y requiere que el usuario proporcione una selección alternativa. Si una aplicación permite al usuario crear archivos nuevos, debería hacerlo proporcionando un comando de menú Nuevo por separado.

El método getSaveFile suele estar asociado con el comando Guardar como en el menú Archivo. Si el usuario introduce un archivo que ya existe, el cuadro de diálogo solicita al usuario confirmación sobre si el archivo existente debe ser sobrescrito o no.

Si el usuario selecciona un archivo, tanto getOpenFile como getSaveFile devuelven la ruta completa de este archivo. Si el usuario cancela la operación, ambos comandos devuelven un valor indefinido.

Los siguientes pares opción-valor son posibles como argumentos de línea de comandos para estos dos comandos:

-defaultextension => extension
Especifica una cadena que se añadirá al nombre del archivo si el usuario introduce un nombre de archivo sin extensión. El valor por defecto es la cadena vacía, lo que significa que no se añadirá ninguna extensión al nombre del archivo en ningún caso. Esta opción se ignora en la plataforma Macintosh, que no requiere extensiones para los nombres de archivo, y la implementación de UNIX adivina valores razonables para esto a partir de la opción -filetypes cuando esta no se proporciona.
-filetypes => [patronArchivo ?, ...?]
Si existe una lista de tipos de archivo (listbox) en el diálogo de archivo en la plataforma particular, esta opción proporciona los tiposArchivo en esta lista. Cuando el usuario elige un tipo de archivo en la lista, solo se listan los archivos de ese tipo. Si esta opción no se especifica, o si se establece a la lista vacía, o si la lista de tipos de archivo no es compatible con la plataforma particular, entonces se listan todos los archivos independientemente de su tipo. Vea "ESPECIFICACIÓN DE PATRONES DE ARCHIVO" abajo para una discusión sobre el contenido de los patronArchivo.
-initialdir => directorio
Especifica que se muestren los archivos del directorio cuando aparezca el diálogo. Si este parámetro no se especifica, se muestran los archivos del directorio de trabajo actual. Esta opción puede no funcionar siempre en Macintosh. Esto no es un error. Más bien, el panel de control Controles Generales en Mac permite al usuario final anular el directorio por defecto de la aplicación.
-initialfile => nombreArchivo
Especifica un nombre de archivo que se mostrará en el diálogo cuando aparezca. Esta opción es ignorada por el método getOpenFile.
-multiple
Permite al usuario elegir múltiples archivos desde el diálogo Abrir. En Macintosh, esto solo está disponible cuando los Servicios de Navegación están instalados.
-message => cadena
Especifica un mensaje a incluir en el área del cliente del diálogo. Esto solo está disponible en Macintosh, y solo cuando los Servicios de Navegación están instalados.
-title => cadenaTitulo
Especifica una cadena a mostrar como título del cuadro de diálogo. Si esta opción no se especifica, se muestra un título por defecto. Esta opción es ignorada en la plataforma Macintosh.

ESPECIFICACIÓN DE PATRONES DE ARCHIVO

Los patronArchivo dados por la opción -filetypes son una lista de patrones de archivo. Cada patrón de archivo es una lista del formato

nombreTipo [extension ?extension ...?] ?[tipoMac ?tipoMac ...?]?

nombreTipo es el nombre del tipo de archivo descrito por este patrón de archivo y es la cadena de texto que aparece en la lista de tipos de archivo. extension es una extensión de archivo para este patrón de archivo. tipoMac es un tipo de archivo Macintosh de cuatro caracteres. La lista de tipoMac es opcional y puede omitirse para aplicaciones que no necesitan ejecutarse en la plataforma Macintosh.

Varios patrones de archivo pueden tener el mismo nombreTipo, en cuyo caso se refieren al mismo tipo de archivo y comparten la misma entrada en la lista. Cuando el usuario selecciona una entrada en la lista, se listan todos los archivos que coinciden al menos con uno de los patrones de archivo correspondientes a esa entrada. Por lo general, cada patrón de archivo corresponde a un tipo de archivo distinto. El uso de más de un patrón de archivo para un tipo de archivo es necesario solo en la plataforma Macintosh.

En la plataforma Macintosh, un archivo coincide con un patrón de archivo si su nombre coincide con al menos una de las extensiones Y pertenece a al menos uno de los tipoMac del patrón de archivo. Por ejemplo, el patrón de archivo Archivos de Código Fuente C en el código de ejemplo coincide con archivos que tienen una extensión de \.c Y pertenecen al tipoMac TEXT. Para usar la regla OR en su lugar, puede usar dos patrones de archivo, uno con las extensiones solamente y otro con el tipoMac solamente. El tipo de archivo Archivos GIF en el código de ejemplo coincide con archivos que O tienen una extensión de \.gif O pertenecen al tipoMac GIFF.

En las plataformas Unix y Windows, un archivo coincide con un patrón de archivo si su nombre coincide al menos con una de las extensiones del patrón de archivo. Los tipoMac son ignorados.

ESPECIFICACIÓN DE EXTENSIONES

En las plataformas Unix y Macintosh, las extensiones se comparan utilizando la coincidencia de patrones estilo glob. En las plataformas Windows, las extensiones son comparadas por el sistema operativo subyacente. Los tipos de extensiones posibles son: (1) la extensión especial * coincide con cualquier archivo; (2) la extensión especial "" coincide con cualquier archivo que no tenga una extensión (es decir, el nombre del archivo no contiene un punto); (3) cualquier cadena de caracteres que no contenga caracteres comodín (* y ?).

Debido a las diferentes reglas de coincidencia de patrones en las varias plataformas, para garantizar la portabilidad, no se permiten caracteres comodín en las extensiones, excepto como en la extensión especial *. Se permiten extensiones sin un punto (por ejemplo, ~) pero pueden no funcionar en todas las plataformas.

ADVERTENCIAS

Vea "ADVERTENCIAS" en Tk::chooseDirectory.

EJEMPLO

my $types = [
    ['Text Files',       ['.txt', '.text']],
    ['TCL Scripts',      '.tcl'           ],
    ['C Source Files',   '.c',      'TEXT'],
    ['GIF Files',        '.gif',          ],
    ['GIF Files',        '',        'GIFF'],
    ['All Files',        '*',             ],
];
my $filename = $widget->getOpenFile(-filetypes=>$types);
if ($filename ne "") {
    # Open the file ...
}
