NAME

Tk_AllocBitmapFromObj, Tk_GetBitmap, Tk_GetBitmapFromObj, Tk_DefineBitmap, Tk_NameOfBitmap, Tk_SizeOfBitmap, Tk_FreeBitmapFromObj, Tk_FreeBitmap - mantener la base de datos de pixmaps de solo plano

SYNOPSIS

#include <tk.h>

Pixmap
Tk_AllocBitmapFromObj(interp, tkwin, objPtr)

Pixmap
Tk_GetBitmap(interp, tkwin, info)

Pixmap
Tk_GetBitmapFromObj(tkwin, objPtr)

int
Tk_DefineBitmap(interp, name, source, width, height)

const char *
Tk_NameOfBitmap(display, bitmap)

Tk_SizeOfBitmap(display, bitmap, widthPtr, heightPtr)

Tk_FreeBitmapFromObj(tkwin, objPtr)

Tk_FreeBitmap(display, bitmap)

ARGUMENTS

Tcl_Interp *interp (in)
Interprete para el cual se reportará el error; si es NULL entonces no se dejará mensaje de error después de errores.
Tk_Window tkwin (in)
Token para la ventana en la cual se usará el bitmap.
Tcl_Obj *objPtr (in/out)
Valor de cadena que describe el bitmap deseado; la representación interna se modificará para cachear el puntero al Pixmap correspondiente.
const char *info (in)
Similar a objPtr, pero la descripción del bitmap se pasa como cadena y el Pixmap obtenido no se cacheará.
const char *name (in)
Nombre para el bitmap nuevo que se va a definir.
const void *source (in)
datos del bitmap, en formato estándar de bitmap. Debe almacenarse en memoria estática cuyo valor nunca cambia.
int width (in)
Ancho del bitmap.
int height (in)
Altura del bitmap.
int *widthPtr (out)
Pointer a la palabra que llenará con el ancho del bitmap.
int *heightPtr (out)
Pointer a la palabra que llenará con la altura del bitmap.
Display *display (in)
Display para el cual se asignó el bitmap.
Pixmap bitmap (in)
Identificador para un bitmap asignado por Tk_AllocBitmapFromObj o Tk_GetBitmap.

DESCRIPTION

Estas procedimientos gestionan una colección de bitmaps (pixmaps de solo plano) usadas por un aplicativo. Las procedimientos permiten reutilizar los bitmaps de manera eficiente, evitando el overhead del servidor, y también permiten nombrar los bitmaps con cadenas de caracteres.

Tk_AllocBitmapFromObj devuelve un identificador de Pixmap para un bitmap que coincide con la descripción en objPtr y es adecuado para uso en tkwin. Si es posible reutilizar un bitmap existente, crea uno nuevo de lo contrario. El valor de objPtr debe tener uno de los siguientes formas:

@fileName
fileName debe ser el nombre de un archivo que contiene una descripción de bitmap en el formato estándar de X11.
name
name debe ser el nombre de un bitmap definido previamente con una llamada a Tk_DefineBitmap. Las siguientes nombres son predefinidos por Tk:
error
Símbolo internacional "no" : un círculo con una línea diagonal en diagonal.
gray75
75% gris: un patrón de cuadrícula donde tres de los cuatro bits están encendidos.
gray50
50% gris: un patrón de cuadrícula donde cada otro bit está encendido.
gray25
25% gris: un patrón de cuadrícula donde uno de cada cuatro bits está encendido.
gray12
12.5% gris: un patrón donde una octava de los bits está encendida, consistente en cada cuarto de píxel en cada fila alternativa.
hourglass
Un símbolo de horquilla.
info
Una letra grande "i".
questhead
Un perfil de cabeza humano con un círculo en el centro.
question
Una pregunta grande.
warning
Un punto de exclamación grande.

Además, los siguientes nombres predefinidos están disponibles solo en el entorno de Macintosh:

document
Un documento genérico.
stationery
Un cuaderno de documento.
edition
El símbolo de edición.
application
Un icono genérico de aplicación.
accessory
Un accesorio de mesa.
folder
Un icono de carpeta genérico.
pfolder
Una carpeta cerrada.
trash
Una caja de reciclaje.
floppy
Un disco de flops.
ramdisk
Un disco de flops con chip.
cdrom
Un icono de disco de disco.
preferences
Una carpeta con el símbolo de prefs.
querydoc
Un icono de documento de base de datos.
stop
Un señal de parada.
note
Una cara con palabras en un balón.
caution
Un triángulo con un punto de exclamación.

Normalmente, Tk_AllocBitmapFromObj devuelve un identificador para el bitmap solicitado. Si ocurre un error al crear el bitmap, como cuando objPtr se refiere a un archivo no existente, se devuelve None y se deja un mensaje de error en el resultado de interp si interp no es NULL. Tk_AllocBitmapFromObj cachea información sobre el valor de retorno en objPtr, lo que acelera llamadas futuras a procedimientos como Tk_AllocBitmapFromObj y Tk_GetBitmapFromObj.

Tk_GetBitmap es idéntico a Tk_AllocBitmapFromObj excepto que la descripción del bitmap se pasa mediante una cadena en lugar de un objeto. Esto evita que Tk_GetBitmap cachee el valor de retorno, por lo que Tk_GetBitmap es menos eficiente que Tk_AllocBitmapFromObj.

Tk_GetBitmapFromObj devuelve el token de un bitmap existente, dado la ventana y la descripción utilizadas para crear el bitmap. Tk_GetBitmapFromObj no crea el bitmap de forma efectiva; el bitmap debe haber sido creado previamente con una llamada a Tk_AllocBitmapFromObj o Tk_GetBitmap. El valor de retorno se cachea en objPtr, acelerando llamadas futuras a Tk_GetBitmapFromObj con el mismo objPtr y tkwin

Tk_DefineBitmap asocia un nombre con los datos de bitmap en memoria, permitiendo que el nombre se use en llamadas posteriores a Tk_AllocBitmapFromObj o Tk_GetBitmap. El argumento nameId da un nombre al bitmap; debe ser diferente de uno usado anteriormente en una llamada a Tk_DefineBitmap. Los argumentos source, width y height describen el bitmap. Tk_DefineBitmap normalmente devuelve TCL_OK; si ocurre un error (por ejemplo, si ya existe un bitmap con el nombre nameId), devuelve TCL_ERROR y deja un mensaje de error en el resultado de interp. Nota: Tk_DefineBitmap espera que el contenido de source sea estático: Tk_DefineBitmap no hace una copia privada de este contenido, pero utiliza los bytes de source en llamadas a Tk_AllocBitmapFromObj o Tk_GetBitmap
