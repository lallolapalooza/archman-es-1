NOMBRE

Tk::after - Ejecutar un comando después de un retraso

SINOPSIS

  $widget->after(ms)

  $id = $widget->after(ms?,callback?)

  $id = $widget->repeat(ms?,callback?)

  $widget->afterCancel($id)

  $id = $widget->afterIdle(callback)

  $widget->afterInfo?($id)?

  $id->time(?delay?)

DESCRIPCIÓN

Este método se utiliza para retrasar la ejecución del programa o para ejecutar una devolución de llamada en segundo plano en algún momento futuro.

En perl/Tk, $widget->after se implementa a través de la clase "Tk::After", y las devoluciones de llamada se asocian con $widget, y se cancelan automáticamente cuando el widget se destruye. Una interfaz casi idéntica, pero sin cancelación automática y sin repetición, se proporciona a través del método Tk::after.

Detalles Internos

La clase interna Tk::After tiene la siguiente sinopsis:

$id = Tk::After->new($widget, tid, $time, 'once',   callback);
$id = Tk::After->new($widget, tid, $time, 'repeat', callback);
$id->cancel;
$id->time(?delay?);

$id es un objeto Tk::After, una matriz de 5 elementos:

$widget es la referencia del widget padre.

tid es el ID interno del temporizador, una cadena única.

$time es la cadena 'idle', que representa un temporizador de cola inactiva, o un valor entero en milisegundos.

once o repeat especifica si el temporizador es un evento after de una sola vez o un evento repeat repetido.

callback especifica un objeto Tk::Callback de Perl/Tk.

Cambiar el intervalo del temporizador de repeat

Es posible cambiar el valor de retraso de un temporizador de repeat, o incluso cancelar cualquier temporizador, utilizando el método time. Si se especifica delay y no es cero, se establece un nuevo retraso en el temporizador. Si delay es cero, el evento del temporizador se cancela como si se hubiera invocado $id->cancel. En todos los casos, se devuelve el retraso actual del temporizador en milisegundos.

Nota: el nuevo retraso del temporizador tendrá efecto en el evento del temporizador *siguiente*; este comando no cancelará el temporizador pendiente y lo volverá a emitir con el nuevo tiempo de retraso.

El método after() tiene varias formas como las siguientes:

$widget->after(ms)
El valor ms debe ser un entero que indique un tiempo en milisegundos. El comando duerme durante ms milisegundos y luego devuelve. Mientras el comando duerme, la aplicación no responde a los eventos.
$widget->after(ms,callback)
En esta forma, el comando devuelve inmediatamente, pero organiza que callback se ejecute ms milisegundos después como un manejador de eventos. El callback se ejecutará exactamente una vez, en el momento dado. El comando se ejecutará en el contexto de $widget. Si ocurre un error al ejecutar el comando retrasado, el mecanismo Tk::Error se utiliza para informar del error. El comando after devuelve un identificador (un objeto en el caso de perl/Tk) que se puede utilizar para cancelar el comando retrasado usando afterCancel.
$widget->repeat(ms,callback)
En esta forma, el comando devuelve inmediatamente, pero organiza que callback se ejecute ms milisegundos después como un manejador de eventos. Después de que callback se ejecute, se reprograma para ser ejecutado en otros ms, y así sucesivamente hasta que se cancele.
$widget->afterCancel($id)
$id->cancel
Cancela la ejecución de un comando retrasado que se programó previamente. $id indica qué comando debe cancelarse; debe haber sido el valor de retorno de una llamada anterior a after. Si el comando dado por $id ya se ha ejecutado (y no está programado para ejecutarse de nuevo), entonces afterCancel no tiene ningún efecto.
$widget->afterCancel(callback)
Esta forma no es robusta en perl/Tk - su uso está obsoleto. Este comando también debe cancelar la ejecución de un comando retrasado. El argumento callback se compara con los callbacks pendientes; si se encuentra una coincidencia, ese callback se cancela y nunca se ejecutará; si no hay ningún callback pendiente en este momento, entonces afterCancel no tiene ningún efecto.
$widget->afterIdle(callback)
Organiza que callback se evalúe más tarde como un callback inactivo. El script se ejecutará exactamente una vez, la próxima vez que se inicie el bucle de eventos y no haya eventos que procesar. El comando devuelve un identificador que se puede utilizar para cancelar el comando retrasado usando afterCancel. Si ocurre un error al ejecutar el script, el mecanismo Tk::Error se utiliza para informar del error.
$widget->afterInfo?($id)?
Este comando devuelve información sobre los manejadores de eventos existentes. Si no se proporciona ningún argumento $id, el comando devuelve una lista de los identificadores de todos los manejadores de eventos existentes creados por los comandos after y repeat para $widget. Si se proporciona $id, especifica un manejador existente; $id debe haber sido el valor de retorno de alguna llamada anterior a after o repeat y no debe haberse activado todavía ni haberse cancelado. En este caso, el comando devuelve una lista con tres elementos. El primer elemento de la lista es el callback asociado con $id, el segundo elemento es ya sea idle o el valor entero de milisegundos del temporizador para indicar qué tipo de manejador de eventos es, y el tercero es una cadena once o repeat para diferenciar un evento after de un evento repeat.

Las formas after(ms) y afterIdle del comando suponen que la aplicación está basada en eventos: los comandos retrasados no se ejecutarán a menos que la aplicación entre en el bucle de eventos. En aplicaciones que normalmente no se basan en eventos, se puede entrar en el bucle de eventos con los comandos vwait y update.
