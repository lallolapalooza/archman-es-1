Tk_AllocColorFromObj(3) Procedimientos de la biblioteca Tk Tk_AllocColorFromObj(3)

NOMBRE

Tk_AllocColorFromObj, Tk_GetColor, Tk_GetColorFromObj, Tk_GetColorByValue, Tk_NameOfColor, Tk_FreeColorFromObj, Tk_FreeColor - mantener la base de datos de colores

SINOPSIS

#include <tk.h>

XColor *
Tk_AllocColorFromObj(interp, tkwin, objPtr)

XColor *
Tk_GetColor(interp, tkwin, name)

XColor *
Tk_GetColorFromObj(tkwin, objPtr)

XColor *
Tk_GetColorByValue(tkwin, prefPtr)

const char *
Tk_NameOfColor(colorPtr)

GC
Tk_GCForColor(colorPtr, drawable)

Tk_FreeColorFromObj(tkwin, objPtr)

Tk_FreeColor(colorPtr)

ARGUMENTOS

Tcl_Interp *interp (entrada)
Intérprete a utilizar para la notificación de errores.
Tk_Window tkwin (entrada)
Token para la ventana en la que se utilizará el color.
Tcl_Obj *objPtr (entrada/salida)
El valor de la cadena describe el color deseado; la representación interna se modificará para almacenar en caché un puntero al (XColor *) correspondiente.
const char *name (entrada)
Igual que objPtr excepto que la descripción del color se pasa como una cadena y el (XColor *) resultante no se almacena en caché.
XColor *prefPtr (entrada)
Indica las intensidades de rojo, verde y azul del color deseado.
XColor *colorPtr (entrada)
Puntero a la información de color X. Debe haber sido asignado por una llamada anterior a Tk_AllocColorFromObj, Tk_GetColor o Tk_GetColorByValue, excepto cuando se pasa a Tk_NameOfColor.
Drawable drawable (entrada)
Dibujo en el que se utilizará el contexto gráfico resultante. Debe tener la misma pantalla y profundidad que la ventana para la que se asignó el color.

DESCRIPCIÓN

Estos procedimientos gestionan los colores que está utilizando una aplicación Tk. Permiten compartir colores siempre que sea posible, para preservar el espacio del mapa de colores, y eligen los colores disponibles más cercanos cuando el espacio del mapa de colores está agotado.

Dada una descripción textual de un color, Tk_AllocColorFromObj localiza un valor de píxel que puede usarse para renderizar el color en una ventana particular. El color deseado se especifica con un valor cuyo valor de cadena debe tener una de las siguientes formas:

nombrecolor
Cualquiera de los nombres textuales válidos para un color definido en el archivo de base de datos de colores del servidor, como red o PeachPuff.
#RGB
#RRGGBB
#RRRGGGBBB
#RRRRGGGGBBBB
Una especificación numérica de las intensidades de rojo, verde y azul que se utilizarán para mostrar el color. Cada R, G o B representa un solo dígito hexadecimal. Las cuatro formas permiten que los colores se especifiquen con valores de 4, 8, 12 o 16 bits. Cuando se proporcionan menos de 16 bits para cada color, representan los bits más significativos del color, mientras que los bits inferiores no completados se replicarán repetidamente a partir de los bits superiores disponibles. Por ejemplo, #3a7 es lo mismo que #3333aaaa7777.

Tk_AllocColorFromObj devuelve un puntero a una estructura XColor; la estructura indica las intensidades exactas del color asignado (que pueden diferir ligeramente de las solicitadas, dependiendo de las limitaciones de la pantalla) y un valor de píxel que puede usarse para dibujar con el color en tkwin. Si ocurre un error en Tk_AllocColorFromObj (como un nombre de color desconocido), se devuelve NULL y se almacena un mensaje de error en el resultado de interp si interp no es NULL. Si el mapa de colores de tkwin está lleno, Tk_AllocColorFromObj utilizará el color existente más cercano en el mapa de colores. Tk_AllocColorFromObj almacena información sobre el valor de retorno en objPtr, lo que acelera las llamadas futuras a procedimientos como Tk_AllocColorFromObj y Tk_GetColorFromObj.

Tk_GetColor es idéntico a Tk_AllocColorFromObj excepto que la descripción del color se especifica con una cadena en lugar de un valor. Esto evita que Tk_GetColor almacene en caché el valor de retorno, por lo que Tk_GetColor es menos eficiente que Tk_AllocColorFromObj.

Tk_GetColorFromObj devuelve el token de un color existente, dada la ventana y la descripción utilizadas para crear el color. Tk_GetColorFromObj en realidad no crea el color; el color ya debe haber sido creado con una llamada anterior a Tk_AllocColorFromObj o Tk_GetColor. El valor de retorno se almacena en caché en objPtr, lo que acelera las llamadas futuras a Tk_GetColorFromObj con el mismo objPtr y tkwin.

Tk_GetColorByValue es similar a Tk_GetColor excepto que el color deseado se indica con los campos red, green y blue de la estructura a la que apunta colorPtr.

Este paquete mantiene una base de datos de todos los colores que se están utilizando actualmente. Si el mismo color se solicita varias veces a Tk_GetColor o Tk_AllocColorFromObj (por ejemplo, por diferentes ventanas), o si las mismas intensidades se solicitan varias veces a Tk_GetColorByValue, se reutilizarán los valores de píxeles existentes. La reutilización de un píxel existente evita cualquier interacción con el servidor de ventanas, lo que hace que la asignación sea mucho más eficiente. Estos procedimientos también proporcionan una interfaz portátil que funciona en todas las plataformas. Por esta razón, generalmente debe usar Tk_AllocColorFromObj, Tk_GetColor o Tk_GetColorByValue en lugar de procedimientos de nivel inferior como XAllocColor.

Dado que diferentes llamadas a este paquete pueden devolver el mismo valor de píxel compartido, los llamadores nunca deben cambiar el color de un píxel devuelto por los procedimientos. Si necesita cambiar un valor de color dinámicamente, debe usar XAllocColorCells para asignar el valor de píxel para el color.

El procedimiento Tk_NameOfColor es aproximadamente lo inverso de Tk_GetColor. Si su argumento colorPtr fue creado por Tk_AllocColorFromObj o Tk_GetColor, entonces el valor de retorno es la cadena que se utilizó para crear el color. Si colorPtr fue creado por una llamada a Tk_GetColorByValue, o por cualquier otro mecanismo, entonces el valor de retorno es una cadena que podría pasarse a Tk_GetColor para devolver el mismo color. Nota: la cadena devuelta por Tk_NameOfColor solo se garantiza que persistirá hasta la próxima llamada a Tk_NameOfColor.

Tk_GCForColor devuelve un contexto gráfico cuyo campo foreground es el píxel asignado para colorPtr y cuyos otros campos tienen todos valores predeterminados. Esto proporciona una forma fácil de realizar un dibujo básico con un color. El contexto gráfico se almacena en caché con el color y solo existirá mientras exista colorPtr; se libera cuando se libera la última referencia a colorPtr llamando a Tk_FreeColor.

Cuando un color ya no es necesario, se debe llamar a Tk_FreeColorFromObj o Tk_FreeColor para liberarlo. Para Tk_FreeColorFromObj, el color a liberar se especifica con la misma información utilizada para crearlo; para Tk_FreeColor, el color a liberar se especifica con un puntero a su estructura XColor. Debe haber exactamente una llamada a Tk_FreeColorFromObj o Tk_FreeColor por cada llamada a Tk_AllocColorFromObj, Tk_GetColor o Tk_GetColorByValue.

Tk_AllocColorFromObj

Tk_AllocColorFromObj - Asigna un color de una cadena a un valor de color Tk.

SINOPSIS

                    #include <tk.h>

                    unsigned long Tk_AllocColorFromObj(interp, objPtr)
                        Tcl_Interp *interp;
                        Tcl_Obj *objPtr;

DESCRIPCIÓN

La función Tk_AllocColorFromObj convierte una cadena en objPtr a un valor de color Tk y lo asigna. La cadena debe estar en un formato que Tk pueda reconocer, como un nombre de color X (por ejemplo, "red", "blue") o una especificación RGB (por ejemplo, "#RRGGBB"). La función devuelve un valor de color Tk (un unsigned long) que se puede usar en otras funciones de Tk que esperan un valor de color. Si la cadena no se puede convertir a un color válido, se genera una condición de error y se devuelve NULL.

ARGUMENTOS

  • interp: El intérprete de Tcl.
  • objPtr: El puntero al objeto Tcl que contiene la cadena de color.

PALABRAS CLAVE

color, asignar, Tk
