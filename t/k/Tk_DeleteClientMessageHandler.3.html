Tk_CreateClientMessageHandler(3) Procedimientos de la biblioteca Tk Tk_CreateClientMessageHandler(3)

NOMBRE

Tk_CreateClientMessageHandler, Tk_DeleteClientMessageHandler - asociar una devolución de llamada de procedimiento con eventos X de tipo ClientMessage

SINOPSIS

#include <tk.h>

Tk_CreateClientMessageHandler(proc)

Tk_DeleteClientMessageHandler(proc)

ARGUMENTOS

Tk_ClientMessageProc *proc (entrada)
Procedimiento a invocar cada vez que ocurra un evento X ClientMessage en cualquier pantalla.

DESCRIPCIÓN

Tk_CreateClientMessageHandler organiza para que proc sea invocado en el futuro cada vez que ocurra un evento X ClientMessage que no sea manejado por WM_PROTOCOL. Tk_CreateClientMessageHandler está destinado a ser utilizado por aplicaciones que necesitan observar eventos X ClientMessage, como aplicaciones de arrastrar y soltar.

La devolución de llamada a proc será realizada por Tk_HandleEvent; este mecanismo solo funciona en programas que despachan eventos a través de Tk_HandleEvent (o a través de otros procedimientos de Tk que llaman a Tk_HandleEvent, como Tcl_DoOneEvent o Tk_MainLoop).

Proc debe tener argumentos y resultado que coincidan con el tipo Tk_ClientMessageProc:

typedef int Tk_ClientMessageProc(
        Tk_Window tkwin,
        XEvent *eventPtr);
El parámetro tkwin de proc es la ventana Tk que está asociada con este evento. EventPtr es un puntero al evento X.

Cada vez que Tk_HandleEvent procesa un evento X ClientMessage, se llama a proc si no fue manejado como un WM_PROTOCOL. El valor de retorno de proc es normalmente 0. Un valor de retorno distinto de cero indica que el evento no debe ser manejado más; es decir, proc ha realizado todo el procesamiento que se permite para el evento.

Si hay varios manejadores de eventos ClientMessage, cada uno es llamado para cada evento, en el orden en que fueron establecidos.

Tk_DeleteClientMessageHandler puede ser llamado para eliminar un manejador de eventos ClientMessage creado previamente: elimina cada manejador que encuentra que coincide con el argumento proc. Si no existe tal manejador, entonces Tk_DeleteClientMessageHandler retorna sin hacer nada. Aunque Tk lo soporta, probablemente sea una mala idea tener más de una devolución de llamada con el mismo argumento proc.
