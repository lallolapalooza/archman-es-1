ARGUMENTOS

Tcl_Interp *interp (entrada)
Un intérprete Tcl. La mayoría de los procedimientos usan esto solo para devolver mensajes de error; si es NULL, no se devuelven mensajes de error. Para Tk_CreateOptionTable el valor no puede ser NULL; proporciona el intérprete en el que se utilizará la tabla de opciones.
const Tk_OptionSpec *templatePtr (entrada)
Punta a una matriz de información estática que describe las opciones de configuración que se admiten. Se utiliza para construir una Tk_OptionTable. La información apuntada por este argumento debe existir durante la vida útil de la Tk_OptionTable.
Tk_OptionTable optionTable (entrada)
Token para una tabla de opciones. Debe haber sido devuelto por una llamada previa a Tk_CreateOptionTable.
char *recordPtr (entrada/salida)
Punta a una estructura en la que se almacenan los valores de las opciones de configuración; los campos de este registro son modificados por procedimientos como Tk_SetOptions y leídos por procedimientos como Tk_GetOptionValue.
Tk_Window tkwin (entrada)
Para opciones como TK_OPTION_COLOR, este argumento indica la ventana en la que se utilizará la opción. Si optionTable no utiliza opciones dependientes de la ventana, se puede proporcionar un valor NULL para este argumento.
int objc (entrada)
Número de valores en objv.
Tcl_Obj *const *objv (entrada)
Argumentos de línea de comandos para establecer opciones de configuración.
Tk_SavedOptions *savePtr (salida)
Si no es NULL, la estructura apuntada por este argumento se rellena con los valores antiguos de las opciones modificadas y los valores antiguos se restauran automáticamente si ocurre un error en Tk_SetOptions.
int *maskPtr (salida)
Si no es NULL, la palabra apuntada por maskPtr se rellena con el OR a nivel de bits de los campos typeMask de las opciones que se modificaron.
Tk_SavedOptions *savedPtr (entrada/salida)
Punta a una estructura previamente rellenada por Tk_SetOptions con los valores antiguos de las opciones modificadas.
Tcl_Obj *namePtr (entrada)
El valor de este objeto es el nombre de una opción particular. Si se pasa NULL a Tk_GetOptionInfo, se devuelve información para todas las opciones. No debe ser NULL cuando se llama a Tk_GetOptionValue.
tipo nombre type (entrada)
El nombre del tipo de un registro.
nombre de campo field (entrada)
El nombre de un campo en registros del tipo type.

DESCRIPCIÓN

Estos procedimientos manejan la mayoría de los detalles de análisis de opciones de configuración, como las de los widgets de Tk. Dada una descripción de las opciones admitidas, estos procedimientos manejan todos los detalles de análisis de opciones y almacenamiento de sus valores en una estructura C asociada al widget u objeto. Los procedimientos fueron diseñados principalmente para widgets en Tk, pero también pueden usarse para otros tipos de objetos que tienen opciones de configuración. En el resto de esta página de manual, se utilizará la palabra “widget” para referirse al objeto cuyas opciones se están gestionando; en la práctica, el objeto puede no ser en realidad un widget. El término “registro de widget” se usa para referirse a la estructura de nivel C en la que se almacena la información sobre un widget u objeto particular.

Tenga en cuenta que la forma más sencilla de aprender a usar estos procedimientos es observar un ejemplo funcional. En Tk, el ejemplo más simple es el código que implementa la familia de widgets de botones, que se encuentra en tkButton.c. Otros ejemplos se encuentran en tkSquare.c y tkMenu.c.

Para usar estos procedimientos, el código que implementa el widget debe contener una matriz estática de estructuras Tk_OptionSpec. Esta es una plantilla que describe las diversas opciones admitidas por esa clase de widget; hay una plantilla separada para cada tipo de widget. La plantilla contiene información como el nombre de cada opción, su tipo, su valor predeterminado y dónde se almacena el valor de la opción en el registro del widget. Consulte PLANTILLAS a continuación para obtener más detalles.

Para procesar las opciones de configuración de manera eficiente, la plantilla estática debe complementarse con información adicional que solo está disponible en tiempo de ejecución. El procedimiento Tk_CreateOptionTable crea esta información dinámica a partir de la plantilla y devuelve un token Tk_OptionTable que describe tanto la información estática como la dinámica. Todos los demás procedimientos, como Tk_SetOptions, toman un token Tk_OptionTable como argumento. Típicamente, Tk_CreateOptionTable se llama la primera vez que se crea un widget de una clase particular y la Tk_OptionTable resultante se utiliza en el futuro para todos los widgets de esa clase. Una Tk_OptionTable solo puede usarse en un intérprete, dado por el argumento interp a Tk_CreateOptionTable. Cuando una tabla de opciones ya no es necesaria, se debe llamar a Tk_DeleteOptionTable para liberar todos sus recursos. Todas las tablas de opciones para un intérprete Tcl se liberan automáticamente si se elimina el intérprete.

Tk_InitOptions se invoca cuando se crea un nuevo widget para establecer los valores predeterminados. Tk_InitOptions recibe un token para una tabla de opciones (optionTable) y un puntero a un registro de widget (recordPtr), que es la estructura C que contiene información sobre este widget. Tk_InitOptions utiliza la información de la tabla de opciones para elegir un valor predeterminado apropiado para cada opción, luego almacena el valor predeterminado directamente en el registro del widget, sobrescribiendo cualquier información que ya estuviera presente en el registro del widget. Tk_InitOptions normalmente devuelve TCL_OK. Si ocurrió un error al establecer los valores predeterminados (por ejemplo, porque un valor predeterminado era erróneo), entonces devuelve TCL_ERROR y se deja un mensaje de error en el resultado de interp si interp no es NULL. Para cualquier opción de configuración de un widget que tenga TK_OPTION_DONT_SET_DEFAULT establecido en su campo flags, la inicialización anterior se omite por completo, véase más abajo.

Tk_SetOptions se invoca para modificar las opciones de configuración basándose en la información especificada en un comando Tcl. El comando podría ser uno que crea un nuevo widget o un comando que modifica opciones en un widget existente. Los argumentos objc y objv describen los valores de los argumentos del comando Tcl. Objv debe contener un número par de objetos: el primer objeto de cada par da el nombre de una opción y el segundo objeto da el nuevo valor para esa opción. Tk_SetOptions busca cada nombre en optionTable, verifica que el nuevo valor de la opción se ajuste al tipo en optionTable y almacena el valor de la opción en el registro del widget dado por recordPtr. Tk_SetOptions normalmente devuelve TCL_OK. Si ocurrió un error (como un nombre de opción desconocido o un valor de opción ilegal), entonces devuelve TCL_ERROR y se deja un mensaje de error en el resultado de interp si interp no es NULL.

Tk_SetOptions tiene dos características adicionales. Primero, si el argumento maskPtr no es NULL, entonces apunta a un valor entero que se rellena con información sobre las opciones que se modificaron. Por cada opción en la plantilla pasada a Tk_CreateOptionTable hay un campo typeMask. Los bits de este campo son definidos por el código que implementa el widget; por ejemplo, cada bit podría corresponder a una configuración de opción particular. Alternativamente, los bits podrían usarse funcionalmente. Por ejemplo, un bit podría usarse para redibujar: todas las opciones que afectan la visualización del widget, de modo que cambiar la opción requiera que el widget se redibuje, podrían tener ese bit establecido. Otro bit podría indicar que la geometría del widget debe ser recalculada, y así sucesivamente. Tk_SetOptions combina los campos typeMask de todas las

e opciones que se modificaron y devuelve este valor en *maskPtr; el llamador puede usar esta información para optimizarse y, por ejemplo, no volver a mostrar el widget si las opciones modificadas no afectan su apariencia.

La segunda característica adicional de Tk_SetOptions tiene que ver con la recuperación de errores. Si ocurre un error mientras se procesan las opciones de configuración, esta característica permite restaurar todas las opciones de configuración a sus valores anteriores. Los errores pueden ocurrir al procesar opciones en Tk_SetOptions o más tarde en el llamador. En muchos casos, el llamador realiza procesamiento adicional después de que Tk_SetOptions regresa; por ejemplo, puede usar el valor de una opción para establecer un rastreador en una variable y puede detectar un error si la variable es una matriz en lugar de un escalar. La recuperación de errores se habilita pasando un valor no NULL para el argumento savePtr a Tk_SetOptions; este debe ser un puntero a una estructura Tk_SavedOptions no inicializada en la pila del llamador. Tk_SetOptions sobrescribe la estructura apuntada por savePtr con información sobre los valores antiguos de cualquier opción modificada por el procedimiento. Si Tk_SetOptions regresa con éxito, el llamador usa la estructura de una de dos maneras. Si el llamador completa su procesamiento de las nuevas opciones sin errores, debe pasar la estructura a Tk_FreeSavedOptions para que los valores antiguos puedan liberarse. Si el llamador detecta un error en su procesamiento de las nuevas opciones, entonces debe pasar la estructura a Tk_RestoreSavedOptions, que copiará los valores antiguos de vuelta al registro del widget y liberará los nuevos valores. Si Tk_SetOptions detecta un error, automáticamente restaura cualquier opción que ya se haya modificado y deja *savePtr en un estado vacío: el llamador no necesita llamar ni a Tk_FreeSavedOptions ni a Tk_RestoreSavedOptions. Si el argumento savePtr a Tk_SetOptions es NULL, entonces Tk_SetOptions libera cada valor de opción antiguo inmediatamente cuando establece un nuevo valor para la opción. En este caso, si ocurre un error en la tercera opción, los valores antiguos de las dos primeras opciones no se pueden restaurar.

Tk_GetOptionValue devuelve el valor actual de una opción de configuración para un widget particular. El argumento namePtr contiene el nombre de una opción; Tk_GetOptionValue usa optionTable para buscar la opción y extraer su valor del registro del widget apuntado por recordPtr, luego devuelve un objeto que contiene ese valor. Si ocurre un error (por ejemplo, porque namePtr contiene un nombre de opción desconocido), entonces se devuelve NULL y se deja un mensaje de error en el resultado de interp a menos que interp sea NULL.

Tk_GetOptionInfo devuelve información sobre las opciones de configuración en un formato adecuado para los comandos de widget configure. Si el argumento namePtr no es NULL, apunta a un objeto que da el nombre de una opción de configuración; Tk_GetOptionInfo devuelve un objeto que contiene una lista con cinco elementos, que son el nombre de la opción, el nombre y la clase utilizados para la opción en la base de datos de opciones, el valor predeterminado para la opción y el valor actual para la opción. Si el argumento namePtr es NULL, entonces Tk_GetOptionInfo devuelve información sobre todas las opciones en forma de una lista de listas; cada sublista describe una opción. Las opciones sinónimas se manejan de manera diferente según si namePtr es NULL: si namePtr es NULL, entonces la sublista para cada opción sinónima tiene solo dos elementos, que son el nombre de la opción y el nombre de la otra opción a la que se refiere; si namePtr no es NULL y nombra una opción sinónima, entonces el objeto devuelto es la lista de cinco elementos para la otra opción a la que se refiere el sinónimo. Si ocurre un error (por ejemplo, porque namePtr contiene un nombre de opción desconocido), entonces se devuelve NULL y se deja un mensaje de error en el resultado de interp a menos que interp sea NULL.

Tk_FreeConfigOptions debe invocarse cuando se elimina un widget. Libera todos los recursos asociados con cualquiera de las opciones de configuración definidas en recordPtr por optionTable.

La macro Tk_Offset se proporciona como una forma segura de generar los valores objOffset e internalOffset para las entradas en las estructuras Tk_OptionSpec. Toma dos argumentos: el nombre de un tipo de registro y el nombre de un campo en ese registro. Devuelve el desplazamiento en bytes del campo con nombre en los registros del tipo dado.

PLANTILLAS

La matriz de estructuras Tk_OptionSpec pasada a Tk_CreateOptionTable a través de su argumento templatePtr describe las opciones de configuración admitidas por una clase particular de widgets. Cada estructura especifica una opción de configuración y tiene los siguientes campos:

typedef struct {
    Tk_OptionType type;
    const char *optionName;
    const char *dbName;
    const char *dbClass;
    const char *defValue;
    int objOffset;
    int internalOffset;
    int flags;
    const void *clientData;
    int typeMask;
} Tk_OptionSpec;
El campo type indica qué tipo de opción de configuración es esta (por ejemplo, TK_OPTION_COLOR para un valor de color, o TK_OPTION_INT para un valor entero). Type determina cómo se analiza el valor de la opción (más sobre esto a continuación). El campo optionName es una cadena como -font o -bg; es el nombre utilizado para la opción en los comandos Tcl y se pasa a los procedimientos a través de los argumentos objc o namePtr. Los campos dbName y dbClass son utilizados por Tk_InitOptions para buscar un valor predeterminado para esta opción en la base de datos de opciones; si dbName es NULL, entonces Tk_InitOptions no utiliza la base de datos de opciones para esta opción. El campo defValue especifica un valor predeterminado para esta opción de configuración si no se especifica ningún valor en la base de datos de opciones. Los campos objOffset e internalOffset indican dónde almacenar el valor de esta opción en los registros del widget (más sobre esto a continuación); los valores para los campos objOffset e internalOffset siempre deben generarse con la macro Tk_Offset. El campo flags contiene información adicional para controlar el procesamiento de esta opción de configuración (ver más abajo para detalles). ClientData proporciona datos adicionales específicos del tipo necesarios para ciertos tipos. Por ejemplo, para los tipos TK_OPTION_COLOR, clientData es una cadena que indica el valor predeterminado a usar en pantallas monocromáticas. Consulte las descripciones de los diferentes tipos a continuación para obtener detalles. El último campo, typeMask, es utilizado por Tk_SetOptions para devolver información sobre qué opciones se modificaron; consulte la descripción de Tk_SetOptions arriba para obtener detalles.

Cuando Tk_InitOptions y Tk_SetOptions almacenan el valor de una opción en el registro del widget, pueden hacerlo de una de las dos maneras. Si el campo objOffset de Tk_OptionSpec es mayor o igual a cero, entonces el valor de la opción se almacena como un (Tcl_Obj *) en la ubicación del registro del widget dada por objOffset. Si el campo internalOffset de Tk_OptionSpec es mayor o igual a cero, entonces el valor de la opción se almacena en una forma interna específica del tipo en la ubicación del registro del widget dada por internalOffset. Por ejemplo, si el tipo de la opción es TK_OPTION_INT, entonces la forma interna es un entero. Si el campo objOffset o internalOffset es negativo, entonces el valor no se almacena de esa forma. Al menos uno de los desplazamientos debe ser mayor o igual a cero.

El campo flags consta de uno o más bits ORados juntos. Las siguientes banderas son compatibles:

TK_OPTION_NULL_OK
Si este bit está establecido para una opción, se aceptará una cadena vacía como valor para la opción y la forma interna resultante será un puntero NULL, un valor cero o None, dependiendo del tipo de la opción. Si la bandera no está establecida, las cadenas vacías generarán errores. TK_OPTION_NULL_OK se utiliza típicamente para permitir que una característica se desactive por completo, por ejemplo, establecer el valor de un cursor en None para que una ventana simplemente herede el cursor de su padre. No todos los tipos de opciones admiten la bandera TK_OPTION_NULL_OK; para aquellos que lo hacen, hay una indicación explícita de ello en las descripciones a continuación.
TK_OPTION_DONT_SET_DEFAULT
Si este bit está establecido para una opción, no se establecerá ningún valor predeterminado en Tk_InitOptions para esta opción. Ni la base de datos de opciones, ni ningún valor predeterminado del sistema, ni optionTable se utilizan para proporcionar un valor predeterminado a esta opción. En cambio, se asume que el llamador ya ha proporcionado un valor predeterminado en el código del widget.

El campo type de cada estructura Tk_OptionSpec determina cómo analizar el valor de esa opción de configuración. El valor legal para type, y las acciones correspondientes, se describen a continuación. Si el tipo requiere que se pase un valor tkwin a procedimientos como Tk_SetOptions, o si utiliza el campo clientData de Tk_OptionSpec, entonces se indica explícitamente; si no se menciona, el tipo no requiere ni tkwin ni clientData.

TK_OPTION_ANCHOR
El valor debe ser una posición de anclaje estándar como ne o center. La forma interna es un valor Tk_Anchor como los devueltos por Tk_GetAnchorFromObj.
TK_OPTION_BITMAP
El valor debe ser un nombre de bitmap estándar de Tk. La forma interna es un token Pixmap como los devueltos por Tk_AllocBitmapFromObj. Este tipo de opción requiere que se proporcione tkwin a procedimientos como Tk_SetOptions, y admite la bandera TK_OPTION_NULL_OK.
TK_OPTION_BOOLEAN
El valor debe ser un valor booleano estándar como true o no. La forma interna es un entero con valor 0 o 1. Tenga en cuenta que si el campo objOffset no se utiliza, se perderá la información sobre el valor original de esta opción.
TK_OPTION_BORDER
El valor debe ser un nombre de color estándar como red o #ff8080. La forma interna es un token Tk_3DBorder como los devueltos por Tk_Alloc3DBorderFromObj. Este tipo de opción requiere que se proporcione tkwin a procedimientos como Tk_SetOptions, y admite la bandera TK_OPTION_NULL_OK.
TK_OPTION_COLOR
El valor debe ser un color estándar

Este tipo de opción requiere que se proporcione tkwin a procedimientos como Tk_SetOptions (para identificar la aplicación), y admite el indicador TK_OPTION_NULL_OK. .Sh STORAGE MANAGEMENT ISSUES Si un campo de un registro de widget tiene su desplazamiento almacenado en el campo objOffset o internalOffset de una estructura Tk_OptionSpec, los procedimientos descritos aquí se encargarán de todas las cuestiones de asignación de almacenamiento y gestión de recursos asociadas con el campo. Cuando se cambia el valor de una opción, Tk_SetOptions (o Tk_FreeSavedOptions) liberará automáticamente cualquier recurso asociado con el valor anterior, como Tk_Fonts para opciones TK_OPTION_FONT o memoria asignada dinámicamente para opciones TK_OPTION_STRING. Para una opción almacenada como un objeto utilizando el campo objOffset de una estructura Tk_OptionSpec, el registro del widget comparte el objeto al que apunta el valor objv de la llamada a Tk_SetOptions. El recuento de referencias para este objeto se incrementa cuando se almacena un puntero a él en el registro del widget y se decrementa cuando se modifica la opción. Cuando se elimina el widget, se debe invocar Tk_FreeConfigOptions; liberará los recursos asociados con todas las opciones y decrementará los recuentos de referencias para cualquier objeto. Sin embargo, el código del widget es responsable de almacenar NULL o None en todos los campos de puntero y token antes de invocar Tk_InitOptions. Esto es necesario para permitir una limpieza adecuada en el raro caso de que ocurra un error en Tk_InitOptions. .Sh OBJOFFSET VS. INTERNALOFFSET En la mayoría de los casos, es más sencillo utilizar el campo internalOffset de una estructura Tk_OptionSpec y no el campo objOffset. Esto hace que la forma interna del valor esté inmediatamente disponible para el código del widget, por lo que el valor no tiene que extraerse de un objeto cada vez que se utiliza. Sin embargo, hay dos casos en los que el campo objOffset es útil. El primer caso es para las opciones TK_OPTION_PIXELS. En este caso, la forma interna es un valor entero de píxeles que solo es válido para una pantalla en particular. Si se recupera el valor de la opción, se devolverá como un número simple. Por ejemplo, después del comando .b configure -borderwidth 2m, el comando .b configure -borderwidth podría devolver 7, que es el valor entero de píxeles correspondiente a 2m. Desafortunadamente, esto pierde el valor original independiente de la pantalla. Por lo tanto, para las opciones TK_OPTION_PIXELS es mejor utilizar el campo objOffset. En este caso, el valor original de la opción se conserva en el objeto y se puede devolver cuando se recupera la opción. En la mayoría de los casos, es conveniente utilizar también el campo internalOffset, de modo que el valor entero esté inmediatamente disponible para su uso en el código del widget (alternativamente, se puede usar Tk_GetPixelsFromObj para extraer el valor entero del objeto cada vez que sea necesario). Tenga en cuenta que el problema de perder información en las recuperaciones solo existe para las opciones TK_OPTION_PIXELS. La segunda razón para usar el campo objOffset es para implementar nuevos tipos de opciones no admitidos por estos procedimientos. Para implementar un nuevo tipo de opción, puede usar TK_OPTION_STRING como tipo en la estructura Tk_OptionSpec y establecer el campo objOffset pero no el campo internalOffset. Luego, después de llamar a Tk_SetOptions, convierta el objeto a la forma interna usted mismo. Los widgets Ttk no admiten la maquinaria internalOffset. DESCRIPTION

The Tk option database primitives provide a mechanism for managing widget configuration options. They allow you to define a set of options for a widget, specify how those options are converted to internal representations, and retrieve and manipulate those options.

Tk_OptionSpec

The Tk_OptionSpec structure describes a single widget option. It contains the following fields:

optionName
The name of the option (e.g., "-text", "-foreground"). This must be a null-terminated string.
objOffset
If non-negative, this is the offset in bytes from the start of the widget record to the location where the option’s value will be stored as a Tcl_Obj *. If negative, the option’s value is stored internally using a custom type defined by setProc, getProc, restoreProc, and freeProc.
customPtr
If objOffset is negative, this field points to a Tk_ObjCustomOption structure that defines the custom type. Otherwise, this field is unused.
defValuePtr
A pointer to the default value for the option, represented as a Tcl_Obj *. If this is NULL, the option has no default value and must be provided by the user or the option database.
flags
A bitmask of flags that control how the option is handled. See the flags argument description above for a list of possible flags.

Tk_OptionTable

A Tk_OptionTable is a collection of Tk_OptionSpec structures. It is used to group related options together. Option tables can be merged using Tk_MergeOptionTables.

Tk_SavedOptions

A Tk_SavedOptions structure is used to store the original values of options before they are changed. This allows the changes to be undone later using Tk_RestoreSavedOptions.

Custom Option Types

For options that do not have a simple internal representation (e.g., complex data structures, resources that need special handling), you can define a custom type using the Tk_ObjCustomOption structure. This structure contains pointers to four procedures that handle the conversion between Tcl objects and the internal representation:

setProc
This procedure is called by Tk_SetOptions to convert a Tcl object into the internal representation and store it in the widget record. It receives the following arguments:
clientData
A copy of the clientData field from the Tk_ObjCustomOption structure.
interp
A pointer to the Tcl interpreter.
Tkwin
The Tk window associated with the option.
valuePtr
A pointer to a Tcl_Obj * representing the new value of the option.
recordPtr
A pointer to the widget record.
internalOffset
The offset within the widget record where the internal representation should be stored.
saveInternalPtr
A pointer to storage where the original value of the option should be saved before it is modified. This is used to support Tk_RestoreSavedOptions.
flags
The flags associated with the option from the Tk_OptionSpec structure.

The setProc should return TCL_OK on success and TCL_ERROR on failure, leaving an error message in the interpreter if necessary. It may modify *valuePtr and should store the converted value at the offset specified by internalOffset.

getProc
This procedure is called by Tk_GetOptionValue and Tk_GetOptionInfo to convert the internal representation of an option back into a Tcl object. It receives the following arguments:
clientData
A copy of the clientData field from the Tk_ObjCustomOption structure.
Tkwin
The Tk window associated with the option.
recordPtr
A pointer to the widget record.
internalOffset
The offset within the widget record where the internal representation is stored.

The getProc must return a pointer to a Tcl_Obj * representing the value of the option. It may return a new object or an existing one. The caller is responsible for managing the reference count of the returned object.

restoreProc
This procedure is called by Tk_RestoreSavedOptions to restore a previously saved internal representation of a custom option value. It receives the following arguments:
clientData
A copy of the clientData field from the Tk_ObjCustomOption structure.
Tkwin
The Tk window associated with the option.
internalPtr
A pointer to the location where the internal representation of the option value is stored.
saveInternalPtr
A pointer to the saved value.

The restoreProc must copy the value from saveInternalPtr to internalPtr. It does not need to free any memory.

freeProc
This procedure is called by Tk_SetOptions and Tk_FreeSavedOptions to free any storage allocated for the internal representation of a custom option. It receives the following arguments:
clientData
A copy of the clientData field from the Tk_ObjCustomOption structure.
Tkwin
The Tk window associated with the option.
internalPtr
A pointer to the location where the internal representation of the option value is stored.

The freeProc must free any storage associated with the option. It has no return value.

If restoreProc or freeProc are NULL, then no function will be called for those operations.

The setProc procedure is invoked by Tk_SetOptions to convert a Tcl_Obj into an internal representation and store the resulting value in the widget record. The arguments are:

clientData
A copy of the clientData field in the Tk_ObjCustomOption structure.
interp
A pointer to a Tcl interpreter, used for error reporting.
Tkwin
A copy of the tkwin argument to Tk_SetOptions
valuePtr
A pointer to a reference to a Tcl_Obj describing the new value for the option; it could have been specified explicitly in the call to Tk_SetOptions or it could come from the option database or a default. If the objOffset for the option is non-negative (the option value is stored as a (Tcl_Obj *) in the widget record), the Tcl_Obj pointer referenced by valuePtr is the pointer that will be stored at the objOffset for the option. SetProc may modify the value if necessary; for example, setProc may change the value to NULL to support the TK_OPTION_NULL_OK flag.
recordPtr
A pointer to the start of the widget record to modify.
internalOffset
Offset in bytes from the start of the widget record to the location where the internal representation of the option value is to be placed.
saveInternalPtr
A pointer to storage allocated in a Tk_SavedOptions structure for the internal representation of the original option value. Before setting the option to its new value, setProc should set the value referenced by saveInternalPtr to the original value of the option in order to support Tk_RestoreSavedOptions.
flags
A copy of the flags field in the Tk_OptionSpec structure for the option

SetProc returns a standard Tcl result: TCL_OK to indicate successful processing, or TCL_ERROR to indicate a failure of any kind. An error message may be left in the Tcl interpreter given by interp in the case of an error.

The getProc procedure is invoked by Tk_GetOptionValue and Tk_GetOptionInfo to retrieve a Tcl_Obj representation of the internal representation of an option. The clientData argument is a copy of the clientData field in the Tk_ObjCustomOption structure. Tkwin is a copy of the tkwin argument to Tk_GetOptionValue or Tk_GetOptionInfo. RecordPtr is a pointer to the beginning of the widget record to query. InternalOffset is the offset in bytes from the beginning of the widget record to the location where the internal representation of the option value is stored. GetProc must return a pointer to a Tcl_Obj representing the value of the option.

The restoreProc procedure is invoked by Tk_RestoreSavedOptions to restore a previously saved internal representation of a custom option value. The clientData argument is a copy of the clientData field in the Tk_ObjCustomOption structure. Tkwin is a copy of the tkwin argument to Tk_GetOptionValue or Tk_GetOptionInfo. InternalPtr is a pointer to the location where internal representation of the option value is stored. SaveInternalPtr is a pointer to the saved value. RestoreProc must copy the value from saveInternalPtr to internalPtr to restore the value. RestoreProc need not free any memory associated with either internalPtr or saveInternalPtr; freeProc will be invoked to free that memory if necessary. RestoreProc has no return value.

The freeProc procedure is invoked by Tk_SetOptions and Tk_FreeSavedOptions to free any storage allocated for the internal representation of a custom option. The clientData argument is a copy of the clientData field in the Tk_ObjCustomOption structure. Tkwin is a copy of the tkwin argument to Tk_GetOptionValue or Tk_GetOptionInfo. InternalPtr is a pointer to the location where the internal representation of the option value is stored. The freeProc must free any storage associated with the option. FreeProc has no return value.

TEMPLATES

Tk provides several built-in option types that can be used in the Tk_OptionSpec structure. These include:

  • Tk_AnchorOptionTransient: For anchor options (e.g., "nw", "center").
  • Tk_BitmapOptionTransient: For bitmap options.
  • Tk_BooleanOptionTransient: For boolean options (e.g., "on", "off", "true", "false").
  • Tk_BorderOptionTransient: For border width options.
  • Tk_ColorOptionTransient: For color options.
  • Tk_CursorOptionTransient: For cursor options.
  • Tk_DoubleOptionTransient: For double-precision floating-point options.
  • Tk_FontOptionTransient: For font options.
  • Tk_IntOptionTransient: For integer options.
  • Tk_JustifyOptionTransient: For justification options (e.g., "left", "center", "right").
  • Tk_PixelsOptionTransient: For pixel-based screen distance options.
  • Tk_ReliefOptionTransient: For relief options (e.g., "flat", "raised", "sunken").
  • Tk_ScreenDistOptionTransient: For screen distance options (e.g., "10p", "2c").
  • Tk_StringOptionTransient: For string options.

These transient options are pointers to structures that contain the necessary information for the custom option handlers. You can use them directly in the customPtr field of a Tk_OptionSpec.

STORAGE MANAGEMENT ISSUES

When using custom option types, it is crucial to manage memory correctly. The setProc is responsible for allocating memory for the internal representation if necessary. The freeProc is responsible for freeing this memory when the option is no longer needed or when the widget is destroyed. The restoreProc should not free memory; it only copies values.

If an option's value is stored as a Tcl_Obj * (i.e., objOffset is non-negative), Tk handles the memory management of the Tcl object itself. However, if the internal representation pointed to by the Tcl object requires separate memory management, the setProc, getProc, and freeProc should handle it accordingly.

OBJOFFSET VS. INTERNALOFFSET

The objOffset field in Tk_OptionSpec specifies the offset where the option's value is stored as a Tcl_Obj * within the widget record. If this value is negative, it indicates that a custom type is being used, and the offset provided to the setProc, getProc, restoreProc, and freeProc (also named internalOffset in those procedures) refers to the location of the custom internal representation within the widget record.

CUSTOM OPTION TYPES

When defining custom option types, ensure that the setProc correctly handles the conversion from the Tcl object to the internal representation, and that the getProc correctly converts the internal representation back to a Tcl object. The restoreProc and freeProc are essential for proper memory management when dealing with custom types that allocate their own storage.

The clientData field in Tk_ObjCustomOption can be used to pass additional information to the custom procedures, such as pointers to type-specific data or configuration options.
