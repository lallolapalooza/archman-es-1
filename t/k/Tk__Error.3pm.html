NOMBRE

Tk::Error - Método invocado para procesar errores en segundo plano

SINOPSIS

Personalización:

require Tk::ErrorDialog;

o

sub Tk::Error
{
  my ($widget,$error,@locations) = @_;
  ...
}

DESCRIPCIÓN

El método Tk::Error es invocado por perl/Tk cuando ocurre un error en segundo plano. Se proporcionan dos implementaciones posibles en la distribución y las aplicaciones o usuarios individuales pueden (re)definir un método Tk::Error (por ejemplo, como una subrutina de perl) si desean manejar los errores en segundo plano de alguna otra manera.

Un error en segundo plano es aquel que ocurre en un comando que no se originó con la aplicación. Por ejemplo, si ocurre un error al ejecutar una función de devolución de llamada especificada con un comando bind o after, entonces es un error en segundo plano. Para un error que no sea en segundo plano, el error simplemente se puede devolver a través de subrutinas anidadas hasta que llegue al código de nivel superior en la aplicación; entonces la aplicación puede informar el error de la manera que desee. Cuando ocurre un error en segundo plano, el desenrollado termina en la biblioteca Tk y no hay una forma obvia para que Tk informe el error.

Cuando Tk detecta un error en segundo plano, guarda información sobre el error e invoca el método Tk::Error más tarde, cuando Tk está inactivo.

Tk::Error es invocado por perl/Tk como si fuera por el código perl:

    $mainwindow->Tk::Error("mensaje de error", ubicación ...);

$mainwindow es la MainWindow asociada con el widget que detectó el error, "mensaje de error" es una cadena que describe el error que se ha detectado, ubicación es una lista de una o más "ubicaciones" que describen la secuencia de llamadas en el punto en que se detectó el error.

Las ubicaciones son típicamente una mezcla de informes de ubicación de perl que dan el nombre del script y el número de línea, y cadenas simples que describen ubicaciones en el código C de Tk o perl/Tk.

Tk ignorará cualquier resultado devuelto por el método Tk::Error. Si ocurre otro error dentro del método Tk::Error (por ejemplo, si llama a die), Tk informa este error escribiendo un mensaje en stderr (esto es para evitar bucles infinitos debido a errores en Tk::Error).

Si se acumulan varios errores en segundo plano antes de que se invoque Tk::Error para procesarlos, Tk::Error se invocará una vez por cada error, en el orden en que ocurrieron. Sin embargo, si Tk::Error llama a Tk->break, entonces los errores restantes se omiten sin llamar a Tk::Error.

El módulo Tk incluye una subrutina predeterminada Tk::Error que simplemente informa el error en stderr.

Tk::ErrorDialog

Se proporciona una definición alternativa a través de:

    "require Tk::ErrorDialog;"

que muestra un cuadro de diálogo que contiene el mensaje de error y ofrece al usuario la posibilidad de ver un rastreo de pila que muestra dónde ocurrió el error.

Esta es una implementación OO del comando Tcl/Tk bgerror, con un giro: dado que solo hay un widget ErrorDialog, no se requiere que invoque el constructor para crearlo; se creará automáticamente cuando ocurra el primer error en segundo plano. Sin embargo, para configurar las opciones de -cleanupcode y -appendtraceback de ErrorDialog, debe llamar al constructor y crearlo manualmente.

El objeto ErrorDialog consiste esencialmente en dos subwidgets: un widget Dialog para mostrar el error en segundo plano y un widget Text para la información del rastreo de pila. Si es necesario, puede invocar varios métodos de widget para personalizar estos subwidgets; sus nombres anunciados se describen a continuación.

    $mw->ErrorDialog(-cleanupcode => código, -appendtraceback => bool);

$mw es una referencia de ventana.

código es una referencia de CÓDIGO si se requiere un procesamiento especial posterior al error en segundo plano (el valor predeterminado es indefinido). La subrutina de devolución de llamada se llama con @_ teniendo los mismos argumentos con los que se invocó Tk::Error.

bool es un booleano que indica si se deben agregar o no rastreos de pila sucesivos (el valor predeterminado es 1, agregar).

Widgets ErrorDialog anunciados

error_dialog es la referencia del widget Dialog.

text es la referencia del widget Text que contiene la información del rastreo de pila.

ERRORES

Si after o fileevent no se invocan como métodos de un widget, perl/Tk no puede proporcionar un argumento $mainwindow. Para soportar dicho código de versiones anteriores de perl/Tk, perl/Tk invoca Tk::Error con la cadena 'Tk' en su lugar: Tk->Tk::Error\(...\). En este caso, el Tk::Error en Tk::ErrorDialog e implementaciones similares no pueden "abrir" una ventana ya que no saben qué pantalla usar. Se debe proporcionar un mecanismo para suministrar la MainWindow en aplicaciones que solo tienen una (un caso muy común).
