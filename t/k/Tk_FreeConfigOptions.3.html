NOMBRE

Tk_CreateOptionTable, Tk_DeleteOptionTable, Tk_InitOptions, Tk_SetOptions, Tk_FreeSavedOptions, Tk_RestoreSavedOptions, Tk_GetOptionValue, Tk_GetOptionInfo, Tk_FreeConfigOptions, Tk_Offset - procesar opciones de configuración

#include <tk.h>

Tk_DeleteOptionTable(optionTable)

Tk_InitOptions(interp, recordPtr, optionTable, tkwin)

Tk_SetOptions(interp, recordPtr, optionTable, objc, objv, tkwin, savePtr, maskPtr)

Tk_FreeSavedOptions(savePtr)

Tk_RestoreSavedOptions(savePtr)

Tcl_Obj *
Tk_GetOptionValue(interp, recordPtr, optionTable, namePtr, tkwin)

Tk_GetOptionInfo(interp, recordPtr, optionTable, namePtr, tkwin)

ARGUMENTOS

Tcl_Interp *interp (entrada)
Un intérprete Tcl. La mayoría de los procedimientos solo lo usan para devolver mensajes de error; si es NULL, no se devuelven mensajes de error. Para Tk_CreateOptionTable el valor no puede ser NULL; proporciona el intérprete en el que se utilizará la tabla de opciones.
const Tk_OptionSpec *templatePtr (entrada)
Punta a una matriz de información estática que describe las opciones de configuración que se admiten. Se utiliza para construir una Tk_OptionTable. La información apuntada por este argumento debe existir durante la vida útil de la Tk_OptionTable.
Tk_OptionTable optionTable (entrada)
Token para una tabla de opciones. Debe haber sido devuelto por una llamada anterior a Tk_CreateOptionTable.
char *recordPtr (entrada/salida)
Punta a la estructura en la que se almacenan los valores de las opciones de configuración; los campos de este registro son modificados por procedimientos como Tk_SetOptions y leídos por procedimientos como Tk_GetOptionValue.
Tk_Window tkwin (entrada)
Para opciones como TK_OPTION_COLOR, este argumento indica la ventana en la que se utilizará la opción. Si optionTable no utiliza opciones dependientes de la ventana, entonces se puede suministrar un valor NULL para este argumento.
int objc (entrada)
Número de valores en objv.
Tcl_Obj *const *objv (entrada)
Argumentos de línea de comandos para establecer opciones de configuración.
Tk_SavedOptions *savePtr (salida)
Si no es NULL, la estructura apuntada por este argumento se rellena con los valores antiguos de cualquier opción que se haya modificado y los valores antiguos se restauran automáticamente si ocurre un error en Tk_SetOptions.
int *maskPtr (salida)
Si no es NULL, la palabra apuntada por maskPtr se rellena con el OR a nivel de bits de los campos typeMask de las opciones que se modificaron.
Tk_SavedOptions *savedPtr (entrada/salida)
Punta a una estructura rellenada previamente por Tk_SetOptions con valores antiguos de opciones modificadas.
Tcl_Obj *namePtr (entrada)
El valor de este objeto es el nombre de una opción particular. Si se pasa NULL a Tk_GetOptionInfo, se devuelve información para todas las opciones. No debe ser NULL cuando se llama a Tk_GetOptionValue.
nombre de tipo type (entrada)
El nombre del tipo de un registro.
nombre de campo field (entrada)
El nombre de un campo en registros del tipo type.

DESCRIPCIÓN

Estos procedimientos manejan la mayoría de los detalles de análisis de opciones de configuración, como las de los widgets Tk. Dada una descripción de las opciones que se admiten, estos procedimientos manejan todos los detalles de análisis de opciones y almacenamiento de sus valores en una estructura C asociada con el widget u objeto. Los procedimientos fueron diseñados principalmente para widgets en Tk, pero también se pueden usar para otros tipos de objetos que tienen opciones de configuración. En el resto de esta página de manual se usará "widget" para referirse al objeto cuyas opciones se están gestionando; en la práctica, el objeto puede no ser realmente un widget. El término "registro de widget" se usa para referirse a la estructura a nivel de C en la que se almacena información sobre un widget u objeto particular.

Tenga en cuenta que la forma más fácil de aprender a usar estos procedimientos es observar un ejemplo funcional. En Tk, el ejemplo más simple es el código que implementa la familia de widgets de botones, que se encuentra en tkButton.c. Otros ejemplos están en tkSquare.c y tkMenu.c.

Para usar estos procedimientos, el código que implementa el widget debe contener una matriz estática de estructuras Tk_OptionSpec. Esta es una plantilla que describe las diversas opciones admitidas por esa clase de widget; hay una plantilla separada para cada tipo de widget. La plantilla contiene información como el nombre de cada opción, su tipo, su valor predeterminado y dónde se almacena el valor de la opción en el registro del widget. Vea PLANTILLAS a continuación para más detalles.

Para procesar las opciones de configuración de manera eficiente, la plantilla estática debe complementarse con información adicional que solo está disponible en tiempo de ejecución. El procedimiento Tk_CreateOptionTable crea esta información dinámica a partir de la plantilla y devuelve un token Tk_OptionTable que describe tanto la información estática como la dinámica. Todos los demás procedimientos, como Tk_SetOptions, toman un token Tk_OptionTable como argumento. Típicamente, Tk_CreateOptionTable se llama la primera vez que se crea un widget de una clase particular y la Tk_OptionTable resultante se usa en el futuro para todos los widgets de esa clase. Una Tk_OptionTable solo puede usarse en un único intérprete, dado por el argumento interp a Tk_CreateOptionTable. Cuando una tabla de opciones ya no es necesaria, se debe llamar a Tk_DeleteOptionTable para liberar todos sus recursos. Todas las tablas de opciones de un intérprete Tcl se liberan automáticamente si se elimina el intérprete.

Tk_InitOptions se invoca cuando se crea un nuevo widget para establecer los valores predeterminados. Tk_InitOptions recibe un token para una tabla de opciones (optionTable) y un puntero a un registro de widget (recordPtr), que es la estructura C que contiene información sobre este widget. Tk_InitOptions utiliza la información de la tabla de opciones para elegir un valor predeterminado apropiado para cada opción, luego almacena el valor predeterminado directamente en el registro del widget, sobrescribiendo cualquier información que ya estuviera presente en el registro del widget. Tk_InitOptions normalmente devuelve TCL_OK. Si ocurrió un error al establecer los valores predeterminados (por ejemplo, porque un valor predeterminado era erróneo), entonces se devuelve TCL_ERROR y se deja un mensaje de error en el resultado de interp si interp no es NULL. Para cualquier opción de configuración de un widget que tenga TK_OPTION_DONT_SET_DEFAULT establecido en su campo flags, la inicialización anterior se omite por completo, véase más abajo.

Tk_SetOptions se invoca para modificar las opciones de configuración basándose en la información especificada en un comando Tcl. El comando podría ser uno que crea un nuevo widget, o un comando que modifica opciones en un widget existente. Los argumentos objc y objv describen los valores de los argumentos del comando Tcl. Objv debe contener un número par de objetos: el primer objeto de cada par da el nombre de una opción y el segundo objeto da el nuevo valor para esa opción. Tk_SetOptions busca cada nombre en optionTable, verifica que el nuevo valor de la opción se ajuste al tipo en optionTable, y almacena el valor de la opción en el registro del widget proporcionado por recordPtr. Tk_SetOptions normalmente devuelve TCL_OK. Si ocurrió un error (como un nombre de opción desconocido o un valor de opción ilegal), entonces se devuelve TCL_ERROR y se deja un mensaje de error en el resultado de interp si interp no es NULL.

Tk_SetOptions tiene dos características adicionales. Primero, si el argumento maskPtr no es NULL, entonces apunta a un valor entero que se rellena con información sobre las opciones que se modificaron. Por cada opción en la plantilla pasada a Tk_CreateOptionTable hay un campo typeMask. Los bits de este campo están definidos por el código que implementa el widget; por ejemplo, cada bit podría corresponder a una configuración de opción particular. Alternativamente, los bits podrían usarse funcionalmente. Por ejemplo, un bit podría usarse para redibujar: todas las opciones que afectan la visualización del widget, de tal manera que cambiar la opción requiera que el widget se redibuje, podrían tener ese bit establecido. Otro bit podría indicar que la geometría del widget debe recalcularse, y así sucesivamente. Tk_SetOptions ORa juntos los campos typeMask

La segunda característica adicional de Tk_SetOptions tiene que ver con la recuperación de errores. Si ocurre un error al procesar las opciones de configuración, esta característica permite restaurar todas las opciones de configuración a sus valores anteriores. Los errores pueden ocurrir al procesar opciones en Tk_SetOptions o más tarde en el llamador. En muchos casos, el llamador realiza un procesamiento adicional después de que Tk_SetOptions regresa; por ejemplo, puede usar un valor de opción para establecer un rastro en una variable y puede detectar un error si la variable es una matriz en lugar de un escalar. La recuperación de errores se habilita pasando un valor no NULL para el argumento savePtr a Tk_SetOptions; este debe ser un puntero a una estructura Tk_SavedOptions no inicializada en la pila del llamador. Tk_SetOptions sobrescribe la estructura apuntada por *savePtr con información sobre los valores antiguos de cualquier opción modificada por el procedimiento. Si Tk_SetOptions regresa exitosamente, el llamador usa la estructura de una de dos maneras. Si el llamador completa su procesamiento de las nuevas opciones sin errores, entonces debe pasar la estructura a Tk_FreeSavedOptions para que los valores antiguos puedan ser liberados. Si el llamador detecta un error en su procesamiento de las nuevas opciones, entonces debe pasar la estructura a Tk_RestoreSavedOptions, que copiará los valores antiguos de vuelta al registro del widget y liberará los nuevos valores. Si Tk_SetOptions detecta un error, restaura automáticamente cualquier opción que ya se haya modificado y deja *savePtr en un estado vacío: el llamador no necesita llamar a Tk_FreeSavedOptions ni a Tk_RestoreSavedOptions. Si el argumento savePtr a Tk_SetOptions es NULL, entonces Tk_SetOptions libera cada valor de opción antiguo inmediatamente cuando establece un nuevo valor para la opción. En este caso, si ocurre un error en la tercera opción, los valores antiguos para las dos primeras opciones no pueden ser restaurados.

Tk_GetOptionValue devuelve el valor actual de una opción de configuración para un widget en particular. El argumento namePtr contiene el nombre de una opción; Tk_GetOptionValue usa optionTable para buscar la opción y extraer su valor del registro del widget apuntado por recordPtr, luego devuelve un objeto que contiene ese valor. Si ocurre un error (por ejemplo, porque namePtr contiene un nombre de opción desconocido) entonces se devuelve NULL y se deja un mensaje de error en el resultado de interp a menos que interp sea NULL.

Tk_GetOptionInfo devuelve información sobre las opciones de configuración en un formato adecuado para los comandos de widget configure. Si el argumento namePtr no es NULL, apunta a un objeto que da el nombre de una opción de configuración; Tk_GetOptionInfo devuelve un objeto que contiene una lista con cinco elementos, que son el nombre de la opción, el nombre y la clase utilizados para la opción en la base de datos de opciones, el valor predeterminado para la opción y el valor actual para la opción. Si el argumento namePtr es NULL, entonces Tk_GetOptionInfo devuelve información sobre todas las opciones en forma de una lista de listas; cada sublista describe una opción. Las opciones sinónimas se manejan de manera diferente dependiendo de si namePtr es NULL: si namePtr es NULL, entonces la sublista para cada opción sinónima tiene solo dos elementos, que son el nombre de la opción y el nombre de la otra opción a la que se refiere; si namePtr no es NULL y nombra una opción sinónima, entonces el objeto devuelto es la lista de cinco elementos para la otra opción a la que se refiere el sinónimo. Si ocurre un error (por ejemplo, porque namePtr contiene un nombre de opción desconocido) entonces se devuelve NULL y se deja un mensaje de error en el resultado de interp a menos que interp sea NULL.

Tk_FreeConfigOptions debe invocarse cuando se elimina un widget. Libera todos los recursos asociados con cualquiera de las opciones de configuración definidas en recordPtr por optionTable.

La macro Tk_Offset se proporciona como una forma segura de generar los valores objOffset e internalOffset para las entradas en las estructuras Tk_OptionSpec. Toma dos argumentos: el nombre de un tipo de registro y el nombre de un campo en ese registro. Devuelve el desplazamiento de bytes del campo con nombre en registros del tipo dado.

PLANTILLAS

La matriz de estructuras Tk_OptionSpec pasada a Tk_CreateOptionTable a través de su argumento templatePtr describe las opciones de configuración compatibles con una clase particular de widgets. Cada estructura especifica una opción de configuración y tiene los siguientes campos:

typedef struct {
    Tk_OptionType type;
    const char *optionName;
    const char *dbName;
    const char *dbClass;
    const char *defValue;
    int objOffset;
    int internalOffset;
    int flags;
    const void *clientData;
    int typeMask;
} Tk_OptionSpec;
El campo type indica qué tipo de opción de configuración es esta (por ejemplo, TK_OPTION_COLOR para un valor de color o TK_OPTION_INT para un valor entero). Type determina cómo se analiza el valor de la opción (más sobre esto a continuación). El campo optionName es una cadena como -font o -bg; es el nombre utilizado para la opción en los comandos Tcl y se pasa a los procedimientos a través de los argumentos objc o namePtr. Los campos dbName y dbClass son utilizados por Tk_InitOptions para buscar un valor predeterminado para esta opción en la base de datos de opciones; si dbName es NULL, entonces Tk_InitOptions no usa la base de datos de opciones para esta opción. El campo defValue especifica un valor predeterminado para esta opción de configuración si no se especifica ningún valor en la base de datos de opciones. Los campos objOffset e internalOffset indican dónde almacenar el valor de esta opción en los registros del widget (más sobre esto a continuación); los valores para los campos objOffset e internalOffset siempre deben generarse con la macro Tk_Offset. El campo flags contiene información adicional para controlar el procesamiento de esta opción de configuración (ver más abajo para detalles). ClientData proporciona datos adicionales específicos del tipo necesarios para ciertos tipos. Por ejemplo, para los tipos TK_OPTION_COLOR, clientData es una cadena que indica el valor predeterminado a usar en pantallas monocromáticas. Consulte las descripciones de los diferentes tipos a continuación para obtener detalles. El último campo, typeMask, es utilizado por Tk_SetOptions para devolver información sobre qué opciones se modificaron; consulte la descripción de Tk_SetOptions arriba para obtener detalles.

Cuando Tk_InitOptions y Tk_SetOptions almacenan el valor de una opción en el registro del widget, pueden hacerlo de dos maneras. Si el campo objOffset de Tk_OptionSpec es mayor o igual que cero, entonces el valor de la opción se almacena como un (Tcl_Obj *) en la ubicación del registro del widget dada por objOffset. Si el campo internalOffset de Tk_OptionSpec es mayor o igual que cero, entonces el valor de la opción se almacena en una forma interna específica del tipo en la ubicación del registro del widget dada por internalOffset. Por ejemplo, si el tipo de la opción es TK_OPTION_INT, entonces la forma interna es un entero. Si el campo objOffset o internalOffset es negativo, el valor no se almacena de esa forma. Al menos uno de los desplazamientos debe ser mayor o igual que cero.

El campo flags consiste en uno o más bits combinados con OR. Se admiten las siguientes banderas:

TK_OPTION_NULL_OK
Si este bit está establecido para una opción, se aceptará una cadena vacía como valor para la opción y la forma interna resultante será un puntero NULL, un valor cero, o None, dependiendo del tipo de la opción. Si la bandera no está establecida, las cadenas vacías generarán errores. TK_OPTION_NULL_OK se usa típicamente para permitir que una función se desactive por completo, por ejemplo, para establecer un valor de cursor en None de modo que una ventana simplemente herede el cursor de su padre. No todos los tipos de opciones admiten la bandera TK_OPTION_NULL_OK; para aquellos que lo hacen, hay una indicación explícita de este hecho en las descripciones a continuación.
TK_OPTION_DONT_SET_DEFAULT
Si este bit está establecido para una opción, no se establecerá ningún valor predeterminado en Tk_InitOptions para esta opción. Ni la base de datos de opciones, ni ningún valor predeterminado del sistema, ni optionTable se utilizan para proporcionar un valor predeterminado a esta opción. En su lugar, se asume que el llamador ya ha proporcionado un valor predeterminado en el código del widget.

El campo type de cada estructura Tk_OptionSpec determina cómo analizar el valor de esa opción de configuración. El valor legal para type, y las acciones correspondientes, se describen a continuación. Si el tipo requiere que se pase un valor tkwin a procedimientos como Tk_SetOptions, o si utiliza el campo clientData de Tk_OptionSpec, entonces se indica explícitamente; si no se menciona, el tipo no requiere ni tkwin ni clientData.

TK_OPTION_ANCHOR
El valor debe ser una posición de anclaje estándar como ne o center. La forma interna es un valor Tk_Anchor como los devueltos por Tk_GetAnchorFromObj.
TK_OPTION_BITMAP
El valor debe ser un nombre de bitmap Tk estándar. La forma interna es un token de Pixmap como los devueltos por Tk_AllocBitmapFromObj. Este tipo de opción requiere que se proporcione tkwin a procedimientos como Tk_SetOptions, y admite la bandera TK_OPTION_NULL_OK.
TK_OPTION_BOOLEAN
El valor debe ser un valor booleano estándar como true o no. La forma interna es un entero con valor 0 o 1. Tenga en cuenta que si no se utiliza el campo objOffset, se perderá la información sobre el valor original de esta opción.
TK_OPTION_BORDER
El valor debe ser un nombre de color estándar como red o #ff8080. La forma interna es un token Tk_3DBorder como los devueltos por Tk_Alloc3DBorderFromObj. Este tipo de opción requiere que se proporcione tkwin a procedimientos como Tk_SetOptions, y admite la bandera TK_OPTION_NULL_OK.
TK_OPTION_COLOR
El valor debe ser un nombre de color estándar como red o #ff8080. La forma interna es un token Tk_3DBorder como los devueltos por Tk_Alloc3DBorderFromObj. Este tipo de opción requiere que se proporcione tkwin a procedimientos como Tk_SetOptions, y admite la bandera TK_OPTION_NULL_OK.

In this case, the internal form is an integer pixel value that is valid only for a particular screen. If the value of the option is retrieved, it will be returned as a simple number. For example, after the command .b configure -borderwidth 2m, the command .b configure -borderwidth might return 7, which is the integer pixel value corresponding to 2m. Unfortunately, this loses the original screen-independent value. Thus for TK_OPTION_PIXELS options it is better to use the objOffset field. In this case the original value of the option is retained in the object and can be returned when the option is retrieved. In most cases it is convenient to use the internalOffset field as well, so that the integer value is immediately available for use in the widget code (alternatively, Tk_GetPixelsFromObj can be used to extract the integer value from the object whenever it is needed). Note that the problem of losing information on retrievals exists only for TK_OPTION_PIXELS options." }, { "type": "paragraph", "text": "The second reason to use the objOffset field is in order to implement new types of options not supported by these procedures. To implement a new type of option, you can use TK_OPTION_STRING as the type in the Tk_OptionSpec structure and set the objOffset field but not the internalOffset field. Then, after calling Tk_SetOptions, convert the object to internal form yourself." }, { "type": "paragraph", "text": "Ttk widgets do not support the internalOffset machinery. El procedimiento _setProc_ es invocado por Tk_SetOptions para convertir un Tcl_Obj en una representación interna y almacenar el valor resultante en el registro del widget. Los argumentos son:

clientData
Una copia del campo _clientData_ en la estructura Tk_ObjCustomOption.
interp
Un puntero a un intérprete Tcl, utilizado para la notificación de errores.
Tkwin
Una copia del argumento _tkwin_ a Tk_SetOptions
valuePtr
Un puntero a una referencia a un Tcl_Obj que describe el nuevo valor para la opción; podría haber sido especificado explícitamente en la llamada a Tk_SetOptions o podría provenir de la base de datos de opciones o de un valor predeterminado. Si el objOffset para la opción es no negativo (el valor de la opción se almacena como un (Tcl_Obj *) en el registro del widget), el puntero Tcl_Obj referenciado por _valuePtr_ es el puntero que se almacenará en el objOffset para la opción. _SetProc_ puede modificar el valor si es necesario; por ejemplo, _setProc_ puede cambiar el valor a NULL para soportar la bandera TK_OPTION_NULL_OK.
recordPtr
Un puntero al inicio del registro del widget a modificar.
internalOffset
Desplazamiento en bytes desde el inicio del registro del widget hasta la ubicación donde se colocará la representación interna del valor de la opción.
saveInternalPtr
Un puntero al almacenamiento asignado en una estructura Tk_SavedOptions para la representación interna del valor original de la opción. Antes de establecer la opción a su nuevo valor, _setProc_ debe establecer el valor referenciado por _saveInternalPtr_ al valor original de la opción para soportar Tk_RestoreSavedOptions.
flags
Una copia del campo _flags_ en la estructura Tk_OptionSpec para la opción

_SetProc_ devuelve un resultado Tcl estándar: TCL_OK para indicar un procesamiento exitoso, o TCL_ERROR para indicar un fallo de cualquier tipo. Se puede dejar un mensaje de error en el intérprete Tcl proporcionado por _interp_ en caso de error.

El procedimiento _getProc_ es invocado por Tk_GetOptionValue y Tk_GetOptionInfo para recuperar una representación Tcl_Obj de la representación interna de una opción. El argumento _clientData_ es una copia del campo _clientData_ en la estructura Tk_ObjCustomOption. _Tkwin_ es una copia del argumento _tkwin_ a Tk_GetOptionValue o Tk_GetOptionInfo. _RecordPtr_ es un puntero al inicio del registro del widget a consultar. _InternalOffset_ es el desplazamiento en bytes desde el inicio del registro del widget hasta la ubicación donde se almacena la representación interna del valor de la opción. _GetProc_ debe devolver un puntero a un Tcl_Obj que represente el valor de la opción.

El procedimiento _restoreProc_ es invocado por Tk_RestoreSavedOptions para restaurar una representación interna previamente guardada de un valor de opción personalizado. El argumento _clientData_ es una copia del campo _clientData_ en la estructura Tk_ObjCustomOption. _Tkwin_ es una copia del argumento _tkwin_ a Tk_GetOptionValue o Tk_GetOptionInfo. _InternalPtr_ es un puntero a la ubicación donde se almacena la representación interna del valor de la opción. _SaveInternalPtr_ es un puntero al valor guardado. _RestoreProc_ debe copiar el valor de _saveInternalPtr_ a _internalPtr_ para restaurar el valor. _RestoreProc_ no necesita liberar ninguna memoria asociada con _internalPtr_ o _saveInternalPtr_; _freeProc_ será invocado para liberar esa memoria si es necesario. _RestoreProc_ no tiene valor de retorno.

El procedimiento _freeProc_ es invocado por Tk_SetOptions y Tk_FreeSavedOptions para liberar cualquier almacenamiento asignado para la representación interna de una opción personalizada. El argumento _clientData_ es una copia del campo _clientData_ en la estructura Tk_ObjCustomOption. _Tkwin_ es una copia del argumento _tkwin_ a Tk_GetOptionValue o Tk_GetOptionInfo. _InternalPtr_ es un puntero a la ubicación donde se almacena la representación interna del valor de la opción. El _freeProc_ debe liberar cualquier almacenamiento asociado con la opción. _FreeProc_ no tiene valor de retorno.
