Tk_CreateImageType(3)

Paquete: tk

Licencias: TCL

Tk_CreateImageType(3) Procedimientos de la Biblioteca Tk Tk_CreateImageType(3)

NOMBRE

Tk_CreateImageType, Tk_GetImageMasterData, Tk_GetImageModelData, Tk_InitImageArgs - definir un nuevo tipo de imagen

SINOPSIS

#include <tk.h>

Tk_CreateImageType(typePtr)

ClientData
Tk_GetImageMasterData(interp, name, typePtrPtr)

ClientData
Tk_GetImageModelData(interp, name, typePtrPtr)

Tk_InitImageArgs(interp, argc, argvPtr)

ARGUMENTOS

const Tk_ImageType *typePtr (entrada)
Estructura que define el nuevo tipo de imagen. Para Tk 8.4 y anteriores, esto debe ser estático: el código de imagen retiene un puntero a esta estructura. En Tk 8.5, esta limitación se relajó.
Tcl_Interp *interp (entrada)
Intérprete en el que se creó la imagen.
const char *name (entrada)
Nombre de la imagen existente.
Tk_ImageType **typePtrPtr (salida)
Punta a la palabra en la que almacenar un puntero a la información de tipo para la imagen dada, si existe.
int argc (entrada)
Número de argumentos
char ***argvPtr (entrada/salida)
Puntero a la lista de argumentos

DESCRIPCION

Tk_CreateImageType se invoca para definir un nuevo tipo de imagen. Un tipo de imagen corresponde a un valor particular del argumento type para el comando image create. Puede existir cualquier número de tipos de imagen diferentes, y se pueden definir nuevos tipos dinámicamente llamando a Tk_CreateImageType. Por ejemplo, podría existir un tipo para mapas de bits de 2 colores, otro para imágenes en color, otro para imágenes difuminadas, otro para vídeo, etc.

El código que implementa un nuevo tipo de imagen se llama un *gestor de imágenes*. Consiste en una colección de procedimientos más tres tipos diferentes de estructuras de datos. La primera estructura de datos es una estructura Tk_ImageType, que contiene el nombre del tipo de imagen y punteros a cinco procedimientos proporcionados por el gestor de imágenes para manejar imágenes de este tipo:

typedef struct Tk_ImageType {
    const char *name;
    Tk_ImageCreateProc *createProc;
    Tk_ImageGetProc *getProc;
    Tk_ImageDisplayProc *displayProc;
    Tk_ImageFreeProc *freeProc;
    Tk_ImageDeleteProc *deleteProc;
} Tk_ImageType;
Los campos de esta estructura se describirán en subsecciones posteriores de esta entrada.

La segunda estructura de datos principal manipulada por un gestor de imágenes se llama *modelo de imagen*; contiene información general sobre una imagen particular, como los valores de las opciones de configuración especificadas en un comando image create. Normalmente habrá una de estas estructuras por cada invocación del comando image create.

La tercera estructura de datos relacionada con las imágenes es una *instancia de imagen*. Normalmente habrá una de estas estructuras por cada uso de una imagen en un widget particular. Es posible que una única imagen aparezca simultáneamente en múltiples widgets, o incluso múltiples veces en el mismo widget. Además, diferentes instancias pueden estar en diferentes pantallas o visualizaciones. La estructura de datos de la instancia de imagen describe cosas que pueden variar de una instancia a otra, como colores y contextos gráficos para redibujar. Normalmente hay una estructura de instancia por cada opción -image especificada para un widget o elemento de lienzo.

Las siguientes subsecciones describen los campos de una Tk_ImageType con más detalle.

NOMBRE

typePtr->name proporciona un nombre para el tipo de imagen. Una vez que Tk_CreateImageType regresa, este nombre se puede usar en los comandos image create para crear imágenes del nuevo tipo. Si ya existía un tipo de imagen con este nombre, el nuevo tipo de imagen reemplaza al anterior.

CREATEPROC

typePtr->createProc proporciona la dirección de un procedimiento que Tk llamará cada vez que se invoque image create para crear una imagen del nuevo tipo. typePtr->createProc debe coincidir con el siguiente prototipo:

typedef int Tk_ImageCreateProc(
        Tcl_Interp *interp,
        const char *name,
        int objc,
        Tcl_Obj *const objv[],
        const Tk_ImageType *typePtr,
        Tk_ImageMaster model,
        ClientData *modelDataPtr);
El argumento interp es el intérprete en el que se invocó el comando image, y name es el nombre de la nueva imagen, que fue especificado explícitamente en el comando image o generado automáticamente por el comando image. Los argumentos objc y objv describen todas las opciones de configuración para la nueva imagen (todo lo que sigue al argumento de nombre para image). El argumento model es un token que se refiere a la información de Tk sobre esta imagen; el gestor de imágenes debe devolver este token a Tk al invocar el procedimiento Tk_ImageChanged. Típicamente createProc analizará objc y objv y creará una estructura de datos de modelo de imagen para la nueva imagen. createProc puede almacenar un valor arbitrario de una palabra en *modelDataPtr, que se le devolverá al gestor de imágenes al invocar otras callbacks. Típicamente el valor es un puntero a la estructura de datos del modelo para la imagen.

Si createProc encuentra un error, debe dejar un mensaje de error en el resultado del intérprete y devolver TCL_ERROR; de lo contrario, debe devolver TCL_OK.

createProc debe llamar a Tk_ImageChanged para establecer el tamaño de la imagen y solicitar una redibujada inicial.

GETPROC

Tk invoca typePtr->getProc cada vez que un widget llama a Tk_GetImage para usar una imagen particular. Este procedimiento debe coincidir con el siguiente prototipo:

typedef ClientData Tk_ImageGetProc(
        Tk_Window tkwin,
        ClientData modelData);
El argumento tkwin identifica la ventana en la que se usará la imagen y modelData es el valor devuelto por createProc cuando se creó el modelo de imagen. getProc normalmente creará una estructura de datos para la nueva instancia, incluyendo cosas como los recursos necesarios para mostrar la imagen en la ventana dada. getProc devuelve un token de una palabra para la instancia, que típicamente es la dirección de la estructura de datos de la instancia. Tk devolverá este valor al gestor de imágenes al invocar sus procedimientos displayProc y freeProc.

DISPLAYPROC

Tk invoca typePtr->displayProc cada vez que se necesita mostrar una imagen (es decir, cada vez que un widget llama a Tk_RedrawImage). displayProc debe coincidir con el siguiente prototipo:

typedef void Tk_ImageDisplayProc(
        ClientData instanceData,
        Display *display,
        Drawable drawable,
        int imageX,
        int imageY,
        int width,
        int height,
        int drawableX,
        int drawableY);
instanceData será el mismo que el valor devuelto por getProc cuando se creó la instancia. display y drawable indican dónde mostrar la imagen; drawable puede ser un mapa de bits en lugar de la ventana especificada a getProc (este suele ser el caso, ya que la mayoría de los widgets usan doble búfer para redibujar para obtener efectos visuales más suaves). imageX, imageY, width e height identifican la región de la imagen que debe redibujarse. Esta región siempre estará dentro del tamaño de la imagen según lo especificado en la llamada más reciente a Tk_ImageChanged. drawableX y drawableY indican dónde se debe mostrar la imagen en drawable; displayProc debe mostrar la región dada de la imagen de tal manera que el punto (imageX, imageY) en la imagen aparezca en (drawableX, drawableY) en drawable.

FREEPROC

typePtr->freeProc contiene la dirección de un procedimiento que Tk invocará cuando se libere una instancia de imagen (es decir, cuando se invoque Tk_FreeImage). Esto puede suceder, por ejemplo, cuando se elimina un widget o un elemento de imagen en un lienzo, o cuando se cambia la imagen que se muestra en un widget o elemento de lienzo. freeProc debe coincidir con el siguiente prototipo:

typedef void Tk_ImageFreeProc(
        ClientData instanceData);
El argumento instanceData es el mismo valor que se devolvió de getProc cuando se creó la instancia. El procedimiento freeProc es responsable de liberar cualquier recurso que se haya asignado específicamente para esta instancia de imagen (por ejemplo, el contexto gráfico para dibujar la imagen en la pantalla especificada por el argumento display a displayProc).

DELETEPROC

typePtr->deleteProc contiene la dirección de un procedimiento que Tk invocará cuando un modelo de imagen sea eliminado (es decir, cuando se invoque image delete). deleteProc debe coincidir con el siguiente prototipo:

typedef void Tk_ImageDeleteProc(
        Tcl_Interp *interp,
        ClientData modelData);
El argumento modelData es el valor que se almacenó en *modelDataPtr por createProc cuando se creó el modelo de imagen. El procedimiento deleteProc es responsable de liberar cualquier recurso que se haya asignado específicamente para el modelo de imagen (por ejemplo, la estructura de datos del modelo de imagen en sí). Debe ser capaz de manejar el caso en que el modelo de imagen todavía tenga instancias activas.

PROCEDIMIENTOS DE UTILIDAD

Las siguientes funciones se proporcionan como ayuda para escribir gestores de imágenes:

TK_GETIMAGEMASTERDATA

Este procedimiento se puede usar para encontrar la información de modelo para una imagen dada su nombre. El parámetro name es el nombre de la imagen. El parámetro typePtrPtr se puede establecer para recibir un puntero a la estructura Tk_ImageType para el tipo de la imagen. Si se encuentra la imagen, devuelve los datos del modelo de la imagen (el valor que el gestor de imágenes almacenó en *modelDataPtr cuando la imagen fue creada). Si la imagen no se encuentra, devuelve NULL.

TK_GETIMAGEMODELDATA

Idéntico a Tk_GetImageMasterData, pero se utiliza para imágenes que no son propiedad de ningún widget y que por lo tanto sólo pueden ser eliminadas por comando explícito image delete.

TK_INITIMAGEARGS

Este procedimiento se utiliza para analizar los argumentos de un comando image. Toma el intérprete, el número de argumentos y el puntero a la lista de argumentos. Los argumentos de la imagen se interpretan como un par nombre-valor. argvPtr se actualiza para apuntar a la primera opción sin analizar.

Devuelve TCL_OK si los argumentos se analizaron correctamente, o TCL_ERROR en caso contrario.
