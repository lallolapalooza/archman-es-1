event(3) Documentación de Contribución de Usuarios de Perl event(3)

NOMBRE

Tk::event - Instalaciones de eventos varios: definir eventos virtuales y generar eventos

SINOPSIS

$widget->eventAcción(?arg, arg, ...?);

DESCRIPCIÓN

Los métodos eventAcción proporcionan varias instalaciones para tratar con eventos del sistema de ventanas, como definir eventos virtuales y sintetizar eventos. Los eventos virtuales son compartidos por todos los widgets de la misma MainWindow. Diferentes MainWindows pueden tener eventos virtuales diferentes.

Los siguientes métodos son soportados actualmente:

$widget->eventAdd('<<virtual>>', secuencia ?,secuencia, ...?)
Asocia el evento virtual virtual con la(s) secuencia(s) de eventos físicos dadas por los argumentos secuencia, de modo que el evento virtual se active siempre que ocurra cualquiera de las secuencias. Virtual puede ser cualquier valor de cadena y secuencia puede tener cualquiera de los valores permitidos para el argumento secuencia del método bind. Si virtual ya está definido, las nuevas secuencias de eventos físicos se suman a las secuencias existentes para el evento.
$widget->eventDelete('<<virtual>>' ?,secuencia, secuencia, ...?)
Elimina cada una de las secuencias de las asociadas con el evento virtual dado por virtual. Virtual puede ser cualquier valor de cadena y secuencia puede tener cualquiera de los valores permitidos para el argumento secuencia del método bind. Cualquier secuencia no asociada actualmente con virtual se ignora. Si no se proporciona ningún argumento secuencia, se eliminan todas las secuencias de eventos físicos para virtual, de modo que el evento virtual ya no se activará.
$widget->eventGenerate(evento ?,opción => valor, opción => valor, ...?)
Genera un evento de ventana y lo organiza para que se procese como si hubiera provenido del sistema de ventanas. $ventana es una referencia a la ventana para la cual se generará el evento. Evento proporciona una descripción básica del evento, como <Shift-Button-2> o <<Paste>>. Si Ventana está vacío, se refiere a toda la pantalla, y las coordenadas son relativas a la pantalla. Evento puede tener cualquiera de las formas permitidas para el argumento secuencia del método bind, excepto que debe consistir en un solo patrón de evento, no una secuencia. Se pueden usar pares opción-valor para especificar atributos adicionales del evento, como la posición del ratón x e y; ver "CAMPOS DE EVENTOS" a continuación. Si la opción -cuando no se especifica, el evento se procesa inmediatamente: todos los manejadores para el evento se completarán antes de que el método eventGenerate retorne. Si se especifica la opción -cuando, determina cuándo se procesa el evento.
$widget->eventInfo(?'<<virtual>>'?)
Devuelve información sobre eventos virtuales. Si se omite el argumento <<virtual>>, el valor de retorno es una lista de todos los eventos virtuales que están definidos actualmente. Si se especifica <<virtual>>, el valor de retorno es una lista cuyos elementos son las secuencias de eventos físicos definidas actualmente para el evento virtual dado; si el evento virtual no está definido, se devuelve undef.

CAMPOS DE EVENTOS

Las siguientes opciones son compatibles con el método eventGenerate. Estas corresponden a las expansiones de ``%'' permitidas en el script de enlace para el método bind.

-arriba => ventana
Ventana especifica el campo arriba para el evento, ya sea como un nombre de ruta de ventana o como un ID de ventana entero. Válido para eventos Configure. Corresponde a la sustitución %a para scripts de enlace.
-borde => tamaño
Tamaño debe ser una distancia de pantalla; especifica el campo border_width para el evento. Válido para eventos Configure. Corresponde a la sustitución %B para scripts de enlace.
-boton => numero
Número debe ser un entero; especifica el campo detalle para un evento ButtonPress o ButtonRelease, anulando cualquier número de botón proporcionado en el argumento base evento. Corresponde a la sustitución %b para scripts de enlace.
-cuenta => numero
Número debe ser un entero; especifica el campo cuenta para el evento. Válido para eventos Expose. Corresponde a la sustitución %c para scripts de enlace.
-delta => numero
numero debe ser un entero; especifica el campo delta para el evento MouseWheel. El delta se refiere a la dirección y magnitud con la que se giró la rueda del ratón. Tenga en cuenta que el valor no es una distancia de pantalla, sino unidades de movimiento en la rueda del ratón. Típicamente, estos valores son múltiplos de 120. Por ejemplo, 120 debería desplazar el widget de texto hacia arriba 4 líneas y -240 debería desplazar el widget de texto hacia abajo 8 líneas. Por supuesto, otros widgets pueden definir comportamientos diferentes para el movimiento de la rueda del ratón. Este campo corresponde a la sustitución %D para scripts de enlace.
-detalle => detalle
Detalle especifica el campo detalle para el evento y debe ser uno de los siguientes:
NotifyAncestor         NotifyNonlinearVirtual
NotifyDetailNone       NotifyPointer
NotifyInferior         NotifyPointerRoot
NotifyNonlinear        NotifyVirtual

Válido para eventos Enter, Leave, FocusIn y FocusOut. Corresponde a la sustitución %d para scripts de enlace.

-foco booleano
Booleano debe ser un valor booleano; especifica el campo foco para el evento. Válido para eventos Enter y Leave. Corresponde a la sustitución %f para scripts de enlace.
-altura tamaño
Tamaño debe ser una distancia de pantalla; especifica el campo altura para el evento. Válido para eventos Configure. Corresponde a la sustitución %h para scripts de enlace.
-codigoteclado numero
Número debe ser un entero; especifica el campo codigoteclado para el evento. Válido para eventos KeyPress y KeyRelease. Corresponde a la sustitución %k para scripts de enlace.
-simboloteclado nombre
Nombre debe ser el nombre de un símbolo de tecla válido, como g, space o Return; su valor de código de tecla correspondiente se utiliza como campo codigoteclado para el evento, anulando cualquier detalle especificado en el argumento base evento. Válido para eventos KeyPress y KeyRelease. Corresponde a la sustitución %K para scripts de enlace.
-modo notificación
Notificación especifica el campo modo para el evento y debe ser uno de NotifyNormal, NotifyGrab, NotifyUngrab o NotifyWhileGrabbed. Válido para eventos Enter, Leave, FocusIn y FocusOut. Corresponde a la sustitución %m para scripts de enlace.
-anular booleano
Booleano debe ser un valor booleano; especifica el campo override_redirect para el evento. Válido para eventos Map, Reparent y Configure. Corresponde a la sustitución %o para scripts de enlace.
-lugar dónde
Dónde
especifica el campo place para el evento; debe ser PlaceOnTop o PlaceOnBottom. Válido para eventos Circulate. Corresponde a la sustitución %p para scripts de enlace.
-root window
Window debe ser un nombre de ruta de ventana o un identificador entero de ventana; especifica el campo root para el evento. Válido para eventos KeyPress, KeyRelease, ButtonPress, ButtonRelease, Enter, Leave y Motion. Corresponde a la sustitución %R para scripts de enlace.
-rootx coord
Coord debe ser una distancia de pantalla; especifica el campo x_root para el evento. Válido para eventos KeyPress, KeyRelease, ButtonPress, ButtonRelease, Enter, Leave y Motion. Corresponde a la sustitución %X para scripts de enlace.
-rooty coord
Coord debe ser una distancia de pantalla; especifica el campo y_root para el evento. Válido para eventos KeyPress, KeyRelease, ButtonPress, ButtonRelease, Enter, Leave y Motion. Corresponde a la sustitución %Y para scripts de enlace.
-sendevent boolean
Boolean debe ser un valor booleano; especifica el campo send_event para el evento. Válido para todos los eventos. Corresponde a la sustitución %E para scripts de enlace.
-serial number
Number debe ser un entero; especifica el campo serial para el evento. Válido para todos los eventos. Corresponde a la sustitución %# para scripts de enlace.
-state state
State especifica el campo state para el evento. Para eventos KeyPress, KeyRelease, ButtonPress, ButtonRelease, Enter, Leave y Motion debe ser un valor entero. Para eventos Visibility debe ser uno de VisibilityUnobscured, VisibilityPartiallyObscured o VisibilityFullyObscured. Esta opción anula cualquier modificador como Meta o Control especificado en el event base. Corresponde a la sustitución %s para scripts de enlace.
-subwindow window
Window especifica el campo subwindow para el evento, ya sea como un nombre de ruta para un widget Tk o como un identificador entero de ventana. Válido para eventos KeyPress, KeyRelease, ButtonPress, ButtonRelease, Enter, Leave y Motion. Similar a la sustitución %S para scripts de enlace.
-time integer
Integer debe ser un valor entero; especifica el campo time para el evento. Válido para eventos KeyPress, KeyRelease, ButtonPress, ButtonRelease, Enter, Leave, Motion y Property. Corresponde a la sustitución %t para scripts de enlace.
-warp boolean
boolean debe ser un valor booleano; especifica si el puntero de la pantalla también debe ser deformado. Válido para eventos KeyPress, KeyRelease, ButtonPress, ButtonRelease y Motion.
-width size
Size debe ser una distancia de pantalla; especifica el campo width para el evento. Válido para eventos Configure. Corresponde a la sustitución %w para scripts de enlace.
-when when
When determina cuándo se procesará el evento; debe tener uno de los siguientes valores:
now
Procesa el evento inmediatamente, antes de que el comando retorne. Esto también ocurre si se omite la opción -when.
tail
Coloca el evento en la cola de eventos de perl/Tk detrás de cualquier evento ya en cola para esta aplicación.
head
Coloca el evento al principio de la cola de eventos de perl/Tk, de modo que se maneje antes que cualquier otro evento ya en cola.
mark
Coloca el evento al principio de la cola de eventos de perl/Tk pero detrás de cualquier otro evento ya en cola con -when mark. Esta opción es útil al generar una serie de eventos que deben procesarse en orden pero al principio de la cola.
-x coord
Coord debe ser una distancia de pantalla; especifica el campo x para el evento. Válido para eventos KeyPress, KeyRelease, ButtonPress, ButtonRelease, Motion, Enter, Leave, Expose, Configure, Gravity y Reparent. Corresponde a la sustitución %x para scripts de enlace. Si Window está vacío, la coordenada es relativa a la pantalla y esta opción corresponde a la sustitución %X para scripts de enlace.
-y coord
Coord debe ser una distancia de pantalla; especifica el campo y para el evento. Válido para eventos KeyPress, KeyRelease, ButtonPress, ButtonRelease, Motion, Enter, Leave, Expose, Configure, Gravity y Reparent. Corresponde a la sustitución %y para scripts de enlace. Si Window está vacío, la coordenada es relativa a la pantalla y esta opción corresponde a la sustitución %Y para scripts de enlace.

Cualquier opción que no se especifique al generar un evento se rellenará con el valor 0, excepto serial, que se rellenará con el siguiente número de serie del evento X.

EJEMPLOS DE EVENTOS VIRTUALES

Para que se active una unión de evento virtual, deben ocurrir dos cosas. Primero, el evento virtual debe definirse con el método eventAdd. Segundo, se debe crear una unión para el evento virtual con el método bind. Considere las siguientes definiciones de eventos virtuales:

$widget->eventAdd('<<Paste>>' => '<Control-y>');
$widget->eventAdd('<<Paste>>' => '<Button-2>');
$widget->eventAdd('<<Save>>' => '<Control-X><Control-S>');
$widget->eventAdd('<<Save>>' => '<Shift-F12>');

En el método bind, un evento virtual se puede unir como cualquier otro tipo de evento integrado de la siguiente manera:

$entry->bind('Tk::Entry', '<<Paste>>' => sub {
               $entry->Insert($entry->selectionGet) });

Los dobles corchetes se utilizan para especificar que se está uniendo un evento virtual. Si el usuario escribe Control-y o presiona el botón 2, o si se sintetiza un evento virtual <<Paste>> con eventGenerate, se invocará la unión <<Paste>>.

Si una unión virtual tiene la misma secuencia exacta que una unión física separada, la unión física tendrá prioridad. Considere el siguiente ejemplo:

$mw->eventAdd('<<Paste>>' => '<Control-y>','<Meta-Control-y>');
$mw->bind('Tk::Entry', '<Control-y>' => sub{print 'Control-y'});
$mw->bind('Tk::Entry', '<<Paste>>'   => sub{print 'Paste'});

Cuando el usuario escribe Control-y, se invocará la unión <Control-y>, porque un evento físico se considera más específico que un evento virtual, si todo lo demás es igual. Sin embargo, cuando el usuario escribe Meta-Control-y, se invocará la unión <<Paste>>, porque el modificador Meta en el patrón físico asociado con la unión virtual es más específico que la secuencia <Control-y> para el evento físico.

Se pueden crear uniones en un evento virtual antes de que exista el evento virtual. De hecho, el evento virtual nunca necesita ser definido, por ejemplo, en plataformas donde el evento virtual específico sería insignificante o no se podría generar.

Cuando una definición de un evento virtual cambia en tiempo de ejecución, todas las ventanas responderán inmediatamente a la nueva definición. A partir del ejemplo anterior, si se ejecuta el siguiente código:

$entry->bind(ref($entry), '<Control-y>' => undef);
$entry->eventAdd('<<Paste>>' => '<Key-F6>');

el comportamiento cambiará de dos maneras. Primero, emergerá la unión sobrescrita <<Paste>>. Escribir Control-y ya no invocará la unión <Control-y>, sino el evento virtual <<Paste>>. Segundo, presionar la tecla F6 ahora también invocará la unión <<Paste>>.
