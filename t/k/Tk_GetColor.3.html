NOMBRE

Tk_AllocColorFromObj, Tk_GetColor, Tk_GetColorFromObj, Tk_GetColorByValue, Tk_NameOfColor, Tk_FreeColorFromObj, Tk_FreeColor - mantener base de datos de colores

ARGUMENTOS

Tcl_Interp *interp (entrada)
Intérprete para el reporte de errores.
Tk_Window tkwin (entrada)
Ventana en la cual se usará el color.
Tcl_Obj *objPtr (entrada/salida)
Valor de cadena que describe el color deseado; la representación interna se modificará para almacenar un puntero a (XColor *).
const char *name (entrada)
Descripción del color se pasa como una cadena, y el resultado (XColor *) no se almacena.
XColor *prefPtr (entrada)
Intensidades de rojo, verde y azul del color deseado.
XColor *colorPtr (entrada)
Puntero a información de color X. Debe haber sido asignado previamente por llamada a Tk_AllocColorFromObj, Tk_GetColor o Tk_GetColorByValue, excepto cuando se pasa a Tk_NameOfColor.
Drawable drawable (entrada)
Drawable en el cual el contexto de dibujo resultante se usará. Debe tener la misma pantalla y profundidad que la ventana para la cual se asignó el color.

DESCRIPCIÓN

Estos procedimientos gestionan los colores utilizados por una aplicación Tk. Permiten compartir colores cuando sea posible, preservando el espacio de colores, y eligen los colores más cercanos cuando el espacio de colores esté agotado.

Dada una descripción textual de un color, Tk_AllocColorFromObj localiza un valor de píxel que pueda usarse para renderizar el color en una ventana particular. El color deseado se especifica con un valor cuyo valor de cadena debe ser uno de los siguientes formatos:

colorname
Cualquier nombre válido de color definido en el archivo de base de datos de colores del servidor, como red o PeachPuff.
#RGB
#RRGGBB
#RRRGGGBBB
#RRRRGGGGBBBB
Una especificación numérica de las intensidades de rojo, verde y azul para mostrar el color. Cada R, G o B representa un dígito hexadecimal. Los cuatro formatos permiten especificar colores con 4 bits, 8 bits, 12 bits o 16 bits. Cuando se proporcionen menos de 16 bits por color, representan los bits más significativos del color, mientras que los bits de la parte inferior no especificada se repiten repetidamente desde los bits más altos disponibles. Por ejemplo, #3a7 es el mismo que #3333aaaa7777.

Tk_AllocColorFromObj devuelve un puntero a una estructura XColor; esta estructura indica las intensidades exactas del color asignado (que pueden diferir ligeramente de las solicitadas, dependiendo del límite de la pantalla). El valor de píxel que puede usarse para dibujar con el color en tkwin también se devuelve. Si ocurre un error en Tk_AllocColorFromObj (por ejemplo, un nombre de color desconocido), se devuelve NULL y un mensaje de error se almacena en el resultado de interp si interp no es NULL. Si el colormap de tkwin está lleno, Tk_AllocColorFromObj usará el color más cercano existente en el colormap. Tk_AllocColorFromObj almacena información sobre el valor devuelto en objPtr, lo que acelera futuras llamadas a procedimientos como Tk_AllocColorFromObj y Tk_GetColorFromObj.

Tk_GetColor es idéntico a Tk_AllocColorFromObj excepto que la descripción del color se pasa con una cadena en lugar de un valor. Esto evita que Tk_GetColor almacene el valor devuelto, por lo que Tk_GetColor es menos eficiente que Tk_AllocColorFromObj.

Tk_GetColorFromObj devuelve el token de un color existente, dado la ventana y la descripción utilizadas para crear el color. Tk_GetColorFromObj no realmente crea el color; el color debe haber sido creado previamente con una llamada a Tk_AllocColorFromObj o Tk_GetColor. El valor devuelto se almacena en objPtr, acelerando futuras llamadas a Tk_GetColorFromObj con el mismo objPtr y tkwin.

Tk_GetColorByValue es similar a Tk_GetColor excepto que el color deseado se indica con los campos red, green, y blue de la estructura apuntada por colorPtr.

Este paquete mantiene una base de datos de todos los colores en uso actualmente. Si se solicita múltiples veces el mismo color desde Tk_GetColor o Tk_AllocColorFromObj (por ejemplo, por diferentes ventanas), o si se solicita múltiples veces las mismas intensidades desde Tk_GetColorByValue, se reutilizan los valores de píxel existentes. Reutilizar un valor de píxel evita cualquier interacción con el servidor de ventanas, lo que hace que la asignación sea mucho más eficiente. Estos procedimientos también ofrecen una interfaz portátil que funciona en todas las plataformas. Por este motivo, se debería generalmente usar Tk_AllocColorFromObj, Tk_GetColor o Tk_GetColorByValue en lugar de procedimientos de nivel inferior como XAllocColor.

Dado que diferentes llamadas a este paquete pueden devolver el mismo valor de píxel compartido, los usuarios deben nunca cambiar el color de un píxel devuelto por los procedimientos. Si se necesita cambiar dinámicamente el valor de color, se debe usar XAllocColorCells para asignar el valor de píxel del color.

El procedimiento Tk_NameOfColor es aproximadamente el inverso de Tk_GetColor. Si su argumento colorPtr fue creado por Tk_AllocColorFromObj o Tk_GetColor, el valor devuelto es la cadena usada para crear el color. Si colorPtr fue creado por una llamada a Tk_GetColorByValue o por cualquier otro mecanismo, el valor devuelto es una cadena que podría ser pasada a Tk_GetColor para devolver el mismo color. Nota: el valor devuelto por Tk_NameOfColor solo está garantizado hasta la siguiente llamada a Tk_NameOfColor.

Tk_GCForColor devuelve un contexto de dibujo cuyo campo foreground es el píxel asignado para colorPtr, y los campos restantes tienen valores por defecto. Esto proporciona una forma fácil de hacer dibujo con un color. El contexto de dibujo se almacena con el color y existirá solo mientras colorPtr exista; se libera cuando la última referencia a colorPtr se libera llamando a Tk_FreeColor.

Cuando un color ya no es necesario, Tk_FreeColorFromObj o Tk_FreeColor debe llamarse para liberarlo. Para Tk_FreeColorFromObj, el color a liberar se especifica con la misma información que se usó para crearlo; para Tk_FreeColor, el color a liberar se especifica con un puntero a su estructura de XColor. Deben haber exactamente una llamada a Tk_FreeColorFromObj o Tk_FreeColor por cada llamada a Tk_AllocColorFromObj, Tk_GetColor, o Tk_GetColorByValue.
