NOMBRE

Tk_FindPhoto, Tk_PhotoPutBlock, Tk_PhotoPutZoomedBlock, Tk_PhotoGetImage, Tk_PhotoBlank, Tk_PhotoExpand, Tk_PhotoGetSize, Tk_PhotoSetSize - manipular los datos de imagen almacenados en una imagen de foto.

ARGUMENTOS

Tcl_Interp *interp (entrada)
Intérprete en el que se creó la imagen y en el que se deben informar los errores.
const char *imageName (entrada)
Nombre de la imagen de foto.
Tk_PhotoHandle handle (entrada)
Identificador opaco que identifica la imagen de foto a la que se va a afectar.
Tk_PhotoImageBlock *blockPtr (entrada)
Especifica la dirección y el diseño del almacenamiento de los datos de imagen.
int x (entrada)
Especifica la coordenada X donde se colocará la esquina superior izquierda del bloque dentro de la imagen.
int y (entrada)
Especifica la coordenada Y donde se colocará la esquina superior izquierda del bloque dentro de la imagen.
int width (entrada)
Especifica el ancho del área de imagen que se verá afectada (para Tk_PhotoPutBlock) o el ancho de imagen deseado (para Tk_PhotoExpand y Tk_PhotoSetSize).
int compRule (entrada)
Especifica la regla de composición utilizada al combinar píxeles transparentes en un bloque de datos con una imagen de foto. Debe ser una de TK_PHOTO_COMPOSITE_OVERLAY (que coloca el bloque de datos sobre la imagen de foto existente, permitiendo que el contenido anterior se vea a través de los bits transparentes) o TK_PHOTO_COMPOSITE_SET (que descarta el contenido de la imagen de foto existente en el rectángulo que cubre el bloque de datos).
int height (entrada)
Especifica la altura del área de imagen que se verá afectada (para Tk_PhotoPutBlock) o la altura de imagen deseada (para Tk_PhotoExpand y Tk_PhotoSetSize).
int *widthPtr (salida)
Puntero a la ubicación donde se almacenará el ancho de la imagen.
int *heightPtr (salida)
Puntero a la ubicación donde se almacenará la altura de la imagen.
int subsampleX (entrada)
Especifica el factor de submuestreo en la dirección X para los datos de imagen de entrada.
int subsampleY (entrada)
Especifica el factor de submuestreo en la dirección Y para los datos de imagen de entrada.
int zoomX (entrada)
Especifica el factor de zoom que se aplicará en la dirección X a los píxeles que se escriben en la imagen de foto.
int zoomY (entrada)
Especifica el factor de zoom que se aplicará en la dirección Y a los píxeles que se escriben en la imagen de foto.

DESCRIPCIÓN

Tk_FindPhoto devuelve un identificador opaco que se utiliza para identificar una imagen de foto específica a los otros procedimientos. El parámetro es el nombre de la imagen, es decir, el nombre especificado al comando image create photo, o asignado por ese comando si no se especificó ningún nombre. Si imageName no existe o no es una imagen de foto, Tk_FindPhoto devuelve NULL.

Tk_PhotoPutBlock se utiliza para suministrar bloques de datos de imagen para su visualización. La llamada afecta a un área de la imagen de tamaño width x height píxeles, con su esquina superior izquierda en las coordenadas (x,y). Todos los valores width, height, x e y deben ser no negativos. Si parte de esta área se encuentra fuera de los límites actuales de la imagen, la imagen se ampliará para incluir el área, a menos que el usuario haya especificado un tamaño de imagen explícito con las opciones de configuración del widget -width y/o -height (ver photo(n)); en ese caso, el área se recortará silenciosamente a los límites de la imagen.

El parámetro block es un puntero a una estructura Tk_PhotoImageBlock, definida de la siguiente manera:

typedef struct {
    unsigned char *pixelPtr;
    int width;
    int height;
    int pitch;
    int pixelSize;
    int offset[4];
} Tk_PhotoImageBlock;
El campo pixelPtr apunta al primer píxel, es decir, al píxel superior izquierdo del bloque. Los campos width y height especifican las dimensiones del bloque de píxeles. El campo pixelSize especifica la diferencia de dirección entre dos píxeles horizontalmente adyacentes. Debe ser 4 para datos de imagen RGB y 2 para datos de imagen en escala de grises. Son posibles otros valores, si los desplazamientos en la matriz offset se ajustan en consecuencia (por ejemplo, para datos rojos, verdes y azules almacenados en planos diferentes). Sin embargo, este diseño se desaconseja encarecidamente. Debido a un error, es posible que no funcione correctamente si se proporciona un canal alfa. (ver la sección ERRORES a continuación). El campo pitch especifica la diferencia de dirección entre dos píxeles verticalmente adyacentes. La matriz offset contiene los desplazamientos desde la dirección de un píxel hasta las direcciones de los bytes que contienen los componentes rojo, verde, azul y alfa (transparencia). Si los desplazamientos para rojo, verde y azul son iguales, la imagen se interpreta como en escala de grises. Si difieren, se asumen datos RGB. Normalmente, los desplazamientos serán 0, 1, 2, 3 para datos RGB y 0, 0, 0, 1 para escala de grises. Es posible proporcionar datos de imagen sin canal alfa estableciendo el desplazamiento del alfa a un valor negativo y ajustando el campo pixelSize en consecuencia. Sin embargo, este uso se desaconseja (ver la sección ERRORES a continuación).

El parámetro compRule de Tk_PhotoPutBlock especifica una regla de composición que indica qué hacer con los píxeles transparentes. El valor TK_PHOTO_COMPOSITE_OVERLAY indica que el contenido anterior de la imagen de foto debe verse a través, y el valor TK_PHOTO_COMPOSITE_SET indica que el contenido anterior de la imagen de foto debe ser completamente ignorado, y los valores del bloque se copian directamente. El comportamiento en Tk8.3 y anteriores era equivalente a tener TK_PHOTO_COMPOSITE_OVERLAY como regla de composición.

Los valores dados para los parámetros width y height de Tk_PhotoPutBlock no tienen que corresponder a los valores especificados en block. Si son más pequeños, Tk_PhotoPutBlock extrae un sub-bloque de los datos de imagen proporcionados. Si son más grandes, los datos proporcionados se replican (de forma repetida) para llenar el área especificada. Estas reglas operan de forma independiente en las direcciones horizontal y vertical.

Tk_PhotoPutBlock normalmente devuelve TCL_OK, aunque si no puede asignar suficiente memoria para contener la imagen resultante, devuelve TCL_ERROR y, si el argumento interp no es NULL, se coloca un mensaje de error en el resultado del intérprete.

Tk_PhotoPutZoomedBlock funciona como Tk_PhotoPutBlock excepto que la imagen puede reducirse o ampliarse para su visualización. Los parámetros subsampleX e subsampleY permiten reducir el tamaño de la imagen mediante submuestreo. Tk_PhotoPutZoomedBlock utilizará solo los píxeles de la imagen de entrada cuyas coordenadas X sean múltiplos de subsampleX, y cuyas coordenadas Y sean múltiplos de subsampleY. Por ejemplo, una imagen de 512x512 píxeles se puede reducir a 256x256 estableciendo subsampleX e subsampleY a 2.

Los parámetros zoomX y zoomY permiten ampliar la imagen mediante la replicación de píxeles. Cada píxel de la imagen de entrada (posiblemente submuestreada) se escribirá en un bloque de zoomX píxeles de ancho y zoomY píxeles de alto de la imagen mostrada. Se pueden usar el submuestreo y el zoom juntos para efectos especiales.

Tk_PhotoGetImage se puede utilizar para recuperar datos de imagen de una imagen de foto. Tk_PhotoGetImage rellena la estructura apuntada por el parámetro blockPtr con valores que describen la dirección y el diseño de los datos de imagen que la imagen de foto tiene almacenados internamente. Los valores son válidos hasta que la imagen se destruye o se cambia su tamaño.

Es posible modificar una imagen escribiendo directamente en los datos a los que apunta el campo pixelPtr. Sin embargo, el tamaño de la imagen no se puede cambiar de esta manera. Además, los cambios realizados al escribir directamente en pixelPtr no serán visibles de inmediato, sino solo después de una llamada a Tk_ImageChanged o después de un evento que haga que los widgets interesados se redibujen. Tk_FindPhoto, Tk_PhotoPutBlock, Tk_PhotoPutZoomedBlock, Tk_PhotoGetImage, Tk_PhotoBlank, Tk_PhotoExpand, Tk_PhotoSetSize, Tk_PhotoGetSize - manipulate Tk photo image objects

SYNOPSIS

#include <tk.h>
Tk_Image Tk_FindPhoto(Tcl_Interp *interp, const char *name);
int Tk_PhotoPutBlock(Tcl_Interp *interp, Tk_Image image,
        const TkPhotoImageBlock *blockPtr, int offsetBlue, int offsetGreen,
        int offsetRed, int offsetGray, int offsetReversed, int pixelSize,
        int width, int height);
int Tk_PhotoPutZoomedBlock(Tcl_Interp *interp, Tk_Image image,
        const TkPhotoImageBlock *blockPtr, int offsetBlue, int offsetGreen,
        int offsetRed, int offsetGray, int offsetReversed, int pixelSize,
        int width, int height, int subsampleDivide, int subsampleShift);
int Tk_PhotoGetImage(Tcl_Interp *interp, Tk_Image image,
        TkPhotoImageBlock *blockPtr);
void Tk_PhotoBlank(Tk_Image image);
int Tk_PhotoExpand(Tcl_Interp *interp, Tk_Image image, int width, int height);
int Tk_PhotoSetSize(Tcl_Interp *interp, Tk_Image image, int width, int height);
void Tk_PhotoGetSize(Tk_Image image, int *widthPtr, int *heightPtr);

ARGUMENTS

interp (in)
Interpreter to use for error reporting. Can be NULL.
name (in)
Name of the photo image.
image (in)
Identifier for the photo image, obtained from Tk_FindPhoto or created by the `image create photo` command.
blockPtr (in)
Pointer to a TkPhotoImageBlock structure describing the image data. The data in the block must be in row-major order. The block structure is defined in tk.h as:
typedef struct TkPhotoImageBlock {
    char *pixelPtr;          /* Pointer to the start of the pixel data. */
    char *pitchPtr;          /* Pointer to the start of the next row. */
    char *planePtr;          /* Pointer to the start of the plane. */
    Tcl_Obj *pixelFormatObj; /* For non-standard pixel formats (e.g. RGB, RGBA, GRAY).
                                 NULL for standard formats. */
} TkPhotoImageBlock;
offsetBlue (in)
Offset in bytes from the start of a pixel to the blue component. Use -1 if there is no blue component.
offsetGreen (in)
Offset in bytes from the start of a pixel to the green component. Use -1 if there is no green component.
offsetRed (in)
Offset in bytes from the start of a pixel to the red component. Use -1 if there is no red component.
offsetGray (in)
Offset in bytes from the start of a pixel to the grayscale component. Use -1 if there is no grayscale component.
offsetReversed (in)
Offset in bytes from the start of a pixel to the alpha component. Use -1 if there is no alpha component. The alpha value is interpreted as 0 for fully transparent and 255 for fully opaque.
pixelSize (in)
The number of bytes per pixel. This should be large enough to contain all the specified offsets.
width (in)
The width of the pixel data in the block. This is the number of pixels in each row.
height (in)
The height of the pixel data in the block. This is the number of rows.
subsampleDivide (in)
Used by Tk_PhotoPutZoomedBlock to specify the width of the source image being passed in the block. The actual width of the block is `width*subsampleDivide`.
subsampleShift (in)
Used by Tk_PhotoPutZoomedBlock to specify the height of the source image being passed in the block. The actual height of the block is `height*subsampleShift`.
widthPtr (out)
Location to store the width of the photo image.
heightPtr (out)
Location to store the height of the photo image.

DESCRIPTION

These procedures are used to create and manipulate Tk photo image objects. Photo images are useful for displaying images that are generated programmatically, such as the output of an image processing algorithm.

Tk_FindPhoto returns the Tk_Image handle for the photo image named name. If no such image exists, it returns the handle for a newly created photo image with that name. An error is returned if name is invalid or if the interpreter is unable to create the image.

Tk_PhotoPutBlock copies image data from the TkPhotoImageBlock structure pointed to by blockPtr into the photo image identified by image. The data in the block is assumed to be a section of a larger image. The arguments offsetBlue, offsetGreen, offsetRed, offsetGray, and offsetReversed specify the byte offsets from the start of a pixel to each color component (or alpha, for offsetReversed). pixelSize is the total number of bytes per pixel. width and height are the dimensions of the block in pixels. If the photo image is smaller than the block being supplied, it is automatically expanded. The photo image is automatically resized to accommodate the supplied block. Note that the photo image is cleared before the block is put into it; if you want to assemble an image from multiple blocks, use Tk_PhotoExpand or Tk_PhotoSetSize first, then use Tk_PhotoPutBlock multiple times.

Tk_PhotoPutZoomedBlock is similar to Tk_PhotoPutBlock, but it is intended for use when the data in the block has been subsampled. The subsampleDivide and subsampleShift arguments specify the width and height of the source image being passed in the block. The width and height arguments specify the width and height of the block being passed in pixels.

Tk_PhotoGetImage retrieves image data from the photo image identified by image. It returns the data in the structure pointed to by blockPtr. If the photo image is empty, blockPtr is filled with NULL pointers and zero dimensions. The caller is responsible for freeing the memory pointed to by blockPtr->pixelPtr, blockPtr->pitchPtr, and blockPtr->planePtr after use. The caller should also set the pixelFormatObj to NULL if it is not needed.

Tk_PhotoBlank blanks the entire area of the photo image. Blank areas of a photo image are transparent.

Tk_PhotoExpand requests that the widget's image be expanded to be at least width x height pixels in size. The width and/or height are unchanged if the user has specified an explicit image width or height with the -width and/or -height configuration options, respectively. If the image data are being supplied in many small blocks, it is more efficient to use Tk_PhotoExpand or Tk_PhotoSetSize at the beginning rather than allowing the image to expand in many small increments as image blocks are supplied.

Tk_PhotoExpand normally returns TCL_OK, though if it cannot allocate sufficient memory to hold the resulting image, TCL_ERROR is returned instead and, if the interp argument is non-NULL, an error message is placed in the interpreter's result.

Tk_PhotoSetSize specifies the size of the image, as if the user had specified the given width and height values to the -width and -height configuration options. A value of zero for width or height does not change the image's width or height, but allows the width or height to be changed by subsequent calls to Tk_PhotoPutBlock, Tk_PhotoPutZoomedBlock or Tk_PhotoExpand.

Tk_PhotoSetSize normally returns TCL_OK, though if it cannot allocate sufficient memory to hold the resulting image, TCL_ERROR is returned instead and, if the interp argument is non-NULL, an error message is placed in the interpreter's result.

Tk_PhotoGetSize returns the dimensions of the image in *widthPtr and *heightPtr.

PORTABILITY

In Tk 8.3 and earlier, Tk_PhotoPutBlock and Tk_PhotoPutZoomedBlock had different signatures. If you want to compile code that uses the old interface against 8.4 without updating your code, compile it with the flag -DUSE_COMPOSITELESS_PHOTO_PUT_BLOCK. Code linked using Stubs against older versions of Tk will continue to work.

In Tk 8.4, Tk_PhotoPutBlock, Tk_PhotoPutZoomedBlock, Tk_PhotoExpand and Tk_PhotoSetSize did not take an interp argument or return any result code. If insufficient memory was available for an image, Tk would panic. This behaviour is still supported if you compile your extension with the additional flag -DUSE_PANIC_ON_PHOTO_ALLOC_FAILURE. Code linked using Stubs against older versions of Tk will continue to work.

BUGS

The Tk_PhotoImageBlock structure used to provide image data to Tk_PhotoPutBlock promises great flexibility in the layout of the data (e.g. separate planes for the red, green, blue and alpha channels). Unfortunately, the implementation fails to hold this promise. The problem is that the pixelSize field is (incorrectly) used to determine whether the image has an alpha channel. Currently, if the offset for the alpha channel is greater than or equal to pixelSize, tk_PhotoPutblock assumes no alpha data is present and makes the image fully opaque. This means that for layouts where the channels are separate (or any other exotic layout where pixelSize has to be smaller than the alpha offset), the alpha channel will not be read correctly. In order to be on the safe side if this issue will be corrected in a future release, it is strongly recommended you always provide alpha data - even if the image has no transparency - and only use the "standard" layout with a pixelSize of 2 for grayscale and 4 for RGB data with offsets of 0, 0, 0, 1 or 0, 1, 2, 3 respectively.
