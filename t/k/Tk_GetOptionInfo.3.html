Tk_GetOptionInfo(3) Procedimientos de la biblioteca Tk Tk_GetOptionInfo(3)

NOMBRE

Tk_CreateOptionTable, Tk_DeleteOptionTable, Tk_InitOptions, Tk_SetOptions, Tk_FreeSavedOptions, Tk_RestoreSavedOptions, Tk_GetOptionValue, Tk_GetOptionInfo, Tk_FreeConfigOptions, Tk_Offset - procesamiento de opciones de configuración

SINOPSIS

#include <tk.h>

Tk_CreateOptionTable(interp, templatePtr)

Tk_DeleteOptionTable(optionTable)

int
Tk_InitOptions(interp, recordPtr, optionTable, tkwin)

int
Tk_SetOptions(interp, recordPtr, optionTable, objc, objv, tkwin, savePtr, maskPtr)

Tk_FreeSavedOptions(savedPtr)

Tk_RestoreSavedOptions(savedPtr)

Tcl_Obj *
Tk_GetOptionValue(interp, recordPtr, optionTable, namePtr, tkwin)

Tk_GetOptionInfo(interp, recordPtr, optionTable, namePtr, tkwin)

ARGUMENTOS

Tcl_Interp *interp (in)
Un intérprete Tcl. La mayoría de las funciones solo usan este valor para devolver mensajes de error; si es NULL, entonces no se devuelven mensajes de error. Para Tk_CreateOptionTable, el valor no puede ser NULL; da el intérprete en el cual se utilizará la tabla de opciones.
const Tk_OptionSpec *templatePtr (in)
Punta a un arreglo estático que describe las opciones de configuración que se soportan. Se usa para construir un Tk_OptionTable. El valor al que apunta este argumento debe existir durante la vida de Tk_OptionTable.
Tk_OptionTable optionTable (in)
Token de una tabla de opciones. Debe haber sido devuelto por una llamada previa a Tk_CreateOptionTable.
char *recordPtr (in/out)
Punta a un registro en el cual se almacenan los valores de opciones de configuración; los campos de este registro son modificados por procedimientos como Tk_SetOptions y leídos por procedimientos como Tk_GetOptionValue.
Tk_Window tkwin (in)
Para opciones como TK_OPTION_COLOR, este argumento indica la ventana en la cual se usará la opción. Si optionTable no usa opciones dependientes de ventanas, puede ser NULL para este argumento.
int objc (in)
Número de valores en objv.
Tcl_Obj *const *objv (in)
Argumentos de línea de comandos para configurar opciones.
Tk_SavedOptions *savePtr (out)
Si no es NULL, el valor al que apunta este argumento se llena con los valores antiguos de las opciones modificadas y se restauran automáticamente si ocurre un error en Tk_SetOptions.
int *maskPtr (out)
Si no es NULL, el valor al que apunta maskPtr se llena con el OR bit a bit de los typeMask para las opciones modificadas.
Tk_SavedOptions *savedPtr (in/out)
Punta a una estructura previamente llenada por Tk_SetOptions con los valores antiguos de las opciones modificadas.
Tcl_Obj *namePtr (in)
El valor de este objeto es el nombre de una opción específica. Si se pasa NULL a Tk_GetOptionInfo, se devuelve información para todas las opciones. No debe ser NULL cuando se llame a Tk_GetOptionValue.
tipo type (in)
El nombre del tipo de un registro.
campo field (in)
El nombre de un campo en los registros del tipo type. El valor de este campo se almacena en el registro del widget.

DESCRIPCIÓN

Estas funciones manejan la mayoría de los detalles de la interpretación de opciones de configuración como las que se usan en los widgets de Tk. Dado una descripción de qué opciones se soportan, estas funciones manejan todos los detalles de la interpretación de opciones y su almacenamiento en una estructura C asociada al widget u objeto. Estas funciones fueron diseñadas principalmente para widgets de Tk, pero también pueden usarse para otros tipos de objetos que tengan opciones de configuración. En el resto de esta página de manual, el término "widget" se usará para referirse al objeto cuyas opciones se están gestionando; en la práctica, el objeto no necesariamente es un widget. El término "registro de widget" se usará para referirse a la estructura C en la cual se almacena la información sobre un widget u objeto específico.

Nota: La forma más fácil de aprender cómo usar estas funciones es ver un ejemplo de uso funcional. En Tk, el ejemplo más simple es el código que implementa la familia de widgets de botón, que está en tkButton.c. Otros ejemplos están en tkSquare.c y tkMenu.c.

Para usar estas funciones, el código que implementa el widget debe contener un arreglo estático de estructuras Tk_OptionSpec. Esto es una plantilla que describe las diversas opciones soportadas por esta clase de widget; hay una plantilla separada para cada tipo de widget. La plantilla contiene información como el nombre de cada opción, su tipo, su valor por defecto y dónde se almacena el valor de la opción en el registro del widget. Para más detalles, véase la sección PLANTILLAS.

Para procesar opciones de configuración de manera eficiente, la plantilla estática debe ser ampliada con información adicional que se puede obtener solo en tiempo de ejecución. La función Tk_CreateOptionTable crea esta información dinámica a partir de la plantilla y devuelve un token de Tk_OptionTable que describe tanto la información estática como la dinámica. Todas las otras funciones, como Tk_SetOptions, reciben un token de Tk_OptionTable como argumento. En general, Tk_CreateOptionTable se llama la primera vez que se crea un widget de una clase específica y el resultado es usado en futuros widgets de esa clase. Una tabla de opciones puede ser usada solo en un único intérprete, dado por el argumento interp de Tk_CreateOptionTable. Cuando una tabla de opciones ya no es necesaria, Tk_DeleteOptionTable debe llamarse para liberar todos sus recursos. Todas las tablas de opciones de un intérprete se liberan automáticamente si el intérprete se elimina.

Tk_InitOptions se llama cuando se crea un nuevo widget para establecer los valores por defecto. Tk_InitOptions recibe un token de tabla de opciones (optionTable) y un puntero a un registro de widget (recordPtr), que es la estructura C que contiene la información sobre este widget. Tk_InitOptions usa la información en el token de tabla de opciones para elegir un valor por defecto adecuado para cada opción, luego almacena el valor por defecto directamente en el registro del widget, sobrescribiendo cualquier información previamente almacenada en el registro. Tk_InitOptions normalmente devuelve TCL_OK. Si ocurre un error al establecer los valores por defecto (por ejemplo, debido a un valor erróneo como el valor por defecto), entonces TCL_ERROR se devuelve y un mensaje de error se deja en el resultado de interp si interp no es NULL. Para cualquier opción de configuración de un widget que tenga TK_OPTION_DONT_SET_DEFAULT establecido en su campo flags, la inicialización anterior se omite por completo, como se describe más adelante.

Tk_SetOptions se llama para modificar opciones de configuración basadas en la información especificada en un comando Tcl. El comando puede ser uno que crea un nuevo widget, o uno que modifica las opciones de un widget existente. Los argumentos objc y objv describen los valores de los argumentos del comando Tcl. Objv debe contener un número par de objetos: el primer objeto de cada par da el nombre de una opción y el segundo objeto da el nuevo valor para esa opción. Tk_SetOptions busca cada nombre en optionTable, verifica que el valor nuevo de la opción se ajuste al tipo en optionTable y almacena el valor de la opción en el registro del widget dado por recordPtr. Tk_SetOptions normalmente devuelve TCL_OK. Si ocurre un error (por ejemplo, nombre de opción desconocido o valor de opción ilegal), entonces TCL_ERROR se devuelve y un mensaje de error se deja en el resultado de interp si interp no es NULL.

Tk_SetOptions tiene dos características adicionales. Primero, si el argumento maskPtr no es NULL, apunta a un valor entero que se llena con información sobre las opciones modificadas. Para cada opción en la plantilla que se pasa a Tk_CreateOptionTable hay un campo typeMask. Los bits de este campo son definidos por el código que implementa el widget; por ejemplo, cada bit puede corresponder a una opción de configuración específica. Alternativamente, los bits pueden usarse funcionalmente. Por ejemplo, un bit puede usarse para el redibujado: todas las opciones que afectan la visualización de un widget, como cambiar la opción requiere redibujar el widget, pueden tener este bit establecido. Otro bit puede indicar que la geometría del widget debe recalcularse, y así sucesivamente. Tk_SetOptions ORea juntas las typeMask de cada opción modificada.

Segundo, si el argumento savePtr no es NULL, apunta a una estructura Tk_SavedOptions que se llena con los valores antiguos de las opciones que se modifican. Si Tk_SetOptions devuelve TCL_ERROR, entonces el código de llamada puede usar Tk_RestoreSavedOptions para restaurar las opciones a sus valores antiguos. Si Tk_SetOptions devuelve TCL_OK, entonces el código de llamada puede usar Tk_FreeSavedOptions para liberar la memoria que se usa para almacenar los valores antiguos.

Tk_GetOptionValue se llama para obtener el valor actual de una opción de configuración específica. El valor se devuelve como un objeto Tcl (Tcl_Obj *). Si ocurre un error, o si la opción no está definida, se devuelve NULL.

Tk_GetOptionInfo se llama para obtener información sobre una opción de configuración. El valor devuelto es un objeto Tcl que contiene una lista de valores. El primer elemento de la lista es el nombre de la opción, seguido del tipo, el valor por defecto, el valor actual y el valor si se usa un valor por defecto. Si namePtr es NULL, se devuelve una lista de listas, una para cada opción de configuración.

Tk_FreeConfigOptions se llama para liberar todos los recursos que se han asignado para las opciones de un widget específico. Esto se llama típicamente cuando se destruye un widget.

Tk_Offset es una macro útil que se usa para calcular el desplazamiento de un campo dentro de una estructura. Devuelve el número de bytes desde el inicio de la estructura hasta el campo dado. El tipo de la estructura y el nombre del campo se pasan como argumentos. Por ejemplo, Tk_Offset(MyStruct, myField) devuelve el desplazamiento de myField dentro de MyStruct. Esto se usa para especificar dónde se deben almacenar las opciones en el registro del widget.

PLANTILLAS

Cada función que toma un optionTable también toma un argumento templatePtr. Este es un arreglo estático de estructuras Tk_OptionSpec, que se usa para especificar el conjunto de opciones de configuración disponibles para un widget u otro objeto. El arreglo debe terminar con una entrada nula. Cada entrada en el arreglo tiene el siguiente formato:

struct Tk_OptionSpec { const char *name; /* Nombre de la opción. */ const char * dbName; /* Nombre de la base de datos X (opcional). */ int type; /* Tipo de opción. */ int offset; /* Desplazamiento en el registro del widget. */ const char * defaultValue; /* Valor por defecto. */ Tcl_Obj *(*parse)(); /* Procedimiento de análisis (opcional). */ void (*free)(); /* Procedimiento de liberación (opcional). */ int flags; /* Banderas (ver abajo). */ int typeMask; /* Máscara de tipo para enmascarar el resultado de Tk_SetOptions. */ };

name
El nombre de la opción de configuración, como se usa en Tcl (por ejemplo, "background"). El nombre debe ser un identificador Tcl válido. Debe ser el mismo que el nombre usado en el comando configure.
dbName
Si no es NULL, este es el nombre de la opción tal como se usa en la base de datos X (por ejemplo, "background"). Si es NULL, entonces el valor de name se usa también para el nombre de la base de datos X.
type
Especifica el tipo de la opción. Tk proporciona tipos predefinidos como TK_OPTION_BOOLEAN, TK_OPTION_INT, TK_OPTION_DOUBLE, TK_OPTION_STRING, TK_OPTION_FONT, TK_OPTION_COLOR, TK_OPTION_PIXELS, TK_OPTION_BITMAP, TK_OPTION_RELIEF, TK_OPTION_JUSTIFY, TK_OPTION_COMMAND, y TK_OPTION_SPECIFIED_STRING. Si un tipo específico no está disponible, se puede usar TK_OPTION_CUSTOM y proporcionar procedimientos de análisis y liberación personalizados. Si el tipo es TK_OPTION_NULL_OK, entonces se permite que el valor de la opción sea el valor nulo de Tcl. Si se usa una combinación de tipos, se usan las operaciones OR bit a bit. Por ejemplo, TK_OPTION_FONT | TK_OPTION_NULL_OK permite que una fuente o un valor nulo sean especificados.
offset
El desplazamiento en bytes desde el inicio del registro del widget hasta el campo donde se debe almacenar el valor de esta opción. Esto se calcula normalmente usando la macro Tk_Offset.
defaultValue
Una cadena que representa el valor por defecto de la opción. Este valor se usa cuando la opción no se especifica en el comando de configuración. El valor se analiza usando el procedimiento de análisis para el tipo dado.
parse
Si no es NULL, este es un puntero a un procedimiento que se llama para analizar el valor de la opción. Se usa para tipos personalizados ( TK_OPTION_CUSTOM). El procedimiento tiene la siguiente firma: 
Tcl_Obj *parse(interp, value, tkwin)
    Tcl_Interp *interp;
    Tcl_Obj *value;
    Tk_Window tkwin;
El procedimiento debe devolver un objeto Tcl que represente el valor analizado, o NULL si ocurre un error.
free
Si no es NULL, este es un puntero a un procedimiento que se llama para liberar cualquier recurso que haya sido asignado por el procedimiento de análisis. Se usa para tipos personalizados. El procedimiento tiene la siguiente firma: 
void free(interp, objPtr, tkwin)
    Tcl_Interp *interp;
    Tcl_Obj *objPtr;
    Tk_Window tkwin;
El procedimiento debe liberar los recursos asociados con el objeto Tcl dado.
flags
Banderas que modifican el comportamiento de la opción. Las banderas disponibles son:
TK_OPTION_NULL_OK
Permite que el valor de la opción sea el valor nulo de Tcl.
TK_OPTION_AUTOSCALE
La opción se escala automáticamente según la configuración de DPI del sistema.
TK_OPTION_FILE_NAME
La opción es un nombre de archivo. Tk realizará una búsqueda de ruta si la opción no se puede abrir.
TK_OPTION_DIR_NAME
La opción es un nombre de directorio.
TK_OPTION_SYNONYM
Esta entrada es un sinónimo de otra opción. El campo offset debe contener un puntero a la entrada de la opción de la que es sinónimo.
TK_OPTION_DOC_ONLY
La opción solo se usa para la documentación y no se procesa realmente.
TK_OPTION_IMPLICIT_BIT
Esta opción se establece implícitamente cuando se establece otra opción. El campo offset contiene el índice de la opción implicada.
TK_OPTION_NEGATIVE_PIXELS
Permite valores negativos para opciones de píxeles.
TK_OPTION_USER_BIT
Un bit de usuario que puede ser utilizado por la aplicación.
Las banderas se pueden combinar usando operaciones OR bit a bit.
typeMask
Una máscara de bits que se usa para notificar a la aplicación sobre los cambios en las opciones. Cada bit en la máscara puede corresponder a una acción específica que debe realizarse cuando la opción cambia (por ejemplo, redibujar el widget, cambiar la geometría, etc.).

The second additional feature of Tk_SetOptions has to do with error recovery. If an error occurs while processing configuration options, this feature makes it possible to restore all the configuration options to their previous values. Errors can occur either while processing options in Tk_SetOptions or later in the caller. In many cases the caller does additional processing after Tk_SetOptions returns; for example, it might use an option value to set a trace on a variable and may detect an error if the variable is an array instead of a scalar. Error recovery is enabled by passing in a non-NULL value for the savePtr argument to Tk_SetOptions; this should be a pointer to an uninitialized Tk_SavedOptions structure on the caller's stack. Tk_SetOptions overwrites the structure pointed to by savePtr with information about the old values of any options modified by the procedure. If Tk_SetOptions returns successfully, the caller uses the structure in one of two ways. If the caller completes its processing of the new options without any errors, then it must pass the structure to Tk_FreeSavedOptions so that the old values can be freed. If the caller detects an error in its processing of the new options, then it should pass the structure to Tk_RestoreSavedOptions, which will copy the old values back into the widget record and free the new values. If Tk_SetOptions detects an error then it automatically restores any options that had already been modified and leaves *savePtr in an empty state: the caller need not call either Tk_FreeSavedOptions or Tk_RestoreSavedOptions. If the savePtr argument to Tk_SetOptions is NULL then Tk_SetOptions frees each old option value immediately when it sets a new value for the option. In this case, if an error occurs in the third option, the old values for the first two options cannot be restored.

Tk_GetOptionValue returns the current value of a configuration option for a particular widget. The namePtr argument contains the name of an option; Tk_GetOptionValue uses optionTable to lookup the option and extract its value from the widget record pointed to by recordPtr, then it returns an object containing that value. If an error occurs (e.g., because namePtr contains an unknown option name) then NULL is returned and an error message is left in interp's result unless interp is NULL.

Tk_GetOptionInfo returns information about configuration options in a form suitable for configure widget commands. If the namePtr argument is not NULL, it points to an object that gives the name of a configuration option; Tk_GetOptionInfo returns an object containing a list with five elements, which are the name of the option, the name and class used for the option in the option database, the default value for the option, and the current value for the option. If the namePtr argument is NULL, then Tk_GetOptionInfo returns information about all options in the form of a list of lists; each sublist describes one option. Synonym options are handled differently depending on whether namePtr is NULL: if namePtr is NULL then the sublist for each synonym option has only two elements, which are the name of the option and the name of the other option that it refers to; if namePtr is non-NULL and names a synonym option then the object returned is the five-element list for the other option that the synonym refers to. If an error occurs (e.g., because namePtr contains an unknown option name) then NULL is returned and an error message is left in interp's result unless interp is NULL.

Tk_FreeConfigOptions must be invoked when a widget is deleted. It frees all of the resources associated with any of the configuration options defined in recordPtr by optionTable.

The Tk_Offset macro is provided as a safe way of generating the objOffset and internalOffset values for entries in Tk_OptionSpec structures. It takes two arguments: the name of a type of record, and the name of a field in that record. It returns the byte offset of the named field in records of the given type.

PLANTILLAS

The array of Tk_OptionSpec structures passed to Tk_CreateOptionTable via its templatePtr argument describes the configuration options supported by a particular class of widgets. Each structure specifies one configuration option and has the following fields:

typedef struct {
    Tk_OptionType type;
    const char *optionName;
    const char *dbName;
    const char *dbClass;
    const char *defValue;
    int objOffset;
    int internalOffset;
    int flags;
    const void *clientData;
    int typeMask;
} Tk_OptionSpec;
The type field indicates what kind of configuration option this is (e.g. TK_OPTION_COLOR for a color value, or TK_OPTION_INT for an integer value). Type determines how the value of the option is parsed (more on this below). The optionName field is a string such as -font or -bg; it is the name used for the option in Tcl commands and passed to procedures via the objc or namePtr arguments. The dbName and dbClass fields are used by Tk_InitOptions to look up a default value for this option in the option database; if dbName is NULL then the option database is not used by Tk_InitOptions for this option. The defValue field specifies a default value for this configuration option if no value is specified in the option database. The objOffset and internalOffset fields indicate where to store the value of this option in widget records (more on this below); values for the objOffset and internalOffset fields should always be generated with the Tk_Offset macro. The flags field contains additional information to control the processing of this configuration option (see below for details). ClientData provides additional type-specific data needed by certain types. For instance, for TK_OPTION_COLOR types, clientData is a string giving the default value to use on monochrome displays. See the descriptions of the different types below for details. The last field, typeMask, is used by Tk_SetOptions to return information about which options were modified; see the description of Tk_SetOptions above for details.

When Tk_InitOptions and Tk_SetOptions store the value of an option into the widget record, they can do it in either of two ways. If the objOffset field of the Tk_OptionSpec is greater than or equal to zero, then the value of the option is stored as a (Tcl_Obj *) at the location in the widget record given by objOffset. If the internalOffset field of the Tk_OptionSpec is greater than or equal to zero, then the value of the option is stored in a type-specific internal form at the location in the widget record given by internalOffset. For example, if the option's type is TK_OPTION_INT then the internal form is an integer. If the objOffset or internalOffset field is negative then the value is not stored in that form. At least one of the offsets must be greater than or equal to zero.

The flags field consists of one or more bits ORed together. The following flags are supported:

TK_OPTION_NULL_OK
If this bit is set for an option then an empty string will be accepted as the value for the option and the resulting internal form will be a NULL pointer, a zero value, or None, depending on the type of the option. If the flag is not set then empty strings will result in errors. TK_OPTION_NULL_OK is typically used to allow a feature to be turned off entirely, e.g. set a cursor value to None so that a window simply inherits its parent's cursor. Not all option types support the TK_OPTION_NULL_OK flag; for those that do, there is an explicit indication of that fact in the descriptions below.
TK_OPTION_DONT_SET_DEFAULT
If this bit is set for an option then no default value will be set in Tk_InitOptions for this option. Neither the option database, nor any system default value, nor optionTable are used to give a default value to this option. Instead it is assumed that the caller has already supplied a default value in the widget code.

The type field of each Tk_OptionSpec structure determines how to parse the value of that configuration option. The legal value for type, and the corresponding actions, are described below. If the type requires a tkwin value to be passed into procedures like Tk_SetOptions, or if it uses the clientData field of the Tk_OptionSpec, then it is indicated explicitly; if not mentioned, the type requires neither tkwin nor clientData.

TK_OPTION_ANCHOR
The value must be a standard anchor position such as ne or center. The internal form is a Tk_Anchor value like the ones returned by Tk_GetAnchorFromObj.
TK_OPTION_BITMAP
The value must be a standard Tk bitmap name. The internal form is a Pixmap token like the ones returned by Tk_AllocBitmapFromObj. This option type requires tkwin to be supplied to procedures such as Tk_SetOptions, and it supports the TK_OPTION_NULL_OK flag.
TK_OPTION_BOOLEAN
The value must be a standard boolean value such as true or no. The internal form is an integer with value 0 or 1. Note that if the objOffset field is not used, information about the original value of this option will be lost.
TK_OPTION_BORDER
The value must be a standard color name such as red or #ff8080. The internal form is a Tk_3DBorder token like the ones returned by Tk_Alloc3DBorderFromObj. This option type requires tkwin to be supplied to procedures such as Tk_SetOptions, and it supports the TK_OPTION_NULL_OK flag.

El procedimiento setProc es invocado por Tk_SetOptions para convertir un Tcl_Obj en una representación interna y almacenar el valor resultante en el registro del widget. Los argumentos son:

clientData
Una copia del campo clientData en la estructura Tk_ObjCustomOption.
interp
Un puntero a un intérprete Tcl, utilizado para la notificación de errores.
Tkwin
Una copia del argumento tkwin a Tk_SetOptions
valuePtr
Un puntero a una referencia a un Tcl_Obj que describe el nuevo valor para la opción; podría haber sido especificado explícitamente en la llamada a Tk_SetOptions o podría provenir de la base de datos de opciones o de un valor predeterminado. Si objOffset para la opción no es negativo (el valor de la opción se almacena como un (Tcl_Obj *) en el registro del widget), el puntero Tcl_Obj al que se hace referencia en valuePtr es el puntero que se almacenará en objOffset para la opción. SetProc puede modificar el valor si es necesario; por ejemplo, setProc puede cambiar el valor a NULL para admitir la bandera TK_OPTION_NULL_OK.
recordPtr
Un puntero al inicio del registro del widget a modificar.
internalOffset
Desplazamiento en bytes desde el inicio del registro del widget hasta la ubicación donde se colocará la representación interna del valor de la opción.
saveInternalPtr
Un puntero al almacenamiento asignado en una estructura Tk_SavedOptions para la representación interna del valor original de la opción. Antes de establecer la opción a su nuevo valor, setProc debe establecer el valor al que se hace referencia en saveInternalPtr al valor original de la opción para admitir Tk_RestoreSavedOptions.
flags
Una copia del campo flags en la estructura Tk_OptionSpec para la opción.

SetProc devuelve un resultado Tcl estándar: TCL_OK para indicar un procesamiento exitoso, o TCL_ERROR para indicar un fallo de cualquier tipo. Se puede dejar un mensaje de error en el intérprete Tcl proporcionado por interp en caso de error.

El procedimiento getProc es invocado por Tk_GetOptionValue y Tk_GetOptionInfo para recuperar una representación Tcl_Obj de la representación interna de una opción. El argumento clientData es una copia del campo clientData en la estructura Tk_ObjCustomOption. Tkwin es una copia del argumento tkwin a Tk_GetOptionValue o Tk_GetOptionInfo. RecordPtr es un puntero al principio del registro del widget a consultar. InternalOffset es el desplazamiento en bytes desde el principio del registro del widget hasta la ubicación donde se almacena la representación interna del valor de la opción. GetProc debe devolver un puntero a un Tcl_Obj que represente el valor de la opción.

El procedimiento restoreProc es invocado por Tk_RestoreSavedOptions para restaurar una representación interna previamente guardada de un valor de opción personalizado. El argumento clientData es una copia del campo clientData en la estructura Tk_ObjCustomOption. Tkwin es una copia del argumento tkwin a Tk_GetOptionValue o Tk_GetOptionInfo. InternalPtr es un puntero a la ubicación donde se almacena la representación interna del valor de la opción. SaveInternalPtr es un puntero al valor guardado. RestoreProc debe copiar el valor de saveInternalPtr a internalPtr para restaurar el valor. RestoreProc no necesita liberar ninguna memoria asociada con internalPtr o saveInternalPtr; se invocará freeProc para liberar esa memoria si es necesario. RestoreProc no tiene valor de retorno.

El procedimiento freeProc es invocado por Tk_SetOptions y Tk_FreeSavedOptions para liberar cualquier almacenamiento asignado para la representación interna de una opción personalizada. El argumento clientData es una copia del campo clientData en la estructura Tk_ObjCustomOption. Tkwin es una copia del argumento tkwin a Tk_GetOptionValue o Tk_GetOptionInfo. InternalPtr es un puntero a la ubicación donde se almacena la representación interna del valor de la opción. FreeProc debe liberar cualquier almacenamiento asociado con la opción. FreeProc no tiene valor de retorno.
