Tk_CreateBindingTable(3)

Paquete: tk

Licencias: TCL

Tk_CreateBindingTable(3) Procedimientos de la biblioteca Tk Tk_CreateBindingTable(3)

NOMBRE

Tk_CreateBindingTable, Tk_DeleteBindingTable, Tk_CreateBinding, Tk_DeleteBinding, Tk_GetBinding, Tk_GetAllBindings, Tk_DeleteAllBindings, Tk_BindEvent - invocar scripts en respuesta a eventos X

SINOPSIS

#include <tk.h>

Tk_BindingTable
Tk_CreateBindingTable(interp)

Tk_DeleteBindingTable(bindingTable)

unsigned long
Tk_CreateBinding(interp, bindingTable, object, eventString, script, append)

int
Tk_DeleteBinding(interp, bindingTable, object, eventString)

const char *
Tk_GetBinding(interp, bindingTable, object, eventString)

Tk_GetAllBindings(interp, bindingTable, object)

Tk_DeleteAllBindings(bindingTable, object)

Tk_BindEvent(bindingTable, eventPtr, tkwin, numObjects, objectPtr)

ARGUMENTOS

Tcl_Interp *interp (entrada)
Intérprete a utilizar al invocar las vinculaciones en la tabla de vinculaciones. También se utiliza para devolver resultados y errores de los procedimientos de vinculación.
Tk_BindingTable bindingTable (entrada)
Token para la tabla de vinculaciones; debe haber sido devuelto por alguna llamada previa a Tk_CreateBindingTable.
ClientData object (entrada)
Identifica el objeto con el que está asociada la vinculación.
const char *eventString (entrada)
Cadena que describe la secuencia de eventos.
const char *script (entrada)
Script Tcl a invocar cuando se active la vinculación.
int append (entrada)
Distinto de cero significa añadir script al script existente para la vinculación, si lo hay; cero significa reemplazar el script existente con uno nuevo.
XEvent *eventPtr (entrada)
Evento X a comparar con las vinculaciones en bindingTable.
Tk_Window tkwin (entrada)
Identificador de cualquier ventana en la pantalla donde ocurrió el evento. Se utiliza para encontrar información relacionada con la pantalla, como mapas de teclas.
int numObjects (entrada)
Número de identificadores de objetos apuntados por objectPtr.
ClientData *objectPtr (entrada)
Puntero a una matriz de identificadores de objetos: las vinculaciones se considerarán para cada uno de estos objetos en orden, de primero a último.

DESCRIPCIÓN

Estos procedimientos proporcionan un mecanismo de propósito general para crear e invocar vinculaciones. Las vinculaciones se organizan en términos de tablas de vinculaciones. Una tabla de vinculaciones consiste en una colección de vinculaciones más un historial de eventos recientes. Dentro de una tabla de vinculaciones, las vinculaciones se asocian con objetos. El significado de un objeto es definido por los clientes del paquete de vinculaciones. Por ejemplo, Tk utiliza una tabla de vinculaciones para mantener todas las vinculaciones creadas por el comando bind. Para esta tabla, los objetos son punteros a cadenas como nombres de ventanas, nombres de clases u otras etiquetas de vinculación como all. Tk también mantiene una tabla de vinculaciones separada para cada widget de lienzo, que administra las vinculaciones creadas por el comando de widget bind del lienzo; dentro de esta tabla, un objeto es ya sea un puntero a la estructura interna para un elemento del lienzo o un Tk_Uid que identifica una etiqueta.

El procedimiento Tk_CreateBindingTable crea una nueva tabla de vinculaciones y asocia interp con ella (cuando se invocan las vinculaciones en la tabla, los scripts se evaluarán en interp). Tk_CreateBindingTable devuelve un token para la tabla, que debe usarse en las llamadas a otros procedimientos como Tk_CreateBinding o Tk_BindEvent.

Tk_DeleteBindingTable libera todo el estado asociado con una tabla de vinculaciones. Una vez que regresa, el llamador ya no debe usar el token bindingTable.

Tk_CreateBinding agrega una nueva vinculación a una tabla existente. El argumento object identifica el objeto con el que se debe asociar la vinculación, y puede ser cualquier valor de una palabra. Típicamente es un puntero a una cadena o estructura de datos. El argumento eventString identifica el evento o secuencia de eventos para la vinculación; consulte la documentación del comando bind para una descripción de su formato. script es el script Tcl que se evaluará cuando se active la vinculación. append indica qué hacer si ya existe una vinculación para object y eventString: si append es cero, entonces script reemplaza el script antiguo; si append es distinto de cero, entonces el nuevo script se agrega al antiguo. Tk_CreateBinding devuelve una máscara de eventos X para todos los eventos asociados con las vinculaciones. Esta información puede ser útil para invocar XSelectInput para seleccionar eventos relevantes, o para deshabilitar el uso de ciertos eventos en vinculaciones. Si ocurrió un error al crear la vinculación (por ejemplo, eventString se refiere a un evento inexistente), entonces se devuelve 0 y se deja un mensaje de error como resultado del intérprete interp.

Tk_DeleteBinding elimina de bindingTable la vinculación dada por object y eventString, si existe tal vinculación. Tk_DeleteBinding siempre devuelve TCL_OK. En algunos casos puede restablecer el resultado del intérprete al valor vacío predeterminado.

Tk_GetBinding devuelve un puntero al script asociado con eventString y object en bindingTable. Si no existe tal vinculación, entonces se devuelve NULL y se deja un mensaje de error como resultado del intérprete interp.

Tk_GetAllBindings devuelve en el resultado de interp una lista de todas las cadenas de eventos para las cuales existen vinculaciones en bindingTable asociadas con object. Si no hay vinculaciones para object, el resultado será una cadena vacía.

Tk_DeleteAllBindings elimina todas las vinculaciones en bindingTable que están asociadas con object.

Tk_BindEvent se llama para procesar un evento. Hace una copia del evento en una lista de historial interna asociada con la tabla de vinculaciones, luego busca vinculaciones que coincidan con el evento. Tk_BindEvent procesa cada uno de los objetos apuntados por objectPtr en orden. Para cada objeto, encuentra todas las vinculaciones que coinciden con el historial de eventos actual, selecciona la vinculación más específica utilizando el mecanismo de prioridad descrito en la documentación de bind, e invoca el script para esa vinculación. Si no hay vinculaciones coincidentes para un objeto particular, entonces se omite el objeto. Tk_BindEvent continúa a través de todos los objetos, manejando excepciones como errores, break y continue como se describe en la documentación de bind.
