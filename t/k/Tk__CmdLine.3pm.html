NOMBRE

Tk::CmdLine - Procesa opciones de línea de comandos X11 estándar y establece recursos iniciales

SINOPSIS

Tk::CmdLine::SetArguments([@argument]);
my $valor = Tk::CmdLine::cget([$opción]);
Tk::CmdLine::SetResources((\@recurso | $recurso) [, $prioridad]);
Tk::CmdLine::LoadResources(
    [ -simbolo   => $simbolo     ]
    [ -archivo   => $espec_archivo   ]
    [ -prioridad => $prioridad   ]
    [ -eco     => $manejador_archivo ] );

DESCRIPCIÓN

Procesa opciones de línea de comandos X11 estándar y establece recursos iniciales.

La página del manual de X11R5 para X11 dice: "La mayoría de los programas X intentan usar los mismos nombres para las opciones y argumentos de la línea de comandos. Todas las aplicaciones escritas con X Toolkit Intrinsics aceptan automáticamente las siguientes opciones: ...". Este módulo procesa estas opciones de línea de comandos para aplicaciones perl/Tk usando la función "SetArguments"().

Este módulo puede usarse opcionalmente para cargar recursos iniciales explícitamente a través de la función "SetResources"(), o desde archivos especificados (por defecto: los archivos de recursos estándar específicos de la aplicación X11) a través de la función "LoadResources"().

Opciones de Línea de Comandos

-background Color | -bg Color
Especifica el color que se utilizará para el fondo de la ventana.
-class Clase
Especifica la clase bajo la cual se encontrarán los recursos de la aplicación. Esta opción es útil en alias de shell para distinguir entre invocaciones de una aplicación, sin recurrir a la creación de enlaces para alterar el nombre del archivo ejecutable.
-display Pantalla | -screen Pantalla
Especifica el nombre del servidor X a utilizar.
-font Fuente | -fn Fuente
Especifica la fuente que se utilizará para mostrar texto.
-foreground Color | -fg Color
Especifica el color que se utilizará para texto o gráficos.
-geometry Geometría
Especifica el tamaño y la ubicación iniciales de la *primera* MainWindow.
-iconic
Indica que el usuario preferiría que las ventanas de la aplicación no fueran visibles inicialmente, como si las ventanas hubieran sido minimizadas inmediatamente por el usuario. Los administradores de ventanas pueden optar por no respetar la solicitud de la aplicación.
-motif
Especifica que la aplicación debe adherirse lo más posible a los estándares de apariencia de Motif. Por ejemplo, los elementos activos como los botones y los deslizadores de las barras de desplazamiento no cambiarán de color cuando el puntero pase sobre ellos.
-name Nombre
Especifica el nombre bajo el cual se encontrarán los recursos de la aplicación. Esta opción es útil en alias de shell para distinguir entre invocaciones de una aplicación, sin recurrir a la creación de enlaces para alterar el nombre del archivo ejecutable.
-synchronous
Indica que las solicitudes al servidor X deben enviarse de forma síncrona, en lugar de asíncrona. Dado que Xlib normalmente almacena en búfer las solicitudes al servidor, los errores no se informan necesariamente inmediatamente después de que ocurren. Esta opción desactiva el almacenamiento en búfer para que la aplicación pueda depurarse. Nunca debe usarse con un programa que funcione.
-title CadenaTítulo
Esta opción especifica el título que se utilizará para esta ventana. Esta información es utilizada a veces por un administrador de ventanas para proporcionar algún tipo de encabezado que identifique la ventana.
-xrm CadenaRecurso
Especifica un patrón de recurso y un valor para anular cualquier valor predeterminado. También es muy útil para establecer recursos que no tienen argumentos de línea de comandos explícitos.

La CadenaRecurso tiene el formato <patrón>:<valor>, es decir, el primer ':' se utiliza para determinar qué parte es el patrón y qué parte es el valor. El par (<patrón>, <valor>) se introduce en la base de datos de opciones con optionAdd (para cada MainWindow configurada), con prioridad interactiva.

Recursos Iniciales

Existen varios mecanismos para inicializar la base de datos de recursos que utilizará una aplicación X11. Los recursos pueden definirse en un archivo $"HOME"/.Xdefaults, un archivo de valores predeterminados de aplicación del sistema (por ejemplo, /usr/lib/X11/app-defaults/<CLASE>), o un archivo de valores predeterminados de aplicación del usuario (por ejemplo, $"HOME"/<CLASE>). La funcionalidad de Tk::CmdLine para establecer recursos iniciales se ocupa de los dos últimos.

Los archivos de recursos contienen líneas de datos del formato <patrón>:<valor>. También pueden contener líneas en blanco y líneas de comentarios (denotadas por un carácter ! como primer carácter no en blanco). Consulte la opción para obtener una descripción de <patrón>:<valor>.

Archivos de Valores Predeterminados de Aplicación del Sistema
Los archivos de valores predeterminados de aplicación del sistema pueden especificarse a través de la variable de entorno $"XFILESEARCHPATH" que, si está establecida, contiene una lista de patrones de archivos (unidos usando el delimitador de ruta dependiente del SO, por ejemplo, dos puntos en UNIX).
Archivos de Valores Predeterminados de Aplicación del Usuario
Los archivos de valores predeterminados de aplicación del usuario pueden especificarse a través de las variables de entorno $"XUSERFILESEARCHPATH", $"XAPPLRESDIR" o $"HOME".

MÉTODOS

SetArguments - Tk::CmdLine::SetArguments([@argument])
Extrae las opciones X11 contenidas en un array especificado (@ARGV por defecto). 
Tk::CmdLine::SetArguments([@argument])

Las opciones X11 pueden especificarse usando un solo guion - según la convención X11, o usando dos guiones -- según el estándar POSIX (por ejemplo, -geometry 100x100, -geometry 100x100 o -geometry=100x100). Las opciones pueden intercalarse con otras opciones o argumentos. Un -- por sí solo termina el procesamiento de opciones.

Por defecto, las opciones de línea de comandos se extraen de @ARGV la primera vez que se crea una MainWindow. El constructor de Tk::MainWindow invoca indirectamente "SetArguments"() para hacer esto.

GetArguments - Tk::CmdLine::GetArguments()
Obtiene una lista de las opciones X11 que han sido procesadas por "SetArguments"(). ("GetArguments"() invoca primero "SetArguments"() si aún no ha sido invocado.)
cget - Tk::CmdLine::cget([$opción])
Obtiene el valor de una opción de configuración especificada a través de "SetArguments"(). ("cget"() invoca primero "SetArguments"() si aún no ha sido invocado.) 
Tk::CmdLine::cget([$opción])

Las opciones válidas son: -class, -name, -screen y -title. Si no se especifica ninguna opción, se implica -class.

Un uso típico de "cget"() podría ser obtener la clase de la aplicación para definir el nombre de un archivo de recursos que se cargará a través de "LoadResources"().

my $class = Tk::CmdLine::cget(); # procesa la lín
SetResources - Tk::CmdLine::SetResources((\@resource | $resource) [, $priority])
Establece recursos de forma explícita. Puede pasar un array de recursos, o un solo recurso. La prioridad es opcional (valor predeterminado 10, los valores más bajos tienen mayor prioridad). 
Tk::CmdLine::SetResources([\@resource | $resource] [, $priority])

Los recursos se pasan como una lista de pares clave-valor, por ejemplo:

Tk::CmdLine::SetResources(
    -name    => 'myapp',
    -background => 'red',
    -foreground => 'white'
)
LoadResources - Tk::CmdLine::LoadResources(...)
Carga recursos desde archivos. Los archivos son escaneados en orden de prioridad descendente. Los valores encontrados posteriormente anulan los encontrados anteriormente. 
Tk::CmdLine::LoadResources(
    [ -simbolo   => $simbolo     ]
    [ -archivo   => $espec_archivo   ]
    [ -prioridad => $prioridad   ]
    [ -eco     => $manejador_archivo ] )

Las opciones son:

-simbolo => $simbolo
Busca recursos para el símbolo especificado. Si no se especifica ningún símbolo, se usa el nombre de la aplicación (obtenido de "cget(-name)").
-archivo => $espec_archivo
Lee un archivo de recursos especificado. Si no se especifica ningún archivo, se usa la búsqueda predeterminada de archivos de recursos de la aplicación.
-prioridad => $prioridad
Especifica la prioridad para cargar los recursos. Los valores más bajos tienen mayor prioridad. El valor predeterminado es 10. Utilice esto para anular los valores de otros archivos cargados. Por ejemplo, para hacer que un archivo tenga una prioridad más alta que los archivos de sistema predeterminados (que suelen tener prioridad 10), puede especificar un valor inferior, como 5.
-eco => $manejador_archivo
Escribe cada línea de recurso leída en el manejador de archivo especificado. Útil para depurar.

La búsqueda predeterminada de archivos de recursos incluye:

valores predeterminados de la aplicación del usuario
Un archivo del formato $HOME/<CLASS>.
ruta de búsqueda de archivos de usuario
Archivos especificados por la variable de entorno $XUSERFILESEARCHPATH.
directorio de valores predeterminados de la aplicación
Un archivo del formato $HOME/<CLASS>.
valores predeterminados de la aplicación del sistema
Archivos especificados por la variable de entorno $XFILESEARCHPATH.

Consulte los archivos manuales de X (por ejemplo, X(1)) para obtener una descripción completa de las variables de entorno y el orden de búsqueda.

Generalmente, solo se necesita la opción "LoadResources"() si desea cargar recursos de un archivo específico de su aplicación. Si no, los recursos estándar (como los archivos de valores predeterminados de la aplicación del sistema y del usuario) se cargarán automáticamente cuando se llame a la función del constructor de la ventana principal.

EJEMPLO

Aquí hay un ejemplo de cómo se podría usar Tk::CmdLine en un programa simple:

 use Tk;
 use Tk::CmdLine;

 my $mw = MainWindow->new( -title => "Mi Aplicación" );

 # Procesa @ARGV para opciones como -geometry, -fg, etc.
 # Esto lo hace el constructor de MainWindow por defecto, pero
 # puedes llamarlo explícitamente si es necesario.
 # Tk::CmdLine::SetArguments();

 # Carga los recursos de la aplicación desde los archivos de recursos
 # de la aplicación y del sistema. Si no se llama, esto se
 # llamará implícitamente al crear la primera ventana.
 Tk::CmdLine::LoadResources();

 # Obtén el nombre de la clase para usarlo en el archivo de recursos
 # Nota: Tk::CmdLine::cget() procesará @ARGV si aún no se ha hecho.
 my $app_class = Tk::CmdLine::cget( -class );

 # Ahora podemos cargar recursos específicos de nuestra aplicación,
 # por ejemplo, desde $HOME/MyApp o /usr/lib/X11/app-defaults/MyApp
 Tk::CmdLine::LoadResources( -simbolo => $app_class );

 # Configura widgets, etc.
 my $label = $mw->Label( -text => "¡Hola, Mundo!" )->pack;

 # Obtiene el color de primer plano que se puede haber especificado
 # en la línea de comandos o en un archivo de recursos.
 # Nota: Tk::CmdLine::GetArguments() también procesará @ARGV si es necesario.
 my @args = Tk::CmdLine::GetArguments();
 my $fg_color = Tk::CmdLine::cget( -foreground );
 $label->configure( -foreground => $fg_color ) if $fg_color;

 # Inicia el bucle principal de Tk
 MainLoop;

Tk::CmdLine - A module for processing command-line options and Tk resources =head1 SYNOPSIS use Tk; use Tk::CmdLine; # Example 1: Default behaviour - process @ARGV when MainWindow is created my $mw = MainWindow->new(); # Example 2: Explicitly process @ARGV before MainWindow is created Tk::CmdLine::SetArguments(); my $mw = MainWindow->new(); # Example 3: Load resources from default files before MainWindow is created Tk::CmdLine::LoadResources(); my $mw = MainWindow->new(); MainLoop(); =head1 DESCRIPTION This module processes command-line options (which are passed in the special array variable C<@ARGV> by default) and Tk resources. It allows you to easily handle command-line arguments, including Tk-specific options such as C<-bg>, C<-fg>, C<-font>, C<-geometry>, etc. It also provides functionality for loading Tk resource files, both system-wide and user-specific. The module is designed to be flexible, allowing you to control when and how command-line arguments and resources are processed. =head2 Core Functions =head3 SetArguments [(\@ARGV | $arg), ...] Process command-line arguments. =over =item * (\@ARGV | $arg) Tk::CmdLine::SetArguments(); # Processes the default @ARGV Tk::CmdLine::SetArguments(\@my_args); # Processes the array reference $my_args Tk::CmdLine::SetArguments("-fg", "red", "-text", "Hello"); # Processes arguments directly =back If no arguments are given, C<@ARGV> is processed. Otherwise, the specified arguments are processed. Tk-specific options (like C<-bg>, C<-fg>, etc.) are consumed and their values are stored. All other options are returned in C<@ARGV> after the call to C. Note that C is automatically invoked by C if it has not already been invoked. =head3 GetArguments Return the list of arguments that have been processed by C. =over =item * Tk::CmdLine::GetArguments(); =back This function returns the remaining arguments after Tk-specific options have been consumed. This is useful if you want to handle non-Tk options yourself. =head3 SetResources ((\@resource | $resource) [, $priority]) Set the initial resources. =over =item * ((\@resource | $resource) [, $priority]) Tk::CmdLine::SetResources( ('*Button*background: red', '*Button*foreground: blue'), 'widgetDefault' ); Tk::CmdLine::SetResources( '*Button*background: red', 'widgetDefault' ); =back A single resource can be specified as a string like "pattern:value". Multiple resources can be specified by passing an array reference containing strings of the above form, or anonymous arrays of the form [ pattern, value ]. The optional second argument specifies the priority, as defined in option, to be associated with the resources (default: C). Note that C first invokes C if it has not already been invoked. =head3 LoadResources ([%options]) Load initial resources from one or more files. =over =item * [ -symbol => $symbol ] Specifies the name of an environment variable that, if set, defines a list of one or more directories and/or file patterns (joined using the OS-dependent path delimiter, e.g. colon on UNIX). C<$XUSERFILESEARCHPATH> is a special case. If C<$XUSERFILESEARCHPATH> is not set, C<$XAPPLRESDIR> is checked instead. If C<$XAPPLRESDIR> is not set, C<$HOME> is checked instead. An item is identified as a file pattern if it contains one or more /%[A-Za-z]/ patterns. Only patterns %L, %T and %N are currently recognized. All others are replaced with the null string. Pattern %L is translated into $LANG. Pattern %T is translated into C. Pattern %N is translated into the application class name. Each file pattern, after substitutions are applied, is assumed to define a FileSpec to be examined. When a directory is specified, FileSpecs C/$LANG/C and C/C are defined, in that order. =item * [ -file => $fileSpec ] Specifies a resource file to be loaded in. The file is silently skipped if it does not exist, or if it is not readable. =item * [ -priority => $priority ] Specifies the priority, as defined in option, to be associated with the resources (default: C). =item * [ -echo => $fileHandle ] May be used to specify that a line should be printed to the corresponding FileHandle (default: \*STDOUT) every time a file is examined / loaded. =back If no C<-symbol> or C<-file> options are specified, C processes symbol C<$XFILESEARCHPATH> with priority C and C<$XUSERFILESEARCHPATH> with priority C. (Note that C<$XFILESEARCHPATH> and C<$XUSERFILESEARCHPATH> are supposed to contain only patterns. C<$XAPPLRESDIR> and C<$HOME> are supposed to be a single directory. C does not check/care whether this is the case.) For each set of FileSpecs, C examines each FileSpec to determine if the file exists and is readable. The first file that meets this criteria is read in and C is invoked. Note that C first invokes C if it has not already been invoked. =head1 NOTES This module is an object-oriented module whose methods can be invoked as object methods, class methods or regular functions. This is accomplished via an internally-maintained object reference which is created as necessary, and which always points to the last object used. C, C and C return the object reference. =head1 EXAMPLES =over =item 1. C<@ARGV> is processed by Tk::CmdLine at MainWindow creation. use Tk; # my $mw = MainWindow->new(); MainLoop(); =item 2. C<@ARGV> is processed by Tk::CmdLine before MainWindow creation. An C<@ARGV> of (--geometry=100x100 -opt1 a b c -bg red) is equal to (-opt1 a b c) after C is invoked. use Tk; Tk::CmdLine::SetArguments(); # Tk::CmdLine->SetArguments() works too # my $mw = MainWindow->new(); MainLoop(); =item 3. Just like 2) except that default arguments are loaded first. use Tk; Tk::CmdLine::SetArguments(qw(-name test -iconic)); Tk::CmdLine::SetArguments(); # my $mw = MainWindow->new(); MainLoop(); =item 4. C<@ARGV> is processed by Tk::CmdLine before MainWindow creation. Standard resource files are loaded in before MainWindow creation. use Tk; Tk::CmdLine::SetArguments(); # Tk::CmdLine::LoadResources(); my $mw = MainWindow->new(); MainLoop(); =item 5. C<@ARGV> is processed by Tk::CmdLine before MainWindow creation. Standard resource files are loaded in before MainWindow creation using non-default priorities. use Tk; Tk::CmdLine::SetArguments(); # Tk::CmdLine::LoadResources(-echo => \*STDOUT, -priority => 65, -symbol => 'XFILESEARCHPATH' ); Tk::CmdLine::LoadResources(-echo => \*STDOUT, -priority => 75, -symbol => 'XUSERFILESEARCHPATH' ); my $mw = MainWindow->new(); MainLoop(); =item 6. C<@ARGV> is processed by Tk::CmdLine before MainWindow creation. Standard resource files are loaded in before MainWindow creation. Individual resources are also loaded in before MainWindow creation. use Tk; Tk::CmdLine::SetArguments(); # Tk::CmdLine::LoadResources(); Tk::CmdLine::SetResources( # set a single resource '*Button*background: red', 'widgetDefault' ); Tk::CmdLine::SetResources( # set multiple resources [ '*Button*background: red', '*Button*foreground: blue' ], 'widgetDefault' ); my $mw = MainWindow->new(); MainLoop(); =back =head1 ENVIRONMENT =over =item * HOME (optional) Home directory which may contain user application defaults files as C<$HOME>/$/ or C<$HOME>/. =item * LANG (optional) The current language (default: C). =item * XFILESEARCHPATH (optional) List of FileSpec patterns (joined using the OS-dependent path delimiter, e.g. colon on UNIX) used in defining system application defaults files. =item * XUSERFILESEARCHPATH (optional) List of FileSpec patterns (joined using the OS-dependent path delimiter, e.g. colon on UNIX) used in defining user application defaults files. =item * XAPPLRESDIR (optional) Directory containing user application defaults files as C<$XAPPLRESDIR>/$/ or C<$XAPPLRESDIR>/. =back =head1 SEE ALSO MainWindow option =head1 HISTORY =over =item * 1999.03.04 Ben Pavon Rewritten as an object-oriented module. Allow one to process command line options in a specified array (@ARGV by default). Eliminate restrictions on the format and location of the options within the array (previously the X11 options could not be specified in POSIX format and had to be at the beginning of the array). Added the C and C functions to allow the definition of resources prior to MainWindow creation. =item * 2000.08.31 Ben Pavon Added the C method which returns the list of arguments that have been processed by C. Modified C to split the symbols using the OS-dependent path delimiter defined in the C module. Modified C to eliminate a warning message when processing patterns %l, =back %C, %S.
