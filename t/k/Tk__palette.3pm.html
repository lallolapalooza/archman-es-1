NOMBRE

Tk::palette - Modificar la paleta de colores de Tk

SINOPSIS

$widget->setPalette(background)

$widget->setPalette(nombre=>valor?,nombre=>valor ... ?)

$widget->bisque

DESCRIPCIÓN

El método setPalette cambia el esquema de colores de Tk. Lo hace modificando los colores de los widgets existentes y cambiando la base de datos de opciones para que los widgets futuros utilicen el nuevo esquema de colores. Si se invoca setPalette con un solo argumento, este es el nombre de un color a utilizar como color de fondo normal; setPalette calculará una paleta de colores completa a partir de este color de fondo. Alternativamente, los argumentos de setPalette pueden consistir en cualquier número de pares nombre-valor, donde el primer argumento del par es el nombre de una opción en la base de datos de opciones de Tk y el segundo argumento es el nuevo valor a utilizar para esa opción. Los siguientes nombres de base de datos son actualmente compatibles:

activeBackground       foreground      selectColor
activeForeground       highlightBackground     selectBackground
background     highlightColor  selectForeground
disabledForeground     insertBackground        troughColor

setPalette intenta calcular valores predeterminados razonables para cualquier opción que no especifique. Puede especificar opciones distintas de las anteriores y Tk también cambiará esas opciones en los widgets. Esta característica puede ser útil si está utilizando widgets personalizados con opciones de color adicionales.

Una vez que ha calculado el nuevo valor a utilizar para cada una de las opciones de color, setPalette escanea la jerarquía de widgets para modificar las opciones de todos los widgets existentes. Para cada widget, comprueba si alguna de las opciones anteriores está definida para él. Si es así, y si el valor actual de la opción es el predeterminado, el valor se cambia; si la opción tiene un valor distinto del predeterminado, setPalette no lo modificará. El valor predeterminado de una opción es el proporcionado por el widget (($w->configure('option'))[3]) a menos que setPalette se haya ejecutado previamente, en cuyo caso es el valor especificado en la invocación anterior de setPalette.

Después de modificar todos los widgets de la aplicación, setPalette agrega opciones a la base de datos de opciones para cambiar los valores predeterminados de los widgets creados en el futuro. Las nuevas opciones se agregan con prioridad widgetDefault, por lo que serán anuladas por opciones del archivo .Xdefaults o por opciones especificadas en la línea de comandos que crea un widget.

El método bisque se proporciona por compatibilidad con versiones anteriores: restaura los colores de la aplicación al esquema de colores marrón claro (``bisque'') utilizado en Tk 3.6 y versiones anteriores.

ERRORES

El uso de nombres de la base de datos de opciones en lugar de los nombres de configuración es comprensible dado el mecanismo (copiado de Tcl/Tk), pero es potencialmente confuso.

La interpolación de diferentes 'tonos' de color utilizados para efectos 3D en el espacio 'RGB' puede provocar cambios indeseables en el 'tono'. La interpolación en 'HSV' (como se usa en Tk::ColorEditor) sería más robusta y el soporte de color de X11R5 probablemente aún más.

VER TAMBIÉN
