ARGUMENTOS

Tcl_Interp *interp (entrada)
Intérprete a usar para la notificación de errores.
Tk_Window tkwin (entrada)
Token de la ventana (para todos los procedimientos excepto Tk_Get3DBorder, debe ser la ventana para la que se asignó el borde).
Tcl_Obj *objPtr (entrada)
Puntero al valor cuya descripción del color corresponde al fondo (áreas planas). Los bordes iluminados serán más brillantes que este y los bordes sombreados serán más oscuros que este.
const char *colorName (entrada)
Igual que objPtr excepto que el valor se proporciona como una cadena en lugar de un valor.
Drawable drawable (entrada)
Token de X para la ventana o pixmap; indica dónde se deben dibujar los gráficos. Debe ser la ventana X para tkwin o un pixmap con la misma pantalla y profundidad que tkwin.
Tk_3DBorder border (entrada)
Token del borde previamente asignado en una llamada a Tk_Get3DBorder.
int x (entrada)
Coordenada X de la esquina superior izquierda del rectángulo que describe el borde o bisel, en píxeles.
int y (entrada)
Coordenada Y de la esquina superior izquierda del rectángulo que describe el borde o bisel, en píxeles.
int width (entrada)
Ancho del rectángulo que describe el borde o bisel, en píxeles.
int height (entrada)
Altura del rectángulo que describe el borde o bisel, en píxeles.
int borderWidth (entrada)
Ancho del borde en píxeles. Un valor positivo significa que el borde está dentro del rectángulo dado por x, y, width, height; un valor negativo significa que el borde está fuera del rectángulo.
int relief (entrada)
Indica la posición 3D del interior del valor con respecto al exterior; debe ser TK_RELIEF_RAISED, TK_RELIEF_SUNKEN, TK_RELIEF_GROOVE, TK_RELIEF_SOLID, o TK_RELIEF_RIDGE (también puede ser TK_RELIEF_FLAT para Tk_Fill3DRectangle).
XPoint *pointPtr (entrada)
Puntero a una matriz de puntos que describe el conjunto de vértices de un polígono. El polígono no necesita estar cerrado (se cerrará automáticamente si no lo está).
int numPoints (entrada)
Número de puntos en *pointPtr.
int polyBorderWidth (entrada)
Ancho del borde en píxeles. Si es positivo, el borde se dibuja a la izquierda de la trayectoria dada por pointPtr; si es negativo, el borde se dibuja a la derecha de la trayectoria. Si leftRelief es TK_RELIEF_GROOVE o TK_RELIEF_RIDGE, entonces el borde se centra en la trayectoria.
int leftRelief (entrada)
Altura del lado izquierdo de la trayectoria del polígono con respecto al derecho. TK_RELIEF_RAISED significa que el lado izquierdo debe parecer más alto y TK_RELIEF_SUNKEN significa que el lado derecho debe parecer más alto; TK_RELIEF_GROOVE y TK_RELIEF_RIDGE significan lo obvio. Para Tk_Fill3DPolygon, TK_RELIEF_FLAT también puede especificarse para indicar que no hay diferencia de altura.
int leftBevel (entrada)
Un valor distinto de cero significa que este bisel forma el lado izquierdo del valor; cero significa que forma el lado derecho.
int leftIn (entrada)
Un valor distinto de cero significa que el borde izquierdo del bisel horizontal se inclina hacia adentro, de modo que la parte inferior del borde está más a la derecha que la superior. Cero significa que el borde se inclina hacia afuera, de modo que la parte inferior está más a la izquierda que la superior.
int rightIn (entrada)
Un valor distinto de cero significa que el borde derecho del bisel horizontal se inclina hacia adentro, de modo que la parte inferior del borde está más a la izquierda que la superior. Cero significa que el borde se inclina hacia afuera, de modo que la parte inferior está más a la derecha que la superior.
int topBevel (entrada)
Un valor distinto de cero significa que este bisel forma el lado superior del valor; cero significa que forma el lado inferior.
int which (entrada)
Especifica cuál de los contextos gráficos del borde se desea. Debe ser TK_3D_FLAT_GC, TK_3D_LIGHT_GC, o TK_3D_DARK_GC.

DESCRIPCIÓN

Estos procedimientos proporcionan facilidades para dibujar bordes de ventana de una manera que produce una apariencia tridimensional. Tk_Alloc3DBorderFromObj asigna los colores y pixmaps necesarios para dibujar un borde en la ventana dada por el argumento tkwin. El valor de objPtr es un nombre de color estándar de Tk que determina los colores del borde. El color indicado por objPtr no se usará realmente en el borde; indica el color de fondo de la ventana (es decir, un color para superficies planas). Las porciones iluminadas del borde parecerán más brillantes que lo indicado por objPtr, y las porciones sombreadas del borde parecerán más oscuras que objPtr.

Tk_Alloc3DBorderFromObj devuelve un token que puede usarse en llamadas posteriores a Tk_Draw3DRectangle. Si ocurre un error al asignar información para el borde (por ejemplo, se dio un nombre de color inválido), se devuelve NULL y se deja un mensaje de error como resultado del intérprete interp. Si se devuelve correctamente, Tk_Alloc3DBorderFromObj almacena información sobre el valor de retorno en objPtr, lo que acelera las llamadas futuras a Tk_Alloc3DBorderFromObj con el mismo objPtr y tkwin.

Tk_Get3DBorder es idéntico a Tk_Alloc3DBorderFromObj excepto que el color se especifica con una cadena en lugar de un valor. Esto evita que Tk_Get3DBorder almacene en caché el valor de retorno, por lo que Tk_Get3DBorder es menos eficiente que Tk_Alloc3DBorderFromObj.

Tk_Get3DBorderFromObj devuelve el token de un borde existente, dado el nombre de la ventana y el color utilizados para crear el borde. Tk_Get3DBorderFromObj no crea realmente el borde; ya debe haber sido creado con una llamada anterior a Tk_Alloc3DBorderFromObj o Tk_Get3DBorder. El valor de retorno se almacena en caché en objPtr, lo que acelera las llamadas futuras a Tk_Get3DBorderFromObj con el mismo objPtr y tkwin.

Una vez que se ha creado una estructura de borde, se puede invocar a Tk_Draw3DRectangle para dibujar el borde. El argumento tkwin especifica la ventana para la que se asignó el borde, y drawable especifica una ventana o pixmap en la que se va a dibujar el borde. Drawable no tiene por qué referirse a la misma ventana que tkwin, pero debe referirse a un pixmap o ventana compatible: uno asociado con la misma pantalla y con la misma profundidad que tkwin. Los argumentos x, y, width y height definen el cuadro delimitador de la región del borde dentro de drawable (generalmente x e y son cero y width y height son las dimensiones de la ventana), y borderWidth especifica el número de píxeles ocupados realmente por el borde. El argumento relief indica cuál de varios efectos tridimensionales se desea: TK_RELIEF_RAISED significa que el interior del rectángulo debe parecer elevado con respecto al exterior del rectángulo, y TK_RELIEF_SUNKEN significa que el interior debe parecer hundido. TK_RELIEF_GROOVE y TK_RELIEF_RIDGE significan que debe parecer haber una ranura o cresta alrededor del exterior del rectángulo.

ARGUMENTS

‐ 'border'
Specifies the border whose attributes are to be used for drawing. This is a token returned by Tk_Alloc3DBorderFromObj or Tk_Get3DBorder.
‐ 'colorName'
Specifies the color to use for the border, in the format used by Tk_Alloc3DBorderFromObj. This is the name of the color (e.g. "red" or "#ff0000").
‐ 'colorNameObj'
A pointer to an XColor structure specifying the color to use for the border. This is the return value of Tk_3DBorderColor.
‐ 'drawable'
The drawable on which to draw.
‐ 'height'
The height of the rectangular area, in pixels.
‐ 'leftBorder'
Specifies the width of the left border in pixels for Tk_3DVerticalBevel.
‐ 'leftIn'
Used by Tk_3DHorizontalBevel to control the shape of the mitered corner. A value of 1 produces a trapezoid that is narrower at the bottom than the top; a value of 0 produces a trapezoid that is wider at the bottom than the top.
‐ 'leftRelief'
Specifies which side of the trajectory should appear raised when drawing a 3D polygon. Valid values are TK_RELIEF_RAISED and TK_RELIEF_DEPRESSED.
‐ 'numPoints'
The number of points in the pointPtr array.
‐ 'pointPtr'
Points to an array of Tk_Point structures that define the corners of the polygon.
‐ 'polyBorderWidth'
Specifies how wide the border should be around the polygon, in pixels. If the value is negative, the border is drawn inside the polygon; if positive, it is drawn outside.
‐ 'relief'
Specifies the desired 3D effect. This may be one of the following values:
TK_RELIEF_FLAT
No border is drawn. The area is simply filled with the background color.
TK_RELIEF_RAISED
The border appears raised from the surface.
TK_RELIEF_DEPRESSED
The border appears sunken into the surface.
TK_RELIEF_GROOVE
A groove is carved around the area.
TK_RELIEF_RIDGE
A ridge is added around the area.
See the Tk_3DRelief manual page for a full description of the border styles.
‐ 'rightIn'
Used by Tk_3DHorizontalBevel to control the shape of the mitered corner. A value of 1 produces a trapezoid that is narrower at the bottom than the top; a value of 0 produces a trapezoid that is wider at the bottom than the top.

Specifies the width of the top border in pixels for Tk_3DHorizontalBevel.
‐ 'width'
The width of the rectangular area, in pixels.
‐ 'which'
Specifies which of the three graphics contexts associated with a border is to be returned. This may be one of the following values:
TK_3D_FLAT_GC
The graphics context used for drawing flat surfaces.
TK_3D_LIGHT_GC
The graphics context used for drawing the light part of a 3D border.
TK_3D_DARK_GC
The graphics context used for drawing the dark part of a 3D border.
‐ 'tkwin'
The window in which the border is being drawn.
‐ 'x'
The x-coordinate of the top-left corner of the rectangular area.
‐ 'y'
The y-coordinate of the top-left corner of the rectangular area.

DESCRIPTION

These procedures provide a complete set of tools for drawing two-dimensional shapes with a three-dimensional appearance. This appearance is achieved by drawing borders around the shapes using colors that simulate light and shadow.

The procedure Tk_Alloc3DBorderFromObj allocates a new border token given a window and a color name. The color name may be specified in any format accepted by Tcl_GetColor. The token should be released when no longer needed by calling Tk_Free3DBorderFromObj. If a border token already exists for the given window and color name, it is returned; otherwise, a new one is created.

Tk_Get3DBorder is similar to Tk_Alloc3DBorderFromObj, but it takes a null-terminated string for the color name instead of a Tcl_Obj. This function is provided for compatibility with older versions of Tk.

The procedure Tk_Draw3DRectangle draws a rectangle with the specified border and relief. It first fills the rectangular area with the background color (one corresponding to the color used to create border). Then it draws a border around the rectangle using the colors from border to give it a raised or sunken appearance, depending on the value of relief. The borderWidth argument specifies how wide the border should be, in pixels. If borderWidth is 0, no border is drawn.

The procedure Tk_Fill3DRectangle is similar to Tk_Draw3DRectangle, except that it first fills the rectangular area with the background color (one corresponding to the color used to create border). Then it calls Tk_Draw3DRectangle to draw a border just inside the outer edge of the rectangular area. The argument relief indicates the desired effect (TK_RELIEF_FLAT means no border should be drawn; all that happens is to fill the rectangle with the background color).

The procedure Tk_Draw3DPolygon may be used to draw more complex shapes with a three-dimensional appearance. The pointPtr and numPoints arguments define a trajectory, polyBorderWidth indicates how wide the border should be (and on which side of the trajectory to draw it), and leftRelief indicates which side of the trajectory should appear raised. Tk_Draw3DPolygon draws a border around the given trajectory using the colors from border to produce a three-dimensional appearance. If the trajectory is non-self-intersecting, the appearance will be a raised or sunken polygon shape. The trajectory may be self-intersecting, although it's not clear how useful this is.

Tk_Fill3DPolygon is to Tk_Draw3DPolygon what Tk_Fill3DRectangle is to Tk_Draw3DRectangle: it fills the polygonal area with the background color from border, then calls Tk_Draw3DPolygon to draw a border around the area (unless leftRelief is TK_RELIEF_FLAT; in this case no border is drawn).

The procedures Tk_3DVerticalBevel and Tk_3DHorizontalBevel provide lower-level drawing primitives that are used by procedures such as Tk_Draw3DRectangle. These procedures are also useful in their own right for drawing rectilinear border shapes. Tk_3DVerticalBevel draws a vertical beveled edge, such as the left or right side of a rectangle, and Tk_3DHorizontalBevel draws a horizontal beveled edge, such as the top or bottom of a rectangle. Each procedure takes x, y, width, and height arguments that describe the rectangular area of the beveled edge (e.g., width is the border width for Tk_3DVerticalBevel). The leftBorder and topBorder arguments indicate the position of the border relative to the “inside” of the value, and relief indicates the relief of the inside of the value relative to the outside. Tk_3DVerticalBevel just draws a rectangular region. Tk_3DHorizontalBevel draws a trapezoidal region to generate mitered corners; it should be called after Tk_3DVerticalBevel (otherwise Tk_3DVerticalBevel will overwrite the mitering in the corner). The leftIn and rightIn arguments to Tk_3DHorizontalBevel describe the mitering at the corners; a value of 1 means that the bottom edge of the trapezoid will be shorter than the top, 0 means it will be longer. For example, to draw a rectangular border the top bevel should be drawn with 1 for both leftIn and rightIn, and the bottom bevel should be drawn with 0 for both arguments.

The procedure Tk_SetBackgroundFromBorder will modify the background pixel and/or pixmap of tkwin to produce a result compatible with border. For color displays, the resulting background will just be the color specified when border was created; for monochrome displays, the resulting background will be a light stipple pattern, in order to distinguish the background from the illuminated portion of the border.

Given a token for a border, the procedure Tk_NameOf3DBorder will return the color name that was used to create the border.

The procedure Tk_3DBorderColor returns the XColor structure that will be used for flat surfaces drawn for its border argument by procedures like Tk_Fill3DRectangle. The return value corresponds to the color name that was used to create the border. The XColor, and its associated pixel value, will remain allocated as long as border exists.

The procedure Tk_3DBorderGC returns one of the X graphics contexts that are used to draw the border. The argument which selects which one of the three possible GC's: TK_3D_FLAT_GC returns the context used for flat surfaces, TK_3D_LIGHT_GC returns the context for light shadows, and TK_3D_DARK_GC returns the context for dark shadows.

When a border is no longer needed, Tk_Free3DBorderFromObj or Tk_Free3DBorder should be called to release the resources associated with it. For Tk_Free3DBorderFromObj the border to release is specified with the window and color name used to create the border; for Tk_Free3DBorder the border to release is specified with the Tk_3DBorder token for the border. There should be exactly one call to Tk_Free3DBorderFromObj or Tk_Free3DBorder for each call to Tk_Alloc3DBorderFromObj or Tk_Get3DBorder.
