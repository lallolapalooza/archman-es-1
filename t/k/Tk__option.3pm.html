NOMBRE

Tk::option - Uso de la base de datos de opciones en Perl/Tk

SINOPSIS

    $widget->widgetClass(Name=>nombre, -class=>clase);

    $widget->PathName;

    $widget->optionAdd(patrón=>valor ?,prioridad?);

    $widget->optionClear;

    $widget->optionGet(nombre, clase);

    $widget->optionReadfile(nombreArchivo ?,prioridad?);

DESCRIPCIÓN

La base de datos de opciones (también conocida como la base de datos de recursos o la base de datos de valores predeterminados de aplicación) es un conjunto de reglas para aplicar opciones predeterminadas a los widgets. Los usuarios y administradores del sistema pueden establecer estas reglas para personalizar la apariencia de las aplicaciones sin modificar el código de la aplicación; por ejemplo, un usuario podría configurar colores personales de primer plano y fondo, o un sitio podría utilizar fuentes asociadas a preferencias visuales o de idioma. Diferentes gestores de ventanas (e implementaciones de ellos) han implementado la base de datos de manera diferente, pero la mayoría de los gestores de ventanas basados en Xt utilizan el archivo .Xdefaults o la utilidad xrdb para gestionar las preferencias del usuario; algunos utilizan ambos, y/o implementan un conjunto más complejo de bases de datos de sitio, usuario y aplicación. Consulte la documentación de su sitio para estos temas o para la propiedad RESOURCE_MANAGER de su gestor de ventanas.

Ser un buen ciudadano

Para la mayoría de las aplicaciones, la base de datos de opciones simplemente funciona. Los métodos option... son para aplicaciones que necesitan hacer algo inusual, como agregar nuevas reglas o probar el valor predeterminado de una opción. Incluso en tales casos, la aplicación debe tener en cuenta las preferencias del usuario. No codifique de forma rígida las opciones de los widgets sin una razón muy buena. Todos los usuarios tienen sus propios gustos y todos son diferentes. Eligen una fuente especial en un tamaño especial y a menudo pasan mucho tiempo elaborando un esquema de colores que amarán hasta la muerte. Cuando respetas sus elecciones, disfrutarán mucho más trabajando con tus aplicaciones. No destruyas el aspecto y la sensación común de un escritorio personal.

Reglas de opciones e identificación de widgets

Todos los widgets en una aplicación se identifican jerárquicamente por su nombre de ruta, comenzando desde la VentanaPrincipal y pasando por cada widget utilizado para crear el punto final. Los elementos de la ruta son nombres de widgets, muy parecidos a los elementos de una ruta de archivo desde el directorio raíz hasta un archivo. Las reglas en la base de datos de opciones son patrones que se comparan con el nombre de ruta de un widget para determinar qué valores predeterminados se aplican. Cuando se crea un widget, la opción Name se puede usar para asignar el nombre del widget y así crear una ruta distintiva para los widgets en una aplicación. Si no se proporciona la opción Name, Perl/Tk asigna un nombre predeterminado basado en el tipo de widget; el nombre predeterminado de una VentanaPrincipal es el nombreapp. Estos valores predeterminados están bien para la mayoría de los widgets, así que no sientas que necesitas encontrar un nombre significativo para cada widget que creas. Un widget debe tener un nombre distintivo para permitir a los usuarios adaptar sus opciones independientemente de otros widgets en una aplicación. Por ejemplo, para crear un widget Text al que se le asignarán opciones especiales, dale un nombre como:

$texto = $mw->Text(Name => 'textoImportante');

Luego puedes personalizar los atributos del widget con una regla en la base de datos de opciones como:

*textoImportante*primerplano: rojo

La opción clase identifica grupos de widgets, generalmente dentro de una aplicación, pero también para agrupar widgets similares entre diferentes aplicaciones. Uno típicamente asigna una clase a un TopLevel o Frame para que la clase se aplique a todos los hijos de ese widget. Para extender el ejemplo, podríamos ser más específicos sobre el widget textoImportante dándole a su marco una clase:

$marco = $mw->Frame(-class => 'Urgente');
$texto = $marco->Text(Name => 'textoImportante');

Entonces el patrón del recurso se puede especificar así:

*Urgente*textoImportante*primerplano: rojo

De manera similar, el patrón "*Urgente*fondo: cyan" se aplicaría a todos los widgets en el marco.

MÉTODOS

$widget->widgetClass(Name=>nombre, -class=>clase);
Identifica un nuevo widget con nombre y/o clase. Name especifica el elemento de ruta para el widget; los nombres generalmente comienzan con una letra minúscula. -class especifica la clase para el widget y sus hijos; las clases generalmente comienzan con una letra mayúscula. Si no se especifica, Perl/Tk asignará un nombre predeterminado único a cada widget. Solo los widgets MainWindow tienen una clase predeterminada, creada al convertir en mayúscula la primera letra del nombre de la aplicación.
$widget->PathName;
El método PathName devuelve el nombre de ruta del widget, que identifica de forma única al widget dentro de la aplicación.
$widget->optionAdd(patrón=>valor ?, prioridad?);
El método optionAdd agrega una nueva opción a la base de datos. Patrón contiene la opción que se está especificando y consiste en nombres y/o clases separados por asteriscos o puntos, en el formato X habitual. Valor contiene una cadena de texto para asociar con patrón; este es el valor que se devolverá en las llamadas al método optionGet. Si se especifica prioridad, indica el nivel de prioridad para esta opción (ver abajo los valores permitidos); por defecto es interactive. Este método siempre devuelve una cadena vacía.
$widget->optionClear;
El método optionClear borra la base de datos de opciones. Las opciones predeterminadas (de la propiedad RESOURCE_MANAGER o del archivo .Xdefaults) se recargarán automáticamente la próxima vez que se agregue o elimine una opción de la base de datos. Este método siempre devuelve una cadena vacía.
$widget->optionGet(nombre,clase);
El método optionGet devuelve el valor de la opción especificada para $widget bajo nombre y clase. Para buscar la opción, optionGet compara los patrones en la base de datos de recursos con el nombre de ruta de $widget junto con la clase de $widget (o su padre si $widget no tiene una clase especificada). La clase y el nombre del widget son opciones establecidas cuando se crea el widget (no relacionadas con la clase en el sentido de `bless`); el nombre de la MainWindow es el appname y su clase es (por defecto) derivada del nombre del script.

Si varias entradas en la base de datos de opciones coinciden con el nombre de ruta, nombre y clase de $widget, entonces el método devuelve la que fue creada con el nivel de prioridad más alto. Si hay varias entradas coincidentes en el mismo nivel de prioridad, entonces devuelve la entrada que fue introducida más recientemente en la base de datos de opciones. Si no hay entradas coincidentes, se devuelve una cadena vacía.

$widget->optionReadfile(nombreArchivo?,prioridad?);
El método optionReadfile lee nombreArchivo, que debe tener el formato estándar para una base de datos de recursos X como .Xdefaults, y agrega todas las opciones especificadas en ese archivo a la base de datos de opciones. Si se especifica prioridad, indica el nivel de prioridad en el que ingresar las opciones; prioridad tiene como valor predeterminado interactive.

Los argumentos de prioridad para los métodos option normalmente se especifican simbólicamente utilizando uno de los siguientes valores:

widgetDefault
Nivel 20. Se utiliza para los valores predeterminados codificados de forma rígida en los widgets.

PRIORITIES

The Tk::option module supports the following keywords for specifying option priorities:

startupFile
Nivel 40. Se usa para opciones especificadas en archivos de inicio específicos de la aplicación.
userDefault
Nivel 60. Se usa para opciones especificadas en archivos de configuración específicos del usuario, como .Xdefaults, bases de datos de recursos cargadas en el servidor X o archivos de inicio específicos del usuario.
interactive
Nivel 80. Se usa para opciones especificadas interactivamente después de que la aplicación comienza a ejecutarse. Si no se especifica priority, se utiliza este nivel por defecto.

Cualquiera de las palabras clave anteriores puede abreviarse. Además, las prioridades pueden especificarse numéricamente usando enteros entre 0 y 100, inclusive. La forma numérica probablemente sea una mala idea, excepto para nuevos niveles de prioridad distintos de los dados anteriormente.

BUGS

El esquema de prioridades utilizado por el núcleo de Tk no es el mismo que el utilizado por las rutinas normales de Xlib. En particular, asume que el orden de las entradas está definido, pero comandos de usuario como xrdb -merge pueden cambiar el orden.
