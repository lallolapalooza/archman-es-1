NOMBRE

Tk_ConfigureWidget, Tk_ConfigureInfo, Tk_ConfigureValue, Tk_FreeOptions - procesar opciones de configuración para widgets

SINOPSIS

#include <tk.h>

int
Tk_ConfigureWidget(interp, tkwin, specs, argc, argv, widgRec, flags)

int
Tk_ConfigureInfo(interp, tkwin, specs, widgRec, argvName, flags)

int
Tk_ConfigureValue(interp, tkwin, specs, widgRec, argvName, flags)

Tk_FreeOptions(specs, widgRec, display, flags)

ARGUMENTOS

Tcl_Interp *interp (entrada)
Intérprete a utilizar para devolver mensajes de error.
Tk_Window tkwin (entrada)
Ventana utilizada para representar el widget (necesaria para configurar recursos de X).
const Tk_ConfigSpec *specs (entrada)
Puntero a la tabla que especifica las opciones de configuración legales para este widget.
int argc (entrada)
Número de argumentos en argv.
const char **argv (entrada)
Opciones de línea de comandos para configurar el widget.
char *widgRec (entrada/salida)
Punta a la estructura del registro del widget. Los campos de esta estructura se modifican mediante Tk_ConfigureWidget para almacenar información de configuración.
int flags (entrada)
Si no es cero, especifica una combinación OR-ada de banderas que controlan el procesamiento de la información de configuración. TK_CONFIG_ARGV_ONLY hace que se ignoren la base de datos de opciones y los valores predeterminados, y las banderas TK_CONFIG_USER_BIT y superiores se utilizan para deshabilitar selectivamente las entradas en specs.
nombre de tipo type (entrada)
El nombre del tipo de un registro de widget.
nombre de campo field (entrada)
El nombre de un campo en registros del tipo type.
const char *argvName (entrada)
El nombre utilizado en las líneas de comandos de Tcl para referirse a una opción particular (por ejemplo, al crear un widget o invocar el comando configure del widget). Si es NULL, entonces se devuelve información solo para esta opción. Si es NULL, entonces se devuelve información para todas las opciones disponibles.
Display *display (entrada)
Pantalla que contiene el widget cuyo registro se está liberando; necesario para liberar recursos.

DESCRIPCIÓN

Nota: Tk_ConfigureWidget debe ser reemplazado por la nueva API basada en Tcl_Obj, Tk_SetOptions. La interfaz antigua se conserva por compatibilidad retroactiva.

Tk_ConfigureWidget se llama para configurar varios aspectos de un widget, como colores, fuentes, ancho del borde, etc. Está pensado como un procedimiento de conveniencia para reducir la cantidad de código que deben escribir los administradores de widgets individuales para manejar la información de configuración. Normalmente se invoca cuando se crean los widgets y de nuevo cuando se invoca el comando configure para un widget. Aunque está pensado principalmente para widgets, Tk_ConfigureWidget se puede utilizar en otras situaciones en las que la información argc-argv se va a utilizar para rellenar una estructura de registro, como la configuración de elementos gráficos para un widget de lienzo o entradas de un menú.

Tk_ConfigureWidget procesa una tabla que especifica las opciones de configuración que se admiten (specs) y una colección de argumentos de línea de comandos (argc y argv) para rellenar campos de un registro (widgRec). Utiliza la base de datos de opciones y los valores predeterminados especificados en specs para rellenar campos de widgRec que no se especifican en argv. Tk_ConfigureWidget normalmente devuelve el valor TCL_OK; en este caso, no modifica interp. Si ocurre un error, se devuelve TCL_ERROR y Tk_ConfigureWidget dejará un mensaje de error en el resultado del intérprete interp de la forma estándar de Tcl. En caso de un retorno de error, algunos de los campos de widgRec ya podrían haberse establecido, si la información de configuración para ellos se procesó correctamente antes de que ocurriera el error. Los otros campos se establecerán con valores iniciales razonables para que se pueda llamar a Tk_FreeOptions para la limpieza.

La matriz specs especifica los tipos de opciones de configuración que espera el widget. Cada una de sus entradas especifica una opción de configuración y tiene la siguiente estructura:

typedef struct {
    int type;
    const char *argvName;
    const char *dbName;
    const char *dbClass;
    const char *defValue;
    int offset;
    int specFlags;
    const Tk_CustomOption *customPtr;
} Tk_ConfigSpec;
El campo type indica qué tipo de opción de configuración es esta (por ejemplo, TK_CONFIG_COLOR para un valor de color, o TK_CONFIG_INT para un valor entero). El campo type indica cómo utilizar el valor de la opción (más información a continuación). El campo argvName es una cadena como “-font” o “-bg”, que se compara con los valores en argv (si argvName es NULL, significa que es una entrada agrupada; consulte ENTRADAS AGRUPADAS a continuación). Los campos dbName y dbClass se utilizan para buscar un valor para esta opción en la base de datos de opciones. El campo defValue especifica un valor predeterminado para esta opción de configuración si no se especifica ningún valor en argv o en la base de datos de opciones. Offset indica dónde en widgRec almacenar la información sobre esta opción. specFlags contiene información adicional para controlar el procesamiento de esta opción de configuración (consulte BANDERAS a continuación). El último campo, customPtr, solo se utiliza si type es TK_CONFIG_CUSTOM; consulte TIPOS DE OPCIONES PERSONALIZADAS a continuación.

Tk_ConfigureWidget primero procesa argv para ver qué opciones de configuración (si las hay) se especifican allí. Argv debe contener un número par de campos; el primero de cada par de campos debe coincidir con el argvName de alguna entrada en specs (se aceptan abreviaturas únicas), y el segundo campo del par contiene el valor para esa opción de configuración. Si hay entradas en spec para las que no hubo entradas coincidentes en argv, Tk_ConfigureWidget utiliza los campos dbName y dbClass de la entrada specs para sondear la base de datos de opciones; si se encuentra un valor, se utiliza como valor para la opción. Finalmente, si no se encuentra ninguna entrada en la base de datos de opciones, se utiliza el campo defValue de la entrada specs como valor para la opción de configuración. Si defValue es NULL, o si el bit TK_CONFIG_DONT_SET_DEFAULT está establecido en flags, entonces no hay valor predeterminado y esta entrada specs se ignorará si no se especifica ningún valor en argv o en la base de datos de opciones.

Una vez que se determina un valor de cadena para una opción de configuración, Tk_ConfigureWidget traduce el valor de cadena a una forma más útil, como un color si type es TK_CONFIG_COLOR o un entero si type es TK_CONFIG_INT. Luego, este valor se almacena en el registro al que apunta widgRec. Se supone que este registro contiene información relevante para el administrador del widget; su tipo exacto es desconocido para Tk_ConfigureWidget. El campo offset de cada entrada specs indica dónde en widgRec almacenar la información sobre esta opción de configuración. Debe usar la macro Tk_Offset para generar valores de offset (consulte a continuación una descripción de Tk_Offset). La ubicación indicada por widgRec y offset se denominará el "objetivo" en las descripciones a continuación.

El campo type de cada entrada en specs determina qué hacer con el valor de cadena de esa opción de configuración. Los valores legales para type y las acciones correspondientes son:

TK_CONFIG_ACTIVE_CURSOR
El valor debe ser una cadena ASCII que identifique un cursor en un formato adecuado para pasar a Tk_GetCursor. El valor se convierte en un Tk_Cursor llamando a Tk_GetCursor y el resultado se almacena en el objetivo. Además, el cursor resultante se establece como el cursor activo para tkwin llamando a XDefineCursor. Si se especifica TK_CONFIG_NULL_OK en specFlags, el valor puede ser una cadena vacía, en cuyo caso el objetivo y el cursor activo de tkwin se establecerán en None. Si el valor anterior del objetivo no era None, se libera pasándolo a Tk_FreeCursor.
TK_CONFIG_ANCHOR
El valor debe ser una cadena ASCII que identifique un punto de anclaje de una de las maneras aceptadas por Tk_GetAnchor. La cadena se convierte en un Tk_Anchor mediante

TYPES

Each entry in the specs array describes one configuration option. The first field in the structure is type, which indicates how the option's value should be interpreted and converted. The following are the standard types recognized by Tk_ConfigureWidget:

TK_CONFIG_ACTIVE_CURSOR
The value must be an ASCII string identifying a cursor in a form suitable for passing to Tk_GetCursor. The value is converted to a Tk_Cursor by calling Tk_GetCursor and the result is stored in the target. If TK_CONFIG_NULL_OK is specified in specFlags then the value may be an empty string, in which case the target is set to None. If the previous value of the target was not None, then it is freed by passing it to Tk_FreeCursor. Furthermore, the cursor is made the active cursor for tkwin.
TK_CONFIG_ANCHOR
The value must be an ASCII string identifying an anchor position in one of the forms accepted by Tk_GetAnchor. The string is converted to a Tk_Anchor by calling Tk_GetAnchor and the result is stored in the target.
TK_CONFIG_BITMAP
The value must be an ASCII string identifying a bitmap in a form suitable for passing to Tk_GetBitmap. The value is converted to a Pixmap by calling Tk_GetBitmap and the result is stored in the target. If TK_CONFIG_NULL_OK is specified in specFlags then the value may be an empty string, in which case the target is set to None. If the previous value of the target was not None, then it is freed by passing it to Tk_FreeBitmap.
TK_CONFIG_BOOLEAN
The value must be an ASCII string specifying a boolean value. Any of the values “true”, “yes”, “on”, or “1”, or an abbreviation of one of these values, means true; any of the values “false”, “no”, “off”, or “0”, or an abbreviation of one of these values, means false. The target is expected to be an integer; for true values it will be set to 1 and for false values it will be set to 0.
TK_CONFIG_BORDER
The value must be an ASCII string identifying a border color in a form suitable for passing to Tk_Get3DBorder. The value is converted to a (Tk_3DBorder *) by calling Tk_Get3DBorder and the result is stored in the target. If TK_CONFIG_NULL_OK is specified in specFlags then the value may be an empty string, in which case the target will be set to NULL. If the previous value of the target was not NULL, then it is freed by passing it to Tk_Free3DBorder.
TK_CONFIG_CAP_STYLE
The value must be an ASCII string identifying a cap style in one of the ways accepted by Tk_GetCapStyle. The string is converted to an integer value corresponding to the cap style by calling Tk_GetCapStyle and the result is stored in the target.
TK_CONFIG_COLOR
The value must be an ASCII string identifying a color in a form suitable for passing to Tk_GetColor. The value is converted to an (XColor *) by calling Tk_GetColor and the result is stored in the target. If TK_CONFIG_NULL_OK is specified in specFlags then the value may be an empty string, in which case the target will be set to None. If the previous value of the target was not NULL, then it is freed by passing it to Tk_FreeColor.
TK_CONFIG_CURSOR
This option is identical to TK_CONFIG_ACTIVE_CURSOR except that the new cursor is not made the active one for tkwin.
TK_CONFIG_CUSTOM
This option allows applications to define new option types. The customPtr field of the entry points to a structure defining the new option type. See the section CUSTOM OPTION TYPES below for details.
TK_CONFIG_DOUBLE
The value must be an ASCII floating-point number in the format accepted by strtod. The string is converted to a double value, and the value is stored in the target.
TK_CONFIG_END
Marks the end of the table. The last entry in specs must have this type; all of its other fields are ignored and it will never match any arguments.
TK_CONFIG_FONT
The value must be an ASCII string identifying a font in a form suitable for passing to Tk_GetFont. The value is converted to a Tk_Font by calling Tk_GetFont and the result is stored in the target. If TK_CONFIG_NULL_OK is specified in specFlags then the value may be an empty string, in which case the target will be set to NULL. If the previous value of the target was not NULL, then it is freed by passing it to Tk_FreeFont.
TK_CONFIG_INT
The value must be an ASCII integer string in the format accepted by strtol (e.g. “0” and “0x” prefixes may be used to specify octal or hexadecimal numbers, respectively). The string is converted to an integer value and the integer is stored in the target.
TK_CONFIG_JOIN_STYLE
The value must be an ASCII string identifying a join style in one of the ways accepted by Tk_GetJoinStyle. The string is converted to an integer value corresponding to the join style by calling Tk_GetJoinStyle and the result is stored in the target.
TK_CONFIG_JUSTIFY
The value must be an ASCII string identifying a justification method in one of the ways accepted by Tk_GetJustify. The string is converted to a Tk_Justify by calling Tk_GetJustify and the result is stored in the target.
TK_CONFIG_MM
The value must specify a screen distance in one of the forms acceptable to Tk_GetScreenMM. The string is converted to double-precision floating-point distance in millimeters and the value is stored in the target.
TK_CONFIG_PIXELS
The value must specify screen units in one of the forms acceptable to Tk_GetPixels. The string is converted to an integer distance in pixels and the value is stored in the target.
TK_CONFIG_RELIEF
The value must be an ASCII string identifying a relief in a form suitable for passing to Tk_GetRelief. The value is converted to an integer relief value by calling Tk_GetRelief and the result is stored in the target.
TK_CONFIG_STRING
A copy of the value is made by allocating memory space with Tcl_Alloc and copying the value into the dynamically-allocated space. A pointer to the new string is stored in the target. If TK_CONFIG_NULL_OK is specified in specFlags then the value may be an empty string, in which case the target will be set to NULL. If the previous value of the target was not NULL, then it is freed by passing it to Tcl_Free.
TK_CONFIG_SYNONYM
This type value identifies special entries in specs that are synonyms for other entries. If an argv value matches the argvName of a TK_CONFIG_SYNONYM entry, the entry is not used directly. Instead, Tk_ConfigureWidget searches specs for another entry whose argvName is the same as the dbName field in the TK_CONFIG_SYNONYM entry; this new entry is used just as if its argvName had matched the argv value. The synonym mechanism allows multiple argv values to be used for a single configuration option, such as “-background” and “-bg”.
TK_CONFIG_UID
The value is translated to a Tk_Uid (by passing it to Tk_GetUid). The resulting value is stored in the target. If TK_CONFIG_NULL_OK is specified in specFlags and the value is an empty string then the target will be set to NULL.
TK_CONFIG_WINDOW
The value must be a window path name. It is translated to a Tk_Window token and the token is stored in the target.

GROUPED ENTRIES

In some cases it is useful to generate multiple resources from a single configuration value. For example, a color name might be used both to generate the background color for a widget (using TK_CONFIG_COLOR) and to generate a 3-D border to draw around the widget (using TK_CONFIG_BORDER). In cases like this it is possible to specify that several consecutive entries in specs are to be treated as a group. The first entry is used to determine a value (using its argvName, dbName, dbClass, and defValue fields). The value will be processed several times (one for each entry in the group), generating multiple different resources and modifying multiple targets within widgRec. Each of the entries after the first must have a NULL value in its argvName field; this indicates that the entry is to be grouped with the entry that precedes it. Only the type and offset fields are used from these follow-on entries.

FLAGS

The flags argument passed to Tk_ConfigureWidget is used in conjunction with the specFlags fields in the entries of specs to provide additional control over the processing of configuration options. These values are used in three different ways as described below.

First, if the flags argument to Tk_ConfigureWidget has the TK_CONFIG_ARGV_ONLY bit set (i.e., flags | TK_CONFIG_ARGV_ONLY != 0), then the option database and defValue fields are not used. In this case, if an entry in specs does not match a field in argv then nothing happens: the corresponding target is not modified. This feature is useful when the goal is to modify certain configuration options while leaving others in their current state, such as when a configure widget command is being processed.

Second, the specFlags field of an entry in specs may be used to control the processing of that entry. Each specFlags field may consists of an OR-ed combination of the following values:

TK_CONFIG_COLOR_ONLY
If this bit is set then the entry will only be considered if the display for tkwin has more than one bit plane. If the display is monochromatic then this specs entry will be ignored.
TK_CONFIG_MONO_ONLY
If this bit is set then the entry will only be considered if the display for tkwin is monochromatic. If the display has more than one bit plane then this specs entry will be ignored.
TK_CONFIG_NULL_OK
If this bit is set then an empty string value is acceptable for this option. When an empty string is given, the target will be set to NULL (or None in Tk terminology), and any previous value will be freed. If the bit is not set, then an empty string is an error.
TK_CONFIG_DONT_SET_DEFAULT
If this bit is set, then the configuration option will not be stored in the option database. This is useful for options that are intended to be set only by the application and not by the user. If the bit is not set, the option is stored in the database, potentially overwriting any existing value.
TK_CONFIG_RESTRICTED
This flag indicates that the option should not be set via the option database. It can only be set via the command line arguments.

Third, the specFlags field may be used to specify a default value for the option. If the argv entry for the option is not specified, and if the TK_CONFIG_DONT_SET_DEFAULT bit is not set in specFlags, then the defValue field is used as the option's value. If defValue is NULL, then the option is not set unless it is specified in argv or the option database.

f este bit está establecido, la entrada solo se considerará si la pantalla para tkwin tiene exactamente un plano de bits. Si la pantalla no es monocromática, esta entrada de specs se ignorará.
TK_CONFIG_NULL_OK
Este bit solo es relevante para algunos tipos de entradas (ver las descripciones de los diversos tipos de entradas anteriores). Si este bit está establecido, indica que un valor de cadena vacía para el campo es aceptable y si ocurre, entonces el destino se establecerá en NULL o None, dependiendo del tipo de el destino. Esta bandera se usa típicamente para permitir que una característica se desactive completamente, por ejemplo, establecer un valor de cursor en None para que una ventana simplemente herede el cursor de su padre. Si este bit no está establecido, entonces las cadenas vacías se procesan como cadenas, lo que generalmente resulta en un error.
TK_CONFIG_DONT_SET_DEFAULT
Si este bit es uno, significa que el campo defValue de la entrada solo debe usarse para devolver el valor predeterminado en Tk_ConfigureInfo. En las llamadas a Tk_ConfigureWidget no se suministrará ningún valor predeterminado para las entradas con esta bandera establecida; se asume que el llamador ya ha proporcionado un valor predeterminado en la ubicación de destino. Esta bandera proporciona una optimización de rendimiento donde es costoso procesar la cadena predeterminada: el cliente puede calcular el valor predeterminado una vez, guardar el valor y proporcionarlo antes de llamar a Tk_ConfigureWidget.
TK_CONFIG_OPTION_SPECIFIED
Este bit está obsoleto. Solía ser establecido y borrado por Tk_ConfigureWidget para que los llamadores pudieran detectar qué entradas se especificaron en argv, pero se eliminó porque era inherentemente no seguro para subprocesos. El código que desea detectar qué opciones se especificaron debería usar Tk_SetOptions en su lugar.

Las banderas TK_CONFIG_MONO_ONLY y TK_CONFIG_COLOR_ONLY se usan típicamente para especificar valores predeterminados diferentes para pantallas monocromáticas y en color. Esto se hace creando dos entradas en specs que son idénticas excepto por sus campos defValue y specFlags. Una entrada debe tener el valor TK_CONFIG_MONO_ONLY en su specFlags y el valor predeterminado para pantallas monocromáticas en su defValue; la otra entrada debe tener el valor TK_CONFIG_COLOR_ONLY en su specFlags y el defValue apropiado para pantallas en color.

En tercer lugar, es posible usar flags y specFlags juntos para deshabilitar selectivamente algunas entradas. Esta característica no se necesita con mucha frecuencia. Es útil en casos donde varios tipos similares de widgets se implementan en un solo lugar. Permite crear una única tabla specs con todas las opciones de configuración para todos los tipos de widgets. Al procesar un tipo de widget en particular, solo se usarán las entradas relevantes para ese tipo. Este efecto se logra estableciendo los bits de orden superior (aquellos en posiciones iguales o mayores que TK_CONFIG_USER_BIT) en specFlags o en flags. Para que una entrada en particular en specs sea utilizada, sus bits de orden superior deben coincidir exactamente con los bits de orden superior del valor flags pasado a Tk_ConfigureWidget. Si se está utilizando una tabla specs para N diferentes tipos de widgets, entonces se usarán N bits de orden superior. Cada entrada specs tendrá uno o más de esos bits establecidos en su campo specFlags para indicar los tipos de widget para los cuales esta entrada es válida. Al llamar a Tk_ConfigureWidget, flags tendrá un solo uno de esos bits establecido para seleccionar las entradas para el tipo de widget deseado. Para un ejemplo funcional de esta característica, ver el código en tkButton.c.

TK_OFFSET

La macro Tk_Offset se proporciona como una forma segura de generar los valores offset para las entradas en las estructuras Tk_ConfigSpec. Toma dos argumentos: el nombre de un tipo de registro y el nombre de un campo en ese registro. Devuelve el desplazamiento de bytes del campo nombrado en los registros del tipo dado.

TK_CONFIGUREINFO

El procedimiento Tk_ConfigureInfo se puede usar para obtener información sobre una o todas las opciones para un widget dado. Dado un token para una ventana (tkwin), una tabla que describe las opciones de configuración para una clase de widgets (specs), un puntero a un registro de widget que contiene la información actual para un widget (widgRec), y un argumento argvName NULL, Tk_ConfigureInfo genera una cadena que describe todas las opciones de configuración para la ventana. La cadena se coloca en el resultado del intérprete interp. En circunstancias normales, devuelve TCL_OK; si ocurre un error, devuelve TCL_ERROR y el resultado del intérprete contendrá un mensaje de error.

Si argvName es NULL, entonces el valor dejado en el resultado del intérprete por Tk_ConfigureInfo consiste en una lista de una o más entradas, cada una de las cuales describe una opción de configuración (es decir, una entrada en specs). Cada entrada en la lista contendrá dos o cinco valores. Si la entrada correspondiente en specs tiene el tipo TK_CONFIG_SYNONYM, entonces la lista contendrá dos valores: el argvName para la entrada y el dbName (nombre sinónimo). De lo contrario, la lista contendrá cinco valores: argvName, dbName, dbClass, defValue y el valor actual. El valor actual se calcula a partir del campo apropiado de widgRec llamando a procedimientos como Tk_NameOfColor.

Si el argumento argvName a Tk_ConfigureInfo no es NULL, entonces indica una sola opción, y la información se devuelve solo para esa opción. La cadena colocada en el resultado del intérprete será una lista que contiene dos o cinco valores como se describió anteriormente; esto será idéntico a la sublista correspondiente que se habría devuelto si argvName hubiera sido NULL.

El argumento flags a Tk_ConfigureInfo se utiliza para restringir las entradas specs a considerar, al igual que para Tk_ConfigureWidget.

TK_CONFIGUREVALUE

Tk_ConfigureValue toma argumentos similares a Tk_ConfigureInfo; en lugar de devolver una lista de valores, simplemente devuelve el valor actual de la opción dada por argvName (argvName no debe ser NULL). El valor se devuelve en el resultado del intérprete interp y normalmente se devuelve TCL_OK como resultado del procedimiento. Si ocurre un error en Tk_ConfigureValue (por ejemplo, argvName no es un nombre de opción válido), se devuelve TCL_ERROR y se deja un mensaje de error en el resultado del intérprete. Este procedimiento se llama típicamente para implementar los comandos de widget cget.

TK_FREEOPTIONS

El procedimiento Tk_FreeOptions se puede invocar durante la limpieza del widget para liberar todos los recursos asociados con las opciones de configuración. Escanea specs y para cada entrada correspondiente a un recurso que debe liberarse explícitamente (por ejemplo, aquellos con el tipo TK_CONFIG_COLOR), libera el recurso en el registro del widget. Si el campo en el registro del widget no hace referencia a un recurso (por ejemplo, contiene un puntero nulo), entonces no se libera ningún recurso para esa entrada. Después de liberar un recurso, Tk_FreeOptions establece el campo correspondiente del registro del widget a nulo.

TIPOS DE OPCIONES PERSONALIZADAS

Las aplicaciones pueden extender los tipos de configuración integrados con tipos de configuración adicionales escribiendo procedimientos para analizar e imprimir opciones de un tipo y creando una estructura que apunte a esos procedimientos:

typedef struct Tk_CustomOption {
    Tk_OptionParseProc *parseProc;
    Tk_OptionPrintProc *printProc;
    ClientData clientData;
} Tk_CustomOption;
typedef int Tk_OptionParseProc(
        ClientData clientData,
        Tcl_Interp *interp,
        Tk_Window tkwin,
        char *value,
        char *widgRec,
        int offset);
typedef const char *Tk_OptionPrintProc(
        ClientData clientData,
        Tk_Window tkwin,
        char *widgRec,
        int offset,
        Tcl_FreeProc **freeProcPtr);
La estructura Tk_CustomOption contiene tres campos, que son punteros a los dos procedimientos y un valor clientData que se pasará a esos procedimientos cuando se invoquen. El valor clientData normalmente apunta a una estructura que contiene información necesaria para los procedimientos cuando analizan e imprimen opciones.

El procedimiento parseProc es invocado por Tk_ConfigureWidget para analizar una cadena y almacenar el valor resultante en el registro del widget. El argumento clientData es una copia del campo clientData en la estructura Tk_CustomOption. El argumento interp apunta a un intérprete de Tcl utilizado para la notificación de errores. Tkwin es una copia del argumento tkwin a Tk_ConfigureWidget. El argumento value es una cadena que describe el valor de la opción; podría haber sido especificado explícitamente en la llamada a Tk_ConfigureWidget o podría provenir de la base de datos de opciones o de un valor predeterminado. Value nunca será un puntero nulo pero puede apuntar a una cadena vacía. RecordPtr es lo mismo que el argumento widgRec a Tk_ConfigureWidget; apunta al inicio del registro del widget a modificar. El último argumento, offset, da el desplazamiento en bytes desde el inicio del registro del widget hasta la ubicación donde se colocará el valor de la opción. El procedimiento debe traducir la cadena a la forma que sea apropiada para la opción y almacenar el valor en el registro del widget. Normalmente debería devolver TCL_OK, pero si ocurre un error al traducir la cadena a un valor, debería devolver TCL_ERROR y almacenar un mensaje de error en el resultado del intérprete interp.

DESCRIPTION

The Tk_ConfigureWidget function is the main entry point for configuring Tk widgets. It takes a list of option specifications (spec) and a set of option values (objv) and updates the widget record (rec, passed via tkwin in the library implementation) with the new option values. The spec array describes the type and storage location of each option.

The Tk_ConfigSpec structure defines an individual option. Its fields are:

  • specFlags: Flags that control how the option is handled. May be combined using the bitwise OR operator. Possible values are TK_CONFIG_OPTION_TABLE, TK_CONFIG_NULL_OK, TK_CONFIG_MONO_FONT, TK_CONFIG_COLOR_CASE, TK_CONFIG_RELOCATE, TK_CONFIG_DONT_SET_DEFAULT, TK_CONFIG_ABBREVIATED, TK_CONFIG_JUGGLE, TK_CONFIG_OBJECT_TYPE, TK_CONFIG_LENIENT_SYNTAX, TK_CONFIG_USER_BIT (plus 10 bits for user-defined flags).
  • type: The type of the option. Possible values are TK_CONFIG_BOOLEAN, TK_CONFIG_STRING, TK_CONFIG_INT, TK_CONFIG_DOUBLE, TK_CONFIG_CHAR, TK_CONFIG_FONT, TK_CONFIG_COLOR, TK_CONFIG_PIXELS, TK_CONFIG_RELIEF, TK_CONFIG_ANCHOR, TK_CONFIG_JUSTIFY, TK_CONFIG_CAP_STYLE, TK_CONFIG_JOIN_STYLE, TK_CONFIG_BITMAP, TK_CONFIG_CURSOR, TK_CONFIG_ACTIVE_CURSOR, TK_CONFIG_STROKE, TK_CONFIG_SYMBOL, TK_CONFIG_SYMBOL_OR_COLOR, TK_CONFIG_MM, TK_CONFIG_CUSTOM.
  • offset: The offset of the option within the widget record.
  • name: The name of the option (e.g., "background", "width").
  • defVal: The default value of the option.
  • customPtr: For TK_CONFIG_CUSTOM type, this points to a Tk_CustomOption structure that defines the parsing and printing procedures for the custom option type.

The Tk_ConfigureWidget function is typically called by a widget's configuration routine. It parses the option values, updates the widget record, and returns an error code if any option is invalid. The freeProcPtr argument is a pointer to a procedure that should be called to free any dynamically allocated storage for the result string. If the result string is stored in static memory then freeProcPtr need not do anything with the freeProcPtr argument.

Once parseProc and printProc have been defined and a Tk_CustomOption structure has been created for them, options of this new type may be manipulated with Tk_ConfigSpec entries whose type fields are TK_CONFIG_CUSTOM and whose customPtr fields point to the Tk_CustomOption structure.

Obtains information about a widget's configuration options. The information is returned in a null-terminated array of Tk_ConfigSpec structures pointed to by configInfo.

TK_CONFIGUREVALUE

Retrieves the value of a specific configuration option for a widget. The value is returned as a Tcl object.

TK_FREEOPTIONS

Frees any dynamically allocated memory associated with widget configuration options. This should be called when a widget is destroyed.

CUSTOM OPTION TYPES

Custom option types allow you to define your own option types beyond the standard ones provided by Tk. You need to provide three procedures:

  • parseProc: Parses the string value of the option and stores it in the widget record.
  • printProc: Converts the value stored in the widget record back into a string representation.
  • freeProc: Frees any dynamically allocated memory associated with the option.

These procedures are specified in a Tk_CustomOption structure, which is then referenced by a Tk_ConfigSpec entry with type set to TK_CONFIG_CUSTOM.

Once parseProc and printProc have been defined and a Tk_CustomOption structure has been created for them, options of this new type may be manipulated with Tk_ConfigSpec entries whose type fields are TK_CONFIG_CUSTOM and whose customPtr fields point to the Tk_CustomOption structure.

EXAMPLES

Although the explanation of Tk_ConfigureWidget is fairly complicated, its actual use is pretty straightforward. The easiest way to get started is to copy the code from an existing widget. The library implementation of frames (tkFrame.c) has a simple configuration table, and the library implementation of buttons (tkButton.c) has a much more complex table that uses many of the fancy specFlags mechanisms.
