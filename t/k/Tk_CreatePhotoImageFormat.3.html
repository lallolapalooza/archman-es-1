Tk_CreatePhotoImageFormat(3) Procedimientos de la biblioteca Tk Tk_CreatePhotoImageFormat(3)

NOMBRE

Tk_CreatePhotoImageFormat - definir un nuevo formato de archivo para imágenes fotográficas

SINOPSIS

#include <tk.h>

Tk_CreatePhotoImageFormat(formatPtr)

ARGUMENTOS

const Tk_PhotoImageFormat *formatPtr (entrada)
Estructura que define el nuevo formato de archivo.

DESCRIPCIÓN

Tk_CreatePhotoImageFormat se invoca para definir un nuevo formato de archivo para datos de imagen para usar con imágenes fotográficas. El código que implementa un formato de archivo de imagen se llama manejador de formato de archivo de imagen, o manejador para abreviar. El código de imagen fotográfica mantiene una lista de manejadores que se pueden usar para leer y escribir datos desde o hacia un archivo. Algunos manejadores también pueden admitir la lectura de datos de imagen desde una cadena o la conversión de datos de imagen a un formato de cadena. El usuario puede especificar qué manejador usar con la opción de configuración de imagen -format o la opción -format de los subcomandos read y write de la imagen fotográfica.

Un manejador de formato de archivo de imagen consiste en una colección de procedimientos más una estructura Tk_PhotoImageFormat, que contiene el nombre del formato de archivo de imagen y punteros a seis procedimientos proporcionados por el manejador para tratar con archivos y cadenas en este formato. La estructura Tk_PhotoImageFormat contiene los siguientes campos:

typedef struct Tk_PhotoImageFormat {
    const char *name;
    Tk_ImageFileMatchProc *fileMatchProc;
    Tk_ImageStringMatchProc *stringMatchProc;
    Tk_ImageFileReadProc *fileReadProc;
    Tk_ImageStringReadProc *stringReadProc;
    Tk_ImageFileWriteProc *fileWriteProc;
    Tk_ImageStringWriteProc *stringWriteProc;
} Tk_PhotoImageFormat;

El manejador no necesita proporcionar implementaciones de los seis procedimientos. Por ejemplo, los procedimientos que manejan datos de cadena no se proporcionarían para un formato en el que los datos de imagen se almacenan en binario, y por lo tanto podrían contener caracteres nulos. Si algún procedimiento no está implementado, el puntero correspondiente en la estructura Tk_PhotoImageFormat debe establecerse en NULL. El manejador debe proporcionar el procedimiento fileMatchProc si proporciona el procedimiento fileReadProc, y el procedimiento stringMatchProc si proporciona el procedimiento stringReadProc.

NOMBRE

formatPtr->name proporciona un nombre para el tipo de imagen. Una vez que Tk_CreatePhotoImageFormat retorna, este nombre puede usarse en la opción de configuración y subcomando de imagen fotográfica -format. La página del manual de la imagen fotográfica (photo(n)) describe cómo se eligen los formatos de archivo de imagen en función de sus nombres y el valor dado a la opción -format. El primer carácter de formatPtr->name no debe ser un carácter en mayúscula del conjunto de caracteres ASCII (es decir, uno de los caracteres A-Z). Dichos nombres se utilizan solo para la compatibilidad con interfaces heredadas (ver más abajo).

FILEMATCHPROC

formatPtr->fileMatchProc proporciona la dirección de un procedimiento para que Tk lo llame cuando esté buscando un manejador de formato de archivo de imagen adecuado para leer datos en un archivo determinado. formatPtr->fileMatchProc debe coincidir con el siguiente prototipo:

typedef int Tk_ImageFileMatchProc(
        Tcl_Channel chan,
        const char *fileName,
        Tcl_Obj *format,
        int *widthPtr,
        int *heightPtr,
        Tcl_Interp *interp);
El argumento fileName es el nombre del archivo que contiene los datos de la imagen, que está abierto para lectura como chan. El argumento format contiene el valor dado para la opción -format, o NULL si la opción no se especificó. Si los datos en el archivo parecen estar en el formato admitido por este manejador, el procedimiento formatPtr->fileMatchProc debe almacenar el ancho y alto de la imagen en *widthPtr y *heightPtr respectivamente, y retornar 1. De lo contrario, debe retornar 0.

STRINGMATCHPROC

formatPtr->stringMatchProc proporciona la dirección de un procedimiento para que Tk lo llame cuando esté buscando un manejador de formato de archivo de imagen adecuado para leer datos desde una cadena dada. formatPtr->stringMatchProc debe coincidir con el siguiente prototipo:

typedef int Tk_ImageStringMatchProc(
        Tcl_Obj *data,
        Tcl_Obj *format,
        int *widthPtr,
        int *heightPtr,
        Tcl_Interp *interp);
El argumento data apunta al objeto que contiene los datos de la imagen. El argumento format contiene el valor dado para la opción -format, o NULL si la opción no se especificó. Si los datos en la cadena parecen estar en el formato admitido por este manejador, el procedimiento formatPtr->stringMatchProc debe almacenar el ancho y alto de la imagen en *widthPtr y *heightPtr respectivamente, y retornar 1. De lo contrario, debe retornar 0.

FILEREADPROC

formatPtr->fileReadProc proporciona la dirección de un procedimiento para que Tk lo llame para leer datos de un archivo de imagen en una imagen fotográfica. formatPtr->fileReadProc debe coincidir con el siguiente prototipo:

typedef int Tk_ImageFileReadProc(
        Tcl_Interp *interp,
        Tcl_Channel chan,
        const char *fileName,
        Tcl_Obj *format,
        PhotoHandle imageHandle,
        int destX, int destY,
        int width, int height,
        int srcX, int srcY);
El argumento interp es el intérprete en el que se invocó el comando para leer la imagen; debe usarse para informar errores. Los datos de la imagen están en el archivo llamado fileName, que está abierto para lectura como chan. El argumento format contiene el valor dado para la opción -format, o NULL si la opción no se especificó. Los datos de la imagen en el archivo, o una subimagen de la misma, deben leerse en la imagen fotográfica identificada por el manejador imageHandle. La subimagen de los datos en el archivo tiene dimensiones width x height y tiene su esquina superior izquierda en las coordenadas (srcX,srcY). Debe almacenarse en la imagen fotográfica con su esquina superior izquierda en las coordenadas (destX,destY) utilizando el procedimiento Tk_PhotoPutBlock. El valor de retorno es un valor de retorno estándar de Tcl.

STRINGREADPROC

formatPtr->stringReadProc proporciona la dirección de un procedimiento para que Tk lo llame para leer datos desde una cadena en una imagen fotográfica. formatPtr->stringReadProc debe coincidir con el siguiente prototipo:

typedef int Tk_ImageStringReadProc(
        Tcl_Interp *interp,
        Tcl_Obj *data,
        Tcl_Obj *format,
        PhotoHandle imageHandle,
        int destX, int destY,
        int width, int height,
        int srcX, int srcY);
El argumento interp es el intérprete en el que se invocó el comando para leer la imagen; debe usarse para informar errores. El argumento data apunta a los datos de la imagen en forma de objeto. El argumento format contiene el valor dado para la opción -format, o NULL si la opción no se especificó. Los datos de la imagen en la cadena, o una subimagen de la misma, deben leerse en la imagen fotográfica identificada por el manejador imageHandle. La subimagen de los datos en la cadena tiene dimensiones width x height y tiene su esquina superior izquierda en las coordenadas (srcX,srcY). Debe almacenarse en la imagen fotográfica con su esquina superior izquierda en las coordenadas (destX,destY) utilizando el procedimiento Tk_PhotoPutBlock. El valor de retorno es un valor de retorno estándar de Tcl.

FILEWRITEPROC

formatPtr->fileWriteProc proporciona la dirección de un procedimiento para que Tk lo llame para escribir datos desde una imagen fotográfica a un archivo. formatPtr->fileWriteProc debe coincidir con el siguiente prototipo:

typedef int Tk_ImageFileWriteProc(
        Tcl_Interp *interp,
        const char *fileName,
        Tcl_Obj *format,
        Tk_PhotoImageBlock *blockPtr);
El argumento interp es el intérprete en el que se invocó el comando para escribir la imagen; debe usarse para informar errores. El archivo de destino es fileName. El argumento format contiene el valor dado para la opción -format, o NULL si la opción no se especificó. Los datos de la imagen que se van a escribir se encuentran en el bloque especificado por blockPtr. El procedimiento debe escribir los datos de imagen en formato de archivo según lo especificado por format en el archivo fileName. El valor de retorno es un valor de retorno estándar de Tcl.

STRINGWRITEPROC

formatPtr->stringWriteProc proporciona la dirección de un procedimiento para que Tk lo llame para escribir datos desde una imagen fotográfica a una cadena. formatPtr->stringWriteProc debe coincidir con el siguiente prototipo:

typedef int Tk_ImageStringWriteProc(
        Tcl_Interp *interp,
        Tcl_Obj *format,
        Tk_PhotoImageBlock *blockPtr);
El argumento interp es el intérprete en el que se invocó el comando para escribir la imagen; debe usarse para informar errores. El argumento format contiene el valor dado para la opción -format, o NULL si la opción no se especificó. Los datos de la imagen que se van a escribir se encuentran en el bloque especificado por blockPtr. El procedimiento debe escribir los datos de imagen en formato de archivo según lo especificado por format en el objeto Tcl devuelto. El valor de retorno es un valor de retorno estándar de Tcl.

COMENTARIOS

Cuando Tk lee o escribe datos de imagen, primero busca un manejador de formato que coincida con el valor de la opción -format, si se especificó. Si no se especificó ningún formato o si el manejador especificado no pudo manejar los datos (por ejemplo, devolvió 0 de su procedimiento de coincidencia), Tk itera a través de todos los manejadores registrados que admiten lectura de archivos o cadenas (según corresponda) y usa el primero que coincida con los datos. Los manejadores se registran llamando a Tk_CreatePhotoImageFormat. Es responsabilidad del código de la aplicación registrar todos los manejadores de formato de imagen que desea que estén disponibles. Se pueden registrar varios manejadores de formato de archivo para el mismo nombre, pero solo el primero será accesible para el usuario a través de la opción -format (consulte la sección NOMBRE anterior). Si se requieren varios manejadores para el mismo nombre, el usuario debe especificar el orden de registro apropiado, o Tk no podrá seleccionar el manejador correcto.

En la versión 8.4, se introdujo una interfaz de programa para la creación de imágenes fotográficas, que permite a los desarrolladores de aplicaciones registrar sus propios formatos de archivo de imagen. A partir de la versión 8.5, la interfaz de programa solo puede ser utilizada por el código de extensión y el código de aplicación. Sin embargo, todavía se puede llamar a Tk_CreatePhotoImageFormat, que es un procedimiento de la biblioteca Tk.

Asegúrese de que los nombres de formato de archivo especificados en formatPtr->name no contengan caracteres en mayúsculas del conjunto de caracteres ASCII. Tk utiliza estos nombres exclusivamente para fines de compatibilidad con versiones anteriores y los considera sensibles a mayúsculas y minúsculas. Si se utiliza un carácter en mayúscula, Tk dará un error.

EJEMPLO

Para registrar un manejador de formato de archivo llamado "gif" para archivos GIF:

static Tk_PhotoImageFormat gifFormat = {
    "gif",               /* name */
    Tk_GifFileMatch,     /* fileMatchProc */
    NULL,                /* stringMatchProc */
    Tk_GifFileRead,      /* fileReadProc */
    NULL,                /* stringReadProc */
    NULL,                /* fileWriteProc */
    NULL                 /* stringWriteProc */
};
...
Tk_CreatePhotoImageFormat(&gifFormat);

Tk_CreatePhotoImageFormat(3) — Tk

NAME

Tk_CreatePhotoImageFormat, Tk_CreateOldPhotoformat — define a new photo image format

SYNOPSIS

#include <tk.h>

int
Tk_CreatePhotoImageFormat(
        Tcl_Interp *interp,
        const char *formatName,
        Tk_ImageFileMatchProc *fileMatchProc,
        Tk_ImageFileReadProc *fileReadProc,
        Tk_ImageFileWriteProc *fileWriteProc,
        Tk_ImageStringWriteProc *stringWriteProc,
        ClientData clientData);

int
Tk_CreateOldPhotoformat(
        Tcl_Interp *interp,
        const char *formatName,
        Tk_OldImageFileMatchProc *fileMatchProc,
        Tk_OldImageFileReadProc *fileReadProc,
        Tk_OldImageFileWriteProc *fileWriteProc,
        Tk_OldImageStringWriteProc *stringWriteProc,
        ClientData clientData);

ARGUMENTS

Tcl_Interp *interp
Interpreter to use for reporting errors.
const char *formatName
Name of the new format. This is the string that will be used with the -format option of the image create photo command.
Tk_ImageFileMatchProc *fileMatchProc
Procedure to call to determine if a file contains an image in this format.
Tk_ImageFileReadProc *fileReadProc
Procedure to call to read an image from a file.
Tk_ImageFileWriteProc *fileWriteProc
Procedure to call to write an image to a file.
Tk_ImageStringWriteProc *stringWriteProc
Procedure to call to write an image to a string.
ClientData clientData
Arbitrary data that will be passed to the callback procedures.

DESCRIPTION

The Tk_CreatePhotoImageFormat function is used by extensions to Tk to register new photo image formats. The image subsystem in Tk uses these formats to handle images created by the <code>image create photo</code> command. When a new photo image is created, Tk calls the fileMatchProc for each registered format, attempting to find one that can handle the given file. If a match is found, Tk calls the corresponding fileReadProc to read the image data.

A format must provide at least one of fileReadProc or stringWriteProc. If fileReadProc is provided, fileMatchProc must also be provided. If fileWriteProc is provided, fileMatchProc must also be provided.

The Tk_CreateOldPhotoformat function is provided for compatibility with older versions of Tk. It is strongly recommended that new code use Tk_CreatePhotoImageFormat.

The formatName argument specifies the name of the new format. This is the string that should be used with the -format option of the image create photo command.

The clientData argument is application-specific data that will be passed to each of the callback procedures. It is typically used to pass a pointer to a structure containing format-specific information, such as magic numbers or other data needed by the callbacks.

The callback procedures all have the following structure:

Tk_ImageFileMatchProc *fileMatchProc
A pointer to a procedure that Tk will call to determine if a given file contains an image in this format. The procedure should have the following prototype:
typedef int (Tk_ImageFileMatchProc)(
        Tcl_Interp *interp,
        const char *fileName,
        Tcl_Channel chan,
        const char *formatString,
        int *matchPtr);

The procedure should return TCL_OK on success and a Tcl error code otherwise. If the file is not in this format, the procedure should set `*matchPtr` to 0 and return TCL_OK. If the file is in this format, it should set `*matchPtr` to 1 and return TCL_OK. If an error occurs, it should set an error message in the interpreter and return an error code.

The fileMatchProc is called with arguments as follows: interp is the interpreter in which the command was invoked; fileName is the name of the file to check; chan is an open channel to the file; formatString is the value specified for the -format option, or NULL if the option was not specified; and matchPtr is a pointer to an integer that should be set to 1 if the file matches the format, or 0 otherwise.

Tk_ImageFileReadProc *fileReadProc

typedef int (Tk_ImageFileReadProc)(
        Tcl_Interp *interp,
        const char *fileName,
        Tcl_Channel chan,
        const char *formatString,
        Tk_PhotoImageBlock *blockPtr);

The procedure should read an image from the file and fill in the fields of the structure pointed to by blockPtr. It should return TCL_OK on success or an error code otherwise. It should set an error message in the interpreter if an error occurs.

The fileReadProc is called with arguments as follows: interp is the interpreter in which the command was invoked; fileName is the name of the file to read; chan is an open channel to the file; formatString is the value specified for the -format option, or NULL if the option was not specified; and blockPtr is a pointer to a Tk_PhotoImageBlock structure that should be filled in with the image data.

The Tk_PhotoImageBlock structure is defined as follows:

typedef struct Tk_PhotoImageBlock {
    char *pixelData;         /* Pointer to pixel data. */
    int  *width;             /* Pointer to width in pixels. */
    int  *height;            /* Pointer to height in pixels. */
    int  *pitch;             /* Number of bytes per scanline. */
    int  *pixelSize;         /* Number of bytes per pixel. */
    unsigned char *red;      /* Table mapping pixel data to red values. */
    unsigned char *green;    /* Table mapping pixel data to green values. */
    unsigned char *blue;     /* Table mapping pixel data to blue values. */
    unsigned char *alpha;    /* Table mapping pixel data to alpha values. */
} Tk_PhotoImageBlock;

The pixelData field should point to an array of pixel data. The width and height fields should point to integers containing the image width and height. The pitch field should point to an integer containing the number of bytes per scanline. The pixelSize field should point to an integer containing the number of bytes per pixel. The red, green, blue, and alpha fields should point to arrays of unsigned chars that map the pixel data to color values. These arrays should be indexed by the pixel data. For example, if the pixel data is stored as 8-bit values, then red[i] would be the red value for pixel data i.

The fileWriteProc argument is a pointer to a procedure that Tk will call to write an image to a file. The procedure should have the following prototype:

typedef int (Tk_ImageFileWriteProc)(
        Tcl_Interp *interp,
        const char *fileName,
        const char *formatString,
        Tk_PhotoImageBlock *blockPtr);

The procedure should write the image data to the specified file in the given format. It should return TCL_OK on success or an error code otherwise. It should set an error message in the interpreter if an error occurs.

The fileWriteProc is called with arguments as follows: interp is the interpreter in which the command was invoked; fileName is the name of the file in which to write the image data; formatString is the value specified for the -format option, or NULL if the option was not specified; and blockPtr is a pointer to a Tk_PhotoImageBlock structure describing the image data to be written.

The stringWriteProc argument is a pointer to a procedure that Tk will call to write an image to a string. The procedure should have the following prototype:

typedef int (Tk_ImageStringWriteProc)(
        Tcl_Interp *interp,
        const char *formatString,
        Tk_PhotoImageBlock *blockPtr);

The procedure should write the image data to the interpreter's result in the specified format. It should return TCL_OK on success or an error code otherwise. It should set an error message in the interpreter if an error occurs.

The stringWriteProc is called with arguments as follows: interp is the interpreter in which the command was invoked; formatString is the value specified for the -format option, or NULL if the option was not specified; and blockPtr is a pointer to a Tk_PhotoImageBlock structure describing the image data to be converted.

The return value from Tk_CreatePhotoImageFormat is TCL_OK if the format was created successfully, or TCL_ERROR if an error occurred (e.g., if a format with the same name already exists).

FILEMATCHPROC

The formatPtr->fileMatchProc procedure is called by Tk to determine if a file contains an image in this format. formatPtr->fileMatchProc must match the following prototype:

typedef int Tk_ImageFileMatchProc(
        Tcl_Interp *interp,
        const char *fileName,
        Tcl_Channel chan,
        const char *formatString,
        int *matchPtr);

The interp argument is the interpreter in which the command was invoked. It should be used for reporting errors. The fileName argument points to the name of the file that is being checked. The chan argument is an open channel to the file. The formatString argument contains the value given for the -format option, or NULL if the option was not specified. The matchPtr argument points to an integer that must be set by the procedure. If the file matches the format, the procedure should set `*matchPtr` to 1; otherwise, it should set `*matchPtr` to 0. The procedure should return TCL_OK if it was able to determine whether the file matches or not, and an error code otherwise. If the procedure returns an error code, the value of `*matchPtr` is irrelevant.

FILEREADPROC

The formatPtr->fileReadProc procedure is called by Tk to read image data from a file into memory. formatPtr->fileReadProc must match the following prototype:

typedef int Tk_ImageFileReadProc(
        Tcl_Interp *interp,
        const char *fileName,
        Tcl_Channel chan,
        const char *formatString,
        Tk_PhotoImageBlock *blockPtr);

The interp argument is the interpreter in which the command was invoked; it should be used for reporting errors. The fileName argument points to the string giving the name of the file to be read. The chan argument is an open channel to the file. The formatString argument contains the value given for the -format option, or NULL if the option was not specified. The format string can contain extra characters after the name of the format. If appropriate, the formatPtr->fileReadProc procedure may interpret these characters to specify further details about the image file. The blockPtr argument points to the Tk_PhotoImageBlock structure to be filled in with image data. The procedure should return TCL_OK on success, or a Tcl error code if an error occurred. If an error occurs, an error message should be set in the interpreter.

FILEWRITEPROC

The formatPtr->fileWriteProc procedure is called by Tk to write image data from memory to a file. formatPtr->fileWriteProc must match the following prototype:

typedef int Tk_ImageFileWriteProc(
        Tcl_Interp *interp,
        const char *fileName,
        const char *formatString,
        Tk_PhotoImageBlock *blockPtr);

The interp argument is the interpreter in which the command was invoked; it should be used for reporting errors. The fileName argument points to the string giving the name of the file in which to write the image data. The formatString argument contains the value given for the -format option, or NULL if the option was not specified. The format string can contain extra characters after the name of the format. If appropriate, the formatPtr->fileWriteProc procedure may interpret these characters to specify further details about the image file. The return value is a standard Tcl return value.

STRINGWRITEPROC

formatPtr->stringWriteProc provides the address of a procedure for Tk to call to translate image data from a photo image into a string. formatPtr->stringWriteProc must match the following prototype:

typedef int Tk_ImageStringWriteProc(
        Tcl_Interp *interp,
        const char *formatString,
        Tk_PhotoImageBlock *blockPtr);

The interp argument is the interpreter in which the command was invoked to convert the image; it should be used for reporting errors. The image data to be converted are in memory and are described by the Tk_PhotoImageBlock structure pointed to by blockPtr; see the manual page FindPhoto(3) for details. The data for the string should be put in the interpreter interp result. The formatString argument contains the value given for the -format option, or NULL if the option was not specified. The format string can contain extra characters after the name of the format. If appropriate, the formatPtr->stringWriteProc procedure may interpret these characters to specify further details about the image file. The return value is a standard Tcl return value.

LEGACY INTERFACE SUPPORT

In Tk 8.2 and earlier, the definition of all the function pointer types stored in fields of a Tk_PhotoImageFormat struct were incompatibly different. Legacy programs and libraries dating from those days may still contain code that defines extended Tk photo image formats using the old interface. The Tk header file will still support this legacy interface if the code is compiled with the macro USE_OLD_IMAGE defined. Alternatively, the legacy interfaces are used if the first character of formatPtr->name is an uppercase ASCII character (A-Z), and explicit casts are used to forgive the type mismatch. For example,

static Tk_PhotoImageFormat myFormat = {
    "MyFormat",
    (Tk_ImageFileMatchProc *) FileMatch,
    NULL,
    (Tk_ImageFileReadProc *) FileRead,
    NULL,
    NULL,
    NULL
};

would define a minimal Tk_PhotoImageFormat that operates provide only file reading capability, where FileMatch and FileRead are written according to the legacy interfaces of Tk 8.2 or earlier.

Any stub-enabled extension providing an extended photo image format via the legacy interface enabled by the USE_OLD_IMAGE macro that is compiled against Tk 8.5 headers and linked against the Tk 8.5 stub library will produce a file that can be loaded only into interps with Tk 8.5 or later; that is, the normal stub-compatibility rules. If a developer needs to generate from such code a file that is loadable into interps with Tk 8.4 or earlier, they must use Tk 8.4 headers and stub libraries to do so.

Any new code written today should not make use of the legacy interfaces. Expect their support to go away in Tk 9.
