Tk_CreateBindingTable(3) Procedimientos de la biblioteca Tk Tk_CreateBindingTable(3)

NOMBRE

Tk_CreateBindingTable, Tk_DeleteBindingTable, Tk_CreateBinding, Tk_DeleteBinding, Tk_GetBinding, Tk_GetAllBindings, Tk_DeleteAllBindings, Tk_BindEvent - invocar scripts en respuesta a eventos X

SINOPSIS

#include <tk.h>

Tk_BindingTable
Tk_CreateBindingTable(interp)

Tk_DeleteBindingTable(bindingTable)

unsigned long
Tk_CreateBinding(interp, bindingTable, object, eventString, script, append)

int
Tk_DeleteBinding(interp, bindingTable, object, eventString)

const char *
Tk_GetBinding(interp, bindingTable, object, eventString)

Tk_GetAllBindings(interp, bindingTable, object)

Tk_DeleteAllBindings(bindingTable, object)

Tk_BindEvent(bindingTable, eventPtr, tkwin, numObjects, objectPtr)

ARGUMENTOS

Tcl_Interp *interp (entrada)
Intérprete a usar al invocar bindings en la tabla de bindings. También se usa para devolver resultados y errores de los procedimientos de binding.
Tk_BindingTable bindingTable (entrada)
Token para la tabla de bindings; debe haber sido devuelto por alguna llamada anterior a Tk_CreateBindingTable.
ClientData object (entrada)
Identifica el objeto con el que se asocia el binding.
const char *eventString (entrada)
Cadena que describe la secuencia de eventos.
const char *script (entrada)
Script de Tcl a invocar cuando se activa el binding.
int append (entrada)
Distinto de cero significa añadir script al script existente para el binding, si lo hay; cero significa reemplazar el script existente por uno nuevo.
XEvent *eventPtr (entrada)
Evento X a hacer coincidir con los bindings en bindingTable.
Tk_Window tkwin (entrada)
Identificador de cualquier ventana en la pantalla donde ocurrió el evento. Se usa para encontrar información relacionada con la pantalla, como mapas de teclado.
int numObjects (entrada)
Número de identificadores de objetos apuntados por objectPtr.
ClientData *objectPtr (entrada)
Apuntando a un array de identificadores de objetos: se considerarán los bindings para cada uno de estos objetos en orden de primero a último.

DESCRIPCIÓN

Estos procedimientos proporcionan un mecanismo de propósito general para crear e invocar bindings. Los bindings se organizan en términos de tablas de bindings. Una tabla de bindings consiste en una colección de bindings más un historial de eventos recientes. Dentro de una tabla de bindings, los bindings se asocian con objetos. El significado de un objeto lo definen los clientes del paquete de bindings. Por ejemplo, Tk usa una tabla de bindings para mantener todos los bindings creados por el comando bind. Para esta tabla, los objetos son punteros a cadenas como nombres de ventanas, nombres de clases u otras etiquetas de bindings como all. Tk también mantiene una tabla de bindings separada para cada widget de canvas, que gestiona los bindings creados por el comando de widget bind del canvas; dentro de esta tabla, un objeto es un puntero a la estructura interna de un elemento de canvas o un Tk_Uid que identifica una etiqueta.

El procedimiento Tk_CreateBindingTable crea una nueva tabla de bindings y asocia interp con ella (cuando se invocan los bindings en la tabla, los scripts se evaluarán en interp). Tk_CreateBindingTable devuelve un token para la tabla, que debe usarse en llamadas a otros procedimientos como Tk_CreateBinding o Tk_BindEvent.

Tk_DeleteBindingTable libera todo el estado asociado con una tabla de bindings. Una vez que devuelve, el llamador no debe volver a usar el token bindingTable.

Tk_CreateBinding añade un nuevo binding a una tabla existente. El argumento object identifica el objeto al que se asocia el binding, y puede ser cualquier valor de una sola palabra. Típicamente es un puntero a una cadena o estructura de datos. El argumento eventString identifica el evento o secuencia de eventos para el binding; consulte la documentación del comando bind para una descripción de su formato. script es el script de Tcl que se evaluará cuando se active el binding. append indica qué hacer si ya existe un binding para object y eventString: si append es cero, entonces script reemplaza el script antiguo; si append es distinto de cero, entonces el nuevo script se añade al antiguo. Tk_CreateBinding devuelve una máscara de eventos X para todos los eventos asociados con los bindings. Esta información puede ser útil para invocar XSelectInput para seleccionar eventos relevantes, o para desautorizar el uso de ciertos eventos en bindings. Si ocurrió un error al crear el binding (p. ej., eventString se refiere a un evento inexistente), entonces se devuelve 0 y se deja un mensaje de error como resultado del intérprete interp.

Tk_DeleteBinding elimina de bindingTable el binding dado por object y eventString, si existe tal binding. Tk_DeleteBinding siempre devuelve TCL_OK. En algunos casos puede restablecer el resultado del intérprete al valor predeterminado vacío.

Tk_GetBinding devuelve un puntero al script asociado con eventString y object en bindingTable. Si no existe tal binding, se devuelve NULL y se deja un mensaje de error como resultado del intérprete interp.

Tk_GetAllBindings devuelve en el resultado de interp una lista de todas las cadenas de eventos para las que existen bindings en bindingTable asociados con object. Si no hay bindings para object, el resultado será una cadena vacía.

Tk_DeleteAllBindings elimina todos los bindings en bindingTable que están asociados con object.

Tk_BindEvent se llama para procesar un evento. Realiza una copia del evento en una lista de historial interna asociada con la tabla de bindings, luego busca bindings que coincidan con el evento. Tk_BindEvent procesa cada uno de los objetos apuntados por objectPtr en turno. Para cada objeto, encuentra todos los bindings que coinciden con el historial de eventos actual, selecciona el binding más específico utilizando el mecanismo de prioridad descrito en la documentación de bind, e invoca el script para ese binding. Si no hay bindings que coincidan para un objeto particular, entonces se omite el objeto. Tk_BindEvent continúa a través de todos los objetos, manejando excepciones como errores, break y continue como se describe en la documentación de bind.
