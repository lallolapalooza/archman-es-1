ARGUMENTOS

Tcl_Interp *interp (entrada)
Intérprete a utilizar para la notificación de errores.
Tk_Window tkwin (entrada)
Token para la ventana (para todos los procedimientos excepto Tk_Get3DBorder, debe ser la ventana para la cual se asignó el borde).
Tcl_Obj *objPtr (entrada)
Puntero al valor cuya descripción del color corresponde al fondo (áreas planas). Los bordes iluminados serán más brillantes que este y los bordes sombreados serán más oscuros que este.
const char *colorName (entrada)
Igual que objPtr excepto que el valor se proporciona como una cadena en lugar de un valor.
Drawable drawable (entrada)
Token X de la ventana o pixmap; indica dónde se dibujarán los gráficos. Debe ser la ventana X para tkwin o un pixmap con la misma pantalla y profundidad que tkwin.
Tk_3DBorder border (entrada)
Token para el borde asignado previamente en una llamada a Tk_Get3DBorder.
int x (entrada)
Coordenada X de la esquina superior izquierda del rectángulo que describe el borde o biselado, en píxeles.
int y (entrada)
Coordenada Y de la esquina superior izquierda del rectángulo que describe el borde o biselado, en píxeles.
int width (entrada)
Ancho del rectángulo que describe el borde o biselado, en píxeles.
int height (entrada)
Altura del rectángulo que describe el borde o biselado, en píxeles.
int borderWidth (entrada)
Ancho del borde en píxeles. Un valor positivo significa que el borde está dentro del rectángulo dado por x, y, width, height; un valor negativo significa que el borde está fuera del rectángulo.
int relief (entrada)
Indica la posición 3D del interior del valor con respecto al exterior; debe ser TK_RELIEF_RAISED, TK_RELIEF_SUNKEN, TK_RELIEF_GROOVE, TK_RELIEF_SOLID o TK_RELIEF_RIDGE (también puede ser TK_RELIEF_FLAT para Tk_Fill3DRectangle).
XPoint *pointPtr (entrada)
Puntero a un array de puntos que describen el conjunto de vértices de un polígono. El polígono no necesita estar cerrado (se cerrará automáticamente si no lo está).
int numPoints (entrada)
Número de puntos en *pointPtr.
int polyBorderWidth (entrada)
Ancho del borde en píxeles. Si es positivo, el borde se dibuja a la izquierda de la trayectoria dada por pointPtr; si es negativo, el borde se dibuja a la derecha de la trayectoria. Si leftRelief es TK_RELIEF_GROOVE o TK_RELIEF_RIDGE, el borde se centrará en la trayectoria.
int leftRelief (entrada)
Altura del camino del borde izquierdo del polígono con respecto al derecho. TK_RELIEF_RAISED significa que el lado izquierdo debe parecer más alto y TK_RELIEF_SUNKEN significa que el lado derecho debe parecer más alto; TK_RELIEF_GROOVE y TK_RELIEF_RIDGE significan lo obvio. Para Tk_Fill3DPolygon, TK_RELIEF_FLAT también puede especificarse para indicar que no hay diferencia de altura.
int leftBevel (entrada)
Si es distinto de cero, este bisel forma el lado izquierdo del valor; si es cero, forma el lado derecho.
int leftIn (entrada)
Si es distinto de cero, el borde izquierdo del biselado horizontal se inclina hacia adentro, de modo que la parte inferior del borde está más a la derecha que la superior. Si es cero, el borde se inclina hacia afuera, de modo que la parte inferior está más a la izquierda que la superior.
int rightIn (entrada)
Si es distinto de cero, el borde derecho del biselado horizontal se inclina hacia adentro, de modo que la parte inferior del borde está más a la izquierda que la superior. Si es cero, el borde se inclina hacia afuera, de modo que la parte inferior está más a la derecha que la superior.
int topBevel (entrada)
Si es distinto de cero, este bisel forma el lado superior del valor; si es cero, forma el lado inferior.
int which (entrada)
Especifica cuál de los contextos gráficos del borde se desea. Debe ser TK_3D_FLAT_GC, TK_3D_LIGHT_GC o TK_3D_DARK_GC.

DESCRIPCIÓN

Estos procedimientos proporcionan facilidades para dibujar bordes de ventanas de una manera que produce una apariencia tridimensional. Tk_Alloc3DBorderFromObj asigna colores y Pixmaps necesarios para dibujar un borde en la ventana dada por el argumento tkwin. El valor de objPtr es un nombre de color estándar de Tk que determina los colores del borde. El color indicado por objPtr no se usará realmente en el borde; indica el color de fondo de la ventana (es decir, un color para superficies planas). Las porciones iluminadas del borde aparecerán más brillantes que las indicadas por objPtr, y las porciones sombreadas del borde aparecerán más oscuras que objPtr.

Tk_Alloc3DBorderFromObj devuelve un token que puede ser utilizado en llamadas posteriores a Tk_Draw3DRectangle. Si ocurre un error al asignar información para el borde (por ejemplo, se dio un nombre de color inválido) entonces se devuelve NULL y se deja un mensaje de error como resultado del intérprete interp. Si devuelve con éxito, Tk_Alloc3DBorderFromObj almacena información sobre el valor de retorno en objPtr, lo que acelera las llamadas futuras a Tk_Alloc3DBorderFromObj con el mismo objPtr y tkwin.

Tk_Get3DBorder es idéntico a Tk_Alloc3DBorderFromObj excepto que el color se especifica con una cadena en lugar de un valor. Esto evita que Tk_Get3DBorder almacene en caché el valor de retorno, por lo que Tk_Get3DBorder es menos eficiente que Tk_Alloc3DBorderFromObj.

Tk_Get3DBorderFromObj devuelve el token de un borde existente, dado el nombre de la ventana y el color utilizados para crear el borde. Tk_Get3DBorderFromObj no crea realmente el borde; ya debe haber sido creado con una llamada anterior a Tk_Alloc3DBorderFromObj o Tk_Get3DBorder. El valor de retorno se almacena en caché en objPtr, lo que acelera las llamadas futuras a Tk_Get3DBorderFromObj con el mismo objPtr y tkwin.

Una vez creado un objeto de borde, se puede invocar Tk_Draw3DRectangle para dibujar el borde. El argumento tkwin especifica la ventana para la que se asignó el borde, y drawable especifica una ventana o pixmap en la que se dibujará el borde. Drawable no tiene por qué referirse a la misma ventana que tkwin, pero debe referirse a un pixmap o ventana compatible: uno asociado con la misma pantalla y con la misma profundidad que tkwin. Los argumentos x, y, width e height definen el cuadro delimitador de la región del borde dentro de drawable (generalmente x e y son cero y width y height son las dimensiones de la ventana), y borderWidth especifica el número de píxeles realmente ocupados por el borde. El argumento relief indica cuál de varios efectos tridimensionales se desea: TK_RELIEF_RAISED significa que el interior del rectángulo debe aparecer elevado con respecto al exterior del rectángulo, y TK_RELIEF_SUNKEN significa que el interior debe aparecer deprimido. TK_RELIEF_GROOVE y TK_RELIEF_RIDGE significan que debe aparecer una ranura o una cresta alrededor del exterior del rectángulo.

ARGUMENTS

All procedures that take a border argument expect a value returned by Tk_Alloc3DBorder or Tk_Get3DBorder.

All procedures that take a tkwin argument expect a window token returned by Tk_MainWindow or Tk_NameToWindow.

The border argument is a token for a 3D border. This token may be retrieved from a color string using Tk_Alloc3DBorder or Tk_Get3DBorder.

The tkwin argument is a token for a window. This token is needed to find the screen and display information associated with the window.

The drawable argument is the destination for drawing.

The x, y, width, and height arguments describe the rectangular area to be drawn. These coordinates are relative to the top-left corner of the drawable.

The borderWidth argument is the width of the border to draw, in pixels.

The relief argument specifies the desired 3D effect. It can have any of the following values: TK_RELIEF_FLAT, TK_RELIEF_RAISED, TK_RELIEF_SUNKEN, TK_RELIEF_GROOVE, TK_RELIEF_RIDGE. See the tk_relief manual page for a description of these values.

The pointPtr and numPoints arguments describe a polygon. pointPtr points to an array of Tk_Point structures, where each Tk_Point contains x and y coordinates. numPoints is the number of points in the array.

The polyBorderWidth argument specifies the width of the border around the polygon, in pixels.

The leftRelief and rightRelief arguments specify the relief style for the left and right sides of the polygon, respectively. Possible values are TK_RELIEF_RAISED and TK_RELIEF_SUNKEN.

The leftBorder and topBorder arguments to Tk_3DVerticalBevel specify the width of the border on the left and top sides of the rectangle, respectively. These arguments are used to control how much of the rectangle is drawn as border, and how much is left as flat background.

The leftIn and rightIn arguments to Tk_3DHorizontalBevel control the shape of the mitered corners. A value of 1 means the bottom edge is shorter than the top; a value of 0 means the bottom edge is longer.

The which argument to Tk_3DBorderGC specifies which graphics context to return. It may be one of TK_3D_FLAT_GC, TK_3D_LIGHT_GC, or TK_3D_DARK_GC.

For Tk_Free3DBorderFromObj, interp is the current Tcl interpreter, tkwin is the window token, and colorObj is a Tcl object containing the color string used to create the border.

DESCRIPTION

These procedures provide facilities for drawing objects with a three-dimensional appearance. The core idea is to use two shades of a base color to simulate light and shadow. The base color is specified by the border argument, which is created using Tk_Alloc3DBorder or Tk_Get3DBorder.

Tk_Fill3DRectangle fills the rectangular area specified by x, y, width, and height with the background color associated with border. Then, it draws a 3D border around the area using the colors specified by border. The borderWidth argument determines how many pixels thick the border is, and relief determines the 3D effect. TK_RELIEF_FLAT means no border is drawn.

Tk_Draw3DRectangle is similar to Tk_Fill3DRectangle, except that it does not fill the rectangle with the background color. It only draws the border.

Tk_Fill3DPolygon is analogous to Tk_Fill3DRectangle. It first fills the polygonal area defined by pointPtr and numPoints with the background color from border. Then, it calls Tk_Draw3DPolygon to draw a border around the area (unless leftRelief is TK_RELIEF_FLAT, in which case no border is drawn).

Tk_Draw3DPolygon draws a border around a polygon. The pointPtr and numPoints arguments define the polygon's boundary. polyBorderWidth specifies the border width. leftRelief and rightRelief specify the desired appearance of the left and right sides of the border, respectively. If the polygon is not self-intersecting, these procedures can create the appearance of a raised or sunken polygon.

Tk_3DVerticalBevel and Tk_3DHorizontalBevel are lower-level procedures used by the rectangle and polygon drawing routines. They can also be used directly to draw beveled edges. Tk_3DVerticalBevel draws a vertical beveled edge, and Tk_3DHorizontalBevel draws a horizontal beveled edge. The relief argument controls whether the bevel is raised or sunken.

Tk_SetBackgroundFromBorder ensures that the background color of the window tkwin is compatible with the border. For color displays, this usually means setting the background to the border's base color. For monochrome displays, it may use a stipple pattern to create contrast.

Tk_NameOf3DBorder returns the name of the color used to create the 3D border.

Tk_3DBorderColor returns an XColor structure representing the color used for flat surfaces within the border. This color is suitable for use with the X drawing functions.

Tk_3DBorderGC returns a graphics context (GC) suitable for drawing parts of the 3D border. The which argument selects the GC for flat surfaces (TK_3D_FLAT_GC), light shadows (TK_3D_LIGHT_GC), or dark shadows (TK_3D_DARK_GC).

Tk_Free3DBorderFromObj and Tk_Free3DBorder release the resources associated with a 3D border. You should call one of these functions once for each call to Tk_Alloc3DBorderFromObj or Tk_Get3DBorder.
