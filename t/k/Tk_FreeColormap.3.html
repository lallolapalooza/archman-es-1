Tk_GetColormap(3) Procedimientos de la biblioteca Tk Tk_GetColormap(3)

NOMBRE

Tk_GetColormap, Tk_PreserveColormap, Tk_FreeColormap - asignar y liberar mapas de color

SINOPSIS

#include <tk.h>

Colormap
Tk_GetColormap(interp, tkwin, string)

Tk_PreserveColormap(display, colormap)

Tk_FreeColormap(display, colormap)

ARGUMENTOS

Tcl_Interp *interp (entrada)
Intérprete a usar para reportar errores.
Tk_Window tkwin (entrada)
Token para la ventana en la que se utilizará el mapa de color.
const char *string (entrada)
Selecciona un mapa de color: ya sea new o el nombre de una ventana con la misma pantalla y visual que tkwin.
Display *display (entrada)
Pantalla para la que se asignó colormap.
Colormap colormap (entrada)
Mapa de color a liberar o preservar; debe haber sido devuelto por una llamada previa a Tk_GetColormap o Tk_GetVisual.

DESCRIPCIÓN

Estos procedimientos se utilizan para gestionar mapas de color. Tk_GetColormap devuelve un mapa de color adecuado para su uso en tkwin. Si su argumento string es new, se crea un nuevo mapa de color; de lo contrario, string debe ser el nombre de otra ventana con la misma pantalla y visual que tkwin, y se devuelve el mapa de color de esa ventana. Si string no tiene sentido, o si se refiere a una ventana en una pantalla diferente a la de tkwin o con un visual diferente al de tkwin, entonces Tk_GetColormap devuelve None y deja un mensaje de error en el resultado de interp.

Tk_PreserveColormap incrementa el contador de referencias interno para un mapa de color devuelto previamente por Tk_GetColormap, lo que permite que el mapa de color se almacene en varias ubicaciones sin saber en qué orden se liberarán.

Se debe llamar a Tk_FreeColormap cuando un mapa de color devuelto por Tk_GetColormap ya no sea necesario. Tk mantiene un contador de referencias para cada mapa de color devuelto por Tk_GetColormap, por lo que eventualmente debería haber una llamada a Tk_FreeColormap por cada llamada a Tk_GetColormap y cada llamada a Tk_PreserveColormap. Cuando el contador de referencias de un mapa de color llega a cero, Tk libera el mapa de color X.

Tk_GetVisual y Tk_GetColormap funcionan juntos, de tal manera que un nuevo mapa de color creado por Tk_GetVisual puede ser devuelto posteriormente por Tk_GetColormap. El mecanismo de conteo de referencias para mapas de color incluye ambos procedimientos, por lo que los llamantes de Tk_GetVisual también deben llamar a Tk_FreeColormap para liberar el mapa de color. Si se llama a Tk_GetColormap con un valor de string de new, el mapa de color resultante nunca será devuelto por Tk_GetVisual; sin embargo, puede ser utilizado en otras ventanas llamando a Tk_GetColormap con el nombre de la ventana original como string.
