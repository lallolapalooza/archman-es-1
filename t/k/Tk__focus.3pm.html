NOMBRE

Tk::focus - Gestiona el foco de entrada

SINOPSIS

   $widget->focus

   $widget->focusOpción

   $widget->focusNext

   $widget->focusPrev

   $widget->focusFollowsMouse

DESCRIPCIÓN

Los métodos focus se utilizan para gestionar el foco de entrada de Tk. En cualquier momento dado, una ventana en cada pantalla se designa como la ventana de foco; cualquier pulsación o liberación de tecla para la pantalla se envía a esa ventana. Normalmente, el gestor de ventanas se encarga de redirigir el foco entre las ventanas de nivel superior de una pantalla. Por ejemplo, algunos gestores de ventanas establecen automáticamente el foco de entrada en una ventana de nivel superior siempre que el ratón entra en ella; otros redirigen el foco de entrada solo cuando el usuario hace clic en una ventana. Normalmente, el gestor de ventanas solo establece el foco en las ventanas de nivel superior, dejando que la aplicación se encargue de redirigir el foco entre los hijos de la de nivel superior.

Tk recuerda una ventana de foco para cada nivel superior (el descendiente más reciente de ese nivel superior que recibió el foco); cuando el gestor de ventanas da el foco a un nivel superior, Tk lo redirige automáticamente a la ventana recordada. Dentro de un nivel superior, Tk utiliza un modelo de foco explícito por defecto. Mover el ratón dentro de un nivel superior normalmente no cambia el foco; el foco cambia solo cuando un widget decide explícitamente reclamar el foco (por ejemplo, debido a un clic en un botón) o cuando el usuario escribe una tecla como Tab, que mueve el foco.

El método focusFollowsMouse puede invocarse para crear un modelo de foco implícito: reconfigura Tk de manera que el foco se establezca en una ventana cada vez que el ratón entra en ella. Los métodos focusNext y focusPrev implementan un orden de foco entre las ventanas de un nivel superior; se utilizan en los enlaces por defecto para Tab y Shift-Tab, entre otras cosas.

Los métodos focus pueden tomar cualquiera de las siguientes formas:

$widget->focusCurrent
Devuelve la ventana de foco en la pantalla que contiene el $widget, o una cadena vacía si ninguna ventana de esta aplicación tiene el foco en esa pantalla.
$widget->focus
Si la aplicación tiene actualmente el foco de entrada en la pantalla de $widget, este comando restablece el foco de entrada para la pantalla de $widget a $widget y devuelve una cadena vacía. Si la aplicación no tiene actualmente el foco de entrada en la pantalla de $widget, $widget será recordado como el foco para su nivel superior; la próxima vez que el foco llegue al nivel superior, Tk lo redirigirá a $widget.
$widget->focusForce
Establece el foco de la pantalla de $widget a $widget, incluso si la aplicación no tiene actualmente el foco de entrada para la pantalla. Este comando debe usarse con moderación, si es que se usa. En el uso normal, una aplicación no debe reclamar el foco para sí misma; en su lugar, debe esperar a que el gestor de ventanas le dé el foco.
$widget->focusLastfor
Devuelve el nombre de la ventana más reciente que tuvo el foco de entrada entre todas las ventanas del mismo nivel superior que $widget. Si ninguna ventana en ese nivel superior ha tenido nunca el foco de entrada, o si la ventana de foco más reciente ha sido eliminada, se devuelve el nivel superior. El valor de retorno es la ventana que recibirá el foco de entrada la próxima vez que el gestor de ventanas dé el foco al nivel superior.
$widget->focusNext
$widget->focusPrev
focusNext es un método de utilidad utilizado para la navegación por teclado, pero puede ser útil en otros contextos. Establece el foco en la siguiente ventana después de $widget en el orden de foco. El orden de foco está determinado por el orden de apilamiento de las ventanas y la estructura de la jerarquía de ventanas. Entre hermanos, el orden de foco es el mismo que el orden de apilamiento, siendo la ventana más baja la primera. Si una ventana tiene hijos, se visita primero la ventana, seguida de sus hijos (recursivamente), seguida de su siguiente hermano. Las ventanas de nivel superior distintas de $widget se omiten, por lo que focusNext nunca devuelve una ventana en un nivel superior diferente al de $widget.

Después de calcular la siguiente ventana, focusNext examina la opción -takefocus de la ventana para ver si debe omitirse. Si es así, focusNext continúa hacia la siguiente ventana en el orden de foco, hasta que finalmente encuentra una ventana que aceptará el foco o regresa a $widget.

focusPrev es similar a focusNext excepto que establece el foco en la ventana anterior a $widget en el orden de foco.

$widget->focusFollowsMouse
focusFollowsMouse cambia el modelo de foco de la aplicación a uno implícito donde la ventana bajo el ratón obtiene el foco. Después de que se llama a este procedimiento, cada vez que el ratón entra en una ventana, Tk le otorgará automáticamente el foco de entrada. El comando focus puede usarse para mover el foco a una ventana distinta de la que está bajo el ratón, pero tan pronto como el ratón se mueva a una nueva ventana, el foco saltará a esa ventana. Nota: actualmente no hay soporte incorporado para devolver la aplicación a un modelo de foco explícito; para hacerlo, tendrás que escribir un script que elimine los enlaces creados por focusFollowsMouse.

CUARTO DE PULGADA

Cuando una ventana interna recibe el foco de entrada, Tk en realidad no establece el foco X en esa ventana; en lo que respecta a X, el foco permanecerá en la ventana de nivel superior que contiene la ventana con el foco. Sin embargo, Tk genera eventos FocusIn y FocusOut como si el foco X estuviera en la ventana interna. Este enfoque resuelve una serie de problemas que ocurrirían si el foco X se moviera realmente; el hecho de que el foco X esté en el nivel superior es invisible a menos que se utilice código C para consultar directamente el servidor X.

SALVEDADES

Tenga en cuenta que para el widget Canvas, la llamada a focus debe estar completamente calificada. Esto se debe a que ya existe un método focus para el widget Canvas, que establece el foco en etiquetas de lienzo individuales.

    $canvas->Tk::focus

NOMBRE

Tk::focus - Manejo del foco en Tk

SINOPSIS

    use Tk;
    use Tk::focus qw(tk_focusFollowsMouse tk_focusNextWidget tk_focusPrevWidget tk_focusLastActiveWindow tk_focusViaName tk_focusWindow);

    # ... (configuración de la ventana principal y widgets)

    # Ejemplo de uso:
    # Hacer que el foco siga al ratón
    tk_focusFollowsMouse $widget_con_foco;

    # Mover el foco al siguiente widget
    tk_focusNextWidget $widget_actual;

    # Mover el foco al widget anterior
    tk_focusPrevWidget $widget_actual;

    # Obtener la ventana con el último foco activo
    my $ultima_ventana = tk_focusLastActiveWindow;

    # Establecer el foco a través del nombre
    tk_focusViaName $nombre_del_widget;

    # Establecer el foco a una ventana específica
    tk_focusWindow $widget_a_enfocar;

DESCRIPCIÓN

El módulo Tk::focus proporciona una colección de subrutinas para gestionar el comportamiento del foco en las aplicaciones Tk escritas en Perl.

El foco determina qué widget recibirá los eventos del teclado y del ratón. Estas subrutinas permiten un control preciso sobre cómo y cuándo cambia el foco.

  • tk_focusFollowsMouse($widget_con_foco): Configura el widget especificado para que reciba automáticamente el foco cuando el puntero del ratón se mueve sobre él. Si se pasa un argumento vacío o undef, desactiva este comportamiento para todos los widgets.
  • tk_focusNextWidget($widget_actual): Mueve el foco al siguiente widget en el orden de tabulación a partir del $widget_actual.
  • tk_focusPrevWidget($widget_actual): Mueve el foco al widget anterior en el orden de tabulación a partir del $widget_actual.
  • tk_focusLastActiveWindow(): Devuelve la ventana principal (Toplevel) que tuvo el foco activo más recientemente.
  • tk_focusViaName($nombre_del_widget): Establece el foco en el widget cuyo nombre se proporciona. El nombre debe ser una cadena que identifique de forma única al widget.
  • tk_focusWindow($widget_a_enfocar): Establece explícitamente el foco en el widget especificado por $widget_a_enfocar.

DETALLES

El orden de tabulación de los widgets se determina por la jerarquía de los widgets en la ventana y por cómo se crearon. Los widgets que se crean más tarde generalmente vienen después en el orden de tabulación.

La funcionalidad tk_focusFollowsMouse puede ser inconsistente en algunos entornos de escritorio o sistemas operativos.

Cuando se trabaja con múltiples ventanas Toplevel, tk_focusLastActiveWindow es útil para restaurar el foco a la ventana que el usuario estaba utilizando anteriormente.

ADVERTENCIAS

El uso excesivo de tk_focusFollowsMouse puede confundir a los usuarios si no se espera el cambio de foco inmediato.

Asegúrese de que los widgets a los que intenta enfocar existen y son visibles antes de llamar a las funciones de enfoque.

Las funciones de enfoque a veces pueden verse afectadas por el comportamiento del sistema operativo subyacente y el gestor de ventanas.
