NOMBRE

Tk_FindPhoto, Tk_PhotoPutBlock, Tk_PhotoPutZoomedBlock, Tk_PhotoGetImage, Tk_PhotoBlank, Tk_PhotoExpand, Tk_PhotoGetSize, Tk_PhotoSetSize - manipular los datos de imagen almacenados en una imagen de foto.

SINOPSIS

#include <tk.h>

Tk_PhotoHandle
Tk_FindPhoto(interp, imageName)

int
Tk_PhotoPutBlock(interp, handle, blockPtr, x, y, width, height,compRule)

int
Tk_PhotoPutZoomedBlock(interp, handle, blockPtr, x, y, width, height,zoomX, zoomY, subsampleX, subsampleY, compRule)

int
Tk_PhotoGetImage(handle, blockPtr)

void
Tk_PhotoBlank(handle)

int
Tk_PhotoExpand(interp, handle, width, height)

void
Tk_PhotoGetSize(handle, widthPtr, heightPtr)

int
Tk_PhotoSetSize(interp. handle, width, height)

ARGUMENTOS

Tcl_Interp *interp (entrada)
Intérprete en el que se creó la imagen y en el que se deben informar los errores.
const char *imageName (entrada)
Nombre de la imagen de foto.
Tk_PhotoHandle handle (entrada)
Identificador opaco que identifica la imagen de foto a la que se va a afectar.
Tk_PhotoImageBlock *blockPtr (entrada)
Especifica la dirección y el diseño de almacenamiento de los datos de imagen.
int x (entrada)
Especifica la coordenada X donde se colocará la esquina superior izquierda del bloque dentro de la imagen.
int y (entrada)
Especifica la coordenada Y donde se colocará la esquina superior izquierda del bloque dentro de la imagen.
int width (entrada)
Especifica el ancho del área de imagen que se va a afectar (para Tk_PhotoPutBlock) o el ancho de imagen deseado (para Tk_PhotoExpand y Tk_PhotoSetSize).
int compRule (entrada)
Especifica la regla de composición utilizada al combinar píxeles transparentes en un bloque de datos con una imagen de foto. Debe ser una de TK_PHOTO_COMPOSITE_OVERLAY (que coloca el bloque de datos sobre la imagen de foto existente, con el contenido anterior que se muestra a través de los bits transparentes) o TK_PHOTO_COMPOSITE_SET (que descarta el contenido existente de la imagen de foto en el rectángulo cubierto por el bloque de datos).
int height (entrada)
Especifica la altura del área de imagen que se va a afectar (para Tk_PhotoPutBlock) o la altura de imagen deseada (para Tk_PhotoExpand y Tk_PhotoSetSize).
int *widthPtr (salida)
Puntero a la ubicación donde se almacenará el ancho de la imagen.
int *heightPtr (salida)
Puntero a la ubicación donde se almacenará la altura de la imagen.
int subsampleX (entrada)
Especifica el factor de submuestreo en la dirección X para los datos de imagen de entrada.
int subsampleY (entrada)
Especifica el factor de submuestreo en la dirección Y para los datos de imagen de entrada.
int zoomX (entrada)
Especifica el factor de zoom que se aplicará en la dirección X a los píxeles que se escriben en la imagen de foto.
int zoomY (entrada)
Especifica el factor de zoom que se aplicará en la dirección Y a los píxeles que se escriben en la imagen de foto.

DESCRIPCIÓN

Tk_FindPhoto devuelve un identificador opaco que se utiliza para identificar una imagen de foto específica a los demás procedimientos. El parámetro es el nombre de la imagen, es decir, el nombre especificado al comando image create photo, o asignado por dicho comando si no se especificó ningún nombre. Si imageName no existe o no es una imagen de foto, Tk_FindPhoto devuelve NULL.

Tk_PhotoPutBlock se utiliza para proporcionar bloques de datos de imagen para su visualización. La llamada afecta a un área de la imagen de tamaño width x height píxeles, con su esquina superior izquierda en las coordenadas (x,y). Todos los valores de width, height, x e y deben ser no negativos. Si parte de esta área se encuentra fuera de los límites actuales de la imagen, la imagen se expandirá para incluir el área, a menos que el usuario haya especificado un tamaño de imagen explícito con las opciones de configuración del widget -width y/o -height (ver photo(n)); en ese caso, el área se recortará silenciosamente a los límites de la imagen.

El parámetro block es un puntero a una estructura Tk_PhotoImageBlock, definida de la siguiente manera:

typedef struct {
    unsigned char *pixelPtr;
    int width;
    int height;
    int pitch;
    int pixelSize;
    int offset[4];
} Tk_PhotoImageBlock;
El campo pixelPtr apunta al primer píxel, es decir, al píxel superior izquierdo del bloque. Los campos width y height especifican las dimensiones del bloque de píxeles. El campo pixelSize especifica la diferencia de dirección entre dos píxeles horizontalmente adyacentes. Debe ser 4 para datos de imagen RGB y 2 para datos de imagen en escala de grises. Son posibles otros valores, si los desplazamientos en la matriz offset se ajustan en consecuencia (por ejemplo, para datos rojos, verdes y azules almacenados en diferentes planos). Sin embargo, se desaconseja encarecidamente el uso de dicho diseño. Debido a un error, puede que no funcione correctamente si se proporciona un canal alfa. (ver la sección ERRORES a continuación). El campo pitch especifica la diferencia de dirección entre dos píxeles verticalmente adyacentes. La matriz offset contiene los desplazamientos desde la dirección de un píxel a las direcciones de los bytes que contienen los componentes rojo, verde, azul y alfa (transparencia). Si los desplazamientos para rojo, verde y azul son iguales, la imagen se interpreta como escala de grises. Si difieren, se asume que son datos RGB. Normalmente, los desplazamientos serán 0, 1, 2, 3 para datos RGB y 0, 0, 0, 1 para escala de grises. Es posible proporcionar datos de imagen sin canal alfa estableciendo el desplazamiento alfa a un valor negativo y ajustando el campo pixelSize en consecuencia. Sin embargo, este uso se desaconseja (ver la sección ERRORES a continuación).

El parámetro compRule para Tk_PhotoPutBlock especifica una regla de composición que indica qué hacer con los píxeles transparentes. El valor TK_PHOTO_COMPOSITE_OVERLAY indica que el contenido anterior de la imagen de foto debe mostrarse a través, y el valor TK_PHOTO_COMPOSITE_SET indica que el contenido anterior de la imagen de foto debe ignorarse por completo, y los valores del bloque deben copiarse directamente. El comportamiento en Tk8.3 y anteriores era equivalente a tener TK_PHOTO_COMPOSITE_OVERLAY como regla de composición.

Los valores dados para los parámetros width y height a Tk_PhotoPutBlock no tienen que corresponder a los valores especificados en block. Si son más pequeños, Tk_PhotoPutBlock extrae un sub-bloque de los datos de imagen proporcionados. Si son más grandes, los datos proporcionados se replican (de forma mosaica) para llenar el área especificada. Estas reglas operan independientemente en las direcciones horizontal y vertical.

Tk_PhotoPutBlock normalmente devuelve TCL_OK, aunque si no puede asignar suficiente memoria para mantener la imagen resultante, se devuelve TCL_ERROR y, si el argumento interp no es NULL, se coloca un mensaje de error en el resultado del intérprete.

Tk_PhotoPutZoomedBlock funciona de manera similar a Tk_PhotoPutBlock, excepto que la imagen puede reducirse o ampliarse para su visualización. Los parámetros subsampleX y subsampleY permiten reducir el tamaño de la imagen mediante submuestreo. Tk_PhotoPutZoomedBlock utilizará solo los píxeles de la imagen de entrada cuyas coordenadas X sean múltiplos de subsampleX, y cuyas coordenadas Y sean múltiplos de subsampleY. Por ejemplo, una imagen de 512x512 píxeles puede reducirse a 256x256 estableciendo subsampleX y subsampleY en 2.

Los parámetros zoomX y zoomY permiten ampliar la imagen mediante replicación de píxeles. Cada píxel de la imagen de entrada (posiblemente submuestreada) se escribirá en un bloque de zoomX píxeles de ancho y zoomY píxeles de alto de la imagen mostrada. El submuestreo y el zoom se pueden usar juntos para efectos especiales.

Tk_PhotoGetImage se puede utilizar para recuperar datos de imagen de una imagen de foto. Tk_PhotoGetImage rellena la estructura apuntada por el parámetro blockPtr con valores que describen la dirección y el diseño de los datos de imagen que la imagen de foto ha almacenado internamente. Los valores son válidos hasta que la imagen se destruye o su tamaño cambia.

Es posible modificar una imagen escribiendo directamente en los datos a los que apunta el campo pixelPtr. Sin embargo, el tamaño de la imagen no se puede cambiar de esta manera. Además, los cambios realizados al escribir directamente en pixelPtr no serán visibles inmediatamente, sino solo después de una llamada a Tk_ImageChanged o después de un evento que haga que los widgets interesados se redibujen. NAME

Tk_PhotoSetSize, Tk_PhotoExpand, Tk_PhotoGetSize, Tk_PhotoPutBlock, Tk_PhotoPutZoomedBlock, Tk_PhotoGetImage, Tk_PhotoBlank - manipulate photo image objects

ARGUMENTS

-->
See Tk_PhotoHandle for details on the photo argument.
-->
See Tk_PhotoImageBlock for details on the blockPtr argument.
-->
The width and height arguments specify the desired dimensions of the photo image in pixels.
-->
The x and y arguments specify the top-left corner of the block of pixels being supplied or requested.
-->
The zoomMultiply and zoomDivide arguments are used by Tk_PhotoPutZoomedBlock to specify an initial scaling factor. The block of pixels will be scaled by the factor zoomMultiply/zoomDivide before being written into the image.

DESCRIPTION

The Tk_PhotoSetSize command sets the dimensions of the photo image to be width pixels wide by height pixels tall. If width or height are specified as zero, then the corresponding dimension is not changed. This is useful if the image is being created in many small blocks, as it allows the application to specify the final size without needing to allocate all the memory for the image initially.

Tk_PhotoPutBlock writes a block of pixel data into the photo image, starting at coordinates (x,y). The blockPtr argument describes the pixel data, including its dimensions, the offset to the red, green, blue and red channels, and the size of one pixel in bytes. The x and y coordinates are relative to the top-left corner of the photo image. The block will be copied into the image; subsequent changes to the pixel data referenced by blockPtr will not affect the image.

Tk_PhotoPutZoomedBlock is similar to Tk_PhotoPutBlock, but it scales the pixel data by the factor zoomMultiply/zoomDivide before writing it into the image. This can be used to write smaller images into larger photo images, for example.

Tk_PhotoGetImage is the inverse of Tk_PhotoPutBlock. It copies a block of pixel data from the photo image, starting at coordinates (x,y) and with dimensions width x height, into the buffer supplied by blockPtr. The buffer must be large enough to hold the requested data. It is the application's responsibility to allocate and free the buffer.

When writing pixel data using Tk_PhotoPutBlock or Tk_PhotoPutZoomedBlock, the pixel data should be in the format specified by the Tk_PhotoImageBlock structure. This structure contains fields for the width and height of the block, pointers to the red, green, blue, and alpha channels (or NULL if not present), and offsets and pixel size information. The Tk library handles conversions between different channel orders and pixel sizes internally. However, for maximum compatibility and efficiency, it is recommended that applications use the standard interleaved RGB format (pixel size 4, offsets 0, 1, 2 for R, G, B respectively) or RGBA format (pixel size 4, offsets 0, 1, 2, 3 for R, G, B, A respectively).

The Tk_PhotoImageBlock structure may be reused after a call to Tk_PhotoPutBlock or Tk_PhotoPutZoomedBlock. However, the pixel data pointed to by the structure may be copied, so the application should not rely on the data remaining in the same memory location.

The Tk library may choose to cache image data. Calls to Tk_PhotoPutBlock or Tk_PhotoPutZoomedBlock will overwrite existing image data in the specified region. If the application needs to make arbitrary changes to a copy of the image data and write it back with Tk_PhotoPutBlock or Tk_PhotoPutZoomedBlock.

Tk_PhotoGetImage returns 1 for compatibility with the corresponding procedure in the old photo widget.

Tk_PhotoBlank blanks the entire area of the photo image. Blank areas of a photo image are transparent.

Tk_PhotoExpand requests that the widget's image be expanded to be at least width x height pixels in size. The width and/or height are unchanged if the user has specified an explicit image width or height with the -width and/or -height configuration options, respectively. If the image data are being supplied in many small blocks, it is more efficient to use Tk_PhotoExpand or Tk_PhotoSetSize at the beginning rather than allowing the image to expand in many small increments as image blocks are supplied.

Tk_PhotoExpand normally returns TCL_OK, though if it cannot allocate sufficient memory to hold the resulting image, TCL_ERROR is returned instead and, if the interp argument is non-NULL, an error message is placed in the interpreter's result.

Tk_PhotoSetSize specifies the size of the image, as if the user had specified the given width and height values to the -width and -height configuration options. A value of zero for width or height does not change the image's width or height, but allows the width or height to be changed by subsequent calls to Tk_PhotoPutBlock, Tk_PhotoPutZoomedBlock or Tk_PhotoExpand.

Tk_PhotoSetSize normally returns TCL_OK, though if it cannot allocate sufficient memory to hold the resulting image, TCL_ERROR is returned instead and, if the interp argument is non-NULL, an error message is placed in the interpreter's result.

Tk_PhotoGetSize returns the dimensions of the image in *widthPtr and *heightPtr.

PORTABILITY

In Tk 8.3 and earlier, Tk_PhotoPutBlock and Tk_PhotoPutZoomedBlock had different signatures. If you want to compile code that uses the old interface against 8.4 without updating your code, compile it with the flag -DUSE_COMPOSITELESS_PHOTO_PUT_BLOCK. Code linked using Stubs against older versions of Tk will continue to work.

In Tk 8.4, Tk_PhotoPutBlock, Tk_PhotoPutZoomedBlock, Tk_PhotoExpand and Tk_PhotoSetSize did not take an interp argument or return any result code. If insufficient memory was available for an image, Tk would panic. This behaviour is still supported if you compile your extension with the additional flag -DUSE_PANIC_ON_PHOTO_ALLOC_FAILURE. Code linked using Stubs against older versions of Tk will continue to work.

BUGS

The Tk_PhotoImageBlock structure used to provide image data to Tk_PhotoPutBlock promises great flexibility in the layout of the data (e.g. separate planes for the red, green, blue and alpha channels). Unfortunately, the implementation fails to hold this promise. The problem is that the pixelSize field is (incorrectly) used to determine whether the image has an alpha channel. Currently, if the offset for the alpha channel is greater than or equal to pixelSize, tk_PhotoPutblock assumes no alpha data is present and makes the image fully opaque. This means that for layouts where the channels are separate (or any other exotic layout where pixelSize has to be smaller than the alpha offset), the alpha channel will not be read correctly. In order to be on the safe side if this issue will be corrected in a future release, it is strongly recommended you always provide alpha data - even if the image has no transparency - and only use the "standard" layout with a pixelSize of 2 for grayscale and 4 for RGB data with offsets of 0, 0, 0, 1 or 0, 1, 2, 3 respectively.
