Nombre del nuevo bitmap a definir.

int width (entrada)
Ancho del bitmap.

Alto del bitmap.

Puntero a una palabra para rellenar con el ancho del bitmap.

DESCRIPCIÓN

Estos procedimientos gestionan una colección de bitmaps (pixmaps de un solo plano) que está utilizando una aplicación. Los procedimientos permiten reutilizar bitmaps de manera eficiente, evitando así la sobrecarga del servidor, y también permiten nombrar bitmaps con cadenas de caracteres.

Tk_AllocBitmapFromObj devuelve un identificador Pixmap para un bitmap que coincide con la descripción en objPtr y es adecuado para su uso en tkwin. Reutiliza un bitmap existente, si es posible, y crea uno nuevo en caso contrario. El valor de objPtr debe tener una de las siguientes formas:

@nombreArchivo
NombreArchivo debe ser el nombre de un archivo que contiene una descripción de bitmap en el formato estándar de X11.
nombre
Nombre debe ser el nombre de un bitmap definido previamente con una llamada a Tk_DefineBitmap. Los siguientes nombres están predefinidos por Tk:
error
El símbolo internacional de "prohibido": un círculo con una línea diagonal que lo atraviesa.
gray75
Gris al 75%: un patrón de tablero de ajedrez donde tres de cada cuatro bits están activados.
gray50
Gris al 50%: un patrón de tablero de ajedrez donde cada dos bits están activados.
gray25
Gris al 25%: un patrón de tablero de ajedrez donde uno de cada cuatro bits está activado.
gray12
Gris al 12.5%: un patrón donde un octavo de los bits están activados, consistente en cada cuarto píxel en filas alternas.
hourglass
Un símbolo de reloj de arena.
info
Una letra "i" grande.
questhead
La silueta de una cabeza humana, con un signo de interrogación dentro.

Un signo de interrogación grande.
warning
Un signo de exclamación grande.

Además, los siguientes nombres predefinidos solo están disponibles en la plataforma Macintosh:

Icono de aplicación genérico.

Un accesorio de escritorio.

Icono de carpeta genérico.

Una carpeta bloqueada.

Un cubo de basura.

Un disquete.

Un disquete con un chip.

Un icono de disco CD.

Una carpeta con símbolo de preferencias.

Una cara con bocadillos de diálogo.

Un triángulo con un signo de exclamación.

En condiciones normales, Tk_AllocBitmapFromObj devuelve un identificador para el bitmap solicitado. Si ocurre un error al crear el bitmap, como cuando objPtr hace referencia a un archivo inexistente, se devuelve None y se deja un mensaje de error en el resultado de interp si interp no es NULL. Tk_AllocBitmapFromObj almacena en caché información sobre el valor de retorno en objPtr, lo que acelera las llamadas futuras a procedimientos como Tk_AllocBitmapFromObj y Tk_GetBitmapFromObj.

Tk_GetBitmap es idéntico a Tk_AllocBitmapFromObj excepto que la descripción del bitmap se especifica con una cadena en lugar de un objeto. Esto evita que Tk_GetBitmap almacene en caché el valor de retorno, por lo que Tk_GetBitmap es menos eficiente que Tk_AllocBitmapFromObj.

Tk_GetBitmapFromObj devuelve el token de un bitmap existente, dada la ventana y la descripción utilizadas para crear el bitmap. Tk_GetBitmapFromObj en realidad no crea el bitmap; el bitmap ya debe haber sido creado con una llamada anterior a Tk_AllocBitmapFromObj o Tk_GetBitmap. El valor de retorno se almacena en caché en objPtr, lo que acelera las llamadas futuras a Tk_GetBitmapFromObj con el mismo objPtr y tkwin.

Tk_DefineBitmap asocia un nombre con datos de bitmap en memoria para que el nombre pueda ser utilizado en llamadas posteriores a Tk_AllocBitmapFromObj o Tk_GetBitmap. El argumento nameId proporciona un nombre para el bitmap; no debe haber sido utilizado previamente en una llamada a Tk_DefineBitmap. Los argumentos source, width y height describen el bitmap. Tk_DefineBitmap normalmente devuelve TCL_OK; si ocurre un error (por ejemplo, ya se ha definido un bitmap con el nombre nameId), se devuelve TCL_ERROR y se deja un mensaje de error en el resultado del intérprete interp. Ventana que se va a utilizar para determinar la pantalla y las unidades de visualización si es necesario. Puede ser la ventana raíz de la aplicación. Si tkwin es None, se utilizará la ventana raíz de la aplicación.

Nombre del mapa de bits. Para los mapas de bits definidos en el código, este es el nombre que se dio en la llamada a Tk_DefineBitmap. DESCRIPCIÓN

Las utilidades de mapas de bits de Tk son un mecanismo para gestionar mapas de bits X. El mapa de bits se representa como una estructura de datos opaca que el servidor X utiliza para almacenar los datos de la imagen. Tk mantiene una base de datos de todos los mapas de bits que se están utilizando actualmente. Cuando se solicita un mapa de bits, Tk primero busca en su base de datos para ver si ya se está utilizando un mapa de bits idéntico. Si es así, devuelve el mapa de bits existente; de lo contrario, crea uno nuevo. Cuando un mapa de bits ya no es necesario, Tk lo libera automáticamente. Este enfoque puede reducir considerablemente la sobrecarga del servidor.

La función Tk_DefineBitmap permite definir un mapa de bits utilizando datos de mapa de bits C incrustados. El argumento name es el nombre que se utilizará para hacer referencia al mapa de bits posteriormente. Los argumentos bits, width y height son los datos del mapa de bits que se van a incrustar. Normalmente, estos datos provienen de un archivo de mapa de bits C generado por el programa bitmap y contienen un patrón de relleno. El siguiente código utiliza Tk_DefineBitmap para definir un nuevo mapa de bits llamado foo:

Pixmap bitmap;
#include "stip.bitmap"
Tk_DefineBitmap(interp, "foo", stip_bits,
    stip_width, stip_height);
...
bitmap = Tk_GetBitmap(interp, tkwin, "foo");

Este código provoca que el archivo de mapa de bits se lea en tiempo de compilación y que la información del mapa de bits se incorpore a la imagen ejecutable del programa. El mismo archivo de mapa de bits podría leerse en tiempo de ejecución utilizando Tk_GetBitmap:

Pixmap bitmap;
bitmap = Tk_GetBitmap(interp, tkwin, "@stip.bitmap");

La segunda forma es un poco más flexible (el archivo podría modificarse después de que el programa se haya compilado, o se podría proporcionar una cadena diferente para leer un archivo diferente), pero es un poco más lenta y requiere que el archivo de mapa de bits exista por separado del programa.

Tk mantiene una base de datos de todos los mapas de bits que están actualmente en uso. Siempre que sea posible, devolverá un mapa de bits existente en lugar de crear uno nuevo. Cuando un mapa de bits ya no se utiliza, Tk lo liberará automáticamente. Este enfoque puede reducir sustancialmente la sobrecarga del servidor, por lo que Tk_AllocBitmapFromObj y Tk_GetBitmap generalmente deben preferirse a los procedimientos de Xlib como XReadBitmapFile.

Los mapas de bits devueltos por Tk_AllocBitmapFromObj y Tk_GetBitmap se comparten, por lo que los llamadores nunca deben modificarlos. Si un mapa de bits debe modificarse dinámicamente, entonces debe crearse llamando directamente a procedimientos de Xlib como XReadBitmapFile o XCreatePixmap.

El procedimiento Tk_NameOfBitmap es aproximadamente el inverso de Tk_GetBitmap. Dado un argumento X Pixmap, devuelve la descripción textual que se pasó a Tk_GetBitmap cuando se creó el mapa de bits. Bitmap debe haber sido el valor de retorno de una llamada anterior a Tk_AllocBitmapFromObj o Tk_GetBitmap.

Tk_SizeOfBitmap devuelve las dimensiones de su argumento bitmap en las palabras apuntadas por los argumentos widthPtr y heightPtr. Al igual que con Tk_NameOfBitmap, bitmap debe haber sido creado por Tk_AllocBitmapFromObj o Tk_GetBitmap.

Cuando un mapa de bits ya no es necesario, se debe llamar a Tk_FreeBitmapFromObj o Tk_FreeBitmap para liberarlo. Para Tk_FreeBitmapFromObj, el mapa de bits a liberar se especifica con la misma información utilizada para crearlo; para Tk_FreeBitmap, el mapa de bits a liberar se especifica con su token Pixmap. Debe haber exactamente una llamada a Tk_FreeBitmapFromObj o Tk_FreeBitmap por cada llamada a Tk_AllocBitmapFromObj o Tk_GetBitmap.

ERRORES

Al determinar si un mapa de bits existente se puede utilizar para satisfacer una nueva solicitud, Tk_AllocBitmapFromObj y Tk_GetBitmap solo consideran el valor inmediato de la descripción de la cadena. Por ejemplo, cuando se pasa un nombre de archivo a Tk_GetBitmap, Tk_GetBitmap asumirá que es seguro reutilizar un mapa de bits existente creado a partir del mismo nombre de archivo: no comprobará si el propio archivo ha cambiado, o si el directorio actual ha cambiado, haciendo que el nombre haga referencia a un archivo diferente.
