Tk_ConfigureWindow(3) Procedimientos de la biblioteca Tk Tk_ConfigureWindow(3)

NOMBRE

Tk_ConfigureWindow, Tk_MoveWindow, Tk_ResizeWindow, Tk_MoveResizeWindow, Tk_SetWindowBorderWidth, Tk_ChangeWindowAttributes, Tk_SetWindowBackground, Tk_SetWindowBackgroundPixmap, Tk_SetWindowBorder, Tk_SetWindowBorderPixmap, Tk_SetWindowColormap, Tk_DefineCursor, Tk_UndefineCursor - cambiar la configuración o atributos de la ventana

SINOPSIS

#include <tk.h>

Tk_ConfigureWindow(tkwin, valueMask, valuePtr)

Tk_MoveWindow(tkwin, x, y)

Tk_ResizeWindow(tkwin, width, height)

Tk_MoveResizeWindow(tkwin, x, y, width, height)

Tk_SetWindowBorderWidth(tkwin, borderWidth)

Tk_ChangeWindowAttributes(tkwin, valueMask, attsPtr)

Tk_SetWindowBackground(tkwin, pixel)

Tk_SetWindowBackgroundPixmap(tkwin, pixmap)

Tk_SetWindowBorder(tkwin, pixel)

Tk_SetWindowBorderPixmap(tkwin, pixmap)

Tk_SetWindowColormap(tkwin, colormap)

Tk_DefineCursor(tkwin, cursor)

Tk_UndefineCursor(tkwin)

ARGUMENTOS

Tk_Window tkwin (entrada)
Token para la ventana.
unsigned int valueMask (entrada)
Máscara OR de valores como CWX o CWBorderPixel, que indica qué campos de *valuePtr o *attsPtr se utilizarán.
XWindowChanges *valuePtr (entrada)
Puntero a una estructura que contiene los nuevos valores para los parámetros de configuración seleccionados por valueMask. Los campos no seleccionados por valueMask se ignoran.
int x (entrada)
Nueva coordenada x del píxel superior izquierdo de tkwin (incluyendo borde, si lo hay) dentro del padre de tkwin.
int y (entrada)
Nueva coordenada y del píxel superior izquierdo de tkwin (incluyendo borde, si lo hay) dentro del padre de tkwin.
int width (entrada)
Nuevo ancho para tkwin (interior, sin incluir el borde).
int height (entrada)
Nuevo alto para tkwin (interior, sin incluir el borde).
int borderWidth (entrada)
Nuevo ancho del borde de tkwin.
XSetWindowAttributes *attsPtr (entrada)
Puntero a una estructura que contiene los nuevos valores para los atributos dados por el argumento valueMask. Los atributos no seleccionados por valueMask se ignoran.
unsigned long pixel (entrada)
Nuevo color de fondo o borde para la ventana.
Pixmap pixmap (entrada)
Nuevo pixmap a utilizar para el fondo o el borde de tkwin. ADVERTENCIA: no se puede eliminar inmediatamente, como en las llamadas de Xlib. Ver nota abajo.
Colormap colormap (entrada)
Nuevo mapa de colores a utilizar para tkwin.
Tk_Cursor cursor (entrada)
Nuevo cursor a utilizar para tkwin. Si se especifica None, entonces tkwin no tendrá su propio cursor; utilizará el cursor de su padre.

DESCRIPCIÓN

Estos procedimientos son análogos a los procedimientos de la biblioteca X con nombres similares, como XConfigureWindow. Cada uno de los procedimientos anteriores llama al procedimiento X correspondiente y también guarda la información de configuración en la estructura local de Tk para la ventana. Esto permite que la aplicación recupere rápidamente la información (usando macros como Tk_X y Tk_Height) sin tener que contactar al servidor X. Además, si aún no se ha creado ninguna ventana X para tkwin, estos procedimientos no emiten operaciones X ni invocan manejadores de eventos; guardan la información en la estructura local de Tk para la ventana; cuando la ventana se cree más tarde, la información guardada se utilizará para configurar la ventana.

Consulte la documentación de la biblioteca X para obtener detalles sobre lo que hacen estos procedimientos y cómo utilizan sus argumentos.

En los procedimientos Tk_ConfigureWindow, Tk_MoveWindow, Tk_ResizeWindow, Tk_MoveResizeWindow y Tk_SetWindowBorderWidth, si tkwin es una ventana interna, se invocan inmediatamente los manejadores de eventos interesados en eventos de configuración, antes de que el procedimiento devuelva. Si tkwin es una ventana de nivel superior, los manejadores de eventos se invocarán más tarde, después de que X haya visto la solicitud y haya devuelto un evento para ella.

Las aplicaciones que utilizan Tk nunca deben llamar directamente a procedimientos como XConfigureWindow; siempre deben usar los procedimientos Tk correspondientes.

El tamaño y la ubicación de una ventana solo deben ser modificados por el gestor de geometría apropiado para esa ventana y nunca por la ventana misma (pero vea Tk_MoveToplevelWindow para mover una ventana de nivel superior).

No puede usar Tk_ConfigureWindow para cambiar el orden de apilamiento de una ventana (valueMask puede no contener los bits CWSibling o CWStackMode). Para cambiar el orden de apilamiento, use el procedimiento Tk_RestackWindow.

El procedimiento Tk_SetWindowColormap agregará automáticamente tkwin a la propiedad TK_COLORMAP_WINDOWS de su ancestro de nivel superior más cercano si el nuevo mapa de colores es diferente al de el padre de tkwin y tkwin ya no está en la propiedad TK_COLORMAP_WINDOWS.

ERRORES

Tk_SetWindowBackgroundPixmap y Tk_SetWindowBorderPixmap difieren ligeramente de sus contrapartes de Xlib en que el argumento pixmap puede no ser necesariamente eliminado inmediatamente después de llamar a uno de estos procedimientos. Esto se debe a que la ventana de tkwin puede no existir aún en el momento de la llamada, en cuyo caso pixmap simplemente se guarda y se utiliza más tarde cuando se crea realmente la ventana de tkwin. Si desea eliminar pixmap, llame primero a Tk_MakeWindowExist para asegurarse de que la ventana de tkwin existe y que pixmap se ha pasado al servidor X.

Un problema similar ocurre para el argumento cursor pasado a Tk_DefineCursor. La solución es la misma que para los pixmaps anteriores: llame a Tk_MakeWindowExist antes de liberar el cursor.

VER TAMBIÉN

Tk_MoveToplevelWindow, Tk_RestackWindow
