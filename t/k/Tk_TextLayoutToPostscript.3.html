ARGUMENTOS

Tk_Font tkfont (entrada)
Fuente a utilizar al construir y mostrar un diseño de texto. El tkfont debe permanecer válido durante la vida útil del diseño de texto. Debe haber sido devuelto por una llamada previa a Tk_GetFont.
const char *string (entrada)
Cadena de texto potencialmente multilínea cuyas dimensiones se van a calcular y almacenar en el diseño de texto. El string debe permanecer válido durante la vida útil del diseño de texto.
int numChars (entrada)
El número de caracteres a considerar de string. Si numChars es menor que 0, asume que string termina en nulo y utiliza Tcl_NumUtfChars para determinar la longitud de string.
int wrapLength (entrada)
Longitud máxima permitida por línea, en píxeles. Las líneas en string se dividirán automáticamente en límites de palabras y se ajustarán cuando alcancen esta longitud. Si wrapLength es demasiado pequeño incluso para que quepa un solo carácter en una línea, se expandirá para permitir que un carácter quepa en cada línea. Si wrapLength es <= 0, no hay ajuste automático; las líneas serán tan largas como necesiten ser y solo se ajustarán si se encuentra un carácter de nueva línea/retorno.
Tk_Justify justify (entrada)
Cómo justificar las líneas en un diseño de texto multilínea. Los valores posibles son TK_JUSTIFY_LEFT, TK_JUSTIFY_CENTER o TK_JUSTIFY_RIGHT. Si el diseño de texto solo ocupa una sola línea, entonces justify es irrelevante.
int flags (entrada)
Varios bits de bandera OR-eados juntos. TK_IGNORE_TABS significa que los caracteres de tabulación no se expandirán al siguiente punto de tabulación. TK_IGNORE_NEWLINES significa que los caracteres de nueva línea/retorno no causarán un salto de línea. Si se ignoran las tabulaciones o las nuevas líneas/retornos, se tratarán como caracteres regulares, midiéndose y mostrándose de manera dependiente de la plataforma como se describe en Tk_MeasureChars, y no tendrán comportamientos especiales.
int *widthPtr (salida)
Si no es NULL, se rellena con el ancho, en píxeles, de la línea más ancha en el diseño de texto, o el ancho, en píxeles, del cuadro delimitador para el carácter especificado por index.
int *heightPtr (salida)
Si no es NULL, se rellena con la altura total, en píxeles, de todas las líneas en el diseño de texto, o la altura, en píxeles, del cuadro delimitador para el carácter especificado por index.
Tk_TextLayout layout (entrada)
Un token que representa la información de diseño almacenada en caché sobre el texto justificado, multilínea y de una sola fuente. Este token es devuelto por Tk_ComputeTextLayout.
Display *display (entrada)
Pantalla en la que dibujar.
Drawable drawable (entrada)
Ventana o pixmap en la que dibujar.
GC gc (entrada)
Contexto gráfico a utilizar para dibujar el diseño de texto. La fuente seleccionada en este GC debe corresponder al tkfont utilizado al construir el diseño de texto.
int x, y (entrada)
Punto, en píxeles, en el que colocar la esquina superior izquierda del diseño de texto cuando se está dibujando, o las coordenadas de un punto (con respecto a la esquina superior izquierda del diseño de texto) para comprobar contra el diseño de texto.
int firstChar (entrada)
El índice del primer carácter a dibujar del diseño de texto dado. El número 0 significa dibujar desde el principio.
int lastChar (entrada)
El índice del último carácter hasta el cual dibujar. El carácter especificado por lastChar no se dibujará. Un número menor que 0 significa dibujar todos los caracteres en el diseño de texto.
int underline (entrada)
Índice del único carácter a subrayar en el diseño de texto, o un número menor que 0 para no subrayar.
int index (entrada)
El índice del carácter cuyo cuadro delimitador se desea. El cuadro delimitador se calcula con respecto a la esquina superior izquierda del diseño de texto.
int *xPtr, *yPtr (salida)
Se rellena con la esquina superior izquierda, en píxeles, del cuadro delimitador para el carácter especificado por index. Cualquiera o ambos xPtr y yPtr pueden ser NULL, en cuyo caso el valor correspondiente no se calcula.
int width, height (entrada)
Especifica el ancho y alto, en píxeles, del área rectangular a comparar para intersección contra el diseño de texto.
Tcl_Interp *interp (salida)
El código Postscript que imprimirá el diseño de texto se anexa al resultado del intérprete interp.

DESCRIPCIÓN

Estas rutinas son para medir y mostrar texto justificado, multilínea y de una sola fuente. Para medir y mostrar cadenas simples de una sola fuente y una sola línea, consulte la documentación de Tk_MeasureChars. No existe una interfaz de programación en el núcleo de Tk que admita texto multifuente y multilínea; el soporte para ese comportamiento debe construirse sobre capas más simples. Tenga en cuenta que, a diferencia de las rutinas de visualización de texto de nivel inferior, las funciones descritas aquí operan en longitudes e índices orientados a caracteres en lugar de valores orientados a bytes. Consulte la descripción de Tcl_UtfAtIndex para obtener más detalles sobre cómo convertir entre desplazamientos de caracteres y bytes.

Las rutinas descritas aquí se construyen sobre la interfaz de programación descrita en la documentación de Tk_MeasureChars. Los caracteres de tabulación y los caracteres de nueva línea/retorno pueden ser tratados especialmente por estos procedimientos, pero todos los demás caracteres se pasan al nivel inferior.

Tk_ComputeTextLayout calcula la información de diseño necesaria para mostrar una cadena de texto justificada, multilínea y de una sola fuente y devuelve un token Tk_TextLayout que contiene esta información. Este token se utiliza en llamadas posteriores a procedimientos como Tk_DrawTextLayout, Tk_DistanceToTextLayout y Tk_FreeTextLayout. El string y el tkfont utilizados al calcular el diseño deben permanecer válidos durante la vida útil de este token.

Tk_FreeTextLayout se llama para liberar el almacenamiento asociado con layout cuando ya no se necesita. No se debe utilizar un layout en ningún otro procedimiento de diseño de texto una vez que se haya liberado.

Tk_DrawTextLayout utiliza la información en layout para mostrar una cadena de texto justificada, multilínea y de una sola fuente en la ubicación especificada.

Tk_UnderlineTextLayout utiliza la información en layout para mostrar un subrayado debajo de un carácter individual. Este procedimiento no dibuja el texto, solo el subrayado. Para producir texto subrayado de forma nativa, se debe construir y utilizar una fuente subrayada. Todos los caracteres, incluidos los tabuladores, los caracteres de nueva línea/retorno y los espacios al final de las líneas, se pueden subrayar utilizando este método. Sin embargo, el subrayado nunca se dibujará fuera del ancho calculado de layout; el subrayado se detendrá en el borde para cualquier carácter que se extienda parcialmente fuera de layout, y el subrayado no será visible en absoluto para ningún carácter que se ubique completamente fuera del diseño.

Tk_PointToChar utiliza la información en layout para determinar el carácter más cercano al punto dado. El punto se especifica con respecto a la esquina superior izquierda del layout, que se considera ubicado en (0, 0). Cualquier punto cuyo valor y sea menor que 0 se considerará más cercano al primer carácter en el diseño de texto; cualquier punto cuyo valor y sea mayor que la altura del diseño de texto se considerará más cercano al último carácter en el diseño de texto. ARGUMENTS

‑

interp (in) Interpreter to use for error reporting and Postscript output.

‑

layout (in) The text layout to operate on.

‑

x, y (in) Coordinates at which to draw the text layout.

‑

screenWidth, screenHeight (in) Dimensions of the screen area available for drawing.

‑

drawWidth (in) The width of the drawing area available for the text layout.

‑

tabOrigin (in) The x-coordinate of the start of the tab stops. For example, if the text is indented 10 pixels, then tabOrigin should be 10.

‑

flags (in) Flags controlling drawing behavior. If the TK_PARTIAL_LAYOUT flag is set, then characters that extend partially outside of drawWidth will be drawn; otherwise they will be clipped. If the TK_WHOLE_PIECES flag is set, then only characters that are entirely within the drawWidth will be drawn. If the TK_TEXT_LAYOUT_TEXT_ONLY flag is set, then no underlining will be drawn.

‑

index (in) Index of the character within the layout.

‑

*xPtr, *yPtr, *widthPtr, *heightPtr (out) Location into which bounding box information will be stored.

‑

*indexPtr (out) Location into which the index of the closest character will be stored.

‑

rectPtr (in) Pointer to a Tk rectangle structure containing the rectangle to test against.

‑

text (in) The text string to be laid out.

‑

length (in) The length of the text string. If length is -1, then text is null-terminated.

‑

tkfont (in) The font to use for the text.

‑

wrapLength (in) The maximum line length in screen units. If 0, then no wrapping occurs. If the value is larger than the screen width, then the value is ignored and the screen width is used instead.

‑

breakChars (in) A string containing characters that will be considered break points for wrapping. In addition to these characters, space characters will also be considered break points.

DESCRIPTION

These functions manipulate text layouts, which are opaque data structures that store information about how text should be displayed. This information includes line breaks, character positions, and bounding boxes for individual characters.

Tk_ComputeTextLayout creates and returns a text layout structure for the given text string, font, and wrapping parameters. If wrapLength is 0, then lines will only be broken at newline or return characters. Otherwise, lines will be broken at word breaks (spaces or characters in breakChars`) or newline/return characters, whichever comes first, and will not exceed wrapLength. If a word is longer than wrapLength, it will be broken, and as much as possible will be placed on the current line, and the remainder on subsequent lines. If wrapLength is so small that not even one character fits on a line, then wrapLength is ignored and one character is placed on the line. The tabOrigin argument specifies the x-coordinate to use for the start of tab calculations. The flags argument can be used to control the behavior of the layout computation. If the TK_WHOLE_WORDS flag is set, then lines will only be broken at word breaks (not within words). If the TK_IGNORE_NL flag is set, then newline characters will be ignored. The returned layout is dynamically allocated and must be freed by the caller using Tk_FreeTextLayout.

Tk_DrawTextLayout draws the text layout specified by layout starting at coordinates (x, y). The drawing is clipped to the screen dimensions specified by screenWidth and screenHeight, and also to the drawWidth. Underlining is drawn for characters that are underlined in the font. tabOrigin specifies the x-coordinate of the first tab stop. The flags argument can be used to control drawing behavior.

Tk_TextLayoutBox returns the bounding box of the entire text layout. The coordinates are relative to the origin (0,0) of the layout.

Tk_TextLayoutClosestIndex finds the index of the character that is closest to the given point (x, y). If the point is to the left of the first character, the index of the first character is returned. If the point is to the right of the last character, the index of the last character plus one is returned. Points within the layout are mapped to the closest character index. If the layout is empty, 0 is returned.

Tk_CharBbox returns the bounding box of a specific character within the layout. The bounding box is relative to the origin (0,0) of the layout. The width is the advance width of the character. The height is the line height. If the index is invalid, 0 is returned and the output pointers are unmodified. Otherwise, a non-zero value is returned, and the output pointers are filled with the bounding box information.

Tk_DistanceToTextLayout computes the shortest distance in pixels from the given point (x, y) to the characters in the layout. Newline/return characters and non-displaying space characters at the end of lines are ignored for hit detection. The return value is 0 if the point hits the layout, and the distance otherwise.

Tk_IntersectTextLayout determines if the layout intersects with the given rectangle. Newline/return characters and non-displaying space characters at the end of lines are ignored. Returns -1 if the layout is entirely outside the rectangle, 0 if it overlaps, and 1 if it is entirely inside.

Tk_TextLayoutToPostscript generates Postscript code representing the text layout as an array of strings. The caller is responsible for adding Postscript code to render this array. The generated code is appended to the interpreter's result.

DISPLAY MODEL

When measuring a text layout, space characters at the end of a line are ignored in terms of their width for justification or total width calculations. They are considered attached to the right edge of the line. Spaces are variable width; the first space extending beyond the layout edge is clipped, and subsequent spaces are considered zero-width. Spaces in the middle of a line are not ignored.

Tab characters are measured. If wrapping is on and there are enough tabs, the next tab can wrap to the next line. Tab alignment might be affected by centering or right-justification of the entire line after tab stop calculations.

When wrapping is on, lines can break at word breaks (spaces, tabs) or newlines/returns. Dashes/hyphens in the middle of words are not word breaks. Tk_ComputeTextLayout tries to put at least one word per line. If wrapLength is too small, words are broken. If not even one character fits, wrapLength is ignored for that line, and one character is placed. When wrapping is off, only newline/return characters cause line breaks.

If the font is underlined, space characters at line ends, newlines/returns, and tabs are not drawn underlined by Tk_DrawTextLayout, as they are placeholders.
