Tk_CreateItemType(3) Procedimientos de la biblioteca Tk Tk_CreateItemType(3)

NOMBRE

Tk_CreateItemType, Tk_GetItemTypes - definir un nuevo tipo de elemento de lienzo

SINOPSIS

#include <tk.h>

Tk_CreateItemType(typePtr)

Tk_ItemType *
Tk_GetItemTypes()

ARGUMENTOS

Tk_ItemType *typePtr (entrada)
Estructura que define el nuevo tipo de elemento de lienzo.

INTRODUCCION

Tk_CreateItemType se invoca para definir un nuevo tipo de elemento de lienzo descrito por el argumento typePtr. Un tipo de elemento corresponde a un valor particular del argumento type del comando de widget create para lienzos, y el código que implementa un tipo de elemento de lienzo se llama un gestor de tipo. Tk define varios tipos de elementos integrados, como rectangle y text y image, pero Tk_CreateItemType permite definir tipos de elementos adicionales. Una vez que Tk_CreateItemType retorna, el nuevo tipo de elemento puede usarse en lienzos nuevos o existentes al igual que los tipos de elementos integrados.

Tk_GetItemTypes devuelve un puntero al primero de la lista de todos los tipos de elementos actualmente definidos para lienzos. Las entradas de la lista están enlazadas a través de sus campos nextPtr, con el final de la lista marcado por un nextPtr NULL.

Puede resultarle más fácil entender el resto de esta entrada del manual si consulta el código de un tipo de elemento de lienzo existente, como bitmap (en el archivo tkCanvBmap.c) o text (tkCanvText.c). La forma más sencilla de crear un nuevo gestor de tipo es copiar el código de un tipo existente y modificarlo para el nuevo tipo.

Tk proporciona varios procedimientos de utilidad para el uso de gestores de tipos de lienzo, como Tk_CanvasCoords y Tk_CanvasPsColor; estos se describen en entradas de manual separadas.

ESTRUCTURAS DE DATOS

Un gestor de tipo consta de una colección de procedimientos que proporcionan un conjunto estándar de operaciones sobre elementos de ese tipo. El gestor de tipo maneja tres tipos de estructuras de datos. La primera estructura de datos es un Tk_ItemType; contiene información como el nombre del tipo y punteros a los procedimientos estándar implementados por el gestor de tipo:

typedef struct Tk_ItemType {
    const char *name;
    int itemSize;
    Tk_ItemCreateProc *createProc;
    const Tk_ConfigSpec *configSpecs;
    Tk_ItemConfigureProc *configProc;
    Tk_ItemCoordProc *coordProc;
    Tk_ItemDeleteProc *deleteProc;
    Tk_ItemDisplayProc *displayProc;
    int alwaysRedraw;
    Tk_ItemPointProc *pointProc;
    Tk_ItemAreaProc *areaProc;
    Tk_ItemPostscriptProc *postscriptProc;
    Tk_ItemScaleProc *scaleProc;
    Tk_ItemTranslateProc *translateProc;
    Tk_ItemIndexProc *indexProc;
    Tk_ItemCursorProc *icursorProc;
    Tk_ItemSelectionProc *selectionProc;
    Tk_ItemInsertProc *insertProc;
    Tk_ItemDCharsProc *dCharsProc;
    Tk_ItemType *nextPtr;
} Tk_ItemType;

Los campos de una estructura Tk_ItemType se describen con más detalle más adelante en esta entrada del manual. Cuando se llama a Tk_CreateItemType, su argumento typePtr debe apuntar a una estructura con todos los campos inicializados excepto nextPtr, que Tk establece para enlazar todos los tipos en una lista. La estructura debe estar en memoria permanente (ya sea asignada estáticamente o asignada dinámicamente pero nunca liberada); Tk conserva un puntero a esta estructura.

La segunda estructura de datos manipulada por un gestor de tipo es un registro de elemento. Para cada elemento en un lienzo, existe un registro de elemento. Todos los elementos de un tipo determinado generalmente tienen registros de elementos con la misma estructura, pero diferentes tipos suelen tener formatos diferentes para sus registros de elementos. La primera parte de cada registro de elemento es una cabecera con una estructura estándar definida por Tk a través del tipo Tk_Item; el resto del registro de elemento lo define el gestor de tipo. Un gestor de tipo debe definir sus registros de elementos con un Tk_Item como primer campo. Por ejemplo, el registro de elemento para los elementos bitmap se define de la siguiente manera:

typedef struct BitmapItem {
    Tk_Item header;
    double x, y;
    Tk_Anchor anchor;
    Pixmap bitmap;
    XColor *fgColor;
    XColor *bgColor;
    GC gc;
} BitmapItem;

La subestructura header contiene información utilizada por Tk para gestionar el elemento, como su identificador, sus etiquetas, su tipo y su cuadro delimitador. Los campos que comienzan con x pertenecen al gestor de tipo: Tk nunca los leerá ni escribirá. El gestor de tipo no debería necesitar leer ni escribir ninguno de los campos de la cabecera, excepto cuatro campos cuyos nombres son x1, y1, x2 e y2. Estos campos proporcionan un cuadro delimitador para los elementos utilizando coordenadas de lienzo enteras: el elemento no debe cubrir ningún píxel con una coordenada x inferior a x1 o una coordenada y inferior a y1, ni debe cubrir ningún píxel con una coordenada x mayor o igual a x2 o una coordenada y mayor o igual a y2. Corresponde al gestor de tipo mantener actualizado el cuadro delimitador a medida que el elemento se mueve y se configura.

Cada vez que Tk llama a un procedimiento de un gestor de tipo, le pasa un puntero a un registro de elemento. El argumento siempre se pasa como un puntero a un Tk_Item; el gestor de tipo normalmente lo convertirá en un puntero a su propio tipo específico, como BitmapItem.

El tercer tipo de estructura de datos utilizada por los gestores de tipo es Tk_Canvas; sirve como un identificador opaco para el widget de lienzo en su conjunto. Los gestores de tipo no necesitan saber nada sobre el contenido de esta estructura. Normalmente se pasa un identificador Tk_Canvas a los procedimientos de un gestor de tipo, y el gestor de tipo puede pasar el identificador de vuelta a procedimientos de la biblioteca como Tk_CanvasTkwin para obtener información sobre el lienzo.

CAMPOS DE TK_ITEMTYPE

NOMBRE

Esta sección y las siguientes describen cada uno de los campos de una estructura Tk_ItemType en detalle. El campo name proporciona un nombre de cadena para el tipo de elemento. Una vez que Tk_CreateImageType retorna, este nombre puede usarse en comandos de widget create para crear elementos del nuevo tipo. Si ya existía un tipo de elemento con este nombre, el nuevo tipo de elemento reemplaza al antiguo.

FLAGS (EN ALWAYSREDRAW)

El campo typePtr->alwaysRedraw (llamado así por razones históricas) contiene una colección de bits de bandera que modifican cómo el núcleo del lienzo interactúa con el elemento. Los siguientes bits están definidos:

1
Indica que el elemento debe redibujarse siempre que se redibuje alguna parte del lienzo, en lugar de solo cuando el cuadro delimitador del elemento se superpone con el área que se está redibujando. Esto lo usan, por ejemplo, los elementos de ventana, que necesitan desmapear subventanas que no están en la pantalla.
TK_CONFIG_OBJS
Indica que las operaciones que de otro modo tomarían una cadena (o arreglo de cadenas) en realidad toman una referencia Tcl_Obj (o un arreglo de dichas referencias). Las operaciones a las que se aplica esto son configProc, coordProc, createProc, indexProc y insertProc.
TK_MOVABLE_POINTS
Indica que el elemento soporta dCharsProc, indexProc e insertProc con la misma semántica que los tipos de línea y polígono integrados de Tk, y que por lo tanto los puntos de coordenadas individuales pueden moverse. No debe establecerse si alguno de los métodos anteriores es NULL.

ITEMSIZE

typePtr->itemSize proporciona el tamaño en bytes de los registros de elementos de este tipo, incluida la cabecera Tk_Item. Tk utiliza este tamaño para asignar espacio de memoria para los elementos del tipo. Todos los registros de elementos de un tipo dado deben tener el mismo tamaño. Si se necesitan campos de longitud variable para un elemento (como una lista de puntos para un polígono), el gestor de tipo puede asignar un objeto separado de longitud variable y mantener un puntero a él en el registro de elemento.

CREATEPROC

Tk_CanvasItemType

A canvas widget supports items of different types (e.g., rectangles, text, bitmaps). For each type, there is a type manager that handles the creation, configuration, deletion, display, and other operations for items of that type. All type managers must be registered with Tk using Tk_CreateCanvasItemType.

The structure of a type manager is described by a Tk_CanvasItemType structure, which is defined as follows:

typedef struct Tk_CanvasItemType {
    const char *name;
    size_t itemSize;
    Tk_ItemCreateProc *createProc;
    Tk_ItemConfigProc *configProc;
    Tk_ItemDeleteProc *deleteProc;
    Tk_ItemDisplayProc *displayProc;
    Tk_ItemPointProc *pointProc;
    Tk_ItemAreaProc *areaProc;
    Tk_ItemNotifyProc *notifyProc;
    Tk_ItemPostscriptProc *postscriptProc;
    int flags;
} Tk_CanvasItemType;

The fields of the structure are:

name
The name of the item type (e.g., "rectangle", "text", "bitmap"). This must be a unique name among all canvas item types.
itemSize
The size, in bytes, of the structure used to store type-specific information for items of this type. This structure must begin with a Tk_ItemType header.
createProc
Points to a procedure that is called by Tk whenever a new item of this type is created. See the createProc section below.
configProc
Points to a procedure that is called by Tk whenever an item of this type is configured. See the configProc section below.
deleteProc
Points to a procedure that is called by Tk whenever an item of this type is deleted. See the deleteProc section below.
displayProc
Points to a procedure that is called by Tk whenever an item of this type needs to be redrawn. See the displayProc section below.
pointProc
Points to a procedure that is called by Tk to determine how close a point is to an item. See the pointProc section below.
areaProc
Points to a procedure that is called by Tk to determine the relationship between an item and a rectangular area. See the areaProc section below.
notifyProc
Points to a procedure that is called by Tk whenever an item of this type is selected, deselected, or dragged. This field may be NULL if the item type does not need to respond to these events. See the Tk manual page for Tk_CanvasItemType for more information.
postscriptProc
Points to a procedure that is called by Tk to generate Postscript output for an item. This field may be NULL if the item type does not support Postscript output. See the postscriptProc section below.
flags
A bitmask that can be used to control various aspects of the item type's behavior. Currently, the only defined flag is TK_CONFIG_OBJS, which indicates that the configuration options should be passed as Tcl objects (instead of strings). If this flag is not set, then objc and objv in the createProc and configProc procedures will refer to an array of strings. For more information, see the description of Tk_ConfigureWidget.

Tk_CreateCanvasItemType

This function is used to register a new canvas item type with Tk.

void Tk_CreateCanvasItemType(
        Tcl_Interp *interp,
        Tk_CanvasItemType *typePtr);

interp is the interpreter in which to register the item type. typePtr points to a Tk_CanvasItemType structure that describes the new item type.

Tk_CanvasGetItemType

This function returns a pointer to the Tk_CanvasItemType structure for the given item type name.

Tk_CanvasItemType *Tk_CanvasGetItemType(
        Tcl_Interp *interp,
        const char *typeName);

interp is the interpreter, and typeName is the name of the item type.

createProc

typePtr->createProc points to a procedure for Tk to call whenever a new item of this type is created. typePtr->createProc must match the following prototype:

typedef int Tk_ItemCreateProc(
        Tcl_Interp *interp,
        Tk_Canvas canvas,
        Tk_Item *itemPtr,
        int objc,
        Tcl_Obj *const objv[]);

The interp argument is the interpreter in which the canvas's create widget command was invoked, and canvas is a handle for the canvas widget. itemPtr is a pointer to a newly-allocated item of size typePtr->itemSize. Tk has already initialized the item's header (the first sizeof(Tk_ItemType) bytes). The objc and objv arguments describe all of the arguments to the create command after the type argument. Note that if TK_CONFIG_OBJS is not set in the typePtr->alwaysRedraw field, the objv parameter will actually contain a pointer to an array of constant strings. For example, in the widget command:

.c create rectangle 10 20 50 50 -fill black

objc will be 6 and objv[0] will contain the integer object 10.

createProc should use objc and objv to initialize the type-specific parts of the item record and set an initial value for the bounding box in the item's header. It should return a standard Tcl completion code and leave an error message in the interpreter result if an error occurs. If an error occurs Tk will free the item record, so createProc must be sure to leave the item record in a clean state if it returns an error (e.g., it must free any additional memory that it allocated for the item).

CONFIGSPECS

Each type manager must provide a standard table describing its configuration options, in a form suitable for use with Tk_ConfigureWidget. This table will normally be used by typePtr->createProc and typePtr->configProc, but Tk also uses it directly to retrieve option information in the itemcget and itemconfigure widget commands. typePtr->configSpecs must point to the configuration table for this type. Note: Tk provides a custom option type tk_CanvasTagsOption for implementing the -tags option; see an existing type manager for an example of how to use it in configSpecs.

CONFIGPROC

typePtr->configProc is called by Tk whenever the itemconfigure widget command is invoked to change the configuration options for a canvas item. This procedure must match the following prototype:

typedef int Tk_ItemConfigureProc(
        Tcl_Interp *interp,
        Tk_Canvas canvas,
        Tk_Item *itemPtr,
        int objc,
        Tcl_Obj *const objv[],
        int flags);

The interp argument identifies the interpreter in which the widget command was invoked, canvas is a handle for the canvas widget, and itemPtr is a pointer to the item being configured. objc and objv contain the configuration options. Note that if TK_CONFIG_OBJS is not set in the typePtr->alwaysRedraw field, the objv parameter will actually contain a pointer to an array of constant strings. For example, if the following command is invoked:

.c itemconfigure 2 -fill red -outline black

objc is 4 and objv contains the string objects -fill through black. objc will always be an even value. The flags argument contains flags to pass to Tk_ConfigureWidget; currently this value is always TK_CONFIG_ARGV_ONLY when Tk invokes typePtr->configProc, but the type manager's createProc procedure will usually invoke configProc with different flag values.

typePtr->configProc returns a standard Tcl completion code and leaves an error message in the interpreter result if an error occurs. It must update the item's bounding box to reflect the new configuration options.

COORDPROC

typePtr->coordProc is invoked by Tk to implement the coords widget command for an item. It must match the following prototype:

typedef int Tk_ItemCoordProc(
        Tcl_Interp *interp,
        Tk_Canvas canvas,
        Tk_Item *itemPtr,
        int objc,
        Tcl_Obj *const objv[]);

The arguments interp, canvas, and itemPtr all have the standard meanings, and objc and objv describe the coordinate arguments. Note that if TK_CONFIG_OBJS is not set in the typePtr->alwaysRedraw field, the objv parameter will actually contain a pointer to an array of constant strings. For example, if the following widget command is invoked:

.c coords 2 30 90

objc will be 2 and objv will contain the integer objects 30 and 90.

The coordProc procedure should process the new coordinates, update the item appropriately (e.g., it must reset the bounding box in the item's header), and return a standard Tcl completion code. If an error occurs, coordProc must leave an error message in the interpreter result.

DELETEPROC

typePtr->deleteProc is invoked by Tk to delete an item and free any resources allocated to it. It must match the following prototype:

typedef void Tk_ItemDeleteProc(
        Tk_Canvas canvas,
        Tk_Item *itemPtr,
        Display *display);

The canvas and itemPtr arguments have the usual interpretations, and display identifies the X display containing the canvas. deleteProc must free up any resources allocated for the item, so that Tk can free the item record. deleteProc should not actually free the item record; this will be done by Tk when deleteProc returns.

DISPLAYPROC

typePtr->displayProc is invoked by Tk to redraw an item on the screen. It must match the following prototype:

typedef void Tk_ItemDisplayProc(
        Tk_Canvas canvas,
        Tk_Item *itemPtr,
        Display *display,
        Drawable dst,
        int x,
        int y,
        int width,
        int height);

The canvas and itemPtr arguments have the usual meaning. display identifies the display containing the canvas, and dst specifies a drawable in which the item should be rendered; typically this is an off-screen pixmap, which Tk will copy into the canvas's window once all relevant items have been drawn. x, y, width, and height specify a rectangular region in canvas coordinates, which is the area to be redrawn; only information that overlaps this area needs to be redrawn. Tk will not call displayProc unless the item's bounding box overlaps the redraw area, but the type manager may wish to use the redraw area to optimize the redisplay of the item.

Because of scrolling and the use of off-screen pixmaps for double-buffered redisplay, the item's coordinates in dst will not necessarily be the same as those in the canvas. displayProc should call Tk_CanvasDrawableCoords to transform coordinates from those of the canvas to those of dst.

Normally an item's displayProc is only invoked if the item overlaps the area being displayed. However, if bit zero of typePtr->alwaysRedraw is 1, (i.e. “typePtr->alwaysRedraw & 1 == 1”) then displayProc is invoked during every redisplay operation, even if the item does not overlap the area of redisplay; this is useful for cases such as window items, where the subwindow needs to be unmapped when it is off the screen.

POINTPROC

typePtr->pointProc is invoked by Tk to find out how close a given point is to a canvas item. Tk uses this procedure for purposes such as locating the item under the mouse or finding the closest item to a given point. The procedure must match the following prototype:

typedef double Tk_ItemPointProc(
        Tk_Canvas canvas,
        Tk_Item *itemPtr,
        double *pointPtr);

canvas and itemPtr have the usual meaning. pointPtr points to an array of two numbers giving the x and y coordinates of a point. pointProc must return a real value giving the distance from the point to the item, or 0 if the point lies inside the item.

AREAPROC

typePtr->areaProc is invoked by Tk to find out the relationship between an item and a rectangular area. It must match the following prototype:

typedef int Tk_ItemAreaProc(
        Tk_Canvas canvas,
        Tk_Item *itemPtr,
        double *rectPtr);

canvas and itemPtr have the usual meaning. rectPtr points to an array of four real numbers; the first two give the x and y coordinates of the upper left corner of a rectangle, and the second two give the x and y coordinates of the lower right corner. areaProc must return -1 if the item lies entirely outside the given area, 0 if it lies partially inside and partially outside the area, and 1 if it lies entirely inside the area.

POSTSCRIPTPROC

typePtr->postscriptProc is invoked by Tk to generate Postscript for an item during the postscript widget command. If the type manager is not capable of generating Postscript then typePtr->postscriptProc should be NULL. The procedure must match the following prototype:

typedef int Tk_ItemPostscriptProc(
        Tcl_Interp *interp,
        Tk_Canvas canvas,
        Tk_Item *itemPtr,
        int prepass);

The interp, canvas, and itemPtr arguments all have the usual meanings. prepass is a non-zero value if this is the first pass of the postscript generation (used for things like defining colors and fonts), and zero for the second pass (used for drawing the actual item).

The procedure should return a standard Tcl return code. If an error occurs, it should leave an error message in the interpreter result.

Tk_CreateItemType (3)

NOMBRE

Tk_CreateItemType - registra un nuevo tipo de elemento en un canvas

SINOPSIS

#include <tk.h>

Tk_ItemType *
Tk_CreateItemType(name, createProc, deleteProc, displayProc,
        measureProc, pointProc, configureProc, classPtr)
    CONST84 char *name;
    Tk_ItemCreateProc *createProc;
    Tk_ItemDeleteProc *deleteProc;
    Tk_ItemDisplayProc *displayProc;
    Tk_ItemMeasureProc *measureProc;
    Tk_ItemPointProc *pointProc;
    Tk_ItemConfigureProc *configureProc;
    Tk_ItemType **classPtr;

ARGUMENTOS

name (entrada)
El nombre del nuevo tipo de elemento, como "rectángulo" o "imagen". El nombre debe ser único.
createProc (entrada)
El procedimiento que se llamará cuando se cree un nuevo elemento de este tipo. Este procedimiento es responsable de inicializar los campos del elemento y devolver el tamaño en bytes de la estructura de datos privada del elemento.
deleteProc (entrada)
El procedimiento que se llamará cuando se elimine un elemento de este tipo. Este procedimiento es responsable de liberar cualquier recurso asignado por el procedimiento createProc.
displayProc (entrada)
El procedimiento que se llamará para dibujar un elemento de este tipo. Este procedimiento es responsable de dibujar el elemento en la ventana especificada.
measureProc (entrada)
El procedimiento que se llamará para medir un elemento de este tipo. Este procedimiento es responsable de devolver las dimensiones del elemento.
pointProc (entrada)
El procedimiento que se llamará para determinar si un punto dado está dentro de un elemento de este tipo. Este procedimiento es responsable de devolver un valor distinto de cero si el punto está dentro del elemento, o cero en caso contrario.
configureProc (entrada)
El procedimiento que se llamará para configurar o reconfigurar un elemento de este tipo. Este procedimiento es responsable de actualizar los campos del elemento según las opciones especificadas.
classPtr (entrada/salida)
Un puntero a un puntero que contendrá el puntero al nuevo tipo de elemento después de que se haya creado. Si ya existe un tipo de elemento con el mismo nombre, se devolverá su puntero y no se creará un nuevo tipo.

INTRODUCCIÓN

La función Tk_CreateItemType se utiliza para registrar un nuevo tipo de elemento con el sistema de elementos del canvas de Tk. Esto permite a los desarrolladores extender el widget de canvas de Tk para admitir nuevos tipos de elementos personalizados.

Cuando se llama a Tk_CreateItemType, se crea una nueva entrada en la tabla de tipos de elementos de Tk. Esta entrada contiene punteros a los procedimientos que se utilizarán para crear, eliminar, mostrar, medir, determinar si un punto está dentro y configurar elementos de este nuevo tipo.

Los procedimientos pasados a Tk_CreateItemType deben seguir las firmas especificadas en los archivos de encabezado de Tk. Estos procedimientos son responsables de gestionar los datos privados asociados con cada elemento de este tipo.

ESTRUCTURAS_DE_DATOS

La función Tk_CreateItemType utiliza la siguiente estructura de datos para representar un tipo de elemento:

typedef struct Tk_ItemType {
    CONST84 char *name;
    Tk_ItemCreateProc *createProc;
    Tk_ItemDeleteProc *deleteProc;
    Tk_ItemDisplayProc *displayProc;
    Tk_ItemMeasureProc *measureProc;
    Tk_ItemPointProc *pointProc;
    Tk_ItemConfigureProc *configureProc;
    Tk_ItemType **nextPtr;
} Tk_ItemType;

Donde:

  • name: El nombre del tipo de elemento.
  • createProc: El procedimiento de creación.
  • deleteProc: El procedimiento de eliminación.
  • displayProc: El procedimiento de visualización.
  • measureProc: El procedimiento de medición.
  • pointProc: El procedimiento para verificar si un punto está dentro.
  • configureProc: El procedimiento de configuración.
  • nextPtr: Se utiliza internamente por Tk para encadenar tipos de elementos.

CAMPOS_TK_ITEMTYPE

Los campos de la estructura Tk_ItemType son los siguientes:

  • name: El nombre del tipo de elemento (por ejemplo, "rectángulo", "cadena").
  • createProc: Puntero a la función que se llama cuando se crea un elemento de este tipo.
  • deleteProc: Puntero a la función que se llama cuando se elimina un elemento de este tipo.
  • displayProc: Puntero a la función que se llama para dibujar un elemento de este tipo.
  • measureProc: Puntero a la función que se llama para obtener las dimensiones de un elemento de este tipo.
  • pointProc: Puntero a la función que se llama para determinar si un punto está dentro de un elemento de este tipo.
  • configureProc: Puntero a la función que se llama para configurar o reconfigurar un elemento de este tipo.
