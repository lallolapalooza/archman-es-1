DESCRIPCIÓN

Estos procedimientos administran una colección de bitmaps (pixmaps de un solo plano) que está siendo utilizada por una aplicación. Los procedimientos permiten reutilizar bitmaps de manera eficiente, evitando así la sobrecarga del servidor, y también permiten nombrar bitmaps con cadenas de caracteres.

Tk_AllocBitmapFromObj devuelve un identificador Pixmap para un bitmap que coincide con la descripción en objPtr y es adecuado para su uso en tkwin. Reutiliza un bitmap existente, si es posible, y crea uno nuevo en caso contrario. El valor de objPtr debe tener una de las siguientes formas:

@nombreArchivo
NombreArchivo debe ser el nombre de un archivo que contenga una descripción de bitmap en el formato estándar de X11.
nombre
Nombre debe ser el nombre de un bitmap definido previamente con una llamada a Tk_DefineBitmap. Los siguientes nombres están predefinidos por Tk:
error
El símbolo internacional de “no”: un círculo con una línea diagonal que lo atraviesa.
gray75
75% de gris: un patrón de tablero de ajedrez donde tres de cada cuatro bits están activados.
gray50
50% de gris: un patrón de tablero de ajedrez donde cada dos bits están activados.
gray25
25% de gris: un patrón de tablero de ajedrez donde uno de cada cuatro bits está activado.
gray12
12.5% de gris: un patrón donde una octava parte de los bits están activados, consistente en cada cuarto píxel en filas alternas.
hourglass
Un símbolo de reloj de arena.
info
Una letra “i” grande.
questhead
La silueta de una cabeza humana, con un signo de interrogación dentro.
question
Un signo de interrogación grande.
warning
Un signo de exclamación grande.

Un cubo de basura.

Un disco flexible.

Un icono de disco CD.

Una cara con globos de texto.

Un triángulo con un signo de exclamación.

En condiciones normales, Tk_AllocBitmapFromObj devuelve un identificador para el bitmap solicitado. Si ocurre un error al crear el bitmap, como cuando objPtr se refiere a un archivo inexistente, entonces se devuelve None y se deja un mensaje de error en el resultado de interp si interp no es NULL. Tk_AllocBitmapFromObj almacena en caché información sobre el valor de retorno en objPtr, lo que acelera las llamadas futuras a procedimientos como Tk_AllocBitmapFromObj y Tk_GetBitmapFromObj.

Tk_GetBitmap es idéntico a Tk_AllocBitmapFromObj excepto que la descripción del bitmap se especifica con una cadena en lugar de un objeto. Esto evita que Tk_GetBitmap almacene en caché el valor de retorno, por lo que Tk_GetBitmap es menos eficiente que Tk_AllocBitmapFromObj.

Tk_GetBitmapFromObj devuelve el token de un bitmap existente, dada la ventana y la descripción utilizadas para crear el bitmap. Tk_GetBitmapFromObj no crea realmente el bitmap; el bitmap debe haber sido creado previamente con una llamada a Tk_AllocBitmapFromObj o Tk_GetBitmap. El valor de retorno se almacena en caché en objPtr, lo que acelera las llamadas futuras a Tk_GetBitmapFromObj con el mismo objPtr y tkwin.

Tk_DefineBitmap asocia un nombre con datos de bitmap en memoria para que el nombre pueda ser utilizado en llamadas posteriores a Tk_AllocBitmapFromObj o Tk_GetBitmap. El argumento nameId proporciona un nombre para el bitmap; no debe haber sido utilizado previamente en una llamada a Tk_DefineBitmap. Los argumentos source, width y height describen el bitmap. Tk_DefineBitmap normalmente devuelve TCL_OK; si ocurre un error (por ejemplo, ya se ha definido un bitmap llamado nameId), entonces se devuelve TCL_ERROR y se deja un mensaje de error en el resultado del intérprete interp. Nota: Tk_DefineBitmap espera que la memoria apuntada por source sea estática: Tk_DefineBitmap no hace una copia privada de esta memoria, sino que utiliza los bytes apuntados por source más adelante en llamadas a Tk_AllocBitmapFromObj o Tk_GetBitmap.

ARGUMENTS

Tcl_Interp *interp
Interpreter to use for error reporting and for accessing the Tk database.
const char *name
Name to give to the bitmap.
CONST char *bits
Pointer to character array containing bitmap data.
int width
Width of bitmap in pixels.
int height
Height of bitmap in pixels.
Tcl_Obj *value
In Tk 8.6 and later, the value describing the bitmap to allocate or free. This is typically a string like "@filename", "name", or "#RRGGBB".
Tk_Window tkwin
Window to use for bitmap operations (needed for determining screen and depth).
const char *string
String describing the bitmap. Formats: "@filename" to read a bitmap from a file, "name" to refer to a previously defined bitmap (see Tk_DefineBitmap), or "#RRGGBB" for a solid color bitmap.
Pixmap bitmap
The X Pixmap token for the bitmap to be freed, whose name is desired, or whose size is desired.
int *widthPtr
Address to store the width of the bitmap.
int *heightPtr
Address to store the height of the bitmap.

DESCRIPTION

A bitmap is a 1-bit-per-pixel image. Tk supports bitmaps created from files, from character arrays compiled into the program, and from solid colors.

The procedure Tk_DefineBitmap is used to define a new bitmap by incorporating its data directly into the application. This is most often used for standard bitmaps (like those used for mouse cursors) that are part of the Tk distribution. The bits argument points to a C array containing the bitmap data, usually generated by the bitmap program and contains a stipple pattern. The following code uses Tk_DefineBitmap to define a new bitmap named foo:

Pixmap bitmap;
#include "stip.bitmap"
Tk_DefineBitmap(interp, "foo", stip_bits,
    stip_width, stip_height);
...
bitmap = Tk_GetBitmap(interp, tkwin, "foo");

This code causes the bitmap file to be read at compile-time and incorporates the bitmap information into the program's executable image. The same bitmap file could be read at run-time using Tk_GetBitmap:

Pixmap bitmap;
bitmap = Tk_GetBitmap(interp, tkwin, "@stip.bitmap");

The second form is a bit more flexible (the file could be modified after the program has been compiled, or a different string could be provided to read a different file), but it is a little slower and requires the bitmap file to exist separately from the program.

Tk maintains a database of all the bitmaps that are currently in use. Whenever possible, it will return an existing bitmap rather than creating a new one. When a bitmap is no longer used, Tk will release it automatically. This approach can substantially reduce server overhead, so Tk_AllocBitmapFromObj and Tk_GetBitmap should generally be used in preference to Xlib procedures like XReadBitmapFile.

The bitmaps returned by Tk_AllocBitmapFromObj and Tk_GetBitmap are shared, so callers should never modify them. If a bitmap must be modified dynamically, then it should be created by calling Xlib procedures such as XReadBitmapFile or XCreatePixmap directly.

The procedure Tk_NameOfBitmap is roughly the inverse of Tk_GetBitmap. Given an X Pixmap argument, it returns the textual description that was passed to Tk_GetBitmap when the bitmap was created. Bitmap must have been the return value from a previous call to Tk_AllocBitmapFromObj or Tk_GetBitmap.

Tk_SizeOfBitmap returns the dimensions of its bitmap argument in the words pointed to by the widthPtr and heightPtr arguments. As with Tk_NameOfBitmap, bitmap must have been created by Tk_AllocBitmapFromObj or Tk_GetBitmap.

When a bitmap is no longer needed, Tk_FreeBitmapFromObj or Tk_FreeBitmap should be called to release it. For Tk_FreeBitmapFromObj the bitmap to release is specified with the same information used to create it; for Tk_FreeBitmap the bitmap to release is specified with its Pixmap token. There should be exactly one call to Tk_FreeBitmapFromObj or Tk_FreeBitmap for each call to Tk_AllocBitmapFromObj or Tk_GetBitmap.

BUGS

In determining whether an existing bitmap can be used to satisfy a new request, Tk_AllocBitmapFromObj and Tk_GetBitmap consider only the immediate value of the string description. For example, when a file name is passed to Tk_GetBitmap, Tk_GetBitmap will assume it is safe to re-use an existing bitmap created from the same file name: it will not check to see whether the file itself has changed, or whether the current directory has changed, thereby causing the name to refer to a different file.
