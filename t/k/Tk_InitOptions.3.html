NOMBRE

Tk_CreateOptionTable, Tk_DeleteOptionTable, Tk_InitOptions, Tk_SetOptions, Tk_FreeSavedOptions, Tk_RestoreSavedOptions, Tk_GetOptionValue, Tk_GetOptionInfo, Tk_FreeConfigOptions, Tk_Offset - procesar opciones de configuración

Tk_RestoreSavedOptions(savedPtr)

Tk_GetOptionValue(interp, recordPtr, optionTable, namePtr, tkwin)

ARGUMENTOS

Tcl_Interp *interp (entrada)
Un intérprete de Tcl. La mayoría de los procedimientos utilizan esto solo para devolver mensajes de error; si es NULL, no se devuelven mensajes de error. Para Tk_CreateOptionTable, el valor no puede ser NULL; proporciona el intérprete en el que se utilizará la tabla de opciones.
const Tk_OptionSpec *templatePtr (entrada)
Apunta a una matriz de información estática que describe las opciones de configuración que se admiten. Se utiliza para construir una Tk_OptionTable. La información a la que apunta este argumento debe existir durante la vida útil de la Tk_OptionTable.
Tk_OptionTable optionTable (entrada)
Token para una tabla de opciones. Debe haber sido devuelto por una llamada previa a Tk_CreateOptionTable.
char *recordPtr (entrada/salida)
Apunta a la estructura en la que se almacenan los valores de las opciones de configuración; los campos de este registro son modificados por procedimientos como Tk_SetOptions y leídos por procedimientos como Tk_GetOptionValue.
Tk_Window tkwin (entrada)
Para opciones como TK_OPTION_COLOR, este argumento indica la ventana en la que se utilizará la opción. Si optionTable no utiliza opciones dependientes de la ventana, se puede proporcionar un valor NULL para este argumento.
int objc (entrada)
Número de valores en objv.
Tcl_Obj *const *objv (entrada)
Argumentos de línea de comandos para establecer opciones de configuración.
Tk_SavedOptions *savePtr (salida)
Si no es NULL, la estructura apuntada por este argumento se rellena con los valores antiguos de las opciones modificadas y los valores antiguos se restauran automáticamente si ocurre un error en Tk_SetOptions.
int *maskPtr (salida)
Si no es NULL, la palabra apuntada por maskPtr se rellena con el OR a nivel de bits de los campos typeMask de las opciones que se modificaron.
Tk_SavedOptions *savedPtr (entrada/salida)
Apunta a una estructura previamente rellenada por Tk_SetOptions con los valores antiguos de las opciones modificadas.
Tcl_Obj *namePtr (entrada)
El valor de este objeto es el nombre de una opción particular. Si se pasa NULL a Tk_GetOptionInfo, se devuelve información para todas las opciones. No debe ser NULL cuando se llama a Tk_GetOptionValue.
type name type (entrada)
El nombre del tipo de un registro.
field name field (entrada)
El nombre de un campo en registros del tipo type.

DESCRIPCIÓN

Estos procedimientos manejan la mayoría de los detalles de análisis de opciones de configuración, como las de los widgets Tk. Dada una descripción de las opciones admitidas, estos procedimientos se encargan de todos los detalles de análisis de opciones y de almacenar sus valores en una estructura C asociada con el widget u objeto. Los procedimientos fueron diseñados principalmente para widgets en Tk, pero también se pueden usar para otros tipos de objetos que tienen opciones de configuración. En el resto de esta página del manual, se usará "widget" para referirse al objeto cuyas opciones se están gestionando; en la práctica, el objeto puede que no sea realmente un widget. El término "registro de widget" se utiliza para referirse a la estructura a nivel de C en la que se almacena información sobre un widget u objeto particular.

Tenga en cuenta que la forma más sencilla de aprender a usar estos procedimientos es mirar un ejemplo funcional. En Tk, el ejemplo más simple es el código que implementa la familia de widgets de botón, que se encuentra en tkButton.c. Otros ejemplos se encuentran en tkSquare.c y tkMenu.c.

Para utilizar estos procedimientos, el código que implementa el widget debe contener una matriz estática de estructuras Tk_OptionSpec. Esta es una plantilla que describe las diversas opciones admitidas por esa clase de widget; hay una plantilla separada para cada tipo de widget. La plantilla contiene información como el nombre de cada opción, su tipo, su valor por defecto y dónde se almacena el valor de la opción en el registro del widget. Consulte PLANTILLAS a continuación para obtener más detalles.

Para procesar las opciones de configuración de manera eficiente, la plantilla estática debe complementarse con información adicional que solo está disponible en tiempo de ejecución. El procedimiento Tk_CreateOptionTable crea esta información dinámica a partir de la plantilla y devuelve un token Tk_OptionTable que describe la información estática y dinámica. Todos los demás procedimientos, como Tk_SetOptions, toman un token Tk_OptionTable como argumento. Normalmente, Tk_CreateOptionTable se llama la primera vez que se crea un widget de una clase particular y la Tk_OptionTable resultante se utiliza en el futuro para todos los widgets de esa clase. Una Tk_OptionTable solo se puede usar en un único intérprete, proporcionado por el argumento interp a Tk_CreateOptionTable. Cuando una tabla de opciones ya no es necesaria, se debe llamar a Tk_DeleteOptionTable para liberar todos sus recursos. Todas las tablas de opciones para un intérprete Tcl se liberan automáticamente si se elimina el intérprete.

Tk_InitOptions se invoca cuando se crea un nuevo widget para establecer los valores por defecto. Tk_InitOptions recibe un token para una tabla de opciones (optionTable) y un puntero a un registro de widget (recordPtr), que es la estructura C que contiene información sobre este widget. Tk_InitOptions utiliza la información de la tabla de opciones para elegir un valor predeterminado adecuado para cada opción, luego almacena el valor predeterminado directamente en el registro del widget, sobrescribiendo cualquier información que ya estuviera presente en el registro del widget. Tk_InitOptions normalmente devuelve TCL_OK. Si se produjo un error al establecer los valores predeterminados (por ejemplo, debido a un valor predeterminado erróneo), entonces devuelve TCL_ERROR y se deja un mensaje de error en el resultado de interp si interp no es NULL. Para cualquier opción de configuración de un widget que tenga TK_OPTION_DONT_SET_DEFAULT establecido en su campo flags, la inicialización anterior se omite por completo, véase a continuación.

Tk_SetOptions se invoca para modificar las opciones de configuración basándose en la información especificada en un comando Tcl. El comando podría ser uno que crea un nuevo widget, o un comando que modifica opciones en un widget existente. Los argumentos objc y objv describen los valores de los argumentos del comando Tcl. Objv debe contener un número par de objetos: el primer objeto de cada par da el nombre de una opción y el segundo objeto da el nuevo valor para esa opción. Tk_SetOptions busca cada nombre en optionTable, comprueba que el nuevo valor de la opción se ajusta al tipo en optionTable y almacena el valor de la opción en el registro del widget dado por recordPtr. Tk_SetOptions normalmente devuelve TCL_OK. Si se produjo un error (como un nombre de opción desconocido o un valor de opción ilegal), entonces devuelve TCL_ERROR y se deja un mensaje de error en el resultado de interp si interp no es NULL.

Tk_SetOptions tiene dos características adicionales. Primero, si el argumento maskPtr no es NULL, entonces apunta a un valor entero que se rellena con información sobre las opciones que se modificaron. Por cada opción en la plantilla pasada a Tk_CreateOptionTable existe un campo typeMask. Los bits de este campo están definidos por el código que implementa el widget; por ejemplo, cada bit podría corresponder a una opción de configuración particular. Alternativamente, se pueden usar bits funcionalmente. Por ejemplo, un bit podría usarse para redibujar: todas las opciones que afectan la visualización del widget, de tal manera que cambiar la opción requiera que el widget se redibuje, podrían tener ese bit establecido. Otro bit podría indicar que la geometría del widget debe ser recalculada, y así sucesivamente. Tk_SetOptions combina los campos typeMask de una

The second additional feature of Tk_SetOptions has to do with error recovery. If an error occurs while processing configuration options, this feature makes it possible to restore all the configuration options to their previous values. Errors can occur either while processing options in Tk_SetOptions or later in the caller. In many cases the caller does additional processing after Tk_SetOptions returns; for example, it might use an option value to set a trace on a variable and may detect an error if the variable is an array instead of a scalar. Error recovery is enabled by passing in a non-NULL value for the savePtr argument to Tk_SetOptions; this should be a pointer to an uninitialized Tk_SavedOptions structure on the caller's stack. Tk_SetOptions overwrites the structure pointed to by savePtr with information about the old values of any options modified by the procedure. If Tk_SetOptions returns successfully, the caller uses the structure in one of two ways. If the caller completes its processing of the new options without any errors, then it must pass the structure to Tk_FreeSavedOptions so that the old values can be freed. If the caller detects an error in its processing of the new options, then it should pass the structure to Tk_RestoreSavedOptions, which will copy the old values back into the widget record and free the new values. If Tk_SetOptions detects an error then it automatically restores any options that had already been modified and leaves *savePtr in an empty state: the caller need not call either Tk_FreeSavedOptions or Tk_RestoreSavedOptions. If the savePtr argument to Tk_SetOptions is NULL then Tk_SetOptions frees each old option value immediately when it sets a new value for the option. In this case, if an error occurs in the third option, the old values for the first two options cannot be restored.

Tk_GetOptionValue returns the current value of a configuration option for a particular widget. The namePtr argument contains the name of an option; Tk_GetOptionValue uses optionTable to lookup the option and extract its value from the widget record pointed to by recordPtr, then it returns an object containing that value. If an error occurs (e.g., because namePtr contains an unknown option name) then NULL is returned and an error message is left in interp's result unless interp is NULL.

Tk_GetOptionInfo returns information about configuration options in a form suitable for configure widget commands. If the namePtr argument is not NULL, it points to an object that gives the name of a configuration option; Tk_GetOptionInfo returns an object containing a list with five elements, which are the name of the option, the name and class used for the option in the option database, the default value for the option, and the current value for the option. If the namePtr argument is NULL, then Tk_GetOptionInfo returns information about all options in the form of a list of lists; each sublist describes one option. Synonym options are handled differently depending on whether namePtr is NULL: if namePtr is NULL then the sublist for each synonym option has only two elements, which are the name of the option and the name of the other option that it refers to; if namePtr is non-NULL and names a synonym option then the object returned is the five-element list for the other option that the synonym refers to. If an error occurs (e.g., because namePtr contains an unknown option name) then NULL is returned and an error message is left in interp's result unless interp is NULL.

Tk_FreeConfigOptions must be invoked when a widget is deleted. It frees all of the resources associated with any of the configuration options defined in recordPtr by optionTable.

The Tk_Offset macro is provided as a safe way of generating the objOffset and internalOffset values for entries in Tk_OptionSpec structures. It takes two arguments: the name of a type of record, and the name of a field in that record. It returns the byte offset of the named field in records of the given type.

PLANTILLAS

El array de estructuras Tk_OptionSpec pasado a Tk_CreateOptionTable a través de su argumento templatePtr describe las opciones de configuración soportadas por una clase particular de widgets. Cada estructura especifica una opción de configuración y tiene los siguientes campos:

typedef struct {
    Tk_OptionType type;
    const char *optionName;
    const char *dbName;
    const char *dbClass;
    const char *defValue;
    int objOffset;
    int internalOffset;
    int flags;
    const void *clientData;
    int typeMask;
} Tk_OptionSpec;
El campo type indica qué tipo de opción de configuración es esta (por ejemplo, TK_OPTION_COLOR para un valor de color, o TK_OPTION_INT para un valor entero). Type determina cómo se analiza el valor de la opción (más sobre esto a continuación). El campo optionName es una cadena como -font o -bg; es el nombre utilizado para la opción en los comandos Tcl y se pasa a los procedimientos a través de los argumentos objc o namePtr. Los campos dbName y dbClass son utilizados por Tk_InitOptions para buscar un valor por defecto para esta opción en la base de datos de opciones; si dbName es NULL, entonces la base de datos de opciones no es utilizada por Tk_InitOptions para esta opción. El campo defValue especifica un valor por defecto para esta opción de configuración si no se especifica ningún valor en la base de datos de opciones. Los campos objOffset e internalOffset indican dónde almacenar el valor de esta opción en los registros del widget (más sobre esto a continuación); los valores para los campos objOffset e internalOffset siempre deben generarse con la macro Tk_Offset. El campo flags contiene información adicional para controlar el procesamiento de esta opción de configuración (ver más abajo para detalles). ClientData proporciona datos adicionales específicos del tipo necesarios para ciertos tipos. Por ejemplo, para los tipos TK_OPTION_COLOR, clientData es una cadena que indica el valor por defecto a utilizar en pantallas monocromáticas. Consulte las descripciones de los diferentes tipos a continuación para obtener detalles. El último campo, typeMask, es utilizado por Tk_SetOptions para devolver información sobre qué opciones fueron modificadas; consulte la descripción de Tk_SetOptions anteriormente para obtener detalles.

Cuando Tk_InitOptions y Tk_SetOptions almacenan el valor de una opción en el registro del widget, pueden hacerlo de una de dos maneras. Si el campo objOffset de Tk_OptionSpec es mayor o igual que cero, entonces el valor de la opción se almacena como un (Tcl_Obj *) en la ubicación del registro del widget dada por objOffset. Si el campo internalOffset de Tk_OptionSpec es mayor o igual que cero, entonces el valor de la opción se almacena en una forma interna específica del tipo en la ubicación del registro del widget dada por internalOffset. Por ejemplo, si el tipo de la opción es TK_OPTION_INT, entonces la forma interna es un entero. Si el campo objOffset o internalOffset es negativo, entonces el valor no se almacena de esa forma. Al menos uno de los offsets debe ser mayor o igual que cero.

El campo flags consiste en uno o más bits combinados con un operador OR. Se soportan los siguientes flags:

TK_OPTION_NULL_OK
Si este bit está establecido para una opción, se aceptará una cadena vacía como valor para la opción y la forma interna resultante será un puntero NULL, un valor cero o None, dependiendo del tipo de la opción. Si el flag no está establecido, las cadenas vacías resultarán en errores. TK_OPTION_NULL_OK se utiliza típicamente para permitir que una característica se desactive por completo, por ejemplo, establecer el valor de un cursor a None para que una ventana simplemente herede el cursor de su padre. No todos los tipos de opciones soportan el flag TK_OPTION_NULL_OK; para aquellos que lo hacen, hay una indicación explícita de ello en las descripciones a continuación.
TK_OPTION_DONT_SET_DEFAULT
Si este bit está establecido para una opción, no se establecerá ningún valor por defecto en Tk_InitOptions para esta opción. Ni la base de datos de opciones, ni ningún valor por defecto del sistema, ni optionTable se utilizan para dar un valor por defecto a esta opción. En su lugar, se asume que el llamador ya ha proporcionado un valor por defecto en el código del widget.

El campo type de cada estructura Tk_OptionSpec determina cómo analizar el valor de esa opción de configuración. El valor legal para type, y las acciones correspondientes, se describen a continuación. Si el tipo requiere que se pase un valor tkwin a procedimientos como Tk_SetOptions, o si utiliza el campo clientData de Tk_OptionSpec, entonces se indica explícitamente; si no se menciona, el tipo no requiere ni tkwin ni clientData.

TK_OPTION_ANCHOR
El valor debe ser una posición de anclaje estándar como ne o center. La forma interna es un valor Tk_Anchor como los devueltos por Tk_GetAnchorFromObj.
TK_OPTION_BITMAP
El valor debe ser un nombre de bitmap estándar de Tk. La forma interna es un token Pixmap como los devueltos por Tk_AllocBitmapFromObj. Este tipo de opción requiere que se proporcione tkwin a procedimientos como Tk_SetOptions, y soporta el flag TK_OPTION_NULL_OK.
TK_OPTION_BOOLEAN
El valor debe ser un valor booleano estándar como true o no. La forma interna es un entero con valor 0 o 1. Tenga en cuenta que si el campo objOffset no se utiliza, se perderá la información sobre el valor original de esta opción.
TK_OPTION_BORDER
El valor debe ser un nombre de color estándar como red o #ff8080. La forma interna es un token Tk_3DBorder como los devueltos por Tk_Alloc3DBorderFromObj. Este tipo de opción requiere que se proporcione tkwin a procedimientos como Tk_SetOptions, y soporta el flag TK_OPTION_NULL_OK.

El procedimiento setProc es invocado por Tk_SetOptions para convertir un Tcl_Obj en una representación interna y almacenar el valor resultante en el registro del widget. Los argumentos son:

clientData
Una copia del campo clientData en la estructura Tk_ObjCustomOption.
interp
Un puntero a un intérprete Tcl, utilizado para reportar errores.
Tkwin
Una copia del argumento tkwin a Tk_SetOptions
valuePtr
Un puntero a una referencia a un Tcl_Obj que describe el nuevo valor para la opción; podría haber sido especificado explícitamente en la llamada a Tk_SetOptions o podría provenir de la base de datos de opciones o de un valor predeterminado. Si el objOffset para la opción es no negativo (el valor de la opción se almacena como un (Tcl_Obj *) en el registro del widget), el puntero Tcl_Obj referenciado por valuePtr es el puntero que se almacenará en el objOffset para la opción. SetProc puede modificar el valor si es necesario; por ejemplo, setProc puede cambiar el valor a NULL para admitir la bandera TK_OPTION_NULL_OK.
recordPtr
Un puntero al inicio del registro del widget a modificar.
internalOffset
Desplazamiento en bytes desde el inicio del registro del widget hasta la ubicación donde se colocará la representación interna del valor de la opción.
saveInternalPtr
Un puntero al almacenamiento asignado en una estructura Tk_SavedOptions para la representación interna del valor original de la opción. Antes de establecer la opción con su nuevo valor, setProc debe establecer el valor referenciado por saveInternalPtr al valor original de la opción para admitir Tk_RestoreSavedOptions.
flags
Una copia del campo flags en la estructura Tk_OptionSpec para la opción.

SetProc devuelve un resultado Tcl estándar: TCL_OK para indicar un procesamiento exitoso, o TCL_ERROR para indicar una falla de cualquier tipo. Se puede dejar un mensaje de error en el intérprete Tcl proporcionado por interp en caso de error.

El procedimiento getProc es invocado por Tk_GetOptionValue y Tk_GetOptionInfo para recuperar una representación Tcl_Obj de la representación interna de una opción. El argumento clientData es una copia del campo clientData en la estructura Tk_ObjCustomOption. Tkwin es una copia del argumento tkwin a Tk_GetOptionValue o Tk_GetOptionInfo. RecordPtr es un puntero al inicio del registro del widget a consultar. InternalOffset es el desplazamiento en bytes desde el inicio del registro del widget hasta la ubicación donde se almacena la representación interna del valor de la opción. GetProc debe devolver un puntero a un Tcl_Obj que represente el valor de la opción.

El procedimiento restoreProc es invocado por Tk_RestoreSavedOptions para restaurar una representación interna previamente guardada de un valor de opción personalizado. El argumento clientData es una copia del campo clientData en la estructura Tk_ObjCustomOption. Tkwin es una copia del argumento tkwin a Tk_GetOptionValue o Tk_GetOptionInfo. InternalPtr es un puntero a la ubicación donde se almacena la representación interna del valor de la opción. SaveInternalPtr es un puntero al valor guardado. RestoreProc debe copiar el valor de saveInternalPtr a internalPtr para restaurar el valor. RestoreProc no necesita liberar ninguna memoria asociada con internalPtr o saveInternalPtr; freeProc será invocado para liberar esa memoria si es necesario. RestoreProc no tiene valor de retorno.

El procedimiento freeProc es invocado por Tk_SetOptions y Tk_FreeSavedOptions para liberar cualquier almacenamiento asignado para la representación interna de una opción personalizada. El argumento clientData es una copia del campo clientData en la estructura Tk_ObjCustomOption. Tkwin es una copia del argumento tkwin a Tk_GetOptionValue o Tk_GetOptionInfo. InternalPtr es un puntero a la ubicación donde se almacena la representación interna del valor de la opción. El freeProc debe liberar cualquier almacenamiento asociado con la opción. FreeProc no tiene valor de retorno.
