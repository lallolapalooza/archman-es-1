OPCIONES ESPECIFICAS DEL WIDGET

Nombre: closeEnough
Clase: CloseEnough
Interruptor: -closeenough
Especifica un valor de punto flotante que indica qué tan cerca debe estar el cursor del ratón de un elemento para que se considere que está ``dentro'' del elemento. Por defecto es 1.0.
Nombre: confine
Clase: Confine
Interruptor: -confine
Especifica un valor booleano que indica si se debe permitir o no establecer la vista del lienzo fuera de la región definida por el argumento scrollRegion. Por defecto es verdadero, lo que significa que la vista estará restringida dentro de la región de desplazamiento.
Nombre: height
Clase: Height
Interruptor: -height
Especifica una altura de ventana deseada que el widget canvas debe solicitar a su gestor de geometría. El valor puede especificarse en cualquiera de las formas descritas en la sección "COORDINADAS" más abajo.
Nombre: scrollRegion
Clase: ScrollRegion
Interruptor: -scrollregion
Especifica una lista con cuatro coordenadas que describen las coordenadas izquierda, superior, derecha e inferior de una región rectangular. Esta región se utiliza con fines de desplazamiento y se considera el límite de la información en el lienzo. Cada una de las coordenadas puede especificarse en cualquiera de las formas dadas en la sección "COORDINADAS" más abajo.
Nombre: state
Clase: State
Interruptor: -state
Modifica el estado predeterminado del lienzo, donde state puede establecerse en uno de los siguientes: normal, deshabilitado o oculto. Los elementos individuales del lienzo tienen su propia opción de estado, que anula el estado predeterminado. Muchas opciones pueden tener especificaciones separadas de modo que la apariencia del elemento pueda ser diferente en diferentes situaciones. Las opciones que comienzan con "active" controlan la apariencia cuando el puntero del ratón está sobre él, mientras que la opción que comienza con "disabled" controla la apariencia cuando el estado está deshabilitado.
Nombre: width
Clase: width
Interruptor: -width
Especifica un ancho de ventana deseado que el widget canvas debe solicitar a su gestor de geometría. El valor puede especificarse en cualquiera de las formas descritas en la sección "COORDINADAS" más abajo.
Nombre: xScrollIncrement
Clase: ScrollIncrement
Interruptor: -xscrollincrement
Especifica un incremento para el desplazamiento horizontal, en cualquiera de las formas usuales permitidas para distancias de pantalla. Si el valor de esta opción es mayor que cero, la vista horizontal en la ventana estará restringida de modo que la coordenada x del lienzo en el borde izquierdo de la ventana sea siempre un múltiplo par de xScrollIncrement; además, las unidades de desplazamiento (por ejemplo, el cambio de vista cuando se seleccionan las flechas izquierda y derecha de una barra de desplazamiento) también serán xScrollIncrement. Si el valor de esta opción es menor o igual a cero, el desplazamiento horizontal no estará restringido.
Nombre: yScrollIncrement
Clase: ScrollIncrement
Interruptor: -yscrollincrement
Especifica un incremento para el desplazamiento vertical, en cualquiera de las formas usuales permitidas para distancias de pantalla. Si el valor de esta opción es mayor que cero, la vista vertical en la ventana estará restringida de modo que la coordenada y del lienzo en el borde superior de la ventana sea siempre un múltiplo par de yScrollIncrement; además, las unidades de desplazamiento (por ejemplo, el cambio de vista cuando se seleccionan las flechas superior e inferior de una barra de desplazamiento) también serán yScrollIncrement. Si el valor de esta opción es menor o igual a cero, el desplazamiento vertical no estará restringido.

DESCRIPCION

El método Canvas crea una nueva ventana (dada por el argumento $lienzo) y la convierte en un widget canvas. Opciones adicionales, descritas anteriormente, pueden especificarse en la línea de comandos o en la base de datos de opciones para configurar aspectos del lienzo, como sus colores y su relieve 3D. El comando canvas devuelve su argumento $lienzo. En el momento en que se invoca este comando, no debe existir una ventana llamada $lienzo, pero el padre de $lienzo debe existir.

Los widgets Canvas implementan gráficos estructurados. Un lienzo muestra cualquier número de elementos, que pueden ser cosas como rectángulos, círculos, líneas y texto. Los elementos pueden manipularse (por ejemplo, moverse o recoloearse) y se pueden asociar devoluciones de llamada a los elementos de manera muy similar a como el método bind permite asociar devoluciones de llamada a widgets. Por ejemplo, se puede asociar una devolución de llamada particular al evento <Button-1> para que se invoque cada vez que se presiona el botón 1 con el cursor del ratón sobre un elemento. Esto significa que los elementos en un lienzo pueden tener comportamientos definidos por las devoluciones de llamada asociadas a ellos.

LISTA DE PANTALLA

Los elementos de un lienzo se ordenan para fines de visualización, de modo que el primer elemento de la lista de visualización se muestra primero, seguido por el siguiente elemento de la lista, y así sucesivamente. Los elementos posteriores en la lista de visualización ocultan los anteriores y a veces se les denomina como que están ``encima'' de los elementos anteriores. Cuando se crea un nuevo elemento, se coloca al final de la lista de visualización, encima de todo lo demás. Se pueden utilizar métodos de widget para reorganizar el orden de la lista de visualización.

Los elementos de ventana son una excepción a las reglas anteriores. Los sistemas de ventanas subyacentes requieren que siempre se dibujen encima de otros elementos. Además, el orden de apilamiento de los elementos de ventana no se ve afectado por ninguno de los métodos del lienzo; debe usar los métodos de widget raise y lower de Tk en su lugar.

ITEM CREATION METHODS

The following methods are used to create canvas items. All of them return the id of the newly created item.

$canvas->create(type, x, y, ?option, value, ...?)
This is the generic method for creating any type of canvas item. The type argument specifies the type of item to create (e.g., 'arc', 'bitmap', 'image', 'line', 'polygon', 'rectangle', 'text', or 'window'). The arguments x and y specify the item's position. The available options depend on the item type.
$canvas->arc(x1, y1, x2, y2, ?option, value, ...?)
Creates an arc item. x1, y1, x2, y2 define the bounding box for the arc. The arc is drawn counterclockwise from the start angle to the end angle. Angles are measured in degrees counterclockwise from the 3 o'clock position. The following options are supported:
fill color
Specifies the interior color of the arc. Defaults to no fill.
outline color
Specifies the outline color of the arc. Defaults to no outline.
style style
Specifies the style of the arc. Can be 'pieslice', 'chord', or 'arc'. Defaults to 'chord'.
start angle
Specifies the starting angle of the arc. Defaults to 0.
extent angle
Specifies the extent of the arc in degrees. Defaults to 90.
width amount
Specifies the width of the outline in screen units. Defaults to 1.
tags tagList
A list of tags to associate with the item.
$canvas->bitmap(x, y, ?option, value, ...?)
Creates a bitmap item. x and y are the coordinates of the center of the bitmap. The following options are supported:
bitmap bitmapName
Specifies the name of the bitmap to display. Built-in bitmaps include 'error', 'gray12', 'gray25', 'gray50', 'gray75', 'gray100', 'hourglass', 'info', 'questhead', 'question', 'right_ptr', 'right_ptr_left', 'left_ptr', 'left_ptr_right', 'spider', 'target', 'tbar'.

Specifies the background color of the bitmap. Defaults to the system's default background color.
foreground color
Specifies the foreground color of the bitmap. Defaults to the system's default foreground color.
activebackground color
Specifies the background color when the mouse cursor is over the item. Defaults to the system's default active background color.
activeforeground color
Specifies the foreground color when the mouse cursor is over the item. Defaults to the system's default active foreground color.

$canvas->bbox(tagOrId, ?tagOrId, tagOrId, ...?)
Devuelve una lista con cuatro elementos que dan un cuadro delimitador aproximado para todos los elementos nombrados por los argumentos tagOrId. La lista tiene el formato ``x1 y1 x2 y2'' tal que las áreas dibujadas de todos los elementos nombrados están dentro de la región delimitada por x1 a la izquierda, x2 a la derecha, y1 en la parte superior y y2 en la parte inferior. El valor de retorno puede sobreestimar el cuadro delimitador real en unos pocos píxeles. Si ningún elemento coincide con alguno de los argumentos tagOrId o si los elementos coincidentes tienen cuadros delimitadores vacíos (es decir, no tienen nada que mostrar), se devuelve una cadena vacía.
$canvas->bind(tagOrId?, sequence? ?,callback?)
Este método asocia callback con todos los elementos dados por tagOrId de modo que siempre que ocurra la secuencia de eventos dada por sequence para uno de los elementos, se invocará la devolución de llamada. Este método es similar al método bind excepto que opera en elementos de un lienzo en lugar de widgets completos. Consulte Tk::bind para obtener detalles completos sobre la sintaxis de sequence y las sustituciones realizadas en callback antes de invocarlo. Si se especifican todos los argumentos, se crea una nueva vinculación, que reemplaza cualquier vinculación existente para la misma sequence e tagOrId (si el primer carácter de command es ``+'' entonces command aumenta una vinculación existente en lugar de reemplazarla). En este caso, el valor de retorno es una cadena vacía. Si se omite callback, el método devuelve el callback asociado con tagOrId y sequence (se produce un error si no existe tal vinculación). Si se omiten tanto callback como sequence, el método devuelve una lista de todas las secuencias para las que se han definido vinculaciones para tagOrId.
Los únicos eventos para los que se pueden especificar vinculaciones son los relacionados con el ratón y el teclado (como Enter, Leave, ButtonPress, Motion y KeyPress) o eventos virtuales. El manejo de eventos en lienzos utiliza el elemento actual definido en "IDS Y ETIQUETAS DE ELEMENTOS" arriba. Los eventos Enter y Leave se activan para un elemento cuando se convierte en el elemento actual o deja de serlo; tenga en cuenta que estos eventos son diferentes de los eventos Enter y Leave para las ventanas. Los eventos relacionados con el ratón se dirigen al elemento actual, si lo hay. Los eventos relacionados con el teclado se dirigen al elemento con el foco, si lo hay (consulte el método focus a continuación para obtener más información al respecto). Si se utiliza un evento virtual en una vinculación, esa vinculación solo se puede activar si el evento virtual está definido por un evento subyacente relacionado con el ratón o el teclado.

Es posible que varias vinculaciones coincidan con un evento particular. Esto podría ocurrir, por ejemplo, si una vinculación está asociada con el id del elemento y otra está asociada con una de las etiquetas del elemento. Cuando esto ocurre, se invocan todas las vinculaciones coincidentes. Se invoca primero una vinculación asociada con la etiqueta all, seguida de una vinculación por cada una de las etiquetas del elemento (en orden), seguida de una vinculación asociada con el id del elemento. Si hay varias vinculaciones coincidentes para una sola etiqueta, solo se invoca la vinculación más específica. Un continue en una devolución de llamada termina esa subrutina, y un método break termina esa subrutina y omite cualquier devolución de llamada restante para el evento, al igual que para el método bind.

Si se han creado vinculaciones para una ventana de lienzo utilizando el método CanvasBind, se invocarán además de las vinculaciones creadas para los elementos del lienzo utilizando el método bind. Las vinculaciones para los elementos se invocarán antes que cualquiera de las vinculaciones para la ventana en su conjunto.

Dada una coordenada x de ventana en el lienzo screenx, este método devuelve la coordenada x del lienzo que se muestra en esa ubicación. Si se especifica gridspacing, la coordenada del lienzo se redondea al múltiplo más cercano de las unidades gridspacing.
$canvas->canvasy(screeny, ?gridspacing?)
Dada una coordenada y de ventana en el lienzo screeny, este método devuelve la coordenada y del lienzo que se muestra en esa ubicación. Si se especifica gridspacing, la coordenada del lienzo se redondea al múltiplo más cercano de las unidades gridspacing.
$canvas->coords(tagOrId ?x0,y0 ...?)
Consulta o modifica las coordenadas que definen un elemento. Si no se especifican coordenadas, este método devuelve una lista cuyos elementos son las coordenadas del elemento nombrado por tagOrId. Si se especifican coordenadas, estas reemplazan las coordenadas actuales del elemento nombrado. Si tagOrId se refiere a varios elementos, se utiliza el primero en la lista de visualización.
$canvas->create(type, x, y, ?x, y, ...?, ?option, value, ...?)
Crea un nuevo elemento en $canvas de tipo type. El formato exacto de los argumentos después de type depende de type, pero generalmente consisten en las coordenadas de uno o más puntos, seguidas de especificaciones de cero o más opciones de elemento. Consulte las subsecciones sobre tipos de elementos individuales a continuación para obtener más información sobre la sintaxis de este método. Este método devuelve el id del nuevo elemento.
$canvas->dchars(tagOrId, first, ?last?)
Para cada elemento dado por tagOrId, elimina los caracteres, o coordenadas, en el rango dado por first y last, inclusive. Si algunos de los elementos dados por tagOrId no admiten Elementos de texto, interpreta first y last como índices de un carácter, los elementos de línea y polígono los interpretan como índices de una coordenada (un par x,y) dentro de los elementos como se describe en "ÍNDICES" arriba. Si se omite last, por defecto es first. Este método devuelve una cadena vacía.
$canvas->delete(?tagOrId, tagOrId, ...?)
Elimina cada uno de los elementos dados por cada tagOrId, y devuelve una cadena vacía.
$canvas->dtag(tagOrId, ?tagToDelete?)
Para cada uno de los elementos dados por tagOrId, elimina la etiqueta dada por tagToDelete de la lista de aquellas asociadas con el elemento. Si un elemento no tiene la etiqueta tagToDelete, el elemento no se ve afectado por el método. Si se omite tagToDelete, por defecto es tagOrId. Este método devuelve una cadena vacía.
$canvas->find(searchCommand, ?arg, arg, ...?)
Este método devuelve una lista que consta de todos los elementos que cumplen las restricciones especificadas por searchCommand y los argumentos arg. SearchCommand y los argumentos tienen cualquiera de las formas aceptadas por el método addtag. Los elementos se devuelven en orden de apilamiento, con el elemento más bajo primero.

$canvas->focus(?tagOrId?)
Establece el foco del teclado para el widget del lienzo en el elemento dado por tagOrId. Si tagOrId se refiere a varios elementos, el foco se establece en el primer elemento de la lista de visualización que admite el cursor de inserción. Si tagOrId no se refiere a ningún elemento, o si ninguno de ellos admite el cursor de inserción, el foco no se cambia. Si tagOrId es una cadena vacía, el elemento de foco se restablece para que ningún elemento tenga el foco. Si no se especifica tagOrId, el método devuelve el id del elemento que actualmente tiene el foco, o una cadena vacía si ningún elemento tiene el foco.
Una vez que el foco se ha establecido en un elemento, el elemento mostrará el cursor de inserción y todos los eventos del teclado se dirigirán a ese elemento. El elemento con foco dentro de un lienzo y la ventana con foco en la pantalla (establecida con el método focus) son totalmente independientes: un elemento dado en realidad no tiene el foco de entrada a menos que (a) su lienzo sea la ventana con foco y (b) el elemento sea el elemento con foco dentro del lienzo. En la mayoría de los casos, es aconsejable seguir el método de widget focus con el método CanvasFocus para establecer la ventana de foco en el lienzo (si no estaba allí ya).

Devuelve una lista cuyos elementos son las etiquetas asociadas con el elemento dado por tagOrId. Si tagOrId se refiere a más de un elemento, las etiquetas se devuelven del primer elemento de la lista de visualización. Si tagOrId no se refiere a ningún elemento, o si el elemento no contiene ninguna etiqueta, se devuelve una cadena vacía.

Si algunos o todos los elementos dados por tagOrId no admiten un cursor de inserción, este método no tiene ningún efecto sobre ellos. Consulte "ÍNDICES" arriba para obtener una descripción de los formularios legales para index. Nota: el cursor de inserción solo se muestra en un elemento si ese elemento tiene actualmente el foco del teclado (consulte el método de widget focus, a continuación), pero la posición del cursor se puede establecer incluso cuando el elemento no tiene el foco. Este método devuelve una cadena vacía.

Este método devuelve una cadena decimal que da el índice numérico dentro de tagOrId correspondiente a index. Index da una descripción textual de la posición deseada como se describe en "ÍNDICES" arriba. Los elementos de texto interpretan index como un índice de un carácter, los elementos de línea y polígono lo interpretan como un índice de una coordenada (un par x,y). Se garantiza que el valor de retorno estará entre 0 y el número de caracteres, o coordenadas, dentro del elemento, inclusive. Si tagOrId se refiere a varios elementos, el índice se procesa en el primero de estos elementos que admite operaciones de indexación (en orden de lista de visualización).

Para líneas y polígonos, la cadena debe ser una secuencia de coordenadas válida. Consulte "ÍNDICES" arriba para obtener información sobre las formas permitidas para antesDeEsto. $lienzo->postscript(?opción, valor, opción, valor, ...?)
Genera una representación Postscript para parte o la totalidad del lienzo. Si se especifica la opción -file, entonces el Postscript se escribe en un archivo y se devuelve una cadena vacía; de lo contrario, el Postscript se devuelve como resultado del método. Si el intérprete que posee el lienzo está marcado como seguro, la operación fallará porque los intérpretes seguros no tienen permitido escribir archivos. Si se especifica la opción -channel, el argumento denota el nombre de un canal ya abierto para escritura. El Postscript se escribe en ese canal, y el canal se deja abierto para escritura adicional al final de la operación. El Postscript se crea en formato Postscript Encapsulado utilizando la versión 3.0 de las Convenciones de Estructura de Documentos. Nota: por defecto, el Postscript solo se genera para la información que aparece en la ventana del lienzo en la pantalla. Si el lienzo se crea recientemente, es posible que aún tenga su tamaño inicial de 1x1 píxel, por lo que no aparecerá nada en el Postscript. Para solucionar este problema, invoque el método update para esperar a que la ventana del lienzo alcance su tamaño final, o utilice las opciones -width y -height para especificar el área del lienzo a imprimir. Los pares de argumentos opción-valor proporcionan información adicional para controlar la generación de Postscript. Las siguientes opciones son compatibles:
-colormap => refHash
RefHash debe ser una referencia a una variable hash o un hash anónimo que especifica una asignación de color a utilizar en el Postscript. Cada valor del hash debe consistir en código Postscript para establecer un valor de color particular (p. ej., ``1.0 1.0 0.0 setrgbcolor''). Al generar información de color en el Postscript, Tk verifica si existe una clave en el hash con el mismo nombre que el color. Si es así, Tk utiliza el valor del elemento como método Postscript para establecer el color. Si esta opción no se ha especificado, o si no hay una clave en refHash para un color dado, entonces Tk utiliza las intensidades de rojo, verde y azul del color X.
-colormode => modo
Especifica cómo generar información de color. Modo debe ser color (para salida a todo color), gray (convertir todos los colores a sus equivalentes en escala de grises) o mono (convertir todos los colores a blanco o negro).
-file => nombreArchivo
Especifica el nombre del archivo en el que escribir el Postscript. Si esta opción no se especifica, entonces el Postscript se devuelve como resultado del método en lugar de escribirse en un archivo.
-fontmap => refHash
RefHash debe ser una referencia a una variable hash o un hash anónimo que especifica una asignación de fuentes a utilizar en el Postscript. Cada valor del hash debe consistir en una referencia a una matriz con dos elementos, que son el nombre y el tamaño en puntos de una fuente Postscript. Al generar comandos Postscript para una fuente particular, Tk verifica si refHash contiene un valor con el mismo nombre que la fuente. Si existe dicho elemento, entonces la información de fuente contenida en ese elemento se utiliza en el Postscript. De lo contrario, Tk intenta adivinar qué fuente Postscript utilizar. Las suposiciones de Tk generalmente solo funcionan para fuentes conocidas como Times, Helvetica y Courier, y solo si el nombre de la fuente X no omite guiones hasta el tamaño en puntos. Por ejemplo, -*-Courier-Bold-R-Normal--*-120-* funcionará, pero *Courier-Bold-R-Normal*120* no lo hará; Tk necesita los guiones para analizar el nombre de la fuente).
-height => tamaño
Especifica la altura del área del lienzo a imprimir. Por defecto, es la altura de la ventana del lienzo.
-pageanchor => ancla
Especifica qué punto del área impresa del lienzo debe aparecer sobre el punto de posicionamiento en la página (que se da mediante las opciones -pagex y -pagey). Por ejemplo, -pageanchor=>n significa que el centro superior del área del lienzo que se está imprimiendo (tal como aparece en la ventana del lienzo) debe estar sobre el punto de posicionamiento. Por defecto, es center.
-pageheight => tamaño
Especifica que el Postscript debe escalarse tanto en x como en y para que el área impresa tenga tamaño de altura en la página Postscript. Tamaño consiste en un número de punto flotante seguido de c para centímetros, i para pulgadas, m para milímetros, o p o nada para puntos de impresora (1/72 pulgada). Por defecto, es la altura del área impresa en la pantalla. Si se especifican tanto -pageheight como -pagewidth, entonces se utiliza el factor de escala de -pagewidth (no se implementa escalado no uniforme).
-pagewidth => tamaño
Especifica que el Postscript debe escalarse tanto en x como en y para que el área impresa tenga tamaño de anchura en la página Postscript. Tamaño tiene el mismo formato que para -pageheight. Por defecto, es el ancho del área impresa en la pantalla. Si se especifican tanto -pageheight como -pagewidth, entonces se utiliza el factor de escala de -pagewidth (no se implementa escalado no uniforme).
-pagex => posición
Posición da la coordenada x del punto de posicionamiento en la página Postscript, utilizando cualquiera de las formas permitidas para -pageheight. Se utiliza junto con las opciones -pagey y -pageanchor para determinar dónde aparece el área impresa en la página Postscript. Por defecto, es el centro de la página.
-pagey => posición
Posición da la coordenada y del punto de posicionamiento en la página Postscript, utilizando cualquiera de las formas permitidas para -pageheight. Se utiliza junto con las opciones -pagex y -pageanchor para determinar dónde aparece el área impresa en la página Postscript. Por defecto, es el centro de la página.
-rotate => booleano
Booleano especifica si el área impresa debe girarse 90 grados. En la salida no rotada, el eje x del área impresa se ejecuta a lo largo de la dimensión corta de la página (orientación "vertical"); en la salida rotada, el eje x se ejecuta a lo largo de la dimensión larga de la página (orientación "horizontal"). Por defecto, no rotado.
-width => tamaño

$canvas->addtag(tagOrId, newTag, ?newTag2, ...?)
Associates each of the items given by tagOrId with one or more new tags. The new tags are specified by newTag, newTag2, etc. If tagOrId refers to more than one item then the new tags are added to all of them. If newTag is the empty string then all tags are removed from the items. This method returns an empty string.
$canvas->below(tagOrId, ?targetTagOrId?)
Returns the id of the item immediately below the item specified by tagOrId in the display list. If tagOrId refers to more than one item then the item returned is the one immediately below the topmost of these items. If targetTagOrId is specified, then the search for the item below is restricted to items that are members of the targetTagOrId group. If no item is found below tagOrId, or if tagOrId is not a valid id or tag, an empty string is returned. Note: This method has no effect on window items.
$canvas->bind(tagOrId, ?event, script?)
Creates, modifies, or queries bindings between events and scripts for canvas items. If only tagOrId is specified, it returns a list of all events that are bound to the item(s) specified by tagOrId. If event is specified but script is not, it returns the script associated with that event for the item(s) specified by tagOrId. If both event and script are specified, it associates script with event for the item(s) specified by tagOrId. If script is the empty string, the binding is destroyed. If the item(s) specified by tagOrId do not exist, this command will be ignored. Bindings are inherited. For example, if an event is bound to the canvas widget itself, all items will inherit that binding. If an event is bound to a tag, all items belonging to that tag will inherit the binding. The most specific binding wins. For example, an event bound directly to an item will override the same event bound to a tag that the item belongs to, or bound to the canvas widget itself.
$canvas->canvas(?x, y, width, height?)

If coordinates are specified, the item(s) are modified to have those coordinates. If tagOrId refers to more than one item, the coordinates of all items are modified. The interpretation of coordinates is item-specific: for a line, it's pairs of (x, y) points; for a polygon, it's (x, y) points; for an oval, it's the coordinates of two diagonally opposite corners. For text items, it returns the coordinates of the anchor point. See the item types below for details.

Manipulates the selection in one of several ways, depending on option. The method may take any of the forms described below. OVERVIEW OF ITEM TYPES

The sections below describe the various types of items supported by canvas widgets. Each item type is characterized by two things: first, the form of the create method used to create instances of the type; and second, a set of configuration options for items of that type, which may be used in the create and itemconfigure methods. Most items don't support indexing or selection or the methods related to them, such as index and insert. Where items do support these facilities, it is noted explicitly in the descriptions below. At present, text, line and polygon items provide this support. For lines and polygons the indexing facility is used to manipulate the coordinates of the item.

Los elementos de tipo oval aparecen como regiones circulares u ovales en la pantalla. Cada óvalo puede tener un contorno, un relleno, o ambos. Los óvalos se crean con métodos de la siguiente forma:

$canvas->createOval(x1, y1, x2, y2, ?option, value, option, value, ...?)

Los argumentos x1, y1, x2 e y2 dan las coordenadas de dos esquinas opuestas en diagonal de una región rectangular que encierra al óvalo. ITEMS POLYGONALES

Los items de tipo polygon aparecen como regiones poligonales o curvas rellenas en la pantalla. Los items poligonales soportan operaciones de indexación de coordenadas usando los métodos del canvas: dchars, index, insert. Los polígonos se crean con métodos de la siguiente forma:

BUSCANDO ITEMS

El método find del canvas se usa para encontrar items en el canvas. Se puede llamar de las siguientes maneras:

find(what, x, y?)
Devuelve el ID del item más cercano a las coordenadas (x,y). What puede ser closest.
find(what, x1, y1, x2, y2?)
Devuelve una lista de IDs de items que se encuentran dentro o se solapan con el rectángulo especificado por (x1,y1) y (x2,y2). What puede ser overlapping.
find(what, tagList?)
Devuelve una lista de IDs de items que tienen las etiquetas especificadas en tagList. What puede ser withtag.
find(what)
Devuelve una lista de IDs de todos los items en el canvas. What debe ser all.

El método find devuelve una lista de IDs de items. Si no se encuentran items, devuelve una lista vacía.

ELIMINANDO ITEMS

El método delete del canvas se usa para eliminar items del canvas. Se puede llamar de las siguientes maneras:

delete(itemList)
Elimina los items especificados en itemList del canvas. ItemList puede ser una lista de IDs de items o una lista de etiquetas. Si se usa una lista de etiquetas, se eliminarán todos los items que tengan alguna de esas etiquetas.

COORDENADAS

Las coordenadas se especifican como pares de números (x,y). La esquina superior izquierda del canvas está en la posición (0,0). Los valores de x aumentan hacia la derecha y los valores de y aumentan hacia abajo.

Las coordenadas pueden ser números enteros o flotantes. También pueden ser expresiones que se evalúen a un número. Las unidades son píxeles por defecto, pero pueden ser cambiadas usando la opción -units del widget canvas.

Las coordenadas pueden ser relativas a otros items en el canvas, usando la notación @id.corner, donde id es el ID del item y corner es una de las esquinas (n, ne, e, se, s, sw, w, nw, center).

Por ejemplo, para dibujar un rectángulo cuya esquina superior izquierda esté en la esquina inferior derecha de un item con ID 5, usaría:

-x1 => "@5.se", -y1 => "@5.se"

ETIQUETAS

Las etiquetas son cadenas de texto que se pueden asociar a items del canvas. Permiten agrupar items y manipularlos como un conjunto. Cada item puede tener una o más etiquetas.

Las etiquetas se especifican usando la opción -tags al crear o configurar un item.

 $canvas->itemconfigure($id, -tags => ['etiqueta1', 'etiqueta2'])

Las etiquetas se pueden usar para encontrar o eliminar items.

CONFIGURACIÓN DE ITEMS

Todos los items del canvas pueden ser modificados después de su creación usando el método itemconfigure.

$canvas->itemconfigure($id, option => value, ...)

Donde id es el ID del item a modificar, y option/value son los pares de opción/valor que se desean cambiar.

Por ejemplo, para cambiar el color de relleno de un item con ID 3:

$canvas->itemconfigure(3, -fill => 'blue')

DESPLAZAMIENTO

El canvas puede ser desplazado usando los widgets Scrollbar. Para hacer esto, asocie el canvas con dos scrollbars, una horizontal y otra vertical.

my $sb_x = $parent->Scrollbar(-orient => 'horizontal');
my $sb_y = $parent->Scrollbar(-orient => 'vertical');
my $canvas = $parent->Canvas(-xscrollcommand => [sub{$sb_x->set(@_)}],
                             -yscrollcommand => [sub{$sb_y->set(@_)}]);
$sb_x->{-command} = [sub{$canvas->xview(@_)}];
$sb_y->{-command} = [sub{$canvas->yview(@_)}];

WINDOW ITEMS

This item type is used to embed arbitrary Tk widgets within a canvas. The widget is specified by the -window option. The widget must be a descendant of the canvas, or a descendant of the canvas’s parent. It cannot be a top-level window. The window item will always obscure any graphics items that overlap it. It is not possible to draw graphics on top of window items. The window item will be displayed in the canvas in the same way as any other item type. The widget may be moved, deleted, or modified using canvas commands. The widget will always be displayed at the same coordinate position relative to the canvas.

-height => pixels
Specifies the height to assign to the item’s window. Pixels may have any of the forms described in the "COORDINATES" section above. If this option isn’t specified, or if it is specified as an empty string, then the window is given whatever height it requests internally.
-state => state
Modifies the state of the window item where state may be set to one of: normal, disabled, or hidden.
-tags => tagList
Specifies a set of tags to apply to the item. TagList consists of a list of tag names, which replace any existing tags for the item. TagList may be an empty list.
-updatecommand => command
Specifies a callback that is to be executed every time the window item is updated on the screen.
-width => pixels
Specifies the width to assign to the item’s window. Pixels may have any of the forms described in the "COORDINATES" section above. If this option isn’t specified, or if it is specified as an empty string, then the window is given whatever width it requests internally.
-window => $widget
Specifies the window to associate with this item. The window specified by $widget must either be a child of the canvas widget or a child of some ancestor of the canvas widget. PathName may not refer to a top-level window.

Note: due to restrictions in the ways that windows are managed, it is not possible to draw other graphical items (such as lines and images) on top of window items. A window item always obscures any graphics that overlap it, regardless of their order in the display list.
