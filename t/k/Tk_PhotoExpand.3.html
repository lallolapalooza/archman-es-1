Tk_FindPhoto(3) Tk Library Procedures Tk_FindPhoto(3)

NOMBRE

Tk_FindPhoto, Tk_PhotoPutBlock, Tk_PhotoPutZoomedBlock, Tk_PhotoGetImage, Tk_PhotoBlank, Tk_PhotoExpand, Tk_PhotoGetSize, Tk_PhotoSetSize - manipular los datos de imagen almacenados en una imagen foto.

SINOPSIS

#include <tk.h>

Tk_PhotoHandle
Tk_FindPhoto(interp, imageName)

int
Tk_PhotoPutBlock(interp, handle, blockPtr, x, y, width, height,compRule)

int
Tk_PhotoPutZoomedBlock(interp, handle, blockPtr, x, y, width, height,zoomX, zoomY, subsampleX, subsampleY, compRule)

int
Tk_PhotoGetImage(handle, blockPtr)

void
Tk_PhotoBlank(handle)

int
Tk_PhotoExpand(interp, handle, width, height)

void
Tk_PhotoGetSize(handle, widthPtr, heightPtr)

int
Tk_PhotoSetSize(interp. handle, width, height)

ARGUMENTOS

Tcl_Interp *interp (in)
Intérprete en el cual se creó la imagen y en el cual se deben reportar los errores.
const char *imageName (in)
Nombre de la imagen foto.
Tk_PhotoHandle handle (in)
Identificador opaco que identifica la imagen foto a la que se va a afectar.
Tk_PhotoImageBlock *blockPtr (in)
Especifica la dirección y el diseño de almacenamiento de los datos de la imagen.
int x (in)
Especifica la coordenada X donde se colocará la esquina superior izquierda del bloque dentro de la imagen.
int y (in)
Especifica la coordenada Y donde se colocará la esquina superior izquierda del bloque dentro de la imagen.
int width (in)
Especifica el ancho del área de la imagen a afectar (para Tk_PhotoPutBlock) o el ancho deseado de la imagen (para Tk_PhotoExpand y Tk_PhotoSetSize).
int compRule (in)
Especifica la regla de composición utilizada al combinar píxeles transparentes en un bloque de datos con una imagen foto. Debe ser TK_PHOTO_COMPOSITE_OVERLAY (que coloca el bloque de datos sobre la imagen foto existente, con el contenido anterior visible en los bits transparentes) o TK_PHOTO_COMPOSITE_SET (que descarta el contenido existente de la imagen foto en el rectángulo cubierto por el bloque de datos).
int height (in)
Especifica la altura del área de la imagen a afectar (para Tk_PhotoPutBlock) o la altura deseada de la imagen (para Tk_PhotoExpand y Tk_PhotoSetSize).
int *widthPtr (out)
Puntero a la ubicación en la que se almacenará el ancho de la imagen.
int *heightPtr (out)
Puntero a la ubicación en la que se almacenará la altura de la imagen.
int subsampleX (in)
Especifica el factor de submuestreo en la dirección X para los datos de la imagen de entrada.
int subsampleY (in)
Especifica el factor de submuestreo en la dirección Y para los datos de la imagen de entrada.
int zoomX (in)
Especifica el factor de zoom que se aplicará en la dirección X a los píxeles que se escriben en la imagen foto.
int zoomY (in)
Especifica el factor de zoom que se aplicará en la dirección Y a los píxeles que se escriben en la imagen foto.

DESCRIPCIÓN

Tk_FindPhoto devuelve un identificador opaco que se utiliza para identificar una imagen foto específica a los demás procedimientos. El parámetro es el nombre de la imagen, es decir, el nombre especificado al comando image create photo, o asignado por ese comando si no se especificó ningún nombre. Si imageName no existe o no es una imagen foto, Tk_FindPhoto devuelve NULL.

Tk_PhotoPutBlock se utiliza para suministrar bloques de datos de imagen para ser mostrados. La llamada afecta a un área de la imagen de tamaño width x height píxeles, con su esquina superior izquierda en las coordenadas (x,y). Todos los valores de width, height, x e y deben ser no negativos. Si parte de esta área queda fuera de los límites actuales de la imagen, la imagen se expandirá para incluir el área, a menos que el usuario haya especificado un tamaño de imagen explícito con las opciones de configuración del widget -width y/o -height (ver photo(n)); en ese caso, el área se recortará silenciosamente a los límites de la imagen.

El parámetro block es un puntero a una estructura Tk_PhotoImageBlock, definida de la siguiente manera:

typedef struct {
    unsigned char *pixelPtr;
    int width;
    int height;
    int pitch;
    int pixelSize;
    int offset[4];
} Tk_PhotoImageBlock;
El campo pixelPtr apunta al primer píxel, es decir, al píxel superior izquierdo del bloque. Los campos width y height especifican las dimensiones del bloque de píxeles. El campo pixelSize especifica la diferencia de dirección entre dos píxeles horizontalmente adyacentes. Debe ser 4 para datos de imagen RGB y 2 para datos de imagen en escala de grises. Son posibles otros valores, si los desplazamientos en la matriz offset se ajustan en consecuencia (por ejemplo, para datos rojos, verdes y azules almacenados en diferentes planos). Sin embargo, se desaconseja fuertemente utilizar dicho diseño. Debido a un error, puede que no funcione correctamente si se proporciona un canal alfa. (ver la sección ERRORES más abajo). El campo pitch especifica la diferencia de dirección entre dos píxeles verticalmente adyacentes. La matriz offset contiene los desplazamientos desde la dirección de un píxel hasta las direcciones de los bytes que contienen los componentes rojo, verde, azul y alfa (transparencia). Si los desplazamientos de rojo, verde y azul son iguales, la imagen se interpreta como escala de grises. Si difieren, se asumen datos RGB. Normalmente los desplazamientos serán 0, 1, 2, 3 para datos RGB y 0, 0, 0, 1 para escala de grises. Es posible proporcionar datos de imagen sin canal alfa estableciendo el desplazamiento alfa a un valor negativo y ajustando el campo pixelSize en consecuencia. Sin embargo, este uso está desaconsejado (ver la sección ERRORES más abajo).

El parámetro compRule de Tk_PhotoPutBlock especifica una regla de composición que indica qué hacer con los píxeles transparentes. El valor TK_PHOTO_COMPOSITE_OVERLAY indica que el contenido anterior de la imagen foto debe mostrarse, y el valor TK_PHOTO_COMPOSITE_SET indica que el contenido anterior de la imagen foto debe ignorarse por completo, y los valores del bloque deben copiarse directamente. El comportamiento en Tk8.3 y anteriores era equivalente a tener TK_PHOTO_COMPOSITE_OVERLAY como regla de composición.

Los valores dados para los parámetros width y height a Tk_PhotoPutBlock no tienen por qué corresponder a los valores especificados en block. Si son más pequeños, Tk_PhotoPutBlock extrae un sub-bloque de los datos de imagen suministrados. Si son más grandes, los datos proporcionados se replican (de forma en mosaico) para llenar el área especificada. Estas reglas operan independientemente en las direcciones horizontal y vertical.

Tk_PhotoPutBlock normalmente devuelve TCL_OK, aunque si no puede asignar suficiente memoria para almacenar la imagen resultante, se devuelve TCL_ERROR y, si el argumento interp no es NULL, se coloca un mensaje de error en el resultado del intérprete.

Tk_PhotoPutZoomedBlock funciona como Tk_PhotoPutBlock excepto que la imagen puede reducirse o ampliarse para su visualización. Los parámetros subsampleX y subsampleY permiten reducir el tamaño de la imagen mediante submuestreo. Tk_PhotoPutZoomedBlock utilizará solo los píxeles de la imagen de entrada cuyas coordenadas X sean múltiplos de subsampleX, y cuyas coordenadas Y sean múltiplos de subsampleY. Por ejemplo, una imagen de 512x512 píxeles se puede reducir a 256x256 estableciendo subsampleX y subsampleY a 2.

Los parámetros zoomX y zoomY permiten ampliar la imagen mediante la replicación de píxeles. Cada píxel de la imagen de entrada (posiblemente submuestreada) se escribirá en un bloque de zoomX píxeles de ancho y zoomY píxeles de alto de la imagen mostrada. El submuestreo y el zoom se pueden utilizar juntos para efectos especiales.

Tk_PhotoGetImage se puede utilizar para recuperar datos de imagen de una imagen foto. Tk_PhotoGetImage rellena la estructura apuntada por el parámetro blockPtr con valores que describen la dirección y el diseño de los datos de imagen que la imagen foto ha almacenado internamente. Los valores son válidos hasta que la imagen se destruye o se cambia su tamaño.

Es posible modificar una imagen escribiendo directamente en los datos a los que apunta el campo pixelPtr. Sin embargo, el tamaño de la imagen no se puede cambiar de esta manera. Además, los cambios realizados al escribir directamente en pixelPtr no serán visibles de inmediato, sino solo después de una llamada a Tk_ImageChanged o después de un evento que haga que los widgets interesados se redibujen. NAME

Tk_PhotoPutBlock, Tk_PhotoPutZoomedBlock, Tk_PhotoGetImage, Tk_PhotoBlank, Tk_PhotoExpand, Tk_PhotoSetSize, Tk_PhotoGetSize - manipulate photo images

int
Tk_PhotoPutZoomedBlock(
        Tcl_Interp *interp,
        tk_photo_image_block_t *blockPtr,
        int x, int y, int width, int height,
        int zoomNum, int zoomDen,
        int subsampleTo, int subsampleFrom);

int
Tk_PhotoGetImage(
        Tcl_Interp *interp,
        const char *name);

void
Tk_PhotoBlank(
        tk_photo_image_block_t *blockPtr);

int
Tk_PhotoExpand(
        Tcl_Interp *interp,
        tk_photo_image_block_t *blockPtr,
        int width, int height);

int
Tk_PhotoSetSize(
        Tcl_Interp *interp,
        tk_photo_image_block_t *blockPtr,
        int width, int height);

void
Tk_PhotoGetSize(
        tk_photo_image_block_t *blockPtr,
        int *widthPtr, int *heightPtr);

ARGUMENTS

interp
Interpreter to use for error reporting. If NULL, no error is reported.
name
Name of the photo image.
blockPtr
Pointer to the tk_photo_image_block_t structure containing image data.
x, y
Top-left corner of the area in the photo image to write to.
width, height
Dimensions of the area in the photo image to write to. These dimensions should match the dimensions of the data in blockPtr.
subsampleTo, subsampleFrom
These arguments are used to implement subsampling. If subsampleTo is less than subsampleFrom, the image data is subsampled so that for every subsampleFrom pixels in the input data, only subsampleTo pixels are written to the photo image. The x and y coordinates should refer to the coordinates in the photo image, and the width and height should refer to the dimensions of the subsampled data.
zoomNum, zoomDen
These arguments are used to implement zooming. If zoomNum is different from zoomDen, the image data is scaled. The x, y, width, and height arguments refer to the coordinates and dimensions in the photo image, and the data in blockPtr is assumed to be scaled by the factor zoomDen/zoomNum.
widthPtr, heightPtr
Pointers to integers where the width and height of the image will be stored.

DESCRIPTION

These procedures manipulate Tk photo images, which are a type of Tk image that can be modified dynamically. Photo images are created using the image create photo command in Tcl. The procedures described here allow C code to modify the contents of a photo image.

Tk_PhotoCreate creates a new photo image named name in the interpreter interp. If a photo image with this name already exists, it is destroyed and replaced with the new one. It returns a pointer to the internal representation of the photo image, which should be passed to other photo image procedures. The caller is responsible for destroying the photo image when it is no longer needed by calling Tk_PhotoDestroy.

Tk_PhotoDestroy destroys the given photo image, freeing associated resources.

Tk_PhotoPutBlock writes a block of pixel data from blockPtr into the photo image. The x, y, width, and height arguments specify the destination region in the photo image and the dimensions of the data in blockPtr. The data in blockPtr is assumed to be in the format described in the Tk_PhotoImageBlock structure documentation. If the destination region is outside the current bounds of the photo image, the photo image is grown to accommodate it. If the data in blockPtr is not opaque, the new pixels are merged with the existing pixels in the destination region using alpha blending. Tk_PhotoPutBlock returns TCL_OK if the data was written successfully, or TCL_ERROR if an error occurred (e.g., insufficient memory).

Tk_PhotoPutZoomedBlock is similar to Tk_PhotoPutBlock, but it also supports zooming. The zoomNum and zoomDen arguments specify the scaling factor to be applied to the data. For example, to scale the data by a factor of 2, you would use zoomNum=2 and zoomDen=1. To scale it down by a factor of 2, you would use zoomNum=1 and zoomDen=2. The coordinates and dimensions specified by x, y, width, and height refer to the destination region in the photo image, while the data in blockPtr is assumed to be scaled by the factor zoomDen/zoomNum. This means that if zoomNum=2 and zoomDen=1, the data in blockPtr is twice as large as the destination region.

Tk_PhotoGetImage is a compatibility function that attempts to retrieve the named photo image and make it available for display. In older versions of Tk, this function was used to load image data into a photo image. In current versions, it's generally not needed, as image data is typically written directly to a photo image using Tk_PhotoPutBlock or Tk_PhotoPutZoomedBlock.

Tk_PhotoBlank blanks the entire area of the photo image. Blank areas of a photo image are transparent.

Tk_PhotoExpand requests that the widget's image be expanded to be at least width x height pixels in size. The width and/or height are unchanged if the user has specified an explicit image width or height with the -width and/or -height configuration options, respectively. If the image data are being supplied in many small blocks, it is more efficient to use Tk_PhotoExpand or Tk_PhotoSetSize at the beginning rather than allowing the image to expand in many small increments as image blocks are supplied.

Tk_PhotoExpand normally returns TCL_OK, though if it cannot allocate sufficient memory to hold the resulting image, TCL_ERROR is returned instead and, if the interp argument is non-NULL, an error message is placed in the interpreter's result.

Tk_PhotoSetSize specifies the size of the image, as if the user had specified the given width and height values to the -width and -height configuration options. A value of zero for width or height does not change the image's width or height, but allows the width or height to be changed by subsequent calls to Tk_PhotoPutBlock, Tk_PhotoPutZoomedBlock or Tk_PhotoExpand.

Tk_PhotoSetSize normally returns TCL_OK, though if it cannot allocate sufficient memory to hold the resulting image, TCL_ERROR is returned instead and, if the interp argument is non-NULL, an error message is placed in the interpreter's result.

Tk_PhotoGetSize returns the dimensions of the image in *widthPtr and *heightPtr.

PORTABILITY

In Tk 8.3 and earlier, Tk_PhotoPutBlock and Tk_PhotoPutZoomedBlock had different signatures. If you want to compile code that uses the old interface against 8.4 without updating your code, compile it with the flag -DUSE_COMPOSITELESS_PHOTO_PUT_BLOCK. Code linked using Stubs against older versions of Tk will continue to work.

In Tk 8.4, Tk_PhotoPutBlock, Tk_PhotoPutZoomedBlock, Tk_PhotoExpand and Tk_PhotoSetSize did not take an interp argument or return any result code. If insufficient memory was available for an image, Tk would panic. This behaviour is still supported if you compile your extension with the additional flag -DUSE_PANIC_ON_PHOTO_ALLOC_FAILURE. Code linked using Stubs against older versions of Tk will continue to work.

BUGS

The Tk_PhotoImageBlock structure used to provide image data to Tk_PhotoPutBlock promises great flexibility in the layout of the data (e.g. separate planes for the red, green, blue and alpha channels). Unfortunately, the implementation fails to hold this promise. The problem is that the pixelSize field is (incorrectly) used to determine whether the image has an alpha channel. Currently, if the offset for the alpha channel is greater than or equal to pixelSize, tk_PhotoPutblock assumes no alpha data is present and makes the image fully opaque. This means that for layouts where the channels are separate (or any other exotic layout where pixelSize has to be smaller than the alpha offset), the alpha channel will not be read correctly. In order to be on the safe side if this issue will be corrected in a future release, it is strongly recommended you always provide alpha data - even if the image has no transparency - and only use the "standard" layout with a pixelSize of 2 for grayscale and 4 for RGB data with offsets of 0, 0, 0, 1 or 0, 1, 2, 3 respectively.
