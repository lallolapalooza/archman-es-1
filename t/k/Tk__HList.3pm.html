NOMBRE

Tk::HList - Crea y manipula widgets de lista jerárquica Tix

SINOPSIS

$hlist = $padre->HList(?opciones?);

OPCIONES ESTÁNDAR

-background -borderwidth -cursor -exportselection -foreground -font -height -highlightcolor -highlightthickness -relief -selectbackground -selectforeground -xscrollcommand -yscrollcommand -width

Consulte Tk::options para obtener detalles sobre las opciones estándar.

DESCRIPCIÓN

El método HList crea una nueva ventana (proporcionada por el argumento $widget) y la convierte en un widget HList. Opciones adicionales, descritas anteriormente, pueden especificarse en la línea de comandos o en la base de datos de opciones para configurar aspectos del widget HList, como su cursor y relieve.

El widget HList se puede utilizar para mostrar cualquier dato que tenga una estructura jerárquica, por ejemplo, árboles de directorios del sistema de archivos. Las entradas de la lista se indentan y se conectan mediante líneas de ramas según su lugar en la jerarquía.

Cada entrada de la lista se identifica mediante un entryPath. El entryPath es una secuencia de nombres de entrada separados por el carácter separador (especificado por la opción -separator). Un nombre de entrada puede ser cualquier cadena que no contenga el carácter separador, o puede ser una cadena que contenga solo un carácter separador.

Por ejemplo, cuando se usa "." como carácter separador, "one.two.three" es el entryPath de una entrada de lista cuyo padre es "one.two", cuyo padre es "one", que es una entrada de nivel superior (no tiene padres).

Otro ejemplo: ".two.three" es el entryPath de una entrada de lista cuyo padre es ".two", cuyo padre es ".", que es una entrada de nivel superior.

ELEMENTOS DE VISUALIZACIÓN

Cada entrada de la lista en un widget HList está asociada con un elemento de visualización. El elemento de visualización determina qué información visual se debe mostrar para esta entrada de lista. Consulte Tk::DItem para obtener una lista de todos los elementos de visualización. Cuando se crea una entrada de lista mediante los métodos de widget itemCreate, add o addchild, el tipo de su elemento de visualización se determina mediante la opción -itemtype pasada a estos métodos. Si se omite -itemtype, entonces, por defecto, se utiliza el tipo especificado por la opción -itemtype de este widget HList.

MÉTODOS DEL WIDGET

El método HList crea un objeto de widget. Este objeto admite los métodos configure y cget descritos en Tk::options, que se pueden utilizar para consultar y modificar las opciones descritas anteriormente. El widget también hereda todos los métodos proporcionados por la clase genérica Tk::Widget.

Los siguientes métodos adicionales están disponibles para los widgets HList:

$hlist->add($entryPath ?,option=>value, ...?)
Crea una nueva entrada de lista con el nombre de ruta $entryPath. Una entrada de lista debe crearse después de que se cree su padre (a menos que esta entrada sea una entrada de nivel superior, que no tiene padre). Consulte también "BUGS" a continuación. Este método devuelve el entryPath de la entrada de lista recién creada. Las siguientes opciones de configuración se pueden proporcionar para configurar la entrada de lista:
-at => position
Inserta la nueva lista en la posición dada por position. position debe ser un entero válido. La posición 0 indica la primera posición, 1 indica la segunda posición, y así sucesivamente.
-after => afterWhich
Inserta la nueva entrada de lista después de la entrada identificada por afterWhich. afterWhich debe ser una entrada de lista válida y debe tener el mismo padre que la nueva entrada de lista.
-before => beforeWhich
Inserta la nueva entrada de lista antes de la entrada identificada por beforeWhich. beforeWhich debe ser una entrada de lista válida y debe tener el mismo padre que la nueva entrada de lista.
-data => string
Especifica una cadena para asociarla con esta entrada de lista. Esta cadena se puede consultar mediante el método info. El programador de la aplicación puede utilizar la opción -data para asociar la entrada de lista con los datos que representa.
-itemtype => type
Especifica el tipo de elemento de visualización que se mostrará para la nueva entrada de lista. type debe ser un tipo de elemento de visualización válido. Actualmente, los tipos de elementos de visualización disponibles son imagetext, text y $widget. Si no se especifica esta opción, por defecto se utiliza el tipo especificado por la opción -itemtype de este widget HList.
-state => state
Especifica si esta entrada puede ser seleccionada o invocada por el usuario. Debe ser normal o disabled.

El método add acepta opciones de configuración adicionales para configurar el elemento de visualización asociado con esta entrada de lista. El conjunto de opciones de configuración adicionales depende del tipo de elemento de visualización dado por la opción -itemtype. Consulte Tk::DItem para obtener una lista de las opciones de configuración para cada uno de los tipos de elementos de visualización.

$hlist->addchild($parentPath, ?option, value, ..., ?)
Agrega una nueva entrada hija a la lista de hijos de la entrada de lista identificada por $parentPath. O, si $parentPath se establece como cadena vacía, crea una nueva entrada de nivel superior. El nombre de la nueva entrada de lista será un nombre único generado automáticamente por el widget HList. Normalmente, si $parentPath es foo, entonces el entryPath de la nueva entrada será foo.0, foo.1, etc. Este método devuelve el entryPath de la entrada de lista recién creada. option puede ser cualquier opción para el método add. Consulte también "BUGS" a continuación.
$hlist->anchorSet($entryPath)
Establece el ancla en la entrada de lista identificada por $entryPath. El ancla es el extremo de la selección que se fija mientras el usuario arrastra una selección con el ratón.
$hlist->anchorClear
Elimina el ancla, si la hay, de este widget HList. Esto solo elimina los resaltados circundantes de la entrada ancla y no afecta su estado de selección.
$hlist->columnWidth($col?, -char?, ?width?)
Consulta o establece el ancho de la columna $col en el widget HList. El valor de $col tiene índice cero: 0 representa la primera columna, 1 representa la segunda, y así sucesivamente. Si no se proporcionan más parámetros, devuelve el ancho actual de esta columna (en número de píxeles). Se pueden proporcionar parámetros adicionales para establecer el ancho de esta columna:
$hlist->columnWidth($col, '')
Una cadena vacía indica que el ancho de la columna debe ser lo suficientemente amplio como para mostrar el elemento más ancho de esta columna. En este caso, el ancho de esta columna puede cambiar como resultado de que los elementos de esta columna cambien su tamaño.
$hlist->columnWidth($col, width)
width debe estar en un formato aceptado por Tk_GetPixels.
$hlist->columnWidth($col, -char, nChars)
El ancho se establece para ser el ancho promedio ocupado por nChars número de caracteres de la fuente especificada por la opción -font de este widget HList.
$hlist->delete(option, $entryPath)
Elimina una o más entradas de lista. option puede ser una de las siguientes:
all
Elimina todas las entradas del HList. En este caso, no es necesario especificar $entryPath.
entry
Elimina la entrada especificada por $entryPath y todos sus descendientes, si los hay.
offsprings
Elimina todos los descendientes, si los hay, de la entrada especificada por $entryPath. Sin embargo, $entryPath en sí no se elimina.
siblings
Elimina todas las entradas de lista que comparten el mismo padre que la entrada especificada por $entryPath. Sin embargo, $entryPath en sí no se elimina.
$hlist->dragsiteSet($entryPath)
Establece el dragsite en la entrada de lista identificada por $entryPath. El dragsite se utiliza para indicar la fuente de una acción de arrastrar y soltar. Actualmente, la funcionalidad de arrastrar y soltar aún no se ha implementado en Tix.
$hlist->dragsiteClear
Elimina el dragsite, si lo hay, de este widget HList. Esto solo elimina los resaltados circundantes de la entrada dragsite y no afecta su estado de selección.
$hlist->dropsiteSet($entryPath)
Establece el sitio de destino en la entrada de la lista identificada por $entryPath. El sitio de destino se utiliza para indicar el objetivo de una acción de arrastrar y soltar. Actualmente, la funcionalidad de arrastrar y soltar no se ha implementado todavía en Tix.
$hlist->dropsiteClear
Elimina el sitio de destino, si existe, del widget HList. Esto solo elimina los resaltados circundantes de la entrada del sitio de destino y no afecta a su estado de selección.
$hlist->entrycget($entryPath, option)
Devuelve el valor actual de la opción de configuración dada por option para la entrada identificada por $entryPath. Option puede tener cualquiera de los valores aceptados por el método add.
$hlist->entryconfigure($entryPath ?,option?, ?value=>option, ...?)
Consulta o modifica las opciones de configuración de la entrada de lista identificada por $entryPath. Si no se especifica option, devuelve una lista que describe todas las opciones disponibles para $entryPath (ver Tk::options para obtener información sobre el formato de esta lista). Si se especifica option sin value, entonces el método devuelve una lista que describe la opción nombrada (esta lista será idéntica a la sublista correspondiente del valor devuelto si no se especifica option). Si se especifican uno o más pares option-value, entonces el método modifica la(s) opción(es) dada(s) para tener el(los) valor(es) dado(s); en este caso, el método devuelve una cadena vacía. Option puede tener cualquiera de los valores aceptados por el método add o addchild. El conjunto exacto de opciones depende del valor de la opción -itemtype pasada al método add o addchild cuando se creó esta entrada de lista.
$hlist->header(option, $col ?,args, ...?)
Manipula los elementos de encabezado de este widget HList. Si la opción -header de este widget HList está establecida en true, entonces se muestra un elemento de encabezado en la parte superior de cada columna. El argumento $col para este método debe ser un entero válido. 0 indica la primera columna, 1 la segunda columna, ... y así sucesivamente. Este método admite las siguientes opciones:
$hlist->header(cget, $col, option)
Si la columna $col-ésima tiene un elemento de visualización de encabezado, devuelve el valor de la option especificada del elemento de encabezado. Si el encabezado no existe, devuelve un error.
$hlist->header(configure, $col, ?option?, ?value, option, value, ...?)
Consulta o modifica las opciones de configuración del elemento de visualización de encabezado de la columna $col-ésima. El elemento de encabezado debe existir, o se producirá un error. Si no se especifica option, devuelve una lista que describe todas las opciones disponibles para el elemento de visualización de encabezado (ver Tk::options para obtener información sobre el formato de esta lista). Si se especifica option sin value, entonces el método devuelve una lista que describe la opción nombrada (esta lista será idéntica a la sublista correspondiente del valor devuelto si no se especifica option). Si se especifican uno o más pares option-value, entonces el método modifica la(s) opción(es) dada(s) para tener el(los) valor(es) dado(s); en este caso, el método devuelve una cadena vacía. Option puede tener cualquiera de los valores aceptados por el método header create. El conjunto exacto de opciones depende del valor de la opción -itemtype pasada al método header create cuando se creó este elemento de visualización.
$hlist->header(create, $col, ?-itemtype type? ?option value ...?)
Crea un nuevo elemento de visualización como encabezado para la columna $col-ésima. Ver también "BUGS" a continuación. Si ya existe un elemento de visualización de encabezado para esta columna, será reemplazado por el nuevo elemento. Se puede utilizar un parámetro opcional -itemtype para especificar qué tipo de elemento de visualización se debe crear. Si no se proporciona -itemtype, entonces se utiliza por defecto el tipo especificado por la opción -itemtype de este widget HList. Se pueden pasar parámetros adicionales, en pares option-value, para configurar la apariencia del elemento de visualización. Cada par option-value debe ser una opción válida para este tipo de elemento de visualización o una de las siguientes:
-borderwidth => color
Especifica el ancho del borde de este elemento de encabezado.
-headerbackground => color
Especifica el color de fondo de este elemento de encabezado.
-relief => type
Especifica el tipo de relieve del borde de este elemento de encabezado.
$hlist->header(delete, $col)
Elimina el elemento de visualización de encabezado para la columna $col-ésima.
$hlist->header(exists, $col)
Devuelve verdadero si existe un elemento de visualización de encabezado para la columna $col-ésima; de lo contrario, devuelve falso.
$hlist->header(size, $col)
Si existe un elemento de visualización de encabezado para la columna $col-ésima, devuelve su tamaño en píxeles en una lista de dos elementos (width, height); devuelve un error si el elemento de visualización de encabezado no existe.
$hlist->hide(option ?,$entryPath?)
Hace que algunas entradas sean invisibles sin eliminarlas. Option puede ser una de las siguientes:
entry
Oculta la entrada de lista identificada por $entryPath.

Actualmente solo se admite la opción entry. Se añadirán otras opciones en la próxima versión.

$hlist->indicator(option, $entryPath, ?args, ...?)
Manipula el indicador en las entradas de la lista. Un indicador suele ser un pequeño elemento de visualización (como una imagen) que se muestra a la izquierda de una entrada para indicar el estado de la entrada. Por ejemplo, puede utilizarse para indicar si un directorio está abierto o cerrado. Option puede ser una de las siguientes:
$hlist->indicator(cget, $entryPath, option)
Si la entrada de lista dada por $entryPath tiene un indicador, devuelve el valor de la option especificada del indicador. Si el indicador no existe, devuelve un error.
$hlist->indicator(configure, $entryPath, ?option?, ?value, option, value, ...?)
Consulta o modifica las opciones de configuración del elemento de visualización del indicador de la entrada especificada por $entryPath. El elemento indicador debe existir, o se producirá un error. Si no se especifica option, devuelve una lista que describe todas las opciones disponibles para el elemento de visualización del indicador (ver Tk::options para obtener información sobre el formato de esta lista). Si se especifica option sin value, entonces el método devuelve una lista que describe la opción nombrada (esta lista será idéntica a la sublista correspondiente del valor devuelto si no se especifica option). Si se especifican uno o más pares option-value, entonces el método modifica la(s) opción(es) dada(s) para tener el(los) valor(es) dado(s); en este caso, el método devuelve una cadena vacía. Option puede tener cualquiera de los valores aceptados por el método indicator create. El conjunto exacto de opciones depende del valor de la opción -itemtype pasada al método indicator create cuando se creó este elemento de visualización.
$hlist->indicator(create, $entryPath, ?, -itemtype type? ?option value ...?)
Crea un nuevo elemento de visualización como indicador para la entrada especificada por $entryPath. Si ya existe un elemento de visualización de indicador para esta entrada, será reemplazado por el nuevo elemento. Se puede utilizar un parámetro opcional -itemtype para especificar qué tipo de elemento de visualización se debe crear. Si no se proporciona -itemtype, entonces se utiliza por defecto el tipo especificado por la opción -itemtype de este widget HList. Se pueden pasar parámetros adicionales, en pares option-value, para configurar la apariencia del elemento de visualización. Cada par option-value debe ser una opción válida para este tipo de elemento de visualización.
$hlist->indicator(delete, $entryPath)
Elimina el elemento de visualización de indicador para la entrada dada por $entryPath.
$hlist->indicator(exists, $entryPath)
Devuelve verdadero si existe un elemento de visualización de indicador para la entrada dada por $entryPath; de lo contrario, devuelve falso.
$hlist->indicator(size, $entryPath)
Si existe un elemento de visualización de indicador para la entrada dada por $entryPath, devuelve su tamaño en una lista de dos elementos de la forma {width height}; devuelve un error si el elemento de visualización de indicador no existe.
$hlist->info(option, arg, ...)
Consulta información sobre el widget HList. option puede ser una de las siguientes:
$hlist->info(anchor)
Devuelve la ruta de entrada (entryPath) del ancla actual, si la hay, del widget HList. Si el ancla no está establecida, devuelve una cadena vacía.
$hlist->infoBbox($entryPath)
Devuelve una lista de cuatro números que describen el cuadro delimitador visible de la entrada dada $entryPath. Los dos primeros elementos de la lista dan las coordenadas x e y de la esquina superior izquierda
Tk::HList(3pm) - PerlTk Manual

NAME

Tk::HList - display a hierarchical listbox

SYNOPSIS

use Tk::HList;

my $hlist = $widget->HList(?OPTIONS?);

# Add/Configure items
$hlist->add( "path.to.item", -text => "Label", ... );
$hlist->addchild( "path.to.item", "new.item.path", ... );
$hlist->entryconfigure( "path.to.item", -text => "New Label", ... );
$hlist->entrycget( "path.to.item", "-option" );

# Item manipulation
$hlist->delete( "path.to.item", ... );
$hlist->see( "path.to.item" );
$hlist->item( "path.to.item", ?OPTIONS? );
$hlist->move( "from.path", "to.path" );
$hlist->moveup( "path.to.item" );
$hlist->movedown( "path.to.item" );
$hlist->raiseto( "path.to.item", ?OPTIONS? );
$hlist->lower( "path.to.item", ?OPTIONS? );

# Selection
$hlist->selection( "set", "path.to.item", ... );
$hlist->selection( "add", "path.to.item", ... );
$hlist->selection( "remove", "path.to.item", ... );
$hlist->selection( "clear" );
$hlist->selection( "get" );

# Scrolling
$hlist->yview(?ARGS?);
$hlist->xview(?ARGS?);

# Other
$hlist->component( ?path, ?OPTIONS? );
$hlist->component_update( ?path, ?OPTIONS? );
$hlist->component_delete( ?path );
$hlist->component_insert( ?path, ?OPTIONS? );
$hlist->component_set( ?path, ?OPTIONS? );
$hlist->component_cget( ?path, ?OPTIONS? );
$hlist->component_configure( ?path, ?OPTIONS? );

STANDARD OPTIONS

Tk::HList supports the standard Tk options common to most widgets, such as -background, -cursor, -font, -foreground, -height, -highlightbackground, -highlightcolor, -highlightthickness, -label, -padx, -pady, -relief, -takefocus, -width, etc.

WIDGET-SPECIFIC OPTIONS

-browsecmd ?script?
Specifies a script to be called whenever the selection changes (e.g., when the user drags the mouse over entries or moves the anchor point with the arrow keys). The script is called with one argument: the path of the currently browsed entry. If -selectmode is set to "multiple" or "extended", this command is called with an undefined parameter, and you have to check the selection yourself.
-command ?script?
Specifies a script to be called when an entry is double-clicked. The script is called with one argument: the path of the double-clicked entry.
-cursor ?cursorName?
Specifies the cursor to be displayed when the mouse pointer is over the widget.
-font ?fontName?
Specifies the font to be used for displaying text in the widget.
-height ?amount?
Specifies the desired height of the widget in lines of text. The default is 10 lines.
-itemtype ?type?
Specifies the default type for items added to the list. The default is "text". Other possible types are "window" and "bitmap".
-label ?labelString?
Specifies a label to be displayed above the HList. This is a standard Tk widget option, but it is often used with HList.
-orient ?orientation?
Specifies the orientation of the widget. Can be either horizontal or vertical. The default is vertical.
-relief ?reliefStyle?
Specifies the relief style for the widget border. The default is "flat".
-selectbackground ?color?
Specifies the background color for selected items.
-selectborderwidth ?amount?
Specifies the border width for selected items.
-selectforeground ?color?
Specifies the foreground color for selected items.
-selectmode ?mode?
Specifies how entries can be selected. The default is "browse". The possible modes are:
browse: Only one item can be selected at a time. The item is highlighted as the mouse pointer moves over it. The selection changes when the mouse button is released.
single: Only one item can be selected at a time. The item is highlighted when the mouse button is released over it.
multiple: Multiple, non-contiguous items can be selected. Items are selected and deselected by clicking on them. The region under the mouse pointer is highlighted during dragging.
extended: Multiple, contiguous items can be selected, similar to a standard listbox. Disjointed selections can be made using the Control key.
-separator ?separatorString?
Specifies the character used to separate levels in the entry path. The default is ".".
-show ?itemSpec?
Specifies which parts of the HList entry should be displayed. It can be a list of item specifications, such as -text, -imageline, -textline, etc. The default is to show all components.
-width ?amount?
Specifies the desired width of the widget in characters. The default is 10 characters.

DESCRIPTION

The Tk::HList widget displays a list of items, each of which can have child items, forming a hierarchical structure. The items are identified by a path string, where levels are separated by a specified character (default is ".").

DISPLAY ITEMS

Each entry in the HList can display multiple components. The following components are supported:

-text ?string?
The text to be displayed for this entry.
-image ?imageName?
An image to be displayed for this entry.
-imageline ?imageName?
An image to be displayed on the line connecting parent and child entries.
-textline ?textString?
A text string to be displayed on the line connecting parent and child entries.
-open ?boolean?
Specifies whether the children of this entry should be displayed. Defaults to false.

Additional options like -fill, -side, -anchor, -underline, -state, -disabledforeground, -activebackground, -activeforeground, -pady, -padx, -font, -fg, -bg, -height, -width can be used to control the appearance and behavior of each display item.

WIDGET METHODS

In addition to the standard Tk widget methods, HList supports the following:

$hlist->add(path, ?option value ...?)
Adds a new entry to the HList. path is the unique path for the new entry. The options control the appearance and behavior of the entry.
$hlist->addchild(parentPath, childPath, ?option value ...?)
Adds a new child entry to an existing entry specified by parentPath. childPath is the unique path for the new child entry.
$hlist->delete(path, ?path ...?)
Deletes one or more entries from the HList.
$hlist->entrycget(path, option)
Returns the value of the given option for the specified entry.
$hlist->entryconfigure(path, ?option value ...?)
Modifies the options for the specified entry.
$hlist->item(path, ?option value ...?)
This is a low-level method to manipulate individual display items within an HList entry. It can be used to get or set options for specific components of an entry. Use with caution, as it bypasses some of the higher-level entry management.
$hlist->move(fromPath, toPath)
Moves the entry specified by fromPath to be a child of the entry specified by toPath.
$hlist->moveup(path)
Moves the entry specified by path up one level among its siblings.
$hlist->movedown(path)
Moves the entry specified by path down one level among its siblings.
$hlist->raiseto(path, ?option value ...?)
Makes the specified entry visible, opening parent entries as needed.
$hlist->lower(path, ?option value ...?)
Hides the specified entry and its children.
$hlist->see(path)
Ensures that the specified entry is visible within the window, scrolling if necessary.
$hlist->selection(option, ?path ...?)
Manipulates the selection of entries. option can be "set", "add", "remove", "clear", or "get".
$hlist->xview(?args?)
Handles horizontal scrolling. See the Tk::Scrolled window manager for details.
$hlist->yview(?args?)
Handles vertical scrolling. It can take the following forms:
$hlist->yview
Returns a list containing two elements, both of which are real fractions between 0 and 1. The first element gives the position of the list element at the top of the window, relative to the HList as a whole (0.5 means it is halfway through the HList, for example). The second element gives the position of the list entry just after the last one in the window, relative to the HList as a whole. These are the same values passed to scrollbars via the -yscrollcommand option.
$hlist->yview($entryPath)
Adjusts the view in the window so that the list entry given by $entryPath is displayed at the top of the window.
$hlist->yview(moveto => fraction)
Adjusts the view in the window so that the list entry given by fraction appears at the top of the window. Fraction is a fraction between 0 and 1; 0 indicates the first entry in the HList, 0.33 indicates the entry one-third the way through the HList, and so on.
$hlist->yview(scroll => number, what)
This method adjust the view in the window up or down according to number and what. Number must be an integer. What must be either units or pages. If what is units, the view adjusts up or down by number lines; if it is pages then the view adjusts by number screenfuls. If number is negative then earlier entries become visible; if it is positive then later entries become visible.

BINDINGS

[1]
If the -selectmode is "browse", when the user drags the mouse pointer over the list entries, the entry under the pointer will be highlighted and the -browsecmd callback will be called with one parameter, the entryPath of the highlighted entry. Only one entry can be highlighted at a time. The -command callback will be called when the user double-clicks on a list entry.
[2]
If the -selectmode is "single", the entries will only be highlighted by mouse <ButtonRelease-1> events. When a new list entry is highlighted, the -browsecmd callback will be called with one parameter indicating the highlighted list entry. The -command callback will be called when the user double-clicks on a list entry.
[3]
If the -selectmode is "multiple", when the user drags the mouse pointer over the list entries, all the entries under the pointer will be highlighted. However, only a contiguous region of list entries can be selected. When the highlighted area is changed, the -browsecmd callback will be called with an undefined parameter. It is the responsibility of the -browsecmd callback to find out the exact highlighted selection in the HList. The -command callback will be called when the user double-clicks on a list entry.
[4]
If the -selectmode is "extended", when the user drags the mouse pointer over the list entries, all the entries under the pointer will be highlighted. The user can also make disjointed selections using <Control-ButtonPress-1>. When the highlighted area is changed, the -browsecmd callback will be called with an undefined parameter. It is the responsibility of the -browsecmd callback to find out the exact highlighted selection in the HList. The -command callback will be called when the user double-clicks on a list entry.
[5]
Arrow key bindings: <Up> arrow key moves the anchor point to the item right on top of the current anchor item. <Down> arrow key moves the anchor point to the item right below the current anchor item. <Left> arrow key moves the anchor to the parent item of the current anchor item. <Right> moves the anchor to the first child of the current anchor item. If the current anchor item does not have any children, moves the anchor to the item right below the current anchor item.

EXAMPLE

This example demonstrates how to use an HList to store a file directory structure and respond to the user's browse events:

use strict;
use Tk;
use Tk::Label;
use Tk::HList;
my $mw = MainWindow->new();
my $label = $mw->Label(-width=>15);
my $hlist = $mw->HList(
                    -itemtype   => 'text',
                    -separator  => '/',
                    -selectmode => 'single',
                    -browsecmd  => sub {
                              my $file = shift;
                              $label->configure(-text=>$file);
                           }
                    );
foreach ( qw(/ /home /home/ioi /home/foo /usr /usr/lib) ) {
    $hlist->add($_, -text=>$_);
}
$hlist->pack;
$label->pack;
MainLoop;

BUGS

The fact that the display item at column 0 is implicitly associated with the whole entry is probably a design bug. This was done for backward compatibility purposes. The result is that there is a large overlap between the item method and the add, addchild, entrycget and entryconfigure methods. Whenever multiple columns exist, the programmer should use ONLY the item method to create and configure the display items in each column; the add, addchild, entrycget and entryconfigure should be used ONLY to create and configure entries.
