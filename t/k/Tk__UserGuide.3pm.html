Algún antecedente

La programación GUI con Tk está basada en eventos. (Esto puede que ya te sea familiar). En programas basados en eventos, el bucle principal de la GUI está fuera del programa del usuario y dentro de la biblioteca de la GUI. Este bucle - iniciado llamando a MainLoop - vigila todos los eventos de interés y activa los procedimientos de manejo correctos para gestionar estos eventos. Algunos de estos procedimientos de manejo pueden ser proporcionados por el usuario; otros formarán parte de la biblioteca.

Para un programador, esto significa que no estás vigilando lo que está sucediendo; en cambio, el toolkit te solicita que realices acciones cuando sea necesario. Por lo tanto, no estás vigilando las solicitudes de 'mostrar ventana / cerrar ventana / redibujar ventana', sino que le dices al toolkit qué rutina manejará tales casos, y el toolkit llamará a los procedimientos cuando sea necesario. Estos procedimientos se conocen como callbacks (llamadas de retorno), y algunos de ellos los escribes tú mismo.

Primeros requisitos

Los programas de Perl que usan Tk necesitan incluir "use Tk". Un programa también debería usar "use strict" y el switch -w para asegurar que el programa funcione sin errores comunes.

Cualquier aplicación Perl/Tk comienza creando la MainWindow (ventana principal) de Tk. Luego creas elementos dentro de la MainWindow, y/o creas nuevas ventanas llamadas Toplevels que también contienen elementos hijos, antes de iniciar el MainLoop, que es la última instrucción lógica de tu programa. También puedes crear más elementos y ventanas mientras se está ejecutando, usando callbacks. Los elementos solo se muestran en la pantalla después de haber sido dispuestos por un gestor de geometría como pack; más información sobre esto más adelante. MainLoop inicia la GUI y maneja todos los eventos. ¡Eso es todo! A continuación se muestra un ejemplo trivial de una sola ventana:

#!/usr/bin/perl -w  
use Tk;
use strict;
my $mw = MainWindow->new;
$mw->Label(-text => 'Hola, mundo!')->pack;
$mw->Button(
    -text    => 'Salir',
    -command => sub { exit },
)->pack;
MainLoop;

Por favor, ejecuta este ejemplo. Te muestra dos tipos de widgets, un Label y un Button, y cómo se empaquetan. Cuando se hace clic, el widget Button invoca el callback especificado por la opción "-command". Finalmente, ten en cuenta el estilo típico de Tk usando pares de opción "-opción" => "valor".

Creación de widgets

Las ventanas y widgets de Tk son jerárquicos, es decir, una ventana incluye una o más ventanas. Creas la primera ventana de Tk usando "MainWindow->new". Esto devuelve un manejador de ventana, asignado a $mw en el ejemplo anterior. Lleva un registro del manejador principal, comúnmente llamado una referencia a widget.

Puedes usar cualquier manejador de Tk para crear widgets hijos dentro de la ventana (o widget). Esto se hace llamando al método constructor de Tk en la variable. En el ejemplo anterior, el método "Label" llamado desde $mw crea un widget Label dentro de la MainWindow. En la llamada al constructor, puedes especificar varias opciones; más tarde puedes añadir o cambiar opciones para cualquier widget usando el método configure, que toma los mismos parámetros que el constructor. La única excepción a la estructura jerárquica es el constructor Toplevel, que crea una nueva ventana externa.

Después de crear cualquier widget (excepto la MainWindow o las Toplevels), debes renderizarlo llamando a pack. (Esto no es del todo cierto; más adelante). Si no necesitas referirte al widget después de la construcción y empaquetado, llama a pack sobre los resultados del constructor, como se muestra para el Label y el Button en el ejemplo anterior. Ten en cuenta que el resultado de la llamada compuesta es el resultado de pack, que es un manejador de Tk válido.

Las ventanas y widgets se eliminan llamando a destroy sobre ellos; esto eliminará y desdibujará el widget y todos sus hijos.

Variables y rutinas de devolución de llamada

La mayoría de las interfaces gráficas se utilizan para configurar un conjunto de valores y condiciones, y luego realizar la acción apropiada. El toolkit Tk es diferente de tu sistema promedio de solicitud basado en texto o de menú, ya que no recopilas la configuración tú mismo y decides una acción basada en un código de entrada; en cambio, dejas estos valores a tu toolkit y solo los obtienes cuando se realiza la acción.

Así, donde un sistema tradicional basado en texto se vería así:

#!/usr/bin/perl -w
use strict;
print "Please type a font name\n";
my $font = <>; chomp $font;
# Validate font
print "Please type a file name\n";
my $filename = <>; chomp $filename;
# Validate filename
print "Type <1> to fax, <2> to print\n";
my $option = <>; chomp $option;
if ($option eq 1) {
    print "Faxing $filename in font $font\n";
} elsif ($option eq 2) {
    print "Now sending $filename to printer in font $font\n";
}

El ejemplo un poco más grande a continuación muestra cómo hacer esto en Tk. Tenga en cuenta el uso de devoluciones de llamada. Tenga en cuenta también que Tk maneja los valores, y la subrutina utiliza el método get para acceder a los valores. Si un usuario cambia de opinión y quiere cambiar la fuente nuevamente, la aplicación nunca se da cuenta; todo lo maneja Tk.

#!/usr/bin/perl -w
use Tk;
use strict;
my $mw = MainWindow->new;
$mw->Label(-text => 'File Name')->pack;
my $filename = $mw->Entry(-width => 20);
$filename->pack;
$mw->Label(-text => 'Font Name')->pack;
my $font = $mw->Entry(-width => 10);
$font->pack;
$mw->Button(
    -text => 'Fax',
    -command => sub{do_fax($filename, $font)}
)->pack;
$mw->Button(
    -text => 'Print',
    -command => sub{do_print($filename, $font)}
)->pack;
MainLoop;
sub do_fax {
    my ($file, $font) = @_;
    my $file_val = $file->get;
    my $font_val = $font->get;
    print "Now faxing $file_val in font $font_val\n";
}
sub do_print {
    my ($file, $font) = @_;
    my $file_val = $file->get;
    my $font_val = $font->get;
    print "Sending file $file_val to printer in font $font_val\n";
}

El empaquetador - agrupación con widgets Frame

En los ejemplos anteriores, debe haber notado las llamadas a pack. Esta es una de las partes más complicadas de Tk. La idea básica es que cualquier ventana o widget debe estar sujeto a un administrador de geometría de Tk; el empaquetador es uno de los administradores de posicionamiento, y grid es otro.

Las acciones del empaquetador son bastante simples: cuando se aplica a un widget, el empaquetador posiciona ese widget en la posición indicada dentro del espacio restante en su padre. Por defecto, la posición es arriba; esto significa que los siguientes elementos se colocarán debajo. También puede especificar las posiciones izquierda, derecha o inferior. Especifique la posición usando -side => 'right'.

Parámetros adicionales de empaquetado especifican el comportamiento del widget cuando queda espacio en el Frame o cuando aumenta el tamaño de la ventana. Si los widgets deben mantener un tamaño fijo, no especifique nada; este es el valor predeterminado. Para los widgets que desea que llenen el espacio horizontal y/o vertical actual, especifique -fill => 'x', 'y' o 'both'; para los widgets que deben crecer, especifique -expand => 1. Estos parámetros no se muestran en el siguiente ejemplo; consulte la demostración del widget.

Si desea agrupar algunos elementos dentro de una ventana que tienen un orden de empaquetado diferente al de otros, puede incluirlos en un Frame. Este es un tipo de ventana que no hace nada y está destinado a empaquetar o llenar (y a jugar con bordes y colores).

El siguiente ejemplo muestra el uso de pack y Frames:

#!/usr/bin/perl -w
use Tk;
use strict;
# Take top and the bottom - now implicit top is in the middle
my $mw = MainWindow->new;
$mw->title( 'The MainWindow' );
$mw->Label(-text => 'At the top (default)')->pack;
$mw->Label(-text => 'At the bottom')->pack(-side => 'bottom');
$mw->Label(-text => 'The middle remains')->pack;
# Since left and right are taken, bottom will not work...
my $top1 = $mw->Toplevel;
$top1->title( 'Toplevel 1' );
$top1->Label(-text => 'Left')->pack(-side => 'left');
$top1->Label(-text => 'Right')->pack(-side => 'right');
$top1->Label(-text => '?Bottom?')->pack(-side => 'bottom');
# But when you use Frames, things work quite alright
my $top2 = $mw->Toplevel;
$top2->title( 'Toplevel 2' );
my $frame = $top2->Frame;
$frame->pack;
$frame->Label(-text => 'Left2')->pack(-side => 'left');
$frame->Label(-text => 'Right2')->pack(-side => 'right');
$top2->Label(-text => 'Bottom2')->pack(-side => 'bottom');
MainLoop;

Más de una ventana

La mayoría de las aplicaciones reales requieren más de una ventana. Como acabas de ver, puedes crear más ventanas externas utilizando un widget Toplevel. Cada ventana es independiente; destruir una ventana Toplevel no afecta a las demás mientras no sean hijas de la Toplevel cerrada. Sin embargo, salir de la MainWindow destruirá todos los widgets Toplevel restantes y finalizará la aplicación. El siguiente ejemplo muestra una aplicación trivial de tres ventanas:

#!/usr/bin/perl -w
use Tk;
use strict;
my $mw = MainWindow->new;
fill_window($mw, 'Main');
my $top1 = $mw->Toplevel;
fill_window($top1, 'First top-level');
my $top2 = $mw->Toplevel;
fill_window($top2, 'Second top-level');
MainLoop;
sub fill_window {
    my ($window, $header) = @_;
    $window->Label(-text => $header)->pack;
    $window->Button(
        -text    => 'close',
        -command => [$window => 'destroy']
    )->pack(-side => 'left');
    $window->Button(
        -text    => 'exit',
        -command => [$mw => 'destroy']
    )->pack(-side => 'right');
}

Más devoluciones de llamada

Hasta ahora, todas las rutinas de devolución de llamada mostradas llamaron a un procedimiento de usuario. También puede hacer que una rutina de devolución de llamada llame a otra rutina de Tk. Esta es la forma en que se implementan las barras de desplazamiento: las barras de desplazamiento pueden llamar a un elemento de Tk o a un procedimiento de usuario, cada vez que su posición ha cambiado. El elemento de Tk al que está conectada una barra de desplazamiento llama a la barra de desplazamiento cuando su tamaño o desplazamiento ha cambiado. De esta manera, los elementos están vinculados. Todavía puede solicitar la posición de una barra de desplazamiento, o establecerla manualmente, pero los valores predeterminados se gestionarán.

El siguiente ejemplo muestra un Listbox con una barra de desplazamiento. Mover la barra de desplazamiento mueve el Listbox. Explorar un Listbox (arrastrar un elemento con el botón izquierdo del ratón) mueve la barra de desplazamiento.

 #!/usr/bin/perl -w
 use Tk;
 use strict;
 my $mw = MainWindow->new;
 my $box = $mw->Listbox(
     -relief => 'sunken',
     -height  => 5,
     -setgrid => 1,
);
my @items = qw(One Two Three Four Five Six Seven
               Eight Nine Ten Eleven Twelve);
foreach (@items) {
   $box->insert('end', $_);
}
my $scroll = $mw->Scrollbar(-command => ['yview', $box]);
$box->configure(-yscrollcommand => ['set', $scroll]);
$box->pack(-side => 'left', -fill => 'both', -expand => 1);
$scroll->pack(-side => 'right', -fill => 'y');
MainLoop;

Tenga en cuenta que existe un método de conveniencia Scrolled que ayuda a construir widgets con barras de desplazamiento gestionadas automáticamente.

Lienzos y etiquetas

Uno de los widgets más potentes de Tk es la ventana Canvas. En una ventana Canvas, puede dibujar gráficos simples e incluir otros widgets. El área del Canvas puede ser más grande que la ventana visible, y luego puede desplazarse. Cada elemento que dibuja en el lienzo tiene su propio id y opcionalmente puede tener una o más etiquetas. Puede referirse a cualquier elemento por su id, y puede referirse a cualquier grupo de elementos por una etiqueta común; puede mover, eliminar o cambiar grupos de elementos utilizando estas etiquetas, y puede enlazar acciones a las etiquetas. Para un Canvas diseñado (a menudo estructurado) correctamente, puede especificar acciones potentes de forma bastante sencilla.

En el siguiente ejemplo, las acciones se enlazan a círculos (un solo clic) y elementos azules (doble clic); obviamente, esto se puede extender a cualquier etiqueta o grupo de etiquetas.

#!/usr/bin/perl -w
use Tk;
use strict;
# Create B<MainWindow> and canvas
my $mw = MainWindow->new;
my $canvas = $mw->Canvas;
$canvas->pack(-expand => 1, -fill => 'both');
# Create various items
create_item($canvas, 1, 1, 'circle', 'blue', 'Jane');
create_item($canvas, 4, 4, 'circle', 'red', 'Peter');
create_item($canvas, 4, 1, 'square', 'blue', 'James');
create_item($canvas, 1, 4, 'square', 'red', 'Patricia');
# Single-clicking with left on a 'circle' item invokes a procedure
$canvas->bind('circle', '<1>' => sub {handle_circle($canvas)});
# Double-clicking with left on a 'blue' item invokes a procedure
$canvas->bind('blue', '<Double-1>' => sub {handle_blue($canvas)});
MainLoop;
# Create an item; use parameters as tags (this is not a default!)
sub create_item {
    my ($can, $x, $y, $form, $color, $name) = @_;
    my $x2 = $x + 1;
    my $y2 = $y + 1;
    my $kind;
    $kind = 'oval' if ($form eq 'circle');
    $kind = 'rectangle' if ($form eq 'square');
    $can->create(
        ($kind, "$x" . 'c', "$y" . 'c',
        "$x2" . 'c', "$y2" . 'c'),
        -tags => [$form, $color, $name],
        -fill => $color);
}
# This gets the real name (not current, blue/red, square/circle)
# Note: you'll want to return a list in realistic situations...
sub get_name {
    my ($can) = @_;
    my $item = $can->find('withtag', 'current');
    my @taglist = $can->gettags($item);
    my $name;
    foreach (@taglist) {
        next if ($_ eq 'current');
        next if ($_ eq 'red' or $_ eq 'blue');
        next if ($_ eq 'square' or $_ eq 'circle');
        $name = $_;
        last;
    }
    return $name;
}
sub handle_circle {
    my ($can) = @_;
    my $name = get_name($can);
    print "Action on circle $name...\n";
}
sub handle_blue {
    my ($can) = @_;
    my $name = get_name($can);
    print "Action on blue item $name...\n";
}

Perl/Tk y Unicode

Perl/Tk sigue el modelo de Perl para manejar Unicode. Es decir, si una cadena está correctamente marcada como una cadena de "caracteres" en el sentido descrito en "TERMINOLOGY" en Encode, entonces Perl/Tk muy probablemente mostrará y manejará esta cadena correctamente.

Tenga en cuenta que cada variable que se pasa de alguna manera a un método de Perl/Tk se cambiará implícitamente a una variable internamente marcada como utf8. Semánticamente nada cambia, ya que la serie

Tk::UserGuide - Perl/Tk User Guide

NAME

Tk::UserGuide - Perl/Tk User Guide

DESCRIPTION

This document provides a guide to using the Perl/Tk module.

Some Background

Perl/Tk is a Perl extension which allows you to create Tk graphical user interfaces (GUIs) from Perl.

First Requirements

To use Perl/Tk, you first need to have Tk installed on your system. The installation process can vary depending on your operating system.

Widget creation

Widgets are the basic building blocks of a Tk GUI. Examples include buttons, labels, and entry fields.

Standard Tk widgets

Perl/Tk provides bindings for most standard Tk widgets.

Variables and callback routines

Perl/Tk uses Perl variables to manage widget states and callback routines to handle events.

The packer - grouping with Frame widgets

The packer is a geometry manager that arranges widgets in a block.

More than one window

You can create multiple toplevel windows in your application.

More callbacks

Callbacks can be associated with various events, not just button clicks.

Canvases and tags

The Canvas widget is a versatile widget for drawing graphics and text.

Perl/Tk and Unicode

Perl/Tk supports Unicode, allowing you to work with characters from various languages.

When Perl/Tk operates in Unicode mode, the internal representation of strings is Unicode (specifically, UTF-8 or UTF-16, depending on the system). When dealing with external data (files, network sockets, databases, etc.), you need to be mindful of the encoding of that data. The internal codepoint representation of strings will remain the same, but things will change when variables with high-bit ISO-8859-1 characters will be passed to the "outer" world. In this case, you have to explicitly mark the encoding of your output stream if using IO, or encode the variables using Encode for other styles of communication.

This is the theory, now some examples.

If you use non-ISO-8859-1 characters in the source code, then use either the "use utf8;" or "use encoding 'encodingname'" pragma:

use utf8;
use Tk;
my $x = "some characters using utf8 encoding";
tkinit->Label(-text => $x)->pack;
MainLoop;

For data that comes from a file, you have to specify the encoding unless it's encoded as ASCII or ISO-8859-1:

use Tk;
open my $FH, "<:encoding(utf-8)", "filename" or die $!;
# or for utf-16 data: open my $FH, "<:encoding(utf-16)", "filename" or die $!;
my $data = <$FH>;
tkinit->Label(-text => $data)->pack;
MainLoop;

Likewise, the encoding must be specified for all data which is read from Tk widgets and that shall be output into a file. For the output, the encoding should be always specified, even if it is ISO-8859-1:

use Tk;
$mw = tkinit;
$mw->Entry(-textvariable => \$input)->pack;
$mw->Button(
    -text => "Write to file",
    -command => sub {
        open my $FH, ">:encoding(iso-8859-1)", "filename" or die $!;
        print $FH $input;
    },
)->pack;
MainLoop;

Note that Tk is Unicode-capable. So you need to be prepared that the user has the appropriate input methods activated to enter non-ASCII characters. If an output encoding is used which does not cover the whole of Unicode codepoints, then a warning will be issued when writing the file, like this:

"\x{20ac}" does not map to iso-8859-1 at /usr/local/lib/perl5/5.8.8/mach/Tk.pm line 250.

Also, the same hexadecimal notation will be used as replacements for the unhandled characters.

Handling encoding in I/O is pretty simple using the "encoding" PerlIO layer, as described above. In other cases, such as when dealing with databases, encoding the data usually has to be done manually, unless the database driver has some means for automatically doing this for you. So when working with a MySQL database, one could use:

use Tk;
use DBI;
use Encode qw(encode);
$mw = tkinit;
$mw->Entry(-textvariable => \$input)->pack;
$mw->Button(
    -text => "Write to database",
    -command => sub {
        my $dbh = DBI->connect("dbi:mysql:test", "root", "") or die;
        my $encoded_input = encode("iso-8859-1", $input);
        $dbh->do("INSERT INTO testtable VALUES (?)", undef, $encoded_input) or die;
    },
)->pack;
MainLoop;

Unfortunately, there are still places in Perl ignorant of Unicode. One of these places is filenames. Consequently, the file selectors in Perl/Tk do not handle encoding of filenames properly. Currently, they suppose that filenames are in ISO-8859-1 encoding, at least on Unix systems. As soon as Perl has a concept of filename encodings, then Perl/Tk will also implement such schemes.
