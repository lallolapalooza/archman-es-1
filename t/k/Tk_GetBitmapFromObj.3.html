NOMBRE

Tk_AllocBitmapFromObj, Tk_GetBitmap, Tk_GetBitmapFromObj, Tk_DefineBitmap, Tk_NameOfBitmap, Tk_SizeOfBitmap, Tk_FreeBitmapFromObj, Tk_FreeBitmap - mantener base de datos de mapas de bits de un solo plano

SINOPSIS

#include <tk.h>

Pixmap
Tk_AllocBitmapFromObj(interp, tkwin, objPtr)

Pixmap
Tk_GetBitmap(interp, tkwin, info)

Pixmap
Tk_GetBitmapFromObj(tkwin, objPtr)

int
Tk_DefineBitmap(interp, name, source, width, height)

const char *
Tk_NameOfBitmap(display, bitmap)

Tk_SizeOfBitmap(display, bitmap, widthPtr, heightPtr)

Tk_FreeBitmapFromObj(tkwin, objPtr)

Tk_FreeBitmap(display, bitmap)

ARGUMENTOS

Tcl_Interp *interp (entrada)
Intérprete a usar para reportar errores; si es NULL, no se deja ningún mensaje de error tras los errores.
Tk_Window tkwin (entrada)
Token para la ventana en la que se usará el mapa de bits.
Tcl_Obj *objPtr (entrada/salida)
El valor de la cadena describe el mapa de bits deseado; la representación interna se modificará para almacenar en caché un puntero al Pixmap correspondiente.
const char *info (entrada)
Igual que objPtr, excepto que la descripción del mapa de bits se pasa como una cadena y el Pixmap resultante no se almacena en caché.
const char *name (entrada)
Nombre para el nuevo mapa de bits que se definirá.
const void *source (entrada)
Datos para el mapa de bits, en formato estándar de mapa de bits. Debe almacenarse en memoria estática cuyo valor nunca cambiará.
int width (entrada)
Ancho del mapa de bits.
int height (entrada)
Alto del mapa de bits.
int *widthPtr (salida)
Puntero a la palabra donde se almacenará el ancho del bitmap.
int *heightPtr (salida)
Puntero a la palabra donde se almacenará el alto del bitmap.
Display *display (entrada)
Pantalla para la cual se asignó el bitmap.
Pixmap bitmap (entrada)
Identificador de un mapa de bits asignado por Tk_AllocBitmapFromObj o Tk_GetBitmap.

DESCRIPCIÓN

Estos procedimientos gestionan una colección de mapas de bits (pixmaps de un solo plano) que está utilizando una aplicación. Los procedimientos permiten reutilizar mapas de bits de forma eficiente, evitando así la sobrecarga del servidor, y también permiten nombrar mapas de bits con cadenas de caracteres.

Tk_AllocBitmapFromObj devuelve un identificador Pixmap para un mapa de bits que coincide con la descripción en objPtr y es adecuado para su uso en tkwin. Reutiliza un mapa de bits existente, si es posible, y crea uno nuevo en caso contrario. El valor de objPtr debe tener una de las siguientes formas:

@nombreArchivo
nombreArchivo debe ser el nombre de un archivo que contenga una descripción de mapa de bits en el formato estándar de X11.
nombre
nombre debe ser el nombre de un mapa de bits definido previamente con una llamada a Tk_DefineBitmap. Los siguientes nombres están predefinidos por Tk:
error
El símbolo internacional de “no”: un círculo con una línea diagonal que lo atraviesa.
gray75
75% de gris: un patrón de tablero de ajedrez donde tres de cada cuatro bits están activados.
gray50
50% de gris: un patrón de tablero de ajedrez donde cada dos bits están activados.
gray25
25% de gris: un patrón de tablero de ajedrez donde uno de cada cuatro bits está activado.
gray12
12.5% de gris: un patrón donde una octava parte de los bits están activados, que consiste en cada cuarto píxel en cada fila alterna.
hourglass
Un símbolo de reloj de arena.
info
Una letra “i” grande.
questhead
La silueta de una cabeza humana, con un signo de interrogación en ella.
question
Un signo de interrogación grande.
warning
Un signo de exclamación grande.

Además, los siguientes nombres predefinidos solo están disponibles en la plataforma Macintosh:

document
Un documento genérico.
stationery
Papelería de documento.
edition
El símbolo de edition.
application
Icono genérico de aplicación.
accessory
Un accesorio de escritorio.
folder
Icono genérico de carpeta.
pfolder
Una carpeta bloqueada.
trash
Un cubo de basura.
floppy
Un icono de disco flexible.
ramdisk
Un disco flexible con un chip.
cdrom
Un icono de disco CD.
preferences
Una carpeta con el símbolo de preferencias.
querydoc
Un icono de documento de base de datos.
stop
Una señal de stop.
note
Una cara con un bocadillo de diálogo.
caution
Un triángulo con un signo de exclamación.

En condiciones normales, Tk_AllocBitmapFromObj devuelve un identificador para el mapa de bits solicitado. Si ocurre un error al crear el mapa de bits, como cuando objPtr hace referencia a un archivo inexistente, entonces se devuelve None y se deja un mensaje de error en el resultado de interp si interp no es NULL. Tk_AllocBitmapFromObj almacena en caché información sobre el valor de retorno en objPtr, lo que acelera las llamadas futuras a procedimientos como Tk_AllocBitmapFromObj y Tk_GetBitmapFromObj.

Tk_GetBitmap es idéntico a Tk_AllocBitmapFromObj, excepto que la descripción del mapa de bits se especifica con una cadena en lugar de un objeto. Esto evita que Tk_GetBitmap almacene en caché el valor de retorno, por lo que Tk_GetBitmap es menos eficiente que Tk_AllocBitmapFromObj.

Tk_GetBitmapFromObj devuelve el token de un mapa de bits existente, dado la ventana y la descripción utilizadas para crear el mapa de bits. Tk_GetBitmapFromObj no crea realmente el mapa de bits; el mapa de bits debe haber sido creado previamente con una llamada a Tk_AllocBitmapFromObj o Tk_GetBitmap. El valor de retorno se almacena en caché en objPtr, lo que acelera las llamadas futuras a Tk_GetBitmapFromObj con el mismo objPtr y tkwin.

Tk_DefineBitmap asocia un nombre con datos de mapa de bits en memoria para que el nombre pueda usarse en llamadas posteriores a Tk_AllocBitmapFromObj o Tk_GetBitmap. El argumento nameId proporciona un nombre para el mapa de bits; no debe haber sido utilizado previamente en una llamada a Tk_DefineBitmap. Los argumentos source, width y height describen el mapa de bits. Tk_DefineBitmap normalmente devuelve TCL_OK; si ocurre un error (por ejemplo, un mapa de bits llamado nameId ya se ha definido), entonces se devuelve TCL_ERROR y se deja un mensaje de error en el resultado del intérprete interp. Nota: Tk_DefineBitmap espera que la memoria apuntada por source sea estática: Tk_DefineBitmap no crea una copia privada de esta memoria, sino que utiliza los bytes apuntados por source más adelante en llamadas a Tk_AllocBitmapFromObj o Tk_GetBitmap.

Normalmente, Tk_DefineBitmap es utilizado por #include-ing un archivo de mapa de bits directamente en un programa C y luego referenciando las variables definidas por el archivo. Por ejemplo, supongamos que existe un archivo stip.bitmap, que

se creó con el programa bitmap y contiene un patrón de puntos. El siguiente código utiliza Tk_DefineBitmap para definir un nuevo mapa de bits llamado foo:

Pixmap bitmap;
#include "stip.bitmap"
Tk_DefineBitmap(interp, "foo", stip_bits,
    stip_width, stip_height);
...
bitmap = Tk_GetBitmap(interp, tkwin, "foo");
Este código hace que el archivo del mapa de bits se lea en tiempo de compilación y incorpora la información del mapa de bits en la imagen ejecutable del programa. El mismo archivo de mapa de bits podría leerse en tiempo de ejecución usando Tk_GetBitmap: 
Pixmap bitmap;
bitmap = Tk_GetBitmap(interp, tkwin, "@stip.bitmap");
La segunda forma es un poco más flexible (el archivo podría modificarse después de que el programa se haya compilado, o se podría proporcionar una cadena diferente para leer un archivo diferente), pero es un poco más lenta y requiere que el archivo del mapa de bits exista por separado del programa.

Tk mantiene una base de datos de todos los mapas de bits que están actualmente en uso. Siempre que sea posible, devolverá un mapa de bits existente en lugar de crear uno nuevo. Cuando un mapa de bits ya no se usa, Tk lo liberará automáticamente. Este enfoque puede reducir sustancialmente la sobrecarga del servidor, por lo que generalmente se deben preferir Tk_AllocBitmapFromObj y Tk_GetBitmap sobre los procedimientos de Xlib como XReadBitmapFile.

Los mapas de bits devueltos por Tk_AllocBitmapFromObj y Tk_GetBitmap se comparten, por lo que los llamadores nunca deben modificarlos. Si un mapa de bits debe modificarse dinámicamente, entonces debe crearse llamando directamente a procedimientos de Xlib como XReadBitmapFile o XCreatePixmap.

El procedimiento Tk_NameOfBitmap es aproximadamente el inverso de Tk_GetBitmap. Dado un argumento X Pixmap, devuelve la descripción textual que se pasó a Tk_GetBitmap cuando se creó el mapa de bits. Bitmap debe haber sido el valor de retorno de una llamada anterior a Tk_AllocBitmapFromObj o Tk_GetBitmap.

Tk_SizeOfBitmap devuelve las dimensiones de su argumento bitmap en las palabras apuntadas por los argumentos widthPtr y heightPtr. Al igual que con Tk_NameOfBitmap, bitmap debe haber sido creado por Tk_AllocBitmapFromObj o Tk_GetBitmap.

Cuando un mapa de bits ya no es necesario, se debe llamar a Tk_FreeBitmapFromObj o Tk_FreeBitmap para liberarlo. Para Tk_FreeBitmapFromObj, el mapa de bits a liberar se especifica con la misma información utilizada para crearlo; para Tk_FreeBitmap, el mapa de bits a liberar se especifica con su token Pixmap. Debe haber exactamente una llamada a Tk_FreeBitmapFromObj o Tk_FreeBitmap por cada llamada a Tk_AllocBitmapFromObj o Tk_GetBitmap.

BUGS

Al determinar si un mapa de bits existente puede usarse para satisfacer una nueva solicitud, Tk_AllocBitmapFromObj y Tk_GetBitmap consideran solo el valor inmediato de la descripción de la cadena. Por ejemplo, cuando se pasa un nombre de archivo a Tk_GetBitmap, Tk_GetBitmap asumirá que es seguro reutilizar un mapa de bits existente creado a partir del mismo nombre de archivo: no verificará si el archivo en sí ha cambiado, o si el directorio actual ha cambiado, lo que haría que el nombre hiciera referencia a un archivo diferente.
