Tk_CreateImageType(3) Procedimientos de la biblioteca Tk Tk_CreateImageType(3)

NOMBRE

Tk_CreateImageType, Tk_GetImageMasterData, Tk_GetImageModelData, Tk_InitImageArgs - definir un nuevo tipo de imagen

SINOPSIS

#include <tk.h>

Tk_CreateImageType(typePtr)

ClientData
Tk_GetImageMasterData(interp, name, typePtrPtr)

ClientData
Tk_GetImageModelData(interp, name, typePtrPtr)

Tk_InitImageArgs(interp, argc, argvPtr)

ARGUMENTOS

const Tk_ImageType *typePtr (entrada)
Estructura que define el nuevo tipo de imagen. Para Tk 8.4 y anteriores, esto debe ser estático: el código de imagen conserva un puntero a esta estructura. En Tk 8.5, esta limitación se relajó.
Tcl_Interp *interp (entrada)
Intérprete en el que se creó la imagen.
const char *name (entrada)
Nombre de la imagen existente.
Tk_ImageType **typePtrPtr (salida)
Apunta a la palabra en la que se debe almacenar un puntero a la información del tipo para la imagen dada, si existe.
int argc (entrada)
Número de argumentos
char ***argvPtr (entrada/salida)
Puntero a la lista de argumentos

DESCRIPCIÓN

Tk_CreateImageType se invoca para definir un nuevo tipo de imagen. Un tipo de imagen corresponde a un valor particular del argumento type para el comando image create. Puede haber cualquier número de tipos de imagen diferentes, y se pueden definir nuevos tipos dinámicamente llamando a Tk_CreateImageType. Por ejemplo, podría haber un tipo para mapas de bits de 2 colores, otro para imágenes multicolor, otro para imágenes de difuminado, otro para video, etc.

El código que implementa un nuevo tipo de imagen se llama gestor de imágenes. Consiste en una colección de procedimientos más tres tipos diferentes de estructuras de datos. La primera estructura de datos es una estructura Tk_ImageType, que contiene el nombre del tipo de imagen y punteros a cinco procedimientos proporcionados por el gestor de imágenes para manejar imágenes de este tipo:

typedef struct Tk_ImageType {
    const char *name;
    Tk_ImageCreateProc *createProc;
    Tk_ImageGetProc *getProc;
    Tk_ImageDisplayProc *displayProc;
    Tk_ImageFreeProc *freeProc;
    Tk_ImageDeleteProc *deleteProc;
} Tk_ImageType;
Los campos de esta estructura se describirán en subsecciones posteriores de esta entrada.

La segunda estructura de datos principal manipulada por un gestor de imágenes se llama modelo de imagen; contiene información general sobre una imagen particular, como los valores de las opciones de configuración especificadas en un comando image create. Normalmente habrá una de estas estructuras por cada invocación del comando image create.

La tercera estructura de datos relacionada con las imágenes es una instancia de imagen. Normalmente habrá una de estas estructuras por cada uso de una imagen en un widget particular. Es posible que una sola imagen aparezca simultáneamente en varios widgets, o incluso varias veces en el mismo widget. Además, diferentes instancias pueden estar en diferentes pantallas o displays. La estructura de datos de instancia de imagen describe cosas que pueden variar de una instancia a otra, como colores y contextos gráficos para redibujar. Normalmente hay una estructura de instancia por cada opción -image especificada para un widget o elemento de lienzo.

Las siguientes subsecciones describen los campos de una Tk_ImageType con más detalle.

NOMBRE

typePtr->name proporciona un nombre para el tipo de imagen. Una vez que Tk_CreateImageType regresa, este nombre puede ser utilizado en comandos image create para crear imágenes del nuevo tipo. Si ya existía un tipo de imagen con este nombre, el nuevo tipo de imagen reemplaza al anterior.

CREATEPROC

typePtr->createProc proporciona la dirección de un procedimiento que Tk llamará cada vez que se invoque image create para crear una imagen del nuevo tipo. typePtr->createProc debe coincidir con el siguiente prototipo:

typedef int Tk_ImageCreateProc(
        Tcl_Interp *interp,
        const char *name,
        int objc,
        Tcl_Obj *const objv[],
        const Tk_ImageType *typePtr,
        Tk_ImageMaster model,
        ClientData *modelDataPtr);
El argumento interp es el intérprete en el que se invocó el comando image, y name es el nombre de la nueva imagen, que fue especificado explícitamente en el comando image o generado automáticamente por el comando image. Los argumentos objc y objv describen todas las opciones de configuración para la nueva imagen (todo lo que sigue al argumento del nombre de image). El argumento model es un token que se refiere a la información de Tk sobre esta imagen; el gestor de imágenes debe devolver este token a Tk al invocar el procedimiento Tk_ImageChanged. Normalmente, createProc analizará objc y objv y creará una estructura de datos de modelo de imagen para la nueva imagen. createProc puede almacenar un valor de una palabra arbitraria en *modelDataPtr, que se devolverá al gestor de imágenes al invocar otras devoluciones de llamada. Normalmente, el valor es un puntero a la estructura de datos del modelo para la imagen.

Si createProc encuentra un error, debe dejar un mensaje de error en el resultado del intérprete y devolver TCL_ERROR; de lo contrario, debe devolver TCL_OK.

createProc debería llamar a Tk_ImageChanged para establecer el tamaño de la imagen y solicitar un redibujado inicial.

GETPROC

Tk invoca typePtr->getProc cada vez que un widget llama a Tk_GetImage para usar una imagen particular. Este procedimiento debe coincidir con el siguiente prototipo:

typedef ClientData Tk_ImageGetProc(
        Tk_Window tkwin,
        ClientData modelData);
El argumento tkwin identifica la ventana en la que se usará la imagen y modelData es el valor devuelto por createProc cuando se creó el modelo de imagen. getProc normalmente creará una estructura de datos para la nueva instancia, incluyendo cosas como los recursos necesarios para mostrar la imagen en la ventana dada. getProc devuelve un token de una palabra para la instancia, que normalmente es la dirección de la estructura de datos de la instancia. Tk pasará este valor de vuelta al gestor de imágenes al invocar sus procedimientos displayProc y freeProc.

DISPLAYPROC

Tk invoca typePtr->displayProc cada vez que una imagen necesita ser mostrada (es decir, cada vez que un widget llama a Tk_RedrawImage). displayProc debe coincidir con el siguiente prototipo:

typedef void Tk_ImageDisplayProc(
        ClientData instanceData,
        Display *display,
        Drawable drawable,
        int imageX,
        int imageY,
        int width,
        int height,
        int drawableX,
        int drawableY);
instanceData será el mismo que el valor devuelto por getProc cuando se creó la instancia. display y drawable indican dónde mostrar la imagen; drawable puede ser un pixmap en lugar de la ventana especificada a getProc (este es generalmente el caso, ya que la mayoría de los widgets usan doble búfer para su redibujado para obtener efectos visuales más fluidos). imageX, imageY, width y height identifican la región de la imagen que debe redibujarse. Esta región siempre estará dentro del tamaño de la imagen según lo especificado en la llamada más reciente a Tk_ImageChanged. drawableX y drawableY indican dónde en drawable se debe mostrar la imagen; displayProc debe mostrar la región dada de la imagen de manera que el punto (imageX, imageY) en la imagen aparezca en (drawableX, drawableY) en drawable.

FREEPROC

typePtr->freeProc contiene la dirección de un procedimiento que Tk invocará cuando se libere una instancia de imagen (es decir, cuando se invoque Tk_FreeImage). Esto puede ocurrir, por ejemplo, cuando se elimina un widget o un elemento de imagen en un lienzo, o cuando se cambia la imagen mostrada en un widget o elemento de lienzo. freeProc debe coincidir con el siguiente prototipo:

Tk_GetImageMasterData(3) — Tk

NAME

Tk_GetImageMasterData, Tk_GetImageModelData — retrieve image manager data

SYNOPSIS

#include <tk.h>

ClientData
Tk_GetImageMasterData(
        Tcl_Interp *interp,
        const char *name,
        Tk_ImageType **typePtrPtr);

ClientData
Tk_GetImageModelData(
        Tcl_Interp *interp,
        const char *name,
        Tk_ImageType **typePtrPtr);

typedef void Tk_ImageFreeProc(
        ClientData instanceData,
        Display *display);

ARGUMENTS

ClientData

instanceData (in): A pointer to the image instance data.

modelData (in): A pointer to the image model data.

Display *

display (in): The display containing the window for the instance.

Tcl_Interp *

interp (in): Interpreter to use for error reporting.

char *

name (in): Name of the image.

int

argc (in): Number of arguments.

char **

argv (in): Argument values.

Tk_ImageType *

typePtr (in): Pointer to type information for the image.

Tk_ImageMaster

model (in): The image master structure.

ClientData *

modelDataPtr (in): Pointer to image model data.

Tk_ImageType **

typePtrPtr (out): Pointer to a pointer that will be filled in with the type information for the image.

DESCRIPTION

An image type manager is responsible for creating, deleting, and redrawing image instances. The manager provides two procedures to Tk: createProc and freeProc.

CREATEPROC

typePtr->createProc is a procedure that Tk invokes when an image instance is created (e.g. when the image create command is invoked). createProc should allocate and initialize storage for the image instance and return a pointer to it. The storage should be freed by freeProc. createProc must match the following prototype:

typedef ClientData Tk_ImageCreateProc(
        Tcl_Interp *interp,
        const char *name,
        int argc,
        const char **argv,
        Tk_ImageType *typePtr,
        Tk_ImageMaster master);

The arguments are the same as for Tk_ImageCreate. The return value is a pointer to the image instance data. This value will be passed back to freeProc and displayProc.

FREEPROC

typePtr->freeProc is a procedure that Tk invokes just before an image instance is destroyed. freeProc should release any resources associated with the image instance, since the instance will never be used again. freeProc must match the following prototype:

typedef void Tk_ImageFreeProc(
        ClientData instanceData,
        Display *display);

The instanceData will be the same as the value returned by createProc when the instance was created, and display is the display containing the window for the instance. freeProc should release any resources associated with the image instance, since the instance will never be used again.

DELETEPROC

typePtr->deleteProc is a procedure that Tk invokes when an image is being deleted (i.e. when the image delete command is invoked). Before invoking deleteProc Tk will invoke freeProc for each of the image's instances. deleteProc must match the following prototype:

typedef void Tk_ImageDeleteProc(
        ClientData modelData);

The modelData argument will be the same as the value stored in *modelDataPtr by createProc when the image was created. deleteProc should release any resources associated with the image.

TK_GETIMAGEMODELDATA

The procedure Tk_GetImageMasterData may be invoked to retrieve information about an image. For example, an image manager can use this procedure to locate its image model data for an image. If there exists an image named name in the interpreter given by interp, then *typePtrPtr is filled in with type information for the image (the typePtr value passed to Tk_CreateImageType when the image type was registered) and the return value is the ClientData value returned by the createProc when the image was created (this is typically a pointer to the image model data structure). If no such image exists then NULL is returned and NULL is stored at *typePtrPtr.

Tk_GetImageModelData is synonym for Tk_GetImageMasterData

LEGACY INTERFACE SUPPORT

In Tk 8.2 and earlier, the definition of Tk_ImageCreateProc was incompatibly different, with the following prototype:

typedef int Tk_ImageCreateProc(
        Tcl_Interp *interp,
        char *name,
        int argc,
        char **argv,
        Tk_ImageType *typePtr,
        Tk_ImageMaster model,
        ClientData *modelDataPtr);

Legacy programs and libraries dating from those days may still contain code that defines extended Tk image types using the old interface. The Tk header file will still support this legacy interface if the code is compiled with the macro USE_OLD_IMAGE defined.

Tk_ImageModel is synonym for Tk_ImageMaster

When the USE_OLD_IMAGE legacy support is enabled, you may see the routine Tk_InitImageArgs in use. This was a migration tool used to create stub-enabled extensions that could be loaded into interps containing all versions of Tk 8.1 and later. Tk 8.5 no longer provides this routine, but uses a macro to convert any attempted calls of this routine into an empty comment. Any stub-enabled extension providing an extended image type via the legacy interface that is compiled against Tk 8.5 headers and linked against the Tk 8.5 stub library will produce a file that can be loaded only into interps with Tk 8.5 or later; that is, the normal stub-compatibility rules. If a developer needs to generate from such code a file that is loadable into interps with Tk 8.4 or earlier, they must use Tk 8.4 headers and stub libraries to do so.

Any new code written today should not make use of the legacy interfaces. Expect their support to go away in Tk 9.
