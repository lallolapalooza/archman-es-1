ARGUMENTOS

Tcl_Interp *interp (entrada)
Intérprete a utilizar para la notificación de errores.
Tk_Window tkwin (entrada)
Token para la ventana (para todos los procedimientos excepto Tk_Get3DBorder, debe ser la ventana para la cual se asignó el borde).
Tcl_Obj *objPtr (entrada)
Puntero a un valor cuyo valor describe el color correspondiente al fondo (áreas planas). Los bordes iluminados aparecerán más brillantes que este y los bordes sombreados más oscuros que este.
const char *colorName (entrada)
Similar a objPtr, pero el valor se proporciona como una cadena en lugar de un valor.
Drawable drawable (entrada)
Token para ventana o pixmap; indica dónde se van a dibujar los gráficos. Debe ser la ventana correspondiente a tkwin o un pixmap con la misma pantalla y profundidad que tkwin.
Tk_3DBorder border (entrada)
Token para el borde previamente asignado en una llamada a Tk_Get3DBorder.
int x (entrada)
Coordenada x de la esquina superior izquierda del esquema de la figura que describe el borde o el bisel, en píxeles.
int y (entrada)
Coordenada y de la esquina superior izquierda del esquema de la figura que describe el borde o el bisel, en píxeles.
int width (entrada)
Ancho de la figura que describe el borde o el bisel, en píxeles.
int height (entrada)
Altura de la figura que describe el borde o el bisel, en píxeles.
int borderWidth (entrada)
Ancho del borde, en píxeles. Un valor positivo significa que el borde está dentro de la figura dada por x, y, width, height; un valor negativo significa que el borde está fuera de la figura.
int relief (entrada)
Indica la posición 3D del interior del valor relativa al exterior; debe ser TK_RELIEF_RAISED, TK_RELIEF_SUNKEN, TK_RELIEF_GROOVE, TK_RELIEF_SOLID o TK_RELIEF_RIDGE (también puede ser TK_RELIEF_FLAT para Tk_Fill3DRectangle).
XPoint *pointPtr (entrada)
Puntero a un array de puntos que describen los vértices de un polígono. El polígono no necesita estar cerrado (se cerrará automáticamente si no lo está).
int numPoints (entrada)
Número de puntos en pointPtr.
int polyBorderWidth (entrada)
Ancho del borde, en píxeles. Si es positivo, el borde se dibuja a la izquierda de la trayectoria dada por pointPtr; si es negativo, el borde se dibuja a la derecha de la trayectoria. Si leftRelief es TK_RELIEF_GROOVE o TK_RELIEF_RIDGE, el borde se centra en la trayectoria.
int leftRelief (entrada)
Altura del lado izquierdo de la trayectoria relativa al lado derecho. TK_RELIEF_RAISED significa que el lado izquierdo debería parecer más alto; TK_RELIEF_SUNKEN significa que el lado derecho debería parecer más alto; TK_RELIEF_GROOVE y TK_RELIEF_RIDGE significan lo obvio. Para Tk_Fill3DPolygon, también se puede especificar TK_RELIEF_FLAT para indicar que no hay diferencia en la altura.
int leftBevel (entrada)
Si no es cero, este bisel forma el lado izquierdo del valor; si es cero, forma el lado derecho.
int leftIn (entrada)
Si no es cero, el lado izquierdo del bisel horizontal se inclina hacia adelante, de modo que la parte inferior del borde se desplaza más a la derecha que la parte superior. Si es cero, los bordes se inclinan hacia atrás, de modo que la parte inferior se desplaza más a la izquierda que la parte superior.
int rightIn (entrada)
Si no es cero, el lado derecho del bisel horizontal se inclina hacia adelante, de modo que la parte inferior del borde se desplaza más a la izquierda que la parte superior. Si es cero, los bordes se inclinan hacia atrás, de modo que la parte inferior se desplaza más a la derecha que la parte superior.
int topBevel (entrada)
Si no es cero, este bisel forma el lado superior del valor; si es cero, forma el lado inferior.
int which (entrada)
Indica qué contexto de gráficos del borde se desea. Debe ser TK_3D_FLAT_GC, TK_3D_LIGHT_GC o TK_3D_DARK_GC.

DESCRIPCIÓN

Estos procedimientos proporcionan las funciones para dibujar bordes de ventanas en un modo que produce una apariencia 3D. Tk_Alloc3DBorderFromObj asigna colores y pixmaps necesarios para dibujar un borde en la ventana dada por el argumento tkwin. El valor de objPtr es un nombre de color estándar de Tk que determina los colores del borde. El color indicado por objPtr no se utilizará realmente en el borde; indica el color del fondo para la ventana (es decir, un color para superficies planas). Las partes iluminadas del borde aparecerán más brillantes que el valor indicado por objPtr, y las partes sombreadas del borde aparecerán más oscuras que objPtr.

Tk_Alloc3DBorderFromObj devuelve un token que puede ser utilizado en llamadas posteriores a Tk_Draw3DRectangle. Si ocurre un error al asignar información para el borde (por ejemplo, se proporcionó un nombre de color inválido), se devuelve NULL y un mensaje de error queda como resultado del intérprete interp. Si devuelve exitosamente, Tk_Alloc3DBorderFromObj almacena en caché la información sobre el valor devuelto en objPtr, lo que acelera futuras llamadas a Tk_Alloc3DBorderFromObj con el mismo objPtr y tkwin.

Tk_Get3DBorder es idéntico a Tk_Alloc3DBorderFromObj, excepto que el color se especifica con una cadena en lugar de un valor. Esto evita que Tk_Get3DBorder almacene en caché el valor devuelto, por lo que Tk_Get3DBorder es menos eficiente que Tk_Alloc3DBorderFromObj.

Tk_Get3DBorderFromObj devuelve el token para un borde existente, dado la ventana y el nombre de color utilizado para crear el borde. Tk_Get3DBorderFromObj no crea realmente el borde; debe haber sido creado previamente con una llamada a Tk_Alloc3DBorderFromObj o Tk_Get3DBorder. El valor devuelto se almacena en caché en objPtr, lo que acelera futuras llamadas a Tk_Get3DBorderFromObj con el mismo objPtr y tkwin.

Una vez que se ha creado una estructura de borde, Tk_Draw3DRectangle puede invocarse para dibujar el borde. El argumento tkwin especifica la ventana para la cual se asignó el borde, y drawable especifica una ventana o pixmap en la cual se dibuja el borde. drawable no debe referirse a la misma ventana que tkwin, pero debe referirse a un pixmap compatible con tkwin: uno asociado a la misma pantalla y con la misma profundidad que tkwin. Los argumentos x, y, width y height definen el cuadro del borde dentro de drawable (generalmente x e y son cero y width y height son las dimensiones de la ventana), y borderWidth especifica el número de píxeles que realmente ocupan el borde. El argumento relief indica qué de varios efectos 3D se desea: TK_RELIEF_RAISED significa que el interior del rectángulo debería parecer elevado en relación con el exterior del rectángulo, y TK_RELIEF_SUNKEN significa que el interior debería parecer hundido. TK_RELIEF_GROOVE y TK_RELIEF_RIDGE significan que hay un surco o una cresta alrededor del exterior del rectángulo.

ARGUMENTS

-border
Specifies the border object to query.
-which
One of TK_3D_FLAT_GC, TK_3D_LIGHT_GC, or TK_3D_DARK_GC.

DESCRIPTION

Tk supports borders with a three-dimensional appearance. Such borders are created by Tk using a combination of colors and drawing primitives. The procedure Tk_Alloc3DBorderFromObj (or its older, deprecated variant, Tk_Get3DBorder) is used to create a border object. This object is then passed to various Tk drawing procedures. This section describes the interface for creating and managing these 3D borders.

The procedure Tk_Fill3DRectangle fills the rectangular area specified by x, y, width, height. It first fills the rectangular area with the background color (one corresponding to the color used to create border). Then it calls Tk_Draw3DRectangle to draw a border just inside the outer edge of the rectangular area. The argument relief indicates the desired effect (TK_RELIEF_FLAT means no border should be drawn; all that happens is to fill the rectangle with the background color).

The procedure Tk_Draw3DPolygon may be used to draw more complex shapes with a three-dimensional appearance. The pointPtr and numPoints arguments define a trajectory, polyBorderWidth indicates how wide the border should be (and on which side of the trajectory to draw it), and leftRelief indicates which side of the trajectory should appear raised. Tk_Draw3DPolygon draws a border around the given trajectory using the colors from border to produce a three-dimensional appearance. If the trajectory is non-self-intersecting, the appearance will be a raised or sunken polygon shape. The trajectory may be self-intersecting, although it's not clear how useful this is.

Tk_Fill3DPolygon is to Tk_Draw3DPolygon what Tk_Fill3DRectangle is to Tk_Draw3DRectangle: it fills the polygonal area with the background color from border, then calls Tk_Draw3DPolygon to draw a border around the area (unless leftRelief is TK_RELIEF_FLAT; in this case no border is drawn).

The procedures Tk_3DVerticalBevel and Tk_3DHorizontalBevel provide lower-level drawing primitives that are used by procedures such as Tk_Draw3DRectangle. These procedures are also useful in their own right for drawing rectilinear border shapes. Tk_3DVerticalBevel draws a vertical beveled edge, such as the left or right side of a rectangle, and Tk_3DHorizontalBevel draws a horizontal beveled edge, such as the top or bottom of a rectangle. Each procedure takes x, y, width, and height arguments that describe the rectangular area of the beveled edge (e.g., width is the border width for Tk_3DVerticalBevel). The leftBorder and topBorder arguments indicate the position of the border relative to the “inside” of the value, and relief indicates the relief of the inside of the value relative to the outside. Tk_3DVerticalBevel just draws a rectangular region. Tk_3DHorizontalBevel draws a trapezoidal region to generate mitered corners; it should be called after Tk_3DVerticalBevel (otherwise Tk_3DVerticalBevel will overwrite the mitering in the corner). The leftIn and rightIn arguments to Tk_3DHorizontalBevel describe the mitering at the corners; a value of 1 means that the bottom edge of the trapezoid will be shorter than the top, 0 means it will be longer. For example, to draw a rectangular border the top bevel should be drawn with 1 for both leftIn and rightIn, and the bottom bevel should be drawn with 0 for both arguments.

The procedure Tk_SetBackgroundFromBorder will modify the background pixel and/or pixmap of tkwin to produce a result compatible with border. For color displays, the resulting background will just be the color specified when border was created; for monochrome displays, the resulting background will be a light stipple pattern, in order to distinguish the background from the illuminated portion of the border.

Given a token for a border, the procedure Tk_NameOf3DBorder will return the color name that was used to create the border.

The procedure Tk_3DBorderColor returns the XColor structure that will be used for flat surfaces drawn for its border argument by procedures like Tk_Fill3DRectangle. The return value corresponds to the color name that was used to create the border. The XColor, and its associated pixel value, will remain allocated as long as border exists.

The procedure Tk_3DBorderGC returns one of the X graphics contexts that are used to draw the border. The argument which selects which one of the three possible GC's: TK_3D_FLAT_GC returns the context used for flat surfaces, TK_3D_LIGHT_GC returns the context for light shadows, and TK_3D_DARK_GC returns the context for dark shadows.

When a border is no longer needed, Tk_Free3DBorderFromObj or Tk_Free3DBorder should be called to release the resources associated with it. For Tk_Free3DBorderFromObj the border to release is specified with the window and color name used to create the border; for Tk_Free3DBorder the border to release is specified with the Tk_3DBorder token for the border. There should be exactly one call to Tk_Free3DBorderFromObj or Tk_Free3DBorder for each call to Tk_Alloc3DBorderFromObj or Tk_Get3DBorder.
