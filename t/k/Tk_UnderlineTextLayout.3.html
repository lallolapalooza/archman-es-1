ARGUMENTOS

Tk_Font tkfont (entrada)
Fuente a usar al construir y mostrar un diseño de texto. El tkfont debe permanecer válido durante la vida útil del diseño de texto. Debe haber sido devuelto por una llamada previa a Tk_GetFont.
const char *string (entrada)
Cadena potencialmente multilínea cuyas dimensiones se van a calcular y almacenar en el diseño de texto. El string debe permanecer válido durante la vida útil del diseño de texto.
int numChars (entrada)
El número de caracteres a considerar de string. Si numChars es menor que 0, asume que string termina en nulo y utiliza Tcl_NumUtfChars para determinar la longitud de string.
int wrapLength (entrada)
Longitud máxima permitida de línea, en píxeles. Las líneas en string se dividirán automáticamente en los límites de palabras y se ajustarán cuando alcancen esta longitud. Si wrapLength es demasiado pequeño incluso para que un solo carácter quepa en una línea, se expandirá para permitir que un carácter quepa en cada línea. Si wrapLength es <= 0, no hay ajuste de línea automático; las líneas se harán tan largas como necesiten y solo se ajustarán si se encuentra un carácter de nueva línea / retorno.
Tk_Justify justify (entrada)
Cómo justificar las líneas en un diseño de texto multilínea. Los valores posibles son TK_JUSTIFY_LEFT, TK_JUSTIFY_CENTER o TK_JUSTIFY_RIGHT. Si el diseño de texto solo ocupa una sola línea, entonces justify es irrelevante.
int flags (entrada)
Varios bits de bandera OR-eados juntos. TK_IGNORE_TABS significa que los caracteres de tabulación no deben expandirse a la siguiente parada de tabulación. TK_IGNORE_NEWLINES significa que los caracteres de nueva línea / retorno no deben causar un salto de línea. Si se ignoran las tabulaciones o las nuevas líneas / retornos, se tratarán como caracteres regulares, midiéndose y mostrándose de manera dependiente de la plataforma, como se describe en Tk_MeasureChars, y no tendrán ningún comportamiento especial.
int *widthPtr (salida)
Si no es NULL, se llena con el ancho, en píxeles, de la línea más ancha en el diseño de texto, o el ancho, en píxeles, del cuadro delimitador para el carácter especificado por index.
int *heightPtr (salida)
Si no es NULL, se llena con la altura total, en píxeles, de todas las líneas en el diseño de texto, o la altura, en píxeles, del cuadro delimitador para el carácter especificado por index.
Tk_TextLayout layout (entrada)
Un token que representa la información de diseño almacenada en caché sobre la pieza de texto justificada, multilínea y de una sola fuente. Este token es devuelto por Tk_ComputeTextLayout.
Display *display (entrada)
Pantalla en la que dibujar.
Drawable drawable (entrada)
Ventana o mapa de bits en el que dibujar.
GC gc (entrada)
Contexto gráfico a utilizar para dibujar el diseño de texto. La fuente seleccionada en este GC debe corresponder al tkfont utilizado al construir el diseño de texto.
int x, y (entrada)
Punto, en píxeles, en el que colocar la esquina superior izquierda del diseño de texto cuando se está dibujando, o las coordenadas de un punto (con respecto a la esquina superior izquierda del diseño de texto) para verificar contra el diseño de texto.
int firstChar (entrada)
El índice del primer carácter a dibujar del diseño de texto dado. El número 0 significa dibujar desde el principio.
int lastChar (entrada)
El índice del último carácter hasta el cual dibujar. El carácter especificado por lastChar en sí mismo no se dibujará. Un número menor que 0 significa dibujar todos los caracteres en el diseño de texto.
int underline (entrada)
Índice del único carácter a subrayar en el diseño de texto, o un número menor que 0 para no subrayar.
int index (entrada)
El índice del carácter cuyo cuadro delimitador se desea. El cuadro delimitador se calcula con respecto a la esquina superior izquierda del diseño de texto.
int *xPtr, *yPtr (salida)
Se llena con la esquina superior izquierda, en píxeles, del cuadro delimitador para el carácter especificado por index. xPtr y/o yPtr pueden ser NULL, en cuyo caso el valor correspondiente no se calcula.
int width, height (entrada)
Especifica el ancho y la altura, en píxeles, del área rectangular a comparar para intersección contra el diseño de texto.
Tcl_Interp *interp (salida)
El código Postscript que imprimirá el diseño de texto se anexa al resultado del intérprete interp.

DESCRIPCIÓN

Estas rutinas son para medir y mostrar texto justificado, multilínea y de una sola fuente. Para medir y mostrar cadenas simples de una sola fuente y una sola línea, consulte la documentación de Tk_MeasureChars. No existe una interfaz de programación en el núcleo de Tk que admita texto multilínea y con múltiples fuentes; el soporte para ese comportamiento debe construirse sobre capas más simples. Tenga en cuenta que, a diferencia de las rutinas de visualización de texto de nivel inferior, las funciones descritas aquí operan sobre longitudes e índices orientados a caracteres en lugar de valores orientados a bytes. Consulte la descripción de Tcl_UtfAtIndex para obtener más detalles sobre la conversión entre desplazamientos de caracteres y bytes.

Las rutinas descritas aquí se basan en la interfaz de programación descrita en la documentación de Tk_MeasureChars. Los caracteres de tabulación y los caracteres de nueva línea / retorno pueden ser tratados especialmente por estos procedimientos, pero todos los demás caracteres se pasan al nivel inferior.

Tk_ComputeTextLayout calcula la información de diseño necesaria para mostrar una cadena de texto justificada, multilínea y de una sola fuente, y devuelve un token Tk_TextLayout que contiene esta información. Este token se utiliza en llamadas posteriores a procedimientos como Tk_DrawTextLayout, Tk_DistanceToTextLayout y Tk_FreeTextLayout. El string y el tkfont utilizados al calcular el diseño deben permanecer válidos durante la vida útil de este token.

Tk_FreeTextLayout se llama para liberar el almacenamiento asociado con layout cuando ya no se necesita. Un layout no debe utilizarse en ningún otro procedimiento de diseño de texto una vez que haya sido liberado.

Tk_DrawTextLayout utiliza la información en layout para mostrar una cadena de texto justificada, multilínea y de una sola fuente en la ubicación especificada.

Tk_UnderlineTextLayout utiliza la información en layout para mostrar un subrayado debajo de un carácter individual. Este procedimiento no dibuja el texto, solo el subrayado. Para producir texto subrayado nativamente, se debe construir y utilizar una fuente subrayada. Todos los caracteres, incluidas las tabulaciones, los caracteres de nueva línea/retorno y los espacios al final de las líneas, se pueden subrayar utilizando este método. Sin embargo, el subrayado nunca se dibujará fuera del ancho calculado de layout; el subrayado se detendrá en el borde para cualquier carácter que se extienda parcialmente fuera de layout, y el subrayado no será visible en absoluto para ningún carácter que se encuentre completamente fuera del diseño.

Tk_PointToChar utiliza la información en layout para determinar el carácter más cercano al punto dado. El punto se especifica con respecto a la esquina superior izquierda de layout, que se considera ubicada en (0, 0). Cualquier punto cuyo valor y sea menor que 0 se considerará más cercano al primer carácter en el diseño de texto; cualquier punto cuyo valor y sea mayor que la altura del diseño de texto se considerará más cercano al último carácter en el diseño de texto. NAME

Tk_UnderlineTextLayout, Tk_CharBbox, Tk_DistanceToTextLayout, Tk_IntersectTextLayout, Tk_TextLayoutToPostscript - compute properties of text layout

SYNOPSIS

#include <tkText.h>
int
Tk_UnderlineTextLayout(layout, x, y, index, charInfoPtr)
int
Tk_CharBbox(layout, index, xPtr, yPtr, widthPtr, heightPtr)
int
Tk_DistanceToTextLayout(layout, x, y)
int
Tk_IntersectTextLayout(layout, x, y, width, height)

Tk_TextLayoutToPostscript(interp, layout)

ARGUMENTS

Tk_TextLayout layout      (in) Text layout object.
int x                     (in) X-coordinate of point.
int y                     (in) Y-coordinate of point.
int index                 (in) Index of character or insertion point.
Tk_TextLayoutCharInfo *charInfoPtr
                          (out) Structure to store character information.
int *xPtr                 (out) Pointer to store X coordinate of bounding box.
int *yPtr                 (out) Pointer to store Y coordinate of bounding box.
int *widthPtr             (out) Pointer to store width of bounding box.
int *heightPtr            (out) Pointer to store height of bounding box.
Tcl_Interp *interp        (in) Interpreter to store Postscript output in.
int width                 (in) Width of rectangle.
int height                (in) Height of rectangle.

DESCRIPTION

These functions provide access to the properties of a text layout object created by Tk_ComputeTextLayout.

Tk_UnderlineTextLayout computes information about the underline for the character or insertion point specified by index in the text layout layout. If the character specified by index is to be underlined, then charInfoPtr will be filled with the position and extent of the underline. Otherwise, the underline information is left unmodified. A non-zero return value indicates that the character at index is to be underlined, while a zero return value indicates that it is not. The x and y coordinates specify a point to aid in determining where the insertion point is relative to the text layout.

If a point has an x-value less than 0, it will be considered closest to the first character on that line; any point whose x-value is greater than the width of the text layout will be considered closest to the last character on that line. The return value is the index of the character that was closest to the point, or one more than the index of any character (to indicate that the point was after the end of the string and that the corresponding caret would be at the end of the string). Given a layout with no characters, the value 0 will always be returned, referring to a hypothetical zero-width placeholder character.

Tk_CharBbox uses the information in layout to return the bounding box for the character specified by index. The width of the bounding box is the advance width of the character, and does not include any left or right bearing. Any character that extends partially outside of layout is considered to be truncated at the edge. Any character that would be located completely outside of layout is considered to be zero-width and pegged against the edge. The height of the bounding box is the line height for this font, extending from the top of the ascent to the bottom of the descent; information about the actual height of individual letters is not available. For measurement purposes, a layout that contains no characters is considered to contain a single zero-width placeholder character at index 0. If index was not a valid character index, the return value is 0 and *xPtr, *yPtr, *widthPtr, and *heightPtr are unmodified. Otherwise, if index did specify a valid, the return value is non-zero, and *xPtr, *yPtr, *widthPtr, and *heightPtr are filled with the bounding box information for the character. If any of xPtr, yPtr, widthPtr, or heightPtr are NULL, the corresponding value is not calculated or stored.

Tk_DistanceToTextLayout computes the shortest distance in pixels from the given point (x, y) to the characters in layout. Newline/return characters and non-displaying space characters that occur at the end of individual lines in the text layout are ignored for hit detection purposes, but tab characters are not. The return value is 0 if the point actually hits the layout. If the point did not hit the layout then the return value is the distance in pixels from the point to the layout.

Tk_IntersectTextLayout determines whether a layout lies entirely inside, entirely outside, or overlaps a given rectangle. Newline/return characters and non-displaying space characters that occur at the end of individual lines in the layout are ignored for intersection calculations. The return value is -1 if the layout is entirely outside of the rectangle, 0 if it overlaps, and 1 if it is entirely inside of the rectangle.

Tk_TextLayoutToPostscript outputs code consisting of a Postscript array of strings that represent the individual lines in layout. It is the responsibility of the caller to take the Postscript array of strings and add some Postscript function operate on the array to render each of the lines. The code that represents the Postscript array of strings is appended to interpreter interp's result.

DISPLAY MODEL

When measuring a text layout, space characters that occur at the end of a line are ignored. The space characters still exist and the insertion point can be positioned amongst them, but their additional width is ignored when justifying lines or returning the total width of a text layout. All end-of-line space characters are considered to be attached to the right edge of the line; this behavior is logical for left-justified text and reasonable for center-justified text, but not very useful when editing right-justified text. Spaces are considered variable width characters; the first space that extends past the edge of the text layout is clipped to the edge, and any subsequent spaces on the line are considered zero width and pegged against the edge. Space characters that occur in the middle of a line of text are not suppressed and occupy their normal space width.

Tab characters are not ignored for measurement calculations. If wrapping is turned on and there are enough tabs on a line, the next tab will wrap to the beginning of the next line. There are some possible strange interactions between tabs and justification; tab positions are calculated and the line length computed in a left-justified world, and then the whole resulting line is shifted so it is centered or right-justified, causing the tab columns not to align any more.

When wrapping is turned on, lines may wrap at word breaks (space or tab characters) or newline/returns. A dash or hyphen character in the middle of a word is not considered a word break. Tk_ComputeTextLayout always attempts to place at least one word on each line. If it cannot because the wrapLength is too small, the word will be broken and as much as fits placed on the line and the rest on subsequent line(s). If wrapLength is so small that not even one character can fit on a given line, the wrapLength is ignored for that line and one character will be placed on the line anyhow. When wrapping is turned off, only newline/return characters may cause a line break.

When a text layout has been created using an underlined tkfont, then any space characters that occur at the end of individual lines, newlines/returns, and tabs will not be displayed underlined when Tk_DrawTextLayout is called, because those characters are never actually drawn - they are merely placeholders maintained in the layout.
