NOMBRE

Tk::Wm - Comunicarse con el gestor de ventanas

SINOPSIS

    $toplevel->método(?argumentos?)

DESCRIPCIÓN

Los métodos wm se utilizan para interactuar con los gestores de ventanas con el fin de controlar aspectos como el título de una ventana, su geometría o los incrementos en términos de los cuales puede ser redimensionada. Los métodos wm pueden tomar cualquiera de un número de formas diferentes, dependiendo del argumento método particular. Todas las formas esperan $toplevel, que debe ser un objeto de ventana de nivel superior.

Las formas legales para los métodos wm son:

$toplevel->aspect(?minNumer minDenom maxNumer maxDenom?)
Si se especifican minNumer, minDenom, maxNumer y maxDenom, se pasarán al gestor de ventanas y este debería usarlos para forzar un rango de relaciones de aspecto aceptables para $toplevel. La relación de aspecto de $toplevel (ancho/largo) se restringirá a estar entre minNumer/minDenom y maxNumer/maxDenom. Si minNumer, etc., se especifican como cadenas vacías, se eliminan las restricciones de relación de aspecto existentes. Si se especifican minNumer, etc., el método devuelve una cadena vacía. De lo contrario, devuelve una matriz que contiene cuatro elementos, que son los valores actuales de minNumer, minDenom, maxNumer y maxDenom (si no hay restricciones de aspecto en vigor, se devuelve una cadena vacía).
$widget->attributes( ?argumentos? );
Este subcomando devuelve o establece atributos específicos de la plataforma asociados con una ventana.
$widget->attributes;
Devuelve una lista de las banderas específicas de la plataforma y sus valores.
$widget->attributes( ?opción? );
Devuelve el valor para la opción específica.
$widget->attributes( ?opción valor opción valor...? );
Establece uno o más de los valores. Los valores son los siguientes:

En Windows, -disabled obtiene o establece si la ventana está en un estado deshabilitado. -toolwindow obtiene o establece el estilo de la ventana como ventana de herramientas (según se define en MSDN). -topmost obtiene o establece si esta es una ventana principal (se muestra sobre todas las demás ventanas).

En Macintosh, actualmente no hay valores de atributo especiales.

En Unix, actualmente no hay valores de atributo especiales.

$toplevel->client(?nombre?)
Si se especifica nombre, este método almacena nombre (que debería ser el nombre del host en el que se está ejecutando la aplicación) en la propiedad WM_CLIENT_MACHINE de $toplevel para su uso por el gestor de ventanas o el gestor de sesiones. El método devuelve una cadena vacía en este caso. Si no se especifica nombre, el método devuelve el último nombre establecido en un método client para $toplevel. Si se especifica nombre como una cadena vacía, el método elimina la propiedad WM_CLIENT_MACHINE de $toplevel.
$toplevel->colormapwindows(?windowList?)
Este método se utiliza para manipular la propiedad WM_COLORMAP_WINDOWS, que proporciona información a los gestores de ventanas sobre ventanas que tienen mapas de color privados. Si no se especifica windowList, el método devuelve una lista cuyos elementos son los nombres de las ventanas en la propiedad WM_COLORMAP_WINDOWS. Si se especifica windowList, consta de una lista de widgets; el método sobrescribe la propiedad WM_COLORMAP_WINDOWS con las ventanas dadas y devuelve una cadena vacía. La propiedad WM_COLORMAP_WINDOWS normalmente debería contener una lista de las ventanas internas dentro de $toplevel cuyos mapas de color difieren de sus padres. El orden de las ventanas en la propiedad indica un orden de prioridad: el gestor de ventanas intentará instalar tantos mapas de color como sea posible desde el principio de esta lista cuando $widget obtenga el foco del mapa de color. Si $widget no está incluido entre las ventanas de windowList, Tk lo agrega implícitamente al final de la propiedad WM_COLORMAP_WINDOWS, de modo que su mapa de color tenga la menor prioridad. Si no se invoca $widget->colormapwindows, Tk establecerá automáticamente la propiedad para cada ventana de nivel superior a todas las ventanas internas cuyos mapas de color difieren de sus padres, seguido de la propia ventana de nivel superior; el orden de las ventanas internas no está definido. Consulte la documentación de ICCCM para obtener más información sobre la propiedad WM_COLORMAP_WINDOWS.
$toplevel->command(?valor?)
Si se especifica valor, este método almacena valor en la propiedad WM_COMMAND de $toplevel para su uso por el gestor de ventanas o el gestor de sesiones y devuelve una cadena vacía. Valor debe tener una estructura de lista adecuada; los elementos deben contener las palabras del comando utilizado para invocar la aplicación. Si no se especifica valor, el método devuelve el último valor establecido en un método command para $toplevel. Si se especifica valor como una cadena vacía, el método elimina la propiedad WM_COMMAND de $toplevel.
$toplevel->deiconify
Organiza para que $toplevel se muestre en forma normal (no iconificada). Esto se hace mapeando la ventana. Si la ventana nunca se ha mapeado, este método no la mapeará, pero se asegurará de que cuando la ventana se mapee por primera vez, se muestre en forma no iconificada. Devuelve una cadena vacía.
$toplevel->focusmodel(?active|passive?)
Si se proporciona active o passive como argumento opcional al método, especifica el modelo de enfoque para $toplevel. En este caso, el método devuelve una cadena vacía. Si no se proporciona ningún argumento adicional, el método devuelve el modelo de enfoque actual para $toplevel. Un modelo de enfoque active significa que $toplevel reclamará el enfoque de entrada para sí mismo o sus descendientes, incluso en momentos en que el enfoque esté actualmente en alguna otra aplicación. Passive significa que $toplevel nunca reclamará el enfoque para sí mismo: el gestor de ventanas debería dar el enfoque a $toplevel en los momentos apropiados. Sin embargo, una vez que el enfoque se ha dado a $toplevel o a uno de sus descendientes, la aplicación puede reasignar el enfoque entre los descendientes de $toplevel. El modelo de enfoque por defecto es passive, y el método focus de Tk asume un modelo de enfoque pasivo.
$toplevel->frame
Si el gestor de ventanas ha reparentado a $widget en un marco decorativo, el método devuelve el identificador de ventana específico de la plataforma para el marco más externo que contiene a $toplevel (la ventana cuyo padre es la raíz o la raíz virtual). Si el gestor de ventanas no ha reparentado a $toplevel, el método devuelve el identificador de ventana específico de la plataforma para $toplevel.

Si se especifica newGeometry, se cambia la geometría de $toplevel y se devuelve una cadena vacía. De lo contrario, se devuelve la geometría actual para $toplevel (esta es la geometría más reciente especificada ya sea por redimensionamiento manual o en un método geometry). $toplevel->wmGrid(?baseWidth,baseHeight,widthInc,heightInc?)
Este método indica que $toplevel se gestionará como una ventana en cuadrícula. También especifica la relación entre las unidades de cuadrícula y las unidades de píxel. baseWidth y baseHeight especifican el número de unidades de cuadrícula correspondientes a las dimensiones de píxel solicitadas internamente por $toplevel usando Tk_GeometryRequest. widthInc y heightInc especifican el número de píxeles en cada unidad de cuadrícula horizontal y vertical. Estos cuatro valores determinan un rango de tamaños aceptables para $toplevel, correspondiente a anchos y altos basados en cuadrícula que son enteros no negativos. Tk pasará esta información al gestor de ventanas; durante el redimensionamiento manual, el gestor de ventanas restringirá el tamaño de la ventana a uno de estos tamaños aceptables. Además, durante el redimensionamiento manual, el gestor de ventanas mostrará el tamaño actual de la ventana en términos de unidades de cuadrícula en lugar de píxeles. Si baseWidth, etc., se especifican como cadenas vacías, entonces $toplevel dejará de ser gestionado como una ventana en cuadrícula. Si se especifican baseWidth, etc., el valor de retorno es una cadena vacía. De lo contrario, el valor de retorno es un array que contiene cuatro elementos correspondientes a baseWidth, baseHeight, widthInc, y heightInc actuales; si $toplevel no está actualmente en cuadrícula, entonces se devuelve una cadena vacía. Nota: este comando no debería ser necesario muy a menudo, ya que el procedimiento de biblioteca Tk_SetGrid y la opción -setgrid proporcionan un acceso más fácil a la misma funcionalidad.
$toplevel->group(?$widget?)
Si se especifica $widget, es el líder de un grupo de ventanas relacionadas. El gestor de ventanas puede usar esta información, por ejemplo, para desmapear todas las ventanas de un grupo cuando se iconeiza el líder del grupo. $widget puede especificarse como una cadena vacía para eliminar $toplevel de cualquier asociación de grupo. Si se especifica $widget entonces el método devuelve una cadena vacía; de lo contrario, devuelve el líder del grupo actual de $toplevel, o una cadena vacía si $toplevel no forma parte de ningún grupo.
$toplevel->iconbitmap(?bitmap?)
Si se especifica bitmap, entonces nombra un mapa de bits en los formularios estándar aceptados por Tk (ver la documentación de Tk_GetBitmap para detalles). Este mapa de bits **en blanco y negro** se pasa al gestor de ventanas para que se muestre en el icono de $toplevel, y el método devuelve una cadena vacía. Si se especifica una cadena vacía para bitmap, entonces se cancela cualquier mapa de bits o imagen de icono actual para $toplevel. Si se especifica bitmap entonces el método devuelve una cadena vacía. De lo contrario, devuelve el nombre del mapa de bits de icono actual asociado con $toplevel, o una cadena vacía si $toplevel no tiene mapa de bits de icono.
$toplevel->iconify
Organizar para que $toplevel se icone. Si $toplevel aún no se ha mapeado por primera vez, este método organizará para que aparezca en el estado iconeado cuando finalmente se mapee.
$toplevel->iconimage(?image?)
Si se especifica image, entonces nombra una imagen Tk normal. Esta imagen se renderiza en un mapa de bits privado **en color** que se pasa al gestor de ventanas para que se muestre en el icono de $toplevel, y el método devuelve una cadena vacía. Si se especifica una cadena vacía para image, entonces se cancela cualquier mapa de bits o imagen de icono actual para $toplevel. Si se especifica image entonces el método devuelve una cadena vacía. De lo contrario, devuelve el nombre de la imagen de icono actual asociada con $toplevel, o una cadena vacía si $toplevel no tiene imagen de icono. El pixmap privado no se borra previamente, por lo que las imágenes que son parcialmente "transparentes" muestran basura en sus partes transparentes.

Los tamaños de las imágenes que se pueden usar como iconos de esta manera son dependientes de la plataforma. En Win32 esto establece el icono "grande", que debe ser de 32x32, se escalará automáticamente a 16x16 para su uso como icono pequeño.

$toplevel->iconmask(?bitmap?)
Si se especifica bitmap, entonces nombra un mapa de bits en los formularios estándar aceptados por Tk (ver la documentación de Tk_GetBitmap para detalles). Este mapa de bits se pasa al gestor de ventanas para que se use como máscara en conjunción con la opción iconbitmap: donde la máscara tiene ceros no se mostrará ningún icono; donde tiene unos, se mostrarán los bits del mapa de bits del icono. Si se especifica una cadena vacía para bitmap entonces se cancela cualquier máscara de icono actual para $toplevel (esto es equivalente a especificar un mapa de bits de todos unos). Si se especifica bitmap entonces el método devuelve una cadena vacía. De lo contrario, devuelve el nombre de la máscara de icono actual asociada con $toplevel, o una cadena vacía si no hay ninguna máscara activa.
$toplevel->iconname(?newName?)
Si se especifica newName, entonces se pasa al gestor de ventanas; el gestor de ventanas debería mostrar newName dentro del icono asociado con $toplevel. En este caso se devuelve una cadena vacía como resultado. Si newName no se especifica entonces el método devuelve el nombre de icono actual para $toplevel, o una cadena vacía si no se ha especificado ningún nombre de icono (en este caso el gestor de ventanas normalmente mostrará el título de la ventana, como se especifica con el método title).
$toplevel->iconphoto(?-default? image1 ?image2 ...?)
Establece el icono de la barra de título para la ventana basándose en las imágenes fotográficas nombradas. Si se especifica -default, esto se aplica también a todas las futuras ventanas de nivel superior creadas. Los datos de las imágenes se toman como una instantánea en el momento de la invocación. Si las imágenes se cambian posteriormente, esto no se refleja en los iconos de la barra de título. Se aceptan múltiples imágenes para permitir diferentes tamaños de imágenes (por ejemplo, 16x16 y 32x32). El gestor de ventanas puede escalar los iconos proporcionados a un tamaño apropiado.

En Windows, las imágenes se empaquetan en una estructura de icono de Windows. Esto anulará un icono especificado a wm iconbitmap, y viceversa. [NOTA: ¡Esto aún no está implementado!]

En X, las imágenes se organizan en la propiedad X _NET_WM_ICON, que la mayoría de los gestores de ventanas modernos soportan. Puede existir un wm iconbitmap simultáneamente. Se recomienda usar no más de 2 iconos, colocando el icono más grande primero.

En Macintosh, esto actualmente no hace nada.

$toplevel->iconposition(?x y?)
Si se especifican x e y, se pasan al gestor de ventanas como una pista sobre dónde posicionar el icono para $toplevel. En este caso se devuelve una cadena vacía. Si se especifican x e y como cadenas vacías entonces se cancela cualquier pista de posición de icono existente. Si no se especifica ni x ni y, entonces el método devuelve un array que contiene dos valores, que son las pistas de posición de icono actuales (si no hay pistas activas entonces se devuelve una cadena vacía).

DESCRIPCIÓN

Esta clase proporciona métodos para controlar el comportamiento de la ventana de nivel superior de un widget de Tk, como su título, tamaño, posición y el comportamiento del gestor de ventanas.

$widget->title(string)
Establece el título de la ventana. El título se muestra en la barra de título de la ventana (si el gestor de ventanas proporciona una). Si se invoca sin argumentos, devuelve el título actual de la ventana.
$widget->transients(parentWindow)
Marca la ventana como transitoria con respecto a parentWindow. Las ventanas transitorias suelen ser ventanas emergentes o diálogos que dependen de una ventana principal. El gestor de ventanas puede tratar las ventanas transitorias de forma diferente a las ventanas normales (por ejemplo, no ponerles un icono o no permitirles moverse independientemente de su ventana principal).
$widget->geometry(geometryString)
Establece la geometría (tamaño y posición) de la ventana. El geometryString tiene el formato estándar de Tk, por ejemplo, "800x600+100+50" significa 800 píxeles de ancho, 600 de alto, posicionado a 100 píxeles del borde izquierdo de la pantalla y 50 píxeles del borde superior. Si se invoca sin argumentos, devuelve la geometría actual de la ventana.
$widget->position(x y)
Establece la posición de la esquina superior izquierda de la ventana en las coordenadas de pantalla (x, y).
$widget->size(width height)
Establece el tamaño de la ventana a width x height píxeles.
$widget->minsize(width height)
Establece el tamaño mínimo permitido para la ventana a width x height píxeles. El gestor de ventanas no permitirá que la ventana se redimensione a un tamaño menor que este.
$widget->maxsize(width height)
Establece el tamaño máximo permitido para la ventana a width x height píxeles. El gestor de ventanas no permitirá que la ventana se redimensione a un tamaño mayor que este.
$widget->resizable(booleanX booleanY)
Controla si la ventana se puede redimensionar interactivamente en las dimensiones X e Y. Los valores booleanos pueden ser 0 (no redimensionable) o 1 (redimensionable).
$widget->iconify()
Minimiza la ventana a un icono. El aspecto del icono lo determina el gestor de ventanas y las opciones de configuración de iconos de Tk.
$widget->deiconify()
Restaura la ventana desde su estado minimizado a su tamaño y posición anteriores.
$widget->withdraw()
Oculta la ventana, como si estuviera minimizada, pero sin mostrar un icono. La ventana todavía existe y puede ser restaurada con deiconify.
$widget->state(state)
Establece el estado de la ventana. Los estados posibles son "normal", "iconic" (minimizada) y "withdrawn" (oculta). Si se llama sin argumento, devuelve el estado actual de la ventana.
$widget->clientwindow()
Devuelve el identificador de la ventana de cliente, que es la ventana dentro de la ventana de nivel superior donde se colocan los widgets de Tk. Esto es útil para incrustar otras aplicaciones o para interactuar con herramientas de nivel inferior.
$widget->frame()
Devuelve el identificador de la ventana del marco que contiene la ventana de nivel superior. Esta es la ventana que el gestor de ventanas conoce y gestiona directamente. Se pueden añadir propiedades X a esta ventana.
$widget->iconbitmap(bitmap_file)
Establece el bitmap que se utilizará como icono para la ventana cuando se minimice. bitmap_file es el nombre de un archivo de bitmap.
$widget->iconimage(imageObject)
Establece la imagen que se utilizará como icono para la ventana cuando se minimice. imageObject es un objeto de imagen de Tk.
$widget->iconposition(x y)
Establece la posición deseada del icono cuando la ventana se minimiza.
$widget->iconwindow(windowObject)
Establece una ventana existente que se utilizará como icono. Esto permite crear iconos animados o más complejos.
$widget->aspect(x y)
Establece la relación de aspecto de la ventana. Tk intentará mantener esta relación de aspecto al redimensionar la ventana. Por ejemplo, $widget->aspect(1 1) haría que la ventana fuera cuadrada.
$widget->mwm(option value ...)
Establece opciones específicas del gestor de ventanas Motif (mwm). Esto se utiliza raramente en aplicaciones Tk modernas.
$widget->wmgrid(x y)
Establece las unidades de rejilla para la gestión de geometría. Cuando se activa la gestión de rejilla, el tamaño de la ventana se expresa en unidades de rejilla en lugar de píxeles. Esto es útil para aplicaciones como editores de texto donde el tamaño en líneas y caracteres es más importante que el tamaño en píxeles.

ICON SIZES

Los tamaños de los bitmaps/imágenes que se pueden utilizar como iconos de esta manera dependen de la plataforma y del gestor de ventanas. Los gestores de ventanas de Unix suelen ser más tolerantes que Win32. Es posible que los iconos de "iconimage" en color causen problemas en algunos gestores de ventanas X.

    "iconimage" y "iconbitmap" establecen el icono "grande", que debería ser de 32x32, se escalará automáticamente a 16x16 para usarlo como icono pequeño. Win32 ignora las solicitudes "iconwin".

  • "kwm" de KDE

    Acepta "iconimage" en color y "iconbitmap" en blanco y negro, pero escalará cualquiera de ellos a un icono pequeño (¿14x14?). Kwm ignora "iconwin".

  • "olwm" u "olvwm" de Sun

    Respeta "iconwin", que anulará "iconimage" o "iconbitmap". Las imágenes en color funcionan.

GEOMETRY MANAGEMENT

Por defecto, una ventana de nivel superior aparece en la pantalla en su tamaño natural, que es el determinado internamente por sus widgets y gestores de geometría. Si el tamaño natural de una ventana de nivel superior cambia, el tamaño de la ventana cambia para coincidir. A una ventana de nivel superior se le puede dar un tamaño distinto a su tamaño natural de dos maneras. Primero, el usuario puede redimensionar la ventana manualmente utilizando las funciones del gestor de ventanas, como los manejadores de redimensionamiento. Segundo, la aplicación puede solicitar un tamaño particular para una ventana de nivel superior utilizando el método geometry. Estos dos casos son manejados idénticamente por Tk; en cualquiera de los casos, el tamaño solicitado anula el tamaño natural. Se puede devolver la ventana a su tamaño natural invocando geometry con una cadena de geometría vacía.

Normalmente, una ventana de nivel superior puede tener cualquier tamaño, desde un píxel en cada dimensión hasta el tamaño de su pantalla. Sin embargo, se pueden utilizar los métodos minsize y maxsize para limitar el rango de tamaños permitidos. El rango establecido por minsize y maxsize se aplica a todas las formas de redimensionamiento, incluido el tamaño natural de la ventana, así como los redimensionamientos manuales y el método geometry. También se puede utilizar el método resizable para deshabilitar completamente el redimensionamiento interactivo en una o ambas dimensiones.

GRIDDED GEOMETRY MANAGEMENT

La gestión de geometría en rejilla ocurre cuando uno de los widgets de una aplicación admite un rango de tamaños útiles. Esto ocurre, por ejemplo, en un editor de texto donde las barras de desplazamiento, los menús y otros adornos tienen un tamaño fijo, pero el widget de edición puede admitir cualquier número de líneas de texto o caracteres por línea. En este caso, generalmente es deseable permitir al usuario especificar el número de líneas o caracteres por línea, ya sea con el método geometry o redimensionando interactivamente la ventana. En el caso del texto, y en otros casos interesantes también, solo los tamaños discretos de la ventana tienen sentido, como números enteros de líneas y caracteres por línea; los tamaños arbitrarios de píxeles no son útiles.

La gestión de geometría en rejilla proporciona soporte para este tipo de aplicación. Tk (y el gestor de ventanas) asumen que hay una rejilla de algún tipo dentro de la aplicación y que la aplicación debe redimensionarse en términos de unidades de rejilla en lugar de píxeles. La gestión de geometría en rejilla se invoca típicamente activando la opción setGrid para un widget; también se puede invocar con el método wmGrid o llamando a Tk_SetGrid. En cada uno de estos enfoques, el widget particular (o a veces el código en la aplicación en su conjunto) especifica la relación entre los tamaños enteros de rejilla para la ventana y los tamaños de píxeles. Para volver a la gestión de geometría no en rejilla, invoque grid con cadenas de argumentos vacías.

Cuando la gestión de geometría en rejilla está habilitada, todas las dimensiones especificadas en los métodos minsize, maxsize y geometry se tratan como unidades de rejilla en lugar de unidades de píxeles. El redimensionamiento interactivo también se realiza en números pares de unidades de rejilla en lugar de píxeles.

BUGS

La mayoría de los gestores de ventanas existentes parecen tener errores que afectan la operación de los métodos wm. Por ejemplo, algunos cambios no tendrán efecto si la ventana ya está activa: la ventana tendrá que retirarse y des-iconificarse para que el cambio ocurra.
