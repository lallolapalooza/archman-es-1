NOMBRE

Tk::Photo - Imágenes a todo color

SINOPSIS

    $widget->Photo(?nombre??, opciones?)

DESCRIPCIÓN

Una foto es una imagen cuyos píxeles pueden mostrar cualquier color o ser transparentes. Una imagen de foto se almacena internamente a todo color (32 bits por píxel) y se muestra utilizando tramado (dithering) si es necesario. Los datos de imagen para una imagen de foto se pueden obtener de un archivo o una cadena de texto, o se pueden suministrar desde código C a través de una interfaz procedimental. Actualmente, solo se admiten los formatos GIF, XBM, XPM, BMP, JPEG, PNG y PPM/PGM, pero existe una interfaz que permite agregar fácilmente formatos de archivo de imagen adicionales. Una imagen de foto es transparente en regiones donde no se han suministrado datos de imagen o donde se ha establecido como transparente mediante la sub-orden transparencySet.

CREACIÓN DE FOTOS

Las fotos se crean utilizando el método Photo. Photo admite las siguientes opciones:

-data => cadena
Especifica el contenido de la imagen como una cadena. La cadena puede contener datos codificados en base64 o datos binarios. El formato de la cadena debe ser uno de aquellos para los que existe un manejador de formato de archivo de imagen que acepte datos de cadena. Si se especifican tanto la opción -data como la opción -file, la opción -file tendrá precedencia.
-format => nombre-formato
Especifica el nombre del formato de archivo para los datos especificados con la opción -data o -file.
-file => nombre
nombre proporciona el nombre de un archivo que se leerá para suministrar datos para la imagen de foto. El formato del archivo debe ser uno de aquellos para los que existe un manejador de formato de archivo de imagen que pueda leer datos.
-gamma => valor
Especifica que los colores asignados para mostrar esta imagen en una ventana deben corregirse para una pantalla no lineal con el valor de exponente gamma especificado. (La intensidad producida por la mayoría de las pantallas CRT es una función de potencia del valor de entrada, para una buena aproximación; gamma es el exponente y típicamente ronda los 2). El valor especificado debe ser mayor que cero. El valor predeterminado es uno (sin corrección). En general, los valores mayores que uno harán la imagen más clara, y los valores menores que uno la harán más oscura.
-height => número
Especifica la altura de la imagen, en píxeles. Esta opción es útil principalmente en situaciones donde el usuario desea construir el contenido de la imagen pieza por pieza. Un valor de cero (el predeterminado) permite que la imagen se expanda o contraiga verticalmente para ajustarse a los datos almacenados en ella.
-palette => especificación-paleta
Especifica la resolución del cubo de color que se asignará para mostrar esta imagen, y por lo tanto, el número de colores utilizados de los mapas de color de las ventanas donde se muestra. La cadena especificación-paleta puede ser un solo número decimal, que especifica el número de tonos de gris a utilizar, o tres números decimales separados por barras (/), especificando el número de tonos de rojo, verde y azul, respectivamente. Si se utiliza la primera forma (un solo número), la imagen se mostrará en monocromo (es decir, en escala de grises).
-width => número
Especifica la anchura de la imagen, en píxeles. Esta opción es útil principalmente en situaciones donde el usuario desea construir el contenido de la imagen pieza por pieza. Un valor de cero (el predeterminado) permite que la imagen se expanda o contraiga horizontalmente para ajustarse a los datos almacenados en ella.

MÉTODOS DE IMAGEN

Cuando se crea una imagen de foto, Tk también crea un nuevo objeto. Este objeto admite los métodos configure y cget descritos en Tk::options, que se pueden utilizar para consultar y modificar las opciones descritas anteriormente.

Aquellas opciones que escriben datos en la imagen generalmente expanden el tamaño de la imagen, si es necesario, para acomodar los datos escritos en ella, a menos que el usuario haya especificado valores distintos de cero para las opciones de configuración -width y/o -height, en cuyo caso el ancho y/o la altura, respectivamente, de la imagen no se modificarán.

Los siguientes métodos adicionales están disponibles para las imágenes de foto:

$image->blank
Borra la imagen; es decir, establece toda la imagen para que no tenga datos, por lo que se mostrará como transparente, y el fondo de cualquier ventana en la que se muestre se verá a través.
$image->copy(imagenOrigen ?,valor(es) de opción ...?)
Copia una región de la imagen llamada $imagenOrigen (que debe ser una imagen de foto) a la imagen llamada $image, posiblemente con zoom y/o submuestreo de píxeles. Si no se especifican opciones, este método copia la totalidad de $imagenOrigen en $image, comenzando en las coordenadas (0,0) en $image. Las siguientes opciones pueden especificarse:
-from => x1, y1, ?, x2, y2?
Especifica una subregión rectangular de la imagen de origen para copiar. (x1,y1) y (x2,y2) especifican esquinas diagonalmente opuestas del rectángulo. Si no se especifican x2 e y2, el valor predeterminado es la esquina inferior derecha de la imagen de origen. Los píxeles copiados incluirán los bordes izquierdo y superior del rectángulo especificado, pero no los bordes inferior o derecho. Si la opción -from no se proporciona, el valor predeterminado es toda la imagen de origen.
-to => x1, y1, ?, x2, y2?
Especifica una subregión rectangular de la imagen de destino a afectar. (x1,y1) y (x2,y2) especifican esquinas diagonalmente opuestas del rectángulo. Si no se especifican x2 e y2, el valor predeterminado es (x1,y1) más el tamaño de la región de origen (después de submuestreo y zoom, si se especifican). Si se especifican x2 e y2, la región de origen se repetirá si es necesario para llenar la región de destino de forma teselada.
-shrink
Especifica que el tamaño de la imagen de destino debe reducirse, si es necesario, de modo que la región que se copia esté en la esquina inferior derecha de la imagen. Esta opción no afectará el ancho o la altura de la imagen si el usuario ha especificado un valor distinto de cero para la opción de configuración -width o -height, respectivamente.
-zoom => x, y
Especifica que la región de origen debe magnificarse por un factor de x en la dirección X e y en la dirección Y. Si no se proporciona y, el valor predeterminado es el mismo que x. Con esta opción, cada píxel en la imagen de origen se expandirá en un bloque de x x y píxeles en la imagen de destino, todos del mismo color. x e y deben ser mayores que 0.
-subsample => x, y
Especifica que la imagen de origen debe reducirse utilizando solo cada x-ésimo píxel en la dirección X y el y-ésimo píxel en la dirección Y. Los valores negativos harán que la imagen se invierta sobre los ejes Y o X, respectivamente. Si no se proporciona y, el valor predeterminado es el mismo que x.
-compositingrule => regla
Especifica cómo se combinan los píxeles transparentes de la imagen de origen con la imagen de destino. Cuando se establece una regla de composición de overlay, el contenido antiguo de la imagen de destino es visible, como si la imagen de origen se imprimiera en una pieza de película transparente y se colocara encima del destino. Cuando se establece una regla de composición de set, el contenido antiguo de la imagen de destino se descarta y la imagen de origen se utiliza tal cual. T

IMAGE METHODS

$image->blank( ?color?)
Initializes the image to a blank image of the current size. If color is specified, it is used to fill the image; otherwise, the image is filled with transparent pixels. If the image has no size, this command is a no-op.
$image->blur(radius ?,sigma?)
Applies a Gaussian blur filter to the image. radius is the blur radius and sigma is the standard deviation for the Gaussian function. If sigma is not specified, it is calculated from radius. This method can be slow for large radii.
$image->brightness(amount)
Adjusts the brightness of the image by amount. amount can be positive or negative.
$image->color(?option value(s), ...?)
Returns a string representation of the image color. The following options can be specified:
-background => color
Specifies the color to use for transparent pixels when returning the color of an image. The default is "red".
-format => format-name
Specifies the format of the returned color string. The following formats are supported:
rgb
Returns the color as an RGB triplet, e.g., "#RRGGBB".
string
Returns the color as a color string recognized by Tk, e.g., "red", "blue", etc.
$image->composite(source_image, mask_image, ?geometry string?)
Composites source_image onto $image using mask_image as the mask. The optional geometry string specifies how to tile the images. The default compositing rule is overlay.
$image->data(?option value(s), ...?)
Returns image data in the form of a string. The following options may be specified:
-background => color
If the color is specified, the data will not contain any transparency information. In all transparent pixels the color will be replaced by the specified color.
-format => format-name
Specifies the name of the image file format handler to be used. Specifically, this method searches for the first handler whose name matches a initial substring of format-name and which has the capability to read this image data. If this option is not given, this method uses the first handler that has the capability to read the image data.
-from => x1, y1, ?, x2, y2?
Specifies a rectangular region of $image to be returned. If only x1 and y1 are specified, the region extends from (x1,y1) to the bottom-right corner of $image. If all four coordinates are given, they specify diagonally opposite corners of the rectangular region, including x1,y1 and excluding x2,y2. The default, if this option is not given, is the whole image.
-grayscale
If this options is specified, the data will not contain color information. All pixel data will be transformed into grayscale.
$image->get(x, y)
Returns the color of the pixel at coordinates (x,y) in the image as a list of three integers between 0 and 255, representing the red, green and blue components respectively.
$image->put(data ?,-format=>format-name? ?,-to=> x1 y1 ?x2 y2??)
Sets pixels in $image to the data specified in data. This command first searches the list of image file format handlers for a handler that can interpret the data in data, and then reads the image encoded within into $image (the destination image). If data does not match any known format, an attempt to interpret it as a (top-to-bottom) list of scan-lines is made, with each scan-line being a (left-to-right) list of pixel colors (see Tk_GetColor for a description of valid colors.) Every scan-line must be of the same length. Note that when data is a single color name, you are instructing Tk to fill a rectangular region with that color. The following options may be specified:
-format =>format-name
Specifies the format of the image data in data. Specifically, only image file format handlers whose names begin with format-name will be used while searching for an image data format handler to read the data.
-to =>x, y ?, x2, y2?
Specifies the coordinates of the top-left corner (x1,y1) of the region of $image into which data from filename are to be read. The default is (0,0). If x2,y2 is given and data is not large enough to cover the rectangle specified by this option, the image data extracted will be tiled so it covers the entire destination rectangle. Note that if data specifies a single color value, then a region extending to the bottom-right corner represented by (x2,y2) will be filled with that color.
$image->read(filename ?,option value(s), ...?)
Reads image data from the file named filename into the image. This method first searches the list of image file format handlers for a handler that can interpret the data in filename, and then reads the image in filename into $image (the destination image). The following options may be specified:
-format => format-name
Specifies the format of the image data in filename. Specifically, only image file format handlers whose names begin with format-name will be used while searching for an image data format handler to read the data.
-from => x1, y1, x2, y2
Specifies a rectangular sub-region of the image file data to be copied to the destination image. If only x1 and y1 are specified, the region extends from (x1,y1) to the bottom-right corner of the image in the image file. If all four coordinates are specified, they specify diagonally opposite corners or the region. The default, if this option is not specified, is the whole of the image in the image file.
-shrink
If this option is specified, the size of $image will be reduced, if necessary, so that the region into which the image file data are read is at the bottom-right corner of the $image. This option will not affect the width or height of the image if the user has specified a non-zero value for the -width or -height configuration option, respectively.
-to => x, y
Specifies the coordinates of the top-left corner of the region of $image into which data from filename are to be read. The default is (0,0).
$image->redither
The dithering algorithm used in displaying photo images propagates quantization errors from one pixel to its neighbors. If the image data for $image is supplied in pieces, the dithered image may not be exactly correct. Normally the difference is not noticeable, but if it is a problem, this method can be used to recalculate the dithered image in each window where the image is displayed.
$image->transparency(subcommand, ?arg, arg ...?);
Allows examination and manipulation of the transparency information in the photo image. Several subcommands are available:
$image->transparencyGet(x, y);
Returns a boolean indicating if the pixel at (x,y) is transparent.
$image->transparencySet(x, y, boolean);
Makes the pixel at (x,y) transparent if boolean is true, and makes that pixel opaque otherwise.
$image->write(filename ?,option value(s), ...?)
Writes image data from $image to a file named filename. The following options may be specified:
-background => color
If the color is specified, the data will not contain any transparency information. In all transparent pixels the color will be replaced by the specified color.
-format => format-name
Specifies the name of the image file format handler to be used to write the data to the file. Specifically, this subcommand searches for the first handler whose name matches a initial substring of format-name and which has the capability to write an image file. If this option is not given, this subcommand uses the first handler that has the capability to write an image file.
-from => x1, y1, ?, x2, y2?
Specifies a rectangular region of $image to be written to the image file. If only x1 and y1 are specified, the region extends from (x1,y1) to the bottom-right corner of $image. If all four coordinates are given, they specify diagonally opposite corners of the rectangular region. The default, if this option is not given, is the whole image.
-grayscale
If this options is specified, the data will not contain color information. All pixel data will be transformed into grayscale.

IMAGE FORMATS

The photo image code is structured to allow handlers for additional image file formats to be added easily. The photo image code maintains a list of these handlers. Handlers are added to the list by registering them with a call to Tk_CreatePhotoImageFormat. The standard Tk distribution comes with handlers for XBM, XPM, BMP, JPEG, PNG and PPM/PGM formats, which are automatically registered on initialization.

When reading an image file or processing string data specified with the -data configuration option, the photo image code invokes each handler in turn until one is found that claims to be able to read the data in the file or string. Usually this will find the correct handler, but if it doesn't, the user may give a format name with the -format option to specify which handler to use. In fact the photo image code will try those handlers whose names begin with the string specified for the -format option (the comparison is case-insensitive). For example, if the user specifies -format => gif, then a handler named GIF87 or GIF89 may be invoked, but a handler named JPEG may not (assuming that such handlers had been registered).

When writing image data to a file, the processing of the -format option is slightly different: the string value given for the -format option must begin with the complete name of the requested handler, and may contain additional information following that, which the handler can use, for example, to specify which variant to use of the formats supported by the handler. Tk::Photo - Tk Photo Image Type

IMAGE FORMATS

The photo image type supports the following image formats:

  • GIF
  • JPEG
  • PBM
  • PGM
  • PPM
  • TIFF

Other image formats can be supported if the Tk installation includes the necessary libraries and the appropriate image types have been compiled into the Tk library. For example, if the Tk library was compiled with support for the PNG format, then PNG images can be loaded by the photo image type.

The -format option can be used to specify the format of an image file if it cannot be determined automatically. This is useful if the file extension is missing or incorrect, or if the file does not conform to the standard format conventions. For example, if you have a file named myimage which is a GIF image, you can load it using the following command:

$widget->Photo(-file => "myimage", -format => "gif")

It is not usually necessary to specify the format, as Tk will attempt to determine the format automatically based on the file content. However, if Tk is unable to determine the format correctly, using the -format option can resolve the issue.

The photo image type can also load image data directly from a scalar that contains the image data, rather than from a file. This is done using the -data option. The -format option can also be used in conjunction with -data to specify the format of the image data.

$widget->Photo(-data => $image_data, -format => "gif")

If the -format option is not specified when using -data, Tk will attempt to determine the format of the image data based on its content. If this fails, the -format option must be used.

COLOR ALLOCATION

When a photo image is displayed in a window, the photo image code allocates colors to use to display the image and dithers the image, if necessary, to display a reasonable approximation to the image using the colors that are available. The colors are allocated as a color cube, that is, the number of colors allocated is the product of the number of shades of red, green and blue.

Normally, the number of colors allocated is chosen based on the depth of the window. For example, in an 8-bit PseudoColor window, the photo image code will attempt to allocate seven shades of red, seven shades of green and four shades of blue, for a total of 198 colors. In a 1-bit StaticGray (monochrome) window, it will allocate two colors, black and white. In a 24-bit DirectColor or TrueColor window, it will allocate 256 shades each of red, green and blue. Fortunately, because of the way that pixel values can be combined in DirectColor and TrueColor windows, this only requires 256 colors to be allocated. If not all of the colors can be allocated, the photo image code reduces the number of shades of each primary color and tries again.

The user can exercise some control over the number of colors that a photo image uses with the -palette configuration option. If this option is used, it specifies the maximum number of shades of each primary color to try to allocate. It can also be used to force the image to be displayed in shades of gray, even on a color display, by giving a single number rather than three numbers separated by slashes.
