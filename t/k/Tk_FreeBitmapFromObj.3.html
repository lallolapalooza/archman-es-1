DESCRIPCIÓN

Estos procedimientos gestionan una colección de bitmaps (pixmaps de un solo plano) que está utilizando una aplicación. Los procedimientos permiten reutilizar los bitmaps de manera eficiente, evitando así la sobrecarga del servidor y también permiten nombrar los bitmaps con cadenas de caracteres.

Tk_AllocBitmapFromObj devuelve un identificador Pixmap para un bitmap que coincide con la descripción en objPtr y es adecuado para su uso en tkwin. Reutiliza un bitmap existente, si es posible, y crea uno nuevo en caso contrario. El valor de objPtr debe tener una de las siguientes formas:

@nombreArchivo
nombreArchivo debe ser el nombre de un archivo que contenga una descripción de bitmap en el formato estándar de X11.
nombre
Nombre debe ser el nombre de un bitmap definido previamente con una llamada a Tk_DefineBitmap. Los siguientes nombres están predefinidos por Tk:
error
El símbolo internacional de "prohibido": un círculo con una línea diagonal.

75% de gris: un patrón de tablero de ajedrez donde tres de cada cuatro bits están activados.
gray50
50% de gris: un patrón de tablero de ajedrez donde cada dos bits están activados.
gray25
25% de gris: un patrón de tablero de ajedrez donde uno de cada cuatro bits está activado.
gray12
12.5% de gris: un patrón donde una octava parte de los bits están activados, que consiste en cada cuarto píxel en cada dos filas.

Un símbolo de reloj de arena.

Una letra "i" grande.

En condiciones normales, Tk_AllocBitmapFromObj devuelve un identificador para el bitmap solicitado. Si ocurre un error al crear el bitmap, como cuando objPtr se refiere a un archivo inexistente, se devuelve None y se deja un mensaje de error en el resultado de interp si interp no es NULL. Tk_AllocBitmapFromObj almacena en caché información sobre el valor de retorno en objPtr, lo que acelera las llamadas futuras a procedimientos como Tk_AllocBitmapFromObj y Tk_GetBitmapFromObj.

Tk_GetBitmap es idéntico a Tk_AllocBitmapFromObj excepto que la descripción del bitmap se especifica con una cadena en lugar de un objeto. Esto evita que Tk_GetBitmap almacene en caché el valor de retorno, por lo que Tk_GetBitmap es menos eficiente que Tk_AllocBitmapFromObj.

Tk_GetBitmapFromObj devuelve el token de un bitmap existente, dada la ventana y la descripción utilizadas para crear el bitmap. Tk_GetBitmapFromObj no crea realmente el bitmap; el bitmap debe haber sido creado previamente con una llamada a Tk_AllocBitmapFromObj o Tk_GetBitmap. El valor de retorno se almacena en caché en objPtr, lo que acelera las llamadas futuras a Tk_GetBitmapFromObj con el mismo objPtr y tkwin.

Tk_DefineBitmap asocia un nombre con datos de bitmap en memoria para que el nombre pueda utilizarse en llamadas posteriores a Tk_AllocBitmapFromObj o Tk_GetBitmap. El argumento nombreId proporciona un nombre para el bitmap; no debe haber sido utilizado previamente en una llamada a Tk_DefineBitmap. Los argumentos source, width y height describen el bitmap. Tk_DefineBitmap normalmente devuelve TCL_OK; si ocurre un error (por ejemplo, ya se ha definido un bitmap llamado nameId), se devuelve TCL_ERROR y se deja un mensaje de error en el resultado del intérprete interp. Nota: Tk_DefineBitmap espera que la memoria apuntada por source sea estática: Tk_DefineBitmap no crea una copia privada de esta memoria, sino que utiliza los bytes apuntados por source más tarde en llamadas a Tk_AllocBitmapFromObj o Tk_GetBitmap.

NAME

Tk_FreeBitmap, Tk_GetBitmap, Tk_DefineBitmap, Tk_AllocBitmapFromObj, Tk_FreeBitmapFromObj, Tk_NameOfBitmap, Tk_SizeOfBitmap - crear, destruir y obtener información sobre bitmaps

SYNOPSIS

#include <tk.h>

Tk_FreeBitmap(interp, bitmap);
Tk_GetBitmap(interp, tkwin, name);
Tk_DefineBitmap(interp, name, bits, width, height);
Tk_AllocBitmapFromObj(interp, tkwin, value);
Tk_FreeBitmapFromObj(interp, tkwin, value);
Tk_NameOfBitmap(tkwin, bitmap);
Tk_SizeOfBitmap(tkwin, bitmap, widthPtr, heightPtr);

ARGUMENTS

Tcl_Interp *interp
Intérprete de Tcl a usar para la conversión de cadenas y para reportar errores.
const char *name

const char *bits
Cadena que representa el bitmap en formato de matriz de bits.
int width

int height
Alto del bitmap en píxeles.
Tk_Window tkwin
Ventana de Tk asociada con la operación. Se utiliza para determinar la pantalla y el generador de colores.
const char *value
Valor de configuración del objeto que representa el bitmap. Esto puede ser un nombre de archivo precedido por '@' o una cadena de definición de bitmap.
Pixmap bitmap

Puntero a una ubicación de memoria donde se almacenará el ancho del bitmap.
int *heightPtr
Puntero a una ubicación de memoria donde se almacenará el alto del bitmap.

DESCRIPTION

Tk utiliza la representación de Xlib de Pixmaps para manejar bitmaps. Las funciones descritas aquí proporcionan una interfaz de alto nivel para la creación, recuperación y gestión de estos Pixmaps.

Tk_DefineBitmap permite definir un nuevo bitmap cuyos datos se proporcionan directamente en el código fuente. El argumento bits es una cadena de caracteres que contiene los datos binarios del bitmap, y width y height especifican sus dimensiones. Por ejemplo, el siguiente código utiliza Tk_DefineBitmap para definir un nuevo bitmap llamado foo:

Pixmap bitmap;
#include "stip.bitmap"
Tk_DefineBitmap(interp, "foo", stip_bits,
    stip_width, stip_height);
...
bitmap = Tk_GetBitmap(interp, tkwin, "foo");

Este código provoca que el archivo de bitmap se lea en tiempo de compilación y que la información del bitmap se incorpore a la imagen ejecutable del programa. El mismo archivo de bitmap podría leerse en tiempo de ejecución utilizando Tk_GetBitmap:

Pixmap bitmap;
bitmap = Tk_GetBitmap(interp, tkwin, "@stip.bitmap");

La segunda forma es un poco más flexible (el archivo podría modificarse después de que el programa se haya compilado, o podría proporcionarse una cadena diferente para leer un archivo diferente), pero es un poco más lenta y requiere que el archivo de bitmap exista por separado del programa.

Tk mantiene una base de datos de todos los bitmaps que están actualmente en uso. Siempre que sea posible, devolverá un bitmap existente en lugar de crear uno nuevo. Cuando un bitmap ya no se utiliza, Tk lo liberará automáticamente. Este enfoque puede reducir sustancialmente la sobrecarga del servidor, por lo que Tk_AllocBitmapFromObj y Tk_GetBitmap generalmente deben usarse en preferencia a procedimientos Xlib como XReadBitmapFile.

Los bitmaps devueltos por Tk_AllocBitmapFromObj y Tk_GetBitmap se comparten, por lo que los llamadores nunca deben modificarlos. Si un bitmap debe modificarse dinámicamente, entonces debe crearse llamando directamente a procedimientos Xlib como XReadBitmapFile o XCreatePixmap.

El procedimiento Tk_NameOfBitmap es aproximadamente el inverso de Tk_GetBitmap. Dada una entrada Pixmap de X, devuelve la descripción textual que se pasó a Tk_GetBitmap cuando se creó el bitmap. bitmap debe haber sido el valor de retorno de una llamada anterior a Tk_AllocBitmapFromObj o Tk_GetBitmap.

Tk_SizeOfBitmap devuelve las dimensiones de su argumento bitmap en las palabras apuntadas por los argumentos widthPtr y heightPtr. Al igual que con Tk_NameOfBitmap, bitmap debe haber sido creado por Tk_AllocBitmapFromObj o Tk_GetBitmap.

Cuando un bitmap ya no es necesario, se debe llamar a Tk_FreeBitmapFromObj o Tk_FreeBitmap para liberarlo. Para Tk_FreeBitmapFromObj, el bitmap a liberar se especifica con la misma información utilizada para crearlo; para Tk_FreeBitmap, el bitmap a liberar se especifica con su token Pixmap. Debería haber exactamente una llamada a Tk_FreeBitmapFromObj o Tk_FreeBitmap por cada llamada a Tk_AllocBitmapFromObj o Tk_GetBitmap.

BUGS

Al determinar si un bitmap existente se puede utilizar para satisfacer una nueva solicitud, Tk_AllocBitmapFromObj y Tk_GetBitmap consideran solo el valor inmediato de la descripción de la cadena. Por ejemplo, cuando se pasa un nombre de archivo a Tk_GetBitmap, Tk_GetBitmap asumirá que es seguro reutilizar un bitmap existente creado a partir del mismo nombre de archivo: no comprobará si el archivo mismo ha cambiado, o si el directorio actual ha cambiado, lo que haría que el nombre hiciera referencia a un archivo diferente.
