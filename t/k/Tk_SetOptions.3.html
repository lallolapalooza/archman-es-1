ARGUMENTOS

Tcl_Interp *interp (entrada)
Un intérprete de Tcl. La mayoría de los procedimientos usan esto solo para devolver mensajes de error; si es NULL, no se devuelven mensajes de error. Para Tk_CreateOptionTable el valor no puede ser NULL; proporciona el intérprete en el que se utilizará la tabla de opciones.
const Tk_OptionSpec *templatePtr (entrada)
Punta a una matriz de información estática que describe las opciones de configuración que se admiten. Se utiliza para construir una Tk_OptionTable. La información a la que apunta este argumento debe existir durante la vida útil de la Tk_OptionTable.
Tk_OptionTable optionTable (entrada)
Token para una tabla de opciones. Debe haber sido devuelto por una llamada anterior a Tk_CreateOptionTable.
char *recordPtr (entrada/salida)
Punta a una estructura en la que se almacenan los valores de las opciones de configuración; los campos de este registro son modificados por procedimientos como Tk_SetOptions y leídos por procedimientos como Tk_GetOptionValue.
Tk_Window tkwin (entrada)
Para opciones como TK_OPTION_COLOR, este argumento indica la ventana en la que se utilizará la opción. Si optionTable no utiliza opciones dependientes de la ventana, se puede proporcionar un valor NULL para este argumento.
int objc (entrada)
Número de valores en objv.
Tcl_Obj *const *objv (entrada)
Argumentos de línea de comandos para establecer opciones de configuración.
Tk_SavedOptions *savePtr (salida)
Si no es NULL, la estructura a la que apunta este argumento se rellena con los valores antiguos de cualquier opción que se haya modificado y los valores antiguos se restauran automáticamente si ocurre un error en Tk_SetOptions.
int *maskPtr (salida)
Si no es NULL, la palabra a la que apunta maskPtr se rellena con el OR a nivel de bits de los campos typeMask para las opciones que se modificaron.
Tk_SavedOptions *savedPtr (entrada/salida)
Punta a una estructura rellenada previamente por Tk_SetOptions con valores antiguos de opciones modificadas.
Tcl_Obj *namePtr (entrada)
El valor de este objeto es el nombre de una opción particular. Si se pasa NULL a Tk_GetOptionInfo, se devuelve información para todas las opciones. No debe ser NULL cuando se llama a Tk_GetOptionValue.
tipo nombre type (entrada)
El nombre del tipo de un registro.
campo nombre field (entrada)
El nombre de un campo en registros de tipo type.

DESCRIPCIÓN

Estos procedimientos manejan la mayoría de los detalles del análisis de opciones de configuración, como las de los widgets de Tk. Dada una descripción de las opciones admitidas, estos procedimientos manejan todos los detalles del análisis de opciones y el almacenamiento de sus valores en una estructura C asociada al widget u objeto. Los procedimientos fueron diseñados principalmente para widgets en Tk, pero también se pueden utilizar para otros tipos de objetos que tengan opciones de configuración. En el resto de esta página del manual, "widget" se utilizará para referirse al objeto cuyas opciones se están gestionando; en la práctica, el objeto puede no ser realmente un widget. El término "registro de widget" se utiliza para referirse a la estructura a nivel de C en la que se almacena la información sobre un widget u objeto particular.

Tenga en cuenta que la forma más fácil de aprender a usar estos procedimientos es mirar un ejemplo funcional. En Tk, el ejemplo más simple es el código que implementa la familia de widgets de botón, que se encuentra en tkButton.c. Otros ejemplos se encuentran en tkSquare.c y tkMenu.c.

Para utilizar estos procedimientos, el código que implementa el widget debe contener una matriz estática de estructuras Tk_OptionSpec. Esta es una plantilla que describe las diversas opciones admitidas por esa clase de widget; hay una plantilla separada para cada tipo de widget. La plantilla contiene información como el nombre de cada opción, su tipo, su valor predeterminado y dónde se almacena el valor de la opción en el registro del widget. Ver PLANTILLAS a continuación para más detalles.

Para procesar las opciones de configuración de manera eficiente, la plantilla estática debe ser aumentada con información adicional que solo está disponible en tiempo de ejecución. El procedimiento Tk_CreateOptionTable crea esta información dinámica a partir de la plantilla y devuelve un token Tk_OptionTable que describe tanto la información estática como la dinámica. Todos los demás procedimientos, como Tk_SetOptions, toman un token Tk_OptionTable como argumento. Típicamente, Tk_CreateOptionTable se llama la primera vez que se crea un widget de una clase particular y la Tk_OptionTable resultante se utiliza en el futuro para todos los widgets de esa clase. Una Tk_OptionTable puede usarse solo en un intérprete, dado por el argumento interp a Tk_CreateOptionTable. Cuando una tabla de opciones ya no es necesaria, se debe llamar a Tk_DeleteOptionTable para liberar todos sus recursos. Todas las tablas de opciones para un intérprete Tcl se liberan automáticamente si el intérprete se elimina.

Tk_InitOptions se invoca cuando se crea un nuevo widget para establecer los valores predeterminados. Tk_InitOptions recibe un token para una tabla de opciones (optionTable) y un puntero a un registro de widget (recordPtr), que es la estructura C que contiene información sobre este widget. Tk_InitOptions utiliza la información de la tabla de opciones para elegir un valor predeterminado apropiado para cada opción, luego almacena el valor predeterminado directamente en el registro del widget, sobrescribiendo cualquier información que ya estuviera presente en el registro del widget. Tk_InitOptions normalmente devuelve TCL_OK. Si ocurrió un error al establecer los valores predeterminados (por ejemplo, porque un valor predeterminado era erróneo), entonces se devuelve TCL_ERROR y se deja un mensaje de error en el resultado de interp si interp no es NULL. Para cualquier opción de configuración de un widget que tenga TK_OPTION_DONT_SET_DEFAULT establecido en su campo flags, la inicialización anterior se omite por completo, ver a continuación.

Tk_SetOptions se invoca para modificar las opciones de configuración basándose en la información especificada en un comando Tcl. El comando puede ser uno que crea un nuevo widget, o un comando que modifica opciones en un widget existente. Los argumentos objc y objv describen los valores de los argumentos del comando Tcl. Objv debe contener un número par de objetos: el primer objeto de cada par da el nombre de una opción y el segundo objeto da el nuevo valor para esa opción. Tk_SetOptions busca cada nombre en optionTable, comprueba que el nuevo valor de la opción se ajuste al tipo en optionTable y almacena el valor de la opción en el registro del widget dado por recordPtr. Tk_SetOptions normalmente devuelve TCL_OK. Si ocurrió un error (como un nombre de opción desconocido o un valor de opción ilegal), entonces se devuelve TCL_ERROR y se deja un mensaje de error en el resultado de interp si interp no es NULL.

Tk_SetOptions tiene dos características adicionales. Primero, si el argumento maskPtr no es NULL, entonces apunta a un valor entero que se rellena con información sobre las opciones que se modificaron. Para cada opción en la plantilla pasada a Tk_CreateOptionTable hay un campo typeMask. Los bits de este campo los define el código que implementa el widget; por ejemplo, cada bit podría corresponder a una opción de configuración particular. Alternativamente, los bits se pueden usar funcionalmente. Por ejemplo, un bit podría usarse para redibujar: todas las opciones que afectan la visualización del widget, de modo que cambiar la opción requiera que el widget se redibuje, podrían tener ese bit establecido. STORAGE MANAGEMENT ISSUES

If a field of a widget record has its offset stored in the objOffset or internalOffset field of a Tk_OptionSpec structure then the procedures described here will handle all of the storage allocation and resource management issues associated with the field. When the value of an option is changed, Tk_SetOptions (or Tk_FreeSavedOptions) will automatically free any resources associated with the old value, such as Tk_Fonts for TK_OPTION_FONT options or dynamically allocated memory for TK_OPTION_STRING options. For an option stored as an object using the objOffset field of a Tk_OptionSpec, the widget record shares the object pointed to by the objv value from the call to Tk_SetOptions. The reference count for this object is incremented when a pointer to it is stored in the widget record and decremented when the option is modified. When the widget is deleted Tk_FreeConfigOptions should be invoked; it will free the resources associated with all options and decrement reference counts for any objects.

However, the widget code is responsible for storing NULL or None in all pointer and token fields before invoking Tk_InitOptions. This is needed to allow proper cleanup in the rare case where an error occurs in Tk_InitOptions.

OBJOFFSET VS. INTERNALOFFSET

In most cases it is simplest to use the internalOffset field of a Tk_OptionSpec structure and not the objOffset field. This makes the internal form of the value immediately available to the widget code so the value does not have to be extracted from an object each time it is used. However, there are two cases where the objOffset field is useful. The first case is for TK_OPTION_PIXELS options. In this case, the internal form is an integer pixel value that is valid only for a particular screen. If the value of the option is retrieved, it will be returned as a simple number. For example, after the command .b configure -borderwidth 2m, the command .b configure -borderwidth might return 7, which is the integer pixel value corresponding to 2m. Unfortunately, this loses the original screen-independent value. Thus for TK_OPTION_PIXELS options it is better to use the objOffset field. In this case the original value of the option is retained in the object and can be returned when the option is retrieved. In most cases it is convenient to use the internalOffset field as well, so that the integer value is immediately available for use in the widget code (alternatively, Tk_GetPixelsFromObj can be used to extract the integer value from the object whenever it is needed). Note that the problem of losing information on retrievals exists only for TK_OPTION_PIXELS options.

The second reason to use the objOffset field is in order to implement new types of options not supported by these procedures. To implement a new type of option, you can use TK_OPTION_STRING as the type in the Tk_OptionSpec structure and set the objOffset field but not the internalOffset field. Then, after calling Tk_SetOptions, convert the object to internal form yourself.

Ttk widgets do not support the internalOffset machinery. Option values of Ttk widgets are always stored as (Tcl_Obj *), meaning that the objOffset field must be used.

clientData
A pointer to arbitrary client-specific data. This data is passed to all the procedures associated with a custom option.
defValue

DESCRIPTION

The Tk_SetOptions and Tk_ConfigureWidget procedures are the primary interface for configuring Tk widgets. They process a set of configuration options for a widget and update the widget's internal state accordingly. The options are described by an array of Tk_OptionSpec structures. The mask argument can be used to control which options are processed.

Tk_SetOptions is used when configuration information is passed as a single Tcl object, typically a list of name-value pairs. The objPtr argument points to this object. The procedure iterates through the list, parsing each option name-value pair and invoking the appropriate procedures to set the option.

Tk_ConfigureWidget is used when configuration information is passed as a series of separate name-value pairs. The objc and objv arguments specify these pairs. The procedure iterates through the pairs, parsing each option name-value pair and invoking the appropriate procedures to set the option.

In both cases, the options are described by the specTable, which is an array of Tk_OptionSpec structures. Each structure describes a single option, including its name, database name and class, default value, flags, and offsets within the widget's internal record where the option's value should be stored. For custom options, a pointer to a Tk_ObjCustomOption structure is used instead of the standard fields.

The mask argument can be used to select which options are processed. For example, to process only options that were explicitly specified in the configuration request, use TK_CONFIG_OPTION_SPECIFIED as the mask. Other useful masks include TK_CONFIG_OPTION_DEFAULT (to process default values) and TK_CONFIG_OPTION_ALL (to process all options).

If an option is successfully processed, its internal representation is stored in the widget record at the offset specified by internalOffset or objOffset. If objOffset is non-negative, the option value is also stored as a Tcl_Obj pointer at that offset. The tkwin argument is used to access screen- specific information, such as screen distance units.

If an error occurs during option processing, Tk_SetOptions and Tk_ConfigureWidget return TCL_ERROR and leave an error message in the interpreter. Otherwise, they return TCL_OK.

Tk_RestoreSavedOptions and Tk_FreeSavedOptions are used to manage saved option values. When an option is configured, its original value can be saved using the saveInternalPtr argument to the option's setProc. Tk_RestoreSavedOptions can then be used to restore the original value. Tk_FreeSavedOptions should be called to free any storage associated with the saved options.

TEMPLATES

The following structures are used to describe configuration options:

Tk_OptionSpec: Describes a single configuration option. It contains fields for the option name, database name and class, default value, flags, and offsets for storing the option's value in the widget record. For standard option types, the value is stored directly at internalOffset. For options stored as Tcl_Obj pointers, the value is stored at objOffset.

Tk_OptionValue: Used to represent an option value when retrieving information about options using Tk_GetOptionValue.

Tk_ObjCustomOption: Describes a custom option type. It provides pointers to procedures that handle setting, getting, freeing, and restoring the option's value. The clientData field can be used to pass arbitrary data to these procedures.

Tk_SavedOptions: A structure used to hold saved option values. It contains a pointer to the Tk window, the option specifications, and the widget record. It is used in conjunction with Tk_RestoreSavedOptions and Tk_FreeSavedOptions.

STORAGE MANAGEMENT ISSUES

The freeProc and restoreProc fields in the Tk_ObjCustomOption structure are used for managing storage associated with custom option values. The freeProc is called to free any dynamically allocated memory used by the option's internal representation. The restoreProc is called to restore a previously saved option value.

It is the responsibility of the custom option's implementer to ensure that memory is properly allocated and freed. The clientData field in Tk_ObjCustomOption can be used to pass a pointer to a structure containing information needed for memory management.

OBJOFFSET VS. INTERNALOFFSET

The objOffset and internalOffset fields in the Tk_OptionSpec structure determine where the option's value is stored in the widget record. internalOffset specifies the offset to the internal representation of the value. objOffset specifies the offset to a pointer to a Tcl_Obj representing the value. If objOffset is -1, the option value is not stored as a Tcl_Obj pointer.

For simple types like integers and booleans, internalOffset is typically used. For more complex types like strings or lists, both internalOffset and objOffset might be used, or only objOffset if the Tcl_Obj representation is sufficient.

CUSTOM OPTION TYPES

Custom option types allow for specialized handling of option values that do not fit the standard Tk option types. They are defined using the Tk_ObjCustomOption structure, which contains pointers to procedures that handle setting, getting, freeing, and restoring the option's value.

The setProc procedure is invoked by Tk_SetOptions to convert a Tcl_Obj into an internal representation and store the resulting value in the widget record. The arguments are:

clientData
A copy of the clientData field in the Tk_ObjCustomOption structure.
interp
A pointer to a Tcl interpreter, used for error reporting.
Tkwin
A copy of the tkwin argument to Tk_SetOptions
valuePtr
A pointer to a reference to a Tcl_Obj describing the new value for the option; it could have been specified explicitly in the call to Tk_SetOptions or it could come from the option database or a default. If the objOffset for the option is non-negative (the option value is stored as a (Tcl_Obj *) in the widget record), the Tcl_Obj pointer referenced by valuePtr is the pointer that will be stored at the objOffset for the option. SetProc may modify the value if necessary; for example, setProc may change the value to NULL to support the TK_OPTION_NULL_OK flag.
recordPtr
A pointer to the start of the widget record to modify.
internalOffset
Offset in bytes from the start of the widget record to the location where the internal representation of the option value is to be placed.
saveInternalPtr
A pointer to storage allocated in a Tk_SavedOptions structure for the internal representation of the original option value. Before setting the option to its new value, setProc should set the value referenced by saveInternalPtr to the original value of the option in order to support Tk_RestoreSavedOptions.
flags
A copy of the flags field in the Tk_OptionSpec structure for the option

SetProc returns a standard Tcl result: TCL_OK to indicate successful processing, or TCL_ERROR to indicate a failure of any kind. An error message may be left in the Tcl interpreter given by interp in the case of an error.

The getProc procedure is invoked by Tk_GetOptionValue and Tk_GetOptionInfo to retrieve a Tcl_Obj representation of the internal representation of an option. The clientData argument is a copy of the clientData field in the Tk_ObjCustomOption structure. Tkwin is a copy of the tkwin argument to Tk_GetOptionValue or Tk_GetOptionInfo. RecordPtr is a pointer to the beginning of the widget record to query. InternalOffset is the offset in bytes from the beginning of the widget record to the location where the internal representation of the option value is stored. GetProc must return a pointer to a Tcl_Obj representing the value of the option.

The restoreProc procedure is invoked by Tk_RestoreSavedOptions to restore a previously saved internal representation of a custom option value. The clientData argument is a copy of the clientData field in the Tk_ObjCustomOption structure. Tkwin is a copy of the tkwin argument to Tk_GetOptionValue or Tk_GetOptionInfo. InternalPtr is a pointer to the location where internal representation of the option value is stored. SaveInternalPtr is a pointer to the saved value. RestoreProc must copy the value from saveInternalPtr to internalPtr to restore the value. RestoreProc need not free any memory associated with either internalPtr or saveInternalPtr; freeProc will be invoked to free that memory if necessary. RestoreProc has no return value.

The freeProc procedure is invoked by Tk_SetOptions and Tk_FreeSavedOptions to free any storage allocated for the internal representation of a custom option. The clientData argument is a copy of the clientData field in the Tk_ObjCustomOption structure. Tkwin is a copy of the tkwin argument to Tk_GetOptionValue or Tk_GetOptionInfo. InternalPtr is a pointer to the location where the internal representation of the option value is stored. The freeProc must free any storage associated with the option. FreeProc has no return value.
