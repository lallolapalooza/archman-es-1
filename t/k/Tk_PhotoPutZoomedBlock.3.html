NOMBRE

Tk_FindPhoto, Tk_PhotoPutBlock, Tk_PhotoPutZoomedBlock, Tk_PhotoGetImage, Tk_PhotoBlank, Tk_PhotoExpand, Tk_PhotoGetSize, Tk_PhotoSetSize - manipula los datos de imagen almacenados en una imagen fotográfica.

ARGUMENTOS

Tcl_Interp *interp (entrada)
Intérprete en el cual se creó la imagen y en el cual se deben reportar los errores.
const char *imageName (entrada)
Nombre de la imagen fotográfica.
Tk_PhotoHandle handle (entrada)
Identificador opaco que identifica la imagen fotográfica a la que se va a afectar.
Tk_PhotoImageBlock *blockPtr (entrada)
Especifica la dirección y el diseño del almacenamiento de los datos de la imagen.
int x (entrada)
Especifica la coordenada X donde se colocará la esquina superior izquierda del bloque dentro de la imagen.
int y (entrada)
Especifica la coordenada Y donde se colocará la esquina superior izquierda del bloque dentro de la imagen.
int width (entrada)
Especifica el ancho del área de la imagen a la que se va a afectar (para Tk_PhotoPutBlock) o el ancho deseado de la imagen (para Tk_PhotoExpand y Tk_PhotoSetSize).
int compRule (entrada)
Especifica la regla de composición utilizada al combinar píxeles transparentes en un bloque de datos con una imagen fotográfica. Debe ser una de las siguientes: TK_PHOTO_COMPOSITE_OVERLAY (que coloca el bloque de datos sobre la imagen fotográfica existente, con el contenido anterior visible en los píxeles transparentes) o TK_PHOTO_COMPOSITE_SET (que descarta el contenido existente de la imagen fotográfica en el rectángulo cubierto por el bloque de datos).
int height (entrada)
Especifica la altura del área de la imagen a la que se va a afectar (para Tk_PhotoPutBlock) o la altura deseada de la imagen (para Tk_PhotoExpand y Tk_PhotoSetSize).
int *widthPtr (salida)
Puntero a la ubicación en la que se almacenará el ancho de la imagen.
int *heightPtr (salida)
Puntero a la ubicación en la que se almacenará la altura de la imagen.
int subsampleX (entrada)
Especifica el factor de submuestreo en la dirección X para los datos de imagen de entrada.
int subsampleY (entrada)
Especifica el factor de submuestreo en la dirección Y para los datos de imagen de entrada.
int zoomX (entrada)
Especifica el factor de zoom que se aplicará en la dirección X a los píxeles que se escriben en la imagen fotográfica.
int zoomY (entrada)
Especifica el factor de zoom que se aplicará en la dirección Y a los píxeles que se escriben en la imagen fotográfica.

DESCRIPCIÓN

Tk_FindPhoto devuelve un identificador opaco que se utiliza para identificar una imagen fotográfica particular a los otros procedimientos. El parámetro es el nombre de la imagen, es decir, el nombre especificado al comando image create photo, o asignado por ese comando si no se especificó ningún nombre. Si imageName no existe o no es una imagen fotográfica, Tk_FindPhoto devuelve NULL.

Tk_PhotoPutBlock se utiliza para suministrar bloques de datos de imagen para ser mostrados. La llamada afecta a un área de la imagen de tamaño width x height píxeles, con su esquina superior izquierda en las coordenadas (x,y). Todos los valores de width, height, x e y deben ser no negativos. Si parte de esta área queda fuera de los límites actuales de la imagen, la imagen se expandirá para incluir el área, a menos que el usuario haya especificado un tamaño de imagen explícito con las opciones de configuración del widget -width y/o -height (ver photo(n)); en ese caso, el área se recortará silenciosamente a los límites de la imagen.

El parámetro block es un puntero a una estructura Tk_PhotoImageBlock, definida como sigue:

typedef struct {
    unsigned char *pixelPtr;
    int width;
    int height;
    int pitch;
    int pixelSize;
    int offset[4];
} Tk_PhotoImageBlock;
El campo pixelPtr apunta al primer píxel, es decir, al píxel superior izquierdo del bloque. Los campos width y height especifican las dimensiones del bloque de píxeles. El campo pixelSize especifica la diferencia de dirección entre dos píxeles horizontalmente adyacentes. Debe ser 4 para datos de imagen RGB y 2 para datos en escala de grises. Son posibles otros valores, si se ajustan las compensaciones en la matriz offset (por ejemplo, para datos rojos, verdes y azules almacenados en diferentes planos). Sin embargo, se desaconseja fuertemente el uso de dicho diseño. Debido a un error, puede que no funcione correctamente si se proporciona un canal alfa. (ver la sección BUGS más abajo). El campo pitch especifica la diferencia de dirección entre dos píxeles verticalmente adyacentes. La matriz offset contiene las compensaciones desde la dirección de un píxel hasta las direcciones de los bytes que contienen los componentes rojo, verde, azul y alfa (transparencia). Si las compensaciones para rojo, verde y azul son iguales, la imagen se interpreta como escala de grises. Si difieren, se asumen datos RGB. Normalmente, las compensaciones serán 0, 1, 2, 3 para datos RGB y 0, 0, 0, 1 para escala de grises. Es posible proporcionar datos de imagen sin canal alfa estableciendo la compensación del alfa a un valor negativo y ajustando el campo pixelSize en consecuencia. Sin embargo, este uso está desaconsejado (ver la sección BUGS más abajo).

El parámetro compRule de Tk_PhotoPutBlock especifica una regla de composición que indica qué hacer con los píxeles transparentes. El valor TK_PHOTO_COMPOSITE_OVERLAY indica que el contenido anterior de la imagen fotográfica debe mostrarse, y el valor TK_PHOTO_COMPOSITE_SET indica que el contenido anterior de la imagen fotográfica debe ignorarse por completo, y que los valores del bloque deben copiarse directamente. El comportamiento en Tk8.3 y anteriores era equivalente a tener TK_PHOTO_COMPOSITE_OVERLAY como regla de composición.

Los valores dados para los parámetros width y height de Tk_PhotoPutBlock no tienen que corresponder a los valores especificados en block. Si son más pequeños, Tk_PhotoPutBlock extrae un sub-bloque de los datos de imagen suministrados. Si son más grandes, los datos proporcionados se replican (de forma embaldosada) para llenar el área especificada. Estas reglas operan independientemente en las direcciones horizontal y vertical.

Tk_PhotoPutBlock normalmente devuelve TCL_OK, aunque si no puede asignar suficiente memoria para mantener la imagen resultante, devuelve TCL_ERROR y, si el argumento interp no es NULL, se coloca un mensaje de error en el resultado del intérprete.

Tk_PhotoPutZoomedBlock funciona como Tk_PhotoPutBlock excepto que la imagen puede reducirse o ampliarse para su visualización. Los parámetros subsampleX e subsampleY permiten reducir el tamaño de la imagen mediante submuestreo. Tk_PhotoPutZoomedBlock utilizará solo los píxeles de la imagen de entrada cuyas coordenadas X sean múltiplos de subsampleX, y cuyas coordenadas Y sean múltiplos de subsampleY. Por ejemplo, una imagen de 512x512 píxeles puede reducirse a 256x256 estableciendo subsampleX y subsampleY en 2.

Los parámetros zoomX y zoomY permiten ampliar la imagen mediante la replicación de píxeles. Cada píxel de la imagen de entrada (posiblemente submuestreada) se escribirá en un bloque de zoomX píxeles de ancho y zoomY píxeles de alto de la imagen mostrada. El submuestreo y el zoom se pueden usar juntos para efectos especiales.

Tk_PhotoGetImage se puede utilizar para recuperar datos de imagen de una imagen fotográfica. Tk_PhotoGetImage rellena la estructura apuntada por el parámetro blockPtr con valores que describen la dirección y el diseño de los datos de imagen que la imagen fotográfica tiene almacenados internamente. Los valores son válidos hasta que la imagen se destruye o se cambia su tamaño.

Es posible modificar una imagen escribiendo directamente en los datos a los que apunta el campo pixelPtr. Sin embargo, el tamaño de la imagen no se puede cambiar de esta manera. Además, los cambios realizados al escribir directamente en pixelPtr no serán visibles de inmediato, sino solo después de llamar a Tk_ImageChanged o después de un evento que haga que los widgets interesados se redibujen. DESCRIPCIÓN

Estas funciones se utilizan para crear y manipular imágenes de fotos de Tk. Las imágenes de fotos son un tipo de imagen que se puede modificar mediante programación para que contenga datos de píxeles arbitrarios. Son ideales para crear imágenes dinámicamente, como las creadas por aplicaciones que procesan imágenes o generan gráficos. Las imágenes de fotos se usan normalmente con el widget image de Tk.

Cada imagen de foto está gestionada por un objeto Tk_PhotoHandle. Cuando se crea una imagen de foto (por ejemplo, mediante el comando photo de Tk), se devuelve un handle para ella.

La función Tk_PhotoPutBlock copia datos de píxeles de un bloque especificado por blockPtr en la posición (x, y) de la imagen de la foto. El blockPtr apunta a una estructura Tk_PhotoImageBlock, que contiene un puntero a los datos de píxeles, así como información sobre la organización de esos datos. El campo pixelSize de la estructura especifica el número de bytes por píxel (normalmente 3 para RGB y 4 para RGBA). El campo nchan especifica el número de canales de color en los datos (normalmente 3 o 4). Los campos width y height especifican las dimensiones del bloque de píxeles. Los campos offsetX[RED], offsetX[GREEN], offsetX[BLUE] y offsetX[ALPHA] especifican el desplazamiento en bytes desde el principio de cada píxel a los canales rojo, verde, azul y alfa, respectivamente.

La función Tk_PhotoPutZoomedBlock es similar a Tk_PhotoPutBlock, pero también permite escalar los datos del bloque de origen al destino. Los argumentos width y height especifican las dimensiones del área de destino dentro de la imagen de la foto en la que se copiará el bloque. Los argumentos subWidth y subHeight especifican las dimensiones del bloque de origen. Esto permite copiar un bloque de píxeles de un tamaño a un área de otro tamaño dentro de la imagen de la foto, proporcionando un efecto de escalado.

Después de llamar a Tk_PhotoPutBlock o Tk_PhotoPutZoomedBlock, es posible que necesite actualizar las ventanas que muestran la imagen. Esto se suele hacer llamando a Tk_ImageChanged.

La función Tk_PhotoGetImage copia los datos de píxeles de la imagen de la foto a la estructura Tk_PhotoImageBlock proporcionada. Esto es útil si necesita realizar modificaciones en una copia de los datos de la imagen y luego volver a escribirlos con Tk_PhotoPutBlock o Tk_PhotoPutZoomedBlock.

La función Tk_PhotoGetImage devuelve 1 por compatibilidad con el procedimiento correspondiente en el widget de foto antiguo.

La función Tk_PhotoBlank pone en blanco toda el área de la imagen de la foto. Las áreas en blanco de una imagen de foto son transparentes.

La función Tk_PhotoExpand solicita que la imagen del widget se expanda para tener al menos un tamaño de width x height píxeles. El ancho y/o la altura no cambian si el usuario ha especificado un ancho o alto de imagen explícito con las opciones de configuración -width y/o -height, respectivamente. Si los datos de la imagen se suministran en muchos bloques pequeños, es más eficiente usar Tk_PhotoExpand o Tk_PhotoSetSize al principio en lugar de permitir que la imagen se expanda en muchos incrementos pequeños a medida que se suministran los bloques de imagen.

La función Tk_PhotoExpand normalmente devuelve TCL_OK, aunque si no puede asignar suficiente memoria para contener la imagen resultante, se devuelve TCL_ERROR y, si el argumento interp no es NULL, se coloca un mensaje de error en el resultado del intérprete.

La función Tk_PhotoSetSize especifica el tamaño de la imagen, como si el usuario hubiera especificado los valores dados de width y height a las opciones de configuración -width y -height. Un valor de cero para width o height no cambia el ancho o alto de la imagen, pero permite que el ancho o alto se cambie mediante llamadas posteriores a Tk_PhotoPutBlock, Tk_PhotoPutZoomedBlock o Tk_PhotoExpand.

La función Tk_PhotoSetSize normalmente devuelve TCL_OK, aunque si no puede asignar suficiente memoria para contener la imagen resultante, se devuelve TCL_ERROR y, si el argumento interp no es NULL, se coloca un mensaje de error en el resultado del intérprete.

La función Tk_PhotoGetSize devuelve las dimensiones de la imagen en *widthPtr y *heightPtr.

PORTABILIDAD

En Tk 8.3 y anteriores, Tk_PhotoPutBlock y Tk_PhotoPutZoomedBlock tenían firmas diferentes. Si desea compilar código que utiliza la interfaz antigua contra 8.4 sin actualizar su código, compílelo con el flag -DUSE_COMPOSITELESS_PHOTO_PUT_BLOCK. El código enlazado utilizando Stubs contra versiones anteriores de Tk seguirá funcionando.

En Tk 8.4, Tk_PhotoPutBlock, Tk_PhotoPutZoomedBlock, Tk_PhotoExpand y Tk_PhotoSetSize no tomaban un argumento interp ni devolvían ningún código de resultado. Si no había suficiente memoria disponible para una imagen, Tk entraba en pánico. Este comportamiento todavía se soporta si compila su extensión con el flag adicional -DUSE_PANIC_ON_PHOTO_ALLOC_FAILURE. El código enlazado utilizando Stubs contra versiones anteriores de Tk seguirá funcionando.

ERRORES

La estructura Tk_PhotoImageBlock utilizada para proporcionar datos de imagen a Tk_PhotoPutBlock promete gran flexibilidad en la disposición de los datos (por ejemplo, planos separados para los canales rojo, verde, azul y alfa). Desafortunadamente, la implementación no cumple esta promesa. El problema es que el campo pixelSize se utiliza (incorrectamente) para determinar si la imagen tiene un canal alfa. Actualmente, si el desplazamiento del canal alfa es mayor o igual que pixelSize, tk_PhotoPutblock asume que no hay datos alfa presentes y hace que la imagen sea completamente opaca. Esto significa que para disposiciones en las que los canales están separados (o cualquier otra disposición exótica donde pixelSize tenga que ser menor que el desplazamiento alfa), el canal alfa no se leerá correctamente. Para estar seguro si este problema se corregirá en una futura versión, se recomienda encarecidamente que siempre proporcione datos alfa, incluso si la imagen no tiene transparencia, y solo utilice la disposición "estándar" con un pixelSize de 2 para escala de grises y 4 para datos RGB con offsets de 0, 0, 0, 1 o 0, 1, 2, 3 respectivamente.
