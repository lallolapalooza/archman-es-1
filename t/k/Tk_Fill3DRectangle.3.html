ARGUMENTOS

Tcl_Interp *interp (entrada)
Intérprete a utilizar para reportar errores.
Tk_Window tkwin (entrada)
Token para la ventana (para todos los procedimientos excepto Tk_Get3DBorder), debe ser la ventana para la cual se ha asignado el borde.
Tcl_Obj *objPtr (entrada)
Puntero a un valor cuyo valor describe el color correspondiente al fondo (áreas planas). Los bordes resaltados aparecerán más brillantes que este valor y los bordes sombreados más oscuros.
const char *colorName (entrada)
Igual que objPtr, pero el valor se proporciona como una cadena en lugar de un valor.
Drawable drawable (entrada)
Token para la ventana o pixmap; indica dónde se dibujan los gráficos. Debe ser la ventana para tkwin o un pixmap con la misma pantalla y profundidad que tkwin.
Tk_3DBorder border (entrada)
Token para el borde previamente asignado en una llamada a Tk_Get3DBorder.
int x (entrada)
Coordenada x de la esquina superior izquierda del rectángulo que describe el borde o bisel, en píxeles.
int y (entrada)
Coordenada y de la esquina superior izquierda del rectángulo que describe el borde o bisel, en píxeles.
int width (entrada)
Ancho del rectángulo que describe el borde o bisel, en píxeles.
int height (entrada)
Altura del rectángulo que describe el borde o bisel, en píxeles.
int borderWidth (entrada)
Ancho del borde, en píxeles. Positivo significa que el borde está dentro de la región dada por x, y, width, height; negativo significa que el borde está fuera de la región.
int relief (entrada)
Indica la posición 3D del interior con respecto al exterior; debe ser TK_RELIEF_RAISED, TK_RELIEF_SUNKEN, TK_RELIEF_GROOVE, TK_RELIEF_SOLID o TK_RELIEF_RIDGE (también puede ser TK_RELIEF_FLAT para Tk_Fill3DRectangle).
XPoint *pointPtr (entrada)
Puntero a un array de puntos que describen los vértices de un polígono. El polígono no necesita estar cerrado (se cerrará automáticamente si no lo está).
int numPoints (entrada)
Número de puntos en pointPtr.
int polyBorderWidth (entrada)
Ancho del borde, en píxeles. Si es positivo, el borde se dibuja a la izquierda de la trayectoria dada por pointPtr; si es negativo, el borde se dibuja a la derecha de la trayectoria. Si leftRelief es TK_RELIEF_GROOVE o TK_RELIEF_RIDGE, el borde está centrado en la trayectoria.
int leftRelief (entrada)
Altura de la parte izquierda de la trayectoria del polígono en relación con la derecha. TK_RELIEF_RAISED significa que la parte izquierda debe parecer más alta, TK_RELIEF_SUNKEN que la parte derecha más alta; TK_RELIEF_GROOVE y TK_RELIEF_RIDGE significan lo obvio. Para Tk_Fill3DPolygon, también se puede especificar TK_RELIEF_FLAT para indicar que no hay diferencia en la altura.
int leftBevel (entrada)
Distinto de cero significa que este bisel forma la parte izquierda del valor; cero significa que forma la parte derecha.
int leftIn (entrada)
Distinto de cero significa que el borde izquierdo del bisel horizontal se inclina hacia adelante, por lo que la parte inferior del borde está más a la derecha que la parte superior. Cero significa que el borde se inclina hacia atrás, por lo que la parte inferior está más a la izquierda que la parte superior.
int rightIn (entrada)
Distinto de cero significa que el borde derecho del bisel horizontal se inclina hacia adelante, por lo que la parte inferior del borde está más a la izquierda que la parte superior. Cero significa que el borde se inclina hacia atrás, por lo que la parte inferior está más a la derecha que la parte superior.
int topBevel (entrada)
Distinto de cero significa que este bisel forma la parte superior del valor; cero significa que forma la parte inferior.
int which (entrada)
Indica cuál de los contextos de gráficos del borde se desea. Debe ser TK_3D_FLAT_GC, TK_3D_LIGHT_GC o TK_3D_DARK_GC.

DESCRIPCIÓN

Estos procedimientos proporcionan facilidades para dibujar bordes de ventana que produzcan una apariencia 3D. Tk_Alloc3DBorderFromObj asigna colores y pixmaps necesarios para dibujar un borde en la ventana dada por el argumento tkwin. El valor de objPtr es un nombre de color estándar de Tk que determina los colores del borde. El color indicado por objPtr no se utilizará realmente en el borde; indica el color del fondo para la ventana (es decir, un color para superficies planas). Las partes resaltadas del borde aparecerán más brillantes que el valor indicado por objPtr, y las partes sombreadas del borde aparecerán más oscuras que objPtr.

Tk_Alloc3DBorderFromObj devuelve un token que puede usarse en llamadas posteriores a Tk_Draw3DRectangle. Si ocurre un error al asignar información para el borde (por ejemplo, se proporcionó un nombre de color inválido), se devuelve NULL y se deja un mensaje de error como resultado del intérprete interp. Si devuelve con éxito, Tk_Alloc3DBorderFromObj almacena en caché información sobre el valor de retorno en objPtr, lo que acelera las llamadas posteriores a Tk_Alloc3DBorderFromObj con el mismo objPtr y tkwin.

Tk_Get3DBorder es idéntico a Tk_Alloc3DBorderFromObj, excepto que el color se especifica con una cadena en lugar de un valor. Esto evita que Tk_Get3DBorder tenga en cuenta el valor de retorno, por lo que Tk_Get3DBorder es menos eficiente que Tk_Alloc3DBorderFromObj.

Tk_Get3DBorderFromObj devuelve el token para un borde existente, dado la ventana y el nombre de color utilizados para crear el borde. Tk_Get3DBorderFromObj en realidad no crea el borde; debe haber sido creado previamente con una llamada a Tk_Alloc3DBorderFromObj o Tk_Get3DBorder. El valor de retorno se almacena en caché en objPtr, lo que acelera las llamadas posteriores a Tk_Get3DBorderFromObj con el mismo objPtr y tkwin.

Una vez que se ha creado una estructura de borde, se puede invocar Tk_Draw3DRectangle para dibujar el borde. El argumento tkwin especifica la ventana para la que se asignó el borde, y drawable especifica una ventana o pixmap en el que se dibuja el borde. drawable no debe referirse a la misma ventana que tkwin, pero debe referirse a un pixmap o ventana compatible: uno asociado con la misma pantalla y con la misma profundidad que tkwin. Los argumentos x, y, width y height definen el área del rectángulo del borde dentro de drawable (generalmente x e y son cero y width y height son las dimensiones de la ventana), y borderWidth especifica el número de píxeles que realmente ocupa el borde. El argumento relief indica qué efectos 3D se desean: TK_RELIEF_RAISED significa que el interior del rectángulo debe parecer elevado con respecto al exterior del rectángulo, y TK_RELIEF_SUNKEN significa que el interior debe parecer hundido. TK_RELIEF_GROOVE y TK_RELIEF_RIDGE significan que debería haber una ranura o una cresta alrededor del exterior del rectángulo.

DESCRIPTION

The procedures Tk_Alloc3DBorderFromObj and Tk_Get3DBorder allocate and retrieve a Tk_3DBorder object for use in drawing borders with a three-dimensional effect. Tkwin is the window for which the border is intended, and value is a Tcl object containing a string that specifies the border. The string typically consists of two color names, separated by a space. The first color is used for the highlighted border segments and the second for the shadowed segments. If only one color is specified, it is used for both. If the border string is empty, then the window's background color is used. Tk_Get3DBorder is similar to Tk_Alloc3DBorderFromObj but it will not create a new border if one already exists with the given value. The Tk_3DBorder object returned by these procedures is a token that is used in subsequent calls to other procedures.

The procedure Tk_Draw3DRectangle draws a rectangular border with a three-dimensional appearance. Drawable is the window or pixmap in which to draw, border is the border object, x, y, width, and height define the outer boundary of the rectangular area, borderWidth is the width of the border in pixels, and relief specifies the desired 3D effect. TK_RELIEF_RAISED makes the border appear raised, TK_RELIEF_SUNKEN makes it appear sunken, and TK_RELIEF_FLAT means no border is drawn. The procedure first fills the rectangular area with the background color (one corresponding to the color used to create border). Then it calls Tk_Draw3DRectangle to draw a border just inside the outer edge of the rectangular area. The argument relief indicates the desired effect (TK_RELIEF_FLAT means no border should be drawn; all that happens is to fill the rectangle with the background color).

The procedure Tk_Fill3DRectangle is similar to Tk_Draw3DRectangle, but it also fills the interior of the rectangle with the background color first. This is useful for drawing widgets like buttons.

The procedure Tk_Draw3DPolygon may be used to draw more complex shapes with a three-dimensional appearance. The pointPtr and numPoints arguments define a trajectory, polyBorderWidth indicates how wide the border should be (and on which side of the trajectory to draw it), and leftRelief indicates which side of the trajectory should appear raised. Tk_Draw3DPolygon draws a border around the given trajectory using the colors from border to produce a three-dimensional appearance. If the trajectory is non-self-intersecting, the appearance will be a raised or sunken polygon shape. The trajectory may be self-intersecting, although it's not clear how useful this is.

Tk_Fill3DPolygon is to Tk_Draw3DPolygon what Tk_Fill3DRectangle is to Tk_Draw3DRectangle: it fills the polygonal area with the background color from border, then calls Tk_Draw3DPolygon to draw a border around the area (unless leftRelief is TK_RELIEF_FLAT; in this case no border is drawn).

The procedures Tk_3DVerticalBevel and Tk_3DHorizontalBevel provide lower-level drawing primitives that are used by procedures such as Tk_Draw3DRectangle. These procedures are also useful in their own right for drawing rectilinear border shapes. Tk_3DVerticalBevel draws a vertical beveled edge, such as the left or right side of a rectangle, and Tk_3DHorizontalBevel draws a horizontal beveled edge, such as the top or bottom of a rectangle. Each procedure takes x, y, width, and height arguments that describe the rectangular area of the beveled edge (e.g., width is the border width for Tk_3DVerticalBevel). The leftBorder and topBorder arguments indicate the position of the border relative to the “inside” of the value, and relief indicates the relief of the inside of the value relative to the outside. Tk_3DVerticalBevel just draws a rectangular region. Tk_3DHorizontalBevel draws a trapezoidal region to generate mitered corners; it should be called after Tk_3DVerticalBevel (otherwise Tk_3DVerticalBevel will overwrite the mitering in the corner). The leftIn and rightIn arguments to Tk_3DHorizontalBevel describe the mitering at the corners; a value of 1 means that the bottom edge of the trapezoid will be shorter than the top, 0 means it will be longer. For example, to draw a rectangular border the top bevel should be drawn with 1 for both leftIn and rightIn, and the bottom bevel should be drawn with 0 for both arguments.

The procedure Tk_SetBackgroundFromBorder will modify the background pixel and/or pixmap of tkwin to produce a result compatible with border. For color displays, the resulting background will just be the color specified when border was created; for monochrome displays, the resulting background will be a light stipple pattern, in order to distinguish the background from the illuminated portion of the border.

Given a token for a border, the procedure Tk_NameOf3DBorder will return the color name that was used to create the border.

The procedure Tk_3DBorderColor returns the XColor structure that will be used for flat surfaces drawn for its border argument by procedures like Tk_Fill3DRectangle. The return value corresponds to the color name that was used to create the border. The XColor, and its associated pixel value, will remain allocated as long as border exists.

The procedure Tk_3DBorderGC returns one of the X graphics contexts that are used to draw the border. The argument which selects which one of the three possible GC's: TK_3D_FLAT_GC returns the context used for flat surfaces, TK_3D_LIGHT_GC returns the context for light shadows, and TK_3D_DARK_GC returns the context for dark shadows.

When a border is no longer needed, Tk_Free3DBorderFromObj or Tk_Free3DBorder should be called to release the resources associated with it. For Tk_Free3DBorderFromObj the border to release is specified with the window and color name used to create the border; for Tk_Free3DBorder the border to release is specified with the Tk_3DBorder token for the border. There should be exactly one call to Tk_Free3DBorderFromObj or Tk_Free3DBorder for each call to Tk_Alloc3DBorderFromObj or Tk_Get3DBorder.
