Tk_ConfigureWidget(3) Procedimientos de la librería Tk Tk_ConfigureWidget(3)

NAME

Tk_ConfigureWidget, Tk_ConfigureInfo, Tk_ConfigureValue, Tk_FreeOptions - procesar opciones de configuración para widgets

SYNOPSIS

#include <tk.h>

int
Tk_ConfigureWidget(interp, tkwin, specs, argc, argv, widgRec, flags)

int
Tk_ConfigureInfo(interp, tkwin, specs, widgRec, argvName, flags)

int
Tk_ConfigureValue(interp, tkwin, specs, widgRec, argvName, flags)

Tk_FreeOptions(specs, widgRec, display, flags)

DESCRIPCIÓN

Tk_ConfigureWidget se llama para configurar varios aspectos de un widget, como colores, fuentes, ancho de borde, etc. Es un procedimiento de conveniencia para reducir el código que debe escribirse en cada gestor de widget para manejar la información de configuración. Se invoca normalmente cuando se crean widgets, y nuevamente cuando se invoca el comando configure para un widget. Aunque se planea principalmente para widgets, Tk_ConfigureWidget puede usarse en otros contextos donde se utilice argc-argv para llenar una estructura de registro, como configurar elementos gráficos en un widget de canvas o entradas de un menú.

Tk_ConfigureWidget procesa una tabla que especifica las opciones de configuración soportadas (specs) y una colección de argumentos de línea de comandos (argc y argv) para llenar los campos de una estructura de registro (widgRec). Usa la base de datos de opciones y los valores por defecto especificados en specs para llenar los campos de widgRec que no estén especificados en argv. Tk_ConfigureWidget normalmente devuelve TCL_OK; en este caso, no modifica interp. Si hay un error, se devuelve TCL_ERROR y se deja un mensaje de error en interp en la forma estándar de Tcl. Si hay un retorno de error, algunos de los campos de widgRec podrían ya estar configurados, si la información de configuración para ellos fue procesada correctamente antes de que se produzca el error. Los otros campos se establecen a valores iniciales razonables para que Tk_FreeOptions pueda llamarse para limpieza.

El specs es un array que especifica el tipo de opciones de configuración esperadas por el widget. Cada entrada tiene la siguiente estructura:

typedef struct {
    int type;
    const char *argvName;
    const char *dbName;
    const char *dbClass;
    const char *defValue;
    int offset;
    int specFlags;
    const Tk_CustomOption *customPtr;
} Tk_ConfigSpec;
El campo type indica el tipo de opción de configuración (por ejemplo, TK_CONFIG_COLOR para un valor de color, o TK_CONFIG_INT para un valor entero). El campo type indica cómo usar el valor de la opción (más información en el siguiente párrafo). El campo argvName es una cadena como -font o -bg, que se compara con los valores en argv (si argvName es nulo, significa que es un entrada agrupada; vea GROUPED ENTRIES a continuación). Los campos dbName y dbClass se usan para buscar un valor para esta opción en la base de datos de opciones. El campo defValue especifica un valor por defecto para esta opción si no se especifica ningún valor en argv o en la base de datos de opciones. El campo offset indica dónde en widgRec se almacena la información sobre esta opción, y specFlags contiene información adicional para controlar el procesamiento de esta opción (ver FLAGS a continuación). El último campo, customPtr, se usa solo si type es TK_CONFIG_CUSTOM; vea CUSTOM OPTION TYPES a continuación.

Tk_ConfigureWidget primero procesa argv para ver qué opciones de configuración (si las hay) se especifican allí. Argv debe contener un número par de campos; el primer campo de cada par debe coincidir con el argvName de alguna entrada en specs (se aceptan abreviaturas únicas), y el segundo campo contiene el valor para esa opción de configuración. Si hay entradas en spec para las cuales no hay correspondientes en argv, Tk_ConfigureWidget usa los campos dbName y dbClass de la entrada correspondiente en specs para probar la base de datos de opciones; si se encuentra un valor, se usa como valor para la opción. Finalmente, si no se encuentra ningún registro en la base de datos, se usa el valor de defValue de la entrada correspondiente en specs como valor para la opción de configuración. Si el defValue es nulo, o si el bit TK_CONFIG_DONT_SET_DEFAULT está seteado en flags, entonces no hay valor por defecto y esta entrada de specs se ignorará si no se especifica ningún valor en argv o en la base de datos de opciones.

Una vez que se ha determinado un valor para una opción de configuración, Tk_ConfigureWidget traduce el valor de cadena en una forma más útil, como un color si type es TK_CONFIG_COLOR o un entero si type es TK_CONFIG_INT. Este valor se almacena en el registro señalado por widgRec. Este registro se asume para contener información relevante para el gestor del widget; su tipo exacto no es conocido por Tk_ConfigureWidget. El campo offset de cada entrada en specs indica dónde en widgRec se almacena la información sobre esta opción de configuración. Deberías usar la macro Tk_Offset para generar los valores de offset (véase una descripción de Tk_Offset a continuación). La ubicación indicada por widgRec y offset se referirá como el "target" en las descripciones a continuación.

El campo type de cada entrada en specs determina qué hacer con el valor de cadena de esa opción de configuración. Los valores legales para type y las acciones correspondientes son:

TK_CONFIG_ACTIVE_CURSOR
El valor debe ser una cadena ASCII identificando un cursor adecuado para pasar a Tk_GetCursor. El valor se convierte en un Tk_Cursor llamando a Tk_GetCursor, y el resultado se almacena en el target. Además, el cursor resultado se hace el cursor activo de tkwin llamando a XDefineCursor. Si TK_CONFIG_NULL_OK está especificado en specFlags, el valor puede ser una cadena vacía, en cuyo caso el target y el cursor activo de tkwin se establecen a None. Si el valor anterior del target no era None, se libera pasando el valor a Tk_FreeCursor.
TK_CONFIG_ANCHOR
El valor debe ser una cadena ASCII identificando un punto de anclaje en uno de los métodos aceptados por Tk_GetAnchor. La cadena se convierte en un Tk_Anchor y se utiliza como valor para el target. El valor se busca en la base de datos de opciones mediante Tk_GetAnchor, y si se encuentra un valor, se usa como valor para la opción. Si no se encuentra ningún valor en la base de datos, se usa el valor de defValue de la entrada correspondiente en specs. Si el defValue es nulo, o si el bit TK_CONFIG_DONT_SET_DEFAULT está seteado en flags, entonces no hay valor por defecto y esta entrada de specs se ignorará si no se especifica ningún valor en argv o en la base de datos de opciones.

El campo type de cada entrada en specs determina qué hacer con el valor de cadena de esa opción de configuración. Los valores legales para type y las acciones correspondientes son:

TK_CONFIG_ACTIVE_CURSOR
El valor debe ser una cadena ASCII identificando un cursor en un formato adecuado para pasar a Tk_GetCursor. El valor se convierte en un Tk_Cursor llamando a Tk_GetCursor y el resultado se almacena en el target. Además, el cursor resultado se hace el cursor activo de tkwin llamando a XDefineCursor. Si TK_CONFIG_NULL_OK está especificado en specFlags, el valor puede ser una cadena vacía, en cuyo caso el target y el cursor activo de tkwin se establecen a None. Si el valor anterior del target no era None, se libera pasando el valor a Tk_FreeCursor.
TK_CONFIG_ANCHOR
El valor debe ser una cadena ASCII identificando un punto de anclaje en uno de los métodos aceptados por Tk_GetAnchor. La cadena se convierte en un Tk_Anchor y se utiliza como valor para el target. El valor se busca en la base de datos de opciones mediante Tk_GetAnchor, y si se encuentra un valor, se usa como valor para la opción. Si no se encuentra ningún valor en la base de datos, se usa el valor de defValue de la entrada correspondiente en specs. Si el defValue es nulo, o si el bit TK_CONFIG_DONT_SET_DEFAULT está seteado en flags, entonces no hay valor por defecto y esta entrada de specs se ignorará si no se especifica ningún valor en argv o en la base de datos de opciones.

TK_CONFIG_BITMAP

TK_CONFIG_BOOLEAN

Cualquiera de los valores “true”, “yes”, “on” o “1”, o una abreviatura de uno de estos valores, significa verdadero; cualquiera de los valores “false”, “no”, “off” o “0”, o una abreviatura de uno de estos valores, significa falso. Se espera que el destino sea un entero; para los valores verdaderos se establecerá en 1 y para los valores falsos se establecerá en 0.
TK_CONFIG_BORDER

El valor se convierte en un (Tk_3DBorder *) llamando a Tk_Get3DBorder y el resultado se almacena en el destino. Si el valor anterior del destino no era NULL, se libera pasándolo a Tk_Free3DBorder.
TK_CONFIG_CAP_STYLE
El valor debe ser una cadena de texto ASCII que identifique un estilo de extremo en una de las formas aceptadas por Tk_GetCapStyle. La cadena se convierte en un valor entero correspondiente al estilo de extremo llamando a Tk_GetCapStyle y el resultado se almacena en el destino.
TK_CONFIG_COLOR
El valor debe ser una cadena de texto ASCII que identifique un color en un formato adecuado para pasar a Tk_GetColor. El valor se convierte en un (XColor *) llamando a Tk_GetColor y el resultado se almacena en el destino. Si se especifica TK_CONFIG_NULL_OK en specFlags, el valor puede ser una cadena vacía, en cuyo caso el destino se establecerá en None. Si el valor anterior del destino no era NULL, se libera pasándolo a Tk_FreeColor.
TK_CONFIG_CURSOR
Esta opción es idéntica a TK_CONFIG_ACTIVE_CURSOR, excepto que el nuevo cursor no se convierte en el cursor activo para tkwin.
TK_CONFIG_CUSTOM
Esta opción permite a las aplicaciones definir nuevos tipos de opciones. El campo customPtr del elemento apunta a una estructura que define el nuevo tipo de opción. Consulte la sección TIPOS DE OPCIONES PERSONALIZADAS a continuación para obtener más detalles.
TK_CONFIG_DOUBLE
El valor debe ser un número de punto flotante ASCII en el formato aceptado por strtol. La cadena se convierte en un valor double y el valor se almacena en el destino.
TK_CONFIG_END
Marca el final de la tabla. El último elemento en specs debe tener este tipo; todos sus demás campos se ignoran y nunca coincidirá con ningún argumento.
TK_CONFIG_FONT
El valor debe ser una cadena de texto ASCII que identifique una fuente en un formato adecuado para pasar a Tk_GetFont. El valor se convierte en una Tk_Font llamando a Tk_GetFont y el resultado se almacena en el destino. Si se especifica TK_CONFIG_NULL_OK en specFlags, el valor puede ser una cadena vacía, en cuyo caso el destino se establecerá en NULL. Si el valor anterior del destino no era NULL, se libera pasándolo a Tk_FreeFont.
TK_CONFIG_INT
El valor debe ser una cadena de enteros ASCII en el formato aceptado por strtol (por ejemplo, se pueden usar prefijos “0” y “0x” para especificar números octales o hexadecimales, respectivamente). La cadena se convierte en un valor entero y el entero se almacena en el destino.
TK_CONFIG_JOIN_STYLE
El valor debe ser una cadena de texto ASCII que identifique un estilo de unión en una de las formas aceptadas por Tk_GetJoinStyle. La cadena se convierte en un valor entero correspondiente al estilo de unión llamando a Tk_GetJoinStyle y el resultado se almacena en el destino.
TK_CONFIG_JUSTIFY
El valor debe ser una cadena de texto ASCII que identifique un método de justificación en una de las formas aceptadas por Tk_GetJustify. La cadena se convierte en una Tk_Justify llamando a Tk_GetJustify y el resultado se almacena en el destino.
TK_CONFIG_MM
El valor debe especificar una distancia en pantalla en una de las formas aceptables para Tk_GetScreenMM. La cadena se convierte en una distancia en milímetros de punto flotante de doble precisión y el valor se almacena en el destino.
TK_CONFIG_PIXELS
El valor debe especificar unidades de pantalla en una de las formas aceptables para Tk_GetPixels. La cadena se convierte en una distancia entera en píxeles y el valor se almacena en el destino.
TK_CONFIG_RELIEF
El valor debe ser una cadena de texto ASCII que identifique un relieve en un formato adecuado para pasar a Tk_GetRelief. El valor se convierte en un valor entero de relieve llamando a Tk_GetRelief y el resultado se almacena en el destino.
TK_CONFIG_STRING
Se realiza una copia del valor asignando espacio de memoria con Tcl_Alloc y copiando el valor en el espacio asignado dinámicamente. Se almacena un puntero a la nueva cadena en el destino. Si se especifica TK_CONFIG_NULL_OK en specFlags, el valor puede ser una cadena vacía, en cuyo caso el destino se establecerá en NULL. Si el valor anterior del destino no era NULL, se libera pasándolo a Tcl_Free.
TK_CONFIG_SYNONYM
Este valor de type identifica entradas especiales en specs que son sinónimos de otras entradas. Si un valor de argv coincide con el argvName de una entrada TK_CONFIG_SYNONYM, la entrada no se utiliza directamente. En su lugar, Tk_ConfigureWidget busca en specs otra entrada cuyo argvName sea el mismo que el campo dbName en la entrada TK_CONFIG_SYNONYM; esta nueva entrada se utiliza como si su argvName hubiera coincidido con el valor de argv. El mecanismo de sinónimos permite utilizar múltiples valores de argv para una sola opción de configuración, como “-background” y “-bg”.
TK_CONFIG_UID
El valor se traduce a un Tk_Uid (pasándolo a Tk_GetUid). El valor resultante se almacena en el destino. Si se especifica TK_CONFIG_NULL_OK en specFlags y el valor es una cadena vacía, el destino se establecerá en NULL.
TK_CONFIG_WINDOW
El valor debe ser un nombre de ruta de ventana. Se traduce a un token Tk_Window y el token se almacena en el destino.

ENTRADAS AGRUPADAS

En algunos casos es útil generar múltiples recursos a partir de un único valor de configuración. Por ejemplo, un nombre de color podría usarse tanto para generar el color de fondo de un widget (usando TK_CONFIG_COLOR) como para generar un borde 3D para dibujar alrededor del widget (usando TK_CONFIG_BORDER). En casos como este, es posible especificar que varias entradas consecutivas en specs se traten como un grupo. La primera entrada se utiliza para determinar un valor (usando sus campos argvName, dbName, dbClass y defValue). El valor se procesará varias veces (una por cada entrada del grupo), generando múltiples recursos diferentes y modificando múltiples destinos dentro de widgRec. Cada una de las entradas posteriores a la primera debe tener un valor NULL en su campo argvName; esto indica que la entrada debe agruparse con la entrada que la precede. Solo se utilizan los campos type y offset de estas entradas posteriores.

FLAGS

El argumento flags pasado a Tk_ConfigureWidget se utiliza junto con los campos specFlags en las entradas de specs para proporcionar control adicional sobre el procesamiento de las opciones de configuración. Estos valores se utilizan de tres maneras diferentes, como se describe a continuación.

En primer lugar, si el argumento flags de Tk_ConfigureWidget tiene el bit TK_CONFIG_ARGV_ONLY establecido (es decir, flags | TK_CONFIG_ARGV_ONLY != 0), entonces la base de datos de opciones y los campos defValue no se utilizan. En este caso, si una entrada en specs no coincide con un campo en argv, no sucede nada: el destino correspondiente no se modifica. Esta característica es útil cuando el objetivo es modificar ciertas opciones de configuración mientras se dejan otras en su estado actual, como cuando se procesa un comando de widget configure.

En segundo lugar, el campo specFlags de una entrada en specs puede usarse para controlar el procesamiento de esa entrada. Cada campo specFlags puede consistir en una combinación OR de los siguientes valores:

TK_CONFIG_COLOR_ONLY
Si este bit está establecido, la entrada solo se considerará si la pantalla para tkwin tiene más de un plano de bits. Si la pantalla es monocromática, esta entrada de specs se ignorará.
TK_CONFIG_MONO_ONLY
Si este bit está establecido, la entrada solo se considerará si la pantalla para tkwin tiene exactamente un plano de bits. Si la pantalla no es monocromática, esta entrada de specs se ignorará.
TK_CONFIG_NULL_OK
Este bit solo es relevante para algunos tipos de entradas (ver las descripciones de los diversos tipos de entrada anteriores). Si este bit está establecido, indica que un valor de cadena vacía para el campo es aceptable y si ocurre, entonces el destino se establecerá en NULL o None, dependiendo del tipo de destino. Esta bandera se usa típicamente para permitir que una característica se desactive por completo, por ejemplo, establecer un valor de cursor en None para que una ventana simplemente herede el cursor de su padre. Si este bit no está establecido, entonces las cadenas vacías se procesan como cadenas, lo que generalmente resulta en un error.
TK_CONFIG_DONT_SET_DEFAULT
Si este bit es uno, significa que el campo defValue de la entrada solo debe usarse para devolver el valor predeterminado en Tk_ConfigureInfo. En las llamadas a Tk_ConfigureWidget no se proporcionará ningún valor predeterminado para las entradas con esta bandera establecida; se asume que el llamador ya ha proporcionado un valor predeterminado en la ubicación de destino. Esta bandera proporciona una optimización de rendimiento donde es costoso procesar la cadena predeterminada: el cliente puede calcular el valor predeterminado una vez, guardar el valor y proporcionarlo antes de llamar a Tk_ConfigureWidget.
TK_CONFIG_OPTION_SPECIFIED
Este bit está obsoleto. Solía ser establecido y borrado por Tk_ConfigureWidget para que los llamadores pudieran detectar qué entradas estaban especificadas en argv, pero fue eliminado porque era inherentemente no seguro para hilos. El código que desee detectar qué opciones se especificaron debería usar Tk_SetOptions en su lugar.

Las banderas TK_CONFIG_MONO_ONLY y TK_CONFIG_COLOR_ONLY se usan típicamente para especificar valores predeterminados diferentes para pantallas monocromáticas y en color. Esto se hace creando dos entradas en specs que son idénticas excepto por sus campos defValue y specFlags. Una entrada debe tener el valor TK_CONFIG_MONO_ONLY en sus specFlags y el valor predeterminado para pantallas monocromáticas en su defValue; la otra entrada debe tener el valor TK_CONFIG_COLOR_ONLY en sus specFlags y el defValue apropiado para pantallas en color.

En tercer lugar, es posible usar flags y specFlags juntos para deshabilitar selectivamente algunas entradas. Esta característica no se necesita con mucha frecuencia. Es útil en casos donde varios tipos similares de widgets se implementan en un solo lugar. Permite crear una tabla specs única con todas las opciones de configuración para todos los tipos de widgets. Al procesar un tipo de widget particular, solo se utilizarán las entradas relevantes para ese tipo. Este efecto se logra estableciendo los bits de orden superior (aquellos en posiciones iguales o mayores que TK_CONFIG_USER_BIT) en specFlags o en flags. Para que una entrada particular en specs sea utilizada, sus bits de orden superior deben coincidir exactamente con los bits de orden superior del valor flags pasado a Tk_ConfigureWidget. Si una tabla specs se está utilizando para N tipos de widgets diferentes, entonces se usarán N de los bits de orden superior. Cada entrada specs tendrá uno o más de esos bits establecidos en su campo specFlags para indicar los tipos de widgets para los que esta entrada es válida. Al llamar a Tk_ConfigureWidget, flags tendrá un solo uno de estos bits establecido para seleccionar las entradas del tipo de widget deseado. Para un ejemplo funcional de esta característica, consulte el código en tkButton.c.

TK_OFFSET

La macro Tk_Offset se proporciona como una forma segura de generar los valores offset para las entradas en las estructuras Tk_ConfigSpec. Toma dos argumentos: el nombre de un tipo de registro y el nombre de un campo en ese registro. Devuelve el desplazamiento en bytes del campo nombrado en registros del tipo dado.

TK_CONFIGUREINFO

El procedimiento Tk_ConfigureInfo puede usarse para obtener información sobre una o todas las opciones para un widget dado. Dado un token para una ventana (tkwin), una tabla que describe las opciones de configuración para una clase de widgets (specs), un puntero a un registro de widget que contiene la información actual para un widget (widgRec), y un argumento argvName NULL, Tk_ConfigureInfo genera una cadena que describe todas las opciones de configuración para la ventana. La cadena se coloca en el resultado del intérprete interp. En circunstancias normales, devuelve TCL_OK; si ocurre un error, devuelve TCL_ERROR y el resultado del intérprete contendrá un mensaje de error.

Si argvName es NULL, entonces el valor dejado en el resultado del intérprete por Tk_ConfigureInfo consiste en una lista de una o más entradas, cada una de las cuales describe una opción de configuración (es decir, una entrada en specs). Cada entrada de la lista contendrá dos o cinco valores. Si la entrada correspondiente en specs tiene el tipo TK_CONFIG_SYNONYM, entonces la lista contendrá dos valores: el argvName para la entrada y el dbName (nombre sinónimo). De lo contrario, la lista contendrá cinco valores: argvName, dbName, dbClass, defValue y el valor actual. El valor actual se calcula a partir del campo apropiado de widgRec llamando a procedimientos como Tk_NameOfColor.

Si el argumento argvName a Tk_ConfigureInfo no es NULL, entonces indica una sola opción, y la información se devuelve solo para esa opción. La cadena colocada en el resultado del intérprete será una lista que contiene dos o cinco valores como se describió anteriormente; esto será idéntico a la sublista correspondiente que se habría devuelto si argvName hubiera sido NULL.

El argumento flags a Tk_ConfigureInfo se utiliza para restringir las entradas de specs a considerar, al igual que para Tk_ConfigureWidget.

TK_CONFIGUREVALUE

Tk_ConfigureValue toma argumentos similares a Tk_ConfigureInfo; en lugar de devolver una lista de valores, simplemente devuelve el valor actual de la opción dada por argvName (argvName no debe ser NULL). El valor se devuelve en el resultado del intérprete interp y normalmente se devuelve TCL_OK como resultado del procedimiento. Si ocurre un error en Tk_ConfigureValue (por ejemplo, argvName no es un nombre de opción válido), se devuelve TCL_ERROR y se deja un mensaje de error en el resultado del intérprete. Este procedimiento se llama típicamente para implementar los comandos de widget cget.

TK_FREEOPTIONS

El procedimiento Tk_FreeOptions puede invocarse durante la limpieza del widget para liberar todos los recursos asociados con las opciones de configuración. Escanea specs y para cada entrada correspondiente a un recurso que debe liberarse explícitamente (por ejemplo, aquellos con el tipo TK_CONFIG_COLOR), libera el recurso en el registro del widget. Si el campo en el registro del widget no se refiere a un recurso (por ejemplo, contiene un puntero nulo), entonces no se libera ningún recurso para esa entrada. Después de liberar un recurso, Tk_FreeOptions establece el campo correspondiente del registro del widget a nulo.

TIPOS DE OPCIONES PERSONALIZADAS

Las aplicaciones pueden extender los tipos de configuración integrados con tipos de configuración adicionales escribiendo procedimientos para analizar e imprimir opciones de un tipo y creando una estructura que apunte a esos procedimientos:

typedef struct Tk_CustomOption {
    Tk_OptionParseProc *parseProc;
    Tk_OptionPrintProc *printProc;
    ClientData clientData;
} Tk_CustomOption;
typedef int Tk_OptionParseProc(
        ClientData clientData,
        Tcl_Interp *interp,
        Tk_Window tkwin,
        char *value,
        char *widgRec,
        int offset);
typedef const char *Tk_OptionPrintProc(
        ClientData clientData,
        Tk_Window tkwin,
        char *widgRec,
        int offset,
        Tcl_FreeProc **freeProcPtr);
La estructura Tk_CustomOption contiene tres campos, que son punteros a los dos procedimientos y un valor clientData que se pasará a esos procedimientos cuando se invoquen. El valor clientData típicamente apunta a una estructura que contiene información necesaria para los procedimientos cuando analizan e imprimen opciones.

El procedimiento parseProc es invocado por Tk_ConfigureWidget para analizar una cadena y almacenar el valor resultante en el registro del widget. El argumento clientData es una copia del campo clientData en la estructura Tk_CustomOption. El argumento interp apunta a un intérprete Tcl utilizado para la generación de informes de errores. Tkwin es una copia del argumento tkwin a Tk_ConfigureWidget. El argumento value es una cadena que describe el valor de la opción; podría haber sido especificado explícitamente en la llamada a Tk_ConfigureWidget o podría provenir de la base de datos de opciones o de un valor predeterminado. value nunca será un puntero nulo pero puede apuntar a una cadena vacía. widgRec es el mismo que el argumento widgRec a Tk_ConfigureWidget; apunta al inicio del registro del widget a modificar. El último argumento, offset, indica el desplazamiento en bytes desde el inicio del registro del widget hasta la ubicación donde se colocará el valor de la opción. El procedimiento debe traducir la cadena a la forma que sea apropiada para la opción y almacenar el valor en el registro del widget. Normalmente debería devolver TCL_OK, pero si ocurre un error al traducir la cadena a un valor, debería devolver TCL_ERROR y almacenar un mensaje de error en el resultado del intérprete interp.

El procedimiento printProc es llamado por Tk_ConfigureInfo para producir un valor de cadena que describe una opción existente. Sus argumentos clientData, tkwin, widgRec y offset tienen el mismo significado que para los procedimientos Tk_OptionParseProc. El procedimiento printProc debe examinar la opción cuyo valor se almacena en offset en widgRec, producir una cadena que describa esa opción y devolver un puntero a la cadena. Si la cadena está almacenada en memoria asignada dinámicamente, entonces el procedimiento debe establecer *freeProcPtr a la dirección de un procedimiento para llamar para liberar la memoria de la cadena; Tk_ConfigureInfo llamará a este procedimiento cuando[ { "text": "con el string.
