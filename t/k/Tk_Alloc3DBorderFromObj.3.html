ARGUMENTOS

Tcl_Interp *interp (entrada)
Intérprete a usar para reportar errores.
Tk_Window tkwin (entrada)
Token para la ventana (para todos los procedimientos excepto Tk_Get3DBorder, debe ser la ventana para la cual se asignó el borde).
Tcl_Obj *objPtr (entrada)
Puntero al valor cuya descripción del color corresponde al fondo (áreas planas). Los bordes iluminados serán más brillantes que este y los bordes sombreados serán más oscuros que este.
const char *colorName (entrada)
Igual que objPtr excepto que el valor se proporciona como una cadena en lugar de un valor.
Drawable drawable (entrada)
Token de X para la ventana o pixmap; indica dónde se van a dibujar los gráficos. Debe ser la ventana X de tkwin o un pixmap con la misma pantalla y profundidad que tkwin.
Tk_3DBorder border (entrada)
Token para el borde previamente asignado en una llamada a Tk_Get3DBorder.
int x (entrada)
Coordenada X de la esquina superior izquierda del rectángulo que describe el borde o bisel, en píxeles.
int y (entrada)
Coordenada Y de la esquina superior izquierda del rectángulo que describe el borde o bisel, en píxeles.
int width (entrada)
Ancho del rectángulo que describe el borde o bisel, en píxeles.
int height (entrada)
Altura del rectángulo que describe el borde o bisel, en píxeles.
int borderWidth (entrada)
Ancho del borde en píxeles. Un valor positivo significa que el borde está dentro del rectángulo dado por x, y, width, height; un valor negativo significa que el borde está fuera del rectángulo.
int relief (entrada)
Indica la posición 3D del interior del valor en relación con el exterior; debe ser TK_RELIEF_RAISED, TK_RELIEF_SUNKEN, TK_RELIEF_GROOVE, TK_RELIEF_SOLID, o TK_RELIEF_RIDGE (también puede ser TK_RELIEF_FLAT para Tk_Fill3DRectangle).
XPoint *pointPtr (entrada)
Puntero a un arreglo de puntos que describen el conjunto de vértices en un polígono. El polígono no necesita estar cerrado (se cerrará automáticamente si no lo está).
int numPoints (entrada)
Número de puntos en *pointPtr.
int polyBorderWidth (entrada)
Ancho del borde en píxeles. Si es positivo, el borde se dibuja a la izquierda de la trayectoria dada por pointPtr; si es negativo, el borde se dibuja a la derecha de la trayectoria. Si leftRelief es TK_RELIEF_GROOVE o TK_RELIEF_RIDGE, el borde se centra en la trayectoria.
int leftRelief (entrada)
Altura del lado izquierdo de la ruta del polígono en relación con el derecho. TK_RELIEF_RAISED significa que el lado izquierdo debe parecer más alto y TK_RELIEF_SUNKEN significa que el lado derecho debe parecer más alto; TK_RELIEF_GROOVE y TK_RELIEF_RIDGE significan lo obvio. Para Tk_Fill3DPolygon, TK_RELIEF_FLAT también puede especificarse para indicar que no hay diferencia de altura.
int leftBevel (entrada)
Si es distinto de cero, este bisel forma el lado izquierdo del valor; si es cero, forma el lado derecho.
int leftIn (entrada)
Si es distinto de cero, el borde izquierdo del bisel horizontal se inclina hacia adentro, de modo que la parte inferior del borde esté más a la derecha que la superior. Si es cero, el borde se inclina hacia afuera, de modo que la parte inferior esté más a la izquierda que la superior.
int rightIn (entrada)
Si es distinto de cero, el borde derecho del bisel horizontal se inclina hacia adentro, de modo que la parte inferior del borde esté más a la izquierda que la superior. Si es cero, el borde se inclina hacia afuera, de modo que la parte inferior esté más a la derecha que la superior.
int topBevel (entrada)
Si es distinto de cero, este bisel forma el lado superior del valor; si es cero, forma el lado inferior.
int which (entrada)
Especifica cuál de los contextos gráficos del borde se desea. Debe ser TK_3D_FLAT_GC, TK_3D_LIGHT_GC, o TK_3D_DARK_GC.

DESCRIPCIÓN

Estos procedimientos proporcionan utilidades para dibujar bordes de ventanas de una manera que produce una apariencia tridimensional. Tk_Alloc3DBorderFromObj asigna colores y Pixmaps necesarios para dibujar un borde en la ventana proporcionada por el argumento tkwin. El valor de objPtr es un nombre de color estándar de Tk que determina los colores del borde. El color indicado por objPtr no se usará realmente en el borde; indica el color de fondo de la ventana (es decir, un color para las superficies planas). Las porciones iluminadas del borde aparecerán más brillantes que las indicadas por objPtr, y las porciones sombreadas del borde aparecerán más oscuras que objPtr.

Tk_Alloc3DBorderFromObj devuelve un token que puede usarse en llamadas posteriores a Tk_Draw3DRectangle. Si ocurre un error al asignar información para el borde (por ejemplo, se dio un nombre de color inválido), se devuelve NULL y se deja un mensaje de error como resultado del intérprete interp. Si devuelve éxito, Tk_Alloc3DBorderFromObj almacena en caché información sobre el valor de retorno en objPtr, lo que acelera las llamadas futuras a Tk_Alloc3DBorderFromObj con el mismo objPtr y tkwin.

Tk_Get3DBorder es idéntico a Tk_Alloc3DBorderFromObj excepto que el color se especifica con una cadena en lugar de un valor. Esto evita que Tk_Get3DBorder almacene en caché el valor de retorno, por lo que Tk_Get3DBorder es menos eficiente que Tk_Alloc3DBorderFromObj.

Tk_Get3DBorderFromObj devuelve el token de un borde existente, dada la ventana y el nombre de color utilizados para crear el borde. Tk_Get3DBorderFromObj no crea realmente el borde; debe haber sido creado previamente con una llamada a Tk_Alloc3DBorderFromObj o Tk_Get3DBorder. El valor de retorno se almacena en caché en objPtr, lo que acelera las llamadas futuras a Tk_Get3DBorderFromObj con el mismo objPtr y tkwin.

Una vez creado un estructure de borde, se puede invocar Tk_Draw3DRectangle para dibujar el borde. El argumento tkwin especifica la ventana para la cual se asignó el borde, y drawable especifica una ventana o pixmap en la que se dibujará el borde. Drawable no necesita referirse a la misma ventana que tkwin, pero debe referirse a un pixmap o ventana compatible: uno asociado con la misma pantalla y con la misma profundidad que tkwin. Los argumentos x, y, width, e height definen el cuadro delimitador de la región del borde dentro de drawable (generalmente x e y son cero y width y height son las dimensiones de la ventana), y borderWidth especifica el número de píxeles ocupados realmente por el borde. El argumento relief indica cuál de varios efectos tridimensionales se desea: TK_RELIEF_RAISED significa que el interior del rectángulo debe parecer elevado en relación con el exterior del rectángulo, y TK_RELIEF_SUNKEN significa que el interior debe parecer hundido. TK_RELIEF_GROOVE y TK_RELIEF_RIDGE significan que debe parecer haber una ranura o cresta alrededor del exterior del rectángulo.

ARGUMENTS

See Tk_Alloc3DBorderFromObj(3) for arguments to allocation/freeing procedures.

border: Specifies the border to use. This is a token returned by Tk_Alloc3DBorderFromObj(3) or Tk_Get3DBorder(3).

tkwin: The window containing the drawing surface. Used to get screen-specific information.

drawable: The X drawable on which to draw.

value: For Tk_Alloc3DBorderFromObj(3), this is a Tcl object specifying the border. See the Tk manual entry for the <<Color>> type for details on border specifications.

tkborder: For Tk_Get3DBorder(3), this is a string naming a border that has already been allocated.

which: For Tk_3DBorderGC(3), selects which of the graphics contexts associated with the border is returned. Valid values are TK_3D_FLAT_GC, TK_3D_LIGHT_GC, and TK_3D_DARK_GC.

x, y, width, height: Specify a rectangular area.

borderWidth: For rectangle procedures, this is the width of the border to be drawn. For Tk_Fill3DRectangle(3) and Tk_Draw3DRectangle(3), this is the width of the border around the rectangle. For Tk_Fill3DPolygon(3) and Tk_Draw3DPolygon(3), this is the width of the border around the polygon.

relief: For Tk_Fill3DRectangle(3) and Tk_Draw3DRectangle(3), indicates the desired 3D relief effect for the rectangle. Valid values are TK_RELIEF_FLAT, TK_RELIEF_RAISED, TK_RELIEF_SUNKEN, TK_RELIEF_GROOVE, TK_RELIEF_RIDGE. For Tk_Fill3DPolygon(3) and Tk_Draw3DPolygon(3), this argument is named leftRelief and indicates which side of the polygon should appear raised.

pointPtr, numPoints: Define a polygon by its vertices.

polyBorderWidth: For polygon procedures, this is the width of the border to be drawn around the polygon.

leftRelief: For Tk_Fill3DPolygon(3) and Tk_Draw3DPolygon(3), indicates which side of the polygon should appear raised.

bevelWidth: For beveling procedures, this is the width of the beveled edge.

leftBorder, topBorder: For Tk_3DVerticalBevel(3), these indicate the position of the border relative to the inside of the value. For Tk_3DHorizontalBevel(3), these indicate the mitering at the corners.

leftIn, rightIn: For Tk_3DHorizontalBevel(3), these arguments describe the mitering at the corners. A value of 1 means that the bottom edge of the trapezoid will be shorter than the top, 0 means it will be longer.

DESCRIPTION

These procedures provide support for drawing three-dimensional border effects in Tk.

The procedures Tk_Alloc3DBorderFromObj(3) and Tk_Get3DBorder(3) are used to allocate 3D borders. Tk_Alloc3DBorderFromObj(3) allocates a border based on the Tcl object value and associates it with the window tkwin. Tk_Get3DBorder(3) retrieves a previously allocated border associated with the string tkborder. Both return a token of type Tk_3DBorder that can be used in subsequent calls to drawing and freeing procedures. Borders should be freed when no longer needed using Tk_Free3DBorderFromObj(3) or Tk_Free3DBorder(3).

Tk_Fill3DRectangle(3) fills the rectangular area specified by x, y, width, and height with the background color associated with the specified border. Then, it calls Tk_Draw3DRectangle(3) to draw a border just inside the outer edge of the rectangular area. The relief argument indicates the desired effect. TK_RELIEF_FLAT means no border should be drawn; only the rectangle is filled with the background color. TK_RELIEF_RAISED and TK_RELIEF_SUNKEN create raised and sunken borders, respectively. TK_RELIEF_GROOVE and TK_RELIEF_RIDGE create borders that appear as grooves or ridges.

The procedure Tk_Draw3DRectangle(3) draws only the border of a rectangle, without filling the interior. It draws a border just inside the outer edge of the rectangular area. The relief argument indicates the desired effect (TK_RELIEF_FLAT means no border should be drawn; all that happens is to fill the rectangle with the background color).

The procedure Tk_Draw3DPolygon may be used to draw more complex shapes with a three-dimensional appearance. The pointPtr and numPoints arguments define a trajectory, polyBorderWidth indicates how wide the border should be (and on which side of the trajectory to draw it), and leftRelief indicates which side of the trajectory should appear raised. Tk_Draw3DPolygon draws a border around the given trajectory using the colors from border to produce a three-dimensional appearance. If the trajectory is non-self-intersecting, the appearance will be a raised or sunken polygon shape. The trajectory may be self-intersecting, although it's not clear how useful this is.

Tk_Fill3DPolygon is to Tk_Draw3DPolygon what Tk_Fill3DRectangle is to Tk_Draw3DRectangle: it fills the polygonal area with the background color from border, then calls Tk_Draw3DPolygon to draw a border around the area (unless leftRelief is TK_RELIEF_FLAT; in this case no border is drawn).

The procedures Tk_3DVerticalBevel and Tk_3DHorizontalBevel provide lower-level drawing primitives that are used by procedures such as Tk_Draw3DRectangle. These procedures are also useful in their own right for drawing rectilinear border shapes. Tk_3DVerticalBevel draws a vertical beveled edge, such as the left or right side of a rectangle, and Tk_3DHorizontalBevel draws a horizontal beveled edge, such as the top or bottom of a rectangle. Each procedure takes x, y, width, and height arguments that describe the rectangular area of the beveled edge (e.g., width is the border width for Tk_3DVerticalBevel). The leftBorder and topBorder arguments indicate the position of the border relative to the “inside” of the value, and relief indicates the relief of the inside of the value relative to the outside. Tk_3DVerticalBevel just draws a rectangular region. Tk_3DHorizontalBevel draws a trapezoidal region to generate mitered corners; it should be called after Tk_3DVerticalBevel (otherwise Tk_3DVerticalBevel will overwrite the mitering in the corner). The leftIn and rightIn arguments to Tk_3DHorizontalBevel describe the mitering at the corners; a value of 1 means that the bottom edge of the trapezoid will be shorter than the top, 0 means it will be longer. For example, to draw a rectangular border the top bevel should be drawn with 1 for both leftIn and rightIn, and the bottom bevel should be drawn with 0 for both arguments.

The procedure Tk_SetBackgroundFromBorder will modify the background pixel and/or pixmap of tkwin to produce a result compatible with border. For color displays, the resulting background will just be the color specified when border was created; for monochrome displays, the resulting background will be a light stipple pattern, in order to distinguish the background from the illuminated portion of the border.

Given a token for a border, the procedure Tk_NameOf3DBorder will return the color name that was used to create the border.

The procedure Tk_3DBorderColor returns the XColor structure that will be used for flat surfaces drawn for its border argument by procedures like Tk_Fill3DRectangle. The return value corresponds to the color name that was used to create the border. The XColor, and its associated pixel value, will remain allocated as long as border exists.

The procedure Tk_3DBorderGC returns one of the X graphics contexts that are used to draw the border. The argument which selects which one of the three possible GC's: TK_3D_FLAT_GC returns the context used for flat surfaces, TK_3D_LIGHT_GC returns the context for light shadows, and TK_3D_DARK_GC returns the context for dark shadows.

When a border is no longer needed, Tk_Free3DBorderFromObj or Tk_Free3DBorder should be called to release the resources associated with it. For Tk_Free3DBorderFromObj the border to release is specified with the window and color name used to create the border; for Tk_Free3DBorder the border to release is specified with the Tk_3DBorder token for the border. There should be exactly one call to Tk_Free3DBorderFromObj or Tk_Free3DBorder for each call to Tk_Alloc3DBorderFromObj or Tk_Get3DBorder.
