ARGUMENTOS

Tcl_Interp *interp (entrada)
Un intérprete de Tcl. La mayoría de los procedimientos usan esto solo para devolver mensajes de error; si es NULL, no se devuelven mensajes de error. Para Tk_CreateOptionTable el valor no puede ser NULL; da el intérprete en el que se utilizará la tabla de opciones.
const Tk_OptionSpec *templatePtr (entrada)
Puntero a una matriz de información estática que describe las opciones de configuración que se admiten. Se utiliza para construir una Tk_OptionTable. La información a la que apunta este argumento debe existir durante la vida útil de la Tk_OptionTable.
Tk_OptionTable optionTable (entrada)
Token para una tabla de opciones. Debe haber sido devuelto por una llamada anterior a Tk_CreateOptionTable.
char *recordPtr (entrada/salida)
Puntero a una estructura en la que se almacenan los valores de las opciones de configuración; los campos de este registro son modificados por procedimientos como Tk_SetOptions y leídos por procedimientos como Tk_GetOptionValue.
Tk_Window tkwin (entrada)
Para opciones como TK_OPTION_COLOR, este argumento indica la ventana en la que se utilizará la opción. Si optionTable no utiliza opciones dependientes de la ventana, entonces se puede proporcionar un valor NULL para este argumento.
int objc (entrada)
Número de valores en objv.
Tcl_Obj *const *objv (entrada)
Argumentos de línea de comandos para establecer opciones de configuración.
Tk_SavedOptions *savePtr (salida)
Si no es NULL, la estructura apuntada por este argumento se rellena con los valores antiguos de las opciones modificadas y los valores antiguos se restauran automáticamente si ocurre un error en Tk_SetOptions.
int *maskPtr (salida)
Si no es NULL, la palabra apuntada por maskPtr se rellena con el OR a nivel de bits de los campos typeMask de las opciones modificadas.
Tk_SavedOptions *savedPtr (entrada/salida)
Puntero a una estructura rellenada previamente por Tk_SetOptions con los valores antiguos de las opciones modificadas.
Tcl_Obj *namePtr (entrada)
El valor de este objeto es el nombre de una opción particular. Si se pasa NULL a Tk_GetOptionInfo, se devuelve información para todas las opciones. No debe ser NULL cuando se llama a Tk_GetOptionValue.
type name type (entrada)
El nombre del tipo de un registro.
field name field (entrada)
El nombre de un campo en registros del tipo type.

DESCRIPCIÓN

Estos procedimientos manejan la mayoría de los detalles de análisis de opciones de configuración, como las de los widgets Tk. Dada una descripción de las opciones admitidas, estos procedimientos manejan todos los detalles de análisis de opciones y almacenamiento de sus valores en una estructura C asociada al widget u objeto. Los procedimientos fueron diseñados principalmente para widgets en Tk, pero también se pueden usar para otros tipos de objetos que tengan opciones de configuración. En el resto de esta página de manual se usará la palabra "widget" para referirse al objeto cuyas opciones se están gestionando; en la práctica, el objeto puede no ser realmente un widget. El término "registro de widget" se usa para referirse a la estructura a nivel C en la que se almacena la información sobre un widget u objeto particular.

Tenga en cuenta que la forma más fácil de aprender a usar estos procedimientos es observar un ejemplo funcional. En Tk, el ejemplo más simple es el código que implementa la familia de widgets de botones, que se encuentra en tkButton.c. Otros ejemplos se encuentran en tkSquare.c y tkMenu.c.

Para usar estos procedimientos, el código que implementa el widget debe contener una matriz estática de estructuras Tk_OptionSpec. Esta es una plantilla que describe las diversas opciones admitidas por esa clase de widget; hay una plantilla separada para cada tipo de widget. La plantilla contiene información como el nombre de cada opción, su tipo, su valor predeterminado y dónde se almacena el valor de la opción en el registro del widget. Ver PLANTILLAS a continuación para más detalles.

Para procesar las opciones de configuración de manera eficiente, la plantilla estática debe aumentarse con información adicional que solo está disponible en tiempo de ejecución. El procedimiento Tk_CreateOptionTable crea esta información dinámica a partir de la plantilla y devuelve un token Tk_OptionTable que describe tanto la información estática como la dinámica. Todos los demás procedimientos, como Tk_SetOptions, toman un token Tk_OptionTable como argumento. Típicamente, Tk_CreateOptionTable se llama la primera vez que se crea un widget de una clase particular y la Tk_OptionTable resultante se utiliza en el futuro para todos los widgets de esa clase. Una Tk_OptionTable solo se puede usar en un intérprete, dado por el argumento interp a Tk_CreateOptionTable. Cuando una tabla de opciones ya no es necesaria, se debe llamar a Tk_DeleteOptionTable para liberar todos sus recursos. Todas las tablas de opciones para un intérprete Tcl se liberan automáticamente si se elimina el intérprete.

Tk_InitOptions se invoca cuando se crea un nuevo widget para establecer los valores predeterminados. A Tk_InitOptions se le pasa un token para una tabla de opciones (optionTable) y un puntero a un registro de widget (recordPtr), que es la estructura C que contiene información sobre este widget. Tk_InitOptions utiliza la información de la tabla de opciones para elegir un valor predeterminado apropiado para cada opción, luego almacena el valor predeterminado directamente en el registro del widget, sobrescribiendo cualquier información que ya estuviera presente en el registro del widget. Tk_InitOptions normalmente devuelve TCL_OK. Si ocurrió un error al establecer los valores predeterminados (por ejemplo, porque un valor predeterminado era erróneo), entonces se devuelve TCL_ERROR y se deja un mensaje de error en el resultado de interp si interp no es NULL. Para cualquier opción de configuración de un widget que tenga TK_OPTION_DONT_SET_DEFAULT establecido en su campo flags, la inicialización anterior se omite completamente, ver abajo.

Tk_SetOptions se invoca para modificar las opciones de configuración basándose en la información especificada en un comando Tcl. El comando podría ser uno que crea un nuevo widget o un comando que modifica opciones en un widget existente. Los argumentos objc y objv describen los valores de los argumentos del comando Tcl. Objv debe contener un número par de objetos: el primer objeto de cada par da el nombre de una opción y el segundo objeto da el nuevo valor para esa opción. Tk_SetOptions busca cada nombre en optionTable, verifica que el nuevo valor de la opción se ajuste al tipo en optionTable, y almacena el valor de la opción en el registro del widget dado por recordPtr. Tk_SetOptions normalmente devuelve TCL_OK. Si ocurrió un error (como un nombre de opción desconocido o un valor de opción ilegal), entonces se devuelve TCL_ERROR y se deja un mensaje de error en el resultado de interp si interp no es NULL.

Tk_SetOptions tiene dos características adicionales. Primero, si el argumento maskPtr no es NULL, entonces apunta a un valor entero que se rellena con información sobre las opciones modificadas. Para cada opción en la plantilla pasada a Tk_CreateOptionTable hay un campo typeMask. Los bits de este campo están definidos por el código que implementa el widget; por ejemplo, cada bit podría corresponder a una opción de configuración particular. Alternativamente, los bits podrían usarse funcionalmente. Por ejemplo, un bit podría usarse para redibujar: todas las opciones que afectan la visualización del widget, de modo que el cambio de la opción requiera que el widget se redibuje, podrían tener ese bit establecido. Otro bit podría indicar que la geometría del widget debe recalcularse, y así sucesivamente. Tk_SetOptions aplica un OR a los campos typeMask de

If a widget record field's offset is stored in the objOffset or internalOffset field of a Tk_OptionSpec struct, then the procedures described here will handle all the storage allocation and resource management issues associated with that field. When an option's value is modified, Tk_SetOptions (or Tk_FreeSavedOptions) will automatically free any resources associated with the old value, such as Tk_Fonts for TK_OPTION_FONT options or dynamic memory for TK_OPTION_STRING options. For a value stored as an object using the objOffset field of a Tk_OptionSpec struct, the widget record shares the object that is mentioned in the objv value of the Tk_SetOptions call. The reference count for this object is incremented when a pointer to it is stored in the widget record, and decremented when the option is modified. When the widget is destroyed, Tk_FreeConfigOptions must be called, which will free resources associated with all options and decrement reference counts for any objects.

However, the widget code is responsible for storing NULL or None in all pointer and token fields before invoking Tk_InitOptions. This is necessary to allow proper cleanup in the rare event that an error occurs in Tk_InitOptions.

However, there are two cases where using the objOffset field is useful. The first case is for TK_OPTION_PIXELS options. In this case, the internal form is an integer pixel value valid only for a particular monitor. If the option's value is retrieved, it will be returned as a simple number. For example, after the command .b configure -borderwidth 2m, the command .b configure -borderwidth might return 7, which is the integer pixel value corresponding to 2m. However, this loses the original screen-independent value. Therefore, for TK_OPTION_PIXELS options, it is better to use the objOffset field. In this case, the original value of the option is kept in the object and can be returned when the option is retrieved. In most cases it is convenient to use the internalOffset field, as the integer value can be used immediately in the widget code (alternatively, Tk_GetPixelsFromObj can be used to extract the integer value from the object when needed). Note that the problem of losing information during retrievals only exists for TK_OPTION_PIXELS options.

The second reason for using the objOffset field is to implement new option types not supported by these procedures. To implement a new option type, you can use TK_OPTION_STRING as the type in the Tk_OptionSpec struct and set the objOffset field but not the internalOffset field. Then, after invoking Tk_SetOptions, you can convert the object to its internal form yourself.

Ttk widgets do not support the internalOffset mechanism. Ttk widget option values are always stored as (Tcl_Obj *), meaning that the objOffset field must be used.

ARGUMENTS

clientData
A pointer to the client data associated with the option. This is usually a pointer to the widget structure itself, but it can be anything. The exact contents of this field are determined by the application.
interp
A pointer to the Tcl interpreter. This is used for error reporting.
objc
The number of elements in the objv array.
objv
An array of Tcl objects representing the configuration options and their values. The array should contain an even number of elements, with alternating option names and values.
optionTable
A pointer to a Tk option table. This table defines the standard Tk options supported by the widget.
customSpecs
A pointer to an array of Tk_OptionSpec structures that define any custom options supported by the widget. This array is terminated by a Tk_OptionSpec with a NULL name field.
recordPtr
A pointer to the widget's record structure. This is where the option values are stored.
flags
A bitmask containing zero or more of the following bits:
  • TK_CONFIG_OBJ_INSTANTIATE: If set, this indicates that the option values should be stored as Tcl objects in the widget record. This is the default behavior for Tk 8.5 and later.
  • TK_CONFIG_MONOCHROME: If set, this indicates that the widget should be configured for monochrome display.
  • TK_CONFIG_COLOR_ONLY: If set, this indicates that only color options should be configured.
  • TK_CONFIG_FONT_MONO: If set, this indicates that the widget should be configured for a monochrome font.
  • TK_CONFIG_NULL_OK: If set, this indicates that a NULL value is acceptable for the option.
  • TK_CONFIG_DONT_SET_DEFAULT: If set, this indicates that the default value for the option should not be set.
tkwin
A pointer to the widget's window. This is used for operations that require window-specific information, such as color lookups or font metrics.

The name of the configuration option.

The byte offset from the beginning of the widget record to the location where the option's value is stored.

DESCRIPTION

These procedures provide a mechanism for managing configuration options for Tk widgets. They allow applications to define standard and custom options, set and retrieve their values, and handle the storage and retrieval of these values.

The Tk_CreateOptionTable function creates a new option table, which is used to store information about the standard options supported by a widget. The Tk_FreeOptionTable function frees the memory associated with an option table.

The Tk_SetOptions and Tk_ConfigureWidget functions are used to set the values of configuration options for a widget. Tk_SetOptions is a more general function that can be used to configure any widget record, while Tk_ConfigureWidget is specifically designed for configuring Tk windows.

The Tk_ConfigureInfoWidget function is used to retrieve information about the configuration options of a widget, such as their current values, default values, and descriptions. This information can be used to generate help messages or to display the current configuration of a widget.

The Tk_OptionValue and Tk_OptionInfo functions are used to retrieve the value or information about a specific configuration option by name. Tk_OptionName returns the name of an option given its offset in the widget record.

The Tk_GetOption function retrieves the value of an option and stores it as a Tcl object.

The various Tk_Get* functions (e.g., Tk_GetBoolean, Tk_GetInt, Tk_GetColor) are used to parse and convert string values into specific data types. They return TCL_OK on success and TCL_ERROR on failure, leaving an error message in the interpreter if necessary.

The corresponding Tk_NameOf* functions (e.g., Tk_NameOfRelief, Tk_NameOfJustify) convert internal integer representations of these values back into human-readable string names.

Tk_Width and Tk_Height return the width and height in pixels of a given Tk font.

The Tk_Set* functions (e.g., Tk_SetBackground, Tk_SetWindowBackground) are used to set standard options like background color, border, and foreground color. Some set values directly in the widget record (via the option table), while others directly manipulate the Tk window's properties.

The Tk_SavedOptions, Tk_RestoreSavedOptions, and Tk_FreeSavedOptions functions are used to manage the saving and restoring of widget configuration options. This is typically used when a widget's configuration is temporarily changed, and the original values need to be restored later (e.g., during event handling).

TEMPLATES

The following functions are templates for callback procedures used with custom option types:

setProc
This procedure is invoked by Tk_SetOptions to convert a Tcl object into an internal representation and store it in the widget record. It should also save the original value for restoration if needed. The clientData argument is a pointer to the client data associated with the option. The interp argument is a pointer to the Tcl interpreter. The tkwin argument is a pointer to the widget's window. The objPtr argument is a pointer to the Tcl object representing the new option value. The flags argument contains configuration flags.

The procedure should store the converted value at the location indicated by recordPtr + internalOffset. It should also copy the original value to the location indicated by saveInternalPtr before overwriting it. If the option is being stored as a Tcl object (i.e., objOffset is non-negative), the procedure should store the pointer to the Tcl object at recordPtr + objOffset.

If successful, setProc should return TCL_OK. On failure, it should return TCL_ERROR and leave an error message in the interpreter.

getProc
This procedure is invoked by Tk_GetOptionValue and Tk_GetOptionInfo to retrieve a Tcl object representation of the internal value of the option. It should return a pointer to a Tcl object representing the option's value. The arguments are the same as for setProc, except that objPtr is not present and recordPtr points to the widget record.
restoreProc
This procedure is invoked by Tk_RestoreSavedOptions to restore a previously saved internal representation of a custom option value. It should copy the value from saveInternalPtr to internalPtr. This procedure has no return value.
freeProc
This procedure is invoked by Tk_SetOptions and Tk_FreeSavedOptions to free any storage allocated for the internal representation of a custom option. This procedure has no return value.

The Tk_CustomOption structure is used to define custom option types. It contains pointers to the callback procedures (setProc, getProc, restoreProc, freeProc), as well as information about the type of the option and where its value is stored in the widget record.

The Tk_OptionSpec structure is used to define both standard and custom options. It contains the name of the option, its type, default value, and other relevant information.

The Tk_OptionTable structure is used to manage a collection of Tk_OptionSpec structures, typically for the standard options supported by a widget.

The Tk_CustomOption structure typically points to a structure containing information that is needed by the procedures when they are parsing and printing options. RestoreProc and freeProc may be NULL, indicating that no function should be called for those operations.

The setProc procedure is invoked by Tk_SetOptions to convert a Tcl_Obj into an internal representation and store the resulting value in the widget record. The arguments are:

clientData
A copy of the clientData field in the Tk_ObjCustomOption structure.
interp
A pointer to a Tcl interpreter, used for error reporting.
Tkwin
A copy of the tkwin argument to Tk_SetOptions
valuePtr
A pointer to a reference to a Tcl_Obj describing the new value for the option; it could have been specified explicitly in the call to Tk_SetOptions or it could come from the option database or a default. If the objOffset for the option is non-negative (the option value is stored as a (Tcl_Obj *) in the widget record), the Tcl_Obj pointer referenced by valuePtr is the pointer that will be stored at the objOffset for the option. SetProc may modify the value if necessary; for example, setProc may change the value to NULL to support the TK_OPTION_NULL_OK flag.
recordPtr
A pointer to the start of the widget record to modify.
internalOffset
Offset in bytes from the start of the widget record to the location where the internal representation of the option value is to be placed.
saveInternalPtr
A pointer to storage allocated in a Tk_SavedOptions structure for the internal representation of the original option value. Before setting the option to its new value, setProc should set the value referenced by saveInternalPtr to the original value of the option in order to support Tk_RestoreSavedOptions.
flags
A copy of the flags field in the Tk_OptionSpec structure for the option

SetProc returns a standard Tcl result: TCL_OK to indicate successful processing, or TCL_ERROR to indicate a failure of any kind. An error message may be left in the Tcl interpreter given by interp in the case of an error.

The getProc procedure is invoked by Tk_GetOptionValue and Tk_GetOptionInfo to retrieve a Tcl_Obj representation of the internal representation of an option. The clientData argument is a copy of the clientData field in the Tk_ObjCustomOption structure. Tkwin is a copy of the tkwin argument to Tk_GetOptionValue or Tk_GetOptionInfo. RecordPtr is a pointer to the beginning of the widget record to query. InternalOffset is the offset in bytes from the beginning of the widget record to the location where the internal representation of the option value is stored. GetProc must return a pointer to a Tcl_Obj representing the value of the option.

The restoreProc procedure is invoked by Tk_RestoreSavedOptions to restore a previously saved internal representation of a custom option value. The clientData argument is a copy of the clientData field in the Tk_ObjCustomOption structure. Tkwin is a copy of the tkwin argument to Tk_GetOptionValue or Tk_GetOptionInfo. InternalPtr is a pointer to the location where internal representation of the option value is stored. SaveInternalPtr is a pointer to the saved value. RestoreProc must copy the value from saveInternalPtr to internalPtr to restore the value. RestoreProc need not free any memory associated with either internalPtr or saveInternalPtr; freeProc will be invoked to free that memory if necessary. RestoreProc has no return value.

The freeProc procedure is invoked by Tk_SetOptions and Tk_FreeSavedOptions to free any storage allocated for the internal representation of a custom option. The clientData argument is a copy of the clientData field in the Tk_ObjCustomOption structure. Tkwin is a copy of the tkwin argument to Tk_GetOptionValue or Tk_GetOptionInfo. InternalPtr is a pointer to the location where the internal representation of the option value is stored. The freeProc must free any storage associated with the option. FreeProc has no return value.

STORAGE MANAGEMENT ISSUES

When dealing with custom option types, the application is responsible for managing the memory associated with the internal representation of the option values. The setProc callback should allocate memory for the new value and store it in the widget record. The freeProc callback should free this memory when it is no longer needed (e.g., when the widget is destroyed or the option is changed to a different value).

The Tk_SavedOptions structure and its associated functions (Tk_RestoreSavedOptions, Tk_FreeSavedOptions) provide a convenient way to handle the saving and restoring of option values, including the memory management for custom types.

OBJOFFSET VS. INTERNALOFFSET

The Tk_OptionSpec structure has two offset fields: objOffset and internalOffset.

  • internalOffset: This is the byte offset from the start of the widget record to the location where the internal representation of the option value is stored. This is always required.

  • objOffset: If this is non-negative, it indicates that the option value is also stored as a Tcl object directly in the widget record at the specified offset. This is useful for options that are frequently accessed or manipulated as Tcl objects.

If objOffset is negative, the option value is only stored in its internal representation. The getProc callback will be responsible for creating a Tcl object representation from the internal value when needed.

CUSTOM OPTION TYPES

Tk provides a set of standard option types (e.g., boolean, integer, color, font). However, for more complex or application-specific data types, you can define custom option types. This is done by providing a Tk_CustomOption structure when calling Tk_SetOptions or Tk_ConfigureWidget. The Tk_CustomOption structure contains pointers to callback procedures (setProc, getProc, restoreProc, freeProc) that handle the conversion, retrieval, restoration, and freeing of the custom option's value.
