NOMBRE

Tk_AllocCursorFromObj, Tk_GetCursor, Tk_GetCursorFromObj, Tk_GetCursorFromData, Tk_NameOfCursor, Tk_FreeCursorFromObj, Tk_FreeCursor - mantener una base de datos de cursores

SINOPSIS

#include <tk.h>

Tk_Cursor
Tk_AllocCursorFromObj(interp, tkwin, objPtr)

Tk_Cursor
Tk_GetCursor(interp, tkwin, name)

Tk_Cursor
Tk_GetCursorFromObj(tkwin, objPtr)

Tk_Cursor
Tk_GetCursorFromData(interp, tkwin, source, mask, width, height, xHot, yHot, fg, bg)

const char *
Tk_NameOfCursor(display, cursor)

Tk_FreeCursorFromObj(tkwin, objPtr)

Tk_FreeCursor(display, cursor)

ARGUMENTOS

Tcl_Interp *interp (entrada)
Intérprete a utilizar para la notificación de errores.
Tk_Window tkwin (entrada)
Token para la ventana en la que se utilizará el cursor.
Tcl_Obj *objPtr (entrada/salida)
Descripción del cursor; ver abajo para posibles valores. La representación interna se modificará para almacenar en caché un puntero al Tk_Cursor correspondiente.
const char *name (entrada)
Igual que objPtr excepto que la descripción del cursor se pasa como una cadena y el Tk_Cursor resultante no se almacena en caché.
const char *source (entrada)
Datos para el cursor, en formato de cursor estándar.
const char *mask (entrada)
Datos para la máscara del cursor, en formato de cursor estándar.
int width (entrada)
Ancho de source y mask.
int height (entrada)
Altura de source y mask.
int xHot (entrada)
Ubicación X del punto activo del cursor.
int yHot (entrada)
Ubicación Y del punto activo del cursor.
Tk_Uid fg (entrada)
Descripción textual del color de primer plano para el cursor.
Tk_Uid bg (entrada)
Descripción textual del color de fondo para el cursor.
Display *display (entrada)
Pantalla para la que se asignó cursor.
Tk_Cursor cursor (entrada)
Identificador opaco de Tk para el cursor. Si se pasa a Tk_FreeCursor, debe haber sido devuelto por alguna llamada anterior a Tk_GetCursor o Tk_GetCursorFromData.

DESCRIPCIÓN

Estos procedimientos gestionan una colección de cursores que está utilizando una aplicación. Los procedimientos permiten reutilizar cursores de manera eficiente, evitando así la sobrecarga del servidor, y también permiten nombrar cursores con cadenas de caracteres.

Tk_AllocCursorFromObj toma como argumento un objeto que describe un cursor y devuelve un identificador opaco de Tk para un cursor que corresponde a la descripción. Reutiliza un cursor existente si es posible y crea uno nuevo si no. Tk_AllocCursorFromObj almacena en caché información sobre el valor de retorno en objPtr, lo que acelera las llamadas futuras a procedimientos como Tk_AllocCursorFromObj y Tk_GetCursorFromObj. Si ocurre un error al crear el cursor, como cuando objPtr se refiere a un archivo inexistente, entonces se devuelve None y se almacenará un mensaje de error en el resultado de interp si interp no es NULL. ObjPtr debe contener una lista Tcl estándar con una de las siguientes formas:

nombre [fgColor [bgColor]]
Nombre es el nombre de un cursor en el cursor estándar de X, es decir, cualquiera de los nombres definidos en cursorcursor.h, sin el prefijo XC_. Algunos valores de ejemplo son X_cursor, hand2 o left_ptr. El Apéndice B de “The X Window System” de Scheifler & Gettys tiene ilustraciones que muestran cómo se ve cada uno de estos cursores. Si se especifican fgColor y bgColor, proporcionan los colores de primer plano y de fondo que se utilizarán para el cursor (se puede utilizar cualquiera de las formas aceptables para Tk_GetColor). Si solo se especifica fgColor, entonces no habrá color de fondo: el fondo será transparente. Si no se especifican colores, el cursor utilizará negro como color de primer plano y blanco como color de fondo.

La versión para Macintosh de Tk admite todos los cursores de X y también aceptará cualquiera de los cursores estándar de Mac, incluyendo ibeam, crosshair, watch, plus y arrow. Además, Tk cargará recursos de cursores de Macintosh de los tipos crsr (color) y CURS (blanco y negro) por el nombre del recurso. Se buscará el cursor con nombre en la aplicación y en todos los archivos de recursos de sus bibliotecas dinámicas abiertas. Si hay conflictos, los cursores de color siempre se cargarán con preferencia a los cursores en blanco y negro.

@sourceName maskName fgColor bgColor
En esta forma, sourceName y maskName son los nombres de los archivos que describen los cursores para los bits de origen y la máscara del cursor. Cada archivo debe estar en formato de cursor X11 estándar. FgColor y bgColor indican los colores que se utilizarán para el cursor, en cualquiera de las formas aceptables para Tk_GetColor. Esta forma del comando no funcionará en computadoras Macintosh o Windows.
@sourceName fgColor
Esta forma es similar a la anterior, excepto que la fuente se utiliza también como máscara. Esto significa que el fondo del cursor es transparente. Esta forma del comando no funcionará en computadoras Macintosh o Windows.
@sourceName
Esta forma solo funciona en Windows y cargará un cursor del sistema de Windows (.ani o .cur) desde el archivo especificado en sourceName.

Tk_GetCursor es idéntico a Tk_AllocCursorFromObj excepto que la descripción del cursor se especifica con una cadena en lugar de un objeto. Esto evita que Tk_GetCursor almacene en caché el valor de retorno, por lo que Tk_GetCursor es menos eficiente que Tk_AllocCursorFromObj.

Tk_GetCursorFromObj devuelve el token de un cursor existente, dados la ventana y la descripción utilizadas para crear el cursor. Tk_GetCursorFromObj no crea realmente el cursor; el cursor ya debe haber sido creado con una llamada anterior a Tk_AllocCursorFromObj o Tk_GetCursor. El valor de retorno se almacena en caché en objPtr, lo que acelera las llamadas futuras a Tk_GetCursorFromObj con el mismo objPtr y tkwin.

Tk_GetCursorFromData permite crear cursores a partir de descripciones en memoria de sus cursores de origen y máscara. Source apunta a datos de cursor estándar para los bits de origen del cursor, y mask apunta a datos de cursor estándar que describen qué píxeles de source se dibujarán y cuáles se considerarán transparentes. Width y height dan las dimensiones del cursor, xHot y yHot indican la ubicación del punto activo del cursor (el punto que se informa cuando ocurre un evento), y fg y bg describen los colores de primer plano y de fondo del cursor textualmente (se puede utilizar cualquiera de las formas adecuadas para Tk_GetColor). Típicamente, los argumentos para Tk_GetCursorFromData se crean incluyendo un archivo de cursor directamente en el código fuente de un programa, como en el siguiente ejemplo:

Tk_Cursor cursor;
#include "source.cursor"
#include "mask.cursor"
cursor = Tk_GetCursorFromData(interp, tkwin, source_bits,
    mask_bits, source_width, source_height, source_x_hot,
    source_y_hot, Tk_GetUid("red"), Tk_GetUid("blue"));

En condiciones normales, Tk_GetCursorFromData devolverá un identificador para el cursor solicitado. Si ocurre un error al crear el cursor, se devolverá None y se almacenará un mensaje de error en el resultado de interp.

Tk_AllocCursorFromObj, Tk_GetCursor y Tk_GetCursorFromData mantienen una base de datos de todos los cursores que han creado. Siempre que sea posible, una llamada a Tk_AllocCursorFromObj, Tk_GetCursor o Tk_GetCursorFromData devolverá un cursor existente en lugar de crear uno nuevo. Este enfoque puede reducir sustancialmente la sobrecarga del servidor, por lo que generalmente se deben preferir los procedimientos de Tk a los procedimientos de Xlib como XCreateFontCursor o XCreatePixmapCursor, que crean un nuevo cursor en cada llamada. Los procedimientos de Tk también son más portátiles que los procedimientos de nivel inferior de X.

Tk_GetCursorFromObj, Tk_GetCursor, Tk_GetCursorFromData, Tk_FreeCursorFromObj, Tk_FreeCursor, Tk_NameOfCursor - allocate and free cursors

SYNOPSIS

#include <tk.h>

Tk_Cursor
Tk_GetCursorFromObj(tkwin, valuePtr)
      Tk_Window tkwin;
      Tcl_Obj *valuePtr;
Tk_Cursor
Tk_GetCursor(tkwin, string)
      Tk_Window tkwin;
      const char *string;
Tk_Cursor
Tk_GetCursorFromData(tkwin, source, mask, foreColor, backColor)
      Tk_Window tkwin;
      const char *source;
      const char *mask;
      XColor *foreColor;
      XColor *backColor;
void
Tk_FreeCursorFromObj(tkwin, valuePtr)
      Tk_Window tkwin;
      Tcl_Obj *valuePtr;
void
Tk_FreeCursor(tkwin, cursor)
      Tk_Window tkwin;
      Tk_Cursor cursor;
const char *
Tk_NameOfCursor(tkwin, cursor)
      Tk_Window tkwin;
      Tk_Cursor cursor;

ARGUMENTS

Tk_Window tkwin–
Identificador de la ventana de Tk para la que se asignará el cursor.
Tcl_Obj *valuePtr–
Puntero a un objeto Tcl que contiene la representación del cursor. Puede ser un entero (para un cursor de sistema), un nombre de archivo (para un cursor bitmap) o una lista de dos cadenas (para un cursor creado a partir de datos XBM).
const char *string–
Cadena que representa el cursor. Puede ser un entero (para un cursor de sistema), un nombre de archivo (para un cursor bitmap) o un nombre de cursor X.
const char *source–
Puntero a una cadena de caracteres que contiene los datos del cursor en formato XBM. Debe ser un puntero válido a una matriz de bytes que contiene los datos del cursor. La cadena debe terminar en null.
const char *mask–
Puntero a una cadena de caracteres que contiene los datos de la máscara del cursor en formato XBM. Debe ser un puntero válido a una matriz de bytes que contiene los datos de la máscara. La cadena debe terminar en null.
XColor *foreColor–
Puntero a una estructura XColor que especifica el color de primer plano del cursor. Si es NULL, se utilizará el color de primer plano predeterminado de la ventana.
XColor *backColor–
Puntero a una estructura XColor que especifica el color de fondo del cursor. Si es NULL, se utilizará el color de fondo predeterminado de la ventana.
Tk_Cursor cursor–
El token Tk_Cursor que se va a liberar o convertir en nombre.

DESCRIPTION

Estas funciones se utilizan para crear, liberar y obtener el nombre de los cursores en Tk.

Tk_GetCursorFromObj asigna un cursor basado en la información proporcionada en el objeto Tcl valuePtr. El objeto puede contener un cursor del sistema (entero), un nombre de archivo de mapa de bits o una lista de dos cadenas para datos XBM.

Tk_GetCursor asigna un cursor basado en la cadena string. La cadena puede ser un nombre de cursor predefinido de X (por ejemplo, "arrow", "hand2"), un entero que representa un cursor de sistema, o el nombre de un archivo que contiene un mapa de bits de cursor.

Tk_GetCursorFromData asigna un cursor creado a partir de datos de cursor y máscara en formato XBM. Los punteros source y mask apuntan a las matrices de bytes que contienen los datos. Los punteros foreColor y backColor especifican los colores del cursor.

Cuando se crea un cursor, Tk intenta reutilizar cursores existentes si es posible para mejorar el rendimiento. Si no se encuentra un cursor existente que coincida con la solicitud, se crea uno nuevo.

Tk_FreeCursorFromObj y Tk_FreeCursor se utilizan para liberar los recursos asociados con un cursor que ya no se necesita. Es importante llamar a estas funciones para evitar fugas de memoria. Debe haber exactamente una llamada a Tk_FreeCursorFromObj o Tk_FreeCursor por cada llamada a Tk_GetCursorFromObj, Tk_GetCursor o Tk_GetCursorFromData.

Tk_NameOfCursor devuelve una cadena que representa el nombre del cursor especificado por el token cursor. La cadena devuelta es un identificador X y solo se garantiza que sea válida hasta la próxima llamada a Tk_NameOfCursor. Esta llamada no es portable, excepto para los cursores devueltos por Tk_GetCursor.

Cuando un cursor devuelto por Tk_AllocCursorFromObj, Tk_GetCursor o Tk_GetCursorFromData ya no es necesario, se debe llamar a Tk_FreeCursorFromObj o Tk_FreeCursor para liberarlo. Para Tk_FreeCursorFromObj, el cursor a liberar se especifica con la misma información utilizada para crearlo; para Tk_FreeCursor, el cursor a liberar se especifica con su token Tk_Cursor. Debe haber exactamente una llamada a Tk_FreeCursor por cada llamada a Tk_AllocCursorFromObj, Tk_GetCursor o Tk_GetCursorFromData.

BUGS

Al determinar si un cursor existente puede satisfacer una nueva solicitud, Tk_AllocCursorFromObj, Tk_GetCursor y Tk_GetCursorFromData solo consideran los valores inmediatos de sus argumentos. Por ejemplo, cuando se pasa un nombre de archivo a Tk_GetCursor, Tk_GetCursor asumirá que es seguro reutilizar un cursor existente creado a partir del mismo nombre de archivo: no comprobará si el propio archivo ha cambiado, o si el directorio actual ha cambiado, causando así que el nombre se refiera a un archivo diferente. De manera similar, Tk_GetCursorFromData asume que si se utiliza el mismo puntero source en dos llamadas diferentes, entonces los punteros se refieren a los mismos datos; no comprueba si los valores de datos reales han cambiado.
